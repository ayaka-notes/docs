---
title: 3. Ayakaleaf Pro'yu başlatın
description: Ayakaleaf Pro'yu Podman üzerinde başlatın, podman-setup ve bin/doctor ile doğrulayın ve yeniden başlatmalardan sonra başlatın.
icon: circle-play
---

<Steps>
<Step title="Konteynerleri başlatın">
```bash title="Start Ayakaleaf Pro"
bin/up -d
```

İlk başlatma MongoDB, Redis ve TeX Live imajlarını indirir ve `data/` içinde veri dizinlerini oluşturur. Podman desteğinin deneysel olduğunu belirten bir uyarı yazdırır.

<Info>

İlk başlatma ayrıca `MongoNetworkError: connect ECONNREFUSED 127.0.0.1:27017` yazdırabilir. Toolkit, MongoDB hâlâ başlarken MongoDB replika kümesini ayarlar ve MongoDB yanıt verene kadar yeniden dener. Bu satırı yok sayabilirsiniz.

</Info>

Bir iki dakika sonra konteynerlerin çalıştığını denetleyin:

```bash title="List the containers"
podman ps --format "{{.Names}} {{.Status}}"
```

```text
mongo Up 34 seconds (healthy)
redis Up 20 seconds
sharelatex Up 20 seconds
```
</Step>

<Step title="Kurulumu yeniden denetleyin">
Artık veri dizinleri mevcut olduğuna ve `sharelatex` konteyneri çalıştığına göre `bin/podman-setup` denetimlerini tamamlayabilir:

```bash title="Check the setup"
bin/podman-setup
```

Yeni veri dizinlerinin sahiplerini denetler ve Podman soketini `sharelatex` konteynerinin içinden test eder:

```text
====== Socket Connectivity ======
[✓] host → socket OK
[✓] container → socket OK

====== Data Directory Permissions ======
[✓] mongo data dir owned by 999
[✓] redis data dir owned by 999
[✓] overleaf data dir owned by 33
...
====== Summary ======
[✓] 27 passed  [!] 1 warnings  [✗] 0 failures
[!] Warnings:
[!] not logged in to quay.io
```

`container → socket OK`, Ayakaleaf Pro'nun derleme konteynerlerini başlatabildiği anlamına gelir. Bir denetim başarısız olursa `bin/podman-setup --apply`, ardından `bin/up -d` çalıştırın. quay.io uyarısı Ayakaleaf Pro için geçerli değildir, bkz. [2. podman-setup'ı çalıştırın](/tr/on-premises/installation/using-podman/2.-run-podman-setup).
</Step>

<Step title="Doctor'ı çalıştırın">
```bash title="Run the doctor"
bin/doctor
```

Podman üzerinde rapor, çalışma zamanını ve güvenlik ayarlarını gösterir:

```text
- Container Daemon
    - status: up
    - runtime: podman
    - server version: 5.8.5
    - socket: /run/user/1000/podman/podman.sock
    - DOCKER_HOST: unix:///run/user/1000/podman/podman.sock
    - host → socket: OK
    - container → socket: OK
- Security
    - SELinux: Enforcing
    - SELINUX_MODE: managed
    - SELINUX_LABEL: sharelatex_t
    - SELinux module: loaded (podman_socket_clsi)
    - SELinux rules: present
    - Seccomp profile: present
```

Sondaki `Server Pro enabled, but not logged in to quay.io repository` uyarısı aynı quay.io denetimidir, bkz. [Yardım alma](/tr/on-premises/support/getting-help#q-and-a).
</Step>

<Step title="Yeniden başlatmadan sonra Ayakaleaf Pro'yu başlatın">
Docker ile, Docker arka plan hizmeti yeniden başlatmadan sonra konteynerleri tekrar başlatır. Rootless Podman'ın arka plan hizmeti yoktur: sunucu açıldığında konteynerlerinizi başlatan kullanıcı hizmetini etkinleştirin:

```bash title="Start the containers at boot"
systemctl --user enable podman-restart.service
```

Bu hizmet, kullanıcınızın yeniden başlatma ilkesi `always` olan her konteynerini başlatır; Toolkit bu ilkeyi tüm konteynerleri için ayarlar. Bunun için `bin/podman-setup --apply`'ın etkinleştirdiği lingering gerekir. Bu hizmet olmadan her yeniden başlatmadan sonra `bin/up -d` çalıştırın.
</Step>

<Step title="Güvenlik duvarında bağlantı noktasını açın">
Varsayılan olarak örnek yalnızca sunucunun kendisinden, `http://localhost:8080` üzerinden bağlantı kabul eder. Diğer bilgisayarlardan açmak için `config/overleaf.rc` içinde `OVERLEAF_LISTEN_IP`'yi ve `config/variables.env` içinde `OVERLEAF_SITE_URL`'yi [5. Örneğinizi kişiselleştirme](/tr/on-premises/installation/using-docker-compose/linux/5.-personalizing-your-instance#listen-address-and-port) bölümünde açıklandığı gibi ayarlayın ve `bin/up -d`'yi yeniden çalıştırın.

Docker'ın aksine rootless Podman, ana makine güvenlik duvarını atlamaz. RHEL'de varsayılan olduğu gibi `firewalld` çalışıyorsa bağlantı noktasını açın:

```bash title="Open port 8080"
sudo firewall-cmd --permanent --add-port=8080/tcp
sudo firewall-cmd --reload
```

Bir bulut sunucusunda bağlantı noktasına sağlayıcının güvenlik grubunda da izin verin. Örneği internete açmadan önce HTTPS kullanın, bkz. [4. Kurulum sonrası görevler](/tr/on-premises/installation/using-podman/4.-post-installation-tasks#use-https).
</Step>
</Steps>
