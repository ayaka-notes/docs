---
title: 5. Örneğinizi kişiselleştirme
description: Mac'inizdeki yerel bir örnek için portu, site URL'sini ve TeX Live imajını ayarlayın, Docker sanal makinesinin çekirdeğini kontrol edin ve Ayakaleaf Pro'yu başlatın.
icon: square-sliders
---

<Steps>
<Step title="Konteyner ayarları">
`config/overleaf.rc` içindeki şu mevcut girdileri düzenleyin:

```bash title="config/overleaf.rc"
PROJECT_NAME=ayakaleaf-macos
SERVER_PRO=true
OVERLEAF_LISTEN_IP=127.0.0.1
OVERLEAF_PORT=8080
SIBLING_CONTAINERS_ENABLED=true
DOCKER_SOCKET_PATH=/var/run/docker.sock
```

Varsayılan veri yollarını ve birlikte gelen MongoDB ve Redis hizmetlerini koruyun. `OVERLEAF_LISTEN_IP=127.0.0.1` ile örneği yalnızca bu Mac'teki tarayıcılar açabilir.
</Step>

<Step title="Uygulama ayarları">
`config/variables.env` içinde, aynı adlara sahip etkin girdilerin yerine geçecek şekilde şu değerleri ayarlayın:

```dotenv title="config/variables.env"
OVERLEAF_SITE_URL=http://localhost:8080
TEX_LIVE_DOCKER_IMAGE=ghcr.io/ayaka-notes/texlive-full:2026.1
ALL_TEX_LIVE_DOCKER_IMAGES=ghcr.io/ayaka-notes/texlive-full:2026.1
ALL_TEX_LIVE_DOCKER_IMAGE_NAMES="TeX Live 2026"
```

Bir oturum gizli anahtarı üretin:

```bash
openssl rand -hex 32
```

Sonucu `config/variables.env` içine `OVERLEAF_SESSION_SECRET` olarak ekleyin. Bu olmadan, konteyneri yeniden oluşturan her `bin/up` tüm kullanıcıların oturumunu kapatır; bkz. [Ortam Değişkenleri](/tr/on-premises/configuration/overleaf-toolkit/environment-variables).

E-posta olmadan çalışan yerel bir örnek için SMTP ayarlarını ve `OVERLEAF_EMAIL_FROM_ADDRESS` değerini ayarlamadan bırakın. Git Bridge, harici kimlik doğrulama ve diğer entegrasyonlar daha sonra kendi [yapılandırma sayfalarıyla](/tr/on-premises/configuration/overleaf-toolkit) eklenebilir.
</Step>

<Step title="Docker sanal makinesinin Linux çekirdeğini kontrol edin" id="check-the-docker-vms-linux-kernel">
MongoDB, macOS üzerinde değil, Docker Desktop sanal makinesinin Linux çekirdeği üzerinde çalışır. İlk başlatmadan önce sürümünü kontrol edin:

```bash
docker info --format '{{.KernelVersion}}'
```

MongoDB, **6.19 ile 7.0.13 arasındaki** Linux çekirdekleriyle Docker içindeki MongoDB'yi de etkileyen bir uyumsuzluk belgelemektedir. Çözüm, bir Docker Desktop güncellemesiyle gelen **7.0.14 veya üzeri** bir çekirdektir; bkz. [MongoDB'nin üretim notları](https://www.mongodb.com/docs/manual/administration/production-notes/).

Docker sanal makineniz etkilenen bir çekirdek kullanıyorsa, aşağıdakini `config/docker-compose.override.yml` dosyasına, orada zaten bulunan `services` ile birleştirerek ekleyin:

```yaml title="config/docker-compose.override.yml"
services:
  mongo:
    environment:
      GLIBC_TUNABLES: glibc.pthread.rseq=1
```

<Warning>

Kullanılabilir olduğunda düzeltilmiş bir çekirdeğe güncelleyin. Çekirdeğiniz etkilenen aralığın dışındaysa bu geçici çözüme gerek yoktur.

</Warning>
</Step>

<Step title="Örneğinizi başlatın">
Toolkit dizininden şunu çalıştırın:

```bash
bin/up -d
```

Toolkit, MongoDB'nin replika kümesini başlatır, TeX Live imajını çeker ve uygulamayı başlatır. İlk indirme biraz zaman alır. İlerlemeyi izlemek için:

```bash
bin/docker-compose ps
bin/docker-compose logs --tail=100 -f sharelatex
```

Günlükleri izlemeyi durdurmak için `Ctrl+C` tuşlarına basın. Konteynerler çalışmaya devam eder.

Yayımlanan portu ve ilk çalıştırma sayfasını kontrol edin:

```bash
bin/docker-compose port sharelatex 80
curl -I http://localhost:8080/launchpad
```

Port `127.0.0.1:8080` olmalıdır.
</Step>
</Steps>
