### Yöneticiyi ve ilk projeyi oluşturma {#create-the-administrator-and-a-first-project}

**Windows tarayıcınızda** [http://localhost:8080/launchpad](http://localhost:8080/launchpad) adresini açın, ilk yönetici hesabını oluşturun ve giriş yapın. Ardından örnek URL'lerde `8080` portunu kullanarak Linux kılavuzunun [6. Kurulum sonrası görevler](/tr/on-premises/installation/using-docker-compose/linux/6.-post-installation-tasks) bölümünü izleyin.

### Derlemeyi doğrulama {#verify-compilation}

Çalışan bir giriş sayfası, ayrı derleyici konteynerlerinin WSL veri dizinine erişebildiğini kanıtlamaz. Boş bir proje oluşturun ve şu `main.tex` dosyasını **pdfLaTeX** ile derleyin:

```latex
\documentclass{article}
\begin{document}
Ayakaleaf Pro on Windows WSL 2.
\end{document}
```

PDF önizlemesi metni göstermelidir. Basic imaj için gerekirse proje ayarlarında **TeX Live 2026 Basic** seçeneğini seçin.

**XeLaTeX** seçin ve şunu test edin:

```latex
\documentclass{article}
\usepackage{fontspec}
\begin{document}
Ayakaleaf WSL XeLaTeX sandbox.
\end{document}
```

Her iki örnek de basic ile çalışır. Çince belgeler için aşağıdakini **XeLaTeX** ile test etmeden önce full gibi `ctex` ve gerekli yazı tiplerini içeren bir imaj kullanın. Basic bunları içermez:

```latex
\documentclass{ctexart}
\begin{document}
你好，Ayakaleaf Pro。
\end{document}
```

Korumalı alanın kullanıldığını doğrulamak için derleme sırasında **Ubuntu**'da şunu çalıştırın:

```bash
docker ps -a --filter ancestor=ghcr.io/ayaka-notes/texlive-basic:2026.1
bin/logs -f clsi
```

Filtrede seçtiğiniz imaj adını kullanın. Kısa derlemeler `docker ps` çalışmadan önce bitebilir; `-a` durdurulmuş konteynerleri de temizlenene kadar gösterir. Bir derleyici konteyneri bu imajı ve Toolkit'in WSL veri dizininden bir `/compile` bind mount'unu kullanmalıdır. Uygulama günlükleri tek başına PDF'i kontrol etmenin yerini tutmaz.

### Kalıcılığı doğrulama {#verify-persistence}

**Ubuntu**'da, Toolkit dizininden:

```bash
bin/stop
bin/start
```

Uygulamayı bekleyin, projeyi Windows'tan yeniden açın ve tekrar derleyin. Hesabınız, kaynak dosya ve proje dosyaları hâlâ orada olmalıdır. Varsayılan canlı veriler Ubuntu içinde `~/ayakaleaf-toolkit/data/` dizinindedir. Hem `config/` hem de `data/` dizinlerini saklayın; Ubuntu dağıtımını kaldırmak veya kaydını silmek bunları silebilir.

### Örneği erişilebilir tutun {#keep-the-instance-available}

Örneği çalışır durumda tutmanın üç bileşeni vardır: Windows uyanık kalır, Docker Desktop çalışır ve konteynerler motorla birlikte yeniden başlar.

Docker Desktop **Settings → General** içinde **Start Docker Desktop when you sign in to your computer** seçeneğini açın; bkz. [Docker Desktop ayarları](https://docs.docker.com/desktop/settings-and-maintenance/settings/). Bu, Docker'ı oturum açmadan önce değil, oturum açtıktan sonra başlatır. Windows yeniden başladıktan sonra oturum açın, Docker Desktop'ın başlamasını bekleyin, Ubuntu'yu açın ve `docker ps` çıktısını ve siteyi kontrol edin.

Docker Desktop'ın **Resource Saver** özelliği Windows uykusundan ayrıdır. Normalde yalnızca hiçbir konteyner çalışmadığında etkinleşir; çalışan uygulama, MongoDB ve Redis bu boşta kalma durumunu engeller. WSL 2'de paylaşılan WSL sanal makinesini kapatmak yerine Docker motorunu duraklatır. Kullanıcılara hizmet verirken Docker Desktop'ı elle **Pause** etmeyin. Yalnızca bu yığını çalışır durumda tutmak için Resource Saver'ı devre dışı bırakmanız gerekmez; bkz. [Docker'ın Resource Saver belgeleri](https://docs.docker.com/desktop/use-desktop/resource-saver/).

Toolkit hizmetleri `restart: always` kullanır. Gerçek ayarı **Ubuntu**'da doğrulayın:

```bash
docker inspect sharelatex mongo redis --format '{{.Name}} restart={{.HostConfig.RestartPolicy.Name}}'
```

Her hizmet `always` bildirmelidir. Docker çalıştığında, bu mevcut konteynerleri yeni bir `bin/up` olmadan yeniden başlatabilir. Elle durdurulan bir konteyner, siz onu başlatana veya motoru yeniden başlatana kadar durdurulmuş kalır; `always` ile bir motor yeniden başlatması onu yeniden başlatabilir. Bkz. [Docker'ın yeniden başlatma ilkesi davranışı](https://docs.docker.com/engine/containers/start-containers-automatically/).

| Eylem | Ayakaleaf üzerindeki etkisi |
| --- | --- |
| `bin/up -d` sonrasında Ubuntu terminalini kapatmak | Konteynerler arka planda çalışır; terminal onların denetleyicisi değildir. Docker Desktop'ı ve WSL ortamını kullanılabilir tutun |
| Docker Dashboard penceresini kapatmak | Docker Desktop sistem tepsisinde çalışmaya devam ederken pencere kapanabilir |
| **Quit Docker Desktop** seçeneğini seçmek | Motoru durdurur ve siteyi erişilemez hale getirir; kurtarmak için Docker Desktop'ı yeniden açın |
| `wsl --shutdown` çalıştırmak | Tüm WSL dağıtımlarını durdurur ve Docker WSL arka ucunu kesintiye uğratır; Docker Desktop'ı yeniden başlatın ve Ubuntu'yu yeniden açın |
| Windows'u uyku, hazırda bekletme moduna almak veya kapatmak | Hizmete erişilemez; yalnızca ekranı açık veya kapalı tutmak bunu değiştirmez |
| `bin/stop` çalıştırmak | Verilerini koruyarak örneği durdurur; devam etmek için `bin/start` kullanın |

AC güçte uzun süreli kullanım için Windows 11 **Settings → System → Power & battery → Screen, sleep & hibernate timeouts** yolunu açın (bazı sürümlerde **Power** veya **Screen and sleep** görünür). Prize takılıyken uyku zaman aşımını **Never** olarak ayarlayın ve yapılandırılmışsa otomatik hazırda bekletmeyi devre dışı bırakın. Ekran yine de kapanabilir. Dizüstü bilgisayarın kapak eylemi ayrı bir ayardır; boşta uyku zaman aşımı Never olsa bile kapağı kapatmak bilgisayarı uyku moduna alabilir. Bkz. [Windows güç ayarları](https://support.microsoft.com/en-us/windows/experience/power-battery/power-settings-in-windows-11).

Site kullanımdayken `wsl --shutdown` komutunu rutin bir temizlik işlemi olarak çalıştırmayın. Bir WSL ayar değişikliği bunu gerektiriyorsa önce örneği durdurun ve bir kesinti planlayın. Windows bu ayarlarla örneği sürekli çalıştırabilir. Oturum kapatmalara ve gözetimsiz yeniden başlatmalara dayanması gereken paylaşılan bir hizmet için [Linux kılavuzunu](/tr/on-premises/installation/using-docker-compose/linux) öneririz.

### Docker Desktop'ı yeniden başlattıktan sonra kurtarmayı kontrol etme {#check-recovery-after-restarting-docker-desktop}

Çalışmaları kaydettikten ve etkin derlemelerin bitmesine izin verdikten sonra Docker Desktop'ın sorun giderme menüsünden **Restart Docker Desktop** seçeneğini seçin. Motoru bekleyin, ardından **Ubuntu**'da kontrol edin:

```bash
docker ps
curl -I http://localhost:8080/launchpad
```

Mevcut projeyi Windows'ta açın ve yeniden derleyin. Hesabın ve kaynak dosyanın hâlâ var olduğunu doğrulayın.

Örneği bilinçli olarak `bin/stop` ile durdurduysanız `bin/start` kullanın. Docker çalışıyor ancak bir hizmet başarısız oluyorsa yapılandırmayı yeniden oluşturmak yerine günlüklerini okuyun. Windows Update, Docker güncellemeleri ve elektrik kesintileri 24 saat çalışan bir kurulumu yine de kesintiye uğratabilir; yedek alın ve planlı bakımdan sonra kurtarmayı kontrol edin.

### Günlük kullanım {#daily-use}

Windows'ta Docker Desktop'ı başlatın. **Ubuntu**'yu açın:

```bash
cd "$HOME/ayakaleaf-toolkit"
```

| Görev | Komut |
| --- | --- |
| Mevcut konteynerleri başlatma | `bin/start` |
| Verileri koruyarak konteynerleri durdurma | `bin/stop` |
| Yapılandırma değişikliklerini uygulama | `bin/up -d` |
| Durumu kontrol etme | `bin/docker-compose ps` |
| Başlatma günlüklerini okuma | `bin/docker-compose logs --tail=100 sharelatex` |
| MongoDB günlüklerini okuma | `bin/docker-compose logs --tail=100 mongo` |
| Derleyici günlüklerini okuma | `bin/logs -f clsi` |

`bin/start` yapılandırma düzenlemelerini uygulamaz: `config/` değiştirildikten sonra `bin/up -d` kullanın. WSL dağıtımını yükseltmeden, taşımadan veya kaldırmadan önce [Veriler ve yedeklemeler](/tr/on-premises/maintenance/data-and-backups) kılavuzunu izleyin. Veritabanı yazarken canlı MongoDB dosyalarını kopyalamak tutarlı bir yedekleme değildir.

Yerel kullanım için `127.0.0.1` değerini koruyun. Diğer bilgisayarlara hizmet vermek ayrıca bilinçli olarak ayarlanmış bir dinleme adresi, site URL'si, Windows güvenlik duvarı/ağ yapılandırması ve HTTPS gerektirir; yalnızca `OVERLEAF_SITE_URL` değerini değiştirmek bir portu yayımlamaz.

Bir şey çalışmazsa [Sorun giderme](/tr/on-premises/installation/using-docker-compose/windows/troubleshooting) sayfasına bakın.
