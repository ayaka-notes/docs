Bu sayfa, Toolkit dağıtımlarında `config/overleaf.rc` dosyasında desteklenen ortam değişkenlerini açıklar.

`config/overleaf.rc` dosyası, `NAME=value` biçimindeki değişken tanımlarından oluşur. `#` ile başlayan satırlar yorum olarak değerlendirilir.

<Info>

`overleaf.rc` veya `variables.env` dosyasında herhangi bir değişiklik yaptıktan sonra `bin/up` komutunu çalıştırarak Docker konteynerlerini yeniden oluşturmanız gerekir.

</Info>

## Konteyner

### `sharelatex`

| Ad                           | Açıklama |
| ---------------------------- | -------- |
| `PROJECT_NAME`               | <p>`docker-compose` komutuna verilen `--project-name` bayrağının değerini ayarlar. Her örnek farklı bir proje adına sahip olabileceğinden, tek bir ana bilgisayarda birden fazla Overleaf örneği çalıştırırken kullanışlıdır.<br /><br />- <strong>Varsayılan</strong>: `overleaf`</p> |
| `OVERLEAF_IMAGE_NAME`        | <p>Server Pro/CE uygulama konteyneri tarafından kullanılan Docker imajı. Bu yalnızca Docker imajı adıdır; Docker imajı etiketi `config/version` dosyasından alınır.<br /><br />- <strong>Varsayılan:</strong><br />- Server Pro: `ghcr.io/ayaka-notes/overleaf-pro`<br />- Community Edition: `sharelatex/sharelatex`</p> |
| `SERVER_PRO`                 | <p>`true` olarak ayarlandığında Toolkit'e varsayılan Server CE imajı (`sharelatex/sharelatex`) yerine Server Pro imajını (`ghcr.io/ayaka-notes/overleaf-pro`) kullanmasını söyler.<br /><br />- <strong>Varsayılan</strong>: `false`</p> |
| `GIT_BRIDGE_ENABLED`         | <p>git-bridge özelliğini etkinleştirmek için `true` olarak ayarlayın (yalnızca Server Pro). Daha fazla bilgi için <a href="https://www.overleaf.com/learn/how-to/Git_integration">https://www.overleaf.com/learn/how-to/Git_integration</a> kullanıcı belgelerine bakın.<br /><br />- <strong>Varsayılan:</strong> `false`</p> |
| `GIT_BRIDGE_IMAGE`           | <p>git-bridge konteyneri tarafından kullanılan Docker imajı (yalnızca Server Pro). Bu yalnızca Docker imajı adıdır; Docker imajı etiketi `config/version` dosyasından alınır.<br /><br />- <strong>Varsayılan:</strong> `ghcr.io/ayaka-notes/overleaf-pro/git-bridge`</p> |
| `GIT_BRIDGE_DATA_PATH`       | `git-bridge` konteynerine (yalnızca Server Pro) bağlanacak ve git depolarını saklamak için kullanılacak dizinin yolunu ayarlar. Bu, tam bir yol (`/` ile başlayan) veya Toolkit'in temel dizinine göre göreli bir yol olabilir. |
| `GIT_BRIDGE_LOG_LEVEL`       | <p>`git-bridge` konteynerinin günlük düzeyini yapılandırır. Kullanılabilir düzeyler: `TRACE`, `DEBUG`, `INFO`, `WARN`, `ERROR`.<br /><br />- <strong>Varsayılan:</strong> `INFO`</p> |
| `SIBLING_CONTAINERS_ENABLED` | <p>`true` olarak ayarlandığında Toolkit'e, projeleri her proje için ayrı bir Docker konteyneri kullanarak ayrı korumalı alanlarda derlemek için <strong>Sibling Containers</strong> tekniğini kullanmasını söyler. Daha fazla bilgi için &#x3C;server-pro-only-configuration/sandboxed-compiles> belgelerine bakın.<br /><br />- <strong>Gerektirir:</strong> `SERVER_PRO=true`<br />- <strong>Varsayılan:</strong> `true`</p> |
| `SIBLING_CONTAINERS_PULL`    | <p>`true` olarak ayarlandığında Toolkit'e, `bin/up` komutu kullanılırken <strong>config/variables.env</strong> dosyasında `ALL_TEX_LIVE_DOCKER_IMAGES` ile ayarlanan tüm TeX Live imajlarını otomatik olarak çekmesini söyler.<br /><br />- <strong>Varsayılan:</strong> `true`</p> |
| `DOCKER_SOCKET_PATH`         | <p>Ana makinedeki (Toolkit'i çalıştıran makine) Docker soketinin yolunu ayarlar. `SIBLING_CONTAINERS_ENABLED` değeri `true` olduğunda, derleyici hizmetinin ana bilgisayarda yeni Docker konteynerleri başlatabilmesi için soket konteynere bağlanır.<br /><br />- <strong>Gerektirir:</strong> `SIBLING_CONTAINERS_ENABLED=true`<br />- <strong>Varsayılan:</strong> `/var/run/docker.sock`</p> |
| `OVERLEAF_DATA_PATH`         | <p>Ana `sharelatex` konteynerine bağlanacak ve derleme verilerini saklamak için kullanılacak dizinin yolunu ayarlar. Bu, tam bir yol (`/` ile başlayan) veya Toolkit'in temel dizinine göre göreli bir yol olabilir.<br /><br />- <strong>Varsayılan:</strong> `data/overleaf`</p> |
| `OVERLEAF_LISTEN_IP`         | <p>Konteynerin bağlanacağı ana bilgisayar IP adresini/adreslerini ayarlar. Örneğin bu değer `0.0.0.0` olarak ayarlanırsa web arayüzü herhangi bir ana bilgisayar IP adresinde kullanılabilir olur. Konteynere doğrudan erişim için `OVERLEAF_LISTEN_IP` değeri genel IP adresinize ayarlanmalıdır. `OVERLEAF_LISTEN_IP` değerini `0.0.0.0` ya da ana bilgisayarınızın harici IP adresi olarak ayarlamak, ile birlikte kullanıldığında genellikle hatalara neden olur.<br /><br />- <strong>Varsayılan:</strong> `127.0.0.1`</p> |
| `OVERLEAF_PORT`              | <p>Konteynerin bağlanacağı ana bilgisayar bağlantı noktasını ayarlar. Örneğin bu değer `8099` ve `OVERLEAF_LISTEN_IP` değeri `127.0.0.1` olarak ayarlanırsa web arayüzü `http://localhost:8099` adresinde kullanılabilir olur.<br /><br />- <strong>Varsayılan:</strong> `80`</p> |
| `OVERLEAF_LOG_PATH`          | <p>Ana `sharelatex` konteynerine bağlanacak ve uygulama günlüklerini Docker ana bilgisayarında erişilebilir kılmak için kullanılacak dizinin yolunu ayarlar. Bu, tam bir yol (`/` ile başlayan) veya Toolkit'in temel dizinine göre göreli bir yol olabilir. Bind-mount'u devre dışı bırakmak için yapılandırma girdisini kaldırın. Ayarlanmadığında, konteyner yeniden oluşturulurken günlükler atılır.<br /><br />Günlük kaydı hakkında bilgi için bkz.<br /><br />- <strong>Varsayılan:</strong> ayarlanmamış</p> |

### `mongo`

| Ad                | Açıklama |
| ----------------- | -------- |
| `MONGO_ENABLED`   | <p>`true` olarak ayarlandığında Toolkit'e veritabanını barındırmak için bir MongoDB konteyneri oluşturmasını söyler. `false` olarak ayarlandığında bu konteyner oluşturulmaz ve sistem bunun yerine `MONGO_URL` ile belirtilen MongoDB veritabanını kullanır.<br /><br />- <strong>Varsayılan</strong>: `true`</p> |
| `MONGO_URL`       | <p>`MONGO_ENABLED` değeri `false` olduğunda kullanılacak MongoDB bağlantı URL'sini belirtir.<br /><br />- <strong>Varsayılan</strong>: ayarlanmamış</p> |
| `MONGO_DATA_PATH` | <p>`mongo` konteynerine bağlanacak ve MongoDB veritabanını saklamak için kullanılacak dizinin yolunu ayarlar. Bu, tam bir yol (`/` ile başlayan) veya toolkit'in temel dizinine göre göreli bir yol olabilir. Bu seçenek yalnızca `MONGO_ENABLED` değeri `true` olduğunda oluşturulan yerel `mongo` konteynerini etkiler.<br /><br />- <strong>Varsayılan</strong>: `data/mongo`</p> |
| `MONGO_IMAGE`     | <p>MongoDB konteyneri tarafından kullanılan Docker imajı. Bu yalnızca Docker imajının adıdır; Docker imajı etiketi `MONGO_VERSION` değişkenine yazılmalıdır (aşağıya bakın).<br /><br />- <strong>Varsayılan:</strong> `mongo`</p> |
| `MONGO_VERSION`   | <p>MongoDB konteyneri tarafından kullanılan MongoDB sürümü. Değer, ana MongoDB sürümü ve bir nokta ile başlamalıdır, ör. `6.0` veya `6.0-with-suffix`.<br /><br />- <strong>Varsayılan:</strong> `6.0`</p> |

### `redis`

| Ad                      | Açıklama |
| ----------------------- | -------- |
| `REDIS_ENABLED`         | <p>`true` olarak ayarlandığında Toolkit'e redis veritabanını barındırmak için bir Redis konteyneri oluşturmasını söyler. `false` olarak ayarlandığında bu konteyner oluşturulmaz ve sistem bunun yerine `REDIS_HOST` ve `REDIS_PORT` ile belirtilen Redis veritabanını kullanır.<br /><br />- <strong>Varsayılan</strong>: `true`</p> |
| `REDIS_HOST`            | <p>`REDIS_ENABLED` değeri `false` olduğunda kullanılacak Redis ana bilgisayarını belirtir.<br /><br />- <strong>Varsayılan</strong>: ayarlanmamış</p> |
| `REDIS_PORT`            | <p>`REDIS_ENABLED` değeri `false` olduğunda kullanılacak Redis bağlantı noktasını belirtir.<br /><br />- <strong>Varsayılan</strong>: ayarlanmamış</p> |
| `REDIS_DATA_PATH`       | <p>`redis` konteynerine bağlanacak ve Redis veritabanını saklamak için kullanılacak dizinin yolunu ayarlar. Bu, tam bir yol (`/` ile başlayan) veya Toolkit'in temel dizinine göre göreli bir yol olabilir. Bu seçenek yalnızca `REDIS_ENABLED` değeri `true` olduğunda oluşturulan yerel `redis` konteynerini etkiler.<br /><br />- <strong>Varsayılan</strong>: `data/redis`</p> |
| `REDIS_AOF_PERSISTENCE` | <p>Redis için AOF (Append Only File) kalıcılığını açar. Bu, Redis kalıcılığı için <strong>önerilen</strong> yapılandırmadır.<br /><br />Ek ayrıntılar için &#x3C;../../maintenance/data-and-backups> içindeki &#x3C;../../../maintenance/data-and-backups#aof-append-only-file> bölümüne bakın.<br /><br />- <strong>Varsayılan:</strong> `true`</p> |

### `nginx`

| Ad                     | Açıklama |
| ---------------------- | -------- |
| `NGINX_ENABLED`        | <p>`true` olarak ayarlandığında Toolkit'e TLS Proxy görevi görecek bir NGINX konteyneri oluşturmasını söyler.<br /><br />- <strong>Varsayılan</strong>: `false`</p> |
| `NGINX_CONFIG_PATH`    | <p>TLS Proxy için kullanılacak NGINX yapılandırma dosyasının yolu.<br /><br />- <strong>Varsayılan</strong>: `config/nginx/nginx.conf`</p> |
| `NGINX_TLS_LISTEN_IP`  | <p>TLS Proxy konteynerinin HTTPS için bağlanacağı ana bilgisayar IP adresini/adreslerini ayarlar. Örneğin bu değer `0.0.0.0` olarak ayarlanırsa HTTPS web arayüzü herhangi bir ana bilgisayar IP adresinde kullanılabilir olur. Genellikle bu değer ana bilgisayarınızın harici IP adresine ayarlanmalıdır.<br /><br />- <strong>Varsayılan</strong>: `127.0.1.1`</p> |
| `NGINX_HTTP_LISTEN_IP` | <p>TLS Proxy konteynerinin HTTP yönlendirmesi için bağlanacağı ana bilgisayar IP adresini/adreslerini ayarlar. Örneğin bu değer `127.0.1.1` olarak ayarlanırsa `127.0.1.1` adresine yapılan HTTP bağlantıları HTTPS web arayüzüne yönlendirilir. Genellikle bu değer ana bilgisayarınızın harici IP adresine ayarlanmalıdır. Genellikle `OVERLEAF_LISTEN_IP` ile çakışmaya neden olacağından `0.0.0.0` olarak ayarlamayın.<br /><br />- <strong>Varsayılan</strong>: `127.0.1.1`</p> |
| `NGINX_HTTP_PORT`      | <p>TLS Proxy konteynerinin HTTP için bağlanacağı ana bilgisayar bağlantı noktasını ayarlar.<br /><br />- <strong>Varsayılan</strong>: `80`</p> |
| `TLS_PORT`             | <p>TLS Proxy konteynerinin HTTPS için bağlanacağı ana bilgisayar bağlantı noktasını ayarlar.<br /><br />- <strong>Varsayılan</strong>: `443`</p> |
| `TLS_PRIVATE_KEY_PATH` | <p>TLS Proxy için kullanılacak özel anahtarın yolu.<br /><br />- <strong>Varsayılan</strong>: `config/nginx/certs/overleaf_key.pem`</p> |
| `TLS_CERTIFICATE_PATH` | <p>TLS Proxy için kullanılacak genel sertifikanın yolu.<br /><br />- <strong>Varsayılan</strong>: `config/nginx/certs/overleaf_certificate.pem`</p> |
