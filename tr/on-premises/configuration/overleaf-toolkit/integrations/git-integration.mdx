Git entegrasyonu şu anda [ayaka-notes/overleaf](https://github.com/ayaka-notes/overleaf) üzerinde mevcuttur.

<Info>

Bu özellik başlangıçta [ayaka-notes/ayakaleaf-pro](https://github.com/ayaka-notes/ayakaleaf-pro) tarafından geliştirilmiştir.

</Info>

<Steps>
<Step title="git-bridge'i etkinleştirin (Yalnızca Toolkit kullanıcıları için)">
Toolkit kullanıyorsanız `config/overleaf.rc` dosyanızda aşağıdakini ayarlayarak `git-bridge`'i etkinleştirin:

```text title="config/overleaf.rc"
GIT_BRIDGE_ENABLED=true
```
</Step>

<Step title="git-bridge konteynerini ekleyin (Yalnızca Docker-compose kullanıcıları için)">
Özel bir `docker-compose.yml` çalıştıran kullanıcılar, aşağıdaki konteyner yapılandırmasını compose dosyalarına eklemelidir:

```yaml title="docker-compose.yml (git-bridge service)" wrap
git-bridge:
    restart: always
    image: ghcr.io/ayaka-notes/overleaf-pro/git-bridge:6.3.2 # tag should match the `sharelatex` container tag
    volumes:
        - ~/git_bridge_data:/data/git-bridge
    container_name: git-bridge
    expose:
        - "8000"
    environment:
        GIT_BRIDGE_API_BASE_URL: "http://sharelatex:3000/api/v0/" 
        GIT_BRIDGE_OAUTH2_SERVER: "http://sharelatex"
        GIT_BRIDGE_POSTBACK_BASE_URL: "http://git-bridge:8000"
        GIT_BRIDGE_ROOT_DIR: "/data/git-bridge"
    user: root
    command: ["/server-pro-start.sh"]
```

`sharelatex` imajıyla aynı etiketi kullanın. [MCP Server](/tr/on-premises/configuration/overleaf-toolkit/mcp-server) (v6.3.1 ve sonrası) `sharelatex` imajının bir parçasıdır ve Git entegrasyonuyla birlikte etkinleştirilir; bu nedenle ek bir konteyner gerektirmez.
</Step>

<Step title="sharelatex konteyner yapılandırmasını güncelleyin">
Ayrıca `git-bridge` konteynerini `sharelatex` konteynerine bağlamanız ve aşağıdaki ortam değişkenlerini tanımlamanız gerekir; lütfen `V1_HISTORY_URL` değişkenine dikkat edin:

```yaml title="docker-compose.yml (sharelatex service)"
sharelatex:
    links:
        - git-bridge
    environment:
         GIT_BRIDGE_ENABLED: true
         GIT_BRIDGE_HOST: "git-bridge"
         GIT_BRIDGE_PORT: "8000"
         # We use v1 now, if you used to set V1_HISTORY_URL, please update now
         V1_HISTORY_URL: "http://sharelatex:3100/api"
```
</Step>

<Step title="İzleme ve kaynak hususları">
`git-bridge`'i etkinleştirdikten sonra ana makine kaynaklarınızı izlemenizi öneririz. Yük artışı şunlara bağlı olacaktır:

* özelliğe erişen kullanıcı sayısı

### Projeleri S3'e taşıma (swap)

Git entegrasyonu, bir kullanıcı tarafından klonlanan her proje için diskte eksiksiz bir git deposu depolar. Disk alanınız sınırlıysa, daha az kullanılan depoları AWS S3'e taşıyacak bir swap işini etkinleştirebilirsiniz. Taşınmış bir depoya yeniden ihtiyaç duyulursa diske geri taşınır. Aşağıdaki ortam değişkenleri swap işini kontrol eder:

| Ad                                    | Açıklama                                                                                                                                           |
| ------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| `GIT_BRIDGE_SWAPSTORE_TYPE`           | Swap işini etkinleştirmek için bunu "s3" olarak ayarlayın.                                                                                         |
| `GIT_BRIDGE_SWAPSTORE_AWS_ACCESS_KEY` | AWS erişim anahtarınız                                                                                                                             |
| `GIT_BRIDGE_SWAPSTORE_AWS_SECRET`     | AWS gizli anahtarınız                                                                                                                              |
| `GIT_BRIDGE_SWAPSTORE_S3_BUCKET_NAME` | Bu bucket, sıkıştırılmış (zip) git depolarını içerecektir                                                                                          |
| `GIT_BRIDGE_SWAPSTORE_AWS_REGION`     | Bucket'ın bölgesi                                                                                                                                  |
| `GIT_BRIDGE_SWAPJOB_MIN_PROJECTS`     | <p>Diskte en az kaç proje tutulacağı.<br /><br /><strong>- Varsayılan:</strong> 50</p>                                                              |
| `GIT_BRIDGE_SWAPJOB_LOW_GIB`          | <p>Swap için alt eşik değeri. Swap işi, disk kullanımı bu değerin altına inene kadar projeleri taşır.<br /><br /><strong>- Varsayılan:</strong> 128 GB</p> |
| `GIT_BRIDGE_SWAPJOB_HIGH_GIB`         | <p>Swap için üst eşik değeri. Swap işi, disk kullanımı bu değere ulaştığında taşımaya başlar.<br /><br /><strong>- Varsayılan:</strong> 256 GB</p> |
| `GIT_BRIDGE_SWAPJOB_INTERVAL_MILLIS`  | <p>Disk kullanımının kontrol edilmesi ve swap işinin çalıştırılması arasındaki süre.<br /><br /><strong>- Varsayılan:</strong> 3600000 ms = 1 saat</p> |

### S\&C

<Accordion title="Projemi başka biriyle paylaşırsam Git Bridge izin modeli nasıl çalışır?">

Salt okunur erişime sahip kullanıcılar bu projeyi yalnızca klonlayabilir; okuma-yazma erişimine sahip kullanıcılar projeleri klonlayabilir ve push edebilir. Not: Kullanıcıların bu projeye katılmak için oturum açmış olması gerekir.

</Accordion>

<Accordion title="Bir projeyi nasıl klonlarım ve hangi kullanıcı adı ile parolayı kullanırım?">

Düzenleyicide sol çubuktaki **Integrations** bölümünü açın ve **Git integration** öğesine tıklayın. Burada klonlama komutu şu biçimde gösterilir:

```sh
git clone https://<your-overleaf>/git/<project_id>
```

Git kimlik bilgilerini istediğinde kullanıcı adı olarak `git`, parola olarak da bir Kişisel Erişim Token'ı (Personal Access Token) girin. Token'ı **Account Settings** bölümünde oluşturun; bir yıl geçerlidir. Hesap parolanız çalışmaz.

Değişiklikler otomatik olarak senkronize edilmez: düzenleyicide yapılan değişiklikleri almak için `git pull`, kendi değişikliklerinizi göndermek için `git push` kullanın. `/git` yolu `sharelatex` konteyneri tarafından sunulur; bu nedenle önündeki bir reverse proxy için ek bir kural gerekmez.

</Accordion>

<Accordion title="`git push`, `HTTP 413` veya `curl 55 Broken pipe` hatasıyla başarısız oluyor">

Push, yükleme boyutu sınırından büyüktür. Bu sınır `MAX_UPLOAD_SIZE` ile ayarlanır (megabayt cinsinden, varsayılan `50`) ve push işlemleri için de geçerlidir. Bunu `config/variables.env` dosyasında artırın, örneğin `MAX_UPLOAD_SIZE=200`, ardından `bin/up -d` komutunu çalıştırın. [TLS proxy](/tr/on-premises/configuration/overleaf-toolkit/tls-proxy) veya kendi reverse proxy'nizi kullanıyorsanız, onun `client_max_body_size` değerini de artırın (Toolkit'in `config/nginx/nginx.conf` dosyasında `50M`).

git-bridge ayrıca 50 MB'tan büyük dosyaları ve 2.000'den fazla dosya içeren projeleri reddeder. Bu sınırlar `config/variables.env` dosyasındaki `GIT_BRIDGE_REPOSTORE_MAX_FILE_SIZE` (bayt cinsinden) ve `GIT_BRIDGE_REPOSTORE_MAX_FILE_NUM` ile ayarlanır.

</Accordion>
