### Overleaf i18n Yapılandırması

<Info>

Bu belge, kendi sunucunuzda barındırılan bir **Overleaf** örneği için uluslararasılaştırmanın (i18n) nasıl yapılandırılacağını açıklar.

</Info>

Overleaf birçok dile çevrilmiştir. Uygun yapılandırmayla şunları yapabilirsiniz:

* Overleaf örneğinizi **tek bir sabit dilde** çalıştırabilir veya
* `www.overleaf.com`'a benzer şekilde kullanıcıların dili dinamik olarak değiştirmesine olanak tanıyan **birden çok dili** etkinleştirebilirsiniz.

***

#### Tek Dil Yapılandırması

Site dili, `OVERLEAF_SITE_LANGUAGE` ortam değişkeni (Overleaf **4.x ve öncesi** sürümler için `SHARELATEX_SITE_LANGUAGE`) kullanılarak yapılandırılır.

Desteklenen dil kodları şunlardır:

* `en` - İngilizce (varsayılan)
* `es` - İspanyolca
* `pt` - Portekizce
* `de` - Almanca
* `fr` - Fransızca
* `cs` - Çekçe
* `nl` - Felemenkçe
* `sv` - İsveççe
* `it` - İtalyanca
* `tr` - Türkçe
* `zh-CN` - Çince (basitleştirilmiş)
* `no` - Norveççe
* `da` - Danca
* `ru` - Rusça
* `ko` - Korece
* `ja` - Japonca
* `pl` - Lehçe
* `fi` - Fince

Varsayılan dil İngilizcedir. Arayüz dilini değiştirmek için (örneğin Basitleştirilmiş Çince olarak), `config/variables.env` dosyasına aşağıdaki satırı ekleyin:

```bash title="config/variables.env"
OVERLEAF_SITE_LANGUAGE=zh-CN
```

Ardından yapılandırmayı uygulayın:

```bash
bin/up
```

Servisler yeniden başladıktan sonra, web arayüzü menülerindeki arayüz dili yeni ayarı yansıtmalıdır.

#### Çoklu Dil Yapılandırması

Kullanıcıların **oturumu kapatmadan dil değiştirebilmesi** için Overleaf örneğinizin alan adlarına göre farklı diller sunacak şekilde yapılandırılması gerekir.

Bu bölümde şunlar varsayılmaktadır:

* Birincil alan adınız `overleaftest.com`
* Bir **joker karakterli (wildcard) TLS sertifikanız** var (ör. `*.overleaftest.com`)
* **`localhost` kullanmıyorsunuz** (çünkü alt alan adı tabanlı dil yönlendirmesini destekleyemez)

Yerel testler için `dev-overleaf.com` gibi bir alan adı kullanabilirsiniz.

<Steps>
<Step title="TLS Proxy Yapılandırması (Nginx)">
Overleaf'in kullanıcının hangi dil alan adına eriştiğini belirleyebilmesi için TLS ters proxy'nizin orijinal `Host` başlığını iletmesi gerekir.

Aşağıdaki yönergenin mevcut olduğundan emin olun:

```nginx
proxy_set_header Host $host;
```

İşte örnek bir Nginx yapılandırması:

```nginx
server {
    listen 443 ssl;
    server_name    _; # Catch all, see http://nginx.org/en/docs/http/server_names.html
    server_name *.overleaftest.com;
    ssl_certificate /etc/nginx/ssl/nginx.crt;
    ssl_certificate_key /etc/nginx/ssl/nginx.key;
    ssl_protocols               TLSv1 TLSv1.1 TLSv1.2;
    ssl_prefer_server_ciphers   on;
    # used cloudflares ciphers https://github.com/cloudflare/sslconfig/blob/master/conf
    ssl_ciphers EECDH+CHACHA20:EECDH+AES128:RSA+AES128:EECDH+AES256:RSA+AES256:EECDH+3DES:RSA+3DES:!MD5;

    # config to enable HSTS(HTTP Strict Transport Security) https://developer.mozilla.org/en-US/docs/Security/HTTP_Strict_Transport_Security
    # to avoid ssl stripping https://en.wikipedia.org/wiki/SSL_stripping#SSL_stripping	
    add_header Strict-Transport-Security "max-age=31536000; includeSubdomains;";
    server_tokens off;
    add_header X-Frame-Options SAMEORIGIN;
    add_header X-Content-Type-Options nosniff;
    client_max_body_size 50M;

    location / {
        proxy_pass http://localhost:5000; # change to whatever host/port the docker container is listening on.
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_read_timeout 3m;
        proxy_send_timeout 3m;
        
        # add this to your nginx conf
        proxy_set_header Host $host;
    }
}
```
</Step>

<Step title="Çerez Alan Adını Yapılandırma">
Dil değiştirirken kullanıcıların oturumunun kapanmasını önlemek için çerezlerin dil alt alan adları arasında paylaşılması gerekir.

`config/variables.env` dosyasına aşağıdaki satırı ekleyin:

```env title="config/variables.env"
# Note the leading dot
COOKIE_DOMAIN=.overleaftest.com
```

Bu, kimlik doğrulama çerezlerinin `overleaftest.com` altındaki tüm alt alan adları için geçerli olmasını sağlar.
</Step>

<Step title="Dil–Alan Adı Eşlemesi">
Ardından, dil kodlarının alt alan adlarıyla nasıl eşleneceğini\
`OVERLEAF_LANG_DOMAIN_MAPPING` kullanarak tanımlayın.

#### Örnek Yapılandırma

```dotenv title="config/variables.env" wrap
OVERLEAF_LANG_DOMAIN_MAPPING='{"www": {"lngCode": "en","url": "https:\/\/www.overleaftest.com"},"cn": {"lngCode": "zh-CN","url": "https:\/\/cn.overleaftest.com"}}'
```

Bu yapılandırmayla:

* `https://www.overleaftest.com` → İngilizce arayüz
* `https://cn.overleaftest.com` → Basitleştirilmiş Çince arayüz

Bu eşlemeyi gerektiğinde ek diller ve alt alan adlarıyla genişletebilirsiniz.
</Step>

<Step title="Apex Alan Adını Yönlendirme">
Son olarak, apex alan adını (`overleaftest.com`) varsayılan dil alan adına (`www.overleaftest.com`) yönlendirin.

```nginx
server{
    listen 80;
    server_name overleaftest.com;
    return 301 https://www.overleaftest.com$request_uri;
}

server {
    listen 443 ssl http2;
    server_name overleaftest.com;
    ssl_certificate     /path/to/fullchain.cer;
    ssl_certificate_key /path/to/overleaftest.com.key;
    return 301 https://www.overleaftest.com$request_uri;
}
```
</Step>
</Steps>
