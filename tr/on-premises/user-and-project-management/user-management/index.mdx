## Yönetici kullanıcı oluşturma {#creating-an-administrator-user}

Overleaf Toolkit kurulumları:

```bash title="Overleaf Toolkit" wrap
$ bin/docker-compose exec sharelatex /bin/bash -ce "cd /overleaf/services/web && node modules/server-ce-scripts/scripts/create-user --admin --email=joe@example.com"
```

Eski docker-compose.yml kurulumları:

```bash title="Legacy docker-compose" wrap
$ docker exec sharelatex /bin/bash -ce "cd /overleaf/services/web && node modules/server-ce-scripts/scripts/create-user --admin --email=joe@example.com"
```

Komut, belirtilen e-posta adresine sahip kullanıcı henüz yoksa onu oluşturur ve yönetici yapar. Komut çıktısı, bu kullanıcı için parola belirleyip ilk kez giriş yapabileceğiniz bir URL içerir.

<Info>

Programatik bir yaklaşım için aynı betiği yöneticilerin yanı sıra normal kullanıcılar oluşturmak için de kullanabilirsiniz. Normal kullanıcılar için --admin bayrağını kullanmayın.

</Info>

Kimlik doğrulama için dahili hesaplar kullanıyorsanız ve mevcut bir kullanıcıyı örnek yöneticisi yapmanız veya yönetici izinlerini geri almanız gerekiyorsa şunları yapın:

<Steps>
<Step title="Yönetici arayüzü üzerinden">
* Mevcut bir yönetici olarak giriş yapın.
* Admin -> Manage Users'a tıklayın.
* Kullanıcıyı arayın ve e-posta adresine tıklayın.
* Site Admin bölümüne kadar aşağı kaydırın ve (show) bağlantısına tıklayın.
* Is Site Admin kutusunu işaretleyin.
* Bitirmek için Save'e tıklayın.
</Step>
</Steps>

## Kullanıcıları silme {#deleting-users}

Artık gerekli olmadıkça hesapları silmemeniz genellikle tavsiye edilir. Bir hesabı silmek hesabı kaldırır ve ortak çalışanların projelere erişimini kaybetmesine neden olur. Şu anda hesapları devre dışı bırakmanın bir yolu yoktur; hesaplar ya verileri korunarak var olmaya devam eder ya da silinir.

Varsayılan olarak hesaplar geçici olarak silinir (soft-delete). Kullanıcıları örneğinizden kalıcı olarak kaldırma hakkında bilgi için [Ortam değişkenleri](/tr/on-premises/configuration/overleaf-toolkit/environment-variables) kılavuzundaki `ENABLE_CRON_RESOURCE_DELETION` bölümüne bakın.

<Info>

Hesaplar varsayılan olarak geçici olarak silinir. Kalıcı silme davranışı için `ENABLE_CRON_RESOURCE_DELETION` bölümüne bakın.

</Info>

### Admin -> Manage Users üzerinden {#via-admin->-manage-users}

<Steps>
<Step title="">
* Yönetici olarak giriş yapın.
* Admin -> Manage Users'a tıklayın.
* Kullanıcıyı arayın ve e-posta adresinin yanındaki kutuyu işaretleyin.
* Çöp kutusu simgesine tıklayın.
* Onaylamak için Delete'e tıklayın.
</Step>
</Steps>

### Komut satırı üzerinden {#via-the-command-line}

Kullanıcı hesapları (ve projeleri) aşağıdaki komutlar kullanılarak silinebilir.

Overleaf Toolkit kurulumları:

```bash title="Overleaf Toolkit"
$ bin/docker-compose exec sharelatex /bin/bash -ce "cd /overleaf/services/web && node modules/server-ce-scripts/scripts/delete-user.mjs --email=joe@example.com"
```

Eski docker-compose.yml kurulumları:

```bash title="Legacy docker-compose"
$ docker exec sharelatex /bin/bash -ce "cd /overleaf/services/web && node modules/server-ce-scripts/scripts/delete-user.mjs --email=joe@example.com"
```

<Danger>

Silme betiği, hesap silme e-postası gönderilemese bile (ör. kullanıcının e-posta adresi artık kullanımda değilse) silme işleminin devam etmesini sağlayan sabit kodlanmış bir zorlama (force) seçeneği kullanır.

</Danger>

<Info>

Silinen kullanıcıya bilgilendirme e-postası gönderilmesini önlemek için --skip-email seçeneği kullanılabilir.

</Info>

## Geçici olarak silinmiş bir kullanıcıyı geri yükleme {#restoring-a-soft-deleted-user}

Bir kullanıcı yalnızca geçici olarak silinmişse, hesabını ve projelerini geri yükleyebilirsiniz.

<Steps>
<Step title="">
* Yönetici olarak giriş yapın.
* Admin -> Manage Users'a tıklayın.
* Geri yüklemek istediğiniz kullanıcıyı arayın.
* Display deleted users düğmesine tıklayın.
* Silinen kullanıcının e-posta adresine tıklayın.
* Recover This Account'a tıklayın.
* Onaylamak için Recover'a tıklayın.
</Step>
</Steps>

<Danger>

ENABLE\_CRON\_RESOURCE\_DELETION true olarak ayarlandığında, geçici olarak silinen hesaplar 90 günlük bir süre içinde geri yüklenebilir. 90 gün sonra hesap kurtarma mümkün değildir.

</Danger>

## Kullanıcıları sayma {#counting-users}

Kullanıcı sayılarını https://you-instance-url/admin/user#license adresindeki yönetici arayüzü üzerinden elde edebilirsiniz. Programatik kontroller ve dışa aktarmalar için aşağıdaki örnekler yardımcı olabilir.

Toplam kullanıcı sayısı:

```bash title="Total number of users"
echo 'db.users.countDocuments()' | docker exec -i mongo mongosh --quiet localhost/sharelatex
# overleaf [direct: primary] sharelatex> 16
```

Metrik uç noktası kullanılarak toplam kullanıcı sayısı:

```bash title="Num active users from metrics"
docker exec sharelatex curl http://127.0.0.1:3000/metrics | grep num_active_users
# # HELP num_active_users num_active_users
# # TYPE num_active_users gauge
# num_active_users{app="web-api",host="b3ae4ff549d8"} 16
```

Toplam aktif kullanıcı sayısı (örnek: son 365 gün içinde aktif olan kullanıcılar):

```bash title="Total number of active users"
echo 'db.users.countDocuments({ lastActive: { $gte: new Date(new Date().getTime() - (365 * 24 * 60 * 60 * 1000)) } })' | docker exec -i mongo mongosh --quiet localhost/sharelatex
# overleaf [direct: primary] sharelatex> 10
```

## Kullanıcı hesabı bilgilerini güncelleme {#updating-user-account-information}

Hesap güncellemelerinin nasıl yapılacağı SSO'nun etkin olup olmadığına bağlıdır.

* SSO kullanılmıyorsa:
  * Yöneticiler kullanıcı hesabı bilgilerini Admin -> Manage Users üzerinden değiştirebilir (e-posta, ad, soyad ve parola sıfırlama bağlantısı oluşturma).
  * Normal kullanıcılar kendi bilgilerini Account -> Account Settings üzerinden güncelleyebilir (parola değiştirme ve Git kimlik doğrulama tokenları oluşturma dahil).
* SSO kullanılıyorsa:
  * Ayakaleaf Pro, oturum açma sırasında kimlik doğrulama sistemine dayanarak kullanıcının adını ve soyadını güncelleyecek şekilde yapılandırılabilir.
  * OVERLEAF\_SAML\_UPDATE\_USER\_DETAILS\_ON\_LOGIN veya OVERLEAF\_LDAP\_UPDATE\_USER\_DETAILS\_ON\_LOGIN true olduğunda, https://your-instance-url/user/settings adresindeki kullanıcı bilgileri formu devre dışı bırakılır ve ad/soyad yalnızca kimlik yönetim sisteminizde ayarlanabilir.

Daha fazla ayrıntı için bakınız:

* [SAML 2.0 yapılandırması](/tr/on-premises/configuration/overleaf-toolkit/authentication/saml-authentication)
* [LDAP yapılandırması](/tr/on-premises/configuration/overleaf-toolkit/authentication/ldap-authentication)

### Soru\&Cevap {#q&a}

<Accordion title="SSO kullanıcılarını önceden, örneğin bir API ile oluşturabilir miyim?">

<strong>Yanıt:</strong> Bunun için bir HTTP API yoktur. Hesabı yukarıdaki `create-user` betiğiyle (`--admin` olmadan) veya **Admin → Manage Users** sayfasında **Create account** ile oluşturun. `EXTERNAL_AUTH` ayarlandığında bu formda bir **External authentication** seçeneği bulunur; bu seçenek hesabı yerel bir parola olmadan ve etkinleştirme e-postası göndermeden oluşturur. İlk LDAP, SAML veya OIDC oturum açmasında kullanıcı, yeni bir hesap yerine aynı e-posta adresine sahip mevcut hesabı alır, bkz. [Hesaplar ve parolalar](/tr/on-premises/configuration/overleaf-toolkit/authentication#accounts-and-passwords).

</Accordion>

<Accordion title="Kullanıcı listesini dışa aktarıp daha sonra geri yükleyebilir miyim?">

<strong>Yanıt:</strong> Hayır. Kullanıcı hesaplarını dışa veya içe aktarma özelliği ne **Admin → Manage Users** sayfasında ne de bir betik olarak bulunur. Hesaplar MongoDB'de depolanır; bu nedenle bunları bir [MongoDB yedeği](/tr/on-premises/maintenance/data-and-backups#mongodb) ile yedekleyin ve geri yükleyin. `export-user-projects.mjs` betiği hesapları değil, kullanıcıların projelerini zip dosyaları olarak dışa aktarır, bkz. [Projeleri dışa aktarma](/tr/on-premises/maintenance/data-and-backups/exporting-projects).

</Accordion>

<Accordion title="`create-user` bağlantısı ne kadar süre geçerlidir ve e-posta olmadan bir parolayı nasıl sıfırlarım?">

<strong>Yanıt:</strong> `create-user` komutunun yazdırdığı bağlantı 7 gün geçerlidir ve çıktıdan kopyaladığınız için SMTP olmadan da çalışır. Yeni bir bağlantı almak için `create-user` komutunu aynı e-postayla yeniden çalıştırın. Mevcut bir hesap için yalnızca yeni bir bağlantı yazdırır, ancak hesabın yönetici bayrağını da `--admin` ile eşleşecek şekilde ayarlar; bu nedenle bir yönetici için çalıştırırken `--admin` seçeneğini koruyun.

Bir yönetici parolayı doğrudan da ayarlayabilir: **Admin → Manage Users** içinde kullanıcının satırındaki **Update** düğmesine tıklayın, **Password** sekmesini açın ve en az 8 karakterlik yeni bir parola girin. Yalnızca LDAP, SAML veya OIDC üzerinden giriş yapan hesaplara orada parola verilemez.

</Accordion>
