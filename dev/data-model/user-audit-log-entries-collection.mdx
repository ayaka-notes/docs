title: User Audit Log Entries Collection
icon: user-clock
---

`userAuditLogEntries` is the audit log of user accounts: logins, password and email changes, linked accounts and admin actions. One document is one event on one account. `web` owns it; the schema is `services/web/app/src/models/UserAuditLogEntry.mjs`, and core writes through `services/web/app/src/Features/User/UserAuditLogHandler.mjs`.

#### Who Writes It

| Code                                                                        | What it does                                                                                                         |
| --------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| `UserAuditLogHandler.mjs:62-110` (`addEntry`)                               | Creates one entry. Throws when `operation` is missing, or when `ipAddress` or `initiatorId` is missing for an operation that needs it. |
| `UserAuditLogHandler.mjs:112-126` (`addEntryInBackground`)                  | Same, without waiting; errors are only logged.                                                                       |
| `services/web/modules/admin-tools/app/src/AdminAuditLog.mjs:14-38`          | Our admin panel: `logOnUser` writes admin actions on the target account with the admin as initiator; `logOnAdmin` writes on the admin's own account when the target has no log left (a purged user, a template). |
| `services/web/modules/authentication/auditLog.mjs:9-21`                     | Our LDAP, SAML and OIDC modules: `logLoginEntry` writes what an SSO login did to the account, with the account itself as initiator. |
| `services/web/app/src/Features/User/UserDeleter.mjs:141`                    | Deletes all entries of a deleted user when the deleted user expires (`expireDeletedUsersAfterDuration`).             |
| `AdminAuditLog.mjs:41-43` (`deleteUserEntries`)                             | Our admin panel deletes all entries of a user it purges (`services/web/modules/admin-tools/app/src/AdminUserManager.mjs:644`). |
| `tools/migrations/20220913125500_migrate_auditLog_to_collections.mjs`       | One-time migration: moved the old `users.auditLog` arrays into this collection.                                      |

#### Indexes

| Name                    | Keys                            | Options                                         | Migration                                                                 |
| ----------------------- | ------------------------------- | ----------------------------------------------- | ------------------------------------------------------------------------- |
| `timestamp_1`           | `{ timestamp: 1 }`              | TTL, `expireAfterSeconds: 78840000` (2.5 years) | `tools/migrations/20220913105500_create_auditLog_indexes.mjs`             |
| `userId_1_timestamp_-1` | `{ userId: 1, timestamp: -1 }`  |                                                 | `tools/migrations/20251117093546_add_timestamp_to_userAuditLogEntries.mjs` |

`tools/migrations/20220929193200_add_auditLog_indexes.mjs` first created `user_id_1` on `{ userId: 1 }`; `20251117093546` replaces it with the compound index. The schema marks `userId` and `managedSubscriptionId` with `index: true`, but Mongoose auto-indexing is off (`services/web/app/src/infrastructure/Mongoose.mjs:7`), so only the migrations above create indexes. The `managedSubscriptionId` index migration is tagged `saas` only.

#### Notes

* Entries expire 2.5 years after `timestamp` through the TTL index.
