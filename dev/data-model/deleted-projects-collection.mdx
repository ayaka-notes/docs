---
title: Deleted Projects Collection
icon: trash-can
---

`deletedProjects` keeps a project after it is deleted: one document per deleted project, with a copy of the whole project document and who deleted it. Web writes it in `services/web/app/src/Features/Project/ProjectDeleter.mjs`; the schema is `services/web/app/src/models/DeletedProject.mjs`. When the hard deletion delay has passed, the expiry destroys the project's data and empties `project`, but the record with `deleterData` stays.

A project in the trash is not here: trashing only adds the user to `trashed` of the project, see [Projects Collection](/dev/data-model/projects-collection).

#### Who Writes It

| Code | What it does |
| ---- | ------------ |
| `ProjectDeleter.mjs:189-293` (`deleteProject`) | Flushes the project, archives its docs out of Mongo, removes it from tags, upserts the record and deletes the `projects` document. |
| `ProjectDeleter.mjs:295-342` (`undeleteProject`) | Inserts the project again under the name `<name> (Restored)` (made unique for the owner) and no longer archived, then deletes the record. Fails with `project_too_old_to_restore` once `project` is `null`. Called from the admin panel: restore one project (`AdminProjectManager.mjs:497-515`) or restore a deleted user with the projects deleted with the account (`services/web/modules/admin-tools/app/src/AdminUserManager.mjs:678-689`). |
| `ProjectDeleter.mjs:344-416` (`expireDeletedProject`) | Destroys the docs, history, chat and project audit log of the project and fires the `projectExpired` hook, then sets `project` and `deleterData.deleterIpAddress` to `null`. If the project exists again, it only deletes the stale record. |
| `ProjectDeleter.mjs:97-146` (`expireDeletedProjectsAfterDuration`) | Expires a batch of records older than the delay. Route `POST /internal/expire-deleted-projects-after-duration` (`services/web/app/src/router.mjs:842-846`), which the Community Edition cron calls every hour at minute 20 when `ENABLE_CRON_RESOURCE_DELETION` is `true` (`server-ce/cron/delete-projects.sh:10-23`, `server-ce/config/crontab-deletion:3`). One project: `POST /internal/project/:projectId/expire-deleted-project` (`router.mjs:852-856`), or Purge in the admin panel (`AdminProjectManager.mjs:517-529`). |

#### Notes

* Modules that listen to `projectExpired` delete their own data of the project: `git-bridge` (`services/web/modules/git-bridge/index.mjs:37`), `github-sync` (`services/web/modules/github-sync/index.mjs:56`), `gitlab-sync` (`services/web/modules/gitlab-sync/index.mjs:46`), `gitea-sync` (`services/web/modules/gitea-sync/index.mjs:46`) and `dropbox` (`services/web/modules/dropbox/index.mjs:54`).
* An expired record is never deleted: `deleterData` stays for good, only `project` and the IP address are emptied.
* Mongoose also gives `deleterData` its own `_id`, which nothing reads.
