`rooms` holds one document per chat room of a project: the project chat, or one review comment thread. Only the chat service writes it, in `services/chat/app/js/Features/Threads/ThreadManager.js`. There is no Mongoose schema. The messages of a room are in the [messages](/dev/data-model/messages-collection) collection.

#### Fields

| Field | Type | Meaning | Source |
| ----- | ---- | ------- | ------ |
| `_id` | ObjectId | Room id. `messages.room_id` points here. | `ThreadManager.js:57-61` |
| `project_id` | ObjectId | Project the room belongs to. | `ThreadManager.js:43-54` |
| `thread_id` | ObjectId | Only on comment threads: the id of the comment, the same as `id` and `op.t` of the comment in `docs.ranges.comments` (see [docs](/dev/data-model/docs-collection)). Missing on the project chat room. | `ThreadManager.js:38-55`, `services/docstore/app/js/RangeManager.js:54-57` |
| `resolved` | Object | Set when the thread is resolved, removed when it is reopened. A thread without it is open. | `ThreadManager.js:94-123` |
| `resolved.user_id` | String | Id of the user who resolved the thread. Stored as a string, not an ObjectId: the request body is only checked to be a valid id, not converted. | `ThreadManager.js:103`, `services/chat/app/js/Features/Messages/MessageHttpSchemas.js:70` |
| `resolved.ts` | Date | When the thread was resolved. | `ThreadManager.js:104` |

#### Who Writes It

| Code | What it does |
| ---- | ------------ |
| `ThreadManager.js:31-63` `findOrCreateThread` | Upserts the room. Runs on every send, read, edit and delete of messages (`services/chat/app/js/Features/Messages/MessageHttpController.js:183,204,227,236,245,280,301`), so the first message of a comment creates its thread room, and reading the project chat creates the project chat room. |

| `ThreadManager.js:111-123` `reopenThread` | Removes `resolved`. Same callers: `TrackChangesController.mjs:160`, `RestoreManager.mjs:285`, `CommentTools.mjs:183`. |
| `ThreadManager.js:154-172` `duplicateThread` | Inserts a new room with a new `thread_id`, copying `resolved`. Used when a doc is restored from history (`RestoreManager.mjs:233`). |
| `ThreadManager.js:12-29` `cloneThreads` | Copies every thread room of a project to another project, with a new `_id` and the same `thread_id`. Used when a project is copied with its ranges (`services/web/app/src/Features/Project/ProjectDuplicator.mjs:197`). |

#### Notes

* A project has at most one room without `thread_id`, the project chat. The chat service finds it with `thread_id: { $exists: false }` (`ThreadManager.js:38-45`).
* The resolved state of a comment lives only here. Docstore strips `op.resolved` before it saves ranges (`services/docstore/app/js/RangeManager.js:59-61`).
* After a project copy, the same `thread_id` exists in two projects. Always query by `project_id` and `thread_id` together, as the chat service does.
* Rooms of a deleted project stay until the deleted project expires.
