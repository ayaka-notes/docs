---
title: Deleted Users Collection
icon: user-xmark
---

`deletedUsers` keeps a user account after it is deleted: one document per deleted account, with a copy of the whole user document and who deleted it. Web writes it in `services/web/app/src/Features/User/UserDeleter.mjs`; the schema is `services/web/app/src/models/DeletedUser.mjs`. When the hard deletion delay has passed, the expiry removes the copy of the user, but the record with `deleterData` stays.

Deleting a user also deletes the projects the user owns; they go to [Deleted Projects](/dev/data-model/deleted-projects-collection) with the reason `account-deletion`.

#### Who Writes It

| Code | What it does |
| ---- | ------------ |
| `UserDeleter.mjs:37-80` (`deleteUser`) | Adds a `delete-account` audit log entry, cleans up the user and fires the `deleteUser` hook, upserts the record (`_createDeletedUser`, `UserDeleter.mjs:192-213`), deletes the user's projects, sends the security alert email unless skipped, and deletes the `users` document. Callers: the account settings page (`services/web/app/src/Features/User/UserController.mjs:280-284`), the admin panel (`services/web/modules/admin-tools/app/src/AdminUserManager.mjs:604-612`) and the `delete-user` script (`delete-user.mjs:40-45`). |
| `UserDeleter.mjs:93-115` (`expireDeletedUser`) | Fires the `expireDeletedUser` hook, deletes the user's onboarding data, then removes `user` and `deleterData.deleterIpAddress`. |
| `UserDeleter.mjs:117-161` (`expireDeletedUsersAfterDuration`) | Expires every record older than the delay and deletes the user's `userAuditLogEntries`. Route `POST /internal/expire-deleted-users-after-duration` (`services/web/app/src/router.mjs:847-851`), which the Community Edition cron calls every hour at minute 15 when `ENABLE_CRON_RESOURCE_DELETION` is `true` (`server-ce/cron/delete-users.sh:10-23`, `server-ce/config/crontab-deletion:2`). One user: `POST /internal/users/:userId/expire` (`router.mjs:857-861`). |
| `AdminUserManager.mjs:630-649` (`purgeDeletedUser`, module `admin-tools`) | Purge in the admin panel: runs `expireDeletedUser` and deletes the user's audit log entries. |
| `AdminUserManager.mjs:651-696` (`restoreDeletedUser`, module `admin-tools`) | Restore in the admin panel: creates the `users` document again from `user` (refused if the email is taken), deletes the record, and restores the projects deleted with the account. |

#### Notes

* Modules that listen to `expireDeletedUser` delete their own data of the user: `dropbox` (`services/web/modules/dropbox/index.mjs:62`), `github-sync` (`services/web/modules/github-sync/index.mjs:66`), `gitlab-sync` (`services/web/modules/gitlab-sync/index.mjs:56`) and `gitea-sync` (`services/web/modules/gitea-sync/index.mjs:56`).
* An expired record is never deleted: `deleterData` stays for good, only `user` and the IP address are removed.
* The user's personal access tokens are not deleted with the account, see [OAuth Access Tokens](/dev/data-model/oauth-access-tokens-collection).
* Mongoose also gives `deleterData` its own `_id`, which nothing reads.
