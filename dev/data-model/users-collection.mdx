title: Users Collection
icon: user
---

`users` holds one document per account. It stores login data, the profile, editor settings, features and activity. The schema is `services/web/app/src/models/User.mjs`; most writes go through `services/web/app/src/Features/User/UserUpdater.mjs`. In the Source column, `User.mjs:N` is a line of that schema, other bare file names are under `services/web/app/src/Features/`, and `modules/...` is under `services/web/`. Line numbers are from `server-pro` at the time of writing.

#### Feature Flags & Limits (`features`)

`features` is the result of a computation, not something to edit by hand. `FeaturesUpdater` starts from `Settings.defaultFeatures`, merges every `featuresOverrides` entry that has not expired, and writes the result with `featuresUpdatedAt` (`FeaturesUpdater.mjs:220-300`, `UserFeaturesUpdater.mjs:10-24`). The production image sets `collaborators`, `dropbox`, `versioning`, `compileTimeout`, `compileGroup`, `trackChanges` and `references` as defaults (`server-ce/config/settings.js:301-309`); the other keys stay unset.

In Ayakaleaf Pro the admin panel turns features off per user. The `admin-tools` module stores them as a `featuresOverrides` entry with `note: 'admin-panel'` (`modules/admin-tools/app/src/AdminFeatures.mjs:13-30`), and the `instance-features` module treats an unset key as on (`modules/instance-features/app/src/UserFeatures.mjs:12-14`).

| `features.dropbox` / `github` / `gitBridge` | Boolean | Dropbox sync, GitHub sync and Git access. Checked by those modules, see `requireUserFeature`. The migration `20230817081910_back_fill_gitBridge_feature_server_pro` set `gitBridge: true` for all users. | `User.mjs:127-129` |

#### Notes

* Mongoose `autoIndex` is off (`services/web/app/src/infrastructure/Mongoose.mjs:7`), so only the migrations above create indexes.
* Deleting a user moves the whole document into `deletedUsers` (see [Deleted Users Collection](/dev/data-model/deleted-users-collection)).
