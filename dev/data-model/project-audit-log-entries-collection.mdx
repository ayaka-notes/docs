`projectAuditLogEntries` is the audit log of projects: sharing, invites, ownership transfers, downloads and admin actions. One document is one event on one project. `web` owns it; the schema is `services/web/app/src/models/ProjectAuditLogEntry.mjs`, and core writes through `services/web/app/src/Features/Project/ProjectAuditLogHandler.mjs`.

#### Fields

| Field                   | Type     | Meaning                                                                                                                                         | Source                          |
| ----------------------- | -------- | ----------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------- |
| `_id`                   | ObjectId | Entry id.                                                                                                                                       | `ProjectAuditLogEntry.mjs:4`    |
| `projectId`             | ObjectId | The project the event is about.                                                                                                                 | `ProjectAuditLogEntry.mjs:6`    |
| `operation`             | String   | What happened, a kebab-case name such as `send-invite` (see the table below).                                                                    | `ProjectAuditLogEntry.mjs:8`    |
| `initiatorId`           | ObjectId | The user who did it, or the admin for admin actions.                                                                                            | `ProjectAuditLogEntry.mjs:9`    |
| `ipAddress`             | String   | IP address of the request (`req.ip`).                                                                                                           | `ProjectAuditLogEntry.mjs:10`   |
| `timestamp`             | Date     | When the entry was written (default `Date.now`).                                                                                                | `ProjectAuditLogEntry.mjs:11`   |
| `info`                  | Object   | Details of the event; the keys depend on the operation.                                                                                         | `ProjectAuditLogEntry.mjs:12`   |
| `managedSubscriptionId` | ObjectId | Managed group subscription of a user involved. Only found when the `saas` feature is on (`services/web/app/src/Features/Subscription/SubscriptionLocator.mjs:111-112`), so never in CE. | `ProjectAuditLogEntry.mjs:7` |
| `__v`                   | Number   | Mongoose version key, added by `ProjectAuditLogEntry.create`.                                                                                   | `ProjectAuditLogHandler.mjs:103` |

#### Who Writes It

| Code                                                                       | What it does                                                                                                                 |
| -------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| `ProjectAuditLogHandler.mjs:80-105` (`addEntry`), `:157-171` (`addEntryInBackground`) | Creates one entry (one per managed subscription involved, which only happens with `saas`).                         |
| `ProjectAuditLogHandler.mjs:120-150` (`addEntryIfManaged`), `:175-190`     | Writes only when a managed subscription is involved. In CE that lookup always returns nothing, so these calls write no entry. |
| `services/web/modules/admin-tools/app/src/AdminAuditLog.mjs:24-32` (`logOnProject`) | Our admin panel writes admin actions with the admin as initiator.                                                   |
| `services/web/app/src/Features/Project/ProjectDeleter.mjs:392`             | Deletes all entries of a project when the deleted project expires (`expireDeletedProject`, `ProjectDeleter.mjs:344`).        |
| `tools/migrations/20220913125500_migrate_auditLog_to_collections.mjs`      | One-time migration: moved the old `projects.auditLog` arrays into this collection.                                           |

#### Indexes

| Name                       | Keys                              | Options                                         | Migration                                                                        |
| -------------------------- | --------------------------------- | ----------------------------------------------- | -------------------------------------------------------------------------------- |
| `timestamp_1`              | `{ timestamp: 1 }`                | TTL, `expireAfterSeconds: 78840000` (2.5 years) | `tools/migrations/20220913105500_create_auditLog_indexes.mjs`                    |
| `projectId_1_timestamp_-1` | `{ projectId: 1, timestamp: -1 }` |                                                 | `tools/migrations/20250912102601_add_timestamp_to_projectAuditLogEntries_index.mjs` |

`tools/migrations/20220929193200_add_auditLog_indexes.mjs` first created `project_id_1` on `{ projectId: 1 }`; `20250912102601` replaces it with the compound index. The schema's `index: true` marks are not applied, as Mongoose auto-indexing is off (`services/web/app/src/infrastructure/Mongoose.mjs:7`). The `managedSubscriptionId` index migration is tagged `saas` only.

#### Notes

* Entries expire 2.5 years after `timestamp` through the TTL index, and all entries of a project go when its deleted-project record expires.
