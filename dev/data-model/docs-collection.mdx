---
title: Docs Collection
icon: file-lines
---

`docs` holds the content of the editable text files of a project (Overleaf calls them docs), for example `main.tex` or `sample.bib`. One document per doc: its lines, its comments and tracked changes, two counters and the deletion state. The file name and place in the tree are not here but in `projects.rootFolder` (see [Projects Collection](/dev/data-model/projects-collection)). Binary files are not here either.

Apart from migrations and maintenance scripts, only docstore writes this collection, in `services/docstore/app/js/MongoManager.js`. There is no Mongoose model; web and document-updater reach it through the docstore HTTP API (`services/docstore/app.js:31-70`). In the Source column, bare file names are under `services/docstore/app/js/`.

#### Ranges

`ranges` has two arrays. document-updater builds them with `libraries/ranges-tracker/index.cjs`; docstore turns ids into ObjectIds and `ts` into Dates before saving (`RangeManager.js:41-63`). A doc without comments or tracked changes has `ranges: {}` or no `ranges`.

| Field | Type | Meaning | Source |
| ----- | ---- | ------- | ------ |
| `ranges.comments` | Array of Object | Commented text spans. | `libraries/ranges-tracker/index.cjs:217-236` |
| `ranges.comments.id` | ObjectId | Comment id. It equals `op.t`, the thread id of the comment in the `rooms` collection; docstore forces them to match. | `RangeManager.js:54-57` |
| `ranges.comments.op.c` | String | The commented text in the doc (not the comment message). | `index.cjs:226-230` |
| `ranges.comments.op.p` | Number | Character offset of the start of `op.c` in the doc. | `index.cjs:226-230` |
| `ranges.comments.op.t` | ObjectId | Thread id, see `id`. | `index.cjs:226-230`, `RangeManager.js:57` |
| `ranges.comments.metadata` | Object | `user_id` and `ts` of the comment. | `index.cjs:232`, `RangeManager.js:62` |
| `ranges.changes` | Array of Object | Tracked changes, sorted by position. | `index.cjs:640-660` |
| `ranges.changes.id` | ObjectId | Id of the change. | `index.cjs:643-647`, `RangeManager.js:51` |
| `ranges.changes.op.i` / `op.d` | String | Inserted text, or deleted text. One of the two. | `index.cjs:640-660` |
| `ranges.changes.op.p` | Number | Character offset of the change. | `index.cjs:640-660` |
| `ranges.changes.metadata.user_id` | ObjectId or String | Author. Changes made by anonymous editors keep the string `anonymous-user`. | `RangeManager.js:45-46`, `DocManager.js:192` |
| `ranges.changes.metadata.ts` | Date | When the change was made. | `RangeManager.js:42-43` |

The text of a comment and its replies is not in `docs`: it is in the `messages` collection, in the room whose `thread_id` is the comment id. Whether a comment is resolved is stored on that room, not here; docstore drops a `resolved` flag if one is sent (`RangeManager.js:59-61`). See [Rooms Collection](/dev/data-model/rooms-collection) and [Messages Collection](/dev/data-model/messages-collection).

#### Who Writes It

| Code | What it does |
| ---- | ------------ |
| `DocManager.js:223-338` (`POST /project/:project_id/doc/:doc_id`) | Creates or updates a doc: `lines`, `ranges` and `version`. web calls it when a doc is created and when document-updater flushes an open doc (`services/web/app/src/Features/Project/ProjectEntityUpdateHandler.mjs:174`). |
| `DocManager.js:346-366` (`PATCH /project/:project_id/doc/:doc_id`) | Marks a doc as deleted with `deleted`, `deletedAt` and `name`. |
| `DocArchiveManager.js:29-88` | Archives a doc: copies `lines`, `ranges` and `rev` to the persistor and sets `inS3`. Runs for a whole project when it is deactivated, and for a single doc on delete when `ARCHIVE_ON_SOFT_DELETE=true` (`DocManager.js:355-363`). |
| `DocArchiveManager.js:150-174` | Brings an archived doc back into Mongo when it is read (`DocManager.js:40-41`). |
| `MongoManager.js:272-274` | Deletes all docs of a project when the project is destroyed. |

#### Who Reads It

| Code | What it does |
| ---- | ------------ |
| `services/document-updater/app/js/PersistenceManager.js:18-30` | Loads a doc (through web) when someone opens it. |
| `services/web/app/src/Features/Docstore/DocstoreManager.mjs` | All web reads: one doc, all docs of a project, all ranges, deleted docs. |
| `services/web/app/src/Features/Project/ProjectDuplicator.mjs:49` | Copies a project; flushes document-updater first. |
| `services/web/modules/admin-tools/app/src/AdminProjectManager.mjs:395-413` | Lists the deleted docs of a project in the admin panel. |

#### Notes

* While a doc is open, its newest text is in document-updater (Redis), not here. Mongo is only updated when document-updater flushes (`services/document-updater/app/js/PersistenceManager.js:128-160`). Code that reads the docs of a whole project should call `flushProjectToMongo` first, as `ProjectDuplicator` does.
* Deleted docs stay in this collection, with `deleted: true`, until the project is destroyed. docstore returns at most `MAX_DELETED_DOCS` (default 2000) of them, newest first (`MongoManager.js:29-44`, `services/docstore/config/settings.defaults.cjs:40`). The history panel does not use them; it reads history-v1.
* The `rev` and `version` counters are unrelated to project history versions in history-v1.
