`templates` holds one document per template in the template gallery. The files of a template (the project zip and the PDF) are not here: they are kept in filestore under `template/<_id>/v/<version>/`. The collection belongs to the `template-gallery` web module (`services/web/modules/template-gallery`). The schema is the Mongoose model `Template` in `services/web/modules/template-gallery/app/src/models/Template.mjs`; the logic is in `services/web/modules/template-gallery/app/src/TemplateGalleryManager.mjs` and `TemplateGalleryHelper.mjs` next to it.

#### Who Writes It

| Code | What it does |
| ---- | ------------ |
| `TemplateGalleryManager.mjs:53-97` (`createTemplateFromProject`) | `POST /template/new/:Project_id`. It copies the project's settings (`TemplateGalleryHelper.mjs:94-134`), uploads the zip and the PDF to filestore, and saves. If the name is taken it answers with a conflict, unless the client asked to override: then it updates that template and raises its `version`, then deletes the files of the previous version. |
| `TemplateGalleryManager.mjs:21-47` (`editTemplate`) | `POST /template/:template_id/edit`. It assigns the posted fields to the document, renders `description` and `author` again, and sets `lastUpdated`. The edit form posts the changed fields among `name`, `license`, `category`, `language`, `authorMD` and `descriptionMD` (`services/web/modules/template-gallery/frontend/js/pages/template/util/api.ts:22-29`). |
| `TemplateGalleryHelper.mjs:186-222` (`deleteTemplateAssets`) | `DELETE /template/:template_id/delete` deletes the document and the files of the given version (`TemplateGalleryManager.mjs:49-51`). |

Only site admins and the user in `OVERLEAF_TEMPLATES_USER_ID` may call these three routes (`services/web/modules/template-gallery/app/src/Router.mjs:55-62,70-84`, `PermissionsMiddleware.mjs:8-19`).

#### Who Reads It

| Code | What it does |
| ---- | ------------ |
| `TemplateGalleryManager.mjs:158-183` (`getTemplate`) | Finds one template by `_id` or `name` for the template page and for `GET /api/template` (`services/web/modules/template-gallery/app/src/TemplateGalleryController.mjs:210-232`). If `project_id` points to a project that no longer exists, the answer leaves it out; the document is not changed. |
| `TemplateGalleryManager.mjs:190-236` (`getCategoryTemplates`) | `GET /api/templates`: one page of a category, searched in `name`, `authorMD` and `descriptionMD`, sorted by `lastUpdated` or by `name` (case-insensitive). |
| `TemplateGalleryHelper.mjs:64-80` (`canUserOverrideTemplate`) | Reads `owner` to name the owner in the conflict message. |

#### Indexes

| Name | Keys | Options | Migration |

| `_id_` | `_id: 1` | | default |

Mongoose `autoIndex` is off (`services/web/app/src/infrastructure/Mongoose.mjs:7`). `tools/migrations/20190912145030_create_templates_indexes.mjs` (unique `project_id`, `user_id`, `name`) is tagged `server-pro` and `saas`, so it does not run in CE, which runs only the `server-ce` migrations (`server-ce/init_scripts/900_run_web_migrations.sh`).

#### Notes

* Upstream treats `templates` as a stale collection and drops it on its own site (`tools/migrations/20241002180623_drop_unused_collections.mjs`, tagged `saas`). In Ayakaleaf Pro the template gallery module uses it.
* Sorting by name uses a case-insensitive collation, and the comment at `TemplateGalleryManager.mjs:186-188` notes that a `name` index would need the same one. CE has no `name` index, so Mongo sorts in memory.
* Deleting the source project or the owner does not delete the template.
