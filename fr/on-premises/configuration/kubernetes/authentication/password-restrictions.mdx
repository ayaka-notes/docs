---

Le service **web** vérifie les mots de passe locaux lorsque les utilisateurs s'inscrivent, définissent ou modifient un mot de passe. Les connexions SSO (LDAP, SAML, OIDC) ne sont pas concernées : leurs mots de passe relèvent du fournisseur d'identité. Voir [Restrictions sur les mots de passe](/fr/on-premises/configuration/overleaf-toolkit/authentication/password-restrictions) pour le Toolkit.

| | |
| --- | --- |
| Service | web, dans chaque pod Ayakaleaf Pro ; lu au démarrage de web |
| Réseau | aucun |
| Tâches périodiques | aucune |

### Configuration

Ajoutez à la ConfigMap `overleaf-env` et redémarrez :

```yaml title="30-config.yaml (additions)"
  OVERLEAF_PASSWORD_VALIDATION_MIN_LENGTH: "12"
  OVERLEAF_PASSWORD_VALIDATION_MAX_LENGTH: "72"
```

```bash
kubectl apply -f 30-config.yaml
kubectl -n overleaf rollout restart deployment/overleaf     # or statefulset/overleaf
```

| Variable | Valeur par défaut | |
| --- | --- | --- |
| `OVERLEAF_PASSWORD_VALIDATION_MIN_LENGTH` | `8` | Longueur minimale de mot de passe acceptée. |
| `OVERLEAF_PASSWORD_VALIDATION_MAX_LENGTH` | `72` | Longueur maximale de mot de passe acceptée ; les valeurs supérieures à `72` sont traitées comme `72`. |

Mettez les nombres entre guillemets : une ConfigMap ne contient que des chaînes.

<Warning>

`OVERLEAF_PASSWORD_VALIDATION_PATTERN` est lu mais pas appliqué : un mot de passe qui ne le respecte pas est accepté. Seules les limites de longueur s'appliquent.

</Warning>

### Plusieurs réplicas

Rien de plus : chaque réplica lit la même ConfigMap.

### Testé sur Kubernetes

Sur Kubernetes 1.37 avec un réplica, `OVERLEAF_PASSWORD_VALIDATION_MIN_LENGTH: "12"` et `OVERLEAF_PASSWORD_VALIDATION_PATTERN: aA$3` dans la ConfigMap, l'activation d'un nouveau compte a refusé un mot de passe de 10 caractères et accepté un mot de passe de 20 caractères composé uniquement de minuscules, que le motif aurait refusé. Nos tests de bout en bout pour l'inscription refusent également `123456` comme trop court avec les valeurs par défaut.
