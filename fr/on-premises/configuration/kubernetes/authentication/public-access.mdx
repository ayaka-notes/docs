L'accès invité aux projets partagés, les pages publiques et l'inscription libre s'activent avec des variables d'environnement lues par le service **web** ; le service real-time sert ensuite les invités via leur session. Ce que chaque option ouvre est décrit dans [Accès public](/fr/on-premises/configuration/overleaf-toolkit/authentication/public-access).

| | |
| --- | --- |
| Service | web (et real-time pour les invités dans l'éditeur), dans chaque pod Ayakaleaf Pro ; lu au démarrage de web |
| Pod → extérieur | le serveur SMTP, lorsque l'inscription envoie des e-mails d'activation |
| État | les jetons d'accès invité dans la session, les limites de débit d'inscription dans Redis |
| Tâches périodiques | aucune |

### Configuration

Ajoutez les options dont vous avez besoin à la ConfigMap `overleaf-env` :

```yaml title="30-config.yaml (additions)"
  # Guests open link-shared projects without an account
  OVERLEAF_ALLOW_ANONYMOUS_READ_AND_WRITE_SHARING: "true"
  # Signed-out visitors may open /learn, /templates, /devs and view links
  OVERLEAF_ALLOW_PUBLIC_ACCESS: "true"
  # Self-registration: "true", or only some domains
  OVERLEAF_ALLOW_PUBLIC_REGISTRATION: "@example.com, @*.uni.example"
```

```bash
kubectl apply -f 30-config.yaml
kubectl -n overleaf rollout restart deployment/overleaf     # or statefulset/overleaf
```

Mettez chaque valeur entre guillemets. Les valeurs qui commencent par `@` doivent être entre guillemets en YAML, sinon `kubectl apply` rejette le fichier.

L'inscription limitée à certains domaines envoie un e-mail d'activation ; l'[envoi des e-mails](/fr/on-premises/configuration/kubernetes/email-delivery) doit donc fonctionner depuis les pods : placez l'hôte SMTP dans la ConfigMap et `OVERLEAF_EMAIL_SMTP_PASS` dans le Secret.

### Plusieurs réplicas

Rien de plus. L'accès d'un invité à un projet est conservé dans la session dans Redis ; l'éditeur fonctionne donc quel que soit le réplica choisi par le répartiteur de charge.

### Testé sur Kubernetes

Sur Kubernetes 1.37, nos tests de bout en bout pour l'accès public réussissent : sur un réplica, l'inscription libre avec `OVERLEAF_ALLOW_PUBLIC_REGISTRATION` défini à `true`, à un domaine, à plusieurs domaines avec un joker de sous-domaine et à `@*`, avec l'e-mail d'activation pour les modes par domaine (43 cas) ; les visiteurs non connectés sur `/devs` et un extrait publié conservé au travers de la connexion avec `OVERLEAF_ALLOW_PUBLIC_ACCESS` (2 cas) ; un invité non connecté dans un projet partagé par lien avec les deux options activées (3 cas) ; et, sur trois réplicas derrière HAProxy, OIDC combiné à l'accès public (1 cas).
