Un déploiement Kubernetes lit les mêmes variables d'environnement que le Toolkit. Lorsqu'une page du Toolkit indique « ajoutez ceci à `config/variables.env` », placez la valeur dans la ConfigMap `overleaf-env`, ou dans le Secret `overleaf-secrets` s'il s'agit d'un mot de passe, d'une clé ou d'un jeton. Redémarrez ensuite :

```bash
kubectl -n overleaf apply -f 30-config.yaml        # after editing the ConfigMap
kubectl -n overleaf patch secret overleaf-secrets --type merge \
  -p '{"stringData":{"GITHUB_TOKEN_CIPHER_PASSWORD":"'"$(openssl rand -hex 32)"'"}}'
kubectl -n overleaf rollout restart deployment/overleaf
```

Les valeurs de `config/overleaf.rc` sont des paramètres du Toolkit, et non des variables d'environnement ; les questions-réponses à la fin de cette page indiquent ce qui les remplace.

### Certificats et autres fichiers

Certaines fonctionnalités attendent un chemin de fichier au lieu d'une valeur : les certificats SAML (`OVERLEAF_SAML_IDP_CERT`, ...), la CA LDAP (`OVERLEAF_LDAP_TLS_OPTS_CA_PATH`), ou une CA privée pour un GitHub Enterprise, GitLab ou Gitea auto-hébergé (`NODE_EXTRA_CA_CERTS`). Placez les fichiers dans un Secret et montez-le à l'endroit où les pages du Toolkit les attendent, `/var/lib/overleaf/certs` :

```bash
kubectl -n overleaf create secret generic overleaf-certs --from-file=idp_cert.pem --from-file=ca.pem
```

```yaml title="40-overleaf.yaml (additions)"
          volumeMounts:
            # ...
            - name: certs
              mountPath: /var/lib/overleaf/certs
              readOnly: true
      volumes:
        # ...
        - name: certs
          secret:
            secretName: overleaf-certs
```

Référencez-les ensuite par leur chemin dans la ConfigMap, par exemple `NODE_EXTRA_CA_CERTS: /var/lib/overleaf/certs/ca.pem`, puis redémarrez.

<Warning>

<strong>Mots de passe de chiffrement.</strong> Définissez dans le Secret chaque `*_CIPHER_PASSWORD` des fonctionnalités que vous utilisez. Sinon, certaines fonctionnalités génèrent un fichier de clé dans le volume de données lors de leur première utilisation : avec un seul réplica, cela fonctionne jusqu'à la perte du volume ; avec plusieurs réplicas, chaque réplica chiffrerait avec une clé différente.

</Warning>

### Questions-réponses

<Accordion title="De quels paramètres du Toolkit issus de `config/overleaf.rc` ai-je besoin ?">

<strong>Réponse :</strong> Aucun d'entre eux n'est lu par Ayakaleaf Pro. Leurs équivalents Kubernetes :

| `config/overleaf.rc`                         | Kubernetes                                                        |
| -------------------------------------------- | ----------------------------------------------------------------- |
| `OVERLEAF_LISTEN_IP`, `OVERLEAF_PORT`        | le Service (NodePort) ou votre ingress                            |
| `SIBLING_CONTAINERS_ENABLED`                 | `SANDBOXED_COMPILES*` dans la ConfigMap, socket Docker dans le pod |
| `GIT_BRIDGE_ENABLED`                         | [Intégration Git](/fr/on-premises/configuration/kubernetes/integrations/git-integration)                          |
| `MONGO_ENABLED`, `REDIS_ENABLED`, `MONGO_URL`, `REDIS_HOST` | les StatefulSets ou vos services managés, `OVERLEAF_MONGO_URL` et `OVERLEAF_REDIS_HOST` |
| `REDIS_AOF_PERSISTENCE`                      | `--appendonly yes` dans `20-redis.yaml`                           |
| `NGINX_ENABLED`, `TLS_*`                     | votre ingress ou répartiteur de charge                            |

</Accordion>
