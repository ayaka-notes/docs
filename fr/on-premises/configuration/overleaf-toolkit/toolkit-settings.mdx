Cette page décrit les variables d'environnement prises en charge dans le fichier `config/overleaf.rc` pour les déploiements Toolkit.

Le fichier `config/overleaf.rc` est constitué de définitions de variables de la forme `NAME=value`. Les lignes commençant par `#` sont traitées comme des commentaires.

<Info>

Après toute modification de `overleaf.rc` ou de `variables.env`, vous devez recréer les conteneurs Docker en exécutant `bin/up`.

</Info>

## Conteneurs

### `sharelatex`

| Nom                          | Description                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| ---------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `PROJECT_NAME`               | <p>Définit la valeur de l'option `--project-name` transmise à `docker-compose`. C'est utile lorsque plusieurs instances d'Overleaf s'exécutent sur un même hôte, car chaque instance peut avoir un nom de projet différent.<br /><br />- <strong>Par défaut</strong> : `overleaf`</p>                                                                                                                                                                                                                                                 |
| `OVERLEAF_IMAGE_NAME`        | <p>Image Docker utilisée par le conteneur de l'application Server Pro/CE. Il s'agit uniquement du nom de l'image Docker ; le tag de l'image Docker provient de `config/version`.<br /><br />- <strong>Par défaut :</strong><br />- Server Pro: `quay.io/sharelatex/sharelatex-pro`<br />- Community Edition: `sharelatex/sharelatex`</p>                                                                                                                                                                                                 |
| `SERVER_PRO`                 | <p>Lorsque cette valeur est `true`, le Toolkit utilise l'image Server Pro (`quay.io/sharelatex/sharelatex-pro`) au lieu de l'image Server CE par défaut (`sharelatex/sharelatex`).<br /><br />- <strong>Par défaut</strong> : `false`</p>                                                                                                                                                                                                                                                                   |
| `GIT_BRIDGE_ENABLED`         | <p>Définissez `true` pour activer la fonctionnalité git-bridge (Server Pro uniquement). Pour plus d'informations, consultez la documentation utilisateur <a href="https://www.overleaf.com/learn/how-to/Git_integration">https://www.overleaf.com/learn/how-to/Git_integration</a>.<br /><br />- <strong>Par défaut :</strong> `false`</p>                                                                                                                                                                                                                        |
| `GIT_BRIDGE_IMAGE`           | <p>Image Docker utilisée par le conteneur git-bridge (Server Pro uniquement). Il s'agit uniquement du nom de l'image Docker ; le tag de l'image Docker provient de `config/version`.<br /><br />- <strong>Par défaut :</strong> `quay.io/sharelatex/git-bridge`</p>                                                                                                                                                                                                                                                                              |
| `GIT_BRIDGE_DATA_PATH`       | Définit le chemin du répertoire qui sera monté dans le conteneur `git-bridge` (Server Pro uniquement) et utilisé pour stocker les dépôts Git. Il peut s'agir d'un chemin absolu (commençant par `/`) ou d'un chemin relatif au répertoire de base du Toolkit.                                                                                                                                                                                                                                                                                     |
| `GIT_BRIDGE_LOG_LEVEL`       | <p>Configure le niveau de journalisation du conteneur `git-bridge`. Niveaux disponibles : `TRACE`, `DEBUG`, `INFO`, `WARN`, `ERROR`.<br /><br />- <strong>Par défaut :</strong> `INFO`</p>                                                                                                                                                                                                                                                                                       |
| `SIBLING_CONTAINERS_ENABLED` | <p>Lorsque cette valeur est `true`, le Toolkit utilise la technique des <strong>Sibling Containers</strong> pour compiler les projets dans des sandboxes séparées, avec un conteneur Docker distinct pour chaque projet. Consultez la documentation &#x3C;server-pro-only-configuration/sandboxed-compiles> pour plus d'informations.<br /><br />- <strong>Nécessite :</strong> `SERVER_PRO=true`<br />- <strong>Par défaut :</strong> `true`</p>                                                                                                    |
| `SIBLING_CONTAINERS_PULL`    | <p>Lorsque cette valeur est `true`, le Toolkit télécharge automatiquement toutes les images TeX Live définies via `ALL_TEX_LIVE_DOCKER_IMAGES` dans le fichier <strong>config/variables.env</strong> lors de l'utilisation de la commande `bin/up`.<br /><br />- <strong>Par défaut :</strong> `true`</p>                                                                                                                                                                                                                                      |
| `DOCKER_SOCKET_PATH`         | <p>Définit le chemin du socket Docker sur la machine hôte (celle qui exécute le Toolkit). Lorsque `SIBLING_CONTAINERS_ENABLED` vaut `true`, le socket est monté dans le conteneur afin de permettre au service de compilation de lancer de nouveaux conteneurs Docker sur l'hôte.<br /><br />- <strong>Nécessite :</strong> `SIBLING_CONTAINERS_ENABLED=true`<br />- <strong>Par défaut :</strong> `/var/run/docker.sock`</p>                                                                                               |
| `OVERLEAF_DATA_PATH`         | <p>Définit le chemin du répertoire qui sera monté dans le conteneur principal `sharelatex` et utilisé pour stocker les données de compilation. Il peut s'agir d'un chemin absolu (commençant par `/`) ou d'un chemin relatif au répertoire de base du Toolkit.<br /><br />- <strong>Par défaut :</strong> `data/overleaf`</p>                                                                                                                                                                                                               |
| `OVERLEAF_LISTEN_IP`         | <p>Définit la ou les adresses IP de l'hôte auxquelles le conteneur se lie. Par exemple, si cette valeur est `0.0.0.0`, l'interface web sera accessible sur toutes les adresses IP de l'hôte. Pour un accès direct au conteneur, `OVERLEAF_LISTEN_IP` doit être défini sur votre adresse IP publique. Définir `OVERLEAF_LISTEN_IP` sur `0.0.0.0` ou sur l'IP externe de votre hôte provoque généralement des erreurs lorsqu'il est utilisé conjointement avec le .<br /><br />- <strong>Par défaut :</strong> `127.0.0.1`</p> |
| `OVERLEAF_PORT`              | <p>Définit le port de l'hôte auquel le conteneur se lie. Par exemple, si cette valeur est `8099` et que `OVERLEAF_LISTEN_IP` vaut `127.0.0.1`, l'interface web sera accessible sur `http://localhost:8099`.<br /><br />- <strong>Par défaut :</strong> `80`</p>                                                                                                                                                                                                                        |
| `OVERLEAF_LOG_PATH`          | <p>Définit le chemin du répertoire qui sera monté dans le conteneur principal `sharelatex` et utilisé pour rendre les journaux de l'application accessibles sur l'hôte Docker. Il peut s'agir d'un chemin absolu (commençant par `/`) ou d'un chemin relatif au répertoire de base du Toolkit. Supprimez cette entrée de configuration pour désactiver le bind mount. Si elle n'est pas définie, les journaux sont perdus lors de la recréation du conteneur.<br /><br />Voir pour plus d'informations sur la journalisation.<br /><br />- <strong>Par défaut :</strong> non défini</p>                                 |

### `mongo`

| Nom               | Description                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| ----------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `MONGO_ENABLED`   | <p>Lorsque cette valeur est `true`, le Toolkit crée un conteneur MongoDB pour héberger la base de données. Lorsqu'elle est `false`, ce conteneur n'est pas créé et le système utilise à la place la base de données MongoDB indiquée par `MONGO_URL`.<br /><br />- <strong>Par défaut</strong> : `true`</p>                                                                                                                                 |
| `MONGO_URL`       | <p>Indique l'URL de connexion MongoDB à utiliser lorsque `MONGO_ENABLED` vaut `false`.<br /><br />- <strong>Par défaut</strong>  : non défini</p>                                                                                                                                                                                                                                                                                                           |
| `MONGO_DATA_PATH` | <p>Définit le chemin du répertoire qui sera monté dans le conteneur `mongo` et utilisé pour stocker la base de données MongoDB. Il peut s'agir d'un chemin absolu (commençant par `/`) ou d'un chemin relatif au répertoire de base du Toolkit. Cette option ne concerne que le conteneur `mongo` local créé lorsque `MONGO_ENABLED` vaut `true`.<br /><br />- <strong>Par défaut</strong> : `data/mongo`</p> |
| `MONGO_IMAGE`     | <p>Image Docker utilisée par le conteneur MongoDB. Il s'agit uniquement du nom de l'image Docker ; le tag de l'image Docker doit être indiqué dans `MONGO_VERSION` (voir ci-dessous).<br /><br />- <strong>Par défaut :</strong> `mongo`</p>                                                                                                                                                                                                                             |
| `MONGO_VERSION`   | <p>Version de MongoDB utilisée par le conteneur MongoDB. La valeur doit commencer par la version majeure de MongoDB suivie d'un point, par ex. `6.0` ou `6.0-with-suffix`.<br /><br />- <strong>Par défaut :</strong> `6.0`</p>                                                                                                                                                                                                                             |

### `redis`

| Nom                     | Description                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| ----------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `REDIS_ENABLED`         | <p>Lorsque cette valeur est `true`, le Toolkit crée un conteneur Redis pour héberger la base de données Redis. Lorsqu'elle est `false`, ce conteneur n'est pas créé et le système utilise à la place la base de données Redis indiquée par `REDIS_HOST` et `REDIS_PORT`.<br /><br />- <strong>Par défaut</strong> : `true`</p>                                                                                                |
| `REDIS_HOST`            | <p>Indique l'hôte Redis à utiliser lorsque `REDIS_ENABLED` vaut `false`.<br /><br />- <strong>Par défaut</strong>  : non défini</p>                                                                                                                                                                                                                                                                                                                     |
| `REDIS_PORT`            | <p>Indique le port Redis à utiliser lorsque `REDIS_ENABLED` vaut `false`.<br /><br />- <strong>Par défaut</strong>  : non défini</p>                                                                                                                                                                                                                                                                                                                     |
| `REDIS_DATA_PATH`       | <p>Définit le chemin du répertoire qui sera monté dans le conteneur `redis` et utilisé pour stocker la base de données Redis. Il peut s'agir d'un chemin absolu (commençant par `/`) ou d'un chemin relatif au répertoire de base du Toolkit. Cette option ne concerne que le conteneur `redis` local créé lorsque `REDIS_ENABLED` vaut `true`.<br /><br />- <strong>Par défaut</strong> : `data/redis`</p> |
| `REDIS_AOF_PERSISTENCE` | <p>Active la persistance AOF (Append Only File) pour Redis. C'est la configuration <strong>recommandée</strong> pour la persistance de Redis.<br /><br />Pour plus de détails, consultez la section &#x3C;../../../maintenance/data-and-backups#aof-append-only-file> de &#x3C;../../maintenance/data-and-backups>.<br /><br />- <strong>Par défaut :</strong> `true`</p>                                                                                               |

### `nginx`

| Nom                    | Description                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `NGINX_ENABLED`        | <p>Lorsque cette valeur est `true`, le Toolkit crée un conteneur NGINX faisant office de proxy TLS.<br /><br />- <strong>Par défaut</strong> : `false`</p>                                                                                                                                                                                                                                                                                                                                 |
| `NGINX_CONFIG_PATH`    | <p>Chemin du fichier de configuration NGINX à utiliser pour le proxy TLS.<br /><br />- <strong>Par défaut</strong> : `config/nginx/nginx.conf`</p>                                                                                                                                                                                                                                                                                                                                                            |
| `NGINX_TLS_LISTEN_IP`  | <p>Définit la ou les adresses IP de l'hôte auxquelles le conteneur du proxy TLS se lie pour HTTPS. Par exemple, si cette valeur est `0.0.0.0`, l'interface web HTTPS sera accessible sur toutes les adresses IP de l'hôte. En général, elle doit être définie sur l'IP externe de votre hôte.<br /><br />- <strong>Par défaut</strong> : `127.0.1.1`</p>                                                                                                                                                       |
| `NGINX_HTTP_LISTEN_IP` | <p>Définit la ou les adresses IP de l'hôte auxquelles le conteneur du proxy TLS se lie pour la redirection HTTP. Par exemple, si cette valeur est `127.0.1.1`, les connexions HTTP vers `127.0.1.1` seront redirigées vers l'interface web HTTPS. En général, elle doit être définie sur l'IP externe de votre hôte. Ne la définissez pas sur `0.0.0.0`, car cela provoque généralement un conflit avec `OVERLEAF_LISTEN_IP`.<br /><br />- <strong>Par défaut</strong> : `127.0.1.1`</p> |
| `NGINX_HTTP_PORT`      | <p>Définit le port de l'hôte auquel le conteneur du proxy TLS se lie pour HTTP.<br /><br />- <strong>Par défaut</strong> : `80`</p>                                                                                                                                                                                                                                                                                                                                                                  |
| `TLS_PORT`             | <p>Définit le port de l'hôte auquel le conteneur du proxy TLS se lie pour HTTPS.<br /><br />- <strong>Par défaut</strong> : `443`</p>                                                                                                                                                                                                                                                                                                                                                                |
| `TLS_PRIVATE_KEY_PATH` | <p>Chemin de la clé privée à utiliser pour le proxy TLS.<br /><br />- <strong>Par défaut</strong> : `config/nginx/certs/overleaf_key.pem`</p>                                                                                                                                                                                                                                                                                                                                                      |
| `TLS_CERTIFICATE_PATH` | <p>Chemin du certificat public à utiliser pour le proxy TLS.<br /><br />- <strong>Par défaut</strong> : `config/nginx/certs/overleaf_certificate.pem`</p>                                                                                                                                                                                                                                                                                                                                       |
