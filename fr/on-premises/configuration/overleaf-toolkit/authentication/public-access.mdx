Vous pouvez ouvrir votre instance Overleaf aux personnes sans compte de trois manières :

* [#project-access](/fr/on-premises/configuration/overleaf-toolkit/authentication/public-access#project-access  "mention") : permettre aux invités d'ouvrir un lien de projet partagé sans se connecter
* [#page-access](/fr/on-premises/configuration/overleaf-toolkit/authentication/public-access#page-access  "mention") : permettre aux visiteurs non connectés de parcourir des pages telles que `/learn`, `/templates` et `/devs`
* [#public-registration](/fr/on-premises/configuration/overleaf-toolkit/authentication/public-access#public-registration  "mention") : permettre aux utilisateurs de s'inscrire eux-mêmes, éventuellement avec un e-mail d'activation et en limitant l'inscription à certains domaines de messagerie

### Accès aux projets {#project-access}

<Info>

Par défaut, même si un utilisateur obtient un lien de partage de projet, il doit **se connecter** avant de pouvoir rejoindre une session d'édition collaborative.

</Info>

Pour autoriser l'accès anonyme aux projets partagés par lien, définissez les deux variables ci-dessous :

```dotenv title="config/variables.env"
OVERLEAF_ALLOW_ANONYMOUS_READ_AND_WRITE_SHARING=true
OVERLEAF_ALLOW_PUBLIC_ACCESS=true
```

`OVERLEAF_ALLOW_ANONYMOUS_READ_AND_WRITE_SHARING` active la lecture/écriture anonyme sur les projets partagés par lien.

`OVERLEAF_ALLOW_PUBLIC_ACCESS` empêche la redirection des utilisateurs non authentifiés vers la page de connexion.

Les liens de modification ont la forme `/1234567890abcdefghijkl` (10 chiffres, puis 12 lettres minuscules) ; les liens de lecture ont la forme `/read/abcdefghijkl` (12 lettres minuscules).

Pour un accès en lecture seule uniquement, définissez `OVERLEAF_ALLOW_PUBLIC_ACCESS=true` seule : les invités peuvent alors ouvrir les liens de lecture (`/read/...`) sans se connecter, tandis que les liens de modification leur demandent toujours de se connecter.

Recréez les conteneurs avec `bin/up`. Ouvrez ensuite une URL de partage de lien dans une fenêtre de navigation privée.

### Accès aux pages {#page-access}

Par défaut (`OVERLEAF_ALLOW_PUBLIC_ACCESS` non définie), **toutes** les pages, à l'exception des pages de connexion et d'inscription, redirigent les visiteurs non connectés vers la page de connexion. Cela inclut les pages censées être publiques : les liens vers celles-ci ne fonctionnent donc que pour les utilisateurs déjà connectés.

Avec `OVERLEAF_ALLOW_PUBLIC_ACCESS=true`, les visiteurs non connectés peuvent ouvrir :

| Page                                                                  | Nécessite                         |
| --------------------------------------------------------------------- | -------------------------------- |
| L'aide LaTeX sur `/learn` (voir [adding-latex-user-help.md](/fr/on-premises/configuration/overleaf-toolkit/adding-latex-user-help  "mention")) | `OVERLEAF_PROXY_LEARN=true`      |
| La galerie de modèles sur `/templates`, les pages de modèles, les aperçus et les téléchargements ZIP (voir [templates.md](/fr/on-premises/configuration/overleaf-toolkit/templates  "mention")) | `OVERLEAF_TEMPLATE_GALLERY=true` |
| La page de l'API d'import Overleaf sur `/devs` (voir [overleaf-import-api.md](/fr/on-premises/configuration/overleaf-toolkit/integrations/overleaf-import-api  "mention")) | —                                |

Cela permet également à l'API d'import Overleaf ([#signed-out-visitors](/fr/on-premises/configuration/overleaf-toolkit/integrations/overleaf-import-api#signed-out-visitors  "mention")) de conserver un formulaire soumis par un visiteur non connecté jusqu'à ce qu'il se connecte.

La liste des projets, l'éditeur et la création de projets (y compris à partir d'un modèle ou via l'API d'import) nécessitent toujours une connexion.

### Inscription publique {#public-registration}

L'inscription publique n'est disponible que dans [ayaka-notes/ayakaleaf-pro](https://github.com/ayaka-notes/ayakaleaf-pro).

<Danger>

Notez qu'une fois l'inscription publique activée, **n'importe qui** ayant accès à votre instance Overleaf peut s'inscrire en tant qu'utilisateur.

Avec `true`, le processus d'inscription ne vérifie pas les adresses e-mail : utilisez-le uniquement sur un intranet ou dans un environnement de confiance, ou utilisez plutôt l'[inscription avec e-mail d'activation](/fr/on-premises/configuration/overleaf-toolkit/authentication/public-access#registration-with-activation-email).

Sur une instance avec OIDC, n'utilisez pas `true` : n'importe qui pourrait s'inscrire avec l'adresse e-mail d'un collègue avant la première connexion OIDC de ce dernier, ce qui lierait le collègue à ce compte. Utilisez l'[inscription avec e-mail d'activation](/fr/on-premises/configuration/overleaf-toolkit/authentication/public-access#registration-with-activation-email) ou désactivez l'inscription publique, voir [Comptes et mots de passe](/fr/on-premises/configuration/overleaf-toolkit/authentication#accounts-and-passwords).

</Danger>

Par défaut, ni la Community Edition ni Overleaf Pro n'autorisent l'inscription publique.

Pour l'activer, ajoutez ceci à `config/variables.env` :

```dotenv title="config/variables.env"
OVERLEAF_ALLOW_PUBLIC_REGISTRATION=true
```

Recréez les conteneurs avec `bin/up`.

Cliquez ensuite sur **Sign up** ou rendez-vous sur `/register`.

### Inscription avec e-mail d'activation {#registration-with-activation-email}

L'inscription avec e-mail d'activation n'est disponible que dans [ayaka-notes/ayakaleaf-pro](https://github.com/ayaka-notes/ayakaleaf-pro). Les utilisateurs s'inscrivent avec leur seule adresse e-mail et définissent leur mot de passe via le lien contenu dans l'e-mail d'activation : seul le propriétaire d'une adresse peut donc utiliser le compte. Une liste de domaines et de jokers nécessite la v6.4.0 ou une version ultérieure ; les versions antérieures n'acceptent qu'un seul domaine, comme `@example.com`.

Avant de l'activer, configurez l'envoi d'e-mails, sinon les utilisateurs ne recevront jamais l'e-mail d'activation. Voir [Envoi d'e-mails](/fr/on-premises/configuration/overleaf-toolkit/email-delivery).

Ajoutez ensuite la ligne suivante à `config/variables.env` :

```dotenv title="config/variables.env" wrap
OVERLEAF_ALLOW_PUBLIC_REGISTRATION=@example.com,@*.example.org
```

`OVERLEAF_ALLOW_PUBLIC_REGISTRATION` peut prendre les valeurs suivantes :

| Valeur                        | Qui peut s'inscrire                                   | E-mail vérifié |
| ----------------------------- | ----------------------------------------------------- | :------------: |
| `true`                        | N'importe qui, avec e-mail et mot de passe            |      Non       |
| `@example.com`                | Les adresses de `example.com`                         |      Oui       |
| `@*.example.org`              | Les adresses de sous-domaines tels que `cs.example.org`, mais pas de `example.org` lui-même |      Oui       |
| `@example.com,@*.example.org` | Toute entrée de la liste, séparées par des virgules   |      Oui       |
| `@*`                          | N'importe qui                                         |      Oui       |

Les domaines sont comparés sans tenir compte de la casse. Pour autoriser un domaine et ses sous-domaines, indiquez les deux : `@example.org,@*.example.org`.

### Questions/réponses {#q&a}

<Accordion title="Que peut faire un éditeur non connecté avec les commentaires ?">

<strong>Réponse :</strong> Un utilisateur non connecté qui ouvre un projet via son lien de modification obtient le même accès qu'un éditeur, à l'exception des actions qui enregistrent leur auteur :

| Action                                                                  | Éditeur non connecté |
| ----------------------------------------------------------------------- | -------------------: |
| Modifier le texte, afficher les commentaires et les modifications suivies |                  Oui |
| Accepter les modifications suivies, changer de mode d'édition           |                  Oui |
| Supprimer un commentaire ou un fil entier                               |                  Oui |
| Ajouter, modifier un commentaire ou y répondre                          |                  Non |
| Résoudre ou rouvrir un commentaire                                      |                  Non |

Le panneau de relecture leur affiche toujours le bouton **Resolve**, mais la résolution échoue avec un message d'erreur.

Les utilisateurs qui ouvrent un projet via son lien de lecture ne voient aucun commentaire ; voir [Rôles et permissions](/fr/on-premises/user-and-project-management/roles-and-permissions#collaborating).

</Accordion>

<Accordion title="Puis-je ajouter des utilisateurs et inviter des collaborateurs sans e-mail, ou avec un code d'invitation ?">

<strong>Réponse :</strong> Il n'existe pas de codes d'invitation, mais des utilisateurs peuvent être ajoutés sans e-mail. Dans **Admin → Manage Users**, cliquez sur **Create account**, saisissez l'adresse e-mail et cliquez sur **Create** : la boîte de dialogue affiche le lien d'activation, valable 7 jours, que vous pouvez copier et envoyer vous-même à l'utilisateur. Pour obtenir un nouveau lien plus tard, cliquez sur l'icône d'enveloppe dans la ligne de l'utilisateur, puis sur **Send activation email**. Pour partager un projet, invitez des utilisateurs qui ont déjà un compte : l'invitation apparaît aussi dans leur liste de projets, ils peuvent donc l'accepter sans l'e-mail. Les personnes sans compte ne reçoivent l'invitation que par e-mail, créez donc d'abord leur compte.

</Accordion>
