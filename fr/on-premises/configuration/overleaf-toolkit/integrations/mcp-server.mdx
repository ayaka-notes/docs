Chaque projet dispose d'un serveur MCP, afin que des clients IA tels que Claude Code, Codex, Cursor, VS Code ou Gemini CLI puissent travailler dessus : lire et modifier ses fichiers, le compiler, lire le journal LaTeX, télécharger le PDF et répondre aux commentaires. Depuis v6.3.3, ils peuvent aussi parcourir l'historique et restaurer des versions, examiner les modifications suivies, ajouter des commentaires, utiliser le chat du projet et déplacer des fichiers.

<Info>

Cette fonctionnalité est développée par [ayaka-notes/ayakaleaf-pro](https://github.com/ayaka-notes/ayakaleaf-pro). Elle est disponible à partir de la v6.3.1. Les outils pour l'historique, les modifications suivies, le chat du projet, les nouveaux commentaires et le déplacement de fichiers sont disponibles à partir de v6.3.3, voir [Nouveautés de v6.3.3](/fr/on-premises/user-guide/users/mcp-server#new-in-v6.3.3).

</Info>

### Configuration {#setup}

Le serveur MCP est fourni avec l'intégration Git : activez [git-bridge](/fr/on-premises/configuration/overleaf-toolkit/integrations/git-integration), et le serveur MCP est également disponible. Il n'y a rien d'autre à configurer.

### Connecter un client IA {#connect-an-ai-client}

1. Dans les **paramètres du compte**, générez un jeton d'authentification Git. Le même jeton est utilisé pour le serveur MCP et pour Git.
2. Dans l'éditeur, ouvrez **Intégrations** et cliquez sur **Serveur MCP**. La boîte de dialogue affiche l'adresse du serveur MCP du projet, `https://<your-overleaf>/project/<project_id>/mcp`, ainsi que la manière de l'ajouter à chaque client IA : copiez la commande et remplacez `<token>` par votre jeton.

Le jeton est envoyé dans l'en-tête HTTP `Authorization: Bearer <token>`. Par exemple, la commande pour Claude Code est :

```bash
claude mcp add --transport http overleaf \
  https://<your-overleaf>/project/<project_id>/mcp \
  --header "Authorization: Bearer <token>"
```

### Utilisation {#usage}

Une fois connecté, formulez vos demandes au client IA en langage courant. Par exemple :

| Vous demandez | Le client IA utilise |
| --- | --- |
| _Corrige les fautes de frappe dans l'introduction._ | `read_file`, `edit_file` : les modifications s'affichent en direct dans l'éditeur |
| _Compile le projet et corrige les erreurs LaTeX._ | `compile`, `get_compile_log`, `edit_file` |
| _Réponds aux commentaires ouverts, puis résous-les._ | `list_comments`, `reply_to_comment`, `resolve_comment` |
| _Passe à XeLaTeX et télécharge le PDF._ | `update_settings`, `compile`, `get_output_file_link` |
| _Réécris le résumé sous forme de modification suivie._ | `read_file`, `edit_file` avec `trackChanges` (v6.3.3) |
| _Qu'est-ce qui a changé depuis la version soumise ?_ | `list_versions`, `list_changes`, `diff` (v6.3.3) |
| _Déplace les chapitres dans un dossier nommé chapters._ | `move_file` (v6.3.3) |

### Outils {#tools}

| Groupe | Outils |
| --- | --- |
| Projet | `get_clone_info`, `get_settings`, `update_settings` |
| Fichiers | `list_files`, `read_file`, `edit_file`, `write_file`, `delete_file`, `move_file`, `create_folder` |
| Compilation | `compile`, `get_compile_log`, `get_output_file_link`, `word_count` |
| Commentaires | `list_comments`, `reply_to_comment`, `resolve_comment`, `reopen_comment`, `add_comment`, `edit_comment_message`, `delete_comment_message` |
| Modifications suivies | `list_tracked_changes`, `accept_tracked_changes`, `reject_tracked_changes` |
| Historique | `list_versions`, `list_changes`, `diff`, `create_version`, `delete_version`, `restore_file`, `restore_project` |
| Chat | `list_chat_messages`, `send_chat_message` |

v6.3.3 compte 33 outils, ou 31 avec `OVERLEAF_DISABLE_CHAT=true`, qui supprime les outils de chat. v6.3.1 et v6.3.2 ont les 17 autres : tout ce qui précède sauf `move_file`, `create_folder`, `add_comment`, `edit_comment_message`, `delete_comment_message`, les outils de modifications suivies, les outils de chat et les outils d'historique autres que `list_versions`. Dans v6.3.3, `read_file` lit aussi un fichier à une version de l'historique, `edit_file` et `write_file` acceptent `trackChanges`, et `update_settings` définit aussi la langue du correcteur orthographique.

Les modifications faites avec `edit_file`, `write_file` et `move_file` s'affichent en direct dans l'éditeur et sont fusionnées avec celles des collaborateurs. Pour de nombreux fichiers à la fois ou des fichiers binaires, le client IA peut aussi cloner le projet avec Git et pousser.

Avec `trackChanges`, la modification d'un fichier existant est une modification suivie de l'utilisateur du jeton, même lorsque le suivi des modifications est désactivé dans le projet ; un nouveau fichier ne l'est jamais. Sans `trackChanges`, les modifications suivent le réglage de suivi des modifications du projet.

### Autorisations {#permissions}

Le serveur MCP respecte les paramètres de partage du projet, comme Git :

* Toute personne pouvant voir le projet peut le lire, le compiler et télécharger sa sortie.
* Seuls le propriétaire et les éditeurs peuvent modifier ses fichiers et ses paramètres, restaurer des versions et accepter ou refuser des modifications suivies.
* Les relecteurs peuvent aussi ajouter des commentaires et y répondre, résoudre, rouvrir ou supprimer les commentaires qu'ils ont lancés, et enregistrer des versions. Ils ne peuvent pas modifier les fichiers, pas même sous forme de modifications suivies.
* Chacun modifie uniquement ses propres messages de commentaire, et les relecteurs ne suppriment que les leurs.
* Seul le propriétaire supprime les versions enregistrées par d'autres.
* Les lecteurs ayant rejoint par un lien ne voient ni les commentaires, ni les modifications suivies, ni l'historique, ni le chat, comme dans l'éditeur. Les lecteurs invités peuvent les voir et utiliser le chat.
* Si le propriétaire du projet n'a pas **Full project history**, les outils d'historique n'affichent que les modifications des dernières 24 heures, comme le panneau d'historique. Les administrateurs les voient toutes.

Le guide utilisateur contient un tableau de ce que chaque rôle peut faire, voir [Qui peut faire quoi](/fr/on-premises/user-guide/users/mcp-server#who-may-do-what).

### Questions/réponses {#q&a}

<Accordion title="Je ne vois ni Integrations ni le serveur MCP dans l'éditeur">

<strong>Réponse :</strong> Le serveur MCP n'a pas de variable d'environnement propre. Il est activé avec `GIT_BRIDGE_ENABLED=true` dans `config/overleaf.rc`, voir [Intégration Git](/fr/on-premises/configuration/overleaf-toolkit/integrations/git-integration). Après l'avoir modifiée, exécutez `bin/up -d`. Sans le git-bridge, l'éditeur n'affiche pas l'onglet **Integrations** dans sa barre latérale gauche.

</Accordion>

<Accordion title="Le client IA indique « Track changes is off for this project »">

<strong>Réponse :</strong> Le client a demandé une modification suivie, mais le compte du propriétaire du projet n'a pas le suivi des modifications. Cliquez sur **Admin**, puis sur **Manage Users**, ouvrez le propriétaire et, dans l'onglet **Features**, activez **Track changes**, voir [Features](/fr/on-premises/user-guide/administrators/user-management#features). Les modifications sans `trackChanges` fonctionnent toujours.

</Accordion>

<Accordion title="Le client IA ne voit que les modifications des dernières 24 heures">

<strong>Réponse :</strong> Le compte du propriétaire du projet n'a pas l'historique complet du projet, donc les outils d'historique affichent ce qu'affiche le panneau d'historique : les modifications des dernières 24 heures. Cliquez sur **Admin**, puis sur **Manage Users**, ouvrez le propriétaire et, dans l'onglet **Features**, activez **Full project history**, voir [Features](/fr/on-premises/user-guide/administrators/user-management#features).

</Accordion>
