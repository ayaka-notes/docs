Cette fonctionnalité est fournie par [ayaka-notes/ayakaleaf-pro](https://github.com/ayaka-notes/overleaf-pro) avec prise en charge d'OAuth 2.0 et est disponible à partir de la v6.3.0. N'hésitez pas à nous faire part de vos retours si vous rencontrez des problèmes.

</Info>

#### Configurer l'intégration Mendeley

1. Rendez-vous sur [ce lien](https://dev.mendeley.com/myapps.html) pour enregistrer une application OAuth Mendeley
2. Configurez la **Redirect URL** comme suit : `${OVERLEAF_SITE_URL}/user/mendeley/oauth/callback`
3. Notez l'**ID** généré (généralement numérique, comme `24061` ci-dessous) et le **Secret** de votre application
4. Modifiez votre fichier `config/variables.env`&#x20;
5. Conservez simplement le flux d'autorisation Elsevier (recommandé)

```dotenv title="config/variables.env"
#################
#   Mendeley    #
#################
# 'mendeley' must be in ENABLED_LINKED_FILE_TYPES (keep 'zotero' too if you use both)
ENABLED_LINKED_FILE_TYPES=project_file,project_output_file,url,mendeley

# From a Mendeley OAuth application (register at https://dev.mendeley.com/myapps.html)
# Redirect URL -> ${OVERLEAF_SITE_URL}/user/mendeley/oauth/callback
MENDELEY_CLIENT_ID=
MENDELEY_CLIENT_SECRET=
# Encrypts the Mendeley OAuth tokens in mongo; if unset, a key file is generated
# in /var/lib/overleaf/data on first use
# How to generate: `openssl rand -hex 32`
MENDELEY_CIPHER_PASSWORD=
# Optional: route the module's server-side Mendeley requests (OAuth + API) through
# an HTTP proxy (must be reachable from the web container; same as github-sync)
# http://10.0.0.1:10808
# (Optional) MENDELEY_PROXY_URL=
```

<Info>

&#x20;`mendeley` doit figurer dans `ENABLED_LINKED_FILE_TYPES` (conservez aussi `zotero` dans la liste si vous utilisez les deux). `MENDELEY_CLIENT_ID` et `MENDELEY_CLIENT_SECRET` proviennent de l'application OAuth que vous avez enregistrée. Le mot de passe de chiffrement sert à chiffrer les jetons OAuth Mendeley dans MongoDB (générez-en un avec `openssl rand -hex 32`) ; s'il est absent, un fichier de clé est généré dans le volume de données lors de la première utilisation. Vous pouvez éventuellement définir `MENDELEY_PROXY_URL` pour faire passer les requêtes Mendeley côté serveur (OAuth + API) par un proxy HTTP accessible depuis le conteneur web.

</Info>

### Remarques

<Warning>

Lors de la mise à niveau vers la version 6.3.0 republiée d'une installation existante contenant des fichiers de bibliographie liés à Mendeley, suivez les [instructions de migration Zotero / Mendeley](/fr/on-premises/release-notes/release-notes-6.x.x#ayakaleaf-pro-6.3.0  "mention"). Les nouvelles installations n'ont pas besoin de cette migration.

</Warning>

<Danger>

Ayakaleaf étant une plateforme collaborative, et afin de renforcer la sécurité, à partir de la version 6.3.0, seul le créateur d'origine d'un fichier de références `bib` est autorisé à mettre à jour le fichier importé.

</Danger>

Par exemple, supposons que le propriétaire du projet, l'utilisateur A, active le partage par lien et crée un fichier `test.bib` dans le projet, lié à son propre compte Zotero. Si un autre utilisateur, l'utilisateur B, accède au projet via le lien partagé, il pourra toujours lire et télécharger `test.bib`, mais ne sera pas autorisé à mettre à jour ni à réimporter le fichier depuis Zotero. Seul l'utilisateur A, en tant que créateur d'origine du fichier de références, peut effectuer des mises à jour. Autrement dit, seul le créateur d'origine du fichier `.bib` a le droit de le mettre à jour.
