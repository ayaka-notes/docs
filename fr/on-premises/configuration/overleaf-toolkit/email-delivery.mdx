Overleaf prend en charge l'envoi d'e-mails selon deux méthodes : le protocole SMTP (Simple Mail Transfer Protocol) et [Amazon Simple Email Service (SES)](https://aws.amazon.com/ses/). SMTP peut être utilisé si un serveur de messagerie est activé sur votre machine locale et écoute les connexions locales.

## Plusieurs adresses e-mail par compte {#several-emails-per-account}

<Info>

Cette fonctionnalité est développée par [ayaka-notes/ayakaleaf-pro](https://github.com/ayaka-notes/ayakaleaf-pro) et est disponible à partir de la v6.4.0.

</Info>

Lorsque l'e-mail est configuré, la page des paramètres liste les adresses e-mail d'un compte au lieu de l'unique champ e-mail. Les utilisateurs ajoutent une adresse e-mail en saisissant un code à 6 chiffres envoyé à celle-ci, et cliquent sur **Make primary** pour basculer leur compte vers elle. C'est ainsi qu'une personne conserve son compte lorsqu'une adresse va lui être retirée, comme celle d'une université après l'obtention du diplôme. Le [guide de l'utilisateur](/on-premises/user-guide/users/multiple-emails) présente les étapes avec des captures d'écran.

* Seule l'adresse e-mail principale permet de se connecter et reçoit les réinitialisations de mot de passe. Une adresse e-mail secondaire ne fait ni l'un ni l'autre, de sorte qu'une adresse réattribuée à quelqu'un d'autre ne peut pas prendre le contrôle du compte.
* Cliquez sur **Make primary** avant la fermeture de l'ancienne boîte aux lettres. Ensuite, un administrateur doit modifier l'adresse e-mail dans **Admin → Manage Users**.
* Une ancienne adresse e-mail principale qui n'a jamais été confirmée est supprimée lorsqu'une autre adresse devient principale. Une adresse confirmée reste comme adresse e-mail secondaire jusqu'à ce que l'utilisateur la supprime.
* **Make primary** est refusé lorsque LDAP ou SAML est activé, car ces comptes ne pourraient pas se connecter avec la nouvelle adresse e-mail. Consultez [Comptes et mots de passe](/fr/on-premises/configuration/overleaf-toolkit/authentication#accounts-and-passwords).
* Sans les paramètres d'e-mail, l'unique champ e-mail reste en place.

## Configuration {#configuration}

L'envoi d'e-mails se configure à l'aide des variables d'environnement suivantes.

#### Configuration de l'expéditeur {#sender-configuration}

| Nom                           | Description                                                                                                                                          |
| ----------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| `OVERLEAF_EMAIL_FROM_ADDRESS` | <p>L'adresse de l'expéditeur, par ex. <a href="mailto:support@mycompany.com">`'support@mycompany.com'`</a><br /><br />- <strong>Obligatoire</strong> : oui</p> |
| `OVERLEAF_EMAIL_REPLY_TO`     | L'adresse de réponse, par ex. `'noreply@mycompany.com'`                                                                                                  |

#### SMTP {#smtp}

| Nom                                     | Description                                                                                                                                                                                                                                                              |
| --------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `OVERLEAF_EMAIL_SMTP_HOST`              | Le nom d'hôte ou l'adresse IP auquel se connecter. Doit être accessible depuis le conteneur Docker                                                                                                                                                                               |
| `OVERLEAF_EMAIL_SMTP_PORT`              | Le port auquel se connecter                                                                                                                                                                                                                                                   |
| `OVERLEAF_EMAIL_SMTP_SECURE`            | Si `true`, la connexion au serveur utilise TLS. Si `false` ou non défini, TLS est utilisé si le serveur prend en charge l'extension `STARTTLS`. Dans la plupart des cas, définissez cette valeur sur `true` si vous vous connectez au port `465`. Pour les ports `587` ou `25`, laissez-la à `false` |
| `OVERLEAF_EMAIL_SMTP_USER`              | Le nom d'utilisateur à utiliser pour s'authentifier auprès du serveur SMTP                                                                                                                                                                                                 |
| `OVERLEAF_EMAIL_SMTP_PASS`              | Le mot de passe associé au nom d'utilisateur SMTP                                                                                                                                                                                                                           |
| `OVERLEAF_EMAIL_SMTP_TLS_REJECT_UNAUTH` | Si `false`, autorise la connexion à un serveur TLS doté d'un certificat TLS autosigné ou invalide                                                                                                                                                                        |
| `OVERLEAF_EMAIL_SMTP_IGNORE_TLS`        | Si `true` et que `OVERLEAF_EMAIL_SMTP_SECURE` vaut `false`, TLS n'est pas utilisé même si le serveur prend en charge l'extension `STARTTLS`                                                                                                                                            |
| `OVERLEAF_EMAIL_SMTP_NAME`              | Nom d'hôte facultatif pour la validation TLS si `OVERLEAF_EMAIL_SMTP_HOST` est défini sur une adresse IP ; par défaut, le nom d'hôte de la machine.                                                                                                                                        |
| `OVERLEAF_EMAIL_SMTP_LOGGER`            | Si `true`, écrit les messages de journalisation dans `web.log`.                                                                                                                                                                                                                        |

#### Interface SMTP d'Amazon SES {#amazon-ses-smtp-interface}

Pour en savoir plus sur l'utilisation de l'interface SMTP d'Amazon SES pour envoyer des e-mails, consultez [cette page](https://docs.aws.amazon.com/ses/latest/dg/send-email-smtp.html).

| Nom                        | Description                                                                                |
| -------------------------- | ------------------------------------------------------------------------------------------ |
| `OVERLEAF_EMAIL_SMTP_HOST` | Le nom d'hôte ou l'adresse IP auquel se connecter. Doit être accessible depuis le conteneur Docker |
| `OVERLEAF_EMAIL_SMTP_PORT` | Le port auquel se connecter                                                                     |
| `OVERLEAF_EMAIL_SMTP_USER` | Le nom d'utilisateur à utiliser pour s'authentifier auprès du serveur SMTP                   |
| `OVERLEAF_EMAIL_SMTP_PASS` | Le mot de passe associé au nom d'utilisateur SMTP                                             |

#### API Amazon SES {#amazon-ses-api}

Pour en savoir plus sur l'utilisation de l'API Amazon SES pour envoyer des e-mails, consultez [cette page](https://docs.aws.amazon.com/ses/latest/dg/send-email-api.html).

| Nom                                    | Description                                 |
| -------------------------------------- | ------------------------------------------- |
| `OVERLEAF_EMAIL_AWS_SES_ACCESS_KEY_ID` | La clé d'accès, si vous utilisez AWS SES             |
| `OVERLEAF_EMAIL_AWS_SES_SECRET_KEY`    | La clé secrète, si vous utilisez AWS SES             |
| `OVERLEAF_EMAIL_AWS_SES_REGION`        | Si non définie, la région par défaut est US-EAST-1 |

#### AWS SES avec rôles d'instance {#aws-ses-with-instance-roles}

| Nom                     | Description                                                                                                                      |
| ----------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| `OVERLEAF_EMAIL_DRIVER` | Lorsque cette variable vaut `ses`, le système de messagerie utilise la méthode de l'API SES et s'appuie sur les rôles d'instance configurés pour envoyer les e-mails. |

#### Personnalisation {#customisation}

| Nom                            | Description                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| ------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `OVERLEAF_CUSTOM_EMAIL_FOOTER` | <p>HTML personnalisé ajouté à la fin de tous les e-mails.<br /><br /><strong>Exemple</strong> : `"<div>This system is run by department x </div> <div> If you have any questions please look at our faq <a href='https://somwhere.com'>here</a></div>"`</p> |
