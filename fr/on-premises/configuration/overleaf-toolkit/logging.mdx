Vous pouvez utiliser le script `bin/logs` pour consulter les journaux des services.

Exemples d'utilisation de base :

```bash
# View the web service logs
bin/logs web

# Show help
bin/logs --help

# View logs for multiple services at once
bin/logs filestore docstore web clsi

# Follow log output (like tail -f)
bin/logs -f filestore docstore web clsi

# Limit the number of lines printed (default 50)
bin/logs -n 50 web

# Show all log lines
bin/logs -n all web

# Redirect output to a file
bin/logs -n all web > web.log
```

Vous pouvez utiliser le script `bin/logs` pour consulter les journaux des services suivants : `clsi`, `contacts`, `docstore`, `document-updater`, `filestore`, `git-bridge`, `mongo`, `notifications`, `real-time`, `redis`, `spelling`, `tags`, `track-changes`, `web`, `web-api`, `history-v1`, `project-history`.

## Copier les journaux

Consultez la documentation d'origine : https://docs.overleaf.com/on-premises/configuration/overleaf-toolkit/logging#copying-logs

Copiez les fichiers journaux du conteneur principal `sharelatex` vers votre ordinateur local :

```bash
docker cp sharelatex:/var/log/overleaf/{service-name}.log {service-name}.log
```

## Conserver les journaux

Les conteneurs Docker sont éphémères : les fichiers et répertoires créés dans le conteneur pendant son exécution (y compris les fichiers journaux) sont supprimés si le conteneur est recréé (par exemple lors de l'exécution de `bin/up`). Pour conserver les fichiers journaux d'une recréation de conteneur à l'autre :

* Définissez la variable d'environnement `OVERLEAF_LOG_PATH` dans le fichier `config/overleaf.rc` utilisé par le Toolkit. Il doit s'agir du répertoire de l'hôte qui sera monté (bind mount) sur le répertoire des journaux à l'intérieur du conteneur `sharelatex`.
* Après avoir modifié cette valeur et exécuté `bin/up -d`, les fichiers journaux seront conservés sur l'hôte et directement accessibles.

<Warning>

Vous devez attribuer la propriété du répertoire des journaux de l'hôte utilisé pour le bind mount à l'utilisateur `www-data` (uid=33) et vous assurer que les permissions sont `drwxr-xr-x` (755).

Exemple :

```bash
chown 33:33 data/overleaf/logs
chmod 755 data/overleaf/logs
```

</Warning>
