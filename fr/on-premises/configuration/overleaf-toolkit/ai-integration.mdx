## Assistant IA et assistant pour les erreurs LaTeX

Ayakaleaf Pro intègre l'IA dans l'éditeur de 2 façons.

* L'assistant IA peut utiliser les documents de votre projet et la sélection en cours comme contexte pour répondre à vos questions et vous proposer des modifications à examiner.
* L'assistant d'erreurs propose une correction ciblée lorsque vous sélectionnez une erreur de compilation LaTeX.

### Configuration du Toolkit

Ajoutez ce qui suit à `config/variables.env` dans votre déploiement Toolkit, en remplaçant l'URL, la clé et le modèle d'exemple par les valeurs de votre fournisseur :

```dotenv
AI_ENABLED=true
AI_BASE_URL=https://ai-gateway.example.com/v1
AI_API_KEY=REPLACE_WITH_YOUR_GATEWAY_API_KEY
AI_MODEL=YOUR_TEXT_MODEL_ID
```

Conservez les vraies clés d'API dans le fichier d'environnement de votre déploiement et hors du contrôle de version. Les valeurs ci-dessus sont des exemples, pas des identifiants fonctionnels.

<Info>

La qualité des suggestions de l'IA dépend du modèle choisi. Si vous disposez déjà d'un abonnement Codex ou ChatGPT, vous pouvez le connecter via le point de terminaison compatible OpenAI de [CLIProxyAPI](https://github.com/router-for-me/CLIProxyAPI).

</Info>

`AI_BASE_URL` est l'URL de base de l'API compatible OpenAI, y compris le préfixe de version du fournisseur si nécessaire. N'ajoutez pas `/chat/completions`, car nous l'ajoutons en interne. La passerelle et le modèle doivent prendre en charge les chat completions en streaming et les outils de type fonction. Les deux fonctionnalités envoient le contexte du document à cette passerelle ; le chat peut également envoyer des images téléversées lorsqu'un modèle prenant en charge les images est utilisé.

Le Toolkit transmet `config/variables.env` au conteneur de l'application. Conservez les noms de variables indiqués ici ; n'ajoutez pas de préfixe `OVERLEAF_`. Depuis le répertoire du Toolkit, recréez le conteneur de l'application après avoir modifié ces variables :

```sh
bin/up -d
```

### Paramètres de la passerelle

| Variable                | Valeur par défaut | Rôle                                                                                                                                                                      |
| ----------------------- | -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `AI_ENABLED`            | `false`        | Définissez exactement `true` pour activer le chat et les suggestions d'erreurs sur l'instance. Si elle n'est pas définie ou a une autre valeur, ces fonctions restent désactivées. Une configuration de passerelle fonctionnelle est également requise. |
| `AI_BASE_URL`           | Aucune ; obligatoire | URL de base de l'API compatible OpenAI.                                                                                                                                    |
| `AI_API_KEY`            | Aucune ; obligatoire | Clé d'API de cette passerelle, utilisée par le serveur.                                                                                                                    |
| `AI_MODEL`              | Aucune ; obligatoire | Modèle de texte utilisé par la configuration de chat par défaut et par les suggestions pour les erreurs LaTeX.                                                              |
| `AI_IMAGE_MODEL`        | Non définie    | Modèle facultatif prenant en charge les images, sur la même passerelle et avec la même clé d'API.                                                                          |
| `AI_MAX_STEPS`          | `20`           | Nombre maximal d'appels d'outils par message utilisateur dans le chat IA, continuations automatiques comprises. Utilisez un entier positif.                               |
| `AI_PROXY_URL`          | Non définie    | URL facultative d'un proxy HTTP pour les appels à la passerelle IA. Elle ne configure pas les clients de recherche web ou de recherche dans la documentation.              |
| `AI_TOKEN_QUOTA`        | `0`            | Limite de jetons par utilisateur, partagée par le chat et les suggestions d'erreurs pour chaque période. Non définie ou `0` signifie illimité ; utilisez un entier positif pour fixer une limite. |
| `AI_TOKEN_QUOTA_PERIOD` | `month`        | `month` est réinitialisé le premier jour à 00:00 UTC ; `week` est réinitialisé le lundi à 00:00 UTC. Les autres valeurs utilisent `month`.                                  |

Pour le téléversement d'images, définissez `AI_IMAGE_MODEL` sur un modèle qui accepte les images en entrée et prend en charge les outils utilisés par le chat. Toute requête de chat dont l'historique contient une image jointe utilise ce modèle, y compris les messages ultérieurs de cette conversation. Sans ce paramètre, les requêtes contenant des images utilisent le modèle de chat normal, qui doit alors lui-même prendre en charge les images. Les suggestions pour les erreurs LaTeX continuent d'utiliser `AI_MODEL`.

Par exemple, pour activer un modèle d'images et un quota IA hebdomadaire :

```dotenv
AI_IMAGE_MODEL=YOUR_IMAGE_CAPABLE_MODEL_ID
AI_TOKEN_QUOTA=100000
AI_TOKEN_QUOTA_PERIOD=week
```

### Accès des utilisateurs et consentement

La disponibilité sur l'instance et l'autorisation des utilisateurs sont distinctes. `AI_ENABLED` et la configuration de la passerelle contrôlent la disponibilité sur l'instance. Un utilisateur connecté doit en outre satisfaire aux vérifications de compte existantes :

* `aiFeatures.enabled` ne doit pas valoir `false`. Ce champ existant de la base de données contrôle à la fois le chat et les suggestions pour les erreurs LaTeX.
* La valeur effective de `features.aiUsageQuota` de l'utilisateur doit correspondre au niveau illimité configuré (`unlimited` par défaut), ou l'ancienne autorisation `features.aiErrorAssistant` doit être activée. Les fonctionnalités effectives incluent les éventuelles surcharges de fonctionnalités applicables au compte.

Cocher la case seule ne modifie pas l'offre de l'utilisateur. Le champ `aiUsageQuota` est un niveau d'autorisation, et non un quota numérique de jetons. `AI_TOKEN_QUOTA` est une limite distincte appliquée de manière identique à chaque utilisateur autorisé ; le module actuel ne permet pas de définir une limite numérique individuelle par compte.

Dans la liste des utilisateurs de l'administration, sélectionnez un utilisateur et ouvrez **Update account info → AI features**. **Enable AI features** met à jour `aiFeatures.enabled` lorsque les modifications du compte sont enregistrées. Le serveur vérifie les autorisations actuelles à chaque nouvelle requête IA, y compris celles provenant d'un éditeur déjà ouvert. Actualisez l'éditeur pour mettre à jour les contrôles visibles après un changement d'autorisation.

### Utilisation et réinitialisation

L'onglet AI features de l'administration affiche sur une même ligne l'**Usage** de la période en cours, la **Limit** et le bouton **Reset**. L'utilisation est lue à l'ouverture de l'onglet ; elle n'est pas actualisée en continu. Rouvrez l'onglet après la fin d'un chat ou d'une suggestion d'erreur pour voir le décompte le plus récent. La réinitialisation prend effet immédiatement et efface uniquement le compteur de la période en cours de cet utilisateur, puis recharge l'utilisation affichée. Il n'est pas nécessaire d'enregistrer le reste du formulaire du compte.

<Frame>
  <img src="/images/on-premises/img-2f5a5399.png" alt="" width="563" />
</Frame>

Le chat et les suggestions d'erreurs partagent un même compteur Redis, mis à jour à partir du nombre total de jetons indiqué par le fournisseur du modèle une fois la requête terminée. Cela inclut les jetons d'entrée et de sortie sur l'ensemble des étapes du modèle. L'entrée peut comprendre l'historique de la conversation, le contexte du document et les résultats des outils ; une question de suivi peut donc consommer davantage de jetons que le nouveau message seul. L'utilisation est enregistrée même lorsque la limite est **Unlimited**. Les requêtes pour lesquelles aucun total de jetons n'est indiqué n'incrémentent pas le compteur ; le module ne peut pas reconstituer l'utilisation historique non enregistrée.

Les vérifications de quota ont lieu avant le streaming. Une requête, ou plusieurs requêtes simultanées, peuvent dépasser le quota restant avant que les requêtes suivantes ne soient bloquées. Il s'agit donc d'un quota d'utilisation et non d'un plafond strict de dépenses auprès du fournisseur. Si la consultation du quota échoue, la requête est autorisée et l'échec est journalisé.

Les deux fonctionnalités utilisent `AI_TOKEN_QUOTA` ; les suggestions d'erreurs n'ont pas de limite distincte en nombre de requêtes. La réinitialisation du compteur ne modifie ni l'autorisation, ni le consentement, ni la limite configurée, ni les données de facturation du fournisseur. Les compteurs utilisent des clés de période en UTC et expirent au bout de 40 jours ; conserver les données Redis permet de préserver l'utilisation en cours lors des redémarrages de l'application.

### Services de recherche facultatifs

La recherche web utilise une API compatible Tavily. Elle est disponible lorsqu'une clé d'API de recherche est configurée. Ces paramètres sont indépendants de la passerelle IA :

| Variable                 | Valeur par défaut                        | Rôle                                                                                                                          |
| ------------------------ | ---------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| `TAVILY_API_KEY`         | Non définie                              | Clé d'API de recherche. Prioritaire sur `WEB_SEARCH_API_KEY`.                                                                 |
| `WEB_SEARCH_API_KEY`     | Non définie                              | Autre nom pour la clé d'API de recherche.                                                                                      |
| `WEB_SEARCH_URL`         | `https://api.tavily.com/search`          | Point de terminaison de recherche ; les points de terminaison personnalisés doivent accepter le format de requête et de réponse de Tavily. |
| `WEB_SEARCH_MAX_RESULTS` | `5`                                      | Nombre de résultats demandés par recherche ; utilisez un entier positif pris en charge par le service.                        |
| `WEB_SEARCH_DEPTH`       | `basic`                                  | Profondeur de recherche, normalement `basic` ou `advanced`.                                                                    |
| `WEB_SEARCH_PROVIDER`    | `tavily`                                 | L'implémentation actuelle ne prend en charge que le protocole compatible Tavily ; modifier cette valeur ne sélectionne pas un autre adaptateur. |
| `DOCS_MCP_URL`           | `https://docs.overleaf.com/~gitbook/mcp` | Point de terminaison de recherche dans la documentation. Définissez une chaîne vide pour désactiver la recherche dans la documentation. |

Par exemple :

```dotenv
TAVILY_API_KEY=REPLACE_WITH_YOUR_SEARCH_API_KEY
WEB_SEARCH_MAX_RESULTS=5
WEB_SEARCH_DEPTH=basic
DOCS_MCP_URL=https://docs.overleaf.com/~gitbook/mcp
```

La recherche dans la documentation appelle l'outil `searchDocumentation` du point de terminaison MCP GitBook configuré et accepte les réponses JSON ou SSE. Il s'agit d'un client MCP pour la recherche dans la documentation ; ces modules n'exposent pas les fichiers du projet en tant que serveur MCP et ne fournissent pas de registre de serveurs MCP à usage général.

Les requêtes de recherche sont envoyées au service de recherche configuré. Les résultats peuvent ensuite être inclus dans les requêtes envoyées à la passerelle IA. Le menu **Tools** du chat permet aux utilisateurs d'activer ou de désactiver **Web** et **Documentation** pour leurs requêtes ; un outil doit également être configuré sur le serveur pour être disponible pour le modèle.
