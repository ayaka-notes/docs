Nous respectons les droits d'auteur ; c'est pourquoi nous recensons ici toutes les fonctionnalités et le code utilisés dans ce projet. Cette page présente les nouvelles fonctionnalités d'Ayakaleaf Pro ainsi que les droits d'auteur du code associé.

Sauf indication contraire, nous utilisons Codex d'OpenAI pour la revue de code et la revue des PR. Ce processus nous a permis de corriger de nombreux problèmes de sécurité, et nous lui exprimons notre sincère gratitude. Pour plus de détails, consultez [ayaka-notes/ayakaleaf-pro/pull](https://github.com/ayaka-notes/ayakaleaf-pro/pulls).

### Vue d'ensemble {#overview}

Au fil des années, de nombreux développeurs de la communauté ont fourni des efforts considérables pour améliorer l'édition communautaire d'Overleaf. Les voici :

* [https://github.com/ertuil/overleaf](https://github.com/ertuil/overleaf)
* [https://github.com/AllanChain/lcpu-overleaf](https://github.com/AllanChain/lcpu-overleaf)
* [https://github.com/yu-i-i/overleaf-cep/](https://github.com/yu-i-i/overleaf-cep/)
* [https://github.com/ayaka-notes/overleaf](https://github.com/ayaka-notes/overleaf)
* [https://github.com/davrot/overleaf\_with\_admin\_extension](https://github.com/davrot/overleaf_with_admin_extension)
* [https://github.com/overleaf/overleaf/pull/1447](https://github.com/overleaf/overleaf/pull/1447) (intégration GitHub)
* [https://github.com/overleaf/overleaf/pull/1385](https://github.com/overleaf/overleaf/pull/1385) (prise en charge de Typst)

Nous avons pu utiliser du code issu de ces projets, et nous tenons à leur exprimer notre gratitude.

#### Fonctionnalité 05 : panneau d'administration {#features-05-admin-panel}

<Warning>

Lorsque votre système compte 1000 utilisateurs ou projets, le panneau d'administration n'affiche que les 1000 utilisateurs ou projets les plus récents. Utilisez le panneau de recherche pour trouver des utilisateurs ou des projets spécifiques.

</Warning>

Cette fonctionnalité a été principalement développée par [yu-i-i/overleaf-cep](https://github.com/yu-i-i/overleaf-cep). Nous avons modifié une partie du code pour l'améliorer, afin que vous puissiez :

* Rechercher des utilisateurs via le backend lorsque vous en avez plus de 1000.
* Rechercher des projets via le backend lorsque vous en avez plus de 1000.
* Ouvrir des projets directement depuis le panneau d'administration des projets.
* Consulter et ajuster la limite de temps de compilation d'un utilisateur depuis le panneau d'administration.
* Réinitialiser le mot de passe d'un utilisateur directement depuis le panneau d'administration.
* Autres améliorations…

#### Fonctionnalité 13 : exécution de Python {#features-13-python-runner}

Cette fonctionnalité est développée par Overleaf officiel. Vous pouvez exécuter des scripts Python dans votre navigateur.

Elle est intégrée et ne nécessite aucune configuration : ouvrez un fichier `.py` dans un projet et cliquez sur **Run**. Le script s'exécute avec Pyodide dans le navigateur de l'utilisateur ; seuls les paquets intégrés à Pyodide sont donc disponibles.

* Le volet de sortie situé sous l'éditeur affiche ce que le script imprime (les 100 dernières lignes). Cliquez sur **Stop** pour interrompre une exécution. Chaque exécution démarre un nouvel interpréteur Python : rien n'est conservé d'une exécution à l'autre.
* Avant chaque exécution, les fichiers texte du projet sont copiés dans le dossier de travail du script, afin que celui-ci puisse les ouvrir via leur chemin dans le projet, par exemple `open('data/results.csv')`. Les fichiers binaires tels que les images et les PDF ne sont pas copiés.
* Les fichiers que le script écrit dans ce dossier sont enregistrés dans le projet au même chemin lorsque l'exécution réussit, en remplaçant tout fichier portant le même nom. Une exécution qui échoue n'enregistre rien. Une exécution peut enregistrer jusqu'à 50 fichiers, 50 Mo par fichier et 100 Mo au total.
* Matplotlib n'a pas d'affichage : enregistrez les graphiques avec `plt.savefig('figure.png')`, puis incluez l'image dans votre document LaTeX.
* Pyodide et ses paquets (tels que NumPy, pandas, SciPy et Matplotlib) sont servis par votre instance ; le navigateur n'a donc pas besoin d'accès à Internet. Les paquets installés avec pip ne peuvent pas être utilisés.

#### Fonctionnalité 17 : intégration des gestionnaires de références {#features-17-reference-manager-integration}

Cette fonctionnalité est développée par [ayaka-notes/ayakaleaf-pro](https://github.com/ayaka-notes/ayakaleaf-pro). L'intégration Zotero a été initialement développée par [davrot](https://github.com/davrot) et [yu-i-i/overleaf-cep](https://github.com/yu-i-i/overleaf-cep) ; nous l'avons retravaillée avec OAuth et avons ajouté l'intégration Mendeley (OAuth 2.0) dans la v6.3.0. Vous pouvez :

* Associer vos comptes Zotero et Mendeley dans les paramètres du compte.
* Importer votre bibliothèque personnelle ou une bibliothèque de groupe sous forme de fichier `.bib` dans votre projet.
* Actualiser à tout moment le fichier `.bib` importé pour le maintenir à jour.

Consultez [Intégration Zotero](/fr/on-premises/configuration/overleaf-toolkit/integrations/zotero-integration) et [Intégration Mendeley](/fr/on-premises/configuration/overleaf-toolkit/integrations/mendeley-integration) pour la configuration.

#### Fonctionnalité 18 : API Open in Overleaf {#features-18-open-in-overleaf-api}

Cette fonctionnalité est développée par [ayaka-notes/ayakaleaf-pro](https://github.com/ayaka-notes/ayakaleaf-pro) et est compatible avec l'API « Open in Overleaf » d'overleaf.com. Vous pouvez ajouter un lien ou un bouton « Open in Ayakaleaf » à votre site web, votre blog ou votre bibliothèque de modèles, afin que les visiteurs puissent ouvrir en un clic un extrait LaTeX, un fichier distant ou un projet ZIP comme nouveau projet sur votre instance. Rendez-vous sur `/devs` sur votre instance pour plus de détails, et consultez [API d'import Overleaf](/fr/on-premises/configuration/overleaf-toolkit/integrations/overleaf-import-api).

#### Fonctionnalité 20 : synchronisation Dropbox {#features-20-dropbox-sync}

Cette fonctionnalité est développée par [ayaka-notes/ayakaleaf-pro](https://github.com/ayaka-notes/ayakaleaf-pro) dans la v6.3.1 en avant-première (publication officielle dans la v6.4.0), à l'image de la synchronisation Dropbox d'overleaf.com. Dès qu'un utilisateur lie son compte Dropbox, chacun de ses projets apparaît sous forme de dossier dans sa Dropbox : les modifications effectuées dans Overleaf sont envoyées vers Dropbox, et celles effectuées dans Dropbox reviennent dans Overleaf. Consultez [Synchronisation Dropbox](/fr/on-premises/configuration/overleaf-toolkit/integrations/dropbox-synchronisation) pour la configuration.

#### Fonctionnalité 21 : serveur MCP {#features-21-mcp-server}

Cette fonctionnalité est développée par [ayaka-notes/ayakaleaf-pro](https://github.com/ayaka-notes/ayakaleaf-pro) dans la v6.3.1. Chaque projet dispose d'un serveur MCP, afin que des clients IA tels que Claude Code, Codex, Cursor, VS Code ou Gemini CLI puissent lire et modifier ses fichiers en direct, le compiler, lire le journal LaTeX, télécharger le PDF et répondre aux commentaires.
