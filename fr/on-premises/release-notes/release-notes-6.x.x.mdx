<Accordion title="Migration Zotero / Mendeley pour les installations existantes">

Lors de la mise à niveau vers l'image 6.3.0 republiée, migrez les métadonnées existantes des bibliographies liées à Zotero/Mendeley à l'aide du script ci-dessous. Cette migration accompagne le correctif `12031b8dfd`.

Elle renomme `zoteroGroupId` / `mendeleyGroupId` en `group_id`, renomme `importedByUserId` en `importer_id` et supprime `importedByName`.

Sauvegardez MongoDB et arrêtez l'application avant d'exécuter la migration. Laissez MongoDB en fonctionnement. Ouvrez son shell (remplacez `mongo` par le nom de votre conteneur) :

```bash
docker exec -it mongo mongosh
```

Exécutez ce qui suit dans `mongosh` (remplacez `sharelatex` par le nom de votre base de données) :

```javascript
use sharelatex

(async () => {
  let updated = 0
  await db.projects.find({}, { rootFolder: 1 }).forEach(async project => {
    const changes = {}
    function visit(folders, path) {
      for (const [i, folder] of (folders || []).entries()) {
        const folderPath = `${path}.${i}`
        for (const [j, file] of (folder.fileRefs || []).entries()) {
          const data = { ...file.linkedFileData }
          if (!["zotero", "mendeley"].includes(data.provider)) continue
          const groupKey = `${data.provider}GroupId`
          if (![groupKey, "importedByUserId", "importedByName"].some(key => key in data)) continue
          for (const [oldKey, newKey] of [[groupKey, "group_id"], ["importedByUserId", "importer_id"]]) {
            if (data[oldKey] != null && data[oldKey] !== "") {
              const value = String(data[oldKey])
              if (newKey in data && data[newKey] !== value) {
                throw new Error(`Conflicting ${newKey}: project ${project._id}, file ${file._id}`)
              }
              data[newKey] = value
            }
            delete data[oldKey]
          }
          delete data.importedByName
          changes[`${folderPath}.fileRefs.${j}.linkedFileData`] = data
        }
        visit(folder.folders, `${folderPath}.folders`)
      }
    }
    visit(project.rootFolder, "rootFolder")
    if (!Object.keys(changes).length) return
    const result = await db.projects.updateOne(
      { _id: project._id, rootFolder: { $eq: project.rootFolder } },
      { $set: changes }
    )
    if (!result.matchedCount) throw new Error(`Project changed during migration: ${project._id}`)
    updated += result.modifiedCount
  })
  print(`Updated ${updated} project(s).`)
})()
```

Le script prend en compte les dossiers imbriqués et ne modifie que les métadonnées Zotero/Mendeley. Il peut être réexécuté sans risque : une migration terminée affiche `Updated 0 project(s).` à l'exécution suivante. S'il s'arrête sur un conflit, examinez le projet/fichier signalé ; les projets précédents ont peut-être déjà été migrés.

Démarrez l'application mise à jour, rechargez l'éditeur et actualisez un fichier de bibliographie existant en tant qu'utilisateur l'ayant importé à l'origine. Les instantanés historiques ne sont pas réécrits. Pour revenir à l'ancienne application, restaurez la sauvegarde MongoDB.

Nous sommes très fiers d'annoncer la sortie d'Overleaf Pro 6.3.0, l'éditeur LaTeX en ligne le plus puissant et le plus complet de la communauté. Comme nous avons toujours eu à cœur d'améliorer l'expérience de nos utilisateurs, cette version apporte d'importants changements et de superbes fonctionnalités que vous allez adorer, notamment un assistant IA et l'intégration de gestionnaires de références tiers.

### Modifications

* Assistant de chat IA : discutez avec un modèle d'IA via votre propre fournisseur, directement dans votre éditeur.
* Assistant d'erreurs LaTeX : obtenez des corrections suggérées par l'IA pour les erreurs de compilation LaTeX.
* Intégration Mendeley : importez des références depuis Mendeley, comme avec Zotero.
* API Open in Overleaf : ajout d'une API permettant d'ouvrir du contenu dans Overleaf.
* Galerie de modèles : ajout de la pagination, de la recherche et du tri côté serveur, de sorte que les grandes galeries n'ont plus besoin de charger tous les modèles dans le navigateur.
* Traductions : mise à jour des correctifs de traduction pour la 6.3.0, y compris les nouveaux textes d'interface dans les langues prises en charge.
* Overleaf amont 6.3.0 : inclut l'édition de fichiers par onglets, des logos d'en-tête distincts pour les thèmes clair et sombre, ainsi que des mises à jour des dépendances et de l'image de base.
* Ajout de `OVERLEAF_HEADER_IMAGE_URL_LIGHT` et `OVERLEAF_HEADER_IMAGE_URL_DARK` pour prendre en charge des logos d'en-tête distincts pour les thèmes clair et sombre.
* Les fichiers peuvent désormais être ouverts dans différents onglets de l'éditeur.
* Ajout de la prise en charge de proxys HTTP(S) configurables, y compris des proxys hébergés localement, via `OVERLEAF_LINKED_URL_OUTBOUND_PROXY`, également utilisé par l'API Open in Overleaf.

#### Fonctionnalité 04 : pagination des modèles

La galerie effectue désormais la pagination, le tri et la recherche dans MongoDB. Elle fonctionne sans aucune préparation ; avec des milliers de modèles, vous pouvez néanmoins ajouter ces index pour qu'elle reste rapide (réexécution sans risque, `mongo`/`sharelatex` = noms de votre conteneur et de votre base de données) :

```bash
docker exec mongo mongosh sharelatex --quiet --eval '
db.templates.createIndex({category:1,lastUpdated:-1},{name:"category_1_lastUpdated_-1",background:true});
db.templates.createIndex({lastUpdated:-1},{name:"lastUpdated_-1",background:true});
db.templates.createIndex({category:1,name:1},{name:"category_1_name_1_ci",collation:{locale:"en",strength:2},background:true});
db.templates.createIndex({name:1},{name:"name_1_ci",collation:{locale:"en",strength:2},background:true});
'
```

Conservez la `collation` des deux index `*_ci` telle qu'écrite — la galerie interroge avec la même collation, et MongoDB n'utilise qu'un index correspondant.

## Ayakaleaf Pro 6.2.2

<strong>Date de sortie :</strong> 2026.07.23

Voir : [https://github.com/ayaka-notes/ayakaleaf-pro/releases/tag/pro-v6.2.2](https://github.com/ayaka-notes/ayakaleaf-pro/releases/tag/pro-v6.2.2)

### Modifications

Rétroportage des correctifs officiels livrés dans Overleaf amont `6.2.2` (par-dessus `6.2.1`) :

* Le secret des jetons d'invitation aux projets ne fuit plus dans les journaux. Le chiffreur des jetons d'invitation journalisait sa propre configuration à chaque chiffrement/déchiffrement, y compris les mots de passe de chiffrement dérivés de `OVERLEAF_INVITE_TOKEN_SECRET`.
* Migration de l'envoi d'e-mails du client AWS SES v1, en fin de vie, vers SESv2. Les instances configurées avec le pilote d'e-mail `ses` pouvaient ne plus envoyer aucun e-mail ; l'envoi passe désormais par `SESv2Client`.
* Les entrées de groupe du menu déroulant de partage de projet sont désormais conditionnées par le nouvel indicateur de fonctionnalité `group-link-sharing`, afin que le partage de lien de groupe ne soit plus proposé sur les instances où il ne s'applique pas.
* Correction de la fenêtre de partage de projet pour les collaborateurs. L'ouvrir en tant que non-propriétaire, ou avec le flux `sharing-updates` désactivé, envoyait une requête qui échouait systématiquement et affichait une erreur « something went wrong ».
* Ajout de `scripts/flush_docs_with_pending_updates.js` à document-updater, un script de maintenance qui récupère les documents restés avec une file `PendingUpdates` bloquée dans Redis après le vidage ou la suppression définitive de leur projet. Prend en charge `--dry-run` et une vérification de sécurité `--estimated-docs`.
* Mise à jour des dépendances : `multer` 2.2.0, `form-data` 2.5.6, `protobufjs` 7.6.3, `@grpc/grpc-js` 1.14.4.

Cette version inclut également les correctifs et améliorations suivants d'Ayakaleaf Pro :

* Ajout de traductions complètes pour 16 langues supplémentaires (cs, da, de, es, fi, fr, it, ja, ko, nl, no, pl, pt, ru, sv, tr), corrigeant des chaînes non traduites comme celles de la page de réinitialisation du mot de passe. Corrige [#38](https://github.com/ayaka-notes/ayakaleaf-pro/issues/38).
* Correction du nombre d'éléments affiché dans le bouton « show N more projects » du panneau d'administration, qui indiquait un nombre erroné car le paramètre de pluriel n'était pas transmis correctement.
* Correction des erreurs de validation de l'export GitHub, désormais affichées via des clés i18n statiques au lieu de messages bruts, et suppression des clés d'erreur qui ne sont plus utilisées par la fenêtre GitHub Sync.

## Ayakaleaf Pro 6.2.1

<strong>Date de sortie :</strong> 2026.07.18

Voir : [https://github.com/ayaka-notes/ayakaleaf-pro/releases/tag/pro-v6.2.1](https://github.com/ayaka-notes/ayakaleaf-pro/releases/tag/pro-v6.2.1)

### Modifications

Rétroportage des correctifs officiels livrés dans Overleaf amont `6.2.1` (par-dessus `6.2.0`) :

* Renforcement du message temps réel `applyOtUpdate` avec un schéma de validation strict au lieu d'accepter n'importe quel objet, ce qui rejette les opérations d'édition malformées.

Évite les problèmes de synchronisation intempestifs / de « modifications non enregistrées » liés à l'annulation et à l'édition concurrente.

<Warning>

* Une nouvelle variable d'environnement obligatoire, `OVERLEAF_INVITE_TOKEN_SECRET`, a été introduite. Vous devez la générer avec `openssl rand -base64 32`. Si elle n'est pas configurée, votre instance Overleaf ne démarrera pas.

Les fonctionnalités incluent :

* Ajout d'un exécuteur Python dans le navigateur.

## Ayakaleaf Pro 6.0.0

<strong>Date de sortie :</strong> 2026.02.17

Version de test, voir : [https://github.com/ayaka-notes/ayakaleaf-pro/releases/tag/pro-v6.0.0](https://github.com/ayaka-notes/ayakaleaf-pro/releases/tag/pro-v6.0.0)

Il s'agit d'une version de test, et également de notre version initiale d'Overleaf Pro. Cette version ne contient aucune fonctionnalité de Server Pro ; elle marque simplement notre point de départ. Nous ajouterons de nouvelles fonctionnalités par la suite, comme le panneau d'administration, git-bridge…

Dans cette version, nous avons introduit l'image Docker d'Overleaf pour ARM. Vous pouvez l'essayer si vous disposez d'un Mac ou d'un serveur ARM, mais certaines fonctionnalités risquent de ne pas bien fonctionner (pas encore testées).

### Image Docker

Vous trouverez l'image Docker ici : [https://github.com/ayaka-notes/overleaf-pro/pkgs/container/overleaf-pro](https://github.com/ayaka-notes/overleaf-pro/pkgs/container/overleaf-pro)

Pour l'image multi-architecture, voir [ici](https://github.com/ayaka-notes/overleaf-pro/pkgs/container/overleaf-pro/691283454?tag=6.0.0).

```bash
docker pull ghcr.io/ayaka-notes/overleaf-pro:6.0.0
```

### Migration des fichiers binaires

Cette nouvelle version réduit de moitié l'espace de stockage utilisé par les fichiers binaires.

Une migration en ligne est incluse dans la version `5.5`, permettant de limiter au maximum l'interruption de service lors de la mise à niveau. Avant de passer à Server Pro `v6`, assurez-vous d'utiliser déjà la dernière version de Server Pro `v5.5` ([Notes de version 5.x.x](https://docs.overleaf.com/on-premises/release-notes/release-notes-5.x.x)) et d'avoir exécuté la migration.

[Voir les instructions complètes de migration](https://docs.overleaf.com/on-premises/release-notes/release-notes-5.x.x/binary-files-migration).

### Mise à niveau de MongoDB vers la v8

Cette version relève la version minimale de MongoDB à `8.0`.

Si vous utilisez actuellement MongoDB `v6` ou une version antérieure, vous devrez mettre à jour une version majeure à la fois (`v6 → v7 → v8`).

<Warning>

Assurez-vous de disposer d'une sauvegarde de la [base de données](https://docs.overleaf.com/on-premises/maintenance/data-and-backups) **avant** la mise à niveau. En cas de retour en arrière, vous devrez restaurer cette sauvegarde.

</Warning>

Pour savoir comment mettre à niveau MongoDB `v6 → v7 → v8`, consultez notre guide pas à pas [ici](https://docs.overleaf.com/on-premises/maintenance/updating-mongodb#example-upgrading-mongodb-from-6.0-to-7.0-toolkit-users).

### Mise à niveau de Redis vers la v7.4

Cette version relève également la version minimale de Redis à `7.4`.

Remplacez `REDIS_IMAGE` dans votre `config/overleaf.rc` par `REDIS_IMAGE=7.4`.

### Nouvelles fonctionnalités

* Le partage par lien peut désormais être désactivé avec `OVERLEAF_DISABLE_LINK_SHARING=true`.
* `OVERLEAF_MAINTENANCE_MESSAGE` et `OVERLEAF_MAINTENANCE_MESSAGE_HTML` permettent désormais de personnaliser le titre et le contenu de la page de maintenance.
* `OVERLEAF_USER_HARD_DELETION_DELAY` et `OVERLEAF_PROJECT_HARD_DELETION_DELAY` peuvent être configurés (en millisecondes) pour modifier le délai d'expiration des utilisateurs/projets supprimés (90 jours par défaut).

### Corrections de bugs

* Correction de l'affichage du pied de page contenant des liens.
* Amélioration des messages d'erreur lors des échecs de connexion SAML.
* Correction de l'absence d'entrée dans le journal d'audit lorsque le statut administrateur d'un utilisateur est modifié lors d'une connexion SSO.
* Correction des erreurs du panneau Historique lorsque TLS est activé dans Redis.
* Les compilations peuvent désormais être arrêtées lors de l'utilisation de compilations hors sandbox.

### Autres modifications

* Tous les liens vers la page d'état (définie via `OVERLEAF_STATUS_PAGE_URL`) utilisent désormais `HTTPS` et s'ouvrent dans un nouvel onglet du navigateur.
