#### Services

L'infrastructure Overleaf Pro comprend quatre services principaux : `sharelatex`, `git-bridge` (facultatif), `mongo` et `redis`. Le service `sharelatex`, qui exécute l'application principale Server Pro, dépend des services `mongo` et `redis` pour sa base de données et ses fonctionnalités de cache et de temps réel, ainsi que de `git-bridge` pour gérer l'[intégration Git](/fr/on-premises/configuration/overleaf-toolkit/git-integration) (facultatif). Le seul port publié sur la machine hôte est le port 80, utilisé par le conteneur `sharelatex`.

Server Pro prend également en charge, de manière facultative, le [stockage compatible S3](/fr/on-premises/configuration/overleaf-toolkit/s3) pour les fichiers de projet et l'historique complet des projets, et peut faire office de proxy vers le [site de documentation principal d'Overleafarrow-up-right](https://www.overleaf.com/learn). Pour plus d'informations, consultez notre guide sur l'[ajout de pages d'aide LaTeX pour les utilisateurs](/fr/on-premises/configuration/overleaf-toolkit/adding-latex-user-help).

<Info>

Si nécessaire, MongoDB et Redis peuvent être externalisés à l'aide de variables d'environnement pointant vers des services externes. Pour plus d'informations, consultez [Configurer Overleaf](/fr/on-premises/configuration) si vous utilisez Docker Compose, et [Paramètres du Toolkit](/fr/on-premises/configuration/overleaf-toolkit/toolkit-settings) si vous utilisez l'Overleaf Toolkit.

</Info>

#### Compilation

Pour les [compilations en sandbox](/fr/on-premises/configuration/overleaf-toolkit/sandboxed-compiles), le conteneur `sharelatex` orchestre la création de nouveaux conteneurs chargés des compilations de projets ; il le fait via le socket Docker de la machine hôte. Vous pouvez en savoir plus sur l'éditeur et le processus complet de compilation et de mise en cache [ici](/fr/on-premises/getting-started/microservices#editor-and-compile-process).

#### Réseau

La communication entre les conteneurs s'effectue grâce à la résolution DNS interne de Docker via un réseau bridge dédié, et aucun pare-feu n'est activé. Par défaut, les services ci-dessus utilisent leurs ports standard respectifs, mais ceux-ci sont configurables via des variables d'environnement. Le conteneur `sharelatex` utilise le port 80 pour l'accès web externe (servi par Nginx), le conteneur `mongo` utilise le port 27017 et `redis` utilise le port 6379.

Pour les clients utilisant notre solution gérée [Overleaf Toolkitarrow-up-right](https://github.com/overleaf/toolkit), vous pouvez facultativement [activer un proxy TLS](/fr/on-premises/configuration/overleaf-toolkit/tls-proxy) pour terminer les connexions HTTPS avec Nginx via une variable d'environnement. Vous pouvez aussi utiliser votre proxy TLS existant.

<Info>

Vous pouvez consulter un diagramme expliquant le flux des requêtes [ici](/fr/on-premises/configuration/overleaf-toolkit/tls-proxy).

</Info>

#### Résumé

* En dehors du réseau Docker, seul le port 80 est accessible, et il est lié à Nginx. <strong>Remarque :</strong> le conteneur `sharelatex` exécute de nombreux [servicesarrow-up-right](https://github.com/overleaf/overleaf/tree/main/services) qui communiquent entre eux via HTTP. Toutefois, ces ports ne sont **pas** accessibles depuis l'extérieur du réseau Docker.
* À l'intérieur du réseau Docker, les services Overleaf, MongoDB, Redis et Git Bridge peuvent communiquer librement entre eux.
* À l'intérieur des conteneurs de [compilation en sandbox](/fr/on-premises/configuration/overleaf-toolkit/sandboxed-compiles), aucun réseau n'est disponible.
