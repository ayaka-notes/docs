Il est possible d'étendre une image TeX Live existante à l'aide d'un nouveau Dockerfile et de configurer l'application pour qu'elle utilise la nouvelle image.

Nous proposons ici quelques recommandations pour installer de nouveaux packages ou de nouvelles polices, mais la configuration d'une image personnalisée n'est pas couverte par nos conditions de support.

Les images TeX Live sont rarement mises à jour. Nous vous suggérons de reconstruire les images personnalisées lors de la mise à niveau de Server Pro.

<Danger>

Les sections suivantes s'appliquent uniquement à Server Pro et aux [Sandboxed Compiles](/fr/on-premises/configuration/overleaf-toolkit/sandboxed-compiles).

</Danger>

### Installer et mettre à jour de nouveaux packages

Vous pouvez utiliser des commandes `tlmgr` telles que `tlmgr install` et `tlmgr update` pour gérer les packages TeX Live, comme dans l'exemple suivant :

```dockerfile
FROM ghcr.io/ayaka-notes/texlive-full:2023.1

RUN tlmgr update --force ebproof
```

### Utiliser `tlmgr` dans une ancienne image TeX Live

Par défaut, `tlmgr` télécharge les ressources depuis la dernière version de TeX Live. Lorsque vous modifiez une ancienne image TeX Live, les téléchargements doivent être redirigés vers l'archive correspondante. Consultez la liste sur [https://www.tug.org/historic/](https://www.tug.org/historic/) pour trouver des miroirs des archives.

```dockerfile
FROM ghcr.io/ayaka-notes/texlive-full:2022.1

RUN tlmgr option repository <MIRROR>/systems/texlive/<YEAR>/tlnet-final
# e.g. RUN tlmgr option repository ftp://tug.org/historic/systems/texlive/2022/tlnet-final

RUN tlmgr update --force ebproof
```

### Installer de nouvelles polices

Il existe différentes procédures pour installer de nouvelles polices dans une distribution TeX Live, et l'installation d'une police personnalisée peut nécessiter plusieurs étapes. Consulter les [instructions d'installation des polices TeX](https://tug.org/fonts/fontinstall.html) dans la documentation officielle de TeX Live constitue probablement un bon point de départ.

Le `Dockerfile` suivant montre un exemple d'installation d'une police TrueType sur une image TeX Live 2022 existante :

```dockerfile
FROM ghcr.io/ayaka-notes/texlive-full:2022.1

COPY ./myfonts/*.ttf /usr/share/fonts/truetype/myfont/

# rebuild font information cache
RUN fc-cache
```

### Configurer Server Pro pour utiliser les nouvelles images

Utilisez le nom `ghcr.io/ayaka-notes/texlive-full` et un tag personnalisé pour construire la nouvelle image, comme ceci :

```bash
docker build -t ghcr.io/ayaka-notes/texlive-full:2023.1-custom
```

Nous pouvons maintenant configurer Server Pro pour utiliser la nouvelle image `2023.1-custom` en mettant à jour les variables d'environnement `TEX_LIVE_DOCKER_IMAGE` et `ALL_TEX_LIVE_DOCKER_IMAGES` :

```text wrap
TEX_LIVE_DOCKER_IMAGE: "ghcr.io/ayaka-notes/texlive-full:2023.1-custom"
ALL_TEX_LIVE_DOCKER_IMAGES: "ghcr.io/ayaka-notes/texlive-full:2023.1,ghcr.io/ayaka-notes/texlive-full:2023.1-custom"
```

Dans l'exemple ci-dessus, les nouveaux projets utilisent par défaut la nouvelle image `2023.1-custom`, tandis que `2023.1` reste disponible en cas de besoin.
