<Danger>

Il est important d'effectuer une [sauvegarde cohérente](/fr/on-premises/maintenance/data-and-backups#performing-a-consistent-backup) **avant** chaque mise à niveau de version majeure, afin de pouvoir revenir en arrière si nécessaire.

</Danger>

Le [toolkit ayakaleaf↗](https://github.com/ayaka-notes/toolkit) est un dépôt git : il est donc facile d'obtenir les nouvelles fonctionnalités du Toolkit. Exécutez simplement la commande `bin/upgrade` et suivez les instructions à l'écran.

Notez que la version de l'image Docker (dans `config/version`) est gérée indépendamment des mises à jour du code du Toolkit. Mettre à jour le code du Toolkit ne modifie **pas** automatiquement la version de l'image Docker que vous exécutez. Dans la plupart des cas, vous pouvez donc mettre à jour votre Toolkit sans mettre à niveau votre déploiement.

#### Le script `bin/upgrade`

Lorsque vous exécutez la commande `bin/upgrade`, le script vérifie si une mise à jour du code du Toolkit est disponible et vous propose de mettre à jour votre Toolkit. Vous pouvez toujours refuser cette mise à jour : rien ne sera alors modifié.

Si vous choisissez de mettre à jour le code du Toolkit, le script vérifie ensuite si la version _par défaut_ de l'image Docker a changé et vous propose de mettre à jour votre fichier de version local (dans `config/version`) pour qu'il corresponde à la nouvelle valeur par défaut.

Si vous choisissez de changer de version, le script vous guide ensuite à travers l'arrêt des services Docker, la réalisation d'une sauvegarde et le redémarrage des services Docker. Votre ancien fichier de version est automatiquement copié dans `config/__old-version`, au cas où vous auriez besoin de revenir à cette version des images Docker.

<Info>

Pour les installations isolées (air-gapped) qui importent manuellement les images Docker, définissez `PULL_BEFORE_UPGRADE=false` dans votre fichier `config/overleaf.rc`.

Consultez [cette page](/fr/on-premises/installation/air-gapped-offline-deployments) pour plus d'informations sur le déploiement dans des environnements isolés ou hors ligne.

</Info>

### Chemin de mise à niveau

Si vous exécutez une version d'Overleaf Community antérieure à la v6.0.0, consultez la [documentation officielle d'Overleaf](https://docs.overleaf.com/on-premises/maintenance/upgrading-your-deployment#upgrade-path) pour effectuer la mise à niveau.

Au sein d'Ayakaleaf Pro, effectuez d'abord la mise à niveau vers la dernière version corrective de votre ligne de versions actuelle, puis vers la suivante, par exemple `6.2.0 → 6.2.2 → 6.3.2`. Lisez les [notes de version](/fr/on-premises/release-notes/release-notes-6.x.x) de chaque version traversée : certaines nécessitent des étapes supplémentaires. Seule la dernière version est prise en charge.
