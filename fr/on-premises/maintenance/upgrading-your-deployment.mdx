<Danger>

Il est important d'effectuer une [sauvegarde cohérente](/fr/on-premises/maintenance/data-and-backups#performing-a-consistent-backup) **avant** chaque mise à niveau de version majeure, afin de pouvoir revenir en arrière si nécessaire.

</Danger>

Le [toolkit ayakaleaf↗](https://github.com/ayaka-notes/toolkit) est un dépôt Git ; il est donc facile d'obtenir les nouvelles fonctionnalités du Toolkit. Il suffit d'exécuter la commande `bin/upgrade` et de suivre les instructions affichées à l'écran.

Notez que la version de l'image Docker (dans `config/version`) est gérée séparément des mises à jour du code du Toolkit. La mise à jour du code du Toolkit ne modifie **pas** automatiquement la version de l'image Docker que vous exécutez. Dans la plupart des cas, vous pouvez donc mettre à niveau votre version du Toolkit sans mettre à niveau votre déploiement.

#### Le script `bin/upgrade`

Lorsque vous exécutez la commande `bin/upgrade`, le script vérifie si une mise à jour du code du Toolkit est disponible et vous propose de mettre à jour votre Toolkit. Vous pouvez toujours refuser cette mise à niveau, et rien ne sera modifié.

Si vous choisissez de mettre à jour le code du Toolkit, le script vérifie ensuite si la version _par défaut_ de l'image Docker a changé et vous propose de mettre à niveau votre fichier de version local (dans `config/version`) pour qu'il corresponde à la nouvelle valeur par défaut.

Si vous choisissez de changer de version, le script vous guide alors à travers les étapes d'arrêt des services Docker, de sauvegarde et de redémarrage des services Docker. Votre ancien fichier de version est automatiquement copié dans `config/__old-version`, au cas où vous auriez besoin de revenir à cette version des images Docker.

<Info>

Pour les installations isolées (air-gapped) qui importent manuellement les images Docker, définissez `PULL_BEFORE_UPGRADE=false` dans votre fichier `config/overleaf.rc`.

Consultez [cette page](/fr/on-premises/installation/air-gapped-offline-deployments) pour plus d'informations sur le déploiement dans des environnements isolés/hors ligne.

</Info>

### Chemin de mise à niveau

Si vous utilisez une version d'Overleaf Community antérieure à la v6.0.0, consultez la [documentation officielle d'Overleaf](https://docs.overleaf.com/on-premises/maintenance/upgrading-your-deployment#upgrade-path) pour effectuer la mise à niveau.
