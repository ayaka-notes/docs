### Consulter le journal d'audit d'un projet

Les administrateurs peuvent consulter un **Audit Log** (journal d'audit) pour chaque projet. Ce journal d'audit indique des événements tels que le passage du partage par lien entre privé et basé sur un jeton, l'envoi et l'acceptation d'invitations, ou encore l'arrivée d'un utilisateur dans le projet au moyen d'un jeton. Les administrateurs peuvent consulter ces journaux projet par projet via **Your Instance** -> **Admin** -> **Manage Users**, puis :

* Recherchez l'utilisateur
* Cliquez sur l'onglet **Projects**
* Sélectionnez un projet
* Cliquez sur l'icône (i)
* Cliquez sur l'onglet **Audit Log**

Si un projet est partagé avec un collaborateur nommé (à l'aide de son adresse e-mail), une fois que le destinataire a rejoint le projet, il apparaît dans la fenêtre de partage avec ses autorisations et est visible par le propriétaire du projet. Ces informations sont également affichées aux administrateurs lorsqu'ils consultent l'onglet Project Info du projet depuis le panneau d'administration.

### Récupérer des documents supprimés

1. Connectez-vous avec vos identifiants d'administrateur
2. Cliquez sur **Admin** et sélectionnez **Manage Users**
3. Dans le champ de recherche, saisissez l'adresse e-mail de l'utilisateur dont vous souhaitez restaurer le document
4. Cliquez sur son adresse e-mail dans la liste des résultats pour ouvrir sa page d'informations utilisateur
5. Cliquez sur l'onglet **Projects** et utilisez le champ de recherche pour trouver le projet
6. Cliquez sur l'icône d'information à côté du nom du projet pour ouvrir **Project Info**
7. Cliquez sur l'onglet **Deleted Docs**
8. Cliquez sur le bouton **Undelete** à côté du document supprimé pour le restaurer dans le projet de l'utilisateur.

Le fichier restauré prend le format suivant : `FILENAME-TIMESTAMP.EXTENSION`. Par exemple, une version restaurée de `main.tex` sera restaurée à la racine du projet sous le nom de fichier `main-2024-02-23-130441542.tex`.

### Transférer la propriété d'un projet

Le panneau d'administration de Server Pro dispose d'une page dédiée pour chaque projet. Vous pouvez y accéder soit en recherchant l'utilisateur sur "/admin/user", puis en allant dans son onglet **Projects**, en trouvant le projet dans la liste et en cliquant sur l'icône d'information ; soit en accédant directement à la page avec un project-id connu [**https://your-instance-url/admin/project/**](https://your-instance-url/admin/project/). Sur la page d'informations du projet, vous trouverez un bouton **Transfer Ownership**, qui ouvre une fenêtre dans laquelle vous pouvez désigner n'importe quel utilisateur comme nouveau propriétaire. Le nouveau propriétaire n'a pas besoin d'être déjà collaborateur du projet.

<Info>

Notez que, dans le cadre du transfert de propriété, l'ancien propriétaire est ajouté comme collaborateur avec un accès en lecture et en écriture au projet.

</Info>

### Modifier le délai d'expiration de compilation des projets

Le délai d'expiration de compilation par défaut des projets est actuellement fixé à 180 secondes. Il est possible de modifier cette valeur, en deux étapes.

Tout d'abord, modifiez le fichier **config/variables.env** pour y ajouter la variable d'environnement `COMPILE_TIMEOUT` et définissez sa valeur sur le délai souhaité en secondes. Par exemple, `COMPILE_TIMEOUT=300` pour 5 minutes.

<Danger>

Il n'est pas utile de dépasser 10 minutes. Si vous le faites, vous atteindrez très probablement un délai d'expiration dans un autre composant de l'application.

</Danger>

Une fois cette modification effectuée, vous devez recréer le conteneur **sharelatex** en exécutant la commande `bin/up -d`.

La définition de cette variable d'environnement ne modifie le délai d'expiration que pour les nouveaux utilisateurs ; elle ne sera **pas** appliquée rétroactivement aux utilisateurs existants, car cette valeur est renseignée lors de la création de l'utilisateur.

Pour ajuster le délai d'expiration des utilisateurs existants, vous devez modifier chaque enregistrement utilisateur dans la base de données. Nous vous conseillons d'être très prudent et recommandons d'effectuer une sauvegarde cohérente avant toute modification.

Vous trouverez des informations sur la réalisation de sauvegardes [ici](/fr/on-premises/maintenance/data-and-backups).

Pour mettre à jour la valeur du délai d'expiration de compilation de tous les utilisateurs existants, exécutez la commande shell suivante sur l'hôte Docker :

```bash wrap
echo 'db.users.updateMany({}, {$set: {"features.compileTimeout": <value>}})' | docker exec -i mongo mongosh --quiet localhost/sharelatex
```

Remplacez `<value>` dans la requête ci-dessus par le délai d'expiration souhaité en secondes.

Une fois la commande terminée, un accusé de réception indiquant le nombre d'enregistrements modifiés devrait s'afficher. Vous pouvez ensuite taper exit puis appuyer sur la touche Entrée pour revenir au shell de l'hôte.

### Suivre l'accès aux projets

Il est possible de savoir qui a chargé un projet et quand, avec la commande suivante :

```bash wrap
docker exec sharelatex bash -c 'grep "join project request" /var/log/overleaf/web.log'
```

Vous obtiendrez ainsi le `timestamp`, le `user_id` et le `project_id`.
