## Créer un utilisateur administrateur {#creating-an-administrator-user}

Déploiements avec l'Overleaf Toolkit :

```bash title="Overleaf Toolkit" wrap
$ bin/docker-compose exec sharelatex /bin/bash -ce "cd /overleaf/services/web && node modules/server-ce-scripts/scripts/create-user --admin --email=joe@example.com"
```

Déploiements avec l'ancien docker-compose.yml :

```bash title="Legacy docker-compose" wrap
$ docker exec sharelatex /bin/bash -ce "cd /overleaf/services/web && node modules/server-ce-scripts/scripts/create-user --admin --email=joe@example.com"
```

La commande crée un utilisateur avec l'adresse e-mail fournie s'il n'existe pas déjà, et en fait un administrateur. La sortie de la commande inclut une URL à visiter pour définir le mot de passe de cet utilisateur et se connecter pour la première fois.

<Info>

Pour une approche automatisée, vous pouvez utiliser le même script pour créer des utilisateurs ordinaires comme des administrateurs. Pour les utilisateurs ordinaires, omettez l'option --admin.

</Info>

Si vous utilisez des comptes internes pour l'authentification et devez promouvoir un utilisateur existant au rang d'administrateur de l'instance ou révoquer ses droits d'administrateur, procédez comme suit :

<Steps>
<Step title="Via l'interface d'administration">
* Connectez-vous en tant qu'administrateur existant.
* Cliquez sur Admin -> Manage Users.
* Recherchez l'utilisateur et cliquez sur son nom.
* Cliquez sur l'icône en forme de crayon.
* Activez ou désactivez Admin.
* Cliquez sur Save pour terminer.
</Step>
</Steps>

## Supprimer des utilisateurs {#deleting-users}

Il est généralement conseillé de ne supprimer des comptes que lorsqu'ils ne sont plus nécessaires. Supprimer un compte retire le compte et fait perdre aux collaborateurs l'accès aux projets. Pour empêcher un utilisateur de se connecter tout en conservant ses données, [désactivez le compte](/on-premises/user-guide/administrators/user-management#disable-or-enable-an-account) à la place.

Par défaut, les comptes font l'objet d'une suppression logique (soft delete). Pour savoir comment supprimer définitivement des utilisateurs de votre instance, consultez `ENABLE_CRON_RESOURCE_DELETION` dans le guide des [variables d'environnement](/fr/on-premises/configuration/overleaf-toolkit/environment-variables).

<Info>

Les comptes font l'objet d'une suppression logique par défaut. Consultez `ENABLE_CRON_RESOURCE_DELETION` pour le comportement de suppression définitive.

</Info>

### Via Admin -> Manage Users {#via-admin->-manage-users}

<Steps>
<Step title="">
* Connectez-vous en tant qu'administrateur.
* Cliquez sur Admin -> Manage Users.
* Recherchez l'utilisateur et cochez la case à côté de son nom.
* Cliquez sur l'icône de corbeille.
* Cliquez sur Delete account pour confirmer.
</Step>
</Steps>

### Via la ligne de commande {#via-the-command-line}

Les comptes utilisateur (et leurs projets) peuvent être supprimés à l'aide des commandes suivantes.

Déploiements avec l'Overleaf Toolkit :

```bash title="Overleaf Toolkit"
$ bin/docker-compose exec sharelatex /bin/bash -ce "cd /overleaf/services/web && node modules/server-ce-scripts/scripts/delete-user.mjs --email=joe@example.com"
```

Déploiements avec l'ancien docker-compose.yml :

```bash title="Legacy docker-compose"
$ docker exec sharelatex /bin/bash -ce "cd /overleaf/services/web && node modules/server-ce-scripts/scripts/delete-user.mjs --email=joe@example.com"
```

<Danger>

Le script de suppression utilise une option de forçage codée en dur qui garantit que la suppression a lieu même si l'e-mail de suppression de compte ne peut pas être envoyé (par exemple, lorsque l'adresse e-mail de l'utilisateur n'est plus en service).

</Danger>

<Info>

L'option --skip-email permet de ne pas envoyer d'e-mail d'information à l'utilisateur supprimé.

</Info>

## Restaurer un utilisateur supprimé logiquement {#restoring-a-soft-deleted-user}

Si un utilisateur n'a été supprimé que de manière réversible, vous pouvez restaurer son compte et les projets supprimés avec lui. Les projets que l'utilisateur avait lui-même supprimés restent supprimés.

<Steps>
<Step title="">
* Connectez-vous en tant qu'administrateur.
* Cliquez sur Admin -> Manage Users.
* Recherchez l'utilisateur que vous souhaitez restaurer.
* Cliquez sur Display deleted users.
* Cliquez sur l'icône en forme de flèche dans la ligne de l'utilisateur.
* Cliquez sur Restore pour confirmer.
</Step>
</Steps>

<Danger>

Lorsque ENABLE\_CRON\_RESOURCE\_DELETION est défini à true, les comptes supprimés logiquement peuvent être restaurés dans un délai de 90 jours. Passé ce délai, la récupération du compte n'est plus possible.

</Danger>

## Compter les utilisateurs {#counting-users}

Vous pouvez obtenir le nombre d'utilisateurs via l'interface d'administration à l'adresse https://you-instance-url/admin/user#license. Pour des vérifications et des exports automatisés, les exemples suivants peuvent vous aider.

Nombre total d'utilisateurs :

```bash title="Total number of users"
echo 'db.users.countDocuments()' | docker exec -i mongo mongosh --quiet localhost/sharelatex
# overleaf [direct: primary] sharelatex> 16
```

Nombre total d'utilisateurs via le point de terminaison des métriques :

```bash title="Num active users from metrics"
docker exec sharelatex curl http://127.0.0.1:3000/metrics | grep num_active_users
# # HELP num_active_users num_active_users
# # TYPE num_active_users gauge
# num_active_users{app="web-api",host="b3ae4ff549d8"} 16
```

Nombre total d'utilisateurs actifs (exemple : utilisateurs actifs au cours des 365 derniers jours) :

```bash title="Total number of active users"
echo 'db.users.countDocuments({ lastActive: { $gte: new Date(new Date().getTime() - (365 * 24 * 60 * 60 * 1000)) } })' | docker exec -i mongo mongosh --quiet localhost/sharelatex
# overleaf [direct: primary] sharelatex> 10
```

## Mettre à jour les informations d'un compte utilisateur {#updating-user-account-information}

La manière de mettre à jour un compte dépend de l'activation ou non du SSO.

* Si le SSO n'est pas utilisé :
  * Les administrateurs peuvent modifier les informations d'un compte utilisateur via Admin -> Manage Users (e-mail, prénom, nom, et génération d'un lien de réinitialisation du mot de passe).
  * Les utilisateurs ordinaires peuvent mettre à jour leurs propres informations via Account -> Account Settings (y compris changer leur mot de passe et générer des jetons d'authentification Git).
* Si le SSO est utilisé :
  * Ayakaleaf Pro peut être configuré pour mettre à jour le prénom et le nom d'un utilisateur lors de la connexion, à partir du système d'authentification.
  * Lorsque OVERLEAF\_SAML\_UPDATE\_USER\_DETAILS\_ON\_LOGIN ou OVERLEAF\_LDAP\_UPDATE\_USER\_DETAILS\_ON\_LOGIN valent true, le formulaire des informations utilisateur sur https://your-instance-url/user/settings est désactivé, et le prénom et le nom ne peuvent être définis que dans votre système de gestion des identités.

Pour plus de détails, voir :

* [Configuration SAML 2.0](/fr/on-premises/configuration/overleaf-toolkit/authentication/saml-authentication)
* [Configuration LDAP](/fr/on-premises/configuration/overleaf-toolkit/authentication/ldap-authentication)

### Q\&A {#q&a}

<Accordion title="Puis-je créer des utilisateurs SSO à l'avance, par exemple via une API ?">

<strong>Réponse :</strong> Il n'existe pas d'API HTTP pour cela. Créez le compte avec le script `create-user` ci-dessus (sans `--admin`), ou dans **Admin → Manage Users** avec **Create account**. Lorsque `EXTERNAL_AUTH` est défini, ce formulaire propose une option **Log in with SSO**, qui crée le compte sans mot de passe local et sans e-mail ni lien d'activation : la boîte de dialogue se ferme après **Create**. Lors de la première connexion LDAP, SAML ou OIDC, l'utilisateur obtient le compte existant ayant la même adresse e-mail au lieu d'un nouveau, voir [Comptes et mots de passe](/fr/on-premises/configuration/overleaf-toolkit/authentication#accounts-and-passwords).

</Accordion>

<Accordion title="Puis-je exporter la liste des utilisateurs et la restaurer plus tard ?">

<strong>Réponse :</strong> Non. Il n'existe aucun export ni import des comptes utilisateurs, ni dans **Admin → Manage Users** ni sous forme de script. Les comptes sont stockés dans MongoDB ; sauvegardez-les et restaurez-les donc avec une [sauvegarde MongoDB](/fr/on-premises/maintenance/data-and-backups#mongodb). Le script `export-user-projects.mjs` exporte les projets des utilisateurs sous forme de fichiers zip, et non les comptes, voir [Exporter des projets](/fr/on-premises/maintenance/data-and-backups/exporting-projects).

</Accordion>

<Accordion title="Combien de temps le lien de `create-user` est-il valide, et comment réinitialiser un mot de passe sans e-mail ?">

<strong>Réponse :</strong> Le lien affiché par `create-user` est valide pendant 7 jours, et il fonctionne sans SMTP puisque vous le copiez depuis la sortie. Pour obtenir un nouveau lien, exécutez à nouveau `create-user` avec la même adresse e-mail. Pour un compte existant, la commande se contente d'afficher un nouveau lien, mais elle définit aussi l'indicateur d'administrateur du compte en fonction de `--admin` ; conservez donc `--admin` lorsque vous l'exécutez pour un administrateur.

Un administrateur peut aussi obtenir un lien de réinitialisation sans e-mail : dans **Admin → Manage Users**, cliquez sur l'icône de cadenas dans la ligne de l'utilisateur, puis sur **Send reset link**, et copiez le lien depuis la boîte de dialogue. Il est valable 1 heure, voir [Envoyer un lien d'activation ou de réinitialisation](/on-premises/user-guide/administrators/user-management#send-an-activation-or-reset-link).

Ou définissez directement un mot de passe : cliquez sur le nom de l'utilisateur, puis sur l'icône en forme de crayon, saisissez un **New password** d'au moins 8 caractères et cliquez sur **Save**. Les comptes qui se connectent uniquement via LDAP, SAML ou OIDC ne peuvent obtenir de mot de passe d'aucune de ces deux manières.

</Accordion>
