Connectez un projet à un dépôt GitLab. Les modifications circulent dans les deux sens, et uniquement lorsque vous cliquez sur **Sync** : rien ne se synchronise tout seul.

<Info>

Un administrateur doit d'abord activer la [synchronisation GitLab](/fr/on-premises/configuration/overleaf-toolkit/integrations/gitlab-synchronisation).

</Info>

## Lier votre compte GitLab {#link-your-gitlab-account}

Vous ne le faites qu'une fois.

<Steps>
<Step title="Ouvrir les paramètres de votre compte">
Cliquez sur **Account**, puis sur **Account settings**. Sous **Project synchronisation**, trouvez **GitLab** et cliquez sur **Link**.

<Frame caption="GitLab dans les paramètres du compte">
  <img src="/images/on-premises/gitlab-sync-link.png" alt="La section GitLab des paramètres du compte avec un bouton Link" />
</Frame>
</Step>

<Step title="Autoriser sur GitLab">
GitLab s'ouvre. Connectez-vous si on vous le demande, puis autorisez l'application.
</Step>

<Step title="Vérifier le lien">
Vous revenez aux paramètres du compte. Un message vert indique que votre compte GitLab est lié, et le bouton indique maintenant **Unlink**.

<Frame caption="Votre compte GitLab est lié">
  <img src="/images/on-premises/gitlab-sync-linked.png" alt="La section GitLab des paramètres du compte avec un bouton Unlink" />
</Frame>
</Step>
</Steps>

Si votre compte n'est pas encore lié, **Import from GitLab** et la carte **GitLab** de l'éditeur vous demandent d'abord de le lier. Cliquez sur **Link to your GitLab account**. Vous arrivez également dans les paramètres du compte, dans un nouvel onglet si vous étiez dans l'éditeur. Revenez ensuite en arrière et recommencez.

<Frame caption="L'invite lorsque votre compte n'est pas lié">
  <img src="/images/on-premises/gitlab-sync-link-prompt.png" alt="La boîte de dialogue Import from GitLab avec un bouton Link to your GitLab account" />
</Frame>

## Importer un dépôt {#import-a-repository}

Cela crée un nouveau projet à partir d'un dépôt GitLab, déjà lié à celui-ci.

<Steps>
<Step title="Ouvrir la boîte de dialogue d'importation">
Sur la page des projets, cliquez sur **New project**, puis sur **Import from GitLab**.

<Frame caption="Le menu New project">
  <img src="/images/on-premises/gitlab-sync-new-project-menu.png" alt="Le menu New project avec Import from GitLab" />
</Frame>
</Step>

<Step title="Choisir le dépôt">
Cliquez sur **Import to Overleaf** à côté du dépôt. La liste contient vos dépôts et ceux de vos groupes.

<Frame caption="Vos dépôts GitLab">
  <img src="/images/on-premises/gitlab-sync-import.png" alt="La boîte de dialogue Import from GitLab listant quatre dépôts" />
</Frame>
</Step>

<Step title="Vérifier le projet">
Le nouveau projet s'ouvre avec les fichiers du dépôt.

<Frame caption="Le projet importé">
  <img src="/images/on-premises/gitlab-sync-imported.png" alt="L'éditeur affichant le projet importé avec ses fichiers et le PDF compilé" />
</Frame>
</Step>
</Steps>

## Exporter un projet vers un nouveau dépôt {#export-a-project-to-a-new-repository}

Cela crée un dépôt à partir d'un projet et les lie. Un projet ne peut être lié que de cette façon ou par importation : vous ne pouvez pas le lier à un dépôt qui existe déjà.

<Steps>
<Step title="Ouvrir GitLab dans l'éditeur">
Ouvrez le projet. Dans la barre de gauche, cliquez sur **Integrations**, puis sur **GitLab**.

<Frame caption="Le panneau Integrations">
  <img src="/images/on-premises/gitlab-sync-integrations.png" alt="Le panneau Integrations avec la carte GitLab" />
</Frame>
</Step>

<Step title="Renseigner le dépôt">
Choisissez l'**Owner**, qui peut être vous ou l'un de vos groupes. Lorsque vous choisissez un groupe, ce champ s'appelle **Organization**. **Repository Name** reprend au départ le nom du projet. La description est facultative, et **Private** est sélectionné par défaut. Cliquez sur **Create a GitLab repository**.

<Frame caption="Export Project to GitLab">
  <img src="/images/on-premises/gitlab-sync-export.png" alt="Le formulaire Export Project to GitLab rempli" />
</Frame>

Si le nom est déjà pris, la boîte de dialogue affiche <strong>Please check that the repository name is valid, and that you have permission to create the repository.</strong> Changez le nom et cliquez à nouveau sur le bouton.
</Step>

<Step title="Vérifier le lien">
La boîte de dialogue indique maintenant **This project is linked to** et nomme le dépôt.

<Frame caption="Le projet est lié">
  <img src="/images/on-premises/gitlab-sync-exported.png" alt="La boîte de dialogue Sync with GitLab après l'exportation" />
</Frame>
</Step>
</Steps>

## Synchroniser {#sync}

<Steps>
<Step title="Ouvrir la boîte de dialogue de synchronisation">
Ouvrez un projet lié. Dans la barre de gauche, cliquez sur **Integrations**, puis sur **GitLab**.

**Recent commits in GitLab** liste ce qui va arriver dans le projet.

<Frame caption="Un nouveau commit en attente sur GitLab">
  <img src="/images/on-premises/gitlab-sync-new-commits.png" alt="La boîte de dialogue Sync with GitLab listant un nouveau commit" />
</Frame>
</Step>

<Step title="Décrire vos modifications">
Si vous avez modifié quelque chose dans le projet, un champ de message de commit apparaît. Il est facultatif : si vous le laissez vide, le commit s'appelle `Updates from Overleaf`.

<Frame caption="Le message de commit de vos modifications">
  <img src="/images/on-premises/gitlab-sync-commit-message.png" alt="La boîte de dialogue Sync with GitLab avec un message de commit rempli" />
</Frame>
</Step>

<Step title="Cliquer sur Sync">
Cliquez sur **Sync**. Les nouveaux commits de GitLab arrivent dans le projet, et vos modifications partent vers la branche par défaut du dépôt. Si les deux côtés ont modifié des choses différentes, elles sont fusionnées pour vous.
</Step>

<Step title="Vérifier le résultat">
La boîte de dialogue affiche <strong>No new commits in GitLab since last merge.</strong> et le champ de message de commit a disparu. Les fichiers de l'éditeur et les commits sur GitLab sont à jour.

<Frame caption="Tout est synchronisé">
  <img src="/images/on-premises/gitlab-sync-done.png" alt="La boîte de dialogue Sync with GitLab après la synchronisation, sans nouveau commit" />
</Frame>
</Step>
</Steps>

### Si les mêmes lignes ont changé des deux côtés {#if-the-same-lines-changed-on-both-sides}

La boîte de dialogue indique que les modifications n'ont pas pu être fusionnées et nomme une nouvelle branche, `overleaf-YYYY-MM-DD-HHMMSS`, qui contient vos modifications. Overleaf ouvre aussi une merge request depuis cette branche sur GitLab.

<Frame caption="Un conflit">
  <img src="/images/on-premises/gitlab-sync-conflict.png" alt="La boîte de dialogue Sync with GitLab avec un avertissement de conflit de fusion" />
</Frame>

1. Fusionnez cette branche dans la branche par défaut sur GitLab ou avec Git. Vous pouvez fermer la boîte de dialogue entre-temps : elle affiche le même message lorsque vous la rouvrez.
2. Cliquez sur **I have manually merged. Continue**. Le résultat fusionné arrive dans le projet. Si vous cliquez avant que la branche soit fusionnée, la boîte de dialogue reste inchangée.
3. La branche reste sur GitLab, sauf si vous l'avez supprimée lors de la fusion. Supprimez-la lorsque vous n'en avez plus besoin.

La même boîte de dialogue apparaît lorsque les règles de fusion du dépôt bloquent la merge request, par exemple lorsqu'elle nécessite une approbation, même si aucune ligne n'est en conflit. Dès que la règle le permet, fusionnez la merge request sur GitLab et cliquez sur **I have manually merged. Continue**. Consultez [Fonctionnement de la synchronisation avec GitLab](/fr/on-premises/configuration/overleaf-toolkit/integrations/gitlab-synchronisation#how-syncing-works-with-gitlab).

## Supprimer le lien d'un projet {#unlink-a-project}

Faites-le lorsque vous ne voulez plus que le projet se synchronise.

<Steps>
<Step title="Cliquer sur Unlink">
Dans la boîte de dialogue de synchronisation, cliquez sur **Unlink**.
</Step>

<Step title="Confirmer">
Cliquez sur **Confirm**. Cela supprime uniquement le lien : la connexion à un dépôt dont vous êtes propriétaire, mentionnée dans l'avertissement, est une option dont vous disposez ensuite, pas quelque chose qui se produit maintenant.

<Frame caption="Confirmer la suppression du lien">
  <img src="/images/on-premises/gitlab-sync-unlink-project.png" alt="La boîte de dialogue Sync with GitLab demandant de confirmer la suppression du lien" />
</Frame>
</Step>

<Step title="Vérifier le résultat">
La boîte de dialogue affiche maintenant **Export Project to GitLab**. Le projet et le dépôt conservent tous deux leur contenu. Pour synchroniser à nouveau, exportez le projet vers un nouveau dépôt, ou importez le dépôt dans un nouveau projet.
</Step>
</Steps>

## Supprimer le lien de votre compte GitLab {#unlink-your-gitlab-account}

Dans **Account settings**, sous **GitLab**, cliquez sur **Unlink**, puis à nouveau sur **Unlink** dans la boîte de dialogue.

<Frame caption="Supprimer le lien de votre compte">
  <img src="/images/on-premises/gitlab-sync-unlink-account.png" alt="La boîte de dialogue Unlink GitLab Account" />
</Frame>

Vos projets restent liés à leurs dépôts. Vous ne pouvez pas les synchroniser tant que vous n'avez pas lié à nouveau votre compte.

<Info>

Pour savoir qui peut faire quoi dans un projet partagé, consultez [Qui peut lier et synchroniser](/fr/on-premises/configuration/overleaf-toolkit/integrations/gitlab-synchronisation#who-can-link-and-sync).

</Info>
