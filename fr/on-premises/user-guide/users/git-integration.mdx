Travaillez sur un projet depuis votre propre ordinateur avec Git. Les modifications ne sont transférées que lorsque vous exécutez `git pull` ou `git push`.

<Info>

Un administrateur doit d'abord activer l'[intégration Git](/fr/on-premises/configuration/overleaf-toolkit/integrations/git-integration).

</Info>

## Créer un jeton {#create-a-token}

Git se connecte avec un jeton d'authentification Git, et non avec le mot de passe de votre compte.

<Steps>
<Step title="Ouvrir les paramètres de votre compte">
Cliquez sur **Account**, puis sur **Account settings**. Sous **Git integration**, cliquez sur **Generate token**. Une fois que vous avez un jeton, ce bouton s'appelle **Add another token**.

<Frame caption="L'intégration Git dans les paramètres du compte">
  <img src="/images/on-premises/git-integration-settings.png" alt="La section Git integration des paramètres du compte avec un bouton Generate token" />
</Frame>
</Step>

<Step title="Copier le jeton">
Cliquez sur **Copy** et conservez le jeton en lieu sûr. Vous ne le voyez qu'une seule fois. Cliquez ensuite sur **Close**.

<Frame caption="Votre nouveau jeton">
  <img src="/images/on-premises/git-integration-token.png" alt="La boîte de dialogue du jeton d'authentification Git avec un bouton Copy" />
</Frame>
</Step>

<Step title="Vérifier le jeton">
La liste affiche maintenant le début du jeton, sa date de création et sa dernière utilisation. Il expire au bout d'un an. Vous pouvez avoir jusqu'à 10 jetons.

<Frame caption="Vos jetons">
  <img src="/images/on-premises/git-integration-tokens.png" alt="La liste des jetons avec un jeton" />
</Frame>
</Step>
</Steps>

## Cloner un projet {#clone-a-project}

<Steps>
<Step title="Ouvrir l'intégration Git dans l'éditeur">
Ouvrez le projet. Dans la barre de gauche, cliquez sur **Integrations**, puis sur **Git integration**.

<Frame caption="Le panneau Integrations">
  <img src="/images/on-premises/git-integration-panel.png" alt="Le panneau Integrations avec la carte Git integration" />
</Frame>
</Step>

<Step title="Copier la commande">
La boîte de dialogue **Clone with Git** affiche la commande, avec l'adresse de votre site et l'ID du projet. Cliquez sur **Copy**. Si vous n'avez pas encore de jeton, **Go to settings** ouvre les paramètres de votre compte dans un nouvel onglet.

<Frame caption="La commande de clonage">
  <img src="/images/on-premises/git-integration-clone.png" alt="La boîte de dialogue Clone with Git avec la commande git clone" />
</Frame>
</Step>

<Step title="L'exécuter">
Collez la commande dans un terminal. Lorsque Git demande un mot de passe, collez votre jeton.

```text
$ git clone https://git@<your-site>/git/<project-id>
Cloning into '<project-id>'...
Password for 'https://git@<your-site>': <your-token>
```

Un dossier portant l'ID du projet contient maintenant les fichiers du projet, sur la branche `main`. Pour choisir le nom du dossier, ajoutez-le à la fin de la commande.
</Step>
</Steps>

Git demande le jeton chaque fois qu'il contacte le site. Pour qu'il soit mémorisé, activez un credential helper : Git le demande une dernière fois, puis le conserve. Le helper `store` le conserve non chiffré dans `~/.git-credentials`.

```bash
git config --global credential.helper store
```

## Récupérer les modifications de l'éditeur {#pull-changes-from-the-editor}

Dans le dossier, exécutez :

```bash
git pull
```

Git liste les fichiers modifiés. Les modifications faites dans l'éditeur arrivent sous forme de commits nommés `Update on Overleaf.`.

```text
Updating db007e3..c3e6332
Fast-forward
 main.tex | 2 +-
 1 file changed, 1 insertion(+), 1 deletion(-)
```

## Envoyer vos modifications {#push-your-changes}

Faites un commit de vos modifications, puis envoyez-les avec push :

```bash
git add main.tex
git commit -m "Add a line from Git"
git push
```

La dernière ligne de la sortie indique la branche qui a avancé :

```text
   53aca61..db007e3  main -> main
```

Les modifications apparaissent dans l'éditeur, et un éditeur ouvert se met à jour de lui-même. Les nouveaux fichiers, dossiers et renommages apparaissent dans l'arborescence des fichiers. Dans **History**, votre modification est marquée <strong>You (via Git)</strong>. Votre message de commit n'y est pas affiché.

### Si Git refuse votre push {#if-git-refuses-your-push}

Si le projet a changé entre-temps, Git rejette le push :

```text
 ! [rejected]        main -> main (fetch first)
```

Récupérez d'abord ces modifications, puis renvoyez :

```bash
git pull --no-rebase --no-edit
git push
```

Un simple `git pull` peut s'arrêter avec `fatal: Need to specify how to reconcile divergent branches.` L'option `--no-rebase` ci-dessus y répond : elle fusionne les deux côtés.

Si les mêmes lignes ont changé des deux côtés, le pull s'arrête avec `CONFLICT (content): Merge conflict in main.tex`. Corrigez le fichier, puis :

```bash
git add main.tex
git commit -m "Merge the changes from the editor"
git push
```

Le site n'accepte pas deux choses :

* Les autres branches : `! [remote rejected] feature -> feature (wrong branch)`. Seule `main` existe, envoyez donc votre travail sur celle-ci.
* Les force push : `! [remote rejected] main -> main (forced push prohibited)`. Placez plutôt vos modifications par-dessus la `main` actuelle.

### Si Git affiche Authentication failed {#if-git-says-authentication-failed}

```text
remote: Enter your Git authentication token when prompted for a password.
fatal: Authentication failed for 'https://<your-site>/git/<project-id>/'
```

Le jeton est erroné ou a été supprimé, ou vous avez saisi le mot de passe de votre compte. Créez un nouveau jeton si vous ne l'avez plus, car vous ne pouvez pas revoir un jeton existant.

## Supprimer un jeton {#delete-a-token}

Dans **Account settings**, sous **Git integration**, cliquez sur l'icône de suppression à côté du jeton, puis sur **Delete** dans la boîte de dialogue. Dès lors, Git répond `Authentication failed` à ce jeton.
