Chaque projet possède son propre serveur MCP, afin qu'un client IA sur votre ordinateur puisse lire et modifier le projet, le compiler et répondre à ses commentaires. Le client se connecte avec un jeton d'authentification Git.

<Info>

Si vous ne voyez pas de carte **MCP server**, consultez [Serveur MCP](/fr/on-premises/configuration/overleaf-toolkit/integrations/mcp-server) pour votre administrateur.

</Info>

## Nouveautés de la v6.3.3 {#new-in-v6-3-3}

À partir de la v6.3.3, le client peut aussi travailler avec l'historique du projet : lister les modifications, comparer deux versions, lire un fichier tel qu'il était, enregistrer et supprimer des versions, et restaurer un fichier ou le projet entier. Il peut lister les modifications suivies et les accepter ou les rejeter, et faire de ses propres modifications des modifications suivies si vous le lui demandez. Il peut commenter un passage de texte et modifier ou supprimer des messages de commentaire, lire et envoyer des messages dans le chat du projet, déplacer et renommer des fichiers et dossiers, créer des dossiers et changer la langue du correcteur orthographique. Qui peut faire quoi suit votre rôle dans le projet, comme dans l'éditeur, car le client travaille avec votre jeton : voir [Qui peut faire quoi](#who-may-do-what).

Le serveur MCP a été introduit dans la v6.3.1. Les v6.3.1 et v6.3.2 ont les mêmes 17 outils ; la v6.3.3 en a 33.

| Outils | v6.3.1 et v6.3.2 | v6.3.3 |
| ----- | ----------------- | ------ |
| `get_clone_info`, `get_settings`, `list_files`, `delete_file`, `compile`, `get_compile_log`, `get_output_file_link`, `word_count`, `reply_to_comment`, `resolve_comment`, `reopen_comment` | Oui | Oui, inchangés |
| `read_file` | Le contenu le plus récent | Aussi un fichier tel qu'il était à une `version` |
| `edit_file`, `write_file` | Suivent le réglage de suivi des modifications du projet | Aussi `trackChanges`, pour faire de la modification une modification suivie |
| `update_settings` | Compilateur, image TeX Live et document principal | Aussi la langue du correcteur orthographique |
| `list_versions` | Version, commentaire et date | Aussi l'`id` attendu par `delete_version`, et qui l'a enregistrée |
| `list_comments` | Messages sans id | Aussi l'`id` de chaque message, attendu par `edit_comment_message` et `delete_comment_message` |
| `list_changes`, `diff`, `create_version`, `delete_version`, `restore_file`, `restore_project`, `list_tracked_changes`, `accept_tracked_changes`, `reject_tracked_changes`, `add_comment`, `edit_comment_message`, `delete_comment_message`, `list_chat_messages`, `send_chat_message`, `move_file`, `create_folder` | Non | Oui |

## Connecter un client {#connect-a-client}

<Steps>
<Step title="Ouvrir la boîte de dialogue">
Ouvrez le projet. Dans la barre de gauche, cliquez sur **Integrations**, puis sur **MCP server**.

<Frame caption="Le panneau Integrations">
  <img src="/images/on-premises/mcp-server-integrations.png" alt="Le panneau Integrations avec la carte MCP server" />
</Frame>

La boîte de dialogue affiche l'adresse du serveur de ce projet et un onglet pour chaque client : **Claude Code**, **Codex**, **Cursor**, **VS Code** et **Gemini CLI**.

<Frame caption="La boîte de dialogue MCP server">
  <img src="/images/on-premises/mcp-server-dialog.png" alt="La boîte de dialogue MCP server avec l'adresse, un onglet par client et la commande pour Claude Code" />
</Frame>
</Step>

<Step title="Créer un jeton">
Cliquez sur **Go to settings**. Les paramètres de votre compte s'ouvrent dans un nouvel onglet. Sous **Git integration**, cliquez sur **Generate token**, ou sur **Add another token** si vous en avez déjà un. Cliquez sur **Copy** et conservez le jeton en lieu sûr, car vous ne le voyez qu'une fois. Cliquez ensuite sur **Close**.

<Frame caption="Votre nouveau jeton">
  <img src="/images/on-premises/mcp-server-token.png" alt="La boîte de dialogue Git authentication token avec un bouton Copy" />
</Frame>

Un jeton que vous utilisez déjà pour l'[intégration Git](/fr/on-premises/user-guide/users/git-integration) fonctionne aussi, de même qu'un seul jeton pour tous vos projets.
</Step>

<Step title="Ajouter le serveur à votre client">
De retour dans la boîte de dialogue, cliquez sur l'onglet de votre client puis sur **Copy** à côté de la configuration.

| Onglet | Où la placer | Le jeton |
| --- | ------------- | --------- |
| **Claude Code** | Exécutez la commande dans un terminal | Remplacez `<token>` dans la commande |
| **Codex** | `~/.codex/config.toml` | Placez-le dans la variable d'environnement `OVERLEAF_TOKEN` |
| **Cursor** | `~/.cursor/mcp.json` | Placez-le dans la variable d'environnement `OVERLEAF_TOKEN` |
| **VS Code** | `.vscode/mcp.json` | Le fichier contient une invite de mot de passe appelée `overleaf-token` à la place du jeton |
| **Gemini CLI** | Exécutez la commande dans un terminal | Remplacez `<token>` dans la commande |

L'adresse appartient à un seul projet. Pour connecter un autre projet, ajoutez-le sous un autre nom, car `overleaf` est déjà pris. Pour Claude Code, par exemple, remplacez `overleaf` par `overleaf-lab` dans la commande.
</Step>
</Steps>

## Vérifier la connexion {#check-the-connection}

### Avec Claude Code {#with-claude-code}

```bash
claude mcp list
```

Le serveur est indiqué comme connecté :

```text
overleaf: https://<your-site>/project/<project-id>/mcp (HTTP) - ✔ Connected
```

### Avec curl {#with-curl}

Cela fonctionne quel que soit votre client. Remplacez l'adresse et le jeton, et envoyez la requête `initialize` du protocole MCP :

```bash
curl -X POST https://<your-site>/project/<project-id>/mcp \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -H "Accept: application/json, text/event-stream" \
  -d '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2025-06-18","capabilities":{},"clientInfo":{"name":"curl","version":"1.0"}}}'
```

La réponse nomme le serveur, suivi de ses instructions pour les clients :

```json
{"result":{"protocolVersion":"2025-06-18","capabilities":{"tools":{"listChanged":true}},"serverInfo":{"name":"overleaf","version":"1.0.0"},"instructions":"This server works on one Overleaf project. ..."},"jsonrpc":"2.0","id":1}
```

Pour voir les outils, envoyez `tools/list` avec la même commande. La réponse liste 33 outils, ou 31 si le chat de projet est désactivé sur votre site. Avant la v6.3.3, elle en liste 17.

```bash
  -d '{"jsonrpc":"2.0","id":2,"method":"tools/list","params":{}}'
```

Pour en appeler un, envoyez `tools/call` :

```bash
  -d '{"jsonrpc":"2.0","id":3,"method":"tools/call","params":{"name":"list_files","arguments":{}}}'
```

```json
{"result":{"content":[{"type":"text","text":"[\n  {\n    \"path\": \"main.tex\",\n    \"type\": \"doc\"\n  }\n]"}]},"jsonrpc":"2.0","id":3}
```

Sous **Git integration**, **Last used** affiche la date pour un jeton que le serveur a reçu.

### Si la connexion échoue {#if-it-does-not-connect}

| Ce que vous voyez | Ce que cela signifie |
| ------------ | ------------- |
| Statut `401`, ou dans Claude Code `✘ Failed to connect` avec `HTTP 401` | Le jeton est absent, erroné ou supprimé |
| Statut `404` | Aucun projet n'a cet ID |
| Statut `405` | La requête n'était pas un `POST` |
| Statut `406` avec `Not Acceptable` | L'en-tête `Accept` est absent : le client doit accepter à la fois `application/json` et `text/event-stream` |

## Ce que vous voyez quand un client travaille {#what-you-see-when-a-client-works}

Les modifications apparaissent dans un éditeur ouvert au fur et à mesure que le client les fait, comme celles d'un collaborateur, sans rechargement. Les nouveaux fichiers et dossiers, les déplacements et les renommages apparaissent dans l'arborescence des fichiers.

<Frame caption="Une ligne ajoutée par edit_file">
  <img src="/images/on-premises/mcp-server-live-edit.png" alt="L'éditeur montrant une ligne ajoutée par edit_file, sans boîte de dialogue ni rechargement" />
</Frame>

`edit_file` ne modifie que du texte qui apparaît exactement une fois. Sinon, le client reçoit une erreur, comme `oldString not found in main.tex, read_file again` ou `oldString appears 2 times in main.tex, add context`, et rien ne change.

À partir de la v6.3.3, `move_file` déplace ou renomme un fichier ou un dossier, en créant au besoin les dossiers du nouveau chemin, et `create_folder` crée un dossier. Si le fichier est introuvable ou si le nouveau chemin existe déjà, le client reçoit une erreur et rien ne change. `update_settings` peut aussi changer la langue du correcteur orthographique, par exemple en `de`, ou le désactiver.

Les réponses aux commentaires apparaissent dans le panneau de révision sous votre nom, car le jeton est le vôtre. Un commentaire résolu via le serveur quitte le panneau, et le rouvrir le fait revenir.

<Frame caption="Une réponse envoyée par reply_to_comment">
  <img src="/images/on-premises/mcp-server-comment.png" alt="Un commentaire dans le panneau de révision avec une réponse envoyée par reply_to_comment" />
</Frame>

À partir de la v6.3.3, `add_comment` commente un passage de texte. Le texte doit apparaître exactement une fois dans le fichier ; s'il apparaît plusieurs fois, le client fournit aussi un passage plus long qui l'entoure et n'apparaît qu'une fois, et seul le texte est commenté. Le commentaire apparaît dans le panneau de révision sous votre nom et reste attaché à son texte quand le fichier change. `edit_comment_message` modifie l'un de vos propres messages. `delete_comment_message` supprime un message, et supprimer le premier supprime tout le commentaire, comme dans le panneau de révision.

`compile` compile le projet et renvoie la liste des fichiers de sortie. `get_output_file_link` donne ensuite un lien pour télécharger le PDF ou un autre fichier de sortie. Le lien ne nécessite pas de jeton et cesse de fonctionner au bout de 5 minutes.

Pour la liste complète des outils, voir [Tools](/on-premises/configuration/overleaf-toolkit/integrations/mcp-server#tools).

## Modifications suivies {#tracked-changes}

À partir de la v6.3.3, vous pouvez demander au client de faire de ses modifications des modifications suivies, par exemple *Rewrite the abstract as a tracked change*. `edit_file` et `write_file` font alors de la modification d'un fichier existant une modification suivie à votre nom, même lorsque le suivi des modifications est désactivé dans le projet, et vous l'acceptez ou la rejetez dans le panneau de révision. Un nouveau fichier n'est jamais une modification suivie. Si vous ne le demandez pas, les modifications suivent le réglage de suivi des modifications du projet, comme les vôtres dans l'éditeur : elles sont suivies lorsque le suivi est activé pour vous ou pour tout le monde.

Si le compte du propriétaire du projet ne dispose pas du suivi des modifications, le client reçoit `Track changes is off for this project` et rien ne change.

Pour relire chaque modification du client, activez le suivi des modifications pour vous-même. Pour distinguer ses modifications des vôtres dans le panneau de révision, donnez au client le jeton d'un autre compte avec lequel vous partagez le projet.

`list_tracked_changes` liste les modifications suivies avec leur fichier, le texte inséré ou supprimé, l'auteur et l'heure. `accept_tracked_changes` et `reject_tracked_changes` prennent les id des modifications et fonctionnent comme le panneau de révision : une modification acceptée reste dans le texte, une insertion rejetée est retirée et une suppression rejetée revient. Un éditeur ouvert affiche le résultat sans rechargement. Les outils indiquent au client de n'accepter ou de ne rejeter que les modifications que vous demandez.

## Historique {#history}

À partir de la v6.3.3, le client voit l'historique du projet tel que le panneau d'historique l'affiche.

| Outil | Effet |
| ---- | ------------ |
| `list_changes` | Liste les modifications, les plus récentes en premier : qui a modifié quels fichiers et quand, avec les versions avant et après chaque modification. Les modifications plus anciennes arrivent par lots supplémentaires. |
| `diff` | Compare deux versions : un fichier sous forme de diff unifié, comme `git diff`, ou les fichiers ajoutés, supprimés, modifiés ou renommés |
| `read_file` avec `version` | Lit un fichier tel qu'il était à une version |
| `list_versions` | Liste les versions enregistrées, avec leur commentaire et qui les a enregistrées |
| `create_version` | Enregistre la version la plus récente, ou une version antérieure, avec un commentaire, comme **Label this version** |
| `delete_version` | Supprime une version enregistrée ; ses modifications restent |
| `restore_file` | Restaure un fichier tel qu'il était à une version, comme **Restore this version** |
| `restore_project` | Restaure le projet entier tel qu'il était à une version, comme **Restore project to this version** |

Une restauration est elle-même une nouvelle modification, vous pouvez donc l'annuler de la même façon. Les outils indiquent au client de ne restaurer que lorsque vous le demandez.

Si le propriétaire du projet ne dispose pas de l'historique complet du projet, le client ne voit que les modifications des dernières 24 heures, ou la plus récente si toutes sont plus anciennes, comme dans le panneau d'historique. Il ne peut pas comparer, lire ou restaurer de versions plus anciennes.

## Chat du projet {#project-chat}

À partir de la v6.3.3, `list_chat_messages` lit le chat du projet, les plus récents en premier, 50 messages à la fois. `send_chat_message` envoie un message à votre nom, et il apparaît aussitôt dans un chat ouvert. Si le chat de projet est désactivé sur votre site, le client n'a aucun de ces deux outils.

## Qui peut faire quoi {#who-may-do-what}

Le client peut faire ce que votre rôle dans le projet autorise.

| Ce que fait le client | Propriétaire | Éditeur | Relecteur | Lecteur (collaborateur nommé) | Lecteur (partage par lien) |
| -------------------- | ----: | -----: | -------: | --------------------------: | --------------------: |
| Lire les fichiers et les paramètres, compiler, lire le journal, télécharger le PDF | Oui | Oui | Oui | Oui | Oui |
| Écrire, modifier, déplacer et supprimer des fichiers, créer des dossiers, changer les paramètres | Oui | Oui | Non | Non | Non |
| Voir l'historique, les commentaires et les modifications suivies | Oui | Oui | Oui | Oui | Non |
| Lire et envoyer des messages de chat | Oui | Oui | Oui | Oui | Non |
| Ajouter des commentaires et y répondre | Oui | Oui | Oui | Non | Non |
| Résoudre, rouvrir ou supprimer un commentaire | Oui | Oui | Ceux qu'il a lancés | Non | Non |
| Modifier un message de commentaire | Les siens | Les siens | Les siens | Non | Non |
| Supprimer un message de commentaire | Oui | Oui | Les siens | Non | Non |
| Accepter ou rejeter des modifications suivies | Oui | Oui | Non | Non | Non |
| Enregistrer une version | Oui | Oui | Oui | Non | Non |
| Supprimer une version enregistrée | Oui | Celles qu'il a enregistrées | Celles qu'il a enregistrées | Non | Non |
| Restaurer un fichier ou le projet | Oui | Oui | Non | Non | Non |

Les éditeurs qui ont rejoint le projet par lien comptent comme éditeurs. Les relecteurs ne peuvent pas modifier de fichiers via MCP, pas même sous forme de modifications suivies.

## Déconnecter un client {#disconnect-a-client}

Supprimez le jeton : voir [Supprimer un jeton](/fr/on-premises/user-guide/users/git-integration#delete-a-token). Dès lors, le serveur répond `401` à ce jeton. Si vous l'utilisez aussi pour Git, Git cesse également de l'accepter.
