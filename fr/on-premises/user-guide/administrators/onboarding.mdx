---
title: Intégration
description: Créez le premier administrateur, vérifiez votre instance et ajoutez le premier utilisateur.
icon: user-plus
---

Faites-le une seule fois, juste après l'[installation](/fr/on-premises/installation/introduction). Cette page utilise la connexion par mot de passe par défaut.

<Steps>
<Step id="open-the-launchpad" title="Ouvrir le launchpad">
Ouvrez `/launchpad` sur votre instance, par exemple `http://localhost/launchpad`. Vous voyez **Create the first Admin account**.

Le formulaire n'existe que tant qu'aucun administrateur n'a été créé. Ensuite, les visiteurs non connectés sont redirigés vers la page de connexion.
</Step>

<Step id="create-the-administrator-account" title="Créer le compte administrateur">
Saisissez une adresse e-mail et un mot de passe, puis cliquez sur **Register**.

<Frame caption="Le premier compte administrateur">
  <img src="/images/on-premises/onboarding-launchpad-filled.png" alt="Le formulaire du launchpad rempli avec admin@example.com" />
</Frame>

Si le mot de passe est refusé, un message apparaît au-dessus du formulaire et aucun compte n'est créé.

<Frame caption="Un mot de passe refusé">
  <img src="/images/on-premises/onboarding-password-error.png" alt="Le message password is too short au-dessus du formulaire du launchpad" />
</Frame>

| Message                                    | Signification                                                                                                                                                                  |
| ------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `password is too short`                    | Moins de 8 caractères.                                                                                                                                                         |
| `password is too long`                     | Plus de 72 caractères.                                                                                                                                                         |
| `password contains an invalid character`   | Sont autorisés les lettres `a-z` et `A-Z`, les chiffres et `@#$%^&*()-_=+[]{};:<>/?!£€.,`. Les espaces et les lettres accentuées ou non latines ne le sont pas.                |
| `password contains part of email address`  | Il contient l'adresse e-mail ou la partie avant `@`, ou il fait partie de l'adresse e-mail. Pour `admin@example.com`, `admin-7Tq9-demo` et `example.com` sont tous deux refusés. |
| `password is too similar to email address` | Il est trop proche de l'adresse e-mail, par exemple `adm1n@example.c0m`.                                                                                                       |

Les majuscules, chiffres et symboles ne sont pas obligatoires par défaut. Pour modifier les limites de longueur, consultez [Restrictions de mot de passe](/fr/on-premises/configuration/overleaf-toolkit/authentication/password-restrictions).
</Step>

<Step id="log-in" title="Se connecter">
Après **Register**, vous êtes sur la page de connexion. Saisissez la même adresse e-mail et le même mot de passe, puis cliquez sur **Login**.

<Frame caption="Se connecter avec le nouveau compte">
  <img src="/images/on-premises/onboarding-login.png" alt="La page de connexion remplie avec admin@example.com" />
</Frame>

Vous revenez sur le launchpad, qui affiche désormais **Status Checks**.
</Step>

<Step id="check-the-instance" title="Vérifier l'instance">
`websockets` doit afficher **OK**.

Pour tester l'e-mail, saisissez votre adresse sous **Send a test email**, cliquez sur **Send**, puis vérifiez votre boîte de réception.

<Frame caption="Les vérifications d'état et l'e-mail de test">
  <img src="/images/on-premises/onboarding-launchpad-checks.png" alt="Le launchpad avec websockets OK, le formulaire d'e-mail de test affichant Email Sent et les deux boutons en bas" />
</Frame>

<Warning>

**Email Sent** ne prouve pas qu'un message a quitté le serveur. Sans [envoi d'e-mails](/fr/on-premises/configuration/overleaf-toolkit/email-delivery), la page affiche le même texte et rien n'arrive.

</Warning>

**Start Using** _le nom de votre site_ ouvre vos projets. **Go To Admin Panel** ouvre les outils du site, voir [Gestion de base](/on-premises/user-guide/administrators/basic-management).
</Step>

<Step id="create-the-first-user" title="Créer le premier utilisateur">
Dans le menu supérieur, cliquez sur **Admin**, puis sur **Manage Users**.

<Frame caption="Le menu Admin">
  <img src="/images/on-premises/onboarding-admin-menu.png" alt="Le menu Admin avec Manage Site, Manage Users et Project/Object Lookup" />
</Frame>

Cliquez sur **Create account**.

<Frame caption="La liste des utilisateurs">
  <img src="/images/on-premises/onboarding-user-list.png" alt="La liste des utilisateurs avec l'administrateur et le bouton Create account" />
</Frame>

Saisissez l'adresse e-mail de l'utilisateur. **First name** et **Last name** sont facultatifs. Ne cochez **Admin** que pour un autre administrateur. Cliquez sur **Create**.

<Frame caption="La boîte de dialogue Create account">
  <img src="/images/on-premises/onboarding-create-account.png" alt="La boîte de dialogue Create account remplie avec user@example.com" />
</Frame>

La boîte de dialogue affiche ensuite le nouveau compte et son lien d'activation, qui expire au bout de 7 jours :

* **Email Sent** signifie que l'e-mail d'activation est parti.
* <strong>No email was sent. Copy the link and pass it on.</strong> signifie que l'e-mail n'est pas parti, par exemple parce que l'[envoi d'e-mails](/fr/on-premises/configuration/overleaf-toolkit/email-delivery) n'est pas configuré.

<Frame caption="Le nouveau compte et son lien d'activation">
  <img src="/images/on-premises/onboarding-account-created.png" alt="La boîte de dialogue Create account pour Demo User avec l'avertissement qu'aucun e-mail n'a été envoyé, le lien, une icône de copie et Expires in 7 days" />
</Frame>

Cliquez sur **Close**. Le compte apparaît dans la liste avec le statut **Pending**.

<Frame caption="Un nouveau compte reste Pending jusqu'à sa première connexion">
  <img src="/images/on-premises/onboarding-user-pending.png" alt="La liste des utilisateurs avec Demo User au statut Pending" />
</Frame>
</Step>

<Step id="give-the-user-access" title="Donner l'accès à l'utilisateur">
**Avec l'envoi d'e-mails configuré**, l'utilisateur reçoit un e-mail d'activation contenant un lien **Set password**. Le lien ouvre cette page. L'utilisateur saisit un mot de passe, clique sur **Activate**, puis arrive sur la page des projets. Les règles de mot de passe ci-dessus s'appliquent.

<Frame caption="Ce que voit l'utilisateur après avoir ouvert le lien">
  <img src="/images/on-premises/onboarding-activate.png" alt="La page d'activation qui demande à l'utilisateur de définir un mot de passe" />
</Frame>

**Sans envoi d'e-mails**, transmettez le lien vous-même. Cliquez sur l'icône de copie dans la boîte de dialogue après **Create** et envoyez le lien à l'utilisateur, qui définit un mot de passe comme ci-dessus.

Si vous avez fermé la boîte de dialogue ou si le lien a expiré, cliquez sur l'icône d'enveloppe dans la ligne de l'utilisateur dans **Manage Users**, puis sur **Send activation email**. La boîte de dialogue affiche un nouveau lien, qui expire au bout de 7 jours.

<Frame caption="Un nouveau lien d'activation">
  <img src="/images/on-premises/onboarding-activation-link.png" alt="La boîte de dialogue Send activation email pour Demo User avec l'avertissement qu'aucun e-mail n'a été envoyé, le lien, une icône de copie et Expires in 7 days" />
</Frame>

Vous pouvez aussi définir un mot de passe vous-même. Dans **Manage Users**, cliquez sur le nom de l'utilisateur, puis sur l'icône de crayon. Saisissez **New password** et cliquez sur **Save**. Transmettez le mot de passe à l'utilisateur, qui se connecte sur `/login`.

<Frame caption="Définir un mot de passe dans l'onglet Account">
  <img src="/images/on-premises/onboarding-set-password.png" alt="L'onglet Account d'un utilisateur en mode édition avec le champ New password rempli" />
</Frame>
</Step>

<Step id="confirm-it-worked" title="Vérifier que tout a fonctionné">
Après la première connexion de l'utilisateur, le statut dans **Manage Users** passe à **Active**.

<Frame caption="L'utilisateur s'est connecté">
  <img src="/images/on-premises/onboarding-user-active.png" alt="La liste des utilisateurs avec Demo User au statut Active" />
</Frame>
</Step>
</Steps>

<Info>

Par défaut, **Sign up** ne crée pas de compte : la page invite les visiteurs à contacter l'adresse définie dans `OVERLEAF_ADMIN_EMAIL`. Pour permettre aux utilisateurs de s'inscrire eux-mêmes, consultez [Accès public](/fr/on-premises/configuration/overleaf-toolkit/authentication/public-access).

</Info>
