Cliquez sur **Admin**, puis sur **Manage Site**. L'**Admin Panel** comporte trois onglets : **System Messages**, **Open Sockets** et **Open/Close Editor**.

## Messages système {#system-messages}

Un message système est une bannière bleue en haut de la page **Projects** et de l'éditeur. Tous les utilisateurs la voient.

### Publier un message {#post-a-message}

Saisissez le texte sous **Message** et cliquez sur **Post Message**. L'onglet liste les messages actuellement affichés.

<Frame caption="Deux messages publiés">
  <img src="/images/on-premises/basic-management-posted.png" alt="L'onglet System Messages listant deux messages publiés au-dessus du champ Message, du bouton Post Message et du bouton Clear all messages" />
</Frame>

<Frame caption="Ce que voient les utilisateurs">
  <img src="/images/on-premises/basic-management-user-projects.png" alt="La page Projects d'un utilisateur avec les deux messages en bannières bleues en haut" />
</Frame>

* Un utilisateur peut fermer un message avec le <strong>×</strong>. Il reste fermé dans ce navigateur.
* Une page déjà ouverte vérifie les nouveaux messages toutes les 15 minutes. Recharger la page les affiche immédiatement.

### Supprimer des messages {#remove-messages}

**Clear all messages** supprime tous les messages d'un coup et ne demande pas de confirmation. Vous ne pouvez pas supprimer un seul message.

## Sockets ouverts {#open-sockets}

Une vue de diagnostic des connexions sortantes que le service web a ouvertes à cet instant. Elle n'indique pas qui est en ligne : la liste peut être vide alors que des utilisateurs sont dans l'éditeur.

## Fermer l'éditeur pour une maintenance {#close-the-editor-for-maintenance}

Utilisez l'onglet **Open/Close Editor**. Ses boutons agissent immédiatement sans demander de confirmation, et l'onglet n'indique pas si l'éditeur est fermé. Pour le vérifier, cliquez sur **Projects** : vous voyez la page **Maintenance** tant qu'il est fermé.

<Frame caption="L'onglet Open/Close Editor">
  <img src="/images/on-premises/basic-management-open-close.png" alt="L'onglet Open/Close Editor avec les boutons Close Editor, Disconnect all users et Reopen Editor" />
</Frame>

<Steps>
<Step id="tell-your-users" title="Prévenir vos utilisateurs">
[Publiez un message](/fr/on-premises/user-guide/administrators/basic-management#post-a-message) indiquant l'heure de la maintenance.
</Step>

<Step id="click-close-editor" title="Cliquer sur Close Editor">
Malgré son nom, cela ferme presque tout le site. Toutes les pages sauf le panneau d'administration affichent **Maintenance**, y compris **Projects**, **Account Settings**, **Templates** et la page de connexion. **Manage Users** et **Project/Object Lookup** continuent de fonctionner.

<Frame caption="Ce que voient les utilisateurs pendant que l'éditeur est fermé">
  <img src="/images/on-premises/basic-management-closed-page.png" alt="La page Maintenance indiquant que l'instance est actuellement en maintenance" />
</Frame>

Les utilisateurs qui ont déjà l'éditeur ouvert restent connectés. Ils peuvent continuer à taper et leurs modifications sont conservées, mais **Recompile** se termine par **Server Error**.

Pour modifier le texte de cette page, consultez [Page de maintenance](/fr/on-premises/configuration/overleaf-toolkit/branding#maintenance-page).
</Step>

<Step id="click-disconnect-all-users" title="Cliquer sur Disconnect all users">
Les utilisateurs dans l'éditeur voient la boîte de dialogue **Please wait**, qui décompte à partir de 10 secondes. Ensuite, leur page se rafraîchit et affiche **Maintenance**.

<Frame caption="Ce que voient les utilisateurs dans l'éditeur">
  <img src="/images/on-premises/basic-management-disconnect-dialog.png" alt="L'éditeur derrière la boîte de dialogue Please wait, qui indique que l'éditeur se rafraîchira automatiquement dans 8 secondes" />
</Frame>

Fermez d'abord l'éditeur : sinon, le rafraîchissement ramène les utilisateurs directement dans l'éditeur.
</Step>

<Step id="do-the-maintenance-then-click-reopen-editor" title="Effectuer la maintenance, puis cliquer sur Reopen Editor">
Toutes les pages fonctionnent à nouveau immédiatement. Les utilisateurs rechargent la page pour continuer.
</Step>
</Steps>

<Warning>

La page de connexion est fermée elle aussi : restez donc connecté jusqu'à ce que vous ayez rouvert l'éditeur. Si vous êtes bloqué, redémarrez l'instance : l'état fermé n'est conservé qu'en mémoire, donc un redémarrage rouvre l'éditeur.

</Warning>

<Info>

Sur Kubernetes avec plusieurs réplicas, **Close Editor** ne ferme que le réplica qui a traité votre requête. Utilisez plutôt le [mode maintenance](/fr/on-premises/configuration/kubernetes/branding#maintenance-mode).

</Info>
