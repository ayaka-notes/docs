Cliquez sur **Admin**, puis sur **Manage Users**. Pour ajouter un compte, consultez [Intégration](/fr/on-premises/user-guide/administrators/onboarding#create-the-first-user).

Votre propre compte est marqué **You** et ses actions sont grisées : vous ne pouvez pas vous désactiver ni vous supprimer.

## Trouver un utilisateur {#find-a-user}

Saisissez du texte dans **Search by name, email or ID**. Un nom complet fonctionne aussi, comme `Carol Novak`, et la recherche trouve également un utilisateur par n'importe laquelle de ses [adresses e-mail secondaires](/fr/on-premises/user-guide/users/multiple-emails). Pour affiner la liste, utilisez les filtres des colonnes **Login**, **Role** et **Status**. Cliquez sur **Name**, **Sign up** ou **Last logged in** pour trier.

<Frame caption="Rechercher un utilisateur">
  <img src="/images/on-premises/user-management-search.png" alt="La liste des utilisateurs filtrée par la recherche carol" />
</Frame>

Les comptes supprimés n'apparaissent pas dans les résultats. Si votre recherche correspond aussi à l'un d'eux, une ligne au-dessus du tableau l'indique, par exemple **Found 1 matching deleted users**. Cliquez sur **Display deleted users** pour les voir.

<Frame caption="Une recherche qui correspond à un compte supprimé">
  <img src="/images/on-premises/user-management-deleted-hint.png" alt="Une recherche sans résultat avec la ligne Found 1 matching deleted users, Display deleted users" />
</Frame>

## Statut des utilisateurs {#user-status}

Chaque compte a exactement un statut, et le filtre **Status** indique combien de comptes a chacun. Survolez un point d'interrogation pour lire sa définition.

<Frame caption="Le filtre Status">
  <img src="/images/on-premises/user-management-status-tooltip.png" alt="Le filtre Status avec l'info-bulle de Active" />
</Frame>

| Statut | Signification | Peut se connecter |
| --- | --- | --- |
| **All** | Tous les comptes qui ne sont pas supprimés. Les quatre statuts ci-dessous (Active + Pending + Inactive + Disabled) totalisent ce nombre. | |
| **Active** | S'est connecté ou a ouvert un projet au cours des 12 derniers mois. | Oui |
| **Pending** | Ne s'est jamais connecté : généralement un compte créé par un administrateur, ou inscrit avec un e-mail d'activation, que l'utilisateur n'a pas encore activé. Un compte inscrit avec un mot de passe n'a pas besoin d'activation et devient Active à sa première connexion. | Oui |
| **Inactive** | S'est connecté auparavant, mais aucune connexion ni ouverture de projet au cours des 12 derniers mois. | Oui |
| **Disabled** | Un administrateur a désactivé le compte. Une connexion mène à la page **Your account is suspended**. | Non |
| **Deleted user** | Le compte a été supprimé par un administrateur ou par l'utilisateur. Il n'est pas compté dans **All** et reste masqué tant que vous ne choisissez pas ce filtre. Une connexion indique que l'adresse e-mail ou le mot de passe est incorrect. | Non |

Les comptes passent d'un statut à l'autre ainsi :

* **Pending, Active et Inactive** suivent l'utilisation du compte, vous ne pouvez donc pas les définir. Un compte Inactive devient Active dès que l'utilisateur se connecte.
* **Enable** et **Restore** ne rétablissent pas un statut antérieur. Le statut vient de la dernière connexion : un compte qui ne s'est jamais connecté redevient Pending. Un compte désactivé reste **Disabled** après **Restore**.
* **Delete permanently** est irréversible. Sinon, les comptes supprimés restent jusqu'à ce que vous les retiriez, sauf si l'instance définit [`ENABLE_CRON_RESOURCE_DELETION`](/fr/on-premises/configuration/overleaf-toolkit/environment-variables), qui les retire après 90 jours.

### Utilisateurs actifs dans l'onglet License {#active-users-on-the-license-tab}

L'onglet **License** et le statut **Active** peuvent afficher des nombres différents, car ils ne comptent pas la même chose. L'onglet **License** compte les utilisateurs couverts par une licence Server Pro, tels qu'Overleaf les définit dans [Understanding license usage](https://docs.overleaf.com/on-premises/user-and-project-management/understanding-license-usage) : "any user who logs in and accesses a project is considered an active user by the system" et "An active user is defined as someone who has opened a project on your Server Pro instance in the last 12 months." Un utilisateur qui s'est connecté sans ouvrir de projet est **Active** dans la liste, mais ne compte pas pour la licence. Un utilisateur qui a ouvert un projet puis a été désactivé compte pour la licence, mais est **Disabled** dans la liste.

## Actions sur un utilisateur {#actions-on-a-user}

Les icônes de la colonne **Actions** sont les mêmes qu'en haut de la page d'un utilisateur.

| Icône | Action | Effet |
| --- | --- | --- |
| Enveloppe | **Send activation email** | Pour un compte qui ne s'est jamais connecté : un nouveau lien d'activation. |
| Cadenas avec une flèche | **Send reset link** | Pour un compte qui s'est déjà connecté : un nouveau lien de réinitialisation du mot de passe. |
| Dossier | **Transfer this user's projects** | Donne tous les projets de l'utilisateur à un autre utilisateur. |
| Cercle | **Disable** | Empêche l'utilisateur de se connecter. |
| Lecture | **Enable** | Permet à nouveau à un utilisateur désactivé de se connecter. |
| Corbeille | **Delete account** | Place le compte dans **Deleted user**. |
| Flèche | **Restore** | Rétablit un compte supprimé. Uniquement pour les comptes supprimés. |
| Corbeille barrée | **Delete permanently** | Retire définitivement un compte supprimé. Uniquement pour les comptes supprimés. |

Chaque action demande une confirmation dans une boîte de dialogue qui nomme le compte.

### Envoyer un lien d'activation ou de réinitialisation {#send-an-activation-or-reset-link}

Un compte affiche l'une de ces deux icônes, selon qu'il s'est déjà connecté ou non. L'icône est grisée pour un compte désactivé, pour un compte sans mot de passe local, comme un compte SSO, et pour votre propre compte.

Cliquez sur l'icône, puis sur le bouton du même nom. La boîte de dialogue reste ouverte et affiche le lien :

* **Email Sent** signifie que l'e-mail est parti.
* <strong>No email was sent. Copy the link and pass it on.</strong> signifie que l'[envoi d'e-mails](/fr/on-premises/configuration/overleaf-toolkit/email-delivery) n'est pas configuré ou que l'e-mail a échoué. Cliquez sur l'icône de copie et envoyez vous-même le lien à l'utilisateur.

Un lien d'activation expire au bout de 7 jours, un lien de réinitialisation au bout d'une heure. L'utilisateur ouvre le lien et définit un mot de passe. Après un lien d'activation, il arrive sur ses projets ; après un lien de réinitialisation, il se connecte.

<Frame caption="Un lien de réinitialisation sur une instance sans envoi d'e-mails">
  <img src="/images/on-premises/user-management-reset-link.png" alt="La boîte de dialogue Send reset link pour Carol Novak avec l'avertissement qu'aucun e-mail n'a été envoyé, le lien, une icône de copie et Expires in 1 hour" />
</Frame>

### Désactiver ou activer un compte {#disable-or-enable-an-account}

Cliquez sur l'icône en forme de cercle, puis sur **Disable**. Le statut passe à **Disabled** et l'utilisateur ne peut plus se connecter. Pour annuler, cliquez sur l'icône de lecture, puis sur **Enable**.

<Frame caption="Désactiver un compte">
  <img src="/images/on-premises/user-management-disable.png" alt="La boîte de dialogue Disable nommant Dave Okafor" />
</Frame>

### Transférer les projets d'un utilisateur {#transfer-a-user’s-projects}

Cliquez sur l'icône de dossier. Saisissez un nom ou une adresse e-mail sous **Select a new owner for this user's projects**, choisissez l'utilisateur, puis cliquez sur **Transfer this user's projects**. Le **Owner** de ces projets change dans la [gestion des projets](/fr/on-premises/user-guide/administrators/project-management).

Les comptes désactivés ne sont pas proposés comme nouveau propriétaire. Si vous modifiez le texte après avoir choisi, le choix est annulé : choisissez de nouveau l'utilisateur.

<Frame caption="Transférer tous les projets d'un utilisateur">
  <img src="/images/on-premises/user-management-transfer.png" alt="La boîte de dialogue de transfert avec Carol Novak choisie comme nouvelle propriétaire" />
</Frame>

### Supprimer un compte {#delete-an-account}

Cliquez sur l'icône de corbeille. Deux options sont disponibles, et aucune n'est cochée par défaut :

* **Notify the user about the account deletion** envoie un e-mail à l'utilisateur.
* **Transfer this user's projects** vous permet de choisir d'abord un nouveau propriétaire pour les projets. Ils restent actifs sous le nouveau propriétaire.

Cliquez sur **Delete account**. Si vous ne transférez pas les projets, ils sont supprimés avec le compte et passent au statut **Deleted** de la [gestion des projets](/fr/on-premises/user-guide/administrators/project-management#project-status).

<Frame caption="Supprimer un compte et transférer ses projets">
  <img src="/images/on-premises/user-management-delete.png" alt="La boîte de dialogue Delete account avec les deux options cochées et un nouveau propriétaire choisi" />
</Frame>

### Restaurer ou supprimer définitivement un compte {#restore-or-permanently-delete-an-account}

Choisissez **Deleted user** dans le filtre **Status**, ou cliquez sur **Display deleted users** après une recherche.

<Frame caption="Un compte supprimé">
  <img src="/images/on-premises/user-management-deleted-list.png" alt="La liste des utilisateurs supprimés avec les icônes Restore et Delete permanently" />
</Frame>

* **Restore** rétablit le compte. Un compte désactivé reste désactivé. Les projets supprimés avec le compte reviennent aussi, et le nom de chacun se termine par `(Restored)`. Les projets que l'utilisateur avait lui-même supprimés restent supprimés.
* **Delete permanently** retire le compte. La boîte de dialogue avertit que cette action est irréversible.

<Frame caption="Supprimer définitivement un compte">
  <img src="/images/on-premises/user-management-purge.png" alt="La boîte de dialogue Delete permanently avertissant que l'action est irréversible" />
</Frame>

### Modifier plusieurs comptes à la fois {#change-several-accounts-at-once}

Cochez les comptes dans la liste. Des boutons apparaissent à côté de **Create account** : **Send activation email**, **Transfer this user's projects**, **Disable**, **Enable**, **Make admin**, **Remove admin** et **Delete account**. Le bas de la liste indique combien de comptes sont sélectionnés. La boîte de dialogue les liste avant votre confirmation.

<Frame caption="Actions groupées">
  <img src="/images/on-premises/user-management-bulk.png" alt="Deux comptes cochés et les boutons d'actions groupées au-dessus de la liste, avec l'enveloppe grisée" />
</Frame>

**Send activation email** est grisé tant que tous les comptes cochés ne sont pas **Pending**. La boîte de dialogue affiche alors un lien par compte. Il n'y a pas de lien de réinitialisation groupé.

<Frame caption="Un lien d'activation par compte">
  <img src="/images/on-premises/user-management-bulk-links.png" alt="La boîte de dialogue Send activation email avec un lien pour Hana Ito, un lien pour Erin Silva et Expires in 7 days" />
</Frame>

## La page d'un utilisateur {#the-user-page}

Cliquez sur le nom d'un utilisateur pour ouvrir sa page. Elle comporte six onglets.

### Account {#account}

Les détails du compte. Pour les modifier, cliquez sur l'icône en forme de crayon, modifiez les champs, puis cliquez sur **Save**. Vous pouvez modifier l'adresse e-mail, les noms et le mot de passe, et activer ou désactiver **Admin**.

Si l'utilisateur a ajouté [d'autres adresses e-mail](/fr/on-premises/user-guide/users/multiple-emails), elles sont listées sous **Emails**. Pendant la modification, **Remove** retire une adresse secondaire du compte, et un autre compte peut alors utiliser cette adresse.

<Frame caption="Un compte avec deux adresses e-mail">
  <img src="/images/on-premises/user-management-secondary-email.png" alt="L'onglet Account en cours de modification, avec une adresse principale et une adresse secondaire avec un bouton Remove" />
</Frame>

Les [règles de mot de passe](/fr/on-premises/user-guide/administrators/onboarding#create-the-administrator-account) de l'intégration s'appliquent. Transmettre le mot de passe à l'utilisateur vous revient. Pour que l'utilisateur le choisisse, [envoyez plutôt un lien de réinitialisation](/fr/on-premises/user-guide/administrators/user-management#send-an-activation-or-reset-link).

<Frame caption="Modifier un compte">
  <img src="/images/on-premises/user-management-edit.png" alt="L'onglet Account en mode modification" />
</Frame>

### Projects {#projects}

Les projets dont cet utilisateur est propriétaire, avec la même recherche, le même filtre **Status** et les mêmes actions que dans la [gestion des projets](/fr/on-premises/user-guide/administrators/project-management).

<Frame caption="Les projets d'un utilisateur">
  <img src="/images/on-premises/user-management-projects.png" alt="L'onglet Projects d'un utilisateur" />
</Frame>

### Features {#features}

Ce qui est activé pour ce compte : collaboration, délai de compilation, intégrations et IA. Pour les modifier, cliquez sur l'icône en forme de crayon, modifiez les valeurs, puis cliquez sur **Save**. Pour **Collaborators per project**, `-1` signifie illimité. **Compile timeout** est en secondes, de 1 à 600.

Sur votre propre compte, le crayon et le **Reset** de **AI usage** sont grisés. Dans l'onglet **Account**, vous pouvez tout de même modifier votre adresse e-mail, vos noms et votre mot de passe.

<Frame caption="Les fonctionnalités d'un utilisateur">
  <img src="/images/on-premises/user-management-features.png" alt="L'onglet Features en mode modification" />
</Frame>

### Integrations {#integrations}

Les jetons d'accès Git de l'utilisateur et les comptes qu'il a associés. Cet onglet est en lecture seule.

<Frame caption="Les intégrations d'un utilisateur">
  <img src="/images/on-premises/user-management-integrations.png" alt="L'onglet Integrations avec GitHub, GitLab et Gitea cochés comme associés" />
</Frame>

### Audit logs {#audit-logs}

Ce qui est arrivé à ce compte : la date, l'opération, qui l'a effectuée, l'adresse IP et les détails. Effectuez une recherche ou filtrez par **Operation**. Les actions que vous effectuez sur un compte y apparaissent avec vous comme initiateur.

<Frame caption="Les journaux d'audit d'un utilisateur">
  <img src="/images/on-premises/user-management-audit.png" alt="L'onglet Audit logs listant les connexions de l'utilisateur et les modifications de fonctionnalités par un administrateur" />
</Frame>

### Sessions {#sessions}

Les endroits où l'utilisateur est connecté. Cliquez sur **Clear sessions** et confirmez pour le déconnecter partout. L'onglet affiche alors **Sessions cleared**.

<Frame caption="Les sessions d'un utilisateur">
  <img src="/images/on-premises/user-management-sessions.png" alt="L'onglet Sessions avec une session et le bouton Clear sessions" />
</Frame>
