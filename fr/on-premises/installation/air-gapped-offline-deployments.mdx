---
title: Déploiements isolés/hors ligne
description: Déployez Ayakaleaf Pro hors ligne en exportant, transférant et chargeant des images Docker.
icon: block-brick
---

En règle générale, nous ne recommandons pas de déployer Ayakaleaf Pro dans un environnement hors ligne, car nombre de ses fonctionnalités, comme GitHub Sync et l'intégration Zotero, nécessitent une connexion Internet.

Si vous souhaitez travailler hors ligne, il ne sera pas toujours possible d'accéder au registre `ghcr.io` pour télécharger les images `ayakaleaf-pro` et TeX Live requises. Ce n'est pas un problème, car Docker fournit des outils d'export et d'import d'images qui vous aideront pour un déploiement hors ligne ou isolé (air-gapped).

Dans les grandes lignes, vous téléchargerez les images requises sur une machine connectée à Internet, les exporterez sur un support amovible (ou les transférerez via SCP/Rsync), puis les importerez sur le serveur isolé.

Pour cela, vous devrez effectuer les étapes suivantes :

* Téléchargez toutes les images requises (`overleaf-pro`, `git-bridge`, `mongo`, `redis` + toutes les [images TeX Live](https://docs.overleaf.com/on-premises/configuration/overleaf-toolkit/server-pro-only-configuration/sandboxed-compiles#available-tex-live-images) nécessaires à l'utilisation des [Sandboxed Compiles](https://docs.overleaf.com/on-premises/configuration/overleaf-toolkit/server-pro-only-configuration/sandboxed-compiles)) sur une machine connectée à Internet
  * `docker pull ghcr.io/ayaka-notes/overleaf-pro:6.1.2`
  * `docker pull quay.io/sharelatex/git-bridge:6.1.2` (le tag doit être identique à celui d'`overleaf-pro`)
  * `docker pull mongo:6` (remplacez par la version réelle)
  * `docker pull redis:6.2` (remplacez par la version réelle)
  * `docker pull ghcr.io/ayaka-notes/texlive-full:2024.1` (remplacez par la version réelle)
* Exportez ensuite **chacune** des images téléchargées dans un fichier .tar. Par exemple : `docker save ghcr.io/ayaka-notes/overleaf-pro:6.1.2 > overleaf-pro:6.1.2.tar`
* Par la méthode de votre choix, transférez les fichiers `.tar` de la machine connectée à Internet vers le serveur hors ligne/isolé
* Pour chaque fichier .tar, utilisez la commande `docker load` pour charger l'image depuis le fichier .tar. Par exemple : `docker load < overleaf-pro:6.1.2.tar`
* Enfin, exécutez la commande `docker images` pour vérifier que le chargement des images a réussi et qu'elles sont disponibles

<Danger>

Par défaut, lorsque vous exécutez la commande `bin/up`, le Toolkit tente de télécharger automatiquement chacune des images TeX Live définies via `ALL_TEX_LIVE_DOCKER_IMAGES` dans `config/variables.env`. Votre déploiement étant isolé, cela échouera ; vous pouvez l'empêcher en définissant `SIBLING_CONTAINERS_PULL=false` dans `config/overleaf.rc`.

</Danger>
