### Créer l'administrateur et un premier projet {#create-the-administrator-and-a-first-project}

Ouvrez [http://localhost:8080/launchpad](http://localhost:8080/launchpad), créez le premier compte administrateur et connectez-vous. Suivez ensuite [6. Tâches post-installation](/fr/on-premises/installation/using-docker-compose/linux/6.-post-installation-tasks) du guide Linux, en utilisant le port `8080` dans ses URL d'exemple.

### Vérifier la compilation {#verify-compilation}

Une page de connexion qui s'ouvre ne prouve pas que les conteneurs de compilation distincts et leurs montages de données fonctionnent. Créez un projet vide et compilez ce `main.tex` :

```latex
\documentclass{article}
\begin{document}
Ayakaleaf Pro on macOS.
\end{document}
```

L'aperçu PDF doit afficher le texte. Si nécessaire, sélectionnez TeX Live 2026 dans les paramètres du projet.

Pour un projet contenant du texte chinois, sélectionnez **XeLaTeX** comme compilateur et testez :

```latex
\documentclass{ctexart}
\begin{document}
你好，Ayakaleaf Pro。
\end{document}
```

### Vérifier la persistance {#verify-persistence}

```bash
bin/stop
bin/start
```

Rouvrez le projet et compilez-le à nouveau. Votre compte, la source et les fichiers du projet doivent toujours être présents. Avec les chemins par défaut, les données actives se trouvent dans le répertoire `data/` du Toolkit sur votre Mac.

### Garder l'instance disponible {#keep-the-instance-available}

Lorsque le Mac est en veille, macOS suspend la machine virtuelle de Docker Desktop avec tous les conteneurs qu'elle contient : personne ne peut ouvrir l'instance, et une compilation en cours s'arrête jusqu'au réveil du Mac. Seule la mise en veille du système compte. L'écran peut s'éteindre.

Si d'autres personnes utilisent l'instance, ou si vous laissez tourner des tâches longues, laissez le Mac branché sur secteur et empêchez la mise en veille automatique, voir [Régler les paramètres de suspension d'activité et de réactivation de votre Mac](https://support.apple.com/guide/mac-help/set-sleep-and-wake-settings-mchle41a6ccd/mac) :

| Mac | Paramètre |
| --- | --- |
| Mac de bureau (Mac mini, iMac, Mac Studio, Mac Pro) | **Réglages Système → Énergie** : activez **Empêcher la suspension d'activité automatique lorsque l'écran est éteint** |
| MacBook | **Réglages Système → Batterie → Options** : activez **Empêcher la suspension d'activité automatique sur l'adaptateur secteur lorsque l'écran est éteint**. Cela ne s'applique que lorsque l'adaptateur secteur est branché, et fermer l'écran met toujours le MacBook en veille |

Pour ne garder le Mac éveillé que pendant un certain temps, exécutez plutôt `caffeinate -i` dans une fenêtre du Terminal. Cela empêche la mise en veille pour inactivité jusqu'à ce que vous appuyiez sur `Ctrl+C` ou fermiez la fenêtre.

Docker Desktop est une application de votre session utilisateur. Pour que l'instance soit de nouveau disponible après un redémarrage, activez **Start Docker Desktop when you sign in to your computer** dans **Settings → General** de Docker Desktop. Les conteneurs du Toolkit utilisent `restart: always` ; Docker les redémarre donc dès que Docker Desktop fonctionne, sans `bin/up`. Tant que personne n'ouvre de session sur le Mac après un redémarrage, l'instance reste arrêtée.

<Info>

Un Mac qui reste éveillé consomme davantage d'énergie. Pour un service qui doit toujours être accessible, nous recommandons un serveur Linux, voir [Linux](/fr/on-premises/installation/using-docker-compose/linux).

</Info>

### Utilisation quotidienne {#daily-use}

Ouvrez Docker Desktop avant de gérer l'instance. Dans un nouveau terminal :

```bash
export PATH="$(brew --prefix gnu-sed)/libexec/gnubin:$PATH"
cd "$HOME/ayakaleaf-toolkit"
```

| Tâche | Commande |
| --- | --- |
| Démarrer les conteneurs existants | `bin/start` |
| Arrêter les conteneurs en conservant les données | `bin/stop` |
| Appliquer les modifications de configuration | `bin/up -d` |
| Vérifier l'état | `bin/docker-compose ps` |
| Lire les journaux de démarrage | `bin/docker-compose logs --tail=100 sharelatex` |
| Lire les journaux du compilateur | `bin/logs -f clsi` |

`bin/start` n'applique pas les modifications de `config/` : exécutez `bin/up -d` après avoir modifié la configuration. Conservez `config/` et `data/`, et suivez [Données et sauvegardes](/fr/on-premises/maintenance/data-and-backups) avant une mise à niveau ou avant de déplacer l'installation. Copier les fichiers de la base de données pendant que MongoDB y écrit ne constitue pas une sauvegarde cohérente.

Conservez l'instance sur `127.0.0.1` pour un usage local. Pour servir d'autres ordinateurs, définissez délibérément l'adresse d'écoute, l'URL du site et HTTPS, voir [5. Personnaliser votre instance](/fr/on-premises/installation/using-docker-compose/linux/5.-personalizing-your-instance) du guide Linux.

Si quelque chose ne fonctionne pas, consultez [Dépannage](/fr/on-premises/installation/using-docker-compose/macos/troubleshooting).
