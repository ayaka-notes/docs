---
title: 5. Personnaliser votre instance
description: Définissez le port, l'URL du site et l'image TeX Live d'une instance locale sur votre Mac, vérifiez le noyau de la VM Docker et démarrez Ayakaleaf Pro.
icon: square-sliders
---

<Steps>
<Step title="Paramètres des conteneurs">
Modifiez ces entrées existantes dans `config/overleaf.rc` :

```bash title="config/overleaf.rc"
PROJECT_NAME=ayakaleaf-macos
SERVER_PRO=true
OVERLEAF_LISTEN_IP=127.0.0.1
OVERLEAF_PORT=8080
SIBLING_CONTAINERS_ENABLED=true
DOCKER_SOCKET_PATH=/var/run/docker.sock
```

Conservez les chemins de données par défaut ainsi que les services MongoDB et Redis fournis. Avec `OVERLEAF_LISTEN_IP=127.0.0.1`, seuls les navigateurs de ce Mac peuvent ouvrir l'instance.
</Step>

<Step title="Paramètres de l'application">
Dans `config/variables.env`, définissez ces valeurs, en remplaçant toute entrée active portant le même nom :

```dotenv title="config/variables.env"
OVERLEAF_SITE_URL=http://localhost:8080
TEX_LIVE_DOCKER_IMAGE=ghcr.io/ayaka-notes/texlive-full:2026.1
ALL_TEX_LIVE_DOCKER_IMAGES=ghcr.io/ayaka-notes/texlive-full:2026.1
ALL_TEX_LIVE_DOCKER_IMAGE_NAMES="TeX Live 2026"
```

Générez un secret de session :

```bash
openssl rand -hex 32
```

Ajoutez le résultat en tant que `OVERLEAF_SESSION_SECRET` dans `config/variables.env`. Sans lui, chaque `bin/up` qui recrée le conteneur déconnecte tous les utilisateurs, voir [Variables d'environnement](/fr/on-premises/configuration/overleaf-toolkit/environment-variables).

Pour une instance locale sans e-mail, laissez les paramètres SMTP et `OVERLEAF_EMAIL_FROM_ADDRESS` non définis. Git Bridge, l'authentification externe et les autres intégrations peuvent être ajoutés plus tard grâce à leurs propres [pages de configuration](/fr/on-premises/configuration/overleaf-toolkit).
</Step>

<Step title="Vérifier le noyau Linux de la VM Docker" id="check-the-docker-vms-linux-kernel">
MongoDB s'exécute sur le noyau Linux de la machine virtuelle de Docker Desktop, et non sur macOS. Vérifiez sa version avant le premier démarrage :

```bash
docker info --format '{{.KernelVersion}}'
```

MongoDB documente une incompatibilité avec les noyaux Linux **6.19 à 7.0.13**, qui affecte également MongoDB dans Docker. La correction est un noyau **7.0.14 ou ultérieur**, fourni avec une mise à jour de Docker Desktop, voir les [notes de production de MongoDB](https://www.mongodb.com/docs/manual/administration/production-notes/).

Si votre VM Docker utilise un noyau concerné, ajoutez ce qui suit à `config/docker-compose.override.yml`, en le fusionnant avec les éventuels `services` déjà présents :

```yaml title="config/docker-compose.override.yml"
services:
  mongo:
    environment:
      GLIBC_TUNABLES: glibc.pthread.rseq=1
```

<Warning>

Passez à un noyau corrigé dès qu'il est disponible. Si votre noyau se situe en dehors de la plage concernée, ce contournement est inutile.

</Warning>
</Step>

<Step title="Démarrer votre instance">
Depuis le répertoire du Toolkit, exécutez :

```bash
bin/up -d
```

Le Toolkit initialise le replica set de MongoDB, récupère l'image TeX Live et démarre l'application. Le premier téléchargement prend un certain temps. Pour suivre la progression :

```bash
bin/docker-compose ps
bin/docker-compose logs --tail=100 -f sharelatex
```

Appuyez sur `Ctrl+C` pour arrêter de suivre les journaux. Les conteneurs continuent de fonctionner.

Vérifiez le port publié et la page de premier lancement :

```bash
bin/docker-compose port sharelatex 80
curl -I http://localhost:8080/launchpad
```

Le port doit être `127.0.0.1:8080`.
</Step>
</Steps>

<Info>

Pour ouvrir ultérieurement l'instance depuis d'autres ordinateurs, modifiez l'adresse d'écoute et l'URL du site, et configurez HTTPS, comme décrit dans [5. Personnaliser votre instance](/fr/on-premises/installation/using-docker-compose/linux/5.-personalizing-your-instance) du guide Linux. Le Mac doit alors rester éveillé, voir [Garder l'instance disponible](/fr/on-premises/installation/using-docker-compose/macos/6.-post-installation-tasks#keep-the-instance-available).

</Info>
