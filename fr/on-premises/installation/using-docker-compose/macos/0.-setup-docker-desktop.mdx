Ayakaleaf Pro fonctionne sur Docker. Sur un Mac, vous utilisez Docker Desktop, qui exécute le moteur Docker dans une machine virtuelle Linux.

<Steps>
<Step title="Installer et démarrer Docker Desktop">
Installez la version de [Docker Desktop](https://docs.docker.com/desktop/setup/install/mac-install/) adaptée à votre Mac (Apple silicon ou Intel), ouvrez-la et attendez que le moteur ait démarré. Vous pouvez aussi le démarrer depuis le Terminal :

```bash
open -a Docker
```
</Step>

<Step title="Vérifier le moteur Docker">
Exécutez ces commandes dans le Terminal :

```bash
docker context show
docker info
docker compose version
```

Le contexte doit pointer vers votre moteur Docker Desktop local, normalement `desktop-linux`. Si un autre contexte est sélectionné, basculez vers Docker Desktop avant de continuer :

```bash
docker context use desktop-linux
```

`docker info` doit afficher une section **Server**. `docker --version` seul indique uniquement que le client est installé.
</Step>

<Step title="Vérifier les ressources et le partage de fichiers">
Dans les **Settings** de Docker Desktop, comparez les limites de processeur, de mémoire et de disque avec [Avant de commencer](/fr/on-premises/installation/using-docker-compose/macos#before-you-start), et vérifiez les paramètres de partage de fichiers, voir [Paramètres de Docker Desktop](https://docs.docker.com/desktop/settings-and-maintenance/settings/).

Ce guide place le Toolkit sous `/Users`, que Docker Desktop partage par défaut. Si vous utilisez un autre emplacement et que `bin/up` échoue avec `Mounts denied`, ajoutez ce répertoire au partage de fichiers.
</Step>

<Step title="Vérifier le socket Docker pour les compilations en sandbox">
Le Toolkit monte `/var/run/docker.sock` dans l'application, afin qu'elle puisse démarrer un conteneur TeX Live distinct pour chaque compilation. Conservez `DOCKER_SOCKET_PATH=/var/run/docker.sock` dans `config/overleaf.rc`.

Sous macOS, la CLI Docker peut se connecter via `~/.docker/run/docker.sock`. Il s'agit du point d'accès client sur le Mac, et non d'une raison de modifier la source du montage du Toolkit : le compilateur a besoin du socket du moteur tel que le voient les conteneurs Linux.

Si `/var/run/docker.sock` est absent du Mac, activez **Allow the default Docker socket to be used** sous **Settings → Advanced**, voir les [exigences d'autorisation de Docker](https://docs.docker.com/desktop/setup/install/mac-permission-requirements/).

<Danger>

N'exécutez pas `chmod 777` sur le socket pour contourner des erreurs. L'accès au socket Docker équivaut à un accès root à la VM Docker.

</Danger>
</Step>
</Steps>
