Dans cette section, nous exécutons Ayakaleaf Pro en local sur votre Mac avec Docker Desktop et l'[Ayakaleaf Toolkit](https://github.com/ayaka-notes/toolkit). Le guide utilise `http://localhost:8080`, conserve les données dans votre répertoire personnel et compile avec TeX Live 2026 dans des conteneurs en sandbox.

Docker Desktop exécute l'application, MongoDB, Redis et le compilateur TeX Live dans une machine virtuelle Linux. Vous n'installez ni MongoDB, ni Redis, ni MacTeX sur macOS lui-même.

Utilisez cette configuration pour un usage personnel et des tests en local. Pour un service partagé disponible en permanence, nous recommandons le [guide Linux](/fr/on-premises/installation/using-docker-compose/linux), avec HTTPS, des sauvegardes et un contrôle d'accès. L'instance est indisponible lorsque le Mac est en veille ou que Docker Desktop est arrêté, voir [Garder l'instance disponible](/fr/on-premises/installation/using-docker-compose/macos/6.-post-installation-tasks#keep-the-instance-available).

## Avant de commencer {#before-you-start}

Vous avez besoin de :

* Une version de macOS prise en charge par [Docker Desktop pour Mac](https://docs.docker.com/desktop/setup/install/mac-install/).
* Git, [Homebrew](https://brew.sh/) et GNU sed. Le Toolkit utilise des options de GNU sed que le sed BSD intégré à macOS n'accepte pas.
* Des ressources suffisantes pour macOS et pour Docker. Pour une petite instance locale, commencez avec 4 processeurs et 8 Go de mémoire alloués à Docker Desktop. Il s'agit d'un point de départ suggéré, et non d'un minimum mesuré.
* Au moins 40 Go d'espace de stockage libre pour une image TeX Live complète, plus l'espace nécessaire à vos projets. Vérifiez à la fois l'espace libre sur le Mac et la limite d'utilisation du disque de Docker Desktop. Commencez avec une seule version de TeX Live : chaque version supplémentaire nécessite à peu près autant d'espace.

Les images de l'application et de TeX Live sont publiées pour `arm64` et `amd64`. Sur Apple silicon, laissez Docker choisir l'image ARM native et ne forcez pas `platform: linux/amd64`.
