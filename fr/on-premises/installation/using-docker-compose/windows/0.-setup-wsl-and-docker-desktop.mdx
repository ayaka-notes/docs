Ayakaleaf Pro utilise des conteneurs Linux. Sous Windows, installez Docker Desktop avec son backend WSL 2 et exécutez les scripts du Toolkit dans Ubuntu.

WSL 2 fournit le noyau Linux. Docker Desktop gère le moteur Docker dans son propre environnement `docker-desktop` ; l'activation de **WSL Integration** permet à la CLI Docker d'Ubuntu de communiquer avec ce moteur. Le Toolkit démarre ensuite l'application, MongoDB et Redis sous forme de conteneurs. Lorsque les compilations en sandbox sont activées, l'application utilise le socket Docker du moteur pour démarrer un conteneur TeX Live distinct pour chaque compilation. Vous n'avez pas besoin d'installations Windows de MongoDB, de Redis ou de TeX Live.

<Steps>
<Step title="Installer WSL 2 et Ubuntu">
Ouvrez **PowerShell en tant qu'administrateur** dans Windows et exécutez :

```powershell
wsl --install -d Ubuntu
```

Redémarrez Windows si vous y êtes invité. Ouvrez **Ubuntu** depuis le menu Démarrer et créez un nom d'utilisateur et un mot de passe Linux. Il s'agit du compte utilisé pour `sudo` dans Ubuntu ; il est distinct de votre session Windows.

De retour dans **PowerShell**, mettez à jour WSL et vérifiez la distribution :

```powershell
wsl --update
wsl --version
wsl --list --verbose
```

La ligne Ubuntu doit afficher **VERSION 2**. Si elle affiche 1, utilisez le nom exact de la distribution indiqué dans la liste :

```powershell
wsl --set-version Ubuntu 2
```

Docker nécessite WSL **2.1.5 ou ultérieur** ; la version du logiciel WSL indiquée par `wsl --version` et la colonne **VERSION 2** de la distribution sont deux vérifications différentes. Consultez le [dépannage de l'installation](/fr/on-premises/installation/using-docker-compose/windows/troubleshooting#wsl-or-docker-reports-that-virtualization-is-unavailable) et les [instructions d'installation de Microsoft](https://learn.microsoft.com/en-us/windows/wsl/install) si l'installation échoue, et activez la virtualisation matérielle dans le BIOS/UEFI si WSL indique qu'elle n'est pas disponible.
</Step>

<Step title="Installer et démarrer Docker Desktop">
Téléchargez [Docker Desktop pour Windows](https://docs.docker.com/desktop/setup/install/windows-install/) pour votre processeur et lancez le programme d'installation. Utilisez le backend **WSL 2** s'il est proposé. Ouvrez **Docker Desktop** depuis le menu Démarrer de Windows et attendez que le moteur démarre.

Dans **Settings → General** de Docker Desktop, activez **Use WSL 2 based engine** si l'option est affichée. Sous **Settings → Resources → WSL Integration**, activez l'intégration pour **Ubuntu**, puis sélectionnez **Apply** ou **Apply & restart**. Si Ubuntu n'est pas votre distribution par défaut, activez explicitement son propre interrupteur.

Si WSL Integration est absent, vérifiez que Docker Desktop utilise des **conteneurs Linux**. Consultez le [guide du backend WSL 2 de Docker](https://docs.docker.com/desktop/features/wsl/).

Utilisez l'intégration de Docker Desktop pour ce guide. Installer un second Docker Engine avec `apt install docker.io` ou démarrer `dockerd` dans Ubuntu crée une configuration distincte et peut provoquer des conflits. Si vous utilisez déjà un Engine dans Ubuntu, suivez les recommandations de migration de Docker avant de basculer ; conservez les données d'application et les sauvegardes existantes.
</Step>

<Step title="Vérifier Docker depuis Ubuntu">
Ouvrez un terminal **Ubuntu**. Exécutez-y ces commandes, sans `sudo` :

```bash
docker version
docker compose version
docker ps
```

`docker version` doit afficher à la fois **Client** et **Server**. Une liste de conteneurs vide est normale sur une nouvelle installation. `docker --version` seul ne prouve pas que le moteur fonctionne.

Si `docker` n'est pas disponible ou ne parvient pas à se connecter, rouvrez Ubuntu après avoir appliqué WSL Integration et vérifiez que Docker Desktop est en cours d'exécution. Consultez [Dépannage](/fr/on-premises/installation/using-docker-compose/windows/troubleshooting#docker-is-unavailable-in-ubuntu).
</Step>

<Step title="Vérifier les ressources et le socket Docker">
Vérifiez les ressources visibles par Docker :

```bash
docker info --format 'CPUs={{.NCPU}} Memory={{.MemTotal}} Kernel={{.KernelVersion}}'
df -h "$HOME"
ls -l /var/run/docker.sock
```

Pour une petite instance locale, 4 processeurs et 8 Go de mémoire disponibles pour Docker constituent une suggestion de départ, et non un minimum mesuré. Gardez aussi suffisamment de mémoire pour Windows. Avec le backend WSL 2, les limites de ressources se gèrent via les [paramètres de WSL](https://learn.microsoft.com/en-us/windows/wsl/wsl-config), et non via les curseurs de ressources de Docker Desktop comme sur Mac. Les modifications qui nécessitent `wsl --shutdown` interrompent toutes les distributions WSL et charges de travail Docker en cours ; appliquez-les avant de démarrer l'instance.

Laissez `DOCKER_SOCKET_PATH=/var/run/docker.sock` dans la configuration du Toolkit. L'application a besoin de ce socket du moteur pour les compilations en sandbox. Ne modifiez pas ses permissions en `777` pour corriger des erreurs de connexion ; rétablissez plutôt l'intégration de Docker Desktop.
</Step>
</Steps>
