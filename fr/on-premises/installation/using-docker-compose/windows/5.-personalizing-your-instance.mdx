---
title: 5. Personnaliser votre instance
description: Définissez le port, l'URL du site et l'image TeX Live, activez les compilations en sandbox et démarrez Ayakaleaf Pro sous WSL 2.
icon: square-sliders
---

Exécutez les commandes et modifiez les fichiers dans **Ubuntu**, depuis `~/ayakaleaf-toolkit`.

<Steps>
<Step title="Paramètres des conteneurs">
Modifiez les entrées existantes dans `config/overleaf.rc` :

```bash title="config/overleaf.rc"
PROJECT_NAME=ayakaleaf-wsl
SERVER_PRO=true
OVERLEAF_LISTEN_IP=127.0.0.1
OVERLEAF_PORT=8080
SIBLING_CONTAINERS_ENABLED=true
DOCKER_SOCKET_PATH=/var/run/docker.sock
```

Conservez les chemins de données par défaut ainsi que les services MongoDB et Redis fournis. Le port `8080` est destiné au navigateur Windows local ; la liaison à `127.0.0.1` le garde local. Les compilations en sandbox utilisent un conteneur Linux distinct pour chaque compilation, au lieu d'exécuter TeX dans le conteneur de l'application. Le socket Docker permet à l'application de créer ces conteneurs, et le Toolkit fournit le chemin sur l'hôte des données de compilation sous `data/overleaf/data/compiles`.
</Step>

<Step title="Paramètres de l'application">
Dans `config/variables.env`, définissez ces valeurs, en remplaçant toute entrée active portant le même nom :

```dotenv title="config/variables.env"
OVERLEAF_SITE_URL=http://localhost:8080
TEX_LIVE_DOCKER_IMAGE=ghcr.io/ayaka-notes/texlive-full:2026.1
ALL_TEX_LIVE_DOCKER_IMAGES=ghcr.io/ayaka-notes/texlive-full:2026.1
ALL_TEX_LIVE_DOCKER_IMAGE_NAMES="TeX Live 2026"
```

L'image full comprend les paquets et les polices nécessaires à un large éventail de projets. Prévoyez au moins 40 Go d'espace de stockage libre pour celle-ci et l'application, plus de l'espace pour les données des projets et les futures mises à jour.

Pour un test de déploiement rapide, utilisez plutôt l'image **basic**, plus petite. Elle suffit pour le test d'article simple de l'étape 6, mais n'inclut pas l'ensemble complet de paquets et de polices :

```dotenv
TEX_LIVE_DOCKER_IMAGE=ghcr.io/ayaka-notes/texlive-basic:2026.1
ALL_TEX_LIVE_DOCKER_IMAGES=ghcr.io/ayaka-notes/texlive-basic:2026.1
ALL_TEX_LIVE_DOCKER_IMAGE_NAMES="TeX Live 2026 Basic"
```

Choisissez l'un de ces deux ensembles, sans clés actives en double. Le [Dockerfile](https://github.com/ayaka-notes/texlive-full/blob/main/texlive/2026/Dockerfile.basic) de l'image basic inclut `latexmk`, XeTeX et `fontspec`, mais pas `ctex` ni la collection complète de polices. Un paquet LaTeX manquant dans basic n'indique pas à lui seul un problème de sandbox.

Générez un secret de session :

```bash
openssl rand -hex 32
```

Ajoutez le résultat en tant que `OVERLEAF_SESSION_SECRET` dans `config/variables.env`. Conservez également le secret de jeton d'invitation généré. Pour une instance locale sans e-mail, laissez les paramètres SMTP et `OVERLEAF_EMAIL_FROM_ADDRESS` non définis.
</Step>

<Step title="Démarrer votre instance">
```bash
bin/up -d
```

Le Toolkit démarre MongoDB, initialise son replica set, télécharge l'image TeX Live sélectionnée, puis démarre Redis et l'application. Il peut sembler marquer une pause pendant le téléchargement d'une image volumineuse. N'exécutez pas un second `bin/up` tant que le premier est encore en cours.

Dans un autre terminal Ubuntu, vérifiez :

```bash
cd "$HOME/ayakaleaf-toolkit"
bin/docker-compose ps
bin/docker-compose logs --tail=100 mongo
bin/docker-compose logs --tail=100 -f sharelatex
```

Appuyez sur `Ctrl+C` pour arrêter de suivre les journaux ; les conteneurs détachés continuent de fonctionner. Si le démarrage échoue au niveau de MongoDB, suivez [MongoDB ne démarre pas](/fr/on-premises/installation/using-docker-compose/windows/troubleshooting#mongodb-fails-to-start) avant de réessayer. Ne supprimez pas son répertoire de données pour réinitialiser une installation existante.

Vérifiez le port et la page de premier lancement :

```bash
bin/docker-compose port sharelatex 80
curl -I http://localhost:8080/launchpad
```

Le port doit être `127.0.0.1:8080`. Attendez la fin de l'initialisation de l'application si la requête HTTP échoue au début.
</Step>

<Step title="Ouvrir l'instance depuis Windows">
Dans votre **navigateur Windows**, ouvrez [http://localhost:8080/launchpad](http://localhost:8080/launchpad). Utilisez également cette adresse dans Windows, plutôt qu'une adresse IP WSL temporaire.

Pour vérifier l'accès HTTP depuis Windows indépendamment du navigateur, exécutez dans **PowerShell** :

```powershell
curl.exe -I http://localhost:8080/launchpad
```

Si Ubuntu peut atteindre la page mais pas Windows, consultez [Windows ne peut pas ouvrir localhost](/fr/on-premises/installation/using-docker-compose/windows/troubleshooting#windows-cannot-open-localhost).
</Step>
</Steps>
