Le [Toolkit](/fr/on-premises/installation/using-docker-compose) est la méthode recommandée pour exécuter Ayakaleaf Pro sur un seul serveur. Si vous exploitez déjà un cluster Kubernetes, cette section y déploie le même conteneur avec de simples manifestes `kubectl` : aucune image supplémentaire, aucun chart Helm.

À la fin de cette section, vous disposez d'une instance Ayakaleaf Pro avec les compilations isolées, un replica set MongoDB et Redis, le tout dans le namespace `overleaf`. Pour exécuter plusieurs instances derrière un équilibreur de charge, poursuivez ensuite avec [Mise à l'échelle horizontale](/fr/on-premises/configuration/kubernetes/horizontal-scaling).

<Info>

La prise en charge de Kubernetes est expérimentale. Nous ne publions ni chart Helm ni images spécifiques à Kubernetes. Les manifestes de ces pages sont ceux que nous avons testés sur Kubernetes 1.37 (kubeadm, containerd 2.4, flannel) avec trois nœuds de 2 vCPU et 4 Go de mémoire chacun. Adaptez le stockage, le réseau et l'ingress à votre cluster.

</Info>

### Correspondance des éléments {#how-the-pieces-fit}

| Toolkit (un seul serveur)                    | Kubernetes                                                               |
| -------------------------------------------- | ------------------------------------------------------------------------ |
| `config/variables.env`                       | ConfigMap `overleaf-env` et Secret `overleaf-secrets`                    |
| Conteneur `sharelatex`                       | Deployment `overleaf` (un pod exécutant tous les services Overleaf)      |
| Conteneurs `mongo` et `redis`                | StatefulSets `mongo` (replica set) et `redis`, ou vos services managés   |
| `~/overleaf-toolkit/data/overleaf`           | PersistentVolumeClaim `overleaf-data`                                    |
| Docker sur l'hôte, utilisé pour les compilations | Docker Engine sur chaque nœud qui exécute Ayakaleaf Pro              |
| `bin/up`, `bin/logs`, `bin/shell`            | `kubectl apply`, `kubectl logs`, `kubectl exec`                          |

### Ce dont vous avez besoin {#what-you-need}

* Un cluster Kubernetes sur lequel vous pouvez installer des paquets : chaque nœud susceptible d'exécuter Ayakaleaf Pro a besoin de **Docker Engine**, car les compilations s'exécutent dans des conteneurs TeX Live qu'Ayakaleaf Pro démarre via le `/var/run/docker.sock` du nœud. Voir [0. Préparer les nœuds](/fr/on-premises/installation/using-kubernetes/0.-prepare-the-nodes).
* Une StorageClass par défaut avec des volumes `ReadWriteOnce`.
* `kubectl` et `openssl` sur votre poste de travail.
