### Créer votre premier compte administrateur {#creating-your-first-administrator-account}

Ouvrez `OVERLEAF_SITE_URL` suivi de `/launchpad`, par exemple `http://192.0.2.10:30080/launchpad`, et enregistrez le compte administrateur comme dans les [tâches post-installation du Toolkit](/fr/on-premises/installation/using-docker-compose/linux/6.-post-installation-tasks). Créez ensuite un projet d'exemple et compilez-le.

Vous pouvez également créer des utilisateurs en ligne de commande :

```bash
kubectl -n overleaf exec deploy/overleaf -- bash -c \
  'cd /overleaf/services/web && node modules/server-ce-scripts/scripts/create-user.mjs --admin --email=admin@example.com'
```

La commande affiche un lien permettant de définir le mot de passe.

### Vérifier que les compilations sont isolées {#checking-that-compiles-are-sandboxed}

Compilez un projet, puis examinez le nœud qui exécute le pod :

```bash
kubectl -n overleaf get pod -l app=overleaf -o wide   # NODE column
# on that node:
sudo docker ps -a --filter ancestor=ghcr.io/ayaka-notes/texlive-full:2026.1
ls -ln /srv/overleaf/compiles                          # owned by uid 33 (www-data)
```

Chaque compilation apparaît sous la forme d'un conteneur éphémère nommé `project-<project id>-<user id>-...`.

### Journaux et shell {#logs-and-a-shell}

| Toolkit          | Kubernetes                                                               |
| ---------------- | ------------------------------------------------------------------------ |
| `bin/logs web`   | `kubectl -n overleaf exec deploy/overleaf -- tail -f /var/log/overleaf/web.log` |
| `bin/shell`      | `kubectl -n overleaf exec -it deploy/overleaf -- bash`                    |
| `bin/up`         | `kubectl apply -f .` puis `kubectl -n overleaf rollout restart deployment/overleaf` |

Le conteneur écrit un fichier journal par service dans `/var/log/overleaf/` (`web.log`, `clsi.log`, `real-time.log`, `document-updater.log`, ...) ; `kubectl logs` affiche la sortie de démarrage.

### Q\&A {#q&a}

<Accordion title="La compilation échoue ou ne se termine jamais.">

<strong>Réponse :</strong> Vérifiez, sur le nœud qui exécute le pod, que Docker est en cours d'exécution et dispose de l'image indiquée dans `TEX_LIVE_DOCKER_IMAGE`, et que `SANDBOXED_COMPILES_HOST_DIR_*` correspondent aux chemins `hostPath`. Le fichier `/var/log/overleaf/clsi.log` du pod indique l'étape en échec.

</Accordion>

<Accordion title="Les utilisateurs sont déconnectés après chaque redémarrage du pod.">

<strong>Réponse :</strong> `OVERLEAF_SESSION_SECRET` est absent du Secret `overleaf-secrets`, voir l'[étape 2](/fr/on-premises/installation/using-kubernetes/2.-create-the-namespace-and-secrets).

</Accordion>
