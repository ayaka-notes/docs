Comme Overleaf Server Pro, notre Ayakaleaf Pro est fourni sous forme de conteneur Docker et constitue un remplacement direct, qui inclut en plus des fonctionnalités telles que le SSO via LDAP et SAML2, une sécurité renforcée, le suivi des modifications, les commentaires, notre version optimisée de TeX Live, les modèles et un panneau d'administration.

* Si vous souhaitez simplement tester les fonctionnalités d'Ayakaleaf Pro ou essayer la démo, vous pouvez suivre notre tutoriel [using-the-github-codespace.md](/fr/on-premises/installation/using-the-github-codespace  "mention"). L'environnement de démo utilise une installation minimale de TeX Live ; certains de vos projets risquent donc de ne pas compiler.
* Si vous n'avez jamais déployé aucune version d'Overleaf, consultez [Installer Docker](/fr/on-premises/installation/setup-docker) pour installer d'abord Docker Engine, puis installez Overleaf en suivant [using-the-toolkit](/fr/on-premises/installation/using-the-toolkit  "mention").
* Si vous avez déjà déployé la Community Edition d'Overleaf, consultez [migrate-from-existing.md](/fr/on-premises/installation/migrate-from-existing  "mention") pour migrer vers Ayakaleaf Pro.
* Si vous préférez utiliser des agents comme Claude ou Codex, vous pouvez consulter : [using-claude-or-codex.md](/fr/on-premises/installation/using-claude-or-codex  "mention").
* Si vous devez déployer dans un environnement hors ligne ou isolé, consultez : [air-gapped-offline-deployments.md](/fr/on-premises/installation/air-gapped-offline-deployments  "mention").
* Si vous êtes déjà utilisateur de Server Pro, merci d'ouvrir une issue pour nous prévenir avant de migrer vers Ayakaleaf Pro, car les données des modèles sont stockées dans un format légèrement différent. Nous serons ravis de vous aider gratuitement à migrer de Server Pro vers Ayakaleaf Pro.
* Si un jour vous vous lassez de notre Ayakaleaf Pro et souhaitez revenir à l'Overleaf Community Edition officielle, c'est entièrement pris en charge. Aucune de vos données ne sera perdue. Pour les utilisateurs de l'Overleaf Toolkit officiel, supprimez simplement votre fichier YAML de surcharge. Pour les utilisateurs du toolkit ayaka-notes, désactivez l'option `SERVER_PRO`. Tout reviendra alors à la Community Edition standard.

### Prérequis matériels

Nous avons effectué des tests et constaté que, si vous exécutez Overleaf sur un serveur à 2 cœurs et 2 Go de RAM, ses composants principaux — essentiellement basés sur Node.js — consomment environ 1 Go de mémoire. Redis et MongoDB peuvent nécessiter 0,5 Go supplémentaire, tandis que le démarrage d'un conteneur Docker en sandbox pour la compilation peut consommer encore 0,3 Go. Concrètement, un serveur à 2 cœurs et 2 Go ne peut gérer qu'environ une compilation simultanée.

* La configuration matérielle minimale pour installer Ayakaleaf Pro est un processeur à 2 cœurs et 3 Go de RAM.
* En raison de la taille de notre image TeX Live, au moins 40 Go de stockage sont nécessaires pour activer la compilation en sandbox.
* Si vous souhaitez installer l'ensemble complet des images TeX Live de 2020 à 2026, assurez-vous de disposer d'au moins 150 Go d'espace disque libre.

Voici quelques configurations matérielles recommandées selon les scénarios d'utilisation :

| Cas d'usage                                             | Configuration recommandée                                                                            |
| ---------------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| Usage personnel, avec collaboration occasionnelle          | 2 cœurs CPU, 4 Go de RAM, 80 Go de stockage                                                                 |
| Petites équipes, jusqu'à 10 utilisateurs avec collaboration légère | 2 cœurs CPU, 8 Go de RAM, 256 Go de stockage                                                                |
| Équipes de taille moyenne, jusqu'à 100 utilisateurs                  | 4 cœurs CPU, 16 Go de RAM, 1 To de stockage                                                                 |
| Déploiements à grande échelle ou universitaires                | Déploiement en cluster distribué, avec stockage S3 ; contactez-nous si vous avez besoin d'aide pour le déploiement |

### Prérequis logiciels

Côté logiciel, nous recommandons d'utiliser une version récente et stable d'Ubuntu (par ex. Ubuntu 24.04 en 2025–2026, Ubuntu 22.04 en 2023–2024) avec la dernière version stable de Docker.

<Info>

La stabilité d'abord : choisissez la version Ubuntu LTS la plus récente qui est disponible depuis un certain temps, et non une version tout juste sortie. Par exemple, en octobre 2026, Ubuntu 26.04 n'est pas pris en charge : il est livré avec le noyau Linux 7.0, et MongoDB refuse de démarrer sur les noyaux Linux 6.19 à 7.0.13 ([détails](https://www.mongodb.com/docs/manual/administration/production-notes/)) ; utilisez donc Ubuntu 24.04.

</Info>

Nous déconseillons de déployer Ayakaleaf Pro sur Windows ou sur d'autres systèmes d'exploitation non pris en charge comme CentOS, car vous pourriez rencontrer des problèmes de compatibilité ou des dysfonctionnements inattendus lors de l'installation et de l'exploitation.

Mais si vous souhaitez essayer de déployer Ayakaleaf Pro sur des systèmes ARM ou sur macOS, n'hésitez pas à partager votre expérience et vos retours avec la communauté.

### Performances de LaTeX

LaTeX est un programme monothread : il ne peut utiliser qu'un seul cœur de processeur à la fois. Lors de la compilation d'un document, les performances sont principalement limitées par la fréquence monocœur du processeur. Ainsi, plus les performances monocœur de votre processeur sont élevées, plus la compilation d'un document sera rapide. Davantage de cœurs n'est utile que lorsque plusieurs utilisateurs compilent des documents simultanément.

En prenant l'exemple du [modèle ThuThesis](https://www.overleaf.com/latex/templates/thuthesis-tsinghua-university-thesis-latex-template/cfwgcxtvkbsx), la compilation prend environ 6 secondes sur un Intel Core i9-14900K (5,6 GHz), contre environ 13 secondes sur une instance Azure Standard D2as v5 (2 vCPU, 8 Gio de RAM) équipée d'un AMD EPYC 7763 (3,2 GHz).

Bien entendu, les performances réelles de compilation dépendent de votre configuration matérielle. La plupart des processeurs de serveur ne fonctionnent pas à des fréquences aussi élevées que le 14900K ; vous devrez donc trouver un compromis entre coût et vitesse de compilation.

Par ailleurs, nous avons mené une analyse approfondie des performances de compilation LaTeX. Si cela vous intéresse, consultez notre article de blog [Overleaf Benchmark: A Deep Research of Concurrent LaTeX Compilation in Overleaf (SaaS and Self-host)](/fr/blog/2026/overleaf-benchmark  "mention").
