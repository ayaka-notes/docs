title: 1. Télécharger et initialiser le Toolkit
description: Clonez le Toolkit Ayakaleaf, créez la configuration et préparez-la pour Ayakaleaf Pro sur Podman.

---

<Steps>
<Step title="Cloner le Toolkit">
Clonez le **Toolkit Ayakaleaf** ([ayaka-notes/toolkit](https://github.com/ayaka-notes/toolkit)) dans votre répertoire personnel et placez-vous dans ce répertoire :

```bash title="Clone the Toolkit" wrap
git clone https://github.com/ayaka-notes/toolkit.git ~/overleaf-toolkit
cd ~/overleaf-toolkit
```

Exécutez toutes les commandes suivantes depuis ce répertoire.
</Step>

<Step title="Créer la configuration">
```bash title="Run initialization"
bin/init
```

Cela crée `config/overleaf.rc`, `config/variables.env` et `config/version`, comme décrit dans [3. Initialiser la configuration](/fr/on-premises/installation/using-docker-compose/linux/3.-initialize-the-configuration) du guide Docker. `bin/init` n'a pas encore besoin de Podman.
</Step>

<Step title="Configurer config/overleaf.rc">
Ouvrez `config/overleaf.rc` et modifiez ces lignes :

```bash title="config/overleaf.rc"
SERVER_PRO=true
OVERLEAF_PORT=8080
SIBLING_CONTAINERS_ENABLED=true
```

Ajoutez ensuite cette ligne à la fin du fichier :

```bash title="config/overleaf.rc"
SELINUX_MODE=managed
```

| Paramètre                         | Pourquoi                                                                                                                                                                                                    |
| --------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `SERVER_PRO=true`                 | Utilise l'image Ayakaleaf Pro de `ghcr.io`. Aucune connexion n'est nécessaire.                                                                                                                               |
| `OVERLEAF_PORT=8080`              | Podman rootless ne peut pas écouter sur les ports inférieurs à `1024`. La valeur par défaut `80` échoue.                                                                                                     |
| `SIBLING_CONTAINERS_ENABLED=true` | Exécute chaque compilation dans son propre conteneur TeX Live. Déjà `true` par défaut ; la configuration Podman ne prend en charge que ce mode.                                                              |
| `SELINUX_MODE=managed`            | Exécute le conteneur `sharelatex` avec le type SELinux `sharelatex_t`, qui peut utiliser le socket Podman et rien de plus. `bin/podman-setup --apply` installe le module de politique correspondant. Consultez [Paramètres du Toolkit](/fr/on-premises/configuration/overleaf-toolkit/toolkit-settings) pour les autres modes. |

Laissez `DOCKER_SOCKET_PATH` tel quel : `bin/podman-setup --apply` le définit sur votre socket Podman à l'étape suivante.

<Warning>

Laissez `GIT_BRIDGE_ENABLED=false`. Dans Ayakaleaf Pro 6.3.4, l'intégration Git ne fonctionne pas sur Podman, consultez [Limitations connues](/fr/on-premises/installation/using-podman#known-limitations).

</Warning>
</Step>

<Step title="Choisir les images TeX Live">
Ouvrez `config/variables.env`, supprimez le `#` devant `TEX_LIVE_DOCKER_IMAGE` et `ALL_TEX_LIVE_DOCKER_IMAGES`, et listez les images TeX Live à utiliser :

```bash title="config/variables.env" wrap
TEX_LIVE_DOCKER_IMAGE=ghcr.io/ayaka-notes/texlive-full:2026.1
ALL_TEX_LIVE_DOCKER_IMAGES=ghcr.io/ayaka-notes/texlive-full:2026.1
```

`bin/up` s'arrête avec `Please configure ALL_TEX_LIVE_DOCKER_IMAGES` si la liste est vide. `texlive-full` est volumineuse ; pour un serveur de test, l'image bien plus petite `ghcr.io/ayaka-notes/texlive-basic:2026.1` convient aussi. Consultez [Compilations isolées](/fr/on-premises/configuration/overleaf-toolkit/sandboxed-compiles) pour les images disponibles.

Définissez les autres variables, comme `OVERLEAF_SITE_URL`, comme décrit dans [5. Personnaliser votre instance](/fr/on-premises/installation/using-docker-compose/linux/5.-personalizing-your-instance#required-environment-variables). Avec l'adresse d'écoute par défaut, utilisez `http://localhost:8080`.
</Step>
</Steps>
