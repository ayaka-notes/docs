---
title: 2. Exécuter podman-setup
description: Laissez bin/podman-setup vérifier l'hôte et configurer Podman rootless, SELinux et le profil seccomp.

---

`bin/podman-setup` vérifie tout ce dont Ayakaleaf Pro a besoin sur Podman. Sans option, il se contente de faire un rapport ; avec `--apply`, il corrige aussi ce qu'il trouve.

<Steps>
<Step title="Vérifier l'hôte">
```bash title="Check only"
bin/podman-setup
```

Sur un hôte neuf, la plupart des vérifications échouent, par exemple :

```text
====== Packages ======
[✗] podman not installed
[✗] podman-docker not installed
...
====== Summary ======
[✓] 7 passed  [!] 13 warnings  [✗] 4 failures
```
</Step>

<Step title="Appliquer les corrections">
```bash title="Check and fix"
bin/podman-setup --apply
```

Exécutez-le dans un terminal : il demande votre mot de passe `sudo` pour les étapes à l'échelle du système. Il télécharge aussi l'image Ayakaleaf Pro pour en extraire le profil seccomp, ce qui prend quelques minutes la première fois. À la fin, il vérifie à nouveau l'hôte :

```text
====== Summary ======
[✓] 23 passed  [!] 2 warnings  [✗] 0 failures
[!] Warnings remaining:
[!] not logged in to quay.io
[!] container → socket skipped (sharelatex not running)
```

Les deux avertissements sont attendus à ce stade :

* `not logged in to quay.io` : la vérification provient du Toolkit officiel, où l'image Server Pro se trouve dans un registre privé. Les images Ayakaleaf Pro sont publiques sur `ghcr.io` et ne nécessitent aucune connexion, ignorez-le donc. Il reste également après l'installation.
* `container → socket skipped (sharelatex not running)` : ce test nécessite l'instance en cours d'exécution. Vous exécuterez à nouveau le script dans [3. Démarrer Ayakaleaf Pro](/fr/on-premises/installation/using-podman/3.-start-ayakaleaf-pro).

Le script se termine avec `0` lorsque toutes les vérifications réussissent, `1` en cas d'avertissements et `2` en cas d'échecs. À cause de l'avertissement quay.io, attendez-vous à `1`.
</Step>
</Steps>

### Ce que le script modifie {#what-the-script-changes}

Avec `--apply`, le script peut modifier les éléments suivants.

À l'échelle du système, avec `sudo` :

* Installe `podman`, `podman-docker`, `git`, `curl`, `checkpolicy` et `policycoreutils` avec `dnf`.
* Active le lingering pour votre utilisateur avec `loginctl`, afin que vos conteneurs continuent de tourner après votre déconnexion.
* Crée `/etc/containers/nodocker`, qui masque le message "Emulate Docker CLI using podman".
* Charge le module de politique SELinux `podman_socket_clsi`, lorsque `SELINUX_MODE=managed`.

Pour votre utilisateur :

* Active le service utilisateur `podman.socket`, l'API compatible Docker qu'Ayakaleaf Pro utilise pour lancer les compilations.
* Installe Docker Compose v2 depuis GitHub dans `~/.local/bin/docker-compose` et le lie dans `~/.docker/cli-plugins/`.
* Fait utiliser ce Compose par Podman dans `~/.config/containers/containers.conf`.
* Ajoute les alias `mongo` et `redis` dans `~/.config/containers/registries.conf.d/overleaf-toolkit.conf`, afin que Podman sache d'où récupérer ces noms d'image courts.

Dans le Toolkit :

* Définit `DOCKER_SOCKET_PATH` et `DOCKER_HOST` dans `config/overleaf.rc` sur `/run/user/<uid>/podman/podman.sock`.
* Extrait le profil seccomp des compilations de l'image Ayakaleaf Pro vers `config/seccomp/<version>/clsi-profile.json`, et définit `SECCOMP_PROFILE` dans `config/variables.env`. Contrairement à Docker, Podman a besoin de ce profil sous forme de fichier sur l'hôte.
* Compile le module de politique SELinux dans `config/selinux/`.
* Définit les propriétaires des répertoires de données dans `data/` avec `podman unshare chown`, une fois qu'ils existent.

<Info>

Chaque modification correspond à une vérification. Si vous modifiez quelque chose à la main, par exemple dans `config/overleaf.rc`, exécutez à nouveau `bin/podman-setup` pour le vérifier.

</Info>
