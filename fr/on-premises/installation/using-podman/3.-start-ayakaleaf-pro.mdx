---
title: 3. Démarrer Ayakaleaf Pro
description: Démarrez Ayakaleaf Pro sur Podman, vérifiez-le avec podman-setup et bin/doctor, et démarrez-le après les redémarrages.
icon: circle-play
---

<Steps>
<Step title="Démarrer les conteneurs">
```bash title="Start Ayakaleaf Pro"
bin/up -d
```

Le premier démarrage télécharge les images MongoDB, Redis et TeX Live, et crée les répertoires de données dans `data/`. Il affiche un avertissement indiquant que la prise en charge de Podman est expérimentale.

<Info>

Le premier démarrage peut aussi afficher `MongoNetworkError: connect ECONNREFUSED 127.0.0.1:27017`. Le Toolkit configure le replica set MongoDB pendant que MongoDB démarre encore, et réessaie jusqu'à ce qu'il réponde. Vous pouvez ignorer cette ligne.

</Info>

Au bout d'une minute ou deux, vérifiez que les conteneurs tournent :

```bash title="List the containers"
podman ps --format "{{.Names}} {{.Status}}"
```

```text
mongo Up 34 seconds (healthy)
redis Up 20 seconds
sharelatex Up 20 seconds
```
</Step>

<Step title="Vérifier à nouveau la configuration">
Maintenant que les répertoires de données existent et que le conteneur `sharelatex` tourne, `bin/podman-setup` peut terminer ses vérifications :

```bash title="Check the setup"
bin/podman-setup
```

Il vérifie les propriétaires des nouveaux répertoires de données et teste le socket Podman depuis l'intérieur du conteneur `sharelatex` :

```text
====== Socket Connectivity ======
[✓] host → socket OK
[✓] container → socket OK

====== Data Directory Permissions ======
[✓] mongo data dir owned by 999
[✓] redis data dir owned by 999
[✓] overleaf data dir owned by 33
...
====== Summary ======
[✓] 27 passed  [!] 1 warnings  [✗] 0 failures
[!] Warnings:
[!] not logged in to quay.io
```

`container → socket OK` signifie qu'Ayakaleaf Pro peut lancer des conteneurs de compilation. Si une vérification échoue, exécutez `bin/podman-setup --apply`, puis `bin/up -d`. L'avertissement quay.io ne s'applique pas à Ayakaleaf Pro, consultez [2. Exécuter podman-setup](/fr/on-premises/installation/using-podman/2.-run-podman-setup).
</Step>

<Step title="Exécuter le doctor">
```bash title="Run the doctor"
bin/doctor
```

Sur Podman, le rapport affiche l'environnement d'exécution et les paramètres de sécurité :

```text
- Container Daemon
    - status: up
    - runtime: podman
    - server version: 5.8.5
    - socket: /run/user/1000/podman/podman.sock
    - DOCKER_HOST: unix:///run/user/1000/podman/podman.sock
    - host → socket: OK
    - container → socket: OK
- Security
    - SELinux: Enforcing
    - SELINUX_MODE: managed
    - SELINUX_LABEL: sharelatex_t
    - SELinux module: loaded (podman_socket_clsi)
    - SELinux rules: present
    - Seccomp profile: present
```

L'avertissement `Server Pro enabled, but not logged in to quay.io repository` à la fin correspond à la même vérification quay.io, consultez [Obtenir de l'aide](/fr/on-premises/support/getting-help#q-and-a).
</Step>

<Step title="Démarrer Ayakaleaf Pro après un redémarrage">
Avec Docker, le démon Docker redémarre les conteneurs après un redémarrage. Podman rootless n'a pas de démon : activez le service utilisateur qui démarre vos conteneurs au démarrage du serveur :

```bash title="Start the containers at boot"
systemctl --user enable podman-restart.service
```

Il démarre chaque conteneur de votre utilisateur dont la politique de redémarrage est `always`, ce que le Toolkit définit pour tous ses conteneurs. Cela nécessite le lingering, que `bin/podman-setup --apply` a activé. Sans ce service, exécutez `bin/up -d` après chaque redémarrage.
</Step>

<Step title="Ouvrir le port dans le pare-feu">
Par défaut, l'instance n'accepte que les connexions provenant du serveur lui-même, sur `http://localhost:8080`. Pour l'ouvrir depuis d'autres ordinateurs, définissez `OVERLEAF_LISTEN_IP` dans `config/overleaf.rc` et `OVERLEAF_SITE_URL` dans `config/variables.env` comme décrit dans [5. Personnaliser votre instance](/fr/on-premises/installation/using-docker-compose/linux/5.-personalizing-your-instance#listen-address-and-port), puis exécutez à nouveau `bin/up -d`.

Contrairement à Docker, Podman rootless ne contourne pas le pare-feu de l'hôte. Si `firewalld` tourne, ce qui est le cas par défaut sous RHEL, ouvrez le port :

```bash title="Open port 8080"
sudo firewall-cmd --permanent --add-port=8080/tcp
sudo firewall-cmd --reload
```

Sur un serveur cloud, autorisez aussi le port dans le groupe de sécurité du fournisseur. Utilisez HTTPS avant d'exposer l'instance à Internet, consultez [4. Tâches post-installation](/fr/on-premises/installation/using-podman/4.-post-installation-tasks#use-https).
</Step>
</Steps>
