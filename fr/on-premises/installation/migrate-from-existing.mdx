### Migrer depuis Overleaf Community

#### Cas 01 : depuis l'Overleaf Toolkit

Si vous utilisez l'Overleaf Toolkit officiel pour Overleaf Community, il suffit d'ajouter un fichier nommé `docker-compose.override.yml` avec le contenu suivant (ou similaire) dans le répertoire `overleaf-toolkit/config` :

```yml title="docker-compose.override.yml"
---
services:
    sharelatex:
        image: ghcr.io/ayaka-notes/overleaf-pro:X.x.x # change to specific version
```

Pour démarrer votre instance, exécutez :

```bash
bin/up
```

C'est tout ! Vous êtes prêt. Vous pouvez ensuite vérifier que votre instance Ayakaleaf fonctionne correctement et que l'interface web est accessible. Une fois que tout fonctionne, poursuivez avec les étapes de [configuration](/fr/on-premises/configuration/overleaf-toolkit) ci-dessous pour activer les fonctionnalités avancées telles que :

* [sandboxed-compiles.md](/fr/on-premises/configuration/overleaf-toolkit/sandboxed-compiles  "mention")
* [authentication](/fr/on-premises/configuration/overleaf-toolkit/authentication  "mention")
* [github-synchronisation.md](/fr/on-premises/configuration/overleaf-toolkit/github-synchronisation  "mention")
* [zotero-integration.md](/fr/on-premises/configuration/overleaf-toolkit/zotero-integration  "mention")

#### Cas 02 : depuis un fichier Docker Compose

Si vous utilisez un fichier `docker-compose.yml` autonome, migrez-le d'abord vers l'Overleaf Toolkit. Le Toolkit simplifie l'installation sur site, les mises à niveau et la maintenance.

Suivez le guide [docker-compose.yml-to-toolkit-migration.md](/fr/on-premises/maintenance/docker-compose.yml-to-toolkit-migration  "mention") pour convertir votre déploiement existant. Conservez votre configuration actuelle et les chemins de vos volumes de données pendant cette migration.

Une fois le déploiement Toolkit opérationnel, suivez [#from-overleaf-toolkit](/fr/on-premises/installation/migrate-from-existing#from-overleaf-toolkit  "mention") pour remplacer son image par Ayakaleaf Pro. Démarrez l'instance avec `bin/up`, puis vérifiez que l'interface web est accessible.

***

### Migrer depuis Overleaf Server Pro

Si vous utilisez actuellement une instance sous licence commerciale d'[Overleaf Server Pro](https://www.overleaf.com/for/enterprises) et souhaitez migrer vers Ayakaleaf Pro, sachez que la migration peut demander un travail supplémentaire, car certains formats de données (`templates`) peuvent ne pas être entièrement compatibles. Nous serons toutefois ravis de vous aider. Veuillez [ouvrir une issue](https://github.com/ayaka-notes/ayakaleaf-pro/issues) ou nous contacter à [ayaka-notes@outlook.com](mailto:ayaka-notes@outlook.com), et nous vous aiderons gratuitement à migrer vers Ayakaleaf Pro.

***

### Migrer depuis Overleaf CEP

Des utilisateurs nous demandent fréquemment s'ils peuvent migrer d'[Overleaf CEP](https://github.com/yu-i-i/overleaf-cep) vers Ayakaleaf Pro. Dans la plupart des cas, Overleaf CEP et Ayakaleaf Pro offrent des fonctionnalités globalement équivalentes et restent compatibles au niveau des données à partir de la version 6.2.0. Les deux projets peuvent publier des fonctionnalités à des moments différents ; par exemple, nous pouvons reprendre (cherry-pick) une fonctionnalité d'Overleaf CEP, et inversement. Bien que nos implémentations d'une même fonctionnalité puissent légèrement différer, il n'y a généralement pas de raison impérieuse de migrer.

Si vous souhaitez tout de même migrer vers Ayakaleaf Pro ou l'essayer, consultez : [#case-01-from-overleaf-toolkit](/fr/on-premises/installation/migrate-from-existing#case-01-from-overleaf-toolkit  "mention"). La procédure de migration est la même.

***

### Migrer depuis Overleaf SaaS

Malheureusement, la migration de la plateforme SaaS d'Overleaf vers une instance Ayakaleaf Pro auto-hébergée peut s'avérer nettement plus difficile. À l'heure actuelle, la seule méthode généralement disponible consiste à télécharger chaque projet sous forme d'archive ZIP, puis à le téléverser sur votre instance Ayakaleaf Pro auto-hébergée. Seuls les fichiers actuels du projet sont ainsi transférés, ce qui signifie que vous _**perdrez**_ :

* Tout l'historique des projets et les révisions précédentes
* Tous les commentaires et les modifications suivies
* Toutes les métadonnées Git et l'historique des commits
* Tous les liens et paramètres de synchronisation GitHub
* Tous les liens entre les fichiers BibTeX et les plateformes tierces de gestion de références

***

### Migrer depuis un fork tiers d'Overleaf

Ayakaleaf Pro peut ne pas prendre en charge les fonctionnalités propres à un fork tiers particulier d'Overleaf. Dès lors qu'un fork s'écarte sensiblement du code amont d'Overleaf, ou introduit des modifications sans préserver la compatibilité avec l'amont, l'intégration des versions ultérieures d'Overleaf peut devenir extrêmement difficile. Vous pouvez tout de même essayer la méthode de migration décrite ci-dessus, mais la compatibilité n'est pas garantie, et nous ne serons peut-être pas en mesure de fournir de l'aide ou un support technique pour les migrations depuis des forks non pris en charge.
