Utilisez Claude Code ou Codex pour planifier et exécuter un déploiement d'Ayakaleaf Pro. L'agent peut effectuer des recherches dans cette documentation via MCP pendant qu'il travaille.

L'agent vous assiste dans le déploiement. Vous restez responsable de la vérification des commandes et de la protection des identifiants.

### Avant de commencer

Préparez un serveur Linux pris en charge avec un accès SSH. Consultez les [prérequis](/fr/on-premises/getting-started/requirements  "mention") avant de continuer.

<Warning>

Ne collez pas de mots de passe, de clés privées, de jetons ou de clés de licence dans les prompts de l'agent. Vérifiez chaque commande avant de l'exécuter, en particulier les commandes qui modifient des fichiers, des réseaux ou des conteneurs.

</Warning>

### Connecter la documentation

Ajoutez le point de terminaison MCP de la documentation à votre agent local.

<Tabs>
<Tab title="Claude Code">

```bash wrap
claude mcp add ayakaleaf-pro --scope user --transport http https://ayakaleaf-pro.ayaka.space/~gitbook/mcp
```

</Tab>

<Tab title="Codex">

```bash wrap
codex mcp add ayakaleaf-pro --url https://ayakaleaf-pro.ayaka.space/~gitbook/mcp
```

</Tab>
</Tabs>

Démarrez une nouvelle session après avoir ajouté le serveur. Demandez à l'agent de confirmer qu'il peut effectuer des recherches dans la documentation d'Ayakaleaf Pro.

### Déployer Ayakaleaf Pro

Ouvrez un terminal sur votre serveur de déploiement. Lancez-y Claude Code ou Codex. Envoyez ensuite ce prompt :

```text wrap
Use the Ayakaleaf Pro documentation MCP server to guide this deployment.
First, inspect the requirements and installation guides.
Ask me for missing deployment details before making changes.
Use the Ayakaleaf Toolkit unless the documentation requires another approach.
Before configuring the instance, summarize relevant optional features.
Ask which features and integrations I want to enable.
Include TLS, sandboxed compiles, Git integration, external MongoDB or Redis,
SSO (OIDC, SAML, or LDAP), GitHub Synchronisation, Zotero, S3 storage,
email delivery, branding, and localization when relevant.
Explain each selected option's prerequisites, security impact, and configuration steps.
Keep unselected optional features disabled.
Show each command before running it.
Do not expose, store, or request secrets in chat.
After deployment, verify that the service is healthy and summarize the changes.
```

L'agent devrait vous guider dans l'installation de Docker, la configuration du Toolkit, la récupération des images et le démarrage. Suivez le guide [using-the-toolkit](/fr/on-premises/installation/using-the-toolkit  "mention") pour la procédure de référence.

### Choisir les fonctionnalités optionnelles

Demandez à l'agent de ne recommander que les fonctionnalités adaptées à votre environnement. Les choix typiques incluent :

* **Accès et sécurité :** TLS, compilations en sandbox et SSO OIDC, SAML ou LDAP.
* **Services externes :** MongoDB, Redis, stockage S3 et envoi d'e-mails.
* **Collaboration :** intégration Git, GitHub Synchronisation et Zotero.

L'agent devrait expliquer les dépendances avant de modifier la configuration. Consultez [toolkit-settings.md](/fr/on-premises/configuration/overleaf-toolkit/toolkit-settings  "mention") et [authentication](/fr/on-premises/configuration/overleaf-toolkit/authentication  "mention") avant d'activer des intégrations en production.

### Vérifier le déploiement

Une fois que l'agent a terminé les étapes :

1. Vérifiez que chaque commande s'est terminée sans erreur.
2. Ouvrez l'URL d'Ayakaleaf Pro configurée dans votre navigateur.
3. Effectuez les [6.-post-installation-tasks.md](/fr/on-premises/installation/using-the-toolkit/6.-post-installation-tasks  "mention").

Pour une installation Community Edition existante, utilisez le guide [migrate-from-existing.md](/fr/on-premises/installation/migrate-from-existing  "mention") au lieu d'un nouveau déploiement.
