### Docker

Docker offre un moyen léger et portable d'empaqueter et d'exécuter des applications dans des conteneurs isolés. En regroupant l'application avec toutes ses dépendances, un conteneur garantit un comportement cohérent d'une machine à l'autre, de l'ordinateur portable aux serveurs de production.

TeX Live est puissant, mais volumineux et sensible aux différences au niveau du système. Empaqueter TeX Live dans une image Docker rend la chaîne d'outils LaTeX prévisible, reproductible et facile à distribuer.

Cependant, certains packages TeX Live ont besoin d'un accès au shell. Pour des raisons de sécurité, le conteneur doit s'exécuter dans un environnement restreint qui empêche les utilisateurs d'exécuter des commandes shell arbitraires (par exemple via `\write18` ou le shell escape). Cette isolation protège le système hôte et évite tout accès involontaire au système de fichiers sous-jacent du conteneur ou à des outils tels que `bash`.

### Édition complète de TeXLive

[TeXLive-Full@ayaka-notes](https://github.com/ayaka-notes/texlive-full/) est une **image Docker TeXLive** complète, conçue pour la compilation LaTeX en sandbox dans [Ayakaleaf Pro](https://github.com/ayaka-notes/ayakaleaf-pro), [Overleaf CEP](https://github.com/yu-i-i/overleaf-cep) ou des environnements de compilation LaTeX autonomes.

Cette image vise à fournir une distribution TeXLive presque complète, avec les polices et outils courants préinstallés, afin de réduire au minimum les échecs de compilation dus à des packages ou des polices manquants. Remarque : cette image Docker **ne contient aucun** composant sharelatex/overleaf. Elle est utilisée pour la compilation d'Overleaf/Overleaf Pro.

#### Fonctionnalités :

* 🚀 Prise en charge des architectures serveur x86\_64 et arm64
* 📦 Installation TeXLive complète et optimisée
* 🧩 Polices et utilitaires courants préinstallés
* 🐳 Prête à l'emploi avec Docker et Docker Compose
* 🧪 Testée avec Overleaf Server Pro / Overleaf Pro
* 🔄 Mise à jour régulièrement avec les dernières versions de TeXLive
* 🏷 Plusieurs tags de version de TeXLive (de 2020 à la plus récente)
* 🧑‍🔬 Prise en charge de Knitr pour le code R dans les documents LaTeX

### Utilisation avec Ayakaleaf Pro

TeX Live Full par Ayaka-notes est spécialement conçue pour [ayakaleaf-pro](https://github.com/ayaka-notes/ayakaleaf-pro) ; si vous êtes [utilisateur du toolkit](https://github.com/overleaf/toolkit), vous pouvez ajouter les variables d'environnement suivantes au fichier `config/variables.env`.

Par exemple :

```dotenv title="config/variables.env" wrap
ALL_TEX_LIVE_DOCKER_IMAGES=ghcr.io/ayaka-notes/texlive-full:2026.1, ghcr.io/ayaka-notes/texlive-full:2025.1
ALL_TEX_LIVE_DOCKER_IMAGE_NAMES=Texlive 2026, Texlive 2025
TEX_LIVE_DOCKER_IMAGE=ghcr.io/ayaka-notes/texlive-full:2026.1
```

### Versions de TeX Live

Grâce à GitHub Action, nous pouvons construire toutes les images TeX en parallèle, notamment :

* `ghcr.io/ayaka-notes/texlive-full:2026.1` (également le tag `latest`)
* `ghcr.io/ayaka-notes/texlive-full:2025.1`
* `ghcr.io/ayaka-notes/texlive-full:2024.1`
* `ghcr.io/ayaka-notes/texlive-full:2023.1`
* `ghcr.io/ayaka-notes/texlive-full:2022.1`
* `ghcr.io/ayaka-notes/texlive-full:2021.1`
* `ghcr.io/ayaka-notes/texlive-full:2020.1`
* `ghcr.io/ayaka-notes/texlive-full:base`

Nous utilisons l'archive miroir de [texlive info](https://texlive.info/tlnet-archive/), qui contient presque toutes les versions de TeX Live de 1996 à 2025. Et grâce au Dockerfile d'Overleaf, nous pouvons construire ce projet plus rapidement.

> Pourquoi TeX Live 2019 et les versions antérieures ne sont-elles pas prises en charge ?
>
> La maintenance de ces anciennes images est extrêmement difficile. De plus, le site [texlive.info](https://texlive.info/) ne fournit pas d'informations sur les versions de TeX Live publiées avant 2019 ; nous ne pouvons donc pas construire d'images pour ces versions. Si vous avez besoin d'une ancienne version précise, veuillez ouvrir une issue pour nous en informer.

### Problèmes

<Accordion title="Problème 01 : absence de police dans le cache">

Lorsqu'Overleaf compile un projet LaTeX et qu'une police est introuvable, **vous constaterez peut-être que la compilation prend beaucoup de temps** : en effet, lorsqu'une police manque, TeX Live tente de **reconstruire l'intégralité du cache des polices**. C'est un processus long.

Dans notre image, le cache des polices est préconstruit ; nous avons corrigé ce problème avec [ce commit](https://github.com/ayaka-notes/texlive-full/commit/0cb66b0dc8b82be628cf6999cfd659d9784e132f)

</Accordion>

<Accordion title="Problème 02 : SyncTeX extrêmement lent">

Lorsque vous utilisez cette image avec sharelatex, vous constaterez peut-être que SyncTeX est extrêmement lent.

Voir : [https://github.com/overleaf/overleaf/issues/1150](https://github.com/overleaf/overleaf/issues/1150) ; il suffit de désactiver HTTP 2.0.

</Accordion>

<Accordion title="Problème 03 : erreur de recompilation avec l'image TeX Live officielle">

Si vous utilisez l'image TeX Live officielle de Docker Hub `texlive/texlive`, vous constaterez peut-être qu'une erreur est signalée lorsque vous recompilez un projet. Ce problème est corrigé dans notre image, car nous utilisons la dernière image de base Ubuntu et installons toutes les dépendances depuis le dépôt officiel d'Ubuntu.

</Accordion>

### Autres remarques techniques

Lors de la construction d'images TeX Live (antérieures à 2019), vous devrez peut-être prêter attention aux problèmes suivants :

* Seuls `http`/`ftp` sont pris en charge avant TeX Live 2017 ; vous ne pouvez donc pas utiliser `https` pour le téléchargement, à moins de modifier le script `peal`.
* Avant 2015, seul un fichier sha256 est fourni. Vous ne pouvez donc pas utiliser sha512 pour la vérification.
