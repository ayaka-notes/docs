## Outils de développement recommandés {#develop-tools-recommended}

Ces services optionnels ne sont pas nécessaires pour faire fonctionner Overleaf, mais ils aident beaucoup pour développer, déboguer et examiner les données. Tous font partie de l'environnement de développement : il n'y a rien à ajouter à `docker-compose.yml`. Une fois connecté au site, le menu **Dev tools** de sa barre de navigation renvoie vers ceux que le site sert sur ses propres chemins.

| Outil | Adresse | Défini dans |
| --- | --- | --- |
| **Grafana**, l'état, les métriques et les logs de chaque service | [http://localhost/grafana/](http://localhost/grafana/) | `develop/grafana/docker-compose.yml`, actif quand `GRAFANA_ENABLED=true` dans `develop/dev.rc` (par défaut) |
| **Mailpit**, une boîte de réception pour chaque e-mail envoyé par le site | [http://localhost/mailpit/](http://localhost/mailpit/) | `develop/mail/docker-compose.yml`, actif quand `MAILPIT_ENABLED=true` (par défaut) |
| **Mongo Express**, une interface pour MongoDB | [http://localhost/mongo-express/](http://localhost/mongo-express/) | `develop/docker-compose.yml`, toujours actif |
| **RedisInsight**, une interface pour les données Redis | [http://localhost/redis-insight/](http://localhost/redis-insight/) | `develop/docker-compose.yml`, toujours actif |
| **Hoppscotch**, un client d'API dans le navigateur, similaire à Postman | [http://localhost:9170](http://localhost:9170/) (`HOPPSCOTCH_PORT`) | `develop/hoppscotch/docker-compose.yml`, actif quand `HOPPSCOTCH_ENABLED=true` (par défaut) |

<Warning>

Aucun de ces outils n'a de connexion : les utilisateurs anonymes de Grafana en sont les administrateurs, et Mongo Express peut modifier n'importe quel document. Le site, Hoppscotch, Mongo Express (8081) et RedisInsight (5540) n'écoutent que sur `127.0.0.1` de l'hôte, donc les autres hôtes ne peuvent pas les atteindre.

</Warning>

### Grafana {#grafana}

Grafana est servi par le site sur `/grafana/`, via webpack-dev-server, il n'a donc pas besoin de port propre. Son dossier **Overleaf Develop** contient ces tableaux de bord :

| Tableau de bord | Ce qu'il montre |
| --- | --- |
| All services (accueil) | État de chaque service, jauges de l'hôte, charge et logs. Un clic sur un service ouvre son tableau de bord |
| Server | CPU, charge, mémoire, disque et réseau de l'hôte, ainsi que les compilations de clsi |
| Errors | Logs d'erreurs, réponses 5xx et 4xx, messages d'erreur les plus fréquents et routes en échec |
| Data flow | Le chemin d'une modification : document-updater et Redis, project-history, history-v1, Mongo, stockage objet |
| Containers | État de chaque conteneur, CPU, mémoire, réseau et disque, compilations en sandbox comprises |
| Un par service | Les services Node.js, git-bridge (JVM), mongo et redis |

Prometheus collecte `/metrics` des services, `mongodb-exporter`, `redis-exporter`, `cadvisor` et `node-exporter` ; Alloy envoie les logs de chaque conteneur du projet à Loki, où les filtres **Log search**, **Service** et **Log level** des tableaux de bord les lisent. Leurs données ne vivent que dans les conteneurs, donc les recréer les vide. cAdvisor s'exécute en mode privilégié et lit `/`, `/sys`, les données Docker et le socket containerd de l'hôte, en lecture seule ; node-exporter lit `/` de l'hôte.

Les tableaux de bord sont générés : modifiez `develop/grafana/make-dashboards` et exécutez-le, au lieu de modifier les fichiers JSON.

### Mailpit {#mailpit}

Avec `MAILPIT_ENABLED=true`, `web` envoie chaque e-mail à Mailpit au lieu d'un vrai serveur de messagerie, et la confirmation d'e-mail est activée (`EMAIL_CONFIRMATION_DISABLED=false`). Les liens d'activation, invitations de projet, réinitialisations de mot de passe et codes de confirmation peuvent alors être suivis depuis la boîte de réception.

### Configurer Hoppscotch {#setup-hoppscotch}

#### Requêtes API via le proxy {#proxy-api-request}

Hoppscotch envoie les requêtes depuis le navigateur, qui ne peut pas joindre les services par leurs noms Docker. Son proxy, Proxyscotch, s'exécute dans le réseau Docker et est servi sur `/proxy` de l'adresse de Hoppscotch. Ouvrez [http://localhost:9170](http://localhost:9170/), allez dans Settings → Interceptor, choisissez **Proxy** et définissez la Proxy URL sur `http://localhost:9170/proxy`. Le réglage reste dans le navigateur.

#### Importer les API des services {#import-the-service-apis}

`develop/hoppscotch/openapi/` contient un fichier OpenAPI pour l'API interne de chaque service. Dans Hoppscotch, ouvrez Collections → Import → Import from File et sélectionnez tous les fichiers en une fois. Chaque fichier devient une collection dont les requêtes vont à l'adresse Docker du service. Les mêmes fichiers sont présentés dans la section [API des services](/fr/dev/service-api/overview).

#### Problèmes de CSRF {#csrf-problems}

<Warning>

Si vous utilisez Postman ou d'autres outils de débogage pour générer une requête **POST**, vous constaterez peut-être que la connexion est **refusée**, avec une erreur 403. Cela s'explique par le fait qu'Overleaf est protégé par une vérification **CSRF**.

</Warning>

<Frame>
  <img src="/images/dev/image-8.png" alt="" />
</Frame>

Dans votre console, vous verrez peut-être :

<Frame>
  <img src="/images/dev/image-9.png" alt="" />
</Frame>

Pour gérer cela dans votre développement Overleaf, vous devez configurer votre jeton CSRF. Voici le tutoriel détaillé.

<Steps>
<Step title="Ajouter un script de pré-requête">
Ajoutez le code suivant dans Pre-Request

<Frame>
  <img src="/images/dev/image-10.png" alt="" />
</Frame>

Voici le script :

```js wrap
pm.sendRequest("http://web:3000/dev/csrf", function (err, res) {
    if (err) {
        console.log(err);
        return;
    }

    // 1) Save CSRF token (/dev/csrf)
    const token = res.text().trim();
    pw.env.set("csrftoken", token);
    console.log("csrftoken =", token);

    const setCookieHeader = (res.headers || []).find(h => h.key?.toLowerCase() === "set-cookie")?.value;
    console.log("set-cookie =", setCookieHeader);

    if (!setCookieHeader) return;

    const cookiePair = setCookieHeader.split(";")[0].trim(); // overleaf.sid=...
    pw.env.set("cookie_header", cookiePair);
    console.log("cookie_header =", cookiePair);
});
```
</Step>

<Step title="Ajouter les en-têtes de requête">
Vous devez ajouter les en-têtes suivants :

| Nom de l'en-tête | Valeur de l'en-tête |
| ---------------- | ------------------- |
| Content-Type     | `application/json`  |
| X-Csrf-Token     | `<<csrftoken>>`     |
| Cookie           | `<<cookie_header>>` |

<Frame>
  <img src="/images/dev/image-11.png" alt="" />
</Frame>
</Step>

<Step title="Se connecter avec les outils d'API">
Vous pouvez maintenant vous connecter avec votre nom d'utilisateur et votre mot de passe.

```json5
{
  "_csrf": "<<csrftoken>>",
  "email": "admin@overleaf.com",
  "password": "xxxxxx"
}
```

Voici la réponse obtenue lorsque vous saisissez un nom d'utilisateur ou un mot de passe incorrect.

</Step>
