---
title: Mettre à jour les traductions i18n
icon: language
---

Le frontend ne charge que les clés de traduction listées dans `services/web/frontend/extracted-translations.json` (`services/web/frontend/translations-loader.js`). Le backend et ses templates lisent les fichiers complets de `services/web/locales/`.

Exécutez ceci dans le répertoire `develop` une fois après la première installation, puis à nouveau après avoir ajouté une traduction ou changé de branche :

```bash
bin/i18n
```

`bin/i18n` fait deux choses :

1. Il réinitialise `services/web/locales/*.json` aux fichiers commités, puis applique les correctifs de locales comme le font les builds d'image : les fichiers du dossier `locales_patches/v*` le plus élevé remplacent les locales, et `locales_patches/added/*.json` sont fusionnés par-dessus, clé par clé.
2. Il exécute `yarn run extract-translations` en tant qu'utilisateur `node` dans le conteneur `webpack`, ce qui réécrit `extracted-translations.json`. Si l'image webpack est absente, il synchronise d'abord `yarn.lock` avec `bin/sync` et construit l'image.

Il nécessite `jq` sur l'hôte.

<Warning>

Les modifications que `bin/i18n` apporte à `services/web/locales/*.json` sont uniquement locales. Ne les commitez pas.

</Warning>

Réutilisez une clé existante chaque fois que possible. Les fichiers de locales proviennent d'Overleaf en amont ou d'un site de traduction tiers, donc ne les modifiez pas directement. Une nouvelle clé va dans `services/web/locales/locales_patches/added/`, dans le fichier de chaque langue à la fois (`en.json`, `zh-CN.json` et les autres).
