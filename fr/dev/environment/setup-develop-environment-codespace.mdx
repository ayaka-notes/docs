Pour gagner du temps et mettre en place rapidement l'environnement de développement, nous proposons une autre version de la configuration de l'environnement de développement : GitHub Codespace.

## Tutoriel de configuration {#configuration-tutorial}

<Steps>
<Step title="Créer un Codespace">
Cliquez sur le bouton suivant pour créer un Codespace dans le cloud pour le développement de server-pro.

[![Open in GitHub Codespaces](https://github.com/codespaces/badge.svg)](https://codespaces.new/ayaka-notes/ayakaleaf-pro)

Il est recommandé de choisir un **type de machine** d'au moins **4 cœurs**. Pour un type de machine plus puissant, vous pouvez en faire la demande auprès de l'équipe de support officielle de GitHub en ouvrant un ticket [ici](https://support.github.com/contact?tags=rr-codespaces%2Ccat_codespaces).

<Frame>
  <img src="/images/dev/image.png" alt="" />
</Frame>
</Step>

<Step title="Lancer le script de configuration">
Vous devrez patienter le temps que le Codespace soit créé. Une fois que vous avez accès à votre terminal, exécutez la commande suivante :

```text
cd develop/
bin/setup
bin/i18n
```

`bin/setup` récupère les images et démarre les services ; `bin/i18n` applique ensuite les traductions des modules d'Ayakaleaf Pro, que les fichiers de locales commités ne contiennent pas, voir [Mettre à jour les traductions i18n](/fr/dev/environment/update-i18n-translations).

<Frame>
  <img src="/images/dev/image-1.png" alt="" />
</Frame>

<Warning>

Ce script (`bin/setup`) vous permet de configurer l'environnement de développement sur le dernier commit de la branche `server-pro` en un minimum de temps. Il peut ne pas convenir aux versions plus anciennes ou aux autres branches.

Nous construisons chaque jour l'image Docker de développement avec [GitHub Action](https://github.com/ayaka-notes/ayakaleaf-pro/actions).

</Warning>
</Step>

<Step title="Accéder à votre Launchpad">
Passez à l'onglet des ports : vous verrez une liste des ports web disponibles. Cliquez sur celui avec `80` (le `OVERLEAF_PORT` de `develop/dev.rc`). Vous devriez maintenant voir la page launchpad. Mailpit, Grafana, Mongo Express et RedisInsight sont sur des chemins du même port (`/mailpit/`, `/grafana/`, `/mongo-express/` et `/redis-insight/`), et le menu **Dev tools** du site y renvoie une fois connecté. La console RustFS est sur 9001 et Hoppscotch sur 9170, voir [Ports](/fr/dev/environment/setup-develop-environment-local#ports).

<Step title="Bon développement">
C'est maintenant à vous de jouer ! Commencez à développer votre super fonctionnalité. `bin/setup` démarre déjà chaque service en mode développement (`node --watch`, comme `bin/dev`), donc les modifications du code apparaissent sans autre commande.

Après avoir modifié `develop/dev.rc`, relancez `bin/setup` : il passe par `bin/docker-compose`, qui ajoute les fichiers des fonctionnalités activées.

<Warning>

Ne démarrez pas les services à la main avec `docker compose -f docker-compose.yml -f docker-compose.dev.yml -f docker-compose.image.yml up`. Cette commande ignore les fichiers de fonctionnalités de `dev.rc`, donc `web`, `filestore` et `history-v1` sont recréés sans les paramètres RustFS et se rabattent sur des volumes locaux, où l'historique et les fichiers binaires de vos projets sont absents.

</Warning>
</Step>
</Steps>
