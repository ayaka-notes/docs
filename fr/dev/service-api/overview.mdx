Overleaf fonctionne comme plusieurs services qui s'appellent mutuellement en HTTP dans le réseau Docker. Les pages de cette section décrivent ces API internes. Elles proviennent des fichiers OpenAPI de [`develop/hoppscotch/openapi/`](https://github.com/ayaka-notes/ayakaleaf-pro/tree/server-pro/develop/hoppscotch/openapi), rédigés à partir du code de chaque service.

Aucune de ces API n'est publique : elles ne sont accessibles que dans le réseau Docker, et la plupart n'ont pas d'authentification.

## Services {#services}

| Service | Adresse | Rôle |
| ------------------------------------------------- | ----------------------------------- | ------------------------------------------------------------------------------------------------ |
| [web](/fr/dev/service-api/web)                                     | `http://web:3000`                   | L'application principale. Son API privée est appelée par les autres services et par les scripts cron de l'image  |
| [document-updater](/fr/dev/service-api/document-updater)           | `http://document-updater:3003`      | Conserve dans Redis les documents ouverts dans l'éditeur, applique les modifications et les réécrit dans Mongo         |
| [docstore](/fr/dev/service-api/docstore)                           | `http://docstore:3016`              | Stocke chaque document de chaque projet dans la collection Mongo `docs`                                 |
| [real-time](/fr/dev/service-api/real-time)                         | `http://real-time:3026`             | Gère les connexions socket.io de l'éditeur et relaie les modifications entre navigateurs et services          |
| [chat](/fr/dev/service-api/chat)                                   | `http://chat:3010`                  | Stocke le chat du projet et les fils de commentaires                                                  |
| [project-history](/fr/dev/service-api/project-history)             | `http://project-history:3054`       | Transforme les modifications en file d'attente en modifications d'historique et les envoie à history-v1 ; conserve les étiquettes               |
| [history-v1](/fr/dev/service-api/history-v1)                       | `http://history-v1:3100`            | Stocke l'historique complet de chaque projet et le contenu des fichiers sous forme de blobs                           |
| [filestore](/fr/dev/service-api/filestore)                         | `http://filestore:3009`             | Sert les fichiers de modèles et, en lecture seule, les blobs écrits par history-v1                           |
| [clsi](/fr/dev/service-api/clsi)                                   | `http://clsi:3013`                  | Compile les projets, exécute SyncTeX et le comptage de mots, convertit des documents                              |
| [notifications](/fr/dev/service-api/notifications)                 | `http://notifications:3042`         | Stocke les notifications affichées dans la liste des projets                                               |
| [linked-url-proxy](/fr/dev/service-api/linked-url-proxy)           | `http://linked-url-proxy:3066`      | Récupère des URL externes pour web et refuse les adresses internes                                     |
| [third-party-datastore](/fr/dev/service-api/third-party-datastore) | `http://third-party-datastore:3002` | Synchronise les projets avec Dropbox via une file de tâches par utilisateur                                       |

## Authentification {#authentication}

* <strong>web :</strong> authentification HTTP basique avec `WEB_API_USER` et `WEB_API_PASSWORD`. Les routes git-bridge utilisent à la place un jeton d'accès personnel.
* <strong>history-v1 :</strong> authentification HTTP basique en tant que `staging` avec `STAGING_PASSWORD`, ou un JWT.
* <strong>Tous les autres services :</strong> aucune.

## Les essayer {#try-them}

L'environnement de développement exécute [Hoppscotch](https://github.com/hoppscotch/hoppscotch) sur `http://localhost:9170`, avec un proxy qui atteint les services par leurs adresses Docker. Son [README](https://github.com/ayaka-notes/ayakaleaf-pro/blob/server-pro/develop/README.md#hoppscotch) explique comment configurer le proxy et importer les fichiers OpenAPI.
