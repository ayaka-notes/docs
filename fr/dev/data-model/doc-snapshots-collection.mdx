`docSnapshots` contient des copies d’un doc que document-updater prend juste avant une modification qui réduit des commentaires ou des modifications suivies. Seul document-updater l’écrit, dans `services/document-updater/app/js/SnapshotManager.js`. Web possède un modèle Mongoose dans `services/web/app/src/models/DocSnapshot.mjs`, mais aucun code ne l’utilise.

#### Champs {#fields}

| Champ | Type | Signification | Source |
| ----- | ---- | ------- | ------ |
| `_id` | ObjectId | Identifiant de l’instantané. | `SnapshotManager.js:24` |
| `project_id` | ObjectId | Projet. | `SnapshotManager.js:19,26`, `DocSnapshot.mjs:7` |
| `doc_id` | ObjectId | Le doc (`docs._id`). | `SnapshotManager.js:20,27`, `DocSnapshot.mjs:8` |
| `version` | Number | Version OT du doc avant la modification. | `SnapshotManager.js:28`, `services/document-updater/app/js/UpdateManager.js:132,264-271`, `DocSnapshot.mjs:9` |
| `lines` | Array of String | Contenu du doc avant la modification. | `SnapshotManager.js:29`, `DocSnapshot.mjs:10` |
| `pathname` | String | Chemin du doc dans le projet à ce moment-là. | `SnapshotManager.js:30`, `DocSnapshot.mjs:11` |
| `ranges` | Mixed | `comments` et `changes` avant la modification, avec la même forme que `docs.ranges` (voir [docs](/fr/dev/data-model/docs-collection)). `id`, `op.t` et `metadata.user_id` sont convertis en ObjectIds et `metadata.ts` en Dates. | `SnapshotManager.js:31,41-68`, `DocSnapshot.mjs:12` |
| `ts` | Date | Date de l’instantané. L’index TTL supprime l’instantané 30 jours plus tard. | `SnapshotManager.js:32`, `DocSnapshot.mjs:13` |

#### Qui l’écrit {#who-writes-it}

| Code | Ce qu’il fait |
| ---- | ------------ |
| `UpdateManager.js:248-271` | Après avoir appliqué une modification, document-updater enregistre le doc tel qu’il était avant la modification lorsque celle-ci a réduit des plages : davantage de plages sont devenues vides, ou plus d’une plage a été supprimée (`services/document-updater/app/js/RangesManager.js:104-106`). |
| `SnapshotManager.js:17-36` `recordSnapshot` | Insère l’instantané. |

#### Qui la lit {#who-reads-it}

Aucun code ne la lit. Le modèle web est défini mais n’est utilisé nulle part.

#### Remarques {#notes}

* Seules les modifications qui passent par `UpdateManager.applyUpdate` créent des instantanés. Celles traitées par `HistoryOTUpdateManager` n’en créent pas (`UpdateManager.js:74-77`).
* Il n’y a pas d’index sur `doc_id`. Cherchez les instantanés d’un doc par `project_id` et `ts`, puis filtrez sur `doc_id`.
