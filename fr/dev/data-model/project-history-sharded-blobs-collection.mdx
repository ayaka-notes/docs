---
title: Collection Project History Sharded Blobs
icon: cubes-stacked
---

`projectHistoryShardedBlobs` contient les enregistrements de blobs qui ne tiennent pas dans [projectHistoryBlobs](/dev/data-model/project-history-blobs-collection) : lorsque le compartiment d’un préfixe de hash y contient déjà 8 enregistrements, les suivants vont ici. Un projet y a au plus 16 documents, un par premier chiffre hexadécimal du hash. Il n’y a pas de schéma Mongoose ; history-v1 l’écrit dans `services/history-v1/storage/lib/blob_store/mongo.js` (structure décrite à `mongo.js:1-16`).

#### Champs {#fields}

| Champ | Type | Signification | Source |
| ----- | ---- | ------- | ------ |
| `_id` | Binary | 13 octets : l’identifiant d’historique du projet, un `0`, et le chiffre de shard, lu en hexadécimal (`<history id>0<digit>`). Le chiffre de shard est le premier chiffre hexadécimal du hash. | `mongo.js:439-453` |
| `blobs` | Object | Enregistrements de blobs regroupés en compartiments. La clé d’un compartiment correspond aux chiffres hexadécimaux 2 à 4 du hash. | `mongo.js:439-443` |
| `blobs.<bcd>` | Array of Object | Les enregistrements du compartiment. Le code ne limite pas sa taille. | `mongo.js:399-407` |
| `blobs.<bcd>[].h` | Binary | Le hash, 20 octets, comme dans projectHistoryBlobs. | `mongo.js:472` |
| `blobs.<bcd>[].b` | Number | Longueur du contenu en octets. | `mongo.js:473` |
| `blobs.<bcd>[].s` | Number | Longueur du contenu en tant que texte ; `null` lorsque le contenu n’est pas du texte modifiable. | `mongo.js:474` |

#### Qui l’écrit {#who-writes-it}

| Code | Ce qu’il fait |
| ---- | ------------ |
| `services/history-v1/storage/lib/blob_store/mongo.js:399-407` | `insertRecordSharded` : upsert avec `$addToSet` dans le compartiment. Appelé par `insertBlob` lorsque le compartiment de projectHistoryBlobs est plein (`mongo.js:387-389`). |
| `mongo.js:75-103` | `clone` : copie les shards du projet vers un autre identifiant d’historique, pour history-v1 `POST /projects/:project_id/clone`, que rien dans web n’appelle. |
| `mongo.js:413-422` | `deleteBlobs` : supprime tous les shards du projet avec son document projectHistoryBlobs, lors de history-v1 `DELETE /projects/:project_id`. |

#### Qui la lit {#who-reads-it}

| Code | Ce qu’il fait |
| ---- | ------------ |
| `mongo.js:144-157` | `findBlobSharded` : un blob, recherché uniquement lorsque son compartiment dans projectHistoryBlobs contient 8 enregistrements et ne le contient pas (`mongo.js:127-131`). |
| `mongo.js:217-260` | `findBlobsSharded` : les blobs que `findBlobs` n’a pas trouvés dans projectHistoryBlobs (`mongo.js:202-206`). |
| `mongo.js:285-306` | `getProjectBlobs` : tous les shards d’un projet. |
| `mongo.js:337-361` | `getProjectBlobsBatch` : tous les shards de plusieurs projets, pour la route des statistiques de blobs. |

#### Index {#indexes}

Uniquement l’index par défaut `_id`. Aucune migration de `tools/migrations/` n’en ajoute.

#### Remarques {#notes}

* Les shards d’un projet sont côte à côte dans l’ordre de `_id`, donc le code les trouve avec une plage `_id` de `<history id>00` à `<history id>0f` (`mongo.js:75-80`, `287-295`).
* La collection n’apparaît qu’une fois qu’un projet a plus de 8 blobs avec le même préfixe de hash à 3 chiffres ; une petite instance peut donc ne pas l’avoir du tout.
