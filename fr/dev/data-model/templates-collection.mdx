`templates` contient un document par modèle de la galerie de modèles. Les fichiers d’un modèle (le zip du projet et le PDF) ne sont pas ici : ils sont conservés dans filestore sous `template/<_id>/v/<version>/`. La collection appartient au module web `template-gallery` (`services/web/modules/template-gallery`). Le schéma est le modèle Mongoose `Template` dans `services/web/modules/template-gallery/app/src/models/Template.mjs` ; la logique se trouve dans `services/web/modules/template-gallery/app/src/TemplateGalleryManager.mjs` et dans `TemplateGalleryHelper.mjs` à côté.

#### Qui écrit {#who-writes-it}

| Code | Rôle |
| ---- | ------------ |
| `TemplateGalleryManager.mjs:53-97` (`createTemplateFromProject`) | `POST /template/new/:Project_id`. Copie les paramètres du projet (`TemplateGalleryHelper.mjs:94-134`), téléverse le zip et le PDF dans filestore, puis enregistre. Si le nom est pris, répond par un conflit, sauf si le client a demandé l’écrasement : il met alors à jour ce modèle et augmente sa `version`, puis supprime les fichiers de la version précédente. |
| `TemplateGalleryManager.mjs:21-47` (`editTemplate`) | `POST /template/:template_id/edit`. Affecte les champs envoyés au document, régénère `description` et `author`, et définit `lastUpdated`. Le formulaire d’édition envoie les champs modifiés parmi `name`, `license`, `category`, `language`, `authorMD` et `descriptionMD` (`services/web/modules/template-gallery/frontend/js/pages/template/util/api.ts:22-29`). |
| `TemplateGalleryHelper.mjs:186-222` (`deleteTemplateAssets`) | `DELETE /template/:template_id/delete` supprime le document et les fichiers de la version donnée (`TemplateGalleryManager.mjs:49-51`). |

Seuls les admins du site et l’utilisateur de `OVERLEAF_TEMPLATES_USER_ID` peuvent appeler ces trois routes (`services/web/modules/template-gallery/app/src/Router.mjs:55-62,70-84`, `PermissionsMiddleware.mjs:8-19`).

#### Index {#indexes}

| Nom | Clés | Options | Migration |
| ---- | ---- | ------- | --------- |
| `_id_` | `_id: 1` | | par défaut |

`autoIndex` de Mongoose est désactivé (`services/web/app/src/infrastructure/Mongoose.mjs:7`). `tools/migrations/20190912145030_create_templates_indexes.mjs` (`project_id`, `user_id`, `name` uniques) est marquée `server-pro` et `saas` ; elle ne s’exécute donc pas dans CE, qui n’exécute que les migrations `server-ce` (`server-ce/init_scripts/900_run_web_migrations.sh`).

#### Remarques {#notes}

* L’amont considère `templates` comme une collection obsolète et la supprime sur son propre site (`tools/migrations/20241002180623_drop_unused_collections.mjs`, marquée `saas`). Dans Ayakaleaf Pro, le module de galerie de modèles l’utilise.
* Le tri par nom utilise une collation insensible à la casse, et le commentaire de `TemplateGalleryManager.mjs:186-188` note qu’un index `name` aurait besoin de la même. CE n’a pas d’index `name`, donc Mongo trie en mémoire.
* Supprimer le projet source ou le propriétaire ne supprime pas le modèle.
