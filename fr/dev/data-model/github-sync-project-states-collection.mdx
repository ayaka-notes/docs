`githubSyncProjectStates` contient un document par projet lié à un dépôt GitHub : quel dépôt, et où la dernière synchronisation s'est arrêtée. La collection appartient au module web `github-sync` (`services/web/modules/github-sync`). Le schéma se trouve dans `services/web/modules/github-sync/app/models/githubSyncProjectStates.mjs`, et tout accès passe par `services/web/modules/github-sync/app/src/SyncStateManager.mjs`.

#### Qui l'écrit {#who-writes-it}

| Code | Ce qu'il fait |
| ---- | ------------- |
| `SyncStateManager.mjs:9-14` (`createProjectState`) | Crée le document : après l'import d'un dépôt comme nouveau projet (`services/web/modules/github-sync/app/src/GitHubSyncHandler.mjs:175-181`), ou après l'export d'un projet vers un nouveau dépôt (`GitHubSyncHandler.mjs:235-241`, propriétaire uniquement, refusé si déjà lié). |
| `SyncStateManager.mjs:16-21` (`updateProjectState`) | `$set` des champs modifiés. `getMergeOverview` définit `mergeStatus: 'diverged'` lorsque la branche synchronisée ne repose plus sur `lastSyncCommit` : la comparaison de GitHub répond `diverged` ou `behind` (`GitHubApiClient.mjs:382-400`), ou le commit a disparu et l'utilisateur peut pousser (`GitHubSyncHandler.mjs:123,126-137`). Une synchronisation (`services/web/modules/github-sync/app/src/GitMerge.mjs`) avance `lastSyncCommit`/`lastSyncVersion` en cas de succès (par exemple `:143,173,224`), enregistre un conflit avec `unmergedBranchName`, `unmergedBranchHead` et `conflictVersion` (`:207-213`), et les efface une fois le conflit résolu (`:250-257`). |
| `SyncStateManager.mjs:23-25` (`removeProjectState`) | Supprime le document quand le propriétaire délie le projet (`GitHubSyncHandler.mjs:83-97`) et quand un projet supprimé expire (`services/web/modules/github-sync/index.mjs:56-58`). |

#### Qui la lit {#who-reads-it}

| Code | Ce qu'il fait |
| ---- | ------------- |
| `GitHubSyncHandler.mjs:39-60` (`getProjectState`) | Fournit à l'éditeur `mergeStatus`, `repoFullName` et `unmergedBranchName`. Sans document, il répond `need-export`, une valeur qui n'est jamais stockée. |
| `GitHubSyncHandler.mjs:110-143` (`getMergeOverview`) | Compare `lastSyncCommit` et `lastSyncVersion` avec GitHub et l'historique du projet pour lister les nouveaux commits. |
| `GitHubSyncHandler.mjs:200` (`exportProject`) | Refuse d'exporter un projet déjà lié. |
| `GitMerge.mjs:27` (`doGitMergeWithoutLock`) | Charge l'état au début d'une synchronisation. |

#### Index {#indexes}

| Nom | Clés | Options | Migration |
| --- | ---- | ------- | --------- |
| `_id_` | `_id: 1` | | default |

L'`autoIndex` de Mongoose est désactivé (`services/web/app/src/infrastructure/Mongoose.mjs:7`), donc le `unique: true` du schéma sur `projectId` ne crée rien. `tools/migrations/20190912145010_create_githubSyncProjectStates_indexes.mjs` (`project_id` et `owner_id` d'upstream) est étiquetée `saas` uniquement et ne s'exécute pas dans CE.

#### Remarques {#notes}

* Une synchronisation s'exécute sous le verrou `gitSync` du projet (`GitMerge.mjs:17-24`). GitLab Sync et Gitea Sync prennent le même verrou, donc une seule synchronisation s'exécute à la fois par projet.
* Un projet supprimé garde son document jusqu'à l'expiration du projet.
* Le jeton GitHub de l'utilisateur se trouve dans [GitHub Sync User Credentials](/fr/dev/data-model/github-sync-user-credentials-collection).
