---
title: Collection Project History Blobs
icon: cubes
---

`projectHistoryBlobs` contient un document par historique de projet : les métadonnées (hachage et tailles) de chaque blob que history-v1 a stocké pour ce projet. Un blob est le contenu d’un fichier ou d’un doc à un moment de son historique. Les octets eux-mêmes sont des objets dans le bucket des blobs de projet. Il n’y a pas de schéma Mongoose : history-v1 écrit la collection dans `services/history-v1/storage/lib/blob_store/mongo.js`, qu’il utilise pour les ids d’historique de 24 caractères hexadécimaux, comme dans CE (`services/history-v1/storage/lib/blob_store/index.js:108-116`).

#### Champs {#fields}

| Champ | Type | Signification | Source |
| ----- | ---- | ------- | ------ |
| `_id` | ObjectId | Id d’historique du projet, la valeur de `projects.overleaf.history.id`. | `mongo.js:37-40` |
| `blobs` | Object | Enregistrements de blobs regroupés en buckets. La clé d’un bucket est formée des 3 premiers chiffres hexadécimaux du hachage. | `mongo.js:39`, `429-431` |
| `blobs.<abc>` | Array of Object | Jusqu’à 8 enregistrements dont le hachage commence par `abc`. Quand un bucket en a déjà 8, l’enregistrement suivant va dans [Collection Project History Sharded Blobs](/fr/dev/data-model/project-history-sharded-blobs-collection). | `mongo.js:23`, `375-389` |
| `blobs.<abc>[].h` | Binary | Le hachage, 20 octets : SHA-1 de blob git, `sha1("blob " + byteLength + "\0" + content)` (`libraries/overleaf-editor-core/lib/blob_utils.js:36-43`). Sa forme hexadécimale est le hachage utilisé ailleurs, par exemple `fileRefs.hash` dans les projets. | `mongo.js:472` |
| `blobs.<abc>[].b` | Number | Longueur du contenu en octets. | `mongo.js:473` |
| `blobs.<abc>[].s` | Number | Longueur du contenu en tant que texte ; `null` quand le contenu n’est pas du texte modifiable (binaire, ou trop volumineux pour être modifié) (`blob_utils.js:116-130`). | `mongo.js:474` |

#### Qui écrit {#who-writes-it}

| Code | Rôle |
| ---- | ------------ |
| `services/history-v1/storage/lib/blob_store/mongo.js:34-47` | `initialize` : insère `{ _id, blobs: {} }` quand history-v1 crée l’historique du projet (`services/history-v1/storage/lib/chunk_store/index.js:67-68`). |
| `mongo.js:370-390` | `insertBlob` : `$addToSet` de l’enregistrement dans son bucket tant que le bucket a moins de 8 enregistrements, sinon dans la collection shardée. S’exécute après le téléversement des octets, depuis `putString`, `putBlob` et `copyBlob` (`blob_store/index.js:223-237`, `271-278`, `456-467`). |
| `mongo.js:54-105` | `clone` : copie les buckets vers un autre id d’historique, pour `POST /projects/:project_id/clone` de history-v1. Rien dans web n’appelle cette route (voir [Collection Project History Chunks](/fr/dev/data-model/project-history-chunks-collection)). |
| `mongo.js:413-422` | `deleteBlobs` : supprime le document et les documents shardés du projet, sur `DELETE /projects/:project_id` de history-v1 (`services/history-v1/api/controllers/projects.js:361-373`). |

D’où viennent les nouveaux blobs :

* Téléversements de fichiers : web envoie le fichier à `PUT /projects/:project_id/blobs/:hash` de history-v1 (`services/web/app/src/Features/History/HistoryManager.mjs:164-169`, `services/history-v1/api/controllers/projects.js:376-402`).
* Copies de projet : web demande à history-v1 de copier le blob de chaque fichier avec `POST /projects/:project_id/blobs/:hash?copyFrom=` (`services/web/app/src/Features/Project/ProjectDuplicator.mjs:333-338`, `HistoryManager.mjs:177-187`, `projects.js:521-555`).
* Texte des docs : quand history-v1 écrit un chunk, il stocke le texte de chaque doc, ainsi que ses commentaires et modifications suivies en JSON, sous forme de blobs (`chunk_store/index.js:402-405`, `libraries/overleaf-editor-core/lib/file_data/string_file_data.js:166-173`).

#### Index {#indexes}

Seulement l’index `_id` par défaut. Aucune migration de `tools/migrations/` n’en ajoute.

#### Remarques {#notes}

* Les octets d’un blob se trouvent à la clé `<project key>/<hash[0:2]>/<hash[2:]>` (`blob_store/index.js:51-53`) dans le bucket `OVERLEAF_EDITOR_PROJECT_BLOBS_BUCKET` (`services/history-v1/config/custom-environment-variables.json:49-52`). La clé de projet est l’id d’historique complété par des zéros, inversé et découpé en 3/3/reste caractères (`libraries/object-persistor/src/ProjectKey.js:8-15`).
* Un blob est stocké une fois par projet : l’insertion d’un hachage que le projet possède déjà est ignorée (`blob_store/index.js:227-230`, `249-252`).
* Le contenu vide n’a pas besoin d’enregistrement ; `getBlob` y répond sans recherche (`blob_store/index.js:378-380`).
* `projectHistoryGlobalBlobs` est lu au démarrage (`blob_store/index.js:138-148`), mais aucun code CE ne l’écrit ; dans CE, chaque blob est donc un blob de projet.
