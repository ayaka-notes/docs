`oauthAuthorizationCodes` est prévue pour les codes du flux OAuth authorization code : un document par code, qu'un client échange contre un jeton d'accès. Le schéma est `services/web/app/src/models/OauthAuthorizationCode.mjs`, et le module web `oauth2-server` contient le code qui y écrirait. Dans Ayakaleaf Pro, rien n'atteint ce code, donc la collection reste vide (voir Remarques).

#### Champs {#fields}

| Champ | Type | Signification | Source |
| ----- | ---- | ------- | ------ |
| `_id` | ObjectId | Identifiant du document. | `OauthAuthorizationCode.mjs:6` |
| `authorizationCode` | String | Le code lui-même, stocké tel quel (non haché). | `OauthAuthorizationCode.mjs:8`, `services/web/modules/oauth2-server/app/src/OAuth2Model.mjs:280` |
| `expiresAt` | Date | Fin de validité. `getAuthorizationCode` rejette un code après cette date, et l'index TTL le supprime. | `OauthAuthorizationCode.mjs:9`, `OAuth2Model.mjs:150-153,281` |
| `oauthApplication_id` | ObjectId | Client de [OAuth Applications](/fr/dev/data-model/oauth-applications-collection) qui a demandé le code. | `OauthAuthorizationCode.mjs:10`, `OAuth2Model.mjs:275-284` |
| `redirectUri` | String | URI de redirection de la requête. | `OauthAuthorizationCode.mjs:11`, `OAuth2Model.mjs:282` |
| `scope` | String | Scope demandé. | `OauthAuthorizationCode.mjs:12`, `OAuth2Model.mjs:283` |
| `user_id` | ObjectId | Utilisateur qui a accordé le code. | `OauthAuthorizationCode.mjs:13`, `OAuth2Model.mjs:285` |
| `codeChallenge`, `codeChallengeMethod` | String | Challenge PKCE et sa méthode. | `OauthAuthorizationCode.mjs:14-15`, `OAuth2Model.mjs:286-287` |

| `OAuth2Model.mjs:307-312` (`revokeAuthorizationCode`) | Supprime un code une fois utilisé. Jamais atteint. |

#### Index {#indexes}

| Nom | Clés | Options | Migration |
| ---- | ---- | ------- | --------- |
| `expiresAt_1` | `{ expiresAt: 1 }` | TTL, `expireAfterSeconds: 0`, partiel : `expiresAt` existe | `20230406125632_oauth_tokens_ttl.mjs` |

Les migrations se trouvent dans `tools/migrations/`. L'index unique `authorizationCode_1` provient uniquement des migrations marquées `saas` et `server-pro`, que Community Edition n'exécute pas.

#### Remarques {#notes}

* Les méthodes du modèle ci-dessus ne sont appelées que par les handlers authorize et token de `@node-oauth/oauth2-server`. Web n'utilise cette bibliothèque que pour vérifier les jetons bearer (`services/web/app/src/Features/Authentication/AuthenticationController.mjs:409-450`), et aucune route ne sert `/oauth/authorize` ni `/oauth/token`, donc aucun code n'est jamais écrit. Les jetons d'accès personnels sont créés directement, voir [OAuth Access Tokens](/fr/dev/data-model/oauth-access-tokens-collection).
