title: Collection GitHub Sync User Credentials
icon: key
---

`githubSyncUserCredentials` contient un document par utilisateur ayant lié un compte GitHub pour GitHub Sync. Elle stocke le jeton d'accès OAuth de l'utilisateur, chiffré. La collection appartient au module web `github-sync` (`services/web/modules/github-sync`). Le schéma se trouve dans `services/web/modules/github-sync/app/models/githubSyncUserCredentials.mjs`, et tout accès passe par `services/web/modules/github-sync/app/src/TokenManager.mjs`.

#### Champs {#fields}

| Champ | Type | Signification | Source |
| ----- | ---- | ------- | ------ |
| `_id` | ObjectId | Défini par Mongoose quand l'upsert insère. | |
| `userId` | ObjectId | L'utilisateur Overleaf. Obligatoire. Le schéma indique `unique: true`, mais aucun index n'est créé (voir Index) ; l'upsert par `userId` conserve un document par utilisateur. | `githubSyncUserCredentials.mjs:8`, `TokenManager.mjs:44-48` |
| `github` | String | Le jeton d'accès OAuth GitHub, chiffré avec `@overleaf/access-token-encryptor`. Le mot de passe vient de `GITHUB_TOKEN_CIPHER_PASSWORD` ; le libellé de chiffrement est `GITHUB_TOKEN_CIPHER_LABEL`, par défaut `2026.3-v3`. Obligatoire. | `githubSyncUserCredentials.mjs:9`, `TokenManager.mjs:12-25` |
| `__v` | Number | La clé de version Mongoose. Le schéma ne la désactive pas. | Valeur par défaut de Mongoose |

Seul le jeton d'accès est stocké : le callback OAuth conserve `access_token` de la réponse de GitHub (`services/web/modules/github-sync/app/src/GitHubApiClient.mjs:180-191`). Il n'y a ni jeton de rafraîchissement ni expiration.

#### Qui l'écrit {#who-writes-it}

| Code | Ce qu'il fait |
| ---- | ------------ |
| `TokenManager.mjs:42-58` (`saveUserToken`) | Fait un upsert du jeton chiffré de l'utilisateur. Quand l'utilisateur lie à nouveau son compte, le jeton remplacé est révoqué chez GitHub en arrière-plan. Appelé depuis le callback OAuth (`services/web/modules/github-sync/app/src/GitHubSyncController.mjs:146`). |
| `TokenManager.mjs:61-76` (`removeUserToken`) | Révoque le jeton chez GitHub (au mieux), puis supprime le document. Appelé lors de la dissociation (`GitHubSyncController.mjs:167`) et quand un utilisateur supprimé expire (`services/web/modules/github-sync/index.mjs:66-68`). |

#### Qui la lit {#who-reads-it}

| Code | Ce qu'il fait |
| ---- | ------------ |
| `TokenManager.mjs:36-40` (`getUserToken`) | Déchiffre le jeton pour chaque appel à l'API GitHub : `services/web/modules/github-sync/app/src/GitHubSyncHandler.mjs` (par exemple `:27`) et `services/web/modules/github-sync/app/src/GitMerge.mjs:43`. Sans document, ou avec un jeton impossible à déchiffrer, il lève `InvalidTokenError`, et l'utilisateur est considéré comme non lié (`GitHubSyncHandler.mjs:25-37`). |
| `services/web/modules/admin-tools/app/src/AdminUserListManager.mjs:393` | Vérifie si l'utilisateur a un document, pour les intégrations affichées dans le panneau d'administration. |

#### Index {#indexes}

| Nom | Clés | Options | Migration |
| ---- | ---- | ------- | --------- |
| `_id_` | `_id: 1` | | default |

L'`autoIndex` de Mongoose est désactivé (`services/web/app/src/infrastructure/Mongoose.mjs:7`), donc le `unique: true` du schéma sur `userId` ne crée rien. `tools/migrations/20190912145011_create_githubSyncUserCredentials_indexes.mjs` (`user_id` d'upstream) est étiquetée `saas` uniquement et ne s'exécute pas dans CE.

#### Remarques {#notes}

* Modifier `GITHUB_TOKEN_CIPHER_PASSWORD` rend les jetons stockés illisibles. Ces utilisateurs sont alors considérés comme non liés jusqu'à ce qu'ils lient à nouveau leur compte.
* Un utilisateur supprimé conserve le document jusqu'à son expiration.
