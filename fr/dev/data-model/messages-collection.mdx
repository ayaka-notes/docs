`messages` contient un document par message : une ligne du chat du projet, ou un commentaire ou une réponse dans un fil de commentaires de relecture. Seul le service chat l’écrit, dans `services/chat/app/js/Features/Messages/MessageManager.js`. Il n’y a pas de schéma Mongoose. Chaque message appartient à un salon de la collection [rooms](/fr/dev/data-model/rooms-collection).

#### Champs {#fields}

| Champ | Type | Signification | Source |
| ----- | ---- | ------- | ------ |
| `_id` | ObjectId | Identifiant du message. | `MessageManager.js:13-14` |
| `room_id` | ObjectId | Le salon (`rooms._id`), pas l’identifiant du projet ni celui du fil. | `MessageManager.js:8,106-108` |
| `user_id` | ObjectId | Auteur. | `MessageManager.js:9,103-105` |
| `content` | String | Texte du message, de 1 à 10240 caractères (`MAX_MESSAGE_LENGTH`). | `MessageManager.js:7`, `services/chat/app/js/Features/Messages/MessageHttpSchemas.js:3,12-15` |
| `timestamp` | Number | Date d’envoi, en millisecondes depuis 1970 (`Date.now()`), pas une Date. | `MessageManager.js:10`, `services/chat/app/js/Features/Messages/MessageHttpController.js:288` |
| `edited_at` | Number | Date de la dernière modification, en millisecondes (`Date.now()`). Absent si le message n’a jamais été modifié. | `MessageManager.js:65-69`, `MessageHttpController.js:189,213` |

#### Qui l’écrit {#who-writes-it}

| Code | Ce qu’il fait |
| ---- | ------------ |
| `MessageManager.js:5-16` `createMessage` | Insère un message (`MessageHttpController.js:275-294`). Web envoie les messages du chat du projet depuis `services/web/app/src/Features/Chat/ChatController.mjs:32`, et les commentaires depuis le module track-changes (`services/web/modules/track-changes/app/src/TrackChangesController.mjs:95`) et le module mcp-server (`services/web/modules/mcp-server/app/src/CommentTools.mjs:133`). |
| `MessageManager.js:51-72` `updateMessage` | Définit `content` et `edited_at`. Lorsqu’un identifiant d’utilisateur est fourni, seul le message de cet utilisateur correspond (`MessageManager.js:62-64`). Appelé depuis `ChatController.mjs:135` et `TrackChangesController.mjs:110`. |
| `MessageManager.js:74-80` `deleteMessage` | Supprime un message. Appelé depuis `ChatController.mjs:105` et `TrackChangesController.mjs:129`. |
| `MessageManager.js:39-49` `deleteAllMessagesInRoom(s)` | Supprime les messages d’un fil supprimé (`MessageHttpController.js:172-173`) ou de tout un projet lorsqu’un projet supprimé expire (`MessageHttpController.js:261-271`, appelé depuis `services/web/app/src/Features/Project/ProjectDeleter.mjs:391`). |
| `MessageManager.js:115-127` `duplicateRoomToOtherRoom` | Copie `content`, `timestamp` et `user_id` de chaque message dans un autre salon, sans `edited_at`. Utilisé lorsqu’une restauration de l’historique duplique un fil (`MessageHttpController.js:316-342`) et lorsqu’un projet est copié avec ses plages (`MessageHttpController.js:344-357`). |

#### Qui la lit {#who-reads-it}

| Code | Ce qu’il fait |
| ---- | ------------ |
| `MessageManager.js:18-29` `getMessages` | Du plus récent au plus ancien, au plus `limit` (50 par défaut) antérieurs à `before` (un `timestamp`). Utilisé pour le chat du projet (`ChatController.mjs:80`). |
| `MessageManager.js:31-37` `findAllMessagesInRooms` | Tous les messages de certains salons, pour la liste des fils du panneau de relecture (`TrackChangesController.mjs:82`), le module mcp-server (`CommentTools.mjs:83`) et la restauration de l’historique (`services/web/app/src/Features/History/RestoreManager.mjs:259`). Web vérifie aussi le premier message d’un fil pour qu’un relecteur ne puisse modifier que les fils qu’il a lancés (`services/web/app/src/Features/Authorization/AuthorizationManager.mjs:409-411`). |
| `MessageManager.js:90-100` `getMessage` | Un message. Web vérifie son `user_id` avant qu’un utilisateur modifie ou supprime son propre message (`services/web/app/src/Features/Authorization/AuthorizationMiddleware.mjs:253-257`, `TrackChangesController.mjs:124-125`). |

#### Remarques {#notes}

* Pour trouver les messages d’un commentaire, cherchez d’abord le salon par `project_id` et `thread_id`, puis interrogez `room_id`. L’identifiant du commentaire dans le doc est le `thread_id`, pas le `room_id`.
* Le texte visé par un commentaire est `op.c` dans `docs.ranges.comments` ; la discussion se trouve ici.
