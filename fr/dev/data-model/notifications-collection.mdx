`notifications` contient les avis affichés en haut du tableau de bord des projets d'un utilisateur. Un document correspond à un avis pour un utilisateur, identifié par sa `key`. Seul le service `notifications` accède à la collection (`services/notifications/app/js/Notifications.js`) ; `web` et `third-party-datastore` appellent son API HTTP. Il n'y a pas de schéma Mongoose.

#### Champs {#fields}

| Champ | Type | Signification | Source |
| --- | --- | --- | --- |
| `_id` | ObjectId | Id de l'avis. `web` marque un avis comme lu grâce à cet id. | `Notifications.js:58-65` |
| `user_id` | ObjectId | L'utilisateur qui voit l'avis. | `Notifications.js:26` |
| `key` | String | Identifie l'avis, par exemple `project-invite-<inviteId>`. L'upsert conserve un document par `user_id` et `key` ; il n'y a pas d'index unique. | `Notifications.js:27`, `:51-55` |
| `templateKey` | String | L'avis que le frontend affiche. Supprimé lorsque l'avis est lu ou ignoré ; le document reste. | `Notifications.js:29`, `:63`, `:72`, `:78` |
| `messageOpts` | Object | Valeurs du texte de l'avis, selon `templateKey` (pour une invitation à un projet : `userName`, `projectName`, `projectId`, `token`). Supprimé lorsque l'utilisateur ignore l'avis par son id. | `Notifications.js:28`, `:63` |
| `expires` | Date | Facultatif. L'index TTL supprime le document après cette date. | `Notifications.js:35-50` |

`NotificationsBuilder.mjs` construit aussi des clés pour les invitations de groupe, les affiliations institutionnelles, les abonnements et les anciens projets de débogage. Leurs appelants se trouvent dans le code des abonnements et des institutions, et la vérification des anciens projets de débogage ne s'exécute qu'avec `isSaas` (`services/web/app/src/Features/Project/ProjectListController.mjs:234-236`).

#### Remarques {#notes}

* Un avis lu n'est pas supprimé : seule `templateKey` disparaît. Comme le document contient toujours la clé, un `addNotification` ultérieur sans `forceCreate` pour la même clé ne fait rien (`Notifications.js:21-24`).
* Les routes `/key/:key` agissent sur la seule clé, pour tous les utilisateurs (`Notifications.js:76-100`).
* Si `web` n'a pas d'`apis.notifications.url`, il ne crée ni ne lit d'avis (`NotificationsHandler.mjs:17`, `:41`).
