---
title: Collection Gitea Sync User Credentials
icon: lock
---

`giteaSyncUserCredentials` contient un document par utilisateur ayant lié un compte Gitea pour Gitea Sync. Elle stocke les jetons OAuth de l'utilisateur, chiffrés. La collection appartient au module web `gitea-sync` (`services/web/modules/gitea-sync`). Le schéma se trouve dans `services/web/modules/gitea-sync/app/models/giteaSyncUserCredentials.mjs`, et tout accès passe par `services/web/modules/gitea-sync/app/src/TokenManager.mjs`.

#### Champs {#fields}

| Champ | Type | Signification | Source |
| ----- | ---- | ------- | ------ |
| `_id` | ObjectId | Défini par Mongoose quand l'upsert insère. | |
| `userId` | ObjectId | L'utilisateur Overleaf. Obligatoire. Le schéma indique `unique: true`, mais aucun index n'est créé (voir Index) ; l'upsert par `userId` conserve un document par utilisateur. | `giteaSyncUserCredentials.mjs:8`, `TokenManager.mjs:89-96` |
| `gitea` | String | Le JSON `{ accessToken, refreshToken, expiresAt }`, chiffré avec `@overleaf/access-token-encryptor`. `expiresAt` est en millisecondes depuis l'epoch, ou `null` ; `refreshToken` peut valoir `null`. Le mot de passe vient de `GITEA_TOKEN_CIPHER_PASSWORD` ; le libellé de chiffrement est `GITEA_TOKEN_CIPHER_LABEL`, par défaut `2026.10-v3`. Obligatoire. | `giteaSyncUserCredentials.mjs:9-10`, `TokenManager.mjs:17-30`, `services/web/modules/gitea-sync/app/src/GiteaApiClient.mjs:198-209` |
| `__v` | Number | La clé de version Mongoose. Le schéma ne la désactive pas. | Valeur par défaut de Mongoose |

#### Qui l'écrit {#who-writes-it}

| Code | Ce qu'il fait |
| ---- | ------------ |
| `TokenManager.mjs:89-96` (`saveUserToken`) | Fait un upsert des identifiants chiffrés de l'utilisateur. Appelé depuis le callback OAuth (`services/web/modules/gitea-sync/app/src/GiteaSyncController.mjs:146`). Contrairement à GitLab Sync, lier à nouveau le compte ne révoque pas le jeton remplacé. |
| `TokenManager.mjs:53-79` (`refreshUserToken`) | Quand le jeton d'accès est à moins de 5 minutes de `expiresAt` (`:12`), il obtient de nouveaux jetons avec le jeton de rafraîchissement et les enregistre (`:76`). Il s'exécute sous le verrou `giteaSyncToken` par utilisateur (`:14,54`), car Gitea remplace le jeton de rafraîchissement à son utilisation. |
| `TokenManager.mjs:100-102` (`removeUserToken`) | Supprime le document. Gitea n'a pas d'API pour révoquer un jeton OAuth, l'utilisateur révoque donc l'autorisation dans Gitea (`:98-99`). Appelé lors de la dissociation (`GiteaSyncController.mjs:173`) et quand un utilisateur supprimé expire (`services/web/modules/gitea-sync/index.mjs:56-58`). |

#### Qui la lit {#who-reads-it}

| Code | Ce qu'il fait |
| ---- | ------------ |
| `TokenManager.mjs:40-44,82-86` (`getUserCredentials`, `getUserToken`) | Déchiffre les identifiants pour chaque appel à l'API Gitea, en les rafraîchissant d'abord quand le jeton est sur le point d'expirer : `services/web/modules/gitea-sync/app/src/GiteaSyncHandler.mjs` (par exemple `:27`) et `services/web/modules/gitea-sync/app/src/GitMerge.mjs:52`. Sans document, ou avec des identifiants impossibles à déchiffrer ou à rafraîchir, il lève `InvalidTokenError`, et l'utilisateur est considéré comme non lié (`GiteaSyncHandler.mjs:25-37`). |
| `services/web/modules/admin-tools/app/src/AdminUserListManager.mjs:395` | Vérifie si l'utilisateur a un document, pour les intégrations affichées dans le panneau d'administration. |

#### Index {#indexes}

| Nom | Clés | Options | Migration |
| ---- | ---- | ------- | --------- |
| `_id_` | `_id: 1` | | default |

L'`autoIndex` de Mongoose est désactivé (`services/web/app/src/infrastructure/Mongoose.mjs:7`), donc le `unique: true` du schéma sur `userId` ne crée rien. Aucune migration ne crée d'index pour cette collection.

#### Remarques {#notes}

* Modifier `GITEA_TOKEN_CIPHER_PASSWORD` rend les identifiants stockés illisibles. Ces utilisateurs sont alors considérés comme non liés jusqu'à ce qu'ils lient à nouveau leur compte.
* Un utilisateur supprimé conserve le document jusqu'à son expiration.
