title: Collection Deleted Projects
icon: trash-can
---

`deletedProjects` conserve un projet après sa suppression : un document par projet supprimé, avec une copie du document de projet complet et l’auteur de la suppression. Web l’écrit dans `services/web/app/src/Features/Project/ProjectDeleter.mjs` ; le schéma est `services/web/app/src/models/DeletedProject.mjs`. Une fois le délai de suppression définitive écoulé, l’expiration détruit les données du projet et vide `project`, mais l’enregistrement avec `deleterData` reste.

Un projet dans la corbeille n’est pas ici : la mise à la corbeille ajoute seulement l’utilisateur à `trashed` du projet, voir [Collection Projects](/fr/dev/data-model/projects-collection).

#### Qui écrit {#who-writes-it}

| Code | Rôle |
| ---- | ------------ |
| `ProjectDeleter.mjs:189-293` (`deleteProject`) | Vide le projet vers le stockage, archive ses docs hors de Mongo, le retire des tags, fait un upsert de l’enregistrement et supprime le document `projects`. |
| `ProjectDeleter.mjs:295-342` (`undeleteProject`) | Réinsère le projet sous le nom `<name> (Restored)` (rendu unique pour le propriétaire) et non archivé, puis supprime l’enregistrement. Échoue avec `project_too_old_to_restore` une fois que `project` vaut `null`. Appelé depuis le panneau d’administration : restaurer un projet (`AdminProjectManager.mjs:497-515`) ou restaurer un utilisateur supprimé avec les projets supprimés en même temps que le compte (`services/web/modules/admin-tools/app/src/AdminUserManager.mjs:678-689`). |
| `ProjectDeleter.mjs:344-416` (`expireDeletedProject`) | Détruit les docs, l’historique, le chat et le journal d’audit du projet et déclenche le hook `projectExpired`, puis met `project` et `deleterData.deleterIpAddress` à `null`. Si le projet existe de nouveau, supprime seulement l’enregistrement obsolète. |
| `ProjectDeleter.mjs:97-146` (`expireDeletedProjectsAfterDuration`) | Fait expirer un lot d’enregistrements plus anciens que le délai. #### Remarques {#notes}

* Les modules qui écoutent `projectExpired` suppriment leurs propres données du projet : `git-bridge` (`services/web/modules/git-bridge/index.mjs:37`), `github-sync` (`services/web/modules/github-sync/index.mjs:56`), `gitlab-sync` (`services/web/modules/gitlab-sync/index.mjs:46`), `gitea-sync` (`services/web/modules/gitea-sync/index.mjs:46`) et `dropbox` (`services/web/modules/dropbox/index.mjs:54`).
* Un enregistrement expiré n’est jamais supprimé : `deleterData` reste définitivement, seuls `project` et l’adresse IP sont vidés.
* Mongoose donne aussi à `deleterData` son propre `_id`, que rien ne lit.
