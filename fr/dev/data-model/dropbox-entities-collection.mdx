---
title: Collection Dropbox Entities
icon: file-arrow-up
---

`dropboxEntities` contient un document par fichier que la synchronisation Dropbox a copié entre un projet et la Dropbox d'un utilisateur, ainsi que des tombstones de courte durée. La collection appartient à la synchronisation Dropbox : third-party-datastore (`services/third-party-datastore/app/js/StateManager.mjs`) l'écrit et la lit, et le module web `dropbox` (`services/web/modules/dropbox/app/src/DropboxHandler.mjs`) la vide. Il n'y a pas de schéma Mongoose.

#### Champs {#fields}

| Champ | Type | Signification | Source |
| ----- | ---- | ------------- | ------ |
| `_id` | ObjectId | Défini par le pilote à l'insertion. | `StateManager.mjs:46,97` |
| `overleaf.userId` | ObjectId | L'utilisateur dont la Dropbox contient le fichier. Défini sur chaque document. | `StateManager.mjs:48,98` |
| `overleaf.projectId` | ObjectId | Le projet du doc ou du fichier. Défini quand il est connu ; les tombstones n'en ont pas. | `StateManager.mjs:49-51` |
| `overleaf.id` | ObjectId | L'`_id` du doc ou du fichier dans le `rootFolder` du projet. Défini quand il est connu. | `StateManager.mjs:52` |
| `overleaf.type` | String | `doc` ou `file`. Le code actuel l'écrit mais ne le lit pas. | `StateManager.mjs:53` ; valeurs issues de `services/web/app/src/Features/ThirdPartyDataStore/TpdsUpdateSender.mjs:35,96` et `UpdateMerger.mjs:104,119` |
| `dropbox.id` | String | L'`id` du fichier dans les métadonnées de fichier Dropbox. Non défini sur les tombstones. | `StateManager.mjs:56` |
| `dropbox.pathLower` | String | Le chemin du fichier dans Dropbox, en minuscules et sans barre oblique finale. Mis à jour quand le fichier ou son dossier de projet est déplacé. | `StateManager.mjs:14-16,57,91,99` |
| `dropbox.rev` | String | La révision Dropbox lors de la dernière synchronisation. Le prochain envoi la transmet, afin qu'un fichier modifié dans Dropbox ne soit pas écrasé. | `StateManager.mjs:58`, `JobProcessor.mjs:114-122` |
| `dropbox.contentHash` | String | Le hash de contenu Dropbox lors de la dernière synchronisation. Un fichier listé avec le même hash est ignoré, car il s'agit de notre propre envoi ou il est déjà appliqué. | `StateManager.mjs:59`, `PullManager.mjs:147-149` |
| `tombstone` | Boolean | `true` marque un chemin que third-party-datastore a lui-même supprimé ou déplacé dans Dropbox. Quand Dropbox signale cette suppression en retour, elle n'est pas appliquée au projet. | `StateManager.mjs:100`, `PullManager.mjs:189-192` |
| `createdAt` | Date | Tombstones uniquement : quand il a été créé. Un pull terminé supprime les tombstones créés avant son début. | `StateManager.mjs:101,115-121` |

Un tombstone n'a que `overleaf.userId`, `dropbox.pathLower`, `tombstone` et `createdAt` (`StateManager.mjs:96-103`).

#### Qui l'écrit {#who-writes-it}

| Code | Ce qu'il fait |
| ---- | ------------- |
| `services/third-party-datastore/app/js/StateManager.mjs:35-62` (`recordEntity`) | Supprime les documents de l'utilisateur ayant le même `dropbox.id`, `dropbox.pathLower` ou `overleaf.id`, puis insère le nouvel état. |
| `services/third-party-datastore/app/js/JobProcessor.mjs:102-134` (`addEntity`) | Enregistre un doc ou un fichier après l'avoir envoyé d'Overleaf vers Dropbox (`:125-133`). |
| `services/third-party-datastore/app/js/PullManager.mjs:142-177` (`applyFile`) | Enregistre un fichier Dropbox après que web l'a appliqué au projet (`:168-176`). |
| `StateManager.mjs:80-94` (`moveEntities`) | Réécrit `dropbox.pathLower` sous un chemin déplacé : renommage de projet (`JobProcessor.mjs:195`) et déplacement de fichier ou de dossier (`JobProcessor.mjs:239`). |
| `StateManager.mjs:96-103` (`addTombstone`) | Après une suppression (`JobProcessor.mjs:153`), un renommage de projet (`:202`) ou un déplacement (`:240`) dans Dropbox. |
| `StateManager.mjs:72-78` (`removeEntities`) | Supprime les entrées à un chemin et en dessous, sauf les tombstones : après une suppression depuis Overleaf (`JobProcessor.mjs:152`) ou dans Dropbox (`PullManager.mjs:206`). |
| `StateManager.mjs:115-121` (`clearTombstones`) | À la fin d'un pull (`PullManager.mjs:31,69`). |
| `StateManager.mjs:186-190` (`removeUserState`), appelé depuis `services/third-party-datastore/app/js/QueueWorker.mjs:43` | Supprime tous les documents de l'utilisateur quand third-party-datastore délie un compte qu'il ne peut plus utiliser. |
| `DropboxHandler.mjs:142-146` (`removeUserState`) | Supprime tous les documents de l'utilisateur à la liaison (`:125`), à la déliaison (`:183`) et quand un utilisateur supprimé expire (`services/web/modules/dropbox/index.mjs:62-64`). |
| `DropboxHandler.mjs:150-154` (`removeProjectState`) | Supprime les documents du projet quand un projet supprimé expire (`index.mjs:54-56`). |

#### Qui la lit {#who-reads-it}

| Code | Ce qu'il fait |
| ---- | ------------- |
| `StateManager.mjs:64-70` (`findEntityByPath`) | Récupère `dropbox.rev` avant un envoi (`JobProcessor.mjs:114`) et `dropbox.contentHash` avant d'appliquer un fichier Dropbox (`PullManager.mjs:147`). |
| `StateManager.mjs:106-112` (`findTombstone`) | Vérifie une suppression signalée au chemin ou à l'un de ses parents (`PullManager.mjs:189`). |
| `StateManager.mjs:160-175` (`getSyncedPaths`) | Liste les chemins de fichiers synchronisés après une réinitialisation du curseur, afin qu'un fichier absent de la liste soit considéré comme supprimé (`PullManager.mjs:74-85`). |

#### Remarques {#notes}

* L'unicité vient uniquement de la suppression avant chaque insertion dans `recordEntity` (`StateManager.mjs:38-45`). Le commentaire de `StateManager.mjs:3-11` mentionne des index uniques ; CE ne les a pas.
* Les requêtes par utilisateur et chemin (`findEntityByPath`, `findTombstone`, `removeEntities`) n'utilisent l'index que pour `overleaf.userId`.
