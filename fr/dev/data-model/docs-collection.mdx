---
title: Collection Docs
icon: file-lines
---

`docs` contient le contenu des fichiers texte modifiables d’un projet (Overleaf les appelle des docs), par exemple `main.tex` ou `sample.bib`. Un document par doc : ses lignes, ses commentaires et modifications suivies, deux compteurs et l’état de suppression. Le nom du fichier et sa place dans l’arborescence ne sont pas ici mais dans `projects.rootFolder` (voir [Collection Projects](/fr/dev/data-model/projects-collection)). Les fichiers binaires ne sont pas ici non plus.

En dehors des migrations et des scripts de maintenance, seul docstore écrit cette collection, dans `services/docstore/app/js/MongoManager.js`. Il n’y a pas de modèle Mongoose ; web et document-updater y accèdent via l’API HTTP de docstore (`services/docstore/app.js:31-70`). Dans la colonne Source, les noms de fichiers seuls se trouvent sous `services/docstore/app/js/`.

#### Champs {#fields}

| Champ | Type | Signification | Source |

#### Ranges {#ranges}

`ranges` contient deux tableaux. document-updater les construit avec `libraries/ranges-tracker/index.cjs` ; docstore convertit les ids en ObjectIds et `ts` en Dates avant l’enregistrement (`RangeManager.js:41-63`). Un doc sans commentaires ni modifications suivies a `ranges: {}` ou pas de `ranges`.

| Champ | Type | Signification | Source |
| ----- | ---- | ------- | ------ |
| `ranges.comments` | Array of Object | Portions de texte commentées. | `libraries/ranges-tracker/index.cjs:217-236` |
| `ranges.comments.id` | ObjectId | Id du commentaire. Il est égal à `op.t`, l’id du fil du commentaire dans la collection `rooms` ; docstore impose leur concordance. | `RangeManager.js:54-57` |
| `ranges.comments.op.c` | String | Le texte commenté dans le doc (pas le message du commentaire). | `index.cjs:226-230` |
| `ranges.comments.op.p` | Number | Position en caractères du début de `op.c` dans le doc. | `index.cjs:226-230` |
| `ranges.comments.op.t` | ObjectId | Id du fil, voir `id`. | `index.cjs:226-230`, `RangeManager.js:57` |
| `ranges.comments.metadata` | Object | `user_id` et `ts` du commentaire. | `index.cjs:232`, `RangeManager.js:62` |
| `ranges.changes` | Array of Object | Modifications suivies, triées par position. | `index.cjs:640-660` |
| `ranges.changes.id` | ObjectId | Id de la modification. | `index.cjs:643-647`, `RangeManager.js:51` |
| `ranges.changes.op.i` / `op.d` | String | Texte inséré, ou texte supprimé. L’un des deux. | `index.cjs:640-660` |
| `ranges.changes.op.p` | Number | Position en caractères de la modification. | `index.cjs:640-660` |
| `ranges.changes.metadata.user_id` | ObjectId or String | Auteur. Les modifications d’éditeurs anonymes gardent la chaîne `anonymous-user`. | `RangeManager.js:45-46`, `DocManager.js:192` |
| `ranges.changes.metadata.ts` | Date | Date de la modification. | `RangeManager.js:42-43` |

Le texte d’un commentaire et de ses réponses n’est pas dans `docs` : il est dans la collection `messages`, dans la room dont le `thread_id` est l’id du commentaire. L’état résolu d’un commentaire est stocké sur cette room, pas ici ; docstore ignore un indicateur `resolved` s’il en reçoit un (`RangeManager.js:59-61`). Voir [Collection Rooms](/fr/dev/data-model/rooms-collection) et [Collection Messages](/fr/dev/data-model/messages-collection).

#### Qui écrit {#who-writes-it}

| Code | Rôle |
| ---- | ------------ |
| `DocManager.js:223-338` (`POST /project/:project_id/doc/:doc_id`) | Crée ou met à jour un doc : `lines`, `ranges` et `version`. Web l’appelle quand un doc est créé et quand document-updater fait le flush d’un doc ouvert (`services/web/app/src/Features/Project/ProjectEntityUpdateHandler.mjs:174`). |
| `DocManager.js:346-366` (`PATCH /project/:project_id/doc/:doc_id`) | Marque un doc comme supprimé avec `deleted`, `deletedAt` et `name`. |
| `DocArchiveManager.js:29-88` | Archive un doc : copie `lines`, `ranges` et `rev` vers le persisteur et définit `inS3`. S’exécute pour un projet entier quand il est désactivé, et pour un seul doc à la suppression quand `ARCHIVE_ON_SOFT_DELETE=true` (`DocManager.js:355-363`). |
| `DocArchiveManager.js:150-174` | Ramène un doc archivé dans Mongo quand il est lu (`DocManager.js:40-41`). |
| `MongoManager.js:272-274` | Supprime tous les docs d’un projet quand le projet est détruit. |

#### Index {#indexes}

Tous proviennent de migrations marquées `server-ce` dans `tools/migrations/`.

| Nom | Clés | Options | Migration |
| ---- | ---- | ------- | --------- |
| `project_id_deleted_deletedAt_1` | `project_id: 1, deleted: 1, deletedAt: -1` | | `20210408123210_create_docs_project_id_deleted_deletedAt_index` |
| `project_id_1_inS3_1_deleted_1` | `project_id: 1, inS3: 1, deleted: 1` | | `20250321092555_add_deleted_to_project_id_in_s3_index` |

#### Remarques {#notes}

* Tant qu’un doc est ouvert, son texte le plus récent est dans document-updater (Redis), pas ici. Mongo n’est mis à jour que lors du flush de document-updater (`services/document-updater/app/js/PersistenceManager.js:128-160`). Le code qui lit les docs d’un projet entier doit d’abord appeler `flushProjectToMongo`, comme le fait `ProjectDuplicator`.
* Les docs supprimés restent dans cette collection, avec `deleted: true`, jusqu’à la destruction du projet. docstore en renvoie au plus `MAX_DELETED_DOCS` (2000 par défaut), du plus récent au plus ancien (`MongoManager.js:29-44`, `services/docstore/config/settings.defaults.cjs:40`). Le panneau d’historique ne les utilise pas ; il lit history-v1.
* Les compteurs `rev` et `version` n’ont aucun rapport avec les versions d’historique du projet dans history-v1.
