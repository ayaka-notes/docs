`projectHistoryFailures` contient un document par projet dont project-history n’a pas pu traiter les mises à jour d’historique, ou pour lequel il a lancé une resynchronisation. Le document est de nouveau supprimé dès que le traitement fonctionne. project-history l’écrit dans `services/project-history/app/js/ErrorRecorder.js` ; son type est dans `services/project-history/app/js/mongo-types.ts:3-24`. Web possède aussi un schéma Mongoose pour elle (`services/web/app/src/models/ProjectHistoryFailure.mjs:5-19`), mais aucun code web n’utilise ce modèle.

#### Remarques {#notes}

* Un document reste jusqu’à ce qu’un flush du projet réussisse ou que le projet soit supprimé (`clearError` ci-dessus) : chaque document signale donc un projet dont le dernier flush ou la dernière resynchronisation n’a pas encore réussi.
* Les chaînes d’erreur commençant par `OError:` sont renvoyées sous la forme `Error:` (`ErrorRecorder.js:18-26`) ; la valeur stockée ne change pas.
