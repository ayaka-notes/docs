Dans cette section, nous abordons le modèle de données d'Overleaf. Overleaf utilise MongoDB pour la persistance des données ; l'unique base de données s'appelle `sharelatex`, du nom du prédécesseur d'Overleaf.

L’environnement de développement exécute déjà Mongo Express à côté de Mongo (voir [setup-develop-tools.md](/fr/dev/environment/setup-develop-tools  "mention")). Ouvrez [http://localhost:8081/](http://localhost:8081/) et connectez-vous avec `admin:pass`.

</Frame>

Vous pouvez aussi ouvrir un shell dans le conteneur Mongo depuis le répertoire `develop` :

```bash
bin/docker-compose exec mongo mongosh sharelatex
```

#### Comment les pages sont rédigées {#how-the-pages-are-written}

* Chaque page liste les champs que le code écrit, avec leur type, leur signification et la ligne de code qui le montre : une ligne de schéma Mongoose, ou l’endroit qui écrit le champ. Les champs que seuls une migration, un script ou l’un des modules web écrivent le précisent.
* Beaucoup de collections n’ont pas de schéma Mongoose : les services les écrivent avec le pilote MongoDB.
* Les index ne sont créés que par les migrations de `tools/migrations/`. CE exécute celles marquées `server-ce` à chaque démarrage (`server-ce/init_scripts/900_run_web_migrations.sh`) ; `autoIndex` de Mongoose est désactivé (`services/web/app/src/infrastructure/Mongoose.mjs:7`). Les tableaux d’index ne listent que ce qu’une instance CE obtient au final.
* Le texte des docs est dans Mongo, mais pas le reste du contenu. Le contenu des fichiers est stocké sous forme de blobs et l’historique sous forme de chunks dans les buckets de history-v1 (dossiers locaux, ou S3 / RustFS) ; les docs ouverts restent dans Redis jusqu’au flush de document-updater.

Une base de données CE contient plus de collections que celles-ci. Beaucoup sont créées vides par leurs migrations d’index et ne servent que sur overleaf.com. Par exemple, rien dans CE ni dans nos modules n’écrit `splittests`, `samlLogs`, `notificationsPreferences`, `onboardingDataCollection` ou `userfeatureusages` en utilisation normale ; ces collections n’ont donc pas de page.
