title: Collection Deleted Users
icon: user-xmark
---

`deletedUsers` conserve un compte utilisateur après sa suppression : un document par compte supprimé, avec une copie du document utilisateur complet et l’auteur de la suppression. Web l’écrit dans `services/web/app/src/Features/User/UserDeleter.mjs` ; le schéma est `services/web/app/src/models/DeletedUser.mjs`. Une fois le délai de suppression définitive écoulé, l’expiration retire la copie de l’utilisateur, mais l’enregistrement avec `deleterData` reste.

Supprimer un utilisateur supprime aussi les projets dont il est propriétaire ; ils vont dans [Collection Deleted Projects](/fr/dev/data-model/deleted-projects-collection) avec la raison `account-deletion`.

#### Remarques {#notes}

* Les modules qui écoutent `expireDeletedUser` suppriment leurs propres données de l’utilisateur : `dropbox` (`services/web/modules/dropbox/index.mjs:62`), `github-sync` (`services/web/modules/github-sync/index.mjs:66`), `gitlab-sync` (`services/web/modules/gitlab-sync/index.mjs:56`) et `gitea-sync` (`services/web/modules/gitea-sync/index.mjs:56`).
* Un enregistrement expiré n’est jamais supprimé : `deleterData` reste définitivement, seuls `user` et l’adresse IP sont retirés.
* Les jetons d’accès personnels de l’utilisateur ne sont pas supprimés avec le compte, voir [Collection OAuth Access Tokens](/fr/dev/data-model/oauth-access-tokens-collection).
* Mongoose donne aussi à `deleterData` son propre `_id`, que rien ne lit.
