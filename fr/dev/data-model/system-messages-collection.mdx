---
title: Collection System Messages
icon: bullhorn
---

`systemmessages` contient les bannières globales qu'un administrateur publie pour tous les utilisateurs connectés. Un document correspond à un message. `web` en est propriétaire ; le schéma est `services/web/app/src/models/SystemMessage.mjs` et le code est `services/web/app/src/Features/SystemMessages/SystemMessageManager.mjs`.

#### Champs {#fields}

| Champ | Type | Signification | Source |
| --- | --- | --- | --- |
| `_id` | ObjectId | Id du message. Le navigateur retient grâce à cet id les messages que l'utilisateur a fermés (`services/web/frontend/js/shared/components/system-message.tsx:10`). | `SystemMessage.mjs:5` |
| `content` | String | Texte du message, par défaut `''`. | `SystemMessage.mjs:7` |
| `__v` | Number | Clé de version Mongoose, ajoutée par `message.save()`. | `SystemMessageManager.mjs:29-30` |

#### Qui l'écrit {#who-writes-it}

| Code | Ce qu'il fait |
| --- | --- |
| `SystemMessageManager.mjs:28-33` (`createMessage`) | `POST /admin/messages` (`services/web/app/src/router.mjs:1150-1152`, `services/web/app/src/Features/ServerAdmin/AdminController.mjs:151-159`): ajoute un message. |
| `SystemMessageManager.mjs:22-26` (`clearMessages`) | `POST /admin/messages/clear` (`router.mjs:1155-1157`, `AdminController.mjs:161-168`): supprime tous les messages. Il n'est pas possible d'en supprimer un seul. |

#### Qui la lit {#who-reads-it}

| Code | Ce qu'il fait |
| --- | --- |
| `SystemMessageManager.mjs:50-65` | Chaque processus `web` garde tous les messages en mémoire et les recharge toutes les 20 à 30 secondes, ainsi que juste après sa propre création ou suppression. |
| `services/web/app/src/Features/SystemMessages/SystemMessageController.mjs:6-24` | `GET /system/messages` (`router.mjs:331`): renvoie les messages en cache aux utilisateurs connectés. Tant que le site est fermé (`siteIsOpen` à false), il renvoie à la place un avis fixe, qui n'est pas stocké dans Mongo. |
| `AdminController.mjs:83-84` | La page `/admin` liste les messages directement depuis Mongo. |

#### Index {#indexes}

Aucune migration ne crée d'index sur `systemmessages` ; seul l'index `_id` par défaut existe.

#### Remarques {#notes}

* Avec `notifyOnSystemMessageChanges` défini, une création ou une suppression est aussi publiée sur le canal Redis `refresh-system-messages`, afin que les autres processus `web` rechargent immédiatement (`SystemMessageManager.mjs:9`, `:35-48`, `:75-87`). Sans ce réglage, ils prennent en compte la modification lors de leur prochain rechargement programmé.
