`oauthApplications` contient les clients OAuth que web connaît. Un document correspond à un client. Dans Ayakaleaf Pro, le seul code qui y écrit est le module web `git-bridge`, qui crée un client nommé `Overleaf Git Bridge` au démarrage de web. Le schéma est `services/web/app/src/models/OauthApplication.mjs`.

#### Champs {#fields}

| Champ | Type | Signification | Source |
| ----- | ---- | ------- | ------ |
| `_id` | ObjectId | Identifiant du document client. `oauthAccessTokens.oauthApplication_id` et `oauthAuthorizationCodes.oauthApplication_id` pointent vers lui. | `OauthApplication.mjs:5` |
| `id` | String | Identifiant du client : 64 lettres minuscules et chiffres aléatoires. | `OauthApplication.mjs:7`, `services/web/modules/git-bridge/index.mjs:25` |
| `clientSecret` | String | Secret du client, écrit sous la forme `v1.` suivi de 32 caractères aléatoires. Seul `getClient` le lit, et rien n'appelle `getClient` (voir Remarques). | `OauthApplication.mjs:8`, `git-bridge/index.mjs:26` |
| `grants` | Array of String | Types de grant. Le client git-bridge a `['password']`. Renvoyé avec le client lors de la vérification d'un jeton (`services/web/modules/oauth2-server/app/src/OAuth2Model.mjs:67-72`). | `OauthApplication.mjs:9`, `git-bridge/index.mjs:27` |
| `name` | String | Nom du client. Le module git-bridge et le code des jetons d'accès personnels trouvent le client par le nom `Overleaf Git Bridge`. | `OauthApplication.mjs:10`, `git-bridge/index.mjs:15-16,28` |
| `redirectUris` | Array of String | URI de redirection autorisées. `[]` pour le client git-bridge. | `OauthApplication.mjs:11`, `git-bridge/index.mjs:29` |
| `scopes` | Array of String | Scopes que le client peut utiliser. `['git_bridge']` pour le client git-bridge. | `OauthApplication.mjs:12`, `git-bridge/index.mjs:30` |
| `pkceEnabled` | Boolean | Uniquement dans le schéma : aucun code de ce dépôt ne l'écrit, et seul `getClient`, inutilisé, le lit (`OAuth2Model.mjs:207`). | `OauthApplication.mjs:13` |

#### Qui écrit {#who-writes-it}

| Code | Rôle |
| ---- | ------------ |
| `git-bridge/index.mjs:9-35` (module `git-bridge`) | Quand `GIT_BRIDGE_ENABLED` vaut `true`, crée le client `Overleaf Git Bridge` au démarrage de web si aucun client de ce nom n'existe. |

#### Qui lit {#who-reads-it}

| Code | Rôle |
| ---- | ------------ |
| `services/web/modules/oauth2-server/app/src/OAuthPersonalAccessTokenManager.mjs:53-61` (module `oauth2-server`) | Trouve le client `Overleaf Git Bridge` par son nom et enregistre son `_id` dans chaque nouveau jeton d'accès personnel. Sans ce client, aucun jeton n'est créé. |
| `OAuth2Model.mjs:31-39,67-72` (`getAccessToken`) | Charge le client d'un jeton via `oauthApplication_id` et renvoie son `id` et ses `grants`. |
| `OAuth2Model.mjs:185-209,241,275` (`getClient`, `saveToken`, `saveAuthorizationCode`) | Recherchent les clients par `id`. Jamais atteints dans ce dépôt, voir Remarques. |

#### Index {#indexes}

Seulement l'index par défaut sur `_id`. L'index unique `id_1` provient uniquement des migrations marquées `saas` (`20190912145016_create_oauthApplications_indexes.mjs`) et `server-pro` (`20230502180757_server_pro_oauth_indexes.mjs`), que Community Edition n'exécute pas.

#### Remarques {#notes}

* Web n'utilise `@node-oauth/oauth2-server` que pour vérifier les jetons bearer (`server.authenticate` dans `services/web/app/src/Features/Authentication/AuthenticationController.mjs:409-450`), ce qui n'appelle que `getAccessToken` et `verifyScope` du modèle. Aucune route ne sert `/oauth/token` ni `/oauth/authorize`, donc `getClient`, `saveToken` et `saveAuthorizationCode` ne sont jamais appelés.
* Le module cherche le client par son nom puis le crée, et Community Edition n'a aucun index unique sur `name` ou `id`. Rien n'empêche donc un second client du même nom. Le code qui a besoin du client prend celui que renvoie `findOne`.
