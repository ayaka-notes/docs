Nous sommes très fiers d'annoncer la sortie d'Overleaf Pro 6.3.1, l'éditeur LaTeX en ligne le plus puissant et le plus complet de la communauté. Une version corrective se résume généralement à une poignée de petites corrections. Celle-ci va bien plus loin : en plus de dizaines de corrections de bugs, elle apporte cinq nouvelles fonctionnalités et relie vos projets aux endroits où vous travaillez déjà, de Dropbox et GitLab à l'agent IA de votre terminal.

### Changements

* Synchronisation Dropbox (avant-première) : gardez chaque projet synchronisé avec votre propre Dropbox, dans les deux sens.
* Synchronisation GitLab (avant-première) : synchronisation bidirectionnelle avec GitLab.com ou votre GitLab autogéré.
* Serveur MCP : laissez Claude Code, Codex, Cursor, VS Code ou Gemini CLI travailler directement sur un projet.
* GitHub Enterprise : faites pointer la synchronisation GitHub vers votre propre instance GitHub Enterprise.
* Reconnaissance de symboles manuscrits : dessinez un symbole, obtenez la commande LaTeX.
* `OVERLEAF_DISABLE_LOCAL_LOGIN` : masquez la connexion par e-mail et mot de passe afin que les utilisateurs se connectent uniquement via le SSO.
* Corrections de bugs détectés par notre système de tests E2E et par l'Internal Horizon Issue Investigation.
* Correctifs de l'Overleaf 6.3.1 en amont.

<Info>

La synchronisation Dropbox et la synchronisation GitLab sont livrées dans la 6.3.1 en **avant-première** pour des tests progressifs, et seront officiellement publiées dans la v6.4.0. Leur configuration et leur comportement peuvent encore évoluer d'ici là. Toutes deux sont désactivées par défaut. Veuillez signaler tout problème sur [GitHub](https://github.com/ayaka-notes/ayakaleaf-pro/issues).

</Info>

#### Fonctionnalité 01 : synchronisation Dropbox (avant-première)

Certaines personnes ne veulent jamais avoir à penser à Git. Elles veulent simplement que leur thèse soit un dossier sur leur ordinateur portable, et c'est exactement ce que leur offre la synchronisation Dropbox. Chaque utilisateur lie son propre compte Dropbox, et les projets dont il est propriétaire ou qui sont partagés avec lui apparaissent sous `Apps/<your app name>/`. Modifiez un fichier dans Overleaf et la modification apparaît dans Dropbox. Modifiez le fichier localement dans votre éditeur préféré, enregistrez-le, et la modification revient dans Overleaf via un webhook signé.

Pour les administrateurs : le Git bridge doit être activé. Créez une application dans l'App Console de Dropbox, puis définissez `DROPBOX_ENABLED`, `DROPBOX_APP_KEY`, `DROPBOX_APP_SECRET`, `DROPBOX_APP_NAME` et `DROPBOX_TOKEN_CIPHER_PASSWORD`. `DROPBOX_SYNC_PROXY_URL` est facultatif et destiné aux serveurs qui ne peuvent pas joindre Dropbox directement. Créez ensuite, une seule fois, les index MongoDB dont la synchronisation Dropbox a besoin, avant que les utilisateurs ne lient leurs comptes.

Consultez [Synchronisation Dropbox](/fr/on-premises/configuration/overleaf-toolkit/dropbox-synchronisation  "mention") pour les instructions de configuration complètes.

#### Fonctionnalité 02 : synchronisation GitLab (avant-première)

La synchronisation GitHub est l'une de nos fonctionnalités les plus appréciées depuis la 6.2, et de nombreuses universités et entreprises hébergent plutôt leur code sur GitLab. La synchronisation GitLab fonctionne de la même manière : liez votre compte, importez un dépôt depuis le menu de nouveau projet, ou exportez un projet vers un nouveau projet GitLab. Poussez et récupérez ensuite les modifications depuis l'éditeur, et fusionnez via des merge requests.

Elle fonctionne avec GitLab.com et avec GitLab autogéré 15.10 ou ultérieur. Définissez `GITLAB_SYNC_ENABLED`, `GITLAB_SYNC_CLIENT_ID`, `GITLAB_SYNC_CLIENT_SECRET` et `GITLAB_TOKEN_CIPHER_PASSWORD`, ainsi que `GITLAB_SYNC_URL` pour une instance autogérée.

Consultez [Synchronisation GitLab](/fr/on-premises/configuration/overleaf-toolkit/gitlab-synchronisation  "mention") pour les instructions de configuration complètes.

#### Fonctionnalité 03 : serveur MCP

Avec la 6.3, nous avons intégré un assistant IA dans l'éditeur. Avec la 6.3.1, nous ouvrons la porte dans l'autre sens : chaque projet dispose désormais de son propre serveur MCP, afin que l'agent IA que vous utilisez déjà puisse travailler directement sur votre article. Demandez à Claude Code de corriger les fautes de frappe de l'introduction, à Codex de compiler et de corriger les erreurs LaTeX, ou à Cursor de répondre aux commentaires de relecture en suspens. L'agent lit et modifie les fichiers en direct : vous et vos collaborateurs voyez ses modifications apparaître dans l'éditeur au fur et à mesure qu'il tape. Il peut également compiler, lire le journal, récupérer le PDF, compter les mots et lister les versions.

L'endpoint est `/project/<project_id>/mcp`. Authentifiez-vous avec le même jeton Git que celui que vous utilisez pour `git clone`. L'accès suit les paramètres de partage du projet : l'agent d'un lecteur peut donc lire mais pas modifier, et chaque outil est soumis à une limite de débit. Il n'y a rien d'autre à configurer : le serveur MCP est activé en même temps que le Git bridge.

Consultez [Serveur MCP](/fr/on-premises/configuration/overleaf-toolkit/mcp-server  "mention") pour savoir comment connecter chaque client IA.

#### Fonctionnalité 04 : GitHub Enterprise

La synchronisation GitHub n'est plus limitée à github.com. Définissez `GITHUB_SYNC_URL` sur votre GitHub Enterprise Server, ou sur GitHub Enterprise Cloud avec résidence des données (`GHE.com`), et les endpoints REST et GraphQL en sont déduits. Si votre instance a une configuration inhabituelle, remplacez-les avec `GITHUB_SYNC_API_URL` et `GITHUB_SYNC_GRAPHQL_URL`. Laissez-les non définies et tout reste sur github.com.

Consultez [Synchronisation GitHub](/fr/on-premises/configuration/overleaf-toolkit/github-synchronisation#github-enterprise  "mention") pour plus de détails.

#### Fonctionnalité 05 : reconnaissance de symboles manuscrits

Vous savez à quoi ressemble le symbole, mais pas comment il s'appelle. Est-ce `\varsigma` ou `\zeta` ? `\models` ou `\vDash` ? Passez la palette de symboles en mode dessin, esquissez-le avec votre souris ou votre pavé tactile, et la palette vous suggère les commandes LaTeX correspondantes.

La reconnaissance s'exécute entièrement dans le navigateur, avec un modèle entraîné par ayaka-notes : rien de ce que vous dessinez ne quitte votre machine. Le bouton de dessin est masqué dans les navigateurs sans `OffscreenCanvas` (par exemple Safari 15).

#### Corrections de bugs

Cette version apporte également une longue liste de corrections. Beaucoup d'entre elles ont été détectées par notre nouveau système de tests E2E, qui exécute désormais chaque jour des suites de tests pour chaque module, et par l'Internal Horizon Issue Investigation : chaque fois que nous corrigeons un bug, nous passons au crible l'ensemble du code à la recherche de bugs similaires avant de le clore.

* **Authentification** : les comptes locaux peuvent définir et modifier leur mot de passe sur les instances SSO, et les utilisateurs OIDC ne peuvent plus modifier leur propre adresse e-mail. Les connexions LDAP, SAML et OIDC n'échouent plus lorsqu'un attribut de nom comporte plusieurs valeurs, et la déconnexion SAML/OIDC fonctionne de nouveau.
* **Utilisateurs suspendus** : suspendre un utilisateur met désormais fin à ses sessions et ferme ses éditeurs ouverts, et ses jetons Git et ses téléchargements MCP sont refusés.
* **Synchronisation GitHub** : seul le propriétaire peut exporter un projet, les modifications effectuées pendant une récupération restent en attente, les fichiers vides sont synchronisés, et les fusions manuelles sont vérifiées sur GitHub.
* **Zotero / Mendeley** : vous recevez un message vous invitant à refaire la liaison lorsque vos identifiants ne fonctionnent plus, et les références sont réindexées après un import.
* **Services externes** : les requêtes vers Zotero, Mendeley, GitHub, GitLab et la recherche web bénéficient d'un délai de connexion de 3 s au lieu de 1 s, de sorte que les réseaux plus lents n'échouent plus.
* **Suivi des modifications** : les données de relecture incluent les documents non chargés et les modifications non enregistrées.
* **Panneau d'administration** : la restauration de projets supprimés, le changement de propriétaire et la modification des utilisateurs fonctionnent correctement, et l'échec d'un e-mail n'empêche plus la création ou la suppression d'un compte.
* **Galerie de modèles** : un tri non valide renvoie 400 au lieu de 500, et la publication d'un projet sans fichier principal en demande un.

Consultez les [notes de version de la 6.3.1](/fr/on-premises/release-notes/release-notes-6.x.x#ayakaleaf-pro-6.3.1  "mention") pour la liste complète.

#### Mise à niveau

* Depuis la 6.3.0 : aucune migration n'est nécessaire. Téléchargez la nouvelle image et redémarrez.
* Depuis la 6.2.x ou une version antérieure avec Zotero ou Mendeley en service : exécutez d'abord la [migration Zotero / Mendeley](/fr/on-premises/release-notes/release-notes-6.x.x#ayakaleaf-pro-6.3.0  "mention") de la 6.3.0.
* La synchronisation Dropbox et la synchronisation GitLab sont désactivées par défaut. La synchronisation GitLab ne nécessite que de nouvelles variables d'environnement. La synchronisation Dropbox nécessite en outre que ses index MongoDB soient créés une fois, avant que les utilisateurs ne lient leurs comptes : voir [Créer les index de la base de données](/fr/on-premises/configuration/overleaf-toolkit/dropbox-synchronisation#create-the-database-indexes  "mention").
