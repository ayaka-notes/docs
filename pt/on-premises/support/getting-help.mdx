### O Doctor

O Overleaf Toolkit vem com um prático script `doctor` para ajudar na depuração. Execute `bin/doctor` e o script exibirá informações sobre o ambiente do host, sua configuração e as dependências de que o Toolkit precisa. Essa saída também pode nos ajudar a diagnosticar problemas nas suas instalações do Ayakaleaf Pro.

<Info>

Os usuários do Overleaf Pro podem [abrir uma issue no GitHub](https://github.com/ayaka-notes/overleaf/issues).

É uma boa ideia incluir a saída do script `bin/doctor` na sua mensagem.

</Info>

### Consultando o Doctor

Execute o script doctor:

```bash title="Run doctor"
bin/doctor
```

### Informações do host

A seção `Host Information` contém informações sobre a máquina que executa o Toolkit (por exemplo, a distribuição e a versão do Linux).

<Accordion title="Exemplo de saída de Host Information">

```text
- Host Information
    - Linux
    - Output of 'lsb_release -a':
            No LSB modules are available.
            Distributor ID:	Ubuntu
            Description:	Ubuntu 22.04.5 LTS
            Release:	22.04
            Codename:	jammy
```

</Accordion>

### Dependências

A seção `Dependencies` lista as ferramentas necessárias para o funcionamento do Toolkit. Se uma ferramenta estiver presente, ela será listada como `status: present` com informações de versão. Se estiver ausente, será listada como `status: MISSING!` e um aviso será adicionado ao final da saída do `doctor`.

<Accordion title="Exemplo de saída de dependência (presente)">

```text
- docker
    - status: present
    - version info: Docker version 28.0.4, build b8034c0
```

</Accordion>

<Accordion title="Exemplo de saída de dependência (ausente)">

```text
- docker
    - status: MISSING!
```

</Accordion>

Se alguma dependência estiver ausente, o Toolkit quase certamente não funcionará.

### Configuração

A seção `Configuration` contém informações sobre os arquivos no diretório `config/`. Para `config/overleaf.rc`, o doctor exibe alguns valores importantes. Arquivos ausentes serão listados como `status: MISSING!` e um aviso será adicionado ao final da saída do `doctor`.

<Accordion title="Exemplo de saída de Configuration">

```text
====== Configuration ======
- config/version
    - status: present
    - version: 6.3.2
- config/overleaf.rc
    - status: present
    - values
        - OVERLEAF_DATA_PATH: /tmp/overleaf
        - SERVER_PRO: false
        - MONGO_ENABLED: false
        - REDIS_ENABLED: true
- config/variables.env
    - status: MISSING!
```

</Accordion>

Observações sobre o exemplo acima:

* `OVERLEAF_DATA_PATH` definido como `/tmp/overleaf` pode não ser um local seguro para dados importantes.
* `MONGO_ENABLED: false` significa que o Toolkit não provisionará seu próprio MongoDB; certifique-se de que `MONGO_URL` aponte para um MongoDB gerenciado externamente, se necessário.
* `config/variables.env` está ausente no exemplo.

### Avisos

A seção `Warnings` resume os problemas descobertos pelo script doctor. Se não houver problemas, esta seção indicará isso.

<Accordion title="Exemplo de saída de Warnings">

```text
====== Warnings ======
- configuration file variables.env not found
- rc file, OVERLEAF_DATA_PATH not set
====== End =======
```

</Accordion>

### Perguntas e respostas

<Accordion title="As mensagens do `bin/doctor` sobre quay.io, configuração do Docker e locale do Perl precisam ser corrigidas?">

<strong>Resposta:</strong> Não, as três são apenas informativas. O `bin/doctor` apenas exibe um relatório; ele não impede o `bin/up`.

* `logged in to quay.io: false` e o aviso `Server Pro enabled, but not logged in to quay.io repository`: essa verificação vem do Toolkit oficial, no qual a imagem do Server Pro fica em um registro privado do quay.io. Com `SERVER_PRO=true`, o Toolkit baixa `ghcr.io/ayaka-notes/overleaf-pro`, que é pública, portanto nenhum login é necessário. Ignore esse aviso.
* `grep: /root/.docker/config.json: No such file or directory` (ou outro diretório home): a verificação do quay.io procura `quay.io` nesse arquivo. O Docker só o grava quando tem configurações a salvar, por exemplo após `docker login`, por isso ele não existe em muitos servidores. Ele não é necessário.
* `perl: warning: Setting locale failed`: o Toolkit usa o `perl` apenas aqui, no `bin/doctor`, para exibir a sua versão, e o Perl emite um aviso quando `LANG` ou `LC_ALL` indica um locale que não está instalado no host. A versão é exibida mesmo assim. Para silenciá-lo, defina essas variáveis com um locale listado por `locale -a`, por exemplo `C.UTF-8`.

Avisos como `Docker daemon is not running`, `docker not found`, `Docker Compose not found` ou um arquivo ausente em `config/` precisam ser corrigidos: o Toolkit não consegue iniciar sem eles.

</Accordion>
