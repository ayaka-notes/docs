#### Serviços

A infraestrutura do Overleaf Pro é composta por quatro serviços principais: `sharelatex`, `git-bridge` (opcional), `mongo` e `redis`. O serviço `sharelatex`, que executa a aplicação principal do Server Pro, depende dos serviços `mongo` e `redis` para as funcionalidades de banco de dados e de cache/tempo real, e do `git-bridge` para lidar com a [integração com o Git](/pt/on-premises/configuration/overleaf-toolkit/git-integration) (opcional). A única porta publicada na máquina host é a porta 80, usada pelo contêiner `sharelatex`.

O Server Pro também oferece suporte opcional a [armazenamento compatível com S3](/pt/on-premises/configuration/overleaf-toolkit/s3) para arquivos de projeto e histórico completo de projetos, além de poder servir como proxy para o [site de documentação principal do Overleafarrow-up-right](https://www.overleaf.com/learn). Para mais informações, consulte o nosso guia sobre as páginas de [Adicionar ajuda de LaTeX para usuários](/pt/on-premises/configuration/overleaf-toolkit/adding-latex-user-help).

<Info>

Se necessário, o MongoDB e o Redis podem ser externalizados usando variáveis de ambiente que apontam para serviços externos. Para mais informações, consulte [Configurar o Overleaf](/pt/on-premises/configuration) se você estiver usando o Docker Compose e [Configurações do Toolkit](/pt/on-premises/configuration/overleaf-toolkit/toolkit-settings) se estiver usando o Overleaf Toolkit.

</Info>

#### Compilação

Para as [compilações em sandbox](/pt/on-premises/configuration/overleaf-toolkit/sandboxed-compiles), o contêiner `sharelatex` orquestra a criação de novos contêineres para processar as compilações dos projetos; isso é feito através do socket do Docker na máquina host. Você pode ler mais sobre o editor e o processo completo de compilação/cache [aqui](/pt/on-premises/getting-started/microservices#editor-and-compile-process).

#### Rede

A comunicação entre os contêineres é feita através da resolução DNS interna do Docker, por meio de uma rede bridge dedicada, e nenhum firewall está ativado. Por padrão, os serviços acima usam as suas respectivas portas padrão, mas estas podem ser configuradas por variáveis de ambiente. O contêiner `sharelatex` usa a porta 80 para acesso web externo (servido pelo Nginx), o contêiner `mongo` usa a porta 27017 e o `redis` usa a porta 6379.

Para clientes que usam a nossa solução gerenciada [Overleaf Toolkitarrow-up-right](https://github.com/overleaf/toolkit), é possível, opcionalmente, [ativar um proxy TLS](/pt/on-premises/configuration/overleaf-toolkit/tls-proxy) para terminar conexões HTTPS usando o Nginx através de uma variável de ambiente. Como alternativa, você pode usar o seu proxy TLS existente.

<Info>

Você pode ver um diagrama que explica o fluxo das requisições [aqui](/pt/on-premises/configuration/overleaf-toolkit/tls-proxy).

</Info>

#### Resumo

* Fora da rede Docker, apenas a porta 80 está acessível e vinculada ao Nginx. **Observação:** o contêiner `sharelatex` executa muitos [serviçosarrow-up-right](https://github.com/overleaf/overleaf/tree/main/services) que se comunicam entre si via HTTP. No entanto, essas portas **não** estão acessíveis de fora da rede Docker.
* Dentro da rede Docker, os serviços do Overleaf, o MongoDB, o Redis e o Git Bridge podem comunicar-se livremente entre si.
* Dentro dos contêineres de [compilação em sandbox](/pt/on-premises/configuration/overleaf-toolkit/sandboxed-compiles), nenhuma rede está disponível.
