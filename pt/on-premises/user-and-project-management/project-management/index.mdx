### Visualizar o log de auditoria de um projeto

Os administradores podem ver um **Audit Log** para cada projeto. Este log de auditoria mostra eventos como quando o compartilhamento por link foi alterado entre privado/baseado em token, quando convites foram enviados/aceitos e quando um usuário entrou no projeto usando um token. Os administradores podem visualizar esses logs por projeto em **Your Instance** -> **Admin** -> **Manage Users** e depois:

* Pesquise o usuário
* Clique na aba **Projects**
* Selecione um projeto
* Clique no ícone (i)
* Clique na aba **Audit Log**

Se um projeto for compartilhado com um colaborador nomeado (usando o seu endereço de e-mail), assim que o destinatário entrar, ele será listado na janela de compartilhamento com a sua permissão e ficará visível para o proprietário do projeto. Essa informação também será mostrada aos administradores ao visualizar a aba Project Info do projeto através do painel de administração.

### Recuperar documentos excluídos

1. Entre usando as suas credenciais de administrador
2. Clique em **Admin** e selecione **Manage Users**
3. No campo de pesquisa, insira o e-mail do usuário cujo documento você deseja restaurar
4. Clique no endereço de e-mail dele na lista de resultados para abrir a página de informações do usuário
5. Clique na aba **Projects** e use o campo de pesquisa para procurar o projeto
6. Clique no ícone de informações ao lado do nome do projeto para abrir o **Project Info**
7. Clique na aba **Deleted Docs**
8. Clique no botão **Undelete** ao lado do documento excluído para restaurá-lo no projeto do usuário.

O arquivo restaurado terá o seguinte formato: `FILENAME-TIMESTAMP.EXTENSION`. Por exemplo, uma versão restaurada de `main.tex` será restaurada na raiz do projeto com o nome de arquivo `main-2024-02-23-130441542.tex`.

### Transferir a propriedade de um projeto

O painel de administração do Server Pro tem uma página dedicada para cada projeto. Você pode acessá-la pesquisando o usuário em "/admin/user", indo até a aba **Projects**, encontrando o projeto na lista e clicando no ícone de informações; ou navegando diretamente para a página com um project-id conhecido [**https://your-instance-url/admin/project/**](https://your-instance-url/admin/project/). Na página de informações do projeto, você encontra o botão **Transfer Ownership**, que abre uma janela onde pode especificar qualquer usuário como novo proprietário. O novo proprietário não precisa ser um colaborador existente do projeto.

<Info>

Observe que o proprietário anterior será adicionado como colaborador com acesso de leitura e escrita ao projeto como parte do processo de transferência de propriedade.

</Info>

### Atualizar o tempo limite de compilação do projeto

O tempo limite de compilação padrão para projetos está atualmente definido como 180 segundos. É possível alterar este valor, num processo de duas etapas.

Primeiro, edite o arquivo **config/variables.env**, adicione a variável de ambiente `COMPILE_TIMEOUT` e defina o seu valor como o tempo limite desejado em segundos. Por exemplo, `COMPILE_TIMEOUT=300` para 5 minutos.

<Danger>

Não vale a pena aumentar o tempo limite para mais de 10 minutos. Se fizer isso, provavelmente atingirá um tempo limite em outro componente da aplicação.

</Danger>

Depois de fazer esta alteração, será necessário recriar o contêiner **sharelatex** executando o comando `bin/up -d`.

Definir esta variável de ambiente atualizará o valor do tempo limite apenas para novos usuários; ela **não** será aplicada retroativamente aos usuários existentes, pois o valor é preenchido quando o usuário é criado.

Para ajustar o tempo limite dos usuários existentes, será necessário alterar o registro de cada usuário no banco de dados. Aconselhamos muita cautela ao fazer isso e recomendamos fazer um backup consistente antes de qualquer alteração.

Você encontra informações sobre como fazer backups [aqui](/pt/on-premises/maintenance/data-and-backups).

Para atualizar o valor do tempo limite de compilação de todos os usuários existentes, execute o seguinte comando de shell no host Docker:

```bash wrap
echo 'db.users.updateMany({}, {$set: {"features.compileTimeout": <value>}})' | docker exec -i mongo mongosh --quiet localhost/sharelatex
```

Substitua `<value>` na consulta acima pelo valor de tempo limite desejado em segundos.

Depois de o comando terminar, você deverá ver uma confirmação com o número de registros modificados. Em seguida, pode digitar exit e pressionar a tecla Enter para voltar ao shell do host.

### Rastrear o acesso aos projetos

É possível ver quem carregou um projeto e quando, com o seguinte comando:

```bash wrap
docker exec sharelatex bash -c 'grep "join project request" /var/log/overleaf/web.log'
```

Isso fornecerá o `timestamp`, o `user_id` e o `project_id`.
