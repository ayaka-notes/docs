<Accordion title="Migração do Zotero / Mendeley para instalações existentes">

Ao atualizar para a imagem 6.3.0 relançada, migre os metadados existentes dos arquivos de bibliografia vinculados ao Zotero/Mendeley usando o script abaixo. Esta migração acompanha a correção `12031b8dfd`.

Ela renomeia `zoteroGroupId` / `mendeleyGroupId` para `group_id`, renomeia `importedByUserId` para `importer_id` e remove `importedByName`.

Faça backup do MongoDB e pare a aplicação antes de executar a migração. Mantenha o MongoDB em execução. Abra o shell dele (substitua `mongo` pelo nome do seu contêiner):

```bash
docker exec -it mongo mongosh
```

Execute o seguinte no `mongosh` (substitua `sharelatex` pelo nome do seu banco de dados):

```javascript
use sharelatex

(async () => {
  let updated = 0
  await db.projects.find({}, { rootFolder: 1 }).forEach(async project => {
    const changes = {}
    function visit(folders, path) {
      for (const [i, folder] of (folders || []).entries()) {
        const folderPath = `${path}.${i}`
        for (const [j, file] of (folder.fileRefs || []).entries()) {
          const data = { ...file.linkedFileData }
          if (!["zotero", "mendeley"].includes(data.provider)) continue
          const groupKey = `${data.provider}GroupId`
          if (![groupKey, "importedByUserId", "importedByName"].some(key => key in data)) continue
          for (const [oldKey, newKey] of [[groupKey, "group_id"], ["importedByUserId", "importer_id"]]) {
            if (data[oldKey] != null && data[oldKey] !== "") {
              const value = String(data[oldKey])
              if (newKey in data && data[newKey] !== value) {
                throw new Error(`Conflicting ${newKey}: project ${project._id}, file ${file._id}`)
              }
              data[newKey] = value
            }
            delete data[oldKey]
          }
          delete data.importedByName
          changes[`${folderPath}.fileRefs.${j}.linkedFileData`] = data
        }
        visit(folder.folders, `${folderPath}.folders`)
      }
    }
    visit(project.rootFolder, "rootFolder")
    if (!Object.keys(changes).length) return
    const result = await db.projects.updateOne(
      { _id: project._id, rootFolder: { $eq: project.rootFolder } },
      { $set: changes }
    )
    if (!result.matchedCount) throw new Error(`Project changed during migration: ${project._id}`)
    updated += result.modifiedCount
  })
  print(`Updated ${updated} project(s).`)
})()
```

O script inclui pastas aninhadas e altera apenas os metadados do Zotero/Mendeley. É seguro executá-lo novamente: uma migração concluída informa `Updated 0 project(s).` na execução seguinte. Se ele parar com um conflito, inspecione o projeto/arquivo informado; projetos anteriores podem já ter sido migrados.

Inicie a aplicação atualizada, recarregue o editor e atualize um arquivo de bibliografia existente como o usuário que o importou originalmente. Os snapshots históricos não são reescritos. Para fazer downgrade para a aplicação antiga, restaure o backup do MongoDB.

Temos muito orgulho de anunciar o lançamento do Overleaf Pro 6.3.0, o editor LaTeX online mais poderoso e completo da comunidade. Como sempre nos concentramos em melhorar a experiência dos nossos usuários, esta versão traz grandes mudanças e recursos incríveis que você certamente vai adorar, incluindo o assistente de IA e a integração com gerenciadores de referências de terceiros.

### Alterações

* Assistente de chat com IA: converse com um modelo de IA por meio do seu próprio provedor, diretamente no editor.
* Assistente de erros de LaTeX: receba sugestões de correção geradas por IA para erros de compilação LaTeX.
* Integração com o Mendeley: importe referências do Mendeley, de forma semelhante ao Zotero.
* API Open in Overleaf: adicionada uma API para abrir conteúdo no Overleaf.
* Galeria de templates: adicionadas paginação, busca e ordenação no servidor, para que galerias grandes não precisem mais carregar todos os templates no navegador.
* Traduções: patches de tradução atualizados para a 6.3.0, incluindo novos textos de interface em todos os idiomas suportados.
* Overleaf 6.3.0 upstream: inclui edição de arquivos em abas, logotipos de cabeçalho separados para os temas claro e escuro e atualizações de dependências e da imagem base.
* Adicionadas `OVERLEAF_HEADER_IMAGE_URL_LIGHT` e `OVERLEAF_HEADER_IMAGE_URL_DARK` para suportar imagens de logotipo do cabeçalho separadas para os temas claro e escuro.
* Agora os arquivos podem ser abertos em abas diferentes no editor.
* Adicionado suporte a proxies HTTP(S) configuráveis, incluindo proxies hospedados localmente, via `OVERLEAF_LINKED_URL_OUTBOUND_PROXY`, que também é usada pela API Open in Overleaf.

#### Recurso 04: paginação de templates

Agora a galeria faz a paginação, a ordenação e a busca no MongoDB. Ela funciona sem nenhuma preparação; com milhares de templates, você ainda pode adicionar estes índices para mantê-la rápida (é seguro executar novamente; `mongo`/`sharelatex` = os nomes do seu contêiner e do seu banco de dados):

```bash
docker exec mongo mongosh sharelatex --quiet --eval '
db.templates.createIndex({category:1,lastUpdated:-1},{name:"category_1_lastUpdated_-1",background:true});
db.templates.createIndex({lastUpdated:-1},{name:"lastUpdated_-1",background:true});
db.templates.createIndex({category:1,name:1},{name:"category_1_name_1_ci",collation:{locale:"en",strength:2},background:true});
db.templates.createIndex({name:1},{name:"name_1_ci",collation:{locale:"en",strength:2},background:true});
'
```

Mantenha a `collation` nos dois índices `*_ci` exatamente como está escrita — a galeria faz as consultas com a mesma collation, e o MongoDB só usa um índice correspondente.

## Ayakaleaf Pro 6.2.2

**Data de lançamento:** 2026.07.23

Veja: [https://github.com/ayaka-notes/ayakaleaf-pro/releases/tag/pro-v6.2.2](https://github.com/ayaka-notes/ayakaleaf-pro/releases/tag/pro-v6.2.2)

### Alterações

Backport dos patches de hotfix oficiais lançados no Overleaf `6.2.2` upstream (sobre a `6.2.1`):

* O segredo do token de convite de projeto deixou de vazar para os logs. O criptografador de tokens de convite registrava sua própria configuração em cada criptografia/descriptografia, o que incluía as senhas de cifra derivadas de `OVERLEAF_INVITE_TOKEN_SECRET`.
* Migração do envio de e-mails do cliente AWS SES v1, que chegou ao fim de vida, para o SESv2. Instâncias configuradas com o driver de e-mail `ses` podiam não conseguir enviar nenhum e-mail; agora o envio passa pelo `SESv2Client`.
* As entradas de grupo do menu suspenso de compartilhamento de projeto agora ficam condicionadas à nova feature flag `group-link-sharing`, para que o compartilhamento de link de grupo não seja mais oferecido em instâncias onde não se aplica.
* Correção do modal de compartilhamento de projeto para colaboradores. Abri-lo sem ser o proprietário, ou com o fluxo `sharing-updates` desativado, gerava uma requisição que sempre falhava e exibia um erro "something went wrong".
* Adicionado `scripts/flush_docs_with_pending_updates.js` ao document-updater, um script de manutenção que recupera documentos que ficaram com uma fila `PendingUpdates` travada no Redis depois que seu projeto foi gravado (flush) ou excluído definitivamente. Suporta `--dry-run` e uma verificação de segurança `--estimated-docs`.
* Atualização de dependências: `multer` 2.2.0, `form-data` 2.5.6, `protobufjs` 7.6.3, `@grpc/grpc-js` 1.14.4.

Esta versão também inclui as seguintes correções e melhorias do Ayakaleaf Pro:

* Adicionadas traduções completas para 16 idiomas adicionais (cs, da, de, es, fi, fr, it, ja, ko, nl, no, pl, pt, ru, sv, tr), corrigindo textos não traduzidos, como a página de redefinição de senha. Corrige [#38](https://github.com/ayaka-notes/ayakaleaf-pro/issues/38).
* Correção da contagem de itens no botão "show N more projects" do painel de administração, que mostrava o número errado porque o placeholder de plural não era passado corretamente.
* Correção dos erros de validação da exportação para o GitHub, que agora são renderizados por meio de chaves de i18n estáticas em vez de mensagens brutas, e remoção das chaves de erro que não são mais usadas pelo modal do GitHub Sync.

Backport dos patches de hotfix oficiais lançados no Overleaf `6.2.1` upstream (sobre a `6.2.0`):

Evita problemas espúrios de sincronização / "alterações não salvas" relacionados ao desfazer e à edição simultânea.

## Ayakaleaf Pro 6.2.0

**Data de lançamento:** 2026.07.10

Temos orgulho de anunciar o lançamento do Overleaf Pro 6.2.0, o editor LaTeX online mais poderoso e completo da comunidade. Agradecimentos especiais a yu-i-i e davrot por suas valiosas contribuições. Eles aprimoraram o GitHub Sync e introduziram a Busca avançada de citações e a integração com o Zotero.

### Observações

<Warning>

* Foi introduzida uma nova variável de ambiente obrigatória, `OVERLEAF_INVITE_TOKEN_SECRET`. Você deve gerá-la com `openssl rand -base64 32`. Se ela não estiver configurada, sua instância do Overleaf não conseguirá iniciar.
* Se você habilitar o GitHub Sync, deverá configurar a variável de ambiente `GITHUB_TOKEN_CIPHER_PASSWORD`. Essa variável é necessária para criptografar com segurança os tokens de acesso do GitHub. Sem ela, sua instância do Overleaf não conseguirá iniciar.

</Warning>

* Adicionada uma nova variável de ambiente, `DEFAULT_LATEX_COMPILER`, para definir o compilador padrão usado por novos projetos (`pdflatex`, `latex`, `xelatex` ou `lualatex`).
* O editor reformulado agora é a única opção disponível.

Esta versão inclui as seguintes melhorias e novos recursos.

* `MAX_UPLOAD_SIZE` agora é configurável, em vez de ser limitado a **50 MB**.
* Corrigido um loop de reinicialização do contêiner quando as compilações em sandbox estavam desativadas.
* Aplicada a exclusão de PATs restrita ao proprietário para OAuth2.
* Corrigido um problema de importação do LDAP.

Os recursos incluem:

* Adicionado um executor de Python baseado no navegador.
* Adicionado suporte ao Pandoc para importar e exportar Markdown, DOCX e outros formatos.
* Adicionado o GitHub Sync.
* Adicionadas traduções completas para o chinês.
* Adicionada a integração com o Zotero.
* Adicionada `DEFAULT_LATEX_COMPILER`.

### Migração de arquivos binários

Esta nova versão reduz pela metade o uso de armazenamento dos arquivos binários.

Uma migração online está incluída na versão `5.5`, permitindo um tempo de inatividade mínimo como parte da atualização. Antes de atualizar para o Server Pro `v6`, certifique-se de que você já está executando a versão mais recente do Server Pro `v5.5` ([Notas de versão 5.x.x](https://docs.overleaf.com/on-premises/release-notes/release-notes-5.x.x)) e de que executou a migração.

[Veja as instruções completas de migração](https://docs.overleaf.com/on-premises/release-notes/release-notes-5.x.x/binary-files-migration).

### Atualização do MongoDB para a v8

Esta versão eleva a versão mínima do MongoDB para `8.0`.

Se você usa atualmente o MongoDB `v6` ou anterior, precisará atualizar uma versão principal de cada vez (`v6 → v7 → v8`).

<Warning>

Certifique-se de ter um backup do [banco de dados](https://docs.overleaf.com/on-premises/maintenance/data-and-backups) **antes** de atualizar. Em caso de rollback, você precisará restaurar o backup do banco de dados.

</Warning>

Para instruções sobre como atualizar o MongoDB `v6 → v7 → v8`, consulte nosso guia passo a passo [aqui](https://docs.overleaf.com/on-premises/maintenance/updating-mongodb#example-upgrading-mongodb-from-6.0-to-7.0-toolkit-users).

### Atualização do Redis para a v7.4

Esta versão também eleva a versão mínima do Redis para `7.4`.

Atualize o `REDIS_IMAGE` no seu `config/overleaf.rc` para `REDIS_IMAGE=7.4`.

### Novos recursos

* O compartilhamento por link agora pode ser desativado com `OVERLEAF_DISABLE_LINK_SHARING=true`.
* `OVERLEAF_MAINTENANCE_MESSAGE` e `OVERLEAF_MAINTENANCE_MESSAGE_HTML` agora estão disponíveis para personalizar o título e o conteúdo da página de manutenção.
* `OVERLEAF_USER_HARD_DELETION_DELAY` e `OVERLEAF_PROJECT_HARD_DELETION_DELAY` podem ser configuradas (em milissegundos) para modificar o prazo de expiração de usuários/projetos excluídos (o padrão é 90 dias).

### Correções de bugs

* Corrigida a renderização do rodapé com links.
* Melhoradas as mensagens de erro em falhas de login via SAML.
* Corrigida a ausência de entrada no log de auditoria quando o status de administrador de um usuário é atualizado no login via SSO.
* Corrigidos erros no painel de histórico quando o TLS está habilitado no Redis.
* Agora é possível interromper compilações ao usar compilações sem sandbox.

### Outras alterações

* Todos os links para a página de status (definida via `OVERLEAF_STATUS_PAGE_URL`) agora usam `HTTPS` e abrem em uma nova aba do navegador.
