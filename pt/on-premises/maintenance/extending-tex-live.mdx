É possível estender uma imagem existente do TeX Live usando um novo Dockerfile e configurar a aplicação para usar a nova imagem.

Aqui estão algumas orientações para instalar novos pacotes ou fontes.

As imagens do TeX Live recebem atualizações pouco frequentes. Sugerimos reconstruir as imagens personalizadas ao atualizar o Ayakaleaf Pro.

<Danger>

As seções a seguir se aplicam apenas aos [Sandboxed Compiles](/pt/on-premises/configuration/overleaf-toolkit/sandboxed-compiles).

</Danger>

### Instalando e atualizando novos pacotes

Você pode usar comandos do `tlmgr`, como `tlmgr install` e `tlmgr update`, para gerenciar pacotes do Tex Live, como no exemplo a seguir:

```dockerfile
FROM ghcr.io/ayaka-notes/texlive-full:2023.1

RUN tlmgr update --force ebproof
```

### Usando o `tlmgr` em uma imagem mais antiga do TeX Live

Por padrão, o `tlmgr` baixa recursos da versão mais recente do TeX Live. Ao corrigir uma imagem mais antiga do TeX Live, os downloads precisam ser direcionados para o arquivo histórico correspondente. Consulte a lista em [https://www.tug.org/historic/](https://www.tug.org/historic/) para ver os espelhos dos arquivos históricos.

```dockerfile
FROM ghcr.io/ayaka-notes/texlive-full:2022.1

RUN tlmgr option repository <MIRROR>/systems/texlive/<YEAR>/tlnet-final
# e.g. RUN tlmgr option repository ftp://tug.org/historic/systems/texlive/2022/tlnet-final

RUN tlmgr update --force ebproof
```

### Instalando novas fontes

Existem diferentes procedimentos para instalar novas fontes em uma distribuição Tex Live, e a instalação de uma fonte personalizada pode exigir várias etapas. Consultar as [instruções para instalar fontes TeX](https://tug.org/fonts/fontinstall.html) na documentação oficial do Tex Live provavelmente é um bom ponto de partida.

O `Dockerfile` a seguir mostra um exemplo de instalação de uma fonte TrueType sobre uma imagem existente do Tex Live 2022:

```dockerfile
FROM ghcr.io/ayaka-notes/texlive-full:2022.1

COPY ./myfonts/*.ttf /usr/share/fonts/truetype/myfont/

# rebuild font information cache
RUN fc-cache
```

### Configurando o Ayakaleaf Pro para usar as novas imagens

Use o nome `ghcr.io/ayaka-notes/texlive-full` e uma tag personalizada para construir a nova imagem, como em:

```bash
docker build -t ghcr.io/ayaka-notes/texlive-full:2023.1-custom .
```

Agora podemos configurar o Ayakaleaf Pro para usar a nova imagem `2023.1-custom` atualizando as variáveis de ambiente `TEX_LIVE_DOCKER_IMAGE`, `ALL_TEX_LIVE_DOCKER_IMAGES` e `ALL_TEX_LIVE_DOCKER_IMAGE_NAMES` (os nomes são opcionais e seguem a ordem das imagens):

```text wrap
TEX_LIVE_DOCKER_IMAGE: "ghcr.io/ayaka-notes/texlive-full:2023.1-custom"
ALL_TEX_LIVE_DOCKER_IMAGES: "ghcr.io/ayaka-notes/texlive-full:2023.1,ghcr.io/ayaka-notes/texlive-full:2023.1-custom"
ALL_TEX_LIVE_DOCKER_IMAGE_NAMES: "TeX Live 2023,TeX Live 2023 custom"
```

No exemplo acima, os novos projetos são configurados por padrão para usar a nova imagem `2023.1-custom`, enquanto a `2023.1` continua disponível para quando for necessária.

A imagem personalizada existe apenas no seu host, então o `bin/up` não consegue baixá-la. Defina `SIBLING_CONTAINERS_PULL=false` em `config/overleaf.rc` (baixe as outras imagens você mesmo com `docker pull`) e, em seguida, execute `bin/up -d` para aplicar as novas configurações.

### Q\&A

<Accordion title="Preciso instalar fontes chinesas para compilar documentos em chinês com XeLaTeX?">

<strong>Resposta:</strong> Não, não com as imagens `texlive-full`. Elas incluem os pacotes chineses do TeX Live (`ctex`, `xeCJK`) com as fontes Fandol, além das fontes Noto CJK (por exemplo, `Noto Serif CJK SC`). Defina o compilador do projeto como XeLaTeX nas configurações do editor e compile, por exemplo:

```latex
\documentclass{ctexart}
\begin{document}
你好，世界！
\end{document}
```

Para usar a Noto em vez da Fandol, adicione `\setCJKmainfont{Noto Serif CJK SC}`. Nenhum `latexmkrc` é necessário. Para outras fontes, crie uma imagem personalizada como mostrado em [Instalando novas fontes](#instalando-novas-fontes).

</Accordion>
