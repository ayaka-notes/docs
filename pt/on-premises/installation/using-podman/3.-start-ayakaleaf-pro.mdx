---
title: 3. Iniciar o Ayakaleaf Pro
description: Inicie o Ayakaleaf Pro no Podman, verifique-o com o podman-setup e o bin/doctor e inicie-o após reinicializações.
icon: circle-play
---

<Steps>
<Step title="Iniciar os contêineres">
```bash title="Start Ayakaleaf Pro"
bin/up -d
```

A primeira inicialização baixa as imagens do MongoDB, do Redis e do TeX Live e cria os diretórios de dados em `data/`. Ela exibe um aviso de que o suporte ao Podman é experimental.

<Info>

A primeira inicialização também pode exibir `MongoNetworkError: connect ECONNREFUSED 127.0.0.1:27017`. O Toolkit configura o replica set do MongoDB enquanto o MongoDB ainda está iniciando e tenta novamente até ele responder. Você pode ignorar essa linha.

</Info>

Depois de um ou dois minutos, verifique se os contêineres estão rodando:

```bash title="List the containers"
podman ps --format "{{.Names}} {{.Status}}"
```

```text
mongo Up 34 seconds (healthy)
redis Up 20 seconds
sharelatex Up 20 seconds
```
</Step>

<Step title="Verificar a configuração novamente">
Agora que os diretórios de dados existem e o contêiner `sharelatex` está rodando, o `bin/podman-setup` pode concluir suas verificações:

```bash title="Check the setup"
bin/podman-setup
```

Ele verifica os donos dos novos diretórios de dados e testa o socket do Podman de dentro do contêiner `sharelatex`:

```text
====== Socket Connectivity ======
[✓] host → socket OK
[✓] container → socket OK

====== Data Directory Permissions ======
[✓] mongo data dir owned by 999
[✓] redis data dir owned by 999
[✓] overleaf data dir owned by 33
...
====== Summary ======
[✓] 27 passed  [!] 1 warnings  [✗] 0 failures
[!] Warnings:
[!] not logged in to quay.io
```

`container → socket OK` significa que o Ayakaleaf Pro pode iniciar contêineres de compilação. Se uma verificação falhar, execute `bin/podman-setup --apply` e depois `bin/up -d`. O aviso do quay.io não se aplica ao Ayakaleaf Pro, veja [2. Executar o podman-setup](/pt/on-premises/installation/using-podman/2.-run-podman-setup).
</Step>

<Step title="Executar o doctor">
```bash title="Run the doctor"
bin/doctor
```

No Podman, o relatório mostra o runtime e as configurações de segurança:

```text
- Container Daemon
    - status: up
    - runtime: podman
    - server version: 5.8.5
    - socket: /run/user/1000/podman/podman.sock
    - DOCKER_HOST: unix:///run/user/1000/podman/podman.sock
    - host → socket: OK
    - container → socket: OK
- Security
    - SELinux: Enforcing
    - SELINUX_MODE: managed
    - SELINUX_LABEL: sharelatex_t
    - SELinux module: loaded (podman_socket_clsi)
    - SELinux rules: present
    - Seccomp profile: present
```

O aviso `Server Pro enabled, but not logged in to quay.io repository` no final é a mesma verificação do quay.io, veja [Obtendo ajuda](/pt/on-premises/support/getting-help#q-and-a).
</Step>

<Step title="Iniciar o Ayakaleaf Pro após uma reinicialização">
Com o Docker, o daemon do Docker inicia os contêineres novamente após uma reinicialização. O Podman rootless não tem daemon: ative o serviço de usuário que inicia seus contêineres quando o servidor liga:

```bash title="Start the containers at boot"
systemctl --user enable podman-restart.service
```

Ele inicia todos os contêineres do seu usuário cuja política de reinício é `always`, que o Toolkit define para todos os seus contêineres. Isso requer o lingering, que o `bin/podman-setup --apply` ativou. Sem esse serviço, execute `bin/up -d` após cada reinicialização.
</Step>

<Step title="Abrir a porta no firewall">
Por padrão, a instância só aceita conexões do próprio servidor, em `http://localhost:8080`. Para abri-la a partir de outros computadores, defina `OVERLEAF_LISTEN_IP` em `config/overleaf.rc` e `OVERLEAF_SITE_URL` em `config/variables.env` conforme descrito em [5. Personalizando sua instância](/pt/on-premises/installation/using-docker-compose/linux/5.-personalizing-your-instance#listen-address-and-port) e execute `bin/up -d` novamente.

Ao contrário do Docker, o Podman rootless não ignora o firewall do host. Se o `firewalld` estiver rodando, o que é o padrão no RHEL, abra a porta:

```bash title="Open port 8080"
sudo firewall-cmd --permanent --add-port=8080/tcp
sudo firewall-cmd --reload
```

Em um servidor na nuvem, libere também a porta no grupo de segurança do provedor. Use HTTPS antes de expor a instância à internet, veja [4. Tarefas pós-instalação](/pt/on-premises/installation/using-podman/4.-post-installation-tasks#use-https).
</Step>
</Steps>
