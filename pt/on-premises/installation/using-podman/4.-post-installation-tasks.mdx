### Criar sua primeira conta de administrador {#create-your-first-administrator-account}

Abra [http://localhost:8080/launchpad](http://localhost:8080/launchpad), ou o seu `OVERLEAF_SITE_URL` seguido de `/launchpad`, e registre a conta de administrador. A partir daqui, tudo funciona como no Docker: siga [6. Tarefas pós-instalação](/pt/on-premises/installation/using-docker-compose/linux/6.-post-installation-tasks) do guia do Docker, usando a porta `8080` nos links de `localhost`.

Crie o projeto de exemplo e compile-o. O PDF mostra que as compilações rodam em seus contêineres TeX Live por meio do Podman. Para ver o contêiner de compilação:

```bash title="List the compile containers"
podman ps -a --filter name=project- --format "{{.Names}} {{.Image}} {{.Status}}"
```

### Usar HTTPS {#use-https}

O [Proxy TLS](/pt/on-premises/configuration/overleaf-toolkit/tls-proxy) do Toolkit funciona no Podman: execute `bin/init --tls` e defina seu certificado e `NGINX_ENABLED=true` conforme descrito lá. Ele escuta nas portas `80` e `443`, que o Podman rootless não pode usar por padrão. Permita que usuários sem privilégios usem portas a partir da `80`:

```bash title="Allow ports 80 and 443"
echo "net.ipv4.ip_unprivileged_port_start=80" | sudo tee /etc/sysctl.d/99-unprivileged-ports.conf
sudo sysctl --system
```

Isso permite que qualquer usuário do servidor escute nessas portas, então faça isso apenas em um servidor dedicado ao Ayakaleaf Pro. Depois, abra-as no firewall:

```bash title="Open ports 80 and 443"
sudo firewall-cmd --permanent --add-port=80/tcp --add-port=443/tcp
sudo firewall-cmd --reload
```

Defina `OVERLEAF_SITE_URL` com o seu endereço `https://` e execute `bin/up -d`. Mantenha os padrões `NGINX_HTTP_PORT=80` e `TLS_PORT=443`: com outras portas, o redirecionamento de HTTP para HTTPS leva à porta errada.

<Info>

Deixe `OVERLEAF_LISTEN_IP` em `127.0.0.1` quando usar o proxy TLS, para que a porta `8080` não fique acessível a partir de outros computadores.

</Info>

### Atualizar {#upgrade}

Atualize com `bin/upgrade`, conforme descrito em [Atualizar sua implantação](/pt/on-premises/maintenance/upgrading-your-deployment). No Podman, ele também extrai o perfil seccomp da nova versão para `config/seccomp/<version>/` e atualiza `SECCOMP_PROFILE`:

```text
Over-writing config/version with 6.3.4
Set SECCOMP_PROFILE=/home/<user>/overleaf-toolkit/config/seccomp/6.3.4/clsi-profile.json in config/variables.env
```

Após uma atualização, execute `bin/podman-setup` para verificar a configuração.

### Alterar o modo do SELinux {#change-the-selinux-mode}

`SELINUX_MODE` em `config/overleaf.rc` define como o SELinux restringe o contêiner `sharelatex`. `managed` é o modo que estas páginas configuram; os outros modos são descritos em [Configurações do Toolkit](/pt/on-premises/configuration/overleaf-toolkit/toolkit-settings). Execute `bin/up -d` depois de alterá-lo.
