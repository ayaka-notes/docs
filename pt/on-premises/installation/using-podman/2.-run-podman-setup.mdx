O `bin/podman-setup` verifica tudo o que o Ayakaleaf Pro precisa no Podman. Sem opções, ele apenas relata; com `--apply`, também corrige o que encontra.

<Steps>
<Step title="Verificar o host">
```bash title="Check only"
bin/podman-setup
```

Em um host limpo, a maioria das verificações falha, por exemplo:

```text
====== Packages ======
[✗] podman not installed
[✗] podman-docker not installed
...
====== Summary ======
[✓] 7 passed  [!] 13 warnings  [✗] 4 failures
```
</Step>

<Step title="Aplicar as correções">
```bash title="Check and fix"
bin/podman-setup --apply
```

Execute-o em um terminal: ele pede sua senha do `sudo` para as etapas que afetam todo o sistema. Ele também baixa a imagem do Ayakaleaf Pro para extrair o perfil seccomp, o que leva alguns minutos na primeira vez. Ao final, ele verifica o host novamente:

```text
====== Summary ======
[✓] 23 passed  [!] 2 warnings  [✗] 0 failures
[!] Warnings remaining:
[!] not logged in to quay.io
[!] container → socket skipped (sharelatex not running)
```

Os dois avisos são esperados neste momento:

* `not logged in to quay.io`: a verificação vem do Toolkit oficial, em que a imagem do Server Pro fica em um registro privado. As imagens do Ayakaleaf Pro são públicas no `ghcr.io` e não precisam de login, então ignore-o. Ele continua aparecendo após a instalação.
* `container → socket skipped (sharelatex not running)`: este teste precisa da instância em execução. Você executa o script novamente em [3. Iniciar o Ayakaleaf Pro](/pt/on-premises/installation/using-podman/3.-start-ayakaleaf-pro).

O script termina com `0` quando todas as verificações passam, `1` quando há avisos e `2` quando há falhas. Por causa do aviso do quay.io, espere `1`.
</Step>
</Steps>

### O que o script altera {#what-the-script-changes}

Com `--apply`, o script pode alterar o seguinte.

Em todo o sistema, com `sudo`:

* Instala `podman`, `podman-docker`, `git`, `curl`, `checkpolicy` e `policycoreutils` com o `dnf`.
* Ativa o lingering para o seu usuário com o `loginctl`, para que seus contêineres continuem rodando depois que você sair.
* Cria `/etc/containers/nodocker`, o que silencia a mensagem "Emulate Docker CLI using podman".
* Carrega o módulo de política do SELinux `podman_socket_clsi`, quando `SELINUX_MODE=managed`.

Para o seu usuário:

* Ativa o serviço de usuário `podman.socket`, a API compatível com Docker que o Ayakaleaf Pro usa para iniciar compilações.
* Instala o Docker Compose v2 a partir do GitHub em `~/.local/bin/docker-compose` e cria um link para ele em `~/.docker/cli-plugins/`.
* Faz o Podman usar esse Compose em `~/.config/containers/containers.conf`.
* Adiciona os aliases `mongo` e `redis` em `~/.config/containers/registries.conf.d/overleaf-toolkit.conf`, para que o Podman saiba de onde baixar esses nomes curtos de imagem.

No Toolkit:

* Define `DOCKER_SOCKET_PATH` e `DOCKER_HOST` em `config/overleaf.rc` como `/run/user/<uid>/podman/podman.sock`.
* Extrai o perfil seccomp para compilações da imagem do Ayakaleaf Pro para `config/seccomp/<version>/clsi-profile.json` e define `SECCOMP_PROFILE` em `config/variables.env`. Ao contrário do Docker, o Podman precisa desse perfil como um arquivo no host.
* Compila o módulo de política do SELinux em `config/selinux/`.
* Define os donos dos diretórios de dados em `data/` com `podman unshare chown`, assim que eles existirem.

<Info>

Cada alteração corresponde a uma verificação. Se você alterar algo manualmente, por exemplo em `config/overleaf.rc`, execute o `bin/podman-setup` novamente para verificar.

</Info>
