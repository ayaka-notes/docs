---
title: 1. Baixar e inicializar o Toolkit
description: Clone o Ayakaleaf Toolkit, crie a configuração e ajuste-a para o Ayakaleaf Pro no Podman.
icon: arrow-down-to-bracket
---

<Steps>
<Step title="Clonar o Toolkit">
Clone o **Ayakaleaf Toolkit** ([ayaka-notes/toolkit](https://github.com/ayaka-notes/toolkit)) no seu diretório pessoal e entre nele:

```bash title="Clone the Toolkit" wrap
git clone https://github.com/ayaka-notes/toolkit.git ~/overleaf-toolkit
cd ~/overleaf-toolkit
```

Execute todos os comandos seguintes a partir deste diretório.
</Step>

<Step title="Criar a configuração">
```bash title="Run initialization"
bin/init
```

Isso cria `config/overleaf.rc`, `config/variables.env` e `config/version`, conforme descrito em [3. Inicializar a configuração](/pt/on-premises/installation/using-docker-compose/linux/3.-initialize-the-configuration) do guia do Docker. O `bin/init` ainda não precisa do Podman.
</Step>

<Step title="Configurar o config/overleaf.rc">
Abra `config/overleaf.rc` e altere estas linhas:

```bash title="config/overleaf.rc"
SERVER_PRO=true
OVERLEAF_PORT=8080
SIBLING_CONTAINERS_ENABLED=true
```

Depois, adicione esta linha ao final do arquivo:

```bash title="config/overleaf.rc"
SELINUX_MODE=managed
```

| Configuração                      | Por quê                                                                                                                                                                                                      |
| --------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `SERVER_PRO=true`                 | Usa a imagem do Ayakaleaf Pro do `ghcr.io`. Não é necessário fazer login.                                                                                                                                    |
| `OVERLEAF_PORT=8080`              | O Podman rootless não pode escutar em portas abaixo de `1024`. A porta padrão `80` falha.                                                                                                                     |
| `SIBLING_CONTAINERS_ENABLED=true` | Executa cada compilação em seu próprio contêiner TeX Live. Já é `true` por padrão; a configuração do Podman só oferece suporte a este modo.                                                                    |
| `SELINUX_MODE=managed`            | Executa o contêiner `sharelatex` com o tipo SELinux `sharelatex_t`, que pode usar o socket do Podman e nada mais. O `bin/podman-setup --apply` instala o módulo de política para ele. Veja [Configurações do Toolkit](/pt/on-premises/configuration/overleaf-toolkit/toolkit-settings) para os outros modos. |

Deixe `DOCKER_SOCKET_PATH` como está: o `bin/podman-setup --apply` o define para o seu socket do Podman no próximo passo.

<Warning>

Mantenha `GIT_BRIDGE_ENABLED=false`. No Ayakaleaf Pro 6.3.4, a integração com Git não funciona no Podman, veja [Limitações conhecidas](/pt/on-premises/installation/using-podman#known-limitations).

</Warning>
</Step>

<Step title="Escolher as imagens do TeX Live">
Abra `config/variables.env`, remova o `#` antes de `TEX_LIVE_DOCKER_IMAGE` e `ALL_TEX_LIVE_DOCKER_IMAGES` e liste as imagens do TeX Live a usar:

```bash title="config/variables.env" wrap
TEX_LIVE_DOCKER_IMAGE=ghcr.io/ayaka-notes/texlive-full:2026.1
ALL_TEX_LIVE_DOCKER_IMAGES=ghcr.io/ayaka-notes/texlive-full:2026.1
```

O `bin/up` para com `Please configure ALL_TEX_LIVE_DOCKER_IMAGES` se a lista estiver vazia. A `texlive-full` é grande; para um servidor de teste, a muito menor `ghcr.io/ayaka-notes/texlive-basic:2026.1` também funciona. Veja [Sandboxed Compiles](/pt/on-premises/configuration/overleaf-toolkit/sandboxed-compiles) para as imagens disponíveis.

Defina as outras variáveis, como `OVERLEAF_SITE_URL`, conforme descrito em [5. Personalizando sua instância](/pt/on-premises/installation/using-docker-compose/linux/5.-personalizing-your-instance#required-environment-variables). Com o endereço de escuta padrão, use `http://localhost:8080`.
</Step>
</Steps>
