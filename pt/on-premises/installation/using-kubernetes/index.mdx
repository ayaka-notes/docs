O [Toolkit](/pt/on-premises/installation/using-the-toolkit) é a forma recomendada de executar o Ayakaleaf Pro em um único servidor. Se você já executa um cluster Kubernetes, esta seção implanta o mesmo contêiner nele com manifestos `kubectl` simples: nenhuma imagem extra, nenhum Helm chart.

Ao final desta seção, você terá uma instância do Ayakaleaf Pro com Sandboxed Compiles, um replica set do MongoDB e o Redis, todos no namespace `overleaf`. Para executar várias instâncias atrás de um balanceador de carga, continue depois com [Escalonamento horizontal](/pt/on-premises/configuration/kubernetes/horizontal-scaling).

<Info>

O suporte ao Kubernetes é experimental. Não publicamos um Helm chart nem imagens específicas para Kubernetes. Os manifestos destas páginas são os que testamos no Kubernetes 1.37 (kubeadm, containerd 2.4, flannel) com três nós de 2 vCPUs e 4 GB de memória cada. Adapte o armazenamento, a rede e o ingress ao seu cluster.

</Info>

### Como as peças se encaixam

| Toolkit (um servidor)                        | Kubernetes                                                               |
| -------------------------------------------- | ------------------------------------------------------------------------ |
| `config/variables.env`                       | ConfigMap `overleaf-env` e Secret `overleaf-secrets`                     |
| contêiner `sharelatex`                       | Deployment `overleaf` (um pod executando todos os serviços do Overleaf)  |
| contêineres `mongo` e `redis`                | StatefulSets `mongo` (replica set) e `redis`, ou seus serviços gerenciados |
| `~/overleaf-toolkit/data/overleaf`           | PersistentVolumeClaim `overleaf-data`                                    |
| Docker no host, usado para as compilações    | Docker Engine em cada nó que executa o Ayakaleaf Pro                     |
| `bin/up`, `bin/logs`, `bin/shell`            | `kubectl apply`, `kubectl logs`, `kubectl exec`                          |

### O que você precisa

* Um cluster Kubernetes em que você possa instalar pacotes: cada nó que pode executar o Ayakaleaf Pro precisa do **Docker Engine**, porque as compilações são executadas em contêineres do TeX Live que o Ayakaleaf Pro inicia por meio do `/var/run/docker.sock` do nó. Veja [0. Preparar os nós](/pt/on-premises/installation/using-kubernetes/0.-prepare-the-nodes).
* Uma StorageClass padrão com volumes `ReadWriteOnce`.
* `kubectl` e `openssl` na sua estação de trabalho.
