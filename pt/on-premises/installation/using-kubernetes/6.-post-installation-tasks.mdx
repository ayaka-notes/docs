### Criando sua primeira conta de administrador {#creating-your-first-administrator-account}

Abra `OVERLEAF_SITE_URL` seguido de `/launchpad`, por exemplo `http://192.0.2.10:30080/launchpad`, e registre a conta de administrador como nas [tarefas pós-instalação do Toolkit](/pt/on-premises/installation/using-docker-compose/linux/6.-post-installation-tasks). Em seguida, crie um projeto de exemplo e compile-o.

Você também pode criar usuários pela linha de comando:

```bash
kubectl -n overleaf exec deploy/overleaf -- bash -c \
  'cd /overleaf/services/web && node modules/server-ce-scripts/scripts/create-user.mjs --admin --email=admin@example.com'
```

Ele exibe um link que define a senha.

### Verificando se as compilações estão em sandbox {#checking-that-compiles-are-sandboxed}

Compile um projeto e depois examine o nó que executa o pod:

```bash
kubectl -n overleaf get pod -l app=overleaf -o wide   # NODE column
# on that node:
sudo docker ps -a --filter ancestor=ghcr.io/ayaka-notes/texlive-full:2026.1
ls -ln /srv/overleaf/compiles                          # owned by uid 33 (www-data)
```

Cada compilação aparece como um contêiner de curta duração chamado `project-<project id>-<user id>-...`.

### Logs e um shell {#logs-and-a-shell}

| Toolkit          | Kubernetes                                                               |
| ---------------- | ------------------------------------------------------------------------ |
| `bin/logs web`   | `kubectl -n overleaf exec deploy/overleaf -- tail -f /var/log/overleaf/web.log` |
| `bin/shell`      | `kubectl -n overleaf exec -it deploy/overleaf -- bash`                    |
| `bin/up`         | `kubectl apply -f .` e depois `kubectl -n overleaf rollout restart deployment/overleaf` |

O contêiner grava um arquivo de log por serviço em `/var/log/overleaf/` (`web.log`, `clsi.log`, `real-time.log`, `document-updater.log`, ...); `kubectl logs` mostra a saída de inicialização.

### Q\&A {#q&a}

<Accordion title="A compilação falha ou nunca termina.">

<strong>Resposta:</strong> Verifique, no nó que executa o pod, se o Docker está em execução e tem a imagem indicada em `TEX_LIVE_DOCKER_IMAGE`, e se `SANDBOXED_COMPILES_HOST_DIR_*` correspondem aos caminhos `hostPath`. O `/var/log/overleaf/clsi.log` no pod indica a etapa que falhou.

</Accordion>

<Accordion title="Os usuários são desconectados após cada reinicialização do pod.">

<strong>Resposta:</strong> `OVERLEAF_SESSION_SECRET` está ausente do Secret `overleaf-secrets`, veja a [etapa 2](/pt/on-premises/installation/using-kubernetes/2.-create-the-namespace-and-secrets).

</Accordion>
