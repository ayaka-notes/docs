```yaml title="40-overleaf.yaml" wrap
apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  name: overleaf-data
  namespace: overleaf
spec:
  accessModes: [ReadWriteOnce]
  resources:
    requests:
      storage: 20Gi
---
apiVersion: apps/v1
kind: Deployment
metadata:
  name: overleaf
  namespace: overleaf
spec:
  replicas: 1
  strategy:
    type: Recreate          # one pod owns the data volume; never run two at once
  selector:
    matchLabels:
      app: overleaf
  template:
    metadata:
      labels:
        app: overleaf
    spec:
      terminationGracePeriodSeconds: 60   # time to flush pending edits, like the Toolkit
      # Keep the environment to what the ConfigMap and Secret set: no REDIS_PORT=tcp://... and the like
      enableServiceLinks: false
      containers:
        - name: sharelatex
          image: ghcr.io/ayaka-notes/overleaf-pro:6.3.2
          envFrom:
            - configMapRef:
                name: overleaf-env
            - secretRef:
                name: overleaf-secrets
          ports:
            - containerPort: 80
          readinessProbe:
            httpGet:
              path: /status
              port: 80
            periodSeconds: 10
          resources:
            requests:
              cpu: 500m
              memory: 1536Mi
            limits:
              memory: 3Gi
          volumeMounts:
            - name: data
              mountPath: /var/lib/overleaf
            - name: compiles
              mountPath: /var/lib/overleaf/data/compiles
            - name: output
              mountPath: /var/lib/overleaf/data/output
            - name: cache
              mountPath: /var/lib/overleaf/data/cache
            - name: docker-sock
              mountPath: /var/run/docker.sock
      volumes:
        - name: data
          persistentVolumeClaim:
            claimName: overleaf-data
        # Compile scratch space on the node; same paths as SANDBOXED_COMPILES_HOST_DIR_*
        - name: compiles
          hostPath:
            path: /srv/overleaf/compiles
            type: DirectoryOrCreate
        - name: output
          hostPath:
            path: /srv/overleaf/output
            type: DirectoryOrCreate
        - name: cache
          hostPath:
            path: /srv/overleaf/cache
            type: DirectoryOrCreate
        - name: docker-sock
          hostPath:
            path: /var/run/docker.sock
            type: Socket
---
apiVersion: v1
kind: Service
metadata:
  name: overleaf
  namespace: overleaf
spec:
  type: NodePort
  selector:
    app: overleaf
  ports:
    - name: http
      port: 80
      targetPort: 80
      nodePort: 30080
```

```bash
kubectl apply -f 40-overleaf.yaml
kubectl -n overleaf rollout status deployment/overleaf --timeout=10m
kubectl -n overleaf logs deployment/overleaf | grep -E 'Finished migrations|Missing required'
```

A primeira inicialização executa as migrações do banco de dados e leva um ou dois minutos. O pod está pronto quando `/status` responde; então abra `OVERLEAF_SITE_URL`.

### Por que o manifesto é assim

* <strong>Volume de dados.</strong> Tudo em `/var/lib/overleaf` (arquivos dos projetos, histórico, uploads) fica no PVC. Com armazenamento local do nó, como o local-path, os dados ficam em um único nó; com armazenamento em bloco de rede, o pod pode se mover entre os nós.
* <strong>Volumes de compilação e o socket do Docker.</strong> O Ayakaleaf Pro pede ao Docker do nó que inicie um contêiner do TeX Live e lhe passa o diretório de compilação do projeto **pelo caminho dele no nó**. Por isso, esses diretórios são volumes `hostPath`, e seus caminhos são repetidos em `SANDBOXED_COMPILES_HOST_DIR_*`. O conteúdo deles são dados temporários e não precisa de backup.
* <strong>`enableServiceLinks: false`.</strong> O Kubernetes adiciona a cada pod variáveis no estilo do Docker para cada Service do namespace: o Service `redis` se torna `REDIS_PORT=tcp://10.x.x.x:6379`, o Service `git-bridge` se torna `GIT_BRIDGE_PORT=tcp://...`. Alguns serviços do Overleaf leem variáveis com esses nomes. Neste pod, as configurações de `OVERLEAF_REDIS_*` e do ConfigMap prevalecem, mas o git-bridge usa `GIT_BRIDGE_PORT` como sua porta e para (veja [Integração com Git](/pt/on-premises/configuration/kubernetes/integrations/git-integration)). Desativar os links mantém o ambiente restrito ao que você definiu.
* <strong>`Recreate`.</strong> Dois pods nunca devem usar o mesmo volume de dados nem executar migrações ao mesmo tempo.
* <strong>Expondo o serviço.</strong> O Service NodePort responde na porta `30080` de cada nó. Em produção, coloque seu ingress controller ou balanceador de carga à frente e termine o TLS ali; ele precisa permitir WebSockets, tempos limite de requisição de 10 minutos (compilações longas) e uploads de 50 MB, e repassar `X-Forwarded-For` e `X-Forwarded-Proto`.
