---
title: 5. Personalizando sua instância
description: Defina a porta, a URL do site e a imagem do TeX Live, ative as compilações em sandbox e inicie o Ayakaleaf Pro no WSL 2.
icon: square-sliders
---

Execute os comandos e edite os arquivos no **Ubuntu**, a partir de `~/ayakaleaf-toolkit`.

<Steps>
<Step title="Configurações do contêiner">
Edite as entradas existentes em `config/overleaf.rc`:

```bash title="config/overleaf.rc"
PROJECT_NAME=ayakaleaf-wsl
SERVER_PRO=true
OVERLEAF_LISTEN_IP=127.0.0.1
OVERLEAF_PORT=8080
SIBLING_CONTAINERS_ENABLED=true
DOCKER_SOCKET_PATH=/var/run/docker.sock
```

Mantenha os caminhos de dados padrão e os serviços MongoDB e Redis incluídos. A porta `8080` é para o navegador local do Windows; fazer bind em `127.0.0.1` a mantém local. As compilações em sandbox usam um contêiner Linux separado para cada compilação, em vez de executar o TeX dentro do contêiner da aplicação. O socket do Docker permite que a aplicação crie esses contêineres, e o Toolkit fornece o caminho no host para os dados de compilação em `data/overleaf/data/compiles`.
</Step>

<Step title="Configurações da aplicação">
Em `config/variables.env`, defina estes valores, substituindo quaisquer entradas ativas com os mesmos nomes:

```dotenv title="config/variables.env"
OVERLEAF_SITE_URL=http://localhost:8080
TEX_LIVE_DOCKER_IMAGE=ghcr.io/ayaka-notes/texlive-full:2026.1
ALL_TEX_LIVE_DOCKER_IMAGES=ghcr.io/ayaka-notes/texlive-full:2026.1
ALL_TEX_LIVE_DOCKER_IMAGE_NAMES="TeX Live 2026"
```

A imagem completa inclui os pacotes e as fontes necessários para uma ampla gama de projetos. Reserve pelo menos 40 GB de armazenamento livre para ela e para a aplicação, além de espaço para os dados dos projetos e futuras atualizações.

Para um teste rápido de implantação, use a imagem **basic**, que é menor. Ela é suficiente para o teste com um artigo simples da etapa 6, mas não inclui o conjunto completo de pacotes e fontes:

```dotenv
TEX_LIVE_DOCKER_IMAGE=ghcr.io/ayaka-notes/texlive-basic:2026.1
ALL_TEX_LIVE_DOCKER_IMAGES=ghcr.io/ayaka-notes/texlive-basic:2026.1
ALL_TEX_LIVE_DOCKER_IMAGE_NAMES="TeX Live 2026 Basic"
```

Escolha um desses conjuntos, sem chaves ativas duplicadas. O [Dockerfile](https://github.com/ayaka-notes/texlive-full/blob/main/texlive/2026/Dockerfile.basic) da imagem basic inclui `latexmk`, XeTeX e `fontspec`, mas não o `ctex` nem a coleção completa de fontes. Um pacote LaTeX ausente na imagem basic não indica, por si só, um problema no sandbox.

Gere um segredo de sessão:

```bash
openssl rand -hex 32
```

Adicione o resultado como `OVERLEAF_SESSION_SECRET` em `config/variables.env`. Guarde também o segredo do token de convite gerado. Para uma instância local sem e-mail, deixe as configurações de SMTP e `OVERLEAF_EMAIL_FROM_ADDRESS` sem definir.
</Step>

<Step title="Iniciar sua instância">
```bash
bin/up -d
```

O Toolkit inicia o MongoDB, inicializa o replica set dele, baixa a imagem do TeX Live selecionada e inicia o Redis e a aplicação. Ele pode parecer parado enquanto uma imagem grande é baixada. Não execute um segundo `bin/up` enquanto o primeiro ainda estiver trabalhando.

Em outro terminal do Ubuntu, verifique:

```bash
cd "$HOME/ayakaleaf-toolkit"
bin/docker-compose ps
bin/docker-compose logs --tail=100 mongo
bin/docker-compose logs --tail=100 -f sharelatex
```

Pressione `Ctrl+C` para parar de acompanhar os logs; os contêineres em modo destacado continuam em execução. Se a inicialização falhar no MongoDB, siga [O MongoDB não inicia](/pt/on-premises/installation/using-docker-compose/windows/troubleshooting#mongodb-fails-to-start) antes de tentar novamente. Não exclua o diretório de dados dele para redefinir uma instalação existente.

Verifique a porta e a página da primeira execução:

```bash
bin/docker-compose port sharelatex 80
curl -I http://localhost:8080/launchpad
```

A porta deve ser `127.0.0.1:8080`. Aguarde a inicialização da aplicação se a requisição HTTP falhar no início.
</Step>

<Step title="Abrir a instância a partir do Windows">
No seu **navegador do Windows**, abra [http://localhost:8080/launchpad](http://localhost:8080/launchpad). Use esse endereço também no Windows, em vez de um endereço IP temporário do WSL.

Para verificar o acesso HTTP do Windows separadamente do navegador, execute no **PowerShell**:

```powershell
curl.exe -I http://localhost:8080/launchpad
```

Se o Ubuntu conseguir acessar a página, mas o Windows não, consulte [O Windows não consegue abrir localhost](/pt/on-premises/installation/using-docker-compose/windows/troubleshooting#windows-cannot-open-localhost).
</Step>
</Steps>
