---
title: 5. Personalizando sua instância
description: Defina a porta, a URL do site e a imagem do TeX Live para uma instância local no seu Mac, verifique o kernel da VM do Docker e inicie o Ayakaleaf Pro.
icon: square-sliders
---

<Steps>
<Step title="Configurações do contêiner">
Edite estas entradas existentes em `config/overleaf.rc`:

```bash title="config/overleaf.rc"
PROJECT_NAME=ayakaleaf-macos
SERVER_PRO=true
OVERLEAF_LISTEN_IP=127.0.0.1
OVERLEAF_PORT=8080
SIBLING_CONTAINERS_ENABLED=true
DOCKER_SOCKET_PATH=/var/run/docker.sock
```

Mantenha os caminhos de dados padrão e os serviços MongoDB e Redis incluídos. Com `OVERLEAF_LISTEN_IP=127.0.0.1`, somente navegadores neste Mac podem abrir a instância.
</Step>

<Step title="Configurações da aplicação">
Em `config/variables.env`, defina estes valores, substituindo quaisquer entradas ativas com os mesmos nomes:

```dotenv title="config/variables.env"
OVERLEAF_SITE_URL=http://localhost:8080
TEX_LIVE_DOCKER_IMAGE=ghcr.io/ayaka-notes/texlive-full:2026.1
ALL_TEX_LIVE_DOCKER_IMAGES=ghcr.io/ayaka-notes/texlive-full:2026.1
ALL_TEX_LIVE_DOCKER_IMAGE_NAMES="TeX Live 2026"
```

Gere um segredo de sessão:

```bash
openssl rand -hex 32
```

Adicione o resultado como `OVERLEAF_SESSION_SECRET` em `config/variables.env`. Sem ele, cada `bin/up` que recria o contêiner desconecta todos os usuários; consulte [Variáveis de ambiente](/pt/on-premises/configuration/overleaf-toolkit/environment-variables).

Para uma instância local sem e-mail, deixe as configurações de SMTP e `OVERLEAF_EMAIL_FROM_ADDRESS` sem definir. O Git Bridge, a autenticação externa e as demais integrações podem ser adicionados mais tarde com suas próprias [páginas de configuração](/pt/on-premises/configuration/overleaf-toolkit).
</Step>

<Step id="check-the-docker-vms-linux-kernel" title="Verificar o kernel Linux da VM do Docker">
O MongoDB é executado no kernel Linux da máquina virtual do Docker Desktop, e não no macOS. Verifique a versão dele antes da primeira inicialização:

```bash
docker info --format '{{.KernelVersion}}'
```

O MongoDB documenta uma incompatibilidade com os kernels Linux **6.19 a 7.0.13**, que também afeta o MongoDB no Docker. A correção é um kernel **7.0.14 ou posterior**, que vem com uma atualização do Docker Desktop; consulte as [notas de produção do MongoDB](https://www.mongodb.com/docs/manual/administration/production-notes/).

Se a sua VM do Docker usar um kernel afetado, adicione o seguinte a `config/docker-compose.override.yml`, mesclado com quaisquer `services` que você já tenha nele:

```yaml title="config/docker-compose.override.yml"
services:
  mongo:
    environment:
      GLIBC_TUNABLES: glibc.pthread.rseq=1
```

<Warning>

Atualize para um kernel corrigido quando estiver disponível. Se o seu kernel estiver fora da faixa afetada, essa solução alternativa é desnecessária.

</Warning>
</Step>

<Step title="Iniciar sua instância">
No diretório do Toolkit, execute:

```bash
bin/up -d
```

O Toolkit inicializa o replica set do MongoDB, baixa a imagem do TeX Live e inicia a aplicação. O primeiro download demora um pouco. Para acompanhar o progresso:

```bash
bin/docker-compose ps
bin/docker-compose logs --tail=100 -f sharelatex
```

Pressione `Ctrl+C` para parar de acompanhar os logs. Os contêineres continuam em execução.

Verifique a porta publicada e a página da primeira execução:

```bash
bin/docker-compose port sharelatex 80
curl -I http://localhost:8080/launchpad
```

A porta deve ser `127.0.0.1:8080`.
</Step>
</Steps>

<Info>

Para abrir a instância a partir de outros computadores mais tarde, altere o endereço de escuta e a URL do site e configure HTTPS, conforme descrito em [5. Personalizando sua instância](/pt/on-premises/installation/using-docker-compose/linux/5.-personalizing-your-instance) do guia para Linux. Nesse caso, o Mac precisa permanecer ativo; consulte [Manter a instância disponível](/pt/on-premises/installation/using-docker-compose/macos/6.-post-installation-tasks#keep-the-instance-available).

</Info>
