### Criar o administrador e um primeiro projeto {#create-the-administrator-and-a-first-project}

Abra [http://localhost:8080/launchpad](http://localhost:8080/launchpad), crie a primeira conta de administrador e faça login. Em seguida, siga [6. Tarefas pós-instalação](/pt/on-premises/installation/using-docker-compose/linux/6.-post-installation-tasks) do guia para Linux, usando a porta `8080` nas URLs de exemplo.

### Verificar a compilação {#verify-compilation}

Uma página de login que abre não prova que os contêineres de compilação separados e suas montagens de dados funcionam. Crie um projeto em branco e compile este `main.tex`:

```latex
\documentclass{article}
\begin{document}
Ayakaleaf Pro on macOS.
\end{document}
```

A pré-visualização do PDF deve mostrar o texto. Se necessário, selecione TeX Live 2026 nas configurações do projeto.

Para um projeto com texto em chinês, selecione **XeLaTeX** como compilador e teste:

```latex
\documentclass{ctexart}
\begin{document}
你好，Ayakaleaf Pro。
\end{document}
```

### Verificar a persistência {#verify-persistence}

```bash
bin/stop
bin/start
```

Reabra o projeto e compile-o novamente. Sua conta, o código-fonte e os arquivos do projeto devem continuar lá. Com os caminhos padrão, os dados ativos ficam no diretório `data/` do Toolkit no seu Mac.

### Manter a instância disponível {#keep-the-instance-available}

Enquanto o Mac está em repouso, o macOS suspende a máquina virtual do Docker Desktop com todos os contêineres dentro dela: ninguém consegue abrir a instância, e uma compilação em andamento é interrompida até que o Mac desperte. Apenas o repouso do sistema importa. A tela pode se desligar.

Se outras pessoas usam a instância, ou se você deixa tarefas longas em execução, mantenha o Mac ligado na energia e impeça o repouso automático; consulte [Definir os ajustes de repouso e despertar do Mac](https://support.apple.com/guide/mac-help/set-sleep-and-wake-settings-mchle41a6ccd/mac):

| Mac | Configuração |
| --- | --- |
| Mac de mesa (Mac mini, iMac, Mac Studio, Mac Pro) | **System Settings → Energy**: ative **Prevent automatic sleeping when the display is off** |
| MacBook | **System Settings → Battery → Options**: ative **Prevent automatic sleeping on power adapter when the display is off**. Isso só se aplica enquanto o adaptador de energia está conectado, e fechar a tampa ainda coloca o MacBook em repouso |

Para manter o Mac ativo apenas por um tempo, execute `caffeinate -i` em uma janela do Terminal. Isso impede o repouso por inatividade até você pressionar `Ctrl+C` ou fechar a janela.

O Docker Desktop é um aplicativo na sua sessão de usuário. Para ter a instância de volta após uma reinicialização, ative **Start Docker Desktop when you sign in to your computer** em **Settings → General** do Docker Desktop. Os contêineres do Toolkit usam `restart: always`, então o Docker os inicia novamente assim que o Docker Desktop estiver em execução, sem `bin/up`. Até que alguém inicie sessão no Mac após uma reinicialização, a instância permanece fora do ar.

<Info>

Um Mac que permanece ativo consome mais energia. Para um serviço que precisa estar sempre acessível, recomendamos um servidor Linux; consulte [Linux](/pt/on-premises/installation/using-docker-compose/linux).

</Info>

### Uso diário {#daily-use}

Abra o Docker Desktop antes de gerenciar a instância. Em um novo terminal:

```bash
export PATH="$(brew --prefix gnu-sed)/libexec/gnubin:$PATH"
cd "$HOME/ayakaleaf-toolkit"
```

| Tarefa | Comando |
| --- | --- |
| Iniciar os contêineres existentes | `bin/start` |
| Parar os contêineres e manter os dados | `bin/stop` |
| Aplicar alterações de configuração | `bin/up -d` |
| Verificar o status | `bin/docker-compose ps` |
| Ler os logs de inicialização | `bin/docker-compose logs --tail=100 sharelatex` |
| Ler os logs do compilador | `bin/logs -f clsi` |

`bin/start` não aplica alterações em `config/`: execute `bin/up -d` depois de editar a configuração. Guarde `config/` e `data/` e siga [Dados e backups](/pt/on-premises/maintenance/data-and-backups) antes de uma atualização ou antes de mover a instalação. Copiar os arquivos do banco de dados enquanto o MongoDB grava neles não é um backup consistente.

Mantenha a instância em `127.0.0.1` para uso local. Para atender outros computadores, defina intencionalmente o endereço de escuta, a URL do site e o HTTPS; consulte [5. Personalizando sua instância](/pt/on-premises/installation/using-docker-compose/linux/5.-personalizing-your-instance) do guia para Linux.

Se algo não funcionar, consulte [Solução de problemas](/pt/on-premises/installation/using-docker-compose/macos/troubleshooting).
