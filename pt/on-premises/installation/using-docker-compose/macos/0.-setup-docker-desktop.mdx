O Ayakaleaf Pro é executado no Docker. No Mac, você usa o Docker Desktop, que executa o engine do Docker em uma máquina virtual Linux.

<Steps>
<Step title="Instalar e iniciar o Docker Desktop">
Instale a versão do [Docker Desktop](https://docs.docker.com/desktop/setup/install/mac-install/) para o seu Mac (Apple silicon ou Intel), abra-o e aguarde até que o engine tenha iniciado. Você também pode iniciá-lo pelo Terminal:

```bash
open -a Docker
```
</Step>

<Step title="Verificar o engine do Docker">
Execute estes comandos no Terminal:

```bash
docker context show
docker info
docker compose version
```

O contexto deve apontar para o engine local do Docker Desktop, normalmente `desktop-linux`. Se outro contexto estiver selecionado, mude para o Docker Desktop antes de continuar:

```bash
docker context use desktop-linux
```

`docker info` deve exibir uma seção **Server**. `docker --version` sozinho mostra apenas que o cliente está instalado.
</Step>

<Step title="Verificar os recursos e o compartilhamento de arquivos">
Em **Settings** do Docker Desktop, compare os limites de CPU, memória e disco com [Antes de começar](/pt/on-premises/installation/using-docker-compose/macos#before-you-start) e verifique as configurações de compartilhamento de arquivos; consulte [Docker Desktop settings](https://docs.docker.com/desktop/settings-and-maintenance/settings/).

Este guia mantém o Toolkit em `/Users`, que o Docker Desktop compartilha por padrão. Se você usar outro local e `bin/up` falhar com `Mounts denied`, adicione esse diretório ao compartilhamento de arquivos.
</Step>

<Step title="Verificar o socket do Docker para compilações em sandbox">
O Toolkit monta `/var/run/docker.sock` na aplicação para que ela possa iniciar um contêiner separado do TeX Live para cada compilação. Mantenha `DOCKER_SOCKET_PATH=/var/run/docker.sock` em `config/overleaf.rc`.

A CLI do Docker no macOS pode se conectar por meio de `~/.docker/run/docker.sock`. Esse é o endpoint do cliente no Mac, e não um motivo para alterar a origem da montagem do Toolkit: o compilador precisa do socket do engine como os contêineres Linux o enxergam.

Se `/var/run/docker.sock` não existir no Mac, ative **Allow the default Docker socket to be used** em **Settings → Advanced**; consulte os [requisitos de permissão do Docker](https://docs.docker.com/desktop/setup/install/mac-permission-requirements/).

<Danger>

Não execute `chmod 777` no socket para contornar erros. O acesso ao socket do Docker equivale a acesso root à VM do Docker.

</Danger>
</Step>
</Steps>
