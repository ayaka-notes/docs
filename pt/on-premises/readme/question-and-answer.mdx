Aqui reunimos as respostas a algumas perguntas frequentes sobre o Ayakaleaf Pro.

### Perguntas básicas

<Accordion title="P01: O Ayakaleaf Pro é uma versão de avaliação gratuita? Ele exige uma licença?">

Não. O Ayakaleaf Pro é totalmente gratuito. Não é uma versão de avaliação e não exige licença.

</Accordion>

<Accordion title="P02: O Ayakaleaf Pro inclui todos os recursos do Overleaf Server Pro?">

Sim. O Ayakaleaf Pro inclui todos os recursos do Overleaf Server Pro, incluindo a integração com o Git-Bridge. Ele também inclui recursos selecionados da plataforma SaaS do Overleaf. Continuamos a desenvolver e a aprimorar o Ayakaleaf Pro.

</Accordion>

<Accordion title="P03: Quanto custa o Overleaf Server Pro?">

O Overleaf Server Pro custa cerca de \$300 por usuário por ano. São necessárias pelo menos 10 licenças, portanto as implantações começam em aproximadamente \$3.000 por ano. Contratos públicos menores nos EUA mostram custos anuais de cerca de \$320–\$370 por usuário. Isso torna o Server Pro caro, especialmente para equipes menores. Consulte [#information-and-price-about-overleaf-server-pro](/pt/on-premises#information-and-price-about-overleaf-server-pro  "mention") para ver compras e preços documentados.

</Accordion>

<Accordion title="P04: Por que o Overleaf Server Pro não inclui sincronização com o GitHub nem recursos de IA?">

O Overleaf Server Pro é amplamente usado por organizações governamentais. Elas o implantam em redes privadas e controlam rigorosamente o acesso. Para proteger dados sensíveis, os recursos incluídos evitam trocar dados com serviços de terceiros. Se você precisar de sincronização com o GitHub, IA ou recursos conectados semelhantes, o Overleaf recomenda uma assinatura da sua plataforma SaaS.

</Accordion>

<Accordion title="P05: O Ayakaleaf Pro é seguro e confiável?">

O Ayakaleaf Pro é de código aberto. Revisamos o código com ferramentas como o Codex Security para reforçar a sua segurança e confiabilidade. Se você não ativar a sincronização de dados com terceiros, os seus dados permanecem no seu servidor. O Ayakaleaf Pro não contém telemetria que envie os seus dados para outro lugar.

</Accordion>

<Accordion title="P06: O Ayakaleaf Pro será mantido a longo prazo?">

Faremos todos os esforços para manter este projeto a longo prazo.

</Accordion>

<Accordion title="P07: O Ayakaleaf Pro está em conformidade com as licenças?">

O Ayakaleaf Pro é um fork comunitário. O seu código e os recursos integrados vêm de contribuições da comunidade. Ele é licenciado sob a AGPL v3. As implantações podem estar em conformidade com esta licença quando cumprem os seus requisitos.

</Accordion>

<Accordion title="P08: Por que o projeto se chama Ayakaleaf Pro?">

O projeto chamava-se originalmente Overleaf Pro em 2024. O desenvolvimento ficou pausado por um tempo e foi retomado no final de 2025. No primeiro trimestre de 2026, o Overleaf renomeou o seu plano de assinatura com IA para Pro. O feedback da comunidade também apontou que o nome Overleaf Pro poderia criar riscos relacionados a marcas registradas e de falsificação de identidade, podendo levar os usuários a pensar que o projeto era oficial.

Renomeamos o projeto para Ayakaleaf Pro para evitar essa confusão. O nome pode ser lido como "Ayaka-notes Overleaf Pro". O mantenedor (pode me chamar de ayaka!) contribui para o desenvolvimento da comunidade Overleaf desde os seus tempos de estudante, há mais de cinco anos. Essa experiência sustenta o nosso compromisso de manutenção a longo prazo.

</Accordion>

<Accordion title="P09: O que distingue o Ayakaleaf Pro dos editores de LaTeX mais recentes criados com IA?">

Desde 2026, a comunidade de código aberto lançou muitos editores de LaTeX criados com IA, incluindo o OpenAI Prism. O Ayakaleaf Pro mantém os seus dados e serviços no seu próprio servidor. Isso lhe dá controle direto sobre a sua implantação e os seus dados.

Muitos editores experimentais da comunidade não têm um plano de manutenção de longo prazo estabelecido. Plataformas de compilação LaTeX de terceiros também podem deixar de operar quando a sua base de usuários ou receita é insuficiente. O Ayakaleaf Pro disponibiliza todo o código-fonte e permite hospedar por conta própria todos os serviços. Mesmo que a manutenção parasse, o seu serviço auto-hospedado existente poderia continuar funcionando.

</Accordion>

### Recursos

<Accordion title="P01: Quais recursos o Ayakaleaf Pro oferece? Posso solicitar um novo recurso?">

Consulte a nossa documentação para ver a lista atual de recursos. Se houver um recurso que você gostaria que adicionássemos, sinta-se à vontade para abrir uma issue (de solicitação de recurso) no GitHub. Faremos o possível para implementar os recursos solicitados, mas o desenvolvimento leva tempo e não podemos garantir que todos os recursos sejam entregues imediatamente.

</Accordion>

<Accordion title="P02: Desenvolvi alguns recursos. Posso enviar um PR, e há garantia de que ele será aceito?">

Contribuições são bem-vindas, mas a aceitação não é garantida. Avaliamos cada PR com base no seu impacto sobre o código-base do Overleaf subjacente, no esforço de manutenção que exige e no valor que traz aos usuários. Faremos o possível para mesclar e manter as contribuições valiosas.

No entanto, podemos rejeitar PRs que introduzam alterações excessivas, que consistam em código gerado por IA não revisado ou mal compreendido ("vibe coding") ou que adicionem recursos difíceis de manter ao longo do tempo.

</Accordion>

<Accordion title="P03: Como configuro um recurso específico?">

Geralmente atualizamos a documentação sempre que lançamos um novo recurso. Consulte a documentação correspondente para obter instruções detalhadas de configuração e explicações sobre as variáveis de ambiente disponíveis.

</Accordion>

<Accordion title="P04: Quais bibliotecas Python o Python Runner pode usar?">

O Python Runner executa Python no navegador do usuário com o [Pyodide](https://pyodide.org/) 0.29.3, e não no servidor. Ele carrega os pacotes que o seu código importa a partir dos [pacotes integrados ao Pyodide](https://pyodide.org/en/0.29.3/usage/packages-in-pyodide.html), como NumPy, pandas e Matplotlib. Pacotes instalados com `pip` e outros pacotes não estão disponíveis. Não há nada a configurar no servidor.

</Accordion>

<Accordion title="P05: A verificação ortográfica pode verificar japonês ou chinês?">

Não. O verificador ortográfico não tem dicionário para japonês ou chinês, por isso esses idiomas não estão na lista de idiomas da verificação ortográfica. Os usuários podem desativar a verificação ortográfica de um projeto nas configurações do editor.

</Accordion>

### Implantação

<Accordion title="P01: O Ayakaleaf Pro suporta implantação distribuída em k8s?">

Para a maioria dos usuários, recomendamos implantar com o [Toolkit](/pt/on-premises/installation/using-the-toolkit). Não recomendamos implantações em clusters de grande escala usando Kubernetes ou plataformas semelhantes, pois elas podem aumentar significativamente a complexidade operacional e o esforço de manutenção.

</Accordion>

<Accordion title="P02: Como posso garantir a disponibilidade ao atender milhares de usuários?">

Consulte o nosso guia de [escalabilidade horizontal](/pt/on-premises/maintenance/horizontal-scaling). Você pode implantar várias instâncias do Overleaf e configurar um balanceador de carga para distribuir o tráfego entre elas.

</Accordion>

<Accordion title="P03: Vocês podem me ajudar com a implantação ou a migração?">

Se você tiver uma instância existente do Overleaf Server Pro, teremos prazer em ajudá-lo a migrar para o Ayakaleaf Pro. Entre em contato por e-mail ou por issues.

</Accordion>

<Accordion title="P04: Posso hospedar o Ayakaleaf Pro em um subcaminho de URL, como `https://example.com/overleaf`?">

Não. O Ayakaleaf Pro precisa ser servido a partir da raiz de um domínio. Use um domínio ou subdomínio dedicado, como `https://overleaf.example.com`.

</Accordion>

<Accordion title="P05: Posso executar o Ayakaleaf Pro no Windows ou no macOS, ou sem o Toolkit?">

Oferecemos suporte a servidores Linux com o [Toolkit](/pt/on-premises/installation/using-the-toolkit). O Docker Desktop no Windows, no WSL2 ou no macOS pode funcionar, mas não o testamos; consulte [Solução de problemas](/pt/on-premises/support/troubleshooting) para um problema conhecido do MongoDB.

Não fornecemos um `docker-compose.yml` independente. Para ver a configuração do Compose que o Toolkit usa, execute `bin/docker-compose config` no diretório do Toolkit.

</Accordion>

<Accordion title="P06: Como desinstalo o Ayakaleaf Pro?">

Não há script de desinstalação. No diretório do Toolkit:

1. Pare e remova os contêineres com `bin/docker-compose down`.
2. Exclua os dados. Por padrão, eles ficam no diretório `data/` do Toolkit. Se você alterou `OVERLEAF_DATA_PATH`, `MONGO_DATA_PATH`, `REDIS_DATA_PATH` ou `GIT_BRIDGE_DATA_PATH` em `config/overleaf.rc`, exclua também esses diretórios. Isso não pode ser desfeito, então [faça um backup](/pt/on-premises/maintenance/data-and-backups) antes, caso possa precisar dos dados.
3. Exclua o diretório do Toolkit.
4. Remova as imagens Docker, que você pode listar com `docker images`: `ghcr.io/ayaka-notes/overleaf-pro`, a imagem do git-bridge, `mongo`, `redis` e as imagens do TeX Live.

</Accordion>

<Accordion title="P07: Como paro, inicio ou reinicio o Ayakaleaf Pro?">

Execute estes comandos no diretório do Toolkit:

* `bin/stop` para todos os contêineres, e `bin/start` os inicia novamente. Os contêineres são mantidos, então os usuários continuam conectados.
* `bin/up -d` cria os contêineres e os inicia em segundo plano. Execute-o depois de alterar `config/variables.env`, `config/overleaf.rc` ou `config/version`: ele recria os contêineres cuja configuração mudou, e só então as alterações entram em vigor. `bin/stop` e `bin/start` não as aplicam.
* `bin/docker-compose restart sharelatex` reinicia apenas o contêiner do Overleaf, sem aplicar alterações de configuração.

Se os usuários forem desconectados sempre que o `bin/up` recriar o contêiner, defina `OVERLEAF_SESSION_SECRET`; consulte as Q\&A em [Variáveis de ambiente](/pt/on-premises/configuration/overleaf-toolkit/environment-variables).

</Accordion>

<Accordion title="P08: Onde coloco a URL de callback do OAuth?">

Na aplicação que você cria no provedor, e não no Ayakaleaf Pro. Não há configuração de callback em `config/variables.env` para nenhuma destas integrações: o Ayakaleaf Pro monta cada URL de callback a partir de `OVERLEAF_SITE_URL` e a envia ao provedor, que a rejeita a menos que corresponda à registrada para a aplicação. Portanto, você só a registra no provedor e define `OVERLEAF_SITE_URL` como o endereço que os usuários abrem.

| Integração | Campo no provedor | Valor |
| --- | --- | --- |
| [GitHub](/pt/on-premises/configuration/overleaf-toolkit/github-synchronisation) | Authorization callback URL | `${OVERLEAF_SITE_URL}/user/github-sync/oauth2/callback` |
| [GitLab](/pt/on-premises/configuration/overleaf-toolkit/gitlab-synchronisation) | Redirect URI | `${OVERLEAF_SITE_URL}/user/gitlab-sync/oauth2/callback` |
| [Gitea](/pt/on-premises/configuration/overleaf-toolkit/gitea-synchronisation) | Redirect URIs | `${OVERLEAF_SITE_URL}/user/gitea-sync/oauth2/callback` |
| [Dropbox](/pt/on-premises/configuration/overleaf-toolkit/dropbox-synchronisation) | Redirect URIs (clique em **Add**) | `${OVERLEAF_SITE_URL}/user/dropbox/oauth/callback` |
| [Zotero](/pt/on-premises/configuration/overleaf-toolkit/zotero-integration) | Callback URL | `${OVERLEAF_SITE_URL}/user/zotero/oauth/callback` |
| [Mendeley](/pt/on-premises/configuration/overleaf-toolkit/mendeley-integration) | Redirect URL | `${OVERLEAF_SITE_URL}/user/mendeley/oauth/callback` |
| [Login OIDC](/pt/on-premises/configuration/overleaf-toolkit/authentication/oidc-authentication) | Redirect URI | `${OVERLEAF_SITE_URL}/oidc/login/callback` |
| [Login SAML](/pt/on-premises/configuration/overleaf-toolkit/authentication/saml-authentication) | ACS URL (Assertion Consumer Service) | `${OVERLEAF_SITE_URL}/saml/login/callback` |

Se você alterar `OVERLEAF_SITE_URL`, por exemplo para um novo domínio, atualize também a URL em todos os provedores; caso contrário, a vinculação falha.

</Accordion>

### LaTeX

<Accordion title="P01: As compilações dos projetos LaTeX dos usuários são isoladas? O Shell Escape está ativado?">

Ao ativar as Sandbox Compiles, a compilação de cada usuário é executada num contêiner Docker separado e fica isolada das compilações dos outros usuários. O Shell Escape está ativado por padrão nas Sandbox Compiles.

</Accordion>

<Accordion title="P02: A imagem das Sandbox Compiles é confiável? A compilação pode falhar?">

Aprimoramos a nossa imagem TeX Live Full para Sandbox Compiles ao longo dos últimos três anos. Na maioria dos casos, os projetos que compilam no overleaf.com também compilam corretamente com o Ayakaleaf Pro. Se uma fonte necessária não estiver disponível, carregue essa fonte manualmente no seu projeto.

</Accordion>

<Accordion title="P03: Meu projeto não compila. Vocês podem me ajudar a solucionar o problema?">

Carregue o seu projeto no site oficial do Overleaf, ative o compartilhamento por link somente leitura e inclua o link em uma issue no GitHub.

Investigaremos e corrigiremos quaisquer bugs que impeçam um projeto de compilar no Ayakaleaf Pro quando ele compila com sucesso no site oficial do Overleaf. Problemas de compilação fora desse escopo não são cobertos pelo nosso suporte.

</Accordion>
