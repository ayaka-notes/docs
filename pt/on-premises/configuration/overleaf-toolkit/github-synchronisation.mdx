### Configurar a sincronização com GitHub

<Warning>

Você precisa habilitar o [git-bridge](/pt/on-premises/configuration/overleaf-toolkit/git-integration) antes de usar a sincronização com GitHub.

```dotenv title="config/overleaf.rc"
GIT_BRIDGE_ENABLED=true
```

</Warning>

Acesse as [configurações de desenvolvedor](https://github.com/settings/developers) para criar seu aplicativo OAuth do GitHub e copie seu `CLIENT_ID` e `SECRET`.

**Observação**: ao criar o OAuth App, informe `${OVERLEAF_SITE_URL}/user/github-sync/oauth2/callback` em **Authorization callback URL**. O Ayakaleaf Pro monta o mesmo endereço a partir de `OVERLEAF_SITE_URL`, então não há nada a definir para ele em `config/variables.env`.

Em seguida, adicione as seguintes configurações aos seus arquivos de variáveis de ambiente do Overleaf.

```dotenv title="config/variables.env" wrap
# used to encrypt the user's GitHub access token.
# How to generate: `openssl rand -hex 32`
GITHUB_TOKEN_CIPHER_PASSWORD=0123456789ABCDEFG # changed to yours

# Github Sync Settings
GITHUB_SYNC_ENABLED=true
GITHUB_SYNC_CLIENT_ID=
GITHUB_SYNC_CLIENT_SECRET=

# OAuth callback is: ${OVERLEAF_SITE_URL}/user/github-sync/oauth2/callback
# (Optional) GITHUB_SYNC_PROXY_URL=http://10.0.0.1:10808
```

<Warning>

Antes de configurar a URL de callback OAuth do GitHub, certifique-se de que `OVERLEAF_SITE_URL` esteja definido corretamente.

</Warning>

Se você estiver em uma região com acesso restrito à rede, talvez precise configurar um proxy para acessar o GitHub. Defina a seguinte variável de ambiente: `GITHUB_SYNC_PROXY_URL=http://10.0.0.1:10808`. Certifique-se de que o uso de um proxy esteja em conformidade com as leis e regulamentações locais.

<Warning>

`GITHUB_SYNC_PROXY_URL` deve ser um proxy de encaminhamento HTTP/HTTPS padrão (por exemplo, a porta HTTP do Clash). Espelhos de download do GitHub, como `gh-proxy.org`, não são suportados.

</Warning>

<Warning>

Não use `127.0.0.1` como host do proxy. Se o proxy estiver em execução no servidor host, use o endereço IP da LAN do servidor (como `192.168.1.xx`) e certifique-se de que o proxy esteja configurado para aceitar conexões de dispositivos da rede local.

</Warning>

### GitHub Enterprise

<Info>

O suporte ao GitHub Enterprise foi introduzido na v6.3.1 e posteriores. Versões anteriores se conectam apenas ao `github.com`, e as variáveis abaixo não têm efeito.

</Info>

Por padrão, a sincronização com GitHub se conecta ao `github.com`. Para usar o GitHub Enterprise Server (auto-hospedado) ou o GitHub Enterprise Cloud com residência de dados (`GHE.com`), defina `GITHUB_SYNC_URL` como o endereço web da sua instância, aquele com o qual você abre os repositórios no navegador.

```dotenv title="config/variables.env" wrap
# GitHub Enterprise Server
GITHUB_SYNC_URL=https://github.example.com

# or GitHub Enterprise Cloud with data residency
# GITHUB_SYNC_URL=https://octocorp.ghe.com
```

Os endpoints das APIs REST e GraphQL são derivados de `GITHUB_SYNC_URL` da mesma forma que o GitHub CLI faz:

| `GITHUB_SYNC_URL`             | API REST                         | API GraphQL                              |
| ----------------------------- | -------------------------------- | ---------------------------------------- |
| `https://github.com` (padrão) | `https://api.github.com`         | `https://api.github.com/graphql`         |
| `https://SUBDOMAIN.ghe.com`   | `https://api.SUBDOMAIN.ghe.com`  | `https://api.SUBDOMAIN.ghe.com/graphql`  |
| `https://HOST` (qualquer outro) | `https://HOST/api/v3`          | `https://HOST/api/graphql`               |

Defina os endpoints da API apenas quando a sua instância os disponibilizar em outro lugar, por exemplo, atrás de um gateway de API:

| Variável                  | Padrão                                                                                    |
| ------------------------- | ----------------------------------------------------------------------------------------- |
| `GITHUB_SYNC_URL`         | `https://github.com`                                                                      |
| `GITHUB_SYNC_API_URL`     | Derivado de `GITHUB_SYNC_URL`, veja a tabela acima                                        |
| `GITHUB_SYNC_GRAPHQL_URL` | Derivado de `GITHUB_SYNC_API_URL` quando definido (`/api/v3` se torna `/api/graphql`; caso contrário, `/graphql` é acrescentado); senão, de `GITHUB_SYNC_URL` |

<Warning>

* Crie o aplicativo OAuth na sua instância enterprise (_Settings → Developer settings → OAuth Apps_); um aplicativo do `github.com` não funciona nela. A URL de callback é a mesma: `${OVERLEAF_SITE_URL}/user/github-sync/oauth2/callback`.
* `GITHUB_SYNC_URL` é apenas o endereço web. Não o defina como um endereço de API, como `https://api.github.com` ou `https://HOST/api/v3`, e não adicione um caminho de organização.
* Os três endereços devem apontar para a mesma instância do GitHub.

</Warning>

<Info>

Se a sua instância usar um certificado de uma CA privada, monte o certificado da CA no contêiner e aponte `NODE_EXTRA_CA_CERTS` para ele, por exemplo, `NODE_EXTRA_CA_CERTS=/var/lib/overleaf/certs/github-ca.pem`.

</Info>

<Danger>

Contas e projetos vinculados pertencem à instância com a qual foram vinculados. Antes de mudar `GITHUB_SYNC_URL` para outra instância, peça aos usuários que desvinculem sua conta do GitHub e seus projetos.

</Danger>

### Quem pode vincular e sincronizar

Assim como no Overleaf Cloud, apenas o proprietário do projeto pode vincular um projeto a um repositório do GitHub. Depois de vinculado, todos os colaboradores com acesso de edição podem sincronizá-lo.

| Ação                                                       | Quem pode fazer                                                |
| ---------------------------------------------------------- | -------------------------------------------------------------- |
| Exportar um projeto para um novo repositório do GitHub     | O proprietário do projeto                                      |
| Importar um repositório do GitHub para um novo projeto     | Qualquer usuário, que se torna o proprietário do novo projeto  |
| Fazer pull, push e merge de um projeto vinculado           | O proprietário e os colaboradores com acesso de edição         |
| Desvincular um projeto do seu repositório                  | O proprietário do projeto                                      |

* O Overleaf se comunica com o GitHub usando a conta do GitHub do usuário que sincroniza; portanto, cada colaborador que sincroniza vincula sua própria conta do GitHub e precisa ter permissão para fazer push no branch padrão do repositório.
* Colaboradores somente leitura não podem usar a sincronização com GitHub no projeto.

### Q\&A

<Accordion title="Posso fazer force push no branch padrão?">

<strong>Resposta:</strong> Não recomendamos. O Overleaf detecta um force push, emite um aviso e assume o branch reescrito, mesclando as alterações feitas no Overleaf desde a última sincronização. Para evitar surpresas, proteja o branch padrão contra force pushes nas configurações do repositório.

</Accordion>

<Accordion title="Posso renomear o branch padrão de um projeto vinculado?">

<strong>Resposta:</strong> Por favor, não faça isso. O Overleaf continua sincronizando com o branch ao qual o projeto foi vinculado. Para sincronizar com outro branch, desvincule o projeto e, em seguida, importe o repositório para um novo projeto, que usará o branch padrão atual.

</Accordion>

<Accordion title="A sincronização com GitHub mostra “Something wrong with GitHub request”">

<strong>Resposta:</strong> Essa mensagem significa que o servidor não conseguiu alcançar o GitHub, por exemplo por causa de um problema de rede, DNS, TLS ou proxy. Execute `bin/logs web` para ver o erro completo. Se o servidor precisar de um proxy para alcançar o GitHub, defina `GITHUB_SYNC_PROXY_URL`.

</Accordion>

<Accordion title="Devo desativar “Expire user access tokens” no GitHub OAuth App?">

<strong>Resposta:</strong> Sim. A sincronização com GitHub não renova tokens expirados. Com tokens que expiram habilitados, os usuários precisam conectar o GitHub novamente sempre que o token expirar.

</Accordion>

<Accordion title="Minha instância precisa estar acessível pela internet?">

<strong>Resposta:</strong> Não. A vinculação de uma conta passa pelo navegador do usuário, então o endereço de callback do OAuth só precisa abrir no navegador do usuário. O servidor só precisa alcançar o GitHub; se precisar de um proxy para isso, defina `GITHUB_SYNC_PROXY_URL`. O GitHub nunca chama a sua instância: um projeto só é sincronizado quando um usuário o sincroniza no editor.

</Accordion>
