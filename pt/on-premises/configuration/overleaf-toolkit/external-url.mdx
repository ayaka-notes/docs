### Recurso "From External URL"

Para habilitar o recurso ["From External URL"](https://www.overleaf.com/learn/how-to/How_to_upload_a_file_using_an_external_URL), a variável `ENABLED_LINKED_FILE_TYPES` deve incluir o tipo `url`:

```text
ENABLED_LINKED_FILE_TYPES=project_file,project_output_file,url
```

Isso estende tanto o menu _Add Files_ quanto o menu suspenso _Insert Figure_ na barra de ferramentas: o menu _Add Files_ permite adicionar um arquivo ao projeto usando sua URL, enquanto o menu suspenso _Insert Figure_ permite inserir uma imagem no documento diretamente a partir de sua URL.

#### Nota de segurança

Quando os usuários adicionam um link para um arquivo externo em seus projetos, o arquivo é obtido em nome do servidor onde o Overleaf está instalado.

Se o servidor do Overleaf estiver hospedado em uma rede privada que também contenha servidores HTTP internos (destinados apenas ao uso interno), um usuário com acesso ao Overleaf poderia potencialmente acessar dados desses serviços internos.

Para evitar isso, os links para arquivos externos não podem apontar para servidores cujos endereços IP pertençam a qualquer uma das faixas de rede restritas. São elas:

* `127.0.0.0/8` (loopback)
* `169.254.0.0/16` (link-local)
* `10.0.0.0/8` (rede privada)
* `172.16.0.0/12` (rede privada)
* `192.168.0.0/16` (rede privada)

Além disso, foi introduzida a seguinte variável de ambiente:

* `OVERLEAF_LINKED_URL_BLOCKED_NETWORKS`
  * Uma lista, separada por espaços em branco, de redes em notação CIDR das quais é proibido obter recursos externos. Normalmente, deve incluir a rede interna da organização.
    * Exemplo: `OVERLEAF_LINKED_URL_BLOCKED_NETWORKS=123.123.0.0/16 124.124.124.0/24`

No entanto, em muitas organizações, servidores da rede interna também podem hospedar dados que devem ser publicamente acessíveis. Para permitir o acesso a recursos específicos mesmo que toda a rede esteja bloqueada, é fornecida a seguinte variável de ambiente:

* `OVERLEAF_LINKED_URL_ALLOWED_RESOURCES`
  * Uma expressão regular que define os recursos web permitidos dos quais arquivos externos podem ser obtidos. Se uma URL corresponder a essa expressão regular, o acesso a ela é concedido mesmo que sua rede esteja bloqueada.
    *   Exemplo: para permitir URLs como `https://www.example.com/~john/pictures/frog.jpg` e `http://www.example.com/public/whatever/lit.bib`:

        `OVERLEAF_LINKED_URL_ALLOWED_RESOURCES=^https?://www\.example\.com/(?:~[^/]+|public)(?:/.*)?`
    *   Exemplo: para negar URLs como `http://www.example.com/private/whatever/file`, permitindo todos os outros recursos fora da subárvore `private`:

        `OVERLEAF_LINKED_URL_ALLOWED_RESOURCES=^https?://www\.example\.com/(?!private)(?:.*)`<br />

#### Proxy de saída

A partir da versão `v6.3.0` relançada (3 de outubro de 2026), você pode configurar um proxy HTTP(S) de saída caso o servidor precise de um para acessar a internet. Isso também se aplica aos recursos ZIP e TeX externos obtidos pela [Open in Overleaf API](/pt/on-premises/configuration/overleaf-toolkit/overleaf-import-api  "mention"). Configure a seguinte variável:

* `OVERLEAF_LINKED_URL_OUTBOUND_PROXY`
  * URL de um proxy HTTP(S) usado para todas as requisições de arquivos externos. Deixe sem definir para conectar diretamente.
    * Exemplo: `OVERLEAF_LINKED_URL_OUTBOUND_PROXY=http://proxy.internal:3128`
  * Com o proxy definido, os nomes de host são resolvidos pelo proxy, e não pelo servidor do Overleaf; portanto, `OVERLEAF_LINKED_URL_BLOCKED_NETWORKS` e as faixas restritas acima só se aplicam a URLs que contenham um endereço IP. **O proxy deve bloquear o acesso às suas redes internas.**
