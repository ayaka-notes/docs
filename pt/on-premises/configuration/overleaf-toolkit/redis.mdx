### Ativando a autenticação por senha

Se você estiver usando um serviço Redis externo e precisar fornecer uma senha, pode fazer isso definindo as variáveis de ambiente `OVERLEAF_REDIS_PASS` e `REDIS_PASSWORD` no arquivo **config/variables.env** e executando o comando `bin/up -d` para recriar o contêiner **sharelatex**.

Se você estiver executando uma instância local do Redis, precisará configurar o serviço **redis** para iniciar com autenticação por senha. Depois de definir as variáveis de ambiente acima, você também precisará concluir estas etapas adicionais:

Crie um arquivo **docker-compose.override.yml** no diretório <strong>config/</strong> com o seguinte conteúdo:

```yaml title="config/docker-compose.override.yml"
services:
    redis:
        command: "redis-server --requirepass <YOUR-PASSWORD>"
```

<Warning>

Se você tiver a persistência AOF ativada, precisará adicionar `--appendonly yes` ao `command`.

</Warning>

Execute `bin/up -d` para recriar os contêineres.

### Ativando a persistência Append-Only File

(Original: https://docs.overleaf.com/on-premises/configuration/overleaf-toolkit/redis#enabling-append-only-file-persistence)

A persistência AOF (Append-Only File) do Redis oferece uma forma robusta de garantir a durabilidade dos dados, registrando cada operação de escrita recebida pelo servidor. Ao contrário dos snapshots RDB, que fazem cópias pontuais do seu conjunto de dados, o AOF mantém um registro completo de todas as alterações feitas nos seus dados.

<Info>

Desativar o RDB é opcional. Em geral, recomenda-se que os dois métodos de persistência sejam usados em conjunto. Antes de fazer qualquer alteração em produção, analise as vantagens e desvantagens de executar AOF e RDB juntos.

</Info>

Você pode ler mais sobre como ativar a persistência AOF no Redis aqui: [https://redis.io/docs/latest/operate/oss\_and\_stack/management/persistence/#how-i-can-switch-to-aof-if-im-currently-using-dumprdb-snapshotsarrow-up-right](https://redis.io/docs/latest/operate/oss_and_stack/management/persistence/#how-i-can-switch-to-aof-if-im-currently-using-dumprdb-snapshotsarrow-up-right)

1. Agende uma janela de manutenção para a atualização.
2. Pare a instância usando `bin/stop` e faça um backup das pastas <strong>config/</strong> e <strong>data/</strong>.
3. Execute `bin/up` para iniciar a instância
4. Execute o comando `docker exec -it redis sh`
5. Execute o comando `redis-cli` para abrir a interface de linha de comando do Redis
6. No redis-cli, execute o comando `config set appendonly yes`
7. Agora você precisará aguardar até que a reescrita do AOF termine de persistir os dados. Para isso, digite `INFO persistence` no redis-cli e aguarde até que `aof_rewrite_in_progress` e `aof_rewrite_scheduled` sejam `0`, verificando também se `aof_last_bgrewrite_status` é `ok`.
8. Saia do redis-cli digitando `exit` e pressionando a tecla Enter
9. Saia do contêiner redis digitando `exit` e pressionando a tecla Enter
10. ​Execute o comando `ls ./data/redis` e confirme que você consegue ver o arquivo **appendonly.aof**
11. Edite o arquivo **config/overleaf.rc** e altere a variável de ambiente `REDIS_AOF_PERSISTENCE` de `false` para `true`
12. Execute `bin/up -d` e verifique se a aplicação funciona (o editor de projetos e o painel de histórico estão funcionais).
