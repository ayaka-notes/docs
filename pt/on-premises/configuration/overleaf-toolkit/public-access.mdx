Você pode abrir sua instância do Overleaf para pessoas sem conta de três maneiras:

* [Acesso a projetos](/pt/on-premises/configuration/overleaf-toolkit/public-access#project-access  "mention"): permite que convidados abram um link de projeto compartilhado sem fazer login
* [Acesso a páginas](/pt/on-premises/configuration/overleaf-toolkit/public-access#page-access  "mention"): permite que visitantes não autenticados naveguem por páginas como `/learn`, `/templates` e `/devs`
* [Registro público](/pt/on-premises/configuration/overleaf-toolkit/public-access#public-registration  "mention"): permite que os usuários se cadastrem por conta própria, opcionalmente limitado a um domínio de e-mail

### Acesso a projetos

<Info>

Por padrão, mesmo que um usuário obtenha um link de compartilhamento de projeto, ele precisa **fazer login** antes de poder participar de uma sessão de edição colaborativa do projeto.

</Info>

Para permitir o acesso anônimo a projetos compartilhados por link, defina as duas variáveis abaixo:

```dotenv title="config/variables.env"
OVERLEAF_ALLOW_ANONYMOUS_READ_AND_WRITE_SHARING=true
OVERLEAF_ALLOW_PUBLIC_ACCESS=true
```

`OVERLEAF_ALLOW_ANONYMOUS_READ_AND_WRITE_SHARING` habilita leitura/gravação anônima em projetos compartilhados por link.

`OVERLEAF_ALLOW_PUBLIC_ACCESS` impede que usuários não autenticados sejam redirecionados para a página de login.

Recrie os contêineres com `bin/up`. Em seguida, abra uma URL de compartilhamento por link em uma janela privada.

### Acesso a páginas

Por padrão (`OVERLEAF_ALLOW_PUBLIC_ACCESS` não definida), **todas** as páginas, exceto as de login e de registro, redirecionam visitantes não autenticados para a página de login. Isso inclui páginas que deveriam ser públicas, de modo que os links para elas só funcionam para usuários que já estão logados.

Com `OVERLEAF_ALLOW_PUBLIC_ACCESS=true`, visitantes não autenticados podem abrir:

| Página                                                                | Requer                           |
| --------------------------------------------------------------------- | -------------------------------- |
| A ajuda de LaTeX em `/learn` (consulte [adding-latex-user-help.md](/pt/on-premises/configuration/overleaf-toolkit/adding-latex-user-help  "mention")) | `OVERLEAF_PROXY_LEARN=true`      |
| A galeria de templates em `/templates`, páginas de templates, pré-visualizações e downloads em ZIP (consulte [templates.md](/pt/on-premises/configuration/overleaf-toolkit/templates  "mention")) | `OVERLEAF_TEMPLATE_GALLERY=true` |
| A página da Overleaf Import API em `/devs` (consulte [overleaf-import-api.md](/pt/on-premises/configuration/overleaf-toolkit/overleaf-import-api  "mention")) | —                                |

Isso também permite que a [Overleaf Import API](/pt/on-premises/configuration/overleaf-toolkit/overleaf-import-api#signed-out-visitors  "mention") guarde o envio de formulário de um visitante não autenticado até que ele faça login.

A lista de projetos, o editor e a criação de projetos (inclusive a partir de um template ou por meio da Import API) continuam exigindo login.

### Registro público

O registro público está disponível apenas no [ayaka-notes/ayakaleaf-pro](https://github.com/ayaka-notes/ayakaleaf-pro).

<Danger>

Observe que, depois de habilitar o registro público, **qualquer pessoa** com acesso à sua instância do Overleaf poderá se registrar como usuário.

O processo de registro não verifica endereços de e-mail; portanto, use-o apenas em uma intranet ou em um ambiente confiável, ou desative-o quando não precisar mais do registro.

</Danger>

Por padrão, nem a Community Edition nem o Overleaf Pro permitem o registro público.

Para habilitá-lo, adicione isto a `config/variables.env`:

```dotenv title="config/variables.env"
OVERLEAF_ALLOW_PUBLIC_REGISTRATION=true
```

Recrie os contêineres com `bin/up`.

Em seguida, clique em **Sign up** ou acesse `/register`.

### Registro com domínio limitado

O registro público com domínio limitado está disponível apenas no [ayaka-notes/ayakaleaf-pro](https://github.com/ayaka-notes/ayakaleaf-pro).

Antes de habilitar isso, configure o envio de e-mails para que os usuários possam receber convites e notificações. Consulte [Envio de e-mails](/pt/on-premises/configuration/overleaf-toolkit/email-delivery).

Em seguida, adicione a seguinte linha a `config/variables.env`:

```dotenv title="config/variables.env" wrap
OVERLEAF_ALLOW_PUBLIC_REGISTRATION=@example.domain
```

`OVERLEAF_ALLOW_PUBLIC_REGISTRATION` pode ser definida como:

* `true` para permitir que qualquer pessoa que consiga acessar o site se registre
* `@example.domain` para restringir o registro a e-mails desse domínio
