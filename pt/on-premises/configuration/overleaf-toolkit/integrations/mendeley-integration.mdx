#### Configurar a integração com o Mendeley

1. Acesse [este link](https://dev.mendeley.com/myapps.html) para registrar um aplicativo OAuth do Mendeley
2. Configure a **Redirect URL** como: `${OVERLEAF_SITE_URL}/user/mendeley/oauth/callback`
3. Anote o **ID** gerado (geralmente numérico, como `24061` abaixo) e o **Secret** do seu aplicativo
4. Modifique o seu `config/variables.env`&#x20;
5. Mantenha o Authorisation Flow: Elsevier (conforme recomendado)

```dotenv title="config/variables.env"
#################
#   Mendeley    #
#################
# 'mendeley' must be in ENABLED_LINKED_FILE_TYPES (keep 'zotero' too if you use both)
ENABLED_LINKED_FILE_TYPES=project_file,project_output_file,url,mendeley

# From a Mendeley OAuth application (register at https://dev.mendeley.com/myapps.html)
# Redirect URL -> ${OVERLEAF_SITE_URL}/user/mendeley/oauth/callback
MENDELEY_CLIENT_ID=
MENDELEY_CLIENT_SECRET=
# Encrypts the Mendeley OAuth tokens in mongo; if unset, a key file is generated
# in /var/lib/overleaf/data on first use
# How to generate: `openssl rand -hex 32`
MENDELEY_CIPHER_PASSWORD=
# Optional: route the module's server-side Mendeley requests (OAuth + API) through
# an HTTP proxy (must be reachable from the web container; same as github-sync)
# http://10.0.0.1:10808
# (Optional) MENDELEY_PROXY_URL=
```

<Info>

&#x20;`mendeley` deve estar incluído em `ENABLED_LINKED_FILE_TYPES` (mantenha também `zotero` na lista se usar ambos). `MENDELEY_CLIENT_ID` e `MENDELEY_CLIENT_SECRET` vêm do seu aplicativo OAuth registrado. A senha de cifragem criptografa os tokens OAuth do Mendeley no MongoDB (gere uma com `openssl rand -hex 32`); sem ela, um arquivo de chave é gerado no volume de dados no primeiro uso. Opcionalmente, defina `MENDELEY_PROXY_URL` para encaminhar as requisições do Mendeley feitas pelo servidor (OAuth + API) por meio de um proxy HTTP acessível a partir do contêiner web.

</Info>

### Observações

<Warning>

Ao atualizar uma instalação existente que tenha arquivos de bibliografia vinculados ao Mendeley para a versão 6.3.0 relançada, siga as [instruções de migração do Zotero / Mendeley](/pt/on-premises/release-notes/release-notes-6.x.x#ayakaleaf-pro-6.3.0  "mention"). Novas instalações não precisam dessa migração.

</Warning>

<Danger>

Como o Ayakaleaf é uma plataforma colaborativa, para melhorar a segurança, a partir da versão 6.3.0 apenas o criador original de um arquivo de referências `bib` poderá atualizar o arquivo importado.

</Danger>

Por exemplo, suponha que o proprietário do projeto, o Usuário A, habilite o compartilhamento por link e crie um arquivo `test.bib` no projeto, vinculando-o à sua própria conta do Zotero. Se outro usuário, o Usuário B, acessar o projeto pelo link compartilhado, ele ainda poderá ler e baixar `test.bib`, mas não poderá atualizar nem reimportar o arquivo a partir do Zotero. Somente o Usuário A, como criador original do arquivo de referências, pode realizar atualizações. Ou seja, apenas o criador original do arquivo `.bib` tem permissão para atualizá-lo.
