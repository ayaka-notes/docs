Cada projeto tem um servidor MCP, para que clientes de IA como Claude Code, Codex, Cursor, VS Code ou Gemini CLI possam trabalhar nele: ler e editar seus arquivos, compilá-lo, ler o log do LaTeX, baixar o PDF e responder a comentários. A partir da v6.3.3, eles também podem consultar o histórico e restaurar versões, revisar alterações rastreadas, adicionar comentários, usar o chat do projeto e mover arquivos.

<Info>

Este recurso foi desenvolvido por [ayaka-notes/ayakaleaf-pro](https://github.com/ayaka-notes/ayakaleaf-pro). Ele foi introduzido na v6.3.1 e posteriores. As ferramentas de histórico, alterações rastreadas, chat do projeto, novos comentários e movimentação de arquivos estão disponíveis a partir da v6.3.3, veja [Novidades da v6.3.3](/on-premises/user-guide/users/mcp-server#new-in-v6.3.3).

</Info>

### Configuração {#setup}

O servidor MCP vem com a integração com Git: habilite o [git-bridge](/pt/on-premises/configuration/overleaf-toolkit/integrations/git-integration), e o servidor MCP também ficará disponível. Não há mais nada a configurar.

### Conectar um cliente de IA {#connect-an-ai-client}

1. Em **Account Settings**, gere um token de autenticação do Git. O mesmo token é usado para o servidor MCP e para o Git.
2. No editor, abra **Integrations** e clique em **MCP server**. São exibidos o endereço do servidor MCP do projeto, `https://<your-overleaf>/project/<project_id>/mcp`, e como adicioná-lo a cada cliente de IA: copie o comando e substitua `<token>` pelo seu token.

O token é enviado no cabeçalho HTTP `Authorization: Bearer <token>`. Por exemplo, o comando para o Claude Code é:

```bash
claude mcp add --transport http overleaf \
  https://<your-overleaf>/project/<project_id>/mcp \
  --header "Authorization: Bearer <token>"
```

### Uso {#usage}

Depois de conectado, faça pedidos ao cliente de IA em linguagem natural. Por exemplo:

| Você pede | O cliente de IA usa |
| --- | --- |
| _Corrija os erros de digitação na introdução._ | `read_file`, `edit_file`: as edições aparecem em tempo real no editor |
| _Compile o projeto e corrija os erros de LaTeX._ | `compile`, `get_compile_log`, `edit_file` |
| _Responda aos comentários abertos e depois resolva-os._ | `list_comments`, `reply_to_comment`, `resolve_comment` |
| _Mude para XeLaTeX e baixe o PDF._ | `update_settings`, `compile`, `get_output_file_link` |
| _Reescreva o resumo como uma alteração rastreada._ | `read_file`, `edit_file` com `trackChanges` (v6.3.3) |
| _O que mudou desde a versão enviada?_ | `list_versions`, `list_changes`, `diff` (v6.3.3) |
| _Mova os capítulos para uma pasta chamada chapters._ | `move_file` (v6.3.3) |

### Ferramentas {#tools}

| Grupo | Ferramentas |
| --- | --- |
| Projeto | `get_clone_info`, `get_settings`, `update_settings` |
| Arquivos | `list_files`, `read_file`, `edit_file`, `write_file`, `delete_file`, `move_file`, `create_folder` |
| Compilação | `compile`, `get_compile_log`, `get_output_file_link`, `word_count` |
| Comentários | `list_comments`, `reply_to_comment`, `resolve_comment`, `reopen_comment`, `add_comment`, `edit_comment_message`, `delete_comment_message` |
| Alterações rastreadas | `list_tracked_changes`, `accept_tracked_changes`, `reject_tracked_changes` |
| Histórico | `list_versions`, `list_changes`, `diff`, `create_version`, `delete_version`, `restore_file`, `restore_project` |
| Chat | `list_chat_messages`, `send_chat_message` |

A v6.3.3 tem 33 ferramentas, ou 31 com `OVERLEAF_DISABLE_CHAT=true`, que remove as ferramentas de chat. A v6.3.1 e a v6.3.2 têm as outras 17: tudo acima exceto `move_file`, `create_folder`, `add_comment`, `edit_comment_message`, `delete_comment_message`, as ferramentas de alterações rastreadas, as de chat e as de histórico além de `list_versions`. Na v6.3.3, `read_file` também lê um arquivo em uma versão do histórico, `edit_file` e `write_file` aceitam `trackChanges`, e `update_settings` também define o idioma da verificação ortográfica.

As edições feitas com `edit_file`, `write_file` e `move_file` aparecem ao vivo no editor e são mescladas com as dos colaboradores. Para muitos arquivos de uma vez ou arquivos binários, o cliente de IA também pode clonar o projeto com Git e fazer push.

Com `trackChanges`, a edição de um arquivo existente é uma alteração rastreada do usuário do token, mesmo quando o controle de alterações está desativado no projeto; um arquivo novo nunca é. Sem `trackChanges`, as edições seguem a configuração de controle de alterações do projeto.

### Permissões {#permissions}

O servidor MCP segue as configurações de compartilhamento do projeto, assim como o Git:

* Todos que podem ver o projeto podem lê-lo, compilá-lo e baixar sua saída.
* Apenas o proprietário e os editores podem alterar seus arquivos e configurações, restaurar versões e aceitar ou rejeitar alterações rastreadas.
* Revisores também podem adicionar comentários e respondê-los, resolver, reabrir ou excluir os comentários que iniciaram, e salvar versões. Eles não podem editar arquivos, nem mesmo como alterações rastreadas.
* Cada pessoa edita apenas suas próprias mensagens de comentário, e revisores excluem apenas as suas.
* Apenas o proprietário exclui versões que outros salvaram.
* Leitores que entraram por um link não podem ver os comentários, as alterações rastreadas, o histórico nem o chat, assim como no editor. Leitores convidados podem vê-los e usar o chat.
* Se o proprietário do projeto não tiver **Full project history**, as ferramentas de histórico mostram apenas as alterações das últimas 24 horas, como o painel de histórico. Administradores veem todas.

O guia do usuário tem uma tabela do que cada função pode fazer, veja [Quem pode fazer o quê](/on-premises/user-guide/users/mcp-server#who-may-do-what).

### Q\&A {#q&a}

<Accordion title="Não vejo Integrations nem MCP server no editor">

<strong>Resposta:</strong> O MCP server não tem uma variável de ambiente própria. Ele é habilitado com `GIT_BRIDGE_ENABLED=true` em `config/overleaf.rc`; consulte [Integração com Git](/pt/on-premises/configuration/overleaf-toolkit/integrations/git-integration). Depois de alterá-la, execute `bin/up -d`. Sem o git-bridge, o editor não mostra a aba **Integrations** na barra lateral esquerda.

</Accordion>

<Accordion title="O cliente de IA diz “Track changes is off for this project”">

<strong>Resposta:</strong> O cliente pediu uma alteração rastreada, mas a conta do proprietário do projeto não tem controle de alterações. Clique em **Admin** e depois em **Manage Users**, abra o proprietário e, na aba **Features**, ative **Track changes**, veja [Features](/pt/on-premises/user-guide/administrators/user-management#features). Edições sem `trackChanges` continuam funcionando.

</Accordion>

<Accordion title="O cliente de IA vê apenas as alterações das últimas 24 horas">

<strong>Resposta:</strong> A conta do proprietário do projeto não tem o histórico completo do projeto, então as ferramentas de histórico mostram o mesmo que o painel de histórico: as alterações das últimas 24 horas. Clique em **Admin** e depois em **Manage Users**, abra o proprietário e, na aba **Features**, ative **Full project history**, veja [Features](/pt/on-premises/user-guide/administrators/user-management#features).

</Accordion>
