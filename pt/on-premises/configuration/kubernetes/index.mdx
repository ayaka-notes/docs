Uma implantação Kubernetes lê as mesmas variáveis de ambiente que o Toolkit. Onde uma página do Toolkit diz "adicione isto a `config/variables.env`", coloque o valor no ConfigMap `overleaf-env`, ou no Secret `overleaf-secrets` quando for uma senha, chave ou token. Depois, reinicie:

```bash
kubectl -n overleaf apply -f 30-config.yaml        # after editing the ConfigMap
kubectl -n overleaf patch secret overleaf-secrets --type merge \
  -p '{"stringData":{"GITHUB_TOKEN_CIPHER_PASSWORD":"'"$(openssl rand -hex 32)"'"}}'
kubectl -n overleaf rollout restart deployment/overleaf
```

Os valores em `config/overleaf.rc` são configurações do Toolkit, não variáveis de ambiente; o Q\&A no final desta página indica o que os substitui.

### Certificados e outros arquivos

Alguns recursos recebem um caminho de arquivo em vez de um valor: os certificados SAML (`OVERLEAF_SAML_IDP_CERT`, ...), a CA do LDAP (`OVERLEAF_LDAP_TLS_OPTS_CA_PATH`) ou uma CA privada para um GitHub Enterprise, GitLab ou Gitea auto-hospedado (`NODE_EXTRA_CA_CERTS`). Coloque os arquivos em um Secret e monte-o onde as páginas do Toolkit os esperam, `/var/lib/overleaf/certs`:

```bash
kubectl -n overleaf create secret generic overleaf-certs --from-file=idp_cert.pem --from-file=ca.pem
```

```yaml title="40-overleaf.yaml (additions)"
          volumeMounts:
            # ...
            - name: certs
              mountPath: /var/lib/overleaf/certs
              readOnly: true
      volumes:
        # ...
        - name: certs
          secret:
            secretName: overleaf-certs
```

Em seguida, refira-se a eles pelo caminho no ConfigMap, por exemplo `NODE_EXTRA_CA_CERTS: /var/lib/overleaf/certs/ca.pem`, e reinicie.

<Warning>

<strong>Senhas de criptografia.</strong> Defina no Secret todas as `*_CIPHER_PASSWORD` dos recursos que você usa. Caso contrário, alguns recursos geram um arquivo de chave no volume de dados no primeiro uso: com uma réplica, isso funciona até o volume ser perdido; com várias réplicas, cada réplica criptografaria com uma chave diferente.

</Warning>

### Q\&A

<Accordion title="De quais configurações do Toolkit em `config/overleaf.rc` eu preciso?">

<strong>Resposta:</strong> Nenhuma delas é lida pelo Ayakaleaf Pro. Seus equivalentes no Kubernetes:

| `config/overleaf.rc`                         | Kubernetes                                                        |
| -------------------------------------------- | ----------------------------------------------------------------- |
| `OVERLEAF_LISTEN_IP`, `OVERLEAF_PORT`        | o Service (NodePort) ou seu ingress                               |
| `SIBLING_CONTAINERS_ENABLED`                 | `SANDBOXED_COMPILES*` no ConfigMap, socket do Docker no pod       |
| `GIT_BRIDGE_ENABLED`                         | [Integração com Git](/pt/on-premises/configuration/kubernetes/integrations/git-integration)                             |
| `MONGO_ENABLED`, `REDIS_ENABLED`, `MONGO_URL`, `REDIS_HOST` | os StatefulSets ou seus serviços gerenciados, `OVERLEAF_MONGO_URL` e `OVERLEAF_REDIS_HOST` |
| `REDIS_AOF_PERSISTENCE`                      | `--appendonly yes` em `20-redis.yaml`                             |
| `NGINX_ENABLED`, `TLS_*`                     | seu ingress ou balanceador de carga                               |

</Accordion>
