A Import API (`/docs` e os botões "Open in Ayakaleaf", o módulo `open-in-overleaf`) é executada no serviço **web** de cada pod do Ayakaleaf Pro e fica ativada por padrão. Os arquivos informados por URL são baixados por meio do linked-url-proxy no mesmo pod. Como chamá-la está descrito em [Overleaf Import API](/pt/on-premises/configuration/overleaf-toolkit/integrations/overleaf-import-api).

| | |
| --- | --- |
| Serviço | web (módulo `open-in-overleaf`); downloads por meio do linked-url-proxy |
| Exterior → Overleaf | navegadores fazem `GET` ou `POST ${OVERLEAF_SITE_URL}/docs` a partir de qualquer site |
| Pod → exterior | downloads de `snip_uri` e `zip_uri`, limitados conforme descrito em [URL externa](/pt/on-premises/configuration/kubernetes/external-url) |
| Estado | a requisição de um visitante não conectado, mantida no Redis por 10 minutos até que ele faça login |
| Tarefas periódicas | nenhuma |

### Configuração

Nada é necessário para ativá-la. Configurações relacionadas no ConfigMap:

| Configuração | |
| --- | --- |
| `OVERLEAF_ALLOW_PUBLIC_ACCESS: "true"` | Visitantes não conectados podem abrir `/devs`, e uma requisição que eles enviam é mantida até que façam login, veja [Acesso público](/pt/on-premises/configuration/kubernetes/authentication/public-access). |
| `MAX_UPLOAD_SIZE` | Maior ZIP que uma requisição pode conter, em MB (padrão `50`). Seu ingress ou balanceador de carga também precisa aceitar corpos de requisição desse tamanho. |
| `OVERLEAF_LINKED_URL_*` | Para quais endereços `snip_uri` e `zip_uri` podem apontar, veja [URL externa](/pt/on-premises/configuration/kubernetes/external-url). |

### Várias réplicas

Nada adicional. A requisição de um visitante não conectado é mantida no Redis, então ela é retomada em qualquer réplica que o visitante alcance depois de fazer login.

### Testado no Kubernetes

No Kubernetes 1.37 com uma réplica, nossos testes ponta a ponta da Import API são aprovados (14 casos): a página `/devs` e seu projeto de exemplo, trechos, documentos completos, links codificados em URL e arquivos de data URLs transformados em projetos, envios que não podem se tornar um projeto recusados, downloads de endereços internos recusados, envios e links de visitantes não conectados mantidos durante o login e, com `OVERLEAF_ALLOW_PUBLIC_ACCESS`, `/devs` para visitantes não conectados e um trecho enviado retomado uma vez após o login; o último caso também é aprovado em três réplicas atrás do HAProxy.
