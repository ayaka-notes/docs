O serviço **web** verifica as senhas locais quando os usuários se registram, definem ou alteram uma senha. Logins via SSO (LDAP, SAML, OIDC) não são afetados; as senhas deles são responsabilidade do provedor de identidade. Consulte [Restrições de senha](/pt/on-premises/configuration/overleaf-toolkit/authentication/password-restrictions) para o Toolkit.

| | |
| --- | --- |
| Serviço | web, em cada pod do Ayakaleaf Pro; lido quando o web inicia |
| Rede | nenhuma |
| Tarefas periódicas | nenhuma |

### Configuração

Adicione ao ConfigMap `overleaf-env` e reinicie:

```yaml title="30-config.yaml (additions)"
  OVERLEAF_PASSWORD_VALIDATION_MIN_LENGTH: "12"
  OVERLEAF_PASSWORD_VALIDATION_MAX_LENGTH: "72"
```

```bash
kubectl apply -f 30-config.yaml
kubectl -n overleaf rollout restart deployment/overleaf     # or statefulset/overleaf
```

| Variável | Padrão | |
| --- | --- | --- |
| `OVERLEAF_PASSWORD_VALIDATION_MIN_LENGTH` | `8` | Senha mais curta aceita. |
| `OVERLEAF_PASSWORD_VALIDATION_MAX_LENGTH` | `72` | Senha mais longa aceita; valores acima de `72` são tratados como `72`. |

Coloque os números entre aspas: um ConfigMap armazena apenas strings.

<Warning>

`OVERLEAF_PASSWORD_VALIDATION_PATTERN` é lida, mas não é aplicada: uma senha que não corresponde a ela é aceita. Apenas os limites de comprimento se aplicam.

</Warning>

### Várias réplicas

Nada extra: todas as réplicas leem o mesmo ConfigMap.

### Testado no Kubernetes

No Kubernetes 1.37 com uma réplica, `OVERLEAF_PASSWORD_VALIDATION_MIN_LENGTH: "12"` e `OVERLEAF_PASSWORD_VALIDATION_PATTERN: aA$3` no ConfigMap, a ativação de uma nova conta recusou uma senha de 10 caracteres e aceitou uma senha de 20 caracteres apenas com letras minúsculas, que o padrão teria recusado. Nossos testes de ponta a ponta para o registro também recusam `123456` como curta demais com os valores padrão.
