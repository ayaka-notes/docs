title: Acesso público
description: Permita que convidados, visitantes não conectados e novos usuários acessem uma implantação Kubernetes.
icon: lock-open
---

O acesso de convidados a projetos compartilhados, as páginas públicas e o autorregistro são ativados com variáveis de ambiente lidas pelo serviço **web**; o serviço de tempo real então atende os convidados por meio da sessão deles. O que cada opção libera está descrito em [Acesso público](/pt/on-premises/configuration/overleaf-toolkit/authentication/public-access).

| | |
| --- | --- |
| Serviço | web (e tempo real para convidados no editor), em cada pod do Ayakaleaf Pro; lido quando o web inicia |
| Pod → exterior | o servidor SMTP, quando o registro envia e-mails de ativação |
| Estado | tokens de acesso de convidados na sessão, limites de taxa de registro no Redis |
| Tarefas periódicas | nenhuma |

### Configuração

Adicione as opções de que você precisa ao ConfigMap `overleaf-env`:

```yaml title="30-config.yaml (additions)"
  # Guests open link-shared projects without an account
  OVERLEAF_ALLOW_ANONYMOUS_READ_AND_WRITE_SHARING: "true"
  # Signed-out visitors may open /learn, /templates, /devs and view links
  OVERLEAF_ALLOW_PUBLIC_ACCESS: "true"
  # Self-registration: "true", or only some domains
  OVERLEAF_ALLOW_PUBLIC_REGISTRATION: "@example.com, @*.uni.example"
```

```bash
kubectl apply -f 30-config.yaml
kubectl -n overleaf rollout restart deployment/overleaf     # or statefulset/overleaf
```

Coloque todos os valores entre aspas. Valores que começam com `@` precisam estar entre aspas no YAML; caso contrário, o `kubectl apply` rejeita o arquivo.

O registro limitado a domínios envia um e-mail de ativação, então o [Envio de e-mails](/pt/on-premises/configuration/kubernetes/email-delivery) precisa funcionar a partir dos pods: coloque o host SMTP no ConfigMap e `OVERLEAF_EMAIL_SMTP_PASS` no Secret.

### Várias réplicas

Nada extra. O acesso de um convidado a um projeto é mantido na sessão no Redis, então o editor funciona em qualquer réplica que o balanceador de carga escolher.

### Testado no Kubernetes

No Kubernetes 1.37, nossos testes de ponta a ponta para acesso público passam: em uma réplica, autorregistro com `OVERLEAF_ALLOW_PUBLIC_REGISTRATION` definida como `true`, como um domínio, como vários domínios com um curinga de subdomínio e como `@*`, com o e-mail de ativação nos modos por domínio (43 casos); visitantes não conectados em `/devs` e um snippet enviado mantido durante o login com `OVERLEAF_ALLOW_PUBLIC_ACCESS` (2 casos); um convidado não conectado em um projeto compartilhado por link com ambas as opções ativadas (3 casos); e, em três réplicas atrás do HAProxy, OIDC junto com acesso público (1 caso).
