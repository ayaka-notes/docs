Temos muito orgulho de anunciar o lançamento do Overleaf Pro 6.3.1, o editor LaTeX online mais poderoso e completo da comunidade. Uma versão de correção normalmente significa um punhado de pequenas correções. Esta vai muito além: junto com dezenas de correções de bugs, ela traz cinco novos recursos e conecta seus projetos aos lugares onde você já trabalha, do Dropbox e do GitLab ao agente de IA no seu terminal.

### Alterações

* Sincronização com Dropbox (prévia antecipada): mantenha cada projeto sincronizado com o seu próprio Dropbox, nas duas direções.
* Sincronização com GitLab (prévia antecipada): sincronização bidirecional com o GitLab.com ou com o seu GitLab autogerenciado.
* MCP Server: permita que Claude Code, Codex, Cursor, VS Code ou Gemini CLI trabalhem diretamente em um projeto.
* GitHub Enterprise: aponte a sincronização com GitHub para a sua própria instância do GitHub Enterprise.
* Reconhecimento de símbolos manuscritos: desenhe um símbolo e obtenha o comando LaTeX.
* `OVERLEAF_DISABLE_LOCAL_LOGIN`: oculte o login com e-mail e senha para que os usuários entrem apenas com SSO.
* Correções de bugs encontradas pelo nosso sistema de testes E2E e pela Internal Horizon Issue Investigation.
* Patches do Overleaf upstream 6.3.1.

<Info>

A sincronização com Dropbox e a sincronização com GitLab são lançadas na 6.3.1 como **prévias antecipadas** para testes graduais e serão lançadas oficialmente na v6.4.0. Sua configuração e seu comportamento ainda podem mudar até lá. Ambas vêm desativadas por padrão. Relate qualquer problema no [GitHub](https://github.com/ayaka-notes/ayakaleaf-pro/issues).

</Info>

#### Recurso 01: sincronização com Dropbox (prévia)

Algumas pessoas nunca querem pensar em Git. Elas só querem que a tese seja uma pasta no notebook, e a sincronização com Dropbox oferece exatamente isso. Cada usuário vincula sua própria conta do Dropbox, e os projetos dos quais é proprietário e os compartilhados com ele aparecem em `Apps/<your app name>/`. Edite no Overleaf e a alteração aparece no Dropbox. Edite o arquivo localmente no seu editor favorito, salve-o, e a alteração volta para o Overleaf por meio de um webhook assinado.

Para administradores: o Git bridge precisa estar habilitado. Crie um aplicativo no Dropbox App Console e depois defina `DROPBOX_ENABLED`, `DROPBOX_APP_KEY`, `DROPBOX_APP_SECRET`, `DROPBOX_APP_NAME` e `DROPBOX_TOKEN_CIPHER_PASSWORD`. `DROPBOX_SYNC_PROXY_URL` é opcional, para servidores que não conseguem acessar o Dropbox diretamente. Em seguida, crie uma única vez os índices do MongoDB de que a sincronização com Dropbox precisa, antes que os usuários vinculem suas contas.

Consulte [Sincronização com Dropbox](/pt/on-premises/configuration/overleaf-toolkit/dropbox-synchronisation  "mention") para as instruções completas de configuração.

#### Recurso 02: sincronização com GitLab (prévia)

A sincronização com GitHub é um dos nossos recursos mais queridos desde a 6.2, e muitas universidades e empresas mantêm seu código no GitLab. A sincronização com GitLab funciona da mesma forma: vincule sua conta, importe um repositório pelo menu de novo projeto ou exporte um projeto para um novo projeto do GitLab. Depois, faça push e pull a partir do editor e mescle por meio de merge requests.

Funciona com o GitLab.com e com o GitLab autogerenciado 15.10 ou posterior. Defina `GITLAB_SYNC_ENABLED`, `GITLAB_SYNC_CLIENT_ID`, `GITLAB_SYNC_CLIENT_SECRET` e `GITLAB_TOKEN_CIPHER_PASSWORD`, além de `GITLAB_SYNC_URL` para uma instância autogerenciada.

Consulte [Sincronização com GitLab](/pt/on-premises/configuration/overleaf-toolkit/gitlab-synchronisation  "mention") para as instruções completas de configuração.

#### Recurso 03: MCP Server

Na 6.3, colocamos um assistente de IA dentro do editor. Na 6.3.1, abrimos a porta no sentido inverso: cada projeto agora tem seu próprio servidor MCP, para que o agente de IA que você já usa possa trabalhar diretamente no seu artigo. Peça ao Claude Code para corrigir os erros de digitação da introdução, peça ao Codex para compilar e corrigir os erros de LaTeX ou peça ao Cursor para responder aos comentários de revisão em aberto. O agente lê e edita arquivos em tempo real, então você e seus colaboradores veem as edições dele aparecerem no editor enquanto ele digita. Ele também pode compilar, ler o log, obter o PDF, contar palavras e listar versões.

O endpoint é `/project/<project_id>/mcp`. Autentique-se com o mesmo token Git que você usa para `git clone`. O acesso segue as configurações de compartilhamento do projeto, então o agente de um visualizador pode ler, mas não editar, e cada ferramenta tem limite de taxa. Não há mais nada a configurar: o servidor MCP é habilitado junto com o Git bridge.

Consulte [MCP Server](/pt/on-premises/configuration/overleaf-toolkit/mcp-server  "mention") para saber como conectar cada cliente de IA.

#### Recurso 04: GitHub Enterprise

A sincronização com GitHub não está mais limitada ao github.com. Defina `GITHUB_SYNC_URL` para o seu GitHub Enterprise Server, ou para o GitHub Enterprise Cloud com residência de dados (`GHE.com`), e os endpoints REST e GraphQL são derivados dele. Se a sua instância fizer algo incomum, substitua-os com `GITHUB_SYNC_API_URL` e `GITHUB_SYNC_GRAPHQL_URL`. Deixe-os sem definir e tudo continua no github.com.

Consulte [Sincronização com GitHub](/pt/on-premises/configuration/overleaf-toolkit/github-synchronisation#github-enterprise  "mention") para mais detalhes.

#### Recurso 05: reconhecimento de símbolos manuscritos

Você sabe como o símbolo é, mas não como ele se chama. É `\varsigma` ou `\zeta`? `\models` ou `\vDash`? Mude a paleta de símbolos para o modo de desenho, esboce-o com o mouse ou o trackpad, e a paleta sugere os comandos LaTeX correspondentes.

O reconhecimento é executado inteiramente no navegador, com um modelo treinado pela ayaka-notes, então nada do que você desenha sai da sua máquina. O botão de desenho fica oculto em navegadores sem `OffscreenCanvas` (por exemplo, Safari 15).

#### Correções de bugs

Esta versão também traz uma longa lista de correções. Muitas delas foram encontradas pelo nosso novo sistema de testes E2E, que agora executa diariamente suítes para cada módulo, e pela Internal Horizon Issue Investigation: toda vez que corrigimos um bug, varremos toda a base de código em busca de bugs semelhantes antes de encerrá-lo.

* **Autenticação**: contas locais podem definir e alterar a senha em instâncias com SSO, e usuários OIDC não podem mais alterar o próprio e-mail. Os logins LDAP, SAML e OIDC não falham mais quando um atributo de nome tem vários valores, e o logout SAML/OIDC voltou a funcionar.
* **Usuários suspensos**: suspender um usuário agora encerra as sessões dele e fecha os editores abertos, e os tokens Git e os downloads MCP dele são rejeitados.
* **Sincronização com GitHub**: apenas o proprietário pode exportar um projeto, as edições feitas durante o pull ficam pendentes, arquivos vazios são sincronizados e merges manuais são verificados no GitHub.
* **Zotero / Mendeley**: você recebe uma mensagem para vincular novamente quando suas credenciais deixam de funcionar, e as referências são reindexadas após uma importação.
* **Serviços externos**: as requisições ao Zotero, ao Mendeley, ao GitHub, ao GitLab e à pesquisa na web têm um tempo limite de conexão de 3 s em vez de 1 s, então redes mais lentas não falham mais.
* **Controle de alterações**: os dados de revisão incluem documentos não carregados e alterações não salvas.
* **Painel de administração**: restaurar projetos excluídos, alterar proprietários e editar usuários funcionam corretamente, e uma falha de e-mail não interrompe mais a criação ou a exclusão de contas.
* **Galeria de modelos**: uma ordenação inválida retorna 400 em vez de 500, e publicar um projeto sem arquivo principal solicita um.

Consulte as [notas de versão da 6.3.1](/pt/on-premises/release-notes/release-notes-6.x.x#ayakaleaf-pro-6.3.1  "mention") para a lista completa.

#### Atualização

* A partir da 6.3.0: nenhuma migração é necessária. Baixe a nova imagem e reinicie.
* A partir da 6.2.x ou anterior com Zotero ou Mendeley em uso: execute primeiro a [migração do Zotero / Mendeley](/pt/on-premises/release-notes/release-notes-6.x.x#ayakaleaf-pro-6.3.0  "mention") da 6.3.0.
* A sincronização com Dropbox e a sincronização com GitLab vêm desativadas por padrão. A sincronização com GitLab precisa apenas de novas variáveis de ambiente. A sincronização com Dropbox também precisa que seus índices do MongoDB sejam criados uma única vez, antes que os usuários vinculem suas contas: consulte [Criar os índices do banco de dados](/pt/on-premises/configuration/overleaf-toolkit/dropbox-synchronisation#create-the-database-indexes  "mention").
