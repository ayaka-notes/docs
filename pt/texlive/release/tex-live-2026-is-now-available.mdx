Este documento vem do [blog do Overleaf](https://www.overleaf.com/blog/tex-live-2026-is-now-available). O Overleaf lançou o TeX Live 2026 em 18 de agosto de 2026. Também atualizamos o [ayaka-notes/texlive-full](https://github.com/ayaka-notes/texlive-full) para o TeX Live 2026.

</Info>

Veja o que mudou, o que verificar antes de migrar e como corrigir os novos erros mais comuns. A atualização mais notável desta versão é que os recursos que produzem PDFs acessíveis estão prontos para uso em fluxos de trabalho de produção e saíram da fase de protótipo. Esta atualização também dá acesso a programas, fontes e pacotes de macros relacionados ao TeX novos e atualizados. Este post do blog aborda todas as informações principais e as mudanças importantes que você precisa conhecer.

O Overleaf lança uma atualização oficial uma vez por ano, após testes rigorosos para garantir que tudo funcione como esperado. Fazemos isso para garantir uma experiência consistente e estável para os milhões de usuários do Overleaf e para que nossa equipe de suporte possa ajudar você com quaisquer problemas ou dúvidas.

### O que é o TeX Live?

O [TeX Live](https://tug.org/texlive/) é uma distribuição gratuita do sistema de composição tipográfica TeX que inclui muitos programas, fontes e pacotes de macros relacionados ao TeX, incluindo o LaTeX, mantida por um grupo central de usuários de TeX e pelo [TeX User Group](https://tug.org/). O Overleaf usa o TeX Live em seus servidores de compilação para gerar a pré-visualização e produzir o PDF do seu projeto.

Com a introdução do TeX Live 2026, os usuários podem criar PDFs totalmente acessíveis e com tags, incluindo matemática legível.

### Meus projetos existentes funcionarão normalmente?

Sim, seus projetos existentes continuarão funcionando, pois continuarão usando a versão do TeX Live da época em que foram criados. Desaconselhamos mudar a versão do TeX Live de um projeto existente, a menos que seja necessário; a mudança pode resultar em novos erros ou avisos.

<strong>Observação:</strong> pode haver modelos na galeria do Overleaf que não funcionem ou não compilem com as opções de acessibilidade habilitadas. A maioria dos modelos não é criada nem mantida pelo Overleaf; entre em contato com o autor em caso de problemas.

### Posso mudar para o TeX Live 2026 em projetos existentes?

Sim, você pode mudar facilmente para o TeX Live 2026 em projetos existentes; a transição é simples e sem complicações. No projeto que deseja alterar, abra _Settings_ e clique em _Compiler_ na barra lateral; você verá uma lista suspensa para selecionar a versão do TeX Live. Isso permite atualizar rapidamente seu projeto para atender aos requisitos de editoras, servidores de preprints e outras plataformas que usam uma versão específica do TeX Live para compilar submissões.

Se o seu projeto compilava sem problemas no TeX Live 2025 (ou em versões anteriores), mas agora apresenta erros no TeX Live 2026, isso pode ser devido a mudanças no kernel ou em alguns pacotes. Sabe-se que alguns pacotes produzem novos erros ou avisos no TeX Live 2026; reunimos os mais comuns, junto com as correções, em uma seção separada abaixo.

### Principais mudanças no TeX Live 2026

#### O PDF acessível e com tags saiu da fase de protótipo

Desde a [atualização de novembro de 2025](https://www.latex-project.org/news/latex2e-news/ltnews42.pdf) do LaTeX Project, a marcação com tags (tagging) não é mais descrita como protótipo; ela é considerada utilizável em fluxos de trabalho de produção, desde que o documento se limite a pacotes e classes que já suportam tagging.

Para habilitar a saída de PDF com tags, basta um único comando colocado antes de `\documentclass`:

```latex
\DocumentMetadata{
 pdfstandard = {UA-2, A-4f},
 tagging = on,
 lang = en
 }
\documentclass{article}
```

Usar `\DocumentMetadata` também ativa alguns padrões: codificação de fontes T1 e, [desde junho de 2025](https://www.latex-project.org/news/latex2e-news/ltnews41.pdf), saída em **PDF 2.0** em vez do antigo 1.7. O PDF 2.0 é importante aqui porque é o que permite a marcação com MathML (a parte que torna a matemática legível para leitores de tela, em vez de um amontoado de símbolos sem rótulo).

Algumas observações práticas:

* Durante a redação, você pode definir `tagging = draft` para manter os avisos de acessibilidade, mas sem gravar a árvore de estrutura (útil para acelerar a compilação de documentos longos).
* Uma chave check-tagging-status informa, no final do log, se os pacotes que você está usando são reconhecidamente compatíveis com tagging. Também há um [banco de dados de status em tempo real](https://latex3.github.io/tagging-project/tagging-status/) que você pode consultar antes de começar.
* Se você quiser apenas a parte de gerenciamento de PDF, sem o código de tagging, agora existe um pacote `pdfmanagement` separado para isso.

Uma mudança que merece destaque em particular: `\DocumentMetadata` agora só pode ser chamado uma vez em um documento. Uma segunda chamada resulta em um erro de compilação, da mesma forma que um segundo `\documentclass`.

#### Matemática acessível, com significado

[Novidade desde novembro de 2025](https://www.latex-project.org/news/latex2e-news/ltnews42.pdf), `\MathMLintent` e `\MathMLarg` permitem que os autores informem às tecnologias assistivas o que uma notação significa, e não apenas como ela é construída. Por exemplo, `|y|` agora pode ser lido em voz alta como _"o valor absoluto de y"_ em vez de _"barra y barra"_.

A marcação de matemática acessível exige compilar com o LuaLaTeX, pois é o mecanismo que gera o MathML, e usar o pacote `unicode-math` ou `lua-unicode-math`.

#### Gráficos e figuras agora também têm significado

A acessibilidade não se limita a texto e matemática. `\includegraphics`, `picture` e `tikzpicture` agora aceitam chaves de acessibilidade, para que cada gráfico possa ser marcado adequadamente:

```latex
\includegraphics[alt={A bar chart of quarterly revenue}]{revenue}
```

Os gráficos podem ser classificados de quatro formas: como uma figura ilustrativa propriamente dita, como um artefato decorativo a ser ignorado pelas ferramentas assistivas, como substituto de um símbolo ou como texto comum (útil para coisas como `todonotes`). A saída do TikZ é suportada nativamente.

#### Uma nova classe para criar apresentações acessíveis e com tags

A classe de documento `beamer` é muito popular para criar slides de apresentação em LaTeX. Infelizmente, ela não é compatível com o código de tagging do LaTeX. Em vez disso, uma nova classe de documento, [`ltx-talk`](https://ctan.org/pkg/ltx-talk), foi criada do zero. Sua sintaxe é bastante semelhante à do `beamer`, embora nem todas as funcionalidades do `beamer` tenham sido implementadas no `ltx-talk`.

#### Novos mecanismos de modelos para estilizar títulos de seções

Os comandos de títulos de seções foram reimplementados no kernel do LaTeX com um novo mecanismo de modelos, resolvendo o problema de pacotes como `titlesec` não serem totalmente compatíveis com o código de tagging do LaTeX. Aqui está um exemplo rápido:

```latex
\EditInstance{heading}{section}{
  number-format=\fbox{\LARGE\bfseries\theheading},
  title-decls=\Large\bfseries\sffamily\color{blue},
  before-vspace=20pt,
}
```

Informações detalhadas estão disponíveis na [documentação](https://tug.ctan.org/macros/latex-dev/required/latex-lab/latex-lab-sec-template.pdf).

#### Um kernel reconstruído por dentro

No kernel deste ano, algumas limitações foram removidas:

* <strong>A rotina de saída agora é configurável:</strong> por quase 40 anos, o mecanismo de montagem de páginas do LaTeX foi praticamente fixo, obrigando os pacotes que precisavam alterá-lo a sobrescrever código interno. Agora ele expõe hooks e sockets para fazer alterações. Os pacotes se tornam mais estáveis e menos propensos a conflitar entre si.
* <strong>Um mecanismo moderno de marcas:</strong> o antigo sistema `\markboth` / `\leftmark` / `\rightmark`, que só suportava duas marcas interligadas, foi reconstruído sobre um sistema flexível que suporta qualquer número de marcas independentes, enquanto os comandos conhecidos continuam funcionando exatamente como antes.
* <strong>Ambientes de bloco e títulos de seções agora funcionam com modelos:</strong> listas, citações, ambientes do tipo teorema e agora os comandos de títulos compartilham um sistema subjacente consistente. Um benefício prático: o LaTeX está começando a emular nativamente pacotes populares como o `enumitem` e o `\newtheoremstyle` do `amsthm`, e a emulação do `titlesec` está em andamento. Agora há menos necessidade de instalar pacotes apenas para mudar o estilo de uma lista ou de uma caixa de teorema.
* <strong>Melhores referências cruzadas para ambientes do tipo teorema:</strong> um novo comando `\newcounteralias` faz com que um lema que compartilha um contador com teoremas apareça corretamente como _"lemma 1"_, e não _"theorem 1"_, quando referenciado com `cleveref`, `zref-clever` ou `hyperref`.

Se você mantém pacotes, e não apenas documentos, duas mudanças merecem atenção: o kernel agora exige formalmente o **`expl3` datado de 2023-11-27 ou mais recente**, e a _"matemática falsa"_ (usar o modo matemático apenas para posicionar caixas) foi removida de construções como `\textsuperscript`, `\parbox`/`minipage` e em torno de estruturas tabulares. Isso melhora o suporte a tagging e a texto da direita para a esquerda, mas você perceberá a diferença se comparar os resultados de `\showoutput` com versões mais antigas do TeX Live.

#### Novo alcance: mais idiomas

* <strong>A indexação para escritas brâmicas,</strong> incluindo bengali, guzerate, canarês, malaiala, cingalês, tâmil e télugo, chegou de forma experimental ao `upmendex`.
* Novas chaves de **metadados de idioma BCP 47** (`language`, `other-languages`) permitem declarar com precisão o idioma de um documento, incluindo variantes regionais, o que também alimenta os próprios metadados de idioma do PDF.

#### Outros pontos a observar

* Os pacotes `enumerate`, `theorem` e `verbatim` agora são considerados legados; para novos documentos, prefira `enumitem`, `amsthm` e `fancyvrb`, respectivamente.
* Se você usa um fluxo de trabalho de impressão ou uma plataforma que espera uma versão mais antiga de PDF, ainda pode definir a versão do PDF por conta própria (por exemplo, `\DocumentMetadata{pdfversion=1.7}`), e a documentação do TeX Live 2026 explica como compilar documentos usando os padrões anteriores.
* Você encontra as [notas de versão oficiais](https://tug.org/texlive/doc/texlive-en/texlive-en.html#news) do TeX Live 2026 no site do TeX Users Group (TUG), assim como as [notas de versão de todas as versões do TeX Live](https://www.tug.org/texlive/doc/texlive-en/texlive-en.html#x1-710009).

### Pacotes comuns afetados pelo TeX Live 2026

Nas seções a seguir, destacamos algumas mudanças que fariam com que projetos que compilavam com sucesso no TeX Live 2025 passem a apresentar erros de compilação no TeX Live 2026.

#### Pacotes relacionados a tabelas não suportados

Com as novas mudanças nas estruturas tabulares do kernel do LaTeX, os pacotes `tabu` e `tabls` não são mais suportados no TL2026 — agora eles causam erros de compilação. O pacote `arydshln` também pode ser incompatível com outros pacotes, por exemplo, com os ambientes `tabularx` e `tabular*`. Da mesma forma, pacotes ou modelos que redefinem `\@array` e `\tabular` também causarão erros de compilação em estruturas do tipo tabela.

#### Opções de idioma obsoletas do `babel`

As opções de idioma `frenchb` e `francais` agora estão obsoletas. Elas devem ser substituídas por `french`.

#### Bug do `varioref`

Devido a um [bug no pacote `varioref`](https://github.com/latex3/latex2e/issues/2112#issuecomment-4881772493), carregá-lo em classes de documento KOMA-Script causa um erro de capacidade do TeX excedida (TeX capacity exceeded), e nenhum PDF é gerado.

```text
\documentclass{scrartcl}
\usepackage{varioref}
\begin{document}
Hello World!
\end{document}
```

A solução alternativa é adicionar

```text
\def\extrasenglish{}
```

no preâmbulo.

#### Classes KOMA-script e `capt-of`

As classes de documento KOMA-script (`scrbook`, `scrartcl`, `scrreport`, `scrletter`) agora definem `\captionof`, portanto o pacote `capt-of` não deve mais ser carregado. (Por outro lado, o pacote `caption` continua seguro para carregar com essas classes de documento.)

#### `thmtools`: erros com `sibling`/`numberlike`/`sharenumber`

Ao declarar novos ambientes do tipo teorema com a opção `sibling` (ou `numberlike`, ou `sharenumber`) do `thmtools`, surgem [erros sobre contadores já definidos](https://github.com/muzimuzhi/thmtools/issues/75), por exemplo `Command \c@proposal already defined`.

```text
\documentclass{article}
\usepackage{thmtools}
\declaretheorem{theorem}
\declaretheorem{proposal}[sibling=theorem]

\begin{document}

\begin{theorem}This is a theorem.\end{theorem}
\begin{proposal}This is a proposal.\end{proposal}

\end{document}
```

A solução alternativa é adicionar as linhas a seguir no preâmbulo, depois de carregar o `thmtools`, mas antes do `\declaretheorem`:

```text
\makeatletter
\@ifundefined{newcounteralias}{}{%
  \renewcommand\thmt@autorefsetup{\@xa\def\csname\thmt@envname autorefname\@xa\endcsname\@xa{\thmt@thmname}}%
}
\makeatother
```

#### `polyglossia`, `xepersian` e `array`

Se você usa os pacotes `polyglossia` ou `xepersian` para compor a escrita árabe e carregou o pacote `array` ou outros pacotes relacionados a tabelas que carregam o `array`, receberá um erro informando que `\UseMathForPositioningText` não está definido quando um texto em árabe for colocado dentro de uma estrutura do tipo tabela.

```text
\documentclass[12pt,a4paper]{article}
\usepackage{polyglossia}
\usepackage{array}
\setdefaultlanguage{arabic}
\newfontfamily\arabicfont[Script=Arabic]{Noto Naskh Arabic}
\begin{document}
\begin{tabular}{c}
السلام عليكم
\end{tabular}
\end{document}
```

Isso pode ser resolvido adicionando `\DocumentMetadata{}` antes da declaração `\documentclass`; ou considere mudar para o pacote `babel` para compor a escrita árabe.

#### `babel-spanish` e `biblatex-apa`

Carregar o `babel-spanish` ao usar o estilo `apa` do `biblatex` causa um erro de compilação relacionado a hooks e `\@makecaption`:

```text
\usepackage[spanish]{babel}
\usepackage[style=apa]{biblatex}
```

Mas o erro pode ser evitado adicionando a opção `shorthands=off` ao `babel`.

#### `xgreek`, `hyperref` e `\appendix`

Quando os pacotes `xgreek` (somente para XeLaTeX e LuaLaTeX) e `hyperref` são carregados, um erro de compilação é gerado para títulos de seções que aparecem depois de `\appendix`:

```text
\documentclass{article}
\usepackage{xgreek}
\usepackage{fontspec}
\setmainfont{GFS Artemisia}
\usepackage{hyperref}
\begin{document}
\section{Εισαγωγή}
\appendix
\section{Δεδομένα}
\end{document}
```

A correção é adicionar a opção `hypertexnames=false` ao `hyperref`.

#### `flowfram` e `titlesec`

Por enquanto, os pacotes `flowfram` e `titlesec` são incompatíveis entre si. Mas os autores podem considerar estilizar os títulos de seções usando a nova interface `\EditInstance`, por exemplo:

```text
\DocumentMetadata{}
\documentclass{article}
\usepackage{flowfram}
\usepackage[dvipsnames]{xcolor}
\EditInstance{heading}{section}{
  number-format=\fbox{\LARGE\bfseries\theheading},
  title-decls=\Large\bfseries\sffamily\color{NavyBlue}
}
\begin{document}
\section{Introduction}
\end{document}
```

Consulte [este link](https://mirrors.ctan.org/macros/latex-dev/required/latex-lab/latex-lab-sec-template.pdf) para mais detalhes.

### TeX Live 2026 no Ayakaleaf Pro

Os administradores do Ayakaleaf Pro poderão instalar o TeX Live 2026 atualizando a configuração da maneira habitual: apontando `TEX_LIVE_DOCKER_IMAGE` (e `ALL_TEX_LIVE_DOCKER_IMAGES`) para a nova imagem do TeX Live 2026. Nenhuma outra atualização é necessária.
