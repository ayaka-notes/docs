Para economizar tempo e criar rapidamente o ambiente de desenvolvimento, oferecemos outra versão da configuração do ambiente de desenvolvimento: o GitHub Codespace.

## Tutorial de configuração {#configuration-tutorial}

<Steps>
<Step title="Criar Codespaces">
Clique no botão a seguir para criar um codespace na nuvem para o desenvolvimento do server-pro.

[![Open in GitHub Codespaces](https://github.com/codespaces/badge.svg)](https://codespaces.new/ayaka-notes/ayakaleaf-pro)

Recomenda-se escolher um **Machine Type** de pelo menos **4-core**. Para tipos de máquina maiores, você pode enviar uma solicitação à equipe de suporte oficial do GitHub abrindo um ticket [aqui](https://support.github.com/contact?tags=rr-codespaces%2Ccat_codespaces).

<Frame>
  <img src="/images/dev/image.png" alt="" />
</Frame>
</Step>

<Step title="Executar o script de configuração">
Você precisará aguardar pacientemente até que o codespace seja criado. Depois de ter acesso ao seu Terminal, execute o seguinte comando:

```text
cd develop/
bin/setup
bin/i18n
```

`bin/setup` baixa as imagens e inicia os serviços; em seguida, `bin/i18n` aplica as traduções dos módulos do Ayakaleaf Pro, que os arquivos de locales commitados não contêm, veja [Atualizar as traduções i18n](/pt/dev/environment/update-i18n-translations).

<Frame>
  <img src="/images/dev/image-1.png" alt="" />
</Frame>

<Warning>

Este script (`bin/setup`) permite configurar o ambiente de desenvolvimento no commit mais recente da branch `server-pro` no menor tempo possível. Ele pode não ser aplicável a versões mais antigas/outras branches.

Construímos a imagem docker de desenvolvimento todos os dias com o [GitHub Action](https://github.com/ayaka-notes/ayakaleaf-pro/actions).

</Warning>
</Step>

<Step title="Acessar o Launchpad">
Mude para a aba de portas e você verá uma lista das portas web disponíveis. Clique na de `80` (o `OVERLEAF_PORT` em `develop/dev.rc`). Agora você deve ver a página launchpad. Mailpit, Grafana, Mongo Express e RedisInsight ficam em caminhos da mesma porta (`/mailpit/`, `/grafana/`, `/mongo-express/` e `/redis-insight/`), e o menu **Dev tools** do site aponta para eles depois que você faz login. O console do RustFS está na 9001 e o Hoppscotch na 9170, veja [Portas](/pt/dev/environment/setup-develop-environment-local#ports).

<Step title="Aproveite o desenvolvimento">
Agora é a sua vez! Comece a criar seu recurso incrível. `bin/setup` já inicia todos os serviços no modo de desenvolvimento (`node --watch`, igual ao `bin/dev`), então as mudanças no código aparecem sem outro comando.

Depois de alterar `develop/dev.rc`, execute `bin/setup` novamente: ele passa por `bin/docker-compose`, que adiciona os arquivos dos recursos ativados.

<Warning>

Não inicie os serviços manualmente com `docker compose -f docker-compose.yml -f docker-compose.dev.yml -f docker-compose.image.yml up`. Isso ignora os arquivos de recursos do `dev.rc`, então `web`, `filestore` e `history-v1` são recriados sem as configurações do RustFS e voltam a usar volumes locais, onde faltam o histórico e os arquivos binários dos seus projetos.

</Warning>
</Step>
</Steps>
