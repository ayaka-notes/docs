---
title: Coleção GitHub Sync User Credentials
icon: key
---

`githubSyncUserCredentials` guarda um documento por usuário que vinculou uma conta do GitHub para o GitHub Sync. Ela armazena o token de acesso OAuth do usuário, criptografado. A coleção pertence ao módulo web `github-sync` (`services/web/modules/github-sync`). O schema está em `services/web/modules/github-sync/app/models/githubSyncUserCredentials.mjs`, e todo acesso passa por `services/web/modules/github-sync/app/src/TokenManager.mjs`.

#### Campos {#fields}

| Campo | Tipo | Significado | Origem |
| ----- | ---- | ------- | ------ |
| `_id` | ObjectId | Definido pelo Mongoose quando o upsert insere. | |
| `userId` | ObjectId | O usuário do Overleaf. Obrigatório. O schema diz `unique: true`, mas nenhum índice é criado (veja Índices); o upsert por `userId` mantém um documento por usuário. | `githubSyncUserCredentials.mjs:8`, `TokenManager.mjs:44-48` |
| `github` | String | O token de acesso OAuth do GitHub, criptografado com `@overleaf/access-token-encryptor`. A senha vem de `GITHUB_TOKEN_CIPHER_PASSWORD`; o rótulo da cifra é `GITHUB_TOKEN_CIPHER_LABEL`, padrão `2026.3-v3`. Obrigatório. | `githubSyncUserCredentials.mjs:9`, `TokenManager.mjs:12-25` |
| `__v` | Number | A chave de versão do Mongoose. O schema não a desativa. | Padrão do Mongoose |

Só o token de acesso é armazenado: o callback OAuth guarda `access_token` da resposta do GitHub (`services/web/modules/github-sync/app/src/GitHubApiClient.mjs:180-191`). Não há refresh token nem expiração.

#### Quem escreve {#who-writes-it}

| Código | O que faz |
| ---- | ------------ |
| `TokenManager.mjs:42-58` (`saveUserToken`) | Faz upsert do token criptografado do usuário. Quando o usuário vincula de novo, o token substituído é revogado no GitHub em segundo plano. Chamado pelo callback OAuth (`services/web/modules/github-sync/app/src/GitHubSyncController.mjs:146`). |
| `TokenManager.mjs:61-76` (`removeUserToken`) | Revoga o token no GitHub (na medida do possível) e depois exclui o documento. Chamado ao desvincular (`GitHubSyncController.mjs:167`) e quando um usuário excluído expira (`services/web/modules/github-sync/index.mjs:66-68`). |

#### Quem lê {#who-reads-it}

| Código | O que faz |
| ---- | ------------ |
| `TokenManager.mjs:36-40` (`getUserToken`) | Descriptografa o token em cada chamada à API do GitHub: `services/web/modules/github-sync/app/src/GitHubSyncHandler.mjs` (por exemplo `:27`) e `services/web/modules/github-sync/app/src/GitMerge.mjs:43`. Sem documento, ou com um token que não pode ser descriptografado, lança `InvalidTokenError`, e o usuário conta como não vinculado (`GitHubSyncHandler.mjs:25-37`). |
| `services/web/modules/admin-tools/app/src/AdminUserListManager.mjs:393` | Verifica se o usuário tem um documento, para as integrações mostradas no painel de administração. |

#### Índices {#indexes}

| Nome | Chaves | Opções | Migração |
| ---- | ---- | ------- | --------- |
| `_id_` | `_id: 1` | | default |

O `autoIndex` do Mongoose está desativado (`services/web/app/src/infrastructure/Mongoose.mjs:7`), então o `unique: true` do schema em `userId` não cria nada. `tools/migrations/20190912145011_create_githubSyncUserCredentials_indexes.mjs` (`user_id` do upstream) tem apenas a tag `saas` e não roda no CE.

#### Notas {#notes}

* Alterar `GITHUB_TOKEN_CIPHER_PASSWORD` torna os tokens armazenados ilegíveis. Esses usuários passam a contar como não vinculados até vincularem de novo.
* Um usuário excluído mantém o documento até expirar.
