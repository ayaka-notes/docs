Nesta seção, discutiremos o modelo de dados do Overleaf. O Overleaf usa o MongoDB para persistência de dados, e o único banco de dados se chama `sharelatex`, que também é o nome do predecessor do Overleaf.

O ambiente de desenvolvimento já executa o Mongo Express ao lado do Mongo (veja [setup-develop-tools.md](/pt/dev/environment/setup-develop-tools  "mention")). Abra [http://localhost:8081/](http://localhost:8081/) e faça login com `admin:pass`.

Você também pode abrir um shell no contêiner do Mongo a partir do diretório `develop`:

```bash
bin/docker-compose exec mongo mongosh sharelatex
```

#### Como as páginas são escritas {#how-the-pages-are-written}

* Cada página lista os campos que o código escreve, com tipo, significado e a linha de código que os comprova: uma linha de um esquema Mongoose ou o ponto que escreve o campo. Campos que só uma migração, um script ou um dos módulos web escrevem indicam isso.
* Muitas coleções não têm esquema Mongoose: os serviços as escrevem com o driver do MongoDB.
* Os índices só são criados pelas migrações em `tools/migrations/`. O CE executa as marcadas com `server-ce` a cada inicialização (`server-ce/init_scripts/900_run_web_migrations.sh`); o `autoIndex` do Mongoose está desativado (`services/web/app/src/infrastructure/Mongoose.mjs:7`). As tabelas de índices listam apenas o que uma instância do CE acaba tendo.
* O texto dos docs fica no Mongo, mas o restante do conteúdo não. O conteúdo dos arquivos é armazenado como blobs e o histórico como chunks nos buckets do history-v1 (pastas locais, ou S3 / RustFS); docs abertos ficam no Redis até o document-updater fazer o flush.

Um banco de dados do CE tem mais coleções do que estas. Muitas são criadas vazias por suas migrações de índices e só são usadas no overleaf.com. Por exemplo, nada no CE ou nos nossos módulos escreve `splittests`, `samlLogs`, `notificationsPreferences`, `onboardingDataCollection` ou `userfeatureusages` no uso normal, por isso elas não têm página.
