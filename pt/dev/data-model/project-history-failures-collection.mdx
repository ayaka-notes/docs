---
title: Coleção Project History Failures
icon: triangle-exclamation
---

`projectHistoryFailures` guarda um documento por projeto cujas atualizações de histórico o project-history não conseguiu processar, ou para o qual iniciou uma ressincronização. O documento é excluído de novo assim que o processamento funciona. O project-history a escreve em `services/project-history/app/js/ErrorRecorder.js`; seu tipo está em `services/project-history/app/js/mongo-types.ts:3-24`. O web também tem um schema Mongoose para ela (`services/web/app/src/models/ProjectHistoryFailure.mjs:5-19`), mas nenhum código do web usa esse modelo.

#### Quem a escreve {#who-writes-it}

| Código | O que faz |
| ---- | ------------ |
| `services/project-history/app/js/ErrorRecorder.js:34-66` | `record`: upsert do erro, `attempts` +1, entrada adicionada a `history`. Chamado quando o processamento das atualizações de um projeto falha (`UpdatesProcessor.js:91`, `169`, `242`, `293`, `345`) e quando uma ressincronização não consegue começar (`SyncManager.js:75`, `96`). |
| `ErrorRecorder.js:86-102` | `recordSyncStart`: upsert, `resyncStartedAt`, `resyncAttempts` +1, entrada adicionada a `history`, cada vez que uma ressincronização começa (`SyncManager.js:104`). |
| `ErrorRecorder.js:68-70` | `clearError`: exclui o documento após um flush bem-sucedido (`UpdatesProcessor.js:101`, `194`, `259`, `355`), no project-history `DELETE /project/:project_id` (`services/project-history/app/js/HttpController.js:1386`) e para um id de projeto inválido durante uma nova tentativa (`services/project-history/app/js/RetryManager.js:161`). |
| `ErrorRecorder.js:72-82` | `setForceDebug`: upsert de `forceDebug` (`HttpController.js:1016-1035`, rota em `services/project-history/app/js/Router.js:82`). |
| `ErrorRecorder.js:109-119` | `cloneFailure`: copia o documento para outro projeto, para o project-history `POST /project/:project_id/clone` (`HttpController.js:135`), que nada no web chama. |

#### Notas {#notes}

* Um documento permanece até que um flush do projeto tenha sucesso ou o projeto seja excluído (`clearError` acima), então cada documento marca um projeto cujo último flush ou ressincronização ainda não teve sucesso.
* Strings de erro que começam com `OError:` são retornadas como `Error:` (`ErrorRecorder.js:18-26`); o valor armazenado não muda.
