title: Coleção Gitea Sync Project States

`giteaSyncProjectStates` guarda um documento por projeto vinculado a um repositório do Gitea: qual repositório e onde a última sincronização parou. A coleção pertence ao módulo web `gitea-sync` (`services/web/modules/gitea-sync`). O schema está em `services/web/modules/gitea-sync/app/models/giteaSyncProjectStates.mjs`, e todo acesso passa por `services/web/modules/gitea-sync/app/src/SyncStateManager.mjs`. Os campos são os mesmos de [GitHub Sync Project States](/pt/dev/data-model/github-sync-project-states-collection).

#### Campos {#fields}

| Campo | Tipo | Significado | Origem |
| ----- | ---- | ------- | ------ |
| `_id` | ObjectId | Definido pelo Mongoose na criação. | |
| `projectId` | ObjectId | O projeto vinculado. Obrigatório. O schema diz `unique: true`, mas nenhum índice é criado (veja Índices). | `giteaSyncProjectStates.mjs:8` |
| `repoFullName` | String | O repositório como `owner/name` (o `full_name` do Gitea). Obrigatório. | `giteaSyncProjectStates.mjs:9`, `GiteaApiClient.mjs:315` |
| `defaultBranchName` | String | O branch com o qual o projeto sincroniza. Definido quando o projeto é vinculado e não muda depois: na importação, o branch enviado pelo formulário de importação; na exportação, o branch padrão do novo repositório, ou `main` quando a API não informa nenhum. Padrão `null`. | `giteaSyncProjectStates.mjs:10`, `GiteaSyncHandler.mjs:175-181,233-239`, `GiteaApiClient.mjs:314-317` |
| `mergeStatus` | String | `clean`, `conflict` ou `diverged`. Padrão `clean`. | `giteaSyncProjectStates.mjs:11` |

#### Quem escreve {#who-writes-it}

| Código | O que faz |
| ---- | ------------ |
| `SyncStateManager.mjs:9-14` (`createProjectState`) | Cria o documento: depois de importar um repositório como novo projeto (`services/web/modules/gitea-sync/app/src/GiteaSyncHandler.mjs:175-181`), ou depois de exportar um projeto para um novo repositório (`GiteaSyncHandler.mjs:233-239`, apenas o proprietário, recusado quando já vinculado). |
| `SyncStateManager.mjs:16-21` (`updateProjectState`) | `$set` dos campos alterados. `getMergeOverview` define `mergeStatus: 'diverged'` quando `lastSyncCommit` não é mais ancestral do branch sincronizado (`services/web/modules/gitea-sync/app/src/GiteaApiClient.mjs:431`), ou o commit sumiu e o usuário pode fazer push (`GiteaSyncHandler.mjs:123,126-137`). Uma sincronização (`services/web/modules/gitea-sync/app/src/GitMerge.mjs`) avança `lastSyncCommit`/`lastSyncVersion` em caso de sucesso (por exemplo `:152,189,231`), registra um conflito com `unmergedBranchName`, `unmergedBranchHead` e `conflictVersion` (`:214-220`) e os limpa quando ele é resolvido (`:257-264`). |
| `SyncStateManager.mjs:23-25` (`removeProjectState`) | Exclui o documento quando o proprietário desvincula o projeto (`GiteaSyncHandler.mjs:83-97`) e quando um projeto excluído expira (`services/web/modules/gitea-sync/index.mjs:46-48`). |

#### Quem lê {#who-reads-it}

| Código | O que faz |
| ---- | ------------ |
| `GiteaSyncHandler.mjs:39-60` (`getProjectState`) | Fornece ao editor `mergeStatus`, `repoFullName` e `unmergedBranchName`. Sem documento, responde `need-export`, um valor que nunca é armazenado. |
| `GiteaSyncHandler.mjs:110-143` (`getMergeOverview`) | Compara `lastSyncCommit` e `lastSyncVersion` com o Gitea e o histórico do projeto para listar os novos commits. |
| `GiteaSyncHandler.mjs:200` (`exportProject`) | Recusa exportar um projeto que já está vinculado. |
| `GitMerge.mjs:36` (`doGitMergeWithoutLock`) | Carrega o estado no início de uma sincronização. |

#### Índices {#indexes}

| Nome | Chaves | Opções | Migração |
| ---- | ---- | ------- | --------- |
| `_id_` | `_id: 1` | | default |

O `autoIndex` do Mongoose está desativado (`services/web/app/src/infrastructure/Mongoose.mjs:7`), então o `unique: true` do schema em `projectId` não cria nada. Nenhuma migração cria índices para esta coleção.

#### Notas {#notes}

* A API do Gitea não consegue criar commits fora de um branch como a do GitHub. Uma sincronização faz commit direto no branch sincronizado quando pode avançar, ou em um branch temporário que depois é mesclado por um pull request (`GitMerge.mjs:16-21`).
* Uma sincronização roda sob o lock `gitSync` do projeto, compartilhado com o GitHub Sync e o GitLab Sync (`GitMerge.mjs:25-32`).
* Um projeto excluído mantém seu documento até expirar.
* O token do Gitea do usuário fica em [Gitea Sync User Credentials](/pt/dev/data-model/gitea-sync-user-credentials-collection).
