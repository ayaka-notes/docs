---
title: Coleção OAuth Access Tokens
icon: ticket
---

`oauthAccessTokens` contém os tokens bearer que o web aceita. No Ayakaleaf Pro são os tokens de acesso pessoal (tokens de autenticação Git) que um utilizador cria na página de definições da conta e usa para o git-bridge e o endpoint MCP. Um documento é um token. O esquema é `services/web/app/src/models/OauthAccessToken.mjs`; o módulo web `oauth2-server` escreve a coleção, sobretudo com o driver nativo.

#### Quem escreve {#who-writes-it}

| Código | O que faz |
| ---- | ------------ |
| `OAuthPersonalAccessTokenManager.mjs:53-88` (`createToken`) | Insere um token de acesso pessoal. A rota `POST /oauth/personal-access-tokens` (`services/web/modules/oauth2-server/app/src/OAuthPersonalAccessTokenRouter.mjs:22-27`) exige a funcionalidade `gitBridge` do utilizador e permite 10 tokens por utilizador (`OAuthPersonalAccessTokenController.mjs:7,34-38`). |
| `OAuthPersonalAccessTokenManager.mjs:90-105` (`removeToken`) | Apaga um token do utilizador. Rota `DELETE /oauth/personal-access-tokens/:token_id` (`OAuthPersonalAccessTokenRouter.mjs:29-32`). |
| `OAuthPersonalAccessTokenManager.mjs:136-140`, `OAuth2Model.mjs:58-61` | Definem `lastUsedAt` após uma verificação bem-sucedida. |

#### Quem lê {#who-reads-it}

| Código | O que faz |
| ---- | ------------ |
| `OAuthPersonalAccessTokenManager.mjs:107-144` (`verifyToken`) | Verifica um token pelo seu hash para `GET /oauth/token/info` (`OAuthPersonalAccessTokenRouter.mjs:11-15`), que o git-bridge chama em git clone e push (`services/git-bridge/src/main/java/uk/ac/ic/wlgitbridge/server/Oauth2Filter.java:285`). Rejeita um token expirado e o token de um utilizador suspenso ou eliminado. |
| `OAuth2Model.mjs:31-82` (`getAccessToken`) | Verifica um token bearer para `AuthenticationController.requireOauth('git_bridge')` (`services/web/app/src/Features/Authentication/AuthenticationController.mjs:409-450`): as rotas de API do git-bridge (`services/web/modules/git-bridge/app/src/GitBridgeRouter.mjs:33-59`) e o endpoint MCP (`services/web/modules/mcp-server/app/src/McpRouter.mjs:16-22`). #### Notas {#notes}

* Eliminar um utilizador não apaga os seus tokens. `UserDeleter` dispara o hook `cleanupPersonalAccessTokens` (`services/web/app/src/Features/User/UserDeleter.mjs:230-234`), mas nenhum módulo o escuta. Ambas as verificações de token rejeitam os tokens porque o utilizador já não existe, e o índice TTL remove-os um dia após `accessTokenExpiresAt`.
* Suspender um utilizador só termina as sessões. Os tokens ficam, e ambas as verificações de token rejeitam-nos enquanto `users.suspended` for `true` (`OAuth2Model.mjs:51-54`, `OAuthPersonalAccessTokenManager.mjs:129-134`).
