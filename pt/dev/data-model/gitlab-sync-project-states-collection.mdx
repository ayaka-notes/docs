---
title: Coleção GitLab Sync Project States
icon: code-merge
---

`gitlabSyncProjectStates` guarda um documento por projeto vinculado a um projeto do GitLab: qual repositório e onde a última sincronização parou. A coleção pertence ao módulo web `gitlab-sync` (`services/web/modules/gitlab-sync`). O schema está em `services/web/modules/gitlab-sync/app/models/gitlabSyncProjectStates.mjs`, e todo acesso passa por `services/web/modules/gitlab-sync/app/src/SyncStateManager.mjs`. Os campos são os mesmos de [GitHub Sync Project States](/pt/dev/data-model/github-sync-project-states-collection).

#### Campos {#fields}

| Campo | Tipo | Significado | Origem |
| ----- | ---- | ------- | ------ |
| `_id` | ObjectId | Definido pelo Mongoose na criação. | |
| `projectId` | ObjectId | O projeto vinculado. Obrigatório. O schema diz `unique: true`, mas nenhum índice é criado (veja Índices). | `gitlabSyncProjectStates.mjs:8` |
| `repoFullName` | String | O caminho do projeto do GitLab com seu namespace (o `path_with_namespace` do GitLab), por exemplo `group/subgroup/name`. Obrigatório. | `gitlabSyncProjectStates.mjs:9`, `GitLabApiClient.mjs:347` |
| `defaultBranchName` | String | O branch com o qual o projeto sincroniza. Definido quando o projeto é vinculado e não muda depois: na importação, o branch enviado pelo formulário de importação; na exportação, o branch padrão do novo repositório, ou `main` quando a API não informa nenhum. Padrão `null`. | `gitlabSyncProjectStates.mjs:10`, `GitLabSyncHandler.mjs:175-181,234-240`, `GitLabApiClient.mjs:346-349` |
| `mergeStatus` | String | `clean`, `conflict` ou `diverged`. Padrão `clean`. | `gitlabSyncProjectStates.mjs:11` |
| `lastSyncCommit` | String | O SHA do commit no branch sincronizado na última sincronização. Padrão `null`. | `gitlabSyncProjectStates.mjs:12` |
| `lastSyncVersion` | Number | A versão do histórico do projeto na última sincronização, obtida de `GET /project/:id/version` do project-history, lida após um flush do histórico. Padrão `null`. | `gitlabSyncProjectStates.mjs:13`, `services/web/modules/gitlab-sync/app/src/HistoryManager.mjs:8-17` |
| `unmergedBranchName` | String | Durante um conflito: o branch temporário com as alterações do Overleaf, chamado `overleaf-YYYY-MM-DD-HHMMSS`. `null` quando não há conflito. | `gitlabSyncProjectStates.mjs:14`, `GitMerge.mjs:817-821` |
| `unmergedBranchHead` | String | Durante um conflito: o commit head desse branch. Padrão `null`. | `gitlabSyncProjectStates.mjs:15` |
| `conflictVersion` | Number | Durante um conflito: a versão do histórico do projeto quando o conflito foi registrado. Padrão `null`. | `gitlabSyncProjectStates.mjs:16` |
| `__v` | Number | A chave de versão do Mongoose. O schema não a desativa. | Padrão do Mongoose |

#### Quem escreve {#who-writes-it}

| Código | O que faz |
| ---- | ------------ |
| `SyncStateManager.mjs:9-14` (`createProjectState`) | Cria o documento: depois de importar um repositório como novo projeto (`services/web/modules/gitlab-sync/app/src/GitLabSyncHandler.mjs:175-181`), ou depois de exportar um projeto para um novo repositório (`GitLabSyncHandler.mjs:234-240`, apenas o proprietário, recusado quando já vinculado). |
| `SyncStateManager.mjs:16-21` (`updateProjectState`) | `$set` dos campos alterados. `getMergeOverview` define `mergeStatus: 'diverged'` quando o branch sincronizado não contém mais `lastSyncCommit` (verificação de merge base, `services/web/modules/gitlab-sync/app/src/GitLabApiClient.mjs:460`), ou o commit sumiu e o usuário pode fazer push (`GitLabSyncHandler.mjs:123,126-137`). Uma sincronização (`services/web/modules/gitlab-sync/app/src/GitMerge.mjs`) avança `lastSyncCommit`/`lastSyncVersion` em caso de sucesso (por exemplo `:152,189,231`), registra um conflito com `unmergedBranchName`, `unmergedBranchHead` e `conflictVersion` (`:214-220`) e os limpa quando ele é resolvido (`:257-264`). |
| `SyncStateManager.mjs:23-25` (`removeProjectState`) | Exclui o documento quando o proprietário desvincula o projeto (`GitLabSyncHandler.mjs:83-97`) e quando um projeto excluído expira (`services/web/modules/gitlab-sync/index.mjs:46-48`). |

#### Quem lê {#who-reads-it}

| Código | O que faz |
| ---- | ------------ |
| `GitLabSyncHandler.mjs:39-60` (`getProjectState`) | Fornece ao editor `mergeStatus`, `repoFullName` e `unmergedBranchName`. Sem documento, responde `need-export`, um valor que nunca é armazenado. |
| `GitLabSyncHandler.mjs:110-143` (`getMergeOverview`) | Compara `lastSyncCommit` e `lastSyncVersion` com o GitLab e o histórico do projeto para listar os novos commits. |
| `GitLabSyncHandler.mjs:200` (`exportProject`) | Recusa exportar um projeto que já está vinculado. |
| `GitMerge.mjs:36` (`doGitMergeWithoutLock`) | Carrega o estado no início de uma sincronização. |

#### Índices {#indexes}

| Nome | Chaves | Opções | Migração |
| ---- | ---- | ------- | --------- |
| `_id_` | `_id: 1` | | default |

O `autoIndex` do Mongoose está desativado (`services/web/app/src/infrastructure/Mongoose.mjs:7`), então o `unique: true` do schema em `projectId` não cria nada. Nenhuma migração cria índices para esta coleção.

#### Notas {#notes}

* A API do GitLab não consegue mover um branch para qualquer commit como a do GitHub. Uma sincronização faz commit direto no branch sincronizado quando pode avançar, ou em um branch temporário que depois é mesclado por um merge request (`GitMerge.mjs:16-21`).
* Uma sincronização roda sob o lock `gitSync` do projeto, compartilhado com o GitHub Sync e o Gitea Sync (`GitMerge.mjs:25-32`).
* Um projeto excluído mantém seu documento até expirar.
* O token do GitLab do usuário fica em [GitLab Sync User Credentials](/pt/dev/data-model/gitlab-sync-user-credentials-collection).
