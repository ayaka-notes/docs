---
title: Coleção Deleted Projects
icon: trash-can
---

`deletedProjects` mantém um projeto depois que ele é excluído: um documento por projeto excluído, com uma cópia do documento completo do projeto e quem o excluiu. O web a escreve em `services/web/app/src/Features/Project/ProjectDeleter.mjs`; o esquema é `services/web/app/src/models/DeletedProject.mjs`. Quando o prazo de exclusão definitiva termina, a expiração destrói os dados do projeto e esvazia `project`, mas o registro com `deleterData` permanece.

Um projeto na lixeira não fica aqui: mover para a lixeira apenas adiciona o usuário a `trashed` do projeto, veja [Coleção Projects](/pt/dev/data-model/projects-collection).

#### Quem escreve {#who-writes-it}

| Código | O que faz |
| ---- | ------------ |
| `ProjectDeleter.mjs:189-293` (`deleteProject`) | Faz o flush do projeto, arquiva seus docs para fora do Mongo, remove-o das tags, faz o upsert do registro e exclui o documento de `projects`. |
| `ProjectDeleter.mjs:295-342` (`undeleteProject`) | Insere o projeto novamente com o nome `<name> (Restored)` (tornado único para o proprietário) e não mais arquivado, depois exclui o registro. Falha com `project_too_old_to_restore` quando `project` é `null`. Chamado pelo painel de administração: restaurar um projeto (`AdminProjectManager.mjs:497-515`) ou restaurar um usuário excluído com os projetos excluídos junto com a conta (`services/web/modules/admin-tools/app/src/AdminUserManager.mjs:678-689`). |
| `ProjectDeleter.mjs:344-416` (`expireDeletedProject`) | Destrói os docs, o histórico, o chat e o log de auditoria do projeto e dispara o hook `projectExpired`, depois define `project` e `deleterData.deleterIpAddress` como `null`. Se o projeto existir novamente, apenas exclui o registro obsoleto. |
| `ProjectDeleter.mjs:97-146` (`expireDeletedProjectsAfterDuration`) | Faz expirar um lote de registros mais antigos que o prazo. Rota `POST /internal/expire-deleted-projects-after-duration` (`services/web/app/src/router.mjs:842-846`), que o cron da Community Edition chama a cada hora no minuto 20 quando `ENABLE_CRON_RESOURCE_DELETION` é `true` (`server-ce/cron/delete-projects.sh:10-23`, `server-ce/config/crontab-deletion:3`). Um único projeto: `POST /internal/project/:projectId/expire-deleted-project` (`router.mjs:852-856`), ou Purge no painel de administração (`AdminProjectManager.mjs:517-529`). |

#### Notas {#notes}

* Os módulos que escutam `projectExpired` excluem seus próprios dados do projeto: `git-bridge` (`services/web/modules/git-bridge/index.mjs:37`), `github-sync` (`services/web/modules/github-sync/index.mjs:56`), `gitlab-sync` (`services/web/modules/gitlab-sync/index.mjs:46`), `gitea-sync` (`services/web/modules/gitea-sync/index.mjs:46`) e `dropbox` (`services/web/modules/dropbox/index.mjs:54`).
* Um registro expirado nunca é excluído: `deleterData` permanece para sempre, apenas `project` e o endereço IP são esvaziados.
* O Mongoose também dá a `deleterData` seu próprio `_id`, que nada lê.
