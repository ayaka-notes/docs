---
title: Coleção System Messages
icon: bullhorn
---

`systemmessages` guarda os banners de todo o site que um administrador publica para todos os usuários conectados. Um documento é uma mensagem. `web` é o proprietário; o schema é `services/web/app/src/models/SystemMessage.mjs` e o código é `services/web/app/src/Features/SystemMessages/SystemMessageManager.mjs`.

#### Campos {#fields}

| Campo | Tipo | Significado | Fonte |
| --- | --- | --- | --- |
| `_id` | ObjectId | Id da mensagem. O navegador lembra por este id quais mensagens o usuário fechou (`services/web/frontend/js/shared/components/system-message.tsx:10`). | `SystemMessage.mjs:5` |
| `content` | String | Texto da mensagem, padrão `''`. | `SystemMessage.mjs:7` |
| `__v` | Number | Chave de versão do Mongoose, adicionada por `message.save()`. | `SystemMessageManager.mjs:29-30` |

#### Quem escreve {#who-writes-it}

| Código | O que faz |
| --- | --- |
| `SystemMessageManager.mjs:28-33` (`createMessage`) | `POST /admin/messages` (`services/web/app/src/router.mjs:1150-1152`, `services/web/app/src/Features/ServerAdmin/AdminController.mjs:151-159`): adiciona uma mensagem. |
| `SystemMessageManager.mjs:22-26` (`clearMessages`) | `POST /admin/messages/clear` (`router.mjs:1155-1157`, `AdminController.mjs:161-168`): exclui todas as mensagens. Não é possível excluir apenas uma. |

#### Quem lê {#who-reads-it}

| Código | O que faz |
| --- | --- |
| `SystemMessageManager.mjs:50-65` | Cada processo `web` mantém todas as mensagens em memória e as recarrega a cada 20 a 30 segundos, e logo após a própria criação ou limpeza. |
| `services/web/app/src/Features/SystemMessages/SystemMessageController.mjs:6-24` | `GET /system/messages` (`router.mjs:331`): retorna as mensagens em cache aos usuários conectados. Enquanto o site está fechado (`siteIsOpen` false), retorna em vez disso um aviso fixo, que não é armazenado no Mongo. |
| `AdminController.mjs:83-84` | A página `/admin` lista as mensagens diretamente do Mongo. |

#### Índices {#indexes}

Nenhuma migração cria um índice em `systemmessages`; existe apenas o índice padrão `_id`.

#### Observações {#notes}

* Com `notifyOnSystemMessageChanges` definido, uma criação ou limpeza também é publicada no canal Redis `refresh-system-messages`, para que os outros processos `web` recarreguem imediatamente (`SystemMessageManager.mjs:9`, `:35-48`, `:75-87`). Sem isso, eles aplicam a mudança no próximo recarregamento agendado.
