`githubSyncProjectStates` guarda um documento por projeto vinculado a um repositório do GitHub: qual repositório e onde a última sincronização parou. A coleção pertence ao módulo web `github-sync` (`services/web/modules/github-sync`). O schema está em `services/web/modules/github-sync/app/models/githubSyncProjectStates.mjs`, e todo acesso passa por `services/web/modules/github-sync/app/src/SyncStateManager.mjs`.

#### Quem escreve {#who-writes-it}

| Código | O que faz |
| ---- | ------------ |
| `SyncStateManager.mjs:9-14` (`createProjectState`) | Cria o documento: depois de importar um repositório como novo projeto (`services/web/modules/github-sync/app/src/GitHubSyncHandler.mjs:175-181`), ou depois de exportar um projeto para um novo repositório (`GitHubSyncHandler.mjs:235-241`, apenas o proprietário, recusado quando já vinculado). |
| `SyncStateManager.mjs:16-21` (`updateProjectState`) | `$set` dos campos alterados. `getMergeOverview` define `mergeStatus: 'diverged'` quando o branch sincronizado não parte mais de `lastSyncCommit`: o compare do GitHub responde `diverged` ou `behind` (`GitHubApiClient.mjs:382-400`), ou o commit sumiu e o usuário pode fazer push (`GitHubSyncHandler.mjs:123,126-137`). Uma sincronização (`services/web/modules/github-sync/app/src/GitMerge.mjs`) avança `lastSyncCommit`/`lastSyncVersion` em caso de sucesso (por exemplo `:143,173,224`), registra um conflito com `unmergedBranchName`, `unmergedBranchHead` e `conflictVersion` (`:207-213`) e os limpa quando ele é resolvido (`:250-257`). |
| `SyncStateManager.mjs:23-25` (`removeProjectState`) | Exclui o documento quando o proprietário desvincula o projeto (`GitHubSyncHandler.mjs:83-97`) e quando um projeto excluído expira (`services/web/modules/github-sync/index.mjs:56-58`). |

#### Quem lê {#who-reads-it}

| Código | O que faz |
| ---- | ------------ |
| `GitHubSyncHandler.mjs:39-60` (`getProjectState`) | Fornece ao editor `mergeStatus`, `repoFullName` e `unmergedBranchName`. Sem documento, responde `need-export`, um valor que nunca é armazenado. |
| `GitHubSyncHandler.mjs:110-143` (`getMergeOverview`) | Compara `lastSyncCommit` e `lastSyncVersion` com o GitHub e o histórico do projeto para listar os novos commits. |
| `GitHubSyncHandler.mjs:200` (`exportProject`) | Recusa exportar um projeto que já está vinculado. |
| `GitMerge.mjs:27` (`doGitMergeWithoutLock`) | Carrega o estado no início de uma sincronização. |

#### Índices {#indexes}

| Nome | Chaves | Opções | Migração |
| ---- | ---- | ------- | --------- |
| `_id_` | `_id: 1` | | default |

O `autoIndex` do Mongoose está desativado (`services/web/app/src/infrastructure/Mongoose.mjs:7`), então o `unique: true` do schema em `projectId` não cria nada. `tools/migrations/20190912145010_create_githubSyncProjectStates_indexes.mjs` (`project_id` e `owner_id` do upstream) tem apenas a tag `saas` e não roda no CE.

#### Notas {#notes}

* Uma sincronização roda sob o lock `gitSync` do projeto (`GitMerge.mjs:17-24`). O GitLab Sync e o Gitea Sync usam o mesmo lock, então só uma sincronização roda por projeto por vez.
* Um projeto excluído mantém seu documento até expirar.
* O token do GitHub do usuário fica em [GitHub Sync User Credentials](/pt/dev/data-model/github-sync-user-credentials-collection).
