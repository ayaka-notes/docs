---
title: Coleção Deleted Users
icon: user-xmark
---

`deletedUsers` mantém uma conta de usuário depois que ela é excluída: um documento por conta excluída, com uma cópia do documento completo do usuário e quem a excluiu. O web a escreve em `services/web/app/src/Features/User/UserDeleter.mjs`; o esquema é `services/web/app/src/models/DeletedUser.mjs`. Quando o prazo de exclusão definitiva termina, a expiração remove a cópia do usuário, mas o registro com `deleterData` permanece.

Excluir um usuário também exclui os projetos que ele possui; eles vão para [Coleção Deleted Projects](/pt/dev/data-model/deleted-projects-collection) com o motivo `account-deletion`.

#### Quem escreve {#who-writes-it}

| Código | O que faz |
| ---- | ------------ |
| `UserDeleter.mjs:37-80` (`deleteUser`) | Adiciona uma entrada de log de auditoria `delete-account`, limpa o usuário e dispara o hook `deleteUser`, faz o upsert do registro (`_createDeletedUser`, `UserDeleter.mjs:192-213`), exclui os projetos do usuário, envia o e-mail de alerta de segurança, a menos que seja ignorado, e exclui o documento de `users`. Chamadores: a página de configurações da conta (`services/web/app/src/Features/User/UserController.mjs:280-284`), o painel de administração (`services/web/modules/admin-tools/app/src/AdminUserManager.mjs:604-612`) e o script `delete-user` (`delete-user.mjs:40-45`). |
| `UserDeleter.mjs:93-115` (`expireDeletedUser`) | Dispara o hook `expireDeletedUser`, exclui os dados de onboarding do usuário e então remove `user` e `deleterData.deleterIpAddress`. |
| `UserDeleter.mjs:117-161` (`expireDeletedUsersAfterDuration`) | Faz expirar todo registro mais antigo que o prazo e exclui as `userAuditLogEntries` do usuário. Rota `POST /internal/expire-deleted-users-after-duration` (`services/web/app/src/router.mjs:847-851`), que o cron da Community Edition chama a cada hora no minuto 15 quando `ENABLE_CRON_RESOURCE_DELETION` é `true` (`server-ce/cron/delete-users.sh:10-23`, `server-ce/config/crontab-deletion:2`). Um único usuário: `POST /internal/users/:userId/expire` (`router.mjs:857-861`). |
| `AdminUserManager.mjs:630-649` (`purgeDeletedUser`, módulo `admin-tools`) | Purge no painel de administração: executa `expireDeletedUser` e exclui as entradas do log de auditoria do usuário. |
| `AdminUserManager.mjs:651-696` (`restoreDeletedUser`, módulo `admin-tools`) | Restaurar no painel de administração: cria novamente o documento de `users` a partir de `user` (recusado se o e-mail estiver em uso), exclui o registro e restaura os projetos excluídos com a conta. |

#### Notas {#notes}

* Os módulos que escutam `expireDeletedUser` excluem seus próprios dados do usuário: `dropbox` (`services/web/modules/dropbox/index.mjs:62`), `github-sync` (`services/web/modules/github-sync/index.mjs:66`), `gitlab-sync` (`services/web/modules/gitlab-sync/index.mjs:56`) e `gitea-sync` (`services/web/modules/gitea-sync/index.mjs:56`).
* Um registro expirado nunca é excluído: `deleterData` permanece para sempre, apenas `user` e o endereço IP são removidos.
* Os tokens de acesso pessoal do usuário não são excluídos com a conta, veja [Coleção OAuth Access Tokens](/pt/dev/data-model/oauth-access-tokens-collection).
* O Mongoose também dá a `deleterData` seu próprio `_id`, que nada lê.
