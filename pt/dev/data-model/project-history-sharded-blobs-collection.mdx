---
title: Coleção Project History Sharded Blobs
icon: cubes-stacked
---

`projectHistoryShardedBlobs` guarda os registros de blob que não couberam em [projectHistoryBlobs](/dev/data-model/project-history-blobs-collection): quando o bucket de um prefixo de hash já tem 8 registros lá, os próximos vêm para cá. Um projeto tem no máximo 16 documentos nela, um por primeiro dígito hexadecimal do hash. Não há schema Mongoose; o history-v1 a escreve em `services/history-v1/storage/lib/blob_store/mongo.js` (estrutura descrita em `mongo.js:1-16`).

#### Campos {#fields}

| Campo | Tipo | Significado | Origem |
| ----- | ---- | ------- | ------ |
| `_id` | Binary | 13 bytes: o id de histórico do projeto, um `0`, e o dígito do shard, lido como hexadecimal (`<history id>0<digit>`). O dígito do shard é o primeiro dígito hexadecimal do hash. | `mongo.js:439-453` |
| `blobs` | Object | Registros de blob agrupados em buckets. A chave de um bucket são os dígitos hexadecimais 2 a 4 do hash. | `mongo.js:439-443` |
| `blobs.<bcd>` | Array of Object | Os registros do bucket. O código não limita seu tamanho. | `mongo.js:399-407` |
| `blobs.<bcd>[].h` | Binary | O hash, 20 bytes, como em projectHistoryBlobs. | `mongo.js:472` |
| `blobs.<bcd>[].b` | Number | Tamanho do conteúdo em bytes. | `mongo.js:473` |
| `blobs.<bcd>[].s` | Number | Tamanho do conteúdo como texto; `null` quando o conteúdo não é texto editável. | `mongo.js:474` |

#### Quem a escreve {#who-writes-it}

| Código | O que faz |
| ---- | ------------ |
| `services/history-v1/storage/lib/blob_store/mongo.js:399-407` | `insertRecordSharded`: upsert com `$addToSet` no bucket. Chamado por `insertBlob` quando o bucket em projectHistoryBlobs está cheio (`mongo.js:387-389`). |
| `mongo.js:75-103` | `clone`: copia os shards do projeto para outro id de histórico, para o history-v1 `POST /projects/:project_id/clone`, que nada no web chama. |
| `mongo.js:413-422` | `deleteBlobs`: exclui todos os shards do projeto junto com seu documento em projectHistoryBlobs, no history-v1 `DELETE /projects/:project_id`. |

#### Quem a lê {#who-reads-it}

| Código | O que faz |
| ---- | ------------ |
| `mongo.js:144-157` | `findBlobSharded`: um blob, buscado só quando seu bucket em projectHistoryBlobs tem 8 registros e não o contém (`mongo.js:127-131`). |
| `mongo.js:217-260` | `findBlobsSharded`: os blobs que `findBlobs` não encontrou em projectHistoryBlobs (`mongo.js:202-206`). |
| `mongo.js:285-306` | `getProjectBlobs`: todos os shards de um projeto. |
| `mongo.js:337-361` | `getProjectBlobsBatch`: todos os shards de vários projetos, para a rota de estatísticas de blobs. |

#### Índices {#indexes}

Só o índice padrão `_id`. Nenhuma migração em `tools/migrations/` adiciona um.

#### Notas {#notes}

* Os shards de um projeto ficam lado a lado na ordem de `_id`, então o código os encontra com um intervalo de `_id` de `<history id>00` a `<history id>0f` (`mongo.js:75-80`, `287-295`).
* A coleção só aparece quando algum projeto tem mais de 8 blobs com o mesmo prefixo de hash de 3 dígitos, então uma instância pequena pode nem tê-la.
