title: Coleção Project History Sync State
icon: rotate
---

`projectHistorySyncState` contém um documento por projeto que foi ressincronizado: o estado da ressincronização atual ou da última, quando o project-history reconstrói o histórico de um projeto a partir do que o web e o docstore guardam. Pertence ao project-history e não tem esquema Mongoose; o código é a classe `SyncState` e suas funções auxiliares em `services/project-history/app/js/SyncManager.js`.

#### Quem escreve {#who-writes-it}

| Código | O que faz |
| ---- | ------------ |
| `services/project-history/app/js/SyncManager.js:195-249` | `setResyncState`: upsert do estado. Chamado quando uma ressincronização começa (`SyncManager.js:163`) e enquanto o project-history processa as atualizações de ressincronização (`services/project-history/app/js/UpdatesProcessor.js:637`, `784`). |
| `SyncManager.js:257-266` | `_recordStuckClearInSyncState`: conta uma ressincronização travada que é limpa. |
| `SyncManager.js:251-255` | `clearResyncState`: exclui o documento no início de uma ressincronização completa (`SyncManager.js:87`), em `DELETE /project/:project_id` do project-history (`services/project-history/app/js/HttpController.js:1363-1396`) e quando uma ressincronização só da estrutura precisa recomeçar (`SyncManager.js:705-716`). |
| `SyncManager.js:273-289` | `clearResyncStateIfAllAfter`: exclui um estado concluído cujo histórico é todo posterior a uma data. Nada em `app/js` o chama. |
| `SyncManager.js:171-181` | `cloneResyncState`: copia o estado para outro projeto, para `POST /project/:project_id/clone` do project-history (`HttpController.js:57`, `124`), que nada no web chama. |

Uma ressincronização é iniciada por `POST /project/:project_id/resync` do project-history (`HttpController.js:950-994`), pelos cron jobs de nova tentativa (`services/project-history/app/js/RetryManager.js:156-179`, `server-ce/config/crontab-history`) e pelo próprio project-history quando o processamento de atualizações precisa de uma (`UpdatesProcessor.js:75`, `224`).

#### Quem lê {#who-reads-it}

| Código | O que faz |
| ---- | ------------ |
| `SyncManager.js:187-193` | `getResyncState`: carrega o estado. Usado para decidir se uma ressincronização está em andamento antes de iniciar outra (`SyncManager.js:106-149`), para ignorar atualizações comuns enquanto ela executa (`SyncManager.js:291-300`) e, após um flush, para informar uma ressincronização em andamento (`UpdatesProcessor.js:463-466`). |
| `HttpController.js:533-545` | `GET /project/:project_id/resync-pending`: se uma ressincronização está em andamento ou travada. |
| `HttpController.js:563-585` | `GET /project/:project_id/debug-info`: o estado de sincronização com o registro de falha. |

#### Notas {#notes}

* Uma ressincronização está em andamento enquanto `resyncProjectStructure` é `true` ou `resyncDocContents` não está vazio (`SyncManager.js:565-567`). Ela é considerada travada após 4 horas, e travada permanentemente após 5 limpezas (`SyncManager.js:43-44`, `569-585`).
* Quando uma ressincronização termina, o project-history também define `overleaf.history.lastResyncedAt` no projeto (`SyncManager.js:239-248`).
