`rooms` guarda um documento por sala de chat de um projeto: o chat do projeto ou um tópico de comentários de revisão. Só o serviço chat a escreve, em `services/chat/app/js/Features/Threads/ThreadManager.js`. Não há schema Mongoose. As mensagens de uma sala ficam na coleção [messages](/pt/dev/data-model/messages-collection).

#### Campos {#fields}

| Campo | Tipo | Significado | Origem |
| ----- | ---- | ------- | ------ |
| `_id` | ObjectId | Id da sala. `messages.room_id` aponta para cá. | `ThreadManager.js:57-61` |
| `project_id` | ObjectId | Projeto ao qual a sala pertence. | `ThreadManager.js:43-54` |
| `thread_id` | ObjectId | Só em tópicos de comentários: o id do comentário, igual a `id` e `op.t` do comentário em `docs.ranges.comments` (veja [docs](/pt/dev/data-model/docs-collection)). Ausente na sala do chat do projeto. | `ThreadManager.js:38-55`, `services/docstore/app/js/RangeManager.js:54-57` |
| `resolved` | Object | Definido quando o tópico é resolvido e removido quando é reaberto. Um tópico sem este campo está aberto. | `ThreadManager.js:94-123` |
| `resolved.user_id` | String | Id do usuário que resolveu o tópico. Guardado como string, não como ObjectId: o corpo da requisição só é verificado como id válido, não convertido. | `ThreadManager.js:103`, `services/chat/app/js/Features/Messages/MessageHttpSchemas.js:70` |
| `resolved.ts` | Date | Quando o tópico foi resolvido. | `ThreadManager.js:104` |

#### Notas {#notes}

* Um projeto tem no máximo uma sala sem `thread_id`: o chat do projeto. O serviço chat a encontra com `thread_id: { $exists: false }` (`ThreadManager.js:38-45`).
* O estado resolvido de um comentário existe só aqui. O docstore remove `op.resolved` antes de salvar os intervalos (`services/docstore/app/js/RangeManager.js:59-61`).
* Depois de copiar um projeto, o mesmo `thread_id` existe em dois projetos. Sempre consulte `project_id` e `thread_id` juntos, como faz o serviço chat.
* As salas de um projeto excluído permanecem até o projeto excluído expirar.
