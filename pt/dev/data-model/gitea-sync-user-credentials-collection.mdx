---
title: Coleção Gitea Sync User Credentials
icon: lock
---

`giteaSyncUserCredentials` guarda um documento por usuário que vinculou uma conta do Gitea para o Gitea Sync. Ela armazena os tokens OAuth do usuário, criptografados. A coleção pertence ao módulo web `gitea-sync` (`services/web/modules/gitea-sync`). O schema está em `services/web/modules/gitea-sync/app/models/giteaSyncUserCredentials.mjs`, e todo acesso passa por `services/web/modules/gitea-sync/app/src/TokenManager.mjs`.

#### Campos {#fields}

| Campo | Tipo | Significado | Origem |
| ----- | ---- | ------- | ------ |
| `_id` | ObjectId | Definido pelo Mongoose quando o upsert insere. | |
| `userId` | ObjectId | O usuário do Overleaf. Obrigatório. O schema diz `unique: true`, mas nenhum índice é criado (veja Índices); o upsert por `userId` mantém um documento por usuário. | `giteaSyncUserCredentials.mjs:8`, `TokenManager.mjs:89-96` |
| `gitea` | String | O JSON `{ accessToken, refreshToken, expiresAt }`, criptografado com `@overleaf/access-token-encryptor`. `expiresAt` está em milissegundos desde a epoch, ou é `null`; `refreshToken` pode ser `null`. A senha vem de `GITEA_TOKEN_CIPHER_PASSWORD`; o rótulo da cifra é `GITEA_TOKEN_CIPHER_LABEL`, padrão `2026.10-v3`. Obrigatório. | `giteaSyncUserCredentials.mjs:9-10`, `TokenManager.mjs:17-30`, `services/web/modules/gitea-sync/app/src/GiteaApiClient.mjs:198-209` |
| `__v` | Number | A chave de versão do Mongoose. O schema não a desativa. | Padrão do Mongoose |

#### Quem escreve {#who-writes-it}

| Código | O que faz |
| ---- | ------------ |
| `TokenManager.mjs:89-96` (`saveUserToken`) | Faz upsert das credenciais criptografadas do usuário. Chamado pelo callback OAuth (`services/web/modules/gitea-sync/app/src/GiteaSyncController.mjs:146`). Diferente do GitLab Sync, vincular de novo não revoga o token substituído. |
| `TokenManager.mjs:53-79` (`refreshUserToken`) | Quando faltam menos de 5 minutos para o `expiresAt` do token de acesso (`:12`), obtém novos tokens com o refresh token e os salva (`:76`). Roda sob o lock `giteaSyncToken` por usuário (`:14,54`), porque o Gitea substitui o refresh token ao usá-lo. |
| `TokenManager.mjs:100-102` (`removeUserToken`) | Exclui o documento. O Gitea não tem API para revogar um token OAuth, então o usuário revoga a autorização no Gitea (`:98-99`). Chamado ao desvincular (`GiteaSyncController.mjs:173`) e quando um usuário excluído expira (`services/web/modules/gitea-sync/index.mjs:56-58`). |

#### Quem lê {#who-reads-it}

| Código | O que faz |
| ---- | ------------ |
| `TokenManager.mjs:40-44,82-86` (`getUserCredentials`, `getUserToken`) | Descriptografa as credenciais em cada chamada à API do Gitea, renovando antes quando o token está para expirar: `services/web/modules/gitea-sync/app/src/GiteaSyncHandler.mjs` (por exemplo `:27`) e `services/web/modules/gitea-sync/app/src/GitMerge.mjs:52`. Sem documento, ou com credenciais que não podem ser descriptografadas nem renovadas, lança `InvalidTokenError`, e o usuário conta como não vinculado (`GiteaSyncHandler.mjs:25-37`). |
| `services/web/modules/admin-tools/app/src/AdminUserListManager.mjs:395` | Verifica se o usuário tem um documento, para as integrações mostradas no painel de administração. |

#### Índices {#indexes}

| Nome | Chaves | Opções | Migração |
| ---- | ---- | ------- | --------- |
| `_id_` | `_id: 1` | | default |

O `autoIndex` do Mongoose está desativado (`services/web/app/src/infrastructure/Mongoose.mjs:7`), então o `unique: true` do schema em `userId` não cria nada. Nenhuma migração cria índices para esta coleção.

#### Notas {#notes}

* Alterar `GITEA_TOKEN_CIPHER_PASSWORD` torna as credenciais armazenadas ilegíveis. Esses usuários passam a contar como não vinculados até vincularem de novo.
* Um usuário excluído mantém o documento até expirar.
