---
title: Coleção GitLab Sync User Credentials
icon: user-lock
---

`gitlabSyncUserCredentials` guarda um documento por usuário que vinculou uma conta do GitLab para o GitLab Sync. Ela armazena os tokens OAuth do usuário, criptografados. A coleção pertence ao módulo web `gitlab-sync` (`services/web/modules/gitlab-sync`). O schema está em `services/web/modules/gitlab-sync/app/models/gitlabSyncUserCredentials.mjs`, e todo acesso passa por `services/web/modules/gitlab-sync/app/src/TokenManager.mjs`.

#### Campos {#fields}

| Campo | Tipo | Significado | Origem |
| ----- | ---- | ------- | ------ |
| `_id` | ObjectId | Definido pelo Mongoose quando o upsert insere. | |
| `userId` | ObjectId | O usuário do Overleaf. Obrigatório. O schema diz `unique: true`, mas nenhum índice é criado (veja Índices); o upsert por `userId` mantém um documento por usuário. | `gitlabSyncUserCredentials.mjs:8`, `TokenManager.mjs:88-95` |
| `gitlab` | String | O JSON `{ accessToken, refreshToken, expiresAt }`, criptografado com `@overleaf/access-token-encryptor`. `expiresAt` está em milissegundos desde a epoch, ou é `null`; `refreshToken` pode ser `null`. A senha vem de `GITLAB_TOKEN_CIPHER_PASSWORD`; o rótulo da cifra é `GITLAB_TOKEN_CIPHER_LABEL`, padrão `2026.10-v3`. Obrigatório. | `gitlabSyncUserCredentials.mjs:9-10`, `TokenManager.mjs:18-31`, `services/web/modules/gitlab-sync/app/src/GitLabApiClient.mjs:209-220` |
| `__v` | Number | A chave de versão do Mongoose. O schema não a desativa. | Padrão do Mongoose |

#### Quem escreve {#who-writes-it}

| Código | O que faz |
| ---- | ------------ |
| `TokenManager.mjs:88-95` (`saveUserToken`) | Faz upsert das credenciais criptografadas do usuário. |
| `TokenManager.mjs:99-108` (`linkUserToken`) | Salva novas credenciais vindas do callback OAuth (`services/web/modules/gitlab-sync/app/src/GitLabSyncController.mjs:146`). Quando o usuário vincula de novo, o token de acesso substituído é revogado no GitLab em segundo plano. |
| `TokenManager.mjs:53-78` (`refreshUserToken`) | Quando faltam menos de 5 minutos para o `expiresAt` do token de acesso (`:13,47-49`), obtém novos tokens com o refresh token e os salva (`:75`). Roda sob o lock `gitlabSyncToken` por usuário (`:15,54`), porque o GitLab gasta um refresh token ao usá-lo. |
| `TokenManager.mjs:111-126` (`removeUserToken`) | Revoga o token de acesso no GitLab (na medida do possível) e depois exclui o documento. Chamado ao desvincular (`GitLabSyncController.mjs:173`) e quando um usuário excluído expira (`services/web/modules/gitlab-sync/index.mjs:56-58`). |

#### Quem lê {#who-reads-it}

| Código | O que faz |
| ---- | ------------ |
| `TokenManager.mjs:41-45,81-85` (`getUserCredentials`, `getUserToken`) | Descriptografa as credenciais em cada chamada à API do GitLab, renovando antes quando o token está para expirar: `services/web/modules/gitlab-sync/app/src/GitLabSyncHandler.mjs` (por exemplo `:27`) e `services/web/modules/gitlab-sync/app/src/GitMerge.mjs:52`. Sem documento, ou com credenciais que não podem ser descriptografadas nem renovadas, lança `InvalidTokenError`, e o usuário conta como não vinculado (`GitLabSyncHandler.mjs:25-37`). |
| `services/web/modules/admin-tools/app/src/AdminUserListManager.mjs:394` | Verifica se o usuário tem um documento, para as integrações mostradas no painel de administração. |

#### Índices {#indexes}

| Nome | Chaves | Opções | Migração |
| ---- | ---- | ------- | --------- |
| `_id_` | `_id: 1` | | default |

O `autoIndex` do Mongoose está desativado (`services/web/app/src/infrastructure/Mongoose.mjs:7`), então o `unique: true` do schema em `userId` não cria nada. Nenhuma migração cria índices para esta coleção.

#### Notas {#notes}

* Alterar `GITLAB_TOKEN_CIPHER_PASSWORD` torna as credenciais armazenadas ilegíveis. Esses usuários passam a contar como não vinculados até vincularem de novo.
* Um usuário excluído mantém o documento até expirar.
