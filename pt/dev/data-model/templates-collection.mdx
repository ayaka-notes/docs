title: Coleção Templates
icon: book-open
---

`templates` contém um documento por modelo na galeria de modelos. Os arquivos de um modelo (o zip do projeto e o PDF) não ficam aqui: eles são guardados no filestore em `template/<_id>/v/<version>/`. A coleção pertence ao módulo web `template-gallery` (`services/web/modules/template-gallery`). O esquema é o modelo Mongoose `Template` em `services/web/modules/template-gallery/app/src/models/Template.mjs`; a lógica fica em `services/web/modules/template-gallery/app/src/TemplateGalleryManager.mjs` e no `TemplateGalleryHelper.mjs` ao lado.

#### Campos {#fields}

| Campo | Tipo | Significado | Origem |
| ----- | ---- | ------- | ------ |

| `name` | String | O título. Obrigatório, no máximo 150 caracteres. #### Quem escreve {#who-writes-it}

| Código | O que faz |
| ---- | ------------ |
| `TemplateGalleryManager.mjs:53-97` (`createTemplateFromProject`) | `POST /template/new/:Project_id`. Copia as configurações do projeto (`TemplateGalleryHelper.mjs:94-134`), envia o zip e o PDF para o filestore e salva. Se o nome já estiver em uso, responde com um conflito, a menos que o cliente tenha pedido para sobrescrever: nesse caso atualiza esse modelo e aumenta sua `version`, depois exclui os arquivos da versão anterior. |
| `TemplateGalleryManager.mjs:21-47` (`editTemplate`) | `POST /template/:template_id/edit`. Atribui os campos enviados ao documento, gera novamente `description` e `author` e define `lastUpdated`. O formulário de edição envia os campos alterados entre `name`, `license`, `category`, `language`, `authorMD` e `descriptionMD` (`services/web/modules/template-gallery/frontend/js/pages/template/util/api.ts:22-29`). |
| `TemplateGalleryHelper.mjs:186-222` (`deleteTemplateAssets`) | `DELETE /template/:template_id/delete` exclui o documento e os arquivos da versão indicada (`TemplateGalleryManager.mjs:49-51`). |

Apenas os admins do site e o usuário em `OVERLEAF_TEMPLATES_USER_ID` podem chamar essas três rotas (`services/web/modules/template-gallery/app/src/Router.mjs:55-62,70-84`, `PermissionsMiddleware.mjs:8-19`).

#### Quem lê {#who-reads-it}

| Código | O que faz |
| ---- | ------------ |
| `TemplateGalleryManager.mjs:158-183` (`getTemplate`) | Encontra um modelo por `_id` ou `name` para a página do modelo e para `GET /api/template` (`services/web/modules/template-gallery/app/src/TemplateGalleryController.mjs:210-232`). Se `project_id` aponta para um projeto que não existe mais, a resposta o omite; o documento não é alterado. |
| `TemplateGalleryManager.mjs:190-236` (`getCategoryTemplates`) | `GET /api/templates`: uma página de uma categoria, pesquisada em `name`, `authorMD` e `descriptionMD`, ordenada por `lastUpdated` ou por `name` (sem diferenciar maiúsculas de minúsculas). |
| `TemplateGalleryHelper.mjs:64-80` (`canUserOverrideTemplate`) | Lê `owner` para nomear o proprietário na mensagem de conflito. |

#### Índices {#indexes}

| Nome | Chaves | Opções | Migração |
| ---- | ---- | ------- | --------- |
| `_id_` | `_id: 1` | | padrão |

O `autoIndex` do Mongoose está desativado (`services/web/app/src/infrastructure/Mongoose.mjs:7`). `tools/migrations/20190912145030_create_templates_indexes.mjs` (`project_id`, `user_id`, `name` únicos) é marcada com `server-pro` e `saas`, então não executa no CE, que executa apenas as migrações `server-ce` (`server-ce/init_scripts/900_run_web_migrations.sh`).

#### Notas {#notes}

* O upstream trata `templates` como uma coleção obsoleta e a remove no próprio site (`tools/migrations/20241002180623_drop_unused_collections.mjs`, marcada com `saas`). No Ayakaleaf Pro, o módulo da galeria de modelos a usa.
* A ordenação por nome usa uma collation que não diferencia maiúsculas de minúsculas, e o comentário em `TemplateGalleryManager.mjs:186-188` observa que um índice de `name` precisaria da mesma. O CE não tem índice de `name`, então o Mongo ordena em memória.
* Excluir o projeto de origem ou o proprietário não exclui o modelo.
