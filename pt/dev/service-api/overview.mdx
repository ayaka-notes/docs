O Overleaf é executado como vários serviços que se chamam via HTTP dentro da rede Docker. As páginas desta seção descrevem essas APIs internas. Elas vêm dos arquivos OpenAPI em [`develop/hoppscotch/openapi/`](https://github.com/ayaka-notes/ayakaleaf-pro/tree/server-pro/develop/hoppscotch/openapi), escritos a partir do código de cada serviço.

Nenhuma dessas APIs é pública: elas só são acessíveis dentro da rede Docker, e a maioria não tem autenticação.

## Serviços {#services}

| Serviço | Endereço | O que faz |
| ------------------------------------------------- | ----------------------------------- | ------------------------------------------------------------------------------------------------ |
| [web](/pt/dev/service-api/web)                                     | `http://web:3000`                   | O aplicativo principal. Sua API privada é chamada pelos outros serviços e pelos scripts cron da imagem  |
| [document-updater](/pt/dev/service-api/document-updater)           | `http://document-updater:3003`      | Mantém no Redis os documentos abertos no editor, aplica as edições e os grava de volta no Mongo         |
| [docstore](/pt/dev/service-api/docstore)                           | `http://docstore:3016`              | Armazena cada documento de cada projeto na coleção do Mongo `docs`                                 |
| [real-time](/pt/dev/service-api/real-time)                         | `http://real-time:3026`             | Mantém as conexões socket.io do editor e repassa edições entre navegadores e serviços          |
| [chat](/pt/dev/service-api/chat)                                   | `http://chat:3010`                  | Armazena o chat do projeto e os tópicos de comentários                                                  |
| [project-history](/pt/dev/service-api/project-history)             | `http://project-history:3054`       | Transforma edições enfileiradas em alterações de histórico e as envia ao history-v1; mantém rótulos               |
| [history-v1](/pt/dev/service-api/history-v1)                       | `http://history-v1:3100`            | Armazena o histórico completo de cada projeto e o conteúdo dos arquivos como blobs                           |
| [filestore](/pt/dev/service-api/filestore)                         | `http://filestore:3009`             | Serve arquivos de modelos e, somente leitura, os blobs que o history-v1 grava                           |
| [clsi](/pt/dev/service-api/clsi)                                   | `http://clsi:3013`                  | Compila projetos, executa SyncTeX e contagem de palavras, converte documentos                              |
| [notifications](/pt/dev/service-api/notifications)                 | `http://notifications:3042`         | Armazena as notificações exibidas na lista de projetos                                               |
| [linked-url-proxy](/pt/dev/service-api/linked-url-proxy)           | `http://linked-url-proxy:3066`      | Busca URLs externas para o web e recusa endereços internos                                     |
| [third-party-datastore](/pt/dev/service-api/third-party-datastore) | `http://third-party-datastore:3002` | Sincroniza projetos com o Dropbox por meio de uma fila de jobs por usuário                                       |

## Autenticação {#authentication}

* <strong>web:</strong> autenticação HTTP básica com `WEB_API_USER` e `WEB_API_PASSWORD`. As rotas do git-bridge usam um token de acesso pessoal.
* <strong>history-v1:</strong> autenticação HTTP básica como `staging` com `STAGING_PASSWORD`, ou um JWT.
* <strong>Todos os outros serviços:</strong> nenhuma.

## Experimente {#try-them}

O ambiente de desenvolvimento executa o [Hoppscotch](https://github.com/hoppscotch/hoppscotch) em `http://localhost:9170`, com um proxy que alcança os serviços pelos endereços Docker. O [README](https://github.com/ayaka-notes/ayakaleaf-pro/blob/server-pro/develop/README.md#hoppscotch) mostra como configurar o proxy e importar os arquivos OpenAPI.
