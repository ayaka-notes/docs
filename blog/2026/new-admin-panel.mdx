Running an Overleaf instance for a lab or a department brings the same questions every week. Why can't this student log in? Who still uses the server? Who gave that account admin rights? Where did last year's thesis go? We rebuilt the admin panel so that you can answer them without opening a database shell.

The new panel follows the look of Overleaf 6.3 and is translated into every language the interface supports. It has one list for all users, one list for all projects, a page for each of them, a place to manage your templates, and audit logs.

<Info>

The new admin panel is merged into our main branch and will be officially released in v6.4.0. Every screenshot in this post comes from a test instance filled with made-up accounts.

</Info>

### What's in it

* **User list**: search, filters by login method, role and status, and bulk actions.
* **User page**: the account, projects, features, integrations, audit logs and sessions of one person.
* **Project list**: every project on the instance, searchable by name, ID, owner or sharing link.
* **Project page**: the settings, files, members, deleted files and audit logs of one project.
* **Template management**: publish a project as a template, update it, and keep the gallery in order.
* **Audit logs**: who did what, when, and from which IP address.

## One list for every user

Click **Admin**, then **Manage Users**. Each account is one row that shows how it logs in, its role and its status.

<Frame caption="The user list">
  <img src="/images/blog/admin-panel-users.png" alt="The user list with accounts that log in with a password, Keycloak, SAML and LDAP, in the Active, Pending, Disabled and Inactive statuses" />
</Frame>

Search by name, email or ID. The **Login**, **Role** and **Status** headers are filters, and each option shows how many accounts it would return. You can see at a glance how many people come in through SAML, and each OIDC provider appears under the name you gave it.

<Frame caption="Filtering by login method">
  <img src="/images/blog/admin-panel-users-login-filter.png" alt="The Login filter open, with the number of accounts for Password, LDAP, SAML and Keycloak" />
</Frame>

Every account has exactly one status, and the four statuses add up to the total.

| Status       | What it means                                                  |
| ------------ | -------------------------------------------------------------- |
| **Active**   | Logged in or opened a project in the last 12 months.           |
| **Pending**  | Has never logged in.                                           |
| **Inactive** | Logged in before, but not in the last 12 months.               |
| **Disabled** | An administrator stopped the account from logging in.          |

Deleted accounts stay out of the way in their own filter. If a search also matches a deleted account, a line above the table says so and offers to show it.

<Frame caption="Filtering by status">
  <img src="/images/blog/admin-panel-users-status-filter.png" alt="The Status filter open, with the number of accounts for each status" />
</Frame>

Search, sorting and paging run on the server, so the lists no longer stop at the first 1,000 rows.

### Bring people in, with or without email

**Create account** adds a user and gives you the link they need. When [email delivery](/on-premises/configuration/overleaf-toolkit/email-delivery  "mention") is not set up, the dialog says so plainly and lets you copy the link, so a small instance can still onboard people.

<Frame caption="A new account's activation link">
  <img src="/images/blog/admin-panel-create-account.png" alt="The Create account dialog for Tom Berg, with the warning that no email was sent, an activation link, a copy icon and Expires in 7 days" />
</Frame>

The panel offers the right link for each account: **Send activation email** for one that has never logged in, valid for 7 days, and **Send reset link** for one that has, valid for 1 hour. Accounts that log in through SSO have no local password, so they get neither.

### Change many accounts at once

Tick some accounts and the toolbar offers **Send activation email**, **Transfer this user's projects**, **Disable**, **Enable**, **Make admin**, **Remove admin** and **Delete account**. The dialog lists the accounts before you confirm. If some of them fail, it tells you which, and what already worked stays done.

<Frame caption="Bulk actions">
  <img src="/images/blog/admin-panel-users-bulk.png" alt="Three ticked accounts and the bulk action buttons next to Create account" />
</Frame>

### Hard to get wrong

* Your own account is marked **You** and its actions are greyed out, so you cannot disable, delete or demote yourself.
* Every action asks for confirmation in a dialog that names the account.
* **Delete account** can hand the user's projects to someone else first.
* A deleted account can be restored, together with the projects that were deleted with it. Only **Delete permanently** is final, and it warns you.

## Every project on the instance

## Template management

A template starts as an ordinary project. You publish it from the editor, and manage it from its page in the gallery or from the admin panel.

### All templates in one table

Click **Admin**, then **Project/Object Lookup**, then the **Templates** tab. It lists every published template with its author, its owner and when it last changed, and you can search it. Click a title to open the template, click an owner to open that user's page, or click the bin to delete a template. A deletion goes on [your own audit log](#when-there-is-no-log-left).

<Frame caption="All templates in the admin panel">
  <img src="/images/blog/admin-panel-templates.png" alt="The Templates tab listing published templates with their authors, owners and last modified dates" />
</Frame>

### Publish from the editor

Open a project and compile it until the PDF looks right, because the gallery shows the PDF of the last successful compile. Then click **File**, then **Manage Template**, and fill in the title, the author, a category, a description in Markdown and a license. The project's compiler and main document go with the template, so projects opened from it use the same ones.

<Frame caption="Publishing a project as a template">
  <img src="/images/blog/admin-panel-template-publish.png" alt="The Manage Template dialog over the editor, with the title, author, category, description and license of a journal article" />
</Frame>

### Update a template

To change a template's files and PDF, publish the project again under the same title. The dialog tells you that the title already exists, and the button becomes **Overwrite**. Projects that people have already opened from the template do not change.

<Frame caption="Publishing under the same title">
  <img src="/images/blog/admin-panel-template-overwrite.png" alt="The Manage Template dialog with the message that a template with this title already exists and an Overwrite button" />
</Frame>

### The template page

Everyone can use **Open as Template**, **View PDF** and the download button. Administrators also get **Admin: Source Project**, **Edit** and **Delete**.

<Frame caption="A template's page">
  <img src="/images/blog/admin-panel-template-page.png" alt="The page of the Journal article template with its PDF preview, details and the Admin: Source Project, Edit and Delete buttons" />
</Frame>

**Edit** changes what the gallery shows about a template: its title, author, category, description and license, and the spell check language of projects opened from it. It does not touch the files or the PDF. The template keeps its own copy of the files, so deleting the source project does not take the template with it.

<Frame caption="Editing a template's details">
  <img src="/images/blog/admin-panel-template-edit.png" alt="The Edit template dialog with the title, author, categories, description, license and language" />
</Frame>

### A gallery for your users

## Audit logs: who did what, and when

This is the part we are most pleased with. Every account and every project now has its own audit log, and site administrators can read it right in the panel.

Open the **Audit logs** tab on a user's page. The newest entries come first.

<Frame caption="An account's audit log">
  <img src="/images/blog/admin-panel-audit-user.png" alt="The audit log of Lena Fischer listing logins by her and changes by an administrator to her features, AI access, admin role and sessions" />
</Frame>

Read from the bottom up, this page tells a story. Lena logged in. An administrator raised her compile timeout to 300 seconds, turned off her AI access, sent her a password reset link, made her an admin and took it back, then disabled and re-enabled the account. Lena logged in again, and the administrator cleared her sessions.

| Column         | What it tells you                                                                             |
| -------------- | --------------------------------------------------------------------------------------------- |
| **Date**       | When it happened.                                                                             |
| **Operation**  | What happened.                                                                                |
| **Initiator**  | Who did it. Things an administrator does to an account show the administrator, not the user.  |
| **IP Address** | Where the request came from.                                                                  |
| **Info**       | The details, such as the new compile timeout, or whether the email really went out.           |

### Find the entry you need

Search by operation or by IP address. The **Operation** header is a filter that lists every operation in this log and how many times it happened.

<Frame caption="Filtering by operation">
  <img src="/images/blog/admin-panel-audit-filter.png" alt="The Operation filter open, listing operations such as Change features, Failed password match and Login with their counts" />
</Frame>

### A log for every project

The project page has the same tab. It shows who was invited, who joined, whose role changed, who downloaded the project and who took it over.

### What gets recorded

These are the main operations on each log, under the names you see in the panel.

| Log     | Area                  | Operations                                                                                                                                                                                                                                  |
| ------- | --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Account | Login and password    | Login, Logout, Failed password match, Update password, Reset password                                                                                                                                                                       |
| Account | Email and SSO         | Add email, Remove email, Change primary email, Link SSO, Unlink SSO                                                                                                                                                                         |
| Account | Integrations          | Link GitHub, Unlink GitHub, Link Dropbox, Unlink Dropbox, Integration account linked, Integration account unlinked, Create Git token, Delete Git token                                                                                      |
| Account | Administrator actions | Create account, Send activation email, Send password reset email, Change name, Change admin access, Change features, Change AI features, Reset AI usage, Account suspension, Account reactivation, Clear sessions, Transfer projects, Delete account, Restore account |
| Project | Sharing               | Send invite, Resend invite, Revoke invite, Accept invite, Join via token, Accept via link sharing, Remove collaborator, Leave project, Project role changed, Toggle access level, Transfer ownership                                       |
| Project | Files                 | Project downloaded, Project exported docx, Project exported markdown, Project exported html, Restore deleted doc                                                                                                                            |
| Project | Administrator actions | Project deleted, Project restored                                                                                                                                                                                                           |
| Project | Git sync              | Integration repo linked, Integration repo unlinked                                                                                                                                                                                          |

### When there is no log left

**Delete permanently** removes an account or a project together with its log, and a template never had one. So these actions are written to the log of the administrator who did them, along with the email or ID of what was removed.

<Frame caption="Permanent deletions on the administrator's own log">
  <img src="/images/blog/admin-panel-audit-admin.png" alt="An administrator's own audit log filtered to purges, listing the deleted accounts" />
</Frame>

### Good to know

* Entries are kept for two and a half years, then MongoDB removes them automatically.
* Behind a reverse proxy, set [`OVERLEAF_TRUSTED_PROXY_IPS`](/on-premises/configuration/overleaf-toolkit/environment-variables  "mention") so that the log shows the visitor's address and not the proxy's.
* Not everything is recorded yet. Git clone and push, edits to a project's settings such as its name or compiler, and the projects an owner creates, archives, trashes or deletes do not appear in the project log.
