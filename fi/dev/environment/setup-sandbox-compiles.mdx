Hiekkalaatikkokäännökset toimivat kehitysympäristössä hieman eri tavalla kuin tuotantoimagessa. Kehitysympäristössä ne on jo määritetty; tämä sivu selittää asetukset ja kolme huomioitavaa asiaa:

* Tiedosto-oikeusongelma
* Volyymin jakaminen history-v1:n ja filestoren välillä
* Alihakemisto-ongelma

### Sandbox Compiles -toiminnon käyttöönotto {#enable-sandbox-compiles}

Hiekkalaatikkokäännökset ovat oletuksena käytössä. `develop/docker-compose.yml` asettaa `SANDBOXED_COMPILES=true` palvelulle `clsi`, ja `develop/dev.env` sisältää loput:

```dotenv title="develop/dev.env" wrap
#################
#   Sandbox     #
#################
SANDBOXED_COMPILES=true
SANDBOXED_COMPILES_HOST_DIR_COMPILES=${PWD}/compiles
SANDBOXED_COMPILES_HOST_DIR_OUTPUT=${PWD}/output
TEXLIVE_IMAGE_USER=tex
ALL_TEX_LIVE_DOCKER_IMAGES=ghcr.io/ayaka-notes/texlive-full:2026.1, ghcr.io/ayaka-notes/texlive-full:2025.1
ALL_TEX_LIVE_DOCKER_IMAGE_NAMES=Texlive 2026, Texlive 2025
TEX_LIVE_DOCKER_IMAGE=ghcr.io/ayaka-notes/texlive-full:2026.1
```

clsi ei hae imageja itse, joten hae imaget kerran komennolla `docker pull ghcr.io/ayaka-notes/texlive-full:2026.1` (ja `:2025.1`).

LaTeX suoritetaan sisarkonteissa käyttäjänä `TEXLIVE_IMAGE_USER`. Kehitysympäristössä se on `tex`, joka on myös clsi:n oletus (`services/clsi/config/settings.defaults.cjs:154`). Tuotantoimage käyttää sen sijaan käyttäjää `www-data`, kun `SANDBOXED_COMPILES_SIBLING_CONTAINERS=true` (`server-ce/config/env.sh:15-21`), koska siellä tiedostot luo Overleaf-kontin `www-data`-käyttäjä.

<Warning>

Älä käytä itse rakentamaasi imagea, sillä saatat kohdata useita virheitä.

</Warning>

### Tiedosto-oikeuksien korjaaminen {#fix-file-permissions}

clsi-kontti käynnistyy rootina, antaa kansiot `compiles`, `output` ja `cache` käyttäjälle `node` (uid `1000`) ja suorittaa sitten clsi:n käyttäjänä `node` (`services/clsi/entrypoint.sh`). Siksi isäntäkoneen `develop/compiles` kuuluu uid:lle `1000`, samalle uid:lle kuin `tex` kehitysympäristössä (katso kommentti tiedostossa `develop/pandoc/Dockerfile`). Yllä olevilla asetuksilla kehitysympäristö kääntää ilman oikeuksien muutoksia.

Jos asetat sen sijaan `TEXLIVE_IMAGE_USER=root`, rootilla (uid `0`) ei ole oikeutta kirjoittaa `compiles`-kansion alikansioihin. Anna siinä tapauksessa `root`-ryhmälle omistajuus ja kirjoitusoikeus `compiles`-kansioon ja aseta `setgid`, jotta uudet alikansiot perivät tämän omistajuuden:

```bash title="bash"
sudo chown -R 1000:root compiles
sudo chmod -R g+w compiles
sudo chmod g+s compiles
```

Tarkemmat tiedot löydät tiedostosta `services/clsi/README.md`.

### Volyymin jakaminen history-v1:n ja filestoren välillä {#volume-share-between-history-v1-and-filestore}

<Info>

Tämän ja seuraavan osion asetukset ovat jo tiedostoissa `develop/docker-compose.yml` ja `develop/dev.env`. Niillä on merkitystä vain, kun `develop/dev.rc` sisältää `S3_ENABLED=false`. Oletusarvolla `S3_ENABLED=true` filestore ja history-v1 säilyttävät nämä tiedostot sen sijaan RustFS-bucketeissa (`develop/s3/docker-compose.yml`).

</Info>

Oletusarvoisesti filestore toimii siltana S3:n ja Overleafin muiden palveluiden välillä. Overleaf CE:ssä ja Server Prossa kaikki tiedostot kuitenkin tallennetaan oletusarvoisesti paikallisesti. Siksi Overleaf otti käyttöön hyvin kekseliään menetelmän.

```javascript title="server-ce/config/settings.js" wrap
switch (process.env.OVERLEAF_FILESTORE_BACKEND) {
  case 's3':
    // s3 case...
  default:
    settings.filestore = {
      backend: 'fs',
      stores: {
        template_files: Path.join(DATA_DIR, 'template_files'),

        // NOTE: The below paths are hard-coded in server-ce/config/production.json, so hard code them here as well.
        // We can use DATA_DIR after switching history-v1 from 'config' to '@overleaf/settings'.
        project_blobs:
          process.env.OVERLEAF_HISTORY_PROJECT_BLOBS_BUCKET ||
          '/var/lib/overleaf/data/history/overleaf-project-blobs',
        global_blobs:
          process.env.OVERLEAF_HISTORY_BLOBS_BUCKET ||
          '/var/lib/overleaf/data/history/overleaf-global-blobs',
      },
    }
}
```

Samalla historiapalvelu käyttää myös `data/history`-hakemistoa. Näin eri mikropalvelut voivat jakaa samat tiedot. Siksi developin filestore-palvelu liittää history-v1:n `history-v1-buckets`-volyymin. Ilman sitä **clsi ei pysty hakemaan blob-tiedostoja filestore-palvelusta**.

```yml title="develop/docker-compose.yml" wrap
  filestore:
    build:
      context: ..
      dockerfile: services/filestore/Dockerfile
    env_file:
      - dev.env
#    environment:
#      - ENABLE_CONVERSIONS=true
    volumes:
      - filestore-public-files:/overleaf/services/filestore/public_files
      - filestore-template-files:/overleaf/services/filestore/template_files
      - filestore-uploads:/overleaf/services/filestore/uploads
      - history-v1-buckets:/buckets
```

filestore löytää bucketit näiden `dev.env`-asetusten avulla:

```dotenv title="develop/dev.env"
OVERLEAF_EDITOR_PROJECT_BLOBS_BUCKET='/buckets/project_blobs'
OVERLEAF_EDITOR_BLOBS_BUCKET='/buckets/blobs'
```

### Alihakemistojen käyttäminen {#use-subdirectories}

filestore lukee historian blobit aina alihakemistojen kanssa (`services/filestore/app/js/KeyBuilder.js:58`, `:70`). Tuotantoimage ottaa `useSubdirectories`-asetuksen käyttöön history-v1:lle (`server-ce/config/production.json`), mutta history-v1:n oletusasetukset eivät, joten kehityksessä history-v1 <strong>litistäisi kaikki tiedot.</strong> Siksi `dev.env` asettaa history-v1:lle `NODE_CONFIG`-muuttujan:&#x20;

```dotenv title="develop/dev.env"
OVERLEAF_EDITOR_PROJECT_BLOBS_BUCKET='/buckets/project_blobs'
OVERLEAF_EDITOR_BLOBS_BUCKET='/buckets/blobs'
NODE_CONFIG='{"persistor":{"useSubdirectories":true}}'
```

Ilman sitä history-v1 tallentaa `project_blobs`-tiedostot näin:

```bash wrap
node@43eb5dac5b1b:/buckets/project_blobs$ ls
169_609_71360f687c431b9796_5b_889ef3cf71c83a4c027c4e4dc3d1a106b27809  
94e_655_88cb5cc77ab70c9796_a0_e21c740cf81e868f158e30e88985b5ea1d6c19
169_609_71360f687c431b9796_a0_e21c740cf81e868f158e30e88985b5ea1d6c19
94e_655_88cb5cc77ab70c9796_fd_3c0326302e49486d3ea86c833edf9b88320c41
169_609_71360f687c431b9796_fd_3c0326302e49486d3ea86c833edf9b88320c41 

```

Kun `useSubdirectories` on `true`, näiden nimien `_` muuttuu muotoon `/`, joten jokainen blob tallennetaan alikansioihin.
