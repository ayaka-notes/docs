## Esivaatimukset {#prerequisites}

Overleaf on tyypillinen mikropalveluarkkitehtuuriin perustuva avoimen lähdekoodin projekti, jonka kaikki palvelut ajetaan Dockerissa.

* Virallisen Community Editionin lähdekoodi on osoitteessa [GitHub Overleaf Official](https://github.com/overleaf/overleaf/tree).
* Overleaf-CEP:n lähdekoodi on saatavilla osoitteessa [GitHub Yu-i-i/Overleaf](https://github.com/yu-i-i/overleaf-cep).
* Ayakaleaf Pro on saatavilla osoitteessa [GitHub ayaka-notes/ayakaleaf-pro](https://github.com/ayaka-notes/ayakaleaf-pro).

Overleaf-kehitysympäristön määrittämiseen tarvitset tehokkaan palvelimen; suosittelemme vähintään 8 ydintä ja 16 Gt RAM-muistia, koska sinun on ajettava yli 20 konttia samanaikaisesti.

<Info>

Koska palvelimet, joissa on vähintään 8 suoritinydintä, ovat yleensä kalliita, suosittelemme vahvasti kehittämään omalla paikallisella tietokoneellasi.

</Info>

Oletamme lisäksi, että kehittäjänä tunnet jo [Dockerin asennuksen](https://docs.docker.com/engine/install/ubuntu/). Suosittelemme vahvasti käyttämään kehitykseen tuoretta ja vakaata Ubuntu LTS -versiota (esim. Ubuntu 24.04 vuosina 2025–2026) ja uusinta Dockeria, sillä tämä vähentää odottamattomien virheiden todennäköisyyttä.

Yhteenvetona tarvitset:

* [x] Tehokkaan palvelimen tai työaseman kehitykseen
* [x] Tuoreen ja vakaan Ubuntu LTS -version (esim. Ubuntu 24.04)
* [x] Docker- ja Git-ympäristön

## Määritysopas {#configuration-tutorial}

Tässä näytämme Ayakaleaf Pron avulla, miten Overleafin kehitysympäristö otetaan käyttöön. Kaikki alla olevat komennot suoritetaan hakemistossa `develop`, ellei toisin mainita.

<Steps>
<Step title="Hae lähdekoodi">
Kloonataan ensin repositorio:

```bash title="bash"
git clone https://github.com/ayaka-notes/ayakaleaf-pro.git
cd ayakaleaf-pro/develop
```
</Step>

<Step title="Synkronoi `yarn.lock`">
Repositorio käyttää Yarn 4:ää (`packageManager` juuren `package.json`-tiedostossa), ja sen `yarn.lock` voi olla epäsynkronissa `package.json`-tiedostojen kanssa. Synkronoi se ensimmäisen kloonauksen jälkeen ja aina, kun jokin `package.json` muuttuu:

```bash title="bash"
bin/sync
```

`bin/sync` suorittaa `yarn install --mode=update-lockfile` -komennon `node:24.18.1`-kontissa, joten et tarvitse Node.js:ää isäntäkoneelle. Älä commitoi muuttunutta `yarn.lock`-tiedostoa.
</Step>

<Step title="Rakenna kehitysimage">
Rakenna palvelut:

```bash title="bash"
bin/build
```

<Info>

Jos Dockerilta loppuu RAM-muisti palveluiden rinnakkaisen rakentamisen aikana, luo tähän hakemistoon `.env`-tiedosto, joka sisältää rivin `COMPOSE_PARALLEL_LIMIT=1`.

</Info>
</Step>

<Step title="Käännösten käyttöönotto">
Ayakaleaf Pron moduulit säilyttävät käännöksensä hakemistossa `services/web/locales/locales_patches/`, jota commitoidut kielitiedostot eivät sisällä. Ota ne käyttöön kerran ennen ensimmäistä käynnistystä, muuten näiden moduulien sivuilla näkyy tekstin sijaan avaimia, kuten `about_to_permanently_delete_accounts`:

```bash title="bash"
bin/i18n
```

Se tarvitsee isäntäkoneelle `jq`:n. Suorita se uudelleen, kun olet lisännyt käännöksen tai vaihtanut haaraa, katso [i18n-käännösten päivittäminen](/fi/dev/environment/update-i18n-translations).
</Step>

<Step title="Käynnistä kaikki mikropalvelut">
Käynnistä sitten palvelut:

```bash title="bash"
bin/up
```

Kun palvelut ovat käynnissä, avaa [http://localhost/launchpad](http://localhost/launchpad) ja luo ensimmäinen ylläpitäjätili. Lisää portti, jos olet muuttanut `OVERLEAF_PORT`-arvoa (katso alla).

<Info>

LDAP on oletuksena käytössä (`LDAP_ENABLED=true` tiedostossa `dev.rc`). Launchpad näyttää silloin LDAP-ylläpitäjän lomakkeen: se kysyy vain sähköpostiosoitetta, ja ylläpitäjä kirjautuu sen jälkeen LDAP:n kautta, esimerkiksi tunnuksilla `professor` / `professor` (`professor@planetexpress.com`). Testikäyttäjät on lueteltu tiedostossa `develop/authentication/README.md`. Aseta `LDAP_ENABLED=false` ja `SAML_ENABLED=false`, jos haluat sen sijaan luoda paikallisen ylläpitäjän salasanalla.

</Info>
</Step>
</Steps>

<Info>

`develop/dev.env` asettaa jo `ADMIN_PRIVILEGE_AVAILABLE=true`, joten ylläpitäjät voivat avata hallintapaneelin ilman lisäasetuksia.

</Info>

### Määritykset (`dev.rc`) {#configuration-dev-rc}

`develop/dev.rc` tiedoston `dev.env` vieressä sisältää kehitysympäristön kytkimet, kuten `overleaf.rc` Overleaf Toolkitissa. Muuta arvoa ja suorita `bin/dev` uudelleen ottaaksesi sen käyttöön; pois päältä kytketty ominaisuus pysäyttää myös konttinsa.

| Muuttuja | Oletus | Mitä se tekee |
| --- | --- | --- |
| `OVERLEAF_PORT` | `80` | Sivuston isäntäportti. |
| `LDAP_ENABLED` | `true` | LDAP-kirjautuminen testikäyttäjillä. |
| `SAML_ENABLED` | `true` | SAML-kirjautuminen testikäyttäjillä. |
| `MAILPIT_ENABLED` | `true` | Kaappaa jokaisen `web`-palvelun sähköpostin Mailpitiin. Ottaa myös sähköpostin vahvistuksen käyttöön (`EMAIL_CONFIRMATION_DISABLED=false`). |
| `S3_ENABLED` | `true` | Säilyttää historia- ja mallitiedostot RustFS:ssä (S3) paikallisten volyymien sijaan. |
| `HOPPSCOTCH_ENABLED` | `true` | Hoppscotch välityspalvelimella Docker-verkkoon, katso [Kehitystyökalujen käyttöönotto](/fi/dev/environment/setup-develop-tools). |
| `HOPPSCOTCH_PORT` | `9170` | Hoppscotchin isäntäportti. |
| `GRAFANA_ENABLED` | `true` | Grafana sivuston polussa `/grafana/` jokaisen palvelun tilan, mittareiden ja lokien kanssa, katso [Kehitystyökalujen käyttöönotto](/fi/dev/environment/setup-develop-tools). |

Jokainen ominaisuus pitää `docker-compose.yml`-tiedostonsa ja muut tiedostonsa omassa kansiossaan: `authentication/ldap`, `authentication/saml`, `mail`, `s3`, `hoppscotch` ja `grafana`. Ominaisuus, joka tarvitsee `web`-asetuksen ilman ympäristömuuttujaa, liittää tiedoston hakemistoon `/etc/overleaf/settings.d/`, ja `develop/settings.dev-env.cjs` yhdistää ne kaikki. Kaikki `bin/*`-skriptit kulkevat `bin/docker-compose`-skriptin kautta, joka lisää päällä olevien ominaisuuksien tiedostot. Käytä `bin/docker-compose`-komentoa `docker compose` -komennon sijaan, kun tarvitset itse compose-komentoa.

<Warning>

Paikalliset volyymit ja RustFS ovat erillisiä tallennustiloja: projektilla, joka on luotu asetuksella `S3_ENABLED=true`, ei ole historiaa eikä binääritiedostoja vaihdon jälkeen arvoon `false`, ja päinvastoin. Kopioidaksesi RustFS:ään sellaisen ympäristön tiedostot, joka oli käytössä ennen kuin `S3_ENABLED` oli olemassa, noudata ohjetta ”Moving existing data into RustFS” tiedostossa [develop/README.md](https://github.com/ayaka-notes/ayakaleaf-pro/blob/server-pro/develop/README.md).

</Warning>

### Portit {#ports}

Sivusto, RustFS-konsoli ja Hoppscotch kuuntelevat isäntäkoneen osoitetta `127.0.0.1`; etäkoneella ohjaa ensin niiden portit eteenpäin, esimerkiksi `ssh -L 9001:localhost:9001 <host>`. Sivusto käyttää `dev.rc`:n `OVERLEAF_PORT`-arvoa, joten lisää portti alla oleviin osoitteisiin, jos olet muuttanut sitä.

| Sivu | Osoite | Kirjautuminen |
| --- | --- | --- |
| Sivusto | [http://localhost](http://localhost) | Sivuston tilit tai testikäyttäjät |
| Sähköpostilaatikko (Mailpit) | [http://localhost/mailpit/](http://localhost/mailpit/) | Ei mitään |
| Grafana | [http://localhost/grafana/](http://localhost/grafana/) | Ei mitään, anonyymit käyttäjät ovat ylläpitäjiä |
| Mongo Express | [http://localhost/mongo-express/](http://localhost/mongo-express/) | Ei mitään |
| RedisInsight | [http://localhost/redis-insight/](http://localhost/redis-insight/) | Ei mitään |
| S3-konsoli (RustFS) | [http://localhost:9001/rustfs/console/](http://localhost:9001/rustfs/console/) | `rustfsadmin` / `rustfsadmin` |
| Hoppscotch | [http://localhost:9170](http://localhost:9170) (`HOPPSCOTCH_PORT`) | Ei mitään |

Sivusto tarjoaa Mailpitin, Grafanan, Mongo Expressin ja RedisInsightin omissa poluissaan webpack-dev-serverin kautta, joten ne eivät tarvitse omia portteja. Kun olet kirjautunut, sivuston navigointipalkin **Dev tools** -valikko linkittää niihin; sivu, jonka ominaisuus on kytketty pois `dev.rc`:ssä, jätetään pois. [Kehitystyökalujen käyttöönotto](/fi/dev/environment/setup-develop-tools) kertoo, mitä kukin niistä tekee.

S3-API (portti 9000) ja SMTP (portti 1025) ovat tavoitettavissa vain Docker-verkon sisällä. Mongo (27017), Redis (6379), Mongo Express (8081), RedisInsight (5540) ja git-bridge (8000) julkaistaan vain isäntäkoneen osoitteessa `127.0.0.1`.

### TeX Live {#tex-live}

Hiekkalaatikkokäännökset ovat oletuksena käytössä: `develop/dev.env` asettaa `SANDBOXED_COMPILES=true` sekä imaget `ghcr.io/ayaka-notes/texlive-full:2026.1` ja `ghcr.io/ayaka-notes/texlive-full:2025.1`. clsi ei hae imageja itse, joten hae ne kerran:

```bash
docker pull ghcr.io/ayaka-notes/texlive-full:2026.1
docker pull ghcr.io/ayaka-notes/texlive-full:2025.1
```

Katso lisätiedot sivulta [Sandbox Compiles -toiminnon määrittäminen](/fi/dev/environment/setup-sandbox-compiles).

<Warning>

Projektilla, joka luotiin, kun `SANDBOXED_COMPILES` oli pois päältä, ei ole TeX Live -imagea. Se kääntyy edelleen oletusimagella, mutta siirtyminen koodin ja PDF:n välillä epäonnistuu virheellä ”That didn't work. Recompile and try again.” Anna tällaisille projekteille kerran `TEX_LIVE_DOCKER_IMAGE`-image; ilman `--commit`-valitsinta skripti vain näyttää, mitä se muuttaisi:

```bash
bin/docker-compose exec web sh -c 'cd /overleaf/services/web && node scripts/backfill_project_image_name.mjs --commit'
```

</Warning>

`dev.env` ottaa myös Pandoc-muunnokset käyttöön asetuksella `PANDOC_IMAGE=overleaf-pandoc:local`. Rakenna tämä image kerran repositorion juuresta:

```bash
docker build -t overleaf-pandoc:local develop/pandoc
```

Kääntääksesi macOS-isäntäkoneella sinun on ehkä ohitettava Docker-socketin polku luomalla hakemistoon `develop` `.env`-tiedosto, joka sisältää `DOCKER_SOCKET_PATH=/var/run/docker.sock.raw`

### Kehitys {#development}

Jotta sinun ei tarvitse ajaa `bin/build && bin/up` jokaisen koodimuutoksen jälkeen, voit ajaa Overleaf Community Editionia _kehitystilassa_, jolloin palvelut päivittyvät automaattisesti koodimuutosten myötä.

Käytä tähän mukana tulevaa `bin/dev`-skriptiä:

```text
bin/dev
```

Tämä käynnistää kaikki palvelut komennolla `node --watch`, joka valvoo koodia automaattisesti ja käynnistää palvelut tarvittaessa uudelleen. Suorita se uudelleen, kun olet muuttanut `dev.rc`:tä.

Suorituskyvyn parantamiseksi voit käynnistää kehitystilassa vain osan palveluista antamalla `bin/dev`-skriptille välilyönnein erotellun luettelon:

```text
bin/dev [service1] [service2] ... [serviceN]
```

<Info>

Kun `web`-palvelu käynnistetään _kehitystilassa_, vain `web`-palvelu päivittyy taustajärjestelmän koodin muuttuessa. Jotta myös käyttöliittymäkoodi päivittyisi automaattisesti, käynnistä myös `webpack`-palvelu _kehitystilassa_.

</Info>

Jos palveluita ei nimetä, kaikki palvelut käynnistyvät kehitystilassa.

Kun olet lisännyt käännöksen tai vaihtanut haaraa, suorita `bin/i18n`, katso [i18n-käännösten päivittäminen](/fi/dev/environment/update-i18n-translations).

### Virheenjäljitys {#debugging}

_Kehitystilassa_ useimmat palvelut tarjoavat virheenkorjausportin, johon voit liittää virheenkorjaimen, kuten Chromen Dev Toolsin tarkastimen tai IDE:hen integroidun virheenkorjaimen. Seuraava taulukko näyttää kunkin palvelun portin, joka on avattu **isäntäkoneen** osoitteeseen `127.0.0.1`:

| Palvelu            | Portti |
| ------------------ | ---- |
| `web`                   | 9229 |
| `clsi`                  | 9230 |
| `chat`                  | 9231 |
| `docstore`              | 9233 |
| `document-updater`      | 9234 |
| `filestore`             | 9235 |
| `notifications`         | 9236 |
| `real-time`             | 9237 |
| `history-v1`            | 9239 |
| `project-history`       | 9240 |
| `linked-url-proxy`      | 9241 |
| `third-party-datastore` | 9242 |

Liittyäksesi palveluun Chromen _etävirheenjäljityksellä_ siirry osoitteeseen chrome://inspect/ ja varmista, että _Discover network targets_ on valittuna. Napsauta seuraavaksi _Configure..._ ja lisää merkintä `localhost:[service port]` jokaiselle palvelulle, johon haluat liittää virheenjäljittimen.

Merkinnän lisäämisen jälkeen palvelu näkyy _Remote Target_ -kohteena, jota voit tarkastella ja jäljittää.

### Lokit {#logging}

Skripti `bin/logs` seuraa lokeja ja muotoilee ne `bunyan`-työkalulla. Se tarvitsee myös `ggrep`:n, joka on GNU grepin nimi, kun se asennetaan Homebrew'lla macOS:ään; Ubuntussa ei ole `ggrep`-komentoa.

```bash
sudo npm install -g bunyan
# Or sudo apt install node-bunyan 
```

Vaihtoehtoisesti voit ajaa suoraan:

```text
bin/docker-compose logs -f [service name]
```

Käytä `bin/docker-compose`-komentoa `docker compose` -komennon sijaan, jotta myös `dev.rc`:n ominaisuuksien palvelut (`mailpit`, `rustfs`, `ldap`, `saml`, `hoppscotch` ja `grafana` Prometheuksen, Lokin ja exporterien kanssa) löytyvät.

Kun `GRAFANA_ENABLED=true`, jokaisen kontin lokit ovat myös Grafanassa, jossa niitä voi suodattaa palvelun, tason ja tekstin mukaan, katso [Kehitystyökalujen käyttöönotto](/fi/dev/environment/setup-develop-tools#grafana).
