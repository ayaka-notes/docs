---
title: Deleted Projects -kokoelma
icon: trash-can
---

`deletedProjects` säilyttää projektin sen poistamisen jälkeen: yksi dokumentti jokaista poistettua projektia kohden, ja siinä kopio koko projektidokumentista sekä tieto siitä, kuka projektin poisti. Web kirjoittaa kokoelman tiedostossa `services/web/app/src/Features/Project/ProjectDeleter.mjs`; skeema on `services/web/app/src/models/DeletedProject.mjs`. Kun lopullisen poiston viive on kulunut, vanhentumiskäsittely tuhoaa projektin tiedot ja tyhjentää kentän `project`, mutta tietue, jossa on `deleterData`, säilyy.

Roskakorissa oleva projekti ei ole täällä: roskakoriin siirtäminen vain lisää käyttäjän projektin kenttään `trashed`, katso [Projects-kokoelma](/fi/dev/data-model/projects-collection).

#### Kuka kirjoittaa {#who-writes-it}

| Koodi | Mitä se tekee |
| ---- | ------------ |
| `ProjectDeleter.mjs:189-293` (`deleteProject`) | Tekee projektille flushin, arkistoi sen docsit pois Mongosta, poistaa sen tunnisteista, tekee tietueelle upsertin ja poistaa `projects`-dokumentin. |
| `ProjectDeleter.mjs:295-342` (`undeleteProject`) | Lisää projektin uudelleen nimellä `<name> (Restored)` (tehty omistajalle yksilölliseksi) eikä enää arkistoituna, ja poistaa sitten tietueen. Epäonnistuu virheellä `project_too_old_to_restore`, kun `project` on `null`. Kutsutaan hallintapaneelista: yhden projektin palautus (`AdminProjectManager.mjs:497-515`) tai poistetun käyttäjän palautus yhdessä tilin mukana poistettujen projektien kanssa (`services/web/modules/admin-tools/app/src/AdminUserManager.mjs:678-689`). |
| `ProjectDeleter.mjs:344-416` (`expireDeletedProject`) | Tuhoaa projektin docsit, historian, keskustelun ja projektin tarkastuslokin, laukaisee koukun `projectExpired` ja asettaa sitten `project`- ja `deleterData.deleterIpAddress`-kentät arvoon `null`. Jos projekti on taas olemassa, poistaa vain vanhentuneen tietueen. |
| `ProjectDeleter.mjs:97-146` (`expireDeletedProjectsAfterDuration`) | Vanhentaa erän viivettä vanhempia tietueita. Reitti `POST /internal/expire-deleted-projects-after-duration` (`services/web/app/src/router.mjs:842-846`), jota Community Editionin cron kutsuu joka tunti minuutilla 20, kun `ENABLE_CRON_RESOURCE_DELETION` on `true` (`server-ce/cron/delete-projects.sh:10-23`, `server-ce/config/crontab-deletion:3`). Yksi projekti: `POST /internal/project/:projectId/expire-deleted-project` (`router.mjs:852-856`) tai Purge hallintapaneelissa (`AdminProjectManager.mjs:517-529`). |

#### Huomautukset {#notes}

* Moduulit, jotka kuuntelevat tapahtumaa `projectExpired`, poistavat omat tietonsa projektista: `git-bridge` (`services/web/modules/git-bridge/index.mjs:37`), `github-sync` (`services/web/modules/github-sync/index.mjs:56`), `gitlab-sync` (`services/web/modules/gitlab-sync/index.mjs:46`), `gitea-sync` (`services/web/modules/gitea-sync/index.mjs:46`) ja `dropbox` (`services/web/modules/dropbox/index.mjs:54`).
* Vanhentunutta tietuetta ei koskaan poisteta: `deleterData` säilyy pysyvästi, vain `project` ja IP-osoite tyhjennetään.
* Mongoose antaa myös kentälle `deleterData` oman `_id`:n, jota mikään ei lue.
