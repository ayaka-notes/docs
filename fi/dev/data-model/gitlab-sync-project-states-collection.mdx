title: GitLab Sync Project States -kokoelma
icon: code-merge
---

`gitlabSyncProjectStates` sisältää yhden dokumentin jokaista GitLab-projektiin linkitettyä projektia kohden: mikä repositorio on kyseessä ja mihin viimeisin synkronointi jäi. Kokoelma kuuluu web-moduuliin `gitlab-sync` (`services/web/modules/gitlab-sync`). Skeema on tiedostossa `services/web/modules/gitlab-sync/app/models/gitlabSyncProjectStates.mjs`, ja kaikki käyttö kulkee `services/web/modules/gitlab-sync/app/src/SyncStateManager.mjs` kautta. Kentät ovat samat kuin kokoelmassa [GitHub Sync Project States](/fi/dev/data-model/github-sync-project-states-collection).

#### Kuka kirjoittaa {#who-writes-it}

| Koodi | Mitä se tekee |
| ---- | ------------ |
| `SyncStateManager.mjs:9-14` (`createProjectState`) | Luo dokumentin: kun repositorio on tuotu uudeksi projektiksi (`services/web/modules/gitlab-sync/app/src/GitLabSyncHandler.mjs:175-181`) tai kun projekti on viety uuteen repositorioon (`GitLabSyncHandler.mjs:234-240`, vain omistaja, hylätään jos projekti on jo linkitetty). |
| `SyncStateManager.mjs:16-21` (`updateProjectState`) | Muuttuneiden kenttien `$set`. `getMergeOverview` asettaa `mergeStatus: 'diverged'`, kun synkronoitu haara ei enää sisällä `lastSyncCommit`-committia (merge base -tarkistus, `services/web/modules/gitlab-sync/app/src/GitLabApiClient.mjs:460`) tai commit on kadonnut ja käyttäjä voi pushata (`GitLabSyncHandler.mjs:123,126-137`). Synkronointi (`services/web/modules/gitlab-sync/app/src/GitMerge.mjs`) siirtää onnistuessaan `lastSyncCommit`/`lastSyncVersion`-arvoja (esimerkiksi `:152,189,231`), kirjaa konfliktin kenttiin `unmergedBranchName`, `unmergedBranchHead` ja `conflictVersion` (`:214-220`) ja tyhjentää ne, kun konflikti on ratkaistu (`:257-264`). |
| `SyncStateManager.mjs:23-25` (`removeProjectState`) | Poistaa dokumentin, kun omistaja poistaa projektin linkityksen (`GitLabSyncHandler.mjs:83-97`) ja kun poistettu projekti vanhenee (`services/web/modules/gitlab-sync/index.mjs:46-48`). |

#### Kuka lukee {#who-reads-it}

| Koodi | Mitä se tekee |
| ---- | ------------ |
| `GitLabSyncHandler.mjs:39-60` (`getProjectState`) | Antaa editorille `mergeStatus`-, `repoFullName`- ja `unmergedBranchName`-arvot. Ilman dokumenttia se vastaa `need-export`, arvo, jota ei koskaan tallenneta. |
| `GitLabSyncHandler.mjs:110-143` (`getMergeOverview`) | Vertaa `lastSyncCommit`- ja `lastSyncVersion`-arvoja GitLab:iin ja projektihistoriaan uusien committien listaamiseksi. |
| `GitLabSyncHandler.mjs:200` (`exportProject`) | Kieltäytyy viemästä projektia, joka on jo linkitetty. |
| `GitMerge.mjs:36` (`doGitMergeWithoutLock`) | Lataa tilan synkronoinnin alussa. |

#### Indeksit {#indexes}

| Nimi | Avaimet | Asetukset | Migraatio |
| ---- | ---- | ------- | --------- |
| `_id_` | `_id: 1` | | default |

Mongoosen `autoIndex` on pois päältä (`services/web/app/src/infrastructure/Mongoose.mjs:7`), joten skeeman `unique: true` kentässä `projectId` ei luo mitään. Mikään migraatio ei luo indeksejä tälle kokoelmalle.

#### Huomautukset {#notes}

* GitLabin API ei voi siirtää haaraa mihin tahansa commitiin kuten GitHubin. Synkronointi committaa suoraan synkronoituun haaraan, kun se voi edetä, ja muuten väliaikaiseen haaraan, joka yhdistetään sitten merge requestilla (`GitMerge.mjs:16-21`).
* Synkronointi ajetaan projektin `gitSync`-lukon alla, joka on yhteinen GitHub Syncin ja Gitea Syncin kanssa (`GitMerge.mjs:25-32`).
* Poistettu projekti säilyttää dokumenttinsa, kunnes projekti vanhenee.
* Käyttäjän GitLab-tunniste on kokoelmassa [GitLab Sync User Credentials](/fi/dev/data-model/gitlab-sync-user-credentials-collection).
