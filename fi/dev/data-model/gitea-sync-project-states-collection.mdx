`giteaSyncProjectStates` sisältää yhden dokumentin jokaista Gitea-repositorioon linkitettyä projektia kohden: mikä repositorio on kyseessä ja mihin viimeisin synkronointi jäi. Kokoelma kuuluu web-moduuliin `gitea-sync` (`services/web/modules/gitea-sync`). Skeema on tiedostossa `services/web/modules/gitea-sync/app/models/giteaSyncProjectStates.mjs`, ja kaikki käyttö kulkee `services/web/modules/gitea-sync/app/src/SyncStateManager.mjs` kautta. Kentät ovat samat kuin kokoelmassa [GitHub Sync Project States](/fi/dev/data-model/github-sync-project-states-collection).

#### Kuka kirjoittaa {#who-writes-it}

| Koodi | Mitä se tekee |
| ---- | ------------ |
| `SyncStateManager.mjs:9-14` (`createProjectState`) | Luo dokumentin: kun repositorio on tuotu uudeksi projektiksi (`services/web/modules/gitea-sync/app/src/GiteaSyncHandler.mjs:175-181`) tai kun projekti on viety uuteen repositorioon (`GiteaSyncHandler.mjs:233-239`, vain omistaja, hylätään jos projekti on jo linkitetty). |
| `SyncStateManager.mjs:16-21` (`updateProjectState`) | Muuttuneiden kenttien `$set`. `getMergeOverview` asettaa `mergeStatus: 'diverged'`, kun `lastSyncCommit` ei enää ole synkronoidun haaran esivanhempi (`services/web/modules/gitea-sync/app/src/GiteaApiClient.mjs:431`) tai commit on kadonnut ja käyttäjä voi pushata (`GiteaSyncHandler.mjs:123,126-137`). Synkronointi (`services/web/modules/gitea-sync/app/src/GitMerge.mjs`) siirtää onnistuessaan `lastSyncCommit`/`lastSyncVersion`-arvoja (esimerkiksi `:152,189,231`), kirjaa konfliktin kenttiin `unmergedBranchName`, `unmergedBranchHead` ja `conflictVersion` (`:214-220`) ja tyhjentää ne, kun konflikti on ratkaistu (`:257-264`). |
| `SyncStateManager.mjs:23-25` (`removeProjectState`) | Poistaa dokumentin, kun omistaja poistaa projektin linkityksen (`GiteaSyncHandler.mjs:83-97`) ja kun poistettu projekti vanhenee (`services/web/modules/gitea-sync/index.mjs:46-48`). |

#### Kuka lukee {#who-reads-it}

| Koodi | Mitä se tekee |
| ---- | ------------ |
| `GiteaSyncHandler.mjs:39-60` (`getProjectState`) | Antaa editorille `mergeStatus`-, `repoFullName`- ja `unmergedBranchName`-arvot. Ilman dokumenttia se vastaa `need-export`, arvo, jota ei koskaan tallenneta. |
| `GiteaSyncHandler.mjs:110-143` (`getMergeOverview`) | Vertaa `lastSyncCommit`- ja `lastSyncVersion`-arvoja Gitea:iin ja projektihistoriaan uusien committien listaamiseksi. |
| `GiteaSyncHandler.mjs:200` (`exportProject`) | Kieltäytyy viemästä projektia, joka on jo linkitetty. |
| `GitMerge.mjs:36` (`doGitMergeWithoutLock`) | Lataa tilan synkronoinnin alussa. |

#### Indeksit {#indexes}

| Nimi | Avaimet | Asetukset | Migraatio |
| ---- | ---- | ------- | --------- |
| `_id_` | `_id: 1` | | default |

Mongoosen `autoIndex` on pois päältä (`services/web/app/src/infrastructure/Mongoose.mjs:7`), joten skeeman `unique: true` kentässä `projectId` ei luo mitään. Mikään migraatio ei luo indeksejä tälle kokoelmalle.

#### Huomautukset {#notes}

* Gitean API ei voi tehdä committeja haaran ulkopuolelle kuten GitHubin. Synkronointi committaa suoraan synkronoituun haaraan, kun se voi edetä, ja muuten väliaikaiseen haaraan, joka yhdistetään sitten pull requestilla (`GitMerge.mjs:16-21`).
* Synkronointi ajetaan projektin `gitSync`-lukon alla, joka on yhteinen GitHub Syncin ja GitLab Syncin kanssa (`GitMerge.mjs:25-32`).
* Poistettu projekti säilyttää dokumenttinsa, kunnes projekti vanhenee.
* Käyttäjän Gitea-tunniste on kokoelmassa [Gitea Sync User Credentials](/fi/dev/data-model/gitea-sync-user-credentials-collection).
