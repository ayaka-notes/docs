`githubSyncProjectStates` sisältää yhden dokumentin jokaista GitHub-repositorioon linkitettyä projektia kohden: mikä repositorio on kyseessä ja mihin viimeisin synkronointi jäi. Kokoelma kuuluu web-moduuliin `github-sync` (`services/web/modules/github-sync`). Skeema on tiedostossa `services/web/modules/github-sync/app/models/githubSyncProjectStates.mjs`, ja kaikki käyttö kulkee `services/web/modules/github-sync/app/src/SyncStateManager.mjs` kautta.

#### Kuka kirjoittaa {#who-writes-it}

| Koodi | Mitä se tekee |
| ---- | ------------ |
| `SyncStateManager.mjs:9-14` (`createProjectState`) | Luo dokumentin: kun repositorio on tuotu uudeksi projektiksi (`services/web/modules/github-sync/app/src/GitHubSyncHandler.mjs:175-181`) tai kun projekti on viety uuteen repositorioon (`GitHubSyncHandler.mjs:235-241`, vain omistaja, hylätään jos projekti on jo linkitetty). |
| `SyncStateManager.mjs:16-21` (`updateProjectState`) | Muuttuneiden kenttien `$set`. `getMergeOverview` asettaa `mergeStatus: 'diverged'`, kun synkronoitu haara ei enää rakennu `lastSyncCommit`-commitin päälle: GitHubin compare vastaa `diverged` tai `behind` (`GitHubApiClient.mjs:382-400`), tai commit on kadonnut ja käyttäjä voi pushata (`GitHubSyncHandler.mjs:123,126-137`). Synkronointi (`services/web/modules/github-sync/app/src/GitMerge.mjs`) siirtää onnistuessaan `lastSyncCommit`/`lastSyncVersion`-arvoja (esimerkiksi `:143,173,224`), kirjaa konfliktin kenttiin `unmergedBranchName`, `unmergedBranchHead` ja `conflictVersion` (`:207-213`) ja tyhjentää ne, kun konflikti on ratkaistu (`:250-257`). |
| `SyncStateManager.mjs:23-25` (`removeProjectState`) | Poistaa dokumentin, kun omistaja poistaa projektin linkityksen (`GitHubSyncHandler.mjs:83-97`) ja kun poistettu projekti vanhenee (`services/web/modules/github-sync/index.mjs:56-58`). |

#### Kuka lukee {#who-reads-it}

| Koodi | Mitä se tekee |
| ---- | ------------ |
| `GitHubSyncHandler.mjs:39-60` (`getProjectState`) | Antaa editorille `mergeStatus`-, `repoFullName`- ja `unmergedBranchName`-arvot. Ilman dokumenttia se vastaa `need-export`, arvo, jota ei koskaan tallenneta. |
| `GitHubSyncHandler.mjs:110-143` (`getMergeOverview`) | Vertaa `lastSyncCommit`- ja `lastSyncVersion`-arvoja GitHub:iin ja projektihistoriaan uusien committien listaamiseksi. |
| `GitHubSyncHandler.mjs:200` (`exportProject`) | Kieltäytyy viemästä projektia, joka on jo linkitetty. |
| `GitMerge.mjs:27` (`doGitMergeWithoutLock`) | Lataa tilan synkronoinnin alussa. |

#### Indeksit {#indexes}

| Nimi | Avaimet | Asetukset | Migraatio |
| ---- | ---- | ------- | --------- |
| `_id_` | `_id: 1` | | default |

Mongoosen `autoIndex` on pois päältä (`services/web/app/src/infrastructure/Mongoose.mjs:7`), joten skeeman `unique: true` kentässä `projectId` ei luo mitään. `tools/migrations/20190912145010_create_githubSyncProjectStates_indexes.mjs` (upstreamin `project_id` ja `owner_id`) on merkitty vain tagilla `saas` eikä aja CE:ssä.

#### Huomautukset {#notes}

* Synkronointi ajetaan projektin `gitSync`-lukon alla (`GitMerge.mjs:17-24`). GitLab Sync ja Gitea Sync ottavat saman lukon, joten projektissa ajetaan kerrallaan vain yksi synkronointi.
* Poistettu projekti säilyttää dokumenttinsa, kunnes projekti vanhenee.
* Käyttäjän GitHub-tunniste on kokoelmassa [GitHub Sync User Credentials](/fi/dev/data-model/github-sync-user-credentials-collection).
