Olemme koonneet tähän vastauksia usein kysyttyihin kysymyksiin Ayakaleaf Prosta.

### Peruskysymykset

<Accordion title="K01: Onko Ayakaleaf Pro ilmainen kokeiluversio? Tarvitaanko siihen lisenssi?">

Ei. Ayakaleaf Pro on täysin ilmainen. Se ei ole kokeiluversio eikä vaadi lisenssiä.

</Accordion>

<Accordion title="K02: Sisältääkö Ayakaleaf Pro kaikki Overleaf Server Pron ominaisuudet?">

Kyllä. Ayakaleaf Pro sisältää kaikki Overleaf Server Pron ominaisuudet, mukaan lukien Git-Bridge-integraation. Lisäksi se sisältää valikoituja ominaisuuksia Overleafin SaaS-alustalta. Jatkamme Ayakaleaf Pron kehittämistä ja parantamista.

</Accordion>

<Accordion title="K03: Paljonko Overleaf Server Pro maksaa?">

Overleaf Server Pro maksaa noin \$300 käyttäjää kohden vuodessa. Se vaatii vähintään 10 lisenssiä, joten käyttöönotot alkavat noin \$3 000:sta vuodessa. Pienemmissä julkisissa yhdysvaltalaisissa sopimuksissa vuosikustannukset ovat noin \$320–\$370 käyttäjää kohden. Tämä tekee Server Prosta kalliin erityisesti pienille tiimeille. Dokumentoituja hankintoja ja hintoja on kohdassa [#information-and-price-about-overleaf-server-pro](/fi/on-premises#information-and-price-about-overleaf-server-pro  "mention").

</Accordion>

<Accordion title="K04: Miksi Overleaf Server Pro ei sisällä GitHub-synkronointia tai tekoälyominaisuuksia?">

Overleaf Server Prota käyttävät yleisesti julkishallinnon organisaatiot. Ne ottavat sen käyttöön yksityisissä verkoissa ja valvovat pääsyä tiukasti. Arkaluonteisten tietojen suojaamiseksi sen sisältämät ominaisuudet välttävät tietojen vaihtamista kolmansien osapuolten palveluiden kanssa. Jos tarvitset GitHub-synkronointia, tekoälyä tai vastaavia verkkoon kytkeytyviä ominaisuuksia, Overleaf suosittelee SaaS-alustansa tilausta.

</Accordion>

<Accordion title="K05: Onko Ayakaleaf Pro turvallinen ja luotettava?">

Ayakaleaf Pro on avointa lähdekoodia. Tarkastamme koodin Codex Securityn kaltaisilla työkaluilla sen tietoturvan ja luotettavuuden vahvistamiseksi. Jos et ota käyttöön kolmannen osapuolen tietojen synkronointia, tietosi pysyvät palvelimellasi. Ayakaleaf Pro ei sisällä telemetriaa, joka lähettäisi tietojasi muualle.

</Accordion>

<Accordion title="K06: Ylläpidetäänkö Ayakaleaf Prota pitkällä aikavälillä?">

Teemme parhaamme ylläpitääksemme tätä projektia pitkällä aikavälillä.

</Accordion>

<Accordion title="K07: Onko Ayakaleaf Pro säännösten mukainen?">

Ayakaleaf Pro on yhteisön ylläpitämä haara (fork). Sen koodi ja integroidut ominaisuudet ovat peräisin yhteisön kontribuutioista. Se on lisensoitu AGPL v3 -lisenssillä. Käyttöönotot voivat noudattaa tätä lisenssiä, kun ne täyttävät sen vaatimukset.

</Accordion>

<Accordion title="K08: Miksi projektin nimi on Ayakaleaf Pro?">

Projektin alkuperäinen nimi vuonna 2024 oli Overleaf Pro. Kehitys oli jonkin aikaa tauolla ja käynnistyi uudelleen loppuvuodesta 2025. Vuoden 2026 ensimmäisellä neljänneksellä Overleaf nimesi tekoälyä hyödyntävän tilauspakettinsa Proksi. Yhteisön palautteessa huomautettiin myös, että Overleaf Pro -nimi voisi aiheuttaa tavaramerkki- ja harhaanjohtamisriskejä. Se voisi saada käyttäjät luulemaan projektia viralliseksi.

Nimesimme projektin uudelleen Ayakaleaf Proksi tämän sekaannuksen välttämiseksi. Nimen voi lukea muodossa "Ayaka-notes Overleaf Pro". Ylläpitäjä (voit kutsua minua nimellä ayaka!) on osallistunut Overleaf-yhteisön kehitykseen opiskeluajoistaan lähtien, yli viiden vuoden ajan. Tämä kokemus tukee sitoutumistamme pitkäaikaiseen ylläpitoon.

</Accordion>

<Accordion title="K09: Mikä erottaa Ayakaleaf Pron uudemmista tekoälyllä rakennetuista LaTeX-editoreista?">

Vuodesta 2026 lähtien avoimen lähdekoodin yhteisö on julkaissut monia tekoälyllä rakennettuja LaTeX-editoreja, kuten OpenAI Prismin. Ayakaleaf Pro pitää tietosi ja palvelusi omalla palvelimellasi. Näin hallitset käyttöönottoasi ja tietojasi suoraan.

Monilla kokeellisilla yhteisön editoreilla ei ole vakiintunutta pitkän aikavälin ylläpitosuunnitelmaa. Kolmansien osapuolten LaTeX-käännösalustat voivat myös lopettaa toimintansa, jos niiden käyttäjäkunta tai tulot eivät riitä. Ayakaleaf Pro toimittaa kaiken lähdekoodin ja antaa sinun isännöidä jokaista palvelua itse. Vaikka ylläpito loppuisi, olemassa oleva itse isännöity palvelusi voisi jatkaa toimintaansa.

</Accordion>

### Ominaisuudet

<Accordion title="K01: Mitä ominaisuuksia Ayakaleaf Pro tarjoaa? Voinko pyytää uutta ominaisuutta?">

Katso ajantasainen ominaisuusluettelo dokumentaatiostamme. Jos haluaisit meidän lisäävän jonkin ominaisuuden, avaa rohkeasti issue (ominaisuuspyyntö) GitHubissa. Teemme parhaamme toteuttaaksemme pyydetyt ominaisuudet, mutta kehitys vie aikaa, emmekä voi taata, että jokainen ominaisuus toimitetaan heti.

</Accordion>

<Accordion title="K02: Olen kehittänyt joitakin ominaisuuksia. Voinko lähettää PR:n, ja hyväksytäänkö se varmasti?">

Kontribuutiot ovat tervetulleita, mutta hyväksyntää ei taata. Arvioimme jokaisen PR:n sen perusteella, miten se vaikuttaa taustalla olevaan Overleaf-koodikantaan, millainen ylläpitotaakka siitä aiheutuu ja mitä arvoa se tuo käyttäjille. Teemme parhaamme yhdistääksemme ja ylläpitääksemme arvokkaita kontribuutioita.

Voimme kuitenkin hylätä PR:t, jotka tuovat liikaa muutoksia, koostuvat tarkastamattomasta tai huonosti ymmärretystä tekoälyn tuottamasta koodista ("vibe coding") tai lisäävät ominaisuuksia, joita olisi vaikea ylläpitää pitkällä aikavälillä.

</Accordion>

<Accordion title="K03: Miten määritän tietyn ominaisuuden?">

Päivitämme yleensä dokumentaation aina, kun julkaisemme uuden ominaisuuden. Katso tarkat määritysohjeet ja käytettävissä olevien ympäristömuuttujien selitykset asiaankuuluvasta dokumentaatiosta.

</Accordion>

<Accordion title="K04: Mitä Python-kirjastoja Python Runner voi käyttää?">

Python Runner ajaa Pythonia käyttäjän selaimessa [Pyodiden](https://pyodide.org/) versiolla 0.29.3, ei palvelimella. Se lataa koodisi tuomat paketit [Pyodideen sisäänrakennetuista paketeista](https://pyodide.org/en/0.29.3/usage/packages-in-pyodide.html), kuten NumPy, pandas ja Matplotlib. `pip`-komennolla asennetut ja muut paketit eivät ole käytettävissä. Palvelimella ei tarvitse määrittää mitään.

</Accordion>

<Accordion title="K05: Voiko oikeinkirjoituksen tarkistus tarkistaa japania tai kiinaa?">

Ei. Oikeinkirjoituksen tarkistimessa ei ole sanakirjaa japanille tai kiinalle, joten nämä kielet eivät ole oikeinkirjoituksen tarkistuksen kieliluettelossa. Käyttäjät voivat poistaa oikeinkirjoituksen tarkistuksen käytöstä projektikohtaisesti editorin asetuksissa.

</Accordion>

### Käyttöönotto

<Accordion title="K01: Tukeeko Ayakaleaf Pro hajautettua käyttöönottoa k8s:ssä?">

Suosittelemme useimmille käyttäjille käyttöönottoa [Toolkitin](/fi/on-premises/installation/using-the-toolkit) avulla. Emme suosittele laajamittaisia klusterikäyttöönottoja Kubernetesilla tai vastaavilla alustoilla, koska ne voivat lisätä merkittävästi operatiivista monimutkaisuutta ja ylläpitotyötä.

</Accordion>

<Accordion title="K02: Miten voin varmistaa saatavuuden, kun palvelen tuhansia käyttäjiä?">

Katso [horisontaalisen skaalauksen](/fi/on-premises/maintenance/horizontal-scaling) opas. Voit ottaa käyttöön useita Overleaf-instansseja ja määrittää kuormantasaajan jakamaan liikenteen niiden kesken.

</Accordion>

<Accordion title="K03: Voitteko auttaa minua käyttöönotossa tai siirrossa?">

Jos sinulla on olemassa oleva Overleaf Server Pro -instanssi, autamme mielellämme siirtymään Ayakaleaf Proon. Ota yhteyttä sähköpostitse tai issueiden kautta.

</Accordion>

<Accordion title="K04: Voinko isännöidä Ayakaleaf Prota URL-alipolussa, kuten `https://example.com/overleaf`?">

Et. Ayakaleaf Prota on tarjottava verkkotunnuksen juuresta. Käytä omaa verkkotunnusta tai aliverkkotunnusta, kuten `https://overleaf.example.com`.

</Accordion>

<Accordion title="K05: Voinko ajaa Ayakaleaf Prota Windowsissa tai macOS:ssä tai ilman Toolkitia?">

Tuemme Linux-palvelimia [Toolkitin](/fi/on-premises/installation/using-the-toolkit) kanssa. Docker Desktop Windowsissa, WSL2:ssa tai macOS:ssä saattaa toimia, mutta emme testaa sitä; katso tunnettu MongoDB-ongelma sivulta [Vianmääritys](/fi/on-premises/support/troubleshooting).

Emme tarjoa erillistä `docker-compose.yml`-tiedostoa. Näet Toolkitin käyttämän Compose-konfiguraation ajamalla Toolkit-hakemistossa komennon `bin/docker-compose config`.

</Accordion>

<Accordion title="K06: Miten poistan Ayakaleaf Pron asennuksen?">

Asennuksen poistoskriptiä ei ole. Toimi Toolkit-hakemistossa seuraavasti:

1. Pysäytä ja poista kontit komennolla `bin/docker-compose down`.
2. Poista data. Oletuksena se on Toolkitin `data/`-hakemistossa. Jos muutit `OVERLEAF_DATA_PATH`-, `MONGO_DATA_PATH`-, `REDIS_DATA_PATH`- tai `GIT_BRIDGE_DATA_PATH`-arvoa tiedostossa `config/overleaf.rc`, poista myös nämä hakemistot. Tätä ei voi perua, joten [varmuuskopioi](/fi/on-premises/maintenance/data-and-backups) ensin, jos saatat tarvita dataa.
3. Poista Toolkit-hakemisto.
4. Poista Docker-imaget, jotka voit luetella komennolla `docker images`: `ghcr.io/ayaka-notes/overleaf-pro`, git-bridge-image, `mongo`, `redis` ja TeX Live -imaget.

</Accordion>

<Accordion title="K07: Miten pysäytän, käynnistän tai käynnistän uudelleen Ayakaleaf Pron?">

Aja nämä Toolkit-hakemistossa:

* `bin/stop` pysäyttää kaikki kontit, `bin/start` käynnistää ne uudelleen. Kontit säilyvät, joten käyttäjät pysyvät kirjautuneina.
* `bin/up -d` luo kontit ja käynnistää ne taustalla. Aja se, kun olet muuttanut tiedostoa `config/variables.env`, `config/overleaf.rc` tai `config/version`: se luo uudelleen kontit, joiden konfiguraatio on muuttunut, ja vasta silloin muutokset tulevat voimaan. `bin/stop` ja `bin/start` eivät ota niitä käyttöön.
* `bin/docker-compose restart sharelatex` käynnistää uudelleen vain Overleaf-kontin ottamatta konfiguraatiomuutoksia käyttöön.

Jos käyttäjät kirjataan ulos aina, kun `bin/up` luo kontin uudelleen, aseta `OVERLEAF_SESSION_SECRET`, katso kysymykset ja vastaukset sivulla [Ympäristömuuttujat](/fi/on-premises/configuration/overleaf-toolkit/environment-variables).

</Accordion>

<Accordion title="K08: Mihin OAuth-takaisinkutsun URL-osoite asetetaan?">

Palveluntarjoajalla luomaasi sovellukseen, ei Ayakaleaf Prohon. Tiedostossa `config/variables.env` ei ole takaisinkutsuasetusta yhdellekään näistä integraatioista: Ayakaleaf Pro muodostaa jokaisen takaisinkutsu-URL-osoitteen `OVERLEAF_SITE_URL`-muuttujasta ja lähettää sen palveluntarjoajalle, joka hylkää sen, ellei se vastaa sovellukselle rekisteröityä osoitetta. Rekisteröit sen siis vain palveluntarjoajalla ja asetat `OVERLEAF_SITE_URL`-muuttujaan osoitteen, jonka käyttäjät avaavat.

| Integraatio | Kenttä palveluntarjoajalla | Arvo |
| --- | --- | --- |
| [GitHub](/fi/on-premises/configuration/overleaf-toolkit/github-synchronisation) | Authorization callback URL | `${OVERLEAF_SITE_URL}/user/github-sync/oauth2/callback` |
| [GitLab](/fi/on-premises/configuration/overleaf-toolkit/gitlab-synchronisation) | Redirect URI | `${OVERLEAF_SITE_URL}/user/gitlab-sync/oauth2/callback` |
| [Gitea](/fi/on-premises/configuration/overleaf-toolkit/gitea-synchronisation) | Redirect URIs | `${OVERLEAF_SITE_URL}/user/gitea-sync/oauth2/callback` |
| [Dropbox](/fi/on-premises/configuration/overleaf-toolkit/dropbox-synchronisation) | Redirect URIs (napsauta **Add**) | `${OVERLEAF_SITE_URL}/user/dropbox/oauth/callback` |
| [Zotero](/fi/on-premises/configuration/overleaf-toolkit/zotero-integration) | Callback URL | `${OVERLEAF_SITE_URL}/user/zotero/oauth/callback` |
| [Mendeley](/fi/on-premises/configuration/overleaf-toolkit/mendeley-integration) | Redirect URL | `${OVERLEAF_SITE_URL}/user/mendeley/oauth/callback` |
| [OIDC-kirjautuminen](/fi/on-premises/configuration/overleaf-toolkit/authentication/oidc-authentication) | Redirect URI | `${OVERLEAF_SITE_URL}/oidc/login/callback` |
| [SAML-kirjautuminen](/fi/on-premises/configuration/overleaf-toolkit/authentication/saml-authentication) | ACS URL (Assertion Consumer Service) | `${OVERLEAF_SITE_URL}/saml/login/callback` |

Jos muutat `OVERLEAF_SITE_URL`-arvoa, esimerkiksi uuteen verkkotunnukseen, päivitä URL-osoite myös jokaisella palveluntarjoajalla, muuten linkittäminen epäonnistuu.

</Accordion>

### LaTeX

<Accordion title="K01: Ovatko käyttäjien LaTeX-projektien käännökset eristettyjä? Onko Shell Escape käytössä?">

Kun otat käyttöön Sandbox Compiles -toiminnon, kunkin käyttäjän käännös ajetaan erillisessä Docker-kontissa ja se on eristetty muiden käyttäjien käännöksistä. Shell Escape on oletuksena käytössä Sandbox Compiles -käännöksissä.

</Accordion>

<Accordion title="K02: Onko Sandbox Compiles -image luotettava? Voiko kääntäminen epäonnistua?">

Olemme parantaneet Sandbox Compiles -toiminnon TeX Live Full -imagea kolmen viime vuoden ajan. Useimmissa tapauksissa projektit, jotka kääntyvät overleaf.comissa, kääntyvät oikein myös Ayakaleaf Prolla. Jos tarvittava fontti ei ole saatavilla, lataa fontti projektiisi manuaalisesti.

</Accordion>

<Accordion title="K03: Projektini ei käänny. Voitteko auttaa minua selvittämään ongelman?">

Lataa projektisi viralliselle Overleaf-sivustolle, ota käyttöön vain luku -oikeuden linkkijako ja liitä linkki GitHub-issueen.

Tutkimme ja korjaamme kaikki bugit, jotka estävät projektia kääntymästä Ayakaleaf Prossa, kun se kääntyy onnistuneesti virallisella Overleaf-sivustolla. Tämän ulkopuoliset käännösongelmat eivät kuulu tukemme piiriin.

</Accordion>
