Jokaisella projektilla on oma MCP-palvelimensa, joten tietokoneesi tekoälyasiakasohjelma voi lukea ja muokata projektia, kääntää sen ja vastata sen kommentteihin. Asiakasohjelma kirjautuu Git-todennustunnuksella.

<Info>

Jos et näe **MCP server** -korttia, ohjaa ylläpitäjä sivulle [MCP-palvelin](/fi/on-premises/configuration/overleaf-toolkit/integrations/mcp-server).

</Info>

## Uutta versiossa v6.3.3 {#new-in-v6-3-3}

Versiosta v6.3.3 alkaen asiakasohjelma voi käsitellä myös projektin historiaa: listata muutokset, verrata kahta versiota, lukea tiedoston sellaisena kuin se oli, tallentaa ja poistaa versioita sekä palauttaa tiedoston tai koko projektin. Se voi listata seuratut muutokset ja hyväksyä tai hylätä ne, ja tehdä omista muokkauksistaan seurattuja muutoksia, kun pyydät. Se voi kommentoida tekstinkohtaa, muokata ja poistaa kommenttiviestejä, lukea ja lähettää viestejä projektin keskustelussa, siirtää ja nimetä uudelleen tiedostoja ja kansioita, luoda kansioita ja vaihtaa oikeinkirjoituksen tarkistuksen kielen. Se, kuka saa tehdä mitä, määräytyy roolisi mukaan projektissa samoin kuin editorissa, koska asiakasohjelma toimii tunnuksellasi: katso [Kuka saa tehdä mitä](#who-may-do-what).

MCP-palvelin otettiin käyttöön versiossa v6.3.1. Versioissa v6.3.1 ja v6.3.2 on samat 17 työkalua; versiossa v6.3.3 niitä on 33.

| Työkalut | v6.3.1 ja v6.3.2 | v6.3.3 |
| ----- | ----------------- | ------ |
| `get_clone_info`, `get_settings`, `list_files`, `delete_file`, `compile`, `get_compile_log`, `get_output_file_link`, `word_count`, `reply_to_comment`, `resolve_comment`, `reopen_comment` | Kyllä | Kyllä, ennallaan |
| `read_file` | Uusin sisältö | Myös tiedosto sellaisena kuin se oli tietyssä `version`-versiossa |
| `edit_file`, `write_file` | Noudattavat projektin muutosten seurannan asetusta | Myös `trackChanges`, jolla muokkauksesta tulee seurattu muutos |
| `update_settings` | Kääntäjä, TeX Live -levykuva ja päädokumentti | Myös oikeinkirjoituksen tarkistuksen kieli |
| `list_versions` | Versio, kommentti ja päivämäärä | Myös `id`, jonka `delete_version` ottaa, ja kuka version tallensi |
| `list_comments` | Viestit ilman id:tä | Myös jokaisen viestin `id`, jonka `edit_comment_message` ja `delete_comment_message` ottavat |
| `list_changes`, `diff`, `create_version`, `delete_version`, `restore_file`, `restore_project`, `list_tracked_changes`, `accept_tracked_changes`, `reject_tracked_changes`, `add_comment`, `edit_comment_message`, `delete_comment_message`, `list_chat_messages`, `send_chat_message`, `move_file`, `create_folder` | Ei | Kyllä |

## Asiakasohjelman yhdistäminen {#connect-a-client}

<Steps>
<Step title="Avaa valintaikkuna">
Avaa projekti. Napsauta vasemmassa palkissa **Integrations** ja sitten **MCP server**.

<Frame caption="Integrations-paneeli">
  <img src="/images/on-premises/mcp-server-integrations.png" alt="Integrations-paneeli ja MCP server -kortti" />
</Frame>

Valintaikkunassa näkyvät tämän projektin palvelimen osoite ja välilehti jokaiselle asiakasohjelmalle: **Claude Code**, **Codex**, **Cursor**, **VS Code** ja **Gemini CLI**.

<Frame caption="MCP server -valintaikkuna">
  <img src="/images/on-premises/mcp-server-dialog.png" alt="MCP server -valintaikkuna: osoite, välilehti jokaiselle asiakasohjelmalle ja Claude Coden komento" />
</Frame>
</Step>

<Step title="Luo tunnus">
Napsauta **Go to settings**. Tilisi asetukset avautuvat uudelle välilehdelle. Napsauta **Git integration** -kohdassa **Generate token** tai **Add another token**, jos sinulla on jo tunnus. Napsauta **Copy** ja säilytä tunnus turvallisessa paikassa, koska näet sen vain kerran. Napsauta sitten **Close**.

<Frame caption="Uusi tunnuksesi">
  <img src="/images/on-premises/mcp-server-token.png" alt="Git authentication token -valintaikkuna ja Copy-painike" />
</Frame>

Myös tunnus, jota käytät jo [Git-integraatioon](/fi/on-premises/user-guide/users/git-integration), toimii, ja samaa tunnusta voi käyttää kaikissa projekteissasi.
</Step>

<Step title="Lisää palvelin asiakasohjelmaan">
Palaa valintaikkunaan, napsauta asiakasohjelmasi välilehteä ja sitten määrityksen vieressä olevaa **Copy**-painiketta.

| Välilehti | Minne se menee | Tunnus |
| --- | ------------- | --------- |
| **Claude Code** | Suorita komento päätteessä | Korvaa komennon `<token>` |
| **Codex** | `~/.codex/config.toml` | Aseta se ympäristömuuttujaan `OVERLEAF_TOKEN` |
| **Cursor** | `~/.cursor/mcp.json` | Aseta se ympäristömuuttujaan `OVERLEAF_TOKEN` |
| **VS Code** | `.vscode/mcp.json` | Tiedostossa on tunnuksen sijaan salasanakehote nimeltä `overleaf-token` |
| **Gemini CLI** | Suorita komento päätteessä | Korvaa komennon `<token>` |

Osoite kuuluu yhdelle projektille. Jos haluat yhdistää toisen projektin, lisää se eri nimellä, koska `overleaf` on jo käytössä. Esimerkiksi Claude Codessa vaihda komennon `overleaf` muotoon `overleaf-lab`.
</Step>
</Steps>

## Yhteyden tarkistaminen {#check-the-connection}

### Claude Codella {#with-claude-code}

```bash
claude mcp list
```

Palvelin näkyy yhdistettynä:

```text
overleaf: https://<your-site>/project/<project-id>/mcp (HTTP) - ✔ Connected
```

### curlilla {#with-curl}

Tämä toimii asiakasohjelmasta riippumatta. Korvaa osoite ja tunnus ja lähetä MCP-protokollan `initialize`-pyyntö:

```bash
curl -X POST https://<your-site>/project/<project-id>/mcp \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -H "Accept: application/json, text/event-stream" \
  -d '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2025-06-18","capabilities":{},"clientInfo":{"name":"curl","version":"1.0"}}}'
```

Vastauksessa on palvelimen nimi ja sen jälkeen palvelimen ohjeet asiakasohjelmille:

```json
{"result":{"protocolVersion":"2025-06-18","capabilities":{"tools":{"listChanged":true}},"serverInfo":{"name":"overleaf","version":"1.0.0"},"instructions":"This server works on one Overleaf project. ..."},"jsonrpc":"2.0","id":1}
```

Nähdäksesi työkalut lähetä `tools/list` samalla komennolla. Vastaus listaa 33 työkalua, tai 31, jos sivustollasi projektin keskustelu on poistettu käytöstä. Ennen versiota v6.3.3 niitä on 17.

```bash
  -d '{"jsonrpc":"2.0","id":2,"method":"tools/list","params":{}}'
```

Kutsu työkalua lähettämällä `tools/call`:

```bash
  -d '{"jsonrpc":"2.0","id":3,"method":"tools/call","params":{"name":"list_files","arguments":{}}}'
```

```json
{"result":{"content":[{"type":"text","text":"[\n  {\n    \"path\": \"main.tex\",\n    \"type\": \"doc\"\n  }\n]"}]},"jsonrpc":"2.0","id":3}
```

### Jos yhteys ei muodostu {#if-it-does-not-connect}

| Mitä näet | Mitä se tarkoittaa |
| ------------ | ------------- |
| Tila `401` tai Claude Codessa `✘ Failed to connect` ja `HTTP 401` | Tunnus puuttuu, on väärä tai poistettu |
| Tila `404` | Millään projektilla ei ole tätä tunnistetta |
| Tila `405` | Pyyntö ei ollut `POST` |
| Tila `406` ja `Not Acceptable` | `Accept`-otsake puuttuu: asiakasohjelman on hyväksyttävä sekä `application/json` että `text/event-stream` |

## Mitä näet, kun asiakasohjelma työskentelee {#what-you-see-when-a-client-works}

Muokkaukset näkyvät avoimessa editorissa sitä mukaa kuin asiakasohjelma tekee niitä, kuten yhteistyökumppanin muokkaukset, ilman uudelleenlatausta. Uudet tiedostot ja kansiot, siirrot ja uudelleennimeämiset näkyvät tiedostopuussa.

<Frame caption="edit_file-työkalun lisäämä rivi">
  <img src="/images/on-premises/mcp-server-live-edit.png" alt="Editori näyttää edit_file-työkalun lisäämän rivin ilman valintaikkunaa ja uudelleenlatausta" />
</Frame>

`edit_file` muuttaa vain tekstiä, joka esiintyy täsmälleen kerran. Muuten asiakasohjelma saa virheen, kuten `oldString not found in main.tex, read_file again` tai `oldString appears 2 times in main.tex, add context`, eikä mikään muutu.

Versiosta v6.3.3 alkaen `move_file` siirtää tai nimeää uudelleen tiedoston tai kansion ja luo tarvittaessa uuden polun kansiot, ja `create_folder` luo kansion. Jos tiedostoa ei löydy tai uusi polku on jo olemassa, asiakasohjelma saa virheen eikä mikään muutu. `update_settings` voi myös vaihtaa oikeinkirjoituksen tarkistuksen kielen, esimerkiksi `de`, tai poistaa tarkistuksen käytöstä.

Vastaukset kommentteihin näkyvät tarkistuspaneelissa sinun nimelläsi, koska tunnus on sinun. Palvelimen kautta ratkaistu kommentti poistuu paneelista, ja sen avaaminen uudelleen tuo sen takaisin.

<Frame caption="reply_to_comment-työkalun lähettämä vastaus">
  <img src="/images/on-premises/mcp-server-comment.png" alt="Kommentti tarkistuspaneelissa ja reply_to_comment-työkalun lähettämä vastaus" />
</Frame>

Versiosta v6.3.3 alkaen `add_comment` kommentoi tekstinkohtaa. Tekstin on esiinnyttävä tiedostossa täsmälleen kerran; jos se esiintyy useammin, asiakasohjelma antaa myös sitä ympäröivän pidemmän kohdan, joka esiintyy kerran, ja vain itse teksti kommentoidaan. Kommentti näkyy tarkistuspaneelissa sinun nimelläsi ja pysyy tekstissään, kun tiedosto muuttuu. `edit_comment_message` muuttaa yhtä omista viesteistäsi. `delete_comment_message` poistaa viestin, ja ensimmäisen poistaminen poistaa koko kommentin, kuten tarkistuspaneelissa.

`compile` kääntää projektin ja palauttaa tulostiedostojen luettelon. Sen jälkeen `get_output_file_link` antaa linkin PDF:n tai muun tulostiedoston lataamiseen. Linkki ei tarvitse tunnusta ja lakkaa toimimasta 5 minuutin kuluttua.

Koko työkaluluettelon löydät kohdasta [Tools](/on-premises/configuration/overleaf-toolkit/integrations/mcp-server#tools).

## Seuratut muutokset {#tracked-changes}

Versiosta v6.3.3 alkaen voit pyytää asiakasohjelmaa tekemään muokkauksistaan seurattuja muutoksia, esimerkiksi *Rewrite the abstract as a tracked change*. Silloin `edit_file` ja `write_file` tekevät olemassa olevan tiedoston muutoksesta seuratun muutoksen sinun nimelläsi, vaikka muutosten seuranta olisi projektissa pois päältä, ja sinä hyväksyt tai hylkäät sen tarkistuspaneelissa. Uusi tiedosto ei ole koskaan seurattu muutos. Jos et pyydä, muokkaukset noudattavat projektin muutosten seurannan asetusta, kuten omasi editorissa: niitä seurataan, kun seuranta on päällä sinulle tai kaikille.

Jos projektin omistajan tilillä ei ole muutosten seurantaa, asiakasohjelma saa viestin `Track changes is off for this project` eikä mikään muutu.

Jos haluat tarkistaa jokaisen asiakasohjelman muokkauksen, ota muutosten seuranta käyttöön itsellesi. Jos haluat erottaa sen muokkaukset omistasi tarkistuspaneelissa, anna asiakasohjelmalle toisen tilin tunnus, jonka kanssa jaat projektin.

`list_tracked_changes` listaa seuratut muutokset tiedoston, lisätyn tai poistetun tekstin, tekijän ja ajan kanssa. `accept_tracked_changes` ja `reject_tracked_changes` ottavat muutosten id:t ja toimivat kuten tarkistuspaneeli: hyväksytty muutos jää tekstiin, hylätty lisäys poistetaan ja hylätty poisto palaa. Avoin editori näyttää tuloksen ilman uudelleenlatausta. Työkalut ohjeistavat asiakasohjelmaa hyväksymään tai hylkäämään vain pyytämäsi muutokset.

## Historia {#history}

Versiosta v6.3.3 alkaen asiakasohjelma näkee projektin historian samoin kuin historiapaneeli sen näyttää.

| Työkalu | Mitä se tekee |
| ---- | ------------ |
| `list_changes` | Listaa muutokset uusimmasta alkaen: kuka muutti mitä tiedostoja ja milloin, sekä versiot ennen jokaista muutosta ja sen jälkeen. Vanhemmat muutokset tulevat seuraavissa erissä. |
| `diff` | Vertaa kahta versiota: yhden tiedoston unified diff -muodossa, kuten `git diff`, tai lisätyt, poistetut, muokatut tai uudelleennimetyt tiedostot |
| `read_file` ja `version` | Lukee tiedoston sellaisena kuin se oli tietyssä versiossa |
| `list_versions` | Listaa tallennetut versiot kommentteineen ja tallentajineen |
| `create_version` | Tallentaa uusimman tai aiemman version kommentin kanssa, kuten **Label this version** |
| `delete_version` | Poistaa tallennetun version; sen muutokset säilyvät |
| `restore_file` | Palauttaa tiedoston sellaiseksi kuin se oli tietyssä versiossa, kuten **Restore this version** |
| `restore_project` | Palauttaa koko projektin sellaiseksi kuin se oli tietyssä versiossa, kuten **Restore project to this version** |

Palautus on itsessään uusi muutos, joten voit kumota sen samalla tavalla. Työkalut ohjeistavat asiakasohjelmaa palauttamaan vain, kun pyydät.

Jos projektin omistajalla ei ole täyttä projektihistoriaa, asiakasohjelma näkee vain viimeisten 24 tunnin muutokset tai uusimman muutoksen, jos kaikki ovat vanhempia, kuten historiapaneelissa. Se ei voi verrata, lukea tai palauttaa vanhempia versioita.

## Projektin keskustelu {#project-chat}

Versiosta v6.3.3 alkaen `list_chat_messages` lukee projektin keskustelua uusimmasta alkaen 50 viestiä kerrallaan. `send_chat_message` lähettää viestin sinun nimelläsi, ja se näkyy heti avoimessa keskustelussa. Jos sivustollasi projektin keskustelu on poistettu käytöstä, asiakasohjelmalla ei ole kumpaakaan työkalua.

## Kuka saa tehdä mitä {#who-may-do-what}

Asiakasohjelma saa tehdä sen, minkä roolisi projektissa sallii.

| Mitä asiakasohjelma tekee | Omistaja | Muokkaaja | Tarkastaja | Katselija (nimetty yhteistyökumppani) | Katselija (linkkijako) |
| -------------------- | ----: | -----: | -------: | --------------------------: | --------------------: |
| Lukea tiedostoja ja asetuksia, kääntää, lukea lokia, ladata PDF:n | Kyllä | Kyllä | Kyllä | Kyllä | Kyllä |
| Kirjoittaa, muokata, siirtää ja poistaa tiedostoja, luoda kansioita, muuttaa asetuksia | Kyllä | Kyllä | Ei | Ei | Ei |
| Nähdä historian, kommentit ja seuratut muutokset | Kyllä | Kyllä | Kyllä | Kyllä | Ei |
| Lukea ja lähettää keskusteluviestejä | Kyllä | Kyllä | Kyllä | Kyllä | Ei |
| Lisätä kommentteja ja vastata niihin | Kyllä | Kyllä | Kyllä | Ei | Ei |
| Ratkaista, avata uudelleen tai poistaa kommentin | Kyllä | Kyllä | Itse aloittamansa | Ei | Ei |
| Muokata kommenttiviestiä | Omat | Omat | Omat | Ei | Ei |
| Poistaa kommenttiviestin | Kyllä | Kyllä | Omat | Ei | Ei |
| Hyväksyä tai hylätä seurattuja muutoksia | Kyllä | Kyllä | Ei | Ei | Ei |
| Tallentaa version | Kyllä | Kyllä | Kyllä | Ei | Ei |
| Poistaa tallennetun version | Kyllä | Itse tallentamansa | Itse tallentamansa | Ei | Ei |
| Palauttaa tiedoston tai projektin | Kyllä | Kyllä | Ei | Ei | Ei |

Linkin kautta liittyneet muokkaajat lasketaan muokkaajiksi. Tarkastajat eivät voi muokata tiedostoja MCP:n kautta, eivät edes seurattuina muutoksina.

## Asiakasohjelman yhteyden katkaiseminen {#disconnect-a-client}

Poista tunnus: katso [Tunnuksen poistaminen](/fi/on-premises/user-guide/users/git-integration#delete-a-token). Siitä lähtien palvelin vastaa tälle tunnukselle `401`. Jos käytät sitä myös Gitissä, myös Git lakkaa hyväksymästä sitä.
