Työskentele projektin parissa omalla tietokoneellasi Gitin avulla. Muutokset siirtyvät vain, kun suoritat `git pull`- tai `git push`-komennon.

<Info>

Ylläpitäjän on ensin otettava [Git-integraatio](/fi/on-premises/configuration/overleaf-toolkit/integrations/git-integration) käyttöön.

</Info>

## Tunnuksen luominen {#create-a-token}

Git kirjautuu Gitin todennustunnuksella, ei tilisi salasanalla.

<Steps>
<Step title="Avaa tilisi asetukset">
Valitse **Account** ja sitten **Account settings**. Valitse **Git integration** -kohdassa **Generate token**. Kun sinulla on tunnus, tämän painikkeen nimi on **Add another token**.

<Frame caption="Git-integraatio tilin asetuksissa">
  <img src="/images/on-premises/git-integration-settings.png" alt="Tilin asetusten Git integration -osio ja Generate token -painike" />
</Frame>
</Step>

<Step title="Kopioi tunnus">
Valitse **Copy** ja säilytä tunnus turvallisessa paikassa. Näet sen vain kerran. Valitse sitten **Close**.

<Frame caption="Uusi tunnuksesi">
  <img src="/images/on-premises/git-integration-token.png" alt="Gitin todennustunnuksen valintaikkuna ja Copy-painike" />
</Frame>
</Step>

<Step title="Tarkista tunnus">
Luettelossa näkyy nyt tunnuksen alku, sen luontiaika ja viimeisin käyttöaika. Tunnus vanhenee vuoden kuluttua. Sinulla voi olla enintään 10 tunnusta.

<Frame caption="Tunnuksesi">
  <img src="/images/on-premises/git-integration-tokens.png" alt="Tunnusluettelo, jossa on yksi tunnus" />
</Frame>
</Step>
</Steps>

## Projektin kloonaaminen {#clone-a-project}

<Steps>
<Step title="Avaa Git-integraatio editorissa">
Avaa projekti. Valitse vasemmasta palkista **Integrations** ja sitten **Git integration**.

<Frame caption="Integrations-paneeli">
  <img src="/images/on-premises/git-integration-panel.png" alt="Integrations-paneeli ja Git integration -kortti" />
</Frame>
</Step>

<Step title="Kopioi komento">
**Clone with Git** -valintaikkuna näyttää komennon, jossa on sivustosi osoite ja projektin tunnus. Valitse **Copy**. Jos sinulla ei vielä ole tunnusta, **Go to settings** avaa tilisi asetukset uudessa välilehdessä.

<Frame caption="Kloonauskomento">
  <img src="/images/on-premises/git-integration-clone.png" alt="Clone with Git -valintaikkuna ja git clone -komento" />
</Frame>
</Step>

<Step title="Suorita komento">
Liitä komento päätteeseen. Kun Git pyytää salasanaa, liitä tunnuksesi.

```text
$ git clone https://git@<your-site>/git/<project-id>
Cloning into '<project-id>'...
Password for 'https://git@<your-site>': <your-token>
```

Projektin tunnuksen mukaan nimetyssä kansiossa ovat nyt projektin tiedostot `main`-haarassa. Jos haluat valita kansion nimen, lisää se komennon loppuun.
</Step>
</Steps>

Git kysyy tunnusta aina, kun se ottaa yhteyden sivustoon. Jotta tunnus muistetaan, ota käyttöön credential helper: Git kysyy vielä kerran ja säilyttää sitten tunnuksen. `store`-helper tallentaa sen salaamattomana tiedostoon `~/.git-credentials`.

```bash
git config --global credential.helper store
```

## Muutosten hakeminen editorista {#pull-changes-from-the-editor}

Suorita kansiossa:

```bash
git pull
```

Git luettelee muuttuneet tiedostot. Editorissa tehdyt muutokset saapuvat committeina, joiden nimi on `Update on Overleaf.`.

```text
Updating db007e3..c3e6332
Fast-forward
 main.tex | 2 +-
 1 file changed, 1 insertion(+), 1 deletion(-)
```

## Muutosten lähettäminen {#push-your-changes}

Tee muutoksistasi commit ja lähetä ne:

```bash
git add main.tex
git commit -m "Add a line from Git"
git push
```

Tulosteen viimeinen rivi näyttää haaran, joka siirtyi:

```text
   53aca61..db007e3  main -> main
```

Muutokset näkyvät editorissa, ja avoinna oleva editori päivittyy itsestään. Uudet tiedostot, kansiot ja uudelleennimeämiset näkyvät tiedostopuussa. **History**-näkymässä muutoksesi on merkitty <strong>You (via Git)</strong>. Commit-viestiäsi ei näytetä siellä.

### Jos Git hylkää pushin {#if-git-refuses-your-push}

Jos projekti on muuttunut sillä välin, Git hylkää pushin:

```text
 ! [rejected]        main -> main (fetch first)
```

Hae ensin nuo muutokset ja lähetä sitten uudelleen:

```bash
git pull --no-rebase --no-edit
git push
```

Pelkkä `git pull` voi pysähtyä viestiin `fatal: Need to specify how to reconcile divergent branches.` Yllä oleva `--no-rebase`-valinta ratkaisee tämän: se yhdistää molemmat puolet.

Jos samat rivit ovat muuttuneet molemmilla puolilla, pull pysähtyy viestiin `CONFLICT (content): Merge conflict in main.tex`. Korjaa tiedosto ja suorita sitten:

```bash
git add main.tex
git commit -m "Merge the changes from the editor"
git push
```

Sivusto ei hyväksy kahta asiaa:

* Muut haarat: `! [remote rejected] feature -> feature (wrong branch)`. Vain `main` on olemassa, joten lähetä työsi sinne.
* Pakotettu push: `! [remote rejected] main -> main (forced push prohibited)`. Lisää muutoksesi sen sijaan nykyisen `main`-haaran päälle.

### Jos Git ilmoittaa Authentication failed {#if-git-says-authentication-failed}

```text
remote: Enter your Git authentication token when prompted for a password.
fatal: Authentication failed for 'https://<your-site>/git/<project-id>/'
```

Tunnus on väärä tai poistettu, tai syötit tilisi salasanan. Luo uusi tunnus, jos sinulla ei enää ole sitä, koska olemassa olevaa tunnusta ei voi nähdä uudelleen.

## Tunnuksen poistaminen {#delete-a-token}

Valitse **Account settings** -kohdan **Git integration** -osiossa tunnuksen vieressä oleva poistokuvake ja sitten valintaikkunassa **Delete**. Sen jälkeen Git vastaa tälle tunnukselle `Authentication failed`.
