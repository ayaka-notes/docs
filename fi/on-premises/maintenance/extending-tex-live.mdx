Olemassa olevaa TeX Live -imagea on mahdollista laajentaa uudella Dockerfilellä ja määrittää sovellus käyttämään uutta imagea.

Tässä on ohjeita uusien pakettien tai fonttien asentamiseen.

TeX Live -imageja päivitetään harvoin. Suosittelemme mukautettujen imagejen uudelleenrakentamista Ayakaleaf Pron päivityksen yhteydessä.

<Danger>

Seuraavat osiot koskevat vain [hiekkalaatikoituja käännöksiä (Sandboxed Compiles)](/fi/on-premises/configuration/overleaf-toolkit/sandboxed-compiles).

</Danger>

### Uusien pakettien asentaminen ja päivittäminen

Voit hallita Tex Live -paketteja `tlmgr`-komennoilla, kuten `tlmgr install` ja `tlmgr update`, seuraavan esimerkin mukaisesti:

```dockerfile
FROM ghcr.io/ayaka-notes/texlive-full:2023.1

RUN tlmgr update --force ebproof
```

### `tlmgr`:n käyttäminen vanhemmassa TeX Live -imagessa

Oletuksena `tlmgr` lataa resurssit uusimmasta TeX Live -julkaisusta. Kun paikkaat vanhempaa TeX Live -imagea, lataukset on vaihdettava vastaavaan arkistoon. Arkistojen peilipalvelimet löydät luettelosta osoitteessa [https://www.tug.org/historic/](https://www.tug.org/historic/).

```dockerfile
FROM ghcr.io/ayaka-notes/texlive-full:2022.1

RUN tlmgr option repository <MIRROR>/systems/texlive/<YEAR>/tlnet-final
# e.g. RUN tlmgr option repository ftp://tug.org/historic/systems/texlive/2022/tlnet-final

RUN tlmgr update --force ebproof
```

### Uusien fonttien asentaminen

Uusien fonttien asentamiseen Tex Live -jakeluun on erilaisia menettelyjä, ja mukautetun fontin asentaminen voi vaatia useita vaiheita. Virallisen Tex Live -dokumentaation [TeX-fonttien asennusohjeet](https://tug.org/fonts/fontinstall.html) ovat todennäköisesti hyvä lähtökohta.

Seuraava `Dockerfile` näyttää esimerkin TrueType-fontin asentamisesta olemassa olevan Tex Live 2022 -imagen päälle:

```dockerfile
FROM ghcr.io/ayaka-notes/texlive-full:2022.1

COPY ./myfonts/*.ttf /usr/share/fonts/truetype/myfont/

# rebuild font information cache
RUN fc-cache
```

### Ayakaleaf Pron määrittäminen käyttämään uusia imageja

Käytä uuden imagen rakentamiseen nimeä `ghcr.io/ayaka-notes/texlive-full` ja mukautettua tagia, esimerkiksi:

```bash
docker build -t ghcr.io/ayaka-notes/texlive-full:2023.1-custom .
```

Nyt voimme määrittää Ayakaleaf Pron käyttämään uutta `2023.1-custom`-imagea päivittämällä ympäristömuuttujat `TEX_LIVE_DOCKER_IMAGE`, `ALL_TEX_LIVE_DOCKER_IMAGES` ja `ALL_TEX_LIVE_DOCKER_IMAGE_NAMES` (nimet ovat valinnaisia ja noudattavat imagejen järjestystä):

```text wrap
TEX_LIVE_DOCKER_IMAGE: "ghcr.io/ayaka-notes/texlive-full:2023.1-custom"
ALL_TEX_LIVE_DOCKER_IMAGES: "ghcr.io/ayaka-notes/texlive-full:2023.1,ghcr.io/ayaka-notes/texlive-full:2023.1-custom"
ALL_TEX_LIVE_DOCKER_IMAGE_NAMES: "TeX Live 2023,TeX Live 2023 custom"
```

Yllä olevassa esimerkissä uudet projektit käyttävät oletuksena uutta `2023.1-custom`-imagea, kun taas `2023.1` on edelleen käytettävissä tarvittaessa.

Mukautettu image on olemassa vain isäntäkoneellasi, joten `bin/up` ei voi hakea sitä. Aseta `SIBLING_CONTAINERS_PULL=false` tiedostossa `config/overleaf.rc` (hae muut imaget itse komennolla `docker pull`) ja ota uudet asetukset käyttöön suorittamalla `bin/up -d`.

### Q\&A

<Accordion title="Täytyykö minun asentaa kiinalaisia fontteja kääntääkseni kiinankielisiä dokumentteja XeLaTeXilla?">

<strong>Vastaus:</strong> Ei, ei `texlive-full`-imageilla. Ne sisältävät TeX Liven kiinan kielen paketit (`ctex`, `xeCJK`) Fandol-fontteineen sekä Noto CJK -fontit (esimerkiksi `Noto Serif CJK SC`). Aseta projektin kääntäjäksi XeLaTeX editorin asetuksissa ja käännä, esimerkiksi:

```latex
\documentclass{ctexart}
\begin{document}
你好，世界！
\end{document}
```

Jos haluat käyttää Notoa Fandolin sijaan, lisää `\setCJKmainfont{Noto Serif CJK SC}`. `latexmkrc`-tiedostoa ei tarvita. Muita fontteja varten rakenna mukautettu image kohdan [Uusien fonttien asentaminen](#uusien-fonttien-asentaminen) mukaisesti.

</Accordion>
