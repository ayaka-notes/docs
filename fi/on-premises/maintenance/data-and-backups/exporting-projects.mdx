---
title: Projektien vienti
icon: file-export
---

Server Pron ja Community Editionin versioon `5.4.0` on lisätty skripti, jonka avulla ylläpitäjät voivat viedä kaikkien käyttäjien projektit (mukaan lukien ne, jotka näkyvät yhä **Deleted**- ja **Trashed**-kansioissa) levyllä olevaan hakemistoon.

<Info>

Skriptin tuottama tulos on sama kuin jos kaikki projektit ladattaisiin käsin Zip-tiedostoina käyttäjän projektinäkymästä. Skripti tallentaa kaikki odottavat muutokset ennen latauksen aloittamista varmistaakseen, että vienti sisältää projektin uusimman version.

</Info>

### Rajoitukset

Vientiskriptillä on seuraavat rajoitukset:

* Projektiasetuksia, kuten TeX Live -imagen nimeä tai kääntäjää, ei viedä. Ne on asetettava, kun projekti ladataan käyttäjän tilille.
* Viedyt projektit eivät sisällä versiohistoriaa.
* Yhteistyökumppaneiden tietoja ei säilytetä. Projektit on jaettava uudelleen. Jos käytössä on linkkijako, katselu- ja muokkauslinkit luodaan uudelleen (ne eivät ole samat kuin aiemmin).
* Kommentteja ja seurattujen muutosten tietoja ei viedä.
* Projektin keskusteluhistoriaa ei viedä.

<Danger>

Tätä skriptiä **ei** ole tarkoitettu korvaamaan koko järjestelmän varmuuskopiota. Jotta voit palauttaa instanssisi katastrofitilanteessa, suosittelemme **vahvasti** ottamaan [yhtenäisen varmuuskopion](https://docs.overleaf.com/on-premises/maintenance/#performing-a-consistent-backup).

</Danger>

### **Liput**

| Nimi           | Kuvaus                                                                          |
| -------------- | ------------------------------------------------------------------------------- |
| `--help`       | Näytä ohje                                                                      |
| `--user-id`    | Käyttäjätunnus (pakollinen, ellei käytetä `--export-all`- tai `--project-id`-lippua) |
| `--project-id` | Vie yksittäinen projekti (**ei voi** käyttää yhdessä `--user-id`- tai `--export-all`-lipun kanssa) |
| `--list`       | Listaa käyttäjän projektit (**ei voi** käyttää yhdessä `--output`-lipun kanssa) |
| `--output`     | Tuloste-zip-tiedosto (yksittäisille vientitoiminnoille)                         |
| `--export-all` | Vie kaikkien käyttäjien projektit (vaatii `--output-dir`-lipun)                 |
| `--output-dir` | Hakemisto kaikkien käyttäjien vientitiedostojen tallentamiseen                  |
| `--log-level`  | Tuetut lokitasot: `trace`\|`debug`\|`info`\|`warn`\|`error`\|`fatal`            |

### **Käyttö**

Vie kaikkien käyttäjien projektit seuraavalla komennolla:

```bash wrap
# Overleaf Toolkit users
$ bin/docker-compose exec sharelatex /bin/bash -ce "cd /overleaf/services/web && node modules/server-ce-scripts/scripts/export-user-projects.mjs --export-all --output-dir=/var/lib/overleaf/data/exports"

# Legacy docker-compose.yml users
docker exec sharelatex /bin/bash -ce "cd /overleaf/services/web && node modules/server-ce-scripts/scripts/export-user-projects.mjs --export-all --output-dir=/var/lib/overleaf/data/exports"
```

<Info>

Jos käytät Server Pron tai Community Editionin versiota &lt;= 3.5.13, sinun on muutettava yllä olevaa esimerkkiä käyttämään skriptiä **`export-legacy-user-projects.js`**.

</Info>

### **Valmistuminen**

Kun vienti on valmis, pääset tiedostoihin isäntäkoneen hakemiston kautta, joka on bind-liitetty polkuun <strong>/var/lib/overleaf</strong> **docker-compose.yml**-tiedostossasi, tai Toolkitia käytettäessä **config/overleaf.rc**-tiedoston `OVERLEAF_DATA_PATH`-ympäristömuuttujan osoittamasta hakemistosta.

<Info>

Overleaf sallii tällä hetkellä päällekkäiset projektinimet. Jos käyttäjällä on samannimisiä projekteja, ne lisätään silti käyttäjän Zip-vientiin, mutta purettaessa vain yksi versio on läsnä. Linuxissa `unzip -B` kirjoittaa samannimiset tiedostot varmuuskopiotiedostoiksi korvaamisen sijaan.

</Info>
