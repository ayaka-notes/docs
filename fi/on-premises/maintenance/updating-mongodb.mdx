<Info>

Jokainen Server CE:n/Server Pron uusi julkaisu ilmoittaa [julkaisutiedoissaan](https://docs.overleaf.com/on-premises/release-notes) kaikista muutoksista tuettuun MongoDB-versioon.

</Info>

### Pitäisikö minun päivittää MongoDB?

MongoDB-version päivittämistä kannattaa harkita **vain**, jos aiot päivittää Server CE- tai Server Pro -instanssisi.

Jos käyttämäsi MongoDB-versio on uudempi kuin nykyiselle (tai tavoitteena olevalle) versiollesi suositeltu, muutoksia ei tarvita.

<Warning>

MongoDB-versiota ei pidä koskaan alentaa.

</Warning>

Jos kohtaat tietyn ongelman, jonka arvelet liittyvän nykyiseen MongoDB-versioosi, voit [avata issuen](https://github.com/overleaf/overleaf/issues), jos olet Server CE -käyttäjä, tai ottaa yhteyttä Overleafin tukeen, jos olet Server Pro -käyttäjä.

### Päivitysprosessi

MongoDB-version päivittäminen Server CE- tai Server Pro -instanssin päivityksen yhteydessä tapahtuu seuraavasti:

1. Päätä, mihin Server CE:n/Server Pron versioon aiot päivittää.
2. Selvitä, mitä MongoDB-versiota kyseinen Overleaf Server CE:n/Server Pron julkaisu suosittelee.
3. Päivitä MongoDB tavoiteversioon ohjeiden mukaisesti.
4. Päivitä Server CE:n/Server Pron imagen versio ja käynnistä instanssi uudelleen.

Suosittelemme päivittämään **Server CE:n/Server Pron** aina uusimpaan saatavilla olevaan versioon, koska sen tuki on aina taattu (koskee vain Server Pro -käyttäjiä).

<Danger>

Server CE:tä/Prota päivitettäessä suosittelemme päivittämään käytössä olevan pääversion uusimpaan julkaisuun **ennen** päivittämistä **seuraavan** pääversion uusimpaan julkaisuun. Jos käyttöönottosi on yli yhden pääversion jäljessä uusimmasta, sinun on tehtävä päivitys useassa vaiheessa.

Jos käytössäsi on esimerkiksi 3.5.10, sinun on päivitettävä versioon 3.5.13 -> suoritettava koko projektihistorian siirto -> 4.2.9 -> 5.5.4.

Pääversioita ei pidä **koskaan** ohittaa (3.5.10 -> 5.5.4). Jos käytät Toolkitia ja olet yli yhden pääversion jäljessä uusimmasta, et **saa** käyttää `bin/upgrade`-skriptiä, koska sinun on tehtävä manuaalinen monivaiheinen päivitys.

</Danger>

<Warning>

On tärkeää ottaa [johdonmukainen varmuuskopio](/fi/on-premises/maintenance/data-and-backups#performing-a-consistent-backup) **ennen** jokaista pääversion päivitystä, jotta voit tarvittaessa palata takaisin.

</Warning>

#### Versioiden tukitiedot

<Danger>

Yllä mainittu ominaisuuksien yhteensopivuusversion vähimmäisarvo perustuu vastaavaan MongoDB-versioon, jota suositellaan käytettäväksi kyseisen Overleaf-version kanssa. Jos aiot käyttää uudempaa versiota, MongoDB:llä on omat vähimmäisvaatimuksensa.

</Danger>

Yhteensopivuustaulukon, josta näkyvät MongoDB:n kanssa käytettäväksi tuetut MongoDB Node.js -ajurin versiot, löydät [täältä](https://www.mongodb.com/docs/drivers/node/current/reference/compatibility/).

MongoDB:n kunkin version elinkaaren päättymistilanteen näet [täältä](https://endoflife.date/mongodb).

#### MongoDB:n päivittäminen

MongoDB edellyttää **vaiheittaisia päivityksiä**. Tämä tarkoittaa, että et voi siirtyä suoraan esimerkiksi versiosta `4.0` versioon `5.0`. Sinun on ensin päivitettävä `4.2`:sta `4.4`:ään ja sitten `5.0`:aan.

<Info>

MongoDB käyttää vakaissa versioissaan parillisia numeroita.

</Info>

* [MongoDB:n julkaisutiedot – MongoDB:n päivittäminen versiosta `5.0` versioon `6.0`](https://www.mongodb.com/docs/v6.0/release-notes/6.0-upgrade-replica-set/)

</Info>

**Perusohjeet**

Useimmissa tapauksissa päivitys edellyttää yhteensopivuuslipun asettamista ennen varsinaista mongo-version päivittämistä. Vaiheet ovat seuraavat:

1. Aseta yhteensopivuuslippu MongoDB:n julkaisutiedoissa kuvatulla tavalla (katso alla olevat esimerkit).
2. Päivitä sitten mongo-image:
   1. **Toolkitin käyttäjät** Päivitä `MONGO_VERSION`, esim. `MONGO_VERSION=6.0`
   2. **Docker Composen käyttäjät** Päivitä `mongo`-imagen tunnisteen (tag) versio,\
      esim. `services -> mongo -> image: mongo:6.0`;

**Esimerkki: MongoDB:n päivittäminen versiosta `5.0` versioon `6.0`**

Aloitetaan varmistamalla, että käytössä on MongoDB `6.0`:

Overleaf Toolkitin käyttäjät:

```bash
bin/docker-compose exec mongo mongod --version
# db version v5.0.24
```

Docker Composen käyttäjät:

```bash
docker compose exec mongo mongod --version
# db version v5.0.24
```

[Päivitysohjeiden](https://docs.mongodb.com/manual/release-notes/3.6-upgrade-standalone/#upgrade-version-path) mukaan ainoa vaatimus on, että `featureCompatibilityVersion` on asetettu arvoon `5.0`. Teemme sen avaamalla MongoDB-komentotulkin ja suorittamalla ohjeissa mainitun komennon:

Overleaf Toolkitin käyttäjät:

```bash
bin/mongo
# MongoDB shell version v5.0.24
# ...
# overleaf:PRIMARY> db.adminCommand( { setFeatureCompatibilityVersion: "5.0" } )
# { 
# "ok" : 1,
# ...
# }
overleaf:PRIMARY> exit
# bye
```

<Info>

Docker Composen käyttäjät voivat avata komentotulkin komennolla `docker compose exec mongo mongosh` ja suorittaa samat komennot kuin Toolkitin käyttäjät.

</Info>

Overleaf Toolkitin käyttäjät:

Pysäytämme sitten Server CE:n/Server Pron ja MongoDB:n instanssit komennolla `bin/stop`, asetamme tiedostoon `config/overleaf.rc` arvon `MONGO_VERSION=6.0` ja käynnistämme sitten `mongo`-palvelun uudelleen komennolla `bin/up mongo`) varmistaaksemme, että päivitys sujui ongelmitta.

Lopuksi päivitämme Server CE:n/Server Pron imagen version tavoiteversioomme ja luomme kaikki palvelut uudelleen komennolla `bin/up -d`.

Docker Composen käyttäjät:

Pysäytämme sitten Server CE:n/Server Pron ja MongoDB:n instanssit komennolla `docker compose stop`, päivitämme [`docker-compose.yml`](https://github.com/overleaf/overleaf/blob/4b1babd4ea634ab12c54e9a9aea7db0e8a500941/docker-compose.yml)-tiedoston käyttämään arvoa `image: mongo:6.0` ja käynnistämme sitten `mongo`-palvelun uudelleen komennolla `docker compose up mongo` varmistaaksemme, että päivitys sujui ongelmitta.

Lopuksi päivitämme Server CE:n/Server Pron imagen version tavoiteversioomme ja luomme kaikki palvelut uudelleen komennolla `docker compose up`.

#### Vastaavat komennot Docker Composen käyttäjille

Docker Composen käyttäjille vastaavat komennot ovat:

* `docker compose exec mongo mongod --version` näyttää mongo-version
* `docker compose exec mongo mongosh` käynnistää mongo-komentotulkin ylläpitokomentoja varten
* `docker compose stop` -komento pysäyttää palvelimen
* Muokkaa [`docker-compose.yml`](https://github.com/overleaf/overleaf/blob/4b1babd4ea634ab12c54e9a9aea7db0e8a500941/docker-compose.yml)-tiedostoa käyttämään arvoa `image: mongo:6.0` päivittääksesi mongo-version
* `docker compose up mongo` käynnistää mongo-palvelun uudelleen ja varmistaa, että päivitys sujui ongelmitta
* Muokkaa [`docker-compose.yml`](https://github.com/overleaf/overleaf/blob/4b1babd4ea634ab12c54e9a9aea7db0e8a500941/docker-compose.yml)-tiedostoa käyttämään arvoa `image: sharelatex:VERSION` päivittääksesi imagen version
* `docker compose up` luo kaikki palvelut uudelleen.

### Mukautetun roolin luominen

Versiossa `5.5.1` otimme käyttöön käynnistyksenaikaisen tarkistuksen, joka varmistaa MongoDB:n ominaisuuksien yhteensopivuusversion. Jos MongoDB-tietokantasi käyttää todennusta (esim. perustodennusta), `sharelatex`-kontti ei ehkä käynnisty, vaan näyttää käyttöoikeusvirheen "_not authorized on admin to execute command_".

Voit ratkaista tämän joko luomalla MongoDB:hen uuden roolin ja määrittämällä sen tietokannan käyttämiseen käytettävälle käyttäjätilille alla olevien ohjeiden mukaisesti, tai asettamalla `ALLOW_MONGO_ADMIN_CHECK_FAILURES=true`, jolloin tarkistus saa epäonnistua estämättä käyttöönoton käynnistymistä.

<Check>

Tämä uusi rooli myöntää **ainoastaan** oikeuden lukea koko klusterin laajuisia MongoDB-palvelimen parametreja, ja sitä voidaan käyttää uudelleen myös valvontatarkoituksiin,

</Check>

```bash wrap
# Toolkit users
$ bin/docker-compose exec -it mongo mongosh -u {{YOUR-ADMIN-USERNAME}} -p

# Switch to the "admin" database using
overleaf [direct: primary] sharelatex> use admin
switched to db admin
overleaf [direct: primary] admin> 

# Create a new role with permission to use "getParamter". Copy and paste the function below into the shell and press the return key

db.createRole(
  {
    role: "clusterParameterReader",
    privileges: [
      {
        resource: { cluster: true },
        actions: ["getParameter"]    
      }
    ],
    roles: [] 
  }
);

# Switch back to the "sharelatex" database 
use sharelatex
switched to db sharelatex
overleaf [direct: primary] sharelatex> 

# Assign the new "clusterParameterReader" role to your database user by copy and pasting the function below into the shell and press the return key 
db.grantRolesToUser(
  "{{YOUR-DATABASE-USER}}",
  [
    { role: "clusterParameterReader", db: "admin" }
  ]
);

# Type exit then return to exit the MongoDB shell
# Run bin/up -d to start the deployment stack
$ bin/up -d
```
