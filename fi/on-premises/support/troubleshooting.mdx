<Accordion title="Overleafin ajaminen NFS-tiedostojärjestelmällä">

NFS-tiedostojärjestelmän liittäminen Overleaf-konttiin on teknisesti mahdollista, mutta sitä ei suositella, ja se voi aiheuttaa monenlaisia suorituskykyvirheitä.

Yksi yleinen käännösten yhteydessä esiintyvä virhe on:

```text
EBUSY: resource busy or locked, unlink '/var/lib/overleaf/data/compiles/62f3d57bef7cf9005c364e75-62f3d57bef7cf9005c364e7a/.nfs573663533034825247625441'
```

Erityisesti emme suosittele NFS-pohjaisten tiedostojärjestelmien käyttöä tilapäiselle datalle, kuten käännösdatan hakemistoille. Suosittelemme seuraaville hakemistoille paikallista työlevyä, mieluiten paikallista SSD-levyä.

`docker-compose`-pohjaisissa asennuksissa suosittelemme yksinkertaisesti ohittamaan NFS:n bind-mount-liitoksen, jolloin sovelluksen polkuja ei tarvitse muuttaa. Tässä on ote `docker-compose`-määrityksestä, jossa käytetään polkuun `/scratch` liitettyä työlevyä:

```yaml title="docker-compose excerpt"
services:
  sharelatex:
    environment:
      SANDBOXED_COMPILES_HOST_DIR: /scratch/compiles/
    volumes:
      - nfs:/var/lib/overleaf/data
      - /scratch/cache/:/var/lib/overleaf/data/cache
      - /scratch/compiles/:/var/lib/overleaf/data/compiles
      - /scratch/output/:/var/lib/overleaf/data/output
      - /scratch/tmp/:/var/lib/overleaf/tmp
```

Olemassa olevia tiedostoja ei tarvitse siirtää NFS:ltä uuteen sijaintiin päivityksen jälkeen. LaTeX-kääntäjä voi luoda kaikki tiedostot uudelleen täydellä käännösajolla.

Lisätietoja: https://docs.overleaf.com/on-premises/support/troubleshooting#running-overleaf-with-an-nfs-filesystem

</Accordion>

<Accordion title="Overleafin ajaminen Windowsissa tai macOS:ssä estää `mongo`-palvelun käynnistymisen">

Jos ajat Overleafia Windowsissa tai macOS:ssä, `mongo`-palvelun uudelleenkäynnistys voi epäonnistua virheellä:

```text title="Example error"
Failed to start up WiredTiger under any compatibility version.
Reason: 1: Operation not permitted
```

Tämä voi tapahtua, kun MongoDB:n data on bind-mount-liitetty tiedostojärjestelmästä, joka ei tarjoa sen vaatimaa toimintaa, kuten Windowsista liitetystä hakemistosta. [Windowsissa WSL 2:n kanssa](/fi/on-premises/installation/using-docker-compose/windows) pidä Toolkit Ubuntun Linux-kotihakemiston alla ja käytä oletusarvoisia bind-liitoksia. Katso alustaoppaan [MongoDB-tarkistukset](/fi/on-premises/installation/using-docker-compose/windows/troubleshooting#mongodb-fails-to-start).

Jos uusi asennus tarvitsee Dockerin hallinnoimaa tallennustilaa, seuraava override käyttää nimettyjä volyymeja (katso [MongoDB-imagen tallennusohjeet](https://github.com/docker-library/docs/blob/master/mongo/content.md#where-to-store-data)). Olemassa olevassa asennuksessa liitosten muuttaminen ei siirrä dataa: varmuuskopioi ja palauta tietokanta/välimuisti ennen vaihtamista, tai palvelu näkee tyhjät volyymit. Lisää tämä tiedostoon `config/docker-compose.override.yml` yhdistäen sen olemassa oleviin määrityksiin:

```yaml title="config/docker-compose.override.yml"
volumes:
  mongo-data:
  redis-data:

services:
  mongo:
    volumes:
      - mongo-data:/data/db

  redis:
    volumes:
      - redis-data:/data
```

Lisätietoja: https://docs.overleaf.com/on-premises/support/troubleshooting#running-overleaf-on-windows-or-macos-results-in-the-mongoservice-not-starting

</Accordion>

<Accordion title="Päivitys Redis 6.2:een johtaa uudelleenkäynnistyssilmukkaan">

Tulosta kopio lokeista komennolla `docker logs redis`.

Jos näet rivin `Fatal: Can't initialize Background Jobs`, koko tuloste näyttää suunnilleen tältä:

```text title="Redis log example"
1:M 11 Feb 2024 15:19:22.609 # Server initialized
1:M 11 Feb 2024 15:19:22.609 # Fatal: Can't initialize Background Jobs.
1:C 11 Feb 2024 15:19:26.055 # oO0OoO0OoO0Oo Redis is starting oO0OoO0OoO0Oo
```

Tämä voi liittyä käytössä olevaan Docker-versioon. Päivittäminen versioon >= 20.10.10 pitäisi ratkaista ongelman.

Lisätietoja on Redisin upstream-issuessa: https://github.com/redis/redis/issues/12362

Lähde: https://docs.overleaf.com/on-premises/support/troubleshooting#upgrading-to-redis-6.2-results-in-a-restart-loop

</Accordion>

<Accordion title="Mallipohjagallerian esikatselu-/pikkukuvien virheellinen suunta">

Joskus Ayakaleaf Pron luomat esikatselu-/pikkukuvat voivat syntyä väärin päin, ja niiden korjaaminen vaatii manuaalista toimenpidettä. Nämä kuvat tallennetaan hakemistoon `/var/lib/overleaf/data/template_files/`.

Suosittelemme varmuuskopioimaan tämän kansion ennen muutosten tekemistä.

Noudata seuraavia vaiheita jokaiselle ongelmasta kärsivälle mallipohjalle:

Etsi mallipohjan ID: Siirry instanssisi mallipohjagalleriaan (/templates/all), avaa ongelmallinen mallipohja ja kopioi ID URL-osoitteesta (esimerkiksi: https://your-instance-url/templates/6645d346c224815e9460a695). Aja korjauskomento: Aja seuraava komento Docker-isännässä (korvaa mallipohjan ID kopioimallasi ID:llä ja päivitä polku tarvittaessa): docker exec sharelatex /bin/bash -c "mogrify -rotate 90 /var/lib/overleaf/data/template\_files/6645d346c224815e9460a695\_\*\{thumbnail,preview\}"

Lähde: https://docs.overleaf.com/on-premises/support/troubleshooting#incorrect-orientation-of-template-gallery-preview-thumbnail-images

</Accordion>

<Accordion title="Please verify that you have enabled system calls. For pdflatex, this is 'pdflatex -shell-escape'.">

`\write18`-komento on Community Editionissa oletuksena pois käytöstä, koska kaikki käännökset tapahtuvat samassa `sharelatex`-kontissa; tämä on turvallisempi oletus.

Jos haluat ottaa sen käyttöön pdflatexille, luo projektisi juureen `latexmkrc`-tiedosto, jossa on seuraava sisältö:

```perl title="latexmkrc"
$pdflatex = 'pdflatex --shell-escape';
```

Yritä sitten kääntää uudelleen.

Lähde: https://docs.overleaf.com/on-premises/support/troubleshooting#please-verify-that-you-have-enabled-system-calls.-for-pdflatex-this-is-pdflatex-shell-escape

</Accordion>

<Accordion title="`bin/up` epäonnistuu virheeseen `unable to upgrade to tcp, received 409` tai `OCI runtime exec failed` viestin ”Initiating Mongo replica set...” jälkeen">

Nämä virheet tarkoittavat, että `mongo`-kontti kaatuu ja käynnistyy jatkuvasti uudelleen. `bin/up` käynnistää MongoDB:n ja ajaa sitten sen sisällä komennon, joka epäonnistuu kontin käynnistyessä uudelleen. `bin/docker-compose ps` näyttää `mongo`-palvelun tilana `Restarting`.

Selvitä varsinainen syy lukemalla MongoDB:n loki:

```sh
bin/logs mongo
```

Yleisiä syitä ovat:

* <strong>Suorittimessa ei ole AVX-tukea.</strong> MongoDB 5.0 ja uudemmat vaativat AVX:n x86-64-arkkitehtuurilla, ja lokissa näkyy `MongoDB 5.0+ requires a CPU with AVX support`. Aseta virtuaalikoneessa suoritintyypiksi `host`, jotta AVX välitetään virtuaalikoneelle.
* <strong>Linux-ydin 6.19–7.0.13.</strong> MongoDB kieltäytyy käynnistymästä näillä ytimillä. Katso kiertotapa kohdasta [Ohjelmistovaatimukset](/fi/on-premises/installation/introduction#software-requirements).
* <strong>Data on luotu vanhemmalla MongoDB-versiolla.</strong> MongoDB 8.0 ei voi avata version 4.4 tai 5.0 dataa suoraan. Päivitä yksi pääversio kerrallaan, katso [MongoDB:n päivittäminen](/fi/on-premises/maintenance/updating-mongodb).

</Accordion>

<Accordion title="Lokissa näkyy ”Running Overleaf Community Edition, skipping TexLive checks”">

Tämä on odotettua Ayakaleaf Prossa, ja voit jättää sen huomiotta. Viesti tulostetaan, kun `OVERLEAF_IS_SERVER_PRO` ei ole `true`, mikä pätee Ayakaleaf Pro -imagessa. Ayakaleaf Pro ei tarvitse tätä muuttujaa, joten jätä se asettamatta.

</Accordion>

<Accordion title="`sharelatex`-kontti käynnistyy jatkuvasti uudelleen">

Ennen kuin Overleaf käynnistyy, kontti suorittaa käynnistystarkistukset ja sammuu, jos jokin niistä epäonnistuu. Toolkit ajaa sitä asetuksella `restart: always`, joten Docker käynnistää sen uudelleen ja sama tarkistus epäonnistuu taas. Käynnistystuloste kertoo, mikä tarkistus epäonnistui:

```sh
bin/docker-compose logs --tail=100 sharelatex
```

Yleisiä syitä ovat:

* **`Missing required secrets`**: aseta `OVERLEAF_INVITE_TOKEN_SECRET` tiedostoon `config/variables.env`, katso [Ympäristömuuttujat](/fi/on-premises/configuration/overleaf-toolkit/environment-variables).
* **`ShareLaTeX to Overleaf rebranding`**: määrityksissä käytetään yhä `SHARELATEX_`-muuttujia tai -polkuja; nimeä ne uudelleen viestin ohjeiden mukaisesti.
* **Virhe kohdan `Checking can connect to mongo and redis` jälkeen**: Overleaf ei tavoita MongoDB:tä tai Redisiä. Tarkista `bin/logs mongo` ja `bin/logs redis`.

Kun syy on korjattu, suorita `bin/up -d`.

</Accordion>

<Accordion title="Kontti pysähtyy kohtaan `910_initiate_doc_version_recovery` tai päättyy koodilla 2">

Jokaisella käynnistyskerralla kontti ajaa käynnistysskriptinsä peräkkäin, ja loki nimeää jokaisen muodossa `*** Running /etc/my_init.d/<script>...`. `910_initiate_doc_version_recovery` tekee työtä vain instansseissa, joissa on joskus ajettu Overleaf 5.0.1:tä. Kaikissa muissa instansseissa se tulostaa `No recovery of doc versions needed.` ja käynnistys jatkuu. Sen tuloste menee myös tiedostoon `data/history/doc-version-recovery.log` hakemistossa `OVERLEAF_DATA_PATH`.

Poistumiskoodi ja komennon `bin/docker-compose logs --tail=100 sharelatex` tulosteen loppu kertovat, mitä tapahtui:

* **Poistumiskoodi 2**, ja loki päättyy riviin `*** Init system aborted.`: kontti pysäytettiin esimerkiksi komennolla `bin/stop`, `docker stop` tai painamalla Ctrl+C komennon `bin/up` aikana. Viimeisellä `Running`-rivillä mainittu skripti on vain se, joka oli käynnissä sillä hetkellä, eikä se epäonnistunut. Käynnistä kontti uudelleen komennolla `bin/up -d` ja anna käynnistyksen valmistua.
* **Poistumiskoodi 1**, ja lokissa näkyy `*** /etc/my_init.d/<script> failed with status <n>`: kyseinen skripti epäonnistui, ja sen virhe on juuri sitä edeltävillä riveillä. Jos `910_initiate_doc_version_recovery` epäonnistui virheeseen `Detected unflushed changes while recovering doc versions`, instanssissa on ajettu 5.0.1:tä ja siinä on yhä tallentamattomia muokkauksia; noudata virallista [Doc version recovery](https://docs.overleaf.com/on-premises/release-notes/release-notes-5.x.x/doc-version-recovery) -ohjetta.

</Accordion>

<Accordion title="”Restricted, sorry you don’t have permission to load this page”">

Tämä sivu näytetään, kun tilisi on kirjautunut sisään mutta sillä ei ole lupaa avata sivua, esimerkiksi kun ylläpitosivun avaa tili, joka ei ole ylläpitäjä, tai kun projektia ei ole jaettu kanssasi.

Avataksesi ylläpitosivut kirjaudu sisään ylläpitäjätilillä. Olemassa oleva ylläpitäjä voi tehdä toisesta tilistä ylläpitäjän, tai voit luoda sellaisen komennolla `create-user --admin`, katso [Käyttäjien hallinta](/fi/on-premises/user-and-project-management/user-management). Kehitysympäristössä (`develop/`) ylläpitosivut edellyttävät lisäksi asetusta `ADMIN_PRIVILEGE_AVAILABLE=true` tiedostossa `develop/dev.env`; Ayakaleaf Pro -image asettaa sen valmiiksi.

</Accordion>
