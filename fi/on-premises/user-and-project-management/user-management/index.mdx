## Ylläpitäjäkäyttäjän luominen {#creating-an-administrator-user}

Overleaf Toolkit -käyttöönotot:

```bash title="Overleaf Toolkit" wrap
$ bin/docker-compose exec sharelatex /bin/bash -ce "cd /overleaf/services/web && node modules/server-ce-scripts/scripts/create-user --admin --email=joe@example.com"
```

Vanhat docker-compose.yml-käyttöönotot:

```bash title="Legacy docker-compose" wrap
$ docker exec sharelatex /bin/bash -ce "cd /overleaf/services/web && node modules/server-ce-scripts/scripts/create-user --admin --email=joe@example.com"
```

Komento luo käyttäjän annetulla sähköpostiosoitteella, jos sitä ei vielä ole, ja tekee siitä ylläpitäjän. Komennon tuloste sisältää URL-osoitteen, jossa voit asettaa käyttäjän salasanan ja kirjautua sisään ensimmäistä kertaa.

<Info>

Ohjelmallisessa lähestymistavassa voit käyttää samaa skriptiä sekä tavallisten käyttäjien että ylläpitäjien luomiseen. Jätä tavallisten käyttäjien kohdalla --admin-lippu pois.

</Info>

Jos käytät todennukseen sisäisiä tilejä ja haluat korottaa olemassa olevan käyttäjän instanssin ylläpitäjäksi tai poistaa ylläpitäjän oikeudet, toimi seuraavasti:

<Steps>
<Step title="Ylläpitäjän käyttöliittymän kautta">
* Kirjaudu sisään olemassa olevana ylläpitäjänä.
* Napsauta Admin -> Manage Users.
* Hae käyttäjä ja napsauta hänen sähköpostiosoitettaan.
* Vieritä alas Site Admin -osioon ja napsauta (show)-linkkiä.
* Valitse valintaruutu Is Site Admin.
* Viimeistele napsauttamalla Save.
</Step>
</Steps>

## Käyttäjien poistaminen {#deleting-users}

Yleensä tilejä ei kannata poistaa, ellei niitä enää tarvita. Tilin poistaminen poistaa tilin ja saa yhteistyökumppanit menettämään pääsyn projekteihin. Tällä hetkellä tilejä ei voi poistaa käytöstä — ne joko ovat olemassa tietoineen tai ne poistetaan.

Oletuksena tilit poistetaan pehmeästi (soft delete). Tietoja käyttäjien pysyvästä poistamisesta instanssistasi on muuttujan `ENABLE_CRON_RESOURCE_DELETION` kohdalla [Ympäristömuuttujat](/fi/on-premises/configuration/overleaf-toolkit/environment-variables)-oppaassa.

<Info>

Tilit poistetaan oletuksena pehmeästi. Katso pysyvän poiston toiminta muuttujasta `ENABLE_CRON_RESOURCE_DELETION`.

</Info>

### Admin -> Manage Users -näkymän kautta {#via-admin->-manage-users}

<Steps>
<Step title="">
* Kirjaudu sisään ylläpitäjänä.
* Napsauta Admin -> Manage Users.
* Hae käyttäjä ja valitse hänen sähköpostiosoitteensa vieressä oleva valintaruutu.
* Napsauta roskakorikuvaketta.
* Vahvista napsauttamalla Delete.
</Step>
</Steps>

### Komentorivin kautta {#via-the-command-line}

Käyttäjätilit (ja niiden projektit) voidaan poistaa seuraavilla komennoilla.

Overleaf Toolkit -käyttöönotot:

```bash title="Overleaf Toolkit"
$ bin/docker-compose exec sharelatex /bin/bash -ce "cd /overleaf/services/web && node modules/server-ce-scripts/scripts/delete-user.mjs --email=joe@example.com"
```

Vanhat docker-compose.yml-käyttöönotot:

```bash title="Legacy docker-compose"
$ docker exec sharelatex /bin/bash -ce "cd /overleaf/services/web && node modules/server-ce-scripts/scripts/delete-user.mjs --email=joe@example.com"
```

<Danger>

Poistoskripti käyttää kovakoodattua pakotusasetusta, joka varmistaa, että poisto etenee, vaikka tilin poistosta kertovan sähköpostin lähettäminen epäonnistuisi (esim. kun käyttäjän sähköpostiosoite ei ole enää käytössä).

</Danger>

<Info>

Asetuksella --skip-email voidaan estää tiedottavan sähköpostin lähettäminen poistetulle käyttäjälle.

</Info>

## Pehmeästi poistetun käyttäjän palauttaminen {#restoring-a-soft-deleted-user}

Jos käyttäjä on poistettu vain pehmeästi, voit palauttaa hänen tilinsä ja projektinsa.

<Steps>
<Step title="">
* Kirjaudu sisään ylläpitäjänä.
* Napsauta Admin -> Manage Users.
* Hae käyttäjä, jonka haluat palauttaa.
* Napsauta Display deleted users -painiketta.
* Napsauta poistetun käyttäjän sähköpostiosoitetta.
* Napsauta Recover This Account.
* Vahvista napsauttamalla Recover.
</Step>
</Steps>

<Danger>

Kun ENABLE\_CRON\_RESOURCE\_DELETION on asetettu arvoon true, pehmeästi poistetut tilit voidaan palauttaa 90 päivän kuluessa. 90 päivän jälkeen tilin palauttaminen ei ole mahdollista.

</Danger>

## Käyttäjien laskeminen {#counting-users}

Saat käyttäjämäärät ylläpitäjän käyttöliittymästä osoitteessa https://you-instance-url/admin/user#license. Ohjelmallisiin tarkistuksiin ja vienteihin seuraavista esimerkeistä voi olla apua.

Käyttäjien kokonaismäärä:

```bash title="Total number of users"
echo 'db.users.countDocuments()' | docker exec -i mongo mongosh --quiet localhost/sharelatex
# overleaf [direct: primary] sharelatex> 16
```

Käyttäjien kokonaismäärä metrics-päätepisteen avulla:

```bash title="Num active users from metrics"
docker exec sharelatex curl http://127.0.0.1:3000/metrics | grep num_active_users
# # HELP num_active_users num_active_users
# # TYPE num_active_users gauge
# num_active_users{app="web-api",host="b3ae4ff549d8"} 16
```

Aktiivisten käyttäjien kokonaismäärä (esimerkki: viimeisten 365 päivän aikana aktiiviset käyttäjät):

```bash title="Total number of active users"
echo 'db.users.countDocuments({ lastActive: { $gte: new Date(new Date().getTime() - (365 * 24 * 60 * 60 * 1000)) } })' | docker exec -i mongo mongosh --quiet localhost/sharelatex
# overleaf [direct: primary] sharelatex> 10
```

## Käyttäjätilin tietojen päivittäminen {#updating-user-account-information}

Tilin päivitysten tekotapa riippuu siitä, onko SSO käytössä.

* Jos SSO:ta ei käytetä:
  * Ylläpitäjät voivat muokata käyttäjätilin tietoja kohdassa Admin -> Manage Users (sähköposti, etunimi, sukunimi sekä salasanan palautuslinkin luominen).
  * Tavalliset käyttäjät voivat päivittää omat tietonsa kohdassa Account -> Account Settings (mukaan lukien salasanan vaihtaminen ja Git-todennustunnisteiden luominen).
* Jos SSO on käytössä:
  * Ayakaleaf Pro voidaan määrittää päivittämään käyttäjän etu- ja sukunimi kirjautumisen yhteydessä todennusjärjestelmän perusteella.
  * Kun OVERLEAF\_SAML\_UPDATE\_USER\_DETAILS\_ON\_LOGIN tai OVERLEAF\_LDAP\_UPDATE\_USER\_DETAILS\_ON\_LOGIN on true, käyttäjätietolomake osoitteessa https://your-instance-url/user/settings on poistettu käytöstä, ja etu- ja sukunimen voi asettaa vain identiteetinhallintajärjestelmässäsi.

Lisätietoja:

* [SAML 2.0 -määritys](/fi/on-premises/configuration/overleaf-toolkit/authentication/saml-authentication)
* [LDAP-määritys](/fi/on-premises/configuration/overleaf-toolkit/authentication/ldap-authentication)

### Q\&A {#q&a}

<Accordion title="Voinko luoda SSO-käyttäjiä etukäteen, esimerkiksi API:n avulla?">

<strong>Vastaus:</strong> Tähän ei ole HTTP-API:a. Luo tili yllä olevalla `create-user`-skriptillä (ilman `--admin`-valitsinta) tai kohdassa **Admin → Manage Users** toiminnolla **Create account**. Kun `EXTERNAL_AUTH` on asetettu, lomakkeessa on **External authentication** -vaihtoehto, joka luo tilin ilman paikallista salasanaa ja ilman aktivointisähköpostia. Ensimmäisellä LDAP-, SAML- tai OIDC-kirjautumisella käyttäjä saa uuden tilin sijaan olemassa olevan tilin, jolla on sama sähköpostiosoite, katso [Tilit ja salasanat](/fi/on-premises/configuration/overleaf-toolkit/authentication#accounts-and-passwords).

</Accordion>

<Accordion title="Voinko viedä käyttäjäluettelon ja palauttaa sen myöhemmin?">

<strong>Vastaus:</strong> Et. Käyttäjätilien vientiä tai tuontia ei ole, ei kohdassa **Admin → Manage Users** eikä skriptinä. Tilit tallennetaan MongoDB:hen, joten varmuuskopioi ja palauta ne [MongoDB-varmuuskopion](/fi/on-premises/maintenance/data-and-backups#mongodb) avulla. `export-user-projects.mjs`-skripti vie käyttäjien projektit zip-tiedostoina, ei tilejä, katso [Projektien vieminen](/fi/on-premises/maintenance/data-and-backups/exporting-projects).

</Accordion>

<Accordion title="Kuinka kauan `create-user`-linkki on voimassa, ja miten nollaan salasanan ilman sähköpostia?">

<strong>Vastaus:</strong> Linkki, jonka `create-user` tulostaa, on voimassa 7 päivää, ja se toimii ilman SMTP:tä, koska kopioit sen tulosteesta. Saat uuden linkin ajamalla `create-user`-komennon uudelleen samalla sähköpostiosoitteella. Olemassa olevalle tilille se vain tulostaa uuden linkin, mutta se myös asettaa tilin ylläpitäjälipun vastaamaan valitsinta `--admin`, joten säilytä `--admin`, kun ajat sen ylläpitäjälle.

Ylläpitäjä voi myös asettaa salasanan suoraan: napsauta kohdassa **Admin → Manage Users** käyttäjän rivillä **Update**, avaa **Password**-välilehti ja syötä uusi, vähintään 8 merkin salasana. Tileille, jotka kirjautuvat vain LDAPin, SAML:n tai OIDC:n kautta, ei voi asettaa salasanaa siellä.

</Accordion>
