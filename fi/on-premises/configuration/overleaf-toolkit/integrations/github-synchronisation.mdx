### GitHub-synkronoinnin määrittäminen

<Warning>

Sinun on otettava [git-bridge](/fi/on-premises/configuration/overleaf-toolkit/git-integration) käyttöön ennen GitHub-synkronoinnin käyttämistä.

```dotenv title="config/overleaf.rc"
GIT_BRIDGE_ENABLED=true
```

</Warning>

Siirry [kehittäjäasetuksiin](https://github.com/settings/developers) luodaksesi GitHub OAuth -sovelluksen ja kopioi sen `CLIENT_ID` ja `SECRET`.

**Huomautus**: kun luot OAuth-sovelluksen, syötä kenttään **Authorization callback URL** arvo `${OVERLEAF_SITE_URL}/user/github-sync/oauth2/callback`. Ayakaleaf Pro muodostaa saman osoitteen `OVERLEAF_SITE_URL`-muuttujasta, joten sitä varten ei tarvitse asettaa mitään tiedostoon `config/variables.env`.

Lisää sitten seuraavat asetukset Overleafin ympäristömuuttujatiedostoihin.

```dotenv title="config/variables.env" wrap
# used to encrypt the user's GitHub access token.
# How to generate: `openssl rand -hex 32`
GITHUB_TOKEN_CIPHER_PASSWORD=0123456789ABCDEFG # changed to yours

# Github Sync Settings
GITHUB_SYNC_ENABLED=true
GITHUB_SYNC_CLIENT_ID=
GITHUB_SYNC_CLIENT_SECRET=

# OAuth callback is: ${OVERLEAF_SITE_URL}/user/github-sync/oauth2/callback
# (Optional) GITHUB_SYNC_PROXY_URL=http://10.0.0.1:10808
```

<Warning>

Varmista ennen GitHub OAuth -takaisinkutsun URL-osoitteen määrittämistä, että `OVERLEAF_SITE_URL` on asetettu oikein.

</Warning>

Jos olet alueella, jolla verkkoyhteyksiä on rajoitettu, sinun on ehkä määritettävä välityspalvelin GitHubin käyttämiseksi. Aseta seuraava ympäristömuuttuja: `GITHUB_SYNC_PROXY_URL=http://10.0.0.1:10808`. Varmista, että välityspalvelimen käyttösi on paikallisten lakien ja määräysten mukaista.

<Warning>

`GITHUB_SYNC_PROXY_URL` -arvon on oltava tavallinen HTTP/HTTPS-välityspalvelin (forward proxy), esimerkiksi Clashin HTTP-portti. GitHubin latauspeilejä, kuten `gh-proxy.org`, ei tueta.

</Warning>

<Warning>

Älä käytä välityspalvelimen isäntänä osoitetta `127.0.0.1`. Jos välityspalvelin toimii isäntäpalvelimella, käytä palvelimen lähiverkon IP-osoitetta (kuten `192.168.1.xx`) ja varmista, että välityspalvelin on määritetty hyväksymään yhteydet lähiverkon laitteista.

</Warning>

### GitHub Enterprise

<Info>

GitHub Enterprise -tuki on otettu käyttöön versiosta v6.3.1 alkaen. Aiemmat versiot muodostavat yhteyden vain osoitteeseen `github.com`, eikä alla olevilla muuttujilla ole niissä vaikutusta.

</Info>

Oletuksena GitHub-synkronointi muodostaa yhteyden osoitteeseen `github.com`. Jos haluat käyttää GitHub Enterprise Serveriä (itse isännöity) tai GitHub Enterprise Cloudia tietojen sijaintivaatimuksin (`GHE.com`), aseta `GITHUB_SYNC_URL` instanssisi verkko-osoitteeksi, eli siksi osoitteeksi, jolla avaat repositorioita selaimessa.

```dotenv title="config/variables.env" wrap
# GitHub Enterprise Server
GITHUB_SYNC_URL=https://github.example.com

# or GitHub Enterprise Cloud with data residency
# GITHUB_SYNC_URL=https://octocorp.ghe.com
```

REST- ja GraphQL-API-päätepisteet johdetaan `GITHUB_SYNC_URL`-arvosta samalla tavalla kuin GitHub CLI tekee:

| `GITHUB_SYNC_URL`             | REST API                         | GraphQL API                              |
| ----------------------------- | -------------------------------- | ---------------------------------------- |
| `https://github.com` (oletus) | `https://api.github.com`         | `https://api.github.com/graphql`         |
| `https://SUBDOMAIN.ghe.com`   | `https://api.SUBDOMAIN.ghe.com`  | `https://api.SUBDOMAIN.ghe.com/graphql`  |
| `https://HOST` (mikä tahansa muu) | `https://HOST/api/v3`        | `https://HOST/api/graphql`               |

Aseta API-päätepisteet vain, jos instanssisi tarjoaa ne muualla, esimerkiksi API-yhdyskäytävän takana:

| Muuttuja                  | Oletusarvo                                                                                |
| ------------------------- | ----------------------------------------------------------------------------------------- |
| `GITHUB_SYNC_URL`         | `https://github.com`                                                                      |
| `GITHUB_SYNC_API_URL`     | Johdetaan `GITHUB_SYNC_URL`-arvosta, katso yllä oleva taulukko                            |
| `GITHUB_SYNC_GRAPHQL_URL` | Johdetaan `GITHUB_SYNC_API_URL`-arvosta, jos se on asetettu (`/api/v3` muuttuu muotoon `/api/graphql`, muuten loppuun lisätään `/graphql`), muutoin `GITHUB_SYNC_URL`-arvosta |

<Warning>

* Luo OAuth-sovellus enterprise-instanssiisi (_Settings → Developer settings → OAuth Apps_). `github.com`-palvelussa luotu sovellus ei toimi siellä. Takaisinkutsun URL-osoite on sama: `${OVERLEAF_SITE_URL}/user/github-sync/oauth2/callback`.
* `GITHUB_SYNC_URL` on pelkkä verkko-osoite. Älä aseta sitä API-osoitteeksi, kuten `https://api.github.com` tai `https://HOST/api/v3`, äläkä lisää siihen organisaation polkua.
* Kaikkien kolmen osoitteen on osoitettava samaan GitHub-instanssiin.

</Warning>

<Info>

Jos instanssisi käyttää yksityisen varmentajan (CA) myöntämää varmennetta, liitä CA-varmenne konttiin ja osoita `NODE_EXTRA_CA_CERTS` siihen, esim. `NODE_EXTRA_CA_CERTS=/var/lib/overleaf/certs/github-ca.pem`.

</Info>

<Danger>

Linkitetyt tilit ja projektit kuuluvat siihen instanssiin, johon ne on linkitetty. Ennen kuin vaihdat `GITHUB_SYNC_URL`-arvon toiseen instanssiin, pyydä käyttäjiä purkamaan GitHub-tiliensä ja projektiensa linkitys.

</Danger>

### Kuka voi linkittää ja synkronoida

Kuten Overleaf Cloudissa, vain projektin omistaja voi linkittää projektin GitHub-repositorioon. Kun linkitys on tehty, jokainen muokkausoikeudet omaava yhteistyökumppani voi synkronoida sen.

| Toiminto                                                   | Kuka voi tehdä sen                                             |
| ---------------------------------------------------------- | -------------------------------------------------------------- |
| Projektin vieminen uuteen GitHub-repositorioon             | Projektin omistaja                                             |
| GitHub-repositorion tuominen uuteen projektiin             | Kuka tahansa käyttäjä, josta tulee uuden projektin omistaja    |
| Linkitetyn projektin pull, push ja merge                   | Omistaja ja muokkausoikeudet omaavat yhteistyökumppanit        |
| Projektin linkityksen purkaminen repositoriosta            | Projektin omistaja                                             |

* Overleaf kommunikoi GitHubin kanssa synkronoivan käyttäjän GitHub-tilillä, joten jokainen synkronoiva yhteistyökumppani linkittää oman GitHub-tilinsä, ja hänellä on oltava oikeus pushata repositorion oletushaaraan.
* Pelkät katseluoikeudet omaavat yhteistyökumppanit eivät voi käyttää projektin GitHub-synkronointia.

### Q\&A

<Accordion title="Voinko tehdä force pushin oletushaaraan?">

<strong>Vastaus:</strong> Emme suosittele sitä. Overleaf havaitsee force pushin, varoittaa siitä ja ottaa uudelleenkirjoitetun haaran haltuunsa yhdistäen Overleafissa edellisen synkronoinnin jälkeen tehdyt muutokset. Yllätysten välttämiseksi suojaa oletushaara force pusheilta repositorion asetuksissa.

</Accordion>

<Accordion title="Voinko nimetä linkitetyn projektin oletushaaran uudelleen?">

<strong>Vastaus:</strong> Älä tee niin. Overleaf jatkaa synkronointia sen haaran kanssa, johon projekti linkitettiin. Jos haluat synkronoida toisen haaran kanssa, pura projektin linkitys ja tuo sitten repositorio uuteen projektiin, joka käyttää nykyistä oletushaaraa.

</Accordion>

<Accordion title="GitHub-synkronointi näyttää viestin ”Something wrong with GitHub request”">

<strong>Vastaus:</strong> Tämä viesti tarkoittaa, että palvelin ei tavoittanut GitHubia esimerkiksi verkko-, DNS-, TLS- tai välityspalvelinongelman vuoksi. Näet koko virheen komennolla `bin/logs web`. Jos palvelin tarvitsee välityspalvelimen tavoittaakseen GitHubin, aseta `GITHUB_SYNC_PROXY_URL`.

</Accordion>

<Accordion title="Pitäisikö GitHub OAuth -sovelluksen ”Expire user access tokens” -asetus poistaa käytöstä?">

<strong>Vastaus:</strong> Kyllä. GitHub-synkronointi ei uusi vanhentuneita tunnuksia. Jos vanhenevat tunnukset ovat käytössä, käyttäjien on yhdistettävä GitHub uudelleen aina, kun heidän tunnuksensa vanhenee.

</Accordion>

<Accordion title="Täytyykö instanssini olla tavoitettavissa internetistä?">

<strong>Vastaus:</strong> Ei. Tilin linkittäminen kulkee käyttäjän selaimen kautta, joten OAuth-takaisinkutsuosoitteen tarvitsee avautua vain käyttäjän selaimessa. Palvelimen tarvitsee tavoittaa vain GitHub; jos se tarvitsee siihen välityspalvelimen, aseta `GITHUB_SYNC_PROXY_URL`. GitHub ei koskaan ota yhteyttä instanssiisi: projekti synkronoidaan vain, kun käyttäjä synkronoi sen editorissa.

</Accordion>
