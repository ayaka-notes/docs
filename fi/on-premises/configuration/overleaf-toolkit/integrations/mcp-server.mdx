Jokaisella projektilla on MCP-palvelin, joten tekoälyasiakkaat, kuten Claude Code, Codex, Cursor, VS Code tai Gemini CLI, voivat työskennellä sen parissa: lukea ja muokata sen tiedostoja, kääntää sen, lukea LaTeX-lokin, ladata PDF:n ja vastata kommentteihin. Versiosta v6.3.3 alkaen ne voivat myös selata historiaa ja palauttaa versioita, tarkastella seurattuja muutoksia, lisätä kommentteja, käyttää projektin chattia ja siirtää tiedostoja.

<Info>

Tämän ominaisuuden on kehittänyt [ayaka-notes/ayakaleaf-pro](https://github.com/ayaka-notes/ayakaleaf-pro). Se on otettu käyttöön versiosta v6.3.1 alkaen. Historian, seurattujen muutosten, projektin chatin, uusien kommenttien ja tiedostojen siirtämisen työkalut ovat käytettävissä versiosta v6.3.3 alkaen, katso [Uutta versiossa v6.3.3](/on-premises/user-guide/users/mcp-server#new-in-v6.3.3).

</Info>

### Määrittäminen {#setup}

MCP-palvelin tulee Git-integraation mukana: ota [git-bridge](/fi/on-premises/configuration/overleaf-toolkit/integrations/git-integration) käyttöön, niin myös MCP-palvelin on käytettävissä. Muuta määritettävää ei ole.

### Tekoälyasiakkaan yhdistäminen {#connect-an-ai-client}

1. Luo **Account Settings** -kohdassa Git-todennustunnus. Samaa tunnusta käytetään sekä MCP-palvelimelle että Gitille.
2. Avaa editorissa **Integrations** ja napsauta **MCP server**. Siinä näkyy projektin MCP-palvelimen osoite `https://<your-overleaf>/project/<project_id>/mcp` sekä ohjeet sen lisäämiseksi kuhunkin tekoälyasiakkaaseen: kopioi komento ja korvaa `<token>` omalla tunnuksellasi.

Tunnus lähetetään HTTP-otsakkeena `Authorization: Bearer <token>`. Esimerkiksi Claude Coden komento on:

```bash
claude mcp add --transport http overleaf \
  https://<your-overleaf>/project/<project_id>/mcp \
  --header "Authorization: Bearer <token>"
```

### Käyttö {#usage}

Kun yhteys on muodostettu, pyydä tekoälyasiakasta tavallisin sanoin. Esimerkiksi:

| Pyydät | Tekoälyasiakas käyttää |
| --- | --- |
| _Korjaa johdannon kirjoitusvirheet._ | `read_file`, `edit_file`: muokkaukset näkyvät reaaliaikaisesti editorissa |
| _Käännä projekti ja korjaa LaTeX-virheet._ | `compile`, `get_compile_log`, `edit_file` |
| _Vastaa avoimiin kommentteihin ja ratkaise ne sitten._ | `list_comments`, `reply_to_comment`, `resolve_comment` |
| _Vaihda XeLaTeXiin ja lataa PDF._ | `update_settings`, `compile`, `get_output_file_link` |
| _Kirjoita tiivistelmä uudelleen seurattuna muutoksena._ | `read_file`, `edit_file` ja `trackChanges` (v6.3.3) |
| _Mikä on muuttunut lähetetyn version jälkeen?_ | `list_versions`, `list_changes`, `diff` (v6.3.3) |
| _Siirrä luvut kansioon nimeltä chapters._ | `move_file` (v6.3.3) |

### Työkalut {#tools}

| Ryhmä | Työkalut |
| --- | --- |
| Projekti | `get_clone_info`, `get_settings`, `update_settings` |
| Tiedostot | `list_files`, `read_file`, `edit_file`, `write_file`, `delete_file`, `move_file`, `create_folder` |
| Kääntäminen | `compile`, `get_compile_log`, `get_output_file_link`, `word_count` |
| Kommentit | `list_comments`, `reply_to_comment`, `resolve_comment`, `reopen_comment`, `add_comment`, `edit_comment_message`, `delete_comment_message` |
| Seuratut muutokset | `list_tracked_changes`, `accept_tracked_changes`, `reject_tracked_changes` |
| Historia | `list_versions`, `list_changes`, `diff`, `create_version`, `delete_version`, `restore_file`, `restore_project` |
| Chat | `list_chat_messages`, `send_chat_message` |

Versiossa v6.3.3 on 33 työkalua, tai 31, kun `OVERLEAF_DISABLE_CHAT=true` poistaa chat-työkalut. Versioissa v6.3.1 ja v6.3.2 on muut 17: kaikki yllä olevat paitsi `move_file`, `create_folder`, `add_comment`, `edit_comment_message`, `delete_comment_message`, seurattujen muutosten työkalut, chat-työkalut ja muut historiatyökalut kuin `list_versions`. Versiossa v6.3.3 `read_file` lukee tiedoston myös historian versiosta, `edit_file` ja `write_file` ottavat vastaan `trackChanges`-parametrin, ja `update_settings` asettaa myös oikoluvun kielen.

Työkaluilla `edit_file`, `write_file` ja `move_file` tehdyt muokkaukset näkyvät editorissa reaaliajassa ja yhdistyvät yhteistyökumppanien muokkauksiin. Monille tiedostoille kerralla tai binääritiedostoille tekoälyasiakas voi myös kloonata projektin Gitillä ja pushata.

Kun `trackChanges` on mukana, olemassa olevan tiedoston muokkaus on tokenin käyttäjän seurattu muutos, vaikka muutosten seuranta olisi projektissa pois päältä; uusi tiedosto ei ole koskaan. Ilman `trackChanges`-parametria muokkaukset noudattavat projektin muutosten seurannan asetusta.

### Käyttöoikeudet {#permissions}

MCP-palvelin noudattaa projektin jakoasetuksia samoin kuin Git:

* Kaikki, jotka voivat tarkastella projektia, voivat lukea sen, kääntää sen ja ladata sen tulosteen.
* Vain omistaja ja muokkaajat voivat muuttaa sen tiedostoja ja asetuksia, palauttaa versioita sekä hyväksyä tai hylätä seurattuja muutoksia.
* Arvioijat voivat myös lisätä kommentteja ja vastata niihin, ratkaista, avata uudelleen tai poistaa aloittamiaan kommentteja sekä tallentaa versioita. He eivät voi muokata tiedostoja, eivät edes seurattuina muutoksina.
* Kukin muokkaa vain omia kommenttiviestejään, ja arvioijat poistavat vain omansa.
* Vain omistaja poistaa muiden tallentamia versioita.
* Linkin kautta liittyneet katselijat eivät näe kommentteja, seurattuja muutoksia, historiaa eivätkä chattia, kuten editorissakaan. Kutsutut katselijat näkevät ne ja voivat käyttää chattia.
* Jos projektin omistajalla ei ole **Full project history** -ominaisuutta, historiatyökalut näyttävät vain viimeisten 24 tunnin muutokset, kuten historiapaneeli. Ylläpitäjät näkevät kaikki.

Käyttöoppaassa on taulukko siitä, mitä kukin rooli saa tehdä, katso [Kuka saa tehdä mitä](/on-premises/user-guide/users/mcp-server#who-may-do-what).

### Q\&A {#q&a}

<Accordion title="En näe editorissa kohtaa Integrations tai MCP server">

<strong>Vastaus:</strong> MCP-palvelimella ei ole omaa ympäristömuuttujaa. Se otetaan käyttöön asetuksella `GIT_BRIDGE_ENABLED=true` tiedostossa `config/overleaf.rc`, katso [Git-integraatio](/fi/on-premises/configuration/overleaf-toolkit/integrations/git-integration). Kun olet muuttanut asetusta, aja `bin/up -d`. Ilman git-bridgeä editori ei näytä **Integrations**-välilehteä vasemmassa palkissaan.

</Accordion>

<Accordion title="Tekoälyasiakas sanoo ”Track changes is off for this project”">

<strong>Vastaus:</strong> Asiakas pyysi seurattua muutosta, mutta projektin omistajan tilillä ei ole muutosten seurantaa. Napsauta **Admin** ja sitten **Manage Users**, avaa omistaja ja ota **Features**-välilehdellä käyttöön **Track changes**, katso [Features](/fi/on-premises/user-guide/administrators/user-management#features). Muokkaukset ilman `trackChanges`-parametria toimivat edelleen.

</Accordion>

<Accordion title="Tekoälyasiakas näkee vain viimeisten 24 tunnin muutokset">

<strong>Vastaus:</strong> Projektin omistajan tilillä ei ole koko projektihistoriaa, joten historiatyökalut näyttävät saman kuin historiapaneeli: viimeisten 24 tunnin muutokset. Napsauta **Admin** ja sitten **Manage Users**, avaa omistaja ja ota **Features**-välilehdellä käyttöön **Full project history**, katso [Features](/fi/on-premises/user-guide/administrators/user-management#features).

</Accordion>
