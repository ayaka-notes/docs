Voit tarkastella palveluiden lokeja `bin/logs`-skriptillä.

Peruskäyttöesimerkkejä:

```bash
# View the web service logs
bin/logs web

# Show help
bin/logs --help

# View logs for multiple services at once
bin/logs filestore docstore web clsi

# Follow log output (like tail -f)
bin/logs -f filestore docstore web clsi

# Limit the number of lines printed (default 50)
bin/logs -n 50 web

# Show all log lines
bin/logs -n all web

# Redirect output to a file
bin/logs -n all web > web.log
```

`bin/logs`-skriptillä voit tarkastella seuraavien palveluiden lokeja: `clsi`, `contacts`, `docstore`, `document-updater`, `filestore`, `git-bridge`, `mongo`, `notifications`, `real-time`, `redis`, `spelling`, `tags`, `track-changes`, `web`, `web-api`, `history-v1`, `project-history`.

## Lokien kopioiminen

Katso alkuperäinen dokumentaatio: https://docs.overleaf.com/on-premises/configuration/overleaf-toolkit/logging#copying-logs

Kopioi lokitiedostot `sharelatex`-pääkontista paikalliselle tietokoneellesi:

```bash
docker cp sharelatex:/var/log/overleaf/{service-name}.log {service-name}.log
```

## Lokien säilyttäminen

Docker-kontit ovat lyhytikäisiä, mikä tarkoittaa, että kontin sisällä ajon aikana luodut tiedostot ja hakemistot (lokitiedostot mukaan lukien) häviävät, jos kontti luodaan uudelleen (esimerkiksi suoritettaessa `bin/up`). Lokitiedostot säilyvät konttien uudelleenluonnin yli seuraavasti:

* Aseta ympäristömuuttuja `OVERLEAF_LOG_PATH` Toolkitin käyttämään `config/overleaf.rc`-tiedostoon. Sen arvon tulee olla isäntäkoneen hakemisto, joka liitetään (bind mount) `sharelatex`-kontin sisäiseen lokihakemistoon.
* Kun olet muuttanut asetuksen ja suorittanut `bin/up -d`, lokitiedostot säilyvät isäntäkoneella ja ovat suoraan käytettävissä.

<Warning>

Liitokseen käytettävän isäntäkoneen lokihakemiston omistajaksi on asetettava `www-data`-käyttäjä (uid=33), ja oikeuksien on oltava `drwxr-xr-x` (755).

Esimerkki:

```bash
chown 33:33 data/overleaf/logs
chmod 755 data/overleaf/logs
```

</Warning>
