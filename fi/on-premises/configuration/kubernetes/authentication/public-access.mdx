Vieraiden pääsy jaettuihin projekteihin, julkiset sivut ja itserekisteröityminen otetaan käyttöön ympäristömuuttujilla, jotka **web**-palvelu lukee; reaaliaikapalvelu palvelee sitten vieraita heidän istuntonsa kautta. Se, mitä kukin kytkin avaa, on kuvattu sivulla [Julkinen käyttö](/fi/on-premises/configuration/overleaf-toolkit/authentication/public-access).

| | |
| --- | --- |
| Palvelu | web (ja reaaliaikapalvelu editorissa oleville vieraille), jokaisessa Ayakaleaf Pro -podissa; luetaan, kun web käynnistyy |
| Pod → ulkoverkko | SMTP-palvelin, kun rekisteröityminen lähettää aktivointisähköposteja |
| Tila | vieraiden käyttötunnisteet istunnossa, rekisteröitymisen nopeusrajoitukset Redisissä |
| Ajastetut tehtävät | ei mitään |

### Konfiguraatio

Lisää tarvitsemasi kytkimet ConfigMapiin `overleaf-env`:

```yaml title="30-config.yaml (additions)"
  # Guests open link-shared projects without an account
  OVERLEAF_ALLOW_ANONYMOUS_READ_AND_WRITE_SHARING: "true"
  # Signed-out visitors may open /learn, /templates, /devs and view links
  OVERLEAF_ALLOW_PUBLIC_ACCESS: "true"
  # Self-registration: "true", or only some domains
  OVERLEAF_ALLOW_PUBLIC_REGISTRATION: "@example.com, @*.uni.example"
```

```bash
kubectl apply -f 30-config.yaml
kubectl -n overleaf rollout restart deployment/overleaf     # or statefulset/overleaf
```

Lainausmerkitse jokainen arvo. Merkillä `@` alkavat arvot on lainausmerkittävä YAML:ssa, muuten `kubectl apply` hylkää tiedoston.

Verkkotunnuksiin rajattu rekisteröityminen lähettää aktivointisähköpostin, joten [sähköpostin toimituksen](/fi/on-premises/configuration/kubernetes/email-delivery) on toimittava podeista: vie SMTP-isäntä ConfigMapiin ja `OVERLEAF_EMAIL_SMTP_PASS` Secretiin.

### Useita replikoita

Mitään ylimääräistä ei tarvita. Vieraan pääsy projektiin säilytetään Redisissä olevassa istunnossa, joten editori toimii millä tahansa replikalla, jonka kuormantasaaja valitsee.

### Testattu Kubernetesissa

Kubernetes 1.37:ssä julkisen pääsyn päästä päähän -testimme menevät läpi: yhdellä replikalla itserekisteröityminen, kun `OVERLEAF_ALLOW_PUBLIC_REGISTRATION` on asetettu arvoon `true`, yhteen verkkotunnukseen, useisiin verkkotunnuksiin aliverkkotunnusten jokerimerkillä ja arvoon `@*`, verkkotunnustiloissa aktivointisähköpostin kanssa (43 tapausta); kirjautumattomat vierailijat sivulla `/devs` ja lähetetty koodinpätkä, joka säilyy kirjautumisen yli asetuksella `OVERLEAF_ALLOW_PUBLIC_ACCESS` (2 tapausta); kirjautumaton vieras linkillä jaetussa projektissa molempien kytkimien ollessa päällä (3 tapausta); sekä kolmella replikalla HAProxyn takana OIDC yhdessä julkisen pääsyn kanssa (1 tapaus).
