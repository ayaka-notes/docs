---
title: Horisontaalinen skaalaus
description: Aja useita Ayakaleaf Pro -replikoita kuormantasaajan takana pysyvillä istunnoilla.
icon: layer-group
---

Yksi replika käyttää jokaiseen käännökseen yhden solmun suoritinta: testisolmuillamme, joissa oli 2 vCPU:ta, kuusi samanaikaista käännöstä kesti kolme kertaa niin kauan kuin yksi, kun taas muut solmut olivat joutilaina. Useat replikat jakavat käyttäjät ja heidän käännöksensä solmujen kesken.

Tämä noudattaa Overleafin [Horisontaalinen skaalaus](/fi/on-premises/maintenance/horizontal-scaling) -mallia Kubernetesiin sovitettuna:

| Vaatimus                                            | Tässä                                                                 |
| --------------------------------------------------- | --------------------------------------------------------------------- |
| Jaettu MongoDB ja Redis                             | asennuksen `10-mongo.yaml` ja `20-redis.yaml`                          |
| Jaetut salaisuudet                                  | [vaiheen 2](/fi/on-premises/installation/using-kubernetes/2.-create-the-namespace-and-secrets) Secretissä `overleaf-secrets` ne ovat jo |
| Projektitiedostot ja historia **S3**:ssa (ei NFS)    | mikä tahansa S3-palvelu, katso [S3](/fi/on-premises/configuration/kubernetes/s3); siellä Garage klusterin sisäisenä esimerkkinä |
| Paikallinen levy jokaiselle replikalle käännöksiä ja latauksia varten | `hostPath` `/srv/overleaf-ha` jokaisella solmulla      |
| Pysyvä reititys, WebSocketit, 10 min aikakatkaisut, 50 Mt:n lataukset | HAProxy Overleafin esimerkkikonfiguraatiolla            |
| git-bridge yksittäisenä instanssina yhden replikan rinnalla | git-bridge, jonka sisarena on `overleaf-0`                     |

<Warning>

Suunnittele S3 alusta alkaen. Instanssi, joka jo säilyttää tiedostoja taltiollaan, tarvitsee ensin [S3-siirron](/fi/on-premises/maintenance/s3-migration). Tämä kokoonpano korvaa vaiheen 5 Deploymentin: poista se (`kubectl delete -f 40-overleaf.yaml`) ennen kuin otat StatefulSetin käyttöön.

</Warning>

<Steps>
<Step title="S3-tallennustila">
Luo kolme bucketia ja kaksi käyttäjää sivun [S3](/fi/on-premises/configuration/kubernetes/s3) mukaisesti omalla S3-palvelullasi tai klusterin sisäisellä Garagella, ja vie neljä avainta Secretiin `overleaf-s3`. Alla oleva konfiguraatio käyttää kyseisen sivun Garage-esimerkkiä.
</Step>

<Step title="Konfiguraatio">
Tämä ConfigMap korvaa tiedoston `30-config.yaml`. Se lisää S3:n ja git-bridgen ja osoittaa `OVERLEAF_SITE_URL`-arvon kuormantasaajaan:

```yaml title="60-config.yaml" wrap

  # Emails: add the sender and the SMTP server together, see Email delivery
  OVERLEAF_MONGO_URL: mongodb://mongo-0.mongo:27017,mongo-1.mongo:27017,mongo-2.mongo:27017/sharelatex?replicaSet=overleaf
  OVERLEAF_REDIS_HOST: redis
  REDIS_HOST: redis
  ENABLED_LINKED_FILE_TYPES: project_file,project_output_file,url
  ENABLE_CONVERSIONS: "true"
  EMAIL_CONFIRMATION_DISABLED: "true"
  OVERLEAF_TRUSTED_PROXY_IPS: loopback,10.244.0.0/16   # HAProxy runs in the pod CIDR
  # Sandboxed compiles, node paths: each replica owns /srv/overleaf-ha on its node
  SANDBOXED_COMPILES: "true"
  SANDBOXED_COMPILES_SIBLING_CONTAINERS: "true"

  SANDBOXED_COMPILES_HOST_DIR_COMPILES: /srv/overleaf-ha/data/compiles
```

</Step>

<Step title="Replikat">
```yaml title="70-overleaf.yaml" wrap
apiVersion: v1
kind: Service
metadata:
  name: overleaf-hl
  namespace: overleaf
spec:
  clusterIP: None            # stable DNS per replica: overleaf-0.overleaf-hl, ...
  selector:
    app: overleaf-ha
  ports:
    - {name: http, port: 80}
    - {name: web, port: 3000}       # git-bridge API (sibling only)
    - {name: history, port: 3100}   # history-v1, used by git-bridge via V1_HISTORY_URL
---
apiVersion: apps/v1
kind: StatefulSet
metadata:
  name: overleaf
  namespace: overleaf
spec:
  serviceName: overleaf-hl
  replicas: 3
  # OrderedReady: overleaf-0 runs the migrations alone before the next replica starts
  podManagementPolicy: OrderedReady
  selector:
    matchLabels:
      app: overleaf-ha
  template:
    metadata:
      labels:
        app: overleaf-ha
    spec:
      terminationGracePeriodSeconds: 60
      # Keep the environment to the ConfigMap and Secrets: no REDIS_PORT=tcp://..., GIT_BRIDGE_PORT=tcp://...
      enableServiceLinks: false
      affinity:
        podAntiAffinity:            # one replica per node: each uses that node's Docker and disk
          requiredDuringSchedulingIgnoredDuringExecution:
            - labelSelector:
                matchLabels:
                  app: overleaf-ha
              topologyKey: kubernetes.io/hostname
      containers:
        - name: sharelatex
          image: ghcr.io/ayaka-notes/overleaf-pro:6.3.2
          env:
            - name: POD_NAME
              valueFrom:
                fieldRef:
                  fieldPath: metadata.name
            # Each replica hands out history URLs with its own stable name, so git-bridge can reach them
            - name: V1_HISTORY_URL
              value: http://$(POD_NAME).overleaf-hl.overleaf.svc.cluster.local:3100/api
          envFrom:
            - configMapRef: {name: overleaf-env}
            - secretRef: {name: overleaf-secrets}
            - secretRef: {name: overleaf-s3}
          ports:
            - containerPort: 80
          readinessProbe:
            httpGet: {path: /status, port: 80}
            periodSeconds: 10
          resources:
            requests: {cpu: 500m, memory: 1536Mi}
            limits: {memory: 3Gi}
          volumeMounts:
            - {name: local, mountPath: /var/lib/overleaf}
            - {name: docker-sock, mountPath: /var/run/docker.sock}
      volumes:
        # Local disk for ephemeral files (compiles, output, uploads); the HOST_DIR_* paths are under it
        - name: local
          hostPath: {path: /srv/overleaf-ha, type: DirectoryOrCreate}
        - name: docker-sock
          hostPath: {path: /var/run/docker.sock, type: Socket}
```

* <strong>StatefulSet, ei Deployment.</strong> Jokainen replika saa pysyvän nimen (`overleaf-0`, `overleaf-1`, ...), johon kuormantasaajan eväste ja git-bridge viittaavat, ja `OrderedReady` käynnistää ensin `overleaf-0`:n yksinään, joten vain yksi replika ajaa tietokantamigraatiot.
* <strong>Yksi replika solmua kohden.</strong> Jokainen replika käynnistää käännöksensä solmunsa Dockerin kautta ja säilyttää ne solmunsa hakemistossa `/srv/overleaf-ha`.
* <strong>`V1_HISTORY_URL` replikakohtaisesti.</strong> Jokainen replika jakaa historialinkit omalla nimellään, jotta git-bridge tavoittaa ne.
</Step>

<Step title="git-bridge">
```yaml title="75-git-bridge.yaml" wrap
apiVersion: v1
kind: Service
metadata:
  name: git-bridge
  namespace: overleaf
spec:
  # Fixed ClusterIP (inside the service CIDR): the sharelatex image's nginx proxies /git/ with
  # `resolver 127.0.0.11` (Docker's DNS), which does not exist in Kubernetes, so GIT_BRIDGE_HOST is this IP
  clusterIP: 10.96.100.80
  selector:
    app: git-bridge
  ports:
    - {name: http, port: 8000}
---
apiVersion: apps/v1
kind: StatefulSet
metadata:
  name: git-bridge
  namespace: overleaf
spec:
  serviceName: git-bridge
  replicas: 1
  selector:
    matchLabels:
      app: git-bridge
  template:
    metadata:
      labels:
        app: git-bridge
    spec:
      # Service "git-bridge" would inject GIT_BRIDGE_PORT=tcp://..., which git-bridge reads as its port
      enableServiceLinks: false
      containers:
        - name: git-bridge
          image: ghcr.io/ayaka-notes/overleaf-pro/git-bridge:6.3.2   # same version as the sharelatex image
          command: ["/server-pro-start.sh"]
          securityContext:
            runAsUser: 0
          env:
            - {name: GIT_BRIDGE_API_BASE_URL, value: "http://overleaf-0.overleaf-hl.overleaf.svc.cluster.local:3000/api/v0/"}
            - {name: GIT_BRIDGE_OAUTH2_SERVER, value: "http://overleaf-0.overleaf-hl.overleaf.svc.cluster.local"}
            - {name: GIT_BRIDGE_POSTBACK_BASE_URL, value: "http://git-bridge.overleaf.svc.cluster.local:8000"}
            - {name: GIT_BRIDGE_ROOT_DIR, value: /data/git-bridge}
          ports:
            - containerPort: 8000
          resources:
            requests: {cpu: 100m, memory: 256Mi}
            limits: {memory: 768Mi}
          volumeMounts:
            - {name: data, mountPath: /data/git-bridge}
  volumeClaimTemplates:
    - metadata:
        name: data
      spec:
        accessModes: [ReadWriteOnce]
        resources:
          requests:
            storage: 5Gi
```

Katso sivulta [Git-integraatio](/fi/on-premises/configuration/kubernetes/integrations/git-integration), miksi `GIT_BRIDGE_HOST` on kiinteä IP-osoite.
</Step>

<Step title="Kuormantasaaja">
HAProxy-konfiguraatio on Overleafin esimerkki viidellä muutoksella: `/project/<id>/mcp` reititetään `overleaf-0`:lle kuten `/git/` (katso [MCP-palvelin](/fi/on-premises/configuration/kubernetes/integrations/mcp-server#several-replicas)), pelkkä HTTP portissa `8080` (image toimii ei-root-käyttäjänä, joka ei voi sitoa porttia 80 containerd:n alla), palvelimet löydetään klusterin DNS:n kautta (podien IP-osoitteet vaihtuvat jokaisella uudelleenkäynnistyksellä), DaemonSet, jotta jokainen solmu vastaa, sekä `balance leastconn` oletusarvon `roundrobin` sijaan (katso alla olevat kysymykset ja vastaukset).

```yaml title="80-haproxy.yaml" wrap
apiVersion: v1
kind: ConfigMap
metadata:
  name: haproxy-config
  namespace: overleaf
data:
  haproxy.cfg: |
    global
      log stdout format raw local0 info

    resolvers kubedns
      parse-resolv-conf
      hold valid 10s

    defaults
      mode                    http
      # New sessions go to the replica with the fewest open connections (editors keep a WebSocket open)
      balance                 leastconn
      option                  httpchk HEAD /status
      http-check              expect status 200
      default-server          check resolvers kubedns init-addr none
      log                     global
      option                  httplog
      # Reroute to a different backend if the sticky one is down
      option                  redispatch 1
      retries                 3
      # Sticky session for 24h of inactivity -- compile output is deleted after 24h
      cookie                  server-pro-ha insert maxidle 24h
      timeout queue           1m
      timeout connect         15s
      timeout client          1m
      # Allow slow compiles -- hard-coded limit in clsi is 10min
      timeout server          10m
      # Disconnect the editor after 23h
      timeout tunnel          23h
      # Lower than NGINX_KEEPALIVE_TIMEOUT (65s) in the sharelatex container
      timeout http-keep-alive 60s

    listen overleaf
      bind :8080
      option forwardfor
      # When TLS ends in front of HAProxy, also pass:  http-request set-header X-Forwarded-Proto https
      # git requests go to the git-bridge sibling
      use-server overleaf-0 if { path_beg /git/ }
      # MCP clients send no cookie: keep compile, log and PDF download on one replica
      use-server overleaf-0 if { path_reg ^/project/[0-9a-f]{24}/mcp(/|$) }
      http-response add-header X-Served-By %s
      stats enable
      stats uri /haproxy
      server overleaf-0 overleaf-0.overleaf-hl.overleaf.svc.cluster.local:80 cookie overleaf-0
      server overleaf-1 overleaf-1.overleaf-hl.overleaf.svc.cluster.local:80 cookie overleaf-1
      server overleaf-2 overleaf-2.overleaf-hl.overleaf.svc.cluster.local:80 cookie overleaf-2
---
apiVersion: apps/v1
# DaemonSet: one HAProxy per node, so the NodePort answers on every node with externalTrafficPolicy
# Local. The cookie holds the replica name, so stickiness works whichever HAProxy a request hits.
kind: DaemonSet
metadata:
  name: haproxy
  namespace: overleaf
spec:
  selector:
    matchLabels:
      app: haproxy
  template:
    metadata:
      labels:
        app: haproxy
      annotations:
        config-hash: "1"   # bump to restart after editing the ConfigMap
    spec:
      containers:
        - name: haproxy
          image: haproxy:lts-alpine
          ports:
            - containerPort: 8080
          resources:
            requests: {cpu: 50m, memory: 32Mi}
            limits: {memory: 256Mi}
          volumeMounts:
            - {name: config, mountPath: /usr/local/etc/haproxy}
      volumes:
        - name: config
          configMap:
            name: haproxy-config
---
apiVersion: v1
kind: Service
metadata:
  name: haproxy
  namespace: overleaf
spec:
  type: NodePort
  externalTrafficPolicy: Local    # keep the client IP (no SNAT); only nodes running HAProxy answer
  selector:
    app: haproxy
  ports:
    - {name: http, port: 80, targetPort: 8080, nodePort: 30081}
```

```bash
kubectl delete -f 40-overleaf.yaml --ignore-not-found
kubectl apply -f 60-config.yaml -f 70-overleaf.yaml -f 75-git-bridge.yaml -f 80-haproxy.yaml
kubectl -n overleaf rollout status statefulset/overleaf --timeout=20m
curl -sI http://192.0.2.10:30081/login | grep -i x-served-by
```

`externalTrafficPolicy: Local` säilyttää käyttäjien IP-osoitteet otsakkeessa `X-Forwarded-For`.
</Step>

### Mitä odottaa

Testasimme kolmea replikaa kolmella solmulla, joissa kussakin oli 2 vCPU:ta ja 4 Gt muistia, ja MongoDB, Redis, Garage, git-bridge ja HAProxy olivat samoilla solmuilla:

* 12 käyttäjää käänsi 600-sivuista dokumenttia samanaikaisesti: kaikki 12 käänsivät ja noutivat PDF:nsä, 4 käyttäjää replikaa kohden; kierros kesti 8–18 sekuntia. Jokaisella solmulla oli vähintään 1,3 Gt muistia vapaana.
* Jokainen käyttäjä pysyy yhdellä replikalla (eväste `server-pro-ha`), mukaan lukien PDF-lataus, jonka on tultava sen kääntäneeltä replikalta. Sama pätee HTTPS:n yli, mukaan lukien editorin WebSocket.
* Kun replika pysähtyy, sen käyttäjät saavat virheitä noin 15–20 sekunnin ajan, kunnes HAProxy merkitsee sen alhaalla olevaksi; sitten he siirtyvät toiselle replikalle ja pysyvät kirjautuneina, koska istunnot ovat Redisissä.

### Kysymyksiä ja vastauksia

<Accordion title="Miksi `balance leastconn`?">

<strong>Vastaus:</strong> Overleafin esimerkillä (`roundrobin`, yksi HAProxy solmua kohden) 12 uutta käyttäjää jakautui testissämme kolmelle replikalle 8, 3 ja 1, ja kuormitetuin replika pani hitaimmat käyttäjät odottamaan 29 sekuntia. Asetuksella `leastconn`, joka suosii replikaa, jolla on vähiten avoimia yhteyksiä (jokainen editori pitää WebSocketin auki), sama testi antoi 4, 4 ja 4 sekä 18 sekuntia. Pysyvyys ei muutu: se perustuu evästeeseen.

</Accordion>

<Accordion title="Voinko käyttää ingress-ohjaintani HAProxyn sijaan?">

<strong>Vastaus:</strong> Kyllä, jos se reitittää evästeen perusteella pysyvälle replikalle, tukee WebSocketeja, sallii 10 minuutin pyyntöajat ja 50 Mt:n lataukset, pitää keep-alive-aikakatkaisunsa alle 65 sekunnissa, lähettää otsakkeet `X-Forwarded-For` ja `X-Forwarded-Proto` sekä ohjaa `/git/`- ja `/project/<id>/mcp`-pyynnöt `overleaf-0`:lle. Reititä replikoiden omiin nimiin (`overleaf-N.overleaf-hl`), älä Serviceen, joka tasaa jokaisen pyynnön.

</Accordion>

<Accordion title="Miten lisään neljännen replikan?">

<strong>Vastaus:</strong> Lisää solmu, jossa on Docker ja TeX Live -imaget, aseta `replicas: 4` tiedostoon `70-overleaf.yaml` ja lisää HAProxy-konfiguraatioon rivi `server overleaf-3 ...` (ja kasvata `config-hash`-arvoa, jotta HAProxy käynnistyy uudelleen).

</Accordion>
