`/learn`-sivut tarjoaa jokaisen Ayakaleaf Pro -podin **web**-palvelu (`learn`-moduuli) välimuistista, joka on ladattu muuttujassa `WIKI_URL` asetetusta wikistä. Moduulin toiminta ja se, mitkä wikit toimivat, on kuvattu sivulla [LaTeX-käyttäjäohjeiden lisääminen](/fi/on-premises/configuration/overleaf-toolkit/adding-latex-user-help).

| | |
| --- | --- |
| Palvelu | web (`learn`-moduuli), jokaisessa Ayakaleaf Pro -podissa |
| Pod → ulkoverkko | `WIKI_URL` (oletus `https://learnwiki.overleaf.com`): jokainen sivu ensimmäisellä käynnistyskerralla, sen jälkeen sivu uudelleen, kun käyttäjä avaa sen ajan `WIKI_MAX_CACHE_AGE` kuluttua |
| Selain → ulkoverkko | sivujen kuvat suoraan osoitteesta `WIKI_URL` |
| Tallennetut tiedot | sivuvälimuisti hakemistossa `/var/lib/overleaf/data/learnPages` datataltiolla |
| Ajastetut tehtävät | ei mitään: sivut päivitetään, kun käyttäjät avaavat ne |

### Konfiguraatio

```yaml title="30-config.yaml (additions)"
  OVERLEAF_PROXY_LEARN: "true"
  # optional: your own MediaWiki
  # WIKI_URL: https://wiki.example.com
```

```bash
kubectl apply -f 30-config.yaml
kubectl -n overleaf rollout restart deployment/overleaf     # or statefulset/overleaf
kubectl -n overleaf rollout status deployment/overleaf --timeout=30m
```

<Warning>

Kun moduuli on käytössä, web-palvelu lataa ensimmäisellä käynnistyskerrallaan koko wikin ennen kuin se ottaa vastaan pyyntöjä, mikä kestää useita minuutteja. Pod pysyy siihen asti ei-valmiina, joten varaa tälle aikaa `rollout status --timeout` -asetuksessa ja kaikissa lisäämissäsi käynnistys- tai liveness-tarkistuksissa. Myöhemmät käynnistykset käyttävät datataltiolla olevaa välimuistia.

</Warning>

Ensimmäisellä käynnistyskerralla, ennen kuin välimuistia on olemassa, podien on tavoitettava `WIKI_URL`: muuten web-palvelu epäonnistuu käynnistyessään ja käynnistetään podin sisällä uudelleen yhä uudelleen, joten pod ei koskaan tule valmiiksi. Poista moduuli käytöstä tai salli podien yhteys wikiin. Kun välimuisti on olemassa, podit käynnistyvät ja tarjoavat välimuistissa olevia sivuja myös silloin, kun wikiä ei tavoiteta.

### Useita replikoita

Jokainen replika pitää omaa välimuistiaan oman solmunsa levyllä, joten jokainen lataa wikin ensimmäisellä käynnistyskerrallaan; asetuksella `podManagementPolicy: OrderedReady` ne tekevät sen yksi kerrallaan. Käyttäjä saattaa nähdä sivusta hieman eri version toisella replikalla, kunnes sivu päivitetään siellä.

### Testattu Kubernetesissa

Kubernetes 1.37:ssä kolmella replikalla HAProxyn takana, joista kukin latasi osoitteen `https://learnwiki.overleaf.com` oman solmunsa välimuistiin ensimmäisellä käynnistyskerrallaan, `/learn`-polun päästä päähän -testimme menevät läpi (12 tapausta): ylätunnisteen Documentation-linkki, tervetuloviesti ja editorin Help-valikko, sisällysluettelon sivupalkki, wikin sisäiset sivut, linkit ja uudelleenohjaukset, wikistä ladatut kuvat, 404 tuntemattomille sivuille, vaadittu kirjautuminen ilman julkista pääsyä sekä välimuistista tarjottu vanhentunut sivu sen jälkeen, kun `WIKI_URL` oli vaihdettu osoitteeseen, jota ei tavoiteta. Kun käynnistettiin tyhjällä välimuistilla ja `WIKI_URL` osoitti osoitteeseen, joka hylkää yhteydet, pod pysyi ei-valmiina käynnistymättä uudelleen, kun taas sen sisällä oleva web-palvelu käynnistyi ja epäonnistui 77 kertaa kolmessa minuutissa.
