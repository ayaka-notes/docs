Pandoc-muunnokset suorittaa jokaisen Ayakaleaf Pro -podin **clsi**-palvelu, kuten käännökset: clsi pyytää solmun Docker Engineä käynnistämään kontin `PANDOC_IMAGE`-imagesta. **web**-palvelu näyttää tuonti- ja vientivalikot. Ominaisuuden toiminta ja imagen rakentaminen on kuvattu sivulla [Pandoc-tuonti ja -vienti](/fi/on-premises/configuration/overleaf-toolkit/pandoc-import-and-export).

| | |
| --- | --- |
| Palvelut | web (valikot ja reitit), clsi (suorittaa muunnoksen), jokaisessa Ayakaleaf Pro -podissa |
| Solmu | Docker Engine ja `PANDOC_IMAGE` jokaisella solmulla, joka voi ajaa Ayakaleaf Prota |
| Edellyttää | [Hiekkalaatikkokäännökset](/fi/on-premises/configuration/kubernetes/sandboxed-compiles) |
| Ajastetut tehtävät | ei mitään |

### Konfigurointi

<Steps>
<Step title="Vie image Dockeriin jokaisella solmulla">
Rakenna image kerran [ayakaleaf-pro](https://github.com/ayaka-notes/ayakaleaf-pro)-repositorion `develop/pandoc`-kansiosta ja lataa se sitten Dockeriin jokaisella solmulla, joka voi ajaa Ayakaleaf Prota:

```bash
docker build -t overleaf-pandoc:local develop/pandoc
docker save overleaf-pandoc:local | ssh node-1 sudo docker load    # repeat for every node
```

Tai pushaa se rekisteriin, jonka solmut tavoittavat, ja hae se jokaisella solmulla komennolla `sudo docker pull`. Kuten TeX Live -imageiden kohdalla, sen on oltava **Dockerissa**, ei pelkästään containerd:ssä.
</Step>

<Step title="ConfigMap">
```yaml
  ENABLE_PANDOC_CONVERSIONS: "true"
  PANDOC_IMAGE: overleaf-pandoc:local
```

Sekä web että clsi lukevat `ENABLE_PANDOC_CONVERSIONS`-asetuksen samasta ConfigMapista, joten ne eivät voi olla Kubernetesissa eri mieltä.
</Step>

<Step title="Ota käyttöön ja käynnistä uudelleen">
```bash
kubectl apply -f 30-config.yaml
kubectl -n overleaf rollout restart deployment/overleaf     # or statefulset/overleaf
```
</Step>
</Steps>

### Useita replikoita

Mitään ylimääräistä ei tarvita sen lisäksi, että image on jokaisella solmulla: jokainen replika tekee muunnokset omalla solmullaan.

### Testattu Kubernetesissa

Kun image oli rakennettu `develop/pandoc`-kansiosta ja ladattu Dockeriin jokaisella solmulla komennolla `docker save | docker load`, Kubernetes 1.37:ssä yhdellä replikalla Pandocin päästä päähän -testimme menevät läpi (6 tapausta): Markdown-dokumentin tuonti LaTeX-projektiksi, rikkinäisestä Word-dokumentista näytettävä virhe, vienti Wordiin (joka voidaan tuoda uudelleen), Markdowniin ja HTML:ään sekä valikoiden piilottaminen ilman `ENABLE_PANDOC_CONVERSIONS`-asetusta.
