**web**-palvelu lähettää kaikki sähköpostit (aktivointi, projektikutsut, salasanan palautus) jokaisesta Ayakaleaf Pro -podista. Asetukset ovat samat kuin Toolkitissa, katso [Sähköpostin toimitus](/fi/on-premises/configuration/overleaf-toolkit/email-delivery).

| | |
| --- | --- |
| Palvelu | web, jokaisessa Ayakaleaf Pro -podissa; luetaan, kun web käynnistyy |
| Pod → ulkoverkko | SMTP-palvelimesi (`OVERLEAF_EMAIL_SMTP_HOST`) tai alueen `OVERLEAF_EMAIL_AWS_SES_REGION` Amazon SES -API |
| Tila | lähetyksen nopeusrajoitus Redisissä |
| Ajastetut tehtävät | ei mitään |

### Konfiguraatio {#configuration}

<Steps>
<Step title="ConfigMap">
```yaml title="30-config.yaml (additions)" wrap
  OVERLEAF_EMAIL_FROM_ADDRESS: no-reply@example.com
  OVERLEAF_EMAIL_SMTP_HOST: smtp.example.com
  OVERLEAF_EMAIL_SMTP_PORT: "587"
  OVERLEAF_EMAIL_SMTP_SECURE: "false"
  OVERLEAF_EMAIL_SMTP_USER: no-reply@example.com
  # optional
  # OVERLEAF_EMAIL_REPLY_TO: support@example.com
  # OVERLEAF_EMAIL_SMTP_IGNORE_TLS: "false"
  # OVERLEAF_EMAIL_SMTP_TLS_REJECT_UNAUTH: "true"
```

`OVERLEAF_EMAIL_FROM_ADDRESS` ottaa lähettämisen käyttöön. Aseta se vain yhdessä SMTP-palvelimen (tai SES:n) kanssa: pelkällä lähettäjällä Ayakaleaf Pro yrittää käyttää podin sisäistä SMTP-palvelinta, ja jokainen sähköposti epäonnistuu. Ilman sitä sähköposteja ei lähetetä, vaan ne vain kirjoitetaan tiedostoon `web.log`.

`OVERLEAF_EMAIL_SMTP_SECURE`, `OVERLEAF_EMAIL_SMTP_IGNORE_TLS` ja `OVERLEAF_EMAIL_SMTP_TLS_REJECT_UNAUTH` luetaan JSON-muodossa, joten käytä arvoa `"true"` tai `"false"`: esimerkiksi arvo `yes` pysäyttää podin kaikki palvelut käynnistyksessä.
</Step>

<Step title="Secret">
```bash
kubectl -n overleaf patch secret overleaf-secrets --type merge \
  -p '{"stringData":{"OVERLEAF_EMAIL_SMTP_PASS":"<SMTP password>"}}'
```

Amazon SES -API:a varten vie tähän sen sijaan `OVERLEAF_EMAIL_AWS_SES_ACCESS_KEY_ID` ja `OVERLEAF_EMAIL_AWS_SES_SECRET_KEY`, ja ConfigMapiin `OVERLEAF_EMAIL_DRIVER: ses` sekä `OVERLEAF_EMAIL_AWS_SES_REGION`.
</Step>

<Step title="Ota käyttöön, käynnistä uudelleen ja testaa">
```bash
kubectl apply -f 30-config.yaml
kubectl -n overleaf rollout restart deployment/overleaf     # or statefulset/overleaf
```

Lähetä itsellesi salasanan palautussähköposti kirjautumissivulta. Jos se ei saavu, tarkista, että SMTP-palvelin on tavoitettavissa podeista, ja katso web-lokia:

```bash
kubectl -n overleaf exec deploy/overleaf -- bash -c 'echo > /dev/tcp/smtp.example.com/587 && echo reachable'
kubectl -n overleaf exec deploy/overleaf -- grep -iE "email|smtp" /var/log/overleaf/web.log | tail
```
</Step>
</Steps>

### Useita sähköpostiosoitteita tiliä kohden {#several-emails-per-account}

Mitään muuta ei tarvitse määrittää: kun sähköposti toimii, käyttäjät voivat lisätä tililleen sähköpostiosoitteita ja siirtää tilin johonkin niistä. Säännöt ovat kohdassa [Useita sähköpostiosoitteita tiliä kohden](/fi/on-premises/configuration/overleaf-toolkit/email-delivery#several-emails-per-account) ja vaiheet [käyttöoppaassa](/on-premises/user-guide/users/multiple-emails). Vahvistuskoodi säilytetään käyttäjän istunnossa Redisissä.

### Useita replikoita {#several-replicas}

Mitään ylimääräistä ei tarvita. Jokainen replika lähettää samoilla asetuksilla, ja lähetyksen nopeusrajoitus lasketaan Redisissä kaikkien replikoiden yli. Jos SMTP-palvelimesi hyväksyy vain tunnetut lähettäjät, salli ne osoitteet, joista podit lähtevät klusterista (yleensä solmujen osoitteet).

### Testattu Kubernetesissa {#tested-on-kubernetes}

Kun SMTP-palvelimena oli Mailpit, Kubernetes 1.37:ssä yhdellä replikalla, sähköpostia lähettävät päästä päähän -testimme menevät läpi: ylläpitäjän luoman tilin aktivointisähköposti, verkkotunnuksiin rajatun itserekisteröitymisen aktivointisähköposti, salasanan palautussähköposti, sähköposti, joka kertoo käyttäjälle tilin poistamisesta, sekä se, mitä tapahtuu, kun SMTP-palvelin hylkää aktivointi- tai poistosähköpostin: tili luodaan tai poistetaan silti, ja aktivointisähköpostin voi lähettää uudelleen myöhemmin. Kun `OVERLEAF_EMAIL_FROM_ADDRESS` oli asetettu ilman SMTP-isäntää, salasanan palautuspyyntö epäonnistui virheeseen ja `web.log` näytti ”error sending message”, kuten yllä on kuvattu.
