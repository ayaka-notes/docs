Kunkin projektin MCP-palvelin toimii jokaisen Ayakaleaf Pro -podin **web**-palvelussa (`mcp-server`-moduuli). Se tulee [Git-integraation](/fi/on-premises/configuration/kubernetes/integrations/git-integration) mukana, eikä sillä ole omia asetuksia. Claude Coden, Codexin ja muiden asiakkaiden yhdistäminen on kuvattu sivulla [MCP-palvelin](/fi/on-premises/configuration/overleaf-toolkit/integrations/mcp-server).

| | |
| --- | --- |
| Palvelu | web, jokaisessa Ayakaleaf Pro -podissa |
| Käyttöön ottaa | `GIT_BRIDGE_ENABLED: "true"` ja git-bridge-StatefulSet, katso [Git-integraatio](/fi/on-premises/configuration/kubernetes/integrations/git-integration) |
| Ulkopuoli → Overleaf | tekoälyasiakkaat lähettävät `POST ${OVERLEAF_SITE_URL}/project/<id>/mcp` Git-todennustunnuksella; PDF-latauslinkit polun `${OVERLEAF_SITE_URL}/project/<id>/mcp/download/` alla |
| Pod → ulkopuoli | ei mitään |
| Tila | ei mitään pyyntöjen välillä; käännöstulosteet jäävät podiin, joka käänsi |
| Ajastetut tehtävät | ei mitään |

### Konfigurointi

Määritä [Git-integraatio](/fi/on-premises/configuration/kubernetes/integrations/git-integration). MCP-palvelin on sen jälkeen osoitteessa `${OVERLEAF_SITE_URL}/project/<project id>/mcp`, ja osoitteen on oltava tavoitettavissa sieltä, missä tekoälyasiakas toimii.

### Useita replikoita

MCP:n kautta tehty käännös suoritetaan replikalla, joka vastaanotti pyynnön, ja sen loki ja PDF ovat olemassa vain siellä. Tekoälyasiakkaat eivät lähetä evästettä, joten kuormantasaaja voi ohjata seuraavan pyynnön, `get_compile_log`-kutsun tai PDF-latauslinkin, toiselle replikalle, joka vastaa ”failed to fetch output file from CLSI” tai 404. Testissämme kolmella replikalla ilman lisäsääntöä 6 lokipyynnöstä 5 ja 4 latauksesta 3 epäonnistui tällä tavalla.

Ohjaa projektin jokainen MCP-pyyntö yhdelle replikalle, kuten polulle `/git/`. Kun käytössä on HAProxy sivulta [Horisontaalinen skaalaus](/fi/on-premises/configuration/kubernetes/horizontal-scaling):

```text
      use-server overleaf-0 if { path_reg ^/project/[0-9a-f]{24}/mcp(/|$) }
```

Kaikki MCP-käännökset suoritetaan tällöin `overleaf-0`:n solmulla. Jos käytät toista ingress-ohjainta, ohjaa polku `/project/<id>/mcp` ja kaikki sen alla oleva yhden replikan omaan nimeen (`overleaf-0.overleaf-hl`).

Tällä säännöllä sama testi (käännös, 6 lokipyyntöä ja 4 PDF-latausta, kaikki ilman evästettä) onnistui joka kerta.

### Testattu Kubernetesissa

Kubernetes 1.37:ssä kolmella replikalla HAProxyn takana MCP-palvelimen päästä päähän -testimme menevät läpi (37 tapausta): työkalujen listaus, väärien, poistettujen tai ilman käyttöoikeutta olevien tunnusten hylkääminen, kääntäminen ja lokin lukeminen, sanamäärä, projektin asetukset ja historia, PDF-latauslinkit, tiedostojen muokkaaminen niin, että muutokset näkyvät reaaliaikaisesti avoimessa editorissa ja vedetään Git-kloonaukseen, kommentit, roolikohtainen käyttöoikeus, käännösten ja asetusten käyttörajoitukset sekä jäädytetyt tilit. Nämä pyynnöt tulivat selainistunnosta, joten kuormantasaaja piti ne yhdellä replikalla; evästeettömien asiakkaiden osalta katso [Useita replikoita](#useita-replikoita).
