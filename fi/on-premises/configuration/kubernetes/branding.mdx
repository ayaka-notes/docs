**web**-palvelu muodostaa otsikon, logon, ylätunnisteen linkit, alatunnisteet ja huoltosivun ympäristömuuttujista. Jokainen asetus ja sen muoto on kuvattu sivulla [Brändäys](/fi/on-premises/configuration/overleaf-toolkit/branding); Kubernetesissa ne menevät ConfigMapiin.

| | |
| --- | --- |
| Palvelu | web, jokaisessa Ayakaleaf Pro -podissa; luetaan, kun web käynnistyy |
| Verkko | ei mitään: logot ovat URL-osoitteita, jotka selain lataa |
| Ajastetut tehtävät | ei mitään (web tarkistaa huoltotiedoston 5 sekunnin välein, katso alla) |

### Konfiguraatio

```yaml title="30-config.yaml (additions)" wrap
  OVERLEAF_NAV_TITLE: Our Overleaf Instance
  OVERLEAF_HEADER_IMAGE_URL: https://example.com/img/logo.png
  OVERLEAF_HEADER_EXTRAS: '[{"text":"Help","url":"https://example.com/help","class":"subdued"}]'
  OVERLEAF_LEFT_FOOTER: '[{"text":"Run by the IT department"}]'
  OVERLEAF_RIGHT_FOOTER: '[{"text":"Imprint","url":"https://example.com/imprint"}]'
  OVERLEAF_MAINTENANCE_MESSAGE: Our Overleaf Instance is down for maintenance and will be back shortly.
```

```bash
kubectl apply -f 30-config.yaml
kubectl -n overleaf rollout restart deployment/overleaf     # or statefulset/overleaf
```

Kirjoita JSON-arvot yksinkertaisiin lainausmerkkeihin kuten yllä, jotta YAML säilyttää ne yhtenä merkkijonona. Virheellinen JSON muuttujassa `OVERLEAF_HEADER_EXTRAS` tai alatunnisteissa ohitetaan, ja siitä kirjataan vain merkintä lokiin käynnistyksessä.

### Huoltotila

Huoltosivu näytetään niin kauan kuin kontin tiedosto `/etc/overleaf/site_status` sisältää arvon `closed`. Jokaisella podilla on oma kopionsa tästä tiedostosta, ja uusi tai uudelleenkäynnistetty pod käynnistyy avoimena. Sulje sivusto kirjoittamalla tiedosto jokaiseen podiin:

```bash
for p in $(kubectl -n overleaf get pod -l app=overleaf -o name); do   # app=overleaf-ha for several replicas
  kubectl -n overleaf exec "$p" -- sh -c 'echo closed > /etc/overleaf/site_status'
done
```

Lopeta huoltotila kirjoittamalla samalla tavalla `open`. Podit huomaavat muutoksen 5 sekunnin kuluessa.

Ylläpitopaneelin **Close Editor** toimii eri tavalla: se sulkee editorin vain siinä replikassa, joka käsitteli ylläpitäjän pyynnön, ja kyseinen replika avaa sen uudelleen käynnistyessään uudelleen. Useilla replikoilla käytä sen sijaan yllä kuvattua tiedostoa.

### Testattu Kubernetesissa

Kubernetes 1.37:ssä: kun yllä olevat asetukset olivat ConfigMapissa, sivuilla näkyivät `OVERLEAF_NAV_TITLE`, vasen alatunniste ja kirjautumisen jälkeen `OVERLEAF_HEADER_EXTRAS`-muuttujan linkki (kirjautumissivut piilottavat ylätunnisteen linkit). Arvon `closed` kirjoittaminen yhden podin tiedostoon `/etc/overleaf/site_status` näytti huoltosivun `OVERLEAF_MAINTENANCE_MESSAGE`-viestillä vain kyseisessä podissa, ja `open` lopetti sen sekunneissa. Kolmella replikalla ylläpitopaneelin Close Editor sulki editorin vain ylläpitäjää palvelleessa replikassa, kun taas kaksi muuta pysyivät avoimina.
