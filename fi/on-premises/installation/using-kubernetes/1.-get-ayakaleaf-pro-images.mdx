Kubernetes ajaa samoja imageja kuin Toolkit. Erillistä Kubernetes-imagea ei ole.

| Image                                                | Käyttäjä                                                                 |
| ---------------------------------------------------- | ----------------------------------------------------------------------- |
| `ghcr.io/ayaka-notes/overleaf-pro:6.3.2`             | Deployment `overleaf`                                               |
| `ghcr.io/ayaka-notes/overleaf-pro/git-bridge:6.3.2`  | [Git-integraatio](/fi/on-premises/configuration/kubernetes/integrations/git-integration) (valinnainen), sama tagi kuin yllä |
| `ghcr.io/ayaka-notes/texlive-*`                      | käännökset, haettu Dockeriin solmuilla [vaiheessa 0](/fi/on-premises/installation/using-kubernetes/0.-prepare-the-nodes) |

Imaget ovat julkisesti saatavilla [ghcr.io:ssa](https://github.com/ayaka-notes/ayakaleaf-pro/pkgs/container/overleaf-pro/) amd64- ja arm64-arkkitehtuureille, joten kubelet voi hakea ne ilman tunnistetietoja.

<Warning>

Käytä aina versiotagia, kuten `6.3.2`, älä `latest`-tagia. Päivitykset ajavat tietokantamigraatioita, ja niissä on noudatettava sivua [Päivittäminen Kubernetesissa](/fi/on-premises/maintenance/upgrading-on-kubernetes); liikkuva tagi päivittäisi podin aina, kun se ajoitetaan uudelleen.

</Warning>

### Kysymyksiä ja vastauksia

<Accordion title="Solmumme eivät tavoita ghcr.io:ta. Mitä teemme?">

<strong>Vastaus:</strong> Kopioi imaget rekisteriin, jonka solmut tavoittavat, ja käytä sitä nimeä manifesteissa, esimerkiksi:

```bash
docker pull ghcr.io/ayaka-notes/overleaf-pro:6.3.2
docker tag ghcr.io/ayaka-notes/overleaf-pro:6.3.2 registry.example.com/ayakaleaf/overleaf-pro:6.3.2
docker push registry.example.com/ayakaleaf/overleaf-pro:6.3.2
```

TLS:ttömälle rekisterille containerd tarvitsee jokaisella solmulla tiedoston `/etc/containerd/certs.d/<registry>/hosts.toml`, jossa on `server = "http://<registry>"`, sekä `config_path`-asetuksen [vaiheen 0](/fi/on-premises/installation/using-kubernetes/0.-prepare-the-nodes) mukaisesti. Docker itse pushaa pelkän HTTP:n kautta vain osoitteeseen `localhost`, joten pushaa rekisteripalvelimella osoitteen `localhost:<port>` kautta tai lisää rekisteri asetukseen `insecure-registries`.

</Accordion>
