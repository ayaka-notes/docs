### Ylläpitäjän ja ensimmäisen projektin luominen {#create-the-administrator-and-a-first-project}

Avaa **Windows-selaimessasi** [http://localhost:8080/launchpad](http://localhost:8080/launchpad), luo ensimmäinen ylläpitäjätili ja kirjaudu sisään. Noudata sitten Linux-oppaan sivua [6. Asennuksen jälkeiset tehtävät](/fi/on-premises/installation/using-docker-compose/linux/6.-post-installation-tasks) ja käytä sen esimerkki-URL-osoitteissa porttia `8080`.

### Käännöksen varmistaminen {#verify-compilation}

Toimiva kirjautumissivu ei todista, että erilliset kääntäjäkontit pääsevät WSL:n datahakemistoon. Luo tyhjä projekti ja käännä tämä `main.tex` **pdfLaTeX**illa:

```latex
\documentclass{article}
\begin{document}
Ayakaleaf Pro on Windows WSL 2.
\end{document}
```

PDF-esikatselun pitäisi näyttää teksti. Jos käytät basic-imagea, valitse tarvittaessa projektin asetuksista **TeX Live 2026 Basic**.

Valitse **XeLaTeX** ja testaa:

```latex
\documentclass{article}
\usepackage{fontspec}
\begin{document}
Ayakaleaf WSL XeLaTeX sandbox.
\end{document}
```

Molemmat esimerkit toimivat basic-imagella. Kiinalaisia asiakirjoja varten käytä imagea, joka sisältää `ctex`:n ja tarvittavat fontit, kuten full-imagea, ennen kuin testaat seuraavaa **XeLaTeX**illa. Basic ei sisällä niitä:

```latex
\documentclass{ctexart}
\begin{document}
你好，Ayakaleaf Pro。
\end{document}
```

Varmista hiekkalaatikon käyttö suorittamalla **Ubuntussa** käännöksen aikana:

```bash
docker ps -a --filter ancestor=ghcr.io/ayaka-notes/texlive-basic:2026.1
bin/logs -f clsi
```

Käytä suodattimessa valitsemasi imagen nimeä. Lyhyet käännökset voivat valmistua ennen kuin `docker ps` ehtii suorittua; `-a` näyttää myös pysäytetyt kontit siivoukseen asti. Kääntäjäkontin pitäisi käyttää kyseistä imagea ja `/compile`-bind-liitosta Toolkitin WSL-datahakemistosta. Pelkät sovelluslokit eivät korvaa PDF:n tarkistamista.

### Pysyvyyden varmistaminen {#verify-persistence}

**Ubuntussa** Toolkit-hakemistossa:

```bash
bin/stop
bin/start
```

Odota sovellusta, avaa projekti uudelleen Windowsista ja käännä se taas. Tilisi, lähdekoodi ja projektin tiedostot pitäisi olla yhä tallessa. Oletusarvoinen elävä data on Ubuntun hakemistossa `~/ayakaleaf-toolkit/data/`. Säilytä sekä `config/` että `data/`; Ubuntu-jakelun poistaminen tai sen rekisteröinnin purkaminen voi poistaa ne.

### Pidä instanssi saatavilla {#keep-the-instance-available}

Instanssin pitämisessä käynnissä on kolme osaa: Windows pysyy hereillä, Docker Desktop on käynnissä ja kontit käynnistyvät uudelleen moottorin mukana.

Ota Docker Desktopin kohdassa **Settings → General** käyttöön **Start Docker Desktop when you sign in to your computer**, katso [Docker Desktopin asetukset](https://docs.docker.com/desktop/settings-and-maintenance/settings/). Tämä käynnistää Dockerin kirjautumisen jälkeen, ei ennen sitä. Kun Windows on käynnistetty uudelleen, kirjaudu sisään, odota Docker Desktopin käynnistymisen valmistumista, avaa Ubuntu ja tarkista `docker ps` ja sivusto.

Docker Desktopin **Resource Saver** on erillinen Windowsin lepotilasta. Se aktivoituu yleensä vain, kun yhtään konttia ei ole käynnissä; käynnissä oleva sovellus, MongoDB ja Redis estävät tämän joutokäyntitilan. WSL 2:ssa se keskeyttää Docker-moottorin sen sijaan, että sammuttaisi jaetun WSL-virtuaalikoneen. Älä keskeytä Docker Desktopia manuaalisesti **Pause**-toiminnolla, kun palvelet käyttäjiä. Resource Saveria ei tarvitse poistaa käytöstä vain tämän kokonaisuuden pitämiseksi käynnissä; katso [Dockerin Resource Saver -dokumentaatio](https://docs.docker.com/desktop/use-desktop/resource-saver/).

Toolkitin palvelut käyttävät asetusta `restart: always`. Tarkista todellinen asetus **Ubuntussa**:

```bash
docker inspect sharelatex mongo redis --format '{{.Name}} restart={{.HostConfig.RestartPolicy.Name}}'
```

Jokaisen palvelun pitäisi ilmoittaa `always`. Kun Docker on käynnissä, se voi käynnistää nämä olemassa olevat kontit uudelleen ilman uutta `bin/up`-komentoa. Manuaalisesti pysäytetty kontti pysyy pysäytettynä, kunnes käynnistät sen tai käynnistät moottorin uudelleen; asetuksella `always` moottorin uudelleenkäynnistys voi käynnistää sen jälleen. Katso [Dockerin uudelleenkäynnistyskäytäntöjen toiminta](https://docs.docker.com/engine/containers/start-containers-automatically/).

| Toiminto | Vaikutus Ayakaleafiin |
| --- | --- |
| Ubuntu-päätteen sulkeminen komennon `bin/up -d` jälkeen | Kontit toimivat taustalla; pääte ei valvo niitä. Pidä Docker Desktop ja WSL-ympäristö käytettävissä |
| Docker Dashboard -ikkunan sulkeminen | Ikkunan voi sulkea, ja Docker Desktop jatkaa ilmaisinalueella |
| **Quit Docker Desktop** -valinta | Pysäyttää moottorin ja tekee sivustosta saavuttamattoman; avaa Docker Desktop uudelleen palauttaaksesi sen |
| Komennon `wsl --shutdown` suorittaminen | Pysäyttää kaikki WSL-jakelut ja keskeyttää Dockerin WSL-taustajärjestelmän; käynnistä Docker Desktop uudelleen ja avaa Ubuntu uudelleen |
| Windowsin lepotila, horrostila tai sammutus | Palvelu ei ole käytettävissä; pelkkä näytön pitäminen päällä tai pois päältä ei muuta tätä |
| Komennon `bin/stop` suorittaminen | Pysäyttää instanssin ja säilyttää sen datan; jatka komennolla `bin/start` |

Pitkäaikaista käyttöä varten verkkovirralla avaa Windows 11:n **Settings → System → Power & battery → Screen, sleep & hibernate timeouts** (joissakin versioissa näkyy **Power** tai **Screen and sleep**). Aseta verkkovirran lepotilan aikakatkaisuksi **Never** ja poista automaattinen horrostila käytöstä, jos se on määritetty. Näyttö saa silti sammua. Kannettavan kannen toiminto on erillinen asetus; kannen sulkeminen voi asettaa sen lepotilaan, vaikka joutokäynnin lepotilan aikakatkaisu olisi Never. Katso [Windowsin virta-asetukset](https://support.microsoft.com/en-us/windows/experience/power-battery/power-settings-in-windows-11).

Älä suorita komentoa `wsl --shutdown` rutiininomaisena siivouksena, kun sivusto on käytössä. Jos WSL-asetusten muutos vaatii sitä, pysäytä instanssi ensin ja suunnittele katkos. Windows voi ajaa instanssia jatkuvasti näillä asetuksilla. Jaettua palvelua varten, jonka on kestettävä uloskirjautumiset ja valvomattomat uudelleenkäynnistykset, suosittelemme [Linux-opasta](/fi/on-premises/installation/using-docker-compose/linux).

### Palautumisen tarkistaminen Docker Desktopin uudelleenkäynnistyksen jälkeen {#check-recovery-after-restarting-docker-desktop}

Kun työ on tallennettu ja aktiiviset käännökset ovat valmistuneet, valitse Docker Desktopin vianmääritysvalikosta **Restart Docker Desktop**. Odota moottoria ja tarkista sitten **Ubuntussa**:

```bash
docker ps
curl -I http://localhost:8080/launchpad
```

Avaa olemassa oleva projekti Windowsissa ja käännä se uudelleen. Varmista, että tili ja lähdekoodi ovat yhä olemassa.

Jos pysäytit instanssin tarkoituksella komennolla `bin/stop`, käytä komentoa `bin/start`. Jos Docker on käynnissä mutta jokin palvelu epäonnistuu, lue sen lokit sen sijaan, että loisit määritykset uudelleen. Windows Update, Docker-päivitykset ja sähkökatkot voivat silti keskeyttää ympärivuorokautisen asennuksen; pidä varmuuskopioita ja tarkista palautuminen suunnitellun huollon jälkeen.

### Päivittäinen käyttö {#daily-use}

Käynnistä Docker Desktop Windowsissa. Avaa **Ubuntu**:

```bash
cd "$HOME/ayakaleaf-toolkit"
```

| Tehtävä | Komento |
| --- | --- |
| Käynnistä olemassa olevat kontit | `bin/start` |
| Pysäytä kontit ja säilytä data | `bin/stop` |
| Ota määritysmuutokset käyttöön | `bin/up -d` |
| Tarkista tila | `bin/docker-compose ps` |
| Lue käynnistyslokit | `bin/docker-compose logs --tail=100 sharelatex` |
| Lue MongoDB:n lokit | `bin/docker-compose logs --tail=100 mongo` |
| Lue kääntäjän lokit | `bin/logs -f clsi` |

`bin/start` ei ota käyttöön määritysmuutoksia: käytä komentoa `bin/up -d`, kun olet muuttanut hakemistoa `config/`. Noudata sivua [Data ja varmuuskopiot](/fi/on-premises/maintenance/data-and-backups) ennen WSL-jakelun päivittämistä, siirtämistä tai poistamista. Elävien MongoDB-tiedostojen kopioiminen tietokannan kirjoittaessa ei ole johdonmukainen varmuuskopio.

Pidä `127.0.0.1` paikallista käyttöä varten. Muiden tietokoneiden palveleminen vaatii myös tietoisesti valitun kuunteluosoitteen, sivuston URL:n, Windowsin palomuuri- ja verkkomääritykset sekä HTTPS:n; pelkkä `OVERLEAF_SITE_URL`-arvon muuttaminen ei julkaise porttia.

Jos jokin ei toimi, katso [Vianmääritys](/fi/on-premises/installation/using-docker-compose/windows/troubleshooting).
