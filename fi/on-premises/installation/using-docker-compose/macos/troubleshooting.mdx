### Alustus epäonnistuu virheeseen invalid command code {#initialization-fails-with-invalid-command-code}

`bin/init` ilmoittaa `sed: ... invalid command code`, kun se löytää macOS:n BSD sedin. Lisää GNU sed `PATH`-muuttujaan sivun [1. Lataa Toolkit](/fi/on-premises/installation/using-docker-compose/macos/1.-download-the-toolkit) mukaisesti ja tarkista `sed --version`.

Epäonnistunut alustus voi jättää kaikki kolme tiedostoa hakemistoon `config/` tyhjällä `OVERLEAF_INVITE_TOKEN_SECRET`-arvolla. `bin/init`-komennon uudelleenajo ilmoittaa silloin `Config files already exist`. Jos kyseessä on uusi asennus, jota ei ole koskaan käynnistetty, siirrä kolme tiedostoa varmuuskopiohakemistoon ja suorita `bin/init` uudelleen. Olemassa olevan instanssin kohdalla säilytä sen määritykset ja salaisuudet, äläkä poista sen tiedostoja saadaksesi `bin/init`-komennon toimimaan uudelleen.

### MongoDB käynnistyy jatkuvasti uudelleen {#mongodb-keeps-restarting}

Lue MongoDB:n lokit ja Docker-virtuaalikoneen ytimen versio:

```bash
bin/docker-compose logs --tail=100 mongo
docker info --format '{{.KernelVersion}}'
```

Jos lokissa mainitaan Linux-ytimen yhteensopimattomuus, noudata kohtaa [Tarkista Docker-virtuaalikoneen Linux-ydin](/fi/on-premises/installation/using-docker-compose/macos/5.-personalizing-your-instance#check-the-docker-vms-linux-kernel) ja suorita `bin/up -d` uudelleen. Pelkkä poistumiskoodi `137` ei todista, että MongoDB:ltä loppui muisti: tarkista kontin tila ja lokit. Vanhemmasta Docker Desktopin MongoDB-ongelmasta katso myös [Vianmääritys](/fi/on-premises/support/troubleshooting).

### Docker-daemoniin ei saada yhteyttä {#cannot-connect-to-the-docker-daemon}

Käynnistä Docker Desktop ja tarkista valittu Docker-konteksti, katso [0. Docker Desktopin asennus](/fi/on-premises/installation/using-docker-compose/macos/0.-setup-docker-desktop). Jos `docker info` toimii mutta käännökset eivät tavoita Dockeria, tarkista socket-asetukset tiedostossa `config/overleaf.rc` ja lue `clsi`-lokit. Macin toimiva Docker CLI ei todista, että sovelluksen socket-liitos on oikein.

### Sivu avautuu, mutta käännökset epäonnistuvat {#the-page-opens-but-compiles-fail}

Tarkista, että TeX Live -image on olemassa paikallisesti ja vastaa Docker-moottorin arkkitehtuuria:

```bash
docker image inspect ghcr.io/ayaka-notes/texlive-full:2026.1 \
  --format '{{.Os}}/{{.Architecture}}'
bin/logs -f clsi
```

Apple siliconilla imagen pitäisi olla `linux/arm64`. Tarkista, että `SERVER_PRO` ja `SIBLING_CONTAINERS_ENABLED` ovat molemmat `true`, ja ota sitten muutokset käyttöön komennolla `bin/up -d`. Jos lokit ilmoittavat puuttuvasta käännöshakemistosta, tarkista Docker Desktopin tiedostojen jakaminen ja `OVERLEAF_DATA_PATH`-sijainti. Älä poista hiekkalaatikkokäännöksiä käytöstä peittääksesi liitosvirheen.

### Not a directory, tai bind-liitos puuttuu {#not-a-directory-or-a-bind-mount-is-missing}

Isännän tiedosto, jonka override liittää, on ehkä poistettu, tai Docker on voinut luoda hakemiston sinne, missä tiedoston pitäisi olla. Tarkista lähdepolku isännällä ja se, odottaako liitos tiedostoa vai hakemistoa. Palauta määritystiedosto ennen kuin luot kontin uudelleen. Hakemistoon `/tmp` tehty asennus voi kohdata tämän, kun macOS poistaa väliaikaistiedostoja.

### Portti- tai konttinimiristiriidat {#port-or-container-name-conflicts}

Jos portti `8080` on käytössä, valitse toinen portti tiedostossa `config/overleaf.rc`, aseta `OVERLEAF_SITE_URL` vastaamaan sitä ja suorita `bin/up -d` uudelleen.

Toolkit antaa konteilleen kiinteät nimet, kuten `sharelatex`, `mongo` ja `redis`. Pelkkä `PROJECT_NAME`-arvon muuttaminen ei tee kahdesta Toolkit-asennuksesta toisistaan riippumattomia. Ennen kuin käynnistät toisen instanssin, tarkista `docker ps -a` ja käytä Compose-overridessa muita konttinimiä, toista porttia ja erillisiä datahakemistoja. Älä poista olemassa olevan käyttöönoton kontteja tai dataa nimiristiriidan ratkaisemiseksi.

### Instanssi ei ole tavoitettavissa jonkin ajan kuluttua {#the-instance-is-unreachable-after-a-while}

Mac meni todennäköisesti lepotilaan, tai Docker Desktop suljettiin. Katso [Pidä instanssi saatavilla](/fi/on-premises/installation/using-docker-compose/macos/6.-post-installation-tasks#keep-the-instance-available).

### `bin/doctor` sanoo, että tämä ei ole Linux, tai pyytää Quay-kirjautumista {#bin/doctor-says-this-is-not-linux-or-asks-for-a-quay-login}

Molemmat varoitukset ovat odotettuja macOS:ssä julkisen imagen kanssa, katso [2. Tutustu Toolkitiin](/fi/on-premises/installation/using-docker-compose/macos/2.-familiarize-yourself-with-the-toolkit). Tarkista sen sijaan imagehaut, palveluiden tila ja käännösten tulokset, äläkä jätä raportin muita virheitä huomiotta.
