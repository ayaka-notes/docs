---
title: 5. Instanssin mukauttaminen
description: Aseta paikallisen Mac-instanssin portti, sivuston URL ja TeX Live -image, tarkista Docker-virtuaalikoneen ydin ja käynnistä Ayakaleaf Pro.
icon: square-sliders
---

<Steps>
<Step title="Kontin asetukset">
Muokkaa näitä olemassa olevia merkintöjä tiedostossa `config/overleaf.rc`:

```bash title="config/overleaf.rc"
PROJECT_NAME=ayakaleaf-macos
SERVER_PRO=true
OVERLEAF_LISTEN_IP=127.0.0.1
OVERLEAF_PORT=8080
SIBLING_CONTAINERS_ENABLED=true
DOCKER_SOCKET_PATH=/var/run/docker.sock
```

Pidä oletusarvoiset datapolut sekä mukana tulevat MongoDB- ja Redis-palvelut. Kun `OVERLEAF_LISTEN_IP=127.0.0.1`, instanssin voivat avata vain tämän Macin selaimet.
</Step>

<Step title="Sovelluksen asetukset">
Aseta tiedostossa `config/variables.env` nämä arvot ja korvaa samannimiset aktiiviset merkinnät:

```dotenv title="config/variables.env"
OVERLEAF_SITE_URL=http://localhost:8080
TEX_LIVE_DOCKER_IMAGE=ghcr.io/ayaka-notes/texlive-full:2026.1
ALL_TEX_LIVE_DOCKER_IMAGES=ghcr.io/ayaka-notes/texlive-full:2026.1
ALL_TEX_LIVE_DOCKER_IMAGE_NAMES="TeX Live 2026"
```

Luo istuntosalaisuus:

```bash
openssl rand -hex 32
```

Lisää tulos tiedostoon `config/variables.env` arvoksi `OVERLEAF_SESSION_SECRET`. Ilman sitä jokainen konttia uudelleen luova `bin/up` kirjaa kaikki käyttäjät ulos, katso [Ympäristömuuttujat](/fi/on-premises/configuration/overleaf-toolkit/environment-variables).

Paikallisessa instanssissa ilman sähköpostia jätä SMTP-asetukset ja `OVERLEAF_EMAIL_FROM_ADDRESS` asettamatta. Git Bridgen, ulkoisen todennuksen ja muut integraatiot voi lisätä myöhemmin niiden omien [määrityssivujen](/fi/on-premises/configuration/overleaf-toolkit) avulla.
</Step>

<Step id="check-the-docker-vms-linux-kernel" title="Tarkista Docker-virtuaalikoneen Linux-ydin">
MongoDB toimii Docker Desktopin virtuaalikoneen Linux-ytimen päällä, ei macOS:n. Tarkista sen versio ennen ensimmäistä käynnistystä:

```bash
docker info --format '{{.KernelVersion}}'
```

MongoDB dokumentoi yhteensopimattomuuden Linux-ytimien **6.19–7.0.13** kanssa, ja se koskee myös Dockerissa ajettavaa MongoDB:tä. Korjaus on ydin **7.0.14 tai uudempi**, joka tulee Docker Desktopin päivityksen mukana, katso [MongoDB:n tuotanto-ohjeet](https://www.mongodb.com/docs/manual/administration/production-notes/).

Jos Docker-virtuaalikoneesi käyttää ongelmallista ydintä, lisää seuraava tiedostoon `config/docker-compose.override.yml` yhdistettynä siellä jo oleviin `services`-määrityksiin:

```yaml title="config/docker-compose.override.yml"
services:
  mongo:
    environment:
      GLIBC_TUNABLES: glibc.pthread.rseq=1
```

<Warning>

Päivitä korjattuun ytimeen, kun se on saatavilla. Jos ytimesi ei ole ongelmallisella välillä, tämä kiertotie on tarpeeton.

</Warning>
</Step>

<Step title="Käynnistä instanssi">
Suorita Toolkit-hakemistossa:

```bash
bin/up -d
```

Toolkit alustaa MongoDB:n replica setin, hakee TeX Live -imagen ja käynnistää sovelluksen. Ensimmäinen lataus kestää jonkin aikaa. Edistymistä voi seurata näin:

```bash
bin/docker-compose ps
bin/docker-compose logs --tail=100 -f sharelatex
```

Lopeta lokien seuraaminen painamalla `Ctrl+C`. Kontit jäävät käyntiin.

Tarkista julkaistu portti ja ensimmäisen käynnistyksen sivu:

```bash
bin/docker-compose port sharelatex 80
curl -I http://localhost:8080/launchpad
```

Portin pitäisi olla `127.0.0.1:8080`.
</Step>
</Steps>
