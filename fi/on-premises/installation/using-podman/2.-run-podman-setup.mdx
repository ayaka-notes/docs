`bin/podman-setup` tarkistaa kaiken, mitä Ayakaleaf Pro tarvitsee Podmanissa. Ilman valitsimia se vain raportoi; valitsimella `--apply` se myös korjaa löytämänsä ongelmat.

<Steps>
<Step title="Tarkista isäntäkone">
```bash title="Check only"
bin/podman-setup
```

Uudella isäntäkoneella useimmat tarkistukset epäonnistuvat, esimerkiksi:

```text
====== Packages ======
[✗] podman not installed
[✗] podman-docker not installed
...
====== Summary ======
[✓] 7 passed  [!] 13 warnings  [✗] 4 failures
```
</Step>

<Step title="Ota korjaukset käyttöön">
```bash title="Check and fix"
bin/podman-setup --apply
```

Aja se päätteessä: se kysyy `sudo`-salasanaasi järjestelmänlaajuisia vaiheita varten. Se myös lataa Ayakaleaf Pro -imagen purkaakseen sen seccomp-profiilin, mikä vie ensimmäisellä kerralla muutaman minuutin. Lopuksi se tarkistaa isäntäkoneen uudelleen:

```text
====== Summary ======
[✓] 23 passed  [!] 2 warnings  [✗] 0 failures
[!] Warnings remaining:
[!] not logged in to quay.io
[!] container → socket skipped (sharelatex not running)
```

Molemmat varoitukset ovat tässä vaiheessa odotettuja:

* `not logged in to quay.io`: tarkistus tulee virallisesta Toolkitista, jossa Server Pro -image on yksityisessä rekisterissä. Ayakaleaf Pro -imaget ovat julkisia osoitteessa `ghcr.io` eivätkä vaadi kirjautumista, joten ohita se. Se jää näkyviin myös asennuksen jälkeen.
* `container → socket skipped (sharelatex not running)`: tämä testi tarvitsee käynnissä olevan instanssin. Ajat skriptin uudelleen kohdassa [3. Käynnistä Ayakaleaf Pro](/fi/on-premises/installation/using-podman/3.-start-ayakaleaf-pro).

Skripti päättyy koodilla `0`, kun kaikki tarkistukset menevät läpi, koodilla `1`, kun on varoituksia, ja koodilla `2`, kun on virheitä. quay.io-varoituksen vuoksi odota koodia `1`.
</Step>
</Steps>

### Mitä skripti muuttaa {#what-the-script-changes}

Valitsimella `--apply` skripti voi muuttaa seuraavia asioita.

Järjestelmänlaajuisesti, `sudo`-komennolla:

* Asentaa paketit `podman`, `podman-docker`, `git`, `curl`, `checkpolicy` ja `policycoreutils` komennolla `dnf`.
* Ottaa käyttäjällesi käyttöön lingeringin komennolla `loginctl`, jotta konttisi jatkavat toimintaansa uloskirjautumisen jälkeen.
* Luo tiedoston `/etc/containers/nodocker`, joka vaientaa viestin "Emulate Docker CLI using podman".
* Lataa SELinux-käytäntömoduulin `podman_socket_clsi`, kun `SELINUX_MODE=managed`.

Käyttäjällesi:

* Ottaa käyttöön käyttäjäpalvelun `podman.socket`, Docker-yhteensopivan API:n, jolla Ayakaleaf Pro käynnistää käännökset.
* Asentaa Docker Compose v2:n GitHubista polkuun `~/.local/bin/docker-compose` ja linkittää sen hakemistoon `~/.docker/cli-plugins/`.
* Määrää Podmanin käyttämään tätä Composea tiedostossa `~/.config/containers/containers.conf`.
* Lisää aliakset `mongo` ja `redis` tiedostoon `~/.config/containers/registries.conf.d/overleaf-toolkit.conf`, jotta Podman tietää, mistä nämä lyhyet image-nimet haetaan.

Toolkitissa:

* Asettaa `DOCKER_SOCKET_PATH`- ja `DOCKER_HOST`-arvot tiedostossa `config/overleaf.rc` polkuun `/run/user/<uid>/podman/podman.sock`.
* Purkaa käännösten seccomp-profiilin Ayakaleaf Pro -imagesta tiedostoon `config/seccomp/<version>/clsi-profile.json` ja asettaa muuttujan `SECCOMP_PROFILE` tiedostossa `config/variables.env`. Toisin kuin Docker, Podman tarvitsee tämän profiilin tiedostona isäntäkoneella.
* Rakentaa SELinux-käytäntömoduulin hakemistoon `config/selinux/`.
* Asettaa hakemiston `data/` datahakemistojen omistajat komennolla `podman unshare chown`, kun ne ovat olemassa.

<Info>

Jokainen muutos vastaa yhtä tarkistusta. Jos muutat jotain käsin, esimerkiksi tiedostossa `config/overleaf.rc`, aja `bin/podman-setup` uudelleen sen varmistamiseksi.

</Info>
