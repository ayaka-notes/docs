---
title: 3. Käynnistä Ayakaleaf Pro
description: Käynnistä Ayakaleaf Pro Podmanissa, varmista toiminta podman-setupilla ja bin/doctorilla ja käynnistä se uudelleenkäynnistysten jälkeen.
icon: circle-play
---

<Steps>
<Step title="Käynnistä kontit">
```bash title="Start Ayakaleaf Pro"
bin/up -d
```

Ensimmäinen käynnistys lataa MongoDB-, Redis- ja TeX Live -imaget ja luo datahakemistot hakemistoon `data/`. Se tulostaa varoituksen, että Podman-tuki on kokeellinen.

<Info>

Ensimmäinen käynnistys voi myös tulostaa `MongoNetworkError: connect ECONNREFUSED 127.0.0.1:27017`. Toolkit määrittää MongoDB-replikajoukon MongoDB:n vielä käynnistyessä ja yrittää uudelleen, kunnes se vastaa. Voit ohittaa tämän rivin.

</Info>

Tarkista minuutin tai kahden kuluttua, että kontit ovat käynnissä:

```bash title="List the containers"
podman ps --format "{{.Names}} {{.Status}}"
```

```text
mongo Up 34 seconds (healthy)
redis Up 20 seconds
sharelatex Up 20 seconds
```
</Step>

<Step title="Tarkista asennus uudelleen">
Nyt kun datahakemistot ovat olemassa ja `sharelatex`-kontti on käynnissä, `bin/podman-setup` voi viimeistellä tarkistuksensa:

```bash title="Check the setup"
bin/podman-setup
```

Se tarkistaa uusien datahakemistojen omistajat ja testaa Podman-socketin `sharelatex`-kontin sisältä:

```text
====== Socket Connectivity ======
[✓] host → socket OK
[✓] container → socket OK

====== Data Directory Permissions ======
[✓] mongo data dir owned by 999
[✓] redis data dir owned by 999
[✓] overleaf data dir owned by 33
...
====== Summary ======
[✓] 27 passed  [!] 1 warnings  [✗] 0 failures
[!] Warnings:
[!] not logged in to quay.io
```

`container → socket OK` tarkoittaa, että Ayakaleaf Pro voi käynnistää käännöskontteja. Jos jokin tarkistus epäonnistuu, aja `bin/podman-setup --apply` ja sitten `bin/up -d`. quay.io-varoitus ei koske Ayakaleaf Prota, katso [2. Aja podman-setup](/fi/on-premises/installation/using-podman/2.-run-podman-setup).
</Step>

<Step title="Aja doctor">
```bash title="Run the doctor"
bin/doctor
```

Podmanissa raportti näyttää ajoympäristön ja tietoturva-asetukset:

```text
- Container Daemon
    - status: up
    - runtime: podman
    - server version: 5.8.5
    - socket: /run/user/1000/podman/podman.sock
    - DOCKER_HOST: unix:///run/user/1000/podman/podman.sock
    - host → socket: OK
    - container → socket: OK
- Security
    - SELinux: Enforcing
    - SELINUX_MODE: managed
    - SELINUX_LABEL: sharelatex_t
    - SELinux module: loaded (podman_socket_clsi)
    - SELinux rules: present
    - Seccomp profile: present
```

Lopussa näkyvä varoitus `Server Pro enabled, but not logged in to quay.io repository` on sama quay.io-tarkistus, katso [Avun saaminen](/fi/on-premises/support/getting-help#q-and-a).
</Step>

<Step title="Käynnistä Ayakaleaf Pro uudelleenkäynnistyksen jälkeen">
Dockerissa Docker-daemon käynnistää kontit uudelleen uudelleenkäynnistyksen jälkeen. Rootless Podmanissa ei ole daemonia: ota käyttöön käyttäjäpalvelu, joka käynnistää konttisi palvelimen käynnistyessä:

```bash title="Start the containers at boot"
systemctl --user enable podman-restart.service
```

Se käynnistää kaikki käyttäjäsi kontit, joiden uudelleenkäynnistyskäytäntö on `always`, ja Toolkit asettaa sen kaikille konteilleen. Tämä vaatii lingeringin, jonka `bin/podman-setup --apply` otti käyttöön. Ilman tätä palvelua aja `bin/up -d` jokaisen uudelleenkäynnistyksen jälkeen.
</Step>

<Step title="Avaa portti palomuurissa">
Oletuksena instanssi hyväksyy yhteydet vain palvelimelta itseltään osoitteessa `http://localhost:8080`. Jos haluat avata sen muilta tietokoneilta, aseta `OVERLEAF_LISTEN_IP` tiedostossa `config/overleaf.rc` ja `OVERLEAF_SITE_URL` tiedostossa `config/variables.env` kohdan [5. Instanssin mukauttaminen](/fi/on-premises/installation/using-docker-compose/linux/5.-personalizing-your-instance#listen-address-and-port) mukaisesti ja aja `bin/up -d` uudelleen.

Toisin kuin Docker, rootless Podman ei ohita isännän palomuuria. Jos `firewalld` on käynnissä, kuten RHEL:ssä oletuksena, avaa portti:

```bash title="Open port 8080"
sudo firewall-cmd --permanent --add-port=8080/tcp
sudo firewall-cmd --reload
```

Pilvipalvelimella salli portti myös palveluntarjoajan suojausryhmässä. Käytä HTTPS:ää ennen kuin avaat instanssin internetiin, katso [4. Asennuksen jälkeiset tehtävät](/fi/on-premises/installation/using-podman/4.-post-installation-tasks#use-https).
</Step>
</Steps>
