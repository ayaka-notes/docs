RHEL ja sen uudelleenrakennukset (Rocky Linux, AlmaLinux) toimitetaan Podmanin eikä Dockerin kanssa, eivätkä kaikki organisaatiot salli Dockeria palvelimillaan. Toolkit voi ajaa Ayakaleaf Pron sen sijaan **rootless Podmanissa**: kontit toimivat tavallisen käyttäjän alaisuudessa, käännökset ajetaan edelleen hiekkalaatikoiduissa TeX Live -konteissa ja SELinux pysyy enforcing-tilassa. Skripti `bin/podman-setup` tarkistaa isäntäkoneen ja korjaa sen, minkä pystyy.

Tämän osion lopussa sinulla on sama instanssi kuin [Docker Composen käytöllä](/fi/on-premises/installation/using-docker-compose): Ayakaleaf Pro hiekkalaatikkokäännöksineen, MongoDB ja Redis, joita hallitaan tuttuun tapaan komennoilla `bin/up`, `bin/doctor` ja `bin/upgrade`.

<Info>

Podman-tuki on kokeellinen. Se tulee virallisesta Overleaf Toolkitista, jota testataan vain RHEL 9:ssä ja uudemmissa rootless Podmanin, hiekkalaatikkokäännösten ja enforcing-tilassa olevan SELinuxin kanssa. Testasimme nämä sivut Rocky Linux 9.9:ssä (Podman 5.8, SELinux enforcing) Ayakaleaf Pro 6.3.4:llä. Docker on edelleen suositeltu konttiajoympäristö.

</Info>

### Mitä tarvitset {#what-you-need}

* **RHEL, Rocky Linux, AlmaLinux tai CentOS Stream 9 tai uudempi**, SELinux enforcing-tilassa. `bin/podman-setup` pysähtyy kaikissa muissa jakeluissa. Käytä Ubuntussa tai Debianissa ohjetta [Docker Composen käyttö](/fi/on-premises/installation/using-docker-compose/linux).
* **Muu kuin root-käyttäjä, jolla on `sudo`-oikeudet** ja joka omistaa kontit. Aja kaikki tämän osion komennot tänä käyttäjänä; `bin/podman-setup` kieltäytyy toimimasta `root`-käyttäjänä.
* **Puhdas isäntäkone**: ei Docker Engineä eikä olemassa olevaa Toolkit-asennusta. Olemassa olevan Docker-pohjaisen instanssin siirtämistä Podmaniin ei käsitellä.

### Miten se eroaa Dockerista {#how-it-differs-from-docker}

|                                  | Docker                               | Rootless Podman                                                                          |
| -------------------------------- | ------------------------------------ | ---------------------------------------------------------------------------------------- |
| Kuka ajaa kontit                 | Docker-daemon, `root`-käyttäjänä     | Oma käyttäjäsi                                                                           |
| Käännösten käynnistämiseen käytetty socket | `/var/run/docker.sock`     | `/run/user/<uid>/podman/podman.sock`                                                     |
| Portit                           | Mitkä tahansa, esimerkiksi `80` ja `443` | `1024` ja sitä suuremmat, esimerkiksi `8080`                                         |
| Isännän palomuuri (`firewalld`)  | Julkaistut portit ohittavat sen      | On voimassa: avaa portti komennolla `firewall-cmd`                                       |
| Käynnistys uudelleenkäynnistyksen jälkeen | Docker-daemon käynnistää ne uudelleen | Käyttäjäpalvelu `podman-restart`                                          |
| SELinux                          | Toolkit ei määritä sitä              | Käytäntömoduuli `podman_socket_clsi` ja `SELINUX_MODE=managed` tiedostossa `config/overleaf.rc` |
| Käännösten seccomp-profiili      | Sisäänrakennettu imageen             | Toolkit purkaa sen hakemistoon `config/seccomp/<version>/` ja asettaa sen muuttujaksi `SECCOMP_PROFILE` |

### Tunnetut rajoitukset {#known-limitations}

* <strong>Git-integraatio.</strong> Ayakaleaf Pro 6.3.4:ssä `git clone` epäonnistuu Podmanissa virheellä `502`: imagen sisäinen NGINX etsii `git-bridge`-kontin Dockerin DNS-palvelimelta (`127.0.0.11`), jota Podmanissa ei ole. Korjaus ([1b911d1092](https://github.com/ayaka-notes/ayakaleaf-pro/commit/1b911d1092c80f7b0ff77c5e3805b40503d49964)) tulee seuraavassa julkaisussa; siihen asti pidä `GIT_BRIDGE_ENABLED=false`.
* <strong>Asiakkaiden IP-osoitteet.</strong> Rootless Podman välittää julkaistun portin kontin verkon sisältä, joten Ayakaleaf Pro näkee jokaisen kävijän sisäisellä osoitteella, kuten `10.89.0.15`. Käyttäjän [auditointilokit](/fi/on-premises/user-guide/administrators/user-management#audit-logs) hallintapaneelissa näyttävät tämän osoitteen käyttäjän IP-osoitteen sijaan.
