## Předpoklady {#prerequisites}

Overleaf je typický open-source projekt s mikroservisní architekturou, ve kterém všechny služby běží v Dockeru.&#x20;

* Zdrojový kód oficiální Community Edition je na [GitHub Overleaf Official](https://github.com/overleaf/overleaf/tree).&#x20;
* Zdrojový kód Overleaf-CEP je dostupný na [GitHub Yu-i-i/Overleaf](https://github.com/yu-i-i/overleaf-cep).
* Ayakaleaf Pro je k dispozici na [GitHub ayaka-notes/ayakaleaf-pro](https://github.com/ayaka-notes/ayakaleaf-pro).

K nastavení vývojového prostředí Overleafu budete potřebovat výkonný server; doporučujeme konfiguraci alespoň s 8 jádry a 16 GB RAM, protože bude potřeba současně provozovat více než 20 kontejnerů.

<Info>

Protože servery s 8 a více jádry CPU bývají obvykle drahé, důrazně doporučujeme vyvíjet na vlastním lokálním počítači.

</Info>

Zároveň předpokládáme, že jako vývojář už znáte [instalaci Dockeru](https://docs.docker.com/engine/install/ubuntu/). Důrazně doporučujeme pro vývoj používat aktuální a stabilní Ubuntu LTS (např. Ubuntu 24.04 v letech 2025–2026) a nejnovější Docker, protože se tím snižuje pravděpodobnost neočekávaných chyb.

Shrnuto, budete potřebovat:

* [x] Výkonný server/desktop pro vývoj
* [x] Aktuální a stabilní Ubuntu LTS (např. Ubuntu 24.04)
* [x] Prostředí Docker a Git

## Návod ke konfiguraci {#configuration-tutorial}

Zde na Ayakaleaf Pro ukazujeme, jak nastavit vývojové prostředí Overleaf. Všechny níže uvedené příkazy se spouštějí v adresáři `develop`, pokud není uvedeno jinak.

<Steps>
<Step title="Stažení zdrojového kódu">
Nejprve si naklonujte repozitář:

```bash title="bash"
git clone https://github.com/ayaka-notes/ayakaleaf-pro.git
cd ayakaleaf-pro/develop
```
</Step>

<Step title="Synchronizace `yarn.lock`">
Repozitář používá Yarn 4 (`packageManager` v kořenovém `package.json`) a jeho `yarn.lock` nemusí být synchronizovaný se soubory `package.json`. Synchronizujte jej po prvním klonování a po každé změně v `package.json`:

```bash title="bash"
bin/sync
```

`bin/sync` spouští `yarn install --mode=update-lockfile` v kontejneru `node:24.18.1`, takže na hostiteli nepotřebujete Node.js. Změněný `yarn.lock` necommitujte.
</Step>

<Step title="Sestavení vývojového image">
Sestavte služby:

```bash title="bash"
bin/build
```

<Info>

Pokud Dockeru při paralelním sestavování služeb dochází RAM, vytvořte v tomto adresáři soubor `.env` obsahující `COMPOSE_PARALLEL_LIMIT=1`.

</Info>
</Step>

<Step title="Použití překladů">
Moduly Ayakaleaf Pro mají své překlady v `services/web/locales/locales_patches/`, které commitnuté soubory lokalizací neobsahují. Použijte je jednou před prvním spuštěním, jinak stránky těchto modulů zobrazí místo textu klíče jako `about_to_permanently_delete_accounts`:

```bash title="bash"
bin/i18n
```

Na hostiteli vyžaduje `jq`. Spusťte jej znovu po přidání překladu nebo změně větve, viz [Aktualizace překladů i18n](/cs/dev/environment/update-i18n-translations).
</Step>

<Step title="Spuštění všech mikroslužeb">
Poté spusťte služby:

```bash title="bash"
bin/up
```

Jakmile služby běží, otevřete [http://localhost/launchpad](http://localhost/launchpad) a vytvořte první administrátorský účet. Pokud jste změnili `OVERLEAF_PORT`, přidejte port (viz níže).

<Info>

LDAP je ve výchozím stavu zapnutý (`LDAP_ENABLED=true` v `dev.rc`). Launchpad pak zobrazí formulář administrátora LDAP: žádá jen e-mail a tento administrátor se poté přihlašuje přes LDAP, například jako `professor` / `professor` (`professor@planetexpress.com`). Testovací uživatelé jsou uvedeni v `develop/authentication/README.md`. Nastavte `LDAP_ENABLED=false` a `SAML_ENABLED=false`, chcete-li místo toho vytvořit lokálního administrátora s heslem.

</Info>
</Step>
</Steps>

<Info>

`develop/dev.env` už nastavuje `ADMIN_PRIVILEGE_AVAILABLE=true`, takže administrátoři mohou otevřít administrační panel bez dalšího nastavení.

</Info>

### Konfigurace (`dev.rc`) {#configuration-dev-rc}

`develop/dev.rc` vedle `dev.env` obsahuje přepínače vývojového prostředí, podobně jako `overleaf.rc` v Overleaf Toolkit. Změňte hodnotu a znovu spusťte `bin/dev`, aby se projevila; vypnutá funkce také zastaví své kontejnery.

| Proměnná | Výchozí | Co dělá |
| --- | --- | --- |
| `OVERLEAF_PORT` | `80` | Port webu na hostiteli. |
| `LDAP_ENABLED` | `true` | Přihlášení přes LDAP s testovacími uživateli. |
| `SAML_ENABLED` | `true` | Přihlášení přes SAML s testovacími uživateli. |
| `MAILPIT_ENABLED` | `true` | Zachytává v Mailpitu každý e-mail z `web`. Zapíná také potvrzování e-mailů (`EMAIL_CONFIRMATION_DISABLED=false`). |
| `S3_ENABLED` | `true` | Ukládá soubory historie a šablon do RustFS (S3) místo lokálních svazků. |
| `HOPPSCOTCH_ENABLED` | `true` | Hoppscotch s proxy do sítě Dockeru, viz [Nastavení vývojových nástrojů](/cs/dev/environment/setup-develop-tools). |
| `HOPPSCOTCH_PORT` | `9170` | Port Hoppscotch na hostiteli. |
| `GRAFANA_ENABLED` | `true` | Grafana na `/grafana/` webu se stavem, metrikami a logy každé služby, viz [Nastavení vývojových nástrojů](/cs/dev/environment/setup-develop-tools). |

Každá funkce má svůj `docker-compose.yml` a další soubory ve vlastní složce: `authentication/ldap`, `authentication/saml`, `mail`, `s3`, `hoppscotch` a `grafana`. Funkce, která potřebuje nastavení `web` bez proměnné prostředí, připojí soubor do `/etc/overleaf/settings.d/` a `develop/settings.dev-env.cjs` je všechny sloučí. Všechny skripty `bin/*` procházejí přes `bin/docker-compose`, který přidá soubory zapnutých funkcí. Když sami potřebujete příkaz compose, volejte `bin/docker-compose` místo `docker compose`.

<Warning>

Lokální svazky a RustFS jsou oddělená úložiště: projekt vytvořený s `S3_ENABLED=true` nemá po přepnutí na `false` historii ani binární soubory, a naopak. Chcete-li do RustFS zkopírovat soubory prostředí, které běželo dříve, než `S3_ENABLED` existovalo, postupujte podle „Moving existing data into RustFS“ v [develop/README.md](https://github.com/ayaka-notes/ayakaleaf-pro/blob/server-pro/develop/README.md).

</Warning>

### Porty {#ports}

Web, konzole RustFS a Hoppscotch naslouchají na `127.0.0.1` hostitele; na vzdáleném počítači nejprve přesměrujte jejich porty, například `ssh -L 9001:localhost:9001 <host>`. Web používá `OVERLEAF_PORT` z `dev.rc`, takže pokud jste jej změnili, přidejte port k níže uvedeným adresám.

| Stránka | Adresa | Přihlášení |
| --- | --- | --- |
| Web | [http://localhost](http://localhost) | Účty webu nebo testovací uživatelé |
| E-mailová schránka (Mailpit) | [http://localhost/mailpit/](http://localhost/mailpit/) | Žádné |
| Grafana | [http://localhost/grafana/](http://localhost/grafana/) | Žádné, anonymní uživatelé jsou administrátoři |
| Mongo Express | [http://localhost/mongo-express/](http://localhost/mongo-express/) | Žádné |
| RedisInsight | [http://localhost/redis-insight/](http://localhost/redis-insight/) | Žádné |
| Konzole S3 (RustFS) | [http://localhost:9001/rustfs/console/](http://localhost:9001/rustfs/console/) | `rustfsadmin` / `rustfsadmin` |
| Hoppscotch | [http://localhost:9170](http://localhost:9170) (`HOPPSCOTCH_PORT`) | Žádné |

Mailpit, Grafanu, Mongo Express a RedisInsight poskytuje web na vlastních cestách přes webpack-dev-server, takže nepotřebují vlastní port. Po přihlášení na ně odkazuje menu **Dev tools** v navigační liště webu; stránka, jejíž funkce je v `dev.rc` vypnutá, se vynechá. [Nastavení vývojových nástrojů](/cs/dev/environment/setup-develop-tools) ukazuje, co každý z nich dělá.

API S3 (port 9000) a SMTP (port 1025) jsou dostupné jen uvnitř sítě Dockeru. Mongo (27017), Redis (6379), Mongo Express (8081), RedisInsight (5540) a git-bridge (8000) jsou publikovány jen na `127.0.0.1` hostitele.

### TeX Live {#tex-live}

Kompilace v sandboxu jsou ve výchozím stavu zapnuté: `develop/dev.env` nastavuje `SANDBOXED_COMPILES=true` a image `ghcr.io/ayaka-notes/texlive-full:2026.1` a `ghcr.io/ayaka-notes/texlive-full:2025.1`. clsi sám image nestahuje, proto je jednou stáhněte:

```bash
docker pull ghcr.io/ayaka-notes/texlive-full:2026.1
docker pull ghcr.io/ayaka-notes/texlive-full:2025.1
```

Podrobnosti najdete v [Nastavení kompilací v sandboxu](/cs/dev/environment/setup-sandbox-compiles).

<Warning>

Projekt vytvořený v době, kdy bylo `SANDBOXED_COMPILES` vypnuté, nemá image TeX Live. Stále se kompiluje s výchozím image, ale přechod mezi kódem a PDF selže s hláškou „That didn't work. Recompile and try again.“ Přiřaďte takovým projektům jednou image z `TEX_LIVE_DOCKER_IMAGE`; bez `--commit` skript jen ukáže, co by změnil:

```bash
bin/docker-compose exec web sh -c 'cd /overleaf/services/web && node scripts/backfill_project_image_name.mjs --commit'
```

</Warning>

`dev.env` také zapíná převody Pandoc s `PANDOC_IMAGE=overleaf-pandoc:local`. Sestavte tento image jednou z kořene repozitáře:

```bash
docker build -t overleaf-pandoc:local develop/pandoc
```

Chcete-li kompilovat na hostiteli s macOS, možná budete muset přepsat cestu k socketu Dockeru vytvořením souboru `.env` v adresáři `develop` s obsahem `DOCKER_SOCKET_PATH=/var/run/docker.sock.raw`

### Vývoj {#development}

Abyste nemuseli po každé změně kódu spouštět `bin/build && bin/up`, můžete Overleaf Community Edition spustit ve _vývojovém režimu_, ve kterém se služby při změnách kódu automaticky aktualizují.

K tomu použijte přiložený skript `bin/dev`:

```text
bin/dev
```

Tím se všechny služby spustí pomocí `node --watch`, který automaticky sleduje kód a podle potřeby služby restartuje. Po změně `dev.rc` jej spusťte znovu.

Pro zlepšení výkonu můžete ve vývojovém režimu spustit jen část služeb tak, že skriptu `bin/dev` předáte jejich seznam oddělený mezerami:

```text
bin/dev [service1] [service2] ... [serviceN]
```

<Info>

Spuštění služby `web` ve _vývojovém režimu_ aktualizuje službu `web` pouze při změnách backendového kódu. Aby se automaticky aktualizoval i frontendový kód, nezapomeňte ve _vývojovém režimu_ spustit také službu `webpack`.

</Info>

Pokud nejsou uvedeny žádné služby, spustí se ve vývojovém režimu všechny.

Po přidání překladu nebo změně větve spusťte `bin/i18n`, viz [Aktualizace překladů i18n](/cs/dev/environment/update-i18n-translations).

### Ladění {#debugging}

Ve _vývojovém režimu_ většina služeb zpřístupňuje ladicí port, ke kterému můžete připojit debugger, například inspektor v Chrome Dev Tools nebo debugger integrovaný v IDE. Následující tabulka ukazuje port zpřístupněný na `127.0.0.1` **hostitelského počítače** pro každou službu:

| Služba             | Port |
| ------------------ | ---- |
| `web`                   | 9229 |
| `clsi`                  | 9230 |
| `chat`                  | 9231 |
| `docstore`              | 9233 |
| `document-updater`      | 9234 |
| `filestore`             | 9235 |
| `notifications`         | 9236 |
| `real-time`             | 9237 |
| `history-v1`            | 9239 |
| `project-history`       | 9240 |
| `linked-url-proxy`      | 9241 |
| `third-party-datastore` | 9242 |

Chcete-li se ke službě připojit pomocí _vzdáleného ladění_ v Chromu, přejděte na chrome://inspect/ a ujistěte se, že je zaškrtnuto _Discover network targets_. Poté klikněte na _Configure..._ a přidejte položku `localhost:[service port]` pro každou ze služeb, ke které chcete připojit debugger.

Po přidání položky se služba zobrazí jako _Remote Target_, který můžete zkoumat a ladit.

### Logování {#logging}

Skript `bin/logs` sleduje logy a formátuje je pomocí `bunyan`. Potřebuje také `ggrep`, což je název GNU grep při instalaci přes Homebrew v macOS; Ubuntu příkaz `ggrep` nemá.

```bash
sudo npm install -g bunyan
# Or sudo apt install node-bunyan 
```

Případně můžete přímo spustit:

```text
bin/docker-compose logs -f [service name]
```

Používejte `bin/docker-compose` místo `docker compose`, aby se našly i služby funkcí z `dev.rc` (`mailpit`, `rustfs`, `ldap`, `saml`, `hoppscotch` a `grafana` s Prometheem, Loki a exportéry).

S `GRAFANA_ENABLED=true` jsou logy každého kontejneru také v Grafaně, kde je lze filtrovat podle služby, úrovně a textu, viz [Nastavení vývojových nástrojů](/cs/dev/environment/setup-develop-tools#grafana).
