V této části probereme datový model Overleafu. Overleaf používá pro ukládání dat MongoDB a jediná databáze se jmenuje `sharelatex`, což je zároveň název předchůdce Overleafu.

Vývojové prostředí už spouští Mongo Express vedle Mongo (viz [setup-develop-tools.md](/cs/dev/environment/setup-develop-tools  "mention")). Otevřete [http://localhost:8081/](http://localhost:8081/) a přihlaste se pomocí `admin:pass`.

Z adresáře `develop` můžete také otevřít shell v kontejneru Mongo:

```bash
bin/docker-compose exec mongo mongosh sharelatex
```

#### Jak jsou stránky napsány {#how-the-pages-are-written}

* Každá stránka uvádí pole, která kód zapisuje, s jejich typem, významem a řádkem kódu, který to dokládá: řádkem schématu Mongoose nebo místem, které pole zapisuje. Pole, která zapisuje jen migrace, skript nebo jeden z webových modulů, to uvádějí.
* Mnoho kolekcí nemá schéma Mongoose: služby je zapisují ovladačem MongoDB.
* Indexy vytvářejí jen migrace v `tools/migrations/`. CE při každém spuštění spouští ty se značkou `server-ce` (`server-ce/init_scripts/900_run_web_migrations.sh`); Mongoose `autoIndex` je vypnutý (`services/web/app/src/infrastructure/Mongoose.mjs:7`). Tabulky indexů uvádějí jen to, co instance CE nakonec má.
* Text docs je v Mongo, ale jiný obsah ne. Obsah souborů se ukládá jako bloby a historie jako chunky v bucketech history-v1 (místní složky nebo S3 / RustFS); otevřené docs jsou v Redis, dokud je document-updater nezapíše flushem.
