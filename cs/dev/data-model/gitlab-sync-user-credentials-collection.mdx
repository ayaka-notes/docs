---
title: Kolekce GitLab Sync User Credentials
icon: user-lock
---

`gitlabSyncUserCredentials` uchovává jeden dokument pro každého uživatele, který propojil účet GitLab pro GitLab Sync. Ukládá zašifrované tokeny OAuth uživatele. Kolekce patří do webového modulu `gitlab-sync` (`services/web/modules/gitlab-sync`). Schéma je v `services/web/modules/gitlab-sync/app/models/gitlabSyncUserCredentials.mjs` a veškerý přístup prochází přes `services/web/modules/gitlab-sync/app/src/TokenManager.mjs`.

#### Pole {#fields}

| Pole | Typ | Význam | Zdroj |
| ----- | ---- | ------- | ------ |
| `_id` | ObjectId | Nastavuje Mongoose, když upsert vkládá. | |
| `userId` | ObjectId | Uživatel Overleafu. Povinné. Schéma uvádí `unique: true`, ale žádný index se nevytváří (viz Indexy); upsert podle `userId` udržuje jeden dokument na uživatele. | `gitlabSyncUserCredentials.mjs:8`, `TokenManager.mjs:88-95` |
| `gitlab` | String | JSON `{ accessToken, refreshToken, expiresAt }`, zašifrovaný pomocí `@overleaf/access-token-encryptor`. `expiresAt` je v milisekundách od epochy, nebo `null`; `refreshToken` může být `null`. Heslo pochází z `GITLAB_TOKEN_CIPHER_PASSWORD`; štítek šifry je `GITLAB_TOKEN_CIPHER_LABEL`, výchozí `2026.10-v3`. Povinné. | `gitlabSyncUserCredentials.mjs:9-10`, `TokenManager.mjs:18-31`, `services/web/modules/gitlab-sync/app/src/GitLabApiClient.mjs:209-220` |
| `__v` | Number | Klíč verze Mongoose. Schéma ho nevypíná. | Výchozí v Mongoose |

#### Kdo zapisuje {#who-writes-it}

| Kód | Co dělá |
| ---- | ------------ |
| `TokenManager.mjs:88-95` (`saveUserToken`) | Provede upsert zašifrovaných přihlašovacích údajů uživatele. |
| `TokenManager.mjs:99-108` (`linkUserToken`) | Uloží nové přihlašovací údaje z callbacku OAuth (`services/web/modules/gitlab-sync/app/src/GitLabSyncController.mjs:146`). Když uživatel propojí účet znovu, nahrazený přístupový token se na pozadí v GitLabu odvolá. |
| `TokenManager.mjs:53-78` (`refreshUserToken`) | Když do `expiresAt` přístupového tokenu zbývá méně než 5 minut (`:13,47-49`), získá pomocí obnovovacího tokenu nové tokeny a uloží je (`:75`). Běží pod zámkem `gitlabSyncToken` pro každého uživatele (`:15,54`), protože GitLab obnovovací token při použití spotřebuje. |
| `TokenManager.mjs:111-126` (`removeUserToken`) | Odvolá přístupový token v GitLabu (podle možností) a pak smaže dokument. Volá se při zrušení propojení (`GitLabSyncController.mjs:173`) a když vyprší smazaný uživatel (`services/web/modules/gitlab-sync/index.mjs:56-58`). |

#### Kdo čte {#who-reads-it}

| Kód | Co dělá |
| ---- | ------------ |
| `TokenManager.mjs:41-45,81-85` (`getUserCredentials`, `getUserToken`) | Dešifruje přihlašovací údaje pro každé volání API GitLab a předtím je obnoví, když token brzy vyprší: `services/web/modules/gitlab-sync/app/src/GitLabSyncHandler.mjs` (například `:27`) a `services/web/modules/gitlab-sync/app/src/GitMerge.mjs:52`. Bez dokumentu nebo s údaji, které nejde dešifrovat ani obnovit, vyhodí `InvalidTokenError` a uživatel se počítá jako nepropojený (`GitLabSyncHandler.mjs:25-37`). |
| `services/web/modules/admin-tools/app/src/AdminUserListManager.mjs:394` | Kontroluje, zda má uživatel dokument, pro integrace zobrazené v administrátorském panelu. |

#### Indexy {#indexes}

| Název | Klíče | Volby | Migrace |
| ---- | ---- | ------- | --------- |
| `_id_` | `_id: 1` | | default |

`autoIndex` v Mongoose je vypnutý (`services/web/app/src/infrastructure/Mongoose.mjs:7`), takže `unique: true` ze schématu na `userId` nic nevytvoří. Žádná migrace pro tuto kolekci nevytváří indexy.

#### Poznámky {#notes}

* Změna `GITLAB_TOKEN_CIPHER_PASSWORD` učiní uložené přihlašovací údaje nečitelnými. Tito uživatelé se pak počítají jako nepropojení, dokud účet znovu nepropojí.
* Smazaný uživatel si ponechá dokument, dokud nevyprší.
