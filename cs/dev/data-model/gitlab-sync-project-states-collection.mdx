`gitlabSyncProjectStates` uchovává jeden dokument pro každý projekt propojený s projektem GitLab: o jaký repozitář jde a kde skončila poslední synchronizace. Kolekce patří do webového modulu `gitlab-sync` (`services/web/modules/gitlab-sync`). Schéma je v `services/web/modules/gitlab-sync/app/models/gitlabSyncProjectStates.mjs` a veškerý přístup prochází přes `services/web/modules/gitlab-sync/app/src/SyncStateManager.mjs`. Pole jsou stejná jako v [GitHub Sync Project States](/cs/dev/data-model/github-sync-project-states-collection).

#### Kdo zapisuje {#who-writes-it}

| Kód | Co dělá |
| ---- | ------------ |
| `SyncStateManager.mjs:9-14` (`createProjectState`) | Vytvoří dokument: po importu repozitáře jako nového projektu (`services/web/modules/gitlab-sync/app/src/GitLabSyncHandler.mjs:175-181`) nebo po exportu projektu do nového repozitáře (`GitLabSyncHandler.mjs:234-240`, jen vlastník, odmítnuto, pokud už je propojen). |
| `SyncStateManager.mjs:16-21` (`updateProjectState`) | `$set` změněných polí. `getMergeOverview` nastaví `mergeStatus: 'diverged'`, když synchronizovaná větev už neobsahuje `lastSyncCommit` (kontrola merge base, `services/web/modules/gitlab-sync/app/src/GitLabApiClient.mjs:460`), nebo commit zmizel a uživatel může pushovat (`GitLabSyncHandler.mjs:123,126-137`). Synchronizace (`services/web/modules/gitlab-sync/app/src/GitMerge.mjs`) při úspěchu posune `lastSyncCommit`/`lastSyncVersion` (například `:152,189,231`), zaznamená konflikt pomocí `unmergedBranchName`, `unmergedBranchHead` a `conflictVersion` (`:214-220`) a po jeho vyřešení je vymaže (`:257-264`). |
| `SyncStateManager.mjs:23-25` (`removeProjectState`) | Smaže dokument, když vlastník zruší propojení projektu (`GitLabSyncHandler.mjs:83-97`) a když vyprší smazaný projekt (`services/web/modules/gitlab-sync/index.mjs:46-48`). |

#### Indexy {#indexes}

| Název | Klíče | Volby | Migrace |
| ---- | ---- | ------- | --------- |
| `_id_` | `_id: 1` | | default |

`autoIndex` v Mongoose je vypnutý (`services/web/app/src/infrastructure/Mongoose.mjs:7`), takže `unique: true` ze schématu na `projectId` nic nevytvoří. Žádná migrace pro tuto kolekci nevytváří indexy.

#### Poznámky {#notes}

* API GitLabu neumí na rozdíl od GitHubu přesunout větev na libovolný commit. Synchronizace commituje přímo na synchronizovanou větev, když se může posunout dopředu, jinak na dočasnou větev, která se pak sloučí přes merge request (`GitMerge.mjs:16-21`).
* Synchronizace běží pod zámkem projektu `gitSync`, sdíleným s GitHub Sync a Gitea Sync (`GitMerge.mjs:25-32`).
* Smazaný projekt si ponechá svůj dokument, dokud nevyprší.
* Token GitLab uživatele je v [GitLab Sync User Credentials](/cs/dev/data-model/gitlab-sync-user-credentials-collection).
