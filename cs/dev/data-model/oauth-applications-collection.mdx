`oauthApplications` obsahuje klienty OAuth, které web zná. Jeden dokument je jeden klient. V Ayakaleaf Pro do ní zapisuje jen webový modul `git-bridge`, který při startu webu vytvoří jednoho klienta s názvem `Overleaf Git Bridge`. Schéma je `services/web/app/src/models/OauthApplication.mjs`.

#### Pole {#fields}

| Pole | Typ | Význam | Zdroj |
| ----- | ---- | ------- | ------ |
| `_id` | ObjectId | Id dokumentu klienta. Odkazují na něj `oauthAccessTokens.oauthApplication_id` a `oauthAuthorizationCodes.oauthApplication_id`. | `OauthApplication.mjs:5` |
| `id` | String | Id klienta: 64 náhodných malých písmen a číslic. | `OauthApplication.mjs:7`, `services/web/modules/git-bridge/index.mjs:25` |
| `clientSecret` | String | Tajný klíč klienta, zapsaný jako `v1.` a 32 náhodných znaků. Čte ho jen `getClient` a nic `getClient` nevolá (viz Poznámky). | `OauthApplication.mjs:8`, `git-bridge/index.mjs:26` |
| `grants` | Array of String | Typy grantů. Klient git-bridge má `['password']`. Vrací se s klientem při kontrole tokenu (`services/web/modules/oauth2-server/app/src/OAuth2Model.mjs:67-72`). | `OauthApplication.mjs:9`, `git-bridge/index.mjs:27` |
| `name` | String | Název klienta. Modul git-bridge i kód osobních přístupových tokenů najdou klienta podle názvu `Overleaf Git Bridge`. | `OauthApplication.mjs:10`, `git-bridge/index.mjs:15-16,28` |
| `redirectUris` | Array of String | Povolené URI přesměrování. U klienta git-bridge `[]`. | `OauthApplication.mjs:11`, `git-bridge/index.mjs:29` |
| `scopes` | Array of String | Scopy, které klient smí používat. U klienta git-bridge `['git_bridge']`. | `OauthApplication.mjs:12`, `git-bridge/index.mjs:30` |
| `pkceEnabled` | Boolean | Jen ve schématu: žádný kód v tomto repozitáři ho nezapisuje a čte ho jen nepoužívaný `getClient` (`OAuth2Model.mjs:207`). | `OauthApplication.mjs:13` |

#### Kdo zapisuje {#who-writes-it}

| Kód | Co dělá |
| ---- | ------------ |
| `git-bridge/index.mjs:9-35` (module `git-bridge`) | Když je `GIT_BRIDGE_ENABLED` nastaveno na `true`, vytvoří při startu webu klienta `Overleaf Git Bridge`, pokud klient s tímto názvem ještě neexistuje. |

#### Kdo čte {#who-reads-it}

| Kód | Co dělá |
| ---- | ------------ |
| `services/web/modules/oauth2-server/app/src/OAuthPersonalAccessTokenManager.mjs:53-61` (module `oauth2-server`) | Najde klienta `Overleaf Git Bridge` podle názvu a uloží jeho `_id` do každého nového osobního přístupového tokenu. Bez klienta se žádný token nevytvoří. |
| `OAuth2Model.mjs:31-39,67-72` (`getAccessToken`) | Načte klienta tokenu přes `oauthApplication_id` a vrátí jeho `id` a `grants`. |
| `OAuth2Model.mjs:185-209,241,275` (`getClient`, `saveToken`, `saveAuthorizationCode`) | Hledají klienty podle `id`. V tomto repozitáři se nikdy nevolají, viz Poznámky. |

#### Indexy {#indexes}

Jen výchozí index na `_id`. Unikátní index `id_1` pochází z migrací se štítky `saas` (`20190912145016_create_oauthApplications_indexes.mjs`) a `server-pro` (`20230502180757_server_pro_oauth_indexes.mjs`), které Community Edition nespouští.

#### Poznámky {#notes}

* Web používá `@node-oauth/oauth2-server` jen ke kontrole tokenů bearer (`server.authenticate` v `services/web/app/src/Features/Authentication/AuthenticationController.mjs:409-450`), což volá jen metody modelu `getAccessToken` a `verifyScope`. Žádná trasa neobsluhuje `/oauth/token` ani `/oauth/authorize`, takže `getClient`, `saveToken` a `saveAuthorizationCode` se nikdy nevolají.
* Modul hledá klienta podle názvu a pak ho vytvoří, a Community Edition nemá unikátní index na `name` ani `id`. Nic tedy nebrání druhému klientovi se stejným názvem. Kód, který klienta potřebuje, vezme toho, kterého vrátí `findOne`.
