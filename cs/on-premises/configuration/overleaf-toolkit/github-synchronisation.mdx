### Nastavení synchronizace s GitHubem

<Warning>

Před použitím synchronizace s GitHubem musíte nejprve povolit [git-bridge](/cs/on-premises/configuration/overleaf-toolkit/git-integration).

```dotenv title="config/overleaf.rc"
GIT_BRIDGE_ENABLED=true
```

</Warning>

Navštivte [nastavení pro vývojáře](https://github.com/settings/developers), vytvořte svou GitHub OAuth aplikaci a zkopírujte její `CLIENT_ID` a `SECRET`.

**Poznámka**: při vytváření OAuth App zadejte do pole **Authorization callback URL** `${OVERLEAF_SITE_URL}/user/github-sync/oauth2/callback`. Ayakaleaf Pro sestavuje stejnou adresu z `OVERLEAF_SITE_URL`, takže pro ni v `config/variables.env` není třeba nic nastavovat.

Poté přidejte následující nastavení do souborů s proměnnými prostředí Overleafu.

```dotenv title="config/variables.env" wrap
# used to encrypt the user's GitHub access token.
# How to generate: `openssl rand -hex 32`
GITHUB_TOKEN_CIPHER_PASSWORD=0123456789ABCDEFG # changed to yours

# Github Sync Settings
GITHUB_SYNC_ENABLED=true
GITHUB_SYNC_CLIENT_ID=
GITHUB_SYNC_CLIENT_SECRET=

# OAuth callback is: ${OVERLEAF_SITE_URL}/user/github-sync/oauth2/callback
# (Optional) GITHUB_SYNC_PROXY_URL=http://10.0.0.1:10808
```

<Warning>

Před konfigurací OAuth callback URL na GitHubu se ujistěte, že je `OVERLEAF_SITE_URL` nastaveno správně.

</Warning>

Pokud se nacházíte v regionu s omezeným přístupem k síti, možná budete muset pro přístup ke GitHubu nakonfigurovat proxy. Nastavte následující proměnnou prostředí: `GITHUB_SYNC_PROXY_URL=http://10.0.0.1:10808`. Ujistěte se, že používání proxy je v souladu s místními zákony a předpisy.

<Warning>

`GITHUB_SYNC_PROXY_URL` musí být standardní dopředná HTTP/HTTPS proxy (např. HTTP port Clash). Zrcadla pro stahování z GitHubu, jako je `gh-proxy.org`, nejsou podporována.

</Warning>

<Warning>

Jako hostitele proxy nepoužívejte `127.0.0.1`. Pokud proxy běží na hostitelském serveru, použijte LAN IP adresu serveru (např. `192.168.1.xx`) a ujistěte se, že je proxy nakonfigurována tak, aby přijímala připojení ze zařízení v místní síti.

</Warning>

### GitHub Enterprise

<Info>

Podpora GitHub Enterprise je k dispozici od verze v6.3.1. Starší verze se připojují pouze k `github.com` a níže uvedené proměnné nemají žádný účinek.

</Info>

Ve výchozím nastavení se synchronizace s GitHubem připojuje k `github.com`. Chcete-li použít GitHub Enterprise Server (hostovaný u vás) nebo GitHub Enterprise Cloud s rezidencí dat (`GHE.com`), nastavte `GITHUB_SYNC_URL` na webovou adresu své instance, tedy tu, přes kterou otevíráte repozitáře v prohlížeči.

```dotenv title="config/variables.env" wrap
# GitHub Enterprise Server
GITHUB_SYNC_URL=https://github.example.com

# or GitHub Enterprise Cloud with data residency
# GITHUB_SYNC_URL=https://octocorp.ghe.com
```

Koncové body REST a GraphQL API se z `GITHUB_SYNC_URL` odvozují stejným způsobem jako v GitHub CLI:

| `GITHUB_SYNC_URL`             | REST API                         | GraphQL API                              |
| ----------------------------- | -------------------------------- | ---------------------------------------- |
| `https://github.com` (výchozí) | `https://api.github.com`         | `https://api.github.com/graphql`         |
| `https://SUBDOMAIN.ghe.com`   | `https://api.SUBDOMAIN.ghe.com`  | `https://api.SUBDOMAIN.ghe.com/graphql`  |
| `https://HOST` (jakýkoli jiný) | `https://HOST/api/v3`            | `https://HOST/api/graphql`               |

Koncové body API nastavujte pouze tehdy, když je vaše instance poskytuje jinde, například za API gateway:

| Proměnná                  | Výchozí hodnota                                                                           |
| ------------------------- | ----------------------------------------------------------------------------------------- |
| `GITHUB_SYNC_URL`         | `https://github.com`                                                                      |
| `GITHUB_SYNC_API_URL`     | Odvozeno z `GITHUB_SYNC_URL`, viz tabulka výše                                            |
| `GITHUB_SYNC_GRAPHQL_URL` | Odvozeno z `GITHUB_SYNC_API_URL`, pokud je nastavena (`/api/v3` se změní na `/api/graphql`, jinak se připojí `/graphql`), jinak z `GITHUB_SYNC_URL` |

<Warning>

* OAuth aplikaci vytvořte na své enterprise instanci (_Settings → Developer settings → OAuth Apps_); aplikace z `github.com` tam nefunguje. Callback URL je stejná: `${OVERLEAF_SITE_URL}/user/github-sync/oauth2/callback`.
* `GITHUB_SYNC_URL` je pouze webová adresa. Nenastavujte ji na adresu API, jako je `https://api.github.com` nebo `https://HOST/api/v3`, a nepřidávejte cestu k organizaci.
* Všechny tři adresy musí odkazovat na stejnou instanci GitHubu.

</Warning>

<Info>

Pokud vaše instance používá certifikát od soukromé certifikační autority, připojte certifikát CA do kontejneru a nastavte na něj `NODE_EXTRA_CA_CERTS`, např. `NODE_EXTRA_CA_CERTS=/var/lib/overleaf/certs/github-ca.pem`.

</Info>

<Danger>

Propojené účty a projekty patří k instanci, se kterou byly propojeny. Před přepnutím `GITHUB_SYNC_URL` na jinou instanci požádejte uživatele, aby zrušili propojení svého účtu GitHub a projektů.

</Danger>

### Kdo může propojovat a synchronizovat

Stejně jako v Overleaf Cloud může projekt s repozitářem GitHub propojit pouze vlastník projektu. Po propojení jej může synchronizovat každý spolupracovník s oprávněním k úpravám.

| Akce                                                       | Kdo ji může provést                                            |
| ---------------------------------------------------------- | -------------------------------------------------------------- |
| Export projektu do nového repozitáře GitHub                | Vlastník projektu                                              |
| Import repozitáře GitHub do nového projektu                | Kterýkoli uživatel, který se stane vlastníkem nového projektu  |
| Pull, push a merge propojeného projektu                    | Vlastník a spolupracovníci s oprávněním k úpravám              |
| Zrušení propojení projektu s jeho repozitářem              | Vlastník projektu                                              |

* Overleaf komunikuje s GitHubem prostřednictvím účtu GitHub uživatele, který synchronizuje, takže každý spolupracovník, který synchronizuje, si propojí vlastní účet GitHub a musí mít oprávnění pushovat do výchozí větve repozitáře.
* Spolupracovníci s oprávněním pouze ke čtení nemohou pro projekt synchronizaci s GitHubem používat.

### Q\&A

<Accordion title="Mohu do výchozí větve provést force push?">

<strong>Odpověď:</strong> Nedoporučujeme to. Overleaf force push rozpozná, upozorní na něj a převezme přepsanou větev, přičemž sloučí změny provedené v Overleafu od poslední synchronizace. Abyste se vyhnuli nepříjemným překvapením, chraňte výchozí větev v nastavení repozitáře před force pushem.

</Accordion>

<Accordion title="Mohu přejmenovat výchozí větev propojeného projektu?">

<strong>Odpověď:</strong> Prosím, nedělejte to. Overleaf nadále synchronizuje s větví, se kterou byl projekt propojen. Chcete-li synchronizovat s jinou větví, zrušte propojení projektu a poté importujte repozitář do nového projektu, který použije aktuální výchozí větev.

</Accordion>

<Accordion title="Synchronizace s GitHubem hlásí „Something wrong with GitHub request“">

<strong>Odpověď:</strong> Tato zpráva znamená, že se server nemohl spojit s GitHubem, například kvůli problému se sítí, DNS, TLS nebo proxy. Úplnou chybu zobrazíte pomocí `bin/logs web`. Pokud server k připojení na GitHub potřebuje proxy, nastavte `GITHUB_SYNC_PROXY_URL`.

</Accordion>

<Accordion title="Mám v GitHub OAuth App vypnout „Expire user access tokens“?">

<strong>Odpověď:</strong> Ano. Synchronizace s GitHubem neobnovuje tokeny, jejichž platnost vypršela. Se zapnutým vypršením tokenů musí uživatelé GitHub znovu připojit pokaždé, když jejich token vyprší.

</Accordion>

<Accordion title="Musí být moje instance dostupná z internetu?">

<strong>Odpověď:</strong> Ne. Propojení účtu probíhá přes prohlížeč uživatele, takže adresa OAuth callbacku se musí otevřít pouze v prohlížeči uživatele. Server se potřebuje dostat jen k GitHubu; pokud k tomu potřebuje proxy, nastavte `GITHUB_SYNC_PROXY_URL`. GitHub vaši instanci nikdy nevolá: projekt se synchronizuje pouze tehdy, když jej uživatel synchronizuje v editoru.

</Accordion>
