MCP server každého projektu běží ve službě **web** (modul `mcp-server`) každého podu Ayakaleaf Pro. Je součástí [integrace s Gitem](/cs/on-premises/configuration/kubernetes/integrations/git-integration) a nemá žádné vlastní nastavení. Jak připojit Claude Code, Codex a další klienty, je popsáno v části [MCP server](/cs/on-premises/configuration/overleaf-toolkit/integrations/mcp-server).

| | |
| --- | --- |
| Služba | web v každém podu Ayakaleaf Pro |
| Zapíná se pomocí | `GIT_BRIDGE_ENABLED: "true"` a StatefulSetu git-bridge, viz [Integrace s Gitem](/cs/on-premises/configuration/kubernetes/integrations/git-integration) |
| Venku → Overleaf | AI klienti volají `POST ${OVERLEAF_SITE_URL}/project/<id>/mcp` s autentizačním tokenem pro Git; odkazy ke stažení PDF pod `${OVERLEAF_SITE_URL}/project/<id>/mcp/download/` |
| Pod → venku | žádné |
| Stav | mezi požadavky žádný; výstup kompilace zůstává na podu, který kompiloval |
| Periodické úlohy | žádné |

### Konfigurace

Nastavte [integraci s Gitem](/cs/on-premises/configuration/kubernetes/integrations/git-integration). MCP server je pak na adrese `${OVERLEAF_SITE_URL}/project/<project id>/mcp` a tato adresa musí být dostupná z místa, kde běží AI klient.

### Více replik

Kompilace přes MCP běží na replice, která přijala požadavek, a její log i PDF existují jen tam. AI klienti neposílají cookie, takže load balancer může další požadavek, `get_compile_log` nebo odkaz ke stažení PDF, poslat na jinou repliku, která odpoví „failed to fetch output file from CLSI“ nebo 404. V našem testu se třemi replikami a bez dalšího pravidla takto selhalo 5 ze 6 požadavků na log a 3 ze 4 stažení.

Směrujte všechny MCP požadavky projektu na jednu repliku, stejně jako u `/git/`. S HAProxy z [horizontálního škálování](/cs/on-premises/configuration/kubernetes/horizontal-scaling):

```text
      use-server overleaf-0 if { path_reg ^/project/[0-9a-f]{24}/mcp(/|$) }
```

Kompilace přes MCP pak všechny běží na uzlu `overleaf-0`. S jiným ingress controllerem směrujte cestu `/project/<id>/mcp` a vše pod ní na vlastní název jedné repliky (`overleaf-0.overleaf-hl`).

S tímto pravidlem byl stejný test (kompilace, 6 požadavků na log a 4 stažení PDF, vše bez cookie) pokaždé úspěšný.

### Testováno na Kubernetes

Na Kubernetes 1.37 se třemi replikami za HAProxy procházejí naše end-to-end testy MCP serveru (37 případů): výpis nástrojů, odmítnutí chybných, smazaných nebo neoprávněných tokenů, kompilace a čtení logu, počet slov, nastavení a historie projektu, odkazy ke stažení PDF, úpravy souborů se změnami zobrazenými živě v otevřeném editoru a stažené do klonu Gitu, komentáře, přístup podle role, limity četnosti pro kompilaci a nastavení a pozastavené účty. Tyto požadavky přicházely z relace prohlížeče, takže je load balancer držel na jedné replice; pro klienty bez cookie viz [Více replik](#several-replicas).
