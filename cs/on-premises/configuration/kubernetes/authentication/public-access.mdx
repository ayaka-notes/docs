Přístup hostů ke sdíleným projektům, veřejné stránky a samoregistrace se zapínají proměnnými prostředí, které čte služba **web**; služba real-time pak obsluhuje hosty prostřednictvím jejich relace. Co jednotlivé přepínače zpřístupňují, popisuje stránka [Veřejný přístup](/cs/on-premises/configuration/overleaf-toolkit/authentication/public-access).

| | |
| --- | --- |
| Služba | web (a real-time pro hosty v editoru), v každém podu Ayakaleaf Pro; načítá se při spuštění služby web |
| Pod → ven | server SMTP, když registrace odesílá aktivační e-maily |
| Stav | přístupové tokeny hostů v relaci, limity registrací v Redisu |
| Periodické úlohy | žádné |

### Konfigurace

Přidejte potřebné přepínače do ConfigMapy `overleaf-env`:

```yaml title="30-config.yaml (additions)"
  # Guests open link-shared projects without an account
  OVERLEAF_ALLOW_ANONYMOUS_READ_AND_WRITE_SHARING: "true"
  # Signed-out visitors may open /learn, /templates, /devs and view links
  OVERLEAF_ALLOW_PUBLIC_ACCESS: "true"
  # Self-registration: "true", or only some domains
  OVERLEAF_ALLOW_PUBLIC_REGISTRATION: "@example.com, @*.uni.example"
```

```bash
kubectl apply -f 30-config.yaml
kubectl -n overleaf rollout restart deployment/overleaf     # or statefulset/overleaf
```

Všechny hodnoty dejte do uvozovek. Hodnoty začínající znakem `@` musí být v YAML v uvozovkách, jinak `kubectl apply` soubor odmítne.

Registrace omezená na domény odesílá aktivační e-mail, takže z podů musí fungovat [doručování e-mailů](/cs/on-premises/configuration/kubernetes/email-delivery): vložte hostitele SMTP do ConfigMapy a `OVERLEAF_EMAIL_SMTP_PASS` do Secretu.

### Více replik

Nic dalšího není potřeba. Přístup hosta k projektu se uchovává v relaci v Redisu, takže editor funguje na kterékoli replice, kterou load balancer zvolí.

### Otestováno na Kubernetes

Na Kubernetes 1.37 procházejí naše end-to-end testy pro veřejný přístup: na jedné replice samoregistrace s `OVERLEAF_ALLOW_PUBLIC_REGISTRATION` nastaveným na `true`, na jednu doménu, na několik domén se zástupným znakem pro subdomény a na `@*`, s aktivačním e-mailem pro režimy s doménami (43 případů); nepřihlášení návštěvníci na `/devs` a odeslaný úryvek zachovaný přes přihlášení s `OVERLEAF_ALLOW_PUBLIC_ACCESS` (2 případy); nepřihlášený host v projektu sdíleném odkazem s oběma zapnutými přepínači (3 případy); a na třech replikách za HAProxy OIDC společně s veřejným přístupem (1 případ).
