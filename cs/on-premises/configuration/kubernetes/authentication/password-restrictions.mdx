Služba **web** kontroluje lokální hesla, když se uživatelé registrují, nastavují nebo mění heslo. Přihlášení přes SSO (LDAP, SAML, OIDC) se to netýká; jejich hesla jsou věcí poskytovatele identity. Pro Toolkit viz [Omezení hesel](/cs/on-premises/configuration/overleaf-toolkit/authentication/password-restrictions).

| | |
| --- | --- |
| Služba | web, v každém podu Ayakaleaf Pro; načítá se při spuštění služby web |
| Síť | žádná |
| Periodické úlohy | žádné |

### Konfigurace

Přidejte do ConfigMapy `overleaf-env` a restartujte:

```yaml title="30-config.yaml (additions)"
  OVERLEAF_PASSWORD_VALIDATION_MIN_LENGTH: "12"
  OVERLEAF_PASSWORD_VALIDATION_MAX_LENGTH: "72"
```

```bash
kubectl apply -f 30-config.yaml
kubectl -n overleaf rollout restart deployment/overleaf     # or statefulset/overleaf
```

| Proměnná | Výchozí hodnota | |
| --- | --- | --- |
| `OVERLEAF_PASSWORD_VALIDATION_MIN_LENGTH` | `8` | Nejkratší přijímané heslo. |
| `OVERLEAF_PASSWORD_VALIDATION_MAX_LENGTH` | `72` | Nejdelší přijímané heslo; hodnoty nad `72` se považují za `72`. |

Čísla dejte do uvozovek: ConfigMapa obsahuje pouze řetězce.

<Warning>

`OVERLEAF_PASSWORD_VALIDATION_PATTERN` se načítá, ale nevynucuje: heslo, které mu neodpovídá, je přijato. Platí pouze omezení délky.

</Warning>

### Více replik

Nic dalšího není potřeba: každá replika čte stejnou ConfigMapu.

### Otestováno na Kubernetes

Na Kubernetes 1.37 s jednou replikou, s `OVERLEAF_PASSWORD_VALIDATION_MIN_LENGTH: "12"` a `OVERLEAF_PASSWORD_VALIDATION_PATTERN: aA$3` v ConfigMapě, aktivace nového účtu odmítla heslo o 10 znacích a přijala heslo o 20 znacích tvořené pouze malými písmeny, které by vzor odmítl. Naše end-to-end testy registrace také s výchozím nastavením odmítají `123456` jako příliš krátké.
