Každá služba uvnitř podu Ayakaleaf Pro zapisuje vlastní soubor logu do `/var/log/overleaf/`; `kubectl logs` zobrazuje pouze výstup kontejneru při startu (inicializační skripty, migrace). Příkaz `bin/logs` z Toolkitu čte stejné soubory, viz [Logování](/cs/on-premises/configuration/overleaf-toolkit/logging).

| Kde | Co |
| --- | --- |
| `kubectl -n overleaf logs <pod>` | start: kontrola tajných klíčů, migrace (`Finished migrations`), spouštění služeb |
| `/var/log/overleaf/<service>.log` v podu | `web.log`, `web-api.log`, `clsi.log`, `real-time.log`, `document-updater.log`, `docstore.log`, `filestore.log`, `history-v1.log`, `project-history.log`, `chat.log`, `notifications.log`, `linked-url-proxy.log` a se zapnutým Dropboxem `third-party-datastore.log` |
| `/var/log/nginx/` v podu | `access.log`, `error.log` nginxu před službami |
| `kubectl -n overleaf logs mongo-0`, `redis-0`, `git-bridge-0` | MongoDB, Redis a git-bridge, které běží ve vlastních podech |

### Čtení logů

| Toolkit | Kubernetes |
| --- | --- |
| `bin/logs web` | `kubectl -n overleaf exec deploy/overleaf -- tail -n 20 /var/log/overleaf/web.log` |
| `bin/logs -f web clsi` | `kubectl -n overleaf exec deploy/overleaf -- tail -f /var/log/overleaf/web.log /var/log/overleaf/clsi.log` |
| `bin/logs -n all web > web.log` | `kubectl -n overleaf cp overleaf/<pod>:/var/log/overleaf/web.log web.log` |
| `bin/logs mongo` | `kubectl -n overleaf logs mongo-0` |

S [více replikami](/cs/on-premises/configuration/kubernetes/horizontal-scaling) má každý pod vlastní soubory: místo `deploy/overleaf` použijte název podu (`overleaf-0`, `overleaf-1`, ...). Hlavička `X-Served-By`, kterou přidává HAProxy, říká, která replika na požadavek odpověděla.

`LOG_LEVEL` v ConfigMapu (výchozí `info`, dále `debug`, `warn`, `error`) nastavuje úroveň všech služeb v podu najednou.

### Uchovávání logů

Soubory jsou uloženy v kontejneru a při nahrazení podu se ztratí. Chcete-li je uchovat, připojte v Deploymentu nebo StatefulSetu svazek do `/var/log/overleaf`, například `hostPath` na uzlu nebo PersistentVolumeClaim:

```yaml
          volumeMounts:
            # ...
            - name: logs
              mountPath: /var/log/overleaf
      volumes:
        # ...
        - name: logs
          hostPath:
            path: /srv/overleaf-logs
            type: DirectoryOrCreate
```

Kontejner soubory denně rotuje a uchovává jich pět, takže svazek neroste bez omezení. Případně je z této cesty sbírejte logovacím agentem vašeho clusteru.

### Testováno na Kubernetes

Na Kubernetes 1.37 se třemi replikami a svazkem `hostPath` v `/var/log/overleaf` podle výše uvedeného obsahoval adresář `/srv/overleaf-logs` každého uzlu dvanáct logů služeb jeho repliky a příkazy z tabulky fungovaly, jak je uvedeno: `tail` přes `kubectl exec`, `kubectl cp` souboru logu, `kubectl logs` podu Overleaf (start a migrace) a podu `mongo-0`.
