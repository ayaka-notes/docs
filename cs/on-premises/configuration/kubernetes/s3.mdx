Soubory projektů a jejich historii ukládá služba **history-v1**, soubory šablon služba **filestore**, obě uvnitř každého podu Ayakaleaf Pro. Ve výchozím nastavení zapisují na datový svazek; s S3 zapisují do bucketů. Které buckety a oprávnění jsou potřeba, je popsáno v části [S3](/cs/on-premises/configuration/overleaf-toolkit/s3).

| | |
| --- | --- |
| Služby | history-v1 (soubory projektů a historie), filestore (soubory šablon), v každém podu Ayakaleaf Pro |
| Pod → S3 | endpoint S3, pro každé čtení nebo zápis souboru |
| Vyžadováno | pro [více replik](/cs/on-premises/configuration/kubernetes/horizontal-scaling): jejich datové svazky nejsou sdílené, buckety ano |
| Periodické úlohy | žádné |

<Warning>

Zvolte S3 dříve, než uživatelé vytvoří projekty. Instance, která již uchovává soubory na svém svazku, nejprve potřebuje [migraci na S3](/cs/on-premises/maintenance/s3-migration).

</Warning>

### Konfigurace

<Steps>
<Step title="Buckety a klíče">
Vytvořte ve své službě S3 tři buckety `overleaf-template-files`, `overleaf-project-blobs` a `overleaf-chunks` a dva uživatele s omezenými oprávněními podle popisu v části [Nastavení S3](/cs/on-premises/configuration/overleaf-toolkit/s3#s3-setup), nebo v clusteru spusťte Garage, jak je ukázáno níže. Vložte čtyři klíče do Secretu:

```bash wrap
kubectl -n overleaf create secret generic overleaf-s3 \
  --from-literal=OVERLEAF_FILESTORE_S3_ACCESS_KEY_ID=<filestore key> \
  --from-literal=OVERLEAF_FILESTORE_S3_SECRET_ACCESS_KEY=<filestore secret> \
  --from-literal=OVERLEAF_HISTORY_S3_ACCESS_KEY_ID=<history key> \
  --from-literal=OVERLEAF_HISTORY_S3_SECRET_ACCESS_KEY=<history secret>
```
</Step>

<Step title="ConfigMap">
```yaml title="30-config.yaml (additions)" wrap
  OVERLEAF_FILESTORE_BACKEND: s3
  OVERLEAF_FILESTORE_TEMPLATE_FILES_BUCKET_NAME: overleaf-template-files
  OVERLEAF_FILESTORE_S3_REGION: eu-west-1
  OVERLEAF_HISTORY_BACKEND: s3
  OVERLEAF_HISTORY_PROJECT_BLOBS_BUCKET: overleaf-project-blobs
  OVERLEAF_HISTORY_CHUNKS_BUCKET: overleaf-chunks
  OVERLEAF_HISTORY_S3_REGION: eu-west-1
  # a self-hosted S3 service also needs its endpoint and path-style addressing
  # OVERLEAF_FILESTORE_S3_ENDPOINT: http://garage:3900
  # OVERLEAF_FILESTORE_S3_PATH_STYLE: "true"
  # OVERLEAF_HISTORY_S3_ENDPOINT: http://garage:3900
  # OVERLEAF_HISTORY_S3_PATH_STYLE: "true"
```
</Step>

<Step title="Přidejte Secret do podu a restartujte">
V Deploymentu (nebo StatefulSetu) přidejte Secret vedle ostatních:

```yaml
          envFrom:
            - configMapRef: {name: overleaf-env}
            - secretRef: {name: overleaf-secrets}
            - secretRef: {name: overleaf-s3}
```

```bash
kubectl apply -f 30-config.yaml -f 40-overleaf.yaml
kubectl -n overleaf rollout restart deployment/overleaf     # or statefulset/overleaf
```
</Step>
</Steps>

### Garage v clusteru

Pokud nemáte službu S3, je [Garage](https://garagehq.deuxfleurs.fr/) malý S3 server, který běží v clusteru. Nastavení z [horizontálního škálování](/cs/on-premises/configuration/kubernetes/horizontal-scaling) bylo testováno s ním. Níže uvedené příkazy samy vygenerují klíče a vytvoří Secret `overleaf-s3`, proto je použijte místo příkazu pro Secret v kroku 1.

<Info>

MinIO, použité v ukázce Overleafu, již nepublikuje obrazy kontejnerů: `minio/minio` zmizel z Docker Hubu i z quay.io.

</Info>

```yaml title="50-garage.yaml" wrap
apiVersion: v1
kind: ConfigMap
metadata:
  name: garage-config
  namespace: overleaf
data:
  garage.toml: |
    metadata_dir = "/var/lib/garage/meta"
    data_dir = "/var/lib/garage/data"
    db_engine = "lmdb"
    replication_factor = 1
    rpc_bind_addr = "[::]:3901"
    rpc_public_addr = "127.0.0.1:3901"
    # rpc_secret and admin_token come from GARAGE_RPC_SECRET / GARAGE_ADMIN_TOKEN
    [s3_api]
    s3_region = "garage"          # Overleaf's OVERLEAF_*_S3_REGION must match
    api_bind_addr = "[::]:3900"
    [admin]
    api_bind_addr = "[::]:3903"
---
apiVersion: v1
kind: Service
metadata:
  name: garage
  namespace: overleaf
spec:
  selector:
    app: garage
  ports:
    - name: s3
      port: 3900
---
apiVersion: apps/v1
kind: StatefulSet
metadata:
  name: garage
  namespace: overleaf
spec:
  serviceName: garage
  replicas: 1
  selector:
    matchLabels:
      app: garage
  template:
    metadata:
      labels:
        app: garage
    spec:
      containers:
        - name: garage
          image: dxflrs/garage:v2.5.0
          env:
            - name: GARAGE_RPC_SECRET
              valueFrom: {secretKeyRef: {name: garage-secrets, key: rpc_secret}}
            - name: GARAGE_ADMIN_TOKEN
              valueFrom: {secretKeyRef: {name: garage-secrets, key: admin_token}}
          ports:
            - containerPort: 3900
          readinessProbe:
            tcpSocket:
              port: 3900
          resources:
            requests: {cpu: 50m, memory: 64Mi}
            limits: {memory: 512Mi}
          volumeMounts:
            - {name: config, mountPath: /etc/garage.toml, subPath: garage.toml}
            - {name: data, mountPath: /var/lib/garage}
      volumes:
        - name: config
          configMap:
            name: garage-config
  volumeClaimTemplates:
    - metadata:
        name: data
      spec:
        accessModes: [ReadWriteOnce]
        resources:
          requests:
            storage: 10Gi
```

Vygenerujte tajné klíče, spusťte Garage a poté vytvořte layout, buckety a dva klíče s omezenými oprávněními. ID klíčů v Garage tvoří `GK` a 24 hexadecimálních znaků, tajné klíče 64 hexadecimálních znaků:

```bash wrap
kubectl -n overleaf create secret generic garage-secrets \
  --from-literal=rpc_secret="$(openssl rand -hex 32)" \
  --from-literal=admin_token="$(openssl rand -base64 32)"
kubectl -n overleaf create secret generic overleaf-s3 \
  --from-literal=OVERLEAF_FILESTORE_S3_ACCESS_KEY_ID="GK$(openssl rand -hex 12)" \
  --from-literal=OVERLEAF_FILESTORE_S3_SECRET_ACCESS_KEY="$(openssl rand -hex 32)" \
  --from-literal=OVERLEAF_HISTORY_S3_ACCESS_KEY_ID="GK$(openssl rand -hex 12)" \
  --from-literal=OVERLEAF_HISTORY_S3_SECRET_ACCESS_KEY="$(openssl rand -hex 32)"
kubectl apply -f 50-garage.yaml
kubectl -n overleaf rollout status statefulset/garage

g() { kubectl -n overleaf exec garage-0 -- /garage "$@"; }
s() { kubectl -n overleaf get secret overleaf-s3 -o jsonpath="{.data.$1}" | base64 -d; }
g layout assign -z dc1 -c 8G "$(g status 2>/dev/null | awk '/^[0-9a-f]{16}/{print $1; exit}')"
g layout apply --version 1
for b in overleaf-template-files overleaf-project-blobs overleaf-chunks; do g bucket create "$b"; done
g key import --yes -n overleaf-filestore "$(s OVERLEAF_FILESTORE_S3_ACCESS_KEY_ID)" "$(s OVERLEAF_FILESTORE_S3_SECRET_ACCESS_KEY)"
g key import --yes -n overleaf-history "$(s OVERLEAF_HISTORY_S3_ACCESS_KEY_ID)" "$(s OVERLEAF_HISTORY_S3_SECRET_ACCESS_KEY)"
g bucket allow --read --write overleaf-template-files --key overleaf-filestore
g bucket allow --read overleaf-project-blobs --key overleaf-filestore
g bucket allow --read --write overleaf-project-blobs --key overleaf-history
g bucket allow --read --write overleaf-chunks --key overleaf-history
```

Oprávnění odpovídají zásadám v části [S3](/cs/on-premises/configuration/overleaf-toolkit/s3#access-policies). Garage kontroluje region: zde je to `garage` a `OVERLEAF_*_S3_REGION` musí být stejný.

S Garage nastavte v ConfigMapu pro obě služby endpoint, `PATH_STYLE: "true"` a region `garage`, jako v `60-config.yaml` z [horizontálního škálování](/cs/on-premises/configuration/kubernetes/horizontal-scaling).

### Více replik

Všechny repliky musí používat stejné buckety a klíče. Zálohujte buckety nástroji svého poskytovatele S3; vlastní disky replik pak neobsahují žádná data, která by potřebovala zálohu.

### Testováno na Kubernetes

Na Kubernetes 1.37 se třemi replikami a Garage podle výše uvedeného prošel každý end-to-end test z těchto stránek, který vytváří projekty, nahrává soubory, používá historii nebo publikuje šablony, a poté buckety `overleaf-project-blobs`, `overleaf-chunks` a `overleaf-template-files` obsahovaly objekty, zatímco vlastní `/var/lib/overleaf/data/history` replik zůstal prázdný.
