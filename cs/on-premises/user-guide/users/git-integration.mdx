Pracujte na projektu na svém vlastním počítači pomocí Gitu. Změny se přenášejí pouze tehdy, když spustíte `git pull` nebo `git push`.

<Info>

Správce musí nejprve zapnout [integraci s Gitem](/cs/on-premises/configuration/overleaf-toolkit/integrations/git-integration).

</Info>

## Vytvoření tokenu {#create-a-token}

Git se přihlašuje pomocí ověřovacího tokenu Gitu, nikoli heslem k vašemu účtu.

<Steps>
<Step title="Otevřete nastavení účtu">
Klikněte na **Account** a poté na **Account settings**. V části **Git integration** klikněte na **Generate token**. Jakmile máte token, toto tlačítko se jmenuje **Add another token**.

<Frame caption="Integrace s Gitem v nastavení účtu">
  <img src="/images/on-premises/git-integration-settings.png" alt="Část Git integration v nastavení účtu s tlačítkem Generate token" />
</Frame>
</Step>

<Step title="Zkopírujte token">
Klikněte na **Copy** a uložte token na bezpečné místo. Uvidíte ho jen jednou. Poté klikněte na **Close**.

<Frame caption="Váš nový token">
  <img src="/images/on-premises/git-integration-token.png" alt="Dialog ověřovacího tokenu Gitu s tlačítkem Copy" />
</Frame>
</Step>

<Step title="Zkontrolujte token">
Seznam teď ukazuje začátek tokenu, kdy byl vytvořen a kdy byl naposledy použit. Platnost vyprší po jednom roce. Můžete mít až 10 tokenů.

<Frame caption="Vaše tokeny">
  <img src="/images/on-premises/git-integration-tokens.png" alt="Seznam tokenů s jedním tokenem" />
</Frame>
</Step>
</Steps>

## Klonování projektu {#clone-a-project}

<Steps>
<Step title="Otevřete integraci s Gitem v editoru">
Otevřete projekt. V levém panelu klikněte na **Integrations** a poté na **Git integration**.

<Frame caption="Panel Integrations">
  <img src="/images/on-premises/git-integration-panel.png" alt="Panel Integrations s kartou Git integration" />
</Frame>
</Step>

<Step title="Zkopírujte příkaz">
Dialog **Clone with Git** zobrazuje příkaz s adresou vašeho webu a ID projektu. Klikněte na **Copy**. Pokud ještě nemáte token, **Go to settings** otevře nastavení účtu na nové kartě.

<Frame caption="Příkaz pro klonování">
  <img src="/images/on-premises/git-integration-clone.png" alt="Dialog Clone with Git s příkazem git clone" />
</Frame>
</Step>

<Step title="Spusťte ho">
Vložte příkaz do terminálu. Když Git požádá o heslo, vložte svůj token.

```text
$ git clone https://git@<your-site>/git/<project-id>
Cloning into '<project-id>'...
Password for 'https://git@<your-site>': <your-token>
```

Složka pojmenovaná podle ID projektu teď obsahuje soubory projektu ve větvi `main`. Chcete-li zvolit název složky, přidejte ho na konec příkazu.
</Step>
</Steps>

Git žádá o token pokaždé, když se připojuje k webu. Aby si ho zapamatoval, zapněte credential helper: Git se zeptá ještě jednou a pak token uchová. Helper `store` ho ukládá nešifrovaně do `~/.git-credentials`.

```bash
git config --global credential.helper store
```

## Stažení změn z editoru {#pull-changes-from-the-editor}

Ve složce spusťte:

```bash
git pull
```

Git vypíše změněné soubory. Změny provedené v editoru přicházejí jako commity s názvem `Update on Overleaf.`.

```text
Updating db007e3..c3e6332
Fast-forward
 main.tex | 2 +-
 1 file changed, 1 insertion(+), 1 deletion(-)
```

## Odeslání změn {#push-your-changes}

Commitněte své změny a poté je odešlete:

```bash
git add main.tex
git commit -m "Add a line from Git"
git push
```

Poslední řádek výstupu ukazuje větev, která se posunula:

```text
   53aca61..db007e3  main -> main
```

Změny se objeví v editoru a otevřený editor se aktualizuje sám. Nové soubory, složky a přejmenování se zobrazí ve stromu souborů. V **History** je vaše změna označena jako <strong>You (via Git)</strong>. Vaše zpráva commitu se tam nezobrazuje.

### Pokud Git push odmítne {#if-git-refuses-your-push}

Pokud se projekt mezitím změnil, Git push odmítne:

```text
 ! [rejected]        main -> main (fetch first)
```

Nejprve tyto změny stáhněte a pak odešlete znovu:

```bash
git pull --no-rebase --no-edit
git push
```

Obyčejný `git pull` se může zastavit se zprávou `fatal: Need to specify how to reconcile divergent branches.` Volba `--no-rebase` výše to řeší: sloučí obě strany.

Pokud se na obou stranách změnily stejné řádky, pull se zastaví se zprávou `CONFLICT (content): Merge conflict in main.tex`. Opravte soubor a poté spusťte:

```bash
git add main.tex
git commit -m "Merge the changes from the editor"
git push
```

Web nepřijímá dvě věci:

* Jiné větve: `! [remote rejected] feature -> feature (wrong branch)`. Existuje pouze `main`, takže práci odesílejte tam.
* Vynucený push: `! [remote rejected] main -> main (forced push prohibited)`. Místo toho umístěte své změny na aktuální `main`.

### Pokud Git hlásí Authentication failed {#if-git-says-authentication-failed}

```text
remote: Enter your Git authentication token when prompted for a password.
fatal: Authentication failed for 'https://<your-site>/git/<project-id>/'
```

Token je nesprávný nebo byl smazán, případně jste zadali heslo k účtu. Pokud token už nemáte, vytvořte nový, protože existující token nelze znovu zobrazit.

## Smazání tokenu {#delete-a-token}

V **Account settings** v části **Git integration** klikněte na ikonu smazání vedle tokenu a poté v dialogu na **Delete**. Od té chvíle Git na tento token odpovídá `Authentication failed`.
