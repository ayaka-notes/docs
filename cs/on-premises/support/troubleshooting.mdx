<Accordion title="Provoz Overleafu se souborovým systémem NFS">

Připojení souborového systému NFS v kontejneru Overleafu je technicky možné, ale nedoporučuje se a může vést k různým typům výkonnostních chyb.

Jedna z běžných chyb, které se při kompilaci objevují, je:

```text
EBUSY: resource busy or locked, unlink '/var/lib/overleaf/data/compiles/62f3d57bef7cf9005c364e75-62f3d57bef7cf9005c364e7a/.nfs573663533034825247625441'
```

Zejména nedoporučujeme používat souborové systémy založené na NFS pro dočasná data, například pro adresáře používané pro data kompilace. Pro následující adresáře doporučujeme použít lokální pracovní (scratch) disk, nejlépe lokální SSD.

U instalací založených na `docker-compose` doporučujeme jednoduše přepsat bind-mount z NFS, čímž se vyhnete změnám cest v aplikaci. Zde je příklad výňatku z konfigurace `docker-compose` s použitím pracovního disku připojeného do `/scratch`:

```yaml title="docker-compose excerpt"
services:
  sharelatex:
    environment:
      SANDBOXED_COMPILES_HOST_DIR: /scratch/compiles/
    volumes:
      - nfs:/var/lib/overleaf/data
      - /scratch/cache/:/var/lib/overleaf/data/cache
      - /scratch/compiles/:/var/lib/overleaf/data/compiles
      - /scratch/output/:/var/lib/overleaf/data/output
      - /scratch/tmp/:/var/lib/overleaf/tmp
```

Po aktualizaci není nutné migrovat žádné existující soubory z NFS na jejich nové umístění. Kompilátor LaTeXu dokáže všechny soubory znovu vytvořit při další úplné kompilaci.

Další podrobnosti viz: https://docs.overleaf.com/on-premises/support/troubleshooting#running-overleaf-with-an-nfs-filesystem

</Accordion>

<Accordion title="Při provozu Overleafu na Windows nebo macOS se nespustí služba `mongo`">

Pokud provozujete Overleaf na Windows nebo macOS, služba `mongo` se nemusí podařit restartovat a zobrazí se chyba:

```text title="Example error"
Failed to start up WiredTiger under any compatibility version.
Reason: 1: Operation not permitted
```

Abyste se této chybě vyhnuli, je nutné data ukládat do svazku (volume), nikoli do adresáře připojeného pomocí bind mount (další podrobnosti viz dokumentace image `mongo`: https://github.com/docker-library/docs/blob/master/mongo/content.md#where-to-store-data). Chcete-li ukládat data do svazků Dockeru připojených v kontejnerech MongoDB a Redis, přidejte do `config/docker-compose.override.yml` následující obsah (pokud soubor ještě neexistuje, vytvořte jej):

```yaml title="config/docker-compose.override.yml"
volumes:
  mongo-data:
  redis-data:

services:
  mongo:
    volumes:
      - mongo-data:/data/db

  redis:
    volumes:
      - redis-data:/data
```

Další informace viz: https://docs.overleaf.com/on-premises/support/troubleshooting#running-overleaf-on-windows-or-macos-results-in-the-mongoservice-not-starting

</Accordion>

<Accordion title="Upgrade na Redis 6.2 vede ke smyčce restartů">

Pomocí příkazu `docker logs redis` vypište kopii logů.

Pokud vidíte řádek `Fatal: Can't initialize Background Jobs`, celý výstup bude vypadat přibližně takto:

```text title="Redis log example"
1:M 11 Feb 2024 15:19:22.609 # Server initialized
1:M 11 Feb 2024 15:19:22.609 # Fatal: Can't initialize Background Jobs.
1:C 11 Feb 2024 15:19:26.055 # oO0OoO0OoO0Oo Redis is starting oO0OoO0OoO0Oo
```

To může souviset s aktuálně používanou verzí Dockeru. Problém by měl vyřešit upgrade na verzi >= 20.10.10.

Další informace najdete v upstream issue Redisu: https://github.com/redis/redis/issues/12362

Reference: https://docs.overleaf.com/on-premises/support/troubleshooting#upgrading-to-redis-6.2-results-in-a-restart-loop

</Accordion>

<Accordion title="Nesprávná orientace náhledových obrázků/miniatur v galerii šablon">

Občas mohou být náhledové obrázky/miniatury generované Server Pro vytvořeny ve špatné orientaci a jejich oprava vyžaduje ruční zásah. Tyto obrázky jsou uloženy v `/var/lib/overleaf/data/template_files/` (>= 5.0.3) a `/var/lib/sharelatex/data/template_files/` (starší verze).

Před provedením jakýchkoli změn doporučujeme tuto složku zálohovat.

Pro každou dotčenou šablonu budete muset provést následující kroky:

Zjištění ID šablonyPřejděte do galerie šablon vaší instance (/templates/all), otevřete dotčenou šablonu a zkopírujte ID z URL (například: https://your-instance-url/templates/6645d346c224815e9460a695).Spuštění opravného příkazuSpusťte z hostitele Dockeru následující příkaz (nahraďte ID šablony tím, které jste zkopírovali, a případně upravte cestu):docker exec sharelatex /bin/bash -c "mogrify -rotate 90 /var/lib/overleaf/data/template\_files/6645d346c224815e9460a695\_\*\{thumbnail,preview\}"

Reference: https://docs.overleaf.com/on-premises/support/troubleshooting#incorrect-orientation-of-template-gallery-preview-thumbnail-images

</Accordion>

<Accordion title="Ověřte prosím, že máte povolena systémová volání. Pro pdflatex je to 'pdflatex -shell-escape'.">

Příkaz `\write18` je v Community Edition ve výchozím nastavení zakázán, protože všechny kompilace probíhají ve stejném kontejneru `sharelatex`; toto je bezpečnější výchozí nastavení.

Pokud jej chcete pro pdflatex povolit, vytvořte v kořenovém adresáři projektu soubor `latexmkrc` s následujícím obsahem:

```perl title="latexmkrc"
$pdflatex = 'pdflatex --shell-escape';
```

Poté zkuste projekt znovu zkompilovat.

Reference: https://docs.overleaf.com/on-premises/support/troubleshooting#please-verify-that-you-have-enabled-system-calls.-for-pdflatex-this-is-pdflatex-shell-escape

</Accordion>
