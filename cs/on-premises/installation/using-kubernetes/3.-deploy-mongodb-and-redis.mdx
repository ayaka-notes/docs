Ayakaleaf Pro potřebuje:

* **MongoDB 8** jako **replica set** (používá transakce). Tři členové rozložení na tři uzly přežijí výpadek uzlu; funguje i jeden člen.
* **Redis 7**, jeden server s perzistencí AOF. Redis uchovává úpravy, které ještě nejsou zapsány do MongoDB, relace a zprávy mezi službami Overleafu. Overleaf se připojuje k jedinému serveru Redis: Sentinel a Redis Cluster nejsou podporovány.

<Info>

Místo toho můžete použít spravované služby, například MongoDB Atlas nebo Redis svého cloudu. Tuto stránku přeskočte a v [kroku 4](/cs/on-premises/installation/using-kubernetes/4.-personalizing-your-instance) na ně nastavte `OVERLEAF_MONGO_URL` a `OVERLEAF_REDIS_HOST`.

</Info>

<Steps>
<Step title="MongoDB">
```yaml title="10-mongo.yaml" wrap
apiVersion: v1
kind: Service
metadata:
  name: mongo
  namespace: overleaf
spec:
  clusterIP: None                 # headless: gives mongo-0.mongo, mongo-1.mongo, ...
  publishNotReadyAddresses: true  # members must resolve each other before the set is initiated
  selector:
    app: mongo
  ports:
    - name: mongo
      port: 27017
---
apiVersion: apps/v1
kind: StatefulSet
metadata:
  name: mongo
  namespace: overleaf
spec:
  serviceName: mongo
  replicas: 3
  selector:
    matchLabels:
      app: mongo
  template:
    metadata:
      labels:
        app: mongo
    spec:
      affinity:
        podAntiAffinity:
          requiredDuringSchedulingIgnoredDuringExecution:
            - labelSelector:
                matchLabels:
                  app: mongo
              topologyKey: kubernetes.io/hostname
      containers:
        - name: mongo
          image: mongo:8.0
          args:
            - --replSet=overleaf
            - --bind_ip_all
            - --wiredTigerCacheSizeGB=0.25   # default is 50% of (RAM - 1 GB); size it for your nodes
          # env:
          #   - name: GLIBC_TUNABLES        # only on kernel 6.19+ (SERVER-121912)
          #     value: glibc.pthread.rseq=1
          ports:
            - containerPort: 27017
          readinessProbe:
            tcpSocket:
              port: 27017
          resources:
            requests:
              cpu: 100m
              memory: 384Mi
            limits:
              memory: 768Mi
          volumeMounts:
            - name: data
              mountPath: /data/db
  volumeClaimTemplates:
    - metadata:
        name: data
      spec:
        accessModes: [ReadWriteOnce]
        resources:
          requests:
            storage: 5Gi
---
# Initiates the replica set once. Safe to re-run: it does nothing when the set exists.
apiVersion: batch/v1
kind: Job
metadata:
  name: mongo-init-replica-set
  namespace: overleaf
spec:
  backoffLimit: 20
  template:
    spec:
      restartPolicy: OnFailure
      containers:
        - name: init
          image: mongo:8.0
          command:
            - mongosh
            - --quiet
            - --host=mongo-0.mongo
            - --eval
            - |
              try {
                rs.status()
                print('replica set already initiated')
              } catch (e) {
                rs.initiate({
                  _id: 'overleaf',
                  members: [
                    { _id: 0, host: 'mongo-0.mongo.overleaf.svc.cluster.local:27017' },
                    { _id: 1, host: 'mongo-1.mongo.overleaf.svc.cluster.local:27017' },
                    { _id: 2, host: 'mongo-2.mongo.overleaf.svc.cluster.local:27017' },
                  ],
                })
              }
```

```bash
kubectl apply -f 10-mongo.yaml
kubectl -n overleaf rollout status statefulset/mongo
kubectl -n overleaf wait --for=condition=complete job/mongo-init-replica-set --timeout=5m
kubectl -n overleaf exec mongo-0 -- mongosh --quiet --eval 'rs.status().members.map(m => m.name + " " + m.stateStr)'
```

Po několika sekundách by měl být jeden člen `PRIMARY` a ostatní `SECONDARY`. Job to zkouší znovu, dokud neodpovědí všichni členové, takže několik neúspěšných podů Jobu je normální.

* Headless Service potřebuje `publishNotReadyAddresses: true`: členové se musí navzájem najít podle názvu dříve, než replica set existuje.
* Členové se přidávají se svými stabilními názvy (`mongo-0.mongo.overleaf.svc.cluster.local`), nikdy ne s IP adresami podů, které se mění při každém restartu.
* Pro jediného člena nastavte `replicas: 1` a v Jobu ponechte pouze `mongo-0`.
</Step>

<Step title="Redis">
```yaml title="20-redis.yaml" wrap
apiVersion: v1
kind: Service
metadata:
  name: redis
  namespace: overleaf
spec:
  selector:
    app: redis
  ports:
    - name: redis
      port: 6379
---
apiVersion: apps/v1
kind: StatefulSet
metadata:
  name: redis
  namespace: overleaf
spec:
  serviceName: redis
  replicas: 1
  selector:
    matchLabels:
      app: redis
  template:
    metadata:
      labels:
        app: redis
    spec:
      containers:
        - name: redis
          image: redis:7.4
          args: [--appendonly, "yes"]
          ports:
            - containerPort: 6379
          readinessProbe:
            tcpSocket:
              port: 6379
          resources:
            requests:
              cpu: 50m
              memory: 128Mi
            limits:
              memory: 512Mi
          volumeMounts:
            - name: data
              mountPath: /data
  volumeClaimTemplates:
    - metadata:
        name: data
      spec:
        accessModes: [ReadWriteOnce]
        resources:
          requests:
            storage: 2Gi
```

```bash
kubectl apply -f 20-redis.yaml
kubectl -n overleaf rollout status statefulset/redis
```
</Step>

### Q\&A

<Accordion title="MongoDB 8 na novém jádře při startu padá. Proč?">

<strong>Odpověď:</strong> MongoDB 8 selhává na linuxovém jádře 6.19 a novějším ([SERVER-121912](https://jira.mongodb.org/browse/SERVER-121912)). Odkomentujte proměnnou prostředí `GLIBC_TUNABLES` v `10-mongo.yaml`.

</Accordion>

<Accordion title="Kolik paměti MongoDB potřebuje?">

<strong>Odpověď:</strong> Ve výchozím nastavení používá MongoDB pro svou cache polovinu paměti uzlu minus 1 GB a vidí paměť uzlu, nikoli limit podu. Nastavte `--wiredTigerCacheSizeGB` podle svých uzlů; `0.25` udrželo každého člena na našich testovacích uzlech se 4 GB na přibližně 200 až 260 MiB.

</Accordion>
