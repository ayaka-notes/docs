Ayakaleaf Pro používá linuxové kontejnery. Ve Windows nainstalujte Docker Desktop s backendem WSL 2 a skripty Toolkitu spouštějte v Ubuntu.

WSL 2 poskytuje linuxové jádro. Docker Desktop spravuje engine Dockeru ve vlastním prostředí `docker-desktop`; zapnutí **WSL Integration** umožní Docker CLI v Ubuntu s tímto enginem komunikovat. Toolkit pak spustí aplikaci, MongoDB a Redis jako kontejnery. Se zapnutými Sandboxed Compiles používá aplikace Docker socket enginu ke spuštění samostatného kontejneru TeX Live pro každou kompilaci. Instalace MongoDB, Redis ani TeX Live pro Windows nepotřebujete.

<Steps>
<Step title="Nainstalujte WSL 2 a Ubuntu">
Ve Windows otevřete **PowerShell jako správce** a spusťte:

```powershell
wsl --install -d Ubuntu
```

Pokud k tomu budete vyzváni, restartujte Windows. Otevřete **Ubuntu** z nabídky Start a vytvořte linuxové uživatelské jméno a heslo. Jde o účet pro `sudo` uvnitř Ubuntu; je oddělený od vašeho přihlášení do Windows.

Zpět v **PowerShellu** aktualizujte WSL a zkontrolujte distribuci:

```powershell
wsl --update
wsl --version
wsl --list --verbose
```

Řádek Ubuntu musí ukazovat **VERSION 2**. Pokud ukazuje 1, použijte přesný název distribuce ze seznamu:

```powershell
wsl --set-version Ubuntu 2
```

Docker vyžaduje WSL **2.1.5 nebo novější**; verze softwaru WSL z `wsl --version` a sloupec **VERSION 2** distribuce jsou různé kontroly. Pokud instalace selže, viz [řešení problémů s instalací](/cs/on-premises/installation/using-docker-compose/windows/troubleshooting#wsl-or-docker-reports-that-virtualization-is-unavailable) a [pokyny k instalaci od Microsoftu](https://learn.microsoft.com/en-us/windows/wsl/install), a pokud WSL hlásí, že hardwarová virtualizace není dostupná, zapněte ji v BIOS/UEFI.
</Step>

<Step title="Nainstalujte a spusťte Docker Desktop">
Stáhněte [Docker Desktop pro Windows](https://docs.docker.com/desktop/setup/install/windows-install/) pro svůj procesor a spusťte instalační program. Pokud je nabídnut, použijte backend **WSL 2**. Otevřete **Docker Desktop** z nabídky Start ve Windows a počkejte, až se engine spustí.

V Docker Desktop v **Settings → General** zapněte **Use WSL 2 based engine**, pokud je tato volba zobrazena. V **Settings → Resources → WSL Integration** zapněte integraci pro **Ubuntu** a poté vyberte **Apply** nebo **Apply & restart**. Pokud Ubuntu není vaší výchozí distribucí, zapněte výslovně její vlastní přepínač.

Pokud WSL Integration chybí, zkontrolujte, že Docker Desktop používá **Linux containers**. Viz [návod Dockeru k backendu WSL 2](https://docs.docker.com/desktop/features/wsl/).

Pro tento návod použijte integraci Docker Desktop. Instalace druhého Docker Engine pomocí `apt install docker.io` nebo spuštění `dockerd` uvnitř Ubuntu vytvoří samostatné nastavení a může způsobit konflikty. Pokud už v Ubuntu Engine používáte, postupujte před přepnutím podle pokynů Dockeru k migraci; zachovejte stávající data aplikací a zálohy.
</Step>

<Step title="Zkontrolujte Docker z Ubuntu">
Otevřete terminál **Ubuntu**. Spusťte v něm tyto příkazy bez `sudo`:

```bash
docker version
docker compose version
docker ps
```

`docker version` musí zobrazit **Client** i **Server**. Prázdný seznam kontejnerů je u nové instalace normální. Samotný `docker --version` nedokazuje, že engine běží.

Pokud `docker` není dostupný nebo se nemůže připojit, po použití WSL Integration Ubuntu znovu otevřete a zkontrolujte, že Docker Desktop běží. Viz [Řešení problémů](/cs/on-premises/installation/using-docker-compose/windows/troubleshooting#docker-is-unavailable-in-ubuntu).
</Step>

<Step title="Zkontrolujte prostředky a Docker socket">
Zkontrolujte prostředky viditelné pro Docker:

```bash
docker info --format 'CPUs={{.NCPU}} Memory={{.MemTotal}} Kernel={{.KernelVersion}}'
df -h "$HOME"
ls -l /var/run/docker.sock
```

Pro malou lokální instanci jsou 4 CPU a 8 GB paměti dostupné pro Docker výchozím doporučením, nikoli změřeným minimem. Ponechte dostatek paměti i pro Windows. S backendem WSL 2 se limity prostředků spravují prostřednictvím [nastavení WSL](https://learn.microsoft.com/en-us/windows/wsl/wsl-config), nikoli posuvníky prostředků Docker Desktop jako na Macu. Změny, které vyžadují `wsl --shutdown`, přeruší všechny běžící distribuce WSL a úlohy Dockeru; proveďte je před spuštěním instance.

V konfiguraci Toolkitu ponechte `DOCKER_SOCKET_PATH=/var/run/docker.sock`. Aplikace potřebuje tento socket enginu pro Sandboxed Compiles. Neměňte jeho oprávnění na `777`, abyste opravili chyby připojení; místo toho obnovte integraci Docker Desktop.
</Step>
</Steps>
