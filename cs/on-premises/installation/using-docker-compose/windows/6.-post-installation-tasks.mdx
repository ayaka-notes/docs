### Vytvoření administrátora a prvního projektu {#create-the-administrator-and-a-first-project}

V **prohlížeči ve Windows** otevřete [http://localhost:8080/launchpad](http://localhost:8080/launchpad), vytvořte první administrátorský účet a přihlaste se. Poté postupujte podle kroku [6. Úlohy po instalaci](/cs/on-premises/installation/using-docker-compose/linux/6.-post-installation-tasks) návodu pro Linux a v jeho ukázkových URL použijte port `8080`.

### Ověření kompilace {#verify-compilation}

Funkční přihlašovací stránka nedokazuje, že samostatné kompilační kontejnery mají přístup k datovému adresáři WSL. Vytvořte prázdný projekt a zkompilujte tento `main.tex` pomocí **pdfLaTeX**:

```latex
\documentclass{article}
\begin{document}
Ayakaleaf Pro on Windows WSL 2.
\end{document}
```

Náhled PDF by měl zobrazit text. U image basic v případě potřeby vyberte v nastavení projektu **TeX Live 2026 Basic**.

Vyberte **XeLaTeX** a otestujte:

```latex
\documentclass{article}
\usepackage{fontspec}
\begin{document}
Ayakaleaf WSL XeLaTeX sandbox.
\end{document}
```

Oba příklady fungují s image basic. Pro čínské dokumenty použijte image obsahující `ctex` a potřebná písma, například full, a teprve pak otestujte následující příklad pomocí **XeLaTeX**. Image basic je neobsahuje:

```latex
\documentclass{ctexart}
\begin{document}
你好，Ayakaleaf Pro。
\end{document}
```

Chcete-li ověřit použití sandboxu, spusťte během kompilace v **Ubuntu**:

```bash
docker ps -a --filter ancestor=ghcr.io/ayaka-notes/texlive-basic:2026.1
bin/logs -f clsi
```

Ve filtru použijte název zvoleného image. Krátké kompilace mohou skončit dříve, než se `docker ps` spustí; `-a` zobrazuje i zastavené kontejnery, dokud nejsou uklizeny. Kompilační kontejner by měl používat tento image a bind mount `/compile` z datového adresáře Toolkitu ve WSL. Samotné logy aplikace nenahrazují kontrolu PDF.

### Ověření trvalosti dat {#verify-persistence}

V **Ubuntu** v adresáři Toolkitu:

```bash
bin/stop
bin/start
```

Počkejte na aplikaci, znovu otevřete projekt z Windows a znovu jej zkompilujte. Váš účet, zdrojový kód i soubory projektu by tam měly stále být. Výchozí živá data jsou v `~/ayakaleaf-toolkit/data/` uvnitř Ubuntu. Uchovejte `config/` i `data/`; odinstalace nebo zrušení registrace distribuce Ubuntu je může smazat.

### Zajištění dostupnosti instance {#keep-the-instance-available}

Udržení instance v provozu má tři části: Windows zůstávají vzhůru, Docker Desktop běží a kontejnery se restartují spolu s enginem.

V Docker Desktop v **Settings → General** zapněte **Start Docker Desktop when you sign in to your computer**, viz [nastavení Docker Desktop](https://docs.docker.com/desktop/settings-and-maintenance/settings/). Docker se tak spustí po přihlášení, nikoli před ním. Po restartu Windows se přihlaste, počkejte, až se Docker Desktop dokončí spouštění, otevřete Ubuntu a zkontrolujte `docker ps` a web.

**Resource Saver** v Docker Desktop je nezávislý na spánku Windows. Obvykle se aktivuje jen tehdy, když neběží žádné kontejnery; běžící aplikace, MongoDB a Redis tomuto stavu nečinnosti brání. Na WSL 2 pozastaví engine Dockeru, místo aby vypnul sdílený virtuální počítač WSL. Během obsluhy uživatelů Docker Desktop ručně nepozastavujte (**Pause**). Resource Saver nemusíte vypínat jen kvůli tomu, aby tento stack běžel; viz [dokumentace Dockeru k Resource Saver](https://docs.docker.com/desktop/use-desktop/resource-saver/).

Služby Toolkitu používají `restart: always`. Skutečné nastavení ověřte v **Ubuntu**:

```bash
docker inspect sharelatex mongo redis --format '{{.Name}} restart={{.HostConfig.RestartPolicy.Name}}'
```

Každá služba by měla hlásit `always`. Jakmile Docker běží, může tyto existující kontejnery restartovat bez nového `bin/up`. Ručně zastavený kontejner zůstává zastavený, dokud jej nespustíte nebo nerestartujete engine; s `always` jej restart enginu může znovu spustit. Viz [chování zásad restartu v Dockeru](https://docs.docker.com/engine/containers/start-containers-automatically/).

| Akce | Dopad na Ayakaleaf |
| --- | --- |
| Zavření terminálu Ubuntu po `bin/up -d` | Kontejnery běží odpojeně; terminál nad nimi nedohlíží. Udržujte Docker Desktop a prostředí WSL dostupné |
| Zavření okna Docker Dashboard | Okno lze zavřít, zatímco Docker Desktop dál běží v oznamovací oblasti |
| Volba **Quit Docker Desktop** | Zastaví engine a web bude nedostupný; pro obnovení Docker Desktop znovu otevřete |
| Spuštění `wsl --shutdown` | Zastaví všechny distribuce WSL a přeruší backend WSL Dockeru; restartujte Docker Desktop a znovu otevřete Ubuntu |
| Spánek, hibernace nebo vypnutí Windows | Služba je nedostupná; pouhé zapnutí nebo vypnutí obrazovky na tom nic nemění |
| Spuštění `bin/stop` | Zastaví instanci a zachová její data; pro pokračování použijte `bin/start` |

Pro dlouhodobý provoz při napájení ze sítě otevřete ve Windows 11 **Settings → System → Power & battery → Screen, sleep & hibernate timeouts** (některé verze zobrazují **Power** nebo **Screen and sleep**). Nastavte časový limit spánku při připojení k napájení na **Never** a vypněte automatickou hibernaci, pokud je nastavena. Displej se stále může vypnout. Akce při zavření víka notebooku je samostatné nastavení; zavření víka jej může uspat, i když je časový limit spánku při nečinnosti nastaven na Never. Viz [nastavení napájení ve Windows](https://support.microsoft.com/en-us/windows/experience/power-battery/power-settings-in-windows-11).

Nespouštějte `wsl --shutdown` jako běžný úklid, zatímco se web používá. Pokud to vyžaduje změna nastavení WSL, nejprve instanci zastavte a naplánujte přerušení. S tímto nastavením mohou Windows instanci provozovat nepřetržitě. Pro sdílenou službu, která musí přežít odhlášení a restarty bez obsluhy, doporučujeme [návod pro Linux](/cs/on-premises/installation/using-docker-compose/linux).

### Ověření obnovy po restartu Docker Desktop {#check-recovery-after-restarting-docker-desktop}

Po uložení práce a dokončení probíhajících kompilací zvolte v nabídce řešení problémů Docker Desktop **Restart Docker Desktop**. Počkejte na engine a poté v **Ubuntu** zkontrolujte:

```bash
docker ps
curl -I http://localhost:8080/launchpad
```

Otevřete existující projekt ve Windows a znovu jej zkompilujte. Ověřte, že účet i zdrojový kód stále existují.

Pokud jste instanci záměrně zastavili pomocí `bin/stop`, použijte `bin/start`. Pokud Docker běží, ale některá služba selhává, místo opětovného vytváření konfigurace si přečtěte její logy. Windows Update, aktualizace Dockeru a výpadek napájení mohou stále přerušit nepřetržitou instalaci; udržujte zálohy a po plánované údržbě obnovu zkontrolujte.

### Každodenní používání {#daily-use}

Ve Windows spusťte Docker Desktop. Otevřete **Ubuntu**:

```bash
cd "$HOME/ayakaleaf-toolkit"
```

| Úloha | Příkaz |
| --- | --- |
| Spustit existující kontejnery | `bin/start` |
| Zastavit kontejnery a zachovat data | `bin/stop` |
| Použít změny konfigurace | `bin/up -d` |
| Zkontrolovat stav | `bin/docker-compose ps` |
| Číst logy spouštění | `bin/docker-compose logs --tail=100 sharelatex` |
| Číst logy MongoDB | `bin/docker-compose logs --tail=100 mongo` |
| Číst logy kompilátoru | `bin/logs -f clsi` |

`bin/start` nepoužije úpravy konfigurace: po změně `config/` použijte `bin/up -d`. Před upgradem, přesunem nebo odstraněním distribuce WSL postupujte podle návodu [Data a zálohy](/cs/on-premises/maintenance/data-and-backups). Kopírování živých souborů MongoDB, zatímco do nich databáze zapisuje, není konzistentní záloha.

Pro lokální použití ponechte `127.0.0.1`. Obsluha dalších počítačů vyžaduje také záměrně nastavenou adresu naslouchání, URL webu, konfiguraci brány firewall a sítě ve Windows a HTTPS; samotná změna `OVERLEAF_SITE_URL` žádný port nezveřejní.

Pokud něco nefunguje, viz [Řešení problémů](/cs/on-premises/installation/using-docker-compose/windows/troubleshooting).
