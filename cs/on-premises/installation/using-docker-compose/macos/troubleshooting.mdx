### Inicializace selže s chybou invalid command code {#initialization-fails-with-invalid-command-code}

`bin/init` hlásí `sed: ... invalid command code`, když najde BSD sed z macOS. Přidejte GNU sed do `PATH` jako v kroku [1. Stažení Toolkitu](/cs/on-premises/installation/using-docker-compose/macos/1.-download-the-toolkit) a zkontrolujte `sed --version`.

Neúspěšná inicializace může zanechat všechny tři soubory v `config/` s prázdným `OVERLEAF_INVITE_TOKEN_SECRET`. Opětovné spuštění `bin/init` pak hlásí `Config files already exist`. U nové instalace, která se nikdy nespustila, přesuňte tyto tři soubory do záložního adresáře a spusťte `bin/init` znovu. U existující instance zachovejte její konfiguraci a tajné klíče a nemažte její soubory jen proto, aby se `bin/init` znovu spustil.

### MongoDB se neustále restartuje {#mongodb-keeps-restarting}

Přečtěte si logy MongoDB a verzi jádra virtuálního počítače Dockeru:

```bash
bin/docker-compose logs --tail=100 mongo
docker info --format '{{.KernelVersion}}'
```

Pokud log zmiňuje nekompatibilitu s linuxovým jádrem, postupujte podle části [Zkontrolujte linuxové jádro virtuálního počítače Dockeru](/cs/on-premises/installation/using-docker-compose/macos/5.-personalizing-your-instance#check-the-docker-vms-linux-kernel) a znovu spusťte `bin/up -d`. Samotný návratový kód `137` nedokazuje, že MongoDB došla paměť: zkontrolujte stav kontejneru a logy. Starší problém s MongoDB na Docker Desktop popisuje také [Řešení problémů](/cs/on-premises/support/troubleshooting).

### Nelze se připojit k démonu Dockeru {#cannot-connect-to-the-docker-daemon}

Spusťte Docker Desktop a zkontrolujte vybraný kontext Dockeru, viz [0. Nastavení Docker Desktop](/cs/on-premises/installation/using-docker-compose/macos/0.-setup-docker-desktop). Pokud `docker info` funguje, ale kompilace se k Dockeru nedostanou, zkontrolujte nastavení socketu v `config/overleaf.rc` a přečtěte si logy `clsi`. Funkční Docker CLI na Macu nedokazuje, že je připojení socketu v aplikaci správné.

### Stránka se otevře, ale kompilace selhávají {#the-page-opens-but-compiles-fail}

Zkontrolujte, že image TeX Live existuje lokálně a odpovídá architektuře enginu Dockeru:

```bash
docker image inspect ghcr.io/ayaka-notes/texlive-full:2026.1 \
  --format '{{.Os}}/{{.Architecture}}'
bin/logs -f clsi
```

Na Apple silicon by image měl být `linux/arm64`. Zkontrolujte, že `SERVER_PRO` i `SIBLING_CONTAINERS_ENABLED` mají hodnotu `true`, a poté změny použijte pomocí `bin/up -d`. Pokud logy hlásí chybějící kompilační adresář, zkontrolujte sdílení souborů v Docker Desktop a umístění `OVERLEAF_DATA_PATH`. Nevypínejte Sandboxed Compiles jen proto, abyste skryli selhání připojení.

### Not a directory nebo chybějící bind mount {#not-a-directory-or-a-bind-mount-is-missing}

Soubor na hostiteli, který override připojuje, mohl být smazán, nebo Docker mohl vytvořit adresář tam, kde má být soubor. Zkontrolujte zdrojovou cestu na hostiteli a to, zda připojení očekává soubor, nebo adresář. Před opětovným vytvořením kontejneru konfigurační soubor obnovte. Instalace pod `/tmp` na to může narazit poté, co macOS odstraní dočasné soubory.

### Konflikty portů nebo názvů kontejnerů {#port-or-container-name-conflicts}

Pokud je port `8080` obsazený, zvolte v `config/overleaf.rc` jiný port, odpovídajícím způsobem nastavte `OVERLEAF_SITE_URL` a znovu spusťte `bin/up -d`.

Toolkit dává svým kontejnerům pevné názvy jako `sharelatex`, `mongo` a `redis`. Samotná změna `PROJECT_NAME` neučiní dvě instalace Toolkitu nezávislými. Než spustíte druhou instanci, zkontrolujte `docker ps -a` a v Compose override použijte jiné názvy kontejnerů, jiný port a samostatné datové adresáře. Neodstraňujte kontejnery ani data existujícího nasazení kvůli vyřešení konfliktu názvů.

### Instance je po chvíli nedostupná {#the-instance-is-unreachable-after-a-while}

Mac pravděpodobně usnul nebo byl Docker Desktop ukončen. Viz [Zajištění dostupnosti instance](/cs/on-premises/installation/using-docker-compose/macos/6.-post-installation-tasks#keep-the-instance-available).

### `bin/doctor` hlásí, že nejde o Linux, nebo žádá přihlášení do Quay {#bin/doctor-says-this-is-not-linux-or-asks-for-a-quay-login}

Obě varování jsou na macOS s veřejným image očekávaná, viz [2. Seznamte se s Toolkitem](/cs/on-premises/installation/using-docker-compose/macos/2.-familiarize-yourself-with-the-toolkit). Místo toho zkontrolujte stahování image, stav služeb a výsledky kompilace a neignorujte ostatní chyby v hlášení.
