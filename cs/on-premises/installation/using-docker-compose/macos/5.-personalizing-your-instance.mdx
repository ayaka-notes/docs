---
title: 5. Přizpůsobení instance
description: Nastavte port, URL webu a image TeX Live pro lokální instanci na Macu, zkontrolujte jádro virtuálního počítače Dockeru a spusťte Ayakaleaf Pro.
icon: square-sliders
---

<Steps>
<Step title="Nastavení kontejnerů">
Upravte tyto existující položky v `config/overleaf.rc`:

```bash title="config/overleaf.rc"
PROJECT_NAME=ayakaleaf-macos
SERVER_PRO=true
OVERLEAF_LISTEN_IP=127.0.0.1
OVERLEAF_PORT=8080
SIBLING_CONTAINERS_ENABLED=true
DOCKER_SOCKET_PATH=/var/run/docker.sock
```

Ponechte výchozí cesty k datům a přibalené služby MongoDB a Redis. S `OVERLEAF_LISTEN_IP=127.0.0.1` mohou instanci otevřít pouze prohlížeče na tomto Macu.
</Step>

<Step title="Nastavení aplikace">
V `config/variables.env` nastavte tyto hodnoty a nahraďte jimi případné aktivní položky se stejnými názvy:

```dotenv title="config/variables.env"
OVERLEAF_SITE_URL=http://localhost:8080
TEX_LIVE_DOCKER_IMAGE=ghcr.io/ayaka-notes/texlive-full:2026.1
ALL_TEX_LIVE_DOCKER_IMAGES=ghcr.io/ayaka-notes/texlive-full:2026.1
ALL_TEX_LIVE_DOCKER_IMAGE_NAMES="TeX Live 2026"
```

Vygenerujte tajný klíč relace:

```bash
openssl rand -hex 32
```

Výsledek přidejte jako `OVERLEAF_SESSION_SECRET` do `config/variables.env`. Bez něj každý `bin/up`, který znovu vytvoří kontejner, odhlásí všechny uživatele, viz [Proměnné prostředí](/cs/on-premises/configuration/overleaf-toolkit/environment-variables).

Pro lokální instanci bez e-mailu ponechte nastavení SMTP a `OVERLEAF_EMAIL_FROM_ADDRESS` nenastavené. Git Bridge, externí ověřování a další integrace lze přidat později pomocí jejich vlastních [konfiguračních stránek](/cs/on-premises/configuration/overleaf-toolkit).
</Step>

<Step title="Zkontrolujte linuxové jádro virtuálního počítače Dockeru" id="check-the-docker-vms-linux-kernel">
MongoDB běží na linuxovém jádře virtuálního počítače Docker Desktop, nikoli na macOS. Před prvním spuštěním zkontrolujte jeho verzi:

```bash
docker info --format '{{.KernelVersion}}'
```

MongoDB dokumentuje nekompatibilitu s linuxovými jádry **6.19 až 7.0.13**, která se týká i MongoDB v Dockeru. Řešením je jádro **7.0.14 nebo novější**, které přichází s aktualizací Docker Desktop, viz [produkční poznámky MongoDB](https://www.mongodb.com/docs/manual/administration/production-notes/).

Pokud virtuální počítač Dockeru používá dotčené jádro, přidejte do `config/docker-compose.override.yml` následující obsah a slučte jej s případnými `services`, které tam již máte:

```yaml title="config/docker-compose.override.yml"
services:
  mongo:
    environment:
      GLIBC_TUNABLES: glibc.pthread.rseq=1
```

<Warning>

Jakmile bude k dispozici opravené jádro, aktualizujte na něj. Pokud je vaše jádro mimo dotčený rozsah, toto obejití není potřeba.

</Warning>
</Step>

<Step title="Spusťte instanci">
V adresáři Toolkitu spusťte:

```bash
bin/up -d
```

Toolkit inicializuje replica set MongoDB, stáhne image TeX Live a spustí aplikaci. První stahování chvíli trvá. Průběh můžete sledovat takto:

```bash
bin/docker-compose ps
bin/docker-compose logs --tail=100 -f sharelatex
```

Stisknutím `Ctrl+C` sledování logů ukončíte. Kontejnery poběží dál.

Zkontrolujte publikovaný port a stránku prvního spuštění:

```bash
bin/docker-compose port sharelatex 80
curl -I http://localhost:8080/launchpad
```

Port by měl být `127.0.0.1:8080`.
</Step>
</Steps>

<Info>

Chcete-li instanci později otevřít z jiných počítačů, změňte adresu naslouchání a URL webu a nastavte HTTPS, jak je popsáno v kroku [5. Přizpůsobení instance](/cs/on-premises/installation/using-docker-compose/linux/5.-personalizing-your-instance) návodu pro Linux. Mac pak musí zůstat vzhůru, viz [Zajištění dostupnosti instance](/cs/on-premises/installation/using-docker-compose/macos/6.-post-installation-tasks#keep-the-instance-available).

</Info>
