---

`bin/podman-setup` kontroluje vše, co Ayakaleaf Pro na Podmanu potřebuje. Bez voleb pouze hlásí výsledky; s `--apply` také opraví, co najde.

<Steps>
<Step title="Kontrola hostitele">
```bash title="Check only"
bin/podman-setup
```

Na čistém hostiteli většina kontrol selže, například:

```text
====== Packages ======
[✗] podman not installed
[✗] podman-docker not installed
...
====== Summary ======
[✓] 7 passed  [!] 13 warnings  [✗] 4 failures
```
</Step>

<Step title="Použití oprav">
```bash title="Check and fix"
bin/podman-setup --apply
```

Spusťte jej v terminálu: pro celosystémové kroky se zeptá na vaše heslo pro `sudo`. Také stáhne obraz Ayakaleaf Pro, aby z něj extrahoval profil seccomp, což poprvé trvá několik minut. Na konci znovu zkontroluje hostitele:

```text
====== Summary ======
[✓] 23 passed  [!] 2 warnings  [✗] 0 failures
[!] Warnings remaining:
[!] not logged in to quay.io
[!] container → socket skipped (sharelatex not running)
```

Obě varování jsou v tuto chvíli očekávaná:

* `not logged in to quay.io`: kontrola pochází z oficiálního Toolkitu, kde je obraz Server Pro v soukromém registru. Obrazy Ayakaleaf Pro jsou veřejné na `ghcr.io` a nevyžadují přihlášení, takže toto varování ignorujte. Zůstane i po instalaci.
* `container → socket skipped (sharelatex not running)`: tento test potřebuje běžící instanci. Skript znovu spustíte v kroku [3. Spuštění Ayakaleaf Pro](/cs/on-premises/installation/using-podman/3.-start-ayakaleaf-pro).

Skript skončí s kódem `0`, když projdou všechny kontroly, `1`, když existují varování, a `2`, když existují chyby. Kvůli varování o quay.io očekávejte `1`.
</Step>
</Steps>

### Co skript mění {#what-the-script-changes}

S `--apply` může skript změnit následující.

V celém systému, pomocí `sudo`:

* Nainstaluje `podman`, `podman-docker`, `git`, `curl`, `checkpolicy` a `policycoreutils` pomocí `dnf`.
* Povolí lingering pro vašeho uživatele pomocí `loginctl`, aby vaše kontejnery běžely i po odhlášení.
* Vytvoří `/etc/containers/nodocker`, což potlačí zprávu "Emulate Docker CLI using podman".
* Načte modul politiky SELinuxu `podman_socket_clsi`, pokud `SELINUX_MODE=managed`.

Pro vašeho uživatele:

* Povolí uživatelskou službu `podman.socket`, API kompatibilní s Dockerem, které Ayakaleaf Pro používá ke spouštění kompilací.
* Nainstaluje Docker Compose v2 z GitHubu do `~/.local/bin/docker-compose` a vytvoří na něj odkaz v `~/.docker/cli-plugins/`.
* Nastaví v `~/.config/containers/containers.conf`, aby Podman používal tento Compose.
* Přidá aliasy `mongo` a `redis` do `~/.config/containers/registries.conf.d/overleaf-toolkit.conf`, aby Podman věděl, odkud stahovat obrazy s těmito krátkými názvy.

V Toolkitu:

* Nastaví `DOCKER_SOCKET_PATH` a `DOCKER_HOST` v `config/overleaf.rc` na `/run/user/<uid>/podman/podman.sock`.
* Extrahuje profil seccomp pro kompilace z obrazu Ayakaleaf Pro do `config/seccomp/<version>/clsi-profile.json` a nastaví `SECCOMP_PROFILE` v `config/variables.env`. Na rozdíl od Dockeru potřebuje Podman tento profil jako soubor na hostiteli.
* Sestaví modul politiky SELinuxu v `config/selinux/`.
* Nastaví vlastníky datových adresářů v `data/` pomocí `podman unshare chown`, jakmile existují.

<Info>

Každá změna odpovídá jedné kontrole. Pokud něco změníte ručně, například v `config/overleaf.rc`, spusťte `bin/podman-setup` znovu a ověřte to.

</Info>
