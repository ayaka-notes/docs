RHEL a jeho přestavby (Rocky Linux, AlmaLinux) se dodávají s Podmanem místo Dockeru a některé organizace Docker na svých serverech nepovolují. Toolkit může Ayakaleaf Pro spouštět místo toho na **rootless Podman**: kontejnery běží pod běžným uživatelem, kompilace stále běží v izolovaných kontejnerech TeX Live a SELinux zůstává v režimu enforcing. Skript `bin/podman-setup` zkontroluje hostitele a opraví, co dokáže.

Na konci této sekce budete mít stejnou instanci jako v části [Použití Docker Compose](/cs/on-premises/installation/using-docker-compose): Ayakaleaf Pro s izolovanými kompilacemi, MongoDB a Redis, kterou spravujete obvyklými příkazy `bin/up`, `bin/doctor` a `bin/upgrade`.

<Info>

Podpora Podmanu je experimentální. Pochází z oficiálního Overleaf Toolkitu, který ji testuje pouze v RHEL 9 a novějším s rootless Podmanem, izolovanými kompilacemi a SELinuxem v režimu enforcing. Tyto stránky jsme otestovali na Rocky Linux 9.9 (Podman 5.8, SELinux enforcing) s Ayakaleaf Pro 6.3.4. Doporučeným kontejnerovým běhovým prostředím zůstává Docker.

</Info>

### Co budete potřebovat {#what-you-need}

* **RHEL, Rocky Linux, AlmaLinux nebo CentOS Stream 9 či novější** se SELinuxem v režimu enforcing. Na jakékoli jiné distribuci se `bin/podman-setup` zastaví. V Ubuntu nebo Debianu použijte [Použití Docker Compose](/cs/on-premises/installation/using-docker-compose/linux).
* **Uživatele bez oprávnění root s přístupem k `sudo`**, který bude vlastnit kontejnery. Všechny příkazy v této sekci spouštějte jako tento uživatel; `bin/podman-setup` odmítá běžet jako `root`.
* **Čistého hostitele**: bez Docker Engine a bez existující instalace Toolkitu. Přesun existující instance založené na Dockeru na Podman zde není popsán.

### Čím se liší od Dockeru {#how-it-differs-from-docker}

|                                     | Docker                                  | Rootless Podman                                                                          |
| ----------------------------------- | --------------------------------------- | ---------------------------------------------------------------------------------------- |
| Kdo spouští kontejnery              | Démon Dockeru jako `root`               | Váš uživatel                                                                             |
| Socket pro spouštění kompilací      | `/var/run/docker.sock`                  | `/run/user/<uid>/podman/podman.sock`                                                     |
| Porty                               | Libovolné, například `80` a `443`       | `1024` a vyšší, například `8080`                                                         |
| Firewall hostitele (`firewalld`)    | Publikované porty jej obcházejí         | Platí: otevřete port pomocí `firewall-cmd`                                               |
| Spuštění po restartu                | Démon Dockeru je spustí znovu           | Uživatelská služba `podman-restart`                                                      |
| SELinux                             | Toolkit jej nekonfiguruje               | Modul politiky `podman_socket_clsi` a `SELINUX_MODE=managed` v `config/overleaf.rc`       |
| Profil seccomp pro kompilace        | Vestavěný v obrazu                      | Toolkit jej extrahuje do `config/seccomp/<version>/` a nastaví jako `SECCOMP_PROFILE`    |

### Známá omezení {#known-limitations}

* <strong>Integrace s Gitem.</strong> V Ayakaleaf Pro 6.3.4 selže `git clone` na Podmanu s chybou `502`: NGINX uvnitř obrazu hledá kontejner `git-bridge` pomocí DNS serveru Dockeru (`127.0.0.11`), který Podman nemá. Oprava ([1b911d1092](https://github.com/ayaka-notes/ayakaleaf-pro/commit/1b911d1092c80f7b0ff77c5e3805b40503d49964)) přijde v příštím vydání; do té doby ponechte `GIT_BRIDGE_ENABLED=false`.
* <strong>IP adresy klientů.</strong> Rootless Podman přeposílá publikovaný port zevnitř sítě kontejneru, takže Ayakaleaf Pro vidí každého návštěvníka s interní adresou, například `10.89.0.15`. [Auditní protokoly](/cs/on-premises/user-guide/administrators/user-management#audit-logs) uživatele v administračním panelu zobrazují tuto adresu místo jeho IP adresy.
