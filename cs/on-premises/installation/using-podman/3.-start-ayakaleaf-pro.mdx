---
title: 3. Spuštění Ayakaleaf Pro
description: Spusťte Ayakaleaf Pro na Podmanu, ověřte jej pomocí podman-setup a bin/doctor a zajistěte jeho spuštění po restartu.
icon: circle-play
---

<Steps>
<Step title="Spuštění kontejnerů">
```bash title="Start Ayakaleaf Pro"
bin/up -d
```

První spuštění stáhne obrazy MongoDB, Redis a TeX Live a vytvoří datové adresáře v `data/`. Vypíše varování, že podpora Podmanu je experimentální.

<Info>

První spuštění může také vypsat `MongoNetworkError: connect ECONNREFUSED 127.0.0.1:27017`. Toolkit nastavuje sadu replik MongoDB, zatímco se MongoDB ještě spouští, a zkouší to znovu, dokud MongoDB neodpoví. Tento řádek můžete ignorovat.

</Info>

Po minutě nebo dvou zkontrolujte, že kontejnery běží:

```bash title="List the containers"
podman ps --format "{{.Names}} {{.Status}}"
```

```text
mongo Up 34 seconds (healthy)
redis Up 20 seconds
sharelatex Up 20 seconds
```
</Step>

<Step title="Opětovná kontrola nastavení">
Nyní, když datové adresáře existují a kontejner `sharelatex` běží, může `bin/podman-setup` dokončit své kontroly:

```bash title="Check the setup"
bin/podman-setup
```

Zkontroluje vlastníky nových datových adresářů a otestuje socket Podmanu zevnitř kontejneru `sharelatex`:

```text
====== Socket Connectivity ======
[✓] host → socket OK
[✓] container → socket OK

====== Data Directory Permissions ======
[✓] mongo data dir owned by 999
[✓] redis data dir owned by 999
[✓] overleaf data dir owned by 33
...
====== Summary ======
[✓] 27 passed  [!] 1 warnings  [✗] 0 failures
[!] Warnings:
[!] not logged in to quay.io
```

`container → socket OK` znamená, že Ayakaleaf Pro může spouštět kompilační kontejnery. Pokud některá kontrola selže, spusťte `bin/podman-setup --apply` a poté `bin/up -d`. Varování o quay.io se na Ayakaleaf Pro nevztahuje, viz [2. Spuštění podman-setup](/cs/on-premises/installation/using-podman/2.-run-podman-setup).
</Step>

<Step title="Spuštění doctoru">
```bash title="Run the doctor"
bin/doctor
```

Na Podmanu zpráva zobrazuje běhové prostředí a nastavení zabezpečení:

```text
- Container Daemon
    - status: up
    - runtime: podman
    - server version: 5.8.5
    - socket: /run/user/1000/podman/podman.sock
    - DOCKER_HOST: unix:///run/user/1000/podman/podman.sock
    - host → socket: OK
    - container → socket: OK
- Security
    - SELinux: Enforcing
    - SELINUX_MODE: managed
    - SELINUX_LABEL: sharelatex_t
    - SELinux module: loaded (podman_socket_clsi)
    - SELinux rules: present
    - Seccomp profile: present
```

Varování `Server Pro enabled, but not logged in to quay.io repository` na konci je stejná kontrola quay.io, viz [Získání pomoci](/cs/on-premises/support/getting-help#q-and-a).
</Step>

<Step title="Spuštění Ayakaleaf Pro po restartu">
S Dockerem spustí kontejnery po restartu znovu démon Dockeru. Rootless Podman žádného démona nemá: povolte uživatelskou službu, která spustí vaše kontejnery při startu serveru:

```bash title="Start the containers at boot"
systemctl --user enable podman-restart.service
```

Spustí každý kontejner vašeho uživatele, jehož politika restartu je `always`, kterou Toolkit nastavuje pro všechny své kontejnery. To vyžaduje lingering, který povolil `bin/podman-setup --apply`. Bez této služby spouštějte `bin/up -d` po každém restartu.
</Step>

<Step title="Otevření portu ve firewallu">
Ve výchozím stavu instance přijímá připojení pouze ze samotného serveru, na adrese `http://localhost:8080`. Chcete-li ji otevřít z jiných počítačů, nastavte `OVERLEAF_LISTEN_IP` v `config/overleaf.rc` a `OVERLEAF_SITE_URL` v `config/variables.env`, jak je popsáno v kroku [5. Přizpůsobení instance](/cs/on-premises/installation/using-docker-compose/linux/5.-personalizing-your-instance#listen-address-and-port), a znovu spusťte `bin/up -d`.

Na rozdíl od Dockeru rootless Podman neobchází firewall hostitele. Pokud běží `firewalld`, což je v RHEL výchozí stav, otevřete port:

```bash title="Open port 8080"
sudo firewall-cmd --permanent --add-port=8080/tcp
sudo firewall-cmd --reload
```

Na cloudovém serveru povolte port také v bezpečnostní skupině poskytovatele. Než instanci zpřístupníte z internetu, použijte HTTPS, viz [4. Úlohy po instalaci](/cs/on-premises/installation/using-podman/4.-post-installation-tasks#use-https).
</Step>
</Steps>
