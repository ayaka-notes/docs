<Accordion title="Migrace Zotero / Mendeley pro stávající instalace">

Při upgradu na opětovně vydaný image 6.3.0 migrujte metadata stávajících propojených souborů bibliografie ze Zotera/Mendeley pomocí níže uvedeného skriptu. Tato migrace doprovází opravu `12031b8dfd`.

Přejmenuje `zoteroGroupId` / `mendeleyGroupId` na `group_id`, přejmenuje `importedByUserId` na `importer_id` a odstraní `importedByName`.

Před spuštěním migrace zálohujte MongoDB a zastavte aplikaci. MongoDB nechte běžet. Otevřete jeho shell (nahraďte `mongo` názvem svého kontejneru):

```bash
docker exec -it mongo mongosh
```

V `mongosh` spusťte následující (nahraďte `sharelatex` názvem své databáze):

```javascript
use sharelatex

(async () => {
  let updated = 0
  await db.projects.find({}, { rootFolder: 1 }).forEach(async project => {
    const changes = {}
    function visit(folders, path) {
      for (const [i, folder] of (folders || []).entries()) {
        const folderPath = `${path}.${i}`
        for (const [j, file] of (folder.fileRefs || []).entries()) {
          const data = { ...file.linkedFileData }
          if (!["zotero", "mendeley"].includes(data.provider)) continue
          const groupKey = `${data.provider}GroupId`
          if (![groupKey, "importedByUserId", "importedByName"].some(key => key in data)) continue
          for (const [oldKey, newKey] of [[groupKey, "group_id"], ["importedByUserId", "importer_id"]]) {
            if (data[oldKey] != null && data[oldKey] !== "") {
              const value = String(data[oldKey])
              if (newKey in data && data[newKey] !== value) {
                throw new Error(`Conflicting ${newKey}: project ${project._id}, file ${file._id}`)
              }
              data[newKey] = value
            }
            delete data[oldKey]
          }
          delete data.importedByName
          changes[`${folderPath}.fileRefs.${j}.linkedFileData`] = data
        }
        visit(folder.folders, `${folderPath}.folders`)
      }
    }
    visit(project.rootFolder, "rootFolder")
    if (!Object.keys(changes).length) return
    const result = await db.projects.updateOne(
      { _id: project._id, rootFolder: { $eq: project.rootFolder } },
      { $set: changes }
    )
    if (!result.matchedCount) throw new Error(`Project changed during migration: ${project._id}`)
    updated += result.modifiedCount
  })
  print(`Updated ${updated} project(s).`)
})()
```

Skript zahrnuje i vnořené složky a mění pouze metadata Zotera/Mendeley. Lze ho bezpečně spustit opakovaně: dokončená migrace při dalším spuštění vypíše `Updated 0 project(s).`. Pokud se zastaví kvůli konfliktu, prověřte uvedený projekt/soubor; dřívější projekty už mohly být migrovány.

Spusťte aktualizovanou aplikaci, znovu načtěte editor a obnovte existující soubor bibliografie jako jeho původní importér. Historické snímky se nepřepisují. Pro návrat ke staré aplikaci obnovte zálohu MongoDB.

S hrdostí oznamujeme vydání Overleaf Pro 6.3.0, nejvýkonnějšího a funkčně nejbohatšího online editoru LaTeXu v komunitě. Protože se vždy soustředíme na zlepšování uživatelského zážitku, přináší toto vydání velké změny a skvělé funkce, které si jistě oblíbíte, včetně AI asistenta a integrace citačních služeb třetích stran.

### Změny

* AI Chat Assistant: Chatujte s AI modelem přes vlastního poskytovatele přímo v editoru.
* LaTeX Error Assistant: Získejte návrhy oprav chyb kompilace LaTeXu od AI.
* Integrace s Mendeley: Importujte citace z Mendeley podobně jako ze Zotera.
* Open in Overleaf API: Přidáno API pro otevírání obsahu v Overleafu.
* Template Gallery: Přidáno stránkování, vyhledávání a řazení na straně serveru, takže rozsáhlé galerie už nemusí načítat všechny šablony v prohlížeči.
* Překlady: Aktualizovány překladové záplaty pro 6.3.0, včetně nových textů rozhraní ve všech podporovaných jazycích.
* Upstream Overleaf 6.3.0: Zahrnuje úpravy souborů v záložkách, samostatná loga záhlaví pro světlý a tmavý motiv a aktualizace závislostí a základního image.
* Přidány `OVERLEAF_HEADER_IMAGE_URL_LIGHT` a `OVERLEAF_HEADER_IMAGE_URL_DARK` pro podporu samostatných obrázků loga záhlaví pro světlý a tmavý motiv.
* Soubory lze nyní v editoru otevírat v různých záložkách.
* Přidána podpora konfigurovatelných HTTP(S) proxy, včetně lokálně hostovaných, pomocí `OVERLEAF_LINKED_URL_OUTBOUND_PROXY`, kterou používá také Open in Overleaf API.

#### Feature 04: Template Pagination

Galerie nyní stránkuje, řadí a vyhledává v MongoDB. Funguje bez jakékoli přípravy; při tisících šablon však můžete přidat tyto indexy, aby zůstala rychlá (lze bezpečně spustit opakovaně, `mongo`/`sharelatex` = názvy vašeho kontejneru a databáze):

```bash
docker exec mongo mongosh sharelatex --quiet --eval '
db.templates.createIndex({category:1,lastUpdated:-1},{name:"category_1_lastUpdated_-1",background:true});
db.templates.createIndex({lastUpdated:-1},{name:"lastUpdated_-1",background:true});
db.templates.createIndex({category:1,name:1},{name:"category_1_name_1_ci",collation:{locale:"en",strength:2},background:true});
db.templates.createIndex({name:1},{name:"name_1_ci",collation:{locale:"en",strength:2},background:true});
'
```

U dvou indexů `*_ci` ponechte `collation` přesně tak, jak je uvedena — galerie se dotazuje se stejnou collation a MongoDB používá jen odpovídající index.

## Ayakaleaf Pro 6.2.2

<strong>Datum vydání:</strong> 2026.07.23

Viz: [https://github.com/ayaka-notes/ayakaleaf-pro/releases/tag/pro-v6.2.2](https://github.com/ayaka-notes/ayakaleaf-pro/releases/tag/pro-v6.2.2)

### Změny

Backport oficiálních opravných záplat dodaných v upstreamovém Overleafu `6.2.2` (nad `6.2.1`):

* Tajný klíč tokenů pozvánek do projektu již neuniká do logů. Šifrovač tokenů pozvánek při každém šifrování/dešifrování logoval vlastní konfiguraci, která obsahovala šifrovací hesla odvozená z `OVERLEAF_INVITE_TOKEN_SECRET`.
* Odchozí e-maily migrovány z klienta AWS SES v1, jehož životnost skončila, na SESv2. Instance nakonfigurované s e-mailovým ovladačem `ses` nemusely e-maily odesílat vůbec; odesílání nyní probíhá přes `SESv2Client`.
* Skupinové položky v rozbalovací nabídce sdílení projektu jsou nyní podmíněny novým příznakem funkce `group-link-sharing`, takže sdílení odkazů pro skupiny se již nenabízí na instancích, kde nedává smysl.
* Opraven dialog sdílení projektu pro spolupracovníky. Jeho otevření uživatelem, který není vlastníkem, nebo při vypnutém toku `sharing-updates` vyvolalo požadavek, který vždy selhal a zobrazil chybu „something went wrong“.
* Do document-updater přidán `scripts/flush_docs_with_pending_updates.js`, údržbový skript, který obnovuje dokumenty se zaseknutou frontou `PendingUpdates` v Redisu poté, co byl jejich projekt vyprázdněn nebo trvale smazán. Podporuje `--dry-run` a bezpečnostní kontrolu `--estimated-docs`.
* Aktualizace závislostí: `multer` 2.2.0, `form-data` 2.5.6, `protobufjs` 7.6.3, `@grpc/grpc-js` 1.14.4.

Toto vydání obsahuje také následující opravy a vylepšení z Ayakaleaf Pro:

* Přidány úplné překlady pro 16 dalších jazyků (cs, da, de, es, fi, fr, it, ja, ko, nl, no, pl, pt, ru, sv, tr), čímž jsou opraveny nepřeložené řetězce, například na stránce obnovení hesla. Opravuje [#38](https://github.com/ayaka-notes/ayakaleaf-pro/issues/38).
* Opraven počet položek na tlačítku „show N more projects“ v administrátorském panelu, které zobrazovalo nesprávné číslo, protože zástupný symbol pro množné číslo nebyl správně předán.
* Opraveny chyby validace exportu na GitHub, které se nyní vykreslují pomocí statických klíčů i18n místo surových zpráv, a odstraněny chybové klíče, které dialog GitHub Sync již nepoužívá.

## Ayakaleaf Pro 6.2.1

<strong>Datum vydání:</strong> 2026.07.18

Viz: [https://github.com/ayaka-notes/ayakaleaf-pro/releases/tag/pro-v6.2.1](https://github.com/ayaka-notes/ayakaleaf-pro/releases/tag/pro-v6.2.1)

### Změny

Backport oficiálních opravných záplat dodaných v upstreamovém Overleafu `6.2.1` (nad `6.2.0`):

* Zpráva `applyOtUpdate` v reálném čase je nyní zabezpečena přísným validačním schématem místo přijímání libovolného objektu, takže chybně utvořené editační operace jsou odmítnuty.
* Toto schéma bylo zmírněno tak, aby `meta.tc` bylo volitelné, a platné aktualizace tak již nejsou přísnější validací odmítány.
* Opraven editor (klient ShareJS), aby operace redukované na prázdnou operaci — vyrušené vzdálenou/souběžnou operací nebo zcela vrácené pomocí undo — byly zahozeny místo odeslání na server a dokument byl správně hlášen jako uložený. Zabraňuje falešným problémům se synchronizací / „neuloženými změnami“ při undo a souběžných úpravách.

## Ayakaleaf Pro 6.2.0

<strong>Datum vydání:</strong> 2026.07.10

Viz: [https://github.com/ayaka-notes/ayakaleaf-pro/releases/tag/pro-v6.2.0](https://github.com/ayaka-notes/ayakaleaf-pro/releases/tag/pro-v6.2.0)

S hrdostí oznamujeme vydání Overleaf Pro 6.2.0, nejvýkonnějšího a funkčně nejbohatšího online editoru LaTeXu v komunitě. Zvláštní poděkování patří yu-i-i a davrotovi za jejich cenné příspěvky. Vylepšili GitHub Sync a přinesli pokročilé vyhledávání citací a integraci se Zoterem.

### Poznámky

<Warning>

* Byla zavedena nová povinná proměnná prostředí `OVERLEAF_INVITE_TOKEN_SECRET`. Musíte ji vygenerovat pomocí `openssl rand -base64 32`. Pokud není nakonfigurována, vaše instance Overleafu se nespustí.
* Pokud povolíte GitHub Sync, musíte nakonfigurovat proměnnou prostředí `GITHUB_TOKEN_CIPHER_PASSWORD`. Tato proměnná je nutná k bezpečnému šifrování přístupových tokenů GitHubu. Bez ní se vaše instance Overleafu nespustí.

</Warning>

* Přidána nová proměnná prostředí `DEFAULT_LATEX_COMPILER` pro nastavení výchozího kompilátoru nových projektů (`pdflatex`, `latex`, `xelatex` nebo `lualatex`).
* Přepracovaný editor je nyní jedinou dostupnou možností.

### Změny

Toto vydání obsahuje následující vylepšení a nové funkce.

* `MAX_UPLOAD_SIZE` je nyní konfigurovatelná místo pevného omezení na **50 MB**.
* Opravena smyčka restartů kontejneru při vypnutých kompilacích v sandboxu.
* Mazání PAT pro OAuth2 je nyní omezeno na vlastníka.
* Opraven problém s importem z LDAP.

Funkce zahrnují:

* Přidáno spouštění Pythonu v prohlížeči.
* Přidána podpora Pandocu pro import a export Markdownu, DOCX a dalších formátů.
* Přidán GitHub Sync.
* Přidány kompletní čínské překlady.
* Přidána integrace se Zoterem.
* Přidána `DEFAULT_LATEX_COMPILER`.

## Ayakaleaf Pro 6.0.0

<strong>Datum vydání:</strong> 2026.02.17

Testovací vydání, viz: [https://github.com/ayaka-notes/ayakaleaf-pro/releases/tag/pro-v6.0.0](https://github.com/ayaka-notes/ayakaleaf-pro/releases/tag/pro-v6.0.0)

Jde o testovací vydání a zároveň naši první verzi Overleaf Pro. Tato verze neobsahuje žádné funkce ze Server Pro, je tedy označena pouze jako náš výchozí bod. Nové funkce, jako je administrátorský panel a git-bridge, přidáme později...

V tomto vydání jsme představili Docker image Overleafu pro ARM. Pokud máte Mac nebo server založený na ARM, můžete ho vyzkoušet, některé funkce však nemusí fungovat dobře (zatím netestováno).

### Docker image

Docker image najdete zde: [https://github.com/ayaka-notes/ayakaleaf-pro/pkgs/container/overleaf-pro](https://github.com/ayaka-notes/ayakaleaf-pro/pkgs/container/overleaf-pro)

Image pro více architektur najdete [zde](https://github.com/ayaka-notes/ayakaleaf-pro/pkgs/container/overleaf-pro/691283454?tag=6.0.0).

```bash
docker pull ghcr.io/ayaka-notes/overleaf-pro:6.0.0
```

### Migrace binárních souborů

Toto nové vydání snižuje využití úložiště binárními soubory na polovinu.

Ve verzi `5.5` je zahrnuta online migrace, která umožňuje minimální výpadek během upgradu. Před upgradem na Server Pro `v6` se ujistěte, že již používáte nejnovější verzi Server Pro `v5.5` ([Release Notes 5.x.x](https://docs.overleaf.com/on-premises/release-notes/release-notes-5.x.x)) a že jste migraci spustili.

[Viz úplné pokyny k migraci](https://docs.overleaf.com/on-premises/release-notes/release-notes-5.x.x/binary-files-migration).

### Upgrade MongoDB na v8

Toto vydání zvyšuje minimální verzi MongoDB na `8.0`.

Pokud aktuálně používáte MongoDB `v6` nebo starší, musíte aktualizovat postupně vždy o jednu hlavní verzi (`v6 → v7 → v8`).

<Warning>

Před upgradem se prosím ujistěte, že máte zálohu [databáze](https://docs.overleaf.com/on-premises/maintenance/data-and-backups). V případě návratu k předchozí verzi budete muset zálohu databáze obnovit.

</Warning>

Pokyny k upgradu MongoDB `v6 → v7 → v8` najdete v našem podrobném návodu [zde](https://docs.overleaf.com/on-premises/maintenance/updating-mongodb#example-upgrading-mongodb-from-6.0-to-7.0-toolkit-users).

### Upgrade Redisu na v7.4

Toto vydání také zvyšuje minimální verzi Redisu na `7.4`.

Aktualizujte `REDIS_IMAGE` v souboru `config/overleaf.rc` na `REDIS_IMAGE=7.4`.

### Nové funkce

* Sdílení odkazem lze nyní vypnout pomocí `OVERLEAF_DISABLE_LINK_SHARING=true`.
* Nově jsou k dispozici `OVERLEAF_MAINTENANCE_MESSAGE` a `OVERLEAF_MAINTENANCE_MESSAGE_HTML` pro přizpůsobení nadpisu a obsahu stránky údržby.
* Pomocí `OVERLEAF_USER_HARD_DELETION_DELAY` a `OVERLEAF_PROJECT_HARD_DELETION_DELAY` lze nastavit (v milisekundách) zpoždění vypršení smazaných uživatelů/projektů (výchozí hodnota je 90 dní).

### Opravy chyb

* Opraveno vykreslování zápatí s odkazy.
* Vylepšeny chybové zprávy při chybách přihlášení přes SAML.
* Opraveno nepřidávání záznamu do auditního logu, když je při přihlášení přes SSO aktualizován administrátorský stav uživatele.
* Opraveny chyby panelu History při povoleném TLS v Redisu.
* Kompilace lze nyní zastavit i při použití kompilací mimo sandbox.

### Další změny

* Všechny odkazy na stavovou stránku (nastavenou pomocí `OVERLEAF_STATUS_PAGE_URL`) nyní používají `HTTPS` a otevírají se v nové záložce prohlížeče.
