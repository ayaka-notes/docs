## Ayakaleaf Pro 6.3.2

<strong>Datum vydání:</strong> 2026.10.23

Viz: [https://github.com/ayaka-notes/ayakaleaf-pro/releases/tag/pro-v6.3.2](https://github.com/ayaka-notes/ayakaleaf-pro/releases/tag/pro-v6.3.2)

S velkou hrdostí oznamujeme vydání Overleaf Pro 6.3.2. Upstream Overleaf 6.3.2 je bezpečnostní vydání, které aktualizuje Node.js, a my jej dodáváme společně se synchronizací s Gitea a opravami chyb nalezených od verze 6.3.1.

<Info>

Synchronizace s Gitea je ve verzi 6.3.2 dodávána jako **předběžná verze** (early preview) pro postupné testování a oficiálně bude vydána ve verzi v6.4.0. Její konfigurace a chování se do té doby ještě mohou změnit. Ve výchozím nastavení je vypnutá. Jakékoli problémy prosím hlaste na [GitHubu](https://github.com/ayaka-notes/ayakaleaf-pro/issues).

</Info>

### Změny

* Obousměrná synchronizace s Gitea (předběžná verze) pro gitea.com a samostatně spravovanou Gitea 1.23+.
* Node.js 24.22.1, bezpečnostní aktualizace z upstream Overleaf 6.3.2.
* Opravy chyb nalezených naším systémem E2E testování a interním vyšetřováním problémů Horizon (Internal Horizon Issue Investigation).

#### Funkce 01: Synchronizace s Gitea (předběžná verze)

Obousměrná synchronizace s Gitea, která funguje stejně jako synchronizace s GitHubem a synchronizace s GitLabem: propojte svůj účet, importujte repozitář z nabídky nového projektu, exportujte projekt, provádějte push a pull a slučujte prostřednictvím pull requestů. Overleaf nikdy neobchází ochranu větví repozitáře. Viz [Synchronizace s Gitea](/cs/on-premises/configuration/overleaf-toolkit/gitea-synchronisation).

### Opravy chyb

* Synchronizace s GitHubem, GitLabem a Gitea: pokud soubor smazaný v repozitáři nelze smazat v Overleafu, synchronizace selže a lze ji zopakovat, místo aby ohlásila úspěch a ponechala soubor v projektu. Stejným způsobem selže i `git push`, který soubor maže ([#121](https://github.com/ayaka-notes/ayakaleaf-pro/issues/121)).
* Git bridge: dokument vytvořený v editoru s netextovou příponou (například `.csv`) zůstane upravitelným dokumentem, i když jej změní `git push`.
* Sledování změn: nepřihlášení editoři projektu sdíleného odkazem mohou mazat vlákna komentářů, ale již je nemohou vyřešit ani znovu otevřít. Recenzenti mohou mazat své vlastní odpovědi.
* Galerie šablon: publikování šablony vyžaduje přístup k projektu.
* Learn: stránky nápovědy uložené v mezipaměti zůstávají dostupné, i když wiki není dosažitelná.

### Upgrade

* Z verze 6.3.1 nebo 6.3.0: žádná migrace není potřeba. Stáhněte nový image a restartujte.
* Z verze 6.2.x nebo starší s používaným Zoterem nebo Mendeley: nejprve spusťte migraci Zotero / Mendeley ve verzi [6.3.0](#ayakaleaf-pro-6.3.0).
* Synchronizace s Gitea je ve výchozím nastavení vypnutá a potřebuje pouze nové proměnné prostředí.

Docker image najdete zde: [https://github.com/ayaka-notes/ayakaleaf-pro/pkgs/container/overleaf-pro](https://github.com/ayaka-notes/ayakaleaf-pro/pkgs/container/overleaf-pro)

## Ayakaleaf Pro 6.3.1

<strong>Datum vydání:</strong> 2026.10.18

Viz: [https://github.com/ayaka-notes/ayakaleaf-pro/releases/tag/pro-v6.3.1](https://github.com/ayaka-notes/ayakaleaf-pro/releases/tag/pro-v6.3.1)

S velkou hrdostí oznamujeme vydání Overleaf Pro 6.3.1. Zatímco běžné opravné vydání by se soustředilo na drobné opravy verze v6.3.0, toto vydání jde mnohem dál: kromě mnoha oprav chyb přináší pět nových funkcí.

<Info>

Synchronizace s Dropboxem a synchronizace s GitLabem jsou ve verzi 6.3.1 dodávány jako **předběžné verze** (early preview) pro postupné testování a oficiálně budou vydány ve verzi v6.4.0. Jejich konfigurace a chování se do té doby ještě mohou změnit. Obě jsou ve výchozím nastavení vypnuté. Jakékoli problémy prosím hlaste na [GitHubu](https://github.com/ayaka-notes/ayakaleaf-pro/issues).

</Info>

### Změny

* Obousměrná synchronizace s Dropboxem (předběžná verze).
* Obousměrná synchronizace s GitLabem (předběžná verze), včetně samostatně spravovaného GitLabu 15.10+.
* MCP server pro každý projekt pro AI klienty jako Claude Code, Codex, Cursor, VS Code a Gemini CLI.
* Podpora GitHub Enterprise pro synchronizaci s GitHubem.
* Rozpoznávání ručně kreslených symbolů v paletě symbolů, běžící celé v prohlížeči.

Úpravy v Overleafu se odesílají do Dropboxu a úpravy v Dropboxu se vracejí prostřednictvím podepsaného webhooku. Musí být povolen Git bridge. ### Opravy chyb

* Ověřování: lokální účty si mohou na instancích s SSO nastavit a změnit heslo a uživatelé OIDC již nemohou měnit svůj vlastní e-mail ([#112](https://github.com/ayaka-notes/ayakaleaf-pro/pull/112)). Metody přihlášení LDAP, SAML a OIDC zůstávají zachovány a odhlášení SAML/OIDC opět funguje. Viz [Účty a hesla](/cs/on-premises/configuration/overleaf-toolkit/authentication#accounts-and-passwords).
* LDAP, SAML a OIDC: atributy jména s více hodnotami (například `cn`) již nezpůsobují selhání přihlášení a e-maily z OIDC se převádějí na malá písmena stejně jako u LDAP a SAML, takže účet, jehož e-mail IdP posílá s jinou velikostí písmen, se propojí, místo aby přihlášení selhalo.
* Pozastavení uživatelé: pozastavení uživatele ukončí jeho relace a zavře jeho otevřené editory. Jeho tokeny Git a stahování přes MCP jsou odmítány.
* Synchronizace s GitHubem: projekt může exportovat pouze vlastník, úpravy provedené během pull zůstávají čekající, prázdné soubory se synchronizují, ruční sloučení se ověřují na GitHubu a nahrazený token je při opětovném propojení zneplatněn.
* Zotero / Mendeley: když přihlašovací údaje přestanou fungovat, zobrazí se zpráva vyzývající k opětovnému propojení a reference se po importu znovu indexují.
* Požadavky na externí API (Zotero, Mendeley, GitHub, GitLab, webové vyhledávání) mají časový limit připojení 3 s místo 1 s ([#106](https://github.com/ayaka-notes/ayakaleaf-pro/pull/106)).
* Sledování změn: data recenze zahrnují nenačtené dokumenty a neuložené změny (z [yu-i-i/overleaf-cep#262](https://github.com/yu-i-i/overleaf-cep/pull/262)).
* Error assistant: nabízí opravy pouze pro dokumenty v projektu ([#103](https://github.com/ayaka-notes/ayakaleaf-pro/pull/103)).
* Administrátorský panel: obnovení smazaného projektu, změna vlastníků a úpravy uživatelů fungují správně. Vyhledávání používá doslovný text a neúspěšně odeslaný e-mail již nenaruší vytvoření ani smazání účtu.
* Galerie šablon: neplatné řazení vrací 400 místo 500, ID šablon se ověřují a při publikování projektu bez hlavního souboru se o něj požádá.
* Git bridge: nginx přeposílá `/git/` na `GIT_BRIDGE_HOST` a `GIT_BRIDGE_PORT` a interní cesty jsou skryté.
* Sandboxed compiles: kontejnery nedávno kompilovaných projektů se uchovávají pro opětovné použití.

<Accordion title="Migrace Zotero / Mendeley pro stávající instalace">

Při upgradu na opětovně vydaný image 6.3.0 migrujte metadata stávajících propojených souborů bibliografie ze Zotera/Mendeley pomocí níže uvedeného skriptu. Tato migrace doprovází opravu `12031b8dfd`.

Přejmenuje `zoteroGroupId` / `mendeleyGroupId` na `group_id`, přejmenuje `importedByUserId` na `importer_id` a odstraní `importedByName`.

Před spuštěním migrace zálohujte MongoDB a zastavte aplikaci. MongoDB nechte běžet. Otevřete jeho shell (nahraďte `mongo` názvem svého kontejneru):

```bash
docker exec -it mongo mongosh
```

V `mongosh` spusťte následující (nahraďte `sharelatex` názvem své databáze):

```javascript
use sharelatex

(async () => {
  let updated = 0
  await db.projects.find({}, { rootFolder: 1 }).forEach(async project => {
    const changes = {}
    function visit(folders, path) {
      for (const [i, folder] of (folders || []).entries()) {
        const folderPath = `${path}.${i}`
        for (const [j, file] of (folder.fileRefs || []).entries()) {
          const data = { ...file.linkedFileData }
          if (!["zotero", "mendeley"].includes(data.provider)) continue
          const groupKey = `${data.provider}GroupId`
          if (![groupKey, "importedByUserId", "importedByName"].some(key => key in data)) continue
          for (const [oldKey, newKey] of [[groupKey, "group_id"], ["importedByUserId", "importer_id"]]) {
            if (data[oldKey] != null && data[oldKey] !== "") {
              const value = String(data[oldKey])
              if (newKey in data && data[newKey] !== value) {
                throw new Error(`Conflicting ${newKey}: project ${project._id}, file ${file._id}`)
              }
              data[newKey] = value
            }
            delete data[oldKey]
          }
          delete data.importedByName
          changes[`${folderPath}.fileRefs.${j}.linkedFileData`] = data
        }
        visit(folder.folders, `${folderPath}.folders`)
      }
    }
    visit(project.rootFolder, "rootFolder")
    if (!Object.keys(changes).length) return
    const result = await db.projects.updateOne(
      { _id: project._id, rootFolder: { $eq: project.rootFolder } },
      { $set: changes }
    )
    if (!result.matchedCount) throw new Error(`Project changed during migration: ${project._id}`)
    updated += result.modifiedCount
  })
  print(`Updated ${updated} project(s).`)
})()
```

Skript zahrnuje i vnořené složky a mění pouze metadata Zotera/Mendeley. Lze ho bezpečně spustit opakovaně: dokončená migrace při dalším spuštění vypíše `Updated 0 project(s).`. Pokud se zastaví kvůli konfliktu, prověřte uvedený projekt/soubor; dřívější projekty už mohly být migrovány.

Spusťte aktualizovanou aplikaci, znovu načtěte editor a obnovte existující soubor bibliografie jako jeho původní importér. Historické snímky se nepřepisují. Pro návrat ke staré aplikaci obnovte zálohu MongoDB.

#### Feature 04: Template Pagination

Galerie nyní stránkuje, řadí a vyhledává v MongoDB. Funguje bez jakékoli přípravy; při tisících šablon však můžete přidat tyto indexy, aby zůstala rychlá (lze bezpečně spustit opakovaně, `mongo`/`sharelatex` = názvy vašeho kontejneru a databáze):

```bash
docker exec mongo mongosh sharelatex --quiet --eval '
db.templates.createIndex({category:1,lastUpdated:-1},{name:"category_1_lastUpdated_-1",background:true});

db.templates.createIndex({category:1,name:1},{name:"category_1_name_1_ci",collation:{locale:"en",strength:2},background:true});

'
```

U dvou indexů `*_ci` ponechte `collation` přesně tak, jak je uvedena — galerie se dotazuje se stejnou collation a MongoDB používá jen odpovídající index.
