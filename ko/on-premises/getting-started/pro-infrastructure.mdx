#### 서비스

overleaf Pro 인프라는 `sharelatex`, `git-bridge`(선택 사항), `mongo`, `redis`의 네 가지 주요 서비스로 구성됩니다. 메인 Server Pro 애플리케이션을 실행하는 `sharelatex` 서비스는 데이터베이스와 캐싱/실시간 기능을 위해 `mongo` 및 `redis` 서비스에 의존하며, [Git 통합](/ko/on-premises/configuration/overleaf-toolkit/git-integration)(선택 사항)을 처리하기 위해 `git-bridge`에 의존합니다. 호스트 머신에 공개되는 유일한 포트는 `sharelatex` 컨테이너가 사용하는 80번 포트입니다.

Server Pro는 선택적으로 프로젝트 파일과 전체 프로젝트 기록을 위한 [S3 호환 스토리지](/ko/on-premises/configuration/overleaf-toolkit/s3)를 지원하며, 메인 [Overleaf 문서 사이트arrow-up-right](https://www.overleaf.com/learn)에 대한 프록시 접근도 지원합니다. 자세한 내용은 [LaTeX 사용자 도움말 추가](/ko/on-premises/configuration/overleaf-toolkit/adding-latex-user-help) 페이지 가이드를 참조하십시오.

<Info>

필요한 경우 환경 변수를 사용해 외부 서비스를 가리키도록 하여 MongoDB와 Redis를 외부화할 수 있습니다. 자세한 내용은 Docker Compose를 사용하는 경우 [Overleaf 구성](/ko/on-premises/configuration)을, Overleaf Toolkit을 사용하는 경우 [Toolkit 설정](/ko/on-premises/configuration/overleaf-toolkit/toolkit-settings)을 참조하십시오.

</Info>

#### 컴파일

[샌드박스 컴파일](/ko/on-premises/configuration/overleaf-toolkit/sandboxed-compiles)의 경우, `sharelatex` 컨테이너가 프로젝트 컴파일을 처리할 새 컨테이너의 생성을 오케스트레이션하며, 이는 호스트 머신의 Docker 소켓을 통해 이루어집니다. 에디터와 엔드투엔드 컴파일/캐싱 과정에 대한 자세한 내용은 [여기](/ko/on-premises/getting-started/microservices#editor-and-compile-process)에서 확인할 수 있습니다.

#### 네트워킹

컨테이너 간 통신은 전용 브리지 네트워크를 통한 Docker의 내부 DNS 확인으로 이루어지며, 방화벽은 활성화되어 있지 않습니다. 기본적으로 위 서비스들은 각각의 표준 포트를 사용하지만 환경 변수로 구성할 수 있습니다. `sharelatex` 컨테이너는 외부 웹 접근에 80번 포트(Nginx가 제공)를 사용하고, `mongo` 컨테이너는 27017번 포트를, `redis`는 6379번 포트를 사용합니다.

관리형 솔루션인 [Overleaf Toolkitarrow-up-right](https://github.com/overleaf/toolkit)를 사용하는 고객은 환경 변수를 통해 Nginx로 HTTPS 연결을 종료하는 [TLS 프록시를 선택적으로 활성화](/ko/on-premises/configuration/overleaf-toolkit/tls-proxy)할 수 있습니다. 또는 기존에 사용 중인 TLS 프록시를 사용할 수도 있습니다.

<Info>

요청 흐름을 설명하는 다이어그램은 [여기](/ko/on-premises/configuration/overleaf-toolkit/tls-proxy)에서 볼 수 있습니다.

</Info>

#### 요약

* Docker 네트워크 외부에서는 Nginx에 바인딩된 80번 포트만 접근할 수 있습니다. **참고:** `sharelatex` 컨테이너는 HTTP를 통해 서로 통신하는 많은 [서비스arrow-up-right](https://github.com/overleaf/overleaf/tree/main/services)를 실행합니다. 그러나 이러한 포트는 Docker 네트워크 외부에서 접근할 수 **없습니다**.
* Docker 네트워크 내부에서는 Overleaf 서비스, MongoDB, Redis, Git Bridge가 서로 자유롭게 통신할 수 있습니다.
* [샌드박스 컴파일](/ko/on-premises/configuration/overleaf-toolkit/sandboxed-compiles) 컨테이너 내부에서는 네트워크를 사용할 수 없습니다.
