<Accordion title="NFS 파일 시스템에서 Overleaf 실행">

Overleaf 컨테이너에 NFS 파일 시스템을 마운트하는 것은 기술적으로 가능하지만 권장하지 않으며, 다양한 유형의 성능 오류가 발생할 수 있습니다.

컴파일 시 흔히 볼 수 있는 오류는 다음과 같습니다.

```text
EBUSY: resource busy or locked, unlink '/var/lib/overleaf/data/compiles/62f3d57bef7cf9005c364e75-62f3d57bef7cf9005c364e7a/.nfs573663533034825247625441'
```

특히 컴파일 데이터에 사용되는 디렉터리처럼 임시 데이터에는 NFS 기반 파일 시스템을 사용하지 않을 것을 권장합니다. 다음 디렉터리에는 로컬 스크래치 디스크, 가급적 로컬 SSD를 사용하는 것을 권장합니다.

`docker-compose` 기반 구성에서는 NFS의 바인드 마운트를 재정의하기만 하면 애플리케이션의 경로를 변경하지 않아도 됩니다. 다음은 `/scratch`에 마운트된 스크래치 디스크를 사용하는 `docker-compose` 설정 발췌 예시입니다.

```yaml title="docker-compose excerpt"
services:
  sharelatex:
    environment:
      SANDBOXED_COMPILES_HOST_DIR: /scratch/compiles/
    volumes:
      - nfs:/var/lib/overleaf/data
      - /scratch/cache/:/var/lib/overleaf/data/cache
      - /scratch/compiles/:/var/lib/overleaf/data/compiles
      - /scratch/output/:/var/lib/overleaf/data/output
      - /scratch/tmp/:/var/lib/overleaf/tmp
```

업데이트 후 기존 파일을 NFS에서 새 위치로 옮길 필요는 없습니다. LaTeX 컴파일러가 전체 컴파일을 다시 실행하여 모든 파일을 재생성할 수 있습니다.

자세한 내용은 다음을 참고하세요: https://docs.overleaf.com/on-premises/support/troubleshooting#running-overleaf-with-an-nfs-filesystem

</Accordion>

<Accordion title="Windows 또는 macOS에서 Overleaf를 실행하면 `mongo` 서비스가 시작되지 않음">

Windows 또는 macOS에서 Overleaf를 실행하는 경우 `mongo` 서비스가 다음 오류와 함께 재시작에 실패할 수 있습니다.

```text title="Example error"
Failed to start up WiredTiger under any compatibility version.
Reason: 1: Operation not permitted
```

이 오류를 피하려면 데이터를 바인드 마운트된 디렉터리가 아닌 볼륨에 저장해야 합니다(자세한 내용은 `mongo` 이미지 문서 참고: https://github.com/docker-library/docs/blob/master/mongo/content.md#where-to-store-data). MongoDB와 Redis 컨테이너 내부에 마운트된 Docker 볼륨에 데이터를 저장하려면 `config/docker-compose.override.yml`에 다음 내용을 추가하세요(이 파일이 아직 없다면 생성하세요).

```yaml title="config/docker-compose.override.yml"
volumes:
  mongo-data:
  redis-data:

services:
  mongo:
    volumes:
      - mongo-data:/data/db

  redis:
    volumes:
      - redis-data:/data
```

자세한 내용은 다음을 참고하세요: https://docs.overleaf.com/on-premises/support/troubleshooting#running-overleaf-on-windows-or-macos-results-in-the-mongoservice-not-starting

</Accordion>

<Accordion title="Redis 6.2로 업그레이드하면 재시작 루프가 발생함">

`docker logs redis` 명령을 사용하여 로그 사본을 출력합니다.

`Fatal: Can't initialize Background Jobs` 줄이 보인다면 전체 출력은 다음과 비슷합니다.

```text title="Redis log example"
1:M 11 Feb 2024 15:19:22.609 # Server initialized
1:M 11 Feb 2024 15:19:22.609 # Fatal: Can't initialize Background Jobs.
1:C 11 Feb 2024 15:19:26.055 # oO0OoO0OoO0Oo Redis is starting oO0OoO0OoO0Oo
```

이는 현재 사용 중인 Docker 버전과 관련이 있을 수 있습니다. 20.10.10 이상 버전으로 업데이트하면 이 문제가 해결됩니다.

자세한 내용은 Redis 업스트림 이슈를 참고하세요: https://github.com/redis/redis/issues/12362

참고: https://docs.overleaf.com/on-premises/support/troubleshooting#upgrading-to-redis-6.2-results-in-a-restart-loop

</Accordion>

<Accordion title="템플릿 갤러리 미리 보기/썸네일 이미지의 방향이 잘못됨">

Server Pro가 생성하는 미리 보기/썸네일 이미지가 가끔 잘못된 방향으로 생성되어 수동으로 수정해야 할 수 있습니다. 이 이미지는 `/var/lib/overleaf/data/template_files/`(5.0.3 이상) 및 `/var/lib/sharelatex/data/template_files/`(이전 버전)에 저장됩니다.

변경하기 전에 이 폴더를 백업하는 것을 권장합니다.

영향을 받는 각 템플릿에 대해 아래 단계를 따라야 합니다.

템플릿 ID 찾기: 인스턴스의 템플릿 갤러리(/templates/all)로 이동하여 영향을 받는 템플릿을 열고 URL에서 ID를 복사합니다(예: https://your-instance-url/templates/6645d346c224815e9460a695). 수정 명령 실행: Docker 호스트에서 다음 명령을 실행합니다(템플릿 ID를 복사한 ID로 바꾸고 필요하면 경로를 수정하세요): docker exec sharelatex /bin/bash -c "mogrify -rotate 90 /var/lib/overleaf/data/template\_files/6645d346c224815e9460a695\_\*\{thumbnail,preview\}"

참고: https://docs.overleaf.com/on-premises/support/troubleshooting#incorrect-orientation-of-template-gallery-preview-thumbnail-images

</Accordion>

<Accordion title="시스템 호출이 활성화되어 있는지 확인하세요. pdflatex의 경우 'pdflatex -shell-escape'입니다.">

Community Edition에서는 모든 컴파일이 동일한 `sharelatex` 컨테이너 안에서 이루어지기 때문에 `\write18` 명령이 기본적으로 비활성화되어 있습니다. 이것이 더 안전한 기본값입니다.

pdflatex에서 이를 활성화하려면 프로젝트 루트에 다음 내용으로 `latexmkrc` 파일을 생성하세요.

```perl title="latexmkrc"
$pdflatex = 'pdflatex --shell-escape';
```

그런 다음 다시 컴파일해 보세요.

참고: https://docs.overleaf.com/on-premises/support/troubleshooting#please-verify-that-you-have-enabled-system-calls.-for-pdflatex-this-is-pdflatex-shell-escape

</Accordion>
