새 Dockerfile로 기존 TeX Live 이미지를 확장하고, 애플리케이션이 새 이미지를 사용하도록 구성할 수 있습니다.

여기서는 새 패키지나 글꼴을 설치하는 몇 가지 지침을 제공합니다.

TeX Live 이미지는 자주 업데이트되지 않습니다. Ayakaleaf Pro를 업그레이드할 때 사용자 지정 이미지를 다시 빌드하는 것을 권장합니다.

<Danger>

다음 섹션은 [샌드박스 컴파일](/ko/on-premises/configuration/overleaf-toolkit/sandboxed-compiles)에만 적용됩니다.

</Danger>

### 새 패키지 설치 및 업데이트

다음 예시처럼 `tlmgr install`, `tlmgr update` 등의 `tlmgr` 명령을 사용해 TeX Live 패키지를 관리할 수 있습니다.

```dockerfile
FROM ghcr.io/ayaka-notes/texlive-full:2023.1

RUN tlmgr update --force ebproof
```

### 이전 TeX Live 이미지에서 `tlmgr` 사용

기본적으로 `tlmgr`는 최신 TeX Live 릴리스에서 리소스를 다운로드합니다. 이전 TeX Live 이미지를 패치할 때는 다운로드 위치를 해당 아카이브로 전환해야 합니다. 아카이브 미러 목록은 [https://www.tug.org/historic/](https://www.tug.org/historic/)에서 확인하세요.

```dockerfile
FROM ghcr.io/ayaka-notes/texlive-full:2022.1

RUN tlmgr option repository <MIRROR>/systems/texlive/<YEAR>/tlnet-final
# e.g. RUN tlmgr option repository ftp://tug.org/historic/systems/texlive/2022/tlnet-final

RUN tlmgr update --force ebproof
```

### 새 글꼴 설치

TeX Live 배포판에 새 글꼴을 설치하는 방법은 여러 가지가 있으며, 사용자 지정 글꼴을 설치하려면 여러 단계가 필요할 수 있습니다. TeX Live 공식 문서의 [TeX 글꼴 설치 안내](https://tug.org/fonts/fontinstall.html)를 먼저 확인하는 것이 좋은 출발점입니다.

다음 `Dockerfile`은 기존 TeX Live 2022 이미지에 TrueType 글꼴을 설치하는 예시입니다.

```dockerfile
FROM ghcr.io/ayaka-notes/texlive-full:2022.1

COPY ./myfonts/*.ttf /usr/share/fonts/truetype/myfont/

# rebuild font information cache
RUN fc-cache
```

### 새 이미지를 사용하도록 Ayakaleaf Pro 구성

다음과 같이 `ghcr.io/ayaka-notes/texlive-full` 이름과 사용자 지정 태그를 사용해 새 이미지를 빌드합니다.

```bash
docker build -t ghcr.io/ayaka-notes/texlive-full:2023.1-custom .
```

이제 `TEX_LIVE_DOCKER_IMAGE`, `ALL_TEX_LIVE_DOCKER_IMAGES`, `ALL_TEX_LIVE_DOCKER_IMAGE_NAMES` 환경 변수를 업데이트하여 Ayakaleaf Pro가 새 `2023.1-custom` 이미지를 사용하도록 구성할 수 있습니다(이름은 선택 사항이며 이미지 순서를 따릅니다).

```text wrap
TEX_LIVE_DOCKER_IMAGE: "ghcr.io/ayaka-notes/texlive-full:2023.1-custom"
ALL_TEX_LIVE_DOCKER_IMAGES: "ghcr.io/ayaka-notes/texlive-full:2023.1,ghcr.io/ayaka-notes/texlive-full:2023.1-custom"
ALL_TEX_LIVE_DOCKER_IMAGE_NAMES: "TeX Live 2023,TeX Live 2023 custom"
```

위 예시에서 새 프로젝트는 기본적으로 새 `2023.1-custom` 이미지를 사용하며, 필요할 때는 `2023.1`도 계속 사용할 수 있습니다.

사용자 지정 이미지는 호스트에만 존재하므로 `bin/up`이 pull할 수 없습니다. `config/overleaf.rc`에서 `SIBLING_CONTAINERS_PULL=false`로 설정하고(다른 이미지는 `docker pull`로 직접 pull하세요), `bin/up -d`를 실행하여 새 설정을 적용하세요.

### Q\&A

<Accordion title="XeLaTeX로 중국어 문서를 컴파일하려면 중국어 글꼴을 설치해야 하나요?">

<strong>답변:</strong> `texlive-full` 이미지라면 필요하지 않습니다. 이 이미지에는 Fandol 글꼴이 포함된 TeX Live 중국어 패키지(`ctex`, `xeCJK`)와 Noto CJK 글꼴(예: `Noto Serif CJK SC`)이 포함되어 있습니다. 편집기 설정에서 프로젝트의 컴파일러를 XeLaTeX로 설정한 다음 컴파일하세요. 예:

```latex
\documentclass{ctexart}
\begin{document}
你好，世界！
\end{document}
```

Fandol 대신 Noto를 사용하려면 `\setCJKmainfont{Noto Serif CJK SC}`를 추가하세요. `latexmkrc`는 필요하지 않습니다. 다른 글꼴의 경우 [새 글꼴 설치](#installing-new-fonts)에 나온 대로 사용자 지정 이미지를 빌드하세요.

</Accordion>
