```text
{
  _id:        '123',
  email:      'alice@example.com'
  first_name: 'Alice',
  last_name:  'Jones'
}
```

이제 회사의 LDAP/Active Directory 시스템과 통합하려고 합니다. 해당 시스템에서 Alice의 정보는 다음과 같습니다.

```text
Alice:
  - uid:  'alicejones'
  - mail: 'alicejones@tech.example.com'
  - givenName:   'Alice'
  - sn: 'Jones'
```

목표는 Alice가 작업 내용을 잃지 않고 기존 Overleaf 자격 증명 대신 LDAP 사용자 이름(`alicejones`)과 비밀번호로 로그인하도록 하는 것입니다. 방법은 다음과 같습니다.

<Warning>

이 절차에서는 **sharelatex** 컨테이너를 다시 생성해야 하므로 어느 정도의 다운타임이 발생합니다. 먼저 테스트/스테이징 환경에서 이 절차를 진행하여 익숙해질 것을 강력히 권장합니다.

</Warning>

<Steps>
<Step title="사용자에게 이메일 주소 업데이트 요청">
Overleaf 계정은 이메일 주소에 연결되어 있으므로, 첫 번째 단계는 사용자의 Overleaf 이메일을 LDAP 또는 SAML 이메일과 일치시키는 것입니다.

이 예시에서는 Alice에게 Overleaf 계정에 로그인하여 이메일을 `alice@example.com`에서 `alicejones@tech.example.com`으로 변경하도록 요청합니다.

<Warning>

자신도 잊지 마세요! 관리자라면 자신의 이메일 주소도 업데이트해야 합니다.

</Warning>

<Check>

사용자가 많다면 [사용자 이름 마이그레이션](/ko/on-premises/user-and-project-management/user-management/username-migration) 스크립트를 사용하여 사용자의 기본 이메일 주소를 일괄 변경할 수 있습니다.

</Check>
</Step>

<Step title="LDAP 또는 SAML 모듈 활성화">
모든 사용자의 이메일 주소가 업데이트되면 이제 스위치를 켤 차례입니다! 새 인증 방식에 맞는 환경 변수를 설정한 다음 `bin/up -d` 명령으로 **sharelatex** 컨테이너를 다시 생성해야 합니다.

이렇게 하면 표준 Overleaf 로그인 양식이 새 LDAP 또는 SAML 로그인 양식으로 바뀝니다.

<Info>

LDAP 활성화에 관한 정보는 [여기](/ko/on-premises/configuration/overleaf-toolkit/authentication/ldap-authentication)에서, SAML 2.0은 [여기](/ko/on-premises/configuration/overleaf-toolkit/authentication/saml-authentication)에서 확인할 수 있습니다.

</Info>
</Step>

<Step title="이제 사용자가 LDAP 또는 SAML로 로그인 가능">
Alice가 다음에 로그인하면 새 양식이 표시됩니다.

![LDAP/Active Directory 로그인 페이지](/images/on-premises/image-4.jpg)

LDAP 사용자 이름(`alicejones`)과 비밀번호를 입력하면, 이메일 주소가 이제 LDAP의 이메일과 일치하므로 기존 Overleaf 계정에 바로 로그인됩니다. 모든 프로젝트는 작업하던 그대로 남아 있습니다.

SAML 2.0을 활성화한 경우 사용자에게 버튼이 표시되며, 이를 클릭하면 자격 증명을 입력할 수 있도록 IdP로 리디렉션됩니다. 인증에 성공하면 Overleaf 인스턴스로 다시 리디렉션되어 계정에 로그인됩니다.

![SAML 로그인 페이지](/images/on-premises/image-5.jpg)

<Info>

로그인 페이지 경험을 사용자 지정하는 방법에 대한 정보는 [환경 변수](/ko/on-premises/configuration/overleaf-toolkit/environment-variables) 페이지를 참고하세요.

롤백이 필요하면 LDAP/SAML 구성을 주석 처리하고 `bin/up -d` 명령으로 **sharelatex** 컨테이너를 다시 생성하기만 하면 됩니다. 그러면 사용자는 현재 이메일 주소와 Overleaf 전용 비밀번호로 로그인할 수 있습니다.

</Info>
</Step>
</Steps>

## 반대 방향: LDAP/SAML에서 기본 인증으로 되돌리기

LDAP 또는 SAML을 한동안 사용하다가 Overleaf의 내장 로그인 시스템으로 옮기고 싶다면 어떻게 할까요(예: LDAP를 더 이상 사용하지 않게 된 경우)? 문제없습니다! 다음과 같이 전환할 수 있습니다.

<Steps>
<Step title="모든 사용자의 이메일이 올바른지 확인">
사용자 계정은 이미 LDAP 또는 SAML 이메일 주소에 연결되어 있습니다. 앞으로 로그인에 사용할 이메일이므로 모든 것이 올바른지 확인하세요.
</Step>

<Step title="LDAP 또는 SAML 모듈 비활성화">
LDAP/SAML 구성 설정을 제거하거나 해제한 다음 `bin/up -d` 명령으로 **sharelatex** 컨테이너를 다시 생성하기만 하면 됩니다. 그러면 기본 Overleaf 이메일 및 비밀번호 로그인 양식이 다시 표시됩니다.

![기본 인증 로그인 페이지](/images/on-premises/image-6.jpg)
</Step>

<Step title="사용자에게 비밀번호 재설정 요청">
이제 사용자가 로그인 페이지를 방문하면 LDAP/SAML 양식 대신 Overleaf 로그인 양식이 표시됩니다.

사용자에게 Overleaf 기본 비밀번호가 없었을 수 있으므로 새로 만들어야 합니다. 각 사용자는 다음을 수행해야 합니다.

* "Forgot your password?" 링크를 클릭합니다.
* 계정에 연결된 이메일 주소(LDAP/SAML의 이메일)를 입력합니다.
* 비밀번호 재설정 이메일의 링크를 따라 새 비밀번호를 설정합니다.

<Info>

아직 하지 않았다면 [이메일 전송](/ko/on-premises/configuration/overleaf-toolkit/email-delivery) 활성화 가이드를 확인하세요.

</Info>

완료되면 이메일과 새 Overleaf 전용 비밀번호로 로그인하여 모든 프로젝트에 접근할 수 있습니다.
</Step>
</Steps>
