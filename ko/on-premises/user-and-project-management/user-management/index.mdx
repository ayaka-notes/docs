## 관리자 사용자 생성 {#creating-an-administrator-user}

Overleaf Toolkit 배포:

```bash title="Overleaf Toolkit" wrap
$ bin/docker-compose exec sharelatex /bin/bash -ce "cd /overleaf/services/web && node modules/server-ce-scripts/scripts/create-user --admin --email=joe@example.com"
```

레거시 docker-compose.yml 배포:

```bash title="Legacy docker-compose" wrap
$ docker exec sharelatex /bin/bash -ce "cd /overleaf/services/web && node modules/server-ce-scripts/scripts/create-user --admin --email=joe@example.com"
```

이 명령은 지정한 이메일 주소의 사용자가 아직 없으면 새로 생성하고 관리자로 지정합니다. 명령 출력에는 이 사용자의 비밀번호를 설정하고 처음 로그인할 수 있는 URL이 포함됩니다.

<Info>

프로그래밍 방식으로 접근하려는 경우 같은 스크립트를 사용해 관리자뿐 아니라 일반 사용자도 생성할 수 있습니다. 일반 사용자의 경우 --admin 플래그를 생략하세요.

</Info>

인증에 내부 계정을 사용하며 기존 사용자를 인스턴스 관리자로 승격하거나 관리자 권한을 회수해야 하는 경우 다음과 같이 하세요:

<Steps>
<Step title="관리자 UI를 통해">
* 기존 관리자로 로그인합니다.
* Admin -> Manage Users를 클릭합니다.
* 사용자를 검색하고 이름을 클릭합니다.
* 연필 아이콘을 클릭합니다.
* Admin을 켜거나 끕니다.
* Save를 클릭하여 완료합니다.
</Step>
</Steps>

## 사용자 삭제 {#deleting-users}

일반적으로 더 이상 필요하지 않은 경우가 아니면 계정을 삭제하지 않는 것이 좋습니다. 계정을 삭제하면 계정이 제거되고 공동 작업자가 프로젝트에 접근할 수 없게 됩니다. 사용자의 로그인을 막고 데이터를 유지하려면 대신 [계정을 비활성화](/on-premises/user-guide/administrators/user-management#disable-or-enable-an-account)하세요.

기본적으로 계정은 소프트 삭제됩니다. 인스턴스에서 사용자를 영구적으로 제거하는 방법은 [환경 변수](/ko/on-premises/configuration/overleaf-toolkit/environment-variables) 가이드의 `ENABLE_CRON_RESOURCE_DELETION`을 참조하세요.

<Info>

계정은 기본적으로 소프트 삭제됩니다. 영구 삭제 동작은 `ENABLE_CRON_RESOURCE_DELETION`을 참조하세요.

</Info>

### Admin -> Manage Users를 통해 {#via-admin->-manage-users}

<Steps>
<Step title="">
* 관리자로 로그인합니다.
* Admin -> Manage Users를 클릭합니다.
* 사용자를 검색하고 이름 옆의 확인란을 선택합니다.
* 휴지통 아이콘을 클릭합니다.
* Delete account를 클릭해 확인합니다.
</Step>
</Steps>

### 명령줄을 통해 {#via-the-command-line}

다음 명령을 사용해 사용자 계정(및 해당 프로젝트)을 삭제할 수 있습니다.

Overleaf Toolkit 배포:

```bash title="Overleaf Toolkit"
$ bin/docker-compose exec sharelatex /bin/bash -ce "cd /overleaf/services/web && node modules/server-ce-scripts/scripts/delete-user.mjs --email=joe@example.com"
```

레거시 docker-compose.yml 배포:

```bash title="Legacy docker-compose"
$ docker exec sharelatex /bin/bash -ce "cd /overleaf/services/web && node modules/server-ce-scripts/scripts/delete-user.mjs --email=joe@example.com"
```

<Danger>

삭제 스크립트는 하드코딩된 강제 옵션을 사용하므로, 계정 삭제 이메일 전송에 실패하더라도(예: 사용자의 이메일이 더 이상 사용되지 않는 경우) 삭제가 진행됩니다.

</Danger>

<Info>

--skip-email 옵션을 사용하여 삭제된 사용자에게 안내 이메일이 전송되지 않도록 할 수 있습니다.

</Info>

## 소프트 삭제된 사용자 복원 {#restoring-a-soft-deleted-user}

사용자가 소프트 삭제만 된 경우, 계정과 함께 삭제된 프로젝트를 복원할 수 있습니다. 사용자가 직접 삭제한 프로젝트는 삭제된 상태로 남습니다.

<Steps>
<Step title="">
* 관리자로 로그인합니다.
* Admin -> Manage Users를 클릭합니다.
* 복원하려는 사용자를 검색합니다.
* Display deleted users를 클릭합니다.
* 사용자 행의 화살표 아이콘을 클릭합니다.
* Restore를 클릭해 확인합니다.
</Step>
</Steps>

<Danger>

ENABLE\_CRON\_RESOURCE\_DELETION이 true로 설정된 경우, 소프트 삭제된 계정은 90일 이내에 복원할 수 있습니다. 90일이 지나면 계정을 복구할 수 없습니다.

</Danger>

## 사용자 수 집계 {#counting-users}

https://you-instance-url/admin/user#license 의 관리자 UI에서 사용자 수를 확인할 수 있습니다. 프로그래밍 방식의 확인 및 내보내기에는 다음 예제가 도움이 될 수 있습니다.

전체 사용자 수:

```bash title="Total number of users"
echo 'db.users.countDocuments()' | docker exec -i mongo mongosh --quiet localhost/sharelatex
# overleaf [direct: primary] sharelatex> 16
```

메트릭 엔드포인트를 사용한 전체 사용자 수:

```bash title="Num active users from metrics"
docker exec sharelatex curl http://127.0.0.1:3000/metrics | grep num_active_users
# # HELP num_active_users num_active_users
# # TYPE num_active_users gauge
# num_active_users{app="web-api",host="b3ae4ff549d8"} 16
```

전체 활성 사용자 수(예: 최근 365일 이내에 활동한 사용자):

```bash title="Total number of active users"
echo 'db.users.countDocuments({ lastActive: { $gte: new Date(new Date().getTime() - (365 * 24 * 60 * 60 * 1000)) } })' | docker exec -i mongo mongosh --quiet localhost/sharelatex
# overleaf [direct: primary] sharelatex> 10
```

## 사용자 계정 정보 업데이트 {#updating-user-account-information}

계정 업데이트 수행 방법은 SSO 활성화 여부에 따라 다릅니다.

* SSO를 사용하지 않는 경우:
  * 관리자는 Admin -> Manage Users에서 사용자 계정 정보(이메일, 이름, 성, 비밀번호 재설정 링크 생성)를 수정할 수 있습니다.
  * 일반 사용자는 Account -> Account Settings에서 자신의 정보를 업데이트할 수 있습니다(비밀번호 변경 및 Git 인증 토큰 생성 포함).
* SSO를 사용하는 경우:
  * Ayakaleaf Pro는 로그인 시 인증 시스템을 기반으로 사용자의 이름과 성을 업데이트하도록 구성할 수 있습니다.
  * OVERLEAF\_SAML\_UPDATE\_USER\_DETAILS\_ON\_LOGIN 또는 OVERLEAF\_LDAP\_UPDATE\_USER\_DETAILS\_ON\_LOGIN이 true인 경우, https://your-instance-url/user/settings 의 사용자 정보 양식이 비활성화되며 이름/성은 ID 관리 시스템에서만 설정할 수 있습니다.

자세한 내용은 다음을 참조하세요:

* [SAML 2.0 구성](/ko/on-premises/configuration/overleaf-toolkit/authentication/saml-authentication)
* [LDAP 구성](/ko/on-premises/configuration/overleaf-toolkit/authentication/ldap-authentication)

### Q\&A {#q&a}

<Accordion title="API 등을 사용해 SSO 사용자를 미리 만들 수 있나요?">

<strong>답변:</strong> 이를 위한 HTTP API는 없습니다. 위의 `create-user` 스크립트(`--admin` 없이)로 계정을 만들거나 **Admin → Manage Users**에서 **Create account**로 만드세요. `EXTERNAL_AUTH`가 설정되어 있으면 이 양식에 **Log in with SSO** 옵션이 있으며, 로컬 비밀번호와 활성화 이메일이나 링크 없이 계정을 만듭니다. **Create** 후 대화 상자가 닫힙니다. 첫 LDAP, SAML 또는 OIDC 로그인 시 사용자는 새 계정 대신 같은 이메일을 가진 기존 계정을 받습니다. [계정과 비밀번호](/ko/on-premises/configuration/overleaf-toolkit/authentication#accounts-and-passwords)를 참고하세요.

</Accordion>

<Accordion title="사용자 목록을 내보낸 후 나중에 복원할 수 있나요?">

<strong>답변:</strong> 아니요. **Admin → Manage Users**에도, 스크립트로도 사용자 계정의 내보내기나 가져오기 기능은 없습니다. 계정은 MongoDB에 저장되므로 [MongoDB 백업](/ko/on-premises/maintenance/data-and-backups#mongodb)으로 백업하고 복원하세요. `export-user-projects.mjs` 스크립트는 계정이 아닌 사용자의 프로젝트를 zip 파일로 내보냅니다. [프로젝트 내보내기](/ko/on-premises/maintenance/data-and-backups/exporting-projects)를 참조하세요.

</Accordion>

<Accordion title="`create-user` 링크는 얼마 동안 유효하며, 이메일 없이 비밀번호를 재설정하려면 어떻게 하나요?">

<strong>답변:</strong> `create-user`가 출력하는 링크는 7일 동안 유효하며, 출력에서 복사하는 방식이므로 SMTP 없이도 동작합니다. 새 링크를 받으려면 같은 이메일로 `create-user`를 다시 실행하세요. 기존 계정의 경우 새 링크만 출력하지만, 계정의 관리자 플래그도 `--admin`에 맞게 설정하므로 관리자에 대해 실행할 때는 `--admin`을 유지하세요.

관리자는 이메일 없이도 재설정 링크를 받을 수 있습니다. **Admin → Manage Users**에서 사용자 행의 자물쇠 아이콘을 클릭하고 **Send reset link**를 클릭한 뒤, 대화 상자에서 링크를 복사하세요. 링크는 1시간 동안 유효합니다. [활성화 또는 재설정 링크 보내기](/on-premises/user-guide/administrators/user-management#send-an-activation-or-reset-link)를 참고하세요.

또는 비밀번호를 직접 설정하세요. 사용자 이름을 클릭하고 연필 아이콘을 클릭한 다음 8자 이상의 **New password**를 입력하고 **Save**를 클릭합니다. LDAP, SAML 또는 OIDC로만 로그인하는 계정은 어느 방법으로도 비밀번호를 받을 수 없습니다.

</Accordion>
