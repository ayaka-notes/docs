## 사용자 이름 마이그레이션

로그인 관점에서 사용자의 기본 식별자는 이메일 주소입니다. 로컬 기반 인증에서 SSO로 마이그레이션하거나 한 IdP에서 다른 IdP로 마이그레이션하는 경우 사용자 이메일 주소를 업데이트해야 할 수 있습니다.

이를 돕기 위해 다음 형식의 CSV 파일을 사용해 사용자 이메일을 마이그레이션하는 스크립트가 제공됩니다:

`oldEmail,newEmail`

몇 가지 유효성 검사를 수행한 후 스크립트는 CSV 파일을 순회하며 사용자의 이메일 주소를 `oldEmail`에서 `newEmail`로 업데이트합니다.

### **유효성 검사**

마이그레이션을 실행하기 전에 `<csv_file>`에 대해 다음 사항을 확인합니다:

* 각 행의 `oldEmail`과 `newEmail`이 모두 유효한 이메일 주소인지
* 중복 항목이 없는지. 예를 들어 서로 다른 사용자를 같은 새 이메일 주소로 업데이트하려 하거나, 같은 사용자 계정을 이미 사용 중인 이메일 주소로 업데이트하려 하지 않는지

### **사용법**

```bash wrap
docker cp <csv_file> sharelatex:/overleaf/services/web/<csv_file> docker exec sharelatex /bin/bash -c "cd /overleaf/services/web;node ./modules/server-ce-scripts/scripts/migrate-user-emails.js [--commit] [--continue|--ignore-missing] [--admin-id=ADMIN_USER_ID] <csv_file>"
```

### **플래그**

| 이름               | 설명                                                                                                                                                                                                                                                      |
| ------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `--commit`         | <p>`--commit` 플래그를 포함하면 실제로 마이그레이션을 수행합니다. 생략하면 마이그레이션이 드라이런 모드로 실행되어 변경 사항은 적용되지 않지만 유효성 검사는 계속 수행됩니다.<br /><br /><strong>기본값</strong>:`false`</p> |
| `--continue`       | `--continue` 플래그는 사용자 계정의 이메일 주소가 이미 업데이트된 경우에도 마이그레이션 과정을 계속 진행합니다                                                                                                                         |
| `--ignore-missing` | `--ignore-missing` 플래그는 사용자 계정을 찾을 수 없는 경우에도 마이그레이션 과정을 계속 진행합니다                                                                                                                                                                  |
| `--admin-id`       | `--admin-id`는 마이그레이션을 수행하는 관리자의 ID로 설정해야 하며, 감사 로그 항목에 사용됩니다. 사용자 ID를 찾으려면 **Admin** > **Manage Users**로 이동하여 자신의 이메일 주소를 검색하고 첫 번째 결과를 클릭하십시오.   |
| `<csv_file>`       | `<csv_file>`은 이전 이메일 주소와 새 이메일 주소가 들어 있는 파일입니다                                                                                                                                                                                             |

### **완료**

마이그레이션 스크립트를 실행하는 동안, 선택한 플래그에 따라 오류가 콘솔에 기록된 후 계속 진행할지, 아니면 콘솔에 기록된 후 종료할지가 결정됩니다. 오류로 인해 스크립트가 중간에 종료되면 실패했음을 나타내기 위해 종료 코드 1로 종료됩니다.

마이그레이션이 완료되면 스크립트는 성공, 실패, 건너뛴 업데이트 수를 콘솔에 기록합니다. 마이그레이션이 성공적으로 완료되면 종료 코드 0으로 종료됩니다.
