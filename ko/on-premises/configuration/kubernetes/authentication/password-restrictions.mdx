**web** 서비스는 사용자가 가입하거나 비밀번호를 설정 또는 변경할 때 로컬 비밀번호를 검사합니다. SSO 로그인(LDAP, SAML, OIDC)은 영향을 받지 않으며, 해당 비밀번호는 ID 공급자가 관리합니다. Toolkit의 경우 [비밀번호 제한](/ko/on-premises/configuration/overleaf-toolkit/authentication/password-restrictions)을 참고하세요.

| | |
| --- | --- |
| 서비스 | web, 모든 Ayakaleaf Pro 파드에서 실행. web이 시작될 때 읽음 |
| 네트워크 | 없음 |
| 주기적 작업 | 없음 |

### 구성

ConfigMap `overleaf-env`에 추가하고 재시작하세요.

```yaml title="30-config.yaml (additions)"
  OVERLEAF_PASSWORD_VALIDATION_MIN_LENGTH: "12"
  OVERLEAF_PASSWORD_VALIDATION_MAX_LENGTH: "72"
```

```bash
kubectl apply -f 30-config.yaml
kubectl -n overleaf rollout restart deployment/overleaf     # or statefulset/overleaf
```

| 변수 | 기본값 | |
| --- | --- | --- |
| `OVERLEAF_PASSWORD_VALIDATION_MIN_LENGTH` | `8` | 허용되는 가장 짧은 비밀번호 길이입니다. |
| `OVERLEAF_PASSWORD_VALIDATION_MAX_LENGTH` | `72` | 허용되는 가장 긴 비밀번호 길이입니다. `72`보다 큰 값은 `72`로 처리됩니다. |

숫자는 따옴표로 감싸세요. ConfigMap은 문자열만 담을 수 있습니다.

<Warning>

`OVERLEAF_PASSWORD_VALIDATION_PATTERN`은 읽히기는 하지만 적용되지 않습니다. 이 패턴과 일치하지 않는 비밀번호도 허용됩니다. 길이 제한만 적용됩니다.

</Warning>

### 여러 레플리카

추가 작업이 없습니다. 모든 레플리카가 같은 ConfigMap을 읽습니다.

### Kubernetes에서의 테스트

레플리카 하나로 구성된 Kubernetes 1.37 환경에서 ConfigMap에 `OVERLEAF_PASSWORD_VALIDATION_MIN_LENGTH: "12"`와 `OVERLEAF_PASSWORD_VALIDATION_PATTERN: aA$3`를 설정한 상태로 새 계정을 활성화했을 때, 10자 비밀번호는 거부되었고 패턴이라면 거부했을 소문자만으로 된 20자 비밀번호는 허용되었습니다. 가입에 대한 엔드투엔드 테스트에서도 기본값으로 `123456`이 너무 짧다는 이유로 거부됩니다.
