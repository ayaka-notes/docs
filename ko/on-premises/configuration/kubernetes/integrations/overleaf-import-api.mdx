Import API(`/docs` 및 "Open in Ayakaleaf" 버튼, `open-in-overleaf` 모듈)는 모든 Ayakaleaf Pro 파드의 **web** 서비스에서 실행되며 기본적으로 활성화되어 있습니다. URL로 지정된 파일은 같은 파드의 linked-url-proxy를 통해 다운로드됩니다. 호출 방법은 [Overleaf Import API](/ko/on-premises/configuration/overleaf-toolkit/integrations/overleaf-import-api)에 설명되어 있습니다.

| | |
| --- | --- |
| 서비스 | web(`open-in-overleaf` 모듈); linked-url-proxy를 통해 다운로드 |
| 외부 → Overleaf | 모든 웹사이트에서 브라우저가 `${OVERLEAF_SITE_URL}/docs`로 `GET` 또는 `POST` 요청 |
| 파드 → 외부 | `snip_uri` 및 `zip_uri` 다운로드, [외부 URL](/ko/on-premises/configuration/kubernetes/external-url)에 설명된 대로 제한됨 |
| 상태 | 로그아웃한 방문자의 요청, 로그인할 때까지 Redis에 10분간 보관 |
| 주기적 작업 | 없음 |

### 구성

활성화하는 데 필요한 작업은 없습니다. ConfigMap의 관련 설정:

| 설정 | |
| --- | --- |
| `OVERLEAF_ALLOW_PUBLIC_ACCESS: "true"` | 로그아웃한 방문자가 `/devs`를 열 수 있으며, 방문자가 보낸 요청은 로그인할 때까지 보관됩니다. [공개 접근](/ko/on-premises/configuration/kubernetes/authentication/public-access)을 참조하세요. |
| `MAX_UPLOAD_SIZE` | 요청에 포함할 수 있는 최대 ZIP 크기(MB 단위, 기본값 `50`). 인그레스 또는 로드 밸런서도 해당 크기의 요청 본문을 허용해야 합니다. |
| `OVERLEAF_LINKED_URL_*` | `snip_uri`와 `zip_uri`가 가리킬 수 있는 주소, [외부 URL](/ko/on-premises/configuration/kubernetes/external-url)을 참조하세요. |

### 여러 레플리카

추가로 필요한 것이 없습니다. 로그아웃한 방문자의 요청은 Redis에 보관되므로, 방문자가 로그인한 후 어느 레플리카에 도달하든 요청이 이어서 처리됩니다.

### Kubernetes에서의 테스트

레플리카 하나를 둔 Kubernetes 1.37에서 Import API에 대한 엔드 투 엔드 테스트가 통과했습니다(14개 케이스). 테스트 항목은 `/devs` 페이지와 예제 프로젝트, 스니펫, 완전한 문서, URL 인코딩된 링크 및 data URL의 파일을 프로젝트로 변환, 프로젝트로 만들 수 없는 제출의 거부, 내부 주소에서의 다운로드 거부, 로그인 과정을 거쳐도 유지되는 로그아웃 상태의 게시물과 링크, 그리고 `OVERLEAF_ALLOW_PUBLIC_ACCESS` 사용 시 로그아웃한 방문자의 `/devs` 접근과 로그인 후 한 번 이어서 처리되는 게시된 스니펫입니다. 마지막 케이스는 HAProxy 뒤에 레플리카 세 개를 둔 환경에서도 통과합니다.
