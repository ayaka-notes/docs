Kubernetes 배포는 Toolkit과 동일한 환경 변수를 읽습니다. Toolkit 페이지에서 "`config/variables.env`에 추가하세요"라고 안내하는 경우, 해당 값을 ConfigMap `overleaf-env`에 넣거나, 비밀번호, 키 또는 토큰이라면 Secret `overleaf-secrets`에 넣으세요. 그런 다음 재시작합니다.

```bash
kubectl -n overleaf apply -f 30-config.yaml        # after editing the ConfigMap
kubectl -n overleaf patch secret overleaf-secrets --type merge \
  -p '{"stringData":{"GITHUB_TOKEN_CIPHER_PASSWORD":"'"$(openssl rand -hex 32)"'"}}'
kubectl -n overleaf rollout restart deployment/overleaf
```

`config/overleaf.rc`의 값은 환경 변수가 아니라 Toolkit 설정입니다. 이를 대체하는 항목은 이 페이지 끝의 Q\&A를 참고하세요.

### 인증서 및 기타 파일

일부 기능은 값 대신 파일 경로를 받습니다. SAML 인증서(`OVERLEAF_SAML_IDP_CERT`, ...), LDAP CA(`OVERLEAF_LDAP_TLS_OPTS_CA_PATH`), 또는 자체 호스팅 GitHub Enterprise, GitLab, Gitea를 위한 사설 CA(`NODE_EXTRA_CA_CERTS`)가 그렇습니다. 파일을 Secret에 넣고 Toolkit 페이지가 기대하는 위치인 `/var/lib/overleaf/certs`에 마운트하세요.

```bash
kubectl -n overleaf create secret generic overleaf-certs --from-file=idp_cert.pem --from-file=ca.pem
```

```yaml title="40-overleaf.yaml (additions)"
          volumeMounts:
            # ...
            - name: certs
              mountPath: /var/lib/overleaf/certs
              readOnly: true
      volumes:
        # ...
        - name: certs
          secret:
            secretName: overleaf-certs
```

그런 다음 ConfigMap에서 경로로 참조하고(예: `NODE_EXTRA_CA_CERTS: /var/lib/overleaf/certs/ca.pem`) 재시작하세요.

<Warning>

<strong>암호화 비밀번호.</strong> 사용하는 기능의 모든 `*_CIPHER_PASSWORD`를 Secret에 설정하세요. 그렇지 않으면 일부 기능은 처음 사용할 때 데이터 볼륨에 키 파일을 생성합니다. 레플리카가 하나라면 볼륨을 잃기 전까지는 동작하지만, 레플리카가 여러 개라면 각 레플리카가 서로 다른 키로 암호화하게 됩니다.

</Warning>

### Q\&A

<Accordion title="`config/overleaf.rc`의 Toolkit 설정 중 어떤 것이 필요한가요?">

<strong>답변:</strong> Ayakaleaf Pro는 그중 어떤 것도 읽지 않습니다. Kubernetes에서 대응하는 항목은 다음과 같습니다.

| `config/overleaf.rc`                         | Kubernetes                                                        |
| -------------------------------------------- | ----------------------------------------------------------------- |
| `OVERLEAF_LISTEN_IP`, `OVERLEAF_PORT`        | Service(NodePort) 또는 인그레스                            |
| `SIBLING_CONTAINERS_ENABLED`                 | ConfigMap의 `SANDBOXED_COMPILES*`, 파드의 Docker 소켓  |
| `GIT_BRIDGE_ENABLED`                         | [Git 연동](/ko/on-premises/configuration/kubernetes/integrations/git-integration)                             |
| `MONGO_ENABLED`, `REDIS_ENABLED`, `MONGO_URL`, `REDIS_HOST` | StatefulSet 또는 관리형 서비스, `OVERLEAF_MONGO_URL` 및 `OVERLEAF_REDIS_HOST` |
| `REDIS_AOF_PERSISTENCE`                      | `20-redis.yaml`의 `--appendonly yes`                             |
| `NGINX_ENABLED`, `TLS_*`                     | 인그레스 또는 로드 밸런서                                     |

</Accordion>
