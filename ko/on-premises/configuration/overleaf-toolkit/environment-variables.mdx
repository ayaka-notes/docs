이 페이지에서는 Toolkit 배포 시 `config/variables.env` 파일에서 지원되는 환경 변수를 설명합니다.

`config/variables.env` 파일은 `NAME=value` 형식의 변수 정의로 구성되며, `#`으로 시작하는 줄은 주석으로 처리됩니다.

<Info>

`overleaf.rc` 또는 `variables.env`에서 무언가를 변경한 후에는 `bin/up`을 실행하여 Docker 컨테이너를 다시 생성해야 합니다.

</Info>

### 모든 버전

이 환경 변수들은 Server CE 및 Server Pro와 호환되며, 두 온프레미스 버전 간에 쉽게 마이그레이션할 수 있는 방법을 제공합니다. Toolkit 배포와 Docker Compose 배포 모두에서 사용할 수 있습니다.

<Info>

이전에는 이 환경 변수들의 접두사가 `OVERLEAF_`가 아니라 `SHARELATEX_`였습니다.

</Info>

| 이름                                                                     | 설명 |
| ---------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `OVERLEAF_SITE_URL`                                                    | Overleaf 인스턴스가 공개적으로 제공되는 주소입니다. 공개 링크와 websocket 연결 시 사용되므로 반드시 올바르게 구성해야 합니다! |
| `OVERLEAF_ADMIN_EMAIL`                                                 | 사용자가 사이트 운영자에게 연락할 수 있는 이메일 주소입니다. |
| `OVERLEAF_APP_NAME`                                                    | 실행 중인 애플리케이션을 지칭할 때 표시되는 이름입니다. 기본값은 'Overleaf (Community Edition)'입니다. |
| `OVERLEAF_MONGO_URL` 및 `MONGO_URL`                                     | 사용할 Mongo 데이터베이스의 URL입니다. |
| `OVERLEAF_REDIS_HOST` 및 `REDIS_HOST`                                   | 사용할 Redis 인스턴스의 호스트 이름입니다. 둘 다 필요합니다([릴리스 노트](/ko/on-premises/release-notes) 참조). |
| `OVERLEAF_REDIS_PORT` 및 `REDIS_PORT`                                   | 사용할 Redis 인스턴스의 포트입니다. 둘 다 필요합니다([릴리스 노트](/ko/on-premises/release-notes) 참조). |
| `OVERLEAF_REDIS_PASS` 및 `REDIS_PASSWORD`                               | Redis에 연결할 때 사용할 비밀번호입니다(해당되는 경우). 환경 변수 **두 개 모두** 설정해야 합니다. 자세한 내용은 [비밀번호 인증 활성화](/ko/on-premises/configuration/overleaf-toolkit/redis#enabling-password-authentication)를 참조하십시오. |
| `OVERLEAF_REDIS_TLS`                                                   | <p>`true`로 설정하면 TLS가 필요한 Redis 인스턴스에 연결할 수 있습니다.<br /><br /><strong>참고:</strong> mTLS는 현재 지원되지 않습니다.</p> |
| `OVERLEAF_NAV_TITLE`                                                   | 애플리케이션의 탭 제목을 설정합니다. |
| `OVERLEAF_HEADER_IMAGE_URL_LIGHT` 및 `OVERLEAF_HEADER_IMAGE_URL_DARK`   | 라이트 및 다크 테마용 사용자 지정 헤더 로고의 URL입니다(6.3.0에서 추가). 각 테마별 변수가 설정되지 않은 경우 `OVERLEAF_HEADER_IMAGE_URL`로 대체됩니다. [Branding](/ko/on-premises/configuration/overleaf-toolkit/branding  "mention")을 참조하십시오. |
| `OVERLEAF_LINKED_URL_OUTBOUND_PROXY` | 외부 연결 파일과, Open in Overleaf API를 통한 외부 ZIP 또는 TeX 리소스를 가져올 때 사용하는 HTTP(S) 프록시의 URL입니다. 재출시된 Ayakaleaf Pro `6.3.0`(2026년 10월 3일)부터 사용할 수 있습니다. 직접 연결하려면 설정하지 마십시오. 예: `OVERLEAF_LINKED_URL_OUTBOUND_PROXY=http://proxy.internal:3128`. 구성 및 네트워크 접근 제한에 대해서는 [Outbound Proxy](/ko/on-premises/configuration/overleaf-toolkit/external-url#outbound-proxy  "mention")를 참조하십시오. |
| `OVERLEAF_INVITE_TOKEN_SECRET`                                         | <p><strong>필수</strong>. 프로젝트 공유 토큰을 보호하는 데 사용되는 임의의 문자열입니다(Server Pro 6.2.0에서 추가).</p><p><strong>최소 문자 수:</strong> 16</p> |
| `OVERLEAF_SESSION_SECRET`                                              | 토큰을 보호하는 데 사용되는 임의의 문자열입니다. 로드 밸런싱을 사용하는 경우 모든 서버에서 동일한 토큰으로 설정해야 합니다. 인스턴스를 하나만 실행하는 경우에는 사용자가 설정할 필요가 없습니다. |
| `OVERLEAF_COOKIE_SESSION_LENGTH`                                       | 기본 세션 쿠키 만료 시간인 5일을 재정의할 수 있습니다. 재정의 값은 밀리초 단위여야 합니다. 예: 세션을 1시간 동안 유지하려면 `COOKIE_SESSION_LENGTH=3600000`으로 설정합니다. (Server Pro 4.2에서 추가) |
| `OVERLEAF_TRUSTED_PROXY_IPS`                                           | <p>설정하지 않으면 기본값은 `loopback`입니다. 수동으로 설정하는 경우 신뢰할 IP 외에도 <strong>sharelatex</strong> 컨테이너 내부에서 실행되는 nginx 인스턴스를 신뢰하는 `loopback`(또는 `127.0.0.1`)을 반드시 포함해야 합니다. IP 주소와 CIDR 범위만 허용됩니다. `localhost`와 같은 호스트 이름을 추가하지 마십시오. 그렇지 않으면 Overleaf가 시작되지 않고 `502 Bad Gateway`를 반환합니다.<br /><br />일반 네트워크에 `172.16.0.0/12`(Docker 네트워크의 기본 서브넷)의 서브넷을 사용하는 경우 `config/variables.env`에 `OVERLEAF_TRUSTED_PROXY_IPS=loopback,<network>`를 설정하십시오. 여기서 `<network>`는 `docker inspect overleaf_default`의 `IPAM -> Config -> Subnet` 값입니다(예: `OVERLEAF_TRUSTED_PROXY_IPS=loopback,172.19.0.0/16`). 이는 `X-Forwarded` 헤더 위조를 방지하기 위한 것입니다.<br /><br />외부 TLS 프록시(즉, Overleaf Toolkit에서 관리하지 않는 프록시)를 사용하는 경우 `OVERLEAF_TRUSTED_PROXY_IPS=loopback,<ip-of-your-tls-proxy>`로 설정되어 있는지 확인하십시오(예: `OVERLEAF_TRUSTED_PROXY_IPS=loopback,192.168.13.37`).</p> |
| `OVERLEAF_RESTRICT_INVITES_TO_EXISTING_ACCOUNTS`                       | `true`로 설정하면 프로젝트 초대를 기존 사용자 계정에 해당하는 이메일 주소로 제한합니다. |
| `OVERLEAF_ALLOW_PUBLIC_ACCESS`                                         | `true`로 설정하면 인증되지 않은 사용자도 사이트를 볼 수 있습니다. 기본값은 `false`이며, 이 경우 인증되지 않은 사용자가 사이트의 어느 부분을 보려고 해도 무조건 로그인 페이지로 리디렉션됩니다. 이 옵션을 설정해도 인증이나 보안이 비활성화되는 것은 아닙니다. 사용자가 프로젝트를 공개하고 인증되지 않은 사용자가 해당 프로젝트를 볼 수 있게 하려면 이 옵션이 필요합니다. |
| `OVERLEAF_ALLOW_ANONYMOUS_READ_AND_WRITE_SHARING`                      | `true`로 설정하면 익명 사용자가 [링크 공유](https://www.overleaf.com/blog/integration-update-link-sharing-2017-11-27) 기능으로 공유된 프로젝트를 보고 편집할 수 있습니다. |
| `OVERLEAF_DISABLE_LINK_SHARING`                                        | [링크 공유](https://www.overleaf.com/blog/integration-update-link-sharing-2017-11-27) 기능을 비활성화합니다. |
| `EMAIL_CONFIRMATION_DISABLED`                                          | `true`로 설정하면 이메일 확인을 요청하는 배너가 표시되지 않습니다. |
| `ADDITIONAL_TEXT_EXTENSIONS`                                           | 편집 가능한 파일의 추가 확장자를 구성하는 문자열 배열입니다. |
| `DEFAULT_LATEX_COMPILER`                                               | <p><strong>새</strong> 프로젝트에서 사용할 기본 컴파일러를 설정합니다. (Server Pro 6.2.0에서 추가)</p><p><strong>옵션:</strong> `pdflatex`, `latex`, `xelatex` 또는 `lualatex`</p> |
| `OVERLEAF_STATUS_PAGE_URL`                                             | 사용자 지정 상태 페이지 URL입니다(Server Pro 3.4.0에서 추가). 예: `status.example.com`. |
| `OVERLEAF_FPH_INITIALIZE_NEW_PROJECTS`                                 | 새 프로젝트가 Full Project History로 초기화되지 않도록 하려면 `'false'`로 설정합니다(Server Pro 3.5.0에서 추가). |
| `OVERLEAF_FPH_DISPLAY_NEW_PROJECTS`                                    | 새 프로젝트에서 기존 기록 대신 Full Project History가 표시되지 않도록 하려면 `'false'`로 설정합니다(Server Pro 3.5.0에서 추가). |
| `ENABLE_CRON_RESOURCE_DELETION`                                        | 이 환경 변수를 `true`로 설정하면 삭제된 프로젝트와 사용자를 90일 후 자동으로 정리합니다. |
| `OVERLEAF_USER_HARD_DELETION_DELAY`                                    | <p>삭제된 사용자의 만료 지연 시간을 변경하는 데 사용합니다. 밀리초 단위로 구성합니다.<br /><br /><strong>기본값:</strong> 90일</p> |
| `OVERLEAF_PROJECT_HARD_DELETION_DELAY`                                 | <p>삭제된 프로젝트의 만료 지연 시간을 변경하는 데 사용합니다. 밀리초 단위로 구성합니다.<br /><br /><strong>기본값:</strong> 90일</p> |
| `MAX_UPLOAD_SIZE`                                                      | <p>개별 업로드의 최대 크기를 메가바이트 단위로 제어합니다. 기본값은 `50`입니다.<br /><br /><strong>주의</strong>: 이 변수는 단위(MB)나 따옴표 등 없이 숫자만 입력합니다.<br /><br />업로드된 `.zip` 파일의 압축 해제 후 전체 크기는 이 값의 6배(기본값 300 MB)로 제한됩니다.</p> |
| `COMPILE_SIZE_LIMIT`                                                   | 최대 요청 본문 크기를 바이트 단위로 제어합니다. 이는 CLSI 서비스에 대한 초기 컴파일 요청에서 전송해야 하는 프로젝트 내 모든 doc 파일(`main.tex`, `references.bib`(연결되지 않은 경우) 등) 크기의 합계입니다. |
| `COMPILE_TIMEOUT`                                                      | 컴파일 완료에 허용되는 시간(초)입니다. 자세한 내용은 [프로젝트 컴파일 시간 제한 업데이트](/ko/on-premises/user-and-project-management/project-management#updating-project-compile-timeout)를 참조하십시오. |
| `MAX_RECONNECT_GRACEFULLY_INTERVAL_MS`                                 | 데이터 손실 위험을 줄이기 위한, 에디터의 정상 재연결, 데이터 플러시 및 컨테이너 종료 사이의 구성 가능한 지연 시간입니다. |
| `SECCOMP_PROFILE`                                                      | <p>이 환경 변수를 SECCOMP 프로필을 가리키는 Docker <strong>호스트</strong> 머신의 경로로 설정합니다. 프로필 사본은 <a href="https://raw.githubusercontent.com/overleaf/overleaf/365af778b68a7940e08282119dc4ef473e2f0044/services/clsi/seccomp/clsi-profile.json">여기</a>에서 다운로드할 수 있습니다.<br /><br />현재 샌드박스 컴파일을 사용하는 Podman 배포에 필요합니다.</p> |
| `OVERLEAF_DISABLE_CHAT`                                                | `true`로 설정하면 프로젝트 내 채팅 기능을 비활성화합니다. |
| `OVERLEAF_LOGIN_SUPPORT_TEXT`                                          | 설정하면 로그인 버튼 아래에 지원 정보를 표시할 수 있습니다. 텍스트는 로그인 화면에 표시되며, 사용자를 내부 지원 창구로 안내하거나 로그인, 계정 생성 등에 관한 안내를 제공하는 데 사용할 수 있습니다. |
| `ALLOW_MONGO_ADMIN_CHECK_FAILURES`                                     | <p>`true`로 설정하면 MongoDB 시작 검사가 실패하더라도 배포 시작이 차단되지 않습니다. 데이터베이스 사용자에게 `clusterParameterReader` 역할이 없는 MongoDB 데이터베이스를 사용하는 경우 필요할 수 있습니다.<br /><br />사용자 지정 역할 생성에 대한 도움말은 <a href="/ko/on-premises/maintenance/updating-mongodb#creating-a-custom-role">여기</a>를 참조하십시오.</p> |
| `V1_HISTORY_URL_FOR_GIT_BRIDGE`                                        | 내부 트래픽(`web` 서비스 → `history-v1` 서비스, 둘 다 `sharelatex` 컨테이너 내부)과 외부 트래픽(`git-bridge` → `history-v1`, 별도 컨테이너에서 실행)에 대해 **history-v1** 엔드포인트를 분리할 수 있습니다. |
| `OVERLEAF_MAINTENANCE_MESSAGE` 및 `OVERLEAF_MAINTENANCE_MESSAGE_HTML`   | 유지보수 페이지의 제목과 내용을 사용자 지정하는 데 사용합니다. `OVERLEAF_STATUS_PAGE_URL`과 함께 사용할 수 없습니다. |

<Info>

SSO 옵션(예: LDAP)이 아닌 Overleaf 로그인 시스템(로컬 계정)을 사용하는 경우 사용자에게 비밀번호 제한을 적용할 수 있습니다. SSO 계정의 경우 비밀번호 정책은 ID 공급자나 디렉터리 서비스에서 적용되며, 추가로 다단계 인증도 지원할 수 있습니다.

</Info>
