### 전역 설정

특정 인증 모듈을 활성화하려면 환경 변수 `EXTERNAL_AUTH`가 필요합니다. 이 환경 변수는 어떤 외부 인증 방식을 활성화할지 지정합니다. 사용 가능한 옵션은 다음과 같습니다(소문자):

* saml
* ldap
* oidc

사용자가 이러한 방법으로만 로그인하도록 하려면 `OVERLEAF_DISABLE_LOCAL_LOGIN=true`를 설정하세요. 이렇게 하면 이메일 및 비밀번호 로그인이 숨겨집니다. `EXTERNAL_AUTH`에서 하나 이상의 방법이 활성화되어 있지 않으면 아무런 효과가 없습니다(6.3.1에서 추가됨).

### 계정과 비밀번호

`EXTERNAL_AUTH`를 설정하면 인스턴스에 로컬 비밀번호가 있는 계정과 없는 계정이 함께 존재할 수 있습니다. 계정이 비밀번호를 설정하거나 변경할 수 있는지는 오직 이것에 따라 결정됩니다. 로컬 비밀번호가 있는 계정은 비밀번호를 직접 관리하고, 로컬 비밀번호가 없는 계정은 SSO로만 로그인하며 비밀번호를 받을 수 없습니다. 관리자도 설정해 줄 수 없습니다.

| 계정 | 로컬 비밀번호 | 로그인 방법 | 이메일로 재설정 | 설정 페이지 | 관리자의 비밀번호 설정 |
| --- | --- | --- | --- | --- | --- |
| 로컬 계정, `EXTERNAL_AUTH` 없음 | 예 | 이메일과 비밀번호 | 예 | 예 | 예 |
| `EXTERNAL_AUTH`가 설정된 인스턴스의 로컬 계정 | 예 | 이메일과 비밀번호 | 예 | 예 | 예 |
| OIDC에 연결된 로컬 계정 | 예 | 이메일과 비밀번호 또는 OIDC | 예 | 예 | 예 |
| 첫 LDAP, SAML 또는 OIDC 로그인으로 생성된 계정 | 아니요 | SSO만 | 아니요 | 아니요 | 아니요 |
| LDAP 또는 SAML로 로그인한 로컬 계정 | 아니요, 해당 로그인 시 제거됨 | SSO만 | 아니요 | 아니요 | 아니요 |
| 관리자가 외부 계정으로 생성한 계정 | 아니요 | SSO만 | 아니요 | 아니요 | 아니요 |

* LDAP와 SAML은 첫 로그인 시 같은 이메일을 가진 로컬 계정을 인수하고, 로그인할 때마다 해당 계정의 로컬 비밀번호를 제거합니다. 다른 이메일인 경우에는 새 계정을 만들고 로컬 계정은 그대로 둡니다.
* OIDC는 계정에 연결되며 비밀번호를 유지하므로, OIDC에 연결된 로컬 계정은 두 가지 방법 모두로 로그인할 수 있습니다. 연결은 설정 페이지의 **Link**로 하거나, 이메일이 일치하는 경우 첫 OIDC 로그인 시 이루어집니다. 연결에 대해서는 [OIDC 인증](/ko/on-premises/configuration/overleaf-toolkit/authentication/oidc-authentication)을 참조하세요.
* 관리자가 로컬 계정으로 생성한 계정에는 활성화 이메일이 발송됩니다. 계정을 활성화하면 이메일로 재설정할 때와 같은 방식으로 비밀번호가 설정됩니다.
* `EXTERNAL_AUTH=ldap saml oidc`처럼 여러 방법을 활성화해도 위 규칙은 동일합니다. 중요한 것은 계정의 로컬 비밀번호뿐입니다.
* 이메일로 재설정하려면 이메일 설정(`OVERLEAF_EMAIL_*`)이 필요합니다. 이메일 설정이 없으면 페이지에는 전송되었다고 표시되지만 이메일은 발송되지 않습니다. 이 경우 관리자가 **Admin → Manage Users**에서 비밀번호를 설정합니다.
* `OVERLEAF_DISABLE_LOCAL_LOGIN=true`는 이메일 및 비밀번호 로그인을 숨기지만 비밀번호는 유지합니다. 로그인을 다시 표시하면 비밀번호를 다시 사용할 수 있습니다.
* `EXTERNAL_AUTH`가 설정되어 있으면 방법과 관계없이 사용자는 설정 페이지에서 자신의 이메일을 변경할 수 없습니다. 이메일은 IdP가 관리하며, 사용자의 첫 OIDC 로그인 시 해당 사용자의 이메일을 가진 계정이 연결되기 때문입니다. 관리자는 **Admin → Manage Users**에서 이메일을 변경합니다.
* OIDC를 사용하는 인스턴스에서는 `true` 대신 `OVERLEAF_ALLOW_PUBLIC_REGISTRATION=@<domain>`을 사용하거나(활성화 이메일이 주소를 증명합니다) 공개 가입을 허용하지 마세요. `true`로 설정하면 동료가 처음 OIDC로 로그인하기 전에 누구나 동료의 이메일로 가입할 수 있으며, 이 경우 동료가 해당 계정에 연결됩니다.

### SSO 관련 제안

Overleaf에서 saml, ldap, oauth를 테스트해 보았습니다. saml과 oauth는 모두 Overleaf에서 잘 동작하지만, ldap은 상황에 따라 다릅니다. [https://docs.goauthentik.io/](https://docs.goauthentik.io/)에서는 잘 동작하지 않지만, openLDAP([https://github.com/rroemhild/docker-test-openldap](https://github.com/rroemhild/docker-test-openldap))에서는 잘 동작합니다.

<Info>

passport-ldapauth를 업데이트해야 합니다. 최근 [https://goauthentik.io/](https://goauthentik.io/)로 Overleaf LDAP을 테스트했을 때 실패했습니다. "passport-ldapauth"를 3.0.0으로 업데이트한 후에는 모든 것이 잘 동작했습니다.

```text
"passport-ldapauth": "^3.0.0",
```

원래 버전은 6년 전의 2.x.x입니다.

</Info>

원인은 확실하지 않습니다. LDAP(그리고 saml, oauth) 인증은 모두 외부 패키지에 의존하기 때문입니다. 동작하지 않는다면 Overleaf Server Pro에서도 같은 상황일 수 있습니다. 모든 환경 변수를 내부 패키지에 그대로 전달할 뿐이므로, 버그가 있더라도 현재로서는 알 수 없습니다.

**따라서 사용자분들께 전체 소스 코드로 SSO를 테스트할 수 있도록 개발 환경을 구성할 것을 적극 권장합니다.** 자세한 내용은 [개발 환경 설정(로컬)](/ko/dev/environment/setup-develop-environment-local  "mention")에서 확인할 수 있습니다. 개발 환경에서는 터미널에서 모든 로그를 볼 수 있어 디버깅에 편리합니다.
