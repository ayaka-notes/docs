계정이 없는 사람에게 Overleaf 인스턴스를 공개하는 방법은 세 가지입니다.

* [프로젝트 접근](/ko/on-premises/configuration/overleaf-toolkit/public-access#project-access  "mention"): 게스트가 로그인하지 않고 공유된 프로젝트 링크를 열 수 있도록 합니다
* [페이지 접근](/ko/on-premises/configuration/overleaf-toolkit/public-access#page-access  "mention"): 로그아웃한 방문자가 `/learn`, `/templates`, `/devs` 같은 페이지를 탐색할 수 있도록 합니다
* [공개 가입](/ko/on-premises/configuration/overleaf-toolkit/public-access#public-registration  "mention"): 사용자가 직접 가입할 수 있도록 하며, 선택적으로 활성화 이메일을 사용하고 특정 이메일 도메인으로 제한할 수 있습니다

### 프로젝트 접근

<Info>

기본적으로 사용자가 프로젝트 공유 링크를 얻더라도 공동 프로젝트 편집 세션에 참여하려면 먼저 **로그인**해야 합니다.

</Info>

링크로 공유된 프로젝트에 익명 접근을 허용하려면 아래 두 변수를 모두 설정합니다.

```dotenv title="config/variables.env"
OVERLEAF_ALLOW_ANONYMOUS_READ_AND_WRITE_SHARING=true
OVERLEAF_ALLOW_PUBLIC_ACCESS=true
```

`OVERLEAF_ALLOW_ANONYMOUS_READ_AND_WRITE_SHARING`은 링크로 공유된 프로젝트에서 익명 읽기/쓰기를 활성화합니다.

`OVERLEAF_ALLOW_PUBLIC_ACCESS`는 인증되지 않은 사용자가 로그인 페이지로 리디렉션되지 않도록 합니다.

`bin/up`으로 컨테이너를 다시 생성합니다. 그런 다음 시크릿 창에서 링크 공유 URL을 엽니다.

### 페이지 접근

기본적으로(`OVERLEAF_ALLOW_PUBLIC_ACCESS`가 설정되지 않은 경우) 로그인 및 가입 페이지를 제외한 **모든** 페이지는 로그아웃한 방문자를 로그인 페이지로 리디렉션합니다. 여기에는 공개용 페이지도 포함되므로, 해당 페이지 링크는 이미 로그인한 사용자에게만 동작합니다.

`OVERLEAF_ALLOW_PUBLIC_ACCESS=true`로 설정하면 로그아웃한 방문자도 다음 페이지를 열 수 있습니다.

| 페이지 | 필요 조건 |
| --------------------------------------------------------------------- | -------------------------------- |
| `/learn`의 LaTeX 도움말([adding-latex-user-help.md](/ko/on-premises/configuration/overleaf-toolkit/adding-latex-user-help  "mention") 참고) | `OVERLEAF_PROXY_LEARN=true`      |
| `/templates`의 템플릿 갤러리, 템플릿 페이지, 미리보기 및 ZIP 다운로드([templates.md](/ko/on-premises/configuration/overleaf-toolkit/templates  "mention") 참고) | `OVERLEAF_TEMPLATE_GALLERY=true` |
| `/devs`의 Overleaf Import API 페이지([overleaf-import-api.md](/ko/on-premises/configuration/overleaf-toolkit/overleaf-import-api  "mention") 참고) | —                                |

또한 [Overleaf Import API](/ko/on-premises/configuration/overleaf-toolkit/overleaf-import-api#signed-out-visitors  "mention")가 로그아웃한 방문자의 양식 제출 내용을 로그인할 때까지 보관할 수 있게 해 줍니다.

프로젝트 목록, 편집기, 프로젝트 생성(템플릿이나 Import API를 통한 생성 포함)에는 여전히 로그인이 필요합니다.

### 공개 가입

공개 가입은 [ayaka-notes/ayakaleaf-pro](https://github.com/ayaka-notes/ayakaleaf-pro)에서만 사용할 수 있습니다.

<Danger>

공개 가입을 활성화하면 Overleaf 인스턴스에 접근할 수 있는 **누구나** 사용자로 가입할 수 있다는 점에 유의하세요.

`true`로 설정하면 가입 과정에서 이메일 주소를 확인하지 않으므로, 인트라넷이나 신뢰할 수 있는 환경에서만 사용하거나 대신 [활성화 이메일을 통한 가입](/ko/on-premises/configuration/overleaf-toolkit/public-access#registration-with-activation-email)을 사용하세요.

OIDC를 사용하는 인스턴스에서는 `true`를 사용하지 마세요. 동료가 처음 OIDC로 로그인하기 전에 누구나 동료의 이메일로 가입할 수 있으며, 이 경우 동료가 해당 계정에 연결됩니다. [활성화 이메일을 통한 가입](/ko/on-premises/configuration/overleaf-toolkit/public-access#registration-with-activation-email)을 사용하거나 공개 가입을 허용하지 마세요. [계정 및 비밀번호](/ko/on-premises/configuration/overleaf-toolkit/authentication#accounts-and-passwords)를 참고하세요.

</Danger>

기본적으로 Community Edition과 Overleaf Pro 모두 공개 가입을 허용하지 않습니다.

활성화하려면 `config/variables.env`에 다음을 추가합니다.

```dotenv title="config/variables.env"
OVERLEAF_ALLOW_PUBLIC_REGISTRATION=true
```

`bin/up`으로 컨테이너를 다시 생성합니다.

그런 다음 **가입**을 클릭하거나 `/register`에 접속합니다.

### 활성화 이메일을 통한 가입

활성화 이메일을 통한 가입은 [ayaka-notes/ayakaleaf-pro](https://github.com/ayaka-notes/ayakaleaf-pro)에서만 사용할 수 있습니다. 사용자는 이메일만으로 가입하고 활성화 이메일의 링크를 통해 비밀번호를 설정하므로, 해당 주소의 소유자만 계정을 사용할 수 있습니다. 도메인 목록과 와일드카드를 사용하려면 v6.4.0 이상이 필요하며, 이전 버전에서는 `@example.com`처럼 도메인 하나만 지정할 수 있습니다.

이 기능을 활성화하기 전에 이메일 전송을 구성하세요. 그렇지 않으면 사용자가 활성화 이메일을 받을 수 없습니다. [이메일 전송](/ko/on-premises/configuration/overleaf-toolkit/email-delivery)을 참고하세요.

그런 다음 `config/variables.env`에 다음 줄을 추가합니다.

```dotenv title="config/variables.env" wrap
OVERLEAF_ALLOW_PUBLIC_REGISTRATION=@example.com,@*.example.org
```

`OVERLEAF_ALLOW_PUBLIC_REGISTRATION`은 다음 값으로 설정할 수 있습니다.

| 값                         | 가입할 수 있는 사용자                                       | 이메일 확인 |
| ----------------------------- | ----------------------------------------------------- | :------------: |
| `true`                        | 이메일과 비밀번호로 누구나                       |       아니요       |
| `@example.com`                | `example.com`의 주소                             |      예       |
| `@*.example.org`              | `cs.example.org`와 같은 하위 도메인의 주소(`example.org` 자체는 제외) |      예       |
| `@example.com,@*.example.org` | 쉼표로 구분된 항목 중 하나에 해당하는 주소         |      예       |
| `@*`                          | 누구나                                                 |      예       |

도메인은 대소문자를 구분하지 않고 일치시킵니다. 도메인과 그 하위 도메인을 모두 허용하려면 `@example.org,@*.example.org`처럼 둘 다 나열하세요.

### Q\&A

<Accordion title="로그인하지 않은 편집자는 댓글로 무엇을 할 수 있나요?">

<strong>답변:</strong> 편집 링크를 통해 프로젝트를 연 로그인하지 않은 사용자는 편집자와 같은 접근 권한을 갖습니다. 단, 누가 수행했는지를 기록하는 작업은 제외됩니다:

| 작업                                              | 로그인하지 않은 편집자 |
| ------------------------------------------------- | ---------------------: |
| 텍스트 편집, 댓글 및 추적된 변경 내용 보기         |                     예 |
| 추적된 변경 내용 수락, 편집 모드 전환              |                     예 |
| 댓글 또는 전체 스레드 삭제                         |                     예 |
| 댓글 추가, 답글 또는 편집                          |                 아니요 |
| 댓글 해결 또는 다시 열기                           |                 아니요 |

검토 패널에는 여전히 **Resolve** 버튼이 표시되지만, 해결하려고 하면 오류 메시지와 함께 실패합니다.

보기 링크를 통해 프로젝트를 연 사용자에게는 댓글이 전혀 표시되지 않습니다. [역할 및 권한](/ko/on-premises/user-and-project-management/roles-and-permissions#collaborating)을 참고하세요.

</Accordion>
