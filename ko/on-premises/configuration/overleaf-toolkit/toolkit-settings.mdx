이 페이지에서는 Toolkit 배포의 `config/overleaf.rc` 파일에서 지원되는 환경 변수를 설명합니다.

`config/overleaf.rc` 파일은 `NAME=value` 형식의 변수 정의로 구성됩니다. `#`으로 시작하는 줄은 주석으로 처리됩니다.

<Info>

`overleaf.rc` 또는 `variables.env`에서 무엇이든 변경한 후에는 `bin/up`을 실행하여 Docker 컨테이너를 다시 생성해야 합니다.

</Info>

## 컨테이너

### `sharelatex`

| 이름 | 설명 |
| ---------------------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| `PROJECT_NAME` | <p>`docker-compose`에 전달되는 `--project-name` 플래그의 값을 설정합니다. 한 호스트에서 여러 Overleaf 인스턴스를 실행할 때 각 인스턴스에 다른 프로젝트 이름을 지정할 수 있어 유용합니다.<br /><br />- <strong>기본값</strong>: `overleaf`</p> |
| `OVERLEAF_IMAGE_NAME` | <p>Server Pro/CE 애플리케이션 컨테이너에서 사용하는 Docker 이미지입니다. Docker 이미지 이름만 지정하며, Docker 이미지 태그는 `config/version`에서 가져옵니다.<br /><br />- <strong>기본값:</strong><br />- Server Pro: `quay.io/sharelatex/sharelatex-pro`<br />- Community Edition: `sharelatex/sharelatex`</p> |
| `SERVER_PRO` | <p>`true`로 설정하면 Toolkit이 기본 Server CE 이미지(`sharelatex/sharelatex`) 대신 Server Pro 이미지(`quay.io/sharelatex/sharelatex-pro`)를 사용합니다.<br /><br />- <strong>기본값</strong>: `false`</p> |
| `GIT_BRIDGE_ENABLED` | <p>git-bridge 기능을 활성화하려면 `true`로 설정합니다(Server Pro 전용). 자세한 내용은 <a href="https://www.overleaf.com/learn/how-to/Git_integration">https://www.overleaf.com/learn/how-to/Git_integration</a> 사용자 문서를 참고하세요.<br /><br />- <strong>기본값:</strong> `false`</p> |
| `GIT_BRIDGE_IMAGE` | <p>git-bridge 컨테이너에서 사용하는 Docker 이미지입니다(Server Pro 전용). Docker 이미지 이름만 지정하며, Docker 이미지 태그는 `config/version`에서 가져옵니다.<br /><br />- <strong>기본값:</strong> `quay.io/sharelatex/git-bridge`</p> |
| `GIT_BRIDGE_DATA_PATH` | `git-bridge` 컨테이너(Server Pro 전용)에 마운트되어 git 저장소를 저장하는 데 사용되는 디렉터리 경로를 설정합니다. 전체 경로(`/`로 시작) 또는 Toolkit 기본 디렉터리에 대한 상대 경로를 사용할 수 있습니다. |
| `GIT_BRIDGE_LOG_LEVEL` | <p>`git-bridge` 컨테이너의 로깅 수준을 구성합니다. 사용 가능한 수준: `TRACE`, `DEBUG`, `INFO`, `WARN`, `ERROR`.<br /><br />- <strong>기본값:</strong> `INFO`</p> |
| `SIBLING_CONTAINERS_ENABLED` | <p>`true`로 설정하면 Toolkit이 <strong>Sibling Containers</strong> 기법을 사용하여 각 프로젝트마다 별도의 Docker 컨테이너를 사용하는 개별 샌드박스에서 프로젝트를 컴파일합니다. 자세한 내용은 &#x3C;server-pro-only-configuration/sandboxed-compiles> 문서를 참고하세요.<br /><br />- <strong>필요 조건:</strong> `SERVER_PRO=true`<br />- <strong>기본값:</strong> `true`</p> |
| `SIBLING_CONTAINERS_PULL` | <p>`true`로 설정하면 `bin/up` 명령을 사용할 때 Toolkit이 <strong>config/variables.env</strong> 파일의 `ALL_TEX_LIVE_DOCKER_IMAGES`로 설정된 모든 TeX Live 이미지를 자동으로 가져옵니다.<br /><br />- <strong>기본값:</strong> `true`</p> |
| `DOCKER_SOCKET_PATH` | <p>호스트 머신(Toolkit을 실행하는 머신)의 Docker 소켓 경로를 설정합니다. `SIBLING_CONTAINERS_ENABLED`가 `true`이면 컴파일러 서비스가 호스트에서 새 Docker 컨테이너를 생성할 수 있도록 소켓이 컨테이너에 마운트됩니다.<br /><br />- <strong>필요 조건:</strong> `SIBLING_CONTAINERS_ENABLED=true`<br />- <strong>기본값:</strong> `/var/run/docker.sock`</p> |
| `OVERLEAF_DATA_PATH` | <p>메인 `sharelatex` 컨테이너에 마운트되어 컴파일 데이터를 저장하는 데 사용되는 디렉터리 경로를 설정합니다. 전체 경로(`/`로 시작) 또는 Toolkit 기본 디렉터리에 대한 상대 경로를 사용할 수 있습니다.<br /><br />- <strong>기본값:</strong> `data/overleaf`</p> |
| `OVERLEAF_LISTEN_IP` | <p>컨테이너가 바인딩할 호스트 IP 주소를 설정합니다. 예를 들어 `0.0.0.0`으로 설정하면 모든 호스트 IP 주소에서 웹 인터페이스를 사용할 수 있습니다. 컨테이너에 직접 접근하려면 `OVERLEAF_LISTEN_IP` 값을 공인 IP 주소로 설정해야 합니다. `OVERLEAF_LISTEN_IP`를 `0.0.0.0` 또는 호스트의 외부 IP로 설정하면 와 함께 사용할 때 일반적으로 오류가 발생합니다.<br /><br />- <strong>기본값:</strong> `127.0.0.1`</p> |
| `OVERLEAF_PORT` | <p>컨테이너가 바인딩할 호스트 포트를 설정합니다. 예를 들어 이 값을 `8099`로, `OVERLEAF_LISTEN_IP`를 `127.0.0.1`로 설정하면 `http://localhost:8099`에서 웹 인터페이스를 사용할 수 있습니다.<br /><br />- <strong>기본값:</strong> `80`</p> |
| `OVERLEAF_LOG_PATH` | <p>메인 `sharelatex` 컨테이너에 마운트되어 Docker 호스트에서 애플리케이션 로그를 사용할 수 있도록 하는 디렉터리 경로를 설정합니다. 전체 경로(`/`로 시작) 또는 Toolkit 기본 디렉터리에 대한 상대 경로를 사용할 수 있습니다. 바인드 마운트를 비활성화하려면 이 구성 항목을 제거하세요. 설정하지 않으면 컨테이너를 다시 생성할 때 로그가 삭제됩니다.<br /><br />로깅에 대한 정보는 를 참고하세요.<br /><br />- <strong>기본값:</strong> 설정 안 됨</p> |

### `mongo`

| 이름 | 설명 |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| `MONGO_ENABLED` | <p>`true`로 설정하면 Toolkit이 데이터베이스를 호스팅할 MongoDB 컨테이너를 생성합니다. `false`로 설정하면 이 컨테이너가 생성되지 않으며, 대신 `MONGO_URL`로 지정된 MongoDB 데이터베이스를 사용합니다.<br /><br />- <strong>기본값</strong>: `true`</p> |
| `MONGO_URL` | <p>`MONGO_ENABLED`가 `false`일 때 사용할 MongoDB 연결 URL을 지정합니다.<br /><br />- <strong>기본값</strong>: 설정 안 됨</p> |
| `MONGO_DATA_PATH` | <p>`mongo` 컨테이너에 마운트되어 MongoDB 데이터베이스를 저장하는 데 사용되는 디렉터리 경로를 설정합니다. 전체 경로(`/`로 시작) 또는 toolkit 기본 디렉터리에 대한 상대 경로를 사용할 수 있습니다. 이 옵션은 `MONGO_ENABLED`가 `true`일 때 생성되는 로컬 `mongo` 컨테이너에만 영향을 줍니다.<br /><br />- <strong>기본값</strong>: `data/mongo`</p> |
| `MONGO_IMAGE` | <p>MongoDB 컨테이너에서 사용하는 Docker 이미지입니다. Docker 이미지 이름만 지정하며, Docker 이미지 태그는 `MONGO_VERSION`(아래 참고)에 지정해야 합니다.<br /><br />- <strong>기본값:</strong> `mongo`</p> |
| `MONGO_VERSION` | <p>MongoDB 컨테이너에서 사용하는 MongoDB 버전입니다. 값은 MongoDB 메이저 버전과 점으로 시작해야 합니다. 예: `6.0` 또는 `6.0-with-suffix`.<br /><br />- <strong>기본값:</strong> `6.0`</p> |

***

### `redis`

| 이름 | 설명 |
| ----------------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| `REDIS_ENABLED` | <p>`true`로 설정하면 Toolkit이 redis 데이터베이스를 호스팅할 Redis 컨테이너를 생성합니다. `false`로 설정하면 이 컨테이너가 생성되지 않으며, 대신 `REDIS_HOST`와 `REDIS_PORT`로 지정된 Redis 데이터베이스를 사용합니다.<br /><br />- <strong>기본값</strong>: `true`</p> |
| `REDIS_HOST` | <p>`REDIS_ENABLED`가 `false`일 때 사용할 Redis 호스트를 지정합니다.<br /><br />- <strong>기본값</strong>: 설정 안 됨</p> |
| `REDIS_PORT` | <p>`REDIS_ENABLED`가 `false`일 때 사용할 Redis 포트를 지정합니다.<br /><br />- <strong>기본값</strong>: 설정 안 됨</p> |
| `REDIS_DATA_PATH` | <p>`redis` 컨테이너에 마운트되어 Redis 데이터베이스를 저장하는 데 사용되는 디렉터리 경로를 설정합니다. 전체 경로(`/`로 시작) 또는 Toolkit 기본 디렉터리에 대한 상대 경로를 사용할 수 있습니다. 이 옵션은 `REDIS_ENABLED`가 `true`일 때 생성되는 로컬 `redis` 컨테이너에만 영향을 줍니다.<br /><br />- <strong>기본값</strong>: `data/redis`</p> |
| `REDIS_AOF_PERSISTENCE` | <p>Redis의 AOF(Append Only File) 영속성을 켭니다. Redis 영속성에 <strong>권장되는</strong> 구성입니다.<br /><br />자세한 내용은 &#x3C;../../maintenance/data-and-backups>의 &#x3C;../../../maintenance/data-and-backups#aof-append-only-file> 섹션을 참고하세요.<br /><br />- <strong>기본값:</strong> `true`</p> |

### `nginx`

| 이름 | 설명 |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| `NGINX_ENABLED` | <p>`true`로 설정하면 Toolkit이 TLS 프록시 역할을 할 NGINX 컨테이너를 생성합니다.<br /><br />- <strong>기본값</strong>: `false`</p> |
| `NGINX_CONFIG_PATH` | <p>TLS 프록시에 사용할 NGINX 구성 파일의 경로입니다.<br /><br />- <strong>기본값</strong>: `config/nginx/nginx.conf`</p> |
| `NGINX_TLS_LISTEN_IP` | <p>TLS 프록시 컨테이너가 HTTPS용으로 바인딩할 호스트 IP 주소를 설정합니다. 예를 들어 `0.0.0.0`으로 설정하면 모든 호스트 IP 주소에서 HTTPS 웹 인터페이스를 사용할 수 있습니다. 일반적으로 호스트의 외부 IP로 설정해야 합니다.<br /><br />- <strong>기본값</strong>: `127.0.1.1`</p> |
| `NGINX_HTTP_LISTEN_IP` | <p>TLS 프록시 컨테이너가 HTTP 리디렉션용으로 바인딩할 호스트 IP 주소를 설정합니다. 예를 들어 `127.0.1.1`로 설정하면 `127.0.1.1`로의 HTTP 연결이 HTTPS 웹 인터페이스로 리디렉션됩니다. 일반적으로 호스트의 외부 IP로 설정해야 합니다. `0.0.0.0`으로 설정하면 일반적으로 `OVERLEAF_LISTEN_IP`와 충돌이 발생하므로 그렇게 설정하지 마세요.<br /><br />- <strong>기본값</strong>: `127.0.1.1`</p> |
| `NGINX_HTTP_PORT` | <p>TLS 프록시 컨테이너가 HTTP용으로 바인딩할 호스트 포트를 설정합니다.<br /><br />- <strong>기본값</strong>: `80`</p> |
| `TLS_PORT` | <p>TLS 프록시 컨테이너가 HTTPS용으로 바인딩할 호스트 포트를 설정합니다.<br /><br />- <strong>기본값</strong>: `443`</p> |
| `TLS_PRIVATE_KEY_PATH` | <p>TLS 프록시에 사용할 개인 키의 경로입니다.<br /><br />- <strong>기본값</strong>: `config/nginx/certs/overleaf_key.pem`</p> |
| `TLS_CERTIFICATE_PATH` | <p>TLS 프록시에 사용할 공개 인증서의 경로입니다.<br /><br />- <strong>기본값</strong>: `config/nginx/certs/overleaf_certificate.pem`</p> |
