각 프로젝트에는 MCP 서버가 있어 Claude Code, Codex, Cursor, VS Code, Gemini CLI 같은 AI 클라이언트가 프로젝트에서 작업할 수 있습니다. 파일을 읽고 편집하고, 컴파일하고, LaTeX 로그를 읽고, PDF를 다운로드하고, 댓글에 답할 수 있습니다. v6.3.3부터는 기록을 살펴보고 버전을 복원하고, 변경 내용 추적을 검토하고, 댓글을 추가하고, 프로젝트 채팅을 사용하고, 파일을 이동할 수도 있습니다.

<Info>

이 기능은 [ayaka-notes/ayakaleaf-pro](https://github.com/ayaka-notes/ayakaleaf-pro)에서 개발했습니다. v6.3.1 이상부터 도입되었습니다. 기록, 변경 내용 추적, 프로젝트 채팅, 새 댓글, 파일 이동 도구는 v6.3.3 이상에서 사용할 수 있습니다. [v6.3.3의 새로운 기능](/on-premises/user-guide/users/mcp-server#new-in-v6.3.3)을 참고하세요.

</Info>

### 설정 {#setup}

MCP 서버는 Git 연동과 함께 제공됩니다. [git-bridge](/ko/on-premises/configuration/overleaf-toolkit/integrations/git-integration)를 활성화하면 MCP 서버도 사용할 수 있습니다. 그 외에 구성할 것은 없습니다.

### AI 클라이언트 연결 {#connect-an-ai-client}

1. **Account Settings**에서 Git 인증 토큰을 생성하세요. 같은 토큰이 MCP 서버와 Git에 사용됩니다.
2. 편집기에서 **Integrations**를 열고 **MCP server**를 클릭하세요. 프로젝트 MCP 서버의 주소 `https://<your-overleaf>/project/<project_id>/mcp`와 각 AI 클라이언트에 추가하는 방법이 표시됩니다. 명령을 복사한 다음 `<token>`을 자신의 토큰으로 바꾸세요.

토큰은 HTTP 헤더 `Authorization: Bearer <token>`으로 전송됩니다. 예를 들어 Claude Code용 명령은 다음과 같습니다.

```bash
claude mcp add --transport http overleaf \
  https://<your-overleaf>/project/<project_id>/mcp \
  --header "Authorization: Bearer <token>"
```

### 사용법 {#usage}

연결되면 AI 클라이언트에 일상적인 말로 요청하세요. 예:

| 요청 내용 | AI 클라이언트가 사용하는 도구 |
| --- | --- |
| _서론의 오타를 수정해 줘._ | `read_file`, `edit_file`: 수정 사항이 편집기에 실시간으로 표시됩니다 |
| _프로젝트를 컴파일하고 LaTeX 오류를 수정해 줘._ | `compile`, `get_compile_log`, `edit_file` |
| _열린 댓글에 답한 다음 해결해 줘._ | `list_comments`, `reply_to_comment`, `resolve_comment` |
| _XeLaTeX로 전환하고 PDF를 다운로드해 줘._ | `update_settings`, `compile`, `get_output_file_link` |
| _초록을 변경 내용 추적으로 다시 써 줘._ | `read_file`, `trackChanges`를 사용한 `edit_file` (v6.3.3) |
| _제출한 버전 이후 무엇이 바뀌었어?_ | `list_versions`, `list_changes`, `diff` (v6.3.3) |
| _챕터들을 chapters라는 폴더로 옮겨 줘._ | `move_file` (v6.3.3) |

### 도구 {#tools}

| 그룹 | 도구 |
| --- | --- |
| 프로젝트 | `get_clone_info`, `get_settings`, `update_settings` |
| 파일 | `list_files`, `read_file`, `edit_file`, `write_file`, `delete_file`, `move_file`, `create_folder` |
| 컴파일 | `compile`, `get_compile_log`, `get_output_file_link`, `word_count` |
| 댓글 | `list_comments`, `reply_to_comment`, `resolve_comment`, `reopen_comment`, `add_comment`, `edit_comment_message`, `delete_comment_message` |
| 변경 내용 추적 | `list_tracked_changes`, `accept_tracked_changes`, `reject_tracked_changes` |
| 기록 | `list_versions`, `list_changes`, `diff`, `create_version`, `delete_version`, `restore_file`, `restore_project` |
| 채팅 | `list_chat_messages`, `send_chat_message` |

v6.3.3에는 33개의 도구가 있으며, 채팅 도구를 제거하는 `OVERLEAF_DISABLE_CHAT=true`를 설정하면 31개입니다. v6.3.1과 v6.3.2에는 나머지 17개가 있습니다. 위의 모든 도구 중 `move_file`, `create_folder`, `add_comment`, `edit_comment_message`, `delete_comment_message`, 변경 내용 추적 도구, 채팅 도구, `list_versions` 이외의 기록 도구를 뺀 것입니다. v6.3.3에서 `read_file`은 기록의 특정 버전에서 파일을 읽을 수도 있고, `edit_file`과 `write_file`은 `trackChanges`를 받으며, `update_settings`는 맞춤법 검사 언어도 설정합니다.

`edit_file`, `write_file`, `move_file`로 한 편집은 편집기에 실시간으로 표시되고 공동 작업자의 편집과 병합됩니다. 여러 파일을 한 번에 다루거나 바이너리 파일의 경우, AI 클라이언트가 Git으로 프로젝트를 클론하여 푸시할 수도 있습니다.

`trackChanges`를 사용하면 기존 파일의 편집은 프로젝트에서 변경 내용 추적이 꺼져 있어도 토큰 사용자의 추적된 변경이 됩니다. 새 파일은 절대 추적된 변경이 되지 않습니다. `trackChanges`가 없으면 편집은 프로젝트의 변경 내용 추적 설정을 따릅니다.

### 권한 {#permissions}

MCP 서버는 Git과 마찬가지로 프로젝트의 공유 설정을 따릅니다.

* 프로젝트를 볼 수 있는 모든 사람은 프로젝트를 읽고, 컴파일하고, 출력물을 다운로드할 수 있습니다.
* 소유자와 편집자만 파일과 설정을 변경하고, 버전을 복원하고, 추적된 변경을 수락하거나 거부할 수 있습니다.
* 검토자는 댓글을 추가하고 답글을 달 수 있으며, 자신이 시작한 댓글을 해결, 다시 열기 또는 삭제하고, 버전을 저장할 수도 있습니다. 파일은 편집할 수 없으며, 추적된 변경으로도 편집할 수 없습니다.
* 모든 사람은 자신의 댓글 메시지만 편집하고, 검토자는 자신의 메시지만 삭제합니다.
* 다른 사람이 저장한 버전은 소유자만 삭제합니다.
* 링크로 참여한 뷰어는 편집기에서와 마찬가지로 댓글, 추적된 변경, 기록, 채팅을 볼 수 없습니다. 초대된 뷰어는 이를 볼 수 있고 채팅을 사용할 수 있습니다.
* 프로젝트 소유자에게 **Full project history**가 없으면 기록 도구는 기록 패널처럼 최근 24시간의 변경만 표시합니다. 관리자는 모두 볼 수 있습니다.

사용자 가이드에 각 역할이 할 수 있는 일을 정리한 표가 있습니다. [누가 무엇을 할 수 있는지](/on-premises/user-guide/users/mcp-server#who-may-do-what)를 참고하세요.

### Q\&A {#q&a}

<Accordion title="편집기에 Integrations 또는 MCP server가 보이지 않습니다">

<strong>답변:</strong> MCP 서버에는 자체 환경 변수가 없습니다. `config/overleaf.rc`의 `GIT_BRIDGE_ENABLED=true`로 활성화됩니다. [Git 연동](/ko/on-premises/configuration/overleaf-toolkit/integrations/git-integration)을 참고하세요. 값을 변경한 후에는 `bin/up -d`를 실행하세요. git-bridge가 없으면 편집기의 왼쪽 레일에 **Integrations** 탭이 표시되지 않습니다.

</Accordion>

<Accordion title="AI 클라이언트가 “Track changes is off for this project”라고 표시합니다">

<strong>답변:</strong> 클라이언트가 추적된 변경을 요청했지만 프로젝트 소유자의 계정에 변경 내용 추적 기능이 없습니다. **Admin**, **Manage Users**를 차례로 클릭하고 소유자를 연 다음 **Features** 탭에서 **Track changes**를 켜세요. [Features](/ko/on-premises/user-guide/administrators/user-management#features)를 참고하세요. `trackChanges`가 없는 편집은 계속 작동합니다.

</Accordion>

<Accordion title="AI 클라이언트에 최근 24시간의 변경만 보입니다">

<strong>답변:</strong> 프로젝트 소유자의 계정에 전체 프로젝트 기록이 없으므로 기록 도구는 기록 패널과 같은 내용, 즉 최근 24시간의 변경만 표시합니다. **Admin**, **Manage Users**를 차례로 클릭하고 소유자를 연 다음 **Features** 탭에서 **Full project history**를 켜세요. [Features](/ko/on-premises/user-guide/administrators/user-management#features)를 참고하세요.

</Accordion>
