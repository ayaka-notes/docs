<Info>

이 기능은 [ayaka-notes/ayakaleaf-pro](https://github.com/ayaka-notes/overleaf-pro)에서 OAuth 2.0 지원과 함께 제공되며, v6.3.0부터 사용할 수 있습니다. 문제가 발생하면 언제든지 피드백을 보내 주세요.

</Info>

#### Mendeley 연동 설정

1. [이 링크](https://dev.mendeley.com/myapps.html)로 이동하여 Mendeley OAuth 애플리케이션을 등록합니다
2. **Redirect URL**을 다음과 같이 구성합니다: `${OVERLEAF_SITE_URL}/user/mendeley/oauth/callback`
3. 생성된 애플리케이션의 **ID**(아래와 같이 보통 `24061` 같은 숫자)와 **Secret**을 기록해 둡니다
4. `config/variables.env`를 수정합니다&#x20;
5. Authorisation Flow는 Elsevier로 그대로 둡니다(권장)

```dotenv title="config/variables.env"
#################
#   Mendeley    #
#################
# 'mendeley' must be in ENABLED_LINKED_FILE_TYPES (keep 'zotero' too if you use both)
ENABLED_LINKED_FILE_TYPES=project_file,project_output_file,url,mendeley

# From a Mendeley OAuth application (register at https://dev.mendeley.com/myapps.html)
# Redirect URL -> ${OVERLEAF_SITE_URL}/user/mendeley/oauth/callback
MENDELEY_CLIENT_ID=
MENDELEY_CLIENT_SECRET=
# Encrypts the Mendeley OAuth tokens in mongo; if unset, a key file is generated
# in /var/lib/overleaf/data on first use
# How to generate: `openssl rand -hex 32`
MENDELEY_CIPHER_PASSWORD=
# Optional: route the module's server-side Mendeley requests (OAuth + API) through
# an HTTP proxy (must be reachable from the web container; same as github-sync)
# http://10.0.0.1:10808
# (Optional) MENDELEY_PROXY_URL=
```

<Info>

&#x20;`ENABLED_LINKED_FILE_TYPES`에는 `mendeley`가 반드시 포함되어야 합니다(둘 다 사용한다면 `zotero`도 목록에 유지하세요). `MENDELEY_CLIENT_ID`와 `MENDELEY_CLIENT_SECRET`은 등록한 OAuth 애플리케이션에서 가져옵니다. cipher password는 MongoDB에 저장되는 Mendeley OAuth 토큰을 암호화합니다(`openssl rand -hex 32`로 생성). 설정하지 않으면 처음 사용할 때 데이터 볼륨에 키 파일이 생성됩니다. 선택적으로 `MENDELEY_PROXY_URL`을 설정하면 서버 측 Mendeley 요청(OAuth + API)을 web 컨테이너에서 접근 가능한 HTTP 프록시를 통해 라우팅할 수 있습니다.

</Info>

### 참고 사항

<Warning>

Mendeley 연결 참고 문헌 파일이 있는 기존 설치를 재배포된 6.3.0으로 업그레이드할 때는 [Zotero / Mendeley 마이그레이션 안내](/ko/on-premises/release-notes/release-notes-6.x.x#ayakaleaf-pro-6.3.0  "mention")를 따르세요. 새로 설치하는 경우에는 이 마이그레이션이 필요하지 않습니다.

</Warning>

<Danger>

Ayakaleaf는 협업 플랫폼이므로 보안 강화를 위해 버전 6.3.0부터는 참고 문헌 `bib` 파일을 처음 만든 사용자만 가져온 파일을 업데이트할 수 있습니다.

</Danger>

예를 들어 프로젝트 소유자인 사용자 A가 링크 공유를 활성화하고 프로젝트에 `test.bib` 파일을 만들어 자신의 Zotero 계정에 연결했다고 가정해 보겠습니다. 다른 사용자 B가 공유 링크를 통해 프로젝트에 접근하면, 사용자 B는 `test.bib`를 읽고 다운로드할 수는 있지만 Zotero에서 파일을 업데이트하거나 다시 가져올 수는 없습니다. 참고 문헌 파일을 처음 만든 사용자 A만 업데이트를 수행할 수 있습니다. 즉, `.bib` 파일을 처음 만든 사용자만 해당 파일을 업데이트할 권한을 가집니다.
