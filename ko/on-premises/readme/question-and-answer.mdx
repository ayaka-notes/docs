Ayakaleaf Pro에 관해 자주 묻는 질문에 대한 답변을 모았습니다.

### 기본 질문

<Accordion title="Q01: Ayakaleaf Pro는 무료 체험판인가요? 라이선스가 필요한가요?">

아니요. Ayakaleaf Pro는 완전히 무료로 사용할 수 있습니다. 체험판이 아니며 라이선스도 필요하지 않습니다.

</Accordion>

<Accordion title="Q02: Ayakaleaf Pro에는 Overleaf Server Pro의 모든 기능이 포함되어 있나요?">

네. Ayakaleaf Pro에는 Git-Bridge 통합을 포함한 Overleaf Server Pro의 모든 기능이 포함되어 있습니다. 또한 Overleaf SaaS 플랫폼의 일부 기능도 포함되어 있습니다. 저희는 Ayakaleaf Pro를 계속 개발하고 개선하고 있습니다.

</Accordion>

<Accordion title="Q03: Overleaf Server Pro의 비용은 얼마인가요?">

Overleaf Server Pro는 사용자당 연간 약 \$300입니다. 최소 10개의 라이선스가 필요하므로 배포 비용은 연간 약 \$3,000부터 시작합니다. 미국의 소규모 공공 계약에서는 사용자당 연간 약 \$320–\$370의 비용이 나타납니다. 따라서 Server Pro는 특히 소규모 팀에게 비쌉니다. 문서화된 구매 사례와 가격은 [#information-and-price-about-overleaf-server-pro](/ko/on-premises#information-and-price-about-overleaf-server-pro  "mention")를 참조하세요.

</Accordion>

<Accordion title="Q04: Overleaf Server Pro에 GitHub Sync나 AI 기능이 포함되지 않은 이유는 무엇인가요?">

Overleaf Server Pro는 정부 기관에서 흔히 사용됩니다. 이들은 사설 네트워크에 배포하고 접근을 엄격히 통제합니다. 민감한 데이터를 보호하기 위해 포함된 기능은 제3자 서비스와 데이터를 주고받지 않습니다. GitHub Sync, AI 또는 이와 유사한 연결 기능이 필요하다면 Overleaf는 SaaS 플랫폼 구독을 권장합니다.

</Accordion>

<Accordion title="Q05: Ayakaleaf Pro는 안전하고 신뢰할 수 있나요?">

Ayakaleaf Pro는 오픈 소스입니다. 저희는 Codex Security 같은 도구로 코드를 검토하여 보안과 신뢰성을 강화합니다. 제3자 데이터 동기화를 활성화하지 않으면 데이터는 사용자의 서버에 그대로 남습니다. Ayakaleaf Pro에는 데이터를 외부로 전송하는 텔레메트리가 없습니다.

</Accordion>

<Accordion title="Q06: Ayakaleaf Pro는 장기적으로 유지 관리되나요?">

저희는 이 프로젝트를 장기적으로 유지 관리하기 위해 최선을 다할 것입니다.

</Accordion>

<Accordion title="Q07: Ayakaleaf Pro는 라이선스를 준수하나요?">

Ayakaleaf Pro는 커뮤니티 포크입니다. 코드와 통합된 기능은 커뮤니티 기여에서 비롯되었습니다. AGPL v3 라이선스로 배포됩니다. 배포 환경이 이 라이선스의 요구 사항을 충족하면 라이선스를 준수할 수 있습니다.

</Accordion>

<Accordion title="Q08: 프로젝트 이름이 Ayakaleaf Pro인 이유는 무엇인가요?">

이 프로젝트는 원래 2024년에 Overleaf Pro라는 이름이었습니다. 한동안 개발이 중단되었다가 2025년 말에 재개되었습니다. 2026년 1분기에 Overleaf는 AI 기능이 포함된 구독 플랜의 이름을 Pro로 변경했습니다. 커뮤니티 피드백에서도 Overleaf Pro라는 이름이 상표 및 사칭 위험을 초래할 수 있다는 지적이 있었습니다. 사용자가 이 프로젝트를 공식 프로젝트로 오해할 수도 있었습니다.

이러한 혼동을 피하기 위해 프로젝트 이름을 Ayakaleaf Pro로 변경했습니다. 이 이름은 "Ayaka-notes Overleaf Pro"로 읽을 수 있습니다. 메인테이너(ayaka라고 불러 주세요!)는 5년 이상 전인 학생 시절부터 Overleaf 커뮤니티 개발에 기여해 왔습니다. 이러한 경험이 장기적인 유지 관리 약속을 뒷받침합니다.

</Accordion>

<Accordion title="Q09: Ayakaleaf Pro는 최근 AI로 만들어진 LaTeX 에디터들과 무엇이 다른가요?">

2026년부터 오픈 소스 커뮤니티에서는 OpenAI Prism을 비롯해 AI로 만들어진 많은 LaTeX 에디터가 출시되었습니다. Ayakaleaf Pro는 데이터와 서비스를 사용자 자신의 서버에 유지합니다. 따라서 배포와 데이터를 직접 제어할 수 있습니다.

많은 실험적인 커뮤니티 에디터는 확립된 장기 유지 관리 계획이 없습니다. 제3자 LaTeX 컴파일 플랫폼도 사용자 기반이나 수익이 부족하면 운영을 중단할 수 있습니다. Ayakaleaf Pro는 모든 소스 코드를 제공하며 모든 서비스를 셀프 호스팅할 수 있게 해 줍니다. 유지 관리가 중단되더라도 기존 셀프 호스팅 서비스는 계속 실행될 수 있습니다.

</Accordion>

### 기능

<Accordion title="Q01: Ayakaleaf Pro는 어떤 기능을 제공하나요? 새 기능을 요청할 수 있나요?">

현재 기능 목록은 문서를 확인해 주세요. 추가되기를 원하는 기능이 있다면 GitHub에 이슈(기능 요청)를 자유롭게 열어 주세요. 요청된 기능을 구현하기 위해 최선을 다하겠지만, 개발에는 시간이 걸리며 모든 기능을 즉시 제공한다고 보장할 수는 없습니다.

</Accordion>

<Accordion title="Q02: 몇 가지 기능을 직접 개발했습니다. PR을 제출할 수 있나요? 반드시 수락되나요?">

기여는 언제나 환영하지만 수락이 보장되지는 않습니다. 저희는 각 PR이 기반이 되는 Overleaf 코드베이스에 미치는 영향, 유지 관리 부담, 사용자에게 제공하는 가치를 기준으로 평가합니다. 가치 있는 기여는 병합하고 유지 관리하기 위해 최선을 다하겠습니다.

다만 과도한 변경을 도입하는 PR, 검토되지 않았거나 충분히 이해되지 않은 AI 생성 코드("바이브 코딩")로 이루어진 PR, 장기적으로 유지 관리하기 어려운 기능을 추가하는 PR은 거절할 수 있습니다.

</Accordion>

<Accordion title="Q03: 특정 기능은 어떻게 구성하나요?">

저희는 일반적으로 새 기능을 출시할 때마다 문서를 업데이트합니다. 자세한 설정 방법과 사용 가능한 환경 변수에 대한 설명은 관련 문서를 참조하세요.

</Accordion>

<Accordion title="Q04: Python Runner에서 사용할 수 있는 Python 라이브러리는 무엇인가요?">

Python Runner는 서버가 아니라 사용자의 브라우저에서 [Pyodide](https://pyodide.org/) 0.29.3으로 Python을 실행합니다. 코드에서 import하는 패키지는 NumPy, pandas, Matplotlib 등 [Pyodide에 내장된 패키지](https://pyodide.org/en/0.29.3/usage/packages-in-pyodide.html)에서 불러옵니다. `pip`로 설치한 패키지나 그 밖의 패키지는 사용할 수 없습니다. 서버에서 구성할 것은 없습니다.

</Accordion>

<Accordion title="Q05: 맞춤법 검사로 일본어나 중국어를 검사할 수 있나요?">

아니요. 맞춤법 검사기에는 일본어나 중국어 사전이 없으므로 이 언어들은 맞춤법 검사 언어 목록에 없습니다. 사용자는 편집기 설정에서 프로젝트의 맞춤법 검사를 끌 수 있습니다.

</Accordion>

### 배포

<Accordion title="Q01: Ayakaleaf Pro는 k8s에서의 분산 배포를 지원하나요?">

대부분의 사용자에게는 [Toolkit](/ko/on-premises/installation/using-the-toolkit)을 사용한 배포를 권장합니다. Kubernetes 또는 유사한 플랫폼을 사용한 대규모 클러스터 배포는 운영 복잡성과 유지 관리 부담을 크게 늘릴 수 있으므로 권장하지 않습니다.

</Accordion>

<Accordion title="Q02: 수천 명의 사용자에게 서비스할 때 가용성을 어떻게 보장할 수 있나요?">

[수평 확장](/ko/on-premises/maintenance/horizontal-scaling) 가이드를 참조하세요. 여러 Overleaf 인스턴스를 배포하고 로드 밸런서를 구성하여 트래픽을 분산할 수 있습니다.

</Accordion>

<Accordion title="Q03: 배포나 마이그레이션을 도와줄 수 있나요?">

기존 Overleaf Server Pro 인스턴스가 있다면 Ayakaleaf Pro로의 마이그레이션을 기꺼이 도와드리겠습니다. 이메일 또는 이슈로 연락해 주세요.

</Accordion>

<Accordion title="Q04: `https://example.com/overleaf`처럼 URL 하위 경로에서 Ayakaleaf Pro를 호스팅할 수 있나요?">

아니요. Ayakaleaf Pro는 도메인의 루트에서 제공되어야 합니다. `https://overleaf.example.com`과 같은 전용 도메인 또는 하위 도메인을 사용하세요.

</Accordion>

<Accordion title="Q05: Windows나 macOS에서, 또는 Toolkit 없이 Ayakaleaf Pro를 실행할 수 있나요?">

저희는 [Toolkit](/ko/on-premises/installation/using-the-toolkit)을 사용하는 Linux 서버를 지원합니다. Windows, WSL2 또는 macOS의 Docker Desktop에서도 작동할 수 있지만 테스트하지는 않습니다. 알려진 MongoDB 문제는 [문제 해결](/ko/on-premises/support/troubleshooting)을 참조하세요.

독립형 `docker-compose.yml`은 제공하지 않습니다. Toolkit이 사용하는 Compose 구성을 보려면 Toolkit 디렉터리에서 `bin/docker-compose config`를 실행하세요.

</Accordion>

<Accordion title="Q06: Ayakaleaf Pro를 어떻게 제거하나요?">

제거 스크립트는 없습니다. Toolkit 디렉터리에서 다음을 수행하세요.

1. `bin/docker-compose down`으로 컨테이너를 중지하고 삭제합니다.
2. 데이터를 삭제합니다. 기본적으로 데이터는 Toolkit의 `data/` 디렉터리에 있습니다. `config/overleaf.rc`에서 `OVERLEAF_DATA_PATH`, `MONGO_DATA_PATH`, `REDIS_DATA_PATH` 또는 `GIT_BRIDGE_DATA_PATH`를 변경했다면 해당 디렉터리도 삭제하세요. 이 작업은 되돌릴 수 없으므로, 데이터가 필요할 수 있다면 먼저 [백업](/ko/on-premises/maintenance/data-and-backups)하세요.
3. Toolkit 디렉터리를 삭제합니다.
4. `docker images`로 확인할 수 있는 Docker 이미지를 삭제합니다: `ghcr.io/ayaka-notes/overleaf-pro`, git-bridge 이미지, `mongo`, `redis` 및 TeX Live 이미지.

</Accordion>

<Accordion title="Q07: Ayakaleaf Pro를 어떻게 중지, 시작 또는 재시작하나요?">

Toolkit 디렉터리에서 다음을 실행하세요.

* `bin/stop`은 모든 컨테이너를 중지하고, `bin/start`는 다시 시작합니다. 컨테이너가 유지되므로 사용자는 로그인 상태를 유지합니다.
* `bin/up -d`는 컨테이너를 생성하고 백그라운드에서 시작합니다. `config/variables.env`, `config/overleaf.rc` 또는 `config/version`을 변경한 후에 실행하세요. 구성이 변경된 컨테이너를 다시 생성하며, 그때서야 변경 사항이 적용됩니다. `bin/stop`과 `bin/start`는 변경 사항을 적용하지 않습니다.
* `bin/docker-compose restart sharelatex`는 구성 변경 사항을 적용하지 않고 Overleaf 컨테이너만 재시작합니다.

`bin/up`이 컨테이너를 다시 생성할 때마다 사용자가 로그아웃된다면 `OVERLEAF_SESSION_SECRET`을 설정하세요. [환경 변수](/ko/on-premises/configuration/overleaf-toolkit/environment-variables)의 Q\&A를 참조하세요.

</Accordion>

<Accordion title="Q08: OAuth 콜백 URL은 어디에 입력하나요?">

Ayakaleaf Pro가 아니라 공급자에서 생성하는 애플리케이션에 입력합니다. 이 연동들에는 `config/variables.env`에 콜백 설정이 없습니다. Ayakaleaf Pro는 모든 콜백 URL을 `OVERLEAF_SITE_URL`로부터 구성하여 공급자에 전송하며, 공급자는 애플리케이션에 등록된 URL과 일치하지 않으면 이를 거부합니다. 따라서 공급자에만 등록하고, `OVERLEAF_SITE_URL`을 사용자가 여는 주소로 설정하면 됩니다.

| 연동 | 공급자의 입력란 | 값 |
| --- | --- | --- |
| [GitHub](/ko/on-premises/configuration/overleaf-toolkit/github-synchronisation) | Authorization callback URL | `${OVERLEAF_SITE_URL}/user/github-sync/oauth2/callback` |
| [GitLab](/ko/on-premises/configuration/overleaf-toolkit/gitlab-synchronisation) | Redirect URI | `${OVERLEAF_SITE_URL}/user/gitlab-sync/oauth2/callback` |
| [Gitea](/ko/on-premises/configuration/overleaf-toolkit/gitea-synchronisation) | Redirect URIs | `${OVERLEAF_SITE_URL}/user/gitea-sync/oauth2/callback` |
| [Dropbox](/ko/on-premises/configuration/overleaf-toolkit/dropbox-synchronisation) | Redirect URIs(**Add** 클릭) | `${OVERLEAF_SITE_URL}/user/dropbox/oauth/callback` |
| [Zotero](/ko/on-premises/configuration/overleaf-toolkit/zotero-integration) | Callback URL | `${OVERLEAF_SITE_URL}/user/zotero/oauth/callback` |
| [Mendeley](/ko/on-premises/configuration/overleaf-toolkit/mendeley-integration) | Redirect URL | `${OVERLEAF_SITE_URL}/user/mendeley/oauth/callback` |
| [OIDC 로그인](/ko/on-premises/configuration/overleaf-toolkit/authentication/oidc-authentication) | Redirect URI | `${OVERLEAF_SITE_URL}/oidc/login/callback` |
| [SAML 로그인](/ko/on-premises/configuration/overleaf-toolkit/authentication/saml-authentication) | ACS URL (Assertion Consumer Service) | `${OVERLEAF_SITE_URL}/saml/login/callback` |

`OVERLEAF_SITE_URL`을 새 도메인 등으로 변경하면 모든 공급자에서도 URL을 업데이트하세요. 그렇지 않으면 연결이 실패합니다.

</Accordion>

### LaTeX

<Accordion title="Q01: 사용자의 LaTeX 프로젝트 컴파일은 격리되나요? Shell Escape가 활성화되어 있나요?">

Sandbox Compiles를 활성화하면 각 사용자의 컴파일은 별도의 Docker 컨테이너에서 실행되며 다른 사용자의 컴파일과 격리됩니다. Sandbox Compiles에서는 Shell Escape가 기본적으로 활성화되어 있습니다.

</Accordion>

<Accordion title="Q02: Sandbox Compiles 이미지는 신뢰할 수 있나요? 컴파일이 실패할 수 있나요?">

저희는 지난 3년간 Sandbox Compiles용 TeX Live Full 이미지를 개선해 왔습니다. 대부분의 경우 overleaf.com에서 컴파일되는 프로젝트는 Ayakaleaf Pro에서도 올바르게 컴파일됩니다. 필요한 글꼴을 사용할 수 없는 경우 해당 글꼴을 프로젝트에 직접 업로드하세요.

</Accordion>

<Accordion title="Q03: 프로젝트가 컴파일되지 않습니다. 문제 해결을 도와줄 수 있나요?">

프로젝트를 공식 Overleaf 웹사이트에 업로드하고 읽기 전용 링크 공유를 활성화한 다음, GitHub 이슈에 해당 링크를 포함해 주세요.

공식 Overleaf 웹사이트에서는 정상적으로 컴파일되지만 Ayakaleaf Pro에서는 컴파일되지 않게 만드는 버그는 조사하여 수정하겠습니다. 이 범위를 벗어나는 컴파일 문제는 지원 대상이 아닙니다.

</Accordion>
