### 관리자와 첫 번째 프로젝트 만들기 {#create-the-administrator-and-a-first-project}

[http://localhost:8080/launchpad](http://localhost:8080/launchpad)를 열고 첫 번째 관리자 계정을 만든 다음 로그인하세요. 그런 다음 Linux 가이드의 [6. 설치 후 작업](/ko/on-premises/installation/using-docker-compose/linux/6.-post-installation-tasks)을 따르되, 예시 URL에서는 포트 `8080`을 사용하세요.

### 컴파일 확인 {#verify-compilation}

로그인 페이지가 열린다고 해서 별도의 컴파일러 컨테이너와 데이터 마운트가 작동한다는 것이 증명되지는 않습니다. 빈 프로젝트를 만들고 다음 `main.tex`를 컴파일하세요.

```latex
\documentclass{article}
\begin{document}
Ayakaleaf Pro on macOS.
\end{document}
```

PDF 미리보기에 텍스트가 표시되어야 합니다. 필요하면 프로젝트 설정에서 TeX Live 2026을 선택하세요.

중국어 텍스트가 있는 프로젝트의 경우 컴파일러로 **XeLaTeX**를 선택하고 다음을 테스트하세요.

```latex
\documentclass{ctexart}
\begin{document}
你好，Ayakaleaf Pro。
\end{document}
```

### 데이터 지속성 확인 {#verify-persistence}

```bash
bin/stop
bin/start
```

프로젝트를 다시 열고 다시 컴파일하세요. 계정, 소스, 프로젝트 파일이 그대로 남아 있어야 합니다. 기본 경로를 사용하는 경우 실제 데이터는 Mac의 Toolkit `data/` 디렉터리에 있습니다.

### 인스턴스 가용성 유지 {#keep-the-instance-available}

Mac이 잠자기 상태가 되면 macOS는 Docker Desktop의 가상 머신과 그 안의 모든 컨테이너를 일시 중단합니다. 아무도 인스턴스를 열 수 없으며, 실행 중인 컴파일은 Mac이 깨어날 때까지 멈춥니다. 중요한 것은 시스템 잠자기뿐입니다. 디스플레이는 꺼져도 됩니다.

다른 사람이 인스턴스를 사용하거나 오래 걸리는 작업을 실행해 둔다면 Mac을 전원에 연결해 두고 자동 잠자기를 방지하세요. [Mac의 잠자기 및 깨우기 설정](https://support.apple.com/guide/mac-help/set-sleep-and-wake-settings-mchle41a6ccd/mac)을 참조하세요.

| Mac | 설정 |
| --- | --- |
| 데스크톱 Mac(Mac mini, iMac, Mac Studio, Mac Pro) | **System Settings → Energy**: **Prevent automatic sleeping when the display is off**를 켭니다 |
| MacBook | **System Settings → Battery → Options**: **Prevent automatic sleeping on power adapter when the display is off**를 켭니다. 이 설정은 전원 어댑터가 연결되어 있을 때만 적용되며, 덮개를 닫으면 MacBook은 여전히 잠자기 상태가 됩니다 |

잠시 동안만 Mac을 깨어 있게 하려면 대신 터미널 창에서 `caffeinate -i`를 실행하세요. `Ctrl+C`를 누르거나 창을 닫을 때까지 유휴 잠자기를 방지합니다.

Docker Desktop은 사용자 세션의 앱입니다. 재시작 후 인스턴스를 다시 사용할 수 있게 하려면 Docker Desktop **Settings → General**에서 **Start Docker Desktop when you sign in to your computer**를 켜세요. Toolkit의 컨테이너는 `restart: always`를 사용하므로, Docker Desktop이 실행되면 `bin/up` 없이도 Docker가 컨테이너를 다시 시작합니다. 재시작 후 누군가 Mac에 로그인할 때까지 인스턴스는 중지된 상태로 남습니다.

<Info>

깨어 있는 Mac은 전력을 더 많이 사용합니다. 항상 접근 가능해야 하는 서비스에는 Linux 서버를 권장합니다. [Linux](/ko/on-premises/installation/using-docker-compose/linux)를 참조하세요.

</Info>

### 일상적인 사용 {#daily-use}

인스턴스를 관리하기 전에 Docker Desktop을 여세요. 새 터미널에서 다음을 실행합니다.

```bash
export PATH="$(brew --prefix gnu-sed)/libexec/gnubin:$PATH"
cd "$HOME/ayakaleaf-toolkit"
```

| 작업 | 명령 |
| --- | --- |
| 기존 컨테이너 시작 | `bin/start` |
| 데이터를 유지한 채 컨테이너 중지 | `bin/stop` |
| 구성 변경 사항 적용 | `bin/up -d` |
| 상태 확인 | `bin/docker-compose ps` |
| 시작 로그 읽기 | `bin/docker-compose logs --tail=100 sharelatex` |
| 컴파일러 로그 읽기 | `bin/logs -f clsi` |

`bin/start`는 `config/`의 변경 사항을 적용하지 않습니다. 구성을 수정한 후에는 `bin/up -d`를 실행하세요. `config/`와 `data/`를 보관하고, 업그레이드하거나 설치를 옮기기 전에는 [데이터 및 백업](/ko/on-premises/maintenance/data-and-backups)을 따르세요. MongoDB가 쓰는 동안 데이터베이스 파일을 복사하는 것은 일관된 백업이 아닙니다.

로컬 사용 시에는 인스턴스를 `127.0.0.1`에 두세요. 다른 컴퓨터에 서비스하려면 수신 주소, 사이트 URL, HTTPS를 의도적으로 설정하세요. Linux 가이드의 [5. 인스턴스 개인화](/ko/on-premises/installation/using-docker-compose/linux/5.-personalizing-your-instance)를 참조하세요.

문제가 있다면 [문제 해결](/ko/on-premises/installation/using-docker-compose/macos/troubleshooting)을 참조하세요.
