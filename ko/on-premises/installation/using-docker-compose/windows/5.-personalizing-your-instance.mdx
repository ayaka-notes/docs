명령 실행과 파일 수정은 **Ubuntu**의 `~/ayakaleaf-toolkit`에서 하세요.

<Steps>
<Step title="컨테이너 설정">
`config/overleaf.rc`에서 기존 항목을 수정하세요.

```bash title="config/overleaf.rc"
PROJECT_NAME=ayakaleaf-wsl
SERVER_PRO=true
OVERLEAF_LISTEN_IP=127.0.0.1
OVERLEAF_PORT=8080
SIBLING_CONTAINERS_ENABLED=true
DOCKER_SOCKET_PATH=/var/run/docker.sock
```

기본 데이터 경로와 번들된 MongoDB 및 Redis 서비스는 그대로 유지하세요. 포트 `8080`은 로컬 Windows 브라우저용이며, `127.0.0.1`에 바인딩하면 로컬에서만 접근할 수 있습니다. Sandboxed Compiles는 애플리케이션 컨테이너 안에서 TeX를 실행하는 대신 컴파일마다 별도의 Linux 컨테이너를 사용합니다. Docker 소켓을 통해 애플리케이션이 이러한 컨테이너를 만들 수 있으며, Toolkit은 `data/overleaf/data/compiles` 아래의 컴파일 데이터에 대한 호스트 경로를 제공합니다.
</Step>

<Step title="애플리케이션 설정">
`config/variables.env`에서 다음 값을 설정하고, 같은 이름의 활성 항목이 있다면 교체하세요.

```dotenv title="config/variables.env"
OVERLEAF_SITE_URL=http://localhost:8080
TEX_LIVE_DOCKER_IMAGE=ghcr.io/ayaka-notes/texlive-full:2026.1
ALL_TEX_LIVE_DOCKER_IMAGES=ghcr.io/ayaka-notes/texlive-full:2026.1
ALL_TEX_LIVE_DOCKER_IMAGE_NAMES="TeX Live 2026"
```

full 이미지에는 폭넓은 프로젝트에 필요한 패키지와 글꼴이 포함되어 있습니다. 이 이미지와 애플리케이션을 위해 최소 40 GB의 여유 저장 공간을 확보하고, 프로젝트 데이터와 향후 업데이트를 위한 공간도 추가로 확보하세요.

빠른 배포 테스트를 하려면 대신 더 작은 **basic** 이미지를 사용하세요. 6단계의 일반 article 테스트에는 충분하지만, 전체 패키지와 글꼴 세트는 포함되어 있지 않습니다.

```dotenv
TEX_LIVE_DOCKER_IMAGE=ghcr.io/ayaka-notes/texlive-basic:2026.1
ALL_TEX_LIVE_DOCKER_IMAGES=ghcr.io/ayaka-notes/texlive-basic:2026.1
ALL_TEX_LIVE_DOCKER_IMAGE_NAMES="TeX Live 2026 Basic"
```

중복된 활성 키 없이 이 중 하나의 세트를 선택하세요. basic 이미지의 [Dockerfile](https://github.com/ayaka-notes/texlive-full/blob/main/texlive/2026/Dockerfile.basic)에는 `latexmk`, XeTeX, `fontspec`이 포함되어 있지만 `ctex`나 전체 글꼴 모음은 포함되어 있지 않습니다. basic에서 LaTeX 패키지가 없다는 것만으로는 샌드박스 문제라고 볼 수 없습니다.

세션 비밀 값을 생성하세요.

```bash
openssl rand -hex 32
```

결과를 `config/variables.env`에 `OVERLEAF_SESSION_SECRET`으로 추가하세요. 생성된 초대 토큰 비밀 값도 유지하세요. 이메일이 없는 로컬 인스턴스라면 SMTP 설정과 `OVERLEAF_EMAIL_FROM_ADDRESS`는 설정하지 않은 채로 두세요.
</Step>

<Step title="인스턴스 시작">
```bash
bin/up -d
```

Toolkit은 MongoDB를 시작하고, 복제본 세트를 초기화하고, 선택한 TeX Live 이미지를 다운로드한 다음 Redis와 애플리케이션을 시작합니다. 큰 이미지를 다운로드하는 동안에는 멈춘 것처럼 보일 수 있습니다. 첫 번째 `bin/up`이 아직 작업 중일 때 두 번째 `bin/up`을 실행하지 마세요.

다른 Ubuntu 터미널에서 다음을 확인하세요.

```bash
cd "$HOME/ayakaleaf-toolkit"
bin/docker-compose ps
bin/docker-compose logs --tail=100 mongo
bin/docker-compose logs --tail=100 -f sharelatex
```

로그 확인을 멈추려면 `Ctrl+C`를 누르세요. 분리(detached) 모드의 컨테이너는 계속 실행됩니다. MongoDB에서 시작이 실패하면 다시 시도하기 전에 [MongoDB가 시작되지 않습니다](/ko/on-premises/installation/using-docker-compose/windows/troubleshooting#mongodb-fails-to-start)를 따르세요. 기존 설치를 초기화하기 위해 데이터 디렉터리를 삭제하지 마세요.

포트와 첫 실행 페이지를 확인하세요.

```bash
bin/docker-compose port sharelatex 80
curl -I http://localhost:8080/launchpad
```

포트는 `127.0.0.1:8080`이어야 합니다. 처음에 HTTP 요청이 실패하면 애플리케이션 초기화가 끝날 때까지 기다리세요.
</Step>

<Step title="Windows에서 인스턴스 열기">
**Windows 브라우저**에서 [http://localhost:8080/launchpad](http://localhost:8080/launchpad)를 여세요. Windows에서도 임시 WSL IP 주소 대신 이 주소를 사용하세요.

브라우저와 별개로 Windows의 HTTP 접근을 확인하려면 **PowerShell**에서 다음을 실행하세요.

```powershell
curl.exe -I http://localhost:8080/launchpad
```

Ubuntu에서는 페이지에 접근할 수 있지만 Windows에서는 접근할 수 없다면 [Windows에서 localhost를 열 수 없습니다](/ko/on-premises/installation/using-docker-compose/windows/troubleshooting#windows-cannot-open-localhost)를 참조하세요.
</Step>
</Steps>
