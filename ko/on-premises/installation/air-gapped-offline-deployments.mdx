---
title: 에어갭/오프라인 배포
description: Docker 이미지를 내보내고, 전송하고, 로드하여 Ayakaleaf Pro를 오프라인으로 배포합니다.
icon: block-brick
---

일반적으로 GitHub Sync 및 Zotero 연동과 같은 많은 기능이 인터넷 연결을 필요로 하기 때문에, 오프라인 환경에서 Ayakaleaf Pro를 배포하는 것은 권장하지 않습니다.

오프라인으로 작업하려는 경우 필요한 `ayakaleaf-pro` 및 TeX Live 이미지를 pull하기 위해 `ghcr.io` 레지스트리에 항상 접근할 수 있는 것은 아닙니다. 하지만 Docker는 이미지를 내보내고 가져오는 도구를 제공하므로 오프라인/에어갭 배포에 문제가 되지 않습니다.

전체적인 흐름은 인터넷에 연결된 장치에서 필요한 이미지를 다운로드하고, 이를 휴대용 장치로 내보낸 다음(또는 SCP/Rsync로 전송한 다음), 에어갭 서버에서 가져오는 것입니다.

이를 위해 다음 단계를 완료해야 합니다:

* 인터넷에 연결된 머신에서 필요한 모든 이미지( `overleaf-pro`, `git-bridge`, `mongo`, `redis` + [Sandboxed Compiles](https://docs.overleaf.com/on-premises/configuration/overleaf-toolkit/server-pro-only-configuration/sandboxed-compiles)에 사용할 필요한 [TeX Live 이미지](https://docs.overleaf.com/on-premises/configuration/overleaf-toolkit/server-pro-only-configuration/sandboxed-compiles#available-tex-live-images))를 pull합니다
  * `docker pull ghcr.io/ayaka-notes/overleaf-pro:6.1.2`
  * `docker pull quay.io/sharelatex/git-bridge:6.1.2` (태그는 `overleaf-pro`와 동일해야 합니다)
  * `docker pull mongo:6` (실제 버전으로 변경하세요)
  * `docker pull redis:6.2` (실제 버전으로 변경하세요)
  * `docker pull ghcr.io/ayaka-notes/texlive-full:2024.1` (실제 버전으로 변경하세요)
* pull한 **각** 이미지를 .tar 파일로 내보내야 합니다. 예: `docker save ghcr.io/ayaka-notes/overleaf-pro:6.1.2 > overleaf-pro:6.1.2.tar`
* 원하는 방법을 사용하여 인터넷에 연결된 머신에서 오프라인/에어갭 서버로 `.tar` 파일을 전송합니다
* 각 .tar 파일에 대해 `docker load` 명령을 사용하여 .tar 파일에서 이미지를 로드합니다. 예: `docker load < overleaf-pro:6.1.2.tar`
* 마지막으로 `docker images` 명령을 실행하여 이미지가 성공적으로 로드되어 사용 가능한지 확인합니다

<Danger>

기본적으로 `bin/up` 명령을 실행하면 Toolkit은 `config/variables.env`의 `ALL_TEX_LIVE_DOCKER_IMAGES`로 설정된 각 TeX Live 이미지를 자동으로 pull하려고 시도합니다. 배포가 에어갭 환경이므로 이 작업은 실패합니다. `config/overleaf.rc`에서 `SIBLING_CONTAINERS_PULL=false`를 사용하면 이를 방지할 수 있습니다.

</Danger>
