RHEL과 그 재빌드 배포판(Rocky Linux, AlmaLinux)은 Docker 대신 Podman을 제공하며, 일부 조직은 서버에서 Docker를 허용하지 않습니다. Toolkit은 대신 **rootless Podman**에서 Ayakaleaf Pro를 실행할 수 있습니다. 컨테이너는 일반 사용자로 실행되고, 컴파일은 여전히 샌드박스화된 TeX Live 컨테이너에서 실행되며, SELinux는 enforcing 상태를 유지합니다. 스크립트 `bin/podman-setup`이 호스트를 검사하고 고칠 수 있는 것을 고칩니다.

이 섹션을 마치면 [Docker Compose 사용](/ko/on-premises/installation/using-docker-compose)과 같은 인스턴스를 갖게 됩니다. 샌드박스 컴파일, MongoDB, Redis를 갖춘 Ayakaleaf Pro를 평소처럼 `bin/up`, `bin/doctor`, `bin/upgrade`로 관리합니다.

<Info>

Podman 지원은 실험적입니다. 이는 공식 Overleaf Toolkit에서 온 것으로, 공식 Toolkit은 RHEL 9 이상에서 rootless Podman, 샌드박스 컴파일, SELinux enforcing 조합으로만 테스트합니다. 저희는 Rocky Linux 9.9(Podman 5.8, SELinux enforcing)에서 Ayakaleaf Pro 6.3.4로 이 페이지들을 테스트했습니다. 권장 컨테이너 런타임은 여전히 Docker입니다.

</Info>

### 필요한 것 {#what-you-need}

* SELinux가 enforcing인 **RHEL, Rocky Linux, AlmaLinux 또는 CentOS Stream 9 이상**. 다른 배포판에서는 `bin/podman-setup`이 중단됩니다. Ubuntu나 Debian에서는 [Docker Compose 사용](/ko/on-premises/installation/using-docker-compose/linux)을 따르세요.
* 컨테이너를 소유할 **`sudo` 권한이 있는 root가 아닌 사용자**. 이 섹션의 모든 명령을 이 사용자로 실행하세요. `bin/podman-setup`은 `root`로 실행되기를 거부합니다.
* **깨끗한 호스트**: Docker Engine도, 기존 Toolkit 설치도 없어야 합니다. 기존 Docker 기반 인스턴스를 Podman으로 옮기는 방법은 다루지 않습니다.

### Docker와의 차이점 {#how-it-differs-from-docker}

|                                  | Docker                               | Rootless Podman                                                                          |
| -------------------------------- | ------------------------------------ | ---------------------------------------------------------------------------------------- |
| 컨테이너를 실행하는 주체         | Docker 데몬(`root`로 실행)           | 사용자 본인                                                                              |
| 컴파일 시작에 사용하는 소켓      | `/var/run/docker.sock`               | `/run/user/<uid>/podman/podman.sock`                                                     |
| 포트                             | 아무 포트, 예: `80`과 `443`          | `1024` 이상, 예: `8080`                                                                  |
| 호스트 방화벽(`firewalld`)       | 게시된 포트가 우회함                 | 적용됨: `firewall-cmd`로 포트를 엽니다                                                   |
| 재부팅 후 시작                   | Docker 데몬이 다시 시작함            | 사용자 서비스 `podman-restart`                                                           |
| SELinux                          | Toolkit이 구성하지 않음              | 정책 모듈 `podman_socket_clsi`와 `config/overleaf.rc`의 `SELINUX_MODE=managed`            |
| 컴파일용 Seccomp 프로필          | 이미지에 내장                        | Toolkit이 `config/seccomp/<version>/`에 추출하고 `SECCOMP_PROFILE`로 설정                |

### 알려진 제한 사항 {#known-limitations}

* <strong>Git 통합.</strong> Ayakaleaf Pro 6.3.4에서는 Podman에서 `git clone`이 `502`로 실패합니다. 이미지 안의 NGINX가 Docker의 DNS 서버(`127.0.0.11`)로 `git-bridge` 컨테이너를 찾는데, Podman에는 이 서버가 없기 때문입니다. 수정 사항([1b911d1092](https://github.com/ayaka-notes/ayakaleaf-pro/commit/1b911d1092c80f7b0ff77c5e3805b40503d49964))은 다음 릴리스에 포함됩니다. 그때까지는 `GIT_BRIDGE_ENABLED=false`로 두세요.
* <strong>클라이언트 IP 주소.</strong> Rootless Podman은 게시된 포트를 컨테이너 네트워크 내부에서 전달하므로, Ayakaleaf Pro는 모든 방문자를 `10.89.0.15` 같은 내부 주소로 봅니다. 관리 패널의 사용자 [감사 로그](/ko/on-premises/user-guide/administrators/user-management#audit-logs)에는 사용자의 IP 주소 대신 이 주소가 표시됩니다.
