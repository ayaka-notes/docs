`bin/podman-setup`은 Ayakaleaf Pro가 Podman에서 필요로 하는 모든 것을 검사합니다. 옵션 없이 실행하면 보고만 하고, `--apply`를 붙이면 발견한 문제도 고칩니다.

<Steps>
<Step title="호스트 검사">
```bash title="Check only"
bin/podman-setup
```

새 호스트에서는 대부분의 검사가 실패합니다. 예를 들면 다음과 같습니다.

```text
====== Packages ======
[✗] podman not installed
[✗] podman-docker not installed
...
====== Summary ======
[✓] 7 passed  [!] 13 warnings  [✗] 4 failures
```
</Step>

<Step title="수정 적용">
```bash title="Check and fix"
bin/podman-setup --apply
```

터미널에서 실행하세요. 시스템 전체에 적용되는 단계에서는 `sudo` 비밀번호를 묻습니다. 또한 seccomp 프로필을 추출하기 위해 Ayakaleaf Pro 이미지를 다운로드하므로 처음에는 몇 분이 걸립니다. 마지막에 호스트를 다시 검사합니다.

```text
====== Summary ======
[✓] 23 passed  [!] 2 warnings  [✗] 0 failures
[!] Warnings remaining:
[!] not logged in to quay.io
[!] container → socket skipped (sharelatex not running)
```

이 시점에서는 두 경고 모두 예상된 것입니다.

* `not logged in to quay.io`: 이 검사는 Server Pro 이미지가 비공개 레지스트리에 있는 공식 Toolkit에서 온 것입니다. Ayakaleaf Pro 이미지는 `ghcr.io`에 공개되어 있어 로그인이 필요 없으므로 무시하세요. 설치 후에도 계속 남아 있습니다.
* `container → socket skipped (sharelatex not running)`: 이 테스트에는 실행 중인 인스턴스가 필요합니다. [3. Ayakaleaf Pro 시작](/ko/on-premises/installation/using-podman/3.-start-ayakaleaf-pro)에서 스크립트를 다시 실행합니다.

스크립트는 모든 검사를 통과하면 `0`, 경고가 있으면 `1`, 실패가 있으면 `2`로 종료합니다. quay.io 경고 때문에 `1`이 예상됩니다.
</Step>
</Steps>

### 스크립트가 변경하는 내용 {#what-the-script-changes}

`--apply`를 사용하면 스크립트가 다음을 변경할 수 있습니다.

시스템 전체(`sudo` 사용):

* `dnf`로 `podman`, `podman-docker`, `git`, `curl`, `checkpolicy`, `policycoreutils`를 설치합니다.
* `loginctl`로 사용자의 lingering을 활성화하여 로그아웃한 후에도 컨테이너가 계속 실행되도록 합니다.
* "Emulate Docker CLI using podman" 메시지를 숨기는 `/etc/containers/nodocker`를 만듭니다.
* `SELINUX_MODE=managed`일 때 SELinux 정책 모듈 `podman_socket_clsi`를 로드합니다.

사용자 대상:

* Ayakaleaf Pro가 컴파일을 시작하는 데 사용하는 Docker 호환 API인 사용자 서비스 `podman.socket`을 활성화합니다.
* GitHub에서 Docker Compose v2를 `~/.local/bin/docker-compose`에 설치하고 `~/.docker/cli-plugins/`에 링크합니다.
* `~/.config/containers/containers.conf`에서 Podman이 이 Compose를 사용하도록 합니다.
* `~/.config/containers/registries.conf.d/overleaf-toolkit.conf`에 별칭 `mongo`와 `redis`를 추가하여 Podman이 이 짧은 이미지 이름을 어디서 가져올지 알게 합니다.

Toolkit 내부:

* `config/overleaf.rc`의 `DOCKER_SOCKET_PATH`와 `DOCKER_HOST`를 `/run/user/<uid>/podman/podman.sock`으로 설정합니다.
* Ayakaleaf Pro 이미지에서 컴파일용 seccomp 프로필을 `config/seccomp/<version>/clsi-profile.json`으로 추출하고 `config/variables.env`에 `SECCOMP_PROFILE`을 설정합니다. Docker와 달리 Podman은 이 프로필이 호스트의 파일로 있어야 합니다.
* `config/selinux/`에서 SELinux 정책 모듈을 빌드합니다.
* `data/`의 데이터 디렉터리가 생성되면 `podman unshare chown`으로 소유자를 설정합니다.

<Info>

각 변경 사항은 하나의 검사에 대응합니다. 예를 들어 `config/overleaf.rc`에서 무언가를 직접 변경했다면 `bin/podman-setup`을 다시 실행하여 확인하세요.

</Info>
