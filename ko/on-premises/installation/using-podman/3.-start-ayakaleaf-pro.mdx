---
title: 3. Ayakaleaf Pro 시작
description: Podman에서 Ayakaleaf Pro를 시작하고, podman-setup과 bin/doctor로 확인하고, 재부팅 후에도 시작되도록 합니다.
icon: circle-play
---

<Steps>
<Step title="컨테이너 시작">
```bash title="Start Ayakaleaf Pro"
bin/up -d
```

첫 시작에서는 MongoDB, Redis, TeX Live 이미지를 다운로드하고 `data/`에 데이터 디렉터리를 만듭니다. Podman 지원이 실험적이라는 경고가 출력됩니다.

<Info>

첫 시작 시 `MongoNetworkError: connect ECONNREFUSED 127.0.0.1:27017`이 출력될 수도 있습니다. Toolkit은 MongoDB가 아직 시작되는 동안 MongoDB 복제본 세트를 설정하고, 응답할 때까지 다시 시도합니다. 이 줄은 무시해도 됩니다.

</Info>

1~2분 후 컨테이너가 실행 중인지 확인합니다.

```bash title="List the containers"
podman ps --format "{{.Names}} {{.Status}}"
```

```text
mongo Up 34 seconds (healthy)
redis Up 20 seconds
sharelatex Up 20 seconds
```
</Step>

<Step title="설정 다시 검사">
이제 데이터 디렉터리가 존재하고 `sharelatex` 컨테이너가 실행 중이므로 `bin/podman-setup`이 검사를 마칠 수 있습니다.

```bash title="Check the setup"
bin/podman-setup
```

새 데이터 디렉터리의 소유자를 확인하고 `sharelatex` 컨테이너 내부에서 Podman 소켓을 테스트합니다.

```text
====== Socket Connectivity ======
[✓] host → socket OK
[✓] container → socket OK

====== Data Directory Permissions ======
[✓] mongo data dir owned by 999
[✓] redis data dir owned by 999
[✓] overleaf data dir owned by 33
...
====== Summary ======
[✓] 27 passed  [!] 1 warnings  [✗] 0 failures
[!] Warnings:
[!] not logged in to quay.io
```

`container → socket OK`는 Ayakaleaf Pro가 컴파일 컨테이너를 시작할 수 있다는 뜻입니다. 검사가 실패하면 `bin/podman-setup --apply`를 실행한 다음 `bin/up -d`를 실행하세요. quay.io 경고는 Ayakaleaf Pro에 해당하지 않습니다. [2. podman-setup 실행](/ko/on-premises/installation/using-podman/2.-run-podman-setup)을 참조하세요.
</Step>

<Step title="doctor 실행">
```bash title="Run the doctor"
bin/doctor
```

Podman에서는 보고서에 런타임과 보안 설정이 표시됩니다.

```text
- Container Daemon
    - status: up
    - runtime: podman
    - server version: 5.8.5
    - socket: /run/user/1000/podman/podman.sock
    - DOCKER_HOST: unix:///run/user/1000/podman/podman.sock
    - host → socket: OK
    - container → socket: OK
- Security
    - SELinux: Enforcing
    - SELINUX_MODE: managed
    - SELINUX_LABEL: sharelatex_t
    - SELinux module: loaded (podman_socket_clsi)
    - SELinux rules: present
    - Seccomp profile: present
```

마지막의 `Server Pro enabled, but not logged in to quay.io repository` 경고는 같은 quay.io 검사입니다. [도움 받기](/ko/on-premises/support/getting-help#q-and-a)를 참조하세요.
</Step>

<Step title="재부팅 후 Ayakaleaf Pro 시작">
Docker에서는 재부팅 후 Docker 데몬이 컨테이너를 다시 시작합니다. Rootless Podman에는 데몬이 없으므로, 서버가 부팅될 때 컨테이너를 시작하는 사용자 서비스를 활성화하세요.

```bash title="Start the containers at boot"
systemctl --user enable podman-restart.service
```

이 서비스는 재시작 정책이 `always`인 사용자의 모든 컨테이너를 시작하며, Toolkit은 모든 컨테이너에 이 정책을 설정합니다. 이를 위해서는 lingering이 필요한데, `bin/podman-setup --apply`가 이미 활성화했습니다. 이 서비스가 없으면 재부팅할 때마다 `bin/up -d`를 실행하세요.
</Step>

<Step title="방화벽에서 포트 열기">
기본적으로 인스턴스는 서버 자체에서 오는 연결만 `http://localhost:8080`으로 받습니다. 다른 컴퓨터에서 열려면 [5. 인스턴스 개인화](/ko/on-premises/installation/using-docker-compose/linux/5.-personalizing-your-instance#listen-address-and-port)에 설명된 대로 `config/overleaf.rc`의 `OVERLEAF_LISTEN_IP`와 `config/variables.env`의 `OVERLEAF_SITE_URL`을 설정하고 `bin/up -d`를 다시 실행하세요.

Docker와 달리 rootless Podman은 호스트 방화벽을 우회하지 않습니다. RHEL의 기본값처럼 `firewalld`가 실행 중이면 포트를 여세요.

```bash title="Open port 8080"
sudo firewall-cmd --permanent --add-port=8080/tcp
sudo firewall-cmd --reload
```

클라우드 서버에서는 공급자의 보안 그룹에서도 포트를 허용하세요. 인스턴스를 인터넷에 공개하기 전에 HTTPS를 사용하세요. [4. 설치 후 작업](/ko/on-premises/installation/using-podman/4.-post-installation-tasks#use-https)을 참조하세요.
</Step>
</Steps>
