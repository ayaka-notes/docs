Kubernetes는 Toolkit과 같은 이미지를 실행합니다. 별도의 Kubernetes 이미지는 없습니다.

| 이미지                                               | 사용처                                                                  |
| ---------------------------------------------------- | ----------------------------------------------------------------------- |
| `ghcr.io/ayaka-notes/overleaf-pro:6.3.2`             | Deployment `overleaf`                                                   |
| `ghcr.io/ayaka-notes/overleaf-pro/git-bridge:6.3.2`  | [Git 연동](/ko/on-premises/configuration/kubernetes/integrations/git-integration)(선택 사항), 위와 같은 태그 |
| `ghcr.io/ayaka-notes/texlive-*`                      | 컴파일, [0단계](/ko/on-premises/installation/using-kubernetes/0.-prepare-the-nodes)에서 노드의 Docker에 pull |

이미지는 amd64 및 arm64용으로 [ghcr.io](https://github.com/ayaka-notes/ayakaleaf-pro/pkgs/container/overleaf-pro/)에 공개되어 있으므로 kubelet이 자격 증명 없이 pull할 수 있습니다.

<Warning>

`latest`가 아닌 `6.3.2`와 같은 버전 태그를 항상 사용하세요. 업그레이드는 데이터베이스 마이그레이션을 실행하므로 [Kubernetes에서 업그레이드](/ko/on-premises/maintenance/upgrading-on-kubernetes)를 따라야 합니다. 변하는 태그를 사용하면 파드가 다시 스케줄링될 때마다 업그레이드됩니다.

</Warning>

### Q\&A

<Accordion title="노드가 ghcr.io에 접근할 수 없습니다. 어떻게 해야 하나요?">

<strong>답변:</strong> 노드가 접근할 수 있는 레지스트리로 이미지를 복사하고 매니페스트에서 그 이름을 사용하세요. 예:

```bash
docker pull ghcr.io/ayaka-notes/overleaf-pro:6.3.2
docker tag ghcr.io/ayaka-notes/overleaf-pro:6.3.2 registry.example.com/ayakaleaf/overleaf-pro:6.3.2
docker push registry.example.com/ayakaleaf/overleaf-pro:6.3.2
```

TLS가 없는 레지스트리의 경우 containerd는 모든 노드에 `server = "http://<registry>"`가 포함된 `/etc/containerd/certs.d/<registry>/hosts.toml`이 필요하며, `config_path`가 [0단계](/ko/on-premises/installation/using-kubernetes/0.-prepare-the-nodes)에서와 같이 설정되어 있어야 합니다. Docker 자체는 `localhost`로만 일반 HTTP push를 하므로, 레지스트리 호스트에서 `localhost:<port>`를 통해 push하거나 `insecure-registries`에 추가하세요.

</Accordion>
