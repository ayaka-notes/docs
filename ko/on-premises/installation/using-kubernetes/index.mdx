[Toolkit](/ko/on-premises/installation/using-the-toolkit)은 단일 서버에서 Ayakaleaf Pro를 실행하는 데 권장되는 방법입니다. 이미 Kubernetes 클러스터를 운영하고 있다면, 이 섹션에서는 일반 `kubectl` 매니페스트로 같은 컨테이너를 클러스터에 배포합니다. 추가 이미지도, Helm 차트도 필요 없습니다.

이 섹션을 마치면 샌드박스 컴파일, MongoDB 레플리카 세트, Redis를 갖춘 Ayakaleaf Pro 인스턴스 하나가 모두 네임스페이스 `overleaf`에서 실행됩니다. 로드 밸런서 뒤에서 여러 인스턴스를 실행하려면 이후 [수평 확장](/ko/on-premises/configuration/kubernetes/horizontal-scaling)으로 이어서 진행하세요.

<Info>

Kubernetes 지원은 실험적입니다. Helm 차트나 Kubernetes 전용 이미지는 게시하지 않습니다. 이 페이지들의 매니페스트는 각각 2 vCPU와 4 GB 메모리를 갖춘 노드 세 개로 구성된 Kubernetes 1.37(kubeadm, containerd 2.4, flannel)에서 테스트한 것입니다. 스토리지, 네트워킹, 인그레스는 클러스터에 맞게 조정하세요.

</Info>

### 구성 요소의 대응 관계

| Toolkit(단일 서버)                           | Kubernetes                                                               |
| -------------------------------------------- | ------------------------------------------------------------------------ |
| `config/variables.env`                       | ConfigMap `overleaf-env` 및 Secret `overleaf-secrets`                    |
| `sharelatex` 컨테이너                        | Deployment `overleaf`(모든 Overleaf 서비스를 실행하는 파드 하나)         |
| `mongo` 및 `redis` 컨테이너                  | StatefulSet `mongo`(레플리카 세트) 및 `redis`, 또는 관리형 서비스        |
| `~/overleaf-toolkit/data/overleaf`           | PersistentVolumeClaim `overleaf-data`                                    |
| 컴파일에 사용되는 호스트의 Docker            | Ayakaleaf Pro를 실행하는 모든 노드의 Docker Engine                       |
| `bin/up`, `bin/logs`, `bin/shell`            | `kubectl apply`, `kubectl logs`, `kubectl exec`                          |

### 필요한 것

* 패키지를 설치할 수 있는 Kubernetes 클러스터: Ayakaleaf Pro를 실행할 수 있는 모든 노드에는 **Docker Engine**이 필요합니다. 컴파일은 Ayakaleaf Pro가 노드의 `/var/run/docker.sock`을 통해 시작하는 TeX Live 컨테이너에서 실행되기 때문입니다. [0. 노드 준비](/ko/on-premises/installation/using-kubernetes/0.-prepare-the-nodes)를 참조하세요.
* `ReadWriteOnce` 볼륨을 제공하는 기본 StorageClass.
* 작업용 컴퓨터의 `kubectl` 및 `openssl`.
