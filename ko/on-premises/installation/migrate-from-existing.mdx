### Overleaf Community에서 마이그레이션

#### 사례 01: Overleaf Toolkit에서

Overleaf Community용 공식 Overleaf Toolkit을 사용 중이라면, `overleaf-toolkit/config` 디렉터리에 다음과 같거나 유사한 내용으로 `docker-compose.override.yml` 파일을 추가하기만 하면 됩니다.

```yml title="docker-compose.override.yml"
---
services:
    sharelatex:
        image: ghcr.io/ayaka-notes/overleaf-pro:X.x.x # change to specific version
```

인스턴스를 시작하려면 다음을 실행합니다.

```bash
bin/up
```

이것으로 끝입니다! 모든 준비가 완료되었습니다. 다음으로 Ayakaleaf 인스턴스가 올바르게 실행되고 있고 웹 인터페이스에 접근할 수 있는지 확인하세요. 모든 것이 작동하면 아래의 [구성](/ko/on-premises/configuration/overleaf-toolkit) 단계를 계속 진행하여 다음과 같은 고급 기능을 활성화하세요.

* [sandboxed-compiles.md](/ko/on-premises/configuration/overleaf-toolkit/sandboxed-compiles  "mention")
* [authentication](/ko/on-premises/configuration/overleaf-toolkit/authentication  "mention")
* [github-synchronisation.md](/ko/on-premises/configuration/overleaf-toolkit/github-synchronisation  "mention")
* [zotero-integration.md](/ko/on-premises/configuration/overleaf-toolkit/zotero-integration  "mention")

#### 사례 02: Docker Compose 파일에서

독립 실행형 `docker-compose.yml`을 사용하는 경우 먼저 Overleaf Toolkit으로 마이그레이션하세요. Toolkit은 온프레미스 설치, 업그레이드 및 유지보수를 간소화합니다.

[docker-compose.yml-to-toolkit-migration.md](/ko/on-premises/maintenance/docker-compose.yml-to-toolkit-migration  "mention")에 따라 기존 배포를 변환하세요. 이 마이그레이션 중에는 현재 구성과 데이터 볼륨 경로를 그대로 유지하세요.

Toolkit 배포가 실행되면 [#from-overleaf-toolkit](/ko/on-premises/installation/migrate-from-existing#from-overleaf-toolkit  "mention")에 따라 이미지를 Ayakaleaf Pro로 전환하세요. `bin/up`으로 인스턴스를 시작한 다음 웹 인터페이스에 접근할 수 있는지 확인하세요.

### Overleaf Server Pro에서 마이그레이션

현재 상용 라이선스가 있는 [Overleaf Server Pro](https://www.overleaf.com/for/enterprises) 인스턴스를 실행 중이고 Ayakaleaf Pro로 마이그레이션하려는 경우, 일부 데이터 형식(`templates`)이 완전히 호환되지 않을 수 있으므로 추가 작업이 필요할 수 있다는 점에 유의하세요. 하지만 기꺼이 도와드리겠습니다. [이슈를 열거나](https://github.com/ayaka-notes/ayakaleaf-pro/issues) [ayaka-notes@outlook.com](mailto:ayaka-notes@outlook.com)으로 연락해 주시면 Ayakaleaf Pro로의 마이그레이션을 무료로 도와드립니다.

***

### Overleaf CEP에서 마이그레이션

[Overleaf CEP](https://github.com/yu-i-i/overleaf-cep)에서 Ayakaleaf Pro로 마이그레이션할 수 있는지에 대한 질문을 자주 받습니다. 대부분의 경우 Overleaf CEP와 Ayakaleaf Pro는 대체로 동등한 기능을 제공하며, 버전 6.2.0 기준으로 데이터 호환성을 유지합니다. 두 프로젝트는 서로 다른 시점에 기능을 릴리스할 수 있습니다. 예를 들어 저희가 Overleaf CEP의 기능을 cherry-pick할 수도 있고, 그 반대도 마찬가지입니다. 같은 기능이라도 구현 방식이 약간 다를 수 있지만, 일반적으로 마이그레이션해야 할 뚜렷한 이유는 없습니다.

그래도 Ayakaleaf Pro로 마이그레이션하거나 사용해 보고 싶다면 [#case-01-from-overleaf-toolkit](/ko/on-premises/installation/migrate-from-existing#case-01-from-overleaf-toolkit  "mention")을 참조하세요. 마이그레이션 과정은 동일합니다.

***

### Overleaf SaaS에서 마이그레이션

안타깝게도 Overleaf SaaS 플랫폼에서 자체 호스팅 Ayakaleaf Pro 인스턴스로 마이그레이션하는 것은 훨씬 더 어려울 수 있습니다. 현재 일반적으로 사용할 수 있는 유일한 방법은 각 프로젝트를 ZIP 아카이브로 다운로드한 다음 자체 호스팅 Ayakaleaf Pro 인스턴스에 업로드하는 것입니다. 이 방법은 현재 프로젝트 파일만 전송하므로 다음 항목을 _**잃게**_ 됩니다.

* 모든 프로젝트 기록 및 이전 버전
* 모든 댓글 및 변경 내용 추적
* 모든 Git 메타데이터 및 커밋 기록
* 모든 GitHub 동기화 링크 및 설정
* BibTeX 파일과 타사 참고문헌 관리 플랫폼 간의 모든 연결

***

### 타사 Overleaf 포크에서 마이그레이션

Ayakaleaf Pro는 특정 타사 Overleaf 포크에 고유한 기능을 지원하지 않을 수 있습니다. 포크가 업스트림 Overleaf 코드베이스에서 크게 벗어나거나 업스트림 호환성을 유지하지 않고 변경 사항을 도입하면, 이후 Overleaf 릴리스를 병합하는 것이 극도로 어려워질 수 있습니다. 위에서 설명한 마이그레이션 방법을 시도해 볼 수는 있지만 호환성은 보장되지 않으며, 지원되지 않는 포크로부터의 마이그레이션에 대해서는 도움이나 기술 지원을 제공하지 못할 수 있습니다.
