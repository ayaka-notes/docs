각 프로젝트에는 자체 MCP 서버가 있어, 컴퓨터의 AI 클라이언트가 프로젝트를 읽고 편집하고, 컴파일하고, 댓글에 답할 수 있습니다. 클라이언트는 Git 인증 토큰으로 로그인합니다.

<Info>

**MCP server** 카드가 보이지 않으면 관리자용 [MCP 서버](/ko/on-premises/configuration/overleaf-toolkit/integrations/mcp-server)를 참고하세요.

</Info>

## v6.3.3의 새로운 기능 {#new-in-v6-3-3}

v6.3.3부터 클라이언트는 프로젝트 기록도 다룰 수 있습니다. 변경 사항 나열, 두 버전 비교, 특정 시점의 파일 읽기, 버전 저장 및 삭제, 파일 하나 또는 프로젝트 전체 복원이 가능합니다. 변경 내용 추적(tracked changes)을 나열하고 수락하거나 거부할 수 있으며, 요청하면 자신의 편집을 추적된 변경으로 만들 수 있습니다. 텍스트 일부에 댓글 달기, 댓글 메시지 편집 및 삭제, 프로젝트 채팅 읽기 및 보내기, 파일과 폴더 이동 및 이름 변경, 폴더 만들기, 맞춤법 검사 언어 변경도 할 수 있습니다. 클라이언트는 여러분의 토큰으로 작동하므로, 누가 무엇을 할 수 있는지는 편집기에서와 마찬가지로 프로젝트에서의 역할을 따릅니다. [누가 무엇을 할 수 있나요](#who-may-do-what)를 참고하세요.

MCP 서버는 v6.3.1에서 도입되었습니다. v6.3.1과 v6.3.2에는 같은 17개의 도구가 있고, v6.3.3에는 33개가 있습니다.

| 도구 | v6.3.1 및 v6.3.2 | v6.3.3 |
| ----- | ----------------- | ------ |
| `get_clone_info`, `get_settings`, `list_files`, `delete_file`, `compile`, `get_compile_log`, `get_output_file_link`, `word_count`, `reply_to_comment`, `resolve_comment`, `reopen_comment` | 예 | 예, 변경 없음 |
| `read_file` | 최신 내용 | 특정 `version` 시점의 파일도 |
| `edit_file`, `write_file` | 프로젝트의 변경 내용 추적 설정을 따름 | `trackChanges`로 편집을 추적된 변경으로 만들 수도 있음 |
| `update_settings` | 컴파일러, TeX Live 이미지, 메인 문서 | 맞춤법 검사 언어도 |
| `list_versions` | 버전, 설명, 날짜 | `delete_version`이 받는 `id`와 저장한 사람도 |
| `list_comments` | id 없는 메시지 | `edit_comment_message`와 `delete_comment_message`가 받는 각 메시지의 `id`도 |
| `list_changes`, `diff`, `create_version`, `delete_version`, `restore_file`, `restore_project`, `list_tracked_changes`, `accept_tracked_changes`, `reject_tracked_changes`, `add_comment`, `edit_comment_message`, `delete_comment_message`, `list_chat_messages`, `send_chat_message`, `move_file`, `create_folder` | 아니요 | 예 |

## 클라이언트 연결하기 {#connect-a-client}

<Steps>
<Step title="대화 상자 열기">
프로젝트를 엽니다. 왼쪽 막대에서 **Integrations**를 클릭한 다음 **MCP server**를 클릭합니다.

<Frame caption="Integrations 패널">
  <img src="/images/on-premises/mcp-server-integrations.png" alt="MCP server 카드가 있는 Integrations 패널" />
</Frame>

대화 상자에 이 프로젝트 서버의 주소와 클라이언트별 탭(**Claude Code**, **Codex**, **Cursor**, **VS Code**, **Gemini CLI**)이 표시됩니다.

<Frame caption="MCP server 대화 상자">
  <img src="/images/on-premises/mcp-server-dialog.png" alt="주소, 클라이언트별 탭, Claude Code용 명령이 있는 MCP server 대화 상자" />
</Frame>
</Step>

<Step title="토큰 만들기">
**Go to settings**를 클릭합니다. 계정 설정이 새 탭에서 열립니다. **Git integration** 아래에서 **Generate token**을 클릭하고, 이미 토큰이 있다면 **Add another token**을 클릭합니다. 토큰은 한 번만 표시되므로 **Copy**를 클릭해 안전한 곳에 보관하세요. 그런 다음 **Close**를 클릭합니다.

<Frame caption="새 토큰">
  <img src="/images/on-premises/mcp-server-token.png" alt="Copy 버튼이 있는 Git authentication token 대화 상자" />
</Frame>

[Git 통합](/ko/on-premises/user-guide/users/git-integration)에 이미 사용 중인 토큰도 사용할 수 있으며, 하나의 토큰을 모든 프로젝트에 쓸 수도 있습니다.
</Step>

<Step title="클라이언트에 서버 추가하기">
대화 상자로 돌아가 사용하는 클라이언트의 탭을 클릭하고, 설정 옆의 **Copy**를 클릭합니다.

| 탭 | 넣을 위치 | 토큰 |
| --- | ------------- | --------- |
| **Claude Code** | 터미널에서 명령 실행 | 명령의 `<token>`을 교체 |
| **Codex** | `~/.codex/config.toml` | 환경 변수 `OVERLEAF_TOKEN`에 설정 |
| **Cursor** | `~/.cursor/mcp.json` | 환경 변수 `OVERLEAF_TOKEN`에 설정 |
| **VS Code** | `.vscode/mcp.json` | 파일에 토큰 대신 `overleaf-token`이라는 비밀번호 입력란이 있음 |
| **Gemini CLI** | 터미널에서 명령 실행 | 명령의 `<token>`을 교체 |

주소는 하나의 프로젝트에 속합니다. 다른 프로젝트를 연결하려면 `overleaf`가 이미 사용 중이므로 다른 이름으로 추가하세요. 예를 들어 Claude Code에서는 명령의 `overleaf`를 `overleaf-lab`으로 바꿉니다.
</Step>
</Steps>

## 연결 확인하기 {#check-the-connection}

### Claude Code로 확인 {#with-claude-code}

```bash
claude mcp list
```

서버가 연결됨으로 표시됩니다:

```text
overleaf: https://<your-site>/project/<project-id>/mcp (HTTP) - ✔ Connected
```

### curl로 확인 {#with-curl}

이 방법은 어떤 클라이언트를 쓰든 작동합니다. 주소와 토큰을 바꾸고 MCP 프로토콜의 `initialize` 요청을 보냅니다:

```bash
curl -X POST https://<your-site>/project/<project-id>/mcp \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -H "Accept: application/json, text/event-stream" \
  -d '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2025-06-18","capabilities":{},"clientInfo":{"name":"curl","version":"1.0"}}}'
```

응답에는 서버 이름과 그 뒤에 클라이언트를 위한 안내가 있습니다:

```json
{"result":{"protocolVersion":"2025-06-18","capabilities":{"tools":{"listChanged":true}},"serverInfo":{"name":"overleaf","version":"1.0.0"},"instructions":"This server works on one Overleaf project. ..."},"jsonrpc":"2.0","id":1}
```

도구를 보려면 같은 명령으로 `tools/list`를 보냅니다. 응답에 33개의 도구가 나열되며, 사이트에서 프로젝트 채팅이 꺼져 있으면 31개입니다. v6.3.3 이전에는 17개입니다.

```bash
  -d '{"jsonrpc":"2.0","id":2,"method":"tools/list","params":{}}'
```

도구를 호출하려면 `tools/call`을 보냅니다:

```bash
  -d '{"jsonrpc":"2.0","id":3,"method":"tools/call","params":{"name":"list_files","arguments":{}}}'
```

```json
{"result":{"content":[{"type":"text","text":"[\n  {\n    \"path\": \"main.tex\",\n    \"type\": \"doc\"\n  }\n]"}]},"jsonrpc":"2.0","id":3}
```

**Git integration** 아래의 **Last used**에 서버가 토큰을 받은 날짜가 표시됩니다.

  <img src="/images/on-premises/mcp-server-last-used.png" alt="토큰 목록. 첫 번째 토큰의 Last used에는 날짜가, 두 번째에는 N/A가 표시됨" />

### 연결되지 않을 때 {#if-it-does-not-connect}

| 보이는 내용 | 의미 |
| ------------ | ------------- |
| 상태 `401`, 또는 Claude Code에서 `✘ Failed to connect`와 `HTTP 401` | 토큰이 없거나, 틀렸거나, 삭제됨 |
| 상태 `404` | 이 ID의 프로젝트가 없음 |
| 상태 `405` | 요청이 `POST`가 아님 |
| 상태 `406`과 `Not Acceptable` | `Accept` 헤더가 없음: 클라이언트는 `application/json`과 `text/event-stream`을 모두 받아야 함 |

## 클라이언트가 작업할 때 보이는 것 {#what-you-see-when-a-client-works}

편집 내용은 공동 작업자의 편집처럼 열린 편집기에 새로 고침 없이 바로 나타납니다. 새 파일과 폴더, 이동과 이름 변경은 파일 트리에 나타납니다.

<Frame caption="edit_file이 추가한 줄">
  <img src="/images/on-premises/mcp-server-live-edit.png" alt="대화 상자나 새로 고침 없이 edit_file이 추가한 줄을 보여 주는 편집기" />
</Frame>

`edit_file`은 정확히 한 번 나타나는 텍스트만 변경합니다. 그렇지 않으면 클라이언트는 `oldString not found in main.tex, read_file again` 또는 `oldString appears 2 times in main.tex, add context` 같은 오류를 받고, 아무것도 바뀌지 않습니다.

v6.3.3부터 `move_file`은 파일이나 폴더를 이동하거나 이름을 바꾸며, 필요하면 새 경로의 폴더를 만듭니다. `create_folder`는 폴더를 만듭니다. 파일을 찾을 수 없거나 새 경로가 이미 있으면 클라이언트는 오류를 받고, 아무것도 바뀌지 않습니다. `update_settings`로 맞춤법 검사 언어를 바꾸거나(예: `de`) 맞춤법 검사를 끌 수도 있습니다.

토큰이 여러분의 것이므로 댓글 답글은 검토 패널에 여러분의 이름으로 표시됩니다. 서버를 통해 해결된 댓글은 패널에서 사라지고, 다시 열면 돌아옵니다.

<Frame caption="reply_to_comment가 보낸 답글">
  <img src="/images/on-premises/mcp-server-comment.png" alt="reply_to_comment가 보낸 답글이 달린 검토 패널의 댓글" />
</Frame>

v6.3.3부터 `add_comment`는 텍스트 일부에 댓글을 답니다. 그 텍스트는 파일에 정확히 한 번 나타나야 합니다. 여러 번 나타나면 클라이언트가 그것을 포함하며 한 번만 나타나는 더 긴 텍스트도 함께 지정하고, 댓글은 해당 텍스트에만 달립니다. 댓글은 검토 패널에 여러분의 이름으로 표시되며 파일이 바뀌어도 그 텍스트에 붙어 있습니다. `edit_comment_message`는 자신의 메시지 하나를 변경합니다. `delete_comment_message`는 메시지를 삭제하며, 첫 메시지를 삭제하면 검토 패널에서처럼 댓글 전체가 삭제됩니다.

`compile`은 프로젝트를 컴파일하고 출력 파일 목록을 반환합니다. 그다음 `get_output_file_link`가 PDF나 다른 출력 파일을 다운로드할 링크를 줍니다. 이 링크는 토큰이 필요 없으며 5분 후 만료됩니다.

전체 도구 목록은 [Tools](/on-premises/configuration/overleaf-toolkit/integrations/mcp-server#tools)를 참고하세요.

## 변경 내용 추적 {#tracked-changes}

v6.3.3부터 클라이언트에게 편집을 추적된 변경으로 만들도록 요청할 수 있습니다(예: *Rewrite the abstract as a tracked change*). 그러면 `edit_file`과 `write_file`이 기존 파일에 한 변경은 프로젝트에서 변경 내용 추적이 꺼져 있어도 여러분의 이름으로 된 추적된 변경이 되며, 검토 패널에서 수락하거나 거부합니다. 새 파일은 추적된 변경이 되지 않습니다. 요청하지 않으면 편집은 편집기에서의 여러분의 편집과 마찬가지로 프로젝트의 변경 내용 추적 설정을 따릅니다. 즉, 여러분 또는 모두에게 변경 내용 추적이 켜져 있으면 추적됩니다.

프로젝트 소유자의 계정에 변경 내용 추적 기능이 없으면 클라이언트는 `Track changes is off for this project`를 받고, 아무것도 바뀌지 않습니다.

클라이언트의 모든 편집을 검토하려면 자신에게 변경 내용 추적을 켜세요. 검토 패널에서 클라이언트의 편집과 여러분의 편집을 구분하려면, 프로젝트를 공유하는 다른 계정의 토큰을 클라이언트에 주세요.

`list_tracked_changes`는 추적된 변경을 파일, 삽입되거나 삭제된 텍스트, 작성자, 시간과 함께 나열합니다. `accept_tracked_changes`와 `reject_tracked_changes`는 변경의 id를 받아 검토 패널처럼 작동합니다. 수락된 변경은 텍스트에 남고, 거부된 삽입은 제거되며, 거부된 삭제는 되돌아옵니다. 열린 편집기는 새로 고침 없이 결과를 보여 줍니다. 도구는 클라이언트에게 여러분이 요청한 변경만 수락하거나 거부하도록 안내합니다.

## 기록 {#history}

v6.3.3부터 클라이언트는 기록 패널에 표시되는 것과 같은 프로젝트 기록을 봅니다.

| 도구 | 기능 |
| ---- | ------------ |
| `list_changes` | 변경 사항을 최신순으로 나열합니다. 누가 언제 어떤 파일을 변경했는지와 각 변경 전후의 버전을 보여 줍니다. 오래된 변경은 이어지는 배치로 제공됩니다. |
| `diff` | 두 버전을 비교합니다. 한 파일을 `git diff`처럼 unified diff로 보여 주거나, 추가·제거·편집·이름 변경된 파일을 보여 줍니다 |
| `version`을 지정한 `read_file` | 특정 버전 시점의 파일을 읽습니다 |
| `list_versions` | 저장된 버전을 설명 및 저장한 사람과 함께 나열합니다 |
| `create_version` | 최신 버전 또는 이전 버전을 설명과 함께 저장합니다(**Label this version**과 같음) |
| `delete_version` | 저장된 버전을 삭제합니다. 그 변경 사항은 남습니다 |
| `restore_file` | 파일을 특정 버전 시점으로 복원합니다(**Restore this version**과 같음) |
| `restore_project` | 프로젝트 전체를 특정 버전 시점으로 복원합니다(**Restore project to this version**과 같음) |

복원은 그 자체로 새로운 변경이므로 같은 방법으로 되돌릴 수 있습니다. 도구는 클라이언트에게 요청이 있을 때만 복원하도록 안내합니다.

프로젝트 소유자에게 전체 프로젝트 기록이 없으면, 클라이언트는 기록 패널에서처럼 최근 24시간의 변경(모든 변경이 그보다 오래되었다면 가장 최근 변경)만 볼 수 있습니다. 그보다 오래된 버전은 비교, 읽기, 복원할 수 없습니다.

## 프로젝트 채팅 {#project-chat}

v6.3.3부터 `list_chat_messages`는 프로젝트 채팅을 최신순으로 한 번에 50개씩 읽습니다. `send_chat_message`는 여러분의 이름으로 메시지를 보내며, 열린 채팅에 바로 나타납니다. 사이트에서 프로젝트 채팅이 꺼져 있으면 클라이언트에는 두 도구가 모두 없습니다.

## 누가 무엇을 할 수 있나요 {#who-may-do-what}

클라이언트는 프로젝트에서 여러분의 역할이 허용하는 일을 할 수 있습니다.

| 클라이언트가 하는 일 | 소유자 | 편집자 | 검토자 | 뷰어(지정된 공동 작업자) | 뷰어(링크 공유) |
| -------------------- | ----: | -----: | -------: | --------------------------: | --------------------: |

## 클라이언트 연결 끊기 {#disconnect-a-client}

토큰을 삭제하세요. [토큰 삭제](/ko/on-premises/user-guide/users/git-integration#delete-a-token)를 참고하세요. 그때부터 서버는 해당 토큰에 `401`로 응답합니다. Git에도 그 토큰을 사용한다면 Git도 더 이상 받아들이지 않습니다.
