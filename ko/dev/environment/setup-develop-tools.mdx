## 권장 개발 도구 {#develop-tools-recommended}

이 선택적 서비스는 Overleaf 실행에 필요하지는 않지만 개발, 디버깅, 데이터 확인에 큰 도움이 됩니다. 모두 개발 환경의 일부이므로 `docker-compose.yml`에 추가할 것은 없습니다. 사이트에 로그인하면 내비게이션 바의 **Dev tools** 메뉴가 사이트가 자체 경로로 제공하는 도구로 연결됩니다.

| 도구 | 주소 | 정의 위치 |
| --- | --- | --- |
| **Grafana**, 모든 서비스의 상태, 메트릭, 로그 | [http://localhost/grafana/](http://localhost/grafana/) | `develop/grafana/docker-compose.yml`, `develop/dev.rc`에서 `GRAFANA_ENABLED=true`일 때 켜짐(기본값) |
| **Mailpit**, 사이트가 보내는 모든 이메일의 받은편지함 | [http://localhost/mailpit/](http://localhost/mailpit/) | `develop/mail/docker-compose.yml`, `MAILPIT_ENABLED=true`일 때 켜짐(기본값) |
| **Mongo Express**, MongoDB용 UI | [http://localhost/mongo-express/](http://localhost/mongo-express/) | `develop/docker-compose.yml`, 항상 켜짐 |
| **RedisInsight**, Redis 데이터용 UI | [http://localhost/redis-insight/](http://localhost/redis-insight/) | `develop/docker-compose.yml`, 항상 켜짐 |
| **Hoppscotch**, Postman과 비슷한 브라우저 기반 API 클라이언트 | [http://localhost:9170](http://localhost:9170/) (`HOPPSCOTCH_PORT`) | `develop/hoppscotch/docker-compose.yml`, `HOPPSCOTCH_ENABLED=true`일 때 켜짐(기본값) |

<Warning>

이 도구들에는 로그인이 없습니다. Grafana의 익명 사용자는 관리자이며, Mongo Express는 어떤 문서든 변경할 수 있습니다. 사이트, Hoppscotch, Mongo Express(8081), RedisInsight(5540)는 호스트의 `127.0.0.1`에서만 수신하므로 다른 호스트에서는 접근할 수 없습니다.

</Warning>

### Grafana {#grafana}

Grafana는 webpack-dev-server를 통해 사이트의 `/grafana/`에서 제공되므로 자체 포트가 필요 없습니다. **Overleaf Develop** 폴더에는 다음 대시보드가 있습니다.

| 대시보드 | 표시 내용 |
| --- | --- |
| All services (홈) | 모든 서비스의 상태, 호스트 게이지, 부하, 로그. 서비스를 클릭하면 해당 대시보드가 열립니다 |
| Server | 호스트의 CPU, 부하, 메모리, 디스크, 네트워크와 clsi의 컴파일 |
| Errors | 오류 로그, 5xx 및 4xx 응답, 가장 빈번한 오류 메시지, 실패하는 라우트 |
| Data flow | 편집의 경로: document-updater와 Redis, project-history, history-v1, Mongo, 객체 저장소 |
| Containers | 모든 컨테이너의 상태, CPU, 메모리, 네트워크, 디스크(샌드박스 컴파일 포함) |
| 서비스마다 하나 | Node.js 서비스, git-bridge(JVM), mongo, redis |

Prometheus는 서비스의 `/metrics`, `mongodb-exporter`, `redis-exporter`, `cadvisor`, `node-exporter`를 수집하고, Alloy는 프로젝트의 모든 컨테이너 로그를 Loki로 보내며 대시보드의 **Log search**, **Service**, **Log level** 필터가 이를 읽습니다. 이 데이터는 컨테이너 안에만 있으므로 컨테이너를 다시 만들면 비워집니다. cAdvisor는 특권 모드로 실행되며 호스트의 `/`, `/sys`, Docker 데이터, containerd 소켓을 읽기 전용으로 읽고, node-exporter는 호스트의 `/`를 읽습니다.

대시보드는 생성된 것입니다. JSON 파일을 편집하는 대신 `develop/grafana/make-dashboards`를 수정하고 실행하세요.

### Mailpit {#mailpit}

`MAILPIT_ENABLED=true`이면 `web`은 모든 이메일을 실제 메일 서버 대신 Mailpit으로 보내며, 이메일 확인이 켜집니다(`EMAIL_CONFIRMATION_DISABLED=false`). 활성화 링크, 프로젝트 초대, 비밀번호 재설정, 확인 코드를 받은편지함에서 따라갈 수 있습니다.

### Hoppscotch 설정 {#setup-hoppscotch}

#### API 요청 프록시 {#proxy-api-request}

Hoppscotch는 브라우저에서 요청을 보내는데, 브라우저는 Docker 이름으로 서비스에 접근할 수 없습니다. 프록시인 Proxyscotch는 Docker 네트워크 안에서 실행되며 Hoppscotch 주소의 `/proxy`에서 제공됩니다. [http://localhost:9170](http://localhost:9170/)을 열고 Settings → Interceptor에서 **Proxy**를 선택한 뒤 Proxy URL을 `http://localhost:9170/proxy`로 설정하세요. 이 설정은 브라우저에 저장됩니다.

#### 서비스 API 가져오기 {#import-the-service-apis}

`develop/hoppscotch/openapi/`에는 각 서비스의 내부 API에 대한 OpenAPI 파일이 있습니다. Hoppscotch에서 Collections → Import → Import from File을 열고 모든 파일을 한 번에 선택하세요. 각 파일은 요청이 서비스의 Docker 주소로 가는 컬렉션이 됩니다. 같은 파일이 [서비스 API](/ko/dev/service-api/overview) 섹션에 표시됩니다.

#### CSRF 문제 {#csrf-problems}

<Warning>

Postman이나 다른 디버그 도구로 **post** 요청을 보내면 로그인이 **금지**되며 403 오류가 발생하는 것을 볼 수 있습니다. 이는 Overleaf가 **csrf** 검증으로 보호되고 있기 때문입니다.

</Warning>

<Frame>
  <img src="/images/dev/image-8.png" alt="" />
</Frame>

콘솔에서 다음과 같은 내용을 볼 수 있습니다.

<Frame>

Overleaf 개발 중 이 문제를 해결하려면 csrf 토큰을 설정해야 합니다. 자세한 방법은 다음과 같습니다.

<Steps>
<Step title="Pre-Request 추가">
Pre-Request에 다음 코드를 추가합니다.

<Frame>
  <img src="/images/dev/image-10.png" alt="" />
</Frame>

스크립트는 다음과 같습니다.

```js wrap
pm.sendRequest("http://web:3000/dev/csrf", function (err, res) {
    if (err) {
        console.log(err);
        return;
    }

    // 1) Save CSRF token (/dev/csrf)
    const token = res.text().trim();
    pw.env.set("csrftoken", token);
    console.log("csrftoken =", token);

    const setCookieHeader = (res.headers || []).find(h => h.key?.toLowerCase() === "set-cookie")?.value;
    console.log("set-cookie =", setCookieHeader);

    if (!setCookieHeader) return;

    const cookiePair = setCookieHeader.split(";")[0].trim(); // overleaf.sid=...
    pw.env.set("cookie_header", cookiePair);
    console.log("cookie_header =", cookiePair);
});
```
</Step>

<Step title="요청 헤더 추가">
다음 헤더를 추가해야 합니다.

| 헤더 이름  | 헤더 값        |
| ------------ | ------------------- |
| Content-Type | `application/json`  |
| X-Csrf-Token | `<<csrftoken>>`     |
| Cookie       | `<<cookie_header>>` |

<Frame>
  <img src="/images/dev/image-11.png" alt="" />
</Frame>
</Step>

```json5
{
  "_csrf": "<<csrftoken>>",
  "email": "admin@overleaf.com",
  "password": "xxxxxx"
}
```
