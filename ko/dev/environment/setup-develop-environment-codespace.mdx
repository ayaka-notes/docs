시간을 절약하고 개발 환경을 빠르게 구축할 수 있도록, GitHub Codespace를 이용하는 또 다른 버전의 개발 환경 구성을 제공합니다.

## 구성 튜토리얼 {#configuration-tutorial}

<Steps>
<Step title="Codespaces 생성">
아래 버튼을 클릭하여 server-pro 개발용 클라우드 Codespaces를 생성하세요.

[![Open in GitHub Codespaces](https://github.com/codespaces/badge.svg)](https://codespaces.new/ayaka-notes/ayakaleaf-pro)

**Machine Type**은 최소 **4-core** 이상을 선택하는 것을 권장합니다. 더 큰 머신 유형이 필요하다면 [여기](https://support.github.com/contact?tags=rr-codespaces%2Ccat_codespaces)에서 티켓을 제출하여 GitHub 공식 지원팀에 요청할 수 있습니다.

<Frame>
  <img src="/images/dev/image.png" alt="" />
</Frame>
</Step>

<Step title="설정 스크립트 실행">
Codespace가 생성될 때까지 잠시 기다려야 합니다. 터미널에 접근할 수 있게 되면 다음 명령을 실행하세요.

```text
cd develop/
bin/setup
bin/i18n
```

`bin/setup`은 이미지를 받아 서비스를 시작합니다. 그런 다음 `bin/i18n`이 커밋된 로케일 파일에 없는 Ayakaleaf Pro 모듈의 번역을 적용합니다. [i18n 번역 업데이트](/ko/dev/environment/update-i18n-translations)를 참고하세요.

<Frame>
  <img src="/images/dev/image-1.png" alt="" />
</Frame>

<Warning>

이 스크립트(`bin/setup`)를 사용하면 `server-pro` 브랜치의 최신 커밋을 기준으로 가능한 한 짧은 시간 안에 개발 환경을 설정할 수 있습니다. 이전 버전이나 다른 브랜치에는 적용되지 않을 수 있습니다.

개발용 Docker 이미지는 [GitHub Action](https://github.com/ayaka-notes/ayakaleaf-pro/actions)으로 매일 빌드됩니다.

</Warning>
</Step>

<Step title="Launchpad 접속">
포트 탭으로 전환하면 사용 가능한 웹 포트 목록이 보입니다. `80`(`develop/dev.rc`의 `OVERLEAF_PORT`)을 클릭하세요. 이제 launchpad 페이지가 보입니다. Mailpit, Grafana, Mongo Express, RedisInsight는 같은 포트의 경로(`/mailpit/`, `/grafana/`, `/mongo-express/`, `/redis-insight/`)에 있으며, 로그인하면 사이트의 **Dev tools** 메뉴에서 연결됩니다. RustFS 콘솔은 9001, Hoppscotch는 9170에 있습니다. [포트](/ko/dev/environment/setup-develop-environment-local#ports)를 참고하세요.

<Step title="개발 즐기기">
이제 여러분의 시간입니다! 멋진 기능을 만들어 보세요. `bin/setup`은 이미 모든 서비스를 개발 모드(`bin/dev`와 같은 `node --watch`)로 시작하므로, 코드 변경 사항이 별도의 명령 없이 반영됩니다.

`develop/dev.rc`를 변경한 후에는 `bin/setup`을 다시 실행하세요. `bin/setup`은 켜져 있는 기능의 파일을 추가하는 `bin/docker-compose`를 거칩니다.

<Warning>

`docker compose -f docker-compose.yml -f docker-compose.dev.yml -f docker-compose.image.yml up`으로 서비스를 직접 시작하지 마세요. 이 명령은 `dev.rc`의 기능 파일을 건너뛰므로 `web`, `filestore`, `history-v1`이 RustFS 설정 없이 다시 생성되어 로컬 볼륨으로 돌아갑니다. 로컬 볼륨에는 프로젝트의 기록과 바이너리 파일이 없습니다.

</Warning>
</Step>
</Steps>
