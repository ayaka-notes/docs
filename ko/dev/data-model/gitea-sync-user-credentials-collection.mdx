---
title: Gitea Sync User Credentials 컬렉션
icon: lock
---

`giteaSyncUserCredentials`는 Gitea Sync를 위해 Gitea 계정을 연결한 사용자마다 문서 하나를 보관합니다. 사용자의 OAuth 토큰을 암호화해 저장합니다. 이 컬렉션은 `gitea-sync` 웹 모듈(`services/web/modules/gitea-sync`)에 속합니다. 스키마는 `services/web/modules/gitea-sync/app/models/giteaSyncUserCredentials.mjs`에 있으며, 모든 접근은 `services/web/modules/gitea-sync/app/src/TokenManager.mjs`를 거칩니다.

#### 필드 {#fields}

| 필드 | 타입 | 의미 | 출처 |
| ----- | ---- | ------- | ------ |
| `_id` | ObjectId | upsert가 삽입할 때 Mongoose가 설정합니다. | |
| `userId` | ObjectId | Overleaf 사용자. 필수. 스키마에는 `unique: true`가 있지만 인덱스는 만들어지지 않습니다(인덱스 참고). `userId` 기준 upsert가 사용자당 문서 하나를 유지합니다. | `giteaSyncUserCredentials.mjs:8`, `TokenManager.mjs:89-96` |
| `gitea` | String | JSON `{ accessToken, refreshToken, expiresAt }`으로, `@overleaf/access-token-encryptor`로 암호화됩니다. `expiresAt`은 에포크 이후 밀리초 또는 `null`이며, `refreshToken`은 `null`일 수 있습니다. 비밀번호는 `GITEA_TOKEN_CIPHER_PASSWORD`에서 가져오고, 암호 레이블은 `GITEA_TOKEN_CIPHER_LABEL`이며 기본값은 `2026.10-v3`입니다. 필수. | `giteaSyncUserCredentials.mjs:9-10`, `TokenManager.mjs:17-30`, `services/web/modules/gitea-sync/app/src/GiteaApiClient.mjs:198-209` |
| `__v` | Number | Mongoose 버전 키. 스키마에서 끄지 않습니다. | Mongoose 기본값 |

#### 쓰는 코드 {#who-writes-it}

| 코드 | 역할 |
| ---- | ------------ |
| `TokenManager.mjs:89-96` (`saveUserToken`) | 사용자의 암호화된 자격 증명을 upsert합니다. OAuth 콜백에서 호출됩니다(`services/web/modules/gitea-sync/app/src/GiteaSyncController.mjs:146`). GitLab Sync와 달리 다시 연결해도 교체된 토큰은 취소되지 않습니다. |
| `TokenManager.mjs:53-79` (`refreshUserToken`) | 액세스 토큰이 `expiresAt`까지 5분 미만 남으면(`:12`) 리프레시 토큰으로 새 토큰을 받아 저장합니다(`:76`). Gitea는 리프레시 토큰을 사용하면 교체하므로, 사용자별 락 `giteaSyncToken` 아래에서 실행됩니다(`:14,54`). |
| `TokenManager.mjs:100-102` (`removeUserToken`) | 문서를 삭제합니다. Gitea에는 OAuth 토큰을 취소하는 API가 없으므로 사용자가 Gitea에서 권한 부여를 취소합니다(`:98-99`). 연결 해제 시(`GiteaSyncController.mjs:173`)와 삭제된 사용자가 만료될 때(`services/web/modules/gitea-sync/index.mjs:56-58`) 호출됩니다. |

#### 읽는 코드 {#who-reads-it}

| 코드 | 역할 |
| ---- | ------------ |
| `TokenManager.mjs:40-44,82-86` (`getUserCredentials`, `getUserToken`) | Gitea API를 호출할 때마다 자격 증명을 복호화하며, 토큰이 곧 만료되면 먼저 갱신합니다: `services/web/modules/gitea-sync/app/src/GiteaSyncHandler.mjs`(예: `:27`)와 `services/web/modules/gitea-sync/app/src/GitMerge.mjs:52`. 문서가 없거나 자격 증명을 복호화 또는 갱신할 수 없으면 `InvalidTokenError`를 던지고, 사용자는 연결되지 않은 것으로 간주됩니다(`GiteaSyncHandler.mjs:25-37`). |
| `services/web/modules/admin-tools/app/src/AdminUserListManager.mjs:395` | 관리자 패널에 표시되는 통합 기능을 위해 사용자에게 문서가 있는지 확인합니다. |

#### 인덱스 {#indexes}

| 이름 | 키 | 옵션 | 마이그레이션 |
| ---- | ---- | ------- | --------- |
| `_id_` | `_id: 1` | | default |

Mongoose `autoIndex`가 꺼져 있으므로(`services/web/app/src/infrastructure/Mongoose.mjs:7`), 스키마의 `userId`에 있는 `unique: true`는 아무것도 만들지 않습니다. 이 컬렉션의 인덱스를 만드는 마이그레이션은 없습니다.

#### 참고 {#notes}

* `GITEA_TOKEN_CIPHER_PASSWORD`를 바꾸면 저장된 자격 증명을 읽을 수 없게 됩니다. 그러면 해당 사용자는 다시 연결할 때까지 연결되지 않은 것으로 간주됩니다.
* 삭제된 사용자는 만료될 때까지 문서를 유지합니다.
