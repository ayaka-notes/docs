title: Docs 컬렉션

`Docs`: Docs는 편집 가능한 파일을 가리키는 Overleaf의 내부 용어로, 예를 들어 순수 `tex` 파일이나 `.bib` 파일이 이에 해당합니다. 파일 내용, 리비전 정보 및 삭제 상태를 저장합니다.

#### 핵심 식별 정보

* `_id`: 이 문서 레코드를 식별하는 고유 MongoDB ObjectId입니다.
* `project_id`: 이 파일이 속한 프로젝트(`Project._id`)에 대한 참조입니다.
* `name`: 프로젝트 파일 트리에 표시되는 파일 이름입니다(예: `main.tex`, `sample.bib`).

#### 리비전 및 버전 관리

* `rev`: 프로젝트 기록 내에서 이 문서의 리비전 번호입니다.
* `version`: 편집기 백엔드에서 사용하는 내부 스키마 또는 형식 버전입니다.

이 필드들은 Overleaf의 자체 버전 관리 시스템에서 증분 편집을 추적하고 기록 및 롤백을 지원하는 데 사용됩니다.

#### 파일 내용

*   `lines`:\
    파일 내용을 한 줄씩 나타내는 문자열 배열입니다.\
    각 요소는 소스 파일의 논리적 한 줄에 해당합니다.

    이 예시에서는 BibTeX 항목을 저장합니다.

    * `@article{greenwade93, ... }`
* `ranges`: 편집기 주석 또는 추적 범위(예: 선택 영역, 댓글 또는 변경 내용 추적)를 위해 예약된 데이터 구조입니다.\
  활성 범위가 없으면 비어 있습니다. `op` 댓글을 문서의 특정 위치에 연결하는 작업 객체입니다.
  * `op.c` — 댓글이 달린 선택 텍스트(문자 내용)
  * `op.p` — 앵커 위치(문자 오프셋)
  * `id` 이 댓글 항목의 고유 ObjectId입니다.
  * `metadata` 작성자 및 타임스탬프 정보입니다.

#### 삭제 상태

* `deleted`:\
  이 문서가 프로젝트에서 삭제되었는지 여부를 나타냅니다.
* `deletedAt`:\
  문서가 삭제된 시간을 기록하는 타임스탬프입니다.

삭제된 문서는 데이터베이스에서 즉시 제거되지 않고, 일반적으로 기록 복구 및 버전 탐색을 위해 보관됩니다.

다음은 Overleaf `docs`의 실제 예시입니다.

<Accordion title="간단한 예시">

```json5
{
    _id: ObjectId('696b8377933aeebb3d3cc25e'),
    project_id: ObjectId('696b8377933aeebb3d3cc252'),
    rev: 1,
    lines: [
        '@article{greenwade93,',
        '    author  = "George D. Greenwade",',
        '    title   = "The {C}omprehensive {T}ex {A}rchive {N}etwork ({CTAN})",',
        '    year    = "1993",',
        '    journal = "TUGBoat",',
        '    volume  = "14",',
        '    number  = "3",',
        '    pages   = "342--351"',
        '}',
        ''
    ],
    ranges: {},
    version: 0,
    deleted: true,
    deletedAt: ISODate('2026-01-17T13:11:42.580Z'),
    name: 'sample.bib'
}
```

</Accordion>
