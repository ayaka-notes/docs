`oauthApplications`에는 web이 알고 있는 OAuth 클라이언트가 저장됩니다. 문서 하나가 클라이언트 하나입니다. Ayakaleaf Pro에서 여기에 쓰는 것은 web 모듈 `git-bridge`뿐이며, web이 시작될 때 `Overleaf Git Bridge`라는 이름의 클라이언트 하나를 만듭니다. 스키마는 `services/web/app/src/models/OauthApplication.mjs`입니다.

#### 필드 {#fields}

| 필드 | 타입 | 의미 | 출처 |
| ----- | ---- | ------- | ------ |
| `_id` | ObjectId | 클라이언트 문서 id. `oauthAccessTokens.oauthApplication_id`와 `oauthAuthorizationCodes.oauthApplication_id`가 이를 가리킵니다. | `OauthApplication.mjs:5` |
| `id` | String | 클라이언트 id: 무작위 소문자와 숫자 64자. | `OauthApplication.mjs:7`, `services/web/modules/git-bridge/index.mjs:25` |
| `clientSecret` | String | 클라이언트 시크릿으로, `v1.`에 무작위 문자 32자를 붙여 기록합니다. `getClient`만 읽으며, `getClient`를 호출하는 곳은 없습니다(참고 참조). | `OauthApplication.mjs:8`, `git-bridge/index.mjs:26` |
| `grants` | Array of String | 그랜트 유형. git-bridge 클라이언트는 `['password']`입니다. 토큰을 검사할 때 클라이언트와 함께 반환됩니다(`services/web/modules/oauth2-server/app/src/OAuth2Model.mjs:67-72`). | `OauthApplication.mjs:9`, `git-bridge/index.mjs:27` |
| `name` | String | 클라이언트 이름. git-bridge 모듈과 개인 액세스 토큰 코드는 `Overleaf Git Bridge`라는 이름으로 클라이언트를 찾습니다. | `OauthApplication.mjs:10`, `git-bridge/index.mjs:15-16,28` |
| `redirectUris` | Array of String | 허용된 리디렉션 URI. git-bridge 클라이언트는 `[]`입니다. | `OauthApplication.mjs:11`, `git-bridge/index.mjs:29` |
| `scopes` | Array of String | 클라이언트가 사용할 수 있는 스코프. git-bridge 클라이언트는 `['git_bridge']`입니다. | `OauthApplication.mjs:12`, `git-bridge/index.mjs:30` |
| `pkceEnabled` | Boolean | 스키마에만 있습니다. 이 저장소의 어떤 코드도 쓰지 않으며, 사용되지 않는 `getClient`만 읽습니다(`OAuth2Model.mjs:207`). | `OauthApplication.mjs:13` |

#### 쓰는 코드 {#who-writes-it}

| 코드 | 역할 |
| ---- | ------------ |
| `git-bridge/index.mjs:9-35` (module `git-bridge`) | `GIT_BRIDGE_ENABLED`가 `true`이면, 같은 이름의 클라이언트가 없을 때 web 시작 시 `Overleaf Git Bridge` 클라이언트를 만듭니다. |

#### 읽는 코드 {#who-reads-it}

| 코드 | 역할 |
| ---- | ------------ |
| `services/web/modules/oauth2-server/app/src/OAuthPersonalAccessTokenManager.mjs:53-61` (module `oauth2-server`) | 이름으로 `Overleaf Git Bridge` 클라이언트를 찾아, 그 `_id`를 새 개인 액세스 토큰마다 저장합니다. 클라이언트가 없으면 토큰이 만들어지지 않습니다. |
| `OAuth2Model.mjs:31-39,67-72` (`getAccessToken`) | `oauthApplication_id`로 토큰의 클라이언트를 불러와 그 `id`와 `grants`를 반환합니다. |
| `OAuth2Model.mjs:185-209,241,275` (`getClient`, `saveToken`, `saveAuthorizationCode`) | `id`로 클라이언트를 조회합니다. 이 저장소에서는 실행되지 않습니다. 참고를 확인하세요. |

#### 인덱스 {#indexes}

기본 `_id` 인덱스만 있습니다. 고유 인덱스 `id_1`은 `saas`(`20190912145016_create_oauthApplications_indexes.mjs`)와 `server-pro`(`20230502180757_server_pro_oauth_indexes.mjs`) 태그가 붙은 마이그레이션에서만 만들어지며, Community Edition은 이를 실행하지 않습니다.

#### 참고 {#notes}

* web은 `@node-oauth/oauth2-server`를 bearer 토큰 검사에만 사용하며(`services/web/app/src/Features/Authentication/AuthenticationController.mjs:409-450`의 `server.authenticate`), 이는 모델의 `getAccessToken`과 `verifyScope`만 호출합니다. `/oauth/token`이나 `/oauth/authorize`를 제공하는 라우트가 없으므로 `getClient`, `saveToken`, `saveAuthorizationCode`는 호출되지 않습니다.
* 모듈은 이름으로 클라이언트를 찾은 뒤 만드는데, Community Edition에는 `name`이나 `id`에 고유 인덱스가 없습니다. 따라서 같은 이름의 두 번째 클라이언트를 막는 것이 없습니다. 클라이언트가 필요한 코드는 `findOne`이 반환한 것을 사용합니다.
