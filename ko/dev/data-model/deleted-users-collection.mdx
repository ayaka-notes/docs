title: Deleted Users 컬렉션
icon: user-xmark
---

`deletedUsers`는 삭제된 사용자 계정을 보관합니다. 삭제된 계정마다 문서 하나가 있으며, 전체 사용자 문서의 사본과 삭제한 사람이 담깁니다. Web이 `services/web/app/src/Features/User/UserDeleter.mjs`에서 쓰며, 스키마는 `services/web/app/src/models/DeletedUser.mjs`입니다. 영구 삭제 지연 시간이 지나면 만료 처리가 사용자 사본을 제거하지만, `deleterData`가 있는 레코드는 남습니다.

사용자를 삭제하면 그 사용자가 소유한 프로젝트도 삭제됩니다. 이 프로젝트들은 이유 `account-deletion`과 함께 [Deleted Projects 컬렉션](/ko/dev/data-model/deleted-projects-collection)에 들어갑니다.

#### 쓰는 코드 {#who-writes-it}

| 코드 | 역할 |

| `UserDeleter.mjs:93-115`(`expireDeletedUser`) | `expireDeletedUser` 훅을 실행하고 사용자의 온보딩 데이터를 삭제한 뒤, `user`와 `deleterData.deleterIpAddress`를 제거합니다. |

| `AdminUserManager.mjs:651-696`(`restoreDeletedUser`, 모듈 `admin-tools`) | 관리자 패널의 복원: `user`로 `users` 문서를 다시 만들고(이메일이 이미 사용 중이면 거부), 레코드를 삭제하고, 계정과 함께 삭제된 프로젝트를 복원합니다. |

#### 참고 {#notes}

* `expireDeletedUser`를 수신하는 모듈은 해당 사용자에 대한 자체 데이터를 삭제합니다: `dropbox`(`services/web/modules/dropbox/index.mjs:62`), `github-sync`(`services/web/modules/github-sync/index.mjs:66`), `gitlab-sync`(`services/web/modules/gitlab-sync/index.mjs:56`), `gitea-sync`(`services/web/modules/gitea-sync/index.mjs:56`).
* 만료된 레코드는 절대 삭제되지 않습니다. `deleterData`는 영구히 남고, `user`와 IP 주소만 제거됩니다.
* 사용자의 개인 액세스 토큰은 계정과 함께 삭제되지 않습니다. [OAuth Access Tokens 컬렉션](/ko/dev/data-model/oauth-access-tokens-collection)을 참고하세요.
* Mongoose는 `deleterData`에도 자체 `_id`를 부여하지만, 이를 읽는 곳은 없습니다.
