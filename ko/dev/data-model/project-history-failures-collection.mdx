---
title: Project History Failures 컬렉션
icon: triangle-exclamation
---

`projectHistoryFailures`에는 project-history가 기록 업데이트를 처리하지 못했거나 재동기화를 시작한 프로젝트마다 문서 하나가 저장됩니다. 처리가 성공하면 문서는 곧바로 다시 삭제됩니다. project-history가 `services/project-history/app/js/ErrorRecorder.js`에서 쓰며, 타입은 `services/project-history/app/js/mongo-types.ts:3-24`에 있습니다. Web에도 이에 대한 Mongoose 스키마가 있지만(`services/web/app/src/models/ProjectHistoryFailure.mjs:5-19`) 그 모델을 사용하는 Web 코드는 없습니다.

#### 쓰는 곳 {#who-writes-it}

| 코드 | 하는 일 |
| ---- | ------------ |
| `services/project-history/app/js/ErrorRecorder.js:34-66` | `record`: 오류를 upsert하고, `attempts`를 1 늘리고, `history`에 항목을 추가합니다. 프로젝트의 업데이트 처리가 실패할 때(`UpdatesProcessor.js:91`, `169`, `242`, `293`, `345`)와 재동기화를 시작할 수 없을 때(`SyncManager.js:75`, `96`) 호출합니다. |

#### 참고 {#notes}

* 문서는 프로젝트의 flush가 성공하거나 프로젝트가 삭제될 때까지 남습니다(위의 `clearError`). 따라서 각 문서는 마지막 flush나 재동기화가 아직 성공하지 않은 프로젝트를 나타냅니다.
* `OError:`로 시작하는 오류 문자열은 `Error:`로 반환됩니다(`ErrorRecorder.js:18-26`). 저장된 값은 바뀌지 않습니다.
