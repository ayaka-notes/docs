---
title: Project History Sharded Blobs 컬렉션
icon: cubes-stacked
---

`projectHistoryShardedBlobs`에는 [projectHistoryBlobs](/dev/data-model/project-history-blobs-collection)에 들어가지 못한 blob 레코드가 저장됩니다. 해시 접두사의 버킷에 이미 레코드가 8개 있으면 이후 레코드는 여기로 옵니다. 프로젝트당 문서는 최대 16개이며, 해시의 첫 16진수 자리마다 하나입니다. Mongoose 스키마는 없습니다. history-v1이 `services/history-v1/storage/lib/blob_store/mongo.js`에서 씁니다(레이아웃 설명은 `mongo.js:1-16`).

#### 필드 {#fields}

| 필드 | 타입 | 의미 | 출처 |
| ----- | ---- | ------- | ------ |
| `_id` | Binary | 13바이트: 프로젝트의 기록 ID(`0`)와 샤드 숫자로, 16진수로 읽습니다(`<history id>0<digit>`). 샤드 숫자는 해시의 첫 16진수 자리입니다. | `mongo.js:439-453` |
| `blobs` | Object | 버킷으로 묶인 blob 레코드. 버킷의 키는 해시의 2~4번째 16진수 자리입니다. | `mongo.js:439-443` |
| `blobs.<bcd>` | Array of Object | 버킷의 레코드. 코드에서 크기를 제한하지 않습니다. | `mongo.js:399-407` |
| `blobs.<bcd>[].h` | Binary | 해시, 20바이트로 projectHistoryBlobs와 같습니다. | `mongo.js:472` |
| `blobs.<bcd>[].b` | Number | 내용의 바이트 길이. | `mongo.js:473` |
| `blobs.<bcd>[].s` | Number | 텍스트로서의 내용 길이. 내용이 편집 가능한 텍스트가 아니면 `null`입니다. | `mongo.js:474` |

#### 쓰는 곳 {#who-writes-it}

| 코드 | 하는 일 |
| ---- | ------------ |
| `services/history-v1/storage/lib/blob_store/mongo.js:399-407` | `insertRecordSharded`: `$addToSet`로 버킷에 upsert합니다. projectHistoryBlobs의 버킷이 가득 찼을 때 `insertBlob`에서 호출합니다(`mongo.js:387-389`). |
| `mongo.js:75-103` | `clone`: 프로젝트의 샤드를 다른 기록 ID로 복사합니다. history-v1 `POST /projects/:project_id/clone`용이며, Web에는 이를 호출하는 코드가 없습니다. |
| `mongo.js:413-422` | `deleteBlobs`: history-v1 `DELETE /projects/:project_id`에서 프로젝트의 모든 샤드를 projectHistoryBlobs 문서와 함께 삭제합니다. |

#### 읽는 곳 {#who-reads-it}

| 코드 | 하는 일 |
| ---- | ------------ |
| `mongo.js:144-157` | `findBlobSharded`: blob 하나. projectHistoryBlobs의 버킷에 레코드가 8개 있고 그 안에 없을 때만 조회합니다(`mongo.js:127-131`). |
| `mongo.js:217-260` | `findBlobsSharded`: `findBlobs`가 projectHistoryBlobs에서 찾지 못한 blob(`mongo.js:202-206`). |
| `mongo.js:285-306` | `getProjectBlobs`: 프로젝트의 모든 샤드. |
| `mongo.js:337-361` | `getProjectBlobsBatch`: 여러 프로젝트의 모든 샤드로, blob 통계 경로에 사용합니다. |

#### 인덱스 {#indexes}

기본 `_id` 인덱스만 있습니다. `tools/migrations/`의 어떤 마이그레이션도 인덱스를 추가하지 않습니다.

#### 참고 {#notes}

* 한 프로젝트의 샤드는 `_id` 순서로 나란히 있으므로, 코드는 `<history id>00`부터 `<history id>0f`까지의 `_id` 범위로 찾습니다(`mongo.js:75-80`, `287-295`).
* 이 컬렉션은 어떤 프로젝트에 같은 3자리 해시 접두사를 가진 blob이 8개를 넘어야 생기므로, 작은 인스턴스에는 아예 없을 수 있습니다.
