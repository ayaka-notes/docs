title: Project History Sync State 컬렉션

`projectHistorySyncState`에는 재동기화된 프로젝트마다 문서 하나가 있으며, 현재 또는 마지막 재동기화의 상태를 담습니다. 재동기화는 project-history가 web과 docstore에 있는 내용으로 프로젝트 기록을 다시 만드는 작업입니다. project-history가 소유하며 Mongoose 스키마는 없습니다. 코드는 `services/project-history/app/js/SyncManager.js`의 `SyncState` 클래스와 그 헬퍼입니다.

#### 필드 {#fields}

| 필드 | 타입 | 의미 | 출처 |
| ----- | ---- | ------- | ------ |
| `_id` | ObjectId | upsert로 생성됩니다. | `SyncManager.js:233-237` |
| `project_id` | ObjectId | 프로젝트입니다. | `SyncManager.js:233-237` |
| `resyncProjectStructure` | Boolean | project-history가 web으로부터 프로젝트 구조(파일 트리)를 기다리는 동안 `true`입니다. | `SyncManager.js:457`, `536-543` |
| `resyncDocContents` | Array of String | 아직 내용을 기다리고 있는 doc의 경로입니다. | `SyncManager.js:458`, `482`, `545-546` |
| `origin` | Object | 재동기화를 요청한 주체입니다. 예를 들어 기본값인 `{ kind: 'history-resync' }`입니다. | `SyncManager.js:150`, `459` |
| `hardResync` | Boolean | 하드 재동기화이면 `true`입니다. 하드 재동기화는 먼저 대기 중인 업데이트와 이전 동기화 상태를 버립니다. | `SyncManager.js:81-100`, `152`, `460` |
| `recoverCorruptedFiles` | Boolean | 재동기화 요청의 옵션입니다(`HttpController.js:963-964`). 하드 재동기화에서 기록 내용이 손상된 doc은 제거된 뒤 docstore에서 다시 추가됩니다(`SyncManager.js:942-951`). | `SyncManager.js:153`, `461` |
| `history` | Array of Object | 최신순으로 정렬된 마지막 100개 상태로, 각각 `{ syncState, timestamp }`입니다. `syncState`에는 위의 다섯 필드가 들어 있습니다. | `SyncManager.js:41`, `202-208` |
| `lastUpdated` | Date | 마지막으로 쓴 시각입니다. | `SyncManager.js:209` |
| `resyncCount` | Number | 시작된 재동기화 횟수입니다. | `SyncManager.js:215` |
| `resyncPendingSince` | Date | 실행 중인 재동기화가 시작된 시각입니다. 끝나면 제거됩니다. | `SyncManager.js:217`, `224-225` |
| `expiresAt` | Date | 재동기화가 끝난 뒤 90일 후로 설정되며, 재동기화가 실행되는 동안에는 제거됩니다. TTL 인덱스가 이 시각에 문서를 삭제합니다. | `SyncManager.js:42`, `216`, `221-223` |
| `stuckClearCount` | Number | 멈춘 재동기화가 정리되고 다시 시작된 횟수입니다. 재동기화가 끝나면 제거됩니다. | `SyncManager.js:261`, `226` |
| `lastStuckClearAt` | Date | 마지막으로 그렇게 정리한 시각입니다. | `SyncManager.js:262`, `227` |
| `lastStuckDocPaths` | Array of String | 마지막 정리 시점에 아직 대기 중이던 doc 경로입니다. | `SyncManager.js:262`, `228` |

#### 쓰는 코드 {#who-writes-it}

| 코드 | 역할 |
| ---- | ------------ |
| `services/project-history/app/js/SyncManager.js:195-249` | `setResyncState`: 상태를 upsert합니다. 재동기화가 시작될 때(`SyncManager.js:163`)와 project-history가 재동기화 업데이트를 처리하는 동안(`services/project-history/app/js/UpdatesProcessor.js:637`, `784`) 호출됩니다. |
| `SyncManager.js:257-266` | `_recordStuckClearInSyncState`: 정리된 멈춘 재동기화를 셉니다. |
| `SyncManager.js:251-255` | `clearResyncState`: 문서를 삭제합니다. 하드 재동기화 시작 시(`SyncManager.js:87`), project-history `DELETE /project/:project_id`에서(`services/project-history/app/js/HttpController.js:1363-1396`), 구조만 하는 재동기화를 다시 시작해야 할 때(`SyncManager.js:705-716`) 실행됩니다. |
| `SyncManager.js:273-289` | `clearResyncStateIfAllAfter`: 기록이 모두 특정 날짜 이후인 완료된 상태를 삭제합니다. `app/js`에서 이를 호출하는 곳은 없습니다. |
| `SyncManager.js:171-181` | `cloneResyncState`: project-history `POST /project/:project_id/clone`(`HttpController.js:57`, `124`)을 위해 상태를 다른 프로젝트로 복사합니다. web에서 이를 호출하는 곳은 없습니다. |

재동기화는 project-history `POST /project/:project_id/resync`(`HttpController.js:950-994`), 재시도 cron 작업(`services/project-history/app/js/RetryManager.js:156-179`, `server-ce/config/crontab-history`), 그리고 업데이트 처리에 필요할 때 project-history 자신(`UpdatesProcessor.js:75`, `224`)이 시작합니다.

#### 읽는 코드 {#who-reads-it}

| 코드 | 역할 |
| ---- | ------------ |
| `SyncManager.js:187-193` | `getResyncState`: 상태를 불러옵니다. 새 재동기화를 시작하기 전에 실행 중인 것이 있는지 판단하고(`SyncManager.js:106-149`), 실행 중에는 일반 업데이트를 건너뛰며(`SyncManager.js:291-300`), 플러시 후 실행 중인 재동기화를 보고하는 데(`UpdatesProcessor.js:463-466`) 사용됩니다. |
| `HttpController.js:533-545` | `GET /project/:project_id/resync-pending`: 재동기화가 실행 중이거나 멈췄는지 여부입니다. |
| `HttpController.js:563-585` | `GET /project/:project_id/debug-info`: 실패 레코드와 함께 동기화 상태를 보여 줍니다. |

#### 참고 {#notes}

* `resyncProjectStructure`가 `true`이거나 `resyncDocContents`가 비어 있지 않은 동안 재동기화가 실행 중입니다(`SyncManager.js:565-567`). 4시간이 지나면 멈춘 것으로, 5번 정리된 뒤에는 영구적으로 멈춘 것으로 간주합니다(`SyncManager.js:43-44`, `569-585`).
* 재동기화가 끝나면 project-history는 프로젝트에 `overleaf.history.lastResyncedAt`도 설정합니다(`SyncManager.js:239-248`).
