`gitlabSyncProjectStates`는 GitLab 프로젝트에 연결된 프로젝트마다 문서 하나를 보관합니다. 어떤 저장소인지, 그리고 마지막 동기화가 어디까지 진행됐는지를 기록합니다. 이 컬렉션은 `gitlab-sync` 웹 모듈(`services/web/modules/gitlab-sync`)에 속합니다. 스키마는 `services/web/modules/gitlab-sync/app/models/gitlabSyncProjectStates.mjs`에 있으며, 모든 접근은 `services/web/modules/gitlab-sync/app/src/SyncStateManager.mjs`를 거칩니다. 필드는 [GitHub Sync Project States](/ko/dev/data-model/github-sync-project-states-collection)와 같습니다.

#### 필드 {#fields}

| 필드 | 타입 | 의미 | 출처 |
| ----- | ---- | ------- | ------ |
| `_id` | ObjectId | 생성 시 Mongoose가 설정합니다. | |
| `projectId` | ObjectId | 연결된 프로젝트. 필수. 스키마에는 `unique: true`가 있지만 인덱스는 만들어지지 않습니다(인덱스 참고). | `gitlabSyncProjectStates.mjs:8` |
| `repoFullName` | String | 네임스페이스를 포함한 GitLab 프로젝트 경로(GitLab의 `path_with_namespace`), 예: `group/subgroup/name`. 필수. | `gitlabSyncProjectStates.mjs:9`, `GitLabApiClient.mjs:347` |
| `defaultBranchName` | String | 프로젝트가 동기화하는 브랜치. 프로젝트를 연결할 때 설정되며 이후 바뀌지 않습니다. 가져오기에서는 가져오기 폼이 보낸 브랜치, 내보내기에서는 새 저장소의 기본 브랜치이며 API가 알려 주지 않으면 `main`입니다. 기본값 `null`. | `gitlabSyncProjectStates.mjs:10`, `GitLabSyncHandler.mjs:175-181,234-240`, `GitLabApiClient.mjs:346-349` |

| `lastSyncCommit` | String | 마지막 동기화 시점에 동기화 대상 브랜치의 커밋 SHA. 기본값 `null`. | `gitlabSyncProjectStates.mjs:12` |

#### 쓰는 코드 {#who-writes-it}

| 코드 | 역할 |
| ---- | ------------ |
| `SyncStateManager.mjs:9-14` (`createProjectState`) | 문서를 만듭니다. 저장소를 새 프로젝트로 가져온 뒤(`services/web/modules/gitlab-sync/app/src/GitLabSyncHandler.mjs:175-181`) 또는 프로젝트를 새 저장소로 내보낸 뒤(`GitLabSyncHandler.mjs:234-240`, 소유자만 가능, 이미 연결된 경우 거부)입니다. |
| `SyncStateManager.mjs:16-21` (`updateProjectState`) | 변경된 필드를 `$set`합니다. 동기화 대상 브랜치에 `lastSyncCommit`이 더 이상 포함되지 않거나(머지 베이스 검사, `services/web/modules/gitlab-sync/app/src/GitLabApiClient.mjs:460`), 커밋이 사라졌고 사용자가 푸시할 수 있으면(`GitLabSyncHandler.mjs:123,126-137`) `getMergeOverview`가 `mergeStatus: 'diverged'`를 설정합니다. 동기화(`services/web/modules/gitlab-sync/app/src/GitMerge.mjs`)는 성공하면 `lastSyncCommit`/`lastSyncVersion`을 옮기고(예: `:152,189,231`), 충돌을 `unmergedBranchName`, `unmergedBranchHead`, `conflictVersion`으로 기록하며(`:214-220`), 충돌이 해결되면 이를 지웁니다(`:257-264`). |
| `SyncStateManager.mjs:23-25` (`removeProjectState`) | 소유자가 프로젝트 연결을 해제할 때(`GitLabSyncHandler.mjs:83-97`)와 삭제된 프로젝트가 만료될 때(`services/web/modules/gitlab-sync/index.mjs:46-48`) 문서를 삭제합니다. |

#### 인덱스 {#indexes}

| 이름 | 키 | 옵션 | 마이그레이션 |
| ---- | ---- | ------- | --------- |
| `_id_` | `_id: 1` | | default |

Mongoose `autoIndex`가 꺼져 있으므로(`services/web/app/src/infrastructure/Mongoose.mjs:7`), 스키마의 `projectId`에 있는 `unique: true`는 아무것도 만들지 않습니다. 이 컬렉션의 인덱스를 만드는 마이그레이션은 없습니다.

#### 참고 {#notes}

* GitLab API는 GitHub처럼 브랜치를 임의의 커밋으로 옮길 수 없습니다. 동기화는 앞으로 진행할 수 있으면 동기화 대상 브랜치에 바로 커밋하고, 그렇지 않으면 임시 브랜치에 커밋한 뒤 머지 리퀘스트로 병합합니다(`GitMerge.mjs:16-21`).
* 동기화는 프로젝트의 `gitSync` 락 아래에서 실행되며, 이 락은 GitHub Sync 및 Gitea Sync와 공유됩니다(`GitMerge.mjs:25-32`).
* 삭제된 프로젝트는 만료될 때까지 문서를 유지합니다.
* 사용자의 GitLab 토큰은 [GitLab Sync User Credentials](/ko/dev/data-model/gitlab-sync-user-credentials-collection)에 있습니다.
