---
title: Project History Blobs 컬렉션
icon: cubes
---

`projectHistoryBlobs`에는 프로젝트 기록마다 문서 하나가 있으며, history-v1이 해당 프로젝트를 위해 저장한 모든 blob의 메타데이터(해시와 크기)를 담습니다. blob은 파일이나 doc의 기록 중 어느 시점의 내용입니다. 바이트 자체는 프로젝트 blob 버킷의 객체입니다. Mongoose 스키마는 없습니다. history-v1이 `services/history-v1/storage/lib/blob_store/mongo.js`에서 컬렉션에 쓰며, CE에서처럼 16진수 24자의 기록 id에 이를 사용합니다(`services/history-v1/storage/lib/blob_store/index.js:108-116`).

#### 필드 {#fields}

| 필드 | 타입 | 의미 | 출처 |
| ----- | ---- | ------- | ------ |
| `_id` | ObjectId | 프로젝트의 기록 id로, `projects.overleaf.history.id`의 값입니다. | `mongo.js:37-40` |
| `blobs` | Object | 버킷별로 묶인 blob 레코드입니다. 버킷의 키는 해시의 처음 16진수 3자리입니다. | `mongo.js:39`, `429-431` |
| `blobs.<abc>` | Array of Object | 해시가 `abc`로 시작하는 레코드 최대 8개입니다. 버킷에 이미 8개가 있으면 다음 레코드는 [Project History Sharded Blobs 컬렉션](/ko/dev/data-model/project-history-sharded-blobs-collection)로 갑니다. | `mongo.js:23`, `375-389` |
| `blobs.<abc>[].h` | Binary | 해시, 20바이트: git blob SHA-1, `sha1("blob " + byteLength + "\0" + content)`(`libraries/overleaf-editor-core/lib/blob_utils.js:36-43`). 이 값의 16진수 형식이 다른 곳에서 쓰이는 해시이며, 예를 들어 프로젝트의 `fileRefs.hash`입니다. | `mongo.js:472` |
| `blobs.<abc>[].b` | Number | 내용의 바이트 길이입니다. | `mongo.js:473` |
| `blobs.<abc>[].s` | Number | 텍스트로서의 내용 길이입니다. 내용이 편집 가능한 텍스트가 아니면(바이너리이거나 편집하기에 너무 큼) `null`입니다(`blob_utils.js:116-130`). | `mongo.js:474` |

#### 쓰는 코드 {#who-writes-it}

| 코드 | 역할 |
| ---- | ------------ |
| `services/history-v1/storage/lib/blob_store/mongo.js:34-47` | `initialize`: history-v1이 프로젝트 기록을 만들 때 `{ _id, blobs: {} }`를 삽입합니다(`services/history-v1/storage/lib/chunk_store/index.js:67-68`). |
| `mongo.js:370-390` | `insertBlob`: 버킷의 레코드가 8개 미만이면 레코드를 해당 버킷에 `$addToSet`하고, 그렇지 않으면 샤딩된 컬렉션에 넣습니다. 바이트 업로드 후 `putString`, `putBlob`, `copyBlob`에서 실행됩니다(`blob_store/index.js:223-237`, `271-278`, `456-467`). |
| `mongo.js:54-105` | `clone`: history-v1 `POST /projects/:project_id/clone`을 위해 버킷을 다른 기록 id로 복사합니다. web에서 이 라우트를 호출하는 곳은 없습니다([Project History Chunks 컬렉션](/ko/dev/data-model/project-history-chunks-collection) 참고). |
| `mongo.js:413-422` | `deleteBlobs`: history-v1 `DELETE /projects/:project_id`에서 문서와 프로젝트의 샤딩된 문서를 삭제합니다(`services/history-v1/api/controllers/projects.js:361-373`). |

새 blob이 오는 곳:

* 파일 업로드: web이 파일을 history-v1 `PUT /projects/:project_id/blobs/:hash`로 보냅니다(`services/web/app/src/Features/History/HistoryManager.mjs:164-169`, `services/history-v1/api/controllers/projects.js:376-402`).
* 프로젝트 복사: web이 history-v1에 `POST /projects/:project_id/blobs/:hash?copyFrom=`로 각 파일의 blob 복사를 요청합니다(`services/web/app/src/Features/Project/ProjectDuplicator.mjs:333-338`, `HistoryManager.mjs:177-187`, `projects.js:521-555`).
* doc 텍스트: history-v1이 청크를 쓸 때 각 doc의 텍스트와 그 댓글 및 변경 내용 추적(JSON)을 blob으로 저장합니다(`chunk_store/index.js:402-405`, `libraries/overleaf-editor-core/lib/file_data/string_file_data.js:166-173`).

#### 읽는 코드 {#who-reads-it}

| 코드 | 역할 |
| ---- | ------------ |
| `mongo.js:113-157` | `findBlob`: 해시로 blob 하나를 찾습니다. 버킷이 가득 차면 샤딩된 컬렉션에서 찾습니다. `BlobStore.getBlob`(`blob_store/index.js:376-387`)이 blob 라우트(`projects.js:416-480`)에 사용하며, 삽입 전에 이미 있는 blob을 건너뛰는 데도 사용합니다(`blob_store/index.js:441-448`). |
| `mongo.js:165-260` | `findBlobs`: 청크의 파일을 불러오기 위해 많은 blob을 한 번에 찾습니다. |
| `mongo.js:265-309` | `getProjectBlobs`: 프로젝트의 모든 blob입니다. |
| `mongo.js:316-363` | `getProjectBlobsBatch`: history-v1 `POST /projects/blob-stats`(`projects.js:620`)를 위한 여러 프로젝트의 모든 blob입니다. admin-tools 모듈은 결과를 프로젝트 크기로 보여 줍니다(`services/web/modules/admin-tools/app/src/AdminProjectManager.mjs:395-405`). |

#### 인덱스 {#indexes}

기본 `_id` 인덱스만 있습니다. `tools/migrations/`의 어떤 마이그레이션도 인덱스를 추가하지 않습니다.

#### 참고 {#notes}

* blob의 바이트는 버킷 `OVERLEAF_EDITOR_PROJECT_BLOBS_BUCKET`(`services/history-v1/config/custom-environment-variables.json:49-52`)의 키 `<project key>/<hash[0:2]>/<hash[2:]>`(`blob_store/index.js:51-53`)에 있습니다. 프로젝트 키는 0으로 채운 기록 id를 뒤집어 3/3/나머지 문자로 나눈 것입니다(`libraries/object-persistor/src/ProjectKey.js:8-15`).
* blob은 프로젝트마다 한 번만 저장됩니다. 프로젝트에 이미 있는 해시의 삽입은 건너뜁니다(`blob_store/index.js:227-230`, `249-252`).
* 빈 내용에는 레코드가 필요 없습니다. `getBlob`은 조회 없이 응답합니다(`blob_store/index.js:378-380`).
* `projectHistoryGlobalBlobs`는 시작 시 읽히지만(`blob_store/index.js:138-148`) CE 코드는 여기에 쓰지 않으므로, CE에서는 모든 blob이 프로젝트 blob입니다.
