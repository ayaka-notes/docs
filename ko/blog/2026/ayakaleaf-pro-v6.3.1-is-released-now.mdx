커뮤니티에서 가장 강력하고 기능이 풍부한 온라인 LaTeX 편집기인 Overleaf Pro 6.3.1의 출시를 매우 자랑스럽게 발표합니다. 패치 릴리스라고 하면 보통 몇 가지 작은 수정에 그칩니다. 하지만 이번 릴리스는 훨씬 더 나아갑니다. 수십 건의 버그 수정과 함께 다섯 가지 새로운 기능을 선보이며, Dropbox와 GitLab부터 터미널 속 AI 에이전트까지, 이미 작업하고 있는 곳과 프로젝트를 연결해 줍니다.

### 변경 사항

* Dropbox 동기화(얼리 프리뷰): 모든 프로젝트를 자신의 Dropbox와 양방향으로 동기화합니다.
* GitLab 동기화(얼리 프리뷰): GitLab.com 또는 자체 관리형 GitLab과 양방향으로 동기화합니다.
* MCP 서버: Claude Code, Codex, Cursor, VS Code 또는 Gemini CLI가 프로젝트에서 직접 작업할 수 있습니다.
* GitHub Enterprise: GitHub 동기화가 자체 GitHub Enterprise 인스턴스를 사용하도록 설정할 수 있습니다.
* 손글씨 기호 인식: 기호를 그리면 해당하는 LaTeX 명령을 알려 줍니다.
* `OVERLEAF_DISABLE_LOCAL_LOGIN`: 이메일 및 비밀번호 로그인을 숨겨 사용자가 SSO로만 로그인하도록 합니다.
* E2E 테스트 시스템과 Internal Horizon Issue Investigation으로 발견한 버그 수정.
* 업스트림 Overleaf 6.3.1 패치.

<Info>

Dropbox 동기화와 GitLab 동기화는 그레이 테스트를 위한 **얼리 프리뷰**로 6.3.1에 포함되며, v6.4.0에서 정식 출시될 예정입니다. 그 전까지 구성과 동작이 변경될 수 있습니다. 두 기능 모두 기본적으로 꺼져 있습니다. 문제가 있으면 [GitHub](https://github.com/ayaka-notes/ayakaleaf-pro/issues)에 보고해 주세요.

</Info>

#### 기능 01: Dropbox 동기화(프리뷰)

Git에 대해서는 전혀 신경 쓰고 싶지 않은 사람들도 있습니다. 그저 논문이 노트북의 폴더 하나이기를 바랄 뿐이고, Dropbox 동기화가 바로 그것을 제공합니다. 각 사용자가 자신의 Dropbox 계정을 연결하면, 소유한 프로젝트와 공유된 프로젝트가 `Apps/<your app name>/` 아래에 나타납니다. Overleaf에서 편집하면 변경 사항이 Dropbox에 나타납니다. 즐겨 쓰는 편집기에서 로컬 파일을 편집하고 저장하면, 변경 사항이 서명된 웹훅을 통해 Overleaf로 돌아옵니다.

관리자용: Git bridge가 활성화되어 있어야 합니다. Dropbox App Console에서 앱을 만든 다음 `DROPBOX_ENABLED`, `DROPBOX_APP_KEY`, `DROPBOX_APP_SECRET`, `DROPBOX_APP_NAME`, `DROPBOX_TOKEN_CIPHER_PASSWORD`를 설정하세요. `DROPBOX_SYNC_PROXY_URL`은 선택 사항으로, Dropbox에 직접 접근할 수 없는 서버를 위한 것입니다. 그런 다음 사용자가 계정을 연결하기 전에 Dropbox 동기화에 필요한 MongoDB 인덱스를 한 번 생성하세요.

전체 설정 방법은 [Dropbox 동기화](/ko/on-premises/configuration/overleaf-toolkit/dropbox-synchronisation  "mention")를 참고하세요.

#### 기능 02: GitLab 동기화(프리뷰)

GitHub 동기화는 6.2부터 가장 사랑받는 기능 중 하나였지만, 많은 대학과 기업은 코드를 GitLab에서 관리합니다. GitLab 동기화도 같은 방식으로 동작합니다. 계정을 연결하고, 새 프로젝트 메뉴에서 저장소를 가져오거나 프로젝트를 새 GitLab 프로젝트로 내보내세요. 그런 다음 편집기에서 푸시와 풀을 하고, 머지 리퀘스트를 통해 병합하면 됩니다.

GitLab.com과 자체 관리형 GitLab 15.10 이상에서 동작합니다. `GITLAB_SYNC_ENABLED`, `GITLAB_SYNC_CLIENT_ID`, `GITLAB_SYNC_CLIENT_SECRET`, `GITLAB_TOKEN_CIPHER_PASSWORD`를 설정하고, 자체 관리형 인스턴스의 경우 `GITLAB_SYNC_URL`도 설정하세요.

전체 설정 방법은 [GitLab 동기화](/ko/on-premises/configuration/overleaf-toolkit/gitlab-synchronisation  "mention")를 참고하세요.

#### 기능 03: MCP 서버

6.3에서는 편집기 안에 AI 어시스턴트를 넣었습니다. 6.3.1에서는 반대 방향으로 문을 엽니다. 이제 모든 프로젝트가 자체 MCP 서버를 가지므로, 이미 사용 중인 AI 에이전트가 논문에서 직접 작업할 수 있습니다. Claude Code에게 서론의 오타를 고쳐 달라고 하거나, Codex에게 컴파일하고 LaTeX 오류를 수정해 달라고 하거나, Cursor에게 아직 열려 있는 검토 댓글에 답해 달라고 할 수 있습니다. 에이전트는 파일을 실시간으로 읽고 편집하므로, 여러분과 공동 작업자는 에이전트가 입력하는 대로 편집 내용이 편집기에 나타나는 것을 볼 수 있습니다. 컴파일, 로그 읽기, PDF 가져오기, 단어 수 세기, 버전 목록 보기도 가능합니다.

엔드포인트는 `/project/<project_id>/mcp`입니다. `git clone`에 사용하는 것과 같은 Git 토큰으로 인증합니다. 접근 권한은 프로젝트의 공유 설정을 따르므로 뷰어의 에이전트는 읽을 수는 있지만 편집할 수는 없으며, 모든 도구에는 속도 제한이 적용됩니다. 그 밖에 구성할 것은 없습니다. MCP 서버는 Git bridge와 함께 활성화됩니다.

<img src="https://github.com/user-attachments/assets/a8702201-db3f-4985-a050-b7ebdbe7a952" alt="MCP 서버" width="787" />

각 AI 클라이언트를 연결하는 방법은 [MCP 서버](/ko/on-premises/configuration/overleaf-toolkit/mcp-server  "mention")를 참고하세요.

#### 기능 04: GitHub Enterprise

GitHub 동기화는 더 이상 github.com에만 국한되지 않습니다. `GITHUB_SYNC_URL`을 GitHub Enterprise Server 또는 데이터 레지던시가 적용된 GitHub Enterprise Cloud(`GHE.com`)로 설정하면, REST 및 GraphQL 엔드포인트가 이를 바탕으로 자동으로 도출됩니다. 인스턴스 구성이 특이한 경우 `GITHUB_SYNC_API_URL`과 `GITHUB_SYNC_GRAPHQL_URL`로 재정의할 수 있습니다. 설정하지 않으면 모든 것이 github.com에 그대로 유지됩니다.

자세한 내용은 [GitHub 동기화](/ko/on-premises/configuration/overleaf-toolkit/github-synchronisation#github-enterprise  "mention")를 참고하세요.

#### 기능 05: 손글씨 기호 인식

기호가 어떻게 생겼는지는 알지만 이름을 모를 때가 있습니다. `\varsigma`일까요, `\zeta`일까요? `\models`일까요, `\vDash`일까요? 기호 팔레트를 그리기 모드로 전환하고 마우스나 트랙패드로 그려 보세요. 팔레트가 일치하는 LaTeX 명령을 제안합니다.

인식은 ayaka-notes가 학습시킨 모델로 전적으로 브라우저에서 실행되므로, 그린 내용이 사용자의 컴퓨터를 벗어나지 않습니다. `OffscreenCanvas`를 지원하지 않는 브라우저(예: Safari 15)에서는 그리기 전환 버튼이 숨겨집니다.

#### 버그 수정

이번 릴리스에는 많은 수정 사항도 포함되어 있습니다. 그중 상당수는 이제 모든 모듈의 테스트 스위트를 매일 실행하는 새로운 E2E 테스트 시스템과 Internal Horizon Issue Investigation을 통해 발견되었습니다. 저희는 버그를 하나 수정할 때마다, 이를 닫기 전에 코드베이스 전체에서 비슷한 버그를 찾아냅니다.

* **인증**: SSO 인스턴스에서도 로컬 계정이 비밀번호를 설정하고 변경할 수 있으며, OIDC 사용자는 더 이상 자신의 이메일을 변경할 수 없습니다. 이름 속성에 여러 값이 있어도 LDAP, SAML, OIDC 로그인이 더 이상 실패하지 않으며, SAML/OIDC 로그아웃이 다시 동작합니다.
* **정지된 사용자**: 이제 사용자를 정지하면 해당 사용자의 세션이 종료되고 열려 있는 편집기가 닫히며, 해당 사용자의 Git 토큰과 MCP 다운로드가 거부됩니다.
* **GitHub 동기화**: 소유자만 프로젝트를 내보낼 수 있고, 풀하는 동안 이루어진 편집은 대기 상태로 유지되며, 빈 파일도 동기화되고, 수동 병합은 GitHub에서 검증됩니다.
* **Zotero / Mendeley**: 자격 증명이 더 이상 작동하지 않으면 다시 연결하라는 메시지가 표시되며, 가져오기 후 참고문헌이 다시 인덱싱됩니다.
* **외부 서비스**: Zotero, Mendeley, GitHub, GitLab, 웹 검색에 대한 요청의 연결 시간 제한이 1초에서 3초로 늘어나, 느린 네트워크에서도 더 이상 실패하지 않습니다.
* **변경 내용 추적**: 검토 데이터에 로드되지 않은 문서와 저장되지 않은 변경 사항이 포함됩니다.
* **관리자 패널**: 삭제된 프로젝트 복원, 소유자 변경, 사용자 편집이 올바르게 동작하며, 이메일 전송에 실패해도 더 이상 계정 생성이나 삭제가 중단되지 않습니다.
* **템플릿 갤러리**: 잘못된 정렬은 500 대신 400을 반환하며, 메인 파일이 없는 프로젝트를 게시할 때 메인 파일을 지정하도록 요청합니다.

전체 목록은 [6.3.1 릴리스 노트](/ko/on-premises/release-notes/release-notes-6.x.x#ayakaleaf-pro-6.3.1  "mention")를 참고하세요.

#### 업그레이드

* 6.3.0에서: 마이그레이션이 필요하지 않습니다. 새 이미지를 받고 다시 시작하세요.
* Zotero 또는 Mendeley를 사용하는 6.2.x 이하에서: 먼저 6.3.0의 [Zotero / Mendeley 마이그레이션](/ko/on-premises/release-notes/release-notes-6.x.x#ayakaleaf-pro-6.3.0  "mention")을 실행하세요.
* Dropbox 동기화와 GitLab 동기화는 기본적으로 꺼져 있습니다. GitLab 동기화에는 새 환경 변수만 필요합니다. Dropbox 동기화는 사용자가 계정을 연결하기 전에 MongoDB 인덱스도 한 번 생성해야 합니다. [데이터베이스 인덱스 생성](/ko/on-premises/configuration/overleaf-toolkit/dropbox-synchronisation#create-the-database-indexes  "mention")을 참고하세요.
