### Docker

Docker는 애플리케이션을 격리된 컨테이너에 패키징하고 실행하는 가볍고 이식성 높은 방법을 제공합니다. 애플리케이션과 필요한 모든 의존성을 함께 묶어, 노트북부터 운영 서버까지 서로 다른 머신에서도 일관된 동작을 보장합니다.

TeX Live는 강력하지만 용량이 크고 시스템 수준의 차이에 민감합니다. TeX Live를 Docker 이미지에 패키징하면 LaTeX 툴체인을 예측 가능하고 재현 가능하며 배포하기 쉽게 만들 수 있습니다.

다만 일부 TeX Live 패키지는 셸 접근에 의존합니다. 보안상의 이유로 컨테이너는 사용자가 임의의 셸 명령(예: `\write18` 또는 shell escape)을 실행할 수 없도록 제한된 환경에서 실행해야 합니다. 이러한 격리는 호스트 시스템을 보호하고, 컨테이너의 기반 파일 시스템이나 `bash` 같은 도구에 의도치 않게 접근하는 것을 방지합니다.

### TeXLive Full Edition

[TeXLive-Full@ayaka-notes](https://github.com/ayaka-notes/texlive-full/)는 [Ayakaleaf Pro](https://github.com/ayaka-notes/ayakaleaf-pro), [Overleaf CEP](https://github.com/yu-i-i/overleaf-cep) 또는 독립 실행형 LaTeX 컴파일 환경에서 샌드박스 LaTeX 컴파일을 위해 설계된 모든 기능을 갖춘 **TeXLive Docker 이미지**입니다.

이 이미지는 누락된 패키지나 글꼴로 인한 컴파일 실패를 최소화하기 위해, 일반적인 글꼴과 도구가 미리 설치된 거의 완전한 TeXLive 배포판을 제공하는 것을 목표로 합니다. 참고: 이 Docker 이미지에는 sharelatex/overleaf 구성 요소가 **포함되어 있지 않습니다**. Overleaf/Overleaf Pro의 컴파일에 사용됩니다.

#### 기능:

* 🚀 x86\_64 및 arm64 서버 아키텍처 모두 지원
* 📦 완전하고 최적화된 TeXLive 설치
* 🧩 일반적인 글꼴 및 유틸리티 사전 설치
* 🐳 Docker 및 Docker Compose에서 바로 사용 가능
* 🧪 Overleaf Server Pro / Overleaf Pro에서 테스트됨
* 🔄 최신 TeXLive 릴리스에 맞춰 정기적으로 업데이트
* 🏷 여러 TeXLive 버전 태그 제공(2020 – 최신)
* 🧑‍🔬 LaTeX 문서 내 R 코드를 위한 Knitr 지원

### Ayakaleaf Pro에서 사용하기

Ayaka-notes의 TeX Live Full은 [ayakaleaf-pro](https://github.com/ayaka-notes/ayakaleaf-pro)를 위해 특별히 설계되었습니다. [Toolkit 사용자](https://github.com/overleaf/toolkit)라면 `config/variables.env` 파일에 다음 환경 변수를 사용할 수 있습니다.

예시:

```dotenv title="config/variables.env" wrap
ALL_TEX_LIVE_DOCKER_IMAGES=ghcr.io/ayaka-notes/texlive-full:2026.1, ghcr.io/ayaka-notes/texlive-full:2025.1
ALL_TEX_LIVE_DOCKER_IMAGE_NAMES=Texlive 2026, Texlive 2025
TEX_LIVE_DOCKER_IMAGE=ghcr.io/ayaka-notes/texlive-full:2026.1
```

### TeX Live 버전

GitHub Action 덕분에 모든 TeX 이미지를 병렬로 빌드할 수 있으며, 다음 이미지가 포함됩니다.

* `ghcr.io/ayaka-notes/texlive-full:2026.1` (`latest` 태그도 동일)
* `ghcr.io/ayaka-notes/texlive-full:2025.1`
* `ghcr.io/ayaka-notes/texlive-full:2024.1`
* `ghcr.io/ayaka-notes/texlive-full:2023.1`
* `ghcr.io/ayaka-notes/texlive-full:2022.1`
* `ghcr.io/ayaka-notes/texlive-full:2021.1`
* `ghcr.io/ayaka-notes/texlive-full:2020.1`
* `ghcr.io/ayaka-notes/texlive-full:base`

[texlive info](https://texlive.info/tlnet-archive/)의 미러 아카이브를 사용하며, 여기에는 1996년부터 2025년까지의 거의 모든 TeX Live 이미지가 포함되어 있습니다. 또한 Overleaf의 Dockerfile 덕분에 이 프로젝트를 더 빠르게 빌드할 수 있습니다.

> TeX Live 2019 이하 버전은 왜 지원되지 않나요?
>
> 이러한 오래된 이미지를 유지 관리하는 것은 매우 어렵습니다. 또한 [texlive.info](https://texlive.info/) 웹사이트는 2019년 이전에 릴리스된 TeX Live 버전에 대한 정보를 제공하지 않으므로 해당 버전의 이미지를 빌드할 수 없습니다. 특정 이전 버전이 필요하다면 이슈를 등록해 알려 주세요.

### 포함된 구성 요소

Docker 이미지에는 다음 패키지가 포함되어 있습니다.

* 모든 TeXLive 패키지(해당 연도 기준)
* R 패키지(일부만)
* fontconfig inkscape pandoc python3-pygments wget python3
* gnupg gnuplot perl-modules perl ca-certificates
* ghostscript qpdf r-base-core tar

Docker 이미지에는 다음 글꼴이 포함되어 있습니다.

* [Google Fonts](https://fonts.google.com/)
* [Microsoft msttcorefonts](https://packages.ubuntu.com/jammy/ttf-mscorefonts-installer)
* [Overleaf 지원 글꼴](https://www.overleaf.com/learn/latex/Questions/Which_OTF_or_TTF_fonts_are_supported_via_fontspec%3F)

<Warning>

관련 글꼴을 상업적으로 사용할 수 있는지 확인하세요. 글꼴을 잘못 사용하여 발생하는 법적 문제에 대해 당사는 **책임지지 않습니다**. 이미지를 다운로드하면 이에 자동으로 동의하는 것으로 간주됩니다.

</Warning>

### 문제 해결

<Accordion title="문제 01: 글꼴 캐시 누락 문제">

Overleaf가 LaTeX 프로젝트를 컴파일할 때 글꼴 누락이 발생하면 **컴파일 진행에 오랜 시간이 걸릴 수 있습니다**. 글꼴이 누락되면 TeX Live가 **전체 글꼴 캐시를 다시 빌드**하려고 하기 때문입니다. 이는 시간이 많이 걸리는 작업입니다.

이 이미지에서는 글꼴 캐시를 미리 빌드해 두었으며, [이 커밋](https://github.com/ayaka-notes/texlive-full/commit/0cb66b0dc8b82be628cf6999cfd659d9784e132f)으로 이 문제를 해결했습니다.

</Accordion>

<Accordion title="문제 02: SyncTeX가 매우 느림">

sharelatex에서 이 이미지를 사용할 때 SyncTeX가 매우 느릴 수 있습니다.

[https://github.com/overleaf/overleaf/issues/1150](https://github.com/overleaf/overleaf/issues/1150)을 참조하세요. HTTP 2.0을 비활성화하면 됩니다.

</Accordion>

<Accordion title="문제 03: 공식 TeX Live 이미지에서 재컴파일 오류">

Docker Hub의 TeX Live 공식 이미지 `texlive/texlive`를 사용하면 프로젝트를 다시 컴파일할 때 오류가 발생할 수 있습니다. 하지만 이 이미지에서는 이 문제가 해결되어 있습니다. 최신 Ubuntu 베이스 이미지를 사용하고 모든 의존성을 Ubuntu 공식 저장소에서 설치하기 때문입니다.

</Accordion>

### 기타 기술 참고 사항

2019년 이전의 TeX Live 이미지를 빌드할 때는 다음 문제에 주의해야 할 수 있습니다.

* TeX Live 2017 이전에는 `http`/`ftp`만 지원되므로, `peal` 스크립트를 수정하지 않는 한 `https`로 다운로드할 수 없습니다.
* 2015년 이전에는 sha256 파일만 제공됩니다. 따라서 sha512로 검증할 수 없습니다.
