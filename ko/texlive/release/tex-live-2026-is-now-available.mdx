이 문서는 [Overleaf 블로그](https://www.overleaf.com/blog/tex-live-2026-is-now-available)에서 가져온 것입니다. Overleaf는 2026년 8월 18일에 TeX Live 2026을 출시했습니다. 저희도 [ayaka-notes/texlive-full](https://github.com/ayaka-notes/texlive-full)을 TeX Live 2026으로 업데이트했습니다.

</Info>

무엇이 바뀌었는지, 전환하기 전에 무엇을 확인해야 하는지, 그리고 가장 흔한 새 오류를 어떻게 해결하는지 알아보겠습니다. 이번 릴리스에서 가장 주목할 만한 업데이트는 접근성 있는 PDF를 생성하는 기능이 프로토타입 단계를 벗어나 실제 프로덕션 워크플로에서 사용할 수 있게 되었다는 점입니다. 이번 업데이트에서는 새롭거나 업데이트된 TeX 관련 프로그램, 글꼴, 매크로 패키지도 사용할 수 있습니다. 이 블로그 글에서는 알아야 할 모든 핵심 정보와 중요한 변경 사항을 다룹니다.

Overleaf는 모든 것이 예상대로 작동하는지 엄격한 테스트를 거친 후 매년 한 번 공식 업데이트를 출시합니다. 이는 수백만 명의 Overleaf 사용자에게 일관되고 안정적인 경험을 제공하고, 지원팀이 문제나 질문에 대해 도움을 드릴 수 있도록 하기 위함입니다.

### TeX Live란 무엇인가요?

[TeX Live](https://tug.org/texlive/)는 LaTeX를 비롯한 많은 TeX 관련 프로그램, 글꼴, 매크로 패키지를 포함하는 TeX 조판 시스템의 무료 배포판으로, TeX 사용자 핵심 그룹과 [TeX User Group](https://tug.org/)이 유지 관리합니다. Overleaf는 컴파일 서버에서 TeX Live를 사용하여 미리보기를 제공하고 프로젝트 PDF를 생성합니다.

TeX Live 2026이 도입되면서 사용자는 읽을 수 있는 수식을 포함하여 완전히 접근 가능한 태그된 PDF를 만들 수 있게 됩니다.

### 기존 프로젝트는 평소처럼 작동하나요?

네, 기존 프로젝트는 생성 당시의 TeX Live 버전을 계속 사용하므로 그대로 작동합니다. 필요한 경우가 아니라면 기존 프로젝트의 TeX Live 버전을 변경하지 않는 것을 권장합니다. 변경하면 새로운 오류나 경고가 발생할 수 있습니다.

<strong>참고:</strong> Overleaf 갤러리의 일부 템플릿은 접근성 옵션을 활성화하면 작동하지 않거나 컴파일되지 않을 수 있습니다. 대부분의 템플릿은 Overleaf가 만들거나 유지 관리하지 않으므로, 문제가 있으면 템플릿 제작자에게 문의하세요.

### 기존 프로젝트에서 TeX Live 2026으로 전환할 수 있나요?

네, 기존 프로젝트에서 TeX Live 2026으로 쉽게 전환할 수 있으며, 전환 과정은 간단하고 번거롭지 않습니다. 변경하려는 프로젝트에서 _Settings_를 열고 사이드바에서 _Compiler_를 클릭하면 TeX Live 버전을 선택할 수 있는 드롭다운이 표시됩니다. 이를 통해 특정 TeX Live 버전으로 제출물을 컴파일하는 출판사, 프리프린트 서버 및 기타 플랫폼의 요구 사항에 맞게 프로젝트를 빠르게 업데이트할 수 있습니다.

프로젝트가 TeX Live 2025(또는 이전 버전)에서는 문제없이 컴파일되었지만 TeX Live 2026에서 오류가 발생한다면, 커널이나 일부 패키지의 변경 때문일 수 있습니다. 일부 패키지는 TeX Live 2026에서 새로운 오류나 경고를 발생시키는 것으로 알려져 있으며, 가장 흔한 사례와 해결 방법을 아래 별도 섹션에 정리했습니다.

### TeX Live 2026의 주요 변경 사항

#### 태그된 접근성 PDF가 프로토타입 단계를 벗어났습니다

LaTeX Project의 [2025년 11월 업데이트](https://www.latex-project.org/news/latex2e-news/ltnews42.pdf) 이후로 태깅은 더 이상 프로토타입으로 설명되지 않으며, 문서가 이미 태깅을 지원하는 패키지와 클래스만 사용한다면 프로덕션 워크플로에서 사용할 수 있는 것으로 간주됩니다.

태그된 PDF 출력을 활성화하려면 `\documentclass` 앞에 명령 하나만 넣으면 됩니다.

```latex
\DocumentMetadata{
 pdfstandard = {UA-2, A-4f},
 tagging = on,
 lang = en
 }
\documentclass{article}
```

`\DocumentMetadata`를 사용하면 몇 가지 기본값도 켜집니다. T1 글꼴 인코딩, 그리고 [2025년 6월부터](https://www.latex-project.org/news/latex2e-news/ltnews41.pdf) 이전의 1.7 대신 **PDF 2.0** 출력이 사용됩니다. 여기서 PDF 2.0이 중요한 이유는 MathML 태깅(수식을 라벨 없는 기호 덩어리가 아니라 스크린 리더가 읽을 수 있게 만드는 요소)을 가능하게 하기 때문입니다.

몇 가지 실용적인 참고 사항:

* 초안 작성 중에는 `tagging = draft`로 설정하여 접근성 경고는 유지하면서 구조 트리 작성은 건너뛸 수 있습니다(긴 문서의 컴파일 속도를 높이는 데 유용합니다).
* check-tagging-status 키는 사용 중인 패키지가 태깅과 호환되는 것으로 알려져 있는지를 로그 끝에 보고합니다. 시작하기 전에 확인할 수 있는 [실시간 상태 데이터베이스](https://latex3.github.io/tagging-project/tagging-status/)도 있습니다.
* 태깅 코드 없이 PDF 관리 기능만 원한다면, 이를 위한 별도의 `pdfmanagement` 패키지가 새로 생겼습니다.

특히 주의할 변경 사항이 하나 있습니다. 이제 `\DocumentMetadata`는 문서에서 한 번만 호출할 수 있습니다. 두 번째로 호출하면 `\documentclass`를 두 번 호출할 때와 마찬가지로 컴파일 오류가 발생합니다.

#### 의미를 담은 접근성 있는 수식

[2025년 11월부터 새로 도입된](https://www.latex-project.org/news/latex2e-news/ltnews42.pdf) `\MathMLintent`와 `\MathMLarg`를 사용하면 저자는 표기가 어떻게 구성되었는지뿐 아니라 무엇을 의미하는지도 보조 기술에 알려줄 수 있습니다. 예를 들어 `|y|`를 _"bar y bar"_ 대신 _"y의 절댓값"_으로 소리 내어 읽을 수 있습니다.

접근성 있는 수식 태깅을 사용하려면 MathML을 생성하는 엔진인 LuaLaTeX로 컴파일해야 하며, `unicode-math` 또는 `lua-unicode-math` 패키지 중 하나가 필요합니다.

#### 그래픽과 그림도 이제 의미를 담습니다

접근성은 텍스트와 수식에만 국한되지 않습니다. 이제 `\includegraphics`, `picture`, `tikzpicture`가 접근성 키를 받으므로 각 그래픽을 적절하게 마크업할 수 있습니다.

```latex
\includegraphics[alt={A bar chart of quarterly revenue}]{revenue}
```

그래픽은 네 가지로 분류할 수 있습니다. 실제 설명용 그림, 보조 도구가 무시해야 할 장식용 아티팩트, 기호를 대신하는 그래픽, 또는 일반 텍스트(`todonotes` 같은 경우에 유용)입니다. TikZ 출력은 기본적으로 지원됩니다.

#### 태그된 접근성 프레젠테이션을 만들기 위한 새 클래스

`beamer` 문서 클래스는 LaTeX로 프레젠테이션 슬라이드를 만드는 데 매우 인기가 있습니다. 안타깝게도 이 클래스는 LaTeX 태깅 코드와 호환되지 않습니다. 대신 새로운 문서 클래스인 [`ltx-talk`](https://ctan.org/pkg/ltx-talk)가 처음부터 새로 만들어졌습니다. 문법은 `beamer`와 대체로 비슷하지만, `beamer`의 모든 기능이 `ltx-talk`에 구현된 것은 아닙니다.

#### 절 제목 스타일 지정을 위한 새로운 템플릿 메커니즘

절 제목 명령이 새로운 템플릿 메커니즘으로 LaTeX 커널에 다시 구현되어, `titlesec` 같은 패키지가 LaTeX 태깅 코드와 완전히 호환되지 않는 문제를 해결했습니다. 간단한 예시는 다음과 같습니다.

```latex
\EditInstance{heading}{section}{
  number-format=\fbox{\LARGE\bfseries\theheading},
  title-decls=\Large\bfseries\sffamily\color{blue},
  before-vspace=20pt,
}
```

자세한 정보는 [문서](https://tug.ctan.org/macros/latex-dev/required/latex-lab/latex-lab-sec-template.pdf)에서 확인할 수 있습니다.

#### 내부부터 재구축된 커널

올해 커널에서는 몇 가지 제한이 제거되었습니다.

* <strong>출력 루틴을 이제 구성할 수 있습니다:</strong> 거의 40년 동안 LaTeX의 페이지 조립 메커니즘은 사실상 고정되어 있어, 이를 변경해야 하는 패키지는 내부 코드를 덮어써야 했습니다. 이제는 대신 변경을 위한 훅과 소켓을 제공합니다. 패키지가 더 안정적이 되고 서로 충돌할 가능성이 줄어듭니다.
* <strong>현대적인 마크 메커니즘:</strong> 서로 얽힌 두 개의 마크만 지원하던 기존 `\markboth` / `\leftmark` / `\rightmark` 시스템이 임의 개수의 독립적인 마크를 지원하는 유연한 시스템 위에 재구축되었으며, 익숙한 명령은 이전과 똑같이 계속 작동합니다.
* <strong>블록 환경과 절 제목이 이제 템플릿 위에서 동작합니다:</strong> 목록, 인용, 정리 계열 환경, 그리고 이제 제목 명령까지 일관된 기반 시스템을 공유합니다. 실용적인 이점 하나: LaTeX가 `enumitem`이나 `amsthm`의 `\newtheoremstyle` 같은 인기 패키지를 기본적으로 에뮬레이션하기 시작했으며, `titlesec` 에뮬레이션도 진행 중입니다. 이제 목록이나 정리 상자의 스타일을 바꾸기 위해 패키지를 설치할 필요가 줄어듭니다.
* <strong>정리 계열 환경의 더 나은 상호 참조:</strong> 새로운 `\newcounteralias` 명령 덕분에 정리와 카운터를 공유하는 보조정리(lemma)가 `cleveref`, `zref-clever` 또는 `hyperref`로 참조될 때 _"theorem 1"_이 아니라 _"lemma 1"_로 올바르게 표시됩니다.

문서뿐 아니라 패키지를 유지 관리한다면 주목할 만한 변경 사항이 두 가지 있습니다. 커널은 이제 공식적으로 **2023-11-27 이후 날짜의 `expl3`**를 요구하며, `\textsuperscript`, `\parbox`/`minipage` 같은 구성 요소와 표 구조 주변에서 _"가짜 수식"_(상자 배치만을 위해 수식 모드를 사용하는 것)이 제거되었습니다. 이는 태깅과 오른쪽에서 왼쪽으로 쓰는 텍스트 지원을 개선하지만, `\showoutput` 결과를 이전 TeX Live 버전과 비교하면 차이를 느낄 수 있습니다.

#### 새로운 지원 범위: 더 많은 언어

* 벵골어, 구자라트어, 칸나다어, 말라얄람어, 싱할라어, 타밀어, 텔루구어를 포함한 <strong>브라흐미 계열 문자의 색인</strong>이 `upmendex`에 실험적으로 도입되었습니다.
* 새로운 **BCP 47 언어 메타데이터** 키(`language`, `other-languages`)를 사용하면 지역 변형까지 문서의 언어를 정확하게 선언할 수 있으며, 이는 PDF 자체의 언어 메타데이터에도 반영됩니다.

#### 그 밖에 알아둘 사항

* `enumerate`, `theorem`, `verbatim` 패키지는 이제 레거시로 간주됩니다. 새 문서에서는 각각 `enumitem`, `amsthm`, `fancyvrb`를 사용하는 것이 좋습니다.
* 이전 PDF 버전을 요구하는 인쇄 워크플로나 플랫폼을 사용하는 경우에도 PDF 버전을 직접 설정할 수 있으며(예: `\DocumentMetadata{pdfversion=1.7}`), TeX Live 2026 문서에서 이전 기본값을 대상으로 문서를 컴파일하는 방법을 다룹니다.
* TeX Live 2026의 [공식 릴리스 노트](https://tug.org/texlive/doc/texlive-en/texlive-en.html#news)와 [모든 TeX Live 버전의 릴리스 노트](https://www.tug.org/texlive/doc/texlive-en/texlive-en.html#x1-710009)는 TeX Users Group(TUG) 웹사이트에서 확인할 수 있습니다.

### TeX Live 2026의 영향을 받는 주요 패키지

다음 섹션에서는 Tex Live 2025에서는 성공적으로 컴파일되었지만 TeX Live 2026에서는 컴파일 오류가 발생하게 되는 몇 가지 변경 사항을 소개합니다.

#### 지원되지 않는 표 관련 패키지

LaTeX 커널의 표 구조가 새롭게 변경되면서 `tabu`와 `tabls` 패키지는 TL2026에서 더 이상 지원되지 않으며, 이제 컴파일 오류를 일으킵니다. `arydshln` 패키지도 `tabularx`나 `tabular*` 환경 등 다른 패키지와 호환되지 않을 수 있습니다. 마찬가지로 `\@array`와 `\tabular`를 재정의하는 패키지나 템플릿도 표 형태 구조 주변에서 컴파일 오류를 일으킵니다.

#### `babel`의 더 이상 사용되지 않는 언어 옵션

`frenchb`와 `francais` 언어 옵션은 이제 더 이상 사용되지 않습니다. 이 옵션은 `french`로 대체해야 합니다.

#### `varioref` 버그

[`varioref` 패키지의 버그](https://github.com/latex3/latex2e/issues/2112#issuecomment-4881772493)로 인해 KOMA-Script 문서 클래스에서 이 패키지를 불러오면 TeX capacity exceeded 오류가 발생하고 PDF가 생성되지 않습니다.

```text
\documentclass{scrartcl}
\usepackage{varioref}
\begin{document}
Hello World!
\end{document}
```

해결 방법은 프리앰블에

```text
\def\extrasenglish{}
```

를 추가하는 것입니다.

#### KOMA-script 클래스와 `capt-of`

KOMA-script 문서 클래스(`scrbook`, `scrartcl`, `scrreport`, `scrletter`)는 이제 `\captionof`를 정의하므로 `capt-of` 패키지를 더 이상 불러오지 않아야 합니다. (반면 `caption` 패키지는 이 문서 클래스와 함께 불러와도 여전히 안전합니다.)

#### `thmtools`: `sibling`/`numberlike`/`sharenumber` 오류

`thmtools` 옵션 `sibling`(또는 `numberlike`, `sharenumber`)으로 새 정리 계열 환경을 선언하면 `Command \c@proposal already defined`처럼 [카운터가 이미 정의되어 있다는 오류](https://github.com/muzimuzhi/thmtools/issues/75)가 발생합니다.

```text
\documentclass{article}
\usepackage{thmtools}
\declaretheorem{theorem}
\declaretheorem{proposal}[sibling=theorem]

\begin{document}

\begin{theorem}This is a theorem.\end{theorem}
\begin{proposal}This is a proposal.\end{proposal}

\end{document}
```

해결 방법은 프리앰블에서 `thmtools`를 불러온 후, `\declaretheorem` 앞에 다음 줄을 추가하는 것입니다.

```text
\makeatletter
\@ifundefined{newcounteralias}{}{%
  \renewcommand\thmt@autorefsetup{\@xa\def\csname\thmt@envname autorefname\@xa\endcsname\@xa{\thmt@thmname}}%
}
\makeatother
```

#### `polyglossia`, `xepersian`, `array`

아랍 문자 조판을 위해 `polyglossia` 또는 `xepersian` 패키지를 사용하면서 `array` 패키지나 `array`를 불러오는 다른 표 관련 패키지를 불러온 경우, 표 형태 구조 안에 아랍어 텍스트를 넣으면 `\UseMathForPositioningText`가 정의되지 않았다는 오류가 발생합니다.

```text
\documentclass[12pt,a4paper]{article}
\usepackage{polyglossia}
\usepackage{array}
\setdefaultlanguage{arabic}
\newfontfamily\arabicfont[Script=Arabic]{Noto Naskh Arabic}
\begin{document}
\begin{tabular}{c}
السلام عليكم
\end{tabular}
\end{document}
```

이 문제는 `\documentclass` 선언 앞에 `\DocumentMetadata{}`를 추가하여 해결할 수 있습니다. 또는 아랍 문자 조판에 `babel` 패키지로 전환하는 것을 고려해 보세요.

#### `babel-spanish`와 `biblatex-apa`

`biblatex` 스타일 `apa`를 사용하면서 `babel-spanish`를 불러오면 훅과 `\@makecaption`에 관한 컴파일 오류가 발생합니다.

```text
\usepackage[spanish]{babel}
\usepackage[style=apa]{biblatex}
```

하지만 `babel`에 `shorthands=off` 옵션을 추가하면 이 오류를 피할 수 있습니다.

#### `xgreek`, `hyperref`, `\appendix`

`xgreek`(XeLaTeX 및 LuaLaTeX 전용)와 `hyperref` 패키지를 불러오면 `\appendix` 뒤에 오는 절 제목에서 컴파일 오류가 발생합니다.

```text
\documentclass{article}
\usepackage{xgreek}
\usepackage{fontspec}
\setmainfont{GFS Artemisia}
\usepackage{hyperref}
\begin{document}
\section{Εισαγωγή}
\appendix
\section{Δεδομένα}
\end{document}
```

해결 방법은 `hyperref`에 `hypertexnames=false` 옵션을 추가하는 것입니다.

#### `flowfram`과 `titlesec`

현재 `flowfram`과 `titlesec` 패키지는 서로 호환되지 않습니다. 하지만 새로운 `\EditInstance` 인터페이스를 사용하여 절 제목의 스타일을 지정하는 것을 고려해 볼 수 있습니다. 예:

```text
\DocumentMetadata{}
\documentclass{article}
\usepackage{flowfram}
\usepackage[dvipsnames]{xcolor}
\EditInstance{heading}{section}{
  number-format=\fbox{\LARGE\bfseries\theheading},
  title-decls=\Large\bfseries\sffamily\color{NavyBlue}
}
\begin{document}
\section{Introduction}
\end{document}
```

자세한 내용은 [이 링크](https://mirrors.ctan.org/macros/latex-dev/required/latex-lab/latex-lab-sec-template.pdf)를 참고하세요.
