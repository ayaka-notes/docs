我们在这里整理了一些关于 Ayakaleaf Pro 的常见问题解答。

### 基本问题

<Accordion title="Q01：Ayakaleaf Pro 是免费试用版吗？需要许可证吗？">

不是。Ayakaleaf Pro 完全免费使用。它不是试用版，也不需要任何许可证。

</Accordion>

<Accordion title="Q02：Ayakaleaf Pro 是否包含 Overleaf Server Pro 的所有功能？">

是的。Ayakaleaf Pro 包含 Overleaf Server Pro 的所有功能，包括 Git-Bridge 集成。它还包含 Overleaf SaaS 平台的部分功能。我们会持续开发和改进 Ayakaleaf Pro。

</Accordion>

<Accordion title="Q03：Overleaf Server Pro 的价格是多少？">

Overleaf Server Pro 每位用户每年的费用约为 \$300。它至少需要购买 10 个许可证，因此部署起步价约为每年 \$3,000。美国一些较小规模的公开合同显示，每位用户每年的费用约为 \$320–\$370。这使得 Server Pro 价格昂贵，对于小型团队尤其如此。有关已记录的采购和价格信息，请参阅 [#information-and-price-about-overleaf-server-pro](/zh-Hans/on-premises#information-and-price-about-overleaf-server-pro  "mention")。

</Accordion>

<Accordion title="Q04：为什么 Overleaf Server Pro 不包含 GitHub 同步或 AI 功能？">

Overleaf Server Pro 通常被政府机构使用。它们将其部署在私有网络中，并严格控制访问。为了保护敏感数据，其包含的功能会避免与第三方服务交换数据。如果你需要 GitHub 同步、AI 或类似的联网功能，Overleaf 建议订阅其 SaaS 平台。

</Accordion>

<Accordion title="Q05：Ayakaleaf Pro 安全可靠吗？">

Ayakaleaf Pro 是开源的。我们使用 Codex Security 等工具审查代码，以增强其安全性和可靠性。如果你不启用第三方数据同步，你的数据将始终保留在你的服务器上。Ayakaleaf Pro 不包含任何会将你的数据发送到其他地方的遥测功能。

</Accordion>

<Accordion title="Q06：Ayakaleaf Pro 会长期维护吗？">

我们将尽一切努力长期维护这个项目。

</Accordion>

<Accordion title="Q07：Ayakaleaf Pro 是否合规？">

Ayakaleaf Pro 是一个社区分支。其代码和集成功能来自社区贡献，并采用 AGPL v3 许可证。只要满足该许可证的要求，部署即可符合其规定。

</Accordion>

<Accordion title="Q08：为什么项目名为 Ayakaleaf Pro？">

该项目最初于 2024 年命名为 Overleaf Pro。开发曾暂停一段时间，之后在 2025 年底重新启动。2026 年第一季度，Overleaf 将其支持 AI 的订阅计划更名为 Pro。社区反馈也指出，Overleaf Pro 这个名称可能带来商标和冒充风险，可能会让用户误以为该项目是官方项目。

为避免这种混淆，我们将项目更名为 Ayakaleaf Pro。这个名称可以理解为"Ayaka-notes Overleaf Pro"。维护者（你可以叫我 ayaka！）从五年多前的学生时代起就一直为 Overleaf 社区开发做贡献。这段经历是我们长期维护承诺的有力支撑。

</Accordion>

<Accordion title="Q09：Ayakaleaf Pro 与新近出现的 AI 构建的 LaTeX 编辑器有何不同？">

自 2026 年以来，开源社区发布了许多 AI 构建的 LaTeX 编辑器，包括 OpenAI Prism。Ayakaleaf Pro 将你的数据和服务保留在你自己的服务器上，让你能够直接掌控自己的部署和数据。

许多实验性的社区编辑器并没有成熟的长期维护计划。第三方 LaTeX 编译平台也可能在用户群或收入不足时停止运营。Ayakaleaf Pro 提供全部源代码，并允许你自行托管每一项服务。即使维护停止，你现有的自托管服务也可以继续运行。

</Accordion>

<Accordion title="Q10：GitHub 仓库 ayaka-notes/overleaf-pro 怎么了？">

随着项目更名（参见 Q08），它已被重命名为 [ayaka-notes/ayakaleaf-pro](https://github.com/ayaka-notes/ayakaleaf-pro)。它并没有被归档或替换：这是同一个仓库，GitHub 会将旧的 `ayaka-notes/overleaf-pro` 链接和 Git 远程地址重定向到新名称。Docker 镜像保留其名称 `ghcr.io/ayaka-notes/overleaf-pro`，因此你无需修改 `config/overleaf.rc` 或 `config/version`。

</Accordion>

### 功能

<Accordion title="Q01：Ayakaleaf Pro 提供哪些功能？我可以申请新功能吗？">

请查阅我们的文档以了解当前的功能列表。如果你希望我们添加某项功能，欢迎在 GitHub 上提交 issue（功能请求）。我们会尽力实现所请求的功能，但开发需要时间，我们无法保证每项功能都能立即交付。

</Accordion>

<Accordion title="Q02：我开发了一些功能。我可以提交 PR 吗？它一定会被接受吗？">

欢迎贡献，但我们不保证一定会接受。我们会根据每个 PR 对底层 Overleaf 代码库的影响、维护负担以及为用户带来的价值来进行评估。我们会尽力合并并维护有价值的贡献。

但是，对于引入过多更改、由未经审查或理解不足的 AI 生成代码（“vibe coding”）构成，或添加难以长期维护的功能的 PR，我们可能会拒绝。

</Accordion>

<Accordion title="Q03：如何配置某项特定功能？">

我们通常会在发布新功能时同步更新文档。有关详细的设置说明以及可用环境变量的解释，请参阅相关文档。

</Accordion>

<Accordion title="Q04：Python Runner 可以使用哪些 Python 库？">

Python Runner 使用 [Pyodide](https://pyodide.org/) 0.29.3 在用户的浏览器中运行 Python，而不是在服务器上运行。它会从 [Pyodide 内置的包](https://pyodide.org/en/0.29.3/usage/packages-in-pyodide.html)中加载你的代码所导入的包，例如 NumPy、pandas 和 Matplotlib。通过 `pip` 安装的包及其他包均不可用。服务器端无需任何配置。

</Accordion>

<Accordion title="Q05：拼写检查可以检查日语或中文吗？">

不可以。拼写检查器没有日语或中文词典，因此这些语言不在拼写检查语言列表中。用户可以在编辑器设置中为项目关闭拼写检查。

若不希望某个单词被标记为拼写错误，请右键单击该单词并选择 **Add to dictionary**。添加的单词会保存到你的账户中，并应用于你的所有项目。如需查看或删除这些单词，请打开编辑器设置，然后依次进入 **Spelling and language → Dictionary → Edit**。添加单词并不会新增拼写检查语言。

</Accordion>

<Accordion title="Q06：我可以添加插件吗？">

没有插件安装程序。各项功能是源代码中 `services/web/modules` 下的模块，内置在 Docker 镜像中，并通过本文档中的设置启用。如需添加你自己的功能，请在源代码中添加一个模块并构建你自己的镜像。

</Accordion>

### 部署

<Accordion title="Q01：Ayakaleaf Pro 是否支持在 k8s 中进行分布式部署？">

对于大多数用户，我们建议使用 [Toolkit](/zh-Hans/on-premises/installation/using-the-toolkit) 进行部署。Kubernetes 支持目前处于实验阶段：[使用 Kubernetes](/zh-Hans/on-premises/installation/using-kubernetes) 展示了我们在单副本或多副本下测试过的清单文件，但集群会增加运维复杂度和维护工作量。[沙盒编译](/zh-Hans/on-premises/configuration/overleaf-toolkit/sandboxed-compiles)通过 Docker socket 创建编译容器，因此每个运行 Ayakaleaf Pro 的节点都需要 Docker Engine。我们不提供 CRI-O、Podman 或 Quadlet 配置。

</Accordion>

<Accordion title="Q02：在为数千名用户提供服务时，如何确保可用性？">

请参阅我们的[水平扩展](/zh-Hans/on-premises/maintenance/horizontal-scaling)指南。你可以部署多个 Overleaf 实例，并配置负载均衡器在它们之间分配流量。

</Accordion>

<Accordion title="Q03：你们可以帮我部署或迁移吗？">

如果你已有 Overleaf Server Pro 实例，我们很乐意帮助你迁移到 Ayakaleaf Pro。请通过电子邮件或 issue 与我们联系。

</Accordion>

<Accordion title="Q04：我可以将 Ayakaleaf Pro 托管在 URL 子路径下吗，例如 `https://example.com/overleaf`？">

不可以。Ayakaleaf Pro 必须从域名的根路径提供服务。请使用专用的域名或子域名，例如 `https://overleaf.example.com`。

</Accordion>

<Accordion title="Q05：我可以在 Windows 或 macOS 上运行 Ayakaleaf Pro，或者不使用 Toolkit 吗？">

我们支持使用 [Toolkit](/zh-Hans/on-premises/installation/using-the-toolkit) 的 Linux 服务器。Windows、WSL2 或 macOS 上的 Docker Desktop 也许可以运行，但我们不对其进行测试，已知的 MongoDB 问题请参阅[故障排除](/zh-Hans/on-premises/support/troubleshooting)。

我们不提供独立的 `docker-compose.yml`。要查看 Toolkit 使用的 Compose 配置，请在 Toolkit 目录中运行 `bin/docker-compose config`。

</Accordion>

<Accordion title="Q06：如何卸载 Ayakaleaf Pro？">

没有卸载脚本。在 Toolkit 目录中：

1. 使用 `bin/docker-compose down` 停止并删除容器。
2. 删除数据。默认情况下，数据位于 Toolkit 的 `data/` 目录中。如果你在 `config/overleaf.rc` 中修改了 `OVERLEAF_DATA_PATH`、`MONGO_DATA_PATH`、`REDIS_DATA_PATH` 或 `GIT_BRIDGE_DATA_PATH`，也请删除这些目录。此操作无法撤销，因此如果你可能还需要这些数据，请先进行[备份](/zh-Hans/on-premises/maintenance/data-and-backups)。
3. 删除 Toolkit 目录。
4. 删除 Docker 镜像（可以使用 `docker images` 列出）：`ghcr.io/ayaka-notes/overleaf-pro`、git-bridge 镜像、`mongo`、`redis` 以及 TeX Live 镜像。

</Accordion>

<Accordion title="Q07：如何停止、启动或重启 Ayakaleaf Pro？">

请在 Toolkit 目录中运行以下命令：

* `bin/stop` 停止所有容器，`bin/start` 重新启动它们。容器会被保留，因此用户会保持登录状态。
* `bin/up -d` 创建容器并在后台启动。修改 `config/variables.env`、`config/overleaf.rc` 或 `config/version` 后请运行它：它会重新创建配置发生变化的容器，只有这样更改才会生效。`bin/stop` 和 `bin/start` 不会应用这些更改。
* `bin/docker-compose restart sharelatex` 只重启 Overleaf 容器，不会应用配置更改。

如果每次 `bin/up` 重新创建容器时用户都会退出登录，请设置 `OVERLEAF_SESSION_SECRET`，参见[环境变量](/zh-Hans/on-premises/configuration/overleaf-toolkit/environment-variables)中的问答。

</Accordion>

<Accordion title="Q08：OAuth 回调 URL 应该填写在哪里？">

填写在你于服务提供方创建的应用中，而不是 Ayakaleaf Pro 中。这些集成在 `config/variables.env` 中都没有回调设置：Ayakaleaf Pro 会根据 `OVERLEAF_SITE_URL` 构建每个回调 URL 并发送给服务提供方，如果它与为该应用注册的 URL 不匹配，服务提供方就会拒绝。因此，你只需在服务提供方处注册它，并将 `OVERLEAF_SITE_URL` 设置为用户访问的地址。

| 集成 | 服务提供方处的字段 | 值 |
| --- | --- | --- |
| [GitHub](/zh-Hans/on-premises/configuration/overleaf-toolkit/integrations/github-synchronisation) | Authorization callback URL | `${OVERLEAF_SITE_URL}/user/github-sync/oauth2/callback` |
| [GitLab](/zh-Hans/on-premises/configuration/overleaf-toolkit/integrations/gitlab-synchronisation) | Redirect URI | `${OVERLEAF_SITE_URL}/user/gitlab-sync/oauth2/callback` |
| [Gitea](/zh-Hans/on-premises/configuration/overleaf-toolkit/integrations/gitea-synchronisation) | Redirect URIs | `${OVERLEAF_SITE_URL}/user/gitea-sync/oauth2/callback` |
| [Dropbox](/zh-Hans/on-premises/configuration/overleaf-toolkit/integrations/dropbox-synchronisation) | Redirect URIs（点击 **Add**） | `${OVERLEAF_SITE_URL}/user/dropbox/oauth/callback` |
| [Zotero](/zh-Hans/on-premises/configuration/overleaf-toolkit/integrations/zotero-integration) | Callback URL | `${OVERLEAF_SITE_URL}/user/zotero/oauth/callback` |
| [Mendeley](/zh-Hans/on-premises/configuration/overleaf-toolkit/integrations/mendeley-integration) | Redirect URL | `${OVERLEAF_SITE_URL}/user/mendeley/oauth/callback` |
| [OIDC 登录](/zh-Hans/on-premises/configuration/overleaf-toolkit/authentication/oidc-authentication) | Redirect URI | `${OVERLEAF_SITE_URL}/oidc/login/callback` |
| [SAML 登录](/zh-Hans/on-premises/configuration/overleaf-toolkit/authentication/saml-authentication) | ACS URL（Assertion Consumer Service） | `${OVERLEAF_SITE_URL}/saml/login/callback` |

如果你修改了 `OVERLEAF_SITE_URL`（例如改用新域名），也请在每个服务提供方处更新该 URL，否则关联将会失败。

</Accordion>

<Accordion title="Q09：数据存储在哪里？我需要多少磁盘空间？">

默认情况下，所有数据都保存在服务器本地磁盘上 Toolkit 的 `data/` 目录中：`data/overleaf`（项目文件、历史记录和编译输出）、`data/mongo` 和 `data/redis`。对于用户数少于 1000 的实例，我们推荐使用本地磁盘并定期进行[备份](/zh-Hans/on-premises/maintenance/data-and-backups)。

Ayakaleaf Pro 镜像大约占用 5 GB。[简介](/zh-Hans/on-premises/installation/introduction)中 40 GB 的最低要求是针对沙盒编译的，其 `texlive-full` 镜像每个约占 28 GB。如果不使用沙盒编译，编译将在 `sharelatex` 容器内运行，使用 TeX Live basic 方案外加 `latexmk`、`texcount`、`synctex`、`etoolbox` 和 `xetex`，因此许多项目会因缺少宏包而编译失败。此后 `data/` 目录会随着你的项目及其历史记录不断增长；可以使用 `du -sh data/*` 进行检查。

</Accordion>

### LaTeX

<Accordion title="Q01：用户的 LaTeX 项目编译是否相互隔离？是否启用了 Shell Escape？">

启用沙盒编译后，每个用户的编译都会在单独的 Docker 容器中运行，并与其他用户的编译相互隔离。沙盒编译默认启用 Shell Escape。

</Accordion>

<Accordion title="Q02：沙盒编译镜像可靠吗？编译会失败吗？">

在过去三年里，我们持续改进了用于沙盒编译的 TeX Live Full 镜像。在大多数情况下，能在 overleaf.com 上编译的项目也能在 Ayakaleaf Pro 中正确编译。如果缺少所需的字体，请手动将该字体上传到你的项目中。

</Accordion>

<Accordion title="Q03：我的项目无法编译。你们可以帮我排查问题吗？">

请将你的项目上传到 Overleaf 官方网站，启用只读链接共享，并在 GitHub issue 中附上该链接。

如果某个项目能在 Overleaf 官方网站上成功编译，却无法在 Ayakaleaf Pro 中编译，我们会调查并修复导致该问题的任何 bug。超出此范围的编译问题不在我们的支持范围内。

</Accordion>
