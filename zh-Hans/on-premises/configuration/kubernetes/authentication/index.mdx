---
title: 身份验证
description: 在 Kubernetes 部署中配置登录方式——OIDC、SAML、LDAP、公开访问、reCAPTCHA 和密码规则。
icon: address-card
---

所有登录方式都在每个 Ayakaleaf Pro pod 的 **web** 服务中运行。它们都不需要额外的 pod 或定期任务，并且都将登录状态保存在 Redis 中的会话里，因此无论是一个副本还是多个副本，其工作方式都相同。在 Kubernetes 上，区别在于设置、密钥和证书存放在哪里，以及必须开放哪些网络路径：

| 方式 | Secret `overleaf-secrets` | Secret `overleaf-certs` | Pod 必须能访问 |
| --- | --- | --- | --- |
| [OIDC](/zh-Hans/on-premises/configuration/kubernetes/authentication/oidc-authentication) | `OVERLEAF_OIDC_CLIENT_SECRET` | 你的 CA（如果是私有 CA） | OP 的 token 和 userinfo 端点 |
| [SAML](/zh-Hans/on-premises/configuration/kubernetes/authentication/saml-authentication) | – | IdP 证书、Overleaf 自己的密钥 | 无需访问：消息经由浏览器传递 |
| [LDAP](/zh-Hans/on-premises/configuration/kubernetes/authentication/ldap-authentication) | `OVERLEAF_LDAP_BIND_CREDENTIALS` | LDAP CA（如果是私有 CA） | LDAP 服务器 |
| [公开访问](/zh-Hans/on-premises/configuration/kubernetes/authentication/public-access) | SMTP 密码，用于激活邮件 | – | SMTP 服务器 |
| [reCAPTCHA](/zh-Hans/on-premises/configuration/kubernetes/authentication/recaptcha) | `RECAPTCHA_SECRET_KEY`、`DEVICE_HISTORY_SECRET` | – | `www.google.com`（或 `RECAPTCHA_ENDPOINT`） |
| [密码限制](/zh-Hans/on-premises/configuration/kubernetes/authentication/password-restrictions) | – | – | – |

`EXTERNAL_AUTH` 用于开启 SSO 方式，在 ConfigMap 中以空格分隔的列表形式设置，例如 `EXTERNAL_AUTH: ldap oidc`。开启 SSO 后的账户以及用户可以更改的内容与 Toolkit 上相同，参见[身份验证](/zh-Hans/on-premises/configuration/overleaf-toolkit/authentication)。

<Warning>

设置错误的登录方式不会阻止 pod 进入就绪状态：web 会在 `/var/log/overleaf/web.log` 中记录 `error setting up passport in modules`，而该方式以及按 `ldap`、`saml`、`oidc` 顺序排在它之后的方式都会保持关闭。每次更改后请检查日志。我们用 `EXTERNAL_AUTH: saml oidc` 和缺失的 IdP 证书进行了尝试：pod 进入了就绪状态，但在修正证书路径之前，`/saml/login` 和 `/oidc/login` 都返回“Something went wrong”（500）。

</Warning>
