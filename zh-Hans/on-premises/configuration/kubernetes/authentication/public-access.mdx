访客访问共享项目、公开页面以及自助注册，均通过 **web** 服务读取的环境变量开启；随后实时服务会通过访客的会话为其提供服务。每个开关开放了哪些内容，请参见[公开访问](/zh-Hans/on-premises/configuration/overleaf-toolkit/authentication/public-access)。

| | |
| --- | --- |
| 服务 | web（以及在编辑器中为访客服务的 real-time），位于每个 Ayakaleaf Pro pod 中；在 web 启动时读取 |
| Pod → 外部 | SMTP 服务器，当注册需要发送激活邮件时 |
| 状态 | 会话中的访客访问令牌，Redis 中的注册速率限制 |
| 定期任务 | 无 |

### 配置

将你需要的开关添加到 ConfigMap `overleaf-env`：

```yaml title="30-config.yaml (additions)"
  # Guests open link-shared projects without an account
  OVERLEAF_ALLOW_ANONYMOUS_READ_AND_WRITE_SHARING: "true"
  # Signed-out visitors may open /learn, /templates, /devs and view links
  OVERLEAF_ALLOW_PUBLIC_ACCESS: "true"
  # Self-registration: "true", or only some domains
  OVERLEAF_ALLOW_PUBLIC_REGISTRATION: "@example.com, @*.uni.example"
```

```bash
kubectl apply -f 30-config.yaml
kubectl -n overleaf rollout restart deployment/overleaf     # or statefulset/overleaf
```

请为每个值加上引号。以 `@` 开头的值在 YAML 中必须加引号，否则 `kubectl apply` 会拒绝该文件。

仅限特定域名的注册会发送激活邮件，因此 pod 必须能够正常进行[邮件发送](/zh-Hans/on-premises/configuration/kubernetes/email-delivery)：请将 SMTP 主机放入 ConfigMap，将 `OVERLEAF_EMAIL_SMTP_PASS` 放入 Secret。

### 多个副本

无需额外操作。访客对项目的访问权限保存在 Redis 中的会话里，因此无论负载均衡器选择哪个副本，编辑器都能正常工作。

### 在 Kubernetes 上的测试

在 Kubernetes 1.37 上，我们针对公开访问的端到端测试全部通过：在一个副本上，将 `OVERLEAF_ALLOW_PUBLIC_REGISTRATION` 分别设为 `true`、一个域名、带子域名通配符的多个域名以及 `@*` 时的自助注册，以及域名模式下的激活邮件（43 个用例）；在设置 `OVERLEAF_ALLOW_PUBLIC_ACCESS` 时，未登录访问者访问 `/devs`，以及提交的代码片段在登录后得以保留（2 个用例）；两个开关都开启时，未登录访客进入通过链接共享的项目（3 个用例）；以及在 HAProxy 之后的三个副本上，OIDC 与公开访问同时使用（1 个用例）。
