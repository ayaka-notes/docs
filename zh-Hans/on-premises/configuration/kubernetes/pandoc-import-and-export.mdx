Pandoc 转换由每个 Ayakaleaf Pro pod 的 **clsi** 服务执行，与编译相同：clsi 请求节点上的 Docker Engine 从 `PANDOC_IMAGE` 启动一个容器。**web** 服务负责显示导入和导出菜单。该功能的作用以及如何构建镜像，请参见 [Pandoc 导入与导出](/zh-Hans/on-premises/configuration/overleaf-toolkit/pandoc-import-and-export)。

| | |
| --- | --- |
| 服务 | web（菜单和路由）、clsi（执行转换），位于每个 Ayakaleaf Pro pod 中 |
| 节点 | Docker Engine 和 `PANDOC_IMAGE`，位于每个可以运行 Ayakaleaf Pro 的节点上 |
| 依赖 | [沙盒编译](/zh-Hans/on-premises/configuration/kubernetes/sandboxed-compiles) |
| 定期任务 | 无 |

### 配置

<Steps>
<Step title="将镜像放入每个节点的 Docker 中">
从 [ayakaleaf-pro](https://github.com/ayaka-notes/ayakaleaf-pro) 仓库的 `develop/pandoc` 文件夹构建一次镜像，然后将其加载到每个可以运行 Ayakaleaf Pro 的节点的 Docker 中：

```bash
docker build -t overleaf-pandoc:local develop/pandoc
docker save overleaf-pandoc:local | ssh node-1 sudo docker load    # repeat for every node
```

或者将其推送到节点可以访问的镜像仓库，并在每个节点上执行 `sudo docker pull`。与 TeX Live 镜像一样，它必须位于 **Docker** 中，而不能仅位于 containerd 中。
</Step>

<Step title="ConfigMap">
```yaml
  ENABLE_PANDOC_CONVERSIONS: "true"
  PANDOC_IMAGE: overleaf-pandoc:local
```

web 和 clsi 都从同一个 ConfigMap 读取 `ENABLE_PANDOC_CONVERSIONS`，因此在 Kubernetes 上二者不会出现不一致。
</Step>

<Step title="应用并重启">
```bash
kubectl apply -f 30-config.yaml
kubectl -n overleaf rollout restart deployment/overleaf     # or statefulset/overleaf
```
</Step>
</Steps>

### 多个副本

除了确保每个节点上都有该镜像之外，无需额外配置：每个副本都在自己的节点上执行转换。

### 在 Kubernetes 上的测试

使用从 `develop/pandoc` 构建并通过 `docker save | docker load` 加载到每个节点 Docker 中的镜像，在 Kubernetes 1.37 上以单副本运行时，Pandoc 的端到端测试全部通过（6 个用例）：将 Markdown 文档导入为 LaTeX 项目、损坏的 Word 文档显示的错误、导出 Word（可再次导入）、Markdown 和 HTML，以及未设置 `ENABLE_PANDOC_CONVERSIONS` 时菜单被隐藏。
