**web** 服务根据环境变量渲染标题、徽标、页眉链接、页脚和维护页面。每项设置及其格式请参见[品牌定制](/zh-Hans/on-premises/configuration/overleaf-toolkit/branding)；在 Kubernetes 上，它们放入 ConfigMap。

| | |
| --- | --- |
| 服务 | web，位于每个 Ayakaleaf Pro pod 中；在 web 启动时读取 |
| 网络 | 无：徽标是由浏览器加载的 URL |
| 定期任务 | 无（web 每 5 秒检查一次维护文件，见下文） |

### 配置

```yaml title="30-config.yaml (additions)" wrap
  OVERLEAF_NAV_TITLE: Our Overleaf Instance
  OVERLEAF_HEADER_IMAGE_URL: https://example.com/img/logo.png
  OVERLEAF_HEADER_EXTRAS: '[{"text":"Help","url":"https://example.com/help","class":"subdued"}]'
  OVERLEAF_LEFT_FOOTER: '[{"text":"Run by the IT department"}]'
  OVERLEAF_RIGHT_FOOTER: '[{"text":"Imprint","url":"https://example.com/imprint"}]'
  OVERLEAF_MAINTENANCE_MESSAGE: Our Overleaf Instance is down for maintenance and will be back shortly.
```

```bash
kubectl apply -f 30-config.yaml
kubectl -n overleaf rollout restart deployment/overleaf     # or statefulset/overleaf
```

请像上面那样将 JSON 值放在单引号中，以便 YAML 将其保留为一个字符串。`OVERLEAF_HEADER_EXTRAS` 或页脚中的无效 JSON 会被忽略，仅在启动时记录到日志中。

### 维护模式

当容器中的文件 `/etc/overleaf/site_status` 内容为 `closed` 时，会显示维护页面。每个 pod 都有自己的一份该文件，新建或重启的 pod 启动时处于开放状态。要关闭站点，请在每个 pod 中写入该文件：

```bash
for p in $(kubectl -n overleaf get pod -l app=overleaf -o name); do   # app=overleaf-ha for several replicas
  kubectl -n overleaf exec "$p" -- sh -c 'echo closed > /etc/overleaf/site_status'
done
```

以同样的方式写入 `open` 即可结束维护。pod 会在 5 秒内识别到该更改。

管理面板中的 **Close Editor** 的工作方式不同：它只会关闭处理该管理员请求的副本中的编辑器，并且该副本重启时会重新开放编辑器。如果有多个副本，请改用上述文件方式。

### 在 Kubernetes 上的测试

在 Kubernetes 1.37 上：在 ConfigMap 中使用上述设置时，页面显示了 `OVERLEAF_NAV_TITLE`、左侧页脚，以及登录后来自 `OVERLEAF_HEADER_EXTRAS` 的链接（登录页面会隐藏页眉链接）。向某个 pod 的 `/etc/overleaf/site_status` 写入 `closed` 后，仅该 pod 显示了带有 `OVERLEAF_MAINTENANCE_MESSAGE` 的维护页面，写入 `open` 后在几秒内即恢复。在三个副本的情况下，管理面板中的 Close Editor 只关闭了处理该管理员请求的副本上的编辑器，其他两个副本保持开放。
