RHEL 及其重建版本（Rocky Linux、AlmaLinux）自带 Podman 而不是 Docker，有些组织也不允许在服务器上使用 Docker。Toolkit 可以改为在 **rootless Podman** 上运行 Ayakaleaf Pro：容器以普通用户身份运行，编译仍在沙盒化的 TeX Live 容器中进行，SELinux 保持 enforcing 状态。脚本 `bin/podman-setup` 会检查主机并修复它能修复的问题。

完成本节后，你将得到与 [使用 Docker Compose](/zh-Hans/on-premises/installation/using-docker-compose) 相同的实例：带有沙盒编译、MongoDB 和 Redis 的 Ayakaleaf Pro，并照常使用 `bin/up`、`bin/doctor` 和 `bin/upgrade` 管理。

<Info>

Podman 支持仍处于实验阶段。它来自官方 Overleaf Toolkit，官方只在 RHEL 9 及更高版本上，以 rootless Podman、沙盒编译和 SELinux enforcing 的组合进行测试。我们在 Rocky Linux 9.9（Podman 5.8，SELinux enforcing）上使用 Ayakaleaf Pro 6.3.4 测试了这些页面。Docker 仍是推荐的容器运行时。

</Info>

### 你需要准备什么 {#what-you-need}

* **RHEL、Rocky Linux、AlmaLinux 或 CentOS Stream 9 及更高版本**，并且 SELinux 处于 enforcing 状态。在其他发行版上 `bin/podman-setup` 会停止运行。在 Ubuntu 或 Debian 上，请使用 [使用 Docker Compose](/zh-Hans/on-premises/installation/using-docker-compose/linux)。
* **一个拥有 `sudo` 权限的非 root 用户**，由它拥有这些容器。本节中的所有命令都以该用户身份运行；`bin/podman-setup` 拒绝以 `root` 身份运行。
* **一台干净的主机**：没有 Docker Engine，也没有已有的 Toolkit 安装。本节不涉及把现有的基于 Docker 的实例迁移到 Podman。

### 与 Docker 的区别 {#how-it-differs-from-docker}

|                                  | Docker                               | Rootless Podman                                                                          |
| -------------------------------- | ------------------------------------ | ---------------------------------------------------------------------------------------- |
| 谁运行容器                        | Docker 守护进程，以 `root` 身份       | 你的用户                                                                                  |
| 用于启动编译的 socket             | `/var/run/docker.sock`               | `/run/user/<uid>/podman/podman.sock`                                                     |
| 端口                              | 任意，例如 `80` 和 `443`              | `1024` 及以上，例如 `8080`                                                                 |
| 主机防火墙（`firewalld`）          | 发布的端口会绕过它                    | 生效：使用 `firewall-cmd` 开放端口                                                         |
| 重启后启动                        | Docker 守护进程重新启动它们           | 用户服务 `podman-restart`                                                                 |
| SELinux                          | Toolkit 不做配置                      | 策略模块 `podman_socket_clsi`，以及 `config/overleaf.rc` 中的 `SELINUX_MODE=managed`        |
| 编译用的 seccomp 配置文件          | 内置于镜像中                          | 由 Toolkit 提取到 `config/seccomp/<version>/` 并设置为 `SECCOMP_PROFILE`                   |

### 已知限制 {#known-limitations}

* <strong>Git 集成。</strong>在 Ayakaleaf Pro 6.3.4 中，`git clone` 在 Podman 上会以 `502` 失败：镜像内的 NGINX 使用 Docker 的 DNS 服务器（`127.0.0.11`）查找 `git-bridge` 容器，而 Podman 没有这个服务器。修复（[1b911d1092](https://github.com/ayaka-notes/ayakaleaf-pro/commit/1b911d1092c80f7b0ff77c5e3805b40503d49964)）将随下一个版本发布；在此之前，请保持 `GIT_BRIDGE_ENABLED=false`。
* <strong>客户端 IP 地址。</strong>Rootless Podman 从容器网络内部转发发布的端口，因此 Ayakaleaf Pro 看到的每个访问者都是内部地址，例如 `10.89.0.15`。管理面板中用户的[审计日志](/zh-Hans/on-premises/user-guide/administrators/user-management#audit-logs)显示的是这个地址，而不是用户的 IP 地址。
