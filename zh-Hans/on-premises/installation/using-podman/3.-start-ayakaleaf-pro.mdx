---
title: 3. 启动 Ayakaleaf Pro
description: 在 Podman 上启动 Ayakaleaf Pro，使用 podman-setup 和 bin/doctor 进行验证，并让它在重启后自动启动。
icon: circle-play
---

<Steps>
<Step title="启动容器">
```bash title="Start Ayakaleaf Pro"
bin/up -d
```

第一次启动会下载 MongoDB、Redis 和 TeX Live 镜像，并在 `data/` 中创建数据目录。它会打印一条警告，说明 Podman 支持仍处于实验阶段。

<Info>

第一次启动也可能打印 `MongoNetworkError: connect ECONNREFUSED 127.0.0.1:27017`。Toolkit 会在 MongoDB 仍在启动时设置 MongoDB 副本集，并不断重试直到它响应。你可以忽略这一行。

</Info>

一两分钟后，检查容器是否在运行：

```bash title="List the containers"
podman ps --format "{{.Names}} {{.Status}}"
```

```text
mongo Up 34 seconds (healthy)
redis Up 20 seconds
sharelatex Up 20 seconds
```
</Step>

<Step title="再次检查设置">
现在数据目录已经存在，`sharelatex` 容器也在运行，`bin/podman-setup` 可以完成它的检查了：

```bash title="Check the setup"
bin/podman-setup
```

它会检查新数据目录的所有者，并从 `sharelatex` 容器内部测试 Podman socket：

```text
====== Socket Connectivity ======
[✓] host → socket OK
[✓] container → socket OK

====== Data Directory Permissions ======
[✓] mongo data dir owned by 999
[✓] redis data dir owned by 999
[✓] overleaf data dir owned by 33
...
====== Summary ======
[✓] 27 passed  [!] 1 warnings  [✗] 0 failures
[!] Warnings:
[!] not logged in to quay.io
```

`container → socket OK` 表示 Ayakaleaf Pro 可以启动编译容器。如果某项检查失败，请运行 `bin/podman-setup --apply`，然后运行 `bin/up -d`。quay.io 警告不适用于 Ayakaleaf Pro，请参阅 [2. 运行 podman-setup](/zh-Hans/on-premises/installation/using-podman/2.-run-podman-setup)。
</Step>

<Step title="运行 doctor">
```bash title="Run the doctor"
bin/doctor
```

在 Podman 上，报告会显示运行时和安全设置：

```text
- Container Daemon
    - status: up
    - runtime: podman
    - server version: 5.8.5
    - socket: /run/user/1000/podman/podman.sock
    - DOCKER_HOST: unix:///run/user/1000/podman/podman.sock
    - host → socket: OK
    - container → socket: OK
- Security
    - SELinux: Enforcing
    - SELINUX_MODE: managed
    - SELINUX_LABEL: sharelatex_t
    - SELinux module: loaded (podman_socket_clsi)
    - SELinux rules: present
    - Seccomp profile: present
```

末尾的警告 `Server Pro enabled, but not logged in to quay.io repository` 是同一个 quay.io 检查，请参阅 [获取帮助](/zh-Hans/on-premises/support/getting-help#q-and-a)。
</Step>

<Step title="重启后启动 Ayakaleaf Pro">
使用 Docker 时，Docker 守护进程会在重启后再次启动容器。Rootless Podman 没有守护进程：请启用在服务器启动时启动你的容器的用户服务：

```bash title="Start the containers at boot"
systemctl --user enable podman-restart.service
```

它会启动你的用户下所有重启策略为 `always` 的容器，Toolkit 为它的所有容器都设置了这一策略。这需要 lingering，而 `bin/podman-setup --apply` 已经启用了它。如果没有这个服务，请在每次重启后运行 `bin/up -d`。
</Step>

<Step title="在防火墙中开放端口">
默认情况下，实例只接受来自服务器本身的连接，地址为 `http://localhost:8080`。要从其他计算机访问，请按照 [5. 个性化你的实例](/zh-Hans/on-premises/installation/using-docker-compose/linux/5.-personalizing-your-instance#listen-address-and-port) 中的说明，在 `config/overleaf.rc` 中设置 `OVERLEAF_LISTEN_IP`，在 `config/variables.env` 中设置 `OVERLEAF_SITE_URL`，然后再次运行 `bin/up -d`。

与 Docker 不同，rootless Podman 不会绕过主机防火墙。如果 `firewalld` 正在运行（这是 RHEL 上的默认设置），请开放端口：

```bash title="Open port 8080"
sudo firewall-cmd --permanent --add-port=8080/tcp
sudo firewall-cmd --reload
```

在云服务器上，还要在提供商的安全组中放行该端口。在把实例暴露到互联网之前请使用 HTTPS，请参阅 [4. 安装后任务](/zh-Hans/on-premises/installation/using-podman/4.-post-installation-tasks#use-https)。
</Step>
</Steps>
