### 创建管理员和第一个项目 {#create-the-administrator-and-a-first-project}

在你的 **Windows 浏览器**中打开 [http://localhost:8080/launchpad](http://localhost:8080/launchpad)，创建第一个管理员账户并登录。然后按照 Linux 指南中的 [6. 安装后任务](/zh-Hans/on-premises/installation/using-docker-compose/linux/6.-post-installation-tasks) 进行操作，并在其示例 URL 中使用端口 `8080`。

### 验证编译 {#verify-compilation}

登录页面能够正常工作并不能证明独立的编译器容器可以访问 WSL 数据目录。请创建一个空白项目，并使用 **pdfLaTeX** 编译以下 `main.tex`：

```latex
\documentclass{article}
\begin{document}
Ayakaleaf Pro on Windows WSL 2.
\end{document}
```

PDF 预览中应显示该文本。如果使用 basic 镜像，必要时请在项目设置中选择 **TeX Live 2026 Basic**。

选择 **XeLaTeX** 并测试：

```latex
\documentclass{article}
\usepackage{fontspec}
\begin{document}
Ayakaleaf WSL XeLaTeX sandbox.
\end{document}
```

这两个示例都可以在 basic 镜像中运行。对于中文文档，请先使用包含 `ctex` 和所需字体的镜像（例如 full），再使用 **XeLaTeX** 测试以下内容。basic 镜像不包含这些内容：

```latex
\documentclass{ctexart}
\begin{document}
你好，Ayakaleaf Pro。
\end{document}
```

要确认是否使用了沙盒，请在编译时于 **Ubuntu** 中运行：

```bash
docker ps -a --filter ancestor=ghcr.io/ayaka-notes/texlive-basic:2026.1
bin/logs -f clsi
```

请在过滤条件中使用你所选的镜像名称。较短的编译可能在 `docker ps` 运行之前就已完成；`-a` 还会显示已停止但尚未清理的容器。编译器容器应使用该镜像，并带有一个来自 Toolkit 的 WSL 数据目录的 `/compile` 绑定挂载。仅查看应用程序日志并不能替代检查 PDF。

### 验证数据持久化 {#verify-persistence}

在 **Ubuntu** 中，从 Toolkit 目录运行：

```bash
bin/stop
bin/start
```

等待应用程序启动，从 Windows 重新打开项目并再次编译。你的账户、源文件和项目文件应该都还在。默认的实时数据位于 Ubuntu 中的 `~/ayakaleaf-toolkit/data/`。请同时保留 `config/` 和 `data/`；卸载或注销 Ubuntu 发行版可能会删除它们。

### 保持实例可用 {#keep-the-instance-available}

让实例保持运行包含三个方面：Windows 保持唤醒、Docker Desktop 保持运行，以及容器随引擎一起重启。

在 Docker Desktop 的 **Settings → General** 中，开启 **Start Docker Desktop when you sign in to your computer**，参见 [Docker Desktop 设置](https://docs.docker.com/desktop/settings-and-maintenance/settings/)。这会在登录后启动 Docker，而不是在登录前。Windows 重启后，请登录，等待 Docker Desktop 启动完成，然后打开 Ubuntu 检查 `docker ps` 和站点。

Docker Desktop 的 **Resource Saver** 与 Windows 睡眠是两回事。它通常只在没有容器运行时才会激活；正在运行的应用程序、MongoDB 和 Redis 会阻止这种空闲状态。在 WSL 2 上，它会暂停 Docker 引擎，而不是关闭共享的 WSL 虚拟机。在为用户提供服务时，不要手动 **Pause** Docker Desktop。你无需仅仅为了让此服务栈保持运行而禁用 Resource Saver；参见 [Docker 的 Resource Saver 文档](https://docs.docker.com/desktop/use-desktop/resource-saver/)。

Toolkit 的服务使用 `restart: always`。请在 **Ubuntu** 中验证实际设置：

```bash
docker inspect sharelatex mongo redis --format '{{.Name}} restart={{.HostConfig.RestartPolicy.Name}}'
```

每个服务都应报告 `always`。Docker 运行后，它可以重新启动这些现有容器，而无需再次执行 `bin/up`。手动停止的容器会保持停止状态，直到你启动它或重启引擎；在 `always` 策略下，引擎重启后可以再次启动它。参见 [Docker 的重启策略行为](https://docs.docker.com/engine/containers/start-containers-automatically/)。

| 操作 | 对 Ayakaleaf 的影响 |
| --- | --- |
| 在 `bin/up -d` 之后关闭 Ubuntu 终端 | 容器以分离模式运行；终端并不负责管理它们。请保持 Docker Desktop 和 WSL 环境可用 |
| 关闭 Docker Dashboard 窗口 | 窗口可以关闭，Docker Desktop 会在系统托盘中继续运行 |
| 选择 **Quit Docker Desktop** | 停止引擎并使站点不可用；再次打开 Docker Desktop 即可恢复 |
| 运行 `wsl --shutdown` | 停止所有 WSL 发行版并中断 Docker WSL 后端；请重启 Docker Desktop 并重新打开 Ubuntu |
| 使 Windows 睡眠、休眠或关机 | 服务不可用；仅让屏幕保持开启或关闭不会改变这一点 |
| 运行 `bin/stop` | 停止实例但保留其数据；使用 `bin/start` 恢复 |

如需在接通交流电源时长时间运行，请打开 Windows 11 的 **Settings → System → Power & battery → Screen, sleep & hibernate timeouts**（某些版本显示为 **Power** 或 **Screen and sleep**）。将接通电源时的睡眠超时设置为 **Never**，如已配置自动休眠，请将其禁用。显示器仍然可以关闭。笔记本电脑的合盖操作是单独的设置；即使空闲睡眠超时设为 Never，合上盖子也可能使其进入睡眠。参见 [Windows 电源设置](https://support.microsoft.com/en-us/windows/experience/power-battery/power-settings-in-windows-11)。

在站点使用期间，不要将运行 `wsl --shutdown` 作为日常清理操作。如果某项 WSL 设置更改需要它，请先停止实例并安排好中断时间。在这些设置下，Windows 可以持续运行该实例。对于必须在注销和无人值守重启后仍然可用的共享服务，我们推荐使用 [Linux 指南](/zh-Hans/on-premises/installation/using-docker-compose/linux)。

### 重启 Docker Desktop 后检查恢复情况 {#check-recovery-after-restarting-docker-desktop}

保存工作并等待正在进行的编译完成后，从 Docker Desktop 的故障排除菜单中选择 **Restart Docker Desktop**。等待引擎启动，然后在 **Ubuntu** 中检查：

```bash
docker ps
curl -I http://localhost:8080/launchpad
```

在 Windows 中打开现有项目并再次编译。确认账户和源文件仍然存在。

如果你是通过 `bin/stop` 有意停止实例的，请使用 `bin/start`。如果 Docker 已运行但某个服务失败，请查看其日志，而不是重新创建配置。Windows 更新、Docker 更新和断电仍然可能中断 24 小时运行的安装；请保留备份，并在计划内维护后检查恢复情况。

### 日常使用 {#daily-use}

在 Windows 中启动 Docker Desktop。打开 **Ubuntu**：

```bash
cd "$HOME/ayakaleaf-toolkit"
```

| 任务 | 命令 |
| --- | --- |
| 启动现有容器 | `bin/start` |
| 停止容器并保留数据 | `bin/stop` |
| 应用配置更改 | `bin/up -d` |
| 检查状态 | `bin/docker-compose ps` |
| 查看启动日志 | `bin/docker-compose logs --tail=100 sharelatex` |
| 查看 MongoDB 日志 | `bin/docker-compose logs --tail=100 mongo` |
| 查看编译器日志 | `bin/logs -f clsi` |

`bin/start` 不会应用配置的编辑：更改 `config/` 后请使用 `bin/up -d`。在升级、迁移或移除 WSL 发行版之前，请按照[数据与备份](/zh-Hans/on-premises/maintenance/data-and-backups)进行操作。在数据库写入时复制正在使用的 MongoDB 文件并不能得到一致的备份。

本地使用时请保持 `127.0.0.1`。若要为其他计算机提供服务，还需要有意识地配置监听地址、站点 URL、Windows 防火墙/网络配置以及 HTTPS；仅更改 `OVERLEAF_SITE_URL` 并不会发布端口。

如果遇到问题，请参阅[故障排除](/zh-Hans/on-premises/installation/using-docker-compose/windows/troubleshooting)。
