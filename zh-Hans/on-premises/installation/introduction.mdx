与 Overleaf Server Pro 一样，我们的 Ayakaleaf Pro 以 Docker 容器的形式提供，可以直接替换使用，并额外包含以下功能：通过 LDAP 和 SAML2 提供的 SSO、更强的安全性、修订追踪、评论、我们优化过的 TeX Live 版本、模板以及管理面板。

* 如果你只是想测试 Ayakaleaf Pro 的功能或试用演示，可以参考我们的 [using-the-github-codespace.md](/zh-Hans/on-premises/installation/using-the-github-codespace  "mention") 教程。演示环境使用最小化的 TeX Live 安装，因此你的部分项目可能无法成功编译。
* 如果你此前从未部署过任何版本的 Overleaf，请先参阅[安装 Docker](/zh-Hans/on-premises/installation/setup-docker) 安装 Docker Engine，然后[使用 Toolkit](/zh-Hans/on-premises/installation/using-the-toolkit  "mention") 安装 Overleaf。
* 如果你已经部署了 Overleaf 社区版，请参阅 [migrate-from-existing.md](/zh-Hans/on-premises/installation/migrate-from-existing  "mention") 迁移到 Ayakaleaf Pro。
* 如果你更喜欢使用 Claude 或 Codex 等智能体，可以参阅：[using-claude-or-codex.md](/zh-Hans/on-premises/installation/using-claude-or-codex  "mention")。
* 如果你需要在离线或隔离网络环境中部署，请参阅：[air-gapped-offline-deployments.md](/zh-Hans/on-premises/installation/air-gapped-offline-deployments  "mention")。
* 如果你是现有的 Server Pro 用户，请在迁移到 Ayakaleaf Pro 之前提交一个 issue 告知我们，因为模板数据的存储格式略有不同。我们非常乐意免费帮助你从 Server Pro 迁移到 Ayakaleaf Pro。
* 如果有一天你厌倦了 Ayakaleaf Pro，想切换回官方的 Overleaf 社区版，这也是完全支持的，你的数据不会丢失。对于官方 Overleaf Toolkit 的用户，只需删除你的 override YAML 文件即可。对于 ayaka-notes toolkit 的用户，请禁用 `SERVER_PRO` 选项。之后一切都会回退到标准的社区版。

### 硬件要求

我们进行了相关测试，发现如果在 2 核、2 GB 内存的服务器上运行 Overleaf，其主要基于 Node.js 的核心组件大约会占用 1 GB 内存。Redis 和 MongoDB 可能还需要额外 0.5 GB，而启动一个用于编译的沙盒 Docker 容器又会占用约 0.3 GB。这意味着一台 2 核、2 GB 的服务器实际上一次只能处理大约一个并发编译。

* 安装 Ayakaleaf Pro 的最低硬件要求为 2 核 CPU 和 3 GB 内存。
* 由于我们的 TeX Live 镜像体积较大，启用沙盒编译至少需要 40 GB 存储空间。
* 如果你想安装 2020 年至 2026 年的完整 TeX Live 镜像集，请确保至少有 150 GB 的可用磁盘空间。

以下是针对不同使用场景推荐的硬件配置：

| 使用场景                                             | 推荐配置                                                                                             |
| ---------------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| 个人使用，偶尔协作                                   | 2 核 CPU，4 GB 内存，80 GB 存储                                                                      |
| 小型团队，最多 10 名用户，轻度协作                   | 2 核 CPU，8 GB 内存，256 GB 存储                                                                     |
| 中型团队，最多 100 名用户                            | 4 核 CPU，16 GB 内存，1 TB 存储                                                                      |
| 大规模或高校部署                                     | 分布式集群部署，使用 S3 存储；如需部署协助，请联系我们                                               |

### 软件要求

在软件要求方面，我们建议使用较新且稳定的 Ubuntu 版本（例如 2025–2026 年使用 Ubuntu 24.04，2023–2024 年使用 Ubuntu 22.04），并搭配最新稳定版的 Docker。

<Info>

稳定性优先：请选择已发布一段时间的最新 Ubuntu LTS 版本，而不是刚刚发布的版本。例如，截至 2026 年 10 月，Ubuntu 26.04 尚不受支持：它搭载 Linux 内核 7.0，而 MongoDB 在 Linux 内核 6.19 至 7.0.13 上无法启动（[详情](https://www.mongodb.com/docs/manual/administration/production-notes/)），因此请使用 Ubuntu 24.04。

</Info>

我们不建议在 Windows 或 CentOS 等其他不受支持的操作系统上部署 Ayakaleaf Pro，因为在安装和运行过程中可能会遇到兼容性问题或意外问题。

不过，如果你想尝试在基于 ARM 的系统或 macOS 上部署 Ayakaleaf Pro，欢迎与社区分享你的经验和反馈。

### LaTeX 性能

LaTeX 是单线程程序，这意味着它一次只能使用一个 CPU 核心。编译单个文档时，性能主要受限于 CPU 的单核时钟频率。因此，CPU 的单核性能越强，编译文档的速度就越快。只有在多个用户同时编译文档时，更多的 CPU 核心才会带来好处。

以 [ThuThesis 模板](https://www.overleaf.com/latex/templates/thuthesis-tsinghua-university-thesis-latex-template/cfwgcxtvkbsx)为例，在 Intel Core i9-14900K（5.6 GHz）上编译时间约为 6 秒，而在搭载 AMD EPYC 7763（3.2 GHz）的 Azure Standard D2as v5 实例（2 vCPU，8 GiB 内存）上则需要约 13 秒。

当然，实际编译性能取决于你的硬件配置。大多数服务器 CPU 的时钟频率达不到 14900K 那么高，因此你需要在成本和编译速度之间进行权衡。

同时，我们也对 LaTeX 编译性能进行了深入分析。如果你感兴趣，请参阅我们的博客文章 [Overleaf Benchmark：Overleaf（SaaS 与自托管）并发 LaTeX 编译深度研究](/zh-Hans/blog/2026/overleaf-benchmark  "mention")。
