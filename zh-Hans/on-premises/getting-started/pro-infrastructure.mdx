#### 服务

Overleaf Pro 基础架构由四个主要服务组成：`sharelatex`、`git-bridge`（可选）、`mongo` 和 `redis`。`sharelatex` 服务运行 Server Pro 主应用程序，它依赖 `mongo` 和 `redis` 服务提供数据库和缓存/实时功能，并依赖 `git-bridge` 处理 [Git 集成](/zh-Hans/on-premises/configuration/overleaf-toolkit/git-integration)（可选）。宿主机上唯一对外发布的端口是 80 端口，由 `sharelatex` 容器使用。

Server Pro 还可选地支持使用 [S3 兼容存储](/zh-Hans/on-premises/configuration/overleaf-toolkit/s3)来存放项目文件和完整项目历史，并且能够代理访问 [Overleaf 主文档站点](https://www.overleaf.com/learn)。更多信息，请参阅我们关于[添加 LaTeX 用户帮助](/zh-Hans/on-premises/configuration/overleaf-toolkit/adding-latex-user-help)页面的指南。

<Info>

如有需要，可以通过环境变量将 MongoDB 和 Redis 外置，指向外部服务。更多信息，如果你使用 Docker Compose，请参阅[配置 Overleaf](/zh-Hans/on-premises/configuration)；如果你使用 Overleaf Toolkit，请参阅 [Toolkit 设置](/zh-Hans/on-premises/configuration/overleaf-toolkit/toolkit-settings)。

</Info>

#### 编译

对于[沙盒编译](/zh-Hans/on-premises/configuration/overleaf-toolkit/sandboxed-compiles)，`sharelatex` 容器会通过宿主机上的 Docker socket 编排创建新容器来处理项目编译。你可以在[这里](/zh-Hans/on-premises/getting-started/microservices#editor-and-compile-process)进一步了解编辑器以及端到端的编译/缓存流程。

#### 网络

容器之间通过专用桥接网络上的 Docker 内部 DNS 解析进行通信，且未启用任何防火墙。默认情况下，上述服务使用各自的标准端口，但可以通过环境变量进行配置。`sharelatex` 容器使用 80 端口提供外部 Web 访问（由 Nginx 提供服务），`mongo` 容器使用 27017 端口，`redis` 使用 6379 端口。

对于使用我们的托管方案 [Overleaf Toolkit](https://github.com/overleaf/toolkit) 的客户，你可以通过环境变量选择[启用 TLS 代理](/zh-Hans/on-premises/configuration/overleaf-toolkit/tls-proxy)，使用 Nginx 终止 HTTPS 连接。或者，你也可以使用现有的 TLS 代理。

<Info>

你可以在[这里](/zh-Hans/on-premises/configuration/overleaf-toolkit/tls-proxy)查看说明请求流转过程的示意图。

</Info>

#### 总结

* 在 Docker 网络之外，只有 80 端口可访问，并绑定到 Nginx。<strong>注意：</strong> `sharelatex` 容器运行着许多通过 HTTP 相互通信的[服务](https://github.com/overleaf/overleaf/tree/main/services)。但是，这些端口在 Docker 网络之外**无法**访问。
* 在 Docker 网络内部，Overleaf 服务、MongoDB、Redis 和 Git Bridge 之间可以自由通信。
* 在[沙盒编译](/zh-Hans/on-premises/configuration/overleaf-toolkit/sandboxed-compiles)容器内部，没有可用的网络。
