我们非常自豪地宣布 Overleaf Pro 6.3.1 正式发布，这是社区中功能最强大、最丰富的在线 LaTeX 编辑器。补丁版本通常只包含少量小修复，而这一版走得更远：除了数十项问题修复之外，它还带来了五项新功能，并将你的项目连接到你已经在使用的地方，从 Dropbox、GitLab 到你终端里的 AI 智能体。

### 变更

* Dropbox 同步（早期预览版）：让每个项目与你自己的 Dropbox 双向保持同步。
* GitLab 同步（早期预览版）：与 GitLab.com 或你自托管的 GitLab 进行双向同步。
* MCP 服务器：让 Claude Code、Codex、Cursor、VS Code 或 Gemini CLI 直接处理项目。
* GitHub Enterprise：将 GitHub 同步指向你自己的 GitHub Enterprise 实例。
* 手写符号识别：画出一个符号，即可得到对应的 LaTeX 命令。
* `OVERLEAF_DISABLE_LOCAL_LOGIN`：隐藏邮箱和密码登录，让用户只能通过 SSO 登录。
* 由我们的 E2E 测试系统和内部 Horizon 问题排查（Internal Horizon Issue Investigation）发现的问题修复。
* 上游 Overleaf 6.3.1 补丁。

<Info>

Dropbox 同步和 GitLab 同步在 6.3.1 中作为**早期预览版**发布，用于灰度测试，并将在 v6.4.0 中正式发布。在此之前，它们的配置和行为仍可能发生变化。两者默认均为关闭状态。如有任何问题，请在 [GitHub](https://github.com/ayaka-notes/ayakaleaf-pro/issues) 上反馈。

#### 功能 01：Dropbox 同步（预览版）

有些人永远不想和 Git 打交道。他们只希望自己的论文是笔记本电脑上的一个文件夹，而 Dropbox 同步正好满足了这一点。每个用户关联自己的 Dropbox 账户后，其拥有的项目和共享给他的项目都会出现在 `Apps/<your app name>/` 下。在 Overleaf 中编辑，更改会出现在 Dropbox 中。在本地用你喜欢的编辑器修改文件并保存，更改会通过签名的 webhook 同步回 Overleaf。

对于管理员：必须启用 Git bridge。在 Dropbox App Console 中创建一个应用，然后设置 `DROPBOX_ENABLED`、`DROPBOX_APP_KEY`、`DROPBOX_APP_SECRET`、`DROPBOX_APP_NAME` 和 `DROPBOX_TOKEN_CIPHER_PASSWORD`。`DROPBOX_SYNC_PROXY_URL` 是可选的，适用于无法直接访问 Dropbox 的服务器。然后在用户关联账户之前，一次性创建 Dropbox 同步所需的 MongoDB 索引。

完整的设置说明请参见 [Dropbox 同步](/zh-Hans/on-premises/configuration/overleaf-toolkit/dropbox-synchronisation  "mention")。

#### 功能 02：GitLab 同步（预览版）

自 6.2 以来，GitHub 同步一直是我们最受欢迎的功能之一，而许多大学和公司则把代码放在 GitLab 上。GitLab 同步的工作方式相同：关联你的账户，从新建项目菜单中导入仓库，或将项目导出为新的 GitLab 项目。然后在编辑器中推送和拉取，并通过合并请求进行合并。

它支持 GitLab.com 以及 15.10 或更高版本的自托管 GitLab。设置 `GITLAB_SYNC_ENABLED`、`GITLAB_SYNC_CLIENT_ID`、`GITLAB_SYNC_CLIENT_SECRET` 和 `GITLAB_TOKEN_CIPHER_PASSWORD`，对于自托管实例还需设置 `GITLAB_SYNC_URL`。

完整的设置说明请参见 [GitLab 同步](/zh-Hans/on-premises/configuration/overleaf-toolkit/gitlab-synchronisation  "mention")。

#### 功能 03：MCP 服务器

在 6.3 中，我们把 AI 助手放进了编辑器。在 6.3.1 中，我们从另一个方向打开了大门：现在每个项目都有自己的 MCP 服务器，因此你已经在使用的 AI 智能体可以直接处理你的论文。让 Claude Code 修复引言中的拼写错误，让 Codex 编译并修复 LaTeX 错误，或者让 Cursor 回复尚未处理的审阅评论。智能体会实时读取和编辑文件，因此你和你的协作者会看到它的编辑随着输入出现在编辑器中。它还可以编译、读取日志、获取 PDF、统计字数以及列出版本。

端点为 `/project/<project_id>/mcp`。使用与 `git clone` 相同的 Git 令牌进行身份验证。访问权限遵循项目的共享设置，因此查看者的智能体只能读取而不能编辑，并且每个工具都有速率限制。无需其他任何配置：MCP 服务器会随 Git bridge 一同启用。

<img src="https://github.com/user-attachments/assets/a8702201-db3f-4985-a050-b7ebdbe7a952" alt="MCP 服务器" width="787" />

如何连接各个 AI 客户端，请参见 [MCP 服务器](/zh-Hans/on-premises/configuration/overleaf-toolkit/mcp-server  "mention")。

#### 功能 04：GitHub Enterprise

GitHub 同步不再局限于 github.com。将 `GITHUB_SYNC_URL` 设置为你的 GitHub Enterprise Server，或带数据驻留的 GitHub Enterprise Cloud（`GHE.com`），REST 和 GraphQL 端点会据此自动推导。如果你的实例有特殊之处，可以使用 `GITHUB_SYNC_API_URL` 和 `GITHUB_SYNC_GRAPHQL_URL` 覆盖它们。不设置这些变量时，一切都保持使用 github.com。

详情请参见 [GitHub 同步](/zh-Hans/on-premises/configuration/overleaf-toolkit/github-synchronisation#github-enterprise  "mention")。

#### 功能 05：手写符号识别

你知道这个符号长什么样，却不知道它叫什么。是 `\varsigma` 还是 `\zeta`？是 `\models` 还是 `\vDash`？将符号面板切换到绘制模式，用鼠标或触控板画出它，面板就会推荐匹配的 LaTeX 命令。

识别完全在浏览器中运行，使用由 ayaka-notes 训练的模型，因此你画的任何内容都不会离开你的设备。在不支持 `OffscreenCanvas` 的浏览器（例如 Safari 15）上，绘制开关会被隐藏。

#### 问题修复

本次发布还带来了一长串修复。其中许多是由我们新的 E2E 测试系统发现的，该系统现在每天为每个模块运行测试套件；另一些则来自内部 Horizon 问题排查：每当我们修复一个问题，都会在关闭它之前排查整个代码库中的同类问题。

* **身份验证**：在启用 SSO 的实例上，本地账户可以设置和更改密码，OIDC 用户不再能更改自己的邮箱。当名称属性有多个值时，LDAP、SAML 和 OIDC 登录不再失败，SAML/OIDC 注销也恢复正常。
* **被暂停的用户**：暂停用户现在会结束其会话并关闭其打开的编辑器，其 Git 令牌和 MCP 下载也会被拒绝。
* **GitHub 同步**：只有所有者才能导出项目，拉取期间所做的编辑会保持待处理状态，空文件会被同步，手动合并会在 GitHub 上进行验证。
* **Zotero / Mendeley**：当你的凭据失效时，会收到重新关联的提示，并且导入后会重新索引参考文献。
* **外部服务**：对 Zotero、Mendeley、GitHub、GitLab 和网页搜索的请求，连接超时从 1 秒改为 3 秒，因此较慢的网络不再失败。
* **修订追踪**：审阅数据包含未加载的文档和未保存的更改。
* **管理面板**：恢复已删除的项目、更改所有者和编辑用户都能正常工作，邮件发送失败也不再影响账户的创建或删除。
* **模板库**：无效的排序会返回 400 而不是 500，发布没有主文件的项目时会要求指定主文件。

完整列表请参见 [6.3.1 发行说明](/zh-Hans/on-premises/release-notes/release-notes-6.x.x#ayakaleaf-pro-6.3.1  "mention")。

#### 升级

* 从 6.3.0 升级：无需迁移。拉取新镜像并重启即可。
* 从 6.2.x 或更早版本升级且正在使用 Zotero 或 Mendeley：请先运行 6.3.0 中的 [Zotero / Mendeley 迁移](/zh-Hans/on-premises/release-notes/release-notes-6.x.x#ayakaleaf-pro-6.3.0  "mention")。
* Dropbox 同步和 GitLab 同步默认关闭。GitLab 同步只需要新的环境变量。Dropbox 同步还需要在用户关联账户之前一次性创建其 MongoDB 索引：请参见[创建数据库索引](/zh-Hans/on-premises/configuration/overleaf-toolkit/dropbox-synchronisation#create-the-database-indexes  "mention")。
