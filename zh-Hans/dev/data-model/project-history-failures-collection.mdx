title: Project History Failures 集合
icon: triangle-exclamation
---

`projectHistoryFailures` 中每个项目一个文档：project-history 无法处理其历史更新的项目，或已为其启动重新同步的项目。一旦处理成功，该文档就会再次被删除。project-history 在 `services/project-history/app/js/ErrorRecorder.js` 中写入它；类型定义在 `services/project-history/app/js/mongo-types.ts:3-24` 中。Web 也有它的 Mongoose schema（`services/web/app/src/models/ProjectHistoryFailure.mjs:5-19`），但没有 Web 代码使用该模型。

#### 写入方 {#who-writes-it}

| 代码 | 作用 |
| ---- | ------------ |
| `services/project-history/app/js/ErrorRecorder.js:34-66` | `record`：upsert 错误，`attempts` 加 1，并向 `history` 添加一条记录。在处理项目更新失败时调用（`UpdatesProcessor.js:91`、`169`、`242`、`293`、`345`），以及无法启动重新同步时调用（`SyncManager.js:75`、`96`）。 |
| `ErrorRecorder.js:86-102` | `recordSyncStart`：每次启动重新同步时 upsert、设置 `resyncStartedAt`、`resyncAttempts` 加 1，并向 `history` 添加一条记录（`SyncManager.js:104`）。 |
| `ErrorRecorder.js:68-70` | `clearError`：在成功 flush 之后删除该文档（`UpdatesProcessor.js:101`、`194`、`259`、`355`），在 project-history `DELETE /project/:project_id` 时删除（`services/project-history/app/js/HttpController.js:1386`），以及在重试期间遇到无效项目 ID 时删除（`services/project-history/app/js/RetryManager.js:161`）。 |
| `ErrorRecorder.js:72-82` | `setForceDebug`：upsert `forceDebug`（`HttpController.js:1016-1035`，路由位于 `services/project-history/app/js/Router.js:82`）。 |
| `ErrorRecorder.js:109-119` | `cloneFailure`：把该文档复制到另一个项目，用于 project-history `POST /project/:project_id/clone`（`HttpController.js:135`），Web 中没有任何代码调用它。 |

#### 说明 {#notes}

* 文档会一直保留，直到该项目的某次 flush 成功或项目被删除（见上文 `clearError`），因此每个文档都标记着一个最近一次 flush 或重新同步尚未成功的项目。
* 以 `OError:` 开头的错误字符串会以 `Error:` 的形式返回（`ErrorRecorder.js:18-26`）；存储的值不变。
