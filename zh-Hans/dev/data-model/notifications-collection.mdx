`notifications` 保存显示在用户项目面板顶部的通知。一个文档是给一个用户的一条通知，由其 `key` 标识。只有 `notifications` 服务直接访问该集合（`services/notifications/app/js/Notifications.js`）；`web` 和 `third-party-datastore` 调用它的 HTTP API。没有 Mongoose schema。

#### 字段 {#fields}

| 字段 | 类型 | 含义 | 来源 |
| --- | --- | --- | --- |
| `_id` | ObjectId | 通知 id。`web` 通过此 id 将通知标记为已读。 | `Notifications.js:58-65` |
| `user_id` | ObjectId | 看到该通知的用户。 | `Notifications.js:26` |
| `key` | String | 标识通知，例如 `project-invite-<inviteId>`。upsert 让每个 `user_id` 和 `key` 只保留一个文档；没有唯一索引。 | `Notifications.js:27`, `:51-55` |
| `templateKey` | String | 前端渲染哪一种通知。通知被阅读或关闭时删除该字段；文档本身保留。 | `Notifications.js:29`, `:63`, `:72`, `:78` |
| `messageOpts` | Object | 通知文本所需的值，取决于 `templateKey`（项目邀请为 `userName`、`projectName`、`projectId`、`token`）。用户按 id 关闭通知时删除。 | `Notifications.js:28`, `:63` |
| `expires` | Date | 可选。TTL 索引会在此时间之后删除文档。 | `Notifications.js:35-50` |

#### 说明 {#notes}

* 已读通知不会被删除：只会去掉 `templateKey`。由于文档仍保留 key，之后对同一 key 不带 `forceCreate` 的 `addNotification` 不会产生任何效果（`Notifications.js:21-24`）。
* `/key/:key` 路由只按 key 操作，跨越所有用户（`Notifications.js:76-100`）。
* 如果 `web` 没有 `apis.notifications.url`，它既不创建也不读取通知（`NotificationsHandler.mjs:17`、`:41`）。
