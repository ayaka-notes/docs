title: Deleted Projects 集合
icon: trash-can
---

`deletedProjects` 在项目被删除后保留该项目：每个被删除的项目一个文档，包含整个项目文档的副本以及删除者。Web 在 `services/web/app/src/Features/Project/ProjectDeleter.mjs` 中写入它；schema 是 `services/web/app/src/models/DeletedProject.mjs`。硬删除延迟过后，过期处理会销毁项目数据并清空 `project`，但带有 `deleterData` 的记录会保留下来。

回收站中的项目不在这里：移入回收站只会把用户加入项目的 `trashed`，参见 [Projects 集合](/zh-Hans/dev/data-model/projects-collection)。

| 代码 | 作用 |

| `ProjectDeleter.mjs:189-293`（`deleteProject`） | 刷写项目，把其 docs 从 Mongo 归档出去，将其从标签中移除，upsert 记录并删除 `projects` 文档。 |
| `ProjectDeleter.mjs:295-342`（`undeleteProject`） | 以 `<name> (Restored)` 的名称（对所有者唯一）重新插入项目并取消归档，然后删除记录。一旦 `project` 为 `null`，就以 `project_too_old_to_restore` 失败。由管理面板调用：恢复一个项目（`AdminProjectManager.mjs:497-515`），或恢复已删除用户及随账户一起删除的项目（`services/web/modules/admin-tools/app/src/AdminUserManager.mjs:678-689`）。 |

#### 说明 {#notes}

* 监听 `projectExpired` 的模块会删除它们自己保存的该项目数据：`git-bridge`（`services/web/modules/git-bridge/index.mjs:37`）、`github-sync`（`services/web/modules/github-sync/index.mjs:56`）、`gitlab-sync`（`services/web/modules/gitlab-sync/index.mjs:46`）、`gitea-sync`（`services/web/modules/gitea-sync/index.mjs:46`）和 `dropbox`（`services/web/modules/dropbox/index.mjs:54`）。
* 过期的记录永远不会被删除：`deleterData` 会永久保留，只有 `project` 和 IP 地址会被清空。
* Mongoose 还会给 `deleterData` 分配它自己的 `_id`，没有任何代码读取它。
