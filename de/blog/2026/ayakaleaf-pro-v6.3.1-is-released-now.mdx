Wir sind sehr stolz, die Veröffentlichung von Overleaf Pro 6.3.1 bekannt zu geben – dem leistungsstärksten und funktionsreichsten Online-LaTeX-Editor der Community. Ein Patch-Release bedeutet normalerweise eine Handvoll kleiner Korrekturen. Dieses geht viel weiter: Neben Dutzenden Fehlerbehebungen bringt es fünf neue Funktionen und verbindet Ihre Projekte mit den Orten, an denen Sie bereits arbeiten – von Dropbox und GitLab bis zum KI-Agenten in Ihrem Terminal.

### Änderungen

* Dropbox-Synchronisierung (Early Preview): Halten Sie jedes Projekt in beide Richtungen mit Ihrer eigenen Dropbox synchron.
* GitLab-Synchronisierung (Early Preview): Bidirektionale Synchronisierung mit GitLab.com oder Ihrem selbstverwalteten GitLab.
* MCP-Server: Lassen Sie Claude Code, Codex, Cursor, VS Code oder Gemini CLI direkt an einem Projekt arbeiten.
* GitHub Enterprise: Richten Sie die GitHub-Synchronisierung auf Ihre eigene GitHub-Enterprise-Instanz aus.
* Handschriftliche Symbolerkennung: Zeichnen Sie ein Symbol und erhalten Sie den LaTeX-Befehl.
* `OVERLEAF_DISABLE_LOCAL_LOGIN`: Blenden Sie die Anmeldung per E-Mail und Passwort aus, sodass sich Benutzer nur über SSO anmelden.
* Fehlerbehebungen, die von unserem E2E-Testsystem und der internen Horizon-Fehleruntersuchung gefunden wurden.
* Upstream-Patches von Overleaf 6.3.1.

<Info>

Die Dropbox-Synchronisierung und die GitLab-Synchronisierung werden in 6.3.1 als **Early Previews** für Graustufentests ausgeliefert und in v6.4.0 offiziell veröffentlicht. Ihre Konfiguration und ihr Verhalten können sich bis dahin noch ändern. Beide sind standardmäßig deaktiviert. Bitte melden Sie Probleme auf [GitHub](https://github.com/ayaka-notes/ayakaleaf-pro/issues).

</Info>

#### Funktion 01: Dropbox-Synchronisierung (Preview)

Manche Menschen wollen sich nie mit Git beschäftigen. Sie möchten einfach, dass ihre Abschlussarbeit ein Ordner auf ihrem Laptop ist – und genau das bietet ihnen die Dropbox-Synchronisierung. Jeder Benutzer verknüpft sein eigenes Dropbox-Konto, und seine eigenen sowie mit ihm geteilten Projekte erscheinen unter `Apps/<your app name>/`. Bearbeiten Sie etwas in Overleaf, und die Änderung erscheint in Dropbox. Bearbeiten Sie die Datei lokal in Ihrem Lieblingseditor, speichern Sie sie, und die Änderung gelangt über einen signierten Webhook zurück zu Overleaf.

Für Administratoren: Git-Bridge muss aktiviert sein. Erstellen Sie eine App in der Dropbox App Console und setzen Sie dann `DROPBOX_ENABLED`, `DROPBOX_APP_KEY`, `DROPBOX_APP_SECRET`, `DROPBOX_APP_NAME` und `DROPBOX_TOKEN_CIPHER_PASSWORD`. `DROPBOX_SYNC_PROXY_URL` ist optional und für Server gedacht, die Dropbox nicht direkt erreichen können. Erstellen Sie anschließend einmalig die MongoDB-Indizes, die die Dropbox-Synchronisierung benötigt, bevor Benutzer ihre Konten verknüpfen.

Die vollständige Einrichtungsanleitung finden Sie unter [Dropbox-Synchronisierung](/de/on-premises/configuration/overleaf-toolkit/dropbox-synchronisation  "mention").

#### Funktion 02: GitLab-Synchronisierung (Preview)

Die GitHub-Synchronisierung gehört seit 6.2 zu unseren beliebtesten Funktionen, doch viele Universitäten und Unternehmen verwalten ihren Code stattdessen auf GitLab. Die GitLab-Synchronisierung funktioniert genauso: Verknüpfen Sie Ihr Konto, importieren Sie ein Repository über das Menü für neue Projekte oder exportieren Sie ein Projekt in ein neues GitLab-Projekt. Pushen und pullen Sie dann direkt aus dem Editor und führen Sie Änderungen über Merge Requests zusammen.

Sie funktioniert mit GitLab.com und mit selbstverwaltetem GitLab ab Version 15.10. Setzen Sie `GITLAB_SYNC_ENABLED`, `GITLAB_SYNC_CLIENT_ID`, `GITLAB_SYNC_CLIENT_SECRET` und `GITLAB_TOKEN_CIPHER_PASSWORD` sowie für eine selbstverwaltete Instanz zusätzlich `GITLAB_SYNC_URL`.

Die vollständige Einrichtungsanleitung finden Sie unter [GitLab-Synchronisierung](/de/on-premises/configuration/overleaf-toolkit/gitlab-synchronisation  "mention").

#### Funktion 03: MCP-Server

In 6.3 haben wir einen KI-Assistenten in den Editor gebracht. In 6.3.1 öffnen wir die Tür in die andere Richtung: Jedes Projekt hat jetzt seinen eigenen MCP-Server, sodass der KI-Agent, den Sie bereits verwenden, direkt an Ihrem Paper arbeiten kann. Bitten Sie Claude Code, die Tippfehler in der Einleitung zu korrigieren, Codex, das Projekt zu kompilieren und die LaTeX-Fehler zu beheben, oder Cursor, die offenen Review-Kommentare zu beantworten. Der Agent liest und bearbeitet Dateien live, sodass Sie und Ihre Mitarbeitenden seine Änderungen im Editor erscheinen sehen, während er tippt. Er kann außerdem kompilieren, das Log lesen, das PDF abrufen, Wörter zählen und Versionen auflisten.

Der Endpunkt ist `/project/<project_id>/mcp`. Authentifizieren Sie sich mit demselben Git-Token, das Sie für `git clone` verwenden. Der Zugriff richtet sich nach den Freigabeeinstellungen des Projekts, sodass der Agent eines Betrachters lesen, aber nicht bearbeiten kann, und jedes Tool ist ratenbegrenzt. Sonst gibt es nichts zu konfigurieren: Der MCP-Server wird zusammen mit der Git-Bridge aktiviert.

<img src="https://github.com/user-attachments/assets/a8702201-db3f-4985-a050-b7ebdbe7a952" alt="MCP-Server" width="787" />

Wie Sie die einzelnen KI-Clients verbinden, erfahren Sie unter [MCP-Server](/de/on-premises/configuration/overleaf-toolkit/mcp-server  "mention").

#### Funktion 04: GitHub Enterprise

Die GitHub-Synchronisierung ist nicht mehr auf github.com beschränkt. Setzen Sie `GITHUB_SYNC_URL` auf Ihren GitHub Enterprise Server oder auf GitHub Enterprise Cloud mit Datenresidenz (`GHE.com`), und die REST- und GraphQL-Endpunkte werden daraus abgeleitet. Wenn Ihre Instanz ungewöhnlich eingerichtet ist, überschreiben Sie sie mit `GITHUB_SYNC_API_URL` und `GITHUB_SYNC_GRAPHQL_URL`. Lassen Sie sie leer, bleibt alles auf github.com.

Details finden Sie unter [GitHub-Synchronisierung](/de/on-premises/configuration/overleaf-toolkit/github-synchronisation#github-enterprise  "mention").

#### Funktion 05: Handschriftliche Symbolerkennung

Sie wissen, wie das Symbol aussieht, aber nicht, wie es heißt. Ist es `\varsigma` oder `\zeta`? `\models` oder `\vDash`? Schalten Sie die Symbolpalette in den Zeichenmodus, skizzieren Sie das Symbol mit Maus oder Trackpad, und die Palette schlägt die passenden LaTeX-Befehle vor.

Die Erkennung läuft vollständig im Browser, mit einem von ayaka-notes trainierten Modell, sodass nichts, was Sie zeichnen, Ihren Rechner verlässt. Der Zeichenschalter wird in Browsern ohne `OffscreenCanvas` (z. B. Safari 15) ausgeblendet.

#### Fehlerbehebungen

Diese Version bringt außerdem eine lange Liste von Korrekturen. Viele davon wurden von unserem neuen E2E-Testsystem gefunden, das jetzt täglich Testsuiten für jedes Modul ausführt, sowie von der internen Horizon-Fehleruntersuchung: Jedes Mal, wenn wir einen Fehler beheben, durchsuchen wir die gesamte Codebasis nach verwandten Fehlern, bevor wir ihn schließen.

* **Authentifizierung**: Lokale Konten können auf SSO-Instanzen ihr Passwort festlegen und ändern, und OIDC-Benutzer können ihre eigene E-Mail-Adresse nicht mehr ändern. Anmeldungen über LDAP, SAML und OIDC schlagen nicht mehr fehl, wenn ein Namensattribut mehrere Werte hat, und die Abmeldung über SAML/OIDC funktioniert wieder.
* **Gesperrte Benutzer**: Das Sperren eines Benutzers beendet jetzt seine Sitzungen und schließt seine geöffneten Editoren, und seine Git-Token und MCP-Downloads werden abgelehnt.
* **GitHub-Synchronisierung**: Nur der Eigentümer kann ein Projekt exportieren, während des Pullens vorgenommene Bearbeitungen bleiben ausstehend, leere Dateien werden synchronisiert, und manuelle Merges werden auf GitHub überprüft.
* **Zotero / Mendeley**: Sie erhalten eine Meldung zum erneuten Verknüpfen, wenn Ihre Zugangsdaten nicht mehr funktionieren, und Literaturangaben werden nach einem Import neu indiziert.
* **Externe Dienste**: Anfragen an Zotero, Mendeley, GitHub, GitLab und die Websuche erhalten ein Verbindungs-Timeout von 3 s statt 1 s, sodass langsamere Netzwerke nicht mehr fehlschlagen.
* **Änderungsverfolgung**: Review-Daten umfassen nicht geladene Dokumente und nicht gespeicherte Änderungen.
* **Admin-Panel**: Das Wiederherstellen gelöschter Projekte, das Ändern von Eigentümern und das Bearbeiten von Benutzern funktionieren korrekt, und eine fehlgeschlagene E-Mail verhindert nicht mehr das Erstellen oder Löschen von Konten.
* **Vorlagengalerie**: Eine ungültige Sortierung liefert 400 statt 500, und beim Veröffentlichen eines Projekts ohne Hauptdatei wird nach einer gefragt.

Die vollständige Liste finden Sie in den [Release Notes zu 6.3.1](/de/on-premises/release-notes/release-notes-6.x.x#ayakaleaf-pro-6.3.1  "mention").

#### Upgrade

* Von 6.3.0: Es ist keine Migration erforderlich. Laden Sie das neue Image herunter und starten Sie neu.
* Von 6.2.x oder früher mit Zotero oder Mendeley im Einsatz: Führen Sie zuerst die [Zotero-/Mendeley-Migration](/de/on-premises/release-notes/release-notes-6.x.x#ayakaleaf-pro-6.3.0  "mention") aus 6.3.0 aus.
* Die Dropbox-Synchronisierung und die GitLab-Synchronisierung sind standardmäßig deaktiviert. Die GitLab-Synchronisierung benötigt nur neue Umgebungsvariablen. Für die Dropbox-Synchronisierung müssen außerdem einmalig ihre MongoDB-Indizes erstellt werden, bevor Benutzer ihre Konten verknüpfen: siehe [Datenbankindizes erstellen](/de/on-premises/configuration/overleaf-toolkit/dropbox-synchronisation#create-the-database-indexes  "mention").
