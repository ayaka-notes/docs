Wie Overleaf Server Pro wird auch unser Ayakaleaf Pro als Docker-Container ausgeliefert und ist ein direkter Drop-in-Ersatz, der zusätzlich Funktionen wie SSO über LDAP und SAML2, verbesserte Sicherheit, Änderungsverfolgung, Kommentare, unsere optimierte Version von TeX Live, Vorlagen und ein Administrationspanel enthält.

* Wenn Sie nur die Funktionen von Ayakaleaf Pro testen oder die Demo ausprobieren möchten, können Sie unserem Tutorial [using-the-github-codespace.md](/de/on-premises/installation/using-the-github-codespace  "mention") folgen. Die Demo-Umgebung verwendet eine minimale TeX-Live-Installation, daher lassen sich einige Ihrer Projekte möglicherweise nicht erfolgreich kompilieren.
* Wenn Sie noch nie eine Version von Overleaf bereitgestellt haben, installieren Sie zunächst Docker Engine gemäß [Docker einrichten](/de/on-premises/installation/setup-docker) und anschließend Overleaf gemäß [using-the-toolkit](/de/on-premises/installation/using-the-toolkit  "mention").
* Wenn Sie bereits die Community Edition von Overleaf bereitgestellt haben, lesen Sie [migrate-from-existing.md](/de/on-premises/installation/migrate-from-existing  "mention"), um zu Ayakaleaf Pro zu migrieren.
* Wenn Sie lieber Agenten wie Claude oder Codex verwenden, lesen Sie: [using-claude-or-codex.md](/de/on-premises/installation/using-claude-or-codex  "mention").
* Wenn Sie in einer Offline- oder Air-Gapped-Umgebung bereitstellen müssen, lesen Sie: [air-gapped-offline-deployments.md](/de/on-premises/installation/air-gapped-offline-deployments  "mention").
* Wenn Sie bereits Server Pro nutzen, eröffnen Sie bitte vor der Migration zu Ayakaleaf Pro ein Issue, um uns Bescheid zu geben, da die Vorlagendaten in einem leicht abweichenden Format gespeichert werden. Wir helfen Ihnen sehr gerne kostenlos bei der Migration von Server Pro zu Ayakaleaf Pro.
* Falls Sie unser Ayakaleaf Pro irgendwann leid sind und zur offiziellen Overleaf Community Edition zurückkehren möchten, wird dies vollständig unterstützt. Dabei gehen keine Daten verloren. Nutzer des offiziellen Overleaf Toolkit entfernen einfach ihre Override-YAML-Datei. Nutzer des ayaka-notes-Toolkits deaktivieren die Option `SERVER_PRO`. Danach fällt alles auf die Standard-Community-Edition zurück.

### Hardwareanforderungen

Unsere Tests haben ergeben, dass die Kernkomponenten von Overleaf – die hauptsächlich auf Node.js basieren – auf einem Server mit 2 Kernen und 2 GB RAM etwa 1 GB Arbeitsspeicher belegen. Redis und MongoDB benötigen möglicherweise weitere 0,5 GB, und das Starten eines Docker-Containers in einer Sandbox für die Kompilierung kann zusätzliche 0,3 GB beanspruchen. Ein Server mit 2 Kernen und 2 GB kann also realistisch nur etwa eine gleichzeitige Kompilierung bewältigen.

* Die Mindestanforderungen an die Hardware für die Installation von Ayakaleaf Pro sind eine CPU mit 2 Kernen und 3 GB RAM.
* Aufgrund der Größe unseres TeX-Live-Images sind mindestens 40 GB Speicherplatz erforderlich, um die Kompilierung in der Sandbox zu aktivieren.
* Wenn Sie den vollständigen Satz an TeX-Live-Images von 2020 bis 2026 installieren möchten, stellen Sie sicher, dass mindestens 150 GB freier Speicherplatz verfügbar sind.

Hier einige empfohlene Hardwarekonfigurationen für verschiedene Einsatzszenarien:

| Anwendungsfall                                       | Empfohlene Konfiguration                                                                             |
| ---------------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| Private Nutzung mit gelegentlicher Zusammenarbeit    | 2 CPU-Kerne, 4 GB RAM, 80 GB Speicher                                                                |
| Kleine Teams, bis zu 10 Benutzer mit geringer Zusammenarbeit | 2 CPU-Kerne, 8 GB RAM, 256 GB Speicher                                                       |
| Mittelgroße Teams, bis zu 100 Benutzer               | 4 CPU-Kerne, 16 GB RAM, 1 TB Speicher                                                                |
| Großbereitstellungen oder Universitäten              | Verteilte Cluster-Bereitstellung mit S3-Speicher; kontaktieren Sie uns, wenn Sie Unterstützung bei der Bereitstellung benötigen |

### Softwareanforderungen

Was die Software betrifft, empfehlen wir eine aktuelle und stabile Ubuntu-Version (z. B. Ubuntu 24.04 in 2025–2026, Ubuntu 22.04 in 2023–2024) zusammen mit der neuesten stabilen Docker-Version.

<Info>

Stabilität hat Vorrang: Wählen Sie die neueste Ubuntu-LTS-Version, die schon eine Weile verfügbar ist, nicht eine gerade erst veröffentlichte. Beispielsweise wird Ubuntu 26.04 (Stand Oktober 2026) nicht unterstützt: Es wird mit Linux-Kernel 7.0 ausgeliefert, und MongoDB startet nicht auf Linux-Kerneln von 6.19 bis 7.0.13 ([Details](https://www.mongodb.com/docs/manual/administration/production-notes/)). Verwenden Sie daher bitte Ubuntu 24.04.

</Info>

Wir raten davon ab, Ayakaleaf Pro unter Windows oder anderen nicht unterstützten Betriebssystemen wie CentOS bereitzustellen, da bei Installation und Betrieb Kompatibilitätsprobleme oder unerwartete Fehler auftreten können.

Wenn Sie Ayakaleaf Pro jedoch auf ARM-basierten Systemen oder macOS ausprobieren möchten, freuen wir uns, wenn Sie Ihre Erfahrungen und Ihr Feedback mit der Community teilen.

### LaTeX-Leistung

LaTeX ist ein Single-Thread-Programm und kann daher jeweils nur einen CPU-Kern nutzen. Beim Kompilieren eines einzelnen Dokuments wird die Leistung in erster Linie durch die Single-Core-Taktfrequenz der CPU begrenzt. Je höher also die Single-Core-Leistung Ihrer CPU, desto schneller können Sie ein Dokument kompilieren. Mehr CPU-Kerne bringen nur dann Vorteile, wenn mehrere Benutzer gleichzeitig Dokumente kompilieren.

Am Beispiel der [ThuThesis-Vorlage](https://www.overleaf.com/latex/templates/thuthesis-tsinghua-university-thesis-latex-template/cfwgcxtvkbsx) beträgt die Kompilierungszeit auf einem Intel Core i9-14900K (5,6 GHz) etwa 6 Sekunden, während sie auf einer Azure-Standard-D2as-v5-Instanz (2 vCPUs, 8 GiB RAM) mit einem AMD EPYC 7763 (3,2 GHz) etwa 13 Sekunden dauert.

Natürlich hängt die tatsächliche Kompilierungsleistung von Ihrer Hardwarekonfiguration ab. Die meisten Server-CPUs erreichen keine so hohen Taktfrequenzen wie der 14900K, daher müssen Sie zwischen Kosten und Kompilierungsgeschwindigkeit abwägen.

Darüber hinaus haben wir eine ausführliche Analyse der LaTeX-Kompilierungsleistung durchgeführt. Bei Interesse lesen Sie unseren Blogbeitrag [Overleaf Benchmark: A Deep Research of Concurrent LaTeX Compilation in Overleaf (SaaS and Self-host)](/de/blog/2026/overleaf-benchmark  "mention").
