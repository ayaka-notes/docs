Verwenden Sie Claude Code oder Codex, um ein Deployment von Ayakaleaf Pro zu planen und durchzuführen. Der Agent kann diese Dokumentation während der Arbeit über MCP durchsuchen.

Der Agent unterstützt Sie beim Deployment. Sie bleiben dafür verantwortlich, Befehle zu überprüfen und Zugangsdaten zu schützen.

### Bevor Sie beginnen

Bereiten Sie einen unterstützten Linux-Server mit SSH-Zugang vor. Lesen Sie die [Anforderungen](/de/on-premises/getting-started/requirements  "mention"), bevor Sie fortfahren.

<Warning>

Fügen Sie keine Passwörter, Private Keys, Tokens oder Lizenzschlüssel in Agenten-Prompts ein. Überprüfen Sie jeden Befehl vor der Ausführung, insbesondere Befehle, die Dateien, Netzwerke oder Container verändern.

</Warning>

### Dokumentation verbinden

Fügen Sie Ihrem lokalen Agenten den MCP-Endpunkt der Dokumentation hinzu.

<Tabs>
<Tab title="Claude Code">

```bash wrap
claude mcp add ayakaleaf-pro --scope user --transport http https://ayakaleaf-pro.ayaka.space/~gitbook/mcp
```

</Tab>

<Tab title="Codex">

```bash wrap
codex mcp add ayakaleaf-pro --url https://ayakaleaf-pro.ayaka.space/~gitbook/mcp
```

</Tab>
</Tabs>

Starten Sie nach dem Hinzufügen des Servers eine neue Sitzung. Bitten Sie den Agenten zu bestätigen, dass er die Ayakaleaf-Pro-Dokumentation durchsuchen kann.

### Ayakaleaf Pro bereitstellen

Öffnen Sie ein Terminal auf Ihrem Deployment-Server. Starten Sie dort Claude Code oder Codex. Senden Sie dann diesen Prompt:

```text wrap
Use the Ayakaleaf Pro documentation MCP server to guide this deployment.
First, inspect the requirements and installation guides.
Ask me for missing deployment details before making changes.
Use the Ayakaleaf Toolkit unless the documentation requires another approach.
Before configuring the instance, summarize relevant optional features.
Ask which features and integrations I want to enable.
Include TLS, sandboxed compiles, Git integration, external MongoDB or Redis,
SSO (OIDC, SAML, or LDAP), GitHub Synchronisation, Zotero, S3 storage,
email delivery, branding, and localization when relevant.
Explain each selected option's prerequisites, security impact, and configuration steps.
Keep unselected optional features disabled.
Show each command before running it.
Do not expose, store, or request secrets in chat.
After deployment, verify that the service is healthy and summarize the changes.
```

Der Agent sollte Sie durch die Docker-Einrichtung, die Toolkit-Konfiguration, den Abruf der Images und den Start führen. Folgen Sie der Anleitung [using-the-toolkit](/de/on-premises/installation/using-the-toolkit  "mention") für den maßgeblichen Ablauf.

### Optionale Funktionen auswählen

Bitten Sie den Agenten, nur Funktionen zu empfehlen, die zu Ihrer Umgebung passen. Typische Optionen sind:

* **Zugriff und Sicherheit:** TLS, Sandboxed Compiles sowie SSO über OIDC, SAML oder LDAP.
* **Externe Dienste:** MongoDB, Redis, S3-Speicher und E-Mail-Versand.
* **Zusammenarbeit:** Git-Integration, GitHub Synchronisation und Zotero.

Der Agent sollte Abhängigkeiten erläutern, bevor er die Konfiguration bearbeitet. Lesen Sie [toolkit-settings.md](/de/on-premises/configuration/overleaf-toolkit/toolkit-settings  "mention") und [authentication](/de/on-premises/configuration/overleaf-toolkit/authentication  "mention"), bevor Sie Integrationen für die Produktion aktivieren.

### Deployment überprüfen

Nachdem der Agent die Schritte abgeschlossen hat:

1. Bestätigen Sie, dass jeder Befehl ohne Fehler ausgeführt wurde.
2. Öffnen Sie die konfigurierte Ayakaleaf-Pro-URL in Ihrem Browser.
3. Führen Sie die [6.-post-installation-tasks.md](/de/on-premises/installation/using-the-toolkit/6.-post-installation-tasks  "mention") durch.

Verwenden Sie für eine bestehende Community-Edition-Installation die Anleitung [migrate-from-existing.md](/de/on-premises/installation/migrate-from-existing  "mention") anstelle eines neuen Deployments.
