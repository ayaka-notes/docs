### Migration von Overleaf Community

#### Fall 01: Vom Overleaf Toolkit

Wenn Sie das offizielle Overleaf Toolkit für Overleaf Community verwenden, fügen Sie einfach eine Datei namens `docker-compose.override.yml` mit folgendem oder ähnlichem Inhalt in das Verzeichnis `overleaf-toolkit/config` ein:

```yml title="docker-compose.override.yml"
---
services:
    sharelatex:
        image: ghcr.io/ayaka-notes/overleaf-pro:X.x.x # change to specific version
```

Um Ihre Instanz zu starten, führen Sie Folgendes aus:

```bash
bin/up
```

Das war's! Alles ist bereit. Als Nächstes können Sie überprüfen, ob Ihre Ayakaleaf-Instanz korrekt läuft und ob Sie auf die Weboberfläche zugreifen können. Sobald alles funktioniert, fahren Sie mit den unten aufgeführten Schritten zur [Konfiguration](/de/on-premises/configuration/overleaf-toolkit) fort, um erweiterte Funktionen zu aktivieren, wie zum Beispiel:

* [sandboxed-compiles.md](/de/on-premises/configuration/overleaf-toolkit/sandboxed-compiles  "mention")
* [authentication](/de/on-premises/configuration/overleaf-toolkit/authentication  "mention")
* [github-synchronisation.md](/de/on-premises/configuration/overleaf-toolkit/github-synchronisation  "mention")
* [zotero-integration.md](/de/on-premises/configuration/overleaf-toolkit/zotero-integration  "mention")

#### Fall 02: Von einer Docker Compose-Datei

Wenn Sie eine eigenständige `docker-compose.yml` verwenden, migrieren Sie diese zunächst zum Overleaf Toolkit. Das Toolkit vereinfacht die On-Premises-Installation, Upgrades und die Wartung.

Folgen Sie der Anleitung [docker-compose.yml-to-toolkit-migration.md](/de/on-premises/maintenance/docker-compose.yml-to-toolkit-migration  "mention"), um Ihre bestehende Bereitstellung umzustellen. Behalten Sie während dieser Migration Ihre aktuelle Konfiguration und die Pfade Ihrer Daten-Volumes bei.

Sobald die Toolkit-Bereitstellung läuft, folgen Sie [#from-overleaf-toolkit](/de/on-premises/installation/migrate-from-existing#from-overleaf-toolkit  "mention"), um das Image auf Ayakaleaf Pro umzustellen. Starten Sie die Instanz mit `bin/up` und überprüfen Sie anschließend, ob Sie auf die Weboberfläche zugreifen können.

### Migration von Overleaf Server Pro

Wenn Sie derzeit eine kommerziell lizenzierte Instanz von [Overleaf Server Pro](https://www.overleaf.com/for/enterprises) betreiben und zu Ayakaleaf Pro migrieren möchten, beachten Sie bitte, dass die Migration zusätzlichen Aufwand erfordern kann, da bestimmte Datenformate (`templates`) möglicherweise nicht vollständig kompatibel sind. Wir helfen Ihnen jedoch gerne. Bitte [eröffnen Sie ein Issue](https://github.com/ayaka-notes/ayakaleaf-pro/issues) oder kontaktieren Sie uns unter [ayaka-notes@outlook.com](mailto:ayaka-notes@outlook.com), und wir unterstützen Sie kostenlos bei der Migration zu Ayakaleaf Pro.

***

### Migration von Overleaf CEP

Wir erhalten häufig Fragen von Benutzern, ob sie von [Overleaf CEP](https://github.com/yu-i-i/overleaf-cep) zu Ayakaleaf Pro migrieren können. In den meisten Fällen bieten Overleaf CEP und Ayakaleaf Pro weitgehend gleichwertige Funktionen und sind ab Version 6.2.0 datenkompatibel. Die beiden Projekte veröffentlichen Funktionen möglicherweise zu unterschiedlichen Zeitpunkten; beispielsweise übernehmen wir per Cherry-Pick eine Funktion aus Overleaf CEP und umgekehrt. Auch wenn sich unsere Implementierungen derselben Funktion leicht unterscheiden können, gibt es im Allgemeinen keinen zwingenden Grund für eine Migration.

Wenn Sie dennoch zu Ayakaleaf Pro migrieren oder es ausprobieren möchten, lesen Sie bitte: [#case-01-from-overleaf-toolkit](/de/on-premises/installation/migrate-from-existing#case-01-from-overleaf-toolkit  "mention"). Der Migrationsprozess ist derselbe.

***

### Migration von Overleaf SaaS

Leider kann die Migration von der Overleaf-SaaS-Plattform zu einer selbst gehosteten Ayakaleaf Pro-Instanz deutlich schwieriger sein. Derzeit besteht die einzige allgemein verfügbare Methode darin, jedes Projekt als ZIP-Archiv herunterzuladen und anschließend in Ihre selbst gehostete Ayakaleaf Pro-Instanz hochzuladen. Dabei werden nur die aktuellen Projektdateien übertragen, das heißt, Sie _**verlieren**_:

* Den gesamten Projektverlauf und alle früheren Revisionen
* Alle Kommentare und nachverfolgten Änderungen
* Alle Git-Metadaten und den Commit-Verlauf
* Alle GitHub-Synchronisationsverknüpfungen und -Einstellungen
* Alle Verknüpfungen zwischen BibTeX-Dateien und Literaturverwaltungsplattformen von Drittanbietern

***

### Migration von einem Overleaf-Fork eines Drittanbieters

Ayakaleaf Pro unterstützt möglicherweise keine Funktionen, die spezifisch für einen bestimmten Overleaf-Fork eines Drittanbieters sind. Sobald ein Fork erheblich von der Upstream-Codebasis von Overleaf abweicht – oder Änderungen ohne Wahrung der Upstream-Kompatibilität einführt –, kann das Zusammenführen nachfolgender Overleaf-Releases äußerst schwierig werden. Sie können die oben beschriebene Migrationsmethode dennoch ausprobieren, die Kompatibilität ist jedoch nicht garantiert, und wir können bei Migrationen von nicht unterstützten Forks möglicherweise keine Hilfe oder technische Unterstützung leisten.
