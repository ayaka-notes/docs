---
title: 1. Toolkit herunterladen und initialisieren
description: Klonen Sie das Ayakaleaf Toolkit, erstellen Sie die Konfiguration und richten Sie sie für Ayakaleaf Pro auf Podman ein.
icon: arrow-down-to-bracket
---

<Steps>
<Step title="Toolkit klonen">
Klonen Sie das **Ayakaleaf Toolkit** ([ayaka-notes/toolkit](https://github.com/ayaka-notes/toolkit)) in Ihr Home-Verzeichnis und wechseln Sie hinein:

```bash title="Clone the Toolkit" wrap
git clone https://github.com/ayaka-notes/toolkit.git ~/overleaf-toolkit
cd ~/overleaf-toolkit
```

Führen Sie alle folgenden Befehle in diesem Verzeichnis aus.
</Step>

<Step title="Konfiguration erstellen">
```bash title="Run initialization"
bin/init
```

Dies erstellt `config/overleaf.rc`, `config/variables.env` und `config/version`, wie in [3. Konfiguration initialisieren](/de/on-premises/installation/using-docker-compose/linux/3.-initialize-the-configuration) der Docker-Anleitung beschrieben. `bin/init` benötigt noch kein Podman.
</Step>

<Step title="config/overleaf.rc einrichten">
Öffnen Sie `config/overleaf.rc` und ändern Sie diese Zeilen:

```bash title="config/overleaf.rc"
SERVER_PRO=true
OVERLEAF_PORT=8080
SIBLING_CONTAINERS_ENABLED=true
```

Fügen Sie dann diese Zeile am Ende der Datei hinzu:

```bash title="config/overleaf.rc"
SELINUX_MODE=managed
```

| Einstellung                       | Warum                                                                                                                                                                                                       |
| --------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `SERVER_PRO=true`                 | Verwendet das Ayakaleaf-Pro-Image von `ghcr.io`. Eine Anmeldung ist nicht nötig.                                                                                                                             |
| `OVERLEAF_PORT=8080`              | Rootless Podman kann nicht auf Ports unter `1024` lauschen. Der Standardwert `80` schlägt fehl.                                                                                                              |
| `SIBLING_CONTAINERS_ENABLED=true` | Führt jede Kompilierung in einem eigenen TeX-Live-Container aus. Standardmäßig bereits `true`; die Podman-Einrichtung unterstützt nur diesen Modus.                                                          |
| `SELINUX_MODE=managed`            | Führt den Container `sharelatex` mit dem SELinux-Typ `sharelatex_t` aus, der den Podman-Socket verwenden darf und sonst nichts. `bin/podman-setup --apply` installiert das Richtlinienmodul dafür. Die anderen Modi finden Sie unter [Toolkit-Einstellungen](/de/on-premises/configuration/overleaf-toolkit/toolkit-settings). |

Lassen Sie `DOCKER_SOCKET_PATH` unverändert: `bin/podman-setup --apply` setzt es im nächsten Schritt auf Ihren Podman-Socket.

<Warning>

Belassen Sie `GIT_BRIDGE_ENABLED=false`. In Ayakaleaf Pro 6.3.4 funktioniert die Git-Integration auf Podman nicht, siehe [Bekannte Einschränkungen](/de/on-premises/installation/using-podman#known-limitations).

</Warning>
</Step>

<Step title="TeX-Live-Images auswählen">
Öffnen Sie `config/variables.env`, entfernen Sie das `#` vor `TEX_LIVE_DOCKER_IMAGE` und `ALL_TEX_LIVE_DOCKER_IMAGES` und listen Sie die zu verwendenden TeX-Live-Images auf:

```bash title="config/variables.env" wrap
TEX_LIVE_DOCKER_IMAGE=ghcr.io/ayaka-notes/texlive-full:2026.1
ALL_TEX_LIVE_DOCKER_IMAGES=ghcr.io/ayaka-notes/texlive-full:2026.1
```

`bin/up` bricht mit `Please configure ALL_TEX_LIVE_DOCKER_IMAGES` ab, wenn die Liste leer ist. `texlive-full` ist groß; für einen Testserver funktioniert auch das viel kleinere `ghcr.io/ayaka-notes/texlive-basic:2026.1`. Die verfügbaren Images finden Sie unter [Sandboxed Compiles](/de/on-premises/configuration/overleaf-toolkit/sandboxed-compiles).

Setzen Sie die anderen Variablen wie `OVERLEAF_SITE_URL` wie in [5. Ihre Instanz personalisieren](/de/on-premises/installation/using-docker-compose/linux/5.-personalizing-your-instance#required-environment-variables) beschrieben. Verwenden Sie mit der Standard-Listen-Adresse `http://localhost:8080`.
</Step>
</Steps>
