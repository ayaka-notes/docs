---
title: 3. Ayakaleaf Pro starten
description: Starten Sie Ayakaleaf Pro auf Podman, überprüfen Sie es mit podman-setup und bin/doctor und starten Sie es nach Neustarts automatisch.
icon: circle-play
---

<Steps>
<Step title="Container starten">
```bash title="Start Ayakaleaf Pro"
bin/up -d
```

Beim ersten Start werden die Images von MongoDB, Redis und TeX Live heruntergeladen und die Datenverzeichnisse in `data/` erstellt. Es wird eine Warnung ausgegeben, dass die Podman-Unterstützung experimentell ist.

<Info>

Beim ersten Start kann außerdem `MongoNetworkError: connect ECONNREFUSED 127.0.0.1:27017` erscheinen. Das Toolkit richtet das MongoDB-Replikat-Set ein, während MongoDB noch startet, und versucht es erneut, bis MongoDB antwortet. Sie können diese Zeile ignorieren.

</Info>

Prüfen Sie nach ein oder zwei Minuten, ob die Container laufen:

```bash title="List the containers"
podman ps --format "{{.Names}} {{.Status}}"
```

```text
mongo Up 34 seconds (healthy)
redis Up 20 seconds
sharelatex Up 20 seconds
```
</Step>

<Step title="Einrichtung erneut prüfen">
Da die Datenverzeichnisse jetzt existieren und der Container `sharelatex` läuft, kann `bin/podman-setup` seine Prüfungen abschließen:

```bash title="Check the setup"
bin/podman-setup
```

Es prüft die Eigentümer der neuen Datenverzeichnisse und testet den Podman-Socket aus dem Container `sharelatex` heraus:

```text
====== Socket Connectivity ======
[✓] host → socket OK
[✓] container → socket OK

====== Data Directory Permissions ======
[✓] mongo data dir owned by 999
[✓] redis data dir owned by 999
[✓] overleaf data dir owned by 33
...
====== Summary ======
[✓] 27 passed  [!] 1 warnings  [✗] 0 failures
[!] Warnings:
[!] not logged in to quay.io
```

`container → socket OK` bedeutet, dass Ayakaleaf Pro Kompilierungscontainer starten kann. Wenn eine Prüfung fehlschlägt, führen Sie `bin/podman-setup --apply` und dann `bin/up -d` aus. Die quay.io-Warnung betrifft Ayakaleaf Pro nicht, siehe [2. podman-setup ausführen](/de/on-premises/installation/using-podman/2.-run-podman-setup).
</Step>

<Step title="Doctor ausführen">
```bash title="Run the doctor"
bin/doctor
```

Auf Podman zeigt der Bericht die Laufzeitumgebung und die Sicherheitseinstellungen:

```text
- Container Daemon
    - status: up
    - runtime: podman
    - server version: 5.8.5
    - socket: /run/user/1000/podman/podman.sock
    - DOCKER_HOST: unix:///run/user/1000/podman/podman.sock
    - host → socket: OK
    - container → socket: OK
- Security
    - SELinux: Enforcing
    - SELINUX_MODE: managed
    - SELINUX_LABEL: sharelatex_t
    - SELinux module: loaded (podman_socket_clsi)
    - SELinux rules: present
    - Seccomp profile: present
```

Die Warnung `Server Pro enabled, but not logged in to quay.io repository` am Ende ist dieselbe quay.io-Prüfung, siehe [Hilfe erhalten](/de/on-premises/support/getting-help#q-and-a).
</Step>

<Step title="Ayakaleaf Pro nach einem Neustart starten">
Mit Docker startet der Docker-Daemon die Container nach einem Neustart wieder. Rootless Podman hat keinen Daemon: Aktivieren Sie den Benutzerdienst, der Ihre Container beim Hochfahren des Servers startet:

```bash title="Start the containers at boot"
systemctl --user enable podman-restart.service
```

Er startet jeden Container Ihres Benutzers mit der Neustartrichtlinie `always`, die das Toolkit für alle seine Container setzt. Dafür ist Lingering nötig, das `bin/podman-setup --apply` aktiviert hat. Ohne diesen Dienst führen Sie nach jedem Neustart `bin/up -d` aus.
</Step>

<Step title="Port in der Firewall öffnen">
Standardmäßig akzeptiert die Instanz nur Verbindungen vom Server selbst unter `http://localhost:8080`. Um sie von anderen Computern aus zu öffnen, setzen Sie `OVERLEAF_LISTEN_IP` in `config/overleaf.rc` und `OVERLEAF_SITE_URL` in `config/variables.env` wie in [5. Ihre Instanz personalisieren](/de/on-premises/installation/using-docker-compose/linux/5.-personalizing-your-instance#listen-address-and-port) beschrieben und führen Sie `bin/up -d` erneut aus.

Anders als Docker umgeht Rootless Podman die Host-Firewall nicht. Wenn `firewalld` läuft, was unter RHEL der Standard ist, öffnen Sie den Port:

```bash title="Open port 8080"
sudo firewall-cmd --permanent --add-port=8080/tcp
sudo firewall-cmd --reload
```

Erlauben Sie auf einem Cloud-Server den Port auch in der Sicherheitsgruppe des Anbieters. Verwenden Sie HTTPS, bevor Sie die Instanz dem Internet zugänglich machen, siehe [4. Aufgaben nach der Installation](/de/on-premises/installation/using-podman/4.-post-installation-tasks#use-https).
</Step>
</Steps>
