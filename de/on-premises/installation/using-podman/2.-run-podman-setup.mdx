---
title: 2. podman-setup ausführen
description: Lassen Sie bin/podman-setup den Host prüfen und Rootless Podman, SELinux und das Seccomp-Profil einrichten.

---

`bin/podman-setup` prüft alles, was Ayakaleaf Pro auf Podman benötigt. Ohne Optionen erstellt es nur einen Bericht; mit `--apply` behebt es außerdem, was es findet.

<Steps>
<Step title="Host prüfen">
```bash title="Check only"
bin/podman-setup
```

Auf einem frischen Host schlagen die meisten Prüfungen fehl, zum Beispiel:

```text
====== Packages ======
[✗] podman not installed
[✗] podman-docker not installed
...
====== Summary ======
[✓] 7 passed  [!] 13 warnings  [✗] 4 failures
```
</Step>

<Step title="Korrekturen anwenden">
```bash title="Check and fix"
bin/podman-setup --apply
```

Führen Sie es in einem Terminal aus: Für die systemweiten Schritte fragt es nach Ihrem `sudo`-Passwort. Außerdem lädt es das Ayakaleaf-Pro-Image herunter, um dessen Seccomp-Profil zu extrahieren, was beim ersten Mal einige Minuten dauert. Am Ende prüft es den Host erneut:

```text
====== Summary ======
[✓] 23 passed  [!] 2 warnings  [✗] 0 failures
[!] Warnings remaining:
[!] not logged in to quay.io
[!] container → socket skipped (sharelatex not running)
```

Beide Warnungen sind an dieser Stelle zu erwarten:

* `not logged in to quay.io`: Die Prüfung stammt aus dem offiziellen Toolkit, in dem das Server-Pro-Image in einer privaten Registry liegt. Ayakaleaf-Pro-Images sind öffentlich auf `ghcr.io` verfügbar und benötigen keine Anmeldung, ignorieren Sie die Warnung also. Sie bleibt auch nach der Installation bestehen.
* `container → socket skipped (sharelatex not running)`: Dieser Test benötigt die laufende Instanz. Sie führen das Skript in [3. Ayakaleaf Pro starten](/de/on-premises/installation/using-podman/3.-start-ayakaleaf-pro) erneut aus.

Das Skript beendet sich mit `0`, wenn alle Prüfungen bestanden sind, mit `1` bei Warnungen und mit `2` bei Fehlern. Wegen der quay.io-Warnung ist `1` zu erwarten.
</Step>
</Steps>

### Was das Skript ändert {#what-the-script-changes}

Mit `--apply` kann das Skript Folgendes ändern.

Systemweit, mit `sudo`:

* Installiert `podman`, `podman-docker`, `git`, `curl`, `checkpolicy` und `policycoreutils` mit `dnf`.
* Aktiviert Lingering für Ihren Benutzer mit `loginctl`, damit Ihre Container nach dem Abmelden weiterlaufen.
* Erstellt `/etc/containers/nodocker`, das die Meldung "Emulate Docker CLI using podman" unterdrückt.
* Lädt das SELinux-Richtlinienmodul `podman_socket_clsi`, wenn `SELINUX_MODE=managed` gesetzt ist.

Für Ihren Benutzer:

* Aktiviert den Benutzerdienst `podman.socket`, die Docker-kompatible API, mit der Ayakaleaf Pro Kompilierungen startet.
* Installiert Docker Compose v2 von GitHub nach `~/.local/bin/docker-compose` und verlinkt es in `~/.docker/cli-plugins/`.
* Lässt Podman dieses Compose in `~/.config/containers/containers.conf` verwenden.
* Fügt die Aliasse `mongo` und `redis` in `~/.config/containers/registries.conf.d/overleaf-toolkit.conf` hinzu, damit Podman weiß, woher diese kurzen Image-Namen geladen werden.

Im Toolkit:

* Setzt `DOCKER_SOCKET_PATH` und `DOCKER_HOST` in `config/overleaf.rc` auf `/run/user/<uid>/podman/podman.sock`.
* Extrahiert das Seccomp-Profil für Kompilierungen aus dem Ayakaleaf-Pro-Image nach `config/seccomp/<version>/clsi-profile.json` und setzt `SECCOMP_PROFILE` in `config/variables.env`. Anders als Docker benötigt Podman dieses Profil als Datei auf dem Host.
* Baut das SELinux-Richtlinienmodul in `config/selinux/`.
* Setzt die Eigentümer der Datenverzeichnisse in `data/` mit `podman unshare chown`, sobald sie existieren.

<Info>

Jede Änderung entspricht einer Prüfung. Wenn Sie etwas von Hand ändern, zum Beispiel in `config/overleaf.rc`, führen Sie `bin/podman-setup` erneut aus, um es zu überprüfen.

</Info>
