RHEL und seine Nachbauten (Rocky Linux, AlmaLinux) liefern Podman statt Docker aus, und manche Organisationen erlauben Docker auf ihren Servern nicht. Das Toolkit kann Ayakaleaf Pro stattdessen auf **Rootless Podman** ausführen: Die Container laufen unter einem normalen Benutzer, Kompilierungen laufen weiterhin in isolierten TeX-Live-Containern, und SELinux bleibt im Modus enforcing. Das Skript `bin/podman-setup` prüft den Host und behebt, was es beheben kann.

Am Ende dieses Abschnitts haben Sie dieselbe Instanz wie mit [Docker Compose verwenden](/de/on-premises/installation/using-docker-compose): Ayakaleaf Pro mit Sandboxed Compiles, MongoDB und Redis, verwaltet mit den gewohnten Befehlen `bin/up`, `bin/doctor` und `bin/upgrade`.

<Info>

Die Podman-Unterstützung ist experimentell. Sie stammt aus dem offiziellen Overleaf Toolkit, das sie nur unter RHEL 9 und neuer mit Rootless Podman, Sandboxed Compiles und SELinux im Modus enforcing testet. Wir haben diese Seiten unter Rocky Linux 9.9 (Podman 5.8, SELinux enforcing) mit Ayakaleaf Pro 6.3.4 getestet. Docker bleibt die empfohlene Container-Laufzeitumgebung.

</Info>

### Was Sie benötigen {#what-you-need}

* **RHEL, Rocky Linux, AlmaLinux oder CentOS Stream 9 oder neuer** mit SELinux im Modus enforcing. Auf jeder anderen Distribution bricht `bin/podman-setup` ab. Verwenden Sie unter Ubuntu oder Debian [Docker Compose verwenden](/de/on-premises/installation/using-docker-compose/linux).
* **Einen Benutzer ohne Root-Rechte mit `sudo`**, dem die Container gehören. Führen Sie jeden Befehl in diesem Abschnitt als dieser Benutzer aus; `bin/podman-setup` verweigert die Ausführung als `root`.
* **Einen sauberen Host**: keine Docker Engine und keine bestehende Toolkit-Installation. Der Umzug einer bestehenden Docker-basierten Instanz auf Podman wird nicht behandelt.

### Unterschiede zu Docker {#how-it-differs-from-docker}

|                                  | Docker                               | Rootless Podman                                                                          |
| -------------------------------- | ------------------------------------ | ---------------------------------------------------------------------------------------- |
| Wer die Container ausführt       | Der Docker-Daemon als `root`         | Ihr Benutzer                                                                             |
| Socket zum Starten von Kompilierungen | `/var/run/docker.sock`          | `/run/user/<uid>/podman/podman.sock`                                                     |
| Ports                            | Beliebig, zum Beispiel `80` und `443` | `1024` und höher, zum Beispiel `8080`                                                   |
| Host-Firewall (`firewalld`)      | Wird von veröffentlichten Ports umgangen | Gilt: Öffnen Sie den Port mit `firewall-cmd`                                         |
| Start nach einem Neustart        | Der Docker-Daemon startet sie neu    | Der Benutzerdienst `podman-restart`                                                      |
| SELinux                          | Wird vom Toolkit nicht konfiguriert  | Richtlinienmodul `podman_socket_clsi` und `SELINUX_MODE=managed` in `config/overleaf.rc`  |
| Seccomp-Profil für Kompilierungen | Im Image enthalten                  | Vom Toolkit nach `config/seccomp/<version>/` extrahiert und als `SECCOMP_PROFILE` gesetzt |

### Bekannte Einschränkungen {#known-limitations}

* <strong>Git-Integration.</strong> In Ayakaleaf Pro 6.3.4 schlägt `git clone` auf Podman mit `502` fehl: Das NGINX im Image sucht den Container `git-bridge` über den DNS-Server von Docker (`127.0.0.11`), den Podman nicht hat. Die Korrektur ([1b911d1092](https://github.com/ayaka-notes/ayakaleaf-pro/commit/1b911d1092c80f7b0ff77c5e3805b40503d49964)) kommt mit dem nächsten Release; belassen Sie bis dahin `GIT_BRIDGE_ENABLED=false`.
* <strong>Client-IP-Adressen.</strong> Rootless Podman leitet den veröffentlichten Port aus dem Netzwerk des Containers weiter, daher sieht Ayakaleaf Pro jeden Besucher mit einer internen Adresse wie `10.89.0.15`. Die [Audit-Logs](/de/on-premises/user-guide/administrators/user-management#audit-logs) eines Benutzers im Admin-Panel zeigen diese Adresse statt seiner IP-Adresse.
