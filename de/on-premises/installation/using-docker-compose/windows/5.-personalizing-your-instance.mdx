---
title: 5. Ihre Instanz personalisieren
description: Legen Sie Port, Site-URL und TeX Live-Image fest, aktivieren Sie Sandboxed Compiles und starten Sie Ayakaleaf Pro unter WSL 2.
icon: square-sliders
---

Führen Sie Befehle aus und bearbeiten Sie Dateien in **Ubuntu**, und zwar aus `~/ayakaleaf-toolkit`.

<Steps>
<Step title="Container-Einstellungen">
Bearbeiten Sie die vorhandenen Einträge in `config/overleaf.rc`:

```bash title="config/overleaf.rc"
PROJECT_NAME=ayakaleaf-wsl
SERVER_PRO=true
OVERLEAF_LISTEN_IP=127.0.0.1
OVERLEAF_PORT=8080
SIBLING_CONTAINERS_ENABLED=true
DOCKER_SOCKET_PATH=/var/run/docker.sock
```

Behalten Sie die Standard-Datenpfade und die mitgelieferten MongoDB- und Redis-Dienste bei. Port `8080` ist für den lokalen Windows-Browser gedacht; die Bindung an `127.0.0.1` hält ihn lokal. Sandboxed Compiles verwenden für jede Kompilierung einen separaten Linux-Container, statt TeX im Anwendungscontainer auszuführen. Über den Docker-Socket kann die Anwendung diese Container erstellen, und das Toolkit stellt den Host-Pfad für die Kompilierungsdaten unter `data/overleaf/data/compiles` bereit.
</Step>

<Step title="Anwendungseinstellungen">
Setzen Sie in `config/variables.env` diese Werte und ersetzen Sie dabei alle aktiven Einträge mit denselben Namen:

```dotenv title="config/variables.env"
OVERLEAF_SITE_URL=http://localhost:8080
TEX_LIVE_DOCKER_IMAGE=ghcr.io/ayaka-notes/texlive-full:2026.1
ALL_TEX_LIVE_DOCKER_IMAGES=ghcr.io/ayaka-notes/texlive-full:2026.1
ALL_TEX_LIVE_DOCKER_IMAGE_NAMES="TeX Live 2026"
```

Das vollständige Image enthält die Pakete und Schriften, die für ein breites Spektrum an Projekten benötigt werden. Planen Sie dafür und für die Anwendung mindestens 40 GB freien Speicherplatz ein, zuzüglich Platz für Projektdaten und künftige Updates.

Verwenden Sie für einen schnellen Bereitstellungstest stattdessen das kleinere **basic**-Image. Es reicht für den einfachen article-Test in Schritt 6, enthält aber nicht den vollständigen Paket- und Schriftenumfang:

```dotenv
TEX_LIVE_DOCKER_IMAGE=ghcr.io/ayaka-notes/texlive-basic:2026.1
ALL_TEX_LIVE_DOCKER_IMAGES=ghcr.io/ayaka-notes/texlive-basic:2026.1
ALL_TEX_LIVE_DOCKER_IMAGE_NAMES="TeX Live 2026 Basic"
```

Wählen Sie einen dieser Sätze, ohne doppelte aktive Schlüssel. Das [Dockerfile](https://github.com/ayaka-notes/texlive-full/blob/main/texlive/2026/Dockerfile.basic) des basic-Images enthält `latexmk`, XeTeX und `fontspec`, aber weder `ctex` noch die vollständige Schriftensammlung. Ein fehlendes LaTeX-Paket im basic-Image deutet für sich genommen nicht auf ein Sandbox-Problem hin.

Erzeugen Sie ein Session-Secret:

```bash
openssl rand -hex 32
```

Fügen Sie das Ergebnis als `OVERLEAF_SESSION_SECRET` in `config/variables.env` ein. Bewahren Sie auch das erzeugte Invite-Token-Secret auf. Lassen Sie für eine lokale Instanz ohne E-Mail die SMTP-Einstellungen und `OVERLEAF_EMAIL_FROM_ADDRESS` ungesetzt.
</Step>

<Step title="Ihre Instanz starten">
```bash
bin/up -d
```

Das Toolkit startet MongoDB, initialisiert dessen Replica Set, lädt das ausgewählte TeX Live-Image herunter und startet Redis und die Anwendung. Es kann scheinbar pausieren, während ein großes Image heruntergeladen wird. Führen Sie kein zweites `bin/up` aus, solange das erste noch läuft.

Prüfen Sie in einem anderen Ubuntu-Terminal:

```bash
cd "$HOME/ayakaleaf-toolkit"
bin/docker-compose ps
bin/docker-compose logs --tail=100 mongo
bin/docker-compose logs --tail=100 -f sharelatex
```

Drücken Sie `Ctrl+C`, um das Verfolgen der Logs zu beenden; im Hintergrund laufende Container laufen weiter. Wenn der Start bei MongoDB fehlschlägt, folgen Sie [MongoDB startet nicht](/de/on-premises/installation/using-docker-compose/windows/troubleshooting#mongodb-fails-to-start), bevor Sie es erneut versuchen. Löschen Sie nicht das Datenverzeichnis, um eine bestehende Installation zurückzusetzen.

Prüfen Sie den Port und die Seite für den ersten Start:

```bash
bin/docker-compose port sharelatex 80
curl -I http://localhost:8080/launchpad
```

Der Port sollte `127.0.0.1:8080` sein. Warten Sie auf die Initialisierung der Anwendung, wenn die HTTP-Anfrage zunächst fehlschlägt.
</Step>

<Step title="Die Instanz von Windows aus öffnen">
Öffnen Sie in Ihrem **Windows-Browser** [http://localhost:8080/launchpad](http://localhost:8080/launchpad). Verwenden Sie diese Adresse auch in Windows, statt einer temporären WSL-IP-Adresse.

Um den HTTP-Zugriff von Windows unabhängig vom Browser zu prüfen, führen Sie in **PowerShell** Folgendes aus:

```powershell
curl.exe -I http://localhost:8080/launchpad
```

Wenn Ubuntu die Seite erreicht, Windows aber nicht, siehe [Windows kann localhost nicht öffnen](/de/on-premises/installation/using-docker-compose/windows/troubleshooting#windows-cannot-open-localhost).
</Step>
</Steps>
