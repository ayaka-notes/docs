Ayakaleaf Pro läuft auf Docker. Auf einem Mac verwenden Sie Docker Desktop, das die Docker-Engine in einer virtuellen Linux-Maschine ausführt.

<Steps>
<Step title="Docker Desktop installieren und starten">
Installieren Sie die [Docker Desktop](https://docs.docker.com/desktop/setup/install/mac-install/)-Version für Ihren Mac (Apple Silicon oder Intel), öffnen Sie sie und warten Sie, bis die Engine gestartet ist. Sie können sie auch über das Terminal starten:

```bash
open -a Docker
```
</Step>

<Step title="Die Docker-Engine prüfen">
Führen Sie diese Befehle im Terminal aus:

```bash
docker context show
docker info
docker compose version
```

Der Kontext sollte auf Ihre lokale Docker-Desktop-Engine zeigen, normalerweise `desktop-linux`. Wenn ein anderer Kontext ausgewählt ist, wechseln Sie zu Docker Desktop, bevor Sie fortfahren:

```bash
docker context use desktop-linux
```

`docker info` muss einen Abschnitt **Server** ausgeben. `docker --version` allein zeigt nur, dass der Client installiert ist.
</Step>

<Step title="Ressourcen und Dateifreigabe prüfen">
Prüfen Sie in den **Settings** von Docker Desktop die Limits für CPU, Arbeitsspeicher und Festplatte anhand von [Bevor Sie beginnen](/de/on-premises/installation/using-docker-compose/macos#before-you-start) sowie die Einstellungen zur Dateifreigabe, siehe [Docker Desktop settings](https://docs.docker.com/desktop/settings-and-maintenance/settings/).

Diese Anleitung legt das Toolkit unter `/Users` ab, das Docker Desktop standardmäßig freigibt. Wenn Sie einen anderen Ort verwenden und `bin/up` mit `Mounts denied` fehlschlägt, fügen Sie dieses Verzeichnis zur Dateifreigabe hinzu.
</Step>

<Step title="Den Docker-Socket für Sandboxed Compiles prüfen">
Das Toolkit bindet `/var/run/docker.sock` in die Anwendung ein, damit sie für jede Kompilierung einen separaten TeX Live-Container starten kann. Behalten Sie `DOCKER_SOCKET_PATH=/var/run/docker.sock` in `config/overleaf.rc` bei.

Die Docker-CLI unter macOS verbindet sich möglicherweise über `~/.docker/run/docker.sock`. Das ist der Client-Endpunkt auf dem Mac und kein Grund, die Mount-Quelle des Toolkit zu ändern: Der Compiler benötigt den Engine-Socket so, wie Linux-Container ihn sehen.

Wenn `/var/run/docker.sock` auf dem Mac fehlt, aktivieren Sie **Allow the default Docker socket to be used** unter **Settings → Advanced**, siehe [Dockers Berechtigungsanforderungen](https://docs.docker.com/desktop/setup/install/mac-permission-requirements/).

<Danger>

Führen Sie kein `chmod 777` auf dem Socket aus, um Fehler zu umgehen. Zugriff auf den Docker-Socket entspricht Root-Zugriff auf die Docker-VM.

</Danger>
</Step>
</Steps>
