### Den Administrator und ein erstes Projekt erstellen {#create-the-administrator-and-a-first-project}

Öffnen Sie [http://localhost:8080/launchpad](http://localhost:8080/launchpad), erstellen Sie das erste Administratorkonto und melden Sie sich an. Folgen Sie dann [6. Aufgaben nach der Installation](/de/on-premises/installation/using-docker-compose/linux/6.-post-installation-tasks) der Linux-Anleitung und verwenden Sie in deren Beispiel-URLs den Port `8080`.

### Die Kompilierung prüfen {#verify-compilation}

Eine Anmeldeseite, die sich öffnet, beweist nicht, dass die separaten Compiler-Container und ihre Daten-Mounts funktionieren. Erstellen Sie ein leeres Projekt und kompilieren Sie diese `main.tex`:

```latex
\documentclass{article}
\begin{document}
Ayakaleaf Pro on macOS.
\end{document}
```

Die PDF-Vorschau sollte den Text anzeigen. Wählen Sie bei Bedarf in den Projekteinstellungen TeX Live 2026 aus.

Wählen Sie für ein Projekt mit chinesischem Text **XeLaTeX** als Compiler und testen Sie:

```latex
\documentclass{ctexart}
\begin{document}
你好，Ayakaleaf Pro。
\end{document}
```

### Die Persistenz prüfen {#verify-persistence}

```bash
bin/stop
bin/start
```

Öffnen Sie das Projekt erneut und kompilieren Sie es noch einmal. Ihr Konto, der Quelltext und die Projektdateien sollten noch vorhanden sein. Mit den Standardpfaden liegen die Live-Daten im Verzeichnis `data/` des Toolkit auf Ihrem Mac.

### Die Instanz verfügbar halten {#keep-the-instance-available}

Während der Mac im Ruhezustand ist, hält macOS die virtuelle Maschine von Docker Desktop mit allen darin enthaltenen Containern an: Niemand kann die Instanz öffnen, und eine laufende Kompilierung stoppt, bis der Mac aufwacht. Nur der Ruhezustand des Systems ist relevant. Der Bildschirm darf sich ausschalten.

Wenn andere Personen die Instanz nutzen oder Sie lange Aufgaben laufen lassen, halten Sie den Mac am Strom und verhindern Sie den automatischen Ruhezustand, siehe [Einstellungen für Ruhezustand und Aktivierung auf dem Mac festlegen](https://support.apple.com/guide/mac-help/set-sleep-and-wake-settings-mchle41a6ccd/mac):

| Mac | Einstellung |
| --- | --- |
| Desktop-Mac (Mac mini, iMac, Mac Studio, Mac Pro) | **System Settings → Energy**: Aktivieren Sie **Prevent automatic sleeping when the display is off** |
| MacBook | **System Settings → Battery → Options**: Aktivieren Sie **Prevent automatic sleeping on power adapter when the display is off**. Dies gilt nur, solange das Netzteil angeschlossen ist, und das Zuklappen des Deckels versetzt das MacBook trotzdem in den Ruhezustand |

Um den Mac nur für eine gewisse Zeit wach zu halten, führen Sie stattdessen `caffeinate -i` in einem Terminalfenster aus. Es verhindert den Ruhezustand bei Inaktivität, bis Sie `Ctrl+C` drücken oder das Fenster schließen.

Docker Desktop ist eine App in Ihrer Benutzersitzung. Damit die Instanz nach einem Neustart wieder verfügbar ist, aktivieren Sie **Start Docker Desktop when you sign in to your computer** unter **Settings → General** in Docker Desktop. Die Container des Toolkit verwenden `restart: always`, sodass Docker sie wieder startet, sobald Docker Desktop läuft, ohne `bin/up`. Bis sich nach einem Neustart jemand am Mac anmeldet, bleibt die Instanz offline.

<Info>

Ein Mac, der wach bleibt, verbraucht mehr Strom. Für einen Dienst, der immer erreichbar sein muss, empfehlen wir einen Linux-Server, siehe [Linux](/de/on-premises/installation/using-docker-compose/linux).

</Info>

### Tägliche Nutzung {#daily-use}

Öffnen Sie Docker Desktop, bevor Sie die Instanz verwalten. In einem neuen Terminal:

```bash
export PATH="$(brew --prefix gnu-sed)/libexec/gnubin:$PATH"
cd "$HOME/ayakaleaf-toolkit"
```

| Aufgabe | Befehl |
| --- | --- |
| Die vorhandenen Container starten | `bin/start` |
| Die Container stoppen und die Daten behalten | `bin/stop` |
| Konfigurationsänderungen übernehmen | `bin/up -d` |
| Den Status prüfen | `bin/docker-compose ps` |
| Die Start-Logs lesen | `bin/docker-compose logs --tail=100 sharelatex` |
| Die Compiler-Logs lesen | `bin/logs -f clsi` |

`bin/start` übernimmt keine Änderungen in `config/`: Führen Sie nach dem Bearbeiten der Konfiguration `bin/up -d` aus. Bewahren Sie `config/` und `data/` auf und folgen Sie [Daten und Backups](/de/on-premises/maintenance/data-and-backups), bevor Sie ein Upgrade durchführen oder die Installation verschieben. Das Kopieren der Datenbankdateien, während MongoDB in sie schreibt, ist kein konsistentes Backup.

Belassen Sie die Instanz für die lokale Nutzung auf `127.0.0.1`. Um andere Computer zu bedienen, legen Sie Listen-Adresse, Site-URL und HTTPS bewusst fest, siehe [5. Ihre Instanz personalisieren](/de/on-premises/installation/using-docker-compose/linux/5.-personalizing-your-instance) der Linux-Anleitung.

Wenn etwas nicht funktioniert, siehe [Fehlerbehebung](/de/on-premises/installation/using-docker-compose/macos/troubleshooting).
