In diesem Abschnitt betreiben wir Ayakaleaf Pro lokal auf Ihrem Mac mit Docker Desktop und dem [Ayakaleaf Toolkit](https://github.com/ayaka-notes/toolkit). Die Anleitung verwendet `http://localhost:8080`, speichert die Daten in Ihrem Home-Verzeichnis und kompiliert mit TeX Live 2026 in Sandbox-Containern.

Docker Desktop führt die Anwendung, MongoDB, Redis und den TeX Live-Compiler in einer virtuellen Linux-Maschine aus. Sie installieren weder MongoDB noch Redis noch MacTeX unter macOS selbst.

Verwenden Sie dieses Setup für den persönlichen Gebrauch und lokale Tests. Für einen ständig verfügbaren, gemeinsam genutzten Dienst empfehlen wir die [Linux-Anleitung](/de/on-premises/installation/using-docker-compose/linux) mit HTTPS, Backups und Zugriffskontrolle. Die Instanz ist nicht verfügbar, solange der Mac im Ruhezustand ist oder Docker Desktop gestoppt ist, siehe [Die Instanz verfügbar halten](/de/on-premises/installation/using-docker-compose/macos/6.-post-installation-tasks#keep-the-instance-available).

## Bevor Sie beginnen {#before-you-start}

Sie benötigen:

* Eine macOS-Version, die von [Docker Desktop for Mac](https://docs.docker.com/desktop/setup/install/mac-install/) unterstützt wird.
* Git, [Homebrew](https://brew.sh/) und GNU sed. Das Toolkit verwendet GNU-sed-Optionen, die das in macOS integrierte BSD sed nicht akzeptiert.
* Genügend Ressourcen für macOS und Docker. Für eine kleine lokale Instanz beginnen Sie mit 4 CPUs und 8 GB Arbeitsspeicher für Docker Desktop. Das ist ein empfohlener Ausgangspunkt, kein gemessenes Minimum.
* Mindestens 40 GB freien Speicherplatz für ein vollständiges TeX Live-Image sowie Platz für Ihre Projekte. Prüfen Sie sowohl den freien Speicherplatz auf dem Mac als auch das Festplattenlimit von Docker Desktop. Beginnen Sie mit einer TeX Live-Version: Jede weitere Version benötigt ungefähr noch einmal so viel Platz.

Die Anwendungs- und TeX Live-Images werden für `arm64` und `amd64` veröffentlicht. Lassen Sie Docker auf Apple Silicon das native ARM-Image wählen und erzwingen Sie nicht `platform: linux/amd64`.
