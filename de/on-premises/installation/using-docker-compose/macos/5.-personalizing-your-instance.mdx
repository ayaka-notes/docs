---
title: 5. Ihre Instanz personalisieren
description: Legen Sie Port, Site-URL und TeX Live-Image für eine lokale Instanz auf Ihrem Mac fest, prüfen Sie den Kernel der Docker-VM und starten Sie Ayakaleaf Pro.
icon: square-sliders
---

<Steps>
<Step title="Container-Einstellungen">
Bearbeiten Sie diese vorhandenen Einträge in `config/overleaf.rc`:

```bash title="config/overleaf.rc"
PROJECT_NAME=ayakaleaf-macos
SERVER_PRO=true
OVERLEAF_LISTEN_IP=127.0.0.1
OVERLEAF_PORT=8080
SIBLING_CONTAINERS_ENABLED=true
DOCKER_SOCKET_PATH=/var/run/docker.sock
```

Behalten Sie die Standard-Datenpfade und die mitgelieferten MongoDB- und Redis-Dienste bei. Mit `OVERLEAF_LISTEN_IP=127.0.0.1` können nur Browser auf diesem Mac die Instanz öffnen.
</Step>

<Step title="Anwendungseinstellungen">
Setzen Sie in `config/variables.env` diese Werte und ersetzen Sie dabei alle aktiven Einträge mit denselben Namen:

```dotenv title="config/variables.env"
OVERLEAF_SITE_URL=http://localhost:8080
TEX_LIVE_DOCKER_IMAGE=ghcr.io/ayaka-notes/texlive-full:2026.1
ALL_TEX_LIVE_DOCKER_IMAGES=ghcr.io/ayaka-notes/texlive-full:2026.1
ALL_TEX_LIVE_DOCKER_IMAGE_NAMES="TeX Live 2026"
```

Erzeugen Sie ein Session-Secret:

```bash
openssl rand -hex 32
```

Fügen Sie das Ergebnis als `OVERLEAF_SESSION_SECRET` in `config/variables.env` ein. Ohne dieses Secret meldet jedes `bin/up`, das den Container neu erstellt, alle Benutzer ab, siehe [Umgebungsvariablen](/de/on-premises/configuration/overleaf-toolkit/environment-variables).

Lassen Sie für eine lokale Instanz ohne E-Mail die SMTP-Einstellungen und `OVERLEAF_EMAIL_FROM_ADDRESS` ungesetzt. Git Bridge, externe Authentifizierung und die anderen Integrationen können Sie später über ihre eigenen [Konfigurationsseiten](/de/on-premises/configuration/overleaf-toolkit) hinzufügen.
</Step>

<Step id="check-the-docker-vms-linux-kernel" title="Den Linux-Kernel der Docker-VM prüfen">
MongoDB läuft auf dem Linux-Kernel der virtuellen Maschine von Docker Desktop, nicht auf macOS. Prüfen Sie dessen Version vor dem ersten Start:

```bash
docker info --format '{{.KernelVersion}}'
```

MongoDB dokumentiert eine Inkompatibilität mit den Linux-Kerneln **6.19 bis 7.0.13**, die auch MongoDB in Docker betrifft. Die Lösung ist ein Kernel **7.0.14 oder neuer**, der mit einem Docker-Desktop-Update ausgeliefert wird, siehe [MongoDBs Production Notes](https://www.mongodb.com/docs/manual/administration/production-notes/).

Wenn Ihre Docker-VM einen betroffenen Kernel verwendet, fügen Sie Folgendes zu `config/docker-compose.override.yml` hinzu und führen Sie es mit eventuell bereits vorhandenen `services` zusammen:

```yaml title="config/docker-compose.override.yml"
services:
  mongo:
    environment:
      GLIBC_TUNABLES: glibc.pthread.rseq=1
```

<Warning>

Aktualisieren Sie auf einen korrigierten Kernel, sobald er verfügbar ist. Liegt Ihr Kernel außerhalb des betroffenen Bereichs, ist dieser Workaround unnötig.

</Warning>
</Step>

<Step title="Ihre Instanz starten">
Führen Sie im Toolkit-Verzeichnis Folgendes aus:

```bash
bin/up -d
```

Das Toolkit initialisiert das Replica Set von MongoDB, lädt das TeX Live-Image herunter und startet die Anwendung. Der erste Download dauert eine Weile. So verfolgen Sie den Fortschritt:

```bash
bin/docker-compose ps
bin/docker-compose logs --tail=100 -f sharelatex
```

Drücken Sie `Ctrl+C`, um das Verfolgen der Logs zu beenden. Die Container laufen weiter.

Prüfen Sie den veröffentlichten Port und die Seite für den ersten Start:

```bash
bin/docker-compose port sharelatex 80
curl -I http://localhost:8080/launchpad
```

Der Port sollte `127.0.0.1:8080` sein.
</Step>
</Steps>

<Info>

Um die Instanz später von anderen Computern aus zu öffnen, ändern Sie die Listen-Adresse und die Site-URL und richten Sie HTTPS ein, wie unter [5. Ihre Instanz personalisieren](/de/on-premises/installation/using-docker-compose/linux/5.-personalizing-your-instance) in der Linux-Anleitung beschrieben. Der Mac muss dann wach bleiben, siehe [Die Instanz verfügbar halten](/de/on-premises/installation/using-docker-compose/macos/6.-post-installation-tasks#keep-the-instance-available).

</Info>
