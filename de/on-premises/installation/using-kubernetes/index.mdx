Das [Toolkit](/de/on-premises/installation/using-docker-compose) ist die empfohlene Methode, um Ayakaleaf Pro auf einem einzelnen Server zu betreiben. Wenn Sie bereits einen Kubernetes-Cluster betreiben, stellt dieser Abschnitt denselben Container mit einfachen `kubectl`-Manifesten darauf bereit: kein zusätzliches Image, kein Helm-Chart.

Am Ende dieses Abschnitts haben Sie eine Ayakaleaf Pro-Instanz mit Sandboxed Compiles, einem MongoDB-Replikatset und Redis, alles im Namespace `overleaf`. Um mehrere Instanzen hinter einem Load Balancer zu betreiben, fahren Sie anschließend mit [Horizontale Skalierung](/de/on-premises/configuration/kubernetes/horizontal-scaling) fort.

<Info>

Die Kubernetes-Unterstützung ist experimentell. Wir veröffentlichen weder ein Helm-Chart noch Kubernetes-spezifische Images. Die Manifeste auf diesen Seiten sind diejenigen, die wir auf Kubernetes 1.37 (kubeadm, containerd 2.4, flannel) mit drei Knoten mit jeweils 2 vCPUs und 4 GB Arbeitsspeicher getestet haben. Passen Sie Speicher, Netzwerk und Ingress an Ihren Cluster an.

</Info>

### Wie die Teile zusammenpassen {#how-the-pieces-fit}

| Toolkit (ein Server)                         | Kubernetes                                                               |
| -------------------------------------------- | ------------------------------------------------------------------------ |
| `config/variables.env`                       | ConfigMap `overleaf-env` und Secret `overleaf-secrets`                   |
| Container `sharelatex`                       | Deployment `overleaf` (ein Pod, der alle Overleaf-Dienste ausführt)      |
| Container `mongo` und `redis`                | StatefulSets `mongo` (Replikatset) und `redis` oder Ihre verwalteten Dienste |
| `~/overleaf-toolkit/data/overleaf`           | PersistentVolumeClaim `overleaf-data`                                    |
| Docker auf dem Host, für Kompilierungen verwendet | Docker Engine auf jedem Knoten, der Ayakaleaf Pro ausführt          |
| `bin/up`, `bin/logs`, `bin/shell`            | `kubectl apply`, `kubectl logs`, `kubectl exec`                          |

### Was Sie benötigen {#what-you-need}

* Einen Kubernetes-Cluster, auf dem Sie Pakete installieren können: Jeder Knoten, der Ayakaleaf Pro ausführen kann, benötigt **Docker Engine**, weil Kompilierungen in TeX Live-Containern laufen, die Ayakaleaf Pro über `/var/run/docker.sock` des Knotens startet. Siehe [0. Knoten vorbereiten](/de/on-premises/installation/using-kubernetes/0.-prepare-the-nodes).
* Eine Standard-StorageClass mit `ReadWriteOnce`-Volumes.
* `kubectl` und `openssl` auf Ihrer Workstation.
