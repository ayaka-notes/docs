### Ihr erstes Administratorkonto erstellen {#creating-your-first-administrator-account}

Öffnen Sie `OVERLEAF_SITE_URL` gefolgt von `/launchpad`, zum Beispiel `http://192.0.2.10:30080/launchpad`, und registrieren Sie das Administratorkonto wie unter [Aufgaben nach der Installation im Toolkit](/de/on-premises/installation/using-docker-compose/linux/6.-post-installation-tasks) beschrieben. Erstellen Sie dann ein Beispielprojekt und kompilieren Sie es.

Sie können Benutzer auch über die Kommandozeile anlegen:

```bash
kubectl -n overleaf exec deploy/overleaf -- bash -c \
  'cd /overleaf/services/web && node modules/server-ce-scripts/scripts/create-user.mjs --admin --email=admin@example.com'
```

Der Befehl gibt einen Link aus, über den das Passwort festgelegt wird.

### Prüfen, ob Kompilierungen in der Sandbox laufen {#checking-that-compiles-are-sandboxed}

Kompilieren Sie ein Projekt und sehen Sie sich dann den Knoten an, auf dem der Pod läuft:

```bash
kubectl -n overleaf get pod -l app=overleaf -o wide   # NODE column
# on that node:
sudo docker ps -a --filter ancestor=ghcr.io/ayaka-notes/texlive-full:2026.1
ls -ln /srv/overleaf/compiles                          # owned by uid 33 (www-data)
```

Jede Kompilierung erscheint als kurzlebiger Container mit dem Namen `project-<project id>-<user id>-...`.

### Logs und eine Shell {#logs-and-a-shell}

| Toolkit          | Kubernetes                                                               |
| ---------------- | ------------------------------------------------------------------------ |
| `bin/logs web`   | `kubectl -n overleaf exec deploy/overleaf -- tail -f /var/log/overleaf/web.log` |
| `bin/shell`      | `kubectl -n overleaf exec -it deploy/overleaf -- bash`                    |
| `bin/up`         | `kubectl apply -f .`, dann `kubectl -n overleaf rollout restart deployment/overleaf` |

Der Container schreibt pro Dienst eine Logdatei in `/var/log/overleaf/` (`web.log`, `clsi.log`, `real-time.log`, `document-updater.log`, ...); `kubectl logs` zeigt die Startausgabe.

### Was einen Neustart übersteht {#what-survives-a-restart}

`kubectl rollout restart` ersetzt die Pods. Nur was auf einem Volume liegt, bleibt erhalten. Änderungen, die über `kubectl exec` in einem Pod vorgenommen wurden, etwa installierte Pakete oder bearbeitete Dateien, gehen mit ihm verloren, ebenso die Logs, sofern `/var/log/overleaf` nicht auf einem Volume liegt, siehe [Logging](/de/on-premises/configuration/kubernetes/logging). Nehmen Sie dauerhafte Änderungen in Ihren Manifesten vor.
