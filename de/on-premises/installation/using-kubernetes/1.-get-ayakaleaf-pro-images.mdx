Kubernetes verwendet dieselben Images wie das Toolkit. Es gibt kein separates Kubernetes-Image.

| Image                                                | Verwendet von                                                           |
| ---------------------------------------------------- | ----------------------------------------------------------------------- |
| `ghcr.io/ayaka-notes/overleaf-pro:6.3.2`             | dem Deployment `overleaf`                                               |
| `ghcr.io/ayaka-notes/overleaf-pro/git-bridge:6.3.2`  | [Git-Integration](/de/on-premises/configuration/kubernetes/integrations/git-integration) (optional), gleicher Tag wie oben |
| `ghcr.io/ayaka-notes/texlive-*`                      | Kompilierungen, auf den Knoten in [Schritt 0](/de/on-premises/installation/using-kubernetes/0.-prepare-the-nodes) in Docker gepullt |

Die Images sind auf [ghcr.io](https://github.com/ayaka-notes/ayakaleaf-pro/pkgs/container/overleaf-pro/) für amd64 und arm64 öffentlich verfügbar, sodass das kubelet sie ohne Zugangsdaten pullen kann.

<Warning>

Verwenden Sie immer einen Versionstag wie `6.3.2`, nicht `latest`. Upgrades führen Datenbankmigrationen aus und müssen [Upgrade auf Kubernetes](/de/on-premises/maintenance/upgrading-on-kubernetes) folgen; ein beweglicher Tag würde einen Pod jedes Mal aktualisieren, wenn er neu eingeplant wird.

</Warning>

### Q\&A

<Accordion title="Unsere Knoten können ghcr.io nicht erreichen. Was tun wir?">

<strong>Antwort:</strong> Kopieren Sie die Images in eine Registry, die die Knoten erreichen können, und verwenden Sie diesen Namen in den Manifesten, zum Beispiel:

```bash
docker pull ghcr.io/ayaka-notes/overleaf-pro:6.3.2
docker tag ghcr.io/ayaka-notes/overleaf-pro:6.3.2 registry.example.com/ayakaleaf/overleaf-pro:6.3.2
docker push registry.example.com/ayakaleaf/overleaf-pro:6.3.2
```

Für eine Registry ohne TLS benötigt containerd auf jedem Knoten eine `/etc/containerd/certs.d/<registry>/hosts.toml` mit `server = "http://<registry>"` sowie `config_path`, gesetzt wie in [Schritt 0](/de/on-premises/installation/using-kubernetes/0.-prepare-the-nodes). Docker selbst pusht nur an `localhost` über einfaches HTTP; pushen Sie daher über `localhost:<port>` auf dem Registry-Host oder fügen Sie sie zu `insecure-registries` hinzu.

</Accordion>
