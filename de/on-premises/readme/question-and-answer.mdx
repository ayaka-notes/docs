Hier haben wir Antworten auf einige häufig gestellte Fragen zu Ayakaleaf Pro zusammengestellt.

### Grundlegende Fragen

<Accordion title="F01: Ist Ayakaleaf Pro eine kostenlose Testversion? Wird eine Lizenz benötigt?">

Nein. Ayakaleaf Pro ist vollständig kostenlos nutzbar. Es handelt sich nicht um eine Testversion, und es wird keine Lizenz benötigt.

</Accordion>

<Accordion title="F02: Enthält Ayakaleaf Pro alle Funktionen von Overleaf Server Pro?">

Ja. Ayakaleaf Pro enthält alle Funktionen von Overleaf Server Pro, einschließlich der Git-Bridge-Integration. Außerdem enthält es ausgewählte Funktionen der Overleaf-SaaS-Plattform. Wir entwickeln Ayakaleaf Pro kontinuierlich weiter und verbessern es.

</Accordion>

<Accordion title="F03: Was kostet Overleaf Server Pro?">

Overleaf Server Pro kostet etwa \$300 pro Benutzer und Jahr. Es sind mindestens 10 Lizenzen erforderlich, sodass Bereitstellungen bei rund \$3.000 jährlich beginnen. Kleinere öffentliche Verträge in den USA weisen jährliche Kosten von etwa \$320–\$370 pro Benutzer aus. Das macht Server Pro teuer, insbesondere für kleinere Teams. Dokumentierte Käufe und Preise finden Sie unter [#information-and-price-about-overleaf-server-pro](/de/on-premises#information-and-price-about-overleaf-server-pro  "mention").

</Accordion>

<Accordion title="F04: Warum enthält Overleaf Server Pro keine GitHub-Synchronisierung oder KI-Funktionen?">

Overleaf Server Pro wird häufig von Regierungsorganisationen eingesetzt. Diese betreiben es in privaten Netzwerken und kontrollieren den Zugriff streng. Zum Schutz sensibler Daten vermeiden die enthaltenen Funktionen den Datenaustausch mit Drittanbieterdiensten. Wenn Sie GitHub-Synchronisierung, KI oder ähnliche vernetzte Funktionen benötigen, empfiehlt Overleaf ein Abonnement seiner SaaS-Plattform.

</Accordion>

<Accordion title="F05: Ist Ayakaleaf Pro sicher und zuverlässig?">

Ayakaleaf Pro ist Open Source. Wir prüfen den Code mit Werkzeugen wie Codex Security, um seine Sicherheit und Zuverlässigkeit zu stärken. Wenn Sie keine Datensynchronisierung mit Drittanbietern aktivieren, bleiben Ihre Daten auf Ihrem Server. Ayakaleaf Pro enthält keine Telemetrie, die Ihre Daten an andere Stellen sendet.

</Accordion>

<Accordion title="F06: Wird Ayakaleaf Pro langfristig gepflegt?">

Wir werden alles daransetzen, dieses Projekt langfristig zu pflegen.

</Accordion>

<Accordion title="F07: Ist Ayakaleaf Pro lizenzkonform?">

Ayakaleaf Pro ist ein Community-Fork. Sein Code und die integrierten Funktionen stammen aus Beiträgen der Community. Es steht unter der AGPL v3. Bereitstellungen können diese Lizenz einhalten, wenn sie deren Anforderungen erfüllen.

</Accordion>

<Accordion title="F08: Warum heißt das Projekt Ayakaleaf Pro?">

Das Projekt hieß ursprünglich 2024 Overleaf Pro. Die Entwicklung ruhte eine Zeit lang und wurde Ende 2025 wieder aufgenommen. Im ersten Quartal 2026 benannte Overleaf sein KI-gestütztes Abonnement in Pro um. Aus der Community kam zudem der Hinweis, dass der Name Overleaf Pro Risiken in Bezug auf Markenrecht und Verwechslung bergen könnte. Nutzer könnten annehmen, das Projekt sei offiziell.

Wir haben das Projekt in Ayakaleaf Pro umbenannt, um diese Verwechslung zu vermeiden. Der Name kann als „Ayaka-notes Overleaf Pro“ gelesen werden. Der Maintainer (Sie können mich ayaka nennen!) trägt seit seiner Studienzeit, vor über fünf Jahren, zur Entwicklung der Overleaf-Community bei. Diese Erfahrung untermauert unser Engagement für eine langfristige Pflege.

</Accordion>

<Accordion title="F09: Was unterscheidet Ayakaleaf Pro von neueren, mit KI entwickelten LaTeX-Editoren?">

Seit 2026 hat die Open-Source-Community viele mit KI entwickelte LaTeX-Editoren veröffentlicht, darunter OpenAI Prism. Ayakaleaf Pro hält Ihre Daten und Dienste auf Ihrem eigenen Server. So behalten Sie die direkte Kontrolle über Ihre Bereitstellung und Ihre Daten.

Viele experimentelle Community-Editoren haben keinen etablierten Plan für eine langfristige Pflege. Auch LaTeX-Kompilierungsplattformen von Drittanbietern können ihren Betrieb einstellen, wenn ihre Nutzerbasis oder ihre Einnahmen nicht ausreichen. Ayakaleaf Pro stellt den gesamten Quellcode bereit und ermöglicht Ihnen, jeden Dienst selbst zu hosten. Selbst wenn die Pflege eingestellt würde, könnte Ihr bestehender selbst gehosteter Dienst weiterlaufen.

</Accordion>

### Funktionen

<Accordion title="F01: Welche Funktionen bietet Ayakaleaf Pro? Kann ich eine neue Funktion anfragen?">

Die aktuelle Funktionsliste finden Sie in unserer Dokumentation. Wenn Sie sich eine bestimmte Funktion wünschen, können Sie gerne ein Issue (als Feature-Request) auf GitHub eröffnen. Wir bemühen uns, angefragte Funktionen umzusetzen, aber die Entwicklung braucht Zeit, und wir können nicht garantieren, dass jede Funktion sofort bereitgestellt wird.

</Accordion>

<Accordion title="F02: Ich habe einige Funktionen entwickelt. Kann ich einen PR einreichen, und wird er garantiert angenommen?">

Beiträge sind willkommen, eine Annahme ist jedoch nicht garantiert. Wir bewerten jeden PR anhand seiner Auswirkungen auf die zugrunde liegende Overleaf-Codebasis, seines Wartungsaufwands und des Nutzens, den er den Benutzern bringt. Wir bemühen uns, wertvolle Beiträge zu übernehmen und zu pflegen.

Wir können jedoch PRs ablehnen, die übermäßig viele Änderungen einführen, aus ungeprüftem oder schlecht verstandenem KI-generiertem Code („Vibe Coding“) bestehen oder Funktionen hinzufügen, die langfristig schwer zu pflegen wären.

</Accordion>

<Accordion title="F03: Wie konfiguriere ich eine bestimmte Funktion?">

Wir aktualisieren die Dokumentation in der Regel, sobald wir eine neue Funktion veröffentlichen. Detaillierte Einrichtungsanweisungen und Erläuterungen zu den verfügbaren Umgebungsvariablen finden Sie in der jeweiligen Dokumentation.

</Accordion>

<Accordion title="F04: Welche Python-Bibliotheken kann der Python Runner verwenden?">

Der Python Runner führt Python im Browser des Benutzers mit [Pyodide](https://pyodide.org/) 0.29.3 aus, nicht auf dem Server. Er lädt die Pakete, die Ihr Code importiert, aus den [in Pyodide integrierten Paketen](https://pyodide.org/en/0.29.3/usage/packages-in-pyodide.html), etwa NumPy, pandas und Matplotlib. Mit `pip` installierte Pakete und andere Pakete sind nicht verfügbar. Auf dem Server muss nichts konfiguriert werden.

</Accordion>

<Accordion title="F05: Kann die Rechtschreibprüfung Japanisch oder Chinesisch prüfen?">

Nein. Die Rechtschreibprüfung hat kein Wörterbuch für Japanisch oder Chinesisch, daher sind diese Sprachen nicht in der Sprachliste der Rechtschreibprüfung enthalten. Benutzer können die Rechtschreibprüfung für ein Projekt in den Editor-Einstellungen deaktivieren.

</Accordion>

### Bereitstellung

<Accordion title="F01: Unterstützt Ayakaleaf Pro eine verteilte Bereitstellung in k8s?">

Für die meisten Benutzer empfehlen wir die Bereitstellung mit dem [Toolkit](/de/on-premises/installation/using-the-toolkit). Wir raten von groß angelegten Cluster-Bereitstellungen mit Kubernetes oder ähnlichen Plattformen ab, da diese die betriebliche Komplexität und den Wartungsaufwand erheblich erhöhen können.

</Accordion>

<Accordion title="F02: Wie kann ich die Verfügbarkeit sicherstellen, wenn ich Tausende von Benutzern bediene?">

Bitte lesen Sie unseren Leitfaden zur [horizontalen Skalierung](/de/on-premises/maintenance/horizontal-scaling). Sie können mehrere Overleaf-Instanzen bereitstellen und einen Load Balancer konfigurieren, der den Datenverkehr auf sie verteilt.

</Accordion>

<Accordion title="F03: Können Sie mir bei der Bereitstellung oder Migration helfen?">

Wenn Sie bereits eine Overleaf-Server-Pro-Instanz betreiben, helfen wir Ihnen gerne bei der Migration zu Ayakaleaf Pro. Bitte kontaktieren Sie uns per E-Mail oder über Issues.

</Accordion>

<Accordion title="F04: Kann ich Ayakaleaf Pro unter einem URL-Unterpfad wie `https://example.com/overleaf` hosten?">

Nein. Ayakaleaf Pro muss vom Stammverzeichnis einer Domain aus bereitgestellt werden. Verwenden Sie eine eigene Domain oder Subdomain, etwa `https://overleaf.example.com`.

</Accordion>

<Accordion title="F05: Kann ich Ayakaleaf Pro unter Windows oder macOS oder ohne das Toolkit betreiben?">

Wir unterstützen Linux-Server mit dem [Toolkit](/de/on-premises/installation/using-the-toolkit). Docker Desktop unter Windows, WSL2 oder macOS funktioniert möglicherweise, wird von uns aber nicht getestet; ein bekanntes MongoDB-Problem finden Sie unter [Fehlerbehebung](/de/on-premises/support/troubleshooting).

Wir stellen keine eigenständige `docker-compose.yml` bereit. Um die Compose-Konfiguration zu sehen, die das Toolkit verwendet, führen Sie `bin/docker-compose config` im Toolkit-Verzeichnis aus.

</Accordion>

<Accordion title="F06: Wie deinstalliere ich Ayakaleaf Pro?">

Es gibt kein Deinstallationsskript. Im Toolkit-Verzeichnis:

1. Stoppen und entfernen Sie die Container mit `bin/docker-compose down`.
2. Löschen Sie die Daten. Standardmäßig befinden sie sich im Verzeichnis `data/` des Toolkit. Wenn Sie `OVERLEAF_DATA_PATH`, `MONGO_DATA_PATH`, `REDIS_DATA_PATH` oder `GIT_BRIDGE_DATA_PATH` in `config/overleaf.rc` geändert haben, löschen Sie auch diese Verzeichnisse. Dies kann nicht rückgängig gemacht werden. Erstellen Sie daher zuerst ein [Backup](/de/on-premises/maintenance/data-and-backups), falls Sie die Daten noch benötigen könnten.
3. Löschen Sie das Toolkit-Verzeichnis.
4. Entfernen Sie die Docker-Images, die Sie mit `docker images` auflisten können: `ghcr.io/ayaka-notes/overleaf-pro`, das git-bridge-Image, `mongo`, `redis` und die TeX Live-Images.

</Accordion>

<Accordion title="F07: Wie stoppe, starte oder starte ich Ayakaleaf Pro neu?">

Führen Sie Folgendes im Toolkit-Verzeichnis aus:

* `bin/stop` stoppt alle Container, `bin/start` startet sie wieder. Die Container bleiben erhalten, sodass Benutzer angemeldet bleiben.
* `bin/up -d` erstellt die Container und startet sie im Hintergrund. Führen Sie den Befehl nach Änderungen an `config/variables.env`, `config/overleaf.rc` oder `config/version` aus: Er erstellt die Container neu, deren Konfiguration sich geändert hat, und erst dann werden die Änderungen wirksam. `bin/stop` und `bin/start` übernehmen sie nicht.
* `bin/docker-compose restart sharelatex` startet nur den Overleaf-Container neu, ohne Konfigurationsänderungen zu übernehmen.

Wenn Benutzer jedes Mal abgemeldet werden, wenn `bin/up` den Container neu erstellt, setzen Sie `OVERLEAF_SESSION_SECRET`, siehe die Fragen & Antworten unter [Umgebungsvariablen](/de/on-premises/configuration/overleaf-toolkit/environment-variables).

</Accordion>

<Accordion title="F08: Wo trage ich die OAuth-Callback-URL ein?">

In der Anwendung, die Sie beim Anbieter erstellen, nicht in Ayakaleaf Pro. Für keine dieser Integrationen gibt es eine Callback-Einstellung in `config/variables.env`: Ayakaleaf Pro bildet jede Callback-URL aus `OVERLEAF_SITE_URL` und sendet sie an den Anbieter, der sie ablehnt, sofern sie nicht mit der für die Anwendung registrierten übereinstimmt. Sie registrieren sie also nur beim Anbieter und setzen `OVERLEAF_SITE_URL` auf die Adresse, die Benutzer öffnen.

| Integration | Feld beim Anbieter | Wert |
| --- | --- | --- |
| [GitHub](/de/on-premises/configuration/overleaf-toolkit/github-synchronisation) | Authorization callback URL | `${OVERLEAF_SITE_URL}/user/github-sync/oauth2/callback` |
| [GitLab](/de/on-premises/configuration/overleaf-toolkit/gitlab-synchronisation) | Redirect URI | `${OVERLEAF_SITE_URL}/user/gitlab-sync/oauth2/callback` |
| [Gitea](/de/on-premises/configuration/overleaf-toolkit/gitea-synchronisation) | Redirect URIs | `${OVERLEAF_SITE_URL}/user/gitea-sync/oauth2/callback` |
| [Dropbox](/de/on-premises/configuration/overleaf-toolkit/dropbox-synchronisation) | Redirect URIs (auf **Add** klicken) | `${OVERLEAF_SITE_URL}/user/dropbox/oauth/callback` |
| [Zotero](/de/on-premises/configuration/overleaf-toolkit/zotero-integration) | Callback URL | `${OVERLEAF_SITE_URL}/user/zotero/oauth/callback` |
| [Mendeley](/de/on-premises/configuration/overleaf-toolkit/mendeley-integration) | Redirect URL | `${OVERLEAF_SITE_URL}/user/mendeley/oauth/callback` |
| [OIDC-Anmeldung](/de/on-premises/configuration/overleaf-toolkit/authentication/oidc-authentication) | Redirect URI | `${OVERLEAF_SITE_URL}/oidc/login/callback` |
| [SAML-Anmeldung](/de/on-premises/configuration/overleaf-toolkit/authentication/saml-authentication) | ACS URL (Assertion Consumer Service) | `${OVERLEAF_SITE_URL}/saml/login/callback` |

Wenn Sie `OVERLEAF_SITE_URL` ändern, zum Beispiel auf eine neue Domain, aktualisieren Sie die URL auch bei jedem Anbieter, sonst schlägt die Verknüpfung fehl.

</Accordion>

### LaTeX

<Accordion title="F01: Sind die LaTeX-Projektkompilierungen der Benutzer isoliert? Ist Shell Escape aktiviert?">

Wenn Sie Sandbox Compiles aktivieren, läuft die Kompilierung jedes Benutzers in einem separaten Docker-Container und ist von den Kompilierungen anderer Benutzer isoliert. Shell Escape ist für Sandbox Compiles standardmäßig aktiviert.

</Accordion>

<Accordion title="F02: Ist das Sandbox-Compiles-Image zuverlässig? Kann die Kompilierung fehlschlagen?">

Wir haben unser TeX Live Full-Image für Sandbox Compiles in den letzten drei Jahren verbessert. In den meisten Fällen lassen sich Projekte, die auf overleaf.com kompilieren, auch mit Ayakaleaf Pro korrekt kompilieren. Wenn eine benötigte Schriftart nicht verfügbar ist, laden Sie diese Schriftart manuell in Ihr Projekt hoch.

</Accordion>

<Accordion title="F03: Mein Projekt lässt sich nicht kompilieren. Können Sie mir bei der Fehlersuche helfen?">

Bitte laden Sie Ihr Projekt auf die offizielle Overleaf-Website hoch, aktivieren Sie die Freigabe per Nur-Lese-Link und fügen Sie den Link in ein GitHub-Issue ein.

Wir untersuchen und beheben alle Fehler, die verhindern, dass ein Projekt in Ayakaleaf Pro kompiliert, wenn es auf der offiziellen Overleaf-Website erfolgreich kompiliert. Kompilierungsprobleme außerhalb dieses Rahmens sind nicht durch unseren Support abgedeckt.

</Accordion>
