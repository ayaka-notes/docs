### Das Audit-Log eines Projekts anzeigen

Administratoren können für jedes Projekt ein **Audit Log** einsehen. Dieses Audit-Log zeigt Ereignisse wie den Wechsel der Linkfreigabe zwischen privat und tokenbasiert, das Senden/Annehmen von Einladungen sowie den Beitritt eines Benutzers zum Projekt über ein Token. Administratoren können diese Logs projektbezogen über **Your Instance** -> **Admin** -> **Manage Users** einsehen und dann:

* Nach dem Benutzer suchen
* Auf den Tab **Projects** klicken
* Ein Projekt auswählen
* Auf das (i)-Symbol klicken
* Auf den Tab **Audit Log** klicken

Wird ein Projekt mit einem namentlich benannten Mitarbeitenden (über dessen E-Mail-Adresse) geteilt, wird dieser nach dem Beitritt im Freigabedialog mit seiner Berechtigung aufgeführt und ist für den Projekteigentümer sichtbar. Diese Informationen werden auch Administratoren angezeigt, wenn sie über das Admin-Panel den Tab „Project Info“ des Projekts aufrufen.

### Gelöschte Dokumente wiederherstellen

1. Melden Sie sich mit Ihren Administrator-Zugangsdaten an
2. Klicken Sie auf **Admin** und wählen Sie **Manage Users**
3. Geben Sie im Suchfeld die E-Mail-Adresse des Benutzers ein, für den Sie das Dokument wiederherstellen möchten
4. Klicken Sie in der Ergebnisliste auf dessen E-Mail-Adresse, um die Seite mit den Benutzerinformationen zu öffnen
5. Klicken Sie auf den Tab **Projects** und suchen Sie das Projekt über das Suchfeld
6. Klicken Sie auf das Informationssymbol neben dem Projektnamen, um **Project Info** zu öffnen
7. Klicken Sie auf den Tab **Deleted Docs**
8. Klicken Sie auf die Schaltfläche **Undelete** neben dem gelöschten Dokument, um es im Projekt des Benutzers wiederherzustellen.

Die wiederhergestellte Datei hat folgendes Format: `FILENAME-TIMESTAMP.EXTENSION`. Eine wiederhergestellte Version von `main.tex` wird beispielsweise im Stammverzeichnis des Projekts mit dem Dateinamen `main-2024-02-23-130441542.tex` wiederhergestellt.

### Eigentümerschaft eines Projekts übertragen

Das Admin-Panel in Server Pro hat für jedes Projekt eine eigene Seite. Sie gelangen dorthin, indem Sie entweder unter "/admin/user" nach dem Benutzer suchen, dann zu dessen Tab **Projects** wechseln, das Projekt in der Liste finden und auf das Informationssymbol klicken, oder indem Sie bei bekannter Projekt-ID direkt zur Seite [**https://your-instance-url/admin/project/**](https://your-instance-url/admin/project/) navigieren. Auf der Projektinformationsseite finden Sie die Schaltfläche **Transfer Ownership**, die einen Dialog öffnet, in dem Sie einen beliebigen Benutzer als neuen Eigentümer festlegen können. Der neue Eigentümer muss kein bestehender Mitarbeitender des Projekts sein.

<Info>

Beachten Sie, dass der bisherige Eigentümer im Rahmen der Eigentümerübertragung als Mitarbeitender mit Lese- und Schreibzugriff zum Projekt hinzugefügt wird.

</Info>

### Kompilierungs-Timeout für Projekte aktualisieren

Das standardmäßige Kompilierungs-Timeout für Projekte ist derzeit auf 180 Sekunden festgelegt. Dieser Wert kann geändert werden; dazu sind zwei Schritte erforderlich.

Bearbeiten Sie zunächst die Datei **config/variables.env**, fügen Sie die Umgebungsvariable `COMPILE_TIMEOUT` hinzu und setzen Sie ihren Wert auf das gewünschte Timeout in Sekunden. Zum Beispiel `COMPILE_TIMEOUT=300` für 5 Minuten.

<Danger>

Es lohnt sich nicht, das Timeout über 10 Minuten hinaus zu erhöhen. Andernfalls werden Sie höchstwahrscheinlich auf ein Timeout in einer anderen Komponente der Anwendung stoßen.

</Danger>

Nachdem diese Änderung vorgenommen wurde, müssen Sie den Container **sharelatex** mit dem Befehl `bin/up -d` neu erstellen.

Das Setzen dieser Umgebungsvariable aktualisiert den Timeout-Wert nur für neue Benutzer; er wird **nicht** rückwirkend auf bestehende Benutzer angewendet, da er beim erstmaligen Anlegen des Benutzers festgelegt wird.

Um das Timeout für bestehende Benutzer anzupassen, müssen Sie jeden Benutzerdatensatz in der Datenbank ändern. Wir raten zu großer Vorsicht dabei und empfehlen, vor allen Änderungen ein konsistentes Backup zu erstellen.

Informationen zum Erstellen von Backups finden Sie [hier](/de/on-premises/maintenance/data-and-backups).

Um den Wert des Kompilierungs-Timeouts für alle bestehenden Benutzer zu aktualisieren, führen Sie auf dem Docker-Host den folgenden Shell-Befehl aus:

```bash wrap
echo 'db.users.updateMany({}, {$set: {"features.compileTimeout": <value>}})' | docker exec -i mongo mongosh --quiet localhost/sharelatex
```

Ersetzen Sie `<value>` in der obigen Abfrage durch den gewünschten Timeout-Wert in Sekunden.

Nach Abschluss des Befehls sollten Sie eine Bestätigung mit der Anzahl der geänderten Datensätze sehen. Anschließend können Sie exit eingeben und die Eingabetaste drücken, um zur Host-Shell zurückzukehren.

### Projektzugriffe nachverfolgen

Mit dem folgenden Befehl können Sie sehen, wer ein Projekt wann geladen hat:

```bash wrap
docker exec sharelatex bash -c 'grep "join project request" /var/log/overleaf/web.log'
```

Dies liefert sowohl `timestamp` als auch `user_id` und `project_id`.
