---
title: Migration von Server Pro zu Group Professional
icon: rectangle-pro
noindex: true
---

Der Wechsel von einer selbst gehosteten Server Pro-Instanz zu einem neuen cloudbasierten Overleaf Group Professional-Abonnement ist eine große Umstellung. Damit dieser Prozess möglichst reibungslos verläuft, haben wir die folgenden Hinweise zusammengestellt.

Grundsätzlich schlagen wir einen dreimonatigen Überschneidungszeitraum ab Ihrem Verlängerungsdatum vor. Das bedeutet:

* Ihre bestehende Server Pro-Instanz und Ihr neues Group Professional-Abonnement sind beide vollständig aktiv.
* Ihr technisches Team kann Zeit einplanen, um das Group Professional-Abonnement einzurichten und über die Zukunft Ihres On-Premises-Deployments von Server Pro zu entscheiden.
* Vor allem haben Ihre Benutzer ausreichend Zeit, ihre Projekte auf die neue Overleaf Group Professional-Plattform zu kopieren.

Diese Kurzanleitung führt Sie durch die wichtigsten Schritte dieser Migration. Legen wir los!

<Steps>
<Step title="Phase 1: Einrichtung und Konfiguration">
(Link: https://docs.overleaf.com/on-premises/user-and-project-management/user-management/migrating-from-server-pro-to-group-professional#phase-1-setup-and-configuration)

* Overleaf erstellt Ihr Group Professional-Abonnement und fügt Ihren Lead Administrator hinzu.
* Ihr Gruppenadministrator kann [Managed Usersarrow-up-right](https://docs.overleaf.com/groups/user-management/managed-user-accounts) aktivieren, [Single Sign-On (SSO)arrow-up-right](https://docs.overleaf.com/groups/overleaf-group-single-sign-on/setting-up-group-sso) konfigurieren und [die Endbenutzer einladenarrow-up-right](https://docs.overleaf.com/groups/user-management/how-to-add-and-remove-users).

<Warning>

Die Aktivierung von Managed Users und die Einführung von SSO sind für die FedRAMP® LI-SaaS-Konformität erforderlich. Wenn Ihre Organisation FedRAMP-Konformität benötigt, richten Sie Managed Users und SSO ein, bevor Sie Endbenutzer einladen.

</Warning>
</Step>

<Step title="Phase 2: Benutzermigration und Datenverwaltung">
(Link: https://docs.overleaf.com/on-premises/user-and-project-management/user-management/migrating-from-server-pro-to-group-professional#phase-2-user-migration-and-data-management)

Dies ist das eigentliche Migrationsfenster mit folgenden Zuständigkeiten:

#### Endbenutzer

* Benutzer sollten alle Projekte, die sie behalten möchten, von Ihrer Server Pro-Instanz in ihre neuen Konten auf [overleaf.comarrow-up-right](http://overleaf.com/) migrieren. Dazu werden [Projekte aus Server Pro exportiertarrow-up-right](https://www.overleaf.com/learn/how-to/Exporting_your_work_from_Overleaf) und [in das eigene Konto hochgeladenarrow-up-right](https://www.overleaf.com/learn/how-to/Uploading_a_project) auf [overleaf.comarrow-up-right](http://overleaf.com/). Wer noch kein Konto auf [overleaf.comarrow-up-right](http://overleaf.com/) hat, kann sich unter [overleaf.com/registerarrow-up-right](http://overleaf.com/register) registrieren.

<Warning>

Bei diesem Exportverfahren wird nur der Quellcode des Projekts (LaTeX- und Binärdateien) übertragen. Bestehende Projekteinstellungen, Freigabeeinstellungen, Kommentare, nachverfolgte Änderungen usw. werden NICHT übertragen. Benutzer müssen ihre Mitarbeiter nach der Migration erneut einladen.

</Warning>

#### Technisches Personal

* In dieser Phase sollte Ihr technisches Team den Umgang mit Ihrer On-Premises-Server Pro-Instanz und deren Daten nach der Migration planen.
* **Datensicherung:** Sie können vor der Außerbetriebnahme alle Projekte exportieren, um ein Archiv anzulegen, mit dem Sie Benutzern helfen können, die vergessen haben, ihre Arbeit zu migrieren oder herunterzuladen. Anleitung: https://docs.overleaf.com/on-premises/maintenance/data-and-backups/exporting-projects
* **Außerbetriebnahme von Server Pro:** Nachdem das Migrationsfenster geschlossen und Ihr Lizenzschlüssel deaktiviert wurde, haben Sie für die Server Pro-Instanz selbst zwei Hauptoptionen (siehe nächster Schritt).
</Step>

<Step title="Optionen zur Außerbetriebnahme von Server Pro">
<Steps>
<Step title="Server Pro vollständig deinstallieren">
Bei der Deinstallation wird Server Pro außer Betrieb genommen und die Software vollständig entfernt.
</Step>

<Step title="Zur Community Edition wechseln">
Beim Wechsel bleibt die Datenbank mit Benutzern und Projekten einschließlich des vollständigen Projektverlaufs erhalten, indem die Instanz von Server Pro in die Community Edition umgewandelt wird.
</Step>
</Steps>

<Info>

Die Community Edition enthält WEDER [Sandboxed Compilesarrow-up-right](https://docs.overleaf.com/on-premises#overview-of-server-pro-and-community-edition) NOCH [LDAP](/de/on-premises/configuration/overleaf-toolkit/authentication/ldap-authentication)/[SAML](/de/on-premises/configuration/overleaf-toolkit/authentication/saml-authentication). Wenn Sie zur nativen Authentifizierung (Benutzername/Passwort) zurückkehren müssen, siehe: https://docs.overleaf.com/on-premises/user-and-project-management/user-management/migrating-to-ldap-or-saml#going-the-other-way-switching-from-ldap-saml-back-to-native-authentication

Einen Vergleich von Server CE und Server Pro finden Sie unter: https://docs.overleaf.com/on-premises/welcome/server-pro-vs.-community-edition

</Info>
</Step>

<Step title="Phase 3: Außerbetriebnahme von Server Pro">
(Link: https://docs.overleaf.com/on-premises/user-and-project-management/user-management/migrating-from-server-pro-to-group-professional#phase-3-server-pro-decommission)

* Das Overleaf-Team deaktiviert Ihren Server Pro-Lizenzschlüssel formell und sendet nach Abschluss eine Bestätigung.
* Führen Sie zu diesem Zeitpunkt eine der oben beschriebenen Maßnahmen zur Außerbetriebnahme durch: Server Pro vollständig deinstallieren oder zur Community Edition wechseln.
</Step>
</Steps>

Die oben genannten zusätzlichen Ressourcen und Links bleiben unverändert.
