## Einen Administrator-Benutzer erstellen {#creating-an-administrator-user}

Bereitstellungen mit dem Overleaf Toolkit:

```bash title="Overleaf Toolkit" wrap
$ bin/docker-compose exec sharelatex /bin/bash -ce "cd /overleaf/services/web && node modules/server-ce-scripts/scripts/create-user --admin --email=joe@example.com"
```

Bereitstellungen mit Legacy-docker-compose.yml:

```bash title="Legacy docker-compose" wrap
$ docker exec sharelatex /bin/bash -ce "cd /overleaf/services/web && node modules/server-ce-scripts/scripts/create-user --admin --email=joe@example.com"
```

Der Befehl erstellt einen Benutzer mit der angegebenen E-Mail-Adresse, sofern dieser noch nicht existiert, und macht ihn zum Administrator. Die Ausgabe des Befehls enthält eine URL, über die Sie das Passwort für diesen Benutzer festlegen und sich zum ersten Mal anmelden können.

<Info>

Für einen programmatischen Ansatz können Sie dasselbe Skript verwenden, um sowohl reguläre Benutzer als auch Administratoren zu erstellen. Lassen Sie für reguläre Benutzer das Flag --admin weg.

</Info>

Wenn Sie interne Konten zur Authentifizierung verwenden und einen bestehenden Benutzer zum Instanz-Administrator machen oder Administratorrechte entziehen müssen, gehen Sie wie folgt vor:

<Steps>
<Step title="Über die Admin-Oberfläche">
* Melden Sie sich als bestehender Administrator an.
* Klicken Sie auf Admin -> Manage Users.
* Suchen Sie den Benutzer und klicken Sie auf seinen Namen.
* Klicken Sie auf das Stiftsymbol.
* Schalten Sie Admin ein oder aus.
* Klicken Sie zum Abschluss auf „Save“.
</Step>
</Steps>

## Benutzer löschen {#deleting-users}

Generell ist es ratsam, Konten nur zu löschen, wenn sie nicht mehr benötigt werden. Das Löschen eines Kontos entfernt das Konto und führt dazu, dass Mitarbeitende den Zugriff auf Projekte verlieren. Um einen Benutzer an der Anmeldung zu hindern und seine Daten zu behalten, [deaktivieren Sie das Konto](/de/on-premises/user-guide/administrators/user-management#disable-or-enable-an-account) stattdessen.

Standardmäßig werden Konten vorläufig gelöscht (Soft Delete). Informationen zum dauerhaften Entfernen von Benutzern aus Ihrer Instanz finden Sie unter `ENABLE_CRON_RESOURCE_DELETION` im Leitfaden [Umgebungsvariablen](/de/on-premises/configuration/overleaf-toolkit/environment-variables).

<Info>

Konten werden standardmäßig vorläufig gelöscht. Informationen zur dauerhaften Löschung finden Sie unter `ENABLE_CRON_RESOURCE_DELETION`.

</Info>

### Über Admin -> Manage Users {#via-admin->-manage-users}

<Steps>
<Step title="">
* Melden Sie sich als Administrator an.
* Klicken Sie auf Admin -> Manage Users.
* Suchen Sie den Benutzer und aktivieren Sie das Kontrollkästchen neben seinem Namen.
* Klicken Sie auf das Papierkorbsymbol.
* Klicken Sie zur Bestätigung auf Delete account.
</Step>
</Steps>

### Über die Befehlszeile {#via-the-command-line}

Benutzerkonten (und ihre Projekte) können mit den folgenden Befehlen gelöscht werden.

Bereitstellungen mit dem Overleaf Toolkit:

```bash title="Overleaf Toolkit"
$ bin/docker-compose exec sharelatex /bin/bash -ce "cd /overleaf/services/web && node modules/server-ce-scripts/scripts/delete-user.mjs --email=joe@example.com"
```

Bereitstellungen mit Legacy-docker-compose.yml:

```bash title="Legacy docker-compose"
$ docker exec sharelatex /bin/bash -ce "cd /overleaf/services/web && node modules/server-ce-scripts/scripts/delete-user.mjs --email=joe@example.com"
```

<Danger>

Das Löschskript verwendet eine fest codierte Force-Option, die sicherstellt, dass die Löschung auch dann durchgeführt wird, wenn die E-Mail zur Kontolöschung nicht gesendet werden kann (z. B. wenn die E-Mail-Adresse des Benutzers nicht mehr existiert).

</Danger>

<Info>

Die Option --skip-email kann verwendet werden, um das Senden einer Informations-E-Mail an den gelöschten Benutzer zu verhindern.

</Info>

## Einen vorläufig gelöschten Benutzer wiederherstellen {#restoring-a-soft-deleted-user}

Wenn ein Benutzer nur vorläufig gelöscht wurde, können Sie sein Konto und die mit ihm gelöschten Projekte wiederherstellen. Projekte, die der Benutzer selbst gelöscht hatte, bleiben gelöscht.

<Steps>
<Step title="">
* Melden Sie sich als Administrator an.
* Klicken Sie auf Admin -> Manage Users.
* Suchen Sie den Benutzer, den Sie wiederherstellen möchten.
* Klicken Sie auf Display deleted users.
* Klicken Sie auf das Pfeilsymbol in der Zeile des Benutzers.
* Klicken Sie zur Bestätigung auf Restore.
</Step>
</Steps>

<Danger>

Wenn ENABLE\_CRON\_RESOURCE\_DELETION auf true gesetzt ist, können vorläufig gelöschte Konten innerhalb von 90 Tagen wiederhergestellt werden. Nach 90 Tagen ist eine Wiederherstellung des Kontos nicht mehr möglich.

</Danger>

## Benutzer zählen {#counting-users}

Die Benutzerzahlen erhalten Sie über die Admin-Oberfläche unter https://you-instance-url/admin/user#license. Für programmatische Prüfungen und Exporte können die folgenden Beispiele hilfreich sein.

Gesamtzahl der Benutzer:

```bash title="Total number of users"
echo 'db.users.countDocuments()' | docker exec -i mongo mongosh --quiet localhost/sharelatex
# overleaf [direct: primary] sharelatex> 16
```

Gesamtzahl der Benutzer über den Metrics-Endpunkt:

```bash title="Num active users from metrics"
docker exec sharelatex curl http://127.0.0.1:3000/metrics | grep num_active_users
# # HELP num_active_users num_active_users
# # TYPE num_active_users gauge
# num_active_users{app="web-api",host="b3ae4ff549d8"} 16
```

Gesamtzahl der aktiven Benutzer (Beispiel: Benutzer, die in den letzten 365 Tagen aktiv waren):

```bash title="Total number of active users"
echo 'db.users.countDocuments({ lastActive: { $gte: new Date(new Date().getTime() - (365 * 24 * 60 * 60 * 1000)) } })' | docker exec -i mongo mongosh --quiet localhost/sharelatex
# overleaf [direct: primary] sharelatex> 10
```

## Benutzerkontoinformationen aktualisieren {#updating-user-account-information}

Wie Kontoaktualisierungen durchgeführt werden, hängt davon ab, ob SSO aktiviert ist.

* Wenn kein SSO verwendet wird:
  * Administratoren können Benutzerkontoinformationen über Admin -> Manage Users ändern (E-Mail, Vorname, Nachname sowie das Erzeugen eines Links zum Zurücksetzen des Passworts).
  * Reguläre Benutzer können ihre eigenen Angaben über Account -> Account Settings aktualisieren (einschließlich Passwortänderung und Erzeugen von Git-Authentifizierungstokens).
* Wenn SSO verwendet wird:
  * Ayakaleaf Pro kann so konfiguriert werden, dass Vor- und Nachname eines Benutzers bei der Anmeldung anhand des Authentifizierungssystems aktualisiert werden.
  * Wenn OVERLEAF\_SAML\_UPDATE\_USER\_DETAILS\_ON\_LOGIN oder OVERLEAF\_LDAP\_UPDATE\_USER\_DETAILS\_ON\_LOGIN auf true gesetzt ist, wird das Formular für Benutzerdetails unter https://your-instance-url/user/settings deaktiviert, und Vor- und Nachname können nur in Ihrem Identitätsmanagementsystem festgelegt werden.

Weitere Details:

* [SAML-2.0-Konfiguration](/de/on-premises/configuration/overleaf-toolkit/authentication/saml-authentication)
* [LDAP-Konfiguration](/de/on-premises/configuration/overleaf-toolkit/authentication/ldap-authentication)

### Q\&A {#q&a}

<Accordion title="Kann ich SSO-Benutzer im Voraus anlegen, zum Beispiel über eine API?">

<strong>Antwort:</strong> Dafür gibt es keine HTTP-API. Erstellen Sie das Konto mit dem obigen Skript `create-user` (ohne `--admin`) oder unter **Admin → Manage Users** mit **Create account**. Wenn `EXTERNAL_AUTH` gesetzt ist, bietet dieses Formular die Option **Log in with SSO**, die das Konto ohne lokales Passwort und ohne Aktivierungs-E-Mail oder -Link erstellt: Der Dialog schließt sich nach **Create**. Bei der ersten Anmeldung über LDAP, SAML oder OIDC erhält der Benutzer das vorhandene Konto mit derselben E-Mail-Adresse statt eines neuen, siehe [Konten und Passwörter](/de/on-premises/configuration/overleaf-toolkit/authentication#accounts-and-passwords).

</Accordion>

<Accordion title="Kann ich die Benutzerliste exportieren und später wiederherstellen?">

<strong>Antwort:</strong> Nein. Es gibt keinen Export oder Import von Benutzerkonten, weder unter **Admin → Manage Users** noch als Skript. Konten werden in MongoDB gespeichert, sichern und stellen Sie sie daher mit einem [MongoDB-Backup](/de/on-premises/maintenance/data-and-backups#mongodb) wieder her. Das Skript `export-user-projects.mjs` exportiert die Projekte der Benutzer als ZIP-Dateien, nicht die Konten, siehe [Projekte exportieren](/de/on-premises/maintenance/data-and-backups/exporting-projects).

</Accordion>

<Accordion title="Wie lange ist der `create-user`-Link gültig, und wie setze ich ein Passwort ohne E-Mail zurück?">

<strong>Antwort:</strong> Der Link, den `create-user` ausgibt, ist 7 Tage gültig und funktioniert ohne SMTP, da Sie ihn aus der Ausgabe kopieren. Um einen neuen Link zu erhalten, führen Sie `create-user` erneut mit derselben E-Mail-Adresse aus. Für ein bestehendes Konto gibt es nur einen neuen Link aus, setzt aber auch das Admin-Flag des Kontos entsprechend `--admin`; behalten Sie `--admin` also bei, wenn Sie es für einen Administrator ausführen.

Ein Administrator kann auch ohne E-Mail einen Link zum Zurücksetzen erhalten: Klicken Sie unter **Admin → Manage Users** auf das Schlosssymbol in der Zeile des Benutzers, dann auf **Send reset link**, und kopieren Sie den Link aus dem Dialog. Er ist 1 Stunde gültig, siehe [Aktivierungs- oder Zurücksetzungslink senden](/de/on-premises/user-guide/administrators/user-management#send-an-activation-or-reset-link).

Oder legen Sie ein Passwort direkt fest: Klicken Sie auf den Namen des Benutzers, dann auf das Stiftsymbol, geben Sie ein **New password** mit mindestens 8 Zeichen ein und klicken Sie auf **Save**. Konten, die sich nur über LDAP, SAML oder OIDC anmelden, können auf keinem der beiden Wege ein Passwort erhalten.

</Accordion>
