## Einen Administrator-Benutzer erstellen

Bereitstellungen mit dem Overleaf Toolkit:

```bash title="Overleaf Toolkit" wrap
$ bin/docker-compose exec sharelatex /bin/bash -ce "cd /overleaf/services/web && node modules/server-ce-scripts/scripts/create-user --admin --email=joe@example.com"
```

Bereitstellungen mit Legacy-docker-compose.yml:

```bash title="Legacy docker-compose" wrap
$ docker exec sharelatex /bin/bash -ce "cd /overleaf/services/web && node modules/server-ce-scripts/scripts/create-user --admin --email=joe@example.com"
```

Der Befehl erstellt einen Benutzer mit der angegebenen E-Mail-Adresse, sofern dieser noch nicht existiert, und macht ihn zum Administrator. Die Ausgabe des Befehls enthält eine URL, über die Sie das Passwort für diesen Benutzer festlegen und sich zum ersten Mal anmelden können.

<Info>

Für einen programmatischen Ansatz können Sie dasselbe Skript verwenden, um sowohl reguläre Benutzer als auch Administratoren zu erstellen. Lassen Sie für reguläre Benutzer das Flag --admin weg.

</Info>

Wenn Sie interne Konten zur Authentifizierung verwenden und einen bestehenden Benutzer zum Instanz-Administrator machen oder Administratorrechte entziehen müssen, gehen Sie wie folgt vor:

<Steps>
<Step title="Über die Admin-Oberfläche">
* Melden Sie sich als bestehender Administrator an.
* Klicken Sie auf Admin -> Manage Users.
* Suchen Sie den Benutzer und klicken Sie auf seine E-Mail-Adresse.
* Scrollen Sie nach unten zum Abschnitt „Site Admin“ und klicken Sie auf den Link (show).
* Aktivieren Sie das Kontrollkästchen „Is Site Admin“.
* Klicken Sie zum Abschluss auf „Save“.
</Step>
</Steps>

## Benutzer löschen

Grundsätzlich ist es ratsam, Konten nur dann zu löschen, wenn sie nicht mehr benötigt werden. Das Löschen eines Kontos entfernt das Konto und führt dazu, dass Mitarbeitende den Zugriff auf Projekte verlieren. Derzeit gibt es keine Möglichkeit, Konten zu deaktivieren – sie existieren entweder mit erhaltenen Daten oder werden gelöscht.

Standardmäßig werden Konten vorläufig gelöscht (Soft Delete). Informationen zum dauerhaften Entfernen von Benutzern aus Ihrer Instanz finden Sie unter `ENABLE_CRON_RESOURCE_DELETION` im Leitfaden [Umgebungsvariablen](/de/on-premises/configuration/overleaf-toolkit/environment-variables).

<Info>

Konten werden standardmäßig vorläufig gelöscht. Informationen zur dauerhaften Löschung finden Sie unter `ENABLE_CRON_RESOURCE_DELETION`.

</Info>

### Über Admin -> Manage Users

<Steps>
<Step title="">
* Melden Sie sich als Administrator an.
* Klicken Sie auf Admin -> Manage Users.
* Suchen Sie den Benutzer und aktivieren Sie das Kontrollkästchen neben seiner E-Mail-Adresse.
* Klicken Sie auf das Papierkorbsymbol.
* Klicken Sie zur Bestätigung auf „Delete“.
</Step>
</Steps>

### Über die Befehlszeile

Benutzerkonten (und ihre Projekte) können mit den folgenden Befehlen gelöscht werden.

Bereitstellungen mit dem Overleaf Toolkit:

```bash title="Overleaf Toolkit"
$ bin/docker-compose exec sharelatex /bin/bash -ce "cd /overleaf/services/web && node modules/server-ce-scripts/scripts/delete-user.mjs --email=joe@example.com"
```

Bereitstellungen mit Legacy-docker-compose.yml:

```bash title="Legacy docker-compose"
$ docker exec sharelatex /bin/bash -ce "cd /overleaf/services/web && node modules/server-ce-scripts/scripts/delete-user.mjs --email=joe@example.com"
```

<Danger>

Das Löschskript verwendet eine fest codierte Force-Option, die sicherstellt, dass die Löschung auch dann durchgeführt wird, wenn die E-Mail zur Kontolöschung nicht gesendet werden kann (z. B. wenn die E-Mail-Adresse des Benutzers nicht mehr existiert).

</Danger>

<Info>

Seit Version 5.5.0 kann die Option --skip-email verwendet werden, um das Senden einer Informations-E-Mail an den gelöschten Benutzer zu verhindern.

</Info>

## Einen vorläufig gelöschten Benutzer wiederherstellen

Wenn ein Benutzer nur vorläufig gelöscht wurde, können Sie sein Konto und seine Projekte wiederherstellen.

<Steps>
<Step title="">
* Melden Sie sich als Administrator an.
* Klicken Sie auf Admin -> Manage Users.
* Suchen Sie den Benutzer, den Sie wiederherstellen möchten.
* Klicken Sie auf die Schaltfläche „Display deleted users“.
* Klicken Sie auf die E-Mail-Adresse des gelöschten Benutzers.
* Klicken Sie auf „Recover This Account“.
* Klicken Sie zur Bestätigung auf „Recover“.
</Step>
</Steps>

<Danger>

Wenn ENABLE\_CRON\_RESOURCE\_DELETION auf true gesetzt ist, können vorläufig gelöschte Konten innerhalb von 90 Tagen wiederhergestellt werden. Nach 90 Tagen ist eine Wiederherstellung des Kontos nicht mehr möglich.

</Danger>

## Benutzer zählen

Die Benutzerzahlen erhalten Sie über die Admin-Oberfläche unter https://you-instance-url/admin/user#license. Für programmatische Prüfungen und Exporte können die folgenden Beispiele hilfreich sein.

Gesamtzahl der Benutzer:

```bash title="Total number of users"
echo 'db.users.countDocuments()' | docker exec -i mongo mongosh --quiet localhost/sharelatex
# overleaf [direct: primary] sharelatex> 16
```

Gesamtzahl der Benutzer über den Metrics-Endpunkt:

```bash title="Num active users from metrics"
docker exec sharelatex curl http://127.0.0.1:3000/metrics | grep num_active_users
# # HELP num_active_users num_active_users
# # TYPE num_active_users gauge
# num_active_users{app="web-api",host="b3ae4ff549d8"} 16
```

Gesamtzahl der aktiven Benutzer (Beispiel: Benutzer, die in den letzten 365 Tagen aktiv waren):

```bash title="Total number of active users"
echo 'db.users.countDocuments({ lastActive: { $gte: new Date(new Date().getTime() - (365 * 24 * 60 * 60 * 1000)) } })' | docker exec -i mongo mongosh --quiet localhost/sharelatex
# overleaf [direct: primary] sharelatex> 10
```

## Benutzerkontoinformationen aktualisieren

Wie Kontoaktualisierungen durchgeführt werden, hängt davon ab, ob SSO aktiviert ist.

* Wenn kein SSO verwendet wird:
  * Administratoren können Benutzerkontoinformationen über Admin -> Manage Users ändern (E-Mail, Vorname, Nachname sowie das Erzeugen eines Links zum Zurücksetzen des Passworts).
  * Reguläre Benutzer können ihre eigenen Angaben über Account -> Account Settings aktualisieren (einschließlich Passwortänderung und Erzeugen von Git-Authentifizierungstokens).
* Wenn SSO verwendet wird:
  * Server Pro kann so konfiguriert werden, dass Vor- und Nachname eines Benutzers bei der Anmeldung anhand des Authentifizierungssystems aktualisiert werden.
  * Wenn OVERLEAF\_SAML\_UPDATE\_USER\_DETAILS\_ON\_LOGIN oder OVERLEAF\_LDAP\_UPDATE\_USER\_DETAILS\_ON\_LOGIN auf true gesetzt ist, wird das Formular für Benutzerdetails unter https://your-instance-url/user/settings deaktiviert, und Vor- und Nachname können nur in Ihrem Identitätsmanagementsystem festgelegt werden.

Weitere Details:

* SAML-2.0-Konfiguration: https://docs.overleaf.com/on-premises/configuration/overleaf-toolkit/server-pro-only-configuration/saml-2.0
* LDAP-Konfiguration: https://docs.overleaf.com/on-premises/configuration/overleaf-toolkit/server-pro-only-configuration/ldap
