## Migration von Benutzernamen

Aus Sicht der Anmeldung ist die E-Mail-Adresse das primäre Identifikationsmerkmal eines Benutzers. Wenn Sie von lokaler Authentifizierung auf SSO umsteigen oder von einem IdP zu einem anderen wechseln, müssen Sie möglicherweise die E-Mail-Adressen der Benutzer aktualisieren.

Dafür steht ein Skript zur Verfügung, das Benutzer-E-Mail-Adressen anhand einer CSV-Datei im folgenden Format migriert:

`oldEmail,newEmail`

Nach einigen Validierungsprüfungen durchläuft das Skript die CSV-Datei und ändert die E-Mail-Adressen der Benutzer von `oldEmail` auf `newEmail`.

### **Validierung**

Vor der Migration wird die `<csv_file>` geprüft, um sicherzustellen, dass:

* in jeder Zeile sowohl `oldEmail` als auch `newEmail` gültige E-Mail-Adressen sind
* es keine doppelten Einträge gibt – Sie also beispielsweise nicht versuchen, verschiedenen Benutzern dieselbe neue E-Mail-Adresse zuzuweisen oder dasselbe Benutzerkonto mit einer bereits verwendeten E-Mail-Adresse zu aktualisieren

### **Verwendung**

```bash wrap
docker cp <csv_file> sharelatex:/overleaf/services/web/<csv_file> docker exec sharelatex /bin/bash -c "cd /overleaf/services/web;node ./modules/server-ce-scripts/scripts/migrate-user-emails.js [--commit] [--continue|--ignore-missing] [--admin-id=ADMIN_USER_ID] <csv_file>"
```

### **Flags**

| Name               | Beschreibung                                                                                                                                                                                                                                                      |
| ------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `--commit`         | <p>Mit dem Flag `--commit` wird die Migration tatsächlich durchgeführt. Fehlt es, läuft die Migration im Dry-Run-Modus, in dem keine Änderungen vorgenommen, aber die Validierungen trotzdem ausgeführt werden.<br /><br /><strong>Standard</strong>:`false`</p> |
| `--continue`       | Mit dem Flag `--continue` wird der Migrationsprozess fortgesetzt, wenn die E-Mail-Adresse eines Benutzerkontos bereits aktualisiert wurde                                                                                                                         |
| `--ignore-missing` | Mit dem Flag `--ignore-missing` wird der Migrationsprozess fortgesetzt, wenn ein Benutzerkonto nicht gefunden wurde                                                                                                                                                                  |
| `--admin-id`       | `--admin-id` sollte auf die ID des Administrators gesetzt werden, der die Migration durchführt; sie wird für Einträge im Audit-Log verwendet. Um Ihre Benutzer-ID zu finden, gehen Sie zu **Admin** > **Manage Users**, suchen Sie nach Ihrer E-Mail-Adresse und klicken Sie auf das erste Ergebnis.   |
| `<csv_file>`       | `<csv_file>` ist die Datei mit den alten und neuen E-Mail-Adressen                                                                                                                                                                                             |

### **Abschluss**

Je nach gewählten Flags wird bei der Ausführung des Migrationsskripts ein Fehler entweder in der Konsole protokolliert und die Ausführung fortgesetzt, oder er wird protokolliert und das Skript beendet. Bricht das Skript aufgrund eines Fehlers vorzeitig ab, wird es mit dem Code 1 beendet, um anzuzeigen, dass es nicht erfolgreich war.

Nach Abschluss der Migration protokolliert das Skript die Anzahl der erfolgreichen, fehlgeschlagenen und übersprungenen Aktualisierungen in der Konsole. Wurde die Migration erfolgreich abgeschlossen, wird es mit dem Code 0 beendet.
