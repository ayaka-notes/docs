### Konto

Bei der Verwaltung des eigenen Kontos werden **alle** Benutzer als reguläre Benutzer behandelt – `Site Admins` und `Template Users` erhalten **keine** zusätzlichen Berechtigungen. Es gibt jedoch Einschränkungen, welche Aktionen reguläre Benutzer je nach Authentifizierungsart ausführen können.

#### Einstellungen

<strong>Authentifizierungsarten: Interne Konten | SSO (SAML/LDAP)</strong>

| Aktion | Interne Konten | SSO (SAML/LDAP) |
| ----------------------------------------- | ----------------: | --------------: |
| Kontoinformationen aktualisieren | Ja | Nein |
| Passwort ändern | Ja | Nein |
| Git-Bridge-Authentifizierungstokens generieren | Ja | Ja |
| Git-Bridge-Authentifizierungstokens löschen | Ja | Ja |
| Sitzungen verwalten | Ja | Ja |

<Info>

Die Git-Bridge-Integration ist **nur** in Ayakaleaf Pro verfügbar. Weitere Informationen finden Sie unter [Overleaf Server Pro vs. Ayakaleaf Pro](/de/on-premises/readme/ayakaleaf-pro-vs-server-pro).

</Info>

#### Ihre Sitzungen

| Aktion | Benutzer |
| -------------------- | ---: |
| Sitzungen löschen | Ja |
| Aktuelle Sitzung anzeigen | Ja |
| Andere Sitzungen anzeigen | Ja |

### Editor-IDE

In der Overleaf-Editor-IDE können Sie eine der folgenden Rollen haben: `Project Owner`, `Editor`, `Reviewer`, `Viewer`, `Site Administrator` oder `Template User`.

<Info>

Ayakaleaf Pro und die Community Edition unterstützen anonymen **Nur-Lese**- und **Lese-/Schreib**-Zugriff auf Projekte.

Weitere Informationen dazu finden Sie [hier](/de/on-premises/configuration/overleaf-toolkit/environment-variables) bei den Umgebungsvariablen `OVERLEAF_ALLOW_PUBLIC_ACCESS` und `OVERLEAF_ALLOW_ANONYMOUS_READ_AND_WRITE_SHARING`.

</Info>

<Info>

Kommentare und die Änderungsverfolgung in Echtzeit sind **nur** in Ayakaleaf Pro verfügbar. Weitere Informationen finden Sie unter [Overleaf Server Pro vs. Ayakaleaf Pro](/de/on-premises/readme/ayakaleaf-pro-vs-server-pro).

Ein abgemeldeter Benutzer, der ein Projekt über dessen Bearbeitungslink öffnet (`OVERLEAF_ALLOW_ANONYMOUS_READ_AND_WRITE_SHARING=true`), gilt als Bearbeiter, kann aber keine Kommentare hinzufügen, beantworten, bearbeiten, auflösen oder wieder öffnen. Siehe [Öffentlicher Zugriff](/de/on-premises/configuration/overleaf-toolkit/public-access).

Die Chatfunktion im Projekt kann durch Setzen von `OVERLEAF_DISABLE_CHAT=true` deaktiviert werden. Weitere Informationen zur Anpassung Ihres Deployments finden Sie im Abschnitt [Umgebungsvariablen](/de/on-premises/configuration/overleaf-toolkit/environment-variables).

</Info>
