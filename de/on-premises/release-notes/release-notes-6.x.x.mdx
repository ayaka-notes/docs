## Ayakaleaf Pro 6.3.0

**Veröffentlichungsdatum:** 2026.10.03 (erneute Veröffentlichung; ursprünglich veröffentlicht am 2026.09.24)

Siehe: [https://github.com/ayaka-notes/ayakaleaf-pro/releases/tag/pro-v6.3.0](https://github.com/ayaka-notes/ayakaleaf-pro/releases/tag/pro-v6.3.0)

<Warning>

Ayakaleaf Pro 6.3.0 wurde ursprünglich am 24. September 2026 veröffentlicht. Diese erneute Veröffentlichung behebt Probleme mit dem KI-Assistenten sowie den Zotero- und Mendeley-Integrationen, die durch Upstream-Updates verursacht wurden.

Die zuvor veröffentlichte Version beschädigt Ihre Daten nicht. Laden Sie das neueste `6.3.0`-Image herunter und aktualisieren Sie Ihre Bereitstellung. **Bestehende Installationen mit verknüpften Literaturdateien aus Zotero oder Mendeley müssen zusätzlich die unten beschriebene Migration ausführen.** Neue Installationen benötigen diese Migration nicht.

</Warning>

<Accordion title="Zotero-/Mendeley-Migration für bestehende Installationen">

Migrieren Sie beim Upgrade auf das erneut veröffentlichte 6.3.0-Image die Metadaten bestehender verknüpfter Zotero-/Mendeley-Literaturdateien mit dem folgenden Skript. Diese Migration gehört zum Fix `12031b8dfd`.

Sie benennt `zoteroGroupId` / `mendeleyGroupId` in `group_id` und `importedByUserId` in `importer_id` um und entfernt `importedByName`.

Sichern Sie MongoDB und stoppen Sie die Anwendung, bevor Sie die Migration ausführen. Lassen Sie MongoDB laufen. Öffnen Sie die Shell (ersetzen Sie `mongo` durch Ihren Containernamen):

```bash
docker exec -it mongo mongosh
```

Führen Sie Folgendes in `mongosh` aus (ersetzen Sie `sharelatex` durch Ihren Datenbanknamen):

```javascript
use sharelatex

(async () => {
  let updated = 0
  await db.projects.find({}, { rootFolder: 1 }).forEach(async project => {
    const changes = {}
    function visit(folders, path) {
      for (const [i, folder] of (folders || []).entries()) {
        const folderPath = `${path}.${i}`
        for (const [j, file] of (folder.fileRefs || []).entries()) {
          const data = { ...file.linkedFileData }
          if (!["zotero", "mendeley"].includes(data.provider)) continue
          const groupKey = `${data.provider}GroupId`
          if (![groupKey, "importedByUserId", "importedByName"].some(key => key in data)) continue
          for (const [oldKey, newKey] of [[groupKey, "group_id"], ["importedByUserId", "importer_id"]]) {
            if (data[oldKey] != null && data[oldKey] !== "") {
              const value = String(data[oldKey])
              if (newKey in data && data[newKey] !== value) {
                throw new Error(`Conflicting ${newKey}: project ${project._id}, file ${file._id}`)
              }
              data[newKey] = value
            }
            delete data[oldKey]
          }
          delete data.importedByName
          changes[`${folderPath}.fileRefs.${j}.linkedFileData`] = data
        }
        visit(folder.folders, `${folderPath}.folders`)
      }
    }
    visit(project.rootFolder, "rootFolder")
    if (!Object.keys(changes).length) return
    const result = await db.projects.updateOne(
      { _id: project._id, rootFolder: { $eq: project.rootFolder } },
      { $set: changes }
    )
    if (!result.matchedCount) throw new Error(`Project changed during migration: ${project._id}`)
    updated += result.modifiedCount
  })
  print(`Updated ${updated} project(s).`)
})()
```

Das Skript berücksichtigt verschachtelte Ordner und ändert nur Zotero-/Mendeley-Metadaten. Es kann gefahrlos erneut ausgeführt werden: Nach abgeschlossener Migration meldet der nächste Lauf `Updated 0 project(s).`. Bricht es mit einem Konflikt ab, prüfen Sie das gemeldete Projekt bzw. die gemeldete Datei; frühere Projekte wurden möglicherweise bereits migriert.

Starten Sie die aktualisierte Anwendung, laden Sie den Editor neu und aktualisieren Sie eine bestehende Literaturdatei als deren ursprünglicher Importeur. Historische Snapshots werden nicht umgeschrieben. Um auf die alte Anwendung zurückzustufen, stellen Sie das MongoDB-Backup wieder her.

Wir freuen uns sehr, die Veröffentlichung von Overleaf Pro 6.3.0 bekannt zu geben, dem leistungsstärksten und funktionsreichsten Online-LaTeX-Editor der Community. Da uns die Verbesserung der Nutzererfahrung stets am Herzen liegt, bringt diese Version umfangreiche Änderungen und großartige Funktionen, die Sie begeistern werden – darunter einen KI-Assistenten und die Integration von Literaturverwaltungen von Drittanbietern.

### Änderungen

* KI-Chat-Assistent: Chatten Sie direkt im Editor mit einem KI-Modell über Ihren eigenen Anbieter.
* LaTeX-Fehlerassistent: Erhalten Sie KI-gestützte Korrekturvorschläge für LaTeX-Kompilierungsfehler.
* Mendeley-Integration: Importieren Sie Literaturangaben aus Mendeley, ähnlich wie bei Zotero.
* Open-in-Overleaf-API: Eine API zum Öffnen von Inhalten in Overleaf wurde hinzugefügt.
* Vorlagengalerie: Serverseitige Paginierung, Suche und Sortierung wurden hinzugefügt, sodass große Galerien nicht mehr alle Vorlagen im Browser laden müssen.
* Übersetzungen: Aktualisierte Übersetzungspatches für 6.3.0, einschließlich neuer Oberflächentexte in allen unterstützten Sprachen.
* Upstream Overleaf 6.3.0: Enthält die Dateibearbeitung in Tabs, separate Header-Logos für helles und dunkles Design sowie Aktualisierungen von Abhängigkeiten und Basis-Image.
* `OVERLEAF_HEADER_IMAGE_URL_LIGHT` und `OVERLEAF_HEADER_IMAGE_URL_DARK` wurden hinzugefügt, um separate Header-Logos für helles und dunkles Design zu unterstützen.
* Dateien können im Editor jetzt in verschiedenen Tabs geöffnet werden.
* Unterstützung für konfigurierbare HTTP(S)-Proxys, einschließlich lokal gehosteter Proxys, über `OVERLEAF_LINKED_URL_OUTBOUND_PROXY` hinzugefügt; dieser wird auch von der Open-in-Overleaf-API verwendet.

#### Feature 04: Template Pagination

Die Galerie paginiert, sortiert und durchsucht jetzt direkt in MongoDB. Das funktioniert ohne jede Vorbereitung; bei Tausenden von Vorlagen können Sie dennoch die folgenden Indizes anlegen, damit sie schnell bleibt (kann gefahrlos erneut ausgeführt werden, `mongo`/`sharelatex` = Ihre Container- und Datenbanknamen):

```bash
docker exec mongo mongosh sharelatex --quiet --eval '
db.templates.createIndex({category:1,lastUpdated:-1},{name:"category_1_lastUpdated_-1",background:true});
db.templates.createIndex({lastUpdated:-1},{name:"lastUpdated_-1",background:true});
db.templates.createIndex({category:1,name:1},{name:"category_1_name_1_ci",collation:{locale:"en",strength:2},background:true});
db.templates.createIndex({name:1},{name:"name_1_ci",collation:{locale:"en",strength:2},background:true});
'
```

Behalten Sie die `collation` der beiden `*_ci`-Indizes genau wie angegeben bei – die Galerie fragt mit derselben Collation ab, und MongoDB verwendet nur einen passenden Index.

## Ayakaleaf Pro 6.2.2

**Veröffentlichungsdatum:** 2026.07.23

Siehe: [https://github.com/ayaka-notes/ayakaleaf-pro/releases/tag/pro-v6.2.2](https://github.com/ayaka-notes/ayakaleaf-pro/releases/tag/pro-v6.2.2)

### Änderungen

Rückportierung der offiziellen Hotfix-Patches aus Upstream-Overleaf `6.2.2` (auf Basis von `6.2.1`):

* Das Geheimnis für Projekteinladungstoken gelangt nicht mehr in die Logs. Der Verschlüsseler für Einladungstoken protokollierte bei jeder Ver- und Entschlüsselung seine eigene Konfiguration, einschließlich der aus `OVERLEAF_INVITE_TOKEN_SECRET` abgeleiteten Cipher-Passwörter.
* Ausgehende E-Mails wurden vom AWS-SES-v1-Client, dessen Support ausgelaufen ist, auf SESv2 migriert. Instanzen mit dem E-Mail-Treiber `ses` konnten mitunter gar keine E-Mails versenden; der Versand läuft jetzt über `SESv2Client`.
* Die Gruppeneinträge im Dropdown zum Teilen von Projekten werden jetzt durch das neue Feature-Flag `group-link-sharing` gesteuert, sodass das Teilen von Gruppenlinks auf Instanzen, für die es nicht gilt, nicht mehr angeboten wird.
* Das Dialogfeld zum Teilen von Projekten für Mitarbeitende wurde korrigiert. Wurde es als Nicht-Eigentümer oder bei deaktiviertem `sharing-updates`-Ablauf geöffnet, wurde eine Anfrage gesendet, die immer fehlschlug und den Fehler „something went wrong“ anzeigte.
* `scripts/flush_docs_with_pending_updates.js` wurde zum document-updater hinzugefügt – ein Wartungsskript, das Dokumente wiederherstellt, deren `PendingUpdates`-Warteschlange in Redis hängen geblieben ist, nachdem ihr Projekt geleert oder endgültig gelöscht wurde. Unterstützt `--dry-run` und eine Sicherheitsprüfung mit `--estimated-docs`.
* Aktualisierte Abhängigkeiten: `multer` 2.2.0, `form-data` 2.5.6, `protobufjs` 7.6.3, `@grpc/grpc-js` 1.14.4.

Diese Version enthält außerdem die folgenden Korrekturen und Verbesserungen von Ayakaleaf Pro:

* Vollständige Übersetzungen für 16 weitere Sprachen (cs, da, de, es, fi, fr, it, ja, ko, nl, no, pl, pt, ru, sv, tr) hinzugefügt; dadurch werden unübersetzte Texte wie auf der Seite zum Zurücksetzen des Passworts behoben. Behebt [#38](https://github.com/ayaka-notes/ayakaleaf-pro/issues/38).
* Die Anzahl in der Schaltfläche „show N more projects“ im Admin-Panel wurde korrigiert; sie zeigte eine falsche Zahl an, weil der Plural-Platzhalter nicht korrekt übergeben wurde.
* Validierungsfehler beim GitHub-Export wurden korrigiert; sie werden jetzt über statische i18n-Schlüssel statt als Rohmeldungen angezeigt, und Fehlerschlüssel, die vom GitHub-Sync-Dialog nicht mehr verwendet werden, wurden entfernt.

## Ayakaleaf Pro 6.2.1

**Veröffentlichungsdatum:** 2026.07.18

Siehe: [https://github.com/ayaka-notes/ayakaleaf-pro/releases/tag/pro-v6.2.1](https://github.com/ayaka-notes/ayakaleaf-pro/releases/tag/pro-v6.2.1)

### Änderungen

Rückportierung der offiziellen Hotfix-Patches aus Upstream-Overleaf `6.2.1` (auf Basis von `6.2.0`):

* Die Echtzeitnachricht `applyOtUpdate` wurde mit einem strikten Validierungsschema abgesichert, statt beliebige Objekte zu akzeptieren; fehlerhafte Bearbeitungsoperationen werden abgelehnt.
* Dieses Schema wurde gelockert, sodass `meta.tc` optional ist und gültige Updates nicht mehr von der strengeren Validierung abgelehnt werden.
* Der Editor (ShareJS-Client) wurde korrigiert: Operationen, die sich auf eine leere Operation reduzieren – weil sie durch eine entfernte/gleichzeitige Operation aufgehoben oder durch Rückgängigmachen vollständig zurückgenommen wurden –, werden verworfen, statt an den Server gesendet zu werden, und das Dokument wird korrekt als gespeichert gemeldet. Verhindert fälschliche Synchronisierungsprobleme bzw. „ungespeicherte Änderungen“ beim Rückgängigmachen und bei gleichzeitiger Bearbeitung.

## Ayakaleaf Pro 6.2.0

**Veröffentlichungsdatum:** 2026.07.10

Siehe: [https://github.com/ayaka-notes/ayakaleaf-pro/releases/tag/pro-v6.2.0](https://github.com/ayaka-notes/ayakaleaf-pro/releases/tag/pro-v6.2.0)

Besonderer Dank gilt yu-i-i und davrot für ihre wertvollen Beiträge. Sie haben GitHub Sync verbessert und die erweiterte Literatursuche sowie die Zotero-Integration eingeführt.

### Hinweise

<Warning>

* Eine neue, zwingend erforderliche Umgebungsvariable `OVERLEAF_INVITE_TOKEN_SECRET` wurde eingeführt. Sie müssen sie mit `openssl rand -base64 32` erzeugen. Ist sie nicht konfiguriert, startet Ihre Overleaf-Instanz nicht.
* Wenn Sie GitHub Sync aktivieren, müssen Sie die Umgebungsvariable `GITHUB_TOKEN_CIPHER_PASSWORD` konfigurieren. Sie wird benötigt, um GitHub-Zugriffstoken sicher zu verschlüsseln. Ohne sie startet Ihre Overleaf-Instanz nicht.

</Warning>

* Die neue Umgebungsvariable `DEFAULT_LATEX_COMPILER` wurde hinzugefügt, um den Standard-Compiler für neue Projekte festzulegen (`pdflatex`, `latex`, `xelatex` oder `lualatex`).
* Der neu gestaltete Editor ist jetzt die einzige verfügbare Option.

Diese Version enthält die folgenden Verbesserungen und neuen Funktionen.

* `MAX_UPLOAD_SIZE` ist jetzt konfigurierbar, statt auf **50 MB** begrenzt zu sein.
* Eine Neustartschleife des Containers bei deaktivierten Sandbox-Kompilierungen wurde behoben.
* Das Löschen von PATs für OAuth2 ist jetzt auf den Eigentümer beschränkt.
* Ein Problem beim LDAP-Import wurde behoben.

Neue Funktionen:

* Ein browserbasierter Python Runner wurde hinzugefügt.
* Pandoc-Unterstützung für Import und Export von Markdown, DOCX und weiteren Formaten wurde hinzugefügt.
* GitHub Sync wurde hinzugefügt.
* Vollständige chinesische Übersetzungen wurden hinzugefügt.
* Die Zotero-Integration wurde hinzugefügt.
* `DEFAULT_LATEX_COMPILER` wurde hinzugefügt.

## Ayakaleaf Pro 6.0.0

**Veröffentlichungsdatum:** 2026.02.17

Test-Release, siehe: [https://github.com/ayaka-notes/ayakaleaf-pro/releases/tag/pro-v6.0.0](https://github.com/ayaka-notes/ayakaleaf-pro/releases/tag/pro-v6.0.0)

Dies ist ein Test-Release und zugleich unsere erste Version von Overleaf Pro. Diese Version enthält noch keine Funktionen von Server Pro und markiert daher nur unseren Ausgangspunkt. Weitere Funktionen wie das Admin-Panel und git-bridge werden wir später hinzufügen …

Mit diesem Release führen wir das Overleaf-Docker-Image für ARM ein. Sie können es ausprobieren, wenn Sie einen Mac oder einen ARM-basierten Server haben, allerdings funktionieren einige Funktionen möglicherweise nicht einwandfrei (noch nicht getestet).

### Docker-Image

Das Docker-Image finden Sie hier: [https://github.com/ayaka-notes/overleaf-pro/pkgs/container/overleaf-pro](https://github.com/ayaka-notes/overleaf-pro/pkgs/container/overleaf-pro)

Das Multi-Arch-Image finden Sie [hier](https://github.com/ayaka-notes/overleaf-pro/pkgs/container/overleaf-pro/691283454?tag=6.0.0).

```bash
docker pull ghcr.io/ayaka-notes/overleaf-pro:6.0.0
```

### Migration von Binärdateien

Dieses neue Release halbiert den Speicherbedarf von Binärdateien.

Version `5.5` enthält eine Online-Migration, die eine minimale Ausfallzeit während des Upgrades ermöglicht. Stellen Sie vor dem Upgrade auf Server Pro `v6` sicher, dass Sie bereits die neueste Version von Server Pro `v5.5` verwenden ([Versionshinweise 5.x.x](https://docs.overleaf.com/on-premises/release-notes/release-notes-5.x.x)) und die Migration ausgeführt haben.

[Vollständige Migrationsanleitung ansehen](https://docs.overleaf.com/on-premises/release-notes/release-notes-5.x.x/binary-files-migration).

### MongoDB-Upgrade auf v8

Dieses Release hebt die minimale MongoDB-Version auf `8.0` an.

Wenn Sie derzeit MongoDB `v6` oder älter verwenden, müssen Sie jeweils um eine Hauptversion aktualisieren (`v6 → v7 → v8`).

<Warning>

Stellen Sie bitte sicher, dass Sie **vor** dem Upgrade ein Backup Ihrer [Datenbank](https://docs.overleaf.com/on-premises/maintenance/data-and-backups) erstellt haben. Im Falle eines Rollbacks müssen Sie das Datenbank-Backup wiederherstellen.

</Warning>

Eine Schritt-für-Schritt-Anleitung für das Upgrade von MongoDB `v6 → v7 → v8` finden Sie [hier](https://docs.overleaf.com/on-premises/maintenance/updating-mongodb#example-upgrading-mongodb-from-6.0-to-7.0-toolkit-users).

### Redis-Upgrade auf v7.4

Dieses Release hebt außerdem die minimale Redis-Version auf `7.4` an.

Setzen Sie `REDIS_IMAGE` in Ihrer `config/overleaf.rc` auf `REDIS_IMAGE=7.4`.

### Neue Funktionen

* Das Teilen per Link kann jetzt mit `OVERLEAF_DISABLE_LINK_SHARING=true` deaktiviert werden.
* Mit `OVERLEAF_MAINTENANCE_MESSAGE` und `OVERLEAF_MAINTENANCE_MESSAGE_HTML` können jetzt Titel und Inhalt der Wartungsseite angepasst werden.
* Mit `OVERLEAF_USER_HARD_DELETION_DELAY` und `OVERLEAF_PROJECT_HARD_DELETION_DELAY` lässt sich (in Millisekunden) die Frist bis zum endgültigen Löschen gelöschter Benutzer/Projekte anpassen (Standard: 90 Tage).

### Fehlerbehebungen

* Darstellung der Fußzeile mit Links korrigiert.
* Fehlermeldungen bei SAML-Anmeldefehlern verbessert.
* Behoben, dass kein Audit-Log-Eintrag erstellt wurde, wenn der Administratorstatus eines Benutzers bei der SSO-Anmeldung aktualisiert wurde.
* Fehler im Verlaufsbereich bei aktiviertem TLS in Redis behoben.
* Kompilierungen können jetzt auch ohne Sandbox-Kompilierung gestoppt werden.

### Weitere Änderungen

* Alle Links zur Statusseite (festgelegt über `OVERLEAF_STATUS_PAGE_URL`) verwenden jetzt `HTTPS` und werden in einem neuen Browser-Tab geöffnet.
