### Funktion "Von externer URL"

Um die Funktion ["From External URL"](https://www.overleaf.com/learn/how-to/How_to_upload_a_file_using_an_external_URL) zu aktivieren, muss die Variable `ENABLED_LINKED_FILE_TYPES` den Typ `url` enthalten:

```text
ENABLED_LINKED_FILE_TYPES=project_file,project_output_file,url
```

Dadurch werden sowohl das Menü _Add Files_ als auch das Dropdown _Insert Figure_ in der Symbolleiste erweitert: Über das Menü _Add Files_ können Sie Ihrem Projekt eine Datei anhand ihrer URL hinzufügen, während Sie über das Dropdown _Insert Figure_ ein Bild direkt über seine URL in Ihr Dokument einfügen können.

#### Sicherheitshinweis

Wenn Benutzer in ihren Projekten einen Link zu einer externen Datei hinzufügen, wird die Datei im Namen des Servers abgerufen, auf dem Overleaf installiert ist.

Wenn der Overleaf-Server in einem privaten Netzwerk betrieben wird, das auch interne HTTP-Server enthält (die nur für den internen Gebrauch bestimmt sind), könnte ein Benutzer mit Zugriff auf Overleaf potenziell auf Daten dieser internen Dienste zugreifen.

Um dies zu verhindern, dürfen Links zu externen Dateien nicht auf Server verweisen, deren IP-Adressen zu einem der gesperrten Netzwerkbereiche gehören. Diese sind:

* `127.0.0.0/8` (Loopback)
* `169.254.0.0/16` (Link-Local)
* `10.0.0.0/8` (privates Netzwerk)
* `172.16.0.0/12` (privates Netzwerk)
* `192.168.0.0/16` (privates Netzwerk)

Zusätzlich wird die folgende Umgebungsvariable eingeführt:

* `OVERLEAF_LINKED_URL_BLOCKED_NETWORKS`
  * Eine durch Leerzeichen getrennte Liste von Netzwerken in CIDR-Notation, aus denen keine externen Ressourcen abgerufen werden dürfen. Typischerweise sollte dies das interne Netzwerk der Organisation umfassen.
    * Beispiel: `OVERLEAF_LINKED_URL_BLOCKED_NETWORKS=123.123.0.0/16 124.124.124.0/24`

In vielen Organisationen hosten Server im internen Netzwerk jedoch auch Daten, die öffentlich zugänglich sein sollen. Um den Zugriff auf bestimmte Ressourcen zu erlauben, auch wenn das gesamte Netzwerk gesperrt ist, steht die folgende Umgebungsvariable zur Verfügung:

* `OVERLEAF_LINKED_URL_ALLOWED_RESOURCES`
  * Ein regulärer Ausdruck, der erlaubte Webressourcen definiert, von denen externe Dateien abgerufen werden dürfen. Wenn eine URL auf diesen regulären Ausdruck passt, wird der Zugriff gewährt, auch wenn ihr Netzwerk ansonsten gesperrt ist.
    *   Beispiel: Um URLs wie `https://www.example.com/~john/pictures/frog.jpg` und `http://www.example.com/public/whatever/lit.bib` zu erlauben:

        `OVERLEAF_LINKED_URL_ALLOWED_RESOURCES=^https?://www\.example\.com/(?:~[^/]+|public)(?:/.*)?`
    *   Beispiel: Um URLs wie `http://www.example.com/private/whatever/file` zu verweigern und gleichzeitig alle anderen Ressourcen außerhalb des Teilbaums `private` zu erlauben:

        `OVERLEAF_LINKED_URL_ALLOWED_RESOURCES=^https?://www\.example\.com/(?!private)(?:.*)`<br />

#### Ausgehender Proxy

Ab dem erneut veröffentlichten `v6.3.0` (3. Oktober 2026) können Sie einen ausgehenden HTTP(S)-Proxy konfigurieren, falls der Server einen solchen für den Internetzugang benötigt. Dies gilt auch für externe ZIP- und TeX-Ressourcen, die über die [Open in Overleaf API](/de/on-premises/configuration/overleaf-toolkit/overleaf-import-api  "mention") abgerufen werden. Konfigurieren Sie die folgende Variable:

* `OVERLEAF_LINKED_URL_OUTBOUND_PROXY`
  * URL eines HTTP(S)-Proxys, der für alle Anfragen nach externen Dateien verwendet wird. Lassen Sie sie leer, um eine direkte Verbindung herzustellen.
    * Beispiel: `OVERLEAF_LINKED_URL_OUTBOUND_PROXY=http://proxy.internal:3128`
  * Bei gesetztem Proxy werden Hostnamen vom Proxy aufgelöst, nicht vom Overleaf-Server. Daher gelten `OVERLEAF_LINKED_URL_BLOCKED_NETWORKS` und die oben genannten gesperrten Bereiche nur für URLs, die eine IP-Adresse enthalten. **Der Proxy muss den Zugriff auf Ihre internen Netzwerke blockieren.**
