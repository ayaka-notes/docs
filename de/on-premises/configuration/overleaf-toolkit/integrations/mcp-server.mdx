Jedes Projekt hat einen MCP-Server, sodass KI-Clients wie Claude Code, Codex, Cursor, VS Code oder Gemini CLI daran arbeiten können: seine Dateien lesen und bearbeiten, es kompilieren, das LaTeX-Log lesen, das PDF herunterladen und Kommentare beantworten. Ab v6.3.3 können sie außerdem den Verlauf durchsuchen und Versionen wiederherstellen, nachverfolgte Änderungen prüfen, Kommentare hinzufügen, den Projektchat nutzen und Dateien verschieben.

<Info>

Diese Funktion wurde von [ayaka-notes/ayakaleaf-pro](https://github.com/ayaka-notes/ayakaleaf-pro) entwickelt. Sie ist ab v6.3.1 verfügbar. Die Tools für den Verlauf, nachverfolgte Änderungen, den Projektchat, neue Kommentare und das Verschieben von Dateien sind ab v6.3.3 verfügbar, siehe [Neu in v6.3.3](/on-premises/user-guide/users/mcp-server#new-in-v6.3.3).

</Info>

### Einrichtung {#setup}

Der MCP-Server ist Teil der Git-Integration: Aktivieren Sie [git-bridge](/de/on-premises/configuration/overleaf-toolkit/integrations/git-integration), dann ist auch der MCP-Server verfügbar. Weitere Konfiguration ist nicht erforderlich.

### Einen KI-Client verbinden {#connect-an-ai-client}

1. Erzeugen Sie in den **Kontoeinstellungen** ein Git-Authentifizierungstoken. Dasselbe Token wird für den MCP-Server und für Git verwendet.
2. Öffnen Sie im Editor **Integrations** und klicken Sie auf **MCP server**. Dort werden die Adresse des MCP-Servers des Projekts, `https://<your-overleaf>/project/<project_id>/mcp`, sowie die Anleitung zum Hinzufügen zu jedem KI-Client angezeigt: Kopieren Sie den Befehl und ersetzen Sie `<token>` durch Ihr Token.

Das Token wird als HTTP-Header `Authorization: Bearer <token>` gesendet. Der Befehl für Claude Code lautet zum Beispiel:

```bash
claude mcp add --transport http overleaf \
  https://<your-overleaf>/project/<project_id>/mcp \
  --header "Authorization: Bearer <token>"
```

### Verwendung {#usage}

Sobald die Verbindung steht, formulieren Sie Ihre Anfragen an den KI-Client in normaler Sprache. Zum Beispiel:

| Ihre Anfrage | Der KI-Client verwendet |
| --- | --- |
| _Korrigiere die Tippfehler in der Einleitung._ | `read_file`, `edit_file`: Die Änderungen erscheinen live im Editor |
| _Kompiliere das Projekt und behebe die LaTeX-Fehler._ | `compile`, `get_compile_log`, `edit_file` |
| _Beantworte die offenen Kommentare und schließe sie dann._ | `list_comments`, `reply_to_comment`, `resolve_comment` |
| _Wechsle zu XeLaTeX und lade das PDF herunter._ | `update_settings`, `compile`, `get_output_file_link` |
| _Schreibe die Zusammenfassung als nachverfolgte Änderung neu._ | `read_file`, `edit_file` mit `trackChanges` (v6.3.3) |
| _Was hat sich seit der eingereichten Version geändert?_ | `list_versions`, `list_changes`, `diff` (v6.3.3) |
| _Verschiebe die Kapitel in einen Ordner namens chapters._ | `move_file` (v6.3.3) |

### Tools {#tools}

| Gruppe | Tools |
| --- | --- |
| Projekt | `get_clone_info`, `get_settings`, `update_settings` |
| Dateien | `list_files`, `read_file`, `edit_file`, `write_file`, `delete_file`, `move_file`, `create_folder` |
| Kompilierung | `compile`, `get_compile_log`, `get_output_file_link`, `word_count` |
| Kommentare | `list_comments`, `reply_to_comment`, `resolve_comment`, `reopen_comment`, `add_comment`, `edit_comment_message`, `delete_comment_message` |
| Nachverfolgte Änderungen | `list_tracked_changes`, `accept_tracked_changes`, `reject_tracked_changes` |
| Verlauf | `list_versions`, `list_changes`, `diff`, `create_version`, `delete_version`, `restore_file`, `restore_project` |
| Chat | `list_chat_messages`, `send_chat_message` |

v6.3.3 hat 33 Tools, oder 31 mit `OVERLEAF_DISABLE_CHAT=true`, wodurch die Chat-Tools entfallen. v6.3.1 und v6.3.2 haben die übrigen 17: alles oben außer `move_file`, `create_folder`, `add_comment`, `edit_comment_message`, `delete_comment_message`, den Tools für nachverfolgte Änderungen, den Chat-Tools und den Verlaufs-Tools außer `list_versions`. In v6.3.3 liest `read_file` eine Datei auch in einer Version des Verlaufs, `edit_file` und `write_file` akzeptieren `trackChanges`, und `update_settings` legt auch die Sprache der Rechtschreibprüfung fest.

Mit `edit_file`, `write_file` und `move_file` vorgenommene Änderungen erscheinen live im Editor und werden mit denen der Mitarbeitenden zusammengeführt. Für viele Dateien auf einmal oder Binärdateien kann der KI-Client das Projekt auch mit Git klonen und pushen.

Mit `trackChanges` ist die Bearbeitung einer vorhandenen Datei eine nachverfolgte Änderung des Benutzers des Tokens, auch wenn die Änderungsverfolgung im Projekt ausgeschaltet ist; eine neue Datei ist das nie. Ohne `trackChanges` folgen Bearbeitungen der Einstellung zur Änderungsverfolgung des Projekts.

### Berechtigungen {#permissions}

Der MCP-Server folgt wie Git den Freigabeeinstellungen des Projekts:

* Alle, die das Projekt ansehen können, können es lesen, kompilieren und seine Ausgabe herunterladen.
* Nur der Besitzer und Mitarbeitende mit Bearbeitungsrechten können seine Dateien und Einstellungen ändern, Versionen wiederherstellen und nachverfolgte Änderungen annehmen oder ablehnen.
* Reviewer können außerdem Kommentare hinzufügen und darauf antworten, die von ihnen begonnenen Kommentare schließen, wieder öffnen oder löschen und Versionen speichern. Sie können keine Dateien bearbeiten, auch nicht als nachverfolgte Änderungen.
* Alle bearbeiten nur ihre eigenen Kommentarnachrichten, und Reviewer löschen nur ihre eigenen.
* Nur der Besitzer löscht Versionen, die andere gespeichert haben.
* Betrachter, die über einen Link beigetreten sind, können die Kommentare, nachverfolgten Änderungen, den Verlauf und den Chat nicht sehen, genau wie im Editor. Eingeladene Betrachter können sie sehen und den Chat nutzen.
* Wenn der Projektbesitzer nicht über **Full project history** verfügt, zeigen die Verlaufs-Tools nur die Änderungen der letzten 24 Stunden, wie das Verlaufspanel. Admins sehen alle.

Das Benutzerhandbuch enthält eine Tabelle, was jede Rolle tun darf, siehe [Wer darf was](/on-premises/user-guide/users/mcp-server#who-may-do-what).

### Fragen & Antworten {#q&a}

<Accordion title="Ich sehe im Editor weder Integrations noch MCP server">

<strong>Antwort:</strong> Der MCP-Server hat keine eigene Umgebungsvariable. Er wird mit `GIT_BRIDGE_ENABLED=true` in `config/overleaf.rc` aktiviert, siehe [Git-Integration](/de/on-premises/configuration/overleaf-toolkit/integrations/git-integration). Führen Sie nach der Änderung `bin/up -d` aus. Ohne die git-bridge zeigt der Editor den Tab **Integrations** in seiner linken Leiste nicht an.

</Accordion>

<Accordion title="Der KI-Client meldet „Track changes is off for this project“">

<strong>Antwort:</strong> Der Client hat eine nachverfolgte Änderung angefordert, aber das Konto des Projektbesitzers hat keine Änderungsverfolgung. Klicken Sie auf **Admin** und dann auf **Manage Users**, öffnen Sie den Besitzer und schalten Sie auf dem Tab **Features** die Option **Track changes** ein, siehe [Features](/de/on-premises/user-guide/administrators/user-management#features). Bearbeitungen ohne `trackChanges` funktionieren weiterhin.

</Accordion>

<Accordion title="Der KI-Client sieht nur die Änderungen der letzten 24 Stunden">

<strong>Antwort:</strong> Das Konto des Projektbesitzers hat keinen vollständigen Projektverlauf, daher zeigen die Verlaufs-Tools dasselbe wie das Verlaufspanel: die Änderungen der letzten 24 Stunden. Klicken Sie auf **Admin** und dann auf **Manage Users**, öffnen Sie den Besitzer und schalten Sie auf dem Tab **Features** die Option **Full project history** ein, siehe [Features](/de/on-premises/user-guide/administrators/user-management#features).

</Accordion>
