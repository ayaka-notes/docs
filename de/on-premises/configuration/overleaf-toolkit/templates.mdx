### Konfiguration

Ab Version 6.3.0 führt die Galerie Paginierung, Suche und Sortierung auf dem Server durch. Eine Migration ist nicht erforderlich. Für große Galerien siehe die [optionalen MongoDB-Indizes](/de/on-premises/release-notes/release-notes-6.x.x#feature-04-template-pagination  "mention") in den Release Notes.

Die Vorlagengalerie wird über die folgenden Umgebungsvariablen gesteuert:

* `OVERLEAF_TEMPLATE_GALLERY`: Auf `true` setzen, um die Vorlagengalerie zu aktivieren.
*   `OVERLEAF_TEMPLATE_CATEGORIES`: Eine optionale, durch Leerzeichen getrennte Liste von null oder mehr Schlüsseln für Vorlagenkategorien. Gültige Schlüssel sind:

    * _`academic-journal`_
    * _`book`_
    * _`presentation`_
    * _`poster`_
    * _`cv`_
    * _`homework`_
    * _`bibliography`_
    * _`calendar`_
    * _`formal-letter`_
    * _`report`_
    * _`thesis`_
    * _`newsletter`_

    Der spezielle Schlüssel _`all`_ wird automatisch angehängt. Er steht für eine Kategorie, die alle Vorlagen enthält.

    Für jeden Kategorieschlüssel können die folgenden optionalen Umgebungsvariablen gesetzt werden:

    * `TEMPLATE_<KEY>_NAME`: Der Anzeigename der Vorlagenkategorie.
    * `TEMPLATE_<KEY>_DESCRIPTION`: Eine kurze Beschreibung der Kategorie.

    Enthält ein Kategorieschlüssel einen Bindestrich (`-`), ersetzen Sie ihn in den Namen der Umgebungsvariablen durch einen Unterstrich (`_`).
* `ENABLE_CONVERSIONS`: Muss auf `true` gesetzt sein, um die Erzeugung von Miniaturansichten und Vorschauen für Vorlagen zu aktivieren.

### Berechtigungen zum Veröffentlichen

Administratoren können Vorlagen veröffentlichen. Sie können außerdem einen Benutzer ohne Administratorrechte bestimmen, der die kuratierten Vorlagen in Ihrer lokalen Galerie unter `/templates` verwaltet.

Dazu setzen Sie die Umgebungsvariable `OVERLEAF_TEMPLATES_USER_ID` in `toolkit/config/variables.env` auf die `ID` des Benutzers, der in Ihrer Instanz für die Vorlagenverwaltung zuständig sein soll, zum Beispiel:

```dotenv
OVERLEAF_TEMPLATES_USER_ID=56a8865231faeb5f07d69959
```

### Vorlagen veröffentlichen

Für jede Vorlage, die Sie hochladen möchten:

1. Erstellen Sie ein Projekt mit dem Quellcode der Vorlage und stellen Sie sicher, dass es kompiliert.
2. Wählen Sie im Editor **File** > **Manage Template**.
3. Geben Sie im angezeigten Formular die Details der Vorlage ein:
   * Der _Titel_ muss eindeutig sein.
   * Das Feld _Beschreibung_ unterstützt Markdown-Formatierung.
   * Das Feld _Autor_ akzeptiert Links im Markdown-Format.

Nach dem Absenden können die Details der Vorlage bearbeitet oder die Vorlage über die Seite der Vorlagengalerie gelöscht werden. Administratoren und der Vorlagenbenutzer (`OVERLEAF_TEMPLATES_USER_ID`) können jede Vorlage verwalten.

### Vorlagen von overleaf.com übernehmen

Da Overleaf Pro für den Offline-Betrieb konzipiert ist, gibt es keine automatisierte Möglichkeit, Vorlagen aus der Galerie von [overleaf.com](https://www.overleaf.com/) in Ihre On-Premises-Installation zu integrieren. Es ist jedoch möglich, dies manuell für jede einzelne Vorlage zu tun.

Standardmäßig ist Overleaf Pro so konfiguriert, dass für Kompilierungen eine TeXLive-Version mit dem Basisschema verwendet wird. Diese Basisversion ist schlank und enthält nur eine sehr begrenzte Auswahl an LaTeX-Paketen, was höchstwahrscheinlich zu Fehlern wegen fehlender Pakete führt, wenn Ihre Benutzer versuchen, Vorlagen von [overleaf.com](https://www.overleaf.com/) in Ihrer lokalen On-Premises-Instanz zu verwenden.

Leider gibt es keine automatische Möglichkeit, fehlende Pakete zu installieren. Server Pro bietet jedoch eine konfigurierbare Einstellung, mit der Ihre Benutzer Projekte mit Zugriff auf mehr Pakete und auf sicherere Weise kompilieren können. Diese Funktion heißt [Sandbox Compiles](https://docs.overleaf.com/on-premises/configuration/overleaf-toolkit/server-pro-only-configuration/sandboxed-compiles) (auch bekannt als Sibling Containers).

Damit heruntergeladene Vorlagen mit Ihrer On-Premises-Instanz von Server Pro kompatibel sind, empfehlen wir dringend, [Sandbox Compiles](https://docs.overleaf.com/on-premises/configuration/overleaf-toolkit/server-pro-only-configuration/sandboxed-compiles) zu aktivieren, da Ihre Benutzer so Zugriff auf dieselbe TeX Live-Umgebung wie auf [overleaf.com](https://www.overleaf.com/) erhalten. Diese Images enthalten die beliebtesten Pakete und Schriftarten und wurden bereits mit unseren Galerievorlagen getestet.

Weitere Informationen dazu, wie Sie konfigurieren, welche TeX Live-Versionen Benutzer in ihrem Projekt auswählen können, und wie Sie die Standardversion des TeX Live-Images für neue Projekte festlegen, finden Sie im Abschnitt [Changing the TeX Live Image](https://docs.overleaf.com/on-premises/configuration/overleaf-toolkit/server-pro-only-configuration/sandboxed-compiles#changing-the-tex-live-image) unserer Dokumentation.

1. Rufen Sie die [Vorlagengalerie](https://www.overleaf.com/latex/templates) auf [overleaf.com](https://www.overleaf.com/) auf und suchen Sie die gewünschte Vorlage, zum Beispiel [IEEE Photonics Journal Paper Template - Example Submission](https://www.overleaf.com/latex/examples/ieee-photonics-journal-paper-template-example-submission/bsfjjfkdsjds)
2. Klicken Sie auf die Schaltfläche **Open as Template**
3. Klicken Sie auf das Projektmenü und wählen Sie **Download Source**
4. Melden Sie sich anschließend bei Ihrem Konto auf der On-Premises-Instanz von Server Pro an
5. Klicken Sie im Projekt-Dashboard auf die Schaltfläche **New Project** und wählen Sie **Upload Project**
6. Klicken Sie auf die Schaltfläche **Select a .zip file** und wählen Sie die heruntergeladene ZIP-Datei der Vorlage aus

Der Benutzer kann diese neu hochgeladene Vorlage dann in seinem eigenen Konto verwenden, oder Sie können sie als Vorlagenbenutzer für andere Benutzer veröffentlichen.

### Fragen und Antworten

<Accordion title="Kann ich das Projekt löschen, nachdem ich die zugehörige Vorlage veröffentlicht habe?">

<strong>Antwort:</strong> Ja, wir raten jedoch davon ab. Wenn Sie eine Vorlage veröffentlichen, erstellen wir einen Snapshot des Projekts und speichern es zum Zeitpunkt der Veröffentlichung als ZIP-Datei. So ist sichergestellt, dass die Vorlage nicht beeinträchtigt wird, selbst wenn Sie das zugehörige Projekt löschen.

Wir speichern jedoch auch die ProjectID, die mit dieser Vorlage verknüpft ist, damit Sie die Vorlage künftig leicht aktualisieren können.

Wenn Sie das zugehörige Projekt löschen, sehen Sie auf der Detailseite der Vorlage die Schaltfläche "Admin: Source Project" nicht mehr (siehe Abbildung unten).

<Accordion title="Warum dauert das Veröffentlichen einer Vorlage bei manchen Projekten so lange?">

<strong>Antwort:</strong> Beim Veröffentlichen der Vorlage speichern wir das Projekt als ZIP- und als PDF-Datei, was in der Regel schnell geht. Zusätzlich müssen wir jedoch Miniaturansichten des PDFs erzeugen, damit diese in den Vorlagendetails angezeigt werden können.

Die Dauer der Erzeugung von Miniaturansichten hängt in der Regel vom Inhalt der ersten Seite Ihres PDFs ab. Um einen Ausgleich zwischen Anzeigequalität und Konvertierungszeit zu schaffen, wählen wir eine mittlere Breite.

Enthält die erste Seite des PDFs jedoch viel Text, kann die Konvertierung der Miniaturansichten 40 Sekunden oder sogar länger dauern – bitte haben Sie Geduld. Hier ein Beispiel für ein großes Poster, bei dem es länger dauert.
