</Info>

#### Mendeley-Integration einrichten

1. Öffnen Sie [diesen Link](https://dev.mendeley.com/myapps.html), um eine Mendeley-OAuth-Anwendung zu registrieren
2. Konfigurieren Sie die **Redirect URL** als: `${OVERLEAF_SITE_URL}/user/mendeley/oauth/callback`
3. Notieren Sie sich die generierte **ID** (in der Regel numerisch, wie `24061` unten) und das **Secret** Ihrer Anwendung
4. Passen Sie Ihre `config/variables.env` an
5. Behalten Sie den Authorisation Flow „Elsevier" bei (empfohlen)

```dotenv title="config/variables.env"
#################
#   Mendeley    #
#################
# 'mendeley' must be in ENABLED_LINKED_FILE_TYPES (keep 'zotero' too if you use both)
ENABLED_LINKED_FILE_TYPES=project_file,project_output_file,url,mendeley

# From a Mendeley OAuth application (register at https://dev.mendeley.com/myapps.html)
# Redirect URL -> ${OVERLEAF_SITE_URL}/user/mendeley/oauth/callback
MENDELEY_CLIENT_ID=
MENDELEY_CLIENT_SECRET=
# Encrypts the Mendeley OAuth tokens in mongo; if unset, a key file is generated
# in /var/lib/overleaf/data on first use
# How to generate: `openssl rand -hex 32`
MENDELEY_CIPHER_PASSWORD=
# Optional: route the module's server-side Mendeley requests (OAuth + API) through
# an HTTP proxy (must be reachable from the web container; same as github-sync)
# http://10.0.0.1:10808
# (Optional) MENDELEY_PROXY_URL=
```

<Info>

`mendeley` muss in `ENABLED_LINKED_FILE_TYPES` enthalten sein (behalten Sie auch `zotero` in der Liste, wenn Sie beides verwenden). `MENDELEY_CLIENT_ID` und `MENDELEY_CLIENT_SECRET` stammen aus Ihrer registrierten OAuth-Anwendung. Das Cipher-Passwort verschlüsselt die Mendeley-OAuth-Token in MongoDB (generieren Sie eines mit `openssl rand -hex 32`); ohne dieses wird bei der ersten Verwendung eine Schlüsseldatei im Daten-Volume erzeugt. Optional können Sie `MENDELEY_PROXY_URL` setzen, um die serverseitigen Mendeley-Anfragen (OAuth + API) über einen HTTP-Proxy zu leiten, der vom Web-Container aus erreichbar ist.

</Info>

### Hinweise

<Warning>

Wenn Sie eine bestehende Installation mit verknüpften Mendeley-Literaturdateien auf die erneut veröffentlichte Version 6.3.0 aktualisieren, befolgen Sie die [Migrationsanleitung für Zotero / Mendeley](/de/on-premises/release-notes/release-notes-6.x.x#ayakaleaf-pro-6.3.0  "mention"). Neue Installationen benötigen diese Migration nicht.

</Warning>

<Danger>

Da Ayakaleaf eine kollaborative Plattform ist, darf zur Verbesserung der Sicherheit ab Version 6.3.0 nur die ursprüngliche Erstellerin bzw. der ursprüngliche Ersteller einer Literatur-`bib`-Datei die importierte Datei aktualisieren.

</Danger>

Angenommen, die Projekteigentümerin, Nutzerin A, aktiviert die Link-Freigabe und erstellt im Projekt eine Datei `test.bib`, die sie mit ihrem eigenen Zotero-Konto verknüpft. Greift ein anderer Nutzer, Nutzer B, über den geteilten Link auf das Projekt zu, kann Nutzer B `test.bib` weiterhin lesen und herunterladen, darf die Datei jedoch nicht aktualisieren oder erneut aus Zotero importieren. Nur Nutzerin A als ursprüngliche Erstellerin der Literaturdatei kann Aktualisierungen durchführen. Mit anderen Worten: Nur die ursprüngliche Erstellerin bzw. der ursprüngliche Ersteller der `.bib`-Datei ist berechtigt, sie zu aktualisieren.
