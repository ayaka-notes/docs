Diese Seite beschreibt die Umgebungsvariablen, die in der Datei `config/variables.env` für Toolkit-Bereitstellungen unterstützt werden.

Die Datei `config/variables.env` besteht aus Variablendefinitionen im Format `NAME=value`; Zeilen, die mit `#` beginnen, werden als Kommentare behandelt.

<Info>

Nach jeder Änderung an `overleaf.rc` oder `variables.env` müssen Sie die Docker-Container neu erstellen, indem Sie `bin/up` ausführen.

</Info>

### Alle Versionen

Diese Umgebungsvariablen sind mit Server CE und Server Pro kompatibel und ermöglichen eine einfache Migration zwischen diesen beiden On-Premises-Versionen. Sie können sowohl bei Toolkit- als auch bei Docker Compose-Bereitstellungen verwendet werden.

<Info>

Früher hatten diese Umgebungsvariablen das Präfix `SHARELATEX_` statt `OVERLEAF_`.

</Info>

| Name | Beschreibung |
| --- | --- |
| `OVERLEAF_SITE_URL` | Die Adresse, unter der Ihre Overleaf-Instanz öffentlich erreichbar ist. Sie wird in öffentlichen Links und beim Verbindungsaufbau über Websockets verwendet und muss daher korrekt konfiguriert sein! |
| `OVERLEAF_ADMIN_EMAIL` | Die E-Mail-Adresse, unter der Benutzer die Person erreichen können, die die Website betreibt. |
| `OVERLEAF_APP_NAME` | Der Name, der angezeigt wird, wenn von der laufenden Anwendung die Rede ist. Standardwert ist 'Overleaf (Community Edition)'. |
| `OVERLEAF_MONGO_URL` und `MONGO_URL` | Die URL der zu verwendenden Mongo-Datenbank. |
| `OVERLEAF_REDIS_HOST` und `REDIS_HOST` | Der Hostname der zu verwendenden Redis-Instanz. Beide sind erforderlich (siehe [Versionshinweise](/de/on-premises/release-notes)). |
| `OVERLEAF_REDIS_PORT` und `REDIS_PORT` | Der Port der zu verwendenden Redis-Instanz. Beide sind erforderlich (siehe [Versionshinweise](/de/on-premises/release-notes)). |
| `OVERLEAF_REDIS_PASS` und `REDIS_PASSWORD` | Das Passwort für die Verbindung zu Redis (falls zutreffend). **Beide** Umgebungsvariablen müssen gesetzt sein. Weitere Informationen finden Sie unter [Passwortauthentifizierung aktivieren](/de/on-premises/configuration/overleaf-toolkit/redis#enabling-password-authentication). |
| `OVERLEAF_REDIS_TLS` | <p>Wenn auf `true` gesetzt, ermöglicht dies die Verbindung zu einer Redis-Instanz, die TLS erfordert.<br /><br /><strong>Hinweis:</strong> mTLS wird derzeit nicht unterstützt.</p> |
| `OVERLEAF_NAV_TITLE` | Legt den Tab-Titel der Anwendung fest. |
| `OVERLEAF_HEADER_IMAGE_URL_LIGHT` und `OVERLEAF_HEADER_IMAGE_URL_DARK` | URLs benutzerdefinierter Header-Logos für das helle und das dunkle Theme (hinzugefügt in 6.3.0). Jedes Theme greift auf `OVERLEAF_HEADER_IMAGE_URL` zurück, wenn die jeweilige Variable nicht gesetzt ist. Siehe [Branding](/de/on-premises/configuration/overleaf-toolkit/branding "mention"). |
| `OVERLEAF_LINKED_URL_OUTBOUND_PROXY` | URL eines HTTP(S)-Proxys zum Abrufen externer verknüpfter Dateien sowie externer ZIP- oder TeX-Ressourcen über die Open-in-Overleaf-API. Verfügbar ab dem neu veröffentlichten Ayakaleaf Pro `6.3.0` (3. Oktober 2026). Lassen Sie die Variable leer, um eine direkte Verbindung herzustellen. Beispiel: `OVERLEAF_LINKED_URL_OUTBOUND_PROXY=http://proxy.internal:3128`. Hinweise zur Konfiguration und zu Netzwerkzugriffsbeschränkungen finden Sie unter [Outbound Proxy](/de/on-premises/configuration/overleaf-toolkit/external-url#outbound-proxy "mention"). |
| `OVERLEAF_INVITE_TOKEN_SECRET` | <p><strong>Erforderlich</strong>. Eine zufällige Zeichenfolge zur Absicherung von Token für die Projektfreigabe (hinzugefügt in Server Pro 6.2.0).</p><p><strong>Mindestanzahl an Zeichen:</strong> 16</p> |
| `OVERLEAF_SESSION_SECRET` | Eine zufällige Zeichenfolge zur Absicherung von Token; bei Lastverteilung muss sie auf allen Servern auf denselben Wert gesetzt werden. Wenn nur eine Instanz betrieben wird, muss sie nicht vom Benutzer gesetzt werden. |
| `OVERLEAF_COOKIE_SESSION_LENGTH` | Ermöglicht es, die standardmäßige Ablaufzeit des Sitzungscookies von 5 Tagen zu überschreiben. Der Wert ist in Millisekunden anzugeben. Beispiel: Damit die Sitzung 1 Stunde dauert, setzen Sie `COOKIE_SESSION_LENGTH=3600000`. (Hinzugefügt in Server Pro 4.2) |
| `OVERLEAF_TRUSTED_PROXY_IPS` | <p>Wenn nicht gesetzt, ist der Standardwert `loopback`. Wenn Sie den Wert manuell setzen, müssen Sie zusätzlich zu Ihren vertrauenswürdigen IPs auch `loopback` (oder `127.0.0.1`) angeben, wodurch der nginx-Instanz im <strong>sharelatex</strong>-Container vertraut wird. Es werden nur IP-Adressen und CIDR-Bereiche akzeptiert: Fügen Sie keine Hostnamen wie `localhost` hinzu, da Overleaf sonst nicht startet und `502 Bad Gateway` zurückgibt.<br /><br />Wenn Sie für Ihr reguläres Netzwerk ein Subnetz aus `172.16.0.0/12` (Standardsubnetz für Docker-Netzwerke) verwenden, setzen Sie bitte `OVERLEAF_TRUSTED_PROXY_IPS=loopback,<network>` in Ihrer `config/variables.env`. Dabei ist `<network>` der Wert `IPAM -> Config -> Subnet` aus `docker inspect overleaf_default`, z. B. `OVERLEAF_TRUSTED_PROXY_IPS=loopback,172.19.0.0/16`. Dies verhindert das Fälschen von `X-Forwarded`-Headern.<br /><br />Wenn Sie einen externen TLS-Proxy verwenden (d. h. einen, der nicht vom Overleaf Toolkit verwaltet wird), stellen Sie bitte sicher, dass `OVERLEAF_TRUSTED_PROXY_IPS=loopback,<ip-of-your-tls-proxy>` gesetzt ist, z. B. `OVERLEAF_TRUSTED_PROXY_IPS=loopback,192.168.13.37`.</p> |
| `OVERLEAF_RESTRICT_INVITES_TO_EXISTING_ACCOUNTS` | Wenn auf `true` gesetzt, werden Projekteinladungen auf E-Mail-Adressen beschränkt, die bestehenden Benutzerkonten entsprechen. |
| `OVERLEAF_ALLOW_PUBLIC_ACCESS` | Wenn auf `true` gesetzt, können nicht authentifizierte Benutzer die Website ansehen. Der Standardwert ist `false`, d. h. nicht authentifizierte Benutzer werden bedingungslos zur Anmeldeseite umgeleitet, wenn sie versuchen, einen Teil der Website aufzurufen. Beachten Sie, dass diese Option Authentifizierung oder Sicherheit in keiner Weise deaktiviert. Diese Option ist erforderlich, wenn Ihre Benutzer ihre Projekte öffentlich machen und nicht authentifizierten Benutzern das Ansehen dieser Projekte ermöglichen möchten. |
| `OVERLEAF_ALLOW_ANONYMOUS_READ_AND_WRITE_SHARING` | Wenn auf `true` gesetzt, können anonyme Benutzer Projekte ansehen und bearbeiten, die über die Funktion [Link-Freigabe](https://www.overleaf.com/blog/integration-update-link-sharing-2017-11-27) geteilt wurden. |
| `OVERLEAF_DISABLE_LINK_SHARING` | Deaktiviert die Funktion [Link-Freigabe](https://www.overleaf.com/blog/integration-update-link-sharing-2017-11-27). |
| `EMAIL_CONFIRMATION_DISABLED` | Wenn auf `true` gesetzt, wird das Banner mit der Aufforderung zur E-Mail-Bestätigung nicht angezeigt. |
| `ADDITIONAL_TEXT_EXTENSIONS` | Ein Array von Strings zur Konfiguration zusätzlicher Dateiendungen für bearbeitbare Dateien. |
| `DEFAULT_LATEX_COMPILER` | <p>Legt den Standard-Compiler für <strong>neue</strong> Projekte fest. (Hinzugefügt in Server Pro 6.2.0).</p><p><strong>Optionen:</strong> `pdflatex`, `latex`, `xelatex` oder `lualatex`</p> |
| `OVERLEAF_STATUS_PAGE_URL` | Benutzerdefinierte URL der Statusseite (hinzugefügt in Server Pro 3.4.0), z. B. `status.example.com`. |
| `OVERLEAF_FPH_INITIALIZE_NEW_PROJECTS` | Auf `'false'` setzen, um zu verhindern, dass neue Projekte mit Full Project History initialisiert werden (hinzugefügt in Server Pro 3.5.0). |
| `OVERLEAF_FPH_DISPLAY_NEW_PROJECTS` | Auf `'false'` setzen, um zu verhindern, dass neue Projekte die Full Project History statt des alten Verlaufs anzeigen (hinzugefügt in Server Pro 3.5.0). |
| `ENABLE_CRON_RESOURCE_DELETION` | Setzen Sie diese Umgebungsvariable auf `true`, um die automatische Bereinigung gelöschter Projekte und Benutzer nach 90 Tagen zu aktivieren. |
| `OVERLEAF_USER_HARD_DELETION_DELAY` | <p>Ändert die Ablauffrist für gelöschte Benutzer. Angabe in Millisekunden.<br /><br /><strong>Standard:</strong> 90 Tage</p> |
| `OVERLEAF_PROJECT_HARD_DELETION_DELAY` | <p>Ändert die Ablauffrist für gelöschte Projekte. Angabe in Millisekunden.<br /><br /><strong>Standard:</strong> 90 Tage</p> |
| `MAX_UPLOAD_SIZE` | <p>Steuert die maximale Größe eines einzelnen Uploads in Megabyte. Standardwert ist `50`.<br /><br /><strong>Achtung</strong>: Diese Variable ist eine reine Zahl ohne Einheit (MB) oder sonstige Ergänzung.<br /><br />Die gesamte unkomprimierte Größe einer hochgeladenen `.zip`-Datei ist auf das 6-Fache dieses Werts begrenzt (standardmäßig 300 MB).</p> |
| `COMPILE_SIZE_LIMIT` | Steuert die maximale Größe des Request-Bodys in Byte. Dies ist die Summe aller Dokumentdateigrößen im Projekt (`main.tex`, `references.bib` (falls nicht verknüpft) usw.), die in der ersten Kompilierungsanfrage an den CLSI-Dienst gesendet werden müssen. |
| `COMPILE_TIMEOUT` | Die Zeit in Sekunden, die für den Abschluss einer Kompilierung zulässig ist. Weitere Informationen finden Sie unter [Kompilier-Timeout von Projekten aktualisieren](/de/on-premises/user-and-project-management/project-management#updating-project-compile-timeout). |
| `MAX_RECONNECT_GRACEFULLY_INTERVAL_MS` | Eine konfigurierbare Verzögerung zwischen dem geordneten Neuverbinden des Editors, dem Festschreiben der Daten und dem Herunterfahren des Containers, um das Risiko von Datenverlust zu verringern. |
| `SECCOMP_PROFILE` | <p>Setzen Sie diese Umgebungsvariable auf einen Pfad auf dem Docker-<strong>Host</strong>, der auf das SECCOMP-Profil verweist. Eine Kopie des Profils können Sie <a href="https://raw.githubusercontent.com/overleaf/overleaf/365af778b68a7940e08282119dc4ef473e2f0044/services/clsi/seccomp/clsi-profile.json">hier</a> herunterladen.<br /><br />Derzeit für Podman-Bereitstellungen bei Verwendung von Sandboxed Compiles erforderlich.</p> |
| `OVERLEAF_DISABLE_CHAT` | Wenn auf `true` gesetzt, wird die Chat-Funktion innerhalb von Projekten deaktiviert. |
| `OVERLEAF_LOGIN_SUPPORT_TEXT` | Wenn gesetzt, können Support-Informationen unterhalb der Anmeldeschaltfläche angezeigt werden. Der Text erscheint auf dem Anmeldebildschirm und kann verwendet werden, um Benutzer an den internen Support zu verweisen oder Hinweise zur Anmeldung, Kontoerstellung usw. zu geben. |
| `ALLOW_MONGO_ADMIN_CHECK_FAILURES` | <p>Wenn auf `true` gesetzt, dürfen die MongoDB-Startprüfungen fehlschlagen, ohne den Start der Bereitstellung zu verhindern. Dies kann erforderlich sein, wenn Sie eine MongoDB-Datenbank verwenden, in der Ihr Datenbankbenutzer nicht über die Rolle `clusterParameterReader` verfügt.<br /><br />Hilfe zum Erstellen einer benutzerdefinierten Rolle finden Sie <a href="/de/on-premises/maintenance/updating-mongodb#creating-a-custom-role">hier</a>.</p> |
| `V1_HISTORY_URL_FOR_GIT_BRIDGE` | Ermöglicht die Trennung des **history-v1**-Endpunkts für internen Datenverkehr (`web`-Dienst → `history-v1`-Dienst, beide im `sharelatex`-Container) und externen Datenverkehr (`git-bridge` → `history-v1`, in separaten Containern ausgeführt). |
| `OVERLEAF_MAINTENANCE_MESSAGE` und `OVERLEAF_MAINTENANCE_MESSAGE_HTML` | Dienen zur Anpassung von Titel und Inhalt der Wartungsseite. Können nicht zusammen mit `OVERLEAF_STATUS_PAGE_URL` verwendet werden. |

<Info>

Bei Verwendung des Overleaf-Anmeldesystems (lokale Konten) – nicht bei einer SSO-Option wie LDAP – können Passwortrichtlinien für Benutzer durchgesetzt werden. Bei SSO-Konten werden Passwortrichtlinien von Ihrem Identitätsanbieter oder Verzeichnisdienst durchgesetzt, was zusätzlich die Unterstützung von Multi-Faktor-Authentifizierung ermöglicht.

</Info>
