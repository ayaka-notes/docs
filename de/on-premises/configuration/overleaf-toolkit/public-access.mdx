Sie können Ihre Overleaf-Instanz auf drei Arten für Personen ohne Konto öffnen:

* [Projektzugriff](/de/on-premises/configuration/overleaf-toolkit/public-access#project-access  "mention"): Gäste können einen geteilten Projektlink ohne Anmeldung öffnen
* [Seitenzugriff](/de/on-premises/configuration/overleaf-toolkit/public-access#page-access  "mention"): abgemeldete Besucher können Seiten wie `/learn`, `/templates` und `/devs` aufrufen
* [Öffentliche Registrierung](/de/on-premises/configuration/overleaf-toolkit/public-access#public-registration  "mention"): Benutzer können sich selbst registrieren, optional mit einer Aktivierungs-E-Mail und beschränkt auf E-Mail-Domains

### Projektzugriff

<Info>

Standardmäßig muss sich ein Benutzer, selbst wenn er einen Projekt-Freigabelink erhält, zuerst **anmelden**, bevor er an einer gemeinsamen Bearbeitungssitzung teilnehmen kann.

</Info>

Um anonymen Zugriff auf per Link geteilte Projekte zu erlauben, setzen Sie die beiden folgenden Variablen:

```dotenv title="config/variables.env"
OVERLEAF_ALLOW_ANONYMOUS_READ_AND_WRITE_SHARING=true
OVERLEAF_ALLOW_PUBLIC_ACCESS=true
```

`OVERLEAF_ALLOW_ANONYMOUS_READ_AND_WRITE_SHARING` aktiviert anonymen Lese-/Schreibzugriff auf per Link geteilte Projekte.

`OVERLEAF_ALLOW_PUBLIC_ACCESS` verhindert, dass nicht authentifizierte Benutzer auf die Anmeldeseite umgeleitet werden.

Erstellen Sie die Container mit `bin/up` neu. Öffnen Sie dann eine Link-Freigabe-URL in einem privaten Fenster.

### Seitenzugriff

Standardmäßig (wenn `OVERLEAF_ALLOW_PUBLIC_ACCESS` nicht gesetzt ist) leitet **jede** Seite außer der Anmelde- und Registrierungsseite abgemeldete Besucher auf die Anmeldeseite um. Das gilt auch für Seiten, die eigentlich öffentlich sein sollen, sodass Links darauf nur für bereits angemeldete Benutzer funktionieren.

Mit `OVERLEAF_ALLOW_PUBLIC_ACCESS=true` können abgemeldete Besucher Folgendes öffnen:

| Seite                                                                 | Voraussetzung                    |
| --------------------------------------------------------------------- | -------------------------------- |
| LaTeX-Hilfe unter `/learn` (siehe [adding-latex-user-help.md](/de/on-premises/configuration/overleaf-toolkit/adding-latex-user-help  "mention")) | `OVERLEAF_PROXY_LEARN=true`      |
| Die Vorlagengalerie unter `/templates`, Vorlagenseiten, Vorschauen und ZIP-Downloads (siehe [templates.md](/de/on-premises/configuration/overleaf-toolkit/templates  "mention")) | `OVERLEAF_TEMPLATE_GALLERY=true` |
| Die Seite der Overleaf Import API unter `/devs` (siehe [overleaf-import-api.md](/de/on-premises/configuration/overleaf-toolkit/overleaf-import-api  "mention")) | —                                |

Außerdem kann die [Overleaf Import API](/de/on-premises/configuration/overleaf-toolkit/overleaf-import-api#signed-out-visitors  "mention") so ein von einem abgemeldeten Besucher abgeschicktes Formular aufbewahren, bis sich dieser angemeldet hat.

Die Projektliste, der Editor und das Erstellen von Projekten (auch aus einer Vorlage oder über die Import API) erfordern weiterhin eine Anmeldung.

### Öffentliche Registrierung

Die öffentliche Registrierung ist nur in [ayaka-notes/ayakaleaf-pro](https://github.com/ayaka-notes/ayakaleaf-pro) verfügbar.

<Danger>

Bitte beachten Sie, dass sich nach dem Aktivieren der öffentlichen Registrierung **jeder**, der Zugriff auf Ihre Overleaf-Instanz hat, als Benutzer registrieren kann.

Mit `true` werden bei der Registrierung E-Mail-Adressen nicht verifiziert. Verwenden Sie sie daher nur in einem Intranet oder einer vertrauenswürdigen Umgebung, oder verwenden Sie stattdessen die [Registrierung mit Aktivierungs-E-Mail](/de/on-premises/configuration/overleaf-toolkit/public-access#registration-with-activation-email).

Verwenden Sie auf einer Instanz mit OIDC nicht `true`: Jeder könnte sich vor der ersten OIDC-Anmeldung einer Kollegin oder eines Kollegen mit deren E-Mail-Adresse registrieren, wodurch die Kollegin oder der Kollege mit diesem Konto verknüpft würde. Verwenden Sie die [Registrierung mit Aktivierungs-E-Mail](/de/on-premises/configuration/overleaf-toolkit/public-access#registration-with-activation-email) oder keine öffentliche Registrierung, siehe [Konten und Passwörter](/de/on-premises/configuration/overleaf-toolkit/authentication#accounts-and-passwords).

</Danger>

Standardmäßig erlauben weder die Community Edition noch Overleaf Pro eine öffentliche Registrierung.

Um sie zu aktivieren, fügen Sie Folgendes zu `config/variables.env` hinzu:

```dotenv title="config/variables.env"
OVERLEAF_ALLOW_PUBLIC_REGISTRATION=true
```

Erstellen Sie die Container mit `bin/up` neu.

Klicken Sie dann auf **Sign up** oder rufen Sie `/register` auf.

### Registrierung mit Aktivierungs-E-Mail

Die Registrierung mit Aktivierungs-E-Mail ist nur in [ayaka-notes/ayakaleaf-pro](https://github.com/ayaka-notes/ayakaleaf-pro) verfügbar. Benutzer registrieren sich nur mit ihrer E-Mail-Adresse und legen ihr Passwort über den Link in der Aktivierungs-E-Mail fest, sodass nur der Inhaber einer Adresse das Konto nutzen kann. Eine Liste von Domains und Platzhaltern erfordert v6.4.0 oder neuer; frühere Versionen akzeptieren nur eine einzelne Domain, etwa `@example.com`.

Konfigurieren Sie vor dem Aktivieren den E-Mail-Versand, da Benutzer sonst nie die Aktivierungs-E-Mail erhalten. Siehe [E-Mail-Versand](/de/on-premises/configuration/overleaf-toolkit/email-delivery).

Fügen Sie dann die folgende Zeile zu `config/variables.env` hinzu:

```dotenv title="config/variables.env" wrap
OVERLEAF_ALLOW_PUBLIC_REGISTRATION=@example.com,@*.example.org
```

`OVERLEAF_ALLOW_PUBLIC_REGISTRATION` kann auf folgende Werte gesetzt werden:

| Wert                          | Wer sich registrieren kann                            | E-Mail verifiziert |
| ----------------------------- | ----------------------------------------------------- | :----------------: |
| `true`                        | Jeder, mit E-Mail-Adresse und Passwort                |        Nein        |
| `@example.com`                | Adressen von `example.com`                            |         Ja         |
| `@*.example.org`              | Adressen von Subdomains wie `cs.example.org`, nicht von `example.org` selbst |         Ja         |
| `@example.com,@*.example.org` | Alle aufgeführten Einträge, durch Kommas getrennt     |         Ja         |
| `@*`                          | Jeder                                                 |         Ja         |

Domains werden ohne Beachtung der Groß-/Kleinschreibung abgeglichen. Um eine Domain und ihre Subdomains zuzulassen, führen Sie beide auf: `@example.org,@*.example.org`.

### Q\&A

<Accordion title="Was kann ein abgemeldeter Bearbeiter mit Kommentaren tun?">

<strong>Antwort:</strong> Ein abgemeldeter Benutzer, der ein Projekt über dessen Bearbeitungslink öffnet, erhält denselben Zugriff wie ein Bearbeiter, mit Ausnahme von Aktionen, bei denen festgehalten wird, wer sie ausgeführt hat:

| Aktion                                                       | Abgemeldeter Bearbeiter |
| ------------------------------------------------------------ | ----------------------: |
| Text bearbeiten, Kommentare und verfolgte Änderungen anzeigen |                      Ja |
| Verfolgte Änderungen annehmen, den Bearbeitungsmodus wechseln |                      Ja |
| Einen Kommentar oder einen ganzen Thread löschen             |                      Ja |
| Einen Kommentar hinzufügen, beantworten oder bearbeiten      |                    Nein |
| Einen Kommentar auflösen oder wieder öffnen                  |                    Nein |

Das Review-Panel zeigt ihnen weiterhin die Schaltfläche **Resolve** an, das Auflösen schlägt jedoch mit einer Fehlermeldung fehl.

Benutzer, die ein Projekt über dessen Ansichtslink öffnen, sehen überhaupt keine Kommentare, siehe [Rollen und Berechtigungen](/de/on-premises/user-and-project-management/roles-and-permissions#collaborating).

</Accordion>
