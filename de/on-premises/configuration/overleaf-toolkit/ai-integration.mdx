## KI-Assistent und LaTeX-Fehlerassistent

Ayakaleaf Pro bringt KI-Funktionen auf zwei Arten in den Editor.

* Der KI-Assistent kann Ihre Projektdokumente und die aktuelle Auswahl als Kontext nutzen, um Fragen zu beantworten und Änderungen vorzuschlagen, die Sie prüfen können.
* Der Fehlerassistent schlägt eine gezielte Korrektur vor, wenn Sie einen LaTeX-Kompilierungsfehler auswählen.

### Toolkit-Konfiguration

Fügen Sie Folgendes zu `config/variables.env` in Ihrem Toolkit-Deployment hinzu und ersetzen Sie dabei die Beispiel-URL, den Schlüssel und das Modell durch die Werte Ihres Anbieters:

```dotenv
AI_ENABLED=true
AI_BASE_URL=https://ai-gateway.example.com/v1
AI_API_KEY=REPLACE_WITH_YOUR_GATEWAY_API_KEY
AI_MODEL=YOUR_TEXT_MODEL_ID
```

Bewahren Sie echte API-Schlüssel in der Umgebungsdatei Ihres Deployments auf und halten Sie sie aus der Versionskontrolle heraus. Die obigen Werte sind Platzhalter, keine funktionierenden Zugangsdaten.

<Info>

Die Qualität der KI-Vorschläge hängt vom gewählten Modell ab. Wenn Sie bereits ein Codex- oder ChatGPT-Abonnement haben, können Sie es über den OpenAI-kompatiblen Endpunkt von [CLIProxyAPI](https://github.com/router-for-me/CLIProxyAPI) anbinden.

</Info>

`AI_BASE_URL` ist die Basis-URL der OpenAI-kompatiblen API, gegebenenfalls einschließlich des Versionspräfixes des Anbieters. Hängen Sie nicht `/chat/completions` an, da dies intern ergänzt wird. Gateway und Modell müssen Streaming-Chat-Completions und Function-Tools unterstützen. Beide Funktionen senden Dokumentkontext an dieses Gateway; der Chat kann bei Verwendung eines bildfähigen Modells auch hochgeladene Bilder senden.

Das Toolkit leitet `config/variables.env` an den Anwendungscontainer weiter. Behalten Sie die hier gezeigten Variablennamen bei; fügen Sie kein `OVERLEAF_`-Präfix hinzu. Erstellen Sie nach dem Ändern dieser Variablen den Anwendungscontainer aus dem Toolkit-Verzeichnis neu:

```sh
bin/up -d
```

### Gateway-Einstellungen

| Variable                | Standard       | Zweck                                                                                                                                                                     |
| ----------------------- | -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `AI_ENABLED`            | `false`        | Auf genau `true` setzen, um Chat und Fehlervorschläge für die Instanz zu aktivieren. Nicht gesetzt oder jeder andere Wert lässt sie deaktiviert. Zusätzlich ist eine funktionierende Gateway-Konfiguration erforderlich. |
| `AI_BASE_URL`           | Keiner; erforderlich | Basis-URL der OpenAI-kompatiblen API.                                                                                                                               |
| `AI_API_KEY`            | Keiner; erforderlich | API-Schlüssel für dieses Gateway, vom Server verwendet.                                                                                                             |
| `AI_MODEL`              | Keiner; erforderlich | Textmodell, das von der Standard-Chat-Konfiguration und für Vorschläge zu LaTeX-Fehlern verwendet wird.                                                             |
| `AI_IMAGE_MODEL`        | Nicht gesetzt  | Optionales bildfähiges Modell auf demselben Gateway mit demselben API-Schlüssel.                                                                                          |
| `AI_MAX_STEPS`          | `20`           | Maximale Anzahl von Tool-Aufrufen pro Benutzernachricht im KI-Chat, einschließlich automatischer Fortsetzungen. Verwenden Sie eine positive Ganzzahl.                      |
| `AI_PROXY_URL`          | Nicht gesetzt  | Optionale HTTP-Proxy-URL für Aufrufe an das KI-Gateway. Sie konfiguriert nicht die Clients für Web- oder Dokumentationssuche.                                              |
| `AI_TOKEN_QUOTA`        | `0`            | Token-Limit pro Benutzer und Zeitraum, das sich Chat und Fehlervorschläge teilen. Nicht gesetzt oder `0` bedeutet unbegrenzt; verwenden Sie eine positive Ganzzahl für ein Limit. |
| `AI_TOKEN_QUOTA_PERIOD` | `month`        | `month` wird am ersten Tag um 00:00 UTC zurückgesetzt; `week` montags um 00:00 UTC. Andere Werte verwenden `month`.                                                        |

Für Bild-Uploads setzen Sie `AI_IMAGE_MODEL` auf ein Modell, das Bildeingaben akzeptiert und die vom Chat verwendeten Tools unterstützt. Jede Chat-Anfrage, deren Verlauf einen Bildanhang enthält, verwendet dieses Modell, einschließlich späterer Nachrichten in dieser Unterhaltung. Ohne diese Einstellung verwenden Bildanfragen das normale Chat-Modell, das dann selbst Bilder unterstützen muss. Vorschläge zu LaTeX-Fehlern verwenden weiterhin `AI_MODEL`.

Beispiel zum Aktivieren eines Bildmodells und eines wöchentlichen KI-Kontingents:

```dotenv
AI_IMAGE_MODEL=YOUR_IMAGE_CAPABLE_MODEL_ID
AI_TOKEN_QUOTA=100000
AI_TOKEN_QUOTA_PERIOD=week
```

### Benutzerzugriff und Einwilligung

Verfügbarkeit auf Instanzebene und Benutzerberechtigung sind voneinander getrennt. `AI_ENABLED` und die Gateway-Konfiguration steuern die Verfügbarkeit für die Instanz. Ein angemeldeter Benutzer muss zusätzlich die bestehenden Kontoprüfungen bestehen:

* `aiFeatures.enabled` darf nicht `false` sein. Dieses bestehende Datenbankfeld steuert sowohl den Chat als auch Vorschläge zu LaTeX-Fehlern.
* Das effektive `features.aiUsageQuota` des Benutzers muss der konfigurierten unbegrenzten Stufe entsprechen (standardmäßig `unlimited`), oder die bestehende Legacy-Berechtigung `features.aiErrorAssistant` muss aktiviert sein. Die effektiven Features umfassen zutreffende Feature-Overrides des Kontos.

Das Aktivieren des Kontrollkästchens allein ändert den Plan des Benutzers nicht. Das Feld `aiUsageQuota` ist eine Berechtigungsstufe, kein numerisches Token-Kontingent. `AI_TOKEN_QUOTA` ist ein separates Limit, das für jeden berechtigten Benutzer gleichermaßen gilt; das aktuelle Modul bietet kein individuelles numerisches Limit pro Konto.

Wählen Sie in der Benutzerliste der Administration einen Benutzer aus und öffnen Sie **Update account info → AI features**. **Enable AI features** aktualisiert `aiFeatures.enabled`, wenn die Kontoänderungen gespeichert werden. Der Server prüft bei neuen KI-Anfragen die aktuellen Berechtigungen, auch bei Anfragen aus einem bereits geöffneten Editor. Laden Sie den Editor nach einer Berechtigungsänderung neu, um die sichtbaren Bedienelemente zu aktualisieren.

### Nutzung und Zurücksetzen

Der Admin-Tab „AI features“ zeigt in einer Zeile die **Usage** des aktuellen Zeitraums, das **Limit** und die Schaltfläche **Reset**. Die Nutzung wird beim Öffnen des Tabs gelesen und nicht fortlaufend aktualisiert. Öffnen Sie den Tab erneut, nachdem ein Chat oder ein Fehlervorschlag abgeschlossen ist, um den neuesten Stand zu sehen. Das Zurücksetzen wirkt sofort und löscht nur den Zähler dieses Benutzers für den aktuellen Zeitraum; anschließend wird die angezeigte Nutzung neu geladen. Das restliche Kontoformular muss dafür nicht gespeichert werden.

<Frame>
  <img src="/images/on-premises/img-2f5a5399.png" alt="" width="563" />
</Frame>

Chat und Fehlervorschläge teilen sich einen Redis-Zähler, der nach Abschluss einer Anfrage anhand der vom Modellanbieter gemeldeten Gesamt-Tokens aktualisiert wird. Dies umfasst Eingabe- und Ausgabe-Tokens über alle Modellschritte hinweg. Die Eingabe kann Gesprächsverlauf, Dokumentkontext und Tool-Ergebnisse enthalten, sodass eine Folgefrage mehr Tokens verbrauchen kann als die neue Nachricht allein. Die Nutzung wird auch dann erfasst, wenn das Limit **Unlimited** ist. Anfragen ohne gemeldete Token-Gesamtzahl erhöhen den Zähler nicht; historisch nicht erfasste Nutzung kann das Modul nicht rekonstruieren.

Kontingentprüfungen erfolgen vor dem Streaming. Eine Anfrage oder mehrere gleichzeitige Anfragen können das verbleibende Kontingent überschreiten, bevor spätere Anfragen blockiert werden. Es handelt sich also um ein Nutzungskontingent und nicht um eine strikte Ausgabenobergrenze beim Anbieter. Schlägt die Kontingentabfrage fehl, wird die Anfrage zugelassen und der Fehler protokolliert.

Beide Funktionen verwenden `AI_TOKEN_QUOTA`; für Fehlervorschläge gibt es kein separates Limit für die Anzahl der Anfragen. Das Zurücksetzen des Zählers ändert weder Berechtigung, Einwilligung, das konfigurierte Limit noch die Abrechnungsdaten des Anbieters. Zähler verwenden UTC-basierte Zeitraumschlüssel und laufen nach 40 Tagen ab; bleiben die Redis-Daten erhalten, bleibt die aktuelle Nutzung auch über Neustarts der Anwendung hinweg bestehen.

### Optionale Suchdienste

Die Websuche verwendet eine Tavily-kompatible API. Sie ist verfügbar, wenn ein Such-API-Schlüssel konfiguriert ist. Diese Einstellungen sind unabhängig vom KI-Gateway:

| Variable                 | Standard                                 | Zweck                                                                                                                         |
| ------------------------ | ---------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| `TAVILY_API_KEY`         | Nicht gesetzt                            | Such-API-Schlüssel. Hat Vorrang vor `WEB_SEARCH_API_KEY`.                                                                     |
| `WEB_SEARCH_API_KEY`     | Nicht gesetzt                            | Alternativer Name für den Such-API-Schlüssel.                                                                                 |
| `WEB_SEARCH_URL`         | `https://api.tavily.com/search`          | Such-Endpunkt; benutzerdefinierte Endpunkte müssen das Anfrage- und Antwortformat von Tavily akzeptieren.                     |
| `WEB_SEARCH_MAX_RESULTS` | `5`                                      | Pro Suche angeforderte Ergebnisse; verwenden Sie eine vom Dienst unterstützte positive Ganzzahl.                               |
| `WEB_SEARCH_DEPTH`       | `basic`                                  | Suchtiefe, normalerweise `basic` oder `advanced`.                                                                              |
| `WEB_SEARCH_PROVIDER`    | `tavily`                                 | Die aktuelle Implementierung unterstützt nur das Tavily-kompatible Protokoll; eine Änderung dieses Werts wählt keinen anderen Adapter aus. |
| `DOCS_MCP_URL`           | `https://docs.overleaf.com/~gitbook/mcp` | Endpunkt für die Dokumentationssuche. Setzen Sie ihn auf eine leere Zeichenkette, um die Dokumentationssuche zu deaktivieren.  |

Zum Beispiel:

```dotenv
TAVILY_API_KEY=REPLACE_WITH_YOUR_SEARCH_API_KEY
WEB_SEARCH_MAX_RESULTS=5
WEB_SEARCH_DEPTH=basic
DOCS_MCP_URL=https://docs.overleaf.com/~gitbook/mcp
```

Die Dokumentationssuche ruft das Tool `searchDocumentation` des konfigurierten GitBook-MCP-Endpunkts auf und akzeptiert JSON- oder SSE-Antworten. Es handelt sich um einen MCP-Client für die Dokumentationssuche; diese Module stellen Projektdateien weder als MCP-Server bereit noch bieten sie ein allgemeines MCP-Server-Register.

Suchanfragen werden an den konfigurierten Suchdienst gesendet. Die Suchergebnisse können anschließend in Anfragen an das KI-Gateway einfließen. Über das Menü **Tools** im Chat können Benutzer **Web** und **Documentation** für ihre Anfragen aktivieren oder deaktivieren; ein Tool muss zusätzlich auf dem Server konfiguriert sein, damit es dem Modell zur Verfügung steht.
