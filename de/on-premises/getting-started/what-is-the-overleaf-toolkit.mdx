---
title: Was ist das Ayakaleaf Toolkit?
icon: toolbox
---

Das Ayakaleaf Toolkit ist die empfohlene Bereitstellungsmethode für On-Premises-Installationen der Community Edition und von Ayakaleaf Pro. Es wurde für die gängigste Umgebung konzipiert: einen einzelnen physischen Server oder eine virtuelle Maschine. Das Toolkit verwendet `docker compose`, um die Docker-Container Ihres Servers zu verwalten, und stellt eine Reihe von Skripten bereit, die `docker`-Befehle kapseln und Sie bei den eher technischen Aspekten der Verwaltung einer On-Premises-Version von Overleaf unterstützen.

#### Der Wrapper `bin/docker-compose`

Das Skript `bin/docker-compose` ist ein Wrapper um `docker compose`. Es lädt die Konfiguration aus dem Verzeichnis `config/` und ruft anschließend `docker compose` mit den Argumenten auf, die an das Skript übergeben wurden.

Sie können `bin/docker-compose` als transparenten Wrapper für das auf Ihrem Rechner installierte Programm `docker compose` betrachten.

Beispiel:

```bash title="Check running containers"
$ bin/docker-compose ps
```

#### Komfortable Hilfsskripte

Zusätzlich zu `bin/docker-compose` stellt das Toolkit praktische Skripte für häufige Aufgaben bereit:

* `bin/up`: Kurzform für `bin/docker-compose up`
* `bin/start`: Kurzform für `bin/docker-compose start`
* `bin/stop`: Kurzform für `bin/docker-compose stop`
* `bin/shell`: startet eine Shell im Container **sharelatex**
* `bin/doctor`: Skript zum Sammeln von Informationen über Installation und Bereitstellung. Siehe den Abschnitt „Ihren Server überprüfen“ weiter unten
* `bin/mongo`: startet eine Shell im Container **mongo** und wechselt zur richtigen Datenbank (**sharelatex**)
* `bin/backup-config`: erstellt eine Kopie (zip oder tar) Ihrer aktuellen Konfiguration und speichert sie in einem Zielverzeichnis Ihrer Wahl
* `bin/logs`: Dienst-Logs anzeigen/verfolgen
* `bin/error-logs`: Fehler-Logs der Dienste anzeigen/verfolgen
* `bin/rename-env-vars-5-0`: Migrationsskript zum Aktualisieren der Umgebungsvariablen in **config/variables.env** (Umbenennung von ShareLaTeX in Overleaf)
* `bin/rename-rc-vars`: Migrationsskript zum Aktualisieren der Umgebungsvariablen in **config/overleaf.rc** (Umbenennung von ShareLaTeX in Overleaf)
* `bin/run-script`: Hilfsskript zum einfacheren Ausführen von Skripten, die im Container **sharelatex** gespeichert sind
* `bin/upgrade`: unterstützt bei Upgrades der Instanz. Das Skript prüft (über git) auf Toolkit-Updates und bietet an, die Änderungen zu übernehmen; außerdem prüft es die neueste Docker-Image-Version und bietet an, diese zu aktualisieren. Es fragt jeden Schritt einzeln ab, bietet die Option, die aktuelle Konfiguration zu sichern, und übernimmt das Stoppen/Starten der Docker-Dienste. Weitere Informationen finden Sie unter „Upgrading your deployment“: https://docs.overleaf.com/on-premises/maintenance/upgrading-your-deployment

<Info>

Wenn Sie Ihre Instanz lieber betreiben möchten, ohne sich an die Docker-Logs anzuhängen, können Sie `bin/up -d` ausführen, um sie im Hintergrundmodus (detached) zu starten.

</Info>

#### Ihren Server überprüfen

Das Overleaf Toolkit enthält ein praktisches Skript namens `bin/doctor`, das einen Bericht erstellt, der auf alle nicht erfüllten Abhängigkeiten hinweist.

Bevor Sie fortfahren, führen Sie das Skript `bin/doctor` aus und prüfen Sie, ob alles korrekt funktioniert:

```bash title="Run Overleaf Doctor"
bin/doctor
```
