#### Dienste

Die Overleaf-Pro-Infrastruktur besteht aus vier Hauptdiensten: `sharelatex`, `git-bridge` (optional), `mongo` und `redis`. Der Dienst `sharelatex`, der die Hauptanwendung von Server Pro ausführt, ist für seine Datenbank- und Caching-/Echtzeitfunktionen auf die Dienste `mongo` und `redis` angewiesen sowie auf `git-bridge` für die [Git-Integration](/de/on-premises/configuration/overleaf-toolkit/git-integration) (optional). Der einzige auf dem Host veröffentlichte Port ist Port 80, der vom Container `sharelatex` bereitgestellt wird.

Server Pro unterstützt optional auch [S3-kompatiblen Speicher](/de/on-premises/configuration/overleaf-toolkit/s3) für Projektdateien und den vollständigen Projektverlauf und kann außerdem den Zugriff auf die Haupt-[Overleaf-Dokumentationsseitearrow-up-right](https://www.overleaf.com/learn) per Proxy bereitstellen. Weitere Informationen finden Sie in unserem Leitfaden zum [Hinzufügen der LaTeX-Benutzerhilfe](/de/on-premises/configuration/overleaf-toolkit/adding-latex-user-help).

<Info>

Bei Bedarf können MongoDB und Redis über Umgebungsvariablen ausgelagert werden, die auf externe Dienste verweisen. Weitere Informationen finden Sie unter [Overleaf konfigurieren](/de/on-premises/configuration), wenn Sie Docker Compose verwenden, und unter [Toolkit-Einstellungen](/de/on-premises/configuration/overleaf-toolkit/toolkit-settings), wenn Sie das Overleaf Toolkit verwenden.

</Info>

#### Kompilieren

Für [Sandboxed Compiles](/de/on-premises/configuration/overleaf-toolkit/sandboxed-compiles) orchestriert der Container `sharelatex` die Erstellung neuer Container, die die Projektkompilierungen übernehmen; dies geschieht über den Docker-Socket auf dem Host. Mehr über den Editor und den durchgängigen Kompilierungs-/Caching-Prozess erfahren Sie [hier](/de/on-premises/getting-started/microservices#editor-and-compile-process).

#### Netzwerk

Die Kommunikation zwischen den Containern erfolgt über die interne DNS-Auflösung von Docker in einem dedizierten Bridge-Netzwerk; es sind keine Firewalls aktiviert. Standardmäßig verwenden die oben genannten Dienste ihre jeweiligen Standardports, die jedoch über Umgebungsvariablen konfigurierbar sind. Der Container `sharelatex` verwendet Port 80 für den externen Webzugriff (bereitgestellt durch Nginx), der Container `mongo` verwendet Port 27017 und `redis` Port 6379.

Kunden, die unsere verwaltete Lösung [Overleaf Toolkitarrow-up-right](https://github.com/overleaf/toolkit) nutzen, können optional über eine Umgebungsvariable [einen TLS-Proxy aktivieren](/de/on-premises/configuration/overleaf-toolkit/tls-proxy), der HTTPS-Verbindungen mit Nginx terminiert. Alternativ können Sie Ihren vorhandenen TLS-Proxy verwenden.

<Info>

Ein Diagramm, das den Ablauf der Anfragen erläutert, finden Sie [hier](/de/on-premises/configuration/overleaf-toolkit/tls-proxy).

</Info>

#### Zusammenfassung

* Außerhalb des Docker-Netzwerks ist nur Port 80 erreichbar und an Nginx gebunden. <strong>Hinweis:</strong> Der Container `sharelatex` führt viele [Dienstearrow-up-right](https://github.com/overleaf/overleaf/tree/main/services) aus, die über HTTP miteinander kommunizieren. Diese Ports sind jedoch von außerhalb des Docker-Netzwerks **nicht** erreichbar.
* Innerhalb des Docker-Netzwerks können Overleaf-Dienste, MongoDB, Redis und Git Bridge frei miteinander kommunizieren.
* Innerhalb von [Sandboxed Compiles](/de/on-premises/configuration/overleaf-toolkit/sandboxed-compiles)-Containern ist kein Netzwerk verfügbar.
