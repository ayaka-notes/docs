#### Dienste

Die Overleaf Pro-Infrastruktur besteht aus vier Hauptdiensten: `sharelatex`, `git-bridge` (optional), `mongo` und `redis`. Der Dienst `sharelatex`, der die eigentliche Server Pro-Anwendung ausführt, ist für Datenbank sowie Caching- und Echtzeitfunktionen auf die Dienste `mongo` und `redis` angewiesen und nutzt `git-bridge` für die [Git-Integration](/de/on-premises/configuration/overleaf-toolkit/git-integration) (optional). Der einzige auf dem Host veröffentlichte Port ist Port 80, der vom Container `sharelatex` bereitgestellt wird.

Server Pro unterstützt optional auch [S3-kompatiblen Speicher](/de/on-premises/configuration/overleaf-toolkit/s3) für Projektdateien und den vollständigen Projektverlauf und kann außerdem den Zugriff auf die [Overleaf-Dokumentationsseitearrow-up-right](https://www.overleaf.com/learn) per Proxy bereitstellen. Weitere Informationen finden Sie in unserer Anleitung [LaTeX-Benutzerhilfe hinzufügen](/de/on-premises/configuration/overleaf-toolkit/adding-latex-user-help).

<Info>

Bei Bedarf können MongoDB und Redis ausgelagert werden, indem Umgebungsvariablen auf externe Dienste verweisen. Weitere Informationen finden Sie unter [Overleaf konfigurieren](/de/on-premises/configuration), wenn Sie Docker Compose verwenden, und unter [Toolkit-Einstellungen](/de/on-premises/configuration/overleaf-toolkit/toolkit-settings), wenn Sie das Overleaf Toolkit verwenden.

</Info>

#### Kompilieren

Bei [Sandboxed Compiles](/de/on-premises/configuration/overleaf-toolkit/sandboxed-compiles) orchestriert der Container `sharelatex` die Erstellung neuer Container für die Projektkompilierung; dies geschieht über den Docker-Socket des Hosts. Mehr über den Editor und den gesamten Kompilier- und Caching-Prozess erfahren Sie [hier](/de/on-premises/getting-started/microservices#editor-and-compile-process).

#### Netzwerk

Die Kommunikation zwischen den Containern erfolgt über Dockers interne DNS-Auflösung in einem dedizierten Bridge-Netzwerk; es sind keine Firewalls aktiviert. Standardmäßig verwenden die oben genannten Dienste ihre jeweiligen Standardports, die sich jedoch über Umgebungsvariablen konfigurieren lassen. Der Container `sharelatex` verwendet Port 80 für den externen Webzugriff (bereitgestellt durch Nginx), der Container `mongo` Port 27017 und `redis` Port 6379.

Kunden, die unsere verwaltete Lösung [Overleaf Toolkitarrow-up-right](https://github.com/overleaf/toolkit) nutzen, können optional über eine Umgebungsvariable einen [TLS-Proxy aktivieren](/de/on-premises/configuration/overleaf-toolkit/tls-proxy), der HTTPS-Verbindungen mit Nginx terminiert. Alternativ können Sie Ihren bestehenden TLS-Proxy verwenden.

<Info>

Ein Diagramm zum Ablauf der Anfragen finden Sie [hier](/de/on-premises/configuration/overleaf-toolkit/tls-proxy).

</Info>

#### Zusammenfassung

* Außerhalb des Docker-Netzwerks ist nur Port 80 erreichbar, der an Nginx gebunden ist. **Hinweis:** Der Container `sharelatex` führt viele [Dienstearrow-up-right](https://github.com/overleaf/overleaf/tree/main/services) aus, die über HTTP miteinander kommunizieren. Diese Ports sind jedoch von außerhalb des Docker-Netzwerks **nicht** erreichbar.
* Innerhalb des Docker-Netzwerks können Overleaf-Dienste, MongoDB, Redis und Git Bridge frei miteinander kommunizieren.
* Innerhalb der Container für [Sandboxed Compiles](/de/on-premises/configuration/overleaf-toolkit/sandboxed-compiles) steht kein Netzwerk zur Verfügung.
