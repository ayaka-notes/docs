### Der Doctor

Das Overleaf Toolkit enthält ein praktisches `doctor`-Skript, das bei der Fehlersuche hilft. Führen Sie `bin/doctor` aus, und das Skript gibt Informationen über Ihre Host-Umgebung, Ihre Konfiguration und die vom Toolkit benötigten Abhängigkeiten aus. Diese Ausgabe kann uns auch dabei helfen, Probleme mit Ihren Ayakaleaf-Pro-Installationen zu diagnostizieren.

<Info>

Nutzer von Overleaf Pro können [ein Issue auf GitHub eröffnen](https://github.com/ayaka-notes/overleaf/issues).

Es empfiehlt sich, die Ausgabe des Skripts `bin/doctor` in Ihre Nachricht aufzunehmen.

</Info>

### Den Doctor konsultieren

Führen Sie das Doctor-Skript aus:

```bash title="Run doctor"

```

### Host-Informationen

Der Abschnitt `Host Information` enthält Informationen über den Rechner, auf dem das Toolkit läuft (zum Beispiel Linux-Distribution und Version).

<Accordion title="Beispielausgabe der Host-Informationen">

```text
- Host Information
    - Linux
    - Output of 'lsb_release -a':
            No LSB modules are available.
            Distributor ID:	Ubuntu
            Description:	Ubuntu 22.04.5 LTS
            Release:	22.04
            Codename:	jammy
```

</Accordion>

### Abhängigkeiten

Der Abschnitt `Dependencies` listet die Werkzeuge auf, die das Toolkit benötigt. Ist ein Werkzeug vorhanden, wird es als `status: present` mit Versionsinformationen aufgeführt. Fehlt es, wird es als `status: MISSING!` aufgeführt, und am Ende der `doctor`-Ausgabe wird eine Warnung hinzugefügt.

<Accordion title="Beispielausgabe einer Abhängigkeit (vorhanden)">

```text
- docker
    - status: present
    - version info: Docker version 28.0.4, build b8034c0
```

</Accordion>

<Accordion title="Beispielausgabe einer Abhängigkeit (fehlend)">

```text
- docker
    - status: MISSING!
```

</Accordion>

Fehlen Abhängigkeiten, wird das Toolkit mit ziemlicher Sicherheit nicht funktionieren.

### Konfiguration

Der Abschnitt `Configuration` enthält Informationen über die Dateien im Verzeichnis `config/`. Für `config/overleaf.rc` gibt der Doctor einige wichtige Werte aus. Fehlende Dateien werden als `status: MISSING!` aufgeführt, und am Ende der `doctor`-Ausgabe wird eine Warnung hinzugefügt.

<Accordion title="Beispielausgabe der Konfiguration">

```text
====== Configuration ======
- config/version
    - status: present
    - version: 5.4.0
- config/overleaf.rc
    - status: present
    - values
        - OVERLEAF_DATA_PATH: /tmp/overleaf
        - SERVER_PRO: false
        - MONGO_ENABLED: false
        - REDIS_ENABLED: true
- config/variables.env
    - status: MISSING!
```

</Accordion>

Anmerkungen zum obigen Beispiel:

* `OVERLEAF_DATA_PATH` ist auf `/tmp/overleaf` gesetzt, was möglicherweise kein sicherer Speicherort für wichtige Daten ist.
* `MONGO_ENABLED: false` bedeutet, dass das Toolkit keine eigene MongoDB bereitstellt; stellen Sie bei Bedarf sicher, dass `MONGO_URL` auf eine extern verwaltete MongoDB verweist.
* `config/variables.env` fehlt im Beispiel.

### Warnungen

Der Abschnitt `Warnings` fasst die vom Doctor-Skript gefundenen Probleme zusammen. Gibt es keine Probleme, wird dies in diesem Abschnitt angezeigt.

<Accordion title="Beispielausgabe der Warnungen">

```text
====== Warnings ======
- configuration file variables.env not found
- rc file, OVERLEAF_DATA_PATH not set
====== End =======
```

</Accordion>
