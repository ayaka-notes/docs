### Der Doctor

Das Overleaf Toolkit enthält ein praktisches `doctor`-Skript, das bei der Fehlersuche hilft. Führen Sie `bin/doctor` aus, und das Skript gibt Informationen über Ihre Host-Umgebung, Ihre Konfiguration und die vom Toolkit benötigten Abhängigkeiten aus. Diese Ausgabe kann uns auch helfen, Probleme mit Ihren Ayakaleaf Pro-Installationen zu diagnostizieren.

<Info>

Nutzerinnen und Nutzer von Overleaf Pro können [ein Issue auf GitHub eröffnen](https://github.com/ayaka-notes/overleaf/issues).

Es empfiehlt sich, die Ausgabe des Skripts `bin/doctor` in Ihre Nachricht aufzunehmen.

</Info>


### Host-Informationen

Der Abschnitt `Host Information` enthält Informationen über den Rechner, auf dem das Toolkit läuft (zum Beispiel Linux-Distribution und Release).

<Accordion title="Beispiel für die Ausgabe der Host-Informationen">

```text
- Host Information
    - Linux
    - Output of 'lsb_release -a':
            No LSB modules are available.
            Distributor ID:	Ubuntu
            Description:	Ubuntu 22.04.5 LTS
            Release:	22.04
            Codename:	jammy
```

</Accordion>

### Abhängigkeiten

Der Abschnitt `Dependencies` listet die Werkzeuge auf, die das Toolkit zum Funktionieren benötigt. Ist ein Werkzeug vorhanden, wird es mit `status: present` und Versionsinformationen aufgeführt. Fehlt es, wird es mit `status: MISSING!` aufgeführt, und am Ende der `doctor`-Ausgabe wird eine Warnung hinzugefügt.

<Accordion title="Beispiel für die Ausgabe einer Abhängigkeit (vorhanden)">

```text
- docker
    - status: present
    - version info: Docker version 28.0.4, build b8034c0
```

</Accordion>

<Accordion title="Beispiel für die Ausgabe einer Abhängigkeit (fehlend)">

```text
- docker
    - status: MISSING!
```

</Accordion>

Fehlen Abhängigkeiten, wird das Toolkit mit ziemlicher Sicherheit nicht funktionieren.

### Konfiguration

Der Abschnitt `Configuration` enthält Informationen über die Dateien im Verzeichnis `config/`. Für `config/overleaf.rc` gibt der Doctor einige wichtige Werte aus. Fehlende Dateien werden mit `status: MISSING!` aufgeführt, und am Ende der `doctor`-Ausgabe wird eine Warnung hinzugefügt.

<Accordion title="Beispiel für die Ausgabe der Konfiguration">

```text
====== Configuration ======
- config/version
    - status: present
    - version: 6.3.2
- config/overleaf.rc
    - status: present
    - values
        - OVERLEAF_DATA_PATH: /tmp/overleaf
        - SERVER_PRO: false
        - MONGO_ENABLED: false
        - REDIS_ENABLED: true
- config/variables.env
    - status: MISSING!
```

</Accordion>

Anmerkungen zum obigen Beispiel:

* `OVERLEAF_DATA_PATH` mit dem Wert `/tmp/overleaf` ist möglicherweise kein sicherer Speicherort für wichtige Daten.
* `MONGO_ENABLED: false` bedeutet, dass das Toolkit keine eigene MongoDB bereitstellt; stellen Sie bei Bedarf sicher, dass `MONGO_URL` auf eine extern verwaltete MongoDB verweist.
* `config/variables.env` fehlt im Beispiel.

### Warnungen

Der Abschnitt `Warnings` fasst die vom Doctor-Skript gefundenen Probleme zusammen. Gibt es keine Probleme, wird dies in diesem Abschnitt angezeigt.

<Accordion title="Beispiel für die Ausgabe der Warnungen">

```text
====== Warnings ======
- configuration file variables.env not found
- rc file, OVERLEAF_DATA_PATH not set
====== End =======
```

</Accordion>

### Q\&A

<Accordion title="Müssen die Meldungen zu quay.io, zur Docker-Konfiguration und zur Perl-Locale aus `bin/doctor` behoben werden?">

<strong>Antwort:</strong> Nein, alle drei sind rein informativ. `bin/doctor` gibt nur einen Bericht aus und hält `bin/up` nicht auf.

* `logged in to quay.io: false` und die Warnung `Server Pro enabled, but not logged in to quay.io repository`: Diese Prüfung stammt aus dem offiziellen Toolkit, bei dem das Server-Pro-Image in einer privaten quay.io-Registry liegt. Mit `SERVER_PRO=true` lädt das Toolkit `ghcr.io/ayaka-notes/overleaf-pro`, das öffentlich ist, sodass keine Anmeldung erforderlich ist. Ignorieren Sie diese Warnung.
* `grep: /root/.docker/config.json: No such file or directory` (oder ein anderes Home-Verzeichnis): Die quay.io-Prüfung sucht in dieser Datei nach `quay.io`. Docker legt sie nur an, wenn Einstellungen zu speichern sind, zum Beispiel nach `docker login`, daher fehlt sie auf vielen Servern. Sie wird nicht benötigt.
* `perl: warning: Setting locale failed`: Das Toolkit verwendet `perl` nur hier, in `bin/doctor`, um dessen Version auszugeben, und Perl warnt, wenn `LANG` oder `LC_ALL` eine Locale angibt, die auf dem Host nicht installiert ist. Die Version wird trotzdem ausgegeben. Um die Warnung zu unterdrücken, setzen Sie diese Variablen auf eine von `locale -a` aufgeführte Locale, zum Beispiel `C.UTF-8`.

Warnungen wie `Docker daemon is not running`, `docker not found`, `Docker Compose not found` oder eine fehlende Datei in `config/` müssen dagegen behoben werden: Ohne sie kann das Toolkit nicht starten.

</Accordion>
