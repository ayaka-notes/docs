title: Grundlegende Verwaltung
description: Systemmeldungen veröffentlichen, offene Sockets ansehen und den Editor für Wartungsarbeiten schließen oder wieder öffnen.

---

Klicken Sie auf **Admin** und dann auf **Manage Site**. Das **Admin Panel** hat drei Tabs: **System Messages**, **Open Sockets** und **Open/Close Editor**.

## Systemmeldungen {#system-messages}

Eine Systemmeldung ist ein blaues Banner oben auf der Seite **Projects** und im Editor. Alle Benutzer sehen sie.

### Eine Meldung veröffentlichen {#post-a-message}

Geben Sie den Text unter **Message** ein und klicken Sie auf **Post Message**. Der Tab listet die Meldungen auf, die gerade angezeigt werden.

<Frame caption="Zwei veröffentlichte Meldungen">
  <img src="/images/on-premises/basic-management-posted.png" alt="Der Tab System Messages mit zwei veröffentlichten Meldungen über dem Feld Message, der Schaltfläche Post Message und der Schaltfläche Clear all messages" />
</Frame>

<Frame caption="Was Benutzer sehen">
  <img src="/images/on-premises/basic-management-user-projects.png" alt="Die Seite Projects eines Benutzers mit den zwei Meldungen als blaue Banner oben" />
</Frame>

* Ein Benutzer kann eine Meldung mit dem <strong>×</strong> schließen. Sie bleibt in diesem Browser geschlossen.
* Eine bereits geöffnete Seite prüft alle 15 Minuten auf neue Meldungen. Nach dem Neuladen der Seite erscheinen sie sofort.

### Meldungen entfernen {#remove-messages}

**Clear all messages** entfernt alle Meldungen auf einmal und fragt nicht nach einer Bestätigung. Eine einzelne Meldung können Sie nicht entfernen.

## Offene Sockets {#open-sockets}

Eine Diagnoseansicht der ausgehenden Verbindungen, die der Webdienst in diesem Moment geöffnet hat. Sie zeigt nicht, wer online ist: Die Liste kann leer sein, während Benutzer im Editor arbeiten.

## Den Editor für Wartungsarbeiten schließen {#close-the-editor-for-maintenance}

Verwenden Sie den Tab **Open/Close Editor**. Seine Schaltflächen wirken sofort und fragen nicht nach einer Bestätigung, und der Tab zeigt nicht an, ob der Editor geschlossen ist. Zur Prüfung klicken Sie auf **Projects**: Solange er geschlossen ist, sehen Sie die Seite **Maintenance**.

<Frame caption="Der Tab Open/Close Editor">
  <img src="/images/on-premises/basic-management-open-close.png" alt="Der Tab Open/Close Editor mit den Schaltflächen Close Editor, Disconnect all users und Reopen Editor" />
</Frame>

<Steps>
<Step id="tell-your-users" title="Ihre Benutzer informieren">
[Veröffentlichen Sie eine Meldung](/de/on-premises/user-guide/administrators/basic-management#post-a-message) mit dem Zeitpunkt der Wartung.
</Step>

<Step id="click-close-editor" title="Auf Close Editor klicken">
Trotz des Namens schließt dies fast die gesamte Website. Jede Seite außer dem Admin-Panel zeigt **Maintenance**, einschließlich **Projects**, **Account Settings**, **Templates** und der Anmeldeseite. **Manage Users** und **Project/Object Lookup** funktionieren weiterhin.

<Frame caption="Was Benutzer sehen, während der Editor geschlossen ist">
  <img src="/images/on-premises/basic-management-closed-page.png" alt="Die Seite Maintenance mit dem Hinweis, dass die Instanz gerade gewartet wird" />
</Frame>

Benutzer, die den Editor bereits geöffnet haben, bleiben verbunden. Sie können weiter tippen, und ihre Änderungen bleiben erhalten, aber **Recompile** endet mit **Server Error**.

Wie Sie den Text dieser Seite ändern, lesen Sie unter [Wartungsseite](/de/on-premises/configuration/overleaf-toolkit/branding#maintenance-page).
</Step>

<Step id="click-disconnect-all-users" title="Auf Disconnect all users klicken">
Benutzer im Editor sehen den Dialog **Please wait**, der von 10 Sekunden herunterzählt. Danach wird ihre Seite aktualisiert und zeigt **Maintenance**.

<Frame caption="Was Benutzer im Editor sehen">
  <img src="/images/on-premises/basic-management-disconnect-dialog.png" alt="Der Editor hinter dem Dialog Please wait, der angibt, dass der Editor in 8 Sekunden automatisch aktualisiert wird" />
</Frame>

Schließen Sie zuerst den Editor: Andernfalls bringt die Aktualisierung die Benutzer direkt zurück in den Editor.
</Step>

<Step id="do-the-maintenance-then-click-reopen-editor" title="Die Wartung durchführen und dann auf Reopen Editor klicken">
Alle Seiten funktionieren sofort wieder. Benutzer laden die Seite neu, um weiterzuarbeiten.
</Step>
</Steps>

<Warning>

Auch die Anmeldeseite ist geschlossen. Bleiben Sie daher angemeldet, bis Sie den Editor wieder geöffnet haben. Wenn Sie ausgesperrt sind, starten Sie die Instanz neu: Der geschlossene Zustand wird nur im Arbeitsspeicher gehalten, daher öffnet ein Neustart den Editor wieder.

</Warning>

<Info>

Auf Kubernetes mit mehreren Replikaten schließt **Close Editor** nur das Replikat, das Ihre Anfrage bearbeitet hat. Verwenden Sie stattdessen den [Wartungsmodus](/de/on-premises/configuration/kubernetes/branding#maintenance-mode).

</Info>
