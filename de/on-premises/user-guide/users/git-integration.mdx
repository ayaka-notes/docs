Bearbeiten Sie ein Projekt mit Git auf Ihrem eigenen Computer. Änderungen werden nur übertragen, wenn Sie `git pull` oder `git push` ausführen.

<Info>

Ein Administrator muss zuerst die [Git-Integration](/de/on-premises/configuration/overleaf-toolkit/integrations/git-integration) aktivieren.

</Info>

## Ein Token erstellen {#create-a-token}

Git meldet sich mit einem Git-Authentifizierungstoken an, nicht mit Ihrem Kontopasswort.

<Steps>
<Step title="Kontoeinstellungen öffnen">
Klicken Sie auf **Account** und dann auf **Account settings**. Klicken Sie unter **Git integration** auf **Generate token**. Sobald Sie ein Token haben, heißt diese Schaltfläche **Add another token**.

<Frame caption="Git-Integration in den Kontoeinstellungen">
  <img src="/images/on-premises/git-integration-settings.png" alt="Der Abschnitt Git integration der Kontoeinstellungen mit der Schaltfläche Generate token" />
</Frame>
</Step>

<Step title="Token kopieren">
Klicken Sie auf **Copy** und bewahren Sie das Token an einem sicheren Ort auf. Sie sehen es nur einmal. Klicken Sie dann auf **Close**.

<Frame caption="Ihr neues Token">
  <img src="/images/on-premises/git-integration-token.png" alt="Der Dialog mit dem Git-Authentifizierungstoken und der Schaltfläche Copy" />
</Frame>
</Step>

<Step title="Token prüfen">
Die Liste zeigt jetzt den Anfang des Tokens, wann es erstellt und wann es zuletzt verwendet wurde. Es läuft nach einem Jahr ab. Sie können bis zu 10 Tokens haben.

<Frame caption="Ihre Tokens">
  <img src="/images/on-premises/git-integration-tokens.png" alt="Die Liste der Tokens mit einem Token" />
</Frame>
</Step>
</Steps>

## Ein Projekt klonen {#clone-a-project}

<Steps>
<Step title="Git-Integration im Editor öffnen">
Öffnen Sie das Projekt. Klicken Sie in der linken Leiste auf **Integrations** und dann auf **Git integration**.

<Frame caption="Das Panel Integrations">
  <img src="/images/on-premises/git-integration-panel.png" alt="Das Panel Integrations mit der Karte Git integration" />
</Frame>
</Step>

<Step title="Befehl kopieren">
Der Dialog **Clone with Git** zeigt den Befehl mit der Adresse Ihrer Website und der ID des Projekts. Klicken Sie auf **Copy**. Wenn Sie noch kein Token haben, öffnet **Go to settings** Ihre Kontoeinstellungen in einem neuen Tab.

<Frame caption="Der Klon-Befehl">
  <img src="/images/on-premises/git-integration-clone.png" alt="Der Dialog Clone with Git mit dem Befehl git clone" />
</Frame>
</Step>

<Step title="Befehl ausführen">
Fügen Sie den Befehl in ein Terminal ein. Wenn Git nach einem Passwort fragt, fügen Sie Ihr Token ein.

```text
$ git clone https://git@<your-site>/git/<project-id>
Cloning into '<project-id>'...
Password for 'https://git@<your-site>': <your-token>
```

Ein Ordner, der nach der Projekt-ID benannt ist, enthält jetzt die Dateien des Projekts auf dem Branch `main`. Um den Namen des Ordners selbst zu wählen, hängen Sie ihn an das Ende des Befehls an.
</Step>
</Steps>

Git fragt bei jeder Verbindung mit der Website nach dem Token. Damit es gespeichert wird, aktivieren Sie einen Credential Helper: Git fragt noch einmal und behält das Token dann. Der Helper `store` speichert es unverschlüsselt in `~/.git-credentials`.

```bash
git config --global credential.helper store
```

## Änderungen aus dem Editor abrufen {#pull-changes-from-the-editor}

Führen Sie im Ordner Folgendes aus:

```bash
git pull
```

Git listet die geänderten Dateien auf. Änderungen aus dem Editor kommen als Commits mit dem Namen `Update on Overleaf.` an.

```text
Updating db007e3..c3e6332
Fast-forward
 main.tex | 2 +-
 1 file changed, 1 insertion(+), 1 deletion(-)
```

## Ihre Änderungen hochladen {#push-your-changes}

Committen Sie Ihre Änderungen und pushen Sie sie dann:

```bash
git add main.tex
git commit -m "Add a line from Git"
git push
```

Die letzte Zeile der Ausgabe zeigt den Branch, der sich bewegt hat:

```text
   53aca61..db007e3  main -> main
```

Die Änderungen erscheinen im Editor, und ein geöffneter Editor aktualisiert sich von selbst. Neue Dateien, Ordner und Umbenennungen erscheinen im Dateibaum. In **History** ist Ihre Änderung mit <strong>You (via Git)</strong> markiert. Ihre Commit-Nachricht wird dort nicht angezeigt.

### Wenn Git Ihren Push ablehnt {#if-git-refuses-your-push}

Wenn sich das Projekt in der Zwischenzeit geändert hat, lehnt Git den Push ab:

```text
 ! [rejected]        main -> main (fetch first)
```

Holen Sie zuerst diese Änderungen und pushen Sie dann erneut:

```bash
git pull --no-rebase --no-edit
git push
```

Ein einfaches `git pull` kann mit `fatal: Need to specify how to reconcile divergent branches.` abbrechen. Die Option `--no-rebase` oben beantwortet das: Sie führt die beiden Seiten zusammen.

Wenn sich auf beiden Seiten dieselben Zeilen geändert haben, stoppt der Pull mit `CONFLICT (content): Merge conflict in main.tex`. Korrigieren Sie die Datei und führen Sie dann aus:

```bash
git add main.tex
git commit -m "Merge the changes from the editor"
git push
```

Zwei Dinge akzeptiert die Website nicht:

* Andere Branches: `! [remote rejected] feature -> feature (wrong branch)`. Es gibt nur `main`, also pushen Sie Ihre Arbeit dorthin.
* Force Pushes: `! [remote rejected] main -> main (forced push prohibited)`. Setzen Sie Ihre Änderungen stattdessen auf den aktuellen Stand von `main`.

### Wenn Git Authentication failed meldet {#if-git-says-authentication-failed}

```text
remote: Enter your Git authentication token when prompted for a password.
fatal: Authentication failed for 'https://<your-site>/git/<project-id>/'
```

Das Token ist falsch oder wurde gelöscht, oder Sie haben Ihr Kontopasswort eingegeben. Erstellen Sie ein neues Token, wenn Sie es nicht mehr haben, denn ein vorhandenes Token können Sie nicht erneut ansehen.

## Ein Token löschen {#delete-a-token}

Klicken Sie in **Account settings** unter **Git integration** auf das Löschsymbol neben dem Token und dann im Dialog auf **Delete**. Danach antwortet Git auf dieses Token mit `Authentication failed`.
