Es ist möglich, ein bestehendes TeX Live-Image mithilfe eines neuen Dockerfiles zu erweitern und die Anwendung so zu konfigurieren, dass sie das neue Image verwendet.

Hier geben wir einige Hinweise zur Installation neuer Pakete oder Schriften. Die Konfiguration eines benutzerdefinierten Images ist jedoch nicht durch unsere Supportbedingungen abgedeckt.

Die TeX Live-Images werden nur selten aktualisiert. Wir empfehlen, benutzerdefinierte Images beim Upgrade von Server Pro neu zu bauen.

<Danger>

Die folgenden Abschnitte gelten nur für Server Pro und [Sandboxed Compiles](/de/on-premises/configuration/overleaf-toolkit/sandboxed-compiles).

</Danger>

### Neue Pakete installieren und aktualisieren

Sie können `tlmgr`-Befehle wie `tlmgr install` und `tlmgr update` verwenden, um TeX Live-Pakete zu verwalten, wie im folgenden Beispiel:

```dockerfile
FROM ghcr.io/ayaka-notes/texlive-full:2023.1

RUN tlmgr update --force ebproof
```

### `tlmgr` in einem älteren TeX Live-Image verwenden

Standardmäßig lädt `tlmgr` Ressourcen aus der neuesten TeX Live-Version herunter. Wenn Sie ein älteres TeX Live-Image anpassen, müssen die Downloads auf das jeweilige Archiv umgestellt werden. Eine Liste der Archiv-Mirrors finden Sie unter [https://www.tug.org/historic/](https://www.tug.org/historic/).

```dockerfile
FROM ghcr.io/ayaka-notes/texlive-full:2022.1

RUN tlmgr option repository <MIRROR>/systems/texlive/<YEAR>/tlnet-final
# e.g. RUN tlmgr option repository ftp://tug.org/historic/systems/texlive/2022/tlnet-final

RUN tlmgr update --force ebproof
```

### Neue Schriften installieren

Es gibt verschiedene Verfahren, um neue Schriften in einer TeX Live-Distribution zu installieren, und die Installation einer benutzerdefinierten Schrift kann mehrere Schritte erfordern. Die [Anleitung zur Installation von TeX-Schriften](https://tug.org/fonts/fontinstall.html) in der offiziellen TeX Live-Dokumentation ist dafür vermutlich ein guter Ausgangspunkt.

Das folgende `Dockerfile` zeigt ein Beispiel für die Installation einer TrueType-Schrift auf einem bestehenden TeX Live 2022-Image:

```dockerfile
FROM ghcr.io/ayaka-notes/texlive-full:2022.1

COPY ./myfonts/*.ttf /usr/share/fonts/truetype/myfont/

# rebuild font information cache
RUN fc-cache
```

### Server Pro für die Verwendung der neuen Images konfigurieren

Verwenden Sie den Namen `ghcr.io/ayaka-notes/texlive-full` und einen benutzerdefinierten Tag, um das neue Image zu bauen, zum Beispiel:

```bash
docker build -t ghcr.io/ayaka-notes/texlive-full:2023.1-custom
```

Nun können wir Server Pro so konfigurieren, dass es das neue Image `2023.1-custom` verwendet, indem wir die Umgebungsvariablen `TEX_LIVE_DOCKER_IMAGE` und `ALL_TEX_LIVE_DOCKER_IMAGES` aktualisieren:

```text wrap
TEX_LIVE_DOCKER_IMAGE: "ghcr.io/ayaka-notes/texlive-full:2023.1-custom"
ALL_TEX_LIVE_DOCKER_IMAGES: "ghcr.io/ayaka-notes/texlive-full:2023.1,ghcr.io/ayaka-notes/texlive-full:2023.1-custom"
```

Im obigen Beispiel verwenden neue Projekte standardmäßig das neue Image `2023.1-custom`, während `2023.1` bei Bedarf weiterhin verfügbar ist.
