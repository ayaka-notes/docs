---
title: Projekte exportieren
icon: file-export
---

In Server Pro und Community Edition `5.4.0` haben wir ein Skript aufgenommen, mit dem Administratoren alle Benutzerprojekte (einschließlich derjenigen, die noch in den Ordnern **Deleted** und **Trashed** sichtbar sind) in ein Verzeichnis auf der Festplatte exportieren können.

<Info>

Die Ausgabe dieses Skripts entspricht dem manuellen Herunterladen aller Projekte als Zip-Datei aus dem Projekt-Dashboard des Benutzers. Das Skript schreibt alle ausstehenden Änderungen weg, bevor der Download beginnt, damit der Export die neueste Version des Projekts enthält.

</Info>

### Einschränkungen

Das Exportskript unterliegt den folgenden Einschränkungen:

* Projekteinstellungen wie der Name des TeX Live-Images oder der Compiler werden nicht exportiert. Diese müssen festgelegt werden, wenn das Projekt in das Konto des Benutzers hochgeladen wird.
* Exportierte Projekte enthalten keinen Versionsverlauf.
* Informationen zu Mitarbeitenden bleiben nicht erhalten. Projekte müssen erneut geteilt werden. Bei Verwendung der Link-Freigabe werden Ansichts- und Bearbeitungslinks neu generiert (sie sind nicht mehr dieselben wie zuvor).
* Kommentare und Informationen zu nachverfolgten Änderungen werden nicht exportiert.
* Der Chatverlauf des Projekts wird nicht exportiert.

<Danger>

Dieses Skript ist **nicht** dafür gedacht, eine vollständige Systemsicherung zu ersetzen. Damit Sie Ihre Instanz im Notfall wiederherstellen können, empfehlen wir **dringend**, eine [konsistente Sicherung](https://docs.overleaf.com/on-premises/maintenance/#performing-a-consistent-backup) zu erstellen.

</Danger>

### **Flags**

| Name           | Beschreibung                                                                     |
| -------------- | ------------------------------------------------------------------------------- |
| `--help`       | Hilfe anzeigen                                                                       |
| `--user-id`    | Die Benutzer-ID (erforderlich, außer bei Verwendung von `--export-all` oder `--project-id`)            |
| `--project-id` | Ein einzelnes Projekt exportieren (kann **nicht** mit `--user-id` oder `--export-all` verwendet werden) |
| `--list`       | Projekte des Benutzers auflisten (kann **nicht** mit `--output` verwendet werden)                       |
| `--output`     | Ausgabe-Zip-Datei (für einzelne Exportvorgänge)                                  |
| `--export-all` | Projekte aller Benutzer exportieren (erfordert `--output-dir`)                            |
| `--output-dir` | Verzeichnis zum Speichern der Exportdateien aller Benutzer                                   |
| `--log-level`  | Unterstützte Log-Level: `trace`\|`debug`\|`info`\|`warn`\|`error`\|`fatal`       |

### **Verwendung**

Verwenden Sie den folgenden Befehl, um die Projekte aller Benutzer zu exportieren:

```bash wrap
# Overleaf Toolkit users
$ bin/docker-compose exec sharelatex /bin/bash -ce "cd /overleaf/services/web && node modules/server-ce-scripts/scripts/export-user-projects.mjs --export-all --output-dir=/var/lib/overleaf/data/exports"

# Legacy docker-compose.yml users
docker exec sharelatex /bin/bash -ce "cd /overleaf/services/web && node modules/server-ce-scripts/scripts/export-user-projects.mjs --export-all --output-dir=/var/lib/overleaf/data/exports"
```

<Info>

Wenn Sie Server Pro oder Community Edition &lt;= 3.5.13 verwenden, müssen Sie das obige Beispiel so anpassen, dass das Skript **`export-legacy-user-projects.js`** verwendet wird.

</Info>

### **Abschluss**

Sobald der Export abgeschlossen ist, können Sie auf die Dateien über das Verzeichnis auf dem Host zugreifen, das in Ihrer Datei **docker-compose.yml** per Bind-Mount nach **/var/lib/overleaf** eingebunden ist, bzw. über die Umgebungsvariable `OVERLEAF_DATA_PATH` in der Datei **config/overleaf.rc**, wenn Sie das Toolkit verwenden.

<Info>

Overleaf erlaubt derzeit doppelte Projektnamen. Wenn ein Benutzer Projekte mit gleichem Namen hat, werden diese zwar dennoch in den Zip-Export des Benutzers aufgenommen, beim Entpacken ist jedoch nur eine Version vorhanden. Unter Linux schreibt `unzip -B` Dateien mit gleichem Namen als Sicherungsdateien, anstatt sie zu überschreiben.

</Info>
