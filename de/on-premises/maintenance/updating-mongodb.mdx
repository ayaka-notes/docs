<Info>

Jede neue Version von Server CE/Server Pro weist in ihren [Release Notes](https://docs.overleaf.com/on-premises/release-notes) auf Änderungen der unterstützten MongoDB-Version hin.

</Info>

### Sollte ich MongoDB aktualisieren?

Sie sollten eine Aktualisierung Ihrer MongoDB-Version **nur** in Betracht ziehen, wenn Sie planen, Ihre Server CE/Server Pro-Instanz zu aktualisieren.

Wenn Sie eine MongoDB-Version verwenden, die neuer ist als die für Ihre aktuelle (oder angestrebte) Version empfohlene, sind keine Änderungen erforderlich.

<Warning>

Sie sollten Ihre MongoDB-Version niemals herabstufen.

</Warning>

Wenn Sie ein bestimmtes Problem haben, das Ihrer Meinung nach mit Ihrer aktuellen MongoDB-Version zusammenhängt, können Sie gerne [ein Issue erstellen](https://github.com/overleaf/overleaf/issues), wenn Sie Server CE nutzen, oder sich an den Overleaf-Support wenden, wenn Sie Server Pro nutzen.

### Ablauf der Aktualisierung

Die Aktualisierung der MongoDB-Version im Rahmen eines Upgrades Ihrer Server CE/Server Pro-Instanz läuft wie folgt ab:

1. Legen Sie fest, auf welche Version von Server CE/Server Pro Sie upgraden möchten.
2. Ermitteln Sie die MongoDB-Version, die für dieses konkrete Overleaf Server CE/Server Pro-Release empfohlen wird.
3. Folgen Sie den Anweisungen, um MongoDB auf die Zielversion zu aktualisieren.
4. Aktualisieren Sie die Image-Version von Server CE/Server Pro und starten Sie die Instanz neu.

Wir empfehlen, **Server CE/Server Pro** immer auf die neueste verfügbare Version zu aktualisieren, da deren Unterstützung stets garantiert ist (nur für Server Pro-Nutzer).

<Danger>

Bei einem Upgrade von Server CE/Pro empfehlen wir, zunächst auf das neueste Release der bereitgestellten Hauptversion zu aktualisieren, **bevor** Sie auf das neueste Release der **nächsten** Hauptversion upgraden. Liegt Ihre Bereitstellung mehr als eine Hauptversion hinter der neuesten zurück, müssen Sie ein mehrstufiges Upgrade durchführen.

Wenn Sie beispielsweise 3.5.10 verwenden, müssen Sie auf 3.5.13 upgraden -> die Migration des vollständigen Projektverlaufs durchführen -> 4.2.9 -> 5.5.4.

Sie sollten **niemals** Hauptversionen überspringen (3.5.10 -> 5.5.4). Wenn Sie das Toolkit verwenden und mehr als eine Hauptversion hinter der neuesten liegen, dürfen Sie das Skript `bin/upgrade` **nicht** verwenden, da Sie ein manuelles, mehrstufiges Upgrade durchführen müssen.

</Danger>

<Warning>

Es ist wichtig, **vor** jedem Hauptversions-Upgrade ein [konsistentes Backup](/de/on-premises/maintenance/data-and-backups#performing-a-consistent-backup) zu erstellen, damit Sie bei Bedarf ein Rollback durchführen können.

</Warning>

#### MongoDB upgraden

MongoDB erfordert **schrittweise Upgrades**. Das bedeutet, dass Sie nicht direkt von beispielsweise `4.0` auf `5.0` wechseln können. Sie müssen zunächst von `4.2` auf `4.4` und anschließend auf `5.0` aktualisieren.

<Info>

MongoDB verwendet gerade Versionsnummern für stabile Versionen.

</Info>

**Grundlegende Anweisungen**

In den meisten Fällen erfordert die Aktualisierung das Setzen eines Kompatibilitäts-Flags, bevor die Mongo-Version tatsächlich aktualisiert wird. Die Schritte sind wie folgt:

1. Setzen Sie das Kompatibilitäts-Flag wie in den MongoDB-Release-Notes beschrieben (siehe Beispiele unten).
2. Aktualisieren Sie anschließend das Mongo-Image:
   1. **Toolkit-Nutzer** Aktualisieren Sie `MONGO_VERSION`, z. B. `MONGO_VERSION=6.0`
   2. **Docker Compose-Nutzer** Aktualisieren Sie die Version des `mongo`-Image-Tags,\
      z. B. `services -> mongo -> image: mongo:6.0`;

**Beispiel: Upgrade von MongoDB `5.0` auf `6.0`**

Stellen wir zunächst sicher, dass wir MongoDB `6.0` ausführen:

Nutzer des Overleaf Toolkit:

```bash
bin/docker-compose exec mongo mongod --version
# db version v5.0.24
```

Nutzer von Docker Compose:

```bash
docker compose exec mongo mongod --version
# db version v5.0.24
```

Laut den [Upgrade-Anweisungen](https://docs.mongodb.com/manual/release-notes/3.6-upgrade-standalone/#upgrade-version-path) besteht die einzige Voraussetzung darin, `featureCompatibilityVersion` auf `5.0` zu setzen. Dazu öffnen wir eine MongoDB-Shell und führen den angegebenen Befehl aus:

Nutzer des Overleaf Toolkit:

```bash
bin/mongo
# MongoDB shell version v5.0.24
# ...
# overleaf:PRIMARY> db.adminCommand( { setFeatureCompatibilityVersion: "5.0" } )
# { 
# "ok" : 1,
# ...
# }
overleaf:PRIMARY> exit
# bye
```

<Info>

Docker Compose-Nutzer können `docker compose exec mongo mongosh` ausführen, um eine Shell zu öffnen, und dieselben Befehle wie Toolkit-Nutzer ausführen.

</Info>

Nutzer des Overleaf Toolkit:

Anschließend stoppen wir die Server CE/Server Pro- und MongoDB-Instanzen mit dem Befehl `bin/stop`, setzen `MONGO_VERSION=6.0` in `config/overleaf.rc` und starten dann den Dienst `mongo` mit `bin/up mongo` neu, um zu überprüfen, ob die Aktualisierung reibungslos verlaufen ist.

Abschließend aktualisieren wir die Image-Version von Server CE/Server Pro auf unsere Zielversion und erstellen alle Dienste mit dem Befehl `bin/up -d` neu.

Nutzer von Docker Compose:

Anschließend stoppen wir die Server CE/Server Pro- und MongoDB-Instanzen mit dem Befehl `docker compose stop`, passen die Datei [`docker-compose.yml`](https://github.com/overleaf/overleaf/blob/4b1babd4ea634ab12c54e9a9aea7db0e8a500941/docker-compose.yml) so an, dass `image: mongo:6.0` verwendet wird, und starten dann den Dienst `mongo` mit dem Befehl `docker compose up mongo` neu, um zu überprüfen, ob die Aktualisierung reibungslos verlaufen ist.

Abschließend aktualisieren wir die Image-Version von Server CE/Server Pro auf unsere Zielversion und erstellen alle Dienste mit dem Befehl `docker compose up` neu.

#### Entsprechende Befehle für Docker Compose-Nutzer

Für Docker Compose-Nutzer lauten die entsprechenden Befehle:

* `docker compose exec mongo mongod --version`, um die Mongo-Version anzuzeigen
* `docker compose exec mongo mongosh`, um eine Mongo-Shell für Admin-Befehle zu starten
* `docker compose stop`, um den Server zu stoppen
* Bearbeiten Sie die Datei [`docker-compose.yml`](https://github.com/overleaf/overleaf/blob/4b1babd4ea634ab12c54e9a9aea7db0e8a500941/docker-compose.yml) so, dass `image: mongo:6.0` verwendet wird, um die Mongo-Version zu aktualisieren
* `docker compose up mongo`, um den Mongo-Dienst neu zu starten und zu überprüfen, ob die Aktualisierung reibungslos verlaufen ist
* Bearbeiten Sie die Datei [`docker-compose.yml`](https://github.com/overleaf/overleaf/blob/4b1babd4ea634ab12c54e9a9aea7db0e8a500941/docker-compose.yml) so, dass `image: sharelatex:VERSION` verwendet wird, um die Image-Version zu aktualisieren
* `docker compose up`, um alle Dienste neu zu erstellen.

### Eine benutzerdefinierte Rolle erstellen

In Version `5.5.1` haben wir eine Startprüfung eingeführt, die die Feature Compatibility Version von MongoDB überprüft. Wenn Ihre MongoDB-Datenbank Authentifizierung verwendet (z. B. Basic Authentication), startet der Container `sharelatex` möglicherweise nicht und zeigt den Berechtigungsfehler „_not authorized on admin to execute command_“ an.

Um dies zu beheben, können Sie entweder mithilfe der folgenden Anweisungen eine neue Rolle in MongoDB erstellen und sie dem Benutzerkonto zuweisen, das für den Datenbankzugriff verwendet wird, oder `ALLOW_MONGO_ADMIN_CHECK_FAILURES=true` setzen, damit die Prüfung fehlschlagen darf, ohne den Start der Bereitstellung zu verhindern.

<Check>

Diese neue Rolle gewährt **ausschließlich** die Berechtigung, clusterweite MongoDB-Serverparameter zu lesen, und kann auch für Monitoring-Zwecke wiederverwendet werden.

</Check>

```bash wrap
# Toolkit users
$ bin/docker-compose exec -it mongo mongosh -u {{YOUR-ADMIN-USERNAME}} -p

# Switch to the "admin" database using
overleaf [direct: primary] sharelatex> use admin
switched to db admin
overleaf [direct: primary] admin> 

# Create a new role with permission to use "getParamter". Copy and paste the function below into the shell and press the return key

db.createRole(
  {
    role: "clusterParameterReader",
    privileges: [
      {
        resource: { cluster: true },
        actions: ["getParameter"]    
      }
    ],
    roles: [] 
  }
);

# Switch back to the "sharelatex" database 
use sharelatex
switched to db sharelatex
overleaf [direct: primary] sharelatex> 

# Assign the new "clusterParameterReader" role to your database user by copy and pasting the function below into the shell and press the return key 
db.grantRolesToUser(
  "{{YOUR-DATABASE-USER}}",
  [
    { role: "clusterParameterReader", db: "admin" }
  ]
);

# Type exit then return to exit the MongoDB shell
# Run bin/up -d to start the deployment stack
$ bin/up -d
```
