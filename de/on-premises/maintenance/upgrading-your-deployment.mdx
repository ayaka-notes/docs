<Danger>

Es ist wichtig, dass Sie **vor** jedem Upgrade auf eine neue Hauptversion ein [konsistentes Backup](/de/on-premises/maintenance/data-and-backups#performing-a-consistent-backup) erstellen, damit Sie bei Bedarf zurückkehren können.

</Danger>

Das [Ayakaleaf-Toolkit↗](https://github.com/ayaka-notes/toolkit) ist ein Git-Repository, sodass Sie neue Toolkit-Funktionen ganz einfach erhalten. Führen Sie einfach den Befehl `bin/upgrade` aus und folgen Sie den Anweisungen auf dem Bildschirm.

Beachten Sie, dass die Version des Docker-Images (in `config/version`) getrennt von den Codeaktualisierungen des Toolkits verwaltet wird. Eine Aktualisierung des Toolkit-Codes ändert **nicht** automatisch die Version des Docker-Images, das Sie ausführen. In den meisten Fällen können Sie also Ihre Toolkit-Version aktualisieren, ohne Ihr Deployment zu aktualisieren.

#### Das Skript `bin/upgrade`

Wenn Sie den Befehl `bin/upgrade` ausführen, prüft das Skript, ob ein Update für den Toolkit-Code verfügbar ist, und bietet an, Ihr Toolkit zu aktualisieren. Sie können dieses Upgrade jederzeit ablehnen; dann ändert sich nichts.

Wenn Sie sich für die Aktualisierung des Toolkit-Codes entscheiden, prüft das Skript anschließend, ob sich die _standardmäßige_ Docker-Image-Version geändert hat, und bietet an, Ihre lokale Versionsdatei (in `config/version`) an den neuen Standard anzupassen.

Wenn Sie sich für einen Versionswechsel entscheiden, führt Sie das Skript durch das Herunterfahren der Docker-Dienste, das Erstellen eines Backups und den Neustart der Docker-Dienste. Ihre alte Versionsdatei wird automatisch nach `config/__old-version` kopiert, falls Sie zu dieser Version der Docker-Images zurückkehren müssen.

<Info>

Für Air-Gapped-Setups, bei denen Docker-Images manuell importiert werden, setzen Sie bitte `PULL_BEFORE_UPGRADE=false` in Ihrer Datei `config/overleaf.rc`.

Weitere Informationen zum Deployment in Air-Gapped-/Offline-Umgebungen finden Sie [hier](/de/on-premises/installation/air-gapped-offline-deployments).

</Info>

### Upgrade-Pfad

Wenn Sie eine ältere Version von Overleaf Community vor v6.0.0 verwenden, folgen Sie der [offiziellen Overleaf-Dokumentation](https://docs.overleaf.com/on-premises/maintenance/upgrading-your-deployment#upgrade-path), um das Upgrade abzuschließen.

Aktualisieren Sie innerhalb von Ayakaleaf Pro zuerst auf das neueste Patch-Release Ihrer aktuellen Versionslinie und dann auf die nächste, zum Beispiel `6.2.0 → 6.2.2 → 6.3.2`. Lesen Sie die [Release Notes](/de/on-premises/release-notes/release-notes-6.x.x) jeder Version, die Sie dabei durchlaufen, denn einige erfordern zusätzliche Schritte. Nur das neueste Release wird unterstützt.
