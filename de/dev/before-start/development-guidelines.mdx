### Einführung

Bevor Sie mit der Entwicklung beginnen, sollten Sie die folgenden Punkte verstehen:

* Overleaf wird offiziell in einem [internen Repository](http://github.com/overleaf/internal) entwickelt, und die Community Edition wird in [overleaf/overleaf](https://github.com/overleaf/overleaf) veröffentlicht. Ein Copybot ist dafür zuständig, den Code zwischen dem internen und dem öffentlichen Repository zu synchronisieren.
* [Ayaka-notes/overleaf-pro](https://github.com/ayaka-notes/overleaf-pro) ist ein Fork der Overleaf Community Edition. Wir möchten, dass dieses Projekt langfristig bestehen bleibt, daher beachten Sie bitte die folgenden Regeln, bevor Sie Beiträge leisten.

### Commit-Regeln

* Bitte nehmen Sie keine umfangreichen Änderungen am bestehenden Overleaf-Code vor. Konzentrieren Sie so viel Funktionalität wie möglich im Ordner `services/web/modules`. Dadurch minimieren wir unseren Aufwand beim späteren Zusammenführen und Aktualisieren des Codes.
* Vibe Coding ist zwar sehr bequem, kann unser Projekt aber leicht durcheinanderbringen und es später unwartbar machen. Setzen Sie es daher bitte mit Bedacht ein.
* Bitte fügen Sie während der Entwicklung keine übersetzungsbezogenen Inhalte hinzu; verwenden Sie nach Möglichkeit vorhandene Übersetzungen.
* Vermeiden Sie die Einführung von Umgebungsvariablen, sofern sie nicht unbedingt notwendig sind. Falls doch erforderlich, stellen Sie sicher, dass sie so weit wie möglich mit denen im Overleaf Toolkit oder auf [docs.overleaf.com](https://docs.overleaf.com/) übereinstimmen.

### Branch-Regeln

Für die Entwicklung von overleaf-pro verwenden wir die folgenden Branches:

* `main`: Dieser Branch wird ausschließlich für die Synchronisation des Upstream-Codes verwendet, bitte committen Sie hier **KEINE** externen Änderungen. In diesem Branch setzen wir Tags wie `ce-v[X.x.x]`, die angeben, dass dies `v[X.x.x]` der offiziellen Overleaf Community Edition entspricht. Hinweis: Dieser Tag ist unveränderlich!
* `server-pro`: Dieser Branch ist der Standard-Branch für die tägliche Entwicklung.
* `feature-X`: Dieser Branch dient der Entwicklung eines bestimmten Features.
* `release-vX.0.0`: Der Branch speziell für Releases; hier nehmen wir vor dem Release einige Hotfixes vor.

### GitHub Action

[GitHub Action](https://github.com/ayaka-notes/overleaf-pro/actions) ist für das automatische CI/CD zuständig, darunter:

* Nächtliche Aktualisierung des main-Branches
* Erstellen des Docker-Images für die Entwicklung
* Veröffentlichen des Docker-Images

### Fragen und Antworten

<Accordion title="Wie finde ich den Commit-Hash für Overleaf Community Edition `X.0.0`?">

Zunächst müssen Sie das Docker-Image herunterladen und mit dem folgenden Befehl die Labels in diesem Docker-Image untersuchen:

```shellscript title="bash" wrap
docker inspect --format='{{json .Config.Labels}}' sharelatex/sharelatex:6.0.0
{"com.overleaf.ce.revision":"b0d05c0cf0750714e1f467d20ed6c5f5e9467e8f","org.opencontainers.image.ref.name":"ubuntu","org.opencontainers.image.version":"24.04"}
```

Anschließend können Sie prüfen, ob der [Commit (b0d05c0)](https://github.com/overleaf/overleaf/commit/b0d05c0cf0750714e1f467d20ed6c5f5e9467e8f) im Upstream-master-Branch vorhanden ist.

</Accordion>

<Accordion title="Warum ist der Commit-Hash im CE-Image bei `6.0.0` und `6.0.1` identisch?">

Dies ist ein erwartetes Verhalten. Das Release 6.0.1 ist ein kleines Patch-Release, das auf dem 6.0.0-Image aufbaut. Die Änderungen werden durch Patchen des bestehenden 6.0.0-Images angewendet, anstatt das Image aus einem neuen Commit neu zu bauen. Daher ist der Commit-Hash im Image bei 6.0.0 und 6.0.1 identisch.

Ausführliche Informationen finden Sie unter [hotfix](https://github.com/overleaf/overleaf/tree/main/server-ce/hotfix).

</Accordion>
