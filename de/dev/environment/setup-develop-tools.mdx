## Empfohlene Entwicklungswerkzeuge {#develop-tools-recommended}

Diese optionalen Dienste werden für den Betrieb von Overleaf nicht benötigt, helfen aber sehr beim Entwickeln, Debuggen und beim Untersuchen der Daten. Alle sind Teil der Entwicklungsumgebung, daher muss nichts zu `docker-compose.yml` hinzugefügt werden. Sobald Sie auf der Website angemeldet sind, verlinkt das Menü **Dev tools** in deren Navigationsleiste auf die Tools, die die Website unter eigenen Pfaden bereitstellt.

| Tool | Adresse | Definiert in |
| --- | --- | --- |
| **Grafana**, Zustand, Metriken und Logs aller Dienste | [http://localhost/grafana/](http://localhost/grafana/) | `develop/grafana/docker-compose.yml`, aktiv bei `GRAFANA_ENABLED=true` in `develop/dev.rc` (Standard) |
| **Mailpit**, ein Posteingang für jede E-Mail, die die Website versendet | [http://localhost/mailpit/](http://localhost/mailpit/) | `develop/mail/docker-compose.yml`, aktiv bei `MAILPIT_ENABLED=true` (Standard) |
| **Mongo Express**, eine Oberfläche für MongoDB | [http://localhost/mongo-express/](http://localhost/mongo-express/) | `develop/docker-compose.yml`, immer aktiv |
| **RedisInsight**, eine Oberfläche für die Redis-Daten | [http://localhost/redis-insight/](http://localhost/redis-insight/) | `develop/docker-compose.yml`, immer aktiv |
| **Hoppscotch**, ein browserbasierter API-Client ähnlich wie Postman | [http://localhost:9170](http://localhost:9170/) (`HOPPSCOTCH_PORT`) | `develop/hoppscotch/docker-compose.yml`, aktiv bei `HOPPSCOTCH_ENABLED=true` (Standard) |

<Warning>

Keines dieser Tools hat eine Anmeldung: Die anonymen Benutzer von Grafana sind dessen Admins, und Mongo Express kann jedes Dokument ändern. Die Website, Hoppscotch, Mongo Express (8081) und RedisInsight (5540) lauschen nur auf `127.0.0.1` des Hosts, sodass andere Hosts sie nicht erreichen können.

</Warning>

### Grafana {#grafana}

Grafana wird von der Website unter `/grafana/` über webpack-dev-server bereitgestellt und braucht daher keinen eigenen Port. Sein Ordner **Overleaf Develop** enthält diese Dashboards:

| Dashboard | Was es zeigt |
| --- | --- |
| All services (Startseite) | Zustand jedes Dienstes, Host-Anzeigen, Last und Logs. Ein Klick auf einen Dienst öffnet dessen Dashboard |
| Server | CPU, Last, Speicher, Festplatte und Netzwerk des Hosts sowie die Kompilierungen von clsi |
| Errors | Fehler-Logs, 5xx- und 4xx-Antworten, häufigste Fehlermeldungen und fehlschlagende Routen |
| Data flow | Der Weg einer Bearbeitung: document-updater und Redis, project-history, history-v1, Mongo, Objektspeicher |
| Containers | Zustand jedes Containers, CPU, Speicher, Netzwerk und Festplatte, einschließlich der Sandbox-Kompilierungen |
| Eines pro Dienst | Die Node.js-Dienste, git-bridge (JVM), mongo und redis |

Prometheus fragt `/metrics` der Dienste, `mongodb-exporter`, `redis-exporter`, `cadvisor` und `node-exporter` ab; Alloy sendet die Logs jedes Containers des Projekts an Loki, wo die Filter **Log search**, **Service** und **Log level** der Dashboards sie lesen. Ihre Daten liegen nur in den Containern, daher werden sie beim Neuerstellen geleert. cAdvisor läuft privilegiert und liest `/`, `/sys`, die Docker-Daten und den containerd-Socket des Hosts schreibgeschützt; node-exporter liest `/` des Hosts.

Die Dashboards werden generiert: Ändern Sie `develop/grafana/make-dashboards` und führen Sie es aus, anstatt die JSON-Dateien zu bearbeiten.

### Mailpit {#mailpit}

Mit `MAILPIT_ENABLED=true` sendet `web` jede E-Mail an Mailpit statt an einen echten Mailserver, und die E-Mail-Bestätigung ist aktiv (`EMAIL_CONFIRMATION_DISABLED=false`). Aktivierungslinks, Projekteinladungen, Passwortzurücksetzungen und Bestätigungscodes lassen sich dann aus dem Posteingang heraus aufrufen.

<Frame caption="Eine Aktivierungs-E-Mail, eine Projekteinladung, ein Bestätigungscode und eine Passwortzurücksetzung in Mailpit">

### Hoppscotch einrichten {#setup-hoppscotch}

#### API-Anfragen über einen Proxy {#proxy-api-request}

Hoppscotch sendet Anfragen aus dem Browser, der die Dienste nicht über ihre Docker-Namen erreichen kann. Sein Proxy, Proxyscotch, läuft im Docker-Netzwerk und wird unter `/proxy` der Hoppscotch-Adresse bereitgestellt. Öffnen Sie [http://localhost:9170](http://localhost:9170/), gehen Sie zu Settings → Interceptor, wählen Sie **Proxy** und setzen Sie die Proxy URL auf `http://localhost:9170/proxy`. Die Einstellung bleibt im Browser gespeichert.

#### Die Service-APIs importieren {#import-the-service-apis}

`develop/hoppscotch/openapi/` enthält für jeden Dienst eine OpenAPI-Datei seiner internen API. Öffnen Sie in Hoppscotch Collections → Import → Import from File und wählen Sie alle Dateien auf einmal aus. Jede Datei wird zu einer Collection, deren Anfragen an die Docker-Adresse des Dienstes gehen. Dieselben Dateien werden im Abschnitt [Service-API](/de/dev/service-api/overview) angezeigt.

#### CSRF-Probleme {#csrf-problems}

<Warning>

Wenn Sie mit Postman oder anderen Debugging-Werkzeugen eine **POST**-Anfrage erzeugen, stellen Sie möglicherweise fest, dass die Anmeldung **verweigert** wird, und zwar mit einem 403-Fehler. Das liegt daran, dass Overleaf durch eine **CSRF**-Prüfung geschützt ist.

</Warning>

<Frame>
  <img src="/images/dev/image-8.png" alt="" />
</Frame>

In Ihrer Konsole sehen Sie möglicherweise:

<Frame>
  <img src="/images/dev/image-9.png" alt="" />
</Frame>

Um dies bei Ihrer Overleaf-Entwicklung zu lösen, müssen Sie Ihr CSRF-Token einrichten. Hier ist die ausführliche Anleitung.

<Steps>
<Step title="Pre-Request hinzufügen">
Fügen Sie den folgenden Code als Pre-Request hinzu

<Frame>
  <img src="/images/dev/image-10.png" alt="" />
</Frame>

Das Skript lautet wie folgt:

```js wrap
pm.sendRequest("http://web:3000/dev/csrf", function (err, res) {
    if (err) {
        console.log(err);
        return;
    }

    // 1) Save CSRF token (/dev/csrf)
    const token = res.text().trim();
    pw.env.set("csrftoken", token);
    console.log("csrftoken =", token);

    const setCookieHeader = (res.headers || []).find(h => h.key?.toLowerCase() === "set-cookie")?.value;
    console.log("set-cookie =", setCookieHeader);

    if (!setCookieHeader) return;

    const cookiePair = setCookieHeader.split(";")[0].trim(); // overleaf.sid=...
    pw.env.set("cookie_header", cookiePair);
    console.log("cookie_header =", cookiePair);
});
```
</Step>

<Step title="Request-Header hinzufügen">
Sie müssen die folgenden Header hinzufügen:

| Header-Name  | Header-Wert         |
| ------------ | ------------------- |
| Content-Type | `application/json`  |
| X-Csrf-Token | `<<csrftoken>>`     |
| Cookie       | `<<cookie_header>>` |

<Frame>
  <img src="/images/dev/image-11.png" alt="" />
</Frame>
</Step>

<Step title="Mit API-Werkzeugen anmelden">
Jetzt können Sie sich mit Ihrem Benutzernamen und Passwort anmelden.

```json5
{
  "_csrf": "<<csrftoken>>",
  "email": "admin@overleaf.com",
  "password": "xxxxxx"
}
```

So sieht die Antwort aus, wenn Sie einen falschen Benutzernamen oder ein falsches Passwort eingeben.

<Frame>
  <img src="/images/dev/image-12.png" alt="" />
</Frame>
</Step>
</Steps>
