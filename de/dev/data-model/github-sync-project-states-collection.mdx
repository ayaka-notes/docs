`githubSyncProjectStates` enthält ein Dokument pro Projekt, das mit einem GitHub-Repository verknüpft ist: welches Repository und wo die letzte Synchronisierung aufgehört hat. Die Collection gehört zum Web-Modul `github-sync` (`services/web/modules/github-sync`). Das Schema liegt in `services/web/modules/github-sync/app/models/githubSyncProjectStates.mjs`, und jeder Zugriff läuft über `services/web/modules/github-sync/app/src/SyncStateManager.mjs`.

#### Felder {#fields}

| Feld | Typ | Bedeutung | Quelle |
| ---- | --- | --------- | ------ |
| `_id` | ObjectId | Wird von Mongoose beim Anlegen gesetzt. | |
| `projectId` | ObjectId | Das verknüpfte Projekt. Pflichtfeld. Das Schema sagt `unique: true`, aber es wird kein Index erstellt (siehe Indizes). | `githubSyncProjectStates.mjs:8` |
| `repoFullName` | String | Das Repository als `owner/name` (GitHubs `full_name`). Pflichtfeld. | `githubSyncProjectStates.mjs:9` |
| `defaultBranchName` | String | Der Branch, mit dem das Projekt synchronisiert wird. Wird beim Verknüpfen des Projekts gesetzt und danach nicht geändert: beim Import der Branch, den das Importformular sendet; beim Export der Standard-Branch des neuen Repositorys. Standard `null`. | `githubSyncProjectStates.mjs:10`, `GitHubSyncHandler.mjs:175-181,235-241` |
| `mergeStatus` | String | `clean`, `conflict` oder `diverged`. Standard `clean`. | `githubSyncProjectStates.mjs:11` |
| `lastSyncCommit` | String | Der Commit-SHA auf dem synchronisierten Branch bei der letzten Synchronisierung. Standard `null`. | `githubSyncProjectStates.mjs:12` |
| `lastSyncVersion` | Number | Die Version der Projekthistorie bei der letzten Synchronisierung, aus project-history `GET /project/:id/version`, gelesen nach einem History-Flush. | `conflictVersion` | Number | Während eines Konflikts: die Version der Projekthistorie, als der Konflikt erfasst wurde. Standard `null`. | `githubSyncProjectStates.mjs:16` |

#### Wer sie schreibt {#who-writes-it}

| Code | Was er tut |
| ---- | ---------- |
| `SyncStateManager.mjs:9-14` (`createProjectState`) | Legt das Dokument an: nach dem Import eines Repositorys als neues Projekt (`services/web/modules/github-sync/app/src/GitHubSyncHandler.mjs:175-181`) oder nach dem Export eines Projekts in ein neues Repository (`GitHubSyncHandler.mjs:235-241`, nur Eigentümer, abgelehnt, wenn bereits verknüpft). |
| `SyncStateManager.mjs:16-21` (`updateProjectState`) | `$set` der geänderten Felder. `getMergeOverview` setzt `mergeStatus: 'diverged'`, wenn der synchronisierte Branch nicht mehr auf `lastSyncCommit` aufbaut: GitHubs Compare antwortet `diverged` oder `behind` (`GitHubApiClient.mjs:382-400`), oder der Commit ist weg und der Benutzer darf pushen (`GitHubSyncHandler.mjs:123,126-137`). Eine Synchronisierung (`services/web/modules/github-sync/app/src/GitMerge.mjs`) verschiebt bei Erfolg `lastSyncCommit`/`lastSyncVersion` (zum Beispiel `:143,173,224`), erfasst einen Konflikt mit `unmergedBranchName`, `unmergedBranchHead` und `conflictVersion` (`:207-213`) und leert diese, sobald er gelöst ist (`:250-257`). |
| `SyncStateManager.mjs:23-25` (`removeProjectState`) | Löscht das Dokument, wenn der Eigentümer die Verknüpfung des Projekts aufhebt (`GitHubSyncHandler.mjs:83-97`) und wenn ein gelöschtes Projekt abläuft (`services/web/modules/github-sync/index.mjs:56-58`). |

#### Wer sie liest {#who-reads-it}

| Code | Was er tut |
| ---- | ---------- |
| `GitHubSyncHandler.mjs:39-60` (`getProjectState`) | Liefert dem Editor `mergeStatus`, `repoFullName` und `unmergedBranchName`. Ohne Dokument antwortet es `need-export`, ein Wert, der nie gespeichert wird. |
| `GitHubSyncHandler.mjs:110-143` (`getMergeOverview`) | Vergleicht `lastSyncCommit` und `lastSyncVersion` mit GitHub und der Projekthistorie, um die neuen Commits aufzulisten. |
| `GitHubSyncHandler.mjs:200` (`exportProject`) | Lehnt den Export eines bereits verknüpften Projekts ab. |
| `GitMerge.mjs:27` (`doGitMergeWithoutLock`) | Lädt den Zustand zu Beginn einer Synchronisierung. |

#### Indizes {#indexes}

| Name | Schlüssel | Optionen | Migration |
| ---- | --------- | -------- | --------- |
| `_id_` | `_id: 1` | | default |

Mongoose-`autoIndex` ist ausgeschaltet (`services/web/app/src/infrastructure/Mongoose.mjs:7`), daher erzeugt das `unique: true` des Schemas auf `projectId` nichts. `tools/migrations/20190912145010_create_githubSyncProjectStates_indexes.mjs` (Upstreams `project_id` und `owner_id`) ist nur mit `saas` getaggt und läuft in CE nicht.

#### Hinweise {#notes}

* Eine Synchronisierung läuft unter der `gitSync`-Sperre des Projekts (`GitMerge.mjs:17-24`). GitLab- und Gitea-Sync verwenden dieselbe Sperre, sodass pro Projekt immer nur eine Synchronisierung läuft.
* Ein gelöschtes Projekt behält sein Dokument, bis das Projekt abläuft.
* Das GitHub-Token des Benutzers liegt in [GitHub Sync User Credentials](/de/dev/data-model/github-sync-user-credentials-collection).
