`oauthAccessTokens` enthält die Bearer-Token, die Web akzeptiert. In Ayakaleaf Pro sind das die persönlichen Zugriffstoken (Git-Authentifizierungstoken), die ein Benutzer auf der Seite mit den Kontoeinstellungen erstellt und für git-bridge und den MCP-Endpunkt verwendet. Ein Dokument ist ein Token. Das Schema ist `services/web/app/src/models/OauthAccessToken.mjs`; das Web-Modul `oauth2-server` schreibt die Collection, meist mit dem nativen Treiber.

Die Migrationen liegen in `tools/migrations/`. Der eindeutige Index `accessToken_1` stammt nur aus Migrationen mit den Tags `saas` und `server-pro`, daher gibt es in der Community Edition keinen Index auf `accessToken`.

#### Hinweise {#notes}

* Das Löschen eines Benutzers löscht seine Token nicht. `UserDeleter` löst den Hook `cleanupPersonalAccessTokens` aus (`services/web/app/src/Features/User/UserDeleter.mjs:230-234`), aber kein Modul hört darauf. Beide Token-Prüfungen lehnen die Token ab, weil der Benutzer nicht mehr existiert, und der TTL-Index entfernt sie einen Tag nach `accessTokenExpiresAt`.
* Das Sperren eines Benutzers beendet nur die Sitzungen. Die Token bleiben, und beide Token-Prüfungen lehnen sie ab, solange `users.suspended` auf `true` steht (`OAuth2Model.mjs:51-54`, `OAuthPersonalAccessTokenManager.mjs:129-134`).
