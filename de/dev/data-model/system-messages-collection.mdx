`systemmessages` enthält die seitenweiten Banner, die ein Administrator für alle angemeldeten Benutzer veröffentlicht. Ein Dokument ist eine Nachricht. `web` ist Eigentümer; das Schema ist `services/web/app/src/models/SystemMessage.mjs` und der Code ist `services/web/app/src/Features/SystemMessages/SystemMessageManager.mjs`.

#### Felder {#fields}

| Feld | Typ | Bedeutung | Quelle |
| ---- | --- | --------- | ------ |
| `_id` | ObjectId | Nachrichten-ID. Der Browser merkt sich anhand dieser ID, welche Nachrichten der Benutzer geschlossen hat (`services/web/frontend/js/shared/components/system-message.tsx:10`). | `SystemMessage.mjs:5` |
| `content` | String | Nachrichtentext, Standard `''`. | `SystemMessage.mjs:7` |
| `__v` | Number | Mongoose-Versionsschlüssel, hinzugefügt durch `message.save()`. | `SystemMessageManager.mjs:29-30` |

#### Wer schreibt {#who-writes-it}

| Code | Was er tut |
| ---- | ---------- |
| `SystemMessageManager.mjs:28-33` (`createMessage`) | `POST /admin/messages` (`services/web/app/src/router.mjs:1150-1152`, `services/web/app/src/Features/ServerAdmin/AdminController.mjs:151-159`): fügt eine Nachricht hinzu. |
| `SystemMessageManager.mjs:22-26` (`clearMessages`) | `POST /admin/messages/clear` (`router.mjs:1155-1157`, `AdminController.mjs:161-168`): löscht alle Nachrichten. Eine einzelne Nachricht lässt sich nicht löschen. |

#### Wer liest {#who-reads-it}

| Code | Was er tut |
| ---- | ---------- |
| `SystemMessageManager.mjs:50-65` | Jeder `web`-Prozess hält alle Nachrichten im Speicher und lädt sie alle 20 bis 30 Sekunden neu sowie direkt nach dem eigenen Anlegen oder Leeren. |
| `services/web/app/src/Features/SystemMessages/SystemMessageController.mjs:6-24` | `GET /system/messages` (`router.mjs:331`): gibt die zwischengespeicherten Nachrichten an angemeldete Benutzer zurück. Solange die Website geschlossen ist (`siteIsOpen` false), gibt er stattdessen einen festen Hinweis zurück, der nicht in Mongo gespeichert ist. |
| `AdminController.mjs:83-84` | Die Seite `/admin` listet die Nachrichten direkt aus Mongo auf. |

#### Indizes {#indexes}

Keine Migration legt einen Index auf `systemmessages` an; es existiert nur der Standardindex `_id`.

#### Hinweise {#notes}

* Ist `notifyOnSystemMessageChanges` gesetzt, wird ein Anlegen oder Leeren zusätzlich im Redis-Kanal `refresh-system-messages` veröffentlicht, sodass andere `web`-Prozesse sofort neu laden (`SystemMessageManager.mjs:9`, `:35-48`, `:75-87`). Ohne diese Einstellung übernehmen sie die Änderung beim nächsten zeitgesteuerten Neuladen.
