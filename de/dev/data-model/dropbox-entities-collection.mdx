title: Dropbox-Entities-Collection

---

`dropboxEntities` enthält ein Dokument pro Datei, die die Dropbox-Synchronisierung zwischen einem Projekt und der Dropbox eines Benutzers kopiert hat, sowie kurzlebige Tombstones. Die Collection gehört zur Dropbox-Synchronisierung: third-party-datastore (`services/third-party-datastore/app/js/StateManager.mjs`) schreibt und liest sie, und das Web-Modul `dropbox` (`services/web/modules/dropbox/app/src/DropboxHandler.mjs`) leert sie. Es gibt kein Mongoose-Schema.

#### Felder {#fields}

| Feld | Typ | Bedeutung | Quelle |
| ---- | --- | --------- | ------ |
| `_id` | ObjectId | Wird beim Einfügen vom Treiber gesetzt. | `StateManager.mjs:46,97` |
| `overleaf.userId` | ObjectId | Der Benutzer, in dessen Dropbox die Datei liegt. In jedem Dokument gesetzt. | `StateManager.mjs:48,98` |
| `overleaf.projectId` | ObjectId | Das Projekt des Docs oder der Datei. Gesetzt, wenn bekannt; Tombstones haben keins. | `StateManager.mjs:49-51` |
| `overleaf.id` | ObjectId | Die `_id` des Docs oder der Datei im `rootFolder` des Projekts. Gesetzt, wenn bekannt. | `StateManager.mjs:52` |
| `overleaf.type` | String | `doc` oder `file`. Der aktuelle Code schreibt das Feld, liest es aber nicht. | `StateManager.mjs:53`; Werte aus `services/web/app/src/Features/ThirdPartyDataStore/TpdsUpdateSender.mjs:35,96` und `UpdateMerger.mjs:104,119` |
| `dropbox.id` | String | Die `id` der Datei in den Dropbox-Dateimetadaten. Bei Tombstones nicht gesetzt. | `StateManager.mjs:56` |
| `dropbox.pathLower` | String | Der Pfad der Datei in Dropbox, kleingeschrieben und ohne abschließenden Schrägstrich. Wird aktualisiert, wenn die Datei oder ihr Projektordner verschoben wird. | `StateManager.mjs:14-16,57,91,99` |
| `dropbox.rev` | String | Die Dropbox-Revision bei der letzten Synchronisierung. Der nächste Upload sendet sie mit, sodass eine in Dropbox geänderte Datei nicht überschrieben wird. | `StateManager.mjs:58`, `JobProcessor.mjs:114-122` |
| `dropbox.contentHash` | String | Der Dropbox-Inhaltshash bei der letzten Synchronisierung. Eine aufgelistete Datei mit demselben Hash wird übersprungen, da sie unser eigener Upload oder bereits angewendet ist. | `StateManager.mjs:59`, `PullManager.mjs:147-149` |
| `tombstone` | Boolean | `true` markiert einen Pfad, den third-party-datastore selbst in Dropbox gelöscht oder wegverschoben hat. Wenn Dropbox diese Löschung zurückmeldet, wird sie nicht auf das Projekt angewendet. | `StateManager.mjs:100`, `PullManager.mjs:189-192` |
| `createdAt` | Date | Nur Tombstones: wann er angelegt wurde. Ein abgeschlossener Pull entfernt die Tombstones, die vor seinem Start angelegt wurden. | `StateManager.mjs:101,115-121` |

Ein Tombstone hat nur `overleaf.userId`, `dropbox.pathLower`, `tombstone` und `createdAt` (`StateManager.mjs:96-103`).

#### Wer sie schreibt {#who-writes-it}

| Code | Was er tut |
| ---- | ---------- |
| `services/third-party-datastore/app/js/StateManager.mjs:35-62` (`recordEntity`) | Löscht die Dokumente des Benutzers mit derselben `dropbox.id`, demselben `dropbox.pathLower` oder derselben `overleaf.id` und fügt dann den neuen Zustand ein. |
| `services/third-party-datastore/app/js/JobProcessor.mjs:102-134` (`addEntity`) | Speichert ein Doc oder eine Datei nach dem Upload von Overleaf nach Dropbox (`:125-133`). |
| `services/third-party-datastore/app/js/PullManager.mjs:142-177` (`applyFile`) | Speichert eine Dropbox-Datei, nachdem Web sie auf das Projekt angewendet hat (`:168-176`). |
| `StateManager.mjs:80-94` (`moveEntities`) | Schreibt `dropbox.pathLower` unter einem verschobenen Pfad neu: Projektumbenennung (`JobProcessor.mjs:195`) und Verschieben einer Datei oder eines Ordners (`JobProcessor.mjs:239`). |
| `StateManager.mjs:96-103` (`addTombstone`) | Nach einem Löschen (`JobProcessor.mjs:153`), einer Projektumbenennung (`:202`) oder einem Verschieben (`:240`) in Dropbox. |
| `StateManager.mjs:72-78` (`removeEntities`) | Löscht die Einträge an und unter einem Pfad, außer Tombstones: nach einem Löschen in Overleaf (`JobProcessor.mjs:152`) oder in Dropbox (`PullManager.mjs:206`). |
| `StateManager.mjs:115-121` (`clearTombstones`) | Am Ende eines Pulls (`PullManager.mjs:31,69`). |
| `StateManager.mjs:186-190` (`removeUserState`), aufgerufen von `services/third-party-datastore/app/js/QueueWorker.mjs:43` | Löscht alle Dokumente des Benutzers, wenn third-party-datastore ein Konto trennt, das es nicht mehr verwenden kann. |
| `DropboxHandler.mjs:142-146` (`removeUserState`) | Löscht alle Dokumente des Benutzers beim Verknüpfen (`:125`), beim Trennen (`:183`) und wenn ein gelöschter Benutzer abläuft (`services/web/modules/dropbox/index.mjs:62-64`). |
| `DropboxHandler.mjs:150-154` (`removeProjectState`) | Löscht die Dokumente des Projekts, wenn ein gelöschtes Projekt abläuft (`index.mjs:54-56`). |

#### Wer sie liest {#who-reads-it}

| Code | Was er tut |
| ---- | ---------- |
| `StateManager.mjs:64-70` (`findEntityByPath`) | Holt `dropbox.rev` vor einem Upload (`JobProcessor.mjs:114`) und `dropbox.contentHash` vor dem Anwenden einer Dropbox-Datei (`PullManager.mjs:147`). |
| `StateManager.mjs:106-112` (`findTombstone`) | Prüft eine gemeldete Löschung am Pfad oder an einem seiner übergeordneten Pfade (`PullManager.mjs:189`). |
| `StateManager.mjs:160-175` (`getSyncedPaths`) | Listet die synchronisierten Dateipfade nach einem Zurücksetzen des Cursors auf, sodass eine Datei, die in der Auflistung fehlt, als gelöscht gilt (`PullManager.mjs:74-85`). |

#### Hinweise {#notes}

* Die Eindeutigkeit ergibt sich nur aus dem Löschen vor jedem Einfügen in `recordEntity` (`StateManager.mjs:38-45`). Der Kommentar in `StateManager.mjs:3-11` erwähnt eindeutige Indizes; CE hat sie nicht.
* Abfragen nach Benutzer und Pfad (`findEntityByPath`, `findTombstone`, `removeEntities`) nutzen den Index nur für `overleaf.userId`.
