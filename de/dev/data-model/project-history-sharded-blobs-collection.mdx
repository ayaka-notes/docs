title: Project-History-Sharded-Blobs-Collection

`projectHistoryShardedBlobs` enthält die Blob-Einträge, die nicht mehr in [projectHistoryBlobs](/dev/data-model/project-history-blobs-collection) passen: Hat der Bucket für ein Hash-Präfix dort bereits 8 Einträge, landen die nächsten hier. Ein Projekt hat darin höchstens 16 Dokumente, eines pro erster Hex-Ziffer des Hashs. Es gibt kein Mongoose-Schema; history-v1 schreibt sie in `services/history-v1/storage/lib/blob_store/mongo.js` (Aufbau beschrieben in `mongo.js:1-16`).

#### Felder {#fields}

| Feld | Typ | Bedeutung | Quelle |
| ----- | ---- | ------- | ------ |
| `_id` | Binary | 13 Bytes: die History-ID des Projekts, ein `0`, und die Shard-Ziffer, als Hex gelesen (`<history id>0<digit>`). Die Shard-Ziffer ist die erste Hex-Ziffer des Hashs. | `mongo.js:439-453` |
| `blobs` | Object | Blob-Einträge, gruppiert in Buckets. Der Schlüssel eines Buckets sind die Hex-Ziffern 2 bis 4 des Hashs. | `mongo.js:439-443` |
| `blobs.<bcd>` | Array of Object | Die Einträge des Buckets. Der Code begrenzt seine Größe nicht. | `mongo.js:399-407` |
| `blobs.<bcd>[].h` | Binary | Der Hash, 20 Bytes, wie in projectHistoryBlobs. | `mongo.js:472` |
| `blobs.<bcd>[].b` | Number | Bytelänge des Inhalts. | `mongo.js:473` |
| `blobs.<bcd>[].s` | Number | Länge des Inhalts als Text; `null`, wenn der Inhalt kein bearbeitbarer Text ist. | `mongo.js:474` |

#### Wer schreibt sie {#who-writes-it}

| Code | Was er tut |
| ---- | ------------ |
| `services/history-v1/storage/lib/blob_store/mongo.js:399-407` | `insertRecordSharded`: Upsert mit `$addToSet` in den Bucket. Aufgerufen von `insertBlob`, wenn der Bucket in projectHistoryBlobs voll ist (`mongo.js:387-389`). |
| `mongo.js:75-103` | `clone`: kopiert die Shards des Projekts zu einer anderen History-ID, für history-v1 `POST /projects/:project_id/clone`, was nichts in Web aufruft. |
| `mongo.js:413-422` | `deleteBlobs`: löscht alle Shards des Projekts zusammen mit seinem projectHistoryBlobs-Dokument, bei history-v1 `DELETE /projects/:project_id`. |

#### Wer liest sie {#who-reads-it}

| Code | Was er tut |
| ---- | ------------ |
| `mongo.js:144-157` | `findBlobSharded`: ein Blob, nur gesucht, wenn sein Bucket in projectHistoryBlobs 8 Einträge hat und ihn nicht enthält (`mongo.js:127-131`). |
| `mongo.js:217-260` | `findBlobsSharded`: die Blobs, die `findBlobs` in projectHistoryBlobs nicht gefunden hat (`mongo.js:202-206`). |
| `mongo.js:285-306` | `getProjectBlobs`: alle Shards eines Projekts. |
| `mongo.js:337-361` | `getProjectBlobsBatch`: alle Shards mehrerer Projekte, für die Blob-Statistik-Route. |

#### Indizes {#indexes}

Nur der Standardindex `_id`. Keine Migration in `tools/migrations/` fügt einen hinzu.

#### Hinweise {#notes}

* Die Shards eines Projekts liegen in `_id`-Reihenfolge nebeneinander, daher findet der Code sie mit einem `_id`-Bereich von `<history id>00` bis `<history id>0f` (`mongo.js:75-80`, `287-295`).
* Die Collection entsteht erst, wenn ein Projekt mehr als 8 Blobs mit demselben dreistelligen Hash-Präfix hat, daher fehlt sie auf einer kleinen Instanz eventuell ganz.
