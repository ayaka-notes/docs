`templates` enthält ein Dokument pro Vorlage in der Vorlagengalerie. Die Dateien einer Vorlage (die Projekt-ZIP-Datei und das PDF) stehen nicht hier: Sie liegen in filestore unter `template/<_id>/v/<version>/`. Die Collection gehört zum Web-Modul `template-gallery` (`services/web/modules/template-gallery`). Das Schema ist das Mongoose-Modell `Template` in `services/web/modules/template-gallery/app/src/models/Template.mjs`; die Logik steht in `services/web/modules/template-gallery/app/src/TemplateGalleryManager.mjs` und dem danebenliegenden `TemplateGalleryHelper.mjs`.

#### Wer schreibt {#who-writes-it}

| Code | Funktion |
| ---- | ------------ |
| `TemplateGalleryManager.mjs:53-97` (`createTemplateFromProject`) | `POST /template/new/:Project_id`. Kopiert die Einstellungen des Projekts (`TemplateGalleryHelper.mjs:94-134`), lädt die ZIP-Datei und das PDF in filestore hoch und speichert. Ist der Name vergeben, antwortet es mit einem Konflikt, es sei denn, der Client hat das Überschreiben verlangt: Dann aktualisiert es diese Vorlage, erhöht ihre `version` und löscht anschließend die Dateien der vorherigen Version. |
| `TemplateGalleryManager.mjs:21-47` (`editTemplate`) | `POST /template/:template_id/edit`. Weist die gesendeten Felder dem Dokument zu, rendert `description` und `author` neu und setzt `lastUpdated`. Das Bearbeitungsformular sendet die geänderten Felder unter `name`, `license`, `category`, `language`, `authorMD` und `descriptionMD` (`services/web/modules/template-gallery/frontend/js/pages/template/util/api.ts:22-29`). |
| `TemplateGalleryHelper.mjs:186-222` (`deleteTemplateAssets`) | `DELETE /template/:template_id/delete` löscht das Dokument und die Dateien der angegebenen Version (`TemplateGalleryManager.mjs:49-51`). |

Nur Site-Admins und der Benutzer in `OVERLEAF_TEMPLATES_USER_ID` dürfen diese drei Routen aufrufen (`services/web/modules/template-gallery/app/src/Router.mjs:55-62,70-84`, `PermissionsMiddleware.mjs:8-19`).

#### Wer liest {#who-reads-it}

| Code | Funktion |
| ---- | ------------ |
| `TemplateGalleryManager.mjs:158-183` (`getTemplate`) | Findet eine Vorlage über `_id` oder `name` für die Vorlagenseite und für `GET /api/template` (`services/web/modules/template-gallery/app/src/TemplateGalleryController.mjs:210-232`). Zeigt `project_id` auf ein Projekt, das nicht mehr existiert, lässt die Antwort es weg; das Dokument wird nicht geändert. |
| `TemplateGalleryManager.mjs:190-236` (`getCategoryTemplates`) | `GET /api/templates`: eine Seite einer Kategorie, durchsucht in `name`, `authorMD` und `descriptionMD`, sortiert nach `lastUpdated` oder nach `name` (ohne Beachtung der Groß- und Kleinschreibung). |
| `TemplateGalleryHelper.mjs:64-80` (`canUserOverrideTemplate`) | Liest `owner`, um den Eigentümer in der Konfliktmeldung zu nennen. |

#### Indizes {#indexes}

| Name | Schlüssel | Optionen | Migration |
| ---- | ---- | ------- | --------- |
| `_id_` | `_id: 1` | | Standard |

Mongoose `autoIndex` ist ausgeschaltet (`services/web/app/src/infrastructure/Mongoose.mjs:7`). `tools/migrations/20190912145030_create_templates_indexes.mjs` (eindeutig `project_id`, `user_id`, `name`) ist mit `server-pro` und `saas` markiert und läuft daher nicht in CE, das nur die `server-ce`-Migrationen ausführt (`server-ce/init_scripts/900_run_web_migrations.sh`).

#### Hinweise {#notes}

* Upstream behandelt `templates` als veraltete Collection und löscht sie auf der eigenen Website (`tools/migrations/20241002180623_drop_unused_collections.mjs`, markiert mit `saas`). In Ayakaleaf Pro verwendet das Vorlagengalerie-Modul sie.
* Das Sortieren nach Namen verwendet eine Collation ohne Beachtung der Groß- und Kleinschreibung, und der Kommentar bei `TemplateGalleryManager.mjs:186-188` merkt an, dass ein `name`-Index dieselbe bräuchte. CE hat keinen `name`-Index, daher sortiert Mongo im Speicher.
* Das Löschen des Quellprojekts oder des Eigentümers löscht die Vorlage nicht.
