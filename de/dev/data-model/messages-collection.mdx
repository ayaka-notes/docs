title: Messages-Collection
icon: message
---

`messages` enthält ein Dokument pro Nachricht: eine Zeile im Projekt-Chat oder einen Kommentar bzw. eine Antwort in einem Review-Kommentar-Thread. Nur der Chat-Dienst schreibt sie, in `services/chat/app/js/Features/Messages/MessageManager.js`. Es gibt kein Mongoose-Schema. Jede Nachricht gehört zu einem Raum in der Collection [rooms](/de/dev/data-model/rooms-collection).

#### Felder {#fields}

| Feld | Typ | Bedeutung | Quelle |
| ----- | ---- | ------- | ------ |
| `_id` | ObjectId | Nachrichten-ID. | `MessageManager.js:13-14` |
| `room_id` | ObjectId | Der Raum (`rooms._id`), nicht die Projekt-ID oder die Thread-ID. | `MessageManager.js:8,106-108` |
| `user_id` | ObjectId | Autor. | `MessageManager.js:9,103-105` |
| `content` | String | Text der Nachricht, 1 bis 10240 Zeichen (`MAX_MESSAGE_LENGTH`). | `MessageManager.js:7`, `services/chat/app/js/Features/Messages/MessageHttpSchemas.js:3,12-15` |
| `timestamp` | Number | Sendezeitpunkt in Millisekunden seit 1970 (`Date.now()`), kein Date. | `MessageManager.js:10`, `services/chat/app/js/Features/Messages/MessageHttpController.js:288` |
| `edited_at` | Number | Zeitpunkt der letzten Bearbeitung in Millisekunden (`Date.now()`). Fehlt, wenn nie bearbeitet. | `MessageManager.js:65-69`, `MessageHttpController.js:189,213` |

#### Wer schreibt sie {#who-writes-it}

| Code | Was er tut |
| ---- | ------------ |
| `MessageManager.js:5-16` `createMessage` | Fügt eine Nachricht ein (`MessageHttpController.js:275-294`). Web sendet Projekt-Chat-Nachrichten aus `services/web/app/src/Features/Chat/ChatController.mjs:32` und Kommentare aus dem track-changes-Modul (`services/web/modules/track-changes/app/src/TrackChangesController.mjs:95`) und dem mcp-server-Modul (`services/web/modules/mcp-server/app/src/CommentTools.mjs:133`). |
| `MessageManager.js:51-72` `updateMessage` | Setzt `content` und `edited_at`. Wird eine Benutzer-ID übergeben, passt nur die Nachricht dieses Benutzers (`MessageManager.js:62-64`). Aufgerufen aus `ChatController.mjs:135` und `TrackChangesController.mjs:110`. |
| `MessageManager.js:74-80` `deleteMessage` | Löscht eine Nachricht. Aufgerufen aus `ChatController.mjs:105` und `TrackChangesController.mjs:129`. |
| `MessageManager.js:39-49` `deleteAllMessagesInRoom(s)` | Löscht die Nachrichten eines gelöschten Threads (`MessageHttpController.js:172-173`) oder eines ganzen Projekts, wenn ein gelöschtes Projekt abläuft (`MessageHttpController.js:261-271`, aufgerufen aus `services/web/app/src/Features/Project/ProjectDeleter.mjs:391`). |
| `MessageManager.js:115-127` `duplicateRoomToOtherRoom` | Kopiert `content`, `timestamp` und `user_id` jeder Nachricht in einen anderen Raum, ohne `edited_at`. Wird verwendet, wenn eine Verlaufswiederherstellung einen Thread dupliziert (`MessageHttpController.js:316-342`) und wenn ein Projekt mit seinen Bereichen kopiert wird (`MessageHttpController.js:344-357`). |

#### Wer liest sie {#who-reads-it}

| Code | Was er tut |
| ---- | ------------ |
| `MessageManager.js:18-29` `getMessages` | Neueste zuerst, höchstens `limit` (Standard 50), älter als `before` (ein `timestamp`). Wird für den Projekt-Chat verwendet (`ChatController.mjs:80`). |
| `MessageManager.js:31-37` `findAllMessagesInRooms` | Alle Nachrichten einiger Räume, für die Thread-Liste des Review-Panels (`TrackChangesController.mjs:82`), das mcp-server-Modul (`CommentTools.mjs:83`) und die Verlaufswiederherstellung (`services/web/app/src/Features/History/RestoreManager.mjs:259`). Web prüft außerdem die erste Nachricht eines Threads, damit ein Reviewer nur Threads ändern kann, die er selbst begonnen hat (`services/web/app/src/Features/Authorization/AuthorizationManager.mjs:409-411`). |
| `MessageManager.js:90-100` `getMessage` | Eine Nachricht. Web prüft ihr `user_id`, bevor ein Benutzer seine eigene Nachricht bearbeitet oder löscht (`services/web/app/src/Features/Authorization/AuthorizationMiddleware.mjs:253-257`, `TrackChangesController.mjs:124-125`). |

#### Hinweise {#notes}

* Um die Nachrichten eines Kommentars zu finden, suchen Sie zuerst den Raum über `project_id` und `thread_id` und fragen dann `room_id` ab. Die Kommentar-ID im Doc ist die `thread_id`, nicht die `room_id`.
* Der Text, auf den ein Kommentar verweist, ist `op.c` in `docs.ranges.comments`; die Diskussion steht hier.
