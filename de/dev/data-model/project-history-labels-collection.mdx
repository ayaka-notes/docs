`projectHistoryLabels` enthält die Labels, die Benutzer in der History-Ansicht an Versionen setzen, ein Dokument pro Label. project-history besitzt sie und schreibt sie in `services/project-history/app/js/LabelsManager.js`; es gibt kein Mongoose-Schema. Web greift nur über die project-history-API darauf zu.

#### Felder {#fields}

| Feld | Typ | Bedeutung | Quelle |
| ----- | ---- | ------- | ------ |
| `_id` | ObjectId | Label-ID. | `LabelsManager.js:81-85` |
| `project_id` | ObjectId | Das Projekt. | `LabelsManager.js:73` |
| `comment` | String | Der Labeltext. | `LabelsManager.js:74` |
| `version` | Number | Die Projektverlaufsversion, auf die das Label zeigt. | `LabelsManager.js:75` |
| `created_at` | Date | Wann das Label erstellt wurde; die Anfrage kann eine eigene Zeit übergeben, sonst gilt die aktuelle Zeit. | `LabelsManager.js:70`, `76` |
| `user_id` | ObjectId | Wer das Label erstellt hat. Fehlt, wenn die Anfrage keinen Benutzer enthält. | `LabelsManager.js:78-80` |

#### Wer schreibt sie {#who-writes-it}

| Code | Was er tut |
| ---- | ------------ |
| `services/project-history/app/js/LabelsManager.js:44-90` | `createLabel`: fügt ein Label ein, für project-history `POST /project/:project_id/labels` (`services/project-history/app/js/HttpController.js:1134-1171`). Web ruft es auf, wenn ein Benutzer ein Label hinzufügt, mit der ID des Benutzers (`services/web/app/src/Features/History/HistoryController.mjs:529-546`). |
| `LabelsManager.js:113-126` | `deleteLabel`: löscht ein Label des Projekts, für `DELETE /project/:project_id/labels/:label_id`. Web nutzt es, wenn der Projekteigentümer ein Label löscht (`HistoryController.mjs:649-670`). |
| `LabelsManager.js:92-111` | `deleteLabelForUser`: löscht ein Label nur, wenn der Benutzer es erstellt hat, für `DELETE /project/:project_id/user/:user_id/labels/:label_id`. Web nutzt es für alle anderen. |
| `LabelsManager.js:128-143` | `transferLabels`: überträgt alle Labels eines Benutzers auf einen anderen, für `POST /user/:from_user/labels/transfer/:to_user` (`services/project-history/app/js/Router.js:52-55`). Nichts in Web ruft diese Route auf. |
| `LabelsManager.js:7-25` | `cloneLabels`: kopiert die Labels eines Projekts in ein anderes Projekt, für project-history `POST /project/:project_id/clone` (`HttpController.js:113`), was nichts in Web aufruft. |

#### Wer liest sie {#who-reads-it}

| Code | Was er tut |
| ---- | ------------ |
| `LabelsManager.js:27-42` | `getLabels`: alle Labels eines Projekts, zurückgegeben als `{ id, comment, version, user_id, created_at }` (`LabelsManager.js:163-171`). Verwendet von `GET /project/:project_id/labels` (`HttpController.js:1076-1100`), das Web für die History-Ansicht aufruft und dabei Benutzernamen ergänzt (`HistoryController.mjs:488-499`). |
| `services/project-history/app/js/SummarizedUpdatesManager.js:57` | Fügt die Labels der Liste der Verlaufsupdates hinzu. |

#### Hinweise {#notes}

* Bevor project-history ein Label einfügt, verarbeitet es die anstehenden Updates des Projekts und prüft, ob history-v1 einen Chunk für diese Version hat, außer die Anfrage sendet `validate_exists: false` (`LabelsManager.js:53-59`, `173-195`; `HttpController.js:1109-1115`).
* Kein Code löscht die Labels eines Projekts, wenn das Projekt gelöscht wird: project-history `DELETE /project/:project_id` leert nur den Sync-Status und den Fehlereintrag (`HttpController.js:1363-1396`), und kein anderer Dienst berührt diese Collection.
