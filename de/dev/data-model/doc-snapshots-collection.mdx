`docSnapshots` enthält Kopien eines Docs, die document-updater unmittelbar vor einer Bearbeitung anlegt, die Kommentare oder nachverfolgte Änderungen zusammenfallen lässt. Nur document-updater schreibt sie, in `services/document-updater/app/js/SnapshotManager.js`. Web hat ein Mongoose-Modell in `services/web/app/src/models/DocSnapshot.mjs`, aber kein Code verwendet es.

#### Felder {#fields}

| Feld | Typ | Bedeutung | Quelle |
| ----- | ---- | ------- | ------ |
| `_id` | ObjectId | Snapshot-ID. | `SnapshotManager.js:24` |
| `project_id` | ObjectId | Projekt. | `SnapshotManager.js:19,26`, `DocSnapshot.mjs:7` |
| `doc_id` | ObjectId | Das Doc (`docs._id`). | `SnapshotManager.js:20,27`, `DocSnapshot.mjs:8` |
| `version` | Number | OT-Version des Docs vor der Bearbeitung. | `SnapshotManager.js:28`, `services/document-updater/app/js/UpdateManager.js:132,264-271`, `DocSnapshot.mjs:9` |
| `lines` | Array of String | Inhalt des Docs vor der Bearbeitung. | `SnapshotManager.js:29`, `DocSnapshot.mjs:10` |
| `pathname` | String | Pfad des Docs im Projekt zu diesem Zeitpunkt. | `SnapshotManager.js:30`, `DocSnapshot.mjs:11` |
| `ranges` | Mixed | `comments` und `changes` vor der Bearbeitung, in derselben Form wie `docs.ranges` (siehe [docs](/de/dev/data-model/docs-collection)). `id`, `op.t` und `metadata.user_id` werden in ObjectIds umgewandelt, `metadata.ts` in Dates. | `SnapshotManager.js:31,41-68`, `DocSnapshot.mjs:12` |
| `ts` | Date | Zeitpunkt des Snapshots. Der TTL-Index löscht den Snapshot 30 Tage später. | `SnapshotManager.js:32`, `DocSnapshot.mjs:13` |

#### Wer schreibt sie {#who-writes-it}

| Code | Was er tut |
| ---- | ------------ |
| `UpdateManager.js:248-271` | Nachdem document-updater eine Bearbeitung angewendet hat, speichert er das Doc im Zustand vor der Bearbeitung, wenn die Bearbeitung Bereiche zusammenfallen ließ: Mehr Bereiche wurden leer, oder mehr als ein Bereich wurde entfernt (`services/document-updater/app/js/RangesManager.js:104-106`). |
| `SnapshotManager.js:17-36` `recordSnapshot` | Fügt den Snapshot ein. |

#### Wer liest sie {#who-reads-it}

Kein Code liest sie. Das Web-Modell ist definiert, wird aber nirgends verwendet.

#### Hinweise {#notes}

* Nur Bearbeitungen, die über `UpdateManager.applyUpdate` laufen, erzeugen Snapshots. Bearbeitungen, die `HistoryOTUpdateManager` verarbeitet, tun das nicht (`UpdateManager.js:74-77`).
* Auf `doc_id` gibt es keinen Index. Suchen Sie die Snapshots eines Docs über `project_id` und `ts` und filtern Sie dann nach `doc_id`.
