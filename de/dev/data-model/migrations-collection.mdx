title: Migrations-Collection

---

`migrations` hält fest, welche Datenbankmigrationen gelaufen sind. Ein Dokument ist eine Migration aus `tools/migrations/`. Es wird vom Adapter des Migrationswerkzeugs [east](https://github.com/okv/east), `tools/migrations/lib/adapter.mjs`, geschrieben, nicht von einem laufenden Dienst.

#### Felder {#fields}

| Feld | Typ | Bedeutung | Quelle |
| ---- | --- | --------- | ------ |
| `_id` | ObjectId | Dokument-ID. | `adapter.mjs:103` |
| `name` | String | Dateiname der Migration ohne Endung, zum Beispiel `20190912145029_create_tags_indexes`. | `adapter.mjs:104` |
| `migratedAt` | Date | Wann die Migration abgeschlossen wurde. | `adapter.mjs:105` |

#### Wer schreibt {#who-writes-it}

| Code | Was er tut |
| ---- | ---------- |
| `adapter.mjs:101-107` (`markExecuted`) | Fügt nach dem Lauf einer Migration ein Dokument ein. |
| `adapter.mjs:109-114` (`unmarkExecuted`) | Löscht es wieder, wenn eine Migration zurückgerollt wird. |

CE führt bei jedem Containerstart `yarn run migrations migrate -t server-ce` aus (`server-ce/init_scripts/900_run_web_migrations.sh:4-12`; `-t server-pro`, wenn `OVERLEAF_IS_SERVER_PRO=true`). Nur Migrationen, deren `tags` diese Umgebung enthalten, laufen, und nur sie erhalten hier ein Dokument.

#### Wer liest {#who-reads-it}

| Code | Was er tut |
| ---- | ---------- |
| `adapter.mjs:72-99` (`getExecutedMigrationNames`) | east überspringt jede Migration, deren Name hier bereits steht. |
| `tools/migrations/lib/helpers.mjs:67-75` (`assertDependency`) | Eine Migration, die eine andere zuvor gelaufene Migration benötigt, wirft einen Fehler, wenn deren Name fehlt. |

#### Indizes {#indexes}

| Name | Schlüssel | Optionen | Migration |
| ---- | --------- | -------- | --------- |
| `name_1` | `{ name: 1 }` | unique | `tools/migrations/20190720165251_create_migrations.mjs` |

#### Hinweise {#notes}

* Wird ein Dokument gelöscht, läuft diese Migration beim nächsten Containerstart erneut, sofern ihre Tags passen.
* Mit einem zusätzlichen Mongo-Cluster (`mongo.auxUrl`) werden Migrationen mit dem Tag `auxiliary` stattdessen in der `migrations`-Collection dieses Clusters erfasst (`adapter.mjs:8-15`, `:64-70`). `mongo.auxUrl` stammt aus `MONGO_AUX_CONNECTION_STRING` (`tools/migrations/config/settings.defaults.js:19`), das standardmäßig nicht gesetzt ist.
