`projectInvites` enthält die Einladungen, die ein Projekteigentümer über den Teilen-Dialog verschickt. Ein Dokument ist eine Einladung an eine E-Mail-Adresse. Es wird gelöscht, wenn die Einladung angenommen oder widerrufen wird, oder von Mongo, wenn sie abläuft. Das Schema ist `services/web/app/src/models/ProjectInvite.mjs`, und `services/web/app/src/Features/Collaborators/CollaboratorsInviteHandler.mjs` schreibt es.

Eine Einladung macht niemanden zum Mitglied. Mitglieder stehen in den `*_refs`-Arrays eines Projekts, siehe [Projects-Collection](/de/dev/data-model/projects-collection).

Die Migrationen liegen in `tools/migrations/`. Das Schema deklariert auch den TTL-Index auf `expires`, aber Mongoose-`autoIndex` ist deaktiviert (`services/web/app/src/infrastructure/Mongoose.mjs:7`), daher legt die Migration ihn an.

#### Hinweise {#notes}

* Wenn das Projekt beim Annehmen einer `readAndWrite`- oder `review`-Einladung keinen freien Bearbeiterplatz mehr hat, tritt der Benutzer mit Lesezugriff bei und wird in `pendingEditor_refs` oder `pendingReviewer_refs` des Projekts geführt (`CollaboratorsInviteHandler.mjs:162-205`).
* Ältere Einladungen speicherten das Klartext-Token in einem Feld `token`. Die Migration `20240524135408_add_token_hmac_project_invite_tokens.mjs` fügte `tokenHmac` hinzu, und `20240531082910_remove_project_invite_tokens.mjs` entfernte `token`.
* Nichts löscht die Einladungen eines gelöschten Projekts; sie bleiben, bis der TTL-Index sie entfernt.
