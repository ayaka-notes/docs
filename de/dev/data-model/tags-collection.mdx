`tags` enthält die Tags (Ordner), in die ein Benutzer Projekte auf dem Projekt-Dashboard einsortiert. Ein Dokument ist ein Tag eines Benutzers. `web` ist Eigentümer; das Schema ist `services/web/app/src/models/Tag.mjs`, und alle Schreibvorgänge laufen über `services/web/app/src/Features/Tags/TagsHandler.mjs`.

#### Felder {#fields}

| Feld | Typ | Bedeutung | Quelle |
| ---- | --- | --------- | ------ |
| `_id` | ObjectId | Tag-ID, verwendet in den Routen `/tag/:tagId`. | `Tag.mjs:10` |
| `user_id` | String | Eigentümer des Tags. Aus historischen Gründen ein einfacher String, keine ObjectId. | `Tag.mjs:7-12` |
| `name` | String | Tag-Name, höchstens 50 Zeichen (`MAX_TAG_LENGTH`). Pro Benutzer eindeutig. | `Tag.mjs:13`, `TagsHandler.mjs:4` |
| `color` | String | Optionale Farbe: ein Hex-Code wie `#a1b2c3` oder ein Wert `hsl(<n>, 70%, 45%)` (`TAG_COLOR_REGEX`). | `Tag.mjs:5`, `Tag.mjs:14-22` |
| `project_ids` | Array of String | IDs der Projekte in diesem Tag, als Strings. | `Tag.mjs:23` |
| `__v` | Number | Mongoose-Versionsschlüssel, hinzugefügt, wenn `Tag.create` das Dokument anlegt. | `TagsHandler.mjs:27` |

#### Hinweise {#notes}

* Tags gelten pro Benutzer: Zwei Mitarbeiter am selben Projekt behalten jeweils ihre eigenen Tags dafür.
* `user_id` und `project_ids` sind Strings, fragen Sie sie also mit String-IDs ab, nicht mit ObjectIds.
* Das Löschen eines Benutzers (`services/web/app/src/Features/User/UserDeleter.mjs`) verändert `tags` nicht.
