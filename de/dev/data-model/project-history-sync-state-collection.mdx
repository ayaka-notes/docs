title: Project-History-Sync-State-Collection
icon: rotate
---

`projectHistorySyncState` enthält ein Dokument pro Projekt, das neu synchronisiert wurde: den Zustand des laufenden oder letzten Resyncs, bei dem project-history den Verlauf eines Projekts aus dem neu aufbaut, was Web und docstore enthalten. Die Collection gehört project-history und hat kein Mongoose-Schema; der Code ist die Klasse `SyncState` mit ihren Hilfsfunktionen in `services/project-history/app/js/SyncManager.js`.

#### Wer schreibt {#who-writes-it}

| Code | Funktion |
| ---- | ------------ |
| `services/project-history/app/js/SyncManager.js:195-249` | `setResyncState`: Upsert des Zustands. Aufgerufen, wenn ein Resync beginnt (`SyncManager.js:163`), und während project-history die Resync-Updates verarbeitet (`services/project-history/app/js/UpdatesProcessor.js:637`, `784`). |
| `SyncManager.js:257-266` | `_recordStuckClearInSyncState`: zählt einen hängenden Resync, der geleert wird. |
| `SyncManager.js:251-255` | `clearResyncState`: löscht das Dokument, zu Beginn eines harten Resyncs (`SyncManager.js:87`), bei project-history `DELETE /project/:project_id` (`services/project-history/app/js/HttpController.js:1363-1396`) und wenn ein Resync nur der Struktur von vorn beginnen muss (`SyncManager.js:705-716`). |
| `SyncManager.js:273-289` | `clearResyncStateIfAllAfter`: löscht einen abgeschlossenen Zustand, dessen Verlauf vollständig neuer als ein Datum ist. Nichts in `app/js` ruft es auf. |
| `SyncManager.js:171-181` | `cloneResyncState`: kopiert den Zustand in ein anderes Projekt, für project-history `POST /project/:project_id/clone` (`HttpController.js:57`, `124`), das nichts in Web aufruft. |

Ein Resync wird gestartet durch project-history `POST /project/:project_id/resync` (`HttpController.js:950-994`), durch die Retry-Cron-Jobs (`services/project-history/app/js/RetryManager.js:156-179`, `server-ce/config/crontab-history`) und durch project-history selbst, wenn die Verarbeitung von Updates einen erfordert (`UpdatesProcessor.js:75`, `224`).

#### Hinweise {#notes}

* Ein Resync läuft, solange `resyncProjectStructure` `true` ist oder `resyncDocContents` nicht leer ist (`SyncManager.js:565-567`). Nach 4 Stunden gilt er als hängend, nach 5 Leerungen als dauerhaft hängend (`SyncManager.js:43-44`, `569-585`).
* Wenn ein Resync endet, setzt project-history außerdem `overleaf.history.lastResyncedAt` am Projekt (`SyncManager.js:239-248`).
