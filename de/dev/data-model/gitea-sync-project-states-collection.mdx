`giteaSyncProjectStates` enthält ein Dokument pro Projekt, das mit einem Gitea-Repository verknüpft ist: welches Repository und wo die letzte Synchronisierung aufgehört hat. Die Collection gehört zum Web-Modul `gitea-sync` (`services/web/modules/gitea-sync`). Das Schema liegt in `services/web/modules/gitea-sync/app/models/giteaSyncProjectStates.mjs`, und jeder Zugriff läuft über `services/web/modules/gitea-sync/app/src/SyncStateManager.mjs`. Die Felder sind dieselben wie in [GitHub Sync Project States](/de/dev/data-model/github-sync-project-states-collection).

#### Felder {#fields}

| Feld | Typ | Bedeutung | Quelle |
| ---- | --- | --------- | ------ |
| `_id` | ObjectId | Wird von Mongoose beim Anlegen gesetzt. | |
| `projectId` | ObjectId | Das verknüpfte Projekt. Pflichtfeld. Das Schema sagt `unique: true`, aber es wird kein Index erstellt (siehe Indizes). | `giteaSyncProjectStates.mjs:8` |
| `repoFullName` | String | Das Repository als `owner/name` (Giteas `full_name`). Pflichtfeld. | `giteaSyncProjectStates.mjs:9`, `GiteaApiClient.mjs:315` |
| `defaultBranchName` | String | Der Branch, mit dem das Projekt synchronisiert wird. Wird beim Verknüpfen des Projekts gesetzt und danach nicht geändert: beim Import der Branch, den das Importformular sendet; beim Export der Standard-Branch des neuen Repositorys oder `main`, wenn die API keinen liefert. Standard `null`. | `giteaSyncProjectStates.mjs:10`, `GiteaSyncHandler.mjs:175-181,233-239`, `GiteaApiClient.mjs:314-317` |
| `mergeStatus` | String | `clean`, `conflict` oder `diverged`. Standard `clean`. | `giteaSyncProjectStates.mjs:11` |

#### Wer sie schreibt {#who-writes-it}

| Code | Was er tut |
| ---- | ---------- |
| `SyncStateManager.mjs:9-14` (`createProjectState`) | Legt das Dokument an: nach dem Import eines Repositorys als neues Projekt (`services/web/modules/gitea-sync/app/src/GiteaSyncHandler.mjs:175-181`) oder nach dem Export eines Projekts in ein neues Repository (`GiteaSyncHandler.mjs:233-239`, nur Eigentümer, abgelehnt, wenn bereits verknüpft). |
| `SyncStateManager.mjs:16-21` (`updateProjectState`) | `$set` der geänderten Felder. `getMergeOverview` setzt `mergeStatus: 'diverged'`, wenn `lastSyncCommit` kein Vorfahre des synchronisierten Branches mehr ist (`services/web/modules/gitea-sync/app/src/GiteaApiClient.mjs:431`), oder der Commit ist weg und der Benutzer darf pushen (`GiteaSyncHandler.mjs:123,126-137`). Eine Synchronisierung (`services/web/modules/gitea-sync/app/src/GitMerge.mjs`) verschiebt bei Erfolg `lastSyncCommit`/`lastSyncVersion` (zum Beispiel `:152,189,231`), erfasst einen Konflikt mit `unmergedBranchName`, `unmergedBranchHead` und `conflictVersion` (`:214-220`) und leert diese, sobald er gelöst ist (`:257-264`). |
| `SyncStateManager.mjs:23-25` (`removeProjectState`) | Löscht das Dokument, wenn der Eigentümer die Verknüpfung des Projekts aufhebt (`GiteaSyncHandler.mjs:83-97`) und wenn ein gelöschtes Projekt abläuft (`services/web/modules/gitea-sync/index.mjs:46-48`). |

#### Wer sie liest {#who-reads-it}

| Code | Was er tut |
| ---- | ---------- |
| `GiteaSyncHandler.mjs:39-60` (`getProjectState`) | Liefert dem Editor `mergeStatus`, `repoFullName` und `unmergedBranchName`. Ohne Dokument antwortet es `need-export`, ein Wert, der nie gespeichert wird. |
| `GiteaSyncHandler.mjs:110-143` (`getMergeOverview`) | Vergleicht `lastSyncCommit` und `lastSyncVersion` mit Gitea und der Projekthistorie, um die neuen Commits aufzulisten. |
| `GiteaSyncHandler.mjs:200` (`exportProject`) | Lehnt den Export eines bereits verknüpften Projekts ab. |
| `GitMerge.mjs:36` (`doGitMergeWithoutLock`) | Lädt den Zustand zu Beginn einer Synchronisierung. |

#### Indizes {#indexes}

| Name | Schlüssel | Optionen | Migration |
| ---- | --------- | -------- | --------- |
| `_id_` | `_id: 1` | | default |

Mongoose-`autoIndex` ist ausgeschaltet (`services/web/app/src/infrastructure/Mongoose.mjs:7`), daher erzeugt das `unique: true` des Schemas auf `projectId` nichts. Keine Migration erstellt Indizes für diese Collection.

#### Hinweise {#notes}

* Giteas API kann keine Commits außerhalb eines Branches anlegen, wie es die von GitHub kann. Eine Synchronisierung committet direkt auf den synchronisierten Branch, wenn sie vorwärts gehen kann, oder auf einen temporären Branch, der dann über einen Pull Request zusammengeführt wird (`GitMerge.mjs:16-21`).
* Eine Synchronisierung läuft unter der `gitSync`-Sperre des Projekts, die sie mit GitHub- und GitLab-Sync teilt (`GitMerge.mjs:25-32`).
* Ein gelöschtes Projekt behält sein Dokument, bis das Projekt abläuft.
* Das Gitea-Token des Benutzers liegt in [Gitea Sync User Credentials](/de/dev/data-model/gitea-sync-user-credentials-collection).
