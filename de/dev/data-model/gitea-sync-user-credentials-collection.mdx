`giteaSyncUserCredentials` enthält ein Dokument pro Benutzer, der ein Gitea-Konto für Gitea Sync verknüpft hat. Sie speichert die OAuth-Tokens des Benutzers verschlüsselt. Die Collection gehört zum Web-Modul `gitea-sync` (`services/web/modules/gitea-sync`). Das Schema liegt in `services/web/modules/gitea-sync/app/models/giteaSyncUserCredentials.mjs`, und jeder Zugriff läuft über `services/web/modules/gitea-sync/app/src/TokenManager.mjs`.

#### Felder {#fields}

| Feld | Typ | Bedeutung | Quelle |
| ----- | ---- | ------- | ------ |
| `_id` | ObjectId | Wird von Mongoose gesetzt, wenn der Upsert einfügt. | |
| `userId` | ObjectId | Der Overleaf-Benutzer. Pflichtfeld. Das Schema sagt `unique: true`, aber es wird kein Index erstellt (siehe Indizes); der Upsert nach `userId` hält ein Dokument pro Benutzer. | `giteaSyncUserCredentials.mjs:8`, `TokenManager.mjs:89-96` |
| `gitea` | String | Das JSON `{ accessToken, refreshToken, expiresAt }`, verschlüsselt mit `@overleaf/access-token-encryptor`. `expiresAt` ist in Millisekunden seit der Epoche oder `null`; `refreshToken` kann `null` sein. Das Passwort kommt aus `GITEA_TOKEN_CIPHER_PASSWORD`; das Cipher-Label ist `GITEA_TOKEN_CIPHER_LABEL`, Standard `2026.10-v3`. Pflichtfeld. | `giteaSyncUserCredentials.mjs:9-10`, `TokenManager.mjs:17-30`, `services/web/modules/gitea-sync/app/src/GiteaApiClient.mjs:198-209` |
| `__v` | Number | Der Mongoose-Versionsschlüssel. Das Schema schaltet ihn nicht ab. | Mongoose-Standard |

#### Wer sie schreibt {#who-writes-it}

| Code | Was er tut |
| ---- | ------------ |
| `TokenManager.mjs:89-96` (`saveUserToken`) | Speichert per Upsert die verschlüsselten Zugangsdaten des Benutzers. Aufgerufen vom OAuth-Callback (`services/web/modules/gitea-sync/app/src/GiteaSyncController.mjs:146`). Anders als bei GitLab Sync widerruft ein erneutes Verknüpfen das ersetzte Token nicht. |
| `TokenManager.mjs:53-79` (`refreshUserToken`) | Wenn das Access-Token weniger als 5 Minuten vor `expiresAt` liegt (`:12`), holt es mit dem Refresh-Token neue Tokens und speichert sie (`:76`). Es läuft unter dem Lock `giteaSyncToken` pro Benutzer (`:14,54`), weil Gitea das Refresh-Token bei der Verwendung ersetzt. |
| `TokenManager.mjs:100-102` (`removeUserToken`) | Löscht das Dokument. Gitea hat keine API zum Widerrufen eines OAuth-Tokens, daher widerruft der Benutzer die Berechtigung in Gitea (`:98-99`). Aufgerufen beim Trennen (`GiteaSyncController.mjs:173`) und wenn ein gelöschter Benutzer abläuft (`services/web/modules/gitea-sync/index.mjs:56-58`). |

#### Wer sie liest {#who-reads-it}

| Code | Was er tut |
| ---- | ------------ |
| `TokenManager.mjs:40-44,82-86` (`getUserCredentials`, `getUserToken`) | Entschlüsselt die Zugangsdaten für jeden Gitea-API-Aufruf und erneuert sie vorher, wenn das Token bald abläuft: `services/web/modules/gitea-sync/app/src/GiteaSyncHandler.mjs` (zum Beispiel `:27`) und `services/web/modules/gitea-sync/app/src/GitMerge.mjs:52`. Ohne Dokument oder mit Zugangsdaten, die sich nicht entschlüsseln oder erneuern lassen, wirft es `InvalidTokenError`, und der Benutzer gilt als nicht verknüpft (`GiteaSyncHandler.mjs:25-37`). |
| `services/web/modules/admin-tools/app/src/AdminUserListManager.mjs:395` | Prüft, ob der Benutzer ein Dokument hat, für die im Admin-Panel angezeigten Integrationen. |

#### Indizes {#indexes}

| Name | Schlüssel | Optionen | Migration |
| ---- | ---- | ------- | --------- |
| `_id_` | `_id: 1` | | default |

Mongoose-`autoIndex` ist ausgeschaltet (`services/web/app/src/infrastructure/Mongoose.mjs:7`), daher erzeugt das `unique: true` des Schemas auf `userId` nichts. Keine Migration erstellt Indizes für diese Collection.

#### Hinweise {#notes}

* Eine Änderung von `GITEA_TOKEN_CIPHER_PASSWORD` macht die gespeicherten Zugangsdaten unlesbar. Diese Benutzer gelten dann als nicht verknüpft, bis sie erneut verknüpfen.
* Ein gelöschter Benutzer behält das Dokument, bis der Benutzer abläuft.
