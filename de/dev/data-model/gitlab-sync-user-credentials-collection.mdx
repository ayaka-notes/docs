title: GitLab-Sync-User-Credentials-Collection

`gitlabSyncUserCredentials` enthält ein Dokument pro Benutzer, der ein GitLab-Konto für GitLab Sync verknüpft hat. Sie speichert die OAuth-Tokens des Benutzers verschlüsselt. Die Collection gehört zum Web-Modul `gitlab-sync` (`services/web/modules/gitlab-sync`). Das Schema liegt in `services/web/modules/gitlab-sync/app/models/gitlabSyncUserCredentials.mjs`, und jeder Zugriff läuft über `services/web/modules/gitlab-sync/app/src/TokenManager.mjs`.

#### Felder {#fields}

| Feld | Typ | Bedeutung | Quelle |
| ----- | ---- | ------- | ------ |
| `_id` | ObjectId | Wird von Mongoose gesetzt, wenn der Upsert einfügt. | |
| `userId` | ObjectId | Der Overleaf-Benutzer. Pflichtfeld. Das Schema sagt `unique: true`, aber es wird kein Index erstellt (siehe Indizes); der Upsert nach `userId` hält ein Dokument pro Benutzer. | `gitlabSyncUserCredentials.mjs:8`, `TokenManager.mjs:88-95` |
| `gitlab` | String | Das JSON `{ accessToken, refreshToken, expiresAt }`, verschlüsselt mit `@overleaf/access-token-encryptor`. `expiresAt` ist in Millisekunden seit der Epoche oder `null`; `refreshToken` kann `null` sein. Das Passwort kommt aus `GITLAB_TOKEN_CIPHER_PASSWORD`; das Cipher-Label ist `GITLAB_TOKEN_CIPHER_LABEL`, Standard `2026.10-v3`. Pflichtfeld. | `gitlabSyncUserCredentials.mjs:9-10`, `TokenManager.mjs:18-31`, `services/web/modules/gitlab-sync/app/src/GitLabApiClient.mjs:209-220` |
| `__v` | Number | Der Mongoose-Versionsschlüssel. Das Schema schaltet ihn nicht ab. | Mongoose-Standard |

#### Wer sie schreibt {#who-writes-it}

| Code | Was er tut |
| ---- | ------------ |
| `TokenManager.mjs:88-95` (`saveUserToken`) | Speichert per Upsert die verschlüsselten Zugangsdaten des Benutzers. |
| `TokenManager.mjs:99-108` (`linkUserToken`) | Speichert neue Zugangsdaten aus dem OAuth-Callback (`services/web/modules/gitlab-sync/app/src/GitLabSyncController.mjs:146`). Wenn der Benutzer erneut verknüpft, wird das ersetzte Access-Token im Hintergrund bei GitLab widerrufen. |
| `TokenManager.mjs:53-78` (`refreshUserToken`) | Wenn das Access-Token weniger als 5 Minuten vor `expiresAt` liegt (`:13,47-49`), holt es mit dem Refresh-Token neue Tokens und speichert sie (`:75`). Es läuft unter dem Lock `gitlabSyncToken` pro Benutzer (`:15,54`), weil GitLab ein Refresh-Token bei der Verwendung verbraucht. |
| `TokenManager.mjs:111-126` (`removeUserToken`) | Widerruft das Access-Token bei GitLab (nach bestem Bemühen) und löscht dann das Dokument. Aufgerufen beim Trennen (`GitLabSyncController.mjs:173`) und wenn ein gelöschter Benutzer abläuft (`services/web/modules/gitlab-sync/index.mjs:56-58`). |

#### Wer sie liest {#who-reads-it}

| Code | Was er tut |
| ---- | ------------ |
| `TokenManager.mjs:41-45,81-85` (`getUserCredentials`, `getUserToken`) | Entschlüsselt die Zugangsdaten für jeden GitLab-API-Aufruf und erneuert sie vorher, wenn das Token bald abläuft: `services/web/modules/gitlab-sync/app/src/GitLabSyncHandler.mjs` (zum Beispiel `:27`) und `services/web/modules/gitlab-sync/app/src/GitMerge.mjs:52`. Ohne Dokument oder mit Zugangsdaten, die sich nicht entschlüsseln oder erneuern lassen, wirft es `InvalidTokenError`, und der Benutzer gilt als nicht verknüpft (`GitLabSyncHandler.mjs:25-37`). |
| `services/web/modules/admin-tools/app/src/AdminUserListManager.mjs:394` | Prüft, ob der Benutzer ein Dokument hat, für die im Admin-Panel angezeigten Integrationen. |

#### Indizes {#indexes}

| Name | Schlüssel | Optionen | Migration |
| ---- | ---- | ------- | --------- |
| `_id_` | `_id: 1` | | default |

Mongoose-`autoIndex` ist ausgeschaltet (`services/web/app/src/infrastructure/Mongoose.mjs:7`), daher erzeugt das `unique: true` des Schemas auf `userId` nichts. Keine Migration erstellt Indizes für diese Collection.

#### Hinweise {#notes}

* Eine Änderung von `GITLAB_TOKEN_CIPHER_PASSWORD` macht die gespeicherten Zugangsdaten unlesbar. Diese Benutzer gelten dann als nicht verknüpft, bis sie erneut verknüpfen.
* Ein gelöschter Benutzer behält das Dokument, bis der Benutzer abläuft.
