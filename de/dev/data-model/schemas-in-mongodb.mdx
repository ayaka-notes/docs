In diesem Abschnitt besprechen wir das Datenmodell von Overleaf. Overleaf verwendet MongoDB zur Datenpersistenz. Die einzige Datenbank heißt `sharelatex` – so hieß auch der Vorgänger von Overleaf.

Die Entwicklungsumgebung führt Mongo Express bereits neben Mongo aus (siehe [setup-develop-tools.md](/de/dev/environment/setup-develop-tools  "mention")). Öffnen Sie [http://localhost:8081/](http://localhost:8081/) und melden Sie sich mit `admin:pass` an.

</Frame>

Sie können auch aus dem Verzeichnis `develop` eine Shell im Mongo-Container öffnen:

```bash
bin/docker-compose exec mongo mongosh sharelatex
```

#### Wie die Seiten aufgebaut sind {#how-the-pages-are-written}

* Jede Seite listet die Felder auf, die der Code schreibt, mit Typ, Bedeutung und der Codezeile, die sie belegt: eine Zeile eines Mongoose-Schemas oder die Stelle, die das Feld schreibt. Felder, die nur eine Migration, ein Skript oder eines der Web-Module schreibt, sind entsprechend gekennzeichnet.
* Viele Collections haben kein Mongoose-Schema: Die Dienste schreiben sie mit dem MongoDB-Treiber.
* Indizes werden nur von den Migrationen in `tools/migrations/` angelegt. CE führt die mit `server-ce` markierten bei jedem Start aus (`server-ce/init_scripts/900_run_web_migrations.sh`); Mongoose `autoIndex` ist ausgeschaltet (`services/web/app/src/infrastructure/Mongoose.mjs:7`). Die Indextabellen listen nur auf, was eine CE-Instanz am Ende hat.
* Der Text der Docs liegt in Mongo, anderer Inhalt nicht. Dateiinhalte werden als Blobs und der Verlauf als Chunks in den Buckets von history-v1 gespeichert (lokale Ordner oder S3 / RustFS); geöffnete Docs liegen in Redis, bis document-updater sie flusht.
