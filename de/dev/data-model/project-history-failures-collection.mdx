`projectHistoryFailures` enthält ein Dokument pro Projekt, dessen History-Updates project-history nicht verarbeiten konnte oder für das es einen Resync gestartet hat. Sobald die Verarbeitung funktioniert, wird das Dokument wieder gelöscht. project-history schreibt sie in `services/project-history/app/js/ErrorRecorder.js`; ihr Typ steht in `services/project-history/app/js/mongo-types.ts:3-24`. Web hat dafür ebenfalls ein Mongoose-Schema (`services/web/app/src/models/ProjectHistoryFailure.mjs:5-19`), aber kein Web-Code verwendet dieses Modell.

#### Hinweise {#notes}

* Ein Dokument bleibt, bis ein Flush des Projekts gelingt oder das Projekt gelöscht wird (`clearError` oben). Jedes Dokument markiert also ein Projekt, dessen letzter Flush oder Resync noch nicht gelungen ist.
* Fehlerstrings, die mit `OError:` beginnen, werden als `Error:` zurückgegeben (`ErrorRecorder.js:18-26`); der gespeicherte Wert bleibt unverändert.
