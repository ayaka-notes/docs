`githubSyncUserCredentials` enthält ein Dokument pro Benutzer, der ein GitHub-Konto für GitHub Sync verknüpft hat. Sie speichert das OAuth-Access-Token des Benutzers verschlüsselt. Die Collection gehört zum Web-Modul `github-sync` (`services/web/modules/github-sync`). Das Schema liegt in `services/web/modules/github-sync/app/models/githubSyncUserCredentials.mjs`, und jeder Zugriff läuft über `services/web/modules/github-sync/app/src/TokenManager.mjs`.

#### Felder {#fields}

| Feld | Typ | Bedeutung | Quelle |
| ----- | ---- | ------- | ------ |
| `_id` | ObjectId | Wird von Mongoose gesetzt, wenn der Upsert einfügt. | |
| `userId` | ObjectId | Der Overleaf-Benutzer. Pflichtfeld. Das Schema sagt `unique: true`, aber es wird kein Index erstellt (siehe Indizes); der Upsert nach `userId` hält ein Dokument pro Benutzer. | `githubSyncUserCredentials.mjs:8`, `TokenManager.mjs:44-48` |
| `github` | String | Das GitHub-OAuth-Access-Token, verschlüsselt mit `@overleaf/access-token-encryptor`. Das Passwort kommt aus `GITHUB_TOKEN_CIPHER_PASSWORD`; das Cipher-Label ist `GITHUB_TOKEN_CIPHER_LABEL`, Standard `2026.3-v3`. Pflichtfeld. | `githubSyncUserCredentials.mjs:9`, `TokenManager.mjs:12-25` |
| `__v` | Number | Der Mongoose-Versionsschlüssel. Das Schema schaltet ihn nicht ab. | Mongoose-Standard |

Gespeichert wird nur das Access-Token: Der OAuth-Callback behält `access_token` aus der Antwort von GitHub (`services/web/modules/github-sync/app/src/GitHubApiClient.mjs:180-191`). Es gibt kein Refresh-Token und keinen Ablauf.

#### Wer sie schreibt {#who-writes-it}

| Code | Was er tut |
| ---- | ------------ |
| `TokenManager.mjs:42-58` (`saveUserToken`) | Speichert per Upsert das verschlüsselte Token des Benutzers. Wenn der Benutzer erneut verknüpft, wird das ersetzte Token im Hintergrund bei GitHub widerrufen. Aufgerufen vom OAuth-Callback (`services/web/modules/github-sync/app/src/GitHubSyncController.mjs:146`). |
| `TokenManager.mjs:61-76` (`removeUserToken`) | Widerruft das Token bei GitHub (nach bestem Bemühen) und löscht dann das Dokument. Aufgerufen beim Trennen (`GitHubSyncController.mjs:167`) und wenn ein gelöschter Benutzer abläuft (`services/web/modules/github-sync/index.mjs:66-68`). |

#### Wer sie liest {#who-reads-it}

| Code | Was er tut |
| ---- | ------------ |
| `TokenManager.mjs:36-40` (`getUserToken`) | Entschlüsselt das Token für jeden GitHub-API-Aufruf: `services/web/modules/github-sync/app/src/GitHubSyncHandler.mjs` (zum Beispiel `:27`) und `services/web/modules/github-sync/app/src/GitMerge.mjs:43`. Ohne Dokument oder mit einem Token, das sich nicht entschlüsseln lässt, wirft es `InvalidTokenError`, und der Benutzer gilt als nicht verknüpft (`GitHubSyncHandler.mjs:25-37`). |
| `services/web/modules/admin-tools/app/src/AdminUserListManager.mjs:393` | Prüft, ob der Benutzer ein Dokument hat, für die im Admin-Panel angezeigten Integrationen. |

#### Indizes {#indexes}

| Name | Schlüssel | Optionen | Migration |
| ---- | ---- | ------- | --------- |
| `_id_` | `_id: 1` | | default |

Mongoose-`autoIndex` ist ausgeschaltet (`services/web/app/src/infrastructure/Mongoose.mjs:7`), daher erzeugt das `unique: true` des Schemas auf `userId` nichts. `tools/migrations/20190912145011_create_githubSyncUserCredentials_indexes.mjs` (Upstreams `user_id`) ist nur mit `saas` getaggt und läuft in CE nicht.

#### Hinweise {#notes}

* Eine Änderung von `GITHUB_TOKEN_CIPHER_PASSWORD` macht die gespeicherten Tokens unlesbar. Diese Benutzer gelten dann als nicht verknüpft, bis sie erneut verknüpfen.
* Ein gelöschter Benutzer behält das Dokument, bis der Benutzer abläuft.
