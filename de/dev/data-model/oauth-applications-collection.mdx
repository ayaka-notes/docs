`oauthApplications` enthält die OAuth-Clients, die Web kennt. Ein Dokument ist ein Client. In Ayakaleaf Pro schreibt nur das Web-Modul `git-bridge` hinein: Es legt beim Start von Web einen Client namens `Overleaf Git Bridge` an. Das Schema ist `services/web/app/src/models/OauthApplication.mjs`.

#### Felder {#fields}

| Feld | Typ | Bedeutung | Quelle |
| ----- | ---- | ------- | ------ |
| `_id` | ObjectId | Dokument-ID des Clients. `oauthAccessTokens.oauthApplication_id` und `oauthAuthorizationCodes.oauthApplication_id` verweisen darauf. | `OauthApplication.mjs:5` |
| `id` | String | Client-ID: 64 zufällige Kleinbuchstaben und Ziffern. | `OauthApplication.mjs:7`, `services/web/modules/git-bridge/index.mjs:25` |
| `clientSecret` | String | Client-Secret, geschrieben als `v1.` plus 32 zufällige Zeichen. Nur `getClient` liest es, und nichts ruft `getClient` auf (siehe Hinweise). | `OauthApplication.mjs:8`, `git-bridge/index.mjs:26` |
| `grants` | Array of String | Grant-Typen. Der Git-Bridge-Client hat `['password']`. Wird mit dem Client zurückgegeben, wenn ein Token geprüft wird (`services/web/modules/oauth2-server/app/src/OAuth2Model.mjs:67-72`). | `OauthApplication.mjs:9`, `git-bridge/index.mjs:27` |
| `name` | String | Name des Clients. Das Git-Bridge-Modul und der Code für persönliche Zugriffstoken finden den Client über den Namen `Overleaf Git Bridge`. | `OauthApplication.mjs:10`, `git-bridge/index.mjs:15-16,28` |
| `redirectUris` | Array of String | Erlaubte Redirect-URIs. `[]` beim Git-Bridge-Client. | `OauthApplication.mjs:11`, `git-bridge/index.mjs:29` |
| `scopes` | Array of String | Scopes, die der Client verwenden darf. `['git_bridge']` beim Git-Bridge-Client. | `OauthApplication.mjs:12`, `git-bridge/index.mjs:30` |
| `pkceEnabled` | Boolean | Nur im Schema: Kein Code in diesem Repository schreibt es, und nur das ungenutzte `getClient` liest es (`OAuth2Model.mjs:207`). | `OauthApplication.mjs:13` |

#### Wer schreibt {#who-writes-it}

| Code | Funktion |
| ---- | ------------ |
| `git-bridge/index.mjs:9-35` (module `git-bridge`) | Wenn `GIT_BRIDGE_ENABLED` auf `true` steht, legt es beim Start von Web den Client `Overleaf Git Bridge` an, sofern noch kein Client mit diesem Namen existiert. |

#### Wer liest {#who-reads-it}

| Code | Funktion |
| ---- | ------------ |
| `services/web/modules/oauth2-server/app/src/OAuthPersonalAccessTokenManager.mjs:53-61` (module `oauth2-server`) | Findet den Client `Overleaf Git Bridge` über den Namen und speichert seine `_id` in jedem neuen persönlichen Zugriffstoken. Ohne den Client wird kein Token erstellt. |
| `OAuth2Model.mjs:31-39,67-72` (`getAccessToken`) | Lädt den Client eines Tokens über `oauthApplication_id` und gibt seine `id` und `grants` zurück. |
| `OAuth2Model.mjs:185-209,241,275` (`getClient`, `saveToken`, `saveAuthorizationCode`) | Suchen Clients über `id`. In diesem Repository nie erreicht, siehe Hinweise. |

#### Indizes {#indexes}

Nur der Standardindex auf `_id`. Der eindeutige Index `id_1` stammt aus Migrationen mit den Tags `saas` (`20190912145016_create_oauthApplications_indexes.mjs`) und `server-pro` (`20230502180757_server_pro_oauth_indexes.mjs`), die die Community Edition nicht ausführt.

#### Hinweise {#notes}

* Web nutzt `@node-oauth/oauth2-server` nur zum Prüfen von Bearer-Token (`server.authenticate` in `services/web/app/src/Features/Authentication/AuthenticationController.mjs:409-450`), was nur `getAccessToken` und `verifyScope` des Modells aufruft. Keine Route bedient `/oauth/token` oder `/oauth/authorize`, daher werden `getClient`, `saveToken` und `saveAuthorizationCode` nie aufgerufen.
* Das Modul sucht den Client über den Namen und legt ihn dann an, und die Community Edition hat keinen eindeutigen Index auf `name` oder `id`. Nichts verhindert also einen zweiten Client mit demselben Namen. Code, der den Client braucht, nimmt den, den `findOne` zurückgibt.
