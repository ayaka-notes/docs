---
title: Tokens-Collection
icon: key
---

`tokens` enthält Einmal-Token: das Geheimnis in einem Link, mit dem jemand ein Passwort festlegen kann. Ein Dokument ist ein Token. Es gibt kein Mongoose-Modell; Web schreibt die Collection über `services/web/app/src/Features/Security/OneTimeTokenHandler.mjs` mit dem nativen Treiber.

#### Felder {#fields}

| Feld | Typ | Bedeutung | Quelle |
| ----- | ---- | ------- | ------ |
| `_id` | ObjectId | Dokument-ID. | `OneTimeTokenHandler.mjs:40` |
| `use` | String | Wofür das Token gedacht ist, siehe [Verwendungen](#uses) unten. Jede Abfrage filtert darauf. | `OneTimeTokenHandler.mjs:41` |
| `token` | String | Das Geheimnis im Link: 32 zufällige Bytes als 64 Hex-Zeichen, unverändert gespeichert. | `OneTimeTokenHandler.mjs:38,42` |
| `data` | Object | Wofür das Token steht; wird beim Verwenden zurückgegeben. | `OneTimeTokenHandler.mjs:43` |
| `data.user_id` | String | ID des Benutzers, von jedem Aufrufer als String geschrieben. | `services/web/app/src/Features/PasswordReset/PasswordResetHandler.mjs:27`, `services/web/app/src/Features/User/UserRegistrationHandler.mjs:117`, `services/web/modules/admin-tools/app/src/AdminUserManager.mjs:79` |
| `data.email` | String | E-Mail-Adresse des Benutzers zum Zeitpunkt der Erstellung. Ein Passwort-Reset sucht den Benutzer über diese Haupt-E-Mail-Adresse (`PasswordResetHandler.mjs:66-70`). | wie bei `data.user_id` |
| `createdAt` | Date | Erstellungszeit. Der TTL-Index löscht das Token 90 Tage später. | `OneTimeTokenHandler.mjs:36,44` |
| `expiresAt` | Date | `createdAt` plus `expiresIn` Sekunden: standardmäßig 1 Stunde, 1 Woche für einen Aktivierungslink. Abfragen ignorieren ein Token nach diesem Zeitpunkt. | `OneTimeTokenHandler.mjs:35-37,45` |
| `peekCount` | Number | Wie oft das Token angesehen wurde, ohne verwendet zu werden. Jedes `peekValueFromToken` erhöht um 1; bei 4 (`MAX_PEEKS`) funktioniert das Token nicht mehr. | `OneTimeTokenHandler.mjs:8-31,107` |
| `usedAt` | Date | Zeitpunkt, an dem das Token verwendet oder widerrufen wurde. Abfragen ignorieren ein Token, das es hat. | `OneTimeTokenHandler.mjs:51-104` |

#### Verwendungen {#uses}

| `use` | Funktion | Ablauf | Code |
| ----- | ------- | ------ | ---- |
| `password` | E-Mail zum Zurücksetzen des Passworts, von der Seite „Passwort vergessen“ | 1 Stunde | `PasswordResetHandler.mjs:14-42` |
| `password` | Aktivierungslink: ein Konto mit zufälligem Passwort, dann ein Link zum Festlegen eines Passworts. Verwendet von der öffentlichen Registrierung (`services/web/modules/login-register/app/src/RegisterController.mjs:65`), der Admin-Registrierungsseite von `user-activate` (`services/web/modules/user-activate/app/src/UserActivateController.mjs:27-30`) und dem Skript `create-user` (`services/web/modules/server-ce-scripts/scripts/create-user.mjs:21`) | 1 Woche | `UserRegistrationHandler.mjs:97-130` |
| `password` | Aktivierungs- oder Passwort-Reset-Link aus dem Admin-Panel (Modul `admin-tools`) | 1 Woche (Aktivierung), 1 Stunde (Reset) | `AdminUserManager.mjs:76-103,196-206` |
| `email_confirmation` | Link zur Bestätigung der E-Mail-Adresse. Wird nur gelesen: Nichts in diesem Repository erstellt solche Token mehr, da die Bestätigung jetzt einen 6-stelligen Code sendet (`services/web/app/src/Features/User/UserEmailsConfirmationHandler.mjs:15-35`) | | `UserEmailsConfirmationHandler.mjs:12,37-66` |

#### Wer schreibt {#who-writes-it}

| Code | Funktion |
| ---- | ------------ |
| `OneTimeTokenHandler.mjs:34-49` (`getNewToken`) | Fügt ein Token ein. Aufrufer: `PasswordResetHandler.mjs:28`, `UserRegistrationHandler.mjs:115-119`, `AdminUserManager.mjs:77-81`. |
| `OneTimeTokenHandler.mjs:8-32` (`peekValueFromToken`) | Gibt `data` eines gültigen Tokens zurück und erhöht `peekCount` um 1. Verwendet beim Öffnen der Seite zum Zurücksetzen des Passworts (`services/web/app/src/Features/PasswordReset/PasswordResetController.mjs:195-208`), erneut beim Festlegen des neuen Passworts (`PasswordResetHandler.mjs:94-96`) und von der E-Mail-Bestätigung (`UserEmailsConfirmationHandler.mjs:38-41`). |
| `OneTimeTokenHandler.mjs:75-88` (`expireToken`) | Setzt `usedAt` bei einem Token: nachdem ein neues Passwort festgelegt (`PasswordResetHandler.mjs:44-48,119`) oder eine E-Mail-Adresse bestätigt wurde (`UserEmailsConfirmationHandler.mjs:65`). |
| `OneTimeTokenHandler.mjs:90-104` (`expireAllTokensForUser`) | Setzt `usedAt` bei jedem offenen `password`-Token eines Benutzers, wenn der Benutzer das Passwort in den Einstellungen ändert (`services/web/app/src/Features/User/UserController.mjs:146-149`) oder ein Admin es im Admin-Panel setzt (`AdminUserManager.mjs:479-488`). |

#### Wer liest {#who-reads-it}

| Code | Funktion |
| ---- | ------------ |
| `PasswordResetHandler.mjs:50-70,94-119` | Ermittelt aus einem Reset- oder Aktivierungstoken den Benutzer und setzt dann das Passwort. Die Aktivierungsseite von `user-activate` reicht das Token nur an dieses Formular weiter. |
| `UserEmailsConfirmationHandler.mjs:37-66` | Bestätigt eine E-Mail-Adresse anhand eines `email_confirmation`-Tokens des angemeldeten Benutzers. |
| `AdminUserManager.mjs:213-223` (module `admin-tools`) | Findet das offene Aktivierungstoken eines Benutzers, um den Aktivierungslink im Admin-Panel erneut anzuzeigen. Liest `db.tokens` direkt. |

#### Hinweise {#notes}

* Ein verwendetes oder abgelaufenes Token wird nicht sofort gelöscht: Es bleibt mit `usedAt` oder einem vergangenen `expiresAt` bestehen, bis der TTL-Index es 90 Tage nach `createdAt` entfernt.
* `OneTimeTokenHandler` hat außerdem `getValueFromTokenAndExpire` (`OneTimeTokenHandler.mjs:51-73`), aber nichts ruft es auf.
