### Docker

Docker bietet eine leichtgewichtige und portable Möglichkeit, Anwendungen in isolierten Containern zu paketieren und auszuführen. Indem die Anwendung zusammen mit allen benötigten Abhängigkeiten gebündelt wird, sorgt ein Container für ein konsistentes Verhalten auf unterschiedlichen Rechnern – vom Laptop bis zum Produktionsserver.

TeX Live ist leistungsfähig, aber groß und empfindlich gegenüber Unterschieden auf Systemebene. Wird TeX Live in ein Docker-Image verpackt, wird die LaTeX-Toolchain vorhersehbar, reproduzierbar und einfach zu verteilen.

Einige TeX Live-Pakete sind jedoch auf Shell-Zugriff angewiesen. Aus Sicherheitsgründen sollte der Container in einer eingeschränkten Umgebung laufen, die verhindert, dass Benutzer beliebige Shell-Befehle ausführen (zum Beispiel über `\write18` oder Shell Escape). Diese Isolation schützt das Host-System und verhindert unbeabsichtigten Zugriff auf das zugrunde liegende Dateisystem des Containers oder auf Werkzeuge wie `bash`.

### TeXLive Full Edition

[TeXLive-Full@ayaka-notes](https://github.com/ayaka-notes/texlive-full/) ist ein voll ausgestattetes **TeXLive-Docker-Image**, das für die isolierte LaTeX-Kompilierung in [Ayakaleaf Pro](https://github.com/ayaka-notes/ayakaleaf-pro), [Overleaf CEP](https://github.com/yu-i-i/overleaf-cep) oder in eigenständigen LaTeX-Kompilierumgebungen konzipiert ist.

Dieses Image soll eine nahezu vollständige TeXLive-Distribution mit vorinstallierten gängigen Schriften und Werkzeugen bereitstellen, um Kompilierfehler durch fehlende Pakete oder Schriften zu minimieren. Hinweis: Dieses Docker-Image **enthält keine** sharelatex/overleaf-Komponenten. Es wird für die Kompilierung in Overleaf/Overleaf Pro verwendet.

#### Funktionen:

* 🚀 Unterstützung für x86\_64- und arm64-Serverarchitekturen
* 📦 Vollständige und optimierte TeXLive-Installation
* 🧩 Vorinstallierte gängige Schriften und Hilfsprogramme
* 🐳 Sofort einsatzbereit mit Docker und Docker Compose
* 🧪 Getestet mit Overleaf Server Pro / Overleaf Pro
* 🔄 Regelmäßig mit den neuesten TeXLive-Versionen aktualisiert
* 🏷 Mehrere Tags für TeXLive-Versionen (2020 – aktuell)
* 🧑‍🔬 Knitr-Unterstützung für R-Code in LaTeX-Dokumenten

### Verwendung mit Ayakaleaf Pro

TeX Live Full von Ayaka-notes wurde speziell für [ayakaleaf-pro](https://github.com/ayaka-notes/ayakaleaf-pro) entwickelt. Wenn Sie das [Toolkit](https://github.com/overleaf/toolkit) verwenden, können Sie die folgenden Umgebungsvariablen in der Datei `config/variables.env` setzen.

Zum Beispiel:

```dotenv title="config/variables.env" wrap
ALL_TEX_LIVE_DOCKER_IMAGES=ghcr.io/ayaka-notes/texlive-full:2026.1, ghcr.io/ayaka-notes/texlive-full:2025.1
ALL_TEX_LIVE_DOCKER_IMAGE_NAMES=Texlive 2026, Texlive 2025
TEX_LIVE_DOCKER_IMAGE=ghcr.io/ayaka-notes/texlive-full:2026.1
```

### TeX Live-Versionen

Dank GitHub Action können wir alle TeX-Images parallel bauen. Dazu gehören:

* `ghcr.io/ayaka-notes/texlive-full:2026.1` (auch Tag `latest`)
* `ghcr.io/ayaka-notes/texlive-full:2025.1`
* `ghcr.io/ayaka-notes/texlive-full:2024.1`
* `ghcr.io/ayaka-notes/texlive-full:2023.1`
* `ghcr.io/ayaka-notes/texlive-full:2022.1`
* `ghcr.io/ayaka-notes/texlive-full:2021.1`
* `ghcr.io/ayaka-notes/texlive-full:2020.1`
* `ghcr.io/ayaka-notes/texlive-full:base`

Wir verwenden das Mirror-Archiv von [texlive info](https://texlive.info/tlnet-archive/), das nahezu alle TeX Live-Versionen von 1996 bis 2025 enthält. Und dank des Dockerfiles von Overleaf können wir dieses Projekt schneller bauen.

> Warum werden TeX Live 2019 und ältere Versionen nicht unterstützt?
>
> Die Pflege dieser alten Images ist äußerst schwierig. Außerdem stellt die Website [texlive.info](https://texlive.info/) keine Informationen für TeX Live-Versionen bereit, die vor 2019 veröffentlicht wurden, sodass wir für diese Versionen keine Images bauen können. Wenn Sie eine bestimmte alte Version benötigen, eröffnen Sie bitte ein Issue und teilen Sie es uns mit.

### Probleme

<Accordion title="Problem 01: Fehlende Schriften im Font-Cache">

Wenn Overleaf ein LaTeX-Projekt kompiliert und eine Schrift fehlt, **stellen Sie möglicherweise fest, dass der Kompiliervorgang sehr lange dauert**. Das liegt daran, dass TeX Live bei einer fehlenden Schrift versucht, **den gesamten Font-Cache neu aufzubauen**. Dies ist ein zeitaufwendiger Vorgang.

In unserem Image haben wir den Font-Cache vorab erstellt; wir haben dieses Problem mit [diesem Commit](https://github.com/ayaka-notes/texlive-full/commit/0cb66b0dc8b82be628cf6999cfd659d9784e132f) behoben.

</Accordion>

<Accordion title="Problem 02: SyncTeX extrem langsam">

Wenn Sie dieses Image in sharelatex verwenden, stellen Sie möglicherweise fest, dass SyncTeX extrem langsam ist.

Siehe: [https://github.com/overleaf/overleaf/issues/1150](https://github.com/overleaf/overleaf/issues/1150) – deaktivieren Sie einfach HTTP 2.0.

</Accordion>

<Accordion title="Problem 03: Fehler beim erneuten Kompilieren mit dem offiziellen TeX Live-Image">

Wenn Sie das offizielle TeX Live-Image `texlive/texlive` von Docker Hub verwenden, stellen Sie möglicherweise fest, dass beim erneuten Kompilieren eines Projekts ein Fehler gemeldet wird. In unserem Image ist dieses Problem jedoch behoben, da wir das neueste Ubuntu-Basis-Image verwenden und alle Abhängigkeiten aus dem offiziellen Ubuntu-Repository installieren.

</Accordion>

### Weitere technische Hinweise

Beim Bauen von TeX Live-Images (vor 2019) müssen Sie möglicherweise auf folgende Probleme achten:

* Vor TeX Live 2017 werden nur `http`/`ftp` unterstützt, sodass Sie nicht über `https` herunterladen können, es sei denn, Sie passen das `peal`-Skript an.
* Vor 2015 wird nur eine sha256-Datei bereitgestellt. Sie können daher nicht mit sha512 prüfen.
