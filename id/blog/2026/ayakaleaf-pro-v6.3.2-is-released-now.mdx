Dengan sangat bangga kami mengumumkan rilis Overleaf Pro 6.3.2. Upstream Overleaf 6.3.2 adalah rilis keamanan yang memperbarui Node.js, dan kami merilisnya bersama anggota baru keluarga sinkronisasi: setelah GitHub, GitLab, dan Dropbox, proyek Anda kini juga dapat berada di Gitea.

### Perubahan

* Sinkronisasi Gitea (pratinjau awal): sinkronisasi dua arah dengan gitea.com atau Gitea self-hosted Anda.
* Node.js 24.22.1: pembaruan keamanan di upstream Overleaf 6.3.2.
* Perbaikan bug yang ditemukan oleh sistem pengujian E2E kami dan Internal Horizon Issue Investigation.

<Info>

Sinkronisasi Gitea disertakan di 6.3.2 sebagai **pratinjau awal** untuk pengujian bertahap, dan akan dirilis secara resmi di v6.4.0. Konfigurasi dan perilakunya masih dapat berubah sebelum itu. Fitur ini nonaktif secara default. Silakan laporkan masalah apa pun di [GitHub](https://github.com/ayaka-notes/ayakaleaf-pro/issues).

</Info>

#### Fitur 01: Sinkronisasi Gitea (Pratinjau)

Banyak laboratorium dan tim kecil menjalankan Gitea mereka sendiri, karena cukup ringan untuk satu server kecil. Sinkronisasi Gitea bekerja dengan cara yang sama seperti Sinkronisasi GitHub dan Sinkronisasi GitLab: tautkan akun Anda, impor repositori dari menu proyek baru, atau ekspor proyek ke repositori Gitea baru. Lalu lakukan push dan pull dari editor, dan merge melalui pull request dengan gaya merge milik repositori itu sendiri. Overleaf tidak pernah melewati proteksi branch Anda: jika pull request memerlukan persetujuan atau pemeriksaan yang berhasil, Overleaf menunggu Anda menggabungkannya di Gitea.

Fitur ini berfungsi dengan gitea.com dan dengan Gitea self-hosted 1.23 atau yang lebih baru. Atur `GITEA_SYNC_ENABLED`, `GITEA_SYNC_CLIENT_ID`, `GITEA_SYNC_CLIENT_SECRET`, dan `GITEA_TOKEN_CIPHER_PASSWORD`, serta `GITEA_SYNC_URL` untuk instance self-hosted.

Lihat [Sinkronisasi Gitea](/id/on-premises/configuration/overleaf-toolkit/gitea-synchronisation  "mention") untuk petunjuk penyiapan lengkap.

#### Perbaikan bug

* **Sinkronisasi Git**: jika file yang dihapus di GitHub, GitLab, atau Gitea tidak dapat dihapus di Overleaf, sinkronisasi kini gagal dan dapat dicoba ulang, alih-alih melaporkan keberhasilan dan meninggalkan file tersebut. `git push` yang menghapus file gagal dengan cara yang sama.
* **Git bridge**: dokumen yang dibuat di editor dengan ekstensi non-teks (seperti `.csv`) tetap dapat disunting ketika `git push` mengubahnya.
* **Track changes**: editor yang belum masuk pada proyek yang dibagikan melalui tautan dapat menghapus thread komentar, tetapi tidak lagi dapat menyelesaikan atau membukanya kembali, dan reviewer dapat menghapus balasan mereka sendiri.
* **Galeri templat**: memublikasikan templat memerlukan akses ke proyek.
* **Learn**: halaman bantuan yang di-cache tetap tersedia ketika wiki tidak dapat dijangkau.

Lihat [catatan rilis 6.3.2](/id/on-premises/release-notes/release-notes-6.x.x#ayakaleaf-pro-6.3.2  "mention") untuk daftar lengkapnya.

#### Upgrade

* Dari 6.3.1 atau 6.3.0: tidak diperlukan migrasi. Tarik image baru lalu mulai ulang.
* Dari 6.2.x atau sebelumnya dengan Zotero atau Mendeley yang digunakan: jalankan terlebih dahulu [migrasi Zotero / Mendeley](/id/on-premises/release-notes/release-notes-6.x.x#ayakaleaf-pro-6.3.0  "mention") dari 6.3.0.
* Sinkronisasi Gitea nonaktif secara default dan hanya memerlukan variabel lingkungan baru.
