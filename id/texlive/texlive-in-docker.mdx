### Docker

Docker menyediakan cara yang ringan dan portabel untuk mengemas dan menjalankan aplikasi di dalam container yang terisolasi. Dengan menggabungkan aplikasi beserta semua dependensi yang diperlukan, container memastikan perilaku yang konsisten di berbagai mesin, mulai dari laptop hingga server produksi.

TeX Live sangat andal tetapi berukuran besar dan sensitif terhadap perbedaan tingkat sistem. Mengemas TeX Live di dalam image Docker membuat toolchain LaTeX menjadi dapat diprediksi, dapat direproduksi, dan mudah didistribusikan.

Namun, beberapa paket TeX Live bergantung pada akses shell. Demi alasan keamanan, container sebaiknya berjalan di lingkungan terbatas yang mencegah pengguna mengeksekusi perintah shell sembarangan (misalnya melalui `\write18` atau shell escape). Isolasi ini melindungi sistem host dan mencegah akses yang tidak diinginkan ke filesystem dasar container atau alat-alat seperti `bash`.

### TeXLive Edisi Full

[TeXLive-Full@ayaka-notes](https://github.com/ayaka-notes/texlive-full/) adalah **image Docker TeXLive** berfitur lengkap yang dirancang untuk kompilasi LaTeX dalam sandbox di [Ayakaleaf Pro](https://github.com/ayaka-notes/ayakaleaf-pro), [Overleaf CEP](https://github.com/yu-i-i/overleaf-cep), atau lingkungan kompilasi LaTeX mandiri.

Image ini bertujuan menyediakan distribusi TeXLive yang hampir lengkap dengan font dan alat umum yang sudah terinstal, untuk meminimalkan kegagalan kompilasi akibat paket atau font yang hilang. Catatan: Image Docker ini **tidak berisi** komponen sharelatex/overleaf apa pun. Image ini digunakan untuk kompilasi Overleaf/Overleaf Pro.

#### Fitur:

* 🚀 Mendukung arsitektur server x86\_64 maupun arm64
* 📦 Instalasi TeXLive lengkap dan teroptimasi
* 🧩 Font dan utilitas umum sudah terinstal
* 🐳 Siap digunakan dengan Docker dan Docker Compose
* 🧪 Telah diuji dengan Overleaf Server Pro / Overleaf Pro
* 🔄 Diperbarui secara rutin dengan rilis TeXLive terbaru
* 🏷 Beberapa tag versi TeXLive (2020 – Terbaru)
* 🧑‍🔬 Dukungan Knitr untuk kode R dalam dokumen LaTeX

### Penggunaan di Ayakaleaf Pro

TeX Live Full oleh Ayaka-notes dirancang khusus untuk [ayakaleaf-pro](https://github.com/ayaka-notes/ayakaleaf-pro); Anda dapat menambahkan variabel lingkungan berikut ke file `config/variables.env` jika Anda adalah [pengguna toolkit](https://github.com/overleaf/toolkit).

Contoh:

```dotenv title="config/variables.env" wrap
ALL_TEX_LIVE_DOCKER_IMAGES=ghcr.io/ayaka-notes/texlive-full:2026.1, ghcr.io/ayaka-notes/texlive-full:2025.1
ALL_TEX_LIVE_DOCKER_IMAGE_NAMES=Texlive 2026, Texlive 2025
TEX_LIVE_DOCKER_IMAGE=ghcr.io/ayaka-notes/texlive-full:2026.1
```

### Versi TeX Live

Berkat Github Action, kami dapat membangun semua image tex secara paralel, yang meliputi:

* `ghcr.io/ayaka-notes/texlive-full:2026.1` (Juga tag `latest`)
* `ghcr.io/ayaka-notes/texlive-full:2025.1`
* `ghcr.io/ayaka-notes/texlive-full:2024.1`
* `ghcr.io/ayaka-notes/texlive-full:2023.1`
* `ghcr.io/ayaka-notes/texlive-full:2022.1`
* `ghcr.io/ayaka-notes/texlive-full:2021.1`
* `ghcr.io/ayaka-notes/texlive-full:2020.1`
* `ghcr.io/ayaka-notes/texlive-full:base`

Kami menggunakan arsip mirror dari [texlive info](https://texlive.info/tlnet-archive/), yang mencakup hampir semua image texlive mulai dari 1996 hingga 2025. Dan berkat Dockerfile milik Overleaf, kami dapat membangun proyek ini lebih cepat.

> Mengapa TeX Live 2019 dan versi sebelumnya tidak didukung?
>
> Memelihara image-image lama ini sangatlah sulit. Selain itu, situs web [texlive.info](https://texlive.info/) tidak menyediakan informasi untuk versi TeX Live yang dirilis sebelum 2019, sehingga kami tidak dapat membangun image untuk versi-versi tersebut. Jika Anda membutuhkan versi lama tertentu, silakan buka issue dan beri tahu kami.

### Komponen yang Disertakan

Paket-paket berikut disertakan dalam image docker.

* Semua paket TeXLive (pada tahun tersebut)
* Paket R (hanya yang terpilih)
* fontconfig inkscape pandoc python3-pygments wget python3
* gnupg gnuplot perl-modules perl ca-certificates
* ghostscript qpdf r-base-core tar

Font-font berikut disertakan dalam image docker.

* [Google Fonts](https://fonts.google.com/)
* [Microsoft msttcorefonts](https://packages.ubuntu.com/jammy/ttf-mscorefonts-installer)
* [Font yang didukung Overleaf](https://www.overleaf.com/learn/latex/Questions/Which_OTF_or_TTF_fonts_are_supported_via_fontspec%3F)

<Warning>

Harap pastikan apakah font yang bersangkutan dapat digunakan secara komersial. Kami **tidak bertanggung jawab** atas masalah hukum apa pun yang timbul dari penggunaan font yang tidak tepat oleh Anda. Setelah Anda mengunduh image, Anda secara otomatis menyetujui hal ini.

</Warning>

### Masalah

<Accordion title="Masalah 01: Font Cache Miss">

Saat overleaf mengompilasi proyek latex, jika terjadi font miss, **Anda mungkin mendapati proses kompilasi memakan waktu lama**. Hal ini terjadi karena saat sebuah font tidak ditemukan, texlive akan mencoba **membangun ulang seluruh cache font**. Ini adalah proses yang memakan waktu.

Di image kami, cache font telah dibangun sebelumnya; kami memperbaiki masalah ini melalui [commit ini](https://github.com/ayaka-notes/texlive-full/commit/0cb66b0dc8b82be628cf6999cfd659d9784e132f)

</Accordion>

<Accordion title="Masalah 02: Sync Tex Sangat Lambat">

Saat Anda menggunakan image ini di sharelatex, Anda mungkin mendapati sync tex sangat lambat.

Lihat: [https://github.com/overleaf/overleaf/issues/1150](https://github.com/overleaf/overleaf/issues/1150), cukup nonaktifkan http 2.0.

</Accordion>

<Accordion title="Masalah 03: Error Kompilasi Ulang dengan Image Texlive Resmi">

Jika Anda menggunakan image resmi texlive di docker hub `texlive/texlive`, Anda mungkin mendapati bahwa saat mengompilasi ulang sebuah proyek, akan muncul error. Namun, di image kami, masalah ini telah diperbaiki, karena kami menggunakan image dasar ubuntu terbaru dan menginstal semua dependensi dari repositori resmi ubuntu.

</Accordion>

### Catatan Teknis Lainnya

Saat membangun image texlive (sebelum 2019), Anda mungkin perlu memperhatikan masalah-masalah berikut:

* Hanya `http`/`ftp` yang didukung sebelum texlive 2017, sehingga Anda tidak dapat menggunakan `https` untuk mengunduh, kecuali Anda memodifikasi skrip `peal`.
* Sebelum 2015, hanya file sha256 yang disediakan, sehingga Anda tidak dapat menggunakan sha512 untuk pemeriksaan.
