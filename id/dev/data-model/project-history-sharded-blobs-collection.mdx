`projectHistoryShardedBlobs` menyimpan catatan blob yang tidak muat di [projectHistoryBlobs](/dev/data-model/project-history-blobs-collection): ketika bucket untuk sebuah prefiks hash di sana sudah berisi 8 catatan, catatan berikutnya masuk ke sini. Sebuah proyek memiliki paling banyak 16 dokumen di sini, satu per digit hex pertama hash. Tidak ada skema Mongoose; history-v1 menulisnya di `services/history-v1/storage/lib/blob_store/mongo.js` (tata letak dijelaskan di `mongo.js:1-16`).

#### Field {#fields}

| Field | Tipe | Arti | Sumber |
| ----- | ---- | ------- | ------ |
| `_id` | Binary | 13 byte: id riwayat proyek, sebuah `0`, dan digit shard, dibaca sebagai hex (`<history id>0<digit>`). Digit shard adalah digit hex pertama hash. | `mongo.js:439-453` |
| `blobs` | Object | Catatan blob yang dikelompokkan dalam bucket. Kunci bucket adalah digit hex ke-2 sampai ke-4 dari hash. | `mongo.js:439-443` |
| `blobs.<bcd>` | Array of Object | Catatan dalam bucket. Kode tidak membatasi ukurannya. | `mongo.js:399-407` |
| `blobs.<bcd>[].h` | Binary | Hash, 20 byte, seperti di projectHistoryBlobs. | `mongo.js:472` |
| `blobs.<bcd>[].b` | Number | Panjang konten dalam byte. | `mongo.js:473` |
| `blobs.<bcd>[].s` | Number | Panjang konten sebagai teks; `null` jika konten bukan teks yang dapat disunting. | `mongo.js:474` |

#### Siapa yang menulis {#who-writes-it}

| Kode | Fungsinya |
| ---- | ------------ |
| `services/history-v1/storage/lib/blob_store/mongo.js:399-407` | `insertRecordSharded`: upsert dengan `$addToSet` ke dalam bucket. Dipanggil oleh `insertBlob` ketika bucket di projectHistoryBlobs penuh (`mongo.js:387-389`). |
| `mongo.js:75-103` | `clone`: menyalin shard proyek ke id riwayat lain, untuk history-v1 `POST /projects/:project_id/clone`, yang tidak dipanggil oleh apa pun di web. |
| `mongo.js:413-422` | `deleteBlobs`: menghapus semua shard proyek beserta dokumen projectHistoryBlobs-nya, pada history-v1 `DELETE /projects/:project_id`. |

#### Siapa yang membaca {#who-reads-it}

| Kode | Fungsinya |
| ---- | ------------ |
| `mongo.js:144-157` | `findBlobSharded`: satu blob, hanya dicari ketika bucket-nya di projectHistoryBlobs berisi 8 catatan dan tidak memuatnya (`mongo.js:127-131`). |
| `mongo.js:217-260` | `findBlobsSharded`: blob yang tidak ditemukan `findBlobs` di projectHistoryBlobs (`mongo.js:202-206`). |
| `mongo.js:285-306` | `getProjectBlobs`: semua shard sebuah proyek. |
| `mongo.js:337-361` | `getProjectBlobsBatch`: semua shard dari beberapa proyek, untuk route statistik blob. |

#### Indeks {#indexes}

Hanya indeks bawaan `_id`. Tidak ada migrasi di `tools/migrations/` yang menambahkannya.

#### Catatan {#notes}

* Shard satu proyek berdampingan dalam urutan `_id`, sehingga kode menemukannya dengan rentang `_id` dari `<history id>00` sampai `<history id>0f` (`mongo.js:75-80`, `287-295`).
* Koleksi ini baru muncul ketika suatu proyek memiliki lebih dari 8 blob dengan prefiks hash 3 digit yang sama, jadi instance kecil mungkin sama sekali tidak memilikinya.
