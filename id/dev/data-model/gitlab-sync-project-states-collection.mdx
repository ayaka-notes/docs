`gitlabSyncProjectStates` menyimpan satu dokumen per proyek yang ditautkan ke proyek GitLab: repositori mana, dan di mana sinkronisasi terakhir berhenti. Koleksi ini milik modul web `gitlab-sync` (`services/web/modules/gitlab-sync`). Skemanya ada di `services/web/modules/gitlab-sync/app/models/gitlabSyncProjectStates.mjs`, dan semua akses melalui `services/web/modules/gitlab-sync/app/src/SyncStateManager.mjs`. Field-nya sama dengan di [GitHub Sync Project States](/id/dev/data-model/github-sync-project-states-collection).

#### Siapa yang menulis {#who-writes-it}

| Kode | Fungsinya |
| ---- | ------------ |
| `SyncStateManager.mjs:9-14` (`createProjectState`) | Membuat dokumen: setelah mengimpor repositori sebagai proyek baru (`services/web/modules/gitlab-sync/app/src/GitLabSyncHandler.mjs:175-181`), atau setelah mengekspor proyek ke repositori baru (`GitLabSyncHandler.mjs:234-240`, hanya pemilik, ditolak bila sudah ditautkan). |
| `SyncStateManager.mjs:16-21` (`updateProjectState`) | `$set` untuk field yang berubah. `getMergeOverview` mengatur `mergeStatus: 'diverged'` ketika branch yang disinkronkan tidak lagi berisi `lastSyncCommit` (pemeriksaan merge base, `services/web/modules/gitlab-sync/app/src/GitLabApiClient.mjs:460`), atau commit-nya hilang dan pengguna dapat melakukan push (`GitLabSyncHandler.mjs:123,126-137`). Sinkronisasi (`services/web/modules/gitlab-sync/app/src/GitMerge.mjs`) memajukan `lastSyncCommit`/`lastSyncVersion` saat berhasil (misalnya `:152,189,231`), mencatat konflik dengan `unmergedBranchName`, `unmergedBranchHead`, dan `conflictVersion` (`:214-220`), dan menghapusnya setelah konflik diselesaikan (`:257-264`). |
| `SyncStateManager.mjs:23-25` (`removeProjectState`) | Menghapus dokumen saat pemilik memutus tautan proyek (`GitLabSyncHandler.mjs:83-97`) dan saat proyek yang dihapus kedaluwarsa (`services/web/modules/gitlab-sync/index.mjs:46-48`). |

| Kode | Fungsinya |

| `GitLabSyncHandler.mjs:39-60` (`getProjectState`) | Memberi editor `mergeStatus`, `repoFullName`, dan `unmergedBranchName`. Tanpa dokumen, ia menjawab `need-export`, nilai yang tidak pernah disimpan. |

#### Indeks {#indexes}

| Nama | Kunci | Opsi | Migrasi |
| ---- | ---- | ------- | --------- |
| `_id_` | `_id: 1` | | default |

`autoIndex` Mongoose dimatikan (`services/web/app/src/infrastructure/Mongoose.mjs:7`), jadi `unique: true` skema pada `projectId` tidak membuat apa pun. Tidak ada migrasi yang membuat indeks untuk koleksi ini.

#### Catatan {#notes}

* API GitLab tidak bisa memindahkan branch ke commit mana pun seperti API GitHub. Sinkronisasi melakukan commit langsung ke branch yang disinkronkan bila bisa maju, atau ke branch sementara yang kemudian digabungkan lewat merge request (`GitMerge.mjs:16-21`).
* Sinkronisasi berjalan di bawah lock `gitSync` proyek, yang dipakai bersama dengan GitHub Sync dan Gitea Sync (`GitMerge.mjs:25-32`).
* Proyek yang dihapus menyimpan dokumennya sampai proyek itu kedaluwarsa.
* Token GitLab pengguna ada di [GitLab Sync User Credentials](/id/dev/data-model/gitlab-sync-user-credentials-collection).
