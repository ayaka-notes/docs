`notifications` menyimpan pemberitahuan yang ditampilkan di bagian atas dasbor proyek pengguna. Satu dokumen adalah satu pemberitahuan untuk satu pengguna, yang diidentifikasi oleh `key`-nya. Hanya layanan `notifications` yang mengakses koleksi ini (`services/notifications/app/js/Notifications.js`); `web` dan `third-party-datastore` memanggil API HTTP-nya. Tidak ada skema Mongoose.

#### Field {#fields}

| Field | Tipe | Arti | Sumber |
| --- | --- | --- | --- |
| `_id` | ObjectId | Id pemberitahuan. `web` menandai pemberitahuan sebagai sudah dibaca dengan id ini. | `Notifications.js:58-65` |
| `user_id` | ObjectId | Pengguna yang melihat pemberitahuan. | `Notifications.js:26` |
| `key` | String | Mengidentifikasi pemberitahuan, misalnya `project-invite-<inviteId>`. Upsert menjaga satu dokumen per `user_id` dan `key`; tidak ada indeks unik. | `Notifications.js:27`, `:51-55` |
| `templateKey` | String | Pemberitahuan mana yang dirender frontend. Dihapus saat pemberitahuan dibaca atau ditutup; dokumennya tetap ada. | `Notifications.js:29`, `:63`, `:72`, `:78` |
| `messageOpts` | Object | Nilai untuk teks pemberitahuan, bergantung pada `templateKey` (untuk undangan proyek: `userName`, `projectName`, `projectId`, `token`). Dihapus saat pengguna menutup pemberitahuan berdasarkan id. | `Notifications.js:28`, `:63` |
| `expires` | Date | Opsional. Indeks TTL menghapus dokumen setelah waktu ini. | `Notifications.js:35-50` |

#### Catatan {#notes}

* Pemberitahuan yang sudah dibaca tidak dihapus: hanya `templateKey` yang hilang. Karena dokumen masih menyimpan kuncinya, `addNotification` berikutnya tanpa `forceCreate` untuk kunci yang sama tidak melakukan apa pun (`Notifications.js:21-24`).
* Rute `/key/:key` hanya bekerja berdasarkan kunci, untuk semua pengguna (`Notifications.js:76-100`).
* Jika `web` tidak memiliki `apis.notifications.url`, ia tidak membuat maupun membaca pemberitahuan (`NotificationsHandler.mjs:17`, `:41`).
