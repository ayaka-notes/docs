---
title: Koleksi Gitea Sync User Credentials
icon: lock
---

`giteaSyncUserCredentials` menyimpan satu dokumen per pengguna yang menautkan akun Gitea untuk Gitea Sync. Koleksi ini menyimpan token OAuth pengguna dalam bentuk terenkripsi. Koleksi ini milik modul web `gitea-sync` (`services/web/modules/gitea-sync`). Skemanya ada di `services/web/modules/gitea-sync/app/models/giteaSyncUserCredentials.mjs`, dan semua akses melalui `services/web/modules/gitea-sync/app/src/TokenManager.mjs`.

#### Field {#fields}

| Field | Tipe | Arti | Sumber |
| ----- | ---- | ------- | ------ |
| `_id` | ObjectId | Diatur oleh Mongoose saat upsert menyisipkan dokumen. | |
| `userId` | ObjectId | Pengguna Overleaf. Wajib. Skema menyebut `unique: true`, tetapi tidak ada indeks yang dibuat (lihat Indeks); upsert berdasarkan `userId` menjaga satu dokumen per pengguna. | `giteaSyncUserCredentials.mjs:8`, `TokenManager.mjs:89-96` |
| `gitea` | String | JSON `{ accessToken, refreshToken, expiresAt }`, dienkripsi dengan `@overleaf/access-token-encryptor`. `expiresAt` dalam milidetik sejak epoch, atau `null`; `refreshToken` bisa `null`. Kata sandinya berasal dari `GITEA_TOKEN_CIPHER_PASSWORD`; label cipher-nya `GITEA_TOKEN_CIPHER_LABEL`, default `2026.10-v3`. Wajib. | `giteaSyncUserCredentials.mjs:9-10`, `TokenManager.mjs:17-30`, `services/web/modules/gitea-sync/app/src/GiteaApiClient.mjs:198-209` |
| `__v` | Number | Kunci versi Mongoose. Skema tidak menonaktifkannya. | Default Mongoose |

#### Siapa yang menulis {#who-writes-it}

| Kode | Fungsinya |
| ---- | ------------ |
| `TokenManager.mjs:89-96` (`saveUserToken`) | Melakukan upsert kredensial terenkripsi pengguna. Dipanggil dari callback OAuth (`services/web/modules/gitea-sync/app/src/GiteaSyncController.mjs:146`). Berbeda dengan GitLab Sync, menautkan lagi tidak mencabut token yang diganti. |
| `TokenManager.mjs:53-79` (`refreshUserToken`) | Saat access token kurang dari 5 menit dari `expiresAt` (`:12`), ia mengambil token baru dengan refresh token dan menyimpannya (`:76`). Ia berjalan di bawah lock `giteaSyncToken` per pengguna (`:14,54`), karena Gitea mengganti refresh token saat dipakai. |
| `TokenManager.mjs:100-102` (`removeUserToken`) | Menghapus dokumen. Gitea tidak punya API untuk mencabut token OAuth, jadi pengguna mencabut izinnya di Gitea (`:98-99`). Dipanggil saat memutus tautan (`GiteaSyncController.mjs:173`) dan saat pengguna yang dihapus kedaluwarsa (`services/web/modules/gitea-sync/index.mjs:56-58`). |

#### Siapa yang membaca {#who-reads-it}

| Kode | Fungsinya |
| ---- | ------------ |
| `TokenManager.mjs:40-44,82-86` (`getUserCredentials`, `getUserToken`) | Mendekripsi kredensial untuk setiap panggilan API Gitea, memperbaruinya lebih dulu bila token hampir kedaluwarsa: `services/web/modules/gitea-sync/app/src/GiteaSyncHandler.mjs` (misalnya `:27`) dan `services/web/modules/gitea-sync/app/src/GitMerge.mjs:52`. Tanpa dokumen, atau dengan kredensial yang tidak bisa didekripsi atau diperbarui, ia melempar `InvalidTokenError`, dan pengguna dianggap tidak tertaut (`GiteaSyncHandler.mjs:25-37`). |
| `services/web/modules/admin-tools/app/src/AdminUserListManager.mjs:395` | Memeriksa apakah pengguna punya dokumen, untuk integrasi yang ditampilkan di panel admin. |

#### Indeks {#indexes}

| Nama | Kunci | Opsi | Migrasi |
| ---- | ---- | ------- | --------- |
| `_id_` | `_id: 1` | | default |

`autoIndex` Mongoose dimatikan (`services/web/app/src/infrastructure/Mongoose.mjs:7`), jadi `unique: true` skema pada `userId` tidak membuat apa pun. Tidak ada migrasi yang membuat indeks untuk koleksi ini.

#### Catatan {#notes}

* Mengubah `GITEA_TOKEN_CIPHER_PASSWORD` membuat kredensial yang tersimpan tidak terbaca. Pengguna tersebut lalu dianggap tidak tertaut sampai mereka menautkan lagi.
* Pengguna yang dihapus menyimpan dokumennya sampai pengguna itu kedaluwarsa.
