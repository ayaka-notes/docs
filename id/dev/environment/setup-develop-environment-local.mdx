## Prasyarat {#prerequisites}

Overleaf adalah proyek open source khas dengan arsitektur microservice, di mana semua layanan berjalan di Docker.

* Kode sumber resmi Community Edition tersedia di [GitHub Overleaf Official](https://github.com/overleaf/overleaf/tree).
* Kode sumber Overleaf-CEP tersedia di [GitHub Yu-i-i/Overleaf](https://github.com/yu-i-i/overleaf-cep).
* Ayakaleaf Pro tersedia di [GitHub ayaka-notes/ayakaleaf-pro](https://github.com/ayaka-notes/ayakaleaf-pro).

Untuk menyiapkan lingkungan pengembangan Overleaf, Anda memerlukan server yang bertenaga; konfigurasi minimal 8 core dan RAM 16GB disarankan, karena Anda perlu menjalankan lebih dari 20 kontainer secara bersamaan.

<Info>

Karena server dengan 8 core CPU atau lebih biasanya mahal, sangat disarankan untuk menggunakan komputer lokal Anda untuk pengembangan.

</Info>

Selain itu, sebagai pengembang, kami yakin Anda sudah familier dengan [instalasi Docker](https://docs.docker.com/engine/install/ubuntu/). Kami sangat menyarankan penggunaan Ubuntu LTS yang terbaru dan stabil (misalnya Ubuntu 24.04 pada 2025–2026) serta Docker versi terbaru untuk pengembangan, karena hal ini mengurangi kemungkinan menemui error yang tidak terduga.

Singkatnya, Anda akan membutuhkan:

* [x] Server/desktop yang bertenaga untuk pengembangan
* [x] Ubuntu LTS yang terbaru dan stabil (misalnya Ubuntu 24.04)
* [x] Lingkungan Docker dan Git

## Tutorial Konfigurasi {#configuration-tutorial}

Di sini, kami menggunakan Ayakaleaf Pro untuk menunjukkan cara menyiapkan lingkungan pengembangan Overleaf. Semua perintah di bawah dijalankan di direktori `develop` kecuali disebutkan lain.

<Steps>
<Step title="Tarik Kode Sumber">
Pertama-tama, mari kita clone repositorinya:

```bash title="bash"
git clone https://github.com/ayaka-notes/ayakaleaf-pro.git
cd ayakaleaf-pro/develop
```
</Step>

<Step title="Menyinkronkan `yarn.lock`">
Repositori menggunakan Yarn 4 (`packageManager` di `package.json` root), dan `yarn.lock`-nya bisa tidak sinkron dengan file `package.json`. Sinkronkan setelah clone pertama dan setelah setiap perubahan `package.json`:

```bash title="bash"
bin/sync
```

`bin/sync` menjalankan `yarn install --mode=update-lockfile` di container `node:24.18.1`, jadi Anda tidak memerlukan Node.js di host. Jangan commit `yarn.lock` yang berubah.
</Step>

<Step title="Build Image Pengembangan">
Bangun layanan:

```bash title="bash"
bin/build
```

<Info>

Jika Docker kehabisan RAM saat mem-build layanan secara paralel, buat file `.env` di direktori ini yang berisi `COMPOSE_PARALLEL_LIMIT=1`.

</Info>
</Step>

<Step title="Menerapkan terjemahan">
Modul Ayakaleaf Pro menyimpan terjemahannya di `services/web/locales/locales_patches/`, yang tidak ada di file locale yang di-commit. Terapkan sekali sebelum start pertama, atau halaman modul ini akan menampilkan kunci seperti `about_to_permanently_delete_accounts` alih-alih teks:

```bash title="bash"
bin/i18n
```

Perintah ini memerlukan `jq` di host. Jalankan lagi setelah menambahkan terjemahan atau berganti branch, lihat [Memperbarui Terjemahan i18n](/id/dev/environment/update-i18n-translations).
</Step>

<Step title="Jalankan Semua Microservice">
Kemudian jalankan layanannya:

```bash title="bash"
bin/up
```

Setelah layanan berjalan, buka [http://localhost/launchpad](http://localhost/launchpad) untuk membuat akun admin pertama. Tambahkan port jika Anda mengubah `OVERLEAF_PORT` (lihat di bawah).

<Info>

LDAP aktif secara default (`LDAP_ENABLED=true` di `dev.rc`). Launchpad kemudian menampilkan formulir admin LDAP: formulir ini hanya meminta email, dan admin tersebut setelahnya login melalui LDAP, misalnya sebagai `professor` / `professor` (`professor@planetexpress.com`). Pengguna uji tercantum di `develop/authentication/README.md`. Atur `LDAP_ENABLED=false` dan `SAML_ENABLED=false` untuk membuat admin lokal dengan kata sandi sebagai gantinya.

</Info>
</Step>
</Steps>

<Info>

`develop/dev.env` sudah menetapkan `ADMIN_PRIVILEGE_AVAILABLE=true`, sehingga admin dapat membuka panel Admin tanpa penyiapan tambahan.

</Info>

### Konfigurasi (`dev.rc`) {#configuration-dev-rc}

`develop/dev.rc`, di samping `dev.env`, berisi sakelar lingkungan pengembangan, seperti `overleaf.rc` di Overleaf Toolkit. Ubah sebuah nilai lalu jalankan `bin/dev` lagi untuk menerapkannya; fitur yang dinonaktifkan juga menghentikan container-nya.

| Variabel | Default | Fungsinya |
| --- | --- | --- |
| `OVERLEAF_PORT` | `80` | Port host situs. |
| `LDAP_ENABLED` | `true` | Login LDAP dengan pengguna uji. |
| `SAML_ENABLED` | `true` | Login SAML dengan pengguna uji. |
| `MAILPIT_ENABLED` | `true` | Menangkap setiap email dari `web` di Mailpit. Juga mengaktifkan konfirmasi email (`EMAIL_CONFIRMATION_DISABLED=false`). |
| `S3_ENABLED` | `true` | Menyimpan file riwayat dan template di RustFS (S3) alih-alih volume lokal. |
| `HOPPSCOTCH_ENABLED` | `true` | Hoppscotch dengan proxy ke jaringan Docker, lihat [Menyiapkan Alat Pengembangan](/id/dev/environment/setup-develop-tools). |
| `HOPPSCOTCH_PORT` | `9170` | Port host Hoppscotch. |
| `GRAFANA_ENABLED` | `true` | Grafana di `/grafana/` situs, dengan status, metrik, dan log setiap layanan, lihat [Menyiapkan Alat Pengembangan](/id/dev/environment/setup-develop-tools). |

Setiap fitur menyimpan `docker-compose.yml` dan file lainnya di foldernya sendiri: `authentication/ldap`, `authentication/saml`, `mail`, `s3`, `hoppscotch`, dan `grafana`. Fitur yang memerlukan pengaturan `web` tanpa variabel lingkungan memasang file ke `/etc/overleaf/settings.d/`, dan `develop/settings.dev-env.cjs` menggabungkan semuanya. Semua skrip `bin/*` melewati `bin/docker-compose`, yang menambahkan file fitur yang aktif. Panggil `bin/docker-compose` alih-alih `docker compose` saat Anda sendiri memerlukan perintah compose.

<Warning>

Volume lokal dan RustFS adalah penyimpanan terpisah: proyek yang dibuat dengan `S3_ENABLED=true` tidak memiliki riwayat atau file biner setelah beralih ke `false`, dan sebaliknya. Untuk menyalin file dari lingkungan yang berjalan sebelum `S3_ENABLED` ada ke RustFS, ikuti “Moving existing data into RustFS” di [develop/README.md](https://github.com/ayaka-notes/ayakaleaf-pro/blob/server-pro/develop/README.md).

</Warning>

### Port {#ports}

Situs, konsol RustFS, dan Hoppscotch mendengarkan di `127.0.0.1` host; di mesin jarak jauh, teruskan port-nya terlebih dahulu, misalnya `ssh -L 9001:localhost:9001 <host>`. Situs menggunakan `OVERLEAF_PORT` dari `dev.rc`, jadi tambahkan port ke alamat di bawah jika Anda mengubahnya.

| Halaman | Alamat | Login |
| --- | --- | --- |
| Situs | [http://localhost](http://localhost) | Akun situs, atau pengguna uji |
| Kotak masuk email (Mailpit) | [http://localhost/mailpit/](http://localhost/mailpit/) | Tidak ada |
| Grafana | [http://localhost/grafana/](http://localhost/grafana/) | Tidak ada, pengguna anonim adalah admin |
| Mongo Express | [http://localhost/mongo-express/](http://localhost/mongo-express/) | Tidak ada |
| RedisInsight | [http://localhost/redis-insight/](http://localhost/redis-insight/) | Tidak ada |
| Konsol S3 (RustFS) | [http://localhost:9001/rustfs/console/](http://localhost:9001/rustfs/console/) | `rustfsadmin` / `rustfsadmin` |
| Hoppscotch | [http://localhost:9170](http://localhost:9170) (`HOPPSCOTCH_PORT`) | Tidak ada |

Mailpit, Grafana, Mongo Express, dan RedisInsight disajikan oleh situs di path-nya sendiri melalui webpack-dev-server, sehingga tidak memerlukan port sendiri. Setelah Anda login, menu **Dev tools** di bilah navigasi situs menautkannya; halaman yang fiturnya dinonaktifkan di `dev.rc` tidak ditampilkan. [Menyiapkan Alat Pengembangan](/id/dev/environment/setup-develop-tools) menunjukkan fungsi masing-masing.

S3 API (port 9000) dan SMTP (port 1025) hanya dapat dijangkau di dalam jaringan Docker. Mongo (27017), Redis (6379), Mongo Express (8081), RedisInsight (5540), dan git-bridge (8000) hanya dipublikasikan di `127.0.0.1` host.

### TeX Live {#tex-live}

Kompilasi sandbox aktif secara default: `develop/dev.env` menetapkan `SANDBOXED_COMPILES=true` serta image `ghcr.io/ayaka-notes/texlive-full:2026.1` dan `ghcr.io/ayaka-notes/texlive-full:2025.1`. clsi tidak menarik image sendiri, jadi tarik image tersebut sekali:

```bash
docker pull ghcr.io/ayaka-notes/texlive-full:2026.1
docker pull ghcr.io/ayaka-notes/texlive-full:2025.1
```

Lihat [Menyiapkan Sandbox Compiles](/id/dev/environment/setup-sandbox-compiles) untuk detailnya.

<Warning>

Proyek yang dibuat saat `SANDBOXED_COMPILES` nonaktif tidak memiliki image TeX Live. Proyek itu tetap terkompilasi dengan image default, tetapi lompat antara kode dan PDF gagal dengan “That didn't work. Recompile and try again.” Berikan image `TEX_LIVE_DOCKER_IMAGE` ke proyek tersebut sekali; tanpa `--commit`, skrip hanya menampilkan apa yang akan diubah:

```bash
bin/docker-compose exec web sh -c 'cd /overleaf/services/web && node scripts/backfill_project_image_name.mjs --commit'
```

</Warning>

`dev.env` juga mengaktifkan konversi Pandoc dengan `PANDOC_IMAGE=overleaf-pandoc:local`. Bangun image itu sekali dari root repositori:

```bash
docker build -t overleaf-pandoc:local develop/pandoc
```

Untuk mengompilasi di host macOS, Anda mungkin perlu menimpa path ke socket Docker dengan membuat file `.env` di direktori `develop` yang berisi `DOCKER_SOCKET_PATH=/var/run/docker.sock.raw`

### Pengembangan {#development}

Agar tidak perlu menjalankan `bin/build && bin/up` setiap kali kode berubah, Anda dapat menjalankan Overleaf Community Edition dalam _mode pengembangan_, di mana layanan akan diperbarui secara otomatis saat kode berubah.

Untuk melakukannya, gunakan skrip `bin/dev` yang disertakan:

```text
bin/dev
```

Ini akan menjalankan semua layanan menggunakan `node --watch`, yang akan memantau kode secara otomatis dan memulai ulang layanan bila diperlukan. Jalankan lagi setelah mengubah `dev.rc`.

Untuk meningkatkan performa, Anda dapat menjalankan hanya sebagian layanan dalam mode pengembangan dengan memberikan daftar yang dipisahkan spasi ke skrip `bin/dev`:

```text
bin/dev [service1] [service2] ... [serviceN]
```

<Info>

Menjalankan layanan `web` dalam _mode pengembangan_ hanya akan memperbarui layanan `web` saat kode backend berubah. Agar kode frontend juga diperbarui secara otomatis, pastikan untuk menjalankan layanan `webpack` dalam _mode pengembangan_ juga.

</Info>

Jika tidak ada layanan yang disebutkan, semua layanan akan berjalan dalam mode pengembangan.

Setelah menambahkan terjemahan atau berganti branch, jalankan `bin/i18n`, lihat [Memperbarui Terjemahan i18n](/id/dev/environment/update-i18n-translations).

### Debugging {#debugging}

Saat berjalan dalam _mode pengembangan_, sebagian besar layanan membuka port debugging yang dapat Anda sambungkan ke debugger, seperti inspector di Chrome Dev Tools atau debugger yang terintegrasi di IDE. Tabel berikut menunjukkan port yang dibuka di `127.0.0.1` pada **mesin host** untuk setiap layanan:

| Layanan            | Port |
| ------------------ | ---- |
| `web`                   | 9229 |
| `clsi`                  | 9230 |
| `chat`                  | 9231 |
| `docstore`              | 9233 |
| `document-updater`      | 9234 |
| `filestore`             | 9235 |
| `notifications`         | 9236 |
| `real-time`             | 9237 |
| `history-v1`            | 9239 |
| `project-history`       | 9240 |
| `linked-url-proxy`      | 9241 |
| `third-party-datastore` | 9242 |

Untuk terhubung ke layanan menggunakan _remote debugging_ Chrome, buka chrome://inspect/ dan pastikan _Discover network targets_ dicentang. Selanjutnya klik _Configure..._ dan tambahkan entri `localhost:[service port]` untuk setiap layanan yang ingin Anda hubungkan dengan debugger.

Setelah menambahkan entri, layanan akan muncul sebagai _Remote Target_ yang dapat Anda inspeksi dan debug.

### Logging {#logging}

Skrip `bin/logs` mengikuti log dan memformatnya dengan `bunyan`. Skrip ini juga memerlukan `ggrep`, yaitu nama GNU grep saat diinstal dengan Homebrew di macOS; Ubuntu tidak memiliki perintah `ggrep`.

```bash
sudo npm install -g bunyan
# Or sudo apt install node-bunyan 
```

Atau, Anda dapat langsung menjalankan:

```text
bin/docker-compose logs -f [service name]
```

Gunakan `bin/docker-compose` alih-alih `docker compose`, agar layanan dari fitur di `dev.rc` (`mailpit`, `rustfs`, `ldap`, `saml`, `hoppscotch`, dan `grafana` beserta Prometheus, Loki, dan exporter) juga ditemukan.

Dengan `GRAFANA_ENABLED=true`, log setiap container juga ada di Grafana, tempat log dapat difilter berdasarkan layanan, level, dan teks, lihat [Menyiapkan Alat Pengembangan](/id/dev/environment/setup-develop-tools#grafana).
