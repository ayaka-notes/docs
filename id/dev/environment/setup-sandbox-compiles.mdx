title: Menyiapkan Sandbox Compiles
icon: box-archive
---

Kompilasi sandbox bekerja sedikit berbeda di lingkungan pengembangan dibandingkan di image produksi. Lingkungan pengembangan sudah menyiapkannya; halaman ini menjelaskan pengaturannya dan tiga hal yang perlu diperhatikan:

* Masalah izin file
* Berbagi volume antara history-v1 dan filestore
* Masalah subdirektori

### Mengaktifkan Sandbox Compiles {#enable-sandbox-compiles}

Kompilasi sandbox aktif secara default. `develop/docker-compose.yml` menetapkan `SANDBOXED_COMPILES=true` untuk `clsi`, dan `develop/dev.env` berisi sisanya:

```dotenv title="develop/dev.env" wrap
#################
#   Sandbox     #
#################
SANDBOXED_COMPILES=true
SANDBOXED_COMPILES_HOST_DIR_COMPILES=${PWD}/compiles
SANDBOXED_COMPILES_HOST_DIR_OUTPUT=${PWD}/output
TEXLIVE_IMAGE_USER=tex
ALL_TEX_LIVE_DOCKER_IMAGES=ghcr.io/ayaka-notes/texlive-full:2026.1, ghcr.io/ayaka-notes/texlive-full:2025.1
ALL_TEX_LIVE_DOCKER_IMAGE_NAMES=Texlive 2026, Texlive 2025
TEX_LIVE_DOCKER_IMAGE=ghcr.io/ayaka-notes/texlive-full:2026.1
```

clsi tidak menarik image sendiri, jadi tarik image sekali dengan `docker pull ghcr.io/ayaka-notes/texlive-full:2026.1` (dan `:2025.1`).

LaTeX berjalan di container saudara sebagai `TEXLIVE_IMAGE_USER`. Di lingkungan pengembangan, nilainya `tex`, yang juga merupakan default clsi (`services/clsi/config/settings.defaults.cjs:154`). Image produksi menggunakan `www-data` sebagai gantinya ketika `SANDBOXED_COMPILES_SIBLING_CONTAINERS=true` (`server-ce/config/env.sh:15-21`), karena di sana file dibuat oleh pengguna `www-data` dari container Overleaf.

<Warning>

Jangan gunakan image yang Anda bangun sendiri, karena Anda mungkin akan menemui serangkaian error.

</Warning>

### Memperbaiki Izin File {#fix-file-permissions}

Container clsi dimulai sebagai root, memberikan folder `compiles`, `output`, dan `cache` kepada pengguna `node` (uid `1000`), lalu menjalankan clsi sebagai `node` (`services/clsi/entrypoint.sh`). Jadi `develop/compiles` di host dimiliki oleh uid `1000`, uid yang sama dengan `tex` di lingkungan pengembangan (lihat komentar di `develop/pandoc/Dockerfile`). Dengan pengaturan di atas, lingkungan pengembangan mengompilasi tanpa perubahan izin apa pun.

Jika Anda menetapkan `TEXLIVE_IMAGE_USER=root` sebagai gantinya, root (uid `0`) tidak memiliki izin menulis ke subfolder `compiles`. Dalam hal itu, berikan grup `root` kepemilikan dan izin menulis pada `compiles`, dengan `setgid` diaktifkan agar subfolder baru mewarisi kepemilikan ini:

```bash title="bash"
sudo chown -R 1000:root compiles
sudo chmod -R g+w compiles
sudo chmod g+s compiles
```

Untuk dokumentasi lebih rinci, Anda dapat melihat `services/clsi/README.md`.

### Berbagi Volume antara history-v1 dan filestore {#volume-share-between-history-v1-and-filestore}

<Info>

Pengaturan di bagian ini dan bagian berikutnya sudah ada di `develop/docker-compose.yml` dan `develop/dev.env`. Pengaturan ini hanya berpengaruh dengan `S3_ENABLED=false` di `develop/dev.rc`. Dengan default `S3_ENABLED=true`, filestore dan history-v1 menyimpan file ini di bucket RustFS sebagai gantinya (`develop/s3/docker-compose.yml`).

</Info>

Secara default, filestore berfungsi sebagai jembatan antara S3 dan layanan lain di Overleaf. Namun, di Overleaf CE atau Server Pro, semua file disimpan secara lokal secara default. Karena itu, Overleaf memperkenalkan metode yang cukup rumit.

```javascript title="server-ce/config/settings.js" wrap
switch (process.env.OVERLEAF_FILESTORE_BACKEND) {
  case 's3':
    // s3 case...
  default:
    settings.filestore = {
      backend: 'fs',
      stores: {
        template_files: Path.join(DATA_DIR, 'template_files'),

        // NOTE: The below paths are hard-coded in server-ce/config/production.json, so hard code them here as well.
        // We can use DATA_DIR after switching history-v1 from 'config' to '@overleaf/settings'.
        project_blobs:
          process.env.OVERLEAF_HISTORY_PROJECT_BLOBS_BUCKET ||
          '/var/lib/overleaf/data/history/overleaf-project-blobs',
        global_blobs:
          process.env.OVERLEAF_HISTORY_BLOBS_BUCKET ||
          '/var/lib/overleaf/data/history/overleaf-global-blobs',
      },
    }
}
```

Sementara itu, `data/history` juga digunakan oleh layanan riwayat. Dengan cara ini, berbagai microservice dapat berbagi data yang sama. Itulah sebabnya layanan filestore di develop memasang volume `history-v1-buckets` milik history-v1. Tanpa volume itu, **clsi tidak akan dapat menarik file blob dari layanan filestore**.

```yml title="develop/docker-compose.yml" wrap
  filestore:
    build:
      context: ..
      dockerfile: services/filestore/Dockerfile
    env_file:
      - dev.env
#    environment:
#      - ENABLE_CONVERSIONS=true
    volumes:
      - filestore-public-files:/overleaf/services/filestore/public_files
      - filestore-template-files:/overleaf/services/filestore/template_files
      - filestore-uploads:/overleaf/services/filestore/uploads
      - history-v1-buckets:/buckets
```

filestore menemukan bucket melalui pengaturan berikut di `dev.env`:

```dotenv title="develop/dev.env"
OVERLEAF_EDITOR_PROJECT_BLOBS_BUCKET='/buckets/project_blobs'
OVERLEAF_EDITOR_BLOBS_BUCKET='/buckets/blobs'
```

### Menggunakan Subdirektori {#use-subdirectories}

filestore selalu membaca blob riwayat dengan subdirektori (`services/filestore/app/js/KeyBuilder.js:58`, `:70`). Image produksi mengaktifkan `useSubdirectories` untuk history-v1 (`server-ce/config/production.json`), tetapi konfigurasi default history-v1 tidak, sehingga dalam pengembangan history-v1 akan <strong>meratakan semua data.</strong> Karena itu `dev.env` menetapkan `NODE_CONFIG` untuk history-v1:&#x20;

```dotenv title="develop/dev.env"
OVERLEAF_EDITOR_PROJECT_BLOBS_BUCKET='/buckets/project_blobs'
OVERLEAF_EDITOR_BLOBS_BUCKET='/buckets/blobs'
NODE_CONFIG='{"persistor":{"useSubdirectories":true}}'
```

Tanpa pengaturan itu, history-v1 menyimpan file `project_blobs` seperti ini:

```bash wrap
node@43eb5dac5b1b:/buckets/project_blobs$ ls
169_609_71360f687c431b9796_5b_889ef3cf71c83a4c027c4e4dc3d1a106b27809  
94e_655_88cb5cc77ab70c9796_a0_e21c740cf81e868f158e30e88985b5ea1d6c19
169_609_71360f687c431b9796_a0_e21c740cf81e868f158e30e88985b5ea1d6c19
94e_655_88cb5cc77ab70c9796_fd_3c0326302e49486d3ea86c833edf9b88320c41
169_609_71360f687c431b9796_fd_3c0326302e49486d3ea86c833edf9b88320c41 

```

Dengan `useSubdirectories` bernilai `true`, `_` dalam nama-nama ini menjadi `/`, sehingga setiap blob disimpan dalam subfolder.
