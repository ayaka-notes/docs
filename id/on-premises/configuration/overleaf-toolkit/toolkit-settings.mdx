Halaman ini menjelaskan variabel lingkungan yang didukung di file `config/overleaf.rc` untuk deployment Toolkit.

File `config/overleaf.rc` terdiri dari definisi variabel dalam bentuk `NAME=value`. Baris yang diawali dengan `#` diperlakukan sebagai komentar.

<Info>

Anda perlu membuat ulang kontainer Docker dengan menjalankan `bin/up` setelah mengubah apa pun di `overleaf.rc` atau `variables.env`.

</Info>

## Kontainer

### `sharelatex`

| Nama                         | Deskripsi |
| ---------------------------- | --------- |
| `PROJECT_NAME`               | <p>Mengatur nilai flag `--project-name` yang diberikan ke `docker-compose`. Ini berguna saat menjalankan beberapa instans Overleaf di satu host, karena setiap instans dapat memiliki nama proyek yang berbeda.<br /><br />- <strong>Default</strong>: `overleaf`</p> |
| `OVERLEAF_IMAGE_NAME`        | <p>Image Docker yang digunakan oleh kontainer aplikasi Server Pro/CE. Ini hanya nama image Docker; tag image Docker diambil dari `config/version`.<br /><br />- <strong>Default:</strong><br />- Server Pro: `quay.io/sharelatex/sharelatex-pro`<br />- Community Edition: `sharelatex/sharelatex`</p> |
| `SERVER_PRO`                 | <p>Jika diatur ke `true`, Toolkit akan menggunakan image Server Pro (`quay.io/sharelatex/sharelatex-pro`), alih-alih image Server CE default (`sharelatex/sharelatex`).<br /><br />- <strong>Default</strong>: `false`</p> |
| `GIT_BRIDGE_ENABLED`         | <p>Atur ke `true` untuk mengaktifkan fitur git-bridge (khusus Server Pro). Untuk informasi lebih lanjut, lihat dokumentasi pengguna <a href="https://www.overleaf.com/learn/how-to/Git_integration">https://www.overleaf.com/learn/how-to/Git_integration</a>.<br /><br />- <strong>Default:</strong> `false`</p> |
| `GIT_BRIDGE_IMAGE`           | <p>Image Docker yang digunakan oleh kontainer git-bridge (khusus Server Pro). Ini hanya nama image Docker; tag image Docker diambil dari `config/version`.<br /><br />- <strong>Default:</strong> `quay.io/sharelatex/git-bridge`</p> |
| `GIT_BRIDGE_DATA_PATH`       | Mengatur path ke direktori yang akan di-mount ke dalam kontainer `git-bridge` (khusus Server Pro), dan digunakan untuk menyimpan repositori git. Nilainya dapat berupa path lengkap (diawali dengan `/`), atau relatif terhadap direktori dasar Toolkit. |
| `GIT_BRIDGE_LOG_LEVEL`       | <p>Mengonfigurasi level logging kontainer `git-bridge`. Level yang tersedia: `TRACE`, `DEBUG`, `INFO`, `WARN`, `ERROR`.<br /><br />- <strong>Default:</strong> `INFO`</p> |
| `SIBLING_CONTAINERS_ENABLED` | <p>Jika diatur ke `true`, Toolkit akan menggunakan teknik <strong>Sibling Containers</strong> untuk mengompilasi proyek dalam sandbox terpisah, menggunakan kontainer Docker terpisah untuk setiap proyek. Lihat dokumentasi &#x3C;server-pro-only-configuration/sandboxed-compiles> untuk informasi lebih lanjut.<br /><br />- <strong>Memerlukan:</strong> `SERVER_PRO=true`<br />- <strong>Default:</strong> `true`</p> |
| `SIBLING_CONTAINERS_PULL`    | <p>Jika diatur ke `true`, Toolkit akan secara otomatis menarik semua image TeX Live yang diatur melalui `ALL_TEX_LIVE_DOCKER_IMAGES` di file <strong>config/variables.env</strong> saat menggunakan perintah `bin/up`.<br /><br />- <strong>Default:</strong> `true`</p> |
| `DOCKER_SOCKET_PATH`         | <p>Mengatur path ke socket Docker di mesin host (mesin yang menjalankan Toolkit). Jika `SIBLING_CONTAINERS_ENABLED` bernilai `true`, socket akan di-mount ke dalam kontainer agar layanan compiler dapat membuat kontainer Docker baru di host.<br /><br />- <strong>Memerlukan:</strong> `SIBLING_CONTAINERS_ENABLED=true`<br />- <strong>Default:</strong> `/var/run/docker.sock`</p> |
| `OVERLEAF_DATA_PATH`         | <p>Mengatur path ke direktori yang akan di-mount ke dalam kontainer utama `sharelatex`, dan digunakan untuk menyimpan data kompilasi. Nilainya dapat berupa path lengkap (diawali dengan `/`), atau relatif terhadap direktori dasar Toolkit.<br /><br />- <strong>Default:</strong> `data/overleaf`</p> |
| `OVERLEAF_LISTEN_IP`         | <p>Mengatur alamat IP host tempat kontainer akan melakukan bind. Misalnya, jika diatur ke `0.0.0.0`, antarmuka web akan tersedia di alamat IP host mana pun. Untuk akses kontainer secara langsung, nilai `OVERLEAF_LISTEN_IP` harus diatur ke alamat IP publik Anda. Mengatur `OVERLEAF_LISTEN_IP` ke `0.0.0.0` atau IP eksternal host Anda biasanya akan menyebabkan error jika digunakan bersama dengan .<br /><br />- <strong>Default:</strong> `127.0.0.1`</p> |
| `OVERLEAF_PORT`              | <p>Mengatur port host tempat kontainer akan melakukan bind. Misalnya, jika diatur ke `8099` dan `OVERLEAF_LISTEN_IP` diatur ke `127.0.0.1`, antarmuka web akan tersedia di `http://localhost:8099`.<br /><br />- <strong>Default:</strong> `80`</p> |
| `OVERLEAF_LOG_PATH`          | <p>Mengatur path ke direktori yang akan di-mount ke dalam kontainer utama `sharelatex`, dan digunakan agar log aplikasi tersedia di host Docker. Nilainya dapat berupa path lengkap (diawali dengan `/`), atau relatif terhadap direktori dasar Toolkit. Hapus entri konfigurasi ini untuk menonaktifkan bind-mount. Jika tidak diatur, log akan dibuang saat kontainer dibuat ulang.<br /><br />Lihat untuk informasi tentang logging.<br /><br />- <strong>Default:</strong> tidak diatur</p> |

### `mongo`

| Nama              | Deskripsi |
| ----------------- | --------- |
| `MONGO_ENABLED`   | <p>Jika diatur ke `true`, Toolkit akan membuat kontainer MongoDB untuk menampung database. Jika diatur ke `false`, kontainer ini tidak akan dibuat, dan sistem akan menggunakan database MongoDB yang ditentukan oleh `MONGO_URL`.<br /><br />- <strong>Default</strong>: `true`</p> |
| `MONGO_URL`       | <p>Menentukan URL koneksi MongoDB yang digunakan saat `MONGO_ENABLED` bernilai `false`.<br /><br />- <strong>Default</strong>: tidak diatur</p> |
| `MONGO_DATA_PATH` | <p>Mengatur path ke direktori yang akan di-mount ke dalam kontainer `mongo`, dan digunakan untuk menyimpan database MongoDB. Nilainya dapat berupa path lengkap (diawali dengan `/`), atau relatif terhadap direktori dasar toolkit. Opsi ini hanya memengaruhi kontainer `mongo` lokal yang dibuat saat `MONGO_ENABLED` bernilai `true`.<br /><br />- <strong>Default</strong>: `data/mongo`</p> |
| `MONGO_IMAGE`     | <p>Image Docker yang digunakan oleh kontainer MongoDB. Ini hanya nama image Docker; tag image Docker harus dimasukkan ke `MONGO_VERSION` (lihat di bawah).<br /><br />- <strong>Default:</strong> `mongo`</p> |
| `MONGO_VERSION`   | <p>Versi MongoDB yang digunakan oleh kontainer MongoDB. Nilainya harus diawali dengan versi mayor MongoDB dan sebuah titik, misalnya `6.0` atau `6.0-with-suffix`.<br /><br />- <strong>Default:</strong> `6.0`</p> |

***

### `redis`

| Nama                    | Deskripsi |
| ----------------------- | --------- |
| `REDIS_ENABLED`         | <p>Jika diatur ke `true`, Toolkit akan membuat kontainer Redis untuk menampung database redis. Jika diatur ke `false`, kontainer ini tidak akan dibuat, dan sistem akan menggunakan database Redis yang ditentukan oleh `REDIS_HOST` dan `REDIS_PORT`.<br /><br />- <strong>Default</strong>: `true`</p> |
| `REDIS_HOST`            | <p>Menentukan host Redis yang digunakan saat `REDIS_ENABLED` bernilai `false`.<br /><br />- <strong>Default</strong>: tidak diatur</p> |
| `REDIS_PORT`            | <p>Menentukan port Redis yang digunakan saat `REDIS_ENABLED` bernilai `false`.<br /><br />- <strong>Default</strong>: tidak diatur</p> |
| `REDIS_DATA_PATH`       | <p>Mengatur path ke direktori yang akan di-mount ke dalam kontainer `redis`, dan digunakan untuk menyimpan database Redis. Nilainya dapat berupa path lengkap (diawali dengan `/`), atau relatif terhadap direktori dasar Toolkit. Opsi ini hanya memengaruhi kontainer `redis` lokal yang dibuat saat `REDIS_ENABLED` bernilai `true`.<br /><br />- <strong>Default</strong>: `data/redis`</p> |
| `REDIS_AOF_PERSISTENCE` | <p>Mengaktifkan persistensi AOF (Append Only File) untuk Redis. Ini adalah konfigurasi yang <strong>direkomendasikan</strong> untuk persistensi Redis.<br /><br />Untuk detail tambahan, lihat bagian &#x3C;../../../maintenance/data-and-backups#aof-append-only-file> di &#x3C;../../maintenance/data-and-backups>.<br /><br />- <strong>Default:</strong> `true`</p> |

***

### `nginx`

| Nama                   | Deskripsi |
| ---------------------- | --------- |
| `NGINX_ENABLED`        | <p>Jika diatur ke `true`, Toolkit akan membuat kontainer NGINX yang berfungsi sebagai TLS Proxy.<br /><br />- <strong>Default</strong>: `false`</p> |
| `NGINX_CONFIG_PATH`    | <p>Path ke file konfigurasi NGINX yang digunakan untuk TLS Proxy.<br /><br />- <strong>Default</strong>: `config/nginx/nginx.conf`</p> |
| `NGINX_TLS_LISTEN_IP`  | <p>Mengatur alamat IP host tempat kontainer TLS Proxy akan melakukan bind untuk HTTPS. Misalnya, jika diatur ke `0.0.0.0`, antarmuka web HTTPS akan tersedia di alamat IP host mana pun. Biasanya nilai ini harus diatur ke IP eksternal host Anda.<br /><br />- <strong>Default</strong>: `127.0.1.1`</p> |
| `NGINX_HTTP_LISTEN_IP` | <p>Mengatur alamat IP host tempat kontainer TLS Proxy akan melakukan bind untuk pengalihan HTTP. Misalnya, jika diatur ke `127.0.1.1`, koneksi HTTP ke `127.0.1.1` akan dialihkan ke antarmuka web HTTPS. Biasanya nilai ini harus diatur ke IP eksternal host Anda. Jangan atur ke `0.0.0.0` karena biasanya akan menimbulkan konflik dengan `OVERLEAF_LISTEN_IP`.<br /><br />- <strong>Default</strong>: `127.0.1.1`</p> |
| `NGINX_HTTP_PORT`      | <p>Mengatur port host tempat kontainer TLS Proxy akan melakukan bind untuk HTTP.<br /><br />- <strong>Default</strong>: `80`</p> |
| `TLS_PORT`             | <p>Mengatur port host tempat kontainer TLS Proxy akan melakukan bind untuk HTTPS.<br /><br />- <strong>Default</strong>: `443`</p> |
| `TLS_PRIVATE_KEY_PATH` | <p>Path ke private key yang digunakan untuk TLS Proxy.<br /><br />- <strong>Default</strong>: `config/nginx/certs/overleaf_key.pem`</p> |
| `TLS_CERTIFICATE_PATH` | <p>Path ke sertifikat publik yang digunakan untuk TLS Proxy.<br /><br />- <strong>Default</strong>: `config/nginx/certs/overleaf_certificate.pem`</p> |
