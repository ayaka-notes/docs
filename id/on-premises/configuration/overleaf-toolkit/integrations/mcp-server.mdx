Setiap proyek memiliki MCP server, sehingga klien AI seperti Claude Code, Codex, Cursor, VS Code, atau Gemini CLI dapat bekerja pada proyek tersebut: membaca dan menyunting file-filenya, mengompilasinya, membaca log LaTeX, mengunduh PDF, dan menjawab komentar. Mulai v6.3.3, klien juga dapat menelusuri riwayat dan memulihkan versi, meninjau perubahan terlacak, menambahkan komentar, memakai obrolan proyek, dan memindahkan file.

<Info>

Fitur ini dikembangkan oleh [ayaka-notes/ayakaleaf-pro](https://github.com/ayaka-notes/ayakaleaf-pro). Fitur ini diperkenalkan sejak v6.3.1 dan versi selanjutnya. Alat untuk riwayat, perubahan terlacak, obrolan proyek, komentar baru, dan pemindahan file tersedia mulai v6.3.3, lihat [Yang baru di v6.3.3](/on-premises/user-guide/users/mcp-server#new-in-v6.3.3).

</Info>

### Penyiapan {#setup}

MCP server disertakan bersama integrasi Git: aktifkan [git-bridge](/id/on-premises/configuration/overleaf-toolkit/integrations/git-integration), dan MCP server juga akan tersedia. Tidak ada hal lain yang perlu dikonfigurasi.

### Menghubungkan klien AI {#connect-an-ai-client}

1. Di **Account Settings**, buat token autentikasi Git. Token yang sama digunakan untuk MCP server dan untuk Git.
2. Di editor, buka **Integrations** dan klik **MCP server**. Dialog ini menampilkan alamat MCP server proyek, `https://<your-overleaf>/project/<project_id>/mcp`, serta cara menambahkannya ke setiap klien AI: salin perintahnya, lalu ganti `<token>` dengan token Anda.

Token dikirim sebagai header HTTP `Authorization: Bearer <token>`. Misalnya, perintah untuk Claude Code adalah:

```bash
claude mcp add --transport http overleaf \
  https://<your-overleaf>/project/<project_id>/mcp \
  --header "Authorization: Bearer <token>"
```

### Penggunaan {#usage}

Setelah terhubung, ajukan permintaan ke klien AI dengan bahasa sehari-hari. Contohnya:

| Anda meminta | Klien AI menggunakan |
| --- | --- |
| _Perbaiki salah ketik di bagian pendahuluan._ | `read_file`, `edit_file`: suntingan langsung terlihat di editor |
| _Kompilasi proyek dan perbaiki error LaTeX-nya._ | `compile`, `get_compile_log`, `edit_file` |
| _Jawab komentar yang masih terbuka, lalu selesaikan._ | `list_comments`, `reply_to_comment`, `resolve_comment` |
| _Beralih ke XeLaTeX dan unduh PDF-nya._ | `update_settings`, `compile`, `get_output_file_link` |
| _Tulis ulang abstrak sebagai perubahan terlacak._ | `read_file`, `edit_file` dengan `trackChanges` (v6.3.3) |
| _Apa yang berubah sejak versi yang dikirim?_ | `list_versions`, `list_changes`, `diff` (v6.3.3) |
| _Pindahkan bab-bab ke folder bernama chapters._ | `move_file` (v6.3.3) |

### Tools {#tools}

| Grup | Tools |
| --- | --- |
| Proyek | `get_clone_info`, `get_settings`, `update_settings` |
| File | `list_files`, `read_file`, `edit_file`, `write_file`, `delete_file`, `move_file`, `create_folder` |
| Kompilasi | `compile`, `get_compile_log`, `get_output_file_link`, `word_count` |
| Komentar | `list_comments`, `reply_to_comment`, `resolve_comment`, `reopen_comment`, `add_comment`, `edit_comment_message`, `delete_comment_message` |
| Perubahan terlacak | `list_tracked_changes`, `accept_tracked_changes`, `reject_tracked_changes` |
| Riwayat | `list_versions`, `list_changes`, `diff`, `create_version`, `delete_version`, `restore_file`, `restore_project` |
| Obrolan | `list_chat_messages`, `send_chat_message` |

v6.3.3 memiliki 33 alat, atau 31 dengan `OVERLEAF_DISABLE_CHAT=true`, yang menghapus alat obrolan. v6.3.1 dan v6.3.2 memiliki 17 alat lainnya: semua di atas kecuali `move_file`, `create_folder`, `add_comment`, `edit_comment_message`, `delete_comment_message`, alat perubahan terlacak, alat obrolan, dan alat riwayat selain `list_versions`. Di v6.3.3, `read_file` juga membaca file pada versi riwayat, `edit_file` dan `write_file` menerima `trackChanges`, dan `update_settings` juga mengatur bahasa pemeriksa ejaan.

Pengeditan dengan `edit_file`, `write_file`, dan `move_file` tampil langsung di editor dan digabungkan dengan pengeditan kolaborator. Untuk banyak file sekaligus atau file biner, klien AI juga dapat meng-clone proyek dengan Git lalu push.

Dengan `trackChanges`, pengeditan file yang sudah ada menjadi perubahan terlacak milik pengguna token, bahkan ketika lacak perubahan nonaktif di proyek; file baru tidak pernah demikian. Tanpa `trackChanges`, pengeditan mengikuti pengaturan lacak perubahan proyek.

### Izin {#permissions}

MCP server mengikuti pengaturan berbagi proyek, seperti Git:

* Semua orang yang dapat melihat proyek dapat membacanya, mengompilasinya, dan mengunduh keluarannya.
* Hanya pemilik dan editor yang dapat mengubah file dan pengaturannya, memulihkan versi, serta menerima atau menolak perubahan terlacak.
* Peninjau juga dapat menambahkan komentar dan membalasnya, menyelesaikan, membuka kembali, atau menghapus komentar yang mereka mulai, serta menyimpan versi. Mereka tidak dapat mengedit file, bahkan sebagai perubahan terlacak.
* Setiap orang hanya mengedit pesan komentarnya sendiri, dan peninjau hanya menghapus milik mereka sendiri.
* Hanya pemilik yang menghapus versi yang disimpan orang lain.
* Pembaca yang bergabung melalui tautan tidak dapat melihat komentar, perubahan terlacak, riwayat, atau obrolan, seperti di editor. Pembaca yang diundang dapat melihatnya dan memakai obrolan.
* Jika pemilik proyek tidak memiliki **Full project history**, alat riwayat hanya menampilkan perubahan 24 jam terakhir, seperti panel riwayat. Admin melihat semuanya.

Panduan pengguna memiliki tabel tentang apa yang boleh dilakukan setiap peran, lihat [Siapa boleh melakukan apa](/on-premises/user-guide/users/mcp-server#who-may-do-what).

### Tanya Jawab {#q&a}

<Accordion title="Saya tidak melihat Integrations atau MCP server di editor">

<strong>Jawaban:</strong> MCP server tidak memiliki variabel lingkungan sendiri. MCP server diaktifkan dengan `GIT_BRIDGE_ENABLED=true` di `config/overleaf.rc`, lihat [Integrasi Git](/id/on-premises/configuration/overleaf-toolkit/integrations/git-integration). Setelah mengubahnya, jalankan `bin/up -d`. Tanpa git-bridge, editor tidak menampilkan tab **Integrations** di rail kirinya.

</Accordion>

<Accordion title="Klien AI mengatakan “Track changes is off for this project”">

<strong>Jawaban:</strong> Klien meminta perubahan terlacak, tetapi akun pemilik proyek tidak memiliki fitur lacak perubahan. Klik **Admin**, lalu **Manage Users**, buka pemilik, dan di tab **Features** aktifkan **Track changes**, lihat [Features](/id/on-premises/user-guide/administrators/user-management#features). Pengeditan tanpa `trackChanges` tetap berfungsi.

</Accordion>

<Accordion title="Klien AI hanya melihat perubahan 24 jam terakhir">

<strong>Jawaban:</strong> Akun pemilik proyek tidak memiliki riwayat proyek lengkap, sehingga alat riwayat menampilkan apa yang ditampilkan panel riwayat: perubahan 24 jam terakhir. Klik **Admin**, lalu **Manage Users**, buka pemilik, dan di tab **Features** aktifkan **Full project history**, lihat [Features](/id/on-premises/user-guide/administrators/user-management#features).

</Accordion>
