Akses tamu ke proyek yang dibagikan, halaman publik, dan pendaftaran mandiri diaktifkan dengan variabel lingkungan yang dibaca oleh layanan **web**; layanan real-time kemudian melayani tamu melalui sesi mereka. Apa yang dibuka oleh setiap sakelar dijelaskan di [Akses Publik](/id/on-premises/configuration/overleaf-toolkit/authentication/public-access).

| | |
| --- | --- |
| Layanan | web (dan real-time untuk tamu di editor), di setiap pod Ayakaleaf Pro; dibaca saat web dimulai |
| Pod → luar | server SMTP, saat pendaftaran mengirim email aktivasi |
| Status | token akses tamu di sesi, batas laju pendaftaran di Redis |
| Job berkala | tidak ada |

### Konfigurasi

Tambahkan sakelar yang Anda perlukan ke ConfigMap `overleaf-env`:

```yaml title="30-config.yaml (additions)"
  # Guests open link-shared projects without an account
  OVERLEAF_ALLOW_ANONYMOUS_READ_AND_WRITE_SHARING: "true"
  # Signed-out visitors may open /learn, /templates, /devs and view links
  OVERLEAF_ALLOW_PUBLIC_ACCESS: "true"
  # Self-registration: "true", or only some domains
  OVERLEAF_ALLOW_PUBLIC_REGISTRATION: "@example.com, @*.uni.example"
```

```bash
kubectl apply -f 30-config.yaml
kubectl -n overleaf rollout restart deployment/overleaf     # or statefulset/overleaf
```

Beri tanda kutip pada setiap nilai. Nilai yang diawali dengan `@` harus diberi tanda kutip di YAML, jika tidak `kubectl apply` akan menolak file tersebut.

Pendaftaran yang dibatasi pada domain tertentu mengirim email aktivasi, sehingga [Pengiriman email](/id/on-premises/configuration/kubernetes/email-delivery) harus berfungsi dari pod: masukkan host SMTP ke ConfigMap dan `OVERLEAF_EMAIL_SMTP_PASS` ke Secret.

### Beberapa replika

Tidak ada yang perlu ditambahkan. Akses tamu ke suatu proyek disimpan di sesi di Redis, sehingga editor berfungsi di replika mana pun yang dipilih load balancer.

### Diuji di Kubernetes

Di Kubernetes 1.37, pengujian end-to-end kami untuk akses publik lulus: pada satu replika, pendaftaran mandiri dengan `OVERLEAF_ALLOW_PUBLIC_REGISTRATION` diatur ke `true`, ke satu domain, ke beberapa domain dengan wildcard subdomain, dan ke `@*`, dengan email aktivasi untuk mode domain (43 kasus); pengunjung yang belum login di `/devs` dan snippet yang dikirim tetap tersimpan selama proses login dengan `OVERLEAF_ALLOW_PUBLIC_ACCESS` (2 kasus); tamu yang belum login di proyek yang dibagikan melalui tautan dengan kedua sakelar aktif (3 kasus); dan pada tiga replika di belakang HAProxy, OIDC bersama dengan akses publik (1 kasus).
