Layanan **web** memeriksa kata sandi lokal saat pengguna mendaftar, mengatur, atau mengubah kata sandi. Login SSO (LDAP, SAML, OIDC) tidak terpengaruh; kata sandinya menjadi urusan penyedia identitas. Lihat [Pembatasan kata sandi](/id/on-premises/configuration/overleaf-toolkit/authentication/password-restrictions) untuk Toolkit.

| | |
| --- | --- |
| Layanan | web, di setiap pod Ayakaleaf Pro; dibaca saat web dimulai |
| Jaringan | tidak ada |
| Job berkala | tidak ada |

### Konfigurasi

Tambahkan ke ConfigMap `overleaf-env` dan restart:

```yaml title="30-config.yaml (additions)"
  OVERLEAF_PASSWORD_VALIDATION_MIN_LENGTH: "12"
  OVERLEAF_PASSWORD_VALIDATION_MAX_LENGTH: "72"
```

```bash
kubectl apply -f 30-config.yaml
kubectl -n overleaf rollout restart deployment/overleaf     # or statefulset/overleaf
```

| Variabel | Default | |
| --- | --- | --- |
| `OVERLEAF_PASSWORD_VALIDATION_MIN_LENGTH` | `8` | Kata sandi terpendek yang diterima. |
| `OVERLEAF_PASSWORD_VALIDATION_MAX_LENGTH` | `72` | Kata sandi terpanjang yang diterima; nilai di atas `72` diperlakukan sebagai `72`. |

Beri tanda kutip pada angka: ConfigMap hanya menyimpan string.

<Warning>

`OVERLEAF_PASSWORD_VALIDATION_PATTERN` dibaca tetapi tidak diberlakukan: kata sandi yang tidak cocok dengannya tetap diterima. Hanya batas panjang yang berlaku.

</Warning>

### Beberapa replika

Tidak ada yang perlu ditambahkan: setiap replika membaca ConfigMap yang sama.

### Diuji di Kubernetes

Di Kubernetes 1.37 dengan satu replika, `OVERLEAF_PASSWORD_VALIDATION_MIN_LENGTH: "12"` dan `OVERLEAF_PASSWORD_VALIDATION_PATTERN: aA$3` di ConfigMap, aktivasi akun baru menolak kata sandi 10 karakter dan menerima kata sandi 20 karakter yang hanya terdiri dari huruf kecil, yang seharusnya ditolak oleh pola tersebut. Pengujian end-to-end kami untuk pendaftaran juga menolak `123456` karena terlalu pendek dengan nilai default.
