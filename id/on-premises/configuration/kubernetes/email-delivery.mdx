Layanan **web** mengirim setiap email (aktivasi, undangan proyek, reset kata sandi) dari setiap pod Ayakaleaf Pro. Pengaturannya sama seperti di Toolkit, lihat [Pengiriman email](/id/on-premises/configuration/overleaf-toolkit/email-delivery).

| | |
| --- | --- |
| Layanan | web, di setiap pod Ayakaleaf Pro; dibaca saat web dimulai |
| Pod → luar | server SMTP Anda (`OVERLEAF_EMAIL_SMTP_HOST`), atau Amazon SES API di `OVERLEAF_EMAIL_AWS_SES_REGION` |
| Status | batas laju pengiriman di Redis |
| Job berkala | tidak ada |

### Konfigurasi {#configuration}

<Steps>
<Step title="ConfigMap">
```yaml title="30-config.yaml (additions)" wrap
  OVERLEAF_EMAIL_FROM_ADDRESS: no-reply@example.com
  OVERLEAF_EMAIL_SMTP_HOST: smtp.example.com
  OVERLEAF_EMAIL_SMTP_PORT: "587"
  OVERLEAF_EMAIL_SMTP_SECURE: "false"
  OVERLEAF_EMAIL_SMTP_USER: no-reply@example.com
  # optional
  # OVERLEAF_EMAIL_REPLY_TO: support@example.com
  # OVERLEAF_EMAIL_SMTP_IGNORE_TLS: "false"
  # OVERLEAF_EMAIL_SMTP_TLS_REJECT_UNAUTH: "true"
```

`OVERLEAF_EMAIL_FROM_ADDRESS` mengaktifkan pengiriman. Atur hanya bersama dengan server SMTP (atau SES): jika hanya pengirim yang diatur, Ayakaleaf Pro mencoba server SMTP di dalam pod, dan setiap email gagal. Tanpa pengaturan ini, email tidak dikirim, hanya ditulis ke `web.log`.

`OVERLEAF_EMAIL_SMTP_SECURE`, `OVERLEAF_EMAIL_SMTP_IGNORE_TLS`, dan `OVERLEAF_EMAIL_SMTP_TLS_REJECT_UNAUTH` dibaca sebagai JSON, jadi gunakan `"true"` atau `"false"`: nilai seperti `yes` menghentikan setiap layanan di pod saat startup.
</Step>

<Step title="Secret">
```bash
kubectl -n overleaf patch secret overleaf-secrets --type merge \
  -p '{"stringData":{"OVERLEAF_EMAIL_SMTP_PASS":"<SMTP password>"}}'
```

Untuk Amazon SES API, masukkan `OVERLEAF_EMAIL_AWS_SES_ACCESS_KEY_ID` dan `OVERLEAF_EMAIL_AWS_SES_SECRET_KEY` di sini sebagai gantinya, serta `OVERLEAF_EMAIL_DRIVER: ses` dan `OVERLEAF_EMAIL_AWS_SES_REGION` ke ConfigMap.
</Step>

<Step title="Terapkan, restart, dan uji">
```bash
kubectl apply -f 30-config.yaml
kubectl -n overleaf rollout restart deployment/overleaf     # or statefulset/overleaf
```

Kirim email reset kata sandi ke diri Anda sendiri dari halaman login. Jika email tidak sampai, periksa apakah server SMTP dapat dijangkau dari pod dan lihat log web:

```bash
kubectl -n overleaf exec deploy/overleaf -- bash -c 'echo > /dev/tcp/smtp.example.com/587 && echo reachable'
kubectl -n overleaf exec deploy/overleaf -- grep -iE "email|smtp" /var/log/overleaf/web.log | tail
```
</Step>
</Steps>

### Beberapa email per akun {#several-emails-per-account}

Tidak ada yang perlu dikonfigurasi lagi: setelah email berfungsi, pengguna dapat menambahkan email ke akun mereka dan memindahkan akun ke salah satunya. Lihat [Beberapa email per akun](/id/on-premises/configuration/overleaf-toolkit/email-delivery#several-emails-per-account) untuk aturannya dan [panduan pengguna](/id/on-premises/user-guide/users/multiple-emails) untuk langkah-langkahnya. Kode konfirmasi disimpan di sesi pengguna di Redis.

### Beberapa replika {#several-replicas}

Tidak ada yang perlu ditambahkan. Setiap replika mengirim dengan pengaturan yang sama, dan batas laju pengiriman dihitung di Redis untuk semua replika. Jika server SMTP Anda hanya menerima pengirim yang dikenal, izinkan alamat yang digunakan pod saat keluar dari kluster (biasanya alamat node).

### Diuji di Kubernetes {#tested-on-kubernetes}

Dengan Mailpit sebagai server SMTP, di Kubernetes 1.37 dengan satu replika, pengujian end-to-end kami yang mengirim email lulus: email aktivasi untuk akun yang dibuat admin, email aktivasi untuk pendaftaran mandiri yang dibatasi pada domain tertentu, email reset kata sandi, email yang memberi tahu pengguna bahwa akunnya telah dihapus, serta apa yang terjadi saat server SMTP menolak email aktivasi atau penghapusan: akun tetap dibuat atau dihapus, dan email aktivasi dapat dikirim ulang nanti. Dengan `OVERLEAF_EMAIL_FROM_ADDRESS` tanpa host SMTP, permintaan reset kata sandi gagal dengan error dan `web.log` menampilkan "error sending message", seperti dijelaskan di atas.
