Halaman `/learn` disajikan oleh layanan **web** (modul `learn`) di setiap pod Ayakaleaf Pro, dari cache wiki yang diatur di `WIKI_URL`. Apa yang dilakukan modul ini dan wiki mana yang berfungsi dijelaskan di [Menambahkan bantuan pengguna LaTeX](/id/on-premises/configuration/overleaf-toolkit/adding-latex-user-help).

| | |
| --- | --- |
| Layanan | web (modul `learn`), di setiap pod Ayakaleaf Pro |
| Pod → luar | `WIKI_URL` (default `https://learnwiki.overleaf.com`): setiap halaman saat start pertama, lalu suatu halaman lagi ketika pengguna membukanya setelah `WIKI_MAX_CACHE_AGE` |
| Browser → luar | gambar pada halaman, langsung dari `WIKI_URL` |
| Data yang disimpan | cache halaman di `/var/lib/overleaf/data/learnPages` pada volume data |
| Job berkala | tidak ada: halaman diperbarui saat pengguna membukanya |

### Konfigurasi

```yaml title="30-config.yaml (additions)"
  OVERLEAF_PROXY_LEARN: "true"
  # optional: your own MediaWiki
  # WIKI_URL: https://wiki.example.com
```

```bash
kubectl apply -f 30-config.yaml
kubectl -n overleaf rollout restart deployment/overleaf     # or statefulset/overleaf
kubectl -n overleaf rollout status deployment/overleaf --timeout=30m
```

<Warning>

Pada start pertama dengan modul aktif, layanan web mengunduh seluruh wiki sebelum menerima permintaan, yang memakan waktu beberapa menit. Pod tetap tidak siap (not ready) hingga saat itu, jadi perhitungkan hal ini pada `rollout status --timeout` dan pada setiap startup probe atau liveness probe yang Anda tambahkan. Start berikutnya menggunakan kembali cache pada volume data.

</Warning>

Pada start pertama, sebelum cache ada, pod harus dapat menjangkau `WIKI_URL`: tanpa itu layanan web gagal saat memulai dan di-restart di dalam pod berulang kali, sehingga pod tidak pernah menjadi siap. Nonaktifkan modul ini, atau izinkan pod keluar ke wiki. Setelah cache ada, pod dapat dimulai dan menyajikan halaman dari cache meskipun wiki tidak dapat dijangkau.

### Beberapa replika

Setiap replika menyimpan cache-nya sendiri di disk node-nya, sehingga masing-masing mengunduh wiki saat start pertamanya; dengan `podManagementPolicy: OrderedReady` mereka melakukannya satu per satu. Pengguna mungkin melihat suatu halaman dalam versi yang sedikit berbeda pada replika lain hingga halaman tersebut diperbarui di sana.

### Diuji di Kubernetes

Di Kubernetes 1.37 dengan tiga replika di belakang HAProxy, yang masing-masing mengunduh `https://learnwiki.overleaf.com` ke cache node-nya sendiri saat start pertama, pengujian end-to-end kami untuk `/learn` lulus (12 kasus): tautan Documentation di header, pesan sambutan dan menu Help di editor, sidebar daftar isi, halaman, tautan dan redirect di dalam wiki, gambar yang dimuat dari wiki, 404 untuk halaman yang tidak dikenal, login yang diwajibkan tanpa akses publik, serta halaman lama yang disajikan dari cache setelah `WIKI_URL` diubah ke alamat yang tidak dapat dijangkau. Saat dimulai dengan cache kosong dan `WIKI_URL` mengarah ke alamat yang menolak koneksi, pod tetap tidak siap tanpa restart, sementara layanan web di dalamnya dimulai dan gagal 77 kali dalam tiga menit.
