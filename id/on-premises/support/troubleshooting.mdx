<Accordion title="Menjalankan Overleaf dengan sistem file NFS">

Me-mount sistem file NFS di kontainer Overleaf secara teknis memungkinkan, tetapi tidak disarankan dan dapat mengakibatkan berbagai jenis masalah performa.

Salah satu error umum yang terjadi saat kompilasi adalah:

```text
EBUSY: resource busy or locked, unlink '/var/lib/overleaf/data/compiles/62f3d57bef7cf9005c364e75-62f3d57bef7cf9005c364e7a/.nfs573663533034825247625441'
```

Secara khusus, kami tidak menyarankan penggunaan sistem file berbasis NFS untuk data sementara, seperti direktori yang digunakan untuk data kompilasi. Kami menyarankan penggunaan disk scratch lokal, sebaiknya SSD lokal, untuk direktori-direktori berikut.

Untuk penyiapan berbasis `docker-compose`, kami menyarankan cukup menimpa bind-mount dari NFS, sehingga tidak perlu mengubah path di aplikasi. Berikut contoh potongan konfigurasi `docker-compose` yang menggunakan disk scratch yang di-mount di `/scratch`:

```yaml title="docker-compose excerpt"
services:
  sharelatex:
    environment:
      SANDBOXED_COMPILES_HOST_DIR: /scratch/compiles/
    volumes:
      - nfs:/var/lib/overleaf/data
      - /scratch/cache/:/var/lib/overleaf/data/cache
      - /scratch/compiles/:/var/lib/overleaf/data/compiles
      - /scratch/output/:/var/lib/overleaf/data/output
      - /scratch/tmp/:/var/lib/overleaf/tmp
```

Tidak perlu memigrasikan file yang sudah ada dari NFS ke lokasi barunya setelah pembaruan. Compiler LaTeX dapat membuat ulang semua file dengan menjalankan kompilasi penuh kembali.

Untuk detail lebih lanjut, lihat: https://docs.overleaf.com/on-premises/support/troubleshooting#running-overleaf-with-an-nfs-filesystem

</Accordion>

<Accordion title="Menjalankan Overleaf di Windows atau macOS menyebabkan layanan `mongo` tidak dapat dijalankan">

Jika Anda menjalankan Overleaf di Windows atau macOS, layanan `mongo` mungkin gagal dimulai ulang, dengan error:

```text title="Example error"
Failed to start up WiredTiger under any compatibility version.
Reason: 1: Operation not permitted
```

Hal ini dapat terjadi ketika data MongoDB di-bind-mount dari filesystem yang tidak menyediakan semantik yang diperlukan, seperti direktori yang di-mount dari Windows. Untuk [Windows dengan WSL 2](/id/on-premises/installation/using-docker-compose/windows), simpan Toolkit di direktori home Linux Ubuntu dan gunakan bind mount default. Lihat [pemeriksaan MongoDB](/id/on-premises/installation/using-docker-compose/windows/troubleshooting#mongodb-fails-to-start) di panduan platform tersebut.

Untuk instalasi baru yang memerlukan penyimpanan yang dikelola Docker, override berikut menggunakan named volume (lihat [panduan penyimpanan image MongoDB](https://github.com/docker-library/docs/blob/master/mongo/content.md#where-to-store-data)). Pada instalasi yang sudah ada, mengubah mount tidak memigrasikan data: lakukan backup dan restore database/cache sebelum beralih, atau layanan akan melihat volume kosong. Tambahkan ini ke `config/docker-compose.override.yml`, dengan menggabungkannya dengan konfigurasi yang sudah ada:

```yaml title="config/docker-compose.override.yml"
volumes:
  mongo-data:
  redis-data:

services:
  mongo:
    volumes:
      - mongo-data:/data/db

  redis:
    volumes:
      - redis-data:/data
```

Untuk informasi lebih lanjut, lihat: https://docs.overleaf.com/on-premises/support/troubleshooting#running-overleaf-on-windows-or-macos-results-in-the-mongoservice-not-starting

</Accordion>

<Accordion title="Upgrade ke Redis 6.2 menyebabkan restart loop">

Gunakan perintah `docker logs redis` untuk menampilkan salinan log.

Jika Anda melihat baris `Fatal: Can't initialize Background Jobs`, output lengkapnya akan terlihat seperti ini:

```text title="Redis log example"
1:M 11 Feb 2024 15:19:22.609 # Server initialized
1:M 11 Feb 2024 15:19:22.609 # Fatal: Can't initialize Background Jobs.
1:C 11 Feb 2024 15:19:26.055 # oO0OoO0OoO0Oo Redis is starting oO0OoO0OoO0Oo
```

Hal ini mungkin terkait dengan versi Docker yang sedang digunakan. Memperbarui ke versi >= 20.10.10 seharusnya dapat menyelesaikan masalah ini.

Untuk informasi lebih lanjut, lihat issue upstream Redis: https://github.com/redis/redis/issues/12362

Referensi: https://docs.overleaf.com/on-premises/support/troubleshooting#upgrading-to-redis-6.2-results-in-a-restart-loop

</Accordion>

<Accordion title="Orientasi gambar pratinjau/thumbnail galeri templat yang salah">

Terkadang, gambar pratinjau/thumbnail yang dihasilkan oleh Ayakaleaf Pro dapat dibuat dengan orientasi yang salah dan memerlukan intervensi manual untuk memperbaikinya. Gambar-gambar ini disimpan di `/var/lib/overleaf/data/template_files/`.

Kami menyarankan untuk mem-backup folder ini sebelum melakukan perubahan apa pun.

Anda perlu mengikuti langkah-langkah di bawah ini untuk setiap templat yang terpengaruh:

Temukan ID templatBuka galeri templat instans Anda (/templates/all), buka templat yang terpengaruh, dan salin ID dari URL (misalnya: https://your-instance-url/templates/6645d346c224815e9460a695).Jalankan perintah koreksiJalankan perintah berikut dari host Docker (ganti ID templat dengan yang Anda salin dan perbarui path jika perlu):docker exec sharelatex /bin/bash -c "mogrify -rotate 90 /var/lib/overleaf/data/template\_files/6645d346c224815e9460a695\_\*\{thumbnail,preview\}"

Referensi: https://docs.overleaf.com/on-premises/support/troubleshooting#incorrect-orientation-of-template-gallery-preview-thumbnail-images

</Accordion>

<Accordion title="Please verify that you have enabled system calls. For pdflatex, this is 'pdflatex -shell-escape'.">

Perintah `\write18` dinonaktifkan secara default di Community Edition karena semua kompilasi terjadi di dalam kontainer `sharelatex` yang sama; ini adalah default yang lebih aman.

Jika Anda ingin mengaktifkannya untuk pdflatex, buat file `latexmkrc` di root proyek Anda dengan konten berikut:

```perl title="latexmkrc"
$pdflatex = 'pdflatex --shell-escape';
```

Lalu coba kompilasi ulang.

Referensi: https://docs.overleaf.com/on-premises/support/troubleshooting#please-verify-that-you-have-enabled-system-calls.-for-pdflatex-this-is-pdflatex-shell-escape

</Accordion>

<Accordion title='`bin/up` gagal dengan `unable to upgrade to tcp, received 409` atau `OCI runtime exec failed` setelah "Initiating Mongo replica set..."'>

Error ini berarti kontainer `mongo` terus mengalami crash dan memulai ulang. `bin/up` menjalankan MongoDB lalu menjalankan perintah di dalamnya, yang gagal saat kontainer memulai ulang. `bin/docker-compose ps` menampilkan layanan `mongo` sebagai `Restarting`.

Untuk menemukan penyebab sebenarnya, baca log MongoDB:

```sh
bin/logs mongo
```

Penyebab umumnya adalah:

* <strong>CPU tidak mendukung AVX.</strong> MongoDB 5.0 dan yang lebih baru memerlukan AVX pada x86-64, dan log menampilkan `MongoDB 5.0+ requires a CPU with AVX support`. Pada mesin virtual, atur tipe CPU ke `host` agar AVX diteruskan.
* <strong>Kernel Linux 6.19 hingga 7.0.13.</strong> MongoDB menolak berjalan pada kernel ini. Lihat [Persyaratan perangkat lunak](/id/on-premises/installation/introduction#software-requirements) untuk solusinya.
* <strong>Data dibuat oleh versi MongoDB yang lebih lama.</strong> MongoDB 8.0 tidak dapat membuka data dari 4.4 atau 5.0 secara langsung. Lakukan upgrade satu versi mayor setiap kali, lihat [Memperbarui MongoDB](/id/on-premises/maintenance/updating-mongodb).

</Accordion>

<Accordion title='Log menampilkan "Running Overleaf Community Edition, skipping TexLive checks"'>

Hal ini memang diharapkan pada Ayakaleaf Pro dan dapat Anda abaikan. Pesan ini dicetak saat `OVERLEAF_IS_SERVER_PRO` tidak bernilai `true`, yang memang demikian pada image Ayakaleaf Pro. Ayakaleaf Pro tidak memerlukan variabel ini, jadi biarkan tidak diatur.

</Accordion>

<Accordion title="Kontainer `sharelatex` terus memulai ulang">

Sebelum Overleaf berjalan, kontainer menjalankan pemeriksaan startup dan keluar jika salah satunya gagal. Toolkit menjalankannya dengan `restart: always`, sehingga Docker memulainya lagi dan pemeriksaan yang sama gagal lagi. Output startup menyebutkan pemeriksaan yang gagal:

```sh
bin/docker-compose logs --tail=100 sharelatex
```

Penyebab umumnya adalah:

* **`Missing required secrets`**: atur `OVERLEAF_INVITE_TOKEN_SECRET` di `config/variables.env`, lihat [Variabel lingkungan](/id/on-premises/configuration/overleaf-toolkit/environment-variables).
* **`ShareLaTeX to Overleaf rebranding`**: konfigurasi masih menggunakan variabel atau path `SHARELATEX_`; ganti namanya seperti yang disebutkan dalam pesan.
* **Error setelah `Checking can connect to mongo and redis`**: Overleaf tidak dapat menjangkau MongoDB atau Redis. Periksa `bin/logs mongo` dan `bin/logs redis`.

Setelah memperbaiki penyebabnya, jalankan `bin/up -d`.

</Accordion>

<Accordion title="Kontainer berhenti di `910_initiate_doc_version_recovery` atau keluar dengan kode 2">

Setiap kali dijalankan, kontainer menjalankan skrip startup-nya satu per satu, dan log menyebutkan masing-masing skrip sebagai `*** Running /etc/my_init.d/<script>...`. `910_initiate_doc_version_recovery` hanya memiliki pekerjaan pada instance yang pernah menjalankan Overleaf 5.0.1. Pada instance lain, skrip ini menampilkan `No recovery of doc versions needed.` dan proses startup berlanjut. Output-nya juga ditulis ke `data/history/doc-version-recovery.log` di `OVERLEAF_DATA_PATH`.

Exit code dan bagian akhir `bin/docker-compose logs --tail=100 sharelatex` menunjukkan apa yang terjadi:

* **Exit code 2**, dan log diakhiri dengan `*** Init system aborted.`: kontainer dihentikan, misalnya oleh `bin/stop`, `docker stop`, atau Ctrl+C pada `bin/up`. Skrip di baris `Running` terakhir hanyalah skrip yang sedang berjalan pada saat itu, skrip tersebut tidak gagal. Jalankan kontainer lagi dengan `bin/up -d` dan biarkan proses startup selesai.
* **Exit code 1**, dan log menampilkan `*** /etc/my_init.d/<script> failed with status <n>`: skrip tersebut gagal, dan error-nya ada di baris-baris tepat di atasnya. Jika `910_initiate_doc_version_recovery` gagal dengan `Detected unflushed changes while recovering doc versions`, instance tersebut pernah menjalankan 5.0.1 dan masih memiliki perubahan yang belum di-flush; ikuti panduan resmi [Doc version recovery](https://docs.overleaf.com/on-premises/release-notes/release-notes-5.x.x/doc-version-recovery).

</Accordion>

<Accordion title="“Restricted, sorry you don’t have permission to load this page”">

Halaman ini ditampilkan ketika akun Anda sudah login tetapi tidak diizinkan membuka halaman tersebut, misalnya halaman admin yang dibuka oleh akun yang bukan administrator, atau proyek yang tidak dibagikan kepada Anda.

Untuk membuka halaman admin, login dengan akun administrator. Administrator yang sudah ada dapat menjadikan akun lain sebagai administrator, atau Anda dapat membuatnya dengan perintah `create-user --admin`, lihat [Manajemen pengguna](/id/on-premises/user-and-project-management/user-management). Di lingkungan pengembangan (`develop/`), halaman admin juga memerlukan `ADMIN_PRIVILEGE_AVAILABLE=true` di `develop/dev.env`; image Ayakaleaf Pro sudah mengaturnya.

</Accordion>
