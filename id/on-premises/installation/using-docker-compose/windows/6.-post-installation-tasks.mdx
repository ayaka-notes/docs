### Membuat administrator dan proyek pertama {#create-the-administrator-and-a-first-project}

Buka [http://localhost:8080/launchpad](http://localhost:8080/launchpad) di **browser Windows** Anda, buat akun administrator pertama, lalu login. Kemudian ikuti [6. Tugas pasca-instalasi](/id/on-premises/installation/using-docker-compose/linux/6.-post-installation-tasks) pada panduan Linux, dengan menggunakan port `8080` di URL contohnya.

### Memverifikasi kompilasi {#verify-compilation}

Halaman login yang berfungsi tidak membuktikan bahwa kontainer compiler terpisah dapat mengakses direktori data WSL. Buat proyek kosong dan kompilasi `main.tex` berikut dengan **pdfLaTeX**:

```latex
\documentclass{article}
\begin{document}
Ayakaleaf Pro on Windows WSL 2.
\end{document}
```

Pratinjau PDF seharusnya menampilkan teks tersebut. Untuk image basic, pilih **TeX Live 2026 Basic** di pengaturan proyek jika diperlukan.

Pilih **XeLaTeX** dan uji:

```latex
\documentclass{article}
\usepackage{fontspec}
\begin{document}
Ayakaleaf WSL XeLaTeX sandbox.
\end{document}
```

Kedua contoh berfungsi dengan image basic. Untuk dokumen bahasa Mandarin, gunakan image yang berisi `ctex` dan font yang diperlukan, seperti full, sebelum menguji contoh berikut dengan **XeLaTeX**. Image basic tidak menyertakannya:

```latex
\documentclass{ctexart}
\begin{document}
你好，Ayakaleaf Pro。
\end{document}
```

Untuk memastikan sandbox digunakan, jalankan di **Ubuntu** saat kompilasi berlangsung:

```bash
docker ps -a --filter ancestor=ghcr.io/ayaka-notes/texlive-basic:2026.1
bin/logs -f clsi
```

Gunakan nama image yang Anda pilih di filter. Kompilasi singkat mungkin selesai sebelum `docker ps` dijalankan; `-a` juga menampilkan kontainer yang sudah berhenti hingga dibersihkan. Kontainer compiler seharusnya menggunakan image tersebut dan bind mount `/compile` dari direktori data WSL milik Toolkit. Log aplikasi saja tidak dapat menggantikan pemeriksaan PDF.

### Memverifikasi persistensi {#verify-persistence}

Di **Ubuntu**, dari direktori Toolkit:

```bash
bin/stop
bin/start
```

Tunggu aplikasi siap, buka kembali proyek dari Windows, lalu kompilasi lagi. Akun, kode sumber, dan file proyek Anda seharusnya masih ada. Data aktif default berada di `~/ayakaleaf-toolkit/data/` di dalam Ubuntu. Simpan `config/` dan `data/`; menghapus instalasi atau membatalkan registrasi distribusi Ubuntu dapat menghapus keduanya.

### Menjaga instance tetap tersedia {#keep-the-instance-available}

Ada tiga bagian untuk menjaga instance tetap berjalan: Windows tetap aktif, Docker Desktop berjalan, dan kontainer di-restart bersama engine.

Di **Settings → General** Docker Desktop, aktifkan **Start Docker Desktop when you sign in to your computer**, lihat [pengaturan Docker Desktop](https://docs.docker.com/desktop/settings-and-maintenance/settings/). Ini menjalankan Docker setelah login, bukan sebelum login. Setelah Windows di-restart, login, tunggu hingga Docker Desktop selesai dijalankan, buka Ubuntu, lalu periksa `docker ps` dan situs.

**Resource Saver** Docker Desktop terpisah dari mode tidur Windows. Fitur ini biasanya hanya aktif saat tidak ada kontainer yang berjalan; aplikasi, MongoDB, dan Redis yang sedang berjalan mencegah kondisi idle tersebut. Di WSL 2, fitur ini menjeda engine Docker, bukan mematikan VM WSL bersama. Jangan melakukan **Pause** Docker Desktop secara manual saat melayani pengguna. Anda tidak perlu menonaktifkan Resource Saver hanya untuk menjaga stack ini tetap berjalan; lihat [dokumentasi Resource Saver Docker](https://docs.docker.com/desktop/use-desktop/resource-saver/).

Layanan Toolkit menggunakan `restart: always`. Verifikasi pengaturan sebenarnya di **Ubuntu**:

```bash
docker inspect sharelatex mongo redis --format '{{.Name}} restart={{.HostConfig.RestartPolicy.Name}}'
```

Setiap layanan seharusnya melaporkan `always`. Setelah Docker berjalan, Docker dapat me-restart kontainer yang sudah ada tersebut tanpa `bin/up` baru. Kontainer yang dihentikan secara manual tetap berhenti hingga Anda menjalankannya atau me-restart engine; dengan `always`, restart engine dapat menjalankannya kembali. Lihat [perilaku restart policy Docker](https://docs.docker.com/engine/containers/start-containers-automatically/).

| Tindakan | Dampak pada Ayakaleaf |
| --- | --- |
| Menutup terminal Ubuntu setelah `bin/up -d` | Kontainer berjalan di latar belakang; terminal bukan pengawasnya. Pastikan Docker Desktop dan lingkungan WSL tetap tersedia |
| Menutup jendela Docker Dashboard | Jendela dapat ditutup sementara Docker Desktop tetap berjalan di system tray |
| Memilih **Quit Docker Desktop** | Menghentikan engine dan membuat situs tidak tersedia; buka Docker Desktop lagi untuk memulihkannya |
| Menjalankan `wsl --shutdown` | Menghentikan semua distribusi WSL dan menginterupsi backend WSL Docker; restart Docker Desktop dan buka kembali Ubuntu |
| Mode tidur, hibernasi, atau mematikan Windows | Layanan tidak tersedia; hanya menyalakan atau mematikan layar tidak mengubah hal ini |
| Menjalankan `bin/stop` | Menghentikan instance sambil mempertahankan datanya; gunakan `bin/start` untuk melanjutkan |

Untuk penggunaan jangka panjang dengan daya listrik, buka **Settings → System → Power & battery → Screen, sleep & hibernate timeouts** di Windows 11 (beberapa versi menampilkan **Power** atau **Screen and sleep**). Atur batas waktu tidur saat terhubung ke daya menjadi **Never** dan nonaktifkan hibernasi otomatis jika dikonfigurasi. Layar tetap boleh mati. Tindakan saat lid laptop ditutup adalah pengaturan terpisah; menutup lid dapat membuat laptop masuk ke mode tidur meskipun batas waktu tidur saat idle diatur ke Never. Lihat [pengaturan daya Windows](https://support.microsoft.com/en-us/windows/experience/power-battery/power-settings-in-windows-11).

Jangan menjalankan `wsl --shutdown` sebagai pembersihan rutin saat situs sedang digunakan. Jika perubahan pengaturan WSL memerlukannya, hentikan instance terlebih dahulu dan rencanakan interupsinya. Windows dapat menjalankan instance secara terus-menerus dengan pengaturan ini. Untuk layanan bersama yang harus tetap berjalan meskipun pengguna logout dan reboot tanpa pengawasan, kami merekomendasikan [panduan Linux](/id/on-premises/installation/using-docker-compose/linux).

### Memeriksa pemulihan setelah me-restart Docker Desktop {#check-recovery-after-restarting-docker-desktop}

Setelah menyimpan pekerjaan dan membiarkan kompilasi aktif selesai, pilih **Restart Docker Desktop** dari menu troubleshooting Docker Desktop. Tunggu engine siap, lalu periksa di **Ubuntu**:

```bash
docker ps
curl -I http://localhost:8080/launchpad
```

Buka proyek yang sudah ada di Windows dan kompilasi lagi. Pastikan akun dan kode sumber masih ada.

Jika Anda sengaja menghentikan instance dengan `bin/stop`, gunakan `bin/start`. Jika Docker berjalan tetapi sebuah layanan gagal, baca lognya alih-alih membuat ulang konfigurasi. Windows Update, pembaruan Docker, dan pemadaman listrik tetap dapat menginterupsi instalasi yang berjalan 24 jam; simpan backup dan periksa pemulihan setelah pemeliharaan terencana.

### Penggunaan sehari-hari {#daily-use}

Jalankan Docker Desktop di Windows. Buka **Ubuntu**:

```bash
cd "$HOME/ayakaleaf-toolkit"
```

| Tugas | Perintah |
| --- | --- |
| Menjalankan kontainer yang sudah ada | `bin/start` |
| Menghentikan kontainer dan mempertahankan data | `bin/stop` |
| Menerapkan perubahan konfigurasi | `bin/up -d` |
| Memeriksa status | `bin/docker-compose ps` |
| Membaca log startup | `bin/docker-compose logs --tail=100 sharelatex` |
| Membaca log MongoDB | `bin/docker-compose logs --tail=100 mongo` |
| Membaca log compiler | `bin/logs -f clsi` |

`bin/start` tidak menerapkan perubahan konfigurasi: gunakan `bin/up -d` setelah mengubah `config/`. Ikuti [Data dan backup](/id/on-premises/maintenance/data-and-backups) sebelum meng-upgrade, memindahkan, atau menghapus distribusi WSL. Menyalin file MongoDB yang aktif saat database sedang menulis bukanlah backup yang konsisten.

Pertahankan `127.0.0.1` untuk penggunaan lokal. Melayani komputer lain juga memerlukan alamat listen, URL situs, konfigurasi firewall/jaringan Windows, dan HTTPS yang diatur secara sengaja; mengubah `OVERLEAF_SITE_URL` saja tidak memublikasikan port.

Jika ada yang tidak berfungsi, lihat [Pemecahan masalah](/id/on-premises/installation/using-docker-compose/windows/troubleshooting).
