Ayakaleaf Pro menggunakan kontainer Linux. Di Windows, instal Docker Desktop dengan backend WSL 2 dan jalankan skrip Toolkit di Ubuntu.

WSL 2 menyediakan kernel Linux. Docker Desktop mengelola engine Docker di lingkungan `docker-desktop` miliknya sendiri; mengaktifkan **WSL Integration** memungkinkan Docker CLI di Ubuntu berkomunikasi dengan engine tersebut. Toolkit kemudian menjalankan aplikasi, MongoDB, dan Redis sebagai kontainer. Dengan sandboxed compiles diaktifkan, aplikasi menggunakan socket Docker milik engine untuk menjalankan kontainer TeX Live terpisah untuk setiap kompilasi. Anda tidak memerlukan instalasi MongoDB, Redis, atau TeX Live di Windows.

<Steps>
<Step title="Instal WSL 2 dan Ubuntu">
Buka **PowerShell sebagai administrator** di Windows dan jalankan:

```powershell
wsl --install -d Ubuntu
```

Restart Windows jika diminta. Buka **Ubuntu** dari menu Start dan buat nama pengguna serta kata sandi Linux. Ini adalah akun untuk `sudo` di dalam Ubuntu; akun ini terpisah dari login Windows Anda.

Kembali ke **PowerShell**, perbarui WSL dan periksa distribusinya:

```powershell
wsl --update
wsl --version
wsl --list --verbose
```

Baris Ubuntu harus menampilkan **VERSION 2**. Jika menampilkan 1, gunakan nama distribusi persisnya dari daftar:

```powershell
wsl --set-version Ubuntu 2
```

Docker memerlukan WSL **2.1.5 atau lebih baru**; versi perangkat lunak WSL dari `wsl --version` dan kolom **VERSION 2** distribusi adalah pemeriksaan yang berbeda. Lihat [pemecahan masalah instalasi](/id/on-premises/installation/using-docker-compose/windows/troubleshooting#wsl-or-docker-reports-that-virtualization-is-unavailable) dan [petunjuk instalasi Microsoft](https://learn.microsoft.com/en-us/windows/wsl/install) jika instalasi gagal, dan aktifkan virtualisasi hardware di BIOS/UEFI jika WSL melaporkan bahwa virtualisasi tidak tersedia.
</Step>

<Step title="Instal dan jalankan Docker Desktop">
Unduh [Docker Desktop for Windows](https://docs.docker.com/desktop/setup/install/windows-install/) untuk prosesor Anda dan jalankan installer-nya. Gunakan backend **WSL 2** jika ditawarkan. Buka **Docker Desktop** dari menu Start Windows dan tunggu hingga engine berjalan.

Di **Settings → General** Docker Desktop, aktifkan **Use WSL 2 based engine** jika opsi tersebut ditampilkan. Di **Settings → Resources → WSL Integration**, aktifkan integrasi untuk **Ubuntu**, lalu pilih **Apply** atau **Apply & restart**. Jika Ubuntu bukan distribusi default Anda, aktifkan switch-nya sendiri secara eksplisit.

Jika WSL Integration tidak ada, periksa bahwa Docker Desktop menggunakan **Linux containers**. Lihat [panduan backend WSL 2 Docker](https://docs.docker.com/desktop/features/wsl/).

Gunakan integrasi Docker Desktop untuk panduan ini. Menginstal Docker Engine kedua dengan `apt install docker.io` atau menjalankan `dockerd` di dalam Ubuntu akan membuat penyiapan terpisah dan dapat menyebabkan konflik. Jika Anda sudah menggunakan Engine di Ubuntu, ikuti panduan migrasi Docker sebelum beralih; pertahankan data aplikasi dan backup yang sudah ada.
</Step>

<Step title="Periksa Docker dari Ubuntu">
Buka terminal **Ubuntu**. Jalankan perintah berikut di sana, tanpa `sudo`:

```bash
docker version
docker compose version
docker ps
```

`docker version` harus menampilkan **Client** dan **Server**. Daftar kontainer kosong adalah hal normal pada instalasi baru. `docker --version` saja tidak membuktikan bahwa engine sedang berjalan.

Jika `docker` tidak tersedia atau tidak dapat terhubung, buka kembali Ubuntu setelah menerapkan WSL Integration dan periksa bahwa Docker Desktop sedang berjalan. Lihat [Pemecahan masalah](/id/on-premises/installation/using-docker-compose/windows/troubleshooting#docker-is-unavailable-in-ubuntu).
</Step>

<Step title="Periksa sumber daya dan socket Docker">
Periksa sumber daya yang terlihat oleh Docker:

```bash
docker info --format 'CPUs={{.NCPU}} Memory={{.MemTotal}} Kernel={{.KernelVersion}}'
df -h "$HOME"
ls -l /var/run/docker.sock
```

Untuk instance lokal kecil, 4 CPU dan memori 8 GB yang tersedia untuk Docker adalah saran awal, bukan batas minimum hasil pengukuran. Sisakan juga memori yang cukup untuk Windows. Dengan backend WSL 2, batas sumber daya dikelola melalui [pengaturan WSL](https://learn.microsoft.com/en-us/windows/wsl/wsl-config), bukan slider sumber daya Docker Desktop seperti di Mac. Perubahan yang memerlukan `wsl --shutdown` akan menginterupsi semua distribusi WSL dan workload Docker yang sedang berjalan; terapkan perubahan tersebut sebelum menjalankan instance.

Biarkan `DOCKER_SOCKET_PATH=/var/run/docker.sock` di konfigurasi Toolkit. Aplikasi memerlukan socket engine ini untuk sandboxed compiles. Jangan mengubah izinnya menjadi `777` untuk memperbaiki error koneksi; pulihkan integrasi Docker Desktop sebagai gantinya.
</Step>
</Steps>
