---
title: 5. Menyesuaikan instance Anda
description: Atur port, URL situs, dan image TeX Live untuk instance lokal di Mac Anda, periksa kernel VM Docker, dan jalankan Ayakaleaf Pro.
icon: square-sliders
---

<Steps>
<Step title="Pengaturan kontainer">
Edit entri yang sudah ada berikut di `config/overleaf.rc`:

```bash title="config/overleaf.rc"
PROJECT_NAME=ayakaleaf-macos
SERVER_PRO=true
OVERLEAF_LISTEN_IP=127.0.0.1
OVERLEAF_PORT=8080
SIBLING_CONTAINERS_ENABLED=true
DOCKER_SOCKET_PATH=/var/run/docker.sock
```

Pertahankan path data default serta layanan MongoDB dan Redis bawaan. Dengan `OVERLEAF_LISTEN_IP=127.0.0.1`, hanya browser di Mac ini yang dapat membuka instance.
</Step>

<Step title="Pengaturan aplikasi">
Di `config/variables.env`, atur nilai-nilai berikut, dan ganti entri aktif dengan nama yang sama:

```dotenv title="config/variables.env"
OVERLEAF_SITE_URL=http://localhost:8080
TEX_LIVE_DOCKER_IMAGE=ghcr.io/ayaka-notes/texlive-full:2026.1
ALL_TEX_LIVE_DOCKER_IMAGES=ghcr.io/ayaka-notes/texlive-full:2026.1
ALL_TEX_LIVE_DOCKER_IMAGE_NAMES="TeX Live 2026"
```

Buat session secret:

```bash
openssl rand -hex 32
```

Tambahkan hasilnya sebagai `OVERLEAF_SESSION_SECRET` di `config/variables.env`. Tanpa ini, setiap `bin/up` yang membuat ulang kontainer akan mengeluarkan semua pengguna dari sesi login, lihat [Variabel Lingkungan](/id/on-premises/configuration/overleaf-toolkit/environment-variables).

Untuk instance lokal tanpa email, biarkan pengaturan SMTP dan `OVERLEAF_EMAIL_FROM_ADDRESS` tidak diatur. Git Bridge, autentikasi eksternal, dan integrasi lainnya dapat ditambahkan nanti melalui [halaman konfigurasi](/id/on-premises/configuration/overleaf-toolkit) masing-masing.
</Step>

<Step title="Periksa kernel Linux VM Docker" id="check-the-docker-vms-linux-kernel">
MongoDB berjalan di kernel Linux mesin virtual Docker Desktop, bukan di macOS. Periksa versinya sebelum menjalankan untuk pertama kali:

```bash
docker info --format '{{.KernelVersion}}'
```

MongoDB mendokumentasikan ketidakcocokan dengan kernel Linux **6.19 hingga 7.0.13**, yang juga memengaruhi MongoDB di Docker. Perbaikannya adalah kernel **7.0.14 atau lebih baru**, yang tersedia melalui pembaruan Docker Desktop, lihat [catatan produksi MongoDB](https://www.mongodb.com/docs/manual/administration/production-notes/).

Jika VM Docker Anda menggunakan kernel yang terdampak, tambahkan berikut ini ke `config/docker-compose.override.yml`, digabungkan dengan `services` yang sudah Anda miliki di sana:

```yaml title="config/docker-compose.override.yml"
services:
  mongo:
    environment:
      GLIBC_TUNABLES: glibc.pthread.rseq=1
```

<Warning>

Perbarui ke kernel yang sudah diperbaiki jika tersedia. Jika kernel Anda berada di luar rentang yang terdampak, solusi sementara ini tidak diperlukan.

</Warning>
</Step>

<Step title="Jalankan instance Anda">
Dari direktori Toolkit, jalankan:

```bash
bin/up -d
```

Toolkit menginisialisasi replica set MongoDB, melakukan pull image TeX Live, dan menjalankan aplikasi. Unduhan pertama memerlukan waktu cukup lama. Untuk mengikuti progresnya:

```bash
bin/docker-compose ps
bin/docker-compose logs --tail=100 -f sharelatex
```

Tekan `Ctrl+C` untuk berhenti mengikuti log. Kontainer tetap berjalan.

Periksa port yang dipublikasikan dan halaman first-run:

```bash
bin/docker-compose port sharelatex 80
curl -I http://localhost:8080/launchpad
```

Port seharusnya `127.0.0.1:8080`.
</Step>
</Steps>

<Info>

Untuk membuka instance dari komputer lain nanti, ubah alamat listen dan URL situs, lalu siapkan HTTPS, seperti yang dijelaskan di [5. Menyesuaikan instance Anda](/id/on-premises/installation/using-docker-compose/linux/5.-personalizing-your-instance) pada panduan Linux. Mac kemudian harus tetap aktif, lihat [Menjaga instance tetap tersedia](/id/on-premises/installation/using-docker-compose/macos/6.-post-installation-tasks#keep-the-instance-available).

</Info>
