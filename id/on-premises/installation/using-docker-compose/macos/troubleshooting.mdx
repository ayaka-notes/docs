### Inisialisasi gagal dengan invalid command code {#initialization-fails-with-invalid-command-code}

`bin/init` melaporkan `sed: ... invalid command code` saat menemukan BSD sed bawaan macOS. Letakkan GNU sed di `PATH` seperti di [1. Mengunduh Toolkit](/id/on-premises/installation/using-docker-compose/macos/1.-download-the-toolkit) dan periksa `sed --version`.

Inisialisasi yang gagal dapat meninggalkan ketiga file di `config/` dengan `OVERLEAF_INVITE_TOKEN_SECRET` yang kosong. Menjalankan `bin/init` lagi kemudian akan melaporkan `Config files already exist`. Untuk instalasi baru yang belum pernah dijalankan, pindahkan ketiga file tersebut ke direktori backup dan jalankan `bin/init` lagi. Untuk instance yang sudah ada, pertahankan konfigurasi dan secret-nya, dan jangan menghapus file-filenya agar `bin/init` dapat dijalankan lagi.

### MongoDB terus restart {#mongodb-keeps-restarting}

Baca log MongoDB dan versi kernel VM Docker:

```bash
bin/docker-compose logs --tail=100 mongo
docker info --format '{{.KernelVersion}}'
```

Jika log menyebutkan ketidakcocokan kernel Linux, ikuti [Periksa kernel Linux VM Docker](/id/on-premises/installation/using-docker-compose/macos/5.-personalizing-your-instance#check-the-docker-vms-linux-kernel) dan jalankan `bin/up -d` lagi. Exit code `137` saja tidak membuktikan bahwa MongoDB kehabisan memori: periksa status kontainer dan log. Untuk masalah MongoDB yang lebih lama di Docker Desktop, lihat juga [Pemecahan masalah](/id/on-premises/support/troubleshooting).

### Tidak dapat terhubung ke Docker daemon {#cannot-connect-to-the-docker-daemon}

Jalankan Docker Desktop dan periksa Docker context yang dipilih, lihat [0. Menyiapkan Docker Desktop](/id/on-premises/installation/using-docker-compose/macos/0.-setup-docker-desktop). Jika `docker info` berfungsi tetapi kompilasi tidak dapat menjangkau Docker, periksa pengaturan socket di `config/overleaf.rc` dan baca log `clsi`. Docker CLI yang berfungsi di Mac tidak membuktikan bahwa mount socket aplikasi sudah benar.

### Halaman terbuka, tetapi kompilasi gagal {#the-page-opens-but-compiles-fail}

Periksa bahwa image TeX Live ada secara lokal dan sesuai dengan arsitektur engine Docker:

```bash
docker image inspect ghcr.io/ayaka-notes/texlive-full:2026.1 \
  --format '{{.Os}}/{{.Architecture}}'
bin/logs -f clsi
```

Di Apple silicon, image seharusnya `linux/arm64`. Periksa bahwa `SERVER_PRO` dan `SIBLING_CONTAINERS_ENABLED` keduanya bernilai `true`, lalu terapkan perubahan dengan `bin/up -d`. Jika log melaporkan direktori kompilasi yang hilang, periksa berbagi file Docker Desktop dan lokasi `OVERLEAF_DATA_PATH`. Jangan menonaktifkan sandboxed compiles untuk menyembunyikan kegagalan mount.

### Not a directory, atau bind mount tidak ada {#not-a-directory-or-a-bind-mount-is-missing}

File host yang di-mount oleh override mungkin telah dihapus, atau Docker mungkin telah membuat direktori di tempat yang seharusnya berisi file. Periksa path sumber di host, dan apakah mount tersebut mengharapkan file atau direktori. Pulihkan file konfigurasi sebelum Anda membuat ulang kontainer. Instalasi di bawah `/tmp` dapat mengalami hal ini setelah macOS menghapus file sementara.

### Konflik port atau nama kontainer {#port-or-container-name-conflicts}

Jika port `8080` sedang digunakan, pilih port lain di `config/overleaf.rc`, sesuaikan `OVERLEAF_SITE_URL`, dan jalankan `bin/up -d` lagi.

Toolkit memberikan nama tetap untuk kontainernya, seperti `sharelatex`, `mongo`, dan `redis`. Mengubah `PROJECT_NAME` saja tidak membuat dua instalasi Toolkit menjadi independen. Sebelum Anda menjalankan instance kedua, periksa `docker ps -a`, dan gunakan nama kontainer lain di Compose override, port lain, serta direktori data terpisah. Jangan menghapus kontainer atau data deployment yang sudah ada untuk mengatasi konflik nama.

### Instance tidak dapat dijangkau setelah beberapa waktu {#the-instance-is-unreachable-after-a-while}

Mac kemungkinan masuk ke mode tidur, atau Docker Desktop ditutup. Lihat [Menjaga instance tetap tersedia](/id/on-premises/installation/using-docker-compose/macos/6.-post-installation-tasks#keep-the-instance-available).

### `bin/doctor` menyatakan ini bukan Linux, atau meminta login Quay {#bin/doctor-says-this-is-not-linux-or-asks-for-a-quay-login}

Kedua peringatan tersebut wajar di macOS dengan image publik, lihat [2. Kenali Toolkit](/id/on-premises/installation/using-docker-compose/macos/2.-familiarize-yourself-with-the-toolkit). Sebagai gantinya, periksa pull image, status layanan, dan hasil kompilasi, dan jangan abaikan error lain dalam laporan.
