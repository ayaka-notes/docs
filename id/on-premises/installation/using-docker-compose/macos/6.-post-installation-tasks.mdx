### Membuat administrator dan proyek pertama {#create-the-administrator-and-a-first-project}

Buka [http://localhost:8080/launchpad](http://localhost:8080/launchpad), buat akun administrator pertama, lalu login. Kemudian ikuti [6. Tugas pasca-instalasi](/id/on-premises/installation/using-docker-compose/linux/6.-post-installation-tasks) pada panduan Linux, dengan menggunakan port `8080` di URL contohnya.

### Memverifikasi kompilasi {#verify-compilation}

Halaman login yang terbuka tidak membuktikan bahwa kontainer compiler terpisah dan mount datanya berfungsi. Buat proyek kosong dan kompilasi `main.tex` berikut:

```latex
\documentclass{article}
\begin{document}
Ayakaleaf Pro on macOS.
\end{document}
```

Pratinjau PDF seharusnya menampilkan teks tersebut. Jika perlu, pilih TeX Live 2026 di pengaturan proyek.

Untuk proyek dengan teks bahasa Mandarin, pilih **XeLaTeX** sebagai compiler dan uji:

```latex
\documentclass{ctexart}
\begin{document}
你好，Ayakaleaf Pro。
\end{document}
```

### Memverifikasi persistensi {#verify-persistence}

```bash
bin/stop
bin/start
```

Buka kembali proyek dan kompilasi lagi. Akun Anda, kode sumber, dan file proyek seharusnya masih ada. Dengan path default, data aktif berada di direktori `data/` milik Toolkit di Mac Anda.

### Menjaga instance tetap tersedia {#keep-the-instance-available}

Saat Mac dalam mode tidur, macOS menangguhkan mesin virtual Docker Desktop beserta semua kontainer di dalamnya: tidak ada yang dapat membuka instance, dan kompilasi yang sedang berjalan akan berhenti hingga Mac aktif kembali. Hanya mode tidur sistem yang berpengaruh. Layar boleh mati.

Jika orang lain menggunakan instance, atau Anda membiarkan tugas panjang berjalan, biarkan Mac tetap terhubung ke daya dan cegah mode tidur otomatis, lihat [Mengatur pengaturan tidur dan bangun untuk Mac Anda](https://support.apple.com/guide/mac-help/set-sleep-and-wake-settings-mchle41a6ccd/mac):

| Mac | Pengaturan |
| --- | --- |
| Mac desktop (Mac mini, iMac, Mac Studio, Mac Pro) | **System Settings → Energy**: aktifkan **Prevent automatic sleeping when the display is off** |
| MacBook | **System Settings → Battery → Options**: aktifkan **Prevent automatic sleeping on power adapter when the display is off**. Ini hanya berlaku saat adaptor daya terhubung, dan menutup lid tetap membuat MacBook masuk ke mode tidur |

Untuk menjaga Mac tetap aktif hanya untuk sementara, jalankan `caffeinate -i` di jendela Terminal sebagai gantinya. Perintah ini mencegah mode tidur saat idle hingga Anda menekan `Ctrl+C` atau menutup jendela.

Docker Desktop adalah aplikasi di sesi pengguna Anda. Agar instance kembali berjalan setelah restart, aktifkan **Start Docker Desktop when you sign in to your computer** di **Settings → General** Docker Desktop. Kontainer Toolkit menggunakan `restart: always`, sehingga Docker menjalankannya kembali begitu Docker Desktop berjalan, tanpa `bin/up`. Hingga seseorang login ke Mac setelah restart, instance tetap tidak aktif.

<Info>

Mac yang tetap aktif menggunakan lebih banyak daya. Untuk layanan yang harus selalu dapat dijangkau, kami merekomendasikan server Linux, lihat [Linux](/id/on-premises/installation/using-docker-compose/linux).

</Info>

### Penggunaan sehari-hari {#daily-use}

Buka Docker Desktop sebelum Anda mengelola instance. Di terminal baru:

```bash
export PATH="$(brew --prefix gnu-sed)/libexec/gnubin:$PATH"
cd "$HOME/ayakaleaf-toolkit"
```

| Tugas | Perintah |
| --- | --- |
| Menjalankan kontainer yang sudah ada | `bin/start` |
| Menghentikan kontainer dan mempertahankan data | `bin/stop` |
| Menerapkan perubahan konfigurasi | `bin/up -d` |
| Memeriksa status | `bin/docker-compose ps` |
| Membaca log startup | `bin/docker-compose logs --tail=100 sharelatex` |
| Membaca log compiler | `bin/logs -f clsi` |

`bin/start` tidak menerapkan perubahan di `config/`: jalankan `bin/up -d` setelah Anda mengedit konfigurasi. Simpan `config/` dan `data/`, dan ikuti [Data dan backup](/id/on-premises/maintenance/data-and-backups) sebelum upgrade atau sebelum Anda memindahkan instalasi. Menyalin file database saat MongoDB sedang menulis ke file tersebut bukanlah backup yang konsisten.

Pertahankan instance di `127.0.0.1` untuk penggunaan lokal. Untuk melayani komputer lain, atur alamat listen, URL situs, dan HTTPS secara sengaja, lihat [5. Menyesuaikan instance Anda](/id/on-premises/installation/using-docker-compose/linux/5.-personalizing-your-instance) pada panduan Linux.

Jika ada yang tidak berfungsi, lihat [Pemecahan masalah](/id/on-premises/installation/using-docker-compose/macos/troubleshooting).
