Ayakaleaf Pro membutuhkan:

* **MongoDB 8** sebagai **replica set** (karena menggunakan transaksi). Tiga anggota yang tersebar di tiga node tetap bertahan jika satu node hilang; satu anggota juga dapat digunakan.
* **Redis 7**, satu server dengan persistensi AOF. Redis menyimpan editan yang belum ditulis ke MongoDB, sesi, dan pesan antar layanan Overleaf. Overleaf terhubung ke satu server Redis: Sentinel dan Redis Cluster tidak didukung.

<Info>

Anda dapat menggunakan layanan terkelola sebagai gantinya, seperti MongoDB Atlas atau Redis dari cloud Anda. Lewati halaman ini dan atur `OVERLEAF_MONGO_URL` dan `OVERLEAF_REDIS_HOST` ke layanan tersebut di [langkah 4](/id/on-premises/installation/using-kubernetes/4.-personalizing-your-instance).

</Info>

<Steps>
<Step title="MongoDB">
```yaml title="10-mongo.yaml" wrap
apiVersion: v1
kind: Service
metadata:
  name: mongo
  namespace: overleaf
spec:
  clusterIP: None                 # headless: gives mongo-0.mongo, mongo-1.mongo, ...
  publishNotReadyAddresses: true  # members must resolve each other before the set is initiated
  selector:
    app: mongo
  ports:
    - name: mongo
      port: 27017
---
apiVersion: apps/v1
kind: StatefulSet
metadata:
  name: mongo
  namespace: overleaf
spec:
  serviceName: mongo
  replicas: 3
  selector:
    matchLabels:
      app: mongo
  template:
    metadata:
      labels:
        app: mongo
    spec:
      affinity:
        podAntiAffinity:
          requiredDuringSchedulingIgnoredDuringExecution:
            - labelSelector:
                matchLabels:
                  app: mongo
              topologyKey: kubernetes.io/hostname
      containers:
        - name: mongo
          image: mongo:8.0
          args:
            - --replSet=overleaf
            - --bind_ip_all
            - --wiredTigerCacheSizeGB=0.25   # default is 50% of (RAM - 1 GB); size it for your nodes
          # env:
          #   - name: GLIBC_TUNABLES        # only on kernel 6.19+ (SERVER-121912)
          #     value: glibc.pthread.rseq=1
          ports:
            - containerPort: 27017
          readinessProbe:
            tcpSocket:
              port: 27017
          resources:
            requests:
              cpu: 100m
              memory: 384Mi
            limits:
              memory: 768Mi
          volumeMounts:
            - name: data
              mountPath: /data/db
  volumeClaimTemplates:
    - metadata:
        name: data
      spec:
        accessModes: [ReadWriteOnce]
        resources:
          requests:
            storage: 5Gi
---
# Initiates the replica set once. Safe to re-run: it does nothing when the set exists.
apiVersion: batch/v1
kind: Job
metadata:
  name: mongo-init-replica-set
  namespace: overleaf
spec:
  backoffLimit: 20
  template:
    spec:
      restartPolicy: OnFailure
      containers:
        - name: init
          image: mongo:8.0
          command:
            - mongosh
            - --quiet
            - --host=mongo-0.mongo
            - --eval
            - |
              try {
                rs.status()
                print('replica set already initiated')
              } catch (e) {
                rs.initiate({
                  _id: 'overleaf',
                  members: [
                    { _id: 0, host: 'mongo-0.mongo.overleaf.svc.cluster.local:27017' },
                    { _id: 1, host: 'mongo-1.mongo.overleaf.svc.cluster.local:27017' },
                    { _id: 2, host: 'mongo-2.mongo.overleaf.svc.cluster.local:27017' },
                  ],
                })
              }
```

```bash
kubectl apply -f 10-mongo.yaml
kubectl -n overleaf rollout status statefulset/mongo
kubectl -n overleaf wait --for=condition=complete job/mongo-init-replica-set --timeout=5m
kubectl -n overleaf exec mongo-0 -- mongosh --quiet --eval 'rs.status().members.map(m => m.name + " " + m.stateStr)'
```

Setelah beberapa detik, satu anggota seharusnya menjadi `PRIMARY` dan yang lainnya `SECONDARY`. Job akan mencoba ulang hingga semua anggota merespons, jadi beberapa pod Job yang gagal adalah hal yang normal.

* Service headless memerlukan `publishNotReadyAddresses: true`: anggota harus dapat menemukan satu sama lain berdasarkan nama sebelum replica set terbentuk.
* Anggota ditambahkan dengan nama stabilnya (`mongo-0.mongo.overleaf.svc.cluster.local`), bukan IP pod, yang berubah setiap kali dimulai ulang.
* Untuk satu anggota, atur `replicas: 1` dan pertahankan hanya `mongo-0` di Job.
</Step>

<Step title="Redis">
```yaml title="20-redis.yaml" wrap
apiVersion: v1
kind: Service
metadata:
  name: redis
  namespace: overleaf
spec:
  selector:
    app: redis
  ports:
    - name: redis
      port: 6379
---
apiVersion: apps/v1
kind: StatefulSet
metadata:
  name: redis
  namespace: overleaf
spec:
  serviceName: redis
  replicas: 1
  selector:
    matchLabels:
      app: redis
  template:
    metadata:
      labels:
        app: redis
    spec:
      containers:
        - name: redis
          image: redis:7.4
          args: [--appendonly, "yes"]
          ports:
            - containerPort: 6379
          readinessProbe:
            tcpSocket:
              port: 6379
          resources:
            requests:
              cpu: 50m
              memory: 128Mi
            limits:
              memory: 512Mi
          volumeMounts:
            - name: data
              mountPath: /data
  volumeClaimTemplates:
    - metadata:
        name: data
      spec:
        accessModes: [ReadWriteOnce]
        resources:
          requests:
            storage: 2Gi
```

```bash
kubectl apply -f 20-redis.yaml
kubectl -n overleaf rollout status statefulset/redis
```
</Step>
</Steps>

### Tanya Jawab

<Accordion title="MongoDB 8 crash saat startup di kernel terbaru. Mengapa?">

<strong>Jawaban:</strong> MongoDB 8 gagal di kernel Linux 6.19 dan yang lebih baru ([SERVER-121912](https://jira.mongodb.org/browse/SERVER-121912)). Hapus komentar pada variabel lingkungan `GLIBC_TUNABLES` di `10-mongo.yaml`.

</Accordion>

<Accordion title="Berapa banyak memori yang dibutuhkan MongoDB?">

<strong>Jawaban:</strong> Secara default MongoDB menggunakan setengah dari memori node dikurangi 1 GB untuk cache-nya, dan yang dilihatnya adalah memori node, bukan batas pod. Atur `--wiredTigerCacheSizeGB` agar sesuai dengan node Anda; `0.25` menjaga setiap anggota di sekitar 200 hingga 260 MiB pada node uji 4 GB kami.

</Accordion>
