---
title: 0. Siapkan node
description: Instal Docker Engine, containerd, dan kubeadm di node, lalu pull image TeX Live.
icon: server
---

Ayakaleaf Pro mengompilasi LaTeX di kontainer TeX Live yang [di-sandbox](/id/on-premises/configuration/overleaf-toolkit/sandboxed-compiles). Ayakaleaf Pro memulainya sendiri, melalui socket Docker dari mesin tempatnya berjalan. Di Kubernetes ini berarti:

* setiap node yang dapat menjalankan pod Ayakaleaf Pro memiliki **Docker Engine** yang terinstal dan berjalan;
* setiap image TeX Live yang Anda konfigurasikan di-pull **ke Docker** di setiap node tersebut.

Kubelet tetap dapat menggunakan containerd: Docker Engine menyertakan `containerd.io`, dan keduanya menggunakan daemon yang sama dalam namespace yang berbeda.

<Warning>

Node pool terkelola tanpa Docker (sebagian besar default EKS, GKE, dan AKS) tidak dapat menjalankan sandboxed compiles. Gunakan node pool tempat Anda dapat menginstal Docker Engine, atau beri label pada node tersebut dan pertahankan Ayakaleaf Pro di sana dengan `nodeSelector`.

</Warning>

Langkah-langkah di bawah ini untuk Ubuntu 24.04 dan klaster yang dibangun dengan kubeadm. Jika klaster Anda sudah ada, lakukan langkah 1, 2, dan 5 di node yang akan menjalankan Ayakaleaf Pro.

<Steps>
<Step title="Modul kernel dan sysctl">
```bash
printf 'overlay\nbr_netfilter\n' | sudo tee /etc/modules-load.d/k8s.conf
sudo modprobe overlay && sudo modprobe br_netfilter
printf 'net.bridge.bridge-nf-call-iptables=1\nnet.bridge.bridge-nf-call-ip6tables=1\nnet.ipv4.ip_forward=1\n' \
  | sudo tee /etc/sysctl.d/99-k8s.conf
sudo sysctl --system
sudo swapoff -a   # and comment out swap in /etc/fstab
```
</Step>

<Step title="Docker Engine">
Instal Docker Engine dari repositori Docker seperti di [0. Menyiapkan Docker](/id/on-premises/installation/using-docker-compose/linux/0.-setup-docker). Plugin Compose tidak diperlukan. Langkah ini juga menginstal `containerd.io`.
</Step>

<Step title="containerd untuk kubelet">
Paket `containerd.io` dari repositori Docker memiliki plugin CRI yang dinonaktifkan. Tulis konfigurasi default lengkap, yang mengaktifkannya, dan alihkan ke cgroup systemd:

```bash wrap
containerd config default | sudo tee /etc/containerd/config.toml >/dev/null
sudo sed -i 's/SystemdCgroup = false/SystemdCgroup = true/' /etc/containerd/config.toml
# containerd 2.x writes config_path = '' and ignores /etc/containerd/certs.d without this
sudo sed -i "s|config_path = ''|config_path = '/etc/containerd/certs.d'|" /etc/containerd/config.toml
sudo systemctl restart containerd docker
```
</Step>

<Step title="kubeadm, kubelet, dan kubectl">
Ikuti [Installing kubeadm](https://kubernetes.io/docs/setup/production-environment/tools/kubeadm/install-kubeadm/), lalu buat klaster dengan `kubeadm init` dan `kubeadm join` serta instal plugin jaringan. Misalnya, dengan flannel:

```yaml title="kubeadm-config.yaml"
apiVersion: kubeadm.k8s.io/v1beta4
kind: ClusterConfiguration
networking:
  podSubnet: 10.244.0.0/16   # flannel's default
---
apiVersion: kubelet.config.k8s.io/v1beta1
kind: KubeletConfiguration
cgroupDriver: systemd
# Compile containers are started by Docker, outside the kubelet's accounting: keep memory for them
systemReserved:
  memory: 300Mi
kubeReserved:
  memory: 200Mi
```

```bash
sudo kubeadm init --config kubeadm-config.yaml
kubectl apply -f https://github.com/flannel-io/flannel/releases/latest/download/kube-flannel.yml
```

Klaster juga memerlukan StorageClass default. Untuk klaster uji, [local-path-provisioner](https://github.com/rancher/local-path-provisioner) dapat digunakan; di produksi, gunakan block storage dari platform Anda (Longhorn, Ceph, driver CSI cloud).
</Step>

<Step title="Image TeX Live">
Di **setiap** node yang dapat menjalankan Ayakaleaf Pro, pull image TeX Live yang akan Anda cantumkan di `ALL_TEX_LIVE_DOCKER_IMAGES` dengan Docker, misalnya:

```bash
sudo docker pull ghcr.io/ayaka-notes/texlive-full:2026.1
```

`crictl pull` atau `ctr` tidak membantu di sini: Ayakaleaf Pro meminta image dari Docker. Image full berukuran besar (sekitar 28 GB masing-masing); lihat [Sandboxed Compiles](/id/on-premises/configuration/overleaf-toolkit/sandboxed-compiles) untuk daftarnya. Untuk pengujian pertama, `ghcr.io/ayaka-notes/texlive-basic:2026.1` (sekitar 630 MB, TeX Live minimal) sudah cukup.
</Step>
</Steps>

### Tanya Jawab {#q&a}

<Accordion title="Dapatkah saya menjalankan Ayakaleaf Pro di node tanpa Docker?">

<strong>Jawaban:</strong> Hanya dengan `SANDBOXED_COMPILES=false`. Kompilasi kemudian berjalan di dalam kontainer Ayakaleaf Pro dengan TeX Live bawaan yang kecil, dan dokumen LaTeX dapat membaca dan menulis apa pun yang dapat diakses kontainer tersebut. Kami tidak merekomendasikannya; lihat [Sandboxed Compiles](/id/on-premises/configuration/overleaf-toolkit/sandboxed-compiles).

</Accordion>

<Accordion title="Apakah kompilasi dihitung dalam batas memori pod?">

<strong>Jawaban:</strong> Tidak. Kontainer TeX Live dimulai oleh Docker milik node, di luar pod dan di luar pantauan kubelet. Sisakan memori kosong di node untuk kontainer tersebut, misalnya dengan `systemReserved` seperti di atas, dan jangan memenuhi node dengan pod lain.

</Accordion>
