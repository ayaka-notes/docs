Kubernetes menjalankan image yang sama dengan Toolkit. Tidak ada image Kubernetes tersendiri.

| Image                                                | Digunakan oleh                                                          |
| ---------------------------------------------------- | ----------------------------------------------------------------------- |
| `ghcr.io/ayaka-notes/overleaf-pro:6.3.2`             | Deployment `overleaf`                                                   |
| `ghcr.io/ayaka-notes/overleaf-pro/git-bridge:6.3.2`  | [Integrasi Git](/id/on-premises/configuration/kubernetes/integrations/git-integration) (opsional), tag yang sama seperti di atas |
| `ghcr.io/ayaka-notes/texlive-*`                      | kompilasi, di-pull ke Docker di node pada [langkah 0](/id/on-premises/installation/using-kubernetes/0.-prepare-the-nodes) |

Image tersebut tersedia secara publik di [ghcr.io](https://github.com/ayaka-notes/ayakaleaf-pro/pkgs/container/overleaf-pro/) untuk amd64 dan arm64, sehingga kubelet dapat melakukan pull tanpa kredensial.

<Warning>

Selalu gunakan tag versi, seperti `6.3.2`, bukan `latest`. Upgrade menjalankan migrasi database dan harus mengikuti [Upgrade di Kubernetes](/id/on-premises/maintenance/upgrading-on-kubernetes); tag yang berubah-ubah akan meng-upgrade pod setiap kali dijadwalkan ulang.

</Warning>

### Tanya Jawab

<Accordion title="Node kami tidak dapat menjangkau ghcr.io. Apa yang harus kami lakukan?">

<strong>Jawaban:</strong> Salin image ke registry yang dapat dijangkau node dan gunakan nama tersebut di manifest, misalnya:

```bash
docker pull ghcr.io/ayaka-notes/overleaf-pro:6.3.2
docker tag ghcr.io/ayaka-notes/overleaf-pro:6.3.2 registry.example.com/ayakaleaf/overleaf-pro:6.3.2
docker push registry.example.com/ayakaleaf/overleaf-pro:6.3.2
```

Untuk registry tanpa TLS, containerd memerlukan `/etc/containerd/certs.d/<registry>/hosts.toml` dengan `server = "http://<registry>"` di setiap node, serta `config_path` yang diatur seperti di [langkah 0](/id/on-premises/installation/using-kubernetes/0.-prepare-the-nodes). Docker sendiri hanya melakukan push melalui HTTP biasa ke `localhost`, jadi lakukan push melalui `localhost:<port>` di host registry atau tambahkan ke `insecure-registries`.

</Accordion>
