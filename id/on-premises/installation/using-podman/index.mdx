RHEL dan rebuild-nya (Rocky Linux, AlmaLinux) menyertakan Podman, bukan Docker, dan beberapa organisasi tidak mengizinkan Docker di server mereka. Toolkit dapat menjalankan Ayakaleaf Pro di **Podman tanpa root (rootless)** sebagai gantinya: container berjalan di bawah pengguna biasa, kompilasi tetap berjalan di container TeX Live yang di-sandbox, dan SELinux tetap dalam mode enforcing. Skrip `bin/podman-setup` memeriksa host dan memperbaiki apa yang bisa diperbaikinya.

Di akhir bagian ini Anda memiliki instance yang sama seperti dengan [Menggunakan Docker Compose](/id/on-premises/installation/using-docker-compose): Ayakaleaf Pro dengan kompilasi yang di-sandbox, MongoDB, dan Redis, dikelola dengan `bin/up`, `bin/doctor`, dan `bin/upgrade` seperti biasa.

<Info>

Dukungan Podman bersifat eksperimental. Dukungan ini berasal dari Overleaf Toolkit resmi, yang hanya mengujinya di RHEL 9 dan yang lebih baru dengan Podman tanpa root, kompilasi yang di-sandbox, dan SELinux dalam mode enforcing. Kami menguji halaman-halaman ini di Rocky Linux 9.9 (Podman 5.8, SELinux enforcing) dengan Ayakaleaf Pro 6.3.4. Docker tetap menjadi runtime container yang direkomendasikan.

</Info>

### Yang Anda butuhkan {#what-you-need}

* **RHEL, Rocky Linux, AlmaLinux, atau CentOS Stream 9 atau yang lebih baru**, dengan SELinux dalam mode enforcing. `bin/podman-setup` berhenti di distribusi lain. Di Ubuntu atau Debian, gunakan [Menggunakan Docker Compose](/id/on-premises/installation/using-docker-compose/linux).
* **Pengguna non-root dengan `sudo`** yang akan memiliki container. Jalankan setiap perintah di bagian ini sebagai pengguna tersebut; `bin/podman-setup` menolak berjalan sebagai `root`.
* **Host yang bersih**: tanpa Docker Engine dan tanpa instalasi Toolkit yang sudah ada. Memindahkan instance berbasis Docker yang sudah ada ke Podman tidak dibahas.

### Perbedaannya dengan Docker {#how-it-differs-from-docker}

|                                  | Docker                               | Podman tanpa root                                                                        |
| -------------------------------- | ------------------------------------ | ---------------------------------------------------------------------------------------- |
| Siapa yang menjalankan container | Daemon Docker, sebagai `root`        | Pengguna Anda                                                                            |
| Socket untuk memulai kompilasi   | `/var/run/docker.sock`               | `/run/user/<uid>/podman/podman.sock`                                                     |
| Port                             | Apa saja, misalnya `80` dan `443`    | `1024` ke atas, misalnya `8080`                                                          |
| Firewall host (`firewalld`)      | Dilewati oleh port yang dipublikasikan | Berlaku: buka port dengan `firewall-cmd`                                               |
| Mulai setelah reboot             | Daemon Docker memulainya kembali     | Layanan pengguna `podman-restart`                                                        |
| SELinux                          | Tidak dikonfigurasi oleh Toolkit     | Modul kebijakan `podman_socket_clsi` dan `SELINUX_MODE=managed` di `config/overleaf.rc`   |
| Profil seccomp untuk kompilasi   | Tertanam di image                    | Diekstrak ke `config/seccomp/<version>/` dan diatur sebagai `SECCOMP_PROFILE` oleh Toolkit |

### Batasan yang diketahui {#known-limitations}

* <strong>Integrasi Git.</strong> Di Ayakaleaf Pro 6.3.4, `git clone` gagal dengan `502` di Podman: NGINX di dalam image mencari container `git-bridge` dengan server DNS Docker (`127.0.0.11`), yang tidak dimiliki Podman. Perbaikannya ([1b911d1092](https://github.com/ayaka-notes/ayakaleaf-pro/commit/1b911d1092c80f7b0ff77c5e3805b40503d49964)) hadir di rilis berikutnya; sampai saat itu, biarkan `GIT_BRIDGE_ENABLED=false`.
* <strong>Alamat IP klien.</strong> Podman tanpa root meneruskan port yang dipublikasikan dari dalam jaringan container, sehingga Ayakaleaf Pro melihat setiap pengunjung dengan alamat internal seperti `10.89.0.15`. [Log audit](/id/on-premises/user-guide/administrators/user-management#audit-logs) pengguna di panel admin menampilkan alamat ini, bukan alamat IP mereka.
