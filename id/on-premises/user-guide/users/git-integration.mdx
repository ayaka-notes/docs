Kerjakan proyek di komputer Anda sendiri dengan Git. Perubahan hanya berpindah saat Anda menjalankan `git pull` atau `git push`.

<Info>

Administrator harus mengaktifkan [integrasi Git](/id/on-premises/configuration/overleaf-toolkit/integrations/git-integration) terlebih dahulu.

</Info>

## Membuat token {#create-a-token}

Git masuk dengan token autentikasi Git, bukan dengan kata sandi akun Anda.

<Steps>
<Step title="Buka pengaturan akun Anda">
Klik **Account**, lalu **Account settings**. Di bawah **Git integration**, klik **Generate token**. Setelah Anda memiliki token, tombol ini bernama **Add another token**.

<Frame caption="Integrasi Git di pengaturan akun">
  <img src="/images/on-premises/git-integration-settings.png" alt="Bagian Git integration di pengaturan akun dengan tombol Generate token" />
</Frame>
</Step>

<Step title="Salin token">
Klik **Copy** dan simpan token di tempat yang aman. Anda hanya melihatnya sekali. Lalu klik **Close**.

<Frame caption="Token baru Anda">
  <img src="/images/on-premises/git-integration-token.png" alt="Dialog token autentikasi Git dengan tombol Copy" />
</Frame>
</Step>

<Step title="Periksa token">
Daftar sekarang menampilkan awal token, kapan token dibuat, dan kapan terakhir digunakan. Token kedaluwarsa setelah satu tahun. Anda dapat memiliki hingga 10 token.

<Frame caption="Token Anda">
  <img src="/images/on-premises/git-integration-tokens.png" alt="Daftar token dengan satu token" />
</Frame>
</Step>
</Steps>

## Mengkloning proyek {#clone-a-project}

<Steps>
<Step title="Buka integrasi Git di editor">
Buka proyek. Di bilah kiri, klik **Integrations**, lalu **Git integration**.

<Frame caption="Panel Integrations">
  <img src="/images/on-premises/git-integration-panel.png" alt="Panel Integrations dengan kartu Git integration" />
</Frame>
</Step>

<Step title="Salin perintah">
Dialog **Clone with Git** menampilkan perintah, dengan alamat situs Anda dan ID proyek. Klik **Copy**. Jika Anda belum memiliki token, **Go to settings** membuka pengaturan akun Anda di tab baru.

<Frame caption="Perintah kloning">
  <img src="/images/on-premises/git-integration-clone.png" alt="Dialog Clone with Git dengan perintah git clone" />
</Frame>
</Step>

<Step title="Jalankan perintah">
Tempelkan perintah di terminal. Saat Git meminta kata sandi, tempelkan token Anda.

```text
$ git clone https://git@<your-site>/git/<project-id>
Cloning into '<project-id>'...
Password for 'https://git@<your-site>': <your-token>
```

Folder yang dinamai sesuai ID proyek kini berisi file proyek, di branch `main`. Untuk memilih nama folder, tambahkan nama itu di akhir perintah.
</Step>
</Steps>

Git meminta token setiap kali menghubungi situs. Agar token diingat, aktifkan credential helper: Git meminta sekali lagi, lalu menyimpan token. Helper `store` menyimpannya tanpa enkripsi di `~/.git-credentials`.

```bash
git config --global credential.helper store
```

## Menarik perubahan dari editor {#pull-changes-from-the-editor}

Di dalam folder, jalankan:

```bash
git pull
```

Git menampilkan daftar file yang berubah. Perubahan yang dibuat di editor masuk sebagai commit bernama `Update on Overleaf.`.

```text
Updating db007e3..c3e6332
Fast-forward
 main.tex | 2 +-
 1 file changed, 1 insertion(+), 1 deletion(-)
```

## Mengirim perubahan Anda {#push-your-changes}

Commit perubahan Anda, lalu push:

```bash
git add main.tex
git commit -m "Add a line from Git"
git push
```

Baris terakhir output menampilkan branch yang bergerak:

```text
   53aca61..db007e3  main -> main
```

Perubahan muncul di editor, dan editor yang sedang terbuka memperbarui dirinya sendiri. File, folder, dan penggantian nama baru muncul di pohon file. Di **History**, perubahan Anda ditandai <strong>You (via Git)</strong>. Pesan commit Anda tidak ditampilkan di sana.

### Jika Git menolak push Anda {#if-git-refuses-your-push}

Jika proyek berubah sementara itu, Git menolak push:

```text
 ! [rejected]        main -> main (fetch first)
```

Ambil perubahan tersebut terlebih dahulu, lalu push lagi:

```bash
git pull --no-rebase --no-edit
git push
```

`git pull` biasa dapat berhenti dengan `fatal: Need to specify how to reconcile divergent branches.` Opsi `--no-rebase` di atas mengatasinya: opsi ini menggabungkan kedua sisi.

Jika baris yang sama berubah di kedua sisi, pull berhenti dengan `CONFLICT (content): Merge conflict in main.tex`. Perbaiki file, lalu:

```bash
git add main.tex
git commit -m "Merge the changes from the editor"
git push
```

Ada dua hal yang tidak diterima situs:

* Branch lain: `! [remote rejected] feature -> feature (wrong branch)`. Hanya `main` yang ada, jadi push pekerjaan Anda ke sana.
* Force push: `! [remote rejected] main -> main (forced push prohibited)`. Sebagai gantinya, letakkan perubahan Anda di atas `main` saat ini.

### Jika Git menampilkan Authentication failed {#if-git-says-authentication-failed}

```text
remote: Enter your Git authentication token when prompted for a password.
fatal: Authentication failed for 'https://<your-site>/git/<project-id>/'
```

Token salah atau sudah dihapus, atau Anda memasukkan kata sandi akun. Buat token baru jika Anda tidak lagi memilikinya, karena token yang ada tidak dapat dilihat lagi.

## Menghapus token {#delete-a-token}

Di **Account settings**, di bawah **Git integration**, klik ikon hapus di samping token, lalu **Delete** di dialog. Sejak saat itu, Git menjawab `Authentication failed` untuk token tersebut.
