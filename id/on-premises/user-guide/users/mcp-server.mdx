Setiap proyek memiliki server MCP sendiri, sehingga klien AI di komputer Anda dapat membaca dan mengedit proyek, mengompilasinya, dan membalas komentarnya. Klien masuk dengan token autentikasi Git.

<Info>

Jika Anda tidak melihat kartu **MCP server**, arahkan administrator Anda ke [Server MCP](/id/on-premises/configuration/overleaf-toolkit/integrations/mcp-server).

</Info>

## Baru di v6.3.3 {#new-in-v6-3-3}

Mulai v6.3.3, klien juga dapat bekerja dengan riwayat proyek: menampilkan daftar perubahan, membandingkan dua versi, membaca file seperti sebelumnya, menyimpan dan menghapus versi, serta memulihkan file atau seluruh proyek. Klien dapat menampilkan daftar perubahan terlacak dan menerima atau menolaknya, serta menjadikan editannya sendiri sebagai perubahan terlacak bila Anda memintanya. Klien dapat mengomentari sepotong teks dan mengedit atau menghapus pesan komentar, membaca dan mengirim pesan di obrolan proyek, memindahkan dan mengganti nama file dan folder, membuat folder, serta mengubah bahasa pemeriksa ejaan. Siapa boleh melakukan apa mengikuti peran Anda di proyek, sama seperti di editor, karena klien bekerja dengan token Anda: lihat [Siapa boleh melakukan apa](#who-may-do-what).

Server MCP diperkenalkan di v6.3.1. v6.3.1 dan v6.3.2 memiliki 17 alat yang sama; v6.3.3 memiliki 33.

| Alat | v6.3.1 dan v6.3.2 | v6.3.3 |
| ----- | ----------------- | ------ |
| `get_clone_info`, `get_settings`, `list_files`, `delete_file`, `compile`, `get_compile_log`, `get_output_file_link`, `word_count`, `reply_to_comment`, `resolve_comment`, `reopen_comment` | Ya | Ya, tidak berubah |
| `read_file` | Isi terbaru | Juga file seperti pada suatu `version` |
| `edit_file`, `write_file` | Mengikuti pengaturan lacak perubahan proyek | Juga `trackChanges`, untuk menjadikan editan sebagai perubahan terlacak |
| `update_settings` | Compiler, image TeX Live, dan dokumen utama | Juga bahasa pemeriksa ejaan |
| `list_versions` | Versi, komentar, dan tanggal | Juga `id` yang diterima `delete_version`, dan siapa yang menyimpannya |
| `list_comments` | Pesan tanpa id | Juga `id` setiap pesan, yang diterima `edit_comment_message` dan `delete_comment_message` |
| `list_changes`, `diff`, `create_version`, `delete_version`, `restore_file`, `restore_project`, `list_tracked_changes`, `accept_tracked_changes`, `reject_tracked_changes`, `add_comment`, `edit_comment_message`, `delete_comment_message`, `list_chat_messages`, `send_chat_message`, `move_file`, `create_folder` | Tidak | Ya |

## Menghubungkan klien {#connect-a-client}

<Steps>
<Step title="Buka dialog">
Buka proyek. Di bilah kiri, klik **Integrations**, lalu **MCP server**.

<Frame caption="Panel Integrations">
  <img src="/images/on-premises/mcp-server-integrations.png" alt="Panel Integrations dengan kartu MCP server" />
</Frame>

Dialog menampilkan alamat server proyek ini dan tab untuk setiap klien: **Claude Code**, **Codex**, **Cursor**, **VS Code**, dan **Gemini CLI**.

<Frame caption="Dialog MCP server">
  <img src="/images/on-premises/mcp-server-dialog.png" alt="Dialog MCP server dengan alamat, tab untuk setiap klien, dan perintah untuk Claude Code" />
</Frame>
</Step>

<Step title="Buat token">
Klik **Go to settings**. Pengaturan akun Anda terbuka di tab baru. Di bawah **Git integration**, klik **Generate token**, atau **Add another token** jika Anda sudah memilikinya. Klik **Copy** dan simpan token di tempat yang aman, karena Anda hanya melihatnya sekali. Lalu klik **Close**.

<Frame caption="Token baru Anda">
  <img src="/images/on-premises/mcp-server-token.png" alt="Dialog Git authentication token dengan tombol Copy" />
</Frame>

Token yang sudah Anda gunakan untuk [integrasi Git](/on-premises/user-guide/users/git-integration) juga dapat dipakai, begitu pula satu token untuk semua proyek Anda.
</Step>

<Step title="Tambahkan server ke klien Anda">
Kembali ke dialog, klik tab klien Anda lalu klik **Copy** di samping konfigurasi.

| Tab | Letaknya | Token |
| --- | ------------- | --------- |
| **Claude Code** | Jalankan perintah di terminal | Ganti `<token>` di perintah |
| **Codex** | `~/.codex/config.toml` | Masukkan ke variabel lingkungan `OVERLEAF_TOKEN` |
| **Cursor** | `~/.cursor/mcp.json` | Masukkan ke variabel lingkungan `OVERLEAF_TOKEN` |
| **VS Code** | `.vscode/mcp.json` | File berisi prompt kata sandi bernama `overleaf-token` sebagai ganti token |
| **Gemini CLI** | Jalankan perintah di terminal | Ganti `<token>` di perintah |

Alamat tersebut milik satu proyek. Untuk menghubungkan proyek lain, tambahkan dengan nama lain, karena `overleaf` sudah dipakai. Misalnya di Claude Code, ubah `overleaf` di perintah menjadi `overleaf-lab`.
</Step>
</Steps>

## Memeriksa koneksi {#check-the-connection}

### Dengan Claude Code {#with-claude-code}

```bash
claude mcp list
```

Server tercantum sebagai terhubung:

```text
overleaf: https://<your-site>/project/<project-id>/mcp (HTTP) - ✔ Connected
```

### Dengan curl {#with-curl}

Cara ini berfungsi apa pun klien Anda. Ganti alamat dan token, lalu kirim permintaan `initialize` dari protokol MCP:

```bash
curl -X POST https://<your-site>/project/<project-id>/mcp \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -H "Accept: application/json, text/event-stream" \
  -d '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2025-06-18","capabilities":{},"clientInfo":{"name":"curl","version":"1.0"}}}'
```

Respons menyebutkan nama server, diikuti instruksinya untuk klien:

```json
{"result":{"protocolVersion":"2025-06-18","capabilities":{"tools":{"listChanged":true}},"serverInfo":{"name":"overleaf","version":"1.0.0"},"instructions":"This server works on one Overleaf project. ..."},"jsonrpc":"2.0","id":1}
```

Untuk melihat alat-alatnya, kirim `tools/list` dengan perintah yang sama. Respons mencantumkan 33 alat, atau 31 jika situs Anda menonaktifkan obrolan proyek. Sebelum v6.3.3 tercantum 17.

```bash
  -d '{"jsonrpc":"2.0","id":2,"method":"tools/list","params":{}}'
```

Untuk memanggil salah satunya, kirim `tools/call`:

```bash
  -d '{"jsonrpc":"2.0","id":3,"method":"tools/call","params":{"name":"list_files","arguments":{}}}'
```

```json
{"result":{"content":[{"type":"text","text":"[\n  {\n    \"path\": \"main.tex\",\n    \"type\": \"doc\"\n  }\n]"}]},"jsonrpc":"2.0","id":3}
```

### Jika tidak terhubung {#if-it-does-not-connect}

| Yang Anda lihat | Artinya |
| ------------ | ------------- |
| Status `401`, atau di Claude Code `✘ Failed to connect` dengan `HTTP 401` | Token tidak ada, salah, atau dihapus |
| Status `404` | Tidak ada proyek dengan ID ini |
| Status `405` | Permintaan bukan `POST` |
| Status `406` dengan `Not Acceptable` | Header `Accept` tidak ada: klien harus menerima `application/json` dan `text/event-stream` |

## Yang Anda lihat saat klien bekerja {#what-you-see-when-a-client-works}

Editan muncul di editor yang terbuka saat klien membuatnya, seperti editan kolaborator, tanpa memuat ulang. File dan folder baru, pemindahan, dan penggantian nama muncul di pohon file.

<Frame caption="Baris yang ditambahkan oleh edit_file">
  <img src="/images/on-premises/mcp-server-live-edit.png" alt="Editor menampilkan baris yang ditambahkan edit_file, tanpa dialog dan tanpa memuat ulang" />
</Frame>

`edit_file` hanya mengubah teks yang muncul tepat satu kali. Jika tidak, klien menerima error, seperti `oldString not found in main.tex, read_file again` atau `oldString appears 2 times in main.tex, add context`, dan tidak ada yang berubah.

Mulai v6.3.3, `move_file` memindahkan atau mengganti nama file atau folder, membuat folder pada path baru bila perlu, dan `create_folder` membuat folder. Jika file tidak ditemukan atau path baru sudah ada, klien menerima error dan tidak ada yang berubah. `update_settings` juga dapat mengubah bahasa pemeriksa ejaan, misalnya ke `de`, atau mematikan pemeriksa ejaan.

Balasan komentar muncul di panel tinjauan atas nama Anda, karena token tersebut milik Anda. Komentar yang diselesaikan melalui server hilang dari panel, dan membukanya kembali akan memunculkannya lagi.

<Frame caption="Balasan yang dikirim oleh reply_to_comment">
  <img src="/images/on-premises/mcp-server-comment.png" alt="Komentar di panel tinjauan dengan balasan yang dikirim oleh reply_to_comment" />
</Frame>

Mulai v6.3.3, `add_comment` mengomentari sepotong teks. Teks harus muncul tepat satu kali di file; jika muncul lebih dari sekali, klien juga memberikan potongan yang lebih panjang di sekitarnya yang hanya muncul sekali, dan hanya teks itu yang dikomentari. Komentar muncul di panel tinjauan atas nama Anda dan tetap menempel pada teksnya saat file berubah. `edit_comment_message` mengubah salah satu pesan Anda sendiri. `delete_comment_message` menghapus pesan, dan menghapus pesan pertama akan menghapus seluruh komentar, sama seperti di panel tinjauan.

`compile` mengompilasi proyek dan mengembalikan daftar file keluaran. `get_output_file_link` kemudian memberikan tautan untuk mengunduh PDF atau file keluaran lain. Tautan tidak memerlukan token dan berhenti berfungsi setelah 5 menit.

Untuk daftar lengkap alat, lihat [Tools](/on-premises/configuration/overleaf-toolkit/integrations/mcp-server#tools).

## Perubahan terlacak {#tracked-changes}

Mulai v6.3.3, Anda dapat meminta klien menjadikan editannya sebagai perubahan terlacak, misalnya *Rewrite the abstract as a tracked change*. `edit_file` dan `write_file` kemudian menjadikan perubahan pada file yang ada sebagai perubahan terlacak atas nama Anda, bahkan saat lacak perubahan dimatikan di proyek, dan Anda menerima atau menolaknya di panel tinjauan. File baru tidak pernah menjadi perubahan terlacak. Jika Anda tidak memintanya, editan mengikuti pengaturan lacak perubahan proyek, seperti editan Anda di editor: editan dilacak saat lacak perubahan aktif untuk Anda atau untuk semua orang.

Jika akun pemilik proyek tidak memiliki lacak perubahan, klien menerima `Track changes is off for this project` dan tidak ada yang berubah.

Untuk meninjau setiap editan klien, aktifkan lacak perubahan untuk diri Anda sendiri. Untuk membedakan editannya dari editan Anda di panel tinjauan, berikan klien token akun lain yang berbagi proyek dengan Anda.

`list_tracked_changes` menampilkan daftar perubahan terlacak beserta file, teks yang disisipkan atau dihapus, penulis, dan waktunya. `accept_tracked_changes` dan `reject_tracked_changes` menerima id perubahan dan bekerja seperti panel tinjauan: perubahan yang diterima tetap ada di teks, sisipan yang ditolak dihapus, dan penghapusan yang ditolak kembali. Editor yang terbuka menampilkan hasilnya tanpa memuat ulang. Alat-alat tersebut meminta klien untuk hanya menerima atau menolak perubahan yang Anda minta.

## Riwayat {#history}

Mulai v6.3.3, klien melihat riwayat proyek seperti yang ditampilkan panel riwayat.

| Alat | Fungsinya |
| ---- | ------------ |
| `list_changes` | Menampilkan daftar perubahan, terbaru lebih dulu: siapa mengubah file apa dan kapan, dengan versi sebelum dan sesudah setiap perubahan. Perubahan lama datang dalam kelompok berikutnya. |
| `diff` | Membandingkan dua versi: satu file sebagai unified diff, seperti `git diff`, atau file yang ditambahkan, dihapus, diedit, atau diganti namanya |
| `read_file` dengan `version` | Membaca file seperti pada suatu versi |
| `list_versions` | Menampilkan daftar versi tersimpan, beserta komentarnya dan siapa yang menyimpannya |
| `create_version` | Menyimpan versi terbaru, atau versi sebelumnya, dengan komentar, seperti **Label this version** |
| `delete_version` | Menghapus versi tersimpan; perubahannya tetap ada |
| `restore_file` | Memulihkan file seperti pada suatu versi, seperti **Restore this version** |
| `restore_project` | Memulihkan seluruh proyek seperti pada suatu versi, seperti **Restore project to this version** |

Pemulihan itu sendiri adalah perubahan baru, sehingga Anda dapat membatalkannya dengan cara yang sama. Alat-alat tersebut meminta klien untuk hanya memulihkan saat Anda memintanya.

Jika pemilik proyek tidak memiliki riwayat proyek lengkap, klien hanya melihat perubahan dalam 24 jam terakhir, atau perubahan terbaru jika semuanya lebih lama, sama seperti di panel riwayat. Klien tidak dapat membandingkan, membaca, atau memulihkan versi yang lebih lama.

## Obrolan proyek {#project-chat}

Mulai v6.3.3, `list_chat_messages` membaca obrolan proyek, terbaru lebih dulu, 50 pesan sekaligus. `send_chat_message` mengirim pesan atas nama Anda, dan pesan itu langsung muncul di obrolan yang terbuka. Jika situs Anda menonaktifkan obrolan proyek, klien tidak memiliki kedua alat tersebut.

## Siapa boleh melakukan apa {#who-may-do-what}

Klien boleh melakukan apa yang diizinkan oleh peran Anda di proyek.

| Yang dilakukan klien | Pemilik | Editor | Peninjau | Pembaca (kolaborator yang ditunjuk) | Pembaca (berbagi tautan) |
| -------------------- | ----: | -----: | -------: | --------------------------: | --------------------: |
| Membaca file dan pengaturan, mengompilasi, membaca log, mengunduh PDF | Ya | Ya | Ya | Ya | Ya |
| Menulis, mengedit, memindahkan, dan menghapus file, membuat folder, mengubah pengaturan | Ya | Ya | Tidak | Tidak | Tidak |
| Melihat riwayat, komentar, dan perubahan terlacak | Ya | Ya | Ya | Ya | Tidak |
| Membaca dan mengirim pesan obrolan | Ya | Ya | Ya | Ya | Tidak |
| Menambahkan komentar dan membalasnya | Ya | Ya | Ya | Tidak | Tidak |
| Menyelesaikan, membuka kembali, atau menghapus komentar | Ya | Ya | Yang mereka mulai | Tidak | Tidak |
| Mengedit pesan komentar | Milik sendiri | Milik sendiri | Milik sendiri | Tidak | Tidak |
| Menghapus pesan komentar | Ya | Ya | Milik sendiri | Tidak | Tidak |
| Menerima atau menolak perubahan terlacak | Ya | Ya | Tidak | Tidak | Tidak |
| Menyimpan versi | Ya | Ya | Ya | Tidak | Tidak |
| Menghapus versi tersimpan | Ya | Yang mereka simpan | Yang mereka simpan | Tidak | Tidak |
| Memulihkan file atau proyek | Ya | Ya | Tidak | Tidak | Tidak |

Editor yang bergabung melalui tautan dihitung sebagai editor. Peninjau tidak dapat mengedit file melalui MCP, bahkan sebagai perubahan terlacak.

## Memutus klien {#disconnect-a-client}

Hapus token: lihat [Menghapus token](/on-premises/user-guide/users/git-integration#delete-a-token). Sejak saat itu, server menjawab `401` untuk token tersebut. Jika Anda juga menggunakannya untuk Git, Git juga berhenti menerimanya.
