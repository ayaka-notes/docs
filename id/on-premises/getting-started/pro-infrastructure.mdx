#### Layanan

Infrastruktur overleaf Pro terdiri dari empat layanan utama: `sharelatex`, `git-bridge` (opsional), `mongo`, dan `redis`. Layanan `sharelatex`, yang menjalankan aplikasi utama Server Pro, bergantung pada layanan `mongo` dan `redis` untuk database serta fungsi caching/real-time, dan pada `git-bridge` untuk menangani [integrasi Git](/id/on-premises/configuration/overleaf-toolkit/git-integration) (opsional). Satu-satunya port yang dipublikasikan pada mesin host adalah port 80, yang digunakan oleh kontainer `sharelatex`.

Server Pro juga secara opsional mendukung [penyimpanan yang kompatibel dengan S3](/id/on-premises/configuration/overleaf-toolkit/s3) untuk file proyek dan riwayat proyek lengkap, serta dapat mem-proxy akses ke [situs dokumentasi Overleafarrow-up-right](https://www.overleaf.com/learn) utama. Untuk informasi lebih lanjut, lihat panduan kami tentang halaman [Menambahkan bantuan pengguna LaTeX](/id/on-premises/configuration/overleaf-toolkit/adding-latex-user-help).

<Info>

Jika diperlukan, MongoDB dan Redis dapat dieksternalisasi menggunakan variabel lingkungan yang mengarah ke layanan eksternal. Untuk informasi lebih lanjut, lihat [Mengonfigurasi Overleaf](/id/on-premises/configuration) jika Anda menggunakan Docker Compose dan [Pengaturan Toolkit](/id/on-premises/configuration/overleaf-toolkit/toolkit-settings) jika menggunakan Overleaf Toolkit.

</Info>

#### Kompilasi

Untuk [Sandboxed Compiles](/id/on-premises/configuration/overleaf-toolkit/sandboxed-compiles), kontainer `sharelatex` akan mengorkestrasi pembuatan kontainer baru untuk menangani kompilasi proyek; hal ini dilakukan melalui socket Docker pada mesin host. Anda dapat membaca lebih lanjut tentang editor dan proses kompilasi/caching end-to-end [di sini](/id/on-premises/getting-started/microservices#editor-and-compile-process).

#### Jaringan

Komunikasi antar kontainer difasilitasi melalui resolusi DNS internal Docker melalui jaringan bridge khusus, dan tidak ada firewall yang diaktifkan. Secara default, layanan di atas menggunakan port standarnya masing-masing, tetapi dapat dikonfigurasi melalui variabel lingkungan. Kontainer `sharelatex` menggunakan port 80 untuk akses web eksternal (dilayani oleh Nginx), kontainer `mongo` menggunakan port 27017, dan `redis` menggunakan port 6379.

Bagi pelanggan yang menggunakan solusi terkelola kami [Overleaf Toolkitarrow-up-right](https://github.com/overleaf/toolkit), Anda secara opsional dapat [mengaktifkan proxy TLS](/id/on-premises/configuration/overleaf-toolkit/tls-proxy) untuk mengakhiri koneksi HTTPS menggunakan Nginx melalui variabel lingkungan. Sebagai alternatif, Anda dapat menggunakan proxy TLS yang sudah Anda miliki.

<Info>

Anda dapat melihat diagram yang menjelaskan alur permintaan [di sini](/id/on-premises/configuration/overleaf-toolkit/tls-proxy).

</Info>

#### Ringkasan

* Di luar jaringan Docker, hanya port 80 yang dapat diakses dan terikat ke Nginx. <strong>Catatan:</strong> Kontainer `sharelatex` menjalankan banyak [layananarrow-up-right](https://github.com/overleaf/overleaf/tree/main/services) yang berkomunikasi satu sama lain melalui HTTP. Namun, port-port ini **tidak** dapat diakses dari luar jaringan Docker.
* Di dalam jaringan Docker, layanan Overleaf, MongoDB, Redis, dan Git Bridge dapat saling berkomunikasi dengan bebas.
* Di dalam kontainer [Sandboxed Compiles](/id/on-premises/configuration/overleaf-toolkit/sandboxed-compiles), tidak ada jaringan yang tersedia.
