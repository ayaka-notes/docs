### Melihat log audit proyek

Administrator dapat melihat **Audit Log** untuk setiap proyek. Log audit ini menampilkan peristiwa seperti kapan berbagi tautan diubah antara privat/berbasis token, kapan undangan dikirim/diterima, dan kapan seorang pengguna bergabung ke proyek menggunakan token. Administrator dapat melihat log ini per proyek melalui **Your Instance** -> **Admin** -> **Manage Users**, lalu:

* Cari pengguna
* Klik tab **Projects**
* Pilih sebuah proyek
* Klik ikon (i)
* Klik tab **Audit Log**

Jika sebuah proyek dibagikan dengan kolaborator tertentu (menggunakan alamat email mereka), setelah penerima bergabung, mereka akan tercantum di modal Share beserta izinnya dan terlihat oleh pemilik proyek. Informasi ini juga akan ditampilkan kepada Administrator saat melihat tab Project Info untuk proyek tersebut melalui panel admin.

### Memulihkan dokumen yang dihapus

1. Masuk menggunakan kredensial administrator Anda
2. Klik **Admin** dan pilih **Manage Users**
3. Menggunakan kolom pencarian, masukkan email pengguna yang dokumennya ingin Anda pulihkan
4. Klik alamat email mereka di daftar hasil untuk membuka halaman info pengguna
5. Klik tab **Projects** dan gunakan kolom pencarian untuk mencari proyek
6. Klik ikon informasi di samping nama proyek untuk membuka **Project Info**
7. Klik tab **Deleted Docs**
8. Klik tombol **Undelete** di samping dokumen yang dihapus untuk memulihkannya kembali ke proyek pengguna.

File yang dipulihkan akan menggunakan format berikut: `FILENAME-TIMESTAMP.EXTENSION`. Misalnya, versi `main.tex` yang dipulihkan akan dikembalikan ke root proyek dengan nama file `main-2024-02-23-130441542.tex`.

### Mentransfer kepemilikan proyek

Panel admin di Server Pro memiliki halaman khusus untuk setiap proyek. Anda dapat mencapainya dengan mencari pengguna di "/admin/user", lalu membuka tab **Projects** mereka, menemukan proyek di daftar, dan mengklik ikon informasi; atau dengan langsung membuka halaman tersebut menggunakan project-id yang diketahui [<strong>https://your-instance-url/admin/project/</strong>](https://your-instance-url/admin/project/). Di halaman info proyek, Anda dapat menemukan tombol **Transfer Ownership**, yang membuka modal tempat Anda dapat menentukan pengguna mana pun sebagai pemilik baru. Pemilik baru tidak perlu merupakan kolaborator yang sudah ada di proyek tersebut.

<Info>

Perhatikan bahwa pemilik sebelumnya akan ditambahkan sebagai kolaborator dengan akses baca-tulis ke proyek sebagai bagian dari proses transfer kepemilikan.

</Info>

### Memperbarui batas waktu kompilasi proyek

Batas waktu kompilasi default untuk proyek saat ini diatur ke 180 detik. Nilai ini dapat diubah dan memerlukan proses dua langkah.

Pertama, edit file **config/variables.env**, tambahkan variabel lingkungan `COMPILE_TIMEOUT`, dan atur nilainya ke batas waktu yang diinginkan dalam detik. Misalnya, `COMPILE_TIMEOUT=300` untuk 5 menit.

<Danger>

Tidak ada gunanya menaikkan batas waktu melebihi 10 menit. Jika Anda melakukannya, kemungkinan besar Anda akan mencapai batas waktu di komponen lain dari aplikasi.

</Danger>

Setelah perubahan ini dibuat, Anda perlu membuat ulang kontainer **sharelatex** dengan menjalankan perintah `bin/up -d`.

Mengatur variabel lingkungan ini hanya akan memperbarui nilai batas waktu untuk pengguna baru; nilai ini **tidak** akan diterapkan secara retroaktif ke pengguna yang sudah ada karena nilainya diisi saat pengguna pertama kali dibuat.

Untuk menyesuaikan batas waktu bagi pengguna yang sudah ada, Anda perlu mengubah setiap catatan pengguna di database. Kami menyarankan untuk sangat berhati-hati saat melakukan hal ini, dan merekomendasikan untuk membuat cadangan yang konsisten sebelum melakukan perubahan apa pun.

Anda dapat menemukan informasi tentang cara membuat cadangan [di sini](/id/on-premises/maintenance/data-and-backups).

Untuk memperbarui nilai batas waktu kompilasi pada semua pengguna yang sudah ada, Anda perlu menjalankan perintah shell berikut di host Docker:

```bash wrap
echo 'db.users.updateMany({}, {$set: {"features.compileTimeout": <value>}})' | docker exec -i mongo mongosh --quiet localhost/sharelatex
```

Anda perlu mengganti `<value>` pada kueri di atas dengan nilai batas waktu yang diinginkan dalam detik.

Setelah perintah selesai, Anda akan melihat konfirmasi beserta jumlah catatan yang diubah. Anda kemudian dapat mengetik exit lalu menekan tombol enter untuk kembali ke shell host.

### Melacak akses proyek

Anda dapat melihat siapa yang memuat sebuah proyek dan kapan dengan perintah berikut:

```bash wrap
docker exec sharelatex bash -c 'grep "join project request" /var/log/overleaf/web.log'
```

Perintah ini akan menampilkan `timestamp`, `user_id`, dan `project_id`.
