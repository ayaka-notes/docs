<Info>

本文件來自 [Overleaf 部落格](https://www.overleaf.com/blog/tex-live-2026-is-now-available)。Overleaf 於 2026 年 8 月 18 日發布了 TeX Live 2026。我們也已將 [ayaka-notes/texlive-full](https://github.com/ayaka-notes/texlive-full) 更新至 TeX Live 2026。

</Info>

以下說明有哪些變更、切換前需要檢查哪些事項，以及如何修正最常見的新錯誤。此版本最值得注意的更新是，產生無障礙 PDF 的功能已脫離原型階段，可以用於正式生產的工作流程。此更新也讓您可以使用新增及更新的 TeX 相關程式、字型與巨集套件。本篇部落格文章涵蓋了您需要了解的所有關鍵資訊與重要變更。

Overleaf 每年在經過嚴格測試後發布一次官方更新，以確保一切如預期運作。我們這麼做是為了替數百萬 Overleaf 使用者提供一致且穩定的體驗，並確保我們的支援團隊能協助您處理任何問題或疑問。

### 什麼是 TeX Live？

[TeX Live](https://tug.org/texlive/) 是 TeX 排版系統的免費發行版，包含許多 TeX 相關的程式、字型與巨集套件（包括 LaTeX），由一群核心 TeX 使用者與 [TeX User Group](https://tug.org/) 維護。Overleaf 在其編譯伺服器上使用 TeX Live 來驅動預覽並產生您的專案 PDF。

隨著 TeX Live 2026 的推出，使用者可以建立完全無障礙、帶有標記（tagged）的 PDF，包括可被讀取的數學內容。

### 我現有的專案能照常運作嗎？

可以，您現有的專案仍會正常運作，因為它們會繼續使用建立時的 TeX Live 版本。除非必要，我們不建議變更現有專案的 TeX Live 版本；變更可能會導致新的錯誤或警告。

**注意：** Overleaf 範本庫中可能有部分範本在啟用無障礙選項後無法運作或編譯。大多數範本並非由 Overleaf 建立或維護；如有任何問題，請聯絡範本作者。

### 我可以將現有專案切換到 TeX Live 2026 嗎？

可以，您可以輕鬆地將現有專案切換到 TeX Live 2026；轉換過程簡單且輕鬆。在您要變更的專案中，開啟 _Settings_，然後點選側邊欄中的 _Compiler_，您會看到一個用於選擇 TeX Live 版本的下拉選單。這讓您能快速更新專案，以符合出版商、預印本伺服器及其他使用特定 TeX Live 版本編譯投稿之平台的要求。

如果您的專案在 TeX Live 2025（或更早版本）中編譯沒有問題，但現在在 TeX Live 2026 中出現錯誤，這可能是由於核心或某些套件的變更所致。已知某些套件在 TeX Live 2026 下會產生新的錯誤或警告；我們已在下方的獨立章節中整理出最常見的問題及其修正方式。

### TeX Live 2026 的主要變更

#### 帶標記的無障礙 PDF 已脫離原型階段

自 LaTeX Project 的 [2025 年 11 月更新](https://www.latex-project.org/news/latex2e-news/ltnews42.pdf)起，標記功能不再被描述為原型，只要您的文件使用的套件與文件類別已支援標記，即可視為能用於正式生產的工作流程。

啟用帶標記的 PDF 輸出，只需在 `\documentclass` 之前放置一個指令：

```latex
\DocumentMetadata{
 pdfstandard = {UA-2, A-4f},
 tagging = on,
 lang = en
 }
\documentclass{article}
```

使用 `\DocumentMetadata` 也會開啟一些預設值：T1 字型編碼，以及[自 2025 年 6 月起](https://www.latex-project.org/news/latex2e-news/ltnews41.pdf)改為輸出 **PDF 2.0**，而非較舊的 1.7。PDF 2.0 在此很重要，因為它允許 MathML 標記（這正是讓螢幕閱讀器能讀取數學內容，而非一堆未標示符號的關鍵）。

幾點實用說明：

* 在撰寫草稿時，您可以設定 `tagging = draft`，保留無障礙警告但略過寫入結構樹（有助於加快長篇文件的編譯速度）。
* check-tagging-status 鍵會在日誌結尾回報您所使用的套件是否已知與標記相容。您也可以在開始前查閱[即時狀態資料庫](https://latex3.github.io/tagging-project/tagging-status/)。
* 如果您只需要 PDF 管理的部分而不需要標記程式碼，現在有一個獨立的 `pdfmanagement` 套件可供使用。

特別值得一提的一項變更：`\DocumentMetadata` 現在在一份文件中只能呼叫一次。第二次呼叫會導致編譯錯誤，就如同第二次呼叫 `\documentclass` 一樣。

#### 具有語意的無障礙數學

[自 2025 年 11 月起新增](https://www.latex-project.org/news/latex2e-news/ltnews42.pdf)的 `\MathMLintent` 與 `\MathMLarg`，讓作者能告訴輔助技術某段記號的意義，而不僅是它的建構方式。例如，`|y|` 現在可以被朗讀為 _「y 的絕對值」_，而非 _「bar y bar」_。

無障礙數學標記需要使用 LuaLaTeX 編譯（因為它是產生 MathML 的引擎），並搭配 `unicode-math` 或 `lua-unicode-math` 套件。

#### 圖形與圖表現在也承載語意

無障礙性不僅限於文字與數學。`\includegraphics`、`picture` 與 `tikzpicture` 現在都接受無障礙鍵，因此每個圖形都可以被適當地標記：

```latex
\includegraphics[alt={A bar chart of quarterly revenue}]{revenue}
```

圖形可分為四類：真正的說明性圖表、應被輔助工具忽略的裝飾性元素、符號的替代品，或一般文字（適用於 `todonotes` 之類的情況）。TikZ 輸出開箱即支援。

#### 用於建立帶標記無障礙簡報的新文件類別

`beamer` 文件類別在 LaTeX 中非常受歡迎，常用於製作簡報投影片。遺憾的是，它與 LaTeX 標記程式碼不相容。因此，一個全新的文件類別 [`ltx-talk`](https://ctan.org/pkg/ltx-talk) 從頭開始建立。其語法與 `beamer` 大致相似，但並非 `beamer` 的所有功能都已在 `ltx-talk` 中實作。

#### 用於設定章節標題樣式的新範本機制

章節標題指令已在 LaTeX 核心中以新的範本機制重新實作，解決了 `titlesec` 等套件與 LaTeX 標記程式碼不完全相容的問題。以下是一個簡單範例：

```latex
\EditInstance{heading}{section}{
  number-format=\fbox{\LARGE\bfseries\theheading},
  title-decls=\Large\bfseries\sffamily\color{blue},
  before-vspace=20pt,
}
```

詳細資訊請參閱[文件](https://tug.ctan.org/macros/latex-dev/required/latex-lab/latex-lab-sec-template.pdf)。

#### 底層重建的核心

在今年的核心中，移除了一些限制：

* **輸出常式現在可以設定：** 近 40 年來，LaTeX 的頁面組裝機制實際上是寫死的，迫使需要變更它的套件覆寫內部程式碼。現在它改為公開 hooks 與 sockets 來進行變更。套件因此變得更穩定，也較不容易彼此衝突。
* **現代化的標記（mark）機制：** 舊的 `\markboth` / `\leftmark` / `\rightmark` 系統只支援兩個互相交織的標記，現已改建在一個彈性的系統上，支援任意數量的獨立標記，而熟悉的指令仍會完全照舊運作。
* **區塊環境與章節標題現在以範本運作：** 清單、引文、類定理環境，以及現在的標題指令，都共用一致的底層系統。一個實際的好處是：LaTeX 開始原生模擬熱門套件，例如 `enumitem` 與 `amsthm` 的 `\newtheoremstyle`，而 `titlesec` 的模擬也正在進行中。現在不再那麼需要只為了重新設定清單或定理方塊的樣式而安裝套件。
* **類定理環境的交叉參照更完善：** 新的 `\newcounteralias` 指令讓與定理共用計數器的引理，在使用 `cleveref`、`zref-clever` 或 `hyperref` 參照時，能正確顯示為 _「lemma 1」_，而非 _「theorem 1」_。

如果您維護的是套件而不只是文件，有兩項變更值得您留意：核心現在正式要求 **日期為 2023-11-27 或更新的 `expl3`**，並且已從 `\textsuperscript`、`\parbox`/`minipage` 等結構及表格結構周圍移除 _「假數學」_（純粹為了定位方塊而使用數學模式）。這改善了標記與由右至左文字的支援，但如果您將 `\showoutput` 的結果與舊版 TeX Live 比較，就會注意到差異。

#### 新的觸及範圍：更多語言

* **婆羅米系文字的索引**（包括孟加拉文、古吉拉特文、卡納達文、馬拉雅拉姆文、僧伽羅文、泰米爾文與泰盧固文）已以實驗性質加入 `upmendex`。
* 新的 **BCP 47 語言中繼資料**鍵（`language`、`other-languages`）讓您能精確宣告文件的語言，甚至細分到區域變體，這些資訊也會寫入 PDF 本身的語言中繼資料。

#### 其他需要注意的事項

* `enumerate`、`theorem` 與 `verbatim` 套件現在被視為舊版套件；對於新文件，建議分別改用 `enumitem`、`amsthm` 與 `fancyvrb`。
* 如果您的列印工作流程或平台需要較舊的 PDF 版本，您仍可自行設定 PDF 版本（例如 `\DocumentMetadata{pdfversion=1.7}`），TeX Live 2026 文件也說明了如何以較早的預設值為目標來編譯文件。
* 您可以在 TeX Users Group（TUG）網站上找到 TeX Live 2026 的[官方發行說明](https://tug.org/texlive/doc/texlive-en/texlive-en.html#news)，以及[所有 TeX Live 版本的發行說明](https://www.tug.org/texlive/doc/texlive-en/texlive-en.html#x1-710009)。

### 受 TeX Live 2026 影響的常見套件

在以下各節中，我們列出一些變更，這些變更會導致在 TeX Live 2025 中成功編譯的專案，在 TeX Live 2026 中出現編譯錯誤。

#### 不再支援的表格相關套件

由於 LaTeX 核心中表格結構的新變更，`tabu` 與 `tabls` 套件在 TL2026 中已不再受支援 — 它們現在會導致編譯錯誤。`arydshln` 套件也可能與其他套件不相容，例如 `tabularx` 與 `tabular*` 環境。同樣地，重新定義 `\@array` 與 `\tabular` 的套件或範本，也會在類表格結構周圍導致編譯錯誤。

#### `babel` 已過時的語言選項

`frenchb` 與 `francais` 語言選項現已過時，應改用 `french`。

#### `varioref` 錯誤

由於 [`varioref` 套件中的一個錯誤](https://github.com/latex3/latex2e/issues/2112#issuecomment-4881772493)，在 KOMA-Script 文件類別中載入它會導致 TeX capacity exceeded 錯誤，且不會產生 PDF。

```text
\documentclass{scrartcl}
\usepackage{varioref}
\begin{document}
Hello World!
\end{document}
```

暫時的解決方法是在導言區中加入以下內容：

```text
\def\extrasenglish{}
```

#### KOMA-script 文件類別與 `capt-of`

KOMA-script 文件類別（`scrbook`、`scrartcl`、`scrreport`、`scrletter`）現在已定義 `\captionof`，因此不應再載入 `capt-of` 套件。（另一方面，`caption` 套件仍可安全地與這些文件類別一起載入。）

#### `thmtools`：`sibling`/`numberlike`/`sharenumber` 錯誤

使用 `thmtools` 的 `sibling`（或 `numberlike`、`sharenumber`）選項宣告新的類定理環境時，會出現[計數器已被定義的錯誤](https://github.com/muzimuzhi/thmtools/issues/75)，例如 `Command \c@proposal already defined`。

```text
\documentclass{article}
\usepackage{thmtools}
\declaretheorem{theorem}
\declaretheorem{proposal}[sibling=theorem]

\begin{document}

\begin{theorem}This is a theorem.\end{theorem}
\begin{proposal}This is a proposal.\end{proposal}

\end{document}
```

暫時的解決方法是在導言區中、載入 `thmtools` 之後但在 `\declaretheorem` 之前，加入以下幾行：

```text
\makeatletter
\@ifundefined{newcounteralias}{}{%
  \renewcommand\thmt@autorefsetup{\@xa\def\csname\thmt@envname autorefname\@xa\endcsname\@xa{\thmt@thmname}}%
}
\makeatother
```

#### `polyglossia`、`xepersian` 與 `array`

如果您使用 `polyglossia` 或 `xepersian` 套件排版阿拉伯文字，並且載入了 `array` 套件或其他會載入 `array` 的表格相關套件，那麼當阿拉伯文字放在類表格結構內時，您會收到 `\UseMathForPositioningText` 未定義的錯誤。

```text
\documentclass[12pt,a4paper]{article}
\usepackage{polyglossia}
\usepackage{array}
\setdefaultlanguage{arabic}
\newfontfamily\arabicfont[Script=Arabic]{Noto Naskh Arabic}
\begin{document}
\begin{tabular}{c}
السلام عليكم
\end{tabular}
\end{document}
```

這可以透過在 `\documentclass` 宣告之前加入 `\DocumentMetadata{}` 來解決；或考慮改用 `babel` 套件來排版阿拉伯文字。

#### `babel-spanish` 與 `biblatex-apa`

在使用 `biblatex` 的 `apa` 樣式時載入 `babel-spanish`，會導致與 hooks 及 `\@makecaption` 相關的編譯錯誤：

```text
\usepackage[spanish]{babel}
\usepackage[style=apa]{biblatex}
```

不過，只要為 `babel` 加上 `shorthands=off` 選項即可避免此錯誤。

#### `xgreek`、`hyperref` 與 `\appendix`

當載入 `xgreek`（僅適用於 XeLaTeX 與 LuaLaTeX）與 `hyperref` 套件時，出現在 `\appendix` 之後的章節標題會引發編譯錯誤：

```text
\documentclass{article}
\usepackage{xgreek}
\usepackage{fontspec}
\setmainfont{GFS Artemisia}
\usepackage{hyperref}
\begin{document}
\section{Εισαγωγή}
\appendix
\section{Δεδομένα}
\end{document}
```

修正方式是為 `hyperref` 加上 `hypertexnames=false` 選項。

#### `flowfram` 與 `titlesec`

目前 `flowfram` 與 `titlesec` 套件彼此不相容。不過，作者可以考慮使用新的 `\EditInstance` 介面來設定章節標題樣式，例如：

```text
\DocumentMetadata{}
\documentclass{article}
\usepackage{flowfram}
\usepackage[dvipsnames]{xcolor}
\EditInstance{heading}{section}{
  number-format=\fbox{\LARGE\bfseries\theheading},
  title-decls=\Large\bfseries\sffamily\color{NavyBlue}
}
\begin{document}
\section{Introduction}
\end{document}
```

更多詳細資訊請參閱[此連結](https://mirrors.ctan.org/macros/latex-dev/required/latex-lab/latex-lab-sec-template.pdf)。

### Ayakaleaf Pro 中的 TeX Live 2026

Ayakaleaf Pro 管理員可以依照一般方式更新設定來安裝 TeX Live 2026：將 `TEX_LIVE_DOCKER_IMAGE`（以及 `ALL_TEX_LIVE_DOCKER_IMAGES`）指向新的 TeX Live 2026 映像檔即可。無需進行其他升級。
