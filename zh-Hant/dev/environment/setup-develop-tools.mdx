## 推薦的開發工具 {#develop-tools-recommended}

這些選用服務不是執行 Overleaf 所必需的，但在開發、除錯和檢視資料時非常有幫助。它們都是開發環境的一部分，因此不需要在 `docker-compose.yml` 中新增任何內容。登入網站後，導覽列中的 **Dev tools** 選單會連結到網站在自身路徑上提供的工具。

| 工具 | 位址 | 定義位置 |
| --- | --- | --- |
| **Grafana**, 所有服務的狀態、指標和日誌 | [http://localhost/grafana/](http://localhost/grafana/) | `develop/grafana/docker-compose.yml`, 在 `develop/dev.rc` 中 `GRAFANA_ENABLED=true` 時開啟（預設） |
| **Mailpit**, 網站寄出的每封郵件的收件匣 | [http://localhost/mailpit/](http://localhost/mailpit/) | `develop/mail/docker-compose.yml`, `MAILPIT_ENABLED=true` 時開啟（預設） |
| **Mongo Express**, MongoDB 的 UI | [http://localhost/mongo-express/](http://localhost/mongo-express/) | `develop/docker-compose.yml`, 一律開啟 |
| **RedisInsight**, Redis 資料的 UI | [http://localhost/redis-insight/](http://localhost/redis-insight/) | `develop/docker-compose.yml`, 一律開啟 |
| **Hoppscotch**, 類似 Postman 的瀏覽器型 API 用戶端 | [http://localhost:9170](http://localhost:9170/) (`HOPPSCOTCH_PORT`) | `develop/hoppscotch/docker-compose.yml`, `HOPPSCOTCH_ENABLED=true` 時開啟（預設） |

<Warning>

這些工具都沒有登入機制：Grafana 的匿名使用者就是其管理員，Mongo Express 可以修改任何文件。網站、Hoppscotch、Mongo Express（8081）和 RedisInsight（5540）只監聽主機的 `127.0.0.1`，因此其他主機無法存取它們。

</Warning>

### Grafana {#grafana}

Grafana 由網站透過 webpack-dev-server 在 `/grafana/` 上提供，因此不需要獨立的連接埠。它的 **Overleaf Develop** 資料夾中有以下儀表板：

| 儀表板 | 顯示內容 |
| --- | --- |
| All services (首頁) | 每個服務的狀態、主機指標、負載和日誌。點選某個服務即可開啟其儀表板 |
| Server | 主機的 CPU、負載、記憶體、磁碟和網路，以及 clsi 的編譯 |
| Errors | 錯誤日誌、5xx 和 4xx 回應、最常見的錯誤訊息和失敗的路由 |
| Data flow | 一次編輯的路徑：document-updater 和 Redis、project-history、history-v1、Mongo、物件儲存 |
| Containers | 每個容器的狀態、CPU、記憶體、網路和磁碟，包括沙箱編譯 |
| 每個服務一個 | Node.js 服務、git-bridge（JVM）、mongo 和 redis |

Prometheus 擷取各服務的 `/metrics`，以及 `mongodb-exporter`、`redis-exporter`、`cadvisor` 和 `node-exporter`；Alloy 將專案中每個容器的日誌傳送到 Loki，儀表板中的 **Log search**、**Service** 和 **Log level** 篩選器會從那裡讀取。這些資料只存在於容器中，因此重新建立容器會將其清空。cAdvisor 以特權模式執行，以唯讀方式讀取主機的 `/`、`/sys`、Docker 資料和 containerd 通訊端；node-exporter 讀取主機的 `/`。

儀表板是產生出來的：請修改 `develop/grafana/make-dashboards` 並執行它，而不要直接編輯 JSON 檔案。

### Mailpit {#mailpit}

設定 `MAILPIT_ENABLED=true` 後，`web` 會把每封郵件寄到 Mailpit 而不是真正的郵件伺服器，並且電子郵件確認會開啟（`EMAIL_CONFIRMATION_DISABLED=false`）。這樣就可以從收件匣開啟啟用連結、專案邀請、密碼重設和確認碼。

Mailpit 沒有磁碟區：重新建立其容器會清空收件匣。

### 設定 Hoppscotch {#setup-hoppscotch}

#### 透過 Proxy 傳送 API 請求 {#proxy-api-request}

Hoppscotch 從瀏覽器傳送請求，而瀏覽器無法透過 Docker 名稱存取各服務。它的代理 Proxyscotch 在 Docker 網路內執行，並在 Hoppscotch 位址的 `/proxy` 上提供。開啟 [http://localhost:9170](http://localhost:9170/)，前往 Settings → Interceptor，選擇 **Proxy**，並將 Proxy URL 設為 `http://localhost:9170/proxy`。此設定會保存在瀏覽器中。

#### 匯入服務 API {#import-the-service-apis}

`develop/hoppscotch/openapi/` 中為每個服務的內部 API 提供了一個 OpenAPI 檔案。在 Hoppscotch 中開啟 Collections → Import → Import from File，並一次選取所有檔案。每個檔案都會成為一個集合，其請求會傳送到該服務的 Docker 位址。相同的檔案也顯示在 [服務 API](/zh-Hant/dev/service-api/overview) 一節中。

#### CSRF 問題 {#csrf-problems}

<Warning>

如果您使用 Postman 或其他除錯工具產生 **POST** 請求，可能會發現登入被**禁止**，原因是 403 錯誤。這是因為 Overleaf 受到 **CSRF** 驗證保護。

</Warning>

<Frame>
  <img src="/images/dev/image-8.png" alt="" />
</Frame>

在主控台中，您可能會看到：

<Frame>
  <img src="/images/dev/image-9.png" alt="" />
</Frame>

要在 Overleaf 開發中處理這個問題，您需要設定 CSRF token。以下是詳細教學。

<Steps>
<Step title="新增 Pre-Request">
將以下程式碼加入 Pre-Request

<Frame>
  <img src="/images/dev/image-10.png" alt="" />
</Frame>

腳本如下：

```js wrap
pm.sendRequest("http://web:3000/dev/csrf", function (err, res) {
    if (err) {
        console.log(err);
        return;
    }

    // 1) Save CSRF token (/dev/csrf)
    const token = res.text().trim();
    pw.env.set("csrftoken", token);
    console.log("csrftoken =", token);

    const setCookieHeader = (res.headers || []).find(h => h.key?.toLowerCase() === "set-cookie")?.value;
    console.log("set-cookie =", setCookieHeader);

    if (!setCookieHeader) return;

    const cookiePair = setCookieHeader.split(";")[0].trim(); // overleaf.sid=...
    pw.env.set("cookie_header", cookiePair);
    console.log("cookie_header =", cookiePair);
});
```
</Step>

<Step title="新增請求標頭">
您需要新增以下標頭：

| 標頭名稱  | 標頭值        |
| ------------ | ------------------- |
| Content-Type | `application/json`  |
| X-Csrf-Token | `<<csrftoken>>`     |
| Cookie       | `<<cookie_header>>` |

<Frame>
  <img src="/images/dev/image-11.png" alt="" />
</Frame>
</Step>

<Step title="使用 API 工具登入">
現在您可以使用您的使用者名稱與密碼登入。

```json5
{
  "_csrf": "<<csrftoken>>",
  "email": "admin@overleaf.com",
  "password": "xxxxxx"
}
```

以下是輸入錯誤的使用者名稱或密碼時的回應。

<Frame>
  <img src="/images/dev/image-12.png" alt="" />
</Frame>
</Step>
</Steps>
