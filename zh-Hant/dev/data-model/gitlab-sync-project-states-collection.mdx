`gitlabSyncProjectStates` 為每個連結到 GitLab 專案的專案保存一份文件：連結的是哪個儲存庫，以及上一次同步停在哪裡。 此集合屬於 `gitlab-sync` web 模組（`services/web/modules/gitlab-sync`）。schema 位於 `services/web/modules/gitlab-sync/app/models/gitlabSyncProjectStates.mjs`，所有存取都經過 `services/web/modules/gitlab-sync/app/src/SyncStateManager.mjs`。 欄位與 [GitHub Sync Project States](/zh-Hant/dev/data-model/github-sync-project-states-collection) 相同。

#### 欄位 {#fields}

| 欄位 | 型別 | 含義 | 來源 |
| ----- | ---- | ------- | ------ |
| `_id` | ObjectId | 建立時由 Mongoose 設定。 | |
| `projectId` | ObjectId | 連結的專案。必填。schema 寫了 `unique: true`，但不會建立任何索引（見「索引」）。 | `gitlabSyncProjectStates.mjs:8` |
| `repoFullName` | String | 含命名空間的 GitLab 專案路徑（GitLab 的 `path_with_namespace`），例如 `group/subgroup/name`。必填。 | `gitlabSyncProjectStates.mjs:9`, `GitLabApiClient.mjs:347` |

#### 寫入方 {#who-writes-it}

| 程式碼 | 作用 |
| ---- | ------------ |
| `SyncStateManager.mjs:9-14` (`createProjectState`) | 建立文件：將儲存庫匯入為新專案之後（`services/web/modules/gitlab-sync/app/src/GitLabSyncHandler.mjs:175-181`），或將專案匯出到新儲存庫之後（`GitLabSyncHandler.mjs:234-240`，僅限擁有者，已連結時拒絕）。 |
| `SyncStateManager.mjs:16-21` (`updateProjectState`) | 對變更的欄位執行 `$set`。當已同步分支不再包含 `lastSyncCommit`（merge base 檢查，`services/web/modules/gitlab-sync/app/src/GitLabApiClient.mjs:460`），或者該提交已不存在且使用者有推送權限（`GitLabSyncHandler.mjs:123,126-137`）時，`getMergeOverview` 會設定 `mergeStatus: 'diverged'`。 同步（`services/web/modules/gitlab-sync/app/src/GitMerge.mjs`）成功時會更新 `lastSyncCommit`/`lastSyncVersion`（例如 `:152,189,231`），以 `unmergedBranchName`、`unmergedBranchHead` 和 `conflictVersion` 記錄衝突（`:214-220`），並在衝突解決後清除它們（`:257-264`）。 |
| `SyncStateManager.mjs:23-25` (`removeProjectState`) | 在擁有者取消連結專案時（`GitLabSyncHandler.mjs:83-97`）以及已刪除專案過期時（`services/web/modules/gitlab-sync/index.mjs:46-48`）刪除文件。 |

#### 讀取方 {#who-reads-it}

| 程式碼 | 作用 |
| ---- | ------------ |
| `GitLabSyncHandler.mjs:39-60` (`getProjectState`) | 向編輯器提供 `mergeStatus`、`repoFullName` 和 `unmergedBranchName`。沒有文件時回傳 `need-export`，這個值從不儲存。 |
| `GitLabSyncHandler.mjs:110-143` (`getMergeOverview`) | 將 `lastSyncCommit` 和 `lastSyncVersion` 與 GitLab 及專案歷史比較，列出新的提交。 |
| `GitLabSyncHandler.mjs:200` (`exportProject`) | 拒絕匯出已連結的專案。 |
| `GitMerge.mjs:36` (`doGitMergeWithoutLock`) | 在同步開始時載入狀態。 |

#### 索引 {#indexes}

| 名稱 | 鍵 | 選項 | 遷移 |
| ---- | ---- | ------- | --------- |
| `_id_` | `_id: 1` | | default |

Mongoose 的 `autoIndex` 已關閉（`services/web/app/src/infrastructure/Mongoose.mjs:7`），因此 schema 中 `projectId` 上的 `unique: true` 不會建立任何索引。 沒有遷移為此集合建立索引。

#### 備註 {#notes}

* GitLab 的 API 無法像 GitHub 那樣將分支移到任意提交。能快轉時，同步會直接提交到已同步分支上；否則提交到暫時分支，再透過 merge request 合併（`GitMerge.mjs:16-21`）。
* 同步在專案的 `gitSync` 鎖下執行，與 GitHub Sync 和 Gitea Sync 共用（`GitMerge.mjs:25-32`）。
* 已刪除的專案會保留其文件，直到專案過期。
* 使用者的 GitLab 權杖位於 [GitLab Sync User Credentials](/zh-Hant/dev/data-model/gitlab-sync-user-credentials-collection)。
