`notifications` 儲存顯示在使用者專案儀表板頂端的通知。一份文件是給一位使用者的一則通知，由其 `key` 識別。只有 `notifications` 服務直接存取該集合（`services/notifications/app/js/Notifications.js`）；`web` 和 `third-party-datastore` 呼叫它的 HTTP API。沒有 Mongoose 結構描述。

#### 欄位 {#fields}

| 欄位 | 型別 | 意義 | 來源 |
| --- | --- | --- | --- |
| `_id` | ObjectId | 通知 id。`web` 透過此 id 將通知標示為已讀。 | `Notifications.js:58-65` |
| `user_id` | ObjectId | 看到該通知的使用者。 | `Notifications.js:26` |
| `key` | String | 識別通知，例如 `project-invite-<inviteId>`。upsert 讓每個 `user_id` 和 `key` 只保留一份文件；沒有唯一索引。 | `Notifications.js:27`, `:51-55` |
| `templateKey` | String | 前端要呈現哪一種通知。通知被閱讀或關閉時移除此欄位；文件本身保留。 | `Notifications.js:29`, `:63`, `:72`, `:78` |
| `messageOpts` | Object | 通知文字所需的值，取決於 `templateKey`（專案邀請為 `userName`、`projectName`、`projectId`、`token`）。使用者依 id 關閉通知時移除。 | `Notifications.js:28`, `:63` |
| `expires` | Date | 選用。TTL 索引會在此時間之後刪除文件。 | `Notifications.js:35-50` |

#### 說明 {#notes}

* 已讀通知不會被刪除：只會移除 `templateKey`。由於文件仍保留 key，之後對同一 key 不帶 `forceCreate` 的 `addNotification` 不會產生任何效果（`Notifications.js:21-24`）。
* `/key/:key` 路由只依 key 操作，跨越所有使用者（`Notifications.js:76-100`）。
* 如果 `web` 沒有 `apis.notifications.url`，它既不建立也不讀取通知（`NotificationsHandler.mjs:17`、`:41`）。
