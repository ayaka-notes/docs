我們非常自豪地宣布推出 Overleaf Pro 6.3.2。上游 Overleaf 6.3.2 是更新 Node.js 的安全性版本，而我們隨之推出同步家族的新成員：繼 GitHub、GitLab 與 Dropbox 之後，您的專案現在也能存放在 Gitea 中。

### 變更內容

* Gitea 同步（早期預覽版）：與 gitea.com 或您自架的 Gitea 雙向同步。
* Node.js 24.22.1：上游 Overleaf 6.3.2 中的安全性更新。
* 由我們的 E2E 測試系統與內部 Horizon 問題調查（Internal Horizon Issue Investigation）發現的錯誤修正。

<Info>

Gitea 同步在 6.3.2 中以**早期預覽版**推出，供灰度測試使用，並將在 v6.4.0 正式發布。在此之前，其設定與行為仍可能變更。此功能預設為關閉。如有任何問題，請在 [GitHub](https://github.com/ayaka-notes/ayakaleaf-pro/issues) 上回報。

</Info>

#### 功能 01：Gitea 同步（預覽版）

許多實驗室與小型團隊都自行架設 Gitea，因為它輕量到只需一台小型伺服器就能執行。Gitea 同步的運作方式與 GitHub 同步及 GitLab 同步相同：連結您的帳號，從新增專案選單匯入儲存庫，或將專案匯出為新的 Gitea 儲存庫。接著在編輯器中推送與拉取，並以儲存庫本身的合併方式透過拉取請求（pull request）進行合併。Overleaf 絕不會略過您的分支保護：當拉取請求需要核准或通過檢查時，它會等待您在 Gitea 中完成合併。

它支援 gitea.com 以及 1.23 或更新版本的自架 Gitea。請設定 `GITEA_SYNC_ENABLED`、`GITEA_SYNC_CLIENT_ID`、`GITEA_SYNC_CLIENT_SECRET` 與 `GITEA_TOKEN_CIPHER_PASSWORD`，若為自架執行個體，還需設定 `GITEA_SYNC_URL`。

完整的設定說明請參閱 [Gitea 同步](/zh-Hant/on-premises/configuration/overleaf-toolkit/gitea-synchronisation  "mention")。

#### 錯誤修正

* **Git 同步**：當在 GitHub、GitLab 或 Gitea 上刪除的檔案無法在 Overleaf 中刪除時，同步現在會失敗並可重試，而不會回報成功卻將該檔案遺留下來。刪除檔案的 `git push` 也會以相同方式失敗。
* **Git bridge**：在編輯器中以非文字副檔名（例如 `.csv`）建立的文件，在 `git push` 變更它之後仍可編輯。
* **追蹤修訂**：透過連結共用之專案的未登入編輯者可以刪除留言串，但不再能將其標記為已解決或重新開啟；審閱者可以刪除自己的回覆。
* **範本庫**：發布範本需要具備該專案的存取權限。
* **Learn**：當無法連線至 wiki 時，已快取的說明頁面仍可使用。

完整清單請參閱 [6.3.2 版本說明](/zh-Hant/on-premises/release-notes/release-notes-6.x.x#ayakaleaf-pro-6.3.2  "mention")。

#### 升級

* 從 6.3.1 或 6.3.0 升級：無需遷移。拉取新映像檔並重新啟動即可。
* 從 6.2.x 或更早版本升級且有使用 Zotero 或 Mendeley：請先執行 6.3.0 的 [Zotero / Mendeley 遷移](/zh-Hant/on-premises/release-notes/release-notes-6.x.x#ayakaleaf-pro-6.3.0  "mention")。
* Gitea 同步預設為關閉，只需要新的環境變數。
