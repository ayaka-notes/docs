Kubernetes 執行的映像檔與 Toolkit 相同，沒有另外的 Kubernetes 映像檔。

| 映像檔                                               | 使用者                                                                  |
| ---------------------------------------------------- | ----------------------------------------------------------------------- |
| `ghcr.io/ayaka-notes/overleaf-pro:6.3.2`             | Deployment `overleaf`                                                   |
| `ghcr.io/ayaka-notes/overleaf-pro/git-bridge:6.3.2`  | [Git 整合](/zh-Hant/on-premises/configuration/kubernetes/integrations/git-integration)（選用），與上方使用相同的標籤 |
| `ghcr.io/ayaka-notes/texlive-*`                      | 編譯，於[步驟 0](/zh-Hant/on-premises/installation/using-kubernetes/0.-prepare-the-nodes) 中拉取到節點的 Docker |

這些映像檔在 [ghcr.io](https://github.com/ayaka-notes/ayakaleaf-pro/pkgs/container/overleaf-pro/) 上公開提供 amd64 與 arm64 版本，因此 kubelet 不需要憑證即可拉取。

<Warning>

請一律使用版本標籤（例如 `6.3.2`），而非 `latest`。升級會執行資料庫遷移，必須依照[在 Kubernetes 上升級](/zh-Hant/on-premises/maintenance/upgrading-on-kubernetes)進行；使用會變動的標籤時，Pod 每次被重新排程都可能被升級。

</Warning>

### Q\&A

<Accordion title="我們的節點無法連線至 ghcr.io，該怎麼辦？">

<strong>回答：</strong>請將映像檔複製到節點可以連線的映像檔登錄庫，並在 manifest 中使用該名稱，例如：

```bash
docker pull ghcr.io/ayaka-notes/overleaf-pro:6.3.2
docker tag ghcr.io/ayaka-notes/overleaf-pro:6.3.2 registry.example.com/ayakaleaf/overleaf-pro:6.3.2
docker push registry.example.com/ayakaleaf/overleaf-pro:6.3.2
```

若登錄庫未使用 TLS，containerd 需要在每個節點上建立 `/etc/containerd/certs.d/<registry>/hosts.toml`，內容為 `server = "http://<registry>"`，並依照[步驟 0](/zh-Hant/on-premises/installation/using-kubernetes/0.-prepare-the-nodes) 設定 `config_path`。Docker 本身只會透過純 HTTP 推送到 `localhost`，因此請在登錄庫主機上透過 `localhost:<port>` 推送，或將其加入 `insecure-registries`。

</Accordion>
