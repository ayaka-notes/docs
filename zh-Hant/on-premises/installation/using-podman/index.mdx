RHEL 及其重建版本（Rocky Linux、AlmaLinux）內建 Podman 而非 Docker，有些組織也不允許在伺服器上使用 Docker。Toolkit 可以改為在 **rootless Podman** 上執行 Ayakaleaf Pro：容器以一般使用者身分執行，編譯仍在沙箱化的 TeX Live 容器中進行，SELinux 維持 enforcing 狀態。指令碼 `bin/podman-setup` 會檢查主機並修正它能修正的問題。

完成本節後，你會得到與 [使用 Docker Compose](/zh-Hant/on-premises/installation/using-docker-compose) 相同的執行個體：具備沙箱編譯、MongoDB 與 Redis 的 Ayakaleaf Pro，並照常使用 `bin/up`、`bin/doctor` 與 `bin/upgrade` 管理。

<Info>

Podman 支援仍屬實驗性質。它來自官方 Overleaf Toolkit，官方只在 RHEL 9 及更新版本上，以 rootless Podman、沙箱編譯與 SELinux enforcing 的組合進行測試。我們在 Rocky Linux 9.9（Podman 5.8，SELinux enforcing）上搭配 Ayakaleaf Pro 6.3.4 測試了這些頁面。Docker 仍是建議使用的容器執行環境。

</Info>

### 你需要準備什麼 {#what-you-need}

* **RHEL、Rocky Linux、AlmaLinux 或 CentOS Stream 9 及更新版本**，且 SELinux 處於 enforcing 狀態。在其他發行版上 `bin/podman-setup` 會停止執行。在 Ubuntu 或 Debian 上，請使用 [使用 Docker Compose](/zh-Hant/on-premises/installation/using-docker-compose/linux)。
* **一個具有 `sudo` 權限的非 root 使用者**，由它擁有這些容器。本節的所有指令都以此使用者身分執行；`bin/podman-setup` 拒絕以 `root` 身分執行。
* **一台乾淨的主機**：沒有 Docker Engine，也沒有既有的 Toolkit 安裝。本節不涵蓋將既有的 Docker 執行個體遷移到 Podman。

### 與 Docker 的差異 {#how-it-differs-from-docker}

|                                  | Docker                               | Rootless Podman                                                                          |
| -------------------------------- | ------------------------------------ | ---------------------------------------------------------------------------------------- |
| 誰執行容器                        | Docker 常駐程式，以 `root` 身分       | 你的使用者                                                                                |
| 用於啟動編譯的 socket             | `/var/run/docker.sock`               | `/run/user/<uid>/podman/podman.sock`                                                     |
| 連接埠                            | 任意，例如 `80` 與 `443`              | `1024` 以上，例如 `8080`                                                                   |
| 主機防火牆（`firewalld`）          | 發布的連接埠會繞過它                  | 會生效：使用 `firewall-cmd` 開放連接埠                                                     |
| 重新開機後啟動                    | Docker 常駐程式會重新啟動它們         | 使用者服務 `podman-restart`                                                               |
| SELinux                          | Toolkit 不做設定                      | 原則模組 `podman_socket_clsi`，以及 `config/overleaf.rc` 中的 `SELINUX_MODE=managed`        |
| 編譯用的 seccomp 設定檔            | 內建於映像檔中                        | 由 Toolkit 擷取到 `config/seccomp/<version>/` 並設為 `SECCOMP_PROFILE`                     |

### 已知限制 {#known-limitations}

* <strong>Git 整合。</strong>在 Ayakaleaf Pro 6.3.4 中，`git clone` 在 Podman 上會以 `502` 失敗：映像檔內的 NGINX 使用 Docker 的 DNS 伺服器（`127.0.0.11`）查詢 `git-bridge` 容器，而 Podman 沒有這個伺服器。修正（[1b911d1092](https://github.com/ayaka-notes/ayakaleaf-pro/commit/1b911d1092c80f7b0ff77c5e3805b40503d49964)）會隨下一個版本推出；在此之前，請保持 `GIT_BRIDGE_ENABLED=false`。
* <strong>用戶端 IP 位址。</strong>Rootless Podman 從容器網路內部轉送發布的連接埠，因此 Ayakaleaf Pro 看到的每位訪客都是內部位址，例如 `10.89.0.15`。管理面板中使用者的[稽核記錄](/zh-Hant/on-premises/user-guide/administrators/user-management#audit-logs)顯示的是這個位址，而不是使用者的 IP 位址。
