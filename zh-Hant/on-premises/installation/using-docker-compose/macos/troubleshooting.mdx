### 初始化失敗並出現 invalid command code {#initialization-fails-with-invalid-command-code}

當 `bin/init` 找到 macOS 的 BSD sed 時，會回報 `sed: ... invalid command code`。請依照 [1. 下載 Toolkit](/zh-Hant/on-premises/installation/using-docker-compose/macos/1.-download-the-toolkit) 將 GNU sed 加入 `PATH`，並檢查 `sed --version`。

失敗的初始化可能會在 `config/` 中留下全部三個檔案，且 `OVERLEAF_INVITE_TOKEN_SECRET` 為空值。之後再次執行 `bin/init` 會回報 `Config files already exist`。對於從未啟動過的新安裝，請將這三個檔案移至備份目錄，然後再次執行 `bin/init`。對於現有的執行個體，請保留其設定與機密，不要為了讓 `bin/init` 再次執行而刪除其檔案。

### MongoDB 不斷重新啟動 {#mongodb-keeps-restarting}

請讀取 MongoDB 日誌與 Docker 虛擬機器的核心版本：

```bash
bin/docker-compose logs --tail=100 mongo
docker info --format '{{.KernelVersion}}'
```

若日誌指出 Linux 核心不相容，請依照 [檢查 Docker 虛擬機器的 Linux 核心](/zh-Hant/on-premises/installation/using-docker-compose/macos/5.-personalizing-your-instance#check-the-docker-vms-linux-kernel) 操作，然後再次執行 `bin/up -d`。僅憑結束代碼 `137` 並不能證明 MongoDB 記憶體不足：請檢查容器狀態與日誌。關於 Docker Desktop 上較舊的 MongoDB 問題，另請參閱 [疑難排解](/zh-Hant/on-premises/support/troubleshooting)。

### 無法連線至 Docker daemon {#cannot-connect-to-the-docker-daemon}

請啟動 Docker Desktop 並檢查所選的 Docker context，請參閱 [0. 設定 Docker Desktop](/zh-Hant/on-premises/installation/using-docker-compose/macos/0.-setup-docker-desktop)。若 `docker info` 可以運作，但編譯無法連線到 Docker，請檢查 `config/overleaf.rc` 中的 socket 設定並讀取 `clsi` 日誌。Mac 上的 Docker CLI 能正常運作，並不代表應用程式的 socket 掛載是正確的。

### 頁面可以開啟，但編譯失敗 {#the-page-opens-but-compiles-fail}

請檢查 TeX Live 映像檔是否存在於本機，且與 Docker 引擎的架構相符：

```bash
docker image inspect ghcr.io/ayaka-notes/texlive-full:2026.1 \
  --format '{{.Os}}/{{.Architecture}}'
bin/logs -f clsi
```

在 Apple silicon 上，映像檔應為 `linux/arm64`。請確認 `SERVER_PRO` 與 `SIBLING_CONTAINERS_ENABLED` 皆為 `true`，然後以 `bin/up -d` 套用變更。若日誌回報缺少編譯目錄，請檢查 Docker Desktop 的檔案分享與 `OVERLEAF_DATA_PATH` 的位置。請勿為了掩蓋掛載失敗而關閉沙箱編譯。

### Not a directory，或缺少 bind mount {#not-a-directory-or-a-bind-mount-is-missing}

override 所掛載的主機檔案可能已被刪除，或者 Docker 可能在原本應為檔案的位置建立了目錄。請檢查主機上的來源路徑，以及該掛載預期的是檔案還是目錄。在重新建立容器之前，請先還原設定檔。安裝在 `/tmp` 下的環境可能會在 macOS 移除暫存檔案後遇到此問題。

### 連接埠或容器名稱衝突 {#port-or-container-name-conflicts}

若連接埠 `8080` 已被使用，請在 `config/overleaf.rc` 中選擇其他連接埠，並將 `OVERLEAF_SITE_URL` 設為相符的值，然後再次執行 `bin/up -d`。

Toolkit 會為其容器指定固定名稱，例如 `sharelatex`、`mongo` 與 `redis`。僅變更 `PROJECT_NAME` 並不能讓兩個 Toolkit 安裝彼此獨立。在啟動第二個執行個體之前，請檢查 `docker ps -a`，並在 Compose override 中使用其他容器名稱、其他連接埠與獨立的資料目錄。請勿為了解決名稱衝突而移除現有部署的容器或資料。

### 執行個體過一段時間後無法連線 {#the-instance-is-unreachable-after-a-while}

Mac 可能進入了睡眠，或 Docker Desktop 已被結束。請參閱 [保持執行個體可用](/zh-Hant/on-premises/installation/using-docker-compose/macos/6.-post-installation-tasks#keep-the-instance-available)。

### `bin/doctor` 表示這不是 Linux，或要求登入 Quay {#bin/doctor-says-this-is-not-linux-or-asks-for-a-quay-login}

在 macOS 上使用公開映像檔時，這兩個警告都是預期中的，請參閱 [2. 熟悉 Toolkit](/zh-Hant/on-premises/installation/using-docker-compose/macos/2.-familiarize-yourself-with-the-toolkit)。請改為檢查映像檔拉取、服務狀態與編譯結果，且不要忽略報告中的其他錯誤。
