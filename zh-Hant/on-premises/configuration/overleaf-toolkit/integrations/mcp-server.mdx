每個專案都有一個 MCP Server，因此 Claude Code、Codex、Cursor、VS Code 或 Gemini CLI 等 AI 用戶端可以處理該專案：讀取與編輯其檔案、編譯專案、讀取 LaTeX 記錄、下載 PDF 並回覆留言。 從 v6.3.3 起，它們還可以瀏覽歷史記錄並還原版本、審閱追蹤修訂、新增留言、使用專案聊天以及移動檔案。

<Info>

此功能由 [ayaka-notes/ayakaleaf-pro](https://github.com/ayaka-notes/ayakaleaf-pro) 開發，自 v6.3.1 起推出。 歷史記錄、追蹤修訂、專案聊天、新留言和移動檔案的工具從 v6.3.3 起提供，請參閱 [v6.3.3 新功能](/on-premises/user-guide/users/mcp-server#new-in-v6.3.3)。

</Info>

### 設定 {#setup}

MCP Server 隨 Git 整合一併提供：啟用 [git-bridge](/zh-Hant/on-premises/configuration/overleaf-toolkit/integrations/git-integration) 後，MCP Server 也隨即可用。不需要其他任何設定。

### 連接 AI 用戶端 {#connect-an-ai-client}

1. 在**帳號設定**中產生 Git 驗證權杖。MCP Server 與 Git 使用同一個權杖。
2. 在編輯器中開啟**整合**，然後點擊 **MCP Server**。它會顯示專案 MCP Server 的位址 `https://<your-overleaf>/project/<project_id>/mcp`，以及將其加入各 AI 用戶端的方式：複製指令，並將 `<token>` 替換為您的權杖。

權杖會以 HTTP 標頭 `Authorization: Bearer <token>` 傳送。例如，Claude Code 的指令為：

```bash
claude mcp add --transport http overleaf \
  https://<your-overleaf>/project/<project_id>/mcp \
  --header "Authorization: Bearer <token>"
```

### 使用方式 {#usage}

連接完成後，直接用日常語言向 AI 用戶端提出要求即可。例如：

| 您的要求 | AI 用戶端使用的工具 |
| --- | --- |
| _修正引言中的錯字。_ | `read_file`、`edit_file`：編輯內容會即時顯示在編輯器中 |
| _編譯專案並修正 LaTeX 錯誤。_ | `compile`、`get_compile_log`、`edit_file` |
| _回覆尚未解決的留言，然後將其標示為已解決。_ | `list_comments`、`reply_to_comment`、`resolve_comment` |
| _切換至 XeLaTeX 並下載 PDF。_ | `update_settings`、`compile`、`get_output_file_link` |
| _以追蹤修訂方式重寫摘要。_ | `read_file`、帶 `trackChanges` 的 `edit_file`（v6.3.3） |
| _自提交的版本以來有哪些變更？_ | `list_versions`、`list_changes`、`diff`（v6.3.3） |
| _把各章移到名為 chapters 的資料夾中。_ | `move_file`（v6.3.3） |

### 工具 {#tools}

| 分類 | 工具 |
| --- | --- |
| 專案 | `get_clone_info`, `get_settings`, `update_settings` |
| 檔案 | `list_files`, `read_file`, `edit_file`, `write_file`, `delete_file`, `move_file`, `create_folder` |
| 編譯 | `compile`, `get_compile_log`, `get_output_file_link`, `word_count` |
| 留言 | `list_comments`, `reply_to_comment`, `resolve_comment`, `reopen_comment`, `add_comment`, `edit_comment_message`, `delete_comment_message` |
| 追蹤修訂 | `list_tracked_changes`, `accept_tracked_changes`, `reject_tracked_changes` |
| 歷史記錄 | `list_versions`, `list_changes`, `diff`, `create_version`, `delete_version`, `restore_file`, `restore_project` |
| 聊天 | `list_chat_messages`, `send_chat_message` |

v6.3.3 有 33 個工具；設定 `OVERLEAF_DISABLE_CHAT=true` 會移除聊天工具，剩下 31 個。v6.3.1 和 v6.3.2 有另外 17 個：即上表中除 `move_file`、`create_folder`、`add_comment`、`edit_comment_message`、`delete_comment_message`、追蹤修訂工具、聊天工具以及 `list_versions` 以外的歷史記錄工具之外的所有工具。在 v6.3.3 中，`read_file` 也能讀取歷史記錄中某個版本的檔案，`edit_file` 和 `write_file` 支援 `trackChanges`，`update_settings` 也能設定拼字檢查語言。

透過 `edit_file`、`write_file` 和 `move_file` 進行的編輯會即時顯示在編輯器中，並與協作者的編輯合併。若要一次處理大量檔案或二進位檔案，AI 用戶端也可以用 Git 複製專案並推送。

使用 `trackChanges` 時，對現有檔案的編輯會成為權杖所屬使用者的追蹤修訂，即使專案中關閉了追蹤修訂也是如此；新檔案永遠不會成為追蹤修訂。不使用 `trackChanges` 時，編輯會遵循專案的追蹤修訂設定。

### 權限 {#permissions}

MCP Server 與 Git 一樣，遵循專案的共用設定：

* 所有能檢視專案的人都可以讀取專案、編譯專案並下載其輸出。
* 只有擁有者和編輯者可以變更其檔案和設定、還原版本，以及接受或拒絕追蹤修訂。
* 審閱者也可以新增留言並回覆留言，解決、重新開啟或刪除自己發起的留言，以及儲存版本。他們不能編輯檔案，即使以追蹤修訂方式也不行。
* 每個人只能編輯自己的留言訊息，審閱者也只能刪除自己的訊息。
* 只有擁有者可以刪除他人儲存的版本。
* 透過連結加入的檢視者看不到留言、追蹤修訂、歷史記錄和聊天，與編輯器中一致。受邀的檢視者可以看到這些內容並使用聊天。
* 如果專案擁有者沒有 **Full project history**，歷史記錄工具只會顯示最近 24 小時的變更，與歷史記錄面板相同。管理員可以看到全部。

使用者指南中有一張表，列出每個角色可以做什麼，請參閱 [誰可以做什麼](/on-premises/user-guide/users/mcp-server#who-may-do-what)。

### 問與答 {#q&a}

<Accordion title="我在編輯器中看不到 Integrations 或 MCP server">

<strong>回答：</strong>MCP 伺服器沒有專屬的環境變數。它是透過 `config/overleaf.rc` 中的 `GIT_BRIDGE_ENABLED=true` 啟用，請參閱 [Git 整合](/zh-Hant/on-premises/configuration/overleaf-toolkit/integrations/git-integration)。變更後，請執行 `bin/up -d`。若未啟用 git-bridge，編輯器的左側欄就不會顯示 **Integrations** 分頁。

</Accordion>

<Accordion title="AI 用戶端顯示「Track changes is off for this project」">

<strong>回答：</strong> 用戶端要求了追蹤修訂，但專案擁有者的帳戶沒有追蹤修訂功能。依序點選 **Admin** 和 **Manage Users**，開啟該擁有者，在 **Features** 分頁中開啟 **Track changes**，請參閱 [Features](/zh-Hant/on-premises/user-guide/administrators/user-management#features)。不帶 `trackChanges` 的編輯仍可正常使用。

</Accordion>

<Accordion title="AI 用戶端只能看到最近 24 小時的變更">

<strong>回答：</strong> 專案擁有者的帳戶沒有完整的專案歷史記錄，因此歷史記錄工具顯示的內容與歷史記錄面板相同：最近 24 小時的變更。依序點選 **Admin** 和 **Manage Users**，開啟該擁有者，在 **Features** 分頁中開啟 **Full project history**，請參閱 [Features](/zh-Hant/on-premises/user-guide/administrators/user-management#features)。

</Accordion>
