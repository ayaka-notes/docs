---

Zotero 匯入在每個 Ayakaleaf Pro Pod 的 **web** 服務（`tpr-webmodule` 模組）中執行。請依照 [Zotero 整合](/zh-Hant/on-premises/configuration/overleaf-toolkit/integrations/zotero-integration) 註冊 Zotero OAuth 用戶端，回呼 URL 為 `${OVERLEAF_SITE_URL}/user/zotero/oauth/callback`，接著依下列方式設定 Kubernetes。

| | |
| --- | --- |
| 服務 | web，位於每個 Ayakaleaf Pro Pod 中；於 web 啟動時讀取 |
| Pod → Zotero | 當使用者連結 Zotero 或匯入、重新整理檔案時，連線至 `https://www.zotero.org/oauth/*` 與 `https://api.zotero.org` |
| 瀏覽器 → Zotero | `https://www.zotero.org/oauth/authorize`，接著返回回呼 URL |
| Zotero → Overleaf | 無：您的執行個體不需要能從網際網路連線 |
| 儲存的資料 | 使用者的 Zotero 金鑰，經加密後儲存於 MongoDB |
| 定期工作 | 無：只有在使用者要求時才會重新整理檔案 |

### 設定

<Steps>
<Step title="ConfigMap">
```yaml title="30-config.yaml (changes)"
  ENABLED_LINKED_FILE_TYPES: project_file,project_output_file,url,zotero
  ZOTERO_CLIENT_ID: <client key>
  # optional: send the module's requests to Zotero through an HTTP proxy
  # ZOTERO_PROXY_URL: http://proxy.example.com:3128
```

`ENABLED_LINKED_FILE_TYPES` 會取代安裝時設定的值；請保留您現有的類型並加入 `zotero`（若同時使用 Mendeley，也請加入 `mendeley`）。
</Step>

<Step title="Secret">
```bash
kubectl -n overleaf patch secret overleaf-secrets --type merge -p '{"stringData":{
  "ZOTERO_CLIENT_SECRET":"<client secret>",
  "ZOTERO_CIPHER_PASSWORD":"'"$(openssl rand -hex 32)"'"}}'
```

`ZOTERO_CIPHER_PASSWORD` 用於加密儲存在 MongoDB 中的使用者 Zotero 金鑰。若未設定，每個 Pod 會在各自的 `/var/lib/overleaf/data` 中產生金鑰檔案。在 [多個副本](/zh-Hant/on-premises/configuration/kubernetes/horizontal-scaling) 的情況下，每個節點都會有不同的金鑰，由其他副本提供服務的使用者將無法使用其已連結的 Zotero 帳號。請在第一位使用者連結 Zotero 之前設定此值：之後若變更，所有使用者都必須重新連結 Zotero。
</Step>

<Step title="套用並重新啟動">
```bash
kubectl apply -f 30-config.yaml
kubectl -n overleaf rollout restart deployment/overleaf     # or statefulset/overleaf
```
</Step>
</Steps>

### 多個副本

請在 Secret 中設定 `ZOTERO_CIPHER_PASSWORD`，詳見上文。若未設定，在某個副本上匯入的檔案將無法在另一個副本上重新整理：重新整理會失敗並顯示「The remote service produced an error」，因為該副本的金鑰檔案無法解密使用者的 Zotero 金鑰。將密碼設定於 Secret 後，所有副本都能正常運作；我們透過在 `overleaf-0` 上匯入並在 `overleaf-1` 上重新整理，測試了這兩種情況。OAuth 交握會將其狀態保存在 Redis 中的工作階段裡，因此回呼可以抵達任何副本。

### 在 Kubernetes 上的測試

我們在 Kubernetes 1.37 上以三個副本置於 HAProxy 之後，針對模擬的 www.zotero.org 與 api.zotero.org（透過來自 `overleaf-certs` 的 `NODE_EXTRA_CA_CERTS` 信任）執行 Zotero 的端對端測試，全部通過（18 個案例）：透過 OAuth 1.0a 連結與解除連結、將文獻庫與群組匯入 `.bib` 檔案、重新整理該檔案、在 Zotero 上撤銷金鑰、要求重新連結、協作者可搜尋參考文獻、只有匯入者可以重新整理、API 錯誤，以及與 Zotero 之間的緩慢連線。
