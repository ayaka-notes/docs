匯入 API（`/docs` 與「Open in Ayakaleaf」按鈕，即 `open-in-overleaf` 模組）在每個 Ayakaleaf Pro Pod 的 **web** 服務中執行，且預設為啟用。以 URL 提供的檔案會透過同一個 Pod 中的 linked-url-proxy 下載。呼叫方式請參閱 [Overleaf 匯入 API](/zh-Hant/on-premises/configuration/overleaf-toolkit/integrations/overleaf-import-api)。

| | |
| --- | --- |
| 服務 | web（`open-in-overleaf` 模組）；透過 linked-url-proxy 下載 |
| 外部 → Overleaf | 瀏覽器從任何網站對 `${OVERLEAF_SITE_URL}/docs` 發送 `GET` 或 `POST` |
| Pod → 外部 | `snip_uri` 與 `zip_uri` 的下載，依 [外部 URL](/zh-Hant/on-premises/configuration/kubernetes/external-url) 所述加以限制 |
| 狀態 | 未登入訪客的請求，會在 Redis 中保留 10 分鐘，直到其登入為止 |
| 定期工作 | 無 |

### 設定

不需要任何設定即可啟用。ConfigMap 中的相關設定：

| 設定 | |
| --- | --- |
| `OVERLEAF_ALLOW_PUBLIC_ACCESS: "true"` | 未登入的訪客可以開啟 `/devs`，且其送出的請求會保留到登入為止，請參閱[公開存取](/zh-Hant/on-premises/configuration/kubernetes/authentication/public-access)。 |
| `MAX_UPLOAD_SIZE` | 單一請求可攜帶的 ZIP 最大大小，單位為 MB（預設為 `50`）。您的 Ingress 或負載平衡器也必須接受此大小的請求內容。 |
| `OVERLEAF_LINKED_URL_*` | `snip_uri` 與 `zip_uri` 可以指向哪些位址，請參閱[外部 URL](/zh-Hant/on-premises/configuration/kubernetes/external-url)。 |

### 多個副本

不需要額外設定。未登入訪客的請求保存在 Redis 中，因此無論訪客登入後連線到哪個副本，都會在該副本上繼續處理。

### 在 Kubernetes 上的測試

我們在 Kubernetes 1.37 上以單一副本執行匯入 API 的端對端測試，全部通過（14 個案例）：`/devs` 頁面及其範例專案、程式碼片段、完整文件、URL 編碼連結與來自 data URL 的檔案轉換為專案、拒絕無法成為專案的提交內容、拒絕從內部位址下載、未登入時送出的請求與連結在登入後保留，以及在啟用 `OVERLEAF_ALLOW_PUBLIC_ACCESS` 時，未登入訪客可存取 `/devs`，且送出的程式碼片段在登入後會繼續處理一次；最後一個案例在三個副本置於 HAProxy 之後的情況下也能通過。
