---
title: 身分驗證
description: 在 Kubernetes 部署中設定登入方式 - OIDC、SAML、LDAP、公開存取、reCAPTCHA 與密碼規則。
icon: address-card
---

所有登入方式都在每個 Ayakaleaf Pro pod 的 **web** 服務中執行。它們都不需要額外的 pod 或定期工作，而且都將登入狀態保存在 Redis 中的工作階段裡，因此無論是一個副本還是多個副本，運作方式都相同。在 Kubernetes 上不同的是設定、密鑰與憑證放在哪裡，以及必須開放哪些網路路徑：

| 方式 | Secret `overleaf-secrets` | Secret `overleaf-certs` | Pod 必須能連線到 |
| --- | --- | --- | --- |
| [OIDC](/zh-Hant/on-premises/configuration/kubernetes/authentication/oidc-authentication) | `OVERLEAF_OIDC_CLIENT_SECRET` | 您的 CA（若為私有） | OP 的 token 與 userinfo 端點 |
| [SAML](/zh-Hant/on-premises/configuration/kubernetes/authentication/saml-authentication) | – | IdP 憑證、Overleaf 自己的金鑰 | 無：訊息經由瀏覽器傳遞 |
| [LDAP](/zh-Hant/on-premises/configuration/kubernetes/authentication/ldap-authentication) | `OVERLEAF_LDAP_BIND_CREDENTIALS` | LDAP CA（若為私有） | LDAP 伺服器 |
| [公開存取](/zh-Hant/on-premises/configuration/kubernetes/authentication/public-access) | SMTP 密碼，用於啟用帳號的電子郵件 | – | SMTP 伺服器 |
| [reCAPTCHA](/zh-Hant/on-premises/configuration/kubernetes/authentication/recaptcha) | `RECAPTCHA_SECRET_KEY`、`DEVICE_HISTORY_SECRET` | – | `www.google.com`（或 `RECAPTCHA_ENDPOINT`） |
| [密碼限制](/zh-Hant/on-premises/configuration/kubernetes/authentication/password-restrictions) | – | – | – |

`EXTERNAL_AUTH` 用於啟用 SSO 方式，在 ConfigMap 中以空格分隔的清單表示，例如 `EXTERNAL_AUTH: ldap oidc`。啟用 SSO 後的帳號以及使用者可以變更的項目與 Toolkit 相同，請參閱[身分驗證](/zh-Hant/on-premises/configuration/overleaf-toolkit/authentication)。

<Warning>

設定錯誤的方式並不會阻止 pod 進入就緒狀態：web 會在 `/var/log/overleaf/web.log` 中記錄 `error setting up passport in modules`，而該方式以及依 `ldap`、`saml`、`oidc` 順序排在其後的方式都會維持關閉。每次變更後請檢查日誌。我們以 `EXTERNAL_AUTH: saml oidc` 並缺少 IdP 憑證的情況進行測試：pod 進入就緒狀態，而 `/saml/login` 與 `/oidc/login` 都回應「Something went wrong」（500），直到憑證路徑修正為止。

</Warning>
