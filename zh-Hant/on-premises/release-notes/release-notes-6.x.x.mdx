## Ayakaleaf Pro 6.3.2

<strong>發布日期：</strong> 2026.10.23

請參閱：[https://github.com/ayaka-notes/ayakaleaf-pro/releases/tag/pro-v6.3.2](https://github.com/ayaka-notes/ayakaleaf-pro/releases/tag/pro-v6.3.2)

我們非常自豪地宣布推出 Overleaf Pro 6.3.2。上游 Overleaf 6.3.2 是更新 Node.js 的安全性版本，我們將其與 Gitea 同步以及自 6.3.1 以來發現的錯誤修正一併推出。

<Info>

Gitea 同步在 6.3.2 中以**早期預覽版**推出，供灰度測試使用，並將在 v6.4.0 正式發布。在此之前，其設定與行為仍可能變更。此功能預設為關閉。如有任何問題，請在 [GitHub](https://github.com/ayaka-notes/ayakaleaf-pro/issues) 上回報。

</Info>

### 變更

* 雙向 Gitea 同步（早期預覽版），支援 gitea.com 與 1.23+ 的自架 Gitea。
* Node.js 24.22.1，即上游 Overleaf 6.3.2 中的安全性更新。
* 由我們的 E2E 測試系統與內部 Horizon 問題調查（Internal Horizon Issue Investigation）發現的錯誤修正。

#### 功能 01：Gitea 同步（預覽版）

與 Gitea 雙向同步，運作方式與 GitHub 同步及 GitLab 同步相同：連結你的帳號、從新增專案選單匯入儲存庫、匯出專案、推送與拉取，並透過拉取請求（pull request）進行合併。Overleaf 絕不會略過儲存庫的分支保護。請參閱 [Gitea 同步](/zh-Hant/on-premises/configuration/overleaf-toolkit/gitea-synchronisation)。

### 錯誤修正

* GitHub、GitLab 與 Gitea 同步：當儲存庫中已刪除的檔案無法在 Overleaf 中刪除時，同步會失敗並可重試，而不會回報成功卻將該檔案留在專案中。刪除檔案的 `git push` 也會以相同方式失敗（[#121](https://github.com/ayaka-notes/ayakaleaf-pro/issues/121)）。
* Git bridge：在編輯器中以非文字副檔名（例如 `.csv`）建立的文件，在 `git push` 變更它之後仍會保持為可編輯的文件。
* 追蹤修訂：透過連結共用之專案的未登入編輯者可以刪除留言串，但不再能將其標記為已解決或重新開啟。審閱者可以刪除自己的回覆。
* 範本庫：發布範本需要具備該專案的存取權限。
* Learn：當無法連線至 wiki 時，已快取的說明頁面仍可使用。

### 升級

* 從 6.3.1 或 6.3.0 升級：無需遷移。拉取新映像檔並重新啟動即可。
* 從 6.2.x 或更早版本升級且有使用 Zotero 或 Mendeley：請先執行 [6.3.0](#ayakaleaf-pro-6.3.0) 中的 Zotero / Mendeley 遷移。
* Gitea 同步預設為關閉，只需要新的環境變數。

## Ayakaleaf Pro 6.3.1

<strong>發布日期：</strong> 2026.10.18

請參閱：[https://github.com/ayaka-notes/ayakaleaf-pro/releases/tag/pro-v6.3.1](https://github.com/ayaka-notes/ayakaleaf-pro/releases/tag/pro-v6.3.1)

我們非常自豪地宣布推出 Overleaf Pro 6.3.1。一般的修補版本通常只會針對 v6.3.0 進行小幅修正，但此版本更進一步：除了大量錯誤修正之外，還推出了五項新功能。

<Info>

Dropbox 同步與 GitLab 同步在 6.3.1 中以**早期預覽版**推出，供灰度測試使用，並將在 v6.4.0 正式發布。在此之前，其設定與行為仍可能變更。兩者預設皆為關閉。如有任何問題，請在 [GitHub](https://github.com/ayaka-notes/ayakaleaf-pro/issues) 上回報。

</Info>

### 變更

* 雙向 Dropbox 同步（早期預覽版）。
* 雙向 GitLab 同步（早期預覽版），包括 15.10+ 的自行管理 GitLab。
* 每個專案各自的 MCP Server，供 Claude Code、Codex、Cursor、VS Code 與 Gemini CLI 等 AI 用戶端使用。
* GitHub 同步支援 GitHub Enterprise。
* 符號面板中的手寫符號辨識，完全在瀏覽器中執行。
* 新增 `OVERLEAF_DISABLE_LOCAL_LOGIN`，可在啟用 SSO 的執行個體上隱藏電子郵件與密碼登入。
* 由我們的 E2E 測試系統與內部 Horizon 問題調查（Internal Horizon Issue Investigation）發現的錯誤修正。
* 上游 Overleaf 6.3.1 修補。

#### 功能 01：Dropbox 同步（預覽版）

每位使用者連結自己的 Dropbox 帳號後，其擁有及與其共用的專案都會出現在 `Apps/<DROPBOX_APP_NAME>/` 下。在 Overleaf 中的編輯會推送至 Dropbox，而在 Dropbox 中的編輯則會透過簽署的 webhook 回傳。必須啟用 Git bridge。請參閱 [Dropbox 同步](/zh-Hant/on-premises/configuration/overleaf-toolkit/dropbox-synchronisation)。

#### 功能 02：GitLab 同步（預覽版）

與 GitLab 雙向同步，運作方式與 GitHub 同步相同：連結你的帳號、從新增專案選單匯入儲存庫、匯出專案、推送與拉取，並透過合併請求進行合併。請參閱 [GitLab 同步](/zh-Hant/on-premises/configuration/overleaf-toolkit/gitlab-synchronisation)。

每個專案都會在 `/project/<project_id>/mcp` 取得一個 MCP 端點，與 git bridge 一同啟用。請使用與 `git clone` 相同的 Git 權杖進行驗證。存取權限遵循專案的角色，且每個工具都有速率限制。請參閱 [MCP Server](/zh-Hant/on-premises/configuration/overleaf-toolkit/mcp-server)。

#### 功能 04：GitHub Enterprise

透過 `GITHUB_SYNC_URL` 將 GitHub 同步指向 GitHub Enterprise Server 或具備資料落地的 GitHub Enterprise Cloud。預設仍使用 github.com。請參閱 [GitHub Enterprise](/zh-Hant/on-premises/configuration/overleaf-toolkit/github-synchronisation#github-enterprise)。

#### 功能 05：手寫符號辨識

將符號面板切換為繪製模式並畫出符號，即可取得相符的 LaTeX 指令。辨識在瀏覽器中使用由 ayaka-notes 訓練的模型執行，因此不會有任何資料離開使用者的電腦。在不支援 `OffscreenCanvas` 的瀏覽器（例如 Safari 15）上，繪製切換按鈕會被隱藏。

### 錯誤修正

* 身分驗證：在啟用 SSO 的執行個體上，本機帳號可以設定與變更密碼，OIDC 使用者不再能變更自己的電子郵件（[#112](https://github.com/ayaka-notes/ayakaleaf-pro/pull/112)）。LDAP、SAML 與 OIDC 登入方式會被保留，SAML/OIDC 登出也恢復正常。請參閱[帳號與密碼](/zh-Hant/on-premises/configuration/overleaf-toolkit/authentication#accounts-and-passwords)。
* LDAP、SAML 與 OIDC：具有多個值的名稱屬性（例如 `cn`）不再導致登入失敗，且 OIDC 電子郵件會像 LDAP 與 SAML 一樣轉為小寫，因此 IdP 以不同大小寫傳送電子郵件的帳號可以順利連結，而不會失敗。
* 已停權的使用者：停權使用者會結束其工作階段並關閉其開啟的編輯器。其 Git 權杖與 MCP 下載會被拒絕。
* GitHub 同步：只有擁有者可以匯出專案，拉取期間所做的編輯會維持待處理狀態，空白檔案會被同步，手動合併會在 GitHub 上驗證，重新連結時會撤銷被取代的權杖。
* Zotero / Mendeley：憑證失效時顯示重新連結訊息，並在匯入後重新索引參考文獻。
* 外部 API 請求（Zotero、Mendeley、GitHub、GitLab、網頁搜尋）的連線逾時由 1 秒改為 3 秒（[#106](https://github.com/ayaka-notes/ayakaleaf-pro/pull/106)）。
* 追蹤修訂：審閱資料包含尚未載入的文件與尚未儲存的變更（來自 [yu-i-i/overleaf-cep#262](https://github.com/yu-i-i/overleaf-cep/pull/262)）。
* 錯誤助理：只針對專案中的文件提供修正建議（[#103](https://github.com/ayaka-notes/ayakaleaf-pro/pull/103)）。
* 管理面板：還原已刪除的專案、變更擁有者與編輯使用者皆能正常運作。搜尋使用字面文字，電子郵件寄送失敗也不再影響帳號的建立或刪除。
* 範本庫：無效的排序會回傳 400 而非 500，範本 ID 會經過驗證，發布沒有主檔案的專案時會要求指定主檔案。
* Git bridge：nginx 會將 `/git/` 代理至 `GIT_BRIDGE_HOST` 與 `GIT_BRIDGE_PORT`，並隱藏內部路由。
* 沙箱編譯：最近編譯過的專案的容器會被保留以供重複使用。

### 升級

* 從 6.3.0 升級：無需遷移。拉取新映像檔並重新啟動即可。
* 從 6.2.x 或更早版本升級且有使用 Zotero 或 Mendeley：請先執行 [6.3.0](#ayakaleaf-pro-6.3.0) 中的 Zotero / Mendeley 遷移。

<Accordion title="現有安裝的 Zotero／Mendeley 遷移">

升級至重新發布的 6.3.0 映像檔時，請使用下方指令碼遷移現有的 Zotero／Mendeley 連結參考文獻中繼資料。此遷移搭配修正 `12031b8dfd`。

此遷移會將 `zoteroGroupId`／`mendeleyGroupId` 重新命名為 `group_id`、將 `importedByUserId` 重新命名為 `importer_id`，並移除 `importedByName`。

執行遷移前，請先備份 MongoDB 並停止應用程式。保持 MongoDB 執行中，並開啟其 shell（將 `mongo` 替換為你的容器名稱）：

```bash
docker exec -it mongo mongosh
```

在 `mongosh` 中執行下列內容（將 `sharelatex` 替換為你的資料庫名稱）：

```javascript
use sharelatex

(async () => {
  let updated = 0
  await db.projects.find({}, { rootFolder: 1 }).forEach(async project => {
    const changes = {}
    function visit(folders, path) {
      for (const [i, folder] of (folders || []).entries()) {
        const folderPath = `${path}.${i}`
        for (const [j, file] of (folder.fileRefs || []).entries()) {
          const data = { ...file.linkedFileData }
          if (!["zotero", "mendeley"].includes(data.provider)) continue
          const groupKey = `${data.provider}GroupId`
          if (![groupKey, "importedByUserId", "importedByName"].some(key => key in data)) continue
          for (const [oldKey, newKey] of [[groupKey, "group_id"], ["importedByUserId", "importer_id"]]) {
            if (data[oldKey] != null && data[oldKey] !== "") {
              const value = String(data[oldKey])
              if (newKey in data && data[newKey] !== value) {
                throw new Error(`Conflicting ${newKey}: project ${project._id}, file ${file._id}`)
              }
              data[newKey] = value
            }
            delete data[oldKey]
          }
          delete data.importedByName
          changes[`${folderPath}.fileRefs.${j}.linkedFileData`] = data
        }
        visit(folder.folders, `${folderPath}.folders`)
      }
    }
    visit(project.rootFolder, "rootFolder")
    if (!Object.keys(changes).length) return
    const result = await db.projects.updateOne(
      { _id: project._id, rootFolder: { $eq: project.rootFolder } },
      { $set: changes }
    )
    if (!result.matchedCount) throw new Error(`Project changed during migration: ${project._id}`)
    updated += result.modifiedCount
  })
  print(`Updated ${updated} project(s).`)
})()
```

此指令碼會處理巢狀資料夾，且只會變更 Zotero／Mendeley 中繼資料。重複執行是安全的：已完成的遷移在下次執行時會回報 `Updated 0 project(s).`。若因衝突而中止，請檢查所回報的專案／檔案；先前的專案可能已完成遷移。

啟動更新後的應用程式，重新載入編輯器，並以原始匯入者的身分重新整理現有的參考文獻檔案。歷史快照不會被改寫。若要降級回舊版應用程式，請還原 MongoDB 備份。

</Accordion>

* AI 聊天助理：直接在編輯器中，透過你自己的供應商與 AI 模型對話。

#### 功能 04：範本分頁

範本庫現在會在 MongoDB 中進行分頁、排序與搜尋。無需任何準備即可運作；若有數千個範本，你仍可加入下列索引以維持速度（可安全地重複執行，`mongo`／`sharelatex` 分別為你的容器與資料庫名稱）：

```bash
docker exec mongo mongosh sharelatex --quiet --eval '
db.templates.createIndex({category:1,lastUpdated:-1},{name:"category_1_lastUpdated_-1",background:true});
db.templates.createIndex({lastUpdated:-1},{name:"lastUpdated_-1",background:true});
db.templates.createIndex({category:1,name:1},{name:"category_1_name_1_ci",collation:{locale:"en",strength:2},background:true});
db.templates.createIndex({name:1},{name:"name_1_ci",collation:{locale:"en",strength:2},background:true});
'
```

請保留兩個 `*_ci` 索引上的 `collation` 設定，不要更動——範本庫查詢使用相同的 collation，而 MongoDB 只會使用相符的索引。

這是一個測試版本，也是 Overleaf Pro 的初始版本。此版本不包含任何 Server Pro 的功能，因此僅作為我們的起點。我們之後會加入新功能，例如管理面板與 git-bridge 等。

在此版本中，我們推出了 ARM 版的 Overleaf Docker 映像檔。若你有 Mac 或 ARM 架構伺服器，可以試用看看，但部分功能可能無法正常運作（尚未測試）。

### Docker 映像檔

你可以在這裡找到 Docker 映像檔： [https://github.com/ayaka-notes/ayakaleaf-pro/pkgs/container/overleaf-pro](https://github.com/ayaka-notes/ayakaleaf-pro/pkgs/container/overleaf-pro)

多架構映像檔請參閱[這裡](https://github.com/ayaka-notes/ayakaleaf-pro/pkgs/container/overleaf-pro/691283454?tag=6.0.0).

```bash
docker pull ghcr.io/ayaka-notes/overleaf-pro:6.0.0
```

### 二進位檔案遷移

此新版本將二進位檔案的儲存空間用量減少了一半。

Overleaf `5.5` 包含線上遷移，讓升級過程中的停機時間降到最低。升級至 Ayakaleaf Pro `v6` 之前，請確認你已在執行最新版的 Overleaf `v5.5`（[5.x.x 版本說明](https://docs.overleaf.com/on-premises/release-notes/release-notes-5.x.x)），並已執行遷移。

請參閱 Overleaf 官方文件中的[完整遷移說明](https://docs.overleaf.com/on-premises/release-notes/release-notes-5.x.x/binary-files-migration)。

### MongoDB 升級至 v8

此版本將 MongoDB 最低版本提高至 `8.0`。

若你目前使用 MongoDB `v6` 或更早版本，需要一次升級一個主要版本（`v6 → v7 → v8`）。

<Warning>

請務必在升級**之前**備份[資料庫](/zh-Hant/on-premises/maintenance/data-and-backups)。若需要回復，你必須還原資料庫備份。

</Warning>

關於如何將 MongoDB 從 `v6 → v7 → v8` 升級，請參閱[這裡](/zh-Hant/on-premises/maintenance/updating-mongodb#upgrading-mongodb)的逐步指南。

### Redis 升級至 v7.4

此版本也將 Redis 最低版本提高至 `7.4`。

將 `config/overleaf.rc` 中的 `REDIS_IMAGE` 更新為 `REDIS_IMAGE=7.4`。

### 新功能

* 現在可以使用 `OVERLEAF_DISABLE_LINK_SHARING=true` 停用連結分享。
* 現在可使用 `OVERLEAF_MAINTENANCE_MESSAGE` 與 `OVERLEAF_MAINTENANCE_MESSAGE_HTML` 自訂維護頁面的標題與內容。
* 可設定 `OVERLEAF_USER_HARD_DELETION_DELAY` 與 `OVERLEAF_PROJECT_HARD_DELETION_DELAY`（以毫秒為單位），以調整已刪除使用者／專案的到期延遲時間（預設為 90 天）。

### 錯誤修正

* 修正含連結之頁尾的呈現問題。
* 改善 SAML 登入錯誤時的錯誤訊息。
* 修正透過 SSO 登入更新使用者管理員狀態時，未新增稽核日誌項目的問題。
* 修正 Redis 啟用 TLS 時歷史記錄面板發生錯誤的問題。
* 使用非沙箱編譯時，現在可以停止編譯。

### 其他變更

* 所有指向狀態頁面（透過 `OVERLEAF_STATUS_PAGE_URL` 設定）的連結現在都使用 `HTTPS`，並在新的瀏覽器分頁中開啟。
