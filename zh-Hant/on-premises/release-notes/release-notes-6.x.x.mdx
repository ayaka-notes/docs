<Accordion title="現有安裝的 Zotero／Mendeley 遷移">

升級至重新發布的 6.3.0 映像檔時，請使用下方指令碼遷移現有的 Zotero／Mendeley 連結參考文獻中繼資料。此遷移搭配修正 `12031b8dfd`。

此遷移會將 `zoteroGroupId`／`mendeleyGroupId` 重新命名為 `group_id`、將 `importedByUserId` 重新命名為 `importer_id`，並移除 `importedByName`。

執行遷移前，請先備份 MongoDB 並停止應用程式。保持 MongoDB 執行中，並開啟其 shell（將 `mongo` 替換為你的容器名稱）：

```bash
docker exec -it mongo mongosh
```

在 `mongosh` 中執行下列內容（將 `sharelatex` 替換為你的資料庫名稱）：

```javascript
use sharelatex

(async () => {
  let updated = 0
  await db.projects.find({}, { rootFolder: 1 }).forEach(async project => {
    const changes = {}
    function visit(folders, path) {
      for (const [i, folder] of (folders || []).entries()) {
        const folderPath = `${path}.${i}`
        for (const [j, file] of (folder.fileRefs || []).entries()) {
          const data = { ...file.linkedFileData }
          if (!["zotero", "mendeley"].includes(data.provider)) continue
          const groupKey = `${data.provider}GroupId`
          if (![groupKey, "importedByUserId", "importedByName"].some(key => key in data)) continue
          for (const [oldKey, newKey] of [[groupKey, "group_id"], ["importedByUserId", "importer_id"]]) {
            if (data[oldKey] != null && data[oldKey] !== "") {
              const value = String(data[oldKey])
              if (newKey in data && data[newKey] !== value) {
                throw new Error(`Conflicting ${newKey}: project ${project._id}, file ${file._id}`)
              }
              data[newKey] = value
            }
            delete data[oldKey]
          }
          delete data.importedByName
          changes[`${folderPath}.fileRefs.${j}.linkedFileData`] = data
        }
        visit(folder.folders, `${folderPath}.folders`)
      }
    }
    visit(project.rootFolder, "rootFolder")
    if (!Object.keys(changes).length) return
    const result = await db.projects.updateOne(
      { _id: project._id, rootFolder: { $eq: project.rootFolder } },
      { $set: changes }
    )
    if (!result.matchedCount) throw new Error(`Project changed during migration: ${project._id}`)
    updated += result.modifiedCount
  })
  print(`Updated ${updated} project(s).`)
})()
```

此指令碼會處理巢狀資料夾，且只會變更 Zotero／Mendeley 中繼資料。重複執行是安全的：已完成的遷移在下次執行時會回報 `Updated 0 project(s).`。若因衝突而中止，請檢查所回報的專案／檔案；先前的專案可能已完成遷移。

啟動更新後的應用程式，重新載入編輯器，並以原始匯入者的身分重新整理現有的參考文獻檔案。歷史快照不會被改寫。若要降級回舊版應用程式，請還原 MongoDB 備份。

我們非常自豪地宣布推出 Overleaf Pro 6.3.0——社群中功能最強大、最豐富的線上 LaTeX 編輯器。我們始終致力於提升使用者體驗，此版本帶來重大變革與你一定會喜愛的精彩功能，包括 AI 助理與第三方參考文獻整合。

### 變更

* AI 聊天助理：直接在編輯器中，透過你自己的供應商與 AI 模型對話。
* LaTeX 錯誤助理：取得 AI 針對 LaTeX 編譯錯誤建議的修正方式。
* Mendeley 整合：與 Zotero 類似，可從 Mendeley 匯入參考文獻。
* Open in Overleaf API：新增可在 Overleaf 中開啟內容的 API。
* 範本庫：新增伺服器端分頁、搜尋與排序，大型範本庫不再需要在瀏覽器中載入所有範本。
* 翻譯：更新 6.3.0 的翻譯修補，包括各支援語言的新介面文字。
* 上游 Overleaf 6.3.0：包括分頁式檔案編輯、淺色與深色主題各自的頁首標誌，以及相依套件與基礎映像檔更新。
* 新增 `OVERLEAF_HEADER_IMAGE_URL_LIGHT` 與 `OVERLEAF_HEADER_IMAGE_URL_DARK`，支援淺色與深色主題使用不同的頁首標誌圖片。
* 現在可以在編輯器的不同分頁中開啟檔案。
* 新增透過 `OVERLEAF_LINKED_URL_OUTBOUND_PROXY` 設定 HTTP(S) 代理（包括本機託管的代理）的支援，Open in Overleaf API 也會使用此設定。

#### 功能 04：範本分頁

範本庫現在會在 MongoDB 中進行分頁、排序與搜尋。無需任何準備即可運作；若有數千個範本，你仍可加入下列索引以維持速度（可安全地重複執行，`mongo`／`sharelatex` 分別為你的容器與資料庫名稱）：

```bash
docker exec mongo mongosh sharelatex --quiet --eval '
db.templates.createIndex({category:1,lastUpdated:-1},{name:"category_1_lastUpdated_-1",background:true});
db.templates.createIndex({lastUpdated:-1},{name:"lastUpdated_-1",background:true});
db.templates.createIndex({category:1,name:1},{name:"category_1_name_1_ci",collation:{locale:"en",strength:2},background:true});
db.templates.createIndex({name:1},{name:"name_1_ci",collation:{locale:"en",strength:2},background:true});
'
```

請保留兩個 `*_ci` 索引上的 `collation` 設定，不要更動——範本庫查詢使用相同的 collation，而 MongoDB 只會使用相符的索引。

## Ayakaleaf Pro 6.2.2

<strong>發布日期：</strong> 2026.07.23

請參閱：[https://github.com/ayaka-notes/ayakaleaf-pro/releases/tag/pro-v6.2.2](https://github.com/ayaka-notes/ayakaleaf-pro/releases/tag/pro-v6.2.2)

### 變更

向後移植上游 Overleaf `6.2.2` 所提供的官方緊急修補（以 `6.2.1` 為基礎）：

* 修正專案邀請權杖密鑰洩漏到日誌的問題。邀請權杖加密器在每次加密／解密時都會記錄自身設定，其中包含由 `OVERLEAF_INVITE_TOKEN_SECRET` 衍生的加密密碼。
* 將外寄郵件從已終止支援的 AWS SES v1 用戶端遷移至 SESv2。設定使用 `ses` 郵件驅動程式的執行個體先前可能完全無法寄送郵件；現在改由 `SESv2Client` 寄送。
* 將分享專案下拉選單中的群組項目置於新的 `group-link-sharing` 功能旗標之後，讓不適用群組連結分享的執行個體不再提供此選項。
* 修正協作者的分享專案對話框。以非擁有者身分開啟，或在停用 `sharing-updates` 流程時開啟，會發出一個必定失敗的請求，並顯示「something went wrong」錯誤。
* 在 document-updater 中新增 `scripts/flush_docs_with_pending_updates.js`，這是一個維護指令碼，用於復原專案被清空或永久刪除後，在 Redis 中留下卡住 `PendingUpdates` 佇列的文件。支援 `--dry-run` 與 `--estimated-docs` 安全檢查。
* 更新相依套件： `multer` 2.2.0, `form-data` 2.5.6, `protobufjs` 7.6.3, `@grpc/grpc-js` 1.14.4.

此版本也包含下列來自 Ayakaleaf Pro 的修正與改進：

* 新增 16 種語言（cs、da、de、es、fi、fr、it、ja、ko、nl、no、pl、pt、ru、sv、tr）的完整翻譯，修正密碼重設頁面等未翻譯的字串。修正 [#38](https://github.com/ayaka-notes/ayakaleaf-pro/issues/38).
* 修正管理面板中「show N more projects」按鈕的項目數量，先前因複數預留位置未正確傳遞而顯示錯誤的數字。
* 修正 GitHub 匯出驗證錯誤，現在改以靜態 i18n 鍵而非原始訊息呈現，並移除 GitHub 同步對話框不再使用的錯誤鍵。

## Ayakaleaf Pro 6.2.0

<strong>發布日期：</strong> 2026.07.10

請參閱：[https://github.com/ayaka-notes/ayakaleaf-pro/releases/tag/pro-v6.2.0](https://github.com/ayaka-notes/ayakaleaf-pro/releases/tag/pro-v6.2.0)

我們自豪地宣布推出 Overleaf Pro 6.2.0——社群中功能最強大、最豐富的線上 LaTeX 編輯器。特別感謝 yu-i-i 與 davrot 的寶貴貢獻，他們強化了 GitHub 同步，並推出了進階引用搜尋與 Zotero 整合。

### 注意事項

<Warning>

* 新增必要的環境變數 `OVERLEAF_INVITE_TOKEN_SECRET`。你必須使用 `openssl rand -base64 32` 產生它。若未設定，Overleaf 執行個體將無法啟動。
* 若啟用 GitHub 同步，你必須設定 `GITHUB_TOKEN_CIPHER_PASSWORD` 環境變數。此變數用於安全地加密 GitHub 存取權杖。若未設定，Overleaf 執行個體將無法啟動。

</Warning>

* 新增 `DEFAULT_LATEX_COMPILER` 環境變數，用於設定新專案預設使用的編譯器（`pdflatex`、`latex`、`xelatex` 或 `lualatex`）。
* 重新設計的編輯器現在是唯一可用的選項。

### 變更

此版本包含下列改進與新功能。

* `MAX_UPLOAD_SIZE` 現在可以自行設定，不再限制為 **50 MB**。
* 修正停用沙箱編譯時容器不斷重新啟動的問題。
* 強制 OAuth2 的 PAT 刪除僅限擁有者範圍。
* 修正 LDAP 匯入問題。

功能包括：

* 新增以瀏覽器為基礎的 Python 執行器。
* 新增 Pandoc 支援，可匯入與匯出 Markdown、DOCX 及其他格式。
* 新增 GitHub 同步。
* 新增完整的中文翻譯。
* 新增 Zotero 整合。
* 新增 `DEFAULT_LATEX_COMPILER`。

## Ayakaleaf Pro 6.0.0

<strong>發布日期：</strong> 2026.02.17

測試版本，請參閱：[https://github.com/ayaka-notes/ayakaleaf-pro/releases/tag/pro-v6.0.0](https://github.com/ayaka-notes/ayakaleaf-pro/releases/tag/pro-v6.0.0)

這是一個測試版本，也是 Overleaf Pro 的初始版本。此版本不包含任何 Server Pro 的功能，因此僅作為我們的起點。我們之後會加入新功能，例如管理面板與 git-bridge 等。

在此版本中，我們推出了 ARM 版的 Overleaf Docker 映像檔。若你有 Mac 或 ARM 架構伺服器，可以試用看看，但部分功能可能無法正常運作（尚未測試）。

### Docker 映像檔

你可以在這裡找到 Docker 映像檔： [https://github.com/ayaka-notes/overleaf-pro/pkgs/container/overleaf-pro](https://github.com/ayaka-notes/overleaf-pro/pkgs/container/overleaf-pro)

多架構映像檔請參閱[這裡](https://github.com/ayaka-notes/overleaf-pro/pkgs/container/overleaf-pro/691283454?tag=6.0.0).

```bash
docker pull ghcr.io/ayaka-notes/overleaf-pro:6.0.0
```

### 二進位檔案遷移

此新版本將二進位檔案的儲存空間用量減少了一半。

`5.5` 版本包含線上遷移，讓升級過程中的停機時間降到最低。升級至 Server Pro `v6` 之前，請確認你已在執行最新版的 Server Pro `v5.5`（[5.x.x 版本說明](https://docs.overleaf.com/on-premises/release-notes/release-notes-5.x.x)），並已執行遷移。

[查看完整的遷移說明](https://docs.overleaf.com/on-premises/release-notes/release-notes-5.x.x/binary-files-migration).

### MongoDB 升級至 v8

此版本將 MongoDB 最低版本提高至 `8.0`。

若你目前使用 MongoDB `v6` 或更早版本，需要一次升級一個主要版本（`v6 → v7 → v8`）。

<Warning>

請務必在升級**之前**備份[資料庫](https://docs.overleaf.com/on-premises/maintenance/data-and-backups)。若需要回復，你必須還原資料庫備份。

</Warning>

關於如何將 MongoDB 從 `v6 → v7 → v8` 升級，請參閱[這裡](https://docs.overleaf.com/on-premises/maintenance/updating-mongodb#example-upgrading-mongodb-from-6.0-to-7.0-toolkit-users)的逐步指南。

### Redis 升級至 v7.4

此版本也將 Redis 最低版本提高至 `7.4`。

將 `config/overleaf.rc` 中的 `REDIS_IMAGE` 更新為 `REDIS_IMAGE=7.4`。

### 新功能

* 現在可以使用 `OVERLEAF_DISABLE_LINK_SHARING=true` 停用連結分享。
* 現在可使用 `OVERLEAF_MAINTENANCE_MESSAGE` 與 `OVERLEAF_MAINTENANCE_MESSAGE_HTML` 自訂維護頁面的標題與內容。
* 可設定 `OVERLEAF_USER_HARD_DELETION_DELAY` 與 `OVERLEAF_PROJECT_HARD_DELETION_DELAY`（以毫秒為單位），以調整已刪除使用者／專案的到期延遲時間（預設為 90 天）。

### 錯誤修正

* 修正含連結之頁尾的呈現問題。
* 改善 SAML 登入錯誤時的錯誤訊息。
* 修正透過 SSO 登入更新使用者管理員狀態時，未新增稽核日誌項目的問題。
* 修正 Redis 啟用 TLS 時歷史記錄面板發生錯誤的問題。
* 使用非沙箱編譯時，現在可以停止編譯。

### 其他變更

* 所有指向狀態頁面（透過 `OVERLEAF_STATUS_PAGE_URL` 設定）的連結現在都使用 `HTTPS`，並在新的瀏覽器分頁中開啟。
