#### 服務

Overleaf Pro 基礎架構由四個主要服務組成：`sharelatex`、`git-bridge`（選用）、`mongo` 與 `redis`。執行 Server Pro 主應用程式的 `sharelatex` 服務，依賴 `mongo` 與 `redis` 服務提供資料庫及快取／即時功能，並依賴 `git-bridge` 處理 [Git 整合](/zh-Hant/on-premises/configuration/overleaf-toolkit/git-integration)（選用）。主機上唯一對外公開的連接埠是 80 埠，由 `sharelatex` 容器使用。

Server Pro 也可選擇性地支援以 [S3 相容儲存空間](/zh-Hant/on-premises/configuration/overleaf-toolkit/s3)存放專案檔案與完整專案歷史，並且能代理存取 [Overleaf 主要說明文件網站arrow-up-right](https://www.overleaf.com/learn)。詳細資訊請參閱我們的[新增 LaTeX 使用者說明](/zh-Hant/on-premises/configuration/overleaf-toolkit/adding-latex-user-help)頁面指南。

<Info>

如有需要，可以透過環境變數將 MongoDB 與 Redis 指向外部服務。詳細資訊請參閱[設定 Overleaf](/zh-Hant/on-premises/configuration)（若您使用 Docker Compose）以及 [Toolkit 設定](/zh-Hant/on-premises/configuration/overleaf-toolkit/toolkit-settings)（若您使用 Overleaf Toolkit）。

</Info>

#### 編譯

對於[沙箱編譯](/zh-Hant/on-premises/configuration/overleaf-toolkit/sandboxed-compiles)，`sharelatex` 容器會透過主機上的 Docker socket，協調建立新的容器來處理專案編譯。您可以在[這裡](/zh-Hant/on-premises/getting-started/microservices#editor-and-compile-process)進一步了解編輯器以及端對端的編譯／快取流程。

#### 網路

容器之間的通訊是透過專用的橋接網路，藉由 Docker 內部的 DNS 解析來進行，且未啟用任何防火牆。預設情況下，上述服務使用各自的標準連接埠，但可透過環境變數進行設定。`sharelatex` 容器使用 80 埠提供外部網頁存取（由 Nginx 提供服務），`mongo` 容器使用 27017 埠，`redis` 則使用 6379 埠。

對於使用我們管理解決方案 [Overleaf Toolkitarrow-up-right](https://github.com/overleaf/toolkit) 的客戶，可以選擇透過環境變數[啟用 TLS 代理](/zh-Hant/on-premises/configuration/overleaf-toolkit/tls-proxy)，使用 Nginx 終止 HTTPS 連線。或者，您也可以使用現有的 TLS 代理。

<Info>

您可以在[這裡](/zh-Hant/on-premises/configuration/overleaf-toolkit/tls-proxy)查看說明請求流程的圖表。

</Info>

#### 摘要

* 在 Docker 網路之外，只有 80 埠可供存取，並綁定至 Nginx。**注意：**`sharelatex` 容器中執行了許多透過 HTTP 互相通訊的[服務arrow-up-right](https://github.com/overleaf/overleaf/tree/main/services)。不過，這些連接埠**無法**從 Docker 網路外部存取。
* 在 Docker 網路內部，Overleaf 服務、MongoDB、Redis 與 Git Bridge 可以自由地互相通訊。
* 在[沙箱編譯](/zh-Hant/on-premises/configuration/overleaf-toolkit/sandboxed-compiles)容器內部，沒有可用的網路。
