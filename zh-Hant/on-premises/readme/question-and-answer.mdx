我們在此彙整了一些關於 Ayakaleaf Pro 的常見問題解答。

### 基本問題

<Accordion title="Q01：Ayakaleaf Pro 是免費試用版嗎？需要授權嗎？">

不是。Ayakaleaf Pro 完全免費使用。它不是試用版，也不需要任何授權。

</Accordion>

<Accordion title="Q02：Ayakaleaf Pro 是否包含 Overleaf Server Pro 的所有功能？">

是的。Ayakaleaf Pro 包含 Overleaf Server Pro 的所有功能，包括 Git-Bridge 整合。它還包含部分 Overleaf SaaS 平台的功能。我們會持續開發並改進 Ayakaleaf Pro。

</Accordion>

<Accordion title="Q03：Overleaf Server Pro 的價格是多少？">

Overleaf Server Pro 每位使用者每年的費用約為 \$300。它至少需要購買 10 個授權，因此部署費用每年約 \$3,000 起。美國規模較小的公開合約顯示，每位使用者每年的費用約為 \$320–\$370。這使得 Server Pro 相當昂貴，尤其是對小型團隊而言。有據可查的採購紀錄與價格請參閱 [#information-and-price-about-overleaf-server-pro](/zh-Hant/on-premises#information-and-price-about-overleaf-server-pro  "mention")。

</Accordion>

<Accordion title="Q04：為什麼 Overleaf Server Pro 不包含 GitHub 同步或 AI 功能？">

Overleaf Server Pro 常被政府機關使用。這些機構會將其部署在私人網路中，並嚴格控管存取權限。為了保護敏感資料，其內建功能會避免與第三方服務交換資料。如果您需要 GitHub 同步、AI 或類似的連網功能，Overleaf 建議您訂閱其 SaaS 平台。

</Accordion>

<Accordion title="Q05：Ayakaleaf Pro 安全可靠嗎？">

Ayakaleaf Pro 是開放原始碼軟體。我們使用 Codex Security 等工具審查程式碼，以強化其安全性與可靠性。如果您未啟用第三方資料同步，您的資料就會保留在您的伺服器上。Ayakaleaf Pro 不包含任何會將您的資料傳送至其他地方的遙測功能。

</Accordion>

<Accordion title="Q06：Ayakaleaf Pro 會長期維護嗎？">

我們會盡一切努力長期維護此專案。

</Accordion>

<Accordion title="Q07：Ayakaleaf Pro 是否合規？">

Ayakaleaf Pro 是一個社群分支（fork）。其程式碼與整合的功能皆來自社群貢獻，並以 AGPL v3 授權發布。只要部署符合該授權的要求，即可遵循此授權規範。

</Accordion>

<Accordion title="Q08：為什麼這個專案叫做 Ayakaleaf Pro？">

此專案最初於 2024 年命名為 Overleaf Pro。開發曾暫停一段時間，並於 2025 年底重新啟動。2026 年第一季，Overleaf 將其具備 AI 功能的訂閱方案更名為 Pro。社群回饋也指出，Overleaf Pro 這個名稱可能帶來商標與冒名的風險，讓使用者誤以為此專案是官方產品。

為了避免這種混淆，我們將專案更名為 Ayakaleaf Pro。這個名稱可以解讀為「Ayaka-notes Overleaf Pro」。維護者（你可以叫我 ayaka！）從五年多前的學生時期就開始參與 Overleaf 社群開發，這份經驗支撐著我們長期維護的承諾。

</Accordion>

<Accordion title="Q09：Ayakaleaf Pro 與較新的 AI 打造 LaTeX 編輯器有何不同？">

自 2026 年以來，開源社群已推出許多以 AI 打造的 LaTeX 編輯器，包括 OpenAI Prism。Ayakaleaf Pro 將您的資料與服務保留在您自己的伺服器上，讓您能直接掌控自己的部署與資料。

許多實驗性的社群編輯器並沒有明確的長期維護計畫。第三方 LaTeX 編譯平台也可能在使用者基礎或營收不足時停止營運。Ayakaleaf Pro 提供全部原始碼，並讓您能自行託管所有服務。即使維護停止，您現有的自行託管服務仍可繼續運作。

</Accordion>

### 功能

<Accordion title="Q01：Ayakaleaf Pro 提供哪些功能？我可以提出新功能需求嗎？">

目前的功能清單請參閱我們的文件。如果有您希望我們新增的功能，歡迎在 GitHub 上開立 issue（功能需求）。我們會盡力實作使用者提出的功能，但開發需要時間，我們無法保證每項功能都能立即推出。

</Accordion>

<Accordion title="Q02：我開發了一些功能，可以提交 PR 嗎？一定會被接受嗎？">

歡迎貢獻，但不保證一定會被接受。我們會根據每個 PR 對底層 Overleaf 程式碼的影響、維護負擔，以及為使用者帶來的價值進行評估。我們會盡力合併並維護有價值的貢獻。

不過，對於變更幅度過大、由未經審查或未被充分理解的 AI 生成程式碼（「vibe coding」）組成，或會新增難以長期維護之功能的 PR，我們可能會予以拒絕。

</Accordion>

<Accordion title="Q03：如何設定特定功能？">

我們通常會在推出新功能時同步更新文件。詳細的設定說明與可用環境變數的解釋，請參閱相關文件。

</Accordion>

<Accordion title="Q04：Python Runner 可以使用哪些 Python 函式庫？">

Python Runner 是在使用者的瀏覽器中以 [Pyodide](https://pyodide.org/) 0.29.3 執行 Python，而非在伺服器上執行。它會從 [Pyodide 內建的套件](https://pyodide.org/en/0.29.3/usage/packages-in-pyodide.html)中載入您程式碼所匯入的套件，例如 NumPy、pandas 與 Matplotlib。以 `pip` 安裝的套件及其他套件無法使用。伺服器上不需要進行任何設定。

</Accordion>

<Accordion title="Q05：拼字檢查可以檢查日文或中文嗎？">

不行。拼字檢查器沒有日文或中文的字典，因此這些語言不在拼字檢查的語言清單中。使用者可以在編輯器設定中為專案關閉拼字檢查。

</Accordion>

### 部署

<Accordion title="Q01：Ayakaleaf Pro 是否支援在 k8s 中進行分散式部署？">

對大多數使用者而言，我們建議使用 [Toolkit](/zh-Hant/on-premises/installation/using-the-toolkit) 進行部署。我們不建議使用 Kubernetes 或類似平台進行大規模叢集部署，因為這可能會大幅增加營運複雜度與維護工作量。

</Accordion>

<Accordion title="Q02：在服務數千名使用者時，如何確保可用性？">

請參閱我們的[水平擴展](/zh-Hant/on-premises/maintenance/horizontal-scaling)指南。您可以部署多個 Overleaf 執行個體，並設定負載平衡器將流量分散至各個執行個體。

</Accordion>

<Accordion title="Q03：你們可以協助我部署或遷移嗎？">

如果您已有 Overleaf Server Pro 執行個體，我們很樂意協助您遷移至 Ayakaleaf Pro。請透過電子郵件或 issue 與我們聯絡。

</Accordion>

<Accordion title="Q04：可以將 Ayakaleaf Pro 架設在 URL 子路徑下嗎，例如 `https://example.com/overleaf`？">

不行。Ayakaleaf Pro 必須從網域的根路徑提供服務。請使用專用的網域或子網域，例如 `https://overleaf.example.com`。

</Accordion>

<Accordion title="Q05：可以在 Windows 或 macOS 上執行 Ayakaleaf Pro，或不使用 Toolkit 嗎？">

我們支援搭配 [Toolkit](/zh-Hant/on-premises/installation/using-the-toolkit) 的 Linux 伺服器。Windows、WSL2 或 macOS 上的 Docker Desktop 或許可行，但我們並未進行測試，已知的 MongoDB 問題請參閱[疑難排解](/zh-Hant/on-premises/support/troubleshooting)。

我們不提供獨立的 `docker-compose.yml`。若要查看 Toolkit 所使用的 Compose 設定，請在 Toolkit 目錄中執行 `bin/docker-compose config`。

</Accordion>

<Accordion title="Q06：如何解除安裝 Ayakaleaf Pro？">

沒有解除安裝腳本。請在 Toolkit 目錄中：

1. 使用 `bin/docker-compose down` 停止並移除容器。
2. 刪除資料。預設情況下，資料位於 Toolkit 的 `data/` 目錄中。若您在 `config/overleaf.rc` 中變更過 `OVERLEAF_DATA_PATH`、`MONGO_DATA_PATH`、`REDIS_DATA_PATH` 或 `GIT_BRIDGE_DATA_PATH`，也請刪除這些目錄。此操作無法復原，因此若您之後可能需要這些資料，請先進行[備份](/zh-Hant/on-premises/maintenance/data-and-backups)。
3. 刪除 Toolkit 目錄。
4. 移除 Docker 映像檔（可使用 `docker images` 列出）：`ghcr.io/ayaka-notes/overleaf-pro`、git-bridge 映像檔、`mongo`、`redis` 以及 TeX Live 映像檔。

</Accordion>

<Accordion title="Q07：如何停止、啟動或重新啟動 Ayakaleaf Pro？">

請在 Toolkit 目錄中執行以下指令：

* `bin/stop` 會停止所有容器，`bin/start` 會重新啟動它們。容器會被保留，因此使用者會維持登入狀態。
* `bin/up -d` 會建立容器並在背景啟動。請在變更 `config/variables.env`、`config/overleaf.rc` 或 `config/version` 後執行：它會重新建立設定有所變更的容器，變更也只有在此時才會生效。`bin/stop` 與 `bin/start` 不會套用這些變更。
* `bin/docker-compose restart sharelatex` 只會重新啟動 Overleaf 容器，不會套用設定變更。

若每次 `bin/up` 重新建立容器時使用者都會被登出，請設定 `OVERLEAF_SESSION_SECRET`，請參閱[環境變數](/zh-Hant/on-premises/configuration/overleaf-toolkit/environment-variables)中的問與答。

</Accordion>

<Accordion title="Q08：OAuth 回呼 URL 應該填在哪裡？">

填在您於服務供應商處建立的應用程式中，而非 Ayakaleaf Pro 中。對於下列任何整合，`config/variables.env` 中都沒有回呼設定：Ayakaleaf Pro 會根據 `OVERLEAF_SITE_URL` 組成每個回呼 URL 並傳送給服務供應商，若該 URL 與應用程式所註冊的 URL 不符，服務供應商就會拒絕。因此，您只需要在服務供應商處註冊此 URL，並將 `OVERLEAF_SITE_URL` 設為使用者開啟的位址即可。

| 整合 | 服務供應商處的欄位 | 值 |
| --- | --- | --- |
| [GitHub](/zh-Hant/on-premises/configuration/overleaf-toolkit/github-synchronisation) | Authorization callback URL | `${OVERLEAF_SITE_URL}/user/github-sync/oauth2/callback` |
| [GitLab](/zh-Hant/on-premises/configuration/overleaf-toolkit/gitlab-synchronisation) | Redirect URI | `${OVERLEAF_SITE_URL}/user/gitlab-sync/oauth2/callback` |
| [Gitea](/zh-Hant/on-premises/configuration/overleaf-toolkit/gitea-synchronisation) | Redirect URIs | `${OVERLEAF_SITE_URL}/user/gitea-sync/oauth2/callback` |
| [Dropbox](/zh-Hant/on-premises/configuration/overleaf-toolkit/dropbox-synchronisation) | Redirect URIs（點選 **Add**） | `${OVERLEAF_SITE_URL}/user/dropbox/oauth/callback` |
| [Zotero](/zh-Hant/on-premises/configuration/overleaf-toolkit/zotero-integration) | Callback URL | `${OVERLEAF_SITE_URL}/user/zotero/oauth/callback` |
| [Mendeley](/zh-Hant/on-premises/configuration/overleaf-toolkit/mendeley-integration) | Redirect URL | `${OVERLEAF_SITE_URL}/user/mendeley/oauth/callback` |
| [OIDC 登入](/zh-Hant/on-premises/configuration/overleaf-toolkit/authentication/oidc-authentication) | Redirect URI | `${OVERLEAF_SITE_URL}/oidc/login/callback` |
| [SAML 登入](/zh-Hant/on-premises/configuration/overleaf-toolkit/authentication/saml-authentication) | ACS URL（Assertion Consumer Service） | `${OVERLEAF_SITE_URL}/saml/login/callback` |

若您變更了 `OVERLEAF_SITE_URL`（例如改用新網域），也請更新每個服務供應商處的 URL，否則連結將會失敗。

</Accordion>

### LaTeX

<Accordion title="Q01：使用者的 LaTeX 專案編譯是否相互隔離？是否啟用 Shell Escape？">

啟用沙箱編譯（Sandbox Compiles）後，每位使用者的編譯都會在獨立的 Docker 容器中執行，並與其他使用者的編譯相互隔離。沙箱編譯預設啟用 Shell Escape。

</Accordion>

<Accordion title="Q02：沙箱編譯的映像檔可靠嗎？編譯可能會失敗嗎？">

過去三年來，我們持續改進用於沙箱編譯的 TeX Live Full 映像檔。在大多數情況下，能在 overleaf.com 上編譯的專案，也能在 Ayakaleaf Pro 中正確編譯。如果缺少所需的字型，請手動將該字型上傳至您的專案。

</Accordion>

<Accordion title="Q03：我的專案無法編譯，可以協助我排除問題嗎？">

請將您的專案上傳至 Overleaf 官方網站，啟用唯讀連結分享，並在 GitHub issue 中附上該連結。

如果某個專案能在 Overleaf 官方網站上成功編譯，卻無法在 Ayakaleaf Pro 中編譯，我們會調查並修正造成問題的錯誤。超出此範圍的編譯問題不在我們的支援範圍內。

</Accordion>
