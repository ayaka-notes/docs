你自己的帳號標有 **You**，其操作會呈灰色：你無法停用或刪除自己。

## 尋找使用者 {#find-a-user}

在 **Search by name, email or ID** 中輸入內容。也可以輸入全名，例如 `Carol Novak`，搜尋也能透過使用者的任一[次要電子郵件](/zh-Hant/on-premises/user-guide/users/multiple-emails)找到該使用者。若要縮小清單範圍，請使用 **Login**、**Role** 與 **Status** 欄的篩選器。點選 **Name**、**Sign up** 或 **Last logged in** 即可排序。

<Frame caption="搜尋使用者">
  <img src="/images/on-premises/user-management-search.png" alt="依搜尋字詞 carol 篩選後的使用者清單" />
</Frame>

已刪除的帳號不會出現在結果中。如果你的搜尋也符合已刪除的帳號，表格上方會有一行提示，例如 **Found 1 matching deleted users**。點選 **Display deleted users** 即可查看。

<Frame caption="符合已刪除帳號的搜尋">
  <img src="/images/on-premises/user-management-deleted-hint.png" alt="沒有結果的搜尋，以及 Found 1 matching deleted users, Display deleted users 這一行" />
</Frame>

## 使用者狀態 {#user-status}

每個帳號都恰好有一種狀態，**Status** 篩選器會顯示每種狀態的帳號數量。將滑鼠移到問號上即可閱讀其定義。

<Frame caption="Status 篩選器">
  <img src="/images/on-premises/user-management-status-tooltip.png" alt="顯示 Active 提示說明的 Status 篩選器" />
</Frame>

| 狀態 | 意義 | 能否登入 |
| --- | --- | --- |
| **All** | 所有未被刪除的帳號。下列四種狀態（Active + Pending + Inactive + Disabled）加總等於這個數字。 | |
| **Active** | 在過去 12 個月內登入過或開啟過專案。 | 是 |
| **Pending** | 從未登入：通常是管理員建立的帳號，或透過啟用郵件註冊、使用者尚未啟用的帳號。以密碼註冊的帳號不需要啟用，首次登入時即變為 Active。 | 是 |
| **Inactive** | 以前登入過，但在過去 12 個月內沒有登入或開啟專案。 | 是 |
| **Disabled** | 管理員停用了該帳號。登入會進入 **Your account is suspended** 頁面。 | 否 |
| **Deleted user** | 該帳號已被管理員或使用者本人刪除。它不計入 **All**，在你選擇此篩選器之前一直隱藏。登入時會提示電子郵件或密碼不正確。 | 否 |

帳號依下列方式在狀態之間轉換：

* **Pending、Active 與 Inactive** 取決於帳號的使用情況，因此你無法設定它們。使用者一登入，Inactive 帳號就會變為 Active。
* **Enable** 與 **Restore** 不會恢復先前的狀態。狀態取決於最近一次登入：從未登入過的帳號會重新變為 Pending。已停用的帳號在 **Restore** 後仍為 **Disabled**。
* **Delete permanently** 無法復原。除此之外，已刪除的帳號會一直保留，直到你將其移除，除非執行個體設定了 [`ENABLE_CRON_RESOURCE_DELETION`](/zh-Hant/on-premises/configuration/overleaf-toolkit/environment-variables)，該設定會在 90 天後移除它們。

### License 分頁中的活躍使用者 {#active-users-on-the-license-tab}

**License** 分頁與 **Active** 狀態顯示的數字可能不同，因為它們計算的內容不同。**License** 分頁計算 Server Pro 授權所涵蓋的使用者，其定義見 Overleaf 的 [Understanding license usage](https://docs.overleaf.com/on-premises/user-and-project-management/understanding-license-usage)："any user who logs in and accesses a project is considered an active user by the system"，以及 "An active user is defined as someone who has opened a project on your Server Pro instance in the last 12 months."。登入過但沒有開啟任何專案的使用者在清單中為 **Active**，但不計入授權。開啟過專案、之後被停用的使用者計入授權，但在清單中為 **Disabled**。

## 對使用者執行的操作 {#actions-on-a-user}

**Actions** 欄中的圖示與使用者頁面頂端的圖示相同。

| 圖示 | 操作 | 作用 |
| --- | --- | --- |
| 信封 | **Send activation email** | 針對從未登入的帳號：產生新的啟用連結。 |
| 帶箭頭的鎖 | **Send reset link** | 針對已登入過的帳號：產生新的密碼重設連結。 |
| 資料夾 | **Transfer this user's projects** | 將該使用者擁有的所有專案轉給另一位使用者。 |
| 圓圈 | **Disable** | 阻止使用者登入。 |
| 播放 | **Enable** | 允許已停用的使用者重新登入。 |
| 垃圾桶 | **Delete account** | 將帳號移到 **Deleted user**。 |
| 箭頭 | **Restore** | 還原已刪除的帳號。僅適用於已刪除的帳號。 |
| 打叉的垃圾桶 | **Delete permanently** | 永久移除已刪除的帳號。僅適用於已刪除的帳號。 |

每個操作都會在標明該帳號的對話方塊中要求確認。

### 傳送啟用或重設連結 {#send-an-activation-or-reset-link}

依帳號是否登入過，它會顯示這兩個圖示之一。對於已停用的帳號、沒有本機密碼的帳號（例如 SSO 帳號）以及你自己的帳號，該圖示會呈灰色。

點選圖示，再點選同名按鈕。對話方塊會保持開啟並顯示連結：

* **Email Sent** 表示郵件已寄出。
* <strong>No email was sent. Copy the link and pass it on.</strong> 表示未設定[電子郵件寄送](/zh-Hant/on-premises/configuration/overleaf-toolkit/email-delivery)或郵件寄送失敗。點選複製圖示，自行將連結傳給使用者。

啟用連結 7 天後過期，重設連結 1 小時後過期。使用者開啟連結並設定密碼。使用啟用連結後會進入其專案清單，使用重設連結後則需登入。

<Frame caption="未設定電子郵件寄送的執行個體上的重設連結">
  <img src="/images/on-premises/user-management-reset-link.png" alt="Carol Novak 的 Send reset link 對話方塊，顯示未寄出郵件的警告、連結、複製圖示與 Expires in 1 hour" />
</Frame>

### 停用或啟用帳號 {#disable-or-enable-an-account}

點選圓圈圖示，再點選 **Disable**。狀態會變為 **Disabled**，使用者將無法再登入。若要復原，請點選播放圖示，再點選 **Enable**。

<Frame caption="停用帳號">
  <img src="/images/on-premises/user-management-disable.png" alt="標明 Dave Okafor 的 Disable 對話方塊" />
</Frame>

### 轉移使用者的專案 {#transfer-a-user’s-projects}

點選資料夾圖示。在 **Select a new owner for this user's projects** 下輸入名稱或電子郵件，選擇使用者，再點選 **Transfer this user's projects**。這些專案的 **Owner** 會在[專案管理](/on-premises/user-guide/administrators/project-management)中變更。

已停用的帳號不會列為新擁有者的選項。如果選擇後又修改文字，選擇會被取消：請重新選擇使用者。

<Frame caption="轉移使用者的所有專案">
  <img src="/images/on-premises/user-management-transfer.png" alt="已選擇 Carol Novak 為新擁有者的轉移對話方塊" />
</Frame>

### 刪除帳號 {#delete-an-account}

點選垃圾桶圖示。有兩個選項可用，預設都不勾選：

* **Notify the user about the account deletion** 會寄一封郵件給使用者。
* **Transfer this user's projects** 讓你先為專案選擇新的擁有者。專案在新擁有者名下保持活躍。

點選 **Delete account**。如果不轉移專案，專案會隨帳號一起刪除，並進入[專案管理](/on-premises/user-guide/administrators/project-management#project-status)中的 **Deleted** 狀態。

<Frame caption="刪除帳號並轉移其專案">
  <img src="/images/on-premises/user-management-delete.png" alt="勾選兩個選項並選擇了新擁有者的 Delete account 對話方塊" />
</Frame>

### 還原或永久刪除帳號 {#restore-or-permanently-delete-an-account}

在 **Status** 篩選器中選擇 **Deleted user**，或在搜尋後點選 **Display deleted users**。

<Frame caption="已刪除的帳號">
  <img src="/images/on-premises/user-management-deleted-list.png" alt="已刪除使用者清單，附有 Restore 與 Delete permanently 圖示" />
</Frame>

* **Restore** 會還原該帳號。已停用的帳號仍維持停用。隨帳號一起刪除的專案也會還原，每個專案名稱的結尾會加上 `(Restored)`。使用者自己刪除的專案仍維持刪除狀態。
* **Delete permanently** 會移除該帳號。對話方塊會警告此操作無法復原。

<Frame caption="永久刪除帳號">
  <img src="/images/on-premises/user-management-purge.png" alt="警告操作無法復原的 Delete permanently 對話方塊" />
</Frame>

### 一次變更多個帳號 {#change-several-accounts-at-once}

在清單中勾選帳號。**Create account** 旁會出現按鈕：**Send activation email**、**Transfer this user's projects**、**Disable**、**Enable**、**Make admin**、**Remove admin** 與 **Delete account**。清單底部會顯示已選取的帳號數量。在你確認之前，對話方塊會列出這些帳號。

<Frame caption="批次操作">
  <img src="/images/on-premises/user-management-bulk.png" alt="勾選了兩個帳號，清單上方顯示批次操作按鈕，信封按鈕呈灰色" />
</Frame>

除非所有勾選的帳號都是 **Pending**，否則 **Send activation email** 會呈灰色。此時對話方塊會為每個帳號顯示一個連結。沒有批次重設連結。

<Frame caption="每個帳號一個啟用連結">
  <img src="/images/on-premises/user-management-bulk-links.png" alt="Send activation email 對話方塊，顯示 Hana Ito 與 Erin Silva 各自的連結以及 Expires in 7 days" />
</Frame>

## 使用者頁面 {#the-user-page}

點選使用者的名稱即可開啟其頁面。該頁面有六個分頁。

### Account {#account}

帳號的詳細資料。若要變更，請點選鉛筆圖示，編輯欄位，再點選 **Save**。你可以變更電子郵件、名稱與密碼，並開啟或關閉 **Admin**。

如果使用者新增了[更多電子郵件](/zh-Hant/on-premises/user-guide/users/multiple-emails)，它們會列在 **Emails** 下。編輯時，**Remove** 會將次要電子郵件從帳號移除，之後其他帳號就可以使用該地址。

<Frame caption="有兩個電子郵件的帳號">
  <img src="/images/on-premises/user-management-secondary-email.png" alt="正在編輯的 Account 分頁，包含一個主要電子郵件與一個附 Remove 按鈕的次要電子郵件" />
</Frame>

初始設定中的[密碼規則](/zh-Hant/on-premises/user-guide/administrators/onboarding#create-the-administrator-account)同樣適用。如何將密碼交給使用者由你決定。若要讓使用者自行設定，請改為[傳送重設連結](/zh-Hant/on-premises/user-guide/administrators/user-management#send-an-activation-or-reset-link)。

<Frame caption="編輯帳號">
  <img src="/images/on-premises/user-management-edit.png" alt="處於編輯模式的 Account 分頁" />
</Frame>

### Projects {#projects}

該使用者擁有的專案，搜尋、**Status** 篩選器與操作都與[專案管理](/on-premises/user-guide/administrators/project-management)中相同。

<Frame caption="使用者的專案">
  <img src="/images/on-premises/user-management-projects.png" alt="使用者的 Projects 分頁" />
</Frame>

### Features {#features}

該帳號啟用的功能：協作、編譯逾時、整合與 AI。若要變更，請點選鉛筆圖示，更改數值，再點選 **Save**。對於 **Collaborators per project**，`-1` 表示不限。**Compile timeout** 以秒為單位，範圍為 1 到 600。

在你自己的帳號上，鉛筆圖示與 **AI usage** 的 **Reset** 會呈灰色。在 **Account** 分頁中，你仍可以變更自己的電子郵件、名稱與密碼。

<Frame caption="使用者的功能">
  <img src="/images/on-premises/user-management-features.png" alt="處於編輯模式的 Features 分頁" />
</Frame>

### Integrations {#integrations}

使用者的 Git 存取權杖以及其連結的帳號。此分頁為唯讀。

<Frame caption="使用者的整合">
  <img src="/images/on-premises/user-management-integrations.png" alt="Integrations 分頁，其中 GitHub、GitLab 與 Gitea 被勾選為已連結" />
</Frame>

### Audit logs {#audit-logs}

該帳號發生過的事：日期、操作、執行者、IP 位址與詳細資料。可以搜尋，或依 **Operation** 篩選。你對帳號執行的操作會以你為發起者顯示在這裡。

<Frame caption="使用者的稽核記錄">
  <img src="/images/on-premises/user-management-audit.png" alt="Audit logs 分頁，列出使用者的登入記錄與管理員所做的功能變更" />
</Frame>

### Sessions {#sessions}

使用者在哪些地方處於登入狀態。點選 **Clear sessions** 並確認，即可讓其在所有地方登出。之後該分頁會顯示 **Sessions cleared**。
