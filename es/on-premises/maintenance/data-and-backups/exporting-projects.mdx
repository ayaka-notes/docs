---
title: Exportar proyectos
icon: file-export
---

En Server Pro y Community Edition `5.4.0` hemos incluido un script que permite a los administradores exportar todos los proyectos de los usuarios (incluidos los que todavía aparecen en las carpetas **Deleted** y **Trashed**) a un directorio en disco.

<Info>

El resultado de ejecutar este script es el mismo que descargar manualmente un Zip de todos los proyectos desde el panel de proyectos del usuario. El script aplicará cualquier cambio pendiente antes de iniciar la descarga para garantizar que la exportación contenga la última versión del proyecto.

</Info>

### Limitaciones

El script de exportación tiene las siguientes limitaciones:

* No se exporta ninguna configuración del proyecto, como el nombre de la imagen de TeX Live o el compilador. Estos ajustes deben configurarse cuando el proyecto se suba a la cuenta del usuario.
* Los proyectos exportados no contienen historial de versiones.
* No se conserva la información de los colaboradores. Los proyectos tendrán que volver a compartirse. Si se usa el uso compartido mediante enlace, los enlaces de visualización y edición se regenerarán (no serán los mismos que antes).
* No se exportarán los comentarios ni la información de control de cambios.
* No se exportará el historial del chat del proyecto.

<Danger>

Este script **no** está diseñado para sustituir una copia de seguridad completa del sistema. Para asegurarte de poder recuperar tu instancia en un escenario de recuperación ante desastres, te recomendamos **encarecidamente** realizar una [copia de seguridad consistente](https://docs.overleaf.com/on-premises/maintenance/#performing-a-consistent-backup).

</Danger>

### **Opciones**

| Nombre         | Descripción                                                                            |
| -------------- | -------------------------------------------------------------------------------------- |
| `--help`       | Muestra la ayuda                                                                       |
| `--user-id`    | El ID del usuario (obligatorio salvo que se use `--export-all` o `--project-id`)       |
| `--project-id` | Exporta un único proyecto (**no** se puede usar con `--user-id` ni `--export-all`)     |
| `--list`       | Lista los proyectos del usuario (**no** se puede usar con `--output`)                  |
| `--output`     | Archivo zip de salida (para operaciones de exportación individuales)                   |
| `--export-all` | Exporta los proyectos de todos los usuarios (requiere `--output-dir`)                  |
| `--output-dir` | Directorio donde se almacenan los archivos exportados de todos los usuarios            |
| `--log-level`  | Niveles de registro admitidos: `trace`\|`debug`\|`info`\|`warn`\|`error`\|`fatal`      |

### **Uso**

Usa el siguiente comando para exportar los proyectos de todos los usuarios:

```bash wrap
# Overleaf Toolkit users
$ bin/docker-compose exec sharelatex /bin/bash -ce "cd /overleaf/services/web && node modules/server-ce-scripts/scripts/export-user-projects.mjs --export-all --output-dir=/var/lib/overleaf/data/exports"

# Legacy docker-compose.yml users
docker exec sharelatex /bin/bash -ce "cd /overleaf/services/web && node modules/server-ce-scripts/scripts/export-user-projects.mjs --export-all --output-dir=/var/lib/overleaf/data/exports"
```

<Info>

Si ejecutas Server Pro o Community Edition &lt;= 3.5.13, tendrás que adaptar el ejemplo anterior para usar el script **`export-legacy-user-projects.js`**.

</Info>

### **Finalización**

Una vez completada la exportación, puedes acceder a los archivos a través del directorio del host montado (bind mount) en <strong>/var/lib/overleaf</strong> en tu archivo **docker-compose.yml**, o mediante la variable de entorno `OVERLEAF_DATA_PATH` del archivo **config/overleaf.rc** si usas el Toolkit.

<Info>

Actualmente Overleaf permite nombres de proyecto duplicados. Si un usuario tiene proyectos con nombres duplicados, se añadirán igualmente a su exportación Zip, pero al extraerla solo estará presente una versión. En Linux, `unzip -B` escribirá los archivos con el mismo nombre como archivos de copia de seguridad en lugar de sobrescribirlos.

</Info>
