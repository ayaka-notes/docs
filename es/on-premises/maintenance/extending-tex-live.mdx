Es posible ampliar una imagen de TeX Live existente mediante un nuevo Dockerfile y configurar la aplicación para que use la nueva imagen.

Aquí ofrecemos algunas pautas para instalar nuevos paquetes o fuentes, pero la configuración de una imagen personalizada no está cubierta por nuestras condiciones de soporte.

Las imágenes de TeX Live se actualizan con poca frecuencia. Te sugerimos reconstruir las imágenes personalizadas al actualizar Server Pro.

<Danger>

Las siguientes secciones se aplican solo a Server Pro y a [Sandboxed Compiles](/es/on-premises/configuration/overleaf-toolkit/sandboxed-compiles).

</Danger>

### Instalar y actualizar paquetes

Puedes usar comandos de `tlmgr` como `tlmgr install` y `tlmgr update` para gestionar los paquetes de TeX Live, como en el siguiente ejemplo:

```dockerfile
FROM ghcr.io/ayaka-notes/texlive-full:2023.1

RUN tlmgr update --force ebproof
```

### Usar `tlmgr` en una imagen antigua de TeX Live

De forma predeterminada, `tlmgr` descarga los recursos de la última versión de TeX Live. Al parchear una imagen antigua de TeX Live, hay que cambiar las descargas al archivo histórico correspondiente. Consulta la lista en [https://www.tug.org/historic/](https://www.tug.org/historic/) para ver los mirrors de los archivos históricos.

```dockerfile
FROM ghcr.io/ayaka-notes/texlive-full:2022.1

RUN tlmgr option repository <MIRROR>/systems/texlive/<YEAR>/tlnet-final
# e.g. RUN tlmgr option repository ftp://tug.org/historic/systems/texlive/2022/tlnet-final

RUN tlmgr update --force ebproof
```

### Instalar nuevas fuentes

Existen distintos procedimientos para instalar nuevas fuentes en una distribución de TeX Live, e instalar una fuente personalizada puede requerir varios pasos. Consultar las [instrucciones para instalar fuentes TeX](https://tug.org/fonts/fontinstall.html) en la documentación oficial de TeX Live es probablemente un buen punto de partida.

El siguiente `Dockerfile` muestra un ejemplo de instalación de una fuente TrueType sobre una imagen existente de TeX Live 2022:

```dockerfile
FROM ghcr.io/ayaka-notes/texlive-full:2022.1

COPY ./myfonts/*.ttf /usr/share/fonts/truetype/myfont/

# rebuild font information cache
RUN fc-cache
```

### Configurar Server Pro para usar las nuevas imágenes

Usa el nombre `ghcr.io/ayaka-notes/texlive-full` y una etiqueta personalizada para construir la nueva imagen, como en:

```bash
docker build -t ghcr.io/ayaka-notes/texlive-full:2023.1-custom
```

Ahora podemos configurar Server Pro para usar la nueva imagen `2023.1-custom` actualizando las variables de entorno `TEX_LIVE_DOCKER_IMAGE` y `ALL_TEX_LIVE_DOCKER_IMAGES`:

```text wrap
TEX_LIVE_DOCKER_IMAGE: "ghcr.io/ayaka-notes/texlive-full:2023.1-custom"
ALL_TEX_LIVE_DOCKER_IMAGES: "ghcr.io/ayaka-notes/texlive-full:2023.1,ghcr.io/ayaka-notes/texlive-full:2023.1-custom"
```

En el ejemplo anterior, los proyectos nuevos se configuran por defecto para usar la nueva imagen `2023.1-custom`, mientras que `2023.1` sigue disponible para cuando se necesite.
