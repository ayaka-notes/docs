---
title: Migración de docker-compose.yml al Toolkit
description: Migra un despliegue de Overleaf con Docker Compose al Toolkit.
icon: right-left
---

Si actualmente utilizas Docker Compose mediante un archivo `docker-compose.yml`, migrar al Toolkit puede facilitar el despliegue, la actualización y el mantenimiento de una versión on-premises de Overleaf.

Para migrar, tendrás que convertir tu configuración actual de Docker Compose al formato que utiliza el Toolkit. Este proceso consiste en copiar la configuración existente en el Toolkit.

Esta guía te acompañará en cada paso del proceso, para garantizar una migración sin problemas de Docker Compose al Toolkit.

<Info>

Estas instrucciones son para la v4.x y anteriores. Por eso, todas las variables usan el prefijo `SHARELATEX_` en lugar de `OVERLEAF_`.

</Info>

<Steps>
<Step title="Clonar el repositorio del Toolkit">
Primero, clona el repositorio del Toolkit en la máquina host:

```bash
git clone https://github.com/overleaf/toolkit.git ./overleaf-toolkit
```

A continuación, ejecuta el comando `bin/init` para inicializar el Toolkit con su configuración predeterminada.
</Step>

<Step title="Configurar la imagen y la versión">
En un `docker-compose.yml` típico, la imagen y la versión se definen en la descripción del componente, por ejemplo:

```yaml
version: '2.2'
services:
    sharelatex:
        restart: always
        # Server Pro users:
        # image: quay.io/sharelatex/sharelatex-pro
        image: sharelatex/sharelatex:3.5.13
```

Al usar el Toolkit, el nombre de la imagen se resuelve automáticamente; el único requisito es definir `SERVER_PRO=true` en **config/overleaf.rc** para elegir la imagen de Server Pro, o `SERVER_PRO=false` para usar Community Edition.

El número de versión deseado de Server Pro/Community Edition se define en el archivo **config/version**. El Toolkit requiere un número de versión concreto, como `4.2.3`. Si estás usando `latest`, puedes usar `bin/images` para encontrar el ID de imagen de tu versión `latest` local y, después, usar las notas de la versión de 2.x.x, 3.x.x, 4.x.x o 5.x.x para relacionar el ID de imagen con la versión.

Si obtienes la imagen de tu propio registro interno, puedes sobrescribir la imagen que usa el Toolkit definiendo `OVERLEAF_IMAGE_NAME`. No necesitas especificar la etiqueta, ya que el Toolkit la añadirá automáticamente en función de tu archivo **config/version**.
</Step>

<Step title="Configurar el acceso externo">
De forma predeterminada, Overleaf escucha en `127.0.0.1:80`, lo que solo permite tráfico desde la máquina host de Docker.

Para permitir el acceso externo, define `OVERLEAF_LISTEN_IP` y `OVERLEAF_PORT` en el archivo [**config/overleaf.rc**](/es/on-premises/configuration/overleaf-toolkit/environment-variables).
</Step>

<Step title="Migración de variables de entorno">
Probablemente tengas un conjunto de variables de entorno definidas en el servicio `sharelatex` de tu `docker-compose.yml`, por ejemplo:

```yaml
environment:
    OVERLEAF_APP_NAME: Overleaf Community Edition
    OVERLEAF_PROXY_LEARN: 'true'
    …
```

Copia estas variables en el archivo [**config/variables.env**](/es/on-premises/configuration/overleaf-toolkit/environment-variables) del Toolkit, con el siguiente formato (usa `=` en lugar de `:`):

```env
OVERLEAF_APP_NAME=Overleaf Community Edition
OVERLEAF_PROXY_LEARN=true
```

Excepciones / diferencias al usar el Toolkit:

* Las variables que empiezan por `SANDBOXED_COMPILES_` y `DOCKER_RUNNER` ya no son necesarias. Para habilitar Sandboxed Compiles, define `SIBLING_CONTAINERS_ENABLED=true` en tu archivo **config/overleaf.rc**.
* Las variables que empiezan por `OVERLEAF_MONGO_`, `OVERLEAF_REDIS_` y la variable `REDIS_HOST` ya no son necesarias. MongoDB y Redis se configuran ahora en el archivo **config/overleaf.rc** mediante `MONGO_URL`, `REDIS_HOST` y `REDIS_PORT`.

Para opciones de configuración avanzadas, consulta la documentación de [config/overleaf.rc](/es/on-premises/configuration/overleaf-toolkit/environment-variables).
</Step>

<Step title="Proxy NGINX">
Para obtener instrucciones sobre cómo migrar `nginx`, consulta la [documentación del proxy TLS](/es/on-premises/configuration/overleaf-toolkit/tls-proxy):
</Step>

<Step title="Volúmenes">
Define las ubicaciones de los volúmenes de datos en **config/overleaf.rc**:

#### ShareLaTeX

Define `OVERLEAF_DATA_PATH` con la ubicación del volumen de datos que usa el contenedor `sharelatex`.

#### MongoDB

Define `MONGO_DATA_PATH` con la ubicación del volumen de datos que usa el contenedor `mongo`.

#### Redis

Define `REDIS_DATA_PATH` con la ubicación del volumen de datos que usa el contenedor `redis`.
</Step>
</Steps>

Para más detalles y configuración avanzada, consulta la documentación de configuración del Toolkit enlazada anteriormente.
