### Ver el registro de auditoría de un proyecto

Los administradores pueden ver un **Audit Log** (registro de auditoría) para cada proyecto. Este registro de auditoría muestra eventos como cuándo cambió el uso compartido por enlace entre privado y basado en token, cuándo se enviaron o aceptaron invitaciones y cuándo un usuario se unió al proyecto mediante un token. Los administradores pueden consultar estos registros por proyecto a través de **Your Instance** -> **Admin** -> **Manage Users** y, a continuación:

* Buscar al usuario
* Hacer clic en la pestaña **Projects**
* Seleccionar un proyecto
* Hacer clic en el icono (i)
* Hacer clic en la pestaña **Audit Log**

Si un proyecto se comparte con un colaborador concreto (mediante su dirección de correo electrónico), una vez que el destinatario se haya unido, aparecerá en el modal Share junto con sus permisos y será visible para el propietario del proyecto. Esta información también se mostrará a los administradores al consultar la pestaña Project Info del proyecto a través del panel de administración.

### Recuperar documentos eliminados

1. Inicia sesión con tus credenciales de administrador
2. Haz clic en **Admin** y selecciona **Manage Users**
3. En el campo de búsqueda, introduce el correo electrónico del usuario cuyo documento quieres restaurar
4. Haz clic en su dirección de correo electrónico en la lista de resultados para abrir su página de información de usuario
5. Haz clic en la pestaña **Projects** y utiliza el campo de búsqueda para buscar el proyecto
6. Haz clic en el icono de información junto al nombre del proyecto para abrir **Project Info**
7. Haz clic en la pestaña **Deleted Docs**
8. Haz clic en el botón **Undelete** junto al documento eliminado para restaurarlo en el proyecto del usuario.

El archivo restaurado tendrá el siguiente formato: `FILENAME-TIMESTAMP.EXTENSION`. Por ejemplo, una versión restaurada de `main.tex` se restaurará en la raíz del proyecto con el nombre de archivo `main-2024-02-23-130441542.tex`.

### Transferir la propiedad de un proyecto

El panel de administración de Server Pro tiene una página dedicada para cada proyecto. Puedes llegar a ella buscando al usuario en "/admin/user", yendo a su pestaña **Projects**, localizando el proyecto en la lista y haciendo clic en el icono de información; o bien navegando directamente a la página con un ID de proyecto conocido [**https://your-instance-url/admin/project/**](https://your-instance-url/admin/project/). En la página de información del proyecto encontrarás un botón **Transfer Ownership**, que abre un modal en el que puedes indicar cualquier usuario como nuevo propietario. No es necesario que el nuevo propietario sea un colaborador existente del proyecto.

<Info>

Ten en cuenta que, como parte del proceso de transferencia de propiedad, el propietario anterior se añadirá como colaborador con acceso de lectura y escritura al proyecto.

</Info>

### Actualizar el tiempo límite de compilación de los proyectos

El tiempo límite de compilación predeterminado de los proyectos está establecido actualmente en 180 segundos. Es posible cambiar este valor, lo que requiere un proceso de dos pasos.

Primero, edita el archivo **config/variables.env**, añade la variable de entorno `COMPILE_TIMEOUT` y establece su valor en el tiempo límite deseado en segundos. Por ejemplo, `COMPILE_TIMEOUT=300` para 5 minutos.

<Danger>

No merece la pena aumentar el tiempo límite por encima de 10 minutos. Si lo haces, lo más probable es que alcances un tiempo límite en otro componente de la aplicación.

</Danger>

Una vez realizado este cambio, tendrás que recrear el contenedor **sharelatex** ejecutando el comando `bin/up -d`.

Establecer esta variable de entorno actualizará el valor del tiempo límite solo para los usuarios nuevos; **no** se aplicará retroactivamente a los usuarios existentes, ya que el valor se asigna cuando se crea el usuario por primera vez.

Para ajustar el tiempo límite de los usuarios existentes, tendrás que modificar el registro de cada usuario en la base de datos. Te aconsejamos tener mucha precaución al hacerlo y recomendamos realizar una copia de seguridad coherente antes de hacer cualquier cambio.

Puedes encontrar información sobre cómo realizar copias de seguridad [aquí](/es/on-premises/maintenance/data-and-backups).

Para actualizar el valor del tiempo límite de compilación de todos los usuarios existentes, tendrás que ejecutar el siguiente comando de shell en el host de Docker:

```bash wrap
echo 'db.users.updateMany({}, {$set: {"features.compileTimeout": <value>}})' | docker exec -i mongo mongosh --quiet localhost/sharelatex
```

Tendrás que sustituir `<value>` en la consulta anterior por el valor de tiempo límite deseado en segundos.

Cuando el comando finalice, deberías ver una confirmación con el número de registros modificados. Después puedes escribir exit y pulsar la tecla Intro para volver al shell del host.

### Seguimiento del acceso a los proyectos

Es posible ver quién carga un proyecto y cuándo con el siguiente comando:

```bash wrap
docker exec sharelatex bash -c 'grep "join project request" /var/log/overleaf/web.log'
```

Esto mostrará el `timestamp`, el `user_id` y el `project_id`.
