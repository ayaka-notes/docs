## Crear un usuario administrador {#creating-an-administrator-user}

Despliegues con el Overleaf Toolkit:

```bash title="Overleaf Toolkit" wrap
$ bin/docker-compose exec sharelatex /bin/bash -ce "cd /overleaf/services/web && node modules/server-ce-scripts/scripts/create-user --admin --email=joe@example.com"
```

Despliegues heredados con docker-compose.yml:

```bash title="Legacy docker-compose" wrap
$ docker exec sharelatex /bin/bash -ce "cd /overleaf/services/web && node modules/server-ce-scripts/scripts/create-user --admin --email=joe@example.com"
```

El comando creará un usuario con la dirección de correo electrónico indicada, si aún no existe, y lo convertirá en administrador. La salida del comando incluye una URL que debes visitar para establecer la contraseña de este usuario e iniciar sesión por primera vez.

<Info>

Para un enfoque programático, puedes usar el mismo script para crear tanto usuarios normales como administradores. Para usuarios normales, omite la opción --admin.

</Info>

Si usas cuentas internas para la autenticación y necesitas convertir a un usuario existente en administrador de la instancia o revocarle los permisos de administrador, haz lo siguiente:

<Steps>
<Step title="Desde la interfaz de administración">
* Inicia sesión como un administrador existente.
* Haz clic en Admin -> Manage Users.
* Busca al usuario y haz clic en su dirección de correo electrónico.
* Desplázate hasta la sección Site Admin y haz clic en el enlace (show).
* Marca la casilla Is Site Admin.
* Haz clic en Save para terminar.
</Step>
</Steps>

## Eliminar usuarios {#deleting-users}

En general, no es recomendable eliminar cuentas a menos que ya no sean necesarias. Eliminar una cuenta borra la cuenta y hace que los colaboradores pierdan el acceso a los proyectos. Actualmente no hay forma de desactivar cuentas: o existen con sus datos conservados o se eliminan.

Por defecto, las cuentas se eliminan de forma lógica (soft delete). Para obtener información sobre cómo eliminar usuarios de tu instancia de forma permanente, consulta `ENABLE_CRON_RESOURCE_DELETION` en la guía de [Variables de entorno](/es/on-premises/configuration/overleaf-toolkit/environment-variables).

<Info>

Las cuentas se eliminan de forma lógica por defecto. Consulta `ENABLE_CRON_RESOURCE_DELETION` para conocer el comportamiento de la eliminación permanente.

</Info>

### Desde Admin -> Manage Users {#via-admin->-manage-users}

<Steps>
<Step title="">
* Inicia sesión como administrador.
* Haz clic en Admin -> Manage Users.
* Busca al usuario y marca la casilla junto a su dirección de correo electrónico.
* Haz clic en el icono de la papelera.
* Haz clic en Delete para confirmar.
</Step>
</Steps>

### Desde la línea de comandos {#via-the-command-line}

Las cuentas de usuario (y sus proyectos) pueden eliminarse con los siguientes comandos.

Despliegues con el Overleaf Toolkit:

```bash title="Overleaf Toolkit"
$ bin/docker-compose exec sharelatex /bin/bash -ce "cd /overleaf/services/web && node modules/server-ce-scripts/scripts/delete-user.mjs --email=joe@example.com"
```

Despliegues heredados con docker-compose.yml:

```bash title="Legacy docker-compose"
$ docker exec sharelatex /bin/bash -ce "cd /overleaf/services/web && node modules/server-ce-scripts/scripts/delete-user.mjs --email=joe@example.com"
```

<Danger>

El script de eliminación usa una opción de forzado fija en el código que garantiza que la eliminación continúe aunque falle el envío del correo de eliminación de la cuenta (por ejemplo, cuando el correo del usuario ya no está en servicio).

</Danger>

<Info>

Se puede usar la opción --skip-email para no enviar un correo informativo al usuario eliminado.

</Info>

## Restaurar un usuario eliminado de forma lógica {#restoring-a-soft-deleted-user}

Si un usuario solo se ha eliminado de forma lógica, puedes restaurar su cuenta y sus proyectos.

<Steps>
<Step title="">
* Inicia sesión como administrador.
* Haz clic en Admin -> Manage Users.
* Busca al usuario que quieres restaurar.
* Haz clic en el botón Display deleted users.
* Haz clic en la dirección de correo electrónico del usuario eliminado.
* Haz clic en Recover This Account.
* Haz clic en Recover para confirmar.
</Step>
</Steps>

<Danger>

Cuando ENABLE\_CRON\_RESOURCE\_DELETION está establecido en true, las cuentas eliminadas de forma lógica pueden restaurarse en un plazo de 90 días. Pasados 90 días, no es posible recuperar la cuenta.

</Danger>

## Contar usuarios {#counting-users}

Puedes obtener el número de usuarios desde la interfaz de administración en https://you-instance-url/admin/user#license. Para comprobaciones y exportaciones programáticas, los siguientes ejemplos pueden ser útiles.

Número total de usuarios:

```bash title="Total number of users"
echo 'db.users.countDocuments()' | docker exec -i mongo mongosh --quiet localhost/sharelatex
# overleaf [direct: primary] sharelatex> 16
```

Número total de usuarios mediante el endpoint de métricas:

```bash title="Num active users from metrics"
docker exec sharelatex curl http://127.0.0.1:3000/metrics | grep num_active_users
# # HELP num_active_users num_active_users
# # TYPE num_active_users gauge
# num_active_users{app="web-api",host="b3ae4ff549d8"} 16
```

Número total de usuarios activos (ejemplo: usuarios activos en los últimos 365 días):

```bash title="Total number of active users"
echo 'db.users.countDocuments({ lastActive: { $gte: new Date(new Date().getTime() - (365 * 24 * 60 * 60 * 1000)) } })' | docker exec -i mongo mongosh --quiet localhost/sharelatex
# overleaf [direct: primary] sharelatex> 10
```

## Actualizar la información de las cuentas de usuario {#updating-user-account-information}

La forma de actualizar las cuentas depende de si SSO está habilitado.

* Si no se usa SSO:
  * Los administradores pueden modificar la información de las cuentas de usuario desde Admin -> Manage Users (correo electrónico, nombre, apellidos y generar un enlace para restablecer la contraseña).
  * Los usuarios normales pueden actualizar sus propios datos desde Account -> Account Settings (incluido cambiar la contraseña y generar tokens de autenticación de Git).
* Si se usa SSO:
  * Ayakaleaf Pro puede configurarse para actualizar el nombre y los apellidos de un usuario al iniciar sesión, según el sistema de autenticación.
  * Cuando OVERLEAF\_SAML\_UPDATE\_USER\_DETAILS\_ON\_LOGIN u OVERLEAF\_LDAP\_UPDATE\_USER\_DETAILS\_ON\_LOGIN son true, el formulario de datos del usuario en https://your-instance-url/user/settings se deshabilita y el nombre y los apellidos solo pueden establecerse en tu sistema de gestión de identidades.

Para más detalles, consulta:

* [Configuración de SAML 2.0](/es/on-premises/configuration/overleaf-toolkit/authentication/saml-authentication)
* [Configuración de LDAP](/es/on-premises/configuration/overleaf-toolkit/authentication/ldap-authentication)

### Q\&A {#q&a}

<Accordion title="¿Puedo crear usuarios de SSO por adelantado, por ejemplo con una API?">

<strong>Respuesta:</strong> No hay ninguna API HTTP para esto. Crea la cuenta con el script `create-user` anterior (sin `--admin`) o en **Admin → Manage Users** con **Create account**. Cuando `EXTERNAL_AUTH` está establecido, ese formulario tiene una opción **External authentication**, que crea la cuenta sin contraseña local y sin correo de activación. En el primer inicio de sesión con LDAP, SAML u OIDC, el usuario obtiene la cuenta existente con el mismo correo electrónico en lugar de una nueva; consulta [Cuentas y contraseñas](/es/on-premises/configuration/overleaf-toolkit/authentication#accounts-and-passwords).

</Accordion>

<Accordion title="¿Puedo exportar la lista de usuarios y restaurarla más adelante?">

<strong>Respuesta:</strong> No. No existe exportación ni importación de cuentas de usuario, ni en **Admin → Manage Users** ni como script. Las cuentas se almacenan en MongoDB, así que haz una copia de seguridad y restáuralas con una [copia de seguridad de MongoDB](/es/on-premises/maintenance/data-and-backups#mongodb). El script `export-user-projects.mjs` exporta los proyectos de los usuarios como archivos zip, no las cuentas; consulta [Exportar proyectos](/es/on-premises/maintenance/data-and-backups/exporting-projects).

</Accordion>

<Accordion title="¿Cuánto tiempo es válido el enlace de `create-user` y cómo restablezco una contraseña sin correo electrónico?">

<strong>Respuesta:</strong> El enlace que imprime `create-user` es válido durante 7 días, y funciona sin SMTP porque lo copias de la salida. Para obtener un enlace nuevo, vuelve a ejecutar `create-user` con el mismo correo electrónico. Para una cuenta existente solo imprime un enlace nuevo, pero también ajusta el indicador de administrador de la cuenta según `--admin`, así que mantén `--admin` cuando lo ejecutes para un administrador.

Un administrador también puede establecer una contraseña directamente: en **Admin → Manage Users**, haz clic en **Update** en la fila del usuario, abre la pestaña **Password** e introduce una nueva contraseña de al menos 8 caracteres. Las cuentas que inician sesión solo mediante LDAP, SAML u OIDC no pueden obtener una contraseña ahí.

</Accordion>
