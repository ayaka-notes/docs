## Migración de nombres de usuario

Desde el punto de vista del inicio de sesión, el identificador principal de un usuario es su dirección de correo electrónico. Si migras de la autenticación local a SSO o de un IdP a otro, es posible que tengas que actualizar las direcciones de correo electrónico de los usuarios.

Para ayudarte con ello, se proporciona un script que migra los correos electrónicos de los usuarios a partir de un archivo CSV con el siguiente formato:

`oldEmail,newEmail`

Tras realizar algunas comprobaciones de validación, el script recorrerá el archivo CSV y actualizará las direcciones de correo electrónico de los usuarios de `oldEmail` a `newEmail`.

### **Validación**

Antes de ejecutar la migración, se comprobará el `<csv_file>` para garantizar que:

* En cada fila, tanto `oldEmail` como `newEmail` son direcciones de correo electrónico válidas
* No hay entradas duplicadas; por ejemplo, que no intentas actualizar distintos usuarios a la misma dirección de correo electrónico nueva ni actualizar la misma cuenta de usuario con una dirección de correo electrónico ya utilizada

### **Uso**

```bash wrap
docker cp <csv_file> sharelatex:/overleaf/services/web/<csv_file> docker exec sharelatex /bin/bash -c "cd /overleaf/services/web;node ./modules/server-ce-scripts/scripts/migrate-user-emails.js [--commit] [--continue|--ignore-missing] [--admin-id=ADMIN_USER_ID] <csv_file>"
```

### **Opciones**

| Nombre             | Descripción                                                                                                                                                                                                                                                      |
| ------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `--commit`         | <p>La inclusión de la opción `--commit` realizará efectivamente la migración. Si se omite, la migración se ejecutará en modo de simulación (dry-run), en el que no se realizan cambios pero sí se lleva a cabo la validación.<br /><br /><strong>Predeterminado</strong>:`false`</p> |
| `--continue`       | La opción `--continue` continuará el proceso de migración si la dirección de correo electrónico de una cuenta de usuario ya se ha actualizado                                                                                                                     |
| `--ignore-missing` | La opción `--ignore-missing` continuará el proceso de migración si no se encuentra una cuenta de usuario                                                                                                                                                         |
| `--admin-id`       | `--admin-id` debe establecerse con el ID del administrador que realiza la migración y se utilizará en las entradas del registro de auditoría. Ve a **Admin** > **Manage Users**, busca tu dirección de correo electrónico y haz clic en el primer resultado para encontrar tu user-id. |
| `<csv_file>`       | `<csv_file>` es el archivo que contiene las direcciones de correo electrónico antiguas y nuevas                                                                                                                                                                  |

### **Finalización**

Durante la ejecución del script de migración, las opciones que hayas elegido determinarán si un error se registra en la consola y el proceso continúa, o se registra en la consola y el proceso termina. Si el script finaliza prematuramente debido a un error, saldrá con el código 1 para indicar que no ha tenido éxito.

Al completar la migración, el script registrará en la consola el número de actualizaciones correctas, fallidas y omitidas. Si la migración se completa correctamente, saldrá con el código 0.
