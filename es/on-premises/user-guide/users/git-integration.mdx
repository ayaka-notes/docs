Trabaje en un proyecto desde su propio ordenador con Git. Los cambios solo se transfieren cuando ejecuta `git pull` o `git push`.

<Info>

Un administrador tiene que activar primero la [integración con Git](/es/on-premises/configuration/overleaf-toolkit/integrations/git-integration).

</Info>

## Crear un token {#create-a-token}

Git inicia sesión con un token de autenticación de Git, no con la contraseña de su cuenta.

<Steps>
<Step title="Abrir la configuración de su cuenta">
Haga clic en **Account** y luego en **Account settings**. En **Git integration**, haga clic en **Generate token**. Una vez que tenga un token, este botón se llama **Add another token**.

<Frame caption="La integración con Git en la configuración de la cuenta">
  <img src="/images/on-premises/git-integration-settings.png" alt="La sección Git integration de la configuración de la cuenta con un botón Generate token" />
</Frame>
</Step>

<Step title="Copiar el token">
Haga clic en **Copy** y guarde el token en un lugar seguro. Solo lo verá una vez. Luego haga clic en **Close**.

<Frame caption="Su nuevo token">
  <img src="/images/on-premises/git-integration-token.png" alt="El diálogo del token de autenticación de Git con un botón Copy" />
</Frame>
</Step>

<Step title="Comprobar el token">
La lista muestra ahora el comienzo del token, cuándo se creó y cuándo se usó por última vez. Caduca al cabo de un año. Puede tener hasta 10 tokens.

<Frame caption="Sus tokens">
  <img src="/images/on-premises/git-integration-tokens.png" alt="La lista de tokens con un token" />
</Frame>
</Step>
</Steps>

## Clonar un proyecto {#clone-a-project}

<Steps>
<Step title="Abrir la integración con Git en el editor">
Abra el proyecto. En la barra izquierda, haga clic en **Integrations** y luego en **Git integration**.

<Frame caption="El panel Integrations">
  <img src="/images/on-premises/git-integration-panel.png" alt="El panel Integrations con la tarjeta Git integration" />
</Frame>
</Step>

<Step title="Copiar el comando">
El diálogo **Clone with Git** muestra el comando, con la dirección de su sitio y el ID del proyecto. Haga clic en **Copy**. Si todavía no tiene un token, **Go to settings** abre la configuración de su cuenta en una pestaña nueva.

<Frame caption="El comando de clonación">
  <img src="/images/on-premises/git-integration-clone.png" alt="El diálogo Clone with Git con el comando git clone" />
</Frame>
</Step>

<Step title="Ejecutarlo">
Pegue el comando en una terminal. Cuando Git le pida una contraseña, pegue su token.

```text
$ git clone https://git@<your-site>/git/<project-id>
Cloning into '<project-id>'...
Password for 'https://git@<your-site>': <your-token>
```

Una carpeta con el nombre del ID del proyecto contiene ahora los archivos del proyecto, en la rama `main`. Para elegir el nombre de la carpeta, añádalo al final del comando.
</Step>
</Steps>

Git pide el token cada vez que se conecta con el sitio. Para que lo recuerde, active un credential helper: Git lo pide una vez más y después lo conserva. El helper `store` lo guarda sin cifrar en `~/.git-credentials`.

```bash
git config --global credential.helper store
```

## Traer los cambios del editor {#pull-changes-from-the-editor}

Dentro de la carpeta, ejecute:

```bash
git pull
```

Git enumera los archivos que cambiaron. Los cambios hechos en el editor llegan como commits llamados `Update on Overleaf.`.

```text
Updating db007e3..c3e6332
Fast-forward
 main.tex | 2 +-
 1 file changed, 1 insertion(+), 1 deletion(-)
```

## Enviar sus cambios {#push-your-changes}

Haga commit de sus cambios y luego envíelos con push:

```bash
git add main.tex
git commit -m "Add a line from Git"
git push
```

La última línea de la salida muestra la rama que avanzó:

```text
   53aca61..db007e3  main -> main
```

Los cambios aparecen en el editor, y un editor abierto se actualiza solo. Los archivos nuevos, las carpetas y los cambios de nombre aparecen en el árbol de archivos. En **History**, su cambio aparece marcado como <strong>You (via Git)</strong>. Su mensaje de commit no se muestra allí.

### Si Git rechaza su push {#if-git-refuses-your-push}

Si el proyecto cambió mientras tanto, Git rechaza el push:

```text
 ! [rejected]        main -> main (fetch first)
```

Traiga primero esos cambios y luego vuelva a hacer push:

```bash
git pull --no-rebase --no-edit
git push
```

Un `git pull` simple puede detenerse con `fatal: Need to specify how to reconcile divergent branches.` La opción `--no-rebase` de arriba lo resuelve: fusiona ambos lados.

Si las mismas líneas cambiaron en ambos lados, el pull se detiene con `CONFLICT (content): Merge conflict in main.tex`. Corrija el archivo y luego:

```bash
git add main.tex
git commit -m "Merge the changes from the editor"
git push
```

Hay dos cosas que el sitio no acepta:

* Otras ramas: `! [remote rejected] feature -> feature (wrong branch)`. Solo existe `main`, así que envíe su trabajo allí.
* Force push: `! [remote rejected] main -> main (forced push prohibited)`. En su lugar, coloque sus cambios encima de la `main` actual.

### Si Git dice Authentication failed {#if-git-says-authentication-failed}

```text
remote: Enter your Git authentication token when prompted for a password.
fatal: Authentication failed for 'https://<your-site>/git/<project-id>/'
```

El token es incorrecto o se eliminó, o usted escribió la contraseña de su cuenta. Cree un token nuevo si ya no lo tiene, porque no puede volver a ver uno existente.

## Eliminar un token {#delete-a-token}

En **Account settings**, en **Git integration**, haga clic en el icono de eliminar junto al token y luego en **Delete** en el diálogo. A partir de entonces, Git responde `Authentication failed` a ese token.
