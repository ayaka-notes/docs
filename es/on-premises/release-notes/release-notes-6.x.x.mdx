Consulta: [https://github.com/ayaka-notes/ayakaleaf-pro/releases/tag/pro-v6.3.0](https://github.com/ayaka-notes/ayakaleaf-pro/releases/tag/pro-v6.3.0)

<Warning>

Ayakaleaf Pro 6.3.0 se publicó inicialmente el 24 de septiembre de 2026. Esta republicación soluciona problemas en las integraciones del asistente de IA, Zotero y Mendeley causados por actualizaciones upstream.

La versión publicada anteriormente no daña tus datos. Descarga la imagen `6.3.0` más reciente y actualiza tu despliegue. <strong>Las instalaciones existentes con archivos de bibliografía vinculados a Zotero o Mendeley también deben ejecutar la migración siguiente.</strong> Las instalaciones nuevas no necesitan esta migración.

<Accordion title="Migración de Zotero / Mendeley para instalaciones existentes">

Al actualizar a la imagen 6.3.0 republicada, migra los metadatos existentes de las bibliografías vinculadas a Zotero/Mendeley con el script siguiente. Esta migración acompaña a la corrección `12031b8dfd`.

Renombra `zoteroGroupId` / `mendeleyGroupId` a `group_id`, renombra `importedByUserId` a `importer_id` y elimina `importedByName`.

Haz una copia de seguridad de MongoDB y detén la aplicación antes de ejecutar la migración. Mantén MongoDB en ejecución. Abre su shell (sustituye `mongo` por el nombre de tu contenedor):

```bash
docker exec -it mongo mongosh
```

Ejecuta lo siguiente en `mongosh` (sustituye `sharelatex` por el nombre de tu base de datos):

```javascript
use sharelatex

(async () => {
  let updated = 0
  await db.projects.find({}, { rootFolder: 1 }).forEach(async project => {
    const changes = {}
    function visit(folders, path) {
      for (const [i, folder] of (folders || []).entries()) {
        const folderPath = `${path}.${i}`
        for (const [j, file] of (folder.fileRefs || []).entries()) {
          const data = { ...file.linkedFileData }
          if (!["zotero", "mendeley"].includes(data.provider)) continue
          const groupKey = `${data.provider}GroupId`
          if (![groupKey, "importedByUserId", "importedByName"].some(key => key in data)) continue
          for (const [oldKey, newKey] of [[groupKey, "group_id"], ["importedByUserId", "importer_id"]]) {
            if (data[oldKey] != null && data[oldKey] !== "") {
              const value = String(data[oldKey])
              if (newKey in data && data[newKey] !== value) {
                throw new Error(`Conflicting ${newKey}: project ${project._id}, file ${file._id}`)
              }
              data[newKey] = value
            }
            delete data[oldKey]
          }
          delete data.importedByName
          changes[`${folderPath}.fileRefs.${j}.linkedFileData`] = data
        }
        visit(folder.folders, `${folderPath}.folders`)
      }
    }
    visit(project.rootFolder, "rootFolder")
    if (!Object.keys(changes).length) return
    const result = await db.projects.updateOne(
      { _id: project._id, rootFolder: { $eq: project.rootFolder } },
      { $set: changes }
    )
    if (!result.matchedCount) throw new Error(`Project changed during migration: ${project._id}`)
    updated += result.modifiedCount
  })
  print(`Updated ${updated} project(s).`)
})()
```

El script incluye las carpetas anidadas y solo modifica los metadatos de Zotero/Mendeley. Es seguro volver a ejecutarlo: una migración completada indica `Updated 0 project(s).` en la siguiente ejecución. Si se detiene por un conflicto, revisa el proyecto/archivo indicado; es posible que los proyectos anteriores ya se hayan migrado.

Inicia la aplicación actualizada, recarga el editor y actualiza un archivo de bibliografía existente como su importador original. Las instantáneas históricas no se reescriben. Para volver a la aplicación anterior, restaura la copia de seguridad de MongoDB.

Nos enorgullece anunciar la publicación de Overleaf Pro 6.3.0, el editor de LaTeX en línea más potente y completo de la comunidad. Como siempre nos hemos centrado en mejorar la experiencia de nuestros usuarios, esta versión trae enormes cambios y funciones maravillosas que sin duda te encantarán, como el asistente de IA y la integración de referencias de terceros.

### Cambios

* Asistente de chat con IA: chatea con un modelo de IA a través de tu propio proveedor, directamente en tu editor.
* Asistente de errores de LaTeX: obtén correcciones sugeridas por IA para los errores de compilación de LaTeX.
* Integración con Mendeley: importa referencias desde Mendeley de forma similar a Zotero.
* API Open in Overleaf: se ha añadido una API para abrir contenido en Overleaf.
* Galería de plantillas: se ha añadido paginación, búsqueda y ordenación en el servidor, de modo que las galerías grandes ya no necesitan cargar todas las plantillas en el navegador.
* Traducciones: se han actualizado los parches de traducción para la 6.3.0, incluido el nuevo texto de la interfaz en todos los idiomas admitidos.
* Overleaf 6.3.0 upstream: incluye edición de archivos en pestañas, logotipos de cabecera independientes para los temas claro y oscuro, y actualizaciones de dependencias y de la imagen base.
* Se han añadido `OVERLEAF_HEADER_IMAGE_URL_LIGHT` y `OVERLEAF_HEADER_IMAGE_URL_DARK` para admitir imágenes de logotipo de cabecera independientes para los temas claro y oscuro.
* Ahora los archivos se pueden abrir en distintas pestañas del editor.
* Se ha añadido compatibilidad con proxies HTTP(S) configurables, incluidos proxies alojados localmente, mediante `OVERLEAF_LINKED_URL_OUTBOUND_PROXY`, que también usa la API Open in Overleaf.

#### Función 04: paginación de plantillas

Ahora la galería pagina, ordena y busca en MongoDB. Funciona sin ninguna preparación; con miles de plantillas, puedes añadir estos índices para mantenerla rápida (es seguro volver a ejecutarlo; `mongo`/`sharelatex` = los nombres de tu contenedor y de tu base de datos):

```bash
docker exec mongo mongosh sharelatex --quiet --eval '
db.templates.createIndex({category:1,lastUpdated:-1},{name:"category_1_lastUpdated_-1",background:true});
db.templates.createIndex({lastUpdated:-1},{name:"lastUpdated_-1",background:true});
db.templates.createIndex({category:1,name:1},{name:"category_1_name_1_ci",collation:{locale:"en",strength:2},background:true});
db.templates.createIndex({name:1},{name:"name_1_ci",collation:{locale:"en",strength:2},background:true});
'
```

Mantén la `collation` de los dos índices `*_ci` tal como está escrita: la galería realiza las consultas con la misma collation y MongoDB solo usa un índice que coincida.

## Ayakaleaf Pro 6.2.2

<strong>Fecha de publicación:</strong> 2026.07.23

Consulta: [https://github.com/ayaka-notes/ayakaleaf-pro/releases/tag/pro-v6.2.2](https://github.com/ayaka-notes/ayakaleaf-pro/releases/tag/pro-v6.2.2)

### Cambios

Se incorporan los parches de corrección oficiales publicados en Overleaf `6.2.2` upstream (sobre la `6.2.1`):

* Se evita que el secreto del token de invitación a proyectos se filtre en los logs. El cifrador de tokens de invitación registraba su propia configuración en cada cifrado/descifrado, lo que incluía las contraseñas de cifrado derivadas de `OVERLEAF_INVITE_TOKEN_SECRET`.
* Se migra el correo saliente del cliente AWS SES v1, que ha llegado al final de su vida útil, a SESv2. Las instancias configuradas con el driver de correo `ses` podían no enviar ningún correo; ahora el envío se realiza a través de `SESv2Client`.
* Las entradas de grupo del desplegable para compartir proyectos quedan condicionadas al nuevo indicador de función `group-link-sharing`, de modo que el uso compartido de enlaces de grupo ya no se ofrece en instancias donde no aplica.
* Se corrige el modal para compartir proyectos para los colaboradores. Al abrirlo sin ser propietario, o con el flujo `sharing-updates` deshabilitado, se enviaba una solicitud que siempre fallaba y mostraba un error "something went wrong".
* Se añade `scripts/flush_docs_with_pending_updates.js` a document-updater, un script de mantenimiento que recupera los documentos que quedan con una cola `PendingUpdates` bloqueada en Redis después de que su proyecto se haya vaciado o eliminado definitivamente. Admite `--dry-run` y una comprobación de seguridad `--estimated-docs`.
* Actualización de dependencias: `multer` 2.2.0, `form-data` 2.5.6, `protobufjs` 7.6.3, `@grpc/grpc-js` 1.14.4.

Esta versión también incluye las siguientes correcciones y mejoras de Ayakaleaf Pro:

* Se añaden traducciones completas para 16 idiomas adicionales (cs, da, de, es, fi, fr, it, ja, ko, nl, no, pl, pt, ru, sv, tr), lo que corrige cadenas sin traducir como la de la página de restablecimiento de contraseña. Corrige [#38](https://github.com/ayaka-notes/ayakaleaf-pro/issues/38).
* Se corrige el recuento de elementos del botón "show N more projects" del panel de administración, que mostraba un número incorrecto porque el marcador de plural no se pasaba correctamente.
* Se corrigen los errores de validación de la exportación a GitHub, que ahora se muestran mediante claves i18n estáticas en lugar de mensajes sin procesar, y se eliminan las claves de error que ya no usa el modal de GitHub Sync.

## Ayakaleaf Pro 6.2.1

<strong>Fecha de publicación:</strong> 2026.07.18

Consulta: [https://github.com/ayaka-notes/ayakaleaf-pro/releases/tag/pro-v6.2.1](https://github.com/ayaka-notes/ayakaleaf-pro/releases/tag/pro-v6.2.1)

### Cambios

Se incorporan los parches de corrección oficiales publicados en Overleaf `6.2.1` upstream (sobre la `6.2.0`):

* Se refuerza el mensaje en tiempo real `applyOtUpdate` con un esquema de validación estricto en lugar de aceptar cualquier objeto, rechazando las operaciones de edición mal formadas.

* Se corrige el editor (cliente ShareJS) para que las operaciones que se reducen a una operación vacía (anuladas por una operación remota/concurrente o revertidas por completo al deshacer) se descarten en lugar de enviarse al servidor, y el documento se indique correctamente como guardado. Evita problemas espurios de sincronización / "cambios sin guardar" relacionados con deshacer y la edición concurrente.

## Ayakaleaf Pro 6.2.0

<strong>Fecha de publicación:</strong> 2026.07.10

Consulta: [https://github.com/ayaka-notes/ayakaleaf-pro/releases/tag/pro-v6.2.0](https://github.com/ayaka-notes/ayakaleaf-pro/releases/tag/pro-v6.2.0)

Nos enorgullece anunciar la publicación de Overleaf Pro 6.2.0, el editor de LaTeX en línea más potente y completo de la comunidad. Damos las gracias especialmente a yu-i-i y davrot por sus valiosas contribuciones. Han mejorado GitHub Sync e introducido la búsqueda avanzada de citas y la integración con Zotero.

### Notas

<Warning>

* Se ha introducido una nueva variable de entorno obligatoria, `OVERLEAF_INVITE_TOKEN_SECRET`. Debes generarla con `openssl rand -base64 32`. Si no está configurada, tu instancia de Overleaf no podrá iniciarse.
* Si habilitas GitHub Sync, debes configurar la variable de entorno `GITHUB_TOKEN_CIPHER_PASSWORD`. Esta variable es necesaria para cifrar de forma segura los tokens de acceso de GitHub. Sin ella, tu instancia de Overleaf no podrá iniciarse.

</Warning>

* Se ha añadido una nueva variable de entorno `DEFAULT_LATEX_COMPILER` para establecer el compilador predeterminado que usan los proyectos nuevos (`pdflatex`, `latex`, `xelatex` o `lualatex`).
* El editor rediseñado es ahora la única opción disponible.

### Cambios

Esta versión incluye las siguientes mejoras y nuevas funciones.

* `MAX_UPLOAD_SIZE` ahora es configurable en lugar de estar limitado a **50 MB**.
* Se ha corregido un bucle de reinicio del contenedor cuando las compilaciones en sandbox estaban deshabilitadas.
* Se ha aplicado la eliminación de PAT limitada al propietario para OAuth2.
* Se ha corregido un problema de importación de LDAP.

Las funciones incluyen:

* Se ha añadido un ejecutor de Python basado en el navegador.
* Se ha añadido compatibilidad con Pandoc para importar y exportar Markdown, DOCX y otros formatos.
* Se ha añadido GitHub Sync.
* Se han añadido traducciones completas al chino.
* Se ha añadido la integración con Zotero.
* Se ha añadido `DEFAULT_LATEX_COMPILER`.

## Ayakaleaf Pro 6.0.0

<strong>Fecha de publicación:</strong> 2026.02.17

Versión de prueba; consulta: [https://github.com/ayaka-notes/ayakaleaf-pro/releases/tag/pro-v6.0.0](https://github.com/ayaka-notes/ayakaleaf-pro/releases/tag/pro-v6.0.0)

Se trata de una versión de prueba y también de nuestra versión inicial de Overleaf Pro. Esta versión no contiene ninguna función de Server Pro, por lo que solo marca nuestro punto de partida. Añadiremos nuevas funciones más adelante, como el panel de administración, git-bridge...

En esta versión hemos introducido la imagen de Docker de Overleaf para ARM. Puedes probarla si tienes un Mac o un servidor basado en ARM, pero es posible que algunas funciones no funcionen bien (aún no se han probado).

### Imagen de Docker

Puedes encontrar la imagen de Docker aquí: [https://github.com/ayaka-notes/overleaf-pro/pkgs/container/overleaf-pro](https://github.com/ayaka-notes/overleaf-pro/pkgs/container/overleaf-pro)

Para la imagen multiarquitectura, consulta [esta página](https://github.com/ayaka-notes/overleaf-pro/pkgs/container/overleaf-pro/691283454?tag=6.0.0).

```bash
docker pull ghcr.io/ayaka-notes/overleaf-pro:6.0.0
```

### Migración de archivos binarios

Esta nueva versión reduce a la mitad el uso de almacenamiento de los archivos binarios.

La versión `5.5` incluye una migración en línea, que permite un tiempo de inactividad mínimo como parte de la actualización. Antes de actualizar a Server Pro `v6`, asegúrate de que ya ejecutas la última versión de Server Pro `v5.5` ([Notas de la versión 5.x.x](https://docs.overleaf.com/on-premises/release-notes/release-notes-5.x.x)) y de que has ejecutado la migración.

[Consulta las instrucciones completas de migración](https://docs.overleaf.com/on-premises/release-notes/release-notes-5.x.x/binary-files-migration).

### Actualización de MongoDB a v8

Esta versión eleva la versión mínima de MongoDB a `8.0`.

Si actualmente usas MongoDB `v6` o anterior, tendrás que actualizar las versiones de una en una versión principal (`v6 → v7 → v8`).

<Warning>

Asegúrate de tener una copia de seguridad de la [base de datos](https://docs.overleaf.com/on-premises/maintenance/data-and-backups) **antes** de actualizar. En caso de revertir, tendrás que restaurar la copia de seguridad de la base de datos.

</Warning>

Para obtener instrucciones sobre cómo actualizar MongoDB `v6 → v7 → v8`, consulta nuestra guía paso a paso [aquí](https://docs.overleaf.com/on-premises/maintenance/updating-mongodb#example-upgrading-mongodb-from-6.0-to-7.0-toolkit-users).

### Actualización de Redis a v7.4

Esta versión también eleva la versión mínima de Redis a `7.4`.

Actualiza tu `REDIS_IMAGE` en `config/overleaf.rc` a `REDIS_IMAGE=7.4`.

### Nuevas funciones

* Ahora el uso compartido mediante enlace se puede deshabilitar con `OVERLEAF_DISABLE_LINK_SHARING=true`.
* `OVERLEAF_MAINTENANCE_MESSAGE` y `OVERLEAF_MAINTENANCE_MESSAGE_HTML` ya están disponibles para personalizar el título y el contenido de la página de mantenimiento.
* `OVERLEAF_USER_HARD_DELETION_DELAY` y `OVERLEAF_PROJECT_HARD_DELETION_DELAY` se pueden configurar (en milisegundos) para modificar el plazo de caducidad de los usuarios/proyectos eliminados (90 días de forma predeterminada).

### Correcciones de errores

* Se ha corregido la representación del pie de página con enlaces.
* Se han mejorado los mensajes de error en los errores de inicio de sesión SAML.
* Se ha corregido que no se añadiera la entrada del registro de auditoría cuando se actualiza el estado de administrador de un usuario al iniciar sesión con SSO.
* Se han corregido errores del panel de historial cuando TLS está habilitado en Redis.
* Ahora se pueden detener las compilaciones cuando se usan compilaciones sin sandbox.

### Otros cambios

* Todos los enlaces a la página de estado (establecida mediante `OVERLEAF_STATUS_PAGE_URL`) ahora usan `HTTPS` y se abren en una nueva pestaña del navegador.
