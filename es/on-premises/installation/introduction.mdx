Al igual que Overleaf Server Pro, nuestro Ayakaleaf Pro se distribuye como un contenedor Docker y es un sustituto directo que, además, incluye funciones como SSO mediante LDAP y SAML2, seguridad mejorada, control de cambios, comentarios, nuestra versión optimizada de TeX Live, plantillas y panel de administración.

* Si solo quieres probar las funciones de Ayakaleaf Pro o la demo, puedes seguir nuestro tutorial [using-the-github-codespace.md](/es/on-premises/installation/using-the-github-codespace  "mention"). El entorno de demostración usa una instalación mínima de TeX Live, por lo que es posible que algunos de tus proyectos no compilen correctamente.
* Si nunca has desplegado ninguna versión de Overleaf, consulta primero [Configurar Docker](/es/on-premises/installation/setup-docker) para instalar Docker Engine y, después, instala Overleaf [using-the-toolkit](/es/on-premises/installation/using-the-toolkit  "mention").
* Si ya has desplegado Overleaf Community Edition, consulta [migrate-from-existing.md](/es/on-premises/installation/migrate-from-existing  "mention") para migrar a Ayakaleaf Pro.
* Si prefieres usar agentes como Claude o Codex, puedes consultar: [using-claude-or-codex.md](/es/on-premises/installation/using-claude-or-codex  "mention").
* Si necesitas desplegar en un entorno sin conexión o aislado (air-gapped), consulta: [air-gapped-offline-deployments.md](/es/on-premises/installation/air-gapped-offline-deployments  "mention").
* Si ya eres usuario de Server Pro, abre una issue para avisarnos antes de migrar a Ayakaleaf Pro, ya que los datos de las plantillas se almacenan en un formato ligeramente diferente. Estaremos encantados de ayudarte a migrar de Server Pro a Ayakaleaf Pro de forma gratuita.
* Si en algún momento te cansas de nuestro Ayakaleaf Pro y quieres volver a la edición oficial Overleaf Community Edition, es totalmente posible. No perderás ninguno de tus datos. Si usas el Overleaf Toolkit oficial, simplemente elimina tu archivo YAML de override. Si usas el toolkit de ayaka-notes, desactiva la opción `SERVER_PRO`. Todo volverá entonces a la Community Edition estándar.

### Requisitos de hardware

Hemos realizado las pruebas pertinentes y hemos comprobado que, si ejecutas Overleaf en un servidor de 2 núcleos y 2 GB de RAM, sus componentes principales (basados principalmente en Node.js) consumen aproximadamente 1 GB de memoria. Redis y MongoDB pueden requerir 0,5 GB adicionales, mientras que iniciar un contenedor Docker en sandbox para la compilación puede consumir otros 0,3 GB. Esto significa que un servidor de 2 núcleos y 2 GB solo puede gestionar, de forma realista, una compilación simultánea cada vez.

* Los requisitos mínimos de hardware para instalar Ayakaleaf Pro son una CPU de 2 núcleos y 3 GB de RAM.
* Debido al tamaño de nuestra imagen de TeX Live, se necesitan al menos 40 GB de almacenamiento para habilitar la compilación en sandbox.
* Si quieres instalar el conjunto completo de imágenes de TeX Live de 2020 a 2026, asegúrate de disponer de al menos 150 GB de espacio libre en disco.

Estas son algunas configuraciones de hardware recomendadas para distintos escenarios de uso:

| Caso de uso                                          | Configuración recomendada                                                                            |
| ---------------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| Uso personal, con colaboración ocasional             | 2 núcleos de CPU, 4 GB de RAM, 80 GB de almacenamiento                                               |
| Equipos pequeños, hasta 10 usuarios con colaboración ligera | 2 núcleos de CPU, 8 GB de RAM, 256 GB de almacenamiento                                       |
| Equipos medianos, hasta 100 usuarios                 | 4 núcleos de CPU, 16 GB de RAM, 1 TB de almacenamiento                                               |
| Despliegues a gran escala o universitarios           | Despliegue en clúster distribuido, con almacenamiento S3; contáctanos si necesitas ayuda con el despliegue |

### Requisitos de software

En cuanto a los requisitos de software, recomendamos usar una versión reciente y estable de Ubuntu (p. ej., Ubuntu 24.04 en 2025–2026, Ubuntu 22.04 en 2023–2024) junto con la última versión estable de Docker.

<Info>

La estabilidad es lo primero: elige la versión LTS de Ubuntu más reciente que lleve un tiempo publicada, no una que acabe de salir. Por ejemplo, a fecha de octubre de 2026, Ubuntu 26.04 no es compatible: incluye el kernel de Linux 7.0, y MongoDB se niega a arrancar en los kernels de Linux 6.19 a 7.0.13 ([detalles](https://www.mongodb.com/docs/manual/administration/production-notes/)), así que usa Ubuntu 24.04.

</Info>

No recomendamos desplegar Ayakaleaf Pro en Windows ni en otros sistemas operativos no compatibles como CentOS, ya que podrías encontrar problemas de compatibilidad o problemas inesperados durante la instalación y el funcionamiento.

Pero si quieres probar a desplegar Ayakaleaf Pro en sistemas basados en ARM o en macOS, te animamos a compartir tu experiencia y tus comentarios con la comunidad.

### Rendimiento de LaTeX

LaTeX es un programa de un solo hilo, lo que significa que solo puede utilizar un núcleo de CPU a la vez. Al compilar un único documento, el rendimiento está limitado principalmente por la velocidad de reloj de un solo núcleo de la CPU. Por tanto, cuanto mayor sea el rendimiento de un solo núcleo de tu CPU, más rápido podrás compilar un documento. Disponer de más núcleos de CPU solo es beneficioso cuando varios usuarios compilan documentos simultáneamente.

Tomando como ejemplo la [plantilla ThuThesis](https://www.overleaf.com/latex/templates/thuthesis-tsinghua-university-thesis-latex-template/cfwgcxtvkbsx), el tiempo de compilación es de unos 6 segundos en un Intel Core i9-14900K (5,6 GHz), mientras que tarda unos 13 segundos en una instancia Azure Standard D2as v5 (2 vCPU, 8 GiB de RAM) con un AMD EPYC 7763 (3,2 GHz).

Por supuesto, el rendimiento real de la compilación depende de tu configuración de hardware. La mayoría de las CPU de servidor no funcionan a velocidades de reloj tan altas como el 14900K, por lo que tendrás que buscar un equilibrio entre coste y velocidad de compilación.

Además, hemos realizado un análisis en profundidad del rendimiento de la compilación de LaTeX. Si te interesa, consulta nuestro blog [Overleaf Benchmark: A Deep Research of Concurrent LaTeX Compilation in Overleaf (SaaS and Self-host)](/es/blog/2026/overleaf-benchmark  "mention").
