title: 0. Configurar WSL 2 y Docker Desktop
description: Instala WSL 2 y Ubuntu y, a continuación, conecta Ubuntu con Docker Desktop en Windows.

Ayakaleaf Pro usa contenedores Linux. En Windows, instala Docker Desktop con su backend WSL 2 y ejecuta los scripts del Toolkit en Ubuntu.

WSL 2 proporciona el kernel Linux. Docker Desktop gestiona el motor de Docker en su propio entorno `docker-desktop`; al habilitar **WSL Integration**, la CLI de Docker de Ubuntu puede comunicarse con ese motor. A continuación, el Toolkit inicia la aplicación, MongoDB y Redis como contenedores. Con la compilación en sandbox habilitada, la aplicación usa el socket de Docker del motor para iniciar un contenedor de TeX Live independiente para cada compilación. No necesitas instalaciones de MongoDB, Redis ni TeX Live para Windows.

<Steps>
<Step title="Instalar WSL 2 y Ubuntu">
Abre **PowerShell como administrador** en Windows y ejecuta:

```powershell
wsl --install -d Ubuntu
```

Reinicia Windows si se te pide. Abre **Ubuntu** desde el menú Inicio y crea un nombre de usuario y una contraseña de Linux. Esta es la cuenta para `sudo` dentro de Ubuntu; es independiente de tu inicio de sesión de Windows.

De vuelta en **PowerShell**, actualiza WSL y comprueba la distribución:

```powershell
wsl --update
wsl --version
wsl --list --verbose
```

La fila de Ubuntu debe mostrar **VERSION 2**. Si muestra 1, usa el nombre exacto de la distribución que aparece en la lista:

```powershell
wsl --set-version Ubuntu 2
```

Docker requiere WSL **2.1.5 o posterior**; la versión del software WSL que muestra `wsl --version` y la columna **VERSION 2** de la distribución son comprobaciones distintas. Consulta la [solución de problemas de instalación](/es/on-premises/installation/using-docker-compose/windows/troubleshooting#wsl-or-docker-reports-that-virtualization-is-unavailable) y las [instrucciones de instalación de Microsoft](https://learn.microsoft.com/en-us/windows/wsl/install) si la instalación falla, y activa la virtualización por hardware en la BIOS/UEFI si WSL indica que no está disponible.
</Step>

<Step title="Instalar e iniciar Docker Desktop">
Descarga [Docker Desktop para Windows](https://docs.docker.com/desktop/setup/install/windows-install/) para tu procesador y ejecuta el instalador. Usa el backend **WSL 2** si se ofrece. Abre **Docker Desktop** desde el menú Inicio de Windows y espera a que se inicie el motor.

En **Settings → General** de Docker Desktop, activa **Use WSL 2 based engine** si se muestra la opción. En **Settings → Resources → WSL Integration**, habilita la integración para **Ubuntu** y selecciona **Apply** o **Apply & restart**. Si Ubuntu no es tu distribución predeterminada, activa explícitamente su propio interruptor.

Si falta WSL Integration, comprueba que Docker Desktop esté usando **contenedores Linux**. Consulta [la guía del backend WSL 2 de Docker](https://docs.docker.com/desktop/features/wsl/).

Usa la integración de Docker Desktop para esta guía. Instalar un segundo Docker Engine con `apt install docker.io` o iniciar `dockerd` dentro de Ubuntu crea una configuración separada y puede provocar conflictos. Si ya usas un Engine en Ubuntu, sigue las indicaciones de migración de Docker antes de cambiar; conserva los datos de aplicación y las copias de seguridad existentes.
</Step>

<Step title="Comprobar Docker desde Ubuntu">
Abre un terminal de **Ubuntu**. Ejecuta allí estos comandos, sin `sudo`:

```bash
docker version
docker compose version
docker ps
```

`docker version` debe mostrar tanto **Client** como **Server**. Una lista de contenedores vacía es normal en una instalación nueva. `docker --version` por sí solo no demuestra que el motor esté en ejecución.

Si `docker` no está disponible o no puede conectarse, vuelve a abrir Ubuntu después de aplicar WSL Integration y comprueba que Docker Desktop está en ejecución. Consulta [Solución de problemas](/es/on-premises/installation/using-docker-compose/windows/troubleshooting#docker-is-unavailable-in-ubuntu).
</Step>

<Step title="Comprobar los recursos y el socket de Docker">
Comprueba los recursos visibles para Docker:

```bash
docker info --format 'CPUs={{.NCPU}} Memory={{.MemTotal}} Kernel={{.KernelVersion}}'
df -h "$HOME"
ls -l /var/run/docker.sock
```

Para una instancia local pequeña, 4 CPU y 8 GB de memoria disponibles para Docker son una sugerencia de partida, no un mínimo medido. Reserva también memoria suficiente para Windows. Con el backend WSL 2, los límites de recursos se gestionan mediante la [configuración de WSL](https://learn.microsoft.com/en-us/windows/wsl/wsl-config), en lugar de con los controles deslizantes de recursos de Docker Desktop del Mac. Los cambios que requieren `wsl --shutdown` interrumpen todas las distribuciones de WSL y las cargas de trabajo de Docker en ejecución; aplícalos antes de iniciar la instancia.

Deja `DOCKER_SOCKET_PATH=/var/run/docker.sock` en la configuración del Toolkit. La aplicación necesita el socket de este motor para la compilación en sandbox. No cambies sus permisos a `777` para corregir errores de conexión; restaura en su lugar la integración de Docker Desktop.
</Step>
</Steps>
