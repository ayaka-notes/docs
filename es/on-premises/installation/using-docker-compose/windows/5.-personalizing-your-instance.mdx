---
title: 5. Personalizar tu instancia
description: Establece el puerto, la URL del sitio y la imagen de TeX Live, habilita la compilación en sandbox e inicia Ayakaleaf Pro en WSL 2.
icon: square-sliders
---

Ejecuta los comandos y edita los archivos en **Ubuntu**, desde `~/ayakaleaf-toolkit`.

<Steps>
<Step title="Ajustes del contenedor">
Edita las entradas existentes en `config/overleaf.rc`:

```bash title="config/overleaf.rc"
PROJECT_NAME=ayakaleaf-wsl
SERVER_PRO=true
OVERLEAF_LISTEN_IP=127.0.0.1
OVERLEAF_PORT=8080
SIBLING_CONTAINERS_ENABLED=true
DOCKER_SOCKET_PATH=/var/run/docker.sock
```

Mantén las rutas de datos predeterminadas y los servicios de MongoDB y Redis incluidos. El puerto `8080` es para el navegador local de Windows; vincularlo a `127.0.0.1` lo mantiene local. La compilación en sandbox usa un contenedor Linux independiente para cada compilación, en lugar de ejecutar TeX dentro del contenedor de la aplicación. El socket de Docker permite a la aplicación crear esos contenedores, y el Toolkit proporciona la ruta del host para los datos de compilación en `data/overleaf/data/compiles`.
</Step>

<Step title="Ajustes de la aplicación">
En `config/variables.env`, establece estos valores, sustituyendo cualquier entrada activa con el mismo nombre:

```dotenv title="config/variables.env"
OVERLEAF_SITE_URL=http://localhost:8080
TEX_LIVE_DOCKER_IMAGE=ghcr.io/ayaka-notes/texlive-full:2026.1
ALL_TEX_LIVE_DOCKER_IMAGES=ghcr.io/ayaka-notes/texlive-full:2026.1
ALL_TEX_LIVE_DOCKER_IMAGE_NAMES="TeX Live 2026"
```

La imagen full incluye los paquetes y las fuentes necesarios para una amplia variedad de proyectos. Reserva al menos 40 GB de almacenamiento libre para ella y la aplicación, más espacio para los datos de los proyectos y futuras actualizaciones.

Para una prueba rápida del despliegue, usa en su lugar la imagen **basic**, más pequeña. Basta para la prueba con un artículo sencillo del paso 6, pero no incluye el conjunto completo de paquetes y fuentes:

```dotenv
TEX_LIVE_DOCKER_IMAGE=ghcr.io/ayaka-notes/texlive-basic:2026.1
ALL_TEX_LIVE_DOCKER_IMAGES=ghcr.io/ayaka-notes/texlive-basic:2026.1
ALL_TEX_LIVE_DOCKER_IMAGE_NAMES="TeX Live 2026 Basic"
```

Elige uno de estos conjuntos, sin claves activas duplicadas. El [Dockerfile](https://github.com/ayaka-notes/texlive-full/blob/main/texlive/2026/Dockerfile.basic) de la imagen basic incluye `latexmk`, XeTeX y `fontspec`, pero no `ctex` ni la colección completa de fuentes. Que falte un paquete de LaTeX en basic no indica por sí solo un problema del sandbox.

Genera un secreto de sesión:

```bash
openssl rand -hex 32
```

Añade el resultado como `OVERLEAF_SESSION_SECRET` en `config/variables.env`. Conserva también el secreto de token de invitación generado. Para una instancia local sin correo electrónico, deja sin establecer los ajustes SMTP y `OVERLEAF_EMAIL_FROM_ADDRESS`.
</Step>

<Step title="Iniciar tu instancia">
```bash
bin/up -d
```

El Toolkit inicia MongoDB, inicializa su replica set, descarga la imagen de TeX Live seleccionada e inicia Redis y la aplicación. Puede parecer que se detiene mientras se descarga una imagen grande. No ejecutes un segundo `bin/up` mientras el primero sigue trabajando.

En otro terminal de Ubuntu, comprueba:

```bash
cd "$HOME/ayakaleaf-toolkit"
bin/docker-compose ps
bin/docker-compose logs --tail=100 mongo
bin/docker-compose logs --tail=100 -f sharelatex
```

Pulsa `Ctrl+C` para dejar de seguir los registros; los contenedores en segundo plano siguen ejecutándose. Si el arranque falla en MongoDB, sigue [MongoDB no arranca](/es/on-premises/installation/using-docker-compose/windows/troubleshooting#mongodb-fails-to-start) antes de reintentarlo. No elimines su directorio de datos para restablecer una instalación existente.

Comprueba el puerto y la página de primer arranque:

```bash
bin/docker-compose port sharelatex 80
curl -I http://localhost:8080/launchpad
```

El puerto debería ser `127.0.0.1:8080`. Si la solicitud HTTP falla al principio, espera a que la aplicación termine de inicializarse.
</Step>

<Step title="Abrir la instancia desde Windows">
En tu **navegador de Windows**, abre [http://localhost:8080/launchpad](http://localhost:8080/launchpad). Usa también esta dirección en Windows, en lugar de una dirección IP temporal de WSL.

Para comprobar el acceso HTTP desde Windows independientemente del navegador, ejecuta en **PowerShell**:

```powershell
curl.exe -I http://localhost:8080/launchpad
```

Si Ubuntu puede acceder a la página pero Windows no, consulta [Windows no puede abrir localhost](/es/on-premises/installation/using-docker-compose/windows/troubleshooting#windows-cannot-open-localhost).
</Step>
</Steps>
