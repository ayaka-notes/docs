### Echando un vistazo {#taking-a-look-around}

Ahora que tienes una copia local del Toolkit, echemos un vistazo a la estructura del repositorio con el comando `ls`.

```bash title="Run this"
ls -l
```

<Info>

El comando `ls -l` muestra una vista detallada en formato largo del contenido de un directorio, con información adicional de los archivos, como permisos, propietario y tamaño.

</Info>

Si todo se ha clonado correctamente, deberías ver algo como esto:

```text
drwxr-xr-x 3 fry fry  4096 Aug 30 14:16 bin
-rw-r--r-- 1 fry fry  6465 Aug 30 14:16 CHANGELOG.md
drwxr-xr-x 2 fry fry  4096 Sep  6 12:43 config
drwxr-xr-x 5 fry fry  4096 Aug 30 14:22 data
drwxr-xr-x 3 fry fry  4096 Aug 30 14:16 doc
drwxr-xr-x 3 fry fry  4096 Aug 30 14:16 lib
-rw-r--r-- 1 fry fry 34520 Aug 30 14:16 LICENSE
-rw-r--r-- 1 fry fry  1178 Aug 30 14:16 README.md
```

<Info>

Todos los archivos de configuración propios del usuario se encuentran en el directorio `config/`. Este directorio está **excluido** del sistema de control de versiones git, por lo que no se modificará al actualizar el Toolkit.

</Info>

## Estructura del repositorio {#repository-layout}

| Nombre   | Descripción                                                                                                                                                                                                                                               |
| -------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `bin`    | Esta carpeta contiene una colección de scripts que te ayudan a gestionar tu instancia del servidor de Overleaf. Puedes leer más sobre estos scripts en la sección Comandos más abajo.                                                                     |
| `config` | Esta carpeta contiene tus propios archivos de configuración locales.                                                                                                                                                                                      |
| `lib`    | Esta carpeta contiene los archivos de configuración base que utiliza el Toolkit.                                                                                                                                                                          |
| `data`   | Por defecto, esta carpeta contiene la ubicación de almacenamiento de MongoDb, Redis y Overleaf. Para más información, consulta la sección [Datos persistentes](/es/on-premises/configuration/overleaf-toolkit/files-and-locations#persistent-data) más abajo. |

<Warning>

Recomendamos **no** modificar directamente los archivos fuera de la carpeta `/config`. Si necesitas hacer cambios, puedes realizarlos mediante variables de entorno definidas en **config/variables.env** o en **config/overleaf.rc**.\
Por ejemplo, para establecer la imagen del servicio `mongo`, en lugar de editar directamente `lib/docker-compose.mongo.yml`, establece la imagen mediante la variable de entorno `MONGO_IMAGE` en `config/overleaf.rc`. Para más información, consulta la página [Ajustes del Toolkit](/es/on-premises/configuration/overleaf-toolkit/toolkit-settings).

</Warning>

<Info>

El Toolkit **no** modificará ningún dato del directorio `config/` sin tu permiso.

</Info>

## Comandos {#commands}

Ejecuta estos scripts desde el directorio del Toolkit. Cada uno muestra sus opciones con `--help`.

| Comando | Qué hace |
| --- | --- |
| `bin/init` | Crea los archivos de configuración en `config/` la primera vez. `bin/init --tls` añade la configuración del proxy TLS de NGINX. |
| `bin/up` | Crea e inicia los contenedores (`bin/docker-compose up`). Añade `-d` para ejecutarlos en segundo plano en lugar de seguir los registros. Ejecútalo después de cada cambio en `config/`: vuelve a crear los contenedores cuya configuración haya cambiado. |
| `bin/start` | Vuelve a iniciar los contenedores existentes (`bin/docker-compose start`). No aplica los cambios de configuración. |
| `bin/stop` | Detiene los contenedores y los conserva (`bin/docker-compose stop`). |
| `bin/docker-compose down` | Elimina los contenedores y su red y conserva los datos. `bin/up -d` los vuelve a crear. |
| `bin/docker-compose` | Ejecuta `docker compose` con los archivos del Toolkit, por ejemplo `bin/docker-compose ps` o `bin/docker-compose restart sharelatex`. |
| `bin/logs` | Muestra o sigue los registros de uno o varios servicios, por ejemplo `bin/logs -f web`. |
| `bin/error-logs` | Como `bin/logs`, pero muestra solo los errores. |
| `bin/shell` | Abre una shell dentro del contenedor `sharelatex`. |
| `bin/mongo` | Abre una shell de MongoDB en la base de datos `sharelatex`. |
| `bin/run-script` | Ejecuta un script incluido dentro del contenedor `sharelatex`. |
| `bin/doctor` | Comprueba el host y la configuración, e imprime un informe para compartir cuando pidas ayuda. |
| `bin/images` | Muestra las imágenes de Docker de Overleaf que hay en el host. |
| `bin/backup-config` | Copia el directorio `config/` a una ubicación de copia de seguridad (copia, zip o tar). |
| `bin/upgrade` | Actualiza el Toolkit y la imagen de Overleaf paso a paso; consulta [Actualizar tu despliegue](/es/on-premises/maintenance/upgrading-your-deployment). |
| `bin/rename-env-vars-5-0`, `bin/rename-rc-vars` | Migraciones puntuales de los antiguos nombres de variables `SHARELATEX_*` a `OVERLEAF_*`. |

### Qué se conserva al reconstruir {#what-survives-a-rebuild}

Una reconstrucción sustituye un contenedor por uno nuevo. Solo los directorios de datos (`data/` de forma predeterminada) y `config/` están fuera del contenedor, así que todo lo demás se pierde con él: los paquetes instalados o los archivos editados mediante `bin/shell`, y los registros de `/var/log/overleaf`, salvo que configure [`OVERLEAF_LOG_PATH`](/es/on-premises/configuration/overleaf-toolkit/logging).

| Comando | Sustituye el contenedor | Cambios hechos dentro | Registros | `data/` y `config/` |
| --- | --- | --- | --- | --- |
| `bin/stop` y luego `bin/start` | No | Se conservan | Se conservan | Se conservan |
| `bin/docker-compose restart sharelatex` | No | Se conservan | Se conservan | Se conservan |
| `bin/up`, sin cambios en `config/` | No | Se conservan | Se conservan | Se conservan |
| `bin/up`, tras un cambio en `config/` | Sí | **Se pierden** | **Se pierden** | Se conservan |
| `bin/up -d --force-recreate` | Sí | **Se pierden** | **Se pierden** | Se conservan |
| `bin/docker-compose down` y luego `bin/up -d` | Sí | **Se pierden** | **Se pierden** | Se conservan |
| `bin/upgrade`, a una versión nueva | Sí | **Se pierden** | **Se pierden** | Se conservan |

* Los comandos que conservan el contenedor no aplican los cambios de `config/`. Use `bin/up` para ello.
* Para reconstruir todos los contenedores, ejecute `bin/docker-compose down` y luego `bin/up -d`. Sus proyectos, usuarios e historial se conservan.
* Haga los cambios permanentes mediante `config/variables.env`, `config/overleaf.rc` o `config/docker-compose.override.yml`, no dentro de un contenedor.
* Sin `OVERLEAF_SESSION_SECRET`, un contenedor nuevo firma las sesiones con un secreto nuevo, así que todos tienen que volver a iniciar sesión.
* Sus datos solo se eliminan si usted mismo elimina los directorios de datos. Antes de una actualización, haga una [copia de seguridad](/es/on-premises/maintenance/data-and-backups).

<Info>

Si cada `bin/up` cierra la sesión de todos los usuarios, establece `OVERLEAF_SESSION_SECRET`. Sin ella, las cookies de sesión se firman con un secreto que se vuelve a generar cada vez que se crea de nuevo el contenedor; consulta las preguntas y respuestas de [Variables de entorno](/es/on-premises/configuration/overleaf-toolkit/environment-variables).

</Info>
