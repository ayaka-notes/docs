### Crear el administrador y un primer proyecto {#create-the-administrator-and-a-first-project}

Abre [http://localhost:8080/launchpad](http://localhost:8080/launchpad), crea la primera cuenta de administrador e inicia sesión. Después, sigue [6. Tareas posteriores a la instalación](/es/on-premises/installation/using-docker-compose/linux/6.-post-installation-tasks) de la guía de Linux, usando el puerto `8080` en sus URL de ejemplo.

### Verificar la compilación {#verify-compilation}

Que la página de inicio de sesión se abra no demuestra que los contenedores de compilación independientes y sus montajes de datos funcionen. Crea un proyecto en blanco y compila este `main.tex`:

```latex
\documentclass{article}
\begin{document}
Ayakaleaf Pro on macOS.
\end{document}
```

La vista previa del PDF debería mostrar el texto. Si es necesario, selecciona TeX Live 2026 en la configuración del proyecto.

Para un proyecto con texto en chino, selecciona **XeLaTeX** como compilador y prueba:

```latex
\documentclass{ctexart}
\begin{document}
你好，Ayakaleaf Pro。
\end{document}
```

### Verificar la persistencia {#verify-persistence}

```bash
bin/stop
bin/start
```

Vuelve a abrir el proyecto y compílalo de nuevo. Tu cuenta, el código fuente y los archivos del proyecto deberían seguir ahí. Con las rutas predeterminadas, los datos en uso están en el directorio `data/` del Toolkit en tu Mac.

### Mantener la instancia disponible {#keep-the-instance-available}

Mientras el Mac está en reposo, macOS suspende la máquina virtual de Docker Desktop con todos los contenedores que contiene: nadie puede abrir la instancia, y una compilación en curso se detiene hasta que el Mac se reactiva. Solo importa el reposo del sistema. La pantalla puede apagarse.

Si otras personas usan la instancia, o dejas tareas largas en ejecución, mantén el Mac conectado a la corriente e impide el reposo automático; consulta [Ajustar la configuración de reposo y activación del Mac](https://support.apple.com/guide/mac-help/set-sleep-and-wake-settings-mchle41a6ccd/mac):

| Mac | Ajuste |
| --- | --- |
| Mac de escritorio (Mac mini, iMac, Mac Studio, Mac Pro) | **Ajustes del Sistema → Energía**: activa **Evitar el reposo automático cuando la pantalla esté apagada** |
| MacBook | **Ajustes del Sistema → Batería → Opciones**: activa **Evitar el reposo automático con el adaptador de corriente cuando la pantalla esté apagada**. Esto solo se aplica mientras el adaptador de corriente está conectado, y cerrar la tapa sigue poniendo el MacBook en reposo |

Para mantener el Mac activo solo durante un tiempo, ejecuta en su lugar `caffeinate -i` en una ventana de Terminal. Impide el reposo por inactividad hasta que pulses `Ctrl+C` o cierres la ventana.

Docker Desktop es una app de tu sesión de usuario. Para que la instancia vuelva a estar disponible después de un reinicio, activa **Start Docker Desktop when you sign in to your computer** en **Settings → General** de Docker Desktop. Los contenedores del Toolkit usan `restart: always`, por lo que Docker los vuelve a iniciar en cuanto Docker Desktop se ejecuta, sin `bin/up`. Hasta que alguien inicie sesión en el Mac después de un reinicio, la instancia permanece detenida.

<Info>

Un Mac que permanece activo consume más energía. Para un servicio que debe estar siempre accesible, recomendamos un servidor Linux; consulta [Linux](/es/on-premises/installation/using-docker-compose/linux).

</Info>

### Uso diario {#daily-use}

Abre Docker Desktop antes de gestionar la instancia. En un terminal nuevo:

```bash
export PATH="$(brew --prefix gnu-sed)/libexec/gnubin:$PATH"
cd "$HOME/ayakaleaf-toolkit"
```

| Tarea | Comando |
| --- | --- |
| Iniciar los contenedores existentes | `bin/start` |
| Detener los contenedores y conservar los datos | `bin/stop` |
| Aplicar cambios de configuración | `bin/up -d` |
| Comprobar el estado | `bin/docker-compose ps` |
| Leer los registros de arranque | `bin/docker-compose logs --tail=100 sharelatex` |
| Leer los registros del compilador | `bin/logs -f clsi` |

`bin/start` no aplica los cambios de `config/`: ejecuta `bin/up -d` después de editar la configuración. Conserva `config/` y `data/`, y sigue [Datos y copias de seguridad](/es/on-premises/maintenance/data-and-backups) antes de una actualización o antes de trasladar la instalación. Copiar los archivos de la base de datos mientras MongoDB escribe en ellos no es una copia de seguridad coherente.

Mantén la instancia en `127.0.0.1` para uso local. Para dar servicio a otros equipos, establece de forma deliberada la dirección de escucha, la URL del sitio y HTTPS; consulta [5. Personalizar tu instancia](/es/on-premises/installation/using-docker-compose/linux/5.-personalizing-your-instance) de la guía de Linux.

Si algo no funciona, consulta [Solución de problemas](/es/on-premises/installation/using-docker-compose/macos/troubleshooting).
