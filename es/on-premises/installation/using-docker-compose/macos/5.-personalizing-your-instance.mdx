---
title: 5. Personalizar tu instancia
description: Establece el puerto, la URL del sitio y la imagen de TeX Live para una instancia local en tu Mac, comprueba el kernel de la máquina virtual de Docker e inicia Ayakaleaf Pro.
icon: square-sliders
---

<Steps>
<Step title="Ajustes del contenedor">
Edita estas entradas existentes en `config/overleaf.rc`:

```bash title="config/overleaf.rc"
PROJECT_NAME=ayakaleaf-macos
SERVER_PRO=true
OVERLEAF_LISTEN_IP=127.0.0.1
OVERLEAF_PORT=8080
SIBLING_CONTAINERS_ENABLED=true
DOCKER_SOCKET_PATH=/var/run/docker.sock
```

Mantén las rutas de datos predeterminadas y los servicios de MongoDB y Redis incluidos. Con `OVERLEAF_LISTEN_IP=127.0.0.1`, solo los navegadores de este Mac pueden abrir la instancia.
</Step>

<Step title="Ajustes de la aplicación">
En `config/variables.env`, establece estos valores, sustituyendo cualquier entrada activa con el mismo nombre:

```dotenv title="config/variables.env"
OVERLEAF_SITE_URL=http://localhost:8080
TEX_LIVE_DOCKER_IMAGE=ghcr.io/ayaka-notes/texlive-full:2026.1
ALL_TEX_LIVE_DOCKER_IMAGES=ghcr.io/ayaka-notes/texlive-full:2026.1
ALL_TEX_LIVE_DOCKER_IMAGE_NAMES="TeX Live 2026"
```

Genera un secreto de sesión:

```bash
openssl rand -hex 32
```

Añade el resultado como `OVERLEAF_SESSION_SECRET` en `config/variables.env`. Sin él, cada `bin/up` que vuelve a crear el contenedor cierra la sesión de todos los usuarios; consulta [Variables de entorno](/es/on-premises/configuration/overleaf-toolkit/environment-variables).

Para una instancia local sin correo electrónico, deja sin establecer los ajustes SMTP y `OVERLEAF_EMAIL_FROM_ADDRESS`. Git Bridge, la autenticación externa y las demás integraciones pueden añadirse más adelante con sus propias [páginas de configuración](/es/on-premises/configuration/overleaf-toolkit).
</Step>

<Step title="Comprobar el kernel Linux de la máquina virtual de Docker" id="check-the-docker-vms-linux-kernel">
MongoDB se ejecuta sobre el kernel Linux de la máquina virtual de Docker Desktop, no sobre macOS. Comprueba su versión antes del primer arranque:

```bash
docker info --format '{{.KernelVersion}}'
```

MongoDB documenta una incompatibilidad con los kernels Linux **6.19 a 7.0.13**, que también afecta a MongoDB en Docker. La solución es un kernel **7.0.14 o posterior**, que llega con una actualización de Docker Desktop; consulta [las notas de producción de MongoDB](https://www.mongodb.com/docs/manual/administration/production-notes/).

Si tu máquina virtual de Docker usa un kernel afectado, añade lo siguiente a `config/docker-compose.override.yml`, combinado con los `services` que ya tengas ahí:

```yaml title="config/docker-compose.override.yml"
services:
  mongo:
    environment:
      GLIBC_TUNABLES: glibc.pthread.rseq=1
```

<Warning>

Actualiza a un kernel corregido cuando esté disponible. Si tu kernel está fuera del rango afectado, esta solución alternativa no es necesaria.

</Warning>
</Step>

<Step title="Iniciar tu instancia">
Desde el directorio del Toolkit, ejecuta:

```bash
bin/up -d
```

El Toolkit inicializa el replica set de MongoDB, descarga la imagen de TeX Live e inicia la aplicación. La primera descarga tarda un rato. Para seguir el progreso:

```bash
bin/docker-compose ps
bin/docker-compose logs --tail=100 -f sharelatex
```

Pulsa `Ctrl+C` para dejar de seguir los registros. Los contenedores siguen ejecutándose.

Comprueba el puerto publicado y la página de primer arranque:

```bash
bin/docker-compose port sharelatex 80
curl -I http://localhost:8080/launchpad
```

El puerto debería ser `127.0.0.1:8080`.
</Step>
</Steps>

<Info>

Para abrir más adelante la instancia desde otros equipos, cambia la dirección de escucha y la URL del sitio, y configura HTTPS, como se describe en [5. Personalizar tu instancia](/es/on-premises/installation/using-docker-compose/linux/5.-personalizing-your-instance) de la guía de Linux. En ese caso, el Mac tiene que permanecer activo; consulta [Mantener la instancia disponible](/es/on-premises/installation/using-docker-compose/macos/6.-post-installation-tasks#keep-the-instance-available).

</Info>
