### Migrar desde Overleaf Community

#### Caso 01: desde Overleaf Toolkit

Si utilizas el Overleaf Toolkit oficial para Overleaf Community, basta con añadir un archivo llamado `docker-compose.override.yml` con el siguiente contenido (o uno similar) en el directorio `overleaf-toolkit/config`:

```yml title="docker-compose.override.yml"
---
services:
    sharelatex:
        image: ghcr.io/ayaka-notes/overleaf-pro:X.x.x # change to specific version
```

Para iniciar tu instancia, ejecuta:

```bash
bin/up
```

¡Eso es todo! Ya lo tienes listo. A continuación, puedes verificar que tu instancia de Ayakaleaf se ejecuta correctamente y que puedes acceder a la interfaz web. Cuando todo funcione, continúa con los pasos de [configuración](/es/on-premises/configuration/overleaf-toolkit) para habilitar funcionalidades avanzadas como:

* [sandboxed-compiles.md](/es/on-premises/configuration/overleaf-toolkit/sandboxed-compiles  "mention")
* [authentication](/es/on-premises/configuration/overleaf-toolkit/authentication  "mention")
* [github-synchronisation.md](/es/on-premises/configuration/overleaf-toolkit/github-synchronisation  "mention")
* [zotero-integration.md](/es/on-premises/configuration/overleaf-toolkit/zotero-integration  "mention")

#### Caso 02: desde un archivo Docker Compose

Si utilizas un `docker-compose.yml` independiente, primero migra a Overleaf Toolkit. El Toolkit simplifica la instalación local, las actualizaciones y el mantenimiento.

Sigue la guía [docker-compose.yml-to-toolkit-migration.md](/es/on-premises/maintenance/docker-compose.yml-to-toolkit-migration  "mention") para convertir tu despliegue existente. Conserva tu configuración actual y las rutas de los volúmenes de datos durante esta migración.

Cuando el despliegue con el Toolkit esté en funcionamiento, sigue [#from-overleaf-toolkit](/es/on-premises/installation/migrate-from-existing#from-overleaf-toolkit  "mention") para cambiar su imagen a Ayakaleaf Pro. Inicia la instancia con `bin/up` y verifica que puedes acceder a la interfaz web.

### Migrar desde Overleaf Server Pro

Si actualmente ejecutas una instancia con licencia comercial de [Overleaf Server Pro](https://www.overleaf.com/for/enterprises) y quieres migrar a Ayakaleaf Pro, ten en cuenta que la migración puede requerir trabajo adicional, ya que ciertos formatos de datos (`templates`) podrían no ser totalmente compatibles. No obstante, estaremos encantados de ayudarte. [Abre una incidencia](https://github.com/ayaka-notes/ayakaleaf-pro/issues) o contáctanos en [ayaka-notes@outlook.com](mailto:ayaka-notes@outlook.com), y te ayudaremos a migrar a Ayakaleaf Pro de forma gratuita.

***

### Migrar desde Overleaf CEP

Recibimos con frecuencia preguntas de usuarios sobre si pueden migrar de [Overleaf CEP](https://github.com/yu-i-i/overleaf-cep) a Ayakaleaf Pro. En la mayoría de los casos, Overleaf CEP y Ayakaleaf Pro ofrecen funcionalidades muy similares y, a partir de la versión 6.2.0, siguen siendo compatibles a nivel de datos. Ambos proyectos pueden publicar funcionalidades en momentos distintos; por ejemplo, podemos incorporar (cherry-pick) una funcionalidad de Overleaf CEP, y viceversa. Aunque nuestras implementaciones de una misma funcionalidad pueden diferir ligeramente, en general no hay un motivo de peso para migrar.

Si aun así quieres migrar a Ayakaleaf Pro o probarlo, consulta: [#case-01-from-overleaf-toolkit](/es/on-premises/installation/migrate-from-existing#case-01-from-overleaf-toolkit  "mention"). El proceso de migración es el mismo.

***

### Migrar desde Overleaf SaaS

Lamentablemente, migrar desde la plataforma SaaS de Overleaf a una instancia autoalojada de Ayakaleaf Pro puede resultar bastante más difícil. Actualmente, el único método disponible de forma general es descargar cada proyecto como archivo ZIP y después subirlo a tu instancia autoalojada de Ayakaleaf Pro. Así solo se transfieren los archivos actuales del proyecto, lo que significa que _**perderás**_:

* Todo el historial del proyecto y las revisiones anteriores
* Todos los comentarios y cambios registrados
* Todos los metadatos de Git y el historial de commits
* Todos los vínculos y ajustes de sincronización con GitHub
* Todos los vínculos entre archivos BibTeX y plataformas de gestión de referencias de terceros

***

### Migrar desde un fork de Overleaf de terceros

Es posible que Ayakaleaf Pro no admita funcionalidades específicas de un fork de Overleaf de terceros. Cuando un fork se aleja significativamente del código base de Overleaf upstream —o introduce cambios sin mantener la compatibilidad con upstream—, integrar las versiones posteriores de Overleaf puede volverse extremadamente difícil. Puedes intentar igualmente el método de migración descrito arriba, pero no se garantiza la compatibilidad, y es posible que no podamos ofrecer ayuda ni soporte técnico para migraciones desde forks no compatibles.
