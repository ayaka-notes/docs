### Migrar desde Overleaf Community

#### Caso 01: desde el Overleaf Toolkit

Si usas el Overleaf Toolkit oficial para Overleaf Community, solo tienes que añadir un archivo llamado `docker-compose.override.yml` con el siguiente contenido (o uno similar) en el directorio `overleaf-toolkit/config`:

```yml title="docker-compose.override.yml"
---
services:
    sharelatex:
        image: ghcr.io/ayaka-notes/overleaf-pro:X.x.x # change to specific version
```

Para iniciar tu instancia, ejecuta:

```bash
bin/up
```

¡Eso es todo! Ya está todo listo. A continuación, puedes verificar que tu instancia de Ayakaleaf funciona correctamente y que puedes acceder a la interfaz web. Cuando todo funcione, continúa con los pasos de [configuración](/es/on-premises/configuration/overleaf-toolkit) que se indican a continuación para habilitar funciones avanzadas como:

* [sandboxed-compiles.md](/es/on-premises/configuration/overleaf-toolkit/sandboxed-compiles  "mention")
* [authentication](/es/on-premises/configuration/overleaf-toolkit/authentication  "mention")
* [github-synchronisation.md](/es/on-premises/configuration/overleaf-toolkit/github-synchronisation  "mention")
* [zotero-integration.md](/es/on-premises/configuration/overleaf-toolkit/zotero-integration  "mention")

#### Caso 02: desde un archivo Docker Compose

Si usas un `docker-compose.yml` independiente, primero mígralo al Overleaf Toolkit. El Toolkit simplifica la instalación local, las actualizaciones y el mantenimiento.

Sigue [docker-compose.yml-to-toolkit-migration.md](/es/on-premises/maintenance/docker-compose.yml-to-toolkit-migration  "mention") para convertir tu despliegue existente. Conserva tu configuración actual y las rutas de los volúmenes de datos durante esta migración.

Cuando el despliegue del Toolkit esté en funcionamiento, sigue [#from-overleaf-toolkit](/es/on-premises/installation/migrate-from-existing#from-overleaf-toolkit  "mention") para cambiar su imagen a Ayakaleaf Pro. Inicia la instancia con `bin/up` y verifica que puedes acceder a la interfaz web.

### Migrar desde Overleaf Server Pro

Si actualmente ejecutas una instancia con licencia comercial de [Overleaf Server Pro](https://www.overleaf.com/for/enterprises) y quieres migrar a Ayakaleaf Pro, ten en cuenta que la migración puede requerir trabajo adicional, ya que algunos formatos de datos (`templates`) pueden no ser totalmente compatibles. No obstante, estaremos encantados de ayudarte. [Abre una incidencia](https://github.com/ayaka-notes/ayakaleaf-pro/issues) o contáctanos en [ayaka-notes@outlook.com](mailto:ayaka-notes@outlook.com), y te ayudaremos a migrar a Ayakaleaf Pro de forma gratuita.

***

### Migrar desde Overleaf CEP

A menudo recibimos preguntas de usuarios sobre si pueden migrar de [Overleaf CEP](https://github.com/yu-i-i/overleaf-cep) a Ayakaleaf Pro. En la mayoría de los casos, Overleaf CEP y Ayakaleaf Pro ofrecen una funcionalidad prácticamente equivalente y siguen siendo compatibles a nivel de datos a partir de la versión 6.2.0. Los dos proyectos pueden publicar funciones en momentos distintos; por ejemplo, podemos incorporar (cherry-pick) una función de Overleaf CEP, y viceversa. Aunque nuestras implementaciones de una misma función pueden diferir ligeramente, por lo general no hay ninguna razón de peso para migrar.

Si aun así quieres migrar a Ayakaleaf Pro o probarlo, consulta: [#case-01-from-overleaf-toolkit](/es/on-premises/installation/migrate-from-existing#case-01-from-overleaf-toolkit  "mention"). El proceso de migración es el mismo.

***

### Migrar desde Overleaf SaaS

Lamentablemente, migrar desde la plataforma SaaS de Overleaf a una instancia autoalojada de Ayakaleaf Pro puede ser considerablemente más difícil. Actualmente, el único método disponible de forma general es descargar cada proyecto como archivo ZIP y luego subirlo a tu instancia autoalojada de Ayakaleaf Pro. Esto solo transfiere los archivos actuales del proyecto, lo que significa que _**perderás**_:

* Todo el historial del proyecto y las revisiones anteriores
* Todos los comentarios y cambios controlados
* Todos los metadatos de Git y el historial de commits
* Todos los enlaces y ajustes de sincronización con GitHub
* Todos los vínculos entre los archivos BibTeX y las plataformas de gestión de referencias de terceros

***

### Migrar desde un fork de Overleaf de terceros

Es posible que Ayakaleaf Pro no admita funciones específicas de un fork concreto de Overleaf de terceros. Cuando un fork se aleja significativamente del código base upstream de Overleaf —o introduce cambios sin mantener la compatibilidad con upstream—, fusionar las versiones posteriores de Overleaf puede resultar extremadamente difícil. Aun así, puedes probar el método de migración descrito anteriormente, pero no se garantiza la compatibilidad y es posible que no podamos ofrecer ayuda ni soporte técnico para migraciones desde forks no compatibles.
