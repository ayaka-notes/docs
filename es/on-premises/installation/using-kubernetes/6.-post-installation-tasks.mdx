### Crear tu primera cuenta de administrador {#creating-your-first-administrator-account}

Abre `OVERLEAF_SITE_URL` seguido de `/launchpad`, por ejemplo `http://192.0.2.10:30080/launchpad`, y registra la cuenta de administrador como en las [tareas posteriores a la instalación del Toolkit](/es/on-premises/installation/using-docker-compose/linux/6.-post-installation-tasks). Después, crea un proyecto de ejemplo y compílalo.

También puedes crear usuarios desde la línea de comandos:

```bash
kubectl -n overleaf exec deploy/overleaf -- bash -c \
  'cd /overleaf/services/web && node modules/server-ce-scripts/scripts/create-user.mjs --admin --email=admin@example.com'
```

Muestra un enlace que permite establecer la contraseña.

### Comprobar que las compilaciones están aisladas {#checking-that-compiles-are-sandboxed}

Compila un proyecto y, después, examina el nodo que ejecuta el pod:

```bash
kubectl -n overleaf get pod -l app=overleaf -o wide   # NODE column
# on that node:
sudo docker ps -a --filter ancestor=ghcr.io/ayaka-notes/texlive-full:2026.1
ls -ln /srv/overleaf/compiles                          # owned by uid 33 (www-data)
```

Cada compilación aparece como un contenedor de corta duración llamado `project-<project id>-<user id>-...`.

### Registros y una shell {#logs-and-a-shell}

| Toolkit          | Kubernetes                                                               |
| ---------------- | ------------------------------------------------------------------------ |
| `bin/logs web`   | `kubectl -n overleaf exec deploy/overleaf -- tail -f /var/log/overleaf/web.log` |
| `bin/shell`      | `kubectl -n overleaf exec -it deploy/overleaf -- bash`                    |
| `bin/up`         | `kubectl apply -f .` y después `kubectl -n overleaf rollout restart deployment/overleaf` |

El contenedor escribe un archivo de registro por servicio en `/var/log/overleaf/` (`web.log`, `clsi.log`, `real-time.log`, `document-updater.log`, ...); `kubectl logs` muestra la salida de arranque.

### Qué se conserva al reiniciar {#what-survives-a-restart}

`kubectl rollout restart` sustituye los pods. Solo se conserva lo que está en un volumen. Los cambios hechos dentro de un pod mediante `kubectl exec`, como paquetes instalados o archivos editados, se pierden con él, y también los registros salvo que `/var/log/overleaf` esté en un volumen; consulte [Registro](/es/on-premises/configuration/kubernetes/logging). Haga los cambios permanentes en sus manifiestos.

### Preguntas y respuestas {#q&a}

<Accordion title="La compilación falla o nunca termina.">

<strong>Respuesta:</strong> Comprueba, en el nodo que ejecuta el pod, que Docker está en ejecución y tiene la imagen indicada en `TEX_LIVE_DOCKER_IMAGE`, y que `SANDBOXED_COMPILES_HOST_DIR_*` coincide con las rutas `hostPath`. `/var/log/overleaf/clsi.log` en el pod indica el paso que falla.

</Accordion>

<Accordion title="Los usuarios pierden la sesión tras cada reinicio del pod.">

<strong>Respuesta:</strong> Falta `OVERLEAF_SESSION_SECRET` en el Secret `overleaf-secrets`; consulta el [paso 2](/es/on-premises/installation/using-kubernetes/2.-create-the-namespace-and-secrets).

</Accordion>
