El [Toolkit](/es/on-premises/installation/using-docker-compose) es la forma recomendada de ejecutar Ayakaleaf Pro en un único servidor. Si ya utilizas un clúster de Kubernetes, esta sección despliega el mismo contenedor en él con manifiestos simples de `kubectl`: sin imágenes adicionales ni chart de Helm.

Al final de esta sección tendrás una instancia de Ayakaleaf Pro con compilaciones aisladas, un replica set de MongoDB y Redis, todo en el namespace `overleaf`. Para ejecutar varias instancias detrás de un balanceador de carga, continúa después con [Escalado horizontal](/es/on-premises/configuration/kubernetes/horizontal-scaling).

<Info>

La compatibilidad con Kubernetes es experimental. No publicamos un chart de Helm ni imágenes específicas para Kubernetes. Los manifiestos de estas páginas son los que probamos en Kubernetes 1.37 (kubeadm, containerd 2.4, flannel) con tres nodos de 2 vCPU y 4 GB de memoria cada uno. Adapta el almacenamiento, la red y el ingress a tu clúster.

</Info>

### Cómo encajan las piezas {#how-the-pieces-fit}

| Toolkit (un servidor)                        | Kubernetes                                                               |
| -------------------------------------------- | ------------------------------------------------------------------------ |
| `config/variables.env`                       | ConfigMap `overleaf-env` y Secret `overleaf-secrets`                     |
| contenedor `sharelatex`                      | Deployment `overleaf` (un pod que ejecuta todos los servicios de Overleaf) |
| contenedores `mongo` y `redis`               | StatefulSets `mongo` (replica set) y `redis`, o tus servicios gestionados |
| `~/overleaf-toolkit/data/overleaf`           | PersistentVolumeClaim `overleaf-data`                                    |
| Docker en el host, usado para las compilaciones | Docker Engine en cada nodo que ejecuta Ayakaleaf Pro                  |
| `bin/up`, `bin/logs`, `bin/shell`            | `kubectl apply`, `kubectl logs`, `kubectl exec`                          |

### Qué necesitas {#what-you-need}

* Un clúster de Kubernetes en el que puedas instalar paquetes: cada nodo que pueda ejecutar Ayakaleaf Pro necesita **Docker Engine**, porque las compilaciones se ejecutan en contenedores de TeX Live que Ayakaleaf Pro inicia a través del `/var/run/docker.sock` del nodo. Consulta [0. Preparar los nodos](/es/on-premises/installation/using-kubernetes/0.-prepare-the-nodes).
* Una StorageClass por defecto con volúmenes `ReadWriteOnce`.
* `kubectl` y `openssl` en tu estación de trabajo.
