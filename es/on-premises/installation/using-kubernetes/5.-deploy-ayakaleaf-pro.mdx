```yaml title="40-overleaf.yaml" wrap
apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  name: overleaf-data
  namespace: overleaf
spec:
  accessModes: [ReadWriteOnce]
  resources:
    requests:
      storage: 20Gi
---
apiVersion: apps/v1
kind: Deployment
metadata:
  name: overleaf
  namespace: overleaf
spec:
  replicas: 1
  strategy:
    type: Recreate          # one pod owns the data volume; never run two at once
  selector:
    matchLabels:
      app: overleaf
  template:
    metadata:
      labels:
        app: overleaf
    spec:
      terminationGracePeriodSeconds: 60   # time to flush pending edits, like the Toolkit
      # Keep the environment to what the ConfigMap and Secret set: no REDIS_PORT=tcp://... and the like
      enableServiceLinks: false
      containers:
        - name: sharelatex
          image: ghcr.io/ayaka-notes/overleaf-pro:6.3.2
          envFrom:
            - configMapRef:
                name: overleaf-env
            - secretRef:
                name: overleaf-secrets
          ports:
            - containerPort: 80
          readinessProbe:
            httpGet:
              path: /status
              port: 80
            periodSeconds: 10
          resources:
            requests:
              cpu: 500m
              memory: 1536Mi
            limits:
              memory: 3Gi
          volumeMounts:
            - name: data
              mountPath: /var/lib/overleaf
            - name: compiles
              mountPath: /var/lib/overleaf/data/compiles
            - name: output
              mountPath: /var/lib/overleaf/data/output
            - name: cache
              mountPath: /var/lib/overleaf/data/cache
            - name: docker-sock
              mountPath: /var/run/docker.sock
      volumes:
        - name: data
          persistentVolumeClaim:
            claimName: overleaf-data
        # Compile scratch space on the node; same paths as SANDBOXED_COMPILES_HOST_DIR_*
        - name: compiles
          hostPath:
            path: /srv/overleaf/compiles
            type: DirectoryOrCreate
        - name: output
          hostPath:
            path: /srv/overleaf/output
            type: DirectoryOrCreate
        - name: cache
          hostPath:
            path: /srv/overleaf/cache
            type: DirectoryOrCreate
        - name: docker-sock
          hostPath:
            path: /var/run/docker.sock
            type: Socket
---
apiVersion: v1
kind: Service
metadata:
  name: overleaf
  namespace: overleaf
spec:
  type: NodePort
  selector:
    app: overleaf
  ports:
    - name: http
      port: 80
      targetPort: 80
      nodePort: 30080
```

```bash
kubectl apply -f 40-overleaf.yaml
kubectl -n overleaf rollout status deployment/overleaf --timeout=10m
kubectl -n overleaf logs deployment/overleaf | grep -E 'Finished migrations|Missing required'
```

El primer arranque ejecuta las migraciones de la base de datos y tarda uno o dos minutos. El pod está listo cuando `/status` responde; entonces abre `OVERLEAF_SITE_URL`.

### Por qué el manifiesto es así

* <strong>Volumen de datos.</strong> Todo lo que hay en `/var/lib/overleaf` (archivos de proyectos, historial, subidas) reside en el PVC. Con almacenamiento local del nodo, como local-path, los datos permanecen en un nodo; con almacenamiento en bloque en red, el pod puede moverse entre nodos.
* <strong>Volúmenes de compilación y el socket de Docker.</strong> Ayakaleaf Pro pide al Docker del nodo que inicie un contenedor de TeX Live y le pasa el directorio de compilación del proyecto **mediante su ruta en el nodo**. Por eso estos directorios son volúmenes `hostPath`, y sus rutas se repiten en `SANDBOXED_COMPILES_HOST_DIR_*`. Su contenido son datos temporales y no necesita copia de seguridad.
* <strong>`enableServiceLinks: false`.</strong> Kubernetes añade a cada pod variables al estilo de Docker para cada Service del namespace: el Service `redis` se convierte en `REDIS_PORT=tcp://10.x.x.x:6379`, y el Service `git-bridge` en `GIT_BRIDGE_PORT=tcp://...`. Algunos servicios de Overleaf leen variables con estos nombres. En este pod prevalecen los ajustes de `OVERLEAF_REDIS_*` y del ConfigMap, pero git-bridge toma `GIT_BRIDGE_PORT` como su puerto y se detiene (consulta [Integración con Git](/es/on-premises/configuration/kubernetes/integrations/git-integration)). Desactivar los enlaces limita el entorno a lo que tú estableces.
* <strong>`Recreate`.</strong> Dos pods nunca deben usar el mismo volumen de datos ni ejecutar migraciones al mismo tiempo.
* <strong>Exponerlo.</strong> El Service NodePort responde en el puerto `30080` de cada nodo. En producción, coloca delante tu controlador de ingress o balanceador de carga y termina TLS allí; debe permitir WebSockets, tiempos de espera de petición de 10 minutos (compilaciones largas) y subidas de 50 MB, y pasar `X-Forwarded-For` y `X-Forwarded-Proto`.
