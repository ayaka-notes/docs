---
title: Despliegues aislados (air-gapped) y sin conexión
description: Despliega Ayakaleaf Pro sin conexión exportando, transfiriendo y cargando imágenes de Docker.
icon: block-brick
---

En general, no recomendamos desplegar Ayakaleaf Pro en un entorno sin conexión, ya que muchas de sus funciones, como GitHub Sync y la integración con Zotero, requieren conexión a internet.

Si quieres trabajar sin conexión, es posible que no siempre puedas acceder al registro `ghcr.io` para descargar las imágenes necesarias de `ayakaleaf-pro` y TeX Live. Esto no supone un problema, ya que Docker proporciona herramientas para exportar e importar imágenes que te ayudarán con un despliegue sin conexión o aislado (air-gapped).

A grandes rasgos, descargarás las imágenes necesarias en un dispositivo con conexión a internet, las exportarás a un dispositivo portátil (o las transferirás mediante SCP/Rsync) y las importarás en el servidor aislado.

Para ello, deberás completar los siguientes pasos:

* Descarga todas las imágenes necesarias ( `overleaf-pro`, `git-bridge`, `mongo`, `redis` + las [imágenes de TeX Live](https://docs.overleaf.com/on-premises/configuration/overleaf-toolkit/server-pro-only-configuration/sandboxed-compiles#available-tex-live-images) que necesites para usar con [Sandboxed Compiles](https://docs.overleaf.com/on-premises/configuration/overleaf-toolkit/server-pro-only-configuration/sandboxed-compiles)) en una máquina con conexión a internet
  * `docker pull ghcr.io/ayaka-notes/overleaf-pro:6.1.2`
  * `docker pull quay.io/sharelatex/git-bridge:6.1.2` (la etiqueta debe ser la misma que la de `overleaf-pro`)
  * `docker pull mongo:6` (cámbiala por la versión real)
  * `docker pull redis:6.2` (cámbiala por la versión real)
  * `docker pull ghcr.io/ayaka-notes/texlive-full:2024.1` (cámbiala por la versión real)
* A continuación, deberás exportar **cada una** de las imágenes descargadas a un archivo .tar. Por ejemplo, `docker save ghcr.io/ayaka-notes/overleaf-pro:6.1.2 > overleaf-pro:6.1.2.tar`
* Con el método que prefieras, transfiere los archivos `.tar` desde la máquina con conexión a internet al servidor sin conexión o aislado
* Para cada uno de los archivos .tar, usa el comando `docker load` para cargar la imagen desde el archivo .tar. Por ejemplo, `docker load < overleaf-pro:6.1.2.tar`
* Por último, ejecuta el comando `docker images` para ver o confirmar que las imágenes se han cargado correctamente y están disponibles

<Danger>

De forma predeterminada, al ejecutar el comando `bin/up`, el Toolkit intentará descargar automáticamente cada una de las imágenes de TeX Live configuradas mediante `ALL_TEX_LIVE_DOCKER_IMAGES` en `config/variables.env`. Como tu despliegue está aislado, esto fallará; puedes evitarlo usando `SIBLING_CONTAINERS_PULL=false` en `config/overleaf.rc`.

</Danger>
