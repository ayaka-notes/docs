---
title: 1. Descargar e inicializar el Toolkit
description: Clona el Toolkit de Ayakaleaf, crea la configuración y prepárala para Ayakaleaf Pro en Podman.
icon: arrow-down-to-bracket
---

<Steps>
<Step title="Clonar el Toolkit">
Clona el **Toolkit de Ayakaleaf** ([ayaka-notes/toolkit](https://github.com/ayaka-notes/toolkit)) en tu directorio personal y entra en él:

```bash title="Clone the Toolkit" wrap
git clone https://github.com/ayaka-notes/toolkit.git ~/overleaf-toolkit
cd ~/overleaf-toolkit
```

Ejecuta todos los comandos siguientes desde este directorio.
</Step>

<Step title="Crear la configuración">
```bash title="Run initialization"
bin/init
```

Esto crea `config/overleaf.rc`, `config/variables.env` y `config/version`, como se describe en [3. Inicializar la configuración](/es/on-premises/installation/using-docker-compose/linux/3.-initialize-the-configuration) de la guía de Docker. `bin/init` todavía no necesita Podman.
</Step>

<Step title="Configurar config/overleaf.rc">
Abre `config/overleaf.rc` y cambia estas líneas:

```bash title="config/overleaf.rc"
SERVER_PRO=true
OVERLEAF_PORT=8080
SIBLING_CONTAINERS_ENABLED=true
```

Después añade esta línea al final del archivo:

```bash title="config/overleaf.rc"
SELINUX_MODE=managed
```

| Ajuste                            | Por qué                                                                                                                                                                                                     |
| --------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `SERVER_PRO=true`                 | Usa la imagen de Ayakaleaf Pro de `ghcr.io`. No hace falta iniciar sesión.                                                                                                                                   |
| `OVERLEAF_PORT=8080`              | Podman rootless no puede escuchar en puertos inferiores a `1024`. El valor predeterminado `80` falla.                                                                                                        |
| `SIBLING_CONTAINERS_ENABLED=true` | Ejecuta cada compilación en su propio contenedor de TeX Live. Ya es `true` de forma predeterminada; la configuración de Podman solo admite este modo.                                                       |
| `SELINUX_MODE=managed`            | Ejecuta el contenedor `sharelatex` con el tipo de SELinux `sharelatex_t`, que puede usar el socket de Podman y nada más. `bin/podman-setup --apply` instala el módulo de política para ello. Consulta [Configuración del Toolkit](/es/on-premises/configuration/overleaf-toolkit/toolkit-settings) para los demás modos. |

Deja `DOCKER_SOCKET_PATH` como está: `bin/podman-setup --apply` lo establece en tu socket de Podman en el siguiente paso.

<Warning>

Mantén `GIT_BRIDGE_ENABLED=false`. En Ayakaleaf Pro 6.3.4, la integración con Git no funciona en Podman; consulta [Limitaciones conocidas](/es/on-premises/installation/using-podman#known-limitations).

</Warning>
</Step>

<Step title="Elegir las imágenes de TeX Live">
Abre `config/variables.env`, elimina el `#` delante de `TEX_LIVE_DOCKER_IMAGE` y `ALL_TEX_LIVE_DOCKER_IMAGES`, y enumera las imágenes de TeX Live que quieres usar:

```bash title="config/variables.env" wrap
TEX_LIVE_DOCKER_IMAGE=ghcr.io/ayaka-notes/texlive-full:2026.1
ALL_TEX_LIVE_DOCKER_IMAGES=ghcr.io/ayaka-notes/texlive-full:2026.1
```

`bin/up` se detiene con `Please configure ALL_TEX_LIVE_DOCKER_IMAGES` si la lista está vacía. `texlive-full` es grande; para un servidor de pruebas también sirve la mucho más pequeña `ghcr.io/ayaka-notes/texlive-basic:2026.1`. Consulta [Compilaciones aisladas](/es/on-premises/configuration/overleaf-toolkit/sandboxed-compiles) para ver las imágenes disponibles.

Establece las demás variables, como `OVERLEAF_SITE_URL`, como se describe en [5. Personalizar tu instancia](/es/on-premises/installation/using-docker-compose/linux/5.-personalizing-your-instance#required-environment-variables). Con la dirección de escucha predeterminada, usa `http://localhost:8080`.
</Step>
</Steps>
