---
title: 3. Iniciar Ayakaleaf Pro
description: Inicia Ayakaleaf Pro en Podman, verifícalo con podman-setup y bin/doctor, e inícialo tras los reinicios.
icon: circle-play
---

<Steps>
<Step title="Iniciar los contenedores">
```bash title="Start Ayakaleaf Pro"
bin/up -d
```

El primer inicio descarga las imágenes de MongoDB, Redis y TeX Live, y crea los directorios de datos en `data/`. Muestra una advertencia de que la compatibilidad con Podman es experimental.

<Info>

El primer inicio también puede mostrar `MongoNetworkError: connect ECONNREFUSED 127.0.0.1:27017`. El Toolkit configura el conjunto de réplicas de MongoDB mientras MongoDB aún se está iniciando, y lo reintenta hasta que responde. Puedes ignorar esta línea.

</Info>

Después de uno o dos minutos, comprueba que los contenedores se están ejecutando:

```bash title="List the containers"
podman ps --format "{{.Names}} {{.Status}}"
```

```text
mongo Up 34 seconds (healthy)
redis Up 20 seconds
sharelatex Up 20 seconds
```
</Step>

<Step title="Volver a comprobar la configuración">
Ahora que existen los directorios de datos y el contenedor `sharelatex` está en ejecución, `bin/podman-setup` puede completar sus comprobaciones:

```bash title="Check the setup"
bin/podman-setup
```

Comprueba los propietarios de los nuevos directorios de datos y prueba el socket de Podman desde dentro del contenedor `sharelatex`:

```text
====== Socket Connectivity ======
[✓] host → socket OK
[✓] container → socket OK

====== Data Directory Permissions ======
[✓] mongo data dir owned by 999
[✓] redis data dir owned by 999
[✓] overleaf data dir owned by 33
...
====== Summary ======
[✓] 27 passed  [!] 1 warnings  [✗] 0 failures
[!] Warnings:
[!] not logged in to quay.io
```

`container → socket OK` significa que Ayakaleaf Pro puede iniciar contenedores de compilación. Si una comprobación falla, ejecuta `bin/podman-setup --apply` y después `bin/up -d`. La advertencia de quay.io no se aplica a Ayakaleaf Pro; consulta [2. Ejecutar podman-setup](/es/on-premises/installation/using-podman/2.-run-podman-setup).
</Step>

<Step title="Ejecutar doctor">
```bash title="Run the doctor"
bin/doctor
```

En Podman, el informe muestra el entorno de ejecución y la configuración de seguridad:

```text
- Container Daemon
    - status: up
    - runtime: podman
    - server version: 5.8.5
    - socket: /run/user/1000/podman/podman.sock
    - DOCKER_HOST: unix:///run/user/1000/podman/podman.sock
    - host → socket: OK
    - container → socket: OK
- Security
    - SELinux: Enforcing
    - SELINUX_MODE: managed
    - SELINUX_LABEL: sharelatex_t
    - SELinux module: loaded (podman_socket_clsi)
    - SELinux rules: present
    - Seccomp profile: present
```

La advertencia `Server Pro enabled, but not logged in to quay.io repository` del final es la misma comprobación de quay.io; consulta [Obtener ayuda](/es/on-premises/support/getting-help#q-and-a).
</Step>

<Step title="Iniciar Ayakaleaf Pro tras un reinicio">
Con Docker, el daemon de Docker vuelve a iniciar los contenedores tras un reinicio. Podman rootless no tiene daemon: activa el servicio de usuario que inicia tus contenedores cuando arranca el servidor:

```bash title="Start the containers at boot"
systemctl --user enable podman-restart.service
```

Inicia todos los contenedores de tu usuario cuya política de reinicio sea `always`, que el Toolkit establece para todos sus contenedores. Esto requiere lingering, que `bin/podman-setup --apply` activó. Sin este servicio, ejecuta `bin/up -d` después de cada reinicio.
</Step>

<Step title="Abrir el puerto en el cortafuegos">
De forma predeterminada, la instancia solo acepta conexiones desde el propio servidor, en `http://localhost:8080`. Para abrirla desde otros equipos, establece `OVERLEAF_LISTEN_IP` en `config/overleaf.rc` y `OVERLEAF_SITE_URL` en `config/variables.env` como se describe en [5. Personalizar tu instancia](/es/on-premises/installation/using-docker-compose/linux/5.-personalizing-your-instance#listen-address-and-port), y vuelve a ejecutar `bin/up -d`.

A diferencia de Docker, Podman rootless no omite el cortafuegos del host. Si `firewalld` está en ejecución, que es lo predeterminado en RHEL, abre el puerto:

```bash title="Open port 8080"
sudo firewall-cmd --permanent --add-port=8080/tcp
sudo firewall-cmd --reload
```

En un servidor en la nube, permite también el puerto en el grupo de seguridad del proveedor. Usa HTTPS antes de exponer la instancia a Internet; consulta [4. Tareas posteriores a la instalación](/es/on-premises/installation/using-podman/4.-post-installation-tasks#use-https).
</Step>
</Steps>
