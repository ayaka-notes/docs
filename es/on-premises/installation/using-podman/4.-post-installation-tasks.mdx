### Crea tu primera cuenta de administrador {#create-your-first-administrator-account}

Abre [http://localhost:8080/launchpad](http://localhost:8080/launchpad), o tu `OVERLEAF_SITE_URL` seguida de `/launchpad`, y registra la cuenta de administrador. A partir de aquí todo funciona como con Docker: sigue [6. Tareas posteriores a la instalación](/es/on-premises/installation/using-docker-compose/linux/6.-post-installation-tasks) de la guía de Docker, usando el puerto `8080` en sus enlaces a `localhost`.

Crea el proyecto de ejemplo y compílalo. El PDF demuestra que las compilaciones se ejecutan en sus contenedores de TeX Live a través de Podman. Para ver el contenedor de compilación:

```bash title="List the compile containers"
podman ps -a --filter name=project- --format "{{.Names}} {{.Image}} {{.Status}}"
```

### Usar HTTPS {#use-https}

El [proxy TLS](/es/on-premises/configuration/overleaf-toolkit/tls-proxy) del Toolkit funciona en Podman: ejecuta `bin/init --tls` y establece tu certificado y `NGINX_ENABLED=true` como se describe allí. Escucha en los puertos `80` y `443`, que Podman rootless no puede usar de forma predeterminada. Permite que los usuarios sin privilegios usen los puertos a partir del `80`:

```bash title="Allow ports 80 and 443"
echo "net.ipv4.ip_unprivileged_port_start=80" | sudo tee /etc/sysctl.d/99-unprivileged-ports.conf
sudo sysctl --system
```

Esto permite que cualquier usuario del servidor escuche en estos puertos, así que hazlo solo en un servidor dedicado a Ayakaleaf Pro. Después, ábrelos en el cortafuegos:

```bash title="Open ports 80 and 443"
sudo firewall-cmd --permanent --add-port=80/tcp --add-port=443/tcp
sudo firewall-cmd --reload
```

Establece `OVERLEAF_SITE_URL` en tu dirección `https://` y ejecuta `bin/up -d`. Mantén los valores predeterminados `NGINX_HTTP_PORT=80` y `TLS_PORT=443`: con otros puertos, la redirección de HTTP a HTTPS lleva al puerto equivocado.

<Info>

Deja `OVERLEAF_LISTEN_IP` en `127.0.0.1` cuando uses el proxy TLS, para que el puerto `8080` no sea accesible desde otros equipos.

</Info>

### Actualizar {#upgrade}

Actualiza con `bin/upgrade`, como se describe en [Actualizar tu despliegue](/es/on-premises/maintenance/upgrading-your-deployment). En Podman, también extrae el perfil seccomp de la nueva versión a `config/seccomp/<version>/` y actualiza `SECCOMP_PROFILE`:

```text
Over-writing config/version with 6.3.4
Set SECCOMP_PROFILE=/home/<user>/overleaf-toolkit/config/seccomp/6.3.4/clsi-profile.json in config/variables.env
```

Después de una actualización, ejecuta `bin/podman-setup` para comprobar la configuración.

### Cambiar el modo de SELinux {#change-the-selinux-mode}

`SELINUX_MODE` en `config/overleaf.rc` establece cómo SELinux confina el contenedor `sharelatex`. `managed` es el que configuran estas páginas; los demás modos se describen en [Configuración del Toolkit](/es/on-premises/configuration/overleaf-toolkit/toolkit-settings). Ejecuta `bin/up -d` después de cambiarlo.
