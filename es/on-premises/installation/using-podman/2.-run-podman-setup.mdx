---
title: 2. Ejecutar podman-setup
description: Deja que bin/podman-setup compruebe el host y configure Podman rootless, SELinux y el perfil seccomp.

---

`bin/podman-setup` comprueba todo lo que Ayakaleaf Pro necesita en Podman. Sin opciones, solo informa; con `--apply`, también corrige lo que encuentra.

<Steps>
<Step title="Comprobar el host">
```bash title="Check only"
bin/podman-setup
```

En un host nuevo, la mayoría de las comprobaciones fallan, por ejemplo:

```text
====== Packages ======
[✗] podman not installed
[✗] podman-docker not installed
...
====== Summary ======
[✓] 7 passed  [!] 13 warnings  [✗] 4 failures
```
</Step>

<Step title="Aplicar las correcciones">
```bash title="Check and fix"
bin/podman-setup --apply
```

Ejecútalo en una terminal: te pide la contraseña de `sudo` para los pasos que afectan a todo el sistema. También descarga la imagen de Ayakaleaf Pro para extraer su perfil seccomp, lo que tarda unos minutos la primera vez. Al final vuelve a comprobar el host:

```text
====== Summary ======
[✓] 23 passed  [!] 2 warnings  [✗] 0 failures
[!] Warnings remaining:
[!] not logged in to quay.io
[!] container → socket skipped (sharelatex not running)
```

Ambas advertencias son esperables en este punto:

* `not logged in to quay.io`: la comprobación procede del Toolkit oficial, donde la imagen de Server Pro está en un registro privado. Las imágenes de Ayakaleaf Pro son públicas en `ghcr.io` y no requieren inicio de sesión, así que ignórala. También se mantiene después de la instalación.
* `container → socket skipped (sharelatex not running)`: esta prueba necesita la instancia en ejecución. Volverás a ejecutar el script en [3. Iniciar Ayakaleaf Pro](/es/on-premises/installation/using-podman/3.-start-ayakaleaf-pro).

El script termina con `0` cuando se superan todas las comprobaciones, con `1` cuando hay advertencias y con `2` cuando hay fallos. Debido a la advertencia de quay.io, espera `1`.
</Step>
</Steps>

### Qué cambia el script {#what-the-script-changes}

Con `--apply`, el script puede cambiar lo siguiente.

En todo el sistema, con `sudo`:

* Instala `podman`, `podman-docker`, `git`, `curl`, `checkpolicy` y `policycoreutils` con `dnf`.
* Activa el lingering para tu usuario con `loginctl`, para que tus contenedores sigan ejecutándose después de cerrar sesión.
* Crea `/etc/containers/nodocker`, que silencia el mensaje "Emulate Docker CLI using podman".
* Carga el módulo de política de SELinux `podman_socket_clsi`, cuando `SELINUX_MODE=managed`.

Para tu usuario:

* Activa el servicio de usuario `podman.socket`, la API compatible con Docker que Ayakaleaf Pro usa para iniciar las compilaciones.
* Instala Docker Compose v2 desde GitHub en `~/.local/bin/docker-compose` y lo enlaza en `~/.docker/cli-plugins/`.
* Hace que Podman use este Compose en `~/.config/containers/containers.conf`.
* Añade los alias `mongo` y `redis` en `~/.config/containers/registries.conf.d/overleaf-toolkit.conf`, para que Podman sepa de dónde descargar estos nombres cortos de imagen.

En el Toolkit:

* Establece `DOCKER_SOCKET_PATH` y `DOCKER_HOST` en `config/overleaf.rc` a `/run/user/<uid>/podman/podman.sock`.
* Extrae el perfil seccomp para compilaciones de la imagen de Ayakaleaf Pro a `config/seccomp/<version>/clsi-profile.json` y establece `SECCOMP_PROFILE` en `config/variables.env`. A diferencia de Docker, Podman necesita este perfil como archivo en el host.
* Compila el módulo de política de SELinux en `config/selinux/`.
* Establece los propietarios de los directorios de datos en `data/` con `podman unshare chown`, una vez que existen.

<Info>

Cada cambio se corresponde con una comprobación. Si cambias algo a mano, por ejemplo en `config/overleaf.rc`, vuelve a ejecutar `bin/podman-setup` para verificarlo.

</Info>
