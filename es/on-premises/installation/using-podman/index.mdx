RHEL y sus recompilaciones (Rocky Linux, AlmaLinux) incluyen Podman en lugar de Docker, y algunas organizaciones no permiten Docker en sus servidores. El Toolkit puede ejecutar Ayakaleaf Pro sobre **Podman rootless**: los contenedores se ejecutan con un usuario normal, las compilaciones siguen ejecutándose en contenedores de TeX Live aislados y SELinux permanece en modo enforcing. El script `bin/podman-setup` comprueba el host y corrige lo que puede.

Al final de esta sección tendrás la misma instancia que con [Uso de Docker Compose](/es/on-premises/installation/using-docker-compose): Ayakaleaf Pro con compilaciones aisladas, MongoDB y Redis, administrado con los habituales `bin/up`, `bin/doctor` y `bin/upgrade`.

<Info>

La compatibilidad con Podman es experimental. Procede del Toolkit oficial de Overleaf, que solo la prueba en RHEL 9 y posteriores con Podman rootless, compilaciones aisladas y SELinux en modo enforcing. Probamos estas páginas en Rocky Linux 9.9 (Podman 5.8, SELinux enforcing) con Ayakaleaf Pro 6.3.4. Docker sigue siendo el entorno de ejecución de contenedores recomendado.

</Info>

### Qué necesitas {#what-you-need}

* **RHEL, Rocky Linux, AlmaLinux o CentOS Stream 9 o posterior**, con SELinux en modo enforcing. `bin/podman-setup` se detiene en cualquier otra distribución. En Ubuntu o Debian, usa [Uso de Docker Compose](/es/on-premises/installation/using-docker-compose/linux).
* **Un usuario que no sea root con `sudo`**, que será el propietario de los contenedores. Ejecuta todos los comandos de esta sección como ese usuario; `bin/podman-setup` se niega a ejecutarse como `root`.
* **Un host limpio**: sin Docker Engine ni una instalación existente del Toolkit. No se cubre la migración de una instancia existente basada en Docker a Podman.

### En qué se diferencia de Docker {#how-it-differs-from-docker}

|                                  | Docker                               | Podman rootless                                                                          |
| -------------------------------- | ------------------------------------ | ---------------------------------------------------------------------------------------- |
| Quién ejecuta los contenedores   | El daemon de Docker, como `root`     | Tu usuario                                                                               |
| Socket usado para iniciar compilaciones | `/var/run/docker.sock`        | `/run/user/<uid>/podman/podman.sock`                                                     |
| Puertos                          | Cualquiera, por ejemplo `80` y `443` | `1024` y superiores, por ejemplo `8080`                                                  |
| Cortafuegos del host (`firewalld`) | Los puertos publicados lo omiten   | Se aplica: abre el puerto con `firewall-cmd`                                             |
| Inicio tras un reinicio          | El daemon de Docker los reinicia     | El servicio de usuario `podman-restart`                                                  |
| SELinux                          | El Toolkit no lo configura           | Módulo de política `podman_socket_clsi` y `SELINUX_MODE=managed` en `config/overleaf.rc`  |
| Perfil seccomp para compilaciones | Incluido en la imagen               | El Toolkit lo extrae a `config/seccomp/<version>/` y lo establece como `SECCOMP_PROFILE` |

### Limitaciones conocidas {#known-limitations}

* <strong>Integración con Git.</strong> En Ayakaleaf Pro 6.3.4, `git clone` falla con `502` en Podman: el NGINX de la imagen busca el contenedor `git-bridge` con el servidor DNS de Docker (`127.0.0.11`), que Podman no tiene. La corrección ([1b911d1092](https://github.com/ayaka-notes/ayakaleaf-pro/commit/1b911d1092c80f7b0ff77c5e3805b40503d49964)) llegará con la próxima versión; hasta entonces, deja `GIT_BRIDGE_ENABLED=false`.
* <strong>Direcciones IP de los clientes.</strong> Podman rootless reenvía el puerto publicado desde dentro de la red del contenedor, por lo que Ayakaleaf Pro ve a cada visitante con una dirección interna como `10.89.0.15`. Los [registros de auditoría](/es/on-premises/user-guide/administrators/user-management#audit-logs) de un usuario en el panel de administración muestran esta dirección en lugar de su dirección IP.
