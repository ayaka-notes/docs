Esta página describe los archivos de configuración que usa el Toolkit para configurar tu despliegue on-premises de Overleaf.

### Datos persistentes

El Overleaf Toolkit necesita almacenar datos persistentes, como los archivos necesarios para compilar proyectos LaTeX y el contenido de la base de datos MongoDB. Esto se consigue montando algunos directorios de la máquina anfitriona en los contenedores Docker y escribiendo los datos en esos directorios.

#### Directorios de datos

El contenedor `sharelatex` necesita un directorio en el que almacenar los datos relacionados con las compilaciones de LaTeX. Este directorio se define con la variable `OVERLEAF_DATA_PATH` en `config/overleaf.rc`.

El contenedor `mongo`, si está habilitado, necesita un directorio en el que almacenar sus archivos de base de datos, y lo mismo ocurre con el contenedor `redis`. Estos directorios también se pueden configurar en `config/overleaf.rc`.

#### Permisos de archivos

Como Docker se ejecuta como `root`, los directorios de datos acabarán siendo propiedad del usuario `root`, aunque el Toolkit lo utilice un usuario que no sea root. Esto no es un problema, pero conviene tenerlo en cuenta si piensas modificar los datos persistentes desde fuera de los contenedores.

### Ubicación de los archivos de configuración

Todos los archivos de configuración propiedad del usuario se encuentran en el directorio `config/`.

Este directorio está **excluido** del sistema de control de versiones git, por lo que no se modificará al actualizar el código del Toolkit. El Toolkit **no** modificará ningún dato del directorio `config/` sin tu permiso.

<Info>

Los cambios en los archivos de configuración no se aplicarán automáticamente a los contenedores existentes, aunque el contenedor se detenga y se reinicie (con `bin/stop` y `bin/start`). Para aplicar los cambios, ejecuta `bin/up` y, entre bastidores, `docker compose` aplicará automáticamente los cambios de configuración a un nuevo contenedor. (O ejecuta `bin/up -d` si prefieres no adjuntarte a los logs de Docker).

</Info>

### El archivo `config/overleaf.rc`

El archivo `config/overleaf.rc` contiene los ajustes de configuración de nivel superior más importantes que usa el Toolkit. Contiene sentencias que definen variables, con el formato: `VARIABLE_NAME=value`

Para ver un desglose de todas las opciones de configuración disponibles, consulta nuestra sección de ajustes.

### El archivo `variables.env`

El archivo `config/variables.env` contiene variables de entorno que se cargan en el contenedor `sharelatex` y se usan para configurar los microservicios de Overleaf. Entre ellas se incluyen el nombre de la aplicación, tal como se muestra en el encabezado de la interfaz web, los ajustes para el envío de correos y otros ajustes, como SSO.

Para ver un desglose de todas las variables de entorno disponibles, consulta la sección [Variables de entorno](/es/on-premises/configuration/overleaf-toolkit/environment-variables).

### El archivo `config/version`

El archivo `config/version` contiene el número de versión de la imagen Docker que se usará para crear la instancia en ejecución de tu servidor Overleaf.

<Info>

Los cambios en estos archivos de configuración no se aplicarán automáticamente a los contenedores existentes, aunque el contenedor se detenga y se reinicie (con `bin/stop` y `bin/start`). Para aplicar tus cambios, ejecuta `bin/up` y el Toolkit creará automáticamente un nuevo contenedor con los cambios de configuración aplicados.

</Info>

### El archivo `docker-compose.override.yml`

Si existe, el archivo `config/docker-compose.override.yml` se incluirá en la invocación de `docker compose`. Esto resulta útil para sobrescribir la configuración específica de Docker Compose.

`config/variables.env` no se carga en los contenedores `mongo` y `redis`. Para definir una variable de entorno en ellos, añádela aquí y ejecuta `bin/up -d`, por ejemplo:

```yml
services:
    mongo:
        environment:
            GLIBC_TUNABLES: glibc.pthread.rseq=1
```

Consulta la [documentación de docker-compose](https://docs.docker.com/compose/extends/#adding-and-overriding-configuration) para más detalles.

### Q\&A

<Accordion title="¿Qué sistema de archivos deben usar los directorios de datos? ¿Puedo usar btrfs, copy-on-write o compresión zstd?">

<strong>Respuesta:</strong> El Toolkit no comprueba el sistema de archivos. Quien tiene requisitos es MongoDB, por lo que la elección importa sobre todo para `data/mongo` (`MONGO_DATA_PATH`). Las [notas de producción](https://www.mongodb.com/docs/v8.0/administration/production-notes/) de MongoDB indican que se use XFS o ext4 en Linux, y recomiendan encarecidamente XFS con WiredTiger, el motor de almacenamiento que utiliza. No tratan btrfs ni otros sistemas de archivos copy-on-write. Si tu sistema de archivos raíz es btrfs, puedes montar un volumen XFS y hacer que `MONGO_DATA_PATH` apunte a él. El sistema de archivos también debe admitir `fsync()` en directorios, algo que no hacen HGFS ni las carpetas compartidas de VirtualBox.

La compresión del sistema de archivos ahorra poco para `data/mongo`: WiredTiger ya [comprime](https://www.mongodb.com/docs/v8.0/core/wiredtiger/) las colecciones con snappy y los índices con compresión de prefijos. Para NFS, consulta [Solución de problemas](/es/on-premises/support/troubleshooting).

</Accordion>
