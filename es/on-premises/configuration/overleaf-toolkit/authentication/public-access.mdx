Puedes abrir tu instancia de Overleaf a personas sin cuenta de tres formas:

* [Acceso a proyectos](/es/on-premises/configuration/overleaf-toolkit/public-access#project-access  "mention"): permite que los invitados abran un enlace de proyecto compartido sin iniciar sesión
* [Acceso a páginas](/es/on-premises/configuration/overleaf-toolkit/public-access#page-access  "mention"): permite que los visitantes sin sesión iniciada naveguen por páginas como `/learn`, `/templates` y `/devs`
* [Registro público](/es/on-premises/configuration/overleaf-toolkit/public-access#public-registration  "mention"): permite que los usuarios se registren por sí mismos, opcionalmente con un correo electrónico de activación y limitado a dominios de correo electrónico

### Acceso a proyectos

<Info>

De forma predeterminada, aunque un usuario obtenga un enlace para compartir un proyecto, debe **iniciar sesión** antes de poder unirse a una sesión de edición colaborativa del proyecto.

</Info>

Para permitir el acceso anónimo a los proyectos compartidos mediante enlace, establece las dos variables siguientes:

```dotenv title="config/variables.env"
OVERLEAF_ALLOW_ANONYMOUS_READ_AND_WRITE_SHARING=true
OVERLEAF_ALLOW_PUBLIC_ACCESS=true
```

`OVERLEAF_ALLOW_ANONYMOUS_READ_AND_WRITE_SHARING` habilita la lectura/escritura anónima en los proyectos compartidos mediante enlace.

`OVERLEAF_ALLOW_PUBLIC_ACCESS` evita que los usuarios no autenticados sean redirigidos a la página de inicio de sesión.

Vuelve a crear los contenedores con `bin/up`. A continuación, abre una URL de enlace compartido en una ventana privada.

### Acceso a páginas

De forma predeterminada (sin establecer `OVERLEAF_ALLOW_PUBLIC_ACCESS`), **todas** las páginas excepto las de inicio de sesión y registro redirigen a los visitantes sin sesión iniciada a la página de inicio de sesión. Esto incluye páginas pensadas para ser públicas, por lo que los enlaces a ellas solo funcionan para usuarios que ya han iniciado sesión.

Con `OVERLEAF_ALLOW_PUBLIC_ACCESS=true`, los visitantes sin sesión iniciada pueden abrir:

| Página                                                                | Requiere                         |
| --------------------------------------------------------------------- | -------------------------------- |
| La ayuda de LaTeX en `/learn` (consulta [adding-latex-user-help.md](/es/on-premises/configuration/overleaf-toolkit/adding-latex-user-help  "mention")) | `OVERLEAF_PROXY_LEARN=true`      |
| La galería de plantillas en `/templates`, las páginas de plantillas, las vistas previas y las descargas ZIP (consulta [templates.md](/es/on-premises/configuration/overleaf-toolkit/templates  "mention")) | `OVERLEAF_TEMPLATE_GALLERY=true` |
| La página de la API de importación de Overleaf en `/devs` (consulta [overleaf-import-api.md](/es/on-premises/configuration/overleaf-toolkit/overleaf-import-api  "mention")) | —                                |

También permite que la [API de importación de Overleaf](/es/on-premises/configuration/overleaf-toolkit/overleaf-import-api#signed-out-visitors  "mention") conserve el envío de un formulario de un visitante sin sesión iniciada hasta que este inicie sesión.

La lista de proyectos, el editor y la creación de proyectos (también a partir de una plantilla o mediante la API de importación) siguen requiriendo iniciar sesión.

### Registro público

El registro público solo está disponible en [ayaka-notes/ayakaleaf-pro](https://github.com/ayaka-notes/ayakaleaf-pro).

<Danger>

Ten en cuenta que, una vez que habilites el registro público, **cualquier persona** con acceso a tu instancia de Overleaf podrá registrarse como usuario.

Con `true`, el proceso de registro no verifica las direcciones de correo electrónico, así que úsalo únicamente en una intranet o en un entorno de confianza, o usa en su lugar el [registro con correo electrónico de activación](/es/on-premises/configuration/overleaf-toolkit/public-access#registration-with-activation-email).

En una instancia con OIDC, no uses `true`: cualquiera podría registrarse con el correo electrónico de un colega antes del primer inicio de sesión con OIDC de ese colega, lo que vincularía al colega con esa cuenta. Usa el [registro con correo electrónico de activación](/es/on-premises/configuration/overleaf-toolkit/public-access#registration-with-activation-email) o no permitas el registro público; consulta [Cuentas y contraseñas](/es/on-premises/configuration/overleaf-toolkit/authentication#accounts-and-passwords).

</Danger>

De forma predeterminada, ni Community Edition ni Overleaf Pro permiten el registro público.

Para habilitarlo, añade esto a `config/variables.env`:

```dotenv title="config/variables.env"
OVERLEAF_ALLOW_PUBLIC_REGISTRATION=true
```

Vuelve a crear los contenedores con `bin/up`.

A continuación, haz clic en **Sign up** o visita `/register`.

### Registro con correo electrónico de activación

El registro con correo electrónico de activación solo está disponible en [ayaka-notes/ayakaleaf-pro](https://github.com/ayaka-notes/ayakaleaf-pro). Los usuarios se registran solo con su correo electrónico y establecen su contraseña mediante el enlace del correo de activación, de modo que solo el titular de una dirección puede usar la cuenta. Una lista de dominios y comodines requiere v6.4.0 o posterior; las versiones anteriores solo aceptan un dominio, como `@example.com`.

Antes de habilitarlo, configura el envío de correo electrónico; de lo contrario, los usuarios nunca recibirán el correo de activación. Consulta [Envío de correo electrónico](/es/on-premises/configuration/overleaf-toolkit/email-delivery).

A continuación, añade la siguiente línea a `config/variables.env`:

```dotenv title="config/variables.env" wrap
OVERLEAF_ALLOW_PUBLIC_REGISTRATION=@example.com,@*.example.org
```

`OVERLEAF_ALLOW_PUBLIC_REGISTRATION` puede establecerse en:

| Valor                         | Quién puede registrarse                                       | Correo verificado |
| ----------------------------- | ----------------------------------------------------- | :------------: |
| `true`                        | Cualquiera, con correo electrónico y contraseña                       |       No       |
| `@example.com`                | Direcciones de `example.com`                             |      Sí       |
| `@*.example.org`              | Direcciones de subdominios como `cs.example.org`, no del propio `example.org` |      Sí       |
| `@example.com,@*.example.org` | Cualquiera de las entradas indicadas, separadas por comas         |      Sí       |
| `@*`                          | Cualquiera                                                 |      Sí       |

Los dominios se comparan sin distinguir entre mayúsculas y minúsculas. Para permitir un dominio y sus subdominios, indica ambos: `@example.org,@*.example.org`.

### Q\&A

<Accordion title="¿Qué puede hacer con los comentarios un editor sin sesión iniciada?">

<strong>Respuesta:</strong> Un usuario sin sesión iniciada que abre un proyecto mediante su enlace de edición obtiene el mismo acceso que un editor, salvo las acciones que registran quién las realizó:

| Acción                                            | Editor sin sesión iniciada |
| ------------------------------------------------- | ----: |
| Editar el texto, ver comentarios y cambios controlados |               Sí |
| Aceptar cambios controlados, cambiar el modo de edición   |               Sí |
| Eliminar un comentario o un hilo completo                |               Sí |
| Añadir, responder o editar un comentario                   |                No |
| Resolver o reabrir un comentario                       |                No |

El panel de revisión les sigue mostrando el botón **Resolve**, pero la resolución falla con un mensaje de error.

Los usuarios que abren un proyecto mediante su enlace de visualización no ven ningún comentario; consulta [Roles y permisos](/es/on-premises/user-and-project-management/roles-and-permissions#collaborating).

</Accordion>
