Esta página describe las variables de entorno admitidas en el archivo `config/variables.env` para los despliegues con el Toolkit.

El archivo `config/variables.env` consta de definiciones de variables con la forma `NAME=value`; las líneas que empiezan por `#` se tratan como comentarios.

<Info>

Es necesario volver a crear los contenedores de Docker después de cambiar cualquier cosa en `overleaf.rc` o `variables.env`, ejecutando `bin/up`.

</Info>

### Todas las versiones

Estas variables de entorno son compatibles con Server CE y Server Pro, y ofrecen una vía de migración sencilla entre estas dos versiones locales. También pueden usarse tanto en despliegues con el Toolkit como con Docker Compose.

<Info>

Anteriormente, estas variables de entorno tenían el prefijo `SHARELATEX_` en lugar de `OVERLEAF_`.

</Info>

| Nombre | Descripción |
| --- | --- |
| `OVERLEAF_SITE_URL` | La dirección donde tu instancia de Overleaf está disponible públicamente. Se usa en los enlaces públicos y al conectarse mediante websockets, ¡así que debe configurarse correctamente! |
| `OVERLEAF_ADMIN_EMAIL` | La dirección de correo electrónico en la que los usuarios pueden contactar con la persona que gestiona el sitio. |
| `OVERLEAF_APP_NAME` | El nombre que se muestra al hacer referencia a la aplicación en ejecución. El valor predeterminado es 'Overleaf (Community Edition)'. |
| `OVERLEAF_MONGO_URL` y `MONGO_URL` | La URL de la base de datos Mongo que se usará. |
| `OVERLEAF_REDIS_HOST` y `REDIS_HOST` | El nombre de host de la instancia de Redis que se usará. Ambas son obligatorias (consulta las [notas de la versión](/es/on-premises/release-notes)). |
| `OVERLEAF_REDIS_PORT` y `REDIS_PORT` | El puerto de la instancia de Redis que se usará. Ambas son obligatorias (consulta las [notas de la versión](/es/on-premises/release-notes)). |
| `OVERLEAF_REDIS_PASS` y `REDIS_PASSWORD` | La contraseña que se usará al conectarse a Redis (si corresponde). Deben establecerse **ambas** variables de entorno. Consulta [habilitar la autenticación por contraseña](/es/on-premises/configuration/overleaf-toolkit/redis#enabling-password-authentication) para más información. |
| `OVERLEAF_REDIS_TLS` | <p>Si se establece en `true`, permite la conexión a una instancia de Redis que requiera TLS.<br /><br /><strong>Nota:</strong> actualmente no se admite mTLS.</p> |
| `OVERLEAF_NAV_TITLE` | Establece el título de la pestaña de la aplicación. |
| `OVERLEAF_HEADER_IMAGE_URL_LIGHT` y `OVERLEAF_HEADER_IMAGE_URL_DARK` | URL de los logotipos de cabecera personalizados para los temas claro y oscuro (añadidas en 6.3.0). Cada tema recurre a `OVERLEAF_HEADER_IMAGE_URL` cuando su variable específica no está definida. Consulta [Branding](/es/on-premises/configuration/overleaf-toolkit/branding  "mention"). |
| `OVERLEAF_LINKED_URL_OUTBOUND_PROXY` | URL de un proxy HTTP(S) para obtener archivos externos vinculados y recursos ZIP o TeX externos a través de la API Open in Overleaf. Disponible a partir de la versión republicada de Ayakaleaf Pro `6.3.0` (3 de octubre de 2026). Déjala sin definir para conectarte directamente. Ejemplo: `OVERLEAF_LINKED_URL_OUTBOUND_PROXY=http://proxy.internal:3128`. Consulta [Outbound Proxy](/es/on-premises/configuration/overleaf-toolkit/external-url#outbound-proxy  "mention") para la configuración y las restricciones de acceso a la red. |
| `OVERLEAF_INVITE_TOKEN_SECRET` | <p><strong>Obligatoria</strong>. Una cadena aleatoria que se usa para proteger los tokens para compartir proyectos (añadida en Server Pro 6.2.0).</p><p><strong>Mínimo de caracteres:</strong> 16</p> |
| `OVERLEAF_SESSION_SECRET` | Una cadena aleatoria que se usa para proteger los tokens; si se usa balanceo de carga, debe establecerse el mismo token en todas las máquinas. Si solo se ejecuta 1 instancia, no es necesario que el usuario la establezca. |
| `OVERLEAF_COOKIE_SESSION_LENGTH` | Permite sobrescribir el tiempo de expiración predeterminado de 5 días de la cookie de sesión. El valor debe indicarse en milisegundos. Ejemplo: para que la sesión dure 1 hora, establece `COOKIE_SESSION_LENGTH=3600000`. (Añadida en Server Pro 4.2) |
| `OVERLEAF_TRUSTED_PROXY_IPS` | <p>Si no se establece, el valor predeterminado es `loopback`. Si la estableces manualmente, además de tus IP de confianza, debes incluir también `loopback` (o `127.0.0.1`), que confía en la instancia de nginx que se ejecuta dentro del contenedor <strong>sharelatex</strong>. Solo se aceptan direcciones IP y rangos CIDR: no añadas nombres de host como `localhost`; de lo contrario, Overleaf no se iniciará y devolverá `502 Bad Gateway`.<br /><br />Si usas una subred de `172.16.0.0/12` (la subred predeterminada de las redes de Docker) para tu red habitual, establece `OVERLEAF_TRUSTED_PROXY_IPS=loopback,<network>` en tu `config/variables.env`, donde `<network>` es el valor de `IPAM -> Config -> Subnet` en `docker inspect overleaf_default`, p. ej., `OVERLEAF_TRUSTED_PROXY_IPS=loopback,172.19.0.0/16`. Esto sirve para evitar la suplantación de las cabeceras `X-Forwarded`.<br /><br />Si usas un proxy TLS externo (es decir, no gestionado por el Overleaf Toolkit), asegúrate de que `OVERLEAF_TRUSTED_PROXY_IPS=loopback,<ip-of-your-tls-proxy>`, p. ej., `OVERLEAF_TRUSTED_PROXY_IPS=loopback,192.168.13.37`.</p> |
| `OVERLEAF_RESTRICT_INVITES_TO_EXISTING_ACCOUNTS` | Si se establece en `true`, restringe las invitaciones a proyectos a las direcciones de correo electrónico que correspondan a cuentas de usuario existentes. |
| `OVERLEAF_ALLOW_PUBLIC_ACCESS` | Si se establece en `true`, permite que los usuarios no autenticados vean el sitio. El valor predeterminado es `false`, lo que significa que los usuarios no autenticados serán redirigidos incondicionalmente a la página de inicio de sesión cuando intenten ver cualquier parte del sitio. Ten en cuenta que establecer esta opción no desactiva en absoluto la autenticación ni la seguridad. Esta opción es necesaria si tus usuarios quieren hacer públicos sus proyectos y que usuarios no autenticados puedan verlos. |
| `OVERLEAF_ALLOW_ANONYMOUS_READ_AND_WRITE_SHARING` | Si se establece en `true`, permite que los usuarios anónimos vean y editen proyectos compartidos mediante la función de [compartir por enlace](https://www.overleaf.com/blog/integration-update-link-sharing-2017-11-27). |
| `OVERLEAF_DISABLE_LINK_SHARING` | Desactiva la función de [compartir por enlace](https://www.overleaf.com/blog/integration-update-link-sharing-2017-11-27). |
| `EMAIL_CONFIRMATION_DISABLED` | Si se establece en `true`, no se mostrará el banner que solicita la confirmación del correo electrónico. |
| `ADDITIONAL_TEXT_EXTENSIONS` | Un array de cadenas para configurar extensiones adicionales de archivos editables. |
| `DEFAULT_LATEX_COMPILER` | <p>Se usa para establecer el compilador predeterminado de los proyectos <strong>nuevos</strong>. (Añadida en Server Pro 6.2.0).</p><p><strong>Opciones:</strong> `pdflatex`, `latex`, `xelatex` o `lualatex`</p> |
| `OVERLEAF_STATUS_PAGE_URL` | URL de una página de estado personalizada (añadida en Server Pro 3.4.0), p. ej., `status.example.com`. |
| `OVERLEAF_FPH_INITIALIZE_NEW_PROJECTS` | Establécela en `'false'` para evitar que los proyectos nuevos se inicialicen con Full Project History (añadida en Server Pro 3.5.0). |
| `OVERLEAF_FPH_DISPLAY_NEW_PROJECTS` | Establécela en `'false'` para evitar que los proyectos nuevos muestren Full Project History en lugar del historial antiguo (añadida en Server Pro 3.5.0). |
| `ENABLE_CRON_RESOURCE_DELETION` | Establece esta variable de entorno en `true` para habilitar la limpieza automática de los proyectos y usuarios eliminados después de 90 días. |
| `OVERLEAF_USER_HARD_DELETION_DELAY` | <p>Se usa para modificar el plazo de expiración de los usuarios eliminados. Se configura en milisegundos.<br /><br /><strong>Valor predeterminado:</strong> 90 días</p> |
| `OVERLEAF_PROJECT_HARD_DELETION_DELAY` | <p>Se usa para modificar el plazo de expiración de los proyectos eliminados. Se configura en milisegundos.<br /><br /><strong>Valor predeterminado:</strong> 90 días</p> |
| `MAX_UPLOAD_SIZE` | <p>Controla el tamaño máximo de una subida individual, en megabytes. El valor predeterminado es `50`.<br /><br /><strong>Atención</strong>: esta variable es solo un número, sin unidad (MB) ni envoltorio.<br /><br />El tamaño total sin comprimir de un archivo `.zip` subido está limitado a 6 × este valor (300 MB de forma predeterminada).</p> |
| `COMPILE_SIZE_LIMIT` | Controla el tamaño máximo del cuerpo de la solicitud en bytes. Es la suma de los tamaños de todos los archivos de documento del proyecto (`main.tex`, `references.bib` (si no está vinculado), etc.) que deben enviarse en la solicitud de compilación inicial al servicio CLSI. |
| `COMPILE_TIMEOUT` | El tiempo en segundos permitido para que se complete una compilación. Para más información, consulta [Actualizar el tiempo de espera de compilación del proyecto](/es/on-premises/user-and-project-management/project-management#updating-project-compile-timeout). |
| `MAX_RECONNECT_GRACEFULLY_INTERVAL_MS` | Un retardo configurable entre la reconexión ordenada del editor, el volcado de datos y el apagado del contenedor, para mitigar el riesgo de pérdida de datos. |
| `SECCOMP_PROFILE` | <p>Establece esta variable de entorno en una ruta de la máquina <strong>host</strong> de Docker que apunte al perfil SECCOMP. Puedes descargar una copia del perfil <a href="https://raw.githubusercontent.com/overleaf/overleaf/365af778b68a7940e08282119dc4ef473e2f0044/services/clsi/seccomp/clsi-profile.json">aquí</a>.<br /><br />Actualmente es necesaria para los despliegues con Podman cuando se usan compilaciones aisladas.</p> |
| `OVERLEAF_DISABLE_CHAT` | Si se establece en `true`, desactiva la función de chat dentro del proyecto. |
| `OVERLEAF_DISABLE_LOCAL_LOGIN` | Si se establece en `true`, oculta el inicio de sesión con correo electrónico y contraseña para que los usuarios solo puedan iniciar sesión con LDAP, SAML u OIDC. Solo tiene efecto cuando `EXTERNAL_AUTH` habilita al menos uno de ellos (añadido en Ayakaleaf Pro 6.4.0). |
| `OVERLEAF_LOGIN_SUPPORT_TEXT` | Si se establece, puede usarse para mostrar información de soporte debajo del botón de inicio de sesión. El texto se mostrará en la pantalla de inicio de sesión y puede usarse para dirigir a los usuarios al soporte interno u ofrecer orientación sobre el inicio de sesión, la creación de cuentas, etc. |
| `ALLOW_MONGO_ADMIN_CHECK_FAILURES` | <p>Si se establece en `true`, permite que las comprobaciones de inicio de MongoDB fallen sin impedir que se inicie el despliegue. Puede ser necesario si usas una base de datos MongoDB en la que tu usuario de base de datos no tiene el rol `clusterParameterReader`.<br /><br />Para obtener ayuda sobre cómo crear un rol personalizado, consulta <a href="/es/on-premises/maintenance/updating-mongodb#creating-a-custom-role">aquí</a>.</p> |
| `V1_HISTORY_URL_FOR_GIT_BRIDGE` | Permite separar el endpoint de **history-v1** para el tráfico interno (servicio `web` → servicio `history-v1`, ambos en el contenedor `sharelatex`) y el tráfico externo (`git-bridge` → `history-v1`, que se ejecutan en contenedores separados). |
| `OVERLEAF_MAINTENANCE_MESSAGE` y `OVERLEAF_MAINTENANCE_MESSAGE_HTML` | Se usan para personalizar el título y el contenido de la página de mantenimiento. No se pueden usar junto con `OVERLEAF_STATUS_PAGE_URL`. |

<Info>

Es posible imponer restricciones de contraseña a los usuarios cuando se usa el sistema de inicio de sesión de Overleaf (cuentas locales), y no una opción de SSO como LDAP. En las cuentas SSO, las políticas de contraseñas las aplicará tu proveedor de identidad o servicio de directorio, lo que además permite admitir la autenticación multifactor.

</Info>
