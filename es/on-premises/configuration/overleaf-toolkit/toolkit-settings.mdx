Esta página describe las variables de entorno admitidas en el archivo `config/overleaf.rc` para los despliegues con el Toolkit.

El archivo `config/overleaf.rc` está formado por definiciones de variables con el formato `NAME=value`. Las líneas que empiezan por `#` se tratan como comentarios.

<Info>

Es necesario volver a crear los contenedores de Docker ejecutando `bin/up` después de cambiar cualquier cosa en `overleaf.rc` o `variables.env`.

</Info>

## Contenedor

### `sharelatex`

| Nombre                         | Descripción                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| ---------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `PROJECT_NAME`               | <p>Establece el valor de la opción `--project-name` que se pasa a `docker-compose`. Resulta útil al ejecutar varias instancias de Overleaf en un mismo host, ya que cada instancia puede tener un nombre de proyecto distinto.<br /><br />- <strong>Valor predeterminado</strong>: `overleaf`</p>                                                                                                                                                                                                                                                 |
| `OVERLEAF_IMAGE_NAME`        | <p>Imagen de Docker que usa el contenedor de la aplicación Server Pro/CE. Es solo el nombre de la imagen de Docker; la etiqueta de la imagen se obtiene de `config/version`.<br /><br />- <strong>Valor predeterminado:</strong><br />- Server Pro: `quay.io/sharelatex/sharelatex-pro`<br />- Community Edition: `sharelatex/sharelatex`</p>                                                                                                                                                                                                 |
| `SERVER_PRO`                 | <p>Cuando se establece en `true`, indica al Toolkit que use la imagen de Server Pro (`quay.io/sharelatex/sharelatex-pro`) en lugar de la imagen predeterminada de Server CE (`sharelatex/sharelatex`).<br /><br />- <strong>Valor predeterminado</strong>: `false`</p>                                                                                                                                                                                                                                                                   |
| `GIT_BRIDGE_ENABLED`         | <p>Establécela en `true` para habilitar la función git-bridge (solo Server Pro). Para más información, consulta la documentación de usuario <a href="https://www.overleaf.com/learn/how-to/Git_integration">https://www.overleaf.com/learn/how-to/Git_integration</a>.<br /><br />- <strong>Valor predeterminado:</strong> `false`</p>                                                                                                                                                                                                                        |
| `GIT_BRIDGE_IMAGE`           | <p>Imagen de Docker que usa el contenedor de git-bridge (solo Server Pro). Es solo el nombre de la imagen de Docker; la etiqueta de la imagen se obtiene de `config/version`.<br /><br />- <strong>Valor predeterminado:</strong> `quay.io/sharelatex/git-bridge`</p>                                                                                                                                                                                                                                                                              |
| `GIT_BRIDGE_DATA_PATH`       | Establece la ruta del directorio que se montará en el contenedor `git-bridge` (solo Server Pro) y que se usará para almacenar los repositorios git. Puede ser una ruta completa (que empiece por `/`) o relativa al directorio base del Toolkit.                                                                                                                                                                                                                                                                                     |
| `GIT_BRIDGE_LOG_LEVEL`       | <p>Configura el nivel de registro del contenedor `git-bridge`. Niveles disponibles: `TRACE`, `DEBUG`, `INFO`, `WARN`, `ERROR`.<br /><br />- <strong>Valor predeterminado:</strong> `INFO`</p>                                                                                                                                                                                                                                                                                       |
| `SIBLING_CONTAINERS_ENABLED` | <p>Cuando se establece en `true`, indica al Toolkit que use la técnica de <strong>Sibling Containers</strong> para compilar los proyectos en sandboxes independientes, usando un contenedor de Docker distinto para cada proyecto. Consulta la documentación de &#x3C;server-pro-only-configuration/sandboxed-compiles> para más información.<br /><br />- <strong>Requiere:</strong> `SERVER_PRO=true`<br />- <strong>Valor predeterminado:</strong> `true`</p>                                                                                                    |
| `SIBLING_CONTAINERS_PULL`    | <p>Cuando se establece en `true`, indica al Toolkit que descargue automáticamente todas las imágenes de TeX Live definidas mediante `ALL_TEX_LIVE_DOCKER_IMAGES` en el archivo <strong>config/variables.env</strong> al usar el comando `bin/up`.<br /><br />- <strong>Valor predeterminado:</strong> `true`</p>                                                                                                                                                                                                                                      |
| `DOCKER_SOCKET_PATH`         | <p>Establece la ruta del socket de Docker en la máquina host (la máquina que ejecuta el Toolkit). Cuando `SIBLING_CONTAINERS_ENABLED` es `true`, el socket se montará en el contenedor para permitir que el servicio de compilación cree nuevos contenedores de Docker en el host.<br /><br />- <strong>Requiere:</strong> `SIBLING_CONTAINERS_ENABLED=true`<br />- <strong>Valor predeterminado:</strong> `/var/run/docker.sock`</p>                                                                                               |
| `OVERLEAF_DATA_PATH`         | <p>Establece la ruta del directorio que se montará en el contenedor principal `sharelatex` y que se usará para almacenar los datos de compilación. Puede ser una ruta completa (que empiece por `/`) o relativa al directorio base del Toolkit.<br /><br />- <strong>Valor predeterminado:</strong> `data/overleaf`</p>                                                                                                                                                                                                               |
| `OVERLEAF_LISTEN_IP`         | <p>Establece la(s) dirección(es) IP del host a la(s) que se vinculará el contenedor. Por ejemplo, si se establece en `0.0.0.0`, la interfaz web estará disponible en cualquier dirección IP del host. Para el acceso directo al contenedor, el valor de `OVERLEAF_LISTEN_IP` debe establecerse en tu dirección IP pública. Establecer `OVERLEAF_LISTEN_IP` en `0.0.0.0` o en la IP externa de tu host suele provocar errores cuando se usa junto con el .<br /><br />- <strong>Valor predeterminado:</strong> `127.0.0.1`</p> |
| `OVERLEAF_PORT`              | <p>Establece el puerto del host al que se vinculará el contenedor. Por ejemplo, si se establece en `8099` y `OVERLEAF_LISTEN_IP` está establecida en `127.0.0.1`, la interfaz web estará disponible en `http://localhost:8099`.<br /><br />- <strong>Valor predeterminado:</strong> `80`</p>                                                                                                                                                                                                                        |
| `OVERLEAF_LOG_PATH`          | <p>Establece la ruta del directorio que se montará en el contenedor principal `sharelatex` y que se usará para que los registros de la aplicación estén disponibles en el host de Docker. Puede ser una ruta completa (que empiece por `/`) o relativa al directorio base del Toolkit. Elimina esta entrada de configuración para deshabilitar el montaje (bind-mount). Si no se define, los registros se descartarán al volver a crear el contenedor.<br /><br />Consulta para obtener información sobre el registro.<br /><br />- <strong>Valor predeterminado:</strong> sin definir</p>                                 |

### `mongo`

| Nombre              | Descripción                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| ----------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `MONGO_ENABLED`   | <p>Cuando se establece en `true`, indica al Toolkit que cree un contenedor de MongoDB para alojar la base de datos. Cuando se establece en `false`, este contenedor no se creará y el sistema usará en su lugar la base de datos de MongoDB especificada en `MONGO_URL`.<br /><br />- <strong>Valor predeterminado</strong>: `true`</p>                                                                                                                                 |
| `MONGO_URL`       | <p>Especifica la URL de conexión de MongoDB que se usará cuando `MONGO_ENABLED` sea `false`.<br /><br />- <strong>Valor predeterminado</strong>: sin definir</p>                                                                                                                                                                                                                                                                                                           |
| `MONGO_DATA_PATH` | <p>Establece la ruta del directorio que se montará en el contenedor `mongo` y que se usará para almacenar la base de datos de MongoDB. Puede ser una ruta completa (que empiece por `/`) o relativa al directorio base del Toolkit. Esta opción solo afecta al contenedor local `mongo` que se crea cuando `MONGO_ENABLED` es `true`.<br /><br />- <strong>Valor predeterminado</strong>: `data/mongo`</p> |
| `MONGO_IMAGE`     | <p>Imagen de Docker que usa el contenedor de MongoDB. Es solo el nombre de la imagen de Docker; la etiqueta de la imagen debe indicarse en `MONGO_VERSION` (ver más abajo).<br /><br />- <strong>Valor predeterminado:</strong> `mongo`</p>                                                                                                                                                                                                                             |
| `MONGO_VERSION`   | <p>Versión de MongoDB que usa el contenedor de MongoDB. El valor debe empezar por la versión principal de MongoDB seguida de un punto, p. ej. `6.0` o `6.0-with-suffix`.<br /><br />- <strong>Valor predeterminado:</strong> `6.0`</p>                                                                                                                                                                                                                             |

### `redis`

| Nombre                    | Descripción                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| ----------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `REDIS_ENABLED`         | <p>Cuando se establece en `true`, indica al Toolkit que cree un contenedor de Redis para alojar la base de datos de Redis. Cuando se establece en `false`, este contenedor no se creará y el sistema usará en su lugar la base de datos de Redis especificada en `REDIS_HOST` y `REDIS_PORT`.<br /><br />- <strong>Valor predeterminado</strong>: `true`</p>                                                                                                |
| `REDIS_HOST`            | <p>Especifica el host de Redis que se usará cuando `REDIS_ENABLED` sea `false`.<br /><br />- <strong>Valor predeterminado</strong>: sin definir</p>                                                                                                                                                                                                                                                                                                                     |
| `REDIS_PORT`            | <p>Especifica el puerto de Redis que se usará cuando `REDIS_ENABLED` sea `false`.<br /><br />- <strong>Valor predeterminado</strong>: sin definir</p>                                                                                                                                                                                                                                                                                                                     |
| `REDIS_DATA_PATH`       | <p>Establece la ruta del directorio que se montará en el contenedor `redis` y que se usará para almacenar la base de datos de Redis. Puede ser una ruta completa (que empiece por `/`) o relativa al directorio base del Toolkit. Esta opción solo afecta al contenedor local `redis` que se crea cuando `REDIS_ENABLED` es `true`.<br /><br />- <strong>Valor predeterminado</strong>: `data/redis`</p> |
| `REDIS_AOF_PERSISTENCE` | <p>Activa la persistencia AOF (Append Only File) para Redis. Es la configuración <strong>recomendada</strong> para la persistencia de Redis.<br /><br />Para más detalles, consulta la sección &#x3C;../../../maintenance/data-and-backups#aof-append-only-file> en &#x3C;../../maintenance/data-and-backups>.<br /><br />- <strong>Valor predeterminado:</strong> `true`</p>                                                                                               |

### `nginx`

| Nombre                   | Descripción                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `NGINX_ENABLED`        | <p>Cuando se establece en `true`, indica al Toolkit que cree un contenedor de NGINX que actúe como proxy TLS.<br /><br />- <strong>Valor predeterminado</strong>: `false`</p>                                                                                                                                                                                                                                                                                                                                 |
| `NGINX_CONFIG_PATH`    | <p>Ruta del archivo de configuración de NGINX que se usará para el proxy TLS.<br /><br />- <strong>Valor predeterminado</strong>: `config/nginx/nginx.conf`</p>                                                                                                                                                                                                                                                                                                                                                            |
| `NGINX_TLS_LISTEN_IP`  | <p>Establece la(s) dirección(es) IP del host a la(s) que se vinculará el contenedor del proxy TLS para HTTPS. Por ejemplo, si se establece en `0.0.0.0`, la interfaz web HTTPS estará disponible en cualquier dirección IP del host. Normalmente debería establecerse en la IP externa de tu host.<br /><br />- <strong>Valor predeterminado</strong>: `127.0.1.1`</p>                                                                                                                                                       |
| `NGINX_HTTP_LISTEN_IP` | <p>Establece la(s) dirección(es) IP del host a la(s) que se vinculará el contenedor del proxy TLS para la redirección HTTP. Por ejemplo, si se establece en `127.0.1.1`, las conexiones HTTP a `127.0.1.1` se redirigirán a la interfaz web HTTPS. Normalmente debería establecerse en la IP externa de tu host. No la establezcas en `0.0.0.0`, ya que normalmente provocará un conflicto con `OVERLEAF_LISTEN_IP`.<br /><br />- <strong>Valor predeterminado</strong>: `127.0.1.1`</p> |
| `NGINX_HTTP_PORT`      | <p>Establece el puerto del host al que se vinculará el contenedor del proxy TLS para HTTP.<br /><br />- <strong>Valor predeterminado</strong>: `80`</p>                                                                                                                                                                                                                                                                                                                                                                  |
| `TLS_PORT`             | <p>Establece el puerto del host al que se vinculará el contenedor del proxy TLS para HTTPS.<br /><br />- <strong>Valor predeterminado</strong>: `443`</p>                                                                                                                                                                                                                                                                                                                                                                |
| `TLS_PRIVATE_KEY_PATH` | <p>Ruta de la clave privada que se usará para el proxy TLS.<br /><br />- <strong>Valor predeterminado</strong>: `config/nginx/certs/overleaf_key.pem`</p>                                                                                                                                                                                                                                                                                                                                                      |
| `TLS_CERTIFICATE_PATH` | <p>Ruta del certificado público que se usará para el proxy TLS.<br /><br />- <strong>Valor predeterminado</strong>: `config/nginx/certs/overleaf_certificate.pem`</p>                                                                                                                                                                                                                                                                                                                                       |
