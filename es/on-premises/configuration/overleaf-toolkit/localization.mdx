### Configuración de i18n de Overleaf

<Info>

Este documento describe cómo configurar la internacionalización (i18n) de una instancia autoalojada de **Overleaf**.

</Info>

Overleaf se ha traducido a varios idiomas. Con la configuración adecuada, puedes:

* Ejecutar tu instancia de Overleaf en **un único idioma fijo**, o
* Habilitar **varios idiomas**, lo que permite a los usuarios cambiar de idioma dinámicamente, de forma similar a `www.overleaf.com`.

***

#### Configuración de un solo idioma

El idioma del sitio se configura mediante la variable de entorno `OVERLEAF_SITE_LANGUAGE` (o `SHARELATEX_SITE_LANGUAGE` para las versiones de Overleaf **4.x y anteriores**).

Los códigos de idioma admitidos incluyen:

* `en` - Inglés (predeterminado)
* `es` - Español
* `pt` - Portugués
* `de` - Alemán
* `fr` - Francés
* `cs` - Checo
* `nl` - Neerlandés
* `sv` - Sueco
* `it` - Italiano
* `tr` - Turco
* `zh-CN` - Chino (simplificado)
* `no` - Noruego
* `da` - Danés
* `ru` - Ruso
* `ko` - Coreano
* `ja` - Japonés
* `pl` - Polaco
* `fi` - Finés

El inglés es el idioma predeterminado. Para cambiar el idioma de la interfaz (por ejemplo, a chino simplificado), añade la siguiente línea a `config/variables.env`:

```bash title="config/variables.env"
OVERLEAF_SITE_LANGUAGE=zh-CN
```

A continuación, aplica la configuración:

```bash
bin/up
```

Una vez reiniciados los servicios, el idioma de los menús de la interfaz web debería reflejar el nuevo ajuste.

#### Configuración de varios idiomas

Para permitir que los usuarios **cambien de idioma sin cerrar sesión**, tu instancia de Overleaf debe configurarse para servir distintos idiomas según el nombre de dominio.

Esta sección supone que:

* Tu dominio principal es `overleaftest.com`
* Tienes un **certificado TLS comodín** (p. ej., `*.overleaftest.com`)
* **No usas `localhost`** (ya que no admite el enrutamiento de idiomas basado en subdominios)

Para pruebas locales, puedes usar un dominio como `dev-overleaf.com`.

<Steps>
<Step title="Configuración del proxy TLS (Nginx)">
Tu proxy inverso TLS debe reenviar la cabecera `Host` original para que Overleaf pueda determinar a qué dominio de idioma ha accedido el usuario.

Asegúrate de que esté presente la siguiente directiva:

```nginx
proxy_set_header Host $host;
```

Este es un ejemplo de configuración de Nginx:

```nginx
server {
    listen 443 ssl;
    server_name    _; # Catch all, see http://nginx.org/en/docs/http/server_names.html
    server_name *.overleaftest.com;
    ssl_certificate /etc/nginx/ssl/nginx.crt;
    ssl_certificate_key /etc/nginx/ssl/nginx.key;
    ssl_protocols               TLSv1 TLSv1.1 TLSv1.2;
    ssl_prefer_server_ciphers   on;
    # used cloudflares ciphers https://github.com/cloudflare/sslconfig/blob/master/conf
    ssl_ciphers EECDH+CHACHA20:EECDH+AES128:RSA+AES128:EECDH+AES256:RSA+AES256:EECDH+3DES:RSA+3DES:!MD5;

    # config to enable HSTS(HTTP Strict Transport Security) https://developer.mozilla.org/en-US/docs/Security/HTTP_Strict_Transport_Security
    # to avoid ssl stripping https://en.wikipedia.org/wiki/SSL_stripping#SSL_stripping	
    add_header Strict-Transport-Security "max-age=31536000; includeSubdomains;";
    server_tokens off;
    add_header X-Frame-Options SAMEORIGIN;
    add_header X-Content-Type-Options nosniff;
    client_max_body_size 50M;

    location / {
        proxy_pass http://localhost:5000; # change to whatever host/port the docker container is listening on.
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_read_timeout 3m;
        proxy_send_timeout 3m;
        
        # add this to your nginx conf
        proxy_set_header Host $host;
    }
}
```
</Step>

<Step title="Configurar el dominio de las cookies">
Para evitar que los usuarios cierren sesión al cambiar de idioma, las cookies deben compartirse entre los subdominios de idioma.

Añade la siguiente línea a `config/variables.env`:

```env title="config/variables.env"
# Note the leading dot
COOKIE_DOMAIN=.overleaftest.com
```

Esto garantiza que las cookies de autenticación sean válidas para todos los subdominios de `overleaftest.com`.
</Step>

<Step title="Asignación de idiomas a dominios">
A continuación, define cómo se asignan los códigos de idioma a los subdominios mediante\
`OVERLEAF_LANG_DOMAIN_MAPPING`.

#### Ejemplo de configuración

```dotenv title="config/variables.env" wrap
OVERLEAF_LANG_DOMAIN_MAPPING='{"www": {"lngCode": "en","url": "https:\/\/www.overleaftest.com"},"cn": {"lngCode": "zh-CN","url": "https:\/\/cn.overleaftest.com"}}'
```

Con esta configuración:

* `https://www.overleaftest.com` → interfaz en inglés
* `https://cn.overleaftest.com` → interfaz en chino simplificado

Puedes ampliar esta asignación con idiomas y subdominios adicionales según sea necesario.
</Step>

<Step title="Redirigir el dominio raíz">
Por último, redirige el dominio raíz (`overleaftest.com`) al dominio del idioma predeterminado (`www.overleaftest.com`).

```nginx
server{
    listen 80;
    server_name overleaftest.com;
    return 301 https://www.overleaftest.com$request_uri;
}

server {
    listen 443 ssl http2;
    server_name overleaftest.com;
    ssl_certificate     /path/to/fullchain.cer;
    ssl_certificate_key /path/to/overleaftest.com.key;
    return 301 https://www.overleaftest.com$request_uri;
}
```
</Step>
</Steps>
