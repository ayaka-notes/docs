### Configurar la integración con Zotero

1. Abre [este enlace](https://www.zotero.org/oauth/apps) para crear un cliente OAuth de Zotero (como se muestra en la imagen)
2. Elige **Application Type**: **Browser**
3. Configura la URL de callback con tu `${OVERLEAF_SITE_URL}/user/zotero/oauth/callback`
4. Configura tu `config/variables.env`

<Frame>
  <img src="/images/on-premises/image-41.png" alt="" width="375" />
</Frame>

```dotenv title="config/variables.env"
#################
#    Zotero     #
#################
# 'zotero' must be in ENABLED_LINKED_FILE_TYPES (set in develop/docker-compose.yml)
ENABLED_LINKED_FILE_TYPES=project_file,project_output_file,url,zotero

# From a Zotero OAuth client (register at https://www.zotero.org/oauth/apps)
# Application Type: Browser 
# Callback URL -> ${OVERLEAF_SITE_URL}/user/zotero/oauth/callback
ZOTERO_CLIENT_ID=
ZOTERO_CLIENT_SECRET=
# Encrypts the Zotero API key in mongo (set in dev to avoid writing a key file
# to /var/lib/overleaf/data, which the dev web container can't create)
# How to generate: `openssl rand -hex 32`
ZOTERO_CIPHER_PASSWORD=dev-zotero-cipher-password
# Optional: route the module's server-side Zotero requests (OAuth + API) through
# an HTTP proxy (must be reachable from the web container; same as github-sync)
# http://10.0.0.1:10808
# (Optional) ZOTERO_PROXY_URL=
```

### Notas

<Warning>

Al actualizar una instalación existente con archivos de bibliografía vinculados a Zotero a la versión 6.3.0 republicada, sigue las [instrucciones de migración de Zotero / Mendeley](/es/on-premises/release-notes/release-notes-6.x.x#ayakaleaf-pro-6.3.0  "mention"). Las instalaciones nuevas no necesitan esta migración.

</Warning>

<Danger>

Como Ayakaleaf es una plataforma colaborativa, para mejorar la seguridad, a partir de la versión 6.3.0 solo el creador original de un archivo `bib` de referencias podrá actualizar el archivo importado.

</Danger>

Por ejemplo, supongamos que el propietario del proyecto, el usuario A, habilita el uso compartido mediante enlace y crea un archivo `test.bib` en el proyecto, vinculándolo a su propia cuenta de Zotero. Si otro usuario, el usuario B, accede al proyecto a través del enlace compartido, el usuario B podrá seguir leyendo y descargando `test.bib`, pero no podrá actualizar ni volver a importar el archivo desde Zotero. Solo el usuario A, como creador original del archivo de referencias, puede realizar actualizaciones. Dicho de otro modo, solo el creador original del archivo `.bib` tiene permiso para actualizarlo.

### Preguntas y respuestas

<Accordion title="¿Cómo uso Zotero en un proyecto?">

<strong>Respuesta:</strong> Después de vincular Zotero en **Account Settings**, abre un proyecto y haz clic en **New file → From Zotero**. Elige un nombre de archivo, `zotero.bib` por defecto, y la biblioteca, y después crea el archivo. Cita sus entradas como de costumbre, por ejemplo con `\bibliography{zotero}`.

El archivo es de solo lectura en el editor. Después de cambiar tu biblioteca de Zotero, abre el archivo y haz clic en **Refresh** para volver a importarlo.

</Accordion>

<Accordion title="¿Por qué «Main bibliography file for this project» está vacío o deshabilitado?">

<strong>Respuesta:</strong> Este ajuste solo muestra los archivos `.bib` que se pueden editar en el editor. Los archivos importados desde Zotero son de solo lectura, así que no aparecen. Es el comportamiento esperado: puedes seguir citando sus entradas.

</Accordion>

<Accordion title="¿Mi instancia tiene que ser accesible desde internet?">

<strong>Respuesta:</strong> No. La vinculación de Zotero pasa por el navegador del usuario, así que solo el servidor necesita llegar a Zotero. Si para ello necesita un proxy, establece `ZOTERO_PROXY_URL`.

</Accordion>
