Cada proyecto tiene un servidor MCP, de modo que clientes de IA como Claude Code, Codex, Cursor, VS Code o Gemini CLI pueden trabajar en él: leer y editar sus archivos, compilarlo, leer el registro de LaTeX, descargar el PDF y responder a los comentarios.

<Info>

Esta función ha sido desarrollada por [ayaka-notes/ayakaleaf-pro](https://github.com/ayaka-notes/ayakaleaf-pro). Está disponible a partir de la v6.3.1.

</Info>

### Configuración

El servidor MCP viene con la integración con Git: habilita [git-bridge](/es/on-premises/configuration/overleaf-toolkit/integrations/git-integration) y el servidor MCP también estará disponible. No hay nada más que configurar.

### Conectar un cliente de IA

1. En **Configuración de la cuenta**, genera un token de autenticación de Git. El mismo token se usa para el servidor MCP y para Git.
2. En el editor, abre **Integraciones** y haz clic en **Servidor MCP**. Se muestra la dirección del servidor MCP del proyecto, `https://<your-overleaf>/project/<project_id>/mcp`, y cómo añadirlo a cada cliente de IA: copia el comando y sustituye `<token>` por tu token.

El token se envía como la cabecera HTTP `Authorization: Bearer <token>`. Por ejemplo, el comando para Claude Code es:

```bash
claude mcp add --transport http overleaf \
  https://<your-overleaf>/project/<project_id>/mcp \
  --header "Authorization: Bearer <token>"
```

### Uso

Una vez conectado, pídele al cliente de IA lo que necesites con tus propias palabras. Por ejemplo:

| Lo que pides | El cliente de IA usa |
| --- | --- |
| _Corrige las erratas de la introducción._ | `read_file`, `edit_file`: las ediciones aparecen en tiempo real en el editor |
| _Compila el proyecto y corrige los errores de LaTeX._ | `compile`, `get_compile_log`, `edit_file` |
| _Responde a los comentarios abiertos y luego resuélvelos._ | `list_comments`, `reply_to_comment`, `resolve_comment` |
| _Cambia a XeLaTeX y descarga el PDF._ | `update_settings`, `compile`, `get_output_file_link` |

### Herramientas

| Grupo | Herramientas |
| --- | --- |
| Proyecto | `get_clone_info`, `get_settings`, `update_settings`, `list_versions` |
| Archivos | `list_files`, `read_file`, `edit_file`, `write_file`, `delete_file` |
| Compilación | `compile`, `get_compile_log`, `get_output_file_link`, `word_count` |
| Comentarios | `list_comments`, `reply_to_comment`, `resolve_comment`, `reopen_comment` |

Las ediciones hechas con `edit_file` y `write_file` aparecen en tiempo real en el editor y se combinan con las de los colaboradores. Para muchos archivos a la vez, archivos binarios o cambios de nombre, el cliente de IA también puede clonar el proyecto con Git y hacer push.

### Permisos

El servidor MCP respeta la configuración de uso compartido del proyecto, igual que Git:

* Cualquier persona que pueda ver el proyecto puede leerlo, compilarlo y descargar sus resultados.
* Solo el propietario y los editores pueden modificar sus archivos y su configuración.
* Los revisores también pueden responder a los comentarios, y resolver o reabrir los comentarios que iniciaron.
* Los lectores que se unieron mediante un enlace no pueden ver los comentarios, igual que en el editor.

### Preguntas y respuestas

<Accordion title="No veo Integrations ni el servidor MCP en el editor">

<strong>Respuesta:</strong> El servidor MCP no tiene ninguna variable de entorno propia. Se habilita con `GIT_BRIDGE_ENABLED=true` en `config/overleaf.rc`; consulta [Integración con Git](/es/on-premises/configuration/overleaf-toolkit/integrations/git-integration). Después de cambiarla, ejecuta `bin/up -d`. Sin el git-bridge, el editor no muestra la pestaña **Integrations** en su barra lateral izquierda.

</Accordion>
