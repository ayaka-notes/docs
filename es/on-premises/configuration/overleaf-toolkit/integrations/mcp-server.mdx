Cada proyecto tiene un servidor MCP, de modo que clientes de IA como Claude Code, Codex, Cursor, VS Code o Gemini CLI pueden trabajar en él: leer y editar sus archivos, compilarlo, leer el registro de LaTeX, descargar el PDF y responder a los comentarios. Desde v6.3.3 también pueden revisar el historial y restaurar versiones, revisar cambios con seguimiento, añadir comentarios, usar el chat del proyecto y mover archivos.

<Info>

Esta función ha sido desarrollada por [ayaka-notes/ayakaleaf-pro](https://github.com/ayaka-notes/ayakaleaf-pro). Está disponible a partir de la v6.3.1. Las herramientas de historial, cambios con seguimiento, chat del proyecto, nuevos comentarios y movimiento de archivos están disponibles desde v6.3.3, consulta [Novedades de v6.3.3](/on-premises/user-guide/users/mcp-server#new-in-v6.3.3).

</Info>

### Configuración {#setup}

El servidor MCP viene con la integración con Git: habilita [git-bridge](/es/on-premises/configuration/overleaf-toolkit/integrations/git-integration) y el servidor MCP también estará disponible. No hay nada más que configurar.

### Conectar un cliente de IA {#connect-an-ai-client}

1. En **Configuración de la cuenta**, genera un token de autenticación de Git. El mismo token se usa para el servidor MCP y para Git.
2. En el editor, abre **Integraciones** y haz clic en **Servidor MCP**. Se muestra la dirección del servidor MCP del proyecto, `https://<your-overleaf>/project/<project_id>/mcp`, y cómo añadirlo a cada cliente de IA: copia el comando y sustituye `<token>` por tu token.

El token se envía como la cabecera HTTP `Authorization: Bearer <token>`. Por ejemplo, el comando para Claude Code es:

```bash
claude mcp add --transport http overleaf \
  https://<your-overleaf>/project/<project_id>/mcp \
  --header "Authorization: Bearer <token>"
```

### Uso {#usage}

Una vez conectado, pídele al cliente de IA lo que necesites con tus propias palabras. Por ejemplo:

| Lo que pides | El cliente de IA usa |
| --- | --- |
| _Corrige las erratas de la introducción._ | `read_file`, `edit_file`: las ediciones aparecen en tiempo real en el editor |
| _Compila el proyecto y corrige los errores de LaTeX._ | `compile`, `get_compile_log`, `edit_file` |
| _Responde a los comentarios abiertos y luego resuélvelos._ | `list_comments`, `reply_to_comment`, `resolve_comment` |
| _Cambia a XeLaTeX y descarga el PDF._ | `update_settings`, `compile`, `get_output_file_link` |
| _Reescribe el resumen como un cambio con seguimiento._ | `read_file`, `edit_file` con `trackChanges` (v6.3.3) |
| _¿Qué ha cambiado desde la versión enviada?_ | `list_versions`, `list_changes`, `diff` (v6.3.3) |
| _Mueve los capítulos a una carpeta llamada chapters._ | `move_file` (v6.3.3) |

### Herramientas {#tools}

| Grupo | Herramientas |
| --- | --- |
| Proyecto | `get_clone_info`, `get_settings`, `update_settings` |
| Archivos | `list_files`, `read_file`, `edit_file`, `write_file`, `delete_file`, `move_file`, `create_folder` |
| Compilación | `compile`, `get_compile_log`, `get_output_file_link`, `word_count` |
| Comentarios | `list_comments`, `reply_to_comment`, `resolve_comment`, `reopen_comment`, `add_comment`, `edit_comment_message`, `delete_comment_message` |
| Cambios con seguimiento | `list_tracked_changes`, `accept_tracked_changes`, `reject_tracked_changes` |
| Historial | `list_versions`, `list_changes`, `diff`, `create_version`, `delete_version`, `restore_file`, `restore_project` |
| Chat | `list_chat_messages`, `send_chat_message` |

v6.3.3 tiene 33 herramientas, o 31 con `OVERLEAF_DISABLE_CHAT=true`, que elimina las herramientas de chat. v6.3.1 y v6.3.2 tienen las otras 17: todo lo anterior excepto `move_file`, `create_folder`, `add_comment`, `edit_comment_message`, `delete_comment_message`, las herramientas de cambios con seguimiento, las de chat y las de historial distintas de `list_versions`. En v6.3.3, `read_file` también lee un archivo en una versión del historial, `edit_file` y `write_file` aceptan `trackChanges`, y `update_settings` también define el idioma del corrector ortográfico.

Las ediciones hechas con `edit_file`, `write_file` y `move_file` aparecen en directo en el editor y se combinan con las de los colaboradores. Para muchos archivos a la vez o archivos binarios, el cliente de IA también puede clonar el proyecto con Git y hacer push.

Con `trackChanges`, la edición de un archivo existente es un cambio con seguimiento del usuario del token, aunque el control de cambios esté desactivado en el proyecto; un archivo nuevo nunca lo es. Sin `trackChanges`, las ediciones siguen la configuración de control de cambios del proyecto.

### Permisos {#permissions}

El servidor MCP respeta la configuración de uso compartido del proyecto, igual que Git:

* Todas las personas que pueden ver el proyecto pueden leerlo, compilarlo y descargar su salida.
* Solo el propietario y los editores pueden cambiar sus archivos y su configuración, restaurar versiones y aceptar o rechazar cambios con seguimiento.
* Los revisores también pueden añadir comentarios y responderlos, resolver, reabrir o eliminar los comentarios que iniciaron, y guardar versiones. No pueden editar archivos, ni siquiera como cambios con seguimiento.
* Cada persona edita solo sus propios mensajes de comentario, y los revisores eliminan solo los suyos.
* Solo el propietario elimina versiones que otros guardaron.
* Los lectores que se unieron mediante un enlace no pueden ver los comentarios, los cambios con seguimiento, el historial ni el chat, igual que en el editor. Los lectores invitados pueden verlos y usar el chat.
* Si el propietario del proyecto no tiene **Full project history**, las herramientas de historial muestran solo los cambios de las últimas 24 horas, como el panel de historial. Los administradores los ven todos.

La guía del usuario tiene una tabla con lo que puede hacer cada rol, consulta [Quién puede hacer qué](/on-premises/user-guide/users/mcp-server#who-may-do-what).

### Preguntas y respuestas {#q&a}

<Accordion title="No veo Integrations ni el servidor MCP en el editor">

<strong>Respuesta:</strong> El servidor MCP no tiene ninguna variable de entorno propia. Se habilita con `GIT_BRIDGE_ENABLED=true` en `config/overleaf.rc`; consulta [Integración con Git](/es/on-premises/configuration/overleaf-toolkit/integrations/git-integration). Después de cambiarla, ejecuta `bin/up -d`. Sin el git-bridge, el editor no muestra la pestaña **Integrations** en su barra lateral izquierda.

</Accordion>

<Accordion title="El cliente de IA dice «Track changes is off for this project»">

<strong>Respuesta:</strong> El cliente pidió un cambio con seguimiento, pero la cuenta del propietario del proyecto no tiene control de cambios. Haz clic en **Admin** y luego en **Manage Users**, abre al propietario y, en la pestaña **Features**, activa **Track changes**, consulta [Features](/es/on-premises/user-guide/administrators/user-management#features). Las ediciones sin `trackChanges` siguen funcionando.

</Accordion>

<Accordion title="El cliente de IA solo ve los cambios de las últimas 24 horas">

<strong>Respuesta:</strong> La cuenta del propietario del proyecto no tiene el historial completo del proyecto, así que las herramientas de historial muestran lo mismo que el panel de historial: los cambios de las últimas 24 horas. Haz clic en **Admin** y luego en **Manage Users**, abre al propietario y, en la pestaña **Features**, activa **Full project history**, consulta [Features](/es/on-premises/user-guide/administrators/user-management#features).

</Accordion>
