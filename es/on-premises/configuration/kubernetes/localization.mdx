El servicio **web** elige el idioma de la interfaz a partir de los ajustes siguientes, en cada petición según el nombre de host que usó el navegador. Los idiomas y los ajustes se describen en [Localización](/es/on-premises/configuration/overleaf-toolkit/localization).

| | |
| --- | --- |
| Servicio | web, en cada pod de Ayakaleaf Pro; se lee cuando web arranca |
| Red | un nombre de host por idioma, todos dirigidos a Ayakaleaf Pro |
| Tareas periódicas | ninguna |

### Un solo idioma

```yaml
  OVERLEAF_SITE_LANGUAGE: zh-CN
```

```bash
kubectl apply -f 30-config.yaml
kubectl -n overleaf rollout restart deployment/overleaf     # or statefulset/overleaf
```

### Varios idiomas en subdominios

<Steps>
<Step title="Dirigir cada host de idioma a Ayakaleaf Pro">
Añade un nombre DNS por idioma y dirígelos todos a Ayakaleaf Pro con un certificado que los cubra, por ejemplo `*.example.com`. Tu ingress o balanceador de carga debe pasar la cabecera `Host` sin cambios, algo que ingress-nginx y HAProxy hacen por defecto.

Los usuarios deben acceder a los hosts de idioma en los puertos estándar (`https://cn.example.com`, no `https://cn.example.com:30443`): Ayakaleaf Pro compara el host sin el puerto.
</Step>

<Step title="ConfigMap">
```yaml title="30-config.yaml (additions)" wrap
  OVERLEAF_SITE_URL: https://www.example.com
  COOKIE_DOMAIN: .example.com
  OVERLEAF_LANG_DOMAIN_MAPPING: '{"www": {"lngCode": "en", "url": "https://www.example.com"}, "cn": {"lngCode": "zh-CN", "url": "https://cn.example.com"}}'
```

`COOKIE_DOMAIN` hace que la cookie de inicio de sesión funcione en todos los hosts de idioma. Pon el JSON entre comillas simples. Un JSON no válido en `OVERLEAF_LANG_DOMAIN_MAPPING` detiene todos los servicios del pod al arrancar, así que comprueba `kubectl -n overleaf get pod` después del reinicio.
</Step>
</Steps>

### Varias réplicas

El idioma proviene del nombre de host de cada petición, por lo que no depende de la réplica. La cookie de afinidad del balanceador de carga se establece por nombre de host salvo que le indiques un dominio, de modo que cambiar de idioma puede llevar a un usuario a otra réplica; su sesión está en Redis y sigue siendo válida.

### Probado en Kubernetes

En Kubernetes 1.37 detrás de HAProxy, con `OVERLEAF_LANG_DOMAIN_MAPPING` asignando el host del sitio al inglés, un host `de.` al alemán y un host `fr.` con el NodePort `:30081` al francés: el host del sitio mostró inglés, el host `de.` alemán, y el host `fr.` con el puerto volvió al inglés, como se describe arriba.
