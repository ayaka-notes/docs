Un despliegue de Kubernetes lee las mismas variables de entorno que el Toolkit. Cuando una página del Toolkit diga "añade esto a `config/variables.env`", pon el valor en el ConfigMap `overleaf-env`, o en el Secret `overleaf-secrets` si se trata de una contraseña, una clave o un token. Después, reinicia:

```bash
kubectl -n overleaf apply -f 30-config.yaml        # after editing the ConfigMap
kubectl -n overleaf patch secret overleaf-secrets --type merge \
  -p '{"stringData":{"GITHUB_TOKEN_CIPHER_PASSWORD":"'"$(openssl rand -hex 32)"'"}}'
kubectl -n overleaf rollout restart deployment/overleaf
```

Los valores de `config/overleaf.rc` son ajustes del Toolkit, no variables de entorno; las preguntas y respuestas al final de esta página indican qué los sustituye.

### Certificados y otros archivos

Algunas funciones admiten una ruta de archivo en lugar de un valor: los certificados SAML (`OVERLEAF_SAML_IDP_CERT`, ...), la CA de LDAP (`OVERLEAF_LDAP_TLS_OPTS_CA_PATH`) o una CA privada para un GitHub Enterprise, GitLab o Gitea autoalojado (`NODE_EXTRA_CA_CERTS`). Guarda los archivos en un Secret y móntalo donde los esperan las páginas del Toolkit, `/var/lib/overleaf/certs`:

```bash
kubectl -n overleaf create secret generic overleaf-certs --from-file=idp_cert.pem --from-file=ca.pem
```

```yaml title="40-overleaf.yaml (additions)"
          volumeMounts:
            # ...
            - name: certs
              mountPath: /var/lib/overleaf/certs
              readOnly: true
      volumes:
        # ...
        - name: certs
          secret:
            secretName: overleaf-certs
```

Después, haz referencia a ellos por su ruta en el ConfigMap, por ejemplo `NODE_EXTRA_CA_CERTS: /var/lib/overleaf/certs/ca.pem`, y reinicia.

<Warning>

<strong>Contraseñas de cifrado.</strong> Define en el Secret todas las `*_CIPHER_PASSWORD` de las funciones que uses. De lo contrario, algunas funciones generan un archivo de clave en el volumen de datos la primera vez que se usan: con una réplica funciona hasta que se pierde el volumen; con varias réplicas, cada réplica cifraría con una clave distinta.

</Warning>

### Preguntas y respuestas

<Accordion title="¿Qué ajustes del Toolkit de `config/overleaf.rc` necesito?">

<strong>Respuesta:</strong> Ayakaleaf Pro no lee ninguno de ellos. Sus equivalentes en Kubernetes:

| `config/overleaf.rc`                         | Kubernetes                                                        |
| -------------------------------------------- | ----------------------------------------------------------------- |
| `OVERLEAF_LISTEN_IP`, `OVERLEAF_PORT`        | el Service (NodePort) o tu ingress                            |
| `SIBLING_CONTAINERS_ENABLED`                 | `SANDBOXED_COMPILES*` en el ConfigMap, el socket de Docker en el pod  |
| `GIT_BRIDGE_ENABLED`                         | [Integración con Git](/es/on-premises/configuration/kubernetes/integrations/git-integration)                             |
| `MONGO_ENABLED`, `REDIS_ENABLED`, `MONGO_URL`, `REDIS_HOST` | los StatefulSets o tus servicios gestionados, `OVERLEAF_MONGO_URL` y `OVERLEAF_REDIS_HOST` |
| `REDIS_AOF_PERSISTENCE`                      | `--appendonly yes` en `20-redis.yaml`                             |
| `NGINX_ENABLED`, `TLS_*`                     | tu ingress o balanceador de carga                                     |

</Accordion>
