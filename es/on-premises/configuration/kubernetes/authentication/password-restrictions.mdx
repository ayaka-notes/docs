---

El servicio **web** comprueba las contraseñas locales cuando los usuarios se registran, establecen o cambian una contraseña. Los inicios de sesión SSO (LDAP, SAML, OIDC) no se ven afectados; sus contraseñas son responsabilidad del proveedor de identidad. Consulta [Restricciones de contraseña](/es/on-premises/configuration/overleaf-toolkit/authentication/password-restrictions) para el Toolkit.

| | |
| --- | --- |
| Servicio | web, en cada pod de Ayakaleaf Pro; se lee cuando web arranca |
| Red | ninguna |
| Tareas periódicas | ninguna |

### Configuración

Añade al ConfigMap `overleaf-env` y reinicia:

```yaml title="30-config.yaml (additions)"
  OVERLEAF_PASSWORD_VALIDATION_MIN_LENGTH: "12"
  OVERLEAF_PASSWORD_VALIDATION_MAX_LENGTH: "72"
```

```bash
kubectl apply -f 30-config.yaml
kubectl -n overleaf rollout restart deployment/overleaf     # or statefulset/overleaf
```

| Variable | Valor por defecto | |
| --- | --- | --- |
| `OVERLEAF_PASSWORD_VALIDATION_MIN_LENGTH` | `8` | Contraseña más corta aceptada. |
| `OVERLEAF_PASSWORD_VALIDATION_MAX_LENGTH` | `72` | Contraseña más larga aceptada; los valores superiores a `72` se tratan como `72`. |

Pon los números entre comillas: un ConfigMap solo contiene cadenas.

<Warning>

`OVERLEAF_PASSWORD_VALIDATION_PATTERN` se lee pero no se aplica: se acepta una contraseña que no lo cumpla. Solo se aplican los límites de longitud.

</Warning>

### Varias réplicas

No hace falta nada más: todas las réplicas leen el mismo ConfigMap.

### Probado en Kubernetes

En Kubernetes 1.37 con una réplica, `OVERLEAF_PASSWORD_VALIDATION_MIN_LENGTH: "12"` y `OVERLEAF_PASSWORD_VALIDATION_PATTERN: aA$3` en el ConfigMap, al activar una cuenta nueva se rechazó una contraseña de 10 caracteres y se aceptó una contraseña de 20 caracteres formada solo por minúsculas, que el patrón habría rechazado. Nuestras pruebas de extremo a extremo para el registro también rechazan `123456` por ser demasiado corta con los valores por defecto.
