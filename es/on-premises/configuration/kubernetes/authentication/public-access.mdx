El acceso de invitados a proyectos compartidos, las páginas públicas y el autorregistro se activan con variables de entorno que lee el servicio **web**; después, el servicio de tiempo real atiende a los invitados mediante su sesión. Lo que abre cada opción se describe en [Acceso público](/es/on-premises/configuration/overleaf-toolkit/authentication/public-access).

| | |
| --- | --- |
| Servicio | web (y real-time para los invitados en el editor), en cada pod de Ayakaleaf Pro; se lee cuando web arranca |
| Pod → exterior | el servidor SMTP, cuando el registro envía correos de activación |
| Estado | los tokens de acceso de invitados en la sesión, los límites de frecuencia del registro en Redis |
| Tareas periódicas | ninguna |

### Configuración

Añade las opciones que necesites al ConfigMap `overleaf-env`:

```yaml title="30-config.yaml (additions)"
  # Guests open link-shared projects without an account
  OVERLEAF_ALLOW_ANONYMOUS_READ_AND_WRITE_SHARING: "true"
  # Signed-out visitors may open /learn, /templates, /devs and view links
  OVERLEAF_ALLOW_PUBLIC_ACCESS: "true"
  # Self-registration: "true", or only some domains
  OVERLEAF_ALLOW_PUBLIC_REGISTRATION: "@example.com, @*.uni.example"
```

```bash
kubectl apply -f 30-config.yaml
kubectl -n overleaf rollout restart deployment/overleaf     # or statefulset/overleaf
```

Pon todos los valores entre comillas. Los valores que empiezan por `@` deben ir entre comillas en YAML; de lo contrario, `kubectl apply` rechaza el archivo.

El registro limitado a dominios envía un correo de activación, por lo que el [envío de correo electrónico](/es/on-premises/configuration/kubernetes/email-delivery) debe funcionar desde los pods: pon el host SMTP en el ConfigMap y `OVERLEAF_EMAIL_SMTP_PASS` en el Secret.

### Varias réplicas

No hace falta nada más. El acceso de un invitado a un proyecto se guarda en la sesión en Redis, por lo que el editor funciona en cualquier réplica que elija el balanceador de carga.

### Probado en Kubernetes

En Kubernetes 1.37, nuestras pruebas de extremo a extremo para el acceso público se superan: en una réplica, el autorregistro con `OVERLEAF_ALLOW_PUBLIC_REGISTRATION` establecido en `true`, en un dominio, en varios dominios con un comodín de subdominio y en `@*`, con el correo de activación para los modos por dominio (43 casos); los visitantes sin sesión iniciada en `/devs` y un fragmento enviado que se conserva tras el inicio de sesión con `OVERLEAF_ALLOW_PUBLIC_ACCESS` (2 casos); un invitado sin sesión iniciada en un proyecto compartido por enlace con ambas opciones activadas (3 casos); y, en tres réplicas detrás de HAProxy, OIDC junto con el acceso público (1 caso).
