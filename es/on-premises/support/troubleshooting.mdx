<Accordion title="Ejecutar Overleaf con un sistema de archivos NFS">

Montar un sistema de archivos NFS en un contenedor de Overleaf es técnicamente posible, pero no se recomienda y puede provocar distintos tipos de errores de rendimiento.

Un error habitual que aparece en las compilaciones es:

```text
EBUSY: resource busy or locked, unlink '/var/lib/overleaf/data/compiles/62f3d57bef7cf9005c364e75-62f3d57bef7cf9005c364e7a/.nfs573663533034825247625441'
```

En particular, desaconsejamos utilizar sistemas de archivos respaldados por NFS para datos efímeros, como los directorios que se usan para los datos de compilación. Recomendamos utilizar un disco temporal local, preferiblemente un SSD local, para los siguientes directorios.

En las instalaciones basadas en `docker-compose`, sugerimos simplemente sobrescribir el bind-mount de NFS, lo que evita cambiar rutas en la aplicación. Este es un ejemplo de extracto de configuración de `docker-compose` que utiliza un disco temporal montado en `/scratch`:

```yaml title="docker-compose excerpt"
services:
  sharelatex:
    environment:
      SANDBOXED_COMPILES_HOST_DIR: /scratch/compiles/
    volumes:
      - nfs:/var/lib/overleaf/data
      - /scratch/cache/:/var/lib/overleaf/data/cache
      - /scratch/compiles/:/var/lib/overleaf/data/compiles
      - /scratch/output/:/var/lib/overleaf/data/output
      - /scratch/tmp/:/var/lib/overleaf/tmp
```

No es necesario migrar ningún archivo existente desde el NFS a su nueva ubicación después de la actualización. El compilador de LaTeX puede volver a crear todos los archivos con una nueva compilación completa.

Para obtener más detalles, consulte: https://docs.overleaf.com/on-premises/support/troubleshooting#running-overleaf-with-an-nfs-filesystem

</Accordion>

<Accordion title="Al ejecutar Overleaf en Windows o macOS, el servicio `mongo` no se inicia">

Si ejecuta Overleaf en Windows o macOS, es posible que el servicio `mongo` no logre reiniciarse y muestre el siguiente error:

```text title="Example error"
Failed to start up WiredTiger under any compatibility version.
Reason: 1: Operation not permitted
```

Para evitar este error, los datos deben almacenarse en un volumen en lugar de en un directorio con bind mount (consulte la documentación de la imagen `mongo` para obtener más detalles: https://github.com/docker-library/docs/blob/master/mongo/content.md#where-to-store-data). Para almacenar los datos en volúmenes de Docker montados dentro de los contenedores de MongoDB y Redis, añada lo siguiente a `config/docker-compose.override.yml` (cree este archivo si aún no existe):

```yaml title="config/docker-compose.override.yml"
volumes:
  mongo-data:
  redis-data:

services:
  mongo:
    volumes:
      - mongo-data:/data/db

  redis:
    volumes:
      - redis-data:/data
```

Para obtener más información, consulte: https://docs.overleaf.com/on-premises/support/troubleshooting#running-overleaf-on-windows-or-macos-results-in-the-mongoservice-not-starting

</Accordion>

<Accordion title="La actualización a Redis 6.2 provoca un bucle de reinicios">

Utilice el comando `docker logs redis` para obtener una copia de los registros.

Si ve la línea `Fatal: Can't initialize Background Jobs`, la salida completa tendrá un aspecto similar a este:

```text title="Redis log example"
1:M 11 Feb 2024 15:19:22.609 # Server initialized
1:M 11 Feb 2024 15:19:22.609 # Fatal: Can't initialize Background Jobs.
1:C 11 Feb 2024 15:19:26.055 # oO0OoO0OoO0Oo Redis is starting oO0OoO0OoO0Oo
```

Esto puede estar relacionado con la versión de Docker que se esté utilizando. Actualizar a una versión >= 20.10.10 debería resolver este problema.

Para obtener más información, consulte la incidencia original de Redis: https://github.com/redis/redis/issues/12362

Referencia: https://docs.overleaf.com/on-premises/support/troubleshooting#upgrading-to-redis-6.2-results-in-a-restart-loop

</Accordion>

<Accordion title="Orientación incorrecta de las imágenes de vista previa/miniatura de la galería de plantillas">

En ocasiones, las imágenes de vista previa/miniatura generadas por Server Pro pueden crearse con una orientación incorrecta y requerir una intervención manual para corregirlas. Estas imágenes se almacenan en `/var/lib/overleaf/data/template_files/` (>= 5.0.3) y en `/var/lib/sharelatex/data/template_files/` (versiones anteriores).

Recomendamos hacer una copia de seguridad de esta carpeta antes de realizar cualquier cambio.

Deberá seguir los pasos que se indican a continuación para cada plantilla afectada:

Busque el ID de la plantillaVaya a la galería de plantillas de su instancia (/templates/all), abra una plantilla afectada y copie el ID de la URL (por ejemplo: https://your-instance-url/templates/6645d346c224815e9460a695).Ejecute el comando de correcciónEjecute el siguiente comando desde el host de Docker (sustituya el ID de la plantilla por el que ha copiado y actualice la ruta si procede):docker exec sharelatex /bin/bash -c "mogrify -rotate 90 /var/lib/overleaf/data/template\_files/6645d346c224815e9460a695\_\*\{thumbnail,preview\}"

Referencia: https://docs.overleaf.com/on-premises/support/troubleshooting#incorrect-orientation-of-template-gallery-preview-thumbnail-images

</Accordion>

<Accordion title="Compruebe que ha habilitado las llamadas al sistema. Para pdflatex, esto es 'pdflatex -shell-escape'.">

El comando `\write18` está deshabilitado de forma predeterminada en Community Edition, ya que todas las compilaciones se realizan dentro del mismo contenedor `sharelatex`; este es el valor predeterminado más seguro.

Si desea habilitarlo para pdflatex, cree un archivo `latexmkrc` en la raíz de su proyecto con el siguiente contenido:

```perl title="latexmkrc"
$pdflatex = 'pdflatex --shell-escape';
```

A continuación, intente volver a compilar.

Referencia: https://docs.overleaf.com/on-premises/support/troubleshooting#please-verify-that-you-have-enabled-system-calls.-for-pdflatex-this-is-pdflatex-shell-escape

</Accordion>
