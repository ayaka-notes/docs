### El Doctor

El Overleaf Toolkit incluye un práctico script `doctor` que ayuda a depurar problemas. Ejecuta `bin/doctor` y el script mostrará información sobre tu entorno anfitrión, tu configuración y las dependencias que necesita el Toolkit. Esta salida también puede ayudarnos a diagnosticar problemas en tus instalaciones de Ayakaleaf Pro.

<Info>

Los usuarios de Overleaf Pro pueden [abrir un issue en GitHub](https://github.com/ayaka-notes/overleaf/issues).

Es buena idea incluir la salida del script `bin/doctor` en tu mensaje.

</Info>

### Consultar al Doctor

Ejecuta el script doctor:

```bash title="Run doctor"
bin/doctor
```

### Información del host

La sección `Host Information` contiene información sobre la máquina que ejecuta el Toolkit (por ejemplo, la distribución y la versión de Linux).

<Accordion title="Ejemplo de salida de Host Information">

```text
- Host Information
    - Linux
    - Output of 'lsb_release -a':
            No LSB modules are available.
            Distributor ID:	Ubuntu
            Description:	Ubuntu 22.04.5 LTS
            Release:	22.04
            Codename:	jammy
```

</Accordion>

### Dependencias

La sección `Dependencies` enumera las herramientas necesarias para que el Toolkit funcione. Si una herramienta está presente, aparecerá como `status: present` junto con la información de su versión. Si falta, aparecerá como `status: MISSING!` y se añadirá una advertencia al final de la salida de `doctor`.

<Accordion title="Ejemplo de salida de Dependency (presente)">

```text
- docker
    - status: present
    - version info: Docker version 28.0.4, build b8034c0
```

</Accordion>

<Accordion title="Ejemplo de salida de Dependency (ausente)">

```text
- docker
    - status: MISSING!
```

</Accordion>

Si falta alguna dependencia, es casi seguro que el Toolkit no funcionará.

### Configuración

La sección `Configuration` contiene información sobre los archivos del directorio `config/`. Para `config/overleaf.rc`, el doctor muestra algunos valores clave. Los archivos que falten aparecerán como `status: MISSING!` y se añadirá una advertencia al final de la salida de `doctor`.

<Accordion title="Ejemplo de salida de Configuration">

```text
====== Configuration ======
- config/version
    - status: present
    - version: 5.4.0
- config/overleaf.rc
    - status: present
    - values
        - OVERLEAF_DATA_PATH: /tmp/overleaf
        - SERVER_PRO: false
        - MONGO_ENABLED: false
        - REDIS_ENABLED: true
- config/variables.env
    - status: MISSING!
```

</Accordion>

Notas sobre el ejemplo anterior:

* Un `OVERLEAF_DATA_PATH` establecido en `/tmp/overleaf` puede no ser una ubicación segura para datos importantes.
* `MONGO_ENABLED: false` significa que el Toolkit no aprovisionará su propio MongoDB; si es necesario, asegúrate de que `MONGO_URL` apunta a un MongoDB gestionado externamente.
* En el ejemplo falta `config/variables.env`.

### Advertencias

La sección `Warnings` resume los problemas detectados por el script doctor. Si no hay problemas, esta sección lo indicará.

<Accordion title="Ejemplo de salida de Warnings">

```text
====== Warnings ======
- configuration file variables.env not found
- rc file, OVERLEAF_DATA_PATH not set
====== End =======
```

</Accordion>
