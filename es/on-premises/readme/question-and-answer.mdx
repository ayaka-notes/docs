Aquí hemos recopilado las respuestas a algunas preguntas frecuentes sobre Ayakaleaf Pro.

### Preguntas básicas {#basic-question}

<Accordion title="P01: ¿Es Ayakaleaf Pro una versión de prueba gratuita? ¿Requiere licencia?">

No. Ayakaleaf Pro es completamente gratuito. No es una versión de prueba y no requiere licencia.

</Accordion>

<Accordion title="P02: ¿Incluye Ayakaleaf Pro todas las funcionalidades de Overleaf Server Pro?">

Sí. Ayakaleaf Pro incluye todas las funcionalidades de Overleaf Server Pro, incluida la integración con Git-Bridge. También incluye funcionalidades seleccionadas de la plataforma SaaS de Overleaf. Seguimos desarrollando y mejorando Ayakaleaf Pro.

</Accordion>

<Accordion title="P03: ¿Cuánto cuesta Overleaf Server Pro?">

Overleaf Server Pro cuesta alrededor de \$300 por usuario al año. Requiere al menos 10 licencias, por lo que los despliegues parten de unos \$3.000 anuales. Los contratos públicos más pequeños en EE. UU. muestran costes anuales de unos \$320–\$370 por usuario. Esto hace que Server Pro sea caro, sobre todo para equipos pequeños. Consulta [#information-and-price-about-overleaf-server-pro](/es/on-premises#information-and-price-about-overleaf-server-pro  "mention") para ver compras y precios documentados.

</Accordion>

<Accordion title="P04: ¿Por qué Overleaf Server Pro no incluye GitHub Sync ni funcionalidades de IA?">

Overleaf Server Pro lo utilizan habitualmente organizaciones gubernamentales. Lo despliegan en redes privadas y controlan estrictamente el acceso. Para proteger los datos sensibles, sus funcionalidades incluidas evitan intercambiar datos con servicios de terceros. Si necesitas GitHub Sync, IA u otras funcionalidades conectadas similares, Overleaf recomienda suscribirse a su plataforma SaaS.

</Accordion>

<Accordion title="P05: ¿Es Ayakaleaf Pro seguro y fiable?">

Ayakaleaf Pro es de código abierto. Revisamos el código con herramientas como Codex Security para reforzar su seguridad y fiabilidad. Si no habilitas la sincronización de datos con terceros, tus datos permanecen en tu servidor. Ayakaleaf Pro no contiene telemetría que envíe tus datos a otro lugar.

</Accordion>

<Accordion title="P06: ¿Se mantendrá Ayakaleaf Pro a largo plazo?">

Haremos todo lo posible por mantener este proyecto a largo plazo.

</Accordion>

<Accordion title="P07: ¿Cumple Ayakaleaf Pro con la normativa de licencias?">

Ayakaleaf Pro es un fork de la comunidad. Su código y sus funcionalidades integradas proceden de contribuciones de la comunidad. Está publicado bajo la licencia AGPL v3. Los despliegues pueden cumplir con esta licencia siempre que satisfagan sus requisitos.

</Accordion>

<Accordion title="P08: ¿Por qué el proyecto se llama Ayakaleaf Pro?">

El proyecto se llamaba originalmente Overleaf Pro en 2024. El desarrollo se detuvo durante un tiempo y se reanudó a finales de 2025. En el primer trimestre de 2026, Overleaf renombró como Pro su plan de suscripción con IA. Los comentarios de la comunidad también señalaron que el nombre Overleaf Pro podía generar riesgos de marca registrada y de suplantación, ya que podía hacer creer a los usuarios que el proyecto era oficial.

Renombramos el proyecto como Ayakaleaf Pro para evitar esa confusión. El nombre puede leerse como "Ayaka-notes Overleaf Pro". El responsable del mantenimiento (¡puedes llamarme ayaka!) contribuye al desarrollo comunitario de Overleaf desde su etapa de estudiante, hace más de cinco años. Esta experiencia respalda nuestro compromiso de mantenimiento a largo plazo.

</Accordion>

<Accordion title="P09: ¿Qué distingue a Ayakaleaf Pro de los nuevos editores de LaTeX creados con IA?">

Desde 2026, la comunidad de código abierto ha publicado muchos editores de LaTeX creados con IA, incluido OpenAI Prism. Ayakaleaf Pro mantiene tus datos y servicios en tu propio servidor. Esto te da control directo sobre tu despliegue y tus datos.

Muchos editores experimentales de la comunidad no tienen un plan de mantenimiento a largo plazo consolidado. Las plataformas de compilación de LaTeX de terceros también pueden dejar de funcionar cuando su base de usuarios o sus ingresos son insuficientes. Ayakaleaf Pro entrega todo el código fuente y te permite alojar tú mismo todos los servicios. Incluso si el mantenimiento se detuviera, tu servicio autoalojado existente podría seguir funcionando.

</Accordion>

<Accordion title="P10: ¿Qué pasó con el repositorio de GitHub ayaka-notes/overleaf-pro?">

Se renombró a [ayaka-notes/ayakaleaf-pro](https://github.com/ayaka-notes/ayakaleaf-pro) con el cambio de nombre del proyecto (consulta la P08). No se archivó ni se sustituyó: es el mismo repositorio, y GitHub redirige los enlaces y los remotos de Git antiguos de `ayaka-notes/overleaf-pro` al nuevo nombre. La imagen Docker conserva su nombre, `ghcr.io/ayaka-notes/overleaf-pro`, por lo que no necesitas cambiar `config/overleaf.rc` ni `config/version`.

</Accordion>

### Funcionalidades {#features}

<Accordion title="P01: ¿Qué funcionalidades ofrece Ayakaleaf Pro? ¿Puedo solicitar una nueva funcionalidad?">

Consulta nuestra documentación para ver la lista actual de funcionalidades. Si hay alguna funcionalidad que te gustaría que añadiéramos, no dudes en abrir una issue (de solicitud de funcionalidad) en GitHub. Haremos todo lo posible por implementar las funcionalidades solicitadas, pero el desarrollo lleva tiempo y no podemos garantizar que todas las funcionalidades se entreguen de inmediato.

</Accordion>

<Accordion title="P02: He desarrollado algunas funcionalidades. ¿Puedo enviar un PR? ¿Se aceptará con seguridad?">

Las contribuciones son bienvenidas, pero su aceptación no está garantizada. Evaluamos cada PR en función de su impacto en la base de código subyacente de Overleaf, la carga de mantenimiento que supone y el valor que aporta a los usuarios. Haremos todo lo posible por fusionar y mantener las contribuciones valiosas.

Sin embargo, podemos rechazar PR que introduzcan cambios excesivos, que consistan en código generado por IA no revisado o mal comprendido ("vibe coding"), o que añadan funcionalidades difíciles de mantener a lo largo del tiempo.

</Accordion>

<Accordion title="P03: ¿Cómo configuro una funcionalidad concreta?">

Por lo general, actualizamos la documentación cada vez que publicamos una nueva funcionalidad. Consulta la documentación correspondiente para ver instrucciones de configuración detalladas y explicaciones de las variables de entorno disponibles.

</Accordion>

<Accordion title="P04: ¿Qué bibliotecas de Python puede usar Python Runner?">

Python Runner ejecuta Python en el navegador del usuario con [Pyodide](https://pyodide.org/) 0.29.3, no en el servidor. Carga los paquetes que importa tu código a partir de los [paquetes integrados en Pyodide](https://pyodide.org/en/0.29.3/usage/packages-in-pyodide.html), como NumPy, pandas y Matplotlib. Los paquetes instalados con `pip` y otros paquetes no están disponibles. No hay nada que configurar en el servidor.

</Accordion>

<Accordion title="P05: ¿Puede el corrector ortográfico revisar japonés o chino?">

No. El corrector ortográfico no tiene diccionario para japonés ni chino, por lo que estos idiomas no aparecen en la lista de idiomas de corrección ortográfica. Los usuarios pueden desactivar la corrección ortográfica de un proyecto en la configuración del editor.

Para que una palabra deje de marcarse como mal escrita, haz clic derecho sobre ella y elige **Add to dictionary**. Las palabras añadidas se guardan en tu cuenta y se aplican a todos tus proyectos. Para revisarlas o eliminarlas, abre la configuración del editor y, después, **Spelling and language → Dictionary → Edit**. Añadir palabras no añade un nuevo idioma de corrección ortográfica.

</Accordion>

<Accordion title="P06: ¿Puedo añadir plugins?">

No hay un instalador de plugins. Las funcionalidades son módulos en `services/web/modules` del código fuente, integrados en la imagen Docker y activados con los ajustes descritos en esta documentación. Para añadir los tuyos, añade un módulo al código fuente y construye tu propia imagen.

</Accordion>

### Despliegue {#deployment}

<Accordion title="P01: ¿Admite Ayakaleaf Pro el despliegue distribuido en k8s?">

Para la mayoría de los usuarios, recomendamos desplegar con el [Toolkit](/es/on-premises/installation/using-docker-compose). La compatibilidad con Kubernetes es experimental: [Usar Kubernetes](/es/on-premises/installation/using-kubernetes) muestra los manifiestos que probamos con una o varias réplicas, pero un clúster añade complejidad operativa y esfuerzo de mantenimiento. [Sandboxed Compiles](/es/on-premises/configuration/overleaf-toolkit/sandboxed-compiles) crea sus contenedores de compilación a través del socket de Docker, por lo que cada nodo que ejecute Ayakaleaf Pro necesita Docker Engine. No proporcionamos configuraciones para CRI-O, Podman ni Quadlet.

</Accordion>

<Accordion title="P02: ¿Cómo puedo garantizar la disponibilidad al dar servicio a miles de usuarios?">

Consulta nuestra guía de [escalado horizontal](/es/on-premises/maintenance/horizontal-scaling). Puedes desplegar varias instancias de Overleaf y configurar un balanceador de carga para distribuir el tráfico entre ellas.

</Accordion>

<Accordion title="P03: ¿Podéis ayudarme con el despliegue o la migración?">

Si tienes una instancia existente de Overleaf Server Pro, estaremos encantados de ayudarte a migrar a Ayakaleaf Pro. Ponte en contacto por correo electrónico o mediante issues.

</Accordion>

<Accordion title="P04: ¿Puedo alojar Ayakaleaf Pro en una subruta de URL, como `https://example.com/overleaf`?">

No. Ayakaleaf Pro debe servirse desde la raíz de un dominio. Usa un dominio o subdominio dedicado, como `https://overleaf.example.com`.

</Accordion>

<Accordion title="P05: ¿Puedo ejecutar Ayakaleaf Pro en Windows o macOS, o sin el Toolkit?">

Sí. El Toolkit funciona en [Linux](/es/on-premises/installation/using-docker-compose/linux), en [macOS con Docker Desktop](/es/on-premises/installation/using-docker-compose/macos) y en [Windows con WSL 2 y Docker Desktop](/es/on-premises/installation/using-docker-compose/windows). Recomendamos Linux para servidores compartidos y de producción. Las guías de macOS y Windows incluyen la configuración de la compilación en sandbox.

No proporcionamos un `docker-compose.yml` independiente. Para ver la configuración de Compose que usa el Toolkit, ejecuta `bin/docker-compose config` en el directorio del Toolkit.

</Accordion>

<Accordion title="P06: ¿Cómo desinstalo Ayakaleaf Pro?">

No hay ningún script de desinstalación. En el directorio del Toolkit:

1. Detén y elimina los contenedores con `bin/docker-compose down`.
2. Elimina los datos. De forma predeterminada están en el directorio `data/` del Toolkit. Si cambiaste `OVERLEAF_DATA_PATH`, `MONGO_DATA_PATH`, `REDIS_DATA_PATH` o `GIT_BRIDGE_DATA_PATH` en `config/overleaf.rc`, elimina también esos directorios. Esto no se puede deshacer, así que haz antes una [copia de seguridad](/es/on-premises/maintenance/data-and-backups) si puedes necesitar los datos.
3. Elimina el directorio del Toolkit.
4. Elimina las imágenes de Docker, que puedes listar con `docker images`: `ghcr.io/ayaka-notes/overleaf-pro`, la imagen de git-bridge, `mongo`, `redis` y las imágenes de TeX Live.

</Accordion>

<Accordion title="P07: ¿Cómo detengo, inicio o reinicio Ayakaleaf Pro?">

Ejecuta estos comandos en el directorio del Toolkit:

* `bin/stop` detiene todos los contenedores y `bin/start` los vuelve a iniciar. Los contenedores se conservan, así que los usuarios mantienen la sesión iniciada.
* `bin/up -d` crea los contenedores y los inicia en segundo plano. Ejecútalo después de cambiar `config/variables.env`, `config/overleaf.rc` o `config/version`: vuelve a crear los contenedores cuya configuración haya cambiado, y solo entonces se aplican los cambios. `bin/stop` y `bin/start` no los aplican.
* `bin/docker-compose restart sharelatex` reinicia solo el contenedor de Overleaf, sin aplicar los cambios de configuración.

Si los usuarios pierden la sesión cada vez que `bin/up` vuelve a crear el contenedor, establece `OVERLEAF_SESSION_SECRET`; consulta las preguntas y respuestas de [Variables de entorno](/es/on-premises/configuration/overleaf-toolkit/environment-variables).

</Accordion>

<Accordion title="P08: ¿Dónde pongo la URL de callback de OAuth?">

En la aplicación que creas en el proveedor, no en Ayakaleaf Pro. No hay ningún ajuste de callback en `config/variables.env` para ninguna de estas integraciones: Ayakaleaf Pro construye cada URL de callback a partir de `OVERLEAF_SITE_URL` y la envía al proveedor, que la rechaza si no coincide con la registrada para la aplicación. Por tanto, solo tienes que registrarla en el proveedor y establecer `OVERLEAF_SITE_URL` en la dirección que abren los usuarios.

| Integración | Campo en el proveedor | Valor |
| --- | --- | --- |
| [GitHub](/es/on-premises/configuration/overleaf-toolkit/integrations/github-synchronisation) | Authorization callback URL | `${OVERLEAF_SITE_URL}/user/github-sync/oauth2/callback` |
| [GitLab](/es/on-premises/configuration/overleaf-toolkit/integrations/gitlab-synchronisation) | Redirect URI | `${OVERLEAF_SITE_URL}/user/gitlab-sync/oauth2/callback` |
| [Gitea](/es/on-premises/configuration/overleaf-toolkit/integrations/gitea-synchronisation) | Redirect URIs | `${OVERLEAF_SITE_URL}/user/gitea-sync/oauth2/callback` |
| [Dropbox](/es/on-premises/configuration/overleaf-toolkit/integrations/dropbox-synchronisation) | Redirect URIs (haz clic en **Add**) | `${OVERLEAF_SITE_URL}/user/dropbox/oauth/callback` |
| [Zotero](/es/on-premises/configuration/overleaf-toolkit/integrations/zotero-integration) | Callback URL | `${OVERLEAF_SITE_URL}/user/zotero/oauth/callback` |
| [Mendeley](/es/on-premises/configuration/overleaf-toolkit/integrations/mendeley-integration) | Redirect URL | `${OVERLEAF_SITE_URL}/user/mendeley/oauth/callback` |
| [Inicio de sesión con OIDC](/es/on-premises/configuration/overleaf-toolkit/authentication/oidc-authentication) | Redirect URI | `${OVERLEAF_SITE_URL}/oidc/login/callback` |
| [Inicio de sesión con SAML](/es/on-premises/configuration/overleaf-toolkit/authentication/saml-authentication) | ACS URL (Assertion Consumer Service) | `${OVERLEAF_SITE_URL}/saml/login/callback` |

Si cambias `OVERLEAF_SITE_URL`, por ejemplo a un nuevo dominio, actualiza también la URL en todos los proveedores; de lo contrario, la vinculación fallará.

</Accordion>

<Accordion title="P09: ¿Dónde se almacenan los datos y cuánto espacio en disco necesito?">

De forma predeterminada, todo permanece en el disco local del servidor, en el directorio `data/` del Toolkit: `data/overleaf` (archivos de proyecto, historial y resultados de compilación), `data/mongo` y `data/redis`. Para instancias con menos de 1000 usuarios, recomendamos el disco local con [copias de seguridad](/es/on-premises/maintenance/data-and-backups) periódicas.

La imagen de Ayakaleaf Pro ocupa unos 5 GB. El mínimo de 40 GB indicado en la [Introducción](/es/on-premises/installation/introduction) corresponde a Sandboxed Compiles, cuyas imágenes `texlive-full` ocupan unos 28 GB cada una. Sin Sandboxed Compiles, las compilaciones se ejecutan dentro del contenedor `sharelatex` con el esquema básico de TeX Live más `latexmk`, `texcount`, `synctex`, `etoolbox` y `xetex`, por lo que muchos proyectos fallan por falta de paquetes. Después, el directorio `data/` crece con tus proyectos y su historial; compruébalo con `du -sh data/*`.

</Accordion>

<Accordion title="P10: ¿Puedo mantener Ayakaleaf funcionando en Windows las 24 horas del día?">

Sí, siempre que Windows permanezca activo y Docker Desktop siga ejecutándose. Activa **Start Docker Desktop when you sign in to your computer**, conserva las políticas `restart: always` del Toolkit y desactiva la suspensión y la hibernación automáticas mientras el equipo esté conectado a la corriente. La pantalla puede apagarse; el comportamiento de la tapa de un portátil es un ajuste aparte. Cerrar el terminal de Ubuntu después de `bin/up -d` no detiene los contenedores en segundo plano. Salir de Docker Desktop, pausar su motor o ejecutar `wsl --shutdown` interrumpe el servicio.

El Resource Saver de Docker Desktop es distinto de la suspensión de Windows: se aplica cuando no hay contenedores en ejecución, por lo que una pila de Ayakaleaf en ejecución no está inactiva solo porque nadie esté editando. Tras reiniciar Windows, el ajuste de inicio al iniciar sesión sigue requiriendo que alguien inicie sesión. Sigue [Mantener la instancia disponible](/es/on-premises/installation/using-docker-compose/windows/6.-post-installation-tasks#keep-the-instance-available) para las comprobaciones y los pasos de recuperación. Linux sigue siendo nuestra recomendación cuando la disponibilidad no debe depender de un inicio de sesión interactivo en el escritorio.

</Accordion>

<Accordion title="P11: Docker Desktop indica que la virtualización está desactivada. ¿Necesito Hyper-V?">

Esta guía usa el **backend WSL 2**. Necesita la virtualización de la CPU activada en la BIOS/UEFI, la característica **Virtual Machine Platform** (Plataforma de máquina virtual) de Windows y una instalación de WSL 2 que funcione. La característica completa **Hyper-V** es un backend distinto de Docker Desktop y no es un requisito previo para esta configuración con WSL.

Comprueba **Administrador de tareas → Rendimiento → CPU → Virtualización** y `wsl --list --verbose` en PowerShell. Errores como `0x80370102` pueden significar que la virtualización, la característica de Windows o el hipervisor de arranque están desactivados. Consulta los [pasos de solución de problemas de la instalación en Windows](/es/on-premises/installation/using-docker-compose/windows/troubleshooting#wsl-or-docker-reports-that-virtualization-is-unavailable), con los enlaces de reparación de Microsoft y Docker. Reinicia Windows después de activar las características necesarias; reinstalar Ayakaleaf no puede arreglar un motor de Docker que no arranca.

</Accordion>

### LaTeX {#latex}

<Accordion title="P01: ¿Están aisladas las compilaciones de los proyectos LaTeX de los usuarios? ¿Está habilitado Shell Escape?">

Cuando habilitas Sandbox Compiles, la compilación de cada usuario se ejecuta en un contenedor Docker independiente y queda aislada de las compilaciones de los demás usuarios. Shell Escape está habilitado por defecto en Sandbox Compiles.

</Accordion>

<Accordion title="P02: ¿Es fiable la imagen de Sandbox Compiles? ¿Puede fallar la compilación?">

Durante los últimos tres años hemos mejorado nuestra imagen TeX Live Full para Sandbox Compiles. En la mayoría de los casos, los proyectos que compilan en overleaf.com también compilan correctamente con Ayakaleaf Pro. Si falta una fuente necesaria, súbela manualmente a tu proyecto.

</Accordion>

<Accordion title="P03: Mi proyecto no compila. ¿Podéis ayudarme a solucionarlo?">

Sube tu proyecto al sitio web oficial de Overleaf, habilita el uso compartido mediante enlace de solo lectura e incluye el enlace en una issue de GitHub.

Investigaremos y corregiremos cualquier error que impida compilar un proyecto en Ayakaleaf Pro cuando este compila correctamente en el sitio web oficial de Overleaf. Los problemas de compilación fuera de este ámbito no están cubiertos por nuestro soporte.

</Accordion>
