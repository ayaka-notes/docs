Nos enorgullece enormemente anunciar el lanzamiento de Overleaf Pro 6.3.1, el editor de LaTeX en línea más potente y completo de la comunidad. Una versión de parche suele traer un puñado de pequeñas correcciones. Esta va mucho más allá: junto con decenas de correcciones de errores, trae cinco funciones nuevas y conecta tus proyectos con los lugares donde ya trabajas, desde Dropbox y GitLab hasta el agente de IA de tu terminal.

### Cambios

* Sincronización con Dropbox (versión preliminar): mantén cada proyecto sincronizado con tu propio Dropbox, en ambas direcciones.
* Sincronización con GitLab (versión preliminar): sincronización bidireccional con GitLab.com o con tu GitLab autogestionado.
* Servidor MCP: permite que Claude Code, Codex, Cursor, VS Code o Gemini CLI trabajen directamente en un proyecto.
* GitHub Enterprise: apunta la sincronización con GitHub a tu propia instancia de GitHub Enterprise.
* Reconocimiento de símbolos manuscritos: dibuja un símbolo y obtén el comando de LaTeX.
* `OVERLEAF_DISABLE_LOCAL_LOGIN`: oculta el inicio de sesión con correo electrónico y contraseña para que los usuarios solo inicien sesión con SSO.
* Correcciones de errores detectados por nuestro sistema de pruebas E2E y por la Internal Horizon Issue Investigation.
* Parches de Overleaf 6.3.1 upstream.

<Info>

La sincronización con Dropbox y la sincronización con GitLab se incluyen en la 6.3.1 como **versiones preliminares** para pruebas graduales, y se publicarán oficialmente en la v6.4.0. Su configuración y su comportamiento aún pueden cambiar antes de entonces. Ambas están desactivadas de forma predeterminada. Informa de cualquier problema en [GitHub](https://github.com/ayaka-notes/ayakaleaf-pro/issues).

</Info>

#### Función 01: sincronización con Dropbox (versión preliminar)

Hay personas que nunca quieren pensar en Git. Solo quieren que su tesis sea una carpeta en su portátil, y la sincronización con Dropbox les da exactamente eso. Cada usuario vincula su propia cuenta de Dropbox, y los proyectos de los que es propietario y los compartidos con él aparecen en `Apps/<your app name>/`. Edita en Overleaf y el cambio aparece en Dropbox. Edita el archivo localmente en tu editor favorito, guárdalo y el cambio vuelve a Overleaf a través de un webhook firmado.

Para administradores: git bridge debe estar habilitado. Crea una aplicación en la Dropbox App Console y, a continuación, establece `DROPBOX_ENABLED`, `DROPBOX_APP_KEY`, `DROPBOX_APP_SECRET`, `DROPBOX_APP_NAME` y `DROPBOX_TOKEN_CIPHER_PASSWORD`. `DROPBOX_SYNC_PROXY_URL` es opcional, para servidores que no pueden acceder directamente a Dropbox. Después, crea una sola vez los índices de MongoDB que necesita la sincronización con Dropbox, antes de que los usuarios vinculen sus cuentas.

Consulta [Sincronización con Dropbox](/es/on-premises/configuration/overleaf-toolkit/dropbox-synchronisation  "mention") para ver las instrucciones de configuración completas.

#### Función 02: sincronización con GitLab (versión preliminar)

La sincronización con GitHub ha sido una de nuestras funciones más queridas desde la 6.2, y muchas universidades y empresas guardan su código en GitLab. La sincronización con GitLab funciona de la misma manera: vincula tu cuenta, importa un repositorio desde el menú de nuevo proyecto o exporta un proyecto a un nuevo proyecto de GitLab. Después, haz push y pull desde el editor y fusiona mediante merge requests.

Funciona con GitLab.com y con GitLab autogestionado 15.10 o posterior. Establece `GITLAB_SYNC_ENABLED`, `GITLAB_SYNC_CLIENT_ID`, `GITLAB_SYNC_CLIENT_SECRET` y `GITLAB_TOKEN_CIPHER_PASSWORD`, además de `GITLAB_SYNC_URL` para una instancia autogestionada.

Consulta [Sincronización con GitLab](/es/on-premises/configuration/overleaf-toolkit/gitlab-synchronisation  "mention") para ver las instrucciones de configuración completas.

#### Función 03: servidor MCP

En la 6.3 pusimos un asistente de IA dentro del editor. En la 6.3.1 abrimos la puerta en sentido contrario: ahora cada proyecto tiene su propio servidor MCP, de modo que el agente de IA que ya usas puede trabajar directamente en tu artículo. Pide a Claude Code que corrija las erratas de la introducción, pide a Codex que compile y corrija los errores de LaTeX, o pide a Cursor que responda a los comentarios de revisión pendientes. El agente lee y edita los archivos en directo, así que tú y tus colaboradores veis aparecer sus ediciones en el editor mientras escribe. También puede compilar, leer el registro, obtener el PDF, contar palabras y listar versiones.

El endpoint es `/project/<project_id>/mcp`. Autentícate con el mismo token de Git que usas para `git clone`. El acceso sigue la configuración de uso compartido del proyecto, de modo que el agente de un lector puede leer pero no editar, y todas las herramientas tienen límite de frecuencia. No hay nada más que configurar: el servidor MCP se habilita junto con git bridge.

Consulta [Servidor MCP](/es/on-premises/configuration/overleaf-toolkit/mcp-server  "mention") para saber cómo conectar cada cliente de IA.

#### Función 04: GitHub Enterprise

La sincronización con GitHub ya no se limita a github.com. Establece `GITHUB_SYNC_URL` con tu GitHub Enterprise Server, o con GitHub Enterprise Cloud con residencia de datos (`GHE.com`), y los endpoints REST y GraphQL se derivan de ella. Si tu instancia hace algo inusual, sobrescríbelos con `GITHUB_SYNC_API_URL` y `GITHUB_SYNC_GRAPHQL_URL`. Si las dejas sin definir, todo sigue en github.com.

Consulta [Sincronización con GitHub](/es/on-premises/configuration/overleaf-toolkit/github-synchronisation#github-enterprise  "mention") para más detalles.

#### Función 05: reconocimiento de símbolos manuscritos

Sabes cómo es el símbolo, pero no cómo se llama. ¿Es `\varsigma` o `\zeta`? ¿`\models` o `\vDash`? Cambia la paleta de símbolos al modo de dibujo, dibújalo con el ratón o el trackpad y la paleta sugerirá los comandos de LaTeX correspondientes.

El reconocimiento se ejecuta íntegramente en el navegador, con un modelo entrenado por ayaka-notes, así que nada de lo que dibujas sale de tu equipo. El selector de dibujo se oculta en los navegadores sin `OffscreenCanvas` (p. ej., Safari 15).

#### Correcciones de errores

Esta versión también trae una larga lista de correcciones. Muchas de ellas las encontró nuestro nuevo sistema de pruebas E2E, que ahora ejecuta a diario conjuntos de pruebas para cada módulo, y la Internal Horizon Issue Investigation: cada vez que corregimos un error, revisamos todo el código en busca de errores similares antes de cerrarlo.

* **Autenticación**: las cuentas locales pueden establecer y cambiar su contraseña en instancias con SSO, y los usuarios de OIDC ya no pueden cambiar su propio correo electrónico. Los inicios de sesión con LDAP, SAML y OIDC ya no fallan cuando un atributo de nombre tiene varios valores, y el cierre de sesión de SAML/OIDC vuelve a funcionar.
* **Usuarios suspendidos**: al suspender a un usuario ahora se cierran sus sesiones y sus editores abiertos, y se rechazan sus tokens de Git y sus descargas por MCP.
* **Sincronización con GitHub**: solo el propietario puede exportar un proyecto, las ediciones hechas durante un pull quedan pendientes, los archivos vacíos se sincronizan y las fusiones manuales se verifican en GitHub.
* **Zotero / Mendeley**: recibes un mensaje para volver a vincular cuando tus credenciales dejan de funcionar, y las referencias se reindexan después de una importación.
* **Servicios externos**: las solicitudes a Zotero, Mendeley, GitHub, GitLab y la búsqueda web tienen un tiempo de espera de conexión de 3 s en lugar de 1 s, por lo que las redes más lentas ya no fallan.
* **Control de cambios**: los datos de revisión incluyen los documentos no cargados y los cambios no guardados.
* **Panel de administración**: restaurar proyectos eliminados, cambiar propietarios y editar usuarios funciona correctamente, y un correo electrónico fallido ya no impide crear ni eliminar cuentas.
* **Galería de plantillas**: una ordenación no válida devuelve 400 en lugar de 500, y al publicar un proyecto sin archivo principal se solicita uno.

Consulta las [notas de la versión 6.3.1](/es/on-premises/release-notes/release-notes-6.x.x#ayakaleaf-pro-6.3.1  "mention") para ver la lista completa.

#### Actualización

* Desde la 6.3.0: no se necesita ninguna migración. Descarga la nueva imagen y reinicia.
* Desde la 6.2.x o anterior con Zotero o Mendeley en uso: ejecuta primero la [migración de Zotero / Mendeley](/es/on-premises/release-notes/release-notes-6.x.x#ayakaleaf-pro-6.3.0  "mention") de la 6.3.0.
* La sincronización con Dropbox y la sincronización con GitLab están desactivadas de forma predeterminada. La sincronización con GitLab solo necesita nuevas variables de entorno. La sincronización con Dropbox también necesita que sus índices de MongoDB se creen una vez, antes de que los usuarios vinculen sus cuentas: consulta [Crear los índices de la base de datos](/es/on-premises/configuration/overleaf-toolkit/dropbox-synchronisation#create-the-database-indexes  "mention").
