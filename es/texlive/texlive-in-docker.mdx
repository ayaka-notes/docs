### Docker

Docker ofrece una forma ligera y portable de empaquetar y ejecutar aplicaciones en contenedores aislados. Al empaquetar la aplicación junto con todas sus dependencias, un contenedor garantiza un comportamiento coherente en distintas máquinas, desde portátiles hasta servidores de producción.

TeX Live es potente, pero grande y sensible a las diferencias a nivel de sistema. Empaquetar TeX Live dentro de una imagen Docker hace que la cadena de herramientas de LaTeX sea predecible, reproducible y fácil de distribuir.

Sin embargo, algunos paquetes de TeX Live dependen del acceso a la shell. Por motivos de seguridad, el contenedor debe ejecutarse en un entorno restringido que impida a los usuarios ejecutar comandos de shell arbitrarios (por ejemplo, mediante `\write18` o shell escape). Este aislamiento protege el sistema anfitrión y evita accesos no deseados al sistema de archivos subyacente del contenedor o a herramientas como `bash`.

### Edición completa de TeXLive

[TeXLive-Full@ayaka-notes](https://github.com/ayaka-notes/texlive-full/) es una **imagen Docker de TeXLive** completa, diseñada para la compilación de LaTeX en sandbox en [Ayakaleaf Pro](https://github.com/ayaka-notes/ayakaleaf-pro), [Overleaf CEP](https://github.com/yu-i-i/overleaf-cep) o entornos de compilación de LaTeX independientes.

Esta imagen pretende ofrecer una distribución de TeXLive casi completa, con fuentes y herramientas comunes preinstaladas, para minimizar los fallos de compilación causados por paquetes o fuentes ausentes. Nota: esta imagen Docker **no contiene** ningún componente de sharelatex/overleaf. Se usa para las compilaciones de Overleaf/Overleaf Pro.

#### Características:

* 🚀 Compatible con las arquitecturas de servidor x86\_64 y arm64
* 📦 Instalación de TeXLive completa y optimizada
* 🧩 Fuentes y utilidades comunes preinstaladas
* 🐳 Lista para usar con Docker y Docker Compose
* 🧪 Probada con Overleaf Server Pro / Overleaf Pro
* 🔄 Actualizada periódicamente con las últimas versiones de TeXLive
* 🏷 Etiquetas para múltiples versiones de TeXLive (2020 – la más reciente)
* 🧑‍🔬 Compatibilidad con Knitr para código R en documentos LaTeX

### Uso con Ayakaleaf Pro

TeX Live Full de Ayaka-notes está diseñada especialmente para [ayakaleaf-pro](https://github.com/ayaka-notes/ayakaleaf-pro); si eres [usuario del toolkit](https://github.com/overleaf/toolkit), puedes añadir las siguientes variables de entorno al archivo `config/variables.env`.

Por ejemplo:

```dotenv title="config/variables.env" wrap
ALL_TEX_LIVE_DOCKER_IMAGES=ghcr.io/ayaka-notes/texlive-full:2026.1, ghcr.io/ayaka-notes/texlive-full:2025.1
ALL_TEX_LIVE_DOCKER_IMAGE_NAMES=Texlive 2026, Texlive 2025
TEX_LIVE_DOCKER_IMAGE=ghcr.io/ayaka-notes/texlive-full:2026.1
```

### Versiones de TeX Live

Gracias a GitHub Actions, podemos compilar todas las imágenes de TeX en paralelo, entre ellas:

* `ghcr.io/ayaka-notes/texlive-full:2026.1` (también con la etiqueta `latest`)
* `ghcr.io/ayaka-notes/texlive-full:2025.1`
* `ghcr.io/ayaka-notes/texlive-full:2024.1`
* `ghcr.io/ayaka-notes/texlive-full:2023.1`
* `ghcr.io/ayaka-notes/texlive-full:2022.1`
* `ghcr.io/ayaka-notes/texlive-full:2021.1`
* `ghcr.io/ayaka-notes/texlive-full:2020.1`
* `ghcr.io/ayaka-notes/texlive-full:base`

Usamos el archivo espejo de [texlive info](https://texlive.info/tlnet-archive/), que incluye casi todas las versiones de TeX Live desde 1996 hasta 2025. Y gracias al Dockerfile de Overleaf, podemos compilar este proyecto más rápido.

> ¿Por qué no se admiten TeX Live 2019 y versiones anteriores?
>
> Mantener estas imágenes antiguas es extremadamente difícil. Además, el sitio web [texlive.info](https://texlive.info/) no ofrece información sobre las versiones de TeX Live publicadas antes de 2019, por lo que no podemos compilar imágenes para esas versiones. Si necesitas una versión antigua concreta, abre una incidencia y háznoslo saber.

### Problemas

<Accordion title="Problema 01: fallos de la caché de fuentes">

Cuando Overleaf compila un proyecto LaTeX y falta una fuente, **es posible que la compilación tarde mucho tiempo**, porque cuando falta una fuente, TeX Live intenta **reconstruir toda la caché de fuentes**. Es un proceso que lleva mucho tiempo.

En nuestra imagen hemos generado previamente la caché de fuentes; solucionamos este problema con [este commit](https://github.com/ayaka-notes/texlive-full/commit/0cb66b0dc8b82be628cf6999cfd659d9784e132f)

</Accordion>

<Accordion title="Problema 02: SyncTeX extremadamente lento">

Al usar esta imagen en sharelatex, es posible que SyncTeX sea extremadamente lento.

Consulta: [https://github.com/overleaf/overleaf/issues/1150](https://github.com/overleaf/overleaf/issues/1150); basta con deshabilitar HTTP 2.0.

</Accordion>

<Accordion title="Problema 03: error al recompilar con la imagen oficial de TeX Live">

Si usas la imagen oficial de TeX Live de Docker Hub `texlive/texlive`, es posible que al recompilar un proyecto se produzca un error. En nuestra imagen, sin embargo, este problema está solucionado, ya que usamos la imagen base de Ubuntu más reciente e instalamos todas las dependencias desde el repositorio oficial de Ubuntu.

</Accordion>

### Otros recordatorios técnicos

Al compilar imágenes de TeX Live (anteriores a 2019), es posible que debas prestar atención a los siguientes problemas:

* Antes de TeX Live 2017 solo se admite `http`/`ftp`, por lo que no puedes usar `https` para descargar, a menos que modifiques el script `peal`.
* Antes de 2015 solo se proporciona el archivo sha256, por lo que no puedes usar sha512 para la verificación.
