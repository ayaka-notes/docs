Overleaf se ejecuta como varios servicios que se llaman entre sí por HTTP dentro de la red de Docker. Las páginas de esta sección describen estas API internas. Proceden de los archivos OpenAPI de [`develop/hoppscotch/openapi/`](https://github.com/ayaka-notes/ayakaleaf-pro/tree/server-pro/develop/hoppscotch/openapi), que se escribieron a partir del código de cada servicio.

Ninguna de estas API es pública: solo son accesibles dentro de la red de Docker, y la mayoría no tiene autenticación.

## Servicios {#services}

| Servicio | Dirección | Qué hace |
| ------------------------------------------------- | ----------------------------------- | ------------------------------------------------------------------------------------------------ |
| [web](/es/dev/service-api/web)                                     | `http://web:3000`                   | La aplicación principal. Su API privada la llaman los demás servicios y los scripts cron de la imagen  |
| [document-updater](/es/dev/service-api/document-updater)           | `http://document-updater:3003`      | Mantiene en Redis los documentos abiertos en el editor, aplica las ediciones y los vuelve a escribir en Mongo         |
| [docstore](/es/dev/service-api/docstore)                           | `http://docstore:3016`              | Guarda cada documento de cada proyecto en la colección de Mongo `docs`                                 |
| [real-time](/es/dev/service-api/real-time)                         | `http://real-time:3026`             | Mantiene las conexiones socket.io del editor y retransmite ediciones entre navegadores y servicios          |
| [chat](/es/dev/service-api/chat)                                   | `http://chat:3010`                  | Guarda el chat del proyecto y los hilos de comentarios                                                  |
| [project-history](/es/dev/service-api/project-history)             | `http://project-history:3054`       | Convierte las ediciones en cola en cambios de historial y los envía a history-v1; guarda las etiquetas               |
| [history-v1](/es/dev/service-api/history-v1)                       | `http://history-v1:3100`            | Guarda el historial completo de cada proyecto y el contenido de los archivos como blobs                           |
| [filestore](/es/dev/service-api/filestore)                         | `http://filestore:3009`             | Sirve archivos de plantillas y, en solo lectura, los blobs que escribe history-v1                           |
| [clsi](/es/dev/service-api/clsi)                                   | `http://clsi:3013`                  | Compila proyectos, ejecuta SyncTeX y recuentos de palabras, convierte documentos                              |
| [notifications](/es/dev/service-api/notifications)                 | `http://notifications:3042`         | Guarda las notificaciones que se muestran en la lista de proyectos                                               |
| [linked-url-proxy](/es/dev/service-api/linked-url-proxy)           | `http://linked-url-proxy:3066`      | Obtiene URL externas para web y rechaza direcciones internas                                     |
| [third-party-datastore](/es/dev/service-api/third-party-datastore) | `http://third-party-datastore:3002` | Sincroniza proyectos con Dropbox mediante una cola de trabajos por usuario                                       |

## Autenticación {#authentication}

* <strong>web:</strong> autenticación HTTP básica con `WEB_API_USER` y `WEB_API_PASSWORD`. Las rutas de git-bridge usan en su lugar un token de acceso personal.
* <strong>history-v1:</strong> autenticación HTTP básica como `staging` con `STAGING_PASSWORD`, o un JWT.
* <strong>Todos los demás servicios:</strong> ninguna.

## Probarlas {#try-them}

El entorno de desarrollo ejecuta [Hoppscotch](https://github.com/hoppscotch/hoppscotch) en `http://localhost:9170`, con un proxy que llega a los servicios por sus direcciones de Docker. Su [README](https://github.com/ayaka-notes/ayakaleaf-pro/blob/server-pro/develop/README.md#hoppscotch) muestra cómo configurar el proxy e importar los archivos OpenAPI.
