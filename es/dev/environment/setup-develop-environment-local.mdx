## Requisitos previos

Overleaf es un proyecto de código abierto típico con arquitectura de microservicios, en el que todos los servicios se ejecutan en Docker.&#x20;

* El código fuente oficial de Community Edition está en [GitHub Overleaf Official](https://github.com/overleaf/overleaf/tree).&#x20;
* El código fuente de Overleaf-CEP está disponible en [GitHub Yu-i-i/Overleaf](https://github.com/yu-i-i/overleaf-cep).
* Overleaf Pro Edition está disponible en [GitHub Ayaka-notes/overleaf-pro](https://github.com/ayaka-notes/overleaf-pro).

Para configurar un entorno de desarrollo de Overleaf necesitará un servidor potente; se recomienda una configuración de al menos 8 núcleos y 16 GB de RAM, ya que deberá ejecutar más de 20 contenedores simultáneamente.

<Info>

Dado que los servidores con 8 o más núcleos de CPU suelen ser caros, se recomienda encarecidamente utilizar su equipo local para el desarrollo.

</Info>

Por otra parte, como desarrollador, entendemos que ya está familiarizado con la [instalación de Docker](https://docs.docker.com/engine/install/ubuntu/). Recomendamos encarecidamente utilizar una versión LTS de Ubuntu reciente y estable (por ejemplo, Ubuntu 24.04 en 2025–2026) y la última versión de Docker para el desarrollo, ya que así se reduce la posibilidad de encontrar errores inesperados.

En resumen, necesitará:

* [x] Un servidor/equipo de escritorio potente para desarrollar
* [x] Una versión LTS de Ubuntu reciente y estable (por ejemplo, Ubuntu 24.04)
* [x] Un entorno con Docker y Git

## Tutorial de configuración

Aquí utilizaremos overleaf-cep como ejemplo para mostrar cómo configurar un entorno de desarrollo de Overleaf.

<Steps>
<Step title="Descargue el código fuente">
En primer lugar, clonemos el repositorio:

```bash title="bash"
git clone https://github.com/ayaka-notes/overleaf-pro.git
cd overleaf-pro
```
</Step>

<Step title="Sincronice `package-lock.json`">
Dado que Overleaf se desarrolla en un [repositorio interno](http://github.com/overleaf/internal), es muy probable que el archivo `package-lock.json` quede desincronizado debido a algunos problemas de desarrollo. Debemos ejecutar el siguiente comando para sincronizarlo (si dispone de un entorno nodejs local).

```bash title="bash"
npm install --package-lock-only --ignore-scripts
```

Si no tiene nodejs instalado, no se preocupe: puede usar directamente `docker` para ejecutar el mismo comando. Ejecútelo **desde la raíz del repositorio de Overleaf:**

```bash title="bash"
docker run --rm \
  -v "$(pwd)":/workspace \
  -w /workspace \
  node:22.18.0 \
  npm install --package-lock-only --ignore-scripts
```
</Step>

<Step title="Compile la imagen de desarrollo">
Overleaf proporciona un directorio específico, `/develop`, para almacenar los scripts de desarrollo. Solo tiene que compilar los servicios:

```bash title="bash"
cd ./develop
bin/build
```

<Info>

Si Docker se queda sin RAM al compilar los servicios en paralelo, cree un archivo `.env` en este directorio que contenga `COMPOSE_PARALLEL_LIMIT=1`.

</Info>
</Step>

<Step title="Inicie todos los microservicios">
A continuación, inicie los servicios:

```bash title="bash"
bin/up
```

Una vez que los servicios estén en ejecución, abra [http://localhost/launchpad](http://localhost/launchpad) para crear la primera cuenta de administrador.

<Danger>

Debe ejecutar `bin/up` antes de ejecutar el comando `bin/dev`. De lo contrario, podría encontrarse con una serie de problemas de permisos.

</Danger>
</Step>
</Steps>

<Info>

De forma predeterminada, los privilegios de administrador no están disponibles. Debe añadir lo siguiente a `develop/dev.env`. Después, tendrá acceso al panel de administración.

```text
ADMIN_PRIVILEGE_AVAILABLE=true
```

</Info>

### TeX Live

Para compilar un PDF es necesario crear una imagen de TeX Live que se encargue de la compilación dentro de Docker:

```text
docker build texlive -t texlive-full
```

Para compilar en un host macOS, es posible que tenga que sobrescribir la ruta al socket de Docker creando un archivo `.env` en este directorio que contenga `DOCKER_SOCKET_PATH=/var/run/docker.sock.raw`

También puede utilizar [ayaka-notes/texlive-full](https://github.com/ayaka-notes/texlive-full), aunque puede usar la etiqueta base, que es la versión mínima de texlive.

### Desarrollo

Para evitar ejecutar `bin/build && bin/up` después de cada cambio en el código, puede ejecutar Overleaf Community Edition en _modo de desarrollo_, en el que los servicios se actualizan automáticamente cuando cambia el código.

Para ello, utilice el script `bin/dev` incluido:

```text
bin/dev
```

Esto iniciará todos los servicios con `node --watch`, que supervisará automáticamente el código y reiniciará los servicios cuando sea necesario.

Para mejorar el rendimiento, puede iniciar solo un subconjunto de los servicios en modo de desarrollo pasando una lista separada por espacios al script `bin/dev`:

```text
bin/dev [service1] [service2] ... [serviceN]
```

<Info>

Iniciar el servicio `web` en _modo de desarrollo_ solo actualizará el servicio `web` cuando cambie el código del backend. Para actualizar automáticamente también el código del frontend, asegúrese de iniciar también el servicio `webpack` en _modo de desarrollo_.

</Info>

Si no se especifica ningún servicio, todos los servicios se iniciarán en modo de desarrollo.

### Depuración

Cuando se ejecutan en _modo de desarrollo_, la mayoría de los servicios exponen un puerto de depuración al que puede conectar un depurador, como el inspector de las Dev Tools de Chrome o uno integrado en un IDE. La siguiente tabla muestra el puerto expuesto en la **máquina host** para cada servicio:

| Servicio           | Puerto |
| ------------------ | ---- |
| `web`              | 9229 |
| `clsi`             | 9230 |
| `chat`             | 9231 |
| `contacts`         | 9232 |
| `docstore`         | 9233 |
| `document-updater` | 9234 |
| `filestore`        | 9235 |
| `notifications`    | 9236 |
| `real-time`        | 9237 |
| `references`       | 9238 |
| `history-v1`       | 9239 |
| `project-history`  | 9240 |
| `linked-url-proxy` | 9241 |

Para conectarse a un servicio mediante la _depuración remota_ de Chrome, vaya a chrome://inspect/ y asegúrese de que la opción _Discover network targets_ esté marcada. A continuación, haga clic en _Configure..._ y añada una entrada `localhost:[service port]` para cada uno de los servicios a los que quiera conectar un depurador.

Tras añadir una entrada, el servicio aparecerá como un _Remote Target_ que podrá inspeccionar y depurar.

### Registros

En el entorno de desarrollo, Overleaf proporciona el script `bin/logs`; sin embargo, debe instalar algunas dependencias:

```bash
sudo npm install -g bunyan
# Or sudo apt install node-bunyan 
```

O bien, puede ejecutar directamente:

```text
docker compose logs -f [service name]
```
