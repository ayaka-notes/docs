## Herramientas de desarrollo recomendadas {#develop-tools-recommended}

Estos servicios opcionales no son necesarios para ejecutar Overleaf, pero ayudan mucho a desarrollar, depurar y revisar los datos. Todos forman parte del entorno de desarrollo, así que no hay nada que añadir a `docker-compose.yml`. Una vez que inicias sesión en el sitio, el menú **Dev tools** de su barra de navegación enlaza a los que el sitio sirve en sus propias rutas.

| Herramienta | Dirección | Definida en |
| --- | --- | --- |
| **Grafana**, el estado, las métricas y los logs de cada servicio | [http://localhost/grafana/](http://localhost/grafana/) | `develop/grafana/docker-compose.yml`, activa con `GRAFANA_ENABLED=true` en `develop/dev.rc` (por defecto) |
| **Mailpit**, una bandeja de entrada para cada correo que envía el sitio | [http://localhost/mailpit/](http://localhost/mailpit/) | `develop/mail/docker-compose.yml`, activa con `MAILPIT_ENABLED=true` (por defecto) |
| **Mongo Express**, una interfaz para MongoDB | [http://localhost/mongo-express/](http://localhost/mongo-express/) | `develop/docker-compose.yml`, siempre activa |
| **RedisInsight**, una interfaz para los datos de Redis | [http://localhost/redis-insight/](http://localhost/redis-insight/) | `develop/docker-compose.yml`, siempre activa |
| **Hoppscotch**, un cliente de API en el navegador, similar a Postman | [http://localhost:9170](http://localhost:9170/) (`HOPPSCOTCH_PORT`) | `develop/hoppscotch/docker-compose.yml`, activa con `HOPPSCOTCH_ENABLED=true` (por defecto) |

<Warning>

Ninguna de estas herramientas tiene inicio de sesión: los usuarios anónimos de Grafana son sus administradores, y Mongo Express puede cambiar cualquier documento. El sitio, Hoppscotch, Mongo Express (8081) y RedisInsight (5540) solo escuchan en `127.0.0.1` del host, así que otros hosts no pueden acceder a ellos.

</Warning>

### Grafana {#grafana}

El sitio sirve Grafana en `/grafana/`, a través de webpack-dev-server, así que no necesita un puerto propio. Su carpeta **Overleaf Develop** tiene estos paneles:

| Panel | Qué muestra |
| --- | --- |
| All services (inicio) | Estado de cada servicio, indicadores del host, carga y logs. Un clic en un servicio abre su panel |
| Server | CPU, carga, memoria, disco y red del host, y las compilaciones de clsi |
| Errors | Logs de errores, respuestas 5xx y 4xx, mensajes de error más frecuentes y rutas que fallan |
| Data flow | El recorrido de una edición: document-updater y Redis, project-history, history-v1, Mongo, almacenamiento de objetos |
| Containers | Estado de cada contenedor, CPU, memoria, red y disco, incluidas las compilaciones en sandbox |
| Uno por servicio | Los servicios Node.js, git-bridge (JVM), mongo y redis |

Prometheus recoge `/metrics` de los servicios, `mongodb-exporter`, `redis-exporter`, `cadvisor` y `node-exporter`; Alloy envía los logs de cada contenedor del proyecto a Loki, donde los leen los filtros **Log search**, **Service** y **Log level** de los paneles. Sus datos viven solo en los contenedores, así que recrearlos los vacía. cAdvisor se ejecuta con privilegios y lee `/`, `/sys`, los datos de Docker y el socket de containerd del host, en solo lectura; node-exporter lee `/` del host.

Los paneles se generan: cambia `develop/grafana/make-dashboards` y ejecútalo, en lugar de editar los archivos JSON.

### Mailpit {#mailpit}

Con `MAILPIT_ENABLED=true`, `web` envía cada correo a Mailpit en lugar de a un servidor de correo real, y la confirmación de correo está activada (`EMAIL_CONFIRMATION_DISABLED=false`). Así puedes seguir desde la bandeja de entrada los enlaces de activación, las invitaciones a proyectos, los restablecimientos de contraseña y los códigos de confirmación.

### Configurar Hoppscotch {#setup-hoppscotch}

#### Solicitudes de API a través del proxy {#proxy-api-request}

Hoppscotch envía las peticiones desde el navegador, que no puede llegar a los servicios por sus nombres de Docker. Su proxy, Proxyscotch, se ejecuta dentro de la red de Docker y se sirve en `/proxy` de la dirección de Hoppscotch. Abre [http://localhost:9170](http://localhost:9170/), ve a Settings → Interceptor, elige **Proxy** y establece la Proxy URL en `http://localhost:9170/proxy`. La configuración se queda en el navegador.

#### Importar las API de los servicios {#import-the-service-apis}

`develop/hoppscotch/openapi/` tiene un archivo OpenAPI para la API interna de cada servicio. En Hoppscotch, abre Collections → Import → Import from File y selecciona todos los archivos a la vez. Cada archivo se convierte en una colección cuyas peticiones van a la dirección Docker del servicio. Los mismos archivos se muestran en la sección [API de servicios](/es/dev/service-api/overview).

#### Problemas de CSRF {#csrf-problems}

<Warning>

Si usas Postman u otras herramientas de depuración para generar una solicitud **post**, es posible que el inicio de sesión quede **prohibido**, con un error 403. Esto se debe a que Overleaf está protegido mediante verificación **csrf**.

</Warning>

<Frame>
  <img src="/images/dev/image-8.png" alt="" />
</Frame>

En tu consola, puede que veas:

<Frame>
  <img src="/images/dev/image-9.png" alt="" />
</Frame>

Para resolver esto en tu desarrollo de Overleaf, debes configurar tu token csrf. Este es el tutorial detallado.

<Steps>
<Step title="Añadir Pre-Request">
Añade el siguiente código en Pre-Request

<Frame>
  <img src="/images/dev/image-10.png" alt="" />
</Frame>

El script es el siguiente:

```js wrap
pm.sendRequest("http://web:3000/dev/csrf", function (err, res) {
    if (err) {
        console.log(err);
        return;
    }

    // 1) Save CSRF token (/dev/csrf)
    const token = res.text().trim();
    pw.env.set("csrftoken", token);
    console.log("csrftoken =", token);

    const setCookieHeader = (res.headers || []).find(h => h.key?.toLowerCase() === "set-cookie")?.value;
    console.log("set-cookie =", setCookieHeader);

    if (!setCookieHeader) return;

    const cookiePair = setCookieHeader.split(";")[0].trim(); // overleaf.sid=...
    pw.env.set("cookie_header", cookiePair);
    console.log("cookie_header =", cookiePair);
});
```
</Step>

<Step title="Añadir cabeceras de la solicitud">
Debes añadir las siguientes cabeceras:

| Nombre de la cabecera | Valor de la cabecera |
| --------------------- | -------------------- |
| Content-Type          | `application/json`   |
| X-Csrf-Token          | `<<csrftoken>>`      |
| Cookie                | `<<cookie_header>>`  |

<Frame>
  <img src="/images/dev/image-11.png" alt="" />
</Frame>
</Step>

<Step title="Iniciar sesión con herramientas de API">
Ahora puedes iniciar sesión con tu nombre de usuario y contraseña.

```json5
{
  "_csrf": "<<csrftoken>>",
  "email": "admin@overleaf.com",
  "password": "xxxxxx"
}
```

Esta es la respuesta cuando introduces un nombre de usuario o una contraseña incorrectos.

<Frame>
  <img src="/images/dev/image-12.png" alt="" />
</Frame>
</Step>
</Steps>
