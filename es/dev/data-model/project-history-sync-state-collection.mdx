title: Colección Project History Sync State
icon: rotate
---

`projectHistorySyncState` contiene un documento por proyecto que se ha resincronizado: el estado de la resincronización actual o de la última, cuando project-history reconstruye el historial de un proyecto a partir de lo que tienen web y docstore. Pertenece a project-history y no tiene esquema de Mongoose; el código es la clase `SyncState` y sus funciones auxiliares en `services/project-history/app/js/SyncManager.js`.

#### Quién escribe {#who-writes-it}

| Código | Qué hace |
| ---- | ------------ |
| `services/project-history/app/js/SyncManager.js:195-249` | `setResyncState`: upsert del estado. Se llama cuando empieza una resincronización (`SyncManager.js:163`) y mientras project-history procesa las actualizaciones de resincronización (`services/project-history/app/js/UpdatesProcessor.js:637`, `784`). |
| `SyncManager.js:257-266` | `_recordStuckClearInSyncState`: cuenta una resincronización atascada que se limpia. |
| `SyncManager.js:251-255` | `clearResyncState`: elimina el documento al inicio de una resincronización completa (`SyncManager.js:87`), en `DELETE /project/:project_id` de project-history (`services/project-history/app/js/HttpController.js:1363-1396`) y cuando una resincronización solo de estructura tiene que empezar de nuevo (`SyncManager.js:705-716`). |
| `SyncManager.js:273-289` | `clearResyncStateIfAllAfter`: elimina un estado terminado cuyo historial es posterior en su totalidad a una fecha. Nada en `app/js` lo llama. |
| `SyncManager.js:171-181` | `cloneResyncState`: copia el estado a otro proyecto, para `POST /project/:project_id/clone` de project-history (`HttpController.js:57`, `124`), que nada en web llama. |

Una resincronización la inicia `POST /project/:project_id/resync` de project-history (`HttpController.js:950-994`), las tareas cron de reintento (`services/project-history/app/js/RetryManager.js:156-179`, `server-ce/config/crontab-history`) y el propio project-history cuando el procesamiento de actualizaciones necesita una (`UpdatesProcessor.js:75`, `224`).

#### Notas {#notes}

* Una resincronización está en curso mientras `resyncProjectStructure` es `true` o `resyncDocContents` no está vacío (`SyncManager.js:565-567`). Se considera atascada después de 4 horas, y atascada de forma permanente después de 5 limpiezas (`SyncManager.js:43-44`, `569-585`).
* Cuando termina una resincronización, project-history también establece `overleaf.history.lastResyncedAt` en el proyecto (`SyncManager.js:239-248`).
