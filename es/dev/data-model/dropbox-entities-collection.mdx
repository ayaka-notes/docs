---
title: Colección Dropbox Entities
icon: file-arrow-up
---

`dropboxEntities` contiene un documento por cada archivo que la sincronización con Dropbox ha copiado entre un proyecto y el Dropbox de un usuario, además de tombstones de corta duración. Pertenece a la sincronización con Dropbox: third-party-datastore (`services/third-party-datastore/app/js/StateManager.mjs`) la escribe y la lee, y el módulo web `dropbox` (`services/web/modules/dropbox/app/src/DropboxHandler.mjs`) la vacía. No hay esquema de Mongoose.

#### Campos {#fields}

| Campo | Tipo | Significado | Fuente |
| ----- | ---- | ----------- | ------ |
| `_id` | ObjectId | Lo establece el driver al insertar. | `StateManager.mjs:46,97` |
| `overleaf.userId` | ObjectId | El usuario en cuyo Dropbox está el archivo. Se establece en todos los documentos. | `StateManager.mjs:48,98` |
| `overleaf.projectId` | ObjectId | El proyecto del doc o archivo. Se establece cuando se conoce; los tombstones no lo tienen. | `StateManager.mjs:49-51` |
| `overleaf.id` | ObjectId | El `_id` del doc o archivo en el `rootFolder` del proyecto. Se establece cuando se conoce. | `StateManager.mjs:52` |
| `overleaf.type` | String | `doc` o `file`. El código actual lo escribe pero no lo lee. | `StateManager.mjs:53`; valores de `services/web/app/src/Features/ThirdPartyDataStore/TpdsUpdateSender.mjs:35,96` y `UpdateMerger.mjs:104,119` |
| `dropbox.id` | String | El `id` del archivo en los metadatos de archivo de Dropbox. No se establece en los tombstones. | `StateManager.mjs:56` |
| `dropbox.pathLower` | String | La ruta del archivo en Dropbox, en minúsculas y sin barra final. Se actualiza cuando el archivo o su carpeta de proyecto se mueve. | `StateManager.mjs:14-16,57,91,99` |
| `dropbox.rev` | String | La revisión de Dropbox en la última sincronización. La siguiente subida la envía, para que no se sobrescriba un archivo que cambió en Dropbox. | `StateManager.mjs:58`, `JobProcessor.mjs:114-122` |
| `dropbox.contentHash` | String | El hash de contenido de Dropbox en la última sincronización. Un archivo listado con el mismo hash se omite, porque es nuestra propia subida o ya está aplicado. | `StateManager.mjs:59`, `PullManager.mjs:147-149` |
| `tombstone` | Boolean | `true` marca una ruta que el propio third-party-datastore eliminó o movió en Dropbox. Cuando Dropbox informa de esa eliminación, no se aplica al proyecto. | `StateManager.mjs:100`, `PullManager.mjs:189-192` |
| `createdAt` | Date | Solo tombstones: cuándo se creó. Un pull terminado elimina los tombstones creados antes de que empezara. | `StateManager.mjs:101,115-121` |

Un tombstone solo tiene `overleaf.userId`, `dropbox.pathLower`, `tombstone` y `createdAt` (`StateManager.mjs:96-103`).

#### Quién la escribe {#who-writes-it}

| Código | Qué hace |
| ------ | -------- |
| `services/third-party-datastore/app/js/StateManager.mjs:35-62` (`recordEntity`) | Elimina los documentos del usuario con el mismo `dropbox.id`, `dropbox.pathLower` u `overleaf.id` y luego inserta el nuevo estado. |
| `services/third-party-datastore/app/js/JobProcessor.mjs:102-134` (`addEntity`) | Registra un doc o archivo después de subirlo de Overleaf a Dropbox (`:125-133`). |
| `services/third-party-datastore/app/js/PullManager.mjs:142-177` (`applyFile`) | Registra un archivo de Dropbox después de que web lo aplicara al proyecto (`:168-176`). |
| `StateManager.mjs:80-94` (`moveEntities`) | Reescribe `dropbox.pathLower` bajo una ruta movida: cambio de nombre del proyecto (`JobProcessor.mjs:195`) y movimiento de archivo o carpeta (`JobProcessor.mjs:239`). |
| `StateManager.mjs:96-103` (`addTombstone`) | Después de una eliminación (`JobProcessor.mjs:153`), un cambio de nombre del proyecto (`:202`) o un movimiento (`:240`) en Dropbox. |
| `StateManager.mjs:72-78` (`removeEntities`) | Elimina las entradas en una ruta y por debajo de ella, excepto los tombstones: tras una eliminación desde Overleaf (`JobProcessor.mjs:152`) o en Dropbox (`PullManager.mjs:206`). |
| `StateManager.mjs:115-121` (`clearTombstones`) | Al final de un pull (`PullManager.mjs:31,69`). |
| `StateManager.mjs:186-190` (`removeUserState`), llamado desde `services/third-party-datastore/app/js/QueueWorker.mjs:43` | Elimina todos los documentos del usuario cuando third-party-datastore desvincula una cuenta que ya no puede usar. |
| `DropboxHandler.mjs:142-146` (`removeUserState`) | Elimina todos los documentos del usuario al vincular (`:125`), al desvincular (`:183`) y cuando caduca un usuario eliminado (`services/web/modules/dropbox/index.mjs:62-64`). |
| `DropboxHandler.mjs:150-154` (`removeProjectState`) | Elimina los documentos del proyecto cuando caduca un proyecto eliminado (`index.mjs:54-56`). |

#### Quién la lee {#who-reads-it}

| Código | Qué hace |
| ------ | -------- |
| `StateManager.mjs:64-70` (`findEntityByPath`) | Obtiene `dropbox.rev` antes de una subida (`JobProcessor.mjs:114`) y `dropbox.contentHash` antes de aplicar un archivo de Dropbox (`PullManager.mjs:147`). |
| `StateManager.mjs:106-112` (`findTombstone`) | Comprueba una eliminación notificada en la ruta o en uno de sus padres (`PullManager.mjs:189`). |
| `StateManager.mjs:160-175` (`getSyncedPaths`) | Lista las rutas de archivos sincronizados tras reiniciar el cursor, de modo que un archivo que falta en el listado cuenta como eliminado (`PullManager.mjs:74-85`). |

#### Notas {#notes}

* La unicidad viene solo de la eliminación previa a cada inserción en `recordEntity` (`StateManager.mjs:38-45`). El comentario en `StateManager.mjs:3-11` menciona índices únicos; CE no los tiene.
* Las consultas por usuario y ruta (`findEntityByPath`, `findTombstone`, `removeEntities`) usan el índice solo para `overleaf.userId`.
