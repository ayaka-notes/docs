---
title: Colección Deleted Users
icon: user-xmark
---

`deletedUsers` conserva una cuenta de usuario después de eliminarla: un documento por cuenta eliminada, con una copia del documento completo del usuario y quién la eliminó. Web la escribe en `services/web/app/src/Features/User/UserDeleter.mjs`; el esquema es `services/web/app/src/models/DeletedUser.mjs`. Cuando pasa el plazo de eliminación definitiva, la expiración quita la copia del usuario, pero el registro con `deleterData` permanece.

Eliminar un usuario también elimina los proyectos de los que es propietario; van a [Colección Deleted Projects](/es/dev/data-model/deleted-projects-collection) con el motivo `account-deletion`.

#### Quién escribe {#who-writes-it}

| Código | Qué hace |
| ---- | ------------ |
| `UserDeleter.mjs:37-80` (`deleteUser`) | Añade una entrada de registro de auditoría `delete-account`, limpia el usuario y dispara el hook `deleteUser`, hace un upsert del registro (`_createDeletedUser`, `UserDeleter.mjs:192-213`), elimina los proyectos del usuario, envía el correo de alerta de seguridad salvo que se omita y elimina el documento de `users`. Llamadores: la página de configuración de la cuenta (`services/web/app/src/Features/User/UserController.mjs:280-284`), el panel de administración (`services/web/modules/admin-tools/app/src/AdminUserManager.mjs:604-612`) y el script `delete-user` (`delete-user.mjs:40-45`). |
| `UserDeleter.mjs:93-115` (`expireDeletedUser`) | Dispara el hook `expireDeletedUser`, elimina los datos de onboarding del usuario y luego quita `user` y `deleterData.deleterIpAddress`. |
| `UserDeleter.mjs:117-161` (`expireDeletedUsersAfterDuration`) | Hace expirar cada registro más antiguo que el plazo y elimina las `userAuditLogEntries` del usuario. Ruta `POST /internal/expire-deleted-users-after-duration` (`services/web/app/src/router.mjs:847-851`), que el cron de la Community Edition llama cada hora en el minuto 15 cuando `ENABLE_CRON_RESOURCE_DELETION` es `true` (`server-ce/cron/delete-users.sh:10-23`, `server-ce/config/crontab-deletion:2`). Un solo usuario: `POST /internal/users/:userId/expire` (`router.mjs:857-861`). |
| `AdminUserManager.mjs:630-649` (`purgeDeletedUser`, módulo `admin-tools`) | Purge en el panel de administración: ejecuta `expireDeletedUser` y elimina las entradas del registro de auditoría del usuario. |
| `AdminUserManager.mjs:651-696` (`restoreDeletedUser`, módulo `admin-tools`) | Restaurar en el panel de administración: vuelve a crear el documento de `users` a partir de `user` (se rechaza si el correo está en uso), elimina el registro y restaura los proyectos eliminados con la cuenta. |

#### Notas {#notes}

* Los módulos que escuchan `expireDeletedUser` eliminan sus propios datos del usuario: `dropbox` (`services/web/modules/dropbox/index.mjs:62`), `github-sync` (`services/web/modules/github-sync/index.mjs:66`), `gitlab-sync` (`services/web/modules/gitlab-sync/index.mjs:56`) y `gitea-sync` (`services/web/modules/gitea-sync/index.mjs:56`).
* Un registro expirado nunca se elimina: `deleterData` permanece para siempre, solo se quitan `user` y la dirección IP.
* Los tokens de acceso personal del usuario no se eliminan con la cuenta, consulta [Colección OAuth Access Tokens](/es/dev/data-model/oauth-access-tokens-collection).
* Mongoose también da a `deleterData` su propio `_id`, que nada lee.
