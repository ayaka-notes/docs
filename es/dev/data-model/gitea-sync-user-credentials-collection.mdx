---
title: Colección Gitea Sync User Credentials
icon: lock
---

`giteaSyncUserCredentials` contiene un documento por cada usuario que vinculó una cuenta de Gitea para Gitea Sync. Guarda los tokens OAuth del usuario, cifrados. Pertenece al módulo web `gitea-sync` (`services/web/modules/gitea-sync`). El esquema está en `services/web/modules/gitea-sync/app/models/giteaSyncUserCredentials.mjs`, y todo el acceso pasa por `services/web/modules/gitea-sync/app/src/TokenManager.mjs`.

#### Campos {#fields}

| Campo | Tipo | Significado | Fuente |
| ----- | ---- | ------- | ------ |
| `_id` | ObjectId | Lo establece Mongoose cuando el upsert inserta. | |
| `userId` | ObjectId | El usuario de Overleaf. Obligatorio. El esquema indica `unique: true`, pero no se crea ningún índice (ver Índices); el upsert por `userId` mantiene un documento por usuario. | `giteaSyncUserCredentials.mjs:8`, `TokenManager.mjs:89-96` |
| `gitea` | String | El JSON `{ accessToken, refreshToken, expiresAt }`, cifrado con `@overleaf/access-token-encryptor`. `expiresAt` está en milisegundos desde la época Unix, o es `null`; `refreshToken` puede ser `null`. La contraseña viene de `GITEA_TOKEN_CIPHER_PASSWORD`; la etiqueta de cifrado es `GITEA_TOKEN_CIPHER_LABEL`, por defecto `2026.10-v3`. Obligatorio. | `giteaSyncUserCredentials.mjs:9-10`, `TokenManager.mjs:17-30`, `services/web/modules/gitea-sync/app/src/GiteaApiClient.mjs:198-209` |
| `__v` | Number | La clave de versión de Mongoose. El esquema no la desactiva. | Valor predeterminado de Mongoose |

#### Quién la escribe {#who-writes-it}

| Código | Qué hace |
| ---- | ------------ |
| `TokenManager.mjs:89-96` (`saveUserToken`) | Hace un upsert de las credenciales cifradas del usuario. Se llama desde el callback de OAuth (`services/web/modules/gitea-sync/app/src/GiteaSyncController.mjs:146`). A diferencia de GitLab Sync, volver a vincular la cuenta no revoca el token reemplazado. |
| `TokenManager.mjs:53-79` (`refreshUserToken`) | Cuando faltan menos de 5 minutos para el `expiresAt` del token de acceso (`:12`), obtiene tokens nuevos con el token de actualización y los guarda (`:76`). Se ejecuta bajo el bloqueo `giteaSyncToken` por usuario (`:14,54`), porque Gitea reemplaza el token de actualización al usarlo. |
| `TokenManager.mjs:100-102` (`removeUserToken`) | Elimina el documento. Gitea no tiene una API para revocar un token OAuth, así que el usuario revoca la autorización en Gitea (`:98-99`). Se llama al desvincular (`GiteaSyncController.mjs:173`) y cuando caduca un usuario eliminado (`services/web/modules/gitea-sync/index.mjs:56-58`). |

#### Quién la lee {#who-reads-it}

| Código | Qué hace |
| ---- | ------------ |
| `TokenManager.mjs:40-44,82-86` (`getUserCredentials`, `getUserToken`) | Descifra las credenciales para cada llamada a la API de Gitea, actualizándolas primero cuando el token está a punto de caducar: `services/web/modules/gitea-sync/app/src/GiteaSyncHandler.mjs` (por ejemplo `:27`) y `services/web/modules/gitea-sync/app/src/GitMerge.mjs:52`. Sin documento, o con credenciales que no se pueden descifrar ni actualizar, lanza `InvalidTokenError`, y el usuario cuenta como no vinculado (`GiteaSyncHandler.mjs:25-37`). |
| `services/web/modules/admin-tools/app/src/AdminUserListManager.mjs:395` | Comprueba si el usuario tiene un documento, para las integraciones que se muestran en el panel de administración. |

#### Índices {#indexes}

| Nombre | Claves | Opciones | Migración |
| ---- | ---- | ------- | --------- |
| `_id_` | `_id: 1` | | default |

El `autoIndex` de Mongoose está desactivado (`services/web/app/src/infrastructure/Mongoose.mjs:7`), así que el `unique: true` del esquema en `userId` no crea nada. Ninguna migración crea índices para esta colección.

#### Notas {#notes}

* Cambiar `GITEA_TOKEN_CIPHER_PASSWORD` hace ilegibles las credenciales guardadas. Esos usuarios cuentan entonces como no vinculados hasta que vuelvan a vincular la cuenta.
* Un usuario eliminado conserva el documento hasta que caduca.
