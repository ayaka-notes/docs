`githubSyncProjectStates` contiene un documento por cada proyecto vinculado a un repositorio de GitHub: qué repositorio y dónde se quedó la última sincronización. Pertenece al módulo web `github-sync` (`services/web/modules/github-sync`). El esquema está en `services/web/modules/github-sync/app/models/githubSyncProjectStates.mjs`, y todo el acceso pasa por `services/web/modules/github-sync/app/src/SyncStateManager.mjs`.

| ----- | ---- | ----------- | ------ |

#### Quién la escribe {#who-writes-it}

| Código | Qué hace |
| ------ | -------- |
| `SyncStateManager.mjs:9-14` (`createProjectState`) | Crea el documento: tras importar un repositorio como proyecto nuevo (`services/web/modules/github-sync/app/src/GitHubSyncHandler.mjs:175-181`), o tras exportar un proyecto a un repositorio nuevo (`GitHubSyncHandler.mjs:235-241`, solo el propietario, rechazado si ya está vinculado). |
| `SyncStateManager.mjs:16-21` (`updateProjectState`) | `$set` de los campos modificados. `getMergeOverview` establece `mergeStatus: 'diverged'` cuando la rama sincronizada ya no parte de `lastSyncCommit`: la comparación de GitHub responde `diverged` o `behind` (`GitHubApiClient.mjs:382-400`), o el commit ya no existe y el usuario puede hacer push (`GitHubSyncHandler.mjs:123,126-137`). Una sincronización (`services/web/modules/github-sync/app/src/GitMerge.mjs`) avanza `lastSyncCommit`/`lastSyncVersion` si tiene éxito (por ejemplo `:143,173,224`), registra un conflicto con `unmergedBranchName`, `unmergedBranchHead` y `conflictVersion` (`:207-213`), y los borra una vez resuelto (`:250-257`). |
| `SyncStateManager.mjs:23-25` (`removeProjectState`) | Elimina el documento cuando el propietario desvincula el proyecto (`GitHubSyncHandler.mjs:83-97`) y cuando caduca un proyecto eliminado (`services/web/modules/github-sync/index.mjs:56-58`). |

#### Quién la lee {#who-reads-it}

| Código | Qué hace |
| ------ | -------- |
| `GitHubSyncHandler.mjs:39-60` (`getProjectState`) | Da al editor `mergeStatus`, `repoFullName` y `unmergedBranchName`. Sin documento responde `need-export`, un valor que nunca se almacena. |
| `GitHubSyncHandler.mjs:110-143` (`getMergeOverview`) | Compara `lastSyncCommit` y `lastSyncVersion` con GitHub y el historial del proyecto para listar los commits nuevos. |
| `GitHubSyncHandler.mjs:200` (`exportProject`) | Rechaza exportar un proyecto que ya está vinculado. |
| `GitMerge.mjs:27` (`doGitMergeWithoutLock`) | Carga el estado al inicio de una sincronización. |

#### Índices {#indexes}

| Nombre | Claves | Opciones | Migración |
| ------ | ------ | -------- | --------- |
| `_id_` | `_id: 1` | | default |

El `autoIndex` de Mongoose está desactivado (`services/web/app/src/infrastructure/Mongoose.mjs:7`), así que el `unique: true` del esquema en `projectId` no crea nada. `tools/migrations/20190912145010_create_githubSyncProjectStates_indexes.mjs` (`project_id` y `owner_id` de upstream) solo tiene la etiqueta `saas` y no se ejecuta en CE.

#### Notas {#notes}

* Una sincronización se ejecuta bajo el bloqueo `gitSync` del proyecto (`GitMerge.mjs:17-24`). GitLab Sync y Gitea Sync toman el mismo bloqueo, así que solo se ejecuta una sincronización por proyecto a la vez.
* Un proyecto eliminado conserva su documento hasta que el proyecto caduca.
* El token de GitHub del usuario está en [GitHub Sync User Credentials](/es/dev/data-model/github-sync-user-credentials-collection).
