title: Colección OAuth Applications
icon: id-badge
---

`oauthApplications` contiene los clientes OAuth que conoce web. Un documento es un cliente. En Ayakaleaf Pro el único que escribe en ella es el módulo web `git-bridge`, que crea un cliente llamado `Overleaf Git Bridge` cuando arranca web. El esquema es `services/web/app/src/models/OauthApplication.mjs`.

#### Campos {#fields}

| Campo | Tipo | Significado | Origen |
| ----- | ---- | ------- | ------ |
| `_id` | ObjectId | Id del documento del cliente. `oauthAccessTokens.oauthApplication_id` y `oauthAuthorizationCodes.oauthApplication_id` apuntan a él. | `OauthApplication.mjs:5` |
| `id` | String | Id del cliente: 64 letras minúsculas y dígitos aleatorios. | `OauthApplication.mjs:7`, `services/web/modules/git-bridge/index.mjs:25` |
| `clientSecret` | String | Secreto del cliente, escrito como `v1.` más 32 caracteres aleatorios. Solo lo lee `getClient`, y nada llama a `getClient` (ver Notas). | `OauthApplication.mjs:8`, `git-bridge/index.mjs:26` |
| `grants` | Array of String | Tipos de grant. El cliente de git-bridge tiene `['password']`. Se devuelve con el cliente cuando se comprueba un token (`services/web/modules/oauth2-server/app/src/OAuth2Model.mjs:67-72`). | `OauthApplication.mjs:9`, `git-bridge/index.mjs:27` |
| `name` | String | Nombre del cliente. El módulo git-bridge y el código de tokens de acceso personal encuentran el cliente por el nombre `Overleaf Git Bridge`. | `OauthApplication.mjs:10`, `git-bridge/index.mjs:15-16,28` |
| `redirectUris` | Array of String | URI de redirección permitidas. `[]` para el cliente de git-bridge. | `OauthApplication.mjs:11`, `git-bridge/index.mjs:29` |
| `scopes` | Array of String | Scopes que puede usar el cliente. `['git_bridge']` para el cliente de git-bridge. | `OauthApplication.mjs:12`, `git-bridge/index.mjs:30` |
| `pkceEnabled` | Boolean | Solo en el esquema: ningún código de este repositorio lo escribe, y solo lo lee `getClient`, que no se usa (`OAuth2Model.mjs:207`). | `OauthApplication.mjs:13` |

#### Quién escribe {#who-writes-it}

| Código | Qué hace |
| ---- | ------------ |
| `git-bridge/index.mjs:9-35` (module `git-bridge`) | Cuando `GIT_BRIDGE_ENABLED` es `true`, crea el cliente `Overleaf Git Bridge` al arrancar web si no existe ningún cliente con ese nombre. |

#### Quién lee {#who-reads-it}

| Código | Qué hace |
| ---- | ------------ |
| `services/web/modules/oauth2-server/app/src/OAuthPersonalAccessTokenManager.mjs:53-61` (module `oauth2-server`) | Busca el cliente `Overleaf Git Bridge` por nombre y guarda su `_id` en cada nuevo token de acceso personal. Sin el cliente no se crea ningún token. |
| `OAuth2Model.mjs:31-39,67-72` (`getAccessToken`) | Carga el cliente de un token mediante `oauthApplication_id` y devuelve su `id` y sus `grants`. |
| `OAuth2Model.mjs:185-209,241,275` (`getClient`, `saveToken`, `saveAuthorizationCode`) | Buscan clientes por `id`. Nunca se alcanzan en este repositorio, ver Notas. |

#### Índices {#indexes}

Solo el índice predeterminado de `_id`. El índice único `id_1` procede de migraciones etiquetadas `saas` (`20190912145016_create_oauthApplications_indexes.mjs`) y `server-pro` (`20230502180757_server_pro_oauth_indexes.mjs`), que Community Edition no ejecuta.

#### Notas {#notes}

* Web usa `@node-oauth/oauth2-server` solo para comprobar tokens bearer (`server.authenticate` en `services/web/app/src/Features/Authentication/AuthenticationController.mjs:409-450`), que solo llama a `getAccessToken` y `verifyScope` del modelo. Ninguna ruta sirve `/oauth/token` ni `/oauth/authorize`, así que `getClient`, `saveToken` y `saveAuthorizationCode` nunca se llaman.
* El módulo busca el cliente por nombre y luego lo crea, y Community Edition no tiene índice único en `name` ni en `id`. Nada impide, por tanto, un segundo cliente con el mismo nombre. El código que necesita el cliente toma el que devuelva `findOne`.
