`docSnapshots` guarda copias de un doc que document-updater toma justo antes de una edición que contrae comentarios o cambios con seguimiento. Solo document-updater la escribe, en `services/document-updater/app/js/SnapshotManager.js`. Web tiene un modelo de Mongoose en `services/web/app/src/models/DocSnapshot.mjs`, pero ningún código lo usa.

#### Campos {#fields}

| Campo | Tipo | Significado | Origen |
| ----- | ---- | ------- | ------ |
| `_id` | ObjectId | Id de la instantánea. | `SnapshotManager.js:24` |
| `project_id` | ObjectId | Proyecto. | `SnapshotManager.js:19,26`, `DocSnapshot.mjs:7` |
| `doc_id` | ObjectId | El doc (`docs._id`). | `SnapshotManager.js:20,27`, `DocSnapshot.mjs:8` |
| `version` | Number | Versión OT del doc antes de la edición. | `SnapshotManager.js:28`, `services/document-updater/app/js/UpdateManager.js:132,264-271`, `DocSnapshot.mjs:9` |
| `lines` | Array of String | Contenido del doc antes de la edición. | `SnapshotManager.js:29`, `DocSnapshot.mjs:10` |
| `pathname` | String | Ruta del doc en el proyecto en ese momento. | `SnapshotManager.js:30`, `DocSnapshot.mjs:11` |
| `ranges` | Mixed | `comments` y `changes` antes de la edición, con la misma forma que `docs.ranges` (consulta [docs](/es/dev/data-model/docs-collection)). `id`, `op.t` y `metadata.user_id` se convierten en ObjectIds y `metadata.ts` en Dates. | `SnapshotManager.js:31,41-68`, `DocSnapshot.mjs:12` |
| `ts` | Date | Cuándo se tomó la instantánea. El índice TTL la elimina 30 días después. | `SnapshotManager.js:32`, `DocSnapshot.mjs:13` |

#### Quién la escribe {#who-writes-it}

| Código | Qué hace |
| ---- | ------------ |
| `UpdateManager.js:248-271` | Después de aplicar una edición, document-updater registra el doc tal como estaba antes de la edición cuando esta contrajo rangos: más rangos quedaron vacíos o se eliminó más de un rango (`services/document-updater/app/js/RangesManager.js:104-106`). |
| `SnapshotManager.js:17-36` `recordSnapshot` | Inserta la instantánea. |

#### Quién la lee {#who-reads-it}

Ningún código la lee. El modelo de web está definido, pero no se usa en ninguna parte.

#### Notas {#notes}

* Solo las ediciones que pasan por `UpdateManager.applyUpdate` toman instantáneas. Las que gestiona `HistoryOTUpdateManager` no lo hacen (`UpdateManager.js:74-77`).
* No hay índice en `doc_id`. Busca las instantáneas de un doc por `project_id` y `ts`, y luego filtra por `doc_id`.
