---
title: Colección Project History Labels
icon: tag
---

`projectHistoryLabels` guarda las etiquetas que los usuarios ponen en versiones en la vista Historial, un documento por etiqueta. project-history es su propietario y la escribe en `services/project-history/app/js/LabelsManager.js`; no hay esquema de Mongoose. Web solo accede a ella a través de la API de project-history.

#### Campos {#fields}

| Campo | Tipo | Significado | Origen |
| ----- | ---- | ------- | ------ |
| `_id` | ObjectId | Id de la etiqueta. | `LabelsManager.js:81-85` |
| `project_id` | ObjectId | El proyecto. | `LabelsManager.js:73` |
| `comment` | String | El texto de la etiqueta. | `LabelsManager.js:74` |
| `version` | Number | La versión del historial del proyecto a la que apunta la etiqueta. | `LabelsManager.js:75` |
| `created_at` | Date | Cuándo se creó la etiqueta; la solicitud puede pasar su propia hora, si no, es la actual. | `LabelsManager.js:70`, `76` |
| `user_id` | ObjectId | Quién creó la etiqueta. Se omite cuando la solicitud no tiene usuario. | `LabelsManager.js:78-80` |

#### Quién la escribe {#who-writes-it}

| Código | Qué hace |
| ---- | ------------ |
| `services/project-history/app/js/LabelsManager.js:44-90` | `createLabel`: inserta una etiqueta, para project-history `POST /project/:project_id/labels` (`services/project-history/app/js/HttpController.js:1134-1171`). Web lo llama cuando un usuario añade una etiqueta, con el id del usuario (`services/web/app/src/Features/History/HistoryController.mjs:529-546`). |
| `LabelsManager.js:113-126` | `deleteLabel`: elimina una etiqueta del proyecto, para `DELETE /project/:project_id/labels/:label_id`. Web lo usa cuando el propietario del proyecto elimina una etiqueta (`HistoryController.mjs:649-670`). |
| `LabelsManager.js:92-111` | `deleteLabelForUser`: elimina una etiqueta solo si la creó el usuario, para `DELETE /project/:project_id/user/:user_id/labels/:label_id`. Web lo usa para todos los demás. |
| `LabelsManager.js:128-143` | `transferLabels`: traspasa todas las etiquetas de un usuario a otro, para `POST /user/:from_user/labels/transfer/:to_user` (`services/project-history/app/js/Router.js:52-55`). Nada en web llama a esta ruta. |
| `LabelsManager.js:7-25` | `cloneLabels`: copia las etiquetas de un proyecto a otro proyecto, para project-history `POST /project/:project_id/clone` (`HttpController.js:113`), a la que nada en web llama. |

#### Quién la lee {#who-reads-it}

| Código | Qué hace |
| ---- | ------------ |
| `LabelsManager.js:27-42` | `getLabels`: todas las etiquetas de un proyecto, devueltas como `{ id, comment, version, user_id, created_at }` (`LabelsManager.js:163-171`). Lo usa `GET /project/:project_id/labels` (`HttpController.js:1076-1100`), que web llama para la vista Historial y completa los nombres de usuario (`HistoryController.mjs:488-499`). |
| `services/project-history/app/js/SummarizedUpdatesManager.js:57` | Añade las etiquetas a la lista de actualizaciones del historial. |

#### Notas {#notes}

* Antes de insertar una etiqueta, project-history procesa las actualizaciones en cola del proyecto y comprueba que history-v1 tenga un chunk para esa versión, salvo que la solicitud envíe `validate_exists: false` (`LabelsManager.js:53-59`, `173-195`; `HttpController.js:1109-1115`).
* Ningún código elimina las etiquetas de un proyecto cuando se elimina el proyecto: project-history `DELETE /project/:project_id` solo borra el estado de sincronización y el registro de fallos (`HttpController.js:1363-1396`), y ningún otro servicio toca esta colección.
