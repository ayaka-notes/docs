title: Colección Project History Failures
icon: triangle-exclamation
---

`projectHistoryFailures` guarda un documento por proyecto cuyas actualizaciones de historial project-history no pudo procesar, o para el que inició una resincronización. El documento se vuelve a eliminar en cuanto el procesamiento funciona. project-history la escribe en `services/project-history/app/js/ErrorRecorder.js`; su tipo está en `services/project-history/app/js/mongo-types.ts:3-24`. Web también tiene un esquema de Mongoose para ella (`services/web/app/src/models/ProjectHistoryFailure.mjs:5-19`), pero ningún código de web usa ese modelo.

#### Quién la escribe {#who-writes-it}

| Código | Qué hace |
| ---- | ------------ |
| `services/project-history/app/js/ErrorRecorder.js:34-66` | `record`: upsert del error, `attempts` +1, entrada añadida a `history`. Se llama cuando falla el procesamiento de las actualizaciones de un proyecto (`UpdatesProcessor.js:91`, `169`, `242`, `293`, `345`) y cuando no puede iniciarse una resincronización (`SyncManager.js:75`, `96`). |
| `ErrorRecorder.js:86-102` | `recordSyncStart`: upsert, `resyncStartedAt`, `resyncAttempts` +1, entrada añadida a `history`, cada vez que se inicia una resincronización (`SyncManager.js:104`). |
| `ErrorRecorder.js:68-70` | `clearError`: elimina el documento tras un flush correcto (`UpdatesProcessor.js:101`, `194`, `259`, `355`), en project-history `DELETE /project/:project_id` (`services/project-history/app/js/HttpController.js:1386`) y ante un id de proyecto incorrecto durante un reintento (`services/project-history/app/js/RetryManager.js:161`). |
| `ErrorRecorder.js:72-82` | `setForceDebug`: upsert de `forceDebug` (`HttpController.js:1016-1035`, ruta en `services/project-history/app/js/Router.js:82`). |
| `ErrorRecorder.js:109-119` | `cloneFailure`: copia el documento a otro proyecto, para project-history `POST /project/:project_id/clone` (`HttpController.js:135`), a la que nada en web llama. |

#### Notas {#notes}

* Un documento permanece hasta que un flush del proyecto tiene éxito o el proyecto se elimina (`clearError` arriba), así que cada documento marca un proyecto cuyo último flush o resincronización aún no ha tenido éxito.
* Las cadenas de error que empiezan por `OError:` se devuelven como `Error:` (`ErrorRecorder.js:18-26`); el valor guardado no cambia.
