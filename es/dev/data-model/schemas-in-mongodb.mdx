En esta sección analizaremos el modelo de datos de Overleaf. Overleaf usa MongoDB para la persistencia de datos; la única base de datos se llama `sharelatex`, que es también el nombre del predecesor de Overleaf.

El entorno de desarrollo ya ejecuta Mongo Express junto a Mongo (consulta [setup-develop-tools.md](/es/dev/environment/setup-develop-tools  "mention")). Abre [http://localhost:8081/](http://localhost:8081/) e inicia sesión con `admin:pass`.

También puedes abrir una shell en el contenedor de Mongo desde el directorio `develop`:

```bash
bin/docker-compose exec mongo mongosh sharelatex
```

#### Cómo están escritas las páginas {#how-the-pages-are-written}

* Cada página lista los campos que escribe el código, con su tipo, su significado y la línea de código que lo muestra: una línea de un esquema de Mongoose o el lugar que escribe el campo. Los campos que solo escribe una migración, un script o uno de los módulos web lo indican.
* Muchas colecciones no tienen esquema de Mongoose: los servicios las escriben con el driver de MongoDB.
* Los índices solo los crean las migraciones de `tools/migrations/`. CE ejecuta las etiquetadas `server-ce` en cada arranque (`server-ce/init_scripts/900_run_web_migrations.sh`); `autoIndex` de Mongoose está desactivado (`services/web/app/src/infrastructure/Mongoose.mjs:7`). Las tablas de índices solo listan lo que acaba teniendo una instancia de CE.
* El texto de los docs está en Mongo, pero el resto del contenido no. El contenido de los archivos se guarda como blobs y el historial como chunks en los buckets de history-v1 (carpetas locales, o S3 / RustFS); los docs abiertos están en Redis hasta que document-updater hace flush.

Una base de datos de CE tiene más colecciones que estas. Muchas las crean vacías sus migraciones de índices y solo se usan en overleaf.com. Por ejemplo, nada en CE ni en nuestros módulos escribe `splittests`, `samlLogs`, `notificationsPreferences`, `onboardingDataCollection` o `userfeatureusages` en el uso normal, así que no tienen página.
