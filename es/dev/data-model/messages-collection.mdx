title: Colección Messages
icon: message
---

`messages` guarda un documento por mensaje: una línea del chat del proyecto, o un comentario o respuesta en un hilo de comentarios de revisión. Solo el servicio chat la escribe, en `services/chat/app/js/Features/Messages/MessageManager.js`. No hay esquema de Mongoose. Cada mensaje pertenece a una sala de la colección [rooms](/es/dev/data-model/rooms-collection).

#### Campos {#fields}

| Campo | Tipo | Significado | Origen |
| ----- | ---- | ------- | ------ |
| `_id` | ObjectId | Id del mensaje. | `MessageManager.js:13-14` |
| `room_id` | ObjectId | La sala (`rooms._id`), no el id del proyecto ni el id del hilo. | `MessageManager.js:8,106-108` |
| `user_id` | ObjectId | Autor. | `MessageManager.js:9,103-105` |
| `content` | String | Texto del mensaje, de 1 a 10240 caracteres (`MAX_MESSAGE_LENGTH`). | `MessageManager.js:7`, `services/chat/app/js/Features/Messages/MessageHttpSchemas.js:3,12-15` |
| `timestamp` | Number | Cuándo se envió, en milisegundos desde 1970 (`Date.now()`), no un Date. | `MessageManager.js:10`, `services/chat/app/js/Features/Messages/MessageHttpController.js:288` |
| `edited_at` | Number | Cuándo se editó por última vez, en milisegundos (`Date.now()`). No existe si nunca se editó. | `MessageManager.js:65-69`, `MessageHttpController.js:189,213` |

#### Quién la escribe {#who-writes-it}

| Código | Qué hace |
| ---- | ------------ |
| `MessageManager.js:5-16` `createMessage` | Inserta un mensaje (`MessageHttpController.js:275-294`). Web envía los mensajes del chat del proyecto desde `services/web/app/src/Features/Chat/ChatController.mjs:32`, y los comentarios desde el módulo track-changes (`services/web/modules/track-changes/app/src/TrackChangesController.mjs:95`) y el módulo mcp-server (`services/web/modules/mcp-server/app/src/CommentTools.mjs:133`). |
| `MessageManager.js:51-72` `updateMessage` | Establece `content` y `edited_at`. Cuando se indica un id de usuario, solo coincide el mensaje de ese usuario (`MessageManager.js:62-64`). Se llama desde `ChatController.mjs:135` y `TrackChangesController.mjs:110`. |
| `MessageManager.js:74-80` `deleteMessage` | Elimina un mensaje. Se llama desde `ChatController.mjs:105` y `TrackChangesController.mjs:129`. |
| `MessageManager.js:39-49` `deleteAllMessagesInRoom(s)` | Elimina los mensajes de un hilo eliminado (`MessageHttpController.js:172-173`) o de todo un proyecto cuando caduca un proyecto eliminado (`MessageHttpController.js:261-271`, llamado desde `services/web/app/src/Features/Project/ProjectDeleter.mjs:391`). |
| `MessageManager.js:115-127` `duplicateRoomToOtherRoom` | Copia `content`, `timestamp` y `user_id` de cada mensaje a otra sala, sin `edited_at`. Se usa cuando una restauración del historial duplica un hilo (`MessageHttpController.js:316-342`) y cuando se copia un proyecto con sus rangos (`MessageHttpController.js:344-357`). |

#### Quién la lee {#who-reads-it}

| Código | Qué hace |
| ---- | ------------ |
| `MessageManager.js:18-29` `getMessages` | Los más recientes primero, como máximo `limit` (50 por defecto) anteriores a `before` (un `timestamp`). Se usa para el chat del proyecto (`ChatController.mjs:80`). |
| `MessageManager.js:31-37` `findAllMessagesInRooms` | Todos los mensajes de algunas salas, para la lista de hilos del panel de revisión (`TrackChangesController.mjs:82`), el módulo mcp-server (`CommentTools.mjs:83`) y la restauración del historial (`services/web/app/src/Features/History/RestoreManager.mjs:259`). Web también comprueba el primer mensaje de un hilo para que un revisor solo pueda cambiar los hilos que inició (`services/web/app/src/Features/Authorization/AuthorizationManager.mjs:409-411`). |
| `MessageManager.js:90-100` `getMessage` | Un mensaje. Web comprueba su `user_id` antes de que un usuario edite o elimine su propio mensaje (`services/web/app/src/Features/Authorization/AuthorizationMiddleware.mjs:253-257`, `TrackChangesController.mjs:124-125`). |

#### Notas {#notes}

* Para encontrar los mensajes de un comentario, busca primero la sala por `project_id` y `thread_id`, y luego consulta `room_id`. El id del comentario en el doc es el `thread_id`, no el `room_id`.
* El texto al que apunta un comentario es `op.c` en `docs.ranges.comments`; la conversación está aquí.
