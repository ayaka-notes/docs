---
title: Colección GitHub Sync User Credentials
icon: key
---

`githubSyncUserCredentials` contiene un documento por cada usuario que vinculó una cuenta de GitHub para GitHub Sync. Guarda el token de acceso OAuth del usuario, cifrado. Pertenece al módulo web `github-sync` (`services/web/modules/github-sync`). El esquema está en `services/web/modules/github-sync/app/models/githubSyncUserCredentials.mjs`, y todo el acceso pasa por `services/web/modules/github-sync/app/src/TokenManager.mjs`.

#### Campos {#fields}

| Campo | Tipo | Significado | Fuente |
| ----- | ---- | ------- | ------ |
| `_id` | ObjectId | Lo establece Mongoose cuando el upsert inserta. | |
| `userId` | ObjectId | El usuario de Overleaf. Obligatorio. El esquema indica `unique: true`, pero no se crea ningún índice (ver Índices); el upsert por `userId` mantiene un documento por usuario. | `githubSyncUserCredentials.mjs:8`, `TokenManager.mjs:44-48` |
| `github` | String | El token de acceso OAuth de GitHub, cifrado con `@overleaf/access-token-encryptor`. La contraseña viene de `GITHUB_TOKEN_CIPHER_PASSWORD`; la etiqueta de cifrado es `GITHUB_TOKEN_CIPHER_LABEL`, por defecto `2026.3-v3`. Obligatorio. | `githubSyncUserCredentials.mjs:9`, `TokenManager.mjs:12-25` |
| `__v` | Number | La clave de versión de Mongoose. El esquema no la desactiva. | Valor predeterminado de Mongoose |

Solo se guarda el token de acceso: el callback de OAuth conserva `access_token` de la respuesta de GitHub (`services/web/modules/github-sync/app/src/GitHubApiClient.mjs:180-191`). No hay token de actualización ni caducidad.

#### Quién la escribe {#who-writes-it}

| Código | Qué hace |
| ---- | ------------ |
| `TokenManager.mjs:42-58` (`saveUserToken`) | Hace un upsert del token cifrado del usuario. Cuando el usuario vuelve a vincular la cuenta, el token reemplazado se revoca en GitHub en segundo plano. Se llama desde el callback de OAuth (`services/web/modules/github-sync/app/src/GitHubSyncController.mjs:146`). |
| `TokenManager.mjs:61-76` (`removeUserToken`) | Revoca el token en GitHub (en la medida de lo posible) y luego elimina el documento. Se llama al desvincular (`GitHubSyncController.mjs:167`) y cuando caduca un usuario eliminado (`services/web/modules/github-sync/index.mjs:66-68`). |

#### Quién la lee {#who-reads-it}

| Código | Qué hace |
| ---- | ------------ |
| `TokenManager.mjs:36-40` (`getUserToken`) | Descifra el token para cada llamada a la API de GitHub: `services/web/modules/github-sync/app/src/GitHubSyncHandler.mjs` (por ejemplo `:27`) y `services/web/modules/github-sync/app/src/GitMerge.mjs:43`. Sin documento, o con un token que no se puede descifrar, lanza `InvalidTokenError`, y el usuario cuenta como no vinculado (`GitHubSyncHandler.mjs:25-37`). |
| `services/web/modules/admin-tools/app/src/AdminUserListManager.mjs:393` | Comprueba si el usuario tiene un documento, para las integraciones que se muestran en el panel de administración. |

#### Índices {#indexes}

| Nombre | Claves | Opciones | Migración |
| ---- | ---- | ------- | --------- |
| `_id_` | `_id: 1` | | default |

El `autoIndex` de Mongoose está desactivado (`services/web/app/src/infrastructure/Mongoose.mjs:7`), así que el `unique: true` del esquema en `userId` no crea nada. `tools/migrations/20190912145011_create_githubSyncUserCredentials_indexes.mjs` (`user_id` de upstream) solo tiene la etiqueta `saas` y no se ejecuta en CE.

#### Notas {#notes}

* Cambiar `GITHUB_TOKEN_CIPHER_PASSWORD` hace ilegibles los tokens guardados. Esos usuarios cuentan entonces como no vinculados hasta que vuelvan a vincular la cuenta.
* Un usuario eliminado conserva el documento hasta que caduca.
