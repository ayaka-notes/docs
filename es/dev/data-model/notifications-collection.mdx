---
title: Colección Notifications
icon: bell
---

`notifications` guarda los avisos que se muestran en la parte superior del panel de proyectos de un usuario. Un documento es un aviso para un usuario, identificado por su `key`. Solo el servicio `notifications` accede a la colección (`services/notifications/app/js/Notifications.js`); `web` y `third-party-datastore` llaman a su API HTTP. No hay esquema de Mongoose.

#### Campos {#fields}

| Campo | Tipo | Significado | Fuente |
| --- | --- | --- | --- |
| `_id` | ObjectId | Id del aviso. `web` marca un aviso como leído mediante este id. | `Notifications.js:58-65` |
| `user_id` | ObjectId | El usuario que ve el aviso. | `Notifications.js:26` |
| `key` | String | Identifica el aviso, por ejemplo `project-invite-<inviteId>`. El upsert mantiene un documento por `user_id` y `key`; no hay índice único. | `Notifications.js:27`, `:51-55` |
| `templateKey` | String | Qué aviso representa el frontend. Se elimina cuando el aviso se lee o se descarta; el documento permanece. | `Notifications.js:29`, `:63`, `:72`, `:78` |
| `messageOpts` | Object | Valores para el texto del aviso, según `templateKey` (para una invitación a un proyecto: `userName`, `projectName`, `projectId`, `token`). Se elimina cuando el usuario descarta el aviso por su id. | `Notifications.js:28`, `:63` |
| `expires` | Date | Opcional. El índice TTL elimina el documento después de esta fecha. | `Notifications.js:35-50` |

`NotificationsBuilder.mjs` también construye claves para invitaciones de grupo, afiliaciones institucionales, suscripciones y proyectos de depuración antiguos. Sus llamadores están en el código de suscripciones e instituciones, y la comprobación de proyectos de depuración antiguos solo se ejecuta con `isSaas` (`services/web/app/src/Features/Project/ProjectListController.mjs:234-236`).

#### Notas {#notes}

* Un aviso leído no se elimina: solo desaparece `templateKey`. Como el documento conserva la clave, un `addNotification` posterior sin `forceCreate` para la misma clave no hace nada (`Notifications.js:21-24`).
* Las rutas `/key/:key` actúan solo sobre la clave, para todos los usuarios (`Notifications.js:76-100`).
* Si `web` no tiene `apis.notifications.url`, no crea ni lee avisos (`NotificationsHandler.mjs:17`, `:41`).
