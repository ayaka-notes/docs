---
title: Colección Deleted Projects
icon: trash-can
---

`deletedProjects` conserva un proyecto después de eliminarlo: un documento por proyecto eliminado, con una copia del documento completo del proyecto y quién lo eliminó. Web la escribe en `services/web/app/src/Features/Project/ProjectDeleter.mjs`; el esquema es `services/web/app/src/models/DeletedProject.mjs`. Cuando pasa el plazo de eliminación definitiva, la expiración destruye los datos del proyecto y vacía `project`, pero el registro con `deleterData` permanece.

Un proyecto en la papelera no está aquí: enviarlo a la papelera solo añade el usuario a `trashed` del proyecto, consulta [Colección Projects](/es/dev/data-model/projects-collection).

#### Quién escribe {#who-writes-it}

| Código | Qué hace |
| ---- | ------------ |
| `ProjectDeleter.mjs:189-293` (`deleteProject`) | Vuelca el proyecto, archiva sus docs fuera de Mongo, lo quita de las etiquetas, hace un upsert del registro y elimina el documento de `projects`. |
| `ProjectDeleter.mjs:295-342` (`undeleteProject`) | Vuelve a insertar el proyecto con el nombre `<name> (Restored)` (único para el propietario) y sin archivar, y luego elimina el registro. Falla con `project_too_old_to_restore` una vez que `project` es `null`. Se llama desde el panel de administración: restaurar un proyecto (`AdminProjectManager.mjs:497-515`) o restaurar un usuario eliminado con los proyectos eliminados junto con la cuenta (`services/web/modules/admin-tools/app/src/AdminUserManager.mjs:678-689`). |
| `ProjectDeleter.mjs:344-416` (`expireDeletedProject`) | Destruye los docs, el historial, el chat y el registro de auditoría del proyecto y dispara el hook `projectExpired`; luego pone `project` y `deleterData.deleterIpAddress` a `null`. Si el proyecto vuelve a existir, solo elimina el registro obsoleto. |
| `ProjectDeleter.mjs:97-146` (`expireDeletedProjectsAfterDuration`) | Hace expirar un lote de registros más antiguos que el plazo. Ruta `POST /internal/expire-deleted-projects-after-duration` (`services/web/app/src/router.mjs:842-846`), que el cron de la Community Edition llama cada hora en el minuto 20 cuando `ENABLE_CRON_RESOURCE_DELETION` es `true` (`server-ce/cron/delete-projects.sh:10-23`, `server-ce/config/crontab-deletion:3`). Un solo proyecto: `POST /internal/project/:projectId/expire-deleted-project` (`router.mjs:852-856`), o Purge en el panel de administración (`AdminProjectManager.mjs:517-529`). |

#### Notas {#notes}

* Los módulos que escuchan `projectExpired` eliminan sus propios datos del proyecto: `git-bridge` (`services/web/modules/git-bridge/index.mjs:37`), `github-sync` (`services/web/modules/github-sync/index.mjs:56`), `gitlab-sync` (`services/web/modules/gitlab-sync/index.mjs:46`), `gitea-sync` (`services/web/modules/gitea-sync/index.mjs:46`) y `dropbox` (`services/web/modules/dropbox/index.mjs:54`).
* Un registro expirado nunca se elimina: `deleterData` permanece para siempre, solo se vacían `project` y la dirección IP.
* Mongoose también da a `deleterData` su propio `_id`, que nada lee.
