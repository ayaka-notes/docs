`giteaSyncProjectStates` contiene un documento por cada proyecto vinculado a un repositorio de Gitea: qué repositorio y dónde se quedó la última sincronización. Pertenece al módulo web `gitea-sync` (`services/web/modules/gitea-sync`). El esquema está en `services/web/modules/gitea-sync/app/models/giteaSyncProjectStates.mjs`, y todo el acceso pasa por `services/web/modules/gitea-sync/app/src/SyncStateManager.mjs`. Los campos son los mismos que en [GitHub Sync Project States](/es/dev/data-model/github-sync-project-states-collection).

#### Campos {#fields}

| Campo | Tipo | Significado | Fuente |
| ----- | ---- | ----------- | ------ |
| `_id` | ObjectId | Lo establece Mongoose al crear. | |
| `projectId` | ObjectId | El proyecto vinculado. Obligatorio. El esquema indica `unique: true`, pero no se crea ningún índice (ver Índices). | `giteaSyncProjectStates.mjs:8` |
| `repoFullName` | String | El repositorio como `owner/name` (el `full_name` de Gitea). Obligatorio. | `giteaSyncProjectStates.mjs:9`, `GiteaApiClient.mjs:315` |
| `defaultBranchName` | String | La rama con la que se sincroniza el proyecto. Se establece al vincular el proyecto y no cambia después: al importar, la rama enviada por el formulario de importación; al exportar, la rama predeterminada del nuevo repositorio, o `main` cuando la API no da ninguna. Valor predeterminado `null`. | `giteaSyncProjectStates.mjs:10`, `GiteaSyncHandler.mjs:175-181,233-239`, `GiteaApiClient.mjs:314-317` |
| `mergeStatus` | String | `clean`, `conflict` o `diverged`. Valor predeterminado `clean`. | `giteaSyncProjectStates.mjs:11` |
| `lastSyncCommit` | String | El SHA del commit en la rama sincronizada en la última sincronización. Valor predeterminado `null`. | `giteaSyncProjectStates.mjs:12` |
| `lastSyncVersion` | Number | La versión del historial del proyecto en la última sincronización, obtenida de project-history `GET /project/:id/version` tras un flush del historial. Valor predeterminado `null`. | `giteaSyncProjectStates.mjs:13`, `services/web/modules/gitea-sync/app/src/HistoryManager.mjs:8-17` |
| `unmergedBranchName` | String | Durante un conflicto: la rama temporal con los cambios de Overleaf, llamada `overleaf-YYYY-MM-DD-HHMMSS`. `null` cuando no hay conflicto. | `giteaSyncProjectStates.mjs:14`, `GitMerge.mjs:814-818` |
| `unmergedBranchHead` | String | Durante un conflicto: el commit de cabeza de esa rama. Valor predeterminado `null`. | `giteaSyncProjectStates.mjs:15` |
| `conflictVersion` | Number | Durante un conflicto: la versión del historial del proyecto cuando se registró el conflicto. Valor predeterminado `null`. | `giteaSyncProjectStates.mjs:16` |
| `__v` | Number | La clave de versión de Mongoose. El esquema no la desactiva. | Valor predeterminado de Mongoose |

#### Quién la escribe {#who-writes-it}

| Código | Qué hace |
| ------ | -------- |
| `SyncStateManager.mjs:9-14` (`createProjectState`) | Crea el documento: tras importar un repositorio como proyecto nuevo (`services/web/modules/gitea-sync/app/src/GiteaSyncHandler.mjs:175-181`), o tras exportar un proyecto a un repositorio nuevo (`GiteaSyncHandler.mjs:233-239`, solo el propietario, rechazado si ya está vinculado). |
| `SyncStateManager.mjs:16-21` (`updateProjectState`) | `$set` de los campos modificados. `getMergeOverview` establece `mergeStatus: 'diverged'` cuando `lastSyncCommit` ya no es un ancestro de la rama sincronizada (`services/web/modules/gitea-sync/app/src/GiteaApiClient.mjs:431`), o el commit ya no existe y el usuario puede hacer push (`GiteaSyncHandler.mjs:123,126-137`). Una sincronización (`services/web/modules/gitea-sync/app/src/GitMerge.mjs`) avanza `lastSyncCommit`/`lastSyncVersion` si tiene éxito (por ejemplo `:152,189,231`), registra un conflicto con `unmergedBranchName`, `unmergedBranchHead` y `conflictVersion` (`:214-220`), y los borra una vez resuelto (`:257-264`). |
| `SyncStateManager.mjs:23-25` (`removeProjectState`) | Elimina el documento cuando el propietario desvincula el proyecto (`GiteaSyncHandler.mjs:83-97`) y cuando caduca un proyecto eliminado (`services/web/modules/gitea-sync/index.mjs:46-48`). |

#### Quién la lee {#who-reads-it}

| Código | Qué hace |
| ------ | -------- |
| `GiteaSyncHandler.mjs:39-60` (`getProjectState`) | Da al editor `mergeStatus`, `repoFullName` y `unmergedBranchName`. Sin documento responde `need-export`, un valor que nunca se almacena. |
| `GiteaSyncHandler.mjs:110-143` (`getMergeOverview`) | Compara `lastSyncCommit` y `lastSyncVersion` con Gitea y el historial del proyecto para listar los commits nuevos. |
| `GiteaSyncHandler.mjs:200` (`exportProject`) | Rechaza exportar un proyecto que ya está vinculado. |
| `GitMerge.mjs:36` (`doGitMergeWithoutLock`) | Carga el estado al inicio de una sincronización. |

#### Índices {#indexes}

| Nombre | Claves | Opciones | Migración |
| ------ | ------ | -------- | --------- |
| `_id_` | `_id: 1` | | default |

El `autoIndex` de Mongoose está desactivado (`services/web/app/src/infrastructure/Mongoose.mjs:7`), así que el `unique: true` del esquema en `projectId` no crea nada. Ninguna migración crea índices para esta colección.

#### Notas {#notes}

* La API de Gitea no puede crear commits fuera de una rama como la de GitHub. Una sincronización hace commit directamente en la rama sincronizada cuando puede avanzar, o en una rama temporal que luego se fusiona mediante una pull request (`GitMerge.mjs:16-21`).
* Una sincronización se ejecuta bajo el bloqueo `gitSync` del proyecto, compartido con GitHub Sync y GitLab Sync (`GitMerge.mjs:25-32`).
* Un proyecto eliminado conserva su documento hasta que el proyecto caduca.
* El token de Gitea del usuario está en [Gitea Sync User Credentials](/es/dev/data-model/gitea-sync-user-credentials-collection).
