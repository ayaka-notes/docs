title: Colección OAuth Authorization Codes
icon: lock-open
---

`oauthAuthorizationCodes` está pensada para los códigos del flujo OAuth de authorization code: un documento por código, que un cliente cambia por un token de acceso. El esquema es `services/web/app/src/models/OauthAuthorizationCode.mjs`, y el módulo web `oauth2-server` tiene el código que escribiría en ella. En Ayakaleaf Pro nada llega a ese código, así que la colección queda vacía (ver Notas).

#### Campos {#fields}

| Campo | Tipo | Significado | Origen |
| ----- | ---- | ------- | ------ |
| `_id` | ObjectId | Id del documento. | `OauthAuthorizationCode.mjs:6` |
| `authorizationCode` | String | El código en sí, guardado tal cual (sin hash). | `OauthAuthorizationCode.mjs:8`, `services/web/modules/oauth2-server/app/src/OAuth2Model.mjs:280` |
| `expiresAt` | Date | Fin de la validez. `getAuthorizationCode` rechaza un código después de esta fecha, y el índice TTL lo borra. | `OauthAuthorizationCode.mjs:9`, `OAuth2Model.mjs:150-153,281` |
| `oauthApplication_id` | ObjectId | Cliente de [OAuth Applications](/es/dev/data-model/oauth-applications-collection) que pidió el código. | `OauthAuthorizationCode.mjs:10`, `OAuth2Model.mjs:275-284` |
| `redirectUri` | String | URI de redirección de la solicitud. | `OauthAuthorizationCode.mjs:11`, `OAuth2Model.mjs:282` |
| `scope` | String | Scope solicitado. | `OauthAuthorizationCode.mjs:12`, `OAuth2Model.mjs:283` |
| `user_id` | ObjectId | Usuario que concedió el código. | `OauthAuthorizationCode.mjs:13`, `OAuth2Model.mjs:285` |
| `codeChallenge`, `codeChallengeMethod` | String | Challenge PKCE y su método. | `OauthAuthorizationCode.mjs:14-15`, `OAuth2Model.mjs:286-287` |

#### Quién escribe {#who-writes-it}

| Código | Qué hace |
| ---- | ------------ |
| `OAuth2Model.mjs:274-300` (`saveAuthorizationCode`) | Inserta un código. No se alcanza, ver Notas. |
| `OAuth2Model.mjs:307-312` (`revokeAuthorizationCode`) | Borra un código una vez usado. No se alcanza. |

#### Quién lee {#who-reads-it}

| Código | Qué hace |
| ---- | ------------ |
| `OAuth2Model.mjs:137-177` (`getAuthorizationCode`) | Carga un código con su usuario y su cliente. No se alcanza. |

#### Índices {#indexes}

| Nombre | Claves | Opciones | Migración |
| ---- | ---- | ------- | --------- |
| `expiresAt_1` | `{ expiresAt: 1 }` | TTL, `expireAfterSeconds: 0`, parcial: `expiresAt` existe | `20230406125632_oauth_tokens_ttl.mjs` |

Las migraciones están en `tools/migrations/`. El índice único `authorizationCode_1` solo procede de migraciones etiquetadas `saas` y `server-pro`, que Community Edition no ejecuta.

#### Notas {#notes}

* Los métodos del modelo anteriores solo los llaman los handlers authorize y token de `@node-oauth/oauth2-server`. Web usa esa biblioteca solo para comprobar tokens bearer (`services/web/app/src/Features/Authentication/AuthenticationController.mjs:409-450`), y ninguna ruta sirve `/oauth/authorize` ni `/oauth/token`, así que nunca se escribe ningún código. Los tokens de acceso personal se crean directamente, ver [OAuth Access Tokens](/es/dev/data-model/oauth-access-tokens-collection).
