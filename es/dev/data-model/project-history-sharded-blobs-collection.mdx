---
title: Colección Project History Sharded Blobs
icon: cubes-stacked
---

`projectHistoryShardedBlobs` guarda los registros de blobs que no cupieron en [projectHistoryBlobs](/dev/data-model/project-history-blobs-collection): cuando el cubo de un prefijo de hash ya tiene 8 registros allí, los siguientes van aquí. Un proyecto tiene como máximo 16 documentos en ella, uno por primer dígito hexadecimal del hash. No hay esquema de Mongoose; history-v1 la escribe en `services/history-v1/storage/lib/blob_store/mongo.js` (estructura descrita en `mongo.js:1-16`).

#### Campos {#fields}

| Campo | Tipo | Significado | Origen |
| ----- | ---- | ------- | ------ |
| `_id` | Binary | 13 bytes: el id de historial del proyecto, un `0`, y el dígito de shard, leído como hexadecimal (`<history id>0<digit>`). El dígito de shard es el primer dígito hexadecimal del hash. | `mongo.js:439-453` |
| `blobs` | Object | Registros de blobs agrupados en cubos. La clave de un cubo son los dígitos hexadecimales 2 a 4 del hash. | `mongo.js:439-443` |
| `blobs.<bcd>` | Array of Object | Los registros del cubo. El código no limita su tamaño. | `mongo.js:399-407` |
| `blobs.<bcd>[].h` | Binary | El hash, 20 bytes, como en projectHistoryBlobs. | `mongo.js:472` |
| `blobs.<bcd>[].b` | Number | Longitud del contenido en bytes. | `mongo.js:473` |
| `blobs.<bcd>[].s` | Number | Longitud del contenido como texto; `null` cuando el contenido no es texto editable. | `mongo.js:474` |

#### Quién la escribe {#who-writes-it}

| Código | Qué hace |
| ---- | ------------ |
| `services/history-v1/storage/lib/blob_store/mongo.js:399-407` | `insertRecordSharded`: upsert con `$addToSet` en el cubo. Lo llama `insertBlob` cuando el cubo en projectHistoryBlobs está lleno (`mongo.js:387-389`). |
| `mongo.js:75-103` | `clone`: copia los shards del proyecto a otro id de historial, para history-v1 `POST /projects/:project_id/clone`, a la que nada en web llama. |
| `mongo.js:413-422` | `deleteBlobs`: elimina todos los shards del proyecto junto con su documento de projectHistoryBlobs, en history-v1 `DELETE /projects/:project_id`. |

#### Quién la lee {#who-reads-it}

| Código | Qué hace |
| ---- | ------------ |
| `mongo.js:144-157` | `findBlobSharded`: un blob, buscado solo cuando su cubo en projectHistoryBlobs tiene 8 registros y no lo contiene (`mongo.js:127-131`). |
| `mongo.js:217-260` | `findBlobsSharded`: los blobs que `findBlobs` no encontró en projectHistoryBlobs (`mongo.js:202-206`). |
| `mongo.js:285-306` | `getProjectBlobs`: todos los shards de un proyecto. |
| `mongo.js:337-361` | `getProjectBlobsBatch`: todos los shards de varios proyectos, para la ruta de estadísticas de blobs. |

#### Índices {#indexes}

Solo el índice predeterminado `_id`. Ninguna migración de `tools/migrations/` añade uno.

#### Notas {#notes}

* Los shards de un proyecto están uno junto al otro en el orden de `_id`, así que el código los encuentra con un rango de `_id` de `<history id>00` a `<history id>0f` (`mongo.js:75-80`, `287-295`).
* La colección solo aparece cuando algún proyecto tiene más de 8 blobs con el mismo prefijo de hash de 3 dígitos, así que una instancia pequeña puede no tenerla en absoluto.
