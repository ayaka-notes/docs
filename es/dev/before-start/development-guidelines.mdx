### Introducción

Antes de sumergirte en el desarrollo, esperamos que comprendas lo siguiente:

* Overleaf se desarrolla oficialmente en un [repositorio interno](http://github.com/overleaf/internal), y la edición Community se publica en [overleaf/overleaf](https://github.com/overleaf/overleaf). Un copybot se encarga de sincronizar el código entre el repositorio interno y el público.
* [Ayaka-notes/overleaf-pro](https://github.com/ayaka-notes/overleaf-pro) es una versión bifurcada (fork) de Overleaf Community. Queremos que este proyecto perdure a largo plazo, así que sigue estas reglas antes de contribuir.

### Reglas de commits

* No realices modificaciones extensas en el código existente de Overleaf. Concentra la mayor funcionalidad posible en la carpeta `services/web/modules`. Así minimizaremos el trabajo al fusionar y actualizar el código más adelante.
* El "vibe coding" es sin duda una vía muy cómoda, pero puede desordenar fácilmente el proyecto y hacerlo inmantenible en el futuro, así que úsalo con precaución.
* No añadas contenido relacionado con traducciones durante el desarrollo; utiliza las traducciones existentes siempre que sea posible.
* Evita introducir variables de entorno salvo que sea absolutamente necesario. Si son imprescindibles, asegúrate de que sean lo más coherentes posible con las del Overleaf Toolkit o de [docs.overleaf.com](https://docs.overleaf.com/).

### Reglas de ramas

Usamos las siguientes ramas para el desarrollo de overleaf-pro:

* `main`: esta rama se usa únicamente para sincronizar el código de upstream; **NO** hagas commit de ningún cambio externo. En esta rama creamos etiquetas como `ce-v[X.x.x]`, que indican que corresponde a la `v[X.x.x]` de la edición Community oficial de Overleaf. Nota: ¡esta etiqueta es inmutable!
* `server-pro`: esta es la rama predeterminada para el desarrollo diario.
* `feature-X`: esta rama se usa para desarrollar una funcionalidad concreta.
* `release-vX.0.0`: rama específica para una versión; en ella aplicamos algunas correcciones urgentes (hot-fix) antes del lanzamiento.

### GitHub Action

[GitHub Action](https://github.com/ayaka-notes/overleaf-pro/actions) se encarga del CI/CD automático, que incluye:

* Actualización nocturna de la rama main
* Compilación de la imagen de Docker para desarrollo
* Publicación de la imagen de Docker

### Preguntas y respuestas

<Accordion title="¿Cómo encontrar el hash de commit de Overleaf Community Edition `X.0.0`?">

En primer lugar, debes descargar la imagen de Docker y ejecutar el siguiente comando para inspeccionar las etiquetas (labels) de esa imagen:

```shellscript title="bash" wrap
docker inspect --format='{{json .Config.Labels}}' sharelatex/sharelatex:6.0.0
{"com.overleaf.ce.revision":"b0d05c0cf0750714e1f467d20ed6c5f5e9467e8f","org.opencontainers.image.ref.name":"ubuntu","org.opencontainers.image.version":"24.04"}
```

Después puedes comprobar si el [commit (b0d05c0)](https://github.com/overleaf/overleaf/commit/b0d05c0cf0750714e1f467d20ed6c5f5e9467e8f) está presente en la rama master de upstream.

</Accordion>

<Accordion title="¿Por qué el hash de commit es el mismo en la imagen CE entre `6.0.0` y `6.0.1`?">

Es el comportamiento esperado. La versión 6.0.1 es una versión de parche menor construida sobre la imagen 6.0.0. Los cambios se aplican parcheando la imagen 6.0.0 existente, en lugar de reconstruir la imagen a partir de un commit nuevo. Por lo tanto, el hash de commit dentro de la imagen es idéntico entre 6.0.0 y 6.0.1.

Para obtener información detallada, consulta [hotfix](https://github.com/overleaf/overleaf/tree/main/server-ce/hotfix).

</Accordion>
