## Anbefalte utviklingsverktøy {#develop-tools-recommended}

Disse valgfrie tjenestene trengs ikke for å kjøre Overleaf, men de hjelper mye ved utvikling, feilsøking og undersøkelse av dataene. Alle er en del av utviklingsmiljøet, så det er ingenting å legge til i `docker-compose.yml`. Når du er logget inn på nettstedet, lenker menyen **Dev tools** i navigasjonslinjen til de verktøyene nettstedet serverer på egne stier.

| Verktøy | Adresse | Definert i |
| --- | --- | --- |
| **Grafana**, tilstand, målinger og logger for hver tjeneste | [http://localhost/grafana/](http://localhost/grafana/) | `develop/grafana/docker-compose.yml`, på når `GRAFANA_ENABLED=true` i `develop/dev.rc` (standard) |
| **Mailpit**, en innboks for hver e-post nettstedet sender | [http://localhost/mailpit/](http://localhost/mailpit/) | `develop/mail/docker-compose.yml`, på når `MAILPIT_ENABLED=true` (standard) |
| **Mongo Express**, et grensesnitt for MongoDB | [http://localhost/mongo-express/](http://localhost/mongo-express/) | `develop/docker-compose.yml`, alltid på |
| **RedisInsight**, et grensesnitt for Redis-dataene | [http://localhost/redis-insight/](http://localhost/redis-insight/) | `develop/docker-compose.yml`, alltid på |
| **Hoppscotch**, en nettleserbasert API-klient som ligner på Postman | [http://localhost:9170](http://localhost:9170/) (`HOPPSCOTCH_PORT`) | `develop/hoppscotch/docker-compose.yml`, på når `HOPPSCOTCH_ENABLED=true` (standard) |

<Warning>

Ingen av disse verktøyene har innlogging: Grafanas anonyme brukere er administratorene, og Mongo Express kan endre ethvert dokument. Nettstedet, Hoppscotch, Mongo Express (8081) og RedisInsight (5540) lytter bare på vertens `127.0.0.1`, så andre verter kan ikke nå dem.

</Warning>

### Grafana {#grafana}

Grafana serveres av nettstedet på `/grafana/` via webpack-dev-server, og trenger derfor ingen egen port. Mappen **Overleaf Develop** har disse dashbordene:

| Dashbord | Hva det viser |
| --- | --- |
| All services (start) | Tilstand for hver tjeneste, vertsmålere, last og logger. Et klikk på en tjeneste åpner dashbordet for den |
| Server | CPU, last, minne, disk og nettverk for verten, og kompileringene til clsi |
| Errors | Feillogger, 5xx- og 4xx-svar, de vanligste feilmeldingene og ruter som feiler |
| Data flow | Veien til en endring: document-updater og Redis, project-history, history-v1, Mongo, objektlagring |
| Containers | Tilstand for hver container, CPU, minne, nettverk og disk, inkludert sandkassekompileringer |
| Ett per tjeneste | Node.js-tjenestene, git-bridge (JVM), mongo og redis |

Prometheus henter `/metrics` fra tjenestene, `mongodb-exporter`, `redis-exporter`, `cadvisor` og `node-exporter`; Alloy sender loggene fra hver container i prosjektet til Loki, der dashbordenes filtre **Log search**, **Service** og **Log level** leser dem. Dataene ligger bare i containerne, så de tømmes når containerne gjenopprettes. cAdvisor kjører privilegert og leser vertens `/`, `/sys`, Docker-data og containerd-socketen, skrivebeskyttet; node-exporter leser vertens `/`.

Dashbordene genereres: endre `develop/grafana/make-dashboards` og kjør det, i stedet for å redigere JSON-filene.

### Mailpit {#mailpit}

Med `MAILPIT_ENABLED=true` sender `web` all e-post til Mailpit i stedet for til en ekte e-postserver, og e-postbekreftelse er på (`EMAIL_CONFIRMATION_DISABLED=false`). Aktiveringslenker, prosjektinvitasjoner, tilbakestilling av passord og bekreftelseskoder kan da følges fra innboksen.

### Sette opp Hoppscotch {#setup-hoppscotch}

#### API-forespørsler via proxy {#proxy-api-request}

Hoppscotch sender forespørsler fra nettleseren, som ikke kan nå tjenestene via Docker-navnene deres. Proxyen, Proxyscotch, kjører i Docker-nettverket og serveres på `/proxy` på Hoppscotch-adressen. Åpne [http://localhost:9170](http://localhost:9170/), gå til Settings → Interceptor, velg **Proxy** og sett Proxy URL til `http://localhost:9170/proxy`. Innstillingen lagres i nettleseren.

#### Importer tjeneste-API-ene {#import-the-service-apis}

`develop/hoppscotch/openapi/` har en OpenAPI-fil for det interne API-et til hver tjeneste. Åpne Collections → Import → Import from File i Hoppscotch og velg alle filene samtidig. Hver fil blir en samling der forespørslene går til tjenestens Docker-adresse. De samme filene vises i delen [Tjeneste-API](/no/dev/service-api/overview).

#### CSRF-problemer {#csrf-problems}

<Warning>

Hvis du bruker Postman eller andre feilsøkingsverktøy til å sende en **POST**-forespørsel, kan du oppleve at innloggingen blir **avvist**, og årsaken er 403-feilen. Det skyldes at Overleaf er beskyttet av **CSRF**-verifisering.

</Warning>

<Frame>
  <img src="/images/dev/image-8.png" alt="" />
</Frame>

I konsollen kan du se:

<Frame>
  <img src="/images/dev/image-9.png" alt="" />
</Frame>

For å håndtere dette i Overleaf-utviklingen må du sette opp CSRF-tokenet ditt. Her er en detaljert veiledning.

<Steps>
<Step title="Legg til Pre-Request">
Legg til følgende kode i Pre-Request

<Frame>
  <img src="/images/dev/image-10.png" alt="" />
</Frame>

Skriptet er som følger:

```js wrap
pm.sendRequest("http://web:3000/dev/csrf", function (err, res) {
    if (err) {
        console.log(err);
        return;
    }

    // 1) Save CSRF token (/dev/csrf)
    const token = res.text().trim();
    pw.env.set("csrftoken", token);
    console.log("csrftoken =", token);

    const setCookieHeader = (res.headers || []).find(h => h.key?.toLowerCase() === "set-cookie")?.value;
    console.log("set-cookie =", setCookieHeader);

    if (!setCookieHeader) return;

    const cookiePair = setCookieHeader.split(";")[0].trim(); // overleaf.sid=...
    pw.env.set("cookie_header", cookiePair);
    console.log("cookie_header =", cookiePair);
});
```
</Step>

<Step title="Legg til forespørselsheadere">
Du må legge til følgende headere:

| Headernavn   | Headerverdi         |
| ------------ | ------------------- |
| Content-Type | `application/json`  |
| X-Csrf-Token | `<<csrftoken>>`     |
| Cookie       | `<<cookie_header>>` |

<Frame>
  <img src="/images/dev/image-11.png" alt="" />
</Frame>
</Step>

<Step title="Logg inn med API-verktøy">
Nå kan du logge inn med brukernavn og passord.

```json5
{
  "_csrf": "<<csrftoken>>",
  "email": "admin@overleaf.com",
  "password": "xxxxxx"
}
```

Her er svaret når du skriver inn feil brukernavn eller passord.
