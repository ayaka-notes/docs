## Anbefalte utviklingsverktøy

Disse valgfrie tjenestene er ikke nødvendige for å kjøre Overleaf, men de anbefales sterkt for utvikling, feilsøking og inspeksjon under lokal utvikling.

* **Hoppscotch** er et lett verktøy for API-testing, likt Postman, men nettleserbasert og svært praktisk under utvikling.
  * Frontend: [http://localhost:3000](http://localhost:3000/)
  * Proxy (for å omgå CORS): [http://localhost:9159](http://localhost:9159/)
* **RedisInsight** gir et visuelt grensesnitt for å inspisere Redis-data. Grensesnittet er tilgjengelig på: [http://localhost:5540](http://localhost:5540/)
* **Mongo Express** er et nettbasert grensesnitt for MongoDB. Du kan besøke [http://localhost:8081](http://localhost:8081/) med **påloggingsinformasjonen**: `admin:pass`

Legg til følgende i `docker-compose.yml`:

<Accordion title="develop/docker-compose.yml">

```yml title="develop/docker-compose.yml"
# services: 
  # Overleaf Dev Containers
  # ...
  
  # Add those for your development
  # API debug
  hoppscotch-frontend:
    image: hoppscotch/hoppscotch-frontend:latest
    ports:
      - "3000:3000"

  hoppscotch-proxy:
    image: hoppscotch/proxyscotch:latest
    environment:
      - PORT=9159
    ports:
      - "9159:9159"

  # Redis-insight
  redis-insight:
    image: redislabs/redisinsight:latest
    ports:
      - "5540:5540"
    depends_on:
      - redis
    volumes:
      - ./data/redis-insight:/data

  # mongo-express
  # basicAuth credentials are "admin:pass"
  mongo-express:
    image: mongo-express
    ports:
      - "8081:8081"
    environment:
      ME_CONFIG_MONGODB_SERVER: mongo
```

</Accordion>

### Sette opp Hoppscotch

#### API-forespørsler via proxy

For å sette opp Hoppscotch kan du besøke [http://localhost:3000](http://localhost:3000/) og deretter gå til fanen for innstillinger. Du må sette `Proxy` til [http://localhost:9159](http://localhost:9159/), slik at feilsøkingsverktøyene dine kan samhandle med containerens interne nettverk.

#### CSRF-problemer

<Warning>

Hvis du bruker Postman eller andre feilsøkingsverktøy til å sende en **POST**-forespørsel, kan du oppleve at innloggingen blir **avvist**, og årsaken er 401-feilen. Det skyldes at Overleaf er beskyttet av **CSRF**-verifisering.

</Warning>

<Frame>
  <img src="/images/dev/image-9.png" alt="" />
</Frame>

For å håndtere dette i Overleaf-utviklingen må du sette opp CSRF-tokenet ditt. Her er en detaljert veiledning.

<Steps>
<Step title="Legg til Pre-Request">
Legg til følgende kode i Pre-Request

<Frame>
  <img src="/images/dev/image-11.png" alt="" />
</Frame>

Skriptet er som følger:

```js wrap
pm.sendRequest("http://web:3000/dev/csrf", function (err, res) {
    if (err) {
        console.log(err);
        return;
    }

    // 1) Save CSRF token (/dev/csrf)
    const token = res.text().trim();
    pw.env.set("csrftoken", token);
    console.log("csrftoken =", token);

    const setCookieHeader = (res.headers || []).find(h => h.key?.toLowerCase() === "set-cookie")?.value;
    console.log("set-cookie =", setCookieHeader);

    if (!setCookieHeader) return;

    const cookiePair = setCookieHeader.split(";")[0].trim(); // overleaf.sid=...
    pw.env.set("cookie_header", cookiePair);
    console.log("cookie_header =", cookiePair);
});
```
</Step>

<Step title="Legg til forespørselsheadere">
Du må legge til følgende headere:

| Headernavn   | Headerverdi         |
| ------------ | ------------------- |
| Content-Type | `application/json`  |
| X-Csrf-Token | `<<csrftoken>>`     |
| Cookie       | `<<cookie_header>>` |

<Frame>
  <img src="/images/dev/image-12.png" alt="" />
</Frame>
</Step>

<Step title="Logg inn med API-verktøy">
Nå kan du logge inn med brukernavn og passord.

```json5
{
  "_csrf": "<<csrftoken>>",
  "email": "admin@overleaf.com",
  "password": "xxxxxx"
}
```

Her er svaret når du skriver inn feil brukernavn eller passord.
