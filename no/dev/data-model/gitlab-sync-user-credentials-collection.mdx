---
title: GitLab Sync User Credentials-samlingen
icon: user-lock
---

`gitlabSyncUserCredentials` inneholder ett dokument per bruker som har koblet en GitLab-konto for GitLab Sync. Den lagrer brukerens OAuth-tokener, kryptert. Samlingen hører til webmodulen `gitlab-sync` (`services/web/modules/gitlab-sync`). Skjemaet ligger i `services/web/modules/gitlab-sync/app/models/gitlabSyncUserCredentials.mjs`, og all tilgang går gjennom `services/web/modules/gitlab-sync/app/src/TokenManager.mjs`.

#### Felter {#fields}

| Felt | Type | Betydning | Kilde |
| ----- | ---- | ------- | ------ |
| `_id` | ObjectId | Settes av Mongoose når upserten setter inn. | |
| `userId` | ObjectId | Overleaf-brukeren. Påkrevd. Skjemaet sier `unique: true`, men ingen indeks bygges (se Indekser); upserten på `userId` holder ett dokument per bruker. | `gitlabSyncUserCredentials.mjs:8`, `TokenManager.mjs:88-95` |
| `gitlab` | String | JSON-verdien `{ accessToken, refreshToken, expiresAt }`, kryptert med `@overleaf/access-token-encryptor`. `expiresAt` er i millisekunder siden epoken, eller `null`; `refreshToken` kan være `null`. Passordet kommer fra `GITLAB_TOKEN_CIPHER_PASSWORD`; chifferetiketten er `GITLAB_TOKEN_CIPHER_LABEL`, standard `2026.10-v3`. Påkrevd. | `gitlabSyncUserCredentials.mjs:9-10`, `TokenManager.mjs:18-31`, `services/web/modules/gitlab-sync/app/src/GitLabApiClient.mjs:209-220` |
| `__v` | Number | Mongoose sin versjonsnøkkel. Skjemaet slår den ikke av. | Mongoose-standard |

#### Hvem skriver {#who-writes-it}

| Kode | Hva den gjør |
| ---- | ------------ |
| `TokenManager.mjs:88-95` (`saveUserToken`) | Gjør upsert av brukerens krypterte påloggingsinformasjon. |
| `TokenManager.mjs:99-108` (`linkUserToken`) | Lagrer ny påloggingsinformasjon fra OAuth-callbacken (`services/web/modules/gitlab-sync/app/src/GitLabSyncController.mjs:146`). Når brukeren kobler på nytt, tilbakekalles det erstattede tilgangstokenet hos GitLab i bakgrunnen. |
| `TokenManager.mjs:53-78` (`refreshUserToken`) | Når tilgangstokenet har mindre enn 5 minutter igjen til `expiresAt` (`:13,47-49`), henter den nye tokener med oppdateringstokenet og lagrer dem (`:75`). Den kjører under låsen `gitlabSyncToken` per bruker (`:15,54`), fordi GitLab bruker opp et oppdateringstoken når det brukes. |
| `TokenManager.mjs:111-126` (`removeUserToken`) | Tilbakekaller tilgangstokenet hos GitLab (så langt det går), og sletter deretter dokumentet. Kalles ved frakobling (`GitLabSyncController.mjs:173`) og når en slettet bruker utløper (`services/web/modules/gitlab-sync/index.mjs:56-58`). |

#### Hvem leser {#who-reads-it}

| Kode | Hva den gjør |
| ---- | ------------ |
| `TokenManager.mjs:41-45,81-85` (`getUserCredentials`, `getUserToken`) | Dekrypterer påloggingsinformasjonen for hvert kall til GitLab sitt API, og fornyer den først når tokenet snart utløper: `services/web/modules/gitlab-sync/app/src/GitLabSyncHandler.mjs` (for eksempel `:27`) og `services/web/modules/gitlab-sync/app/src/GitMerge.mjs:52`. Uten dokument, eller med påloggingsinformasjon som ikke kan dekrypteres eller fornyes, kaster den `InvalidTokenError`, og brukeren regnes som ikke koblet (`GitLabSyncHandler.mjs:25-37`). |
| `services/web/modules/admin-tools/app/src/AdminUserListManager.mjs:394` | Sjekker om brukeren har et dokument, for integrasjonene som vises i adminpanelet. |

#### Indekser {#indexes}

| Navn | Nøkler | Alternativer | Migrering |
| ---- | ---- | ------- | --------- |
| `_id_` | `_id: 1` | | default |

Mongoose `autoIndex` er slått av (`services/web/app/src/infrastructure/Mongoose.mjs:7`), så skjemaets `unique: true` på `userId` oppretter ingenting. Ingen migrering oppretter indekser for denne samlingen.

#### Merknader {#notes}

* Å endre `GITLAB_TOKEN_CIPHER_PASSWORD` gjør den lagrede påloggingsinformasjonen uleselig. Disse brukerne regnes da som ikke koblet til de kobler på nytt.
* En slettet bruker beholder dokumentet til brukeren utløper.
