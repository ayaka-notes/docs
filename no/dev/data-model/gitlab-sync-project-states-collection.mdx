`gitlabSyncProjectStates` inneholder ett dokument per prosjekt som er koblet til et GitLab-prosjekt: hvilket repository, og hvor den siste synkroniseringen stoppet. Samlingen hører til webmodulen `gitlab-sync` (`services/web/modules/gitlab-sync`). Skjemaet ligger i `services/web/modules/gitlab-sync/app/models/gitlabSyncProjectStates.mjs`, og all tilgang går gjennom `services/web/modules/gitlab-sync/app/src/SyncStateManager.mjs`. Feltene er de samme som i [GitHub Sync Project States](/no/dev/data-model/github-sync-project-states-collection).

| Felt | Type | Betydning | Kilde |
| ----- | ---- | ------- | ------ |
| `_id` | ObjectId | Settes av Mongoose ved opprettelse. | |

| `repoFullName` | String | GitLab-prosjektets sti med navnerom (GitLab sitt `path_with_namespace`), for eksempel `group/subgroup/name`. Påkrevd. | `gitlabSyncProjectStates.mjs:9`, `GitLabApiClient.mjs:347` |
| `defaultBranchName` | String | Grenen prosjektet synkroniseres med. Settes når prosjektet kobles og endres ikke senere: ved import grenen som importskjemaet sender; ved eksport standardgrenen til det nye repositoryet, eller `main` når API-et ikke oppgir noen. Standard `null`. | `gitlabSyncProjectStates.mjs:10`, `GitLabSyncHandler.mjs:175-181,234-240`, `GitLabApiClient.mjs:346-349` |
| `mergeStatus` | String | `clean`, `conflict` eller `diverged`. Standard `clean`. | `gitlabSyncProjectStates.mjs:11` |

#### Hvem skriver {#who-writes-it}

| Kode | Hva den gjør |
| ---- | ------------ |
| `SyncStateManager.mjs:9-14` (`createProjectState`) | Oppretter dokumentet: etter at et repository er importert som et nytt prosjekt (`services/web/modules/gitlab-sync/app/src/GitLabSyncHandler.mjs:175-181`), eller etter at et prosjekt er eksportert til et nytt repository (`GitLabSyncHandler.mjs:234-240`, kun eier, avvist hvis det allerede er koblet). |
| `SyncStateManager.mjs:16-21` (`updateProjectState`) | `$set` av de endrede feltene. `getMergeOverview` setter `mergeStatus: 'diverged'` når den synkroniserte grenen ikke lenger inneholder `lastSyncCommit` (merge base-sjekk, `services/web/modules/gitlab-sync/app/src/GitLabApiClient.mjs:460`), eller når commiten er borte og brukeren kan pushe (`GitLabSyncHandler.mjs:123,126-137`). En synkronisering (`services/web/modules/gitlab-sync/app/src/GitMerge.mjs`) flytter `lastSyncCommit`/`lastSyncVersion` når den lykkes (for eksempel `:152,189,231`), registrerer en konflikt med `unmergedBranchName`, `unmergedBranchHead` og `conflictVersion` (`:214-220`), og tømmer dem når konflikten er løst (`:257-264`). |
| `SyncStateManager.mjs:23-25` (`removeProjectState`) | Sletter dokumentet når eieren kobler fra prosjektet (`GitLabSyncHandler.mjs:83-97`) og når et slettet prosjekt utløper (`services/web/modules/gitlab-sync/index.mjs:46-48`). |

#### Hvem leser {#who-reads-it}

| Kode | Hva den gjør |
| ---- | ------------ |
| `GitLabSyncHandler.mjs:39-60` (`getProjectState`) | Gir editoren `mergeStatus`, `repoFullName` og `unmergedBranchName`. Uten dokument svarer den `need-export`, en verdi som aldri lagres. |
| `GitLabSyncHandler.mjs:110-143` (`getMergeOverview`) | Sammenligner `lastSyncCommit` og `lastSyncVersion` med GitLab og prosjekthistorikken for å liste de nye commitene. |
| `GitLabSyncHandler.mjs:200` (`exportProject`) | Nekter å eksportere et prosjekt som allerede er koblet. |
| `GitMerge.mjs:36` (`doGitMergeWithoutLock`) | Laster inn tilstanden i starten av en synkronisering. |

#### Indekser {#indexes}

| Navn | Nøkler | Alternativer | Migrering |
| ---- | ---- | ------- | --------- |
| `_id_` | `_id: 1` | | default |

Mongoose `autoIndex` er slått av (`services/web/app/src/infrastructure/Mongoose.mjs:7`), så skjemaets `unique: true` på `projectId` oppretter ingenting. Ingen migrering oppretter indekser for denne samlingen.

#### Merknader {#notes}

* GitLab sitt API kan ikke flytte en gren til hvilken som helst commit slik GitHub sitt kan. En synkronisering committer rett på den synkroniserte grenen når den kan gå fremover, ellers på en midlertidig gren som så flettes via en merge request (`GitMerge.mjs:16-21`).
* En synkronisering kjører under prosjektets `gitSync`-lås, som deles med GitHub Sync og Gitea Sync (`GitMerge.mjs:25-32`).
* Et slettet prosjekt beholder dokumentet sitt til prosjektet utløper.
* Brukerens GitLab-token ligger i [GitLab Sync User Credentials](/no/dev/data-model/gitlab-sync-user-credentials-collection).
