---
title: Gitea Sync User Credentials-samlingen
icon: lock
---

`giteaSyncUserCredentials` inneholder ett dokument per bruker som har koblet en Gitea-konto for Gitea Sync. Den lagrer brukerens OAuth-tokener, kryptert. Samlingen hører til webmodulen `gitea-sync` (`services/web/modules/gitea-sync`). Skjemaet ligger i `services/web/modules/gitea-sync/app/models/giteaSyncUserCredentials.mjs`, og all tilgang går gjennom `services/web/modules/gitea-sync/app/src/TokenManager.mjs`.

#### Felter {#fields}

| Felt | Type | Betydning | Kilde |
| ----- | ---- | ------- | ------ |
| `_id` | ObjectId | Settes av Mongoose når upserten setter inn. | |
| `userId` | ObjectId | Overleaf-brukeren. Påkrevd. Skjemaet sier `unique: true`, men ingen indeks bygges (se Indekser); upserten på `userId` holder ett dokument per bruker. | `giteaSyncUserCredentials.mjs:8`, `TokenManager.mjs:89-96` |
| `gitea` | String | JSON-verdien `{ accessToken, refreshToken, expiresAt }`, kryptert med `@overleaf/access-token-encryptor`. `expiresAt` er i millisekunder siden epoken, eller `null`; `refreshToken` kan være `null`. Passordet kommer fra `GITEA_TOKEN_CIPHER_PASSWORD`; chifferetiketten er `GITEA_TOKEN_CIPHER_LABEL`, standard `2026.10-v3`. Påkrevd. | `giteaSyncUserCredentials.mjs:9-10`, `TokenManager.mjs:17-30`, `services/web/modules/gitea-sync/app/src/GiteaApiClient.mjs:198-209` |
| `__v` | Number | Mongoose sin versjonsnøkkel. Skjemaet slår den ikke av. | Mongoose-standard |

#### Hvem skriver {#who-writes-it}

| Kode | Hva den gjør |
| ---- | ------------ |
| `TokenManager.mjs:89-96` (`saveUserToken`) | Gjør upsert av brukerens krypterte påloggingsinformasjon. Kalles fra OAuth-callbacken (`services/web/modules/gitea-sync/app/src/GiteaSyncController.mjs:146`). I motsetning til GitLab Sync tilbakekaller ikke en ny kobling det erstattede tokenet. |
| `TokenManager.mjs:53-79` (`refreshUserToken`) | Når tilgangstokenet har mindre enn 5 minutter igjen til `expiresAt` (`:12`), henter den nye tokener med oppdateringstokenet og lagrer dem (`:76`). Den kjører under låsen `giteaSyncToken` per bruker (`:14,54`), fordi Gitea erstatter oppdateringstokenet når det brukes. |
| `TokenManager.mjs:100-102` (`removeUserToken`) | Sletter dokumentet. Gitea har ikke noe API for å tilbakekalle et OAuth-token, så brukeren tilbakekaller tillatelsen i Gitea (`:98-99`). Kalles ved frakobling (`GiteaSyncController.mjs:173`) og når en slettet bruker utløper (`services/web/modules/gitea-sync/index.mjs:56-58`). |

#### Hvem leser {#who-reads-it}

| Kode | Hva den gjør |
| ---- | ------------ |
| `TokenManager.mjs:40-44,82-86` (`getUserCredentials`, `getUserToken`) | Dekrypterer påloggingsinformasjonen for hvert kall til Gitea sitt API, og fornyer den først når tokenet snart utløper: `services/web/modules/gitea-sync/app/src/GiteaSyncHandler.mjs` (for eksempel `:27`) og `services/web/modules/gitea-sync/app/src/GitMerge.mjs:52`. Uten dokument, eller med påloggingsinformasjon som ikke kan dekrypteres eller fornyes, kaster den `InvalidTokenError`, og brukeren regnes som ikke koblet (`GiteaSyncHandler.mjs:25-37`). |
| `services/web/modules/admin-tools/app/src/AdminUserListManager.mjs:395` | Sjekker om brukeren har et dokument, for integrasjonene som vises i adminpanelet. |

#### Indekser {#indexes}

| Navn | Nøkler | Alternativer | Migrering |
| ---- | ---- | ------- | --------- |
| `_id_` | `_id: 1` | | default |

Mongoose `autoIndex` er slått av (`services/web/app/src/infrastructure/Mongoose.mjs:7`), så skjemaets `unique: true` på `userId` oppretter ingenting. Ingen migrering oppretter indekser for denne samlingen.

#### Merknader {#notes}

* Å endre `GITEA_TOKEN_CIPHER_PASSWORD` gjør den lagrede påloggingsinformasjonen uleselig. Disse brukerne regnes da som ikke koblet til de kobler på nytt.
* En slettet bruker beholder dokumentet til brukeren utløper.
