`giteaSyncProjectStates` inneholder ett dokument per prosjekt som er koblet til et Gitea-repository: hvilket repository, og hvor den siste synkroniseringen stoppet. Samlingen hører til webmodulen `gitea-sync` (`services/web/modules/gitea-sync`). Skjemaet ligger i `services/web/modules/gitea-sync/app/models/giteaSyncProjectStates.mjs`, og all tilgang går gjennom `services/web/modules/gitea-sync/app/src/SyncStateManager.mjs`. Feltene er de samme som i [GitHub Sync Project States](/no/dev/data-model/github-sync-project-states-collection).

#### Hvem skriver {#who-writes-it}

| Kode | Hva den gjør |
| ---- | ------------ |
| `SyncStateManager.mjs:9-14` (`createProjectState`) | Oppretter dokumentet: etter at et repository er importert som et nytt prosjekt (`services/web/modules/gitea-sync/app/src/GiteaSyncHandler.mjs:175-181`), eller etter at et prosjekt er eksportert til et nytt repository (`GiteaSyncHandler.mjs:233-239`, kun eier, avvist hvis det allerede er koblet). |
| `SyncStateManager.mjs:16-21` (`updateProjectState`) | `$set` av de endrede feltene. `getMergeOverview` setter `mergeStatus: 'diverged'` når `lastSyncCommit` ikke lenger er en forfar til den synkroniserte grenen (`services/web/modules/gitea-sync/app/src/GiteaApiClient.mjs:431`), eller når commiten er borte og brukeren kan pushe (`GiteaSyncHandler.mjs:123,126-137`). En synkronisering (`services/web/modules/gitea-sync/app/src/GitMerge.mjs`) flytter `lastSyncCommit`/`lastSyncVersion` når den lykkes (for eksempel `:152,189,231`), registrerer en konflikt med `unmergedBranchName`, `unmergedBranchHead` og `conflictVersion` (`:214-220`), og tømmer dem når konflikten er løst (`:257-264`). |
| `SyncStateManager.mjs:23-25` (`removeProjectState`) | Sletter dokumentet når eieren kobler fra prosjektet (`GiteaSyncHandler.mjs:83-97`) og når et slettet prosjekt utløper (`services/web/modules/gitea-sync/index.mjs:46-48`). |

#### Indekser {#indexes}

| Navn | Nøkler | Alternativer | Migrering |
| ---- | ---- | ------- | --------- |
| `_id_` | `_id: 1` | | default |

Mongoose `autoIndex` er slått av (`services/web/app/src/infrastructure/Mongoose.mjs:7`), så skjemaets `unique: true` på `projectId` oppretter ingenting. Ingen migrering oppretter indekser for denne samlingen.

#### Merknader {#notes}

* Gitea sitt API kan ikke lage commits utenfor en gren slik GitHub sitt kan. En synkronisering committer rett på den synkroniserte grenen når den kan gå fremover, ellers på en midlertidig gren som så flettes via en pull request (`GitMerge.mjs:16-21`).
* En synkronisering kjører under prosjektets `gitSync`-lås, som deles med GitHub Sync og GitLab Sync (`GitMerge.mjs:25-32`).
* Et slettet prosjekt beholder dokumentet sitt til prosjektet utløper.
* Brukerens Gitea-token ligger i [Gitea Sync User Credentials](/no/dev/data-model/gitea-sync-user-credentials-collection).
