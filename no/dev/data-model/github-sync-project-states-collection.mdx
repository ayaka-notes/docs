`githubSyncProjectStates` inneholder ett dokument per prosjekt som er koblet til et GitHub-repository: hvilket repository, og hvor den siste synkroniseringen stoppet. Samlingen hører til webmodulen `github-sync` (`services/web/modules/github-sync`). Skjemaet ligger i `services/web/modules/github-sync/app/models/githubSyncProjectStates.mjs`, og all tilgang går gjennom `services/web/modules/github-sync/app/src/SyncStateManager.mjs`.

#### Felter {#fields}

| Felt | Type | Betydning | Kilde |
| ----- | ---- | ------- | ------ |
| `_id` | ObjectId | Settes av Mongoose ved opprettelse. | |
| `projectId` | ObjectId | Det koblede prosjektet. Påkrevd. Skjemaet sier `unique: true`, men ingen indeks bygges (se Indekser). | `githubSyncProjectStates.mjs:8` |
| `repoFullName` | String | Repositoryet som `owner/name` (GitHub sitt `full_name`). Påkrevd. | `githubSyncProjectStates.mjs:9` |

Standard `null`. | `githubSyncProjectStates.mjs:10`, `GitHubSyncHandler.mjs:175-181,235-241` |

#### Hvem skriver {#who-writes-it}

| Kode | Hva den gjør |
| ---- | ------------ |
| `SyncStateManager.mjs:9-14` (`createProjectState`) | Oppretter dokumentet: etter at et repository er importert som et nytt prosjekt (`services/web/modules/github-sync/app/src/GitHubSyncHandler.mjs:175-181`), eller etter at et prosjekt er eksportert til et nytt repository (`GitHubSyncHandler.mjs:235-241`, kun eier, avvist hvis det allerede er koblet). |
| `SyncStateManager.mjs:16-21` (`updateProjectState`) | `$set` av de endrede feltene. `getMergeOverview` setter `mergeStatus: 'diverged'` når den synkroniserte grenen ikke lenger bygger på `lastSyncCommit`: GitHub sin compare svarer `diverged` eller `behind` (`GitHubApiClient.mjs:382-400`), eller commiten er borte og brukeren kan pushe (`GitHubSyncHandler.mjs:123,126-137`). En synkronisering (`services/web/modules/github-sync/app/src/GitMerge.mjs`) flytter `lastSyncCommit`/`lastSyncVersion` når den lykkes (for eksempel `:143,173,224`), registrerer en konflikt med `unmergedBranchName`, `unmergedBranchHead` og `conflictVersion` (`:207-213`), og tømmer dem når konflikten er løst (`:250-257`). |
| `SyncStateManager.mjs:23-25` (`removeProjectState`) | Sletter dokumentet når eieren kobler fra prosjektet (`GitHubSyncHandler.mjs:83-97`) og når et slettet prosjekt utløper (`services/web/modules/github-sync/index.mjs:56-58`). |

#### Indekser {#indexes}

| Navn | Nøkler | Alternativer | Migrering |
| ---- | ---- | ------- | --------- |
| `_id_` | `_id: 1` | | default |

Mongoose `autoIndex` er slått av (`services/web/app/src/infrastructure/Mongoose.mjs:7`), så skjemaets `unique: true` på `projectId` oppretter ingenting. `tools/migrations/20190912145010_create_githubSyncProjectStates_indexes.mjs` (upstreams `project_id` og `owner_id`) er bare merket `saas` og kjører ikke i CE.

#### Merknader {#notes}

* En synkronisering kjører under prosjektets `gitSync`-lås (`GitMerge.mjs:17-24`). GitLab Sync og Gitea Sync tar den samme låsen, så bare én synkronisering kjører per prosjekt om gangen.
* Et slettet prosjekt beholder dokumentet sitt til prosjektet utløper.
* Brukerens GitHub-token ligger i [GitHub Sync User Credentials](/no/dev/data-model/github-sync-user-credentials-collection).
