`templates` inneholder ett dokument per mal i malgalleriet. Filene til en mal (prosjektets zip og PDF-en) ligger ikke her: de lagres i filestore under `template/<_id>/v/<version>/`. Samlingen tilhører webmodulen `template-gallery` (`services/web/modules/template-gallery`). Skjemaet er Mongoose-modellen `Template` i `services/web/modules/template-gallery/app/src/models/Template.mjs`; logikken ligger i `services/web/modules/template-gallery/app/src/TemplateGalleryManager.mjs` og `TemplateGalleryHelper.mjs` ved siden av.

#### Hvem skriver {#who-writes-it}

| Kode | Hva den gjør |
| ---- | ------------ |
| `TemplateGalleryManager.mjs:53-97` (`createTemplateFromProject`) | `POST /template/new/:Project_id`. Kopierer prosjektets innstillinger (`TemplateGalleryHelper.mjs:94-134`), laster opp zip-filen og PDF-en til filestore og lagrer. Hvis navnet er tatt, svarer den med en konflikt, med mindre klienten ba om å overskrive: da oppdaterer den malen og øker `version`, og sletter deretter filene for forrige versjon. |
| `TemplateGalleryManager.mjs:21-47` (`editTemplate`) | `POST /template/:template_id/edit`. Tilordner de innsendte feltene til dokumentet, gjengir `description` og `author` på nytt og setter `lastUpdated`. Redigeringsskjemaet sender de endrede feltene blant `name`, `license`, `category`, `language`, `authorMD` og `descriptionMD` (`services/web/modules/template-gallery/frontend/js/pages/template/util/api.ts:22-29`). |
| `TemplateGalleryHelper.mjs:186-222` (`deleteTemplateAssets`) | `DELETE /template/:template_id/delete` sletter dokumentet og filene for den angitte versjonen (`TemplateGalleryManager.mjs:49-51`). |

Bare nettstedsadministratorer og brukeren i `OVERLEAF_TEMPLATES_USER_ID` kan kalle disse tre rutene (`services/web/modules/template-gallery/app/src/Router.mjs:55-62,70-84`, `PermissionsMiddleware.mjs:8-19`).

#### Hvem leser {#who-reads-it}

| Kode | Hva den gjør |
| ---- | ------------ |
| `TemplateGalleryManager.mjs:158-183` (`getTemplate`) | Finner én mal via `_id` eller `name` for malsiden og for `GET /api/template` (`services/web/modules/template-gallery/app/src/TemplateGalleryController.mjs:210-232`). Hvis `project_id` peker på et prosjekt som ikke lenger finnes, utelater svaret det; dokumentet endres ikke. |
| `TemplateGalleryManager.mjs:190-236` (`getCategoryTemplates`) | `GET /api/templates`: én side i en kategori, søkt i `name`, `authorMD` og `descriptionMD`, sortert etter `lastUpdated` eller etter `name` (uten hensyn til store og små bokstaver). |
| `TemplateGalleryHelper.mjs:64-80` (`canUserOverrideTemplate`) | Leser `owner` for å navngi eieren i konfliktmeldingen. |

#### Indekser {#indexes}

| Navn | Nøkler | Alternativer | Migrering |
| ---- | ---- | ------- | --------- |
| `_id_` | `_id: 1` | | standard |

Mongoose `autoIndex` er slått av (`services/web/app/src/infrastructure/Mongoose.mjs:7`). `tools/migrations/20190912145030_create_templates_indexes.mjs` (unike `project_id`, `user_id`, `name`) er merket `server-pro` og `saas`, så den kjører ikke i CE, som bare kjører `server-ce`-migreringene (`server-ce/init_scripts/900_run_web_migrations.sh`).

#### Merknader {#notes}

* Upstream behandler `templates` som en utdatert samling og fjerner den på sitt eget nettsted (`tools/migrations/20241002180623_drop_unused_collections.mjs`, merket `saas`). I Ayakaleaf Pro bruker malgallerimodulen den.
* Sortering etter navn bruker en sorteringsrekkefølge uten hensyn til store og små bokstaver, og kommentaren ved `TemplateGalleryManager.mjs:186-188` påpeker at en `name`-indeks ville trenge den samme. CE har ingen `name`-indeks, så Mongo sorterer i minnet.
* Å slette kildeprosjektet eller eieren sletter ikke malen.
