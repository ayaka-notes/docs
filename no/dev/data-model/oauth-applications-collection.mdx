`oauthApplications` inneholder OAuth-klientene som web kjenner til. Ett dokument er én klient. I Ayakaleaf Pro skriver bare webmodulen `git-bridge` til den: den oppretter én klient med navnet `Overleaf Git Bridge` når web starter. Skjemaet er `services/web/app/src/models/OauthApplication.mjs`.

#### Felter {#fields}

| Felt | Type | Betydning | Kilde |
| ----- | ---- | ------- | ------ |
| `_id` | ObjectId | Id-en til klientdokumentet. `oauthAccessTokens.oauthApplication_id` og `oauthAuthorizationCodes.oauthApplication_id` peker på den. | `OauthApplication.mjs:5` |
| `id` | String | Klient-id: 64 tilfeldige små bokstaver og sifre. | `OauthApplication.mjs:7`, `services/web/modules/git-bridge/index.mjs:25` |
| `clientSecret` | String | Klienthemmelighet, skrevet som `v1.` pluss 32 tilfeldige tegn. Bare `getClient` leser den, og ingenting kaller `getClient` (se Merknader). | `OauthApplication.mjs:8`, `git-bridge/index.mjs:26` |
| `grants` | Array of String | Granttyper. Git-bridge-klienten har `['password']`. Returneres med klienten når et token sjekkes (`services/web/modules/oauth2-server/app/src/OAuth2Model.mjs:67-72`). | `OauthApplication.mjs:9`, `git-bridge/index.mjs:27` |
| `name` | String | Klientens navn. Git-bridge-modulen og koden for personlige tilgangstokener finner klienten via navnet `Overleaf Git Bridge`. | `OauthApplication.mjs:10`, `git-bridge/index.mjs:15-16,28` |
| `redirectUris` | Array of String | Tillatte omdirigerings-URI-er. `[]` for git-bridge-klienten. | `OauthApplication.mjs:11`, `git-bridge/index.mjs:29` |
| `scopes` | Array of String | Scopes klienten kan bruke. `['git_bridge']` for git-bridge-klienten. | `OauthApplication.mjs:12`, `git-bridge/index.mjs:30` |
| `pkceEnabled` | Boolean | Bare i skjemaet: ingen kode i dette repoet skriver det, og bare den ubrukte `getClient` leser det (`OAuth2Model.mjs:207`). | `OauthApplication.mjs:13` |

#### Hvem skriver {#who-writes-it}

| Kode | Hva den gjør |
| ---- | ------------ |
| `git-bridge/index.mjs:9-35` (module `git-bridge`) | Når `GIT_BRIDGE_ENABLED` er `true`, oppretter den klienten `Overleaf Git Bridge` når web starter, hvis ingen klient med det navnet finnes. |

#### Hvem leser {#who-reads-it}

| Kode | Hva den gjør |
| ---- | ------------ |
| `services/web/modules/oauth2-server/app/src/OAuthPersonalAccessTokenManager.mjs:53-61` (module `oauth2-server`) | Finner klienten `Overleaf Git Bridge` via navnet og lagrer dens `_id` i hvert nye personlige tilgangstoken. Uten klienten opprettes ikke noe token. |
| `OAuth2Model.mjs:31-39,67-72` (`getAccessToken`) | Laster klienten til et token via `oauthApplication_id` og returnerer dens `id` og `grants`. |
| `OAuth2Model.mjs:185-209,241,275` (`getClient`, `saveToken`, `saveAuthorizationCode`) | Slår opp klienter via `id`. Nås aldri i dette repoet, se Merknader. |

#### Indekser {#indexes}

Bare standardindeksen på `_id`. Den unike indeksen `id_1` kommer fra migreringer merket `saas` (`20190912145016_create_oauthApplications_indexes.mjs`) og `server-pro` (`20230502180757_server_pro_oauth_indexes.mjs`), som Community Edition ikke kjører.

#### Merknader {#notes}

* Web bruker `@node-oauth/oauth2-server` bare til å sjekke bearer-tokener (`server.authenticate` i `services/web/app/src/Features/Authentication/AuthenticationController.mjs:409-450`), som bare kaller modellens `getAccessToken` og `verifyScope`. Ingen rute betjener `/oauth/token` eller `/oauth/authorize`, så `getClient`, `saveToken` og `saveAuthorizationCode` kalles aldri.
* Modulen slår opp klienten via navnet og oppretter den deretter, og Community Edition har ingen unik indeks på `name` eller `id`. Ingenting hindrer derfor en ny klient med samme navn. Kode som trenger klienten, tar den som `findOne` returnerer.
