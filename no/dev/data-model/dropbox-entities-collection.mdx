---
title: Dropbox Entities-samlingen
icon: file-arrow-up
---

`dropboxEntities` har ett dokument per fil som Dropbox-synkroniseringen har kopiert mellom et prosjekt og én brukers Dropbox, pluss kortlivede tombstones. Samlingen hører til Dropbox-synkroniseringen: third-party-datastore (`services/third-party-datastore/app/js/StateManager.mjs`) skriver og leser den, og webmodulen `dropbox` (`services/web/modules/dropbox/app/src/DropboxHandler.mjs`) tømmer den. Det finnes ikke noe Mongoose-skjema.

#### Felt {#fields}

| Felt | Type | Betydning | Kilde |
| ---- | ---- | --------- | ----- |
| `_id` | ObjectId | Settes av driveren ved innsetting. | `StateManager.mjs:46,97` |
| `overleaf.userId` | ObjectId | Brukeren som har filen i sin Dropbox. Settes på hvert dokument. | `StateManager.mjs:48,98` |
| `overleaf.projectId` | ObjectId | Prosjektet til docen eller filen. Settes når det er kjent; tombstones har ingen. | `StateManager.mjs:49-51` |
| `overleaf.id` | ObjectId | `_id` til docen eller filen i prosjektets `rootFolder`. Settes når den er kjent. | `StateManager.mjs:52` |
| `overleaf.type` | String | `doc` eller `file`. Gjeldende kode skriver den, men leser den ikke. | `StateManager.mjs:53`; verdier fra `services/web/app/src/Features/ThirdPartyDataStore/TpdsUpdateSender.mjs:35,96` og `UpdateMerger.mjs:104,119` |
| `dropbox.id` | String | Filens `id` i Dropbox-filmetadataene. Settes ikke på tombstones. | `StateManager.mjs:56` |
| `dropbox.pathLower` | String | Filens sti i Dropbox, med små bokstaver og uten avsluttende skråstrek. Oppdateres når filen eller prosjektmappen flyttes. | `StateManager.mjs:14-16,57,91,99` |
| `dropbox.rev` | String | Dropbox-revisjonen ved siste synkronisering. Neste opplasting sender den, slik at en fil som er endret i Dropbox, ikke blir overskrevet. | `StateManager.mjs:58`, `JobProcessor.mjs:114-122` |
| `dropbox.contentHash` | String | Dropbox-innholdshashen ved siste synkronisering. En listet fil med samme hash hoppes over, siden den er vår egen opplasting eller allerede er brukt. | `StateManager.mjs:59`, `PullManager.mjs:147-149` |
| `tombstone` | Boolean | `true` markerer en sti som third-party-datastore selv har slettet eller flyttet bort i Dropbox. Når Dropbox rapporterer slettingen tilbake, blir den ikke brukt på prosjektet. | `StateManager.mjs:100`, `PullManager.mjs:189-192` |
| `createdAt` | Date | Bare tombstones: når den ble laget. En fullført pull fjerner tombstones som ble laget før den startet. | `StateManager.mjs:101,115-121` |

En tombstone har bare `overleaf.userId`, `dropbox.pathLower`, `tombstone` og `createdAt` (`StateManager.mjs:96-103`).

#### Hvem som skriver den {#who-writes-it}

| Kode | Hva den gjør |
| ---- | ------------ |
| `services/third-party-datastore/app/js/StateManager.mjs:35-62` (`recordEntity`) | Sletter brukerens dokumenter med samme `dropbox.id`, `dropbox.pathLower` eller `overleaf.id`, og setter deretter inn den nye tilstanden. |
| `services/third-party-datastore/app/js/JobProcessor.mjs:102-134` (`addEntity`) | Registrerer en doc eller fil etter opplasting fra Overleaf til Dropbox (`:125-133`). |
| `services/third-party-datastore/app/js/PullManager.mjs:142-177` (`applyFile`) | Registrerer en Dropbox-fil etter at web har brukt den på prosjektet (`:168-176`). |
| `StateManager.mjs:80-94` (`moveEntities`) | Skriver om `dropbox.pathLower` under en flyttet sti: nytt prosjektnavn (`JobProcessor.mjs:195`) og flytting av fil eller mappe (`JobProcessor.mjs:239`). |
| `StateManager.mjs:96-103` (`addTombstone`) | Etter en sletting (`JobProcessor.mjs:153`), et nytt prosjektnavn (`:202`) eller en flytting (`:240`) i Dropbox. |
| `StateManager.mjs:72-78` (`removeEntities`) | Sletter oppføringene på og under en sti, unntatt tombstones: etter en sletting fra Overleaf (`JobProcessor.mjs:152`) eller i Dropbox (`PullManager.mjs:206`). |
| `StateManager.mjs:115-121` (`clearTombstones`) | På slutten av en pull (`PullManager.mjs:31,69`). |
| `StateManager.mjs:186-190` (`removeUserState`), kalt fra `services/third-party-datastore/app/js/QueueWorker.mjs:43` | Sletter alle brukerens dokumenter når third-party-datastore kobler fra en konto den ikke lenger kan bruke. |
| `DropboxHandler.mjs:142-146` (`removeUserState`) | Sletter alle brukerens dokumenter ved tilkobling (`:125`), ved frakobling (`:183`) og når en slettet bruker utløper (`services/web/modules/dropbox/index.mjs:62-64`). |
| `DropboxHandler.mjs:150-154` (`removeProjectState`) | Sletter prosjektets dokumenter når et slettet prosjekt utløper (`index.mjs:54-56`). |

#### Hvem som leser den {#who-reads-it}

| Kode | Hva den gjør |
| ---- | ------------ |
| `StateManager.mjs:64-70` (`findEntityByPath`) | Henter `dropbox.rev` før en opplasting (`JobProcessor.mjs:114`) og `dropbox.contentHash` før en Dropbox-fil brukes (`PullManager.mjs:147`). |
| `StateManager.mjs:106-112` (`findTombstone`) | Sjekker en rapportert sletting på stien eller på en av foreldrestiene (`PullManager.mjs:189`). |
| `StateManager.mjs:160-175` (`getSyncedPaths`) | Lister de synkroniserte filstiene etter en tilbakestilling av markøren, slik at en fil som mangler i listen, regnes som slettet (`PullManager.mjs:74-85`). |

#### Indekser {#indexes}

| Navn | Nøkler | Alternativer | Migrering |

`20220811111800_create_dropboxEntities_index.mjs` og `20220825160708_recreate_dropboxEntities.mjs` har bare taggen `saas`, så CE har verken de unike indeksene deres på `(overleaf.userId, dropbox.id)` og `(overleaf.userId, overleaf.id)` eller den hashede indeksen deres på `dropbox.pathLower`.

#### Merknader {#notes}

* Unikhet kommer bare fra slettingen før hver innsetting i `recordEntity` (`StateManager.mjs:38-45`). Kommentaren i `StateManager.mjs:3-11` nevner unike indekser; CE har dem ikke.
* Spørringer på bruker og sti (`findEntityByPath`, `findTombstone`, `removeEntities`) bruker indeksen bare for `overleaf.userId`.
