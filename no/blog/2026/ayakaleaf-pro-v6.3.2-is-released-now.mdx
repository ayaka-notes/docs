Vi er svært stolte av å kunngjøre utgivelsen av Overleaf Pro 6.3.2. Oppstrøms Overleaf 6.3.2 er en sikkerhetsutgivelse som oppdaterer Node.js, og vi leverer den sammen med et nytt medlem av synkroniseringsfamilien: etter GitHub, GitLab og Dropbox kan prosjektene dine nå også ligge i Gitea.

### Endringer

* Gitea Sync (tidlig forhåndsversjon): toveis synkronisering med gitea.com eller ditt selvdriftede Gitea.
* Node.js 24.22.1: sikkerhetsoppdateringen i oppstrøms Overleaf 6.3.2.
* Feilrettinger funnet av E2E-testsystemet vårt og Internal Horizon Issue Investigation.

<Info>

Gitea Sync leveres i 6.3.2 som en **tidlig forhåndsversjon** (early preview) for gradvis testing, og blir offisielt lansert i v6.4.0. Konfigurasjonen og virkemåten kan fortsatt endres før den tid. Den er deaktivert som standard. Rapporter eventuelle problemer på [GitHub](https://github.com/ayaka-notes/ayakaleaf-pro/issues).

</Info>

#### Funksjon 01: Gitea Sync (forhåndsversjon)

Mange laboratorier og små team driver sitt eget Gitea, fordi det er lett nok for én liten server. Gitea Sync fungerer på samme måte som GitHub Sync og GitLab Sync: koble til kontoen din, importer et repositorium fra menyen for nytt prosjekt, eller eksporter et prosjekt til et nytt Gitea-repositorium. Deretter pusher og puller du fra editoren, og slår sammen via pull requests med repositoriets egen sammenslåingsstil. Overleaf omgår aldri grenbeskyttelsen din: når en pull request krever godkjenninger eller vellykkede kontroller, venter den på at du slår den sammen i Gitea.

Det fungerer med gitea.com og med selvdriftet Gitea 1.23 eller nyere. Sett `GITEA_SYNC_ENABLED`, `GITEA_SYNC_CLIENT_ID`, `GITEA_SYNC_CLIENT_SECRET` og `GITEA_TOKEN_CIPHER_PASSWORD`, samt `GITEA_SYNC_URL` for en selvdriftet instans.

Se [Gitea-synkronisering](/no/on-premises/configuration/overleaf-toolkit/gitea-synchronisation  "mention") for fullstendige oppsettinstruksjoner.

#### Feilrettinger

* **Git-synkronisering**: når en fil som er slettet på GitHub, GitLab eller Gitea, ikke kan slettes i Overleaf, mislykkes synkroniseringen nå og kan prøves på nytt, i stedet for å rapportere suksess og la filen bli liggende. En `git push` som sletter en fil, mislykkes på samme måte.
* **Git bridge**: et dokument som er opprettet i editoren med en filtype som ikke er tekst (for eksempel `.csv`), forblir redigerbart når en `git push` endrer det.
* **Sporing av endringer**: utloggede redaktører av et prosjekt som er delt via lenke, kan slette kommentartråder, men kan ikke lenger løse eller gjenåpne dem, og gjennomlesere kan slette sine egne svar.
* **Malgalleri**: publisering av en mal krever tilgang til prosjektet.
* **Learn**: hurtigbufrede hjelpesider forblir tilgjengelige når wikien ikke kan nås.

Se [versjonsmerknadene for 6.3.2](/no/on-premises/release-notes/release-notes-6.x.x#ayakaleaf-pro-6.3.2  "mention") for den fullstendige listen.

#### Oppgradering

* Fra 6.3.1 eller 6.3.0: ingen migrering er nødvendig. Hent det nye imaget og start på nytt.
* Fra 6.2.x eller eldre med Zotero eller Mendeley i bruk: kjør først [Zotero-/Mendeley-migreringen](/no/on-premises/release-notes/release-notes-6.x.x#ayakaleaf-pro-6.3.0  "mention") fra 6.3.0.
* Gitea Sync er deaktivert som standard og trenger bare nye miljøvariabler.
