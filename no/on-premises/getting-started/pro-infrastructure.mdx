#### Tjenester

Overleaf Pro-infrastrukturen består av fire hovedtjenester: `sharelatex`, `git-bridge` (valgfri), `mongo` og `redis`. Tjenesten `sharelatex`, som kjører hovedapplikasjonen Server Pro, er avhengig av tjenestene `mongo` og `redis` for database og hurtigbuffer/sanntidsfunksjonalitet, og av `git-bridge` for å håndtere [Git-integrasjonen](/no/on-premises/configuration/overleaf-toolkit/git-integration) (valgfri). Den eneste porten som publiseres på vertsmaskinen, er port 80, som brukes av `sharelatex`-containeren.

Server Pro støtter også valgfritt [S3-kompatibel lagring](/no/on-premises/configuration/overleaf-toolkit/s3) for prosjektfiler og full prosjekthistorikk, og kan i tillegg videreformidle (proxy) tilgang til hovedsiden for [Overleaf-dokumentasjonenarrow-up-right](https://www.overleaf.com/learn). For mer informasjon, se veiledningen vår om sider for [Legge til LaTeX-brukerhjelp](/no/on-premises/configuration/overleaf-toolkit/adding-latex-user-help).

<Info>

Ved behov kan MongoDB og Redis flyttes ut ved hjelp av miljøvariabler som peker til eksterne tjenester. For mer informasjon, se [Konfigurere Overleaf](/no/on-premises/configuration) hvis du bruker Docker Compose, og [Toolkit-innstillinger](/no/on-premises/configuration/overleaf-toolkit/toolkit-settings) hvis du bruker Overleaf Toolkit.

</Info>

#### Kompilering

For [Sandboxed Compiles](/no/on-premises/configuration/overleaf-toolkit/sandboxed-compiles) vil `sharelatex`-containeren styre opprettelsen av nye containere som håndterer kompilering av prosjekter; dette gjøres via Docker-socketen på vertsmaskinen. Du kan lese mer om editoren og den helhetlige kompilerings-/hurtigbufferprosessen [her](/no/on-premises/getting-started/microservices#editor-and-compile-process).

#### Nettverk

Kommunikasjon mellom containere skjer via Dockers interne DNS-oppslag over et dedikert bridge-nettverk, og ingen brannmurer er aktivert. Som standard bruker tjenestene ovenfor sine respektive standardporter, men disse kan konfigureres med miljøvariabler. `sharelatex`-containeren bruker port 80 for ekstern webtilgang (levert av Nginx), `mongo`-containeren bruker port 27017 og `redis` bruker port 6379.

For kunder som bruker vår administrerte løsning [Overleaf Toolkitarrow-up-right](https://github.com/overleaf/toolkit), kan du valgfritt [aktivere en TLS-proxy](/no/on-premises/configuration/overleaf-toolkit/tls-proxy) som terminerer HTTPS-tilkoblinger med Nginx via en miljøvariabel. Alternativt kan du bruke din eksisterende TLS-proxy.

<Info>

Du kan se et diagram som forklarer flyten av forespørsler [her](/no/on-premises/configuration/overleaf-toolkit/tls-proxy).

</Info>

#### Oppsummering

* Utenfor Docker-nettverket er kun port 80 tilgjengelig, og den er bundet til Nginx. <strong>Merk:</strong> `sharelatex`-containeren kjører mange [tjenesterarrow-up-right](https://github.com/overleaf/overleaf/tree/main/services) som kommuniserer med hverandre via HTTP. Disse portene er imidlertid **ikke** tilgjengelige utenfor Docker-nettverket.
* Innenfor Docker-nettverket kan Overleaf-tjenestene, MongoDB, Redis og Git Bridge kommunisere fritt med hverandre.
* Inne i [Sandboxed Compiles](/no/on-premises/configuration/overleaf-toolkit/sandboxed-compiles)-containere er det ikke noe nettverk tilgjengelig.
