---
title: Eksportere prosjekter
icon: file-export
---

I Server Pro og Community Edition `5.4.0` har vi inkludert et skript som lar administratorer eksportere alle brukerprosjekter (inkludert prosjekter som fortsatt er synlige i mappene **Deleted** og **Trashed**) til en katalog på disk.

<Info>

Resultatet av å kjøre dette skriptet er det samme som å laste ned en zip-fil av alle prosjekter manuelt fra brukerens prosjektoversikt. Skriptet tømmer eventuelle ventende endringer før nedlastingen starter, for å sikre at eksporten inneholder den nyeste versjonen av prosjektet.

</Info>

### Begrensninger

Eksportskriptet har følgende begrensninger:

* Ingen prosjektinnstillinger, som navnet på TeX Live-imaget eller kompilatoren, eksporteres. Disse må angis når prosjektet lastes opp til brukerens konto.
* Eksporterte prosjekter inneholder ingen versjonshistorikk.
* Ingen informasjon om samarbeidspartnere bevares. Prosjektene må deles på nytt. Hvis du bruker lenkedeling, blir visnings- og redigeringslenkene generert på nytt (de blir ikke de samme som før).
* Kommentarer og informasjon om sporede endringer eksporteres ikke.
* Chathistorikken for prosjektet eksporteres ikke.

<Danger>

Dette skriptet er **ikke** utformet for å erstatte en full systemsikkerhetskopi. For å sikre at du kan gjenopprette instansen ved en katastrofe, anbefaler vi **sterkt** at du tar en [konsistent sikkerhetskopi](https://docs.overleaf.com/on-premises/maintenance/#performing-a-consistent-backup).

</Danger>

### **Flagg**

| Navn           | Beskrivelse                                                                     |
| -------------- | ------------------------------------------------------------------------------- |
| `--help`       | Vis hjelp                                                                       |
| `--user-id`    | Bruker-ID-en (påkrevd med mindre `--export-all` eller `--project-id` brukes)    |
| `--project-id` | Eksporter ett enkelt prosjekt (**kan ikke** brukes sammen med `--user-id` eller `--export-all`) |
| `--list`       | List opp brukerens prosjekter (**kan ikke** brukes sammen med `--output`)       |
| `--output`     | Zip-fil for utdata (for enkelteksporter)                                        |
| `--export-all` | Eksporter alle brukeres prosjekter (krever `--output-dir`)                      |
| `--output-dir` | Katalog for lagring av eksportfilene til alle brukere                           |
| `--log-level`  | Støttede loggnivåer: `trace`\|`debug`\|`info`\|`warn`\|`error`\|`fatal`         |

### **Bruk**

Bruk følgende kommando for å eksportere prosjekter for alle brukere:

```bash wrap
# Overleaf Toolkit users
$ bin/docker-compose exec sharelatex /bin/bash -ce "cd /overleaf/services/web && node modules/server-ce-scripts/scripts/export-user-projects.mjs --export-all --output-dir=/var/lib/overleaf/data/exports"

# Legacy docker-compose.yml users
docker exec sharelatex /bin/bash -ce "cd /overleaf/services/web && node modules/server-ce-scripts/scripts/export-user-projects.mjs --export-all --output-dir=/var/lib/overleaf/data/exports"
```

<Info>

Hvis du kjører Server Pro eller Community Edition &lt;= 3.5.13, må du oppdatere eksemplet ovenfor til å bruke skriptet **`export-legacy-user-projects.js`**.

</Info>

### **Fullføring**

Når eksporten er fullført, får du tilgang til filene via katalogen på verten som er bind-montert til **/var/lib/overleaf** i filen **docker-compose.yml**, eller via miljøvariabelen `OVERLEAF_DATA_PATH` i filen **config/overleaf.rc** hvis du bruker Toolkit.

<Info>

Overleaf tillater for øyeblikket dupliserte prosjektnavn. Hvis en bruker har duplikater, blir disse prosjektene likevel lagt til i brukerens zip-eksport, men når den pakkes ut, vil bare én versjon være til stede. På Linux vil `unzip -B` skrive filer med samme navn som sikkerhetskopifiler i stedet for å overskrive dem.

</Info>
