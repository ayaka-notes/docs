Det er mulig å utvide et eksisterende TeX Live-image med en ny Dockerfile og konfigurere applikasjonen til å bruke det nye imaget.

Her gir vi noen retningslinjer for å installere nye pakker eller skrifter, men konfigurasjon av et egendefinert image dekkes ikke av supportvilkårene våre.

TeX Live-imagene oppdateres sjelden. Vi anbefaler å bygge egendefinerte images på nytt når du oppgraderer Server Pro.

<Danger>

Følgende avsnitt gjelder kun for Server Pro og [Sandboxed Compiles](/no/on-premises/configuration/overleaf-toolkit/sandboxed-compiles).

</Danger>

### Installere og oppdatere nye pakker

Du kan bruke `tlmgr`-kommandoer som `tlmgr install` og `tlmgr update` til å administrere TeX Live-pakker, som i følgende eksempel:

```dockerfile
FROM ghcr.io/ayaka-notes/texlive-full:2023.1

RUN tlmgr update --force ebproof
```

### Bruke `tlmgr` i et eldre TeX Live-image

Som standard laster `tlmgr` ned ressurser fra den nyeste TeX Live-utgivelsen. Når du oppdaterer et eldre TeX Live-image, må nedlastingene byttes til det tilsvarende arkivet. Se listen på [https://www.tug.org/historic/](https://www.tug.org/historic/) for speil av arkivene.

```dockerfile
FROM ghcr.io/ayaka-notes/texlive-full:2022.1

RUN tlmgr option repository <MIRROR>/systems/texlive/<YEAR>/tlnet-final
# e.g. RUN tlmgr option repository ftp://tug.org/historic/systems/texlive/2022/tlnet-final

RUN tlmgr update --force ebproof
```

### Installere nye skrifter

Det finnes ulike fremgangsmåter for å installere nye skrifter i en TeX Live-distribusjon, og installasjon av en egendefinert skrift kan kreve flere trinn. [Instruksjonene for å installere TeX-skrifter](https://tug.org/fonts/fontinstall.html) i den offisielle TeX Live-dokumentasjonen er trolig et godt utgangspunkt.

Følgende `Dockerfile` viser et eksempel på installasjon av en TrueType-skrift oppå et eksisterende TeX Live 2022-image:

```dockerfile
FROM ghcr.io/ayaka-notes/texlive-full:2022.1

COPY ./myfonts/*.ttf /usr/share/fonts/truetype/myfont/

# rebuild font information cache
RUN fc-cache
```

### Konfigurere Server Pro til å bruke de nye imagene

Bruk navnet `ghcr.io/ayaka-notes/texlive-full` og en egendefinert tag for å bygge det nye imaget, som i:

```bash
docker build -t ghcr.io/ayaka-notes/texlive-full:2023.1-custom
```

Nå kan vi konfigurere Server Pro til å bruke det nye `2023.1-custom`-imaget ved å oppdatere miljøvariablene `TEX_LIVE_DOCKER_IMAGE` og `ALL_TEX_LIVE_DOCKER_IMAGES`:

```text wrap
TEX_LIVE_DOCKER_IMAGE: "ghcr.io/ayaka-notes/texlive-full:2023.1-custom"
ALL_TEX_LIVE_DOCKER_IMAGES: "ghcr.io/ayaka-notes/texlive-full:2023.1,ghcr.io/ayaka-notes/texlive-full:2023.1-custom"
```

I eksempelet ovenfor er nye prosjekter som standard satt til å bruke det nye `2023.1-custom`-imaget, mens `2023.1` fortsatt er tilgjengelig ved behov.
