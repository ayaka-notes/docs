<Accordion title="Zotero-/Mendeley-migrering for eksisterende installasjoner">

Når du oppgraderer til det nyutgitte 6.3.0-imaget, migrerer du eksisterende metadata for lenkede bibliografier fra Zotero/Mendeley med skriptet nedenfor. Denne migreringen hører til rettelsen `12031b8dfd`.

Den gir `zoteroGroupId` / `mendeleyGroupId` nytt navn til `group_id`, gir `importedByUserId` nytt navn til `importer_id` og fjerner `importedByName`.

Ta sikkerhetskopi av MongoDB og stopp applikasjonen før du kjører migreringen. La MongoDB kjøre. Åpne skallet (erstatt `mongo` med navnet på containeren din):

```bash
docker exec -it mongo mongosh
```

Kjør følgende i `mongosh` (erstatt `sharelatex` med navnet på databasen din):

```javascript
use sharelatex

(async () => {
  let updated = 0
  await db.projects.find({}, { rootFolder: 1 }).forEach(async project => {
    const changes = {}
    function visit(folders, path) {
      for (const [i, folder] of (folders || []).entries()) {
        const folderPath = `${path}.${i}`
        for (const [j, file] of (folder.fileRefs || []).entries()) {
          const data = { ...file.linkedFileData }
          if (!["zotero", "mendeley"].includes(data.provider)) continue
          const groupKey = `${data.provider}GroupId`
          if (![groupKey, "importedByUserId", "importedByName"].some(key => key in data)) continue
          for (const [oldKey, newKey] of [[groupKey, "group_id"], ["importedByUserId", "importer_id"]]) {
            if (data[oldKey] != null && data[oldKey] !== "") {
              const value = String(data[oldKey])
              if (newKey in data && data[newKey] !== value) {
                throw new Error(`Conflicting ${newKey}: project ${project._id}, file ${file._id}`)
              }
              data[newKey] = value
            }
            delete data[oldKey]
          }
          delete data.importedByName
          changes[`${folderPath}.fileRefs.${j}.linkedFileData`] = data
        }
        visit(folder.folders, `${folderPath}.folders`)
      }
    }
    visit(project.rootFolder, "rootFolder")
    if (!Object.keys(changes).length) return
    const result = await db.projects.updateOne(
      { _id: project._id, rootFolder: { $eq: project.rootFolder } },
      { $set: changes }
    )
    if (!result.matchedCount) throw new Error(`Project changed during migration: ${project._id}`)
    updated += result.modifiedCount
  })
  print(`Updated ${updated} project(s).`)
})()
```

Skriptet tar med nestede mapper og endrer bare metadata for Zotero/Mendeley. Det er trygt å kjøre det på nytt: en fullført migrering rapporterer `Updated 0 project(s).` ved neste kjøring. Hvis det stopper med en konflikt, undersøker du prosjektet/filen som rapporteres; tidligere prosjekter kan allerede være migrert.

Start den oppdaterte applikasjonen, last inn editoren på nytt og oppdater en eksisterende bibliografifil som den opprinnelige importøren. Historiske øyeblikksbilder skrives ikke om. For å nedgradere til den gamle applikasjonen gjenoppretter du sikkerhetskopien av MongoDB.

### Endringer

* AI-chatassistent: Chat med en AI-modell via din egen leverandør, rett i editoren.
* LaTeX-feilassistent: Få AI-foreslåtte rettelser for feil ved LaTeX-kompilering.
* Mendeley-integrasjon: Importer referanser fra Mendeley på samme måte som fra Zotero.
* Open in Overleaf API: Lagt til et API for å åpne innhold i Overleaf.
* Malgalleri: Lagt til paginering, søk og sortering på serversiden, slik at store gallerier ikke lenger må laste inn alle maler i nettleseren.
* Oversettelser: Oppdaterte oversettelsesoppdateringer for 6.3.0, inkludert ny grensesnittekst på tvers av støttede språk.
* Overleaf 6.3.0 oppstrøms: Inkluderer redigering av filer i faner, separate topptekstlogoer for lyst og mørkt tema samt oppdateringer av avhengigheter og basisimage.
* Lagt til `OVERLEAF_HEADER_IMAGE_URL_LIGHT` og `OVERLEAF_HEADER_IMAGE_URL_DARK` for å støtte separate topptekstlogoer for lyst og mørkt tema.
* Filer kan nå åpnes i ulike faner i editoren.
* Lagt til støtte for konfigurerbare HTTP(S)-proxyer, inkludert lokalt driftede proxyer, via `OVERLEAF_LINKED_URL_OUTBOUND_PROXY`, som også brukes av Open in Overleaf API.

#### Funksjon 04: Paginering av maler

Galleriet håndterer nå paginering, sortering og søk i MongoDB. Det fungerer uten noen forberedelser; med tusenvis av maler kan du likevel legge til disse indeksene for å holde det raskt (trygt å kjøre på nytt, `mongo`/`sharelatex` = navnene på containeren og databasen din):

```bash
docker exec mongo mongosh sharelatex --quiet --eval '
db.templates.createIndex({category:1,lastUpdated:-1},{name:"category_1_lastUpdated_-1",background:true});
db.templates.createIndex({lastUpdated:-1},{name:"lastUpdated_-1",background:true});
db.templates.createIndex({category:1,name:1},{name:"category_1_name_1_ci",collation:{locale:"en",strength:2},background:true});
db.templates.createIndex({name:1},{name:"name_1_ci",collation:{locale:"en",strength:2},background:true});
'
```

Behold `collation` på de to `*_ci`-indeksene slik de er skrevet — galleriet sender spørringer med samme collation, og MongoDB bruker bare en indeks som samsvarer.

## Ayakaleaf Pro 6.2.2

<strong>Utgivelsesdato:</strong> 2026.07.23

Se: [https://github.com/ayaka-notes/ayakaleaf-pro/releases/tag/pro-v6.2.2](https://github.com/ayaka-notes/ayakaleaf-pro/releases/tag/pro-v6.2.2)

### Endringer

Tilbakeport av de offisielle hurtigrettelsene som ble levert i Overleaf `6.2.2` oppstrøms (oppå `6.2.1`):

* Slutt å lekke hemmeligheten for prosjektinvitasjonstokenet til loggene. Krypteringsmodulen for invitasjonstokener logget sin egen konfigurasjon ved hver kryptering/dekryptering, inkludert chifferpassordene som er avledet fra `OVERLEAF_INVITE_TOKEN_SECRET`.
* Migrer utgående e-post fra AWS SES v1-klienten, som har nådd slutten av levetiden, til SESv2. Instanser konfigurert med e-postdriveren `ses` kunne mislykkes helt med å sende e-post; sending går nå via `SESv2Client`.
* Skjul gruppeoppføringene i nedtrekksmenyen for prosjektdeling bak det nye funksjonsflagget `group-link-sharing`, slik at deling av gruppelenker ikke lenger tilbys på instanser der det ikke er relevant.
* Rett dialogen for prosjektdeling for samarbeidspartnere. Når den ble åpnet av en som ikke var eier, eller med `sharing-updates`-flyten deaktivert, ble det sendt en forespørsel som alltid feilet og viste feilmeldingen "something went wrong".
* Legg til `scripts/flush_docs_with_pending_updates.js` i document-updater, et vedlikeholdsskript som gjenoppretter dokumenter som er etterlatt med en fastlåst `PendingUpdates`-kø i Redis etter at prosjektet deres ble tømt eller slettet permanent. Støtter `--dry-run` og en sikkerhetskontroll med `--estimated-docs`.
* Oppdater avhengigheter: `multer` 2.2.0, `form-data` 2.5.6, `protobufjs` 7.6.3, `@grpc/grpc-js` 1.14.4.

Denne utgivelsen inkluderer også følgende rettelser og forbedringer fra Ayakaleaf Pro:

* Legg til fullstendige oversettelser for 16 ekstra språk (cs, da, de, es, fi, fr, it, ja, ko, nl, no, pl, pt, ru, sv, tr), som retter uoversatte tekster som siden for tilbakestilling av passord. Retter [#38](https://github.com/ayaka-notes/ayakaleaf-pro/issues/38).
* Rett antallet i knappen "show N more projects" i administrasjonspanelet, som viste feil tall fordi plassholderen for flertall ikke ble sendt riktig.
* Rett valideringsfeil ved GitHub-eksport, som nå vises via statiske i18n-nøkler i stedet for rå meldinger, og fjern feilnøklene som ikke lenger brukes av GitHub Sync-dialogen.

## Ayakaleaf Pro 6.2.1

Forhindrer falske synkroniseringsproblemer / "unsaved changes"-problemer ved angring og samtidig redigering.

## Ayakaleaf Pro 6.2.0

<strong>Utgivelsesdato:</strong> 2026.07.10

Se: [https://github.com/ayaka-notes/ayakaleaf-pro/releases/tag/pro-v6.2.0](https://github.com/ayaka-notes/ayakaleaf-pro/releases/tag/pro-v6.2.0)

Vi er stolte av å kunngjøre utgivelsen av Overleaf Pro 6.2.0, den kraftigste og mest funksjonsrike LaTeX-editoren på nett i fellesskapet. En spesiell takk til yu-i-i og davrot for deres verdifulle bidrag. De forbedret GitHub Sync og innførte avansert referansesøk og Zotero-integrasjon.

### Merknader

<Warning>

* En ny påkrevd miljøvariabel, `OVERLEAF_INVITE_TOKEN_SECRET`, er innført. Du må generere den med `openssl rand -base64 32`. Hvis den ikke er konfigurert, vil ikke Overleaf-instansen starte.
* Hvis du aktiverer GitHub Sync, må du konfigurere miljøvariabelen `GITHUB_TOKEN_CIPHER_PASSWORD`. Denne variabelen kreves for å kryptere GitHub-tilgangstokener på en sikker måte. Uten den vil ikke Overleaf-instansen starte.

</Warning>

* Lagt til en ny miljøvariabel, `DEFAULT_LATEX_COMPILER`, for å angi standardkompilatoren for nye prosjekter (enten `pdflatex`, `latex`, `xelatex` eller `lualatex`).
* Den redesignede editoren er nå det eneste tilgjengelige alternativet.

### Endringer

Denne utgivelsen inkluderer følgende forbedringer og nye funksjoner.

* `MAX_UPLOAD_SIZE` kan nå konfigureres i stedet for å være begrenset til **50 MB**.
* Rettet en omstartsløkke for containeren når sandkassekompilering var deaktivert.
* Håndhevet sletting av PAT-er avgrenset til eieren for OAuth2.
* Rettet et problem med LDAP-import.

Funksjonene inkluderer:

* Lagt til en nettleserbasert Python-kjører.
* Lagt til Pandoc-støtte for import og eksport av Markdown, DOCX og andre formater.
* Lagt til GitHub Sync.
* Lagt til fullstendige kinesiske oversettelser.
* Lagt til Zotero-integrasjon.
* Lagt til `DEFAULT_LATEX_COMPILER`.

## Ayakaleaf Pro 6.0.0

<strong>Utgivelsesdato:</strong> 2026.02.17

Testutgivelse, se: [https://github.com/ayaka-notes/ayakaleaf-pro/releases/tag/pro-v6.0.0](https://github.com/ayaka-notes/ayakaleaf-pro/releases/tag/pro-v6.0.0)

Dette er en testutgivelse og også vår første versjon av Overleaf Pro. Denne versjonen inneholder ingen funksjoner fra Server Pro, så den markerer bare utgangspunktet vårt. Vi vil legge til nye funksjoner senere, som administrasjonspanel og git-bridge ...

I denne utgivelsen har vi lansert Overleaf-imaget for Docker på ARM. Du kan prøve det hvis du har en Mac eller en ARM-basert server, men enkelte funksjoner fungerer kanskje ikke så godt (ikke testet ennå).

### Docker-image

Du finner Docker-imaget her: [https://github.com/ayaka-notes/ayakaleaf-pro/pkgs/container/overleaf-pro](https://github.com/ayaka-notes/ayakaleaf-pro/pkgs/container/overleaf-pro)

For image med flere arkitekturer, se [her](https://github.com/ayaka-notes/ayakaleaf-pro/pkgs/container/overleaf-pro/691283454?tag=6.0.0).

```bash
docker pull ghcr.io/ayaka-notes/overleaf-pro:6.0.0
```

### Migrering av binærfiler

Denne nye utgivelsen halverer lagringsbruken for binærfiler.

En migrering som kan kjøres mens tjenesten er i drift, er inkludert i versjon `5.5`, noe som gir minimal nedetid ved oppgraderingen. Før du oppgraderer til Server Pro `v6`, må du sørge for at du allerede kjører den nyeste versjonen av Server Pro `v5.5` ([Versjonsmerknader 5.x.x](https://docs.overleaf.com/on-premises/release-notes/release-notes-5.x.x)) og har kjørt migreringen.

[Se fullstendige migreringsinstruksjoner](https://docs.overleaf.com/on-premises/release-notes/release-notes-5.x.x/binary-files-migration).

### Oppgradering av MongoDB til v8

Denne utgivelsen øker minste MongoDB-versjon til `8.0`.

Hvis du bruker MongoDB `v6` eller eldre, må du oppdatere én hovedversjon om gangen (`v6 → v7 → v8`).

<Warning>

Sørg for at du har en sikkerhetskopi av [databasen](https://docs.overleaf.com/on-premises/maintenance/data-and-backups) **før** du oppgraderer. Ved tilbakerulling må du gjenopprette sikkerhetskopien av databasen.

</Warning>

For instruksjoner om hvordan du oppgraderer MongoDB `v6 → v7 → v8`, se trinn-for-trinn-veiledningen vår [her](https://docs.overleaf.com/on-premises/maintenance/updating-mongodb#example-upgrading-mongodb-from-6.0-to-7.0-toolkit-users).

### Oppgradering av Redis til v7.4

Denne utgivelsen øker også minste Redis-versjon til `7.4`.

Oppdater `REDIS_IMAGE` i `config/overleaf.rc` til `REDIS_IMAGE=7.4`.

### Nye funksjoner

* Lenkedeling kan nå deaktiveres med `OVERLEAF_DISABLE_LINK_SHARING=true`.
* `OVERLEAF_MAINTENANCE_MESSAGE` og `OVERLEAF_MAINTENANCE_MESSAGE_HTML` er nå tilgjengelige for å tilpasse tittelen og innholdet på vedlikeholdssiden.
* `OVERLEAF_USER_HARD_DELETION_DELAY` og `OVERLEAF_PROJECT_HARD_DELETION_DELAY` kan konfigureres (i millisekunder) for å endre forsinkelsen før slettede brukere/prosjekter utløper (standard er 90 dager).

### Feilrettinger

* Rettet visning av bunntekst med lenker.
* Forbedret feilmeldinger ved feil under SAML-innlogging.
* Rettet at en revisjonsloggoppføring ikke ble lagt til når en brukers administratorstatus oppdateres ved SSO-innlogging.
* Rettet feil i historikkpanelet når TLS er aktivert i Redis.
* Kompileringer kan nå stoppes ved bruk av kompilering uten sandkasse.

### Andre endringer

* Alle lenker til statussiden (angitt via `OVERLEAF_STATUS_PAGE_URL`) bruker nå `HTTPS` og åpnes i en ny nettleserfane.
