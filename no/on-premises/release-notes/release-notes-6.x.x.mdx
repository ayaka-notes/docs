## Ayakaleaf Pro 6.3.2

<strong>Utgivelsesdato:</strong> 2026.10.23

Se: [https://github.com/ayaka-notes/ayakaleaf-pro/releases/tag/pro-v6.3.2](https://github.com/ayaka-notes/ayakaleaf-pro/releases/tag/pro-v6.3.2)

Vi er svært stolte av å kunngjøre utgivelsen av Overleaf Pro 6.3.2. Oppstrøms Overleaf 6.3.2 er en sikkerhetsutgivelse som oppdaterer Node.js, og vi leverer den sammen med Gitea Sync og feilrettingene som er funnet siden 6.3.1.

<Info>

Gitea Sync leveres i 6.3.2 som en **tidlig forhåndsversjon** (early preview) for gradvis testing, og blir offisielt lansert i v6.4.0. Konfigurasjonen og virkemåten kan fortsatt endres før den tid. Den er deaktivert som standard. Rapporter eventuelle problemer på [GitHub](https://github.com/ayaka-notes/ayakaleaf-pro/issues).

</Info>

### Endringer

* Toveis Gitea Sync (tidlig forhåndsversjon), for gitea.com og selvdriftet Gitea 1.23+.
* Node.js 24.22.1, sikkerhetsoppdateringen i oppstrøms Overleaf 6.3.2.
* Feilrettinger funnet av E2E-testsystemet vårt og Internal Horizon Issue Investigation.

#### Funksjon 01: Gitea Sync (forhåndsversjon)

Toveis synkronisering med Gitea, på samme måte som GitHub Sync og GitLab Sync fungerer: koble til kontoen din, importer et repositorium fra menyen for nytt prosjekt, eksporter et prosjekt, push og pull, og slå sammen via pull requests. Overleaf omgår aldri grenbeskyttelsen i repositoriet. Se [Gitea-synkronisering](/no/on-premises/configuration/overleaf-toolkit/gitea-synchronisation).

### Feilrettinger

* GitHub, GitLab og Gitea Sync: når en fil som er slettet i repositoriet, ikke kan slettes i Overleaf, mislykkes synkroniseringen og kan prøves på nytt, i stedet for å rapportere suksess og la filen bli liggende i prosjektet. En `git push` som sletter en fil, mislykkes på samme måte ([#121](https://github.com/ayaka-notes/ayakaleaf-pro/issues/121)).
* Git bridge: et dokument som er opprettet i editoren med en filtype som ikke er tekst (for eksempel `.csv`), forblir et redigerbart dokument når en `git push` endrer det.
* Sporing av endringer: utloggede redaktører av et prosjekt som er delt via lenke, kan slette kommentartråder, men kan ikke lenger løse eller gjenåpne dem. Gjennomlesere kan slette sine egne svar.
* Malgalleri: publisering av en mal krever tilgang til prosjektet.
* Learn: hurtigbufrede hjelpesider forblir tilgjengelige når wikien ikke kan nås.

### Oppgradering

* Fra 6.3.1 eller 6.3.0: ingen migrering er nødvendig. Hent det nye imaget og start på nytt.
* Fra 6.2.x eller eldre med Zotero eller Mendeley i bruk: kjør først Zotero-/Mendeley-migreringen i [6.3.0](#ayakaleaf-pro-6.3.0).
* Gitea Sync er deaktivert som standard og trenger bare nye miljøvariabler.

Se [Dropbox-synkronisering](/no/on-premises/configuration/overleaf-toolkit/dropbox-synchronisation).

### Feilrettinger

* Autentisering: lokale kontoer kan angi og endre passordet sitt på SSO-instanser, og OIDC-brukere kan ikke lenger endre sin egen e-postadresse ([#112](https://github.com/ayaka-notes/ayakaleaf-pro/pull/112)). Innloggingsmetodene LDAP, SAML og OIDC bevares, og utlogging med SAML/OIDC fungerer igjen. Se [Kontoer og passord](/no/on-premises/configuration/overleaf-toolkit/authentication#accounts-and-passwords).
* LDAP, SAML og OIDC: navneattributter med flere verdier (som `cn`) får ikke lenger innloggingen til å mislykkes, og OIDC-e-postadresser gjøres om til små bokstaver slik som for LDAP og SAML, så en konto der IdP-en sender e-postadressen med annen bruk av store og små bokstaver, kobles til i stedet for å feile.
* Suspenderte brukere: når en bruker suspenderes, avsluttes øktene deres og de åpne editorene lukkes. Git-tokenene og MCP-nedlastingene deres avvises.
* GitHub Sync: bare eieren kan eksportere et prosjekt, endringer som gjøres under en pull, forblir ventende, tomme filer synkroniseres, manuelle sammenslåinger verifiseres på GitHub, og et erstattet token tilbakekalles ved ny tilkobling.
* Zotero / Mendeley: viser en melding om å koble til på nytt når påloggingsinformasjonen ikke lenger fungerer, og indekserer referanser på nytt etter en import.
* Eksterne API-forespørsler (Zotero, Mendeley, GitHub, GitLab, nettsøk) får et tidsavbrudd for tilkobling på 3 s i stedet for 1 s ([#106](https://github.com/ayaka-notes/ayakaleaf-pro/pull/106)).
* Sporing av endringer: gjennomgangsdata inkluderer dokumenter som ikke er lastet inn, og ulagrede endringer (fra [yu-i-i/overleaf-cep#262](https://github.com/yu-i-i/overleaf-cep/pull/262)).
* Error assistant: foreslår bare rettelser for dokumenter i prosjektet ([#103](https://github.com/ayaka-notes/ayakaleaf-pro/pull/103)).
* Administrasjonspanel: gjenoppretting av et slettet prosjekt, endring av eiere og redigering av brukere fungerer riktig. Søk bruker teksten bokstavelig, og en mislykket e-post stopper ikke lenger oppretting eller sletting av kontoer.
* Malgalleri: en ugyldig sortering returnerer 400 i stedet for 500, mal-ID-er valideres, og publisering av et prosjekt uten hovedfil ber om en.
* Git bridge: nginx videresender `/git/` til `GIT_BRIDGE_HOST` og `GIT_BRIDGE_PORT`, og interne ruter skjules.
* Sandboxed compiles: containere for nylig kompilerte prosjekter beholdes for gjenbruk.

### Oppgradering

* Fra 6.3.0: ingen migrering er nødvendig. Hent det nye imaget og start på nytt.

Dropbox Sync trenger i tillegg at MongoDB-indeksene opprettes én gang, før brukerne kobler til kontoene sine: se [Opprett databaseindeksene](/no/on-premises/configuration/overleaf-toolkit/dropbox-synchronisation#create-the-database-indexes).

<Accordion title="Zotero-/Mendeley-migrering for eksisterende installasjoner">

Når du oppgraderer til det nyutgitte 6.3.0-imaget, migrerer du eksisterende metadata for lenkede bibliografier fra Zotero/Mendeley med skriptet nedenfor. Denne migreringen hører til rettelsen `12031b8dfd`.

Den gir `zoteroGroupId` / `mendeleyGroupId` nytt navn til `group_id`, gir `importedByUserId` nytt navn til `importer_id` og fjerner `importedByName`.

Ta sikkerhetskopi av MongoDB og stopp applikasjonen før du kjører migreringen. La MongoDB kjøre. Åpne skallet (erstatt `mongo` med navnet på containeren din):

```bash
docker exec -it mongo mongosh
```

Kjør følgende i `mongosh` (erstatt `sharelatex` med navnet på databasen din):

```javascript
use sharelatex

(async () => {
  let updated = 0
  await db.projects.find({}, { rootFolder: 1 }).forEach(async project => {
    const changes = {}
    function visit(folders, path) {
      for (const [i, folder] of (folders || []).entries()) {
        const folderPath = `${path}.${i}`
        for (const [j, file] of (folder.fileRefs || []).entries()) {
          const data = { ...file.linkedFileData }
          if (!["zotero", "mendeley"].includes(data.provider)) continue
          const groupKey = `${data.provider}GroupId`
          if (![groupKey, "importedByUserId", "importedByName"].some(key => key in data)) continue
          for (const [oldKey, newKey] of [[groupKey, "group_id"], ["importedByUserId", "importer_id"]]) {
            if (data[oldKey] != null && data[oldKey] !== "") {
              const value = String(data[oldKey])
              if (newKey in data && data[newKey] !== value) {
                throw new Error(`Conflicting ${newKey}: project ${project._id}, file ${file._id}`)
              }
              data[newKey] = value
            }
            delete data[oldKey]
          }
          delete data.importedByName
          changes[`${folderPath}.fileRefs.${j}.linkedFileData`] = data
        }
        visit(folder.folders, `${folderPath}.folders`)
      }
    }
    visit(project.rootFolder, "rootFolder")
    if (!Object.keys(changes).length) return
    const result = await db.projects.updateOne(
      { _id: project._id, rootFolder: { $eq: project.rootFolder } },
      { $set: changes }
    )
    if (!result.matchedCount) throw new Error(`Project changed during migration: ${project._id}`)
    updated += result.modifiedCount
  })
  print(`Updated ${updated} project(s).`)
})()
```

Skriptet tar med nestede mapper og endrer bare metadata for Zotero/Mendeley. Det er trygt å kjøre det på nytt: en fullført migrering rapporterer `Updated 0 project(s).` ved neste kjøring. Hvis det stopper med en konflikt, undersøker du prosjektet/filen som rapporteres; tidligere prosjekter kan allerede være migrert.

Start den oppdaterte applikasjonen, last inn editoren på nytt og oppdater en eksisterende bibliografifil som den opprinnelige importøren. Historiske øyeblikksbilder skrives ikke om. For å nedgradere til den gamle applikasjonen gjenoppretter du sikkerhetskopien av MongoDB.

</Accordion>

#### Funksjon 04: Paginering av maler

Galleriet håndterer nå paginering, sortering og søk i MongoDB. Det fungerer uten noen forberedelser; med tusenvis av maler kan du likevel legge til disse indeksene for å holde det raskt (trygt å kjøre på nytt, `mongo`/`sharelatex` = navnene på containeren og databasen din):

```bash
docker exec mongo mongosh sharelatex --quiet --eval '
db.templates.createIndex({category:1,lastUpdated:-1},{name:"category_1_lastUpdated_-1",background:true});
db.templates.createIndex({lastUpdated:-1},{name:"lastUpdated_-1",background:true});
db.templates.createIndex({category:1,name:1},{name:"category_1_name_1_ci",collation:{locale:"en",strength:2},background:true});
db.templates.createIndex({name:1},{name:"name_1_ci",collation:{locale:"en",strength:2},background:true});
'
```

Behold `collation` på de to `*_ci`-indeksene slik de er skrevet — galleriet sender spørringer med samme collation, og MongoDB bruker bare en indeks som samsvarer.

* Slutt å lekke hemmeligheten for prosjektinvitasjonstokenet til loggene. Krypteringsmodulen for invitasjonstokener logget sin egen konfigurasjon ved hver kryptering/dekryptering, inkludert chifferpassordene som er avledet fra `OVERLEAF_INVITE_TOKEN_SECRET`.

Støtter `--dry-run` og en sikkerhetskontroll med `--estimated-docs`.
