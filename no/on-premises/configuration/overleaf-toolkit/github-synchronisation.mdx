### Sette opp GitHub-synkronisering

<Warning>

Du må aktivere [git-bridge](/no/on-premises/configuration/overleaf-toolkit/git-integration) før du kan bruke GitHub-synkronisering.

```dotenv title="config/overleaf.rc"
GIT_BRIDGE_ENABLED=true
```

</Warning>

Gå til [utviklerinnstillingene](https://github.com/settings/developers) for å opprette GitHub OAuth-applikasjonen din, og kopier `CLIENT_ID` og `SECRET`.

**Merk**: når du oppretter OAuth-appen, skriver du inn `${OVERLEAF_SITE_URL}/user/github-sync/oauth2/callback` i **Authorization callback URL**. Ayakaleaf Pro bygger den samme adressen fra `OVERLEAF_SITE_URL`, så det er ingenting å angi for den i `config/variables.env`.

Legg deretter til følgende innstillinger i Overleaf-miljøvariabelfilene dine.

```dotenv title="config/variables.env" wrap
# used to encrypt the user's GitHub access token.
# How to generate: `openssl rand -hex 32`
GITHUB_TOKEN_CIPHER_PASSWORD=0123456789ABCDEFG # changed to yours

# Github Sync Settings
GITHUB_SYNC_ENABLED=true
GITHUB_SYNC_CLIENT_ID=
GITHUB_SYNC_CLIENT_SECRET=

# OAuth callback is: ${OVERLEAF_SITE_URL}/user/github-sync/oauth2/callback
# (Optional) GITHUB_SYNC_PROXY_URL=http://10.0.0.1:10808
```

<Warning>

Før du konfigurerer callback-URL-en for GitHub OAuth, må du sørge for at `OVERLEAF_SITE_URL` er riktig satt.

</Warning>

Hvis du befinner deg i en region med begrenset nettverkstilgang, kan det hende du må konfigurere en proxy for å få tilgang til GitHub. Sett følgende miljøvariabel: `GITHUB_SYNC_PROXY_URL=http://10.0.0.1:10808`. Sørg for at bruken av proxy er i samsvar med lokale lover og forskrifter.

<Warning>

`GITHUB_SYNC_PROXY_URL` må være en vanlig HTTP/HTTPS-videresendingsproxy (for eksempel HTTP-porten til Clash). GitHub-nedlastingsspeil som `gh-proxy.org` støttes ikke.

</Warning>

<Warning>

Ikke bruk `127.0.0.1` som proxy-vert. Hvis proxyen kjører på vertsserveren, bruker du serverens LAN-IP-adresse (som `192.168.1.xx`) og sørger for at proxyen er konfigurert til å godta tilkoblinger fra enheter på det lokale nettverket.

</Warning>

### GitHub Enterprise

<Info>

Støtte for GitHub Enterprise er introdusert fra og med v6.3.1. Tidligere versjoner kobler bare til `github.com`, og variablene nedenfor har ingen effekt.

</Info>

Som standard kobler GitHub-synkronisering til `github.com`. For å bruke GitHub Enterprise Server (selvdriftet) eller GitHub Enterprise Cloud med datalagring i bestemt region (`GHE.com`), setter du `GITHUB_SYNC_URL` til nettadressen til instansen din, den du åpner repositorier med i nettleseren.

```dotenv title="config/variables.env" wrap
# GitHub Enterprise Server
GITHUB_SYNC_URL=https://github.example.com

# or GitHub Enterprise Cloud with data residency
# GITHUB_SYNC_URL=https://octocorp.ghe.com
```

REST- og GraphQL-API-endepunktene utledes fra `GITHUB_SYNC_URL` på samme måte som GitHub CLI gjør:

| `GITHUB_SYNC_URL`             | REST-API                         | GraphQL-API                              |
| ----------------------------- | -------------------------------- | ---------------------------------------- |
| `https://github.com` (standard) | `https://api.github.com`         | `https://api.github.com/graphql`         |
| `https://SUBDOMAIN.ghe.com`   | `https://api.SUBDOMAIN.ghe.com`  | `https://api.SUBDOMAIN.ghe.com/graphql`  |
| `https://HOST` (alle andre)    | `https://HOST/api/v3`            | `https://HOST/api/graphql`               |

Sett bare API-endepunktene når instansen din leverer dem et annet sted, for eksempel bak en API-gateway:

| Variabel                  | Standard                                                                                   |
| ------------------------- | ----------------------------------------------------------------------------------------- |
| `GITHUB_SYNC_URL`         | `https://github.com`                                                                      |
| `GITHUB_SYNC_API_URL`     | Utledet fra `GITHUB_SYNC_URL`, se tabellen ovenfor                                       |
| `GITHUB_SYNC_GRAPHQL_URL` | Utledet fra `GITHUB_SYNC_API_URL` når den er satt (`/api/v3` blir `/api/graphql`, ellers legges `/graphql` til), ellers fra `GITHUB_SYNC_URL` |

<Warning>

* Opprett OAuth-applikasjonen på enterprise-instansen din (_Settings → Developer settings → OAuth Apps_), en applikasjon fra `github.com` fungerer ikke der. Callback-URL-en er den samme: `${OVERLEAF_SITE_URL}/user/github-sync/oauth2/callback`.
* `GITHUB_SYNC_URL` er kun nettadressen. Ikke sett den til en API-adresse som `https://api.github.com` eller `https://HOST/api/v3`, og ikke legg til en organisasjonssti.
* Alle tre adressene må peke til den samme GitHub-instansen.

</Warning>

<Info>

Hvis instansen din bruker et sertifikat fra en privat CA, monterer du CA-sertifikatet i containeren og lar `NODE_EXTRA_CA_CERTS` peke til det, f.eks. `NODE_EXTRA_CA_CERTS=/var/lib/overleaf/certs/github-ca.pem`.

</Info>

<Danger>

Koblede kontoer og prosjekter tilhører instansen de ble koblet til. Før du bytter `GITHUB_SYNC_URL` til en annen instans, må du be brukerne om å koble fra GitHub-kontoen og prosjektene sine.

</Danger>

### Hvem kan koble til og synkronisere

I likhet med Overleaf Cloud er det bare prosjekteieren som kan koble et prosjekt til et GitHub-repositorium. Når det er koblet til, kan alle samarbeidspartnere med redigeringstilgang synkronisere det.

| Handling                                                     | Hvem kan gjøre det                                                  |
| ---------------------------------------------------------- | -------------------------------------------------------------- |
| Eksportere et prosjekt til et nytt GitHub-repositorium                | Prosjekteieren                                              |
| Importere et GitHub-repositorium til et nytt prosjekt              | Enhver bruker, som blir eier av det nye prosjektet             |
| Hente, pushe og slå sammen et koblet prosjekt                      | Eieren og samarbeidspartnere med redigeringstilgang                   |
| Koble et prosjekt fra repositoriet sitt                       | Prosjekteieren                                              |

* Overleaf kommuniserer med GitHub via GitHub-kontoen til brukeren som synkroniserer, så alle samarbeidspartnere som synkroniserer, kobler til sin egen GitHub-konto og må ha tillatelse til å pushe til standardgrenen i repositoriet.
* Samarbeidspartnere med kun lesetilgang kan ikke bruke GitHub-synkronisering for prosjektet.

### Q\&A

<Accordion title="Kan jeg force-pushe til standardgrenen?">

<strong>Svar:</strong> Vi anbefaler det ikke. Overleaf oppdager en force push, advarer om den og overtar den omskrevne grenen, og slår sammen endringene som er gjort i Overleaf siden forrige synkronisering. For å unngå overraskelser bør du beskytte standardgrenen mot force push i innstillingene for repositoriet.

</Accordion>

<Accordion title="Kan jeg gi nytt navn til standardgrenen i et koblet prosjekt?">

<strong>Svar:</strong> Vennligst ikke gjør det. Overleaf fortsetter å synkronisere med grenen prosjektet ble koblet til. For å synkronisere med en annen gren kobler du fra prosjektet og importerer deretter repositoriet til et nytt prosjekt, som bruker den gjeldende standardgrenen.

</Accordion>

<Accordion title="GitHub-synkronisering viser «Something wrong with GitHub request»">

<strong>Svar:</strong> Denne meldingen betyr at serveren ikke kunne nå GitHub, for eksempel på grunn av et problem med nettverk, DNS, TLS eller proxy. Kjør `bin/logs web` for å se hele feilen. Hvis serveren trenger en proxy for å nå GitHub, setter du `GITHUB_SYNC_PROXY_URL`.

</Accordion>

<Accordion title="Bør jeg deaktivere «Expire user access tokens» i GitHub OAuth-appen?">

<strong>Svar:</strong> Ja. GitHub-synkroniseringen fornyer ikke utløpte tokener. Med utløpende tokener aktivert må brukerne koble til GitHub på nytt hver gang tokenet deres utløper.

</Accordion>

<Accordion title="Må instansen min være tilgjengelig fra internett?">

<strong>Svar:</strong> Nei. Kobling av en konto går gjennom brukerens nettleser, så OAuth-callback-adressen trenger bare å kunne åpnes i brukerens nettleser. Serveren trenger bare å nå GitHub; hvis den trenger en proxy til det, setter du `GITHUB_SYNC_PROXY_URL`. GitHub kaller aldri instansen din: et prosjekt synkroniseres bare når en bruker synkroniserer det i editoren.

</Accordion>
