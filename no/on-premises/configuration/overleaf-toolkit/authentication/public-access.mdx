Du kan åpne Overleaf-instansen for personer uten konto på tre måter:

* [Project Access](/no/on-premises/configuration/overleaf-toolkit/public-access#project-access  "mention"): la gjester åpne en delt prosjektlenke uten å logge inn
* [Page Access](/no/on-premises/configuration/overleaf-toolkit/public-access#page-access  "mention"): la utloggede besøkende bla gjennom sider som `/learn`, `/templates` og `/devs`
* [Public Registration](/no/on-premises/configuration/overleaf-toolkit/public-access#public-registration  "mention"): la brukere registrere seg selv, eventuelt med en aktiverings-e-post og begrenset til e-postdomener

### Prosjekttilgang

<Info>

Som standard må en bruker **logge inn** før vedkommende kan bli med i en samarbeidsøkt for prosjektredigering, selv om brukeren har fått en delingslenke til prosjektet.

</Info>

For å tillate anonym tilgang til prosjekter som deles via lenke, setter du begge variablene nedenfor:

```dotenv title="config/variables.env"
OVERLEAF_ALLOW_ANONYMOUS_READ_AND_WRITE_SHARING=true
OVERLEAF_ALLOW_PUBLIC_ACCESS=true
```

`OVERLEAF_ALLOW_ANONYMOUS_READ_AND_WRITE_SHARING` aktiverer anonym lese- og skrivetilgang til prosjekter som deles via lenke.

`OVERLEAF_ALLOW_PUBLIC_ACCESS` hindrer at uautentiserte brukere blir omdirigert til innloggingssiden.

Opprett containerne på nytt med `bin/up`. Åpne deretter en delingslenke i et privat vindu.

### Sidetilgang

Som standard (når `OVERLEAF_ALLOW_PUBLIC_ACCESS` ikke er satt) omdirigerer **alle** sider unntatt innloggings- og registreringssidene utloggede besøkende til innloggingssiden. Dette gjelder også sider som er ment å være offentlige, så lenker til dem fungerer bare for brukere som allerede er logget inn.

Med `OVERLEAF_ALLOW_PUBLIC_ACCESS=true` kan utloggede besøkende åpne:

| Side                                                                  | Krever                           |
| --------------------------------------------------------------------- | -------------------------------- |
| LaTeX-hjelp på `/learn` (se [adding-latex-user-help.md](/no/on-premises/configuration/overleaf-toolkit/adding-latex-user-help  "mention")) | `OVERLEAF_PROXY_LEARN=true`      |
| Malgalleriet på `/templates`, malsider, forhåndsvisninger og ZIP-nedlastinger (se [templates.md](/no/on-premises/configuration/overleaf-toolkit/templates  "mention")) | `OVERLEAF_TEMPLATE_GALLERY=true` |
| Siden for Overleaf Import API på `/devs` (se [overleaf-import-api.md](/no/on-premises/configuration/overleaf-toolkit/overleaf-import-api  "mention")) | —                                |

Det gjør det også mulig for [Overleaf Import API](/no/on-premises/configuration/overleaf-toolkit/overleaf-import-api#signed-out-visitors  "mention") å ta vare på en skjemainnsending fra en utlogget besøkende til vedkommende har logget inn.

Prosjektlisten, editoren og oppretting av prosjekter (også fra en mal eller via Import API) krever fortsatt innlogging.

### Offentlig registrering

Offentlig registrering er bare tilgjengelig i [ayaka-notes/ayakaleaf-pro](https://github.com/ayaka-notes/ayakaleaf-pro).

<Danger>

Merk at når du aktiverer offentlig registrering, kan **hvem som helst** med tilgang til Overleaf-instansen registrere seg som bruker.

Med `true` verifiserer ikke registreringsprosessen e-postadresser, så bruk den bare på et intranett eller i et pålitelig miljø, eller bruk i stedet [registrering med aktiverings-e-post](/no/on-premises/configuration/overleaf-toolkit/public-access#registration-with-activation-email).

På en instans med OIDC må du ikke bruke `true`: hvem som helst kan da registrere seg med en kollegas e-postadresse før kollegaens første OIDC-innlogging, noe som ville koblet kollegaen til den kontoen. Bruk [registrering med aktiverings-e-post](/no/on-premises/configuration/overleaf-toolkit/public-access#registration-with-activation-email) eller ingen offentlig registrering, se [Kontoer og passord](/no/on-premises/configuration/overleaf-toolkit/authentication#accounts-and-passwords).

</Danger>

Som standard tillater verken Community Edition eller Overleaf Pro offentlig registrering.

For å aktivere det legger du til dette i `config/variables.env`:

```dotenv title="config/variables.env"
OVERLEAF_ALLOW_PUBLIC_REGISTRATION=true
```

Opprett containerne på nytt med `bin/up`.

Klikk deretter **Sign up** eller gå til `/register`.

### Registrering med aktiverings-e-post

Registrering med aktiverings-e-post er bare tilgjengelig i [ayaka-notes/ayakaleaf-pro](https://github.com/ayaka-notes/ayakaleaf-pro). Brukerne registrerer seg kun med e-postadressen og angir passordet sitt via lenken i aktiverings-e-posten, slik at bare eieren av en adresse kan bruke kontoen. En liste med domener og jokertegn krever v6.4.0 eller nyere; tidligere versjoner godtar bare ett domene, som `@example.com`.

Før du aktiverer dette, må du konfigurere e-postlevering, ellers får brukerne aldri aktiverings-e-posten. Se [E-postlevering](/no/on-premises/configuration/overleaf-toolkit/email-delivery).

Legg deretter til følgende linje i `config/variables.env`:

```dotenv title="config/variables.env" wrap
OVERLEAF_ALLOW_PUBLIC_REGISTRATION=@example.com,@*.example.org
```

`OVERLEAF_ALLOW_PUBLIC_REGISTRATION` kan settes til:

| Verdi                         | Hvem kan registrere seg                               | E-post verifisert |
| ----------------------------- | ----------------------------------------------------- | :------------: |
| `true`                        | Alle, med e-post og passord                           |       Nei      |
| `@example.com`                | Adresser i `example.com`                              |       Ja       |
| `@*.example.org`              | Adresser i underdomener som `cs.example.org`, ikke selve `example.org` |       Ja       |
| `@example.com,@*.example.org` | Alle de oppførte oppføringene, atskilt med komma      |       Ja       |
| `@*`                          | Alle                                                  |       Ja       |

Domener sammenlignes uten hensyn til store og små bokstaver. For å tillate et domene og underdomenene, oppgir du begge: `@example.org,@*.example.org`.

### Q\&A

<Accordion title="Hva kan en utlogget redaktør gjøre med kommentarer?">

<strong>Svar:</strong> En utlogget bruker som åpner et prosjekt via redigeringslenken, får samme tilgang som en redaktør, bortsett fra handlinger som registrerer hvem som utførte dem:

| Handling                                                 | Utlogget redaktør |
| -------------------------------------------------------- | ----------------: |
| Redigere teksten, vise kommentarer og sporede endringer   |                Ja |
| Godta sporede endringer, bytte redigeringsmodus          |                Ja |
| Slette en kommentar eller en hel tråd                    |                Ja |
| Legge til, svare på eller redigere en kommentar          |               Nei |
| Løse eller gjenåpne en kommentar                         |               Nei |

Gjennomgangspanelet viser fortsatt **Resolve**-knappen for dem, men løsingen mislykkes med en feilmelding.

Brukere som åpner et prosjekt via visningslenken, ser ingen kommentarer i det hele tatt, se [Roller og tillatelser](/no/on-premises/user-and-project-management/roles-and-permissions#collaborating).

</Accordion>
