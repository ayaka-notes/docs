### i18n-konfigurasjon for Overleaf

<Info>

Dette dokumentet beskriver hvordan du konfigurerer internasjonalisering (i18n) for en selvdriftet **Overleaf**-instans.

</Info>

Overleaf er oversatt til flere språk. Med riktig konfigurasjon kan du:

* Kjøre Overleaf-instansen på **ett fast språk**, eller
* Aktivere **flere språk**, slik at brukerne kan bytte språk dynamisk, på samme måte som på `www.overleaf.com`.

***

#### Konfigurasjon med ett språk

Nettstedsspråket konfigureres med miljøvariabelen `OVERLEAF_SITE_LANGUAGE`.

Støttede språkkoder inkluderer:

* `en` - engelsk (standard)
* `es` - spansk
* `pt` - portugisisk
* `de` - tysk
* `fr` - fransk
* `cs` - tsjekkisk
* `nl` - nederlandsk
* `sv` - svensk
* `it` - italiensk
* `tr` - tyrkisk
* `zh-CN` - kinesisk (forenklet)
* `no` - norsk
* `da` - dansk
* `ru` - russisk
* `ko` - koreansk
* `ja` - japansk
* `pl` - polsk
* `fi` - finsk

Engelsk er standardspråket. For å endre grensesnittspråket (for eksempel til forenklet kinesisk) legger du til følgende linje i `config/variables.env`:

```bash title="config/variables.env"
OVERLEAF_SITE_LANGUAGE=zh-CN
```

Bruk deretter konfigurasjonen:

```bash
bin/up
```

Når tjenestene har startet på nytt, skal grensesnittspråket i menyene i nettgrensesnittet gjenspeile den nye innstillingen.

#### Konfigurasjon med flere språk

For at brukerne skal kunne **bytte språk uten å logge ut**, må Overleaf-instansen konfigureres til å levere ulike språk basert på domenenavn.

Dette avsnittet forutsetter at:

* Hoveddomenet ditt er `overleaftest.com`
* Du har et **wildcard-TLS-sertifikat** (f.eks. `*.overleaftest.com`)
* Du **ikke bruker `localhost`** (siden det ikke støtter språkruting basert på underdomener)

For lokal testing kan du bruke et domene som `dev-overleaf.com`.

<Steps>
<Step title="TLS-proxykonfigurasjon (Nginx)">
TLS-omvendt-proxyen din må videresende den opprinnelige `Host`-headeren slik at Overleaf kan avgjøre hvilket språkdomene brukeren besøkte.

Sørg for at følgende direktiv er til stede:

```nginx
proxy_set_header Host $host;
```

Her er et eksempel på en Nginx-konfigurasjon:

```nginx
server {
    listen 443 ssl;
    server_name    _; # Catch all, see http://nginx.org/en/docs/http/server_names.html
    server_name *.overleaftest.com;
    ssl_certificate /etc/nginx/ssl/nginx.crt;
    ssl_certificate_key /etc/nginx/ssl/nginx.key;
    ssl_protocols               TLSv1 TLSv1.1 TLSv1.2;
    ssl_prefer_server_ciphers   on;
    # used cloudflares ciphers https://github.com/cloudflare/sslconfig/blob/master/conf
    ssl_ciphers EECDH+CHACHA20:EECDH+AES128:RSA+AES128:EECDH+AES256:RSA+AES256:EECDH+3DES:RSA+3DES:!MD5;

    # config to enable HSTS(HTTP Strict Transport Security) https://developer.mozilla.org/en-US/docs/Security/HTTP_Strict_Transport_Security
    # to avoid ssl stripping https://en.wikipedia.org/wiki/SSL_stripping#SSL_stripping	
    add_header Strict-Transport-Security "max-age=31536000; includeSubdomains;";
    server_tokens off;
    add_header X-Frame-Options SAMEORIGIN;
    add_header X-Content-Type-Options nosniff;
    client_max_body_size 50M;

    location / {
        proxy_pass http://localhost:5000; # change to whatever host/port the docker container is listening on.
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_read_timeout 3m;
        proxy_send_timeout 3m;
        
        # add this to your nginx conf
        proxy_set_header Host $host;
    }
}
```
</Step>

<Step title="Konfigurer cookie-domene">
For å hindre at brukere blir logget ut når de bytter språk, må informasjonskapsler deles på tvers av språkunderdomenene.

Legg til følgende linje i `config/variables.env`:

```env title="config/variables.env"
# Note the leading dot
COOKIE_DOMAIN=.overleaftest.com
```

Dette sikrer at autentiseringskapslene er gyldige for alle underdomener under `overleaftest.com`.
</Step>

<Step title="Kobling mellom språk og domene">
Deretter definerer du hvordan språkkoder kobles til underdomener ved hjelp av\
`OVERLEAF_LANG_DOMAIN_MAPPING`.

#### Eksempelkonfigurasjon

```dotenv title="config/variables.env" wrap
OVERLEAF_LANG_DOMAIN_MAPPING='{"www": {"lngCode": "en","url": "https:\/\/www.overleaftest.com"},"cn": {"lngCode": "zh-CN","url": "https:\/\/cn.overleaftest.com"}}'
```

Med denne konfigurasjonen:

* `https://www.overleaftest.com` → engelsk grensesnitt
* `https://cn.overleaftest.com` → forenklet kinesisk grensesnitt

Du kan utvide denne koblingen med flere språk og underdomener etter behov.

<Warning>

Vi anbefaler å servere hovednettstedet på `www` og alltid ta med en `www`-nøkkel: sett `OVERLEAF_SITE_URL` til `www`-adressen (for eksempel `https://www.overleaftest.com`), la `www`-nøkkelen peke dit, og omdiriger apex-domenet dit som vist nedenfor. `www`-nøkkelen er hovednettstedet og kan bruke hvilket som helst språk. Uten den blir standardoppføringen for `www` stående, og språkvelgeren viser et ekstra engelsk element som lenker til `http://127.0.0.1:3000`.

</Warning>
</Step>

<Step title="Omdiriger apex-domenet">
Til slutt omdirigerer du apex-domenet (`overleaftest.com`) til standardspråkdomenet (`www.overleaftest.com`).

```nginx
server{
    listen 80;
    server_name overleaftest.com;
    return 301 https://www.overleaftest.com$request_uri;
}

server {
    listen 443 ssl http2;
    server_name overleaftest.com;
    ssl_certificate     /path/to/fullchain.cer;
    ssl_certificate_key /path/to/overleaftest.com.key;
    return 301 https://www.overleaftest.com$request_uri;
}
```
</Step>
</Steps>

### Spørsmål og svar

<Accordion title="Hvor er knappen for å bytte språk?">

<strong>Svar:</strong> Språkknappen (oversettelsesikonet) finnes i bunnteksten på siden, for eksempel nederst i prosjektlisten. Den vises ikke i editoren.

Knappen vises bare når `OVERLEAF_LANG_DOMAIN_MAPPING` tilordner to eller flere språk, som beskrevet i [Konfigurasjon med flere språk](/no/on-premises/configuration/overleaf-toolkit/localization#multiple-language-configuration). Når bare `OVERLEAF_SITE_LANGUAGE` er satt, bruker hele nettstedet det ene språket, og det finnes ingen knapp.

Når du velger et språk, åpnes den samme siden på domenet for det språket, for eksempel `cn.overleaftest.com`. Valget lagres ikke som en brukerinnstilling.

</Accordion>

<Accordion title="Hvorfor åpner et språk i velgeren `http://127.0.0.1:3000`?">

<strong>Svar:</strong> `OVERLEAF_LANG_DOMAIN_MAPPING` har ingen `www`-nøkkel. Tilordningen slås sammen med standardtilordningen, som har en `www`-oppføring for engelsk med den interne adressen `http://127.0.0.1:3000`. Hvis tilordningen din bare bruker andre nøkler, som `cn` og `en`, beholdes denne standardoppføringen og vises i velgeren.

Legg til en `www`-nøkkel med adressen fra `OVERLEAF_SITE_URL`, fjern en eventuell andre oppføring for samme språk, og kjør deretter `bin/up -d`:

```dotenv
OVERLEAF_LANG_DOMAIN_MAPPING='{"www":{"lngCode":"en","url":"https://www.overleaftest.com"},"cn":{"lngCode":"zh-CN","url":"https://cn.overleaftest.com"}}'
```

</Accordion>
