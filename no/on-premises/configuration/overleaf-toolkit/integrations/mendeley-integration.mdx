<Info>

Denne funksjonaliteten leveres av [ayaka-notes/ayakaleaf-pro](https://github.com/ayaka-notes/ayakaleaf-pro) med støtte for OAuth 2.0 og er tilgjengelig fra v6.3.0. Vi tar gjerne imot tilbakemeldinger hvis du støter på problemer.

</Info>

#### Sette opp Mendeley-integrasjon

1. Gå til [denne lenken](https://dev.mendeley.com/myapps.html) for å registrere en Mendeley OAuth-applikasjon
2. Konfigurer **Redirect URL** som: `${OVERLEAF_SITE_URL}/user/mendeley/oauth/callback`
3. Noter den genererte **ID**-en (vanligvis numerisk, som `24061` nedenfor) og **Secret** for applikasjonen din
4. Endre filen `config/variables.env`&#x20;
5. Behold bare Authorisation Flow: Elsevier (som anbefalt)

```dotenv title="config/variables.env"
#################
#   Mendeley    #
#################
# 'mendeley' must be in ENABLED_LINKED_FILE_TYPES (keep 'zotero' too if you use both)
ENABLED_LINKED_FILE_TYPES=project_file,project_output_file,url,mendeley

# From a Mendeley OAuth application (register at https://dev.mendeley.com/myapps.html)
# Redirect URL -> ${OVERLEAF_SITE_URL}/user/mendeley/oauth/callback
MENDELEY_CLIENT_ID=
MENDELEY_CLIENT_SECRET=
# Encrypts the Mendeley OAuth tokens in mongo; if unset, a key file is generated
# in /var/lib/overleaf/data on first use
# How to generate: `openssl rand -hex 32`
MENDELEY_CIPHER_PASSWORD=
# Optional: route the module's server-side Mendeley requests (OAuth + API) through
# an HTTP proxy (must be reachable from the web container; same as github-sync)
# http://10.0.0.1:10808
# (Optional) MENDELEY_PROXY_URL=
```

<Info>

&#x20;`mendeley` må være inkludert i `ENABLED_LINKED_FILE_TYPES` (behold også `zotero` i listen hvis du bruker begge). `MENDELEY_CLIENT_ID` og `MENDELEY_CLIENT_SECRET` kommer fra den registrerte OAuth-applikasjonen din. Chifferpassordet krypterer Mendeley OAuth-tokenene i MongoDB (generer et med `openssl rand -hex 32`); uten det genereres en nøkkelfil i datavolumet ved første gangs bruk. Du kan eventuelt angi `MENDELEY_PROXY_URL` for å rute Mendeley-forespørslene på serversiden (OAuth + API) gjennom en HTTP-proxy som er tilgjengelig fra web-containeren.

</Info>

### Merknader

<Warning>

Når du oppgraderer en eksisterende installasjon med lenkede Mendeley-bibliografifiler til den gjenutgitte 6.3.0, må du følge [migreringsinstruksjonene for Zotero / Mendeley](/no/on-premises/release-notes/release-notes-6.x.x#ayakaleaf-pro-6.3.0  "mention"). Nye installasjoner trenger ikke denne migreringen.

</Warning>

<Danger>

Siden Ayakaleaf er en samarbeidsplattform, er det for økt sikkerhet fra og med versjon 6.3.0 bare den opprinnelige oppretteren av en referansefil (`bib`) som kan oppdatere den importerte filen.

</Danger>

Anta for eksempel at prosjekteieren, bruker A, aktiverer lenkedeling og oppretter en `test.bib`-fil i prosjektet, lenket til sin egen Zotero-konto. Hvis en annen bruker, bruker B, får tilgang til prosjektet via den delte lenken, kan bruker B fortsatt lese og laste ned `test.bib`, men får ikke lov til å oppdatere eller importere filen på nytt fra Zotero. Bare bruker A, som den opprinnelige oppretteren av referansefilen, kan utføre oppdateringer. Med andre ord er det bare den opprinnelige oppretteren av `.bib`-filen som har tillatelse til å oppdatere den.
