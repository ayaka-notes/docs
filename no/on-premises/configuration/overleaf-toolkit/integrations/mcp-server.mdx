Hvert prosjekt har en MCP-server, slik at AI-klienter som Claude Code, Codex, Cursor, VS Code eller Gemini CLI kan arbeide med det: lese og redigere filene, kompilere prosjektet, lese LaTeX-loggen, laste ned PDF-en og svare på kommentarer. Fra v6.3.3 kan de også bla gjennom historikken og gjenopprette versjoner, gå gjennom sporede endringer, legge til kommentarer, bruke prosjektchatten og flytte filer.

<Info>

Denne funksjonen er utviklet av [ayaka-notes/ayakaleaf-pro](https://github.com/ayaka-notes/ayakaleaf-pro). Den er introdusert fra og med v6.3.1. Verktøyene for historikk, sporede endringer, prosjektchat, nye kommentarer og flytting av filer finnes fra v6.3.3, se [Nytt i v6.3.3](/no/on-premises/user-guide/users/mcp-server#new-in-v6.3.3).

</Info>

### Oppsett {#setup}

MCP-serveren følger med Git-integrasjonen: aktiver [git-bridge](/no/on-premises/configuration/overleaf-toolkit/integrations/git-integration), så er MCP-serveren også tilgjengelig. Det er ikke noe annet å konfigurere.

### Koble til en AI-klient {#connect-an-ai-client}

1. Generer et Git-autentiseringstoken i **Account Settings**. Det samme tokenet brukes for MCP-serveren og for Git.
2. Åpne **Integrations** i editoren og klikk **MCP server**. Der vises adressen til prosjektets MCP-server, `https://<your-overleaf>/project/<project_id>/mcp`, og hvordan du legger den til i hver AI-klient: kopier kommandoen, og erstatt `<token>` med tokenet ditt.

Tokenet sendes som HTTP-headeren `Authorization: Bearer <token>`. Kommandoen for Claude Code er for eksempel:

```bash
claude mcp add --transport http overleaf \
  https://<your-overleaf>/project/<project_id>/mcp \
  --header "Authorization: Bearer <token>"
```

### Bruk {#usage}

Når klienten er tilkoblet, spør du AI-klienten med vanlige ord. For eksempel:

| Du spør | AI-klienten bruker |
| --- | --- |
| _Rett skrivefeilene i innledningen._ | `read_file`, `edit_file`: endringene vises i sanntid i editoren |
| _Kompiler prosjektet og rett LaTeX-feilene._ | `compile`, `get_compile_log`, `edit_file` |
| _Svar på de åpne kommentarene, og løs dem deretter._ | `list_comments`, `reply_to_comment`, `resolve_comment` |
| _Bytt til XeLaTeX og last ned PDF-en._ | `update_settings`, `compile`, `get_output_file_link` |
| _Skriv om sammendraget som en sporet endring._ | `read_file`, `edit_file` med `trackChanges` (v6.3.3) |
| _Hva er endret siden den innsendte versjonen?_ | `list_versions`, `list_changes`, `diff` (v6.3.3) |
| _Flytt kapitlene til en mappe som heter chapters._ | `move_file` (v6.3.3) |

### Verktøy {#tools}

| Gruppe | Verktøy |
| --- | --- |
| Prosjekt | `get_clone_info`, `get_settings`, `update_settings` |
| Filer | `list_files`, `read_file`, `edit_file`, `write_file`, `delete_file`, `move_file`, `create_folder` |
| Kompilering | `compile`, `get_compile_log`, `get_output_file_link`, `word_count` |
| Kommentarer | `list_comments`, `reply_to_comment`, `resolve_comment`, `reopen_comment`, `add_comment`, `edit_comment_message`, `delete_comment_message` |
| Sporede endringer | `list_tracked_changes`, `accept_tracked_changes`, `reject_tracked_changes` |
| Historikk | `list_versions`, `list_changes`, `diff`, `create_version`, `delete_version`, `restore_file`, `restore_project` |
| Chat | `list_chat_messages`, `send_chat_message` |

v6.3.3 har 33 verktøy, eller 31 med `OVERLEAF_DISABLE_CHAT=true`, som fjerner chatverktøyene. v6.3.1 og v6.3.2 har de andre 17: alt over unntatt `move_file`, `create_folder`, `add_comment`, `edit_comment_message`, `delete_comment_message`, verktøyene for sporede endringer, chatverktøyene og historikkverktøyene utenom `list_versions`. I v6.3.3 leser `read_file` også en fil i en versjon av historikken, `edit_file` og `write_file` tar `trackChanges`, og `update_settings` angir også språket for stavekontrollen.

Endringer gjort med `edit_file`, `write_file` og `move_file` vises direkte i editoren og slås sammen med samarbeidspartnernes. For mange filer samtidig eller binære filer kan AI-klienten også klone prosjektet med Git og pushe.

Med `trackChanges` blir en endring av en eksisterende fil en sporet endring av tokenets bruker, selv når sporing av endringer er slått av i prosjektet; en ny fil blir det aldri. Uten `trackChanges` følger endringene prosjektets innstilling for sporing av endringer.

### Tillatelser {#permissions}

MCP-serveren følger prosjektets delingsinnstillinger, på samme måte som Git:

* Alle som kan se prosjektet, kan lese det, kompilere det og laste ned utdataene.
* Bare eieren og redaktører kan endre filene og innstillingene, gjenopprette versjoner og godta eller avvise sporede endringer.
* Korrekturlesere kan også legge til kommentarer og svare på dem, løse, gjenåpne eller slette kommentarene de startet, og lagre versjoner. De kan ikke redigere filer, heller ikke som sporede endringer.
* Alle redigerer bare sine egne kommentarmeldinger, og korrekturlesere sletter bare sine egne.
* Bare eieren sletter versjoner som andre har lagret.
* Lesere som ble med via en lenke, kan ikke se kommentarene, de sporede endringene, historikken eller chatten, akkurat som i editoren. Inviterte lesere kan se dem og bruke chatten.
* Hvis prosjekteieren ikke har **Full project history**, viser historikkverktøyene bare endringene fra de siste 24 timene, slik historikkpanelet gjør. Administratorer ser alle.

Brukerveiledningen har en tabell over hva hver rolle kan gjøre, se [Hvem kan gjøre hva](/no/on-premises/user-guide/users/mcp-server#who-may-do-what).

### Spørsmål og svar {#q&a}

<Accordion title="Jeg ser ikke Integrations eller MCP server i editoren">

<strong>Svar:</strong> MCP-serveren har ingen egen miljøvariabel. Den aktiveres med `GIT_BRIDGE_ENABLED=true` i `config/overleaf.rc`, se [Git-integrasjon](/no/on-premises/configuration/overleaf-toolkit/integrations/git-integration). Etter at du har endret den, kjører du `bin/up -d`. Uten git-bridge viser ikke editoren fanen **Integrations** i venstre felt.

</Accordion>

<Accordion title="AI-klienten sier «Track changes is off for this project»">

<strong>Svar:</strong> Klienten ba om en sporet endring, men kontoen til prosjekteieren har ikke sporing av endringer. Klikk **Admin**, deretter **Manage Users**, åpne eieren og slå på **Track changes** på fanen **Features**, se [Features](/no/on-premises/user-guide/administrators/user-management#features). Endringer uten `trackChanges` fungerer fortsatt.

</Accordion>

<Accordion title="AI-klienten ser bare endringene fra de siste 24 timene">

<strong>Svar:</strong> Kontoen til prosjekteieren har ikke full prosjekthistorikk, så historikkverktøyene viser det historikkpanelet viser: endringene fra de siste 24 timene. Klikk **Admin**, deretter **Manage Users**, åpne eieren og slå på **Full project history** på fanen **Features**, se [Features](/no/on-premises/user-guide/administrators/user-management#features).

</Accordion>
