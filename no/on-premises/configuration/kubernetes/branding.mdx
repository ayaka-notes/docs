**web**-tjenesten gjengir tittelen, logoen, lenkene i toppteksten, bunntekstene og vedlikeholdssiden fra miljøvariabler. Hver innstilling og formatet dens er beskrevet i [Merkevarebygging](/no/on-premises/configuration/overleaf-toolkit/branding); på Kubernetes legges de i ConfigMap-en.

| | |
| --- | --- |
| Tjeneste | web, i hver Ayakaleaf Pro-pod; leses når web starter |
| Nettverk | ingen: logoer er URL-er som nettleseren laster |
| Periodiske jobber | ingen (web sjekker vedlikeholdsfilen hvert 5. sekund, se nedenfor) |

### Konfigurasjon

```yaml title="30-config.yaml (additions)" wrap
  OVERLEAF_NAV_TITLE: Our Overleaf Instance
  OVERLEAF_HEADER_IMAGE_URL: https://example.com/img/logo.png
  OVERLEAF_HEADER_EXTRAS: '[{"text":"Help","url":"https://example.com/help","class":"subdued"}]'
  OVERLEAF_LEFT_FOOTER: '[{"text":"Run by the IT department"}]'
  OVERLEAF_RIGHT_FOOTER: '[{"text":"Imprint","url":"https://example.com/imprint"}]'
  OVERLEAF_MAINTENANCE_MESSAGE: Our Overleaf Instance is down for maintenance and will be back shortly.
```

```bash
kubectl apply -f 30-config.yaml
kubectl -n overleaf rollout restart deployment/overleaf     # or statefulset/overleaf
```

Sett JSON-verdier i enkle anførselstegn, som ovenfor, slik at YAML beholder dem som én streng. Ugyldig JSON i `OVERLEAF_HEADER_EXTRAS` eller bunntekstene ignoreres og logges bare ved oppstart.

### Vedlikeholdsmodus

Vedlikeholdssiden vises så lenge filen `/etc/overleaf/site_status` i containeren inneholder `closed`. Hver pod har sin egen kopi av denne filen, og en ny eller omstartet pod starter åpen. For å stenge nettstedet skriver du filen i hver pod:

```bash
for p in $(kubectl -n overleaf get pod -l app=overleaf -o name); do   # app=overleaf-ha for several replicas
  kubectl -n overleaf exec "$p" -- sh -c 'echo closed > /etc/overleaf/site_status'
done
```

Skriv `open` på samme måte for å avslutte. Podene fanger opp endringen innen 5 sekunder.

**Close Editor** i administrasjonspanelet fungerer annerledes: den stenger editoren bare i replikaen som betjente administratorens forespørsel, og den replikaen åpner den igjen når den starter på nytt. Med flere replikaer bruker du heller filen som ovenfor.

### Testet på Kubernetes

På Kubernetes 1.37: med innstillingene ovenfor i ConfigMap-en viste sidene `OVERLEAF_NAV_TITLE`, den venstre bunnteksten og, etter innlogging, lenken fra `OVERLEAF_HEADER_EXTRAS` (innloggingssidene skjuler lenkene i toppteksten). Å skrive `closed` til `/etc/overleaf/site_status` i én pod viste vedlikeholdssiden med `OVERLEAF_MAINTENANCE_MESSAGE` bare på den poden, og `open` avsluttet den i løpet av sekunder. Med tre replikaer stengte Close Editor i administrasjonspanelet editoren bare på replikaen som betjente administratoren, mens de to andre forble åpne.
