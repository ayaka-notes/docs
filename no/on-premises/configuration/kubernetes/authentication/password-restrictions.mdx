**web**-tjenesten kontrollerer lokale passord når brukere registrerer seg, angir eller endrer et passord. SSO-innlogginger (LDAP, SAML, OIDC) påvirkes ikke; passordene deres er identitetsleverandørens ansvar. Se [Passordbegrensninger](/no/on-premises/configuration/overleaf-toolkit/authentication/password-restrictions) for Toolkit.

| | |
| --- | --- |
| Tjeneste | web, i hver Ayakaleaf Pro-pod; leses når web starter |
| Nettverk | ingen |
| Periodiske jobber | ingen |

### Konfigurasjon

Legg til i ConfigMap-en `overleaf-env` og start på nytt:

```yaml title="30-config.yaml (additions)"
  OVERLEAF_PASSWORD_VALIDATION_MIN_LENGTH: "12"
  OVERLEAF_PASSWORD_VALIDATION_MAX_LENGTH: "72"
```

```bash
kubectl apply -f 30-config.yaml
kubectl -n overleaf rollout restart deployment/overleaf     # or statefulset/overleaf
```

| Variabel | Standard | |
| --- | --- | --- |
| `OVERLEAF_PASSWORD_VALIDATION_MIN_LENGTH` | `8` | Korteste passord som godtas. |
| `OVERLEAF_PASSWORD_VALIDATION_MAX_LENGTH` | `72` | Lengste passord som godtas; verdier over `72` behandles som `72`. |

Sett anførselstegn rundt tallene: en ConfigMap inneholder bare strenger.

<Warning>

`OVERLEAF_PASSWORD_VALIDATION_PATTERN` leses, men håndheves ikke: et passord som ikke samsvarer med det, godtas. Bare lengdegrensene gjelder.

</Warning>

### Flere replikaer

Ingenting ekstra: alle replikaer leser den samme ConfigMap-en.

### Testet på Kubernetes

På Kubernetes 1.37 med én replika, `OVERLEAF_PASSWORD_VALIDATION_MIN_LENGTH: "12"` og `OVERLEAF_PASSWORD_VALIDATION_PATTERN: aA$3` i ConfigMap-en, avviste aktivering av en ny konto et passord på 10 tegn og godtok et passord på 20 tegn med bare små bokstaver, som mønsteret ville ha avvist. Ende-til-ende-testene våre for registrering avviser også `123456` som for kort med standardverdiene.
