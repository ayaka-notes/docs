En Kubernetes-distribusjon leser de samme miljøvariablene som Toolkit. Der en Toolkit-side sier «legg dette til i `config/variables.env`», legger du verdien inn i ConfigMap-en `overleaf-env`, eller i Secret-en `overleaf-secrets` når det er et passord, en nøkkel eller et token. Start deretter på nytt:

```bash
kubectl -n overleaf apply -f 30-config.yaml        # after editing the ConfigMap
kubectl -n overleaf patch secret overleaf-secrets --type merge \
  -p '{"stringData":{"GITHUB_TOKEN_CIPHER_PASSWORD":"'"$(openssl rand -hex 32)"'"}}'
kubectl -n overleaf rollout restart deployment/overleaf
```

Verdiene i `config/overleaf.rc` er Toolkit-innstillinger, ikke miljøvariabler; Q\&A-delen på slutten av denne siden forteller hva som erstatter dem.

### Sertifikater og andre filer

Noen funksjoner tar en filsti i stedet for en verdi: SAML-sertifikatene (`OVERLEAF_SAML_IDP_CERT`, ...), LDAP-CA-en (`OVERLEAF_LDAP_TLS_OPTS_CA_PATH`), eller en privat CA for en selvhostet GitHub Enterprise, GitLab eller Gitea (`NODE_EXTRA_CA_CERTS`). Legg filene inn i en Secret og monter den der Toolkit-sidene forventer dem, `/var/lib/overleaf/certs`:

```bash
kubectl -n overleaf create secret generic overleaf-certs --from-file=idp_cert.pem --from-file=ca.pem
```

```yaml title="40-overleaf.yaml (additions)"
          volumeMounts:
            # ...
            - name: certs
              mountPath: /var/lib/overleaf/certs
              readOnly: true
      volumes:
        # ...
        - name: certs
          secret:
            secretName: overleaf-certs
```

Henvis deretter til dem med sti i ConfigMap-en, for eksempel `NODE_EXTRA_CA_CERTS: /var/lib/overleaf/certs/ca.pem`, og start på nytt.

<Warning>

<strong>Cipher-passord.</strong> Sett hvert `*_CIPHER_PASSWORD` for funksjonene du bruker, i Secret-en. Ellers genererer enkelte funksjoner en nøkkelfil i datavolumet ved første bruk: med én replika fungerer det til volumet går tapt, med flere replikaer ville hver replika kryptere med en annen nøkkel.

</Warning>

### Q\&A

<Accordion title="Hvilke Toolkit-innstillinger fra `config/overleaf.rc` trenger jeg?">

<strong>Svar:</strong> Ingen av dem leses av Ayakaleaf Pro. Tilsvarende i Kubernetes:

| `config/overleaf.rc`                         | Kubernetes                                                        |
| -------------------------------------------- | ----------------------------------------------------------------- |
| `OVERLEAF_LISTEN_IP`, `OVERLEAF_PORT`        | Service-en (NodePort) eller din ingress                           |
| `SIBLING_CONTAINERS_ENABLED`                 | `SANDBOXED_COMPILES*` i ConfigMap-en, Docker-socket i poden       |
| `GIT_BRIDGE_ENABLED`                         | [Git-integrasjon](/no/on-premises/configuration/kubernetes/integrations/git-integration)                             |
| `MONGO_ENABLED`, `REDIS_ENABLED`, `MONGO_URL`, `REDIS_HOST` | StatefulSet-ene eller dine administrerte tjenester, `OVERLEAF_MONGO_URL` og `OVERLEAF_REDIS_HOST` |
| `REDIS_AOF_PERSISTENCE`                      | `--appendonly yes` i `20-redis.yaml`                              |
| `NGINX_ENABLED`, `TLS_*`                     | din ingress eller lastbalanserer                                  |

</Accordion>
