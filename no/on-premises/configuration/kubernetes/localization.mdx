**web**-tjenesten velger grensesnittspråket ut fra innstillingene nedenfor, per forespørsel ut fra vertsnavnet nettleseren brukte. Språkene og innstillingene er beskrevet i [Lokalisering](/no/on-premises/configuration/overleaf-toolkit/localization).

| | |
| --- | --- |
| Tjeneste | web, i hver Ayakaleaf Pro-pod; leses når web starter |
| Nettverk | ett vertsnavn per språk, alle rutet til Ayakaleaf Pro |
| Periodiske jobber | ingen |

### Ett språk

```yaml
  OVERLEAF_SITE_LANGUAGE: zh-CN
```

```bash
kubectl apply -f 30-config.yaml
kubectl -n overleaf rollout restart deployment/overleaf     # or statefulset/overleaf
```

### Flere språk på underdomener

<Steps>
<Step title="Rut hver språkvert til Ayakaleaf Pro">
Legg til et DNS-navn per språk, og rut alle til Ayakaleaf Pro med et sertifikat som dekker dem, for eksempel `*.example.com`. Ingressen eller lastbalansereren din må sende `Host`-headeren videre uendret, noe ingress-nginx og HAProxy gjør som standard.

Brukere må nå språkvertene på standardportene (`https://cn.example.com`, ikke `https://cn.example.com:30443`): Ayakaleaf Pro sammenligner verten uten porten.
</Step>

<Step title="ConfigMap">
```yaml title="30-config.yaml (additions)" wrap
  OVERLEAF_SITE_URL: https://www.example.com
  COOKIE_DOMAIN: .example.com
  OVERLEAF_LANG_DOMAIN_MAPPING: '{"www": {"lngCode": "en", "url": "https://www.example.com"}, "cn": {"lngCode": "zh-CN", "url": "https://cn.example.com"}}'
```

`COOKIE_DOMAIN` gjør at innloggingsinformasjonskapselen fungerer på alle språkverter. Sett JSON-en i enkle anførselstegn. Ugyldig JSON i `OVERLEAF_LANG_DOMAIN_MAPPING` stopper alle tjenestene i poden ved oppstart, så kontroller `kubectl -n overleaf get pod` etter omstarten.
</Step>
</Steps>

### Flere replikaer

Språket kommer fra vertsnavnet i hver forespørsel, så det avhenger ikke av replikaen. Lastbalansererens «sticky»-informasjonskapsel settes per vertsnavn med mindre du gir den et domene, så bytte av språk kan flytte en bruker til en annen replika; økten deres ligger i Redis og forblir gyldig.

### Testet på Kubernetes

På Kubernetes 1.37 bak HAProxy, med `OVERLEAF_LANG_DOMAIN_MAPPING` som tilordnet nettstedets vert til engelsk, en `de.`-vert til tysk og en `fr.`-vert med NodePort `:30081` til fransk: nettstedets vert viste engelsk, `de.`-verten tysk, og `fr.`-verten med porten falt tilbake til engelsk, som beskrevet ovenfor.
