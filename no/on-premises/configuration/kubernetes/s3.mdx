Prosjektfiler og historikken deres lagres av **history-v1**-tjenesten, malfiler av **filestore**-tjenesten, begge inne i hver Ayakaleaf Pro-pod. Som standard skriver de til datavolumet; med S3 skriver de til bøtter. Hvilke bøtter og tillatelser som trengs, er beskrevet i [S3](/no/on-premises/configuration/overleaf-toolkit/s3).

| | |
| --- | --- |
| Tjenester | history-v1 (prosjektfiler og historikk), filestore (malfiler), i hver Ayakaleaf Pro-pod |
| Pod → S3 | S3-endepunktet, for hver fil som leses eller skrives |
| Påkrevd | for [flere replikaer](/no/on-premises/configuration/kubernetes/horizontal-scaling): datavolumene deres deles ikke, det gjør bøttene |
| Periodiske jobber | ingen |

<Warning>

Velg S3 før brukerne oppretter prosjekter. En instans som allerede lagrer filer på volumet sitt, trenger [S3-migreringen](/no/on-premises/maintenance/s3-migration) først.

</Warning>

### Konfigurasjon

<Steps>
<Step title="Bøtter og nøkler">
Opprett de tre bøttene `overleaf-template-files`, `overleaf-project-blobs` og `overleaf-chunks` og de to begrensede brukerne hos S3-tjenesten din som beskrevet i [S3-oppsett](/no/on-premises/configuration/overleaf-toolkit/s3#s3-setup), eller kjør Garage i klyngen som vist nedenfor. Legg de fire nøklene i en Secret:

```bash wrap
kubectl -n overleaf create secret generic overleaf-s3 \
  --from-literal=OVERLEAF_FILESTORE_S3_ACCESS_KEY_ID=<filestore key> \
  --from-literal=OVERLEAF_FILESTORE_S3_SECRET_ACCESS_KEY=<filestore secret> \
  --from-literal=OVERLEAF_HISTORY_S3_ACCESS_KEY_ID=<history key> \
  --from-literal=OVERLEAF_HISTORY_S3_SECRET_ACCESS_KEY=<history secret>
```
</Step>

<Step title="ConfigMap">
```yaml title="30-config.yaml (additions)" wrap
  OVERLEAF_FILESTORE_BACKEND: s3
  OVERLEAF_FILESTORE_TEMPLATE_FILES_BUCKET_NAME: overleaf-template-files
  OVERLEAF_FILESTORE_S3_REGION: eu-west-1
  OVERLEAF_HISTORY_BACKEND: s3
  OVERLEAF_HISTORY_PROJECT_BLOBS_BUCKET: overleaf-project-blobs
  OVERLEAF_HISTORY_CHUNKS_BUCKET: overleaf-chunks
  OVERLEAF_HISTORY_S3_REGION: eu-west-1
  # a self-hosted S3 service also needs its endpoint and path-style addressing
  # OVERLEAF_FILESTORE_S3_ENDPOINT: http://garage:3900
  # OVERLEAF_FILESTORE_S3_PATH_STYLE: "true"
  # OVERLEAF_HISTORY_S3_ENDPOINT: http://garage:3900
  # OVERLEAF_HISTORY_S3_PATH_STYLE: "true"
```
</Step>

<Step title="Legg Secret-en til i poden og start på nytt">
I Deployment-en (eller StatefulSet-en) legger du til Secret-en ved siden av de andre:

```yaml
          envFrom:
            - configMapRef: {name: overleaf-env}
            - secretRef: {name: overleaf-secrets}
            - secretRef: {name: overleaf-s3}
```

```bash
kubectl apply -f 30-config.yaml -f 40-overleaf.yaml
kubectl -n overleaf rollout restart deployment/overleaf     # or statefulset/overleaf
```
</Step>
</Steps>

### Garage i klyngen

Uten en S3-tjeneste er [Garage](https://garagehq.deuxfleurs.fr/) en liten S3-server som kjører i klyngen. Oppsettet for [Horisontal skalering](/no/on-premises/configuration/kubernetes/horizontal-scaling) ble testet med den. Kommandoene nedenfor genererer nøklene og oppretter Secret-en `overleaf-s3` selv, så bruk dem i stedet for Secret-kommandoen i trinn 1.

<Info>

MinIO, som brukes i Overleafs eksempel, publiserer ikke lenger containerimages: `minio/minio` er borte fra Docker Hub og quay.io.

</Info>

```yaml title="50-garage.yaml" wrap
apiVersion: v1
kind: ConfigMap
metadata:
  name: garage-config
  namespace: overleaf
data:
  garage.toml: |
    metadata_dir = "/var/lib/garage/meta"
    data_dir = "/var/lib/garage/data"
    db_engine = "lmdb"
    replication_factor = 1
    rpc_bind_addr = "[::]:3901"
    rpc_public_addr = "127.0.0.1:3901"
    # rpc_secret and admin_token come from GARAGE_RPC_SECRET / GARAGE_ADMIN_TOKEN
    [s3_api]
    s3_region = "garage"          # Overleaf's OVERLEAF_*_S3_REGION must match
    api_bind_addr = "[::]:3900"
    [admin]
    api_bind_addr = "[::]:3903"
---
apiVersion: v1
kind: Service
metadata:
  name: garage
  namespace: overleaf
spec:
  selector:
    app: garage
  ports:
    - name: s3
      port: 3900
---
apiVersion: apps/v1
kind: StatefulSet
metadata:
  name: garage
  namespace: overleaf
spec:
  serviceName: garage
  replicas: 1
  selector:
    matchLabels:
      app: garage
  template:
    metadata:
      labels:
        app: garage
    spec:
      containers:
        - name: garage
          image: dxflrs/garage:v2.5.0
          env:
            - name: GARAGE_RPC_SECRET
              valueFrom: {secretKeyRef: {name: garage-secrets, key: rpc_secret}}
            - name: GARAGE_ADMIN_TOKEN
              valueFrom: {secretKeyRef: {name: garage-secrets, key: admin_token}}
          ports:
            - containerPort: 3900
          readinessProbe:
            tcpSocket:
              port: 3900
          resources:
            requests: {cpu: 50m, memory: 64Mi}
            limits: {memory: 512Mi}
          volumeMounts:
            - {name: config, mountPath: /etc/garage.toml, subPath: garage.toml}
            - {name: data, mountPath: /var/lib/garage}
      volumes:
        - name: config
          configMap:
            name: garage-config
  volumeClaimTemplates:
    - metadata:
        name: data
      spec:
        accessModes: [ReadWriteOnce]
        resources:
          requests:
            storage: 10Gi
```

Generer hemmelighetene, start Garage, og opprett deretter oppsettet, bøttene og de to begrensede nøklene. Garage-nøkkel-ID-er er `GK` pluss 24 heksadesimale tegn, hemmeligheter 64 heksadesimale tegn:

```bash wrap
kubectl -n overleaf create secret generic garage-secrets \
  --from-literal=rpc_secret="$(openssl rand -hex 32)" \
  --from-literal=admin_token="$(openssl rand -base64 32)"
kubectl -n overleaf create secret generic overleaf-s3 \
  --from-literal=OVERLEAF_FILESTORE_S3_ACCESS_KEY_ID="GK$(openssl rand -hex 12)" \
  --from-literal=OVERLEAF_FILESTORE_S3_SECRET_ACCESS_KEY="$(openssl rand -hex 32)" \
  --from-literal=OVERLEAF_HISTORY_S3_ACCESS_KEY_ID="GK$(openssl rand -hex 12)" \
  --from-literal=OVERLEAF_HISTORY_S3_SECRET_ACCESS_KEY="$(openssl rand -hex 32)"
kubectl apply -f 50-garage.yaml
kubectl -n overleaf rollout status statefulset/garage

g() { kubectl -n overleaf exec garage-0 -- /garage "$@"; }
s() { kubectl -n overleaf get secret overleaf-s3 -o jsonpath="{.data.$1}" | base64 -d; }
g layout assign -z dc1 -c 8G "$(g status 2>/dev/null | awk '/^[0-9a-f]{16}/{print $1; exit}')"
g layout apply --version 1
for b in overleaf-template-files overleaf-project-blobs overleaf-chunks; do g bucket create "$b"; done
g key import --yes -n overleaf-filestore "$(s OVERLEAF_FILESTORE_S3_ACCESS_KEY_ID)" "$(s OVERLEAF_FILESTORE_S3_SECRET_ACCESS_KEY)"
g key import --yes -n overleaf-history "$(s OVERLEAF_HISTORY_S3_ACCESS_KEY_ID)" "$(s OVERLEAF_HISTORY_S3_SECRET_ACCESS_KEY)"
g bucket allow --read --write overleaf-template-files --key overleaf-filestore
g bucket allow --read overleaf-project-blobs --key overleaf-filestore
g bucket allow --read --write overleaf-project-blobs --key overleaf-history
g bucket allow --read --write overleaf-chunks --key overleaf-history
```

Tillatelsene samsvarer med policyene i [S3](/no/on-premises/configuration/overleaf-toolkit/s3#access-policies). Garage kontrollerer regionen: den er `garage` her, og `OVERLEAF_*_S3_REGION` må være den samme.

Med Garage angir du endepunktet, `PATH_STYLE: "true"` og regionen `garage` for begge tjenestene i ConfigMap-en, som i `60-config.yaml` i [Horisontal skalering](/no/on-premises/configuration/kubernetes/horizontal-scaling).

### Flere replikaer

Alle replikaer må bruke de samme bøttene og nøklene. Ta sikkerhetskopi av bøttene med verktøyene til S3-leverandøren din; replikaenes egne disker inneholder da ingen data som trenger sikkerhetskopi.

### Testet på Kubernetes

På Kubernetes 1.37 med tre replikaer og Garage som ovenfor besto alle ende-til-ende-testene på disse sidene som oppretter prosjekter, laster opp filer, bruker historikken eller publiserer maler, og etterpå inneholdt bøttene `overleaf-project-blobs`, `overleaf-chunks` og `overleaf-template-files` objektene, mens replikaenes egen `/var/lib/overleaf/data/history` forble tom.
