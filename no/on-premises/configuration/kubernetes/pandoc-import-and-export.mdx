Pandoc-konverteringer kjøres av **clsi**-tjenesten i hver Ayakaleaf Pro-pod, på samme måte som kompileringer: clsi ber Docker Engine på noden om å starte en container fra `PANDOC_IMAGE`. **web**-tjenesten viser import- og eksportmenyene. Hva funksjonen gjør og hvordan du bygger imaget, er beskrevet i [Import og eksport med Pandoc](/no/on-premises/configuration/overleaf-toolkit/pandoc-import-and-export).

| | |
| --- | --- |
| Tjenester | web (menyer og ruter), clsi (kjører konverteringen), i hver Ayakaleaf Pro-pod |
| Node | Docker Engine og `PANDOC_IMAGE`, på hver node som kan kjøre Ayakaleaf Pro |
| Krever | [Sandboxed Compiles](/no/on-premises/configuration/kubernetes/sandboxed-compiles) |
| Periodiske jobber | ingen |

### Konfigurasjon

<Steps>
<Step title="Legg imaget inn i Docker på hver node">
Bygg imaget én gang fra mappen `develop/pandoc` i repositoriet [ayakaleaf-pro](https://github.com/ayaka-notes/ayakaleaf-pro), og last det deretter inn i Docker på hver node som kan kjøre Ayakaleaf Pro:

```bash
docker build -t overleaf-pandoc:local develop/pandoc
docker save overleaf-pandoc:local | ssh node-1 sudo docker load    # repeat for every node
```

Eller push det til et register nodene kan nå, og kjør `sudo docker pull` på hver node. Som med TeX Live-imagene må det ligge i **Docker**, ikke bare i containerd.
</Step>

<Step title="ConfigMap">
```yaml
  ENABLE_PANDOC_CONVERSIONS: "true"
  PANDOC_IMAGE: overleaf-pandoc:local
```

Både web og clsi leser `ENABLE_PANDOC_CONVERSIONS` fra den samme ConfigMap-en, så de kan ikke være uenige på Kubernetes.
</Step>

<Step title="Bruk og start på nytt">
```bash
kubectl apply -f 30-config.yaml
kubectl -n overleaf rollout restart deployment/overleaf     # or statefulset/overleaf
```
</Step>
</Steps>

### Flere replikaer

Ingenting ekstra utover at imaget finnes på hver node: hver replika konverterer på sin egen node.

### Testet på Kubernetes

Med imaget bygget fra `develop/pandoc` og lastet inn i Docker på hver node med `docker save | docker load`, på Kubernetes 1.37 med én replika, består ende-til-ende-testene våre for Pandoc (6 tilfeller): import av et Markdown-dokument som et LaTeX-prosjekt, feilen som vises for et ødelagt Word-dokument, eksport til Word (som kan importeres igjen), Markdown og HTML, og menyene som skjules uten `ENABLE_PANDOC_CONVERSIONS`.
