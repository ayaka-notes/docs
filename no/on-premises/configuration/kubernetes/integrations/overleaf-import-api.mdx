Import-API-et (`/docs` og «Open in Ayakaleaf»-knappene, modulen `open-in-overleaf`) kjører i **web**-tjenesten i hver Ayakaleaf Pro-pod og er slått på som standard. Filer som oppgis via URL, lastes ned gjennom linked-url-proxy i samme pod. Hvordan du kaller det, er beskrevet i [Overleaf Import API](/no/on-premises/configuration/overleaf-toolkit/integrations/overleaf-import-api).

| | |
| --- | --- |
| Tjeneste | web (modulen `open-in-overleaf`); nedlastinger gjennom linked-url-proxy |
| Utsiden → Overleaf | nettlesere sender `GET` eller `POST ${OVERLEAF_SITE_URL}/docs` fra et hvilket som helst nettsted |
| Pod → utsiden | nedlastinger av `snip_uri` og `zip_uri`, begrenset som beskrevet i [Ekstern URL](/no/on-premises/configuration/kubernetes/external-url) |
| Tilstand | forespørselen til en utlogget besøkende, lagret i Redis i 10 minutter til vedkommende logger inn |
| Periodiske jobber | ingen |

### Konfigurasjon

Ingenting trengs for å slå det på. Relaterte innstillinger i ConfigMap-en:

| Innstilling | |
| --- | --- |
| `OVERLEAF_ALLOW_PUBLIC_ACCESS: "true"` | Utloggede besøkende kan åpne `/devs`, og en forespørsel de sender, lagres til de logger inn, se [Offentlig tilgang](/no/on-premises/configuration/kubernetes/authentication/public-access). |
| `MAX_UPLOAD_SIZE` | Største ZIP-fil en forespørsel kan inneholde, i MB (standard `50`). Ingressen eller lastbalansereren din må også godta forespørselsinnhold av den størrelsen. |
| `OVERLEAF_LINKED_URL_*` | Hvilke adresser `snip_uri` og `zip_uri` kan peke til, se [Ekstern URL](/no/on-premises/configuration/kubernetes/external-url). |

### Flere replikaer

Ingenting ekstra. Forespørselen til en utlogget besøkende lagres i Redis, så den gjenopptas på den replikaen den besøkende når etter innlogging.

### Testet på Kubernetes

På Kubernetes 1.37 med én replika består ende-til-ende-testene våre for Import-API-et (14 tilfeller): `/devs`-siden og eksempelprosjektet der, utdrag, komplette dokumenter, URL-kodede lenker og filer fra data-URL-er gjort om til prosjekter, innsendinger som ikke kan bli et prosjekt avvist, nedlastinger fra interne adresser avvist, innsendinger og lenker fra utloggede brukere bevart gjennom innloggingen, og, med `OVERLEAF_ALLOW_PUBLIC_ACCESS`, `/devs` for utloggede besøkende og et innsendt utdrag gjenopptatt én gang etter innlogging; det siste tilfellet består også på tre replikaer bak HAProxy.
