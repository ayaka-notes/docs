Hvert prosjekts MCP-server kjører i **web**-tjenesten (modulen `mcp-server`) i hver Ayakaleaf Pro-pod. Den følger med [Git-integrasjonen](/no/on-premises/configuration/kubernetes/integrations/git-integration) og har ingen egne innstillinger. Hvordan du kobler til Claude Code, Codex og andre klienter, er beskrevet i [MCP-server](/no/on-premises/configuration/overleaf-toolkit/integrations/mcp-server).

| | |
| --- | --- |
| Tjeneste | web, i hver Ayakaleaf Pro-pod |
| Slås på av | `GIT_BRIDGE_ENABLED: "true"` og git-bridge-StatefulSet-en, se [Git-integrasjon](/no/on-premises/configuration/kubernetes/integrations/git-integration) |
| Utsiden → Overleaf | AI-klienter sender `POST ${OVERLEAF_SITE_URL}/project/<id>/mcp` med et Git-autentiseringstoken; PDF-nedlastingslenker under `${OVERLEAF_SITE_URL}/project/<id>/mcp/download/` |
| Pod → utsiden | ingen |
| Tilstand | ingen mellom forespørsler; kompileringsutdata blir værende på poden som kompilerte |
| Periodiske jobber | ingen |

### Konfigurasjon

Sett opp [Git-integrasjonen](/no/on-premises/configuration/kubernetes/integrations/git-integration). MCP-serveren er da på `${OVERLEAF_SITE_URL}/project/<project id>/mcp`, og adressen må kunne nås fra der AI-klienten kjører.

### Flere replikaer

En kompilering via MCP kjører på replikaen som mottok forespørselen, og loggen og PDF-en finnes bare der. AI-klienter sender ingen informasjonskapsel, så lastbalansereren kan sende neste forespørsel, `get_compile_log` eller PDF-nedlastingslenken, til en annen replika, som svarer «failed to fetch output file from CLSI» eller 404. I testen vår med tre replikaer og ingen ekstra regel mislyktes 5 av 6 loggforespørsler og 3 av 4 nedlastinger på denne måten.

Rut alle MCP-forespørsler for et prosjekt til én replika, som for `/git/`. Med HAProxy fra [Horisontal skalering](/no/on-premises/configuration/kubernetes/horizontal-scaling):

```text
      use-server overleaf-0 if { path_reg ^/project/[0-9a-f]{24}/mcp(/|$) }
```

MCP-kompileringer kjører da alle på noden til `overleaf-0`. Med en annen ingress-kontroller ruter du stien `/project/<id>/mcp` og alt under den til én replikas eget navn (`overleaf-0.overleaf-hl`).

Med denne regelen lyktes den samme testen (en kompilering, 6 loggforespørsler og 4 PDF-nedlastinger, alle uten informasjonskapsel) hver gang.

### Testet på Kubernetes

På Kubernetes 1.37 med tre replikaer bak HAProxy består ende-til-ende-testene våre for MCP-serveren (37 tilfeller): oppføring av verktøyene, tokener som avvises når de er feil, slettet eller uten tilgang, kompilering og lesing av loggen, ordtelling, prosjektinnstillinger og historikk, PDF-nedlastingslenker, redigering av filer med endringene vist direkte i det åpne redigeringsprogrammet og hentet inn i en Git-klon, kommentarer, tilgang etter rolle, hastighetsgrensene for kompilering og innstillinger, og suspenderte kontoer. Disse forespørslene kom fra en nettleserøkt, så lastbalansereren holdt dem på én replika; for klienter uten informasjonskapsel, se [Flere replikaer](#flere-replikaer).
