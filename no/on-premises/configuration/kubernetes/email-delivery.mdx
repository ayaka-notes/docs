**web**-tjenesten sender all e-post (aktivering, prosjektinvitasjoner, tilbakestilling av passord) fra hver Ayakaleaf Pro-pod. Innstillingene er de samme som i Toolkit, se [E-postlevering](/no/on-premises/configuration/overleaf-toolkit/email-delivery).

| | |
| --- | --- |
| Tjeneste | web, i hver Ayakaleaf Pro-pod; leses når web starter |
| Pod → utsiden | SMTP-serveren din (`OVERLEAF_EMAIL_SMTP_HOST`), eller Amazon SES-API-et i `OVERLEAF_EMAIL_AWS_SES_REGION` |
| Tilstand | hastighetsbegrensningen for sending i Redis |
| Periodiske jobber | ingen |

### Konfigurasjon {#configuration}

<Steps>
<Step title="ConfigMap">
```yaml title="30-config.yaml (additions)" wrap
  OVERLEAF_EMAIL_FROM_ADDRESS: no-reply@example.com
  OVERLEAF_EMAIL_SMTP_HOST: smtp.example.com
  OVERLEAF_EMAIL_SMTP_PORT: "587"
  OVERLEAF_EMAIL_SMTP_SECURE: "false"
  OVERLEAF_EMAIL_SMTP_USER: no-reply@example.com
  # optional
  # OVERLEAF_EMAIL_REPLY_TO: support@example.com
  # OVERLEAF_EMAIL_SMTP_IGNORE_TLS: "false"
  # OVERLEAF_EMAIL_SMTP_TLS_REJECT_UNAUTH: "true"
```

`OVERLEAF_EMAIL_FROM_ADDRESS` slår på sending. Angi den bare sammen med SMTP-serveren (eller SES): med bare avsenderen prøver Ayakaleaf Pro en SMTP-server inne i poden, og all e-post feiler. Uten den sendes ikke e-post, den skrives bare til `web.log`.

`OVERLEAF_EMAIL_SMTP_SECURE`, `OVERLEAF_EMAIL_SMTP_IGNORE_TLS` og `OVERLEAF_EMAIL_SMTP_TLS_REJECT_UNAUTH` leses som JSON, så bruk `"true"` eller `"false"`: en verdi som `yes` stopper alle tjenestene i poden ved oppstart.
</Step>

<Step title="Secret">
```bash
kubectl -n overleaf patch secret overleaf-secrets --type merge \
  -p '{"stringData":{"OVERLEAF_EMAIL_SMTP_PASS":"<SMTP password>"}}'
```

For Amazon SES-API-et legger du i stedet `OVERLEAF_EMAIL_AWS_SES_ACCESS_KEY_ID` og `OVERLEAF_EMAIL_AWS_SES_SECRET_KEY` her, og `OVERLEAF_EMAIL_DRIVER: ses` og `OVERLEAF_EMAIL_AWS_SES_REGION` i ConfigMap-en.
</Step>

<Step title="Bruk, start på nytt og test">
```bash
kubectl apply -f 30-config.yaml
kubectl -n overleaf rollout restart deployment/overleaf     # or statefulset/overleaf
```

Send deg selv en e-post for tilbakestilling av passord fra innloggingssiden. Hvis den ikke kommer frem, kontrollerer du at SMTP-serveren kan nås fra podene, og ser i web-loggen:

```bash
kubectl -n overleaf exec deploy/overleaf -- bash -c 'echo > /dev/tcp/smtp.example.com/587 && echo reachable'
kubectl -n overleaf exec deploy/overleaf -- grep -iE "email|smtp" /var/log/overleaf/web.log | tail
```
</Step>
</Steps>

### Flere e-postadresser per konto {#several-emails-per-account}

Ingenting mer å konfigurere: når e-post fungerer, kan brukere legge til e-postadresser på kontoen sin og flytte kontoen til en av dem. Se [Flere e-postadresser per konto](/no/on-premises/configuration/overleaf-toolkit/email-delivery#several-emails-per-account) for reglene og [brukerveiledningen](/no/on-premises/user-guide/users/multiple-emails) for trinnene. Bekreftelseskoden lagres i brukerens økt i Redis.

### Flere replikaer {#several-replicas}

Ingenting ekstra. Hver replika sender med de samme innstillingene, og hastighetsbegrensningen for sending telles i Redis på tvers av alle replikaer. Hvis SMTP-serveren din bare godtar kjente avsendere, tillater du adressene podene forlater klyngen med (vanligvis nodenes).

### Testet på Kubernetes {#tested-on-kubernetes}

Med Mailpit som SMTP-server, på Kubernetes 1.37 med én replika, består ende-til-ende-testene våre som sender e-post: aktiverings-e-posten for en konto en administrator oppretter, aktiverings-e-posten for en selvregistrering begrenset til domener, e-posten for tilbakestilling av passord, e-posten som forteller en bruker at kontoen er slettet, og hva som skjer når SMTP-serveren avviser en aktiverings- eller slette-e-post: kontoen blir likevel opprettet eller slettet, og aktiverings-e-posten kan sendes på nytt senere. Med `OVERLEAF_EMAIL_FROM_ADDRESS` og ingen SMTP-vert feilet en forespørsel om tilbakestilling av passord med en feil, og `web.log` viste «error sending message», som beskrevet ovenfor.
