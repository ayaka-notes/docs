## Opprette en administratorbruker

Installasjoner med Overleaf Toolkit:

```bash title="Overleaf Toolkit" wrap
$ bin/docker-compose exec sharelatex /bin/bash -ce "cd /overleaf/services/web && node modules/server-ce-scripts/scripts/create-user --admin --email=joe@example.com"
```

Eldre installasjoner med docker-compose.yml:

```bash title="Legacy docker-compose" wrap
$ docker exec sharelatex /bin/bash -ce "cd /overleaf/services/web && node modules/server-ce-scripts/scripts/create-user --admin --email=joe@example.com"
```

Kommandoen oppretter en bruker med den oppgitte e-postadressen hvis brukeren ikke allerede finnes, og gjør vedkommende til administrator. Utdataene fra kommandoen inneholder en URL du kan besøke for å angi passordet til denne brukeren og logge inn for første gang.

<Info>

For en programmatisk tilnærming kan du bruke det samme skriptet til å opprette både vanlige brukere og administratorer. For vanlige brukere utelater du flagget --admin.

</Info>

Hvis du bruker interne kontoer for autentisering og må gi en eksisterende bruker administratorrettigheter for instansen eller fjerne administratorrettigheter, gjør du følgende:

<Steps>
<Step title="Via administrasjonsgrensesnittet">
* Logg inn som en eksisterende administrator.
* Klikk Admin -> Manage Users.
* Søk etter brukeren og klikk på e-postadressen.
* Rull ned til delen Site Admin og klikk på lenken (show).
* Kryss av for Is Site Admin.
* Klikk Save for å fullføre.
</Step>
</Steps>

## Slette brukere

Det er generelt tilrådelig å ikke slette kontoer med mindre de ikke lenger trengs. Sletting av en konto fjerner kontoen og fører til at samarbeidspartnere mister tilgang til prosjekter. Det finnes for øyeblikket ingen måte å deaktivere kontoer på — enten finnes de med dataene sine bevart, eller så er de slettet.

Som standard blir kontoer mykslettet. For informasjon om permanent fjerning av brukere fra instansen, se `ENABLE_CRON_RESOURCE_DELETION` i veiledningen [Miljøvariabler](/no/on-premises/configuration/overleaf-toolkit/environment-variables).

<Info>

Kontoer blir mykslettet som standard. Se `ENABLE_CRON_RESOURCE_DELETION` for hvordan permanent sletting fungerer.

</Info>

### Via Admin -> Manage Users

<Steps>
<Step title="">
* Logg inn som administrator.
* Klikk Admin -> Manage Users.
* Søk etter brukeren og kryss av i boksen ved siden av e-postadressen.
* Klikk på søppelbøtteikonet.
* Klikk Delete for å bekrefte.
</Step>
</Steps>

### Via kommandolinjen

Brukerkontoer (og prosjektene deres) kan slettes med følgende kommandoer.

Installasjoner med Overleaf Toolkit:

```bash title="Overleaf Toolkit"
$ bin/docker-compose exec sharelatex /bin/bash -ce "cd /overleaf/services/web && node modules/server-ce-scripts/scripts/delete-user.mjs --email=joe@example.com"
```

Eldre installasjoner med docker-compose.yml:

```bash title="Legacy docker-compose"
$ docker exec sharelatex /bin/bash -ce "cd /overleaf/services/web && node modules/server-ce-scripts/scripts/delete-user.mjs --email=joe@example.com"
```

<Danger>

Sletteskriptet bruker et hardkodet force-alternativ som sikrer at slettingen gjennomføres selv om e-posten om kontosletting ikke kan sendes (f.eks. når brukerens e-postadresse ikke lenger er i bruk).

</Danger>

<Info>

Fra og med versjon 5.5.0 kan alternativet --skip-email brukes for å unngå å sende en informerende e-post til den slettede brukeren.

</Info>

## Gjenopprette en mykslettet bruker

Hvis en bruker bare er mykslettet, kan du gjenopprette kontoen og prosjektene deres.

<Steps>
<Step title="">
* Logg inn som administrator.
* Klikk Admin -> Manage Users.
* Søk etter brukeren du vil gjenopprette.
* Klikk på knappen Display deleted users.
* Klikk på e-postadressen til den slettede brukeren.
* Klikk Recover This Account.
* Klikk Recover for å bekrefte.
</Step>
</Steps>

<Danger>

Når ENABLE\_CRON\_RESOURCE\_DELETION er satt til true, kan mykslettede kontoer gjenopprettes innen et tidsvindu på 90 dager. Etter 90 dager er det ikke mulig å gjenopprette kontoen.

</Danger>

## Telle brukere

Du kan hente antall brukere via administrasjonsgrensesnittet på https://you-instance-url/admin/user#license. For programmatiske kontroller og eksporter kan følgende eksempler være nyttige.

Totalt antall brukere:

```bash title="Total number of users"
echo 'db.users.countDocuments()' | docker exec -i mongo mongosh --quiet localhost/sharelatex
# overleaf [direct: primary] sharelatex> 16
```

Totalt antall brukere via metrics-endepunktet:

```bash title="Num active users from metrics"
docker exec sharelatex curl http://127.0.0.1:3000/metrics | grep num_active_users
# # HELP num_active_users num_active_users
# # TYPE num_active_users gauge
# num_active_users{app="web-api",host="b3ae4ff549d8"} 16
```

Totalt antall aktive brukere (eksempel: brukere som har vært aktive de siste 365 dagene):

```bash title="Total number of active users"
echo 'db.users.countDocuments({ lastActive: { $gte: new Date(new Date().getTime() - (365 * 24 * 60 * 60 * 1000)) } })' | docker exec -i mongo mongosh --quiet localhost/sharelatex
# overleaf [direct: primary] sharelatex> 10
```

## Oppdatere informasjon om brukerkontoer

Hvordan kontooppdateringer utføres, avhenger av om SSO er aktivert.

* Hvis SSO ikke brukes:
  * Administratorer kan endre informasjon om brukerkontoer via Admin -> Manage Users (e-post, fornavn, etternavn og generering av en lenke for tilbakestilling av passord).
  * Vanlige brukere kan oppdatere sine egne opplysninger via Account -> Account Settings (inkludert å endre passord og generere tokener for Git-autentisering).
* Hvis SSO brukes:
  * Server Pro kan konfigureres til å oppdatere en brukers for- og etternavn ved innlogging basert på autentiseringssystemet.
  * Når OVERLEAF\_SAML\_UPDATE\_USER\_DETAILS\_ON\_LOGIN eller OVERLEAF\_LDAP\_UPDATE\_USER\_DETAILS\_ON\_LOGIN er true, er skjemaet for brukeropplysninger på https://your-instance-url/user/settings deaktivert, og for- og etternavn kan bare angis i identitetsstyringssystemet ditt.

For mer informasjon, se:

* SAML 2.0-konfigurasjon: https://docs.overleaf.com/on-premises/configuration/overleaf-toolkit/server-pro-only-configuration/saml-2.0
* LDAP-konfigurasjon: https://docs.overleaf.com/on-premises/configuration/overleaf-toolkit/server-pro-only-configuration/ldap
