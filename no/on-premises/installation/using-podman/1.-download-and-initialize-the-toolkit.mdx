---
title: 1. Last ned og initialiser Toolkit
description: Klon Ayakaleaf Toolkit, opprett konfigurasjonen og sett den opp for Ayakaleaf Pro på Podman.
icon: arrow-down-to-bracket
---

<Steps>
<Step title="Klon Toolkit">
Klon **Ayakaleaf Toolkit** ([ayaka-notes/toolkit](https://github.com/ayaka-notes/toolkit)) til hjemmekatalogen din og gå inn i den:

```bash title="Clone the Toolkit" wrap
git clone https://github.com/ayaka-notes/toolkit.git ~/overleaf-toolkit
cd ~/overleaf-toolkit
```

Kjør alle de følgende kommandoene fra denne katalogen.
</Step>

<Step title="Opprett konfigurasjonen">
```bash title="Run initialization"
bin/init
```

Dette oppretter `config/overleaf.rc`, `config/variables.env` og `config/version`, som beskrevet i [3. Initialiser konfigurasjonen](/no/on-premises/installation/using-docker-compose/linux/3.-initialize-the-configuration) i Docker-veiledningen. `bin/init` trenger ikke Podman ennå.
</Step>

<Step title="Sett opp config/overleaf.rc">
Åpne `config/overleaf.rc` og endre disse linjene:

```bash title="config/overleaf.rc"
SERVER_PRO=true
OVERLEAF_PORT=8080
SIBLING_CONTAINERS_ENABLED=true
```

Legg deretter til denne linjen på slutten av filen:

```bash title="config/overleaf.rc"
SELINUX_MODE=managed
```

| Innstilling                       | Hvorfor                                                                                                                                                                                                     |
| --------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `SERVER_PRO=true`                 | Bruker Ayakaleaf Pro-imaget fra `ghcr.io`. Ingen innlogging er nødvendig.                                                                                                                                    |
| `OVERLEAF_PORT=8080`              | Rootless Podman kan ikke lytte på porter under `1024`. Standardporten `80` feiler.                                                                                                                          |
| `SIBLING_CONTAINERS_ENABLED=true` | Kjører hver kompilering i sin egen TeX Live-container. Allerede `true` som standard; Podman-oppsettet støtter bare denne modusen.                                                                           |
| `SELINUX_MODE=managed`            | Kjører `sharelatex`-containeren med SELinux-typen `sharelatex_t`, som kan bruke Podman-socketen og ingenting mer. `bin/podman-setup --apply` installerer policymodulen for den. Se [Toolkit-innstillinger](/no/on-premises/configuration/overleaf-toolkit/toolkit-settings) for de andre modusene. |

La `DOCKER_SOCKET_PATH` være som den er: `bin/podman-setup --apply` setter den til Podman-socketen din i neste steg.

<Warning>

Behold `GIT_BRIDGE_ENABLED=false`. I Ayakaleaf Pro 6.3.4 fungerer ikke Git-integrasjonen på Podman, se [Kjente begrensninger](/no/on-premises/installation/using-podman#known-limitations).

</Warning>
</Step>

<Step title="Velg TeX Live-imagene">
Åpne `config/variables.env`, fjern `#` foran `TEX_LIVE_DOCKER_IMAGE` og `ALL_TEX_LIVE_DOCKER_IMAGES`, og list opp TeX Live-imagene som skal brukes:

```bash title="config/variables.env" wrap
TEX_LIVE_DOCKER_IMAGE=ghcr.io/ayaka-notes/texlive-full:2026.1
ALL_TEX_LIVE_DOCKER_IMAGES=ghcr.io/ayaka-notes/texlive-full:2026.1
```

`bin/up` stopper med `Please configure ALL_TEX_LIVE_DOCKER_IMAGES` hvis listen er tom. `texlive-full` er stort; for en testserver fungerer også det mye mindre `ghcr.io/ayaka-notes/texlive-basic:2026.1`. Se [Sandboxed Compiles](/no/on-premises/configuration/overleaf-toolkit/sandboxed-compiles) for tilgjengelige images.

Sett de andre variablene, som `OVERLEAF_SITE_URL`, som beskrevet i [5. Tilpasse instansen din](/no/on-premises/installation/using-docker-compose/linux/5.-personalizing-your-instance#required-environment-variables). Med standard lytteadresse bruker du `http://localhost:8080`.
</Step>
</Steps>
