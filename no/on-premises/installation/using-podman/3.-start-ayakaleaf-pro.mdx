---
title: 3. Start Ayakaleaf Pro
description: Start Ayakaleaf Pro på Podman, verifiser det med podman-setup og bin/doctor, og start det etter omstarter.
icon: circle-play
---

<Steps>
<Step title="Start containerne">
```bash title="Start Ayakaleaf Pro"
bin/up -d
```

Første oppstart laster ned MongoDB-, Redis- og TeX Live-imagene, og oppretter datakatalogene i `data/`. Den skriver ut en advarsel om at Podman-støtte er eksperimentell.

<Info>

Første oppstart kan også skrive ut `MongoNetworkError: connect ECONNREFUSED 127.0.0.1:27017`. Toolkit setter opp MongoDB-replikasettet mens MongoDB fortsatt starter, og prøver igjen til den svarer. Du kan ignorere denne linjen.

</Info>

Etter et minutt eller to sjekker du at containerne kjører:

```bash title="List the containers"
podman ps --format "{{.Names}} {{.Status}}"
```

```text
mongo Up 34 seconds (healthy)
redis Up 20 seconds
sharelatex Up 20 seconds
```
</Step>

<Step title="Sjekk oppsettet på nytt">
Nå som datakatalogene finnes og `sharelatex`-containeren kjører, kan `bin/podman-setup` fullføre sjekkene sine:

```bash title="Check the setup"
bin/podman-setup
```

Det sjekker eierne av de nye datakatalogene og tester Podman-socketen fra innsiden av `sharelatex`-containeren:

```text
====== Socket Connectivity ======
[✓] host → socket OK
[✓] container → socket OK

====== Data Directory Permissions ======
[✓] mongo data dir owned by 999
[✓] redis data dir owned by 999
[✓] overleaf data dir owned by 33
...
====== Summary ======
[✓] 27 passed  [!] 1 warnings  [✗] 0 failures
[!] Warnings:
[!] not logged in to quay.io
```

`container → socket OK` betyr at Ayakaleaf Pro kan starte kompileringscontainere. Hvis en sjekk feiler, kjører du `bin/podman-setup --apply` og deretter `bin/up -d`. quay.io-advarselen gjelder ikke Ayakaleaf Pro, se [2. Kjør podman-setup](/no/on-premises/installation/using-podman/2.-run-podman-setup).
</Step>

<Step title="Kjør doctor">
```bash title="Run the doctor"
bin/doctor
```

På Podman viser rapporten kjøremiljøet og sikkerhetsinnstillingene:

```text
- Container Daemon
    - status: up
    - runtime: podman
    - server version: 5.8.5
    - socket: /run/user/1000/podman/podman.sock
    - DOCKER_HOST: unix:///run/user/1000/podman/podman.sock
    - host → socket: OK
    - container → socket: OK
- Security
    - SELinux: Enforcing
    - SELINUX_MODE: managed
    - SELINUX_LABEL: sharelatex_t
    - SELinux module: loaded (podman_socket_clsi)
    - SELinux rules: present
    - Seccomp profile: present
```

Advarselen `Server Pro enabled, but not logged in to quay.io repository` på slutten er den samme quay.io-sjekken, se [Få hjelp](/no/on-premises/support/getting-help#q-and-a).
</Step>

<Step title="Start Ayakaleaf Pro etter en omstart">
Med Docker starter Docker-daemonen containerne igjen etter en omstart. Rootless Podman har ingen daemon: aktiver brukertjenesten som starter containerne dine når serveren starter:

```bash title="Start the containers at boot"
systemctl --user enable podman-restart.service
```

Den starter alle containere for brukeren din med omstartspolicyen `always`, som Toolkit setter for alle sine containere. Dette krever lingering, som `bin/podman-setup --apply` aktiverte. Uten denne tjenesten må du kjøre `bin/up -d` etter hver omstart.
</Step>

<Step title="Åpne porten i brannmuren">
Som standard godtar instansen bare tilkoblinger fra selve serveren, på `http://localhost:8080`. For å åpne den for andre datamaskiner setter du `OVERLEAF_LISTEN_IP` i `config/overleaf.rc` og `OVERLEAF_SITE_URL` i `config/variables.env` som beskrevet i [5. Tilpasse instansen din](/no/on-premises/installation/using-docker-compose/linux/5.-personalizing-your-instance#listen-address-and-port), og kjører `bin/up -d` på nytt.

I motsetning til Docker omgår ikke rootless Podman vertens brannmur. Hvis `firewalld` kjører, som er standard på RHEL, åpner du porten:

```bash title="Open port 8080"
sudo firewall-cmd --permanent --add-port=8080/tcp
sudo firewall-cmd --reload
```

På en skyserver må du også tillate porten i leverandørens sikkerhetsgruppe. Bruk HTTPS før du eksponerer instansen mot internett, se [4. Oppgaver etter installasjon](/no/on-premises/installation/using-podman/4.-post-installation-tasks#use-https).
</Step>
</Steps>
