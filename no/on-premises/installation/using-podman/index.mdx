RHEL og gjenoppbyggingene av den (Rocky Linux, AlmaLinux) leveres med Podman i stedet for Docker, og noen organisasjoner tillater ikke Docker på serverne sine. Toolkit kan i stedet kjøre Ayakaleaf Pro på **rootless Podman**: containerne kjører som en vanlig bruker, kompileringer kjører fortsatt i sandkassede TeX Live-containere, og SELinux forblir i enforcing-modus. Skriptet `bin/podman-setup` sjekker verten og retter det det kan.

Når du er ferdig med denne delen, har du den samme instansen som med [Bruke Docker Compose](/no/on-premises/installation/using-docker-compose): Ayakaleaf Pro med sandkassede kompileringer, MongoDB og Redis, administrert med de vanlige `bin/up`, `bin/doctor` og `bin/upgrade`.

<Info>

Podman-støtte er eksperimentell. Den kommer fra den offisielle Overleaf Toolkit, som bare testes på RHEL 9 og nyere med rootless Podman, sandkassede kompileringer og SELinux i enforcing-modus. Vi testet disse sidene på Rocky Linux 9.9 (Podman 5.8, SELinux enforcing) med Ayakaleaf Pro 6.3.4. Docker er fortsatt det anbefalte container-kjøremiljøet.

</Info>

### Hva du trenger {#what-you-need}

* **RHEL, Rocky Linux, AlmaLinux eller CentOS Stream 9 eller nyere**, med SELinux i enforcing-modus. `bin/podman-setup` stopper på alle andre distribusjoner. På Ubuntu eller Debian bruker du [Bruke Docker Compose](/no/on-premises/installation/using-docker-compose/linux).
* **En bruker som ikke er root, med `sudo`**, som skal eie containerne. Kjør alle kommandoene i denne delen som denne brukeren; `bin/podman-setup` nekter å kjøre som `root`.
* **En ren vert**: ingen Docker Engine og ingen eksisterende Toolkit-installasjon. Flytting av en eksisterende Docker-basert instans til Podman dekkes ikke.

### Slik skiller det seg fra Docker {#how-it-differs-from-docker}

|                                  | Docker                               | Rootless Podman                                                                          |
| -------------------------------- | ------------------------------------ | ---------------------------------------------------------------------------------------- |
| Hvem kjører containerne          | Docker-daemonen, som `root`          | Brukeren din                                                                             |
| Socket som brukes til å starte kompileringer | `/var/run/docker.sock`   | `/run/user/<uid>/podman/podman.sock`                                                     |
| Porter                           | Hvilke som helst, for eksempel `80` og `443` | `1024` og over, for eksempel `8080`                                              |
| Vertens brannmur (`firewalld`)   | Omgås av publiserte porter           | Gjelder: åpne porten med `firewall-cmd`                                                  |
| Start etter omstart              | Docker-daemonen starter dem på nytt  | Brukertjenesten `podman-restart`                                                         |
| SELinux                          | Ikke konfigurert av Toolkit          | Policymodulen `podman_socket_clsi` og `SELINUX_MODE=managed` i `config/overleaf.rc`       |
| Seccomp-profil for kompileringer | Innebygd i imaget                    | Hentes ut til `config/seccomp/<version>/` og settes som `SECCOMP_PROFILE` av Toolkit     |

### Kjente begrensninger {#known-limitations}

* <strong>Git-integrasjon.</strong> I Ayakaleaf Pro 6.3.4 feiler `git clone` med `502` på Podman: NGINX inne i imaget slår opp `git-bridge`-containeren med Dockers DNS-server (`127.0.0.11`), som Podman ikke har. Rettelsen ([1b911d1092](https://github.com/ayaka-notes/ayakaleaf-pro/commit/1b911d1092c80f7b0ff77c5e3805b40503d49964)) kommer med neste versjon; inntil da lar du `GIT_BRIDGE_ENABLED=false` stå.
* <strong>Klientenes IP-adresser.</strong> Rootless Podman videresender den publiserte porten fra innsiden av containerens nettverk, så Ayakaleaf Pro ser alle besøkende med en intern adresse som `10.89.0.15`. En brukers [revisjonslogger](/no/on-premises/user-guide/administrators/user-management#audit-logs) i administrasjonspanelet viser denne adressen i stedet for brukerens IP-adresse.
