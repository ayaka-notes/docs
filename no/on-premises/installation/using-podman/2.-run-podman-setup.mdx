description: La bin/podman-setup sjekke verten og sette opp rootless Podman, SELinux og seccomp-profilen.

---

`bin/podman-setup` sjekker alt Ayakaleaf Pro trenger på Podman. Uten valg rapporterer det bare; med `--apply` retter det også det det finner.

<Steps>
<Step title="Sjekk verten">
```bash title="Check only"
bin/podman-setup
```

På en ny vert feiler de fleste sjekkene, for eksempel:

```text
====== Packages ======
[✗] podman not installed
[✗] podman-docker not installed
...
====== Summary ======
[✓] 7 passed  [!] 13 warnings  [✗] 4 failures
```
</Step>

<Step title="Bruk rettelsene">
```bash title="Check and fix"
bin/podman-setup --apply
```

Kjør det i en terminal: det ber om `sudo`-passordet ditt for stegene som gjelder hele systemet. Det laster også ned Ayakaleaf Pro-imaget for å hente ut seccomp-profilen, noe som tar noen minutter første gang. Til slutt sjekker det verten på nytt:

```text
====== Summary ======
[✓] 23 passed  [!] 2 warnings  [✗] 0 failures
[!] Warnings remaining:
[!] not logged in to quay.io
[!] container → socket skipped (sharelatex not running)
```

Begge advarslene er forventet på dette tidspunktet:

* `not logged in to quay.io`: sjekken kommer fra den offisielle Toolkit, der Server Pro-imaget ligger i et privat register. Ayakaleaf Pro-images er offentlige på `ghcr.io` og krever ingen innlogging, så du kan ignorere den. Den blir stående også etter installasjonen.
* `container → socket skipped (sharelatex not running)`: denne testen trenger den kjørende instansen. Du kjører skriptet på nytt i [3. Start Ayakaleaf Pro](/no/on-premises/installation/using-podman/3.-start-ayakaleaf-pro).

Skriptet avslutter med `0` når alle sjekker består, `1` når det er advarsler og `2` når det er feil. På grunn av quay.io-advarselen kan du forvente `1`.
</Step>
</Steps>

### Hva skriptet endrer {#what-the-script-changes}

Med `--apply` kan skriptet endre følgende.

For hele systemet, med `sudo`:

* Installerer `podman`, `podman-docker`, `git`, `curl`, `checkpolicy` og `policycoreutils` med `dnf`.
* Aktiverer lingering for brukeren din med `loginctl`, slik at containerne dine fortsetter å kjøre etter at du logger ut.
* Oppretter `/etc/containers/nodocker`, som demper meldingen "Emulate Docker CLI using podman".
* Laster SELinux-policymodulen `podman_socket_clsi` når `SELINUX_MODE=managed`.

For brukeren din:

* Aktiverer brukertjenesten `podman.socket`, det Docker-kompatible API-et som Ayakaleaf Pro bruker til å starte kompileringer.
* Installerer Docker Compose v2 fra GitHub til `~/.local/bin/docker-compose`, og lenker den i `~/.docker/cli-plugins/`.
* Får Podman til å bruke denne Compose i `~/.config/containers/containers.conf`.
* Legger til aliasene `mongo` og `redis` i `~/.config/containers/registries.conf.d/overleaf-toolkit.conf`, slik at Podman vet hvor disse korte image-navnene skal hentes fra.

I Toolkit:

* Setter `DOCKER_SOCKET_PATH` og `DOCKER_HOST` i `config/overleaf.rc` til `/run/user/<uid>/podman/podman.sock`.
* Henter ut seccomp-profilen for kompileringer fra Ayakaleaf Pro-imaget til `config/seccomp/<version>/clsi-profile.json`, og setter `SECCOMP_PROFILE` i `config/variables.env`. I motsetning til Docker trenger Podman denne profilen som en fil på verten.
* Bygger SELinux-policymodulen i `config/selinux/`.
* Setter eierne av datakatalogene i `data/` med `podman unshare chown`, når de finnes.

<Info>

Hver endring svarer til en sjekk. Hvis du endrer noe for hånd, for eksempel i `config/overleaf.rc`, kjører du `bin/podman-setup` på nytt for å verifisere det.

</Info>
