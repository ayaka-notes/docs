### Tilpasse instansen din

Før du starter Overleaf-instansen for første gang, oppdaterer du to konfigurasjonsfiler med din egen informasjon:

| Fil                    | Leses av                                   | Angis her                                                         |
| ---------------------- | ------------------------------------------ | ----------------------------------------------------------------- |
| `config/overleaf.rc`   | Toolkit-skriptene, som `bin/up`            | hvordan containerne kjører: `OVERLEAF_LISTEN_IP`, `OVERLEAF_PORT`, `SERVER_PRO`, datastier |
| `config/variables.env` | applikasjonen inne i containeren           | hvordan Overleaf oppfører seg: `OVERLEAF_SITE_URL`, e-post, TeX Live-images |

<Steps>
<Step title="Rediger variabelfilen">
Åpne `config/variables.env` i favoritteditoren din og oppdater miljøvariablene nedenfor med de nødvendige verdiene.
</Step>

<Step title="Lytteadresse og port">
Som standard publiserer Toolkit nettgrensesnittet på `127.0.0.1:80`, så det kan bare åpnes fra en nettleser på selve serveren. Andre datamaskiner får feilen «connection refused» eller «server not found». For å endre dette redigerer du `config/overleaf.rc`:

```bash title="config/overleaf.rc"
OVERLEAF_LISTEN_IP=0.0.0.0
OVERLEAF_PORT=8080
```

`OVERLEAF_LISTEN_IP` er IP-adressen på verten som containeren binder seg til, og `OVERLEAF_PORT` er porten på verten. Sammen utgjør de Docker-porttilordningen `OVERLEAF_LISTEN_IP:OVERLEAF_PORT:80`. Velg verdiene som passer til oppsettet ditt:

| Oppsett                                                                         | `OVERLEAF_LISTEN_IP`                  | `OVERLEAF_PORT`        | Åpne i nettleseren            |
| ------------------------------------------------------------------------------- | ------------------------------------- | ---------------------- | ----------------------------- |
| Bare på denne maskinen (standard)                                               | `127.0.0.1`                           | `80`                   | `http://localhost`            |
| Andre datamaskiner på LAN eller internett kobler til direkte                    | `0.0.0.0`, eller én IP-adresse for serveren | `80`, eller en hvilken som helst ledig port | `http://<server-ip>:<port>`   |
| Bak din egen reverse proxy (NGINX, Caddy, Cloudflare Tunnel) på samme vert      | `127.0.0.1`                           | en hvilken som helst ledig port | proxyens URL                  |
| Bak Toolkits [TLS-proxy](/no/on-premises/configuration/overleaf-toolkit/tls-proxy) | `127.0.0.1`                           | `80`                   | `https://<your-domain>`       |

Hvis port `80` allerede er i bruk på verten, for eksempel av en annen webserver, setter du `OVERLEAF_PORT` til en ledig port, for eksempel `8080`. Ellers mislykkes `bin/up` med `bind: address already in use`.

<Warning>

Porter som publiseres av Docker, omgår vertens brannmurer, som `ufw` og `firewalld`. Med `0.0.0.0` kan instansen nås fra alle nettverk serveren er koblet til. På en skyserver må du også tillate porten i leverandørens sikkerhetsgruppe. Bruk HTTPS før du eksponerer instansen mot internett, se [TLS-proxy](/no/on-premises/configuration/overleaf-toolkit/tls-proxy).

</Warning>

Du kan starte med standardverdien og først åpne instansen på `localhost`. For å tillate tilgang fra andre datamaskiner senere endrer du disse to variablene i `config/overleaf.rc` og `OVERLEAF_SITE_URL` i `config/variables.env`, og kjører deretter `bin/up` på nytt for å gjenopprette containerne.
</Step>

<Step title="Påkrevde miljøvariabler">
Oppdater følgende variabler i `config/variables.env`:

| Navn                          | Beskrivelse                                                                                                                                                    | Eksempel                        |
| ----------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------- |
| `OVERLEAF_SITE_URL`           | Hvor Overleaf-instansen din er offentlig tilgjengelig. Dette brukes i offentlige lenker og ved tilkobling over websockets, så den **må konfigureres riktig**! | `https://overleaf.lilliput.com` |
| `OVERLEAF_EMAIL_FROM_ADDRESS` | Denne e-postadressen brukes som `from`-adresse for all utgående e-post.                                                                                        | `no-reply@lilliput.com`         |
| `OVERLEAF_ADMIN_EMAIL`        | E-postadressen der brukerne kan nå personen som driver nettstedet.                                                                                             | `it-services@lilliput.com`      |

`OVERLEAF_SITE_URL` er adressen brukerne skriver inn i nettleseren, ikke lytteadressen. Ta med porten når den ikke er `80` (HTTP) eller `443` (HTTPS), for eksempel `http://192.168.1.20:8080`. Ikke bruk `http://0.0.0.0`. Hvis `OVERLEAF_SITE_URL` ikke samsvarer med adressen i nettleseren, klarer ikke editoren å koble til, og lenker i e-poster og OAuth-callbacker peker til feil sted.

Sett også `OVERLEAF_SESSION_SECRET` til en verdi som er generert med `openssl rand -hex 32`. Uten den logger hver `bin/up` som gjenoppretter containeren, og hver oppgradering, ut alle brukere. Se spørsmål og svar i [Miljøvariabler](/no/on-premises/configuration/overleaf-toolkit/environment-variables).

Når du har oppdatert disse miljøvariablene, lagrer du og avslutter.
</Step>

<Step title="Sett opp Sandbox Compile">
Deretter konfigurerer du TeX Live Full for [sandboxed-compiles.md](/no/on-premises/configuration/overleaf-toolkit/sandboxed-compiles  "mention"). Åpne `config/variables.env` og oppdater følgende miljøvariabler:

```dotenv title="config/variables.env" wrap
ALL_TEX_LIVE_DOCKER_IMAGES=ghcr.io/ayaka-notes/texlive-full:2026.1, ghcr.io/ayaka-notes/texlive-full:2025.1
ALL_TEX_LIVE_DOCKER_IMAGE_NAMES=Texlive 2026, Texlive 2025
TEX_LIVE_DOCKER_IMAGE=ghcr.io/ayaka-notes/texlive-full:2026.1
```
</Step>

<Step title="Start instansen din">
For å starte instansen kjører du:

```text title="Start the instance"
bin/up
```

Denne kommandoen laster ned de nødvendige imagene, inkludert TeX Live, oppretter containerne (med dine tilpasninger) og starter instansen. Du skal se loggutdata fra de ulike Docker-containerne.

For å starte dem igjen senere (uten å koble til loggutdataene) kjører du:

```text title="Start without attaching to logs"
bin/start
```
</Step>
</Steps>

<Info>

Toolkit bruker `docker compose` til å administrere Overleaf-containerne i Docker. Toolkit har et sett med skript som pakker inn `docker compose` og tar seg av de fleste detaljene for deg.

</Info>

Hvis alt går bra, skal du kunne se innloggingssiden for den nye Overleaf-instansen ved å gå til [http://127.0.0.1/](http://127.0.0.1/) eller [http://localhost/](http://localhost/) i nettleseren. Hvis du har endret `OVERLEAF_LISTEN_IP` eller `OVERLEAF_PORT`, åpner du i stedet adressen fra tabellen i trinnet **Lytteadresse og port**, for eksempel `http://<server-ip>:8080`.

For å kontrollere hvilken adresse og port nettgrensesnittet er publisert på, kjører du:

```text title="Show the published port"
bin/docker-compose port sharelatex 80
```

Utdataene, for eksempel `0.0.0.0:8080`, viser IP-adressen og porten på verten som er i bruk. Hvis de viser `127.0.0.1`, kan instansen bare nås fra selve serveren.

<Warning>

Avhengig av nettverkskonfigurasjonen og hvor Overleaf-instansen er driftet, kan det hende du må gjøre ytterligere konfigurasjonsendringer. Se Toolkit-innstillingene for flere detaljer: [toolkit-settings.md](/no/on-premises/configuration/overleaf-toolkit/toolkit-settings  "mention")

</Warning>
