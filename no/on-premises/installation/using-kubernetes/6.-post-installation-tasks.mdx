### Opprette din første administratorkonto {#creating-your-first-administrator-account}

Åpne `OVERLEAF_SITE_URL` etterfulgt av `/launchpad`, for eksempel `http://192.0.2.10:30080/launchpad`, og registrer administratorkontoen som i [Toolkits oppgaver etter installasjon](/no/on-premises/installation/using-docker-compose/linux/6.-post-installation-tasks). Opprett deretter et eksempelprosjekt og kompiler det.

Du kan også opprette brukere fra kommandolinjen:

```bash
kubectl -n overleaf exec deploy/overleaf -- bash -c \
  'cd /overleaf/services/web && node modules/server-ce-scripts/scripts/create-user.mjs --admin --email=admin@example.com'
```

Den skriver ut en lenke som angir passordet.

### Kontrollere at kompileringer kjører i sandkasse {#checking-that-compiles-are-sandboxed}

Kompiler et prosjekt, og se deretter på noden som kjører poden:

```bash
kubectl -n overleaf get pod -l app=overleaf -o wide   # NODE column
# on that node:
sudo docker ps -a --filter ancestor=ghcr.io/ayaka-notes/texlive-full:2026.1
ls -ln /srv/overleaf/compiles                          # owned by uid 33 (www-data)
```

Hver kompilering vises som en kortlivet container med navnet `project-<project id>-<user id>-...`.

### Logger og et skall {#logs-and-a-shell}

| Toolkit          | Kubernetes                                                               |
| ---------------- | ------------------------------------------------------------------------ |
| `bin/logs web`   | `kubectl -n overleaf exec deploy/overleaf -- tail -f /var/log/overleaf/web.log` |
| `bin/shell`      | `kubectl -n overleaf exec -it deploy/overleaf -- bash`                    |
| `bin/up`         | `kubectl apply -f .` og deretter `kubectl -n overleaf rollout restart deployment/overleaf` |

Containeren skriver én loggfil per tjeneste i `/var/log/overleaf/` (`web.log`, `clsi.log`, `real-time.log`, `document-updater.log`, ...); `kubectl logs` viser oppstartsutdataene.

### Hva som overlever en omstart {#what-survives-a-restart}

`kubectl rollout restart` erstatter podene. Bare det som ligger på et volum, blir værende. Endringer gjort inne i en pod via `kubectl exec`, for eksempel installerte pakker eller redigerte filer, går tapt med den, og det gjør også loggene med mindre `/var/log/overleaf` ligger på et volum, se [Logging](/no/on-premises/configuration/kubernetes/logging). Gjør varige endringer i manifestene dine.

### Q\&A {#q&a}

<Accordion title="Kompileringen mislykkes eller blir aldri ferdig.">

<strong>Svar:</strong> Kontroller, på noden som kjører poden, at Docker kjører og har imaget som er oppgitt i `TEX_LIVE_DOCKER_IMAGE`, og at `SANDBOXED_COMPILES_HOST_DIR_*` samsvarer med `hostPath`-stiene. `/var/log/overleaf/clsi.log` i poden angir hvilket trinn som feiler.

</Accordion>

<Accordion title="Brukere logges ut hver gang poden starter på nytt.">

<strong>Svar:</strong> `OVERLEAF_SESSION_SECRET` mangler i Secret-en `overleaf-secrets`, se [trinn 2](/no/on-premises/installation/using-kubernetes/2.-create-the-namespace-and-secrets).

</Accordion>
