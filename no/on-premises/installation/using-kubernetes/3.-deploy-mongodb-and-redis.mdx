Ayakaleaf Pro trenger:

* **MongoDB 8** som et **replikasett** (det bruker transaksjoner). Tre medlemmer fordelt på tre noder overlever tapet av en node; ett medlem fungerer også.
* **Redis 7**, én server med AOF-persistens. Redis inneholder redigeringene som ennå ikke er skrevet til MongoDB, øktene og meldingene mellom Overleaf-tjenestene. Overleaf kobler til én enkelt Redis-server: Sentinel og Redis Cluster støttes ikke.

<Info>

Du kan bruke administrerte tjenester i stedet, for eksempel MongoDB Atlas eller skyleverandørens Redis. Hopp over denne siden og angi `OVERLEAF_MONGO_URL` og `OVERLEAF_REDIS_HOST` til dem i [trinn 4](/no/on-premises/installation/using-kubernetes/4.-personalizing-your-instance).

</Info>

<Steps>
<Step title="MongoDB">
```yaml title="10-mongo.yaml" wrap
apiVersion: v1
kind: Service
metadata:
  name: mongo
  namespace: overleaf
spec:
  clusterIP: None                 # headless: gives mongo-0.mongo, mongo-1.mongo, ...
  publishNotReadyAddresses: true  # members must resolve each other before the set is initiated
  selector:
    app: mongo
  ports:
    - name: mongo
      port: 27017
---
apiVersion: apps/v1
kind: StatefulSet
metadata:
  name: mongo
  namespace: overleaf
spec:
  serviceName: mongo
  replicas: 3
  selector:
    matchLabels:
      app: mongo
  template:
    metadata:
      labels:
        app: mongo
    spec:
      affinity:
        podAntiAffinity:
          requiredDuringSchedulingIgnoredDuringExecution:
            - labelSelector:
                matchLabels:
                  app: mongo
              topologyKey: kubernetes.io/hostname
      containers:
        - name: mongo
          image: mongo:8.0
          args:
            - --replSet=overleaf
            - --bind_ip_all
            - --wiredTigerCacheSizeGB=0.25   # default is 50% of (RAM - 1 GB); size it for your nodes
          # env:
          #   - name: GLIBC_TUNABLES        # only on kernel 6.19+ (SERVER-121912)
          #     value: glibc.pthread.rseq=1
          ports:
            - containerPort: 27017
          readinessProbe:
            tcpSocket:
              port: 27017
          resources:
            requests:
              cpu: 100m
              memory: 384Mi
            limits:
              memory: 768Mi
          volumeMounts:
            - name: data
              mountPath: /data/db
  volumeClaimTemplates:
    - metadata:
        name: data
      spec:
        accessModes: [ReadWriteOnce]
        resources:
          requests:
            storage: 5Gi
---
# Initiates the replica set once. Safe to re-run: it does nothing when the set exists.
apiVersion: batch/v1
kind: Job
metadata:
  name: mongo-init-replica-set
  namespace: overleaf
spec:
  backoffLimit: 20
  template:
    spec:
      restartPolicy: OnFailure
      containers:
        - name: init
          image: mongo:8.0
          command:
            - mongosh
            - --quiet
            - --host=mongo-0.mongo
            - --eval
            - |
              try {
                rs.status()
                print('replica set already initiated')
              } catch (e) {
                rs.initiate({
                  _id: 'overleaf',
                  members: [
                    { _id: 0, host: 'mongo-0.mongo.overleaf.svc.cluster.local:27017' },
                    { _id: 1, host: 'mongo-1.mongo.overleaf.svc.cluster.local:27017' },
                    { _id: 2, host: 'mongo-2.mongo.overleaf.svc.cluster.local:27017' },
                  ],
                })
              }
```

```bash
kubectl apply -f 10-mongo.yaml
kubectl -n overleaf rollout status statefulset/mongo
kubectl -n overleaf wait --for=condition=complete job/mongo-init-replica-set --timeout=5m
kubectl -n overleaf exec mongo-0 -- mongosh --quiet --eval 'rs.status().members.map(m => m.name + " " + m.stateStr)'
```

Etter noen sekunder skal ett medlem være `PRIMARY` og de andre `SECONDARY`. Job-en prøver på nytt til alle medlemmene svarer, så noen mislykkede Job-poder er normalt.

* Den headless Service-en trenger `publishNotReadyAddresses: true`: medlemmene må finne hverandre etter navn før replikasettet finnes.
* Medlemmene legges til med sine stabile navn (`mongo-0.mongo.overleaf.svc.cluster.local`), aldri pod-IP-er, som endres ved hver omstart.
* For ett enkelt medlem angir du `replicas: 1` og beholder bare `mongo-0` i Job-en.
</Step>

<Step title="Redis">
```yaml title="20-redis.yaml" wrap
apiVersion: v1
kind: Service
metadata:
  name: redis
  namespace: overleaf
spec:
  selector:
    app: redis
  ports:
    - name: redis
      port: 6379
---
apiVersion: apps/v1
kind: StatefulSet
metadata:
  name: redis
  namespace: overleaf
spec:
  serviceName: redis
  replicas: 1
  selector:
    matchLabels:
      app: redis
  template:
    metadata:
      labels:
        app: redis
    spec:
      containers:
        - name: redis
          image: redis:7.4
          args: [--appendonly, "yes"]
          ports:
            - containerPort: 6379
          readinessProbe:
            tcpSocket:
              port: 6379
          resources:
            requests:
              cpu: 50m
              memory: 128Mi
            limits:
              memory: 512Mi
          volumeMounts:
            - name: data
              mountPath: /data
  volumeClaimTemplates:
    - metadata:
        name: data
      spec:
        accessModes: [ReadWriteOnce]
        resources:
          requests:
            storage: 2Gi
```

```bash
kubectl apply -f 20-redis.yaml
kubectl -n overleaf rollout status statefulset/redis
```
</Step>

### Q\&A

<Accordion title="MongoDB 8 krasjer ved oppstart på en nyere kjerne. Hvorfor?">

<strong>Svar:</strong> MongoDB 8 feiler på Linux-kjerne 6.19 og nyere ([SERVER-121912](https://jira.mongodb.org/browse/SERVER-121912)). Fjern kommenteringen av miljøvariabelen `GLIBC_TUNABLES` i `10-mongo.yaml`.

</Accordion>

<Accordion title="Hvor mye minne trenger MongoDB?">

<strong>Svar:</strong> Som standard bruker MongoDB halvparten av nodens minne minus 1 GB til hurtigbufferen sin, og den ser nodens minne, ikke podens grense. Angi `--wiredTigerCacheSizeGB` slik at det passer nodene dine; `0.25` holdt hvert medlem på omtrent 200 til 260 MiB på testnodene våre med 4 GB.

</Accordion>
