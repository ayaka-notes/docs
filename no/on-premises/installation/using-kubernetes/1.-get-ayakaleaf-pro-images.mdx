Kubernetes kjører de samme imagene som Toolkit. Det finnes ikke noe eget Kubernetes-image.

| Image                                                | Brukes av                                                               |
| ---------------------------------------------------- | ----------------------------------------------------------------------- |
| `ghcr.io/ayaka-notes/overleaf-pro:6.3.2`             | Deployment-en `overleaf`                                                |
| `ghcr.io/ayaka-notes/overleaf-pro/git-bridge:6.3.2`  | [Git-integrasjon](/no/on-premises/configuration/kubernetes/integrations/git-integration) (valgfritt), samme tagg som ovenfor |
| `ghcr.io/ayaka-notes/texlive-*`                      | kompileringer, hentet inn i Docker på nodene i [trinn 0](/no/on-premises/installation/using-kubernetes/0.-prepare-the-nodes) |

Imagene er offentlige på [ghcr.io](https://github.com/ayaka-notes/ayakaleaf-pro/pkgs/container/overleaf-pro/) for amd64 og arm64, så kubelet kan hente dem uten påloggingsinformasjon.

<Warning>

Bruk alltid en versjonstagg, for eksempel `6.3.2`, ikke `latest`. Oppgraderinger kjører databasemigreringer og må følge [Oppgradering på Kubernetes](/no/on-premises/maintenance/upgrading-on-kubernetes); en tagg som flytter seg, ville oppgradert en pod hver gang den planlegges på nytt.

</Warning>

### Q\&A

<Accordion title="Nodene våre kan ikke nå ghcr.io. Hva gjør vi?">

<strong>Svar:</strong> Kopier imagene til et register nodene kan nå, og bruk det navnet i manifestene, for eksempel:

```bash
docker pull ghcr.io/ayaka-notes/overleaf-pro:6.3.2
docker tag ghcr.io/ayaka-notes/overleaf-pro:6.3.2 registry.example.com/ayakaleaf/overleaf-pro:6.3.2
docker push registry.example.com/ayakaleaf/overleaf-pro:6.3.2
```

For et register uten TLS trenger containerd en `/etc/containerd/certs.d/<registry>/hosts.toml` med `server = "http://<registry>"` på hver node, og `config_path` angitt som i [trinn 0](/no/on-premises/installation/using-kubernetes/0.-prepare-the-nodes). Docker selv pusher bare over vanlig HTTP til `localhost`, så push via `localhost:<port>` på registerverten, eller legg det til i `insecure-registries`.

</Accordion>
