[Toolkit](/no/on-premises/installation/using-docker-compose) er den anbefalte måten å kjøre Ayakaleaf Pro på én server på. Hvis du allerede kjører en Kubernetes-klynge, distribuerer denne delen den samme containeren i den med enkle `kubectl`-manifester: ingen ekstra images, ingen Helm-chart.

Når du er ferdig med denne delen, har du én Ayakaleaf Pro-instans med Sandboxed Compiles, et MongoDB-replikasett og Redis, alt i navnerommet `overleaf`. For å kjøre flere instanser bak en lastbalanserer fortsetter du deretter med [Horisontal skalering](/no/on-premises/configuration/kubernetes/horizontal-scaling).

<Info>

Kubernetes-støtten er eksperimentell. Vi publiserer ikke noe Helm-chart eller Kubernetes-spesifikke images. Manifestene på disse sidene er de vi testet på Kubernetes 1.37 (kubeadm, containerd 2.4, flannel) med tre noder med 2 vCPU-er og 4 GB minne hver. Tilpass lagring, nettverk og ingress til klyngen din.

</Info>

### Hvordan delene henger sammen {#how-the-pieces-fit}

| Toolkit (én server)                          | Kubernetes                                                               |
| -------------------------------------------- | ------------------------------------------------------------------------ |
| `config/variables.env`                       | ConfigMap `overleaf-env` og Secret `overleaf-secrets`                    |
| `sharelatex`-container                       | Deployment `overleaf` (én pod som kjører alle Overleaf-tjenestene)       |
| `mongo`- og `redis`-containere               | StatefulSet-ene `mongo` (replikasett) og `redis`, eller dine administrerte tjenester |
| `~/overleaf-toolkit/data/overleaf`           | PersistentVolumeClaim `overleaf-data`                                    |
| Docker på verten, brukt til kompileringer    | Docker Engine på hver node som kjører Ayakaleaf Pro                      |
| `bin/up`, `bin/logs`, `bin/shell`            | `kubectl apply`, `kubectl logs`, `kubectl exec`                          |

### Hva du trenger {#what-you-need}

* En Kubernetes-klynge du kan installere pakker i: hver node som kan kjøre Ayakaleaf Pro, trenger **Docker Engine**, fordi kompileringer kjører i TeX Live-containere som Ayakaleaf Pro starter via nodens `/var/run/docker.sock`. Se [0. Forbered nodene](/no/on-premises/installation/using-kubernetes/0.-prepare-the-nodes).
* En standard-StorageClass med `ReadWriteOnce`-volumer.
* `kubectl` og `openssl` på arbeidsstasjonen din.
