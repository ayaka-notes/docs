Ayakaleaf Pro bruker Linux-containere. På Windows installerer du Docker Desktop med WSL 2-backenden og kjører Toolkit-skriptene i Ubuntu.

WSL 2 leverer Linux-kjernen. Docker Desktop administrerer Docker-motoren i sitt eget `docker-desktop`-miljø; når du aktiverer **WSL Integration**, kan Docker CLI i Ubuntu kommunisere med den motoren. Toolkit starter deretter applikasjonen, MongoDB og Redis som containere. Med sandkassede kompileringer aktivert bruker applikasjonen motorens Docker-socket til å starte en separat TeX Live-container for hver kompilering. Du trenger ikke Windows-installasjoner av MongoDB, Redis eller TeX Live.

<Steps>
<Step title="Installer WSL 2 og Ubuntu">
Åpne **PowerShell som administrator** i Windows og kjør:

```powershell
wsl --install -d Ubuntu
```

Start Windows på nytt hvis du blir bedt om det. Åpne **Ubuntu** fra Start-menyen og opprett et Linux-brukernavn og -passord. Dette er kontoen for `sudo` i Ubuntu; den er atskilt fra Windows-påloggingen din.

Tilbake i **PowerShell** oppdaterer du WSL og sjekker distribusjonen:

```powershell
wsl --update
wsl --version
wsl --list --verbose
```

Ubuntu-raden må vise **VERSION 2**. Hvis den viser 1, bruker du det nøyaktige distribusjonsnavnet fra listen:

```powershell
wsl --set-version Ubuntu 2
```

Docker krever WSL **2.1.5 eller nyere**; WSL-programvareversjonen fra `wsl --version` og distribusjonens **VERSION 2**-kolonne er to forskjellige sjekker. Se [feilsøking av installasjonen](/no/on-premises/installation/using-docker-compose/windows/troubleshooting#wsl-or-docker-reports-that-virtualization-is-unavailable) og [Microsofts installasjonsinstruksjoner](https://learn.microsoft.com/en-us/windows/wsl/install) hvis installasjonen mislykkes, og aktiver maskinvarevirtualisering i BIOS/UEFI hvis WSL rapporterer at den er utilgjengelig.
</Step>

<Step title="Installer og start Docker Desktop">
Last ned [Docker Desktop for Windows](https://docs.docker.com/desktop/setup/install/windows-install/) for prosessoren din og kjør installasjonsprogrammet. Bruk **WSL 2**-backenden hvis du får valget. Åpne **Docker Desktop** fra Start-menyen i Windows og vent til motoren starter.

I **Settings → General** i Docker Desktop aktiverer du **Use WSL 2 based engine** hvis alternativet vises. Under **Settings → Resources → WSL Integration** aktiverer du integrasjon for **Ubuntu** og velger deretter **Apply** eller **Apply & restart**. Hvis Ubuntu ikke er standarddistribusjonen din, aktiverer du dens egen bryter eksplisitt.

Hvis WSL Integration mangler, sjekker du at Docker Desktop bruker **Linux containers**. Se [Dockers veiledning for WSL 2-backenden](https://docs.docker.com/desktop/features/wsl/).

Bruk integrasjonen i Docker Desktop for denne veiledningen. Å installere en ekstra Docker Engine med `apt install docker.io` eller starte `dockerd` i Ubuntu skaper et separat oppsett og kan føre til konflikter. Hvis du allerede bruker en Engine i Ubuntu, følger du Dockers migreringsveiledning før du bytter; ta vare på eksisterende applikasjonsdata og sikkerhetskopier.
</Step>

<Step title="Sjekk Docker fra Ubuntu">
Åpne en **Ubuntu**-terminal. Kjør disse kommandoene der, uten `sudo`:

```bash
docker version
docker compose version
docker ps
```

`docker version` må vise både **Client** og **Server**. En tom containerliste er normalt på en ny installasjon. `docker --version` alene beviser ikke at motoren kjører.

Hvis `docker` er utilgjengelig eller ikke kan koble til, åpner du Ubuntu på nytt etter at du har tatt i bruk WSL Integration, og sjekker at Docker Desktop kjører. Se [Feilsøking](/no/on-premises/installation/using-docker-compose/windows/troubleshooting#docker-is-unavailable-in-ubuntu).
</Step>

<Step title="Sjekk ressurser og Docker-socketen">
Sjekk ressursene som er synlige for Docker:

```bash
docker info --format 'CPUs={{.NCPU}} Memory={{.MemTotal}} Kernel={{.KernelVersion}}'
df -h "$HOME"
ls -l /var/run/docker.sock
```

For en liten lokal instans er 4 CPU-er og 8 GB minne tilgjengelig for Docker et foreslått utgangspunkt, ikke et målt minimum. Sett av nok minne til Windows også. Med WSL 2-backenden administreres ressursgrenser via [WSL-innstillinger](https://learn.microsoft.com/en-us/windows/wsl/wsl-config), i stedet for ressursglidebryterne i Docker Desktop på Mac. Endringer som krever `wsl --shutdown`, avbryter alle kjørende WSL-distribusjoner og Docker-arbeidslaster; ta dem i bruk før du starter instansen.

La `DOCKER_SOCKET_PATH=/var/run/docker.sock` stå i Toolkit-konfigurasjonen. Applikasjonen trenger denne motorsocketen for sandkassede kompileringer. Ikke endre tillatelsene til `777` for å løse tilkoblingsfeil; gjenopprett i stedet integrasjonen i Docker Desktop.
</Step>
</Steps>
