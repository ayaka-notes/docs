### Opprett administratoren og et første prosjekt {#create-the-administrator-and-a-first-project}

Åpne [http://localhost:8080/launchpad](http://localhost:8080/launchpad), opprett den første administratorkontoen og logg inn. Følg deretter [6. Oppgaver etter installasjon](/no/on-premises/installation/using-docker-compose/linux/6.-post-installation-tasks) i Linux-veiledningen, og bruk port `8080` i eksempel-URL-ene der.

### Bekreft kompilering {#verify-compilation}

At en påloggingsside åpnes, beviser ikke at de separate kompilatorcontainerne og datamonteringene deres fungerer. Opprett et tomt prosjekt og kompiler denne `main.tex`:

```latex
\documentclass{article}
\begin{document}
Ayakaleaf Pro on macOS.
\end{document}
```

PDF-forhåndsvisningen skal vise teksten. Velg om nødvendig TeX Live 2026 i prosjektinnstillingene.

For et prosjekt med kinesisk tekst velger du **XeLaTeX** som kompilator og tester:

```latex
\documentclass{ctexart}
\begin{document}
你好，Ayakaleaf Pro。
\end{document}
```

### Bekreft varig lagring {#verify-persistence}

```bash
bin/stop
bin/start
```

Åpne prosjektet igjen og kompiler det på nytt. Kontoen din, kildekoden og prosjektfilene skal fortsatt være der. Med standardstiene ligger de aktive dataene i Toolkits `data/`-mappe på Mac-en din.

### Hold instansen tilgjengelig {#keep-the-instance-available}

Mens Mac-en sover, setter macOS den virtuelle maskinen til Docker Desktop på pause sammen med alle containerne i den: ingen kan åpne instansen, og en kompilering som kjører, stopper til Mac-en våkner. Det er bare systemets dvale som betyr noe. Skjermen kan gjerne slå seg av.

Hvis andre bruker instansen, eller du lar lange oppgaver kjøre, holder du Mac-en tilkoblet strøm og forhindrer automatisk dvale, se [Angi innstillinger for dvale og vekking på Mac-en](https://support.apple.com/guide/mac-help/set-sleep-and-wake-settings-mchle41a6ccd/mac):

| Mac | Innstilling |
| --- | --- |
| Stasjonær Mac (Mac mini, iMac, Mac Studio, Mac Pro) | **System Settings → Energy**: slå på **Prevent automatic sleeping when the display is off** |
| MacBook | **System Settings → Battery → Options**: slå på **Prevent automatic sleeping on power adapter when the display is off**. Dette gjelder bare mens strømadapteren er tilkoblet, og når du lukker lokket, går MacBook-en fortsatt i dvale |

For å holde Mac-en våken bare en stund kjører du i stedet `caffeinate -i` i et Terminal-vindu. Det forhindrer dvale ved inaktivitet til du trykker `Ctrl+C` eller lukker vinduet.

Docker Desktop er en app i brukerøkten din. For å få instansen tilbake etter en omstart slår du på **Start Docker Desktop when you sign in to your computer** under **Settings → General** i Docker Desktop. Toolkits containere bruker `restart: always`, så Docker starter dem igjen når Docker Desktop kjører, uten `bin/up`. Inntil noen logger inn på Mac-en etter en omstart, forblir instansen nede.

<Info>

En Mac som holdes våken, bruker mer strøm. For en tjeneste som alltid må være tilgjengelig, anbefaler vi en Linux-server, se [Linux](/no/on-premises/installation/using-docker-compose/linux).

</Info>

### Daglig bruk {#daily-use}

Åpne Docker Desktop før du administrerer instansen. I en ny terminal:

```bash
export PATH="$(brew --prefix gnu-sed)/libexec/gnubin:$PATH"
cd "$HOME/ayakaleaf-toolkit"
```

| Oppgave | Kommando |
| --- | --- |
| Start de eksisterende containerne | `bin/start` |
| Stopp containerne og behold dataene | `bin/stop` |
| Ta i bruk konfigurasjonsendringer | `bin/up -d` |
| Sjekk statusen | `bin/docker-compose ps` |
| Les oppstartsloggene | `bin/docker-compose logs --tail=100 sharelatex` |
| Les kompilatorloggene | `bin/logs -f clsi` |

`bin/start` tar ikke i bruk endringer i `config/`: kjør `bin/up -d` etter at du har redigert konfigurasjonen. Ta vare på `config/` og `data/`, og følg [Data og sikkerhetskopier](/no/on-premises/maintenance/data-and-backups) før en oppgradering eller før du flytter installasjonen. Å kopiere databasefilene mens MongoDB skriver til dem, gir ikke en konsistent sikkerhetskopi.

Behold instansen på `127.0.0.1` for lokal bruk. For å betjene andre datamaskiner angir du lytteadressen, nettstedets URL og HTTPS bevisst, se [5. Tilpasse instansen din](/no/on-premises/installation/using-docker-compose/linux/5.-personalizing-your-instance) i Linux-veiledningen.

Hvis noe ikke fungerer, se [Feilsøking](/no/on-premises/installation/using-docker-compose/macos/troubleshooting).
