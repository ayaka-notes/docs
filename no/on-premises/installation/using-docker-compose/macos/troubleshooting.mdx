### Initialiseringen mislykkes med invalid command code {#initialization-fails-with-invalid-command-code}

`bin/init` rapporterer `sed: ... invalid command code` når den finner BSD sed fra macOS. Legg GNU sed på `PATH` som i [1. Last ned Toolkit](/no/on-premises/installation/using-docker-compose/macos/1.-download-the-toolkit), og sjekk `sed --version`.

En mislykket initialisering kan etterlate alle tre filene i `config/` med en tom `OVERLEAF_INVITE_TOKEN_SECRET`. Når du kjører `bin/init` på nytt, rapporterer den da `Config files already exist`. For en ny installasjon som aldri har startet, flytter du de tre filene til en sikkerhetskopimappe og kjører `bin/init` på nytt. For en eksisterende instans beholder du konfigurasjonen og hemmelighetene, og du skal ikke slette filene for å få `bin/init` til å kjøre igjen.

### MongoDB starter stadig på nytt {#mongodb-keeps-restarting}

Les MongoDB-loggene og kjerneversjonen til Docker-VM-en:

```bash
bin/docker-compose logs --tail=100 mongo
docker info --format '{{.KernelVersion}}'
```

Hvis loggen nevner inkompatibiliteten med Linux-kjernen, følger du [Sjekk Linux-kjernen i Docker-VM-en](/no/on-premises/installation/using-docker-compose/macos/5.-personalizing-your-instance#check-the-docker-vms-linux-kernel) og kjører `bin/up -d` på nytt. Avslutningskode `137` alene beviser ikke at MongoDB gikk tom for minne: sjekk containerens tilstand og loggene. For et eldre MongoDB-problem på Docker Desktop, se også [Feilsøking](/no/on-premises/support/troubleshooting).

### Kan ikke koble til Docker-daemonen {#cannot-connect-to-the-docker-daemon}

Start Docker Desktop og sjekk den valgte Docker-konteksten, se [0. Sett opp Docker Desktop](/no/on-premises/installation/using-docker-compose/macos/0.-setup-docker-desktop). Hvis `docker info` fungerer, men kompileringer ikke når Docker, sjekker du socketinnstillingene i `config/overleaf.rc` og leser `clsi`-loggene. En fungerende Docker CLI på Mac-en beviser ikke at applikasjonens socketmontering er riktig.

### Siden åpnes, men kompileringer mislykkes {#the-page-opens-but-compiles-fail}

Sjekk at TeX Live-imaget finnes lokalt og samsvarer med arkitekturen til Docker-motoren:

```bash
docker image inspect ghcr.io/ayaka-notes/texlive-full:2026.1 \
  --format '{{.Os}}/{{.Architecture}}'
bin/logs -f clsi
```

På Apple silicon skal imaget være `linux/arm64`. Sjekk at `SERVER_PRO` og `SIBLING_CONTAINERS_ENABLED` begge er `true`, og ta deretter i bruk endringene med `bin/up -d`. Hvis loggene rapporterer en manglende kompileringsmappe, sjekker du fildelingen i Docker Desktop og plasseringen til `OVERLEAF_DATA_PATH`. Ikke slå av sandkassede kompileringer for å skjule en monteringsfeil.

### Not a directory, eller en bind-montering mangler {#not-a-directory-or-a-bind-mount-is-missing}

En vertsfil som en override monterer, kan ha blitt slettet, eller Docker kan ha opprettet en mappe der filen skulle vært. Sjekk kildestien på verten, og om monteringen forventer en fil eller en mappe. Gjenopprett konfigurasjonsfilen før du gjenoppretter containeren. En installasjon under `/tmp` kan få dette problemet etter at macOS fjerner midlertidige filer.

### Konflikter med port eller containernavn {#port-or-container-name-conflicts}

Hvis port `8080` er i bruk, velger du en annen port i `config/overleaf.rc`, setter `OVERLEAF_SITE_URL` tilsvarende og kjører `bin/up -d` på nytt.

Toolkit gir containerne sine faste navn som `sharelatex`, `mongo` og `redis`. Å endre bare `PROJECT_NAME` gjør ikke to Toolkit-installasjoner uavhengige. Før du starter en ny instans, sjekker du `docker ps -a` og bruker andre containernavn i en Compose-override, en annen port og separate datamapper. Ikke fjern containerne eller dataene til en eksisterende installasjon for å løse en navnekonflikt.

### Instansen er utilgjengelig etter en stund {#the-instance-is-unreachable-after-a-while}

Mac-en har sannsynligvis gått i dvale, eller Docker Desktop ble avsluttet. Se [Hold instansen tilgjengelig](/no/on-premises/installation/using-docker-compose/macos/6.-post-installation-tasks#keep-the-instance-available).

### `bin/doctor` sier at dette ikke er Linux, eller ber om en Quay-pålogging {#bin/doctor-says-this-is-not-linux-or-asks-for-a-quay-login}

Begge advarslene er forventet på macOS med det offentlige imaget, se [2. Bli kjent med Toolkit](/no/on-premises/installation/using-docker-compose/macos/2.-familiarize-yourself-with-the-toolkit). Sjekk i stedet hentingen av image, tjenestestatusen og kompileringsresultatene, og ikke ignorer andre feil i rapporten.
