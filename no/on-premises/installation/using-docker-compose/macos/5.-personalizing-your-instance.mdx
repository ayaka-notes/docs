<Steps>
<Step title="Containerinnstillinger">
Rediger disse eksisterende oppføringene i `config/overleaf.rc`:

```bash title="config/overleaf.rc"
PROJECT_NAME=ayakaleaf-macos
SERVER_PRO=true
OVERLEAF_LISTEN_IP=127.0.0.1
OVERLEAF_PORT=8080
SIBLING_CONTAINERS_ENABLED=true
DOCKER_SOCKET_PATH=/var/run/docker.sock
```

Behold standardstiene for data og de medfølgende MongoDB- og Redis-tjenestene. Med `OVERLEAF_LISTEN_IP=127.0.0.1` kan bare nettlesere på denne Mac-en åpne instansen.
</Step>

<Step title="Applikasjonsinnstillinger">
I `config/variables.env` setter du disse verdiene og erstatter eventuelle aktive oppføringer med samme navn:

```dotenv title="config/variables.env"
OVERLEAF_SITE_URL=http://localhost:8080
TEX_LIVE_DOCKER_IMAGE=ghcr.io/ayaka-notes/texlive-full:2026.1
ALL_TEX_LIVE_DOCKER_IMAGES=ghcr.io/ayaka-notes/texlive-full:2026.1
ALL_TEX_LIVE_DOCKER_IMAGE_NAMES="TeX Live 2026"
```

Generer en økthemmelighet:

```bash
openssl rand -hex 32
```

Legg til resultatet som `OVERLEAF_SESSION_SECRET` i `config/variables.env`. Uten den logger hver `bin/up` som gjenoppretter containeren, ut alle brukere, se [Miljøvariabler](/no/on-premises/configuration/overleaf-toolkit/environment-variables).

For en lokal instans uten e-post lar du SMTP-innstillingene og `OVERLEAF_EMAIL_FROM_ADDRESS` være uangitt. Git Bridge, ekstern autentisering og de andre integrasjonene kan legges til senere med sine egne [konfigurasjonssider](/no/on-premises/configuration/overleaf-toolkit).
</Step>

<Step title="Sjekk Linux-kjernen i Docker-VM-en" id="check-the-docker-vms-linux-kernel">
MongoDB kjører på Linux-kjernen i den virtuelle maskinen til Docker Desktop, ikke på macOS. Sjekk versjonen før første oppstart:

```bash
docker info --format '{{.KernelVersion}}'
```

MongoDB dokumenterer en inkompatibilitet med Linux-kjerner **6.19 til og med 7.0.13**, som også påvirker MongoDB i Docker. Løsningen er en kjerne **7.0.14 eller nyere**, som kommer med en oppdatering av Docker Desktop, se [MongoDBs produksjonsmerknader](https://www.mongodb.com/docs/manual/administration/production-notes/).

Hvis Docker-VM-en din bruker en berørt kjerne, legger du til følgende i `config/docker-compose.override.yml`, slått sammen med eventuelle `services` du allerede har der:

```yaml title="config/docker-compose.override.yml"
services:
  mongo:
    environment:
      GLIBC_TUNABLES: glibc.pthread.rseq=1
```

<Warning>

Oppdater til en rettet kjerne når den er tilgjengelig. Hvis kjernen din er utenfor det berørte området, er denne løsningen unødvendig.

</Warning>
</Step>

<Step title="Start instansen din">
Fra Toolkit-mappen kjører du:

```bash
bin/up -d
```

Toolkit initialiserer MongoDBs replikasett, henter TeX Live-imaget og starter applikasjonen. Den første nedlastingen tar en stund. Slik følger du fremdriften:

```bash
bin/docker-compose ps
bin/docker-compose logs --tail=100 -f sharelatex
```

Trykk `Ctrl+C` for å slutte å følge loggene. Containerne fortsetter å kjøre.

Sjekk den publiserte porten og siden for første kjøring:

```bash
bin/docker-compose port sharelatex 80
curl -I http://localhost:8080/launchpad
```

Porten skal være `127.0.0.1:8080`.
</Step>
</Steps>
