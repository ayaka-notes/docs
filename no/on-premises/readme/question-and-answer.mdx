Her har vi samlet svar på noen vanlige spørsmål om Ayakaleaf Pro.

### Grunnleggende spørsmål

<Accordion title="Q01: Er Ayakaleaf Pro en gratis prøveversjon? Krever den en lisens?">

Nei. Ayakaleaf Pro er helt gratis å bruke. Det er ikke en prøveversjon og krever ingen lisens.

</Accordion>

<Accordion title="Q02: Inkluderer dere (ayakaleaf pro) alle funksjonene i Overleaf Server Pro?">

Ja. Ayakaleaf Pro inkluderer alle funksjonene i Overleaf Server Pro, inkludert Git-Bridge-integrasjon. Den inkluderer også utvalgte funksjoner fra SaaS-plattformen til Overleaf. Vi fortsetter å utvikle og forbedre Ayakaleaf Pro.

</Accordion>

<Accordion title="Q03: Hva koster Overleaf Server Pro?">

Overleaf Server Pro koster rundt \$300 per bruker per år. Det kreves minst 10 lisenser, så installasjoner starter på omtrent \$3,000 i året. Mindre offentlige kontrakter i USA viser årlige kostnader på rundt \$320–\$370 per bruker. Dette gjør Server Pro dyrt, særlig for mindre team. Se [#information-and-price-about-overleaf-server-pro](/no/on-premises#information-and-price-about-overleaf-server-pro  "mention") for dokumenterte kjøp og priser.

</Accordion>

<Accordion title="Q04: Hvorfor inkluderer ikke Overleaf Server Pro GitHub Sync eller AI-funksjoner?">

Overleaf Server Pro brukes ofte av offentlige organisasjoner. De installerer den i private nettverk og kontrollerer tilgangen strengt. For å beskytte sensitive data unngår de inkluderte funksjonene å utveksle data med tredjepartstjenester. Hvis du trenger GitHub Sync, AI eller lignende tilkoblede funksjoner, anbefaler Overleaf et abonnement på SaaS-plattformen sin.

</Accordion>

<Accordion title="Q05: Er Ayakaleaf Pro sikker og pålitelig?">

Ayakaleaf Pro er åpen kildekode. Vi gjennomgår koden med verktøy som Codex Security for å styrke sikkerheten og påliteligheten. Hvis du ikke aktiverer datasynkronisering med tredjeparter, blir dataene dine liggende på serveren din. Ayakaleaf Pro inneholder ingen telemetri som sender dataene dine andre steder.

</Accordion>

<Accordion title="Q06: Vil Ayakaleaf Pro bli vedlikeholdt på lang sikt?">

Vi vil gjøre vårt ytterste for å vedlikeholde dette prosjektet på lang sikt.

</Accordion>

<Accordion title="Q07: Er Ayakaleaf Pro i samsvar med regelverk og lisenser?">

Ayakaleaf Pro er en fork drevet av fellesskapet. Koden og de integrerte funksjonene kommer fra bidrag fra fellesskapet. Den er lisensiert under AGPL v3. Installasjoner kan overholde denne lisensen når de oppfyller kravene i den.

</Accordion>

<Accordion title="Q08: Hvorfor heter prosjektet Ayakaleaf Pro?">

Prosjektet het opprinnelig Overleaf Pro i 2024. Utviklingen ble satt på pause en periode og startet igjen sent i 2025. I første kvartal 2026 endret Overleaf navnet på sitt AI-aktiverte abonnement til Pro. Tilbakemeldinger fra fellesskapet påpekte også at navnet Overleaf Pro kunne skape risiko knyttet til varemerker og etterligning. Det kunne få brukere til å tro at prosjektet var offisielt.

Vi endret navnet på prosjektet til Ayakaleaf Pro for å unngå denne forvirringen. Navnet kan leses som «Ayaka-notes Overleaf Pro». Vedlikeholderen (du kan kalle meg ayaka!) har bidratt til utviklingen i Overleaf-fellesskapet siden studietiden, for over fem år siden. Denne erfaringen underbygger vår forpliktelse til langsiktig vedlikehold.

</Accordion>

<Accordion title="Q09: Hva skiller Ayakaleaf Pro fra nyere AI-bygde LaTeX-editorer?">

Siden 2026 har fellesskapet for åpen kildekode lansert mange AI-bygde LaTeX-editorer, inkludert OpenAI Prism. Ayakaleaf Pro holder dataene og tjenestene dine på din egen server. Dette gir deg direkte kontroll over installasjonen og dataene dine.

Mange eksperimentelle editorer fra fellesskapet har ingen etablert plan for langsiktig vedlikehold. Tredjepartsplattformer for LaTeX-kompilering kan også slutte å fungere når brukerbasen eller inntektene er utilstrekkelige. Ayakaleaf Pro leverer all kildekode og lar deg drifte alle tjenester selv. Selv om vedlikeholdet skulle stoppe, kan din eksisterende selvdriftede tjeneste fortsette å kjøre.

</Accordion>

### Funksjoner

<Accordion title="Q01: Hvilke funksjoner tilbyr Ayakaleaf Pro? Kan jeg be om en ny funksjon?">

Se dokumentasjonen vår for gjeldende funksjonsliste. Hvis det er en funksjon du vil at vi skal legge til, kan du gjerne opprette en issue (funksjonsforespørsel) på GitHub. Vi gjør vårt beste for å implementere ønskede funksjoner, men utvikling tar tid, og vi kan ikke garantere at alle funksjoner blir levert med en gang.

</Accordion>

<Accordion title="Q02: Jeg har utviklet noen funksjoner. Kan jeg sende inn en PR, og er det garantert at den blir godtatt?">

Bidrag er velkomne, men det er ingen garanti for at de blir godtatt. Vi vurderer hver PR ut fra hvordan den påvirker den underliggende Overleaf-kodebasen, vedlikeholdsbyrden og verdien den gir brukerne. Vi gjør vårt beste for å slå sammen og vedlikeholde verdifulle bidrag.

Vi kan imidlertid avvise PR-er som innfører omfattende endringer, består av AI-generert kode som ikke er gjennomgått eller godt forstått («vibe coding»), eller legger til funksjoner som vil være vanskelige å vedlikeholde over tid.

</Accordion>

<Accordion title="Q03: Hvordan konfigurerer jeg en bestemt funksjon?">

Vi oppdaterer vanligvis dokumentasjonen hver gang vi lanserer en ny funksjon. Se den aktuelle dokumentasjonen for detaljerte oppsettsinstruksjoner og forklaringer av de tilgjengelige miljøvariablene.

</Accordion>

<Accordion title="Q04: Hvilke Python-biblioteker kan Python Runner bruke?">

Python Runner kjører Python i brukerens nettleser med [Pyodide](https://pyodide.org/) 0.29.3, ikke på serveren. Den laster inn pakkene som koden din importerer, fra [pakkene som er innebygd i Pyodide](https://pyodide.org/en/0.29.3/usage/packages-in-pyodide.html), som NumPy, pandas og Matplotlib. Pakker installert med `pip` og andre pakker er ikke tilgjengelige. Det er ingenting å konfigurere på serveren.

</Accordion>

<Accordion title="Q05: Kan stavekontrollen sjekke japansk eller kinesisk?">

Nei. Stavekontrollen har ingen ordbok for japansk eller kinesisk, så disse språkene finnes ikke i listen over språk for stavekontroll. Brukerne kan slå av stavekontrollen for et prosjekt i editorinnstillingene.

</Accordion>

### Installasjon

<Accordion title="Q01: Støtter Ayakaleaf Pro distribuert installasjon i k8s?">

For de fleste brukere anbefaler vi å installere med [Toolkit](/no/on-premises/installation/using-the-toolkit). Vi anbefaler ikke storskala klyngeinstallasjoner med Kubernetes eller lignende plattformer, siden de kan øke driftskompleksiteten og vedlikeholdsarbeidet betydelig.

</Accordion>

<Accordion title="Q02: Hvordan kan jeg sikre tilgjengelighet når jeg betjener tusenvis av brukere?">

Se veiledningen vår om [horisontal skalering](/no/on-premises/maintenance/horizontal-scaling). Du kan installere flere Overleaf-instanser og konfigurere en lastbalanserer som fordeler trafikken mellom dem.

</Accordion>

<Accordion title="Q03: Kan dere hjelpe meg med installasjon eller migrering?">

Hvis du har en eksisterende Overleaf Server Pro-instans, hjelper vi deg gjerne med å migrere til Ayakaleaf Pro. Ta kontakt via e-post eller issues.

</Accordion>

<Accordion title="Q04: Kan jeg hoste Ayakaleaf Pro under en understi i URL-en, som `https://example.com/overleaf`?">

Nei. Ayakaleaf Pro må serveres fra roten av et domene. Bruk et eget domene eller underdomene, for eksempel `https://overleaf.example.com`.

</Accordion>

<Accordion title="Q05: Kan jeg kjøre Ayakaleaf Pro på Windows eller macOS, eller uten Toolkit?">

Vi støtter Linux-servere med [Toolkit](/no/on-premises/installation/using-the-toolkit). Docker Desktop på Windows, WSL2 eller macOS kan fungere, men vi tester det ikke, se [Feilsøking](/no/on-premises/support/troubleshooting) for et kjent problem med MongoDB.

Vi tilbyr ingen frittstående `docker-compose.yml`. For å se Compose-konfigurasjonen som Toolkit bruker, kjører du `bin/docker-compose config` i Toolkit-katalogen.

</Accordion>

<Accordion title="Q06: Hvordan avinstallerer jeg Ayakaleaf Pro?">

Det finnes ikke noe avinstalleringsskript. I Toolkit-katalogen:

1. Stopp og fjern containerne med `bin/docker-compose down`.
2. Slett dataene. Som standard ligger de i katalogen `data/` i Toolkit. Hvis du har endret `OVERLEAF_DATA_PATH`, `MONGO_DATA_PATH`, `REDIS_DATA_PATH` eller `GIT_BRIDGE_DATA_PATH` i `config/overleaf.rc`, må du også slette disse katalogene. Dette kan ikke angres, så [ta sikkerhetskopi](/no/on-premises/maintenance/data-and-backups) først hvis du kan få bruk for dataene.
3. Slett Toolkit-katalogen.
4. Fjern Docker-imagene, som du kan liste opp med `docker images`: `ghcr.io/ayaka-notes/overleaf-pro`, git-bridge-imaget, `mongo`, `redis` og TeX Live-imagene.

</Accordion>

<Accordion title="Q07: Hvordan stopper, starter eller starter jeg Ayakaleaf Pro på nytt?">

Kjør disse i Toolkit-katalogen:

* `bin/stop` stopper alle containerne, og `bin/start` starter dem igjen. Containerne beholdes, så brukerne forblir innlogget.
* `bin/up -d` oppretter containerne og starter dem i bakgrunnen. Kjør den etter at du har endret `config/variables.env`, `config/overleaf.rc` eller `config/version`: den gjenoppretter containerne der konfigurasjonen er endret, og først da trer endringene i kraft. `bin/stop` og `bin/start` tar dem ikke i bruk.
* `bin/docker-compose restart sharelatex` starter bare Overleaf-containeren på nytt, uten å ta i bruk konfigurasjonsendringer.

Hvis brukerne logges ut hver gang `bin/up` gjenoppretter containeren, setter du `OVERLEAF_SESSION_SECRET`, se spørsmål og svar i [Miljøvariabler](/no/on-premises/configuration/overleaf-toolkit/environment-variables).

</Accordion>

<Accordion title="Q08: Hvor legger jeg inn OAuth-callback-URL-en?">

I applikasjonen du oppretter hos leverandøren, ikke i Ayakaleaf Pro. Det finnes ingen callback-innstilling i `config/variables.env` for noen av disse integrasjonene: Ayakaleaf Pro bygger hver callback-URL fra `OVERLEAF_SITE_URL` og sender den til leverandøren, som avviser den med mindre den samsvarer med den som er registrert for applikasjonen. Du registrerer den altså bare hos leverandøren, og setter `OVERLEAF_SITE_URL` til adressen brukerne åpner.

| Integrasjon | Felt hos leverandøren | Verdi |
| --- | --- | --- |
| [GitHub](/no/on-premises/configuration/overleaf-toolkit/github-synchronisation) | Authorization callback URL | `${OVERLEAF_SITE_URL}/user/github-sync/oauth2/callback` |
| [GitLab](/no/on-premises/configuration/overleaf-toolkit/gitlab-synchronisation) | Redirect URI | `${OVERLEAF_SITE_URL}/user/gitlab-sync/oauth2/callback` |
| [Gitea](/no/on-premises/configuration/overleaf-toolkit/gitea-synchronisation) | Redirect URIs | `${OVERLEAF_SITE_URL}/user/gitea-sync/oauth2/callback` |
| [Dropbox](/no/on-premises/configuration/overleaf-toolkit/dropbox-synchronisation) | Redirect URIs (klikk **Add**) | `${OVERLEAF_SITE_URL}/user/dropbox/oauth/callback` |
| [Zotero](/no/on-premises/configuration/overleaf-toolkit/zotero-integration) | Callback URL | `${OVERLEAF_SITE_URL}/user/zotero/oauth/callback` |
| [Mendeley](/no/on-premises/configuration/overleaf-toolkit/mendeley-integration) | Redirect URL | `${OVERLEAF_SITE_URL}/user/mendeley/oauth/callback` |
| [OIDC-innlogging](/no/on-premises/configuration/overleaf-toolkit/authentication/oidc-authentication) | Redirect URI | `${OVERLEAF_SITE_URL}/oidc/login/callback` |
| [SAML-innlogging](/no/on-premises/configuration/overleaf-toolkit/authentication/saml-authentication) | ACS URL (Assertion Consumer Service) | `${OVERLEAF_SITE_URL}/saml/login/callback` |

Hvis du endrer `OVERLEAF_SITE_URL`, for eksempel til et nytt domene, må du også oppdatere URL-en hos hver leverandør, ellers mislykkes koblingen.

</Accordion>

### LaTeX

<Accordion title="Q01: Er brukernes kompileringer av LaTeX-prosjekter isolert? Er Shell Escape aktivert?">

Når du aktiverer Sandbox Compiles, kjøres hver brukers kompilering i en separat Docker-container og er isolert fra andre brukeres kompileringer. Shell Escape er aktivert som standard for Sandbox Compiles.

</Accordion>

<Accordion title="Q02: Er Sandbox Compiles-imaget pålitelig? Kan kompileringen mislykkes?">

Vi har forbedret TeX Live Full-imaget vårt for Sandbox Compiles gjennom de siste tre årene. I de fleste tilfeller vil prosjekter som kompilerer på overleaf.com, også kompilere riktig med Ayakaleaf Pro. Hvis en nødvendig skrifttype ikke er tilgjengelig, kan du laste opp skrifttypen til prosjektet manuelt.

</Accordion>

<Accordion title="Q03: Prosjektet mitt vil ikke kompilere. Kan dere hjelpe meg med feilsøkingen?">

Last opp prosjektet ditt til det offisielle Overleaf-nettstedet, aktiver deling med skrivebeskyttet lenke, og legg ved lenken i en GitHub-issue.

Vi undersøker og retter feil som hindrer et prosjekt i å kompilere i Ayakaleaf Pro når det kompilerer uten problemer på det offisielle Overleaf-nettstedet. Kompileringsproblemer utenfor dette omfanget dekkes ikke av støtten vår.

</Accordion>
