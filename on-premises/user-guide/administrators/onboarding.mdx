---
title: Onboarding
description: Create the first administrator, check your instance and add the first user.
icon: user-plus
---

Do this once, right after the [installation](/on-premises/installation/introduction). This page uses the default password login.

<Steps>
<Step title="Open the launchpad">
Open `/launchpad` on your instance, for example `http://localhost/launchpad`. You see **Create the first Admin account**.

The form is there only until the first administrator exists. After that, signed-out visitors are sent to the login page.
</Step>

<Step title="Create the administrator account">
Enter an email and a password, then click **Register**.

<Frame caption="The first administrator account">
  <img src="/images/on-premises/onboarding-launchpad-filled.png" alt="The launchpad form filled in with admin@example.com" />
</Frame>

If the password is refused, a message appears above the form and no account is created.

<Frame caption="A refused password">
  <img src="/images/on-premises/onboarding-password-error.png" alt="The message password is too short above the launchpad form" />
</Frame>

| Message                                    | Meaning                                                                                                                                                            |
| ------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `password is too short`                    | Fewer than 8 characters.                                                                                                                                           |
| `password is too long`                     | More than 72 characters.                                                                                                                                           |
| `password contains an invalid character`   | Allowed are letters `a-z` and `A-Z`, digits and `@#$%^&*()-_=+[]{};:<>/?!£€.,`. Spaces and accented or non-Latin letters are not.                                  |
| `password contains part of email address`  | It contains the email or the part before `@`, or it is part of the email. For `admin@example.com`, both `admin-7Tq9-demo` and `example.com` are refused.           |
| `password is too similar to email address` | It is close to the email, for example `adm1n@example.c0m`.                                                                                                         |

Capital letters, digits and symbols are not required by default. To change the length limits, see [Password restrictions](/on-premises/configuration/overleaf-toolkit/authentication/password-restrictions).
</Step>

<Step title="Log in">
After **Register** you are on the login page. Enter the same email and password, then click **Login**.

<Frame caption="Log in with the new account">
  <img src="/images/on-premises/onboarding-login.png" alt="The login page filled in with admin@example.com" />
</Frame>

You are back on the launchpad, now with **Status Checks**.
</Step>

<Step title="Check the instance">
`websockets` should show **OK**.

To test email, enter your address under **Send a test email**, click **Send**, then check your inbox.

<Frame caption="Status checks and the test email">
  <img src="/images/on-premises/onboarding-launchpad-checks.png" alt="The launchpad with websockets OK, the test email form showing Email Sent, and the two buttons at the bottom" />
</Frame>

<Warning>

**Email Sent** does not prove that a message left the server. Without [email delivery](/on-premises/configuration/overleaf-toolkit/email-delivery), the page shows the same text and nothing arrives.

</Warning>

**Start Using** _your site name_ opens your projects. **Go To Admin Panel** opens the site tools, see [Basic management](/on-premises/user-guide/administrators/basic-management).
</Step>

<Step title="Create the first user">
In the top menu, click **Admin**, then **Manage Users**.

<Frame caption="The Admin menu">
  <img src="/images/on-premises/onboarding-admin-menu.png" alt="The Admin menu with Manage Site, Manage Users and Project/Object Lookup" />
</Frame>

Click **Create account**.

<Frame caption="The user list">
  <img src="/images/on-premises/onboarding-user-list.png" alt="The user list with the administrator and the Create account button" />
</Frame>

Enter the user's email. **First name** and **Last name** are optional. Tick **Admin** only for another administrator. Click **Create**.

<Frame caption="The Create account dialog">
  <img src="/images/on-premises/onboarding-create-account.png" alt="The Create account dialog filled in with user@example.com" />
</Frame>

The account appears in the list with the status **Pending**.

<Frame caption="A new account stays Pending until its first login">
  <img src="/images/on-premises/onboarding-user-pending.png" alt="The user list with Demo User in the Pending status" />
</Frame>
</Step>

<Step title="Give the user access">
**With email delivery configured**, the user receives an activation email with a **Set password** link. The link opens this page. The user enters a password and clicks **Activate**, and then lands on the projects page. The password rules above apply.

<Frame caption="What the user sees after opening the link">
  <img src="/images/on-premises/onboarding-activate.png" alt="The activation page asking the user to set a password" />
</Frame>

**Without email delivery**, pass the link on yourself. In **Manage Users**, click the envelope icon on the user's row, then **Send activation email**. The dialog says **No email was sent** and shows the link, which expires in 7 days. Click the copy icon and send the link to the user, who sets a password as above.

<Frame caption="The activation link to pass on">
  <img src="/images/on-premises/onboarding-activation-link.png" alt="The Send activation email dialog for Demo User with the warning that no email was sent, the link, a copy icon and Expires in 7 days" />
</Frame>

You can also set a password yourself. In **Manage Users**, click the user's name, then the pencil icon. Enter **New password** and click **Save**. Pass the password on to the user, who logs in at `/login`.

<Frame caption="Setting a password on the Account tab">
  <img src="/images/on-premises/onboarding-set-password.png" alt="The Account tab of a user in edit mode with the New password field filled in" />
</Frame>
</Step>

<Step title="Confirm it worked">
After the user's first login, the status in **Manage Users** changes to **Active**.

<Frame caption="The user has logged in">
  <img src="/images/on-premises/onboarding-user-active.png" alt="The user list with Demo User in the Active status" />
</Frame>
</Step>
</Steps>

<Info>

**Sign up** does not create accounts by default: the page asks visitors to contact the address in `OVERLEAF_ADMIN_EMAIL`. To let people register themselves, see [Public Access](/on-premises/configuration/overleaf-toolkit/authentication/public-access).

</Info>
