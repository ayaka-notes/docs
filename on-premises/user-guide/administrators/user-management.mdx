## Find a user

Type in **Search by name, email or ID**. A full name works too, such as `Carol Novak`, and the search also finds a user by any of their [secondary emails](/on-premises/user-guide/users/multiple-emails). To narrow the list, use the filters on the **Login**, **Role** and **Status** columns. Click **Name**, **Sign up** or **Last logged in** to sort.

<Frame caption="Searching for a user">
  <img src="/images/on-premises/user-management-search.png" alt="The user list filtered by the search carol" />
</Frame>

Deleted accounts do not appear in the results. If your search also matches one, a line above the table says so, for example **Found 1 matching deleted users**. Click **Display deleted users** to see them.

## User status

Every account has exactly one status, and the **Status** filter shows how many accounts each one has. Hover over a question mark to read its definition.

<Frame caption="The Status filter">
  <img src="/images/on-premises/user-management-status-tooltip.png" alt="The Status filter with the tooltip of Active" />
</Frame>

| Status         | What it means                                                                                                                                                     | Can log in |
| -------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------- |
| **All**        | Every account that is not deleted. The four statuses below (Active + Pending + Inactive + Disabled) add up to this number.                                        |            |
| **Active**     | Logged in or opened a project in the last 12 months.                                                                                                              | Yes        |
| **Pending**    | Has never logged in: usually an account created by an administrator, or registered with an activation email, that the user has not activated yet. An account registered with a password needs no activation and becomes Active at its first login.                                                                                                               | Yes        |
| **Inactive**   | Logged in before, but no login or opened project in the last 12 months.                                                                                           | Yes        |
| **Disabled**   | An administrator disabled the account. Logging in leads to the page **Your account is suspended**.                                                                | No         |
| **Deleted user** | The account was deleted by an administrator or by the user. It is not counted in **All** and is hidden until you choose this filter. Logging in says the email or password is incorrect.                            | No         |

Accounts move between the statuses like this:

* **Pending, Active and Inactive** follow the account's use, so you cannot set them. An Inactive account becomes Active as soon as the user logs in.
* **Enable** and **Restore** do not bring back an earlier status. The status comes from the last login: an account that has never logged in is Pending again. A disabled account stays **Disabled** after **Restore**.
* **Delete permanently** cannot be undone. Deleted accounts otherwise stay until you remove them, unless the instance sets [`ENABLE_CRON_RESOURCE_DELETION`](/on-premises/configuration/overleaf-toolkit/environment-variables), which removes them after 90 days.

### Active users on the License tab

The **License** tab and the **Active** status can show different numbers, because they count different things. The **License** tab counts the users a Server Pro license covers, as Overleaf defines them in [Understanding license usage](https://docs.overleaf.com/on-premises/user-and-project-management/understanding-license-usage): "any user who logs in and accesses a project is considered an active user by the system", and "An active user is defined as someone who has opened a project on your Server Pro instance in the last 12 months." A user who logged in but opened no project is **Active** in the list, but does not count for the license. A user who opened a project and was disabled later counts for the license, but is **Disabled** in the list.

## Actions on a user

The icons in the **Actions** column are the same ones as at the top of a user's page.

| Icon          | Action                          | What it does                                                 |
| ------------- | ------------------------------- | ------------------------------------------------------------ |
| Envelope      | **Send activation email**       | For an account that has never logged in: a new activation link. |
| Lock with an arrow | **Send reset link**        | For an account that has logged in: a new password reset link. |
| Folder        | **Transfer this user's projects** | Gives all the projects the user owns to another user.        |
| Circle        | **Disable**                     | Stops the user from logging in.                              |
| Play          | **Enable**                      | Lets a disabled user log in again.                           |
| Bin           | **Delete account**              | Moves the account to **Deleted user**.                       |
| Arrow         | **Restore**                     | Brings a deleted account back. Only for deleted accounts.    |
| Crossed bin   | **Delete permanently**          | Removes a deleted account for good. Only for deleted accounts. |

Each action asks for confirmation in a dialog that names the account.

### Send an activation or reset link

An account shows one of these two icons, depending on whether it has logged in. The icon is greyed out for a disabled account, for an account without a local password, such as an SSO account, and for your own account.

Click the icon, then the button with the same name. The dialog stays open and shows the link:

* **Email Sent** means that the email went out.
* <strong>No email was sent. Copy the link and pass it on.</strong> means that [email delivery](/on-premises/configuration/overleaf-toolkit/email-delivery) is not configured or the email failed. Click the copy icon and send the user the link yourself.

An activation link expires in 7 days, a reset link in 1 hour. The user opens the link and sets a password. After an activation link they land on their projects, and after a reset link they log in.

### Disable or enable an account

Click the circle icon, then **Disable**. The status changes to **Disabled**, and the user can no longer log in. To undo it, click the play icon, then **Enable**.

<Frame caption="Disabling an account">
  <img src="/images/on-premises/user-management-disable.png" alt="The Disable dialog naming Dave Okafor" />
</Frame>

### Transfer a user's projects

Click the folder icon. Type a name or email under **Select a new owner for this user's projects**, choose the user, then click **Transfer this user's projects**. The **Owner** of those projects changes in [Project management](/on-premises/user-guide/administrators/project-management).

Disabled accounts are not offered as the new owner. If you change the text after choosing, the choice is cancelled: choose the user again.

<Frame caption="Transferring all of a user's projects">
  <img src="/images/on-premises/user-management-transfer.png" alt="The transfer dialog with Carol Novak chosen as the new owner" />
</Frame>

### Delete an account

Click the bin icon. Two options are available, and neither is selected by default:

* **Notify the user about the account deletion** sends the user an email.
* **Transfer this user's projects** lets you choose a new owner for the projects first. They stay active under the new owner.

Click **Delete account**. If you do not transfer the projects, they are deleted with the account and move to the **Deleted** status of [Project management](/on-premises/user-guide/administrators/project-management#project-status).

<Frame caption="Deleting an account and transferring its projects">
  <img src="/images/on-premises/user-management-delete.png" alt="The Delete account dialog with both options ticked and a new owner chosen" />
</Frame>

### Restore or permanently delete an account

Choose **Deleted user** in the **Status** filter, or click **Display deleted users** after a search.

<Frame caption="A deleted account">
  <img src="/images/on-premises/user-management-deleted-list.png" alt="The list of deleted users with the Restore and Delete permanently icons" />
</Frame>

* **Restore** brings the account back. A disabled account stays disabled. The projects deleted with the account come back too, and each one's name gets `(Restored)` at the end. Projects the user had deleted themselves stay deleted.
* **Delete permanently** removes the account. The dialog warns that this cannot be undone.

<Frame caption="Deleting an account permanently">
  <img src="/images/on-premises/user-management-purge.png" alt="The Delete permanently dialog warning that the action cannot be undone" />
</Frame>

### Change several accounts at once

Tick the accounts in the list. Buttons appear next to **Create account**: **Send activation email**, **Transfer this user's projects**, **Disable**, **Enable**, **Make admin**, **Remove admin** and **Delete account**. The bottom of the list shows how many accounts are selected. The dialog lists them before you confirm.

<Frame caption="Bulk actions">
  <img src="/images/on-premises/user-management-bulk.png" alt="Two ticked accounts and the bulk action buttons above the list, with the envelope greyed out" />
</Frame>

**Send activation email** is greyed out unless all the ticked accounts are **Pending**. The dialog then shows one link per account. There is no bulk reset link.

<Frame caption="One activation link per account">
  <img src="/images/on-premises/user-management-bulk-links.png" alt="The Send activation email dialog with a link for Hana Ito and a link for Erin Silva, and Expires in 7 days" />
</Frame>

## The user page

Click a user's name to open their page. It has six tabs.

### Account

The account's details. To change them, click the pencil icon, edit the fields, then click **Save**. You can change the email, the names and the password, and turn **Admin** on or off.

If the user added [more emails](/on-premises/user-guide/users/multiple-emails), they are listed under **Emails**. While you edit, **Remove** takes a secondary email off the account, and another account can then use that address.

<Frame caption="An account with two emails">
  <img src="/images/on-premises/user-management-secondary-email.png" alt="The Account tab being edited, with a primary email and a secondary email with a Remove button" />
</Frame>

The [password rules](/on-premises/user-guide/administrators/onboarding#create-the-administrator-account) from onboarding apply. Passing the password on to the user is up to you. To let the user choose it, [send a reset link](/on-premises/user-guide/administrators/user-management#send-an-activation-or-reset-link) instead.

<Frame caption="Editing an account">
  <img src="/images/on-premises/user-management-edit.png" alt="The Account tab in edit mode" />
</Frame>

### Projects

The projects this user owns, with the same search, **Status** filter and actions as in [Project management](/on-premises/user-guide/administrators/project-management).

<Frame caption="A user's projects">
  <img src="/images/on-premises/user-management-projects.png" alt="The Projects tab of a user" />
</Frame>

### Features

What this account has switched on: collaboration, compile timeout, integrations and AI. To change them, click the pencil icon, change the values, then click **Save**. For **Collaborators per project**, `-1` means unlimited. **Compile timeout** is in seconds, from 1 to 600.

On your own account, the pencil and the **Reset** of **AI usage** are greyed out. On the **Account** tab you can still change your own email, names and password.

<Frame caption="A user's features">
  <img src="/images/on-premises/user-management-features.png" alt="The Features tab in edit mode" />
</Frame>

### Integrations

The user's Git access tokens and which accounts they linked. This tab is read-only.

<Frame caption="A user's integrations">
  <img src="/images/on-premises/user-management-integrations.png" alt="The Integrations tab with GitHub, GitLab and Gitea ticked as linked" />
</Frame>

### Audit logs

What happened to this account: the date, the operation, who did it, the IP address and details. Search it, or filter by **Operation**. Actions you take on an account appear here with you as the initiator.

<Frame caption="A user's audit logs">
  <img src="/images/on-premises/user-management-audit.png" alt="The Audit logs tab listing the user's logins and feature changes by an administrator" />
</Frame>

### Sessions

Where the user is logged in. Click **Clear sessions** and confirm to log them out everywhere. The tab then says **Sessions cleared**.

<Frame caption="A user's sessions">
  <img src="/images/on-premises/user-management-sessions.png" alt="The Sessions tab with one session and the Clear sessions button" />
</Frame>
