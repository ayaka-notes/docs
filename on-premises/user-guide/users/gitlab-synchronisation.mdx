Connect a project to a GitLab repository. Changes go both ways, and only when you click **Sync**: nothing syncs on its own.

<Info>

An administrator has to turn on [GitLab Synchronisation](/on-premises/configuration/overleaf-toolkit/integrations/gitlab-synchronisation) first.

</Info>

## Link your GitLab account

You do this once.

<Steps>
<Step title="Open your account settings">
Click **Account**, then **Account settings**. Under **Project synchronisation**, find **GitLab** and click **Link**.

<Frame caption="GitLab in the account settings">
  <img src="/images/on-premises/gitlab-sync-link.png" alt="The GitLab section of the account settings with a Link button" />
</Frame>
</Step>

<Step title="Authorize on GitLab">
GitLab opens. Sign in if you are asked to, then authorize the application.
</Step>

<Step title="Check the link">
You are back in the account settings. A green message says your GitLab account is linked, and the button now says **Unlink**.

<Frame caption="Your GitLab account is linked">
  <img src="/images/on-premises/gitlab-sync-linked.png" alt="The GitLab section of the account settings with an Unlink button" />
</Frame>
</Step>
</Steps>

If your account is not linked yet, **Import from GitLab** and the **GitLab** card in the editor ask you to link it first. Click **Link to your GitLab account**. You also end up in the account settings, in a new tab if you started in the editor. Then go back and start again.

<Frame caption="The prompt when your account is not linked">
  <img src="/images/on-premises/gitlab-sync-link-prompt.png" alt="The Import from GitLab dialog with a Link to your GitLab account button" />
</Frame>

## Import a repository

This creates a new project from a GitLab repository, already linked to it.

<Steps>
<Step title="Open the import dialog">
On the projects page, click **New project**, then **Import from GitLab**.

<Frame caption="The New project menu">
  <img src="/images/on-premises/gitlab-sync-new-project-menu.png" alt="The New project menu with Import from GitLab" />
</Frame>
</Step>

<Step title="Choose the repository">
Click **Import to Overleaf** next to the repository. The list includes your repositories and those of your groups.

<Frame caption="Your GitLab repositories">
  <img src="/images/on-premises/gitlab-sync-import.png" alt="The Import from GitLab dialog listing four repositories" />
</Frame>
</Step>

<Step title="Check the project">
The new project opens with the files of the repository.

<Frame caption="The imported project">
  <img src="/images/on-premises/gitlab-sync-imported.png" alt="The editor showing the imported project with its files and compiled PDF" />
</Frame>
</Step>
</Steps>

## Export a project to a new repository

This creates a repository from a project and links them. A project can only be linked this way or by importing: you cannot link it to a repository that already exists.

<Steps>
<Step title="Open GitLab in the editor">
Open the project. In the left bar, click **Integrations**, then **GitLab**.

<Frame caption="The Integrations panel">
  <img src="/images/on-premises/gitlab-sync-integrations.png" alt="The Integrations panel with the GitLab card" />
</Frame>
</Step>

<Step title="Fill in the repository">
Choose the **Owner**, which can be you or one of your groups. When you pick a group, this field is called **Organization**. **Repository Name** starts as the project's name. The description is optional, and **Private** is selected by default. Click **Create a GitLab repository**.

<Frame caption="Export Project to GitLab">
  <img src="/images/on-premises/gitlab-sync-export.png" alt="The Export Project to GitLab form filled in" />
</Frame>

If the name is already taken, the dialog says <strong>Please check that the repository name is valid, and that you have permission to create the repository.</strong> Change the name and click the button again.
</Step>

<Step title="Check the link">
The dialog now says **This project is linked to** and names the repository.

<Frame caption="The project is linked">
  <img src="/images/on-premises/gitlab-sync-exported.png" alt="The Sync with GitLab dialog after the export" />
</Frame>
</Step>
</Steps>

## Sync

<Steps>
<Step title="Open the sync dialog">
Open a linked project. In the left bar, click **Integrations**, then **GitLab**.

**Recent commits in GitLab** lists what will come into the project.

<Frame caption="A new commit waiting in GitLab">
  <img src="/images/on-premises/gitlab-sync-new-commits.png" alt="The Sync with GitLab dialog listing one new commit" />
</Frame>
</Step>

<Step title="Describe your changes">
If you changed something in the project, a commit message box appears. It is optional: when you leave it empty, the commit is called `Updates from Overleaf`.

<Frame caption="The commit message for your changes">
  <img src="/images/on-premises/gitlab-sync-commit-message.png" alt="The Sync with GitLab dialog with a commit message filled in" />
</Frame>
</Step>

<Step title="Click Sync">
Click **Sync**. New commits from GitLab come into the project, and your changes go to the default branch of the repository. If both sides changed different things, they are merged for you.
</Step>

<Step title="Check the result">
The dialog shows <strong>No new commits in GitLab since last merge.</strong> and the commit message box is gone. The files in the editor and the commits on GitLab are up to date.

<Frame caption="Everything is in sync">
  <img src="/images/on-premises/gitlab-sync-done.png" alt="The Sync with GitLab dialog after syncing, with no new commits" />
</Frame>
</Step>
</Steps>

### If the same lines changed on both sides

The dialog says the changes could not be merged and names a new branch, `overleaf-YYYY-MM-DD-HHMMSS`, which holds your changes. Overleaf also opens a merge request from that branch on GitLab.

<Frame caption="A conflict">
  <img src="/images/on-premises/gitlab-sync-conflict.png" alt="The Sync with GitLab dialog with a merge conflict warning" />
</Frame>

1. Merge that branch into the default branch on GitLab or with Git. You can close the dialog in the meantime: it shows the same message when you open it again.
2. Click **I have manually merged. Continue**. The merged result comes into the project. If you click it before the branch is merged, the dialog stays as it is.
3. The branch stays on GitLab, unless you deleted it when merging. Delete it when you no longer need it.

The same dialog appears when the repository's merge rules hold the merge request back, for example when it needs an approval, even if no lines conflict. Once the rule allows it, merge the merge request on GitLab and click **I have manually merged. Continue**. See [How syncing works with GitLab](/on-premises/configuration/overleaf-toolkit/integrations/gitlab-synchronisation#how-syncing-works-with-gitlab).

## Unlink a project

Do this when you no longer want the project to sync.

<Steps>
<Step title="Click Unlink">
In the sync dialog, click **Unlink**.
</Step>

<Step title="Confirm">
Click **Confirm**. This only removes the link: the connection to a repository you own, which the warning mentions, is an option you have afterwards, not something that happens now.

<Frame caption="Confirm the unlink">
  <img src="/images/on-premises/gitlab-sync-unlink-project.png" alt="The Sync with GitLab dialog asking to confirm the unlink" />
</Frame>
</Step>

<Step title="Check the result">
The dialog now shows **Export Project to GitLab**. The project and the repository both keep their content. To sync again, export the project to a new repository, or import the repository into a new project.
</Step>
</Steps>

## Unlink your GitLab account

In **Account settings**, under **GitLab**, click **Unlink**, then **Unlink** again in the dialog.

<Frame caption="Unlink your account">
  <img src="/images/on-premises/gitlab-sync-unlink-account.png" alt="The Unlink GitLab Account dialog" />
</Frame>

Your projects stay linked to their repositories. You cannot sync them until you link your account again.

<Info>

For who can do what in a shared project, see [Who can link and sync](/on-premises/configuration/overleaf-toolkit/integrations/gitlab-synchronisation#who-can-link-and-sync).

</Info>
