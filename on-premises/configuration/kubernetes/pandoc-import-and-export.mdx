Pandoc conversions are run by the **clsi** service of every Ayakaleaf Pro pod, like compiles: clsi asks the Docker Engine of the node to start a container from `PANDOC_IMAGE`. The **web** service shows the import and export menus. What the feature does and how to build the image is described in [Pandoc Import and Export](/on-premises/configuration/overleaf-toolkit/pandoc-import-and-export).

| | |
| --- | --- |
| Services | web (menus and routes), clsi (runs the conversion), in every Ayakaleaf Pro pod |
| Node | Docker Engine and `PANDOC_IMAGE`, on every node that can run Ayakaleaf Pro |
| Requires | [Sandboxed Compiles](/on-premises/configuration/kubernetes/sandboxed-compiles) |
| Periodic jobs | none |

### Configuration

<Steps>
<Step title="Put the image into Docker on every node">
Build the image once from the `develop/pandoc` folder of the [ayakaleaf-pro](https://github.com/ayaka-notes/ayakaleaf-pro) repository, then load it into Docker on each node that can run Ayakaleaf Pro:

```bash
docker build -t overleaf-pandoc:local develop/pandoc
docker save overleaf-pandoc:local | ssh node-1 sudo docker load    # repeat for every node
```

Or push it to a registry the nodes can reach and `sudo docker pull` it on each node. As with the TeX Live images, it must be in **Docker**, not only in containerd.
</Step>

<Step title="ConfigMap">
```yaml
  ENABLE_PANDOC_CONVERSIONS: "true"
  PANDOC_IMAGE: overleaf-pandoc:local
```

Both web and clsi read `ENABLE_PANDOC_CONVERSIONS` from the same ConfigMap, so they cannot disagree on Kubernetes.
</Step>

<Step title="Apply and restart">
```bash
kubectl apply -f 30-config.yaml
kubectl -n overleaf rollout restart deployment/overleaf     # or statefulset/overleaf
```
</Step>
</Steps>

### Several replicas

Nothing extra beyond having the image on every node: each replica converts on its own node.

### Tested on Kubernetes

With the image built from `develop/pandoc` and loaded into Docker on every node with `docker save | docker load`, on Kubernetes 1.37 with one replica, our end-to-end tests for Pandoc pass (6 cases): importing a Markdown document as a LaTeX project, the error shown for a broken Word document, exporting Word (which imports again), Markdown and HTML, and the menus hidden without `ENABLE_PANDOC_CONVERSIONS`.
