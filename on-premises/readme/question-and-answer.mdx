Here, we’ve compiled answers to some frequently asked questions about Ayakaleaf Pro.

### Basic Question

<Accordion title="Q01: Is Ayakaleaf Pro a free trial? Does it require a license?">

No. Ayakaleaf Pro is completely free to use. It is not a trial and requires no license.

</Accordion>

<Accordion title="Q02: Do you (ayakaleaf pro) include all Overleaf Server Pro features?">

Yes. Ayakaleaf Pro includes all Overleaf Server Pro features, including Git-Bridge integration. It also includes selected features from the Overleaf SaaS platform. We continue to develop and improve Ayakaleaf Pro.

</Accordion>

<Accordion title="Q03: How much does Overleaf Server Pro cost?">

Overleaf Server Pro costs around \$300 per user each year. It requires at least 10 licenses, so deployments start at roughly \$3,000 annually. Smaller public U.S. contracts show annual costs of about \$320–\$370 per user. This makes Server Pro expensive, especially for smaller teams. See [#information-and-price-about-overleaf-server-pro](/on-premises#information-and-price-about-overleaf-server-pro  "mention") for documented purchases and pricing.

</Accordion>

<Accordion title="Q04: Why does Overleaf Server Pro not include GitHub Sync or AI features?">

Overleaf Server Pro is commonly used by government organizations. They deploy it on private networks and strictly control access. To protect sensitive data, its included features avoid exchanging data with third-party services. If you need GitHub Sync, AI, or similar connected features, Overleaf recommends a subscription to its SaaS platform.

</Accordion>

<Accordion title="Q05: Is Ayakaleaf Pro secure and reliable?">

Ayakaleaf Pro is open source. We review the code with tools such as Codex Security to strengthen its security and reliability. If you do not enable third-party data synchronization, your data stays on your server. Ayakaleaf Pro contains no telemetry that sends your data elsewhere.

</Accordion>

<Accordion title="Q06: Will Ayakaleaf Pro be maintained long term?">

We will make every effort to maintain this project over the long term.

</Accordion>

<Accordion title="Q07: Is Ayakaleaf Pro compliant?">

Ayakaleaf Pro is a community fork. Its code and integrated features come from community contributions. It is licensed under AGPL v3. Deployments can comply with this license when they meet its requirements.

</Accordion>

<Accordion title="Q08: Why is the project called Ayakaleaf Pro?">

The project was originally named Overleaf Pro in 2024. Development paused for a time, then restarted in late 2025. In the first quarter of 2026, Overleaf renamed its AI-enabled subscription plan to Pro. Community feedback also noted that the Overleaf Pro name could create trademark and impersonation risks. It could make users think the project was official.

We renamed the project Ayakaleaf Pro to avoid that confusion. The name can be read as “Ayaka-notes Overleaf Pro.” The maintainer (you can call me ayaka!) has contributed to Overleaf community development since their student years, over five years ago. This experience supports our long-term maintenance commitment.

</Accordion>

<Accordion title="Q09: What distinguishes Ayakaleaf Pro from newer AI-built LaTeX editors?">

Since 2026, the open-source community has released many AI-built LaTeX editors, including OpenAI Prism. Ayakaleaf Pro keeps your data and services on your own server. This gives you direct control over your deployment and data.

Many experimental community editors have no established long-term maintenance plan. Third-party LaTeX compilation platforms can also stop operating when their user base or revenue is insufficient. Ayakaleaf Pro delivers all source code and lets you self-host every service. Even if maintenance stopped, your existing self-hosted service could continue to run.

</Accordion>

### Features

<Accordion title="Q01: What features does Ayakaleaf Pro offer? Can I request a new feature?">

Please check our documentation for the current feature list. If there’s a feature you’d like us to add, feel free to open a issue (for feature request) on GitHub. We’ll do our best to implement requested features, but development takes time, and we can’t guarantee that every feature will be delivered right away.

</Accordion>

<Accordion title="Q02: I’ve built some features. Can I submit a PR, and is it guaranteed to be accepted?">

Contributions are welcome, but acceptance is not guaranteed. We evaluate each PR based on its impact on the underlying Overleaf codebase, its maintenance burden, and the value it brings to users. We’ll do our best to merge and maintain valuable contributions.

However, we may reject PRs that introduce excessive changes, consist of unreviewed or poorly understood AI-generated code (“vibe coding”), or add features that would be difficult to maintain over time.

</Accordion>

<Accordion title="Q03: How do I configure a specific feature?">

We generally update the documentation whenever we release a new feature. Please refer to the relevant documentation for detailed setup instructions and explanations of the available environment variables.

</Accordion>

<Accordion title="Q04: Which Python libraries can the Python Runner use?">

The Python Runner runs Python in the user's browser with [Pyodide](https://pyodide.org/) 0.29.3, not on the server. It loads the packages that your code imports from the [packages built into Pyodide](https://pyodide.org/en/0.29.3/usage/packages-in-pyodide.html), such as NumPy, pandas and Matplotlib. Packages installed with `pip` and other packages are not available. There is nothing to configure on the server.

</Accordion>

<Accordion title="Q05: Can spell checking check Japanese or Chinese?">

No. The spell checker has no dictionary for Japanese or Chinese, so these languages are not in the spell-check language list. Users can turn off spell checking for a project in the editor settings.

</Accordion>

### Deployment

<Accordion title="Q01: Does Ayakaleaf Pro support distributed deployment in k8s?">

For most users, we recommend deploying with the [Toolkit](/on-premises/installation/using-the-toolkit). We do not recommend large-scale cluster deployments using Kubernetes or similar platforms, as they can significantly increase operational complexity and maintenance effort.

</Accordion>

<Accordion title="Q02: How can I ensure availability when serving thousands of users?">

Please refer to our [horizontal scaling](/on-premises/maintenance/horizontal-scaling) guide. You can deploy multiple Overleaf instances and configure a load balancer to distribute traffic across them.

</Accordion>

<Accordion title="Q03: Can you help me deploy or migrate?">

If you have an existing Overleaf Server Pro instance, we’d be happy to help you migrate to Ayakaleaf Pro. Please contact via email or issues.

</Accordion>

<Accordion title="Q04: Can I host Ayakaleaf Pro under a URL sub-path, like `https://example.com/overleaf`?">

No. Ayakaleaf Pro must be served from the root of a domain. Use a dedicated domain or subdomain, such as `https://overleaf.example.com`.

</Accordion>

<Accordion title="Q05: Can I run Ayakaleaf Pro on Windows or macOS, or without the Toolkit?">

We support Linux servers with the [Toolkit](/on-premises/installation/using-the-toolkit). Docker Desktop on Windows, WSL2 or macOS may work, but we do not test it, see [Troubleshooting](/on-premises/support/troubleshooting) for a known MongoDB problem.

We do not provide a standalone `docker-compose.yml`. To see the Compose configuration that the Toolkit uses, run `bin/docker-compose config` in the Toolkit directory.

</Accordion>

<Accordion title="Q06: How do I uninstall Ayakaleaf Pro?">

There is no uninstall script. In the Toolkit directory:

1. Stop and remove the containers with `bin/docker-compose down`.
2. Delete the data. By default it is in the `data/` directory of the Toolkit. If you changed `OVERLEAF_DATA_PATH`, `MONGO_DATA_PATH`, `REDIS_DATA_PATH` or `GIT_BRIDGE_DATA_PATH` in `config/overleaf.rc`, delete those directories too. This cannot be undone, so [back up](/on-premises/maintenance/data-and-backups) first if you may need the data.
3. Delete the Toolkit directory.
4. Remove the Docker images, which you can list with `docker images`: `ghcr.io/ayaka-notes/overleaf-pro`, the git-bridge image, `mongo`, `redis` and the TeX Live images.

</Accordion>

<Accordion title="Q07: How do I stop, start or restart Ayakaleaf Pro?">

Run these in the Toolkit directory:

* `bin/stop` stops all containers, `bin/start` starts them again. The containers are kept, so users stay logged in.
* `bin/up -d` creates the containers and starts them in the background. Run it after changing `config/variables.env`, `config/overleaf.rc` or `config/version`: it recreates the containers whose configuration changed, and only then do the changes take effect. `bin/stop` and `bin/start` do not apply them.
* `bin/docker-compose restart sharelatex` restarts only the Overleaf container, without applying configuration changes.

If users are logged out every time `bin/up` recreates the container, set `OVERLEAF_SESSION_SECRET`, see the Q\&A in [Environment Variables](/on-premises/configuration/overleaf-toolkit/environment-variables).

</Accordion>

<Accordion title="Q08: Where do I put the OAuth callback URL?">

In the application you create at the provider, not in Ayakaleaf Pro. There is no callback setting in `config/variables.env` for any of these integrations: Ayakaleaf Pro builds every callback URL from `OVERLEAF_SITE_URL` and sends it to the provider, which rejects it unless it matches the one registered for the application. So you only register it at the provider, and set `OVERLEAF_SITE_URL` to the address users open.

| Integration | Field at the provider | Value |
| --- | --- | --- |
| [GitHub](/on-premises/configuration/overleaf-toolkit/github-synchronisation) | Authorization callback URL | `${OVERLEAF_SITE_URL}/user/github-sync/oauth2/callback` |
| [GitLab](/on-premises/configuration/overleaf-toolkit/gitlab-synchronisation) | Redirect URI | `${OVERLEAF_SITE_URL}/user/gitlab-sync/oauth2/callback` |
| [Gitea](/on-premises/configuration/overleaf-toolkit/gitea-synchronisation) | Redirect URIs | `${OVERLEAF_SITE_URL}/user/gitea-sync/oauth2/callback` |
| [Dropbox](/on-premises/configuration/overleaf-toolkit/dropbox-synchronisation) | Redirect URIs (click **Add**) | `${OVERLEAF_SITE_URL}/user/dropbox/oauth/callback` |
| [Zotero](/on-premises/configuration/overleaf-toolkit/zotero-integration) | Callback URL | `${OVERLEAF_SITE_URL}/user/zotero/oauth/callback` |
| [Mendeley](/on-premises/configuration/overleaf-toolkit/mendeley-integration) | Redirect URL | `${OVERLEAF_SITE_URL}/user/mendeley/oauth/callback` |
| [OIDC login](/on-premises/configuration/overleaf-toolkit/authentication/oidc-authentication) | Redirect URI | `${OVERLEAF_SITE_URL}/oidc/login/callback` |
| [SAML login](/on-premises/configuration/overleaf-toolkit/authentication/saml-authentication) | ACS URL (Assertion Consumer Service) | `${OVERLEAF_SITE_URL}/saml/login/callback` |

If you change `OVERLEAF_SITE_URL`, for example to a new domain, update the URL at every provider too, or linking fails.

</Accordion>

### LaTeX

<Accordion title="Q01: Are users’ LaTeX project compilations isolated? Is Shell Escape enabled?">

When you enable Sandbox Compiles, each user’s compilation runs in a separate Docker container and is isolated from other users’ compilations. Shell Escape is enabled by default for Sandbox Compiles.

</Accordion>

<Accordion title="Q02: Is the Sandbox Compiles image reliable? Can compilation fail?">

We have improved our TeX Live Full image for Sandbox Compiles over the past three years. In most cases, projects that compile on overleaf.com also compile correctly with Ayakaleaf Pro. If a required font is unavailable, upload that font to your project manually.

</Accordion>

<Accordion title="Q03: My project won’t compile. Can you help me troubleshoot it?">

Please upload your project to the official Overleaf website, enable read-only link sharing, and include the link in a GitHub issue.

We will investigate and fix any bugs that prevent a project from compiling in Ayakaleaf Pro when it compiles successfully on the official Overleaf website. Compilation problems outside this scope are not covered by our support.

</Accordion>
