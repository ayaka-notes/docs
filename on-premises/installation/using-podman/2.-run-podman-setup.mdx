`bin/podman-setup` checks everything Ayakaleaf Pro needs on Podman. Without options it only reports; with `--apply` it also fixes what it finds.

<Steps>
<Step title="Check the host">
```bash title="Check only"
bin/podman-setup
```

On a fresh host most checks fail, for example:

```text
====== Packages ======
[✗] podman not installed
[✗] podman-docker not installed
...
====== Summary ======
[✓] 7 passed  [!] 13 warnings  [✗] 4 failures
```
</Step>

<Step title="Apply the fixes">
```bash title="Check and fix"
bin/podman-setup --apply
```

Run it in a terminal: it asks for your `sudo` password for the system-wide steps. It also downloads the Ayakaleaf Pro image to extract its seccomp profile, which takes a few minutes the first time. At the end it checks the host again:

```text
====== Summary ======
[✓] 23 passed  [!] 2 warnings  [✗] 0 failures
[!] Warnings remaining:
[!] not logged in to quay.io
[!] container → socket skipped (sharelatex not running)
```

Both warnings are expected at this point:

* `not logged in to quay.io`: the check comes from the official Toolkit, where the Server Pro image is on a private registry. Ayakaleaf Pro images are public on `ghcr.io` and need no login, so ignore it. It stays after the installation, too.
* `container → socket skipped (sharelatex not running)`: this test needs the running instance. You run the script again in [3. Start Ayakaleaf Pro](/on-premises/installation/using-podman/3.-start-ayakaleaf-pro).

The script exits with `0` when all checks pass, `1` when there are warnings and `2` when there are failures. Because of the quay.io warning, expect `1`.
</Step>
</Steps>

### What the script changes

With `--apply`, the script may change the following.

System-wide, with `sudo`:

* Installs `podman`, `podman-docker`, `git`, `curl`, `checkpolicy` and `policycoreutils` with `dnf`.
* Enables lingering for your user with `loginctl`, so that your containers keep running after you log out.
* Creates `/etc/containers/nodocker`, which silences the "Emulate Docker CLI using podman" message.
* Loads the SELinux policy module `podman_socket_clsi`, when `SELINUX_MODE=managed`.

For your user:

* Enables the user service `podman.socket`, the Docker-compatible API that Ayakaleaf Pro uses to start compiles.
* Installs Docker Compose v2 from GitHub to `~/.local/bin/docker-compose`, and links it in `~/.docker/cli-plugins/`.
* Makes Podman use this Compose in `~/.config/containers/containers.conf`.
* Adds the aliases `mongo` and `redis` in `~/.config/containers/registries.conf.d/overleaf-toolkit.conf`, so that Podman knows where to pull these short image names from.

In the Toolkit:

* Sets `DOCKER_SOCKET_PATH` and `DOCKER_HOST` in `config/overleaf.rc` to `/run/user/<uid>/podman/podman.sock`.
* Extracts the seccomp profile for compiles from the Ayakaleaf Pro image to `config/seccomp/<version>/clsi-profile.json`, and sets `SECCOMP_PROFILE` in `config/variables.env`. Unlike Docker, Podman needs this profile as a file on the host.
* Builds the SELinux policy module in `config/selinux/`.
* Sets the owners of the data directories in `data/` with `podman unshare chown`, once they exist.

<Info>

Each change matches a check. If you change something by hand, for example in `config/overleaf.rc`, run `bin/podman-setup` again to verify it.

</Info>
