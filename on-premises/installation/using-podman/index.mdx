RHEL and its rebuilds (Rocky Linux, AlmaLinux) ship Podman instead of Docker, and some organisations don't allow Docker on their servers. The Toolkit can run Ayakaleaf Pro on **rootless Podman** instead: the containers run under a normal user, compiles still run in sandboxed TeX Live containers, and SELinux stays enforcing. The script `bin/podman-setup` checks the host and fixes what it can.

By the end of this section you have the same instance as with [Using Docker Compose](/on-premises/installation/using-docker-compose): Ayakaleaf Pro with sandboxed compiles, MongoDB and Redis, managed with the usual `bin/up`, `bin/doctor` and `bin/upgrade`.

<Info>

Podman support is experimental. It comes from the official Overleaf Toolkit, which only tests it on RHEL 9 and later with rootless Podman, sandboxed compiles and SELinux enforcing. We tested these pages on Rocky Linux 9.9 (Podman 5.8, SELinux enforcing) with Ayakaleaf Pro 6.3.4. Docker remains the recommended container runtime.

</Info>

### What you need

* **RHEL, Rocky Linux, AlmaLinux or CentOS Stream 9 or later**, with SELinux enforcing. `bin/podman-setup` stops on any other distribution. On Ubuntu or Debian, use [Using Docker Compose](/on-premises/installation/using-docker-compose/linux).
* **A non-root user with `sudo`** that will own the containers. Run every command in this section as this user; `bin/podman-setup` refuses to run as `root`.
* **A clean host**: no Docker Engine and no existing Toolkit installation. Moving an existing Docker-based instance to Podman is not covered.

### How it differs from Docker

|                                  | Docker                               | Rootless Podman                                                                          |
| -------------------------------- | ------------------------------------ | ---------------------------------------------------------------------------------------- |
| Who runs the containers          | The Docker daemon, as `root`         | Your user                                                                                |
| Socket used to start compiles    | `/var/run/docker.sock`               | `/run/user/<uid>/podman/podman.sock`                                                     |
| Ports                            | Any, for example `80` and `443`      | `1024` and above, for example `8080`                                                     |
| Host firewall (`firewalld`)      | Bypassed by published ports          | Applies: open the port with `firewall-cmd`                                               |
| Start after a reboot             | The Docker daemon restarts them      | The user service `podman-restart`                                                        |
| SELinux                          | Not configured by the Toolkit        | Policy module `podman_socket_clsi` and `SELINUX_MODE=managed` in `config/overleaf.rc`     |
| Seccomp profile for compiles     | Built into the image                 | Extracted to `config/seccomp/<version>/` and set as `SECCOMP_PROFILE` by the Toolkit     |

### Known limitations

* <strong>Git integration.</strong> In Ayakaleaf Pro 6.3.4, `git clone` fails with `502` on Podman: the NGINX inside the image looks up the `git-bridge` container with Docker's DNS server (`127.0.0.11`), which Podman doesn't have. The fix ([1b911d1092](https://github.com/ayaka-notes/ayakaleaf-pro/commit/1b911d1092c80f7b0ff77c5e3805b40503d49964)) comes with the next release; until then, leave `GIT_BRIDGE_ENABLED=false`.
* <strong>Client IP addresses.</strong> Rootless Podman forwards the published port from inside the container's network, so Ayakaleaf Pro sees every visitor with an internal address such as `10.89.0.15`. A user's [audit logs](/on-premises/user-guide/administrators/user-management#audit-logs) in the admin panel show this address instead of their IP address.
