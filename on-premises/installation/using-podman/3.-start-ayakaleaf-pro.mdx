---
title: 3. Start Ayakaleaf Pro
description: Start Ayakaleaf Pro on Podman, verify it with podman-setup and bin/doctor, and start it after reboots.
icon: circle-play
---

<Steps>
<Step title="Start the containers">
```bash title="Start Ayakaleaf Pro"
bin/up -d
```

The first start downloads MongoDB, Redis and the TeX Live images, and creates the data directories in `data/`. It prints a warning that Podman support is experimental.

<Info>

The first start may also print `MongoNetworkError: connect ECONNREFUSED 127.0.0.1:27017`. The Toolkit sets up the MongoDB replica set while MongoDB is still starting, and tries again until it answers. You can ignore this line.

</Info>

After a minute or two, check that the containers run:

```bash title="List the containers"
podman ps --format "{{.Names}} {{.Status}}"
```

```text
mongo Up 34 seconds (healthy)
redis Up 20 seconds
sharelatex Up 20 seconds
```
</Step>

<Step title="Check the setup again">
Now that the data directories exist and the `sharelatex` container runs, `bin/podman-setup` can finish its checks:

```bash title="Check the setup"
bin/podman-setup
```

It checks the owners of the new data directories and tests the Podman socket from inside the `sharelatex` container:

```text
====== Socket Connectivity ======
[✓] host → socket OK
[✓] container → socket OK

====== Data Directory Permissions ======
[✓] mongo data dir owned by 999
[✓] redis data dir owned by 999
[✓] overleaf data dir owned by 33
...
====== Summary ======
[✓] 27 passed  [!] 1 warnings  [✗] 0 failures
[!] Warnings:
[!] not logged in to quay.io
```

`container → socket OK` means Ayakaleaf Pro can start compile containers. If a check fails, run `bin/podman-setup --apply`, then `bin/up -d`. The quay.io warning doesn't apply to Ayakaleaf Pro, see [2. Run podman-setup](/on-premises/installation/using-podman/2.-run-podman-setup).
</Step>

<Step title="Run the doctor">
```bash title="Run the doctor"
bin/doctor
```

On Podman, the report shows the runtime and the security settings:

```text
- Container Daemon
    - status: up
    - runtime: podman
    - server version: 5.8.5
    - socket: /run/user/1000/podman/podman.sock
    - DOCKER_HOST: unix:///run/user/1000/podman/podman.sock
    - host → socket: OK
    - container → socket: OK
- Security
    - SELinux: Enforcing
    - SELINUX_MODE: managed
    - SELINUX_LABEL: sharelatex_t
    - SELinux module: loaded (podman_socket_clsi)
    - SELinux rules: present
    - Seccomp profile: present
```

The warning `Server Pro enabled, but not logged in to quay.io repository` at the end is the same quay.io check, see [Getting help](/on-premises/support/getting-help#q-and-a).
</Step>

<Step title="Start Ayakaleaf Pro after a reboot">
With Docker, the Docker daemon starts the containers again after a reboot. Rootless Podman has no daemon: enable the user service that starts your containers when the server boots:

```bash title="Start the containers at boot"
systemctl --user enable podman-restart.service
```

It starts every container of your user whose restart policy is `always`, which the Toolkit sets for all its containers. This needs lingering, which `bin/podman-setup --apply` enabled. Without this service, run `bin/up -d` after each reboot.
</Step>

<Step title="Open the port in the firewall">
By default, the instance only accepts connections from the server itself, on `http://localhost:8080`. To open it from other computers, set `OVERLEAF_LISTEN_IP` in `config/overleaf.rc` and `OVERLEAF_SITE_URL` in `config/variables.env` as described in [5. Personalizing your instance](/on-premises/installation/using-docker-compose/linux/5.-personalizing-your-instance#listen-address-and-port), and run `bin/up -d` again.

Unlike Docker, rootless Podman doesn't bypass the host firewall. If `firewalld` runs, which is the default on RHEL, open the port:

```bash title="Open port 8080"
sudo firewall-cmd --permanent --add-port=8080/tcp
sudo firewall-cmd --reload
```

On a cloud server, also allow the port in the provider's security group. Use HTTPS before exposing the instance to the internet, see [4. Post-installation tasks](/on-premises/installation/using-podman/4.-post-installation-tasks#use-https).
</Step>
</Steps>
