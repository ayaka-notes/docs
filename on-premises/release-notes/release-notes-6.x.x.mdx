<Accordion title="Zotero / Mendeley migration for existing installations">

When upgrading to the re-released 6.3.0 image, migrate existing Zotero/Mendeley linked bibliography metadata using the script below. This migration accompanies fix `12031b8dfd`.

This renames `zoteroGroupId` / `mendeleyGroupId` to `group_id`, renames `importedByUserId` to `importer_id`, and removes `importedByName`.

Back up MongoDB and stop the application before running the migration. Keep MongoDB running. Open its shell (replace `mongo` with your container name):

```bash
docker exec -it mongo mongosh
```

Run the following in `mongosh` (replace `sharelatex` with your database name):

```javascript
use sharelatex

(async () => {
  let updated = 0
  await db.projects.find({}, { rootFolder: 1 }).forEach(async project => {
    const changes = {}
    function visit(folders, path) {
      for (const [i, folder] of (folders || []).entries()) {
        const folderPath = `${path}.${i}`
        for (const [j, file] of (folder.fileRefs || []).entries()) {
          const data = { ...file.linkedFileData }
          if (!["zotero", "mendeley"].includes(data.provider)) continue
          const groupKey = `${data.provider}GroupId`
          if (![groupKey, "importedByUserId", "importedByName"].some(key => key in data)) continue
          for (const [oldKey, newKey] of [[groupKey, "group_id"], ["importedByUserId", "importer_id"]]) {
            if (data[oldKey] != null && data[oldKey] !== "") {
              const value = String(data[oldKey])
              if (newKey in data && data[newKey] !== value) {
                throw new Error(`Conflicting ${newKey}: project ${project._id}, file ${file._id}`)
              }
              data[newKey] = value
            }
            delete data[oldKey]
          }
          delete data.importedByName
          changes[`${folderPath}.fileRefs.${j}.linkedFileData`] = data
        }
        visit(folder.folders, `${folderPath}.folders`)
      }
    }
    visit(project.rootFolder, "rootFolder")
    if (!Object.keys(changes).length) return
    const result = await db.projects.updateOne(
      { _id: project._id, rootFolder: { $eq: project.rootFolder } },
      { $set: changes }
    )
    if (!result.matchedCount) throw new Error(`Project changed during migration: ${project._id}`)
    updated += result.modifiedCount
  })
  print(`Updated ${updated} project(s).`)
})()
```

The script includes nested folders and only changes Zotero/Mendeley metadata. It is safe to rerun: a completed migration reports `Updated 0 project(s).` on the next run. If it stops with a conflict, inspect the reported project/file; earlier projects may already have been migrated.

Start the updated application, reload the editor, and refresh an existing bibliography file as its original importer. Historical snapshots are not rewritten. To downgrade to the old application, restore the MongoDB backup.

#### Feature 04: Template Pagination

The gallery now pages, sorts and searches in MongoDB. It works without any preparation; with thousands of templates, you can still add these indexes to keep it fast (safe to re-run, `mongo`/`sharelatex` = your container and database names):

```bash
docker exec mongo mongosh sharelatex --quiet --eval '
db.templates.createIndex({category:1,lastUpdated:-1},{name:"category_1_lastUpdated_-1",background:true});
db.templates.createIndex({lastUpdated:-1},{name:"lastUpdated_-1",background:true});
db.templates.createIndex({category:1,name:1},{name:"category_1_name_1_ci",collation:{locale:"en",strength:2},background:true});
db.templates.createIndex({name:1},{name:"name_1_ci",collation:{locale:"en",strength:2},background:true});
'
```

Keep the `collation` on the two `*_ci` indexes as written — the gallery queries with the same collation and MongoDB only uses a matching index.

## Ayakaleaf Pro 6.2.2

<strong>Release date:</strong> 2026.07.23

See: [https://github.com/ayaka-notes/ayakaleaf-pro/releases/tag/pro-v6.2.2](https://github.com/ayaka-notes/ayakaleaf-pro/releases/tag/pro-v6.2.2)

### Changes

Backport the official hotfix patches shipped in upstream Overleaf `6.2.2` (on top of `6.2.1`):

* Stop leaking the project invite token secret into the logs. The invite token encryptor logged its own configuration on every encrypt/decrypt, which included the cipher passwords derived from `OVERLEAF_INVITE_TOKEN_SECRET`.
* Migrate outgoing email from the end-of-life AWS SES v1 client to SESv2. Instances configured with the `ses` email driver could fail to send email at all; sending now goes through `SESv2Client`.
* Gate the group entries of the share-project dropdown behind the new `group-link-sharing` feature flag, so group link sharing is no longer offered on instances where it does not apply.
* Fix the share-project modal for collaborators. Opening it as a non-owner, or with the `sharing-updates` flow disabled, issued a request that always failed and surfaced a "something went wrong" error.
* Add `scripts/flush_docs_with_pending_updates.js` to document-updater, a maintenance script that recovers documents left with a stuck `PendingUpdates` queue in Redis after their project was flushed or hard deleted. Supports `--dry-run` and a `--estimated-docs` safety check.
* Update dependencies: `multer` 2.2.0, `form-data` 2.5.6, `protobufjs` 7.6.3, `@grpc/grpc-js` 1.14.4.

This release also includes the following fixes and improvements from Ayakaleaf Pro:

* Add full translations for 16 additional languages (cs, da, de, es, fi, fr, it, ja, ko, nl, no, pl, pt, ru, sv, tr), fixing untranslated strings such as the password reset page. Fixes [#38](https://github.com/ayaka-notes/ayakaleaf-pro/issues/38).
* Fix the item count in the admin panel "show N more projects" button, which showed the wrong number because the plural placeholder was not passed correctly.
* Fix GitHub export validation errors, which are now rendered through static i18n keys instead of raw messages, and drop the error keys that are no longer used by the GitHub Sync modal.

## Ayakaleaf Pro 6.2.1

<strong>Release date:</strong> 2026.07.18

See: [https://github.com/ayaka-notes/ayakaleaf-pro/releases/tag/pro-v6.2.1](https://github.com/ayaka-notes/ayakaleaf-pro/releases/tag/pro-v6.2.1)

### Changes

Backport the official hotfix patches shipped in upstream Overleaf `6.2.1` (on top of `6.2.0`):

* Harden the real-time `applyOtUpdate` message with a strict validation schema instead of accepting any object, rejecting malformed edit operations.
* Relax that schema to make `meta.tc` optional, so valid updates are no longer rejected by the stricter validation.
* Fix the editor (ShareJS client) so operations that reduce to an empty op — cancelled out by a remote/concurrent op, or fully reverted by undo — are dropped instead of being sent to the server, and the document is correctly reported as saved. Prevents spurious sync / "unsaved changes" issues around undo and concurrent editing.

We are proud to announce the release of Overleaf Pro 6.2.0, the most powerful and feature-rich online LaTeX editor in the community. Special thanks to yu-i-i and davrot for their valuable contributions. They enhanced GitHub Sync and introduced Advanced Citation Search, and Zotero integration.

### Notes

<Warning>

* A new required `OVERLEAF_INVITE_TOKEN_SECRET` environment variable has been introduced. You must generate it with `openssl rand -base64 32`. If it is not configured, your Overleaf instance will fail to start.
* If you enable GitHub Sync, you must configure the `GITHUB_TOKEN_CIPHER_PASSWORD` environment variable. This variable is required to securely encrypt GitHub access tokens. Without it, your Overleaf instance will fail to start.

</Warning>

* Added a new `DEFAULT_LATEX_COMPILER` environment variable to set the default compiler used by new projects (either `pdflatex`, `latex`, `xelatex` or `lualatex`).

Features include:
