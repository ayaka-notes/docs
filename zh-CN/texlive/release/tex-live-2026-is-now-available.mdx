</Info>

本文介绍了有哪些变化、切换前需要检查什么，以及如何修复最常见的新错误。此版本最值得关注的更新是：生成无障碍 PDF 的功能已经结束原型阶段，可以在生产工作流中使用。此次更新还为您带来了新增和更新的 TeX 相关程序、字体和宏包。这篇博文涵盖了您需要了解的所有关键信息和重要变化。

Overleaf 每年会在经过严格测试、确保一切按预期运行后发布一次官方更新。这样做是为了确保数百万 Overleaf 用户获得一致且稳定的体验，并确保我们的支持团队能够帮助您解决任何问题或疑问。

### 什么是 TeX Live？

[TeX Live](https://tug.org/texlive/) 是 TeX 排版系统的免费发行版，包含众多 TeX 相关程序、字体和宏包（包括 LaTeX），由一群核心 TeX 用户和 [TeX 用户组](https://tug.org/)维护。Overleaf 在其编译服务器上使用 TeX Live 来驱动预览并生成项目的 PDF。

随着 TeX Live 2026 的推出，用户将能够创建完全无障碍的带标签 PDF，包括可读的数学公式。

### 我现有的项目还能照常工作吗？

可以，您现有的项目仍将照常工作，因为它们会继续使用创建时的 TeX Live 版本。除非必要，我们不建议更改现有项目的 TeX Live 版本；更改可能会导致新的错误或警告。

**注意：** Overleaf 模板库中可能有一些模板在启用无障碍选项后无法正常工作或编译。大多数模板并非由 Overleaf 创建或维护；如有任何问题，请联系模板作者。

### 我可以将现有项目切换到 TeX Live 2026 吗？

可以，您可以轻松地将现有项目切换到 TeX Live 2026，过渡过程简单省心。在要更改的项目中，打开 _Settings_，然后点击侧边栏中的 _Compiler_，您会看到一个用于选择 TeX Live 版本的下拉菜单。这样您就可以快速更新项目，以满足出版商、预印本服务器及其他使用特定 TeX Live 版本编译投稿的平台的要求。

如果您的项目在 TeX Live 2025（或更早版本）中编译正常，但在 TeX Live 2026 中报错，这可能是由于内核或某些宏包发生了变化。已知部分宏包在 TeX Live 2026 下会产生新的错误或警告；我们在下文的单独章节中汇总了最常见的问题及其修复方法。

### TeX Live 2026 的主要变化

#### 带标签的无障碍 PDF 已结束原型阶段

自 LaTeX 项目的 [2025 年 11 月更新](https://www.latex-project.org/news/latex2e-news/ltnews42.pdf)起，标签功能不再被描述为原型，而是被认为可用于生产工作流，前提是您的文档只使用已支持标签功能的宏包和文档类。

只需在 `\documentclass` 之前放置一条命令即可启用带标签的 PDF 输出：

```latex
\DocumentMetadata{
 pdfstandard = {UA-2, A-4f},
 tagging = on,
 lang = en
 }
\documentclass{article}
```

使用 `\DocumentMetadata` 还会启用一些默认设置：T1 字体编码，以及[自 2025 年 6 月起](https://www.latex-project.org/news/latex2e-news/ltnews41.pdf)输出 **PDF 2.0** 而非较旧的 1.7。PDF 2.0 在这里很重要，因为它支持 MathML 标签（正是这一部分让屏幕阅读器能够读懂数学公式，而不是面对一堆无标注的符号）。

一些实用说明：

* 在起草阶段，您可以设置 `tagging = draft`，以保留无障碍警告但跳过写入结构树（有助于加快长文档的编译速度）。
* check-tagging-status 键会在日志末尾报告您所使用的宏包是否已知与标签功能兼容。此外还有一个[实时状态数据库](https://latex3.github.io/tagging-project/tagging-status/)，您可以在开始之前查阅。
* 如果您只需要 PDF 管理功能而不需要标签代码，现在可以使用单独的 `pdfmanagement` 宏包。

有一项变化特别值得注意：`\DocumentMetadata` 现在在一个文档中只能调用一次。第二次调用会导致编译错误，就像第二次调用 `\documentclass` 一样。

#### 有语义的无障碍数学公式

[自 2025 年 11 月起新增](https://www.latex-project.org/news/latex2e-news/ltnews42.pdf)的 `\MathMLintent` 和 `\MathMLarg` 让作者可以告诉辅助技术某个记号的含义，而不仅仅是它的构成方式。例如，`|y|` 现在可以被朗读为 _“y 的绝对值”_，而不是 _“竖线 y 竖线”_。

无障碍数学标签需要使用 LuaLaTeX 编译（因为它是生成 MathML 的引擎），并且需要 `unicode-math` 或 `lua-unicode-math` 宏包。

#### 图形和插图现在也能携带语义

无障碍功能不仅限于文本和数学公式。`\includegraphics`、`picture` 和 `tikzpicture` 现在都接受无障碍键，因此可以为每个图形添加适当的标注：

```latex
\includegraphics[alt={A bar chart of quarterly revenue}]{revenue}
```

图形可以分为四类：真正的说明性插图、可被辅助工具忽略的装饰性元素、符号的替代品，或普通文本（适用于 `todonotes` 之类的场景）。TikZ 输出开箱即用地受到支持。

#### 用于创建带标签无障碍演示文稿的新文档类

`beamer` 文档类在 LaTeX 中制作演示幻灯片非常流行。遗憾的是，它与 LaTeX 标签代码不兼容。为此，一个全新的文档类 [`ltx-talk`](https://ctan.org/pkg/ltx-talk) 被从零开始创建。它的语法与 `beamer` 大体相似，但并非 `beamer` 的所有功能都已在 `ltx-talk` 中实现。

#### 用于设置章节标题样式的新模板机制

章节标题命令已在 LaTeX 内核中使用新的模板机制重新实现，解决了 `titlesec` 等宏包与 LaTeX 标签代码不完全兼容的问题。下面是一个简单示例：

```latex
\EditInstance{heading}{section}{
  number-format=\fbox{\LARGE\bfseries\theheading},
  title-decls=\Large\bfseries\sffamily\color{blue},
  before-vspace=20pt,
}
```

详细信息请参阅[文档](https://tug.ctan.org/macros/latex-dev/required/latex-lab/latex-lab-sec-template.pdf)。

#### 底层重构的内核

今年的内核移除了一些限制：

* **输出例程现在可配置：** 近 40 年来，LaTeX 的页面组装机制实际上是硬编码的，需要修改它的宏包不得不覆盖内部代码。现在它提供了钩子（hooks）和插槽（sockets）来进行修改。宏包因此更加稳定，也更不容易相互冲突。
* **现代化的标记机制：** 旧的 `\markboth` / `\leftmark` / `\rightmark` 系统只支持两个相互交织的标记，现在已基于一个灵活的系统重建，支持任意数量的独立标记，而大家熟悉的命令仍与以前完全一样地工作。
* **块环境和章节标题现在基于模板运行：** 列表、引用、类定理环境以及现在的标题命令共享一套一致的底层系统。一个实际的好处是：LaTeX 开始原生模拟 `enumitem` 和 `amsthm` 的 `\newtheoremstyle` 等流行宏包，对 `titlesec` 的模拟也正在进行中。现在，仅仅为了重新设置列表或定理框的样式而安装宏包的需求减少了。
* **更好的类定理环境交叉引用：** 新的 `\newcounteralias` 命令意味着，与定理共享计数器的引理在使用 `cleveref`、`zref-clever` 或 `hyperref` 引用时，会正确显示为 _“lemma 1”_，而不是 _“theorem 1”_。

如果您维护的是宏包而不仅仅是文档，有两项变化值得关注：内核现在正式要求 **`expl3` 日期为 2023-11-27 或更新**；并且 _“伪数学模式”_（仅为定位盒子而使用数学模式）已从 `\textsuperscript`、`\parbox`/`minipage` 等结构以及表格结构周围移除。这改进了标签功能和从右到左文本的支持，但如果您将 `\showoutput` 的结果与旧版 TeX Live 进行比较，就会注意到这一点。

#### 新的覆盖范围：更多语言

* **婆罗米系文字的索引**（包括孟加拉文、古吉拉特文、卡纳达文、马拉雅拉姆文、僧伽罗文、泰米尔文和泰卢固文）已在 `upmendex` 中以实验形式提供。
* 新的 **BCP 47 语言元数据**键（`language`、`other-languages`）让您可以精确声明文档的语言（精确到地区变体），这些信息也会写入 PDF 自身的语言元数据中。

#### 其他需要注意的事项

* `enumerate`、`theorem` 和 `verbatim` 宏包现在被视为旧版宏包；对于新文档，请分别优先使用 `enumitem`、`amsthm` 和 `fancyvrb`。
* 如果您所使用的印刷工作流或平台要求较旧的 PDF 版本，您仍然可以自行设置 PDF 版本（例如 `\DocumentMetadata{pdfversion=1.7}`），TeX Live 2026 文档中也介绍了如何针对较早的默认设置编译文档。
* 您可以在 TeX 用户组（TUG）网站上找到 TeX Live 2026 的[官方发行说明](https://tug.org/texlive/doc/texlive-en/texlive-en.html#news)，以及[所有 TeX Live 版本的发行说明](https://www.tug.org/texlive/doc/texlive-en/texlive-en.html#x1-710009)。

### 受 TeX Live 2026 影响的常见宏包

在以下章节中，我们重点介绍一些会导致项目在 TeX Live 2025 中编译成功、但在 TeX Live 2026 中出现编译错误的变化。

#### 不再受支持的表格相关宏包

由于 LaTeX 内核对表格结构做了新的修改，`tabu` 和 `tabls` 宏包在 TL2026 中不再受支持——它们现在会导致编译错误。`arydshln` 宏包也可能与其他宏包不兼容，例如 `tabularx` 和 `tabular*` 环境。同样，重新定义 `\@array` 和 `\tabular` 的宏包或模板也会在类表格结构附近导致编译错误。

#### `babel` 已废弃的语言选项

`frenchb` 和 `francais` 语言选项现已废弃，应替换为 `french`。

#### `varioref` 缺陷

由于 [`varioref` 宏包中的一个缺陷](https://github.com/latex3/latex2e/issues/2112#issuecomment-4881772493)，在 KOMA-Script 文档类中加载它会导致 TeX capacity exceeded 错误，并且不会生成 PDF。

```text
\documentclass{scrartcl}
\usepackage{varioref}
\begin{document}
Hello World!
\end{document}
```

解决方法是在导言区添加

```text
\def\extrasenglish{}
```

即可。

#### KOMA-script 文档类与 `capt-of`

KOMA-script 文档类（`scrbook`、`scrartcl`、`scrreport`、`scrletter`）现在自行定义了 `\captionof`，因此不应再加载 `capt-of` 宏包。（另一方面，`caption` 宏包仍可安全地与这些文档类一起加载。）

#### `thmtools`：`sibling`/`numberlike`/`sharenumber` 错误

使用 `thmtools` 的 `sibling`（或 `numberlike`、`sharenumber`）选项声明新的类定理环境时，会出现[计数器已被定义的错误](https://github.com/muzimuzhi/thmtools/issues/75)，例如 `Command \c@proposal already defined`。

```text
\documentclass{article}
\usepackage{thmtools}
\declaretheorem{theorem}
\declaretheorem{proposal}[sibling=theorem]

\begin{document}

\begin{theorem}This is a theorem.\end{theorem}
\begin{proposal}This is a proposal.\end{proposal}

\end{document}
```

解决方法是在导言区中、加载 `thmtools` 之后且在 `\declaretheorem` 之前添加以下几行：

```text
\makeatletter
\@ifundefined{newcounteralias}{}{%
  \renewcommand\thmt@autorefsetup{\@xa\def\csname\thmt@envname autorefname\@xa\endcsname\@xa{\thmt@thmname}}%
}
\makeatother
```

#### `polyglossia`、`xepersian` 与 `array`

如果您使用 `polyglossia` 或 `xepersian` 宏包排版阿拉伯文字，并且加载了 `array` 宏包或其他会加载 `array` 的表格相关宏包，那么当阿拉伯文本位于类表格结构中时，会出现 `\UseMathForPositioningText` 未定义的错误。

```text
\documentclass[12pt,a4paper]{article}
\usepackage{polyglossia}
\usepackage{array}
\setdefaultlanguage{arabic}
\newfontfamily\arabicfont[Script=Arabic]{Noto Naskh Arabic}
\begin{document}
\begin{tabular}{c}
السلام عليكم
\end{tabular}
\end{document}
```

可以通过在 `\documentclass` 声明之前添加 `\DocumentMetadata{}` 来解决；也可以考虑改用 `babel` 宏包排版阿拉伯文字。

#### `babel-spanish` 与 `biblatex-apa`

在使用 `biblatex` 的 `apa` 样式时加载 `babel-spanish`，会导致与钩子和 `\@makecaption` 相关的编译错误：

```text
\usepackage[spanish]{babel}
\usepackage[style=apa]{biblatex}
```

但可以通过为 `babel` 添加 `shorthands=off` 选项来避免该错误。

#### `xgreek`、`hyperref` 与 `\appendix`

当加载了 `xgreek`（仅适用于 XeLaTeX 和 LuaLaTeX）和 `hyperref` 宏包时，出现在 `\appendix` 之后的章节标题会引发编译错误：

```text
\documentclass{article}
\usepackage{xgreek}
\usepackage{fontspec}
\setmainfont{GFS Artemisia}
\usepackage{hyperref}
\begin{document}
\section{Εισαγωγή}
\appendix
\section{Δεδομένα}
\end{document}
```

修复方法是为 `hyperref` 添加 `hypertexnames=false` 选项。

#### `flowfram` 与 `titlesec`

目前 `flowfram` 和 `titlesec` 宏包互不兼容。不过，作者可以考虑使用新的 `\EditInstance` 接口来设置章节标题样式，例如：

```text
\DocumentMetadata{}
\documentclass{article}
\usepackage{flowfram}
\usepackage[dvipsnames]{xcolor}
\EditInstance{heading}{section}{
  number-format=\fbox{\LARGE\bfseries\theheading},
  title-decls=\Large\bfseries\sffamily\color{NavyBlue}
}
\begin{document}
\section{Introduction}
\end{document}
```

更多详情请参阅[此链接](https://mirrors.ctan.org/macros/latex-dev/required/latex-lab/latex-lab-sec-template.pdf)。

### Ayakaleaf Pro 中的 TeX Live 2026

Ayakaleaf Pro 管理员可以按照常规方式更新配置来安装 TeX Live 2026：将 `TEX_LIVE_DOCKER_IMAGE`（以及 `ALL_TEX_LIVE_DOCKER_IMAGES`）指向新的 TeX Live 2026 镜像即可，无需其他升级操作。
