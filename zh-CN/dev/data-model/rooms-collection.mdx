`rooms` 中项目的每个聊天房间对应一个文档：项目聊天，或一个审阅评论线程。只有 chat 服务写入它，位置在 `services/chat/app/js/Features/Threads/ThreadManager.js`。没有 Mongoose schema。房间的消息保存在 [messages](/zh-CN/dev/data-model/messages-collection) 集合中。

#### 字段 {#fields}

| 字段 | 类型 | 含义 | 来源 |
| ----- | ---- | ------- | ------ |
| `_id` | ObjectId | 房间 ID。`messages.room_id` 指向这里。 | `ThreadManager.js:57-61` |
| `project_id` | ObjectId | 房间所属的项目。 | `ThreadManager.js:43-54` |
| `thread_id` | ObjectId | 仅存在于评论线程上：评论的 ID，与 `docs.ranges.comments` 中该评论的 `id` 和 `op.t` 相同（参见 [docs](/zh-CN/dev/data-model/docs-collection)）。项目聊天房间没有此字段。 | `ThreadManager.js:38-55`, `services/docstore/app/js/RangeManager.js:54-57` |
| `resolved` | Object | 线程被解决时设置，重新打开时移除。没有此字段的线程处于打开状态。 | `ThreadManager.js:94-123` |
| `resolved.user_id` | String | 解决该线程的用户 ID。以字符串而非 ObjectId 存储：请求体只校验其为有效 ID，不做转换。 | `ThreadManager.js:103`, `services/chat/app/js/Features/Messages/MessageHttpSchemas.js:70` |
| `resolved.ts` | Date | 线程被解决的时间。 | `ThreadManager.js:104` |

#### 说明 {#notes}

* 一个项目最多只有一个没有 `thread_id` 的房间，即项目聊天。chat 服务用 `thread_id: { $exists: false }` 查找它（`ThreadManager.js:38-45`）。
* 评论的已解决状态只保存在这里。Docstore 在保存范围之前会去掉 `op.resolved`（`services/docstore/app/js/RangeManager.js:59-61`）。
* 复制项目后，同一个 `thread_id` 会存在于两个项目中。请始终同时按 `project_id` 和 `thread_id` 查询，就像 chat 服务那样。
* 已删除项目的房间会一直保留，直到已删除项目过期。
