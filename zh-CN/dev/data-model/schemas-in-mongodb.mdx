在本节中，我们将讨论 Overleaf 的数据模型。Overleaf 使用 MongoDB 进行数据持久化，唯一的数据库名为 `sharelatex`，这也是 Overleaf 前身的名字。

开发环境已经在 Mongo 旁边运行了 Mongo Express（参见 [setup-develop-tools.md](/zh-CN/dev/environment/setup-develop-tools  "mention")）。打开 [http://localhost:8081/](http://localhost:8081/)，并使用 `admin:pass` 登录。

你也可以在 `develop` 目录中打开 Mongo 容器里的 shell：

```bash
bin/docker-compose exec mongo mongosh sharelatex
```

#### 这些页面的写法 {#how-the-pages-are-written}

* 每个页面列出代码写入的字段，以及字段类型、含义和能说明它的代码行：Mongoose schema 中的一行，或写入该字段的位置。只有迁移、脚本或某个 web 模块写入的字段会特别注明。
* 很多集合没有 Mongoose schema：服务直接使用 MongoDB 驱动写入它们。
* 索引只由 `tools/migrations/` 中的迁移创建。CE 每次启动时运行标记为 `server-ce` 的迁移（`server-ce/init_scripts/900_run_web_migrations.sh`）；Mongoose 的 `autoIndex` 已关闭（`services/web/app/src/infrastructure/Mongoose.mjs:7`）。索引表只列出 CE 实例最终拥有的索引。
* doc 的文本在 Mongo 中，但其他内容不在。文件内容以 blob 的形式、历史以 chunk 的形式存储在 history-v1 的 bucket 中（本地文件夹，或 S3 / RustFS）；打开的 doc 在 document-updater 刷写之前保存在 Redis 中。

CE 数据库中的集合比这些更多。很多集合由各自的索引迁移创建为空集合，只在 overleaf.com 上使用。例如，在正常使用中，CE 和我们的模块都不会写入 `splittests`、`samlLogs`、`notificationsPreferences`、`onboardingDataCollection` 或 `userfeatureusages`，因此它们没有对应页面。
