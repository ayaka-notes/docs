title: Project History Chunks 集合
icon: layer-group
---

`projectHistoryChunks` 中每个历史 chunk 一个文档，chunk 是一个项目历史中的一段连续版本。Mongo 只保存 chunk 的元数据；chunk 本身（一个快照加上其后的更改）是 chunks bucket 中经 gzip 压缩的 JSON 对象。没有 Mongoose schema：history-v1 在 `services/history-v1/storage/lib/chunk_store/mongo.js` 中写入该集合，它用于所有 24 个十六进制字符的历史 id，CE 中正是如此（`services/history-v1/storage/lib/chunk_store/index.js:644-652`）。

#### 字段 {#fields}

| 字段 | 类型 | 含义 | 来源 |
| ----- | ---- | ------- | ------ |
| `_id` | ObjectId | Chunk id。它也是 bucket 中 chunk 对象的名称（参见说明）。 | `mongo.js:183-185` |
| `projectId` | ObjectId | 项目的历史 id，即 `projects.overleaf.history.id` 中的值。在 CE 中，web 用项目自身的 `_id` 创建历史（`services/web/app/src/Features/History/HistoryManager.mjs:51-55`）。 | `mongo.js:186` |
| `startVersion` | Number | chunk 中第一个更改之前的项目版本。 | `mongo.js:187` |
| `endVersion` | Number | chunk 中最后一个更改之后的项目版本。 | `mongo.js:188` |
| `endTimestamp` | Date | chunk 中最后一个更改的时间；chunk 没有更改时为 `null`，例如新项目的第一个 chunk（`libraries/overleaf-editor-core/lib/chunk.js:146-149`）。 | `mongo.js:189` |
| `state` | String | `pending`、`active`、`closed` 或 `deleted`，参见说明。 | `mongo.js:190`, `343`, `378`, `409` |
| `updatedAt` | Date | 在插入、激活和删除时设置。关闭 chunk 不会改变它。 | `mongo.js:191`, `343`, `409`, `434`, `450` |

#### 说明 {#notes}

* 状态流转：`pending`（记录已写入，正在上传）→ `active`（最新的 chunk，仍可扩展）→ `closed`（后面有更新的 chunk）或 `deleted`（被取代，或项目已删除）。读取只看 `active` 和 `closed`。
* chunk 对象是经 gzip 压缩的 JSON（`services/history-v1/storage/lib/history_store.js:151-170`），位于键 `<project key>/<chunk id>`（`history_store.js:65-67`）。项目键是用零填充的历史 id，反转后按 3/3/其余字符切分（`libraries/object-persistor/src/ProjectKey.js:8-15`）。bucket 是 `OVERLEAF_EDITOR_CHUNKS_BUCKET`（`services/history-v1/config/custom-environment-variables.json:53-56`）：开发环境中为 `/buckets/chunks`（`develop/docker-compose.yml:90`），使用 `S3_ENABLED=true` 时为 `overleaf-chunks`（`develop/s3/docker-compose.yml:51`）。
* 处于 `deleted` 或 `pending` 状态的记录及其 bucket 对象只会被 `delete_old_chunks.js` 移除（`yarn delete_old_chunks`，`services/history-v1/package.json:79`）。CE 镜像没有为此设置 cron 任务（`server-ce/config/crontab-history`, `server-ce/config/crontab-deletion`），因此在 CE 中它们会一直保留。
* 当 web 让已删除项目过期时，会调用 history-v1 的 `DELETE /projects/:history_id`（`services/web/app/src/Features/Project/ProjectDeleter.mjs:385-391`, `HistoryManager.mjs:127-135`, `152-162`），从而把该项目的所有 chunk 标记为 `deleted`。
* 配置了 `backupStore` 时，确认 chunk 还会把 `overleaf.history.currentEndVersion`、`currentEndTimestamp`、`updatedAt` 和 `overleaf.backup.pendingChangeAt` 写入项目（`mongo.js:232-262`）。CE 没有配置 `backupStore`，所以 `mongo.js:238-240` 会提前返回。
