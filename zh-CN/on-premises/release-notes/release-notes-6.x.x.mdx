## Ayakaleaf Pro 6.3.2

<strong>发布日期：</strong> 2026.10.23

参见：[https://github.com/ayaka-notes/ayakaleaf-pro/releases/tag/pro-v6.3.2](https://github.com/ayaka-notes/ayakaleaf-pro/releases/tag/pro-v6.3.2)

我们非常自豪地宣布 Overleaf Pro 6.3.2 正式发布。上游 Overleaf 6.3.2 是一个更新 Node.js 的安全版本，我们将它与 Gitea 同步以及自 6.3.1 以来发现的问题修复一同发布。

<Info>

Gitea 同步在 6.3.2 中作为**早期预览版**发布，用于灰度测试，并将在 v6.4.0 中正式发布。在此之前，它的配置和行为仍可能发生变化。它默认处于关闭状态。如有任何问题，请在 [GitHub](https://github.com/ayaka-notes/ayakaleaf-pro/issues) 上反馈。

</Info>

### 变更

* 双向 Gitea 同步（早期预览版），支持 gitea.com 和 1.23+ 的自托管 Gitea。
* Node.js 24.22.1，即上游 Overleaf 6.3.2 中的安全更新。
* 由我们的 E2E 测试系统和内部 Horizon 问题排查（Internal Horizon Issue Investigation）发现的问题修复。

#### 功能 01：Gitea 同步（预览版）

与 Gitea 进行双向同步，工作方式与 GitHub 同步和 GitLab 同步相同：关联你的账户，从新建项目菜单中导入仓库，导出项目，推送和拉取，并通过拉取请求进行合并。Overleaf 从不绕过仓库的分支保护。参见 [Gitea 同步](/zh-CN/on-premises/configuration/overleaf-toolkit/gitea-synchronisation)。

### 问题修复

* GitHub、GitLab 和 Gitea 同步：当在仓库中删除的文件无法在 Overleaf 中删除时，同步会失败并可以重试，而不是报告成功并将该文件遗留在项目中。删除文件的 `git push` 也会以同样的方式失败（[#121](https://github.com/ayaka-notes/ayakaleaf-pro/issues/121)）。
* Git bridge：在编辑器中创建的、带有非文本扩展名（例如 `.csv`）的文档，在被 `git push` 修改后仍保持为可编辑文档。
* 修订追踪：通过链接共享的项目中未登录的编辑者可以删除评论线程，但不能再解决或重新打开它们。审阅者可以删除自己的回复。
* 模板库：发布模板需要拥有该项目的访问权限。
* Learn：当无法访问 wiki 时，已缓存的帮助页面仍然可用。

### 升级

* 从 6.3.1 或 6.3.0 升级：无需迁移。拉取新镜像并重启即可。
* 从 6.2.x 或更早版本升级且正在使用 Zotero 或 Mendeley：请先运行 [6.3.0](#ayakaleaf-pro-6.3.0) 中的 Zotero / Mendeley 迁移。
* Gitea 同步默认关闭，只需要新的环境变量。

## Ayakaleaf Pro 6.3.1

<strong>发布日期：</strong> 2026.10.18

参见：[https://github.com/ayaka-notes/ayakaleaf-pro/releases/tag/pro-v6.3.1](https://github.com/ayaka-notes/ayakaleaf-pro/releases/tag/pro-v6.3.1)

我们非常自豪地宣布 Overleaf Pro 6.3.1 正式发布。典型的补丁版本通常只针对 v6.3.0 做一些小修复，而这一版走得更远：除了大量问题修复之外，它还引入了五项新功能。

<Info>

Dropbox 同步和 GitLab 同步在 6.3.1 中作为**早期预览版**发布，用于灰度测试，并将在 v6.4.0 中正式发布。在此之前，它们的配置和行为仍可能发生变化。两者默认均为关闭状态。如有任何问题，请在 [GitHub](https://github.com/ayaka-notes/ayakaleaf-pro/issues) 上反馈。

### 变更

* 双向 Dropbox 同步（早期预览版）。
* 双向 GitLab 同步（早期预览版），包括 15.10+ 的自托管 GitLab。
* 每个项目独立的 MCP 服务器，供 Claude Code、Codex、Cursor、VS Code 和 Gemini CLI 等 AI 客户端使用。
* GitHub 同步支持 GitHub Enterprise。
* 符号面板中的手写符号识别，完全在浏览器中运行。
* 新增 `OVERLEAF_DISABLE_LOCAL_LOGIN`，用于在启用 SSO 的实例上隐藏邮箱和密码登录。
* 由我们的 E2E 测试系统和内部 Horizon 问题排查（Internal Horizon Issue Investigation）发现的问题修复。
* 上游 Overleaf 6.3.1 补丁。

#### 功能 01：Dropbox 同步（预览版）

每个用户关联自己的 Dropbox 账户后，其拥有的项目和共享给他的项目都会出现在 `Apps/<DROPBOX_APP_NAME>/` 下。在 Overleaf 中的编辑会推送到 Dropbox，在 Dropbox 中的编辑会通过签名的 webhook 同步回来。必须启用 Git bridge。参见 [Dropbox 同步](/zh-CN/on-premises/configuration/overleaf-toolkit/dropbox-synchronisation)。

#### 功能 02：GitLab 同步（预览版）

与 GitLab 进行双向同步，工作方式与 GitHub 同步相同：关联你的账户，从新建项目菜单中导入仓库，导出项目，推送和拉取，并通过合并请求进行合并。参见 [GitLab 同步](/zh-CN/on-premises/configuration/overleaf-toolkit/gitlab-synchronisation)。

### 问题修复

* 身份验证：在启用 SSO 的实例上，本地账户可以设置和更改密码，OIDC 用户不再能更改自己的邮箱（[#112](https://github.com/ayaka-notes/ayakaleaf-pro/pull/112)）。LDAP、SAML 和 OIDC 登录方式得以保留，SAML/OIDC 注销也恢复正常。参见[账户和密码](/zh-CN/on-premises/configuration/overleaf-toolkit/authentication#accounts-and-passwords)。
* LDAP、SAML 和 OIDC：具有多个值的名称属性（例如 `cn`）不再导致登录失败，并且 OIDC 邮箱会像 LDAP 和 SAML 一样转换为小写，因此 IdP 以不同大小写发送邮箱的账户可以正常关联，而不会失败。
* 被暂停的用户：暂停用户会结束其会话并关闭其打开的编辑器。其 Git 令牌和 MCP 下载会被拒绝。
* GitHub 同步：只有所有者才能导出项目，拉取期间所做的编辑会保持待处理状态，空文件会被同步，手动合并会在 GitHub 上进行验证，重新关联时会吊销被替换的令牌。
* Zotero / Mendeley：凭据失效时显示重新关联提示，并在导入后重新索引参考文献。
* 外部 API 请求（Zotero、Mendeley、GitHub、GitLab、网页搜索）的连接超时从 1 秒改为 3 秒（[#106](https://github.com/ayaka-notes/ayakaleaf-pro/pull/106)）。
* 修订追踪：审阅数据包含未加载的文档和未保存的更改（来自 [yu-i-i/overleaf-cep#262](https://github.com/yu-i-i/overleaf-cep/pull/262)）。
* 错误助手：仅为项目中的文档提供修复建议（[#103](https://github.com/ayaka-notes/ayakaleaf-pro/pull/103)）。
* 管理面板：恢复已删除的项目、更改所有者和编辑用户都能正常工作。搜索使用字面文本，邮件发送失败也不再影响账户的创建或删除。
* 模板库：无效的排序会返回 400 而不是 500，模板 ID 会经过验证，发布没有主文件的项目时会要求指定主文件。
* Git bridge：nginx 将 `/git/` 代理到 `GIT_BRIDGE_HOST` 和 `GIT_BRIDGE_PORT`，并隐藏内部路由。
* 沙盒编译：最近编译过的项目的容器会被保留以供复用。

<Accordion title="现有安装的 Zotero / Mendeley 迁移">

升级到重新发布的 6.3.0 镜像时，请使用以下脚本迁移现有的 Zotero/Mendeley 关联参考文献元数据。此迁移与修复 `12031b8dfd` 配套。

它会将 `zoteroGroupId` / `mendeleyGroupId` 重命名为 `group_id`，将 `importedByUserId` 重命名为 `importer_id`，并删除 `importedByName`。

运行迁移前，请备份 MongoDB 并停止应用程序。保持 MongoDB 运行。打开其 shell（将 `mongo` 替换为你的容器名称）：

```bash
docker exec -it mongo mongosh
```

在 `mongosh` 中运行以下内容（将 `sharelatex` 替换为你的数据库名称）：

```javascript
use sharelatex

(async () => {
  let updated = 0
  await db.projects.find({}, { rootFolder: 1 }).forEach(async project => {
    const changes = {}
    function visit(folders, path) {
      for (const [i, folder] of (folders || []).entries()) {
        const folderPath = `${path}.${i}`
        for (const [j, file] of (folder.fileRefs || []).entries()) {
          const data = { ...file.linkedFileData }
          if (!["zotero", "mendeley"].includes(data.provider)) continue
          const groupKey = `${data.provider}GroupId`
          if (![groupKey, "importedByUserId", "importedByName"].some(key => key in data)) continue
          for (const [oldKey, newKey] of [[groupKey, "group_id"], ["importedByUserId", "importer_id"]]) {
            if (data[oldKey] != null && data[oldKey] !== "") {
              const value = String(data[oldKey])
              if (newKey in data && data[newKey] !== value) {
                throw new Error(`Conflicting ${newKey}: project ${project._id}, file ${file._id}`)
              }
              data[newKey] = value
            }
            delete data[oldKey]
          }
          delete data.importedByName
          changes[`${folderPath}.fileRefs.${j}.linkedFileData`] = data
        }
        visit(folder.folders, `${folderPath}.folders`)
      }
    }
    visit(project.rootFolder, "rootFolder")
    if (!Object.keys(changes).length) return
    const result = await db.projects.updateOne(
      { _id: project._id, rootFolder: { $eq: project.rootFolder } },
      { $set: changes }
    )
    if (!result.matchedCount) throw new Error(`Project changed during migration: ${project._id}`)
    updated += result.modifiedCount
  })
  print(`Updated ${updated} project(s).`)
})()
```

该脚本会处理嵌套文件夹，并且只修改 Zotero/Mendeley 元数据。它可以安全地重复运行：迁移完成后，再次运行会报告 `Updated 0 project(s).`。如果因冲突而停止，请检查报告的项目/文件；之前的项目可能已经迁移完成。

启动更新后的应用程序，重新加载编辑器，并以原导入者的身份刷新现有的参考文献文件。历史快照不会被重写。如需降级到旧版应用程序，请恢复 MongoDB 备份。

#### 功能 04：模板分页

模板库现在在 MongoDB 中进行分页、排序和搜索。它无需任何准备即可使用；如果有数千个模板，你仍然可以添加以下索引来保持其快速运行（可安全重复运行，`mongo`/`sharelatex` = 你的容器名和数据库名）：

```bash
docker exec mongo mongosh sharelatex --quiet --eval '
db.templates.createIndex({category:1,lastUpdated:-1},{name:"category_1_lastUpdated_-1",background:true});
db.templates.createIndex({lastUpdated:-1},{name:"lastUpdated_-1",background:true});
db.templates.createIndex({category:1,name:1},{name:"category_1_name_1_ci",collation:{locale:"en",strength:2},background:true});
db.templates.createIndex({name:1},{name:"name_1_ci",collation:{locale:"en",strength:2},background:true});
'
```

请保持两个 `*_ci` 索引上的 `collation` 与上面写的一致——模板库使用相同的 collation 进行查询，而 MongoDB 只会使用匹配的索引。
