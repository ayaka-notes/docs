<Danger>

在每次主版本升级**之前**，务必进行一次[一致性备份](/zh-CN/on-premises/maintenance/data-and-backups#performing-a-consistent-backup)，以便在需要时能够回滚。

</Danger>

[ayakaleaf toolkit↗](https://github.com/ayaka-notes/toolkit) 是一个 git 仓库，因此获取 Toolkit 的新功能非常简单。只需运行 `bin/upgrade` 命令并按照屏幕上的提示操作即可。

值得注意的是，Docker 镜像版本（位于 `config/version`）与 Toolkit 代码更新是分开管理的。更新 Toolkit 代码**不会**自动更改你正在运行的 Docker 镜像版本。这意味着在大多数情况下，你可以只升级 Toolkit 版本而不升级你的部署。

#### `bin/upgrade` 脚本

运行 `bin/upgrade` 命令时，脚本会检查 Toolkit 代码是否有可用更新，并询问是否更新你的 Toolkit。你随时可以拒绝此次升级，此时不会发生任何更改。

如果你选择更新 Toolkit 代码，脚本接着会检查 _默认_ Docker 镜像版本是否发生了变化，并询问是否将你的本地版本文件（位于 `config/version`）升级为新的默认版本。

如果你选择切换版本，脚本会引导你完成关闭 Docker 服务、进行备份以及重新启动 Docker 服务的过程。你的旧版本文件会被自动复制到 `config/__old-version`，以备你需要回滚到该版本的 Docker 镜像。

<Info>

对于手动导入 Docker 镜像的离线（air-gapped）环境，请在 `config/overleaf.rc` 文件中设置 `PULL_BEFORE_UPGRADE=false`。

有关在离线（air-gapped/offline）环境中部署的更多信息，请查看[此处](/zh-CN/on-premises/installation/air-gapped-offline-deployments)。

</Info>

### 升级路径

如果你运行的是 v6.0.0 之前的旧版 Overleaf Community，请参阅 [Overleaf 官方文档](https://docs.overleaf.com/on-premises/maintenance/upgrading-your-deployment#upgrade-path)完成升级。
