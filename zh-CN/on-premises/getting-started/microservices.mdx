部署和管理 Overleaf Server CE 与 Overleaf Pro 实例的推荐方式是使用 Toolkit。

Toolkit 通过一些自定义脚本简化了 Overleaf 实例的创建，这些脚本将所需微服务的编排细节抽象化。只需运行附带的初始化脚本，提供一些配置选项（例如持久化存储路径），Toolkit 就会负责配置并连接构成 Overleaf Server CE 或 Pro 实例的各个微服务。

这让你可以专注于自定义用户体验并实现本地部署实例所需的特定功能。Toolkit 在幕后处理所有复杂性，让 Overleaf 实例的部署更加简单。

<Info>

由于历史原因，Overleaf 的主容器名为 `sharelatex`，并基于 `sharelatex/sharelatex` Docker 镜像。这是因为该技术基于 ShareLaTeX 代码库，而 ShareLaTeX 已并入 Overleaf。更多详情请参阅[这篇博客文章](https://www.overleaf.com/blog/518-exciting-news-sharelatex-is-joining-overleaf)。将来某个时候，它会被重命名以符合 Overleaf 的命名规范。

</Info>

#### 架构

在 Overleaf 容器内部，软件以一组由 `runit` 管理的微服务形式运行。容器内一些值得关注的文件包括：

* `/etc/service/`：微服务的初始化文件。
* `/var/log/overleaf/`：各微服务的日志。
* `/overleaf/services/`：各微服务的代码。
* `/var/lib/overleaf/`：持久化数据的挂载点（对应宿主机上 `OVERLEAF_DATA_PATH` 所指定的目录）。

#### MongoDB 和 Redis 容器

Overleaf 依赖两个外部数据库：MongoDB 和 Redis。默认情况下，除 Overleaf 容器外，Toolkit 还会为这两个数据库各配置一个容器，总共三个 Docker 容器。

<Info>

如果你更希望连接到现有的 MongoDB 或 Redis 实例，可以在 [overleaf.rc](/zh-CN/on-premises/configuration/overleaf-toolkit/files-and-locations#the-overleaf.rc-file) 配置文件中进行相应设置。

</Info>

#### 编辑器与编译流程

本节概述文档的处理方式和编译流程。

<Info>

本页描述的是仅在 Overleaf Pro 中提供的沙盒编译（Sandboxed Compiles）的编译流程。在 Server CE 中，编译流程使用简单的子进程——请将涉及**容器**的条目替换为单个条目**在子进程中运行编译**。

</Info>

组件 / 参与者：

* `user` — 应用程序的用户
* `editor` — 在浏览器中运行的客户端应用程序
* `clsi` — 用于编译 PDF 的微服务
* `document-updater` — 用于处理文档更新的微服务
* `filestore` — 处理二进制文件的微服务
* `real-time` — 用于处理 WebSocket 的微服务
* `web` — 用于处理 API 请求的（并不那么"微"的）服务

**Redis 缓存**

* **user**：加载编辑器页面
* **editor**：打开 WebSocket
* **editor**：通过 WebSocket 发送打开文档的请求
  * **real-time** -> **document-updater**：将文档从 MongoDB 加载到 Redis
* **editor**：通过 WebSocket 发送文档更新
  * **real-time** -> **document-updater**：在 Redis 中更新文档
* **editor**：发送更多编译请求
  * 距离上次刷写（按文档计）超过 5 分钟后：
    * **document-updater**：将文档从 Redis 刷写到 MongoDB
* **editor**：发送更多更新
  * 每 100 次更新（按文档计）：
    * **document-updater**：将文档历史从 Redis 刷写到 MongoDB
* **user**：离开编辑器/关闭浏览器标签页
  * 5 分钟后
    * **real-time**：检查是否还有其他协作者，如果没有：
      * **real-time** -> **document-updater**：将文档从 Redis 刷写到 MongoDB

**从 MongoDB 读取到 Redis**

* **document-updater** -> **web** -> **docstore**：从 MongoDB 读取

**从 Redis 刷写到 MongoDB**

* **document-updater** -> **web** -> **docstore**：写入 MongoDB

**编译——"full"（完整）同步模式**

* **editor**：发送同步模式设置为 "full" 的编译请求
* **web** -> **document-updater**：将所有文档从 Redis 刷写到 MongoDB
* **web** -> **docstore**：从 MongoDB 下载所有文档
* **web** -> **clsi**：向 `clsi` 发送编译请求，包括：
  * 同步模式
  * 文件树的哈希值 -> 即"项目状态"
  * 所有文档及其内容 -> 受 7MB 请求体大小限制
  * 用于单独下载的二进制文件 URL
* **clsi**：根据同步模式和"项目状态"检查磁盘上的状态
  * 这是完整同步，因此可以忽略之前的磁盘状态
* **clsi**：清理编译目录
* **clsi**：将所有文档写入编译目录
* **clsi**：将所有二进制文件写入编译目录
  * `clsi` 从每个项目的本地缓存中复制文件
  * 缓存未命中时：
    * **clsi** -> **filestore**：下载文件
* **clsi**：写入"项目状态"
* **clsi**：确保存在具有所需配置的 Docker 容器
  * 构建容器选项，包括 texlive 版本
  * 对选项进行哈希
  * 容器名称：`project-<project-id>-<user-id>-<hash>`
* **clsi**：启动容器并将 stdout/stderr 流式写入内存 -> 上限 2MB
* **clsi**：保留已停止的容器 -> 24 小时后清理
* **clsi**：将 stdout/stderr 写入磁盘
* **clsi**：将输出文件复制到唯一的输出目录
  * build-id 由 8 个随机字节加上毫秒精度的时间戳组成
  * 仅保留最近 3 个（匿名用户）/ 最近 1 个（已登录用户）构建文件夹，其余全部删除
* **clsi**：编译失败/超时
  * 删除编译缓存——其中可能包含不完整的文件或已损坏的缓存
* **editor**：下载 output.log 和 output.pdf

**编译——"incremental"（增量）同步模式**

* **editor**：发送同步模式设置为 "incremental" 的编译请求
* **web** -> **document-updater**：从 Redis 获取所有文档
  * "项目状态"哈希值也存储在 Redis 中
  * **web** 将文件树的哈希值发送给 `document-updater`，若不匹配，`document-updater` 可将增量编译转为完整编译
    * 参见编辑器请求 "full" 编译时执行的编译流程
* **web** -> **clsi**：向 `clsi` 发送编译请求，包括：
  * 同步模式
  * 文件树的哈希值 -> 即"项目状态"
  * 来自 Redis 的所有文档及其内容 -> 受 7MB 请求体大小限制
  * 不包含二进制文件
* **clsi**：根据同步模式和"项目状态"检查磁盘上的状态
  * 这是增量同步，因此"项目状态"必须匹配
  * 不匹配时：返回 409，让 web 以 "full" 同步重试
    * 参见编辑器请求 "full" 编译时执行的编译流程
* **clsi**：将更新后的文档写入编译目录
* **clsi**：确保存在具有所需配置的 Docker 容器
  * 构建容器选项，包括 texlive 版本
  * 对选项进行哈希
  * 容器名称：`project-<project-id>-<user-id>-<hash>`
* **clsi**：启动容器并将 stdout/stderr 流式写入内存 -> 上限 2MB
* **clsi**：保留已停止的容器 -> 24 小时后清理
* **clsi**：将 stdout/stderr 写入磁盘
* **clsi**：将输出文件复制到唯一的输出目录
  * build-id 由 8 个随机字节加上毫秒精度的时间戳组成
  * 仅保留最近 3 个（匿名用户）/ 最近 1 个（已登录用户）构建文件夹，其余全部删除
* **clsi**：编译失败/超时
  * 删除编译缓存——其中可能包含不完整的文件或已损坏的缓存
* **editor**：下载 output.log 和 output.pdf

**编译——模式切换**

* **editor**：观察到编译失败，下一次编译为 "full" 编译
* **editor**：观察到编译成功，下一次编译为 "incremental" 编译
