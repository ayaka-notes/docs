Kubernetes 部署读取的环境变量与 Toolkit 相同。当 Toolkit 页面要求“将其添加到 `config/variables.env`”时，请将该值放入 ConfigMap `overleaf-env`；如果是密码、密钥或令牌，则放入 Secret `overleaf-secrets`。然后重启：

```bash
kubectl -n overleaf apply -f 30-config.yaml        # after editing the ConfigMap
kubectl -n overleaf patch secret overleaf-secrets --type merge \
  -p '{"stringData":{"GITHUB_TOKEN_CIPHER_PASSWORD":"'"$(openssl rand -hex 32)"'"}}'
kubectl -n overleaf rollout restart deployment/overleaf
```

`config/overleaf.rc` 中的值是 Toolkit 设置，而不是环境变量；本页末尾的 Q\&A 说明了用什么来替代它们。

### 证书和其他文件

有些功能接受的是文件路径而不是值：SAML 证书（`OVERLEAF_SAML_IDP_CERT` 等）、LDAP CA（`OVERLEAF_LDAP_TLS_OPTS_CA_PATH`），或用于自托管 GitHub Enterprise、GitLab 或 Gitea 的私有 CA（`NODE_EXTRA_CA_CERTS`）。请将这些文件放入一个 Secret，并将其挂载到 Toolkit 页面所期望的位置 `/var/lib/overleaf/certs`：

```bash
kubectl -n overleaf create secret generic overleaf-certs --from-file=idp_cert.pem --from-file=ca.pem
```

```yaml title="40-overleaf.yaml (additions)"
          volumeMounts:
            # ...
            - name: certs
              mountPath: /var/lib/overleaf/certs
              readOnly: true
      volumes:
        # ...
        - name: certs
          secret:
            secretName: overleaf-certs
```

然后在 ConfigMap 中按路径引用它们，例如 `NODE_EXTRA_CA_CERTS: /var/lib/overleaf/certs/ca.pem`，并重启。

<Warning>

<strong>加密密码。</strong>请在 Secret 中为你使用的功能设置所有 `*_CIPHER_PASSWORD`。否则，某些功能会在首次使用时在数据卷中生成一个密钥文件：在只有一个副本时，这在卷丢失之前都能正常工作；而在有多个副本时，每个副本都会使用不同的密钥进行加密。

</Warning>

### Q\&A

<Accordion title="我需要 `config/overleaf.rc` 中的哪些 Toolkit 设置？">

<strong>回答：</strong>Ayakaleaf Pro 不会读取其中任何一项。它们在 Kubernetes 中的对应项如下：

| `config/overleaf.rc`                         | Kubernetes                                                        |
| -------------------------------------------- | ----------------------------------------------------------------- |
| `OVERLEAF_LISTEN_IP`、`OVERLEAF_PORT`        | Service（NodePort）或你的 Ingress                                 |
| `SIBLING_CONTAINERS_ENABLED`                 | ConfigMap 中的 `SANDBOXED_COMPILES*`，Pod 中的 Docker 套接字      |
| `GIT_BRIDGE_ENABLED`                         | [Git 集成](/zh-CN/on-premises/configuration/kubernetes/integrations/git-integration)                             |
| `MONGO_ENABLED`、`REDIS_ENABLED`、`MONGO_URL`、`REDIS_HOST` | StatefulSet 或你的托管服务，`OVERLEAF_MONGO_URL` 和 `OVERLEAF_REDIS_HOST` |
| `REDIS_AOF_PERSISTENCE`                      | `20-redis.yaml` 中的 `--appendonly yes`                           |
| `NGINX_ENABLED`、`TLS_*`                     | 你的 Ingress 或负载均衡器                                         |

</Accordion>
