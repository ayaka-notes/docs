Mendeley 导入运行在每个 Ayakaleaf Pro pod 的 **web** 服务（`tpr-webmodule` 模块）中。请按照 [Mendeley 集成](/zh-CN/on-premises/configuration/overleaf-toolkit/integrations/mendeley-integration) 中的说明注册 Mendeley 应用，重定向 URL 为 `${OVERLEAF_SITE_URL}/user/mendeley/oauth/callback`，然后按如下方式配置 Kubernetes。

| | |
| --- | --- |
| 服务 | web，位于每个 Ayakaleaf Pro pod 中；在 web 启动时读取 |
| Pod → Mendeley | `https://api.mendeley.com`（OAuth 令牌和 API），在用户关联 Mendeley、导入或刷新文件时访问 |
| 浏览器 → Mendeley | `https://api.mendeley.com/oauth/authorize`，然后返回重定向 URL |
| Mendeley → Overleaf | 无：实例无需能从互联网访问 |
| 存储的数据 | 用户的 Mendeley 令牌，加密后存储在 MongoDB 中 |
| 定期任务 | 无：仅在用户请求时刷新文件 |

### 配置

<Steps>
<Step title="ConfigMap">
```yaml title="30-config.yaml (changes)"
  ENABLED_LINKED_FILE_TYPES: project_file,project_output_file,url,mendeley
  MENDELEY_CLIENT_ID: "<application ID>"
  # optional: send the module's requests to Mendeley through an HTTP proxy
  # MENDELEY_PROXY_URL: http://proxy.example.com:3128
```

请为应用 ID 加上引号：它是一个数字，而 ConfigMap 只能保存字符串。`ENABLED_LINKED_FILE_TYPES` 会替换安装时设置的值；请保留你已有的类型并添加 `mendeley`（如果两者都使用，还需添加 `zotero`）。
</Step>

<Step title="Secret">
```bash
kubectl -n overleaf patch secret overleaf-secrets --type merge -p '{"stringData":{
  "MENDELEY_CLIENT_SECRET":"<secret>",
  "MENDELEY_CIPHER_PASSWORD":"'"$(openssl rand -hex 32)"'"}}'
```

`MENDELEY_CIPHER_PASSWORD` 用于加密存储在 MongoDB 中的用户 Mendeley 令牌。如果未设置，每个 pod 会在自己的 `/var/lib/overleaf/data` 中生成一个密钥文件。在[多个副本](/zh-CN/on-premises/configuration/kubernetes/horizontal-scaling)的情况下，每个节点的密钥都不同，由其他副本提供服务的用户将无法使用其已关联的 Mendeley 账户。请在第一个用户关联 Mendeley 之前设置它：之后更改会导致所有用户都需要重新关联 Mendeley。
</Step>

<Step title="应用并重启">
```bash
kubectl apply -f 30-config.yaml
kubectl -n overleaf rollout restart deployment/overleaf     # or statefulset/overleaf
```
</Step>
</Steps>

### 多个副本

请在 Secret 中设置 `MENDELEY_CIPHER_PASSWORD`，见上文。Mendeley 令牌与 Zotero 密钥使用相同的代码加密：如果没有该密码，在一个副本上导入的文件无法在另一个副本上刷新，正如我们在 [Zotero](/zh-CN/on-premises/configuration/kubernetes/integrations/zotero-integration#several-replicas) 中所见。OAuth `state` 保存在 Redis 中的会话里，因此回调可以到达任意副本。

### 在 Kubernetes 上的测试

我们针对 api.mendeley.com 的模拟服务（通过来自 `overleaf-certs` 的 `NODE_EXTRA_CA_CERTS` 信任），在 Kubernetes 1.37 上以三个副本部署在 HAProxy 之后，运行了 Mendeley 的端到端测试，全部通过（18 个用例）：通过 OAuth 2.0 关联和取消关联、将文献库和群组导入到 `.bib` 文件、刷新该文件、刷新即将过期的访问令牌、已撤销的令牌、要求重新关联、协作者可搜索参考文献、仅导入者可以刷新、API 错误，以及与 Mendeley 的慢速连接。
