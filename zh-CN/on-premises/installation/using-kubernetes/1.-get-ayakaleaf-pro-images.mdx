Kubernetes 运行的是与 Toolkit 相同的镜像。没有单独的 Kubernetes 镜像。

| 镜像                                                 | 使用者                                                                  |
| ---------------------------------------------------- | ----------------------------------------------------------------------- |
| `ghcr.io/ayaka-notes/overleaf-pro:6.3.2`             | Deployment `overleaf`                                                   |
| `ghcr.io/ayaka-notes/overleaf-pro/git-bridge:6.3.2`  | [Git 集成](/zh-CN/on-premises/configuration/kubernetes/integrations/git-integration)（可选），标签与上面相同 |
| `ghcr.io/ayaka-notes/texlive-*`                      | 编译，在[第 0 步](/zh-CN/on-premises/installation/using-kubernetes/0.-prepare-the-nodes)中拉取到节点的 Docker 中 |

这些镜像在 [ghcr.io](https://github.com/ayaka-notes/ayakaleaf-pro/pkgs/container/overleaf-pro/) 上公开提供 amd64 和 arm64 版本，因此 kubelet 无需凭据即可拉取。

<Warning>

请始终使用版本标签（例如 `6.3.2`），而不是 `latest`。升级会运行数据库迁移，必须遵循[在 Kubernetes 上升级](/zh-CN/on-premises/maintenance/upgrading-on-kubernetes)进行；使用会变动的标签会导致 pod 在每次被重新调度时都进行升级。

</Warning>

### Q\&A

<Accordion title="我们的节点无法访问 ghcr.io，该怎么办？">

<strong>回答：</strong>将镜像复制到节点可以访问的镜像仓库，并在清单文件中使用该名称，例如：

```bash
docker pull ghcr.io/ayaka-notes/overleaf-pro:6.3.2
docker tag ghcr.io/ayaka-notes/overleaf-pro:6.3.2 registry.example.com/ayakaleaf/overleaf-pro:6.3.2
docker push registry.example.com/ayakaleaf/overleaf-pro:6.3.2
```

对于未启用 TLS 的镜像仓库，containerd 需要在每个节点上有一个包含 `server = "http://<registry>"` 的 `/etc/containerd/certs.d/<registry>/hosts.toml`，并按照[第 0 步](/zh-CN/on-premises/installation/using-kubernetes/0.-prepare-the-nodes)设置 `config_path`。Docker 本身只会通过纯 HTTP 推送到 `localhost`，因此请在镜像仓库主机上通过 `localhost:<port>` 推送，或将其添加到 `insecure-registries` 中。

</Accordion>
