Ayakaleaf Pro 运行在你自己的基础设施中。你掌控它的数据、访问权限和网络边界。本页说明默认的安全模型，并指出你需要承担的运维责任。

### Ayakaleaf Pro 可靠且安全吗？

Ayakaleaf Pro 是一个自托管的 Overleaf Pro 增强版，我们的源代码发布在 [ayaka-notes/ayakaleaf-pro](https://github.com/ayaka-notes/ayakaleaf-pro)。由你的部署决定服务运行在哪里、数据存放在哪里。

安全性取决于你的配置和运维。请保护好管理员访问权限、启用 HTTPS 并做好备份。

感谢 OpenAI 的大力支持。我们会定期使用 [Codex Security](https://chatgpt.com/codex/cloud/security/findings) 扫描我们的代码仓库以发现安全问题，并公开分享漏洞修复的结果。

### 我的数据会去哪里？

默认情况下，应用数据保留在你的部署之内：

* MongoDB 存储用户和项目数据。
* Redis 存储缓存和实时协作数据。
* 本地卷或兼容 S3 的存储保存项目文件。

默认只对外暴露 Web 服务。内部服务之间通过 Docker 网络通信。

### 我的数据会被发送给第三方或从第三方获取吗？

除非你启用了需要外部通信的功能，否则任何数据都不会离开你的部署。Ayakaleaf Pro _不发送遥测数据、不进行使用情况分析，也不发送崩溃报告_。在默认配置中，错误报告和分析功能均已禁用。

有些功能完全不会发出外部请求。模板存储在你自己的部署中并由其提供服务。Python 脚本运行器通过 WebAssembly 在用户的浏览器中执行，其运行时由你自己的 Web 服务提供，而不是来自公共 CDN，因此脚本代码和输出永远不会进入网络。Git Bridge 只能在内部 Docker 网络中访问。全项目搜索、符号面板、修订追踪、项目历史和管理面板完全在本地运行。沙箱编译容器在创建时就禁用了网络。

其余功能的请求会到达以下目的地。每个请求都由 Web 服务发起：

<Accordion title="AI 助手与搜索">

AI 功能默认处于禁用状态。启用后，聊天和 LaTeX 错误建议会将提示词和相关的项目上下文发送到通过 `AI_BASE_URL` 配置的模型端点。可选的网页搜索会将查询发送到所配置的兼容 Tavily 的服务，文档搜索则将查询发送到 `DOCS_MCP_URL`（默认值：`https://docs.overleaf.com/~gitbook/mcp`）。搜索结果可能会被包含在发送给模型提供商的请求中。有关配置和用户控制，请参阅 [AI Integration](/zh-CN/on-premises/configuration/overleaf-toolkit/ai-integration  "mention")。

</Accordion>

<Accordion title="GitHub 集成">

**GitHub 集成**会访问 `github.com` 和 `api.github.com`。它需要每个用户通过关联 GitHub 账户单独启用，授权时会请求 `read:org`、`repo` 和 `workflow` 权限范围。推送时会将完整的项目文件内容作为 Git blob 上传，然后组装成树和提交。它还会执行分支、引用、比较和合并操作，并读取所关联账户的个人资料、组织成员关系和仓库列表。项目内容会双向离开你的部署——请将已关联的 GitHub 账户视为其所关联的每个项目的导出通道。

</Accordion>

<Accordion title="Zotero 集成">

**Zotero 集成**会访问 `www.zotero.org` 进行授权，访问 `api.zotero.org` 获取文献库数据。它需要每个用户通过关联 Zotero 账户单独启用。发送的内容包括 OAuth 握手信息和用户的 API 密钥。读取是单向的：参考文献库以 BibTeX 形式拉取，不会上传任何项目内容。

</Accordion>

<Accordion title="Mendeley 集成">

**Mendeley 集成**会访问 `api.mendeley.com` 进行授权和获取文献库数据。它需要每个用户通过关联 Mendeley 账户单独启用。OAuth 握手会请求 Mendeley 的 `all` 权限范围（这是其 API 提供的唯一权限范围），但 Ayakaleaf 只执行读取操作：参考文献库和群组文献库以 BibTeX 形式拉取，不会上传任何项目内容。访问令牌会自动刷新；当 Mendeley 撤销授权时，已存储的凭据会被丢弃，用户需要重新关联账户。

</Accordion>

<Accordion title="文档页面">

**文档页面**从 `https://learnwiki.overleaf.com` 获取，可通过 `WIKI_URL` 进行配置。请求由 Web 服务发出，而不是由用户的浏览器发出，因此上游 wiki 看到的是你的服务器地址，永远不会看到你用户的地址。只会发送所请求的页面标题，并且响应会缓存在磁盘上。如果无法接受出站的文档流量，请将 `WIKI_URL` 指向你自己的镜像，或屏蔽该目的地。

</Accordion>

<Accordion title="邮件发送">

**邮件发送**会访问你所配置的任意 SMTP 服务器或邮件 API；没有默认值。收件人地址和邮件内容（包括密码重置和邀请链接）会离开你的部署。

</Accordion>

<Accordion title="两项可选检查（PWD/reCAPTCHA）">

**两项可选检查默认处于禁用状态。** 除非设置了 `HAVE_I_BEEN_PWNED_ENABLED`，否则泄露密码检查不会生效；启用后，它会将密码 SHA-1 哈希的前几个字符发送到 `api.pwnedpasswords.com`，绝不会发送密码本身。除非配置了 reCAPTCHA 站点密钥，否则 CAPTCHA 验证不会生效；生效时会访问 `www.google.com`。

</Accordion>

<Accordion title="单点登录（OAuth/LDAP/SAML）">

**单点登录**只会访问你提供的身份提供商，传输的内容取决于所用协议。使用 LDAP 时，Web 服务直接连接到你的目录服务：它使用你配置的服务账户进行绑定，在你定义的基准、过滤器和属性列表下进行搜索，并将登录表单中输入的密码与你的目录进行验证，因此用户名和密码会到达目录服务器。启用基于目录的联系人功能会额外进行一次搜索以填充联系人列表。使用 OIDC 时，Web 服务会在你的令牌端点交换授权码，然后调用你的用户信息端点，默认请求 `openid profile email` 权限范围；这可以通过 `OVERLEAF_OIDC_SCOPE` 进行配置。使用 SAML 时，认证请求通过用户的浏览器传递给身份提供商，而不是通过服务器直连。在这三种情况下，用户的姓名和邮箱地址都是从身份提供商获取的，而不是发送给它的，随后会存储在本地用户记录中。

</Accordion>

<Accordion title="第三方凭据">

**第三方凭据**（OAuth 令牌和 API 密钥）保存在 MongoDB 的用户记录中，使用 AES-256-CTR 加密，每条记录使用独立的盐值和初始化向量。它们永远不会以明文存储，也永远不会写入日志。如果设置了 `${PROVIDER}_CIPHER_PASSWORD`（例如 Zotero 和 Mendeley），则使用它作为加密密钥；否则会在首次使用时生成一个密钥，并以仅所有者可访问的权限持久化保存在你的数据卷中。请将该密钥与数据卷一起备份：如果密钥丢失，已存储的凭据将无法解密，所有用户都必须重新关联账户。

</Accordion>

<Accordion title="通过 URL 链接的文件">

**通过 URL 链接的文件**由你的部署代表用户获取，因此目的地是用户提供的任意地址。除非你将 `url` 添加到 `ENABLED_LINKED_FILE_TYPES` 中，否则 URL 链接文件功能处于禁用状态，默认配置中不包含它。通过 Open in Overleaf API 进行的外部 ZIP 和 TeX 导入也使用同一个 `linked-url-proxy` 组件。直接请求会解析目标主机名并拒绝受限的网络范围，但受所配置的允许资源例外规则约束。配置了 `OVERLEAF_LINKED_URL_OUTBOUND_PROXY` 时，由出站代理解析主机名，因此代理本身必须实施内网访问限制；应用层的网络检查只适用于包含 IP 地址的 URL。详情请参阅 [External URL — Outbound Proxy](/zh-CN/on-premises/configuration/overleaf-toolkit/external-url#outbound-proxy  "mention")。这些请求只获取所提供的 URL，而不会上传项目文件。

</Accordion>

如果你的策略要求设置出站白名单，请只放行已启用功能所需的主机——GitHub 需要 `github.com` 和 `api.github.com`，Zotero 需要 `www.zotero.org` 和 `api.zotero.org`，Mendeley 需要 `api.mendeley.com`，文档需要 `learnwiki.overleaf.com` 或你自己的 `WIKI_URL`，密码检查需要 `api.pwnedpasswords.com`，CAPTCHA 需要 `www.google.com`，再加上你自己的邮件服务器和身份提供商。如果启用了 AI 功能或搜索，还需放行所配置的模型、网页搜索和文档 MCP 端点。拒绝所有已启用功能不需要的目的地。如果出站流量必须集中检查或记录，可以通过设置 `GITHUB_SYNC_PROXY_URL`、`MENDELEY_PROXY_URL` 和 `ZOTERO_PROXY_URL`，让 GitHub、Zotero 和 Mendeley 集成分别经由 HTTP 代理转发。URL 链接文件的获取和远程导入可以使用 `OVERLEAF_LINKED_URL_OUTBOUND_PROXY`。通过 URL 链接的文件无法限定在某个主机列表内，因为目的地是由用户在请求时选择的；请通过代理组件自身的允许资源设置来限制该功能，或保持其禁用状态。

<Warning>

如果你在部署 Ayakaleaf Pro 时启用了 [s3.md](/zh-CN/on-premises/configuration/overleaf-toolkit/s3  "mention") 存储，存储在 S3 中的数据是否加密？

_**不加密。**_ 数据未经加密。所有历史数据块、模板文件、PDF 及其他文件都以明文存储。如果你使用第三方外部 S3 存储提供商，请格外注意数据安全和隐私。

</Warning>

### 项目编译是隔离的吗？

Ayakaleaf Pro 支持沙箱编译。每次编译都在独立的容器中运行。沙箱容器默认没有网络访问权限，这降低了内部网络资源的暴露风险。

沙箱编译需要访问宿主机的 Docker 套接字。请仅允许可信的运维人员管理宿主机。

### 我可以信任 CI 构建和容器镜像吗？

Ayakaleaf Pro 的容器镜像由 GitHub Actions 构建和发布。镜像可从公开的 GitHub Container Registry 获取。

镜像支持 `amd64` 和 `arm64`。拉取镜像时，Docker 会自动选择匹配的架构。

不要在生产环境中使用 `latest` 标签。请固定明确的版本，最好使用镜像摘要（digest）。

请在非生产环境中测试每次升级。在正式上线前验证镜像、配置和各项集成。

### 代码是开源的吗？

Ayakaleaf Pro 及相关功能仓库均公开可用。这使用户能够审查变更并追溯上游来源。

公开的源代码便于独立审查，但其本身并不能保证发布构建是可复现的。

升级之前，请检查：

* 发布标签或提交。
* 镜像版本或摘要。
* 第三方依赖项和许可证要求。
