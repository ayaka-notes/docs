我们非常自豪地宣布 Overleaf Pro 6.3.2 正式发布。上游 Overleaf 6.3.2 是一个更新 Node.js 的安全版本，而我们在发布它的同时，还为同步家族带来了一位新成员：继 GitHub、GitLab 和 Dropbox 之后，你的项目现在也可以存放在 Gitea 中了。

### 变更

* Gitea 同步（早期预览版）：与 gitea.com 或你自托管的 Gitea 进行双向同步。
* Node.js 24.22.1：上游 Overleaf 6.3.2 中的安全更新。
* 由我们的 E2E 测试系统和内部 Horizon 问题排查（Internal Horizon Issue Investigation）发现的问题修复。

<Info>

Gitea 同步在 6.3.2 中作为**早期预览版**发布，用于灰度测试，并将在 v6.4.0 中正式发布。在此之前，它的配置和行为仍可能发生变化。它默认处于关闭状态。如有任何问题，请在 [GitHub](https://github.com/ayaka-notes/ayakaleaf-pro/issues) 上反馈。

</Info>

#### 功能 01：Gitea 同步（预览版）

许多实验室和小团队都在运行自己的 Gitea，因为它足够轻量，一台小型服务器就能跑起来。Gitea 同步的工作方式与 GitHub 同步和 GitLab 同步相同：关联你的账户，从新建项目菜单中导入仓库，或将项目导出到新的 Gitea 仓库。然后在编辑器中推送和拉取，并通过拉取请求以仓库自身的合并方式进行合并。Overleaf 从不绕过你的分支保护：当拉取请求需要审批或通过检查时，它会等待你在 Gitea 中完成合并。

它支持 gitea.com 以及 1.23 或更高版本的自托管 Gitea。请设置 `GITEA_SYNC_ENABLED`、`GITEA_SYNC_CLIENT_ID`、`GITEA_SYNC_CLIENT_SECRET` 和 `GITEA_TOKEN_CIPHER_PASSWORD`，对于自托管实例还需设置 `GITEA_SYNC_URL`。

完整的设置说明请参见 [Gitea 同步](/zh-CN/on-premises/configuration/overleaf-toolkit/gitea-synchronisation  "mention")。

#### 问题修复

* **Git 同步**：当在 GitHub、GitLab 或 Gitea 上删除的文件无法在 Overleaf 中删除时，同步现在会失败并可以重试，而不是报告成功并将该文件遗留在项目中。删除文件的 `git push` 也会以同样的方式失败。
* **Git bridge**：在编辑器中创建的、带有非文本扩展名（例如 `.csv`）的文档，在被 `git push` 修改后仍可编辑。
* **修订追踪**：通过链接共享的项目中未登录的编辑者可以删除评论线程，但不能再解决或重新打开它们；审阅者可以删除自己的回复。
* **模板库**：发布模板需要拥有该项目的访问权限。
* **Learn**：当无法访问 wiki 时，已缓存的帮助页面仍然可用。

完整列表请参见 [6.3.2 发行说明](/zh-CN/on-premises/release-notes/release-notes-6.x.x#ayakaleaf-pro-6.3.2  "mention")。

#### 升级

* 从 6.3.1 或 6.3.0 升级：无需迁移。拉取新镜像并重启即可。
* 从 6.2.x 或更早版本升级且正在使用 Zotero 或 Mendeley：请先运行 6.3.0 中的 [Zotero / Mendeley 迁移](/zh-CN/on-premises/release-notes/release-notes-6.x.x#ayakaleaf-pro-6.3.0  "mention")。
* Gitea 同步默认关闭，只需要新的环境变量。

#### Docker 镜像

你可以在这里找到 Docker 镜像：[https://github.com/ayaka-notes/ayakaleaf-pro/pkgs/container/overleaf-pro](https://github.com/ayaka-notes/ayakaleaf-pro/pkgs/container/overleaf-pro)
