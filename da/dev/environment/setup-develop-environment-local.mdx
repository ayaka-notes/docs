## Forudsætninger {#prerequisites}

Overleaf er et typisk open source-projekt med mikroservicearkitektur, hvor alle tjenester kører i Docker.&#x20;

* Den officielle kildekode til Community Edition findes på [GitHub Overleaf Official](https://github.com/overleaf/overleaf/tree).&#x20;
* Kildekoden til Overleaf-CEP er tilgængelig på [GitHub Yu-i-i/Overleaf](https://github.com/yu-i-i/overleaf-cep).
* Ayakaleaf Pro er tilgængelig på [GitHub ayaka-notes/ayakaleaf-pro](https://github.com/ayaka-notes/ayakaleaf-pro).

For at opsætte et udviklingsmiljø til Overleaf skal du bruge en kraftig server; en konfiguration med mindst 8 kerner og 16 GB RAM anbefales, da du skal køre mere end 20 containere samtidigt.

<Info>

Da servere med 8 eller flere CPU-kerner typisk er dyre, anbefales det kraftigt at bruge din lokale computer til udvikling.

</Info>

Som udvikler går vi samtidig ud fra, at du allerede er fortrolig med [installation af Docker](https://docs.docker.com/engine/install/ubuntu/). Vi anbefaler kraftigt at bruge en nyere og stabil Ubuntu LTS (f.eks. Ubuntu 24.04 i 2025–2026) og den nyeste Docker til udvikling, da det mindsker risikoen for uventede fejl.

Kort sagt skal du bruge:

* [x] En kraftig server/desktop til udvikling
* [x] En nyere og stabil Ubuntu LTS (f.eks. Ubuntu 24.04)
* [x] Et Docker- og Git-miljø

## Konfigurationsvejledning {#configuration-tutorial}

Her bruger vi Ayakaleaf Pro til at vise, hvordan du opsætter et udviklingsmiljø til Overleaf. Alle kommandoer nedenfor køres i mappen `develop`, medmindre andet er angivet.

<Steps>
<Step title="Hent kildekoden">
Lad os først klone repositoriet:

```bash title="bash"
git clone https://github.com/ayaka-notes/ayakaleaf-pro.git
cd ayakaleaf-pro/develop
```
</Step>

<Step title="Synkroniser `yarn.lock`">
Repoet bruger Yarn 4 (`packageManager` i rodens `package.json`), og dets `yarn.lock` kan være ude af synk med `package.json`-filerne. Synkroniser den efter den første kloning og efter enhver ændring i en `package.json`:

```bash title="bash"
bin/sync
```

`bin/sync` kører `yarn install --mode=update-lockfile` i en `node:24.18.1`-container, så du behøver ikke Node.js på værten. Commit ikke den ændrede `yarn.lock`.
</Step>

<Step title="Byg udviklingsimaget">
Byg tjenesterne:

```bash title="bash"
bin/build
```

<Info>

Hvis Docker løber tør for RAM, mens tjenesterne bygges parallelt, skal du oprette en `.env`-fil i denne mappe, der indeholder `COMPOSE_PARALLEL_LIMIT=1`.

</Info>
</Step>

<Step title="Anvend oversættelserne">
Modulerne i Ayakaleaf Pro har deres oversættelser i `services/web/locales/locales_patches/`, som de committede sprogfiler ikke indeholder. Anvend dem én gang før første start, ellers viser disse modulers sider nøgler som `about_to_permanently_delete_accounts` i stedet for tekst:

```bash title="bash"
bin/i18n
```

Det kræver `jq` på værten. Kør det igen, når du har tilføjet en oversættelse eller skiftet gren, se [Opdater i18n-oversættelser](/da/dev/environment/update-i18n-translations).
</Step>

<Step title="Start alle mikrotjenester">
Start derefter tjenesterne:

```bash title="bash"
bin/up
```

Når tjenesterne kører, skal du åbne [http://localhost/launchpad](http://localhost/launchpad) for at oprette den første administratorkonto. Tilføj porten, hvis du har ændret `OVERLEAF_PORT` (se nedenfor).

<Info>

LDAP er slået til som standard (`LDAP_ENABLED=true` i `dev.rc`). Launchpad viser så LDAP-administratorformularen: den beder kun om en e-mailadresse, og den administrator logger derefter ind via LDAP, for eksempel som `professor` / `professor` (`professor@planetexpress.com`). Testbrugerne står i `develop/authentication/README.md`. Sæt `LDAP_ENABLED=false` og `SAML_ENABLED=false` for i stedet at oprette en lokal administrator med adgangskode.

</Info>
</Step>
</Steps>

<Info>

`develop/dev.env` sætter allerede `ADMIN_PRIVILEGE_AVAILABLE=true`, så administratorer kan åbne administrationspanelet uden ekstra opsætning.

</Info>

### Konfiguration (`dev.rc`) {#configuration-dev-rc}

`develop/dev.rc` ved siden af `dev.env` indeholder udviklingsmiljøets kontakter, ligesom `overleaf.rc` i Overleaf Toolkit. Ændr en værdi, og kør `bin/dev` igen for at anvende den; en funktion, der er slået fra, stopper også sine containere.

| Variabel | Standard | Hvad den gør |
| --- | --- | --- |
| `OVERLEAF_PORT` | `80` | Sitets værtsport. |
| `LDAP_ENABLED` | `true` | LDAP-login med testbrugere. |
| `SAML_ENABLED` | `true` | SAML-login med testbrugere. |
| `MAILPIT_ENABLED` | `true` | Opfanger alle e-mails fra `web` i Mailpit. Slår også e-mailbekræftelse til (`EMAIL_CONFIRMATION_DISABLED=false`). |
| `S3_ENABLED` | `true` | Gemmer historik- og skabelonfiler i RustFS (S3) i stedet for lokale volumener. |
| `HOPPSCOTCH_ENABLED` | `true` | Hoppscotch med en proxy ind i Docker-netværket, se [Opsætning af udviklingsværktøjer](/da/dev/environment/setup-develop-tools). |
| `HOPPSCOTCH_PORT` | `9170` | Hoppscotchs værtsport. |
| `GRAFANA_ENABLED` | `true` | Grafana på sitets `/grafana/` med tilstand, målinger og logs for hver tjeneste, se [Opsætning af udviklingsværktøjer](/da/dev/environment/setup-develop-tools). |

Hver funktion har sin `docker-compose.yml` og andre filer i sin egen mappe: `authentication/ldap`, `authentication/saml`, `mail`, `s3`, `hoppscotch` og `grafana`. En funktion, der har brug for en `web`-indstilling uden miljøvariabel, monterer en fil i `/etc/overleaf/settings.d/`, og `develop/settings.dev-env.cjs` fletter dem alle. Alle `bin/*`-scripts går gennem `bin/docker-compose`, som tilføjer filerne for de funktioner, der er slået til. Brug `bin/docker-compose` i stedet for `docker compose`, når du selv har brug for en compose-kommando.

<Warning>

De lokale volumener og RustFS er adskilte lagre: et projekt oprettet med `S3_ENABLED=true` har ingen historik eller binære filer efter skift til `false`, og omvendt. For at kopiere filerne fra et miljø, der kørte, før `S3_ENABLED` fandtes, til RustFS skal du følge »Moving existing data into RustFS« i [develop/README.md](https://github.com/ayaka-notes/ayakaleaf-pro/blob/server-pro/develop/README.md).

</Warning>

### Porte {#ports}

Sitet, RustFS-konsollen og Hoppscotch lytter på værtens `127.0.0.1`; på en fjernmaskine skal du først videresende deres porte, for eksempel `ssh -L 9001:localhost:9001 <host>`. Sitet bruger `OVERLEAF_PORT` fra `dev.rc`, så tilføj porten til adresserne nedenfor, hvis du har ændret den.

| Side | Adresse | Login |
| --- | --- | --- |
| Site | [http://localhost](http://localhost) | Sitets konti eller testbrugerne |
| E-mailindbakke (Mailpit) | [http://localhost/mailpit/](http://localhost/mailpit/) | Ingen |
| Grafana | [http://localhost/grafana/](http://localhost/grafana/) | Ingen, anonyme brugere er administratorer |
| Mongo Express | [http://localhost/mongo-express/](http://localhost/mongo-express/) | Ingen |
| RedisInsight | [http://localhost/redis-insight/](http://localhost/redis-insight/) | Ingen |
| S3-konsol (RustFS) | [http://localhost:9001/rustfs/console/](http://localhost:9001/rustfs/console/) | `rustfsadmin` / `rustfsadmin` |
| Hoppscotch | [http://localhost:9170](http://localhost:9170) (`HOPPSCOTCH_PORT`) | Ingen |

Mailpit, Grafana, Mongo Express og RedisInsight serveres af sitet på deres egne stier via webpack-dev-server, så de behøver ingen egen port. Når du er logget ind, linker menuen **Dev tools** i sitets navigationslinje til dem; en side, hvis funktion er slået fra i `dev.rc`, udelades. [Opsætning af udviklingsværktøjer](/da/dev/environment/setup-develop-tools) viser, hvad hver af dem gør.

S3-API'et (port 9000) og SMTP (port 1025) kan kun nås inde i Docker-netværket. Mongo (27017), Redis (6379), Mongo Express (8081), RedisInsight (5540) og git-bridge (8000) publiceres kun på værtens `127.0.0.1`.

### TeX Live {#tex-live}

Sandkassekompileringer er slået til som standard: `develop/dev.env` sætter `SANDBOXED_COMPILES=true` og imagene `ghcr.io/ayaka-notes/texlive-full:2026.1` og `ghcr.io/ayaka-notes/texlive-full:2025.1`. clsi henter ikke images selv, så hent dem én gang:

```bash
docker pull ghcr.io/ayaka-notes/texlive-full:2026.1
docker pull ghcr.io/ayaka-notes/texlive-full:2025.1
```

Se [Opsætning af Sandbox Compiles](/da/dev/environment/setup-sandbox-compiles) for detaljer.

<Warning>

Et projekt, der blev oprettet, mens `SANDBOXED_COMPILES` var slået fra, har intet TeX Live-image. Det kompilerer stadig med standardimaget, men at springe mellem koden og PDF'en fejler med »That didn't work. Recompile and try again.« Giv sådanne projekter imaget fra `TEX_LIVE_DOCKER_IMAGE` én gang; uden `--commit` viser scriptet kun, hvad det ville ændre:

```bash
bin/docker-compose exec web sh -c 'cd /overleaf/services/web && node scripts/backfill_project_image_name.mjs --commit'
```

</Warning>

`dev.env` slår også Pandoc-konverteringer til med `PANDOC_IMAGE=overleaf-pandoc:local`. Byg det image én gang fra roden af repoet:

```bash
docker build -t overleaf-pandoc:local develop/pandoc
```

For at kompilere på en macOS-vært skal du muligvis tilsidesætte stien til Docker-socket ved at oprette en `.env`-fil i mappen `develop` med indholdet `DOCKER_SOCKET_PATH=/var/run/docker.sock.raw`

### Udvikling {#development}

For at undgå at køre `bin/build && bin/up` efter hver kodeændring kan du køre Overleaf Community Edition i _udviklingstilstand_, hvor tjenesterne automatisk opdateres ved kodeændringer.

Det gør du med det medfølgende script `bin/dev`:

```text
bin/dev
```

Dette starter alle tjenester med `node --watch`, som automatisk overvåger koden og genstarter tjenesterne efter behov. Kør det igen, når du har ændret `dev.rc`.

For at forbedre ydeevnen kan du starte kun en delmængde af tjenesterne i udviklingstilstand ved at give scriptet `bin/dev` en mellemrumsadskilt liste:

```text
bin/dev [service1] [service2] ... [serviceN]
```

<Info>

Hvis tjenesten `web` startes i _udviklingstilstand_, opdateres `web`-tjenesten kun, når backend-koden ændres. For også at opdatere frontend-koden automatisk skal du sørge for også at starte tjenesten `webpack` i _udviklingstilstand_.

</Info>

Hvis der ikke angives nogen tjenester, starter alle tjenester i udviklingstilstand.

Når du har tilføjet en oversættelse eller skiftet gren, skal du køre `bin/i18n`, se [Opdater i18n-oversættelser](/da/dev/environment/update-i18n-translations).

### Fejlfinding {#debugging}

I _udviklingstilstand_ eksponerer de fleste tjenester en fejlfindingsport, som du kan tilknytte en debugger til, for eksempel inspektøren i Chromes Dev Tools eller en, der er integreret i en IDE. Følgende tabel viser porten, der eksponeres på `127.0.0.1` på **værtsmaskinen** for hver tjeneste:

| Tjeneste           | Port |
| ------------------ | ---- |
| `web`                   | 9229 |
| `clsi`                  | 9230 |
| `chat`                  | 9231 |
| `docstore`              | 9233 |
| `document-updater`      | 9234 |
| `filestore`             | 9235 |
| `notifications`         | 9236 |
| `real-time`             | 9237 |
| `history-v1`            | 9239 |
| `project-history`       | 9240 |
| `linked-url-proxy`      | 9241 |
| `third-party-datastore` | 9242 |

For at tilknytte dig en tjeneste med Chromes _remote debugging_ skal du gå til chrome://inspect/ og sikre dig, at _Discover network targets_ er markeret. Klik derefter på _Configure..._ og tilføj en post `localhost:[service port]` for hver af de tjenester, du vil tilknytte en debugger til.

Når du har tilføjet en post, vises tjenesten som et _Remote Target_, som du kan inspicere og debugge.

### Logning {#logging}

Scriptet `bin/logs` følger logs og formaterer dem med `bunyan`. Det kræver også `ggrep`, som er navnet på GNU grep, når det installeres med Homebrew på macOS; Ubuntu har ingen `ggrep`-kommando.

```bash
sudo npm install -g bunyan
# Or sudo apt install node-bunyan 
```

Alternativt kan du køre direkte med:

```text
bin/docker-compose logs -f [service name]
```

Brug `bin/docker-compose` i stedet for `docker compose`, så tjenesterne for funktionerne i `dev.rc` (`mailpit`, `rustfs`, `ldap`, `saml`, `hoppscotch` og `grafana` med Prometheus, Loki og eksportørerne) også findes.

Med `GRAFANA_ENABLED=true` ligger logs fra alle containere også i Grafana, hvor de kan filtreres efter tjeneste, niveau og tekst, se [Opsætning af udviklingsværktøjer](/da/dev/environment/setup-develop-tools#grafana).
