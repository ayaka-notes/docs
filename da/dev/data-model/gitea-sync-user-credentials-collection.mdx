---
title: Gitea Sync User Credentials-samlingen
icon: lock
---

`giteaSyncUserCredentials` indeholder ét dokument pr. bruger, der har forbundet en Gitea-konto til Gitea Sync. Den gemmer brugerens OAuth-tokens, krypteret. Samlingen hører til webmodulet `gitea-sync` (`services/web/modules/gitea-sync`). Skemaet ligger i `services/web/modules/gitea-sync/app/models/giteaSyncUserCredentials.mjs`, og al adgang går gennem `services/web/modules/gitea-sync/app/src/TokenManager.mjs`.

#### Felter {#fields}

| Felt | Type | Betydning | Kilde |
| ----- | ---- | ------- | ------ |
| `_id` | ObjectId | Sættes af Mongoose, når upserten indsætter. | |
| `userId` | ObjectId | Overleaf-brugeren. Påkrævet. Skemaet siger `unique: true`, men der bygges intet indeks (se Indekser); upserten på `userId` holder ét dokument pr. bruger. | `giteaSyncUserCredentials.mjs:8`, `TokenManager.mjs:89-96` |
| `gitea` | String | JSON-værdien `{ accessToken, refreshToken, expiresAt }`, krypteret med `@overleaf/access-token-encryptor`. `expiresAt` er i millisekunder siden epoken, eller `null`; `refreshToken` kan være `null`. Adgangskoden kommer fra `GITEA_TOKEN_CIPHER_PASSWORD`; chifferetiketten er `GITEA_TOKEN_CIPHER_LABEL`, standard `2026.10-v3`. Påkrævet. | `giteaSyncUserCredentials.mjs:9-10`, `TokenManager.mjs:17-30`, `services/web/modules/gitea-sync/app/src/GiteaApiClient.mjs:198-209` |
| `__v` | Number | Mongoose’ versionsnøgle. Skemaet slår den ikke fra. | Mongoose-standard |

#### Hvem skriver {#who-writes-it}

| Kode | Hvad den gør |
| ---- | ------------ |
| `TokenManager.mjs:89-96` (`saveUserToken`) | Laver upsert af brugerens krypterede loginoplysninger. Kaldes fra OAuth-callbacken (`services/web/modules/gitea-sync/app/src/GiteaSyncController.mjs:146`). I modsætning til GitLab Sync tilbagekalder en ny forbindelse ikke det erstattede token. |
| `TokenManager.mjs:53-79` (`refreshUserToken`) | Når adgangstokenet har mindre end 5 minutter til `expiresAt` (`:12`), henter den nye tokens med opdateringstokenet og gemmer dem (`:76`). Den kører under låsen `giteaSyncToken` pr. bruger (`:14,54`), fordi Gitea erstatter opdateringstokenet, når det bruges. |
| `TokenManager.mjs:100-102` (`removeUserToken`) | Sletter dokumentet. Gitea har intet API til at tilbagekalde et OAuth-token, så brugeren tilbagekalder tilladelsen i Gitea (`:98-99`). Kaldes ved afbrydelse af forbindelsen (`GiteaSyncController.mjs:173`), og når en slettet bruger udløber (`services/web/modules/gitea-sync/index.mjs:56-58`). |

#### Hvem læser {#who-reads-it}

| Kode | Hvad den gør |
| ---- | ------------ |
| `TokenManager.mjs:40-44,82-86` (`getUserCredentials`, `getUserToken`) | Dekrypterer loginoplysningerne ved hvert kald til Giteas API og fornyer dem først, når tokenet snart udløber: `services/web/modules/gitea-sync/app/src/GiteaSyncHandler.mjs` (for eksempel `:27`) og `services/web/modules/gitea-sync/app/src/GitMerge.mjs:52`. Uden dokument, eller med loginoplysninger der ikke kan dekrypteres eller fornyes, kaster den `InvalidTokenError`, og brugeren regnes som ikke forbundet (`GiteaSyncHandler.mjs:25-37`). |
| `services/web/modules/admin-tools/app/src/AdminUserListManager.mjs:395` | Tjekker, om brugeren har et dokument, til de integrationer der vises i adminpanelet. |

#### Indekser {#indexes}

| Navn | Nøgler | Indstillinger | Migrering |
| ---- | ---- | ------- | --------- |
| `_id_` | `_id: 1` | | default |

Mongoose `autoIndex` er slået fra (`services/web/app/src/infrastructure/Mongoose.mjs:7`), så skemaets `unique: true` på `userId` opretter intet. Ingen migrering opretter indekser for denne samling.

#### Bemærkninger {#notes}

* Ændres `GITEA_TOKEN_CIPHER_PASSWORD`, bliver de gemte loginoplysninger ulæselige. Disse brugere regnes så som ikke forbundet, indtil de forbinder igen.
* En slettet bruger beholder dokumentet, indtil brugeren udløber.
