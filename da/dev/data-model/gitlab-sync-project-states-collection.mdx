`gitlabSyncProjectStates` indeholder ét dokument pr. projekt, der er forbundet med et GitLab-projekt: hvilket repository, og hvor den seneste synkronisering slap. Samlingen hører til webmodulet `gitlab-sync` (`services/web/modules/gitlab-sync`). Skemaet ligger i `services/web/modules/gitlab-sync/app/models/gitlabSyncProjectStates.mjs`, og al adgang går gennem `services/web/modules/gitlab-sync/app/src/SyncStateManager.mjs`. Felterne er de samme som i [GitHub Sync Project States](/da/dev/data-model/github-sync-project-states-collection).

#### Hvem skriver {#who-writes-it}

| Kode | Hvad den gør |
| ---- | ------------ |
| `SyncStateManager.mjs:9-14` (`createProjectState`) | Opretter dokumentet: efter import af et repository som et nyt projekt (`services/web/modules/gitlab-sync/app/src/GitLabSyncHandler.mjs:175-181`), eller efter eksport af et projekt til et nyt repository (`GitLabSyncHandler.mjs:234-240`, kun ejeren, afvises hvis det allerede er forbundet). |
| `SyncStateManager.mjs:16-21` (`updateProjectState`) | `$set` af de ændrede felter. `getMergeOverview` sætter `mergeStatus: 'diverged'`, når den synkroniserede gren ikke længere indeholder `lastSyncCommit` (merge base-tjek, `services/web/modules/gitlab-sync/app/src/GitLabApiClient.mjs:460`), eller når committen er væk, og brugeren kan pushe (`GitLabSyncHandler.mjs:123,126-137`). En synkronisering (`services/web/modules/gitlab-sync/app/src/GitMerge.mjs`) flytter `lastSyncCommit`/`lastSyncVersion`, når den lykkes (for eksempel `:152,189,231`), registrerer en konflikt med `unmergedBranchName`, `unmergedBranchHead` og `conflictVersion` (`:214-220`), og rydder dem, når konflikten er løst (`:257-264`). |
| `SyncStateManager.mjs:23-25` (`removeProjectState`) | Sletter dokumentet, når ejeren afbryder forbindelsen til projektet (`GitLabSyncHandler.mjs:83-97`), og når et slettet projekt udløber (`services/web/modules/gitlab-sync/index.mjs:46-48`). |

#### Hvem læser {#who-reads-it}

| Kode | Hvad den gør |
| ---- | ------------ |
| `GitLabSyncHandler.mjs:39-60` (`getProjectState`) | Giver editoren `mergeStatus`, `repoFullName` og `unmergedBranchName`. Uden dokument svarer den `need-export`, en værdi der aldrig gemmes. |
| `GitLabSyncHandler.mjs:110-143` (`getMergeOverview`) | Sammenligner `lastSyncCommit` og `lastSyncVersion` med GitLab og projekthistorikken for at liste de nye commits. |
| `GitLabSyncHandler.mjs:200` (`exportProject`) | Nægter at eksportere et projekt, der allerede er forbundet. |
| `GitMerge.mjs:36` (`doGitMergeWithoutLock`) | Indlæser tilstanden ved starten af en synkronisering. |

#### Indekser {#indexes}

| Navn | Nøgler | Indstillinger | Migrering |
| ---- | ---- | ------- | --------- |
| `_id_` | `_id: 1` | | default |

Mongoose `autoIndex` er slået fra (`services/web/app/src/infrastructure/Mongoose.mjs:7`), så skemaets `unique: true` på `projectId` opretter intet. Ingen migrering opretter indekser for denne samling.

#### Bemærkninger {#notes}

* GitLabs API kan ikke flytte en gren til en vilkårlig commit, som GitHubs kan. En synkronisering committer direkte på den synkroniserede gren, når den kan gå fremad, ellers på en midlertidig gren, der derefter merges via en merge request (`GitMerge.mjs:16-21`).
* En synkronisering kører under projektets `gitSync`-lås, som deles med GitHub Sync og Gitea Sync (`GitMerge.mjs:25-32`).
* Et slettet projekt beholder sit dokument, indtil projektet udløber.
* Brugerens GitLab-token ligger i [GitLab Sync User Credentials](/da/dev/data-model/gitlab-sync-user-credentials-collection).
