`giteaSyncProjectStates` indeholder ét dokument pr. projekt, der er forbundet med et Gitea-repository: hvilket repository, og hvor den seneste synkronisering slap. Samlingen hører til webmodulet `gitea-sync` (`services/web/modules/gitea-sync`). Skemaet ligger i `services/web/modules/gitea-sync/app/models/giteaSyncProjectStates.mjs`, og al adgang går gennem `services/web/modules/gitea-sync/app/src/SyncStateManager.mjs`. Felterne er de samme som i [GitHub Sync Project States](/da/dev/data-model/github-sync-project-states-collection).

#### Hvem skriver {#who-writes-it}

| Kode | Hvad den gør |
| ---- | ------------ |
| `SyncStateManager.mjs:9-14` (`createProjectState`) | Opretter dokumentet: efter import af et repository som et nyt projekt (`services/web/modules/gitea-sync/app/src/GiteaSyncHandler.mjs:175-181`), eller efter eksport af et projekt til et nyt repository (`GiteaSyncHandler.mjs:233-239`, kun ejeren, afvises hvis det allerede er forbundet). |
| `SyncStateManager.mjs:16-21` (`updateProjectState`) | `$set` af de ændrede felter. `getMergeOverview` sætter `mergeStatus: 'diverged'`, når `lastSyncCommit` ikke længere er en forfader til den synkroniserede gren (`services/web/modules/gitea-sync/app/src/GiteaApiClient.mjs:431`), eller når committen er væk, og brugeren kan pushe (`GiteaSyncHandler.mjs:123,126-137`). En synkronisering (`services/web/modules/gitea-sync/app/src/GitMerge.mjs`) flytter `lastSyncCommit`/`lastSyncVersion`, når den lykkes (for eksempel `:152,189,231`), registrerer en konflikt med `unmergedBranchName`, `unmergedBranchHead` og `conflictVersion` (`:214-220`), og rydder dem, når konflikten er løst (`:257-264`). |
| `SyncStateManager.mjs:23-25` (`removeProjectState`) | Sletter dokumentet, når ejeren afbryder forbindelsen til projektet (`GiteaSyncHandler.mjs:83-97`), og når et slettet projekt udløber (`services/web/modules/gitea-sync/index.mjs:46-48`). |

#### Hvem læser {#who-reads-it}

| Kode | Hvad den gør |
| ---- | ------------ |
| `GiteaSyncHandler.mjs:39-60` (`getProjectState`) | Giver editoren `mergeStatus`, `repoFullName` og `unmergedBranchName`. Uden dokument svarer den `need-export`, en værdi der aldrig gemmes. |
| `GiteaSyncHandler.mjs:110-143` (`getMergeOverview`) | Sammenligner `lastSyncCommit` og `lastSyncVersion` med Gitea og projekthistorikken for at liste de nye commits. |

#### Indekser {#indexes}

| Navn | Nøgler | Indstillinger | Migrering |
| ---- | ---- | ------- | --------- |
| `_id_` | `_id: 1` | | default |

Mongoose `autoIndex` er slået fra (`services/web/app/src/infrastructure/Mongoose.mjs:7`), så skemaets `unique: true` på `projectId` opretter intet. Ingen migrering opretter indekser for denne samling.

#### Bemærkninger {#notes}

* Giteas API kan ikke lave commits uden for en gren, som GitHubs kan. En synkronisering committer direkte på den synkroniserede gren, når den kan gå fremad, ellers på en midlertidig gren, der derefter merges via en pull request (`GitMerge.mjs:16-21`).
* En synkronisering kører under projektets `gitSync`-lås, som deles med GitHub Sync og GitLab Sync (`GitMerge.mjs:25-32`).
* Et slettet projekt beholder sit dokument, indtil projektet udløber.
* Brugerens Gitea-token ligger i [Gitea Sync User Credentials](/da/dev/data-model/gitea-sync-user-credentials-collection).
