---
title: GitLab Sync User Credentials-samlingen
icon: user-lock
---

`gitlabSyncUserCredentials` indeholder ét dokument pr. bruger, der har forbundet en GitLab-konto til GitLab Sync. Den gemmer brugerens OAuth-tokens, krypteret. Samlingen hører til webmodulet `gitlab-sync` (`services/web/modules/gitlab-sync`). Skemaet ligger i `services/web/modules/gitlab-sync/app/models/gitlabSyncUserCredentials.mjs`, og al adgang går gennem `services/web/modules/gitlab-sync/app/src/TokenManager.mjs`.

#### Felter {#fields}

| Felt | Type | Betydning | Kilde |
| ----- | ---- | ------- | ------ |
| `_id` | ObjectId | Sættes af Mongoose, når upserten indsætter. | |
| `userId` | ObjectId | Overleaf-brugeren. Påkrævet. Skemaet siger `unique: true`, men der bygges intet indeks (se Indekser); upserten på `userId` holder ét dokument pr. bruger. | `gitlabSyncUserCredentials.mjs:8`, `TokenManager.mjs:88-95` |
| `gitlab` | String | JSON-værdien `{ accessToken, refreshToken, expiresAt }`, krypteret med `@overleaf/access-token-encryptor`. `expiresAt` er i millisekunder siden epoken, eller `null`; `refreshToken` kan være `null`. Adgangskoden kommer fra `GITLAB_TOKEN_CIPHER_PASSWORD`; chifferetiketten er `GITLAB_TOKEN_CIPHER_LABEL`, standard `2026.10-v3`. Påkrævet. | `gitlabSyncUserCredentials.mjs:9-10`, `TokenManager.mjs:18-31`, `services/web/modules/gitlab-sync/app/src/GitLabApiClient.mjs:209-220` |
| `__v` | Number | Mongoose’ versionsnøgle. Skemaet slår den ikke fra. | Mongoose-standard |

#### Hvem skriver {#who-writes-it}

| Kode | Hvad den gør |
| ---- | ------------ |
| `TokenManager.mjs:88-95` (`saveUserToken`) | Laver upsert af brugerens krypterede loginoplysninger. |
| `TokenManager.mjs:99-108` (`linkUserToken`) | Gemmer nye loginoplysninger fra OAuth-callbacken (`services/web/modules/gitlab-sync/app/src/GitLabSyncController.mjs:146`). Når brugeren forbinder igen, tilbagekaldes det erstattede adgangstoken hos GitLab i baggrunden. |
| `TokenManager.mjs:53-78` (`refreshUserToken`) | Når adgangstokenet har mindre end 5 minutter til `expiresAt` (`:13,47-49`), henter den nye tokens med opdateringstokenet og gemmer dem (`:75`). Den kører under låsen `gitlabSyncToken` pr. bruger (`:15,54`), fordi GitLab bruger et opdateringstoken op, når det bruges. |
| `TokenManager.mjs:111-126` (`removeUserToken`) | Tilbagekalder adgangstokenet hos GitLab (så vidt muligt) og sletter derefter dokumentet. Kaldes ved afbrydelse af forbindelsen (`GitLabSyncController.mjs:173`), og når en slettet bruger udløber (`services/web/modules/gitlab-sync/index.mjs:56-58`). |

#### Hvem læser {#who-reads-it}

| Kode | Hvad den gør |
| ---- | ------------ |
| `TokenManager.mjs:41-45,81-85` (`getUserCredentials`, `getUserToken`) | Dekrypterer loginoplysningerne ved hvert kald til GitLabs API og fornyer dem først, når tokenet snart udløber: `services/web/modules/gitlab-sync/app/src/GitLabSyncHandler.mjs` (for eksempel `:27`) og `services/web/modules/gitlab-sync/app/src/GitMerge.mjs:52`. Uden dokument, eller med loginoplysninger der ikke kan dekrypteres eller fornyes, kaster den `InvalidTokenError`, og brugeren regnes som ikke forbundet (`GitLabSyncHandler.mjs:25-37`). |
| `services/web/modules/admin-tools/app/src/AdminUserListManager.mjs:394` | Tjekker, om brugeren har et dokument, til de integrationer der vises i adminpanelet. |

#### Indekser {#indexes}

| Navn | Nøgler | Indstillinger | Migrering |
| ---- | ---- | ------- | --------- |
| `_id_` | `_id: 1` | | default |

Mongoose `autoIndex` er slået fra (`services/web/app/src/infrastructure/Mongoose.mjs:7`), så skemaets `unique: true` på `userId` opretter intet. Ingen migrering opretter indekser for denne samling.

#### Bemærkninger {#notes}

* Ændres `GITLAB_TOKEN_CIPHER_PASSWORD`, bliver de gemte loginoplysninger ulæselige. Disse brugere regnes så som ikke forbundet, indtil de forbinder igen.
* En slettet bruger beholder dokumentet, indtil brugeren udløber.
