`githubSyncProjectStates` indeholder ét dokument pr. projekt, der er forbundet med et GitHub-repository: hvilket repository, og hvor den seneste synkronisering slap. Samlingen hører til webmodulet `github-sync` (`services/web/modules/github-sync`). Skemaet ligger i `services/web/modules/github-sync/app/models/githubSyncProjectStates.mjs`, og al adgang går gennem `services/web/modules/github-sync/app/src/SyncStateManager.mjs`.

#### Hvem skriver {#who-writes-it}

| Kode | Hvad den gør |
| ---- | ------------ |
| `SyncStateManager.mjs:9-14` (`createProjectState`) | Opretter dokumentet: efter import af et repository som et nyt projekt (`services/web/modules/github-sync/app/src/GitHubSyncHandler.mjs:175-181`), eller efter eksport af et projekt til et nyt repository (`GitHubSyncHandler.mjs:235-241`, kun ejeren, afvises hvis det allerede er forbundet). |
| `SyncStateManager.mjs:16-21` (`updateProjectState`) | `$set` af de ændrede felter. `getMergeOverview` sætter `mergeStatus: 'diverged'`, når den synkroniserede gren ikke længere bygger på `lastSyncCommit`: GitHubs compare svarer `diverged` eller `behind` (`GitHubApiClient.mjs:382-400`), eller committen er væk, og brugeren kan pushe (`GitHubSyncHandler.mjs:123,126-137`). En synkronisering (`services/web/modules/github-sync/app/src/GitMerge.mjs`) flytter `lastSyncCommit`/`lastSyncVersion`, når den lykkes (for eksempel `:143,173,224`), registrerer en konflikt med `unmergedBranchName`, `unmergedBranchHead` og `conflictVersion` (`:207-213`), og rydder dem, når konflikten er løst (`:250-257`). |
| `SyncStateManager.mjs:23-25` (`removeProjectState`) | Sletter dokumentet, når ejeren afbryder forbindelsen til projektet (`GitHubSyncHandler.mjs:83-97`), og når et slettet projekt udløber (`services/web/modules/github-sync/index.mjs:56-58`). |

#### Indekser {#indexes}

| Navn | Nøgler | Indstillinger | Migrering |
| ---- | ---- | ------- | --------- |
| `_id_` | `_id: 1` | | default |

Mongoose `autoIndex` er slået fra (`services/web/app/src/infrastructure/Mongoose.mjs:7`), så skemaets `unique: true` på `projectId` opretter intet. `tools/migrations/20190912145010_create_githubSyncProjectStates_indexes.mjs` (upstreams `project_id` og `owner_id`) er kun mærket `saas` og kører ikke i CE.

#### Bemærkninger {#notes}

* En synkronisering kører under projektets `gitSync`-lås (`GitMerge.mjs:17-24`). GitLab Sync og Gitea Sync tager den samme lås, så der kører kun én synkronisering pr. projekt ad gangen.
* Et slettet projekt beholder sit dokument, indtil projektet udløber.
* Brugerens GitHub-token ligger i [GitHub Sync User Credentials](/da/dev/data-model/github-sync-user-credentials-collection).
