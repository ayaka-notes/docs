---
title: Docs-samlingen
icon: file-lines
---

`docs` indeholder indholdet af et projekts redigerbare tekstfiler (Overleaf kalder dem docs), for eksempel `main.tex` eller `sample.bib`. Ét dokument pr. doc: dets linjer, dets kommentarer og sporede ændringer, to tællere og sletningsstatussen. Filnavnet og placeringen i træet ligger ikke her, men i `projects.rootFolder` (se [Projects-samlingen](/da/dev/data-model/projects-collection)). Binære filer ligger heller ikke her.

Bortset fra migreringer og vedligeholdelsesscripts er det kun docstore, der skriver denne samling, i `services/docstore/app/js/MongoManager.js`. Der er ingen Mongoose-model; web og document-updater tilgår den via docstores HTTP-API (`services/docstore/app.js:31-70`). I kolonnen Kilde ligger rene filnavne under `services/docstore/app/js/`.

#### Felter {#fields}

| Felt | Type | Betydning | Kilde |
| ----- | ---- | ------- | ------ |
| `_id` | ObjectId | Doc-id, det samme som `_id` for doc-posten i `projects.rootFolder`. | `MongoManager.js:142-147` |
| `project_id` | ObjectId | Doc'ets projekt. | `MongoManager.js:144` |
| `lines` | Array of String | Teksten, ét element pr. linje. Mangler, mens doc'et er arkiveret (`inS3: true`). | `DocManager.js:314-316`, `MongoManager.js:203` |
| `ranges` | Object | Kommentarer og sporede ændringer, se nedenfor. Mangler, mens doc'et er arkiveret. | `DocManager.js:317-319`, `RangeManager.js:36-65` |
| `rev` | Number | docstores egen tæller. Starter på 1 og stiger med 1, hver gang `lines` eller `ranges` ændres. Hver opdatering matcher den gamle `rev`, så to skrivere ikke kan overskrive hinanden. Ikke en historikversion. | `MongoManager.js:115-136`, `:145`, `:254-269` |
| `version` | Number | Doc'ets OT-version fra document-updater, gemt ved flush. docstore afviser en flush med en lavere version. Ældre docs havde den i samlingen `docOps`; migreringen `20231105000000_move_doc_versions_from_docops_to_docs` flyttede den hertil. | `DocManager.js:283-290`, `:320-322` |

#### Ranges {#ranges}

`ranges` har to arrays. document-updater bygger dem med `libraries/ranges-tracker/index.cjs`; docstore laver id'er om til ObjectIds og `ts` til Dates før lagring (`RangeManager.js:41-63`). Et doc uden kommentarer eller sporede ændringer har `ranges: {}` eller intet `ranges`.

| Felt | Type | Betydning | Kilde |
| ----- | ---- | ------- | ------ |
| `ranges.comments` | Array of Object | Kommenterede tekstafsnit. | `libraries/ranges-tracker/index.cjs:217-236` |
| `ranges.comments.id` | ObjectId | Kommentar-id. Det er lig med `op.t`, kommentarens tråd-id i samlingen `rooms`; docstore tvinger dem til at stemme overens. | `RangeManager.js:54-57` |
| `ranges.comments.op.c` | String | Den kommenterede tekst i doc'et (ikke kommentarbeskeden). | `index.cjs:226-230` |
| `ranges.comments.op.p` | Number | Tegnpositionen for starten af `op.c` i doc'et. | `index.cjs:226-230` |
| `ranges.comments.op.t` | ObjectId | Tråd-id, se `id`. | `index.cjs:226-230`, `RangeManager.js:57` |
| `ranges.comments.metadata` | Object | Kommentarens `user_id` og `ts`. | `index.cjs:232`, `RangeManager.js:62` |
| `ranges.changes` | Array of Object | Sporede ændringer, sorteret efter position. | `index.cjs:640-660` |
| `ranges.changes.id` | ObjectId | Ændringens id. | `index.cjs:643-647`, `RangeManager.js:51` |
| `ranges.changes.op.i` / `op.d` | String | Indsat tekst eller slettet tekst. Én af de to. | `index.cjs:640-660` |
| `ranges.changes.op.p` | Number | Ændringens tegnposition. | `index.cjs:640-660` |
| `ranges.changes.metadata.user_id` | ObjectId or String | Forfatter. Ændringer fra anonyme redaktører beholder strengen `anonymous-user`. | `RangeManager.js:45-46`, `DocManager.js:192` |
| `ranges.changes.metadata.ts` | Date | Hvornår ændringen blev foretaget. | `RangeManager.js:42-43` |

Teksten i en kommentar og svarene på den ligger ikke i `docs`: den ligger i samlingen `messages`, i det room, hvis `thread_id` er kommentarens id. Om en kommentar er løst, gemmes på det rum, ikke her; docstore kasserer et `resolved`-flag, hvis et sendes (`RangeManager.js:59-61`). Se [Rooms-samlingen](/da/dev/data-model/rooms-collection) og [Messages-samlingen](/da/dev/data-model/messages-collection).

#### Hvem skriver {#who-writes-it}

| Kode | Hvad den gør |
| ---- | ------------ |
| `DocManager.js:223-338` (`POST /project/:project_id/doc/:doc_id`) | Opretter eller opdaterer et doc: `lines`, `ranges` og `version`. Web kalder den, når et doc oprettes, og når document-updater flusher et åbent doc (`services/web/app/src/Features/Project/ProjectEntityUpdateHandler.mjs:174`). |
| `DocManager.js:346-366` (`PATCH /project/:project_id/doc/:doc_id`) | Markerer et doc som slettet med `deleted`, `deletedAt` og `name`. |
| `DocArchiveManager.js:29-88` | Arkiverer et doc: kopierer `lines`, `ranges` og `rev` til persistoren og sætter `inS3`. Kører for et helt projekt, når det deaktiveres, og for ét doc ved sletning, når `ARCHIVE_ON_SOFT_DELETE=true` (`DocManager.js:355-363`). |
| `DocArchiveManager.js:150-174` | Henter et arkiveret doc tilbage til Mongo, når det læses (`DocManager.js:40-41`). |
| `MongoManager.js:272-274` | Sletter alle docs i et projekt, når projektet destrueres. |

| Kode | Hvad den gør |

#### Indekser {#indexes}

Alle kommer fra migreringer mærket `server-ce` i `tools/migrations/`.

| Navn | Nøgler | Indstillinger | Migrering |
| ---- | ---- | ------- | --------- |

| `project_id_1_inS3_1_deleted_1` | `project_id: 1, inS3: 1, deleted: 1` | | `20250321092555_add_deleted_to_project_id_in_s3_index` |

#### Bemærkninger {#notes}

* Mens et doc er åbent, ligger den nyeste tekst i document-updater (Redis), ikke her. Mongo opdateres kun, når document-updater flusher (`services/document-updater/app/js/PersistenceManager.js:128-160`). Kode, der læser docs for et helt projekt, bør først kalde `flushProjectToMongo`, sådan som `ProjectDuplicator` gør.
* Slettede docs bliver liggende i denne samling med `deleted: true`, indtil projektet destrueres. docstore returnerer højst `MAX_DELETED_DOCS` (standard 2000) af dem, nyeste først (`MongoManager.js:29-44`, `services/docstore/config/settings.defaults.cjs:40`). Historikpanelet bruger dem ikke; det læser history-v1.
* Tællerne `rev` og `version` har intet med projektets historikversioner i history-v1 at gøre.
