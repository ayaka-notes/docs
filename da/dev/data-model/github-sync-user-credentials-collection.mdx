---
title: GitHub Sync User Credentials-samlingen
icon: key
---

`githubSyncUserCredentials` indeholder ét dokument pr. bruger, der har forbundet en GitHub-konto til GitHub Sync. Den gemmer brugerens OAuth-adgangstoken, krypteret. Samlingen hører til webmodulet `github-sync` (`services/web/modules/github-sync`). Skemaet ligger i `services/web/modules/github-sync/app/models/githubSyncUserCredentials.mjs`, og al adgang går gennem `services/web/modules/github-sync/app/src/TokenManager.mjs`.

#### Felter {#fields}

| Felt | Type | Betydning | Kilde |
| ----- | ---- | ------- | ------ |
| `_id` | ObjectId | Sættes af Mongoose, når upserten indsætter. | |
| `userId` | ObjectId | Overleaf-brugeren. Påkrævet. Skemaet siger `unique: true`, men der bygges intet indeks (se Indekser); upserten på `userId` holder ét dokument pr. bruger. | `githubSyncUserCredentials.mjs:8`, `TokenManager.mjs:44-48` |
| `github` | String | GitHubs OAuth-adgangstoken, krypteret med `@overleaf/access-token-encryptor`. Adgangskoden kommer fra `GITHUB_TOKEN_CIPHER_PASSWORD`; chifferetiketten er `GITHUB_TOKEN_CIPHER_LABEL`, standard `2026.3-v3`. Påkrævet. | `githubSyncUserCredentials.mjs:9`, `TokenManager.mjs:12-25` |
| `__v` | Number | Mongoose’ versionsnøgle. Skemaet slår den ikke fra. | Mongoose-standard |

Kun adgangstokenet gemmes: OAuth-callbacken beholder `access_token` fra GitHubs svar (`services/web/modules/github-sync/app/src/GitHubApiClient.mjs:180-191`). Der er ingen opdateringstoken eller udløbstid.

#### Hvem skriver {#who-writes-it}

| Kode | Hvad den gør |
| ---- | ------------ |
| `TokenManager.mjs:42-58` (`saveUserToken`) | Laver upsert af brugerens krypterede token. Når brugeren forbinder igen, tilbagekaldes det erstattede token hos GitHub i baggrunden. Kaldes fra OAuth-callbacken (`services/web/modules/github-sync/app/src/GitHubSyncController.mjs:146`). |
| `TokenManager.mjs:61-76` (`removeUserToken`) | Tilbagekalder tokenet hos GitHub (så vidt muligt) og sletter derefter dokumentet. Kaldes ved afbrydelse af forbindelsen (`GitHubSyncController.mjs:167`), og når en slettet bruger udløber (`services/web/modules/github-sync/index.mjs:66-68`). |

#### Hvem læser {#who-reads-it}

| Kode | Hvad den gør |
| ---- | ------------ |
| `TokenManager.mjs:36-40` (`getUserToken`) | Dekrypterer tokenet ved hvert kald til GitHubs API: `services/web/modules/github-sync/app/src/GitHubSyncHandler.mjs` (for eksempel `:27`) og `services/web/modules/github-sync/app/src/GitMerge.mjs:43`. Uden dokument, eller med et token der ikke kan dekrypteres, kaster den `InvalidTokenError`, og brugeren regnes som ikke forbundet (`GitHubSyncHandler.mjs:25-37`). |
| `services/web/modules/admin-tools/app/src/AdminUserListManager.mjs:393` | Tjekker, om brugeren har et dokument, til de integrationer der vises i adminpanelet. |

#### Indekser {#indexes}

| Navn | Nøgler | Indstillinger | Migrering |
| ---- | ---- | ------- | --------- |
| `_id_` | `_id: 1` | | default |

Mongoose `autoIndex` er slået fra (`services/web/app/src/infrastructure/Mongoose.mjs:7`), så skemaets `unique: true` på `userId` opretter intet. `tools/migrations/20190912145011_create_githubSyncUserCredentials_indexes.mjs` (upstreams `user_id`) er kun mærket `saas` og kører ikke i CE.

#### Bemærkninger {#notes}

* Ændres `GITHUB_TOKEN_CIPHER_PASSWORD`, bliver de gemte tokens ulæselige. Disse brugere regnes så som ikke forbundet, indtil de forbinder igen.
* En slettet bruger beholder dokumentet, indtil brugeren udløber.
