Arbejd på et projekt på din egen computer med Git. Ændringer overføres kun, når du kører `git pull` eller `git push`.

<Info>

En administrator skal først slå [Git-integrationen](/da/on-premises/configuration/overleaf-toolkit/integrations/git-integration) til.

</Info>

## Opret et token {#create-a-token}

Git logger ind med et Git-godkendelsestoken, ikke med adgangskoden til din konto.

<Steps>
<Step title="Åbn dine kontoindstillinger">
Klik på **Account** og derefter på **Account settings**. Under **Git integration** klikker du på **Generate token**. Når du har et token, hedder knappen **Add another token**.

<Frame caption="Git-integration i kontoindstillingerne">
  <img src="/images/on-premises/git-integration-settings.png" alt="Afsnittet Git integration i kontoindstillingerne med knappen Generate token" />
</Frame>
</Step>

<Step title="Kopiér tokenet">
Klik på **Copy**, og opbevar tokenet et sikkert sted. Du ser det kun én gang. Klik derefter på **Close**.

<Frame caption="Dit nye token">
  <img src="/images/on-premises/git-integration-token.png" alt="Dialogboksen for Git-godkendelsestoken med knappen Copy" />
</Frame>
</Step>

<Step title="Kontrollér tokenet">
Listen viser nu starten af tokenet, hvornår det blev oprettet, og hvornår det sidst blev brugt. Det udløber efter et år. Du kan have op til 10 tokens.

<Frame caption="Dine tokens">
  <img src="/images/on-premises/git-integration-tokens.png" alt="Listen over tokens med ét token" />
</Frame>
</Step>
</Steps>

## Klon et projekt {#clone-a-project}

<Steps>
<Step title="Åbn Git-integrationen i editoren">
Åbn projektet. Klik på **Integrations** i venstre bjælke og derefter på **Git integration**.

<Frame caption="Panelet Integrations">
  <img src="/images/on-premises/git-integration-panel.png" alt="Panelet Integrations med kortet Git integration" />
</Frame>
</Step>

<Step title="Kopiér kommandoen">
Dialogboksen **Clone with Git** viser kommandoen med adressen på dit websted og projektets ID. Klik på **Copy**. Hvis du endnu ikke har et token, åbner **Go to settings** dine kontoindstillinger i en ny fane.

<Frame caption="Klonkommandoen">
  <img src="/images/on-premises/git-integration-clone.png" alt="Dialogboksen Clone with Git med kommandoen git clone" />
</Frame>
</Step>

<Step title="Kør den">
Indsæt kommandoen i en terminal. Når Git beder om en adgangskode, indsætter du dit token.

```text
$ git clone https://git@<your-site>/git/<project-id>
Cloning into '<project-id>'...
Password for 'https://git@<your-site>': <your-token>
```

En mappe med projekt-ID'et som navn indeholder nu projektets filer på grenen `main`. Hvis du vil vælge mappens navn, tilføjer du det i slutningen af kommandoen.
</Step>
</Steps>

Git beder om tokenet, hver gang det kontakter webstedet. For at få det husket slår du en credential helper til: Git spørger én gang til og gemmer derefter tokenet. Helperen `store` gemmer det ukrypteret i `~/.git-credentials`.

```bash
git config --global credential.helper store
```

## Hent ændringer fra editoren {#pull-changes-from-the-editor}

Kør følgende i mappen:

```bash
git pull
```

Git viser de filer, der er ændret. Ændringer foretaget i editoren kommer som commits med navnet `Update on Overleaf.`.

```text
Updating db007e3..c3e6332
Fast-forward
 main.tex | 2 +-
 1 file changed, 1 insertion(+), 1 deletion(-)
```

## Send dine ændringer {#push-your-changes}

Lav et commit af dine ændringer, og send dem derefter:

```bash
git add main.tex
git commit -m "Add a line from Git"
git push
```

Den sidste linje i outputtet viser den gren, der blev flyttet:

```text
   53aca61..db007e3  main -> main
```

Ændringerne vises i editoren, og en åben editor opdaterer sig selv. Nye filer, mapper og omdøbninger vises i filtræet. I **History** er din ændring markeret <strong>You (via Git)</strong>. Din commit-besked vises ikke der.

### Hvis Git afviser din push {#if-git-refuses-your-push}

Hvis projektet er ændret i mellemtiden, afviser Git din push:

```text
 ! [rejected]        main -> main (fetch first)
```

Hent først disse ændringer, og send derefter igen:

```bash
git pull --no-rebase --no-edit
git push
```

En almindelig `git pull` kan stoppe med `fatal: Need to specify how to reconcile divergent branches.` Indstillingen `--no-rebase` ovenfor løser det: den fletter begge sider.

Hvis de samme linjer er ændret på begge sider, stopper pull med `CONFLICT (content): Merge conflict in main.tex`. Ret filen, og kør derefter:

```bash
git add main.tex
git commit -m "Merge the changes from the editor"
git push
```

Der er to ting, webstedet ikke accepterer:

* Andre grene: `! [remote rejected] feature -> feature (wrong branch)`. Kun `main` findes, så send dit arbejde dertil.
* Tvungen push: `! [remote rejected] main -> main (forced push prohibited)`. Læg i stedet dine ændringer oven på den aktuelle `main`.

### Hvis Git siger Authentication failed {#if-git-says-authentication-failed}

```text
remote: Enter your Git authentication token when prompted for a password.
fatal: Authentication failed for 'https://<your-site>/git/<project-id>/'
```

Tokenet er forkert eller slettet, eller du indtastede adgangskoden til din konto. Opret et nyt token, hvis du ikke længere har det, for du kan ikke se et eksisterende token igen.

## Slet et token {#delete-a-token}

I **Account settings**, under **Git integration**, klikker du på sletteikonet ud for tokenet og derefter på **Delete** i dialogboksen. Fra da af svarer Git `Authentication failed` på det token.
