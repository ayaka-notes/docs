<Info>

Denne funktionalitet leveres af [ayaka-notes/ayakaleaf-pro](https://github.com/ayaka-notes/ayakaleaf-pro) med understøttelse af OAuth 2.0 og er tilgængelig fra v6.3.0. Vi tager gerne imod din feedback, hvis du støder på problemer.

</Info>

#### Opsætning af Mendeley-integration

1. Gå til [dette link](https://dev.mendeley.com/myapps.html) for at registrere en Mendeley OAuth-applikation
2. Konfigurer **Redirect URL** som: `${OVERLEAF_SITE_URL}/user/mendeley/oauth/callback`
3. Noter det genererede **ID** (normalt et tal som `24061`, som vist nedenfor) og **Secret** for din applikation
4. Rediger din `config/variables.env`&#x20;
5. Behold blot Authorisation Flow: Elsevier (som anbefalet)

```dotenv title="config/variables.env"
#################
#   Mendeley    #
#################
# 'mendeley' must be in ENABLED_LINKED_FILE_TYPES (keep 'zotero' too if you use both)
ENABLED_LINKED_FILE_TYPES=project_file,project_output_file,url,mendeley

# From a Mendeley OAuth application (register at https://dev.mendeley.com/myapps.html)
# Redirect URL -> ${OVERLEAF_SITE_URL}/user/mendeley/oauth/callback
MENDELEY_CLIENT_ID=
MENDELEY_CLIENT_SECRET=
# Encrypts the Mendeley OAuth tokens in mongo; if unset, a key file is generated
# in /var/lib/overleaf/data on first use
# How to generate: `openssl rand -hex 32`
MENDELEY_CIPHER_PASSWORD=
# Optional: route the module's server-side Mendeley requests (OAuth + API) through
# an HTTP proxy (must be reachable from the web container; same as github-sync)
# http://10.0.0.1:10808
# (Optional) MENDELEY_PROXY_URL=
```

<Info>

&#x20;`mendeley` skal være inkluderet i `ENABLED_LINKED_FILE_TYPES` (behold også `zotero` på listen, hvis du bruger begge). `MENDELEY_CLIENT_ID` og `MENDELEY_CLIENT_SECRET` kommer fra din registrerede OAuth-applikation. Cipher-adgangskoden krypterer Mendeley OAuth-tokens i MongoDB (generer en via `openssl rand -hex 32`); uden den genereres en nøglefil i datavolumen ved første brug. Du kan eventuelt angive `MENDELEY_PROXY_URL` for at route Mendeley-anmodningerne på serversiden (OAuth + API) gennem en HTTP-proxy, der er tilgængelig fra web-containeren.

</Info>

### Bemærkninger

<Warning>

Når du opgraderer en eksisterende installation med bibliografifiler, der er linket til Mendeley, til den genudgivne 6.3.0, skal du følge [migreringsvejledningen for Zotero / Mendeley](/da/on-premises/release-notes/release-notes-6.x.x#ayakaleaf-pro-6.3.0  "mention"). Nye installationer behøver ikke denne migrering.

</Warning>

<Danger>

Da Ayakaleaf er en samarbejdsplatform, er det for at forbedre sikkerheden fra og med version 6.3.0 kun den oprindelige opretter af en reference-`bib`-fil, der har tilladelse til at opdatere den importerede fil.

</Danger>

Antag for eksempel, at projektejeren, bruger A, aktiverer linkdeling og opretter en `test.bib`-fil i projektet, som er linket til vedkommendes egen Zotero-konto. Hvis en anden bruger, bruger B, får adgang til projektet via det delte link, vil bruger B stadig kunne læse og downloade `test.bib`, men vil ikke have tilladelse til at opdatere eller genimportere filen fra Zotero. Kun bruger A, som den oprindelige opretter af referencefilen, kan foretage opdateringer. Med andre ord har kun den oprindelige opretter af `.bib`-filen tilladelse til at opdatere den.
