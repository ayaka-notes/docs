### Opsætning af GitHub-synkronisering

<Warning>

Du skal først aktivere [git-bridge](/da/on-premises/configuration/overleaf-toolkit/git-integration), før du kan bruge GitHub-synkronisering.

```dotenv title="config/overleaf.rc"
GIT_BRIDGE_ENABLED=true
```

</Warning>

Gå til [udviklerindstillinger](https://github.com/settings/developers) for at oprette din GitHub OAuth-applikation, og kopiér dit `CLIENT_ID` og din `SECRET`.

**Bemærk**: Din OAuth-callback-URL er: `${OVERLEAF_SITE_URL}/user/github-sync/oauth2/callback`.

Tilføj derefter følgende indstillinger til dine Overleaf-miljøvariabelfiler.

```dotenv title="config/variables.env" wrap
# used to encrypt the user's GitHub access token.
# How to generate: `openssl rand -hex 32`
GITHUB_TOKEN_CIPHER_PASSWORD=0123456789ABCDEFG # changed to yours

# Github Sync Settings
GITHUB_SYNC_ENABLED=true
GITHUB_SYNC_CLIENT_ID=
GITHUB_SYNC_CLIENT_SECRET=

# OAuth callback is: ${OVERLEAF_SITE_URL}/user/github-sync/oauth2/callback
# (Optional) GITHUB_SYNC_PROXY_URL=http://10.0.0.1:10808
```

<Warning>

Før du konfigurerer GitHub OAuth-callback-URL'en, skal du sikre dig, at `OVERLEAF_SITE_URL` er sat korrekt.

</Warning>

Hvis du befinder dig i en region med begrænset netværksadgang, kan det være nødvendigt at konfigurere en proxy for at få adgang til GitHub. Sæt følgende miljøvariabel: `GITHUB_SYNC_PROXY_URL=http://10.0.0.1:10808`. Sørg for, at din brug af en proxy overholder lokale love og regler.

<Warning>

`GITHUB_SYNC_PROXY_URL` skal være en almindelig HTTP/HTTPS-videresendelsesproxy (f.eks. HTTP-porten i Clash). GitHub-downloadspejle som `gh-proxy.org` understøttes ikke.

</Warning>

<Warning>

Brug ikke `127.0.0.1` som proxyvært. Hvis proxyen kører på værtsserveren, skal du bruge serverens LAN-IP-adresse (f.eks. `192.168.1.xx`) og sikre dig, at proxyen er konfigureret til at acceptere forbindelser fra enheder på det lokale netværk.

</Warning>

### GitHub Enterprise

<Info>

Understøttelse af GitHub Enterprise er introduceret i v6.3.1 og senere. Tidligere versioner forbinder kun til `github.com`, og variablerne nedenfor har ingen effekt.

</Info>

Som standard forbinder GitHub-synkronisering til `github.com`. For at bruge GitHub Enterprise Server (selvhostet) eller GitHub Enterprise Cloud med dataresidens (`GHE.com`) skal du sætte `GITHUB_SYNC_URL` til webadressen for din instans, den adresse du åbner repositories med i browseren.

```dotenv title="config/variables.env" wrap
# GitHub Enterprise Server
GITHUB_SYNC_URL=https://github.example.com

# or GitHub Enterprise Cloud with data residency
# GITHUB_SYNC_URL=https://octocorp.ghe.com
```

REST- og GraphQL-API-endpoints udledes af `GITHUB_SYNC_URL` på samme måde, som GitHub CLI gør det:

| `GITHUB_SYNC_URL`             | REST API                         | GraphQL API                              |
| ----------------------------- | -------------------------------- | ---------------------------------------- |
| `https://github.com` (standard) | `https://api.github.com`         | `https://api.github.com/graphql`         |
| `https://SUBDOMAIN.ghe.com`   | `https://api.SUBDOMAIN.ghe.com`  | `https://api.SUBDOMAIN.ghe.com/graphql`  |
| `https://HOST` (alle andre)   | `https://HOST/api/v3`            | `https://HOST/api/graphql`               |

Sæt kun API-endpoints, hvis din instans udstiller dem et andet sted, for eksempel bag en API-gateway:

| Variabel                  | Standard                                                                                  |
| ------------------------- | ----------------------------------------------------------------------------------------- |
| `GITHUB_SYNC_URL`         | `https://github.com`                                                                      |
| `GITHUB_SYNC_API_URL`     | Udledes af `GITHUB_SYNC_URL`, se tabellen ovenfor                                         |
| `GITHUB_SYNC_GRAPHQL_URL` | Udledes af `GITHUB_SYNC_API_URL`, når den er sat (`/api/v3` bliver til `/api/graphql`, ellers tilføjes `/graphql`), ellers af `GITHUB_SYNC_URL` |

<Warning>

* Opret OAuth-applikationen på din enterprise-instans (_Settings → Developer settings → OAuth Apps_). En applikation fra `github.com` virker ikke der. Callback-URL'en er den samme: `${OVERLEAF_SITE_URL}/user/github-sync/oauth2/callback`.
* `GITHUB_SYNC_URL` er kun webadressen. Sæt den ikke til en API-adresse som `https://api.github.com` eller `https://HOST/api/v3`, og tilføj ikke en organisationssti.
* Alle tre adresser skal pege på den samme GitHub-instans.

</Warning>

<Info>

Hvis din instans bruger et certifikat fra en privat CA, skal du montere CA-certifikatet i containeren og pege `NODE_EXTRA_CA_CERTS` på det, f.eks. `NODE_EXTRA_CA_CERTS=/var/lib/overleaf/certs/github-ca.pem`.

</Info>

<Danger>

Forbundne konti og projekter hører til den instans, de blev forbundet med. Før du skifter `GITHUB_SYNC_URL` til en anden instans, skal du bede brugerne om at fjerne forbindelsen til deres GitHub-konto og projekter.

</Danger>

### Hvem kan forbinde og synkronisere

Ligesom på Overleaf Cloud kan kun projektejeren forbinde et projekt med et GitHub-repository. Når det er forbundet, kan alle samarbejdspartnere med redigeringsadgang synkronisere det.

| Handling                                                   | Hvem kan gøre det                                              |
| ---------------------------------------------------------- | -------------------------------------------------------------- |
| Eksportere et projekt til et nyt GitHub-repository         | Projektejeren                                                  |
| Importere et GitHub-repository til et nyt projekt          | Enhver bruger, som bliver ejer af det nye projekt              |
| Pull, push og merge af et forbundet projekt                | Ejeren og samarbejdspartnere med redigeringsadgang             |
| Fjerne forbindelsen mellem et projekt og dets repository   | Projektejeren                                                  |

* Overleaf kommunikerer med GitHub via GitHub-kontoen for den bruger, der synkroniserer, så alle samarbejdspartnere, der synkroniserer, forbinder deres egen GitHub-konto og skal have tilladelse til at pushe til repositoryets standardbranch.
* Samarbejdspartnere med kun læseadgang kan ikke bruge GitHub-synkronisering for projektet.

### Q\&A

<Accordion title="Kan jeg force-pushe til standardbranchen?">

<strong>Svar:</strong> Det anbefaler vi ikke. Overleaf registrerer et force push, advarer om det og overtager den omskrevne branch, hvorefter ændringerne foretaget i Overleaf siden sidste synkronisering merges. For at undgå overraskelser bør du beskytte standardbranchen mod force push i repositoryets indstillinger.

</Accordion>

<Accordion title="Kan jeg omdøbe standardbranchen i et forbundet projekt?">

<strong>Svar:</strong> Lad venligst være. Overleaf fortsætter med at synkronisere med den branch, projektet blev forbundet med. For at synkronisere med en anden branch skal du fjerne forbindelsen til projektet og derefter importere repositoryet i et nyt projekt, som bruger den aktuelle standardbranch.

</Accordion>
