### Overleaf i18-konfiguration

<Info>

Dette dokument beskriver, hvordan du konfigurerer internationalisering (i18n) for en selvhostet **Overleaf**-instans.

</Info>

Overleaf er oversat til flere sprog. Med den rette konfiguration kan du:

* Køre din Overleaf-instans på **ét fast sprog**, eller
* Aktivere **flere sprog**, så brugerne kan skifte sprog dynamisk, ligesom på `www.overleaf.com`.

***

#### Konfiguration med ét sprog

Sitets sprog konfigureres med miljøvariablen `OVERLEAF_SITE_LANGUAGE`(eller `SHARELATEX_SITE_LANGUAGE` for Overleaf-versioner **4.x og tidligere**).

Understøttede sprogkoder omfatter:

* `en` - Engelsk (standard)
* `es` - Spansk
* `pt` - Portugisisk
* `de` - Tysk
* `fr` - Fransk
* `cs` - Tjekkisk
* `nl` - Nederlandsk
* `sv` - Svensk
* `it` - Italiensk
* `tr` - Tyrkisk
* `zh-CN` - Kinesisk (forenklet)
* `no` - Norsk
* `da` - Dansk
* `ru` - Russisk
* `ko` - Koreansk
* `ja` - Japansk
* `pl` - Polsk
* `fi` - Finsk

Engelsk er standardsproget. For at ændre brugerfladens sprog (for eksempel til forenklet kinesisk) skal du tilføje følgende linje til `config/variables.env`:

```bash title="config/variables.env"
OVERLEAF_SITE_LANGUAGE=zh-CN
```

Anvend derefter konfigurationen:

```bash
bin/up
```

Når tjenesterne er genstartet, bør sproget i webbrugerfladens menuer afspejle den nye indstilling.

#### Konfiguration med flere sprog

For at give brugerne mulighed for at **skifte sprog uden at blive logget ud** skal din Overleaf-instans være konfigureret til at levere forskellige sprog baseret på domænenavne.

Dette afsnit forudsætter:

* Dit primære domæne er `overleaftest.com`
* Du har et **wildcard-TLS-certifikat** (f.eks. `*.overleaftest.com`)
* Du **bruger ikke `localhost`** (da det ikke understøtter sprogrouting baseret på underdomæner)

Til lokal test kan du bruge et domæne som `dev-overleaf.com`.

<Steps>
<Step title="TLS-proxykonfiguration (Nginx)">
Din TLS-reverse proxy skal videresende den oprindelige `Host`-header, så Overleaf kan afgøre, hvilket sprogdomæne brugeren har tilgået.

Sørg for, at følgende direktiv er til stede:

```nginx
proxy_set_header Host $host;
```

Her er et eksempel på en Nginx-konfiguration:

```nginx
server {
    listen 443 ssl;
    server_name    _; # Catch all, see http://nginx.org/en/docs/http/server_names.html
    server_name *.overleaftest.com;
    ssl_certificate /etc/nginx/ssl/nginx.crt;
    ssl_certificate_key /etc/nginx/ssl/nginx.key;
    ssl_protocols               TLSv1 TLSv1.1 TLSv1.2;
    ssl_prefer_server_ciphers   on;
    # used cloudflares ciphers https://github.com/cloudflare/sslconfig/blob/master/conf
    ssl_ciphers EECDH+CHACHA20:EECDH+AES128:RSA+AES128:EECDH+AES256:RSA+AES256:EECDH+3DES:RSA+3DES:!MD5;

    # config to enable HSTS(HTTP Strict Transport Security) https://developer.mozilla.org/en-US/docs/Security/HTTP_Strict_Transport_Security
    # to avoid ssl stripping https://en.wikipedia.org/wiki/SSL_stripping#SSL_stripping	
    add_header Strict-Transport-Security "max-age=31536000; includeSubdomains;";
    server_tokens off;
    add_header X-Frame-Options SAMEORIGIN;
    add_header X-Content-Type-Options nosniff;
    client_max_body_size 50M;

    location / {
        proxy_pass http://localhost:5000; # change to whatever host/port the docker container is listening on.
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_read_timeout 3m;
        proxy_send_timeout 3m;
        
        # add this to your nginx conf
        proxy_set_header Host $host;
    }
}
```
</Step>

<Step title="Konfigurer cookie-domæne">
For at forhindre, at brugere bliver logget ud, når de skifter sprog, skal cookies deles på tværs af sprogunderdomænerne.

Tilføj følgende linje til `config/variables.env`:

```env title="config/variables.env"
# Note the leading dot
COOKIE_DOMAIN=.overleaftest.com
```

Det sikrer, at godkendelsescookies er gyldige for alle underdomæner under `overleaftest.com`.
</Step>

<Step title="Tilknytning mellem sprog og domæne">
Definer derefter, hvordan sprogkoder tilknyttes underdomæner, med\
`OVERLEAF_LANG_DOMAIN_MAPPING`.

#### Eksempel på konfiguration

```dotenv title="config/variables.env" wrap
OVERLEAF_LANG_DOMAIN_MAPPING='{"www": {"lngCode": "en","url": "https:\/\/www.overleaftest.com"},"cn": {"lngCode": "zh-CN","url": "https:\/\/cn.overleaftest.com"}}'
```

Med denne konfiguration:

* `https://www.overleaftest.com` → engelsk brugerflade
* `https://cn.overleaftest.com` → brugerflade på forenklet kinesisk

Du kan udvide denne tilknytning med flere sprog og underdomæner efter behov.
</Step>

<Step title="Omdiriger apex-domænet">
Til sidst skal du omdirigere apex-domænet (`overleaftest.com`) til standardsprogdomænet (`www.overleaftest.com`).

```nginx
server{
    listen 80;
    server_name overleaftest.com;
    return 301 https://www.overleaftest.com$request_uri;
}

server {
    listen 443 ssl http2;
    server_name overleaftest.com;
    ssl_certificate     /path/to/fullchain.cer;
    ssl_certificate_key /path/to/overleaftest.com.key;
    return 301 https://www.overleaftest.com$request_uri;
}
```
</Step>
</Steps>
