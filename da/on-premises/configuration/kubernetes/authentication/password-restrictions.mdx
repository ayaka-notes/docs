**web**-tjenesten kontrollerer lokale adgangskoder, når brugere registrerer sig, angiver eller ændrer en adgangskode. SSO-login (LDAP, SAML, OIDC) påvirkes ikke; deres adgangskoder er identitetsudbyderens anliggende. Se [Adgangskodekrav](/da/on-premises/configuration/overleaf-toolkit/authentication/password-restrictions) for Toolkit.

| | |
| --- | --- |
| Tjeneste | web, i hver Ayakaleaf Pro-pod; læses, når web starter |
| Netværk | intet |
| Periodiske job | ingen |

### Konfiguration

Tilføj til ConfigMap'en `overleaf-env`, og genstart:

```yaml title="30-config.yaml (additions)"
  OVERLEAF_PASSWORD_VALIDATION_MIN_LENGTH: "12"
  OVERLEAF_PASSWORD_VALIDATION_MAX_LENGTH: "72"
```

```bash
kubectl apply -f 30-config.yaml
kubectl -n overleaf rollout restart deployment/overleaf     # or statefulset/overleaf
```

| Variabel | Standard | |
| --- | --- | --- |
| `OVERLEAF_PASSWORD_VALIDATION_MIN_LENGTH` | `8` | Korteste accepterede adgangskode. |
| `OVERLEAF_PASSWORD_VALIDATION_MAX_LENGTH` | `72` | Længste accepterede adgangskode; værdier over `72` behandles som `72`. |

Sæt anførselstegn om tallene: en ConfigMap indeholder kun strenge.

<Warning>

`OVERLEAF_PASSWORD_VALIDATION_PATTERN` læses, men håndhæves ikke: en adgangskode, der ikke matcher det, accepteres. Kun længdegrænserne gælder.

</Warning>

### Testet på Kubernetes

På Kubernetes 1.37 med én replika, `OVERLEAF_PASSWORD_VALIDATION_MIN_LENGTH: "12"` og `OVERLEAF_PASSWORD_VALIDATION_PATTERN: aA$3` i ConfigMap'en afviste aktiveringen af en ny konto en adgangskode på 10 tegn og accepterede en adgangskode på 20 tegn udelukkende med små bogstaver, som mønsteret ville have afvist. Vores end-to-end-test for registrering afviser også `123456` som for kort med standardværdierne.
