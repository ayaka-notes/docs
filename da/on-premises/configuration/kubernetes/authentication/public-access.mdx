Gæsteadgang til delte projekter, offentlige sider og selvregistrering slås til med miljøvariabler, som **web**-tjenesten læser; real-time-tjenesten betjener derefter gæster via deres session. Hvad hver indstilling åbner for, er beskrevet i [Offentlig adgang](/da/on-premises/configuration/overleaf-toolkit/authentication/public-access).

| | |
| --- | --- |
| Tjeneste | web (og real-time for gæster i editoren), i hver Ayakaleaf Pro-pod; læses, når web starter |
| Pod → omverdenen | SMTP-serveren, når registrering sender aktiverings-e-mails |
| Tilstand | gæsteadgangstokens i sessionen, hastighedsbegrænsninger for registrering i Redis |
| Periodiske job | ingen |

### Konfiguration

Tilføj de indstillinger, du har brug for, til ConfigMap'en `overleaf-env`:

```yaml title="30-config.yaml (additions)"
  # Guests open link-shared projects without an account
  OVERLEAF_ALLOW_ANONYMOUS_READ_AND_WRITE_SHARING: "true"
  # Signed-out visitors may open /learn, /templates, /devs and view links
  OVERLEAF_ALLOW_PUBLIC_ACCESS: "true"
  # Self-registration: "true", or only some domains
  OVERLEAF_ALLOW_PUBLIC_REGISTRATION: "@example.com, @*.uni.example"
```

```bash
kubectl apply -f 30-config.yaml
kubectl -n overleaf rollout restart deployment/overleaf     # or statefulset/overleaf
```

Sæt anførselstegn om alle værdier. Værdier, der starter med `@`, skal have anførselstegn i YAML, ellers afviser `kubectl apply` filen.

Registrering begrænset til domæner sender en aktiverings-e-mail, så [Levering af e-mail](/da/on-premises/configuration/kubernetes/email-delivery) skal fungere fra podsene: læg SMTP-værten i ConfigMap'en og `OVERLEAF_EMAIL_SMTP_PASS` i Secret'en.

### Flere replikaer

Intet ekstra. En gæsts adgang til et projekt gemmes i sessionen i Redis, så editoren virker på den replika, som load balanceren vælger.

### Testet på Kubernetes

På Kubernetes 1.37 består vores end-to-end-test for offentlig adgang: på én replika selvregistrering med `OVERLEAF_ALLOW_PUBLIC_REGISTRATION` sat til `true`, til ét domæne, til flere domæner med et subdomæne-wildcard og til `@*`, med aktiverings-e-mailen for domænetilstandene (43 tilfælde); besøgende, der ikke er logget ind, på `/devs` og et indsendt kodestykke, der bevares gennem login med `OVERLEAF_ALLOW_PUBLIC_ACCESS` (2 tilfælde); en gæst, der ikke er logget ind, i et linkdelt projekt med begge indstillinger slået til (3 tilfælde); og på tre replikaer bag HAProxy OIDC sammen med offentlig adgang (1 tilfælde).
