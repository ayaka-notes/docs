**web**-tjenesten vælger brugerfladens sprog ud fra indstillingerne nedenfor, pr. forespørgsel ud fra det værtsnavn, browseren brugte. Sprogene og indstillingerne er beskrevet under [Lokalisering](/da/on-premises/configuration/overleaf-toolkit/localization).

| | |
| --- | --- |
| Tjeneste | web, i hver Ayakaleaf Pro-pod; læses, når web starter |
| Netværk | ét værtsnavn pr. sprog, alle routet til Ayakaleaf Pro |
| Periodiske job | ingen |

### Ét sprog

```yaml
  OVERLEAF_SITE_LANGUAGE: zh-CN
```

```bash
kubectl apply -f 30-config.yaml
kubectl -n overleaf rollout restart deployment/overleaf     # or statefulset/overleaf
```

### Flere sprog på subdomæner

<Steps>
<Step title="Route alle sprogværter til Ayakaleaf Pro">
Tilføj et DNS-navn pr. sprog, og route dem alle til Ayakaleaf Pro med et certifikat, der dækker dem, for eksempel `*.example.com`. Din ingress eller load balancer skal videregive `Host`-headeren uændret, hvilket ingress-nginx og HAProxy gør som standard.

Brugerne skal nå sprogværterne på standardportene (`https://cn.example.com`, ikke `https://cn.example.com:30443`): Ayakaleaf Pro sammenligner værten uden porten.
</Step>

<Step title="ConfigMap">
```yaml title="30-config.yaml (additions)" wrap
  OVERLEAF_SITE_URL: https://www.example.com
  COOKIE_DOMAIN: .example.com
  OVERLEAF_LANG_DOMAIN_MAPPING: '{"www": {"lngCode": "en", "url": "https://www.example.com"}, "cn": {"lngCode": "zh-CN", "url": "https://cn.example.com"}}'
```

`COOKIE_DOMAIN` får login-cookien til at virke på alle sprogværter. Sæt JSON'en i enkelte anførselstegn. Ugyldig JSON i `OVERLEAF_LANG_DOMAIN_MAPPING` stopper alle podens tjenester ved opstart, så kontrollér `kubectl -n overleaf get pod` efter genstarten.
</Step>
</Steps>

### Flere replikaer

Sproget kommer fra værtsnavnet i hver forespørgsel, så det afhænger ikke af replikaen. Load balancerens sticky cookie sættes pr. værtsnavn, medmindre du giver den et domæne, så et sprogskift kan flytte en bruger til en anden replika; brugerens session ligger i Redis og forbliver gyldig.

### Testet på Kubernetes

På Kubernetes 1.37 bag HAProxy, med `OVERLEAF_LANG_DOMAIN_MAPPING`, der mappede webstedets vært til engelsk, en `de.`-vært til tysk og en `fr.`-vært med NodePort `:30081` til fransk: webstedets vært viste engelsk, `de.`-værten tysk, og `fr.`-værten med porten faldt tilbage til engelsk, som beskrevet ovenfor.
