Hvert projekts MCP-server kører i **web**-tjenesten (modulet `mcp-server`) i hver Ayakaleaf Pro-pod. Den følger med [Git-integrationen](/da/on-premises/configuration/kubernetes/integrations/git-integration) og har ingen egen indstilling. Hvordan du forbinder Claude Code, Codex og andre klienter, er beskrevet under [MCP-server](/da/on-premises/configuration/overleaf-toolkit/integrations/mcp-server).

| | |
| --- | --- |
| Tjeneste | web, i hver Ayakaleaf Pro-pod |
| Slås til med | `GIT_BRIDGE_ENABLED: "true"` og git-bridge-StatefulSet'et, se [Git-integration](/da/on-premises/configuration/kubernetes/integrations/git-integration) |
| Udefra → Overleaf | AI-klienter sender `POST ${OVERLEAF_SITE_URL}/project/<id>/mcp` med et Git-godkendelsestoken; PDF-downloadlinks under `${OVERLEAF_SITE_URL}/project/<id>/mcp/download/` |
| Pod → udefra | ingen |
| Tilstand | ingen mellem forespørgsler; kompileringsoutput forbliver på den pod, der kompilerede |
| Periodiske job | ingen |

### Konfiguration

Opsæt [Git-integrationen](/da/on-premises/configuration/kubernetes/integrations/git-integration). MCP-serveren findes derefter på `${OVERLEAF_SITE_URL}/project/<project id>/mcp`, og adressen skal kunne nås fra der, hvor AI-klienten kører.

### Flere replikaer

En kompilering via MCP kører på den replika, der modtog forespørgslen, og dens log og PDF findes kun der. AI-klienter sender ingen cookie, så load balanceren kan sende den næste forespørgsel, `get_compile_log` eller PDF-downloadlinket, til en anden replika, som svarer »failed to fetch output file from CLSI« eller 404. I vores test med tre replikaer og ingen ekstra regel mislykkedes 5 af 6 logforespørgsler og 3 af 4 downloads på denne måde.

Send alle MCP-forespørgsler for et projekt til én replika, ligesom for `/git/`. Med HAProxy fra [Horisontal skalering](/da/on-premises/configuration/kubernetes/horizontal-scaling):

```text
      use-server overleaf-0 if { path_reg ^/project/[0-9a-f]{24}/mcp(/|$) }
```

MCP-kompileringer kører så alle på `overleaf-0`'s node. Med en anden ingress controller skal du route stien `/project/<id>/mcp` og alt under den til én replikas eget navn (`overleaf-0.overleaf-hl`).

Med denne regel lykkedes den samme test (en kompilering, 6 logforespørgsler og 4 PDF-downloads, alle uden cookie) hver gang.

### Testet på Kubernetes

På Kubernetes 1.37 med tre replikaer bag HAProxy består vores end-to-end-tests for MCP-serveren (37 tilfælde): visning af værktøjerne, tokens der afvises, når de er forkerte, slettede eller uden adgang, kompilering og læsning af loggen, ordtælling, projektindstillinger og historik, PDF-downloadlinks, redigering af filer med ændringerne vist live i den åbne editor og hentet ind i en Git-klon, kommentarer, adgang efter rolle, hastighedsbegrænsningerne for kompilering og indstillinger samt suspenderede konti. Disse forespørgsler kom fra en browsersession, så load balanceren holdt dem på én replika; for klienter uden cookie, se [Flere replikaer](#flere-replikaer).
