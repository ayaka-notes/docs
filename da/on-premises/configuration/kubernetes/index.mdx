En Kubernetes-udrulning læser de samme miljøvariabler som Toolkit. Hvor en Toolkit-side siger „tilføj dette til `config/variables.env`", skal du lægge værdien i ConfigMap'en `overleaf-env` eller i Secret'en `overleaf-secrets`, når det er en adgangskode, nøgle eller token. Genstart derefter:

```bash
kubectl -n overleaf apply -f 30-config.yaml        # after editing the ConfigMap
kubectl -n overleaf patch secret overleaf-secrets --type merge \
  -p '{"stringData":{"GITHUB_TOKEN_CIPHER_PASSWORD":"'"$(openssl rand -hex 32)"'"}}'
kubectl -n overleaf rollout restart deployment/overleaf
```

Værdier i `config/overleaf.rc` er Toolkit-indstillinger, ikke miljøvariabler; spørgsmål og svar sidst på denne side fortæller, hvad der erstatter dem.

### Certifikater og andre filer

Nogle funktioner tager en filsti i stedet for en værdi: SAML-certifikaterne (`OVERLEAF_SAML_IDP_CERT`, ...), LDAP-CA'en (`OVERLEAF_LDAP_TLS_OPTS_CA_PATH`) eller en privat CA til en selvhostet GitHub Enterprise, GitLab eller Gitea (`NODE_EXTRA_CA_CERTS`). Læg filerne i en Secret, og montér den, hvor Toolkit-siderne forventer dem, `/var/lib/overleaf/certs`:

```bash
kubectl -n overleaf create secret generic overleaf-certs --from-file=idp_cert.pem --from-file=ca.pem
```

```yaml title="40-overleaf.yaml (additions)"
          volumeMounts:
            # ...
            - name: certs
              mountPath: /var/lib/overleaf/certs
              readOnly: true
      volumes:
        # ...
        - name: certs
          secret:
            secretName: overleaf-certs
```

Henvis derefter til dem via sti i ConfigMap'en, for eksempel `NODE_EXTRA_CA_CERTS: /var/lib/overleaf/certs/ca.pem`, og genstart.

<Warning>

<strong>Cipher-adgangskoder.</strong> Angiv alle `*_CIPHER_PASSWORD` for de funktioner, du bruger, i Secret'en. Ellers genererer nogle funktioner en nøglefil i datavolumen ved første brug: med én replika virker det, indtil volumen går tabt, men med flere replikaer ville hver replika kryptere med en forskellig nøgle.

</Warning>

### Spørgsmål og svar

<Accordion title="Hvilke Toolkit-indstillinger fra `config/overleaf.rc` har jeg brug for?">

<strong>Svar:</strong> Ingen af dem læses af Ayakaleaf Pro. Deres modstykker i Kubernetes:

| `config/overleaf.rc`                         | Kubernetes                                                        |
| -------------------------------------------- | ----------------------------------------------------------------- |
| `OVERLEAF_LISTEN_IP`, `OVERLEAF_PORT`        | Service'en (NodePort) eller din ingress                           |
| `SIBLING_CONTAINERS_ENABLED`                 | `SANDBOXED_COMPILES*` i ConfigMap'en, Docker-socket i poden       |
| `GIT_BRIDGE_ENABLED`                         | [Git-integration](/da/on-premises/configuration/kubernetes/integrations/git-integration)                             |
| `MONGO_ENABLED`, `REDIS_ENABLED`, `MONGO_URL`, `REDIS_HOST` | StatefulSet'ene eller dine administrerede tjenester, `OVERLEAF_MONGO_URL` og `OVERLEAF_REDIS_HOST` |
| `REDIS_AOF_PERSISTENCE`                      | `--appendonly yes` i `20-redis.yaml`                              |
| `NGINX_ENABLED`, `TLS_*`                     | din ingress eller load balancer                                   |

</Accordion>
