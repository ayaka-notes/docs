#### Tjenester

Overleaf Pro-infrastrukturen består af fire primære tjenester: `sharelatex`, `git-bridge` (valgfri), `mongo` og `redis`. Tjenesten `sharelatex`, som kører selve Server Pro-applikationen, er afhængig af tjenesterne `mongo` og `redis` til henholdsvis database og caching/realtidsfunktioner samt af `git-bridge` til at håndtere [Git-integrationen](/da/on-premises/configuration/overleaf-toolkit/git-integration) (valgfri). Den eneste port, der er udstillet på værtsmaskinen, er port 80, som bruges af `sharelatex`-containeren.

Server Pro understøtter desuden valgfrit [S3-kompatibelt lager](/da/on-premises/configuration/overleaf-toolkit/s3) til projektfiler og den fulde projekthistorik og kan også fungere som proxy for adgang til den primære [Overleaf-dokumentationssidearrow-up-right](https://www.overleaf.com/learn). Se vores vejledning om [Tilføjelse af LaTeX-brugerhjælp](/da/on-premises/configuration/overleaf-toolkit/adding-latex-user-help) for at få flere oplysninger.

<Info>

Om nødvendigt kan MongoDB og Redis flyttes ud ved hjælp af miljøvariabler, der peger på eksterne tjenester. Se [Konfiguration af Overleaf](/da/on-premises/configuration), hvis du bruger Docker Compose, og [Toolkit-indstillinger](/da/on-premises/configuration/overleaf-toolkit/toolkit-settings), hvis du bruger Overleaf Toolkit.

</Info>

#### Kompilering

Ved [Sandboxed Compiles](/da/on-premises/configuration/overleaf-toolkit/sandboxed-compiles) styrer `sharelatex`-containeren oprettelsen af nye containere, der håndterer projektkompileringer; det sker via Docker-socketten på værtsmaskinen. Du kan læse mere om editoren og den samlede kompilerings-/cachingproces [her](/da/on-premises/getting-started/microservices#editor-and-compile-process).

#### Netværk

Kommunikationen mellem containerne foregår via Dockers interne DNS-opslag over et dedikeret bridge-netværk, og der er ingen firewalls aktiveret. Som standard bruger ovenstående tjenester deres respektive standardporte, men de kan konfigureres via miljøvariabler. `sharelatex`-containeren bruger port 80 til ekstern webadgang (serveret af Nginx), `mongo`-containeren bruger port 27017, og `redis` bruger port 6379.

Kunder, der bruger vores administrerede løsning [Overleaf Toolkitarrow-up-right](https://github.com/overleaf/toolkit), kan valgfrit [aktivere en TLS-proxy](/da/on-premises/configuration/overleaf-toolkit/tls-proxy) via en miljøvariabel for at terminere HTTPS-forbindelser med Nginx. Alternativt kan du bruge din eksisterende TLS-proxy.

<Info>

Du kan se et diagram, der forklarer, hvordan forespørgsler flyder, [her](/da/on-premises/configuration/overleaf-toolkit/tls-proxy).

</Info>

#### Opsummering

* Uden for Docker-netværket er kun port 80 tilgængelig, og den er bundet til Nginx. <strong>Bemærk:</strong> `sharelatex`-containeren kører mange [tjenesterarrow-up-right](https://github.com/overleaf/overleaf/tree/main/services), der kommunikerer med hinanden via HTTP. Disse porte er dog **ikke** tilgængelige uden for Docker-netværket.
* Inden for Docker-netværket kan Overleaf-tjenesterne, MongoDB, Redis og Git Bridge kommunikere frit med hinanden.
* Inde i [Sandboxed Compiles](/da/on-premises/configuration/overleaf-toolkit/sandboxed-compiles)-containere er der intet netværk tilgængeligt.
