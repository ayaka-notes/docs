### Doktoren

Overleaf Toolkit leveres med et praktisk `doctor`-script, der hjælper med fejlfinding. Kør `bin/doctor`, og scriptet udskriver oplysninger om dit værtsmiljø, din konfiguration og de afhængigheder, som Toolkit har brug for. Dette output kan også hjælpe os med at diagnosticere problemer med dine Ayakaleaf Pro-installationer.

<Info>

Brugere af Overleaf Pro kan [oprette et issue på GitHub](https://github.com/ayaka-notes/overleaf/issues).

Det er en god idé at inkludere outputtet fra scriptet `bin/doctor` i din besked.

</Info>

```bash title="Run doctor"
bin/doctor
```

### Afhængigheder

Afsnittet `Dependencies` viser de værktøjer, der kræves, for at Toolkit kan fungere. Hvis et værktøj er til stede, vises det som `status: present` med versionsoplysninger. Hvis det mangler, vises det som `status: MISSING!`, og der tilføjes en advarsel nederst i outputtet fra `doctor`.

<Accordion title="Eksempel på output for afhængigheder (til stede)">

```text
- docker
    - status: present
    - version info: Docker version 28.0.4, build b8034c0
```

</Accordion>

<Accordion title="Eksempel på output for afhængigheder (mangler)">

```text
- docker
    - status: MISSING!
```

</Accordion>

Hvis nogen afhængigheder mangler, vil Toolkit næsten med sikkerhed ikke fungere.

### Konfiguration

Afsnittet `Configuration` indeholder oplysninger om filerne i mappen `config/`. For `config/overleaf.rc` udskriver doctor nogle centrale værdier. Manglende filer vises som `status: MISSING!`, og der tilføjes en advarsel nederst i outputtet fra `doctor`.

<Accordion title="Eksempel på konfigurationsoutput">

```text
====== Configuration ======
- config/version
    - status: present
    - version: 6.3.2
- config/overleaf.rc
    - status: present
    - values
        - OVERLEAF_DATA_PATH: /tmp/overleaf
        - SERVER_PRO: false
        - MONGO_ENABLED: false
        - REDIS_ENABLED: true
- config/variables.env
    - status: MISSING!
```

</Accordion>

Bemærkninger til eksemplet ovenfor:

* `OVERLEAF_DATA_PATH` sat til `/tmp/overleaf` er muligvis ikke en sikker placering til vigtige data.
* `MONGO_ENABLED: false` betyder, at Toolkit ikke opretter sin egen MongoDB; sørg for, at `MONGO_URL` peger på en eksternt administreret MongoDB, hvis det er nødvendigt.
* `config/variables.env` mangler i eksemplet.

### Advarsler

Afsnittet `Warnings` opsummerer de problemer, som doctor-scriptet har fundet. Hvis der ikke er nogen problemer, angiver dette afsnit det.

<Accordion title="Eksempel på output for advarsler">

```text
====== Warnings ======
- configuration file variables.env not found
- rc file, OVERLEAF_DATA_PATH not set
====== End =======
```

</Accordion>

### Spørgsmål og svar

<Accordion title="Skal meddelelserne om quay.io, Docker-konfiguration og Perl-locale fra `bin/doctor` rettes?">

<strong>Svar:</strong> Nej, alle tre er kun til information. `bin/doctor` udskriver blot en rapport; den stopper ikke `bin/up`.

* `logged in to quay.io: false` og advarslen `Server Pro enabled, but not logged in to quay.io repository`: dette tjek stammer fra det officielle Toolkit, hvor Server Pro-imaget ligger i et privat quay.io-registry. Med `SERVER_PRO=true` henter Toolkit `ghcr.io/ayaka-notes/overleaf-pro`, som er offentligt, så det er ikke nødvendigt at logge ind. Ignorer denne advarsel.
* `grep: /root/.docker/config.json: No such file or directory` (eller en anden hjemmemappe): quay.io-tjekket leder efter `quay.io` i den fil. Docker skriver den kun, når der er indstillinger at gemme, f.eks. efter `docker login`, så den mangler på mange servere. Den er ikke nødvendig.
* `perl: warning: Setting locale failed`: Toolkit bruger kun `perl` her, i `bin/doctor`, til at udskrive dens version, og Perl advarer, når `LANG` eller `LC_ALL` angiver en locale, der ikke er installeret på værten. Versionen udskrives stadig. For at fjerne advarslen skal du sætte disse variabler til en locale, der vises af `locale -a`, f.eks. `C.UTF-8`.

Advarsler som `Docker daemon is not running`, `docker not found`, `Docker Compose not found` eller en manglende fil i `config/` skal derimod rettes: Toolkit kan ikke starte uden dem.

</Accordion>
