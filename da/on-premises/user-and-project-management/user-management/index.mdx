## Oprettelse af en administratorbruger

Installationer med Overleaf Toolkit:

```bash title="Overleaf Toolkit" wrap
$ bin/docker-compose exec sharelatex /bin/bash -ce "cd /overleaf/services/web && node modules/server-ce-scripts/scripts/create-user --admin --email=joe@example.com"
```

Ældre installationer med docker-compose.yml:

```bash title="Legacy docker-compose" wrap
$ docker exec sharelatex /bin/bash -ce "cd /overleaf/services/web && node modules/server-ce-scripts/scripts/create-user --admin --email=joe@example.com"
```

Kommandoen opretter en bruger med den angivne e-mailadresse, hvis brugeren ikke allerede findes, og gør vedkommende til administrator. Kommandoens output indeholder en URL, du kan besøge for at angive adgangskoden for denne bruger og logge ind første gang.

<Info>

Hvis du vil arbejde programmatisk, kan du bruge det samme script til at oprette almindelige brugere såvel som administratorer. For almindelige brugere skal du udelade flaget --admin.

</Info>

Hvis du bruger interne konti til godkendelse og har brug for at gøre en eksisterende bruger til instansadministrator eller fjerne administratorrettigheder, skal du gøre følgende:

<Steps>
<Step title="Via administratorgrænsefladen">
* Log ind som en eksisterende administrator.
* Klik på Admin -> Manage Users.
* Søg efter brugeren, og klik på vedkommendes e-mailadresse.
* Rul ned til afsnittet Site Admin, og klik på linket (show).
* Markér afkrydsningsfeltet Is Site Admin.
* Klik på Save for at afslutte.
</Step>
</Steps>

## Sletning af brugere

Det anbefales generelt ikke at slette konti, medmindre de ikke længere er nødvendige. Sletning af en konto fjerner kontoen og får samarbejdspartnere til at miste adgangen til projekter. Der er i øjeblikket ingen måde at deaktivere konti på — de findes enten med deres data bevaret, eller de er slettet.

Som standard bliver konti blødt slettet (soft-deleted). Se `ENABLE_CRON_RESOURCE_DELETION` i vejledningen [Miljøvariabler](/da/on-premises/configuration/overleaf-toolkit/environment-variables) for at få oplysninger om permanent fjernelse af brugere fra din instans.

<Info>

Konti bliver som standard blødt slettet. Se `ENABLE_CRON_RESOURCE_DELETION` for at få oplysninger om permanent sletning.

</Info>

### Via Admin -> Manage Users

<Steps>
<Step title="">
* Log ind som administrator.
* Klik på Admin -> Manage Users.
* Søg efter brugeren, og markér afkrydsningsfeltet ud for vedkommendes e-mailadresse.
* Klik på skraldespandsikonet.
* Klik på Delete for at bekræfte.
</Step>
</Steps>

### Via kommandolinjen

Brugerkonti (og deres projekter) kan slettes med følgende kommandoer.

Installationer med Overleaf Toolkit:

```bash title="Overleaf Toolkit"
$ bin/docker-compose exec sharelatex /bin/bash -ce "cd /overleaf/services/web && node modules/server-ce-scripts/scripts/delete-user.mjs --email=joe@example.com"
```

Ældre installationer med docker-compose.yml:

```bash title="Legacy docker-compose"
$ docker exec sharelatex /bin/bash -ce "cd /overleaf/services/web && node modules/server-ce-scripts/scripts/delete-user.mjs --email=joe@example.com"
```

<Danger>

Sletningsscriptet bruger en hårdkodet force-indstilling, der sikrer, at sletningen gennemføres, selv hvis e-mailen om sletning af kontoen ikke kan sendes (f.eks. når brugerens e-mailadresse ikke længere er i brug).

</Danger>

<Info>

Siden version 5.5.0 kan indstillingen --skip-email bruges til at undgå at sende en informerende e-mail til den slettede bruger.

</Info>

## Gendannelse af en blødt slettet bruger

Hvis en bruger kun er blevet blødt slettet, kan du gendanne vedkommendes konto og projekter.

<Steps>
<Step title="">
* Log ind som administrator.
* Klik på Admin -> Manage Users.
* Søg efter den bruger, du vil gendanne.
* Klik på knappen Display deleted users.
* Klik på den slettede brugers e-mailadresse.
* Klik på Recover This Account.
* Klik på Recover for at bekræfte.
</Step>
</Steps>

<Danger>

Når ENABLE\_CRON\_RESOURCE\_DELETION er sat til true, kan blødt slettede konti gendannes inden for en periode på 90 dage. Efter 90 dage er det ikke muligt at gendanne kontoen.

</Danger>

## Optælling af brugere

Du kan få antallet af brugere via administratorgrænsefladen på https://you-instance-url/admin/user#license. Til programmatiske kontroller og eksporter kan følgende eksempler være nyttige.

Samlet antal brugere:

```bash title="Total number of users"
echo 'db.users.countDocuments()' | docker exec -i mongo mongosh --quiet localhost/sharelatex
# overleaf [direct: primary] sharelatex> 16
```

Samlet antal brugere via metrics-endpointet:

```bash title="Num active users from metrics"
docker exec sharelatex curl http://127.0.0.1:3000/metrics | grep num_active_users
# # HELP num_active_users num_active_users
# # TYPE num_active_users gauge
# num_active_users{app="web-api",host="b3ae4ff549d8"} 16
```

Samlet antal aktive brugere (eksempel: brugere, der har været aktive inden for de seneste 365 dage):

```bash title="Total number of active users"
echo 'db.users.countDocuments({ lastActive: { $gte: new Date(new Date().getTime() - (365 * 24 * 60 * 60 * 1000)) } })' | docker exec -i mongo mongosh --quiet localhost/sharelatex
# overleaf [direct: primary] sharelatex> 10
```

## Opdatering af brugerkontooplysninger

Hvordan kontoopdateringer udføres, afhænger af, om SSO er aktiveret.

* Hvis SSO ikke bruges:
  * Administratorer kan ændre brugerkontooplysninger via Admin -> Manage Users (e-mail, fornavn, efternavn og generering af et link til nulstilling af adgangskode).
  * Almindelige brugere kan opdatere deres egne oplysninger via Account -> Account Settings (herunder ændring af adgangskode og generering af Git-godkendelsestokens).
* Hvis SSO bruges:
  * Server Pro kan konfigureres til at opdatere en brugers for- og efternavn ved login baseret på godkendelsessystemet.
  * Når OVERLEAF\_SAML\_UPDATE\_USER\_DETAILS\_ON\_LOGIN eller OVERLEAF\_LDAP\_UPDATE\_USER\_DETAILS\_ON\_LOGIN er true, er formularen med brugeroplysninger på https://your-instance-url/user/settings deaktiveret, og for-/efternavn kan kun angives i dit identitetsstyringssystem.

Se flere detaljer her:

* SAML 2.0-konfiguration: https://docs.overleaf.com/on-premises/configuration/overleaf-toolkit/server-pro-only-configuration/saml-2.0
* LDAP-konfiguration: https://docs.overleaf.com/on-premises/configuration/overleaf-toolkit/server-pro-only-configuration/ldap
