[Toolkit](/da/on-premises/installation/using-docker-compose) er den anbefalede måde at køre Ayakaleaf Pro på en enkelt server. Hvis du allerede kører et Kubernetes-cluster, udruller dette afsnit den samme container på det med almindelige `kubectl`-manifester: intet ekstra image, intet Helm-chart.

Når du er færdig med dette afsnit, har du én Ayakaleaf Pro-instans med sandboxed compiles, et MongoDB-replikasæt og Redis, alt sammen i namespacet `overleaf`. For at køre flere instanser bag en load balancer kan du bagefter fortsætte med [Horisontal skalering](/da/on-premises/configuration/kubernetes/horizontal-scaling).

<Info>

Understøttelse af Kubernetes er eksperimentel. Vi udgiver ikke et Helm-chart eller Kubernetes-specifikke images. Manifesterne på disse sider er dem, vi har testet på Kubernetes 1.37 (kubeadm, containerd 2.4, flannel) med tre noder med hver 2 vCPU'er og 4 GB hukommelse. Tilpas lagring, netværk og ingress til dit cluster.

</Info>

### Sådan passer delene sammen {#how-the-pieces-fit}

| Toolkit (én server)                          | Kubernetes                                                               |
| -------------------------------------------- | ------------------------------------------------------------------------ |
| `config/variables.env`                       | ConfigMap `overleaf-env` og Secret `overleaf-secrets`                    |
| `sharelatex`-container                       | Deployment `overleaf` (én pod, der kører alle Overleaf-tjenester)        |
| `mongo`- og `redis`-containere               | StatefulSets `mongo` (replikasæt) og `redis` eller dine administrerede tjenester |
| `~/overleaf-toolkit/data/overleaf`           | PersistentVolumeClaim `overleaf-data`                                    |
| Docker på værten, brugt til kompileringer    | Docker Engine på hver node, der kører Ayakaleaf Pro                      |
| `bin/up`, `bin/logs`, `bin/shell`            | `kubectl apply`, `kubectl logs`, `kubectl exec`                          |

### Hvad du har brug for {#what-you-need}

* Et Kubernetes-cluster, som du kan installere pakker på: hver node, der kan køre Ayakaleaf Pro, skal have **Docker Engine**, fordi kompileringer kører i TeX Live-containere, som Ayakaleaf Pro starter via nodens `/var/run/docker.sock`. Se [0. Forbered noderne](/da/on-premises/installation/using-kubernetes/0.-prepare-the-nodes).
* En standard-StorageClass med `ReadWriteOnce`-volumes.
* `kubectl` og `openssl` på din arbejdsstation.
