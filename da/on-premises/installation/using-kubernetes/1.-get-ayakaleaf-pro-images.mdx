Kubernetes kører de samme images som Toolkit. Der findes ikke et separat Kubernetes-image.

| Image                                                | Bruges af                                                               |
| ---------------------------------------------------- | ----------------------------------------------------------------------- |
| `ghcr.io/ayaka-notes/overleaf-pro:6.3.2`             | Deployment'et `overleaf`                                                |
| `ghcr.io/ayaka-notes/overleaf-pro/git-bridge:6.3.2`  | [Git-integration](/da/on-premises/configuration/kubernetes/integrations/git-integration) (valgfrit), samme tag som ovenfor |
| `ghcr.io/ayaka-notes/texlive-*`                      | kompileringer, pullet ind i Docker på noderne i [trin 0](/da/on-premises/installation/using-kubernetes/0.-prepare-the-nodes) |

Imagene er offentlige på [ghcr.io](https://github.com/ayaka-notes/ayakaleaf-pro/pkgs/container/overleaf-pro/) til amd64 og arm64, så kubelet'en kan pulle dem uden legitimationsoplysninger.

<Warning>

Brug altid et versionstag, såsom `6.3.2`, ikke `latest`. Opgraderinger kører databasemigreringer og skal følge [Opgradering på Kubernetes](/da/on-premises/maintenance/upgrading-on-kubernetes); et skiftende tag ville opgradere en pod, hver gang den blev omplaceret.

</Warning>

### Spørgsmål og svar

<Accordion title="Vores noder kan ikke nå ghcr.io. Hvad gør vi?">

<strong>Svar:</strong> Kopiér imagene til et registry, som noderne kan nå, og brug det navn i manifesterne, for eksempel:

```bash
docker pull ghcr.io/ayaka-notes/overleaf-pro:6.3.2
docker tag ghcr.io/ayaka-notes/overleaf-pro:6.3.2 registry.example.com/ayakaleaf/overleaf-pro:6.3.2
docker push registry.example.com/ayakaleaf/overleaf-pro:6.3.2
```

For et registry uden TLS skal containerd have en `/etc/containerd/certs.d/<registry>/hosts.toml` med `server = "http://<registry>"` på hver node og `config_path` sat som i [trin 0](/da/on-premises/installation/using-kubernetes/0.-prepare-the-nodes). Docker selv pusher kun over almindelig HTTP til `localhost`, så push via `localhost:<port>` på registry-værten, eller tilføj det til `insecure-registries`.

</Accordion>
