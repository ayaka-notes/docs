---
title: 5. Tilpasning af din instans
description: Angiv port, site-URL og TeX Live-image til en lokal instans på din Mac, kontrollér Docker-VM'ens kerne, og start Ayakaleaf Pro.
icon: square-sliders
---

<Steps>
<Step title="Containerindstillinger">
Rediger disse eksisterende poster i `config/overleaf.rc`:

```bash title="config/overleaf.rc"
PROJECT_NAME=ayakaleaf-macos
SERVER_PRO=true
OVERLEAF_LISTEN_IP=127.0.0.1
OVERLEAF_PORT=8080
SIBLING_CONTAINERS_ENABLED=true
DOCKER_SOCKET_PATH=/var/run/docker.sock
```

Behold standardstierne til data og de medfølgende MongoDB- og Redis-tjenester. Med `OVERLEAF_LISTEN_IP=127.0.0.1` kan kun browsere på denne Mac åbne instansen.
</Step>

<Step title="Applikationsindstillinger">
Sæt disse værdier i `config/variables.env`, og erstat eventuelle aktive poster med de samme navne:

```dotenv title="config/variables.env"
OVERLEAF_SITE_URL=http://localhost:8080
TEX_LIVE_DOCKER_IMAGE=ghcr.io/ayaka-notes/texlive-full:2026.1
ALL_TEX_LIVE_DOCKER_IMAGES=ghcr.io/ayaka-notes/texlive-full:2026.1
ALL_TEX_LIVE_DOCKER_IMAGE_NAMES="TeX Live 2026"
```

Generér en sessionshemmelighed:

```bash
openssl rand -hex 32
```

Tilføj resultatet som `OVERLEAF_SESSION_SECRET` i `config/variables.env`. Uden den logger hver `bin/up`, der genopretter containeren, alle brugere ud; se [Miljøvariabler](/da/on-premises/configuration/overleaf-toolkit/environment-variables).

For en lokal instans uden e-mail skal du lade SMTP-indstillingerne og `OVERLEAF_EMAIL_FROM_ADDRESS` være usat. Git Bridge, ekstern godkendelse og de andre integrationer kan tilføjes senere med deres egne [konfigurationssider](/da/on-premises/configuration/overleaf-toolkit).
</Step>

<Step id="check-the-docker-vms-linux-kernel" title="Kontrollér Docker-VM'ens Linux-kerne">
MongoDB kører på Linux-kernen i Docker Desktops virtuelle maskine, ikke på macOS. Kontrollér dens version før første start:

```bash
docker info --format '{{.KernelVersion}}'
```

MongoDB dokumenterer en inkompatibilitet med Linux-kerner **6.19 til og med 7.0.13**, som også påvirker MongoDB i Docker. Løsningen er en kerne **7.0.14 eller nyere**, som følger med en opdatering af Docker Desktop; se [MongoDBs produktionsnoter](https://www.mongodb.com/docs/manual/administration/production-notes/).

Hvis din Docker-VM bruger en berørt kerne, skal du tilføje følgende til `config/docker-compose.override.yml`, flettet med eventuelle `services`, du allerede har der:

```yaml title="config/docker-compose.override.yml"
services:
  mongo:
    environment:
      GLIBC_TUNABLES: glibc.pthread.rseq=1
```

<Warning>

Opdater til en rettet kerne, når den er tilgængelig. Hvis din kerne ligger uden for det berørte interval, er denne løsning unødvendig.

</Warning>
</Step>

<Step title="Start din instans">
Kør følgende fra Toolkit-mappen:

```bash
bin/up -d
```

Toolkit initialiserer MongoDBs replica set, henter TeX Live-imaget og starter applikationen. Den første download tager et stykke tid. Sådan følger du forløbet:

```bash
bin/docker-compose ps
bin/docker-compose logs --tail=100 -f sharelatex
```

Tryk på `Ctrl+C` for at stoppe med at følge loggene. Containerne bliver ved med at køre.

Kontrollér den publicerede port og siden til første kørsel:

```bash
bin/docker-compose port sharelatex 80
curl -I http://localhost:8080/launchpad
```

Porten skal være `127.0.0.1:8080`.
</Step>
</Steps>

<Info>

For senere at åbne instansen fra andre computere skal du ændre lytteadressen og site-URL'en og opsætte HTTPS som beskrevet i [5. Tilpasning af din instans](/da/on-premises/installation/using-docker-compose/linux/5.-personalizing-your-instance) i Linux-vejledningen. Mac'en skal så forblive vågen; se [Hold instansen tilgængelig](/da/on-premises/installation/using-docker-compose/macos/6.-post-installation-tasks#keep-the-instance-available).

</Info>
