### Initialisering mislykkes med invalid command code {#initialization-fails-with-invalid-command-code}

`bin/init` rapporterer `sed: ... invalid command code`, når den finder macOS' BSD sed. Sæt GNU sed på `PATH` som i [1. Download Toolkit](/da/on-premises/installation/using-docker-compose/macos/1.-download-the-toolkit), og kontrollér `sed --version`.

En mislykket initialisering kan efterlade alle tre filer i `config/` med en tom `OVERLEAF_INVITE_TOKEN_SECRET`. Hvis du kører `bin/init` igen, rapporterer den så `Config files already exist`. For en ny installation, der aldrig er startet, skal du flytte de tre filer til en backupmappe og køre `bin/init` igen. For en eksisterende instans skal du beholde dens konfiguration og hemmeligheder og ikke slette dens filer for at få `bin/init` til at køre igen.

### MongoDB genstarter hele tiden {#mongodb-keeps-restarting}

Læs MongoDB-loggene og kerneversionen i Docker-VM'en:

```bash
bin/docker-compose logs --tail=100 mongo
docker info --format '{{.KernelVersion}}'
```

Hvis loggen nævner inkompatibiliteten med Linux-kernen, skal du følge [Kontrollér Docker-VM'ens Linux-kerne](/da/on-premises/installation/using-docker-compose/macos/5.-personalizing-your-instance#check-the-docker-vms-linux-kernel) og køre `bin/up -d` igen. Afslutningskode `137` alene beviser ikke, at MongoDB løb tør for hukommelse: kontrollér containerens tilstand og loggene. For et ældre MongoDB-problem på Docker Desktop kan du også se [Fejlfinding](/da/on-premises/support/troubleshooting).

### Kan ikke forbinde til Docker-daemonen {#cannot-connect-to-the-docker-daemon}

Start Docker Desktop, og kontrollér den valgte Docker-kontekst; se [0. Opsætning af Docker Desktop](/da/on-premises/installation/using-docker-compose/macos/0.-setup-docker-desktop). Hvis `docker info` virker, men kompileringer ikke kan nå Docker, skal du kontrollere socket-indstillingerne i `config/overleaf.rc` og læse `clsi`-loggene. Et fungerende Docker CLI på Mac'en beviser ikke, at applikationens socket-mount er korrekt.

### Siden åbner, men kompileringer mislykkes {#the-page-opens-but-compiles-fail}

Kontrollér, at TeX Live-imaget findes lokalt og matcher Docker-enginens arkitektur:

```bash
docker image inspect ghcr.io/ayaka-notes/texlive-full:2026.1 \
  --format '{{.Os}}/{{.Architecture}}'
bin/logs -f clsi
```

På Apple silicon skal imaget være `linux/arm64`. Kontrollér, at `SERVER_PRO` og `SIBLING_CONTAINERS_ENABLED` begge er `true`, og anvend derefter ændringerne med `bin/up -d`. Hvis loggene rapporterer en manglende kompileringsmappe, skal du kontrollere Docker Desktops fildeling og placeringen af `OVERLEAF_DATA_PATH`. Slå ikke sandboxed compiles fra for at skjule en mount-fejl.

### Not a directory, eller et bind-mount mangler {#not-a-directory-or-a-bind-mount-is-missing}

En fil på værten, som en override monterer, kan være blevet slettet, eller Docker kan have oprettet en mappe, hvor filen skulle være. Kontrollér kildestien på værten, og om mountet forventer en fil eller en mappe. Gendan konfigurationsfilen, før du genopretter containeren. En installation under `/tmp` kan løbe ind i dette, når macOS fjerner midlertidige filer.

### Konflikter med port eller containernavn {#port-or-container-name-conflicts}

Hvis port `8080` er i brug, skal du vælge en anden port i `config/overleaf.rc`, sætte `OVERLEAF_SITE_URL` tilsvarende og køre `bin/up -d` igen.

Toolkit giver sine containere faste navne som `sharelatex`, `mongo` og `redis`. Det er ikke nok at ændre `PROJECT_NAME` for at gøre to Toolkit-installationer uafhængige. Før du starter en anden instans, skal du kontrollere `docker ps -a` og bruge andre containernavne i en Compose-override, en anden port og separate datamapper. Fjern ikke containere eller data fra en eksisterende udrulning for at løse en navnekonflikt.

### Instansen kan ikke nås efter et stykke tid {#the-instance-is-unreachable-after-a-while}

Mac'en er sandsynligvis gået i dvale, eller Docker Desktop er blevet afsluttet. Se [Hold instansen tilgængelig](/da/on-premises/installation/using-docker-compose/macos/6.-post-installation-tasks#keep-the-instance-available).

### `bin/doctor` siger, at dette ikke er Linux, eller beder om et Quay-login {#bin/doctor-says-this-is-not-linux-or-asks-for-a-quay-login}

Begge advarsler er forventede på macOS med det offentlige image; se [2. Bliv fortrolig med Toolkit](/da/on-premises/installation/using-docker-compose/macos/2.-familiarize-yourself-with-the-toolkit). Kontrollér i stedet hentningen af images, tjenesternes status og kompileringsresultaterne, og ignorer ikke andre fejl i rapporten.
