### Opret administratoren og et første projekt {#create-the-administrator-and-a-first-project}

Åbn [http://localhost:8080/launchpad](http://localhost:8080/launchpad) i din **Windows-browser**, opret den første administratorkonto, og log ind. Følg derefter [6. Opgaver efter installationen](/da/on-premises/installation/using-docker-compose/linux/6.-post-installation-tasks) i Linux-vejledningen, og brug port `8080` i dens eksempel-URL'er.

### Kontrollér kompilering {#verify-compilation}

En fungerende loginside beviser ikke, at de separate kompileringscontainere har adgang til WSL-datamappen. Opret et tomt projekt, og kompilér denne `main.tex` med **pdfLaTeX**:

```latex
\documentclass{article}
\begin{document}
Ayakaleaf Pro on Windows WSL 2.
\end{document}
```

PDF-forhåndsvisningen skal vise teksten. Med basic-imaget skal du om nødvendigt vælge **TeX Live 2026 Basic** i projektindstillingerne.

Vælg **XeLaTeX**, og test:

```latex
\documentclass{article}
\usepackage{fontspec}
\begin{document}
Ayakaleaf WSL XeLaTeX sandbox.
\end{document}
```

Begge eksempler virker med basic. Til kinesiske dokumenter skal du bruge et image, der indeholder `ctex` og de nødvendige skrifttyper, f.eks. full, før du tester følgende med **XeLaTeX**. Basic indeholder dem ikke:

```latex
\documentclass{ctexart}
\begin{document}
你好，Ayakaleaf Pro。
\end{document}
```

For at bekræfte, at sandboxen bruges, skal du køre følgende i **Ubuntu**, mens der kompileres:

```bash
docker ps -a --filter ancestor=ghcr.io/ayaka-notes/texlive-basic:2026.1
bin/logs -f clsi
```

Brug navnet på dit valgte image i filteret. Korte kompileringer kan blive færdige, før `docker ps` kører; `-a` viser også stoppede containere, indtil de ryddes op. En kompileringscontainer skal bruge det image og et `/compile`-bind-mount fra Toolkits WSL-datamappe. Applikationsloggene alene er ingen erstatning for at kontrollere PDF'en.

### Kontrollér persistens {#verify-persistence}

I **Ubuntu** fra Toolkit-mappen:

```bash
bin/stop
bin/start
```

Vent på applikationen, åbn projektet igen fra Windows, og kompilér igen. Din konto, kildekoden og projektfilerne skal stadig være der. De aktive data ligger som standard i `~/ayakaleaf-toolkit/data/` i Ubuntu. Behold både `config/` og `data/`; hvis du afinstallerer eller afregistrerer Ubuntu-distributionen, kan de blive slettet.

### Hold instansen tilgængelig {#keep-the-instance-available}

Der er tre dele i at holde instansen kørende: Windows forbliver vågen, Docker Desktop kører, og containerne genstarter sammen med enginen.

Under **Settings → General** i Docker Desktop skal du slå **Start Docker Desktop when you sign in to your computer** til; se [Docker Desktop settings](https://docs.docker.com/desktop/settings-and-maintenance/settings/). Det starter Docker efter login, ikke før login. Efter en genstart af Windows skal du logge ind, vente på, at Docker Desktop er færdig med at starte, åbne Ubuntu og kontrollere `docker ps` og sitet.

Docker Desktops **Resource Saver** er adskilt fra Windows' dvale. Den aktiveres normalt kun, når ingen containere kører; den kørende applikation, MongoDB og Redis forhindrer denne inaktive tilstand. På WSL 2 sætter den Docker-enginen på pause i stedet for at lukke den delte WSL-VM ned. Brug ikke **Pause** manuelt i Docker Desktop, mens du betjener brugere. Du behøver ikke at deaktivere Resource Saver blot for at holde denne stak kørende; se [Dockers dokumentation om Resource Saver](https://docs.docker.com/desktop/use-desktop/resource-saver/).

Toolkit-tjenesterne bruger `restart: always`. Kontrollér den faktiske indstilling i **Ubuntu**:

```bash
docker inspect sharelatex mongo redis --format '{{.Name}} restart={{.HostConfig.RestartPolicy.Name}}'
```

Hver tjeneste skal rapportere `always`. Når Docker kører, kan den genstarte disse eksisterende containere uden en ny `bin/up`. En manuelt stoppet container forbliver stoppet, indtil du starter den eller genstarter enginen; med `always` kan en genstart af enginen starte den igen. Se [Dockers adfærd for genstartspolitikker](https://docs.docker.com/engine/containers/start-containers-automatically/).

| Handling | Effekt på Ayakaleaf |
| --- | --- |
| Luk Ubuntu-terminalen efter `bin/up -d` | Containerne kører frakoblet; terminalen overvåger dem ikke. Hold Docker Desktop og WSL-miljøet tilgængeligt |
| Luk vinduet Docker Dashboard | Vinduet kan lukkes, mens Docker Desktop fortsætter i systembakken |
| Vælg **Quit Docker Desktop** | Stopper enginen og gør sitet utilgængeligt; åbn Docker Desktop igen for at gendanne |
| Kør `wsl --shutdown` | Stopper alle WSL-distributioner og afbryder Dockers WSL-backend; genstart Docker Desktop, og åbn Ubuntu igen |
| Sæt Windows i dvale, dvaletilstand (hibernation), eller luk den ned | Tjenesten er utilgængelig; det ændrer ikke noget kun at have skærmen tændt eller slukket |
| Kør `bin/stop` | Stopper instansen og bevarer dens data; brug `bin/start` for at fortsætte |

Ved langvarig brug på netstrøm skal du åbne **Settings → System → Power & battery → Screen, sleep & hibernate timeouts** i Windows 11 (nogle versioner viser **Power** eller **Screen and sleep**). Sæt dvaletimeout ved tilsluttet strøm til **Never**, og deaktiver automatisk dvaletilstand (hibernation), hvis den er konfigureret. Skærmen kan stadig slukke. En laptops handling ved lukning af låget er en separat indstilling; hvis du lukker låget, kan den gå i dvale, selv med en dvaletimeout ved inaktivitet på Never. Se [Strømindstillinger i Windows](https://support.microsoft.com/en-us/windows/experience/power-battery/power-settings-in-windows-11).

Kør ikke `wsl --shutdown` som rutinemæssig oprydning, mens sitet er i brug. Hvis en ændring af WSL-indstillingerne kræver det, skal du stoppe instansen først og planlægge en afbrydelse. Windows kan køre instansen kontinuerligt med disse indstillinger. Til en delt tjeneste, der skal overleve logouts og genstarter uden tilsyn, anbefaler vi [Linux-vejledningen](/da/on-premises/installation/using-docker-compose/linux).

### Kontrollér gendannelse efter genstart af Docker Desktop {#check-recovery-after-restarting-docker-desktop}

Når du har gemt dit arbejde og ladet aktive kompileringer blive færdige, skal du vælge **Restart Docker Desktop** i Docker Desktops fejlfindingsmenu. Vent på enginen, og kontrollér derefter i **Ubuntu**:

```bash
docker ps
curl -I http://localhost:8080/launchpad
```

Åbn det eksisterende projekt i Windows, og kompilér det igen. Bekræft, at kontoen og kildekoden stadig findes.

Hvis du bevidst har stoppet instansen med `bin/stop`, skal du bruge `bin/start`. Hvis Docker kører, men en tjeneste fejler, skal du læse dens logge i stedet for at genoprette konfigurationen. Windows Update, Docker-opdateringer og strømsvigt kan stadig afbryde en installation, der kører døgnet rundt; tag sikkerhedskopier, og kontrollér gendannelsen efter planlagt vedligeholdelse.

### Daglig brug {#daily-use}

Start Docker Desktop i Windows. Åbn **Ubuntu**:

```bash
cd "$HOME/ayakaleaf-toolkit"
```

| Opgave | Kommando |
| --- | --- |
| Start eksisterende containere | `bin/start` |
| Stop containere, og behold data | `bin/stop` |
| Anvend konfigurationsændringer | `bin/up -d` |
| Kontrollér status | `bin/docker-compose ps` |
| Læs opstartslogge | `bin/docker-compose logs --tail=100 sharelatex` |
| Læs MongoDB-logge | `bin/docker-compose logs --tail=100 mongo` |
| Læs kompilatorlogge | `bin/logs -f clsi` |

`bin/start` anvender ikke ændringer i konfigurationen: brug `bin/up -d`, når du har ændret `config/`. Følg [Data og sikkerhedskopier](/da/on-premises/maintenance/data-and-backups), før du opgraderer, flytter eller fjerner WSL-distributionen. At kopiere aktive MongoDB-filer, mens databasen skriver, er ikke en konsistent sikkerhedskopi.

Behold `127.0.0.1` til lokal brug. At betjene andre computere kræver også en bevidst valgt lytteadresse, site-URL, Windows-firewall/netværkskonfiguration og HTTPS; det er ikke nok at ændre `OVERLEAF_SITE_URL` for at publicere en port.

Hvis noget ikke virker, kan du se [Fejlfinding](/da/on-premises/installation/using-docker-compose/windows/troubleshooting).
