Ayakaleaf Pro bruger Linux-containere. På Windows installerer du Docker Desktop med WSL 2-backenden og kører Toolkit-scriptene i Ubuntu.

WSL 2 leverer Linux-kernen. Docker Desktop administrerer Docker-enginen i sit eget `docker-desktop`-miljø; når du aktiverer **WSL Integration**, kan Docker CLI i Ubuntu tale med den engine. Toolkit starter derefter applikationen, MongoDB og Redis som containere. Med sandboxed compiles aktiveret bruger applikationen enginens Docker-socket til at starte en separat TeX Live-container til hver kompilering. Du har ikke brug for Windows-installationer af MongoDB, Redis eller TeX Live.

<Steps>
<Step title="Installer WSL 2 og Ubuntu">
Åbn **PowerShell som administrator** i Windows, og kør:

```powershell
wsl --install -d Ubuntu
```

Genstart Windows, hvis du bliver bedt om det. Åbn **Ubuntu** fra startmenuen, og opret et Linux-brugernavn og en adgangskode. Det er kontoen til `sudo` i Ubuntu; den er adskilt fra dit Windows-login.

Tilbage i **PowerShell** skal du opdatere WSL og kontrollere distributionen:

```powershell
wsl --update
wsl --version
wsl --list --verbose
```

Ubuntu-rækken skal vise **VERSION 2**. Hvis den viser 1, skal du bruge dens nøjagtige distributionsnavn fra listen:

```powershell
wsl --set-version Ubuntu 2
```

Docker kræver WSL **2.1.5 eller nyere**; WSL-softwareversionen fra `wsl --version` og distributionens kolonne **VERSION 2** er forskellige kontroller. Se [fejlfinding af installationen](/da/on-premises/installation/using-docker-compose/windows/troubleshooting#wsl-or-docker-reports-that-virtualization-is-unavailable) og [Microsofts installationsvejledning](https://learn.microsoft.com/en-us/windows/wsl/install), hvis installationen mislykkes, og aktiver hardwarevirtualisering i BIOS/UEFI, hvis WSL rapporterer, at den ikke er tilgængelig.
</Step>

<Step title="Installer og start Docker Desktop">
Download [Docker Desktop for Windows](https://docs.docker.com/desktop/setup/install/windows-install/) til din processor, og kør installationsprogrammet. Brug **WSL 2**-backenden, hvis den tilbydes. Åbn **Docker Desktop** fra Windows' startmenu, og vent, til enginen starter.

Under **Settings → General** i Docker Desktop skal du aktivere **Use WSL 2 based engine**, hvis indstillingen vises. Under **Settings → Resources → WSL Integration** skal du aktivere integrationen for **Ubuntu** og derefter vælge **Apply** eller **Apply & restart**. Hvis Ubuntu ikke er din standarddistribution, skal du eksplicit aktivere dens egen kontakt.

Hvis WSL Integration mangler, skal du kontrollere, at Docker Desktop bruger **Linux containers**. Se [Dockers vejledning til WSL 2-backenden](https://docs.docker.com/desktop/features/wsl/).

Brug Docker Desktops integration til denne vejledning. Hvis du installerer en ekstra Docker Engine med `apt install docker.io` eller starter `dockerd` i Ubuntu, opretter du en separat opsætning, som kan give konflikter. Hvis du allerede bruger en Engine i Ubuntu, skal du følge Dockers migreringsvejledning, før du skifter; behold eksisterende applikationsdata og sikkerhedskopier.
</Step>

<Step title="Kontrollér Docker fra Ubuntu">
Åbn en **Ubuntu**-terminal. Kør disse kommandoer der, uden `sudo`:

```bash
docker version
docker compose version
docker ps
```

`docker version` skal vise både **Client** og **Server**. En tom containerliste er normal på en ny installation. `docker --version` alene beviser ikke, at enginen kører.

Hvis `docker` ikke er tilgængelig eller ikke kan forbinde, skal du åbne Ubuntu igen efter at have anvendt WSL Integration og kontrollere, at Docker Desktop kører. Se [Fejlfinding](/da/on-premises/installation/using-docker-compose/windows/troubleshooting#docker-is-unavailable-in-ubuntu).
</Step>

<Step title="Kontrollér ressourcer og Docker-socket">
Kontrollér de ressourcer, Docker kan se:

```bash
docker info --format 'CPUs={{.NCPU}} Memory={{.MemTotal}} Kernel={{.KernelVersion}}'
df -h "$HOME"
ls -l /var/run/docker.sock
```

Til en lille lokal instans er 4 CPU'er og 8 GB hukommelse tilgængeligt for Docker et forslag til udgangspunkt, ikke et målt minimum. Sørg også for nok hukommelse til Windows. Med WSL 2-backenden administreres ressourcegrænser via [WSL-indstillinger](https://learn.microsoft.com/en-us/windows/wsl/wsl-config) i stedet for Docker Desktops ressourceskydere som på Mac. Ændringer, der kræver `wsl --shutdown`, afbryder alle kørende WSL-distributioner og Docker-arbejdsbelastninger; anvend dem, før du starter instansen.

Behold `DOCKER_SOCKET_PATH=/var/run/docker.sock` i Toolkit-konfigurationen. Applikationen har brug for denne engine-socket til sandboxed compiles. Ændr ikke dens tilladelser til `777` for at løse forbindelsesfejl; gendan i stedet Docker Desktops integration.
</Step>
</Steps>
