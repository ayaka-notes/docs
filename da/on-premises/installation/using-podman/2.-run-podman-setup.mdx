`bin/podman-setup` tjekker alt, hvad Ayakaleaf Pro har brug for på Podman. Uden indstillinger rapporterer det kun; med `--apply` retter det også det, det finder.

<Steps>
<Step title="Tjek værten">
```bash title="Check only"
bin/podman-setup
```

På en ny vært fejler de fleste tjek, for eksempel:

```text
====== Packages ======
[✗] podman not installed
[✗] podman-docker not installed
...
====== Summary ======
[✓] 7 passed  [!] 13 warnings  [✗] 4 failures
```
</Step>

<Step title="Anvend rettelserne">
```bash title="Check and fix"
bin/podman-setup --apply
```

Kør det i en terminal: det beder om din `sudo`-adgangskode til de systemdækkende trin. Det downloader også Ayakaleaf Pro-imaget for at udtrække dets seccomp-profil, hvilket tager et par minutter første gang. Til sidst tjekker det værten igen:

```text
====== Summary ======
[✓] 23 passed  [!] 2 warnings  [✗] 0 failures
[!] Warnings remaining:
[!] not logged in to quay.io
[!] container → socket skipped (sharelatex not running)
```

Begge advarsler er forventede på dette tidspunkt:

* `not logged in to quay.io`: tjekket kommer fra den officielle Toolkit, hvor Server Pro-imaget ligger i et privat registry. Ayakaleaf Pro-images er offentlige på `ghcr.io` og kræver intet login, så ignorer den. Den bliver også stående efter installationen.
* `container → socket skipped (sharelatex not running)`: denne test kræver den kørende instans. Du kører scriptet igen i [3. Start Ayakaleaf Pro](/da/on-premises/installation/using-podman/3.-start-ayakaleaf-pro).

Scriptet afslutter med `0`, når alle tjek består, `1`, når der er advarsler, og `2`, når der er fejl. På grund af quay.io-advarslen kan du forvente `1`.
</Step>
</Steps>

### Hvad scriptet ændrer {#what-the-script-changes}

Med `--apply` kan scriptet ændre følgende.

Systemdækkende, med `sudo`:

* Installerer `podman`, `podman-docker`, `git`, `curl`, `checkpolicy` og `policycoreutils` med `dnf`.
* Aktiverer lingering for din bruger med `loginctl`, så dine containere bliver ved med at køre, når du logger ud.
* Opretter `/etc/containers/nodocker`, som undertrykker beskeden "Emulate Docker CLI using podman".
* Indlæser SELinux-politikmodulet `podman_socket_clsi`, når `SELINUX_MODE=managed`.

For din bruger:

* Aktiverer brugertjenesten `podman.socket`, det Docker-kompatible API, som Ayakaleaf Pro bruger til at starte kompileringer.
* Installerer Docker Compose v2 fra GitHub i `~/.local/bin/docker-compose` og linker det i `~/.docker/cli-plugins/`.
* Får Podman til at bruge denne Compose i `~/.config/containers/containers.conf`.
* Tilføjer aliasserne `mongo` og `redis` i `~/.config/containers/registries.conf.d/overleaf-toolkit.conf`, så Podman ved, hvor disse korte image-navne skal hentes fra.

I Toolkit:

* Sætter `DOCKER_SOCKET_PATH` og `DOCKER_HOST` i `config/overleaf.rc` til `/run/user/<uid>/podman/podman.sock`.
* Udtrækker seccomp-profilen til kompileringer fra Ayakaleaf Pro-imaget til `config/seccomp/<version>/clsi-profile.json` og sætter `SECCOMP_PROFILE` i `config/variables.env`. I modsætning til Docker skal Podman have denne profil som en fil på værten.
* Bygger SELinux-politikmodulet i `config/selinux/`.
* Sætter ejerne af datamapperne i `data/` med `podman unshare chown`, når de findes.

<Info>

Hver ændring svarer til et tjek. Hvis du ændrer noget manuelt, for eksempel i `config/overleaf.rc`, så kør `bin/podman-setup` igen for at bekræfte det.

</Info>
