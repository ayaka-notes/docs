RHEL og dens genopbygninger (Rocky Linux, AlmaLinux) leveres med Podman i stedet for Docker, og nogle organisationer tillader ikke Docker på deres servere. Toolkit kan i stedet køre Ayakaleaf Pro på **rootless Podman**: containerne kører som en almindelig bruger, kompileringer kører stadig i sandboxede TeX Live-containere, og SELinux forbliver i enforcing-tilstand. Scriptet `bin/podman-setup` tjekker værten og retter det, det kan.

Når du er færdig med dette afsnit, har du den samme instans som med [Brug af Docker Compose](/da/on-premises/installation/using-docker-compose): Ayakaleaf Pro med sandboxede kompileringer, MongoDB og Redis, administreret med de sædvanlige `bin/up`, `bin/doctor` og `bin/upgrade`.

<Info>

Podman-understøttelse er eksperimentel. Den kommer fra den officielle Overleaf Toolkit, som kun testes på RHEL 9 og nyere med rootless Podman, sandboxede kompileringer og SELinux i enforcing-tilstand. Vi testede disse sider på Rocky Linux 9.9 (Podman 5.8, SELinux enforcing) med Ayakaleaf Pro 6.3.4. Docker er fortsat det anbefalede container-runtime.

</Info>

### Det skal du bruge {#what-you-need}

* **RHEL, Rocky Linux, AlmaLinux eller CentOS Stream 9 eller nyere**, med SELinux i enforcing-tilstand. `bin/podman-setup` stopper på alle andre distributioner. På Ubuntu eller Debian skal du bruge [Brug af Docker Compose](/da/on-premises/installation/using-docker-compose/linux).
* **En bruger, der ikke er root, med `sudo`**, som skal eje containerne. Kør alle kommandoer i dette afsnit som denne bruger; `bin/podman-setup` nægter at køre som `root`.
* **En ren vært**: ingen Docker Engine og ingen eksisterende Toolkit-installation. Flytning af en eksisterende Docker-baseret instans til Podman er ikke dækket.

### Sådan adskiller det sig fra Docker {#how-it-differs-from-docker}

|                                  | Docker                               | Rootless Podman                                                                          |
| -------------------------------- | ------------------------------------ | ---------------------------------------------------------------------------------------- |
| Hvem kører containerne           | Docker-daemonen, som `root`          | Din bruger                                                                               |
| Socket brugt til at starte kompileringer | `/var/run/docker.sock`       | `/run/user/<uid>/podman/podman.sock`                                                     |
| Porte                            | Alle, for eksempel `80` og `443`     | `1024` og derover, for eksempel `8080`                                                   |
| Værtens firewall (`firewalld`)   | Omgås af publicerede porte           | Gælder: åbn porten med `firewall-cmd`                                                    |
| Start efter genstart             | Docker-daemonen genstarter dem       | Brugertjenesten `podman-restart`                                                         |
| SELinux                          | Ikke konfigureret af Toolkit         | Politikmodulet `podman_socket_clsi` og `SELINUX_MODE=managed` i `config/overleaf.rc`      |
| Seccomp-profil til kompileringer | Indbygget i imaget                   | Udtrækkes til `config/seccomp/<version>/` og sættes som `SECCOMP_PROFILE` af Toolkit     |

### Kendte begrænsninger {#known-limitations}

* <strong>Git-integration.</strong> I Ayakaleaf Pro 6.3.4 fejler `git clone` med `502` på Podman: NGINX inde i imaget slår `git-bridge`-containeren op med Dockers DNS-server (`127.0.0.11`), som Podman ikke har. Rettelsen ([1b911d1092](https://github.com/ayaka-notes/ayakaleaf-pro/commit/1b911d1092c80f7b0ff77c5e3805b40503d49964)) kommer med næste udgivelse; indtil da skal du beholde `GIT_BRIDGE_ENABLED=false`.
* <strong>Klienters IP-adresser.</strong> Rootless Podman videresender den publicerede port fra containerens netværk, så Ayakaleaf Pro ser alle besøgende med en intern adresse som `10.89.0.15`. En brugers [revisionslogs](/da/on-premises/user-guide/administrators/user-management#audit-logs) i administrationspanelet viser denne adresse i stedet for brugerens IP-adresse.
