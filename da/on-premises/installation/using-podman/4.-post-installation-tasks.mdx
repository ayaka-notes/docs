### Opret din første administratorkonto {#create-your-first-administrator-account}

Åbn [http://localhost:8080/launchpad](http://localhost:8080/launchpad), eller din `OVERLEAF_SITE_URL` efterfulgt af `/launchpad`, og registrer administratorkontoen. Herfra fungerer alt som med Docker: følg [6. Opgaver efter installationen](/da/on-premises/installation/using-docker-compose/linux/6.-post-installation-tasks) i Docker-vejledningen, og brug port `8080` i dens `localhost`-links.

Opret eksempelprojektet, og kompiler det. PDF'en viser, at kompileringer kører i deres TeX Live-containere gennem Podman. Sådan ser du kompileringscontaineren:

```bash title="List the compile containers"
podman ps -a --filter name=project- --format "{{.Names}} {{.Image}} {{.Status}}"
```

### Brug HTTPS {#use-https}

Toolkits [TLS-proxy](/da/on-premises/configuration/overleaf-toolkit/tls-proxy) virker på Podman: kør `bin/init --tls`, og sæt dit certifikat og `NGINX_ENABLED=true` som beskrevet der. Den lytter på portene `80` og `443`, som rootless Podman som standard ikke må bruge. Tillad uprivilegerede brugere at bruge porte fra `80` og opefter:

```bash title="Allow ports 80 and 443"
echo "net.ipv4.ip_unprivileged_port_start=80" | sudo tee /etc/sysctl.d/99-unprivileged-ports.conf
sudo sysctl --system
```

Det lader alle brugere på serveren lytte på disse porte, så gør det kun på en server, der er dedikeret til Ayakaleaf Pro. Åbn dem derefter i firewallen:

```bash title="Open ports 80 and 443"
sudo firewall-cmd --permanent --add-port=80/tcp --add-port=443/tcp
sudo firewall-cmd --reload
```

Sæt `OVERLEAF_SITE_URL` til din `https://`-adresse, og kør `bin/up -d`. Behold standardværdierne `NGINX_HTTP_PORT=80` og `TLS_PORT=443`: med andre porte fører omdirigeringen fra HTTP til HTTPS til den forkerte port.

<Info>

Lad `OVERLEAF_LISTEN_IP` stå på `127.0.0.1`, når du bruger TLS-proxyen, så port `8080` ikke kan nås fra andre computere.

</Info>

### Opgrader {#upgrade}

Opgrader med `bin/upgrade`, som beskrevet i [Opgradering af din udrulning](/da/on-premises/maintenance/upgrading-your-deployment). På Podman udtrækker den også seccomp-profilen for den nye version til `config/seccomp/<version>/` og opdaterer `SECCOMP_PROFILE`:

```text
Over-writing config/version with 6.3.4
Set SECCOMP_PROFILE=/home/<user>/overleaf-toolkit/config/seccomp/6.3.4/clsi-profile.json in config/variables.env
```

Efter en opgradering skal du køre `bin/podman-setup` for at tjekke opsætningen.

### Skift SELinux-tilstand {#change-the-selinux-mode}

`SELINUX_MODE` i `config/overleaf.rc` bestemmer, hvordan SELinux begrænser `sharelatex`-containeren. `managed` er den tilstand, disse sider sætter op; de andre tilstande er beskrevet i [Toolkit-indstillinger](/da/on-premises/configuration/overleaf-toolkit/toolkit-settings). Kør `bin/up -d` efter at have ændret den.
