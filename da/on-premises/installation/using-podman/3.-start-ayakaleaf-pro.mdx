---
title: 3. Start Ayakaleaf Pro
description: Start Ayakaleaf Pro på Podman, bekræft det med podman-setup og bin/doctor, og start det efter genstarter.
icon: circle-play
---

<Steps>
<Step title="Start containerne">
```bash title="Start Ayakaleaf Pro"
bin/up -d
```

Den første start downloader MongoDB-, Redis- og TeX Live-images og opretter datamapperne i `data/`. Den udskriver en advarsel om, at Podman-understøttelse er eksperimentel.

<Info>

Den første start kan også udskrive `MongoNetworkError: connect ECONNREFUSED 127.0.0.1:27017`. Toolkit sætter MongoDB-replikasættet op, mens MongoDB stadig starter, og prøver igen, indtil den svarer. Du kan ignorere denne linje.

</Info>

Efter et minut eller to skal du tjekke, at containerne kører:

```bash title="List the containers"
podman ps --format "{{.Names}} {{.Status}}"
```

```text
mongo Up 34 seconds (healthy)
redis Up 20 seconds
sharelatex Up 20 seconds
```
</Step>

<Step title="Tjek opsætningen igen">
Nu hvor datamapperne findes, og `sharelatex`-containeren kører, kan `bin/podman-setup` gøre sine tjek færdige:

```bash title="Check the setup"
bin/podman-setup
```

Det tjekker ejerne af de nye datamapper og tester Podman-socketten inde fra `sharelatex`-containeren:

```text
====== Socket Connectivity ======
[✓] host → socket OK
[✓] container → socket OK

====== Data Directory Permissions ======
[✓] mongo data dir owned by 999
[✓] redis data dir owned by 999
[✓] overleaf data dir owned by 33
...
====== Summary ======
[✓] 27 passed  [!] 1 warnings  [✗] 0 failures
[!] Warnings:
[!] not logged in to quay.io
```

`container → socket OK` betyder, at Ayakaleaf Pro kan starte kompileringscontainere. Hvis et tjek fejler, så kør `bin/podman-setup --apply` og derefter `bin/up -d`. quay.io-advarslen gælder ikke for Ayakaleaf Pro, se [2. Kør podman-setup](/da/on-premises/installation/using-podman/2.-run-podman-setup).
</Step>

<Step title="Kør doctor">
```bash title="Run the doctor"
bin/doctor
```

På Podman viser rapporten runtime og sikkerhedsindstillingerne:

```text
- Container Daemon
    - status: up
    - runtime: podman
    - server version: 5.8.5
    - socket: /run/user/1000/podman/podman.sock
    - DOCKER_HOST: unix:///run/user/1000/podman/podman.sock
    - host → socket: OK
    - container → socket: OK
- Security
    - SELinux: Enforcing
    - SELINUX_MODE: managed
    - SELINUX_LABEL: sharelatex_t
    - SELinux module: loaded (podman_socket_clsi)
    - SELinux rules: present
    - Seccomp profile: present
```

Advarslen `Server Pro enabled, but not logged in to quay.io repository` til sidst er det samme quay.io-tjek, se [Få hjælp](/da/on-premises/support/getting-help#q-and-a).
</Step>

<Step title="Start Ayakaleaf Pro efter en genstart">
Med Docker starter Docker-daemonen containerne igen efter en genstart. Rootless Podman har ingen daemon: aktiver brugertjenesten, der starter dine containere, når serveren starter:

```bash title="Start the containers at boot"
systemctl --user enable podman-restart.service
```

Den starter alle din brugers containere, hvis genstartspolitik er `always`, som Toolkit sætter for alle sine containere. Det kræver lingering, som `bin/podman-setup --apply` har aktiveret. Uden denne tjeneste skal du køre `bin/up -d` efter hver genstart.
</Step>

<Step title="Åbn porten i firewallen">
Som standard accepterer instansen kun forbindelser fra selve serveren, på `http://localhost:8080`. For at åbne den for andre computere skal du sætte `OVERLEAF_LISTEN_IP` i `config/overleaf.rc` og `OVERLEAF_SITE_URL` i `config/variables.env` som beskrevet i [5. Tilpasning af din instans](/da/on-premises/installation/using-docker-compose/linux/5.-personalizing-your-instance#listen-address-and-port) og køre `bin/up -d` igen.

I modsætning til Docker omgår rootless Podman ikke værtens firewall. Hvis `firewalld` kører, hvilket er standard på RHEL, skal du åbne porten:

```bash title="Open port 8080"
sudo firewall-cmd --permanent --add-port=8080/tcp
sudo firewall-cmd --reload
```

På en cloudserver skal du også tillade porten i udbyderens sikkerhedsgruppe. Brug HTTPS, før du eksponerer instansen på internettet, se [4. Opgaver efter installationen](/da/on-premises/installation/using-podman/4.-post-installation-tasks#use-https).
</Step>
</Steps>
