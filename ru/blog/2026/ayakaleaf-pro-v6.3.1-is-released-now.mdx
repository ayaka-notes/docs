Мы с большой гордостью объявляем о выпуске Overleaf Pro 6.3.1 — самого мощного и функционального онлайн-редактора LaTeX в сообществе. Патч-выпуск обычно означает несколько мелких исправлений. Этот идёт гораздо дальше: помимо десятков исправлений ошибок, он приносит пять новых функций и связывает ваши проекты с тем, где вы уже работаете, — от Dropbox и GitLab до ИИ-агента в вашем терминале.

### Изменения

* Синхронизация с Dropbox (ранняя предварительная версия): поддерживайте каждый проект в синхронизации с вашим собственным Dropbox в обоих направлениях.
* Синхронизация с GitLab (ранняя предварительная версия): двусторонняя синхронизация с GitLab.com или вашим собственным экземпляром GitLab.
* MCP Server: позвольте Claude Code, Codex, Cursor, VS Code или Gemini CLI работать с проектом напрямую.
* GitHub Enterprise: направьте GitHub Sync на ваш собственный экземпляр GitHub Enterprise.
* Распознавание рукописных символов: нарисуйте символ и получите команду LaTeX.
* `OVERLEAF_DISABLE_LOCAL_LOGIN`: скройте вход по электронной почте и паролю, чтобы пользователи входили только через SSO.
* Исправления ошибок, найденных нашей системой E2E-тестирования и в рамках Internal Horizon Issue Investigation.
* Патчи upstream Overleaf 6.3.1.

<Info>

Синхронизация с Dropbox и синхронизация с GitLab поставляются в 6.3.1 как **ранние предварительные версии** для поэтапного (gray) тестирования и будут официально выпущены в v6.4.0. До этого их конфигурация и поведение ещё могут измениться. Обе функции по умолчанию отключены. Пожалуйста, сообщайте о любых проблемах на [GitHub](https://github.com/ayaka-notes/ayakaleaf-pro/issues).

</Info>

#### Функция 01: синхронизация с Dropbox (предварительная версия)

Некоторые люди вообще не хотят думать о Git. Им просто нужно, чтобы их диссертация была папкой на ноутбуке, и синхронизация с Dropbox даёт им именно это. Каждый пользователь привязывает свою учётную запись Dropbox, и принадлежащие ему проекты, а также проекты, к которым ему предоставлен доступ, появляются в `Apps/<your app name>/`. Отредактируйте файл в Overleaf — изменение появится в Dropbox. Отредактируйте файл локально в любимом редакторе, сохраните его — и изменение вернётся в Overleaf через подписанный webhook.

Для администраторов: должен быть включён Git bridge. Создайте приложение в Dropbox App Console, затем задайте `DROPBOX_ENABLED`, `DROPBOX_APP_KEY`, `DROPBOX_APP_SECRET`, `DROPBOX_APP_NAME` и `DROPBOX_TOKEN_CIPHER_PASSWORD`. `DROPBOX_SYNC_PROXY_URL` необязателен и нужен для серверов, которые не могут обращаться к Dropbox напрямую. Затем один раз, до того как пользователи привяжут свои учётные записи, создайте индексы MongoDB, необходимые для синхронизации с Dropbox.

Полные инструкции по настройке см. в разделе [Синхронизация с Dropbox](/ru/on-premises/configuration/overleaf-toolkit/dropbox-synchronisation  "mention").

#### Функция 02: синхронизация с GitLab (предварительная версия)

GitHub Sync — одна из самых любимых функций начиная с 6.2, но многие университеты и компании хранят свой код в GitLab. Синхронизация с GitLab работает так же: привяжите свою учётную запись, импортируйте репозиторий из меню нового проекта или экспортируйте проект в новый проект GitLab. Затем выполняйте push и pull прямо из редактора и выполняйте слияние через merge requests.

Она работает с GitLab.com и с собственными экземплярами GitLab версии 15.10 или новее. Задайте `GITLAB_SYNC_ENABLED`, `GITLAB_SYNC_CLIENT_ID`, `GITLAB_SYNC_CLIENT_SECRET` и `GITLAB_TOKEN_CIPHER_PASSWORD`, а для собственного экземпляра — также `GITLAB_SYNC_URL`.

Полные инструкции по настройке см. в разделе [Синхронизация с GitLab](/ru/on-premises/configuration/overleaf-toolkit/gitlab-synchronisation  "mention").

#### Функция 03: MCP Server

В 6.3 мы встроили ИИ-ассистента в редактор. В 6.3.1 мы открываем дверь в обратную сторону: теперь у каждого проекта есть собственный MCP-сервер, поэтому ИИ-агент, которым вы уже пользуетесь, может работать с вашей статьёй напрямую. Попросите Claude Code исправить опечатки во введении, попросите Codex скомпилировать проект и исправить ошибки LaTeX или попросите Cursor ответить на открытые комментарии рецензентов. Агент читает и редактирует файлы в реальном времени, поэтому вы и ваши соавторы видите, как его правки появляются в редакторе по мере ввода. Он также может компилировать проект, читать лог, получать PDF, подсчитывать слова и выводить список версий.

Эндпоинт — `/project/<project_id>/mcp`. Для аутентификации используйте тот же Git-токен, что и для `git clone`. Доступ определяется настройками совместного доступа проекта, поэтому агент пользователя с правами только на просмотр может читать, но не редактировать, а каждый инструмент ограничен по частоте запросов. Больше ничего настраивать не нужно: MCP-сервер включается вместе с Git bridge.

#### Функция 04: GitHub Enterprise

GitHub Sync больше не ограничен github.com. Укажите в `GITHUB_SYNC_URL` адрес вашего GitHub Enterprise Server или GitHub Enterprise Cloud с размещением данных (`GHE.com`), и эндпоинты REST и GraphQL будут определены на его основе. Если ваш экземпляр устроен необычно, переопределите их с помощью `GITHUB_SYNC_API_URL` и `GITHUB_SYNC_GRAPHQL_URL`. Если не задавать эти переменные, всё останется на github.com.

Подробнее см. в разделе [Синхронизация с GitHub](/ru/on-premises/configuration/overleaf-toolkit/github-synchronisation#github-enterprise  "mention").

#### Функция 05: распознавание рукописных символов

Вы знаете, как выглядит символ, но не знаете, как он называется. Это `\varsigma` или `\zeta`? `\models` или `\vDash`? Переключите палитру символов в режим рисования, нарисуйте символ мышью или трекпадом, и палитра предложит подходящие команды LaTeX.

Распознавание полностью выполняется в браузере с помощью модели, обученной ayaka-notes, поэтому ничего из нарисованного вами не покидает ваш компьютер. Переключатель рисования скрыт в браузерах без `OffscreenCanvas` (например, Safari 15).

#### Исправления ошибок

Этот выпуск также содержит длинный список исправлений. Многие из них были найдены нашей новой системой E2E-тестирования, которая теперь ежедневно запускает наборы тестов для каждого модуля, а также в рамках Internal Horizon Issue Investigation: каждый раз, исправляя ошибку, мы проверяем всю кодовую базу на наличие похожих ошибок, прежде чем закрыть её.

* **Аутентификация**: локальные учётные записи могут задавать и менять пароль на экземплярах с SSO, а пользователи OIDC больше не могут сами менять свой адрес электронной почты. Вход через LDAP, SAML и OIDC больше не завершается ошибкой, когда атрибут имени имеет несколько значений, а выход из SAML/OIDC снова работает.
* **Заблокированные пользователи**: блокировка пользователя теперь завершает его сеансы и закрывает открытые им редакторы, а его Git-токены и загрузки через MCP отклоняются.
* **GitHub Sync**: экспортировать проект может только владелец, правки, сделанные во время pull, остаются в ожидании, пустые файлы синхронизируются, а ручные слияния проверяются на GitHub.
* **Zotero / Mendeley**: когда ваши учётные данные перестают работать, вы получаете сообщение с предложением повторно привязать учётную запись, а после импорта ссылки переиндексируются.
* **Внешние сервисы**: запросы к Zotero, Mendeley, GitHub, GitLab и веб-поиску получают тайм-аут подключения 3 с вместо 1 с, поэтому в более медленных сетях они больше не завершаются ошибкой.
* **Отслеживание изменений**: данные рецензирования включают незагруженные документы и несохранённые изменения.
* **Панель администратора**: восстановление удалённых проектов, смена владельцев и редактирование пользователей работают корректно, а сбой отправки письма больше не нарушает создание или удаление учётной записи.
* **Галерея шаблонов**: недопустимая сортировка возвращает 400 вместо 500, а при публикации проекта без основного файла предлагается его указать.

Полный список см. в [примечаниях к выпуску 6.3.1](/ru/on-premises/release-notes/release-notes-6.x.x#ayakaleaf-pro-6.3.1  "mention").

#### Обновление

* С 6.3.0: миграция не требуется. Загрузите новый образ и перезапустите.
* С 6.2.x или более ранних версий при использовании Zotero или Mendeley: сначала выполните [миграцию Zotero / Mendeley](/ru/on-premises/release-notes/release-notes-6.x.x#ayakaleaf-pro-6.3.0  "mention") из 6.3.0.
* Синхронизация с Dropbox и синхронизация с GitLab по умолчанию отключены. Для синхронизации с GitLab нужны только новые переменные окружения. Для синхронизации с Dropbox также необходимо один раз, до того как пользователи привяжут свои учётные записи, создать её индексы MongoDB: см. [Создание индексов базы данных](/ru/on-premises/configuration/overleaf-toolkit/dropbox-synchronisation#create-the-database-indexes  "mention").
