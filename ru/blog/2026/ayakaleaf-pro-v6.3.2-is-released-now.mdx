Мы с большой гордостью объявляем о выпуске Overleaf Pro 6.3.2. Upstream Overleaf 6.3.2 — это выпуск безопасности, обновляющий Node.js, и мы поставляем его вместе с новым участником семейства синхронизаций: после GitHub, GitLab и Dropbox ваши проекты теперь могут жить и в Gitea.

* Node.js 24.22.1: обновление безопасности из upstream Overleaf 6.3.2.
* Исправления ошибок, найденных нашей системой E2E-тестирования и в рамках Internal Horizon Issue Investigation.

#### Функция 01: синхронизация с Gitea (предварительная версия)

Многие лаборатории и небольшие команды используют собственный Gitea, потому что он достаточно лёгкий для одного небольшого сервера. Синхронизация с Gitea работает так же, как GitHub Sync и синхронизация с GitLab: привяжите свою учётную запись, импортируйте репозиторий из меню нового проекта или экспортируйте проект в новый репозиторий Gitea. Затем выполняйте push и pull прямо из редактора и выполняйте слияние через pull requests с использованием стиля слияния, заданного в репозитории. Overleaf никогда не обходит защиту ваших веток: если для pull request требуются одобрения или успешные проверки, он ждёт, пока вы выполните слияние в Gitea.

Она работает с gitea.com и с собственными экземплярами Gitea версии 1.23 или новее. Задайте `GITEA_SYNC_ENABLED`, `GITEA_SYNC_CLIENT_ID`, `GITEA_SYNC_CLIENT_SECRET` и `GITEA_TOKEN_CIPHER_PASSWORD`, а для собственного экземпляра — также `GITEA_SYNC_URL`.

Полные инструкции по настройке см. в разделе [Синхронизация с Gitea](/ru/on-premises/configuration/overleaf-toolkit/gitea-synchronisation  "mention").

#### Исправления ошибок

* **Git-синхронизация**: если файл, удалённый в GitHub, GitLab или Gitea, не удаётся удалить в Overleaf, синхронизация теперь завершается ошибкой и может быть повторена, вместо того чтобы сообщать об успехе и оставлять файл. `git push`, удаляющий файл, завершается ошибкой так же.
* **Git bridge**: документ с нетекстовым расширением (например, `.csv`), созданный в редакторе, остаётся редактируемым, когда его изменяет `git push`.
* **Отслеживание изменений**: неавторизованные редакторы проекта с доступом по ссылке могут удалять ветки комментариев, но больше не могут разрешать или повторно открывать их, а рецензенты могут удалять собственные ответы.
* **Галерея шаблонов**: для публикации шаблона требуется доступ к проекту.
* **Learn**: кешированные страницы справки остаются доступными, когда wiki недоступна.

Полный список см. в [примечаниях к выпуску 6.3.2](/ru/on-premises/release-notes/release-notes-6.x.x#ayakaleaf-pro-6.3.2  "mention").

#### Обновление

* С 6.3.1 или 6.3.0: миграция не требуется. Загрузите новый образ и перезапустите.
* С 6.2.x или более ранних версий при использовании Zotero или Mendeley: сначала выполните [миграцию Zotero / Mendeley](/ru/on-premises/release-notes/release-notes-6.x.x#ayakaleaf-pro-6.3.0  "mention") из 6.3.0.
* Синхронизация с Gitea по умолчанию отключена, и для неё нужны только новые переменные окружения.
