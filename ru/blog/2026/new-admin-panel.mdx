Когда вы обслуживаете экземпляр Overleaf для лаборатории или кафедры, каждую неделю возникают одни и те же вопросы. Почему этот студент не может войти? Кто ещё пользуется сервером? Кто выдал той учётной записи права администратора? Куда делась прошлогодняя диссертация? Мы заново создали панель администратора, чтобы вы могли отвечать на эти вопросы, не открывая оболочку базы данных.

Новая панель выполнена в стиле Overleaf 6.3 и переведена на все языки, которые поддерживает интерфейс. В ней есть список всех пользователей, список всех проектов, страница для каждого из них, место для управления шаблонами и журналы аудита.

<Info>

Новая панель администратора влита в нашу основную ветку и будет официально выпущена в v6.4.0. Все снимки экрана в этой статье сделаны на тестовом экземпляре с вымышленными учётными записями.

</Info>

### Что в ней есть {#what’s-in-it}

* **Список пользователей**: поиск, фильтры по способу входа, роли и статусу, массовые действия.
* **Страница пользователя**: учётная запись, проекты, функции, интеграции, журналы аудита и сеансы одного человека.
* **Список проектов**: все проекты экземпляра с поиском по имени, ID, владельцу или ссылке для общего доступа.
* **Страница проекта**: настройки, файлы, участники, удалённые файлы и журналы аудита одного проекта.
* **Управление шаблонами**: публикуйте проект как шаблон, обновляйте его и поддерживайте порядок в галерее.
* **Журналы аудита**: кто, что, когда и с какого IP-адреса сделал.

## Один список для всех пользователей {#one-list-for-every-user}

Нажмите **Admin**, затем **Manage Users**. Каждая учётная запись занимает одну строку, где видно, как она входит в систему, её роль и статус.

</Frame>

Ищите по имени, адресу электронной почты или ID. Заголовки **Login**, **Role** и **Status** служат фильтрами, и у каждого варианта показано, сколько учётных записей он вернёт. Вы сразу видите, сколько людей входит через SAML, а каждый поставщик OIDC отображается под именем, которое вы ему дали.

<Frame caption="Фильтр по способу входа">
  <img src="/images/blog/admin-panel-users-login-filter.png" alt="Открытый фильтр Login с числом учётных записей для Password, LDAP, SAML и Keycloak" />
</Frame>

У каждой учётной записи ровно один статус, и сумма четырёх статусов равна общему числу.

| Статус       | Что он означает                                                            |
| ------------ | -------------------------------------------------------------------------- |
| **Active**   | Входила в систему или открывала проект за последние 12 месяцев.            |
| **Pending**  | Ни разу не входила в систему.                                              |
| **Inactive** | Входила раньше, но не за последние 12 месяцев.                             |
| **Disabled** | Администратор запретил учётной записи входить в систему.                   |

Удалённые учётные записи не мешают: у них свой фильтр. Если поиск совпадает и с удалённой учётной записью, строка над таблицей сообщает об этом и предлагает её показать.

<Frame caption="Фильтр по статусу">
  <img src="/images/blog/admin-panel-users-status-filter.png" alt="Открытый фильтр Status с числом учётных записей для каждого статуса" />
</Frame>

Поиск, сортировка и разбивка на страницы выполняются на сервере, поэтому списки больше не обрываются на первых 1000 строках.

### Добавляйте людей с электронной почтой или без неё {#bring-people-in-with-or-without-email}

**Create account** добавляет пользователя и даёт вам нужную ему ссылку. Если [доставка электронной почты](/ru/on-premises/configuration/overleaf-toolkit/email-delivery  "mention") не настроена, диалог прямо говорит об этом и позволяет скопировать ссылку, так что даже небольшой экземпляр может принимать новых людей.

<Frame caption="Ссылка активации новой учётной записи">
  <img src="/images/blog/admin-panel-create-account.png" alt="Диалог Create account для Tom Berg с предупреждением, что письмо не отправлено, ссылкой активации, значком копирования и Expires in 7 days" />
</Frame>

Панель предлагает подходящую ссылку для каждой учётной записи: **Send activation email** для той, что ни разу не входила, действует 7 дней, и **Send reset link** для той, что уже входила, действует 1 час. У учётных записей, которые входят через SSO, нет локального пароля, поэтому они не получают ни одну из ссылок.

### Изменяйте много учётных записей сразу {#change-many-accounts-at-once}

Отметьте несколько учётных записей, и на панели инструментов появятся **Send activation email**, **Transfer this user's projects**, **Disable**, **Enable**, **Make admin**, **Remove admin** и **Delete account**. Перед подтверждением диалог показывает список учётных записей. Если для некоторых действие не удалось, он сообщит, для каких, а то, что уже сработало, останется выполненным.

<Frame caption="Массовые действия">
  <img src="/images/blog/admin-panel-users-bulk.png" alt="Три отмеченные учётные записи и кнопки массовых действий рядом с Create account" />

### Трудно ошибиться {#hard-to-get-wrong}

* Ваша собственная учётная запись помечена **You**, а её действия неактивны, поэтому вы не можете отключить, удалить или понизить себя.
* Каждое действие требует подтверждения в диалоге, где указана учётная запись.
* **Delete account** может сначала передать проекты пользователя кому-то другому.
* Удалённую учётную запись можно восстановить вместе с проектами, удалёнными вместе с ней. Окончательно только **Delete permanently**, и оно предупреждает вас.

## Управление шаблонами {#template-management}

Шаблон начинается как обычный проект. Вы публикуете его из редактора и управляете им на его странице в галерее или в панели администратора.

### Все шаблоны в одной таблице {#all-templates-in-one-table}

Нажмите **Admin**, затем **Project/Object Lookup**, затем вкладку **Templates**. На ней перечислены все опубликованные шаблоны с автором, владельцем и временем последнего изменения, и по ней можно искать. Нажмите на название, чтобы открыть шаблон, на владельца, чтобы открыть страницу этого пользователя, или на корзину, чтобы удалить шаблон. Удаление записывается в [ваш собственный журнал аудита](#when-there-is-no-log-left).

<Frame caption="Все шаблоны в панели администратора">
  <img src="/images/blog/admin-panel-templates.png" alt="Вкладка Templates со списком опубликованных шаблонов, их авторов, владельцев и дат последнего изменения" />

Откройте проект и компилируйте его, пока PDF не станет правильным, потому что галерея показывает PDF последней успешной компиляции. Затем нажмите **File**, потом **Manage Template** и заполните название, автора, категорию, описание в Markdown и лицензию. Компилятор и главный документ проекта переходят в шаблон, поэтому проекты, открытые из него, используют те же.

## Журналы аудита: кто, что и когда сделал {#audit-logs-who-did-what-and-when}

Этой частью мы довольны больше всего. Теперь у каждой учётной записи и каждого проекта есть собственный журнал аудита, и администраторы сайта могут читать его прямо в панели.

Откройте вкладку **Audit logs** на странице пользователя. Новые записи идут первыми.

<Frame caption="Журнал аудита учётной записи">
  <img src="/images/blog/admin-panel-audit-user.png" alt="Журнал аудита Lena Fischer со списком её входов и изменений, внесённых администратором в её функции, доступ к ИИ, роль администратора и сеансы" />
</Frame>

Если читать снизу вверх, эта страница рассказывает историю. Лена вошла в систему. Администратор увеличил её тайм-аут компиляции до 300 секунд, отключил ей доступ к ИИ, отправил ссылку для сброса пароля, сделал её администратором и отменил это, затем отключил и снова включил учётную запись. Лена снова вошла, и администратор очистил её сеансы.

| Столбец        | Что он сообщает                                                                                              |
| -------------- | ------------------------------------------------------------------------------------------------------------ |
| **Date**       | Когда это произошло.                                                                                         |
| **Operation**  | Что произошло.                                                                                               |
| **Initiator**  | Кто это сделал. Для действий администратора с учётной записью показан администратор, а не пользователь.      |
| **IP Address** | Откуда пришёл запрос.                                                                                        |
| **Info**       | Подробности, например новый тайм-аут компиляции или было ли письмо действительно отправлено.                 |

### Найдите нужную запись {#find-the-entry-you-need}

Ищите по операции или IP-адресу. Заголовок **Operation** служит фильтром, который перечисляет все операции в этом журнале и сколько раз каждая произошла.

### Что записывается {#what-gets-recorded}

Вот основные операции каждого журнала под теми названиями, которые вы видите в панели.

| Журнал         | Область                     | Операции                                                                                                                                                                                                                                    |
| -------------- | --------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Учётная запись | Вход и пароль               | Login, Logout, Failed password match, Update password, Reset password                                                                                                                                                                       |
| Учётная запись | Почта и SSO                 | Add email, Remove email, Change primary email, Link SSO, Unlink SSO                                                                                                                                                                         |
| Учётная запись | Интеграции                  | Link GitHub, Unlink GitHub, Link Dropbox, Unlink Dropbox, Integration account linked, Integration account unlinked, Create Git token, Delete Git token                                                                                      |
| Учётная запись | Действия администраторов    | Create account, Send activation email, Send password reset email, Change name, Change admin access, Change features, Change AI features, Reset AI usage, Account suspension, Account reactivation, Clear sessions, Transfer projects, Delete account, Restore account |
| Проект         | Общий доступ                | Send invite, Resend invite, Revoke invite, Accept invite, Join via token, Accept via link sharing, Remove collaborator, Leave project, Project role changed, Toggle access level, Transfer ownership                                       |
| Проект         | Файлы                       | Project downloaded, Project exported docx, Project exported markdown, Project exported html, Restore deleted doc                                                                                                                            |
| Проект         | Действия администраторов    | Project deleted, Project restored                                                                                                                                                                                                           |
| Проект         | Синхронизация Git           | Integration repo linked, Integration repo unlinked                                                                                                                                                                                          |

### Когда журнала больше нет {#when-there-is-no-log-left}

**Delete permanently** удаляет учётную запись или проект вместе с журналом, а у шаблона журнала никогда не было. Поэтому такие действия записываются в журнал администратора, который их выполнил, вместе с адресом электронной почты или ID удалённого объекта.

### Полезно знать {#good-to-know}

* Записи хранятся два с половиной года, после чего MongoDB удаляет их автоматически.
* За обратным прокси задайте [`OVERLEAF_TRUSTED_PROXY_IPS`](/ru/on-premises/configuration/overleaf-toolkit/environment-variables  "mention"), чтобы журнал показывал адрес посетителя, а не прокси.
* Пока записывается не всё. Git clone и push, изменения настроек проекта, таких как имя или компилятор, а также проекты, которые владелец создаёт, архивирует, перемещает в корзину или удаляет, не отображаются в журнале проекта.
