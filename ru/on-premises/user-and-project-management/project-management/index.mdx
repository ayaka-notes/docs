### Просмотр журнала аудита проекта

Администраторы могут просматривать **журнал аудита** (Audit Log) каждого проекта. В этом журнале отображаются такие события, как переключение общего доступа по ссылке между закрытым режимом и режимом на основе токенов, отправка и принятие приглашений, а также присоединение пользователя к проекту по токену. Администраторы могут просматривать эти журналы для каждого проекта отдельно через **Your Instance** -> **Admin** -> **Manage Users**, а затем:

* Найдите пользователя
* Откройте вкладку **Projects**
* Выберите проект
* Нажмите на значок (i)
* Откройте вкладку **Audit Log**

Если проект открыт для конкретного соавтора (по его адресу электронной почты), то после того как получатель присоединится, он будет указан в окне Share вместе со своими правами доступа и будет виден владельцу проекта. Эти сведения также отображаются администраторам при просмотре вкладки Project Info проекта в панели администратора.

### Восстановление удалённых документов

1. Войдите в систему с учётными данными администратора
2. Нажмите **Admin** и выберите **Manage Users**
3. В поле поиска введите адрес электронной почты пользователя, для которого нужно восстановить документ
4. Нажмите на его адрес электронной почты в списке результатов, чтобы открыть страницу сведений о пользователе
5. Откройте вкладку **Projects** и найдите проект с помощью поля поиска
6. Нажмите на значок информации рядом с названием проекта, чтобы открыть **Project Info**
7. Откройте вкладку **Deleted Docs**
8. Нажмите кнопку **Undelete** рядом с удалённым документом, чтобы восстановить его в проекте пользователя.

Восстановленный файл будет иметь имя в формате `FILENAME-TIMESTAMP.EXTENSION`. Например, восстановленная версия `main.tex` будет помещена в корень проекта под именем `main-2024-02-23-130441542.tex`.

### Передача прав владения проектом

В панели администратора Server Pro для каждого проекта есть отдельная страница. Попасть на неё можно, найдя пользователя на "/admin/user", перейдя на его вкладку **Projects**, найдя проект в списке и нажав на значок информации; либо перейдя напрямую на страницу с известным project-id [**https://your-instance-url/admin/project/**](https://your-instance-url/admin/project/). На странице сведений о проекте есть кнопка **Transfer Ownership**, которая открывает окно, где можно указать любого пользователя в качестве нового владельца. Новый владелец не обязательно должен быть соавтором проекта.

<Info>

Обратите внимание, что в процессе передачи прав владения предыдущий владелец будет добавлен в проект в качестве соавтора с правами на чтение и запись.

</Info>

### Изменение тайм-аута компиляции проекта

По умолчанию тайм-аут компиляции проектов в настоящее время составляет 180 секунд. Это значение можно изменить; для этого нужно выполнить два шага.

Сначала отредактируйте файл **config/variables.env**: добавьте переменную окружения `COMPILE_TIMEOUT` и задайте ей нужное значение тайм-аута в секундах. Например, `COMPILE_TIMEOUT=300` для 5 минут.

<Danger>

Увеличивать тайм-аут более чем до 10 минут не имеет смысла. В этом случае вы, скорее всего, упрётесь в тайм-аут другого компонента приложения.

</Danger>

После внесения этого изменения необходимо пересоздать контейнер **sharelatex**, выполнив команду `bin/up -d`.

Установка этой переменной окружения обновит значение тайм-аута только для новых пользователей: к существующим пользователям оно **не** применяется задним числом, поскольку задаётся при первоначальном создании пользователя.

Чтобы изменить тайм-аут для существующих пользователей, необходимо изменить запись каждого пользователя в базе данных. Мы советуем делать это очень осторожно и рекомендуем создать согласованную резервную копию перед внесением каких-либо изменений.

Сведения о создании резервных копий можно найти [здесь](/ru/on-premises/maintenance/data-and-backups).

Чтобы обновить значение тайм-аута компиляции для всех существующих пользователей, выполните на хосте Docker следующую команду оболочки:

```bash wrap
echo 'db.users.updateMany({}, {$set: {"features.compileTimeout": <value>}})' | docker exec -i mongo mongosh --quiet localhost/sharelatex
```

Замените `<value>` в приведённом выше запросе нужным значением тайм-аута в секундах.

После выполнения команды вы увидите подтверждение с количеством изменённых записей. Затем можно ввести exit и нажать Enter, чтобы вернуться в оболочку хоста.

### Отслеживание доступа к проектам

Узнать, кто и когда открывал проект, можно с помощью следующей команды:

```bash wrap
docker exec sharelatex bash -c 'grep "join project request" /var/log/overleaf/web.log'
```

Она выведет `timestamp`, `user_id` и `project_id`.
