<Accordion title="Запуск Overleaf с файловой системой NFS">

Монтирование файловой системы NFS в контейнере Overleaf технически возможно, но не рекомендуется и может приводить к различным проблемам с производительностью.

Одна из типичных ошибок при компиляции:

```text
EBUSY: resource busy or locked, unlink '/var/lib/overleaf/data/compiles/62f3d57bef7cf9005c364e75-62f3d57bef7cf9005c364e7a/.nfs573663533034825247625441'
```

В частности, мы не рекомендуем использовать файловые системы на базе NFS для временных данных, например каталогов, используемых для данных компиляции. Для следующих каталогов рекомендуем использовать локальный рабочий диск, предпочтительно локальный SSD.

Для установок на основе `docker-compose` мы предлагаем просто переопределить bind-монтирование из NFS, что позволяет не менять пути в приложении. Вот пример фрагмента конфигурации `docker-compose` с использованием рабочего диска, смонтированного в `/scratch`:

```yaml title="docker-compose excerpt"
services:
  sharelatex:
    environment:
      SANDBOXED_COMPILES_HOST_DIR: /scratch/compiles/
    volumes:
      - nfs:/var/lib/overleaf/data
      - /scratch/cache/:/var/lib/overleaf/data/cache
      - /scratch/compiles/:/var/lib/overleaf/data/compiles
      - /scratch/output/:/var/lib/overleaf/data/output
      - /scratch/tmp/:/var/lib/overleaf/tmp
```

После обновления переносить существующие файлы из NFS в новое расположение не нужно. Компилятор LaTeX может заново создать все файлы при полной повторной компиляции.

Подробнее см.: https://docs.overleaf.com/on-premises/support/troubleshooting#running-overleaf-with-an-nfs-filesystem

</Accordion>

<Accordion title="При запуске Overleaf в Windows или macOS не запускается сервис `mongo`">

Если вы запускаете Overleaf в Windows или macOS, сервис `mongo` может не перезапуститься с ошибкой:

```text title="Example error"
Failed to start up WiredTiger under any compatibility version.
Reason: 1: Operation not permitted
```

Чтобы избежать этой ошибки, данные необходимо хранить в томе, а не в каталоге, подключённом через bind-монтирование (подробнее см. документацию образа `mongo`: https://github.com/docker-library/docs/blob/master/mongo/content.md#where-to-store-data). Чтобы хранить данные в томах Docker, смонтированных внутри контейнеров MongoDB и Redis, добавьте следующее в `config/docker-compose.override.yml` (создайте этот файл, если он ещё не существует):

```yaml title="config/docker-compose.override.yml"
volumes:
  mongo-data:
  redis-data:

services:
  mongo:
    volumes:
      - mongo-data:/data/db

  redis:
    volumes:
      - redis-data:/data
```

Подробнее см.: https://docs.overleaf.com/on-premises/support/troubleshooting#running-overleaf-on-windows-or-macos-results-in-the-mongoservice-not-starting

</Accordion>

<Accordion title="Обновление до Redis 6.2 приводит к циклу перезапусков">

Используйте команду `docker logs redis`, чтобы вывести копию журналов.

Если вы видите строку `Fatal: Can't initialize Background Jobs`, полный вывод будет выглядеть примерно так:

```text title="Redis log example"
1:M 11 Feb 2024 15:19:22.609 # Server initialized
1:M 11 Feb 2024 15:19:22.609 # Fatal: Can't initialize Background Jobs.
1:C 11 Feb 2024 15:19:26.055 # oO0OoO0OoO0Oo Redis is starting oO0OoO0OoO0Oo
```

Это может быть связано с используемой в данный момент версией Docker. Обновление до версии >= 20.10.10 должно решить эту проблему.

Подробнее см. issue в апстриме Redis: https://github.com/redis/redis/issues/12362

Источник: https://docs.overleaf.com/on-premises/support/troubleshooting#upgrading-to-redis-6.2-results-in-a-restart-loop

</Accordion>

<Accordion title="Неправильная ориентация изображений предпросмотра/миниатюр в галерее шаблонов">

Иногда изображения предпросмотра/миниатюр, генерируемые Server Pro, создаются с неправильной ориентацией, и для их исправления требуется ручное вмешательство. Эти изображения хранятся в `/var/lib/overleaf/data/template_files/` (>= 5.0.3) и `/var/lib/sharelatex/data/template_files/` (в более ранних версиях).

Перед внесением изменений рекомендуем создать резервную копию этой папки.

Для каждого затронутого шаблона необходимо выполнить следующие шаги:

Найдите ID шаблонаПерейдите в галерею шаблонов вашего экземпляра (/templates/all), откройте затронутый шаблон и скопируйте ID из URL (например: https://your-instance-url/templates/6645d346c224815e9460a695).Выполните команду исправленияВыполните следующую команду на Docker-хосте (замените ID шаблона на скопированный и при необходимости измените путь):docker exec sharelatex /bin/bash -c "mogrify -rotate 90 /var/lib/overleaf/data/template\_files/6645d346c224815e9460a695\_\*\{thumbnail,preview\}"

Источник: https://docs.overleaf.com/on-premises/support/troubleshooting#incorrect-orientation-of-template-gallery-preview-thumbnail-images

</Accordion>

<Accordion title="Убедитесь, что системные вызовы включены. Для pdflatex это 'pdflatex -shell-escape'.">

Команда `\write18` по умолчанию отключена в Community Edition, поскольку все компиляции выполняются в одном контейнере `sharelatex`; это более безопасное значение по умолчанию.

Если вы хотите включить её для pdflatex, создайте в корне проекта файл `latexmkrc` со следующим содержимым:

```perl title="latexmkrc"
$pdflatex = 'pdflatex --shell-escape';
```

Затем попробуйте перекомпилировать.

Источник: https://docs.overleaf.com/on-premises/support/troubleshooting#please-verify-that-you-have-enabled-system-calls.-for-pdflatex-this-is-pdflatex-shell-escape

</Accordion>
