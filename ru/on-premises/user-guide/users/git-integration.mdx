Работайте над проектом на своём компьютере с помощью Git. Изменения передаются только тогда, когда вы выполняете `git pull` или `git push`.

<Info>

Сначала администратор должен включить [интеграцию с Git](/ru/on-premises/configuration/overleaf-toolkit/integrations/git-integration).

</Info>

## Создание токена {#create-a-token}

Git входит в систему с помощью токена аутентификации Git, а не пароля вашей учётной записи.

<Steps>
<Step title="Откройте настройки учётной записи">
Нажмите **Account**, затем **Account settings**. В разделе **Git integration** нажмите **Generate token**. Когда у вас уже есть токен, эта кнопка называется **Add another token**.

<Frame caption="Интеграция с Git в настройках учётной записи">
  <img src="/images/on-premises/git-integration-settings.png" alt="Раздел Git integration в настройках учётной записи с кнопкой Generate token" />
</Frame>
</Step>

<Step title="Скопируйте токен">
Нажмите **Copy** и сохраните токен в надёжном месте. Он показывается только один раз. Затем нажмите **Close**.

<Frame caption="Ваш новый токен">
  <img src="/images/on-premises/git-integration-token.png" alt="Диалоговое окно токена аутентификации Git с кнопкой Copy" />
</Frame>
</Step>

<Step title="Проверьте токен">
Теперь в списке видно начало токена, время его создания и последнего использования. Срок действия токена истекает через год. У вас может быть до 10 токенов.

<Frame caption="Ваши токены">
  <img src="/images/on-premises/git-integration-tokens.png" alt="Список токенов с одним токеном" />
</Frame>
</Step>
</Steps>

## Клонирование проекта {#clone-a-project}

<Steps>
<Step title="Откройте интеграцию с Git в редакторе">
Откройте проект. На левой панели нажмите **Integrations**, затем **Git integration**.

<Frame caption="Панель Integrations">
  <img src="/images/on-premises/git-integration-panel.png" alt="Панель Integrations с карточкой Git integration" />
</Frame>
</Step>

<Step title="Скопируйте команду">
В диалоговом окне **Clone with Git** показана команда с адресом вашего сайта и ID проекта. Нажмите **Copy**. Если у вас ещё нет токена, **Go to settings** откроет настройки учётной записи в новой вкладке.

<Frame caption="Команда клонирования">
  <img src="/images/on-premises/git-integration-clone.png" alt="Диалоговое окно Clone with Git с командой git clone" />
</Frame>
</Step>

<Step title="Выполните её">
Вставьте команду в терминал. Когда Git запросит пароль, вставьте свой токен.

```text
$ git clone https://git@<your-site>/git/<project-id>
Cloning into '<project-id>'...
Password for 'https://git@<your-site>': <your-token>
```

Теперь папка с именем, равным ID проекта, содержит файлы проекта в ветке `main`. Чтобы выбрать имя папки, добавьте его в конец команды.
</Step>
</Steps>

Git запрашивает токен при каждом обращении к сайту. Чтобы он запомнился, включите credential helper: Git спросит ещё раз, а затем сохранит токен. Helper `store` хранит его в незашифрованном виде в `~/.git-credentials`.

```bash
git config --global credential.helper store
```

## Получение изменений из редактора {#pull-changes-from-the-editor}

Внутри папки выполните:

```bash
git pull
```

Git перечислит изменённые файлы. Изменения, сделанные в редакторе, приходят в виде коммитов с названием `Update on Overleaf.`.

```text
Updating db007e3..c3e6332
Fast-forward
 main.tex | 2 +-
 1 file changed, 1 insertion(+), 1 deletion(-)
```

## Отправка изменений {#push-your-changes}

Закоммитьте изменения, затем отправьте их:

```bash
git add main.tex
git commit -m "Add a line from Git"
git push
```

Последняя строка вывода показывает ветку, которая продвинулась:

```text
   53aca61..db007e3  main -> main
```

Изменения появляются в редакторе, а открытый редактор обновляется сам. Новые файлы, папки и переименования отображаются в дереве файлов. В **History** ваше изменение помечено как <strong>You (via Git)</strong>. Сообщение коммита там не показывается.

### Если Git отклоняет push {#if-git-refuses-your-push}

Если проект за это время изменился, Git отклоняет push:

```text
 ! [rejected]        main -> main (fetch first)
```

Сначала получите эти изменения, затем снова выполните push:

```bash
git pull --no-rebase --no-edit
git push
```

Обычный `git pull` может остановиться с сообщением `fatal: Need to specify how to reconcile divergent branches.` Параметр `--no-rebase` выше решает эту проблему: он объединяет обе стороны.

Если одни и те же строки изменились с обеих сторон, pull останавливается с сообщением `CONFLICT (content): Merge conflict in main.tex`. Исправьте файл, затем выполните:

```bash
git add main.tex
git commit -m "Merge the changes from the editor"
git push
```

Сайт не принимает две вещи:

* Другие ветки: `! [remote rejected] feature -> feature (wrong branch)`. Существует только `main`, поэтому отправляйте работу туда.
* Принудительный push: `! [remote rejected] main -> main (forced push prohibited)`. Вместо этого поместите свои изменения поверх текущей `main`.

### Если Git сообщает Authentication failed {#if-git-says-authentication-failed}

```text
remote: Enter your Git authentication token when prompted for a password.
fatal: Authentication failed for 'https://<your-site>/git/<project-id>/'
```

Токен неверен или удалён, либо вы ввели пароль учётной записи. Создайте новый токен, если у вас его больше нет: существующий токен нельзя посмотреть повторно.

## Удаление токена {#delete-a-token}

В **Account settings**, в разделе **Git integration**, нажмите значок удаления рядом с токеном, затем **Delete** в диалоговом окне. После этого Git отвечает `Authentication failed` на этот токен.
