У каждого проекта есть собственный MCP-сервер, поэтому ИИ-клиент на вашем компьютере может читать и редактировать проект, компилировать его и отвечать на комментарии. Клиент входит с помощью токена аутентификации Git.

<Info>

Если вы не видите карточку **MCP server**, направьте администратора на страницу [MCP-сервер](/ru/on-premises/configuration/overleaf-toolkit/integrations/mcp-server).

</Info>

## Новое в v6.3.3 {#new-in-v6-3-3}

Начиная с v6.3.3, клиент может работать и с историей проекта: просматривать изменения, сравнивать две версии, читать файл в прежнем состоянии, сохранять и удалять версии, восстанавливать файл или весь проект. Он может просматривать отслеживаемые изменения и принимать или отклонять их, а также делать свои правки отслеживаемыми изменениями, если вы об этом попросите. Он может комментировать фрагмент текста, редактировать и удалять сообщения комментариев, читать и отправлять сообщения в чате проекта, перемещать и переименовывать файлы и папки, создавать папки и менять язык проверки орфографии. Кто что может делать, зависит от вашей роли в проекте, как и в редакторе, потому что клиент работает с вашим токеном: см. [Кто что может делать](#who-may-do-what).

MCP-сервер появился в v6.3.1. В v6.3.1 и v6.3.2 одни и те же 17 инструментов; в v6.3.3 их 33.

| Инструменты | v6.3.1 и v6.3.2 | v6.3.3 |
| ----- | ----------------- | ------ |
| `get_clone_info`, `get_settings`, `list_files`, `delete_file`, `compile`, `get_compile_log`, `get_output_file_link`, `word_count`, `reply_to_comment`, `resolve_comment`, `reopen_comment` | Да | Да, без изменений |
| `read_file` | Последнее содержимое | Также файл в состоянии на `version` |
| `edit_file`, `write_file` | Следуют настройке отслеживания изменений проекта | Также `trackChanges`, чтобы сделать правку отслеживаемым изменением |
| `update_settings` | Компилятор, образ TeX Live и основной документ | Также язык проверки орфографии |
| `list_versions` | Версия, комментарий и дата | Также `id`, который принимает `delete_version`, и кто сохранил версию |
| `list_comments` | Сообщения без id | Также `id` каждого сообщения, который принимают `edit_comment_message` и `delete_comment_message` |
| `list_changes`, `diff`, `create_version`, `delete_version`, `restore_file`, `restore_project`, `list_tracked_changes`, `accept_tracked_changes`, `reject_tracked_changes`, `add_comment`, `edit_comment_message`, `delete_comment_message`, `list_chat_messages`, `send_chat_message`, `move_file`, `create_folder` | Нет | Да |

## Подключение клиента {#connect-a-client}

<Steps>
<Step title="Откройте диалог">
Откройте проект. На левой панели нажмите **Integrations**, затем **MCP server**.

<Frame caption="Панель Integrations">
  <img src="/images/on-premises/mcp-server-integrations.png" alt="Панель Integrations с карточкой MCP server" />
</Frame>

Диалог показывает адрес сервера этого проекта и вкладку для каждого клиента: **Claude Code**, **Codex**, **Cursor**, **VS Code** и **Gemini CLI**.

<Frame caption="Диалог MCP server">
  <img src="/images/on-premises/mcp-server-dialog.png" alt="Диалог MCP server с адресом, вкладкой для каждого клиента и командой для Claude Code" />
</Frame>
</Step>

<Step title="Создайте токен">
Нажмите **Go to settings**. Настройки учётной записи откроются в новой вкладке. В разделе **Git integration** нажмите **Generate token** или **Add another token**, если токен у вас уже есть. Нажмите **Copy** и сохраните токен в надёжном месте, потому что он показывается только один раз. Затем нажмите **Close**.

<Frame caption="Ваш новый токен">
  <img src="/images/on-premises/mcp-server-token.png" alt="Диалог Git authentication token с кнопкой Copy" />
</Frame>

Подойдёт и токен, который вы уже используете для [интеграции с Git](/ru/on-premises/user-guide/users/git-integration), а один токен можно использовать для всех проектов.
</Step>

<Step title="Добавьте сервер в клиент">
Вернитесь в диалог, откройте вкладку своего клиента и нажмите **Copy** рядом с конфигурацией.

| Вкладка | Куда вставить | Токен |
| --- | ------------- | --------- |
| **Claude Code** | Выполните команду в терминале | Замените `<token>` в команде |
| **Codex** | `~/.codex/config.toml` | Укажите его в переменной окружения `OVERLEAF_TOKEN` |
| **Cursor** | `~/.cursor/mcp.json` | Укажите его в переменной окружения `OVERLEAF_TOKEN` |
| **VS Code** | `.vscode/mcp.json` | Вместо токена в файле есть запрос пароля `overleaf-token` |
| **Gemini CLI** | Выполните команду в терминале | Замените `<token>` в команде |

Адрес относится к одному проекту. Чтобы подключить другой проект, добавьте его под другим именем, потому что `overleaf` уже занято. Например, в Claude Code замените `overleaf` в команде на `overleaf-lab`.
</Step>
</Steps>

## Проверка соединения {#check-the-connection}

### С помощью Claude Code {#with-claude-code}

```bash
claude mcp list
```

Сервер отображается как подключённый:

```text
overleaf: https://<your-site>/project/<project-id>/mcp (HTTP) - ✔ Connected
```

### С помощью curl {#with-curl}

Этот способ работает с любым клиентом. Замените адрес и токен и отправьте запрос `initialize` протокола MCP:

```bash
curl -X POST https://<your-site>/project/<project-id>/mcp \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -H "Accept: application/json, text/event-stream" \
  -d '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2025-06-18","capabilities":{},"clientInfo":{"name":"curl","version":"1.0"}}}'
```

В ответе указано имя сервера, а за ним его инструкции для клиентов:

```json
{"result":{"protocolVersion":"2025-06-18","capabilities":{"tools":{"listChanged":true}},"serverInfo":{"name":"overleaf","version":"1.0.0"},"instructions":"This server works on one Overleaf project. ..."},"jsonrpc":"2.0","id":1}
```

Чтобы увидеть инструменты, отправьте `tools/list` той же командой. В ответе 33 инструмента или 31, если на вашем сайте отключён чат проекта. До v6.3.3 их 17.

```bash
  -d '{"jsonrpc":"2.0","id":2,"method":"tools/list","params":{}}'
```

Чтобы вызвать инструмент, отправьте `tools/call`:

```bash
  -d '{"jsonrpc":"2.0","id":3,"method":"tools/call","params":{"name":"list_files","arguments":{}}}'
```

```json
{"result":{"content":[{"type":"text","text":"[\n  {\n    \"path\": \"main.tex\",\n    \"type\": \"doc\"\n  }\n]"}]},"jsonrpc":"2.0","id":3}
```

### В настройках учётной записи {#in-your-account-settings}

В разделе **Git integration** поле **Last used** показывает дату для токена, который получил сервер.

<Frame caption="Первый токен использован">
  <img src="/images/on-premises/mcp-server-last-used.png" alt="Список токенов: у первого токена дата в Last used, у второго N/A" />

### Если соединение не устанавливается {#if-it-does-not-connect}

| Что вы видите | Что это значит |
| ------------ | ------------- |
| Статус `401` или в Claude Code `✘ Failed to connect` с `HTTP 401` | Токен отсутствует, неверен или удалён |
| Статус `404` | Проекта с таким ID нет |
| Статус `405` | Запрос был не `POST` |
| Статус `406` с `Not Acceptable` | Отсутствует заголовок `Accept`: клиент должен принимать и `application/json`, и `text/event-stream` |

## Что вы видите, когда работает клиент {#what-you-see-when-a-client-works}

Правки появляются в открытом редакторе по мере того, как клиент их вносит, как правки соавтора, без перезагрузки. Новые файлы и папки, перемещения и переименования появляются в дереве файлов.

<Frame caption="Строка, добавленная edit_file">
  <img src="/images/on-premises/mcp-server-live-edit.png" alt="Редактор показывает строку, добавленную edit_file, без диалога и без перезагрузки" />
</Frame>

`edit_file` меняет только текст, который встречается ровно один раз. Иначе клиент получает ошибку, например `oldString not found in main.tex, read_file again` или `oldString appears 2 times in main.tex, add context`, и ничего не меняется.

Начиная с v6.3.3, `move_file` перемещает или переименовывает файл или папку, при необходимости создавая папки нового пути, а `create_folder` создаёт папку. Если файл не найден или новый путь уже существует, клиент получает ошибку, и ничего не меняется. `update_settings` также может сменить язык проверки орфографии, например на `de`, или отключить проверку.

Ответы на комментарии появляются на панели рецензирования под вашим именем, потому что токен ваш. Комментарий, решённый через сервер, исчезает с панели, а повторное открытие возвращает его.

<Frame caption="Ответ, отправленный reply_to_comment">
  <img src="/images/on-premises/mcp-server-comment.png" alt="Комментарий на панели рецензирования с ответом, отправленным reply_to_comment" />
</Frame>

Начиная с v6.3.3, `add_comment` комментирует фрагмент текста. Текст должен встречаться в файле ровно один раз; если он встречается несколько раз, клиент также указывает более длинный окружающий фрагмент, который встречается один раз, и комментируется только сам текст. Комментарий появляется на панели рецензирования под вашим именем и остаётся привязанным к своему тексту при изменении файла. `edit_comment_message` изменяет одно из ваших сообщений. `delete_comment_message` удаляет сообщение, а удаление первого удаляет весь комментарий, как на панели рецензирования.

`compile` компилирует проект и возвращает список выходных файлов. Затем `get_output_file_link` даёт ссылку для скачивания PDF или другого выходного файла. Ссылке не нужен токен, и через 5 минут она перестаёт работать.

Полный список инструментов см. в разделе [Tools](/on-premises/configuration/overleaf-toolkit/integrations/mcp-server#tools).

## Отслеживаемые изменения {#tracked-changes}

Начиная с v6.3.3, вы можете попросить клиента вносить правки как отслеживаемые изменения, например *Rewrite the abstract as a tracked change*. Тогда `edit_file` и `write_file` делают изменение существующего файла отслеживаемым изменением от вашего имени, даже если отслеживание изменений в проекте выключено, и вы принимаете или отклоняете его на панели рецензирования. Новый файл никогда не бывает отслеживаемым изменением. Если вы не просите, правки следуют настройке отслеживания изменений проекта, как и ваши в редакторе: они отслеживаются, когда отслеживание включено для вас или для всех.

Если в учётной записи владельца проекта нет отслеживания изменений, клиент получает `Track changes is off for this project`, и ничего не меняется.

Чтобы проверять каждую правку клиента, включите отслеживание изменений для себя. Чтобы отличать его правки от ваших на панели рецензирования, дайте клиенту токен другой учётной записи, с которой вы делите проект.

`list_tracked_changes` перечисляет отслеживаемые изменения с их файлом, вставленным или удалённым текстом, автором и временем. `accept_tracked_changes` и `reject_tracked_changes` принимают id изменений и работают как панель рецензирования: принятое изменение остаётся в тексте, отклонённая вставка удаляется, а отклонённое удаление возвращается. Открытый редактор показывает результат без перезагрузки. Инструменты указывают клиенту принимать или отклонять только те изменения, о которых вы просите.

## История {#history}

Начиная с v6.3.3, клиент видит историю проекта так же, как её показывает панель истории.

| Инструмент | Что делает |
| ---- | ------------ |
| `list_changes` | Перечисляет изменения, начиная с новых: кто, когда и какие файлы изменил, с версиями до и после каждого изменения. Более старые изменения приходят следующими порциями. |
| `diff` | Сравнивает две версии: один файл в виде unified diff, как `git diff`, или файлы, которые были добавлены, удалены, изменены или переименованы |
| `read_file` с `version` | Читает файл в состоянии на определённую версию |
| `list_versions` | Перечисляет сохранённые версии с комментарием и тем, кто их сохранил |
| `create_version` | Сохраняет последнюю или более раннюю версию с комментарием, как **Label this version** |
| `delete_version` | Удаляет сохранённую версию; её изменения остаются |
| `restore_file` | Восстанавливает файл в состоянии на версию, как **Restore this version** |
| `restore_project` | Восстанавливает весь проект в состоянии на версию, как **Restore project to this version** |

Восстановление само является новым изменением, поэтому его можно отменить тем же способом. Инструменты указывают клиенту восстанавливать только по вашей просьбе.

Если у владельца проекта нет полной истории проекта, клиент видит только изменения за последние 24 часа или последнее изменение, если все они старше, как на панели истории. Сравнивать, читать или восстанавливать более старые версии он не может.

## Чат проекта {#project-chat}

Начиная с v6.3.3, `list_chat_messages` читает чат проекта, начиная с новых, по 50 сообщений за раз. `send_chat_message` отправляет сообщение от вашего имени, и оно сразу появляется в открытом чате. Если на вашем сайте чат проекта отключён, у клиента нет ни одного из этих инструментов.

## Кто что может делать {#who-may-do-what}

Клиент может делать то, что разрешает ваша роль в проекте.

| Что делает клиент | Владелец | Редактор | Рецензент | Читатель (именной соавтор) | Читатель (доступ по ссылке) |
| -------------------- | ----: | -----: | -------: | --------------------------: | --------------------: |
| Читать файлы и настройки, компилировать, читать журнал, скачивать PDF | Да | Да | Да | Да | Да |
| Записывать, редактировать, перемещать и удалять файлы, создавать папки, менять настройки | Да | Да | Нет | Нет | Нет |
| Просматривать историю, комментарии и отслеживаемые изменения | Да | Да | Да | Да | Нет |
| Читать и отправлять сообщения в чате | Да | Да | Да | Да | Нет |
| Добавлять комментарии и отвечать на них | Да | Да | Да | Нет | Нет |
| Решать, повторно открывать или удалять комментарий | Да | Да | Начатые им самим | Нет | Нет |
| Редактировать сообщение комментария | Свои | Свои | Свои | Нет | Нет |
| Удалять сообщение комментария | Да | Да | Свои | Нет | Нет |
| Принимать или отклонять отслеживаемые изменения | Да | Да | Нет | Нет | Нет |
| Сохранять версию | Да | Да | Да | Нет | Нет |
| Удалять сохранённую версию | Да | Сохранённые им самим | Сохранённые им самим | Нет | Нет |
| Восстанавливать файл или проект | Да | Да | Нет | Нет | Нет |

Редакторы, присоединившиеся по ссылке, считаются редакторами. Рецензенты не могут редактировать файлы через MCP, даже в виде отслеживаемых изменений.

## Отключение клиента {#disconnect-a-client}

Удалите токен: см. [Удаление токена](/ru/on-premises/user-guide/users/git-integration#delete-a-token). После этого сервер отвечает `401` на этот токен. Если вы используете его и для Git, Git тоже перестаёт его принимать.
