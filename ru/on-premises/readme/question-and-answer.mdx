Здесь мы собрали ответы на некоторые часто задаваемые вопросы об Ayakaleaf Pro.

### Общие вопросы

<Accordion title="Q01: Является ли Ayakaleaf Pro пробной версией? Нужна ли для него лицензия?">

Нет. Ayakaleaf Pro полностью бесплатен. Это не пробная версия, и лицензия для него не требуется.

</Accordion>

<Accordion title="Q02: Включает ли Ayakaleaf Pro все функции Overleaf Server Pro?">

Да. Ayakaleaf Pro включает все функции Overleaf Server Pro, в том числе интеграцию Git-Bridge. Он также включает некоторые функции SaaS-платформы Overleaf. Мы продолжаем развивать и улучшать Ayakaleaf Pro.

</Accordion>

<Accordion title="Q03: Сколько стоит Overleaf Server Pro?">

Overleaf Server Pro стоит около \$300 за пользователя в год. Требуется не менее 10 лицензий, поэтому стоимость развёртывания начинается примерно с \$3,000 в год. В небольших государственных контрактах США годовая стоимость составляет около \$320–\$370 за пользователя. Это делает Server Pro дорогим решением, особенно для небольших команд. Задокументированные закупки и цены см. в разделе [#information-and-price-about-overleaf-server-pro](/ru/on-premises#information-and-price-about-overleaf-server-pro  "mention").

</Accordion>

<Accordion title="Q04: Почему Overleaf Server Pro не включает GitHub Sync и функции ИИ?">

Overleaf Server Pro часто используется государственными организациями. Они развёртывают его в частных сетях и строго контролируют доступ. Чтобы защитить конфиденциальные данные, включённые в него функции не обмениваются данными со сторонними сервисами. Если вам нужны GitHub Sync, ИИ или аналогичные функции, требующие подключения к внешним сервисам, Overleaf рекомендует оформить подписку на свою SaaS-платформу.

</Accordion>

<Accordion title="Q05: Безопасен ли и надёжен ли Ayakaleaf Pro?">

Ayakaleaf Pro — проект с открытым исходным кодом. Мы проверяем код с помощью таких инструментов, как Codex Security, чтобы повысить его безопасность и надёжность. Если вы не включаете синхронизацию данных со сторонними сервисами, ваши данные остаются на вашем сервере. Ayakaleaf Pro не содержит телеметрии, отправляющей ваши данные куда-либо.

</Accordion>

<Accordion title="Q06: Будет ли Ayakaleaf Pro поддерживаться в долгосрочной перспективе?">

Мы приложим все усилия, чтобы поддерживать этот проект в долгосрочной перспективе.

</Accordion>

<Accordion title="Q07: Соответствует ли Ayakaleaf Pro лицензионным требованиям?">

Ayakaleaf Pro — это форк сообщества. Его код и интегрированные функции созданы благодаря вкладу сообщества. Он распространяется по лицензии AGPL v3. Развёртывания соответствуют этой лицензии при выполнении её требований.

</Accordion>

<Accordion title="Q08: Почему проект называется Ayakaleaf Pro?">

Изначально, в 2024 году, проект назывался Overleaf Pro. На какое-то время разработка приостановилась, а затем возобновилась в конце 2025 года. В первом квартале 2026 года Overleaf переименовал свой тарифный план с функциями ИИ в Pro. Кроме того, сообщество отмечало, что название Overleaf Pro может создавать риски, связанные с товарными знаками и выдачей себя за другой продукт. Пользователи могли решить, что это официальный проект.

Чтобы избежать этой путаницы, мы переименовали проект в Ayakaleaf Pro. Название можно читать как «Ayaka-notes Overleaf Pro». Сопровождающий проекта (можете называть меня ayaka!) участвует в развитии сообщества Overleaf со студенческих лет, то есть уже более пяти лет. Этот опыт подкрепляет наше обязательство по долгосрочному сопровождению.

</Accordion>

<Accordion title="Q09: Чем Ayakaleaf Pro отличается от новых редакторов LaTeX, созданных с помощью ИИ?">

С 2026 года сообщество open source выпустило множество редакторов LaTeX, созданных с помощью ИИ, включая OpenAI Prism. Ayakaleaf Pro хранит ваши данные и сервисы на вашем собственном сервере. Это даёт вам непосредственный контроль над развёртыванием и данными.

У многих экспериментальных редакторов сообщества нет устоявшегося плана долгосрочного сопровождения. Сторонние платформы компиляции LaTeX также могут прекратить работу, если у них недостаточно пользователей или доходов. Ayakaleaf Pro предоставляет весь исходный код и позволяет размещать все сервисы на собственных серверах. Даже если сопровождение прекратится, ваш существующий самостоятельно размещённый сервис сможет продолжить работу.

</Accordion>

### Возможности

<Accordion title="Q01: Какие возможности предлагает Ayakaleaf Pro? Можно ли запросить новую функцию?">

Актуальный список функций смотрите в нашей документации. Если вы хотите, чтобы мы добавили какую-либо функцию, создайте issue (запрос на функцию) на GitHub. Мы постараемся реализовать запрошенные функции, но разработка требует времени, и мы не можем гарантировать, что каждая функция появится сразу.

</Accordion>

<Accordion title="Q02: Я разработал(а) некоторые функции. Могу ли я отправить PR и гарантированно ли он будет принят?">

Мы приветствуем вклад в проект, но принятие не гарантируется. Мы оцениваем каждый PR с учётом его влияния на базовый код Overleaf, нагрузки на сопровождение и пользы для пользователей. Мы постараемся принимать и сопровождать ценные доработки.

Однако мы можем отклонить PR, которые вносят чрезмерные изменения, состоят из непроверенного или плохо понятого кода, сгенерированного ИИ («вайб-кодинг»), или добавляют функции, которые будет сложно сопровождать в долгосрочной перспективе.

</Accordion>

<Accordion title="Q03: Как настроить определённую функцию?">

Как правило, мы обновляем документацию при выпуске каждой новой функции. Подробные инструкции по настройке и описание доступных переменных окружения см. в соответствующем разделе документации.

</Accordion>

<Accordion title="Q04: Какие библиотеки Python может использовать Python Runner?">

Python Runner выполняет Python в браузере пользователя с помощью [Pyodide](https://pyodide.org/) 0.29.3, а не на сервере. Он загружает пакеты, которые импортирует ваш код, из [пакетов, встроенных в Pyodide](https://pyodide.org/en/0.29.3/usage/packages-in-pyodide.html), таких как NumPy, pandas и Matplotlib. Пакеты, установленные через `pip`, и другие пакеты недоступны. Настраивать на сервере ничего не нужно.

</Accordion>

<Accordion title="Q05: Может ли проверка орфографии проверять японский или китайский язык?">

Нет. У средства проверки орфографии нет словаря для японского и китайского языков, поэтому этих языков нет в списке языков проверки орфографии. Пользователи могут отключить проверку орфографии для проекта в настройках редактора.

</Accordion>

### Развёртывание

<Accordion title="Q01: Поддерживает ли Ayakaleaf Pro распределённое развёртывание в k8s?">

Большинству пользователей мы рекомендуем выполнять развёртывание с помощью [Toolkit](/ru/on-premises/installation/using-the-toolkit). Мы не рекомендуем крупномасштабные кластерные развёртывания с использованием Kubernetes или аналогичных платформ, поскольку они могут значительно усложнить эксплуатацию и сопровождение.

</Accordion>

<Accordion title="Q02: Как обеспечить доступность при обслуживании тысяч пользователей?">

Обратитесь к нашему руководству по [горизонтальному масштабированию](/ru/on-premises/maintenance/horizontal-scaling). Вы можете развернуть несколько экземпляров Overleaf и настроить балансировщик нагрузки для распределения трафика между ними.

</Accordion>

<Accordion title="Q03: Можете ли вы помочь с развёртыванием или миграцией?">

Если у вас есть экземпляр Overleaf Server Pro, мы будем рады помочь вам перейти на Ayakaleaf Pro. Свяжитесь с нами по электронной почте или через issues.

</Accordion>

<Accordion title="Q04: Можно ли разместить Ayakaleaf Pro по подпути URL, например `https://example.com/overleaf`?">

Нет. Ayakaleaf Pro должен обслуживаться из корня домена. Используйте отдельный домен или поддомен, например `https://overleaf.example.com`.

</Accordion>

<Accordion title="Q05: Можно ли запускать Ayakaleaf Pro в Windows или macOS либо без Toolkit?">

Мы поддерживаем Linux-серверы с [Toolkit](/ru/on-premises/installation/using-the-toolkit). Docker Desktop в Windows, WSL2 или macOS может работать, но мы его не тестируем; об известной проблеме с MongoDB см. в разделе [Устранение неполадок](/ru/on-premises/support/troubleshooting).

Мы не предоставляем отдельный `docker-compose.yml`. Чтобы посмотреть конфигурацию Compose, которую использует Toolkit, выполните `bin/docker-compose config` в каталоге Toolkit.

</Accordion>

<Accordion title="Q06: Как удалить Ayakaleaf Pro?">

Скрипта удаления нет. В каталоге Toolkit:

1. Остановите и удалите контейнеры командой `bin/docker-compose down`.
2. Удалите данные. По умолчанию они находятся в каталоге `data/` в Toolkit. Если вы изменяли `OVERLEAF_DATA_PATH`, `MONGO_DATA_PATH`, `REDIS_DATA_PATH` или `GIT_BRIDGE_DATA_PATH` в `config/overleaf.rc`, удалите и эти каталоги. Это действие необратимо, поэтому сначала [создайте резервную копию](/ru/on-premises/maintenance/data-and-backups), если данные могут понадобиться.
3. Удалите каталог Toolkit.
4. Удалите Docker-образы, список которых можно получить командой `docker images`: `ghcr.io/ayaka-notes/overleaf-pro`, образ git-bridge, `mongo`, `redis` и образы TeX Live.

</Accordion>

<Accordion title="Q07: Как остановить, запустить или перезапустить Ayakaleaf Pro?">

Выполняйте эти команды в каталоге Toolkit:

* `bin/stop` останавливает все контейнеры, `bin/start` снова их запускает. Контейнеры сохраняются, поэтому пользователи остаются в системе.
* `bin/up -d` создаёт контейнеры и запускает их в фоновом режиме. Выполняйте её после изменения `config/variables.env`, `config/overleaf.rc` или `config/version`: она пересоздаёт контейнеры, конфигурация которых изменилась, и только после этого изменения вступают в силу. `bin/stop` и `bin/start` их не применяют.
* `bin/docker-compose restart sharelatex` перезапускает только контейнер Overleaf, не применяя изменения конфигурации.

Если пользователи выходят из системы каждый раз, когда `bin/up` пересоздаёт контейнер, задайте `OVERLEAF_SESSION_SECRET`, см. раздел «Вопросы и ответы» в [Переменные окружения](/ru/on-premises/configuration/overleaf-toolkit/environment-variables).

</Accordion>

<Accordion title="Q08: Куда указывать URL обратного вызова OAuth?">

В приложении, которое вы создаёте у провайдера, а не в Ayakaleaf Pro. Ни для одной из этих интеграций в `config/variables.env` нет параметра обратного вызова: Ayakaleaf Pro формирует каждый URL обратного вызова из `OVERLEAF_SITE_URL` и отправляет его провайдеру, который отклоняет его, если он не совпадает с зарегистрированным для приложения. Поэтому вы регистрируете его только у провайдера и задаёте в `OVERLEAF_SITE_URL` адрес, который открывают пользователи.

| Интеграция | Поле у провайдера | Значение |
| --- | --- | --- |
| [GitHub](/ru/on-premises/configuration/overleaf-toolkit/github-synchronisation) | Authorization callback URL | `${OVERLEAF_SITE_URL}/user/github-sync/oauth2/callback` |
| [GitLab](/ru/on-premises/configuration/overleaf-toolkit/gitlab-synchronisation) | Redirect URI | `${OVERLEAF_SITE_URL}/user/gitlab-sync/oauth2/callback` |
| [Gitea](/ru/on-premises/configuration/overleaf-toolkit/gitea-synchronisation) | Redirect URIs | `${OVERLEAF_SITE_URL}/user/gitea-sync/oauth2/callback` |
| [Dropbox](/ru/on-premises/configuration/overleaf-toolkit/dropbox-synchronisation) | Redirect URIs (нажмите **Add**) | `${OVERLEAF_SITE_URL}/user/dropbox/oauth/callback` |
| [Zotero](/ru/on-premises/configuration/overleaf-toolkit/zotero-integration) | Callback URL | `${OVERLEAF_SITE_URL}/user/zotero/oauth/callback` |
| [Mendeley](/ru/on-premises/configuration/overleaf-toolkit/mendeley-integration) | Redirect URL | `${OVERLEAF_SITE_URL}/user/mendeley/oauth/callback` |
| [Вход через OIDC](/ru/on-premises/configuration/overleaf-toolkit/authentication/oidc-authentication) | Redirect URI | `${OVERLEAF_SITE_URL}/oidc/login/callback` |
| [Вход через SAML](/ru/on-premises/configuration/overleaf-toolkit/authentication/saml-authentication) | ACS URL (Assertion Consumer Service) | `${OVERLEAF_SITE_URL}/saml/login/callback` |

Если вы меняете `OVERLEAF_SITE_URL`, например на новый домен, обновите URL и у каждого провайдера, иначе привязка не будет работать.

</Accordion>

### LaTeX

<Accordion title="Q01: Изолированы ли компиляции проектов LaTeX разных пользователей? Включён ли Shell Escape?">

Если включена изолированная компиляция (Sandbox Compiles), компиляция каждого пользователя выполняется в отдельном контейнере Docker и изолирована от компиляций других пользователей. Для Sandbox Compiles Shell Escape включён по умолчанию.

</Accordion>

<Accordion title="Q02: Надёжен ли образ Sandbox Compiles? Может ли компиляция завершиться ошибкой?">

За последние три года мы улучшили наш образ TeX Live Full для Sandbox Compiles. В большинстве случаев проекты, которые компилируются на overleaf.com, корректно компилируются и в Ayakaleaf Pro. Если нужный шрифт недоступен, загрузите его в проект вручную.

</Accordion>

<Accordion title="Q03: Мой проект не компилируется. Можете ли вы помочь найти причину?">

Загрузите ваш проект на официальный сайт Overleaf, включите общий доступ по ссылке только для чтения и добавьте эту ссылку в issue на GitHub.

Мы изучим и исправим ошибки, из-за которых проект не компилируется в Ayakaleaf Pro, если он успешно компилируется на официальном сайте Overleaf. Проблемы компиляции за пределами этого случая не входят в нашу поддержку.

</Accordion>
