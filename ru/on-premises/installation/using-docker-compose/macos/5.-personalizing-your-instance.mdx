<Steps>
<Step title="Настройки контейнеров">
Измените следующие существующие записи в `config/overleaf.rc`:

```bash title="config/overleaf.rc"
PROJECT_NAME=ayakaleaf-macos
SERVER_PRO=true
OVERLEAF_LISTEN_IP=127.0.0.1
OVERLEAF_PORT=8080
SIBLING_CONTAINERS_ENABLED=true
DOCKER_SOCKET_PATH=/var/run/docker.sock
```

Оставьте пути к данным по умолчанию и входящие в комплект сервисы MongoDB и Redis. При `OVERLEAF_LISTEN_IP=127.0.0.1` открыть экземпляр могут только браузеры на этом Mac.
</Step>

<Step title="Настройки приложения">
В `config/variables.env` задайте следующие значения, заменив все активные записи с теми же именами:

```dotenv title="config/variables.env"
OVERLEAF_SITE_URL=http://localhost:8080
TEX_LIVE_DOCKER_IMAGE=ghcr.io/ayaka-notes/texlive-full:2026.1
ALL_TEX_LIVE_DOCKER_IMAGES=ghcr.io/ayaka-notes/texlive-full:2026.1
ALL_TEX_LIVE_DOCKER_IMAGE_NAMES="TeX Live 2026"
```

Сгенерируйте секрет сеанса:

```bash
openssl rand -hex 32
```

Добавьте результат как `OVERLEAF_SESSION_SECRET` в `config/variables.env`. Без него каждый запуск `bin/up`, пересоздающий контейнер, будет выводить из системы всех пользователей, см. [Переменные окружения](/ru/on-premises/configuration/overleaf-toolkit/environment-variables).

Для локального экземпляра без электронной почты не задавайте настройки SMTP и `OVERLEAF_EMAIL_FROM_ADDRESS`. Git Bridge, внешнюю аутентификацию и другие интеграции можно добавить позже, следуя их [страницам конфигурации](/ru/on-premises/configuration/overleaf-toolkit).
</Step>

<Step id="check-the-docker-vms-linux-kernel" title="Проверьте ядро Linux виртуальной машины Docker">
MongoDB работает на ядре Linux виртуальной машины Docker Desktop, а не на macOS. Проверьте его версию перед первым запуском:

```bash
docker info --format '{{.KernelVersion}}'
```

MongoDB документирует несовместимость с ядрами Linux **с 6.19 по 7.0.13**, которая затрагивает и MongoDB в Docker. Решение — ядро **7.0.14 или новее**, которое приходит с обновлением Docker Desktop, см. [production notes MongoDB](https://www.mongodb.com/docs/manual/administration/production-notes/).

Если ваша виртуальная машина Docker использует затронутое ядро, добавьте следующее в `config/docker-compose.override.yml`, объединив с уже имеющимися там `services`:

```yaml title="config/docker-compose.override.yml"
services:
  mongo:
    environment:
      GLIBC_TUNABLES: glibc.pthread.rseq=1
```

<Warning>

Обновитесь до исправленного ядра, когда оно станет доступно. Если ваше ядро не входит в затронутый диапазон, этот обходной путь не нужен.

</Warning>
</Step>

<Step title="Запустите экземпляр">
В каталоге Toolkit выполните:

```bash
bin/up -d
```

Toolkit инициализирует набор реплик MongoDB, загружает образ TeX Live и запускает приложение. Первая загрузка занимает некоторое время. Чтобы следить за ходом процесса:

```bash
bin/docker-compose ps
bin/docker-compose logs --tail=100 -f sharelatex
```

Нажмите `Ctrl+C`, чтобы прекратить просмотр журналов. Контейнеры продолжат работать.

Проверьте опубликованный порт и страницу первого запуска:

```bash
bin/docker-compose port sharelatex 80
curl -I http://localhost:8080/launchpad
```

Порт должен быть `127.0.0.1:8080`.
</Step>
</Steps>

<Info>

Чтобы позже открыть экземпляр с других компьютеров, измените адрес прослушивания и URL сайта и настройте HTTPS, как описано в разделе [5. Персонализация экземпляра](/ru/on-premises/installation/using-docker-compose/linux/5.-personalizing-your-instance) руководства для Linux. Тогда Mac должен оставаться в активном режиме, см. [Обеспечение доступности экземпляра](/ru/on-premises/installation/using-docker-compose/macos/6.-post-installation-tasks#keep-the-instance-available).

</Info>
