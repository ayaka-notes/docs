### Инициализация завершается ошибкой invalid command code {#initialization-fails-with-invalid-command-code}

`bin/init` сообщает `sed: ... invalid command code`, когда находит BSD sed из macOS. Добавьте GNU sed в `PATH`, как описано в разделе [1. Загрузка Toolkit](/ru/on-premises/installation/using-docker-compose/macos/1.-download-the-toolkit), и проверьте `sed --version`.

После неудачной инициализации в `config/` могут остаться все три файла с пустым `OVERLEAF_INVITE_TOKEN_SECRET`. Повторный запуск `bin/init` тогда сообщает `Config files already exist`. Для новой установки, которая ещё ни разу не запускалась, переместите эти три файла в каталог резервных копий и снова выполните `bin/init`. Для существующего экземпляра сохраните его конфигурацию и секреты и не удаляйте его файлы ради повторного запуска `bin/init`.

### MongoDB постоянно перезапускается {#mongodb-keeps-restarting}

Прочитайте журналы MongoDB и версию ядра виртуальной машины Docker:

```bash
bin/docker-compose logs --tail=100 mongo
docker info --format '{{.KernelVersion}}'
```

Если в журнале упоминается несовместимость с ядром Linux, выполните шаг [Проверьте ядро Linux виртуальной машины Docker](/ru/on-premises/installation/using-docker-compose/macos/5.-personalizing-your-instance#check-the-docker-vms-linux-kernel) и снова запустите `bin/up -d`. Один лишь код выхода `137` не доказывает, что MongoDB не хватило памяти: проверьте состояние контейнера и журналы. Об одной давней проблеме MongoDB в Docker Desktop см. также раздел [Устранение неполадок](/ru/on-premises/support/troubleshooting).

### Не удаётся подключиться к демону Docker {#cannot-connect-to-the-docker-daemon}

Запустите Docker Desktop и проверьте выбранный контекст Docker, см. [0. Установка Docker Desktop](/ru/on-premises/installation/using-docker-compose/macos/0.-setup-docker-desktop). Если `docker info` работает, но компиляции не могут обратиться к Docker, проверьте настройки сокета в `config/overleaf.rc` и прочитайте журналы `clsi`. Работающий Docker CLI на Mac не доказывает, что сокет в приложении смонтирован правильно.

### Страница открывается, но компиляция завершается ошибкой {#the-page-opens-but-compiles-fail}

Проверьте, что образ TeX Live есть локально и соответствует архитектуре движка Docker:

```bash
docker image inspect ghcr.io/ayaka-notes/texlive-full:2026.1 \
  --format '{{.Os}}/{{.Architecture}}'
bin/logs -f clsi
```

На Apple silicon образ должен быть `linux/arm64`. Проверьте, что `SERVER_PRO` и `SIBLING_CONTAINERS_ENABLED` оба имеют значение `true`, затем примените изменения с помощью `bin/up -d`. Если журналы сообщают об отсутствующем каталоге компиляции, проверьте общий доступ к файлам в Docker Desktop и расположение `OVERLEAF_DATA_PATH`. Не отключайте изолированные компиляции, чтобы скрыть ошибку монтирования.

### Not a directory или отсутствует bind-монтирование {#not-a-directory-or-a-bind-mount-is-missing}

Файл на хосте, который монтируется через переопределение, мог быть удалён, или Docker мог создать каталог там, где должен быть файл. Проверьте исходный путь на хосте и то, ожидает ли монтирование файл или каталог. Восстановите конфигурационный файл, прежде чем пересоздавать контейнер. С этим может столкнуться установка в `/tmp` после того, как macOS удалит временные файлы.

### Конфликты портов или имён контейнеров {#port-or-container-name-conflicts}

Если порт `8080` занят, выберите другой порт в `config/overleaf.rc`, задайте соответствующий `OVERLEAF_SITE_URL` и снова выполните `bin/up -d`.

Toolkit даёт своим контейнерам фиксированные имена, такие как `sharelatex`, `mongo` и `redis`. Одно лишь изменение `PROJECT_NAME` не делает две установки Toolkit независимыми. Прежде чем запускать второй экземпляр, проверьте `docker ps -a` и используйте другие имена контейнеров в переопределении Compose, другой порт и отдельные каталоги данных. Не удаляйте контейнеры или данные существующего развертывания, чтобы устранить конфликт имён.

### Через некоторое время экземпляр становится недоступен {#the-instance-is-unreachable-after-a-while}

Вероятно, Mac перешёл в спящий режим или работа Docker Desktop была завершена. См. раздел [Обеспечение доступности экземпляра](/ru/on-premises/installation/using-docker-compose/macos/6.-post-installation-tasks#keep-the-instance-available).

### `bin/doctor` сообщает, что это не Linux, или запрашивает вход в Quay {#bin/doctor-says-this-is-not-linux-or-asks-for-a-quay-login}

Оба предупреждения ожидаемы в macOS при использовании публичного образа, см. [2. Знакомство с Toolkit](/ru/on-premises/installation/using-docker-compose/macos/2.-familiarize-yourself-with-the-toolkit). Вместо этого проверьте загрузку образов, состояние сервисов и результаты компиляции и не игнорируйте другие ошибки в отчёте.
