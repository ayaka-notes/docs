### Создание администратора и первого проекта {#create-the-administrator-and-a-first-project}

Откройте [http://localhost:8080/launchpad](http://localhost:8080/launchpad), создайте первую учётную запись администратора и войдите в систему. Затем следуйте разделу [6. Действия после установки](/ru/on-premises/installation/using-docker-compose/linux/6.-post-installation-tasks) руководства для Linux, используя порт `8080` в приведённых там примерах URL.

### Проверка компиляции {#verify-compilation}

То, что страница входа открывается, ещё не доказывает, что отдельные контейнеры компилятора и их точки монтирования данных работают. Создайте пустой проект и скомпилируйте этот `main.tex`:

```latex
\documentclass{article}
\begin{document}
Ayakaleaf Pro on macOS.
\end{document}
```

В предварительном просмотре PDF должен отобразиться текст. При необходимости выберите TeX Live 2026 в настройках проекта.

Для проекта с китайским текстом выберите компилятор **XeLaTeX** и проверьте:

```latex
\documentclass{ctexart}
\begin{document}
你好，Ayakaleaf Pro。
\end{document}
```

### Проверка сохранности данных {#verify-persistence}

```bash
bin/stop
bin/start
```

Снова откройте проект и скомпилируйте его. Ваша учётная запись, исходный код и файлы проекта должны остаться на месте. При путях по умолчанию рабочие данные находятся в каталоге `data/` Toolkit на вашем Mac.

### Обеспечение доступности экземпляра {#keep-the-instance-available}

Пока Mac находится в спящем режиме, macOS приостанавливает виртуальную машину Docker Desktop вместе со всеми контейнерами в ней: никто не может открыть экземпляр, а выполняющаяся компиляция останавливается до пробуждения Mac. Значение имеет только сон системы. Дисплей может отключаться.

Если экземпляром пользуются другие люди или вы оставляете выполняться длительные задачи, держите Mac подключённым к питанию и запретите автоматический переход в спящий режим, см. [Настройка режима сна и пробуждения на Mac](https://support.apple.com/guide/mac-help/set-sleep-and-wake-settings-mchle41a6ccd/mac):

| Mac | Настройка |
| --- | --- |
| Настольный Mac (Mac mini, iMac, Mac Studio, Mac Pro) | **System Settings → Energy**: включите **Prevent automatic sleeping when the display is off** |
| MacBook | **System Settings → Battery → Options**: включите **Prevent automatic sleeping on power adapter when the display is off**. Это действует только при подключённом адаптере питания, а закрытие крышки по-прежнему переводит MacBook в спящий режим |

Чтобы не давать Mac засыпать лишь некоторое время, вместо этого выполните `caffeinate -i` в окне Терминала. Эта команда предотвращает переход в спящий режим при бездействии, пока вы не нажмёте `Ctrl+C` или не закроете окно.

Docker Desktop — это приложение в вашем пользовательском сеансе. Чтобы экземпляр снова заработал после перезагрузки, включите **Start Docker Desktop when you sign in to your computer** в разделе **Settings → General** Docker Desktop. Контейнеры Toolkit используют `restart: always`, поэтому Docker снова запускает их, как только запускается Docker Desktop, без `bin/up`. Пока после перезагрузки никто не войдёт в систему на Mac, экземпляр остаётся недоступным.

<Info>

Mac, который не переходит в спящий режим, потребляет больше энергии. Для сервиса, который должен быть доступен всегда, мы рекомендуем сервер Linux, см. [Linux](/ru/on-premises/installation/using-docker-compose/linux).

</Info>

### Повседневное использование {#daily-use}

Откройте Docker Desktop, прежде чем управлять экземпляром. В новом терминале:

```bash
export PATH="$(brew --prefix gnu-sed)/libexec/gnubin:$PATH"
cd "$HOME/ayakaleaf-toolkit"
```

| Задача | Команда |
| --- | --- |
| Запустить существующие контейнеры | `bin/start` |
| Остановить контейнеры, сохранив данные | `bin/stop` |
| Применить изменения конфигурации | `bin/up -d` |
| Проверить состояние | `bin/docker-compose ps` |
| Прочитать журналы запуска | `bin/docker-compose logs --tail=100 sharelatex` |
| Прочитать журналы компилятора | `bin/logs -f clsi` |

`bin/start` не применяет изменения в `config/`: после редактирования конфигурации выполните `bin/up -d`. Сохраняйте `config/` и `data/` и следуйте разделу [Данные и резервное копирование](/ru/on-premises/maintenance/data-and-backups) перед обновлением или переносом установки. Копирование файлов базы данных, пока MongoDB записывает в них, не является согласованной резервной копией.

Для локального использования оставляйте экземпляр на `127.0.0.1`. Чтобы обслуживать другие компьютеры, осознанно настройте адрес прослушивания, URL сайта и HTTPS, см. раздел [5. Персонализация экземпляра](/ru/on-premises/installation/using-docker-compose/linux/5.-personalizing-your-instance) руководства для Linux.

Если что-то не работает, см. раздел [Устранение неполадок](/ru/on-premises/installation/using-docker-compose/macos/troubleshooting).
