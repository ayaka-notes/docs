Ayakaleaf Pro использует Linux-контейнеры. В Windows установите Docker Desktop с бэкендом WSL 2 и запускайте скрипты Toolkit в Ubuntu.

WSL 2 предоставляет ядро Linux. Docker Desktop управляет движком Docker в собственной среде `docker-desktop`; включение **WSL Integration** позволяет Docker CLI в Ubuntu обращаться к этому движку. Затем Toolkit запускает приложение, MongoDB и Redis в виде контейнеров. При включённых изолированных компиляциях приложение использует сокет Docker движка, чтобы запускать отдельный контейнер TeX Live для каждой компиляции. Устанавливать MongoDB, Redis или TeX Live в Windows не нужно.

<Steps>
<Step title="Установите WSL 2 и Ubuntu">
Откройте в Windows **PowerShell от имени администратора** и выполните:

```powershell
wsl --install -d Ubuntu
```

Перезагрузите Windows, если появится запрос. Откройте **Ubuntu** из меню «Пуск» и создайте имя пользователя и пароль Linux. Это учётная запись для `sudo` внутри Ubuntu; она не связана с вашей учётной записью Windows.

Вернитесь в **PowerShell**, обновите WSL и проверьте дистрибутив:

```powershell
wsl --update
wsl --version
wsl --list --verbose
```

В строке Ubuntu должно быть указано **VERSION 2**. Если указано 1, используйте точное имя дистрибутива из списка:

```powershell
wsl --set-version Ubuntu 2
```

Docker требует WSL **2.1.5 или новее**; версия программы WSL из `wsl --version` и столбец **VERSION 2** дистрибутива — это разные проверки. Если установка завершается ошибкой, см. [устранение неполадок установки](/ru/on-premises/installation/using-docker-compose/windows/troubleshooting#wsl-or-docker-reports-that-virtualization-is-unavailable) и [инструкции Microsoft по установке](https://learn.microsoft.com/en-us/windows/wsl/install), а если WSL сообщает, что виртуализация недоступна, включите аппаратную виртуализацию в BIOS/UEFI.
</Step>

<Step title="Установите и запустите Docker Desktop">
Загрузите [Docker Desktop for Windows](https://docs.docker.com/desktop/setup/install/windows-install/) для вашего процессора и запустите установщик. Если будет предложено, используйте бэкенд **WSL 2**. Откройте **Docker Desktop** из меню «Пуск» Windows и дождитесь запуска движка.

В разделе **Settings → General** Docker Desktop включите **Use WSL 2 based engine**, если этот параметр отображается. В разделе **Settings → Resources → WSL Integration** включите интеграцию для **Ubuntu**, затем нажмите **Apply** или **Apply & restart**. Если Ubuntu не является дистрибутивом по умолчанию, явно включите её собственный переключатель.

Если WSL Integration отсутствует, проверьте, что Docker Desktop использует **Linux containers**. См. [руководство Docker по бэкенду WSL 2](https://docs.docker.com/desktop/features/wsl/).

В этом руководстве используйте интеграцию Docker Desktop. Установка второго Docker Engine через `apt install docker.io` или запуск `dockerd` внутри Ubuntu создаёт отдельную конфигурацию и может вызвать конфликты. Если вы уже используете Engine в Ubuntu, перед переключением следуйте рекомендациям Docker по миграции; сохраните существующие данные приложений и резервные копии.
</Step>

<Step title="Проверьте Docker из Ubuntu">
Откройте терминал **Ubuntu**. Выполните в нём следующие команды без `sudo`:

```bash
docker version
docker compose version
docker ps
```

`docker version` должна показать и **Client**, и **Server**. Пустой список контейнеров в новой установке — это нормально. Одна лишь команда `docker --version` не доказывает, что движок работает.

Если `docker` недоступен или не может подключиться, заново откройте Ubuntu после применения WSL Integration и проверьте, что Docker Desktop запущен. См. раздел [Устранение неполадок](/ru/on-premises/installation/using-docker-compose/windows/troubleshooting#docker-is-unavailable-in-ubuntu).
</Step>

<Step title="Проверьте ресурсы и сокет Docker">
Проверьте ресурсы, доступные Docker:

```bash
docker info --format 'CPUs={{.NCPU}} Memory={{.MemTotal}} Kernel={{.KernelVersion}}'
df -h "$HOME"
ls -l /var/run/docker.sock
```

Для небольшого локального экземпляра 4 CPU и 8 ГБ памяти, доступные Docker, — рекомендуемая отправная точка, а не измеренный минимум. Оставьте достаточно памяти и для Windows. При бэкенде WSL 2 лимиты ресурсов управляются через [настройки WSL](https://learn.microsoft.com/en-us/windows/wsl/wsl-config), а не через ползунки ресурсов Docker Desktop, как на Mac. Изменения, требующие `wsl --shutdown`, прерывают работу всех запущенных дистрибутивов WSL и нагрузок Docker; применяйте их до запуска экземпляра.

Оставьте `DOCKER_SOCKET_PATH=/var/run/docker.sock` в конфигурации Toolkit. Этот сокет движка нужен приложению для изолированных компиляций. Не меняйте его права на `777`, чтобы исправить ошибки подключения; вместо этого восстановите интеграцию Docker Desktop.
</Step>
</Steps>
