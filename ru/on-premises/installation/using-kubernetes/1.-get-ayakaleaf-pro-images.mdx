Kubernetes использует те же образы, что и Toolkit. Отдельного образа для Kubernetes нет.

| Образ                                                | Где используется                                                        |
| ---------------------------------------------------- | ----------------------------------------------------------------------- |
| `ghcr.io/ayaka-notes/overleaf-pro:6.3.2`             | Deployment `overleaf`                                                   |
| `ghcr.io/ayaka-notes/overleaf-pro/git-bridge:6.3.2`  | [Интеграция с Git](/ru/on-premises/configuration/kubernetes/integrations/git-integration) (необязательно), тот же тег, что и выше |
| `ghcr.io/ayaka-notes/texlive-*`                      | компиляции; загружаются в Docker на узлах на [шаге 0](/ru/on-premises/installation/using-kubernetes/0.-prepare-the-nodes) |

Образы публично доступны на [ghcr.io](https://github.com/ayaka-notes/ayakaleaf-pro/pkgs/container/overleaf-pro/) для amd64 и arm64, поэтому kubelet может загружать их без учётных данных.

<Warning>

Всегда используйте тег версии, например `6.3.2`, а не `latest`. Обновления запускают миграции базы данных и должны выполняться согласно разделу [Обновление в Kubernetes](/ru/on-premises/maintenance/upgrading-on-kubernetes); изменяющийся тег обновлял бы под при каждом его перепланировании.

</Warning>

### Вопросы и ответы

<Accordion title="Наши узлы не имеют доступа к ghcr.io. Что делать?">

<strong>Ответ:</strong> Скопируйте образы в реестр, доступный узлам, и используйте это имя в манифестах, например:

```bash
docker pull ghcr.io/ayaka-notes/overleaf-pro:6.3.2
docker tag ghcr.io/ayaka-notes/overleaf-pro:6.3.2 registry.example.com/ayakaleaf/overleaf-pro:6.3.2
docker push registry.example.com/ayakaleaf/overleaf-pro:6.3.2
```

Для реестра без TLS containerd на каждом узле нужен файл `/etc/containerd/certs.d/<registry>/hosts.toml` с `server = "http://<registry>"` и `config_path`, заданный как на [шаге 0](/ru/on-premises/installation/using-kubernetes/0.-prepare-the-nodes). Сам Docker отправляет образы по обычному HTTP только на `localhost`, поэтому отправляйте через `localhost:<port>` на хосте реестра или добавьте его в `insecure-registries`.

</Accordion>
