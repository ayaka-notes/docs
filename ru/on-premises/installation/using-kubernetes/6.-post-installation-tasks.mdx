### Создание первой учётной записи администратора {#creating-your-first-administrator-account}

Откройте `OVERLEAF_SITE_URL` с добавлением `/launchpad`, например `http://192.0.2.10:30080/launchpad`, и зарегистрируйте учётную запись администратора, как описано в разделе [Действия после установки для Toolkit](/ru/on-premises/installation/using-docker-compose/linux/6.-post-installation-tasks). Затем создайте пример проекта и скомпилируйте его.

Пользователей также можно создавать из командной строки:

```bash
kubectl -n overleaf exec deploy/overleaf -- bash -c \
  'cd /overleaf/services/web && node modules/server-ce-scripts/scripts/create-user.mjs --admin --email=admin@example.com'
```

Команда выводит ссылку для установки пароля.

### Проверка изоляции компиляций {#checking-that-compiles-are-sandboxed}

Скомпилируйте проект, затем посмотрите на узел, на котором работает под:

```bash
kubectl -n overleaf get pod -l app=overleaf -o wide   # NODE column
# on that node:
sudo docker ps -a --filter ancestor=ghcr.io/ayaka-notes/texlive-full:2026.1
ls -ln /srv/overleaf/compiles                          # owned by uid 33 (www-data)
```

Каждая компиляция отображается как кратковременный контейнер с именем `project-<project id>-<user id>-...`.

### Журналы и оболочка {#logs-and-a-shell}

| Toolkit          | Kubernetes                                                               |
| ---------------- | ------------------------------------------------------------------------ |
| `bin/logs web`   | `kubectl -n overleaf exec deploy/overleaf -- tail -f /var/log/overleaf/web.log` |
| `bin/shell`      | `kubectl -n overleaf exec -it deploy/overleaf -- bash`                    |
| `bin/up`         | `kubectl apply -f .`, затем `kubectl -n overleaf rollout restart deployment/overleaf` |

Контейнер пишет по одному файлу журнала на сервис в `/var/log/overleaf/` (`web.log`, `clsi.log`, `real-time.log`, `document-updater.log`, ...); `kubectl logs` показывает вывод при запуске.

### Что переживает перезапуск {#what-survives-a-restart}

`kubectl rollout restart` заменяет поды. Сохраняется только то, что находится на томе. Изменения, внесённые внутри пода через `kubectl exec`, например установленные пакеты или отредактированные файлы, теряются вместе с ним, как и журналы, если `/var/log/overleaf` не находится на томе, см. [Журналирование](/ru/on-premises/configuration/kubernetes/logging). Вносите постоянные изменения в свои манифесты.

### Вопросы и ответы {#q&a}

<Accordion title="Компиляция завершается ошибкой или никогда не заканчивается.">

<strong>Ответ:</strong> Проверьте на узле, где работает под, что Docker запущен и в нём есть образ, указанный в `TEX_LIVE_DOCKER_IMAGE`, а также что `SANDBOXED_COMPILES_HOST_DIR_*` совпадают с путями `hostPath`. В `/var/log/overleaf/clsi.log` в поде указан шаг, на котором происходит сбой.

</Accordion>

<Accordion title="Пользователи выходят из системы после каждого перезапуска пода.">

<strong>Ответ:</strong> В Secret `overleaf-secrets` отсутствует `OVERLEAF_SESSION_SECRET`, см. [шаг 2](/ru/on-premises/installation/using-kubernetes/2.-create-the-namespace-and-secrets).

</Accordion>
