[Toolkit](/ru/on-premises/installation/using-the-toolkit) — рекомендуемый способ запуска Ayakaleaf Pro на одном сервере. Если у вас уже есть кластер Kubernetes, в этом разделе тот же контейнер разворачивается в нём с помощью простых манифестов `kubectl`: без дополнительного образа и без Helm-чарта.

К концу этого раздела у вас будет один экземпляр Ayakaleaf Pro с изолированной компиляцией, набор реплик MongoDB и Redis — всё в пространстве имён `overleaf`. Чтобы затем запустить несколько экземпляров за балансировщиком нагрузки, продолжите с раздела [Горизонтальное масштабирование](/ru/on-premises/configuration/kubernetes/horizontal-scaling).

<Info>

Поддержка Kubernetes экспериментальная. Мы не публикуем Helm-чарт или образы специально для Kubernetes. Манифесты на этих страницах — те, что мы протестировали в Kubernetes 1.37 (kubeadm, containerd 2.4, flannel) на трёх узлах с 2 vCPU и 4 ГБ памяти каждый. Адаптируйте хранилище, сеть и ingress под свой кластер.

</Info>

### Как всё сочетается

| Toolkit (один сервер)                        | Kubernetes                                                               |
| -------------------------------------------- | ------------------------------------------------------------------------ |
| `config/variables.env`                       | ConfigMap `overleaf-env` и Secret `overleaf-secrets`                     |
| Контейнер `sharelatex`                       | Deployment `overleaf` (один под со всеми сервисами Overleaf)             |
| Контейнеры `mongo` и `redis`                 | StatefulSet `mongo` (набор реплик) и `redis` или ваши управляемые сервисы |
| `~/overleaf-toolkit/data/overleaf`           | PersistentVolumeClaim `overleaf-data`                                    |
| Docker на хосте, используемый для компиляций | Docker Engine на каждом узле, где работает Ayakaleaf Pro                 |
| `bin/up`, `bin/logs`, `bin/shell`            | `kubectl apply`, `kubectl logs`, `kubectl exec`                          |

### Что вам понадобится

* Кластер Kubernetes, на узлы которого можно устанавливать пакеты: каждому узлу, на котором может работать Ayakaleaf Pro, нужен **Docker Engine**, потому что компиляции выполняются в контейнерах TeX Live, которые Ayakaleaf Pro запускает через `/var/run/docker.sock` узла. См. [0. Подготовка узлов](/ru/on-premises/installation/using-kubernetes/0.-prepare-the-nodes).
* StorageClass по умолчанию с томами `ReadWriteOnce`.
* `kubectl` и `openssl` на вашей рабочей станции.
