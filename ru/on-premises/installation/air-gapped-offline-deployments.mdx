В целом мы не рекомендуем развертывать Ayakaleaf Pro в автономной среде, поскольку многие его функции, например GitHub Sync и интеграция с Zotero, требуют подключения к интернету.

Если вы хотите работать автономно, доступ к реестру `ghcr.io` для загрузки необходимых образов `ayakaleaf-pro` и TeX Live может быть не всегда возможен. Это не проблема: Docker предоставляет средства для экспорта и импорта образов, которые помогут при автономном развертывании или развертывании в изолированной сети (air-gapped).

В общих чертах вы загрузите необходимые образы на устройстве с доступом к интернету, экспортируете их на переносной носитель (или передадите с помощью SCP/Rsync) и импортируете на изолированный сервер.

Для этого выполните следующие шаги:

* На машине с доступом к интернету загрузите все необходимые образы (`overleaf-pro`, `git-bridge`, `mongo`, `redis` + все нужные [образы TeX Live](https://docs.overleaf.com/on-premises/configuration/overleaf-toolkit/server-pro-only-configuration/sandboxed-compiles#available-tex-live-images) для использования с [Sandboxed Compiles](https://docs.overleaf.com/on-premises/configuration/overleaf-toolkit/server-pro-only-configuration/sandboxed-compiles))
  * `docker pull ghcr.io/ayaka-notes/overleaf-pro:6.3.0`
  * `docker pull ghcr.io/ayaka-notes/overleaf-pro/git-bridge:6.3.0` (тег должен совпадать с тегом `overleaf-pro`)
  * `docker pull mongo:8.0` (замените на фактическую версию)
  * `docker pull redis:7.4` (замените на фактическую версию)
  * `docker pull ghcr.io/ayaka-notes/texlive-full:2024.1` (замените на фактическую версию)
* Затем **каждый** из загруженных образов необходимо экспортировать в файл .tar. Например, `docker save ghcr.io/ayaka-notes/overleaf-pro:6.3.0 > overleaf-pro:6.3.0.tar`
* Любым удобным способом перенесите файлы `.tar` с машины, подключённой к интернету, на автономный/изолированный сервер
* Для каждого файла .tar выполните команду `docker load`, чтобы загрузить образ из файла .tar. Например, `docker load < overleaf-pro:6.3.0.tar`
* Наконец, выполните команду `docker images`, чтобы просмотреть образы и убедиться, что они успешно загружены и доступны

<Danger>

По умолчанию при выполнении команды `bin/up` Toolkit пытается автоматически загрузить все образы TeX Live, заданные в `ALL_TEX_LIVE_DOCKER_IMAGES` в файле `config/variables.env`. Поскольку ваше развертывание изолировано, это завершится ошибкой — чтобы отключить такое поведение, задайте `SIBLING_CONTAINERS_PULL=false` в `config/overleaf.rc`.

</Danger>
