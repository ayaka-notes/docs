RHEL и его пересборки (Rocky Linux, AlmaLinux) поставляются с Podman вместо Docker, а некоторые организации не разрешают Docker на своих серверах. Toolkit может запускать Ayakaleaf Pro на **rootless Podman**: контейнеры работают от имени обычного пользователя, компиляция по-прежнему выполняется в изолированных контейнерах TeX Live, а SELinux остаётся в режиме enforcing. Скрипт `bin/podman-setup` проверяет хост и исправляет то, что может.

В конце этого раздела у вас будет такой же экземпляр, как в разделе [С помощью Docker Compose](/ru/on-premises/installation/using-docker-compose): Ayakaleaf Pro с изолированной компиляцией, MongoDB и Redis, которым вы управляете привычными командами `bin/up`, `bin/doctor` и `bin/upgrade`.

<Info>

Поддержка Podman экспериментальная. Она взята из официального Overleaf Toolkit, который тестирует её только в RHEL 9 и новее с rootless Podman, изолированной компиляцией и SELinux в режиме enforcing. Мы проверили эти страницы на Rocky Linux 9.9 (Podman 5.8, SELinux enforcing) с Ayakaleaf Pro 6.3.4. Рекомендуемой средой выполнения контейнеров остаётся Docker.

</Info>

### Что вам понадобится {#what-you-need}

* **RHEL, Rocky Linux, AlmaLinux или CentOS Stream 9 или новее** с SELinux в режиме enforcing. В любом другом дистрибутиве `bin/podman-setup` останавливается. В Ubuntu или Debian используйте [С помощью Docker Compose](/ru/on-premises/installation/using-docker-compose/linux).
* **Пользователь без прав root с доступом к `sudo`**, которому будут принадлежать контейнеры. Выполняйте все команды этого раздела от имени этого пользователя; `bin/podman-setup` отказывается запускаться от `root`.
* **Чистый хост**: без Docker Engine и без существующей установки Toolkit. Перенос существующего экземпляра на Docker в Podman здесь не описан.

### Чем это отличается от Docker {#how-it-differs-from-docker}

|                                  | Docker                               | Rootless Podman                                                                          |
| -------------------------------- | ------------------------------------ | ---------------------------------------------------------------------------------------- |
| Кто запускает контейнеры         | Демон Docker от имени `root`         | Ваш пользователь                                                                         |
| Сокет для запуска компиляции     | `/var/run/docker.sock`               | `/run/user/<uid>/podman/podman.sock`                                                     |
| Порты                            | Любые, например `80` и `443`         | `1024` и выше, например `8080`                                                           |
| Брандмауэр хоста (`firewalld`)   | Опубликованные порты его обходят     | Действует: откройте порт с помощью `firewall-cmd`                                        |
| Запуск после перезагрузки        | Их перезапускает демон Docker        | Пользовательская служба `podman-restart`                                                 |
| SELinux                          | Toolkit не настраивает               | Модуль политики `podman_socket_clsi` и `SELINUX_MODE=managed` в `config/overleaf.rc`      |
| Профиль seccomp для компиляции   | Встроен в образ                      | Toolkit извлекает его в `config/seccomp/<version>/` и задаёт как `SECCOMP_PROFILE`       |

### Известные ограничения {#known-limitations}

* <strong>Интеграция с Git.</strong> В Ayakaleaf Pro 6.3.4 `git clone` на Podman завершается ошибкой `502`: NGINX внутри образа ищет контейнер `git-bridge` через DNS-сервер Docker (`127.0.0.11`), которого в Podman нет. Исправление ([1b911d1092](https://github.com/ayaka-notes/ayakaleaf-pro/commit/1b911d1092c80f7b0ff77c5e3805b40503d49964)) войдёт в следующий выпуск; до тех пор оставьте `GIT_BRIDGE_ENABLED=false`.
* <strong>IP-адреса клиентов.</strong> Rootless Podman перенаправляет опубликованный порт изнутри сети контейнера, поэтому Ayakaleaf Pro видит каждого посетителя с внутренним адресом, например `10.89.0.15`. [Журналы аудита](/ru/on-premises/user-guide/administrators/user-management#audit-logs) пользователя в панели администратора показывают этот адрес вместо его IP-адреса.
