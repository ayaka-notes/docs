`bin/podman-setup` проверяет всё, что нужно Ayakaleaf Pro на Podman. Без параметров скрипт только сообщает о результатах; с `--apply` он также исправляет найденные проблемы.

<Steps>
<Step title="Проверка хоста">
```bash title="Check only"
bin/podman-setup
```

На чистом хосте большинство проверок не проходит, например:

```text
====== Packages ======
[✗] podman not installed
[✗] podman-docker not installed
...
====== Summary ======
[✓] 7 passed  [!] 13 warnings  [✗] 4 failures
```
</Step>

<Step title="Применение исправлений">
```bash title="Check and fix"
bin/podman-setup --apply
```

Запускайте скрипт в терминале: для общесистемных шагов он запрашивает пароль `sudo`. Он также загружает образ Ayakaleaf Pro, чтобы извлечь из него профиль seccomp, что в первый раз занимает несколько минут. В конце он снова проверяет хост:

```text
====== Summary ======
[✓] 23 passed  [!] 2 warnings  [✗] 0 failures
[!] Warnings remaining:
[!] not logged in to quay.io
[!] container → socket skipped (sharelatex not running)
```

Оба предупреждения на этом этапе ожидаемы:

* `not logged in to quay.io`: эта проверка взята из официального Toolkit, где образ Server Pro находится в закрытом реестре. Образы Ayakaleaf Pro публично доступны в `ghcr.io` и не требуют входа, поэтому игнорируйте это предупреждение. Оно останется и после установки.
* `container → socket skipped (sharelatex not running)`: для этой проверки нужен запущенный экземпляр. Вы снова запустите скрипт в шаге [3. Запуск Ayakaleaf Pro](/ru/on-premises/installation/using-podman/3.-start-ayakaleaf-pro).

Скрипт завершается с кодом `0`, если все проверки пройдены, `1` при наличии предупреждений и `2` при наличии ошибок. Из-за предупреждения о quay.io ожидайте `1`.
</Step>
</Steps>

### Что меняет скрипт {#what-the-script-changes}

С `--apply` скрипт может изменить следующее.

На уровне системы, через `sudo`:

* Устанавливает `podman`, `podman-docker`, `git`, `curl`, `checkpolicy` и `policycoreutils` с помощью `dnf`.
* Включает lingering для вашего пользователя с помощью `loginctl`, чтобы контейнеры продолжали работать после выхода из системы.
* Создаёт `/etc/containers/nodocker`, что отключает сообщение "Emulate Docker CLI using podman".
* Загружает модуль политики SELinux `podman_socket_clsi`, если `SELINUX_MODE=managed`.

Для вашего пользователя:

* Включает пользовательскую службу `podman.socket`, Docker-совместимый API, через который Ayakaleaf Pro запускает компиляцию.
* Устанавливает Docker Compose v2 с GitHub в `~/.local/bin/docker-compose` и создаёт на него ссылку в `~/.docker/cli-plugins/`.
* Настраивает Podman на использование этого Compose в `~/.config/containers/containers.conf`.
* Добавляет псевдонимы `mongo` и `redis` в `~/.config/containers/registries.conf.d/overleaf-toolkit.conf`, чтобы Podman знал, откуда загружать образы с этими короткими именами.

В Toolkit:

* Задаёт `DOCKER_SOCKET_PATH` и `DOCKER_HOST` в `config/overleaf.rc` равными `/run/user/<uid>/podman/podman.sock`.
* Извлекает профиль seccomp для компиляции из образа Ayakaleaf Pro в `config/seccomp/<version>/clsi-profile.json` и задаёт `SECCOMP_PROFILE` в `config/variables.env`. В отличие от Docker, Podman нужен этот профиль в виде файла на хосте.
* Собирает модуль политики SELinux в `config/selinux/`.
* Назначает владельцев каталогов данных в `data/` с помощью `podman unshare chown`, когда они уже существуют.

<Info>

Каждому изменению соответствует проверка. Если вы что-то меняете вручную, например в `config/overleaf.rc`, снова запустите `bin/podman-setup`, чтобы проверить результат.

</Info>
