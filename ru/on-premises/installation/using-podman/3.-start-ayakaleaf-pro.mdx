---
title: 3. Запуск Ayakaleaf Pro
description: Запустите Ayakaleaf Pro на Podman, проверьте его с помощью podman-setup и bin/doctor и настройте запуск после перезагрузки.
icon: circle-play
---

<Steps>
<Step title="Запуск контейнеров">
```bash title="Start Ayakaleaf Pro"
bin/up -d
```

При первом запуске загружаются образы MongoDB, Redis и TeX Live и создаются каталоги данных в `data/`. Выводится предупреждение о том, что поддержка Podman экспериментальная.

<Info>

При первом запуске также может появиться `MongoNetworkError: connect ECONNREFUSED 127.0.0.1:27017`. Toolkit настраивает набор реплик MongoDB, пока MongoDB ещё запускается, и повторяет попытки, пока она не ответит. Эту строку можно игнорировать.

</Info>

Через минуту-другую убедитесь, что контейнеры работают:

```bash title="List the containers"
podman ps --format "{{.Names}} {{.Status}}"
```

```text
mongo Up 34 seconds (healthy)
redis Up 20 seconds
sharelatex Up 20 seconds
```
</Step>

<Step title="Повторная проверка настройки">
Теперь, когда каталоги данных существуют и контейнер `sharelatex` работает, `bin/podman-setup` может завершить свои проверки:

```bash title="Check the setup"
bin/podman-setup
```

Скрипт проверяет владельцев новых каталогов данных и тестирует сокет Podman изнутри контейнера `sharelatex`:

```text
====== Socket Connectivity ======
[✓] host → socket OK
[✓] container → socket OK

====== Data Directory Permissions ======
[✓] mongo data dir owned by 999
[✓] redis data dir owned by 999
[✓] overleaf data dir owned by 33
...
====== Summary ======
[✓] 27 passed  [!] 1 warnings  [✗] 0 failures
[!] Warnings:
[!] not logged in to quay.io
```

`container → socket OK` означает, что Ayakaleaf Pro может запускать контейнеры компиляции. Если проверка не проходит, выполните `bin/podman-setup --apply`, а затем `bin/up -d`. Предупреждение о quay.io к Ayakaleaf Pro не относится, см. [2. Запуск podman-setup](/ru/on-premises/installation/using-podman/2.-run-podman-setup).
</Step>

<Step title="Запуск doctor">
```bash title="Run the doctor"
bin/doctor
```

На Podman отчёт показывает среду выполнения и параметры безопасности:

```text
- Container Daemon
    - status: up
    - runtime: podman
    - server version: 5.8.5
    - socket: /run/user/1000/podman/podman.sock
    - DOCKER_HOST: unix:///run/user/1000/podman/podman.sock
    - host → socket: OK
    - container → socket: OK
- Security
    - SELinux: Enforcing
    - SELINUX_MODE: managed
    - SELINUX_LABEL: sharelatex_t
    - SELinux module: loaded (podman_socket_clsi)
    - SELinux rules: present
    - Seccomp profile: present
```

Предупреждение `Server Pro enabled, but not logged in to quay.io repository` в конце относится к той же проверке quay.io, см. [Получение помощи](/ru/on-premises/support/getting-help#q-and-a).
</Step>

<Step title="Запуск Ayakaleaf Pro после перезагрузки">
В Docker после перезагрузки контейнеры снова запускает демон Docker. У rootless Podman нет демона: включите пользовательскую службу, которая запускает ваши контейнеры при загрузке сервера:

```bash title="Start the containers at boot"
systemctl --user enable podman-restart.service
```

Она запускает все контейнеры вашего пользователя с политикой перезапуска `always`, которую Toolkit задаёт для всех своих контейнеров. Для этого нужен lingering, который включил `bin/podman-setup --apply`. Без этой службы выполняйте `bin/up -d` после каждой перезагрузки.
</Step>

<Step title="Открытие порта в брандмауэре">
По умолчанию экземпляр принимает подключения только с самого сервера, по адресу `http://localhost:8080`. Чтобы открыть его с других компьютеров, задайте `OVERLEAF_LISTEN_IP` в `config/overleaf.rc` и `OVERLEAF_SITE_URL` в `config/variables.env`, как описано в шаге [5. Персонализация экземпляра](/ru/on-premises/installation/using-docker-compose/linux/5.-personalizing-your-instance#listen-address-and-port), и снова выполните `bin/up -d`.

В отличие от Docker, rootless Podman не обходит брандмауэр хоста. Если работает `firewalld`, что в RHEL происходит по умолчанию, откройте порт:

```bash title="Open port 8080"
sudo firewall-cmd --permanent --add-port=8080/tcp
sudo firewall-cmd --reload
```

На облачном сервере также разрешите порт в группе безопасности провайдера. Прежде чем открывать экземпляр в интернет, настройте HTTPS, см. [4. Действия после установки](/ru/on-premises/installation/using-podman/4.-post-installation-tasks#use-https).
</Step>
</Steps>
