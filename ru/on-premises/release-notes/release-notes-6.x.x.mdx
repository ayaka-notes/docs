<Accordion title="Миграция Zotero / Mendeley для существующих установок">

При обновлении до повторно выпущенного образа 6.3.0 перенесите метаданные существующих связанных файлов библиографии Zotero/Mendeley с помощью приведённого ниже скрипта. Эта миграция сопровождает исправление `12031b8dfd`.

Она переименовывает `zoteroGroupId` / `mendeleyGroupId` в `group_id`, переименовывает `importedByUserId` в `importer_id` и удаляет `importedByName`.

Перед запуском миграции создайте резервную копию MongoDB и остановите приложение. MongoDB должна продолжать работать. Откройте её оболочку (замените `mongo` на имя вашего контейнера):

```bash
docker exec -it mongo mongosh
```

Выполните следующее в `mongosh` (замените `sharelatex` на имя вашей базы данных):

```javascript
use sharelatex

(async () => {
  let updated = 0
  await db.projects.find({}, { rootFolder: 1 }).forEach(async project => {
    const changes = {}
    function visit(folders, path) {
      for (const [i, folder] of (folders || []).entries()) {
        const folderPath = `${path}.${i}`
        for (const [j, file] of (folder.fileRefs || []).entries()) {
          const data = { ...file.linkedFileData }
          if (!["zotero", "mendeley"].includes(data.provider)) continue
          const groupKey = `${data.provider}GroupId`
          if (![groupKey, "importedByUserId", "importedByName"].some(key => key in data)) continue
          for (const [oldKey, newKey] of [[groupKey, "group_id"], ["importedByUserId", "importer_id"]]) {
            if (data[oldKey] != null && data[oldKey] !== "") {
              const value = String(data[oldKey])
              if (newKey in data && data[newKey] !== value) {
                throw new Error(`Conflicting ${newKey}: project ${project._id}, file ${file._id}`)
              }
              data[newKey] = value
            }
            delete data[oldKey]
          }
          delete data.importedByName
          changes[`${folderPath}.fileRefs.${j}.linkedFileData`] = data
        }
        visit(folder.folders, `${folderPath}.folders`)
      }
    }
    visit(project.rootFolder, "rootFolder")
    if (!Object.keys(changes).length) return
    const result = await db.projects.updateOne(
      { _id: project._id, rootFolder: { $eq: project.rootFolder } },
      { $set: changes }
    )
    if (!result.matchedCount) throw new Error(`Project changed during migration: ${project._id}`)
    updated += result.modifiedCount
  })
  print(`Updated ${updated} project(s).`)
})()
```

Скрипт обрабатывает вложенные папки и изменяет только метаданные Zotero/Mendeley. Его можно безопасно запускать повторно: после завершённой миграции следующий запуск сообщит `Updated 0 project(s).` Если скрипт остановится из-за конфликта, проверьте указанный проект/файл; более ранние проекты к этому моменту уже могут быть перенесены.

Запустите обновлённое приложение, перезагрузите редактор и обновите существующий файл библиографии от имени пользователя, который его изначально импортировал. Исторические снимки не перезаписываются. Чтобы откатиться на старую версию приложения, восстановите резервную копию MongoDB.

Мы с гордостью представляем выпуск Overleaf Pro 6.3.0 — самого мощного и функционального онлайн-редактора LaTeX в сообществе. Мы всегда стремимся улучшать опыт наших пользователей, и этот выпуск приносит масштабные изменения и замечательные функции, которые вам непременно понравятся, включая ИИ-ассистента и интеграцию со сторонними менеджерами библиографии.

### Изменения

* ИИ-чат-ассистент: общайтесь с ИИ-моделью через собственного поставщика прямо в редакторе.
* Ассистент по ошибкам LaTeX: получайте предложенные ИИ исправления ошибок компиляции LaTeX.
* Интеграция с Mendeley: импорт ссылок из Mendeley по аналогии с Zotero.
* API Open in Overleaf: добавлен API для открытия содержимого в Overleaf.
* Галерея шаблонов: добавлены постраничный вывод, поиск и сортировка на стороне сервера, поэтому для больших галерей больше не нужно загружать все шаблоны в браузер.
* Переводы: обновлены патчи переводов для 6.3.0, включая новые тексты интерфейса на всех поддерживаемых языках.
* Исходный Overleaf 6.3.0: включает редактирование файлов во вкладках, отдельные логотипы в шапке для светлой и тёмной тем, а также обновления зависимостей и базового образа.
* Добавлены `OVERLEAF_HEADER_IMAGE_URL_LIGHT` и `OVERLEAF_HEADER_IMAGE_URL_DARK` для поддержки отдельных изображений логотипа в шапке для светлой и тёмной тем.
* Теперь файлы можно открывать в разных вкладках редактора.
* Добавлена поддержка настраиваемых HTTP(S)-прокси, включая локально размещённые, через `OVERLEAF_LINKED_URL_OUTBOUND_PROXY`, который также используется API Open in Overleaf.

#### Функция 04: Постраничный вывод шаблонов

Теперь постраничный вывод, сортировка и поиск в галерее выполняются в MongoDB. Это работает без какой-либо подготовки; при тысячах шаблонов вы можете дополнительно добавить следующие индексы, чтобы сохранить высокую скорость работы (команду можно безопасно запускать повторно; `mongo`/`sharelatex` — имена вашего контейнера и базы данных):

```bash
docker exec mongo mongosh sharelatex --quiet --eval '
db.templates.createIndex({category:1,lastUpdated:-1},{name:"category_1_lastUpdated_-1",background:true});
db.templates.createIndex({lastUpdated:-1},{name:"lastUpdated_-1",background:true});
db.templates.createIndex({category:1,name:1},{name:"category_1_name_1_ci",collation:{locale:"en",strength:2},background:true});
db.templates.createIndex({name:1},{name:"name_1_ci",collation:{locale:"en",strength:2},background:true});
'
```

Оставьте `collation` для двух индексов `*_ci` в точности как указано — галерея выполняет запросы с той же схемой сравнения (collation), а MongoDB использует только индекс с совпадающей схемой.

## Ayakaleaf Pro 6.2.2

<strong>Дата выпуска:</strong> 2026.07.23

См.: [https://github.com/ayaka-notes/ayakaleaf-pro/releases/tag/pro-v6.2.2](https://github.com/ayaka-notes/ayakaleaf-pro/releases/tag/pro-v6.2.2)

### Изменения

Перенесены официальные патчи с исправлениями из исходного Overleaf `6.2.2` (поверх `6.2.1`):

* Секрет токена приглашения в проект больше не попадает в журналы. Шифровальщик токенов приглашений при каждом шифровании/расшифровке записывал в журнал собственную конфигурацию, включая пароли шифрования, производные от `OVERLEAF_INVITE_TOKEN_SECRET`.
* Отправка исходящей почты переведена с клиента AWS SES v1, срок поддержки которого истёк, на SESv2. Экземпляры, настроенные с почтовым драйвером `ses`, могли вообще не отправлять письма; теперь отправка выполняется через `SESv2Client`.
* Групповые пункты раскрывающегося списка общего доступа к проекту скрыты за новым флагом функции `group-link-sharing`, поэтому совместный доступ по ссылке для групп больше не предлагается в экземплярах, где он неприменим.
* Исправлено модальное окно общего доступа к проекту для соавторов. При его открытии не владельцем или при отключённом процессе `sharing-updates` отправлялся запрос, который всегда завершался ошибкой и выводил сообщение "something went wrong".
* В document-updater добавлен `scripts/flush_docs_with_pending_updates.js` — служебный скрипт для восстановления документов, у которых в Redis осталась зависшая очередь `PendingUpdates` после сброса или окончательного удаления проекта. Поддерживает `--dry-run` и проверку безопасности `--estimated-docs`.
* Обновлены зависимости: `multer` 2.2.0, `form-data` 2.5.6, `protobufjs` 7.6.3, `@grpc/grpc-js` 1.14.4.

Этот выпуск также включает следующие исправления и улучшения Ayakaleaf Pro:

* Добавлены полные переводы ещё на 16 языков (cs, da, de, es, fi, fr, it, ja, ko, nl, no, pl, pt, ru, sv, tr), исправлены непереведённые строки, например на странице сброса пароля. Исправляет [#38](https://github.com/ayaka-notes/ayakaleaf-pro/issues/38).
* Исправлено количество элементов на кнопке «show N more projects» в панели администратора, которая показывала неверное число из-за некорректной передачи заполнителя множественного числа.
* Исправлены ошибки валидации экспорта в GitHub: теперь они отображаются через статические ключи i18n, а не в виде необработанных сообщений; удалены ключи ошибок, которые больше не используются модальным окном GitHub Sync.

### Изменения

Перенесены официальные патчи с исправлениями из исходного Overleaf `6.2.1` (поверх `6.2.0`):

* Исправлен редактор (клиент ShareJS): операции, сводящиеся к пустой операции — взаимно уничтоженные удалённой/параллельной операцией или полностью отменённые через undo, — теперь отбрасываются, а не отправляются на сервер, и документ корректно отображается как сохранённый. Это предотвращает ложные проблемы синхронизации / «несохранённых изменений» при отмене действий и параллельном редактировании.

В этом выпуске минимальная версия MongoDB повышена до `8.0`.

Если вы сейчас используете MongoDB `v6` или более раннюю версию, необходимо обновляться последовательно, по одной мажорной версии за раз (`v6 → v7 → v8`).

<Warning>

Обязательно создайте резервную копию [базы данных](https://docs.overleaf.com/on-premises/maintenance/data-and-backups) **перед** обновлением. В случае отката потребуется восстановить базу данных из резервной копии.

</Warning>

Инструкции по обновлению MongoDB `v6 → v7 → v8` см. в нашем пошаговом руководстве [здесь](https://docs.overleaf.com/on-premises/maintenance/updating-mongodb#example-upgrading-mongodb-from-6.0-to-7.0-toolkit-users).

В этом выпуске также повышена минимальная версия Redis до `7.4`.

### Новые функции

* Совместный доступ по ссылке теперь можно отключить с помощью `OVERLEAF_DISABLE_LINK_SHARING=true`.
* Для настройки заголовка и содержимого страницы технического обслуживания теперь доступны `OVERLEAF_MAINTENANCE_MESSAGE` и `OVERLEAF_MAINTENANCE_MESSAGE_HTML`.
* С помощью `OVERLEAF_USER_HARD_DELETION_DELAY` и `OVERLEAF_PROJECT_HARD_DELETION_DELAY` можно настроить (в миллисекундах) задержку окончательного удаления удалённых пользователей/проектов (по умолчанию 90 дней).

### Исправления ошибок

* Исправлено отображение нижнего колонтитула со ссылками.
* Улучшены сообщения об ошибках при входе через SAML.
* Исправлено отсутствие записи в журнале аудита при изменении статуса администратора пользователя во время входа через SSO.
* Исправлены ошибки панели истории при включённом TLS в Redis.
* Теперь компиляцию можно остановить при использовании неизолированной компиляции.

### Прочие изменения

* Все ссылки на страницу статуса (задаваемую через `OVERLEAF_STATUS_PAGE_URL`) теперь используют `HTTPS` и открываются в новой вкладке браузера.
