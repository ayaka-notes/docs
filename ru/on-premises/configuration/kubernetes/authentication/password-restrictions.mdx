Сервис **web** проверяет локальные пароли, когда пользователи регистрируются, задают или меняют пароль. На вход через SSO (LDAP, SAML, OIDC) это не влияет: за их пароли отвечает провайдер удостоверений. Описание для Toolkit см. в разделе [Ограничения паролей](/ru/on-premises/configuration/overleaf-toolkit/authentication/password-restrictions).

| | |
| --- | --- |
| Сервис | web в каждом поде Ayakaleaf Pro; считывается при запуске web |
| Сеть | нет |
| Периодические задания | нет |

### Настройка

Добавьте в ConfigMap `overleaf-env` и перезапустите:

```yaml title="30-config.yaml (additions)"
  OVERLEAF_PASSWORD_VALIDATION_MIN_LENGTH: "12"
  OVERLEAF_PASSWORD_VALIDATION_MAX_LENGTH: "72"
```

```bash
kubectl apply -f 30-config.yaml
kubectl -n overleaf rollout restart deployment/overleaf     # or statefulset/overleaf
```

| Переменная | По умолчанию | |
| --- | --- | --- |
| `OVERLEAF_PASSWORD_VALIDATION_MIN_LENGTH` | `8` | Минимальная допустимая длина пароля. |
| `OVERLEAF_PASSWORD_VALIDATION_MAX_LENGTH` | `72` | Максимальная допустимая длина пароля; значения больше `72` считаются равными `72`. |

Заключайте числа в кавычки: ConfigMap хранит только строки.

<Warning>

`OVERLEAF_PASSWORD_VALIDATION_PATTERN` считывается, но не применяется: пароль, не соответствующий шаблону, принимается. Действуют только ограничения длины.

</Warning>

### Несколько реплик

Ничего дополнительного не требуется: все реплики читают один и тот же ConfigMap.

### Проверено на Kubernetes

На Kubernetes 1.37 с одной репликой, с `OVERLEAF_PASSWORD_VALIDATION_MIN_LENGTH: "12"` и `OVERLEAF_PASSWORD_VALIDATION_PATTERN: aA$3` в ConfigMap, при активации новой учётной записи пароль из 10 символов был отклонён, а пароль из 20 символов, состоящий только из строчных букв, который шаблон должен был бы отклонить, был принят. Наши сквозные тесты регистрации также отклоняют `123456` как слишком короткий при настройках по умолчанию.
