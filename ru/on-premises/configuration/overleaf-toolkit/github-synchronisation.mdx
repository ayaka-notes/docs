### Настройка синхронизации с GitHub

<Warning>

Перед использованием синхронизации с GitHub необходимо сначала включить [git-bridge](/ru/on-premises/configuration/overleaf-toolkit/git-integration).

```dotenv title="config/overleaf.rc"
GIT_BRIDGE_ENABLED=true
```

</Warning>

Перейдите в [настройки разработчика](https://github.com/settings/developers), чтобы создать OAuth-приложение GitHub, и скопируйте ваши `CLIENT_ID` и `SECRET`.

**Примечание**: ваш URL обратного вызова OAuth: `${OVERLEAF_SITE_URL}/user/github-sync/oauth2/callback`.

Затем добавьте следующие настройки в файлы переменных окружения Overleaf.

```dotenv title="config/variables.env" wrap
# used to encrypt the user's GitHub access token.
# How to generate: `openssl rand -hex 32`
GITHUB_TOKEN_CIPHER_PASSWORD=0123456789ABCDEFG # changed to yours

# Github Sync Settings
GITHUB_SYNC_ENABLED=true
GITHUB_SYNC_CLIENT_ID=
GITHUB_SYNC_CLIENT_SECRET=

# OAuth callback is: ${OVERLEAF_SITE_URL}/user/github-sync/oauth2/callback
# (Optional) GITHUB_SYNC_PROXY_URL=http://10.0.0.1:10808
```

<Warning>

Перед настройкой URL обратного вызова OAuth в GitHub убедитесь, что `OVERLEAF_SITE_URL` задан правильно.

</Warning>

Если вы находитесь в регионе с ограниченным доступом к сети, для доступа к GitHub может потребоваться прокси. Задайте следующую переменную окружения: `GITHUB_SYNC_PROXY_URL=http://10.0.0.1:10808`. Убедитесь, что использование прокси соответствует местному законодательству и нормативным актам.

<Warning>

`GITHUB_SYNC_PROXY_URL` должен быть стандартным прямым HTTP/HTTPS-прокси (например, HTTP-порт Clash). Зеркала для загрузки с GitHub, такие как `gh-proxy.org`, не поддерживаются.

</Warning>

<Warning>

Не используйте `127.0.0.1` в качестве хоста прокси. Если прокси работает на хост-сервере, используйте IP-адрес сервера в локальной сети (например, `192.168.1.xx`) и убедитесь, что прокси настроен на приём подключений от устройств локальной сети.

</Warning>

### GitHub Enterprise

<Info>

Поддержка GitHub Enterprise доступна начиная с версии v6.3.1. Более ранние версии подключаются только к `github.com`, и перечисленные ниже переменные в них не действуют.

</Info>

По умолчанию синхронизация с GitHub подключается к `github.com`. Чтобы использовать GitHub Enterprise Server (самостоятельно размещённый) или GitHub Enterprise Cloud с размещением данных в выбранном регионе (`GHE.com`), задайте в `GITHUB_SYNC_URL` веб-адрес вашего экземпляра — тот, по которому вы открываете репозитории в браузере.

```dotenv title="config/variables.env" wrap
# GitHub Enterprise Server
GITHUB_SYNC_URL=https://github.example.com

# or GitHub Enterprise Cloud with data residency
# GITHUB_SYNC_URL=https://octocorp.ghe.com
```

Адреса REST и GraphQL API определяются на основе `GITHUB_SYNC_URL` так же, как это делает GitHub CLI:

| `GITHUB_SYNC_URL`             | REST API                         | GraphQL API                              |
| ----------------------------- | -------------------------------- | ---------------------------------------- |
| `https://github.com` (по умолчанию) | `https://api.github.com`         | `https://api.github.com/graphql`         |
| `https://SUBDOMAIN.ghe.com`   | `https://api.SUBDOMAIN.ghe.com`  | `https://api.SUBDOMAIN.ghe.com/graphql`  |
| `https://HOST` (любой другой)    | `https://HOST/api/v3`            | `https://HOST/api/graphql`               |

Задавайте адреса API только в том случае, если ваш экземпляр предоставляет их по другому адресу, например за API-шлюзом:

| Переменная                | Значение по умолчанию                                                                     |
| ------------------------- | ----------------------------------------------------------------------------------------- |
| `GITHUB_SYNC_URL`         | `https://github.com`                                                                      |
| `GITHUB_SYNC_API_URL`     | Определяется на основе `GITHUB_SYNC_URL`, см. таблицу выше                                |
| `GITHUB_SYNC_GRAPHQL_URL` | Определяется на основе `GITHUB_SYNC_API_URL`, если он задан (`/api/v3` заменяется на `/api/graphql`, в противном случае добавляется `/graphql`), иначе — на основе `GITHUB_SYNC_URL` |

<Warning>

* Создайте OAuth-приложение в вашем корпоративном экземпляре (_Settings → Developer settings → OAuth Apps_): приложение с `github.com` там не работает. URL обратного вызова тот же: `${OVERLEAF_SITE_URL}/user/github-sync/oauth2/callback`.
* `GITHUB_SYNC_URL` — это только веб-адрес. Не указывайте в нём адрес API, например `https://api.github.com` или `https://HOST/api/v3`, и не добавляйте путь организации.
* Все три адреса должны указывать на один и тот же экземпляр GitHub.

</Warning>

<Info>

Если ваш экземпляр использует сертификат частного центра сертификации (CA), смонтируйте сертификат CA в контейнер и укажите путь к нему в `NODE_EXTRA_CA_CERTS`, например `NODE_EXTRA_CA_CERTS=/var/lib/overleaf/certs/github-ca.pem`.

</Info>

<Danger>

Привязанные учётные записи и проекты относятся к тому экземпляру, с которым они были привязаны. Прежде чем переключать `GITHUB_SYNC_URL` на другой экземпляр, попросите пользователей отвязать свои учётные записи GitHub и проекты.

</Danger>

### Кто может привязывать и синхронизировать

Как и в Overleaf Cloud, привязать проект к репозиторию GitHub может только владелец проекта. После привязки синхронизировать проект может любой соавтор с правами на редактирование.

| Действие                                                   | Кто может это сделать                                          |
| ---------------------------------------------------------- | -------------------------------------------------------------- |
| Экспорт проекта в новый репозиторий GitHub                 | Владелец проекта                                               |
| Импорт репозитория GitHub в новый проект                   | Любой пользователь, который становится владельцем нового проекта |
| Pull, push и слияние привязанного проекта                  | Владелец и соавторы с правами на редактирование                |
| Отвязка проекта от репозитория                             | Владелец проекта                                               |

* Overleaf взаимодействует с GitHub от имени учётной записи GitHub пользователя, выполняющего синхронизацию, поэтому каждый соавтор, который синхронизирует проект, привязывает собственную учётную запись GitHub и должен иметь право на push в ветку по умолчанию репозитория.
* Соавторы с правами только на просмотр не могут использовать синхронизацию с GitHub для этого проекта.

### Q\&A

<Accordion title="Можно ли выполнять force push в ветку по умолчанию?">

<strong>Ответ:</strong> Мы не рекомендуем этого делать. Overleaf обнаруживает force push, предупреждает о нём и принимает переписанную ветку, выполняя слияние изменений, сделанных в Overleaf с момента последней синхронизации. Чтобы избежать неожиданностей, защитите ветку по умолчанию от force push в настройках репозитория.

</Accordion>

<Accordion title="Можно ли переименовать ветку по умолчанию привязанного проекта?">

<strong>Ответ:</strong> Пожалуйста, не делайте этого. Overleaf продолжает синхронизацию с той веткой, к которой был привязан проект. Чтобы синхронизироваться с другой веткой, отвяжите проект, а затем импортируйте репозиторий в новый проект — он будет использовать текущую ветку по умолчанию.

</Accordion>
