Открыть экземпляр Overleaf для людей без учётной записи можно тремя способами:

* [Доступ к проектам](/ru/on-premises/configuration/overleaf-toolkit/public-access#project-access  "mention"): гости могут открывать ссылку на общий проект без входа в систему
* [Доступ к страницам](/ru/on-premises/configuration/overleaf-toolkit/public-access#page-access  "mention"): неавторизованные посетители могут просматривать такие страницы, как `/learn`, `/templates` и `/devs`
* [Публичная регистрация](/ru/on-premises/configuration/overleaf-toolkit/public-access#public-registration  "mention"): пользователи могут регистрироваться самостоятельно, при необходимости — с письмом активации и только с адресами определённых почтовых доменов

### Доступ к проектам

<Info>

По умолчанию, даже если пользователь получил ссылку для совместного доступа к проекту, ему необходимо **войти в систему**, прежде чем присоединиться к совместному редактированию проекта.

</Info>

Чтобы разрешить анонимный доступ к проектам, открытым по ссылке, задайте обе переменные ниже:

```dotenv title="config/variables.env"
OVERLEAF_ALLOW_ANONYMOUS_READ_AND_WRITE_SHARING=true
OVERLEAF_ALLOW_PUBLIC_ACCESS=true
```

`OVERLEAF_ALLOW_ANONYMOUS_READ_AND_WRITE_SHARING` включает анонимное чтение и запись для проектов, открытых по ссылке.

`OVERLEAF_ALLOW_PUBLIC_ACCESS` отключает перенаправление неаутентифицированных пользователей на страницу входа.

Пересоздайте контейнеры командой `bin/up`. Затем откройте ссылку для совместного доступа в приватном окне браузера.

### Доступ к страницам

По умолчанию (если `OVERLEAF_ALLOW_PUBLIC_ACCESS` не задана) **все** страницы, кроме страниц входа и регистрации, перенаправляют неавторизованных посетителей на страницу входа. Это касается и страниц, которые задуманы как публичные, поэтому ссылки на них работают только для пользователей, уже вошедших в систему.

При `OVERLEAF_ALLOW_PUBLIC_ACCESS=true` неавторизованные посетители могут открывать:

| Страница                                                              | Требуется                        |
| --------------------------------------------------------------------- | -------------------------------- |
| Справка по LaTeX по адресу `/learn` (см. [adding-latex-user-help.md](/ru/on-premises/configuration/overleaf-toolkit/adding-latex-user-help  "mention")) | `OVERLEAF_PROXY_LEARN=true`      |
| Галерея шаблонов по адресу `/templates`, страницы шаблонов, предпросмотр и загрузка ZIP (см. [templates.md](/ru/on-premises/configuration/overleaf-toolkit/templates  "mention")) | `OVERLEAF_TEMPLATE_GALLERY=true` |
| Страница Overleaf Import API по адресу `/devs` (см. [overleaf-import-api.md](/ru/on-premises/configuration/overleaf-toolkit/overleaf-import-api  "mention")) | —                                |

Кроме того, это позволяет [Overleaf Import API](/ru/on-premises/configuration/overleaf-toolkit/overleaf-import-api#signed-out-visitors  "mention") сохранять данные формы, отправленной неавторизованным посетителем, до тех пор, пока он не войдёт в систему.

Список проектов, редактор и создание проектов (в том числе из шаблона или через Import API) по-прежнему требуют входа в систему.

### Публичная регистрация

Публичная регистрация доступна только в [ayaka-notes/ayakaleaf-pro](https://github.com/ayaka-notes/ayakaleaf-pro).

<Danger>

Обратите внимание: после включения публичной регистрации **любой**, у кого есть доступ к вашему экземпляру Overleaf, сможет зарегистрироваться как пользователь.

При значении `true` адреса электронной почты в процессе регистрации не проверяются, поэтому используйте эту функцию только в интрасети или в доверенной среде либо используйте вместо неё [регистрацию с письмом активации](/ru/on-premises/configuration/overleaf-toolkit/public-access#registration-with-activation-email).

В экземпляре с OIDC не используйте `true`: кто угодно может зарегистрироваться с адресом электронной почты коллеги до первого входа этого коллеги через OIDC, и тогда коллега будет привязан к этой учётной записи. Используйте [регистрацию с письмом активации](/ru/on-premises/configuration/overleaf-toolkit/public-access#registration-with-activation-email) или отключите публичную регистрацию, см. [Учётные записи и пароли](/ru/on-premises/configuration/overleaf-toolkit/authentication#accounts-and-passwords).

</Danger>

По умолчанию ни Community Edition, ни Overleaf Pro не допускают публичную регистрацию.

Чтобы включить её, добавьте следующее в `config/variables.env`:

```dotenv title="config/variables.env"
OVERLEAF_ALLOW_PUBLIC_REGISTRATION=true
```

Пересоздайте контейнеры командой `bin/up`.

Затем нажмите **Sign up** или перейдите по адресу `/register`.

### Регистрация с письмом активации

Регистрация с письмом активации доступна только в [ayaka-notes/ayakaleaf-pro](https://github.com/ayaka-notes/ayakaleaf-pro). Пользователи регистрируются, указав только адрес электронной почты, и задают пароль по ссылке из письма активации, поэтому пользоваться учётной записью может только владелец адреса. Для списка доменов и подстановочных знаков нужна версия v6.4.0 или новее; более ранние версии принимают только один домен, например `@example.com`.

Перед её включением настройте доставку электронной почты, иначе пользователи не получат письмо активации. См. [Доставка электронной почты](/ru/on-premises/configuration/overleaf-toolkit/email-delivery).

Затем добавьте следующую строку в `config/variables.env`:

```dotenv title="config/variables.env" wrap
OVERLEAF_ALLOW_PUBLIC_REGISTRATION=@example.com,@*.example.org
```

`OVERLEAF_ALLOW_PUBLIC_REGISTRATION` может принимать значения:

| Значение                      | Кто может зарегистрироваться                          | Проверка почты |
| ----------------------------- | ----------------------------------------------------- | :------------: |
| `true`                        | Любой, с адресом электронной почты и паролем          |      Нет       |
| `@example.com`                | Адреса домена `example.com`                           |       Да       |
| `@*.example.org`              | Адреса поддоменов, например `cs.example.org`, но не самого `example.org` |       Да       |
| `@example.com,@*.example.org` | Любая из перечисленных записей, разделённых запятыми  |       Да       |
| `@*`                          | Любой                                                 |       Да       |

Домены сопоставляются без учёта регистра. Чтобы разрешить домен и его поддомены, укажите оба: `@example.org,@*.example.org`.

### Q\&A

<Accordion title="Что может делать с комментариями редактор, не выполнивший вход?">

<strong>Ответ:</strong> Пользователь, не выполнивший вход и открывший проект по ссылке для редактирования, получает тот же доступ, что и редактор, за исключением действий, при которых фиксируется, кто их выполнил:

| Действие                                          | Редактор, не выполнивший вход |
| ------------------------------------------------- | ----------------------------: |
| Редактирование текста, просмотр комментариев и отслеживаемых изменений | Да |
| Принятие отслеживаемых изменений, переключение режима редактирования | Да |
| Удаление комментария или всей ветки обсуждения   | Да |
| Добавление комментария, ответ на него или его редактирование | Нет |
| Разрешение или повторное открытие комментария     | Нет |

Панель рецензирования по-прежнему показывает им кнопку **Resolve**, но разрешение комментария завершается сообщением об ошибке.

Пользователи, открывшие проект по ссылке для просмотра, вообще не видят комментариев, см. [Роли и права доступа](/ru/on-premises/user-and-project-management/roles-and-permissions#collaborating).

</Accordion>
