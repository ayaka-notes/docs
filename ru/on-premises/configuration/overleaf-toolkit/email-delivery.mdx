Overleaf поддерживает отправку электронной почты двумя способами: через Simple Mail Transfer Protocol (SMTP) и [Amazon Simple Email Service (SES)](https://aws.amazon.com/ses/). SMTP можно использовать, если на вашем localhost включён почтовый сервер, принимающий локальные подключения.

## Несколько адресов электронной почты в одной учётной записи {#several-emails-per-account}

<Info>

Эта функция разработана [ayaka-notes/ayakaleaf-pro](https://github.com/ayaka-notes/ayakaleaf-pro) и доступна начиная с v6.4.0.

</Info>

Когда почта настроена, страница настроек показывает список адресов электронной почты учётной записи вместо единственного поля. Пользователи добавляют адрес, вводя 6-значный код, отправленный на него, и нажимают **Make primary**, чтобы перенести на него учётную запись. Так можно сохранить учётную запись, когда адрес будет отозван, например университетский после выпуска. В [руководстве пользователя](/ru/on-premises/user-guide/users/multiple-emails) есть шаги со снимками экрана.

* Входить и получать сброс пароля может только основной адрес. Дополнительный адрес не делает ни того, ни другого, поэтому адрес, переданный кому-то другому, не может захватить учётную запись.
* Нажмите **Make primary** до того, как старый почтовый ящик закроют. После этого адрес должен менять администратор в **Admin → Manage Users**.
* Старый основной адрес, который так и не был подтверждён, удаляется, когда основным становится другой адрес. Подтверждённый остаётся дополнительным, пока пользователь его не удалит.
* **Make primary** отклоняется, если включён LDAP или SAML, потому что такие учётные записи не смогли бы войти с новым адресом. См. [Учётные записи и пароли](/ru/on-premises/configuration/overleaf-toolkit/authentication#accounts-and-passwords).
* Без настроек почты остаётся единственное поле адреса электронной почты.

## Конфигурация {#configuration}

Электронная почта настраивается с помощью следующих переменных окружения.

#### Настройка отправителя {#sender-configuration}

| Название                      | Описание |
| ----------------------------- | -------- |
| `OVERLEAF_EMAIL_FROM_ADDRESS` | <p>Адрес отправителя, например <a href="mailto:support@mycompany.com">`'support@mycompany.com'`</a><br /><br />- <strong>Обязательно</strong>: да</p> |
| `OVERLEAF_EMAIL_REPLY_TO`     | Адрес для ответа, например `'noreply@mycompany.com'` |

#### SMTP {#smtp}

| Название                                | Описание |
| --------------------------------------- | -------- |
| `OVERLEAF_EMAIL_SMTP_HOST`              | Имя хоста или IP-адрес для подключения. Должен быть доступен из Docker-контейнера |
| `OVERLEAF_EMAIL_SMTP_PORT`              | Порт для подключения |
| `OVERLEAF_EMAIL_SMTP_SECURE`            | Если `true`, при подключении к серверу будет использоваться TLS. Если `false` или не задано, TLS используется, если сервер поддерживает расширение `STARTTLS`. В большинстве случаев задайте значение `true`, если подключаетесь к порту `465`. Для портов `587` или `25` оставьте `false` |
| `OVERLEAF_EMAIL_SMTP_USER`              | Имя пользователя для аутентификации на SMTP-сервере |
| `OVERLEAF_EMAIL_SMTP_PASS`              | Пароль, связанный с именем пользователя SMTP |
| `OVERLEAF_EMAIL_SMTP_TLS_REJECT_UNAUTH` | Если `false`, будет разрешено подключение к TLS-серверу с самоподписанным или недействительным TLS-сертификатом |
| `OVERLEAF_EMAIL_SMTP_IGNORE_TLS`        | Если `true` и `OVERLEAF_EMAIL_SMTP_SECURE` равно `false`, TLS не используется, даже если сервер поддерживает расширение `STARTTLS` |
| `OVERLEAF_EMAIL_SMTP_NAME`              | Необязательное имя хоста для проверки TLS, если в `OVERLEAF_EMAIL_SMTP_HOST` указан IP-адрес; по умолчанию используется имя хоста машины. |
| `OVERLEAF_EMAIL_SMTP_LOGGER`            | Если `true`, сообщения журнала выводятся в `web.log`. |

#### SMTP-интерфейс Amazon SES {#amazon-ses-smtp-interface}

Подробнее об отправке электронной почты через SMTP-интерфейс Amazon SES можно прочитать [здесь](https://docs.aws.amazon.com/ses/latest/dg/send-email-smtp.html).

| Название                   | Описание |
| -------------------------- | -------- |
| `OVERLEAF_EMAIL_SMTP_HOST` | Имя хоста или IP-адрес для подключения. Должен быть доступен из Docker-контейнера |
| `OVERLEAF_EMAIL_SMTP_PORT` | Порт для подключения |
| `OVERLEAF_EMAIL_SMTP_USER` | Имя пользователя для аутентификации на SMTP-сервере |
| `OVERLEAF_EMAIL_SMTP_PASS` | Пароль, связанный с именем пользователя SMTP |

#### API Amazon SES {#amazon-ses-api}

Подробнее об отправке электронной почты через API Amazon SES можно прочитать [здесь](https://docs.aws.amazon.com/ses/latest/dg/send-email-api.html).

| Название                               | Описание |
| -------------------------------------- | -------- |
| `OVERLEAF_EMAIL_AWS_SES_ACCESS_KEY_ID` | Ключ доступа при использовании AWS SES |
| `OVERLEAF_EMAIL_AWS_SES_SECRET_KEY`    | Секретный ключ при использовании AWS SES |
| `OVERLEAF_EMAIL_AWS_SES_REGION`        | Если не задано, используется регион по умолчанию US-EAST-1 |

#### AWS SES с ролями экземпляров {#aws-ses-with-instance-roles}

| Название                | Описание |
| ----------------------- | -------- |
| `OVERLEAF_EMAIL_DRIVER` | Если задано значение `ses`, почтовая система будет использовать метод SES API и отправлять почту, опираясь на настроенные роли экземпляра. |

#### Настройка {#customisation}

| Название                       | Описание |
| ------------------------------ | -------- |
| `OVERLEAF_CUSTOM_EMAIL_FOOTER` | <p>Пользовательский HTML, добавляемый ко всем письмам, например<br /><br /><strong>Пример</strong>: `"<div>This system is run by department x </div> <div> If you have any questions please look at our faq <a href='https://somwhere.com'>here</a></div>"`</p> |
