Для просмотра логов сервисов можно использовать скрипт `bin/logs`.

Основные примеры использования:

```bash
# View the web service logs
bin/logs web

# Show help
bin/logs --help

# View logs for multiple services at once
bin/logs filestore docstore web clsi

# Follow log output (like tail -f)
bin/logs -f filestore docstore web clsi

# Limit the number of lines printed (default 50)
bin/logs -n 50 web

# Show all log lines
bin/logs -n all web

# Redirect output to a file
bin/logs -n all web > web.log
```

С помощью скрипта `bin/logs` можно просматривать логи следующих сервисов: `clsi`, `contacts`, `docstore`, `document-updater`, `filestore`, `git-bridge`, `mongo`, `notifications`, `real-time`, `redis`, `spelling`, `tags`, `track-changes`, `web`, `web-api`, `history-v1`, `project-history`.

## Копирование логов

См. оригинальную документацию: https://docs.overleaf.com/on-premises/configuration/overleaf-toolkit/logging#copying-logs

Скопируйте файлы логов из основного контейнера `sharelatex` на локальный компьютер:

```bash
docker cp sharelatex:/var/log/overleaf/{service-name}.log {service-name}.log
```

## Сохранение логов

Контейнеры Docker эфемерны: файлы и каталоги, созданные внутри контейнера во время работы (включая файлы логов), будут удалены при пересоздании контейнера (например, при запуске `bin/up`). Чтобы сохранять файлы логов между пересозданиями контейнера:

* Задайте переменную окружения `OVERLEAF_LOG_PATH` в файле `config/overleaf.rc`, используемом Toolkit. Это должен быть каталог на хосте, который будет смонтирован (bind mount) в каталог логов внутри контейнера `sharelatex`.
* После изменения этого параметра и запуска `bin/up -d` файлы логов будут сохраняться на хосте и будут доступны напрямую.

<Warning>

Владельцем каталога логов на хосте, используемого для bind mount, должен быть пользователь `www-data` (uid=33), а права доступа должны быть `drwxr-xr-x` (755).

Пример:

```bash
chown 33:33 data/overleaf/logs
chmod 755 data/overleaf/logs
```

</Warning>
