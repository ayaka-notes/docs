У каждого проекта есть MCP-сервер, поэтому ИИ-клиенты, такие как Claude Code, Codex, Cursor, VS Code или Gemini CLI, могут работать над ним: читать и редактировать его файлы, компилировать проект, читать журнал LaTeX, скачивать PDF и отвечать на комментарии. Начиная с v6.3.3, они также могут просматривать историю и восстанавливать версии, проверять отслеживаемые изменения, добавлять комментарии, пользоваться чатом проекта и перемещать файлы.

<Info>

Эта функция разработана в [ayaka-notes/ayakaleaf-pro](https://github.com/ayaka-notes/ayakaleaf-pro). Она доступна начиная с версии v6.3.1. Инструменты для истории, отслеживаемых изменений, чата проекта, новых комментариев и перемещения файлов доступны начиная с v6.3.3, см. [Новое в v6.3.3](/on-premises/user-guide/users/mcp-server#new-in-v6.3.3).

</Info>

### Настройка {#setup}

MCP-сервер входит в состав интеграции с Git: включите [git-bridge](/ru/on-premises/configuration/overleaf-toolkit/integrations/git-integration), и MCP-сервер тоже станет доступен. Больше ничего настраивать не нужно.

### Подключение ИИ-клиента {#connect-an-ai-client}

1. В **настройках учётной записи** (**Account Settings**) создайте токен аутентификации Git. Один и тот же токен используется и для MCP-сервера, и для Git.
2. В редакторе откройте **Integrations** и нажмите **MCP server**. Там показан адрес MCP-сервера проекта, `https://<your-overleaf>/project/<project_id>/mcp`, и способ добавить его в каждый ИИ-клиент: скопируйте команду и замените `<token>` своим токеном.

Токен передаётся в HTTP-заголовке `Authorization: Bearer <token>`. Например, команда для Claude Code выглядит так:

```bash
claude mcp add --transport http overleaf \
  https://<your-overleaf>/project/<project_id>/mcp \
  --header "Authorization: Bearer <token>"
```

### Использование {#usage}

После подключения обращайтесь к ИИ-клиенту обычными словами. Например:

| Ваш запрос | Что использует ИИ-клиент |
| --- | --- |
| _Исправь опечатки во введении._ | `read_file`, `edit_file`: правки сразу отображаются в редакторе |
| _Скомпилируй проект и исправь ошибки LaTeX._ | `compile`, `get_compile_log`, `edit_file` |
| _Ответь на открытые комментарии, затем отметь их как решённые._ | `list_comments`, `reply_to_comment`, `resolve_comment` |
| _Переключись на XeLaTeX и скачай PDF._ | `update_settings`, `compile`, `get_output_file_link` |
| _Перепиши аннотацию как отслеживаемое изменение._ | `read_file`, `edit_file` с `trackChanges` (v6.3.3) |
| _Что изменилось с отправленной версии?_ | `list_versions`, `list_changes`, `diff` (v6.3.3) |
| _Перемести главы в папку chapters._ | `move_file` (v6.3.3) |

### Инструменты {#tools}

| Группа | Инструменты |
| --- | --- |
| Проект | `get_clone_info`, `get_settings`, `update_settings` |
| Файлы | `list_files`, `read_file`, `edit_file`, `write_file`, `delete_file`, `move_file`, `create_folder` |
| Компиляция | `compile`, `get_compile_log`, `get_output_file_link`, `word_count` |
| Комментарии | `list_comments`, `reply_to_comment`, `resolve_comment`, `reopen_comment`, `add_comment`, `edit_comment_message`, `delete_comment_message` |
| Отслеживаемые изменения | `list_tracked_changes`, `accept_tracked_changes`, `reject_tracked_changes` |
| История | `list_versions`, `list_changes`, `diff`, `create_version`, `delete_version`, `restore_file`, `restore_project` |
| Чат | `list_chat_messages`, `send_chat_message` |

В v6.3.3 есть 33 инструмента, или 31 с `OVERLEAF_DISABLE_CHAT=true`, который убирает инструменты чата. В v6.3.1 и v6.3.2 есть остальные 17: всё перечисленное выше, кроме `move_file`, `create_folder`, `add_comment`, `edit_comment_message`, `delete_comment_message`, инструментов отслеживаемых изменений, инструментов чата и инструментов истории, кроме `list_versions`. В v6.3.3 `read_file` также читает файл в версии из истории, `edit_file` и `write_file` принимают `trackChanges`, а `update_settings` также задаёт язык проверки орфографии.

Правки, сделанные через `edit_file`, `write_file` и `move_file`, сразу отображаются в редакторе и объединяются с правками соавторов. Для множества файлов сразу или двоичных файлов ИИ-клиент также может клонировать проект через Git и выполнить push.

С `trackChanges` правка существующего файла становится отслеживаемым изменением пользователя токена, даже если отслеживание изменений в проекте выключено; новый файл никогда им не является. Без `trackChanges` правки следуют настройке отслеживания изменений проекта.

### Права доступа {#permissions}

MCP-сервер, как и Git, следует настройкам совместного доступа к проекту:

* Все, кто может просматривать проект, могут читать его, компилировать и скачивать результат.
* Только владелец и редакторы могут изменять его файлы и настройки, восстанавливать версии и принимать или отклонять отслеживаемые изменения.
* Рецензенты также могут добавлять комментарии и отвечать на них, закрывать, повторно открывать или удалять начатые ими комментарии и сохранять версии. Они не могут редактировать файлы, даже в виде отслеживаемых изменений.
* Каждый редактирует только свои сообщения в комментариях, а рецензенты удаляют только свои.
* Только владелец удаляет версии, сохранённые другими.
* Читатели, присоединившиеся по ссылке, не видят комментарии, отслеживаемые изменения, историю и чат, как и в редакторе. Приглашённые читатели видят их и могут пользоваться чатом.
* Если у владельца проекта нет **Full project history**, инструменты истории показывают только изменения за последние 24 часа, как и панель истории. Администраторы видят все.

В руководстве пользователя есть таблица того, что может каждая роль, см. [Кто что может](/on-premises/user-guide/users/mcp-server#who-may-do-what).

### Вопросы и ответы {#q&a}

<Accordion title="Я не вижу Integrations или MCP server в редакторе">

<strong>Ответ:</strong> У MCP-сервера нет собственной переменной окружения. Он включается с помощью `GIT_BRIDGE_ENABLED=true` в `config/overleaf.rc`, см. [Интеграция с Git](/ru/on-premises/configuration/overleaf-toolkit/integrations/git-integration). После изменения выполните `bin/up -d`. Без git-bridge редактор не показывает вкладку **Integrations** на левой панели.

</Accordion>

<Accordion title="ИИ-клиент сообщает «Track changes is off for this project»">

<strong>Ответ:</strong> Клиент запросил отслеживаемое изменение, но у учётной записи владельца проекта нет отслеживания изменений. Нажмите **Admin**, затем **Manage Users**, откройте владельца и на вкладке **Features** включите **Track changes**, см. [Features](/ru/on-premises/user-guide/administrators/user-management#features). Правки без `trackChanges` по-прежнему работают.

</Accordion>

<Accordion title="ИИ-клиент видит только изменения за последние 24 часа">

<strong>Ответ:</strong> У учётной записи владельца проекта нет полной истории проекта, поэтому инструменты истории показывают то же, что и панель истории: изменения за последние 24 часа. Нажмите **Admin**, затем **Manage Users**, откройте владельца и на вкладке **Features** включите **Full project history**, см. [Features](/ru/on-premises/user-guide/administrators/user-management#features).

</Accordion>
