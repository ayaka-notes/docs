#### Сервисы

Инфраструктура Overleaf Pro включает четыре основных сервиса: `sharelatex`, `git-bridge` (необязательный), `mongo` и `redis`. Сервис `sharelatex`, в котором работает основное приложение Server Pro, зависит от сервисов `mongo` и `redis`, обеспечивающих базу данных и функции кэширования/работы в реальном времени, а также от `git-bridge`, отвечающего за [интеграцию с Git](/ru/on-premises/configuration/overleaf-toolkit/git-integration) (необязательно). Единственный порт, публикуемый на хост-машине, — порт 80, который используется контейнером `sharelatex`.

Server Pro также дополнительно поддерживает [S3-совместимое хранилище](/ru/on-premises/configuration/overleaf-toolkit/s3) для файлов проектов и полной истории проектов, а также может проксировать доступ к основному [сайту документации Overleafarrow-up-right](https://www.overleaf.com/learn). Подробнее см. в нашем руководстве [Добавление справки по LaTeX для пользователей](/ru/on-premises/configuration/overleaf-toolkit/adding-latex-user-help).

<Info>

При необходимости MongoDB и Redis можно вынести во внешние сервисы, указав их с помощью переменных окружения. Подробнее см. [Настройка Overleaf](/ru/on-premises/configuration), если вы используете Docker Compose, и [Параметры Toolkit](/ru/on-premises/configuration/overleaf-toolkit/toolkit-settings), если используете Overleaf Toolkit.

</Info>

#### Компиляция

Для [изолированной компиляции (Sandboxed Compiles)](/ru/on-premises/configuration/overleaf-toolkit/sandboxed-compiles) контейнер `sharelatex` управляет созданием новых контейнеров для компиляции проектов; он делает это через сокет Docker на хост-машине. Подробнее о редакторе и сквозном процессе компиляции/кэширования можно прочитать [здесь](/ru/on-premises/getting-started/microservices#editor-and-compile-process).

#### Сеть

Взаимодействие между контейнерами осуществляется через внутреннее разрешение имён DNS в Docker с помощью выделенной сети типа bridge; межсетевые экраны не включены. По умолчанию перечисленные выше сервисы используют свои стандартные порты, но их можно изменить с помощью переменных окружения. Контейнер `sharelatex` использует порт 80 для внешнего веб-доступа (обслуживается Nginx), контейнер `mongo` — порт 27017, а `redis` — порт 6379.

Клиенты, использующие наше управляемое решение [Overleaf Toolkitarrow-up-right](https://github.com/overleaf/toolkit), могут при желании [включить TLS-прокси](/ru/on-premises/configuration/overleaf-toolkit/tls-proxy) для терминирования HTTPS-соединений с помощью Nginx через переменную окружения. Также можно использовать уже имеющийся у вас TLS-прокси.

<Info>

Схему, поясняющую прохождение запросов, можно посмотреть [здесь](/ru/on-premises/configuration/overleaf-toolkit/tls-proxy).

</Info>

#### Итоги

* За пределами сети Docker доступен только порт 80, привязанный к Nginx. <strong>Примечание:</strong> в контейнере `sharelatex` работает множество [сервисовarrow-up-right](https://github.com/overleaf/overleaf/tree/main/services), которые взаимодействуют друг с другом по HTTP. Однако эти порты **не** доступны извне сети Docker.
* Внутри сети Docker сервисы Overleaf, MongoDB, Redis и Git Bridge могут свободно взаимодействовать друг с другом.
* Внутри контейнеров [изолированной компиляции](/ru/on-premises/configuration/overleaf-toolkit/sandboxed-compiles) сеть недоступна.
