---
title: Коллекция Dropbox Projects
icon: folder-open
---

`dropboxProjects` сопоставляет проект с его папкой в Dropbox одного пользователя. У проекта, к которому открыт доступ нескольким пользователям Dropbox, по одному документу на пользователя. Коллекция относится к синхронизации с Dropbox: third-party-datastore (`services/third-party-datastore/app/js/StateManager.mjs`) записывает её, а веб-модуль `dropbox` (`services/web/modules/dropbox/app/src/DropboxHandler.mjs`) читает и очищает её. Схемы Mongoose нет.

#### Поля {#fields}

| Поле | Тип | Значение | Источник |
| ---- | --- | -------- | -------- |
| `_id` | ObjectId | Задаётся драйвером при вставке. | `StateManager.mjs:144` |
| `userId` | ObjectId | Пользователь Overleaf, в чьём Dropbox находится папка. | `StateManager.mjs:145` |
| `projectId` | ObjectId | Проект, синхронизируемый в папку. | `StateManager.mjs:146` |
| `dropboxId` | String | `id` папки в метаданных папки Dropbox. | `StateManager.mjs:147`, `JobProcessor.mjs:82-87`, `PullManager.mjs:138` |
| `pathLower` | String | Путь к папке в Dropbox в нижнем регистре и без завершающей косой черты. Папки проектов лежат на верхнем уровне, по одной на проект, например `/thesis (1)`, если Dropbox пронумеровал её рядом с `Thesis` другого проекта. | `StateManager.mjs:14-16,148`, `PullManager.mjs:112-117` |

#### Кто записывает {#who-writes-it}

| Код | Что делает |
| --- | ---------- |
| `services/third-party-datastore/app/js/StateManager.mjs:137-150` (`setProjectFolder`) | Удаляет документы пользователя с тем же `projectId`, `dropboxId` или `pathLower`, затем вставляет новое сопоставление. |
| `services/third-party-datastore/app/js/JobProcessor.mjs:58-91` (`projectFolder`) | Создаёт папку в Dropbox и записывает её, когда web запрашивает папку нового проекта или проекта, в который добавили пользователя (`createProject`, `:245-251`), или отправляет файл проекта, у которого ещё нет папки (`addEntity`, `:113`). |
| `JobProcessor.mjs:174-203` (`renameProject`) | После того как переименование проекта переместило папку, записывает новый путь или удаляет сопоставление, если папки больше нет (`:190`). |
| `services/third-party-datastore/app/js/PullManager.mjs:119-140` (`resolveProject`) | Когда pull находит папку без сопоставления, записывает проект, который web нашёл по имени. |
| `PullManager.mjs:188-207` (`applyDeletion`) | Когда папка проекта удалена в Dropbox, удаляет сопоставление (`StateManager.mjs:152-157`). |
| `StateManager.mjs:186-190` (`removeUserState`), вызывается из `services/third-party-datastore/app/js/QueueWorker.mjs:43` | Удаляет все документы пользователя, когда third-party-datastore отвязывает аккаунт, который больше не может использовать. |
| `DropboxHandler.mjs:142-146` (`removeUserState`) | Удаляет все документы пользователя при привязке (`:125`), при отвязке (`:183`) и когда истекает срок удалённого пользователя (`services/web/modules/dropbox/index.mjs:62-64`). |
| `DropboxHandler.mjs:150-154` (`removeProjectState`) | Удаляет документы проекта, когда истекает срок удалённого проекта (`index.mjs:54-56`). |

| Код | Что делает |
| --- | ---------- |
| `StateManager.mjs:130-135` (`getFolderOfProject`) | Находит папку проекта: `JobProcessor.mjs:59,98,176` и `PullManager.mjs:133`. |
| `StateManager.mjs:123-128` (`getProjectByFolder`) | Находит проект папки: `JobProcessor.mjs:65` (имя уже занято), `PullManager.mjs:120,197`. |
| `StateManager.mjs:160-175` (`getSyncedPaths`) | Перечисляет пути папок после сброса курсора, чтобы папка, отсутствующая в списке, считалась удалённой (`PullManager.mjs:74-85`). |
| `DropboxHandler.mjs:234-250` (`getProjectFolderName`) | Возвращает имя папки, показываемое в диалоге Dropbox в редакторе (`services/web/modules/dropbox/app/src/DropboxController.mjs:130`). |

#### Индексы {#indexes}

| Имя | Ключи | Параметры | Миграция |
| --- | ----- | --------- | -------- |
| `_id_` | `_id: 1` | | default |

Других индексов здесь в CE нет. Уникальные индексы `projectId_userId_1` и `userId_dropboxId_1` создаются миграциями `tools/migrations/20220815105500_create_dropboxProjects_index.mjs` и `20220817120900_create_dropboxProjects_index.mjs`, у которых только тег `saas`, поэтому CE их никогда не запускает.

#### Примечания {#notes}

* Уникальность обеспечивается только удалением перед каждой вставкой в `setProjectFolder` (`StateManager.mjs:140-149`). Комментарий в `StateManager.mjs:3-11` упоминает уникальные индексы; в CE их нет.
* Когда сопоставление проекта удаляется, его папка остаётся в Dropbox. Правка в ней тогда читается как новый проект, как и для папки, созданной в Dropbox (`DropboxHandler.mjs:148-149`).
* Удалённый проект сохраняет сопоставление до истечения срока, потому что его ещё можно восстановить (`index.mjs:52-53`).
* Курсора Dropbox `list_folder` пользователя здесь нет. Он находится в `users.dropbox.cursor` (`StateManager.mjs:177-184`).
