---
title: Коллекция Project History Failures
icon: triangle-exclamation
---

`projectHistoryFailures` хранит по одному документу на проект, обновления истории которого project-history не смог обработать или для которого он запустил ресинхронизацию. Документ снова удаляется, как только обработка проходит успешно. project-history пишет её в `services/project-history/app/js/ErrorRecorder.js`; её тип описан в `services/project-history/app/js/mongo-types.ts:3-24`. В web тоже есть схема Mongoose для неё (`services/web/app/src/models/ProjectHistoryFailure.mjs:5-19`), но никакой код web эту модель не использует.

#### Кто пишет {#who-writes-it}

| Код | Что делает |
| ---- | ------------ |
| `services/project-history/app/js/ErrorRecorder.js:34-66` | `record`: upsert ошибки, `attempts` +1, запись добавляется в `history`. Вызывается, когда обработка обновлений проекта завершается сбоем (`UpdatesProcessor.js:91`, `169`, `242`, `293`, `345`), и когда ресинхронизацию не удаётся запустить (`SyncManager.js:75`, `96`). |
| `ErrorRecorder.js:86-102` | `recordSyncStart`: upsert, `resyncStartedAt`, `resyncAttempts` +1, запись добавляется в `history` при каждом запуске ресинхронизации (`SyncManager.js:104`). |
| `ErrorRecorder.js:68-70` | `clearError`: удаляет документ после успешного flush (`UpdatesProcessor.js:101`, `194`, `259`, `355`), при project-history `DELETE /project/:project_id` (`services/project-history/app/js/HttpController.js:1386`) и при неверном идентификаторе проекта во время повторной попытки (`services/project-history/app/js/RetryManager.js:161`). |
| `ErrorRecorder.js:72-82` | `setForceDebug`: upsert `forceDebug` (`HttpController.js:1016-1035`, маршрут в `services/project-history/app/js/Router.js:82`). |
| `ErrorRecorder.js:109-119` | `cloneFailure`: копирует документ в другой проект, для project-history `POST /project/:project_id/clone` (`HttpController.js:135`), который ничто в web не вызывает. |

#### Кто читает {#who-reads-it}

#### Примечания {#notes}

* Документ остаётся, пока flush проекта не пройдёт успешно или проект не будет удалён (`clearError` выше), поэтому каждый документ отмечает проект, последний flush или ресинхронизация которого ещё не удались.
* Строки ошибок, начинающиеся с `OError:`, возвращаются как `Error:` (`ErrorRecorder.js:18-26`); сохранённое значение не меняется.
