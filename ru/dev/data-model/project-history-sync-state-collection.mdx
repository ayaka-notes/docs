---
title: Коллекция Project History Sync State
icon: rotate
---

`projectHistorySyncState` содержит один документ на каждый проект, который проходил ресинхронизацию: состояние текущей или последней ресинхронизации, при которой project-history заново строит историю проекта по тому, что хранят web и docstore. Коллекция принадлежит project-history и не имеет схемы Mongoose; код находится в классе `SyncState` и его вспомогательных функциях в `services/project-history/app/js/SyncManager.js`.

#### Кто пишет {#who-writes-it}

| Код | Что делает |
| ---- | ------------ |
| `services/project-history/app/js/SyncManager.js:195-249` | `setResyncState`: upsert состояния. Вызывается при запуске ресинхронизации (`SyncManager.js:163`) и пока project-history обрабатывает обновления ресинхронизации (`services/project-history/app/js/UpdatesProcessor.js:637`, `784`). |
| `SyncManager.js:257-266` | `_recordStuckClearInSyncState`: учитывает сброшенную зависшую ресинхронизацию. |
| `SyncManager.js:251-255` | `clearResyncState`: удаляет документ в начале жёсткой ресинхронизации (`SyncManager.js:87`), при `DELETE /project/:project_id` в project-history (`services/project-history/app/js/HttpController.js:1363-1396`) и когда ресинхронизацию только структуры нужно начать заново (`SyncManager.js:705-716`). |
| `SyncManager.js:273-289` | `clearResyncStateIfAllAfter`: удаляет завершённое состояние, вся история которого новее заданной даты. Ничто в `app/js` её не вызывает. |
| `SyncManager.js:171-181` | `cloneResyncState`: копирует состояние в другой проект для `POST /project/:project_id/clone` в project-history (`HttpController.js:57`, `124`), который ничто в web не вызывает. |

Ресинхронизацию запускают `POST /project/:project_id/resync` в project-history (`HttpController.js:950-994`), задания cron для повторных попыток (`services/project-history/app/js/RetryManager.js:156-179`, `server-ce/config/crontab-history`) и сам project-history, когда она нужна при обработке обновлений (`UpdatesProcessor.js:75`, `224`).

#### Кто читает {#who-reads-it}

| Код | Что делает |
| ---- | ------------ |
| `SyncManager.js:187-193` | `getResyncState`: загружает состояние. Используется, чтобы перед запуском новой ресинхронизации решить, не выполняется ли уже другая (`SyncManager.js:106-149`), чтобы пропускать обычные обновления во время её выполнения (`SyncManager.js:291-300`) и чтобы после сброса на диск сообщить о текущей ресинхронизации (`UpdatesProcessor.js:463-466`). |
| `HttpController.js:533-545` | `GET /project/:project_id/resync-pending`: выполняется ли ресинхронизация или зависла ли она. |
| `HttpController.js:563-585` | `GET /project/:project_id/debug-info`: состояние синхронизации вместе с записью о сбое. |

#### Примечания {#notes}

* Ресинхронизация выполняется, пока `resyncProjectStructure` равно `true` или `resyncDocContents` не пуст (`SyncManager.js:565-567`). Через 4 часа она считается зависшей, а после 5 сбросов зависшей навсегда (`SyncManager.js:43-44`, `569-585`).
* Когда ресинхронизация завершается, project-history также устанавливает в проекте `overleaf.history.lastResyncedAt` (`SyncManager.js:239-248`).
