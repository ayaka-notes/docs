---
title: Коллекция Gitea Sync Project States
icon: code-pull-request
---

`giteaSyncProjectStates` хранит по одному документу на каждый проект, связанный с репозиторием Gitea: какой это репозиторий и на чём остановилась последняя синхронизация. Коллекция относится к веб-модулю `gitea-sync` (`services/web/modules/gitea-sync`). Схема находится в `services/web/modules/gitea-sync/app/models/giteaSyncProjectStates.mjs`, а весь доступ идёт через `services/web/modules/gitea-sync/app/src/SyncStateManager.mjs`. Поля те же, что в [GitHub Sync Project States](/ru/dev/data-model/github-sync-project-states-collection).

#### Поля {#fields}

| Поле | Тип | Значение | Источник |
| ----- | ---- | ------- | ------ |
| `_id` | ObjectId | Задаётся Mongoose при создании. | |
| `projectId` | ObjectId | Связанный проект. Обязательное. В схеме указано `unique: true`, но индекс не создаётся (см. «Индексы»). | `giteaSyncProjectStates.mjs:8` |
| `repoFullName` | String | Репозиторий в виде `owner/name` (`full_name` в Gitea). Обязательное. | `giteaSyncProjectStates.mjs:9`, `GiteaApiClient.mjs:315` |
| `defaultBranchName` | String | Ветка, с которой синхронизируется проект. Задаётся при связывании проекта и потом не меняется: при импорте это ветка из формы импорта, при экспорте это ветка по умолчанию нового репозитория или `main`, если API её не возвращает. По умолчанию `null`. | `giteaSyncProjectStates.mjs:10`, `GiteaSyncHandler.mjs:175-181,233-239`, `GiteaApiClient.mjs:314-317` |
| `mergeStatus` | String | `clean`, `conflict` или `diverged`. По умолчанию `clean`. | `giteaSyncProjectStates.mjs:11` |
| `lastSyncCommit` | String | SHA коммита в синхронизируемой ветке на момент последней синхронизации. По умолчанию `null`. | `giteaSyncProjectStates.mjs:12` |
| `lastSyncVersion` | Number | Версия истории проекта на момент последней синхронизации из `GET /project/:id/version` сервиса project-history, прочитанная после сброса истории. | `conflictVersion` | Number | Во время конфликта: версия истории проекта на момент записи конфликта. По умолчанию `null`. | `giteaSyncProjectStates.mjs:16` |
| `__v` | Number | Ключ версии Mongoose. Схема его не отключает. | По умолчанию в Mongoose |

#### Кто пишет {#who-writes-it}

| Код | Что делает |
| ---- | ------------ |
| `SyncStateManager.mjs:9-14` (`createProjectState`) | Создаёт документ: после импорта репозитория как нового проекта (`services/web/modules/gitea-sync/app/src/GiteaSyncHandler.mjs:175-181`) или после экспорта проекта в новый репозиторий (`GiteaSyncHandler.mjs:233-239`, только владелец, отказ, если проект уже связан). |
| `SyncStateManager.mjs:16-21` (`updateProjectState`) | `$set` изменённых полей. `getMergeOverview` устанавливает `mergeStatus: 'diverged'`, когда `lastSyncCommit` больше не является предком синхронизируемой ветки (`services/web/modules/gitea-sync/app/src/GiteaApiClient.mjs:431`) либо коммит исчез, а пользователь может пушить (`GiteaSyncHandler.mjs:123,126-137`). Синхронизация (`services/web/modules/gitea-sync/app/src/GitMerge.mjs`) при успехе передвигает `lastSyncCommit`/`lastSyncVersion` (например, `:152,189,231`), записывает конфликт в `unmergedBranchName`, `unmergedBranchHead` и `conflictVersion` (`:214-220`) и очищает их, когда конфликт разрешён (`:257-264`). |
| `SyncStateManager.mjs:23-25` (`removeProjectState`) | Удаляет документ, когда владелец отвязывает проект (`GiteaSyncHandler.mjs:83-97`) и когда истекает срок удалённого проекта (`services/web/modules/gitea-sync/index.mjs:46-48`). |

#### Кто читает {#who-reads-it}

| Код | Что делает |
| ---- | ------------ |
| `GiteaSyncHandler.mjs:39-60` (`getProjectState`) | Передаёт редактору `mergeStatus`, `repoFullName` и `unmergedBranchName`. Если документа нет, отвечает `need-export`; это значение никогда не сохраняется. |
| `GiteaSyncHandler.mjs:110-143` (`getMergeOverview`) | Сравнивает `lastSyncCommit` и `lastSyncVersion` с Gitea и историей проекта, чтобы перечислить новые коммиты. |
| `GiteaSyncHandler.mjs:200` (`exportProject`) | Отказывается экспортировать уже связанный проект. |
| `GitMerge.mjs:36` (`doGitMergeWithoutLock`) | Загружает состояние в начале синхронизации. |

#### Индексы {#indexes}

| Имя | Ключи | Параметры | Миграция |
| ---- | ---- | ------- | --------- |
| `_id_` | `_id: 1` | | default |

`autoIndex` в Mongoose выключен (`services/web/app/src/infrastructure/Mongoose.mjs:7`), поэтому `unique: true` из схемы на `projectId` ничего не создаёт. Ни одна миграция не создаёт индексы для этой коллекции.

#### Примечания {#notes}

* API Gitea не умеет, как GitHub, создавать коммиты вне ветки. Синхронизация коммитит прямо в синхронизируемую ветку, если может продвинуть её вперёд, а иначе во временную ветку, которая затем сливается через pull request (`GitMerge.mjs:16-21`).
* Синхронизация выполняется под блокировкой проекта `gitSync`, общей с GitHub Sync и GitLab Sync (`GitMerge.mjs:25-32`).
* Удалённый проект сохраняет свой документ, пока не истечёт его срок.
* Токен Gitea пользователя хранится в [Gitea Sync User Credentials](/ru/dev/data-model/gitea-sync-user-credentials-collection).
