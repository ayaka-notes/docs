`rooms` хранит по одному документу на чат-комнату проекта: чат проекта или одну ветку комментариев рецензирования. Пишет в неё только сервис chat, в `services/chat/app/js/Features/Threads/ThreadManager.js`. Схемы Mongoose нет. Сообщения комнаты находятся в коллекции [messages](/ru/dev/data-model/messages-collection).

#### Поля {#fields}

| Поле | Тип | Значение | Источник |
| ----- | ---- | ------- | ------ |
| `_id` | ObjectId | Идентификатор комнаты. Сюда указывает `messages.room_id`. | `ThreadManager.js:57-61` |
| `project_id` | ObjectId | Проект, которому принадлежит комната. | `ThreadManager.js:43-54` |
| `thread_id` | ObjectId | Только у веток комментариев: идентификатор комментария, совпадающий с `id` и `op.t` комментария в `docs.ranges.comments` (см. [docs](/ru/dev/data-model/docs-collection)). У комнаты чата проекта отсутствует. | `ThreadManager.js:38-55`, `services/docstore/app/js/RangeManager.js:54-57` |
| `resolved` | Object | Устанавливается, когда ветка разрешена, и удаляется, когда она снова открыта. Ветка без этого поля открыта. | `ThreadManager.js:94-123` |
| `resolved.user_id` | String | Идентификатор пользователя, разрешившего ветку. Хранится как строка, а не ObjectId: тело запроса только проверяется на корректный идентификатор, но не преобразуется. | `ThreadManager.js:103`, `services/chat/app/js/Features/Messages/MessageHttpSchemas.js:70` |
| `resolved.ts` | Date | Когда ветка была разрешена. | `ThreadManager.js:104` |

#### Кто пишет {#who-writes-it}

| Код | Что делает |
| ---- | ------------ |
| `ThreadManager.js:31-63` `findOrCreateThread` | Выполняет upsert комнаты. Запускается при каждой отправке, чтении, редактировании и удалении сообщений (`services/chat/app/js/Features/Messages/MessageHttpController.js:183,204,227,236,245,280,301`), поэтому первое сообщение комментария создаёт комнату его ветки, а чтение чата проекта создаёт комнату чата проекта. |
| `ThreadManager.js:94-109` `resolveThread` | Устанавливает `resolved`. Вызывается из web модулем track-changes (`services/web/modules/track-changes/app/src/TrackChangesController.mjs:142`), восстановлением истории (`services/web/app/src/Features/History/RestoreManager.mjs:276`) и модулем mcp-server (`services/web/modules/mcp-server/app/src/CommentTools.mjs:159`). |
| `ThreadManager.js:111-123` `reopenThread` | Удаляет `resolved`. Те же вызывающие: `TrackChangesController.mjs:160`, `RestoreManager.mjs:285`, `CommentTools.mjs:183`. |
| `ThreadManager.js:154-172` `duplicateThread` | Вставляет новую комнату с новым `thread_id`, копируя `resolved`. Используется, когда документ восстанавливается из истории (`RestoreManager.mjs:233`). |
| `ThreadManager.js:12-29` `cloneThreads` | Копирует все комнаты веток проекта в другой проект с новым `_id` и тем же `thread_id`. Используется, когда проект копируется вместе с диапазонами (`services/web/app/src/Features/Project/ProjectDuplicator.mjs:197`). |
| `ThreadManager.js:125-131` `deleteThread` | Удаляет одну комнату ветки; затем контроллер удаляет её сообщения (`MessageHttpController.js:167-175`). Вызывается модулем track-changes (`TrackChangesController.mjs:173`). |
| `ThreadManager.js:133-137` `deleteAllThreadsInProject` | Удаляет все комнаты проекта (`MessageHttpController.js:261-273`). Вызывается, когда истекает срок удалённого проекта (`services/web/app/src/Features/Project/ProjectDeleter.mjs:391`). |

#### Примечания {#notes}

* У проекта не больше одной комнаты без `thread_id`: это чат проекта. Сервис chat находит её по `thread_id: { $exists: false }` (`ThreadManager.js:38-45`).
* Состояние «разрешено» у комментария хранится только здесь. Docstore удаляет `op.resolved` перед сохранением диапазонов (`services/docstore/app/js/RangeManager.js:59-61`).
* После копирования проекта один и тот же `thread_id` существует в двух проектах. Всегда выполняйте запрос по `project_id` и `thread_id` вместе, как это делает сервис chat.
* Комнаты удалённого проекта остаются, пока не истечёт срок удалённого проекта.
