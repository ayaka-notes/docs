---
title: Коллекция Gitea Sync User Credentials
icon: lock
---

`giteaSyncUserCredentials` хранит по одному документу на каждого пользователя, который связал учётную запись Gitea для Gitea Sync. В нём хранятся OAuth-токены пользователя в зашифрованном виде. Коллекция относится к веб-модулю `gitea-sync` (`services/web/modules/gitea-sync`). Схема находится в `services/web/modules/gitea-sync/app/models/giteaSyncUserCredentials.mjs`, а весь доступ идёт через `services/web/modules/gitea-sync/app/src/TokenManager.mjs`.

#### Поля {#fields}

| Поле | Тип | Значение | Источник |
| ----- | ---- | ------- | ------ |
| `_id` | ObjectId | Задаётся Mongoose, когда upsert вставляет документ. | |
| `userId` | ObjectId | Пользователь Overleaf. Обязательное. В схеме указано `unique: true`, но индекс не создаётся (см. «Индексы»); upsert по `userId` сохраняет один документ на пользователя. | `giteaSyncUserCredentials.mjs:8`, `TokenManager.mjs:89-96` |
| `gitea` | String | JSON `{ accessToken, refreshToken, expiresAt }`, зашифрованный с помощью `@overleaf/access-token-encryptor`. `expiresAt` задаётся в миллисекундах от начала эпохи или равен `null`; `refreshToken` может быть `null`. Пароль берётся из `GITEA_TOKEN_CIPHER_PASSWORD`; метка шифра `GITEA_TOKEN_CIPHER_LABEL`, по умолчанию `2026.10-v3`. Обязательное. | `giteaSyncUserCredentials.mjs:9-10`, `TokenManager.mjs:17-30`, `services/web/modules/gitea-sync/app/src/GiteaApiClient.mjs:198-209` |
| `__v` | Number | Ключ версии Mongoose. Схема его не отключает. | По умолчанию в Mongoose |

#### Кто пишет {#who-writes-it}

| Код | Что делает |
| ---- | ------------ |
| `TokenManager.mjs:89-96` (`saveUserToken`) | Делает upsert зашифрованных учётных данных пользователя. Вызывается из OAuth-колбэка (`services/web/modules/gitea-sync/app/src/GiteaSyncController.mjs:146`). В отличие от GitLab Sync, повторное связывание не отзывает заменённый токен. |
| `TokenManager.mjs:53-79` (`refreshUserToken`) | Когда до `expiresAt` токена доступа остаётся меньше 5 минут (`:12`), получает новые токены по токену обновления и сохраняет их (`:76`). Работает под блокировкой `giteaSyncToken` для каждого пользователя (`:14,54`), потому что Gitea заменяет токен обновления при использовании. |
| `TokenManager.mjs:100-102` (`removeUserToken`) | Удаляет документ. В Gitea нет API для отзыва OAuth-токена, поэтому пользователь сам отзывает разрешение в Gitea (`:98-99`). Вызывается при отвязке (`GiteaSyncController.mjs:173`) и когда истекает срок удалённого пользователя (`services/web/modules/gitea-sync/index.mjs:56-58`). |

#### Кто читает {#who-reads-it}

| Код | Что делает |
| ---- | ------------ |
| `TokenManager.mjs:40-44,82-86` (`getUserCredentials`, `getUserToken`) | Расшифровывает учётные данные для каждого вызова API Gitea, сначала обновляя их, если срок токена скоро истекает: `services/web/modules/gitea-sync/app/src/GiteaSyncHandler.mjs` (например, `:27`) и `services/web/modules/gitea-sync/app/src/GitMerge.mjs:52`. Если документа нет или учётные данные не удаётся расшифровать или обновить, выбрасывает `InvalidTokenError`, и пользователь считается несвязанным (`GiteaSyncHandler.mjs:25-37`). |
| `services/web/modules/admin-tools/app/src/AdminUserListManager.mjs:395` | Проверяет, есть ли у пользователя документ, для интеграций, показываемых в панели администратора. |

#### Индексы {#indexes}

| Имя | Ключи | Параметры | Миграция |
| ---- | ---- | ------- | --------- |
| `_id_` | `_id: 1` | | default |

`autoIndex` в Mongoose выключен (`services/web/app/src/infrastructure/Mongoose.mjs:7`), поэтому `unique: true` из схемы на `userId` ничего не создаёт. Ни одна миграция не создаёт индексы для этой коллекции.

#### Примечания {#notes}

* Смена `GITEA_TOKEN_CIPHER_PASSWORD` делает сохранённые учётные данные нечитаемыми. Такие пользователи считаются несвязанными, пока не свяжут учётную запись заново.
* Удалённый пользователь сохраняет документ, пока не истечёт его срок.
