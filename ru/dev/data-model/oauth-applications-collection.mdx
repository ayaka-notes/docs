`oauthApplications` хранит OAuth-клиенты, известные web. Один документ соответствует одному клиенту. В Ayakaleaf Pro в неё пишет только веб-модуль `git-bridge`: при запуске web он создаёт один клиент с именем `Overleaf Git Bridge`. Схема находится в `services/web/app/src/models/OauthApplication.mjs`.

#### Поля {#fields}

| Поле | Тип | Значение | Источник |
| ----- | ---- | ------- | ------ |
| `_id` | ObjectId | Id документа клиента. На него ссылаются `oauthAccessTokens.oauthApplication_id` и `oauthAuthorizationCodes.oauthApplication_id`. | `OauthApplication.mjs:5` |
| `id` | String | Id клиента: 64 случайные строчные буквы и цифры. | `OauthApplication.mjs:7`, `services/web/modules/git-bridge/index.mjs:25` |
| `clientSecret` | String | Секрет клиента, записывается как `v1.` и 32 случайных символа. Его читает только `getClient`, а `getClient` никто не вызывает (см. Примечания). | `OauthApplication.mjs:8`, `git-bridge/index.mjs:26` |
| `grants` | Array of String | Типы grant. У клиента git-bridge: `['password']`. Возвращается вместе с клиентом при проверке токена (`services/web/modules/oauth2-server/app/src/OAuth2Model.mjs:67-72`). | `OauthApplication.mjs:9`, `git-bridge/index.mjs:27` |
| `name` | String | Имя клиента. Модуль git-bridge и код персональных токенов доступа находят клиента по имени `Overleaf Git Bridge`. | `OauthApplication.mjs:10`, `git-bridge/index.mjs:15-16,28` |
| `redirectUris` | Array of String | Разрешённые URI перенаправления. У клиента git-bridge: `[]`. | `OauthApplication.mjs:11`, `git-bridge/index.mjs:29` |
| `scopes` | Array of String | Scopes, которые может использовать клиент. У клиента git-bridge: `['git_bridge']`. | `OauthApplication.mjs:12`, `git-bridge/index.mjs:30` |
| `pkceEnabled` | Boolean | Только в схеме: никакой код в этом репозитории его не записывает, а читает только неиспользуемый `getClient` (`OAuth2Model.mjs:207`). | `OauthApplication.mjs:13` |

#### Кто пишет {#who-writes-it}

| Код | Что делает |
| ---- | ------------ |
| `git-bridge/index.mjs:9-35` (module `git-bridge`) | Если `GIT_BRIDGE_ENABLED` равно `true`, при запуске web создаёт клиент `Overleaf Git Bridge`, если клиента с таким именем ещё нет. |

#### Кто читает {#who-reads-it}

| Код | Что делает |
| ---- | ------------ |
| `services/web/modules/oauth2-server/app/src/OAuthPersonalAccessTokenManager.mjs:53-61` (module `oauth2-server`) | Находит клиент `Overleaf Git Bridge` по имени и сохраняет его `_id` в каждом новом персональном токене доступа. Без клиента токен не создаётся. |
| `OAuth2Model.mjs:31-39,67-72` (`getAccessToken`) | Загружает клиент токена через `oauthApplication_id` и возвращает его `id` и `grants`. |
| `OAuth2Model.mjs:185-209,241,275` (`getClient`, `saveToken`, `saveAuthorizationCode`) | Ищут клиентов по `id`. В этом репозитории никогда не вызываются, см. Примечания. |

#### Индексы {#indexes}

Только индекс по умолчанию на `_id`. Уникальный индекс `id_1` создают только миграции с тегами `saas` (`20190912145016_create_oauthApplications_indexes.mjs`) и `server-pro` (`20230502180757_server_pro_oauth_indexes.mjs`), которые Community Edition не запускает.

#### Примечания {#notes}

* Web использует `@node-oauth/oauth2-server` только для проверки bearer-токенов (`server.authenticate` в `services/web/app/src/Features/Authentication/AuthenticationController.mjs:409-450`), что вызывает только методы модели `getAccessToken` и `verifyScope`. Ни один маршрут не обслуживает `/oauth/token` или `/oauth/authorize`, поэтому `getClient`, `saveToken` и `saveAuthorizationCode` никогда не вызываются.
* Модуль ищет клиента по имени, а затем создаёт его, и в Community Edition нет уникального индекса на `name` или `id`. Поэтому ничто не мешает появлению второго клиента с тем же именем. Код, которому нужен клиент, берёт тот, который вернёт `findOne`.
