---
title: Коллекция Deleted Projects
icon: trash-can
---

`deletedProjects` хранит проект после удаления: один документ на каждый удалённый проект, с копией всего документа проекта и сведениями о том, кто его удалил. Web записывает коллекцию в `services/web/app/src/Features/Project/ProjectDeleter.mjs`; схема: `services/web/app/src/models/DeletedProject.mjs`. Когда истекает срок до окончательного удаления, процедура истечения уничтожает данные проекта и очищает `project`, но запись с `deleterData` остаётся.

Проекта в корзине здесь нет: перемещение в корзину лишь добавляет пользователя в `trashed` проекта, см. [Коллекция Projects](/ru/dev/data-model/projects-collection).

#### Кто пишет {#who-writes-it}

| Код | Что делает |
| ---- | ------------ |
| `ProjectDeleter.mjs:189-293` (`deleteProject`) | Сбрасывает проект на диск, архивирует его docs из Mongo, убирает его из тегов, делает upsert записи и удаляет документ `projects`. |
| `ProjectDeleter.mjs:295-342` (`undeleteProject`) | Снова вставляет проект под именем `<name> (Restored)` (уникальным для владельца) и без архивации, затем удаляет запись. Завершается ошибкой `project_too_old_to_restore`, когда `project` равно `null`. Вызывается из панели администратора: восстановление одного проекта (`AdminProjectManager.mjs:497-515`) или восстановление удалённого пользователя вместе с проектами, удалёнными вместе с учётной записью (`services/web/modules/admin-tools/app/src/AdminUserManager.mjs:678-689`). |
| `ProjectDeleter.mjs:344-416` (`expireDeletedProject`) | Уничтожает docs, историю, чат и журнал аудита проекта, вызывает хук `projectExpired`, затем устанавливает `project` и `deleterData.deleterIpAddress` в `null`. Если проект снова существует, удаляет только устаревшую запись. |
| `ProjectDeleter.mjs:97-146` (`expireDeletedProjectsAfterDuration`) | Завершает срок пакета записей старше заданной задержки. Маршрут `POST /internal/expire-deleted-projects-after-duration` (`services/web/app/src/router.mjs:842-846`), который cron Community Edition вызывает каждый час в 20 минут, когда `ENABLE_CRON_RESOURCE_DELETION` равно `true` (`server-ce/cron/delete-projects.sh:10-23`, `server-ce/config/crontab-deletion:3`). Один проект: `POST /internal/project/:projectId/expire-deleted-project` (`router.mjs:852-856`) или Purge в панели администратора (`AdminProjectManager.mjs:517-529`). |

#### Примечания {#notes}

* Модули, которые слушают `projectExpired`, удаляют свои данные проекта: `git-bridge` (`services/web/modules/git-bridge/index.mjs:37`), `github-sync` (`services/web/modules/github-sync/index.mjs:56`), `gitlab-sync` (`services/web/modules/gitlab-sync/index.mjs:46`), `gitea-sync` (`services/web/modules/gitea-sync/index.mjs:46`) и `dropbox` (`services/web/modules/dropbox/index.mjs:54`).
* Истёкшая запись никогда не удаляется: `deleterData` остаётся навсегда, очищаются только `project` и IP-адрес.
* Mongoose также присваивает `deleterData` собственный `_id`, который никто не читает.
