---
title: Коллекция Project History Blobs
icon: cubes
---

`projectHistoryBlobs` содержит один документ на историю проекта: метаданные (хеш и размеры) каждого blob, который history-v1 сохранил для этого проекта. Blob представляет собой содержимое файла или doc в какой-то момент его истории. Сами байты хранятся как объекты в бакете blob-ов проекта. Схемы Mongoose нет: history-v1 записывает коллекцию в `services/history-v1/storage/lib/blob_store/mongo.js`, который он использует для id истории из 24 шестнадцатеричных символов, как в CE (`services/history-v1/storage/lib/blob_store/index.js:108-116`).

#### Поля {#fields}

| Поле | Тип | Значение | Источник |
| ----- | ---- | ------- | ------ |
| `_id` | ObjectId | Id истории проекта, значение из `projects.overleaf.history.id`. | `mongo.js:37-40` |
| `blobs` | Object | Записи blob-ов, сгруппированные по корзинам. Ключ корзины: первые 3 шестнадцатеричные цифры хеша. | `mongo.js:39`, `429-431` |
| `blobs.<abc>` | Array of Object | До 8 записей, хеш которых начинается с `abc`. Когда в корзине уже 8 записей, следующая попадает в [Коллекция Project History Sharded Blobs](/ru/dev/data-model/project-history-sharded-blobs-collection). | `mongo.js:23`, `375-389` |
| `blobs.<abc>[].h` | Binary | Хеш, 20 байт: SHA-1 git blob, `sha1("blob " + byteLength + "\0" + content)` (`libraries/overleaf-editor-core/lib/blob_utils.js:36-43`). Его шестнадцатеричная форма и есть хеш, используемый в других местах, например `fileRefs.hash` в проектах. | `mongo.js:472` |
| `blobs.<abc>[].b` | Number | Длина содержимого в байтах. | `mongo.js:473` |
| `blobs.<abc>[].s` | Number | Длина содержимого как текста; `null`, если содержимое не является редактируемым текстом (двоичное или слишком большое для редактирования) (`blob_utils.js:116-130`). | `mongo.js:474` |

#### Кто пишет {#who-writes-it}

| Код | Что делает |
| ---- | ------------ |
| `services/history-v1/storage/lib/blob_store/mongo.js:34-47` | `initialize`: вставляет `{ _id, blobs: {} }`, когда history-v1 создаёт историю проекта (`services/history-v1/storage/lib/chunk_store/index.js:67-68`). |
| `mongo.js:370-390` | `insertBlob`: `$addToSet` записи в её корзину, пока в корзине меньше 8 записей, иначе в шардированную коллекцию. Выполняется после загрузки байтов из `putString`, `putBlob` и `copyBlob` (`blob_store/index.js:223-237`, `271-278`, `456-467`). |
| `mongo.js:54-105` | `clone`: копирует корзины в другой id истории для `POST /projects/:project_id/clone` в history-v1. Ничто в web не вызывает этот маршрут (см. [Коллекция Project History Chunks](/ru/dev/data-model/project-history-chunks-collection)). |
| `mongo.js:413-422` | `deleteBlobs`: удаляет документ и шардированные документы проекта при `DELETE /projects/:project_id` в history-v1 (`services/history-v1/api/controllers/projects.js:361-373`). |

Откуда берутся новые blob-ы:

* Загрузка файлов: web отправляет файл в `PUT /projects/:project_id/blobs/:hash` history-v1 (`services/web/app/src/Features/History/HistoryManager.mjs:164-169`, `services/history-v1/api/controllers/projects.js:376-402`).
* Копии проектов: web просит history-v1 скопировать blob каждого файла через `POST /projects/:project_id/blobs/:hash?copyFrom=` (`services/web/app/src/Features/Project/ProjectDuplicator.mjs:333-338`, `HistoryManager.mjs:177-187`, `projects.js:521-555`).
* Текст docs: когда history-v1 записывает чанк, он сохраняет как blob-ы текст каждого doc, а также его комментарии и отслеживаемые изменения в виде JSON (`chunk_store/index.js:402-405`, `libraries/overleaf-editor-core/lib/file_data/string_file_data.js:166-173`).

#### Кто читает {#who-reads-it}

| Код | Что делает |
| ---- | ------------ |
| `mongo.js:113-157` | `findBlob`: один blob по хешу; ищет в шардированной коллекции, если корзина заполнена. Используется `BlobStore.getBlob` (`blob_store/index.js:376-387`) для маршрутов blob-ов (`projects.js:416-480`) и перед вставкой, чтобы пропустить уже существующие blob-ы (`blob_store/index.js:441-448`). |
| `mongo.js:165-260` | `findBlobs`: много blob-ов сразу, для загрузки файлов чанка. |
| `mongo.js:265-309` | `getProjectBlobs`: все blob-ы проекта. |
| `mongo.js:316-363` | `getProjectBlobsBatch`: все blob-ы нескольких проектов, для `POST /projects/blob-stats` в history-v1 (`projects.js:620`). Модуль admin-tools показывает результат как размер проекта (`services/web/modules/admin-tools/app/src/AdminProjectManager.mjs:395-405`). |

#### Индексы {#indexes}

Только стандартный индекс `_id`. Ни одна миграция в `tools/migrations/` не добавляет других.

#### Примечания {#notes}

* Байты blob хранятся по ключу `<project key>/<hash[0:2]>/<hash[2:]>` (`blob_store/index.js:51-53`) в бакете `OVERLEAF_EDITOR_PROJECT_BLOBS_BUCKET` (`services/history-v1/config/custom-environment-variables.json:49-52`). Ключ проекта: id истории, дополненный нулями, перевёрнутый и разбитый на 3/3/остальные символы (`libraries/object-persistor/src/ProjectKey.js:8-15`).
* Blob хранится один раз на проект: вставка хеша, который у проекта уже есть, пропускается (`blob_store/index.js:227-230`, `249-252`).
* Пустому содержимому запись не нужна; `getBlob` отвечает на него без поиска (`blob_store/index.js:378-380`).
* `projectHistoryGlobalBlobs` читается при запуске (`blob_store/index.js:138-148`), но никакой код CE в неё не пишет, поэтому в CE каждый blob является blob-ом проекта.
