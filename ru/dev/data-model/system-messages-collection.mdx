---
title: Коллекция systemmessages
icon: bullhorn
---

`systemmessages` хранит баннеры для всего сайта, которые администратор публикует для всех вошедших пользователей. Каждый документ описывает одно сообщение. Владельцем является `web`; схема: `services/web/app/src/models/SystemMessage.mjs`, код: `services/web/app/src/Features/SystemMessages/SystemMessageManager.mjs`.

#### Поля {#fields}

| Поле | Тип | Значение | Источник |
| --- | --- | --- | --- |
| `_id` | ObjectId | Id сообщения. По этому id браузер запоминает, какие сообщения пользователь закрыл (`services/web/frontend/js/shared/components/system-message.tsx:10`). | `SystemMessage.mjs:5` |
| `content` | String | Текст сообщения, по умолчанию `''`. | `SystemMessage.mjs:7` |
| `__v` | Number | Ключ версии Mongoose, добавляется `message.save()`. | `SystemMessageManager.mjs:29-30` |

#### Кто записывает {#who-writes-it}

| Код | Что делает |
| --- | --- |
| `SystemMessageManager.mjs:28-33` (`createMessage`) | `POST /admin/messages` (`services/web/app/src/router.mjs:1150-1152`, `services/web/app/src/Features/ServerAdmin/AdminController.mjs:151-159`): добавляет одно сообщение. |
| `SystemMessageManager.mjs:22-26` (`clearMessages`) | `POST /admin/messages/clear` (`router.mjs:1155-1157`, `AdminController.mjs:161-168`): удаляет все сообщения. Удалить только одно нельзя. |

#### Кто читает {#who-reads-it}

| Код | Что делает |
| --- | --- |
| `SystemMessageManager.mjs:50-65` | Каждый процесс `web` держит все сообщения в памяти и перезагружает их каждые 20-30 секунд, а также сразу после собственного создания или очистки. |
| `services/web/app/src/Features/SystemMessages/SystemMessageController.mjs:6-24` | `GET /system/messages` (`router.mjs:331`): возвращает закэшированные сообщения вошедшим пользователям. Пока сайт закрыт (`siteIsOpen` равно false), вместо них возвращается фиксированное уведомление, которое не хранится в Mongo. |
| `AdminController.mjs:83-84` | Страница `/admin` выводит сообщения напрямую из Mongo. |

#### Индексы {#indexes}

Ни одна миграция не создаёт индекс для `systemmessages`; существует только индекс `_id` по умолчанию.

#### Примечания {#notes}

* Если задан `notifyOnSystemMessageChanges`, создание или очистка также публикуется в канал Redis `refresh-system-messages`, и другие процессы `web` сразу перезагружают сообщения (`SystemMessageManager.mjs:9`, `:35-48`, `:75-87`). Без этого они подхватят изменение при следующей плановой перезагрузке.
