---
title: Коллекция GitLab Sync User Credentials
icon: user-lock
---

`gitlabSyncUserCredentials` хранит по одному документу на каждого пользователя, который связал учётную запись GitLab для GitLab Sync. В нём хранятся OAuth-токены пользователя в зашифрованном виде. Коллекция относится к веб-модулю `gitlab-sync` (`services/web/modules/gitlab-sync`). Схема находится в `services/web/modules/gitlab-sync/app/models/gitlabSyncUserCredentials.mjs`, а весь доступ идёт через `services/web/modules/gitlab-sync/app/src/TokenManager.mjs`.

#### Поля {#fields}

| Поле | Тип | Значение | Источник |
| ----- | ---- | ------- | ------ |
| `_id` | ObjectId | Задаётся Mongoose, когда upsert вставляет документ. | |
| `userId` | ObjectId | Пользователь Overleaf. Обязательное. В схеме указано `unique: true`, но индекс не создаётся (см. «Индексы»); upsert по `userId` сохраняет один документ на пользователя. | `gitlabSyncUserCredentials.mjs:8`, `TokenManager.mjs:88-95` |
| `gitlab` | String | JSON `{ accessToken, refreshToken, expiresAt }`, зашифрованный с помощью `@overleaf/access-token-encryptor`. `expiresAt` задаётся в миллисекундах от начала эпохи или равен `null`; `refreshToken` может быть `null`. Пароль берётся из `GITLAB_TOKEN_CIPHER_PASSWORD`; метка шифра `GITLAB_TOKEN_CIPHER_LABEL`, по умолчанию `2026.10-v3`. Обязательное. | `gitlabSyncUserCredentials.mjs:9-10`, `TokenManager.mjs:18-31`, `services/web/modules/gitlab-sync/app/src/GitLabApiClient.mjs:209-220` |
| `__v` | Number | Ключ версии Mongoose. Схема его не отключает. | По умолчанию в Mongoose |

#### Кто пишет {#who-writes-it}

| Код | Что делает |
| ---- | ------------ |
| `TokenManager.mjs:88-95` (`saveUserToken`) | Делает upsert зашифрованных учётных данных пользователя. |
| `TokenManager.mjs:99-108` (`linkUserToken`) | Сохраняет новые учётные данные из OAuth-колбэка (`services/web/modules/gitlab-sync/app/src/GitLabSyncController.mjs:146`). Когда пользователь связывает учётную запись заново, заменённый токен доступа отзывается в GitLab в фоне. |
| `TokenManager.mjs:53-78` (`refreshUserToken`) | Когда до `expiresAt` токена доступа остаётся меньше 5 минут (`:13,47-49`), получает новые токены по токену обновления и сохраняет их (`:75`). Работает под блокировкой `gitlabSyncToken` для каждого пользователя (`:15,54`), потому что GitLab расходует токен обновления при использовании. |
| `TokenManager.mjs:111-126` (`removeUserToken`) | Отзывает токен доступа в GitLab (по возможности), затем удаляет документ. Вызывается при отвязке (`GitLabSyncController.mjs:173`) и когда истекает срок удалённого пользователя (`services/web/modules/gitlab-sync/index.mjs:56-58`). |

#### Кто читает {#who-reads-it}

| Код | Что делает |
| ---- | ------------ |
| `TokenManager.mjs:41-45,81-85` (`getUserCredentials`, `getUserToken`) | Расшифровывает учётные данные для каждого вызова API GitLab, сначала обновляя их, если срок токена скоро истекает: `services/web/modules/gitlab-sync/app/src/GitLabSyncHandler.mjs` (например, `:27`) и `services/web/modules/gitlab-sync/app/src/GitMerge.mjs:52`. Если документа нет или учётные данные не удаётся расшифровать или обновить, выбрасывает `InvalidTokenError`, и пользователь считается несвязанным (`GitLabSyncHandler.mjs:25-37`). |
| `services/web/modules/admin-tools/app/src/AdminUserListManager.mjs:394` | Проверяет, есть ли у пользователя документ, для интеграций, показываемых в панели администратора. |

#### Индексы {#indexes}

| Имя | Ключи | Параметры | Миграция |
| ---- | ---- | ------- | --------- |
| `_id_` | `_id: 1` | | default |

`autoIndex` в Mongoose выключен (`services/web/app/src/infrastructure/Mongoose.mjs:7`), поэтому `unique: true` из схемы на `userId` ничего не создаёт. Ни одна миграция не создаёт индексы для этой коллекции.

#### Примечания {#notes}

* Смена `GITLAB_TOKEN_CIPHER_PASSWORD` делает сохранённые учётные данные нечитаемыми. Такие пользователи считаются несвязанными, пока не свяжут учётную запись заново.
* Удалённый пользователь сохраняет документ, пока не истечёт его срок.
