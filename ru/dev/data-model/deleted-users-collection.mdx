---
title: Коллекция Deleted Users
icon: user-xmark
---

`deletedUsers` хранит учётную запись пользователя после удаления: один документ на каждую удалённую учётную запись, с копией всего документа пользователя и сведениями о том, кто её удалил. Web записывает коллекцию в `services/web/app/src/Features/User/UserDeleter.mjs`; схема: `services/web/app/src/models/DeletedUser.mjs`. Когда истекает срок до окончательного удаления, процедура истечения удаляет копию пользователя, но запись с `deleterData` остаётся.

Удаление пользователя удаляет и проекты, которыми он владеет; они попадают в [Коллекция Deleted Projects](/ru/dev/data-model/deleted-projects-collection) с причиной `account-deletion`.

#### Кто пишет {#who-writes-it}

| Код | Что делает |
| ---- | ------------ |
| `UserDeleter.mjs:37-80` (`deleteUser`) | Добавляет запись журнала аудита `delete-account`, очищает данные пользователя и вызывает хук `deleteUser`, делает upsert записи (`_createDeletedUser`, `UserDeleter.mjs:192-213`), удаляет проекты пользователя, отправляет письмо с предупреждением о безопасности, если оно не пропущено, и удаляет документ `users`. Вызывающие: страница настроек учётной записи (`services/web/app/src/Features/User/UserController.mjs:280-284`), панель администратора (`services/web/modules/admin-tools/app/src/AdminUserManager.mjs:604-612`) и скрипт `delete-user` (`delete-user.mjs:40-45`). |
| `UserDeleter.mjs:93-115` (`expireDeletedUser`) | Вызывает хук `expireDeletedUser`, удаляет данные онбординга пользователя, затем удаляет `user` и `deleterData.deleterIpAddress`. |
| `UserDeleter.mjs:117-161` (`expireDeletedUsersAfterDuration`) | Завершает срок всех записей старше заданной задержки и удаляет `userAuditLogEntries` пользователя. Маршрут `POST /internal/expire-deleted-users-after-duration` (`services/web/app/src/router.mjs:847-851`), который cron Community Edition вызывает каждый час в 15 минут, когда `ENABLE_CRON_RESOURCE_DELETION` равно `true` (`server-ce/cron/delete-users.sh:10-23`, `server-ce/config/crontab-deletion:2`). Один пользователь: `POST /internal/users/:userId/expire` (`router.mjs:857-861`). |
| `AdminUserManager.mjs:630-649` (`purgeDeletedUser`, модуль `admin-tools`) | Purge в панели администратора: выполняет `expireDeletedUser` и удаляет записи журнала аудита пользователя. |
| `AdminUserManager.mjs:651-696` (`restoreDeletedUser`, модуль `admin-tools`) | Восстановление в панели администратора: заново создаёт документ `users` из `user` (отказ, если адрес электронной почты занят), удаляет запись и восстанавливает проекты, удалённые вместе с учётной записью. |

#### Примечания {#notes}

* Модули, которые слушают `expireDeletedUser`, удаляют свои данные пользователя: `dropbox` (`services/web/modules/dropbox/index.mjs:62`), `github-sync` (`services/web/modules/github-sync/index.mjs:66`), `gitlab-sync` (`services/web/modules/gitlab-sync/index.mjs:56`) и `gitea-sync` (`services/web/modules/gitea-sync/index.mjs:56`).
* Истёкшая запись никогда не удаляется: `deleterData` остаётся навсегда, удаляются только `user` и IP-адрес.
* Персональные токены доступа пользователя не удаляются вместе с учётной записью, см. [Коллекция OAuth Access Tokens](/ru/dev/data-model/oauth-access-tokens-collection).
* Mongoose также присваивает `deleterData` собственный `_id`, который никто не читает.
