---
title: Коллекция GitHub Sync Project States
icon: code-branch
---

`githubSyncProjectStates` хранит по одному документу на каждый проект, связанный с репозиторием GitHub: какой это репозиторий и на чём остановилась последняя синхронизация. Коллекция относится к веб-модулю `github-sync` (`services/web/modules/github-sync`). Схема находится в `services/web/modules/github-sync/app/models/githubSyncProjectStates.mjs`, а весь доступ идёт через `services/web/modules/github-sync/app/src/SyncStateManager.mjs`.

#### Поля {#fields}

| Поле | Тип | Значение | Источник |
| ----- | ---- | ------- | ------ |
| `_id` | ObjectId | Задаётся Mongoose при создании. | |
| `projectId` | ObjectId | Связанный проект. Обязательное. В схеме указано `unique: true`, но индекс не создаётся (см. «Индексы»). | `githubSyncProjectStates.mjs:8` |
| `repoFullName` | String | Репозиторий в виде `owner/name` (`full_name` в GitHub). Обязательное. | `githubSyncProjectStates.mjs:9` |
| `defaultBranchName` | String | Ветка, с которой синхронизируется проект. Задаётся при связывании проекта и потом не меняется: при импорте это ветка из формы импорта, при экспорте это ветка по умолчанию нового репозитория. По умолчанию `null`. | `githubSyncProjectStates.mjs:10`, `GitHubSyncHandler.mjs:175-181,235-241` |
| `mergeStatus` | String | `clean`, `conflict` или `diverged`. По умолчанию `clean`. | `githubSyncProjectStates.mjs:11` |

#### Кто пишет {#who-writes-it}

| Код | Что делает |
| ---- | ------------ |
| `SyncStateManager.mjs:9-14` (`createProjectState`) | Создаёт документ: после импорта репозитория как нового проекта (`services/web/modules/github-sync/app/src/GitHubSyncHandler.mjs:175-181`) или после экспорта проекта в новый репозиторий (`GitHubSyncHandler.mjs:235-241`, только владелец, отказ, если проект уже связан). |
| `SyncStateManager.mjs:16-21` (`updateProjectState`) | `$set` изменённых полей. `getMergeOverview` устанавливает `mergeStatus: 'diverged'`, когда синхронизируемая ветка больше не основана на `lastSyncCommit`: compare в GitHub отвечает `diverged` или `behind` (`GitHubApiClient.mjs:382-400`), либо коммит исчез, а пользователь может пушить (`GitHubSyncHandler.mjs:123,126-137`). Синхронизация (`services/web/modules/github-sync/app/src/GitMerge.mjs`) при успехе передвигает `lastSyncCommit`/`lastSyncVersion` (например, `:143,173,224`), записывает конфликт в `unmergedBranchName`, `unmergedBranchHead` и `conflictVersion` (`:207-213`) и очищает их, когда конфликт разрешён (`:250-257`). |
| `SyncStateManager.mjs:23-25` (`removeProjectState`) | Удаляет документ, когда владелец отвязывает проект (`GitHubSyncHandler.mjs:83-97`) и когда истекает срок удалённого проекта (`services/web/modules/github-sync/index.mjs:56-58`). |

#### Кто читает {#who-reads-it}

| Код | Что делает |
| ---- | ------------ |
| `GitHubSyncHandler.mjs:39-60` (`getProjectState`) | Передаёт редактору `mergeStatus`, `repoFullName` и `unmergedBranchName`. Если документа нет, отвечает `need-export`; это значение никогда не сохраняется. |
| `GitHubSyncHandler.mjs:110-143` (`getMergeOverview`) | Сравнивает `lastSyncCommit` и `lastSyncVersion` с GitHub и историей проекта, чтобы перечислить новые коммиты. |
| `GitHubSyncHandler.mjs:200` (`exportProject`) | Отказывается экспортировать уже связанный проект. |
| `GitMerge.mjs:27` (`doGitMergeWithoutLock`) | Загружает состояние в начале синхронизации. |

#### Индексы {#indexes}

| Имя | Ключи | Параметры | Миграция |
| ---- | ---- | ------- | --------- |
| `_id_` | `_id: 1` | | default |

`autoIndex` в Mongoose выключен (`services/web/app/src/infrastructure/Mongoose.mjs:7`), поэтому `unique: true` из схемы на `projectId` ничего не создаёт. `tools/migrations/20190912145010_create_githubSyncProjectStates_indexes.mjs` (`project_id` и `owner_id` из upstream) помечена только тегом `saas` и в CE не запускается.

#### Примечания {#notes}

* Синхронизация выполняется под блокировкой проекта `gitSync` (`GitMerge.mjs:17-24`). GitLab Sync и Gitea Sync берут ту же блокировку, поэтому для проекта одновременно идёт только одна синхронизация.
* Удалённый проект сохраняет свой документ, пока не истечёт его срок.
* Токен GitHub пользователя хранится в [GitHub Sync User Credentials](/ru/dev/data-model/github-sync-user-credentials-collection).
