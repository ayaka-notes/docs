В этом разделе мы рассмотрим модель данных Overleaf. Overleaf использует MongoDB для хранения данных; единственная база данных называется `sharelatex` — так назывался предшественник Overleaf.

Среда разработки уже запускает Mongo Express рядом с Mongo (см. [setup-develop-tools.md](/ru/dev/environment/setup-develop-tools  "mention")). Откройте [http://localhost:8081/](http://localhost:8081/) и войдите с `admin:pass`.

Вы также можете открыть оболочку в контейнере Mongo из каталога `develop`:

```bash
bin/docker-compose exec mongo mongosh sharelatex
```

#### Как устроены страницы {#how-the-pages-are-written}

* Каждая страница перечисляет поля, которые записывает код, с их типом, значением и строкой кода, которая это показывает: строкой схемы Mongoose или местом, где поле записывается. Для полей, которые пишет только миграция, скрипт или один из web-модулей, это указано.
* У многих коллекций нет схемы Mongoose: сервисы пишут в них через драйвер MongoDB.
* Индексы создают только миграции из `tools/migrations/`. CE при каждом запуске выполняет миграции с тегом `server-ce` (`server-ce/init_scripts/900_run_web_migrations.sh`); `autoIndex` в Mongoose отключён (`services/web/app/src/infrastructure/Mongoose.mjs:7`). В таблицах индексов перечислено только то, что в итоге есть у экземпляра CE.
* Текст docs хранится в Mongo, а остальное содержимое нет. Содержимое файлов хранится в виде blob-ов, а история в виде чанков в бакетах history-v1 (локальные папки или S3 / RustFS); открытые docs находятся в Redis, пока document-updater не сбросит их на диск.

В базе данных CE больше коллекций, чем перечислено здесь. Многие из них создаются пустыми миграциями индексов и используются только на overleaf.com. Например, ни CE, ни наши модули при обычной работе не пишут в `splittests`, `samlLogs`, `notificationsPreferences`, `onboardingDataCollection` и `userfeatureusages`, поэтому у них нет страниц.
