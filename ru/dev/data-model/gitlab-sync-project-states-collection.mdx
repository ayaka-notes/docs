---
title: Коллекция GitLab Sync Project States
icon: code-merge
---

`gitlabSyncProjectStates` хранит по одному документу на каждый проект, связанный с проектом GitLab: какой это репозиторий и на чём остановилась последняя синхронизация. Коллекция относится к веб-модулю `gitlab-sync` (`services/web/modules/gitlab-sync`). Схема находится в `services/web/modules/gitlab-sync/app/models/gitlabSyncProjectStates.mjs`, а весь доступ идёт через `services/web/modules/gitlab-sync/app/src/SyncStateManager.mjs`. Поля те же, что в [GitHub Sync Project States](/ru/dev/data-model/github-sync-project-states-collection).

| Поле | Тип | Значение | Источник |
| ----- | ---- | ------- | ------ |
| `_id` | ObjectId | Задаётся Mongoose при создании. | |
| `projectId` | ObjectId | Связанный проект. Обязательное. В схеме указано `unique: true`, но индекс не создаётся (см. «Индексы»). | `gitlabSyncProjectStates.mjs:8` |
| `repoFullName` | String | Путь проекта GitLab вместе с пространством имён (`path_with_namespace` в GitLab), например `group/subgroup/name`. Обязательное. | `gitlabSyncProjectStates.mjs:9`, `GitLabApiClient.mjs:347` |
| `defaultBranchName` | String | Ветка, с которой синхронизируется проект. Задаётся при связывании проекта и потом не меняется: при импорте это ветка из формы импорта, при экспорте это ветка по умолчанию нового репозитория или `main`, если API её не возвращает. По умолчанию `null`. | `gitlabSyncProjectStates.mjs:10`, `GitLabSyncHandler.mjs:175-181,234-240`, `GitLabApiClient.mjs:346-349` |
| `mergeStatus` | String | `clean`, `conflict` или `diverged`. По умолчанию `clean`. | `gitlabSyncProjectStates.mjs:11` |

| `lastSyncVersion` | Number | Версия истории проекта на момент последней синхронизации из `GET /project/:id/version` сервиса project-history, прочитанная после сброса истории. | `conflictVersion` | Number | Во время конфликта: версия истории проекта на момент записи конфликта. По умолчанию `null`. | `gitlabSyncProjectStates.mjs:16` |
| `__v` | Number | Ключ версии Mongoose. Схема его не отключает. | По умолчанию в Mongoose |

#### Кто пишет {#who-writes-it}

| Код | Что делает |
| ---- | ------------ |
| `SyncStateManager.mjs:9-14` (`createProjectState`) | Создаёт документ: после импорта репозитория как нового проекта (`services/web/modules/gitlab-sync/app/src/GitLabSyncHandler.mjs:175-181`) или после экспорта проекта в новый репозиторий (`GitLabSyncHandler.mjs:234-240`, только владелец, отказ, если проект уже связан). |
| `SyncStateManager.mjs:16-21` (`updateProjectState`) | `$set` изменённых полей. `getMergeOverview` устанавливает `mergeStatus: 'diverged'`, когда синхронизируемая ветка больше не содержит `lastSyncCommit` (проверка merge base, `services/web/modules/gitlab-sync/app/src/GitLabApiClient.mjs:460`) либо коммит исчез, а пользователь может пушить (`GitLabSyncHandler.mjs:123,126-137`). Синхронизация (`services/web/modules/gitlab-sync/app/src/GitMerge.mjs`) при успехе передвигает `lastSyncCommit`/`lastSyncVersion` (например, `:152,189,231`), записывает конфликт в `unmergedBranchName`, `unmergedBranchHead` и `conflictVersion` (`:214-220`) и очищает их, когда конфликт разрешён (`:257-264`). |
| `SyncStateManager.mjs:23-25` (`removeProjectState`) | Удаляет документ, когда владелец отвязывает проект (`GitLabSyncHandler.mjs:83-97`) и когда истекает срок удалённого проекта (`services/web/modules/gitlab-sync/index.mjs:46-48`). |

#### Кто читает {#who-reads-it}

| Код | Что делает |
| ---- | ------------ |
| `GitLabSyncHandler.mjs:39-60` (`getProjectState`) | Передаёт редактору `mergeStatus`, `repoFullName` и `unmergedBranchName`. Если документа нет, отвечает `need-export`; это значение никогда не сохраняется. |
| `GitLabSyncHandler.mjs:110-143` (`getMergeOverview`) | Сравнивает `lastSyncCommit` и `lastSyncVersion` с GitLab и историей проекта, чтобы перечислить новые коммиты. |
| `GitLabSyncHandler.mjs:200` (`exportProject`) | Отказывается экспортировать уже связанный проект. |
| `GitMerge.mjs:36` (`doGitMergeWithoutLock`) | Загружает состояние в начале синхронизации. |

#### Индексы {#indexes}

| Имя | Ключи | Параметры | Миграция |
| ---- | ---- | ------- | --------- |
| `_id_` | `_id: 1` | | default |

`autoIndex` в Mongoose выключен (`services/web/app/src/infrastructure/Mongoose.mjs:7`), поэтому `unique: true` из схемы на `projectId` ничего не создаёт. Ни одна миграция не создаёт индексы для этой коллекции.

#### Примечания {#notes}

* API GitLab не умеет, как GitHub, переводить ветку на любой коммит. Синхронизация коммитит прямо в синхронизируемую ветку, если может продвинуть её вперёд, а иначе во временную ветку, которая затем сливается через merge request (`GitMerge.mjs:16-21`).
* Синхронизация выполняется под блокировкой проекта `gitSync`, общей с GitHub Sync и Gitea Sync (`GitMerge.mjs:25-32`).
* Удалённый проект сохраняет свой документ, пока не истечёт его срок.
* Токен GitLab пользователя хранится в [GitLab Sync User Credentials](/ru/dev/data-model/gitlab-sync-user-credentials-collection).
