<Accordion title="Migrazione Zotero / Mendeley per le installazioni esistenti">

Quando esegui l'aggiornamento all'immagine 6.3.0 ripubblicata, migra i metadati dei file bibliografici collegati a Zotero/Mendeley esistenti usando lo script seguente. Questa migrazione accompagna la correzione `12031b8dfd`.

Rinomina `zoteroGroupId` / `mendeleyGroupId` in `group_id`, rinomina `importedByUserId` in `importer_id` e rimuove `importedByName`.

Esegui il backup di MongoDB e arresta l'applicazione prima di eseguire la migrazione. Lascia MongoDB in esecuzione. Apri la sua shell (sostituisci `mongo` con il nome del tuo container):

```bash
docker exec -it mongo mongosh
```

Esegui quanto segue in `mongosh` (sostituisci `sharelatex` con il nome del tuo database):

```javascript
use sharelatex

(async () => {
  let updated = 0
  await db.projects.find({}, { rootFolder: 1 }).forEach(async project => {
    const changes = {}
    function visit(folders, path) {
      for (const [i, folder] of (folders || []).entries()) {
        const folderPath = `${path}.${i}`
        for (const [j, file] of (folder.fileRefs || []).entries()) {
          const data = { ...file.linkedFileData }
          if (!["zotero", "mendeley"].includes(data.provider)) continue
          const groupKey = `${data.provider}GroupId`
          if (![groupKey, "importedByUserId", "importedByName"].some(key => key in data)) continue
          for (const [oldKey, newKey] of [[groupKey, "group_id"], ["importedByUserId", "importer_id"]]) {
            if (data[oldKey] != null && data[oldKey] !== "") {
              const value = String(data[oldKey])
              if (newKey in data && data[newKey] !== value) {
                throw new Error(`Conflicting ${newKey}: project ${project._id}, file ${file._id}`)
              }
              data[newKey] = value
            }
            delete data[oldKey]
          }
          delete data.importedByName
          changes[`${folderPath}.fileRefs.${j}.linkedFileData`] = data
        }
        visit(folder.folders, `${folderPath}.folders`)
      }
    }
    visit(project.rootFolder, "rootFolder")
    if (!Object.keys(changes).length) return
    const result = await db.projects.updateOne(
      { _id: project._id, rootFolder: { $eq: project.rootFolder } },
      { $set: changes }
    )
    if (!result.matchedCount) throw new Error(`Project changed during migration: ${project._id}`)
    updated += result.modifiedCount
  })
  print(`Updated ${updated} project(s).`)
})()
```

Lo script include le cartelle annidate e modifica solo i metadati di Zotero/Mendeley. Può essere rieseguito in sicurezza: una migrazione completata riporta `Updated 0 project(s).` all'esecuzione successiva. Se si interrompe con un conflitto, esamina il progetto/file segnalato; i progetti precedenti potrebbero essere già stati migrati.

Avvia l'applicazione aggiornata, ricarica l'editor e aggiorna un file bibliografico esistente come suo importatore originale. Gli snapshot storici non vengono riscritti. Per tornare alla vecchia applicazione, ripristina il backup di MongoDB.

Siamo molto orgogliosi di annunciare il rilascio di Overleaf Pro 6.3.0, l'editor LaTeX online più potente e ricco di funzionalità della community. Poiché ci siamo sempre concentrati sul miglioramento dell'esperienza dei nostri utenti, questa release porta grandi cambiamenti e funzionalità straordinarie che sicuramente apprezzerai, tra cui l'assistente AI e l'integrazione con gestori di riferimenti di terze parti.

### Modifiche

* AI Chat Assistant: chatta con un modello AI tramite il tuo fornitore, direttamente nell'editor.
* LaTeX Error Assistant: ottieni correzioni suggerite dall'AI per gli errori di compilazione LaTeX.
* Integrazione Mendeley: importa riferimenti da Mendeley in modo simile a Zotero.
* Open in Overleaf API: aggiunta un'API per aprire contenuti in Overleaf.
* Template Gallery: aggiunti paginazione, ricerca e ordinamento lato server, così le gallerie di grandi dimensioni non devono più caricare tutti i template nel browser.
* Traduzioni: aggiornate le patch di traduzione per la 6.3.0, inclusi i nuovi testi dell'interfaccia in tutte le lingue supportate.
* Overleaf 6.3.0 upstream: include la modifica dei file a schede, loghi dell'intestazione separati per i temi chiaro e scuro e aggiornamenti delle dipendenze e dell'immagine di base.
* Aggiunte `OVERLEAF_HEADER_IMAGE_URL_LIGHT` e `OVERLEAF_HEADER_IMAGE_URL_DARK` per supportare immagini del logo dell'intestazione separate per i temi chiaro e scuro.
* I file possono ora essere aperti in schede diverse nell'editor.
* Aggiunto il supporto per proxy HTTP(S) configurabili, inclusi proxy ospitati in locale, tramite `OVERLEAF_LINKED_URL_OUTBOUND_PROXY`, usata anche dall'API Open in Overleaf.

#### Funzionalità 04: paginazione dei template

La galleria ora esegue paginazione, ordinamento e ricerca in MongoDB. Funziona senza alcuna preparazione; con migliaia di template puoi comunque aggiungere questi indici per mantenerla veloce (possono essere rieseguiti in sicurezza; `mongo`/`sharelatex` = i nomi del tuo container e del tuo database):

```bash
docker exec mongo mongosh sharelatex --quiet --eval '
db.templates.createIndex({category:1,lastUpdated:-1},{name:"category_1_lastUpdated_-1",background:true});
db.templates.createIndex({lastUpdated:-1},{name:"lastUpdated_-1",background:true});
db.templates.createIndex({category:1,name:1},{name:"category_1_name_1_ci",collation:{locale:"en",strength:2},background:true});
db.templates.createIndex({name:1},{name:"name_1_ci",collation:{locale:"en",strength:2},background:true});
'
```

Mantieni la `collation` sui due indici `*_ci` esattamente come scritta: la galleria esegue le query con la stessa collation e MongoDB usa solo un indice corrispondente.

## Ayakaleaf Pro 6.2.2

**Data di rilascio:** 2026.07.23

Vedi: [https://github.com/ayaka-notes/ayakaleaf-pro/releases/tag/pro-v6.2.2](https://github.com/ayaka-notes/ayakaleaf-pro/releases/tag/pro-v6.2.2)

### Modifiche

Backport delle patch hotfix ufficiali distribuite in Overleaf `6.2.2` upstream (sopra la `6.2.1`):

* Il segreto del token di invito ai progetti non viene più esposto nei log. Il cifratore dei token di invito registrava la propria configurazione a ogni cifratura/decifratura, incluse le password di cifratura derivate da `OVERLEAF_INVITE_TOKEN_SECRET`.
* Migrazione delle email in uscita dal client AWS SES v1, giunto a fine vita, a SESv2. Le istanze configurate con il driver email `ses` potevano non riuscire affatto a inviare email; l'invio ora passa attraverso `SESv2Client`.
* Le voci di gruppo del menu a discesa di condivisione del progetto sono ora subordinate al nuovo feature flag `group-link-sharing`, così la condivisione tramite link di gruppo non viene più proposta nelle istanze in cui non è applicabile.
* Corretta la finestra modale di condivisione del progetto per i collaboratori. Aprendola come non proprietario, o con il flusso `sharing-updates` disabilitato, veniva inviata una richiesta che falliva sempre e mostrava un errore "something went wrong".
* Aggiunto `scripts/flush_docs_with_pending_updates.js` a document-updater, uno script di manutenzione che recupera i documenti rimasti con una coda `PendingUpdates` bloccata in Redis dopo che il loro progetto è stato scaricato (flush) o eliminato definitivamente. Supporta `--dry-run` e un controllo di sicurezza `--estimated-docs`.
* Aggiornamento delle dipendenze: `multer` 2.2.0, `form-data` 2.5.6, `protobufjs` 7.6.3, `@grpc/grpc-js` 1.14.4.

Questa release include anche le seguenti correzioni e miglioramenti di Ayakaleaf Pro:

* Aggiunte traduzioni complete per 16 lingue aggiuntive (cs, da, de, es, fi, fr, it, ja, ko, nl, no, pl, pt, ru, sv, tr), correggendo stringhe non tradotte come quelle della pagina di reimpostazione della password. Risolve [#38](https://github.com/ayaka-notes/ayakaleaf-pro/issues/38).
* Corretto il conteggio degli elementi nel pulsante "show N more projects" del pannello di amministrazione, che mostrava un numero errato perché il segnaposto del plurale non veniva passato correttamente.
* Corretti gli errori di validazione dell'esportazione GitHub, che ora vengono visualizzati tramite chiavi i18n statiche anziché messaggi grezzi, e rimosse le chiavi di errore non più usate dalla finestra modale di GitHub Sync.

## Ayakaleaf Pro 6.2.1

**Data di rilascio:** 2026.07.18

Vedi: [https://github.com/ayaka-notes/ayakaleaf-pro/releases/tag/pro-v6.2.1](https://github.com/ayaka-notes/ayakaleaf-pro/releases/tag/pro-v6.2.1)

### Modifiche

Backport delle patch hotfix ufficiali distribuite in Overleaf `6.2.1` upstream (sopra la `6.2.0`):

* Rafforzato il messaggio in tempo reale `applyOtUpdate` con uno schema di validazione rigoroso anziché accettare qualsiasi oggetto, rifiutando le operazioni di modifica malformate.
* Allentato tale schema rendendo `meta.tc` opzionale, così gli aggiornamenti validi non vengono più rifiutati dalla validazione più rigorosa.
* Corretto l'editor (client ShareJS) in modo che le operazioni che si riducono a un'operazione vuota (annullate da un'operazione remota/concorrente o completamente ripristinate con l'annullamento) vengano scartate anziché inviate al server, e il documento venga correttamente segnalato come salvato. Previene problemi spuri di sincronizzazione / "modifiche non salvate" legati all'annullamento e alla modifica simultanea.

<Warning>

* È stata introdotta una nuova variabile d'ambiente obbligatoria, `OVERLEAF_INVITE_TOKEN_SECRET`. Devi generarla con `openssl rand -base64 32`. Se non è configurata, la tua istanza di Overleaf non si avvierà.

## Ayakaleaf Pro 6.0.0

**Data di rilascio:** 2026.02.17

Release di test, vedi: [https://github.com/ayaka-notes/ayakaleaf-pro/releases/tag/pro-v6.0.0](https://github.com/ayaka-notes/ayakaleaf-pro/releases/tag/pro-v6.0.0)

Questa è una release di test e anche la nostra versione iniziale di Overleaf Pro. Questa versione non contiene alcuna funzionalità di Server Pro, quindi è indicata solo come nostro punto di partenza. Aggiungeremo nuove funzionalità in seguito, come il pannello di amministrazione e git-bridge...

In questa release abbiamo introdotto l'immagine Docker di Overleaf per ARM. Puoi provarla se hai un Mac o un server basato su ARM, ma alcune funzionalità potrebbero non funzionare bene (non ancora testate).

### Immagine Docker

Puoi trovare l'immagine Docker qui: [https://github.com/ayaka-notes/overleaf-pro/pkgs/container/overleaf-pro](https://github.com/ayaka-notes/overleaf-pro/pkgs/container/overleaf-pro)

Per l'immagine multi-architettura, vedi [qui](https://github.com/ayaka-notes/overleaf-pro/pkgs/container/overleaf-pro/691283454?tag=6.0.0).

```bash
docker pull ghcr.io/ayaka-notes/overleaf-pro:6.0.0
```

### Migrazione dei file binari

Questa nuova release dimezza lo spazio di archiviazione utilizzato dai file binari.

Nella versione `5.5` è inclusa una migrazione online, che consente di ridurre al minimo i tempi di inattività durante l'aggiornamento. Prima di eseguire l'aggiornamento a Server Pro `v6`, assicurati di usare già l'ultima versione di Server Pro `v5.5` ([Note di rilascio 5.x.x](https://docs.overleaf.com/on-premises/release-notes/release-notes-5.x.x)) e di aver eseguito la migrazione.

[Consulta le istruzioni complete per la migrazione](https://docs.overleaf.com/on-premises/release-notes/release-notes-5.x.x/binary-files-migration).

### Aggiornamento di MongoDB alla v8

Questa release porta la versione minima di MongoDB a `8.0`.

Se attualmente usi MongoDB `v6` o precedente, dovrai aggiornare una versione principale alla volta (`v6 → v7 → v8`).

<Warning>

Assicurati di avere un backup del [database](https://docs.overleaf.com/on-premises/maintenance/data-and-backups) **prima** di eseguire l'aggiornamento. In caso di rollback, dovrai ripristinare il backup del database.

</Warning>

Per istruzioni su come aggiornare MongoDB `v6 → v7 → v8`, consulta la nostra guida passo passo [qui](https://docs.overleaf.com/on-premises/maintenance/updating-mongodb#example-upgrading-mongodb-from-6.0-to-7.0-toolkit-users).

### Aggiornamento di Redis alla v7.4

Questa release porta anche la versione minima di Redis a `7.4`.

Aggiorna `REDIS_IMAGE` nel tuo `config/overleaf.rc` a `REDIS_IMAGE=7.4`.

### Nuove funzionalità

* La condivisione tramite link può ora essere disabilitata con `OVERLEAF_DISABLE_LINK_SHARING=true`.
* Sono ora disponibili `OVERLEAF_MAINTENANCE_MESSAGE` e `OVERLEAF_MAINTENANCE_MESSAGE_HTML` per personalizzare il titolo e il contenuto della pagina di manutenzione.
* `OVERLEAF_USER_HARD_DELETION_DELAY` e `OVERLEAF_PROJECT_HARD_DELETION_DELAY` possono essere configurate (in millisecondi) per modificare il ritardo di scadenza degli utenti/progetti eliminati (predefinito: 90 giorni).

### Correzioni di bug

* Corretto il rendering del footer con i link.
* Migliorati i messaggi di errore in caso di errori di accesso SAML.
* Corretta la mancata aggiunta di una voce nel registro di audit quando lo stato di amministratore di un utente viene aggiornato all'accesso SSO.
* Corretti gli errori del pannello History quando TLS è abilitato in Redis.
* Le compilazioni possono ora essere interrotte quando si usano compilazioni non in sandbox.

### Altre modifiche

* Tutti i link alla pagina di stato (impostata tramite `OVERLEAF_STATUS_PAGE_URL`) ora usano `HTTPS` e si aprono in una nuova scheda del browser.
