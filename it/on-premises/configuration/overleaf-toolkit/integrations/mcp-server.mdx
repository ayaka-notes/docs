Ogni progetto ha un server MCP, così i client AI come Claude Code, Codex, Cursor, VS Code o Gemini CLI possono lavorarci: leggerne e modificarne i file, compilarlo, leggere il log LaTeX, scaricare il PDF e rispondere ai commenti. Da v6.3.3 possono anche consultare la cronologia e ripristinare versioni, rivedere le modifiche tracciate, aggiungere commenti, usare la chat del progetto e spostare file.

<Info>

Questa funzionalità è sviluppata da [ayaka-notes/ayakaleaf-pro](https://github.com/ayaka-notes/ayakaleaf-pro). È disponibile dalla v6.3.1 in poi. Gli strumenti per cronologia, modifiche tracciate, chat del progetto, nuovi commenti e spostamento di file sono disponibili da v6.3.3, vedi [Novità di v6.3.3](/it/on-premises/user-guide/users/mcp-server#new-in-v6.3.3).

</Info>

### Configurazione {#setup}

Il server MCP è incluso nell'integrazione Git: abilita [git-bridge](/it/on-premises/configuration/overleaf-toolkit/integrations/git-integration) e anche il server MCP sarà disponibile. Non c'è nient'altro da configurare.

### Collegare un client AI {#connect-an-ai-client}

1. In **Impostazioni account**, genera un token di autenticazione Git. Lo stesso token viene usato per il server MCP e per Git.
2. Nell'editor, apri **Integrazioni** e fai clic su **Server MCP**. Viene mostrato l'indirizzo del server MCP del progetto, `https://<your-overleaf>/project/<project_id>/mcp`, e come aggiungerlo a ciascun client AI: copia il comando e sostituisci `<token>` con il tuo token.

Il token viene inviato come header HTTP `Authorization: Bearer <token>`. Ad esempio, il comando per Claude Code è:

```bash
claude mcp add --transport http overleaf \
  https://<your-overleaf>/project/<project_id>/mcp \
  --header "Authorization: Bearer <token>"
```

### Utilizzo {#usage}

Una volta collegato, rivolgiti al client AI con parole semplici. Ad esempio:

| Chiedi | Il client AI usa |
| --- | --- |
| _Correggi i refusi nell'introduzione._ | `read_file`, `edit_file`: le modifiche compaiono in tempo reale nell'editor |
| _Compila il progetto e correggi gli errori LaTeX._ | `compile`, `get_compile_log`, `edit_file` |
| _Rispondi ai commenti aperti, poi risolvili._ | `list_comments`, `reply_to_comment`, `resolve_comment` |
| _Passa a XeLaTeX e scarica il PDF._ | `update_settings`, `compile`, `get_output_file_link` |
| _Riscrivi l'abstract come modifica tracciata._ | `read_file`, `edit_file` con `trackChanges` (v6.3.3) |
| _Che cosa è cambiato rispetto alla versione inviata?_ | `list_versions`, `list_changes`, `diff` (v6.3.3) |
| _Sposta i capitoli in una cartella chiamata chapters._ | `move_file` (v6.3.3) |

### Strumenti {#tools}

| Gruppo | Strumenti |
| --- | --- |
| Progetto | `get_clone_info`, `get_settings`, `update_settings` |
| File | `list_files`, `read_file`, `edit_file`, `write_file`, `delete_file`, `move_file`, `create_folder` |
| Compilazione | `compile`, `get_compile_log`, `get_output_file_link`, `word_count` |
| Commenti | `list_comments`, `reply_to_comment`, `resolve_comment`, `reopen_comment`, `add_comment`, `edit_comment_message`, `delete_comment_message` |
| Modifiche tracciate | `list_tracked_changes`, `accept_tracked_changes`, `reject_tracked_changes` |
| Cronologia | `list_versions`, `list_changes`, `diff`, `create_version`, `delete_version`, `restore_file`, `restore_project` |
| Chat | `list_chat_messages`, `send_chat_message` |

v6.3.3 ha 33 strumenti, o 31 con `OVERLEAF_DISABLE_CHAT=true`, che rimuove gli strumenti della chat. v6.3.1 e v6.3.2 hanno gli altri 17: tutto quanto sopra tranne `move_file`, `create_folder`, `add_comment`, `edit_comment_message`, `delete_comment_message`, gli strumenti delle modifiche tracciate, quelli della chat e quelli della cronologia diversi da `list_versions`. In v6.3.3, `read_file` legge anche un file a una versione della cronologia, `edit_file` e `write_file` accettano `trackChanges`, e `update_settings` imposta anche la lingua del controllo ortografico.

Le modifiche fatte con `edit_file`, `write_file` e `move_file` appaiono in tempo reale nell'editor e si uniscono a quelle dei collaboratori. Per molti file alla volta o file binari, il client IA può anche clonare il progetto con Git ed eseguire il push.

Con `trackChanges`, la modifica di un file esistente è una modifica tracciata dell'utente del token, anche quando il rilevamento delle modifiche è disattivato nel progetto; un nuovo file non lo è mai. Senza `trackChanges`, le modifiche seguono l'impostazione di rilevamento delle modifiche del progetto.

### Permessi {#permissions}

Il server MCP segue le impostazioni di condivisione del progetto, come Git:

* Chiunque possa visualizzare il progetto può leggerlo, compilarlo e scaricarne l'output.
* Solo il proprietario e gli editor possono modificarne file e impostazioni, ripristinare versioni e accettare o rifiutare modifiche tracciate.
* I revisori possono anche aggiungere commenti e rispondere, risolvere, riaprire o eliminare i commenti che hanno avviato, e salvare versioni. Non possono modificare i file, nemmeno come modifiche tracciate.
* Ognuno modifica solo i propri messaggi di commento, e i revisori eliminano solo i propri.
* Solo il proprietario elimina le versioni salvate da altri.
* I lettori entrati tramite link non vedono commenti, modifiche tracciate, cronologia o chat, come nell'editor. I lettori invitati possono vederli e usare la chat.
* Se il proprietario del progetto non ha **Full project history**, gli strumenti della cronologia mostrano solo le modifiche delle ultime 24 ore, come il pannello della cronologia. Gli amministratori le vedono tutte.

La guida utente ha una tabella di ciò che ogni ruolo può fare, vedi [Chi può fare cosa](/it/on-premises/user-guide/users/mcp-server#who-may-do-what).

### Q\&A {#q&a}

<Accordion title="Non vedo Integrations o il server MCP nell'editor">

<strong>Risposta:</strong> Il server MCP non ha una propria variabile d'ambiente. Si abilita con `GIT_BRIDGE_ENABLED=true` in `config/overleaf.rc`, vedi [Integrazione Git](/it/on-premises/configuration/overleaf-toolkit/integrations/git-integration). Dopo averla modificata, esegui `bin/up -d`. Senza il git-bridge, l'editor non mostra la scheda **Integrations** nella barra laterale sinistra.

</Accordion>

<Accordion title="Il client IA dice «Track changes is off for this project»">

<strong>Risposta:</strong> Il client ha chiesto una modifica tracciata, ma l'account del proprietario del progetto non ha il rilevamento delle modifiche. Fai clic su **Admin**, poi su **Manage Users**, apri il proprietario e nella scheda **Features** attiva **Track changes**, vedi [Features](/it/on-premises/user-guide/administrators/user-management#features). Le modifiche senza `trackChanges` funzionano comunque.

</Accordion>

<Accordion title="Il client IA vede solo le modifiche delle ultime 24 ore">

<strong>Risposta:</strong> L'account del proprietario del progetto non ha la cronologia completa del progetto, quindi gli strumenti della cronologia mostrano ciò che mostra il pannello della cronologia: le modifiche delle ultime 24 ore. Fai clic su **Admin**, poi su **Manage Users**, apri il proprietario e nella scheda **Features** attiva **Full project history**, vedi [Features](/it/on-premises/user-guide/administrators/user-management#features).

</Accordion>
