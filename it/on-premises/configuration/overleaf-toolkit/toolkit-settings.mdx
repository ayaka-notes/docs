Questa pagina descrive le variabili d'ambiente supportate nel file `config/overleaf.rc` per le installazioni basate sul Toolkit.

Il file `config/overleaf.rc` è composto da definizioni di variabili nella forma `NAME=value`. Le righe che iniziano con `#` vengono trattate come commenti.

<Info>

Dopo aver modificato qualsiasi cosa in `overleaf.rc` o `variables.env` è necessario ricreare i container Docker eseguendo `bin/up`.

</Info>

## Container

### `sharelatex`

| Nome                         | Descrizione |
| ---------------------------- | ----------- |
| `PROJECT_NAME`               | <p>Imposta il valore del flag `--project-name` passato a `docker-compose`. È utile quando si eseguono più istanze di Overleaf su un unico host, poiché ogni istanza può avere un nome di progetto diverso.<br /><br />- <strong>Predefinito</strong>: `overleaf`</p> |
| `OVERLEAF_IMAGE_NAME`        | <p>Immagine Docker usata dal container dell'applicazione Server Pro/CE. Si tratta solo del nome dell'immagine Docker; il tag dell'immagine Docker viene letto da `config/version`.<br /><br />- <strong>Predefinito:</strong><br />- Server Pro: `ghcr.io/ayaka-notes/overleaf-pro`<br />- Community Edition: `sharelatex/sharelatex`</p> |
| `SERVER_PRO`                 | <p>Se impostato su `true`, indica al Toolkit di usare l'immagine Server Pro (`ghcr.io/ayaka-notes/overleaf-pro`) invece dell'immagine predefinita Server CE (`sharelatex/sharelatex`).<br /><br />- <strong>Predefinito</strong>: `false`</p> |
| `GIT_BRIDGE_ENABLED`         | <p>Imposta su `true` per abilitare la funzionalità git-bridge (solo Server Pro). Per maggiori informazioni consulta la documentazione utente <a href="https://www.overleaf.com/learn/how-to/Git_integration">https://www.overleaf.com/learn/how-to/Git_integration</a>.<br /><br />- <strong>Predefinito:</strong> `false`</p> |
| `GIT_BRIDGE_IMAGE`           | <p>Immagine Docker usata dal container git-bridge (solo Server Pro). Si tratta solo del nome dell'immagine Docker; il tag dell'immagine Docker viene letto da `config/version`.<br /><br />- <strong>Predefinito:</strong> `ghcr.io/ayaka-notes/overleaf-pro/git-bridge`</p> |
| `GIT_BRIDGE_DATA_PATH`       | Imposta il percorso della directory che verrà montata nel container `git-bridge` (solo Server Pro) e usata per memorizzare i repository git. Può essere un percorso completo (che inizia con `/`) oppure relativo alla directory di base del Toolkit. |
| `GIT_BRIDGE_LOG_LEVEL`       | <p>Configura il livello di log del container `git-bridge`. Livelli disponibili: `TRACE`, `DEBUG`, `INFO`, `WARN`, `ERROR`.<br /><br />- <strong>Predefinito:</strong> `INFO`</p> |
| `SIBLING_CONTAINERS_ENABLED` | <p>Se impostato su `true`, indica al Toolkit di usare la tecnica dei <strong>Sibling Containers</strong> per compilare i progetti in sandbox separate, usando un container Docker distinto per ogni progetto. Per maggiori informazioni consulta la documentazione &#x3C;server-pro-only-configuration/sandboxed-compiles>.<br /><br />- <strong>Richiede:</strong> `SERVER_PRO=true`<br />- <strong>Predefinito:</strong> `true`</p> |
| `SIBLING_CONTAINERS_PULL`    | <p>Se impostato su `true`, indica al Toolkit di scaricare automaticamente, quando si usa il comando `bin/up`, tutte le immagini TeX Live impostate tramite `ALL_TEX_LIVE_DOCKER_IMAGES` nel file <strong>config/variables.env</strong>.<br /><br />- <strong>Predefinito:</strong> `true`</p> |
| `DOCKER_SOCKET_PATH`         | <p>Imposta il percorso del socket Docker sulla macchina host (la macchina che esegue il Toolkit). Quando `SIBLING_CONTAINERS_ENABLED` è `true`, il socket viene montato nel container per consentire al servizio di compilazione di avviare nuovi container Docker sull'host.<br /><br />- <strong>Richiede:</strong> `SIBLING_CONTAINERS_ENABLED=true`<br />- <strong>Predefinito:</strong> `/var/run/docker.sock`</p> |
| `OVERLEAF_DATA_PATH`         | <p>Imposta il percorso della directory che verrà montata nel container principale `sharelatex` e usata per memorizzare i dati di compilazione. Può essere un percorso completo (che inizia con `/`) oppure relativo alla directory di base del Toolkit.<br /><br />- <strong>Predefinito:</strong> `data/overleaf`</p> |
| `OVERLEAF_LISTEN_IP`         | <p>Imposta l'indirizzo o gli indirizzi IP dell'host a cui il container si collegherà. Ad esempio, se è impostato su `0.0.0.0`, l'interfaccia web sarà disponibile su qualsiasi indirizzo IP dell'host. Per l'accesso diretto al container, il valore di `OVERLEAF_LISTEN_IP` deve essere impostato sul tuo indirizzo IP pubblico. Impostare `OVERLEAF_LISTEN_IP` su `0.0.0.0` o sull'IP esterno dell'host causa in genere errori se usato insieme al .<br /><br />- <strong>Predefinito:</strong> `127.0.0.1`</p> |
| `OVERLEAF_PORT`              | <p>Imposta la porta dell'host a cui il container si collegherà. Ad esempio, se è impostata su `8099` e `OVERLEAF_LISTEN_IP` è impostato su `127.0.0.1`, l'interfaccia web sarà disponibile su `http://localhost:8099`.<br /><br />- <strong>Predefinito:</strong> `80`</p> |
| `OVERLEAF_LOG_PATH`          | <p>Imposta il percorso della directory che verrà montata nel container principale `sharelatex` e usata per rendere disponibili i log dell'applicazione sull'host Docker. Può essere un percorso completo (che inizia con `/`) oppure relativo alla directory di base del Toolkit. Rimuovi la voce di configurazione per disabilitare il bind mount. Se non è impostato, i log verranno eliminati quando il container viene ricreato.<br /><br />Vedi per informazioni sui log.<br /><br />- <strong>Predefinito:</strong> non impostato</p> |

### `mongo`

| Nome              | Descrizione |
| ----------------- | ----------- |
| `MONGO_ENABLED`   | <p>Se impostato su `true`, indica al Toolkit di creare un container MongoDB che ospiti il database. Se impostato su `false`, questo container non verrà creato e il sistema userà invece il database MongoDB specificato da `MONGO_URL`.<br /><br />- <strong>Predefinito</strong>: `true`</p> |
| `MONGO_URL`       | <p>Specifica l'URL di connessione MongoDB da usare quando `MONGO_ENABLED` è `false`.<br /><br />- <strong>Predefinito</strong>: non impostato</p> |
| `MONGO_DATA_PATH` | <p>Imposta il percorso della directory che verrà montata nel container `mongo` e usata per memorizzare il database MongoDB. Può essere un percorso completo (che inizia con `/`) oppure relativo alla directory di base del Toolkit. Questa opzione riguarda solo il container `mongo` locale creato quando `MONGO_ENABLED` è `true`.<br /><br />- <strong>Predefinito</strong>: `data/mongo`</p> |
| `MONGO_IMAGE`     | <p>Immagine Docker usata dal container MongoDB. Si tratta solo del nome dell'immagine Docker; il tag dell'immagine Docker va inserito in `MONGO_VERSION` (vedi sotto).<br /><br />- <strong>Predefinito:</strong> `mongo`</p> |
| `MONGO_VERSION`   | <p>Versione di MongoDB usata dal container MongoDB. Il valore deve iniziare con la versione principale di MongoDB seguita da un punto, ad es. `6.0` o `6.0-with-suffix`.<br /><br />- <strong>Predefinito:</strong> `6.0`</p> |

### `redis`

| Nome                    | Descrizione |
| ----------------------- | ----------- |
| `REDIS_ENABLED`         | <p>Se impostato su `true`, indica al Toolkit di creare un container Redis che ospiti il database Redis. Se impostato su `false`, questo container non verrà creato e il sistema userà invece il database Redis specificato da `REDIS_HOST` e `REDIS_PORT`.<br /><br />- <strong>Predefinito</strong>: `true`</p> |
| `REDIS_HOST`            | <p>Specifica l'host Redis da usare quando `REDIS_ENABLED` è `false`.<br /><br />- <strong>Predefinito</strong>: non impostato</p> |
| `REDIS_PORT`            | <p>Specifica la porta Redis da usare quando `REDIS_ENABLED` è `false`.<br /><br />- <strong>Predefinito</strong>: non impostato</p> |
| `REDIS_DATA_PATH`       | <p>Imposta il percorso della directory che verrà montata nel container `redis` e usata per memorizzare il database Redis. Può essere un percorso completo (che inizia con `/`) oppure relativo alla directory di base del Toolkit. Questa opzione riguarda solo il container `redis` locale creato quando `REDIS_ENABLED` è `true`.<br /><br />- <strong>Predefinito</strong>: `data/redis`</p> |
| `REDIS_AOF_PERSISTENCE` | <p>Attiva la persistenza AOF (Append Only File) per Redis. È la configurazione <strong>consigliata</strong> per la persistenza di Redis.<br /><br />Per ulteriori dettagli, consulta la sezione &#x3C;../../../maintenance/data-and-backups#aof-append-only-file> in &#x3C;../../maintenance/data-and-backups>.<br /><br />- <strong>Predefinito:</strong> `true`</p> |

### `nginx`

| Nome                   | Descrizione |
| ---------------------- | ----------- |
| `NGINX_ENABLED`        | <p>Se impostato su `true`, indica al Toolkit di creare un container NGINX che funga da proxy TLS.<br /><br />- <strong>Predefinito</strong>: `false`</p> |
| `NGINX_CONFIG_PATH`    | <p>Percorso del file di configurazione NGINX da usare per il proxy TLS.<br /><br />- <strong>Predefinito</strong>: `config/nginx/nginx.conf`</p> |
| `NGINX_TLS_LISTEN_IP`  | <p>Imposta l'indirizzo o gli indirizzi IP dell'host a cui il container del proxy TLS si collegherà per HTTPS. Ad esempio, se è impostato su `0.0.0.0`, l'interfaccia web HTTPS sarà disponibile su qualsiasi indirizzo IP dell'host. In genere dovrebbe essere impostato sull'IP esterno del tuo host.<br /><br />- <strong>Predefinito</strong>: `127.0.1.1`</p> |
| `NGINX_HTTP_LISTEN_IP` | <p>Imposta l'indirizzo o gli indirizzi IP dell'host a cui il container del proxy TLS si collegherà per il reindirizzamento HTTP. Ad esempio, se è impostato su `127.0.1.1`, le connessioni HTTP a `127.0.1.1` verranno reindirizzate all'interfaccia web HTTPS. In genere dovrebbe essere impostato sull'IP esterno del tuo host. Non impostarlo su `0.0.0.0`, perché in genere causa un conflitto con `OVERLEAF_LISTEN_IP`.<br /><br />- <strong>Predefinito</strong>: `127.0.1.1`</p> |
| `NGINX_HTTP_PORT`      | <p>Imposta la porta dell'host a cui il container del proxy TLS si collegherà per HTTP.<br /><br />- <strong>Predefinito</strong>: `80`</p> |
| `TLS_PORT`             | <p>Imposta la porta dell'host a cui il container del proxy TLS si collegherà per HTTPS.<br /><br />- <strong>Predefinito</strong>: `443`</p> |
| `TLS_PRIVATE_KEY_PATH` | <p>Percorso della chiave privata da usare per il proxy TLS.<br /><br />- <strong>Predefinito</strong>: `config/nginx/certs/overleaf_key.pem`</p> |
| `TLS_CERTIFICATE_PATH` | <p>Percorso del certificato pubblico da usare per il proxy TLS.<br /><br />- <strong>Predefinito</strong>: `config/nginx/certs/overleaf_certificate.pem`</p> |
