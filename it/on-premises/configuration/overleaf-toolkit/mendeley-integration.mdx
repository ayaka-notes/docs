<Info>

Questa funzionalità è fornita da [ayaka-notes/ayakaleaf-pro](https://github.com/ayaka-notes/overleaf-pro) con supporto OAuth 2.0 ed è disponibile a partire dalla v6.3.0. Se riscontri problemi, il tuo feedback è benvenuto.

</Info>

#### Configurare l'integrazione con Mendeley

1. Vai a [questo link](https://dev.mendeley.com/myapps.html) per registrare un'applicazione OAuth Mendeley
2. Configura il **Redirect URL** come: `${OVERLEAF_SITE_URL}/user/mendeley/oauth/callback`
3. Annota l'**ID** generato (di solito numerico, come `24061` qui sotto) e il **Secret** della tua applicazione
4. Modifica il tuo `config/variables.env`&#x20;
5. Mantieni semplicemente l'Authorisation Flow: Elsevier (come consigliato)

</Frame>

```dotenv title="config/variables.env"
#################
#   Mendeley    #
#################
# 'mendeley' must be in ENABLED_LINKED_FILE_TYPES (keep 'zotero' too if you use both)
ENABLED_LINKED_FILE_TYPES=project_file,project_output_file,url,mendeley

# From a Mendeley OAuth application (register at https://dev.mendeley.com/myapps.html)
# Redirect URL -> ${OVERLEAF_SITE_URL}/user/mendeley/oauth/callback
MENDELEY_CLIENT_ID=
MENDELEY_CLIENT_SECRET=
# Encrypts the Mendeley OAuth tokens in mongo; if unset, a key file is generated
# in /var/lib/overleaf/data on first use
# How to generate: `openssl rand -hex 32`
MENDELEY_CIPHER_PASSWORD=
# Optional: route the module's server-side Mendeley requests (OAuth + API) through
# an HTTP proxy (must be reachable from the web container; same as github-sync)
# http://10.0.0.1:10808
# (Optional) MENDELEY_PROXY_URL=
```

<Info>

&#x20;`mendeley` deve essere incluso in `ENABLED_LINKED_FILE_TYPES` (mantieni anche `zotero` nell'elenco se usi entrambi). `MENDELEY_CLIENT_ID` e `MENDELEY_CLIENT_SECRET` provengono dalla tua applicazione OAuth registrata. La cipher password cifra i token OAuth di Mendeley in MongoDB (generane una con `openssl rand -hex 32`); senza di essa, al primo utilizzo viene generato un file di chiave nel volume dei dati. Facoltativamente, imposta `MENDELEY_PROXY_URL` per instradare le richieste Mendeley lato server (OAuth + API) attraverso un proxy HTTP raggiungibile dal container web.

</Info>

### Note

<Warning>

Quando aggiorni un'installazione esistente con file bibliografici collegati a Mendeley alla 6.3.0 ripubblicata, segui le [istruzioni di migrazione per Zotero / Mendeley](/it/on-premises/release-notes/release-notes-6.x.x#ayakaleaf-pro-6.3.0  "mention"). Le nuove installazioni non necessitano di questa migrazione.

</Warning>

<Danger>

Poiché Ayakaleaf è una piattaforma collaborativa, per migliorare la sicurezza, a partire dalla versione 6.3.0 solo il creatore originale di un file `bib` di riferimenti potrà aggiornare il file importato.

</Danger>

Ad esempio, supponiamo che il proprietario del progetto, l'utente A, abiliti la condivisione tramite link e crei nel progetto un file `test.bib` collegandolo al proprio account Zotero. Se un altro utente, l'utente B, accede al progetto tramite il link condiviso, potrà comunque leggere e scaricare `test.bib`, ma non potrà aggiornare o reimportare il file da Zotero. Solo l'utente A, in quanto creatore originale del file di riferimenti, può effettuare gli aggiornamenti. In altre parole, solo il creatore originale del file `.bib` ha il permesso di aggiornarlo.
