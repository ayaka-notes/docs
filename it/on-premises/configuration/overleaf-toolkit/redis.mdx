### Abilitare l'autenticazione con password

Se usi un servizio Redis esterno e devi fornire una password, puoi farlo impostando le variabili d'ambiente `OVERLEAF_REDIS_PASS` e `REDIS_PASSWORD` nel file **config/variables.env** ed eseguendo il comando `bin/up -d` per ricreare il container **sharelatex**.

Se esegui un'istanza locale di Redis, dovrai configurare il servizio **redis** in modo che si avvii con l'autenticazione tramite password. Dopo aver impostato le variabili d'ambiente indicate sopra, dovrai completare anche questi passaggi aggiuntivi:

Crea un file **docker-compose.override.yml** nella directory <strong>config/</strong> con il seguente contenuto:

```yaml title="config/docker-compose.override.yml"
services:
    redis:
        command: "redis-server --requirepass <YOUR-PASSWORD>"
```

<Warning>

Se hai abilitato la persistenza AOF, dovrai aggiungere `--appendonly yes` al `command`.

</Warning>

Esegui `bin/up -d` per ricreare i container.

### Abilitare la persistenza Append-Only File

(Originale: https://docs.overleaf.com/on-premises/configuration/overleaf-toolkit/redis#enabling-append-only-file-persistence)

La persistenza AOF (Append-Only File) di Redis offre un modo affidabile per garantire la durabilità dei dati, registrando ogni operazione di scrittura ricevuta dal server. A differenza degli snapshot RDB, che acquisiscono copie del dataset in un determinato momento, AOF mantiene un registro completo di tutte le modifiche apportate ai dati.

<Info>

Disabilitare RDB è facoltativo. In genere si consiglia di usare entrambi i metodi di persistenza insieme. Prima di apportare modifiche in produzione, valuta i vantaggi e gli svantaggi dell'uso combinato di AOF e RDB.

</Info>

Puoi leggere di più sull'abilitazione della persistenza AOF in Redis qui: [https://redis.io/docs/latest/operate/oss\_and\_stack/management/persistence/#how-i-can-switch-to-aof-if-im-currently-using-dumprdb-snapshotsarrow-up-right](https://redis.io/docs/latest/operate/oss_and_stack/management/persistence/#how-i-can-switch-to-aof-if-im-currently-using-dumprdb-snapshotsarrow-up-right)

1. Pianifica una finestra di manutenzione per l'aggiornamento.
2. Arresta l'istanza con `bin/stop` ed esegui un backup delle cartelle <strong>config/</strong> e <strong>data/</strong>.
3. Esegui `bin/up` per avviare l'istanza
4. Esegui il comando `docker exec -it redis sh`
5. Esegui il comando `redis-cli` per aprire l'interfaccia a riga di comando di Redis
6. Nella redis-cli, esegui il comando `config set appendonly yes`
7. Ora devi attendere che la riscrittura AOF termini la persistenza dei dati. Per farlo, digita `INFO persistence` nella redis-cli e attendi che `aof_rewrite_in_progress` e `aof_rewrite_scheduled` siano `0`, verificando che `aof_last_bgrewrite_status` sia `ok`.
8. Esci dalla redis-cli digitando `exit` e premendo Invio
9. Esci dal container redis digitando `exit` e premendo Invio
10. Esegui il comando `ls ./data/redis` e verifica che sia presente il file **appendonly.aof**
11. Modifica il file **config/overleaf.rc** e cambia la variabile d'ambiente `REDIS_AOF_PERSISTENCE` da `false` a `true`
12. Esegui `bin/up -d` e assicurati che l'applicazione funzioni (l'editor dei progetti e il pannello della cronologia sono operativi).
