### Configurazione i18n di Overleaf

<Info>

Questo documento descrive come configurare l'internazionalizzazione (i18n) per un'istanza self-hosted di **Overleaf**.

</Info>

Overleaf è stato tradotto in diverse lingue. Con la configurazione appropriata puoi:

* Eseguire la tua istanza di Overleaf in **un'unica lingua fissa**, oppure
* Abilitare **più lingue**, consentendo agli utenti di cambiare lingua dinamicamente, in modo simile a `www.overleaf.com`.

***

#### Configurazione a lingua singola

La lingua del sito si configura tramite la variabile d'ambiente `OVERLEAF_SITE_LANGUAGE`.

I codici lingua supportati includono:

* `en` - Inglese (predefinito)
* `es` - Spagnolo
* `pt` - Portoghese
* `de` - Tedesco
* `fr` - Francese
* `cs` - Ceco
* `nl` - Olandese
* `sv` - Svedese
* `it` - Italiano
* `tr` - Turco
* `zh-CN` - Cinese (semplificato)
* `no` - Norvegese
* `da` - Danese
* `ru` - Russo
* `ko` - Coreano
* `ja` - Giapponese
* `pl` - Polacco
* `fi` - Finlandese

L'inglese è la lingua predefinita. Per cambiare la lingua dell'interfaccia (ad esempio in cinese semplificato), aggiungi la seguente riga a `config/variables.env`:

```bash title="config/variables.env"
OVERLEAF_SITE_LANGUAGE=zh-CN
```

Quindi applica la configurazione:

```bash
bin/up
```

Dopo il riavvio dei servizi, la lingua dei menu dell'interfaccia web dovrebbe riflettere la nuova impostazione.

#### Configurazione multilingua

Per consentire agli utenti di **cambiare lingua senza disconnettersi**, la tua istanza di Overleaf deve essere configurata per servire lingue diverse in base ai nomi di dominio.

Questa sezione presuppone che:

* Il tuo dominio principale sia `overleaftest.com`
* Tu disponga di un **certificato TLS wildcard** (ad es. `*.overleaftest.com`)
* Tu **non stia usando `localhost`** (poiché non supporta l'instradamento della lingua basato su sottodomini)

Per i test in locale puoi usare un dominio come `dev-overleaf.com`.

<Steps>
<Step title="Configurazione del proxy TLS (Nginx)">
Il tuo reverse proxy TLS deve inoltrare l'header `Host` originale, in modo che Overleaf possa determinare a quale dominio di lingua ha avuto accesso l'utente.

Assicurati che sia presente la seguente direttiva:

```nginx
proxy_set_header Host $host;
```

Ecco un esempio di configurazione Nginx:

```nginx
server {
    listen 443 ssl;
    server_name    _; # Catch all, see http://nginx.org/en/docs/http/server_names.html
    server_name *.overleaftest.com;
    ssl_certificate /etc/nginx/ssl/nginx.crt;
    ssl_certificate_key /etc/nginx/ssl/nginx.key;
    ssl_protocols               TLSv1 TLSv1.1 TLSv1.2;
    ssl_prefer_server_ciphers   on;
    # used cloudflares ciphers https://github.com/cloudflare/sslconfig/blob/master/conf
    ssl_ciphers EECDH+CHACHA20:EECDH+AES128:RSA+AES128:EECDH+AES256:RSA+AES256:EECDH+3DES:RSA+3DES:!MD5;

    # config to enable HSTS(HTTP Strict Transport Security) https://developer.mozilla.org/en-US/docs/Security/HTTP_Strict_Transport_Security
    # to avoid ssl stripping https://en.wikipedia.org/wiki/SSL_stripping#SSL_stripping	
    add_header Strict-Transport-Security "max-age=31536000; includeSubdomains;";
    server_tokens off;
    add_header X-Frame-Options SAMEORIGIN;
    add_header X-Content-Type-Options nosniff;
    client_max_body_size 50M;

    location / {
        proxy_pass http://localhost:5000; # change to whatever host/port the docker container is listening on.
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_read_timeout 3m;
        proxy_send_timeout 3m;
        
        # add this to your nginx conf
        proxy_set_header Host $host;
    }
}
```
</Step>

<Step title="Configurare il dominio dei cookie">
Per evitare che gli utenti vengano disconnessi quando cambiano lingua, i cookie devono essere condivisi tra i sottodomini delle lingue.

Aggiungi la seguente riga a `config/variables.env`:

```env title="config/variables.env"
# Note the leading dot
COOKIE_DOMAIN=.overleaftest.com
```

In questo modo i cookie di autenticazione sono validi per tutti i sottodomini di `overleaftest.com`.
</Step>

<Step title="Mappatura lingua–dominio">
Successivamente, definisci come i codici lingua vengono associati ai sottodomini usando\
`OVERLEAF_LANG_DOMAIN_MAPPING`.

#### Esempio di configurazione

```dotenv title="config/variables.env" wrap
OVERLEAF_LANG_DOMAIN_MAPPING='{"www": {"lngCode": "en","url": "https:\/\/www.overleaftest.com"},"cn": {"lngCode": "zh-CN","url": "https:\/\/cn.overleaftest.com"}}'
```

Con questa configurazione:

* `https://www.overleaftest.com` → interfaccia in inglese
* `https://cn.overleaftest.com` → interfaccia in cinese semplificato

Puoi estendere questa mappatura con altre lingue e sottodomini secondo necessità.

<Warning>

Consigliamo di servire il sito principale su `www` e di includere sempre una chiave `www`: imposta `OVERLEAF_SITE_URL` sull'indirizzo `www` (ad esempio `https://www.overleaftest.com`), fai puntare a esso la chiave `www` e reindirizza a esso il dominio apex come mostrato di seguito. La chiave `www` rappresenta il sito principale e può usare qualsiasi lingua. Senza di essa resta la voce `www` predefinita, e il selettore della lingua mostra una voce inglese in più che rimanda a `http://127.0.0.1:3000`.

</Warning>
</Step>

<Step title="Reindirizzare il dominio apex">
Infine, reindirizza il dominio apex (`overleaftest.com`) al dominio della lingua predefinita (`www.overleaftest.com`).

```nginx
server{
    listen 80;
    server_name overleaftest.com;
    return 301 https://www.overleaftest.com$request_uri;
}

server {
    listen 443 ssl http2;
    server_name overleaftest.com;
    ssl_certificate     /path/to/fullchain.cer;
    ssl_certificate_key /path/to/overleaftest.com.key;
    return 301 https://www.overleaftest.com$request_uri;
}
```
</Step>
</Steps>

### Q\&A

<Accordion title="Dov'è il pulsante per cambiare lingua?">

<strong>Risposta:</strong> Il pulsante della lingua (icona di traduzione) si trova nel piè di pagina, ad esempio in fondo all'elenco dei progetti. Non viene mostrato nell'editor.

Il pulsante compare solo quando `OVERLEAF_LANG_DOMAIN_MAPPING` mappa due o più lingue, come descritto in [Configurazione multilingua](/it/on-premises/configuration/overleaf-toolkit/localization#configurazione-multilingua). Se è impostata solo `OVERLEAF_SITE_LANGUAGE`, l'intero sito usa quell'unica lingua e il pulsante non è presente.

La scelta di una lingua apre la stessa pagina sul dominio di quella lingua, ad esempio `cn.overleaftest.com`. Non viene salvata come impostazione dell'utente.

</Accordion>

<Accordion title="Perché una lingua nel selettore apre `http://127.0.0.1:3000`?">

<strong>Risposta:</strong> `OVERLEAF_LANG_DOMAIN_MAPPING` non ha una chiave `www`. La mappatura viene unita a quella predefinita, che contiene una voce `www` per l'inglese con l'indirizzo interno `http://127.0.0.1:3000`. Se la tua mappatura usa solo altre chiavi, come `cn` ed `en`, quella voce predefinita viene mantenuta e compare nel selettore.

Aggiungi una chiave `www` con l'indirizzo di `OVERLEAF_SITE_URL` e rimuovi un'eventuale seconda voce per la stessa lingua, quindi esegui `bin/up -d`:

```dotenv
OVERLEAF_LANG_DOMAIN_MAPPING='{"www":{"lngCode":"en","url":"https://www.overleaftest.com"},"cn":{"lngCode":"zh-CN","url":"https://cn.overleaftest.com"}}'
```

</Accordion>
