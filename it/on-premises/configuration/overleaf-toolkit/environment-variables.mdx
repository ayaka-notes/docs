Questa pagina descrive le variabili d'ambiente supportate nel file `config/variables.env` per le distribuzioni basate sul Toolkit.

Il file `config/variables.env` è composto da definizioni di variabili nella forma `NAME=value`; le righe che iniziano con `#` vengono trattate come commenti.

<Info>

Dopo aver modificato qualsiasi elemento in `overleaf.rc` o `variables.env`, è necessario ricreare i container Docker eseguendo `bin/up`.

</Info>

### Tutte le versioni

Queste variabili d'ambiente sono compatibili con Server CE e Server Pro e offrono un percorso di migrazione semplice tra queste due versioni on-premises. Possono inoltre essere usate sia con le distribuzioni basate sul Toolkit sia con quelle basate su Docker Compose.

<Info>

In precedenza, queste variabili d'ambiente avevano il prefisso `SHARELATEX_` anziché `OVERLEAF_`.

</Info>

| Nome | Descrizione |
| ---------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `OVERLEAF_SITE_URL` | L'indirizzo a cui la tua istanza di Overleaf è pubblicamente raggiungibile. Viene usato nei link pubblici e nelle connessioni tramite websocket, quindi deve essere configurato correttamente! |
| `OVERLEAF_ADMIN_EMAIL` | L'indirizzo email tramite cui gli utenti possono contattare la persona che gestisce il sito. |
| `OVERLEAF_APP_NAME` | Il nome da mostrare quando si fa riferimento all'applicazione in esecuzione. Il valore predefinito è 'Overleaf (Community Edition)'. |
| `OVERLEAF_MONGO_URL` e `MONGO_URL` | L'URL del database Mongo da usare. |
| `OVERLEAF_REDIS_HOST` e `REDIS_HOST` | Il nome host dell'istanza Redis da usare. Sono obbligatorie entrambe (consulta le [note di rilascio](/it/on-premises/release-notes)). |
| `OVERLEAF_REDIS_PORT` e `REDIS_PORT` | La porta dell'istanza Redis da usare. Sono obbligatorie entrambe (consulta le [note di rilascio](/it/on-premises/release-notes)). |
| `OVERLEAF_REDIS_PASS` e `REDIS_PASSWORD` | La password da usare per connettersi a Redis (se applicabile). Devono essere impostate **entrambe** le variabili d'ambiente. Per maggiori informazioni consulta [abilitare l'autenticazione con password](/it/on-premises/configuration/overleaf-toolkit/redis#enabling-password-authentication). |
| `OVERLEAF_REDIS_TLS` | <p>Se impostata a `true`, consente la connessione a un'istanza Redis che richiede TLS.<br /><br /><strong>Nota:</strong> al momento mTLS non è supportato.</p> |
| `OVERLEAF_NAV_TITLE` | Imposta il titolo della scheda dell'applicazione. |
| `OVERLEAF_HEADER_IMAGE_URL_LIGHT` e `OVERLEAF_HEADER_IMAGE_URL_DARK` | URL dei loghi personalizzati dell'intestazione per i temi chiaro e scuro (aggiunte nella 6.3.0). Ogni tema ricorre a `OVERLEAF_HEADER_IMAGE_URL` quando la variabile specifica non è impostata. Consulta [Branding](/it/on-premises/configuration/overleaf-toolkit/branding  "mention"). |
| `OVERLEAF_LINKED_URL_OUTBOUND_PROXY` | URL di un proxy HTTP(S) per recuperare i file collegati esterni e le risorse ZIP o TeX esterne tramite l'API Open in Overleaf. Disponibile a partire dalla nuova release di Ayakaleaf Pro `6.3.0` (3 ottobre 2026). Lasciala non impostata per connetterti direttamente. Esempio: `OVERLEAF_LINKED_URL_OUTBOUND_PROXY=http://proxy.internal:3128`. Consulta [Outbound Proxy](/it/on-premises/configuration/overleaf-toolkit/external-url#outbound-proxy  "mention") per la configurazione e le restrizioni di accesso alla rete. |
| `OVERLEAF_INVITE_TOKEN_SECRET` | <p><strong>Obbligatoria</strong>. Una stringa casuale usata per proteggere i token di condivisione dei progetti (aggiunta in Server Pro 6.2.0).</p><p><strong>Numero minimo di caratteri:</strong> 16</p> |
| `OVERLEAF_SESSION_SECRET` | Una stringa casuale usata per proteggere i token; in caso di bilanciamento del carico deve essere impostata sullo stesso valore su tutte le macchine. Se viene eseguita una sola istanza, l'utente non deve impostarla. |
| `OVERLEAF_COOKIE_SESSION_LENGTH` | Consente di sovrascrivere la durata predefinita del cookie di sessione, pari a 5 giorni. Il valore deve essere espresso in millisecondi. Esempio: per far durare la sessione 1 ora, imposta `COOKIE_SESSION_LENGTH=3600000`. (Aggiunta in Server Pro 4.2) |
| `OVERLEAF_TRUSTED_PROXY_IPS` | <p>Se non è impostata, il valore predefinito è `loopback`. Se la imposti manualmente, oltre ai tuoi IP attendibili devi includere anche `loopback` (o `127.0.0.1`), che rende attendibile l'istanza nginx in esecuzione all'interno del container <strong>sharelatex</strong>. Sono accettati solo indirizzi IP e intervalli CIDR: non aggiungere nomi host come `localhost`, altrimenti Overleaf non si avvia e restituisce `502 Bad Gateway`.<br /><br />Se per la tua rete abituale usi una subnet di `172.16.0.0/12` (la subnet predefinita delle reti Docker), imposta `OVERLEAF_TRUSTED_PROXY_IPS=loopback,<network>` nel tuo `config/variables.env`, dove `<network>` è il valore `IPAM -> Config -> Subnet` restituito da `docker inspect overleaf_default`, ad es. `OVERLEAF_TRUSTED_PROXY_IPS=loopback,172.19.0.0/16`. Questo serve a prevenire la falsificazione degli header `X-Forwarded`.<br /><br />Se usi un proxy TLS esterno (cioè non gestito dall'Overleaf Toolkit), assicurati che `OVERLEAF_TRUSTED_PROXY_IPS=loopback,<ip-of-your-tls-proxy>`, ad es. `OVERLEAF_TRUSTED_PROXY_IPS=loopback,192.168.13.37`.</p> |
| `OVERLEAF_RESTRICT_INVITES_TO_EXISTING_ACCOUNTS` | Se impostata a `true`, limita gli inviti ai progetti agli indirizzi email che corrispondono ad account utente esistenti. |
| `OVERLEAF_ALLOW_PUBLIC_ACCESS` | Se impostata a `true`, consente agli utenti non autenticati di visualizzare il sito. Il valore predefinito è `false`, il che significa che gli utenti non autenticati vengono reindirizzati incondizionatamente alla pagina di login quando provano a visualizzare qualsiasi parte del sito. Nota: impostare questa opzione non disabilita in alcun modo l'autenticazione o la sicurezza. Questa opzione è necessaria se i tuoi utenti intendono rendere pubblici i propri progetti e consentirne la visualizzazione a utenti non autenticati. |
| `OVERLEAF_ALLOW_ANONYMOUS_READ_AND_WRITE_SHARING` | Se impostata a `true`, consente agli utenti anonimi di visualizzare e modificare i progetti condivisi tramite la funzionalità di [condivisione tramite link](https://www.overleaf.com/blog/integration-update-link-sharing-2017-11-27). |
| `OVERLEAF_DISABLE_LINK_SHARING` | Disabilita la funzionalità di [condivisione tramite link](https://www.overleaf.com/blog/integration-update-link-sharing-2017-11-27). |
| `EMAIL_CONFIRMATION_DISABLED` | Se impostata a `true`, il banner che richiede la conferma dell'email non viene mostrato. |
| `ADDITIONAL_TEXT_EXTENSIONS` | Un array di stringhe per configurare estensioni aggiuntive per i file modificabili. |
| `DEFAULT_LATEX_COMPILER` | <p>Imposta il compilatore predefinito usato dai <strong>nuovi</strong> progetti. (Aggiunta in Server Pro 6.2.0).</p><p><strong>Opzioni:</strong> `pdflatex`, `latex`, `xelatex` o `lualatex`</p> |
| `OVERLEAF_STATUS_PAGE_URL` | URL personalizzato della pagina di stato (aggiunta in Server Pro 3.4.0), ad es. `status.example.com`. |
| `OVERLEAF_FPH_INITIALIZE_NEW_PROJECTS` | Imposta a `'false'` per evitare che i nuovi progetti vengano inizializzati con la Full Project History (aggiunta in Server Pro 3.5.0). |
| `OVERLEAF_FPH_DISPLAY_NEW_PROJECTS` | Imposta a `'false'` per evitare che i nuovi progetti mostrino la Full Project History al posto della cronologia legacy (aggiunta in Server Pro 3.5.0). |
| `ENABLE_CRON_RESOURCE_DELETION` | Imposta questa variabile d'ambiente a `true` per abilitare la pulizia automatica dei progetti e degli utenti eliminati dopo 90 giorni. |
| `OVERLEAF_USER_HARD_DELETION_DELAY` | <p>Modifica il ritardo di scadenza degli utenti eliminati. Si configura in millisecondi.<br /><br /><strong>Predefinito:</strong> 90 giorni</p> |
| `OVERLEAF_PROJECT_HARD_DELETION_DELAY` | <p>Modifica il ritardo di scadenza dei progetti eliminati. Si configura in millisecondi.<br /><br /><strong>Predefinito:</strong> 90 giorni</p> |
| `MAX_UPLOAD_SIZE` | <p>Controlla la dimensione massima di un singolo caricamento, in megabyte. Il valore predefinito è `50`.<br /><br /><strong>Attenzione</strong>: questa variabile è solo un numero, senza unità di misura (MB) né altri elementi.<br /><br />La dimensione totale non compressa di un file `.zip` caricato è limitata a 6 × questo valore (300 MB per impostazione predefinita).</p> |
| `COMPILE_SIZE_LIMIT` | Controlla la dimensione massima del corpo della richiesta in byte. Corrisponde alla somma delle dimensioni di tutti i file doc del progetto (`main.tex`, `references.bib` (se non collegato), ecc.) che devono essere inviati nella richiesta di compilazione iniziale al servizio CLSI. |
| `COMPILE_TIMEOUT` | Il tempo, in secondi, concesso per il completamento di una compilazione. Per maggiori informazioni consulta [Aggiornare il timeout di compilazione dei progetti](/it/on-premises/user-and-project-management/project-management#updating-project-compile-timeout). |
| `MAX_RECONNECT_GRACEFULLY_INTERVAL_MS` | Un ritardo configurabile tra la riconnessione controllata dell'editor, lo svuotamento dei dati e l'arresto del container, per ridurre il rischio di perdita di dati. |
| `SECCOMP_PROFILE` | <p>Imposta questa variabile d'ambiente su un percorso della macchina Docker <strong>host</strong> che punta al profilo SECCOMP. Puoi scaricare una copia del profilo <a href="https://raw.githubusercontent.com/overleaf/overleaf/365af778b68a7940e08282119dc4ef473e2f0044/services/clsi/seccomp/clsi-profile.json">qui</a>.<br /><br />Attualmente necessaria per le distribuzioni Podman quando si usano le Sandboxed Compiles.</p> |
| `OVERLEAF_DISABLE_CHAT` | Se impostata a `true`, disabilita la chat all'interno dei progetti. |
| `OVERLEAF_DISABLE_LOCAL_LOGIN` | Se impostata a `true`, nasconde l'accesso con email e password, così gli utenti possono accedere solo con LDAP, SAML o OIDC. Ha effetto solo quando `EXTERNAL_AUTH` ne abilita almeno uno (aggiunta in Ayakaleaf Pro 6.4.0). |
| `OVERLEAF_LOGIN_SUPPORT_TEXT` | Se impostata, può essere usata per mostrare informazioni di supporto sotto il pulsante di login. Il testo viene mostrato nella schermata di login e può servire a indirizzare gli utenti al supporto interno o a fornire indicazioni su login, creazione di account e così via. |
| `ALLOW_MONGO_ADMIN_CHECK_FAILURES` | <p>Se impostata a `true`, consente che i controlli di avvio di MongoDB falliscano senza impedire l'avvio della distribuzione. Potrebbe essere necessario se usi un database MongoDB in cui l'utente del database non ha il ruolo `clusterParameterReader`.<br /><br />Per assistenza sulla creazione di un ruolo personalizzato consulta <a href="/it/on-premises/maintenance/updating-mongodb#creating-a-custom-role">qui</a>.</p> |
| `V1_HISTORY_URL_FOR_GIT_BRIDGE` | Consente di separare l'endpoint **history-v1** per il traffico interno (servizio `web` → servizio `history-v1`, entrambi nel container `sharelatex`) e per il traffico esterno (`git-bridge` → `history-v1`, in esecuzione in container separati). |
| `OVERLEAF_MAINTENANCE_MESSAGE` e `OVERLEAF_MAINTENANCE_MESSAGE_HTML` | Servono a personalizzare il titolo e il contenuto della pagina di manutenzione. Non possono essere usate insieme a `OVERLEAF_STATUS_PAGE_URL`. |

<Info>

È possibile imporre restrizioni sulle password degli utenti quando si usa il sistema di login di Overleaf (account locali), non un'opzione SSO come LDAP. Per gli account SSO, le policy sulle password vengono applicate dal tuo provider di identità o servizio di directory, che può inoltre supportare l'autenticazione a più fattori.

</Info>
