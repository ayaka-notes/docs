Un deployment Kubernetes legge le stesse variabili d'ambiente del Toolkit. Quando una pagina del Toolkit dice "aggiungi questo a `config/variables.env`", inserisci il valore nella ConfigMap `overleaf-env`, oppure nel Secret `overleaf-secrets` se si tratta di una password, una chiave o un token. Quindi riavvia:

```bash
kubectl -n overleaf apply -f 30-config.yaml        # after editing the ConfigMap
kubectl -n overleaf patch secret overleaf-secrets --type merge \
  -p '{"stringData":{"GITHUB_TOKEN_CIPHER_PASSWORD":"'"$(openssl rand -hex 32)"'"}}'
kubectl -n overleaf rollout restart deployment/overleaf
```

I valori in `config/overleaf.rc` sono impostazioni del Toolkit, non variabili d'ambiente; le domande e risposte alla fine di questa pagina indicano cosa li sostituisce.

### Certificati e altri file

Alcune funzionalità accettano un percorso di file anziché un valore: i certificati SAML (`OVERLEAF_SAML_IDP_CERT`, ...), la CA LDAP (`OVERLEAF_LDAP_TLS_OPTS_CA_PATH`) o una CA privata per un GitHub Enterprise, GitLab o Gitea self-hosted (`NODE_EXTRA_CA_CERTS`). Inserisci i file in un Secret e montalo dove le pagine del Toolkit li prevedono, `/var/lib/overleaf/certs`:

```bash
kubectl -n overleaf create secret generic overleaf-certs --from-file=idp_cert.pem --from-file=ca.pem
```

```yaml title="40-overleaf.yaml (additions)"
          volumeMounts:
            # ...
            - name: certs
              mountPath: /var/lib/overleaf/certs
              readOnly: true
      volumes:
        # ...
        - name: certs
          secret:
            secretName: overleaf-certs
```

Quindi fai riferimento a essi tramite il percorso nella ConfigMap, ad esempio `NODE_EXTRA_CA_CERTS: /var/lib/overleaf/certs/ca.pem`, e riavvia.

<Warning>

<strong>Cipher password.</strong> Imposta nel Secret ogni `*_CIPHER_PASSWORD` delle funzionalità che usi. Altrimenti alcune funzionalità generano un file di chiave nel volume dei dati al primo utilizzo: con una replica funziona finché il volume non va perso, con più repliche ogni replica cifrerebbe con una chiave diversa.

</Warning>

### Domande e risposte

<Accordion title="Di quali impostazioni del Toolkit di `config/overleaf.rc` ho bisogno?">

<strong>Risposta:</strong> Nessuna di esse viene letta da Ayakaleaf Pro. I loro equivalenti in Kubernetes:

| `config/overleaf.rc`                         | Kubernetes                                                        |
| -------------------------------------------- | ----------------------------------------------------------------- |
| `OVERLEAF_LISTEN_IP`, `OVERLEAF_PORT`        | il Service (NodePort) o il tuo ingress                            |
| `SIBLING_CONTAINERS_ENABLED`                 | `SANDBOXED_COMPILES*` nella ConfigMap, socket Docker nel pod      |
| `GIT_BRIDGE_ENABLED`                         | [Integrazione Git](/it/on-premises/configuration/kubernetes/integrations/git-integration)                             |
| `MONGO_ENABLED`, `REDIS_ENABLED`, `MONGO_URL`, `REDIS_HOST` | gli StatefulSet o i tuoi servizi gestiti, `OVERLEAF_MONGO_URL` e `OVERLEAF_REDIS_HOST` |
| `REDIS_AOF_PERSISTENCE`                      | `--appendonly yes` in `20-redis.yaml`                             |
| `NGINX_ENABLED`, `TLS_*`                     | il tuo ingress o load balancer                                    |

</Accordion>
