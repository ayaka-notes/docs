L'accesso degli ospiti ai progetti condivisi, le pagine pubbliche e l'auto-registrazione si attivano con variabili d'ambiente lette dal servizio **web**; il servizio real-time serve poi gli ospiti tramite la loro sessione. Cosa apre ciascuna opzione è descritto in [Accesso pubblico](/it/on-premises/configuration/overleaf-toolkit/authentication/public-access).

| | |
| --- | --- |
| Servizio | web (e real-time per gli ospiti nell'editor), in ogni pod di Ayakaleaf Pro; letto all'avvio di web |
| Pod → esterno | il server SMTP, quando la registrazione invia le email di attivazione |
| Stato | token di accesso degli ospiti nella sessione, limiti di frequenza della registrazione in Redis |
| Job periodici | nessuno |

### Configurazione

Aggiungi le opzioni di cui hai bisogno alla ConfigMap `overleaf-env`:

```yaml title="30-config.yaml (additions)"
  # Guests open link-shared projects without an account
  OVERLEAF_ALLOW_ANONYMOUS_READ_AND_WRITE_SHARING: "true"
  # Signed-out visitors may open /learn, /templates, /devs and view links
  OVERLEAF_ALLOW_PUBLIC_ACCESS: "true"
  # Self-registration: "true", or only some domains
  OVERLEAF_ALLOW_PUBLIC_REGISTRATION: "@example.com, @*.uni.example"
```

```bash
kubectl apply -f 30-config.yaml
kubectl -n overleaf rollout restart deployment/overleaf     # or statefulset/overleaf
```

Metti tra virgolette ogni valore. I valori che iniziano con `@` devono essere tra virgolette in YAML, altrimenti `kubectl apply` rifiuta il file.

La registrazione limitata a determinati domini invia un'email di attivazione, quindi l'[invio delle email](/it/on-premises/configuration/kubernetes/email-delivery) deve funzionare dai pod: inserisci l'host SMTP nella ConfigMap e `OVERLEAF_EMAIL_SMTP_PASS` nel Secret.

### Più repliche

Non serve altro. L'accesso di un ospite a un progetto è conservato nella sessione in Redis, quindi l'editor funziona su qualunque replica scelga il load balancer.

### Testato su Kubernetes

Su Kubernetes 1.37, i nostri test end-to-end per l'accesso pubblico vengono superati: su una replica, l'auto-registrazione con `OVERLEAF_ALLOW_PUBLIC_REGISTRATION` impostato a `true`, a un dominio, a più domini con un carattere jolly per i sottodomini e a `@*`, con l'email di attivazione per le modalità a dominio (43 casi); visitatori non autenticati su `/devs` e uno snippet inviato mantenuto durante l'accesso con `OVERLEAF_ALLOW_PUBLIC_ACCESS` (2 casi); un ospite non autenticato in un progetto condiviso tramite link con entrambe le opzioni attive (3 casi); e, su tre repliche dietro HAProxy, OIDC insieme all'accesso pubblico (1 caso).
