Ogni progetto ha il proprio server MCP, così un client di IA sul tuo computer può leggere e modificare il progetto, compilarlo e rispondere ai suoi commenti. Il client accede con un token di autenticazione Git.

<Info>

Se non vedi la scheda **MCP server**, indica al tuo amministratore la pagina [Server MCP](/it/on-premises/configuration/overleaf-toolkit/integrations/mcp-server).

</Info>

## Novità della v6.3.3 {#new-in-v6-3-3}

Dalla v6.3.3, il client può lavorare anche con la cronologia del progetto: elencare le modifiche, confrontare due versioni, leggere un file com'era, salvare ed eliminare versioni e ripristinare un file o l'intero progetto. Può elencare le modifiche tracciate e accettarle o rifiutarle, e rendere le proprie modifiche tracciate quando glielo chiedi. Può commentare un passaggio di testo e modificare o eliminare i messaggi dei commenti, leggere e inviare messaggi nella chat del progetto, spostare e rinominare file e cartelle, creare cartelle e cambiare la lingua del controllo ortografico. Chi può fare cosa segue il tuo ruolo nel progetto, come nell'editor, perché il client lavora con il tuo token: vedi [Chi può fare cosa](#who-may-do-what).

Il server MCP è stato introdotto nella v6.3.1. La v6.3.1 e la v6.3.2 hanno gli stessi 17 strumenti; la v6.3.3 ne ha 33.

| Strumenti | v6.3.1 e v6.3.2 | v6.3.3 |
| ----- | ----------------- | ------ |
| `get_clone_info`, `get_settings`, `list_files`, `delete_file`, `compile`, `get_compile_log`, `get_output_file_link`, `word_count`, `reply_to_comment`, `resolve_comment`, `reopen_comment` | Sì | Sì, invariati |
| `read_file` | Il contenuto più recente | Anche un file com'era a una `version` |
| `edit_file`, `write_file` | Seguono l'impostazione delle modifiche tracciate del progetto | Anche `trackChanges`, per rendere la modifica una modifica tracciata |
| `update_settings` | Compilatore, immagine TeX Live e documento principale | Anche la lingua del controllo ortografico |
| `list_versions` | Versione, commento e data | Anche l'`id` richiesto da `delete_version`, e chi l'ha salvata |
| `list_comments` | Messaggi senza id | Anche l'`id` di ogni messaggio, richiesto da `edit_comment_message` e `delete_comment_message` |
| `list_changes`, `diff`, `create_version`, `delete_version`, `restore_file`, `restore_project`, `list_tracked_changes`, `accept_tracked_changes`, `reject_tracked_changes`, `add_comment`, `edit_comment_message`, `delete_comment_message`, `list_chat_messages`, `send_chat_message`, `move_file`, `create_folder` | No | Sì |

## Collega un client {#connect-a-client}

<Steps>
<Step title="Apri la finestra">
Apri il progetto. Nella barra a sinistra, fai clic su **Integrations**, poi su **MCP server**.

<Frame caption="Il pannello Integrations">
  <img src="/images/on-premises/mcp-server-integrations.png" alt="Il pannello Integrations con la scheda MCP server" />
</Frame>

La finestra mostra l'indirizzo del server di questo progetto e una scheda per ogni client: **Claude Code**, **Codex**, **Cursor**, **VS Code** e **Gemini CLI**.

<Frame caption="La finestra MCP server">
  <img src="/images/on-premises/mcp-server-dialog.png" alt="La finestra MCP server con l'indirizzo, una scheda per ogni client e il comando per Claude Code" />
</Frame>
</Step>

<Step title="Crea un token">
Fai clic su **Go to settings**. Le impostazioni del tuo account si aprono in una nuova scheda. In **Git integration**, fai clic su **Generate token**, oppure su **Add another token** se ne hai già uno. Fai clic su **Copy** e conserva il token in un posto sicuro, perché lo vedi una sola volta. Poi fai clic su **Close**.

<Frame caption="Il tuo nuovo token">
  <img src="/images/on-premises/mcp-server-token.png" alt="La finestra Git authentication token con un pulsante Copy" />
</Frame>

Funziona anche un token che usi già per l'[integrazione Git](/on-premises/user-guide/users/git-integration), così come un unico token per tutti i tuoi progetti.
</Step>

<Step title="Aggiungi il server al client">
Tornato nella finestra, fai clic sulla scheda del tuo client e poi su **Copy** accanto alla configurazione.

| Scheda | Dove va | Il token |
| --- | ------------- | --------- |
| **Claude Code** | Esegui il comando in un terminale | Sostituisci `<token>` nel comando |
| **Codex** | `~/.codex/config.toml` | Mettilo nella variabile d'ambiente `OVERLEAF_TOKEN` |
| **Cursor** | `~/.cursor/mcp.json` | Mettilo nella variabile d'ambiente `OVERLEAF_TOKEN` |
| **VS Code** | `.vscode/mcp.json` | Il file ha una richiesta di password chiamata `overleaf-token` al posto del token |
| **Gemini CLI** | Esegui il comando in un terminale | Sostituisci `<token>` nel comando |

L'indirizzo appartiene a un solo progetto. Per collegare un altro progetto, aggiungilo con un altro nome, perché `overleaf` è già in uso. Per Claude Code, ad esempio, cambia `overleaf` nel comando in `overleaf-lab`.
</Step>
</Steps>

## Verifica la connessione {#check-the-connection}

### Con Claude Code {#with-claude-code}

```bash
claude mcp list
```

Il server risulta connesso:

```text
overleaf: https://<your-site>/project/<project-id>/mcp (HTTP) - ✔ Connected
```

### Con curl {#with-curl}

Funziona qualunque sia il tuo client. Sostituisci l'indirizzo e il token e invia la richiesta `initialize` del protocollo MCP:

```bash
curl -X POST https://<your-site>/project/<project-id>/mcp \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -H "Accept: application/json, text/event-stream" \
  -d '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2025-06-18","capabilities":{},"clientInfo":{"name":"curl","version":"1.0"}}}'
```

La risposta indica il nome del server, seguito dalle sue istruzioni per i client:

```json
{"result":{"protocolVersion":"2025-06-18","capabilities":{"tools":{"listChanged":true}},"serverInfo":{"name":"overleaf","version":"1.0.0"},"instructions":"This server works on one Overleaf project. ..."},"jsonrpc":"2.0","id":1}
```

Per vedere gli strumenti, invia `tools/list` con lo stesso comando. La risposta elenca 33 strumenti, o 31 se nel tuo sito la chat del progetto è disattivata. Prima della v6.3.3 ne elenca 17.

```bash
  -d '{"jsonrpc":"2.0","id":2,"method":"tools/list","params":{}}'
```

Per chiamarne uno, invia `tools/call`:

```bash
  -d '{"jsonrpc":"2.0","id":3,"method":"tools/call","params":{"name":"list_files","arguments":{}}}'
```

```json
{"result":{"content":[{"type":"text","text":"[\n  {\n    \"path\": \"main.tex\",\n    \"type\": \"doc\"\n  }\n]"}]},"jsonrpc":"2.0","id":3}
```

### Se non si connette {#if-it-does-not-connect}

| Cosa vedi | Cosa significa |
| ------------ | ------------- |
| Stato `401`, o in Claude Code `✘ Failed to connect` con `HTTP 401` | Il token manca, è errato o è stato eliminato |
| Stato `404` | Nessun progetto ha questo ID |
| Stato `405` | La richiesta non era un `POST` |
| Stato `406` con `Not Acceptable` | Manca l'intestazione `Accept`: il client deve accettare sia `application/json` sia `text/event-stream` |

## Cosa vedi quando un client lavora {#what-you-see-when-a-client-works}

Le modifiche compaiono in un editor aperto mentre il client le fa, come quelle di un collaboratore, senza ricaricare. Nuovi file e cartelle, spostamenti e rinomine compaiono nell'albero dei file.

<Frame caption="Una riga aggiunta da edit_file">
  <img src="/images/on-premises/mcp-server-live-edit.png" alt="L'editor mostra una riga aggiunta da edit_file, senza finestre e senza ricaricare" />
</Frame>

`edit_file` modifica solo testo che compare esattamente una volta. Altrimenti il client riceve un errore, come `oldString not found in main.tex, read_file again` o `oldString appears 2 times in main.tex, add context`, e non cambia nulla.

Dalla v6.3.3, `move_file` sposta o rinomina un file o una cartella, creando se necessario le cartelle del nuovo percorso, e `create_folder` crea una cartella. Se il file non viene trovato o il nuovo percorso esiste già, il client riceve un errore e non cambia nulla. `update_settings` può anche cambiare la lingua del controllo ortografico, ad esempio in `de`, oppure disattivarlo.

Le risposte ai commenti compaiono nel pannello di revisione con il tuo nome, perché il token è tuo. Un commento risolto tramite il server esce dal pannello, e riaprirlo lo fa tornare.

<Frame caption="Una risposta inviata da reply_to_comment">
  <img src="/images/on-premises/mcp-server-comment.png" alt="Un commento nel pannello di revisione con una risposta inviata da reply_to_comment" />
</Frame>

Dalla v6.3.3, `add_comment` commenta un passaggio di testo. Il testo deve comparire esattamente una volta nel file; quando compare più volte, il client fornisce anche un passaggio più lungo che lo contiene e compare una sola volta, e viene commentato solo il testo. Il commento compare nel pannello di revisione con il tuo nome e resta sul suo testo quando il file cambia. `edit_comment_message` modifica uno dei tuoi messaggi. `delete_comment_message` elimina un messaggio, ed eliminare il primo elimina l'intero commento, come nel pannello di revisione.

`compile` compila il progetto e restituisce l'elenco dei file di output. `get_output_file_link` fornisce poi un link per scaricare il PDF o un altro file di output. Il link non richiede un token e smette di funzionare dopo 5 minuti.

Per l'elenco completo degli strumenti, vedi [Tools](/on-premises/configuration/overleaf-toolkit/integrations/mcp-server#tools).

## Modifiche tracciate {#tracked-changes}

Dalla v6.3.3, puoi chiedere al client di rendere le sue modifiche modifiche tracciate, ad esempio *Rewrite the abstract as a tracked change*. `edit_file` e `write_file` rendono allora la modifica a un file esistente una modifica tracciata a tuo nome, anche quando il tracciamento delle modifiche è disattivato nel progetto, e tu la accetti o la rifiuti nel pannello di revisione. Un nuovo file non è mai una modifica tracciata. Se non lo chiedi, le modifiche seguono l'impostazione del progetto, come le tue nell'editor: vengono tracciate quando il tracciamento è attivo per te o per tutti.

Se l'account del proprietario del progetto non dispone delle modifiche tracciate, il client riceve `Track changes is off for this project` e non cambia nulla.

Per rivedere ogni modifica del client, attiva il tracciamento delle modifiche per te. Per distinguere le sue modifiche dalle tue nel pannello di revisione, dai al client il token di un altro account con cui condividi il progetto.

`list_tracked_changes` elenca le modifiche tracciate con il loro file, il testo inserito o eliminato, l'autore e l'ora. `accept_tracked_changes` e `reject_tracked_changes` accettano gli id delle modifiche e funzionano come il pannello di revisione: una modifica accettata resta nel testo, un inserimento rifiutato viene rimosso e un'eliminazione rifiutata torna. Un editor aperto mostra il risultato senza ricaricare. Gli strumenti dicono al client di accettare o rifiutare solo le modifiche che chiedi.

## Cronologia {#history}

Dalla v6.3.3, il client vede la cronologia del progetto come la mostra il pannello della cronologia.

| Strumento | Cosa fa |
| ---- | ------------ |
| `list_changes` | Elenca le modifiche, dalla più recente: chi ha modificato quali file e quando, con le versioni prima e dopo ogni modifica. Le modifiche più vecchie arrivano in ulteriori blocchi. |
| `diff` | Confronta due versioni: un file come diff unificato, come `git diff`, oppure i file aggiunti, rimossi, modificati o rinominati |
| `read_file` con `version` | Legge un file com'era a una versione |
| `list_versions` | Elenca le versioni salvate, con il loro commento e chi le ha salvate |
| `create_version` | Salva la versione più recente, o una precedente, con un commento, come **Label this version** |
| `delete_version` | Elimina una versione salvata; le sue modifiche restano |
| `restore_file` | Ripristina un file com'era a una versione, come **Restore this version** |
| `restore_project` | Ripristina l'intero progetto com'era a una versione, come **Restore project to this version** |

Un ripristino è a sua volta una nuova modifica, quindi puoi annullarlo allo stesso modo. Gli strumenti dicono al client di ripristinare solo quando lo chiedi.

Se il proprietario del progetto non dispone della cronologia completa del progetto, il client vede solo le modifiche delle ultime 24 ore, o la più recente se sono tutte più vecchie, come nel pannello della cronologia. Non può confrontare, leggere o ripristinare versioni più vecchie.

## Chat del progetto {#project-chat}

Dalla v6.3.3, `list_chat_messages` legge la chat del progetto, dai più recenti, 50 messaggi alla volta. `send_chat_message` invia un messaggio a tuo nome, che compare subito in una chat aperta. Se nel tuo sito la chat del progetto è disattivata, il client non ha nessuno dei due strumenti.

## Chi può fare cosa {#who-may-do-what}

Il client può fare ciò che il tuo ruolo nel progetto consente.

| Cosa fa il client | Proprietario | Editor | Revisore | Visualizzatore (collaboratore nominato) | Visualizzatore (condivisione via link) |
| -------------------- | ----: | -----: | -------: | --------------------------: | --------------------: |
| Leggere file e impostazioni, compilare, leggere il log, scaricare il PDF | Sì | Sì | Sì | Sì | Sì |
| Scrivere, modificare, spostare ed eliminare file, creare cartelle, cambiare le impostazioni | Sì | Sì | No | No | No |
| Vedere la cronologia, i commenti e le modifiche tracciate | Sì | Sì | Sì | Sì | No |
| Leggere e inviare messaggi in chat | Sì | Sì | Sì | Sì | No |
| Aggiungere commenti e rispondere | Sì | Sì | Sì | No | No |
| Risolvere, riaprire o eliminare un commento | Sì | Sì | Quelli che ha avviato | No | No |
| Modificare un messaggio di commento | I propri | I propri | I propri | No | No |
| Eliminare un messaggio di commento | Sì | Sì | I propri | No | No |
| Accettare o rifiutare modifiche tracciate | Sì | Sì | No | No | No |
| Salvare una versione | Sì | Sì | Sì | No | No |
| Eliminare una versione salvata | Sì | Quelle che ha salvato | Quelle che ha salvato | No | No |
| Ripristinare un file o il progetto | Sì | Sì | No | No | No |

Gli editor che si sono uniti tramite link contano come editor. I revisori non possono modificare file tramite MCP, nemmeno come modifiche tracciate.

## Scollega un client {#disconnect-a-client}

Elimina il token: vedi [Eliminare un token](/on-premises/user-guide/users/git-integration#delete-a-token). Da quel momento il server risponde `401` a quel token. Se lo usi anche per Git, anche Git smette di accettarlo.
