<Info>

Ogni nuova release di Server CE/Server Pro indicherà nelle proprie [note di rilascio](https://docs.overleaf.com/on-premises/release-notes) qualsiasi modifica alla versione supportata di MongoDB.

</Info>

### Devo aggiornare MongoDB?

Dovresti valutare l'aggiornamento della versione di MongoDB **solo** se prevedi di aggiornare la tua istanza di Server CE/Server Pro.

Se utilizzi una versione di MongoDB più recente di quella consigliata per la tua versione attuale (o di destinazione), non è necessario apportare alcuna modifica.

<Warning>

Non dovresti mai effettuare il downgrade della versione di MongoDB.

</Warning>

Se riscontri un problema specifico che ritieni possa essere legato alla tua versione attuale di MongoDB, sentiti libero di [aprire una issue](https://github.com/overleaf/overleaf/issues) se sei un utente Server CE, oppure contatta il supporto Overleaf se sei un utente Server Pro.

### Procedura di aggiornamento

L'aggiornamento della versione di MongoDB durante l'aggiornamento della tua istanza di Server CE/Server Pro avviene come segue:

1. Decidi la versione di Server CE/Server Pro a cui intendi aggiornare.
2. Individua la versione di MongoDB consigliata per quella specifica release di Overleaf Server CE/Server Pro.
3. Segui le istruzioni per aggiornare MongoDB alla versione di destinazione.
4. Aggiorna la versione dell'immagine di Server CE/Server Pro e riavvia l'istanza.

Ti consigliamo di aggiornare sempre **Server CE/Server Pro** all'ultima versione disponibile, poiché il suo supporto è sempre garantito (solo per gli utenti Server Pro).

<Danger>

Quando aggiorni Server CE/Pro, consigliamo di aggiornare all'ultima release della versione major installata **prima** di passare all'ultima release della versione major **successiva**. Se la tua installazione è indietro di più di una versione major rispetto all'ultima, dovrai eseguire un aggiornamento in più passaggi.

Ad esempio, se utilizzi la 3.5.10, dovrai aggiornare alla 3.5.13 -> eseguire la migrazione alla Full Project History -> 4.2.9 -> 5.5.4.

Non dovresti **mai** saltare versioni major (3.5.10 -> 5.5.4). Se utilizzi il Toolkit e sei indietro di più di una versione major rispetto all'ultima, **non** devi usare lo script `bin/upgrade`, poiché dovrai eseguire manualmente un aggiornamento in più passaggi.

</Danger>

<Warning>

È importante assicurarsi di effettuare un [backup coerente](/it/on-premises/maintenance/data-and-backups#performing-a-consistent-backup) **prima** di ogni aggiornamento di versione major, per poter tornare indietro in caso di necessità.

</Warning>

#### Aggiornare MongoDB

MongoDB richiede **aggiornamenti graduali**. Ciò significa che non puoi passare direttamente, ad esempio, dalla `4.0` alla `5.0`. Devi prima aggiornare dalla `4.2` alla `4.4` e poi alla `5.0`.

<Info>

MongoDB utilizza numeri pari per le sue versioni stabili.

</Info>

#### **Istruzioni di aggiornamento quando MongoDB viene eseguito al di fuori di Docker**

Ecco i link alle istruzioni di aggiornamento di mongodb.com per l'aggiornamento di MongoDB.

* [Note di rilascio di MongoDB - aggiornamento di MongoDB dalla `4.2` alla `4.4`](https://www.mongodb.com/docs/v4.4/release-notes/4.4-upgrade-standalone/)
* [Note di rilascio di MongoDB - aggiornamento di MongoDB dalla `4.4` alla `5.0`](https://www.mongodb.com/docs/v5.0/release-notes/5.0-upgrade-replica-set/)
* [Note di rilascio di MongoDB - aggiornamento di MongoDB dalla `5.0` alla `6.0`](https://www.mongodb.com/docs/v6.0/release-notes/6.0-upgrade-replica-set/)
* [Note di rilascio di MongoDB - aggiornamento di MongoDB dalla `6.0` alla `7.0`](https://www.mongodb.com/docs/manual/release-notes/7.0-upgrade-replica-set/#std-label-7.0-upgrade-replica-set)
* [Note di rilascio di MongoDB - aggiornamento di MongoDB dalla `7.0` alla `8.0`](https://www.mongodb.com/docs/manual/release-notes/8.0-upgrade-replica-set/#std-label-8.0-upgrade-replica-set)

<Info>

Le istruzioni per la `5.0` e successive fanno riferimento a un'installazione replica set anziché standalone. Poiché Server Pro/CE 4.0.1+ utilizza le transazioni, MongoDB deve essere eseguito come replica set.

</Info>

<Warning>

La documentazione di MongoDB dalla 3.2 alla 4.2 è ora disponibile all'indirizzo [https://www.mongodb.com/docs/legacy/](https://www.mongodb.com/docs/legacy/)

</Warning>

**Istruzioni di base**

Nella maggior parte dei casi, l'aggiornamento richiede l'impostazione di un flag di compatibilità prima di aggiornare effettivamente la versione di mongo. I passaggi sono i seguenti:

1. Imposta il flag di compatibilità come descritto nelle note di rilascio di MongoDB (vedi gli esempi seguenti).
2. Quindi aggiorna l'immagine di mongo:
   1. **Utenti del Toolkit**: aggiorna `MONGO_VERSION`, ad es. `MONGO_VERSION=6.0`
   2. **Utenti di Docker Compose**: aggiorna la versione del tag dell'immagine `mongo`,\
      ad es. `services -> mongo -> image: mongo:6.0`;

**Esempio: aggiornare MongoDB dalla `5.0` alla `6.0`**

Iniziamo assicurandoci di utilizzare MongoDB `6.0`:

Utenti di Overleaf Toolkit:

```bash
bin/docker-compose exec mongo mongod --version
# db version v5.0.24
```

Utenti di Docker Compose:

```bash
docker compose exec mongo mongod --version
# db version v5.0.24
```

Secondo le [istruzioni di aggiornamento](https://docs.mongodb.com/manual/release-notes/3.6-upgrade-standalone/#upgrade-version-path), l'unico requisito è che `featureCompatibilityVersion` sia impostato su `5.0`. Per farlo, apriamo una shell MongoDB ed eseguiamo il comando indicato:

Utenti di Overleaf Toolkit:

```bash
bin/mongo
# MongoDB shell version v5.0.24
# ...
# overleaf:PRIMARY> db.adminCommand( { setFeatureCompatibilityVersion: "5.0" } )
# { 
# "ok" : 1,
# ...
# }
overleaf:PRIMARY> exit
# bye
```

<Info>

Gli utenti di Docker Compose possono eseguire `docker compose exec mongo mongosh` per ottenere una shell ed eseguire gli stessi comandi degli utenti del Toolkit.

</Info>

Utenti di Overleaf Toolkit:

Arrestiamo quindi le istanze di Server CE/Server Pro e MongoDB con il comando `bin/stop`, impostiamo `MONGO_VERSION=6.0` in `config/overleaf.rc` e riavviamo il servizio `mongo` con `bin/up mongo`) per verificare che l'aggiornamento sia andato a buon fine.

Infine, aggiorniamo la versione dell'immagine di Server CE/Server Pro alla versione di destinazione e ricreiamo tutti i servizi con il comando `bin/up -d`.

Utenti di Docker Compose:

Arrestiamo quindi le istanze di Server CE/Server Pro e MongoDB con il comando `docker compose stop`, aggiorniamo il file [`docker-compose.yml`](https://github.com/overleaf/overleaf/blob/4b1babd4ea634ab12c54e9a9aea7db0e8a500941/docker-compose.yml) per utilizzare `image: mongo:6.0` e riavviamo il servizio `mongo` con il comando `docker compose up mongo` per verificare che l'aggiornamento sia andato a buon fine.

Infine, aggiorniamo la versione dell'immagine di Server CE/Server Pro alla versione di destinazione e ricreiamo tutti i servizi con il comando `docker compose up`.

**Esempio: aggiornare MongoDB dalla `6.0` alla `7.0` (utenti del toolkit)**

Inizia assicurandoti di utilizzare MongoDB `6.0` con i comandi `mongod --version` indicati sopra.

Secondo le [istruzioni di aggiornamento](https://www.mongodb.com/docs/manual/release-notes/7.0-upgrade-replica-set/#std-label-7.0-upgrade-replica-set), l'unico requisito è che `featureCompatibilityVersion` sia impostato su `6.0`. Per farlo, apriamo una shell MongoDB ed eseguiamo il comando `db.adminCommand({ setFeatureCompatibilityVersion: "6.0" })` .

Utenti di Overleaf Toolkit:

```bash
bin/mongo
# ...
# overleaf:PRIMARY> db.adminCommand( { setFeatureCompatibilityVersion: "6.0" } )
# { 
# "ok" : 1,
# ...
# }
overleaf:PRIMARY> exit
# bye
```

Arrestiamo quindi le istanze di Server CE/Server Pro e MongoDB con il comando `bin/stop`, impostiamo `MONGO_VERSION=7.0` in `config/overleaf.rc` e riavviamo il servizio `mongo` con `bin/up mongo`) per verificare che l'aggiornamento sia andato a buon fine.

Infine, aggiorniamo la versione dell'immagine di Server CE/Server Pro alla versione di destinazione e ricreiamo tutti i servizi con il comando `bin/up -d`.

**Esempio: aggiornare MongoDB dalla `7.0` alla `8.0` (utenti del toolkit)**

Inizia assicurandoti di utilizzare MongoDB `7.0` con i comandi `mongod --version` indicati sopra.

Secondo le [istruzioni di aggiornamento](https://www.mongodb.com/docs/manual/release-notes/8.0-upgrade-replica-set/#std-label-8.0-upgrade-replica-set), l'unico requisito è che `featureCompatibilityVersion` sia impostato su `7.0`. Per farlo, apriamo una shell MongoDB ed eseguiamo il comando `db.adminCommand({ setFeatureCompatibilityVersion: "7.0", confirm: true })`. Tieni presente che ora è richiesto il parametro aggiuntivo `confirm: true`.

```bash
bin/mongo
# ...
# overleaf:PRIMARY> db.adminCommand( { setFeatureCompatibilityVersion: "7.0", confirm: true } )
# { 
# "ok" : 1,
# ...
# }

```

Arrestiamo quindi le istanze di Server CE/Server Pro e MongoDB con il comando `bin/stop`, impostiamo `MONGO_VERSION=8.0` in `config/overleaf.rc` e riavviamo il servizio `mongo` con `bin/up mongo`) per verificare che l'aggiornamento sia andato a buon fine.

Infine, aggiorniamo la versione dell'immagine di Server CE/Server Pro alla versione di destinazione e ricreiamo tutti i servizi con il comando `bin/up -d`.

#### Comandi equivalenti per gli utenti di docker compose

Per gli utenti di docker compose, i comandi equivalenti sono:

* `docker compose exec mongo mongod --version` per visualizzare la versione di mongo
* `docker compose exec mongo mongosh` per avviare una shell mongo per i comandi di amministrazione
* il comando `docker compose stop` per arrestare il server
* Modifica il file [`docker-compose.yml`](https://github.com/overleaf/overleaf/blob/4b1babd4ea634ab12c54e9a9aea7db0e8a500941/docker-compose.yml) per utilizzare `image: mongo:6.0` e aggiornare la versione di mongo
* `docker compose up mongo` per riavviare il servizio mongo e verificare che l'aggiornamento sia andato a buon fine
* Modifica il file [`docker-compose.yml`](https://github.com/overleaf/overleaf/blob/4b1babd4ea634ab12c54e9a9aea7db0e8a500941/docker-compose.yml) per utilizzare `image: sharelatex:VERSION` e aggiornare la versione dell'immagine
* `docker compose up` per ricreare tutti i servizi.

### Creare un ruolo personalizzato

Nella versione `5.5.1` abbiamo introdotto un controllo all'avvio per verificare la feature compatibility version di MongoDB. Se il tuo database MongoDB utilizza l'autenticazione (ad es. l'autenticazione di base), il container `sharelatex` potrebbe non avviarsi, mostrando un errore di permessi "_not authorized on admin to execute command_".

Per risolvere il problema, puoi creare un nuovo ruolo in MongoDB e assegnarlo all'account utente utilizzato per accedere al database seguendo le istruzioni riportate di seguito, oppure impostare `ALLOW_MONGO_ADMIN_CHECK_FAILURES=true` per consentire al controllo di fallire senza impedire l'avvio dell'installazione.

<Check>

Questo nuovo ruolo concede **solo** il permesso di leggere i parametri del server MongoDB a livello di cluster e può essere riutilizzato anche a scopo di monitoraggio,

</Check>

```bash wrap
# Toolkit users
$ bin/docker-compose exec -it mongo mongosh -u {{YOUR-ADMIN-USERNAME}} -p

# Switch to the "admin" database using
overleaf [direct: primary] sharelatex> use admin
switched to db admin
overleaf [direct: primary] admin> 

# Create a new role with permission to use "getParamter". Copy and paste the function below into the shell and press the return key

db.createRole(
  {
    role: "clusterParameterReader",
    privileges: [
      {
        resource: { cluster: true },
        actions: ["getParameter"]    
      }
    ],
    roles: [] 
  }
);

# Switch back to the "sharelatex" database 
use sharelatex
switched to db sharelatex
overleaf [direct: primary] sharelatex> 

# Assign the new "clusterParameterReader" role to your database user by copy and pasting the function below into the shell and press the return key 
db.grantRolesToUser(
  "{{YOUR-DATABASE-USER}}",
  [
    { role: "clusterParameterReader", db: "admin" }
  ]
);

# Type exit then return to exit the MongoDB shell
# Run bin/up -d to start the deployment stack
$ bin/up -d
```
