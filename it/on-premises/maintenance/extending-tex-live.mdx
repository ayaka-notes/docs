È possibile estendere un'immagine TeX Live esistente usando un nuovo Dockerfile e configurare l'applicazione per usare la nuova immagine.

Ecco alcune linee guida per installare nuovi pacchetti o font.

Le immagini TeX Live ricevono aggiornamenti poco frequenti. Consigliamo di ricompilare le immagini personalizzate quando aggiorni Ayakaleaf Pro.

<Danger>

Le sezioni seguenti si applicano solo alle [Sandboxed Compiles](/it/on-premises/configuration/overleaf-toolkit/sandboxed-compiles).

</Danger>

### Installare e aggiornare nuovi pacchetti

Puoi usare comandi `tlmgr` come `tlmgr install` e `tlmgr update` per gestire i pacchetti TeX Live, come nell'esempio seguente:

```dockerfile
FROM ghcr.io/ayaka-notes/texlive-full:2023.1

RUN tlmgr update --force ebproof
```

### Usare `tlmgr` in un'immagine TeX Live precedente

Per impostazione predefinita `tlmgr` scarica le risorse dall'ultima release di TeX Live. Quando si applicano patch a un'immagine TeX Live precedente, i download devono essere indirizzati all'archivio corrispondente. Consulta l'elenco in [https://www.tug.org/historic/](https://www.tug.org/historic/) per i mirror degli archivi.

```dockerfile
FROM ghcr.io/ayaka-notes/texlive-full:2022.1

RUN tlmgr option repository <MIRROR>/systems/texlive/<YEAR>/tlnet-final
# e.g. RUN tlmgr option repository ftp://tug.org/historic/systems/texlive/2022/tlnet-final

RUN tlmgr update --force ebproof
```

### Installare nuovi font

Esistono diverse procedure per installare nuovi font in una distribuzione TeX Live, e l'installazione di un font personalizzato può richiedere diversi passaggi. Consultare le [istruzioni per installare i font TeX](https://tug.org/fonts/fontinstall.html) nella documentazione ufficiale di TeX Live è probabilmente un buon punto di partenza.

Il seguente `Dockerfile` mostra un esempio di installazione di un font TrueType su un'immagine TeX Live 2022 esistente:

```dockerfile
FROM ghcr.io/ayaka-notes/texlive-full:2022.1

COPY ./myfonts/*.ttf /usr/share/fonts/truetype/myfont/

# rebuild font information cache
RUN fc-cache
```

### Configurare Ayakaleaf Pro per usare le nuove immagini

Usa il nome `ghcr.io/ayaka-notes/texlive-full` e un tag personalizzato per compilare la nuova immagine, come in:

```bash
docker build -t ghcr.io/ayaka-notes/texlive-full:2023.1-custom .
```

Ora possiamo configurare Ayakaleaf Pro per usare la nuova immagine `2023.1-custom` aggiornando le variabili d'ambiente `TEX_LIVE_DOCKER_IMAGE`, `ALL_TEX_LIVE_DOCKER_IMAGES` e `ALL_TEX_LIVE_DOCKER_IMAGE_NAMES` (i nomi sono facoltativi e seguono l'ordine delle immagini):

```text wrap
TEX_LIVE_DOCKER_IMAGE: "ghcr.io/ayaka-notes/texlive-full:2023.1-custom"
ALL_TEX_LIVE_DOCKER_IMAGES: "ghcr.io/ayaka-notes/texlive-full:2023.1,ghcr.io/ayaka-notes/texlive-full:2023.1-custom"
ALL_TEX_LIVE_DOCKER_IMAGE_NAMES: "TeX Live 2023,TeX Live 2023 custom"
```

Nell'esempio sopra, i nuovi progetti sono impostati per usare per impostazione predefinita la nuova immagine `2023.1-custom`, mentre `2023.1` resta disponibile quando serve.

L'immagine personalizzata esiste solo sul tuo host, quindi `bin/up` non può scaricarla. Imposta `SIBLING_CONTAINERS_PULL=false` in `config/overleaf.rc` (scarica tu stesso le altre immagini con `docker pull`), quindi esegui `bin/up -d` per applicare le nuove impostazioni.

### Q\&A

<Accordion title="Devo installare font cinesi per compilare documenti in cinese con XeLaTeX?">

<strong>Risposta:</strong> No, non con le immagini `texlive-full`. Includono i pacchetti cinesi di TeX Live (`ctex`, `xeCJK`) con i font Fandol, e i font Noto CJK (ad esempio `Noto Serif CJK SC`). Imposta XeLaTeX come compilatore del progetto nelle impostazioni dell'editor, quindi compila, ad esempio:

```latex
\documentclass{ctexart}
\begin{document}
你好，世界！
\end{document}
```

Per usare Noto invece di Fandol, aggiungi `\setCJKmainfont{Noto Serif CJK SC}`. Non serve alcun `latexmkrc`. Per altri font, compila un'immagine personalizzata come mostrato in [Installare nuovi font](#installare-nuovi-font).

</Accordion>
