---
title: Esportare i progetti
icon: file-export
---

In Server Pro e Community Edition `5.4.0` abbiamo incluso uno script che consente agli amministratori di esportare tutti i progetti degli utenti (compresi quelli ancora visibili nelle cartelle **Eliminati** e **Cestino**) in una directory su disco.

<Info>

Il risultato dell'esecuzione di questo script è lo stesso che si ottiene scaricando manualmente uno Zip di tutti i progetti dalla dashboard dei progetti dell'utente. Lo script applica eventuali modifiche in sospeso prima di avviare il download, per garantire che l'esportazione contenga la versione più recente del progetto.

</Info>

### Limitazioni

Lo script di esportazione presenta le seguenti limitazioni:

* Le impostazioni del progetto, come il nome dell'immagine TeX Live o il compilatore, non vengono esportate. Devono essere impostate quando il progetto viene caricato nell'account dell'utente.
* I progetti esportati non contengono alcuna cronologia delle versioni.
* Le informazioni sui collaboratori non vengono conservate. I progetti dovranno essere condivisi di nuovo. Se si usa la condivisione tramite link, i link di visualizzazione e modifica verranno rigenerati (non saranno gli stessi di prima).
* I commenti e le informazioni sulle revisioni tracciate non verranno esportati.
* La cronologia della chat del progetto non verrà esportata.

<Danger>

Questo script **non** è pensato per sostituire un backup completo del sistema. Per assicurarti di poter ripristinare la tua istanza in uno scenario di disaster recovery, ti consigliamo **vivamente** di eseguire un [backup consistente](https://docs.overleaf.com/on-premises/maintenance/#performing-a-consistent-backup).

</Danger>

### **Flag**

| Nome           | Descrizione                                                                              |
| -------------- | ---------------------------------------------------------------------------------------- |
| `--help`       | Mostra la guida                                                                          |
| `--user-id`    | L'ID utente (obbligatorio a meno che non si usi `--export-all` o `--project-id`)         |
| `--project-id` | Esporta un singolo progetto (**non può** essere usato con `--user-id` o `--export-all`)  |
| `--list`       | Elenca i progetti dell'utente (**non può** essere usato con `--output`)                  |
| `--output`     | File zip di output (per le operazioni di esportazione singola)                           |
| `--export-all` | Esporta i progetti di tutti gli utenti (richiede `--output-dir`)                         |
| `--output-dir` | Directory in cui salvare i file di esportazione di tutti gli utenti                      |
| `--log-level`  | Livelli di log supportati: `trace`\|`debug`\|`info`\|`warn`\|`error`\|`fatal`            |

### **Utilizzo**

Usa il seguente comando per esportare i progetti di tutti gli utenti:

```bash wrap
# Overleaf Toolkit users
$ bin/docker-compose exec sharelatex /bin/bash -ce "cd /overleaf/services/web && node modules/server-ce-scripts/scripts/export-user-projects.mjs --export-all --output-dir=/var/lib/overleaf/data/exports"

# Legacy docker-compose.yml users
docker exec sharelatex /bin/bash -ce "cd /overleaf/services/web && node modules/server-ce-scripts/scripts/export-user-projects.mjs --export-all --output-dir=/var/lib/overleaf/data/exports"
```

<Info>

Se usi Server Pro o Community Edition &lt;= 3.5.13, dovrai modificare l'esempio precedente per usare lo script **`export-legacy-user-projects.js`**.

</Info>

### **Completamento**

Al termine dell'esportazione, puoi accedere ai file tramite la directory dell'host montata in bind su **/var/lib/overleaf** nel file **docker-compose.yml**, oppure tramite la variabile d'ambiente `OVERLEAF_DATA_PATH` nel file **config/overleaf.rc** se usi il Toolkit.

<Info>

Attualmente Overleaf consente nomi di progetto duplicati. Se un utente ha progetti con nomi duplicati, questi verranno comunque aggiunti allo Zip di esportazione dell'utente, ma una volta estratto sarà presente una sola versione. Su Linux, `unzip -B` scrive i file con lo stesso nome come file di backup invece di sovrascriverli.

</Info>
