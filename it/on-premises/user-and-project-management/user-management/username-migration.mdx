## Migrazione dei nomi utente

Dal punto di vista dell'accesso, l'identificatore principale di un utente è il suo indirizzo email. Se stai migrando dall'autenticazione locale all'SSO o da un IdP a un altro, potrebbe essere necessario aggiornare gli indirizzi email degli utenti.

Per aiutarti, è disponibile uno script che migra le email degli utenti utilizzando un file CSV con il seguente formato:

`oldEmail,newEmail`

Dopo aver eseguito alcuni controlli di validazione, lo script scorrerà il file CSV e aggiornerà gli indirizzi email degli utenti da `oldEmail` a `newEmail`.

### **Validazione**

Prima di eseguire la migrazione, il `<csv_file>` verrà controllato per garantire che:

* Per ogni riga, sia `oldEmail` sia `newEmail` siano indirizzi email validi
* Non ci siano voci duplicate, ad esempio che tu non stia tentando di aggiornare utenti diversi allo stesso nuovo indirizzo email o di aggiornare lo stesso account utente con un indirizzo email già utilizzato

### **Utilizzo**

```bash wrap
docker cp <csv_file> sharelatex:/overleaf/services/web/<csv_file> docker exec sharelatex /bin/bash -c "cd /overleaf/services/web;node ./modules/server-ce-scripts/scripts/migrate-user-emails.js [--commit] [--continue|--ignore-missing] [--admin-id=ADMIN_USER_ID] <csv_file>"
```

### **Flag**

| Nome               | Descrizione                                                                                                                                                                                                                                                      |
| ------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `--commit`         | <p>L'inclusione del flag `--commit` esegue effettivamente la migrazione. Se omesso, la migrazione avverrà in modalità dry-run, in cui non viene apportata alcuna modifica ma la validazione viene comunque eseguita.<br /><br /><strong>Predefinito</strong>:`false`</p> |
| `--continue`       | Il flag `--continue` fa proseguire il processo di migrazione se l'indirizzo email di un account utente è già stato aggiornato                                                                                                                                     |
| `--ignore-missing` | Il flag `--ignore-missing` fa proseguire il processo di migrazione se un account utente non viene trovato                                                                                                                                                        |
| `--admin-id`       | `--admin-id` deve essere impostato sull'ID dell'amministratore che esegue la migrazione e verrà utilizzato per le voci del registro di controllo. Vai su **Admin** > **Manage Users**, cerca il tuo indirizzo email e fai clic sul primo risultato per trovare il tuo user-id. |
| `<csv_file>`       | `<csv_file>` è il file contenente gli indirizzi email vecchi e nuovi                                                                                                                                                                                             |

### **Completamento**

Durante l'esecuzione dello script di migrazione, i flag scelti determinano se un errore viene registrato nella console e l'esecuzione prosegue, oppure se viene registrato nella console e lo script termina. Se lo script termina prematuramente a causa di un errore, uscirà con codice 1 per indicare che non è andato a buon fine.

Al termine della migrazione, lo script registrerà nella console il numero di aggiornamenti riusciti, falliti e saltati. Se la migrazione viene completata correttamente, uscirà con codice 0.
