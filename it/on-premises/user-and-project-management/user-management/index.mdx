## Creare un utente amministratore {#creating-an-administrator-user}

Installazioni con l'Overleaf Toolkit:

```bash title="Overleaf Toolkit" wrap
$ bin/docker-compose exec sharelatex /bin/bash -ce "cd /overleaf/services/web && node modules/server-ce-scripts/scripts/create-user --admin --email=joe@example.com"
```

Installazioni legacy con docker-compose.yml:

```bash title="Legacy docker-compose" wrap
$ docker exec sharelatex /bin/bash -ce "cd /overleaf/services/web && node modules/server-ce-scripts/scripts/create-user --admin --email=joe@example.com"
```

Il comando crea un utente con l'indirizzo email fornito, se non esiste già, e lo rende amministratore. L'output del comando include un URL da visitare per impostare la password di questo utente ed effettuare il primo accesso.

<Info>

Per un approccio programmatico puoi usare lo stesso script per creare sia utenti normali sia amministratori. Per gli utenti normali, ometti il flag --admin.

</Info>

Se utilizzi account interni per l'autenticazione e devi promuovere un utente esistente ad amministratore dell'istanza o revocargli i permessi di amministratore, procedi come segue:

<Steps>
<Step title="Tramite l'interfaccia di amministrazione">
* Accedi come amministratore esistente.
* Fai clic su Admin -> Manage Users.
* Cerca l'utente e fai clic sul suo nome.
* Fai clic sull'icona della matita.
* Attiva o disattiva Admin.
* Fai clic su Save per terminare.
</Step>
</Steps>

## Eliminare utenti {#deleting-users}

In genere è consigliabile non eliminare gli account a meno che non servano più. Eliminare un account rimuove l'account e fa perdere ai collaboratori l'accesso ai progetti. Per impedire a un utente di accedere mantenendo i suoi dati, [disattiva l'account](/on-premises/user-guide/administrators/user-management#disable-or-enable-an-account).

Per impostazione predefinita, gli account vengono eliminati in modo soft (soft-delete). Per informazioni sulla rimozione permanente degli utenti dalla tua istanza, consulta `ENABLE_CRON_RESOURCE_DELETION` nella guida [Variabili d'ambiente](/it/on-premises/configuration/overleaf-toolkit/environment-variables).

<Info>

Per impostazione predefinita, gli account vengono eliminati in modo soft. Consulta `ENABLE_CRON_RESOURCE_DELETION` per il comportamento dell'eliminazione permanente.

</Info>

### Tramite Admin -> Manage Users {#via-admin->-manage-users}

<Steps>
<Step title="">
* Accedi come amministratore.
* Fai clic su Admin -> Manage Users.
* Cerca l'utente e seleziona la casella accanto al suo nome.
* Fai clic sull'icona del cestino.
* Fai clic su Delete account per confermare.
</Step>
</Steps>

### Tramite la riga di comando {#via-the-command-line}

Gli account utente (e i relativi progetti) possono essere eliminati con i seguenti comandi.

Installazioni con l'Overleaf Toolkit:

```bash title="Overleaf Toolkit"
$ bin/docker-compose exec sharelatex /bin/bash -ce "cd /overleaf/services/web && node modules/server-ce-scripts/scripts/delete-user.mjs --email=joe@example.com"
```

Installazioni legacy con docker-compose.yml:

```bash title="Legacy docker-compose"
$ docker exec sharelatex /bin/bash -ce "cd /overleaf/services/web && node modules/server-ce-scripts/scripts/delete-user.mjs --email=joe@example.com"
```

<Danger>

Lo script di eliminazione utilizza un'opzione force impostata nel codice, che garantisce che l'eliminazione proceda anche se l'invio dell'email di eliminazione dell'account non riesce (ad es. quando l'email dell'utente non è più attiva).

</Danger>

<Info>

È possibile usare l'opzione --skip-email per evitare di inviare un'email informativa all'utente eliminato.

</Info>

## Ripristinare un utente eliminato in modo soft {#restoring-a-soft-deleted-user}

Se un utente è stato eliminato solo in modo reversibile (soft delete), puoi ripristinare il suo account e i progetti eliminati con esso. I progetti che l'utente aveva eliminato personalmente restano eliminati.

<Steps>
<Step title="">
* Accedi come amministratore.
* Fai clic su Admin -> Manage Users.
* Cerca l'utente che vuoi ripristinare.
* Fai clic su Display deleted users.
* Fai clic sull'icona della freccia nella riga dell'utente.
* Fai clic su Restore per confermare.
</Step>
</Steps>

<Danger>

Quando ENABLE\_CRON\_RESOURCE\_DELETION è impostato su true, gli account eliminati in modo soft possono essere ripristinati entro 90 giorni. Trascorsi 90 giorni, il recupero dell'account non è possibile.

</Danger>

## Contare gli utenti {#counting-users}

Puoi ottenere il numero di utenti tramite l'interfaccia di amministrazione all'indirizzo https://you-instance-url/admin/user#license. Per controlli ed esportazioni programmatici, i seguenti esempi possono esserti utili.

Numero totale di utenti:

```bash title="Total number of users"
echo 'db.users.countDocuments()' | docker exec -i mongo mongosh --quiet localhost/sharelatex
# overleaf [direct: primary] sharelatex> 16
```

Numero totale di utenti tramite l'endpoint delle metriche:

```bash title="Num active users from metrics"
docker exec sharelatex curl http://127.0.0.1:3000/metrics | grep num_active_users
# # HELP num_active_users num_active_users
# # TYPE num_active_users gauge
# num_active_users{app="web-api",host="b3ae4ff549d8"} 16
```

Numero totale di utenti attivi (esempio: utenti attivi negli ultimi 365 giorni):

```bash title="Total number of active users"
echo 'db.users.countDocuments({ lastActive: { $gte: new Date(new Date().getTime() - (365 * 24 * 60 * 60 * 1000)) } })' | docker exec -i mongo mongosh --quiet localhost/sharelatex
# overleaf [direct: primary] sharelatex> 10
```

## Aggiornare le informazioni dell'account utente {#updating-user-account-information}

Il modo in cui vengono effettuati gli aggiornamenti degli account dipende dall'abilitazione o meno dell'SSO.

* Se l'SSO non è utilizzato:
  * Gli amministratori possono modificare le informazioni dell'account utente tramite Admin -> Manage Users (email, nome, cognome e generazione di un link per la reimpostazione della password).
  * Gli utenti normali possono aggiornare i propri dati tramite Account -> Account Settings (inclusi il cambio password e la generazione dei token di autenticazione Git).
* Se l'SSO è utilizzato:
  * Ayakaleaf Pro può essere configurato per aggiornare nome e cognome di un utente durante l'accesso, in base al sistema di autenticazione.
  * Quando OVERLEAF\_SAML\_UPDATE\_USER\_DETAILS\_ON\_LOGIN o OVERLEAF\_LDAP\_UPDATE\_USER\_DETAILS\_ON\_LOGIN sono true, il modulo dei dati utente su https://your-instance-url/user/settings è disabilitato e nome/cognome possono essere impostati solo nel tuo sistema di gestione delle identità.

Per maggiori dettagli consulta:

* [Configurazione SAML 2.0](/it/on-premises/configuration/overleaf-toolkit/authentication/saml-authentication)
* [Configurazione LDAP](/it/on-premises/configuration/overleaf-toolkit/authentication/ldap-authentication)

### Q\&A {#q&a}

<Accordion title="Posso creare in anticipo gli utenti SSO, ad esempio tramite un'API?">

<strong>Risposta:</strong> Non esiste un'API HTTP per questo. Crea l'account con lo script `create-user` indicato sopra (senza `--admin`) oppure in **Admin → Manage Users** con **Create account**. Quando `EXTERNAL_AUTH` è impostato, quel modulo ha un'opzione **Log in with SSO**, che crea l'account senza password locale e senza email o link di attivazione: la finestra di dialogo si chiude dopo **Create**. Al primo accesso LDAP, SAML o OIDC, l'utente ottiene l'account esistente con lo stesso indirizzo email invece di uno nuovo, vedi [Account e password](/it/on-premises/configuration/overleaf-toolkit/authentication#accounts-and-passwords).

</Accordion>

<Accordion title="Posso esportare l'elenco degli utenti e ripristinarlo in seguito?">

<strong>Risposta:</strong> No. Non esiste un'esportazione o un'importazione degli account utente, né in **Admin → Manage Users** né tramite script. Gli account sono archiviati in MongoDB, quindi esegui il backup e il ripristino con un [backup di MongoDB](/it/on-premises/maintenance/data-and-backups#mongodb). Lo script `export-user-projects.mjs` esporta i progetti degli utenti come file zip, non gli account, vedi [Esportare i progetti](/it/on-premises/maintenance/data-and-backups/exporting-projects).

</Accordion>

<Accordion title="Per quanto tempo è valido il link di `create-user` e come reimposto una password senza email?">

<strong>Risposta:</strong> Il link stampato da `create-user` è valido per 7 giorni e funziona senza SMTP, perché lo copi dall'output. Per ottenere un nuovo link, esegui di nuovo `create-user` con la stessa email. Per un account esistente stampa solo un nuovo link, ma imposta anche il flag di amministratore dell'account in base a `--admin`, quindi mantieni `--admin` quando lo esegui per un amministratore.

Un amministratore può anche ottenere un link di reset senza email: in **Admin → Manage Users**, fai clic sull'icona del lucchetto nella riga dell'utente, poi su **Send reset link**, e copia il link dalla finestra di dialogo. È valido per 1 ora, vedi [Inviare un link di attivazione o di reset](/on-premises/user-guide/administrators/user-management#send-an-activation-or-reset-link).

Oppure imposta direttamente una password: fai clic sul nome dell'utente, poi sull'icona della matita, inserisci una **New password** di almeno 8 caratteri e fai clic su **Save**. Gli account che accedono solo tramite LDAP, SAML o OIDC non possono ottenere una password in nessuno dei due modi.

</Accordion>
