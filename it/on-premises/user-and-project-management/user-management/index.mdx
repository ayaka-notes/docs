## Creare un utente amministratore

Installazioni con Overleaf Toolkit:

```bash title="Overleaf Toolkit" wrap
$ bin/docker-compose exec sharelatex /bin/bash -ce "cd /overleaf/services/web && node modules/server-ce-scripts/scripts/create-user --admin --email=joe@example.com"
```

Installazioni legacy con docker-compose.yml:

```bash title="Legacy docker-compose" wrap
$ docker exec sharelatex /bin/bash -ce "cd /overleaf/services/web && node modules/server-ce-scripts/scripts/create-user --admin --email=joe@example.com"
```

Il comando crea un utente con l'indirizzo email fornito, se non esiste già, e lo rende amministratore. L'output del comando include un URL da visitare per impostare la password di questo utente ed effettuare il primo accesso.

<Info>

Per un approccio programmatico puoi usare lo stesso script per creare sia utenti normali sia amministratori. Per gli utenti normali ometti il flag --admin.

</Info>

Se utilizzi account interni per l'autenticazione e devi promuovere un utente esistente ad amministratore dell'istanza o revocare i permessi di amministratore, procedi come segue:

<Steps>
<Step title="Tramite l'interfaccia di amministrazione">
* Accedi come amministratore esistente.
* Fai clic su Admin -> Manage Users.
* Cerca l'utente e fai clic sul suo indirizzo email.
* Scorri fino alla sezione Site Admin e fai clic sul link (show).
* Seleziona la casella Is Site Admin.
* Fai clic su Save per completare.
</Step>
</Steps>

## Eliminare utenti

In genere è consigliabile non eliminare gli account a meno che non siano più necessari. L'eliminazione di un account rimuove l'account e fa sì che i collaboratori perdano l'accesso ai progetti. Al momento non esiste un modo per disattivare gli account: o esistono con i loro dati conservati, oppure vengono eliminati.

Per impostazione predefinita, gli account vengono eliminati in modo soft (soft delete). Per informazioni sulla rimozione definitiva degli utenti dalla tua istanza, consulta `ENABLE_CRON_RESOURCE_DELETION` nella guida [Variabili d'ambiente](/it/on-premises/configuration/overleaf-toolkit/environment-variables).

<Info>

Per impostazione predefinita gli account vengono eliminati in modo soft. Consulta `ENABLE_CRON_RESOURCE_DELETION` per il comportamento dell'eliminazione definitiva.

</Info>

### Tramite Admin -> Manage Users

<Steps>
<Step title="">
* Accedi come amministratore.
* Fai clic su Admin -> Manage Users.
* Cerca l'utente e seleziona la casella accanto al suo indirizzo email.
* Fai clic sull'icona del cestino.
* Fai clic su Delete per confermare.
</Step>
</Steps>

### Tramite riga di comando

Gli account utente (e i relativi progetti) possono essere eliminati con i seguenti comandi.

Installazioni con Overleaf Toolkit:

```bash title="Overleaf Toolkit"
$ bin/docker-compose exec sharelatex /bin/bash -ce "cd /overleaf/services/web && node modules/server-ce-scripts/scripts/delete-user.mjs --email=joe@example.com"
```

Installazioni legacy con docker-compose.yml:

```bash title="Legacy docker-compose"
$ docker exec sharelatex /bin/bash -ce "cd /overleaf/services/web && node modules/server-ce-scripts/scripts/delete-user.mjs --email=joe@example.com"
```

<Danger>

Lo script di eliminazione utilizza un'opzione di forzatura impostata nel codice che garantisce che l'eliminazione proceda anche se l'invio dell'email di eliminazione dell'account non riesce (ad es. quando l'email dell'utente non è più attiva).

</Danger>

<Info>

Dalla versione 5.5.0, è possibile usare l'opzione --skip-email per evitare l'invio di un'email informativa all'utente eliminato.

</Info>

## Ripristinare un utente eliminato in modo soft

Se un utente è stato eliminato solo in modo soft, puoi ripristinare il suo account e i suoi progetti.

<Steps>
<Step title="">
* Accedi come amministratore.
* Fai clic su Admin -> Manage Users.
* Cerca l'utente che vuoi ripristinare.
* Fai clic sul pulsante Display deleted users.
* Fai clic sull'indirizzo email dell'utente eliminato.
* Fai clic su Recover This Account.
* Fai clic su Recover per confermare.
</Step>
</Steps>

<Danger>

Quando ENABLE\_CRON\_RESOURCE\_DELETION è impostato su true, gli account eliminati in modo soft possono essere ripristinati entro 90 giorni. Trascorsi 90 giorni, il recupero dell'account non è più possibile.

</Danger>

## Contare gli utenti

Puoi ottenere il numero di utenti tramite l'interfaccia di amministrazione all'indirizzo https://you-instance-url/admin/user#license. Per controlli ed esportazioni programmatiche, possono essere utili i seguenti esempi.

Numero totale di utenti:

```bash title="Total number of users"
echo 'db.users.countDocuments()' | docker exec -i mongo mongosh --quiet localhost/sharelatex
# overleaf [direct: primary] sharelatex> 16
```

Numero totale di utenti tramite l'endpoint delle metriche:

```bash title="Num active users from metrics"
docker exec sharelatex curl http://127.0.0.1:3000/metrics | grep num_active_users
# # HELP num_active_users num_active_users
# # TYPE num_active_users gauge
# num_active_users{app="web-api",host="b3ae4ff549d8"} 16
```

Numero totale di utenti attivi (esempio: utenti attivi negli ultimi 365 giorni):

```bash title="Total number of active users"
echo 'db.users.countDocuments({ lastActive: { $gte: new Date(new Date().getTime() - (365 * 24 * 60 * 60 * 1000)) } })' | docker exec -i mongo mongosh --quiet localhost/sharelatex
# overleaf [direct: primary] sharelatex> 10
```

## Aggiornare le informazioni degli account utente

Il modo in cui vengono effettuati gli aggiornamenti degli account dipende dall'eventuale abilitazione dell'SSO.

* Se l'SSO non è utilizzato:
  * Gli amministratori possono modificare le informazioni degli account utente tramite Admin -> Manage Users (email, nome, cognome e generazione di un link per la reimpostazione della password).
  * Gli utenti normali possono aggiornare i propri dati tramite Account -> Account Settings (compresa la modifica della password e la generazione dei token di autenticazione Git).
* Se l'SSO è utilizzato:
  * Server Pro può essere configurato per aggiornare il nome e il cognome di un utente durante l'accesso in base al sistema di autenticazione.
  * Quando OVERLEAF\_SAML\_UPDATE\_USER\_DETAILS\_ON\_LOGIN o OVERLEAF\_LDAP\_UPDATE\_USER\_DETAILS\_ON\_LOGIN sono impostati su true, il modulo dei dati utente su https://your-instance-url/user/settings è disabilitato e nome e cognome possono essere impostati solo nel tuo sistema di gestione delle identità.

Per maggiori dettagli consulta:

* Configurazione SAML 2.0: https://docs.overleaf.com/on-premises/configuration/overleaf-toolkit/server-pro-only-configuration/saml-2.0
* Configurazione LDAP: https://docs.overleaf.com/on-premises/configuration/overleaf-toolkit/server-pro-only-configuration/ldap
