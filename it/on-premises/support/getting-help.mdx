### Il Doctor

L'Overleaf Toolkit include un comodo script `doctor` per aiutare nel debug. Esegui `bin/doctor` e lo script stamperà informazioni sul tuo ambiente host, sulla tua configurazione e sulle dipendenze necessarie al Toolkit. Questo output può anche aiutarci a diagnosticare i problemi delle tue installazioni di Ayakaleaf Pro.

<Info>

Gli utenti di Overleaf Pro possono [aprire una issue su GitHub](https://github.com/ayaka-notes/overleaf/issues).

È una buona idea includere nel tuo messaggio l'output dello script `bin/doctor`.

</Info>


### Dipendenze

La sezione `Dependencies` elenca gli strumenti necessari al funzionamento del Toolkit. Se uno strumento è presente, verrà indicato come `status: present` con le informazioni sulla versione. Se manca, verrà indicato come `status: MISSING!` e verrà aggiunto un avviso in fondo all'output di `doctor`.

<Accordion title="Esempio di output delle dipendenze (presente)">

```text
- docker
    - status: present
    - version info: Docker version 28.0.4, build b8034c0
```

</Accordion>

<Accordion title="Esempio di output delle dipendenze (mancante)">

```text
- docker
    - status: MISSING!
```

</Accordion>

Se mancano delle dipendenze, il Toolkit quasi certamente non funzionerà.

### Configurazione

La sezione `Configuration` contiene informazioni sui file nella directory `config/`. Per `config/overleaf.rc`, il doctor stampa alcuni valori chiave. I file mancanti verranno indicati come `status: MISSING!` e verrà aggiunto un avviso in fondo all'output di `doctor`.

<Accordion title="Esempio di output della configurazione">

```text
====== Configuration ======
- config/version
    - status: present
    - version: 6.3.2
- config/overleaf.rc
    - status: present
    - values
        - OVERLEAF_DATA_PATH: /tmp/overleaf
        - SERVER_PRO: false
        - MONGO_ENABLED: false
        - REDIS_ENABLED: true
- config/variables.env
    - status: MISSING!
```

</Accordion>

Note sull'esempio precedente:

* `OVERLEAF_DATA_PATH` impostato su `/tmp/overleaf` potrebbe non essere una posizione sicura per dati importanti.
* `MONGO_ENABLED: false` significa che il Toolkit non predisporrà un proprio MongoDB; assicurati che `MONGO_URL` punti a un MongoDB gestito esternamente, se necessario.
* Nell'esempio manca `config/variables.env`.

### Avvisi

La sezione `Warnings` riassume i problemi rilevati dallo script doctor. Se non ci sono problemi, questa sezione lo indicherà.

<Accordion title="Esempio di output degli avvisi">

```text
====== Warnings ======
- configuration file variables.env not found
- rc file, OVERLEAF_DATA_PATH not set
====== End =======
```

</Accordion>

### Q\&A

<Accordion title="I messaggi su quay.io, sulla configurazione di Docker e sul locale di Perl mostrati da `bin/doctor` vanno corretti?">

<strong>Risposta:</strong> No, tutti e tre sono puramente informativi. `bin/doctor` si limita a stampare un report e non blocca `bin/up`.

* `logged in to quay.io: false` e l'avviso `Server Pro enabled, but not logged in to quay.io repository`: questo controllo proviene dal Toolkit ufficiale, in cui l'immagine di Server Pro si trova in un registry privato su quay.io. Con `SERVER_PRO=true`, il Toolkit scarica `ghcr.io/ayaka-notes/overleaf-pro`, che è pubblica, quindi non è necessario alcun login. Ignora questo avviso.
* `grep: /root/.docker/config.json: No such file or directory` (o un'altra home directory): il controllo di quay.io cerca `quay.io` in quel file. Docker lo scrive solo quando ha impostazioni da salvare, ad esempio dopo `docker login`, quindi su molti server non è presente. Non è necessario.
* `perl: warning: Setting locale failed`: il Toolkit usa `perl` solo qui, in `bin/doctor`, per stamparne la versione, e Perl emette un avviso quando `LANG` o `LC_ALL` indicano un locale non installato sull'host. La versione viene comunque stampata. Per eliminare l'avviso, imposta queste variabili su un locale elencato da `locale -a`, ad esempio `C.UTF-8`.

Gli avvisi come `Docker daemon is not running`, `docker not found`, `Docker Compose not found` o un file mancante in `config/` vanno invece corretti: senza di essi il Toolkit non può avviarsi.

</Accordion>
