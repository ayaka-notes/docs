### Il Doctor

L'Overleaf Toolkit include un comodo script `doctor` che aiuta nel debug. Esegui `bin/doctor` e lo script stamperà informazioni sull'ambiente host, sulla tua configurazione e sulle dipendenze necessarie al Toolkit. Questo output può aiutarci anche a diagnosticare problemi delle tue installazioni di Ayakaleaf Pro.

<Info>

Gli utenti di Overleaf Pro possono [aprire una issue su GitHub](https://github.com/ayaka-notes/overleaf/issues).

È una buona idea includere nel messaggio l'output dello script `bin/doctor`.

</Info>

### Consultare il Doctor

Esegui lo script doctor:

```bash title="Run doctor"
bin/doctor
```

### Informazioni sull'host

La sezione `Host Information` contiene informazioni sulla macchina che esegue il Toolkit (ad esempio distribuzione e release di Linux).

<Accordion title="Esempio di output di Host Information">

```text
- Host Information
    - Linux
    - Output of 'lsb_release -a':
            No LSB modules are available.
            Distributor ID:	Ubuntu
            Description:	Ubuntu 22.04.5 LTS
            Release:	22.04
            Codename:	jammy
```

</Accordion>

### Dipendenze

La sezione `Dependencies` elenca gli strumenti necessari al funzionamento del Toolkit. Se uno strumento è presente, verrà indicato come `status: present` con le informazioni sulla versione. Se manca, verrà indicato come `status: MISSING!` e verrà aggiunto un avviso in fondo all'output di `doctor`.

<Accordion title="Esempio di output delle dipendenze (presente)">

```text
- docker
    - status: present
    - version info: Docker version 28.0.4, build b8034c0
```

</Accordion>

<Accordion title="Esempio di output delle dipendenze (mancante)">

```text
- docker
    - status: MISSING!
```

</Accordion>

Se mancano delle dipendenze, quasi certamente il Toolkit non funzionerà.

### Configurazione

La sezione `Configuration` contiene informazioni sui file nella directory `config/`. Per `config/overleaf.rc`, il doctor stampa alcuni valori chiave. I file mancanti verranno indicati come `status: MISSING!` e verrà aggiunto un avviso in fondo all'output di `doctor`.

<Accordion title="Esempio di output di Configuration">

```text
====== Configuration ======
- config/version
    - status: present
    - version: 5.4.0
- config/overleaf.rc
    - status: present
    - values
        - OVERLEAF_DATA_PATH: /tmp/overleaf
        - SERVER_PRO: false
        - MONGO_ENABLED: false
        - REDIS_ENABLED: true
- config/variables.env
    - status: MISSING!
```

</Accordion>

Note sull'esempio sopra:

* `OVERLEAF_DATA_PATH` impostato su `/tmp/overleaf` potrebbe non essere una posizione sicura per dati importanti.
* `MONGO_ENABLED: false` significa che il Toolkit non creerà un proprio MongoDB; se necessario, assicurati che `MONGO_URL` punti a un MongoDB gestito esternamente.
* Nell'esempio manca `config/variables.env`.

### Avvisi

La sezione `Warnings` riepiloga i problemi rilevati dallo script doctor. Se non ci sono problemi, questa sezione lo indicherà.

<Accordion title="Esempio di output di Warnings">

```text
====== Warnings ======
- configuration file variables.env not found
- rc file, OVERLEAF_DATA_PATH not set
====== End =======
```

</Accordion>
