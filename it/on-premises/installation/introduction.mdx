Come Overleaf Server Pro, il nostro Ayakaleaf Pro è distribuito come container Docker ed è un sostituto diretto che include inoltre funzionalità come SSO tramite LDAP e SAML2, sicurezza migliorata, controllo delle modifiche, commenti, la nostra versione ottimizzata di TeX Live, template e pannello di amministrazione.

* Se vuoi solo provare le funzionalità di Ayakaleaf Pro o la demo, puoi seguire il nostro tutorial [using-the-github-codespace.md](/it/on-premises/installation/using-the-github-codespace  "mention"). L'ambiente demo usa un'installazione minima di TeX Live, quindi alcuni dei tuoi progetti potrebbero non compilare correttamente.
* Se non hai mai distribuito alcuna versione di Overleaf, consulta [Configurare Docker](/it/on-premises/installation/setup-docker) per installare prima Docker Engine, quindi installa Overleaf seguendo [using-the-toolkit](/it/on-premises/installation/using-the-toolkit  "mention").
* Se hai già distribuito la Community Edition di Overleaf, consulta [migrate-from-existing.md](/it/on-premises/installation/migrate-from-existing  "mention") per migrare ad Ayakaleaf Pro.
* Se preferisci usare agenti come Claude o Codex, puoi consultare: [using-claude-or-codex.md](/it/on-premises/installation/using-claude-or-codex  "mention").
* Se devi eseguire il deployment in un ambiente offline o air-gapped, consulta: [air-gapped-offline-deployments.md](/it/on-premises/installation/air-gapped-offline-deployments  "mention").
* Se sei già un utente di Server Pro, apri una issue per avvisarci prima di migrare ad Ayakaleaf Pro, poiché i dati dei template sono memorizzati in un formato leggermente diverso. Saremo felici di aiutarti gratuitamente a migrare da Server Pro ad Ayakaleaf Pro.
* Se un giorno ti stancassi del nostro Ayakaleaf Pro e volessi tornare all'Overleaf Community Edition ufficiale, è un'operazione pienamente supportata. Nessun dato andrà perso. Per gli utenti dell'Overleaf Toolkit ufficiale, basta rimuovere il file YAML di override. Per gli utenti del toolkit di ayaka-notes, disattiva l'opzione `SERVER_PRO`. Tutto tornerà quindi alla Community Edition standard.

### Requisiti hardware

Abbiamo condotto alcuni test e abbiamo rilevato che, se esegui Overleaf su un server con 2 core e 2 GB di RAM, i suoi componenti principali, basati prevalentemente su Node.js, consumano circa 1 GB di memoria. Redis e MongoDB possono richiedere altri 0,5 GB, mentre l'avvio di un container Docker in sandbox per la compilazione può consumarne altri 0,3 GB. Ciò significa che un server con 2 core e 2 GB può realisticamente gestire solo circa una compilazione simultanea alla volta.

* I requisiti hardware minimi per installare Ayakaleaf Pro sono una CPU a 2 core e 3 GB di RAM.
* A causa delle dimensioni della nostra immagine TeX Live, sono necessari almeno 40 GB di spazio di archiviazione per abilitare la compilazione in sandbox.
* Se vuoi installare il set completo di immagini TeX Live dal 2020 al 2026, assicurati di avere almeno 150 GB di spazio libero su disco.

Ecco alcune configurazioni hardware consigliate per diversi scenari d'uso:

| Caso d'uso                                             | Configurazione consigliata                                                                            |
| ---------------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| Uso personale, con collaborazione occasionale          | 2 core CPU, 4 GB di RAM, 80 GB di spazio di archiviazione                                                                 |
| Piccoli team, fino a 10 utenti con collaborazione leggera | 2 core CPU, 8 GB di RAM, 256 GB di spazio di archiviazione                                                                |
| Team di medie dimensioni, fino a 100 utenti                  | 4 core CPU, 16 GB di RAM, 1 TB di spazio di archiviazione                                                                 |
| Deployment su larga scala o universitari                | Deployment in cluster distribuito, con archiviazione S3; contattaci se hai bisogno di assistenza per il deployment |

### Requisiti software

Per quanto riguarda i requisiti software, consigliamo di usare una versione recente e stabile di Ubuntu (ad es. Ubuntu 24.04 nel 2025–2026, Ubuntu 22.04 nel 2023–2024) insieme all'ultima versione stabile di Docker.

<Info>

La stabilità viene prima di tutto: scegli la versione LTS di Ubuntu più recente che sia disponibile da un po' di tempo, non una appena rilasciata. Ad esempio, a ottobre 2026, Ubuntu 26.04 non è supportata: include il kernel Linux 7.0, e MongoDB si rifiuta di avviarsi sui kernel Linux dalla 6.19 alla 7.0.13 ([dettagli](https://www.mongodb.com/docs/manual/administration/production-notes/)), quindi usa Ubuntu 24.04.

</Info>

Sconsigliamo di distribuire Ayakaleaf Pro su Windows o su altri sistemi operativi non supportati come CentOS, poiché potresti riscontrare problemi di compatibilità o imprevisti durante l'installazione e il funzionamento.

Se però desideri provare a distribuire Ayakaleaf Pro su sistemi basati su ARM o su macOS, ti invitiamo a condividere la tua esperienza e il tuo feedback con la community.

### Prestazioni di LaTeX

LaTeX è un programma single-thread, il che significa che può utilizzare un solo core della CPU alla volta. Quando si compila un singolo documento, le prestazioni sono limitate principalmente dalla frequenza di clock single-core della CPU. Pertanto, più sono elevate le prestazioni single-core della tua CPU, più velocemente potrai compilare un documento. Un numero maggiore di core della CPU è vantaggioso solo quando più utenti compilano documenti contemporaneamente.

Prendendo come esempio il [template ThuThesis](https://www.overleaf.com/latex/templates/thuthesis-tsinghua-university-thesis-latex-template/cfwgcxtvkbsx), il tempo di compilazione è di circa 6 secondi su un Intel Core i9-14900K (5,6 GHz), mentre richiede circa 13 secondi su un'istanza Azure Standard D2as v5 (2 vCPU, 8 GiB di RAM) basata su AMD EPYC 7763 (3,2 GHz).

Naturalmente, le prestazioni effettive di compilazione dipendono dalla tua configurazione hardware. La maggior parte delle CPU per server non raggiunge frequenze di clock elevate come quelle del 14900K, quindi dovrai trovare un compromesso tra costo e velocità di compilazione.

Abbiamo inoltre condotto un'analisi approfondita delle prestazioni di compilazione di LaTeX. Se ti interessa, consulta il nostro blog [Overleaf Benchmark: A Deep Research of Concurrent LaTeX Compilation in Overleaf (SaaS and Self-host)](/it/blog/2026/overleaf-benchmark  "mention").
