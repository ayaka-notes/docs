---
title: 3. Avviare Ayakaleaf Pro
description: Avvia Ayakaleaf Pro su Podman, verificalo con podman-setup e bin/doctor e avvialo dopo i riavvii.
icon: circle-play
---

<Steps>
<Step title="Avviare i container">
```bash title="Start Ayakaleaf Pro"
bin/up -d
```

Il primo avvio scarica le immagini di MongoDB, Redis e TeX Live e crea le directory dei dati in `data/`. Stampa un avviso che il supporto per Podman è sperimentale.

<Info>

Il primo avvio può anche stampare `MongoNetworkError: connect ECONNREFUSED 127.0.0.1:27017`. Il Toolkit configura il replica set di MongoDB mentre MongoDB si sta ancora avviando e riprova finché non risponde. Puoi ignorare questa riga.

</Info>

Dopo un paio di minuti, controlla che i container siano in esecuzione:

```bash title="List the containers"
podman ps --format "{{.Names}} {{.Status}}"
```

```text
mongo Up 34 seconds (healthy)
redis Up 20 seconds
sharelatex Up 20 seconds
```
</Step>

<Step title="Controllare di nuovo la configurazione">
Ora che le directory dei dati esistono e il container `sharelatex` è in esecuzione, `bin/podman-setup` può completare i suoi controlli:

```bash title="Check the setup"
bin/podman-setup
```

Controlla i proprietari delle nuove directory dei dati e testa il socket di Podman dall'interno del container `sharelatex`:

```text
====== Socket Connectivity ======
[✓] host → socket OK
[✓] container → socket OK

====== Data Directory Permissions ======
[✓] mongo data dir owned by 999
[✓] redis data dir owned by 999
[✓] overleaf data dir owned by 33
...
====== Summary ======
[✓] 27 passed  [!] 1 warnings  [✗] 0 failures
[!] Warnings:
[!] not logged in to quay.io
```

`container → socket OK` significa che Ayakaleaf Pro può avviare i container di compilazione. Se un controllo fallisce, esegui `bin/podman-setup --apply` e poi `bin/up -d`. L'avviso su quay.io non riguarda Ayakaleaf Pro, vedi [2. Eseguire podman-setup](/it/on-premises/installation/using-podman/2.-run-podman-setup).
</Step>

<Step title="Eseguire doctor">
```bash title="Run the doctor"
bin/doctor
```

Su Podman, il report mostra il runtime e le impostazioni di sicurezza:

```text
- Container Daemon
    - status: up
    - runtime: podman
    - server version: 5.8.5
    - socket: /run/user/1000/podman/podman.sock
    - DOCKER_HOST: unix:///run/user/1000/podman/podman.sock
    - host → socket: OK
    - container → socket: OK
- Security
    - SELinux: Enforcing
    - SELINUX_MODE: managed
    - SELINUX_LABEL: sharelatex_t
    - SELinux module: loaded (podman_socket_clsi)
    - SELinux rules: present
    - Seccomp profile: present
```

L'avviso `Server Pro enabled, but not logged in to quay.io repository` alla fine è lo stesso controllo su quay.io, vedi [Ottenere aiuto](/it/on-premises/support/getting-help#q-and-a).
</Step>

<Step title="Avviare Ayakaleaf Pro dopo un riavvio">
Con Docker, il daemon Docker riavvia i container dopo un riavvio. Podman rootless non ha un daemon: abilita il servizio utente che avvia i tuoi container all'avvio del server:

```bash title="Start the containers at boot"
systemctl --user enable podman-restart.service
```

Avvia ogni container del tuo utente con policy di riavvio `always`, che il Toolkit imposta per tutti i suoi container. Richiede il lingering, che `bin/podman-setup --apply` ha abilitato. Senza questo servizio, esegui `bin/up -d` dopo ogni riavvio.
</Step>

<Step title="Aprire la porta nel firewall">
Per impostazione predefinita, l'istanza accetta solo connessioni dal server stesso, su `http://localhost:8080`. Per aprirla da altri computer, imposta `OVERLEAF_LISTEN_IP` in `config/overleaf.rc` e `OVERLEAF_SITE_URL` in `config/variables.env` come descritto in [5. Personalizzare la tua istanza](/it/on-premises/installation/using-docker-compose/linux/5.-personalizing-your-instance#listen-address-and-port) ed esegui di nuovo `bin/up -d`.

A differenza di Docker, Podman rootless non aggira il firewall dell'host. Se `firewalld` è in esecuzione, come avviene per impostazione predefinita su RHEL, apri la porta:

```bash title="Open port 8080"
sudo firewall-cmd --permanent --add-port=8080/tcp
sudo firewall-cmd --reload
```

Su un server cloud, consenti la porta anche nel security group del provider. Usa HTTPS prima di esporre l'istanza su Internet, vedi [4. Attività post-installazione](/it/on-premises/installation/using-podman/4.-post-installation-tasks#use-https).
</Step>
</Steps>
