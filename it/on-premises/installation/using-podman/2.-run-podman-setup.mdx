`bin/podman-setup` controlla tutto ciò di cui Ayakaleaf Pro ha bisogno su Podman. Senza opzioni si limita a riportare i risultati; con `--apply` corregge anche ciò che trova.

<Steps>
<Step title="Controllare l'host">
```bash title="Check only"
bin/podman-setup
```

Su un host nuovo la maggior parte dei controlli fallisce, ad esempio:

```text
====== Packages ======
[✗] podman not installed
[✗] podman-docker not installed
...
====== Summary ======
[✓] 7 passed  [!] 13 warnings  [✗] 4 failures
```
</Step>

<Step title="Applicare le correzioni">
```bash title="Check and fix"
bin/podman-setup --apply
```

Eseguilo in un terminale: chiede la tua password `sudo` per i passaggi a livello di sistema. Scarica anche l'immagine di Ayakaleaf Pro per estrarne il profilo seccomp, operazione che la prima volta richiede alcuni minuti. Alla fine controlla di nuovo l'host:

```text
====== Summary ======
[✓] 23 passed  [!] 2 warnings  [✗] 0 failures
[!] Warnings remaining:
[!] not logged in to quay.io
[!] container → socket skipped (sharelatex not running)
```

Entrambi gli avvisi sono previsti a questo punto:

* `not logged in to quay.io`: il controllo proviene dal Toolkit ufficiale, dove l'immagine di Server Pro si trova in un registry privato. Le immagini di Ayakaleaf Pro sono pubbliche su `ghcr.io` e non richiedono login, quindi ignoralo. Resta anche dopo l'installazione.
* `container → socket skipped (sharelatex not running)`: questo test richiede l'istanza in esecuzione. Eseguirai di nuovo lo script in [3. Avviare Ayakaleaf Pro](/it/on-premises/installation/using-podman/3.-start-ayakaleaf-pro).

Lo script termina con `0` quando tutti i controlli passano, con `1` quando ci sono avvisi e con `2` quando ci sono errori. A causa dell'avviso su quay.io, aspettati `1`.
</Step>
</Steps>

### Cosa modifica lo script {#what-the-script-changes}

Con `--apply`, lo script può modificare quanto segue.

A livello di sistema, con `sudo`:

* Installa `podman`, `podman-docker`, `git`, `curl`, `checkpolicy` e `policycoreutils` con `dnf`.
* Abilita il lingering per il tuo utente con `loginctl`, in modo che i tuoi container continuino a funzionare dopo il logout.
* Crea `/etc/containers/nodocker`, che silenzia il messaggio "Emulate Docker CLI using podman".
* Carica il modulo di policy SELinux `podman_socket_clsi`, quando `SELINUX_MODE=managed`.

Per il tuo utente:

* Abilita il servizio utente `podman.socket`, l'API compatibile con Docker che Ayakaleaf Pro usa per avviare le compilazioni.
* Installa Docker Compose v2 da GitHub in `~/.local/bin/docker-compose` e lo collega in `~/.docker/cli-plugins/`.
* Fa usare a Podman questo Compose in `~/.config/containers/containers.conf`.
* Aggiunge gli alias `mongo` e `redis` in `~/.config/containers/registries.conf.d/overleaf-toolkit.conf`, così Podman sa da dove scaricare questi nomi brevi di immagine.

Nel Toolkit:

* Imposta `DOCKER_SOCKET_PATH` e `DOCKER_HOST` in `config/overleaf.rc` su `/run/user/<uid>/podman/podman.sock`.
* Estrae il profilo seccomp per le compilazioni dall'immagine di Ayakaleaf Pro in `config/seccomp/<version>/clsi-profile.json` e imposta `SECCOMP_PROFILE` in `config/variables.env`. A differenza di Docker, Podman ha bisogno di questo profilo come file sull'host.
* Compila il modulo di policy SELinux in `config/selinux/`.
* Imposta i proprietari delle directory dei dati in `data/` con `podman unshare chown`, una volta che esistono.

<Info>

Ogni modifica corrisponde a un controllo. Se modifichi qualcosa a mano, ad esempio in `config/overleaf.rc`, esegui di nuovo `bin/podman-setup` per verificarlo.

</Info>
