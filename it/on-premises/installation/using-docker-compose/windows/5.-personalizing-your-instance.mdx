---
title: 5. Personalizzare la tua istanza
description: Imposta la porta, l'URL del sito e l'immagine TeX Live, abilita le sandboxed compiles e avvia Ayakaleaf Pro su WSL 2.
icon: square-sliders
---

Esegui i comandi e modifica i file in **Ubuntu**, da `~/ayakaleaf-toolkit`.

<Steps>
<Step title="Impostazioni dei container">
Modifica le voci esistenti in `config/overleaf.rc`:

```bash title="config/overleaf.rc"
PROJECT_NAME=ayakaleaf-wsl
SERVER_PRO=true
OVERLEAF_LISTEN_IP=127.0.0.1
OVERLEAF_PORT=8080
SIBLING_CONTAINERS_ENABLED=true
DOCKER_SOCKET_PATH=/var/run/docker.sock
```

Mantieni i percorsi dei dati predefiniti e i servizi MongoDB e Redis inclusi. La porta `8080` è per il browser locale di Windows; il collegamento a `127.0.0.1` la mantiene locale. Le sandboxed compiles usano un container Linux separato per ogni compilazione, invece di eseguire TeX all'interno del container dell'applicazione. Il socket Docker permette all'applicazione di creare quei container, e il Toolkit fornisce il percorso dell'host per i dati di compilazione in `data/overleaf/data/compiles`.
</Step>

<Step title="Impostazioni dell'applicazione">
In `config/variables.env`, imposta questi valori, sostituendo eventuali voci attive con lo stesso nome:

```dotenv title="config/variables.env"
OVERLEAF_SITE_URL=http://localhost:8080
TEX_LIVE_DOCKER_IMAGE=ghcr.io/ayaka-notes/texlive-full:2026.1
ALL_TEX_LIVE_DOCKER_IMAGES=ghcr.io/ayaka-notes/texlive-full:2026.1
ALL_TEX_LIVE_DOCKER_IMAGE_NAMES="TeX Live 2026"
```

L'immagine full include i pacchetti e i font necessari per un'ampia gamma di progetti. Prevedi almeno 40 GB di spazio libero per essa e per l'applicazione, più lo spazio per i dati dei progetti e i futuri aggiornamenti.

Per un rapido test di distribuzione, usa invece l'immagine **basic**, più piccola. È sufficiente per il semplice test con article del passaggio 6, ma non include il set completo di pacchetti e font:

```dotenv
TEX_LIVE_DOCKER_IMAGE=ghcr.io/ayaka-notes/texlive-basic:2026.1
ALL_TEX_LIVE_DOCKER_IMAGES=ghcr.io/ayaka-notes/texlive-basic:2026.1
ALL_TEX_LIVE_DOCKER_IMAGE_NAMES="TeX Live 2026 Basic"
```

Scegli uno di questi set, senza chiavi attive duplicate. Il [Dockerfile](https://github.com/ayaka-notes/texlive-full/blob/main/texlive/2026/Dockerfile.basic) dell'immagine basic include `latexmk`, XeTeX e `fontspec`, ma non `ctex` né la raccolta completa di font. Un pacchetto LaTeX mancante nella basic non indica di per sé un problema della sandbox.

Genera un segreto di sessione:

```bash
openssl rand -hex 32
```

Aggiungi il risultato come `OVERLEAF_SESSION_SECRET` in `config/variables.env`. Conserva anche il segreto del token di invito generato. Per un'istanza locale senza email, lascia non impostati i parametri SMTP e `OVERLEAF_EMAIL_FROM_ADDRESS`.
</Step>

<Step title="Avviare la tua istanza">
```bash
bin/up -d
```

Il Toolkit avvia MongoDB, ne inizializza il replica set, scarica l'immagine TeX Live selezionata e avvia Redis e l'applicazione. Potrebbe sembrare fermo mentre scarica un'immagine di grandi dimensioni. Non eseguire un secondo `bin/up` mentre il primo è ancora in corso.

In un altro terminale Ubuntu, controlla:

```bash
cd "$HOME/ayakaleaf-toolkit"
bin/docker-compose ps
bin/docker-compose logs --tail=100 mongo
bin/docker-compose logs --tail=100 -f sharelatex
```

Premi `Ctrl+C` per smettere di seguire i log; i container in modalità detached continuano a essere eseguiti. Se l'avvio non riesce a livello di MongoDB, segui [MongoDB non si avvia](/it/on-premises/installation/using-docker-compose/windows/troubleshooting#mongodb-fails-to-start) prima di riprovare. Non eliminare la sua directory dei dati per reimpostare un'installazione esistente.

Controlla la porta e la pagina del primo avvio:

```bash
bin/docker-compose port sharelatex 80
curl -I http://localhost:8080/launchpad
```

La porta dovrebbe essere `127.0.0.1:8080`. Se inizialmente la richiesta HTTP non riesce, attendi l'inizializzazione dell'applicazione.
</Step>

<Step title="Aprire l'istanza da Windows">
Nel tuo **browser di Windows**, apri [http://localhost:8080/launchpad](http://localhost:8080/launchpad). Usa questo indirizzo anche in Windows, anziché un indirizzo IP temporaneo di WSL.

Per controllare l'accesso HTTP da Windows indipendentemente dal browser, esegui in **PowerShell**:

```powershell
curl.exe -I http://localhost:8080/launchpad
```

Se Ubuntu riesce a raggiungere la pagina ma Windows no, vedi [Windows non riesce ad aprire localhost](/it/on-premises/installation/using-docker-compose/windows/troubleshooting#windows-cannot-open-localhost).
</Step>
</Steps>
