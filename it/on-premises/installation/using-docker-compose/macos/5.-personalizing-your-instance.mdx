---
title: 5. Personalizzare la tua istanza
description: Imposta la porta, l'URL del sito e l'immagine TeX Live per un'istanza locale sul tuo Mac, controlla il kernel della VM di Docker e avvia Ayakaleaf Pro.
icon: square-sliders
---

<Steps>
<Step title="Impostazioni dei container">
Modifica queste voci esistenti in `config/overleaf.rc`:

```bash title="config/overleaf.rc"
PROJECT_NAME=ayakaleaf-macos
SERVER_PRO=true
OVERLEAF_LISTEN_IP=127.0.0.1
OVERLEAF_PORT=8080
SIBLING_CONTAINERS_ENABLED=true
DOCKER_SOCKET_PATH=/var/run/docker.sock
```

Mantieni i percorsi dei dati predefiniti e i servizi MongoDB e Redis inclusi. Con `OVERLEAF_LISTEN_IP=127.0.0.1`, solo i browser su questo Mac possono aprire l'istanza.
</Step>

<Step title="Impostazioni dell'applicazione">
In `config/variables.env`, imposta questi valori, sostituendo eventuali voci attive con lo stesso nome:

```dotenv title="config/variables.env"
OVERLEAF_SITE_URL=http://localhost:8080
TEX_LIVE_DOCKER_IMAGE=ghcr.io/ayaka-notes/texlive-full:2026.1
ALL_TEX_LIVE_DOCKER_IMAGES=ghcr.io/ayaka-notes/texlive-full:2026.1
ALL_TEX_LIVE_DOCKER_IMAGE_NAMES="TeX Live 2026"
```

Genera un segreto di sessione:

```bash
openssl rand -hex 32
```

Aggiungi il risultato come `OVERLEAF_SESSION_SECRET` in `config/variables.env`. Senza di esso, ogni `bin/up` che ricrea il container disconnette tutti gli utenti; vedi [Variabili d'ambiente](/it/on-premises/configuration/overleaf-toolkit/environment-variables).

Per un'istanza locale senza email, lascia non impostati i parametri SMTP e `OVERLEAF_EMAIL_FROM_ADDRESS`. Git Bridge, l'autenticazione esterna e le altre integrazioni possono essere aggiunti in seguito con le rispettive [pagine di configurazione](/it/on-premises/configuration/overleaf-toolkit).
</Step>

<Step title="Controllare il kernel Linux della VM di Docker" id="check-the-docker-vms-linux-kernel">
MongoDB viene eseguito sul kernel Linux della macchina virtuale di Docker Desktop, non su macOS. Controllane la versione prima del primo avvio:

```bash
docker info --format '{{.KernelVersion}}'
```

MongoDB documenta un'incompatibilità con i kernel Linux **dalla 6.19 alla 7.0.13**, che riguarda anche MongoDB in Docker. La soluzione è un kernel **7.0.14 o successivo**, che arriva con un aggiornamento di Docker Desktop; vedi le [note di produzione di MongoDB](https://www.mongodb.com/docs/manual/administration/production-notes/).

Se la tua VM di Docker usa un kernel interessato, aggiungi quanto segue a `config/docker-compose.override.yml`, unendolo a eventuali `services` già presenti:

```yaml title="config/docker-compose.override.yml"
services:
  mongo:
    environment:
      GLIBC_TUNABLES: glibc.pthread.rseq=1
```

<Warning>

Passa a un kernel corretto non appena disponibile. Se il tuo kernel è al di fuori dell'intervallo interessato, questa soluzione alternativa non è necessaria.

</Warning>
</Step>

<Step title="Avviare la tua istanza">
Dalla directory del Toolkit, esegui:

```bash
bin/up -d
```

Il Toolkit inizializza il replica set di MongoDB, scarica l'immagine TeX Live e avvia l'applicazione. Il primo download richiede un po' di tempo. Per seguire l'avanzamento:

```bash
bin/docker-compose ps
bin/docker-compose logs --tail=100 -f sharelatex
```

Premi `Ctrl+C` per smettere di seguire i log. I container continuano a essere eseguiti.

Controlla la porta pubblicata e la pagina del primo avvio:

```bash
bin/docker-compose port sharelatex 80
curl -I http://localhost:8080/launchpad
```

La porta dovrebbe essere `127.0.0.1:8080`.
</Step>
</Steps>

<Info>

Per aprire in seguito l'istanza da altri computer, cambia l'indirizzo di ascolto e l'URL del sito e configura HTTPS, come descritto in [5. Personalizzare la tua istanza](/it/on-premises/installation/using-docker-compose/linux/5.-personalizing-your-instance) della guida per Linux. Il Mac deve quindi restare attivo; vedi [Mantenere l'istanza disponibile](/it/on-premises/installation/using-docker-compose/macos/6.-post-installation-tasks#keep-the-instance-available).

</Info>
