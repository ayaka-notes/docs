### Creare l'amministratore e un primo progetto {#create-the-administrator-and-a-first-project}

Apri [http://localhost:8080/launchpad](http://localhost:8080/launchpad), crea il primo account amministratore ed effettua l'accesso. Poi segui [6. Attività post-installazione](/it/on-premises/installation/using-docker-compose/linux/6.-post-installation-tasks) della guida per Linux, usando la porta `8080` nei suoi URL di esempio.

### Verificare la compilazione {#verify-compilation}

Una pagina di accesso che si apre non dimostra che i container di compilazione separati e i loro mount dei dati funzionino. Crea un progetto vuoto e compila questo `main.tex`:

```latex
\documentclass{article}
\begin{document}
Ayakaleaf Pro on macOS.
\end{document}
```

L'anteprima PDF dovrebbe mostrare il testo. Se necessario, seleziona TeX Live 2026 nelle impostazioni del progetto.

Per un progetto con testo cinese, seleziona **XeLaTeX** come compilatore e prova:

```latex
\documentclass{ctexart}
\begin{document}
你好，Ayakaleaf Pro。
\end{document}
```

### Verificare la persistenza {#verify-persistence}

```bash
bin/stop
bin/start
```

Riapri il progetto e compilalo di nuovo. Il tuo account, il sorgente e i file del progetto dovrebbero essere ancora presenti. Con i percorsi predefiniti, i dati in uso si trovano nella directory `data/` del Toolkit sul tuo Mac.

### Mantenere l'istanza disponibile {#keep-the-instance-available}

Mentre il Mac è in sospensione, macOS sospende la macchina virtuale di Docker Desktop con tutti i container al suo interno: nessuno può aprire l'istanza, e una compilazione in corso si interrompe finché il Mac non si riattiva. Conta solo la sospensione del sistema. Lo schermo può spegnersi.

Se altre persone usano l'istanza, o lasci in esecuzione attività lunghe, tieni il Mac collegato alla corrente e impedisci la sospensione automatica; vedi [Impostare le opzioni di stop e riattivazione del Mac](https://support.apple.com/guide/mac-help/set-sleep-and-wake-settings-mchle41a6ccd/mac):

| Mac | Impostazione |
| --- | --- |
| Mac desktop (Mac mini, iMac, Mac Studio, Mac Pro) | **System Settings → Energy**: attiva **Prevent automatic sleeping when the display is off** |
| MacBook | **System Settings → Battery → Options**: attiva **Prevent automatic sleeping on power adapter when the display is off**. Vale solo mentre l'alimentatore è collegato, e chiudere il coperchio mette comunque il MacBook in sospensione |

Per tenere il Mac attivo solo per un certo tempo, esegui invece `caffeinate -i` in una finestra del Terminale. Impedisce la sospensione per inattività finché non premi `Ctrl+C` o chiudi la finestra.

Docker Desktop è un'app nella tua sessione utente. Per riavere l'istanza dopo un riavvio, attiva **Start Docker Desktop when you sign in to your computer** in **Settings → General** di Docker Desktop. I container del Toolkit usano `restart: always`, quindi Docker li riavvia non appena Docker Desktop è in esecuzione, senza `bin/up`. Finché qualcuno non accede al Mac dopo un riavvio, l'istanza resta non disponibile.

<Info>

Un Mac che resta attivo consuma più energia. Per un servizio che deve essere sempre raggiungibile, consigliamo un server Linux; vedi [Linux](/it/on-premises/installation/using-docker-compose/linux).

</Info>

### Uso quotidiano {#daily-use}

Apri Docker Desktop prima di gestire l'istanza. In un nuovo terminale:

```bash
export PATH="$(brew --prefix gnu-sed)/libexec/gnubin:$PATH"
cd "$HOME/ayakaleaf-toolkit"
```

| Attività | Comando |
| --- | --- |
| Avviare i container esistenti | `bin/start` |
| Arrestare i container mantenendo i dati | `bin/stop` |
| Applicare le modifiche alla configurazione | `bin/up -d` |
| Controllare lo stato | `bin/docker-compose ps` |
| Leggere i log di avvio | `bin/docker-compose logs --tail=100 sharelatex` |
| Leggere i log del compilatore | `bin/logs -f clsi` |

`bin/start` non applica le modifiche in `config/`: esegui `bin/up -d` dopo aver modificato la configurazione. Conserva `config/` e `data/`, e segui [Dati e backup](/it/on-premises/maintenance/data-and-backups) prima di un aggiornamento o prima di spostare l'installazione. Copiare i file del database mentre MongoDB vi scrive non costituisce un backup coerente.

Mantieni l'istanza su `127.0.0.1` per l'uso locale. Per servire altri computer, imposta deliberatamente l'indirizzo di ascolto, l'URL del sito e HTTPS; vedi [5. Personalizzare la tua istanza](/it/on-premises/installation/using-docker-compose/linux/5.-personalizing-your-instance) della guida per Linux.

Se qualcosa non funziona, consulta [Risoluzione dei problemi](/it/on-premises/installation/using-docker-compose/macos/troubleshooting).
