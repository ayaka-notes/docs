Ayakaleaf Pro funziona su Docker. Su un Mac usi Docker Desktop, che esegue il motore Docker in una macchina virtuale Linux.

<Steps>
<Step title="Installare e avviare Docker Desktop">
Installa la build di [Docker Desktop](https://docs.docker.com/desktop/setup/install/mac-install/) adatta al tuo Mac (Apple silicon o Intel), aprila e attendi che il motore sia avviato. Puoi anche avviarlo dal Terminale:

```bash
open -a Docker
```
</Step>

<Step title="Controllare il motore Docker">
Esegui questi comandi nel Terminale:

```bash
docker context show
docker info
docker compose version
```

Il contesto dovrebbe puntare al motore Docker Desktop locale, normalmente `desktop-linux`. Se è selezionato un altro contesto, passa a Docker Desktop prima di continuare:

```bash
docker context use desktop-linux
```

`docker info` deve stampare una sezione **Server**. `docker --version` da solo mostra soltanto che il client è installato.
</Step>

<Step title="Controllare le risorse e la condivisione dei file">
In **Settings** di Docker Desktop, confronta i limiti di CPU, memoria e disco con [Prima di iniziare](/it/on-premises/installation/using-docker-compose/macos#before-you-start) e controlla le impostazioni di condivisione dei file; vedi [Docker Desktop settings](https://docs.docker.com/desktop/settings-and-maintenance/settings/).

Questa guida mantiene il Toolkit sotto `/Users`, che Docker Desktop condivide per impostazione predefinita. Se usi un'altra posizione e `bin/up` non riesce con `Mounts denied`, aggiungi quella directory alla condivisione dei file.
</Step>

<Step title="Controllare il socket Docker per le sandboxed compiles">
Il Toolkit monta `/var/run/docker.sock` nell'applicazione, in modo che possa avviare un container TeX Live separato per ogni compilazione. Mantieni `DOCKER_SOCKET_PATH=/var/run/docker.sock` in `config/overleaf.rc`.

La CLI di Docker su macOS può connettersi tramite `~/.docker/run/docker.sock`. Quello è l'endpoint del client sul Mac, non un motivo per cambiare l'origine del mount del Toolkit: il compilatore ha bisogno del socket del motore così come lo vedono i container Linux.

Se `/var/run/docker.sock` manca sul Mac, attiva **Allow the default Docker socket to be used** in **Settings → Advanced**; vedi i [requisiti di autorizzazione di Docker](https://docs.docker.com/desktop/setup/install/mac-permission-requirements/).

<Danger>

Non eseguire `chmod 777` sul socket per aggirare gli errori. L'accesso al socket Docker equivale all'accesso root alla VM di Docker.

</Danger>
</Step>
</Steps>

### Passaggio successivo {#next-step}
