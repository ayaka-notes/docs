### Personalizzare la tua istanza

Prima di avviare la tua istanza di Overleaf per la prima volta, aggiorna due file di configurazione con le tue informazioni personalizzate:

| File                   | Letto da                                   | Cosa si imposta                                                   |
| ---------------------- | ------------------------------------------ | ----------------------------------------------------------------- |
| `config/overleaf.rc`   | gli script del Toolkit, come `bin/up`      | come vengono eseguiti i container: `OVERLEAF_LISTEN_IP`, `OVERLEAF_PORT`, `SERVER_PRO`, percorsi dei dati |
| `config/variables.env` | l'applicazione all'interno del container   | il comportamento di Overleaf: `OVERLEAF_SITE_URL`, email, immagini TeX Live |

<Steps>
<Step title="Modificare il file delle variabili">
Apri `config/variables.env` nel tuo editor di testo preferito e aggiorna le variabili d'ambiente seguenti con i valori richiesti.
</Step>

<Step title="Indirizzo e porta di ascolto">
Per impostazione predefinita, il Toolkit pubblica l'interfaccia web su `127.0.0.1:80`, quindi può essere aperta solo da un browser sul server stesso. Gli altri computer ricevono un errore "connection refused" o "server not found". Per modificare questo comportamento, modifica `config/overleaf.rc`:

```bash title="config/overleaf.rc"
OVERLEAF_LISTEN_IP=0.0.0.0
OVERLEAF_PORT=8080
```

`OVERLEAF_LISTEN_IP` è l'indirizzo IP dell'host a cui si collega il container, e `OVERLEAF_PORT` è la porta dell'host. Insieme formano la mappatura delle porte Docker `OVERLEAF_LISTEN_IP:OVERLEAF_PORT:80`. Scegli i valori adatti alla tua configurazione:

| Configurazione                                                                  | `OVERLEAF_LISTEN_IP`                  | `OVERLEAF_PORT`              | Da aprire nel browser         |
| ------------------------------------------------------------------------------- | ------------------------------------- | ---------------------------- | ----------------------------- |
| Solo su questa macchina (predefinito)                                           | `127.0.0.1`                           | `80`                         | `http://localhost`            |
| Altri computer della LAN o di Internet si connettono direttamente               | `0.0.0.0`, o un IP del server         | `80`, o qualsiasi porta libera | `http://<server-ip>:<port>` |
| Dietro un tuo reverse proxy (NGINX, Caddy, Cloudflare Tunnel) sullo stesso host | `127.0.0.1`                           | qualsiasi porta libera       | l'URL del proxy               |
| Dietro il [TLS proxy](/it/on-premises/configuration/overleaf-toolkit/tls-proxy) del Toolkit | `127.0.0.1`               | `80`                         | `https://<your-domain>`       |

Se la porta `80` è già in uso sull'host, ad esempio da un altro server web, imposta `OVERLEAF_PORT` su una porta libera come `8080`. Altrimenti `bin/up` non riesce con `bind: address already in use`.

<Warning>

Le porte pubblicate da Docker aggirano i firewall dell'host come `ufw` e `firewalld`. Con `0.0.0.0`, l'istanza è raggiungibile da ogni rete a cui il server è connesso. Su un server cloud, devi anche consentire la porta nel security group del provider. Usa HTTPS prima di esporre l'istanza a Internet, vedi [TLS proxy](/it/on-premises/configuration/overleaf-toolkit/tls-proxy).

</Warning>

Puoi iniziare con il valore predefinito e aprire prima l'istanza su `localhost`. Per consentire in seguito l'accesso da altri computer, modifica queste due variabili in `config/overleaf.rc` e `OVERLEAF_SITE_URL` in `config/variables.env`, quindi esegui di nuovo `bin/up` per ricreare i container.
</Step>

<Step title="Variabili d'ambiente obbligatorie">
Aggiorna le seguenti variabili in `config/variables.env`:

| Nome                          | Descrizione                                                                                                                                                    | Esempio                         |
| ----------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------- |
| `OVERLEAF_SITE_URL`           | L'indirizzo a cui la tua istanza di Overleaf è accessibile pubblicamente. Viene usato nei link pubblici e nelle connessioni tramite websocket, quindi **deve essere configurato correttamente**! | `https://overleaf.lilliput.com` |
| `OVERLEAF_EMAIL_FROM_ADDRESS` | Questo indirizzo email verrà usato come indirizzo `from` per tutte le email in uscita.                                                                        | `no-reply@lilliput.com`         |
| `OVERLEAF_ADMIN_EMAIL`        | L'indirizzo email a cui gli utenti possono contattare il responsabile del sito.                                                                                | `it-services@lilliput.com`      |

`OVERLEAF_SITE_URL` è l'indirizzo che gli utenti digitano nel browser, non l'indirizzo di ascolto. Includi la porta quando non è `80` (HTTP) o `443` (HTTPS), ad esempio `http://192.168.1.20:8080`. Non usare `http://0.0.0.0`. Se `OVERLEAF_SITE_URL` non corrisponde all'indirizzo nel browser, l'editor non riesce a connettersi e i link nelle email e i callback OAuth puntano al posto sbagliato.

Imposta inoltre `OVERLEAF_SESSION_SECRET` su un valore generato con `openssl rand -hex 32`. Senza di essa, ogni `bin/up` che ricrea il container, e ogni aggiornamento, disconnette tutti gli utenti. Vedi le Q\&A in [Variabili d'ambiente](/it/on-premises/configuration/overleaf-toolkit/environment-variables).

Dopo aver aggiornato queste variabili d'ambiente, salva ed esci.
</Step>

<Step title="Configurare le Sandbox Compiles">
Quindi configura TeX Live Full per le [sandboxed-compiles.md](/it/on-premises/configuration/overleaf-toolkit/sandboxed-compiles  "mention"). Apri `config/variables.env` e aggiorna le seguenti variabili d'ambiente:

```dotenv title="config/variables.env" wrap
ALL_TEX_LIVE_DOCKER_IMAGES=ghcr.io/ayaka-notes/texlive-full:2026.1, ghcr.io/ayaka-notes/texlive-full:2025.1
ALL_TEX_LIVE_DOCKER_IMAGE_NAMES=Texlive 2026, Texlive 2025
TEX_LIVE_DOCKER_IMAGE=ghcr.io/ayaka-notes/texlive-full:2026.1
```
</Step>

<Step title="Avviare la tua istanza">
Per avviare la tua istanza esegui:

```text title="Start the instance"
bin/up
```

Questo comando scaricherà le immagini necessarie, incluso TeX Live, creerà i container (usando le tue personalizzazioni) e avvierà l'istanza. Dovresti vedere l'output dei log dei vari container Docker.

Per avviarli di nuovo in seguito (senza collegarti all'output dei log) esegui:

```text title="Start without attaching to logs"
bin/start
```
</Step>
</Steps>

<Info>

Il Toolkit usa `docker compose` per gestire i container Docker di Overleaf. Il Toolkit fornisce una serie di script che incapsulano `docker compose` e si occupano per te della maggior parte dei dettagli.

</Info>

Se tutto va bene, dovresti riuscire a visualizzare la pagina di accesso della tua nuova istanza di Overleaf visitando [http://127.0.0.1/](http://127.0.0.1/) o [http://localhost/](http://localhost/) nel browser. Se hai modificato `OVERLEAF_LISTEN_IP` o `OVERLEAF_PORT`, apri invece l'indirizzo indicato nella tabella del passaggio **Indirizzo e porta di ascolto**, ad esempio `http://<server-ip>:8080`.

Per verificare su quale indirizzo e porta è pubblicata l'interfaccia web, esegui:

```text title="Show the published port"
bin/docker-compose port sharelatex 80
```

L'output, ad esempio `0.0.0.0:8080`, mostra l'indirizzo IP e la porta dell'host in uso. Se mostra `127.0.0.1`, l'istanza è raggiungibile solo dal server stesso.

<Warning>

A seconda della configurazione di rete e di dove è ospitata la tua istanza di Overleaf, potrebbero essere necessarie ulteriori modifiche alla configurazione. Per maggiori dettagli, consulta le impostazioni del Toolkit: [toolkit-settings.md](/it/on-premises/configuration/overleaf-toolkit/toolkit-settings  "mention")

</Warning>
