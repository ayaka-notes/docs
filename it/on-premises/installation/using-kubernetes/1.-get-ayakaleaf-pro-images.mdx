---
title: 1. Ottenere le immagini di Ayakaleaf Pro
description: Usa le stesse immagini di Ayakaleaf Pro del Toolkit.
icon: split
---

Kubernetes esegue le stesse immagini del Toolkit. Non esiste un'immagine separata per Kubernetes.

| Immagine                                             | Usata da                                                                |
| ---------------------------------------------------- | ----------------------------------------------------------------------- |
| `ghcr.io/ayaka-notes/overleaf-pro:6.3.2`             | il Deployment `overleaf`                                                |
| `ghcr.io/ayaka-notes/overleaf-pro/git-bridge:6.3.2`  | [Integrazione Git](/it/on-premises/configuration/kubernetes/integrations/git-integration) (facoltativa), stesso tag di sopra |
| `ghcr.io/ayaka-notes/texlive-*`                      | compilazioni, scaricate in Docker sui nodi al [passaggio 0](/it/on-premises/installation/using-kubernetes/0.-prepare-the-nodes) |

Le immagini sono pubbliche su [ghcr.io](https://github.com/ayaka-notes/ayakaleaf-pro/pkgs/container/overleaf-pro/) per amd64 e arm64, quindi il kubelet può scaricarle senza credenziali.

<Warning>

Usa sempre un tag di versione, come `6.3.2`, non `latest`. Gli aggiornamenti eseguono migrazioni del database e devono seguire [Aggiornare su Kubernetes](/it/on-premises/maintenance/upgrading-on-kubernetes); un tag mobile aggiornerebbe un pod ogni volta che viene ripianificato.

</Warning>

### Q\&A

<Accordion title="I nostri nodi non riescono a raggiungere ghcr.io. Cosa dobbiamo fare?">

<strong>Risposta:</strong> Copia le immagini in un registry raggiungibile dai nodi e usa quel nome nei manifest, ad esempio:

```bash
docker pull ghcr.io/ayaka-notes/overleaf-pro:6.3.2
docker tag ghcr.io/ayaka-notes/overleaf-pro:6.3.2 registry.example.com/ayakaleaf/overleaf-pro:6.3.2
docker push registry.example.com/ayakaleaf/overleaf-pro:6.3.2
```

Per un registry senza TLS, containerd necessita su ogni nodo di un file `/etc/containerd/certs.d/<registry>/hosts.toml` con `server = "http://<registry>"`, e di `config_path` impostato come al [passaggio 0](/it/on-premises/installation/using-kubernetes/0.-prepare-the-nodes). Docker stesso esegue il push su HTTP in chiaro solo verso `localhost`, quindi esegui il push tramite `localhost:<port>` sull'host del registry oppure aggiungilo a `insecure-registries`.

</Accordion>
