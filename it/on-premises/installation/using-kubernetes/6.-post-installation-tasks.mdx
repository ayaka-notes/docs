### Creare il primo account amministratore

Apri `OVERLEAF_SITE_URL` seguito da `/launchpad`, ad esempio `http://192.0.2.10:30080/launchpad`, e registra l'account amministratore come descritto nelle [attività post-installazione del Toolkit](/it/on-premises/installation/using-the-toolkit/6.-post-installation-tasks). Poi crea un progetto di esempio e compilalo.

Puoi anche creare utenti dalla riga di comando:

```bash
kubectl -n overleaf exec deploy/overleaf -- bash -c \
  'cd /overleaf/services/web && node modules/server-ce-scripts/scripts/create-user.mjs --admin --email=admin@example.com'
```

Il comando stampa un link per impostare la password.

### Verificare che le compilazioni siano in sandbox

Compila un progetto, poi controlla il nodo che esegue il pod:

```bash
kubectl -n overleaf get pod -l app=overleaf -o wide   # NODE column
# on that node:
sudo docker ps -a --filter ancestor=ghcr.io/ayaka-notes/texlive-full:2026.1
ls -ln /srv/overleaf/compiles                          # owned by uid 33 (www-data)
```

Ogni compilazione compare come un container di breve durata denominato `project-<project id>-<user id>-...`.

### Log e shell

| Toolkit          | Kubernetes                                                               |
| ---------------- | ------------------------------------------------------------------------ |
| `bin/logs web`   | `kubectl -n overleaf exec deploy/overleaf -- tail -f /var/log/overleaf/web.log` |
| `bin/shell`      | `kubectl -n overleaf exec -it deploy/overleaf -- bash`                    |
| `bin/up`         | `kubectl apply -f .` e poi `kubectl -n overleaf rollout restart deployment/overleaf` |

Il container scrive un file di log per ogni servizio in `/var/log/overleaf/` (`web.log`, `clsi.log`, `real-time.log`, `document-updater.log`, ...); `kubectl logs` mostra l'output di avvio.

### Q\&A

<Accordion title="La compilazione fallisce o non termina mai.">

<strong>Risposta:</strong> Sul nodo che esegue il pod, verifica che Docker sia in esecuzione e disponga dell'immagine indicata in `TEX_LIVE_DOCKER_IMAGE`, e che `SANDBOXED_COMPILES_HOST_DIR_*` corrispondano ai percorsi `hostPath`. Il file `/var/log/overleaf/clsi.log` nel pod indica il passaggio che fallisce.

</Accordion>

<Accordion title="Gli utenti vengono disconnessi a ogni riavvio del pod.">

<strong>Risposta:</strong> Manca `OVERLEAF_SESSION_SECRET` nel Secret `overleaf-secrets`, vedi il [passaggio 2](/it/on-premises/installation/using-kubernetes/2.-create-the-namespace-and-secrets).

</Accordion>
