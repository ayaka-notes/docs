Il [Toolkit](/it/on-premises/installation/using-docker-compose) è il metodo consigliato per eseguire Ayakaleaf Pro su un singolo server. Se gestisci già un cluster Kubernetes, questa sezione distribuisce lo stesso container su di esso con semplici manifest `kubectl`: nessuna immagine aggiuntiva, nessun chart Helm.

Al termine di questa sezione avrai un'istanza di Ayakaleaf Pro con sandboxed compiles, un replica set MongoDB e Redis, tutto nel namespace `overleaf`. Per eseguire più istanze dietro un load balancer, prosegui poi con [Scalabilità orizzontale](/it/on-premises/configuration/kubernetes/horizontal-scaling).

<Info>

Il supporto a Kubernetes è sperimentale. Non pubblichiamo un chart Helm né immagini specifiche per Kubernetes. I manifest di queste pagine sono quelli che abbiamo testato su Kubernetes 1.37 (kubeadm, containerd 2.4, flannel) con tre nodi da 2 vCPU e 4 GB di memoria ciascuno. Adatta storage, rete e ingress al tuo cluster.

</Info>

### Come si combinano i componenti {#how-the-pieces-fit}

| Toolkit (un server)                          | Kubernetes                                                               |
| -------------------------------------------- | ------------------------------------------------------------------------ |
| `config/variables.env`                       | ConfigMap `overleaf-env` e Secret `overleaf-secrets`                     |
| Container `sharelatex`                       | Deployment `overleaf` (un pod che esegue tutti i servizi di Overleaf)    |
| Container `mongo` e `redis`                  | StatefulSet `mongo` (replica set) e `redis`, oppure i tuoi servizi gestiti |
| `~/overleaf-toolkit/data/overleaf`           | PersistentVolumeClaim `overleaf-data`                                    |
| Docker sull'host, usato per le compilazioni  | Docker Engine su ogni nodo che esegue Ayakaleaf Pro                      |
| `bin/up`, `bin/logs`, `bin/shell`            | `kubectl apply`, `kubectl logs`, `kubectl exec`                          |

### Cosa ti serve {#what-you-need}

* Un cluster Kubernetes su cui puoi installare pacchetti: ogni nodo che può eseguire Ayakaleaf Pro necessita di **Docker Engine**, perché le compilazioni vengono eseguite in container TeX Live che Ayakaleaf Pro avvia tramite il `/var/run/docker.sock` del nodo. Vedi [0. Preparare i nodi](/it/on-premises/installation/using-kubernetes/0.-prepare-the-nodes).
* Una StorageClass predefinita con volumi `ReadWriteOnce`.
* `kubectl` e `openssl` sulla tua workstation.
