Usa Claude Code o Codex per pianificare ed eseguire un'installazione di Ayakaleaf Pro. Durante il lavoro, l'agente può consultare questa documentazione tramite MCP.

L'agente assiste nell'installazione. Resta tua la responsabilità di rivedere i comandi e proteggere le credenziali.

### Prima di iniziare

Prepara un server Linux supportato con accesso SSH. Prima di continuare, consulta i [requisiti](/it/on-premises/getting-started/requirements  "mention").

<Warning>

Non incollare password, chiavi private, token o chiavi di licenza nei prompt dell'agente. Rivedi ogni comando prima di eseguirlo, in particolare i comandi che modificano file, reti o container.

</Warning>

### Collegare la documentazione

Aggiungi l'endpoint MCP della documentazione al tuo agente locale.

<Tabs>
<Tab title="Claude Code">

```bash wrap
claude mcp add ayakaleaf-pro --scope user --transport http https://ayakaleaf-pro.ayaka.space/~gitbook/mcp
```

</Tab>

<Tab title="Codex">

```bash wrap
codex mcp add ayakaleaf-pro --url https://ayakaleaf-pro.ayaka.space/~gitbook/mcp
```

</Tab>
</Tabs>

Avvia una nuova sessione dopo aver aggiunto il server. Chiedi all'agente di confermare di poter consultare la documentazione di Ayakaleaf Pro.

### Distribuire Ayakaleaf Pro

Apri un terminale sul server di installazione e avvia lì Claude Code o Codex. Quindi invia questo prompt:

```text wrap
Use the Ayakaleaf Pro documentation MCP server to guide this deployment.
First, inspect the requirements and installation guides.
Ask me for missing deployment details before making changes.
Use the Ayakaleaf Toolkit unless the documentation requires another approach.
Before configuring the instance, summarize relevant optional features.
Ask which features and integrations I want to enable.
Include TLS, sandboxed compiles, Git integration, external MongoDB or Redis,
SSO (OIDC, SAML, or LDAP), GitHub Synchronisation, Zotero, S3 storage,
email delivery, branding, and localization when relevant.
Explain each selected option's prerequisites, security impact, and configuration steps.
Keep unselected optional features disabled.
Show each command before running it.
Do not expose, store, or request secrets in chat.
After deployment, verify that the service is healthy and summarize the changes.
```

L'agente dovrebbe guidarti nella configurazione di Docker, nella configurazione del Toolkit, nel recupero delle immagini e nell'avvio. Segui la guida [using-the-toolkit](/it/on-premises/installation/using-the-toolkit  "mention") per il flusso di lavoro di riferimento.

### Scegliere le funzionalità opzionali

Chiedi all'agente di consigliare solo le funzionalità adatte al tuo ambiente. Le scelte tipiche includono:

* **Accesso e sicurezza:** TLS, compilazioni in sandbox e SSO tramite OIDC, SAML o LDAP.
* **Servizi esterni:** MongoDB, Redis, storage S3 e invio delle email.
* **Collaborazione:** integrazione Git, GitHub Synchronisation e Zotero.

L'agente dovrebbe spiegare le dipendenze prima di modificare la configurazione. Consulta [toolkit-settings.md](/it/on-premises/configuration/overleaf-toolkit/toolkit-settings  "mention") e [authentication](/it/on-premises/configuration/overleaf-toolkit/authentication  "mention") prima di abilitare le integrazioni in produzione.

### Verificare l'installazione

Dopo che l'agente ha completato i passaggi:

1. Verifica che ogni comando sia stato completato senza errori.
2. Apri nel browser l'URL di Ayakaleaf Pro configurato.
3. Completa le [6.-post-installation-tasks.md](/it/on-premises/installation/using-the-toolkit/6.-post-installation-tasks  "mention").

Per un'installazione esistente di Community Edition, usa la guida [migrate-from-existing.md](/it/on-premises/installation/migrate-from-existing  "mention") invece di una nuova installazione.
