Siamo davvero orgogliosi di annunciare il rilascio di Overleaf Pro 6.3.1, l'editor LaTeX online più potente e ricco di funzionalità della community. Una patch release di solito significa una manciata di piccole correzioni. Questa va molto oltre: insieme a decine di correzioni di bug, porta cinque nuove funzionalità e collega i tuoi progetti ai luoghi in cui lavori già, da Dropbox e GitLab fino all'agente AI nel tuo terminale.

### Modifiche

* Sincronizzazione con Dropbox (anteprima): mantieni ogni progetto sincronizzato con il tuo Dropbox, in entrambe le direzioni.
* Sincronizzazione con GitLab (anteprima): sincronizzazione bidirezionale con GitLab.com o con il tuo GitLab self-managed.
* Server MCP: consenti a Claude Code, Codex, Cursor, VS Code o Gemini CLI di lavorare direttamente su un progetto.
* GitHub Enterprise: punta la sincronizzazione con GitHub alla tua istanza di GitHub Enterprise.
* Riconoscimento dei simboli scritti a mano: disegna un simbolo e ottieni il comando LaTeX.
* `OVERLEAF_DISABLE_LOCAL_LOGIN`: nasconde l'accesso con email e password, così gli utenti accedono solo tramite SSO.
* Correzioni di bug individuati dal nostro sistema di test E2E e dalla Internal Horizon Issue Investigation.
* Patch di Overleaf upstream 6.3.1.

<Info>

La sincronizzazione con Dropbox e la sincronizzazione con GitLab sono incluse nella 6.3.1 come **anteprime** per un test graduale e verranno rilasciate ufficialmente nella v6.4.0. La loro configurazione e il loro comportamento potrebbero ancora cambiare prima di allora. Entrambe sono disattivate per impostazione predefinita. Segnala eventuali problemi su [GitHub](https://github.com/ayaka-notes/ayakaleaf-pro/issues).

</Info>

#### Funzionalità 01: sincronizzazione con Dropbox (anteprima)

Alcune persone non vogliono mai pensare a Git. Vogliono solo che la loro tesi sia una cartella sul portatile, e la sincronizzazione con Dropbox offre esattamente questo. Ogni utente collega il proprio account Dropbox e i progetti di sua proprietà e quelli condivisi con lui compaiono in `Apps/<your app name>/`. Modifica in Overleaf e la modifica compare in Dropbox. Modifica il file in locale nel tuo editor preferito, salvalo e la modifica torna in Overleaf tramite un webhook firmato.

Per gli amministratori: git bridge deve essere abilitato. Crea un'app nella Dropbox App Console, quindi imposta `DROPBOX_ENABLED`, `DROPBOX_APP_KEY`, `DROPBOX_APP_SECRET`, `DROPBOX_APP_NAME` e `DROPBOX_TOKEN_CIPHER_PASSWORD`. `DROPBOX_SYNC_PROXY_URL` è facoltativa, per i server che non riescono a raggiungere direttamente Dropbox. Poi crea, una sola volta, gli indici MongoDB necessari alla sincronizzazione con Dropbox, prima che gli utenti colleghino i propri account.

Consulta [Sincronizzazione con Dropbox](/it/on-premises/configuration/overleaf-toolkit/dropbox-synchronisation  "mention") per le istruzioni di configurazione complete.

#### Funzionalità 02: sincronizzazione con GitLab (anteprima)

La sincronizzazione con GitHub è una delle nostre funzionalità più apprezzate dalla 6.2, e molte università e aziende tengono invece il proprio codice su GitLab. La sincronizzazione con GitLab funziona allo stesso modo: collega il tuo account, importa un repository dal menu del nuovo progetto oppure esporta un progetto in un nuovo progetto GitLab. Poi esegui push e pull dall'editor e unisci le modifiche tramite merge request.

Funziona con GitLab.com e con GitLab self-managed 15.10 o successivo. Imposta `GITLAB_SYNC_ENABLED`, `GITLAB_SYNC_CLIENT_ID`, `GITLAB_SYNC_CLIENT_SECRET` e `GITLAB_TOKEN_CIPHER_PASSWORD`, più `GITLAB_SYNC_URL` per un'istanza self-managed.

Consulta [Sincronizzazione con GitLab](/it/on-premises/configuration/overleaf-toolkit/gitlab-synchronisation  "mention") per le istruzioni di configurazione complete.

#### Funzionalità 03: server MCP

Nella 6.3 abbiamo messo un assistente AI dentro l'editor. Nella 6.3.1 apriamo la porta nell'altra direzione: ogni progetto ha ora il proprio server MCP, così l'agente AI che usi già può lavorare direttamente sul tuo articolo. Chiedi a Claude Code di correggere i refusi nell'introduzione, chiedi a Codex di compilare e correggere gli errori LaTeX, oppure chiedi a Cursor di rispondere ai commenti di revisione aperti. L'agente legge e modifica i file in tempo reale, così tu e i tuoi collaboratori vedete le sue modifiche comparire nell'editor mentre scrive. Può anche compilare, leggere il log, recuperare il PDF, contare le parole ed elencare le versioni.

L'endpoint è `/project/<project_id>/mcp`. Autenticati con lo stesso token Git che usi per `git clone`. L'accesso segue le impostazioni di condivisione del progetto, quindi l'agente di un utente in sola lettura può leggere ma non modificare, e ogni strumento ha un limite di frequenza. Non c'è nient'altro da configurare: il server MCP viene abilitato insieme a git bridge.

Consulta [Server MCP](/it/on-premises/configuration/overleaf-toolkit/mcp-server  "mention") per sapere come collegare ciascun client AI.

#### Funzionalità 04: GitHub Enterprise

La sincronizzazione con GitHub non è più limitata a github.com. Imposta `GITHUB_SYNC_URL` sul tuo GitHub Enterprise Server, oppure su GitHub Enterprise Cloud con residenza dei dati (`GHE.com`), e gli endpoint REST e GraphQL vengono ricavati da essa. Se la tua istanza ha una configurazione insolita, sovrascrivili con `GITHUB_SYNC_API_URL` e `GITHUB_SYNC_GRAPHQL_URL`. Se le lasci non impostate, tutto resta su github.com.

Consulta [Sincronizzazione con GitHub](/it/on-premises/configuration/overleaf-toolkit/github-synchronisation#github-enterprise  "mention") per i dettagli.

#### Funzionalità 05: riconoscimento dei simboli scritti a mano

Sai che aspetto ha il simbolo, ma non come si chiama. È `\varsigma` o `\zeta`? `\models` o `\vDash`? Passa la tavolozza dei simboli alla modalità di disegno, disegnalo con il mouse o il trackpad e la tavolozza suggerisce i comandi LaTeX corrispondenti.

Il riconoscimento avviene interamente nel browser, con un modello addestrato da ayaka-notes, quindi nulla di ciò che disegni lascia il tuo computer. Il pulsante di disegno è nascosto nei browser senza `OffscreenCanvas` (ad es. Safari 15).

#### Correzioni di bug

Questa release porta anche un lungo elenco di correzioni. Molte sono state individuate dal nostro nuovo sistema di test E2E, che ora esegue ogni giorno le suite per ogni modulo, e dalla Internal Horizon Issue Investigation: ogni volta che correggiamo un bug, esaminiamo l'intero codice alla ricerca di bug simili prima di chiuderlo.

* **Autenticazione**: gli account locali possono impostare e cambiare la propria password sulle istanze con SSO e gli utenti OIDC non possono più cambiare la propria email. Gli accessi LDAP, SAML e OIDC non falliscono più quando un attributo del nome ha più valori, e il logout SAML/OIDC funziona di nuovo.
* **Utenti sospesi**: la sospensione di un utente ora termina le sue sessioni e chiude i suoi editor aperti, e i suoi token Git e i download MCP vengono rifiutati.
* **Sincronizzazione con GitHub**: solo il proprietario può esportare un progetto, le modifiche fatte durante un pull restano in sospeso, i file vuoti vengono sincronizzati e i merge manuali vengono verificati su GitHub.
* **Zotero / Mendeley**: ricevi un messaggio per ricollegare l'account quando le credenziali smettono di funzionare, e i riferimenti vengono reindicizzati dopo un'importazione.
* **Servizi esterni**: le richieste a Zotero, Mendeley, GitHub, GitLab e alla ricerca web hanno un timeout di connessione di 3 s invece di 1 s, così le reti più lente non falliscono più.
* **Revisioni**: i dati di revisione includono i documenti non caricati e le modifiche non salvate.
* **Pannello di amministrazione**: il ripristino dei progetti eliminati, il cambio di proprietario e la modifica degli utenti funzionano correttamente, e un'email non inviata non impedisce più la creazione o l'eliminazione di un account.
* **Galleria dei template**: un ordinamento non valido restituisce 400 invece di 500, e la pubblicazione di un progetto senza file principale ne richiede uno.

Consulta le [note di rilascio della 6.3.1](/it/on-premises/release-notes/release-notes-6.x.x#ayakaleaf-pro-6.3.1  "mention") per l'elenco completo.

#### Aggiornamento

* Dalla 6.3.0: non è necessaria alcuna migrazione. Scarica la nuova immagine e riavvia.
* Dalla 6.2.x o precedenti con Zotero o Mendeley in uso: esegui prima la [migrazione di Zotero / Mendeley](/it/on-premises/release-notes/release-notes-6.x.x#ayakaleaf-pro-6.3.0  "mention") della 6.3.0.
* La sincronizzazione con Dropbox e la sincronizzazione con GitLab sono disattivate per impostazione predefinita. La sincronizzazione con GitLab richiede solo nuove variabili d'ambiente. La sincronizzazione con Dropbox richiede anche che i suoi indici MongoDB vengano creati una sola volta, prima che gli utenti colleghino i propri account: consulta [Creare gli indici del database](/it/on-premises/configuration/overleaf-toolkit/dropbox-synchronisation#create-the-database-indexes  "mention").
