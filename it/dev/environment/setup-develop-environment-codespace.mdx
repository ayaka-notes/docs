Per risparmiare tempo e creare rapidamente l'ambiente di sviluppo, forniamo un'ulteriore versione della configurazione dell'ambiente di sviluppo: GitHub Codespace.

## Guida alla configurazione {#configuration-tutorial}

<Steps>
<Step title="Creare i Codespaces">
Fai clic sul pulsante seguente per creare un codespace nel cloud per lo sviluppo di server-pro.

[![Open in GitHub Codespaces](https://github.com/codespaces/badge.svg)](https://codespaces.new/ayaka-notes/ayakaleaf-pro)

Si consiglia di scegliere un **Machine Type** di almeno **4-core**. Per tipi di macchina più grandi, puoi inviare una richiesta al team di supporto ufficiale di GitHub aprendo un ticket [qui](https://support.github.com/contact?tags=rr-codespaces%2Ccat_codespaces).

<Frame>
  <img src="/images/dev/image.png" alt="" />
</Frame>
</Step>

<Step title="Avviare lo script di configurazione">
Dovrai attendere pazientemente che il codespace venga creato. Una volta che hai accesso al Terminale, esegui il comando seguente:

```text
cd develop/
bin/setup
bin/i18n
```

`bin/setup` scarica le immagini e avvia i servizi; poi `bin/i18n` applica le traduzioni dei moduli di Ayakaleaf Pro, che i file delle localizzazioni committati non contengono, vedi [Aggiornare le traduzioni i18n](/it/dev/environment/update-i18n-translations).

<Frame>
  <img src="/images/dev/image-1.png" alt="" />
</Frame>

<Warning>

Questo script (`bin/setup`) ti consente di configurare l'ambiente di sviluppo sull'ultimo commit del branch `server-pro` nel minor tempo possibile. Potrebbe non essere applicabile a versioni precedenti o ad altri branch.

Compiliamo l'immagine Docker di sviluppo ogni giorno con [GitHub Action](https://github.com/ayaka-notes/ayakaleaf-pro/actions).

</Warning>
</Step>

<Step title="Accedere al Launchpad">
Passa alla scheda delle porte: vedrai un elenco delle porte web disponibili. Fai clic su quella con `80` (il `OVERLEAF_PORT` in `develop/dev.rc`). Ora dovresti vedere la pagina launchpad. Mailpit, Grafana, Mongo Express e RedisInsight si trovano su percorsi della stessa porta (`/mailpit/`, `/grafana/`, `/mongo-express/` e `/redis-insight/`), e il menu **Dev tools** del sito vi rimanda dopo l'accesso. La console di RustFS è sulla 9001 e Hoppscotch sulla 9170, vedi [Porte](/it/dev/environment/setup-develop-environment-local#ports).

</Step>

<Step title="Buon sviluppo">
Ora tocca a te! Inizia a sviluppare la tua fantastica funzionalità. `bin/setup` avvia già ogni servizio in modalità sviluppo (`node --watch`, come `bin/dev`), quindi le modifiche al codice compaiono senza altri comandi.

Dopo aver modificato `develop/dev.rc`, esegui di nuovo `bin/setup`: passa da `bin/docker-compose`, che aggiunge i file delle funzionalità attivate.

<Warning>

Non avviare i servizi a mano con `docker compose -f docker-compose.yml -f docker-compose.dev.yml -f docker-compose.image.yml up`. Salta i file delle funzionalità di `dev.rc`, quindi `web`, `filestore` e `history-v1` vengono ricreati senza le impostazioni di RustFS e ripiegano su volumi locali, dove mancano la cronologia e i file binari dei tuoi progetti.

</Warning>
</Step>
</Steps>
