## Prerequisiti

Overleaf è un tipico progetto open source con architettura a microservizi, in cui tutti i servizi vengono eseguiti in Docker.&#x20;

* Il codice sorgente ufficiale della Community Edition è disponibile su [GitHub Overleaf Official](https://github.com/overleaf/overleaf/tree).&#x20;
* Il codice sorgente di Overleaf-CEP è disponibile su [GitHub Yu-i-i/Overleaf](https://github.com/yu-i-i/overleaf-cep).
* Overleaf Pro Edition è disponibile su [GitHub Ayaka-notes/overleaf-pro](https://github.com/ayaka-notes/overleaf-pro).

Per configurare un ambiente di sviluppo Overleaf serve un server potente: è consigliata una configurazione di almeno 8 core e 16 GB di RAM, poiché dovrai eseguire più di 20 container contemporaneamente.

<Info>

Poiché i server con 8 o più core CPU sono in genere costosi, è vivamente consigliato usare il tuo computer locale per lo sviluppo.

</Info>

Inoltre, in quanto sviluppatore, riteniamo che tu abbia già familiarità con l'[installazione di Docker](https://docs.docker.com/engine/install/ubuntu/). Consigliamo vivamente di usare una versione Ubuntu LTS recente e stabile (ad es. Ubuntu 24.04 nel 2025–2026) e la versione più recente di Docker per lo sviluppo, poiché ciò riduce la possibilità di incontrare errori imprevisti.

In sintesi, ti servono:

* [x] Un server/desktop potente per lo sviluppo
* [x] Una versione Ubuntu LTS recente e stabile (ad es. Ubuntu 24.04)
* [x] Un ambiente Docker e Git

## Tutorial di configurazione

Qui useremo overleaf-cep come esempio per mostrare come configurare un ambiente di sviluppo Overleaf.

<Steps>
<Step title="Scarica il codice sorgente">
Prima di tutto, cloniamo il repository:

```bash title="bash"
git clone https://github.com/ayaka-notes/overleaf-pro.git
cd overleaf-pro
```
</Step>

<Step title="Sincronizza `package-lock.json`">
Poiché Overleaf è sviluppato in un [repository interno](http://github.com/overleaf/internal), è molto probabile che il file `package-lock.json` non sia sincronizzato a causa di alcuni problemi di sviluppo. Dobbiamo eseguire il seguente comando per sincronizzarlo (se disponi di un ambiente nodejs locale).

```bash title="bash"
npm install --package-lock-only --ignore-scripts
```

Se non hai nodejs installato, nessun problema: puoi usare direttamente `docker` per eseguire lo stesso comando. Eseguilo **dalla radice del repository Overleaf:**

```bash title="bash"
docker run --rm \
  -v "$(pwd)":/workspace \
  -w /workspace \
  node:22.18.0 \
  npm install --package-lock-only --ignore-scripts
```
</Step>

<Step title="Compila l'immagine di sviluppo">
Overleaf fornisce una directory dedicata `/develop` per gli script di sviluppo. Basta compilare i servizi:

```bash title="bash"
cd ./develop
bin/build
```

<Info>

Se Docker esaurisce la RAM durante la compilazione parallela dei servizi, crea in questa directory un file `.env` contenente `COMPOSE_PARALLEL_LIMIT=1`.

</Info>
</Step>

<Step title="Avvia tutti i microservizi">
Quindi avvia i servizi:

```bash title="bash"
bin/up
```

Una volta avviati i servizi, apri [http://localhost/launchpad](http://localhost/launchpad) per creare il primo account amministratore.

<Danger>

Devi eseguire `bin/up` prima di eseguire il comando `bin/dev`. In caso contrario potresti incontrare una serie di problemi di permessi.

</Danger>
</Step>
</Steps>

<Info>

Per impostazione predefinita i privilegi di amministratore non sono disponibili. Devi aggiungere quanto segue a `develop/dev.env`. Dopodiché potrai accedere al pannello di amministrazione.

```text
ADMIN_PRIVILEGE_AVAILABLE=true
```

</Info>

### TeX Live

Per compilare un PDF è necessario creare un'immagine TeX Live che gestisca la compilazione all'interno di Docker:

```text
docker build texlive -t texlive-full
```

Per compilare su un host macOS, potrebbe essere necessario sovrascrivere il percorso del socket Docker creando in questa directory un file `.env` contenente `DOCKER_SOCKET_PATH=/var/run/docker.sock.raw`

Puoi anche usare [ayaka-notes/texlive-full](https://github.com/ayaka-notes/texlive-full), ma puoi usare il tag base, che è la versione minima di texlive.

### Sviluppo

Per evitare di eseguire `bin/build && bin/up` dopo ogni modifica al codice, puoi eseguire Overleaf Community Edition in _modalità di sviluppo_, in cui i servizi si aggiornano automaticamente quando il codice cambia.

Per farlo, usa lo script `bin/dev` incluso:

```text
bin/dev
```

In questo modo tutti i servizi vengono avviati con `node --watch`, che monitora automaticamente il codice e riavvia i servizi quando necessario.

Per migliorare le prestazioni, puoi avviare in modalità di sviluppo solo un sottoinsieme dei servizi, passando allo script `bin/dev` un elenco separato da spazi:

```text
bin/dev [service1] [service2] ... [serviceN]
```

<Info>

Avviare il servizio `web` in _modalità di sviluppo_ aggiorna il servizio `web` solo quando cambia il codice backend. Per aggiornare automaticamente anche il codice frontend, assicurati di avviare in _modalità di sviluppo_ anche il servizio `webpack`.

</Info>

Se non viene indicato alcun servizio, tutti i servizi verranno avviati in modalità di sviluppo.

### Debug

Quando vengono eseguiti in _modalità di sviluppo_, la maggior parte dei servizi espone una porta di debug a cui puoi collegare un debugger, come l'inspector dei Chrome Dev Tools o uno integrato in un IDE. La tabella seguente mostra la porta esposta sulla **macchina host** per ciascun servizio:

| Servizio           | Porta |
| ------------------ | ---- |
| `web`              | 9229 |
| `clsi`             | 9230 |
| `chat`             | 9231 |
| `contacts`         | 9232 |
| `docstore`         | 9233 |
| `document-updater` | 9234 |
| `filestore`        | 9235 |
| `notifications`    | 9236 |
| `real-time`        | 9237 |
| `references`       | 9238 |
| `history-v1`       | 9239 |
| `project-history`  | 9240 |
| `linked-url-proxy` | 9241 |

Per collegarti a un servizio usando il _remote debugging_ di Chrome, vai su chrome://inspect/ e assicurati che l'opzione _Discover network targets_ sia selezionata. Quindi fai clic su _Configure..._ e aggiungi una voce `localhost:[service port]` per ciascuno dei servizi a cui vuoi collegare un debugger.

Dopo aver aggiunto una voce, il servizio comparirà come _Remote Target_ che potrai ispezionare ed eseguire in debug.

### Logging

Nell'ambiente di sviluppo, Overleaf fornisce lo script `bin/logs`, ma è necessario installare alcune dipendenze:

```bash
sudo npm install -g bunyan
# Or sudo apt install node-bunyan 
```

In alternativa, puoi eseguire direttamente:

```text
docker compose logs -f [service name]
```
