title: Collezione GitLab Sync Project States
icon: code-merge
---

`gitlabSyncProjectStates` contiene un documento per ogni progetto collegato a un progetto GitLab: quale repository e dove si è fermata l'ultima sincronizzazione. Appartiene al modulo web `gitlab-sync` (`services/web/modules/gitlab-sync`). Lo schema è in `services/web/modules/gitlab-sync/app/models/gitlabSyncProjectStates.mjs`, e ogni accesso passa da `services/web/modules/gitlab-sync/app/src/SyncStateManager.mjs`. I campi sono gli stessi di [GitHub Sync Project States](/it/dev/data-model/github-sync-project-states-collection).

#### Campi {#fields}

| Campo | Tipo | Significato | Fonte |
| ----- | ---- | ----------- | ----- |
| `_id` | ObjectId | Impostato da Mongoose alla creazione. | |
| `projectId` | ObjectId | Il progetto collegato. Obbligatorio. Lo schema indica `unique: true`, ma non viene creato alcun indice (vedi Indici). | `gitlabSyncProjectStates.mjs:8` |
| `repoFullName` | String | Il percorso del progetto GitLab con il suo namespace (il `path_with_namespace` di GitLab), ad esempio `group/subgroup/name`. Obbligatorio. | `gitlabSyncProjectStates.mjs:9`, `GitLabApiClient.mjs:347` |
| `defaultBranchName` | String | Il branch con cui il progetto si sincronizza. Impostato quando il progetto viene collegato e non modificato in seguito: all'importazione, il branch inviato dal modulo di importazione; all'esportazione, il branch predefinito del nuovo repository, oppure `main` quando l'API non ne fornisce uno. Predefinito `null`. | `gitlabSyncProjectStates.mjs:10`, `GitLabSyncHandler.mjs:175-181,234-240`, `GitLabApiClient.mjs:346-349` |
| `mergeStatus` | String | `clean`, `conflict` o `diverged`. Predefinito `clean`. | `gitlabSyncProjectStates.mjs:11` |
| `lastSyncCommit` | String | Lo SHA del commit sul branch sincronizzato all'ultima sincronizzazione. Predefinito `null`. | `gitlabSyncProjectStates.mjs:12` |
| `lastSyncVersion` | Number | La versione della cronologia del progetto all'ultima sincronizzazione, da project-history `GET /project/:id/version`, letta dopo un flush della cronologia. Predefinito `null`. | `gitlabSyncProjectStates.mjs:13`, `services/web/modules/gitlab-sync/app/src/HistoryManager.mjs:8-17` |
| `unmergedBranchName` | String | Durante un conflitto: il branch temporaneo con le modifiche di Overleaf, chiamato `overleaf-YYYY-MM-DD-HHMMSS`. `null` quando non c'è conflitto. | `gitlabSyncProjectStates.mjs:14`, `GitMerge.mjs:817-821` |
| `unmergedBranchHead` | String | Durante un conflitto: il commit di testa di quel branch. Predefinito `null`. | `gitlabSyncProjectStates.mjs:15` |
| `conflictVersion` | Number | Durante un conflitto: la versione della cronologia del progetto quando il conflitto è stato registrato. Predefinito `null`. | `gitlabSyncProjectStates.mjs:16` |
| `__v` | Number | La chiave di versione di Mongoose. Lo schema non la disattiva. | Predefinito di Mongoose |

#### Chi la scrive {#who-writes-it}

| Codice | Cosa fa |
| ------ | ------- |
| `SyncStateManager.mjs:9-14` (`createProjectState`) | Crea il documento: dopo aver importato un repository come nuovo progetto (`services/web/modules/gitlab-sync/app/src/GitLabSyncHandler.mjs:175-181`), o dopo aver esportato un progetto in un nuovo repository (`GitLabSyncHandler.mjs:234-240`, solo il proprietario, rifiutato se già collegato). |
| `SyncStateManager.mjs:16-21` (`updateProjectState`) | `$set` dei campi modificati. `getMergeOverview` imposta `mergeStatus: 'diverged'` quando il branch sincronizzato non contiene più `lastSyncCommit` (controllo della merge base, `services/web/modules/gitlab-sync/app/src/GitLabApiClient.mjs:460`), oppure il commit non esiste più e l'utente può fare push (`GitLabSyncHandler.mjs:123,126-137`). Una sincronizzazione (`services/web/modules/gitlab-sync/app/src/GitMerge.mjs`) fa avanzare `lastSyncCommit`/`lastSyncVersion` in caso di successo (ad esempio `:152,189,231`), registra un conflitto con `unmergedBranchName`, `unmergedBranchHead` e `conflictVersion` (`:214-220`), e li azzera una volta risolto (`:257-264`). |
| `SyncStateManager.mjs:23-25` (`removeProjectState`) | Elimina il documento quando il proprietario scollega il progetto (`GitLabSyncHandler.mjs:83-97`) e quando un progetto eliminato scade (`services/web/modules/gitlab-sync/index.mjs:46-48`). |

#### Chi la legge {#who-reads-it}

| Codice | Cosa fa |
| ------ | ------- |
| `GitLabSyncHandler.mjs:39-60` (`getProjectState`) | Fornisce all'editor `mergeStatus`, `repoFullName` e `unmergedBranchName`. Senza documento risponde `need-export`, un valore che non viene mai memorizzato. |
| `GitLabSyncHandler.mjs:110-143` (`getMergeOverview`) | Confronta `lastSyncCommit` e `lastSyncVersion` con GitLab e la cronologia del progetto per elencare i nuovi commit. |
| `GitLabSyncHandler.mjs:200` (`exportProject`) | Rifiuta di esportare un progetto già collegato. |
| `GitMerge.mjs:36` (`doGitMergeWithoutLock`) | Carica lo stato all'inizio di una sincronizzazione. |

#### Indici {#indexes}

| Nome | Chiavi | Opzioni | Migrazione |
| ---- | ------ | ------- | ---------- |
| `_id_` | `_id: 1` | | default |

L'`autoIndex` di Mongoose è disattivato (`services/web/app/src/infrastructure/Mongoose.mjs:7`), quindi il `unique: true` dello schema su `projectId` non crea nulla. Nessuna migrazione crea indici per questa collezione.

#### Note {#notes}

* L'API di GitLab non può spostare un branch su qualsiasi commit come quella di GitHub. Una sincronizzazione fa commit direttamente sul branch sincronizzato quando può avanzare, oppure su un branch temporaneo che viene poi unito tramite una merge request (`GitMerge.mjs:16-21`).
* Una sincronizzazione viene eseguita sotto il lock `gitSync` del progetto, condiviso con GitHub Sync e Gitea Sync (`GitMerge.mjs:25-32`).
* Un progetto eliminato mantiene il suo documento finché il progetto non scade.
* Il token GitLab dell'utente si trova in [GitLab Sync User Credentials](/it/dev/data-model/gitlab-sync-user-credentials-collection).
