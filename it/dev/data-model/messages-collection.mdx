`messages` contiene un documento per messaggio: una riga della chat del progetto, oppure un commento o una risposta in un thread di commenti di revisione. Solo il servizio chat la scrive, in `services/chat/app/js/Features/Messages/MessageManager.js`. Non esiste uno schema Mongoose. Ogni messaggio appartiene a una stanza della collezione [rooms](/it/dev/data-model/rooms-collection).

#### Campi {#fields}

| Campo | Tipo | Significato | Fonte |
| ----- | ---- | ------- | ------ |
| `_id` | ObjectId | Id del messaggio. | `MessageManager.js:13-14` |
| `room_id` | ObjectId | La stanza (`rooms._id`), non l’id del progetto né l’id del thread. | `MessageManager.js:8,106-108` |
| `user_id` | ObjectId | Autore. | `MessageManager.js:9,103-105` |
| `content` | String | Testo del messaggio, da 1 a 10240 caratteri (`MAX_MESSAGE_LENGTH`). | `MessageManager.js:7`, `services/chat/app/js/Features/Messages/MessageHttpSchemas.js:3,12-15` |
| `timestamp` | Number | Quando è stato inviato, in millisecondi dal 1970 (`Date.now()`), non un Date. | `MessageManager.js:10`, `services/chat/app/js/Features/Messages/MessageHttpController.js:288` |
| `edited_at` | Number | Quando è stato modificato l’ultima volta, in millisecondi (`Date.now()`). Assente se mai modificato. | `MessageManager.js:65-69`, `MessageHttpController.js:189,213` |

#### Chi la scrive {#who-writes-it}

| Codice | Cosa fa |
| ---- | ------------ |
| `MessageManager.js:5-16` `createMessage` | Inserisce un messaggio (`MessageHttpController.js:275-294`). Web invia i messaggi della chat del progetto da `services/web/app/src/Features/Chat/ChatController.mjs:32` e i commenti dal modulo track-changes (`services/web/modules/track-changes/app/src/TrackChangesController.mjs:95`) e dal modulo mcp-server (`services/web/modules/mcp-server/app/src/CommentTools.mjs:133`). |
| `MessageManager.js:51-72` `updateMessage` | Imposta `content` e `edited_at`. Se viene passato un id utente, corrisponde solo il messaggio di quell’utente (`MessageManager.js:62-64`). Chiamato da `ChatController.mjs:135` e `TrackChangesController.mjs:110`. |
| `MessageManager.js:74-80` `deleteMessage` | Elimina un messaggio. Chiamato da `ChatController.mjs:105` e `TrackChangesController.mjs:129`. |
| `MessageManager.js:39-49` `deleteAllMessagesInRoom(s)` | Elimina i messaggi di un thread eliminato (`MessageHttpController.js:172-173`) o di un intero progetto quando un progetto eliminato scade (`MessageHttpController.js:261-271`, chiamato da `services/web/app/src/Features/Project/ProjectDeleter.mjs:391`). |
| `MessageManager.js:115-127` `duplicateRoomToOtherRoom` | Copia `content`, `timestamp` e `user_id` di ogni messaggio in un’altra stanza, senza `edited_at`. Usato quando un ripristino della cronologia duplica un thread (`MessageHttpController.js:316-342`) e quando un progetto viene copiato con i suoi intervalli (`MessageHttpController.js:344-357`). |

#### Chi la legge {#who-reads-it}

| Codice | Cosa fa |
| ---- | ------------ |
| `MessageManager.js:18-29` `getMessages` | Dal più recente, al massimo `limit` (predefinito 50) più vecchi di `before` (un `timestamp`). Usato per la chat del progetto (`ChatController.mjs:80`). |
| `MessageManager.js:31-37` `findAllMessagesInRooms` | Tutti i messaggi di alcune stanze, per l’elenco dei thread del pannello di revisione (`TrackChangesController.mjs:82`), il modulo mcp-server (`CommentTools.mjs:83`) e il ripristino della cronologia (`services/web/app/src/Features/History/RestoreManager.mjs:259`). Web controlla anche il primo messaggio di un thread per permettere a un revisore di modificare solo i thread che ha avviato (`services/web/app/src/Features/Authorization/AuthorizationManager.mjs:409-411`). |
| `MessageManager.js:90-100` `getMessage` | Un messaggio. Web controlla il suo `user_id` prima che un utente modifichi o elimini il proprio messaggio (`services/web/app/src/Features/Authorization/AuthorizationMiddleware.mjs:253-257`, `TrackChangesController.mjs:124-125`). |

#### Note {#notes}

* Per trovare i messaggi di un commento, cerca prima la stanza per `project_id` e `thread_id`, poi interroga `room_id`. L’id del commento nel doc è il `thread_id`, non il `room_id`.
* Il testo a cui punta un commento è `op.c` in `docs.ranges.comments`; la discussione è qui.
