title: Collezione Dropbox Projects

`dropboxProjects` associa un progetto alla sua cartella nel Dropbox di un utente. Un progetto condiviso con più utenti Dropbox ha un documento per utente. Appartiene alla sincronizzazione Dropbox: third-party-datastore (`services/third-party-datastore/app/js/StateManager.mjs`) la scrive, e il modulo web `dropbox` (`services/web/modules/dropbox/app/src/DropboxHandler.mjs`) la legge e la svuota. Non c'è uno schema Mongoose.

#### Campi {#fields}

| Campo | Tipo | Significato | Fonte |
| ----- | ---- | ----------- | ----- |
| `_id` | ObjectId | Impostato dal driver all'inserimento. | `StateManager.mjs:144` |
| `userId` | ObjectId | L'utente Overleaf nel cui Dropbox si trova la cartella. | `StateManager.mjs:145` |
| `projectId` | ObjectId | Il progetto sincronizzato nella cartella. | `StateManager.mjs:146` |
| `dropboxId` | String | L'`id` della cartella nei metadati della cartella Dropbox. | `StateManager.mjs:147`, `JobProcessor.mjs:82-87`, `PullManager.mjs:138` |
| `pathLower` | String | Il percorso della cartella in Dropbox, in minuscolo e senza barra finale. Le cartelle dei progetti sono al primo livello, una per progetto, ad esempio `/thesis (1)` quando Dropbox l'ha numerata accanto al `Thesis` di un altro progetto. | `StateManager.mjs:14-16,148`, `PullManager.mjs:112-117` |

#### Chi la scrive {#who-writes-it}

| Codice | Cosa fa |
| ------ | ------- |
| `services/third-party-datastore/app/js/StateManager.mjs:137-150` (`setProjectFolder`) | Elimina i documenti dell'utente con lo stesso `projectId`, `dropboxId` o `pathLower`, poi inserisce la nuova associazione. |
| `services/third-party-datastore/app/js/JobProcessor.mjs:58-91` (`projectFolder`) | Crea la cartella in Dropbox e la registra quando web chiede la cartella di un nuovo progetto o di un progetto a cui l'utente è stato aggiunto (`createProject`, `:245-251`), oppure invia un file di un progetto che non ha ancora una cartella (`addEntity`, `:113`). |
| `JobProcessor.mjs:174-203` (`renameProject`) | Dopo che la ridenominazione di un progetto ha spostato la cartella, registra il nuovo percorso, oppure rimuove l'associazione quando la cartella non esiste più (`:190`). |
| `services/third-party-datastore/app/js/PullManager.mjs:119-140` (`resolveProject`) | Quando un pull trova una cartella senza associazione, registra il progetto che web ha trovato per nome. |
| `PullManager.mjs:188-207` (`applyDeletion`) | Quando una cartella di progetto viene eliminata in Dropbox, rimuove l'associazione (`StateManager.mjs:152-157`). |
| `StateManager.mjs:186-190` (`removeUserState`), chiamato da `services/third-party-datastore/app/js/QueueWorker.mjs:43` | Elimina tutti i documenti dell'utente quando third-party-datastore scollega un account che non può più usare. |
| `DropboxHandler.mjs:142-146` (`removeUserState`) | Elimina tutti i documenti dell'utente al collegamento (`:125`), allo scollegamento (`:183`) e quando un utente eliminato scade (`services/web/modules/dropbox/index.mjs:62-64`). |
| `DropboxHandler.mjs:150-154` (`removeProjectState`) | Elimina i documenti del progetto quando un progetto eliminato scade (`index.mjs:54-56`). |

#### Note {#notes}

* L'unicità deriva solo dall'eliminazione che precede ogni inserimento in `setProjectFolder` (`StateManager.mjs:140-149`). Il commento in `StateManager.mjs:3-11` menziona indici univoci; CE non li ha.
* Quando l'associazione di un progetto viene rimossa, la sua cartella resta in Dropbox. Una modifica lì viene quindi letta come un nuovo progetto, come per una cartella creata in Dropbox (`DropboxHandler.mjs:148-149`).
* Un progetto eliminato mantiene la sua associazione fino alla scadenza, perché può ancora essere ripristinato (`index.mjs:52-53`).
* Il cursore `list_folder` di Dropbox dell'utente non è qui. Si trova in `users.dropbox.cursor` (`StateManager.mjs:177-184`).
