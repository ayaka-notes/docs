`oauthAuthorizationCodes` è pensata per i codici del flusso OAuth authorization code: un documento per codice, che un client scambia con un token di accesso. Lo schema è `services/web/app/src/models/OauthAuthorizationCode.mjs`, e il modulo web `oauth2-server` contiene il codice che vi scriverebbe. In Ayakaleaf Pro niente raggiunge quel codice, quindi la collezione resta vuota (vedi Note).

#### Campi {#fields}

| Campo | Tipo | Significato | Fonte |
| ----- | ---- | ------- | ------ |
| `_id` | ObjectId | Id del documento. | `OauthAuthorizationCode.mjs:6` |
| `authorizationCode` | String | Il codice stesso, salvato così com'è (senza hash). | `OauthAuthorizationCode.mjs:8`, `services/web/modules/oauth2-server/app/src/OAuth2Model.mjs:280` |
| `expiresAt` | Date | Fine della validità. Dopo questa data `getAuthorizationCode` rifiuta il codice, e l'indice TTL lo elimina. | `OauthAuthorizationCode.mjs:9`, `OAuth2Model.mjs:150-153,281` |
| `oauthApplication_id` | ObjectId | Client in [OAuth Applications](/it/dev/data-model/oauth-applications-collection) che ha richiesto il codice. | `OauthAuthorizationCode.mjs:10`, `OAuth2Model.mjs:275-284` |
| `redirectUri` | String | URI di reindirizzamento della richiesta. | `OauthAuthorizationCode.mjs:11`, `OAuth2Model.mjs:282` |
| `scope` | String | Scope richiesto. | `OauthAuthorizationCode.mjs:12`, `OAuth2Model.mjs:283` |
| `user_id` | ObjectId | Utente che ha concesso il codice. | `OauthAuthorizationCode.mjs:13`, `OAuth2Model.mjs:285` |
| `codeChallenge`, `codeChallengeMethod` | String | Challenge PKCE e il suo metodo. | `OauthAuthorizationCode.mjs:14-15`, `OAuth2Model.mjs:286-287` |

#### Chi scrive {#who-writes-it}

| Codice | Cosa fa |
| ---- | ------------ |
| `OAuth2Model.mjs:274-300` (`saveAuthorizationCode`) | Inserisce un codice. Mai raggiunto, vedi Note. |
| `OAuth2Model.mjs:307-312` (`revokeAuthorizationCode`) | Elimina un codice dopo l'uso. Mai raggiunto. |

#### Chi legge {#who-reads-it}

| Codice | Cosa fa |
| ---- | ------------ |
| `OAuth2Model.mjs:137-177` (`getAuthorizationCode`) | Carica un codice con il suo utente e il suo client. Mai raggiunto. |

#### Indici {#indexes}

| Nome | Chiavi | Opzioni | Migrazione |
| ---- | ---- | ------- | --------- |
| `expiresAt_1` | `{ expiresAt: 1 }` | TTL, `expireAfterSeconds: 0`, parziale: `expiresAt` esiste | `20230406125632_oauth_tokens_ttl.mjs` |

Le migrazioni si trovano in `tools/migrations/`. L'indice univoco `authorizationCode_1` proviene solo da migrazioni con tag `saas` e `server-pro`, che Community Edition non esegue.

#### Note {#notes}

* I metodi del modello sopra vengono chiamati solo dagli handler authorize e token di `@node-oauth/oauth2-server`. Web usa questa libreria solo per verificare i token bearer (`services/web/app/src/Features/Authentication/AuthenticationController.mjs:409-450`), e nessuna route serve `/oauth/authorize` o `/oauth/token`, quindi nessun codice viene mai scritto. I token di accesso personali vengono creati direttamente, vedi [OAuth Access Tokens](/it/dev/data-model/oauth-access-tokens-collection).
