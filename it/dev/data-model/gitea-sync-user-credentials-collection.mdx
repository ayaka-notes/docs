---
title: Collezione Gitea Sync User Credentials
icon: lock
---

`giteaSyncUserCredentials` contiene un documento per ogni utente che ha collegato un account Gitea per Gitea Sync. Memorizza i token OAuth dell'utente, cifrati. Appartiene al modulo web `gitea-sync` (`services/web/modules/gitea-sync`). Lo schema è in `services/web/modules/gitea-sync/app/models/giteaSyncUserCredentials.mjs`, e ogni accesso passa da `services/web/modules/gitea-sync/app/src/TokenManager.mjs`.

#### Campi {#fields}

| Campo | Tipo | Significato | Fonte |
| ----- | ---- | ------- | ------ |
| `_id` | ObjectId | Impostato da Mongoose quando l'upsert inserisce. | |
| `userId` | ObjectId | L'utente Overleaf. Obbligatorio. Lo schema indica `unique: true`, ma non viene creato alcun indice (vedi Indici); l'upsert per `userId` mantiene un documento per utente. | `giteaSyncUserCredentials.mjs:8`, `TokenManager.mjs:89-96` |
| `gitea` | String | Il JSON `{ accessToken, refreshToken, expiresAt }`, cifrato con `@overleaf/access-token-encryptor`. `expiresAt` è in millisecondi dall'epoch, oppure `null`; `refreshToken` può essere `null`. La password viene da `GITEA_TOKEN_CIPHER_PASSWORD`; l'etichetta di cifratura è `GITEA_TOKEN_CIPHER_LABEL`, predefinita `2026.10-v3`. Obbligatorio. | `giteaSyncUserCredentials.mjs:9-10`, `TokenManager.mjs:17-30`, `services/web/modules/gitea-sync/app/src/GiteaApiClient.mjs:198-209` |
| `__v` | Number | La chiave di versione di Mongoose. Lo schema non la disattiva. | Predefinito di Mongoose |

#### Chi la scrive {#who-writes-it}

| Codice | Cosa fa |
| ---- | ------------ |
| `TokenManager.mjs:89-96` (`saveUserToken`) | Esegue l'upsert delle credenziali cifrate dell'utente. Chiamato dal callback OAuth (`services/web/modules/gitea-sync/app/src/GiteaSyncController.mjs:146`). A differenza di GitLab Sync, ricollegare l'account non revoca il token sostituito. |
| `TokenManager.mjs:53-79` (`refreshUserToken`) | Quando al `expiresAt` del token di accesso mancano meno di 5 minuti (`:12`), ottiene nuovi token con il token di aggiornamento e li salva (`:76`). Viene eseguito sotto il lock `giteaSyncToken` per utente (`:14,54`), perché Gitea sostituisce il token di aggiornamento quando viene usato. |
| `TokenManager.mjs:100-102` (`removeUserToken`) | Elimina il documento. Gitea non ha un'API per revocare un token OAuth, quindi l'utente revoca l'autorizzazione in Gitea (`:98-99`). Chiamato allo scollegamento (`GiteaSyncController.mjs:173`) e quando un utente eliminato scade (`services/web/modules/gitea-sync/index.mjs:56-58`). |

#### Chi la legge {#who-reads-it}

| Codice | Cosa fa |
| ---- | ------------ |
| `TokenManager.mjs:40-44,82-86` (`getUserCredentials`, `getUserToken`) | Decifra le credenziali per ogni chiamata all'API di Gitea, aggiornandole prima quando il token sta per scadere: `services/web/modules/gitea-sync/app/src/GiteaSyncHandler.mjs` (per esempio `:27`) e `services/web/modules/gitea-sync/app/src/GitMerge.mjs:52`. Senza documento, o con credenziali che non si possono decifrare o aggiornare, lancia `InvalidTokenError`, e l'utente risulta non collegato (`GiteaSyncHandler.mjs:25-37`). |
| `services/web/modules/admin-tools/app/src/AdminUserListManager.mjs:395` | Controlla se l'utente ha un documento, per le integrazioni mostrate nel pannello di amministrazione. |

#### Indici {#indexes}

| Nome | Chiavi | Opzioni | Migrazione |
| ---- | ---- | ------- | --------- |
| `_id_` | `_id: 1` | | default |

L'`autoIndex` di Mongoose è disattivato (`services/web/app/src/infrastructure/Mongoose.mjs:7`), quindi il `unique: true` dello schema su `userId` non crea nulla. Nessuna migrazione crea indici per questa collezione.

#### Note {#notes}

* Cambiare `GITEA_TOKEN_CIPHER_PASSWORD` rende illeggibili le credenziali memorizzate. Quegli utenti risultano quindi non collegati finché non ricollegano l'account.
* Un utente eliminato conserva il documento finché non scade.
