title: Collezione OAuth Applications
icon: id-badge
---

`oauthApplications` contiene i client OAuth che web conosce. Un documento è un client. In Ayakaleaf Pro l'unico a scriverci è il modulo web `git-bridge`, che crea un client chiamato `Overleaf Git Bridge` all'avvio di web. Lo schema è `services/web/app/src/models/OauthApplication.mjs`.

#### Campi {#fields}

| Campo | Tipo | Significato | Fonte |
| ----- | ---- | ------- | ------ |
| `_id` | ObjectId | Id del documento del client. `oauthAccessTokens.oauthApplication_id` e `oauthAuthorizationCodes.oauthApplication_id` puntano a esso. | `OauthApplication.mjs:5` |
| `id` | String | Id del client: 64 lettere minuscole e cifre casuali. | `OauthApplication.mjs:7`, `services/web/modules/git-bridge/index.mjs:25` |
| `clientSecret` | String | Segreto del client, scritto come `v1.` più 32 caratteri casuali. Lo legge solo `getClient`, e niente chiama `getClient` (vedi Note). | `OauthApplication.mjs:8`, `git-bridge/index.mjs:26` |
| `grants` | Array of String | Tipi di grant. Il client git-bridge ha `['password']`. Restituito con il client quando si verifica un token (`services/web/modules/oauth2-server/app/src/OAuth2Model.mjs:67-72`). | `OauthApplication.mjs:9`, `git-bridge/index.mjs:27` |
| `name` | String | Nome del client. Il modulo git-bridge e il codice dei token di accesso personali trovano il client tramite il nome `Overleaf Git Bridge`. | `OauthApplication.mjs:10`, `git-bridge/index.mjs:15-16,28` |
| `redirectUris` | Array of String | URI di reindirizzamento consentiti. `[]` per il client git-bridge. | `OauthApplication.mjs:11`, `git-bridge/index.mjs:29` |
| `scopes` | Array of String | Scope che il client può usare. `['git_bridge']` per il client git-bridge. | `OauthApplication.mjs:12`, `git-bridge/index.mjs:30` |
| `pkceEnabled` | Boolean | Solo nello schema: nessun codice in questo repository lo scrive, e lo legge solo `getClient`, inutilizzato (`OAuth2Model.mjs:207`). | `OauthApplication.mjs:13` |

#### Chi scrive {#who-writes-it}

| Codice | Cosa fa |
| ---- | ------------ |
| `git-bridge/index.mjs:9-35` (module `git-bridge`) | Quando `GIT_BRIDGE_ENABLED` è `true`, crea il client `Overleaf Git Bridge` all'avvio di web se non esiste già un client con quel nome. |

#### Chi legge {#who-reads-it}

| Codice | Cosa fa |
| ---- | ------------ |
| `services/web/modules/oauth2-server/app/src/OAuthPersonalAccessTokenManager.mjs:53-61` (module `oauth2-server`) | Trova il client `Overleaf Git Bridge` per nome e salva il suo `_id` in ogni nuovo token di accesso personale. Senza il client non viene creato alcun token. |
| `OAuth2Model.mjs:31-39,67-72` (`getAccessToken`) | Carica il client di un token tramite `oauthApplication_id` e ne restituisce `id` e `grants`. |
| `OAuth2Model.mjs:185-209,241,275` (`getClient`, `saveToken`, `saveAuthorizationCode`) | Cercano i client per `id`. Mai raggiunti in questo repository, vedi Note. |

#### Indici {#indexes}

Solo l'indice predefinito su `_id`. L'indice univoco `id_1` proviene da migrazioni con tag `saas` (`20190912145016_create_oauthApplications_indexes.mjs`) e `server-pro` (`20230502180757_server_pro_oauth_indexes.mjs`), che Community Edition non esegue.

#### Note {#notes}

* Web usa `@node-oauth/oauth2-server` solo per verificare i token bearer (`server.authenticate` in `services/web/app/src/Features/Authentication/AuthenticationController.mjs:409-450`), che chiama solo `getAccessToken` e `verifyScope` del modello. Nessuna route serve `/oauth/token` o `/oauth/authorize`, quindi `getClient`, `saveToken` e `saveAuthorizationCode` non vengono mai chiamati.
* Il modulo cerca il client per nome e poi lo crea, e Community Edition non ha un indice univoco su `name` o `id`. Niente impedisce quindi un secondo client con lo stesso nome. Il codice che ha bisogno del client prende quello restituito da `findOne`.
