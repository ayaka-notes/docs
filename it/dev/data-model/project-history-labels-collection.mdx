---
title: Collezione Project History Labels
icon: tag
---

`projectHistoryLabels` contiene le etichette che gli utenti assegnano alle versioni nella vista Cronologia, un documento per etichetta. project-history ne è proprietario e la scrive in `services/project-history/app/js/LabelsManager.js`; non esiste uno schema Mongoose. Web vi accede solo tramite l’API di project-history.

#### Campi {#fields}

| Campo | Tipo | Significato | Fonte |
| ----- | ---- | ------- | ------ |
| `_id` | ObjectId | Id dell’etichetta. | `LabelsManager.js:81-85` |
| `project_id` | ObjectId | Il progetto. | `LabelsManager.js:73` |
| `comment` | String | Il testo dell’etichetta. | `LabelsManager.js:74` |
| `version` | Number | La versione della cronologia del progetto a cui punta l’etichetta. | `LabelsManager.js:75` |
| `created_at` | Date | Quando è stata creata l’etichetta; la richiesta può passare un proprio orario, altrimenti si usa l’ora attuale. | `LabelsManager.js:70`, `76` |
| `user_id` | ObjectId | Chi ha creato l’etichetta. Omesso quando la richiesta non ha un utente. | `LabelsManager.js:78-80` |

#### Chi la scrive {#who-writes-it}

| Codice | Cosa fa |
| ---- | ------------ |
| `services/project-history/app/js/LabelsManager.js:44-90` | `createLabel`: inserisce un’etichetta, per project-history `POST /project/:project_id/labels` (`services/project-history/app/js/HttpController.js:1134-1171`). Web lo chiama quando un utente aggiunge un’etichetta, con l’id dell’utente (`services/web/app/src/Features/History/HistoryController.mjs:529-546`). |
| `LabelsManager.js:113-126` | `deleteLabel`: elimina un’etichetta del progetto, per `DELETE /project/:project_id/labels/:label_id`. Web lo usa quando il proprietario del progetto elimina un’etichetta (`HistoryController.mjs:649-670`). |
| `LabelsManager.js:92-111` | `deleteLabelForUser`: elimina un’etichetta solo se l’ha creata l’utente, per `DELETE /project/:project_id/user/:user_id/labels/:label_id`. Web lo usa per tutti gli altri. |
| `LabelsManager.js:128-143` | `transferLabels`: trasferisce tutte le etichette di un utente a un altro, per `POST /user/:from_user/labels/transfer/:to_user` (`services/project-history/app/js/Router.js:52-55`). Nulla in web chiama questa route. |
| `LabelsManager.js:7-25` | `cloneLabels`: copia le etichette di un progetto in un altro progetto, per project-history `POST /project/:project_id/clone` (`HttpController.js:113`), che nulla in web chiama. |

#### Chi la legge {#who-reads-it}

| Codice | Cosa fa |
| ---- | ------------ |
| `LabelsManager.js:27-42` | `getLabels`: tutte le etichette di un progetto, restituite come `{ id, comment, version, user_id, created_at }` (`LabelsManager.js:163-171`). Usato da `GET /project/:project_id/labels` (`HttpController.js:1076-1100`), che web chiama per la vista Cronologia aggiungendo i nomi utente (`HistoryController.mjs:488-499`). |
| `services/project-history/app/js/SummarizedUpdatesManager.js:57` | Aggiunge le etichette all’elenco degli aggiornamenti della cronologia. |

#### Note {#notes}

* Prima di inserire un’etichetta, project-history elabora gli aggiornamenti in coda del progetto e verifica che history-v1 abbia un chunk per quella versione, a meno che la richiesta non invii `validate_exists: false` (`LabelsManager.js:53-59`, `173-195`; `HttpController.js:1109-1115`).
* Nessun codice elimina le etichette di un progetto quando il progetto viene eliminato: project-history `DELETE /project/:project_id` cancella solo lo stato di sincronizzazione e il record di errore (`HttpController.js:1363-1396`), e nessun altro servizio tocca questa collezione.
