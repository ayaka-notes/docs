---
title: Collezione GitLab Sync User Credentials
icon: user-lock
---

`gitlabSyncUserCredentials` contiene un documento per ogni utente che ha collegato un account GitLab per GitLab Sync. Memorizza i token OAuth dell'utente, cifrati. Appartiene al modulo web `gitlab-sync` (`services/web/modules/gitlab-sync`). Lo schema è in `services/web/modules/gitlab-sync/app/models/gitlabSyncUserCredentials.mjs`, e ogni accesso passa da `services/web/modules/gitlab-sync/app/src/TokenManager.mjs`.

#### Campi {#fields}

| Campo | Tipo | Significato | Fonte |
| ----- | ---- | ------- | ------ |
| `_id` | ObjectId | Impostato da Mongoose quando l'upsert inserisce. | |
| `userId` | ObjectId | L'utente Overleaf. Obbligatorio. Lo schema indica `unique: true`, ma non viene creato alcun indice (vedi Indici); l'upsert per `userId` mantiene un documento per utente. | `gitlabSyncUserCredentials.mjs:8`, `TokenManager.mjs:88-95` |
| `gitlab` | String | Il JSON `{ accessToken, refreshToken, expiresAt }`, cifrato con `@overleaf/access-token-encryptor`. `expiresAt` è in millisecondi dall'epoch, oppure `null`; `refreshToken` può essere `null`. La password viene da `GITLAB_TOKEN_CIPHER_PASSWORD`; l'etichetta di cifratura è `GITLAB_TOKEN_CIPHER_LABEL`, predefinita `2026.10-v3`. Obbligatorio. | `gitlabSyncUserCredentials.mjs:9-10`, `TokenManager.mjs:18-31`, `services/web/modules/gitlab-sync/app/src/GitLabApiClient.mjs:209-220` |
| `__v` | Number | La chiave di versione di Mongoose. Lo schema non la disattiva. | Predefinito di Mongoose |

#### Chi la scrive {#who-writes-it}

| Codice | Cosa fa |
| ---- | ------------ |
| `TokenManager.mjs:88-95` (`saveUserToken`) | Esegue l'upsert delle credenziali cifrate dell'utente. |
| `TokenManager.mjs:99-108` (`linkUserToken`) | Salva le nuove credenziali dal callback OAuth (`services/web/modules/gitlab-sync/app/src/GitLabSyncController.mjs:146`). Quando l'utente ricollega l'account, il token di accesso sostituito viene revocato su GitLab in background. |
| `TokenManager.mjs:53-78` (`refreshUserToken`) | Quando al `expiresAt` del token di accesso mancano meno di 5 minuti (`:13,47-49`), ottiene nuovi token con il token di aggiornamento e li salva (`:75`). Viene eseguito sotto il lock `gitlabSyncToken` per utente (`:15,54`), perché GitLab consuma un token di aggiornamento quando viene usato. |
| `TokenManager.mjs:111-126` (`removeUserToken`) | Revoca il token di accesso su GitLab (al meglio delle possibilità), poi elimina il documento. Chiamato allo scollegamento (`GitLabSyncController.mjs:173`) e quando un utente eliminato scade (`services/web/modules/gitlab-sync/index.mjs:56-58`). |

#### Chi la legge {#who-reads-it}

| Codice | Cosa fa |
| ---- | ------------ |
| `TokenManager.mjs:41-45,81-85` (`getUserCredentials`, `getUserToken`) | Decifra le credenziali per ogni chiamata all'API di GitLab, aggiornandole prima quando il token sta per scadere: `services/web/modules/gitlab-sync/app/src/GitLabSyncHandler.mjs` (per esempio `:27`) e `services/web/modules/gitlab-sync/app/src/GitMerge.mjs:52`. Senza documento, o con credenziali che non si possono decifrare o aggiornare, lancia `InvalidTokenError`, e l'utente risulta non collegato (`GitLabSyncHandler.mjs:25-37`). |
| `services/web/modules/admin-tools/app/src/AdminUserListManager.mjs:394` | Controlla se l'utente ha un documento, per le integrazioni mostrate nel pannello di amministrazione. |

#### Indici {#indexes}

| Nome | Chiavi | Opzioni | Migrazione |
| ---- | ---- | ------- | --------- |
| `_id_` | `_id: 1` | | default |

L'`autoIndex` di Mongoose è disattivato (`services/web/app/src/infrastructure/Mongoose.mjs:7`), quindi il `unique: true` dello schema su `userId` non crea nulla. Nessuna migrazione crea indici per questa collezione.

#### Note {#notes}

* Cambiare `GITLAB_TOKEN_CIPHER_PASSWORD` rende illeggibili le credenziali memorizzate. Quegli utenti risultano quindi non collegati finché non ricollegano l'account.
* Un utente eliminato conserva il documento finché non scade.
