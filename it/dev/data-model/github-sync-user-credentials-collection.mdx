title: Collezione GitHub Sync User Credentials
icon: key
---

`githubSyncUserCredentials` contiene un documento per ogni utente che ha collegato un account GitHub per GitHub Sync. Memorizza il token di accesso OAuth dell'utente, cifrato. Appartiene al modulo web `github-sync` (`services/web/modules/github-sync`). Lo schema è in `services/web/modules/github-sync/app/models/githubSyncUserCredentials.mjs`, e ogni accesso passa da `services/web/modules/github-sync/app/src/TokenManager.mjs`.

#### Campi {#fields}

| Campo | Tipo | Significato | Fonte |
| ----- | ---- | ------- | ------ |
| `_id` | ObjectId | Impostato da Mongoose quando l'upsert inserisce. | |
| `userId` | ObjectId | L'utente Overleaf. Obbligatorio. Lo schema indica `unique: true`, ma non viene creato alcun indice (vedi Indici); l'upsert per `userId` mantiene un documento per utente. | `githubSyncUserCredentials.mjs:8`, `TokenManager.mjs:44-48` |
| `github` | String | Il token di accesso OAuth di GitHub, cifrato con `@overleaf/access-token-encryptor`. La password viene da `GITHUB_TOKEN_CIPHER_PASSWORD`; l'etichetta di cifratura è `GITHUB_TOKEN_CIPHER_LABEL`, predefinita `2026.3-v3`. Obbligatorio. | `githubSyncUserCredentials.mjs:9`, `TokenManager.mjs:12-25` |
| `__v` | Number | La chiave di versione di Mongoose. Lo schema non la disattiva. | Predefinito di Mongoose |

Viene memorizzato solo il token di accesso: il callback OAuth conserva `access_token` dalla risposta di GitHub (`services/web/modules/github-sync/app/src/GitHubApiClient.mjs:180-191`). Non ci sono token di aggiornamento né scadenza.

#### Chi la scrive {#who-writes-it}

| Codice | Cosa fa |
| ---- | ------------ |
| `TokenManager.mjs:42-58` (`saveUserToken`) | Esegue l'upsert del token cifrato dell'utente. Quando l'utente ricollega l'account, il token sostituito viene revocato su GitHub in background. Chiamato dal callback OAuth (`services/web/modules/github-sync/app/src/GitHubSyncController.mjs:146`). |
| `TokenManager.mjs:61-76` (`removeUserToken`) | Revoca il token su GitHub (al meglio delle possibilità), poi elimina il documento. Chiamato allo scollegamento (`GitHubSyncController.mjs:167`) e quando un utente eliminato scade (`services/web/modules/github-sync/index.mjs:66-68`). |

#### Chi la legge {#who-reads-it}

| Codice | Cosa fa |
| ---- | ------------ |
| `TokenManager.mjs:36-40` (`getUserToken`) | Decifra il token per ogni chiamata all'API di GitHub: `services/web/modules/github-sync/app/src/GitHubSyncHandler.mjs` (per esempio `:27`) e `services/web/modules/github-sync/app/src/GitMerge.mjs:43`. Senza documento, o con un token che non si può decifrare, lancia `InvalidTokenError`, e l'utente risulta non collegato (`GitHubSyncHandler.mjs:25-37`). |
| `services/web/modules/admin-tools/app/src/AdminUserListManager.mjs:393` | Controlla se l'utente ha un documento, per le integrazioni mostrate nel pannello di amministrazione. |

#### Indici {#indexes}

| Nome | Chiavi | Opzioni | Migrazione |
| ---- | ---- | ------- | --------- |
| `_id_` | `_id: 1` | | default |

L'`autoIndex` di Mongoose è disattivato (`services/web/app/src/infrastructure/Mongoose.mjs:7`), quindi il `unique: true` dello schema su `userId` non crea nulla. `tools/migrations/20190912145011_create_githubSyncUserCredentials_indexes.mjs` (`user_id` di upstream) ha solo il tag `saas` e non viene eseguita in CE.

#### Note {#notes}

* Cambiare `GITHUB_TOKEN_CIPHER_PASSWORD` rende illeggibili i token memorizzati. Quegli utenti risultano quindi non collegati finché non ricollegano l'account.
* Un utente eliminato conserva il documento finché non scade.
