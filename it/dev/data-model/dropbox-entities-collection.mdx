---
title: Collezione Dropbox Entities
icon: file-arrow-up
---

`dropboxEntities` contiene un documento per ogni file che la sincronizzazione Dropbox ha copiato tra un progetto e il Dropbox di un utente, più tombstone di breve durata. Appartiene alla sincronizzazione Dropbox: third-party-datastore (`services/third-party-datastore/app/js/StateManager.mjs`) la scrive e la legge, e il modulo web `dropbox` (`services/web/modules/dropbox/app/src/DropboxHandler.mjs`) la svuota. Non c'è uno schema Mongoose.

#### Campi {#fields}

| Campo | Tipo | Significato | Fonte |
| ----- | ---- | ----------- | ----- |
| `_id` | ObjectId | Impostato dal driver all'inserimento. | `StateManager.mjs:46,97` |
| `overleaf.userId` | ObjectId | L'utente nel cui Dropbox si trova il file. Impostato su ogni documento. | `StateManager.mjs:48,98` |
| `overleaf.projectId` | ObjectId | Il progetto del doc o del file. Impostato quando è noto; i tombstone non ce l'hanno. | `StateManager.mjs:49-51` |
| `overleaf.id` | ObjectId | L'`_id` del doc o del file nel `rootFolder` del progetto. Impostato quando è noto. | `StateManager.mjs:52` |
| `overleaf.type` | String | `doc` o `file`. Il codice attuale lo scrive ma non lo legge. | `StateManager.mjs:53`; valori da `services/web/app/src/Features/ThirdPartyDataStore/TpdsUpdateSender.mjs:35,96` e `UpdateMerger.mjs:104,119` |
| `dropbox.id` | String | L'`id` del file nei metadati del file Dropbox. Non impostato sui tombstone. | `StateManager.mjs:56` |
| `dropbox.pathLower` | String | Il percorso del file in Dropbox, in minuscolo e senza barra finale. Aggiornato quando il file o la sua cartella di progetto viene spostato. | `StateManager.mjs:14-16,57,91,99` |
| `dropbox.rev` | String | La revisione Dropbox all'ultima sincronizzazione. Il caricamento successivo la invia, così un file modificato in Dropbox non viene sovrascritto. | `StateManager.mjs:58`, `JobProcessor.mjs:114-122` |
| `dropbox.contentHash` | String | L'hash del contenuto Dropbox all'ultima sincronizzazione. Un file elencato con lo stesso hash viene saltato, perché è un nostro caricamento o è già applicato. | `StateManager.mjs:59`, `PullManager.mjs:147-149` |
| `tombstone` | Boolean | `true` indica un percorso che third-party-datastore stesso ha eliminato o spostato in Dropbox. Quando Dropbox segnala di ritorno quell'eliminazione, non viene applicata al progetto. | `StateManager.mjs:100`, `PullManager.mjs:189-192` |
| `createdAt` | Date | Solo tombstone: quando è stato creato. Un pull completato rimuove i tombstone creati prima del suo avvio. | `StateManager.mjs:101,115-121` |

Un tombstone ha solo `overleaf.userId`, `dropbox.pathLower`, `tombstone` e `createdAt` (`StateManager.mjs:96-103`).

#### Chi la scrive {#who-writes-it}

| Codice | Cosa fa |
| ------ | ------- |
| `services/third-party-datastore/app/js/StateManager.mjs:35-62` (`recordEntity`) | Elimina i documenti dell'utente con lo stesso `dropbox.id`, `dropbox.pathLower` o `overleaf.id`, poi inserisce il nuovo stato. |
| `services/third-party-datastore/app/js/JobProcessor.mjs:102-134` (`addEntity`) | Registra un doc o un file dopo averlo caricato da Overleaf a Dropbox (`:125-133`). |
| `services/third-party-datastore/app/js/PullManager.mjs:142-177` (`applyFile`) | Registra un file Dropbox dopo che web lo ha applicato al progetto (`:168-176`). |
| `StateManager.mjs:80-94` (`moveEntities`) | Riscrive `dropbox.pathLower` sotto un percorso spostato: ridenominazione del progetto (`JobProcessor.mjs:195`) e spostamento di file o cartelle (`JobProcessor.mjs:239`). |
| `StateManager.mjs:96-103` (`addTombstone`) | Dopo un'eliminazione (`JobProcessor.mjs:153`), una ridenominazione del progetto (`:202`) o uno spostamento (`:240`) in Dropbox. |
| `StateManager.mjs:72-78` (`removeEntities`) | Elimina le voci in un percorso e al di sotto, tranne i tombstone: dopo un'eliminazione da Overleaf (`JobProcessor.mjs:152`) o in Dropbox (`PullManager.mjs:206`). |
| `StateManager.mjs:115-121` (`clearTombstones`) | Alla fine di un pull (`PullManager.mjs:31,69`). |
| `StateManager.mjs:186-190` (`removeUserState`), chiamato da `services/third-party-datastore/app/js/QueueWorker.mjs:43` | Elimina tutti i documenti dell'utente quando third-party-datastore scollega un account che non può più usare. |
| `DropboxHandler.mjs:142-146` (`removeUserState`) | Elimina tutti i documenti dell'utente al collegamento (`:125`), allo scollegamento (`:183`) e quando un utente eliminato scade (`services/web/modules/dropbox/index.mjs:62-64`). |
| `DropboxHandler.mjs:150-154` (`removeProjectState`) | Elimina i documenti del progetto quando un progetto eliminato scade (`index.mjs:54-56`). |

#### Chi la legge {#who-reads-it}

| Codice | Cosa fa |
| ------ | ------- |
| `StateManager.mjs:64-70` (`findEntityByPath`) | Ottiene `dropbox.rev` prima di un caricamento (`JobProcessor.mjs:114`) e `dropbox.contentHash` prima di applicare un file Dropbox (`PullManager.mjs:147`). |
| `StateManager.mjs:106-112` (`findTombstone`) | Verifica un'eliminazione segnalata nel percorso o in uno dei suoi genitori (`PullManager.mjs:189`). |
| `StateManager.mjs:160-175` (`getSyncedPaths`) | Elenca i percorsi dei file sincronizzati dopo un reset del cursore, così che un file assente dall'elenco conti come eliminato (`PullManager.mjs:74-85`). |

`20220811111800_create_dropboxEntities_index.mjs` e `20220825160708_recreate_dropboxEntities.mjs` hanno solo il tag `saas`, quindi CE non ha i loro indici univoci su `(overleaf.userId, dropbox.id)` e `(overleaf.userId, overleaf.id)`, né il loro indice hashed su `dropbox.pathLower`.

#### Note {#notes}

* L'unicità deriva solo dall'eliminazione che precede ogni inserimento in `recordEntity` (`StateManager.mjs:38-45`). Il commento in `StateManager.mjs:3-11` menziona indici univoci; CE non li ha.
* Le query per utente e percorso (`findEntityByPath`, `findTombstone`, `removeEntities`) usano l'indice solo per `overleaf.userId`.
