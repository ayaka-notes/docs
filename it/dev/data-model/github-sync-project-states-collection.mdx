`githubSyncProjectStates` contiene un documento per ogni progetto collegato a un repository GitHub: quale repository e dove si è fermata l'ultima sincronizzazione. Appartiene al modulo web `github-sync` (`services/web/modules/github-sync`). Lo schema è in `services/web/modules/github-sync/app/models/githubSyncProjectStates.mjs`, e ogni accesso passa da `services/web/modules/github-sync/app/src/SyncStateManager.mjs`.

#### Campi {#fields}

| Campo | Tipo | Significato | Fonte |
| ----- | ---- | ----------- | ----- |
| `_id` | ObjectId | Impostato da Mongoose alla creazione. | |
| `projectId` | ObjectId | Il progetto collegato. Obbligatorio. Lo schema indica `unique: true`, ma non viene creato alcun indice (vedi Indici). | `githubSyncProjectStates.mjs:8` |
| `repoFullName` | String | Il repository come `owner/name` (il `full_name` di GitHub). Obbligatorio. | `githubSyncProjectStates.mjs:9` |
| `defaultBranchName` | String | Il branch con cui il progetto si sincronizza. Impostato quando il progetto viene collegato e non modificato in seguito: all'importazione, il branch inviato dal modulo di importazione; all'esportazione, il branch predefinito del nuovo repository. Predefinito `null`. | `githubSyncProjectStates.mjs:10`, `GitHubSyncHandler.mjs:175-181,235-241` |
| `mergeStatus` | String | `clean`, `conflict` o `diverged`. Predefinito `clean`. | `githubSyncProjectStates.mjs:11` |
| `lastSyncCommit` | String | Lo SHA del commit sul branch sincronizzato all'ultima sincronizzazione. Predefinito `null`. | `githubSyncProjectStates.mjs:12` |
| `lastSyncVersion` | Number | La versione della cronologia del progetto all'ultima sincronizzazione, da project-history `GET /project/:id/version`, letta dopo un flush della cronologia. Predefinito `null`. | `githubSyncProjectStates.mjs:13`, `services/web/modules/github-sync/app/src/HistoryManager.mjs:8-17` |
| `unmergedBranchName` | String | Durante un conflitto: il branch temporaneo con le modifiche di Overleaf, chiamato `overleaf-YYYY-MM-DD-HHMMSS`. `null` quando non c'è conflitto. | `githubSyncProjectStates.mjs:14`, `GitMerge.mjs:773-777` |
| `unmergedBranchHead` | String | Durante un conflitto: il commit di testa di quel branch. Predefinito `null`. | `githubSyncProjectStates.mjs:15` |
| `conflictVersion` | Number | Durante un conflitto: la versione della cronologia del progetto quando il conflitto è stato registrato. Predefinito `null`. | `githubSyncProjectStates.mjs:16` |
| `__v` | Number | La chiave di versione di Mongoose. Lo schema non la disattiva. | Predefinito di Mongoose |

#### Chi la scrive {#who-writes-it}

| Codice | Cosa fa |
| ------ | ------- |
| `SyncStateManager.mjs:9-14` (`createProjectState`) | Crea il documento: dopo aver importato un repository come nuovo progetto (`services/web/modules/github-sync/app/src/GitHubSyncHandler.mjs:175-181`), o dopo aver esportato un progetto in un nuovo repository (`GitHubSyncHandler.mjs:235-241`, solo il proprietario, rifiutato se già collegato). |
| `SyncStateManager.mjs:16-21` (`updateProjectState`) | `$set` dei campi modificati. `getMergeOverview` imposta `mergeStatus: 'diverged'` quando il branch sincronizzato non parte più da `lastSyncCommit`: il compare di GitHub risponde `diverged` o `behind` (`GitHubApiClient.mjs:382-400`), oppure il commit non esiste più e l'utente può fare push (`GitHubSyncHandler.mjs:123,126-137`). Una sincronizzazione (`services/web/modules/github-sync/app/src/GitMerge.mjs`) fa avanzare `lastSyncCommit`/`lastSyncVersion` in caso di successo (ad esempio `:143,173,224`), registra un conflitto con `unmergedBranchName`, `unmergedBranchHead` e `conflictVersion` (`:207-213`), e li azzera una volta risolto (`:250-257`). |
| `SyncStateManager.mjs:23-25` (`removeProjectState`) | Elimina il documento quando il proprietario scollega il progetto (`GitHubSyncHandler.mjs:83-97`) e quando un progetto eliminato scade (`services/web/modules/github-sync/index.mjs:56-58`). |

#### Chi la legge {#who-reads-it}

| Codice | Cosa fa |
| ------ | ------- |
| `GitHubSyncHandler.mjs:39-60` (`getProjectState`) | Fornisce all'editor `mergeStatus`, `repoFullName` e `unmergedBranchName`. Senza documento risponde `need-export`, un valore che non viene mai memorizzato. |
| `GitHubSyncHandler.mjs:110-143` (`getMergeOverview`) | Confronta `lastSyncCommit` e `lastSyncVersion` con GitHub e la cronologia del progetto per elencare i nuovi commit. |
| `GitHubSyncHandler.mjs:200` (`exportProject`) | Rifiuta di esportare un progetto già collegato. |
| `GitMerge.mjs:27` (`doGitMergeWithoutLock`) | Carica lo stato all'inizio di una sincronizzazione. |

#### Indici {#indexes}

| Nome | Chiavi | Opzioni | Migrazione |
| ---- | ------ | ------- | ---------- |
| `_id_` | `_id: 1` | | default |

L'`autoIndex` di Mongoose è disattivato (`services/web/app/src/infrastructure/Mongoose.mjs:7`), quindi il `unique: true` dello schema su `projectId` non crea nulla. `tools/migrations/20190912145010_create_githubSyncProjectStates_indexes.mjs` (`project_id` e `owner_id` di upstream) ha solo il tag `saas` e non viene eseguita in CE.

#### Note {#notes}

* Una sincronizzazione viene eseguita sotto il lock `gitSync` del progetto (`GitMerge.mjs:17-24`). GitLab Sync e Gitea Sync usano lo stesso lock, quindi per ogni progetto viene eseguita una sola sincronizzazione alla volta.
* Un progetto eliminato mantiene il suo documento finché il progetto non scade.
* Il token GitHub dell'utente si trova in [GitHub Sync User Credentials](/it/dev/data-model/github-sync-user-credentials-collection).
