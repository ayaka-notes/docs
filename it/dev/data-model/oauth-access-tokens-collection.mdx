title: Collezione OAuth Access Tokens

---

`oauthAccessTokens` contiene i token bearer che web accetta. In Ayakaleaf Pro sono i token di accesso personali (token di autenticazione Git) che un utente crea nella pagina delle impostazioni dell'account e usa per git-bridge e per l'endpoint MCP. Un documento è un token. Lo schema è `services/web/app/src/models/OauthAccessToken.mjs`; il modulo web `oauth2-server` scrive la collezione, per lo più con il driver nativo.

#### Chi scrive {#who-writes-it}

| Codice | Cosa fa |
| ---- | ------------ |
| `OAuthPersonalAccessTokenManager.mjs:53-88` (`createToken`) | Inserisce un token di accesso personale. La route `POST /oauth/personal-access-tokens` (`services/web/modules/oauth2-server/app/src/OAuthPersonalAccessTokenRouter.mjs:22-27`) richiede la funzionalità `gitBridge` dell'utente e consente 10 token per utente (`OAuthPersonalAccessTokenController.mjs:7,34-38`). |
| `OAuthPersonalAccessTokenManager.mjs:90-105` (`removeToken`) | Elimina un token dell'utente. Route `DELETE /oauth/personal-access-tokens/:token_id` (`OAuthPersonalAccessTokenRouter.mjs:29-32`). |
| `OAuthPersonalAccessTokenManager.mjs:136-140`, `OAuth2Model.mjs:58-61` | Impostano `lastUsedAt` dopo un controllo riuscito. |

#### Note {#notes}

* Eliminare un utente non elimina i suoi token. `UserDeleter` attiva l'hook `cleanupPersonalAccessTokens` (`services/web/app/src/Features/User/UserDeleter.mjs:230-234`), ma nessun modulo lo ascolta. Entrambi i controlli dei token rifiutano i token perché l'utente non esiste più, e l'indice TTL li rimuove un giorno dopo `accessTokenExpiresAt`.
* Sospendere un utente chiude solo le sessioni. I token restano, ed entrambi i controlli dei token li rifiutano finché `users.suspended` è `true` (`OAuth2Model.mjs:51-54`, `OAuthPersonalAccessTokenManager.mjs:129-134`).
