---
title: Collezione Docs
icon: file-lines
---

`docs` contiene il contenuto dei file di testo modificabili di un progetto (Overleaf li chiama doc), ad esempio `main.tex` o `sample.bib`. Un documento per doc: le sue righe, i suoi commenti e le modifiche tracciate, due contatori e lo stato di eliminazione. Il nome del file e la sua posizione nell’albero non sono qui ma in `projects.rootFolder` (vedi [Collezione Projects](/it/dev/data-model/projects-collection)). Nemmeno i file binari sono qui.

A parte le migrazioni e gli script di manutenzione, solo docstore scrive questa collezione, in `services/docstore/app/js/MongoManager.js`. Non esiste un modello Mongoose; web e document-updater vi accedono tramite l’API HTTP di docstore (`services/docstore/app.js:31-70`). Nella colonna Fonte, i nomi di file senza percorso si trovano sotto `services/docstore/app/js/`.

#### Campi {#fields}

| Campo | Tipo | Significato | Fonte |
| ----- | ---- | ------- | ------ |
| `_id` | ObjectId | Id del doc, lo stesso `_id` della voce del doc in `projects.rootFolder`. | `MongoManager.js:142-147` |
| `project_id` | ObjectId | Progetto del doc. | `MongoManager.js:144` |
| `lines` | Array of String | Il testo, un elemento per riga. Assente mentre il doc è archiviato (`inS3: true`). | `DocManager.js:314-316`, `MongoManager.js:203` |
| `ranges` | Object | Commenti e modifiche tracciate, vedi sotto. Assente mentre il doc è archiviato. | `DocManager.js:317-319`, `RangeManager.js:36-65` |
| `rev` | Number | Il contatore proprio di docstore. Parte da 1 e aumenta di 1 ogni volta che cambiano `lines` o `ranges`. Ogni aggiornamento verifica il vecchio `rev`, così due scrittori non possono sovrascriversi. Non è una versione della cronologia. | `MongoManager.js:115-136`, `:145`, `:254-269` |
| `version` | Number | La versione OT del doc proveniente da document-updater, salvata al flush. docstore rifiuta un flush con una versione inferiore. I doc più vecchi la tenevano nella collezione `docOps`; la migrazione `20231105000000_move_doc_versions_from_docops_to_docs` l’ha spostata qui. | `DocManager.js:283-290`, `:320-322` |
| `deleted` | Boolean | `true` quando il doc è stato eliminato dal progetto. Assente per i doc mai eliminati. | `services/docstore/app/js/HttpController.js:80-90` |
| `deletedAt` | Date | Quando il doc è stato eliminato. | `HttpController.js:87` |
| `name` | String | Nome del file al momento dell’eliminazione. Impostato solo quando il doc viene eliminato; i doc attivi non hanno `name` qui. | `HttpController.js:88`, `services/web/app/src/Features/Docstore/DocstoreManager.mjs:28-36` |
| `inS3` | Boolean | `true` quando `lines`, `ranges` e `rev` sono stati spostati nel persistor di docstore (`Settings.docstore.bucket`, chiave `<project_id>/<doc_id>`) e `lines` e `ranges` sono stati rimossi da Mongo. #### Ranges {#ranges}

`ranges` ha due array. document-updater li costruisce con `libraries/ranges-tracker/index.cjs`; docstore converte gli id in ObjectId e `ts` in Date prima del salvataggio (`RangeManager.js:41-63`). Un doc senza commenti né modifiche tracciate ha `ranges: {}` oppure nessun `ranges`.

| Campo | Tipo | Significato | Fonte |
| ----- | ---- | ------- | ------ |
| `ranges.comments` | Array of Object | Porzioni di testo commentate. | `libraries/ranges-tracker/index.cjs:217-236` |
| `ranges.comments.id` | ObjectId | Id del commento. È uguale a `op.t`, l’id del thread del commento nella collezione `rooms`; docstore impone che coincidano. | `RangeManager.js:54-57` |
| `ranges.comments.op.c` | String | Il testo commentato nel doc (non il messaggio del commento). | `index.cjs:226-230` |
| `ranges.comments.op.p` | Number | Offset in caratteri dell’inizio di `op.c` nel doc. | `index.cjs:226-230` |
| `ranges.comments.op.t` | ObjectId | Id del thread, vedi `id`. | `index.cjs:226-230`, `RangeManager.js:57` |
| `ranges.comments.metadata` | Object | `user_id` e `ts` del commento. | `index.cjs:232`, `RangeManager.js:62` |
| `ranges.changes` | Array of Object | Modifiche tracciate, ordinate per posizione. | `index.cjs:640-660` |
| `ranges.changes.id` | ObjectId | Id della modifica. | `index.cjs:643-647`, `RangeManager.js:51` |
| `ranges.changes.op.i` / `op.d` | String | Testo inserito o testo eliminato. Uno dei due. | `index.cjs:640-660` |
| `ranges.changes.op.p` | Number | Offset in caratteri della modifica. | `index.cjs:640-660` |
| `ranges.changes.metadata.user_id` | ObjectId or String | Autore. Le modifiche degli editor anonimi mantengono la stringa `anonymous-user`. | `RangeManager.js:45-46`, `DocManager.js:192` |
| `ranges.changes.metadata.ts` | Date | Quando è stata fatta la modifica. | `RangeManager.js:42-43` |

Il testo di un commento e delle sue risposte non è in `docs`: si trova nella collezione `messages`, nella room il cui `thread_id` è l’id del commento. Se un commento è risolto viene memorizzato su quella room, non qui; docstore scarta un flag `resolved` se ne riceve uno (`RangeManager.js:59-61`). Vedi [Collezione Rooms](/it/dev/data-model/rooms-collection) e [Collezione Messages](/it/dev/data-model/messages-collection).

#### Chi scrive {#who-writes-it}

| Codice | Cosa fa |
| ---- | ------------ |
| `DocManager.js:223-338` (`POST /project/:project_id/doc/:doc_id`) | Crea o aggiorna un doc: `lines`, `ranges` e `version`. Web lo chiama quando viene creato un doc e quando document-updater esegue il flush di un doc aperto (`services/web/app/src/Features/Project/ProjectEntityUpdateHandler.mjs:174`). |
| `DocManager.js:346-366` (`PATCH /project/:project_id/doc/:doc_id`) | Contrassegna un doc come eliminato con `deleted`, `deletedAt` e `name`. |
| `DocArchiveManager.js:29-88` | Archivia un doc: copia `lines`, `ranges` e `rev` nel persistor e imposta `inS3`. Viene eseguito per un intero progetto quando viene disattivato, e per un singolo doc all’eliminazione quando `ARCHIVE_ON_SOFT_DELETE=true` (`DocManager.js:355-363`). |
| `DocArchiveManager.js:150-174` | Riporta in Mongo un doc archiviato quando viene letto (`DocManager.js:40-41`). |
| `MongoManager.js:272-274` | Elimina tutti i doc di un progetto quando il progetto viene distrutto. |

| ---- | ---- | ------- | --------- |

#### Note {#notes}

* Mentre un doc è aperto, il suo testo più recente si trova in document-updater (Redis), non qui. Mongo viene aggiornato solo quando document-updater esegue il flush (`services/document-updater/app/js/PersistenceManager.js:128-160`). Il codice che legge i doc di un intero progetto dovrebbe prima chiamare `flushProjectToMongo`, come fa `ProjectDuplicator`.
* I doc eliminati restano in questa collezione, con `deleted: true`, finché il progetto non viene distrutto. docstore ne restituisce al massimo `MAX_DELETED_DOCS` (predefinito 2000), dal più recente (`MongoManager.js:29-44`, `services/docstore/config/settings.defaults.cjs:40`). Il pannello della cronologia non li usa; legge history-v1.
* I contatori `rev` e `version` non hanno relazione con le versioni della cronologia del progetto in history-v1.
