`notifications` contiene gli avvisi mostrati in cima alla dashboard dei progetti di un utente. Un documento è un avviso per un utente, identificato dalla sua `key`. Solo il servizio `notifications` accede alla collezione (`services/notifications/app/js/Notifications.js`); `web` e `third-party-datastore` chiamano la sua API HTTP. Non esiste uno schema Mongoose.

#### Campi {#fields}

| Campo | Tipo | Significato | Fonte |
| --- | --- | --- | --- |
| `_id` | ObjectId | Id dell'avviso. `web` segna un avviso come letto tramite questo id. | `Notifications.js:58-65` |
| `user_id` | ObjectId | L'utente che vede l'avviso. | `Notifications.js:26` |
| `key` | String | Identifica l'avviso, per esempio `project-invite-<inviteId>`. L'upsert mantiene un documento per `user_id` e `key`; non esiste un indice univoco. | `Notifications.js:27`, `:51-55` |
| `templateKey` | String | Quale avviso visualizza il frontend. Viene rimosso quando l'avviso viene letto o chiuso; il documento rimane. | `Notifications.js:29`, `:63`, `:72`, `:78` |
| `messageOpts` | Object | Valori per il testo dell'avviso, a seconda di `templateKey` (per un invito a un progetto: `userName`, `projectName`, `projectId`, `token`). Viene rimosso quando l'utente chiude l'avviso tramite id. | `Notifications.js:28`, `:63` |
| `expires` | Date | Facoltativo. L'indice TTL elimina il documento dopo questa data. | `Notifications.js:35-50` |

| `Notifications.js:58-65` (`removeNotificationId`) | `DELETE /user/:user_id/notification/:notification_id` (`app.ts:31-34`): rimuove `templateKey` e `messageOpts`. |
| `Notifications.js:67-80` | `DELETE /user/:user_id` e `DELETE /key/:key` (`app.ts:35-36`): rimuovono `templateKey` per chiave. |
| `Notifications.js:87-100` | `DELETE /key/:key/bulk` (`app.ts:38-41`) elimina gli avvisi non letti con una chiave; `deleteNotificationByKeyOnly` elimina un documento per chiave. |

`NotificationsBuilder.mjs` costruisce anche chiavi per inviti di gruppo, affiliazioni istituzionali, abbonamenti e vecchi progetti di debug. I loro chiamanti si trovano nel codice di abbonamenti e istituzioni, e il controllo dei vecchi progetti di debug viene eseguito solo con `isSaas` (`services/web/app/src/Features/Project/ProjectListController.mjs:234-236`).

#### Note {#notes}

* Un avviso letto non viene eliminato: sparisce solo `templateKey`. Poiché il documento contiene ancora la chiave, un successivo `addNotification` senza `forceCreate` per la stessa chiave non fa nulla (`Notifications.js:21-24`).
* Le route `/key/:key` agiscono sulla sola chiave, per tutti gli utenti (`Notifications.js:76-100`).
* Se `web` non ha `apis.notifications.url`, non crea né legge avvisi (`NotificationsHandler.mjs:17`, `:41`).
