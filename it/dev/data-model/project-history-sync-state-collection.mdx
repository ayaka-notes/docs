title: Collezione Project History Sync State
icon: rotate
---

`projectHistorySyncState` contiene un documento per ogni progetto che è stato risincronizzato: lo stato della risincronizzazione in corso o dell’ultima, quando project-history ricostruisce la cronologia di un progetto a partire da ciò che contengono web e docstore. Appartiene a project-history e non ha uno schema Mongoose; il codice è la classe `SyncState` con le sue funzioni di supporto in `services/project-history/app/js/SyncManager.js`.

| Campo | Tipo | Significato | Fonte |

| `project_id` | ObjectId | Il progetto. | `SyncManager.js:233-237` |
| `resyncProjectStructure` | Boolean | `true` finché project-history attende da web la struttura del progetto (albero dei file). | `SyncManager.js:457`, `536-543` |
| `resyncDocContents` | Array of String | Percorsi dei doc di cui attende ancora il contenuto. | `SyncManager.js:458`, `482`, `545-546` |
| `origin` | Object | Chi ha richiesto la risincronizzazione, ad esempio `{ kind: 'history-resync' }`, il valore predefinito. | `SyncManager.js:150`, `459` |
| `hardResync` | Boolean | `true` per una risincronizzazione completa, che prima scarta gli aggiornamenti in coda e il vecchio stato di sincronizzazione. | `SyncManager.js:81-100`, `152`, `460` |
| `recoverCorruptedFiles` | Boolean | Opzione della richiesta di risincronizzazione (`HttpController.js:963-964`). | `history` | Array of Object | Gli ultimi 100 stati, dal più recente, ciascuno `{ syncState, timestamp }`; `syncState` contiene i cinque campi sopra. | `SyncManager.js:41`, `202-208` |
| `lastUpdated` | Date | Ora dell’ultima scrittura. | `SyncManager.js:209` |

#### Chi scrive {#who-writes-it}

| Codice | Cosa fa |
| ---- | ------------ |
| `services/project-history/app/js/SyncManager.js:195-249` | `setResyncState`: upsert dello stato. Chiamato quando inizia una risincronizzazione (`SyncManager.js:163`) e mentre project-history elabora gli aggiornamenti di risincronizzazione (`services/project-history/app/js/UpdatesProcessor.js:637`, `784`). |
| `SyncManager.js:257-266` | `_recordStuckClearInSyncState`: conta una risincronizzazione bloccata che viene azzerata. |
| `SyncManager.js:251-255` | `clearResyncState`: elimina il documento all’inizio di una risincronizzazione completa (`SyncManager.js:87`), su `DELETE /project/:project_id` di project-history (`services/project-history/app/js/HttpController.js:1363-1396`) e quando una risincronizzazione della sola struttura deve ricominciare (`SyncManager.js:705-716`). |
| `SyncManager.js:273-289` | `clearResyncStateIfAllAfter`: elimina uno stato concluso la cui cronologia è interamente successiva a una data. Nulla in `app/js` lo chiama. |
| `SyncManager.js:171-181` | `cloneResyncState`: copia lo stato in un altro progetto, per `POST /project/:project_id/clone` di project-history (`HttpController.js:57`, `124`), che nulla in web chiama. |

Una risincronizzazione viene avviata da `POST /project/:project_id/resync` di project-history (`HttpController.js:950-994`), dai cron job di ripetizione (`services/project-history/app/js/RetryManager.js:156-179`, `server-ce/config/crontab-history`) e da project-history stesso quando l’elaborazione degli aggiornamenti ne richiede una (`UpdatesProcessor.js:75`, `224`).

#### Chi legge {#who-reads-it}

| Codice | Cosa fa |
| ---- | ------------ |
| `SyncManager.js:187-193` | `getResyncState`: carica lo stato. Usato per decidere se una risincronizzazione è in corso prima di avviarne una nuova (`SyncManager.js:106-149`), per saltare gli aggiornamenti ordinari mentre è in corso (`SyncManager.js:291-300`) e, dopo un flush, per segnalare una risincronizzazione in corso (`UpdatesProcessor.js:463-466`). |

| `HttpController.js:563-585` | `GET /project/:project_id/debug-info`: lo stato di sincronizzazione con il record dell’errore. |

#### Note {#notes}

* Una risincronizzazione è in corso finché `resyncProjectStructure` è `true` o `resyncDocContents` non è vuoto (`SyncManager.js:565-567`). È considerata bloccata dopo 4 ore, e bloccata in modo permanente dopo 5 azzeramenti (`SyncManager.js:43-44`, `569-585`).
* Quando una risincronizzazione termina, project-history imposta anche `overleaf.history.lastResyncedAt` sul progetto (`SyncManager.js:239-248`).
