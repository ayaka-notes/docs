### Docker

Docker offre un modo leggero e portabile per pacchettizzare ed eseguire applicazioni in container isolati. Raggruppando l'applicazione con tutte le dipendenze necessarie, un container garantisce un comportamento coerente su macchine diverse, dai laptop ai server di produzione.

TeX Live è potente ma voluminoso e sensibile alle differenze a livello di sistema. Pacchettizzare TeX Live in un'immagine Docker rende la toolchain LaTeX prevedibile, riproducibile e facile da distribuire.

Tuttavia, alcuni pacchetti TeX Live si basano sull'accesso alla shell. Per motivi di sicurezza, il container dovrebbe essere eseguito in un ambiente limitato che impedisca agli utenti di eseguire comandi shell arbitrari (ad esempio tramite `\write18` o lo shell escape). Questo isolamento protegge il sistema host ed evita accessi indesiderati al filesystem sottostante del container o a strumenti come `bash`.

### TeXLive Full Edition

[TeXLive-Full@ayaka-notes](https://github.com/ayaka-notes/texlive-full/) è un'**immagine Docker di TeXLive** completa, progettata per la compilazione LaTeX in sandbox in [Ayakaleaf Pro](https://github.com/ayaka-notes/ayakaleaf-pro), [Overleaf CEP](https://github.com/yu-i-i/overleaf-cep) o in ambienti di compilazione LaTeX autonomi.

Questa immagine mira a fornire una distribuzione TeXLive quasi completa con font e strumenti comuni preinstallati, per ridurre al minimo gli errori di compilazione causati da pacchetti o font mancanti. Note: questa immagine Docker **non contiene** alcun componente di sharelatex/overleaf. Viene usata per la compilazione di Overleaf/Overleaf Pro.

#### Caratteristiche:

* 🚀 Supporta sia l'architettura server x86\_64 sia arm64
* 📦 Installazione di TeXLive completa e ottimizzata
* 🧩 Font e utility comuni preinstallati
* 🐳 Pronta all'uso con Docker e Docker Compose
* 🧪 Testata con Overleaf Server Pro / Overleaf Pro
* 🔄 Aggiornata regolarmente con le ultime release di TeXLive
* 🏷 Tag per più versioni di TeXLive (dalla 2020 all'ultima)
* 🧑‍🔬 Supporto a Knitr per il codice R nei documenti LaTeX

### Uso con Ayakaleaf Pro

TeX Live Full di Ayaka-notes è progettato appositamente per [ayakaleaf-pro](https://github.com/ayaka-notes/ayakaleaf-pro); se sei un [utente del toolkit](https://github.com/overleaf/toolkit), puoi aggiungere le seguenti variabili d'ambiente al file `config/variables.env`.

Ad esempio:

```dotenv title="config/variables.env" wrap
ALL_TEX_LIVE_DOCKER_IMAGES=ghcr.io/ayaka-notes/texlive-full:2026.1, ghcr.io/ayaka-notes/texlive-full:2025.1
ALL_TEX_LIVE_DOCKER_IMAGE_NAMES=Texlive 2026, Texlive 2025
TEX_LIVE_DOCKER_IMAGE=ghcr.io/ayaka-notes/texlive-full:2026.1
```

### Versioni di TeX Live

Grazie a GitHub Action, possiamo compilare in parallelo tutte le immagini TeX, che includono:

* `ghcr.io/ayaka-notes/texlive-full:2026.1` (anche con il tag `latest`)
* `ghcr.io/ayaka-notes/texlive-full:2025.1`
* `ghcr.io/ayaka-notes/texlive-full:2024.1`
* `ghcr.io/ayaka-notes/texlive-full:2023.1`
* `ghcr.io/ayaka-notes/texlive-full:2022.1`
* `ghcr.io/ayaka-notes/texlive-full:2021.1`
* `ghcr.io/ayaka-notes/texlive-full:2020.1`
* `ghcr.io/ayaka-notes/texlive-full:base`

Usiamo l'archivio mirror di [texlive info](https://texlive.info/tlnet-archive/), che include quasi tutte le immagini TeX Live dal 1996 al 2025. E grazie al Dockerfile di Overleaf, possiamo compilare questo progetto più rapidamente.

> Perché TeX Live 2019 e versioni precedenti non sono supportati?
>
> Mantenere queste vecchie immagini è estremamente difficile. Inoltre, il sito [texlive.info](https://texlive.info/) non fornisce informazioni sulle versioni di TeX Live rilasciate prima del 2019, quindi non siamo in grado di compilare immagini per tali versioni. Se hai bisogno di una specifica versione precedente, apri una issue e faccelo sapere.

### Componenti inclusi

I seguenti pacchetti sono inclusi nell'immagine Docker.

* Tutti i pacchetti TeXLive (dell'anno corrispondente)
* Pacchetti R (solo alcuni selezionati)
* fontconfig inkscape pandoc python3-pygments wget python3

### Problemi

<Accordion title="Problema 01: cache dei font mancante">

Quando Overleaf compila un progetto LaTeX, se manca un font **potresti notare che la compilazione richiede molto tempo**: ciò accade perché, quando manca un font, TeX Live tenta di **ricostruire l'intera cache dei font**. È un processo che richiede molto tempo.

Nella nostra immagine abbiamo precompilato la cache dei font; abbiamo risolto questo problema con [questo commit](https://github.com/ayaka-notes/texlive-full/commit/0cb66b0dc8b82be628cf6999cfd659d9784e132f)

</Accordion>

<Accordion title="Problema 02: SyncTeX estremamente lento">

Quando usi questa immagine in sharelatex, potresti notare che SyncTeX è estremamente lento.

Vedi: [https://github.com/overleaf/overleaf/issues/1150](https://github.com/overleaf/overleaf/issues/1150): basta disabilitare HTTP 2.0.

</Accordion>

<Accordion title="Problema 03: errore di ricompilazione con l'immagine TeX Live ufficiale">

Se usi l'immagine TeX Live ufficiale su Docker Hub `texlive/texlive`, potresti notare che, quando ricompili un progetto, viene segnalato un errore. Nella nostra immagine, invece, questo problema è risolto, perché usiamo l'immagine base di Ubuntu più recente e installiamo tutte le dipendenze dal repository ufficiale di Ubuntu.

</Accordion>

### Altri promemoria tecnici

Quando compili un'immagine TeX Live (precedente al 2019), potresti dover prestare attenzione ai seguenti problemi:

* Prima di TeX Live 2017 sono supportati solo `http`/`ftp`, quindi non puoi usare `https` per il download, a meno di modificare lo script `peal`.
* Prima del 2015 viene fornito solo il file sha256, quindi non puoi usare sha512 per la verifica.
