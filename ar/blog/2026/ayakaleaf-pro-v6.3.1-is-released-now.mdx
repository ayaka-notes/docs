يسعدنا كثيرًا أن نعلن عن إصدار Overleaf Pro 6.3.1، محرر LaTeX عبر الإنترنت الأقوى والأغنى بالميزات في المجتمع. يعني الإصدار التصحيحي عادةً حفنة من الإصلاحات الصغيرة. أما هذا الإصدار فيذهب إلى أبعد من ذلك بكثير: فإلى جانب عشرات إصلاحات الأخطاء، يجلب خمس ميزات جديدة، ويربط مشاريعك بالأماكن التي تعمل فيها بالفعل، من Dropbox و GitLab إلى وكيل الذكاء الاصطناعي في الطرفية لديك.

### التغييرات

* المزامنة مع Dropbox (معاينة مبكرة): أبقِ كل مشروع متزامنًا مع Dropbox الخاص بك، في كلا الاتجاهين.
* المزامنة مع GitLab (معاينة مبكرة): مزامنة ثنائية الاتجاه مع GitLab.com أو GitLab المُدار ذاتيًا لديك.
* خادم MCP: دع Claude Code أو Codex أو Cursor أو VS Code أو Gemini CLI يعمل على مشروع مباشرةً.
* GitHub Enterprise: وجّه المزامنة مع GitHub إلى مثيل GitHub Enterprise الخاص بك.
* التعرّف على الرموز المكتوبة بخط اليد: ارسم رمزًا واحصل على أمر LaTeX.
* `OVERLEAF_DISABLE_LOCAL_LOGIN`: أخفِ تسجيل الدخول بالبريد الإلكتروني وكلمة المرور ليسجّل المستخدمون الدخول عبر SSO فقط.
* إصلاحات لأخطاء اكتشفها نظام اختبار E2E لدينا والتحقيق الداخلي في المشكلات Horizon (Internal Horizon Issue Investigation).
* رقع Overleaf 6.3.1 من المصدر الأصلي (upstream).

<Info>

تأتي المزامنة مع Dropbox والمزامنة مع GitLab في الإصدار 6.3.1 بوصفهما **معاينتين مبكرتين** للاختبار التدريجي، وستُطلقان رسميًا في الإصدار v6.4.0. وقد تتغيّر إعداداتهما وسلوكهما قبل ذلك. كلتاهما معطّلتان افتراضيًا. يُرجى الإبلاغ عن أي مشكلات على [GitHub](https://github.com/ayaka-notes/ayakaleaf-pro/issues).

</Info>

#### الميزة 01: المزامنة مع Dropbox (معاينة)

بعض الناس لا يريدون التفكير في Git أبدًا. كل ما يريدونه أن تكون أطروحتهم مجلدًا على حاسوبهم المحمول، والمزامنة مع Dropbox تمنحهم ذلك تمامًا. يربط كل مستخدم حسابه الخاص على Dropbox، وتظهر المشاريع التي يملكها والمشتركة معه ضمن `Apps/<your app name>/`. حرّر في Overleaf فيظهر التغيير في Dropbox. حرّر الملف محليًا في محررك المفضل واحفظه، فيعود التغيير إلى Overleaf عبر webhook موقّع.

للمسؤولين: يجب تفعيل Git bridge. أنشئ تطبيقًا في Dropbox App Console، ثم اضبط `DROPBOX_ENABLED` و `DROPBOX_APP_KEY` و `DROPBOX_APP_SECRET` و `DROPBOX_APP_NAME` و `DROPBOX_TOKEN_CIPHER_PASSWORD`. أما `DROPBOX_SYNC_PROXY_URL` فاختياري، للخوادم التي لا تستطيع الوصول إلى Dropbox مباشرةً. ثم أنشئ فهارس MongoDB التي تحتاجها المزامنة مع Dropbox، مرة واحدة، قبل أن يربط المستخدمون حساباتهم.

راجع [المزامنة مع Dropbox](/ar/on-premises/configuration/overleaf-toolkit/dropbox-synchronisation  "mention") للاطلاع على تعليمات الإعداد الكاملة.

#### الميزة 02: المزامنة مع GitLab (معاينة)

كانت المزامنة مع GitHub من أكثر ميزاتنا المحبوبة منذ الإصدار 6.2، بينما تحتفظ جامعات وشركات كثيرة بشيفرتها على GitLab بدلًا من ذلك. تعمل المزامنة مع GitLab بالطريقة نفسها: اربط حسابك، واستورد مستودعًا من قائمة المشروع الجديد، أو صدّر مشروعًا إلى مشروع GitLab جديد. ثم ادفع واسحب من المحرر، وادمج عبر طلبات الدمج (merge requests).

تعمل مع GitLab.com ومع GitLab المُدار ذاتيًا بالإصدار 15.10 أو أحدث. اضبط `GITLAB_SYNC_ENABLED` و `GITLAB_SYNC_CLIENT_ID` و `GITLAB_SYNC_CLIENT_SECRET` و `GITLAB_TOKEN_CIPHER_PASSWORD`، بالإضافة إلى `GITLAB_SYNC_URL` للمثيل المُدار ذاتيًا.

راجع [المزامنة مع GitLab](/ar/on-premises/configuration/overleaf-toolkit/gitlab-synchronisation  "mention") للاطلاع على تعليمات الإعداد الكاملة.

#### الميزة 03: خادم MCP

في الإصدار 6.3 وضعنا مساعد ذكاء اصطناعي داخل المحرر. وفي الإصدار 6.3.1 نفتح الباب في الاتجاه الآخر: أصبح لكل مشروع الآن خادم MCP خاص به، لذا يمكن لوكيل الذكاء الاصطناعي الذي تستخدمه بالفعل العمل على ورقتك مباشرةً. اطلب من Claude Code إصلاح الأخطاء الإملائية في المقدمة، أو اطلب من Codex الترجمة وإصلاح أخطاء LaTeX، أو اطلب من Cursor الرد على تعليقات المراجعة المفتوحة. يقرأ الوكيل الملفات ويعدّلها مباشرةً، لذا ترى أنت ومتعاونوك تعديلاته تظهر في المحرر أثناء كتابته. ويمكنه أيضًا الترجمة، وقراءة السجل، وجلب ملف PDF، وعدّ الكلمات، وسرد الإصدارات.

نقطة النهاية هي `/project/<project_id>/mcp`. صادِق باستخدام رمز Git نفسه الذي تستخدمه مع `git clone`. يتبع الوصول إعدادات مشاركة المشروع، لذا يستطيع وكيل العارض القراءة دون التعديل، ويخضع كل أداة لحدّ معدّل الاستخدام. لا يوجد شيء آخر لإعداده: يُفعَّل خادم MCP مع Git bridge.

<img src="https://github.com/user-attachments/assets/a8702201-db3f-4985-a050-b7ebdbe7a952" alt="خادم MCP" width="787" />

راجع [خادم MCP](/ar/on-premises/configuration/overleaf-toolkit/mcp-server  "mention") لمعرفة كيفية ربط كل عميل ذكاء اصطناعي.

#### الميزة 04: GitHub Enterprise

لم تعد المزامنة مع GitHub مقتصرة على github.com. اضبط `GITHUB_SYNC_URL` على GitHub Enterprise Server الخاص بك، أو على GitHub Enterprise Cloud مع إقامة البيانات (`GHE.com`)، وستُشتق منه نقاط نهاية REST و GraphQL. وإذا كان مثيلك يعمل بطريقة غير معتادة، فتجاوزها باستخدام `GITHUB_SYNC_API_URL` و `GITHUB_SYNC_GRAPHQL_URL`. اتركها دون ضبط ليبقى كل شيء على github.com.

راجع [المزامنة مع GitHub](/ar/on-premises/configuration/overleaf-toolkit/github-synchronisation#github-enterprise  "mention") للتفاصيل.

#### الميزة 05: التعرّف على الرموز المكتوبة بخط اليد

تعرف شكل الرمز، لكنك لا تعرف اسمه. هل هو `\varsigma` أم `\zeta`؟ `\models` أم `\vDash`؟ بدّل لوحة الرموز إلى وضع الرسم، وارسمه بالفأرة أو لوحة اللمس، وستقترح اللوحة أوامر LaTeX المطابقة.

يعمل التعرّف بالكامل في المتصفح، باستخدام نموذج درّبته ayaka-notes، لذا لا يغادر أي شيء ترسمه جهازك. يُخفى مفتاح الرسم في المتصفحات التي لا تدعم `OffscreenCanvas` (مثل Safari 15).

#### إصلاحات الأخطاء

يجلب هذا الإصدار أيضًا قائمة طويلة من الإصلاحات. اكتُشف كثير منها بواسطة نظام اختبار E2E الجديد لدينا، الذي يشغّل الآن مجموعات اختبار لكل وحدة يوميًا، وبواسطة التحقيق الداخلي في المشكلات Horizon: ففي كل مرة نصلح فيها خطأً، نفحص قاعدة الشيفرة بأكملها بحثًا عن أخطاء مماثلة قبل إغلاقه.

* **المصادقة**: يمكن للحسابات المحلية تعيين كلمة مرورها وتغييرها على مثيلات SSO، ولم يعد بإمكان مستخدمي OIDC تغيير بريدهم الإلكتروني. لم تعد عمليات تسجيل الدخول عبر LDAP و SAML و OIDC تفشل عندما تحمل سمة الاسم عدة قيم، ويعمل تسجيل الخروج عبر SAML/OIDC مجددًا.
* **المستخدمون المعلَّقون**: يؤدي تعليق مستخدم الآن إلى إنهاء جلساته وإغلاق محرراته المفتوحة، وتُرفَض رموز Git الخاصة به وعمليات التنزيل عبر MCP.
* **المزامنة مع GitHub**: لا يمكن تصدير المشروع إلا لمالكه، وتبقى التعديلات التي أُجريت أثناء السحب معلّقة، وتُزامَن الملفات الفارغة، ويُتحقق من عمليات الدمج اليدوية على GitHub.
* **Zotero / Mendeley**: تظهر لك رسالة لإعادة الربط عندما تتوقف بيانات اعتمادك عن العمل، وتُعاد فهرسة المراجع بعد الاستيراد.
* **الخدمات الخارجية**: تحصل الطلبات إلى Zotero و Mendeley و GitHub و GitLab والبحث على الويب على مهلة اتصال 3 ثوانٍ بدلًا من ثانية واحدة، لذا لم تعد الشبكات الأبطأ تفشل.
* **تتبع التغييرات**: تتضمن بيانات المراجعة المستندات غير المحمّلة والتغييرات غير المحفوظة.
* **لوحة الإدارة**: تعمل استعادة المشاريع المحذوفة وتغيير المالكين وتعديل المستخدمين بشكل صحيح، ولم يعد فشل البريد الإلكتروني يعطّل إنشاء الحسابات أو حذفها.
* **معرض القوالب**: يُرجع الفرز غير الصالح الرمز 400 بدلًا من 500، ويطلب نشر مشروع بدون ملف رئيسي تحديد ملف رئيسي.

راجع [ملاحظات إصدار 6.3.1](/ar/on-premises/release-notes/release-notes-6.x.x#ayakaleaf-pro-6.3.1  "mention") للاطلاع على القائمة الكاملة.

#### الترقية

* من 6.3.0: لا حاجة إلى ترحيل. اسحب الصورة الجديدة وأعد التشغيل.
* من 6.2.x أو أقدم مع استخدام Zotero أو Mendeley: شغّل أولًا [ترحيل Zotero / Mendeley](/ar/on-premises/release-notes/release-notes-6.x.x#ayakaleaf-pro-6.3.0  "mention") الوارد في 6.3.0.
* المزامنة مع Dropbox والمزامنة مع GitLab معطّلتان افتراضيًا. لا تحتاج المزامنة مع GitLab إلا إلى متغيرات بيئة جديدة. أما المزامنة مع Dropbox فتحتاج أيضًا إلى إنشاء فهارس MongoDB الخاصة بها مرة واحدة، قبل أن يربط المستخدمون حساباتهم: راجع [إنشاء فهارس قاعدة البيانات](/ar/on-premises/configuration/overleaf-toolkit/dropbox-synchronisation#create-the-database-indexes  "mention").
