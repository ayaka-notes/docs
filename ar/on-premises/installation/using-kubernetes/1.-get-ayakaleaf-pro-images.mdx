يشغّل Kubernetes الصور نفسها التي يشغّلها Toolkit. لا توجد صورة منفصلة خاصة بـ Kubernetes.

| الصورة                                                | تُستخدم بواسطة                                                                 |
| ---------------------------------------------------- | ----------------------------------------------------------------------- |
| `ghcr.io/ayaka-notes/overleaf-pro:6.3.2`             | الـ Deployment ‏`overleaf`                                               |
| `ghcr.io/ayaka-notes/overleaf-pro/git-bridge:6.3.2`  | [تكامل Git](/ar/on-premises/configuration/kubernetes/integrations/git-integration) (اختياري)، بالوسم نفسه المذكور أعلاه |
| `ghcr.io/ayaka-notes/texlive-*`                      | عمليات الترجمة، وتُسحب إلى Docker على العقد في [الخطوة 0](/ar/on-premises/installation/using-kubernetes/0.-prepare-the-nodes) |

الصور عامة على [ghcr.io](https://github.com/ayaka-notes/ayakaleaf-pro/pkgs/container/overleaf-pro/) لمعماريتي amd64 وarm64، لذا يستطيع kubelet سحبها دون بيانات اعتماد.

<Warning>

استخدم دائمًا وسم إصدار، مثل `6.3.2`، وليس `latest`. تُجري الترقيات عمليات ترحيل لقاعدة البيانات ويجب أن تتبع [الترقية على Kubernetes](/ar/on-premises/maintenance/upgrading-on-kubernetes)؛ أما الوسم المتغيّر فسيؤدي إلى ترقية الـ pod كلما أُعيدت جدولته.

</Warning>

### أسئلة وأجوبة

<Accordion title="لا تستطيع العقد لدينا الوصول إلى ghcr.io. ماذا نفعل؟">

<strong>الإجابة:</strong> انسخ الصور إلى سجلّ صور (registry) يمكن للعقد الوصول إليه واستخدم ذلك الاسم في ملفات manifest، على سبيل المثال:

```bash
docker pull ghcr.io/ayaka-notes/overleaf-pro:6.3.2
docker tag ghcr.io/ayaka-notes/overleaf-pro:6.3.2 registry.example.com/ayakaleaf/overleaf-pro:6.3.2
docker push registry.example.com/ayakaleaf/overleaf-pro:6.3.2
```

بالنسبة إلى سجلّ صور دون TLS، يحتاج containerd إلى الملف `/etc/containerd/certs.d/<registry>/hosts.toml` مع `server = "http://<registry>"` على كل عقدة، وإلى ضبط `config_path` كما في [الخطوة 0](/ar/on-premises/installation/using-kubernetes/0.-prepare-the-nodes). أما Docker نفسه فلا يدفع عبر HTTP العادي إلا إلى `localhost`، لذا ادفع عبر `localhost:<port>` على مضيف سجلّ الصور أو أضفه إلى `insecure-registries`.

</Accordion>
