### إنشاء أول حساب مسؤول لديك

افتح `OVERLEAF_SITE_URL` متبوعًا بـ `/launchpad`، على سبيل المثال `http://192.0.2.10:30080/launchpad`، وسجّل حساب المسؤول كما في [مهام ما بعد التثبيت في Toolkit](/ar/on-premises/installation/using-the-toolkit/6.-post-installation-tasks). ثم أنشئ مشروعًا نموذجيًا وترجمه.

يمكنك أيضًا إنشاء المستخدمين من سطر الأوامر:

```bash
kubectl -n overleaf exec deploy/overleaf -- bash -c \
  'cd /overleaf/services/web && node modules/server-ce-scripts/scripts/create-user.mjs --admin --email=admin@example.com'
```

يطبع هذا الأمر رابطًا لتعيين كلمة المرور.

### التحقق من أن عمليات الترجمة معزولة

ترجم مشروعًا، ثم افحص العقدة التي تشغّل الـ pod:

```bash
kubectl -n overleaf get pod -l app=overleaf -o wide   # NODE column
# on that node:
sudo docker ps -a --filter ancestor=ghcr.io/ayaka-notes/texlive-full:2026.1
ls -ln /srv/overleaf/compiles                          # owned by uid 33 (www-data)
```

تظهر كل عملية ترجمة على هيئة حاوية قصيرة العمر باسم `project-<project id>-<user id>-...`.

### السجلات وواجهة الأوامر (shell)

| Toolkit          | Kubernetes                                                               |
| ---------------- | ------------------------------------------------------------------------ |
| `bin/logs web`   | `kubectl -n overleaf exec deploy/overleaf -- tail -f /var/log/overleaf/web.log` |
| `bin/shell`      | `kubectl -n overleaf exec -it deploy/overleaf -- bash`                    |
| `bin/up`         | `kubectl apply -f .` ثم `kubectl -n overleaf rollout restart deployment/overleaf` |

تكتب الحاوية ملف سجل واحدًا لكل خدمة في `/var/log/overleaf/` ‏(`web.log`، `clsi.log`، `real-time.log`، `document-updater.log`، ...)؛ أما `kubectl logs` فيعرض مخرجات بدء التشغيل.

### أسئلة وأجوبة

<Accordion title="تفشل عملية الترجمة أو لا تنتهي أبدًا.">

<strong>الإجابة:</strong> تحقّق، على العقدة التي تشغّل الـ pod، من أن Docker قيد التشغيل ويحتوي على الصورة المحدّدة في `TEX_LIVE_DOCKER_IMAGE`، ومن أن `SANDBOXED_COMPILES_HOST_DIR_*` تطابق مسارات `hostPath`. ويذكر الملف `/var/log/overleaf/clsi.log` داخل الـ pod الخطوة التي تفشل.

</Accordion>

<Accordion title="يُسجَّل خروج المستخدمين بعد كل إعادة تشغيل للـ pod.">

<strong>الإجابة:</strong> المتغيّر `OVERLEAF_SESSION_SECRET` مفقود من الـ Secret المسمّى `overleaf-secrets`، راجع [الخطوة 2](/ar/on-premises/installation/using-kubernetes/2.-create-the-namespace-and-secrets).

</Accordion>
