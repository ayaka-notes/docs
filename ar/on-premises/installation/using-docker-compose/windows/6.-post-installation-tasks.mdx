### أنشئ حساب المسؤول وأول مشروع {#create-the-administrator-and-a-first-project}

افتح [http://localhost:8080/launchpad](http://localhost:8080/launchpad) في **متصفح Windows**، وأنشئ أول حساب مسؤول وسجّل الدخول. ثم اتبع [6. مهام ما بعد التثبيت](/ar/on-premises/installation/using-docker-compose/linux/6.-post-installation-tasks) ضمن دليل Linux، مع استخدام المنفذ `8080` في عناوين URL الواردة في أمثلته.

### تحقّق من الترجمة {#verify-compilation}

إن عمل صفحة تسجيل الدخول لا يثبت أن حاويات المترجم المنفصلة تستطيع الوصول إلى مجلد بيانات WSL. أنشئ مشروعًا فارغًا وترجم ملف `main.tex` هذا باستخدام **pdfLaTeX**:

```latex
\documentclass{article}
\begin{document}
Ayakaleaf Pro on Windows WSL 2.
\end{document}
```

يجب أن تعرض معاينة PDF النص. بالنسبة إلى الصورة الأساسية، اختر **TeX Live 2026 Basic** في إعدادات المشروع إذا لزم الأمر.

اختر **XeLaTeX** واختبر:

```latex
\documentclass{article}
\usepackage{fontspec}
\begin{document}
Ayakaleaf WSL XeLaTeX sandbox.
\end{document}
```

يعمل كلا المثالين مع الصورة الأساسية. للمستندات الصينية، استخدم صورة تحتوي على `ctex` والخطوط المطلوبة، مثل الصورة الكاملة، قبل اختبار ما يلي باستخدام **XeLaTeX**. فالصورة الأساسية لا تتضمنها:

```latex
\documentclass{ctexart}
\begin{document}
你好，Ayakaleaf Pro。
\end{document}
```

لتأكيد استخدام البيئة المعزولة، شغّل في **Ubuntu** أثناء الترجمة:

```bash
docker ps -a --filter ancestor=ghcr.io/ayaka-notes/texlive-basic:2026.1
bin/logs -f clsi
```

استخدم اسم الصورة التي اخترتها في المرشّح. قد تنتهي عمليات الترجمة القصيرة قبل تشغيل `docker ps`؛ ويعرض `-a` أيضًا الحاويات المتوقفة حتى تنظيفها. يجب أن تستخدم حاوية المترجم تلك الصورة وربط تركيب `/compile` من مجلد بيانات WSL الخاص بـ Toolkit. لا تُغني سجلات التطبيق وحدها عن التحقق من ملف PDF.

### تحقّق من استمرارية البيانات {#verify-persistence}

في **Ubuntu**، من مجلد Toolkit:

```bash
bin/stop
bin/start
```

انتظر التطبيق، وأعد فتح المشروع من Windows وترجمه مجددًا. يجب أن يبقى حسابك والمصدر وملفات المشروع موجودة. توجد البيانات الحية افتراضيًا في `~/ayakaleaf-toolkit/data/` داخل Ubuntu. احتفظ بكل من `config/` و`data/`؛ فإلغاء تثبيت توزيعة Ubuntu أو إلغاء تسجيلها قد يحذفهما.

### إبقاء النسخة متاحة {#keep-the-instance-available}

لإبقاء النسخة قيد التشغيل ثلاثة أجزاء: أن يبقى Windows مستيقظًا، وأن يعمل Docker Desktop، وأن تُعاد تشغيل الحاويات مع المحرك.

في **Settings → General** الخاصة بـ Docker Desktop، فعّل **Start Docker Desktop when you sign in to your computer**، راجع [إعدادات Docker Desktop](https://docs.docker.com/desktop/settings-and-maintenance/settings/). يشغّل هذا Docker بعد تسجيل الدخول، لا قبله. بعد إعادة تشغيل Windows، سجّل الدخول، وانتظر حتى ينتهي Docker Desktop من بدء التشغيل، وافتح Ubuntu وتحقّق من `docker ps` ومن الموقع.

إن **Resource Saver** في Docker Desktop منفصل عن سكون Windows. فهو لا يُفعَّل عادةً إلا عندما لا تكون هناك حاويات قيد التشغيل؛ والتطبيق وMongoDB وRedis العاملة تمنع حالة الخمول هذه. على WSL 2 يوقف محرك Docker مؤقتًا بدلًا من إيقاف آلة WSL الافتراضية المشتركة. لا تستخدم **Pause** يدويًا في Docker Desktop أثناء خدمة المستخدمين. ولا تحتاج إلى تعطيل Resource Saver لمجرد إبقاء هذه الحزمة قيد التشغيل؛ راجع [وثائق Resource Saver من Docker](https://docs.docker.com/desktop/use-desktop/resource-saver/).

تستخدم خدمات Toolkit السياسة `restart: always`. تحقّق من الإعداد الفعلي في **Ubuntu**:

```bash
docker inspect sharelatex mongo redis --format '{{.Name}} restart={{.HostConfig.RestartPolicy.Name}}'
```

يجب أن تُبلغ كل خدمة عن `always`. بمجرد تشغيل Docker، يمكنه إعادة تشغيل تلك الحاويات الموجودة دون `bin/up` جديد. تبقى الحاوية التي أُوقفت يدويًا متوقفة حتى تشغّلها أو تعيد تشغيل المحرك؛ ومع `always` يمكن لإعادة تشغيل المحرك أن تشغّلها مجددًا. راجع [سلوك سياسة إعادة التشغيل في Docker](https://docs.docker.com/engine/containers/start-containers-automatically/).

| الإجراء | التأثير على Ayakaleaf |
| --- | --- |
| إغلاق طرفية Ubuntu بعد `bin/up -d` | تعمل الحاويات منفصلة؛ والطرفية ليست المشرفة عليها. أبقِ Docker Desktop وبيئة WSL متاحين |
| إغلاق نافذة Docker Dashboard | يمكن إغلاق النافذة بينما يستمر Docker Desktop في علبة النظام |
| اختيار **Quit Docker Desktop** | يوقف المحرك ويجعل الموقع غير متاح؛ افتح Docker Desktop مجددًا للاستعادة |
| تشغيل `wsl --shutdown` | يوقف جميع توزيعات WSL ويقاطع الواجهة الخلفية WSL لـ Docker؛ أعد تشغيل Docker Desktop وأعد فتح Ubuntu |
| سكون Windows أو إسباته أو إيقاف تشغيله | تصبح الخدمة غير متاحة؛ ولا يغيّر إبقاء الشاشة فقط مضاءة أو مطفأة شيئًا من ذلك |
| تشغيل `bin/stop` | يوقف النسخة مع الاحتفاظ ببياناتها؛ استخدم `bin/start` للاستئناف |

للاستخدام طويل الأمد على التيار الكهربائي، افتح في Windows 11 **Settings → System → Power & battery → Screen, sleep & hibernate timeouts** (تعرض بعض الإصدارات **Power** أو **Screen and sleep**). اضبط مهلة السكون عند التوصيل على **Never** وعطّل الإسبات التلقائي إذا كان مضبوطًا. يمكن أن تنطفئ الشاشة مع ذلك. إجراء غطاء الحاسوب المحمول إعداد منفصل؛ فإغلاق الغطاء قد يضعه في وضع السكون حتى مع ضبط مهلة السكون عند الخمول على Never. راجع [إعدادات الطاقة في Windows](https://support.microsoft.com/en-us/windows/experience/power-battery/power-settings-in-windows-11).

لا تشغّل `wsl --shutdown` كتنظيف روتيني أثناء استخدام الموقع. إذا تطلّبه تغيير في إعدادات WSL، فأوقف النسخة أولًا وخطّط لانقطاع. يمكن لـ Windows تشغيل النسخة باستمرار مع هذه الإعدادات. لخدمة مشتركة يجب أن تصمد أمام تسجيلات الخروج وعمليات إعادة التشغيل غير المراقبة، نوصي بـ[دليل Linux](/ar/on-premises/installation/using-docker-compose/linux).

### تحقّق من الاستعادة بعد إعادة تشغيل Docker Desktop {#check-recovery-after-restarting-docker-desktop}

بعد حفظ العمل والسماح لعمليات الترجمة الجارية بالانتهاء، اختر **Restart Docker Desktop** من قائمة استكشاف الأخطاء وإصلاحها في Docker Desktop. انتظر المحرك، ثم تحقّق في **Ubuntu**:

```bash
docker ps
curl -I http://localhost:8080/launchpad
```

افتح المشروع الموجود في Windows وترجمه مجددًا. تأكّد من أن الحساب والمصدر ما زالا موجودين.

إذا أوقفت النسخة عمدًا باستخدام `bin/stop`، فاستخدم `bin/start`. إذا كان Docker يعمل لكن إحدى الخدمات تفشل، فاقرأ سجلاتها بدلًا من إعادة إنشاء الإعدادات. ما زال بإمكان Windows Update وتحديثات Docker وانقطاع الكهرباء مقاطعة تثبيت يعمل على مدار 24 ساعة؛ احتفظ بنسخ احتياطية وتحقّق من الاستعادة بعد الصيانة المخطط لها.

### الاستخدام اليومي {#daily-use}

شغّل Docker Desktop في Windows. افتح **Ubuntu**:

```bash
cd "$HOME/ayakaleaf-toolkit"
```

| المهمة | الأمر |
| --- | --- |
| تشغيل الحاويات الموجودة | `bin/start` |
| إيقاف الحاويات مع الاحتفاظ بالبيانات | `bin/stop` |
| تطبيق تغييرات الإعدادات | `bin/up -d` |
| التحقق من الحالة | `bin/docker-compose ps` |
| قراءة سجلات بدء التشغيل | `bin/docker-compose logs --tail=100 sharelatex` |
| قراءة سجلات MongoDB | `bin/docker-compose logs --tail=100 mongo` |
| قراءة سجلات المترجم | `bin/logs -f clsi` |

لا يطبّق `bin/start` تعديلات الإعدادات: استخدم `bin/up -d` بعد تغيير `config/`. اتبع [البيانات والنسخ الاحتياطية](/ar/on-premises/maintenance/data-and-backups) قبل ترقية توزيعة WSL أو نقلها أو إزالتها. إن نسخ ملفات MongoDB الحية أثناء كتابة قاعدة البيانات لا يُعدّ نسخة احتياطية متسقة.

أبقِ على `127.0.0.1` للاستخدام المحلي. تتطلب خدمة أجهزة كمبيوتر أخرى أيضًا ضبطًا مقصودًا لعنوان الاستماع وعنوان URL للموقع وجدار حماية Windows/إعدادات الشبكة وHTTPS؛ فتغيير `OVERLEAF_SITE_URL` وحده لا ينشر منفذًا.

إذا لم يعمل شيء ما، فراجع [استكشاف الأخطاء وإصلاحها](/ar/on-premises/installation/using-docker-compose/windows/troubleshooting).
