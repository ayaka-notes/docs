يستخدم Ayakaleaf Pro حاويات Linux. على Windows، ثبّت Docker Desktop مع الواجهة الخلفية WSL 2 وشغّل سكربتات Toolkit في Ubuntu.

يوفّر WSL 2 نواة Linux. ويدير Docker Desktop محرك Docker في بيئته الخاصة `docker-desktop`؛ ويتيح تفعيل **WSL Integration** لـ Docker CLI في Ubuntu التواصل مع ذلك المحرك. ثم يشغّل Toolkit التطبيق وMongoDB وRedis كحاويات. ومع تفعيل Sandboxed Compiles، يستخدم التطبيق Docker socket الخاص بالمحرك لتشغيل حاوية TeX Live منفصلة لكل عملية ترجمة. لا تحتاج إلى تثبيت MongoDB أو Redis أو TeX Live على Windows.

<Steps>
<Step title="ثبّت WSL 2 وUbuntu">
افتح **PowerShell كمسؤول** في Windows وشغّل:

```powershell
wsl --install -d Ubuntu
```

أعد تشغيل Windows إذا طُلب منك ذلك. افتح **Ubuntu** من قائمة Start وأنشئ اسم مستخدم وكلمة مرور لـ Linux. هذا هو الحساب المستخدم مع `sudo` داخل Ubuntu؛ وهو منفصل عن تسجيل دخولك إلى Windows.

بالعودة إلى **PowerShell**، حدّث WSL وتحقّق من التوزيعة:

```powershell
wsl --update
wsl --version
wsl --list --verbose
```

يجب أن يعرض صف Ubuntu القيمة **VERSION 2**. إذا عرض 1، فاستخدم اسم التوزيعة الدقيق من القائمة:

```powershell
wsl --set-version Ubuntu 2
```

يتطلب Docker إصدار WSL **2.1.5 أو أحدث**؛ إصدار برنامج WSL من `wsl --version` وعمود **VERSION 2** الخاص بالتوزيعة عمليتا تحقق مختلفتان. راجع [استكشاف أخطاء التثبيت وإصلاحها](/ar/on-premises/installation/using-docker-compose/windows/troubleshooting#wsl-or-docker-reports-that-virtualization-is-unavailable) و[تعليمات التثبيت من Microsoft](https://learn.microsoft.com/en-us/windows/wsl/install) إذا فشل التثبيت، وفعّل المحاكاة الافتراضية للعتاد في BIOS/UEFI إذا أبلغ WSL بأنها غير متاحة.
</Step>

<Step title="ثبّت Docker Desktop وشغّله">
نزّل [Docker Desktop for Windows](https://docs.docker.com/desktop/setup/install/windows-install/) المناسب لمعالجك وشغّل المثبّت. استخدم الواجهة الخلفية **WSL 2** إذا عُرضت. افتح **Docker Desktop** من قائمة Start في Windows وانتظر حتى يبدأ المحرك.

في **Settings → General** الخاصة بـ Docker Desktop، فعّل **Use WSL 2 based engine** إذا كان الخيار ظاهرًا. ضمن **Settings → Resources → WSL Integration**، فعّل التكامل مع **Ubuntu**، ثم اختر **Apply** أو **Apply & restart**. إذا لم تكن Ubuntu توزيعتك الافتراضية، ففعّل المفتاح الخاص بها صراحةً.

إذا كان WSL Integration غير موجود، فتحقّق من أن Docker Desktop يستخدم **Linux containers**. راجع [دليل الواجهة الخلفية WSL 2 من Docker](https://docs.docker.com/desktop/features/wsl/).

استخدم تكامل Docker Desktop في هذا الدليل. إن تثبيت Docker Engine ثانٍ باستخدام `apt install docker.io` أو تشغيل `dockerd` داخل Ubuntu ينشئ إعدادًا منفصلًا وقد يسبب تعارضات. إذا كنت تستخدم بالفعل Engine في Ubuntu، فاتبع إرشادات الترحيل من Docker قبل التبديل؛ واحتفظ ببيانات التطبيق والنسخ الاحتياطية الموجودة.
</Step>

<Step title="تحقّق من Docker من Ubuntu">
افتح طرفية **Ubuntu**. شغّل هذه الأوامر هناك، دون `sudo`:

```bash
docker version
docker compose version
docker ps
```

يجب أن يعرض `docker version` كلًا من **Client** و**Server**. القائمة الفارغة للحاويات أمر طبيعي في تثبيت جديد. لا يثبت `docker --version` وحده أن المحرك قيد التشغيل.

إذا كان `docker` غير متاح أو تعذّر عليه الاتصال، فأعد فتح Ubuntu بعد تطبيق WSL Integration وتحقّق من أن Docker Desktop قيد التشغيل. راجع [استكشاف الأخطاء وإصلاحها](/ar/on-premises/installation/using-docker-compose/windows/troubleshooting#docker-is-unavailable-in-ubuntu).
</Step>

<Step title="تحقّق من الموارد ومن Docker socket">
تحقّق من الموارد المرئية لـ Docker:

```bash
docker info --format 'CPUs={{.NCPU}} Memory={{.MemTotal}} Kernel={{.KernelVersion}}'
df -h "$HOME"
ls -l /var/run/docker.sock
```

لنسخة محلية صغيرة، تُعدّ 4 أنوية معالج و8 GB من الذاكرة متاحة لـ Docker اقتراحًا للبداية، وليست حدًا أدنى مُقاسًا. أبقِ ذاكرة كافية لـ Windows أيضًا. مع الواجهة الخلفية WSL 2، تُدار حدود الموارد عبر [إعدادات WSL](https://learn.microsoft.com/en-us/windows/wsl/wsl-config)، بدلًا من أشرطة تمرير الموارد في Docker Desktop على Mac. التغييرات التي تتطلب `wsl --shutdown` تقاطع جميع توزيعات WSL الجارية وأحمال Docker؛ طبّقها قبل تشغيل النسخة.

أبقِ على `DOCKER_SOCKET_PATH=/var/run/docker.sock` في إعدادات Toolkit. يحتاج التطبيق إلى socket المحرك هذا من أجل Sandboxed Compiles. لا تغيّر أذوناته إلى `777` لإصلاح أخطاء الاتصال؛ بل استعد تكامل Docker Desktop بدلًا من ذلك.
</Step>
</Steps>
