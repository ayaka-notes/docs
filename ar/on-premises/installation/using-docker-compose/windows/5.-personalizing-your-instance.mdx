---
title: 5. تخصيص نسختك
description: اضبط المنفذ وعنوان URL للموقع وصورة TeX Live، وفعّل Sandboxed Compiles وشغّل Ayakaleaf Pro على WSL 2.

---

شغّل الأوامر وحرّر الملفات في **Ubuntu**، من `~/ayakaleaf-toolkit`.

<Steps>
<Step title="إعدادات الحاويات">
عدّل الإدخالات الموجودة في `config/overleaf.rc`:

```bash title="config/overleaf.rc"
PROJECT_NAME=ayakaleaf-wsl
SERVER_PRO=true
OVERLEAF_LISTEN_IP=127.0.0.1
OVERLEAF_PORT=8080
SIBLING_CONTAINERS_ENABLED=true
DOCKER_SOCKET_PATH=/var/run/docker.sock
```

أبقِ على مسارات البيانات الافتراضية وخدمتي MongoDB وRedis المضمّنتين. المنفذ `8080` مخصص لمتصفح Windows المحلي؛ والربط بـ `127.0.0.1` يبقيه محليًا. تستخدم Sandboxed Compiles حاوية Linux منفصلة لكل عملية ترجمة، بدلًا من تشغيل TeX داخل حاوية التطبيق. يتيح Docker socket للتطبيق إنشاء تلك الحاويات، ويوفّر Toolkit مسار المضيف لبيانات الترجمة ضمن `data/overleaf/data/compiles`.
</Step>

<Step title="إعدادات التطبيق">
في `config/variables.env`، اضبط هذه القيم، مع استبدال أي إدخالات فعّالة تحمل الأسماء نفسها:

```dotenv title="config/variables.env"
OVERLEAF_SITE_URL=http://localhost:8080
TEX_LIVE_DOCKER_IMAGE=ghcr.io/ayaka-notes/texlive-full:2026.1
ALL_TEX_LIVE_DOCKER_IMAGES=ghcr.io/ayaka-notes/texlive-full:2026.1
ALL_TEX_LIVE_DOCKER_IMAGE_NAMES="TeX Live 2026"
```

تتضمن الصورة الكاملة الحزم والخطوط اللازمة لطيف واسع من المشاريع. خصّص لها وللتطبيق ما لا يقل عن 40 GB من المساحة الحرة، بالإضافة إلى مساحة لبيانات المشاريع والتحديثات المستقبلية.

لاختبار نشر سريع، استخدم بدلًا من ذلك الصورة **basic** الأصغر. فهي كافية لاختبار المقالة البسيطة في الخطوة 6، لكنها لا تتضمن المجموعة الكاملة من الحزم والخطوط:

```dotenv
TEX_LIVE_DOCKER_IMAGE=ghcr.io/ayaka-notes/texlive-basic:2026.1
ALL_TEX_LIVE_DOCKER_IMAGES=ghcr.io/ayaka-notes/texlive-basic:2026.1
ALL_TEX_LIVE_DOCKER_IMAGE_NAMES="TeX Live 2026 Basic"
```

اختر إحدى هاتين المجموعتين، دون مفاتيح فعّالة مكررة. يتضمن [Dockerfile](https://github.com/ayaka-notes/texlive-full/blob/main/texlive/2026/Dockerfile.basic) الخاص بالصورة الأساسية `latexmk` وXeTeX و`fontspec`، لكنه لا يتضمن `ctex` ولا مجموعة الخطوط الكاملة. إن غياب حزمة LaTeX في الصورة الأساسية لا يدل بحد ذاته على مشكلة في البيئة المعزولة.

ولّد سرًا للجلسة:

```bash
openssl rand -hex 32
```

أضف الناتج بوصفه `OVERLEAF_SESSION_SECRET` في `config/variables.env`. واحتفظ أيضًا بسر رمز الدعوة الذي جرى توليده. لنسخة محلية دون بريد إلكتروني، اترك إعدادات SMTP و`OVERLEAF_EMAIL_FROM_ADDRESS` دون ضبط.
</Step>

<Step title="شغّل نسختك">
```bash
bin/up -d
```

يشغّل Toolkit MongoDB، ويهيّئ مجموعة النسخ المتماثلة (replica set) الخاصة به، وينزّل صورة TeX Live المختارة، ويشغّل Redis والتطبيق. قد يبدو أنه متوقف مؤقتًا أثناء تنزيل صورة كبيرة. لا تشغّل `bin/up` ثانيًا بينما لا يزال الأول يعمل.

في طرفية Ubuntu أخرى، تحقّق:

```bash
cd "$HOME/ayakaleaf-toolkit"
bin/docker-compose ps
bin/docker-compose logs --tail=100 mongo
bin/docker-compose logs --tail=100 -f sharelatex
```

اضغط `Ctrl+C` لإيقاف متابعة السجلات؛ تبقى الحاويات المنفصلة (detached) قيد التشغيل. إذا فشل بدء التشغيل عند MongoDB، فاتبع [يفشل MongoDB في البدء](/ar/on-premises/installation/using-docker-compose/windows/troubleshooting#mongodb-fails-to-start) قبل إعادة المحاولة. لا تحذف مجلد بياناته لإعادة تعيين تثبيت قائم.

تحقّق من المنفذ ومن صفحة التشغيل الأول:

```bash
bin/docker-compose port sharelatex 80
curl -I http://localhost:8080/launchpad
```

يجب أن يكون المنفذ `127.0.0.1:8080`. انتظر اكتمال تهيئة التطبيق إذا فشل طلب HTTP في البداية.
</Step>

<Step title="افتح النسخة من Windows">
في **متصفح Windows**، افتح [http://localhost:8080/launchpad](http://localhost:8080/launchpad). استخدم هذا العنوان في Windows أيضًا، بدلًا من عنوان IP مؤقت لـ WSL.

للتحقق من وصول HTTP في Windows بشكل منفصل عن المتصفح، شغّل في **PowerShell**:

```powershell
curl.exe -I http://localhost:8080/launchpad
```

إذا كان Ubuntu يستطيع الوصول إلى الصفحة لكن Windows لا يستطيع، فراجع [لا يستطيع Windows فتح localhost](/ar/on-premises/installation/using-docker-compose/windows/troubleshooting#windows-cannot-open-localhost).
</Step>
</Steps>
