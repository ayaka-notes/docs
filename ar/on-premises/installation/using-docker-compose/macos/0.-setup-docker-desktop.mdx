يعمل Ayakaleaf Pro على Docker. على جهاز Mac تستخدم Docker Desktop، الذي يشغّل محرك Docker داخل آلة Linux افتراضية.

<Steps>
<Step title="ثبّت Docker Desktop وشغّله">
ثبّت إصدار [Docker Desktop](https://docs.docker.com/desktop/setup/install/mac-install/) المناسب لجهاز Mac (Apple silicon أو Intel)، وافتحه، وانتظر حتى يبدأ المحرك. يمكنك أيضًا تشغيله من Terminal:

```bash
open -a Docker
```
</Step>

<Step title="تحقّق من محرك Docker">
شغّل هذه الأوامر في Terminal:

```bash
docker context show
docker info
docker compose version
```

يجب أن يشير السياق (context) إلى محرك Docker Desktop المحلي، وهو عادةً `desktop-linux`. إذا كان سياق آخر محددًا، فبدّل إلى Docker Desktop قبل المتابعة:

```bash
docker context use desktop-linux
```

يجب أن يطبع `docker info` قسم **Server**. أما `docker --version` وحده فلا يُظهر إلا أن العميل مثبّت.
</Step>

<Step title="تحقّق من الموارد ومشاركة الملفات">
في **Settings** الخاصة بـ Docker Desktop، قارن حدود المعالج والذاكرة والقرص بما ورد في [قبل أن تبدأ](/ar/on-premises/installation/using-docker-compose/macos#before-you-start)، وتحقّق من إعدادات مشاركة الملفات، راجع [إعدادات Docker Desktop](https://docs.docker.com/desktop/settings-and-maintenance/settings/).

يحتفظ هذا الدليل بـ Toolkit ضمن `/Users`، الذي يشاركه Docker Desktop افتراضيًا. إذا استخدمت موقعًا آخر وفشل `bin/up` مع `Mounts denied`، فأضف ذلك المجلد إلى مشاركة الملفات.
</Step>

<Step title="تحقّق من Docker socket من أجل Sandboxed Compiles">
يركّب Toolkit الملف `/var/run/docker.sock` داخل التطبيق، حتى يتمكن من تشغيل حاوية TeX Live منفصلة لكل عملية ترجمة. أبقِ على `DOCKER_SOCKET_PATH=/var/run/docker.sock` في `config/overleaf.rc`.

قد يتصل Docker CLI على macOS عبر `~/.docker/run/docker.sock`. هذه هي نقطة اتصال العميل على جهاز Mac، وليست سببًا لتغيير مصدر التركيب في Toolkit: إذ يحتاج المترجم إلى socket المحرك كما تراه حاويات Linux.

إذا كان `/var/run/docker.sock` غير موجود على جهاز Mac، ففعّل **Allow the default Docker socket to be used** ضمن **Settings → Advanced**، راجع [متطلبات الأذونات في Docker](https://docs.docker.com/desktop/setup/install/mac-permission-requirements/).

<Danger>

لا تشغّل `chmod 777` على الـ socket للالتفاف على الأخطاء. فالوصول إلى Docker socket يعادل صلاحيات root على آلة Docker الافتراضية.

</Danger>
</Step>
</Steps>
