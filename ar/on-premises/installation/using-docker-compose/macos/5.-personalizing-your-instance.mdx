---
title: 5. تخصيص نسختك
description: اضبط المنفذ وعنوان URL للموقع وصورة TeX Live لنسخة محلية على جهاز Mac، وتحقّق من نواة آلة Docker الافتراضية، وشغّل Ayakaleaf Pro.
icon: square-sliders
---

<Steps>
<Step title="إعدادات الحاويات">
عدّل هذه الإدخالات الموجودة في `config/overleaf.rc`:

```bash title="config/overleaf.rc"
PROJECT_NAME=ayakaleaf-macos
SERVER_PRO=true
OVERLEAF_LISTEN_IP=127.0.0.1
OVERLEAF_PORT=8080
SIBLING_CONTAINERS_ENABLED=true
DOCKER_SOCKET_PATH=/var/run/docker.sock
```

أبقِ على مسارات البيانات الافتراضية وخدمتي MongoDB وRedis المضمّنتين. مع `OVERLEAF_LISTEN_IP=127.0.0.1`، لا يمكن فتح النسخة إلا من المتصفحات الموجودة على جهاز Mac هذا.
</Step>

<Step title="إعدادات التطبيق">
في `config/variables.env`، اضبط هذه القيم، مع استبدال أي إدخالات فعّالة تحمل الأسماء نفسها:

```dotenv title="config/variables.env"
OVERLEAF_SITE_URL=http://localhost:8080
TEX_LIVE_DOCKER_IMAGE=ghcr.io/ayaka-notes/texlive-full:2026.1
ALL_TEX_LIVE_DOCKER_IMAGES=ghcr.io/ayaka-notes/texlive-full:2026.1
ALL_TEX_LIVE_DOCKER_IMAGE_NAMES="TeX Live 2026"
```

ولّد سرًا للجلسة:

```bash
openssl rand -hex 32
```

أضف الناتج بوصفه `OVERLEAF_SESSION_SECRET` في `config/variables.env`. من دونه، يؤدي كل `bin/up` يعيد إنشاء الحاوية إلى تسجيل خروج جميع المستخدمين، راجع [متغيرات البيئة](/ar/on-premises/configuration/overleaf-toolkit/environment-variables).

لنسخة محلية دون بريد إلكتروني، اترك إعدادات SMTP و`OVERLEAF_EMAIL_FROM_ADDRESS` دون ضبط. يمكن إضافة Git Bridge والمصادقة الخارجية والتكاملات الأخرى لاحقًا عبر [صفحات الإعداد](/ar/on-premises/configuration/overleaf-toolkit) الخاصة بها.
</Step>

<Step id="check-the-docker-vms-linux-kernel" title="تحقّق من نواة Linux في آلة Docker الافتراضية">
يعمل MongoDB على نواة Linux الخاصة بالآلة الافتراضية لـ Docker Desktop، وليس على macOS. تحقّق من إصدارها قبل أول تشغيل:

```bash
docker info --format '{{.KernelVersion}}'
```

يوثّق MongoDB عدم توافق مع أنوية Linux من **6.19 حتى 7.0.13**، وهو ما يؤثر أيضًا على MongoDB داخل Docker. الإصلاح هو نواة **7.0.14 أو أحدث**، تأتي مع تحديث لـ Docker Desktop، راجع [ملاحظات الإنتاج في MongoDB](https://www.mongodb.com/docs/manual/administration/production-notes/).

إذا كانت آلة Docker الافتراضية تستخدم نواة متأثرة، فأضف ما يلي إلى `config/docker-compose.override.yml`، مدمجًا مع أي `services` موجودة لديك فيه:

```yaml title="config/docker-compose.override.yml"
services:
  mongo:
    environment:
      GLIBC_TUNABLES: glibc.pthread.rseq=1
```

<Warning>

حدّث إلى نواة مُصلَحة عند توفرها. إذا كانت نواتك خارج النطاق المتأثر، فلا حاجة إلى هذا الحل البديل.

</Warning>
</Step>

<Step title="شغّل نسختك">
من مجلد Toolkit، شغّل:

```bash
bin/up -d
```

يهيّئ Toolkit مجموعة النسخ المتماثلة (replica set) في MongoDB، ويسحب صورة TeX Live، ويشغّل التطبيق. يستغرق التنزيل الأول بعض الوقت. لمتابعة التقدم:

```bash
bin/docker-compose ps
bin/docker-compose logs --tail=100 -f sharelatex
```

اضغط `Ctrl+C` لإيقاف متابعة السجلات. تبقى الحاويات قيد التشغيل.

تحقّق من المنفذ المنشور ومن صفحة التشغيل الأول:

```bash
bin/docker-compose port sharelatex 80
curl -I http://localhost:8080/launchpad
```

يجب أن يكون المنفذ `127.0.0.1:8080`.
</Step>
</Steps>

<Info>

لفتح النسخة من أجهزة كمبيوتر أخرى لاحقًا، غيّر عنوان الاستماع وعنوان URL للموقع، واضبط HTTPS، كما هو موضح في [5. تخصيص نسختك](/ar/on-premises/installation/using-docker-compose/linux/5.-personalizing-your-instance) ضمن دليل Linux. عندها يجب أن يبقى جهاز Mac مستيقظًا، راجع [إبقاء النسخة متاحة](/ar/on-premises/installation/using-docker-compose/macos/6.-post-installation-tasks#keep-the-instance-available).

</Info>
