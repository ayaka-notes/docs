### تفشل التهيئة مع invalid command code {#initialization-fails-with-invalid-command-code}

يُبلغ `bin/init` عن `sed: ... invalid command code` عندما يجد BSD sed الخاص بـ macOS. ضع GNU sed في `PATH` كما في [1. تنزيل Toolkit](/ar/on-premises/installation/using-docker-compose/macos/1.-download-the-toolkit) وتحقّق من `sed --version`.

قد تترك تهيئة فاشلة الملفات الثلاثة في `config/` مع قيمة فارغة لـ `OVERLEAF_INVITE_TOKEN_SECRET`. ثم يُبلغ تشغيل `bin/init` مجددًا عن `Config files already exist`. لتثبيت جديد لم يبدأ قط، انقل الملفات الثلاثة إلى مجلد نسخ احتياطي وشغّل `bin/init` مجددًا. أما لنسخة قائمة، فاحتفظ بإعداداتها وأسرارها، ولا تحذف ملفاتها لكي يعمل `bin/init` مجددًا.

### يستمر MongoDB في إعادة التشغيل {#mongodb-keeps-restarting}

اقرأ سجلات MongoDB وإصدار نواة آلة Docker الافتراضية:

```bash
bin/docker-compose logs --tail=100 mongo
docker info --format '{{.KernelVersion}}'
```

إذا ذكر السجل عدم التوافق مع نواة Linux، فاتبع [تحقّق من نواة Linux في آلة Docker الافتراضية](/ar/on-premises/installation/using-docker-compose/macos/5.-personalizing-your-instance#check-the-docker-vms-linux-kernel) وشغّل `bin/up -d` مجددًا. لا يثبت رمز الخروج `137` وحده أن الذاكرة نفدت لدى MongoDB: تحقّق من حالة الحاوية ومن السجلات. لمشكلة أقدم في MongoDB على Docker Desktop، راجع أيضًا [استكشاف الأخطاء وإصلاحها](/ar/on-premises/support/troubleshooting).

### تعذّر الاتصال بـ Docker daemon {#cannot-connect-to-the-docker-daemon}

شغّل Docker Desktop وتحقّق من سياق Docker المحدد، راجع [0. إعداد Docker Desktop](/ar/on-premises/installation/using-docker-compose/macos/0.-setup-docker-desktop). إذا عمل `docker info` لكن عمليات الترجمة لا تستطيع الوصول إلى Docker، فتحقّق من إعدادات الـ socket في `config/overleaf.rc` واقرأ سجلات `clsi`. إن عمل Docker CLI على جهاز Mac لا يثبت أن تركيب الـ socket الخاص بالتطبيق صحيح.

### تفتح الصفحة، لكن عمليات الترجمة تفشل {#the-page-opens-but-compiles-fail}

تحقّق من أن صورة TeX Live موجودة محليًا وتطابق بنية محرك Docker:

```bash
docker image inspect ghcr.io/ayaka-notes/texlive-full:2026.1 \
  --format '{{.Os}}/{{.Architecture}}'
bin/logs -f clsi
```

على Apple silicon، يجب أن تكون الصورة `linux/arm64`. تحقّق من أن `SERVER_PRO` و`SIBLING_CONTAINERS_ENABLED` كلاهما `true`، ثم طبّق التغييرات باستخدام `bin/up -d`. إذا أبلغت السجلات عن مجلد ترجمة مفقود، فتحقّق من مشاركة الملفات في Docker Desktop ومن موقع `OVERLEAF_DATA_PATH`. لا تعطّل Sandboxed Compiles لإخفاء فشل في التركيب.

### Not a directory، أو ربط تركيب (bind mount) مفقود {#not-a-directory-or-a-bind-mount-is-missing}

ربما حُذف ملف على المضيف يركّبه ملف تجاوز (override)، أو ربما أنشأ Docker مجلدًا في المكان الذي يجب أن يكون فيه الملف. تحقّق من مسار المصدر على المضيف، ومما إذا كان التركيب يتوقع ملفًا أم مجلدًا. استعد ملف الإعدادات قبل إعادة إنشاء الحاوية. قد يواجه تثبيت ضمن `/tmp` هذه المشكلة بعد أن يحذف macOS الملفات المؤقتة.

### تعارض المنافذ أو أسماء الحاويات {#port-or-container-name-conflicts}

إذا كان المنفذ `8080` مستخدمًا، فاختر منفذًا آخر في `config/overleaf.rc`، واضبط `OVERLEAF_SITE_URL` ليطابقه، وشغّل `bin/up -d` مجددًا.

يعطي Toolkit حاوياته أسماء ثابتة مثل `sharelatex` و`mongo` و`redis`. لا يكفي تغيير `PROJECT_NAME` وحده لجعل تثبيتين من Toolkit مستقلين. قبل تشغيل نسخة ثانية، تحقّق من `docker ps -a`، واستخدم أسماء حاويات أخرى في ملف تجاوز لـ Compose، ومنفذًا آخر، ومجلدات بيانات منفصلة. لا تحذف حاويات أو بيانات نشر قائم لحل تعارض في الأسماء.

### يتعذّر الوصول إلى النسخة بعد فترة {#the-instance-is-unreachable-after-a-while}

على الأرجح دخل جهاز Mac في وضع السكون، أو أُغلق Docker Desktop. راجع [إبقاء النسخة متاحة](/ar/on-premises/installation/using-docker-compose/macos/6.-post-installation-tasks#keep-the-instance-available).

### يقول `bin/doctor` إن هذا ليس Linux، أو يطلب تسجيل الدخول إلى Quay {#bin/doctor-says-this-is-not-linux-or-asks-for-a-quay-login}

كلا التحذيرين متوقعان على macOS مع الصورة العامة، راجع [2. تعرّف على الـ Toolkit](/ar/on-premises/installation/using-docker-compose/macos/2.-familiarize-yourself-with-the-toolkit). تحقّق بدلًا من ذلك من سحب الصور وحالة الخدمات ونتائج الترجمة، ولا تتجاهل الأخطاء الأخرى في التقرير.
