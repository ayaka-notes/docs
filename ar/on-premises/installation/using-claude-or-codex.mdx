استخدم Claude Code أو Codex لتخطيط نشر Ayakaleaf Pro وتنفيذه. يمكن للوكيل البحث في هذه الوثائق عبر MCP أثناء عمله.

يساعد الوكيل في عملية النشر، بينما تظل أنت مسؤولًا عن مراجعة الأوامر وحماية بيانات الاعتماد.

### قبل أن تبدأ

جهّز خادم Linux مدعومًا مع إمكانية الوصول عبر SSH. راجع [المتطلبات](/ar/on-premises/getting-started/requirements  "mention") قبل المتابعة.

<Warning>

لا تلصق كلمات المرور أو المفاتيح الخاصة أو الرموز المميزة (tokens) أو مفاتيح الترخيص في مطالبات الوكيل. راجع كل أمر قبل تشغيله، ولا سيما الأوامر التي تعدّل الملفات أو الشبكات أو الحاويات.

</Warning>

### ربط الوثائق

أضف نقطة نهاية MCP الخاصة بالوثائق إلى وكيلك المحلي.

<Tabs>
<Tab title="Claude Code">

```bash wrap
claude mcp add ayakaleaf-pro --scope user --transport http https://ayakaleaf-pro.ayaka.space/~gitbook/mcp
```

</Tab>

<Tab title="Codex">

```bash wrap
codex mcp add ayakaleaf-pro --url https://ayakaleaf-pro.ayaka.space/~gitbook/mcp
```

</Tab>
</Tabs>

ابدأ جلسة جديدة بعد إضافة الخادم. اطلب من الوكيل التأكد من قدرته على البحث في وثائق Ayakaleaf Pro.

### نشر Ayakaleaf Pro

افتح طرفية على خادم النشر الخاص بك، وشغّل Claude Code أو Codex هناك. ثم أرسل هذه المطالبة:

```text wrap
Use the Ayakaleaf Pro documentation MCP server to guide this deployment.
First, inspect the requirements and installation guides.
Ask me for missing deployment details before making changes.
Use the Ayakaleaf Toolkit unless the documentation requires another approach.
Before configuring the instance, summarize relevant optional features.
Ask which features and integrations I want to enable.
Include TLS, sandboxed compiles, Git integration, external MongoDB or Redis,
SSO (OIDC, SAML, or LDAP), GitHub Synchronisation, Zotero, S3 storage,
email delivery, branding, and localization when relevant.
Explain each selected option's prerequisites, security impact, and configuration steps.
Keep unselected optional features disabled.
Show each command before running it.
Do not expose, store, or request secrets in chat.
After deployment, verify that the service is healthy and summarize the changes.
```

يجب أن يرشدك الوكيل خلال إعداد Docker، وإعداد Toolkit، وجلب الصورة، وبدء التشغيل. اتبع دليل [using-the-toolkit](/ar/on-premises/installation/using-the-toolkit  "mention") لسير العمل المعتمد.

### اختيار الميزات الاختيارية

اطلب من الوكيل ألا يوصي إلا بالميزات التي تناسب بيئتك. تشمل الخيارات المعتادة:

* <strong>الوصول والأمان:</strong> TLS، وsandboxed compiles، وتسجيل الدخول الموحد SSO عبر OIDC أو SAML أو LDAP.
* <strong>الخدمات الخارجية:</strong> MongoDB، وRedis، وتخزين S3، وإرسال البريد الإلكتروني.
* <strong>التعاون:</strong> التكامل مع Git، وGitHub Synchronisation، وZotero.

يجب أن يشرح الوكيل التبعيات قبل تعديل الإعدادات. راجع [toolkit-settings.md](/ar/on-premises/configuration/overleaf-toolkit/toolkit-settings  "mention") و[المصادقة](/ar/on-premises/configuration/overleaf-toolkit/authentication  "mention") قبل تفعيل التكاملات في بيئة الإنتاج.

### التحقق من النشر

بعد أن يُكمل الوكيل الخطوات:

1. تأكد من أن كل أمر اكتمل دون أخطاء.
2. افتح عنوان URL الذي أعددته لـ Ayakaleaf Pro في متصفحك.
3. أكمل [6.-post-installation-tasks.md](/ar/on-premises/installation/using-the-toolkit/6.-post-installation-tasks  "mention").

إذا كان لديك تثبيت موجود من Community Edition، فاستخدم دليل [migrate-from-existing.md](/ar/on-premises/installation/migrate-from-existing  "mention") بدلًا من نشر جديد.
