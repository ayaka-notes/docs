يتحقق `bin/podman-setup` من كل ما يحتاجه Ayakaleaf Pro على Podman. بدون خيارات يكتفي بالإبلاغ؛ ومع `--apply` يصلح أيضًا ما يجده.

<Steps>
<Step title="تحقق من المضيف">
```bash title="Check only"
bin/podman-setup
```

على مضيف جديد تفشل معظم الفحوص، على سبيل المثال:

```text
====== Packages ======
[✗] podman not installed
[✗] podman-docker not installed
...
====== Summary ======
[✓] 7 passed  [!] 13 warnings  [✗] 4 failures
```
</Step>

<Step title="طبّق الإصلاحات">
```bash title="Check and fix"
bin/podman-setup --apply
```

شغّله في طرفية: يطلب كلمة مرور `sudo` للخطوات على مستوى النظام. كما ينزّل صورة Ayakaleaf Pro لاستخراج ملف seccomp منها، وهذا يستغرق بضع دقائق في المرة الأولى. في النهاية يتحقق من المضيف مرة أخرى:

```text
====== Summary ======
[✓] 23 passed  [!] 2 warnings  [✗] 0 failures
[!] Warnings remaining:
[!] not logged in to quay.io
[!] container → socket skipped (sharelatex not running)
```

كلا التحذيرين متوقع في هذه المرحلة:

* ‏`not logged in to quay.io`: يأتي هذا الفحص من Toolkit الرسمي، حيث توجد صورة Server Pro في سجل خاص. صور Ayakaleaf Pro عامة على `ghcr.io` ولا تحتاج إلى تسجيل دخول، لذا تجاهله. يبقى ظاهرًا بعد التثبيت أيضًا.
* ‏`container → socket skipped (sharelatex not running)`: يحتاج هذا الاختبار إلى نسخة قيد التشغيل. ستشغّل السكربت مرة أخرى في [3. بدء Ayakaleaf Pro](/ar/on-premises/installation/using-podman/3.-start-ayakaleaf-pro).

ينتهي السكربت بالرمز `0` عند نجاح كل الفحوص، و`1` عند وجود تحذيرات، و`2` عند وجود إخفاقات. بسبب تحذير quay.io، توقّع `1`.
</Step>
</Steps>

### ما الذي يغيّره السكربت {#what-the-script-changes}

مع `--apply`، قد يغيّر السكربت ما يلي.

على مستوى النظام، باستخدام `sudo`:

* يثبّت `podman` و`podman-docker` و`git` و`curl` و`checkpolicy` و`policycoreutils` باستخدام `dnf`.
* يفعّل lingering لمستخدمك باستخدام `loginctl`، حتى تستمر حاوياتك في العمل بعد تسجيل خروجك.
* ينشئ `/etc/containers/nodocker`، الذي يُسكت رسالة "Emulate Docker CLI using podman".
* يحمّل وحدة سياسة SELinux ‏`podman_socket_clsi`، عندما يكون `SELINUX_MODE=managed`.

لمستخدمك:

* يفعّل خدمة المستخدم `podman.socket`، وهي واجهة API المتوافقة مع Docker التي يستخدمها Ayakaleaf Pro لبدء الترجمة.
* يثبّت Docker Compose v2 من GitHub في `~/.local/bin/docker-compose`، وينشئ رابطًا له في `~/.docker/cli-plugins/`.
* يجعل Podman يستخدم Compose هذا في `~/.config/containers/containers.conf`.
* يضيف الأسماء المستعارة `mongo` و`redis` في `~/.config/containers/registries.conf.d/overleaf-toolkit.conf`، حتى يعرف Podman من أين يسحب أسماء الصور القصيرة هذه.

في Toolkit:

* يضبط `DOCKER_SOCKET_PATH` و`DOCKER_HOST` في `config/overleaf.rc` على `/run/user/<uid>/podman/podman.sock`.
* يستخرج ملف seccomp للترجمة من صورة Ayakaleaf Pro إلى `config/seccomp/<version>/clsi-profile.json`، ويضبط `SECCOMP_PROFILE` في `config/variables.env`. على عكس Docker، يحتاج Podman إلى هذا الملف كملف على المضيف.
* يبني وحدة سياسة SELinux في `config/selinux/`.
* يضبط مالكي مجلدات البيانات في `data/` باستخدام `podman unshare chown`، بمجرد وجودها.

<Info>

كل تغيير يقابله فحص. إذا غيّرت شيئًا يدويًا، مثلًا في `config/overleaf.rc`، فشغّل `bin/podman-setup` مرة أخرى للتحقق منه.

</Info>
