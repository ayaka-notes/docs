تأتي RHEL ونسخها المعاد بناؤها (Rocky Linux وAlmaLinux) مع Podman بدلًا من Docker، وبعض المؤسسات لا تسمح بتشغيل Docker على خوادمها. يمكن لـ Toolkit تشغيل Ayakaleaf Pro على **Podman بدون صلاحيات root (rootless)** بدلًا من ذلك: تعمل الحاويات تحت مستخدم عادي، وتظل الترجمة تجري في حاويات TeX Live معزولة، ويبقى SELinux في وضع enforcing. يتحقق السكربت `bin/podman-setup` من المضيف ويصلح ما يستطيع إصلاحه.

في نهاية هذا القسم ستحصل على النسخة نفسها التي تحصل عليها مع [استخدام Docker Compose](/ar/on-premises/installation/using-docker-compose): ‏Ayakaleaf Pro مع الترجمة المعزولة وMongoDB وRedis، وتديرها كالمعتاد بالأوامر `bin/up` و`bin/doctor` و`bin/upgrade`.

<Info>

دعم Podman تجريبي. يأتي من Overleaf Toolkit الرسمي، الذي لا يُختبر إلا على RHEL 9 وما بعدها مع Podman بدون root والترجمة المعزولة وSELinux في وضع enforcing. اختبرنا هذه الصفحات على Rocky Linux 9.9 ‏(Podman 5.8، وSELinux في وضع enforcing) مع Ayakaleaf Pro 6.3.4. يظل Docker بيئة تشغيل الحاويات الموصى بها.

</Info>

### ما تحتاج إليه {#what-you-need}

* **‏RHEL أو Rocky Linux أو AlmaLinux أو CentOS Stream 9 وما بعدها**، مع SELinux في وضع enforcing. يتوقف `bin/podman-setup` على أي توزيعة أخرى. على Ubuntu أو Debian، استخدم [استخدام Docker Compose](/ar/on-premises/installation/using-docker-compose/linux).
* **مستخدم غير root لديه صلاحية `sudo`** ويمتلك الحاويات. شغّل كل أوامر هذا القسم بهذا المستخدم؛ يرفض `bin/podman-setup` العمل بصفة `root`.
* **مضيف نظيف**: بدون Docker Engine وبدون تثبيت سابق لـ Toolkit. لا يغطي هذا القسم نقل نسخة قائمة على Docker إلى Podman.

### كيف يختلف عن Docker {#how-it-differs-from-docker}

|                                  | Docker                               | Podman بدون root                                                                          |
| -------------------------------- | ------------------------------------ | ---------------------------------------------------------------------------------------- |
| من يشغّل الحاويات                 | خدمة Docker، بصفة `root`              | مستخدمك                                                                                  |
| المقبس المستخدم لبدء الترجمة      | `/var/run/docker.sock`               | `/run/user/<uid>/podman/podman.sock`                                                     |
| المنافذ                           | أي منفذ، مثل `80` و`443`              | `1024` فما فوق، مثل `8080`                                                                 |
| جدار حماية المضيف (`firewalld`)   | تتجاوزه المنافذ المنشورة              | يُطبَّق: افتح المنفذ باستخدام `firewall-cmd`                                                  |
| البدء بعد إعادة التشغيل           | تعيد خدمة Docker تشغيلها              | خدمة المستخدم `podman-restart`                                                            |
| SELinux                          | لا يضبطه Toolkit                     | وحدة السياسة `podman_socket_clsi` و`SELINUX_MODE=managed` في `config/overleaf.rc`          |
| ملف seccomp للترجمة               | مدمج في الصورة                        | يستخرجه Toolkit إلى `config/seccomp/<version>/` ويضبطه في `SECCOMP_PROFILE`                |

### القيود المعروفة {#known-limitations}

* <strong>تكامل Git.</strong> في Ayakaleaf Pro 6.3.4، يفشل `git clone` على Podman بالرمز `502`: يبحث NGINX داخل الصورة عن حاوية `git-bridge` عبر خادم DNS الخاص بـ Docker ‏(`127.0.0.11`)، وهو غير موجود في Podman. يأتي الإصلاح ([1b911d1092](https://github.com/ayaka-notes/ayakaleaf-pro/commit/1b911d1092c80f7b0ff77c5e3805b40503d49964)) مع الإصدار القادم؛ حتى ذلك الحين، أبقِ `GIT_BRIDGE_ENABLED=false`.
* <strong>عناوين IP للعملاء.</strong> يعيد Podman بدون root توجيه المنفذ المنشور من داخل شبكة الحاوية، لذلك يرى Ayakaleaf Pro كل زائر بعنوان داخلي مثل `10.89.0.15`. تعرض [سجلات التدقيق](/ar/on-premises/user-guide/administrators/user-management#audit-logs) الخاصة بالمستخدم في لوحة الإدارة هذا العنوان بدلًا من عنوان IP الخاص به.
