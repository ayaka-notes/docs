---
title: 3. بدء Ayakaleaf Pro
description: ابدأ Ayakaleaf Pro على Podman، وتحقق منه باستخدام podman-setup و‏bin/doctor، واجعله يبدأ بعد إعادة التشغيل.
icon: circle-play
---

<Steps>
<Step title="ابدأ الحاويات">
```bash title="Start Ayakaleaf Pro"
bin/up -d
```

ينزّل البدء الأول صور MongoDB وRedis وTeX Live، وينشئ مجلدات البيانات في `data/`. ويطبع تحذيرًا بأن دعم Podman تجريبي.

<Info>

قد يطبع البدء الأول أيضًا `MongoNetworkError: connect ECONNREFUSED 127.0.0.1:27017`. يُعدّ Toolkit مجموعة النسخ المتماثلة لـ MongoDB بينما لا يزال MongoDB في طور البدء، ويعيد المحاولة حتى يستجيب. يمكنك تجاهل هذا السطر.

</Info>

بعد دقيقة أو دقيقتين، تحقق من أن الحاويات تعمل:

```bash title="List the containers"
podman ps --format "{{.Names}} {{.Status}}"
```

```text
mongo Up 34 seconds (healthy)
redis Up 20 seconds
sharelatex Up 20 seconds
```
</Step>

<Step title="تحقق من الإعداد مرة أخرى">
الآن بعد أن أصبحت مجلدات البيانات موجودة والحاوية `sharelatex` تعمل، يستطيع `bin/podman-setup` إنهاء فحوصه:

```bash title="Check the setup"
bin/podman-setup
```

يتحقق من مالكي مجلدات البيانات الجديدة ويختبر مقبس Podman من داخل الحاوية `sharelatex`:

```text
====== Socket Connectivity ======
[✓] host → socket OK
[✓] container → socket OK

====== Data Directory Permissions ======
[✓] mongo data dir owned by 999
[✓] redis data dir owned by 999
[✓] overleaf data dir owned by 33
...
====== Summary ======
[✓] 27 passed  [!] 1 warnings  [✗] 0 failures
[!] Warnings:
[!] not logged in to quay.io
```

تعني `container → socket OK` أن Ayakaleaf Pro يستطيع بدء حاويات الترجمة. إذا فشل أحد الفحوص، فشغّل `bin/podman-setup --apply` ثم `bin/up -d`. لا ينطبق تحذير quay.io على Ayakaleaf Pro، راجع [2. تشغيل podman-setup](/ar/on-premises/installation/using-podman/2.-run-podman-setup).
</Step>

<Step title="شغّل doctor">
```bash title="Run the doctor"
bin/doctor
```

على Podman، يعرض التقرير بيئة التشغيل وإعدادات الأمان:

```text
- Container Daemon
    - status: up
    - runtime: podman
    - server version: 5.8.5
    - socket: /run/user/1000/podman/podman.sock
    - DOCKER_HOST: unix:///run/user/1000/podman/podman.sock
    - host → socket: OK
    - container → socket: OK
- Security
    - SELinux: Enforcing
    - SELINUX_MODE: managed
    - SELINUX_LABEL: sharelatex_t
    - SELinux module: loaded (podman_socket_clsi)
    - SELinux rules: present
    - Seccomp profile: present
```

التحذير `Server Pro enabled, but not logged in to quay.io repository` في النهاية هو فحص quay.io نفسه، راجع [الحصول على المساعدة](/ar/on-premises/support/getting-help#q-and-a).
</Step>

<Step title="ابدأ Ayakaleaf Pro بعد إعادة التشغيل">
مع Docker، تعيد خدمة Docker تشغيل الحاويات بعد إعادة تشغيل الخادم. لا توجد خدمة دائمة في Podman بدون root: فعّل خدمة المستخدم التي تبدأ حاوياتك عند إقلاع الخادم:

```bash title="Start the containers at boot"
systemctl --user enable podman-restart.service
```

تبدأ هذه الخدمة كل حاويات مستخدمك التي تكون سياسة إعادة تشغيلها `always`، وهي السياسة التي يضبطها Toolkit لكل حاوياته. يتطلب ذلك lingering، الذي فعّله `bin/podman-setup --apply`. بدون هذه الخدمة، شغّل `bin/up -d` بعد كل إعادة تشغيل.
</Step>

<Step title="افتح المنفذ في جدار الحماية">
افتراضيًا، لا تقبل النسخة الاتصالات إلا من الخادم نفسه، على `http://localhost:8080`. لفتحها من أجهزة أخرى، اضبط `OVERLEAF_LISTEN_IP` في `config/overleaf.rc` و`OVERLEAF_SITE_URL` في `config/variables.env` كما هو موضح في [5. تخصيص نسختك](/ar/on-premises/installation/using-docker-compose/linux/5.-personalizing-your-instance#listen-address-and-port)، ثم شغّل `bin/up -d` مرة أخرى.

على عكس Docker، لا يتجاوز Podman بدون root جدار حماية المضيف. إذا كان `firewalld` يعمل، وهو الوضع الافتراضي على RHEL، فافتح المنفذ:

```bash title="Open port 8080"
sudo firewall-cmd --permanent --add-port=8080/tcp
sudo firewall-cmd --reload
```

على خادم سحابي، اسمح بالمنفذ أيضًا في مجموعة الأمان لدى المزوّد. استخدم HTTPS قبل إتاحة النسخة على الإنترنت، راجع [4. مهام ما بعد التثبيت](/ar/on-premises/installation/using-podman/4.-post-installation-tasks#use-https).
</Step>
</Steps>
