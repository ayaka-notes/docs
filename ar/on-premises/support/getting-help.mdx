### الطبيب (Doctor)

يأتي Overleaf Toolkit مع سكربت `doctor` مفيد للمساعدة في تصحيح الأخطاء. شغّل `bin/doctor` وسيطبع السكربت معلومات حول بيئة الجهاز المضيف، وإعداداتك، والتبعيات التي يحتاجها Toolkit. ويمكن لهذه المخرجات أيضًا أن تساعدنا في تشخيص مشكلات تثبيتات Ayakaleaf Pro الخاصة بك.

<Info>

يمكن لمستخدمي Overleaf Pro [فتح مشكلة (issue) على GitHub](https://github.com/ayaka-notes/overleaf/issues).

من الجيد تضمين مخرجات السكربت `bin/doctor` في رسالتك.

</Info>

### معلومات الجهاز المضيف

يحتوي القسم `Host Information` على معلومات حول الجهاز الذي يشغّل Toolkit (على سبيل المثال، توزيعة Linux وإصدارها).

<Accordion title="مثال على مخرجات معلومات الجهاز المضيف">

```text
- Host Information
    - Linux
    - Output of 'lsb_release -a':
            No LSB modules are available.
            Distributor ID:	Ubuntu
            Description:	Ubuntu 22.04.5 LTS
            Release:	22.04
            Codename:	jammy
```

</Accordion>

### التبعيات

يسرد القسم `Dependencies` الأدوات اللازمة لعمل Toolkit. إذا كانت الأداة موجودة فستُدرج بالحالة `status: present` مع معلومات الإصدار. وإذا كانت مفقودة فستُدرج بالحالة `status: MISSING!` وسيُضاف تحذير في أسفل مخرجات `doctor`.

<Accordion title="مثال على مخرجات التبعيات (موجودة)">

```text
- docker
    - status: present
    - version info: Docker version 28.0.4, build b8034c0
```

</Accordion>

<Accordion title="مثال على مخرجات التبعيات (مفقودة)">

```text
- docker
    - status: MISSING!
```

</Accordion>

إذا كانت أي من التبعيات مفقودة، فمن شبه المؤكد أن Toolkit لن يعمل.

### الإعدادات

يحتوي القسم `Configuration` على معلومات حول الملفات الموجودة في المجلد `config/`. بالنسبة للملف `config/overleaf.rc`، يطبع doctor بعض القيم الأساسية. وستُدرج الملفات المفقودة بالحالة `status: MISSING!` وسيُضاف تحذير في أسفل مخرجات `doctor`.

<Accordion title="مثال على مخرجات الإعدادات">

```text
====== Configuration ======
- config/version
    - status: present
    - version: 6.3.2
- config/overleaf.rc
    - status: present
    - values
        - OVERLEAF_DATA_PATH: /tmp/overleaf
        - SERVER_PRO: false
        - MONGO_ENABLED: false
        - REDIS_ENABLED: true
- config/variables.env
    - status: MISSING!
```

</Accordion>

ملاحظات حول المثال أعلاه:

* قد لا يكون تعيين `OVERLEAF_DATA_PATH` إلى `/tmp/overleaf` موقعًا آمنًا للبيانات المهمة.
* تعني `MONGO_ENABLED: false` أن Toolkit لن يوفّر MongoDB خاصًا به؛ تأكد من أن `MONGO_URL` يشير إلى MongoDB مُدار خارجيًا إذا لزم الأمر.
* الملف `config/variables.env` مفقود في المثال.

### التحذيرات

يلخّص القسم `Warnings` المشكلات التي اكتشفها سكربت doctor. وإذا لم تكن هناك مشكلات، فسيشير هذا القسم إلى ذلك.

<Accordion title="مثال على مخرجات التحذيرات">

```text
====== Warnings ======
- configuration file variables.env not found
- rc file, OVERLEAF_DATA_PATH not set
====== End =======
```

</Accordion>

### أسئلة وأجوبة

<Accordion title="هل تحتاج رسائل quay.io وإعدادات Docker والإعدادات المحلية (locale) لـ Perl الصادرة عن `bin/doctor` إلى إصلاح؟">

<strong>الإجابة:</strong> لا، الرسائل الثلاث كلها للعلم فقط. يطبع `bin/doctor` تقريرًا فحسب، ولا يوقف `bin/up`.

* `logged in to quay.io: false` والتحذير `Server Pro enabled, but not logged in to quay.io repository`: يأتي هذا الفحص من Toolkit الرسمي، حيث تكون صورة Server Pro على سجل quay.io خاص. ومع `SERVER_PRO=true`، يسحب Toolkit الصورة `ghcr.io/ayaka-notes/overleaf-pro`، وهي عامة، لذا لا حاجة إلى تسجيل الدخول. تجاهل هذا التحذير.
* `grep: /root/.docker/config.json: No such file or directory` (أو مجلد منزلي آخر): يبحث فحص quay.io عن `quay.io` في ذلك الملف. لا يكتب Docker هذا الملف إلا عندما تكون لديه إعدادات لحفظها، مثلًا بعد `docker login`، لذا فهو غير موجود على كثير من الخوادم. وهو غير مطلوب.
* `perl: warning: Setting locale failed`: لا يستخدم Toolkit الأمر `perl` إلا هنا، في `bin/doctor`، لطباعة إصداره، ويُصدر Perl تحذيرًا عندما يشير `LANG` أو `LC_ALL` إلى إعداد محلي (locale) غير مثبّت على المضيف. ومع ذلك يُطبع الإصدار. لإخفاء التحذير، اضبط هذه المتغيرات على إعداد محلي مُدرج في ناتج `locale -a`، مثل `C.UTF-8`.

أما التحذيرات مثل `Docker daemon is not running` أو `docker not found` أو `Docker Compose not found` أو وجود ملف مفقود في `config/` فتحتاج إلى إصلاح: إذ لا يمكن لـ Toolkit البدء بدونها.

</Accordion>
