جمعنا هنا إجابات عن بعض الأسئلة الشائعة حول Ayakaleaf Pro.

### أسئلة أساسية {#basic-question}

<Accordion title="س01: هل Ayakaleaf Pro نسخة تجريبية مجانية؟ هل يتطلب ترخيصًا؟">

لا. Ayakaleaf Pro مجاني تمامًا للاستخدام. ليس نسخة تجريبية ولا يتطلب أي ترخيص.

</Accordion>

<Accordion title="س02: هل يتضمن Ayakaleaf Pro جميع ميزات Overleaf Server Pro؟">

نعم. يتضمن Ayakaleaf Pro جميع ميزات Overleaf Server Pro، بما في ذلك تكامل Git-Bridge. كما يتضمن ميزات مختارة من منصة Overleaf SaaS. ونواصل تطوير Ayakaleaf Pro وتحسينه.

</Accordion>

<Accordion title="س03: كم تبلغ تكلفة Overleaf Server Pro؟">

تبلغ تكلفة Overleaf Server Pro نحو \$300 لكل مستخدم سنويًا. ويتطلب 10 تراخيص على الأقل، لذا تبدأ تكلفة النشر من نحو \$3,000 سنويًا. وتُظهر العقود العامة الأصغر في الولايات المتحدة تكاليف سنوية تبلغ نحو \$320–\$370 لكل مستخدم. وهذا يجعل Server Pro مكلفًا، خاصةً للفرق الصغيرة. راجع [#information-and-price-about-overleaf-server-pro](/ar/on-premises#information-and-price-about-overleaf-server-pro  "mention") للاطلاع على عمليات الشراء والأسعار الموثّقة.

</Accordion>

<Accordion title="س04: لماذا لا يتضمن Overleaf Server Pro ميزة GitHub Sync أو ميزات الذكاء الاصطناعي؟">

يُستخدم Overleaf Server Pro عادةً من قبل المؤسسات الحكومية. فهي تنشره على شبكات خاصة وتتحكم في الوصول إليه بصرامة. ولحماية البيانات الحساسة، تتجنب ميزاته المضمّنة تبادل البيانات مع خدمات الجهات الخارجية. إذا كنت بحاجة إلى GitHub Sync أو الذكاء الاصطناعي أو ميزات متصلة مشابهة، فإن Overleaf توصي بالاشتراك في منصتها SaaS.

</Accordion>

<Accordion title="س05: هل Ayakaleaf Pro آمن وموثوق؟">

Ayakaleaf Pro مفتوح المصدر. نراجع الشيفرة باستخدام أدوات مثل Codex Security لتعزيز أمانه وموثوقيته. إذا لم تفعّل مزامنة البيانات مع جهات خارجية، فستبقى بياناتك على خادمك. لا يحتوي Ayakaleaf Pro على أي قياس عن بُعد (telemetry) يرسل بياناتك إلى أي مكان آخر.

</Accordion>

<Accordion title="س06: هل ستتم صيانة Ayakaleaf Pro على المدى الطويل؟">

سنبذل قصارى جهدنا لصيانة هذا المشروع على المدى الطويل.

</Accordion>

<Accordion title="س07: هل Ayakaleaf Pro متوافق مع الأنظمة والتراخيص؟">

Ayakaleaf Pro هو تفرّع (fork) مجتمعي. تأتي شيفرته وميزاته المدمجة من مساهمات المجتمع. وهو مرخّص بموجب AGPL v3. ويمكن لعمليات النشر الامتثال لهذا الترخيص عندما تستوفي متطلباته.

</Accordion>

<Accordion title="س08: لماذا يُسمّى المشروع Ayakaleaf Pro؟">

كان اسم المشروع في الأصل Overleaf Pro في عام 2024. توقف التطوير لفترة، ثم استؤنف في أواخر عام 2025. وفي الربع الأول من عام 2026، أعادت Overleaf تسمية خطة اشتراكها المدعومة بالذكاء الاصطناعي إلى Pro. كما أشارت ملاحظات المجتمع إلى أن اسم Overleaf Pro قد ينطوي على مخاطر تتعلق بالعلامات التجارية وانتحال الصفة، وقد يجعل المستخدمين يظنون أن المشروع رسمي.

أعدنا تسمية المشروع إلى Ayakaleaf Pro لتجنب هذا الالتباس. ويمكن قراءة الاسم على أنه "Ayaka-notes Overleaf Pro". ويساهم المشرف على المشروع (يمكنك مناداتي ayaka!) في تطوير مجتمع Overleaf منذ سنوات دراسته، أي منذ أكثر من خمس سنوات. وتدعم هذه الخبرة التزامنا بالصيانة طويلة الأمد.

</Accordion>

<Accordion title="س09: ما الذي يميّز Ayakaleaf Pro عن محررات LaTeX الأحدث المبنية بالذكاء الاصطناعي؟">

منذ عام 2026، أصدر مجتمع المصادر المفتوحة العديد من محررات LaTeX المبنية بالذكاء الاصطناعي، بما فيها OpenAI Prism. يحتفظ Ayakaleaf Pro ببياناتك وخدماتك على خادمك الخاص، مما يمنحك تحكمًا مباشرًا في عملية النشر وفي بياناتك.

لا تملك العديد من المحررات المجتمعية التجريبية خطة صيانة طويلة الأمد راسخة. كما قد تتوقف منصات ترجمة LaTeX التابعة لجهات خارجية عن العمل عندما تكون قاعدة مستخدميها أو إيراداتها غير كافية. يوفّر Ayakaleaf Pro الشيفرة المصدرية كاملة ويتيح لك استضافة كل خدمة ذاتيًا. وحتى لو توقفت الصيانة، يمكن لخدمتك المستضافة ذاتيًا الحالية أن تستمر في العمل.

</Accordion>

<Accordion title="س10: ماذا حدث لمستودع GitHub ayaka-notes/overleaf-pro؟">

أُعيدت تسميته إلى [ayaka-notes/ayakaleaf-pro](https://github.com/ayaka-notes/ayakaleaf-pro) مع إعادة تسمية المشروع (راجع س08). لم يُؤرشف ولم يُستبدل: إنه المستودع نفسه، ويعيد GitHub توجيه روابط `ayaka-notes/overleaf-pro` القديمة ومستودعات Git البعيدة (remotes) إلى الاسم الجديد. وتحتفظ صورة Docker باسمها، `ghcr.io/ayaka-notes/overleaf-pro`، لذا لا تحتاج إلى تغيير `config/overleaf.rc` أو `config/version`.

</Accordion>

### الميزات {#features}

<Accordion title="س01: ما الميزات التي يقدّمها Ayakaleaf Pro؟ هل يمكنني طلب ميزة جديدة؟">

يُرجى مراجعة وثائقنا للاطلاع على قائمة الميزات الحالية. إذا كانت هناك ميزة تودّ أن نضيفها، فلا تتردد في فتح مشكلة (issue) على GitHub (لطلب ميزة). سنبذل قصارى جهدنا لتنفيذ الميزات المطلوبة، لكن التطوير يستغرق وقتًا، ولا يمكننا ضمان تقديم كل ميزة على الفور.

</Accordion>

<Accordion title="س02: لقد طوّرت بعض الميزات. هل يمكنني إرسال طلب سحب (PR)، وهل قبوله مضمون؟">

المساهمات مرحّب بها، لكن قبولها غير مضمون. نقيّم كل طلب سحب بناءً على تأثيره في قاعدة شيفرة Overleaf الأساسية، وعبء صيانته، والقيمة التي يقدّمها للمستخدمين. وسنبذل قصارى جهدنا لدمج المساهمات القيّمة وصيانتها.

ومع ذلك، قد نرفض طلبات السحب التي تُدخل تغييرات مفرطة، أو تتكوّن من شيفرة مولّدة بالذكاء الاصطناعي لم تُراجَع أو لم تُفهم جيدًا ("vibe coding")، أو تضيف ميزات يصعب صيانتها بمرور الوقت.

</Accordion>

<Accordion title="س03: كيف أكوّن ميزة معيّنة؟">

نحدّث الوثائق عمومًا كلما أصدرنا ميزة جديدة. يُرجى الرجوع إلى الوثائق ذات الصلة للاطلاع على تعليمات الإعداد التفصيلية وشرح متغيرات البيئة المتاحة.

</Accordion>

<Accordion title="س04: ما مكتبات Python التي يمكن لـ Python Runner استخدامها؟">

يشغّل Python Runner لغة Python في متصفح المستخدم باستخدام [Pyodide](https://pyodide.org/) 0.29.3، وليس على الخادم. ويحمّل الحزم التي تستوردها شيفرتك من [الحزم المضمّنة في Pyodide](https://pyodide.org/en/0.29.3/usage/packages-in-pyodide.html)، مثل NumPy وpandas وMatplotlib. أما الحزم المثبتة باستخدام `pip` والحزم الأخرى فغير متاحة. لا يوجد ما يلزم تكوينه على الخادم.

</Accordion>

<Accordion title="س05: هل يمكن للتدقيق الإملائي التحقق من اللغة اليابانية أو الصينية؟">

لا. لا يملك المدقق الإملائي قاموسًا للغة اليابانية أو الصينية، لذا فهاتان اللغتان غير موجودتين في قائمة لغات التدقيق الإملائي. يمكن للمستخدمين إيقاف التدقيق الإملائي لمشروع ما من إعدادات المحرر.

لمنع وضع علامة على كلمة على أنها خطأ إملائي، انقر عليها بزر الفأرة الأيمن واختر **Add to dictionary**. تُحفظ الكلمات المضافة في حسابك وتنطبق على جميع مشاريعك. لمراجعتها أو إزالتها، افتح إعدادات المحرر، ثم **Spelling and language → Dictionary → Edit**. ولا تؤدي إضافة الكلمات إلى إضافة لغة تدقيق إملائي جديدة.

</Accordion>

<Accordion title="س06: هل يمكنني إضافة إضافات (plugins)؟">

لا يوجد مُثبِّت للإضافات. الميزات عبارة عن وحدات (modules) في `services/web/modules` من الشيفرة المصدرية، مبنية ضمن صورة Docker وتُفعَّل بالإعدادات الواردة في هذه الوثائق. لإضافة ميزاتك الخاصة، أضف وحدة إلى الشيفرة المصدرية وابنِ صورتك الخاصة.

</Accordion>

### النشر {#deployment}

<Accordion title="س01: هل يدعم Ayakaleaf Pro النشر الموزّع في k8s؟">

بالنسبة إلى معظم المستخدمين، نوصي بالنشر باستخدام [Toolkit](/ar/on-premises/installation/using-docker-compose). ودعم Kubernetes تجريبي: تعرض صفحة [استخدام Kubernetes](/ar/on-premises/installation/using-kubernetes) ملفات البيان (manifests) التي اختبرناها مع نسخة متماثلة واحدة أو عدة نسخ متماثلة (replicas)، لكن العنقود يضيف تعقيدًا تشغيليًا وجهدًا في الصيانة. تنشئ [Sandboxed Compiles](/ar/on-premises/configuration/overleaf-toolkit/sandboxed-compiles) حاويات الترجمة الخاصة بها عبر مقبس Docker (Docker socket)، لذا تحتاج كل عقدة تشغّل Ayakaleaf Pro إلى Docker Engine. ولا نوفّر إعدادات لـ CRI-O أو Podman أو Quadlet.

</Accordion>

<Accordion title="س02: كيف يمكنني ضمان التوفّر عند خدمة آلاف المستخدمين؟">

يُرجى الرجوع إلى دليل [التوسّع الأفقي](/ar/on-premises/maintenance/horizontal-scaling). يمكنك نشر عدة نسخ من Overleaf وتكوين موازن تحميل (load balancer) لتوزيع حركة المرور بينها.

</Accordion>

<Accordion title="س03: هل يمكنكم مساعدتي في النشر أو الترحيل؟">

إذا كانت لديك نسخة قائمة من Overleaf Server Pro، فيسعدنا مساعدتك في الترحيل إلى Ayakaleaf Pro. يُرجى التواصل عبر البريد الإلكتروني أو المشكلات (issues).

</Accordion>

<Accordion title="س04: هل يمكنني استضافة Ayakaleaf Pro تحت مسار فرعي في عنوان URL، مثل `https://example.com/overleaf`؟">

لا. يجب تقديم Ayakaleaf Pro من جذر النطاق. استخدم نطاقًا أو نطاقًا فرعيًا مخصصًا، مثل `https://overleaf.example.com`.

</Accordion>

<Accordion title="س05: هل يمكنني تشغيل Ayakaleaf Pro على Windows أو macOS، أو بدون Toolkit؟">

نعم. يعمل Toolkit على [Linux](/ar/on-premises/installation/using-docker-compose/linux)، وعلى [macOS باستخدام Docker Desktop](/ar/on-premises/installation/using-docker-compose/macos)، وعلى [Windows باستخدام WSL 2 وDocker Desktop](/ar/on-premises/installation/using-docker-compose/windows). نوصي بنظام Linux للخوادم المشتركة وخوادم الإنتاج. يتضمن دليلا macOS وWindows إعداد Sandboxed Compiles.

لا نوفر ملف `docker-compose.yml` مستقلًا. لرؤية إعدادات Compose التي يستخدمها Toolkit، شغّل `bin/docker-compose config` في مجلد Toolkit.

</Accordion>

<Accordion title="س06: كيف ألغي تثبيت Ayakaleaf Pro؟">

لا يوجد سكربت لإلغاء التثبيت. في مجلد Toolkit:

1. أوقف الحاويات واحذفها باستخدام `bin/docker-compose down`.
2. احذف البيانات. توجد افتراضيًا في المجلد `data/` الخاص بـ Toolkit. إذا غيّرت `OVERLEAF_DATA_PATH` أو `MONGO_DATA_PATH` أو `REDIS_DATA_PATH` أو `GIT_BRIDGE_DATA_PATH` في `config/overleaf.rc`، فاحذف تلك المجلدات أيضًا. لا يمكن التراجع عن ذلك، لذا [خذ نسخة احتياطية](/ar/on-premises/maintenance/data-and-backups) أولًا إذا كنت قد تحتاج إلى البيانات.
3. احذف مجلد Toolkit.
4. احذف صور Docker، التي يمكنك سردها باستخدام `docker images`: `ghcr.io/ayaka-notes/overleaf-pro` وصورة git-bridge و`mongo` و`redis` وصور TeX Live.

</Accordion>

<Accordion title="س07: كيف أوقف Ayakaleaf Pro أو أشغّله أو أعيد تشغيله؟">

شغّل هذه الأوامر في مجلد Toolkit:

* `bin/stop` يوقف جميع الحاويات، و`bin/start` يشغّلها مجددًا. يُحتفظ بالحاويات، لذا يبقى المستخدمون مسجّلي الدخول.
* `bin/up -d` ينشئ الحاويات ويشغّلها في الخلفية. شغّله بعد تغيير `config/variables.env` أو `config/overleaf.rc` أو `config/version`: إذ يعيد إنشاء الحاويات التي تغيّرت إعداداتها، وعندها فقط تسري التغييرات. لا يطبّقها `bin/stop` و`bin/start`.
* `bin/docker-compose restart sharelatex` يعيد تشغيل حاوية Overleaf فقط، دون تطبيق تغييرات الإعدادات.

إذا كان يُسجَّل خروج المستخدمين في كل مرة يعيد فيها `bin/up` إنشاء الحاوية، فاضبط `OVERLEAF_SESSION_SECRET`، راجع قسم الأسئلة والأجوبة في [متغيرات البيئة](/ar/on-premises/configuration/overleaf-toolkit/environment-variables).

</Accordion>

<Accordion title="س08: أين أضع عنوان URL لاستدعاء OAuth (callback)؟">

في التطبيق الذي تنشئه لدى المزوّد، وليس في Ayakaleaf Pro. لا يوجد إعداد للاستدعاء في `config/variables.env` لأي من هذه التكاملات: يبني Ayakaleaf Pro كل عنوان URL للاستدعاء من `OVERLEAF_SITE_URL` ويرسله إلى المزوّد، الذي يرفضه ما لم يطابق العنوان المسجّل للتطبيق. لذا ما عليك سوى تسجيله لدى المزوّد، وضبط `OVERLEAF_SITE_URL` على العنوان الذي يفتحه المستخدمون.

| التكامل | الحقل لدى المزوّد | القيمة |
| --- | --- | --- |
| [GitHub](/ar/on-premises/configuration/overleaf-toolkit/integrations/github-synchronisation) | Authorization callback URL | `${OVERLEAF_SITE_URL}/user/github-sync/oauth2/callback` |
| [GitLab](/ar/on-premises/configuration/overleaf-toolkit/integrations/gitlab-synchronisation) | Redirect URI | `${OVERLEAF_SITE_URL}/user/gitlab-sync/oauth2/callback` |
| [Gitea](/ar/on-premises/configuration/overleaf-toolkit/integrations/gitea-synchronisation) | Redirect URIs | `${OVERLEAF_SITE_URL}/user/gitea-sync/oauth2/callback` |
| [Dropbox](/ar/on-premises/configuration/overleaf-toolkit/integrations/dropbox-synchronisation) | Redirect URIs (انقر على **Add**) | `${OVERLEAF_SITE_URL}/user/dropbox/oauth/callback` |
| [Zotero](/ar/on-premises/configuration/overleaf-toolkit/integrations/zotero-integration) | Callback URL | `${OVERLEAF_SITE_URL}/user/zotero/oauth/callback` |
| [Mendeley](/ar/on-premises/configuration/overleaf-toolkit/integrations/mendeley-integration) | Redirect URL | `${OVERLEAF_SITE_URL}/user/mendeley/oauth/callback` |
| [تسجيل الدخول عبر OIDC](/ar/on-premises/configuration/overleaf-toolkit/authentication/oidc-authentication) | Redirect URI | `${OVERLEAF_SITE_URL}/oidc/login/callback` |
| [تسجيل الدخول عبر SAML](/ar/on-premises/configuration/overleaf-toolkit/authentication/saml-authentication) | ACS URL (Assertion Consumer Service) | `${OVERLEAF_SITE_URL}/saml/login/callback` |

إذا غيّرت `OVERLEAF_SITE_URL`، على سبيل المثال إلى نطاق جديد، فحدّث عنوان URL لدى كل مزوّد أيضًا، وإلا فسيفشل الربط.

</Accordion>

<Accordion title="س09: أين تُخزَّن البيانات، وما مقدار مساحة القرص التي أحتاجها؟">

افتراضيًا، يبقى كل شيء على القرص المحلي للخادم، في مجلد `data/` الخاص بـ Toolkit: `data/overleaf` (ملفات المشاريع وسجلها ومخرجات الترجمة)، و `data/mongo` و `data/redis`. وللمثيلات التي تضم أقل من 1000 مستخدم، نوصي بالقرص المحلي مع [نسخ احتياطية](/ar/on-premises/maintenance/data-and-backups) منتظمة.

تشغل صورة Ayakaleaf Pro نحو 5 GB. أما الحد الأدنى البالغ 40 GB المذكور في [المقدمة](/ar/on-premises/installation/introduction) فهو مخصص لـ Sandboxed Compiles، التي تشغل كل صورة من صور `texlive-full` الخاصة بها نحو 28 GB. ودون Sandboxed Compiles، تعمل عمليات الترجمة داخل حاوية `sharelatex` باستخدام مخطط TeX Live الأساسي (basic scheme) بالإضافة إلى `latexmk` و `texcount` و `synctex` و `etoolbox` و `xetex`، لذا تفشل مشاريع كثيرة بسبب حزم مفقودة. ثم يكبر مجلد `data/` مع مشاريعك وسجلها؛ تحقّق منه باستخدام `du -sh data/*`.

</Accordion>

<Accordion title="س10: هل يمكنني إبقاء Ayakaleaf قيد التشغيل على Windows على مدار 24 ساعة يوميًا؟">

نعم، بشرط أن يبقى Windows في وضع التشغيل وأن يبقى Docker Desktop قيد التشغيل. فعّل **Start Docker Desktop when you sign in to your computer**، وأبقِ على سياسات `restart: always` الخاصة بـ Toolkit، وعطّل السكون (sleep) والإسبات (hibernation) التلقائيين عند التوصيل بالتيار الكهربائي. يمكن أن تنطفئ الشاشة؛ أما سلوك إغلاق غطاء الحاسوب المحمول فهو إعداد منفصل. لا يؤدي إغلاق طرفية Ubuntu بعد `bin/up -d` إلى إيقاف الحاويات المنفصلة (detached). أما الخروج من Docker Desktop، أو إيقاف محركه مؤقتًا، أو تشغيل `wsl --shutdown` فيقطع الخدمة.

يختلف Resource Saver في Docker Desktop عن سكون Windows: فهو يُطبَّق عندما لا تكون هناك حاويات قيد التشغيل، لذا لا تُعدّ حزمة Ayakaleaf العاملة خاملة لمجرد أن أحدًا لا يحرّر. وبعد إعادة تشغيل Windows، يظل إعداد بدء التشغيل عند تسجيل الدخول يتطلب أن يسجّل أحدهم الدخول. اتبع [إبقاء النسخة متاحة](/ar/on-premises/installation/using-docker-compose/windows/6.-post-installation-tasks#keep-the-instance-available) لعمليات التحقق وخطوات الاستعادة. يبقى Linux توصيتنا عندما يجب ألا يعتمد التوافر على تسجيل دخول تفاعلي إلى سطح المكتب.

</Accordion>

<Accordion title="س11: يقول Docker Desktop إن المحاكاة الافتراضية معطّلة. هل أحتاج إلى Hyper-V؟">

يستخدم هذا الدليل **WSL 2 backend**. ويتطلب تفعيل المحاكاة الافتراضية للمعالج (CPU virtualization) في BIOS/UEFI، وميزة **Virtual Machine Platform** في Windows، وتثبيتًا سليمًا لـ WSL 2. أما ميزة **Hyper-V** الكاملة فهي واجهة خلفية منفصلة لـ Docker Desktop وليست شرطًا مسبقًا لإعداد WSL هذا.

تحقّق من **Task Manager → Performance → CPU → Virtualization** ومن `wsl --list --verbose` في PowerShell. قد تعني أخطاء مثل `0x80370102` أن المحاكاة الافتراضية، أو ميزة Windows، أو برنامج hypervisor عند الإقلاع معطّل. راجع [خطوات استكشاف أخطاء تثبيت Windows وإصلاحها](/ar/on-premises/installation/using-docker-compose/windows/troubleshooting#wsl-or-docker-reports-that-virtualization-is-unavailable)، مع روابط الإصلاح من Microsoft وDocker. أعد تشغيل Windows بعد تفعيل الميزات المطلوبة؛ إذ لا يمكن لإعادة تثبيت Ayakaleaf إصلاح محرك Docker لا يبدأ.

</Accordion>

### LaTeX {#latex}

<Accordion title="س01: هل عمليات ترجمة مشاريع LaTeX الخاصة بالمستخدمين معزولة؟ هل Shell Escape مفعّل؟">

عند تفعيل Sandbox Compiles، تعمل عملية الترجمة الخاصة بكل مستخدم في حاوية Docker منفصلة، وتكون معزولة عن عمليات ترجمة المستخدمين الآخرين. يكون Shell Escape مفعّلًا افتراضيًا في Sandbox Compiles.

</Accordion>

<Accordion title="س02: هل صورة Sandbox Compiles موثوقة؟ هل يمكن أن تفشل الترجمة؟">

حسّنّا صورة TeX Live Full الخاصة بـ Sandbox Compiles على مدى السنوات الثلاث الماضية. في معظم الحالات، تُترجم المشاريع التي تُترجم بنجاح على overleaf.com بشكل صحيح أيضًا باستخدام Ayakaleaf Pro. إذا لم يكن أحد الخطوط المطلوبة متاحًا، فارفع ذلك الخط إلى مشروعك يدويًا.

</Accordion>

<Accordion title="س03: لا يُترجم مشروعي. هل يمكنكم مساعدتي في تشخيص المشكلة؟">

يُرجى رفع مشروعك إلى موقع Overleaf الرسمي، وتفعيل مشاركة الرابط للقراءة فقط، وتضمين الرابط في مشكلة (issue) على GitHub.

سنحقّق في أي أخطاء تمنع ترجمة مشروع في Ayakaleaf Pro ونصلحها، متى كان المشروع يُترجم بنجاح على موقع Overleaf الرسمي. أما مشكلات الترجمة الخارجة عن هذا النطاق فلا يشملها دعمنا.

</Accordion>
