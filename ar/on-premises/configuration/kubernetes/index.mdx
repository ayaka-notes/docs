يقرأ النشر على Kubernetes متغيرات البيئة نفسها التي يقرؤها Toolkit. حيثما تقول صفحة من صفحات Toolkit "أضف هذا إلى `config/variables.env`"، ضع القيمة في الـ ConfigMap ‏`overleaf-env`، أو في الـ Secret ‏`overleaf-secrets` عندما تكون كلمة مرور أو مفتاحًا أو رمزًا مميزًا (token). ثم أعد التشغيل:

```bash
kubectl -n overleaf apply -f 30-config.yaml        # after editing the ConfigMap
kubectl -n overleaf patch secret overleaf-secrets --type merge \
  -p '{"stringData":{"GITHUB_TOKEN_CIPHER_PASSWORD":"'"$(openssl rand -hex 32)"'"}}'
kubectl -n overleaf rollout restart deployment/overleaf
```

القيم الموجودة في `config/overleaf.rc` هي إعدادات خاصة بـ Toolkit، وليست متغيرات بيئة؛ ويوضح قسم الأسئلة والأجوبة في نهاية هذه الصفحة ما يحلّ محلها.

### الشهادات والملفات الأخرى

تأخذ بعض الميزات مسار ملف بدلًا من قيمة: شهادات SAML ‏(`OVERLEAF_SAML_IDP_CERT`، ...)، وجهة شهادات LDAP ‏(`OVERLEAF_LDAP_TLS_OPTS_CA_PATH`)، أو جهة شهادات خاصة لـ GitHub Enterprise أو GitLab أو Gitea مستضاف ذاتيًا (`NODE_EXTRA_CA_CERTS`). ضع الملفات في Secret وركّبه حيث تتوقعها صفحات Toolkit، أي `/var/lib/overleaf/certs`:

```bash
kubectl -n overleaf create secret generic overleaf-certs --from-file=idp_cert.pem --from-file=ca.pem
```

```yaml title="40-overleaf.yaml (additions)"
          volumeMounts:
            # ...
            - name: certs
              mountPath: /var/lib/overleaf/certs
              readOnly: true
      volumes:
        # ...
        - name: certs
          secret:
            secretName: overleaf-certs
```

ثم أشر إليها بمساراتها في الـ ConfigMap، مثل `NODE_EXTRA_CA_CERTS: /var/lib/overleaf/certs/ca.pem`، وأعد التشغيل.

<Warning>

<strong>كلمات مرور التشفير.</strong> اضبط في الـ Secret كل `*_CIPHER_PASSWORD` للميزات التي تستخدمها. وإلا فإن بعض الميزات تولّد ملف مفتاح في وحدة تخزين البيانات عند أول استخدام: مع نسخة متماثلة واحدة ينجح ذلك إلى أن تُفقد وحدة التخزين، ومع عدة نسخ متماثلة ستشفّر كل نسخة بمفتاح مختلف.

</Warning>

### أسئلة وأجوبة

<Accordion title="ما إعدادات Toolkit من `config/overleaf.rc` التي أحتاجها؟">

<strong>الإجابة:</strong> لا يقرأ Ayakaleaf Pro أيًا منها. ونظائرها في Kubernetes هي:

| `config/overleaf.rc`                         | Kubernetes                                                        |
| -------------------------------------------- | ----------------------------------------------------------------- |
| `OVERLEAF_LISTEN_IP`، `OVERLEAF_PORT`        | الـ Service ‏(NodePort) أو الـ Ingress لديك                        |
| `SIBLING_CONTAINERS_ENABLED`                 | `SANDBOXED_COMPILES*` في الـ ConfigMap، ومقبس Docker في الـ Pod   |
| `GIT_BRIDGE_ENABLED`                         | [التكامل مع Git](/ar/on-premises/configuration/kubernetes/integrations/git-integration)                             |
| `MONGO_ENABLED`، `REDIS_ENABLED`، `MONGO_URL`، `REDIS_HOST` | الـ StatefulSets أو خدماتك المُدارة، و`OVERLEAF_MONGO_URL` و`OVERLEAF_REDIS_HOST` |
| `REDIS_AOF_PERSISTENCE`                      | `--appendonly yes` في `20-redis.yaml`                             |
| `NGINX_ENABLED`، `TLS_*`                     | الـ Ingress أو موازن الأحمال لديك                                  |

</Accordion>
