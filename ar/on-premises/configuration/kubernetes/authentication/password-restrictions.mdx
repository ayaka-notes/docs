تتحقق خدمة **web** من كلمات المرور المحلية عندما يسجّل المستخدمون أو يعيّنون كلمة مرور أو يغيّرونها. لا تتأثر عمليات تسجيل الدخول عبر SSO ‏(LDAP وSAML وOIDC)؛ فكلمات المرور فيها من شأن موفّر الهوية. راجع [قيود كلمات المرور](/ar/on-premises/configuration/overleaf-toolkit/authentication/password-restrictions) الخاصة بـ Toolkit.

| | |
| --- | --- |
| الخدمة | web، في كل Pod من Pods ‏Ayakaleaf Pro؛ تُقرأ عند بدء تشغيل web |
| الشبكة | لا شيء |
| المهام الدورية | لا توجد |

### الإعداد

أضف ما يلي إلى الـ ConfigMap ‏`overleaf-env` ثم أعد التشغيل:

```yaml title="30-config.yaml (additions)"
  OVERLEAF_PASSWORD_VALIDATION_MIN_LENGTH: "12"
  OVERLEAF_PASSWORD_VALIDATION_MAX_LENGTH: "72"
```

```bash
kubectl apply -f 30-config.yaml
kubectl -n overleaf rollout restart deployment/overleaf     # or statefulset/overleaf
```

| المتغير | القيمة الافتراضية | |
| --- | --- | --- |
| `OVERLEAF_PASSWORD_VALIDATION_MIN_LENGTH` | `8` | أقصر كلمة مرور مقبولة. |
| `OVERLEAF_PASSWORD_VALIDATION_MAX_LENGTH` | `72` | أطول كلمة مرور مقبولة؛ تُعامَل القيم الأكبر من `72` على أنها `72`. |

ضع الأرقام بين علامتي اقتباس: فالـ ConfigMap لا يحتوي إلا على سلاسل نصية.

<Warning>

يُقرأ `OVERLEAF_PASSWORD_VALIDATION_PATTERN` لكنه لا يُطبَّق: تُقبل كلمة المرور التي لا تطابقه. لا تُطبَّق إلا قيود الطول.

</Warning>

### عدة نسخ متماثلة

لا حاجة إلى شيء إضافي: تقرأ كل نسخة متماثلة الـ ConfigMap نفسه.

### الاختبار على Kubernetes

على Kubernetes 1.37 مع نسخة متماثلة واحدة، ومع `OVERLEAF_PASSWORD_VALIDATION_MIN_LENGTH: "12"` و`OVERLEAF_PASSWORD_VALIDATION_PATTERN: aA$3` في الـ ConfigMap، رفض تفعيلُ حساب جديد كلمةَ مرور من 10 أحرف وقبل كلمة مرور من 20 حرفًا صغيرًا فقط، كان النمط سيرفضها. كما ترفض اختباراتنا الشاملة للتسجيل كلمة المرور `123456` لأنها قصيرة جدًا مع القيم الافتراضية.
