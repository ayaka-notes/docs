يُفعَّل وصول الضيوف إلى المشاريع المشتركة، والصفحات العامة، والتسجيل الذاتي باستخدام متغيرات بيئة تقرأها خدمة **web**؛ ثم تخدم خدمة real-time الضيوف عبر جلستهم. يُشرح ما يفتحه كل مفتاح في [الوصول العام](/ar/on-premises/configuration/overleaf-toolkit/authentication/public-access).

| | |
| --- | --- |
| الخدمة | web (وreal-time للضيوف في المحرر)، في كل Pod من Pods ‏Ayakaleaf Pro؛ تُقرأ عند بدء تشغيل web |
| Pod → الخارج | خادم SMTP، عندما يرسل التسجيل رسائل التفعيل |
| الحالة | رموز وصول الضيوف في الجلسة، وحدود معدّل التسجيل في Redis |
| المهام الدورية | لا توجد |

### الإعداد

أضف المفاتيح التي تحتاجها إلى الـ ConfigMap ‏`overleaf-env`:

```yaml title="30-config.yaml (additions)"
  # Guests open link-shared projects without an account
  OVERLEAF_ALLOW_ANONYMOUS_READ_AND_WRITE_SHARING: "true"
  # Signed-out visitors may open /learn, /templates, /devs and view links
  OVERLEAF_ALLOW_PUBLIC_ACCESS: "true"
  # Self-registration: "true", or only some domains
  OVERLEAF_ALLOW_PUBLIC_REGISTRATION: "@example.com, @*.uni.example"
```

```bash
kubectl apply -f 30-config.yaml
kubectl -n overleaf rollout restart deployment/overleaf     # or statefulset/overleaf
```

ضع كل قيمة بين علامتي اقتباس. يجب وضع القيم التي تبدأ بـ `@` بين علامتي اقتباس في YAML، وإلا فسيرفض `kubectl apply` الملف.

يرسل التسجيل المقصور على نطاقات معيّنة رسالة تفعيل، لذا يجب أن يعمل [تسليم البريد الإلكتروني](/ar/on-premises/configuration/kubernetes/email-delivery) من الـ Pods: ضع مضيف SMTP في الـ ConfigMap و`OVERLEAF_EMAIL_SMTP_PASS` في الـ Secret.

### عدة نسخ متماثلة

لا حاجة إلى شيء إضافي. يُحفظ وصول الضيف إلى المشروع في الجلسة داخل Redis، لذا يعمل المحرر على أي نسخة متماثلة يختارها موازن الأحمال.

### الاختبار على Kubernetes

على Kubernetes 1.37، نجحت اختباراتنا الشاملة للوصول العام: على نسخة متماثلة واحدة، التسجيل الذاتي مع ضبط `OVERLEAF_ALLOW_PUBLIC_REGISTRATION` على `true`، وعلى نطاق واحد، وعلى عدة نطاقات مع حرف بدل للنطاقات الفرعية، وعلى `@*`، مع رسالة التفعيل في أوضاع النطاقات (43 حالة)؛ والزوار غير المسجلين دخولهم على `/devs` ومقتطف مُرسَل يُحتفظ به عبر تسجيل الدخول مع `OVERLEAF_ALLOW_PUBLIC_ACCESS` ‏(حالتان)؛ وضيف غير مسجل دخوله في مشروع مشترك عبر رابط مع تفعيل المفتاحين (3 حالات)؛ وعلى ثلاث نسخ متماثلة خلف HAProxy، ‏OIDC مع الوصول العام (حالة واحدة).
