تكتب كل خدمة داخل pod الخاص بـ Ayakaleaf Pro ملف سجلّها الخاص تحت `/var/log/overleaf/`؛ أما `kubectl logs` فلا يعرض إلا مخرجات بدء تشغيل الحاوية (سكربتات التهيئة، وعمليات الترحيل). يقرأ الأمر `bin/logs` في Toolkit الملفات نفسها، راجع [السجلات](/ar/on-premises/configuration/overleaf-toolkit/logging).

| المكان | المحتوى |
| --- | --- |
| `kubectl -n overleaf logs <pod>` | بدء التشغيل: التحقق من الأسرار، وعمليات الترحيل (`Finished migrations`)، وبدء تشغيل الخدمات |
| `/var/log/overleaf/<service>.log` داخل الـ pod | `web.log`، `web-api.log`، `clsi.log`، `real-time.log`، `document-updater.log`، `docstore.log`، `filestore.log`، `history-v1.log`، `project-history.log`، `chat.log`، `notifications.log`، `linked-url-proxy.log`، و`third-party-datastore.log` عند تفعيل Dropbox |
| `/var/log/nginx/` داخل الـ pod | `access.log` و`error.log` الخاصان بـ nginx الموجود أمام الخدمات |
| `kubectl -n overleaf logs mongo-0`، `redis-0`، `git-bridge-0` | MongoDB وRedis وgit-bridge، والتي تعمل في pods خاصة بها |

### قراءة السجلات

| Toolkit | Kubernetes |
| --- | --- |
| `bin/logs web` | `kubectl -n overleaf exec deploy/overleaf -- tail -n 20 /var/log/overleaf/web.log` |
| `bin/logs -f web clsi` | `kubectl -n overleaf exec deploy/overleaf -- tail -f /var/log/overleaf/web.log /var/log/overleaf/clsi.log` |
| `bin/logs -n all web > web.log` | `kubectl -n overleaf cp overleaf/<pod>:/var/log/overleaf/web.log web.log` |
| `bin/logs mongo` | `kubectl -n overleaf logs mongo-0` |

مع [عدة نسخ متماثلة](/ar/on-premises/configuration/kubernetes/horizontal-scaling)، يكون لكل pod ملفاته الخاصة: استخدم اسم الـ pod (`overleaf-0`، `overleaf-1`، ...) بدلًا من `deploy/overleaf`. وتوضّح الترويسة `X-Served-By` التي يضيفها HAProxy أي نسخة متماثلة أجابت عن الطلب.

يضبط `LOG_LEVEL` في الـ ConfigMap (الافتراضي `info`، ويمكن أيضًا `debug` و`warn` و`error`) مستوى كل الخدمات في الـ pod دفعة واحدة.

### الاحتفاظ بالسجلات

توجد الملفات داخل الحاوية وتُفقد عند استبدال الـ pod. للاحتفاظ بها، ركّب وحدة تخزين (volume) على `/var/log/overleaf`، على سبيل المثال `hostPath` على العقدة أو PersistentVolumeClaim، في الـ Deployment أو الـ StatefulSet:

```yaml
          volumeMounts:
            # ...
            - name: logs
              mountPath: /var/log/overleaf
      volumes:
        # ...
        - name: logs
          hostPath:
            path: /srv/overleaf-logs
            type: DirectoryOrCreate
```

تدوّر الحاوية الملفات يوميًا وتحتفظ بخمسة منها، لذا لا تنمو وحدة التخزين بلا حدود. أو اجمعها من ذلك المسار باستخدام وكيل السجلات الخاص بالعنقود (cluster) لديك.

### الاختبار على Kubernetes

على Kubernetes 1.37 مع ثلاث نسخ متماثلة ووحدة تخزين `hostPath` على `/var/log/overleaf` كما في المثال أعلاه، احتوى `/srv/overleaf-logs` في كل عقدة على سجلات الخدمات الاثنتي عشرة الخاصة بالنسخة المتماثلة الموجودة عليها، وعملت الأوامر الواردة في الجدول كما هو موضّح: `tail` عبر `kubectl exec`، و`kubectl cp` لملف سجل، و`kubectl logs` لـ pod الخاص بـ Overleaf (بدء التشغيل وعمليات الترحيل) ولـ `mongo-0`.
