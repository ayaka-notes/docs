تصف هذه الصفحة متغيرات البيئة المدعومة في ملف `config/overleaf.rc` لعمليات النشر باستخدام Toolkit.

يتكون ملف `config/overleaf.rc` من تعريفات متغيرات بالصيغة `NAME=value`. تُعامَل الأسطر التي تبدأ بـ `#` كتعليقات.

<Info>

من الضروري إعادة إنشاء حاويات Docker بعد تغيير أي شيء في `overleaf.rc` أو `variables.env` عن طريق تشغيل `bin/up`.

</Info>

## الحاويات

### `sharelatex`

| الاسم                         | الوصف |
| ---------------------------- | ----------- |
| `PROJECT_NAME`               | <p>يضبط قيمة الخيار `--project-name` المُمرَّر إلى `docker-compose`. يفيد ذلك عند تشغيل عدة نسخ من Overleaf على مضيف واحد، إذ يمكن أن يكون لكل نسخة اسم مشروع مختلف.<br /><br />- <strong>القيمة الافتراضية</strong>: `overleaf`</p> |
| `OVERLEAF_IMAGE_NAME`        | <p>صورة Docker المستخدمة في حاوية تطبيق Server Pro/CE. هذا هو اسم صورة Docker فقط؛ أما وسم صورة Docker فيُؤخذ من `config/version`.<br /><br />- <strong>القيمة الافتراضية:</strong><br />- Server Pro: `ghcr.io/ayaka-notes/overleaf-pro`<br />- Community Edition: `sharelatex/sharelatex`</p> |
| `SERVER_PRO`                 | <p>عند ضبطه على `true`، يوجّه Toolkit لاستخدام صورة Server Pro (`ghcr.io/ayaka-notes/overleaf-pro`) بدلًا من صورة Server CE الافتراضية (`sharelatex/sharelatex`).<br /><br />- <strong>القيمة الافتراضية</strong>: `false`</p> |
| `GIT_BRIDGE_ENABLED`         | <p>اضبطه على `true` لتفعيل ميزة git-bridge (في Server Pro فقط). لمزيد من المعلومات راجع وثائق المستخدم <a href="https://www.overleaf.com/learn/how-to/Git_integration">https://www.overleaf.com/learn/how-to/Git_integration</a>.<br /><br />- <strong>القيمة الافتراضية:</strong> `false`</p> |
| `GIT_BRIDGE_IMAGE`           | <p>صورة Docker المستخدمة في حاوية git-bridge (في Server Pro فقط). هذا هو اسم صورة Docker فقط؛ أما وسم صورة Docker فيُؤخذ من `config/version`.<br /><br />- <strong>القيمة الافتراضية:</strong> `ghcr.io/ayaka-notes/overleaf-pro/git-bridge`</p> |
| `GIT_BRIDGE_DATA_PATH`       | يضبط مسار المجلد الذي سيُركَّب داخل حاوية `git-bridge` (في Server Pro فقط)، ويُستخدم لتخزين مستودعات git. يمكن أن يكون مسارًا كاملًا (يبدأ بـ `/`)، أو مسارًا نسبيًا إلى المجلد الأساسي لـ Toolkit. |
| `GIT_BRIDGE_LOG_LEVEL`       | <p>يكوّن مستوى التسجيل لحاوية `git-bridge`. المستويات المتاحة: `TRACE`، `DEBUG`، `INFO`، `WARN`، `ERROR`.<br /><br />- <strong>القيمة الافتراضية:</strong> `INFO`</p> |
| `SIBLING_CONTAINERS_ENABLED` | <p>عند ضبطه على `true`، يوجّه Toolkit لاستخدام تقنية <strong>الحاويات الشقيقة (Sibling Containers)</strong> لترجمة المشاريع في بيئات معزولة منفصلة، باستخدام حاوية Docker مستقلة لكل مشروع. راجع وثائق &#x3C;server-pro-only-configuration/sandboxed-compiles> لمزيد من المعلومات.<br /><br />- <strong>يتطلب:</strong> `SERVER_PRO=true`<br />- <strong>القيمة الافتراضية:</strong> `true`</p> |
| `SIBLING_CONTAINERS_PULL`    | <p>عند ضبطه على `true`، يوجّه Toolkit لسحب جميع صور TeX Live المحددة باستخدام `ALL_TEX_LIVE_DOCKER_IMAGES` في ملف <strong>config/variables.env</strong> تلقائيًا عند استخدام الأمر `bin/up`.<br /><br />- <strong>القيمة الافتراضية:</strong> `true`</p> |
| `DOCKER_SOCKET_PATH`         | <p>يضبط مسار مقبس Docker على الجهاز المضيف (الجهاز الذي يشغّل Toolkit). عندما تكون قيمة `SIBLING_CONTAINERS_ENABLED` هي `true`، سيُركَّب المقبس داخل الحاوية للسماح لخدمة الترجمة بإنشاء حاويات Docker جديدة على المضيف.<br /><br />- <strong>يتطلب:</strong> `SIBLING_CONTAINERS_ENABLED=true`<br />- <strong>القيمة الافتراضية:</strong> `/var/run/docker.sock`</p> |
| `OVERLEAF_DATA_PATH`         | <p>يضبط مسار المجلد الذي سيُركَّب داخل حاوية `sharelatex` الرئيسية، ويُستخدم لتخزين بيانات الترجمة. يمكن أن يكون مسارًا كاملًا (يبدأ بـ `/`)، أو مسارًا نسبيًا إلى المجلد الأساسي لـ Toolkit.<br /><br />- <strong>القيمة الافتراضية:</strong> `data/overleaf`</p> |
| `OVERLEAF_LISTEN_IP`         | <p>يضبط عنوان (عناوين) IP للمضيف التي ستربط بها الحاوية. على سبيل المثال، إذا ضُبط على `0.0.0.0`، فستكون واجهة الويب متاحة على أي عنوان IP للمضيف. للوصول المباشر إلى الحاوية، يجب ضبط قيمة `OVERLEAF_LISTEN_IP` على عنوان IP العام الخاص بك. عادةً ما يتسبب ضبط `OVERLEAF_LISTEN_IP` على `0.0.0.0` أو على عنوان IP الخارجي للمضيف في حدوث أخطاء عند استخدامه مع .<br /><br />- <strong>القيمة الافتراضية:</strong> `127.0.0.1`</p> |
| `OVERLEAF_PORT`              | <p>يضبط منفذ المضيف الذي ستربط به الحاوية. على سبيل المثال، إذا ضُبط على `8099` وضُبط `OVERLEAF_LISTEN_IP` على `127.0.0.1`، فستكون واجهة الويب متاحة على `http://localhost:8099`.<br /><br />- <strong>القيمة الافتراضية:</strong> `80`</p> |
| `OVERLEAF_LOG_PATH`          | <p>يضبط مسار المجلد الذي سيُركَّب داخل حاوية `sharelatex` الرئيسية، ويُستخدم لإتاحة سجلات التطبيق على مضيف Docker. يمكن أن يكون مسارًا كاملًا (يبدأ بـ `/`)، أو مسارًا نسبيًا إلى المجلد الأساسي لـ Toolkit. احذف إدخال التكوين لتعطيل التركيب (bind-mount). عند عدم ضبطه، ستُتجاهَل السجلات عند إعادة إنشاء الحاوية.<br /><br />راجع للحصول على معلومات حول التسجيل.<br /><br />- <strong>القيمة الافتراضية:</strong> غير مضبوط</p> |

### `mongo`

| الاسم              | الوصف |
| ----------------- | ----------- |
| `MONGO_ENABLED`   | <p>عند ضبطه على `true`، يوجّه Toolkit لإنشاء حاوية MongoDB لاستضافة قاعدة البيانات. عند ضبطه على `false`، لن تُنشأ هذه الحاوية، وسيستخدم النظام بدلًا من ذلك قاعدة بيانات MongoDB المحددة بواسطة `MONGO_URL`.<br /><br />- <strong>القيمة الافتراضية</strong>: `true`</p> |
| `MONGO_URL`       | <p>يحدد عنوان URL للاتصال بـ MongoDB الذي يُستخدم عندما تكون قيمة `MONGO_ENABLED` هي `false`.<br /><br />- <strong>القيمة الافتراضية</strong>: غير مضبوط</p> |
| `MONGO_DATA_PATH` | <p>يضبط مسار المجلد الذي سيُركَّب داخل حاوية `mongo`، ويُستخدم لتخزين قاعدة بيانات MongoDB. يمكن أن يكون مسارًا كاملًا (يبدأ بـ `/`)، أو مسارًا نسبيًا إلى المجلد الأساسي لـ toolkit. يؤثر هذا الخيار فقط على حاوية `mongo` المحلية التي تُنشأ عندما تكون قيمة `MONGO_ENABLED` هي `true`.<br /><br />- <strong>القيمة الافتراضية</strong>: `data/mongo`</p> |
| `MONGO_IMAGE`     | <p>صورة Docker المستخدمة في حاوية MongoDB. هذا هو اسم صورة Docker فقط؛ أما وسم صورة Docker فيجب وضعه في `MONGO_VERSION` (انظر أدناه).<br /><br />- <strong>القيمة الافتراضية:</strong> `mongo`</p> |
| `MONGO_VERSION`   | <p>إصدار MongoDB المستخدم في حاوية MongoDB. يجب أن تبدأ القيمة برقم الإصدار الرئيسي لـ MongoDB متبوعًا بنقطة، مثل `6.0` أو `6.0-with-suffix`.<br /><br />- <strong>القيمة الافتراضية:</strong> `6.0`</p> |

***

### `redis`

| الاسم                    | الوصف |
| ----------------------- | ----------- |
| `REDIS_ENABLED`         | <p>عند ضبطه على `true`، يوجّه Toolkit لإنشاء حاوية Redis لاستضافة قاعدة بيانات redis. عند ضبطه على `false`، لن تُنشأ هذه الحاوية، وسيستخدم النظام بدلًا من ذلك قاعدة بيانات Redis المحددة بواسطة `REDIS_HOST` و`REDIS_PORT`.<br /><br />- <strong>القيمة الافتراضية</strong>: `true`</p> |
| `REDIS_HOST`            | <p>يحدد مضيف Redis الذي يُستخدم عندما تكون قيمة `REDIS_ENABLED` هي `false`.<br /><br />- <strong>القيمة الافتراضية</strong>: غير مضبوط</p> |
| `REDIS_PORT`            | <p>يحدد منفذ Redis الذي يُستخدم عندما تكون قيمة `REDIS_ENABLED` هي `false`.<br /><br />- <strong>القيمة الافتراضية</strong>: غير مضبوط</p> |
| `REDIS_DATA_PATH`       | <p>يضبط مسار المجلد الذي سيُركَّب داخل حاوية `redis`، ويُستخدم لتخزين قاعدة بيانات Redis. يمكن أن يكون مسارًا كاملًا (يبدأ بـ `/`)، أو مسارًا نسبيًا إلى المجلد الأساسي لـ Toolkit. يؤثر هذا الخيار فقط على حاوية `redis` المحلية التي تُنشأ عندما تكون قيمة `REDIS_ENABLED` هي `true`.<br /><br />- <strong>القيمة الافتراضية</strong>: `data/redis`</p> |
| `REDIS_AOF_PERSISTENCE` | <p>يفعّل استمرارية AOF (Append Only File) في Redis. هذا هو التكوين <strong>الموصى به</strong> لاستمرارية بيانات Redis.<br /><br />لمزيد من التفاصيل، راجع القسم &#x3C;../../../maintenance/data-and-backups#aof-append-only-file> في &#x3C;../../maintenance/data-and-backups>.<br /><br />- <strong>القيمة الافتراضية:</strong> `true`</p> |

### `nginx`

| الاسم                   | الوصف |
| ---------------------- | ----------- |
| `NGINX_ENABLED`        | <p>عند ضبطه على `true`، يوجّه Toolkit لإنشاء حاوية NGINX لتعمل كوكيل TLS.<br /><br />- <strong>القيمة الافتراضية</strong>: `false`</p> |
| `NGINX_CONFIG_PATH`    | <p>مسار ملف تكوين NGINX المستخدم لوكيل TLS.<br /><br />- <strong>القيمة الافتراضية</strong>: `config/nginx/nginx.conf`</p> |
| `NGINX_TLS_LISTEN_IP`  | <p>يضبط عنوان (عناوين) IP للمضيف التي ستربط بها حاوية وكيل TLS لبروتوكول HTTPS. على سبيل المثال، إذا ضُبط على `0.0.0.0` فستكون واجهة الويب عبر HTTPS متاحة على أي عنوان IP للمضيف. عادةً يجب ضبطه على عنوان IP الخارجي للمضيف.<br /><br />- <strong>القيمة الافتراضية</strong>: `127.0.1.1`</p> |
| `NGINX_HTTP_LISTEN_IP` | <p>يضبط عنوان (عناوين) IP للمضيف التي ستربط بها حاوية وكيل TLS لإعادة توجيه HTTP. على سبيل المثال، إذا ضُبط على `127.0.1.1` فستُعاد توجيه اتصالات HTTP إلى `127.0.1.1` نحو واجهة الويب عبر HTTPS. عادةً يجب ضبطه على عنوان IP الخارجي للمضيف. لا تضبطه على `0.0.0.0` لأن ذلك يتسبب عادةً في تعارض مع `OVERLEAF_LISTEN_IP`.<br /><br />- <strong>القيمة الافتراضية</strong>: `127.0.1.1`</p> |
| `NGINX_HTTP_PORT`      | <p>يضبط منفذ المضيف الذي ستربط به حاوية وكيل TLS لبروتوكول HTTP.<br /><br />- <strong>القيمة الافتراضية</strong>: `80`</p> |
| `TLS_PORT`             | <p>يضبط منفذ المضيف الذي ستربط به حاوية وكيل TLS لبروتوكول HTTPS.<br /><br />- <strong>القيمة الافتراضية</strong>: `443`</p> |
| `TLS_PRIVATE_KEY_PATH` | <p>مسار المفتاح الخاص المستخدم لوكيل TLS.<br /><br />- <strong>القيمة الافتراضية</strong>: `config/nginx/certs/overleaf_key.pem`</p> |
| `TLS_CERTIFICATE_PATH` | <p>مسار الشهادة العامة المستخدمة لوكيل TLS.<br /><br />- <strong>القيمة الافتراضية</strong>: `config/nginx/certs/overleaf_certificate.pem`</p> |
