يمتلك كل مشروع خادم MCP خاصًا به، بحيث يمكن لعملاء الذكاء الاصطناعي مثل Claude Code و Codex و Cursor و VS Code و Gemini CLI العمل عليه: قراءة ملفاته وتعديلها، وترجمته، وقراءة سجل LaTeX، وتنزيل ملف PDF، والرد على التعليقات. ابتداءً من v6.3.3 يمكنها أيضًا تصفح السجل واستعادة الإصدارات، ومراجعة التغييرات المتتبَّعة، وإضافة التعليقات، واستخدام دردشة المشروع، ونقل الملفات.

<Info>

طُوّرت هذه الميزة بواسطة [ayaka-notes/ayakaleaf-pro](https://github.com/ayaka-notes/ayakaleaf-pro). وهي متاحة بدءًا من الإصدار v6.3.1 وما بعده. أدوات السجل والتغييرات المتتبَّعة ودردشة المشروع والتعليقات الجديدة ونقل الملفات متاحة ابتداءً من v6.3.3، راجع [الجديد في v6.3.3](/on-premises/user-guide/users/mcp-server#new-in-v6.3.3).

</Info>

### الإعداد {#setup}

يأتي خادم MCP مع التكامل مع Git: فعّل [git-bridge](/ar/on-premises/configuration/overleaf-toolkit/integrations/git-integration)، وسيصبح خادم MCP متاحًا أيضًا. لا يوجد أي شيء آخر لتكوينه.

### ربط عميل ذكاء اصطناعي {#connect-an-ai-client}

1. في **Account Settings**، أنشئ رمز مصادقة Git (token). يُستخدم الرمز نفسه لخادم MCP ولـ Git.
2. في المحرر، افتح **Integrations** وانقر على **MCP server**. تعرض النافذة عنوان خادم MCP الخاص بالمشروع، `https://<your-overleaf>/project/<project_id>/mcp`، وطريقة إضافته إلى كل عميل ذكاء اصطناعي: انسخ الأمر، واستبدل `<token>` بالرمز الخاص بك.

يُرسَل الرمز في ترويسة HTTP بالصيغة `Authorization: Bearer <token>`. على سبيل المثال، الأمر الخاص بـ Claude Code هو:

```bash
claude mcp add --transport http overleaf \
  https://<your-overleaf>/project/<project_id>/mcp \
  --header "Authorization: Bearer <token>"
```

### الاستخدام {#usage}

بمجرد الاتصال، اطلب من عميل الذكاء الاصطناعي ما تريد بكلمات بسيطة. على سبيل المثال:

| ما تطلبه | ما يستخدمه عميل الذكاء الاصطناعي |
| --- | --- |
| _أصلح الأخطاء الإملائية في المقدمة._ | `read_file` و `edit_file`: تظهر التعديلات مباشرةً في المحرر |
| _ترجم المشروع وأصلح أخطاء LaTeX._ | `compile` و `get_compile_log` و `edit_file` |
| _أجب عن التعليقات المفتوحة، ثم احسمها._ | `list_comments` و `reply_to_comment` و `resolve_comment` |
| _بدّل إلى XeLaTeX ونزّل ملف PDF._ | `update_settings` و `compile` و `get_output_file_link` |
| _أعد كتابة الملخص كتغيير متتبَّع._ | `read_file`، `edit_file` مع `trackChanges` (v6.3.3) |
| _ما الذي تغيّر منذ الإصدار المُرسَل؟_ | `list_versions`، `list_changes`، `diff` (v6.3.3) |
| _انقل الفصول إلى مجلد اسمه chapters._ | `move_file` (v6.3.3) |

### الأدوات {#tools}

| المجموعة | الأدوات |
| --- | --- |
| المشروع | `get_clone_info`, `get_settings`, `update_settings` |
| الملفات | `list_files`, `read_file`, `edit_file`, `write_file`, `delete_file`, `move_file`, `create_folder` |
| الترجمة | `compile`, `get_compile_log`, `get_output_file_link`, `word_count` |
| التعليقات | `list_comments`, `reply_to_comment`, `resolve_comment`, `reopen_comment`, `add_comment`, `edit_comment_message`, `delete_comment_message` |
| التغييرات المتتبَّعة | `list_tracked_changes`, `accept_tracked_changes`, `reject_tracked_changes` |
| السجل | `list_versions`, `list_changes`, `diff`, `create_version`, `delete_version`, `restore_file`, `restore_project` |
| الدردشة | `list_chat_messages`, `send_chat_message` |

يحتوي v6.3.3 على 33 أداة، أو 31 مع `OVERLEAF_DISABLE_CHAT=true` الذي يزيل أدوات الدردشة. يحتوي v6.3.1 وv6.3.2 على الأدوات الـ 17 الأخرى: كل ما سبق باستثناء `move_file` و`create_folder` و`add_comment` و`edit_comment_message` و`delete_comment_message` وأدوات التغييرات المتتبَّعة وأدوات الدردشة وأدوات السجل غير `list_versions`. في v6.3.3 تقرأ `read_file` الملف أيضًا في إصدار من السجل، وتقبل `edit_file` و`write_file` الخيار `trackChanges`، وتضبط `update_settings` أيضًا لغة التدقيق الإملائي.

تظهر التعديلات التي تُجرى باستخدام `edit_file` و`write_file` و`move_file` مباشرةً في المحرر وتُدمج مع تعديلات المتعاونين. وللعديد من الملفات دفعة واحدة أو للملفات الثنائية، يمكن لعميل الذكاء الاصطناعي أيضًا استنساخ المشروع باستخدام Git ثم الدفع.

مع `trackChanges` يكون تعديل ملف موجود تغييرًا متتبَّعًا لمستخدم الرمز المميز، حتى عندما يكون تتبع التغييرات متوقفًا في المشروع؛ أما الملف الجديد فلا يكون كذلك أبدًا. وبدون `trackChanges` تتبع التعديلات إعداد تتبع التغييرات في المشروع.

### الصلاحيات {#permissions}

يتبع خادم MCP إعدادات مشاركة المشروع، تمامًا مثل Git:

* يمكن لكل من يستطيع عرض المشروع قراءته وترجمته وتنزيل مخرجاته.
* يمكن للمالك والمحررين فقط تغيير ملفاته وإعداداته، واستعادة الإصدارات، وقبول التغييرات المتتبَّعة أو رفضها.
* يمكن للمراجعين أيضًا إضافة التعليقات والرد عليها، وحل التعليقات التي بدأوها أو إعادة فتحها أو حذفها، وحفظ الإصدارات. ولا يمكنهم تعديل الملفات، ولا حتى كتغييرات متتبَّعة.
* يعدّل كل شخص رسائل تعليقاته فقط، ولا يحذف المراجعون إلا رسائلهم.
* المالك وحده يحذف الإصدارات التي حفظها آخرون.
* لا يستطيع المشاهدون الذين انضموا عبر رابط رؤية التعليقات أو التغييرات المتتبَّعة أو السجل أو الدردشة، كما في المحرر. أما المشاهدون المدعوون فيمكنهم رؤيتها واستخدام الدردشة.
* إذا لم يكن لدى مالك المشروع **Full project history**، فإن أدوات السجل لا تعرض إلا تغييرات آخر 24 ساعة، كما تفعل لوحة السجل. ويرى المسؤولون جميعها.

يحتوي دليل المستخدم على جدول بما يُسمح لكل دور بفعله، راجع [من يمكنه فعل ماذا](/on-premises/user-guide/users/mcp-server#who-may-do-what).

### أسئلة وأجوبة {#q&a}

<Accordion title="لا أرى Integrations أو MCP server في المحرر">

<strong>الإجابة:</strong> لا يملك خادم MCP متغير بيئة خاصًا به. يُفعَّل عبر `GIT_BRIDGE_ENABLED=true` في `config/overleaf.rc`، راجع [التكامل مع Git](/ar/on-premises/configuration/overleaf-toolkit/integrations/git-integration). بعد تغييره، شغّل `bin/up -d`. بدون git-bridge، لا يعرض المحرر تبويب **Integrations** في شريطه الجانبي الأيسر.

</Accordion>

<Accordion title="عميل الذكاء الاصطناعي يقول «Track changes is off for this project»">

<strong>الإجابة:</strong> طلب العميل تغييرًا متتبَّعًا، لكن حساب مالك المشروع لا يملك ميزة تتبع التغييرات. انقر على **Admin**، ثم على **Manage Users**، وافتح المالك، وفي علامة التبويب **Features** فعّل **Track changes**، راجع [Features](/ar/on-premises/user-guide/administrators/user-management#features). تظل التعديلات بدون `trackChanges` تعمل.

</Accordion>

<Accordion title="عميل الذكاء الاصطناعي لا يرى إلا تغييرات آخر 24 ساعة">

<strong>الإجابة:</strong> لا يملك حساب مالك المشروع سجل المشروع الكامل، لذا تعرض أدوات السجل ما تعرضه لوحة السجل: تغييرات آخر 24 ساعة. انقر على **Admin**، ثم على **Manage Users**، وافتح المالك، وفي علامة التبويب **Features** فعّل **Full project history**، راجع [Features](/ar/on-premises/user-guide/administrators/user-management#features).

</Accordion>
