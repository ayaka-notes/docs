### إعداد المزامنة مع GitHub

<Warning>

يجب عليك تفعيل [git-bridge](/ar/on-premises/configuration/overleaf-toolkit/git-integration) أولًا قبل استخدام المزامنة مع GitHub.

```dotenv title="config/overleaf.rc"
GIT_BRIDGE_ENABLED=true
```

</Warning>

انتقل إلى [إعدادات المطورين](https://github.com/settings/developers) لإنشاء تطبيق GitHub OAuth الخاص بك، وانسخ `CLIENT_ID` و`SECRET`.

**ملاحظة**: عند إنشاء تطبيق OAuth، أدخل `${OVERLEAF_SITE_URL}/user/github-sync/oauth2/callback` في **Authorization callback URL**. يبني Ayakaleaf Pro العنوان نفسه من `OVERLEAF_SITE_URL`، لذا لا يوجد ما تضبطه له في `config/variables.env`.

بعد ذلك، أضف الإعدادات التالية إلى ملفات متغيرات البيئة الخاصة بـ overleaf.

```dotenv title="config/variables.env" wrap
# used to encrypt the user's GitHub access token.
# How to generate: `openssl rand -hex 32`
GITHUB_TOKEN_CIPHER_PASSWORD=0123456789ABCDEFG # changed to yours

# Github Sync Settings
GITHUB_SYNC_ENABLED=true
GITHUB_SYNC_CLIENT_ID=
GITHUB_SYNC_CLIENT_SECRET=

# OAuth callback is: ${OVERLEAF_SITE_URL}/user/github-sync/oauth2/callback
# (Optional) GITHUB_SYNC_PROXY_URL=http://10.0.0.1:10808
```

<Warning>

قبل تكوين عنوان URL لاستدعاء GitHub OAuth، تأكد من ضبط `OVERLEAF_SITE_URL` بشكل صحيح.

</Warning>

إذا كنت موجودًا في منطقة ذات وصول مقيّد إلى الشبكة، فقد تحتاج إلى تكوين وكيل (proxy) للوصول إلى GitHub. اضبط متغير البيئة التالي: `GITHUB_SYNC_PROXY_URL=http://10.0.0.1:10808`. يُرجى التأكد من أن استخدامك للوكيل يتوافق مع القوانين واللوائح المحلية.

<Warning>

يجب أن يكون `GITHUB_SYNC_PROXY_URL` وكيلًا أماميًا قياسيًا من نوع HTTP/HTTPS (مثل منفذ HTTP في Clash). مرايا تنزيل GitHub مثل `gh-proxy.org` غير مدعومة.

</Warning>

<Warning>

لا تستخدم `127.0.0.1` كمضيف للوكيل. إذا كان الوكيل يعمل على الخادم المضيف، فاستخدم عنوان IP الخاص بالخادم على الشبكة المحلية (مثل `192.168.1.xx`) وتأكد من تكوين الوكيل لقبول الاتصالات من الأجهزة على الشبكة المحلية.

</Warning>

### GitHub Enterprise

<Info>

دعم GitHub Enterprise متاح بدءًا من الإصدار v6.3.1 وما بعده. تتصل الإصدارات الأقدم بـ `github.com` فقط، ولا يكون للمتغيرات أدناه أي تأثير.

</Info>

تتصل المزامنة مع GitHub افتراضيًا بـ `github.com`. لاستخدام GitHub Enterprise Server (المستضاف ذاتيًا) أو GitHub Enterprise Cloud مع موطن البيانات (data residency) (`GHE.com`)، اضبط `GITHUB_SYNC_URL` على عنوان الويب الخاص بنسختك، أي العنوان الذي تفتح به المستودعات في المتصفح.

```dotenv title="config/variables.env" wrap
# GitHub Enterprise Server
GITHUB_SYNC_URL=https://github.example.com

# or GitHub Enterprise Cloud with data residency
# GITHUB_SYNC_URL=https://octocorp.ghe.com
```

تُشتق نقاط نهاية REST وGraphQL API من `GITHUB_SYNC_URL` بالطريقة نفسها التي تتبعها GitHub CLI:

| `GITHUB_SYNC_URL`             | REST API                         | GraphQL API                              |
| ----------------------------- | -------------------------------- | ---------------------------------------- |
| `https://github.com` (افتراضي) | `https://api.github.com`         | `https://api.github.com/graphql`         |
| `https://SUBDOMAIN.ghe.com`   | `https://api.SUBDOMAIN.ghe.com`  | `https://api.SUBDOMAIN.ghe.com/graphql`  |
| `https://HOST` (أي عنوان آخر)    | `https://HOST/api/v3`            | `https://HOST/api/graphql`               |

لا تضبط نقاط نهاية API إلا إذا كانت نسختك تقدّمها في مكان آخر، على سبيل المثال خلف بوابة API:

| المتغير                  | القيمة الافتراضية                                                                                   |
| ------------------------- | ----------------------------------------------------------------------------------------- |
| `GITHUB_SYNC_URL`         | `https://github.com`                                                                      |
| `GITHUB_SYNC_API_URL`     | مُشتق من `GITHUB_SYNC_URL`، راجع الجدول أعلاه                                       |
| `GITHUB_SYNC_GRAPHQL_URL` | مُشتق من `GITHUB_SYNC_API_URL` عند ضبطه (يصبح `/api/v3` هو `/api/graphql`، وإلا يُلحَق `/graphql`)، وإلا فمن `GITHUB_SYNC_URL` |

<Warning>

* أنشئ تطبيق OAuth على نسخة المؤسسة الخاصة بك (_Settings → Developer settings → OAuth Apps_)، فالتطبيق المُنشأ على `github.com` لا يعمل هناك. عنوان URL لاستدعاء OAuth هو نفسه: `${OVERLEAF_SITE_URL}/user/github-sync/oauth2/callback`.
* `GITHUB_SYNC_URL` هو عنوان الويب فقط. لا تضبطه على عنوان API مثل `https://api.github.com` أو `https://HOST/api/v3`، ولا تُضِف مسار مؤسسة (organisation).
* يجب أن تشير العناوين الثلاثة جميعها إلى نسخة GitHub نفسها.

</Warning>

<Info>

إذا كانت نسختك تستخدم شهادة صادرة عن مرجع مصادقة خاص (private CA)، فاربط شهادة CA داخل الحاوية واجعل `NODE_EXTRA_CA_CERTS` يشير إليها، مثل `NODE_EXTRA_CA_CERTS=/var/lib/overleaf/certs/github-ca.pem`.

</Info>

<Danger>

تنتمي الحسابات والمشاريع المرتبطة إلى النسخة التي رُبطت بها. قبل تبديل `GITHUB_SYNC_URL` إلى نسخة أخرى، اطلب من المستخدمين إلغاء ربط حساباتهم ومشاريعهم على GitHub.

</Danger>

### من يمكنه الربط والمزامنة

كما هو الحال في Overleaf Cloud، لا يمكن إلا لمالك المشروع ربط المشروع بمستودع GitHub. وبمجرد ربطه، يمكن لكل متعاون لديه صلاحية التحرير مزامنته.

| الإجراء                                                     | من يمكنه تنفيذه                                                  |
| ---------------------------------------------------------- | -------------------------------------------------------------- |
| تصدير مشروع إلى مستودع GitHub جديد                | مالك المشروع                                              |
| استيراد مستودع GitHub إلى مشروع جديد              | أي مستخدم، ويصبح مالك المشروع الجديد             |
| السحب (pull) والدفع (push) والدمج (merge) لمشروع مرتبط                      | المالك والمتعاونون الذين لديهم صلاحية التحرير                   |
| إلغاء ربط مشروع بمستودعه                       | مالك المشروع                                              |

* يتواصل Overleaf مع GitHub باستخدام حساب GitHub الخاص بالمستخدم الذي يُجري المزامنة، لذا يربط كل متعاون يُجري المزامنة حسابه الخاص على GitHub، ويجب أن يكون مسموحًا له بالدفع إلى الفرع الافتراضي للمستودع.
* لا يمكن للمتعاونين الذين لديهم صلاحية العرض فقط استخدام المزامنة مع GitHub لهذا المشروع.

### أسئلة وأجوبة (Q\&A)

<Accordion title="هل يمكنني إجراء دفع قسري (force push) إلى الفرع الافتراضي؟">

<strong>الإجابة:</strong> لا نوصي بذلك. يكتشف Overleaf الدفع القسري، ويحذّر منه ويتولّى الفرع الذي أُعيدت كتابته، مع دمج التغييرات التي أُجريت في Overleaf منذ آخر مزامنة. لتجنّب المفاجآت، احمِ الفرع الافتراضي من الدفع القسري في إعدادات المستودع.

</Accordion>

<Accordion title="هل يمكنني إعادة تسمية الفرع الافتراضي لمشروع مرتبط؟">

<strong>الإجابة:</strong> يُرجى عدم القيام بذلك. يواصل Overleaf المزامنة مع الفرع الذي رُبط به المشروع. للمزامنة مع فرع آخر، ألغِ ربط المشروع، ثم استورد المستودع إلى مشروع جديد، والذي سيستخدم الفرع الافتراضي الحالي.

</Accordion>

<Accordion title='تعرض المزامنة مع GitHub الرسالة "Something wrong with GitHub request"'>

<strong>الإجابة:</strong> تعني هذه الرسالة أن الخادم لم يتمكن من الوصول إلى GitHub، على سبيل المثال بسبب مشكلة في الشبكة أو DNS أو TLS أو الوكيل. شغّل `bin/logs web` لرؤية الخطأ كاملًا. إذا كان الخادم يحتاج إلى وكيل للوصول إلى GitHub، فاضبط `GITHUB_SYNC_PROXY_URL`.

</Accordion>

<Accordion title='هل يجب أن أعطّل "Expire user access tokens" في تطبيق GitHub OAuth؟'>

<strong>الإجابة:</strong> نعم. لا تجدّد المزامنة مع GitHub الرموز المنتهية الصلاحية. مع تفعيل الرموز المنتهية الصلاحية، سيتعين على المستخدمين ربط GitHub مجددًا في كل مرة تنتهي فيها صلاحية رمزهم.

</Accordion>

<Accordion title="هل يجب أن تكون نسختي قابلة للوصول من الإنترنت؟">

<strong>الإجابة:</strong> لا. يتم ربط الحساب عبر متصفح المستخدم، لذا يكفي أن يُفتح عنوان استدعاء OAuth في متصفح المستخدم. يحتاج الخادم فقط إلى الوصول إلى GitHub؛ وإذا احتاج إلى وكيل لذلك، فاضبط `GITHUB_SYNC_PROXY_URL`. لا يتصل GitHub بنسختك أبدًا: لا يُزامَن المشروع إلا عندما يزامنه المستخدم في المحرر.

</Accordion>
