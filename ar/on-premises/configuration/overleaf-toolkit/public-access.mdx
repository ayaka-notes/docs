يمكنك فتح نسخة Overleaf الخاصة بك للأشخاص الذين لا يملكون حسابًا بثلاث طرق:

* [الوصول إلى المشاريع](/ar/on-premises/configuration/overleaf-toolkit/public-access#project-access  "mention"): السماح للضيوف بفتح رابط مشروع مشترك دون تسجيل الدخول
* [الوصول إلى الصفحات](/ar/on-premises/configuration/overleaf-toolkit/public-access#page-access  "mention"): السماح للزوار غير المسجلين بتصفح صفحات مثل `/learn` و `/templates` و `/devs`
* [التسجيل العام](/ar/on-premises/configuration/overleaf-toolkit/public-access#public-registration  "mention"): السماح للمستخدمين بالتسجيل بأنفسهم، مع إمكانية استخدام رسالة تفعيل عبر البريد الإلكتروني وتقييد ذلك بنطاقات بريد إلكتروني معينة

### الوصول إلى المشاريع

<Info>

افتراضيًا، حتى إذا حصل المستخدم على رابط مشاركة مشروع، فيجب عليه **تسجيل الدخول** قبل أن يتمكن من الانضمام إلى جلسة تحرير تعاونية للمشروع.

</Info>

للسماح بالوصول المجهول إلى المشاريع المشتركة عبر الروابط، اضبط كلا المتغيرين أدناه:

```dotenv title="config/variables.env"
OVERLEAF_ALLOW_ANONYMOUS_READ_AND_WRITE_SHARING=true
OVERLEAF_ALLOW_PUBLIC_ACCESS=true
```

يفعّل `OVERLEAF_ALLOW_ANONYMOUS_READ_AND_WRITE_SHARING` القراءة/الكتابة المجهولة في المشاريع المشتركة عبر الروابط.

يمنع `OVERLEAF_ALLOW_PUBLIC_ACCESS` إعادة توجيه المستخدمين غير المصادق عليهم إلى صفحة تسجيل الدخول.

أعد إنشاء الحاويات باستخدام `bin/up`. ثم افتح رابط مشاركة في نافذة تصفح خاصة.

### الوصول إلى الصفحات

افتراضيًا (عندما لا يكون `OVERLEAF_ALLOW_PUBLIC_ACCESS` مضبوطًا)، تعيد **كل** الصفحات، باستثناء صفحتي تسجيل الدخول والتسجيل، توجيه الزوار غير المسجلين إلى صفحة تسجيل الدخول. ويشمل ذلك الصفحات المقصود أن تكون عامة، لذا لا تعمل الروابط إليها إلا للمستخدمين المسجلين دخولهم بالفعل.

مع `OVERLEAF_ALLOW_PUBLIC_ACCESS=true`، يمكن للزوار غير المسجلين فتح:

| الصفحة                                                                  | المتطلبات                         |
| --------------------------------------------------------------------- | -------------------------------- |
| مساعدة LaTeX على `/learn` (راجع [adding-latex-user-help.md](/ar/on-premises/configuration/overleaf-toolkit/adding-latex-user-help  "mention")) | `OVERLEAF_PROXY_LEARN=true`      |
| معرض القوالب على `/templates`، وصفحات القوالب، ومعايناتها، وتنزيلات ZIP (راجع [templates.md](/ar/on-premises/configuration/overleaf-toolkit/templates  "mention")) | `OVERLEAF_TEMPLATE_GALLERY=true` |
| صفحة Overleaf Import API على `/devs` (راجع [overleaf-import-api.md](/ar/on-premises/configuration/overleaf-toolkit/overleaf-import-api  "mention")) | —                                |

كما يتيح ذلك لـ [Overleaf Import API](/ar/on-premises/configuration/overleaf-toolkit/overleaf-import-api#signed-out-visitors  "mention") الاحتفاظ بنموذج أرسله زائر غير مسجل إلى أن يسجّل دخوله.

لا تزال قائمة المشاريع والمحرر وإنشاء المشاريع (بما في ذلك من قالب أو عبر Import API) تتطلب تسجيل الدخول.

### التسجيل العام

التسجيل العام متاح فقط في [ayaka-notes/ayakaleaf-pro](https://github.com/ayaka-notes/ayakaleaf-pro).

<Danger>

يُرجى ملاحظة أنه بمجرد تفعيل التسجيل العام، يمكن **لأي شخص** لديه إمكانية الوصول إلى نسخة Overleaf الخاصة بك التسجيل كمستخدم.

مع القيمة `true`، لا تتحقق عملية التسجيل من عناوين البريد الإلكتروني، لذا يُرجى استخدامها فقط على شبكة داخلية (إنترانت) أو في بيئة موثوقة، أو استخدم [التسجيل مع رسالة تفعيل عبر البريد الإلكتروني](/ar/on-premises/configuration/overleaf-toolkit/public-access#registration-with-activation-email) بدلًا من ذلك.

على مثيل يستخدم OIDC، لا تستخدم `true`: إذ يمكن لأي شخص التسجيل ببريد زميل إلكتروني قبل أول تسجيل دخول لذلك الزميل عبر OIDC، مما سيربط الزميل بذلك الحساب. استخدم [التسجيل مع رسالة تفعيل عبر البريد الإلكتروني](/ar/on-premises/configuration/overleaf-toolkit/public-access#registration-with-activation-email) أو لا تسمح بالتسجيل العام، راجع [الحسابات وكلمات المرور](/ar/on-premises/configuration/overleaf-toolkit/authentication#accounts-and-passwords).

</Danger>

افتراضيًا، لا يسمح أي من Community Edition أو Overleaf Pro بالتسجيل العام.

لتفعيله، أضف ما يلي إلى `config/variables.env`:

```dotenv title="config/variables.env"
OVERLEAF_ALLOW_PUBLIC_REGISTRATION=true
```

أعد إنشاء الحاويات باستخدام `bin/up`.

ثم انقر على **Sign up** أو زر `/register`.

### التسجيل مع رسالة تفعيل عبر البريد الإلكتروني

التسجيل مع رسالة تفعيل عبر البريد الإلكتروني متاح فقط في [ayaka-notes/ayakaleaf-pro](https://github.com/ayaka-notes/ayakaleaf-pro). يسجّل المستخدمون باستخدام بريدهم الإلكتروني فقط، ويضبطون كلمة المرور عبر الرابط الوارد في رسالة التفعيل، لذا لا يمكن استخدام الحساب إلا لمالك العنوان. تتطلب قائمة النطاقات وأحرف البدل (wildcards) الإصدار v6.4.0 أو أحدث؛ أما الإصدارات السابقة فتقبل نطاقًا واحدًا فقط، مثل `@example.com`.

قبل تفعيل ذلك، قم بإعداد إرسال البريد الإلكتروني، وإلا فلن يتلقى المستخدمون رسالة التفعيل أبدًا. راجع [إرسال البريد الإلكتروني](/ar/on-premises/configuration/overleaf-toolkit/email-delivery).

ثم أضف السطر التالي إلى `config/variables.env`:

```dotenv title="config/variables.env" wrap
OVERLEAF_ALLOW_PUBLIC_REGISTRATION=@example.com,@*.example.org
```

يمكن ضبط `OVERLEAF_ALLOW_PUBLIC_REGISTRATION` على:

| القيمة                         | من يمكنه التسجيل                                       | التحقق من البريد الإلكتروني |
| ----------------------------- | ----------------------------------------------------- | :------------: |
| `true`                        | أي شخص، باستخدام البريد الإلكتروني وكلمة المرور                       |       لا       |
| `@example.com`                | عناوين النطاق `example.com`                             |      نعم       |
| `@*.example.org`              | عناوين النطاقات الفرعية مثل `cs.example.org`، وليس `example.org` نفسه |      نعم       |
| `@example.com,@*.example.org` | أي من الإدخالات المدرجة، مفصولة بفواصل         |      نعم       |
| `@*`                          | أي شخص                                                 |      نعم       |

تُطابَق النطاقات دون تمييز بين الأحرف الكبيرة والصغيرة. للسماح بنطاق ونطاقاته الفرعية، أدرج كليهما: `@example.org,@*.example.org`.

### أسئلة وأجوبة (Q\&A)

<Accordion title="ما الذي يمكن للمحرر غير المسجّل دخوله فعله بالتعليقات؟">

<strong>الإجابة:</strong> يحصل المستخدم غير المسجّل دخوله الذي يفتح مشروعًا عبر رابط التحرير الخاص به على صلاحيات المحرر نفسها، باستثناء الإجراءات التي تسجّل هوية من قام بها:

| الإجراء                                           | محرر غير مسجّل الدخول |
| ------------------------------------------------- | --------------------: |
| تحرير النص، وعرض التعليقات والتغييرات المتتبَّعة  |                   نعم |
| قبول التغييرات المتتبَّعة، وتبديل وضع التحرير     |                   نعم |
| حذف تعليق أو سلسلة كاملة                          |                   نعم |
| إضافة تعليق أو الرد عليه أو تعديله                |                    لا |
| حلّ تعليق أو إعادة فتحه                           |                    لا |

لا تزال لوحة المراجعة تعرض لهم الزر **Resolve**، لكن الحلّ يفشل مع ظهور رسالة خطأ.

أما المستخدمون الذين يفتحون مشروعًا عبر رابط العرض الخاص به فلا يرون أي تعليقات على الإطلاق، راجع [الأدوار والصلاحيات](/ar/on-premises/user-and-project-management/roles-and-permissions#collaborating).

</Accordion>
