## إنشاء مستخدم مسؤول

عمليات النشر باستخدام Overleaf Toolkit:

```bash title="Overleaf Toolkit" wrap
$ bin/docker-compose exec sharelatex /bin/bash -ce "cd /overleaf/services/web && node modules/server-ce-scripts/scripts/create-user --admin --email=joe@example.com"
```

عمليات النشر القديمة باستخدام docker-compose.yml:

```bash title="Legacy docker-compose" wrap
$ docker exec sharelatex /bin/bash -ce "cd /overleaf/services/web && node modules/server-ce-scripts/scripts/create-user --admin --email=joe@example.com"
```

سينشئ الأمر مستخدمًا بعنوان البريد الإلكتروني المحدد إن لم يكن موجودًا بالفعل، وسيجعله مسؤولًا. يتضمن ناتج الأمر رابط URL يمكنك زيارته لتعيين كلمة مرور هذا المستخدم وتسجيل الدخول لأول مرة.

<Info>

لاتباع نهج برمجي، يمكنك استخدام السكربت نفسه لإنشاء مستخدمين عاديين إضافةً إلى المسؤولين. بالنسبة للمستخدمين العاديين، احذف الخيار --admin.

</Info>

إذا كنت تستخدم حسابات داخلية للمصادقة وتحتاج إلى ترقية مستخدم موجود ليصبح مسؤولًا عن النسخة أو إلغاء صلاحيات المسؤول، فقم بما يلي:

<Steps>
<Step title="عبر واجهة الإدارة">
* سجّل الدخول كمسؤول حالي.
* انقر على Admin -> Manage Users.
* ابحث عن المستخدم وانقر على عنوان بريده الإلكتروني.
* مرّر للأسفل إلى قسم Site Admin وانقر على الرابط (show).
* حدّد المربع Is Site Admin.
* انقر على Save للإنهاء.
</Step>
</Steps>

## حذف المستخدمين

يُنصح عمومًا بعدم حذف الحسابات ما لم تعد هناك حاجة إليها. يؤدي حذف حساب إلى إزالته وفقدان المتعاونين إمكانية الوصول إلى المشاريع. لا توجد حاليًا طريقة لتعطيل الحسابات — فإما أن تكون موجودة مع الاحتفاظ ببياناتها أو أن تُحذف.

افتراضيًا، تُحذف الحسابات حذفًا مرنًا (soft-delete). للحصول على معلومات حول إزالة المستخدمين نهائيًا من نسختك، راجع `ENABLE_CRON_RESOURCE_DELETION` في دليل [متغيرات البيئة](/ar/on-premises/configuration/overleaf-toolkit/environment-variables).

<Info>

تُحذف الحسابات حذفًا مرنًا افتراضيًا. راجع `ENABLE_CRON_RESOURCE_DELETION` لمعرفة سلوك الحذف النهائي.

</Info>

### عبر Admin -> Manage Users

<Steps>
<Step title="">
* سجّل الدخول كمسؤول.
* انقر على Admin -> Manage Users.
* ابحث عن المستخدم وحدّد المربع بجوار عنوان بريده الإلكتروني.
* انقر على أيقونة سلة المهملات.
* انقر على Delete للتأكيد.
</Step>
</Steps>

### عبر سطر الأوامر

يمكن حذف حسابات المستخدمين (ومشاريعهم) باستخدام الأوامر التالية.

عمليات النشر باستخدام Overleaf Toolkit:

```bash title="Overleaf Toolkit"
$ bin/docker-compose exec sharelatex /bin/bash -ce "cd /overleaf/services/web && node modules/server-ce-scripts/scripts/delete-user.mjs --email=joe@example.com"
```

عمليات النشر القديمة باستخدام docker-compose.yml:

```bash title="Legacy docker-compose"
$ docker exec sharelatex /bin/bash -ce "cd /overleaf/services/web && node modules/server-ce-scripts/scripts/delete-user.mjs --email=joe@example.com"
```

<Danger>

يستخدم سكربت الحذف خيار فرض (force) مُضمّنًا في الشيفرة يضمن استمرار الحذف حتى لو فشل إرسال رسالة البريد الإلكتروني الخاصة بحذف الحساب (على سبيل المثال، عندما لا يعود بريد المستخدم الإلكتروني في الخدمة).

</Danger>

<Info>

منذ الإصدار 5.5.0، يمكن استخدام الخيار --skip-email لمنع إرسال رسالة بريد إلكتروني إعلامية إلى المستخدم المحذوف.

</Info>

## استعادة مستخدم محذوف حذفًا مرنًا

إذا كان المستخدم قد حُذف حذفًا مرنًا فقط، فيمكنك استعادة حسابه ومشاريعه.

<Steps>
<Step title="">
* سجّل الدخول كمسؤول.
* انقر على Admin -> Manage Users.
* ابحث عن المستخدم الذي تريد استعادته.
* انقر على زر Display deleted users.
* انقر على عنوان البريد الإلكتروني للمستخدم المحذوف.
* انقر على Recover This Account.
* انقر على Recover للتأكيد.
</Step>
</Steps>

<Danger>

عند تعيين ENABLE\_CRON\_RESOURCE\_DELETION إلى true، يمكن استعادة الحسابات المحذوفة حذفًا مرنًا خلال فترة 90 يومًا. بعد 90 يومًا، لا يمكن استعادة الحساب.

</Danger>

## عدّ المستخدمين

يمكنك الحصول على أعداد المستخدمين عبر واجهة الإدارة على https://you-instance-url/admin/user#license. للتحقق والتصدير برمجيًا، قد تفيدك الأمثلة التالية.

العدد الإجمالي للمستخدمين:

```bash title="Total number of users"
echo 'db.users.countDocuments()' | docker exec -i mongo mongosh --quiet localhost/sharelatex
# overleaf [direct: primary] sharelatex> 16
```

العدد الإجمالي للمستخدمين باستخدام نقطة نهاية المقاييس (metrics):

```bash title="Num active users from metrics"
docker exec sharelatex curl http://127.0.0.1:3000/metrics | grep num_active_users
# # HELP num_active_users num_active_users
# # TYPE num_active_users gauge
# num_active_users{app="web-api",host="b3ae4ff549d8"} 16
```

العدد الإجمالي للمستخدمين النشطين (مثال: المستخدمون النشطون خلال آخر 365 يومًا):

```bash title="Total number of active users"
echo 'db.users.countDocuments({ lastActive: { $gte: new Date(new Date().getTime() - (365 * 24 * 60 * 60 * 1000)) } })' | docker exec -i mongo mongosh --quiet localhost/sharelatex
# overleaf [direct: primary] sharelatex> 10
```

## تحديث معلومات حساب المستخدم

تعتمد طريقة تحديث الحسابات على ما إذا كان SSO مفعّلًا.

* إذا لم يكن SSO مستخدمًا:
  * يمكن للمسؤولين تعديل معلومات حساب المستخدم عبر Admin -> Manage Users (البريد الإلكتروني، والاسم الأول، واسم العائلة، وإنشاء رابط لإعادة تعيين كلمة المرور).
  * يمكن للمستخدمين العاديين تحديث بياناتهم الخاصة عبر Account -> Account Settings (بما في ذلك تغيير كلمة المرور وإنشاء رموز مصادقة Git).
* إذا كان SSO مستخدمًا:
  * يمكن تهيئة Server Pro لتحديث الاسم الأول واسم العائلة للمستخدم أثناء تسجيل الدخول بناءً على نظام المصادقة.
  * عندما تكون قيمة OVERLEAF\_SAML\_UPDATE\_USER\_DETAILS\_ON\_LOGIN أو OVERLEAF\_LDAP\_UPDATE\_USER\_DETAILS\_ON\_LOGIN هي true، يتم تعطيل نموذج بيانات المستخدم على https://your-instance-url/user/settings، ولا يمكن تعيين الاسم الأول واسم العائلة إلا في نظام إدارة الهوية لديك.

لمزيد من التفاصيل، راجع:

* إعداد SAML 2.0: https://docs.overleaf.com/on-premises/configuration/overleaf-toolkit/server-pro-only-configuration/saml-2.0
* إعداد LDAP: https://docs.overleaf.com/on-premises/configuration/overleaf-toolkit/server-pro-only-configuration/ldap
