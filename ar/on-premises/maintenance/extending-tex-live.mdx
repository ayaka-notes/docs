يمكن توسيع صورة TeX Live موجودة باستخدام Dockerfile جديد، وإعداد التطبيق لاستخدام الصورة الجديدة.

فيما يلي بعض الإرشادات لتثبيت حزم أو خطوط جديدة.

تتلقى صور TeX Live تحديثات غير متكررة. نقترح إعادة بناء الصور المخصصة عند ترقية Ayakaleaf Pro.

<Danger>

تنطبق الأقسام التالية على [الترجمة المعزولة (Sandboxed Compiles)](/ar/on-premises/configuration/overleaf-toolkit/sandboxed-compiles) فقط.

</Danger>

### تثبيت الحزم الجديدة وتحديثها

يمكنك استخدام أوامر `tlmgr` مثل `tlmgr install` و `tlmgr update` لإدارة حزم TeX Live كما في المثال التالي:

```dockerfile
FROM ghcr.io/ayaka-notes/texlive-full:2023.1

RUN tlmgr update --force ebproof
```

### استخدام `tlmgr` في صورة TeX Live أقدم

افتراضيًا، يقوم `tlmgr` بتنزيل الموارد من أحدث إصدار من TeX Live. عند ترقيع صورة TeX Live أقدم، يجب تحويل التنزيلات إلى الأرشيف المناسب. راجع القائمة في [https://www.tug.org/historic/](https://www.tug.org/historic/) للاطلاع على مرايا الأرشيفات.

```dockerfile
FROM ghcr.io/ayaka-notes/texlive-full:2022.1

RUN tlmgr option repository <MIRROR>/systems/texlive/<YEAR>/tlnet-final
# e.g. RUN tlmgr option repository ftp://tug.org/historic/systems/texlive/2022/tlnet-final

RUN tlmgr update --force ebproof
```

### تثبيت خطوط جديدة

توجد إجراءات مختلفة لتثبيت خطوط جديدة في توزيعة TeX Live، وقد يتطلب تثبيت خط مخصص عدة خطوات. ومن المرجح أن يكون الاطلاع على [تعليمات تثبيت خطوط TeX](https://tug.org/fonts/fontinstall.html) في توثيق TeX Live الرسمي نقطة بداية جيدة.

يوضح الملف `Dockerfile` التالي مثالًا على تثبيت خط TrueType فوق صورة TeX Live 2022 موجودة:

```dockerfile
FROM ghcr.io/ayaka-notes/texlive-full:2022.1

COPY ./myfonts/*.ttf /usr/share/fonts/truetype/myfont/

# rebuild font information cache
RUN fc-cache
```

### إعداد Ayakaleaf Pro لاستخدام الصور الجديدة

استخدم الاسم `ghcr.io/ayaka-notes/texlive-full` ووسمًا (tag) مخصصًا لبناء الصورة الجديدة، كما في:

```bash
docker build -t ghcr.io/ayaka-notes/texlive-full:2023.1-custom .
```

يمكننا الآن إعداد Ayakaleaf Pro لاستخدام الصورة الجديدة `2023.1-custom` عبر تحديث متغيرات البيئة `TEX_LIVE_DOCKER_IMAGE` و `ALL_TEX_LIVE_DOCKER_IMAGES` و `ALL_TEX_LIVE_DOCKER_IMAGE_NAMES` (الأسماء اختيارية وتتبع ترتيب الصور):

```text wrap
TEX_LIVE_DOCKER_IMAGE: "ghcr.io/ayaka-notes/texlive-full:2023.1-custom"
ALL_TEX_LIVE_DOCKER_IMAGES: "ghcr.io/ayaka-notes/texlive-full:2023.1,ghcr.io/ayaka-notes/texlive-full:2023.1-custom"
ALL_TEX_LIVE_DOCKER_IMAGE_NAMES: "TeX Live 2023,TeX Live 2023 custom"
```

في المثال أعلاه، يتم تعيين المشاريع الجديدة افتراضيًا لاستخدام الصورة الجديدة `2023.1-custom`، بينما تظل `2023.1` متاحة عند الحاجة إليها.

الصورة المخصصة موجودة على مضيفك فقط، لذا لا يستطيع `bin/up` سحبها. اضبط `SIBLING_CONTAINERS_PULL=false` في `config/overleaf.rc` (واسحب الصور الأخرى بنفسك باستخدام `docker pull`)، ثم شغّل `bin/up -d` لتطبيق الإعدادات الجديدة.

### أسئلة وأجوبة

<Accordion title="هل أحتاج إلى تثبيت خطوط صينية لترجمة المستندات الصينية باستخدام XeLaTeX؟">

<strong>الإجابة:</strong> لا، ليس مع صور `texlive-full`. فهي تتضمن حزم TeX Live الصينية (`ctex` و`xeCJK`) مع خطوط Fandol، وخطوط Noto CJK (على سبيل المثال `Noto Serif CJK SC`). اضبط مترجم المشروع على XeLaTeX في إعدادات المحرر، ثم ترجم المستند، على سبيل المثال:

```latex
\documentclass{ctexart}
\begin{document}
你好，世界！
\end{document}
```

لاستخدام Noto بدلًا من Fandol، أضف `\setCJKmainfont{Noto Serif CJK SC}`. لا حاجة إلى ملف `latexmkrc`. وبالنسبة إلى الخطوط الأخرى، ابنِ صورة مخصصة كما هو موضح في [تثبيت خطوط جديدة](#تثبيت-خطوط-جديدة).

</Accordion>
