أدرجنا في Server Pro والنسخة المجتمعية (Community Edition) `5.4.0` سكربتًا يتيح للمسؤولين تصدير جميع مشاريع المستخدمين (بما فيها تلك التي لا تزال ظاهرة في مجلدي **Deleted** و**Trashed**) إلى مجلد على القرص.

<Info>

ناتج تشغيل هذا السكربت مطابق لتنزيل ملف Zip لجميع المشاريع يدويًا من لوحة مشاريع المستخدم. ويقوم السكربت بحفظ أي تغييرات معلّقة قبل بدء التنزيل لضمان أن يحتوي التصدير على أحدث إصدار من المشروع.

</Info>

### القيود

لسكربت التصدير القيود التالية:

* لا تُصدَّر أي إعدادات للمشروع، مثل اسم صورة TeX Live أو المترجم. ويجب ضبط هذه الإعدادات عند رفع المشروع إلى حساب المستخدم.
* لا تحتوي المشاريع المصدَّرة على أي سجل للإصدارات.
* لا يُحتفظ بأي معلومات عن المتعاونين. وسيلزم إعادة مشاركة المشاريع. وإذا كنت تستخدم المشاركة عبر الروابط، فستُعاد توليد روابط العرض والتحرير (ولن تكون مطابقة لما كانت عليه سابقًا).
* لن تُصدَّر أي تعليقات أو معلومات عن التغييرات المتعقَّبة.
* لن يُصدَّر سجل محادثات المشروع.

<Danger>

هذا السكربت **غير** مصمم ليحل محل نسخة احتياطية كاملة للنظام. ولضمان قدرتك على استعادة المثيل الخاص بك في سيناريو التعافي من الكوارث، **نوصي بشدة** بأخذ [نسخة احتياطية متسقة](https://docs.overleaf.com/on-premises/maintenance/#performing-a-consistent-backup).

</Danger>

### **الخيارات (Flags)**

| الاسم           | الوصف                                                                     |
| -------------- | ------------------------------------------------------------------------------- |
| `--help`       | عرض المساعدة                                                                       |
| `--user-id`    | معرّف المستخدم (مطلوب ما لم تستخدم `--export-all` أو `--project-id`)            |
| `--project-id` | تصدير مشروع واحد (**لا يمكن** استخدامه مع `--user-id` أو `--export-all`) |
| `--list`       | سرد مشاريع المستخدم (**لا يمكن** استخدامه مع `--output`)                       |
| `--output`     | ملف zip الناتج (لعمليات التصدير المفردة)                                  |
| `--export-all` | تصدير مشاريع جميع المستخدمين (يتطلب `--output-dir`)                            |
| `--output-dir` | المجلد المخصص لتخزين ملفات التصدير لجميع المستخدمين                                   |
| `--log-level`  | مستويات السجل المدعومة: `trace`\|`debug`\|`info`\|`warn`\|`error`\|`fatal`       |

### **الاستخدام**

استخدم الأمر التالي لتصدير مشاريع جميع المستخدمين:

```bash wrap
# Overleaf Toolkit users
$ bin/docker-compose exec sharelatex /bin/bash -ce "cd /overleaf/services/web && node modules/server-ce-scripts/scripts/export-user-projects.mjs --export-all --output-dir=/var/lib/overleaf/data/exports"

# Legacy docker-compose.yml users
docker exec sharelatex /bin/bash -ce "cd /overleaf/services/web && node modules/server-ce-scripts/scripts/export-user-projects.mjs --export-all --output-dir=/var/lib/overleaf/data/exports"
```

<Info>

إذا كنت تشغّل Server Pro أو النسخة المجتمعية بإصدار &lt;= 3.5.13، فستحتاج إلى تحديث المثال أعلاه لاستخدام السكربت **`export-legacy-user-projects.js`**.

</Info>

### **الاكتمال**

بعد اكتمال التصدير، يمكنك الوصول إلى الملفات عبر المجلد على المضيف المربوط (bind-mounted) بالمسار **/var/lib/overleaf** في ملف **docker-compose.yml**، أو عبر متغير البيئة `OVERLEAF_DATA_PATH` في الملف **config/overleaf.rc** إذا كنت تستخدم Toolkit.

<Info>

يسمح Overleaf حاليًا بتكرار أسماء المشاريع. فإذا احتوت مشاريع مستخدم ما على مشروع مكرر الاسم، فستُضاف هذه المشاريع مع ذلك إلى ملف Zip المصدَّر للمستخدم، لكن عند فك الضغط لن يوجد سوى إصدار واحد منها. وفي Linux، سيكتب الأمر `unzip -B` الملفات ذات الأسماء المتطابقة كملفات احتياطية بدلًا من الكتابة فوقها.

</Info>
