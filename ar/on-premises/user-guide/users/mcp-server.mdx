لكل مشروع خادم MCP خاص به، بحيث يستطيع عميل ذكاء اصطناعي على حاسوبك قراءة المشروع وتحريره وتجميعه والرد على تعليقاته. يسجّل العميل الدخول باستخدام رمز مصادقة Git.

<Info>

إذا لم تظهر لك بطاقة **MCP server**، فوجّه المسؤول إلى صفحة [خادم MCP](/ar/on-premises/configuration/overleaf-toolkit/integrations/mcp-server).

</Info>

## الجديد في v6.3.3 {#new-in-v6-3-3}

بدءًا من v6.3.3، يستطيع العميل أيضًا العمل مع سجل المشروع: عرض التغييرات، والمقارنة بين نسختين، وقراءة ملف كما كان، وحفظ النسخ وحذفها، واستعادة ملف أو المشروع بأكمله. ويمكنه عرض التغييرات المتتبَّعة وقبولها أو رفضها، وجعل تعديلاته تغييرات متتبَّعة عندما تطلب منه ذلك. ويمكنه التعليق على جزء من النص وتحرير رسائل التعليقات أو حذفها، وقراءة الرسائل وإرسالها في دردشة المشروع، ونقل الملفات والمجلدات وإعادة تسميتها، وإنشاء المجلدات، وتغيير لغة التدقيق الإملائي. يخضع من يحق له فعل ماذا لدورك في المشروع، كما في المحرر، لأن العميل يعمل برمزك: راجع [من يحق له فعل ماذا](#who-may-do-what).

قُدّم خادم MCP في v6.3.1. تحتوي v6.3.1 وv6.3.2 على الأدوات الـ 17 نفسها، بينما تحتوي v6.3.3 على 33 أداة.

| الأدوات | v6.3.1 وv6.3.2 | v6.3.3 |
| ----- | ----------------- | ------ |
| `get_clone_info`, `get_settings`, `list_files`, `delete_file`, `compile`, `get_compile_log`, `get_output_file_link`, `word_count`, `reply_to_comment`, `resolve_comment`, `reopen_comment` | نعم | نعم، دون تغيير |
| `read_file` | أحدث محتوى | وأيضًا الملف كما كان عند `version` معيّنة |
| `edit_file`, `write_file` | تتبع إعداد تتبّع التغييرات في المشروع | وأيضًا `trackChanges` لجعل التعديل تغييرًا متتبَّعًا |
| `update_settings` | المترجم وصورة TeX Live والمستند الرئيسي | وأيضًا لغة التدقيق الإملائي |
| `list_versions` | النسخة والتعليق والتاريخ | وأيضًا `id` الذي تأخذه `delete_version`، ومن حفظها |
| `list_comments` | رسائل دون id | وأيضًا `id` كل رسالة، الذي تأخذه `edit_comment_message` و`delete_comment_message` |
| `list_changes`, `diff`, `create_version`, `delete_version`, `restore_file`, `restore_project`, `list_tracked_changes`, `accept_tracked_changes`, `reject_tracked_changes`, `add_comment`, `edit_comment_message`, `delete_comment_message`, `list_chat_messages`, `send_chat_message`, `move_file`, `create_folder` | لا | نعم |

## توصيل عميل {#connect-a-client}

<Steps>
<Step title="افتح مربع الحوار">
افتح المشروع. في الشريط الأيسر، انقر على **Integrations** ثم على **MCP server**.

<Frame caption="لوحة Integrations">
  <img src="/images/on-premises/mcp-server-integrations.png" alt="لوحة Integrations مع بطاقة MCP server" />
</Frame>

يعرض مربع الحوار عنوان خادم هذا المشروع وعلامة تبويب لكل عميل: **Claude Code** و**Codex** و**Cursor** و**VS Code** و**Gemini CLI**.

<Frame caption="مربع الحوار MCP server">
  <img src="/images/on-premises/mcp-server-dialog.png" alt="مربع الحوار MCP server مع العنوان وعلامة تبويب لكل عميل والأمر الخاص بـ Claude Code" />
</Frame>
</Step>

<Step title="أنشئ رمزًا">
انقر على **Go to settings**. تُفتح إعدادات حسابك في علامة تبويب جديدة. تحت **Git integration**، انقر على **Generate token**، أو على **Add another token** إذا كان لديك رمز بالفعل. انقر على **Copy** واحتفظ بالرمز في مكان آمن، لأنك لن تراه إلا مرة واحدة. ثم انقر على **Close**.

<Frame caption="رمزك الجديد">
  <img src="/images/on-premises/mcp-server-token.png" alt="مربع الحوار Git authentication token مع زر Copy" />
</Frame>

يعمل أيضًا رمز تستخدمه بالفعل لـ [تكامل Git](/ar/on-premises/user-guide/users/git-integration)، كما يمكن استخدام رمز واحد لجميع مشاريعك.
</Step>

<Step title="أضف الخادم إلى عميلك">
عُد إلى مربع الحوار، وانقر على علامة تبويب عميلك ثم على **Copy** بجوار الإعدادات.

| علامة التبويب | أين توضع | الرمز |
| --- | ------------- | --------- |
| **Claude Code** | شغّل الأمر في الطرفية | استبدل `<token>` في الأمر |
| **Codex** | `~/.codex/config.toml` | ضعه في متغير البيئة `OVERLEAF_TOKEN` |
| **Cursor** | `~/.cursor/mcp.json` | ضعه في متغير البيئة `OVERLEAF_TOKEN` |
| **VS Code** | `.vscode/mcp.json` | يحتوي الملف على مطالبة بكلمة مرور باسم `overleaf-token` بدلًا من الرمز |
| **Gemini CLI** | شغّل الأمر في الطرفية | استبدل `<token>` في الأمر |

العنوان خاص بمشروع واحد. لتوصيل مشروع آخر، أضفه باسم آخر، لأن الاسم `overleaf` مستخدم بالفعل. في Claude Code مثلًا، غيّر `overleaf` في الأمر إلى `overleaf-lab`.
</Step>
</Steps>

## التحقق من الاتصال {#check-the-connection}

### باستخدام Claude Code {#with-claude-code}

```bash
claude mcp list
```

يظهر الخادم على أنه متصل:

```text
overleaf: https://<your-site>/project/<project-id>/mcp (HTTP) - ✔ Connected
```

### باستخدام curl {#with-curl}

تعمل هذه الطريقة مهما كان عميلك. استبدل العنوان والرمز، وأرسل طلب `initialize` الخاص ببروتوكول MCP:

```bash
curl -X POST https://<your-site>/project/<project-id>/mcp \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -H "Accept: application/json, text/event-stream" \
  -d '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2025-06-18","capabilities":{},"clientInfo":{"name":"curl","version":"1.0"}}}'
```

تذكر الاستجابة اسم الخادم، تليه تعليماته للعملاء:

```json
{"result":{"protocolVersion":"2025-06-18","capabilities":{"tools":{"listChanged":true}},"serverInfo":{"name":"overleaf","version":"1.0.0"},"instructions":"This server works on one Overleaf project. ..."},"jsonrpc":"2.0","id":1}
```

لرؤية الأدوات، أرسل `tools/list` بالأمر نفسه. تعرض الاستجابة 33 أداة، أو 31 إذا كانت دردشة المشروع معطّلة في موقعك. قبل v6.3.3 تعرض 17.

```bash
  -d '{"jsonrpc":"2.0","id":2,"method":"tools/list","params":{}}'
```

لاستدعاء أداة، أرسل `tools/call`:

```bash
  -d '{"jsonrpc":"2.0","id":3,"method":"tools/call","params":{"name":"list_files","arguments":{}}}'
```

```json
{"result":{"content":[{"type":"text","text":"[\n  {\n    \"path\": \"main.tex\",\n    \"type\": \"doc\"\n  }\n]"}]},"jsonrpc":"2.0","id":3}
```

### في إعدادات حسابك {#in-your-account-settings}

تحت **Git integration**، يعرض **Last used** التاريخ الخاص برمز تلقّاه الخادم.

<Frame caption="تم استخدام الرمز الأول">
  <img src="/images/on-premises/mcp-server-last-used.png" alt="قائمة الرموز، مع تاريخ تحت Last used للرمز الأول وN/A للرمز الثاني" />
</Frame>

### إذا لم يتصل {#if-it-does-not-connect}

| ما تراه | معناه |
| ------------ | ------------- |
| الحالة `401`، أو في Claude Code ‏`✘ Failed to connect` مع `HTTP 401` | الرمز مفقود أو خاطئ أو محذوف |
| الحالة `404` | لا يوجد مشروع بهذا المعرّف |
| الحالة `405` | لم يكن الطلب من نوع `POST` |
| الحالة `406` مع `Not Acceptable` | الترويسة `Accept` مفقودة: يجب أن يقبل العميل كلًا من `application/json` و`text/event-stream` |

## ما تراه عندما يعمل العميل {#what-you-see-when-a-client-works}

تظهر التعديلات في المحرر المفتوح أثناء قيام العميل بها، مثل تعديلات أي متعاون، دون إعادة تحميل. تظهر الملفات والمجلدات الجديدة وعمليات النقل وإعادة التسمية في شجرة الملفات.

<Frame caption="سطر أضافه edit_file">
  <img src="/images/on-premises/mcp-server-live-edit.png" alt="المحرر يعرض سطرًا أضافه edit_file، دون مربع حوار ودون إعادة تحميل" />
</Frame>

لا يغيّر `edit_file` إلا نصًا يظهر مرة واحدة بالضبط. وإلا يتلقى العميل خطأً، مثل `oldString not found in main.tex, read_file again` أو `oldString appears 2 times in main.tex, add context`، ولا يتغيّر شيء.

بدءًا من v6.3.3، ينقل `move_file` ملفًا أو مجلدًا أو يعيد تسميته، وينشئ مجلدات المسار الجديد عند الحاجة، وينشئ `create_folder` مجلدًا. إذا لم يُعثر على الملف أو كان المسار الجديد موجودًا بالفعل، يتلقى العميل خطأً ولا يتغيّر شيء. يمكن لـ `update_settings` أيضًا تغيير لغة التدقيق الإملائي، مثل `de`، أو إيقاف التدقيق الإملائي.

تظهر الردود على التعليقات في لوحة المراجعة باسمك، لأن الرمز رمزك. يختفي التعليق الذي حُلّ عبر الخادم من اللوحة، وإعادة فتحه تعيده.

<Frame caption="رد أرسله reply_to_comment">
  <img src="/images/on-premises/mcp-server-comment.png" alt="تعليق في لوحة المراجعة مع رد أرسله reply_to_comment" />
</Frame>

بدءًا من v6.3.3، يعلّق `add_comment` على جزء من النص. يجب أن يظهر النص في الملف مرة واحدة بالضبط؛ وعندما يظهر أكثر من مرة، يقدّم العميل أيضًا جزءًا أطول يحيط به ويظهر مرة واحدة، ولا يُعلَّق إلا على النص نفسه. يظهر التعليق في لوحة المراجعة باسمك ويبقى مرتبطًا بنصه عند تغيّر الملف. يغيّر `edit_comment_message` إحدى رسائلك. ويحذف `delete_comment_message` رسالة، وحذف الرسالة الأولى يحذف التعليق كله، كما في لوحة المراجعة.

يجمّع `compile` المشروع ويعيد قائمة ملفات الإخراج. ثم يعطي `get_output_file_link` رابطًا لتنزيل ملف PDF أو ملف إخراج آخر. لا يحتاج الرابط إلى رمز ويتوقف عن العمل بعد 5 دقائق.

للاطلاع على القائمة الكاملة للأدوات، راجع [Tools](/on-premises/configuration/overleaf-toolkit/integrations/mcp-server#tools).

## التغييرات المتتبَّعة {#tracked-changes}

بدءًا من v6.3.3، يمكنك أن تطلب من العميل جعل تعديلاته تغييرات متتبَّعة، مثل *Rewrite the abstract as a tracked change*. عندها يجعل `edit_file` و`write_file` التغيير على ملف موجود تغييرًا متتبَّعًا باسمك، حتى عندما يكون تتبّع التغييرات معطّلًا في المشروع، وتقبله أنت أو ترفضه في لوحة المراجعة. لا يكون الملف الجديد تغييرًا متتبَّعًا أبدًا. إذا لم تطلب ذلك، تتبع التعديلات إعداد تتبّع التغييرات في المشروع، مثل تعديلاتك في المحرر: تُتتبَّع عندما يكون التتبّع مفعّلًا لك أو للجميع.

إذا لم يكن لدى حساب مالك المشروع ميزة تتبّع التغييرات، يتلقى العميل `Track changes is off for this project` ولا يتغيّر شيء.

لمراجعة كل تعديل يجريه العميل، فعّل تتبّع التغييرات لنفسك. ولتمييز تعديلاته عن تعديلاتك في لوحة المراجعة، أعطِ العميل رمز حساب آخر تشاركه المشروع.

يعرض `list_tracked_changes` التغييرات المتتبَّعة مع ملفها والنص المُدرج أو المحذوف والمؤلف والوقت. يأخذ `accept_tracked_changes` و`reject_tracked_changes` معرّفات التغييرات ويعملان مثل لوحة المراجعة: يبقى التغيير المقبول في النص، ويُزال الإدراج المرفوض، ويعود الحذف المرفوض. يعرض المحرر المفتوح النتيجة دون إعادة تحميل. توجّه الأدوات العميل إلى قبول أو رفض التغييرات التي تطلبها فقط.

## السجل {#history}

بدءًا من v6.3.3، يرى العميل سجل المشروع كما تعرضه لوحة السجل.

| الأداة | وظيفتها |
| ---- | ------------ |
| `list_changes` | تعرض التغييرات، الأحدث أولًا: من غيّر أي ملفات ومتى، مع النسخ قبل كل تغيير وبعده. تأتي التغييرات الأقدم في دفعات لاحقة. |
| `diff` | تقارن بين نسختين: ملف واحد بصيغة unified diff مثل `git diff`، أو الملفات التي أُضيفت أو أُزيلت أو حُرّرت أو أُعيدت تسميتها |
| `read_file` مع `version` | تقرأ ملفًا كما كان عند نسخة معيّنة |
| `list_versions` | تعرض النسخ المحفوظة مع تعليقها ومن حفظها |
| `create_version` | تحفظ أحدث نسخة، أو نسخة أقدم، مع تعليق، مثل **Label this version** |
| `delete_version` | تحذف نسخة محفوظة؛ وتبقى تغييراتها |
| `restore_file` | تستعيد ملفًا كما كان عند نسخة معيّنة، مثل **Restore this version** |
| `restore_project` | تستعيد المشروع بأكمله كما كان عند نسخة معيّنة، مثل **Restore project to this version** |

الاستعادة نفسها تغيير جديد، لذا يمكنك التراجع عنها بالطريقة نفسها. توجّه الأدوات العميل إلى الاستعادة فقط عندما تطلب ذلك.

إذا لم يكن لدى مالك المشروع سجل المشروع الكامل، لا يرى العميل إلا تغييرات آخر 24 ساعة، أو أحدث تغيير إذا كانت جميعها أقدم، كما في لوحة السجل. ولا يمكنه مقارنة النسخ الأقدم أو قراءتها أو استعادتها.

## دردشة المشروع {#project-chat}

بدءًا من v6.3.3، يقرأ `list_chat_messages` دردشة المشروع، الأحدث أولًا، 50 رسالة في كل مرة. ويرسل `send_chat_message` رسالة باسمك، فتظهر فورًا في الدردشة المفتوحة. إذا كانت دردشة المشروع معطّلة في موقعك، فلا يملك العميل أيًا من الأداتين.

## من يحق له فعل ماذا {#who-may-do-what}

يمكن للعميل فعل ما يسمح به دورك في المشروع.

| ما يفعله العميل | المالك | المحرّر | المراجع | القارئ (متعاون مُسمّى) | القارئ (مشاركة عبر رابط) |
| -------------------- | ----: | -----: | -------: | --------------------------: | --------------------: |
| قراءة الملفات والإعدادات، والتجميع، وقراءة السجل، وتنزيل PDF | نعم | نعم | نعم | نعم | نعم |
| كتابة الملفات وتحريرها ونقلها وحذفها، وإنشاء المجلدات، وتغيير الإعدادات | نعم | نعم | لا | لا | لا |
| رؤية السجل والتعليقات والتغييرات المتتبَّعة | نعم | نعم | نعم | نعم | لا |
| قراءة رسائل الدردشة وإرسالها | نعم | نعم | نعم | نعم | لا |
| إضافة التعليقات والرد عليها | نعم | نعم | نعم | لا | لا |
| حلّ تعليق أو إعادة فتحه أو حذفه | نعم | نعم | التي بدأها بنفسه | لا | لا |
| تحرير رسالة تعليق | رسائله | رسائله | رسائله | لا | لا |
| حذف رسالة تعليق | نعم | نعم | رسائله | لا | لا |
| قبول التغييرات المتتبَّعة أو رفضها | نعم | نعم | لا | لا | لا |
| حفظ نسخة | نعم | نعم | نعم | لا | لا |
| حذف نسخة محفوظة | نعم | التي حفظها بنفسه | التي حفظها بنفسه | لا | لا |
| استعادة ملف أو المشروع | نعم | نعم | لا | لا | لا |

يُعدّ المحرّرون الذين انضموا عبر رابط محرّرين. لا يستطيع المراجعون تحرير الملفات عبر MCP، ولا حتى كتغييرات متتبَّعة.

## فصل عميل {#disconnect-a-client}

احذف الرمز: راجع [حذف رمز](/ar/on-premises/user-guide/users/git-integration#delete-a-token). منذ ذلك الحين يردّ الخادم بـ `401` على ذلك الرمز. وإذا كنت تستخدمه أيضًا مع Git، يتوقف Git كذلك عن قبوله.
