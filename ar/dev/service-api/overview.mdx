يعمل Overleaf كعدة خدمات يستدعي بعضها بعضًا عبر HTTP داخل شبكة Docker. تصف الصفحات في هذا القسم واجهات البرمجة الداخلية هذه. وهي مأخوذة من ملفات OpenAPI في [`develop/hoppscotch/openapi/`](https://github.com/ayaka-notes/ayakaleaf-pro/tree/server-pro/develop/hoppscotch/openapi)، المكتوبة استنادًا إلى شيفرة كل خدمة.

لا توجد واجهة عامة بين هذه الواجهات: لا يمكن الوصول إليها إلا من داخل شبكة Docker، ومعظمها بلا مصادقة.

## الخدمات {#services}

| الخدمة | العنوان | ما تفعله |
| ------------------------------------------------- | ----------------------------------- | ------------------------------------------------------------------------------------------------ |
| [web](/ar/dev/service-api/web)                                     | `http://web:3000`                   | التطبيق الرئيسي. تستدعي واجهته الخاصة الخدماتُ الأخرى وبرامج cron في الصورة  |
| [document-updater](/ar/dev/service-api/document-updater)           | `http://document-updater:3003`      | تحتفظ بالمستندات المفتوحة في المحرر داخل Redis، وتطبّق التعديلات وتعيد كتابتها إلى Mongo         |
| [docstore](/ar/dev/service-api/docstore)                           | `http://docstore:3016`              | تخزّن كل مستند لكل مشروع في مجموعة Mongo ‏`docs`                                 |
| [real-time](/ar/dev/service-api/real-time)                         | `http://real-time:3026`             | تحتفظ باتصالات socket.io للمحرر وتنقل التعديلات بين المتصفحات والخدمات          |
| [chat](/ar/dev/service-api/chat)                                   | `http://chat:3010`                  | تخزّن محادثة المشروع وسلاسل التعليقات                                                  |
| [project-history](/ar/dev/service-api/project-history)             | `http://project-history:3054`       | تحوّل التعديلات المنتظرة إلى تغييرات في السجل وترسلها إلى history-v1؛ وتحتفظ بالتسميات               |
| [history-v1](/ar/dev/service-api/history-v1)                       | `http://history-v1:3100`            | تخزّن السجل الكامل لكل مشروع ومحتوى الملفات ككائنات blob                           |
| [filestore](/ar/dev/service-api/filestore)                         | `http://filestore:3009`             | تقدّم ملفات القوالب، وللقراءة فقط، كائنات blob التي يكتبها history-v1                           |
| [clsi](/ar/dev/service-api/clsi)                                   | `http://clsi:3013`                  | تترجم المشاريع، وتشغّل SyncTeX وعدّ الكلمات، وتحوّل المستندات                              |
| [notifications](/ar/dev/service-api/notifications)                 | `http://notifications:3042`         | تخزّن الإشعارات المعروضة في قائمة المشاريع                                               |
| [linked-url-proxy](/ar/dev/service-api/linked-url-proxy)           | `http://linked-url-proxy:3066`      | تجلب عناوين URL خارجية لصالح web وترفض العناوين الداخلية                                     |
| [third-party-datastore](/ar/dev/service-api/third-party-datastore) | `http://third-party-datastore:3002` | تزامن المشاريع مع Dropbox عبر طابور مهام واحد لكل مستخدم                                       |

## المصادقة {#authentication}

* <strong>web:</strong> مصادقة HTTP الأساسية باستخدام `WEB_API_USER` و`WEB_API_PASSWORD`. تستخدم مسارات git-bridge رمز وصول شخصيًا بدلًا من ذلك.
* <strong>history-v1:</strong> مصادقة HTTP الأساسية باسم `staging` مع `STAGING_PASSWORD`، أو JWT.
* <strong>جميع الخدمات الأخرى:</strong> لا شيء.

## جرّبها {#try-them}

تشغّل بيئة التطوير [Hoppscotch](https://github.com/hoppscotch/hoppscotch) على `http://localhost:9170`، مع وكيل يصل إلى الخدمات عبر عناوينها في Docker. يوضّح ملف [README](https://github.com/ayaka-notes/ayakaleaf-pro/blob/server-pro/develop/README.md#hoppscotch) الخاص بها كيفية ضبط الوكيل واستيراد ملفات OpenAPI.
