`notifications` تحفظ الإشعارات التي تظهر أعلى لوحة مشاريع المستخدم. كل مستند هو إشعار واحد لمستخدم واحد، ويُعرَّف بقيمة `key`. خدمة `notifications` وحدها تتعامل مع المجموعة (`services/notifications/app/js/Notifications.js`)؛ أما `web` و`third-party-datastore` فيستدعيان واجهة HTTP الخاصة بها. لا يوجد مخطط Mongoose.

| الحقل | النوع | المعنى | المصدر |
| --- | --- | --- | --- |
| `_id` | ObjectId | معرّف الإشعار. يعلّم `web` الإشعار كمقروء بهذا المعرّف. | `Notifications.js:58-65` |
| `user_id` | ObjectId | المستخدم الذي يرى الإشعار. | `Notifications.js:26` |
| `key` | String | يعرّف الإشعار، مثل `project-invite-<inviteId>`. تُبقي عملية upsert مستندًا واحدًا لكل `user_id` و`key`؛ ولا يوجد فهرس فريد. | `Notifications.js:27`, `:51-55` |
| `templateKey` | String | الإشعار الذي تعرضه الواجهة الأمامية. يُزال عند قراءة الإشعار أو تجاهله؛ ويبقى المستند. | `Notifications.js:29`, `:63`, `:72`, `:78` |

#### ملاحظات {#notes}

* الإشعار المقروء لا يُحذف: يختفي `templateKey` فقط. ولأن المستند ما زال يحتفظ بالمفتاح، فإن استدعاء `addNotification` لاحقًا للمفتاح نفسه دون `forceCreate` لا يفعل شيئًا (`Notifications.js:21-24`).
* تعمل مسارات `/key/:key` على المفتاح وحده، عبر جميع المستخدمين (`Notifications.js:76-100`).
* إذا لم يكن لدى `web` القيمة `apis.notifications.url`، فإنه لا ينشئ إشعارات ولا يقرؤها (`NotificationsHandler.mjs:17`، `:41`).
