---
title: مجموعة Gitea Sync User Credentials
icon: lock
---

تحتفظ `giteaSyncUserCredentials` بمستند واحد لكل مستخدم ربط حساب Gitea من أجل Gitea Sync. وهي تخزّن رموز OAuth الخاصة بالمستخدم مشفّرة. تنتمي المجموعة إلى وحدة الويب `gitea-sync` (`services/web/modules/gitea-sync`). المخطط موجود في `services/web/modules/gitea-sync/app/models/giteaSyncUserCredentials.mjs`، وكل وصول يمر عبر `services/web/modules/gitea-sync/app/src/TokenManager.mjs`.

#### الحقول {#fields}

| الحقل | النوع | المعنى | المصدر |
| ----- | ---- | ------- | ------ |
| `_id` | ObjectId | يضبطه Mongoose عندما يُدرج الـ upsert المستند. | |
| `userId` | ObjectId | مستخدم Overleaf. مطلوب. يذكر المخطط `unique: true`، لكن لا يُبنى أي فهرس (انظر الفهارس)؛ ويحافظ الـ upsert حسب `userId` على مستند واحد لكل مستخدم. | `giteaSyncUserCredentials.mjs:8`, `TokenManager.mjs:89-96` |
| `gitea` | String | قيمة JSON `{ accessToken, refreshToken, expiresAt }`، مشفّرة باستخدام `@overleaf/access-token-encryptor`. `expiresAt` بالمللي ثانية منذ بداية الحقبة، أو `null`؛ وقد يكون `refreshToken` مساويًا لـ `null`. تأتي كلمة المرور من `GITEA_TOKEN_CIPHER_PASSWORD`؛ وتسمية التشفير هي `GITEA_TOKEN_CIPHER_LABEL`، والافتراضي `2026.10-v3`. مطلوب. | `giteaSyncUserCredentials.mjs:9-10`, `TokenManager.mjs:17-30`, `services/web/modules/gitea-sync/app/src/GiteaApiClient.mjs:198-209` |
| `__v` | Number | مفتاح الإصدار في Mongoose. لا يعطّله المخطط. | افتراضي في Mongoose |

#### من يكتب فيها {#who-writes-it}

| الشيفرة | ما تفعله |
| ---- | ------------ |
| `TokenManager.mjs:89-96` (`saveUserToken`) | تُجري upsert لبيانات الاعتماد المشفّرة الخاصة بالمستخدم. تُستدعى من رد نداء OAuth (`services/web/modules/gitea-sync/app/src/GiteaSyncController.mjs:146`). على عكس GitLab Sync، لا تؤدي إعادة الربط إلى إلغاء الرمز المستبدَل. |
| `TokenManager.mjs:53-79` (`refreshUserToken`) | عندما يتبقى أقل من 5 دقائق على `expiresAt` لرمز الوصول (`:12`)، تحصل على رموز جديدة باستخدام رمز التحديث وتحفظها (`:76`). تعمل تحت القفل `giteaSyncToken` لكل مستخدم (`:14,54`)، لأن Gitea يستبدل رمز التحديث عند استخدامه. |
| `TokenManager.mjs:100-102` (`removeUserToken`) | تحذف المستند. لا يملك Gitea واجهة برمجية لإلغاء رمز OAuth، لذا يُلغي المستخدم التفويض في Gitea (`:98-99`). تُستدعى عند إلغاء الربط (`GiteaSyncController.mjs:173`) وعندما تنتهي صلاحية مستخدم محذوف (`services/web/modules/gitea-sync/index.mjs:56-58`). |

#### من يقرأ منها {#who-reads-it}

| الشيفرة | ما تفعله |
| ---- | ------------ |
| `TokenManager.mjs:40-44,82-86` (`getUserCredentials`, `getUserToken`) | تفك تشفير بيانات الاعتماد لكل استدعاء لواجهة Gitea البرمجية، وتحدّثها أولًا عندما يكون الرمز على وشك الانتهاء: `services/web/modules/gitea-sync/app/src/GiteaSyncHandler.mjs` (مثل `:27`) و`services/web/modules/gitea-sync/app/src/GitMerge.mjs:52`. عند عدم وجود مستند، أو وجود بيانات اعتماد لا يمكن فك تشفيرها أو تحديثها، ترمي `InvalidTokenError`، ويُعدّ المستخدم غير مرتبط (`GiteaSyncHandler.mjs:25-37`). |
| `services/web/modules/admin-tools/app/src/AdminUserListManager.mjs:395` | تتحقق مما إذا كان لدى المستخدم مستند، من أجل التكاملات المعروضة في لوحة الإدارة. |

#### الفهارس {#indexes}

| الاسم | المفاتيح | الخيارات | الترحيل |
| ---- | ---- | ------- | --------- |
| `_id_` | `_id: 1` | | default |

الخيار `autoIndex` في Mongoose معطّل (`services/web/app/src/infrastructure/Mongoose.mjs:7`)، لذا لا ينشئ `unique: true` في المخطط على `userId` أي شيء. لا يوجد ترحيل ينشئ فهارس لهذه المجموعة.

#### ملاحظات {#notes}

* تغيير `GITEA_TOKEN_CIPHER_PASSWORD` يجعل بيانات الاعتماد المخزّنة غير قابلة للقراءة. ويُعدّ هؤلاء المستخدمون حينها غير مرتبطين حتى يعيدوا الربط.
* يحتفظ المستخدم المحذوف بالمستند حتى تنتهي صلاحيته.
