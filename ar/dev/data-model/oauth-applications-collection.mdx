title: مجموعة OAuth Applications
icon: id-badge
---

تحتوي `oauthApplications` على عملاء OAuth الذين يعرفهم web. كل مستند هو عميل واحد. في Ayakaleaf Pro، الكاتب الوحيد فيها هو وحدة web `git-bridge`، التي تنشئ عميلاً واحداً باسم `Overleaf Git Bridge` عند بدء تشغيل web. المخطط موجود في `services/web/app/src/models/OauthApplication.mjs`.

#### الحقول {#fields}

| الحقل | النوع | المعنى | المصدر |
| ----- | ---- | ------- | ------ |
| `_id` | ObjectId | معرّف مستند العميل. يشير إليه `oauthAccessTokens.oauthApplication_id` و`oauthAuthorizationCodes.oauthApplication_id`. | `OauthApplication.mjs:5` |
| `id` | String | معرّف العميل: 64 حرفاً صغيراً ورقماً عشوائياً. | `OauthApplication.mjs:7`, `services/web/modules/git-bridge/index.mjs:25` |
| `clientSecret` | String | سر العميل، يُكتب على شكل `v1.` متبوعاً بـ 32 حرفاً عشوائياً. لا يقرؤه إلا `getClient`، ولا شيء يستدعي `getClient` (انظر الملاحظات). | `OauthApplication.mjs:8`, `git-bridge/index.mjs:26` |
| `grants` | Array of String | أنواع المنح. لدى عميل git-bridge القيمة `['password']`. تُعاد مع العميل عند التحقق من رمز (`services/web/modules/oauth2-server/app/src/OAuth2Model.mjs:67-72`). | `OauthApplication.mjs:9`, `git-bridge/index.mjs:27` |
| `name` | String | اسم العميل. تجد وحدة git-bridge وشيفرة رموز الوصول الشخصية العميلَ بالاسم `Overleaf Git Bridge`. | `OauthApplication.mjs:10`, `git-bridge/index.mjs:15-16,28` |
| `redirectUris` | Array of String | عناوين URI المسموح بإعادة التوجيه إليها. `[]` لعميل git-bridge. | `OauthApplication.mjs:11`, `git-bridge/index.mjs:29` |
| `scopes` | Array of String | النطاقات التي يحق للعميل استخدامها. `['git_bridge']` لعميل git-bridge. | `OauthApplication.mjs:12`, `git-bridge/index.mjs:30` |
| `pkceEnabled` | Boolean | موجود في المخطط فقط: لا تكتبه أي شيفرة في هذا المستودع، ولا يقرؤه إلا `getClient` غير المستخدم (`OAuth2Model.mjs:207`). | `OauthApplication.mjs:13` |

#### من يكتب فيها {#who-writes-it}

| الشيفرة | ما تفعله |
| ---- | ------------ |
| `git-bridge/index.mjs:9-35` (module `git-bridge`) | عندما تكون قيمة `GIT_BRIDGE_ENABLED` هي `true`، تنشئ العميل `Overleaf Git Bridge` عند بدء تشغيل web إذا لم يوجد عميل بهذا الاسم. |

#### من يقرأ منها {#who-reads-it}

| الشيفرة | ما تفعله |
| ---- | ------------ |
| `services/web/modules/oauth2-server/app/src/OAuthPersonalAccessTokenManager.mjs:53-61` (module `oauth2-server`) | تجد العميل `Overleaf Git Bridge` باسمه وتخزّن `_id` الخاص به في كل رمز وصول شخصي جديد. من دون هذا العميل لا يُنشأ أي رمز. |
| `OAuth2Model.mjs:31-39,67-72` (`getAccessToken`) | تحمّل عميل الرمز عبر `oauthApplication_id` وتعيد `id` و`grants` الخاصين به. |
| `OAuth2Model.mjs:185-209,241,275` (`getClient`, `saveToken`, `saveAuthorizationCode`) | تبحث عن العملاء حسب `id`. لا يُوصل إليها أبداً في هذا المستودع، انظر الملاحظات. |

#### الفهارس {#indexes}

الفهرس الافتراضي على `_id` فقط. يأتي الفهرس الفريد `id_1` من ترحيلات موسومة بـ `saas` (`20190912145016_create_oauthApplications_indexes.mjs`) و`server-pro` (`20230502180757_server_pro_oauth_indexes.mjs`) فقط، ولا يشغّلها Community Edition.

#### ملاحظات {#notes}

* يستخدم web المكتبة `@node-oauth/oauth2-server` للتحقق من رموز bearer فقط (`server.authenticate` في `services/web/app/src/Features/Authentication/AuthenticationController.mjs:409-450`)، وهذا لا يستدعي من النموذج إلا `getAccessToken` و`verifyScope`. لا يوجد مسار يخدم `/oauth/token` أو `/oauth/authorize`، لذا لا تُستدعى `getClient` و`saveToken` و`saveAuthorizationCode` أبداً.
* تبحث الوحدة عن العميل باسمه ثم تنشئه، وليس لدى Community Edition فهرس فريد على `name` أو `id`. لذلك لا شيء يمنع وجود عميل ثانٍ بالاسم نفسه. تأخذ الشيفرة التي تحتاج إلى العميل أيّ عميل يعيده `findOne`.
