---
title: مجموعة GitLab Sync User Credentials
icon: user-lock
---

تحتفظ `gitlabSyncUserCredentials` بمستند واحد لكل مستخدم ربط حساب GitLab من أجل GitLab Sync. وهي تخزّن رموز OAuth الخاصة بالمستخدم مشفّرة. تنتمي المجموعة إلى وحدة الويب `gitlab-sync` (`services/web/modules/gitlab-sync`). المخطط موجود في `services/web/modules/gitlab-sync/app/models/gitlabSyncUserCredentials.mjs`، وكل وصول يمر عبر `services/web/modules/gitlab-sync/app/src/TokenManager.mjs`.

#### الحقول {#fields}

| الحقل | النوع | المعنى | المصدر |
| ----- | ---- | ------- | ------ |
| `_id` | ObjectId | يضبطه Mongoose عندما يُدرج الـ upsert المستند. | |
| `userId` | ObjectId | مستخدم Overleaf. مطلوب. يذكر المخطط `unique: true`، لكن لا يُبنى أي فهرس (انظر الفهارس)؛ ويحافظ الـ upsert حسب `userId` على مستند واحد لكل مستخدم. | `gitlabSyncUserCredentials.mjs:8`, `TokenManager.mjs:88-95` |
| `gitlab` | String | قيمة JSON `{ accessToken, refreshToken, expiresAt }`، مشفّرة باستخدام `@overleaf/access-token-encryptor`. `expiresAt` بالمللي ثانية منذ بداية الحقبة، أو `null`؛ وقد يكون `refreshToken` مساويًا لـ `null`. تأتي كلمة المرور من `GITLAB_TOKEN_CIPHER_PASSWORD`؛ وتسمية التشفير هي `GITLAB_TOKEN_CIPHER_LABEL`، والافتراضي `2026.10-v3`. مطلوب. | `gitlabSyncUserCredentials.mjs:9-10`, `TokenManager.mjs:18-31`, `services/web/modules/gitlab-sync/app/src/GitLabApiClient.mjs:209-220` |
| `__v` | Number | مفتاح الإصدار في Mongoose. لا يعطّله المخطط. | افتراضي في Mongoose |

#### من يكتب فيها {#who-writes-it}

| الشيفرة | ما تفعله |
| ---- | ------------ |
| `TokenManager.mjs:88-95` (`saveUserToken`) | تُجري upsert لبيانات الاعتماد المشفّرة الخاصة بالمستخدم. |
| `TokenManager.mjs:99-108` (`linkUserToken`) | تحفظ بيانات الاعتماد الجديدة القادمة من رد نداء OAuth (`services/web/modules/gitlab-sync/app/src/GitLabSyncController.mjs:146`). عندما يعيد المستخدم الربط، يُلغى رمز الوصول المستبدَل لدى GitLab في الخلفية. |
| `TokenManager.mjs:53-78` (`refreshUserToken`) | عندما يتبقى أقل من 5 دقائق على `expiresAt` لرمز الوصول (`:13,47-49`)، تحصل على رموز جديدة باستخدام رمز التحديث وتحفظها (`:75`). تعمل تحت القفل `gitlabSyncToken` لكل مستخدم (`:15,54`)، لأن GitLab يستهلك رمز التحديث عند استخدامه. |
| `TokenManager.mjs:111-126` (`removeUserToken`) | تُلغي رمز الوصول لدى GitLab (بأفضل جهد)، ثم تحذف المستند. تُستدعى عند إلغاء الربط (`GitLabSyncController.mjs:173`) وعندما تنتهي صلاحية مستخدم محذوف (`services/web/modules/gitlab-sync/index.mjs:56-58`). |

#### من يقرأ منها {#who-reads-it}

| الشيفرة | ما تفعله |
| ---- | ------------ |
| `TokenManager.mjs:41-45,81-85` (`getUserCredentials`, `getUserToken`) | تفك تشفير بيانات الاعتماد لكل استدعاء لواجهة GitLab البرمجية، وتحدّثها أولًا عندما يكون الرمز على وشك الانتهاء: `services/web/modules/gitlab-sync/app/src/GitLabSyncHandler.mjs` (مثل `:27`) و`services/web/modules/gitlab-sync/app/src/GitMerge.mjs:52`. عند عدم وجود مستند، أو وجود بيانات اعتماد لا يمكن فك تشفيرها أو تحديثها، ترمي `InvalidTokenError`، ويُعدّ المستخدم غير مرتبط (`GitLabSyncHandler.mjs:25-37`). |
| `services/web/modules/admin-tools/app/src/AdminUserListManager.mjs:394` | تتحقق مما إذا كان لدى المستخدم مستند، من أجل التكاملات المعروضة في لوحة الإدارة. |

#### الفهارس {#indexes}

| الاسم | المفاتيح | الخيارات | الترحيل |
| ---- | ---- | ------- | --------- |
| `_id_` | `_id: 1` | | default |

الخيار `autoIndex` في Mongoose معطّل (`services/web/app/src/infrastructure/Mongoose.mjs:7`)، لذا لا ينشئ `unique: true` في المخطط على `userId` أي شيء. لا يوجد ترحيل ينشئ فهارس لهذه المجموعة.

#### ملاحظات {#notes}

* تغيير `GITLAB_TOKEN_CIPHER_PASSWORD` يجعل بيانات الاعتماد المخزّنة غير قابلة للقراءة. ويُعدّ هؤلاء المستخدمون حينها غير مرتبطين حتى يعيدوا الربط.
* يحتفظ المستخدم المحذوف بالمستند حتى تنتهي صلاحيته.
