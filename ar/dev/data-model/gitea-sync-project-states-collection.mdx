تحتفظ `giteaSyncProjectStates` بمستند واحد لكل مشروع مرتبط بمستودع Gitea: أي مستودع هو، وأين توقفت آخر مزامنة. تنتمي المجموعة إلى وحدة الويب `gitea-sync` (`services/web/modules/gitea-sync`). المخطط موجود في `services/web/modules/gitea-sync/app/models/giteaSyncProjectStates.mjs`، وكل وصول يمر عبر `services/web/modules/gitea-sync/app/src/SyncStateManager.mjs`. الحقول هي نفسها كما في [GitHub Sync Project States](/ar/dev/data-model/github-sync-project-states-collection).

| `_id` | ObjectId | يضبطه Mongoose عند الإنشاء. | |
| `projectId` | ObjectId | المشروع المرتبط. مطلوب. يذكر المخطط `unique: true`، لكن لا يُبنى أي فهرس (انظر الفهارس). | `giteaSyncProjectStates.mjs:8` |
| `repoFullName` | String | المستودع بصيغة `owner/name` (قيمة `full_name` في Gitea). مطلوب. | `giteaSyncProjectStates.mjs:9`, `GiteaApiClient.mjs:315` |
| `defaultBranchName` | String | الفرع الذي يُزامَن معه المشروع. يُضبط عند ربط المشروع ولا يتغير بعد ذلك: عند الاستيراد هو الفرع الذي يرسله نموذج الاستيراد؛ وعند التصدير هو الفرع الافتراضي للمستودع الجديد، أو `main` إذا لم تُرجع الواجهة البرمجية أي فرع. الافتراضي `null`. | `giteaSyncProjectStates.mjs:10`, `GiteaSyncHandler.mjs:175-181,233-239`, `GiteaApiClient.mjs:314-317` |

#### من يكتب فيها {#who-writes-it}

| الشيفرة | ما تفعله |
| ---- | ------------ |
| `SyncStateManager.mjs:9-14` (`createProjectState`) | تنشئ المستند: بعد استيراد مستودع كمشروع جديد (`services/web/modules/gitea-sync/app/src/GiteaSyncHandler.mjs:175-181`)، أو بعد تصدير مشروع إلى مستودع جديد (`GiteaSyncHandler.mjs:233-239`، للمالك فقط، ويُرفض إذا كان مرتبطًا بالفعل). |
| `SyncStateManager.mjs:16-21` (`updateProjectState`) | `$set` للحقول المتغيرة. تضبط `getMergeOverview` القيمة `mergeStatus: 'diverged'` عندما لا يعود `lastSyncCommit` سلفًا للفرع المُزامَن (`services/web/modules/gitea-sync/app/src/GiteaApiClient.mjs:431`)، أو يكون الإيداع قد اختفى ويستطيع المستخدم الدفع (`GiteaSyncHandler.mjs:123,126-137`). عند نجاح المزامنة (`services/web/modules/gitea-sync/app/src/GitMerge.mjs`) تُحرّك `lastSyncCommit`/`lastSyncVersion` (مثل `:152,189,231`)، وتسجّل التعارض في `unmergedBranchName` و`unmergedBranchHead` و`conflictVersion` (`:214-220`)، وتمسحها بعد حلّه (`:257-264`). |
| `SyncStateManager.mjs:23-25` (`removeProjectState`) | تحذف المستند عندما يلغي المالك ربط المشروع (`GiteaSyncHandler.mjs:83-97`) وعندما تنتهي صلاحية مشروع محذوف (`services/web/modules/gitea-sync/index.mjs:46-48`). |

#### الفهارس {#indexes}

| الاسم | المفاتيح | الخيارات | الترحيل |
| ---- | ---- | ------- | --------- |
| `_id_` | `_id: 1` | | default |

الخيار `autoIndex` في Mongoose معطّل (`services/web/app/src/infrastructure/Mongoose.mjs:7`)، لذا لا ينشئ `unique: true` في المخطط على `projectId` أي شيء. لا يوجد ترحيل ينشئ فهارس لهذه المجموعة.

#### ملاحظات {#notes}

* لا تستطيع الواجهة البرمجية لـ Gitea إنشاء إيداعات خارج فرع كما تستطيع واجهة GitHub. تودع المزامنة مباشرة على الفرع المُزامَن عندما يمكنها التقدم، وإلا فعلى فرع مؤقت يُدمج بعد ذلك عبر pull request (`GitMerge.mjs:16-21`).
* تعمل المزامنة تحت قفل `gitSync` الخاص بالمشروع، وهو مشترك مع GitHub Sync وGitLab Sync (`GitMerge.mjs:25-32`).
* يحتفظ المشروع المحذوف بمستنده حتى تنتهي صلاحيته.
* رمز Gitea الخاص بالمستخدم موجود في [Gitea Sync User Credentials](/ar/dev/data-model/gitea-sync-user-credentials-collection).
