في هذا القسم، سنناقش نموذج بيانات Overleaf. يستخدم Overleaf قاعدة بيانات MongoDB لتخزين البيانات بشكل دائم، واسم قاعدة البيانات الوحيدة هو `sharelatex`، وهو أيضًا اسم المشروع الذي سبق Overleaf.

تشغّل بيئة التطوير بالفعل Mongo Express إلى جانب Mongo (راجع [setup-develop-tools.md](/ar/dev/environment/setup-develop-tools  "mention")). افتح [http://localhost:8081/](http://localhost:8081/) وسجّل الدخول باستخدام `admin:pass`.

يمكنك أيضًا فتح صدفة (shell) في حاوية Mongo من المجلد `develop`:

```bash
bin/docker-compose exec mongo mongosh sharelatex
```

#### كيف كُتبت الصفحات {#how-the-pages-are-written}

* تسرد كل صفحة الحقول التي تكتبها الشيفرة، مع نوعها ومعناها وسطر الشيفرة الذي يوضح ذلك: سطر من مخطط Mongoose، أو الموضع الذي يكتب الحقل. الحقول التي لا يكتبها إلا ترحيل أو سكربت أو إحدى وحدات web تذكر ذلك.
* لا يوجد مخطط Mongoose لكثير من المجموعات: تكتبها الخدمات باستخدام برنامج تشغيل MongoDB.
* لا تُنشئ الفهارس إلا عمليات الترحيل في `tools/migrations/`. يشغّل CE تلك التي تحمل الوسم `server-ce` عند كل بدء تشغيل (`server-ce/init_scripts/900_run_web_migrations.sh`)؛ و`autoIndex` في Mongoose معطّل (`services/web/app/src/infrastructure/Mongoose.mjs:7`). لا تسرد جداول الفهارس إلا ما ينتهي إليه مثيل CE.
* نص docs موجود في Mongo، لكن المحتوى الآخر ليس كذلك. يُخزَّن محتوى الملفات على هيئة blobs والسجل التاريخي على هيئة أجزاء (chunks) في حاويات history-v1 (مجلدات محلية، أو S3 / RustFS)؛ وتبقى docs المفتوحة في Redis حتى يُجري لها document-updater عملية flush.
