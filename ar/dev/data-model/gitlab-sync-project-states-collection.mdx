title: مجموعة GitLab Sync Project States
icon: code-merge
---

تحتفظ `gitlabSyncProjectStates` بمستند واحد لكل مشروع مرتبط بمشروع GitLab: أي مستودع هو، وأين توقفت آخر مزامنة. تنتمي المجموعة إلى وحدة الويب `gitlab-sync` (`services/web/modules/gitlab-sync`). المخطط موجود في `services/web/modules/gitlab-sync/app/models/gitlabSyncProjectStates.mjs`، وكل وصول يمر عبر `services/web/modules/gitlab-sync/app/src/SyncStateManager.mjs`. الحقول هي نفسها كما في [GitHub Sync Project States](/ar/dev/data-model/github-sync-project-states-collection).

#### الحقول {#fields}

| الحقل | النوع | المعنى | المصدر |
| ----- | ---- | ------- | ------ |
| `_id` | ObjectId | يضبطه Mongoose عند الإنشاء. | |
| `projectId` | ObjectId | المشروع المرتبط. مطلوب. يذكر المخطط `unique: true`، لكن لا يُبنى أي فهرس (انظر الفهارس). | `gitlabSyncProjectStates.mjs:8` |
| `repoFullName` | String | مسار مشروع GitLab مع مساحة الأسماء (قيمة `path_with_namespace` في GitLab)، مثل `group/subgroup/name`. مطلوب. | `gitlabSyncProjectStates.mjs:9`, `GitLabApiClient.mjs:347` |
| `defaultBranchName` | String | الفرع الذي يُزامَن معه المشروع. يُضبط عند ربط المشروع ولا يتغير بعد ذلك: عند الاستيراد هو الفرع الذي يرسله نموذج الاستيراد؛ وعند التصدير هو الفرع الافتراضي للمستودع الجديد، أو `main` إذا لم تُرجع الواجهة البرمجية أي فرع. الافتراضي `null`. | `gitlabSyncProjectStates.mjs:10`, `GitLabSyncHandler.mjs:175-181,234-240`, `GitLabApiClient.mjs:346-349` |
| `mergeStatus` | String | `clean` أو `conflict` أو `diverged`. الافتراضي `clean`. | `gitlabSyncProjectStates.mjs:11` |
| `lastSyncCommit` | String | قيمة SHA للإيداع على الفرع المُزامَن عند آخر مزامنة. الافتراضي `null`. | `gitlabSyncProjectStates.mjs:12` |
| `lastSyncVersion` | Number | إصدار سجل المشروع عند آخر مزامنة، من `GET /project/:id/version` في project-history، ويُقرأ بعد تفريغ السجل. الافتراضي `null`. | `gitlabSyncProjectStates.mjs:13`, `services/web/modules/gitlab-sync/app/src/HistoryManager.mjs:8-17` |

| `unmergedBranchHead` | String | أثناء التعارض: الإيداع الرأسي لذلك الفرع. الافتراضي `null`. | `gitlabSyncProjectStates.mjs:15` |
| `conflictVersion` | Number | أثناء التعارض: إصدار سجل المشروع عند تسجيل التعارض. الافتراضي `null`. | `gitlabSyncProjectStates.mjs:16` |
| `__v` | Number | مفتاح الإصدار في Mongoose. لا يعطّله المخطط. | افتراضي في Mongoose |

#### من يكتب فيها {#who-writes-it}

| الشيفرة | ما تفعله |
| ---- | ------------ |
| `SyncStateManager.mjs:9-14` (`createProjectState`) | تنشئ المستند: بعد استيراد مستودع كمشروع جديد (`services/web/modules/gitlab-sync/app/src/GitLabSyncHandler.mjs:175-181`)، أو بعد تصدير مشروع إلى مستودع جديد (`GitLabSyncHandler.mjs:234-240`، للمالك فقط، ويُرفض إذا كان مرتبطًا بالفعل). |
| `SyncStateManager.mjs:16-21` (`updateProjectState`) | `$set` للحقول المتغيرة. تضبط `getMergeOverview` القيمة `mergeStatus: 'diverged'` عندما لا يعود الفرع المُزامَن يحتوي `lastSyncCommit` (فحص merge base، `services/web/modules/gitlab-sync/app/src/GitLabApiClient.mjs:460`)، أو يكون الإيداع قد اختفى ويستطيع المستخدم الدفع (`GitLabSyncHandler.mjs:123,126-137`). عند نجاح المزامنة (`services/web/modules/gitlab-sync/app/src/GitMerge.mjs`) تُحرّك `lastSyncCommit`/`lastSyncVersion` (مثل `:152,189,231`)، وتسجّل التعارض في `unmergedBranchName` و`unmergedBranchHead` و`conflictVersion` (`:214-220`)، وتمسحها بعد حلّه (`:257-264`). |
| `SyncStateManager.mjs:23-25` (`removeProjectState`) | تحذف المستند عندما يلغي المالك ربط المشروع (`GitLabSyncHandler.mjs:83-97`) وعندما تنتهي صلاحية مشروع محذوف (`services/web/modules/gitlab-sync/index.mjs:46-48`). |

#### من يقرأ منها {#who-reads-it}

| الشيفرة | ما تفعله |
| ---- | ------------ |
| `GitLabSyncHandler.mjs:39-60` (`getProjectState`) | تعطي المحرر `mergeStatus` و`repoFullName` و`unmergedBranchName`. عند عدم وجود مستند تُجيب بـ `need-export`، وهي قيمة لا تُخزَّن أبدًا. |
| `GitLabSyncHandler.mjs:110-143` (`getMergeOverview`) | تقارن `lastSyncCommit` و`lastSyncVersion` مع GitLab وسجل المشروع لسرد الإيداعات الجديدة. |
| `GitLabSyncHandler.mjs:200` (`exportProject`) | ترفض تصدير مشروع مرتبط بالفعل. |
| `GitMerge.mjs:36` (`doGitMergeWithoutLock`) | تحمّل الحالة في بداية المزامنة. |

#### الفهارس {#indexes}

| الاسم | المفاتيح | الخيارات | الترحيل |
| ---- | ---- | ------- | --------- |
| `_id_` | `_id: 1` | | default |

الخيار `autoIndex` في Mongoose معطّل (`services/web/app/src/infrastructure/Mongoose.mjs:7`)، لذا لا ينشئ `unique: true` في المخطط على `projectId` أي شيء. لا يوجد ترحيل ينشئ فهارس لهذه المجموعة.

#### ملاحظات {#notes}

* لا تستطيع الواجهة البرمجية لـ GitLab نقل فرع إلى أي إيداع كما تستطيع واجهة GitHub. تودع المزامنة مباشرة على الفرع المُزامَن عندما يمكنها التقدم، وإلا فعلى فرع مؤقت يُدمج بعد ذلك عبر merge request (`GitMerge.mjs:16-21`).
* تعمل المزامنة تحت قفل `gitSync` الخاص بالمشروع، وهو مشترك مع GitHub Sync وGitea Sync (`GitMerge.mjs:25-32`).
* يحتفظ المشروع المحذوف بمستنده حتى تنتهي صلاحيته.
* رمز GitLab الخاص بالمستخدم موجود في [GitLab Sync User Credentials](/ar/dev/data-model/gitlab-sync-user-credentials-collection).
