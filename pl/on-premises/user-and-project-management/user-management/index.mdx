## Tworzenie użytkownika z uprawnieniami administratora {#creating-an-administrator-user}

Wdrożenia z użyciem Overleaf Toolkit:

```bash title="Overleaf Toolkit" wrap
$ bin/docker-compose exec sharelatex /bin/bash -ce "cd /overleaf/services/web && node modules/server-ce-scripts/scripts/create-user --admin --email=joe@example.com"
```

Starsze wdrożenia oparte na docker-compose.yml:

```bash title="Legacy docker-compose" wrap
$ docker exec sharelatex /bin/bash -ce "cd /overleaf/services/web && node modules/server-ce-scripts/scripts/create-user --admin --email=joe@example.com"
```

Polecenie utworzy użytkownika o podanym adresie e-mail, jeśli jeszcze nie istnieje, i nada mu uprawnienia administratora. Wynik polecenia zawiera adres URL, pod którym można ustawić hasło tego użytkownika i zalogować się po raz pierwszy.

<Info>

W podejściu programistycznym możesz używać tego samego skryptu do tworzenia zarówno zwykłych użytkowników, jak i administratorów. W przypadku zwykłych użytkowników pomiń flagę --admin.

</Info>

Jeśli do uwierzytelniania używasz kont wewnętrznych i chcesz nadać istniejącemu użytkownikowi uprawnienia administratora instancji lub je odebrać, wykonaj następujące czynności:

<Steps>
<Step title="Za pomocą interfejsu administratora">
* Zaloguj się jako istniejący administrator.
* Kliknij Admin -> Manage Users.
* Wyszukaj użytkownika i kliknij jego nazwę.
* Kliknij ikonę ołówka.
* Włącz lub wyłącz Admin.
* Kliknij Save, aby zakończyć.
</Step>
</Steps>

## Usuwanie użytkowników {#deleting-users}

Zasadniczo nie zaleca się usuwania kont, chyba że nie są już potrzebne. Usunięcie konta usuwa konto i powoduje, że współpracownicy tracą dostęp do projektów. Aby uniemożliwić użytkownikowi logowanie i zachować jego dane, [wyłącz konto](/on-premises/user-guide/administrators/user-management#disable-or-enable-an-account).

Domyślnie konta są usuwane w sposób miękki (soft delete). Informacje o trwałym usuwaniu użytkowników z instancji znajdziesz w opisie `ENABLE_CRON_RESOURCE_DELETION` w przewodniku [Zmienne środowiskowe](/pl/on-premises/configuration/overleaf-toolkit/environment-variables).

<Info>

Domyślnie konta są usuwane w sposób miękki. Zachowanie trwałego usuwania opisuje `ENABLE_CRON_RESOURCE_DELETION`.

</Info>

### Za pomocą Admin -> Manage Users {#via-admin->-manage-users}

<Steps>
<Step title="">
* Zaloguj się jako administrator.
* Kliknij Admin -> Manage Users.
* Wyszukaj użytkownika i zaznacz pole obok jego nazwy.
* Kliknij ikonę kosza.
* Kliknij Delete account, aby potwierdzić.
</Step>
</Steps>

### Za pomocą wiersza poleceń {#via-the-command-line}

Konta użytkowników (wraz z ich projektami) można usunąć za pomocą następujących poleceń.

Wdrożenia z użyciem Overleaf Toolkit:

```bash title="Overleaf Toolkit"
$ bin/docker-compose exec sharelatex /bin/bash -ce "cd /overleaf/services/web && node modules/server-ce-scripts/scripts/delete-user.mjs --email=joe@example.com"
```

Starsze wdrożenia oparte na docker-compose.yml:

```bash title="Legacy docker-compose"
$ docker exec sharelatex /bin/bash -ce "cd /overleaf/services/web && node modules/server-ce-scripts/scripts/delete-user.mjs --email=joe@example.com"
```

<Danger>

Skrypt usuwania używa na stałe wpisanej opcji wymuszenia, która gwarantuje, że usunięcie zostanie przeprowadzone nawet wtedy, gdy nie uda się wysłać wiadomości e-mail o usunięciu konta (np. gdy adres e-mail użytkownika nie jest już aktywny).

</Danger>

<Info>

Można użyć opcji --skip-email, aby nie wysyłać do usuniętego użytkownika wiadomości informacyjnej.

</Info>

## Przywracanie użytkownika usuniętego w sposób miękki {#restoring-a-soft-deleted-user}

Jeśli użytkownik został usunięty tylko miękko, możesz przywrócić jego konto i projekty usunięte razem z nim. Projekty, które użytkownik sam usunął, pozostają usunięte.

<Steps>
<Step title="">
* Zaloguj się jako administrator.
* Kliknij Admin -> Manage Users.
* Wyszukaj użytkownika, którego chcesz przywrócić.
* Kliknij Display deleted users.
* Kliknij ikonę strzałki w wierszu użytkownika.
* Kliknij Restore, aby potwierdzić.
</Step>
</Steps>

<Danger>

Gdy ENABLE\_CRON\_RESOURCE\_DELETION ma wartość true, konta usunięte w sposób miękki można przywrócić w ciągu 90 dni. Po upływie 90 dni odzyskanie konta nie jest możliwe.

</Danger>

## Zliczanie użytkowników {#counting-users}

Liczbę użytkowników można sprawdzić w interfejsie administratora pod adresem https://you-instance-url/admin/user#license. Przy sprawdzaniu i eksportowaniu programistycznym pomocne mogą być poniższe przykłady.

Całkowita liczba użytkowników:

```bash title="Total number of users"
echo 'db.users.countDocuments()' | docker exec -i mongo mongosh --quiet localhost/sharelatex
# overleaf [direct: primary] sharelatex> 16
```

Całkowita liczba użytkowników z użyciem punktu końcowego metryk:

```bash title="Num active users from metrics"
docker exec sharelatex curl http://127.0.0.1:3000/metrics | grep num_active_users
# # HELP num_active_users num_active_users
# # TYPE num_active_users gauge
# num_active_users{app="web-api",host="b3ae4ff549d8"} 16
```

Całkowita liczba aktywnych użytkowników (przykład: użytkownicy aktywni w ciągu ostatnich 365 dni):

```bash title="Total number of active users"
echo 'db.users.countDocuments({ lastActive: { $gte: new Date(new Date().getTime() - (365 * 24 * 60 * 60 * 1000)) } })' | docker exec -i mongo mongosh --quiet localhost/sharelatex
# overleaf [direct: primary] sharelatex> 10
```

## Aktualizacja informacji o koncie użytkownika {#updating-user-account-information}

Sposób aktualizacji kont zależy od tego, czy włączone jest SSO.

* Jeśli SSO nie jest używane:
  * Administratorzy mogą modyfikować informacje o koncie użytkownika w Admin -> Manage Users (adres e-mail, imię, nazwisko oraz generowanie linku do resetowania hasła).
  * Zwykli użytkownicy mogą aktualizować własne dane w Account -> Account Settings (w tym zmieniać hasło i generować tokeny uwierzytelniania Git).
* Jeśli SSO jest używane:
  * Ayakaleaf Pro można skonfigurować tak, aby podczas logowania aktualizował imię i nazwisko użytkownika na podstawie systemu uwierzytelniania.
  * Gdy OVERLEAF\_SAML\_UPDATE\_USER\_DETAILS\_ON\_LOGIN lub OVERLEAF\_LDAP\_UPDATE\_USER\_DETAILS\_ON\_LOGIN mają wartość true, formularz danych użytkownika na stronie https://your-instance-url/user/settings jest wyłączony, a imię i nazwisko można ustawić wyłącznie w systemie zarządzania tożsamością.

Więcej szczegółów:

* [Konfiguracja SAML 2.0](/pl/on-premises/configuration/overleaf-toolkit/authentication/saml-authentication)
* [Konfiguracja LDAP](/pl/on-premises/configuration/overleaf-toolkit/authentication/ldap-authentication)

### Pytania i odpowiedzi {#q&a}

<Accordion title="Czy mogę utworzyć użytkowników SSO z wyprzedzeniem, na przykład za pomocą API?">

<strong>Odpowiedź:</strong> Nie ma do tego API HTTP. Utwórz konto skryptem `create-user` opisanym powyżej (bez `--admin`) lub w **Admin → Manage Users** przyciskiem **Create account**. Gdy ustawiono `EXTERNAL_AUTH`, formularz ma opcję **Log in with SSO**, która tworzy konto bez lokalnego hasła i bez wiadomości ani linku aktywacyjnego: okno dialogowe zamyka się po **Create**. Przy pierwszym logowaniu LDAP, SAML lub OIDC użytkownik otrzymuje istniejące konto z tym samym adresem e-mail zamiast nowego, zobacz [Konta i hasła](/pl/on-premises/configuration/overleaf-toolkit/authentication#accounts-and-passwords).

</Accordion>

<Accordion title="Czy mogę wyeksportować listę użytkowników i przywrócić ją później?">

<strong>Odpowiedź:</strong> Nie. Nie ma eksportu ani importu kont użytkowników, ani w **Admin → Manage Users**, ani w postaci skryptu. Konta są przechowywane w MongoDB, więc twórz ich kopie zapasowe i przywracaj je za pomocą [kopii zapasowej MongoDB](/pl/on-premises/maintenance/data-and-backups#mongodb). Skrypt `export-user-projects.mjs` eksportuje projekty użytkowników jako pliki zip, a nie konta, zobacz [Eksportowanie projektów](/pl/on-premises/maintenance/data-and-backups/exporting-projects).

</Accordion>

<Accordion title="Jak długo jest ważny link z `create-user` i jak zresetować hasło bez poczty e-mail?">

<strong>Odpowiedź:</strong> Link wypisywany przez `create-user` jest ważny przez 7 dni i działa bez SMTP, ponieważ kopiujesz go z wyjścia polecenia. Aby uzyskać nowy link, uruchom `create-user` ponownie z tym samym adresem e-mail. Dla istniejącego konta polecenie tylko wypisuje nowy link, ale ustawia też flagę administratora konta zgodnie z `--admin`, więc zachowaj `--admin`, gdy uruchamiasz je dla administratora.

Administrator może też uzyskać link resetujący bez poczty e-mail: w **Admin → Manage Users** kliknij ikonę kłódki w wierszu użytkownika, potem **Send reset link**, i skopiuj link z okna dialogowego. Jest ważny przez 1 godzinę, zobacz [Wysyłanie linku aktywacyjnego lub resetującego](/on-premises/user-guide/administrators/user-management#send-an-activation-or-reset-link).

Możesz też ustawić hasło bezpośrednio: kliknij nazwę użytkownika, potem ikonę ołówka, wpisz **New password** o długości co najmniej 8 znaków i kliknij **Save**. Konta logujące się tylko przez LDAP, SAML lub OIDC nie mogą otrzymać hasła żadnym z tych sposobów.

</Accordion>
