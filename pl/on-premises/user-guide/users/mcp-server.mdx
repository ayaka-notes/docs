Każdy projekt ma własny serwer MCP, dzięki czemu klient AI na Twoim komputerze może czytać i edytować projekt, kompilować go i odpowiadać na komentarze. Klient loguje się za pomocą tokena uwierzytelniania Git.

<Info>

Jeśli nie widzisz karty **MCP server**, odeślij administratora do strony [Serwer MCP](/pl/on-premises/configuration/overleaf-toolkit/integrations/mcp-server).

</Info>

## Nowości w v6.3.3 {#new-in-v6-3-3}

Od v6.3.3 klient może też pracować z historią projektu: wyświetlać zmiany, porównywać dwie wersje, czytać plik w dawnej postaci, zapisywać i usuwać wersje oraz przywracać plik lub cały projekt. Może wyświetlać śledzone zmiany i je akceptować lub odrzucać, a także robić ze swoich edycji śledzone zmiany, gdy go o to poprosisz. Może komentować fragment tekstu oraz edytować i usuwać wiadomości komentarzy, czytać i wysyłać wiadomości na czacie projektu, przenosić pliki i foldery oraz zmieniać ich nazwy, tworzyć foldery i zmieniać język sprawdzania pisowni. To, kto co może zrobić, zależy od Twojej roli w projekcie, tak jak w edytorze, ponieważ klient działa z Twoim tokenem: zobacz [Kto co może](#who-may-do-what).

Serwer MCP pojawił się w v6.3.1. W v6.3.1 i v6.3.2 jest tych samych 17 narzędzi; v6.3.3 ma ich 33.

| Narzędzia | v6.3.1 i v6.3.2 | v6.3.3 |
| ----- | ----------------- | ------ |
| `get_clone_info`, `get_settings`, `list_files`, `delete_file`, `compile`, `get_compile_log`, `get_output_file_link`, `word_count`, `reply_to_comment`, `resolve_comment`, `reopen_comment` | Tak | Tak, bez zmian |
| `read_file` | Najnowsza treść | Także plik w postaci z danej `version` |
| `edit_file`, `write_file` | Stosują ustawienie śledzenia zmian projektu | Także `trackChanges`, aby edycja była śledzoną zmianą |
| `update_settings` | Kompilator, obraz TeX Live i dokument główny | Także język sprawdzania pisowni |
| `list_versions` | Wersja, komentarz i data | Także `id`, które przyjmuje `delete_version`, oraz kto ją zapisał |
| `list_comments` | Wiadomości bez id | Także `id` każdej wiadomości, które przyjmują `edit_comment_message` i `delete_comment_message` |
| `list_changes`, `diff`, `create_version`, `delete_version`, `restore_file`, `restore_project`, `list_tracked_changes`, `accept_tracked_changes`, `reject_tracked_changes`, `add_comment`, `edit_comment_message`, `delete_comment_message`, `list_chat_messages`, `send_chat_message`, `move_file`, `create_folder` | Nie | Tak |

## Połącz klienta {#connect-a-client}

<Steps>
<Step title="Otwórz okno">
Otwórz projekt. Na lewym pasku kliknij **Integrations**, a potem **MCP server**.

<Frame caption="Panel Integrations">
  <img src="/images/on-premises/mcp-server-integrations.png" alt="Panel Integrations z kartą MCP server" />
</Frame>

Okno pokazuje adres serwera tego projektu i kartę dla każdego klienta: **Claude Code**, **Codex**, **Cursor**, **VS Code** i **Gemini CLI**.

<Frame caption="Okno MCP server">
  <img src="/images/on-premises/mcp-server-dialog.png" alt="Okno MCP server z adresem, kartą dla każdego klienta i poleceniem dla Claude Code" />
</Frame>
</Step>

<Step title="Utwórz token">
Kliknij **Go to settings**. Ustawienia konta otworzą się w nowej karcie. W sekcji **Git integration** kliknij **Generate token** lub **Add another token**, jeśli masz już token. Kliknij **Copy** i przechowuj token w bezpiecznym miejscu, ponieważ zobaczysz go tylko raz. Następnie kliknij **Close**.

<Frame caption="Twój nowy token">
  <img src="/images/on-premises/mcp-server-token.png" alt="Okno Git authentication token z przyciskiem Copy" />
</Frame>

Działa też token, którego już używasz do [integracji z Git](/on-premises/user-guide/users/git-integration), a jednego tokena możesz używać do wszystkich projektów.
</Step>

<Step title="Dodaj serwer do klienta">
Wróć do okna, kliknij kartę swojego klienta, a następnie **Copy** obok konfiguracji.

| Karta | Gdzie to trafia | Token |
| --- | ------------- | --------- |
| **Claude Code** | Uruchom polecenie w terminalu | Zastąp `<token>` w poleceniu |
| **Codex** | `~/.codex/config.toml` | Umieść go w zmiennej środowiskowej `OVERLEAF_TOKEN` |
| **Cursor** | `~/.cursor/mcp.json` | Umieść go w zmiennej środowiskowej `OVERLEAF_TOKEN` |
| **VS Code** | `.vscode/mcp.json` | Zamiast tokena plik zawiera monit o hasło o nazwie `overleaf-token` |
| **Gemini CLI** | Uruchom polecenie w terminalu | Zastąp `<token>` w poleceniu |

Adres należy do jednego projektu. Aby połączyć inny projekt, dodaj go pod inną nazwą, ponieważ `overleaf` jest już zajęte. Na przykład w Claude Code zmień `overleaf` w poleceniu na `overleaf-lab`.
</Step>
</Steps>

## Sprawdź połączenie {#check-the-connection}

### Za pomocą Claude Code {#with-claude-code}

```bash
claude mcp list
```

Serwer jest widoczny jako połączony:

```text
overleaf: https://<your-site>/project/<project-id>/mcp (HTTP) - ✔ Connected
```

### Za pomocą curl {#with-curl}

To działa niezależnie od klienta. Zastąp adres i token, a następnie wyślij żądanie `initialize` protokołu MCP:

```bash
curl -X POST https://<your-site>/project/<project-id>/mcp \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -H "Accept: application/json, text/event-stream" \
  -d '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2025-06-18","capabilities":{},"clientInfo":{"name":"curl","version":"1.0"}}}'
```

Odpowiedź podaje nazwę serwera, a po niej jego instrukcje dla klientów:

```json
{"result":{"protocolVersion":"2025-06-18","capabilities":{"tools":{"listChanged":true}},"serverInfo":{"name":"overleaf","version":"1.0.0"},"instructions":"This server works on one Overleaf project. ..."},"jsonrpc":"2.0","id":1}
```

Aby zobaczyć narzędzia, wyślij `tools/list` tym samym poleceniem. Odpowiedź zawiera 33 narzędzia lub 31, jeśli w Twojej witrynie czat projektu jest wyłączony. Przed v6.3.3 jest ich 17.

```bash
  -d '{"jsonrpc":"2.0","id":2,"method":"tools/list","params":{}}'
```

Aby wywołać narzędzie, wyślij `tools/call`:

```bash
  -d '{"jsonrpc":"2.0","id":3,"method":"tools/call","params":{"name":"list_files","arguments":{}}}'
```

```json
{"result":{"content":[{"type":"text","text":"[\n  {\n    \"path\": \"main.tex\",\n    \"type\": \"doc\"\n  }\n]"}]},"jsonrpc":"2.0","id":3}
```

### Jeśli nie można się połączyć {#if-it-does-not-connect}

| Co widzisz | Co to oznacza |
| ------------ | ------------- |
| Status `401` lub w Claude Code `✘ Failed to connect` z `HTTP 401` | Brak tokena, token jest błędny lub usunięty |
| Status `404` | Żaden projekt nie ma tego ID |
| Status `405` | Żądanie nie było typu `POST` |
| Status `406` z `Not Acceptable` | Brak nagłówka `Accept`: klient musi akceptować zarówno `application/json`, jak i `text/event-stream` |

## Co widzisz, gdy klient pracuje {#what-you-see-when-a-client-works}

Edycje pojawiają się w otwartym edytorze w miarę jak klient je wprowadza, tak jak edycje współpracownika, bez przeładowania. Nowe pliki i foldery, przeniesienia i zmiany nazw pojawiają się w drzewie plików.

<Frame caption="Wiersz dodany przez edit_file">
  <img src="/images/on-premises/mcp-server-live-edit.png" alt="Edytor pokazuje wiersz dodany przez edit_file, bez okna i bez przeładowania" />
</Frame>

`edit_file` zmienia tylko tekst, który występuje dokładnie raz. W przeciwnym razie klient dostaje błąd, na przykład `oldString not found in main.tex, read_file again` lub `oldString appears 2 times in main.tex, add context`, i nic się nie zmienia.

Od v6.3.3 `move_file` przenosi plik lub folder albo zmienia jego nazwę, w razie potrzeby tworząc foldery nowej ścieżki, a `create_folder` tworzy folder. Jeśli pliku nie znaleziono lub nowa ścieżka już istnieje, klient dostaje błąd i nic się nie zmienia. `update_settings` może też zmienić język sprawdzania pisowni, na przykład na `de`, lub je wyłączyć.

Odpowiedzi na komentarze pojawiają się w panelu recenzji pod Twoim nazwiskiem, ponieważ token jest Twój. Komentarz rozwiązany przez serwer znika z panelu, a ponowne otwarcie go przywraca.

<Frame caption="Odpowiedź wysłana przez reply_to_comment">
  <img src="/images/on-premises/mcp-server-comment.png" alt="Komentarz w panelu recenzji z odpowiedzią wysłaną przez reply_to_comment" />
</Frame>

Od v6.3.3 `add_comment` komentuje fragment tekstu. Tekst musi występować w pliku dokładnie raz; gdy występuje częściej, klient podaje także dłuższy otaczający go fragment, który występuje raz, a komentowany jest tylko sam tekst. Komentarz pojawia się w panelu recenzji pod Twoim nazwiskiem i pozostaje przy swoim tekście, gdy plik się zmienia. `edit_comment_message` zmienia jedną z Twoich wiadomości. `delete_comment_message` usuwa wiadomość, a usunięcie pierwszej usuwa cały komentarz, tak jak w panelu recenzji.

`compile` kompiluje projekt i zwraca listę plików wynikowych. Następnie `get_output_file_link` podaje link do pobrania PDF lub innego pliku wynikowego. Link nie wymaga tokena i przestaje działać po 5 minutach.

Pełną listę narzędzi znajdziesz w sekcji [Tools](/on-premises/configuration/overleaf-toolkit/integrations/mcp-server#tools).

## Śledzone zmiany {#tracked-changes}

Od v6.3.3 możesz poprosić klienta, aby jego edycje były śledzonymi zmianami, na przykład *Rewrite the abstract as a tracked change*. Wtedy `edit_file` i `write_file` robią ze zmiany w istniejącym pliku śledzoną zmianę na Twoje nazwisko, nawet gdy śledzenie zmian jest w projekcie wyłączone, a Ty ją akceptujesz lub odrzucasz w panelu recenzji. Nowy plik nigdy nie jest śledzoną zmianą. Jeśli o to nie poprosisz, edycje stosują ustawienie śledzenia zmian projektu, tak jak Twoje w edytorze: są śledzone, gdy śledzenie jest włączone dla Ciebie lub dla wszystkich.

Jeśli konto właściciela projektu nie ma śledzenia zmian, klient dostaje `Track changes is off for this project` i nic się nie zmienia.

Aby przeglądać każdą edycję klienta, włącz śledzenie zmian dla siebie. Aby odróżnić jego edycje od swoich w panelu recenzji, daj klientowi token innego konta, któremu udostępniasz projekt.

`list_tracked_changes` wyświetla śledzone zmiany z ich plikiem, wstawionym lub usuniętym tekstem, autorem i czasem. `accept_tracked_changes` i `reject_tracked_changes` przyjmują id zmian i działają jak panel recenzji: zaakceptowana zmiana zostaje w tekście, odrzucone wstawienie jest usuwane, a odrzucone usunięcie wraca. Otwarty edytor pokazuje wynik bez przeładowania. Narzędzia nakazują klientowi akceptować lub odrzucać tylko te zmiany, o które prosisz.

## Historia {#history}

Od v6.3.3 klient widzi historię projektu tak, jak pokazuje ją panel historii.

| Narzędzie | Co robi |
| ---- | ------------ |
| `list_changes` | Wyświetla zmiany od najnowszych: kto, kiedy i które pliki zmienił, wraz z wersjami przed każdą zmianą i po niej. Starsze zmiany przychodzą w kolejnych partiach. |
| `diff` | Porównuje dwie wersje: jeden plik jako unified diff, jak `git diff`, albo pliki dodane, usunięte, edytowane lub o zmienionej nazwie |
| `read_file` z `version` | Czyta plik w postaci z danej wersji |
| `list_versions` | Wyświetla zapisane wersje z komentarzem i informacją, kto je zapisał |
| `create_version` | Zapisuje najnowszą lub wcześniejszą wersję z komentarzem, jak **Label this version** |
| `delete_version` | Usuwa zapisaną wersję; jej zmiany pozostają |
| `restore_file` | Przywraca plik do postaci z danej wersji, jak **Restore this version** |
| `restore_project` | Przywraca cały projekt do postaci z danej wersji, jak **Restore project to this version** |

Przywrócenie jest samo w sobie nową zmianą, więc możesz je cofnąć w ten sam sposób. Narzędzia nakazują klientowi przywracać tylko na Twoją prośbę.

Jeśli właściciel projektu nie ma pełnej historii projektu, klient widzi tylko zmiany z ostatnich 24 godzin albo najnowszą zmianę, jeśli wszystkie są starsze, tak jak w panelu historii. Nie może porównywać, czytać ani przywracać starszych wersji.

## Czat projektu {#project-chat}

Od v6.3.3 `list_chat_messages` czyta czat projektu od najnowszych, po 50 wiadomości naraz. `send_chat_message` wysyła wiadomość pod Twoim nazwiskiem, a ta od razu pojawia się w otwartym czacie. Jeśli w Twojej witrynie czat projektu jest wyłączony, klient nie ma żadnego z tych narzędzi.

## Kto co może {#who-may-do-what}

Klient może robić to, na co pozwala Twoja rola w projekcie.

| Co robi klient | Właściciel | Edytor | Recenzent | Przeglądający (wskazany współpracownik) | Przeglądający (udostępnianie linkiem) |
| -------------------- | ----: | -----: | -------: | --------------------------: | --------------------: |
| Czytać pliki i ustawienia, kompilować, czytać dziennik, pobierać PDF | Tak | Tak | Tak | Tak | Tak |
| Zapisywać, edytować, przenosić i usuwać pliki, tworzyć foldery, zmieniać ustawienia | Tak | Tak | Nie | Nie | Nie |
| Widzieć historię, komentarze i śledzone zmiany | Tak | Tak | Tak | Tak | Nie |
| Czytać i wysyłać wiadomości na czacie | Tak | Tak | Tak | Tak | Nie |
| Dodawać komentarze i na nie odpowiadać | Tak | Tak | Tak | Nie | Nie |
| Rozwiązywać, ponownie otwierać lub usuwać komentarz | Tak | Tak | Te, które rozpoczął | Nie | Nie |
| Edytować wiadomość komentarza | Własne | Własne | Własne | Nie | Nie |
| Usuwać wiadomość komentarza | Tak | Tak | Własne | Nie | Nie |
| Akceptować lub odrzucać śledzone zmiany | Tak | Tak | Nie | Nie | Nie |
| Zapisywać wersję | Tak | Tak | Tak | Nie | Nie |
| Usuwać zapisaną wersję | Tak | Te, które zapisał | Te, które zapisał | Nie | Nie |
| Przywracać plik lub projekt | Tak | Tak | Nie | Nie | Nie |

Edytorzy, którzy dołączyli przez link, liczą się jako edytorzy. Recenzenci nie mogą edytować plików przez MCP, nawet jako śledzonych zmian.

## Odłącz klienta {#disconnect-a-client}

Usuń token: zobacz [Usuwanie tokena](/on-premises/user-guide/users/git-integration#delete-a-token). Od tej chwili serwer odpowiada `401` na ten token. Jeśli używasz go też do Git, Git również przestaje go akceptować.
