---
title: Eksportowanie projektów
icon: file-export
---

W Server Pro i Community Edition `5.4.0` dodaliśmy skrypt, który pozwala administratorom eksportować wszystkie projekty użytkowników (w tym te, które nadal są widoczne w folderach **Deleted** i **Trashed**) do katalogu na dysku.

<Info>

Wynik działania tego skryptu jest taki sam jak ręczne pobranie archiwum Zip wszystkich projektów z panelu projektów użytkownika. Przed rozpoczęciem pobierania skrypt zapisze wszystkie oczekujące zmiany, aby eksport zawierał najnowszą wersję projektu.

</Info>

### Ograniczenia

Skrypt eksportu ma następujące ograniczenia:

* Ustawienia projektu, takie jak nazwa obrazu TeX Live czy kompilator, nie są eksportowane. Należy je ustawić po przesłaniu projektu na konto użytkownika.
* Wyeksportowane projekty nie zawierają historii wersji.
* Informacje o współpracownikach nie są zachowywane. Projekty trzeba będzie ponownie udostępnić. W przypadku udostępniania przez link linki do wyświetlania i edycji zostaną wygenerowane ponownie (nie będą takie same jak wcześniej).
* Komentarze i informacje o śledzonych zmianach nie zostaną wyeksportowane.
* Historia czatu projektu nie zostanie wyeksportowana.

<Danger>

Ten skrypt **nie** jest przeznaczony do zastąpienia pełnej kopii zapasowej systemu. Aby mieć pewność, że w razie awarii będzie można odtworzyć instancję, **zdecydowanie** zalecamy wykonanie [spójnej kopii zapasowej](https://docs.overleaf.com/on-premises/maintenance/#performing-a-consistent-backup).

</Danger>

### **Flagi**

| Nazwa          | Opis                                                                            |
| -------------- | ------------------------------------------------------------------------------- |
| `--help`       | Wyświetla pomoc                                                                 |
| `--user-id`    | ID użytkownika (wymagane, chyba że używasz `--export-all` lub `--project-id`)   |
| `--project-id` | Eksportuje pojedynczy projekt (**nie można** używać z `--user-id` ani `--export-all`) |
| `--list`       | Wyświetla listę projektów użytkownika (**nie można** używać z `--output`)       |
| `--output`     | Wyjściowy plik zip (dla pojedynczych operacji eksportu)                         |
| `--export-all` | Eksportuje projekty wszystkich użytkowników (wymaga `--output-dir`)             |
| `--output-dir` | Katalog do przechowywania plików eksportu wszystkich użytkowników               |
| `--log-level`  | Obsługiwane poziomy logowania: `trace`\|`debug`\|`info`\|`warn`\|`error`\|`fatal` |

### **Użycie**

Użyj poniższego polecenia, aby wyeksportować projekty wszystkich użytkowników:

```bash wrap
# Overleaf Toolkit users
$ bin/docker-compose exec sharelatex /bin/bash -ce "cd /overleaf/services/web && node modules/server-ce-scripts/scripts/export-user-projects.mjs --export-all --output-dir=/var/lib/overleaf/data/exports"

# Legacy docker-compose.yml users
docker exec sharelatex /bin/bash -ce "cd /overleaf/services/web && node modules/server-ce-scripts/scripts/export-user-projects.mjs --export-all --output-dir=/var/lib/overleaf/data/exports"
```

<Info>

Jeśli używasz Server Pro lub Community Edition w wersji &lt;= 3.5.13, musisz zmodyfikować powyższy przykład tak, aby korzystał ze skryptu **`export-legacy-user-projects.js`**.

</Info>

### **Zakończenie**

Po zakończeniu eksportu pliki są dostępne w katalogu hosta, który jest podmontowany (bind mount) do <strong>/var/lib/overleaf</strong> w pliku **docker-compose.yml**, lub w katalogu wskazanym przez zmienną środowiskową `OVERLEAF_DATA_PATH` w pliku **config/overleaf.rc**, jeśli korzystasz z Toolkit.

<Info>

Overleaf obecnie dopuszcza powielone nazwy projektów. Jeśli wśród projektów użytkownika występuje duplikat, projekty te nadal zostaną dodane do eksportu Zip użytkownika, ale po rozpakowaniu obecna będzie tylko jedna wersja. W systemie Linux `unzip -B` zapisze pliki o tej samej nazwie jako pliki kopii zapasowych zamiast je nadpisywać.

</Info>
