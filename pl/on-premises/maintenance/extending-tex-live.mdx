Istniejący obraz TeX Live można rozszerzyć za pomocą nowego pliku Dockerfile i skonfigurować aplikację tak, aby używała nowego obrazu.

Poniżej przedstawiamy wskazówki dotyczące instalowania nowych pakietów lub fontów, jednak konfiguracja niestandardowego obrazu nie jest objęta naszymi warunkami wsparcia.

Obrazy TeX Live są aktualizowane rzadko. Zalecamy przebudowywanie niestandardowych obrazów przy aktualizacji Server Pro.

<Danger>

Poniższe sekcje dotyczą wyłącznie Server Pro oraz [Sandboxed Compiles](/pl/on-premises/configuration/overleaf-toolkit/sandboxed-compiles).

</Danger>

### Instalowanie i aktualizowanie pakietów

Do zarządzania pakietami TeX Live możesz używać poleceń `tlmgr`, takich jak `tlmgr install` i `tlmgr update`, jak w poniższym przykładzie:

```dockerfile
FROM ghcr.io/ayaka-notes/texlive-full:2023.1

RUN tlmgr update --force ebproof
```

### Używanie `tlmgr` w starszym obrazie TeX Live

Domyślnie `tlmgr` pobiera zasoby z najnowszego wydania TeX Live. Przy łataniu starszego obrazu TeX Live pobieranie należy przełączyć na odpowiednie archiwum. Listę serwerów lustrzanych archiwów znajdziesz na stronie [https://www.tug.org/historic/](https://www.tug.org/historic/).

```dockerfile
FROM ghcr.io/ayaka-notes/texlive-full:2022.1

RUN tlmgr option repository <MIRROR>/systems/texlive/<YEAR>/tlnet-final
# e.g. RUN tlmgr option repository ftp://tug.org/historic/systems/texlive/2022/tlnet-final

RUN tlmgr update --force ebproof
```

### Instalowanie nowych fontów

Istnieją różne procedury instalowania nowych fontów w dystrybucji TeX Live, a instalacja niestandardowego fontu może wymagać kilku kroków. Dobrym punktem wyjścia będzie prawdopodobnie zapoznanie się z [instrukcjami instalacji fontów TeX](https://tug.org/fonts/fontinstall.html) w oficjalnej dokumentacji TeX Live.

Poniższy plik `Dockerfile` pokazuje przykład instalacji fontu TrueType w istniejącym obrazie TeX Live 2022:

```dockerfile
FROM ghcr.io/ayaka-notes/texlive-full:2022.1

COPY ./myfonts/*.ttf /usr/share/fonts/truetype/myfont/

# rebuild font information cache
RUN fc-cache
```

### Konfigurowanie Server Pro do używania nowych obrazów

Do zbudowania nowego obrazu użyj nazwy `ghcr.io/ayaka-notes/texlive-full` i niestandardowego tagu, na przykład:

```bash
docker build -t ghcr.io/ayaka-notes/texlive-full:2023.1-custom
```

Teraz możemy skonfigurować Server Pro do używania nowego obrazu `2023.1-custom`, aktualizując zmienne środowiskowe `TEX_LIVE_DOCKER_IMAGE` i `ALL_TEX_LIVE_DOCKER_IMAGES`:

```text wrap
TEX_LIVE_DOCKER_IMAGE: "ghcr.io/ayaka-notes/texlive-full:2023.1-custom"
ALL_TEX_LIVE_DOCKER_IMAGES: "ghcr.io/ayaka-notes/texlive-full:2023.1,ghcr.io/ayaka-notes/texlive-full:2023.1-custom"
```

W powyższym przykładzie nowe projekty domyślnie używają nowego obrazu `2023.1-custom`, a obraz `2023.1` pozostaje dostępny, gdy jest potrzebny.
