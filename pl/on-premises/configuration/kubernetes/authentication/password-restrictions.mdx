Usługa **web** sprawdza hasła lokalne, gdy użytkownicy się rejestrują, ustawiają lub zmieniają hasło. Nie dotyczy to logowania SSO (LDAP, SAML, OIDC); ich hasłami zajmuje się dostawca tożsamości. Opis dla Toolkit znajdziesz w [Ograniczenia haseł](/pl/on-premises/configuration/overleaf-toolkit/authentication/password-restrictions).

| | |
| --- | --- |
| Usługa | web, w każdym podzie Ayakaleaf Pro; odczytywane przy starcie web |
| Sieć | brak |
| Zadania okresowe | brak |

### Konfiguracja

Dodaj do ConfigMap `overleaf-env` i zrestartuj:

```yaml title="30-config.yaml (additions)"
  OVERLEAF_PASSWORD_VALIDATION_MIN_LENGTH: "12"
  OVERLEAF_PASSWORD_VALIDATION_MAX_LENGTH: "72"
```

```bash
kubectl apply -f 30-config.yaml
kubectl -n overleaf rollout restart deployment/overleaf     # or statefulset/overleaf
```

| Zmienna | Domyślnie | |
| --- | --- | --- |
| `OVERLEAF_PASSWORD_VALIDATION_MIN_LENGTH` | `8` | Najkrótsze akceptowane hasło. |
| `OVERLEAF_PASSWORD_VALIDATION_MAX_LENGTH` | `72` | Najdłuższe akceptowane hasło; wartości powyżej `72` są traktowane jako `72`. |

Ujmij liczby w cudzysłów: ConfigMap przechowuje wyłącznie ciągi znaków.

<Warning>

`OVERLEAF_PASSWORD_VALIDATION_PATTERN` jest odczytywane, ale nie jest egzekwowane: hasło, które do niego nie pasuje, zostaje zaakceptowane. Obowiązują tylko limity długości.

</Warning>

### Kilka replik

Nic dodatkowego: każda replika odczytuje ten sam ConfigMap.

### Przetestowano na Kubernetes

Na Kubernetes 1.37 z jedną repliką, z `OVERLEAF_PASSWORD_VALIDATION_MIN_LENGTH: "12"` i `OVERLEAF_PASSWORD_VALIDATION_PATTERN: aA$3` w ConfigMap, aktywacja nowego konta odrzuciła 10-znakowe hasło i zaakceptowała 20-znakowe hasło składające się wyłącznie z małych liter, które wzorzec by odrzucił. Nasze testy end-to-end dla rejestracji przy ustawieniach domyślnych również odrzucają `123456` jako zbyt krótkie.
