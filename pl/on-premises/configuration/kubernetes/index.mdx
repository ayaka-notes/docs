Wdrożenie Kubernetes odczytuje te same zmienne środowiskowe co Toolkit. Tam, gdzie strona Toolkit mówi „dodaj to do `config/variables.env`”, umieść wartość w ConfigMap `overleaf-env` lub — jeśli jest to hasło, klucz lub token — w Secret `overleaf-secrets`. Następnie zrestartuj:

```bash
kubectl -n overleaf apply -f 30-config.yaml        # after editing the ConfigMap
kubectl -n overleaf patch secret overleaf-secrets --type merge \
  -p '{"stringData":{"GITHUB_TOKEN_CIPHER_PASSWORD":"'"$(openssl rand -hex 32)"'"}}'
kubectl -n overleaf rollout restart deployment/overleaf
```

Wartości w `config/overleaf.rc` to ustawienia Toolkit, a nie zmienne środowiskowe; sekcja Pytania i odpowiedzi na końcu tej strony wyjaśnia, co je zastępuje.

### Certyfikaty i inne pliki

Niektóre funkcje przyjmują ścieżkę do pliku zamiast wartości: certyfikaty SAML (`OVERLEAF_SAML_IDP_CERT`, ...), CA serwera LDAP (`OVERLEAF_LDAP_TLS_OPTS_CA_PATH`) lub prywatne CA dla samodzielnie hostowanego GitHub Enterprise, GitLab lub Gitea (`NODE_EXTRA_CA_CERTS`). Umieść pliki w Secret i zamontuj go tam, gdzie oczekują ich strony Toolkit, czyli w `/var/lib/overleaf/certs`:

```bash
kubectl -n overleaf create secret generic overleaf-certs --from-file=idp_cert.pem --from-file=ca.pem
```

```yaml title="40-overleaf.yaml (additions)"
          volumeMounts:
            # ...
            - name: certs
              mountPath: /var/lib/overleaf/certs
              readOnly: true
      volumes:
        # ...
        - name: certs
          secret:
            secretName: overleaf-certs
```

Następnie odwołaj się do nich przez ścieżkę w ConfigMap, na przykład `NODE_EXTRA_CA_CERTS: /var/lib/overleaf/certs/ca.pem`, i zrestartuj.

<Warning>

<strong>Hasła szyfrujące.</strong> Ustaw w Secret każde `*_CIPHER_PASSWORD` używanych funkcji. W przeciwnym razie niektóre funkcje przy pierwszym użyciu generują plik klucza na wolumenie danych: przy jednej replice działa to do czasu utraty wolumenu, a przy kilku replikach każda replika szyfrowałaby innym kluczem.

</Warning>

### Pytania i odpowiedzi

<Accordion title="Których ustawień Toolkit z `config/overleaf.rc` potrzebuję?">

<strong>Odpowiedź:</strong> Ayakaleaf Pro nie odczytuje żadnego z nich. Ich odpowiedniki w Kubernetes:

| `config/overleaf.rc`                         | Kubernetes                                                        |
| -------------------------------------------- | ----------------------------------------------------------------- |
| `OVERLEAF_LISTEN_IP`, `OVERLEAF_PORT`        | Service (NodePort) lub Twój ingress                               |
| `SIBLING_CONTAINERS_ENABLED`                 | `SANDBOXED_COMPILES*` w ConfigMap, gniazdo Dockera w podzie       |
| `GIT_BRIDGE_ENABLED`                         | [Integracja z Git](/pl/on-premises/configuration/kubernetes/integrations/git-integration)                       |
| `MONGO_ENABLED`, `REDIS_ENABLED`, `MONGO_URL`, `REDIS_HOST` | obiekty StatefulSet lub Twoje usługi zarządzane, `OVERLEAF_MONGO_URL` i `OVERLEAF_REDIS_HOST` |
| `REDIS_AOF_PERSISTENCE`                      | `--appendonly yes` w `20-redis.yaml`                              |
| `NGINX_ENABLED`, `TLS_*`                     | Twój ingress lub load balancer                                    |

</Accordion>
