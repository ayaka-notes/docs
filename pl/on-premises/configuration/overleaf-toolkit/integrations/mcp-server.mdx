Każdy projekt ma serwer MCP, dzięki czemu klienci AI, tacy jak Claude Code, Codex, Cursor, VS Code czy Gemini CLI, mogą nad nim pracować: odczytywać i edytować jego pliki, kompilować go, odczytywać log LaTeX, pobierać plik PDF i odpowiadać na komentarze. Od v6.3.3 mogą też przeglądać historię i przywracać wersje, przeglądać śledzone zmiany, dodawać komentarze, korzystać z czatu projektu i przenosić pliki.

<Info>

Ta funkcja została opracowana przez [ayaka-notes/ayakaleaf-pro](https://github.com/ayaka-notes/ayakaleaf-pro). Jest dostępna od wersji v6.3.1. Narzędzia do historii, śledzonych zmian, czatu projektu, nowych komentarzy i przenoszenia plików są dostępne od v6.3.3, zobacz [Nowości w v6.3.3](/on-premises/user-guide/users/mcp-server#new-in-v6.3.3).

</Info>

### Konfiguracja {#setup}

Serwer MCP jest dostępny razem z integracją z Git: włącz [git-bridge](/pl/on-premises/configuration/overleaf-toolkit/integrations/git-integration), a serwer MCP również stanie się dostępny. Nie trzeba niczego więcej konfigurować.

### Łączenie klienta AI {#connect-an-ai-client}

1. W **Account Settings** wygeneruj token uwierzytelniania Git. Ten sam token służy do serwera MCP i do Git.
2. W edytorze otwórz **Integrations** i kliknij **MCP server**. Zostanie wyświetlony adres serwera MCP projektu, `https://<your-overleaf>/project/<project_id>/mcp`, oraz sposób dodania go do każdego klienta AI: skopiuj polecenie i zastąp `<token>` swoim tokenem.

Token jest wysyłany jako nagłówek HTTP `Authorization: Bearer <token>`. Na przykład polecenie dla Claude Code wygląda tak:

```bash
claude mcp add --transport http overleaf \
  https://<your-overleaf>/project/<project_id>/mcp \
  --header "Authorization: Bearer <token>"
```

### Użycie {#usage}

Po połączeniu poproś klienta AI o wykonanie zadania zwykłymi słowami. Na przykład:

| Prosisz o | Klient AI używa |
| --- | --- |
| _Popraw literówki we wstępie._ | `read_file`, `edit_file`: zmiany są widoczne na bieżąco w edytorze |
| _Skompiluj projekt i popraw błędy LaTeX._ | `compile`, `get_compile_log`, `edit_file` |
| _Odpowiedz na otwarte komentarze, a następnie je rozwiąż._ | `list_comments`, `reply_to_comment`, `resolve_comment` |
| _Przełącz na XeLaTeX i pobierz plik PDF._ | `update_settings`, `compile`, `get_output_file_link` |
| _Przepisz streszczenie jako śledzoną zmianę._ | `read_file`, `edit_file` z `trackChanges` (v6.3.3) |
| _Co się zmieniło od wysłanej wersji?_ | `list_versions`, `list_changes`, `diff` (v6.3.3) |
| _Przenieś rozdziały do folderu o nazwie chapters._ | `move_file` (v6.3.3) |

### Narzędzia {#tools}

| Grupa | Narzędzia |
| --- | --- |
| Projekt | `get_clone_info`, `get_settings`, `update_settings` |
| Pliki | `list_files`, `read_file`, `edit_file`, `write_file`, `delete_file`, `move_file`, `create_folder` |
| Kompilacja | `compile`, `get_compile_log`, `get_output_file_link`, `word_count` |
| Komentarze | `list_comments`, `reply_to_comment`, `resolve_comment`, `reopen_comment`, `add_comment`, `edit_comment_message`, `delete_comment_message` |
| Śledzone zmiany | `list_tracked_changes`, `accept_tracked_changes`, `reject_tracked_changes` |
| Historia | `list_versions`, `list_changes`, `diff`, `create_version`, `delete_version`, `restore_file`, `restore_project` |
| Czat | `list_chat_messages`, `send_chat_message` |

v6.3.3 ma 33 narzędzia, a 31 z `OVERLEAF_DISABLE_CHAT=true`, które usuwa narzędzia czatu. v6.3.1 i v6.3.2 mają pozostałe 17: wszystko powyżej oprócz `move_file`, `create_folder`, `add_comment`, `edit_comment_message`, `delete_comment_message`, narzędzi śledzonych zmian, narzędzi czatu i narzędzi historii innych niż `list_versions`. W v6.3.3 `read_file` odczytuje też plik w wersji z historii, `edit_file` i `write_file` przyjmują `trackChanges`, a `update_settings` ustawia też język sprawdzania pisowni.

Zmiany wprowadzone przez `edit_file`, `write_file` i `move_file` pojawiają się na żywo w edytorze i są scalane ze zmianami współpracowników. W przypadku wielu plików naraz lub plików binarnych klient AI może też sklonować projekt przez Git i wykonać push.

Z `trackChanges` edycja istniejącego pliku jest śledzoną zmianą użytkownika tokenu, nawet gdy śledzenie zmian jest w projekcie wyłączone; nowy plik nigdy nią nie jest. Bez `trackChanges` edycje stosują się do ustawienia śledzenia zmian projektu.

### Uprawnienia {#permissions}

Serwer MCP przestrzega ustawień udostępniania projektu, podobnie jak Git:

* Każdy, kto może wyświetlić projekt, może go czytać, kompilować i pobierać jego wynik.
* Tylko właściciel i edytorzy mogą zmieniać jego pliki i ustawienia, przywracać wersje oraz akceptować lub odrzucać śledzone zmiany.
* Recenzenci mogą też dodawać komentarze i na nie odpowiadać, rozwiązywać, ponownie otwierać lub usuwać rozpoczęte przez siebie komentarze oraz zapisywać wersje. Nie mogą edytować plików, nawet jako śledzonych zmian.
* Każdy edytuje tylko własne wiadomości w komentarzach, a recenzenci usuwają tylko własne.
* Tylko właściciel usuwa wersje zapisane przez innych.
* Czytelnicy, którzy dołączyli przez link, nie widzą komentarzy, śledzonych zmian, historii ani czatu, tak jak w edytorze. Zaproszeni czytelnicy widzą je i mogą korzystać z czatu.
* Jeśli właściciel projektu nie ma **Full project history**, narzędzia historii pokazują tylko zmiany z ostatnich 24 godzin, tak jak panel historii. Administratorzy widzą wszystkie.

Przewodnik użytkownika zawiera tabelę tego, co może każda rola, zobacz [Kto może co](/on-premises/user-guide/users/mcp-server#who-may-do-what).

### Pytania i odpowiedzi {#q&a}

<Accordion title="Nie widzę Integrations ani serwera MCP w edytorze">

<strong>Odpowiedź:</strong> Serwer MCP nie ma własnej zmiennej środowiskowej. Włącza się go za pomocą `GIT_BRIDGE_ENABLED=true` w `config/overleaf.rc`, zobacz [Integracja z Git](/pl/on-premises/configuration/overleaf-toolkit/integrations/git-integration). Po zmianie uruchom `bin/up -d`. Bez git-bridge edytor nie wyświetla karty **Integrations** na lewym pasku.

</Accordion>

<Accordion title="Klient AI zgłasza „Track changes is off for this project”">

<strong>Odpowiedź:</strong> Klient poprosił o śledzoną zmianę, ale konto właściciela projektu nie ma śledzenia zmian. Kliknij **Admin**, a następnie **Manage Users**, otwórz właściciela i na karcie **Features** włącz **Track changes**, zobacz [Features](/pl/on-premises/user-guide/administrators/user-management#features). Edycje bez `trackChanges` nadal działają.

</Accordion>

<Accordion title="Klient AI widzi tylko zmiany z ostatnich 24 godzin">

<strong>Odpowiedź:</strong> Konto właściciela projektu nie ma pełnej historii projektu, więc narzędzia historii pokazują to samo co panel historii: zmiany z ostatnich 24 godzin. Kliknij **Admin**, a następnie **Manage Users**, otwórz właściciela i na karcie **Features** włącz **Full project history**, zobacz [Features](/pl/on-premises/user-guide/administrators/user-management#features).

</Accordion>
