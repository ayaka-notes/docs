### Doctor

Overleaf Toolkit zawiera przydatny skrypt `doctor`, który ułatwia debugowanie. Uruchom `bin/doctor`, a skrypt wyświetli informacje o środowisku hosta, Twojej konfiguracji oraz zależnościach wymaganych przez Toolkit. Te dane wyjściowe mogą również pomóc nam w diagnozowaniu problemów z Twoimi instalacjami Ayakaleaf Pro.

<Info>

Użytkownicy Overleaf Pro mogą [zgłosić problem na GitHub](https://github.com/ayaka-notes/overleaf/issues).

Warto dołączyć do zgłoszenia wynik działania skryptu `bin/doctor`.

</Info>

### Konsultacja z Doctorem

Uruchom skrypt doctor:

```bash title="Run doctor"
bin/doctor
```

### Informacje o hoście

Sekcja `Host Information` zawiera informacje o maszynie, na której działa Toolkit (na przykład dystrybucję i wydanie systemu Linux).

<Accordion title="Przykładowe dane wyjściowe sekcji Host Information">

```text
- Host Information
    - Linux
    - Output of 'lsb_release -a':
            No LSB modules are available.
            Distributor ID:	Ubuntu
            Description:	Ubuntu 22.04.5 LTS
            Release:	22.04
            Codename:	jammy
```

</Accordion>

### Zależności

Sekcja `Dependencies` zawiera listę narzędzi wymaganych do działania Toolkit. Jeśli narzędzie jest obecne, zostanie oznaczone jako `status: present` wraz z informacją o wersji. Jeśli go brakuje, zostanie oznaczone jako `status: MISSING!`, a na końcu danych wyjściowych `doctor` pojawi się ostrzeżenie.

<Accordion title="Przykładowe dane wyjściowe zależności (obecna)">

```text
- docker
    - status: present
    - version info: Docker version 28.0.4, build b8034c0
```

</Accordion>

<Accordion title="Przykładowe dane wyjściowe zależności (brakująca)">

```text
- docker
    - status: MISSING!
```

</Accordion>

Jeśli brakuje którejkolwiek zależności, Toolkit niemal na pewno nie będzie działać.

### Konfiguracja

Sekcja `Configuration` zawiera informacje o plikach w katalogu `config/`. W przypadku `config/overleaf.rc` doctor wyświetla niektóre kluczowe wartości. Brakujące pliki zostaną oznaczone jako `status: MISSING!`, a na końcu danych wyjściowych `doctor` pojawi się ostrzeżenie.

<Accordion title="Przykładowe dane wyjściowe sekcji Configuration">

```text
====== Configuration ======
- config/version
    - status: present
    - version: 5.4.0
- config/overleaf.rc
    - status: present
    - values
        - OVERLEAF_DATA_PATH: /tmp/overleaf
        - SERVER_PRO: false
        - MONGO_ENABLED: false
        - REDIS_ENABLED: true
- config/variables.env
    - status: MISSING!
```

</Accordion>

Uwagi do powyższego przykładu:

* `OVERLEAF_DATA_PATH` ustawione na `/tmp/overleaf` może nie być bezpieczną lokalizacją dla ważnych danych.
* `MONGO_ENABLED: false` oznacza, że Toolkit nie utworzy własnej instancji MongoDB; w razie potrzeby upewnij się, że `MONGO_URL` wskazuje na zewnętrznie zarządzaną bazę MongoDB.
* W przykładzie brakuje pliku `config/variables.env`.

### Ostrzeżenia

Sekcja `Warnings` podsumowuje problemy wykryte przez skrypt doctor. Jeśli nie ma żadnych problemów, sekcja to zasygnalizuje.

<Accordion title="Przykładowe dane wyjściowe sekcji Warnings">

```text
====== Warnings ======
- configuration file variables.env not found
- rc file, OVERLEAF_DATA_PATH not set
====== End =======
```

</Accordion>
