Ayakaleaf Pro działa w Dockerze. Na Macu używasz Docker Desktop, który uruchamia silnik Dockera w maszynie wirtualnej Linux.

<Steps>
<Step title="Zainstaluj i uruchom Docker Desktop">
Zainstaluj wersję [Docker Desktop](https://docs.docker.com/desktop/setup/install/mac-install/) dla swojego Maca (Apple silicon lub Intel), otwórz ją i poczekaj, aż silnik się uruchomi. Możesz go też uruchomić z Terminala:

```bash
open -a Docker
```
</Step>

<Step title="Sprawdź silnik Dockera">
Uruchom te polecenia w Terminalu:

```bash
docker context show
docker info
docker compose version
```

Kontekst powinien wskazywać na lokalny silnik Docker Desktop, zwykle `desktop-linux`. Jeśli wybrany jest inny kontekst, przełącz się na Docker Desktop, zanim przejdziesz dalej:

```bash
docker context use desktop-linux
```

`docker info` musi wyświetlić sekcję **Server**. Samo `docker --version` pokazuje tylko, że klient jest zainstalowany.
</Step>

<Step title="Sprawdź zasoby i udostępnianie plików">
W **Settings** Docker Desktop porównaj limity procesora, pamięci i dysku z sekcją [Zanim zaczniesz](/pl/on-premises/installation/using-docker-compose/macos#before-you-start) i sprawdź ustawienia udostępniania plików, zobacz [ustawienia Docker Desktop](https://docs.docker.com/desktop/settings-and-maintenance/settings/).

Ten przewodnik trzyma Toolkit w `/Users`, który Docker Desktop udostępnia domyślnie. Jeśli używasz innej lokalizacji, a `bin/up` kończy się błędem `Mounts denied`, dodaj ten katalog do udostępniania plików.
</Step>

<Step title="Sprawdź gniazdo Dockera dla kompilacji w piaskownicy">
Toolkit montuje `/var/run/docker.sock` w aplikacji, aby mogła ona uruchamiać osobny kontener TeX Live dla każdej kompilacji. Pozostaw `DOCKER_SOCKET_PATH=/var/run/docker.sock` w `config/overleaf.rc`.

Docker CLI w macOS może łączyć się przez `~/.docker/run/docker.sock`. To punkt końcowy klienta na Macu, a nie powód do zmiany źródła montowania w Toolkit: kompilator potrzebuje gniazda silnika w takiej postaci, w jakiej widzą je kontenery Linux.

Jeśli na Macu brakuje `/var/run/docker.sock`, włącz **Allow the default Docker socket to be used** w **Settings → Advanced**, zobacz [wymagania dotyczące uprawnień Dockera](https://docs.docker.com/desktop/setup/install/mac-permission-requirements/).

<Danger>

Nie uruchamiaj `chmod 777` na gnieździe, aby obejść błędy. Dostęp do gniazda Dockera jest równoważny dostępowi root do maszyny wirtualnej Dockera.

</Danger>
</Step>
</Steps>
