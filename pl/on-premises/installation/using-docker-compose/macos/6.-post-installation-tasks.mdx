### Tworzenie administratora i pierwszego projektu {#create-the-administrator-and-a-first-project}

Otwórz [http://localhost:8080/launchpad](http://localhost:8080/launchpad), utwórz pierwsze konto administratora i zaloguj się. Następnie postępuj zgodnie z krokiem [6. Zadania poinstalacyjne](/pl/on-premises/installation/using-docker-compose/linux/6.-post-installation-tasks) przewodnika dla systemu Linux, używając portu `8080` w przykładowych adresach URL.

### Weryfikacja kompilacji {#verify-compilation}

To, że strona logowania się otwiera, nie dowodzi, że osobne kontenery kompilatora i ich montowania danych działają. Utwórz pusty projekt i skompiluj ten `main.tex`:

```latex
\documentclass{article}
\begin{document}
Ayakaleaf Pro on macOS.
\end{document}
```

Podgląd PDF powinien pokazać ten tekst. W razie potrzeby wybierz TeX Live 2026 w ustawieniach projektu.

W przypadku projektu z tekstem chińskim wybierz **XeLaTeX** jako kompilator i przetestuj:

```latex
\documentclass{ctexart}
\begin{document}
你好，Ayakaleaf Pro。
\end{document}
```

### Weryfikacja trwałości danych {#verify-persistence}

```bash
bin/stop
bin/start
```

Otwórz ponownie projekt i skompiluj go jeszcze raz. Twoje konto, źródło i pliki projektu powinny nadal być na miejscu. Przy domyślnych ścieżkach bieżące dane znajdują się w katalogu `data/` Toolkit na Twoim Macu.

### Utrzymywanie dostępności instancji {#keep-the-instance-available}

Gdy Mac jest uśpiony, macOS wstrzymuje maszynę wirtualną Docker Desktop wraz ze wszystkimi kontenerami: nikt nie może otworzyć instancji, a trwająca kompilacja zatrzymuje się do czasu wybudzenia Maca. Znaczenie ma tylko uśpienie systemu. Ekran może się wyłączać.

Jeśli z instancji korzystają inne osoby lub zostawiasz uruchomione długie zadania, trzymaj Maca podłączonego do zasilania i zapobiegaj automatycznemu usypianiu, zobacz [Ustawianie usypiania i budzenia Maca](https://support.apple.com/guide/mac-help/set-sleep-and-wake-settings-mchle41a6ccd/mac):

| Mac | Ustawienie |
| --- | --- |
| Mac stacjonarny (Mac mini, iMac, Mac Studio, Mac Pro) | **System Settings → Energy**: włącz **Prevent automatic sleeping when the display is off** |
| MacBook | **System Settings → Battery → Options**: włącz **Prevent automatic sleeping on power adapter when the display is off**. Działa to tylko przy podłączonym zasilaczu, a zamknięcie pokrywy nadal usypia MacBooka |

Aby utrzymać Maca w stanie czuwania tylko przez pewien czas, uruchom zamiast tego `caffeinate -i` w oknie Terminala. Zapobiega to usypianiu z powodu bezczynności, dopóki nie naciśniesz `Ctrl+C` lub nie zamkniesz okna.

Docker Desktop to aplikacja w Twojej sesji użytkownika. Aby instancja wróciła po ponownym uruchomieniu, włącz **Start Docker Desktop when you sign in to your computer** w **Settings → General** Docker Desktop. Kontenery Toolkit używają `restart: always`, więc Docker uruchamia je ponownie, gdy tylko Docker Desktop działa, bez `bin/up`. Dopóki po ponownym uruchomieniu nikt nie zaloguje się na Macu, instancja pozostaje wyłączona.

<Info>

Mac, który pozostaje wybudzony, zużywa więcej energii. Dla usługi, która musi być zawsze dostępna, zalecamy serwer Linux, zobacz [Linux](/pl/on-premises/installation/using-docker-compose/linux).

</Info>

### Codzienne użytkowanie {#daily-use}

Otwórz Docker Desktop, zanim zaczniesz zarządzać instancją. W nowym terminalu:

```bash
export PATH="$(brew --prefix gnu-sed)/libexec/gnubin:$PATH"
cd "$HOME/ayakaleaf-toolkit"
```

| Zadanie | Polecenie |
| --- | --- |
| Uruchomienie istniejących kontenerów | `bin/start` |
| Zatrzymanie kontenerów z zachowaniem danych | `bin/stop` |
| Zastosowanie zmian konfiguracji | `bin/up -d` |
| Sprawdzenie stanu | `bin/docker-compose ps` |
| Odczyt logów uruchamiania | `bin/docker-compose logs --tail=100 sharelatex` |
| Odczyt logów kompilatora | `bin/logs -f clsi` |

`bin/start` nie stosuje zmian w `config/`: po edycji konfiguracji uruchom `bin/up -d`. Zachowaj `config/` i `data/` oraz postępuj zgodnie z instrukcją [Dane i kopie zapasowe](/pl/on-premises/maintenance/data-and-backups) przed aktualizacją lub przeniesieniem instalacji. Kopiowanie plików bazy danych w trakcie zapisu przez MongoDB nie daje spójnej kopii zapasowej.

Do użytku lokalnego pozostaw instancję na `127.0.0.1`. Aby obsługiwać inne komputery, świadomie ustaw adres nasłuchiwania, adres URL witryny i HTTPS, zobacz krok [5. Personalizacja instancji](/pl/on-premises/installation/using-docker-compose/linux/5.-personalizing-your-instance) przewodnika dla systemu Linux.

Jeśli coś nie działa, zobacz [Rozwiązywanie problemów](/pl/on-premises/installation/using-docker-compose/macos/troubleshooting).
