### Inicjalizacja kończy się błędem invalid command code {#initialization-fails-with-invalid-command-code}

`bin/init` zgłasza `sed: ... invalid command code`, gdy trafi na BSD sed z macOS. Umieść GNU sed w `PATH` zgodnie z krokiem [1. Pobierz Toolkit](/pl/on-premises/installation/using-docker-compose/macos/1.-download-the-toolkit) i sprawdź `sed --version`.

Nieudana inicjalizacja może pozostawić wszystkie trzy pliki w `config/` z pustym `OVERLEAF_INVITE_TOKEN_SECRET`. Ponowne uruchomienie `bin/init` zgłasza wtedy `Config files already exist`. W przypadku nowej instalacji, która nigdy nie została uruchomiona, przenieś te trzy pliki do katalogu kopii zapasowej i uruchom `bin/init` ponownie. W przypadku istniejącej instancji zachowaj jej konfigurację i sekrety i nie usuwaj jej plików tylko po to, aby `bin/init` uruchomił się ponownie.

### MongoDB ciągle się restartuje {#mongodb-keeps-restarting}

Odczytaj logi MongoDB i wersję jądra maszyny wirtualnej Dockera:

```bash
bin/docker-compose logs --tail=100 mongo
docker info --format '{{.KernelVersion}}'
```

Jeśli log wskazuje na niezgodność z jądrem Linux, wykonaj krok [Sprawdź jądro Linux maszyny wirtualnej Dockera](/pl/on-premises/installation/using-docker-compose/macos/5.-personalizing-your-instance#check-the-docker-vms-linux-kernel) i ponownie uruchom `bin/up -d`. Sam kod wyjścia `137` nie dowodzi, że MongoDB zabrakło pamięci: sprawdź stan kontenera i logi. Starszy problem z MongoDB w Docker Desktop opisano też w sekcji [Rozwiązywanie problemów](/pl/on-premises/support/troubleshooting).

### Nie można połączyć się z demonem Dockera {#cannot-connect-to-the-docker-daemon}

Uruchom Docker Desktop i sprawdź wybrany kontekst Dockera, zobacz [0. Instalacja Docker Desktop](/pl/on-premises/installation/using-docker-compose/macos/0.-setup-docker-desktop). Jeśli `docker info` działa, ale kompilacje nie mogą dotrzeć do Dockera, sprawdź ustawienia gniazda w `config/overleaf.rc` i przeczytaj logi `clsi`. Działający Docker CLI na Macu nie dowodzi, że montowanie gniazda w aplikacji jest poprawne.

### Strona się otwiera, ale kompilacje kończą się błędem {#the-page-opens-but-compiles-fail}

Sprawdź, czy obraz TeX Live istnieje lokalnie i czy odpowiada architekturze silnika Dockera:

```bash
docker image inspect ghcr.io/ayaka-notes/texlive-full:2026.1 \
  --format '{{.Os}}/{{.Architecture}}'
bin/logs -f clsi
```

Na komputerach z Apple silicon obraz powinien mieć postać `linux/arm64`. Sprawdź, czy `SERVER_PRO` i `SIBLING_CONTAINERS_ENABLED` mają wartość `true`, a następnie zastosuj zmiany poleceniem `bin/up -d`. Jeśli logi zgłaszają brakujący katalog kompilacji, sprawdź udostępnianie plików w Docker Desktop i lokalizację `OVERLEAF_DATA_PATH`. Nie wyłączaj kompilacji w piaskownicy, aby ukryć błąd montowania.

### Not a directory lub brakujący bind mount {#not-a-directory-or-a-bind-mount-is-missing}

Plik hosta montowany przez nadpisanie mógł zostać usunięty albo Docker mógł utworzyć katalog w miejscu, w którym powinien być plik. Sprawdź ścieżkę źródłową na hoście oraz to, czy montowanie oczekuje pliku, czy katalogu. Przywróć plik konfiguracyjny, zanim odtworzysz kontener. Instalacja w `/tmp` może napotkać ten problem, gdy macOS usunie pliki tymczasowe.

### Konflikty portów lub nazw kontenerów {#port-or-container-name-conflicts}

Jeśli port `8080` jest zajęty, wybierz inny port w `config/overleaf.rc`, odpowiednio ustaw `OVERLEAF_SITE_URL` i ponownie uruchom `bin/up -d`.

Toolkit nadaje swoim kontenerom stałe nazwy, takie jak `sharelatex`, `mongo` i `redis`. Sama zmiana `PROJECT_NAME` nie uniezależnia od siebie dwóch instalacji Toolkit. Przed uruchomieniem drugiej instancji sprawdź `docker ps -a` i użyj innych nazw kontenerów w nadpisaniu Compose, innego portu oraz osobnych katalogów danych. Nie usuwaj kontenerów ani danych istniejącego wdrożenia, aby rozwiązać konflikt nazw.

### Instancja po pewnym czasie jest niedostępna {#the-instance-is-unreachable-after-a-while}

Mac prawdopodobnie przeszedł w stan uśpienia albo Docker Desktop został zamknięty. Zobacz [Utrzymywanie dostępności instancji](/pl/on-premises/installation/using-docker-compose/macos/6.-post-installation-tasks#keep-the-instance-available).

### `bin/doctor` informuje, że to nie jest Linux, lub prosi o logowanie do Quay {#bin/doctor-says-this-is-not-linux-or-asks-for-a-quay-login}

Oba ostrzeżenia są w macOS z publicznym obrazem oczekiwane, zobacz [2. Poznaj Toolkit](/pl/on-premises/installation/using-docker-compose/macos/2.-familiarize-yourself-with-the-toolkit). Zamiast tego sprawdź pobieranie obrazów, stan usług i wyniki kompilacji i nie ignoruj innych błędów w raporcie.
