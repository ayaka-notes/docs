---
title: 5. Personalizacja instancji
description: Ustaw port, adres URL witryny i obraz TeX Live dla lokalnej instancji na Macu, sprawdź jądro maszyny wirtualnej Dockera i uruchom Ayakaleaf Pro.
icon: square-sliders
---

<Steps>
<Step title="Ustawienia kontenerów">
Zmień te istniejące wpisy w `config/overleaf.rc`:

```bash title="config/overleaf.rc"
PROJECT_NAME=ayakaleaf-macos
SERVER_PRO=true
OVERLEAF_LISTEN_IP=127.0.0.1
OVERLEAF_PORT=8080
SIBLING_CONTAINERS_ENABLED=true
DOCKER_SOCKET_PATH=/var/run/docker.sock
```

Zachowaj domyślne ścieżki danych oraz dołączone usługi MongoDB i Redis. Przy `OVERLEAF_LISTEN_IP=127.0.0.1` instancję mogą otworzyć tylko przeglądarki na tym Macu.
</Step>

<Step title="Ustawienia aplikacji">
W `config/variables.env` ustaw te wartości, zastępując wszystkie aktywne wpisy o tych samych nazwach:

```dotenv title="config/variables.env"
OVERLEAF_SITE_URL=http://localhost:8080
TEX_LIVE_DOCKER_IMAGE=ghcr.io/ayaka-notes/texlive-full:2026.1
ALL_TEX_LIVE_DOCKER_IMAGES=ghcr.io/ayaka-notes/texlive-full:2026.1
ALL_TEX_LIVE_DOCKER_IMAGE_NAMES="TeX Live 2026"
```

Wygeneruj sekret sesji:

```bash
openssl rand -hex 32
```

Dodaj wynik jako `OVERLEAF_SESSION_SECRET` w `config/variables.env`. Bez niego każde `bin/up`, które odtwarza kontener, wylogowuje wszystkich użytkowników, zobacz [Zmienne środowiskowe](/pl/on-premises/configuration/overleaf-toolkit/environment-variables).

Dla lokalnej instancji bez poczty e-mail pozostaw nieustawione ustawienia SMTP oraz `OVERLEAF_EMAIL_FROM_ADDRESS`. Git Bridge, uwierzytelnianie zewnętrzne i inne integracje możesz dodać później, korzystając z ich [stron konfiguracji](/pl/on-premises/configuration/overleaf-toolkit).
</Step>

<Step id="check-the-docker-vms-linux-kernel" title="Sprawdź jądro Linux maszyny wirtualnej Dockera">
MongoDB działa na jądrze Linux maszyny wirtualnej Docker Desktop, a nie na macOS. Sprawdź jego wersję przed pierwszym uruchomieniem:

```bash
docker info --format '{{.KernelVersion}}'
```

MongoDB dokumentuje niezgodność z jądrami Linux od **6.19 do 7.0.13**, która dotyczy również MongoDB w Dockerze. Rozwiązaniem jest jądro **7.0.14 lub nowsze**, dostarczane wraz z aktualizacją Docker Desktop, zobacz [uwagi produkcyjne MongoDB](https://www.mongodb.com/docs/manual/administration/production-notes/).

Jeśli maszyna wirtualna Dockera używa jądra z tego zakresu, dodaj poniższy fragment do `config/docker-compose.override.yml`, scalając go z sekcją `services`, którą już tam masz:

```yaml title="config/docker-compose.override.yml"
services:
  mongo:
    environment:
      GLIBC_TUNABLES: glibc.pthread.rseq=1
```

<Warning>

Zaktualizuj do poprawionego jądra, gdy będzie dostępne. Jeśli Twoje jądro jest spoza tego zakresu, to obejście jest niepotrzebne.

</Warning>
</Step>

<Step title="Uruchom instancję">
W katalogu Toolkit uruchom:

```bash
bin/up -d
```

Toolkit inicjalizuje zestaw replik MongoDB, pobiera obraz TeX Live i uruchamia aplikację. Pierwsze pobieranie trwa chwilę. Aby śledzić postęp:

```bash
bin/docker-compose ps
bin/docker-compose logs --tail=100 -f sharelatex
```

Naciśnij `Ctrl+C`, aby przestać śledzić logi. Kontenery nadal działają.

Sprawdź opublikowany port i stronę pierwszego uruchomienia:

```bash
bin/docker-compose port sharelatex 80
curl -I http://localhost:8080/launchpad
```

Port powinien mieć postać `127.0.0.1:8080`.
</Step>
</Steps>

<Info>

Aby później otworzyć instancję z innych komputerów, zmień adres nasłuchiwania i adres URL witryny oraz skonfiguruj HTTPS, zgodnie z opisem w kroku [5. Personalizacja instancji](/pl/on-premises/installation/using-docker-compose/linux/5.-personalizing-your-instance) przewodnika dla systemu Linux. Mac musi wtedy pozostawać wybudzony, zobacz [Utrzymywanie dostępności instancji](/pl/on-premises/installation/using-docker-compose/macos/6.-post-installation-tasks#keep-the-instance-available).

</Info>
