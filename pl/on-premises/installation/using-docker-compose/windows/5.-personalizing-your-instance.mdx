---
title: 5. Personalizacja instancji
description: Ustaw port, adres URL witryny i obraz TeX Live, włącz kompilacje w piaskownicy i uruchom Ayakaleaf Pro w WSL 2.
icon: square-sliders
---

Uruchamiaj polecenia i edytuj pliki w **Ubuntu**, w katalogu `~/ayakaleaf-toolkit`.

<Steps>
<Step title="Ustawienia kontenerów">
Zmień istniejące wpisy w `config/overleaf.rc`:

```bash title="config/overleaf.rc"
PROJECT_NAME=ayakaleaf-wsl
SERVER_PRO=true
OVERLEAF_LISTEN_IP=127.0.0.1
OVERLEAF_PORT=8080
SIBLING_CONTAINERS_ENABLED=true
DOCKER_SOCKET_PATH=/var/run/docker.sock
```

Zachowaj domyślne ścieżki danych oraz dołączone usługi MongoDB i Redis. Port `8080` jest przeznaczony dla lokalnej przeglądarki w systemie Windows; powiązanie z `127.0.0.1` sprawia, że pozostaje on lokalny. Kompilacje w piaskownicy używają osobnego kontenera Linux dla każdej kompilacji, zamiast uruchamiać TeX w kontenerze aplikacji. Gniazdo Dockera pozwala aplikacji tworzyć te kontenery, a Toolkit dostarcza ścieżkę hosta dla danych kompilacji w `data/overleaf/data/compiles`.
</Step>

<Step title="Ustawienia aplikacji">
W `config/variables.env` ustaw te wartości, zastępując wszystkie aktywne wpisy o tych samych nazwach:

```dotenv title="config/variables.env"
OVERLEAF_SITE_URL=http://localhost:8080
TEX_LIVE_DOCKER_IMAGE=ghcr.io/ayaka-notes/texlive-full:2026.1
ALL_TEX_LIVE_DOCKER_IMAGES=ghcr.io/ayaka-notes/texlive-full:2026.1
ALL_TEX_LIVE_DOCKER_IMAGE_NAMES="TeX Live 2026"
```

Pełny obraz zawiera pakiety i fonty potrzebne w szerokim zakresie projektów. Przeznacz na niego i na aplikację co najmniej 40 GB wolnego miejsca, plus miejsce na dane projektów i przyszłe aktualizacje.

Do szybkiego testu wdrożenia użyj zamiast tego mniejszego obrazu **basic**. Wystarcza on do prostego testu artykułu w kroku 6, ale nie zawiera pełnego zestawu pakietów i fontów:

```dotenv
TEX_LIVE_DOCKER_IMAGE=ghcr.io/ayaka-notes/texlive-basic:2026.1
ALL_TEX_LIVE_DOCKER_IMAGES=ghcr.io/ayaka-notes/texlive-basic:2026.1
ALL_TEX_LIVE_DOCKER_IMAGE_NAMES="TeX Live 2026 Basic"
```

Wybierz jeden z tych zestawów, bez zduplikowanych aktywnych kluczy. [Dockerfile](https://github.com/ayaka-notes/texlive-full/blob/main/texlive/2026/Dockerfile.basic) obrazu basic zawiera `latexmk`, XeTeX i `fontspec`, ale nie `ctex` ani pełnej kolekcji fontów. Brak pakietu LaTeX w obrazie basic sam w sobie nie wskazuje na problem z piaskownicą.

Wygeneruj sekret sesji:

```bash
openssl rand -hex 32
```

Dodaj wynik jako `OVERLEAF_SESSION_SECRET` w `config/variables.env`. Zachowaj też wygenerowany sekret tokenów zaproszeń. Dla lokalnej instancji bez poczty e-mail pozostaw nieustawione ustawienia SMTP oraz `OVERLEAF_EMAIL_FROM_ADDRESS`.
</Step>

<Step title="Uruchom instancję">
```bash
bin/up -d
```

Toolkit uruchamia MongoDB, inicjalizuje jej zestaw replik, pobiera wybrany obraz TeX Live oraz uruchamia Redis i aplikację. Podczas pobierania dużego obrazu może się wydawać, że proces się zatrzymał. Nie uruchamiaj drugiego `bin/up`, dopóki pierwszy nadal działa.

W innym terminalu Ubuntu sprawdź:

```bash
cd "$HOME/ayakaleaf-toolkit"
bin/docker-compose ps
bin/docker-compose logs --tail=100 mongo
bin/docker-compose logs --tail=100 -f sharelatex
```

Naciśnij `Ctrl+C`, aby przestać śledzić logi; odłączone kontenery nadal działają. Jeśli uruchamianie kończy się błędem na MongoDB, przed ponowną próbą wykonaj kroki z sekcji [MongoDB nie uruchamia się](/pl/on-premises/installation/using-docker-compose/windows/troubleshooting#mongodb-fails-to-start). Nie usuwaj jej katalogu danych, aby zresetować istniejącą instalację.

Sprawdź port i stronę pierwszego uruchomienia:

```bash
bin/docker-compose port sharelatex 80
curl -I http://localhost:8080/launchpad
```

Port powinien mieć postać `127.0.0.1:8080`. Jeśli żądanie HTTP początkowo się nie powiedzie, poczekaj na zakończenie inicjalizacji aplikacji.
</Step>

<Step title="Otwórz instancję z systemu Windows">
W **przeglądarce w systemie Windows** otwórz [http://localhost:8080/launchpad](http://localhost:8080/launchpad). Również w systemie Windows używaj tego adresu zamiast tymczasowego adresu IP WSL.

Aby sprawdzić dostęp HTTP z systemu Windows niezależnie od przeglądarki, uruchom w **PowerShell**:

```powershell
curl.exe -I http://localhost:8080/launchpad
```

Jeśli Ubuntu może otworzyć stronę, ale Windows nie, zobacz [Windows nie może otworzyć localhost](/pl/on-premises/installation/using-docker-compose/windows/troubleshooting#windows-cannot-open-localhost).
</Step>
</Steps>
