Ayakaleaf Pro używa kontenerów Linux. W systemie Windows zainstaluj Docker Desktop z backendem WSL 2 i uruchamiaj skrypty Toolkit w Ubuntu.

WSL 2 zapewnia jądro Linux. Docker Desktop zarządza silnikiem Dockera we własnym środowisku `docker-desktop`; włączenie **WSL Integration** pozwala Docker CLI w Ubuntu komunikować się z tym silnikiem. Toolkit uruchamia następnie aplikację, MongoDB i Redis jako kontenery. Przy włączonych kompilacjach w piaskownicy aplikacja używa gniazda Dockera silnika, aby uruchamiać osobny kontener TeX Live dla każdej kompilacji. Nie potrzebujesz instalacji MongoDB, Redis ani TeX Live w systemie Windows.

<Steps>
<Step title="Zainstaluj WSL 2 i Ubuntu">
Otwórz w systemie Windows **PowerShell jako administrator** i uruchom:

```powershell
wsl --install -d Ubuntu
```

Uruchom ponownie system Windows, jeśli pojawi się taka prośba. Otwórz **Ubuntu** z menu Start i utwórz linuksową nazwę użytkownika i hasło. To konto służy do `sudo` w Ubuntu; jest niezależne od Twojego logowania do systemu Windows.

Wróć do **PowerShell**, zaktualizuj WSL i sprawdź dystrybucję:

```powershell
wsl --update
wsl --version
wsl --list --verbose
```

Wiersz Ubuntu musi pokazywać **VERSION 2**. Jeśli pokazuje 1, użyj dokładnej nazwy dystrybucji z listy:

```powershell
wsl --set-version Ubuntu 2
```

Docker wymaga WSL w wersji **2.1.5 lub nowszej**; wersja oprogramowania WSL z `wsl --version` i kolumna **VERSION 2** dystrybucji to dwie różne kontrole. Jeśli instalacja się nie powiedzie, zobacz [rozwiązywanie problemów z instalacją](/pl/on-premises/installation/using-docker-compose/windows/troubleshooting#wsl-or-docker-reports-that-virtualization-is-unavailable) oraz [instrukcje instalacji od Microsoft](https://learn.microsoft.com/en-us/windows/wsl/install), a jeśli WSL zgłasza, że wirtualizacja jest niedostępna, włącz wirtualizację sprzętową w BIOS/UEFI.
</Step>

<Step title="Zainstaluj i uruchom Docker Desktop">
Pobierz [Docker Desktop for Windows](https://docs.docker.com/desktop/setup/install/windows-install/) dla swojego procesora i uruchom instalator. Jeśli zostanie zaproponowany, wybierz backend **WSL 2**. Otwórz **Docker Desktop** z menu Start systemu Windows i poczekaj, aż silnik się uruchomi.

W **Settings → General** Docker Desktop włącz **Use WSL 2 based engine**, jeśli ta opcja jest widoczna. W **Settings → Resources → WSL Integration** włącz integrację dla **Ubuntu**, a następnie wybierz **Apply** lub **Apply & restart**. Jeśli Ubuntu nie jest Twoją domyślną dystrybucją, włącz jawnie jej własny przełącznik.

Jeśli brakuje WSL Integration, sprawdź, czy Docker Desktop używa **Linux containers**. Zobacz [przewodnik Dockera po backendzie WSL 2](https://docs.docker.com/desktop/features/wsl/).

W tym przewodniku używaj integracji Docker Desktop. Instalacja drugiego silnika Docker Engine poleceniem `apt install docker.io` lub uruchamianie `dockerd` w Ubuntu tworzy osobną konfigurację i może powodować konflikty. Jeśli już używasz silnika w Ubuntu, przed przełączeniem postępuj zgodnie ze wskazówkami Dockera dotyczącymi migracji; zachowaj istniejące dane aplikacji i kopie zapasowe.
</Step>

<Step title="Sprawdź Dockera z poziomu Ubuntu">
Otwórz terminal **Ubuntu**. Uruchom w nim te polecenia, bez `sudo`:

```bash
docker version
docker compose version
docker ps
```

`docker version` musi pokazywać zarówno **Client**, jak i **Server**. Pusta lista kontenerów jest normalna w nowej instalacji. Samo `docker --version` nie dowodzi, że silnik działa.

Jeśli `docker` jest niedostępny lub nie może się połączyć, otwórz ponownie Ubuntu po zastosowaniu WSL Integration i sprawdź, czy Docker Desktop działa. Zobacz [Rozwiązywanie problemów](/pl/on-premises/installation/using-docker-compose/windows/troubleshooting#docker-is-unavailable-in-ubuntu).
</Step>

<Step title="Sprawdź zasoby i gniazdo Dockera">
Sprawdź zasoby widoczne dla Dockera:

```bash
docker info --format 'CPUs={{.NCPU}} Memory={{.MemTotal}} Kernel={{.KernelVersion}}'
df -h "$HOME"
ls -l /var/run/docker.sock
```

Dla małej lokalnej instancji 4 procesory i 8 GB pamięci dostępne dla Dockera to sugerowany punkt wyjścia, a nie zmierzone minimum. Zostaw też wystarczająco dużo pamięci dla systemu Windows. W backendzie WSL 2 limity zasobów zarządzane są przez [ustawienia WSL](https://learn.microsoft.com/en-us/windows/wsl/wsl-config), a nie przez suwaki zasobów Docker Desktop znane z Maca. Zmiany wymagające `wsl --shutdown` przerywają działanie wszystkich uruchomionych dystrybucji WSL i obciążeń Dockera; zastosuj je przed uruchomieniem instancji.

Pozostaw `DOCKER_SOCKET_PATH=/var/run/docker.sock` w konfiguracji Toolkit. Aplikacja potrzebuje tego gniazda silnika do kompilacji w piaskownicy. Nie zmieniaj jego uprawnień na `777`, aby naprawić błędy połączenia; zamiast tego przywróć integrację Docker Desktop.
</Step>
</Steps>
