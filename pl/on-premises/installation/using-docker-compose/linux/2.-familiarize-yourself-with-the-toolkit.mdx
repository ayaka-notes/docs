### Rozejrzyjmy się {#taking-a-look-around}

Masz już lokalną kopię Toolkitu, więc przyjrzyjmy się strukturze repozytorium za pomocą polecenia `ls`.

```bash title="Run this"
ls -l
```

<Info>

Polecenie `ls -l` wyświetla szczegółową, długą listę zawartości katalogu, zawierającą dodatkowe informacje o plikach, takie jak uprawnienia, właściciel i rozmiar.

</Info>

Jeśli klonowanie przebiegło pomyślnie, powinieneś zobaczyć coś takiego:

```text
drwxr-xr-x 3 fry fry  4096 Aug 30 14:16 bin
-rw-r--r-- 1 fry fry  6465 Aug 30 14:16 CHANGELOG.md
drwxr-xr-x 2 fry fry  4096 Sep  6 12:43 config
drwxr-xr-x 5 fry fry  4096 Aug 30 14:22 data
drwxr-xr-x 3 fry fry  4096 Aug 30 14:16 doc
drwxr-xr-x 3 fry fry  4096 Aug 30 14:16 lib
-rw-r--r-- 1 fry fry 34520 Aug 30 14:16 LICENSE
-rw-r--r-- 1 fry fry  1178 Aug 30 14:16 README.md
```

<Info>

Wszystkie pliki konfiguracyjne należące do użytkownika znajdują się w katalogu `config/`. Ten katalog jest **wyłączony** z systemu kontroli wersji git, więc aktualizacja Toolkitu go nie zmieni.

</Info>

## Struktura repozytorium {#repository-layout}

| Nazwa    | Opis |
| -------- | ---- |
| `bin`    | Ten folder zawiera zestaw skryptów pomagających zarządzać instancją serwera Overleaf. Więcej o tych skryptach przeczytasz w sekcji Polecenia poniżej. |
| `config` | Ten folder zawiera Twoje lokalne pliki konfiguracyjne. |
| `lib`    | Ten folder zawiera bazowe pliki konfiguracyjne używane przez Toolkit. |
| `data`   | Domyślnie ten folder zawiera lokalizację przechowywania danych MongoDb, Redis i Overleaf. Więcej informacji znajdziesz w sekcji [Dane trwałe](/pl/on-premises/configuration/overleaf-toolkit/files-and-locations#persistent-data) poniżej. |

<Warning>

Zalecamy, aby **nie** modyfikować bezpośrednio plików poza folderem `/config`. Jeśli musisz wprowadzić zmiany, możesz to zrobić za pomocą zmiennych środowiskowych ustawianych w pliku **config/variables.env** lub **config/overleaf.rc**.\
Na przykład, aby ustawić obraz usługi `mongo`, zamiast bezpośrednio edytować `lib/docker-compose.mongo.yml`, ustaw obraz za pomocą zmiennej środowiskowej `MONGO_IMAGE` w pliku `config/overleaf.rc`. Więcej informacji znajdziesz na stronie [Ustawienia Toolkitu](/pl/on-premises/configuration/overleaf-toolkit/toolkit-settings).

</Warning>

<Info>

Toolkit **nie** zmieni żadnych danych w katalogu `config/` bez Twojej zgody.

</Info>

## Polecenia {#commands}

Uruchamiaj te skrypty z katalogu Toolkit. Każdy z nich wyświetla swoje opcje po podaniu `--help`.

| Polecenie | Działanie |
| --- | --- |
| `bin/init` | Tworzy pliki konfiguracyjne w `config/` przy pierwszym uruchomieniu. `bin/init --tls` dodaje konfigurację proxy TLS NGINX. |
| `bin/up` | Tworzy i uruchamia kontenery (`bin/docker-compose up`). Dodaj `-d`, aby działały w tle zamiast śledzenia logów. Uruchamiaj je po każdej zmianie w `config/`: odtwarza kontenery, których konfiguracja się zmieniła. |
| `bin/start` | Ponownie uruchamia istniejące kontenery (`bin/docker-compose start`). Nie stosuje zmian konfiguracji. |
| `bin/stop` | Zatrzymuje kontenery, ale ich nie usuwa (`bin/docker-compose stop`). |
| `bin/docker-compose down` | Usuwa kontenery i ich sieć, zachowując dane. `bin/up -d` tworzy je ponownie. |
| `bin/docker-compose` | Uruchamia `docker compose` z plikami Toolkit, na przykład `bin/docker-compose ps` lub `bin/docker-compose restart sharelatex`. |
| `bin/logs` | Wyświetla lub śledzi logi jednej lub kilku usług, na przykład `bin/logs -f web`. |
| `bin/error-logs` | Działa jak `bin/logs`, ale wyświetla tylko błędy. |
| `bin/shell` | Otwiera powłokę wewnątrz kontenera `sharelatex`. |
| `bin/mongo` | Otwiera powłokę MongoDB dla bazy danych `sharelatex`. |
| `bin/run-script` | Uruchamia skrypt dostarczany wewnątrz kontenera `sharelatex`. |
| `bin/doctor` | Sprawdza hosta i konfigurację oraz wyświetla raport, który możesz udostępnić, prosząc o pomoc. |
| `bin/images` | Wyświetla listę obrazów Docker Overleaf na hoście. |
| `bin/backup-config` | Kopiuje katalog `config/` do lokalizacji kopii zapasowej (kopia, zip lub tar). |
| `bin/upgrade` | Aktualizuje Toolkit i obraz Overleaf krok po kroku, zobacz [Aktualizacja wdrożenia](/pl/on-premises/maintenance/upgrading-your-deployment). |
| `bin/rename-env-vars-5-0`, `bin/rename-rc-vars` | Jednorazowe migracje starych nazw zmiennych `SHARELATEX_*` na `OVERLEAF_*`. |

### Co przetrwa przebudowę {#what-survives-a-rebuild}

Przebudowa zastępuje kontener nowym. Poza kontenerem znajdują się tylko katalogi danych (domyślnie `data/`) i `config/`, więc wszystko inne znika razem z nim: pakiety zainstalowane lub pliki edytowane przez `bin/shell` oraz logi w `/var/log/overleaf`, chyba że ustawisz [`OVERLEAF_LOG_PATH`](/pl/on-premises/configuration/overleaf-toolkit/logging).

| Polecenie | Zastępuje kontener | Zmiany wprowadzone w nim | Logi | `data/` i `config/` |
| --- | --- | --- | --- | --- |
| `bin/stop`, a potem `bin/start` | Nie | Zachowane | Zachowane | Zachowane |
| `bin/docker-compose restart sharelatex` | Nie | Zachowane | Zachowane | Zachowane |
| `bin/up`, bez zmian w `config/` | Nie | Zachowane | Zachowane | Zachowane |
| `bin/up`, po zmianie w `config/` | Tak | **Utracone** | **Utracone** | Zachowane |
| `bin/up -d --force-recreate` | Tak | **Utracone** | **Utracone** | Zachowane |
| `bin/docker-compose down`, a potem `bin/up -d` | Tak | **Utracone** | **Utracone** | Zachowane |
| `bin/upgrade`, do nowej wersji | Tak | **Utracone** | **Utracone** | Zachowane |

* Polecenia, które zachowują kontener, nie stosują zmian w `config/`. Do tego służy `bin/up`.
* Aby przebudować wszystkie kontenery, uruchom `bin/docker-compose down`, a potem `bin/up -d`. Twoje projekty, użytkownicy i historia pozostają.
* Trwałe zmiany wprowadzaj przez `config/variables.env`, `config/overleaf.rc` lub `config/docker-compose.override.yml`, a nie wewnątrz kontenera.
* Bez `OVERLEAF_SESSION_SECRET` nowy kontener podpisuje sesje nowym sekretem, więc wszyscy muszą zalogować się ponownie.
* Twoje dane są usuwane tylko wtedy, gdy sam usuniesz katalogi danych. Przed aktualizacją wykonaj [kopię zapasową](/pl/on-premises/maintenance/data-and-backups).

<Info>

Jeśli każde `bin/up` wylogowuje wszystkich użytkowników, ustaw `OVERLEAF_SESSION_SECRET`. Bez tej zmiennej ciasteczka sesji są podpisywane sekretem generowanym od nowa przy każdym odtworzeniu kontenera, zobacz sekcję Pytania i odpowiedzi w [Zmienne środowiskowe](/pl/on-premises/configuration/overleaf-toolkit/environment-variables).

</Info>
