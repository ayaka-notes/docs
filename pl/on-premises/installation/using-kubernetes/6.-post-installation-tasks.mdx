### Tworzenie pierwszego konta administratora {#creating-your-first-administrator-account}

Otwórz `OVERLEAF_SITE_URL` z dopisanym `/launchpad`, na przykład `http://192.0.2.10:30080/launchpad`, i zarejestruj konto administratora tak jak w [zadaniach poinstalacyjnych Toolkit](/pl/on-premises/installation/using-docker-compose/linux/6.-post-installation-tasks). Następnie utwórz przykładowy projekt i go skompiluj.

Użytkowników możesz też tworzyć z wiersza poleceń:

```bash
kubectl -n overleaf exec deploy/overleaf -- bash -c \
  'cd /overleaf/services/web && node modules/server-ce-scripts/scripts/create-user.mjs --admin --email=admin@example.com'
```

Polecenie wyświetla link do ustawienia hasła.

### Sprawdzanie, czy kompilacje są izolowane {#checking-that-compiles-are-sandboxed}

Skompiluj projekt, a następnie sprawdź węzeł, na którym działa pod:

```bash
kubectl -n overleaf get pod -l app=overleaf -o wide   # NODE column
# on that node:
sudo docker ps -a --filter ancestor=ghcr.io/ayaka-notes/texlive-full:2026.1
ls -ln /srv/overleaf/compiles                          # owned by uid 33 (www-data)
```

Każda kompilacja pojawia się jako krótkotrwały kontener o nazwie `project-<project id>-<user id>-...`.

### Logi i powłoka {#logs-and-a-shell}

| Toolkit          | Kubernetes                                                               |
| ---------------- | ------------------------------------------------------------------------ |
| `bin/logs web`   | `kubectl -n overleaf exec deploy/overleaf -- tail -f /var/log/overleaf/web.log` |
| `bin/shell`      | `kubectl -n overleaf exec -it deploy/overleaf -- bash`                    |
| `bin/up`         | `kubectl apply -f .`, a następnie `kubectl -n overleaf rollout restart deployment/overleaf` |

Kontener zapisuje jeden plik logu na usługę w `/var/log/overleaf/` (`web.log`, `clsi.log`, `real-time.log`, `document-updater.log`, ...); `kubectl logs` pokazuje dane wyjściowe uruchamiania.

### Co przetrwa restart {#what-survives-a-restart}

`kubectl rollout restart` zastępuje pody. Zostaje tylko to, co jest na wolumenie. Zmiany wprowadzone w podzie przez `kubectl exec`, takie jak zainstalowane pakiety lub edytowane pliki, znikają razem z nim, podobnie jak logi, chyba że `/var/log/overleaf` znajduje się na wolumenie, zobacz [Logowanie](/pl/on-premises/configuration/kubernetes/logging). Trwałe zmiany wprowadzaj w manifestach.

### Pytania i odpowiedzi {#q&a}

<Accordion title="Kompilacja kończy się niepowodzeniem lub nigdy się nie kończy.">

<strong>Odpowiedź:</strong> Sprawdź na węźle, na którym działa pod, czy Docker jest uruchomiony i ma obraz wskazany w `TEX_LIVE_DOCKER_IMAGE` oraz czy `SANDBOXED_COMPILES_HOST_DIR_*` odpowiadają ścieżkom `hostPath`. Plik `/var/log/overleaf/clsi.log` w podzie wskazuje krok, który się nie powiódł.

</Accordion>
