Kubernetes uruchamia te same obrazy co Toolkit. Nie ma osobnego obrazu dla Kubernetes.

| Obraz                                                | Używany przez                                                           |
| ---------------------------------------------------- | ----------------------------------------------------------------------- |
| `ghcr.io/ayaka-notes/overleaf-pro:6.3.2`             | Deployment `overleaf`                                                   |
| `ghcr.io/ayaka-notes/overleaf-pro/git-bridge:6.3.2`  | [Integrację z Git](/pl/on-premises/configuration/kubernetes/integrations/git-integration) (opcjonalnie), ten sam tag co powyżej |
| `ghcr.io/ayaka-notes/texlive-*`                      | kompilacje, pobierane do Dockera na węzłach w [kroku 0](/pl/on-premises/installation/using-kubernetes/0.-prepare-the-nodes) |

Obrazy są publicznie dostępne w [ghcr.io](https://github.com/ayaka-notes/ayakaleaf-pro/pkgs/container/overleaf-pro/) dla amd64 i arm64, więc kubelet może je pobrać bez danych uwierzytelniających.

<Warning>

Zawsze używaj tagu wersji, takiego jak `6.3.2`, a nie `latest`. Aktualizacje uruchamiają migracje bazy danych i muszą przebiegać zgodnie z [Aktualizacją w Kubernetes](/pl/on-premises/maintenance/upgrading-on-kubernetes); ruchomy tag aktualizowałby pod za każdym razem, gdy zostanie on ponownie rozplanowany.

</Warning>

### Pytania i odpowiedzi

<Accordion title="Nasze węzły nie mają dostępu do ghcr.io. Co robić?">

<strong>Odpowiedź:</strong> Skopiuj obrazy do rejestru dostępnego dla węzłów i użyj tej nazwy w manifestach, na przykład:

```bash
docker pull ghcr.io/ayaka-notes/overleaf-pro:6.3.2
docker tag ghcr.io/ayaka-notes/overleaf-pro:6.3.2 registry.example.com/ayakaleaf/overleaf-pro:6.3.2
docker push registry.example.com/ayakaleaf/overleaf-pro:6.3.2
```

W przypadku rejestru bez TLS containerd potrzebuje na każdym węźle pliku `/etc/containerd/certs.d/<registry>/hosts.toml` z `server = "http://<registry>"` oraz `config_path` ustawionego jak w [kroku 0](/pl/on-premises/installation/using-kubernetes/0.-prepare-the-nodes). Sam Docker wypycha przez zwykły HTTP tylko do `localhost`, więc wypychaj przez `localhost:<port>` na hoście rejestru lub dodaj go do `insecure-registries`.

</Accordion>
