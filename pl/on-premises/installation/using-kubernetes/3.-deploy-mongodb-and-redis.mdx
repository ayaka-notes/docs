title: 3. Wdróż MongoDB i Redis
description: Uruchom MongoDB jako zestaw replik i Redis z trwałością danych lub wskaż własne instancje.
icon: database
---

Ayakaleaf Pro potrzebuje:

* **MongoDB 8** jako **zestawu replik** (korzysta z transakcji). Trzech członków rozmieszczonych na trzech węzłach przetrwa utratę węzła; jeden członek również działa.
* **Redis 7**, jednego serwera z trwałością AOF. Redis przechowuje zmiany, które nie zostały jeszcze zapisane w MongoDB, sesje oraz komunikaty między usługami Overleaf. Overleaf łączy się z jednym serwerem Redis: Sentinel i Redis Cluster nie są obsługiwane.

<Info>

Zamiast tego możesz korzystać z usług zarządzanych, takich jak MongoDB Atlas lub Redis Twojej chmury. Pomiń tę stronę i ustaw na nie `OVERLEAF_MONGO_URL` oraz `OVERLEAF_REDIS_HOST` w [kroku 4](/pl/on-premises/installation/using-kubernetes/4.-personalizing-your-instance).

</Info>

<Steps>
<Step title="MongoDB">
```yaml title="10-mongo.yaml" wrap
apiVersion: v1
kind: Service
metadata:
  name: mongo
  namespace: overleaf
spec:
  clusterIP: None                 # headless: gives mongo-0.mongo, mongo-1.mongo, ...
  publishNotReadyAddresses: true  # members must resolve each other before the set is initiated
  selector:
    app: mongo
  ports:
    - name: mongo
      port: 27017
---
apiVersion: apps/v1
kind: StatefulSet
metadata:
  name: mongo
  namespace: overleaf
spec:
  serviceName: mongo
  replicas: 3
  selector:
    matchLabels:
      app: mongo
  template:
    metadata:
      labels:
        app: mongo
    spec:
      affinity:
        podAntiAffinity:
          requiredDuringSchedulingIgnoredDuringExecution:
            - labelSelector:
                matchLabels:
                  app: mongo
              topologyKey: kubernetes.io/hostname
      containers:
        - name: mongo
          image: mongo:8.0
          args:
            - --replSet=overleaf
            - --bind_ip_all
            - --wiredTigerCacheSizeGB=0.25   # default is 50% of (RAM - 1 GB); size it for your nodes
          # env:
          #   - name: GLIBC_TUNABLES        # only on kernel 6.19+ (SERVER-121912)
          #     value: glibc.pthread.rseq=1
          ports:
            - containerPort: 27017
          readinessProbe:
            tcpSocket:
              port: 27017
          resources:
            requests:
              cpu: 100m
              memory: 384Mi
            limits:
              memory: 768Mi
          volumeMounts:
            - name: data
              mountPath: /data/db
  volumeClaimTemplates:
    - metadata:
        name: data
      spec:
        accessModes: [ReadWriteOnce]
        resources:
          requests:
            storage: 5Gi
---
# Initiates the replica set once. Safe to re-run: it does nothing when the set exists.
apiVersion: batch/v1
kind: Job
metadata:
  name: mongo-init-replica-set
  namespace: overleaf
spec:
  backoffLimit: 20
  template:
    spec:
      restartPolicy: OnFailure
      containers:
        - name: init
          image: mongo:8.0
          command:
            - mongosh
            - --quiet
            - --host=mongo-0.mongo
            - --eval
            - |
              try {
                rs.status()
                print('replica set already initiated')
              } catch (e) {
                rs.initiate({
                  _id: 'overleaf',
                  members: [
                    { _id: 0, host: 'mongo-0.mongo.overleaf.svc.cluster.local:27017' },
                    { _id: 1, host: 'mongo-1.mongo.overleaf.svc.cluster.local:27017' },
                    { _id: 2, host: 'mongo-2.mongo.overleaf.svc.cluster.local:27017' },
                  ],
                })
              }
```

```bash
kubectl apply -f 10-mongo.yaml
kubectl -n overleaf rollout status statefulset/mongo
kubectl -n overleaf wait --for=condition=complete job/mongo-init-replica-set --timeout=5m
kubectl -n overleaf exec mongo-0 -- mongosh --quiet --eval 'rs.status().members.map(m => m.name + " " + m.stateStr)'
```

Po kilku sekundach jeden członek powinien mieć stan `PRIMARY`, a pozostali `SECONDARY`. Job ponawia próby, dopóki wszyscy członkowie nie odpowiedzą, więc kilka nieudanych podów Job to normalne zjawisko.

* Usługa headless wymaga `publishNotReadyAddresses: true`: członkowie muszą odnaleźć się nawzajem po nazwie, zanim zestaw replik zacznie istnieć.
* Członkowie są dodawani pod swoimi stałymi nazwami (`mongo-0.mongo.overleaf.svc.cluster.local`), nigdy przez adresy IP podów, które zmieniają się przy każdym ponownym uruchomieniu.
* W przypadku jednego członka ustaw `replicas: 1` i pozostaw w Job tylko `mongo-0`.
</Step>

<Step title="Redis">
```yaml title="20-redis.yaml" wrap
apiVersion: v1
kind: Service
metadata:
  name: redis
  namespace: overleaf
spec:
  selector:
    app: redis
  ports:
    - name: redis
      port: 6379
---
apiVersion: apps/v1
kind: StatefulSet
metadata:
  name: redis
  namespace: overleaf
spec:
  serviceName: redis
  replicas: 1
  selector:
    matchLabels:
      app: redis
  template:
    metadata:
      labels:
        app: redis
    spec:
      containers:
        - name: redis
          image: redis:7.4
          args: [--appendonly, "yes"]
          ports:
            - containerPort: 6379
          readinessProbe:
            tcpSocket:
              port: 6379
          resources:
            requests:
              cpu: 50m
              memory: 128Mi
            limits:
              memory: 512Mi
          volumeMounts:
            - name: data
              mountPath: /data
  volumeClaimTemplates:
    - metadata:
        name: data
      spec:
        accessModes: [ReadWriteOnce]
        resources:
          requests:
            storage: 2Gi
```

```bash
kubectl apply -f 20-redis.yaml
kubectl -n overleaf rollout status statefulset/redis
```
</Step>

### Pytania i odpowiedzi

<Accordion title="MongoDB 8 ulega awarii przy uruchomieniu na najnowszym jądrze. Dlaczego?">

<strong>Odpowiedź:</strong> MongoDB 8 nie działa na jądrze Linux 6.19 i nowszych ([SERVER-121912](https://jira.mongodb.org/browse/SERVER-121912)). Odkomentuj zmienną środowiskową `GLIBC_TUNABLES` w `10-mongo.yaml`.

</Accordion>

<Accordion title="Ile pamięci potrzebuje MongoDB?">

<strong>Odpowiedź:</strong> Domyślnie MongoDB przeznacza na pamięć podręczną połowę pamięci węzła pomniejszoną o 1 GB i widzi pamięć węzła, a nie limit poda. Ustaw `--wiredTigerCacheSizeGB` odpowiednio do swoich węzłów; przy `0.25` każdy członek zużywał około 200–260 MiB na naszych testowych węzłach z 4 GB pamięci.

</Accordion>
