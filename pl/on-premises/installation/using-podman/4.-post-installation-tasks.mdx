### Utworzenie pierwszego konta administratora {#create-your-first-administrator-account}

Otwórz [http://localhost:8080/launchpad](http://localhost:8080/launchpad) lub swój `OVERLEAF_SITE_URL` z dopiskiem `/launchpad` i zarejestruj konto administratora. Od tego momentu wszystko działa jak w Dockerze: wykonaj krok [6. Zadania poinstalacyjne](/pl/on-premises/installation/using-docker-compose/linux/6.-post-installation-tasks) przewodnika po Dockerze, używając portu `8080` w jego linkach do `localhost`.

Utwórz przykładowy projekt i skompiluj go. PDF pokazuje, że kompilacje działają w swoich kontenerach TeX Live przez Podmana. Aby zobaczyć kontener kompilacji:

```bash title="List the compile containers"
podman ps -a --filter name=project- --format "{{.Names}} {{.Image}} {{.Status}}"
```

### Korzystanie z HTTPS {#use-https}

[Proxy TLS](/pl/on-premises/configuration/overleaf-toolkit/tls-proxy) z Toolkit działa na Podmanie: uruchom `bin/init --tls`, ustaw certyfikat i `NGINX_ENABLED=true`, jak tam opisano. Proxy nasłuchuje na portach `80` i `443`, których rootless Podman domyślnie nie może używać. Zezwól nieuprzywilejowanym użytkownikom na używanie portów od `80` w górę:

```bash title="Allow ports 80 and 443"
echo "net.ipv4.ip_unprivileged_port_start=80" | sudo tee /etc/sysctl.d/99-unprivileged-ports.conf
sudo sysctl --system
```

Pozwala to każdemu użytkownikowi serwera nasłuchiwać na tych portach, więc rób to tylko na serwerze przeznaczonym wyłącznie dla Ayakaleaf Pro. Następnie otwórz je w zaporze:

```bash title="Open ports 80 and 443"
sudo firewall-cmd --permanent --add-port=80/tcp --add-port=443/tcp
sudo firewall-cmd --reload
```

Ustaw `OVERLEAF_SITE_URL` na swój adres `https://` i uruchom `bin/up -d`. Zachowaj wartości domyślne `NGINX_HTTP_PORT=80` i `TLS_PORT=443`: przy innych portach przekierowanie z HTTP na HTTPS prowadzi do niewłaściwego portu.

<Info>

Gdy używasz proxy TLS, pozostaw `OVERLEAF_LISTEN_IP` ustawione na `127.0.0.1`, aby port `8080` nie był dostępny z innych komputerów.

</Info>

### Aktualizacja {#upgrade}

Aktualizuj za pomocą `bin/upgrade`, jak opisano w [Aktualizacja wdrożenia](/pl/on-premises/maintenance/upgrading-your-deployment). Na Podmanie polecenie to wypakowuje też profil seccomp nowej wersji do `config/seccomp/<version>/` i aktualizuje `SECCOMP_PROFILE`:

```text
Over-writing config/version with 6.3.4
Set SECCOMP_PROFILE=/home/<user>/overleaf-toolkit/config/seccomp/6.3.4/clsi-profile.json in config/variables.env
```

Po aktualizacji uruchom `bin/podman-setup`, aby sprawdzić konfigurację.

### Zmiana trybu SELinux {#change-the-selinux-mode}

`SELINUX_MODE` w `config/overleaf.rc` określa, jak SELinux ogranicza kontener `sharelatex`. Te strony konfigurują tryb `managed`; pozostałe tryby opisano w [Ustawienia Toolkit](/pl/on-premises/configuration/overleaf-toolkit/toolkit-settings). Po zmianie uruchom `bin/up -d`.
