---

<Steps>
<Step title="Klonowanie Toolkit">
Sklonuj **Ayakaleaf Toolkit** ([ayaka-notes/toolkit](https://github.com/ayaka-notes/toolkit)) do katalogu domowego i przejdź do niego:

```bash title="Clone the Toolkit" wrap
git clone https://github.com/ayaka-notes/toolkit.git ~/overleaf-toolkit
cd ~/overleaf-toolkit
```

Uruchamiaj wszystkie kolejne polecenia z tego katalogu.
</Step>

<Step title="Tworzenie konfiguracji">
```bash title="Run initialization"
bin/init
```

To polecenie tworzy `config/overleaf.rc`, `config/variables.env` i `config/version`, jak opisano w kroku [3. Inicjalizacja konfiguracji](/pl/on-premises/installation/using-docker-compose/linux/3.-initialize-the-configuration) przewodnika po Dockerze. `bin/init` nie potrzebuje jeszcze Podmana.
</Step>

<Step title="Konfiguracja config/overleaf.rc">
Otwórz `config/overleaf.rc` i zmień te wiersze:

```bash title="config/overleaf.rc"
SERVER_PRO=true
OVERLEAF_PORT=8080
SIBLING_CONTAINERS_ENABLED=true
```

Następnie dodaj ten wiersz na końcu pliku:

```bash title="config/overleaf.rc"
SELINUX_MODE=managed
```

| Ustawienie                        | Dlaczego                                                                                                                                                                                                     |
| --------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `SERVER_PRO=true`                 | Używa obrazu Ayakaleaf Pro z `ghcr.io`. Logowanie nie jest potrzebne.                                                                                                                                        |
| `OVERLEAF_PORT=8080`              | Rootless Podman nie może nasłuchiwać na portach poniżej `1024`. Domyślny port `80` nie działa.                                                                                                                |
| `SIBLING_CONTAINERS_ENABLED=true` | Uruchamia każdą kompilację we własnym kontenerze TeX Live. Domyślnie już `true`; konfiguracja Podmana obsługuje tylko ten tryb.                                                                              |
| `SELINUX_MODE=managed`            | Uruchamia kontener `sharelatex` z typem SELinux `sharelatex_t`, który może używać gniazda Podmana i niczego więcej. `bin/podman-setup --apply` instaluje dla niego moduł polityki. Inne tryby opisano w [Ustawienia Toolkit](/pl/on-premises/configuration/overleaf-toolkit/toolkit-settings). |

Pozostaw `DOCKER_SOCKET_PATH` bez zmian: w następnym kroku `bin/podman-setup --apply` ustawi w nim Twoje gniazdo Podmana.

<Warning>

Pozostaw `GIT_BRIDGE_ENABLED=false`. W Ayakaleaf Pro 6.3.4 integracja z Git nie działa na Podmanie, zobacz [Znane ograniczenia](/pl/on-premises/installation/using-podman#known-limitations).

</Warning>
</Step>

<Step title="Wybór obrazów TeX Live">
Otwórz `config/variables.env`, usuń `#` przed `TEX_LIVE_DOCKER_IMAGE` i `ALL_TEX_LIVE_DOCKER_IMAGES` i wymień obrazy TeX Live, których chcesz używać:

```bash title="config/variables.env" wrap
TEX_LIVE_DOCKER_IMAGE=ghcr.io/ayaka-notes/texlive-full:2026.1
ALL_TEX_LIVE_DOCKER_IMAGES=ghcr.io/ayaka-notes/texlive-full:2026.1
```

Jeśli lista jest pusta, `bin/up` zatrzymuje się z komunikatem `Please configure ALL_TEX_LIVE_DOCKER_IMAGES`. Obraz `texlive-full` jest duży; na serwer testowy wystarczy też znacznie mniejszy `ghcr.io/ayaka-notes/texlive-basic:2026.1`. Dostępne obrazy znajdziesz w [Sandboxed Compiles](/pl/on-premises/configuration/overleaf-toolkit/sandboxed-compiles).

Ustaw pozostałe zmienne, takie jak `OVERLEAF_SITE_URL`, jak opisano w kroku [5. Personalizacja instancji](/pl/on-premises/installation/using-docker-compose/linux/5.-personalizing-your-instance#required-environment-variables). Przy domyślnym adresie nasłuchiwania użyj `http://localhost:8080`.
</Step>
</Steps>
