---
title: 3. Uruchomienie Ayakaleaf Pro
description: Uruchom Ayakaleaf Pro na Podmanie, sprawdź go za pomocą podman-setup i bin/doctor oraz uruchamiaj go po restartach.
icon: circle-play
---

<Steps>
<Step title="Uruchomienie kontenerów">
```bash title="Start Ayakaleaf Pro"
bin/up -d
```

Pierwsze uruchomienie pobiera obrazy MongoDB, Redis i TeX Live oraz tworzy katalogi danych w `data/`. Wyświetla ostrzeżenie, że obsługa Podmana jest eksperymentalna.

<Info>

Pierwsze uruchomienie może też wyświetlić `MongoNetworkError: connect ECONNREFUSED 127.0.0.1:27017`. Toolkit konfiguruje zestaw replik MongoDB, gdy MongoDB jeszcze się uruchamia, i ponawia próby, dopóki MongoDB nie odpowie. Możesz zignorować ten wiersz.

</Info>

Po minucie lub dwóch sprawdź, czy kontenery działają:

```bash title="List the containers"
podman ps --format "{{.Names}} {{.Status}}"
```

```text
mongo Up 34 seconds (healthy)
redis Up 20 seconds
sharelatex Up 20 seconds
```
</Step>

<Step title="Ponowne sprawdzenie konfiguracji">
Teraz, gdy katalogi danych istnieją, a kontener `sharelatex` działa, `bin/podman-setup` może dokończyć swoje testy:

```bash title="Check the setup"
bin/podman-setup
```

Sprawdza właścicieli nowych katalogów danych i testuje gniazdo Podmana z wnętrza kontenera `sharelatex`:

```text
====== Socket Connectivity ======
[✓] host → socket OK
[✓] container → socket OK

====== Data Directory Permissions ======
[✓] mongo data dir owned by 999
[✓] redis data dir owned by 999
[✓] overleaf data dir owned by 33
...
====== Summary ======
[✓] 27 passed  [!] 1 warnings  [✗] 0 failures
[!] Warnings:
[!] not logged in to quay.io
```

`container → socket OK` oznacza, że Ayakaleaf Pro może uruchamiać kontenery kompilacji. Jeśli test się nie powiedzie, uruchom `bin/podman-setup --apply`, a następnie `bin/up -d`. Ostrzeżenie o quay.io nie dotyczy Ayakaleaf Pro, zobacz [2. Uruchomienie podman-setup](/pl/on-premises/installation/using-podman/2.-run-podman-setup).
</Step>

<Step title="Uruchomienie doctor">
```bash title="Run the doctor"
bin/doctor
```

Na Podmanie raport pokazuje środowisko uruchomieniowe i ustawienia bezpieczeństwa:

```text
- Container Daemon
    - status: up
    - runtime: podman
    - server version: 5.8.5
    - socket: /run/user/1000/podman/podman.sock
    - DOCKER_HOST: unix:///run/user/1000/podman/podman.sock
    - host → socket: OK
    - container → socket: OK
- Security
    - SELinux: Enforcing
    - SELINUX_MODE: managed
    - SELINUX_LABEL: sharelatex_t
    - SELinux module: loaded (podman_socket_clsi)
    - SELinux rules: present
    - Seccomp profile: present
```

Ostrzeżenie `Server Pro enabled, but not logged in to quay.io repository` na końcu to ten sam test quay.io, zobacz [Uzyskiwanie pomocy](/pl/on-premises/support/getting-help#q-and-a).
</Step>

<Step title="Uruchamianie Ayakaleaf Pro po restarcie">
W Dockerze demon Dockera ponownie uruchamia kontenery po restarcie. Rootless Podman nie ma demona: włącz usługę użytkownika, która uruchamia Twoje kontenery podczas startu serwera:

```bash title="Start the containers at boot"
systemctl --user enable podman-restart.service
```

Uruchamia ona każdy kontener Twojego użytkownika, którego polityka ponownego uruchamiania to `always`, a Toolkit ustawia ją dla wszystkich swoich kontenerów. Wymaga to lingeringu, który włączył `bin/podman-setup --apply`. Bez tej usługi uruchamiaj `bin/up -d` po każdym restarcie.
</Step>

<Step title="Otwarcie portu w zaporze">
Domyślnie instancja akceptuje połączenia tylko z samego serwera, pod adresem `http://localhost:8080`. Aby otworzyć ją z innych komputerów, ustaw `OVERLEAF_LISTEN_IP` w `config/overleaf.rc` i `OVERLEAF_SITE_URL` w `config/variables.env`, jak opisano w kroku [5. Personalizacja instancji](/pl/on-premises/installation/using-docker-compose/linux/5.-personalizing-your-instance#listen-address-and-port), i ponownie uruchom `bin/up -d`.

W przeciwieństwie do Dockera rootless Podman nie omija zapory hosta. Jeśli działa `firewalld`, co jest domyślne w RHEL, otwórz port:

```bash title="Open port 8080"
sudo firewall-cmd --permanent --add-port=8080/tcp
sudo firewall-cmd --reload
```

Na serwerze w chmurze zezwól też na ten port w grupie zabezpieczeń dostawcy. Zanim udostępnisz instancję w internecie, użyj HTTPS, zobacz [4. Zadania poinstalacyjne](/pl/on-premises/installation/using-podman/4.-post-installation-tasks#use-https).
</Step>
</Steps>
