Zebraliśmy tu odpowiedzi na najczęściej zadawane pytania dotyczące Ayakaleaf Pro.

### Pytania podstawowe {#basic-question}

<Accordion title="P01: Czy Ayakaleaf Pro to wersja próbna? Czy wymaga licencji?">

Nie. Korzystanie z Ayakaleaf Pro jest całkowicie bezpłatne. Nie jest to wersja próbna i nie wymaga licencji.

</Accordion>

<Accordion title="P02: Czy Ayakaleaf Pro zawiera wszystkie funkcje Overleaf Server Pro?">

Tak. Ayakaleaf Pro zawiera wszystkie funkcje Overleaf Server Pro, w tym integrację Git-Bridge. Zawiera także wybrane funkcje z platformy SaaS Overleaf. Nieustannie rozwijamy i ulepszamy Ayakaleaf Pro.

</Accordion>

<Accordion title="P03: Ile kosztuje Overleaf Server Pro?">

Overleaf Server Pro kosztuje około \$300 rocznie za użytkownika. Wymagany jest zakup co najmniej 10 licencji, więc koszt wdrożenia zaczyna się od około \$3,000 rocznie. Mniejsze publiczne kontrakty w USA wskazują roczne koszty rzędu \$320–\$370 za użytkownika. Przez to Server Pro jest drogi, zwłaszcza dla mniejszych zespołów. Udokumentowane zakupy i ceny znajdziesz w [#information-and-price-about-overleaf-server-pro](/pl/on-premises#information-and-price-about-overleaf-server-pro  "mention").

</Accordion>

<Accordion title="P04: Dlaczego Overleaf Server Pro nie zawiera synchronizacji z GitHub ani funkcji AI?">

Overleaf Server Pro jest powszechnie używany przez organizacje rządowe. Wdrażają go one w sieciach prywatnych i ściśle kontrolują dostęp. Aby chronić wrażliwe dane, dostępne w nim funkcje nie wymieniają danych z usługami firm trzecich. Jeśli potrzebujesz synchronizacji z GitHub, AI lub podobnych funkcji wymagających połączenia, Overleaf zaleca subskrypcję swojej platformy SaaS.

</Accordion>

<Accordion title="P05: Czy Ayakaleaf Pro jest bezpieczny i niezawodny?">

Ayakaleaf Pro jest oprogramowaniem open source. Przeglądamy kod za pomocą narzędzi takich jak Codex Security, aby wzmocnić jego bezpieczeństwo i niezawodność. Jeśli nie włączysz synchronizacji danych z usługami firm trzecich, Twoje dane pozostają na Twoim serwerze. Ayakaleaf Pro nie zawiera telemetrii wysyłającej Twoje dane gdziekolwiek indziej.

</Accordion>

<Accordion title="P06: Czy Ayakaleaf Pro będzie utrzymywany długoterminowo?">

Dołożymy wszelkich starań, aby utrzymywać ten projekt w długim okresie.

</Accordion>

<Accordion title="P07: Czy Ayakaleaf Pro jest zgodny z licencją?">

Ayakaleaf Pro to fork społecznościowy. Jego kod i zintegrowane funkcje pochodzą z wkładu społeczności. Jest udostępniany na licencji AGPL v3. Wdrożenia mogą być zgodne z tą licencją, jeśli spełniają jej wymagania.

</Accordion>

<Accordion title="P08: Dlaczego projekt nazywa się Ayakaleaf Pro?">

Projekt pierwotnie nosił nazwę Overleaf Pro w 2024 roku. Prace zostały na pewien czas wstrzymane, a następnie wznowione pod koniec 2025 roku. W pierwszym kwartale 2026 roku Overleaf zmienił nazwę swojego planu subskrypcyjnego z funkcjami AI na Pro. Społeczność zwróciła też uwagę, że nazwa Overleaf Pro może stwarzać ryzyko naruszenia znaku towarowego i podszywania się. Mogłaby sugerować użytkownikom, że projekt jest oficjalny.

Aby uniknąć tego nieporozumienia, zmieniliśmy nazwę projektu na Ayakaleaf Pro. Nazwę można odczytywać jako „Ayaka-notes Overleaf Pro”. Opiekun projektu (możesz mówić do mnie ayaka!) uczestniczy w rozwoju społeczności Overleaf od czasów studenckich, czyli od ponad pięciu lat. To doświadczenie wspiera nasze zobowiązanie do długoterminowego utrzymania.

</Accordion>

<Accordion title="P09: Czym Ayakaleaf Pro różni się od nowszych edytorów LaTeX tworzonych przez AI?">

Od 2026 roku społeczność open source wydała wiele edytorów LaTeX tworzonych z pomocą AI, w tym OpenAI Prism. Ayakaleaf Pro przechowuje Twoje dane i usługi na Twoim własnym serwerze. Daje Ci to bezpośrednią kontrolę nad wdrożeniem i danymi.

Wiele eksperymentalnych edytorów społecznościowych nie ma ugruntowanego planu długoterminowego utrzymania. Platformy kompilacji LaTeX firm trzecich mogą też przestać działać, gdy ich baza użytkowników lub przychody okażą się niewystarczające. Ayakaleaf Pro udostępnia cały kod źródłowy i pozwala samodzielnie hostować każdą usługę. Nawet gdyby utrzymanie zostało przerwane, Twoja istniejąca samodzielnie hostowana usługa mogłaby nadal działać.

</Accordion>

<Accordion title="P10: Co stało się z repozytorium GitHub ayaka-notes/overleaf-pro?">

Jego nazwa została zmieniona na [ayaka-notes/ayakaleaf-pro](https://github.com/ayaka-notes/ayakaleaf-pro) wraz ze zmianą nazwy projektu (zobacz P08). Nie zostało zarchiwizowane ani zastąpione: to to samo repozytorium, a GitHub przekierowuje stare linki `ayaka-notes/overleaf-pro` i zdalne repozytoria Git na nową nazwę. Obraz Dockera zachowuje swoją nazwę, `ghcr.io/ayaka-notes/overleaf-pro`, więc nie musisz zmieniać `config/overleaf.rc` ani `config/version`.

</Accordion>

### Funkcje {#features}

<Accordion title="P01: Jakie funkcje oferuje Ayakaleaf Pro? Czy mogę zgłosić prośbę o nową funkcję?">

Aktualną listę funkcji znajdziesz w naszej dokumentacji. Jeśli chcesz, abyśmy dodali jakąś funkcję, śmiało utwórz zgłoszenie (issue z prośbą o funkcję) na GitHubie. Dołożymy wszelkich starań, aby wdrażać zgłoszone funkcje, ale rozwój wymaga czasu i nie możemy zagwarantować, że każda funkcja zostanie dostarczona od razu.

</Accordion>

<Accordion title="P02: Opracowałem kilka funkcji. Czy mogę przesłać PR i czy zostanie on na pewno zaakceptowany?">

Wkład jest mile widziany, ale jego akceptacja nie jest gwarantowana. Każdy PR oceniamy pod kątem jego wpływu na bazowy kod Overleaf, nakładu pracy związanego z utrzymaniem oraz wartości, jaką wnosi dla użytkowników. Dołożymy wszelkich starań, aby scalać i utrzymywać wartościowy wkład.

Możemy jednak odrzucić PR-y, które wprowadzają nadmierne zmiany, składają się z nieprzejrzanego lub słabo zrozumianego kodu wygenerowanego przez AI („vibe coding”) albo dodają funkcje, które byłyby trudne do utrzymania w dłuższej perspektywie.

</Accordion>

<Accordion title="P03: Jak skonfigurować konkretną funkcję?">

Zazwyczaj aktualizujemy dokumentację przy każdym wydaniu nowej funkcji. Szczegółowe instrukcje konfiguracji oraz objaśnienia dostępnych zmiennych środowiskowych znajdziesz w odpowiedniej dokumentacji.

</Accordion>

<Accordion title="P04: Z jakich bibliotek Python może korzystać Python Runner?">

Python Runner uruchamia Pythona w przeglądarce użytkownika za pomocą [Pyodide](https://pyodide.org/) 0.29.3, a nie na serwerze. Ładuje pakiety importowane przez Twój kod spośród [pakietów wbudowanych w Pyodide](https://pyodide.org/en/0.29.3/usage/packages-in-pyodide.html), takich jak NumPy, pandas i Matplotlib. Pakiety instalowane za pomocą `pip` ani inne pakiety nie są dostępne. Na serwerze nie trzeba niczego konfigurować.

</Accordion>

<Accordion title="P05: Czy sprawdzanie pisowni obsługuje język japoński lub chiński?">

Nie. Moduł sprawdzania pisowni nie ma słownika dla języka japońskiego ani chińskiego, więc te języki nie znajdują się na liście języków sprawdzania pisowni. Użytkownicy mogą wyłączyć sprawdzanie pisowni dla projektu w ustawieniach edytora.

Aby słowo nie było oznaczane jako błędnie napisane, kliknij je prawym przyciskiem myszy i wybierz **Add to dictionary**. Dodane słowa są zapisywane na Twoim koncie i obowiązują we wszystkich Twoich projektach. Aby je przejrzeć lub usunąć, otwórz ustawienia edytora, a następnie **Spelling and language → Dictionary → Edit**. Dodawanie słów nie dodaje nowego języka sprawdzania pisowni.

</Accordion>

<Accordion title="P06: Czy mogę dodawać wtyczki?">

Nie ma instalatora wtyczek. Funkcje są modułami w katalogu `services/web/modules` kodu źródłowego, wbudowanymi w obraz Dockera i włączanymi za pomocą ustawień opisanych w tej dokumentacji. Aby dodać własną funkcję, dodaj moduł do kodu źródłowego i zbuduj własny obraz.

</Accordion>

### Wdrażanie {#deployment}

<Accordion title="P01: Czy Ayakaleaf Pro obsługuje rozproszone wdrożenie w k8s?">

Większości użytkowników zalecamy wdrożenie za pomocą [Toolkit](/pl/on-premises/installation/using-docker-compose). Obsługa Kubernetes jest eksperymentalna: [Korzystanie z Kubernetes](/pl/on-premises/installation/using-kubernetes) przedstawia manifesty, które przetestowaliśmy z jedną lub kilkoma replikami, ale klaster zwiększa złożoność operacyjną i nakład pracy związany z utrzymaniem. [Kompilacje w piaskownicy (Sandboxed Compiles)](/pl/on-premises/configuration/overleaf-toolkit/sandboxed-compiles) tworzą swoje kontenery kompilacji przez gniazdo Dockera, więc każdy węzeł, na którym działa Ayakaleaf Pro, potrzebuje Docker Engine. Nie udostępniamy konfiguracji dla CRI-O, Podman ani Quadlet.

</Accordion>

<Accordion title="P02: Jak zapewnić dostępność przy obsłudze tysięcy użytkowników?">

Zapoznaj się z naszym przewodnikiem dotyczącym [skalowania poziomego](/pl/on-premises/maintenance/horizontal-scaling). Możesz wdrożyć wiele instancji Overleaf i skonfigurować load balancer, aby rozdzielał między nie ruch.

</Accordion>

<Accordion title="P03: Czy możecie pomóc mi we wdrożeniu lub migracji?">

Jeśli masz istniejącą instancję Overleaf Server Pro, chętnie pomożemy Ci w migracji do Ayakaleaf Pro. Skontaktuj się z nami przez e-mail lub zgłoszenia (issues).

</Accordion>

<Accordion title="P04: Czy mogę hostować Ayakaleaf Pro pod podścieżką URL, np. `https://example.com/overleaf`?">

Nie. Ayakaleaf Pro musi być udostępniany z katalogu głównego domeny. Użyj dedykowanej domeny lub subdomeny, np. `https://overleaf.example.com`.

</Accordion>

<Accordion title="P05: Czy mogę uruchomić Ayakaleaf Pro w systemie Windows lub macOS albo bez Toolkit?">

Tak. Toolkit działa w systemie [Linux](/pl/on-premises/installation/using-docker-compose/linux), w [macOS z Docker Desktop](/pl/on-premises/installation/using-docker-compose/macos) oraz w [Windows z WSL 2 i Docker Desktop](/pl/on-premises/installation/using-docker-compose/windows). Dla serwerów współdzielonych i produkcyjnych zalecamy system Linux. Przewodniki dla macOS i Windows obejmują konfigurację kompilacji w piaskownicy.

Nie udostępniamy samodzielnego pliku `docker-compose.yml`. Aby zobaczyć konfigurację Compose używaną przez Toolkit, uruchom `bin/docker-compose config` w katalogu Toolkit.

</Accordion>

<Accordion title="P06: Jak odinstalować Ayakaleaf Pro?">

Nie ma skryptu deinstalacyjnego. W katalogu Toolkit:

1. Zatrzymaj i usuń kontenery poleceniem `bin/docker-compose down`.
2. Usuń dane. Domyślnie znajdują się w katalogu `data/` Toolkit. Jeśli zmieniono `OVERLEAF_DATA_PATH`, `MONGO_DATA_PATH`, `REDIS_DATA_PATH` lub `GIT_BRIDGE_DATA_PATH` w `config/overleaf.rc`, usuń również te katalogi. Tej operacji nie można cofnąć, więc jeśli dane mogą Ci być jeszcze potrzebne, najpierw [wykonaj kopię zapasową](/pl/on-premises/maintenance/data-and-backups).
3. Usuń katalog Toolkit.
4. Usuń obrazy Docker, których listę możesz wyświetlić poleceniem `docker images`: `ghcr.io/ayaka-notes/overleaf-pro`, obraz git-bridge, `mongo`, `redis` oraz obrazy TeX Live.

</Accordion>

<Accordion title="P07: Jak zatrzymać, uruchomić lub zrestartować Ayakaleaf Pro?">

Uruchamiaj te polecenia w katalogu Toolkit:

* `bin/stop` zatrzymuje wszystkie kontenery, a `bin/start` uruchamia je ponownie. Kontenery są zachowywane, więc użytkownicy pozostają zalogowani.
* `bin/up -d` tworzy kontenery i uruchamia je w tle. Uruchamiaj je po zmianie `config/variables.env`, `config/overleaf.rc` lub `config/version`: odtwarza kontenery, których konfiguracja się zmieniła, i dopiero wtedy zmiany zaczynają obowiązywać. `bin/stop` i `bin/start` ich nie stosują.
* `bin/docker-compose restart sharelatex` restartuje tylko kontener Overleaf, bez stosowania zmian konfiguracji.

Jeśli użytkownicy są wylogowywani za każdym razem, gdy `bin/up` odtwarza kontener, ustaw `OVERLEAF_SESSION_SECRET`, zobacz sekcję Pytania i odpowiedzi w [Zmienne środowiskowe](/pl/on-premises/configuration/overleaf-toolkit/environment-variables).

</Accordion>

<Accordion title="P08: Gdzie wpisać adres URL wywołania zwrotnego OAuth?">

W aplikacji tworzonej u dostawcy, a nie w Ayakaleaf Pro. W `config/variables.env` nie ma ustawienia adresu wywołania zwrotnego dla żadnej z tych integracji: Ayakaleaf Pro buduje każdy adres URL wywołania zwrotnego na podstawie `OVERLEAF_SITE_URL` i wysyła go do dostawcy, który go odrzuca, jeśli nie jest zgodny z adresem zarejestrowanym dla aplikacji. Wystarczy więc zarejestrować go u dostawcy i ustawić `OVERLEAF_SITE_URL` na adres, który otwierają użytkownicy.

| Integracja | Pole u dostawcy | Wartość |
| --- | --- | --- |
| [GitHub](/pl/on-premises/configuration/overleaf-toolkit/integrations/github-synchronisation) | Authorization callback URL | `${OVERLEAF_SITE_URL}/user/github-sync/oauth2/callback` |
| [GitLab](/pl/on-premises/configuration/overleaf-toolkit/integrations/gitlab-synchronisation) | Redirect URI | `${OVERLEAF_SITE_URL}/user/gitlab-sync/oauth2/callback` |
| [Gitea](/pl/on-premises/configuration/overleaf-toolkit/integrations/gitea-synchronisation) | Redirect URIs | `${OVERLEAF_SITE_URL}/user/gitea-sync/oauth2/callback` |
| [Dropbox](/pl/on-premises/configuration/overleaf-toolkit/integrations/dropbox-synchronisation) | Redirect URIs (kliknij **Add**) | `${OVERLEAF_SITE_URL}/user/dropbox/oauth/callback` |
| [Zotero](/pl/on-premises/configuration/overleaf-toolkit/integrations/zotero-integration) | Callback URL | `${OVERLEAF_SITE_URL}/user/zotero/oauth/callback` |
| [Mendeley](/pl/on-premises/configuration/overleaf-toolkit/integrations/mendeley-integration) | Redirect URL | `${OVERLEAF_SITE_URL}/user/mendeley/oauth/callback` |
| [Logowanie OIDC](/pl/on-premises/configuration/overleaf-toolkit/authentication/oidc-authentication) | Redirect URI | `${OVERLEAF_SITE_URL}/oidc/login/callback` |
| [Logowanie SAML](/pl/on-premises/configuration/overleaf-toolkit/authentication/saml-authentication) | ACS URL (Assertion Consumer Service) | `${OVERLEAF_SITE_URL}/saml/login/callback` |

Jeśli zmienisz `OVERLEAF_SITE_URL`, na przykład na nową domenę, zaktualizuj adres URL również u każdego dostawcy, w przeciwnym razie łączenie kont się nie powiedzie.

</Accordion>

<Accordion title="P09: Gdzie przechowywane są dane i ile miejsca na dysku potrzebuję?">

Domyślnie wszystko pozostaje na lokalnym dysku serwera, w katalogu `data/` Toolkit: `data/overleaf` (pliki projektów, historia i wyniki kompilacji), `data/mongo` i `data/redis`. W przypadku instancji z mniej niż 1000 użytkowników zalecamy lokalny dysk z regularnymi [kopiami zapasowymi](/pl/on-premises/maintenance/data-and-backups).

Obraz Ayakaleaf Pro zajmuje około 5 GB. Minimum 40 GB podane we [Wprowadzeniu](/pl/on-premises/installation/introduction) dotyczy Sandboxed Compiles, których obrazy `texlive-full` zajmują około 28 GB każdy. Bez Sandboxed Compiles kompilacje działają wewnątrz kontenera `sharelatex` ze schematem podstawowym TeX Live oraz `latexmk`, `texcount`, `synctex`, `etoolbox` i `xetex`, więc wiele projektów nie skompiluje się z powodu brakujących pakietów. Katalog `data/` rośnie wtedy wraz z Twoimi projektami i ich historią; sprawdzisz to poleceniem `du -sh data/*`.

</Accordion>

<Accordion title="P10: Czy mogę utrzymywać Ayakaleaf uruchomiony w systemie Windows przez całą dobę?">

Tak, pod warunkiem że Windows nie przechodzi w stan uśpienia, a Docker Desktop pozostaje uruchomiony. Włącz **Start Docker Desktop when you sign in to your computer**, zachowaj zasady `restart: always` z Toolkit i wyłącz automatyczne usypianie oraz hibernację podczas zasilania sieciowego. Ekran może się wyłączać; zachowanie po zamknięciu pokrywy laptopa to osobne ustawienie. Zamknięcie terminala Ubuntu po `bin/up -d` nie zatrzymuje odłączonych kontenerów. Zamknięcie Docker Desktop, wstrzymanie jego silnika lub uruchomienie `wsl --shutdown` przerywa działanie usługi.

Funkcja Resource Saver w Docker Desktop to coś innego niż uśpienie systemu Windows: działa, gdy nie są uruchomione żadne kontenery, więc działający stos Ayakaleaf nie jest bezczynny tylko dlatego, że nikt nie edytuje. Po ponownym uruchomieniu systemu Windows ustawienie uruchamiania przy logowaniu nadal wymaga, aby ktoś się zalogował. Kontrole i kroki przywracania opisano w sekcji [Utrzymywanie dostępności instancji](/pl/on-premises/installation/using-docker-compose/windows/6.-post-installation-tasks#keep-the-instance-available). Linux pozostaje naszą rekomendacją, gdy dostępność nie może zależeć od interaktywnego logowania do pulpitu.

</Accordion>

<Accordion title="P11: Docker Desktop informuje, że wirtualizacja jest wyłączona. Czy potrzebuję Hyper-V?">

Ten przewodnik korzysta z **backendu WSL 2**. Wymaga on włączonej wirtualizacji procesora w BIOS/UEFI, funkcji systemu Windows **Virtual Machine Platform** oraz działającej instalacji WSL 2. Pełna funkcja **Hyper-V** to osobny backend Docker Desktop i nie jest wymagana w tej konfiguracji WSL.

Sprawdź **Task Manager → Performance → CPU → Virtualization** oraz `wsl --list --verbose` w PowerShell. Błędy takie jak `0x80370102` mogą oznaczać, że wirtualizacja, funkcja systemu Windows lub hiperwizor rozruchowy są wyłączone. Zobacz [kroki rozwiązywania problemów z instalacją w systemie Windows](/pl/on-premises/installation/using-docker-compose/windows/troubleshooting#wsl-or-docker-reports-that-virtualization-is-unavailable), zawierające odnośniki do instrukcji naprawy od Microsoft i Docker. Po włączeniu wymaganych funkcji uruchom ponownie system Windows; ponowna instalacja Ayakaleaf nie naprawi silnika Docker, który się nie uruchamia.

</Accordion>

### LaTeX {#latex}

<Accordion title="P01: Czy kompilacje projektów LaTeX użytkowników są izolowane? Czy Shell Escape jest włączony?">

Po włączeniu Sandbox Compiles kompilacja każdego użytkownika działa w osobnym kontenerze Dockera i jest odizolowana od kompilacji innych użytkowników. W Sandbox Compiles Shell Escape jest domyślnie włączony.

</Accordion>

<Accordion title="P02: Czy obraz Sandbox Compiles jest niezawodny? Czy kompilacja może się nie powieść?">

Przez ostatnie trzy lata ulepszaliśmy nasz obraz TeX Live Full dla Sandbox Compiles. W większości przypadków projekty, które kompilują się na overleaf.com, kompilują się poprawnie również w Ayakaleaf Pro. Jeśli wymagana czcionka jest niedostępna, prześlij ją ręcznie do swojego projektu.

</Accordion>

<Accordion title="P03: Mój projekt się nie kompiluje. Czy możecie pomóc mi znaleźć przyczynę?">

Prześlij swój projekt na oficjalną stronę Overleaf, włącz udostępnianie linku tylko do odczytu i dołącz ten link do zgłoszenia na GitHubie.

Zbadamy i naprawimy wszelkie błędy, które uniemożliwiają kompilację projektu w Ayakaleaf Pro, jeśli kompiluje się on poprawnie na oficjalnej stronie Overleaf. Problemy z kompilacją wykraczające poza ten zakres nie są objęte naszym wsparciem.

</Accordion>
