### Docker

Docker zapewnia lekki i przenośny sposób pakowania i uruchamiania aplikacji w izolowanych kontenerach. Dzięki połączeniu aplikacji ze wszystkimi wymaganymi zależnościami kontener gwarantuje spójne działanie na różnych maszynach — od laptopów po serwery produkcyjne.

TeX Live ma ogromne możliwości, ale jest duży i wrażliwy na różnice na poziomie systemu. Spakowanie TeX Live w obrazie Docker sprawia, że zestaw narzędzi LaTeX staje się przewidywalny, powtarzalny i łatwy w dystrybucji.

Niektóre pakiety TeX Live wymagają jednak dostępu do powłoki. Ze względów bezpieczeństwa kontener powinien działać w ograniczonym środowisku, które uniemożliwia użytkownikom wykonywanie dowolnych poleceń powłoki (na przykład przez `\write18` lub shell escape). Taka izolacja chroni system hosta i zapobiega niezamierzonemu dostępowi do systemu plików kontenera lub narzędzi takich jak `bash`.

### Pełna edycja TeXLive

[TeXLive-Full@ayaka-notes](https://github.com/ayaka-notes/texlive-full/) to w pełni funkcjonalny **obraz Docker TeXLive** przeznaczony do kompilacji LaTeX w piaskownicy w [Ayakaleaf Pro](https://github.com/ayaka-notes/ayakaleaf-pro), [Overleaf CEP](https://github.com/yu-i-i/overleaf-cep) lub w samodzielnych środowiskach kompilacji LaTeX.

Ten obraz ma na celu zapewnienie niemal kompletnej dystrybucji TeXLive z preinstalowanymi popularnymi fontami i narzędziami, aby zminimalizować błędy kompilacji spowodowane brakującymi pakietami lub fontami. Uwaga: ten obraz Docker **nie zawiera** żadnych komponentów sharelatex/overleaf. Służy do kompilacji w Overleaf/Overleaf Pro.

#### Funkcje:

* 🚀 Obsługa architektur serwerowych x86\_64 i arm64
* 📦 Pełna i zoptymalizowana instalacja TeXLive
* 🧩 Preinstalowane popularne fonty i narzędzia
* 🐳 Gotowy do użycia z Docker i Docker Compose
* 🧪 Przetestowany z Overleaf Server Pro / Overleaf Pro
* 🔄 Regularnie aktualizowany do najnowszych wydań TeXLive
* 🏷 Tagi dla wielu wersji TeXLive (od 2020 do najnowszej)
* 🧑‍🔬 Obsługa Knitr dla kodu R w dokumentach LaTeX

### Użycie w Ayakaleaf Pro

TeX Live Full od Ayaka-notes został zaprojektowany specjalnie dla [ayakaleaf-pro](https://github.com/ayaka-notes/ayakaleaf-pro). Jeśli [korzystasz z Toolkit](https://github.com/overleaf/toolkit), możesz dodać poniższe zmienne środowiskowe do pliku `config/variables.env`.

Na przykład:

```dotenv title="config/variables.env" wrap
ALL_TEX_LIVE_DOCKER_IMAGES=ghcr.io/ayaka-notes/texlive-full:2026.1, ghcr.io/ayaka-notes/texlive-full:2025.1
ALL_TEX_LIVE_DOCKER_IMAGE_NAMES=Texlive 2026, Texlive 2025
TEX_LIVE_DOCKER_IMAGE=ghcr.io/ayaka-notes/texlive-full:2026.1
```

### Wersje TeX Live

Dzięki GitHub Action możemy równolegle budować wszystkie obrazy TeX, w tym:

* `ghcr.io/ayaka-notes/texlive-full:2026.1` (również tag `latest`)
* `ghcr.io/ayaka-notes/texlive-full:2025.1`
* `ghcr.io/ayaka-notes/texlive-full:2024.1`
* `ghcr.io/ayaka-notes/texlive-full:2023.1`
* `ghcr.io/ayaka-notes/texlive-full:2022.1`
* `ghcr.io/ayaka-notes/texlive-full:2021.1`
* `ghcr.io/ayaka-notes/texlive-full:2020.1`
* `ghcr.io/ayaka-notes/texlive-full:base`

Korzystamy z archiwum lustrzanego [texlive info](https://texlive.info/tlnet-archive/), które obejmuje niemal wszystkie wydania TeX Live od 1996 do 2025 roku. A dzięki plikowi Dockerfile Overleaf możemy budować ten projekt szybciej.

> Dlaczego TeX Live 2019 i starsze wersje nie są obsługiwane?
>
> Utrzymywanie tych starych obrazów jest niezwykle trudne. Ponadto witryna [texlive.info](https://texlive.info/) nie udostępnia informacji o wersjach TeX Live wydanych przed 2019 rokiem, więc nie możemy budować obrazów dla tych wersji. Jeśli potrzebujesz konkretnej starej wersji, zgłoś issue i daj nam znać.

### Zawarte komponenty

Obraz Docker zawiera następujące pakiety:

* Wszystkie pakiety TeXLive (z danego roku)
* Pakiety R (tylko wybrane)
* fontconfig inkscape pandoc python3-pygments wget python3
* gnupg gnuplot perl-modules perl ca-certificates
* ghostscript qpdf r-base-core tar

Obraz Docker zawiera następujące fonty:

* [Google Fonts](https://fonts.google.com/)
* [Microsoft msttcorefonts](https://packages.ubuntu.com/jammy/ttf-mscorefonts-installer)
* [Fonty obsługiwane przez Overleaf](https://www.overleaf.com/learn/latex/Questions/Which_OTF_or_TTF_fonts_are_supported_via_fontspec%3F)

<Warning>

Upewnij się, czy dane fonty mogą być używane komercyjnie. **Nie ponosimy odpowiedzialności** za jakiekolwiek problemy prawne wynikające z niewłaściwego użycia fontów. Pobierając obraz, automatycznie akceptujesz te warunki.

</Warning>

### Problemy

<Accordion title="Problem 01: brak fontu w pamięci podręcznej">

Jeśli podczas kompilacji projektu LaTeX w Overleaf wystąpi brak fontu, **kompilacja może trwać bardzo długo**, ponieważ w przypadku brakującego fontu TeX Live próbuje **przebudować całą pamięć podręczną fontów**. Jest to czasochłonny proces.

W naszym obrazie pamięć podręczna fontów jest zbudowana z góry — rozwiązaliśmy ten problem w [tym commicie](https://github.com/ayaka-notes/texlive-full/commit/0cb66b0dc8b82be628cf6999cfd659d9784e132f)

</Accordion>

<Accordion title="Problem 02: SyncTeX działa bardzo wolno">

Gdy używasz tego obrazu w sharelatex, SyncTeX może działać bardzo wolno.

Zobacz: [https://github.com/overleaf/overleaf/issues/1150](https://github.com/overleaf/overleaf/issues/1150) — wystarczy wyłączyć HTTP 2.0.

</Accordion>

<Accordion title="Problem 03: błąd ponownej kompilacji z oficjalnym obrazem TeX Live">

Jeśli używasz oficjalnego obrazu TeX Live z Docker Hub `texlive/texlive`, możesz zauważyć, że ponowna kompilacja projektu zgłasza błąd. W naszym obrazie ten problem został jednak rozwiązany, ponieważ używamy najnowszego obrazu bazowego Ubuntu i instalujemy wszystkie zależności z oficjalnego repozytorium Ubuntu.

</Accordion>

### Inne wskazówki techniczne

Podczas budowania obrazów TeX Live (sprzed 2019 roku) zwróć uwagę na następujące problemy:

* Przed TeX Live 2017 obsługiwane są wyłącznie `http`/`ftp`, więc nie można pobierać przez `https`, chyba że zmodyfikujesz skrypt `peal`.
* Przed 2015 rokiem udostępniane są tylko pliki sha256, więc nie można weryfikować sum za pomocą sha512.
