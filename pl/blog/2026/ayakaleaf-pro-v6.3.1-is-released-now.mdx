Z wielką dumą ogłaszamy wydanie Overleaf Pro 6.3.1 — najpotężniejszego i najbogatszego w funkcje edytora LaTeX online w społeczności. Wydanie poprawkowe zwykle oznacza garść drobnych poprawek. To idzie znacznie dalej: oprócz dziesiątek poprawek błędów przynosi pięć nowych funkcji i łączy Twoje projekty z miejscami, w których już pracujesz — od Dropbox i GitLab po agenta AI w Twoim terminalu.

### Zmiany

* Synchronizacja z Dropbox (wczesna wersja zapoznawcza): utrzymuj każdy projekt w synchronizacji z własnym Dropbox, w obu kierunkach.
* Synchronizacja z GitLab (wczesna wersja zapoznawcza): dwukierunkowa synchronizacja z GitLab.com lub samodzielnie zarządzanym GitLab.
* Serwer MCP: pozwól Claude Code, Codex, Cursor, VS Code lub Gemini CLI pracować bezpośrednio nad projektem.
* GitHub Enterprise: skieruj synchronizację z GitHub na własną instancję GitHub Enterprise.
* Rozpoznawanie odręcznie rysowanych symboli: narysuj symbol, otrzymaj polecenie LaTeX.
* `OVERLEAF_DISABLE_LOCAL_LOGIN`: ukryj logowanie za pomocą adresu e-mail i hasła, aby użytkownicy logowali się tylko przez SSO.
* Poprawki błędów wykryte przez nasz system testów E2E i Internal Horizon Issue Investigation.
* Poprawki z nadrzędnego Overleaf 6.3.1.

<Info>

Synchronizacja z Dropbox i synchronizacja z GitLab są dostępne w 6.3.1 jako **wczesne wersje zapoznawcze** do testów stopniowych i zostaną oficjalnie wydane w v6.4.0. Ich konfiguracja i działanie mogą się do tego czasu jeszcze zmienić. Obie są domyślnie wyłączone. Wszelkie problemy zgłaszaj w serwisie [GitHub](https://github.com/ayaka-notes/ayakaleaf-pro/issues).

#### Funkcja 01: Synchronizacja z Dropbox (wersja zapoznawcza)

Niektórzy ludzie nigdy nie chcą myśleć o Git. Chcą po prostu, żeby ich praca dyplomowa była folderem na laptopie, a synchronizacja z Dropbox daje im dokładnie to. Każdy użytkownik łączy własne konto Dropbox, a projekty, których jest właścicielem, oraz projekty mu udostępnione pojawiają się w `Apps/<your app name>/`. Edytuj w Overleaf, a zmiana pojawi się w Dropbox. Edytuj plik lokalnie w ulubionym edytorze, zapisz go, a zmiana wróci do Overleaf przez podpisany webhook.

Dla administratorów: Git bridge musi być włączony. Utwórz aplikację w Dropbox App Console, a następnie ustaw `DROPBOX_ENABLED`, `DROPBOX_APP_KEY`, `DROPBOX_APP_SECRET`, `DROPBOX_APP_NAME` i `DROPBOX_TOKEN_CIPHER_PASSWORD`. `DROPBOX_SYNC_PROXY_URL` jest opcjonalne i przeznaczone dla serwerów, które nie mogą połączyć się z Dropbox bezpośrednio. Następnie jednorazowo utwórz indeksy MongoDB potrzebne synchronizacji z Dropbox, zanim użytkownicy połączą swoje konta.

Pełne instrukcje konfiguracji znajdziesz w sekcji [Synchronizacja z Dropbox](/pl/on-premises/configuration/overleaf-toolkit/dropbox-synchronisation  "mention").

#### Funkcja 02: Synchronizacja z GitLab (wersja zapoznawcza)

Synchronizacja z GitHub jest jedną z naszych najbardziej lubianych funkcji od wersji 6.2, a wiele uczelni i firm przechowuje swój kod w GitLab. Synchronizacja z GitLab działa tak samo: połącz konto, zaimportuj repozytorium z menu nowego projektu lub wyeksportuj projekt do nowego projektu GitLab. Następnie wykonuj push i pull z poziomu edytora i scalaj zmiany przez merge requesty.

Działa z GitLab.com oraz z samodzielnie zarządzanym GitLab w wersji 15.10 lub nowszej. Ustaw `GITLAB_SYNC_ENABLED`, `GITLAB_SYNC_CLIENT_ID`, `GITLAB_SYNC_CLIENT_SECRET` i `GITLAB_TOKEN_CIPHER_PASSWORD`, a w przypadku instancji zarządzanej samodzielnie także `GITLAB_SYNC_URL`.

Pełne instrukcje konfiguracji znajdziesz w sekcji [Synchronizacja z GitLab](/pl/on-premises/configuration/overleaf-toolkit/gitlab-synchronisation  "mention").

#### Funkcja 03: Serwer MCP

W wersji 6.3 umieściliśmy asystenta AI w edytorze. W wersji 6.3.1 otwieramy drzwi w drugą stronę: każdy projekt ma teraz własny serwer MCP, więc agent AI, którego już używasz, może pracować bezpośrednio nad Twoim artykułem. Poproś Claude Code o poprawienie literówek we wstępie, Codex o skompilowanie projektu i naprawienie błędów LaTeX, a Cursor o odpowiedź na otwarte komentarze recenzentów. Agent odczytuje i edytuje pliki na bieżąco, więc Ty i Twoi współpracownicy widzicie jego zmiany w edytorze w trakcie pisania. Potrafi także kompilować, czytać log, pobierać PDF, liczyć słowa i wyświetlać listę wersji.

Punkt końcowy to `/project/<project_id>/mcp`. Uwierzytelniaj się tym samym tokenem Git, którego używasz do `git clone`. Dostęp jest zgodny z ustawieniami udostępniania projektu, więc agent przeglądającego może czytać, ale nie edytować, a każde narzędzie ma limit żądań. Nie trzeba niczego więcej konfigurować: serwer MCP jest włączany razem z Git bridge.

<img src="https://github.com/user-attachments/assets/a8702201-db3f-4985-a050-b7ebdbe7a952" alt="Serwer MCP" width="787" />

Informacje o tym, jak połączyć poszczególnych klientów AI, znajdziesz w sekcji [Serwer MCP](/pl/on-premises/configuration/overleaf-toolkit/mcp-server  "mention").

#### Funkcja 04: GitHub Enterprise

Synchronizacja z GitHub nie jest już ograniczona do github.com. Ustaw `GITHUB_SYNC_URL` na swój GitHub Enterprise Server lub GitHub Enterprise Cloud z rezydencją danych (`GHE.com`), a punkty końcowe REST i GraphQL zostaną z niego wyprowadzone. Jeśli Twoja instancja działa w nietypowy sposób, nadpisz je za pomocą `GITHUB_SYNC_API_URL` i `GITHUB_SYNC_GRAPHQL_URL`. Jeśli ich nie ustawisz, wszystko pozostanie przy github.com.

Szczegóły znajdziesz w sekcji [Synchronizacja z GitHub](/pl/on-premises/configuration/overleaf-toolkit/github-synchronisation#github-enterprise  "mention").

#### Funkcja 05: Rozpoznawanie odręcznie rysowanych symboli

Wiesz, jak wygląda symbol, ale nie wiesz, jak się nazywa. To `\varsigma` czy `\zeta`? `\models` czy `\vDash`? Przełącz paletę symboli w tryb rysowania, naszkicuj symbol myszą lub gładzikiem, a paleta zaproponuje pasujące polecenia LaTeX.

Rozpoznawanie działa w całości w przeglądarce z użyciem modelu wytrenowanego przez ayaka-notes, więc nic, co narysujesz, nie opuszcza Twojego komputera. Przełącznik rysowania jest ukryty w przeglądarkach bez `OffscreenCanvas` (np. Safari 15).

#### Poprawki błędów

To wydanie przynosi także długą listę poprawek. Wiele z nich wykrył nasz nowy system testów E2E, który codziennie uruchamia zestawy testów dla każdego modułu, oraz Internal Horizon Issue Investigation: za każdym razem, gdy naprawiamy błąd, przed jego zamknięciem przeszukujemy cały kod w poszukiwaniu podobnych błędów.

* **Uwierzytelnianie**: konta lokalne mogą ustawiać i zmieniać hasło w instancjach z SSO, a użytkownicy OIDC nie mogą już zmieniać własnego adresu e-mail. Logowanie przez LDAP, SAML i OIDC nie kończy się już niepowodzeniem, gdy atrybut nazwy ma kilka wartości, a wylogowanie SAML/OIDC znów działa.
* **Zawieszeni użytkownicy**: zawieszenie użytkownika kończy teraz jego sesje i zamyka otwarte edytory, a jego tokeny Git i pobierania przez MCP są odrzucane.
* **Synchronizacja z GitHub**: tylko właściciel może wyeksportować projekt, zmiany wprowadzone podczas pull pozostają oczekujące, puste pliki są synchronizowane, a ręczne scalenia są weryfikowane w GitHub.
* **Zotero / Mendeley**: gdy dane uwierzytelniające przestaną działać, otrzymasz komunikat o ponownym połączeniu, a bibliografia jest ponownie indeksowana po imporcie.
* **Usługi zewnętrzne**: żądania do Zotero, Mendeley, GitHub, GitLab i wyszukiwania w sieci mają limit czasu połączenia 3 s zamiast 1 s, więc wolniejsze sieci nie powodują już błędów.
* **Śledzenie zmian**: dane recenzji obejmują niezaładowane dokumenty i niezapisane zmiany.
* **Panel administratora**: przywracanie usuniętych projektów, zmiana właściciela i edycja użytkowników działają poprawnie, a nieudane wysłanie wiadomości e-mail nie przerywa już tworzenia ani usuwania konta.
* **Galeria szablonów**: nieprawidłowe sortowanie zwraca 400 zamiast 500, a publikowanie projektu bez pliku głównego wymaga jego wskazania.

Pełną listę znajdziesz w [informacjach o wydaniu 6.3.1](/pl/on-premises/release-notes/release-notes-6.x.x#ayakaleaf-pro-6.3.1  "mention").

#### Aktualizacja

* Z 6.3.0: migracja nie jest potrzebna. Pobierz nowy obraz i uruchom ponownie.
* Z 6.2.x lub starszej wersji z używanym Zotero lub Mendeley: najpierw uruchom [migrację Zotero / Mendeley](/pl/on-premises/release-notes/release-notes-6.x.x#ayakaleaf-pro-6.3.0  "mention") z wersji 6.3.0.
* Synchronizacja z Dropbox i synchronizacja z GitLab są domyślnie wyłączone. Synchronizacja z GitLab wymaga jedynie nowych zmiennych środowiskowych. Synchronizacja z Dropbox wymaga ponadto jednorazowego utworzenia indeksów MongoDB, zanim użytkownicy połączą swoje konta: zobacz [Utwórz indeksy bazy danych](/pl/on-premises/configuration/overleaf-toolkit/dropbox-synchronisation#create-the-database-indexes  "mention").
