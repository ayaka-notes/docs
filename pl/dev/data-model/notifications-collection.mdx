---
title: Kolekcja Notifications
icon: bell
---

`notifications` przechowuje powiadomienia wyświetlane u góry pulpitu projektów użytkownika. Jeden dokument to jedno powiadomienie dla jednego użytkownika, identyfikowane przez `key`. Bezpośrednio z kolekcji korzysta tylko usługa `notifications` (`services/notifications/app/js/Notifications.js`); `web` i `third-party-datastore` wywołują jej API HTTP. Nie ma schematu Mongoose.

#### Pola {#fields}

| Pole | Typ | Znaczenie | Źródło |
| --- | --- | --- | --- |
| `_id` | ObjectId | Id powiadomienia. `web` oznacza powiadomienie jako przeczytane za pomocą tego id. | `Notifications.js:58-65` |
| `user_id` | ObjectId | Użytkownik, który widzi powiadomienie. | `Notifications.js:26` |
| `key` | String | Identyfikuje powiadomienie, na przykład `project-invite-<inviteId>`. Upsert utrzymuje jeden dokument na `user_id` i `key`; nie ma indeksu unikalnego. | `Notifications.js:27`, `:51-55` |
| `templateKey` | String | Które powiadomienie wyświetla frontend. Usuwane, gdy powiadomienie zostanie przeczytane lub zamknięte; dokument pozostaje. | `Notifications.js:29`, `:63`, `:72`, `:78` |
| `messageOpts` | Object | Wartości do tekstu powiadomienia, zależne od `templateKey` (dla zaproszenia do projektu: `userName`, `projectName`, `projectId`, `token`). Usuwane, gdy użytkownik zamknie powiadomienie po id. | `Notifications.js:28`, `:63` |
| `expires` | Date | Opcjonalne. Indeks TTL usuwa dokument po tym czasie. | `Notifications.js:35-50` |

| Kod | Co robi |
| --- | --- |
| `Notifications.js:20-56` (`addNotification`) | `POST /user/:user_id` (`services/notifications/app.ts:29`). Wykonuje upsert według `user_id` + `key`. Jeśli dokument z tym kluczem już istnieje, jest zapisywany ponownie tylko wtedy, gdy wywołujący wyśle `forceCreate`. |
| `Notifications.js:58-65` (`removeNotificationId`) | `DELETE /user/:user_id/notification/:notification_id` (`app.ts:31-34`): usuwa `templateKey` i `messageOpts`. |
| `Notifications.js:67-80` | `DELETE /user/:user_id` i `DELETE /key/:key` (`app.ts:35-36`): usuwają `templateKey` według klucza. |
| `Notifications.js:87-100` | `DELETE /key/:key/bulk` (`app.ts:38-41`) usuwa nieprzeczytane powiadomienia z danym kluczem; `deleteNotificationByKeyOnly` usuwa jeden dokument według klucza. |
| `services/web/app/src/Features/Notifications/NotificationsHandler.mjs:33-66` | Strona `web` dla `addNotification`. Wysyła `forceCreate: true`, chyba że wywołujący przekaże `false`. |
| `services/third-party-datastore/app/js/QueueWorker.mjs:46-58` | Nasza synchronizacja z Dropbox: gdy odłącza konto Dropbox, bezpośrednio publikuje powiadomienie `dropbox-unlinked`. |

`NotificationsBuilder.mjs` buduje też klucze dla zaproszeń do grup, afiliacji instytucjonalnych, subskrypcji i starych projektów debugowania. Ich wywołania znajdują się w kodzie subskrypcji i instytucji, a sprawdzanie starych projektów debugowania działa tylko przy `isSaas` (`services/web/app/src/Features/Project/ProjectListController.mjs:234-236`).

#### Uwagi {#notes}

* Przeczytane powiadomienie nie jest usuwane: znika tylko `templateKey`. Ponieważ dokument nadal zawiera klucz, późniejsze `addNotification` bez `forceCreate` dla tego samego klucza nic nie robi (`Notifications.js:21-24`).
* Trasy `/key/:key` działają tylko według klucza, dla wszystkich użytkowników (`Notifications.js:76-100`).
* Jeśli `web` nie ma `apis.notifications.url`, nie tworzy ani nie odczytuje powiadomień (`NotificationsHandler.mjs:17`, `:41`).
