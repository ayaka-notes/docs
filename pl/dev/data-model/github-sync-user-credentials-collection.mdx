---
title: Kolekcja GitHub Sync User Credentials
icon: key
---

`githubSyncUserCredentials` przechowuje jeden dokument na każdego użytkownika, który połączył konto GitHub dla GitHub Sync. Przechowuje zaszyfrowany token dostępu OAuth użytkownika. Kolekcja należy do modułu web `github-sync` (`services/web/modules/github-sync`). Schemat znajduje się w `services/web/modules/github-sync/app/models/githubSyncUserCredentials.mjs`, a cały dostęp przechodzi przez `services/web/modules/github-sync/app/src/TokenManager.mjs`.

#### Pola {#fields}

| Pole | Typ | Znaczenie | Źródło |
| ----- | ---- | ------- | ------ |
| `_id` | ObjectId | Ustawiane przez Mongoose, gdy upsert wstawia dokument. | |
| `userId` | ObjectId | Użytkownik Overleaf. Wymagane. Schemat podaje `unique: true`, ale żaden indeks nie jest budowany (zobacz Indeksy); upsert po `userId` utrzymuje jeden dokument na użytkownika. | `githubSyncUserCredentials.mjs:8`, `TokenManager.mjs:44-48` |
| `github` | String | Token dostępu OAuth GitHub, zaszyfrowany za pomocą `@overleaf/access-token-encryptor`. Hasło pochodzi z `GITHUB_TOKEN_CIPHER_PASSWORD`; etykieta szyfru to `GITHUB_TOKEN_CIPHER_LABEL`, domyślnie `2026.3-v3`. Wymagane. | `githubSyncUserCredentials.mjs:9`, `TokenManager.mjs:12-25` |
| `__v` | Number | Klucz wersji Mongoose. Schemat go nie wyłącza. | Domyślnie w Mongoose |

Przechowywany jest tylko token dostępu: callback OAuth zachowuje `access_token` z odpowiedzi GitHub (`services/web/modules/github-sync/app/src/GitHubApiClient.mjs:180-191`). Nie ma tokenu odświeżania ani czasu wygaśnięcia.

#### Kto zapisuje {#who-writes-it}

| Kod | Co robi |
| ---- | ------------ |
| `TokenManager.mjs:42-58` (`saveUserToken`) | Wykonuje upsert zaszyfrowanego tokenu użytkownika. Gdy użytkownik łączy konto ponownie, zastąpiony token jest w tle unieważniany w GitHub. Wywoływane z callbacku OAuth (`services/web/modules/github-sync/app/src/GitHubSyncController.mjs:146`). |
| `TokenManager.mjs:61-76` (`removeUserToken`) | Unieważnia token w GitHub (w miarę możliwości), a potem usuwa dokument. Wywoływane przy odłączaniu (`GitHubSyncController.mjs:167`) i gdy wygasa usunięty użytkownik (`services/web/modules/github-sync/index.mjs:66-68`). |

#### Kto odczytuje {#who-reads-it}

| Kod | Co robi |
| ---- | ------------ |
| `TokenManager.mjs:36-40` (`getUserToken`) | Odszyfrowuje token przy każdym wywołaniu API GitHub: `services/web/modules/github-sync/app/src/GitHubSyncHandler.mjs` (na przykład `:27`) i `services/web/modules/github-sync/app/src/GitMerge.mjs:43`. Bez dokumentu albo z tokenem, którego nie da się odszyfrować, rzuca `InvalidTokenError`, a użytkownik jest traktowany jako niepołączony (`GitHubSyncHandler.mjs:25-37`). |
| `services/web/modules/admin-tools/app/src/AdminUserListManager.mjs:393` | Sprawdza, czy użytkownik ma dokument, na potrzeby integracji pokazywanych w panelu administracyjnym. |

#### Indeksy {#indexes}

| Nazwa | Klucze | Opcje | Migracja |
| ---- | ---- | ------- | --------- |
| `_id_` | `_id: 1` | | default |

`autoIndex` w Mongoose jest wyłączony (`services/web/app/src/infrastructure/Mongoose.mjs:7`), więc `unique: true` ze schematu na `userId` niczego nie tworzy. `tools/migrations/20190912145011_create_githubSyncUserCredentials_indexes.mjs` (`user_id` z upstream) ma tylko tag `saas` i nie uruchamia się w CE.

#### Uwagi {#notes}

* Zmiana `GITHUB_TOKEN_CIPHER_PASSWORD` sprawia, że zapisane tokeny stają się nieczytelne. Ci użytkownicy są wtedy traktowani jako niepołączeni, dopóki nie połączą konta ponownie.
* Usunięty użytkownik zachowuje dokument, dopóki nie wygaśnie.
