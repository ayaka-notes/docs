---
title: Kolekcja Project History Sharded Blobs
icon: cubes-stacked
---

`projectHistoryShardedBlobs` przechowuje rekordy blobów, które nie zmieściły się w [projectHistoryBlobs](/dev/data-model/project-history-blobs-collection): gdy kubełek dla prefiksu hasha ma tam już 8 rekordów, kolejne trafiają tutaj. Projekt ma tu najwyżej 16 dokumentów, po jednym na pierwszą cyfrę szesnastkową hasha. Nie ma schematu Mongoose; history-v1 zapisuje ją w `services/history-v1/storage/lib/blob_store/mongo.js` (układ opisany w `mongo.js:1-16`).

#### Pola {#fields}

| Pole | Typ | Znaczenie | Źródło |
| ----- | ---- | ------- | ------ |
| `_id` | Binary | 13 bajtów: identyfikator historii projektu, `0`, oraz cyfra sharda, odczytywana szesnastkowo (`<history id>0<digit>`). Cyfra sharda to pierwsza cyfra szesnastkowa hasha. | `mongo.js:439-453` |
| `blobs` | Object | Rekordy blobów pogrupowane w kubełki. Kluczem kubełka są cyfry szesnastkowe hasha od 2. do 4. | `mongo.js:439-443` |
| `blobs.<bcd>` | Array of Object | Rekordy kubełka. Kod nie ogranicza jego rozmiaru. | `mongo.js:399-407` |
| `blobs.<bcd>[].h` | Binary | Hash, 20 bajtów, jak w projectHistoryBlobs. | `mongo.js:472` |
| `blobs.<bcd>[].b` | Number | Długość zawartości w bajtach. | `mongo.js:473` |
| `blobs.<bcd>[].s` | Number | Długość zawartości jako tekstu; `null`, gdy zawartość nie jest edytowalnym tekstem. | `mongo.js:474` |

#### Kto zapisuje {#who-writes-it}

| Kod | Co robi |
| ---- | ------------ |
| `services/history-v1/storage/lib/blob_store/mongo.js:399-407` | `insertRecordSharded`: upsert z `$addToSet` do kubełka. Wywoływane przez `insertBlob`, gdy kubełek w projectHistoryBlobs jest pełny (`mongo.js:387-389`). |
| `mongo.js:75-103` | `clone`: kopiuje shardy projektu do innego identyfikatora historii, dla history-v1 `POST /projects/:project_id/clone`, której nic w web nie wywołuje. |
| `mongo.js:413-422` | `deleteBlobs`: usuwa wszystkie shardy projektu razem z jego dokumentem projectHistoryBlobs, przy history-v1 `DELETE /projects/:project_id`. |

#### Kto odczytuje {#who-reads-it}

| Kod | Co robi |
| ---- | ------------ |
| `mongo.js:144-157` | `findBlobSharded`: jeden blob, wyszukiwany tylko wtedy, gdy jego kubełek w projectHistoryBlobs ma 8 rekordów i go nie zawiera (`mongo.js:127-131`). |
| `mongo.js:217-260` | `findBlobsSharded`: bloby, których `findBlobs` nie znalazło w projectHistoryBlobs (`mongo.js:202-206`). |
| `mongo.js:285-306` | `getProjectBlobs`: wszystkie shardy projektu. |
| `mongo.js:337-361` | `getProjectBlobsBatch`: wszystkie shardy kilku projektów, dla trasy statystyk blobów. |

#### Indeksy {#indexes}

Tylko domyślny indeks `_id`. Żadna migracja w `tools/migrations/` go nie dodaje.

#### Uwagi {#notes}

* Shardy jednego projektu leżą obok siebie w kolejności `_id`, więc kod znajduje je zakresem `_id` od `<history id>00` do `<history id>0f` (`mongo.js:75-80`, `287-295`).
* Kolekcja pojawia się dopiero wtedy, gdy jakiś projekt ma więcej niż 8 blobów z tym samym 3-cyfrowym prefiksem hasha, więc mała instancja może jej w ogóle nie mieć.
