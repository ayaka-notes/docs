---
title: Kolekcja Gitea Sync User Credentials
icon: lock
---

`giteaSyncUserCredentials` przechowuje jeden dokument na każdego użytkownika, który połączył konto Gitea dla Gitea Sync. Przechowuje zaszyfrowane tokeny OAuth użytkownika. Kolekcja należy do modułu web `gitea-sync` (`services/web/modules/gitea-sync`). Schemat znajduje się w `services/web/modules/gitea-sync/app/models/giteaSyncUserCredentials.mjs`, a cały dostęp przechodzi przez `services/web/modules/gitea-sync/app/src/TokenManager.mjs`.

#### Pola {#fields}

| Pole | Typ | Znaczenie | Źródło |
| ----- | ---- | ------- | ------ |
| `_id` | ObjectId | Ustawiane przez Mongoose, gdy upsert wstawia dokument. | |
| `userId` | ObjectId | Użytkownik Overleaf. Wymagane. Schemat podaje `unique: true`, ale żaden indeks nie jest budowany (zobacz Indeksy); upsert po `userId` utrzymuje jeden dokument na użytkownika. | `giteaSyncUserCredentials.mjs:8`, `TokenManager.mjs:89-96` |
| `gitea` | String | JSON `{ accessToken, refreshToken, expiresAt }`, zaszyfrowany za pomocą `@overleaf/access-token-encryptor`. `expiresAt` to milisekundy od epoki albo `null`; `refreshToken` może być `null`. Hasło pochodzi z `GITEA_TOKEN_CIPHER_PASSWORD`; etykieta szyfru to `GITEA_TOKEN_CIPHER_LABEL`, domyślnie `2026.10-v3`. Wymagane. | `giteaSyncUserCredentials.mjs:9-10`, `TokenManager.mjs:17-30`, `services/web/modules/gitea-sync/app/src/GiteaApiClient.mjs:198-209` |
| `__v` | Number | Klucz wersji Mongoose. Schemat go nie wyłącza. | Domyślnie w Mongoose |

#### Kto zapisuje {#who-writes-it}

| Kod | Co robi |
| ---- | ------------ |
| `TokenManager.mjs:89-96` (`saveUserToken`) | Wykonuje upsert zaszyfrowanych danych uwierzytelniających użytkownika. Wywoływane z callbacku OAuth (`services/web/modules/gitea-sync/app/src/GiteaSyncController.mjs:146`). W przeciwieństwie do GitLab Sync ponowne połączenie nie unieważnia zastąpionego tokenu. |
| `TokenManager.mjs:53-79` (`refreshUserToken`) | Gdy do `expiresAt` tokenu dostępu zostaje mniej niż 5 minut (`:12`), pobiera nowe tokeny za pomocą tokenu odświeżania i je zapisuje (`:76`). Działa pod blokadą `giteaSyncToken` dla każdego użytkownika (`:14,54`), bo Gitea zastępuje token odświeżania przy użyciu. |
| `TokenManager.mjs:100-102` (`removeUserToken`) | Usuwa dokument. Gitea nie ma API do unieważniania tokenu OAuth, więc użytkownik sam cofa uprawnienie w Gitea (`:98-99`). Wywoływane przy odłączaniu (`GiteaSyncController.mjs:173`) i gdy wygasa usunięty użytkownik (`services/web/modules/gitea-sync/index.mjs:56-58`). |

#### Kto odczytuje {#who-reads-it}

| Kod | Co robi |
| ---- | ------------ |
| `TokenManager.mjs:40-44,82-86` (`getUserCredentials`, `getUserToken`) | Odszyfrowuje dane uwierzytelniające przy każdym wywołaniu API Gitea, najpierw je odświeżając, gdy token zaraz wygaśnie: `services/web/modules/gitea-sync/app/src/GiteaSyncHandler.mjs` (na przykład `:27`) i `services/web/modules/gitea-sync/app/src/GitMerge.mjs:52`. Bez dokumentu albo z danymi, których nie da się odszyfrować ani odświeżyć, rzuca `InvalidTokenError`, a użytkownik jest traktowany jako niepołączony (`GiteaSyncHandler.mjs:25-37`). |
| `services/web/modules/admin-tools/app/src/AdminUserListManager.mjs:395` | Sprawdza, czy użytkownik ma dokument, na potrzeby integracji pokazywanych w panelu administracyjnym. |

#### Indeksy {#indexes}

| Nazwa | Klucze | Opcje | Migracja |
| ---- | ---- | ------- | --------- |
| `_id_` | `_id: 1` | | default |

`autoIndex` w Mongoose jest wyłączony (`services/web/app/src/infrastructure/Mongoose.mjs:7`), więc `unique: true` ze schematu na `userId` niczego nie tworzy. Żadna migracja nie tworzy indeksów dla tej kolekcji.

#### Uwagi {#notes}

* Zmiana `GITEA_TOKEN_CIPHER_PASSWORD` sprawia, że zapisane dane uwierzytelniające stają się nieczytelne. Ci użytkownicy są wtedy traktowani jako niepołączeni, dopóki nie połączą konta ponownie.
* Usunięty użytkownik zachowuje dokument, dopóki nie wygaśnie.
