---
title: Kolekcja GitLab Sync User Credentials
icon: user-lock
---

`gitlabSyncUserCredentials` przechowuje jeden dokument na każdego użytkownika, który połączył konto GitLab dla GitLab Sync. Przechowuje zaszyfrowane tokeny OAuth użytkownika. Kolekcja należy do modułu web `gitlab-sync` (`services/web/modules/gitlab-sync`). Schemat znajduje się w `services/web/modules/gitlab-sync/app/models/gitlabSyncUserCredentials.mjs`, a cały dostęp przechodzi przez `services/web/modules/gitlab-sync/app/src/TokenManager.mjs`.

#### Pola {#fields}

| Pole | Typ | Znaczenie | Źródło |
| ----- | ---- | ------- | ------ |
| `_id` | ObjectId | Ustawiane przez Mongoose, gdy upsert wstawia dokument. | |
| `userId` | ObjectId | Użytkownik Overleaf. Wymagane. Schemat podaje `unique: true`, ale żaden indeks nie jest budowany (zobacz Indeksy); upsert po `userId` utrzymuje jeden dokument na użytkownika. | `gitlabSyncUserCredentials.mjs:8`, `TokenManager.mjs:88-95` |
| `gitlab` | String | JSON `{ accessToken, refreshToken, expiresAt }`, zaszyfrowany za pomocą `@overleaf/access-token-encryptor`. `expiresAt` to milisekundy od epoki albo `null`; `refreshToken` może być `null`. Hasło pochodzi z `GITLAB_TOKEN_CIPHER_PASSWORD`; etykieta szyfru to `GITLAB_TOKEN_CIPHER_LABEL`, domyślnie `2026.10-v3`. Wymagane. | `gitlabSyncUserCredentials.mjs:9-10`, `TokenManager.mjs:18-31`, `services/web/modules/gitlab-sync/app/src/GitLabApiClient.mjs:209-220` |
| `__v` | Number | Klucz wersji Mongoose. Schemat go nie wyłącza. | Domyślnie w Mongoose |

#### Kto zapisuje {#who-writes-it}

| Kod | Co robi |
| ---- | ------------ |
| `TokenManager.mjs:88-95` (`saveUserToken`) | Wykonuje upsert zaszyfrowanych danych uwierzytelniających użytkownika. |
| `TokenManager.mjs:99-108` (`linkUserToken`) | Zapisuje nowe dane uwierzytelniające z callbacku OAuth (`services/web/modules/gitlab-sync/app/src/GitLabSyncController.mjs:146`). Gdy użytkownik łączy konto ponownie, zastąpiony token dostępu jest w tle unieważniany w GitLab. |
| `TokenManager.mjs:53-78` (`refreshUserToken`) | Gdy do `expiresAt` tokenu dostępu zostaje mniej niż 5 minut (`:13,47-49`), pobiera nowe tokeny za pomocą tokenu odświeżania i je zapisuje (`:75`). Działa pod blokadą `gitlabSyncToken` dla każdego użytkownika (`:15,54`), bo GitLab zużywa token odświeżania przy użyciu. |
| `TokenManager.mjs:111-126` (`removeUserToken`) | Unieważnia token dostępu w GitLab (w miarę możliwości), a potem usuwa dokument. Wywoływane przy odłączaniu (`GitLabSyncController.mjs:173`) i gdy wygasa usunięty użytkownik (`services/web/modules/gitlab-sync/index.mjs:56-58`). |

#### Kto odczytuje {#who-reads-it}

| Kod | Co robi |
| ---- | ------------ |
| `TokenManager.mjs:41-45,81-85` (`getUserCredentials`, `getUserToken`) | Odszyfrowuje dane uwierzytelniające przy każdym wywołaniu API GitLab, najpierw je odświeżając, gdy token zaraz wygaśnie: `services/web/modules/gitlab-sync/app/src/GitLabSyncHandler.mjs` (na przykład `:27`) i `services/web/modules/gitlab-sync/app/src/GitMerge.mjs:52`. Bez dokumentu albo z danymi, których nie da się odszyfrować ani odświeżyć, rzuca `InvalidTokenError`, a użytkownik jest traktowany jako niepołączony (`GitLabSyncHandler.mjs:25-37`). |
| `services/web/modules/admin-tools/app/src/AdminUserListManager.mjs:394` | Sprawdza, czy użytkownik ma dokument, na potrzeby integracji pokazywanych w panelu administracyjnym. |

#### Indeksy {#indexes}

| Nazwa | Klucze | Opcje | Migracja |
| ---- | ---- | ------- | --------- |
| `_id_` | `_id: 1` | | default |

`autoIndex` w Mongoose jest wyłączony (`services/web/app/src/infrastructure/Mongoose.mjs:7`), więc `unique: true` ze schematu na `userId` niczego nie tworzy. Żadna migracja nie tworzy indeksów dla tej kolekcji.

#### Uwagi {#notes}

* Zmiana `GITLAB_TOKEN_CIPHER_PASSWORD` sprawia, że zapisane dane uwierzytelniające stają się nieczytelne. Ci użytkownicy są wtedy traktowani jako niepołączeni, dopóki nie połączą konta ponownie.
* Usunięty użytkownik zachowuje dokument, dopóki nie wygaśnie.
