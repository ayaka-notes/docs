---
title: Kolekcja Dropbox Entities
icon: file-arrow-up
---

`dropboxEntities` przechowuje jeden dokument na każdy plik, który synchronizacja z Dropboxem skopiowała między projektem a Dropboxem jednego użytkownika, a także krótkotrwałe tombstone'y. Kolekcja należy do synchronizacji z Dropboxem: third-party-datastore (`services/third-party-datastore/app/js/StateManager.mjs`) ją zapisuje i odczytuje, a moduł web `dropbox` (`services/web/modules/dropbox/app/src/DropboxHandler.mjs`) ją czyści. Nie ma schematu Mongoose.

#### Pola {#fields}

| Pole | Typ | Znaczenie | Źródło |
| ---- | --- | --------- | ------ |
| `_id` | ObjectId | Ustawiane przez sterownik przy wstawianiu. | `StateManager.mjs:46,97` |
| `overleaf.userId` | ObjectId | Użytkownik, w którego Dropboxie jest plik. Ustawiane w każdym dokumencie. | `StateManager.mjs:48,98` |
| `overleaf.projectId` | ObjectId | Projekt doca lub pliku. Ustawiane, gdy jest znany; tombstone'y go nie mają. | `StateManager.mjs:49-51` |
| `overleaf.id` | ObjectId | `_id` doca lub pliku w `rootFolder` projektu. Ustawiane, gdy jest znany. | `StateManager.mjs:52` |
| `overleaf.type` | String | `doc` lub `file`. Obecny kod je zapisuje, ale go nie odczytuje. | `StateManager.mjs:53`; wartości z `services/web/app/src/Features/ThirdPartyDataStore/TpdsUpdateSender.mjs:35,96` i `UpdateMerger.mjs:104,119` |
| `dropbox.id` | String | `id` pliku w metadanych pliku Dropbox. Nieustawiane w tombstone'ach. | `StateManager.mjs:56` |
| `dropbox.pathLower` | String | Ścieżka pliku w Dropboxie, małymi literami i bez końcowego ukośnika. Aktualizowana, gdy plik lub folder jego projektu zostanie przeniesiony. | `StateManager.mjs:14-16,57,91,99` |
| `dropbox.rev` | String | Rewizja Dropboxa przy ostatniej synchronizacji. Następne przesłanie ją wysyła, aby plik zmieniony w Dropboxie nie został nadpisany. | `StateManager.mjs:58`, `JobProcessor.mjs:114-122` |
| `dropbox.contentHash` | String | Hash zawartości Dropboxa przy ostatniej synchronizacji. Plik z listy z tym samym hashem jest pomijany, ponieważ to nasze własne przesłanie albo został już zastosowany. | `StateManager.mjs:59`, `PullManager.mjs:147-149` |
| `tombstone` | Boolean | `true` oznacza ścieżkę, którą third-party-datastore sam usunął lub przeniósł w Dropboxie. Gdy Dropbox zgłosi to usunięcie z powrotem, nie jest ono stosowane do projektu. | `StateManager.mjs:100`, `PullManager.mjs:189-192` |
| `createdAt` | Date | Tylko tombstone'y: kiedy został utworzony. Zakończony pull usuwa tombstone'y utworzone przed jego rozpoczęciem. | `StateManager.mjs:101,115-121` |

Tombstone ma tylko `overleaf.userId`, `dropbox.pathLower`, `tombstone` i `createdAt` (`StateManager.mjs:96-103`).

#### Kto ją zapisuje {#who-writes-it}

| Kod | Co robi |
| --- | ------- |
| `services/third-party-datastore/app/js/StateManager.mjs:35-62` (`recordEntity`) | Usuwa dokumenty użytkownika z tym samym `dropbox.id`, `dropbox.pathLower` lub `overleaf.id`, a następnie wstawia nowy stan. |
| `services/third-party-datastore/app/js/JobProcessor.mjs:102-134` (`addEntity`) | Zapisuje doc lub plik po przesłaniu z Overleaf do Dropboxa (`:125-133`). |
| `services/third-party-datastore/app/js/PullManager.mjs:142-177` (`applyFile`) | Zapisuje plik z Dropboxa po tym, jak web zastosował go do projektu (`:168-176`). |
| `StateManager.mjs:80-94` (`moveEntities`) | Przepisuje `dropbox.pathLower` pod przeniesioną ścieżką: zmiana nazwy projektu (`JobProcessor.mjs:195`) i przeniesienie pliku lub folderu (`JobProcessor.mjs:239`). |
| `StateManager.mjs:96-103` (`addTombstone`) | Po usunięciu (`JobProcessor.mjs:153`), zmianie nazwy projektu (`:202`) lub przeniesieniu (`:240`) w Dropboxie. |
| `StateManager.mjs:72-78` (`removeEntities`) | Usuwa wpisy pod ścieżką i poniżej niej, z wyjątkiem tombstone'ów: po usunięciu w Overleaf (`JobProcessor.mjs:152`) lub w Dropboxie (`PullManager.mjs:206`). |
| `StateManager.mjs:115-121` (`clearTombstones`) | Na końcu pulla (`PullManager.mjs:31,69`). |
| `StateManager.mjs:186-190` (`removeUserState`), wywoływane z `services/third-party-datastore/app/js/QueueWorker.mjs:43` | Usuwa wszystkie dokumenty użytkownika, gdy third-party-datastore odłącza konto, którego nie może już używać. |
| `DropboxHandler.mjs:142-146` (`removeUserState`) | Usuwa wszystkie dokumenty użytkownika przy łączeniu (`:125`), przy odłączaniu (`:183`) i gdy wygasa usunięty użytkownik (`services/web/modules/dropbox/index.mjs:62-64`). |
| `DropboxHandler.mjs:150-154` (`removeProjectState`) | Usuwa dokumenty projektu, gdy wygasa usunięty projekt (`index.mjs:54-56`). |

#### Kto ją odczytuje {#who-reads-it}

| Kod | Co robi |
| --- | ------- |
| `StateManager.mjs:64-70` (`findEntityByPath`) | Pobiera `dropbox.rev` przed przesłaniem (`JobProcessor.mjs:114`) i `dropbox.contentHash` przed zastosowaniem pliku z Dropboxa (`PullManager.mjs:147`). |
| `StateManager.mjs:106-112` (`findTombstone`) | Sprawdza zgłoszone usunięcie pod ścieżką lub pod jedną z jej ścieżek nadrzędnych (`PullManager.mjs:189`). |
| `StateManager.mjs:160-175` (`getSyncedPaths`) | Wypisuje ścieżki zsynchronizowanych plików po zresetowaniu kursora, aby plik nieobecny na liście był uznany za usunięty (`PullManager.mjs:74-85`). |

| Nazwa | Klucze | Opcje | Migracja |

`20220811111800_create_dropboxEntities_index.mjs` i `20220825160708_recreate_dropboxEntities.mjs` mają tylko tag `saas`, więc CE nie ma ich unikalnych indeksów na `(overleaf.userId, dropbox.id)` i `(overleaf.userId, overleaf.id)` ani ich indeksu haszowanego na `dropbox.pathLower`.

#### Uwagi {#notes}

* Unikalność wynika wyłącznie z usuwania przed każdym wstawieniem w `recordEntity` (`StateManager.mjs:38-45`). Komentarz w `StateManager.mjs:3-11` wspomina o unikalnych indeksach; CE ich nie ma.
* Zapytania według użytkownika i ścieżki (`findEntityByPath`, `findTombstone`, `removeEntities`) używają indeksu tylko dla `overleaf.userId`.
