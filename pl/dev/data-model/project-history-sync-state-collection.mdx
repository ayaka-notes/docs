---
title: Kolekcja Project History Sync State
icon: rotate
---

`projectHistorySyncState` zawiera jeden dokument na każdy projekt, który przeszedł ponowną synchronizację: stan bieżącej lub ostatniej ponownej synchronizacji, podczas której project-history odbudowuje historię projektu z tego, co przechowują web i docstore. Kolekcja należy do project-history i nie ma schematu Mongoose; kodem jest klasa `SyncState` i jej funkcje pomocnicze w `services/project-history/app/js/SyncManager.js`.

#### Kto zapisuje {#who-writes-it}

| Kod | Co robi |
| ---- | ------------ |
| `services/project-history/app/js/SyncManager.js:195-249` | `setResyncState`: upsert stanu. Wywoływane, gdy rozpoczyna się ponowna synchronizacja (`SyncManager.js:163`), oraz gdy project-history przetwarza aktualizacje ponownej synchronizacji (`services/project-history/app/js/UpdatesProcessor.js:637`, `784`). |
| `SyncManager.js:257-266` | `_recordStuckClearInSyncState`: zlicza wyczyszczoną zawieszoną ponowną synchronizację. |
| `SyncManager.js:251-255` | `clearResyncState`: usuwa dokument na początku twardej ponownej synchronizacji (`SyncManager.js:87`), przy `DELETE /project/:project_id` w project-history (`services/project-history/app/js/HttpController.js:1363-1396`) oraz gdy ponowna synchronizacja samej struktury musi zacząć się od nowa (`SyncManager.js:705-716`). |
| `SyncManager.js:273-289` | `clearResyncStateIfAllAfter`: usuwa zakończony stan, którego cała historia jest nowsza niż podana data. Nic w `app/js` tego nie wywołuje. |
| `SyncManager.js:171-181` | `cloneResyncState`: kopiuje stan do innego projektu, dla `POST /project/:project_id/clone` w project-history (`HttpController.js:57`, `124`), czego nic w web nie wywołuje. |

Ponowną synchronizację uruchamiają `POST /project/:project_id/resync` w project-history (`HttpController.js:950-994`), zadania cron ponawiania (`services/project-history/app/js/RetryManager.js:156-179`, `server-ce/config/crontab-history`) oraz sam project-history, gdy przetwarzanie aktualizacji jej wymaga (`UpdatesProcessor.js:75`, `224`).

#### Kto odczytuje {#who-reads-it}

| Kod | Co robi |
| ---- | ------------ |
| `SyncManager.js:187-193` | `getResyncState`: wczytuje stan. Służy do sprawdzenia przed uruchomieniem nowej ponownej synchronizacji, czy jakaś już trwa (`SyncManager.js:106-149`), do pomijania zwykłych aktualizacji w jej trakcie (`SyncManager.js:291-300`) oraz po flushu do zgłoszenia trwającej ponownej synchronizacji (`UpdatesProcessor.js:463-466`). |
| `HttpController.js:533-545` | `GET /project/:project_id/resync-pending`: czy ponowna synchronizacja trwa lub jest zawieszona. |
| `HttpController.js:563-585` | `GET /project/:project_id/debug-info`: stan synchronizacji wraz z rekordem błędu. |

#### Uwagi {#notes}

* Ponowna synchronizacja trwa, dopóki `resyncProjectStructure` ma wartość `true` lub `resyncDocContents` nie jest puste (`SyncManager.js:565-567`). Po 4 godzinach uznaje się ją za zawieszoną, a po 5 czyszczeniach za trwale zawieszoną (`SyncManager.js:43-44`, `569-585`).
* Po zakończeniu ponownej synchronizacji project-history ustawia też w projekcie `overleaf.history.lastResyncedAt` (`SyncManager.js:239-248`).
