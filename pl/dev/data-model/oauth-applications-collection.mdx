---
title: Kolekcja OAuth Applications
icon: id-badge
---

`oauthApplications` przechowuje klientów OAuth, których zna web. Jeden dokument to jeden klient. W Ayakaleaf Pro zapisuje do niej tylko moduł web `git-bridge`, który przy starcie web tworzy jednego klienta o nazwie `Overleaf Git Bridge`. Schemat to `services/web/app/src/models/OauthApplication.mjs`.

#### Pola {#fields}

| Pole | Typ | Znaczenie | Źródło |
| ----- | ---- | ------- | ------ |
| `_id` | ObjectId | Id dokumentu klienta. Wskazują na nie `oauthAccessTokens.oauthApplication_id` i `oauthAuthorizationCodes.oauthApplication_id`. | `OauthApplication.mjs:5` |
| `id` | String | Id klienta: 64 losowe małe litery i cyfry. | `OauthApplication.mjs:7`, `services/web/modules/git-bridge/index.mjs:25` |
| `clientSecret` | String | Sekret klienta, zapisywany jako `v1.` plus 32 losowe znaki. Czyta go tylko `getClient`, a nic nie wywołuje `getClient` (zobacz Uwagi). | `OauthApplication.mjs:8`, `git-bridge/index.mjs:26` |
| `grants` | Array of String | Typy grantów. Klient git-bridge ma `['password']`. Zwracane z klientem przy sprawdzaniu tokenu (`services/web/modules/oauth2-server/app/src/OAuth2Model.mjs:67-72`). | `OauthApplication.mjs:9`, `git-bridge/index.mjs:27` |
| `name` | String | Nazwa klienta. Moduł git-bridge i kod osobistych tokenów dostępu znajdują klienta po nazwie `Overleaf Git Bridge`. | `OauthApplication.mjs:10`, `git-bridge/index.mjs:15-16,28` |
| `redirectUris` | Array of String | Dozwolone adresy URI przekierowania. `[]` dla klienta git-bridge. | `OauthApplication.mjs:11`, `git-bridge/index.mjs:29` |
| `scopes` | Array of String | Zakresy, których klient może używać. `['git_bridge']` dla klienta git-bridge. | `OauthApplication.mjs:12`, `git-bridge/index.mjs:30` |
| `pkceEnabled` | Boolean | Tylko w schemacie: żaden kod w tym repozytorium go nie zapisuje, a czyta go tylko nieużywane `getClient` (`OAuth2Model.mjs:207`). | `OauthApplication.mjs:13` |

#### Kto zapisuje {#who-writes-it}

| Kod | Co robi |
| ---- | ------------ |
| `git-bridge/index.mjs:9-35` (module `git-bridge`) | Gdy `GIT_BRIDGE_ENABLED` ma wartość `true`, przy starcie web tworzy klienta `Overleaf Git Bridge`, jeśli klient o tej nazwie jeszcze nie istnieje. |

#### Kto odczytuje {#who-reads-it}

| Kod | Co robi |
| ---- | ------------ |
| `services/web/modules/oauth2-server/app/src/OAuthPersonalAccessTokenManager.mjs:53-61` (module `oauth2-server`) | Znajduje klienta `Overleaf Git Bridge` po nazwie i zapisuje jego `_id` w każdym nowym osobistym tokenie dostępu. Bez klienta żaden token nie powstaje. |
| `OAuth2Model.mjs:31-39,67-72` (`getAccessToken`) | Wczytuje klienta tokenu przez `oauthApplication_id` i zwraca jego `id` oraz `grants`. |
| `OAuth2Model.mjs:185-209,241,275` (`getClient`, `saveToken`, `saveAuthorizationCode`) | Wyszukują klientów po `id`. W tym repozytorium nigdy nie są wywoływane, zobacz Uwagi. |

#### Indeksy {#indexes}

Tylko domyślny indeks na `_id`. Unikalny indeks `id_1` pochodzi z migracji oznaczonych `saas` (`20190912145016_create_oauthApplications_indexes.mjs`) i `server-pro` (`20230502180757_server_pro_oauth_indexes.mjs`), których Community Edition nie uruchamia.

#### Uwagi {#notes}

* Web używa `@node-oauth/oauth2-server` tylko do sprawdzania tokenów bearer (`server.authenticate` w `services/web/app/src/Features/Authentication/AuthenticationController.mjs:409-450`), co wywołuje tylko metody modelu `getAccessToken` i `verifyScope`. Żadna trasa nie obsługuje `/oauth/token` ani `/oauth/authorize`, więc `getClient`, `saveToken` i `saveAuthorizationCode` nigdy nie są wywoływane.
* Moduł szuka klienta po nazwie, a potem go tworzy, a Community Edition nie ma unikalnego indeksu na `name` ani `id`. Nic więc nie blokuje drugiego klienta o tej samej nazwie. Kod, który potrzebuje klienta, bierze tego, którego zwróci `findOne`.
