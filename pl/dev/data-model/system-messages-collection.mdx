---
title: Kolekcja System Messages
icon: bullhorn
---

`systemmessages` przechowuje banery dla całej witryny, które administrator publikuje dla wszystkich zalogowanych użytkowników. Jeden dokument to jedna wiadomość. Właścicielem jest `web`; schemat to `services/web/app/src/models/SystemMessage.mjs`, a kod to `services/web/app/src/Features/SystemMessages/SystemMessageManager.mjs`.

#### Pola {#fields}

| Pole | Typ | Znaczenie | Źródło |
| --- | --- | --- | --- |
| `_id` | ObjectId | Id wiadomości. Przeglądarka zapamiętuje po tym id, które wiadomości użytkownik zamknął (`services/web/frontend/js/shared/components/system-message.tsx:10`). | `SystemMessage.mjs:5` |
| `content` | String | Treść wiadomości, domyślnie `''`. | `SystemMessage.mjs:7` |
| `__v` | Number | Klucz wersji Mongoose, dodawany przez `message.save()`. | `SystemMessageManager.mjs:29-30` |

#### Kto zapisuje {#who-writes-it}

| Kod | Co robi |
| --- | --- |
| `SystemMessageManager.mjs:28-33` (`createMessage`) | `POST /admin/messages` (`services/web/app/src/router.mjs:1150-1152`, `services/web/app/src/Features/ServerAdmin/AdminController.mjs:151-159`): dodaje jedną wiadomość. |
| `SystemMessageManager.mjs:22-26` (`clearMessages`) | `POST /admin/messages/clear` (`router.mjs:1155-1157`, `AdminController.mjs:161-168`): usuwa wszystkie wiadomości. Nie da się usunąć pojedynczej. |

#### Kto odczytuje {#who-reads-it}

| Kod | Co robi |
| --- | --- |
| `SystemMessageManager.mjs:50-65` | Każdy proces `web` trzyma wszystkie wiadomości w pamięci i wczytuje je ponownie co 20 do 30 sekund oraz zaraz po własnym utworzeniu lub wyczyszczeniu. |
| `services/web/app/src/Features/SystemMessages/SystemMessageController.mjs:6-24` | `GET /system/messages` (`router.mjs:331`): zwraca zalogowanym użytkownikom wiadomości z pamięci podręcznej. Gdy witryna jest zamknięta (`siteIsOpen` ma wartość false), zamiast tego zwraca stałe powiadomienie, które nie jest przechowywane w Mongo. |
| `AdminController.mjs:83-84` | Strona `/admin` wyświetla wiadomości bezpośrednio z Mongo. |

#### Indeksy {#indexes}

Żadna migracja nie tworzy indeksu na `systemmessages`; istnieje tylko domyślny indeks `_id`.

#### Uwagi {#notes}

* Gdy ustawiono `notifyOnSystemMessageChanges`, utworzenie lub wyczyszczenie jest też publikowane na kanale Redis `refresh-system-messages`, więc inne procesy `web` od razu wczytują wiadomości ponownie (`SystemMessageManager.mjs:9`, `:35-48`, `:75-87`). Bez tego ustawienia zmianę uwzględnią przy następnym planowym wczytaniu.
