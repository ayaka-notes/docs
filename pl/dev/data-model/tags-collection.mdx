`tags` przechowuje tagi (foldery), w których użytkownik porządkuje projekty na pulpicie projektów. Jeden dokument to jeden tag jednego użytkownika. Właścicielem jest `web`; schemat to `services/web/app/src/models/Tag.mjs`, a wszystkie zapisy przechodzą przez `services/web/app/src/Features/Tags/TagsHandler.mjs`.

#### Pola {#fields}

| Pole | Typ | Znaczenie | Źródło |
| --- | --- | --- | --- |
| `_id` | ObjectId | Id tagu, używane w trasach `/tag/:tagId`. | `Tag.mjs:10` |
| `user_id` | String | Właściciel tagu. Zwykły ciąg znaków, a nie ObjectId, ze względów historycznych. | `Tag.mjs:7-12` |
| `name` | String | Nazwa tagu, najwyżej 50 znaków (`MAX_TAG_LENGTH`). Unikalna dla każdego użytkownika. | `Tag.mjs:13`, `TagsHandler.mjs:4` |
| `color` | String | Opcjonalny kolor: kod szesnastkowy, np. `#a1b2c3`, lub wartość `hsl(<n>, 70%, 45%)` (`TAG_COLOR_REGEX`). | `Tag.mjs:5`, `Tag.mjs:14-22` |
| `project_ids` | Array of String | Id projektów w tym tagu, jako ciągi znaków. | `Tag.mjs:23` |
| `__v` | Number | Klucz wersji Mongoose, dodawany, gdy `Tag.create` tworzy dokument. | `TagsHandler.mjs:27` |

#### Indeksy {#indexes}

| Nazwa | Klucze | Opcje | Migracja |
| --- | --- | --- | --- |
| `user_id_1_name_1` | `{ user_id: 1, name: 1 }` | unique | `tools/migrations/20190912145029_create_tags_indexes.mjs` |

Ta sama migracja utworzyła też `user_id_1`; `tools/migrations/20231031164732_drop_redundant_indexes.mjs` ponownie go usuwa, ponieważ obejmuje go indeks złożony.

#### Uwagi {#notes}

* Tagi są przypisane do użytkownika: dwóch współpracowników tego samego projektu ma dla niego własne tagi.
* `user_id` i `project_ids` są ciągami znaków, więc odpytuj je za pomocą id w postaci ciągów, a nie ObjectId.
* Usunięcie użytkownika (`services/web/app/src/Features/User/UserDeleter.mjs`) nie zmienia `tags`.
