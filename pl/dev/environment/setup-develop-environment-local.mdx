## Wymagania wstępne

Overleaf to typowy projekt open source oparty na architekturze mikroserwisów, w którym wszystkie usługi działają w Dockerze.

* Kod źródłowy oficjalnej edycji Community Edition znajduje się na [GitHub Overleaf Official](https://github.com/overleaf/overleaf/tree).
* Kod źródłowy Overleaf-CEP jest dostępny na [GitHub Yu-i-i/Overleaf](https://github.com/yu-i-i/overleaf-cep).
* Overleaf Pro Edition jest dostępna na [GitHub Ayaka-notes/overleaf-pro](https://github.com/ayaka-notes/overleaf-pro).

Do skonfigurowania środowiska deweloperskiego Overleaf potrzebny jest wydajny serwer; zalecana jest konfiguracja z co najmniej 8 rdzeniami i 16 GB RAM, ponieważ jednocześnie trzeba uruchomić ponad 20 kontenerów.

<Info>

Ponieważ serwery z 8 lub więcej rdzeniami CPU są zazwyczaj drogie, zdecydowanie zalecamy prowadzenie prac deweloperskich na komputerze lokalnym.

</Info>

Zakładamy też, że jako programista znasz już [instalację Dockera](https://docs.docker.com/engine/install/ubuntu/). Do prac deweloperskich zdecydowanie zalecamy używanie aktualnej i stabilnej wersji Ubuntu LTS (np. Ubuntu 24.04 w latach 2025–2026) oraz najnowszej wersji Dockera, co zmniejsza ryzyko wystąpienia nieoczekiwanych błędów.

Podsumowując, będziesz potrzebować:

* [x] Wydajnego serwera/komputera stacjonarnego do prac deweloperskich
* [x] Aktualnej i stabilnej wersji Ubuntu LTS (np. Ubuntu 24.04)
* [x] Środowiska Docker i Git

## Samouczek konfiguracji

Jako przykładu użyjemy tutaj overleaf-cep, aby pokazać, jak skonfigurować środowisko deweloperskie Overleaf.

<Steps>
<Step title="Pobierz kod źródłowy">
Najpierw sklonuj repozytorium:

```bash title="bash"
git clone https://github.com/ayaka-notes/overleaf-pro.git
cd overleaf-pro
```
</Step>

<Step title="Zsynchronizuj `package-lock.json`">
Ponieważ Overleaf jest rozwijany w [wewnętrznym repozytorium](http://github.com/overleaf/internal), plik `package-lock.json` bardzo często traci synchronizację z powodu różnych kwestii związanych z procesem rozwoju. Aby go zsynchronizować, należy uruchomić poniższe polecenie (jeśli masz lokalne środowisko nodejs).

```bash title="bash"
npm install --package-lock-only --ignore-scripts
```

Jeśli nie masz zainstalowanego nodejs, nie martw się — możesz użyć bezpośrednio `docker`, aby uruchomić to samo polecenie. Uruchom je **z katalogu głównego repozytorium Overleaf:**

```bash title="bash"
docker run --rm \
  -v "$(pwd)":/workspace \
  -w /workspace \
  node:22.18.0 \
  npm install --package-lock-only --ignore-scripts
```
</Step>

<Step title="Zbuduj obraz deweloperski">
Overleaf udostępnia dedykowany katalog `/develop` na skrypty deweloperskie. Wystarczy zbudować usługi:

```bash title="bash"
cd ./develop
bin/build
```

<Info>

Jeśli Dockerowi zabraknie pamięci RAM podczas równoległego budowania usług, utwórz w tym katalogu plik `.env` zawierający `COMPOSE_PARALLEL_LIMIT=1`.

</Info>
</Step>

<Step title="Uruchom wszystkie mikroserwisy">
Następnie uruchom usługi:

```bash title="bash"
bin/up
```

Gdy usługi będą działać, otwórz [http://localhost/launchpad](http://localhost/launchpad), aby utworzyć pierwsze konto administratora.

<Danger>

Musisz uruchomić `bin/up` przed uruchomieniem polecenia `bin/dev`. W przeciwnym razie możesz napotkać szereg problemów z uprawnieniami.

</Danger>
</Step>
</Steps>

<Info>

Domyślnie uprawnienia administratora nie są dostępne. Musisz dodać poniższy wpis do `develop/dev.env`. Następnie uzyskasz dostęp do panelu administratora.

```text
ADMIN_PRIVILEGE_AVAILABLE=true
```

</Info>

### TeX Live

Kompilacja PDF wymaga zbudowania obrazu TeX Live, który obsługuje kompilację wewnątrz Dockera:

```text
docker build texlive -t texlive-full
```

Aby kompilować na hoście macOS, może być konieczne nadpisanie ścieżki do gniazda Dockera przez utworzenie w tym katalogu pliku `.env` zawierającego `DOCKER_SOCKET_PATH=/var/run/docker.sock.raw`

Możesz także użyć [ayaka-notes/texlive-full](https://github.com/ayaka-notes/texlive-full), wybierając tag base, który jest minimalną wersją texlive.

### Rozwój

Aby uniknąć uruchamiania `bin/build && bin/up` po każdej zmianie kodu, możesz uruchomić Overleaf Community Edition w _trybie deweloperskim_, w którym usługi automatycznie aktualizują się po zmianach w kodzie.

W tym celu użyj dołączonego skryptu `bin/dev`:

```text
bin/dev
```

Spowoduje to uruchomienie wszystkich usług za pomocą `node --watch`, który automatycznie monitoruje kod i w razie potrzeby restartuje usługi.

Aby poprawić wydajność, możesz uruchomić w trybie deweloperskim tylko część usług, przekazując do skryptu `bin/dev` listę rozdzieloną spacjami:

```text
bin/dev [service1] [service2] ... [serviceN]
```

<Info>

Uruchomienie usługi `web` w _trybie deweloperskim_ spowoduje aktualizację usługi `web` tylko przy zmianach kodu backendu. Aby automatycznie aktualizować również kod frontendu, uruchom także usługę `webpack` w _trybie deweloperskim_.

</Info>

Jeśli nie podasz nazw usług, wszystkie usługi zostaną uruchomione w trybie deweloperskim.

### Debugowanie

W _trybie deweloperskim_ większość usług udostępnia port debugowania, do którego można podłączyć debugger, np. inspektor w Chrome Dev Tools lub debugger zintegrowany z IDE. Poniższa tabela przedstawia porty udostępniane na **maszynie hosta** dla poszczególnych usług:

| Usługa             | Port |
| ------------------ | ---- |
| `web`              | 9229 |
| `clsi`             | 9230 |
| `chat`             | 9231 |
| `contacts`         | 9232 |
| `docstore`         | 9233 |
| `document-updater` | 9234 |
| `filestore`        | 9235 |
| `notifications`    | 9236 |
| `real-time`        | 9237 |
| `references`       | 9238 |
| `history-v1`       | 9239 |
| `project-history`  | 9240 |
| `linked-url-proxy` | 9241 |

Aby podłączyć się do usługi za pomocą _zdalnego debugowania_ Chrome, przejdź do chrome://inspect/ i upewnij się, że opcja _Discover network targets_ jest zaznaczona. Następnie kliknij _Configure..._ i dodaj wpis `localhost:[service port]` dla każdej usługi, do której chcesz podłączyć debugger.

Po dodaniu wpisu usługa pojawi się jako _Remote Target_, który można inspekcjonować i debugować.

### Logowanie

W środowisku deweloperskim Overleaf udostępnia skrypt `bin/logs`, jednak wymaga on zainstalowania pewnej zależności:

```bash
sudo npm install -g bunyan
# Or sudo apt install node-bunyan 
```

Możesz też uruchomić bezpośrednio:

```text
docker compose logs -f [service name]
```
