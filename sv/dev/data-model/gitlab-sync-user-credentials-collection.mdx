---
title: Samlingen GitLab Sync User Credentials
icon: user-lock
---

`gitlabSyncUserCredentials` innehåller ett dokument per användare som har kopplat ett GitLab-konto för GitLab Sync. Den lagrar användarens OAuth-token, krypterade. Samlingen hör till webbmodulen `gitlab-sync` (`services/web/modules/gitlab-sync`). Schemat finns i `services/web/modules/gitlab-sync/app/models/gitlabSyncUserCredentials.mjs`, och all åtkomst går via `services/web/modules/gitlab-sync/app/src/TokenManager.mjs`.

#### Fält {#fields}

| Fält | Typ | Betydelse | Källa |
| ----- | ---- | ------- | ------ |
| `_id` | ObjectId | Sätts av Mongoose när upserten infogar. | |
| `userId` | ObjectId | Overleaf-användaren. Obligatoriskt. Schemat anger `unique: true`, men inget index byggs (se Index); upserten på `userId` håller ett dokument per användare. | `gitlabSyncUserCredentials.mjs:8`, `TokenManager.mjs:88-95` |
| `gitlab` | String | JSON-värdet `{ accessToken, refreshToken, expiresAt }`, krypterat med `@overleaf/access-token-encryptor`. `expiresAt` anges i millisekunder sedan epoken, eller `null`; `refreshToken` kan vara `null`. Lösenordet kommer från `GITLAB_TOKEN_CIPHER_PASSWORD`; chifferetiketten är `GITLAB_TOKEN_CIPHER_LABEL`, standard `2026.10-v3`. Obligatoriskt. | `gitlabSyncUserCredentials.mjs:9-10`, `TokenManager.mjs:18-31`, `services/web/modules/gitlab-sync/app/src/GitLabApiClient.mjs:209-220` |
| `__v` | Number | Mongoose versionsnyckel. Schemat stänger inte av den. | Mongoose-standard |

#### Vem skriver {#who-writes-it}

| Kod | Vad den gör |
| ---- | ------------ |
| `TokenManager.mjs:88-95` (`saveUserToken`) | Gör upsert av användarens krypterade autentiseringsuppgifter. |
| `TokenManager.mjs:99-108` (`linkUserToken`) | Sparar nya autentiseringsuppgifter från OAuth-callbacken (`services/web/modules/gitlab-sync/app/src/GitLabSyncController.mjs:146`). När användaren kopplar igen återkallas den ersatta åtkomsttoken hos GitLab i bakgrunden. |
| `TokenManager.mjs:53-78` (`refreshUserToken`) | När åtkomsttoken har mindre än 5 minuter kvar till `expiresAt` (`:13,47-49`) hämtar den nya token med uppdateringstoken och sparar dem (`:75`). Den körs under låset `gitlabSyncToken` per användare (`:15,54`), eftersom GitLab förbrukar en uppdateringstoken när den används. |
| `TokenManager.mjs:111-126` (`removeUserToken`) | Återkallar åtkomsttoken hos GitLab (i mån av möjlighet) och tar sedan bort dokumentet. Anropas vid bortkoppling (`GitLabSyncController.mjs:173`) och när en borttagen användare löper ut (`services/web/modules/gitlab-sync/index.mjs:56-58`). |

#### Vem läser {#who-reads-it}

| Kod | Vad den gör |
| ---- | ------------ |
| `TokenManager.mjs:41-45,81-85` (`getUserCredentials`, `getUserToken`) | Dekrypterar autentiseringsuppgifterna för varje anrop till GitLabs API och förnyar dem först när token snart går ut: `services/web/modules/gitlab-sync/app/src/GitLabSyncHandler.mjs` (till exempel `:27`) och `services/web/modules/gitlab-sync/app/src/GitMerge.mjs:52`. Utan dokument, eller med uppgifter som inte går att dekryptera eller förnya, kastar den `InvalidTokenError`, och användaren räknas som inte kopplad (`GitLabSyncHandler.mjs:25-37`). |
| `services/web/modules/admin-tools/app/src/AdminUserListManager.mjs:394` | Kontrollerar om användaren har ett dokument, för integrationerna som visas i adminpanelen. |

#### Index {#indexes}

| Namn | Nycklar | Alternativ | Migrering |
| ---- | ---- | ------- | --------- |
| `_id_` | `_id: 1` | | default |

Mongoose `autoIndex` är avstängt (`services/web/app/src/infrastructure/Mongoose.mjs:7`), så schemats `unique: true` på `userId` skapar ingenting. Ingen migrering skapar index för den här samlingen.

#### Anteckningar {#notes}

* Att ändra `GITLAB_TOKEN_CIPHER_PASSWORD` gör de lagrade autentiseringsuppgifterna oläsliga. De användarna räknas då som inte kopplade tills de kopplar igen.
* En borttagen användare behåller dokumentet tills användaren löper ut.
