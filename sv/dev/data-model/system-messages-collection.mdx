---
title: Samlingen System Messages
icon: bullhorn
---

`systemmessages` innehåller de banderoller för hela webbplatsen som en administratör publicerar för alla inloggade användare. Ett dokument är ett meddelande. `web` äger den; schemat är `services/web/app/src/models/SystemMessage.mjs` och koden är `services/web/app/src/Features/SystemMessages/SystemMessageManager.mjs`.

#### Fält {#fields}

| Fält | Typ | Betydelse | Källa |
| --- | --- | --- | --- |
| `_id` | ObjectId | Meddelandets id. Webbläsaren kommer ihåg via detta id vilka meddelanden användaren har stängt (`services/web/frontend/js/shared/components/system-message.tsx:10`). | `SystemMessage.mjs:5` |
| `content` | String | Meddelandetext, standard `''`. | `SystemMessage.mjs:7` |
| `__v` | Number | Mongoose-versionsnyckel, läggs till av `message.save()`. | `SystemMessageManager.mjs:29-30` |

#### Vem skriver {#who-writes-it}

| Kod | Vad den gör |
| --- | --- |
| `SystemMessageManager.mjs:28-33` (`createMessage`) | `POST /admin/messages` (`services/web/app/src/router.mjs:1150-1152`, `services/web/app/src/Features/ServerAdmin/AdminController.mjs:151-159`): lägger till ett meddelande. |
| `SystemMessageManager.mjs:22-26` (`clearMessages`) | `POST /admin/messages/clear` (`router.mjs:1155-1157`, `AdminController.mjs:161-168`): raderar alla meddelanden. Det går inte att radera ett enskilt. |

#### Vem läser {#who-reads-it}

| Kod | Vad den gör |
| --- | --- |
| `SystemMessageManager.mjs:50-65` | Varje `web`-process håller alla meddelanden i minnet och läser in dem igen var 20:e till 30:e sekund, och direkt efter sin egen skapning eller rensning. |
| `services/web/app/src/Features/SystemMessages/SystemMessageController.mjs:6-24` | `GET /system/messages` (`router.mjs:331`): returnerar de cachade meddelandena till inloggade användare. Medan webbplatsen är stängd (`siteIsOpen` false) returneras i stället ett fast meddelande, som inte lagras i Mongo. |
| `AdminController.mjs:83-84` | Sidan `/admin` listar meddelandena direkt från Mongo. |

#### Index {#indexes}

Ingen migrering skapar något index på `systemmessages`; bara standardindexet `_id` finns.

#### Anmärkningar {#notes}

* När `notifyOnSystemMessageChanges` är satt publiceras en skapning eller rensning också på Redis-kanalen `refresh-system-messages`, så att andra `web`-processer läser in direkt (`SystemMessageManager.mjs:9`, `:35-48`, `:75-87`). Utan den plockar de upp ändringen vid nästa schemalagda inläsning.
