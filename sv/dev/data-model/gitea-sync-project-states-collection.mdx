---
title: Samlingen Gitea Sync Project States
icon: code-pull-request
---

`giteaSyncProjectStates` innehåller ett dokument per projekt som är kopplat till ett Gitea-repository: vilket repository, och var den senaste synkroniseringen slutade. Samlingen hör till webbmodulen `gitea-sync` (`services/web/modules/gitea-sync`). Schemat finns i `services/web/modules/gitea-sync/app/models/giteaSyncProjectStates.mjs`, och all åtkomst går via `services/web/modules/gitea-sync/app/src/SyncStateManager.mjs`. Fälten är desamma som i [GitHub Sync Project States](/sv/dev/data-model/github-sync-project-states-collection).

#### Vem skriver {#who-writes-it}

| Kod | Vad den gör |
| ---- | ------------ |
| `SyncStateManager.mjs:9-14` (`createProjectState`) | Skapar dokumentet: efter att ett repository importerats som ett nytt projekt (`services/web/modules/gitea-sync/app/src/GiteaSyncHandler.mjs:175-181`), eller efter att ett projekt exporterats till ett nytt repository (`GiteaSyncHandler.mjs:233-239`, endast ägaren, nekas om det redan är kopplat). |
| `SyncStateManager.mjs:16-21` (`updateProjectState`) | `$set` av de ändrade fälten. `getMergeOverview` sätter `mergeStatus: 'diverged'` när `lastSyncCommit` inte längre är en förfader till den synkroniserade grenen (`services/web/modules/gitea-sync/app/src/GiteaApiClient.mjs:431`), eller när committen är borta och användaren får pusha (`GiteaSyncHandler.mjs:123,126-137`). En synkronisering (`services/web/modules/gitea-sync/app/src/GitMerge.mjs`) flyttar `lastSyncCommit`/`lastSyncVersion` när den lyckas (till exempel `:152,189,231`), registrerar en konflikt med `unmergedBranchName`, `unmergedBranchHead` och `conflictVersion` (`:214-220`), och rensar dem när konflikten är löst (`:257-264`). |
| `SyncStateManager.mjs:23-25` (`removeProjectState`) | Tar bort dokumentet när ägaren kopplar bort projektet (`GiteaSyncHandler.mjs:83-97`) och när ett borttaget projekt löper ut (`services/web/modules/gitea-sync/index.mjs:46-48`). |

#### Vem läser {#who-reads-it}

| Kod | Vad den gör |
| ---- | ------------ |
| `GiteaSyncHandler.mjs:39-60` (`getProjectState`) | Ger editorn `mergeStatus`, `repoFullName` och `unmergedBranchName`. Utan dokument svarar den `need-export`, ett värde som aldrig lagras. |
| `GiteaSyncHandler.mjs:110-143` (`getMergeOverview`) | Jämför `lastSyncCommit` och `lastSyncVersion` med Gitea och projekthistoriken för att lista de nya committarna. |
| `GiteaSyncHandler.mjs:200` (`exportProject`) | Vägrar exportera ett projekt som redan är kopplat. |
| `GitMerge.mjs:36` (`doGitMergeWithoutLock`) | Läser in statusen i början av en synkronisering. |

#### Index {#indexes}

| Namn | Nycklar | Alternativ | Migrering |
| ---- | ---- | ------- | --------- |
| `_id_` | `_id: 1` | | default |

Mongoose `autoIndex` är avstängt (`services/web/app/src/infrastructure/Mongoose.mjs:7`), så schemats `unique: true` på `projectId` skapar ingenting. Ingen migrering skapar index för den här samlingen.

#### Anteckningar {#notes}

* Giteas API kan inte skapa commits utanför en gren som GitHubs kan. En synkronisering committar direkt på den synkroniserade grenen när den kan gå framåt, annars på en tillfällig gren som sedan slås ihop via en pull request (`GitMerge.mjs:16-21`).
* En synkronisering körs under projektets `gitSync`-lås, som delas med GitHub Sync och GitLab Sync (`GitMerge.mjs:25-32`).
* Ett borttaget projekt behåller sitt dokument tills projektet löper ut.
* Användarens Gitea-token finns i [Gitea Sync User Credentials](/sv/dev/data-model/gitea-sync-user-credentials-collection).
