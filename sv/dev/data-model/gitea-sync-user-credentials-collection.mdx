---
title: Samlingen Gitea Sync User Credentials
icon: lock
---

`giteaSyncUserCredentials` innehåller ett dokument per användare som har kopplat ett Gitea-konto för Gitea Sync. Den lagrar användarens OAuth-token, krypterade. Samlingen hör till webbmodulen `gitea-sync` (`services/web/modules/gitea-sync`). Schemat finns i `services/web/modules/gitea-sync/app/models/giteaSyncUserCredentials.mjs`, och all åtkomst går via `services/web/modules/gitea-sync/app/src/TokenManager.mjs`.

#### Fält {#fields}

| Fält | Typ | Betydelse | Källa |
| ----- | ---- | ------- | ------ |
| `_id` | ObjectId | Sätts av Mongoose när upserten infogar. | |
| `userId` | ObjectId | Overleaf-användaren. Obligatoriskt. Schemat anger `unique: true`, men inget index byggs (se Index); upserten på `userId` håller ett dokument per användare. | `giteaSyncUserCredentials.mjs:8`, `TokenManager.mjs:89-96` |
| `gitea` | String | JSON-värdet `{ accessToken, refreshToken, expiresAt }`, krypterat med `@overleaf/access-token-encryptor`. `expiresAt` anges i millisekunder sedan epoken, eller `null`; `refreshToken` kan vara `null`. Lösenordet kommer från `GITEA_TOKEN_CIPHER_PASSWORD`; chifferetiketten är `GITEA_TOKEN_CIPHER_LABEL`, standard `2026.10-v3`. Obligatoriskt. | `giteaSyncUserCredentials.mjs:9-10`, `TokenManager.mjs:17-30`, `services/web/modules/gitea-sync/app/src/GiteaApiClient.mjs:198-209` |
| `__v` | Number | Mongoose versionsnyckel. Schemat stänger inte av den. | Mongoose-standard |

#### Vem skriver {#who-writes-it}

| Kod | Vad den gör |
| ---- | ------------ |
| `TokenManager.mjs:89-96` (`saveUserToken`) | Gör upsert av användarens krypterade autentiseringsuppgifter. Anropas från OAuth-callbacken (`services/web/modules/gitea-sync/app/src/GiteaSyncController.mjs:146`). Till skillnad från GitLab Sync återkallar en ny koppling inte den ersatta token. |
| `TokenManager.mjs:53-79` (`refreshUserToken`) | När åtkomsttoken har mindre än 5 minuter kvar till `expiresAt` (`:12`) hämtar den nya token med uppdateringstoken och sparar dem (`:76`). Den körs under låset `giteaSyncToken` per användare (`:14,54`), eftersom Gitea ersätter uppdateringstoken när den används. |
| `TokenManager.mjs:100-102` (`removeUserToken`) | Tar bort dokumentet. Gitea har inget API för att återkalla en OAuth-token, så användaren återkallar behörigheten i Gitea (`:98-99`). Anropas vid bortkoppling (`GiteaSyncController.mjs:173`) och när en borttagen användare löper ut (`services/web/modules/gitea-sync/index.mjs:56-58`). |

#### Vem läser {#who-reads-it}

| Kod | Vad den gör |
| ---- | ------------ |
| `TokenManager.mjs:40-44,82-86` (`getUserCredentials`, `getUserToken`) | Dekrypterar autentiseringsuppgifterna för varje anrop till Giteas API och förnyar dem först när token snart går ut: `services/web/modules/gitea-sync/app/src/GiteaSyncHandler.mjs` (till exempel `:27`) och `services/web/modules/gitea-sync/app/src/GitMerge.mjs:52`. Utan dokument, eller med uppgifter som inte går att dekryptera eller förnya, kastar den `InvalidTokenError`, och användaren räknas som inte kopplad (`GiteaSyncHandler.mjs:25-37`). |
| `services/web/modules/admin-tools/app/src/AdminUserListManager.mjs:395` | Kontrollerar om användaren har ett dokument, för integrationerna som visas i adminpanelen. |

#### Index {#indexes}

| Namn | Nycklar | Alternativ | Migrering |
| ---- | ---- | ------- | --------- |
| `_id_` | `_id: 1` | | default |

Mongoose `autoIndex` är avstängt (`services/web/app/src/infrastructure/Mongoose.mjs:7`), så schemats `unique: true` på `userId` skapar ingenting. Ingen migrering skapar index för den här samlingen.

#### Anteckningar {#notes}

* Att ändra `GITEA_TOKEN_CIPHER_PASSWORD` gör de lagrade autentiseringsuppgifterna oläsliga. De användarna räknas då som inte kopplade tills de kopplar igen.
* En borttagen användare behåller dokumentet tills användaren löper ut.
