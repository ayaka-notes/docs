---
title: Samlingen GitLab Sync Project States
icon: code-merge
---

`gitlabSyncProjectStates` innehåller ett dokument per projekt som är kopplat till ett GitLab-projekt: vilket repository, och var den senaste synkroniseringen slutade. Samlingen hör till webbmodulen `gitlab-sync` (`services/web/modules/gitlab-sync`). Schemat finns i `services/web/modules/gitlab-sync/app/models/gitlabSyncProjectStates.mjs`, och all åtkomst går via `services/web/modules/gitlab-sync/app/src/SyncStateManager.mjs`. Fälten är desamma som i [GitHub Sync Project States](/sv/dev/data-model/github-sync-project-states-collection).

#### Vem skriver {#who-writes-it}

| Kod | Vad den gör |
| ---- | ------------ |
| `SyncStateManager.mjs:9-14` (`createProjectState`) | Skapar dokumentet: efter att ett repository importerats som ett nytt projekt (`services/web/modules/gitlab-sync/app/src/GitLabSyncHandler.mjs:175-181`), eller efter att ett projekt exporterats till ett nytt repository (`GitLabSyncHandler.mjs:234-240`, endast ägaren, nekas om det redan är kopplat). |
| `SyncStateManager.mjs:16-21` (`updateProjectState`) | `$set` av de ändrade fälten. `getMergeOverview` sätter `mergeStatus: 'diverged'` när den synkroniserade grenen inte längre innehåller `lastSyncCommit` (kontroll av merge base, `services/web/modules/gitlab-sync/app/src/GitLabApiClient.mjs:460`), eller när committen är borta och användaren får pusha (`GitLabSyncHandler.mjs:123,126-137`). En synkronisering (`services/web/modules/gitlab-sync/app/src/GitMerge.mjs`) flyttar `lastSyncCommit`/`lastSyncVersion` när den lyckas (till exempel `:152,189,231`), registrerar en konflikt med `unmergedBranchName`, `unmergedBranchHead` och `conflictVersion` (`:214-220`), och rensar dem när konflikten är löst (`:257-264`). |
| `SyncStateManager.mjs:23-25` (`removeProjectState`) | Tar bort dokumentet när ägaren kopplar bort projektet (`GitLabSyncHandler.mjs:83-97`) och när ett borttaget projekt löper ut (`services/web/modules/gitlab-sync/index.mjs:46-48`). |

#### Vem läser {#who-reads-it}

| Kod | Vad den gör |
| ---- | ------------ |
| `GitLabSyncHandler.mjs:39-60` (`getProjectState`) | Ger editorn `mergeStatus`, `repoFullName` och `unmergedBranchName`. Utan dokument svarar den `need-export`, ett värde som aldrig lagras. |
| `GitLabSyncHandler.mjs:110-143` (`getMergeOverview`) | Jämför `lastSyncCommit` och `lastSyncVersion` med GitLab och projekthistoriken för att lista de nya committarna. |
| `GitLabSyncHandler.mjs:200` (`exportProject`) | Vägrar exportera ett projekt som redan är kopplat. |
| `GitMerge.mjs:36` (`doGitMergeWithoutLock`) | Läser in statusen i början av en synkronisering. |

#### Index {#indexes}

| Namn | Nycklar | Alternativ | Migrering |
| ---- | ---- | ------- | --------- |
| `_id_` | `_id: 1` | | default |

Mongoose `autoIndex` är avstängt (`services/web/app/src/infrastructure/Mongoose.mjs:7`), så schemats `unique: true` på `projectId` skapar ingenting. Ingen migrering skapar index för den här samlingen.

#### Anteckningar {#notes}

* GitLabs API kan inte flytta en gren till vilken commit som helst som GitHubs kan. En synkronisering committar direkt på den synkroniserade grenen när den kan gå framåt, annars på en tillfällig gren som sedan slås ihop via en merge request (`GitMerge.mjs:16-21`).
* En synkronisering körs under projektets `gitSync`-lås, som delas med GitHub Sync och Gitea Sync (`GitMerge.mjs:25-32`).
* Ett borttaget projekt behåller sitt dokument tills projektet löper ut.
* Användarens GitLab-token finns i [GitLab Sync User Credentials](/sv/dev/data-model/gitlab-sync-user-credentials-collection).
