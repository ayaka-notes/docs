---
title: Samlingen OAuth Applications
icon: id-badge
---

`oauthApplications` innehåller de OAuth-klienter som web känner till. Ett dokument är en klient. I Ayakaleaf Pro skriver bara webbmodulen `git-bridge` till den: den skapar en klient med namnet `Overleaf Git Bridge` när web startar. Schemat är `services/web/app/src/models/OauthApplication.mjs`.

#### Fält {#fields}

| Fält | Typ | Betydelse | Källa |
| ----- | ---- | ------- | ------ |
| `_id` | ObjectId | Klientdokumentets id. `oauthAccessTokens.oauthApplication_id` och `oauthAuthorizationCodes.oauthApplication_id` pekar på det. | `OauthApplication.mjs:5` |
| `id` | String | Klient-id: 64 slumpmässiga gemener och siffror. | `OauthApplication.mjs:7`, `services/web/modules/git-bridge/index.mjs:25` |
| `clientSecret` | String | Klienthemlighet, skriven som `v1.` plus 32 slumpmässiga tecken. Bara `getClient` läser den, och inget anropar `getClient` (se Anteckningar). | `OauthApplication.mjs:8`, `git-bridge/index.mjs:26` |
| `grants` | Array of String | Granttyper. Git-bridge-klienten har `['password']`. Returneras med klienten när en token kontrolleras (`services/web/modules/oauth2-server/app/src/OAuth2Model.mjs:67-72`). | `OauthApplication.mjs:9`, `git-bridge/index.mjs:27` |
| `name` | String | Klientens namn. Git-bridge-modulen och koden för personliga åtkomsttoken hittar klienten via namnet `Overleaf Git Bridge`. | `OauthApplication.mjs:10`, `git-bridge/index.mjs:15-16,28` |
| `redirectUris` | Array of String | Tillåtna omdirigerings-URI:er. `[]` för git-bridge-klienten. | `OauthApplication.mjs:11`, `git-bridge/index.mjs:29` |
| `scopes` | Array of String | Scopes som klienten får använda. `['git_bridge']` för git-bridge-klienten. | `OauthApplication.mjs:12`, `git-bridge/index.mjs:30` |
| `pkceEnabled` | Boolean | Bara i schemat: ingen kod i detta repo skriver det, och bara den oanvända `getClient` läser det (`OAuth2Model.mjs:207`). | `OauthApplication.mjs:13` |

#### Vem skriver {#who-writes-it}

| Kod | Vad den gör |
| ---- | ------------ |
| `git-bridge/index.mjs:9-35` (module `git-bridge`) | När `GIT_BRIDGE_ENABLED` är `true` skapar den klienten `Overleaf Git Bridge` när web startar, om ingen klient med det namnet finns. |

#### Vem läser {#who-reads-it}

| Kod | Vad den gör |
| ---- | ------------ |
| `services/web/modules/oauth2-server/app/src/OAuthPersonalAccessTokenManager.mjs:53-61` (module `oauth2-server`) | Hittar klienten `Overleaf Git Bridge` via namnet och sparar dess `_id` i varje ny personlig åtkomsttoken. Utan klienten skapas ingen token. |
| `OAuth2Model.mjs:31-39,67-72` (`getAccessToken`) | Läser in klienten för en token via `oauthApplication_id` och returnerar dess `id` och `grants`. |
| `OAuth2Model.mjs:185-209,241,275` (`getClient`, `saveToken`, `saveAuthorizationCode`) | Slår upp klienter via `id`. Nås aldrig i detta repo, se Anteckningar. |

#### Index {#indexes}

Bara standardindexet på `_id`. Det unika indexet `id_1` kommer från migreringar taggade `saas` (`20190912145016_create_oauthApplications_indexes.mjs`) och `server-pro` (`20230502180757_server_pro_oauth_indexes.mjs`), som Community Edition inte kör.

#### Anteckningar {#notes}

* Web använder `@node-oauth/oauth2-server` bara för att kontrollera bearer-token (`server.authenticate` i `services/web/app/src/Features/Authentication/AuthenticationController.mjs:409-450`), vilket bara anropar modellens `getAccessToken` och `verifyScope`. Ingen route betjänar `/oauth/token` eller `/oauth/authorize`, så `getClient`, `saveToken` och `saveAuthorizationCode` anropas aldrig.
* Modulen slår upp klienten via namnet och skapar den sedan, och Community Edition har inget unikt index på `name` eller `id`. Inget hindrar alltså en andra klient med samma namn. Kod som behöver klienten tar den som `findOne` returnerar.
