---
title: Samlingen Notifications
icon: bell
---

`notifications` innehåller de meddelanden som visas överst på en användares projektpanel. Ett dokument är ett meddelande för en användare, identifierat av sin `key`. Bara tjänsten `notifications` rör samlingen (`services/notifications/app/js/Notifications.js`); `web` och `third-party-datastore` anropar dess HTTP-API. Det finns inget Mongoose-schema.

#### Fält {#fields}

| Fält | Typ | Betydelse | Källa |
| --- | --- | --- | --- |
| `_id` | ObjectId | Meddelandets id. `web` markerar ett meddelande som läst med detta id. | `Notifications.js:58-65` |
| `user_id` | ObjectId | Användaren som ser meddelandet. | `Notifications.js:26` |
| `key` | String | Identifierar meddelandet, till exempel `project-invite-<inviteId>`. Upserten behåller ett dokument per `user_id` och `key`; det finns inget unikt index. | `Notifications.js:27`, `:51-55` |
| `templateKey` | String | Vilket meddelande frontend återger. Tas bort när meddelandet läses eller stängs; dokumentet finns kvar. | `Notifications.js:29`, `:63`, `:72`, `:78` |
| `messageOpts` | Object | Värden för meddelandetexten beroende på `templateKey` (för en projektinbjudan: `userName`, `projectName`, `projectId`, `token`). Tas bort när användaren stänger meddelandet via id. | `Notifications.js:28`, `:63` |
| `expires` | Date | Valfritt. TTL-indexet raderar dokumentet efter denna tid. | `Notifications.js:35-50` |

#### Anmärkningar {#notes}

* Ett läst meddelande raderas inte: bara `templateKey` försvinner. Eftersom dokumentet fortfarande har nyckeln gör ett senare `addNotification` utan `forceCreate` för samma nyckel ingenting (`Notifications.js:21-24`).
* Routerna `/key/:key` verkar bara på nyckeln, för alla användare (`Notifications.js:76-100`).
* Om `web` saknar `apis.notifications.url` varken skapar eller läser den meddelanden (`NotificationsHandler.mjs:17`, `:41`).
