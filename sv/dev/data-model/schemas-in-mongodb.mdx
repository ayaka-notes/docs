I det här avsnittet går vi igenom Overleafs datamodell. Overleaf använder MongoDB för datalagring, och den enda databasen heter `sharelatex`, vilket också är namnet på Overleafs föregångare.

Utvecklingsmiljön kör redan Mongo Express bredvid Mongo (se [setup-develop-tools.md](/sv/dev/environment/setup-develop-tools  "mention")). Öppna [http://localhost:8081/](http://localhost:8081/) och logga in med `admin:pass`.

<Frame>
  <img src="/images/dev/screenshot-1768810061206.png" alt="" />
</Frame>

Du kan också öppna ett skal i Mongo-containern från katalogen `develop`:

```bash
bin/docker-compose exec mongo mongosh sharelatex
```

#### Hur sidorna är skrivna {#how-the-pages-are-written}

* Varje sida listar de fält som koden skriver, med typ, betydelse och den kodrad som visar det: en rad i ett Mongoose-schema eller stället som skriver fältet. Fält som bara en migrering, ett skript eller en av webbmodulerna skriver anger det.
* Många samlingar har inget Mongoose-schema: tjänsterna skriver dem med MongoDB-drivrutinen.
* Index skapas bara av migreringarna i `tools/migrations/`. CE kör de som är taggade `server-ce` vid varje start (`server-ce/init_scripts/900_run_web_migrations.sh`); Mongoose `autoIndex` är avstängt (`services/web/app/src/infrastructure/Mongoose.mjs:7`). Indextabellerna listar bara det som en CE-instans till slut har.
* Texten i docs finns i Mongo, men annat innehåll gör det inte. Filinnehåll lagras som blobbar och historik som chunkar i history-v1:s buckets (lokala mappar, eller S3 / RustFS); öppna docs finns i Redis tills document-updater flushar dem.
