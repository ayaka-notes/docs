---
title: Samlingen Project History Blobs
icon: cubes
---

`projectHistoryBlobs` innehåller ett dokument per projekthistorik: metadata (hash och storlekar) för varje blob som history-v1 har lagrat för projektet. En blob är innehållet i en fil eller ett doc vid en viss punkt i dess historik. Själva byten är objekt i bucketen för projektblobbar. Det finns inget Mongoose-schema: history-v1 skriver samlingen i `services/history-v1/storage/lib/blob_store/mongo.js`, som den använder för historik-id med 24 hexadecimala tecken, som i CE (`services/history-v1/storage/lib/blob_store/index.js:108-116`).

#### Fält {#fields}

| Fält | Typ | Betydelse | Källa |
| ----- | ---- | ------- | ------ |
| `_id` | ObjectId | Projektets historik-id, värdet i `projects.overleaf.history.id`. | `mongo.js:37-40` |
| `blobs` | Object | Blobposter grupperade i hinkar. Nyckeln för en hink är de första 3 hexadecimala siffrorna i hashen. | `mongo.js:39`, `429-431` |
| `blobs.<abc>` | Array of Object | Upp till 8 poster vars hash börjar med `abc`. När en hink redan har 8 hamnar nästa post i [Samlingen Project History Sharded Blobs](/sv/dev/data-model/project-history-sharded-blobs-collection). | `mongo.js:23`, `375-389` |
| `blobs.<abc>[].h` | Binary | Hashen, 20 byte: git-blob-SHA-1, `sha1("blob " + byteLength + "\0" + content)` (`libraries/overleaf-editor-core/lib/blob_utils.js:36-43`). Dess hexadecimala form är den hash som används på andra ställen, till exempel `fileRefs.hash` i projekt. | `mongo.js:472` |
| `blobs.<abc>[].b` | Number | Innehållets längd i byte. | `mongo.js:473` |
| `blobs.<abc>[].s` | Number | Innehållets längd som text; `null` när innehållet inte är redigerbar text (binärt, eller för stort för att redigera) (`blob_utils.js:116-130`). | `mongo.js:474` |

#### Vem skriver {#who-writes-it}

| Kod | Vad den gör |
| ---- | ------------ |
| `services/history-v1/storage/lib/blob_store/mongo.js:34-47` | `initialize`: infogar `{ _id, blobs: {} }` när history-v1 skapar projekthistoriken (`services/history-v1/storage/lib/chunk_store/index.js:67-68`). |
| `mongo.js:370-390` | `insertBlob`: `$addToSet` av posten i dess hink så länge hinken har färre än 8 poster, annars i den shardade samlingen. Körs efter att byten har laddats upp, från `putString`, `putBlob` och `copyBlob` (`blob_store/index.js:223-237`, `271-278`, `456-467`). |
| `mongo.js:54-105` | `clone`: kopierar hinkarna till ett annat historik-id, för history-v1 `POST /projects/:project_id/clone`. Inget i web anropar den rutten (se [Samlingen Project History Chunks](/sv/dev/data-model/project-history-chunks-collection)). |
| `mongo.js:413-422` | `deleteBlobs`: raderar dokumentet och projektets shardade dokument, vid history-v1 `DELETE /projects/:project_id` (`services/history-v1/api/controllers/projects.js:361-373`). |

Var nya blobbar kommer ifrån:

* Filuppladdningar: web skickar filen till history-v1 `PUT /projects/:project_id/blobs/:hash` (`services/web/app/src/Features/History/HistoryManager.mjs:164-169`, `services/history-v1/api/controllers/projects.js:376-402`).
* Projektkopior: web ber history-v1 kopiera varje fils blob med `POST /projects/:project_id/blobs/:hash?copyFrom=` (`services/web/app/src/Features/Project/ProjectDuplicator.mjs:333-338`, `HistoryManager.mjs:177-187`, `projects.js:521-555`).
* Doc-text: när history-v1 skriver en chunk lagrar den texten i varje doc, och dess kommentarer och spårade ändringar som JSON, som blobbar (`chunk_store/index.js:402-405`, `libraries/overleaf-editor-core/lib/file_data/string_file_data.js:166-173`).

#### Vem läser {#who-reads-it}

| Kod | Vad den gör |
| ---- | ------------ |
| `mongo.js:113-157` | `findBlob`: en blob via hash; letar i den shardade samlingen när hinken är full. Används av `BlobStore.getBlob` (`blob_store/index.js:376-387`) för blobrutterna (`projects.js:416-480`) och före en infogning för att hoppa över blobbar som redan finns (`blob_store/index.js:441-448`). |
| `mongo.js:165-260` | `findBlobs`: många blobbar på en gång, för att läsa in filerna i en chunk. |
| `mongo.js:265-309` | `getProjectBlobs`: alla blobbar i ett projekt. |
| `mongo.js:316-363` | `getProjectBlobsBatch`: alla blobbar i flera projekt, för history-v1 `POST /projects/blob-stats` (`projects.js:620`). Modulen admin-tools visar resultatet som projektstorlek (`services/web/modules/admin-tools/app/src/AdminProjectManager.mjs:395-405`). |

#### Index {#indexes}

Bara standardindexet på `_id`. Ingen migrering i `tools/migrations/` lägger till något.

#### Anteckningar {#notes}

* Byten i en blob finns under nyckeln `<project key>/<hash[0:2]>/<hash[2:]>` (`blob_store/index.js:51-53`) i bucketen `OVERLEAF_EDITOR_PROJECT_BLOBS_BUCKET` (`services/history-v1/config/custom-environment-variables.json:49-52`). Projektnyckeln är historik-id:t utfyllt med nollor, omvänt och uppdelat i 3/3/resten av tecknen (`libraries/object-persistor/src/ProjectKey.js:8-15`).
* En blob lagras en gång per projekt: infogning av en hash som projektet redan har hoppas över (`blob_store/index.js:227-230`, `249-252`).
* Tomt innehåll behöver ingen post; `getBlob` besvarar det utan uppslag (`blob_store/index.js:378-380`).
* `projectHistoryGlobalBlobs` läses vid start (`blob_store/index.js:138-148`), men ingen CE-kod skriver den, så i CE är varje blob en projektblob.
