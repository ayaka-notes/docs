---
title: Samlingen GitHub Sync Project States
icon: code-branch
---

`githubSyncProjectStates` innehåller ett dokument per projekt som är kopplat till ett GitHub-repository: vilket repository, och var den senaste synkroniseringen slutade. Samlingen hör till webbmodulen `github-sync` (`services/web/modules/github-sync`). Schemat finns i `services/web/modules/github-sync/app/models/githubSyncProjectStates.mjs`, och all åtkomst går via `services/web/modules/github-sync/app/src/SyncStateManager.mjs`.

#### Fält {#fields}

| Fält | Typ | Betydelse | Källa |
| ----- | ---- | ------- | ------ |
| `_id` | ObjectId | Sätts av Mongoose när dokumentet skapas. | |
| `projectId` | ObjectId | Det kopplade projektet. Obligatoriskt. Schemat anger `unique: true`, men inget index byggs (se Index). | `githubSyncProjectStates.mjs:8` |
| `repoFullName` | String | Repositoryt som `owner/name` (GitHubs `full_name`). Obligatoriskt. | `githubSyncProjectStates.mjs:9` |
| `defaultBranchName` | String | Grenen som projektet synkroniseras med. Sätts när projektet kopplas och ändras inte därefter: vid import grenen som importformuläret skickar; vid export det nya repositoryts standardgren. Standard `null`. | `githubSyncProjectStates.mjs:10`, `GitHubSyncHandler.mjs:175-181,235-241` |
| `mergeStatus` | String | `clean`, `conflict` eller `diverged`. Standard `clean`. | `githubSyncProjectStates.mjs:11` |
| `lastSyncCommit` | String | Commit-SHA på den synkroniserade grenen vid senaste synkroniseringen. Standard `null`. | `githubSyncProjectStates.mjs:12` |

#### Vem skriver {#who-writes-it}

| Kod | Vad den gör |
| ---- | ------------ |
| `SyncStateManager.mjs:9-14` (`createProjectState`) | Skapar dokumentet: efter att ett repository importerats som ett nytt projekt (`services/web/modules/github-sync/app/src/GitHubSyncHandler.mjs:175-181`), eller efter att ett projekt exporterats till ett nytt repository (`GitHubSyncHandler.mjs:235-241`, endast ägaren, nekas om det redan är kopplat). |
| `SyncStateManager.mjs:16-21` (`updateProjectState`) | `$set` av de ändrade fälten. `getMergeOverview` sätter `mergeStatus: 'diverged'` när den synkroniserade grenen inte längre bygger på `lastSyncCommit`: GitHubs compare svarar `diverged` eller `behind` (`GitHubApiClient.mjs:382-400`), eller så är committen borta och användaren får pusha (`GitHubSyncHandler.mjs:123,126-137`). En synkronisering (`services/web/modules/github-sync/app/src/GitMerge.mjs`) flyttar `lastSyncCommit`/`lastSyncVersion` när den lyckas (till exempel `:143,173,224`), registrerar en konflikt med `unmergedBranchName`, `unmergedBranchHead` och `conflictVersion` (`:207-213`), och rensar dem när konflikten är löst (`:250-257`). |
| `SyncStateManager.mjs:23-25` (`removeProjectState`) | Tar bort dokumentet när ägaren kopplar bort projektet (`GitHubSyncHandler.mjs:83-97`) och när ett borttaget projekt löper ut (`services/web/modules/github-sync/index.mjs:56-58`). |

#### Vem läser {#who-reads-it}

| Kod | Vad den gör |
| ---- | ------------ |
| `GitHubSyncHandler.mjs:39-60` (`getProjectState`) | Ger editorn `mergeStatus`, `repoFullName` och `unmergedBranchName`. Utan dokument svarar den `need-export`, ett värde som aldrig lagras. |
| `GitHubSyncHandler.mjs:110-143` (`getMergeOverview`) | Jämför `lastSyncCommit` och `lastSyncVersion` med GitHub och projekthistoriken för att lista de nya committarna. |
| `GitHubSyncHandler.mjs:200` (`exportProject`) | Vägrar exportera ett projekt som redan är kopplat. |
| `GitMerge.mjs:27` (`doGitMergeWithoutLock`) | Läser in statusen i början av en synkronisering. |

#### Index {#indexes}

| Namn | Nycklar | Alternativ | Migrering |
| ---- | ---- | ------- | --------- |
| `_id_` | `_id: 1` | | default |

Mongoose `autoIndex` är avstängt (`services/web/app/src/infrastructure/Mongoose.mjs:7`), så schemats `unique: true` på `projectId` skapar ingenting. `tools/migrations/20190912145010_create_githubSyncProjectStates_indexes.mjs` (upstreams `project_id` och `owner_id`) är bara taggad `saas` och körs inte i CE.

#### Anteckningar {#notes}

* En synkronisering körs under projektets `gitSync`-lås (`GitMerge.mjs:17-24`). GitLab Sync och Gitea Sync tar samma lås, så bara en synkronisering körs per projekt åt gången.
* Ett borttaget projekt behåller sitt dokument tills projektet löper ut.
* Användarens GitHub-token finns i [GitHub Sync User Credentials](/sv/dev/data-model/github-sync-user-credentials-collection).
