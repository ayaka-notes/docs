Sandlådekompileringar fungerar lite annorlunda i utvecklingsmiljön än i produktionsavbildningen. Utvecklingsmiljön har redan konfigurerat dem; den här sidan förklarar inställningarna och tre saker att tänka på:

* Problem med filbehörigheter
* Delad volym mellan history-v1 och filestore
* Problem med underkataloger

### Aktivera kompilering i sandlåda {#enable-sandbox-compiles}

Sandlådekompileringar är på som standard. `develop/docker-compose.yml` sätter `SANDBOXED_COMPILES=true` för `clsi`, och `develop/dev.env` innehåller resten:

```dotenv title="develop/dev.env" wrap
#################
#   Sandbox     #
#################
SANDBOXED_COMPILES=true
SANDBOXED_COMPILES_HOST_DIR_COMPILES=${PWD}/compiles
SANDBOXED_COMPILES_HOST_DIR_OUTPUT=${PWD}/output
TEXLIVE_IMAGE_USER=tex
ALL_TEX_LIVE_DOCKER_IMAGES=ghcr.io/ayaka-notes/texlive-full:2026.1, ghcr.io/ayaka-notes/texlive-full:2025.1
ALL_TEX_LIVE_DOCKER_IMAGE_NAMES=Texlive 2026, Texlive 2025
TEX_LIVE_DOCKER_IMAGE=ghcr.io/ayaka-notes/texlive-full:2026.1
```

clsi hämtar inte avbildningar själv, så hämta avbildningarna en gång med `docker pull ghcr.io/ayaka-notes/texlive-full:2026.1` (och `:2025.1`).

LaTeX körs i syskoncontainrarna som `TEXLIVE_IMAGE_USER`. I utvecklingsmiljön är det `tex`, vilket också är standard för clsi (`services/clsi/config/settings.defaults.cjs:154`). Produktionsavbildningen använder i stället `www-data` när `SANDBOXED_COMPILES_SIBLING_CONTAINERS=true` (`server-ce/config/env.sh:15-21`), eftersom filerna där skapas av användaren `www-data` i Overleaf-containern.

<Warning>

Använd inte en egenbyggd image, eftersom du då kan stöta på en rad fel.

</Warning>

### Åtgärda filbehörigheter {#fix-file-permissions}

clsi-containern startar som root, ger mapparna `compiles`, `output` och `cache` till användaren `node` (uid `1000`) och kör sedan clsi som `node` (`services/clsi/entrypoint.sh`). Därför tillhör `develop/compiles` på värden uid `1000`, samma uid som `tex` i utvecklingsmiljön (se kommentaren i `develop/pandoc/Dockerfile`). Med inställningarna ovan kompilerar utvecklingsmiljön utan någon ändring av behörigheter.

Om du i stället sätter `TEXLIVE_IMAGE_USER=root` har root (uid `0`) inte behörighet att skriva till undermapparna i `compiles`. Ge i så fall gruppen `root` ägarskap och skrivbehörighet till `compiles`, med `setgid` satt så att nya undermappar ärver detta ägarskap:

```bash title="bash"
sudo chown -R 1000:root compiles
sudo chmod -R g+w compiles
sudo chmod g+s compiles
```

Detaljerad dokumentation finns i `services/clsi/README.md`.

### Delad volym mellan history-v1 och filestore {#volume-share-between-history-v1-and-filestore}

<Info>

Inställningarna i det här avsnittet och nästa finns redan i `develop/docker-compose.yml` och `develop/dev.env`. De spelar bara roll med `S3_ENABLED=false` i `develop/dev.rc`. Med standardvärdet `S3_ENABLED=true` lagrar filestore och history-v1 i stället dessa filer i RustFS-buckets (`develop/s3/docker-compose.yml`).

</Info>

Som standard fungerar filestore som en brygga mellan S3 och övriga tjänster i Overleaf. I Overleaf CE eller Server Pro lagras dock alla filer lokalt som standard. Därför har Overleaf infört en ganska knepig metod.

```javascript title="server-ce/config/settings.js" wrap
switch (process.env.OVERLEAF_FILESTORE_BACKEND) {
  case 's3':
    // s3 case...
  default:
    settings.filestore = {
      backend: 'fs',
      stores: {
        template_files: Path.join(DATA_DIR, 'template_files'),

        // NOTE: The below paths are hard-coded in server-ce/config/production.json, so hard code them here as well.
        // We can use DATA_DIR after switching history-v1 from 'config' to '@overleaf/settings'.
        project_blobs:
          process.env.OVERLEAF_HISTORY_PROJECT_BLOBS_BUCKET ||
          '/var/lib/overleaf/data/history/overleaf-project-blobs',
        global_blobs:
          process.env.OVERLEAF_HISTORY_BLOBS_BUCKET ||
          '/var/lib/overleaf/data/history/overleaf-global-blobs',
      },
    }
}
```

Samtidigt används `data/history` också av historiktjänsten. På så sätt kan olika mikrotjänster dela samma data. Därför monterar filestore-tjänsten i develop volymen `history-v1-buckets` från history-v1. Utan den **kan clsi inte hämta blobfiler från filestore-tjänsten**.

```yml title="develop/docker-compose.yml" wrap
  filestore:
    build:
      context: ..
      dockerfile: services/filestore/Dockerfile
    env_file:
      - dev.env
#    environment:
#      - ENABLE_CONVERSIONS=true
    volumes:
      - filestore-public-files:/overleaf/services/filestore/public_files
      - filestore-template-files:/overleaf/services/filestore/template_files
      - filestore-uploads:/overleaf/services/filestore/uploads
      - history-v1-buckets:/buckets
```

filestore hittar bucketarna via de här inställningarna i `dev.env`:

```dotenv title="develop/dev.env"
OVERLEAF_EDITOR_PROJECT_BLOBS_BUCKET='/buckets/project_blobs'
OVERLEAF_EDITOR_BLOBS_BUCKET='/buckets/blobs'
```

### Använd underkataloger {#use-subdirectories}

filestore läser alltid historikblobbar med underkataloger (`services/filestore/app/js/KeyBuilder.js:58`, `:70`). Produktionsavbildningen slår på `useSubdirectories` för history-v1 (`server-ce/config/production.json`), men standardkonfigurationen för history-v1 gör det inte, så i utveckling skulle history-v1 <strong>platta till all data.</strong> Därför sätter `dev.env` `NODE_CONFIG` för history-v1:&#x20;

```dotenv title="develop/dev.env"
OVERLEAF_EDITOR_PROJECT_BLOBS_BUCKET='/buckets/project_blobs'
OVERLEAF_EDITOR_BLOBS_BUCKET='/buckets/blobs'
NODE_CONFIG='{"persistor":{"useSubdirectories":true}}'
```

Utan den lagrar history-v1 `project_blobs`-filerna så här:

```bash wrap
node@43eb5dac5b1b:/buckets/project_blobs$ ls
169_609_71360f687c431b9796_5b_889ef3cf71c83a4c027c4e4dc3d1a106b27809  
94e_655_88cb5cc77ab70c9796_a0_e21c740cf81e868f158e30e88985b5ea1d6c19
169_609_71360f687c431b9796_a0_e21c740cf81e868f158e30e88985b5ea1d6c19
94e_655_88cb5cc77ab70c9796_fd_3c0326302e49486d3ea86c833edf9b88320c41
169_609_71360f687c431b9796_fd_3c0326302e49486d3ea86c833edf9b88320c41 

```

När `useSubdirectories` är satt till `true` blir `_` i dessa namn `/`, så att varje blob lagras i undermappar.
