## Rekommenderade utvecklingsverktyg

Dessa valfria tjänster krävs inte för att köra Overleaf, men de rekommenderas starkt för utveckling, felsökning och inspektion under lokal utveckling.

* **Hoppscotch** är ett lättviktigt verktyg för API-testning som liknar Postman, men det är webbläsarbaserat och mycket smidigt för utveckling.
  * Frontend: [http://localhost:3000](http://localhost:3000/)
  * Proxy (för att kringgå CORS): [http://localhost:9159](http://localhost:9159/)
* **RedisInsight** ger ett visuellt gränssnitt för att inspektera Redis-data. Gränssnittet finns på: [http://localhost:5540](http://localhost:5540/)
* **Mongo Express** är ett webbaserat gränssnitt för MongoDB. Du kan besöka [http://localhost:8081](http://localhost:8081/) med **inloggningsuppgifterna**: `admin:pass`

Lägg till följande i din `docker-compose.yml`:

<Accordion title="develop/docker-compose.yml">

```yml title="develop/docker-compose.yml"
# services: 
  # Overleaf Dev Containers
  # ...
  
  # Add those for your development
  # API debug
  hoppscotch-frontend:
    image: hoppscotch/hoppscotch-frontend:latest
    ports:
      - "3000:3000"

  hoppscotch-proxy:
    image: hoppscotch/proxyscotch:latest
    environment:
      - PORT=9159
    ports:
      - "9159:9159"

  # Redis-insight
  redis-insight:
    image: redislabs/redisinsight:latest
    ports:
      - "5540:5540"
    depends_on:
      - redis
    volumes:
      - ./data/redis-insight:/data

  # mongo-express
  # basicAuth credentials are "admin:pass"
  mongo-express:
    image: mongo-express
    ports:
      - "8081:8081"
    environment:
      ME_CONFIG_MONGODB_SERVER: mongo
```

</Accordion>

### Konfigurera Hoppscotch

#### Proxy för API-anrop

För att konfigurera Hoppscotch går du till [http://localhost:3000](http://localhost:3000/) och öppnar fliken Inställningar. Du behöver ställa in `Proxy` till [http://localhost:9159](http://localhost:9159/), så att dina felsökningsverktyg kan kommunicera med containrarnas interna nätverk.

#### CSRF-problem

<Warning>

Om du använder Postman eller andra felsökningsverktyg för att skicka en **POST**-förfrågan kan du märka att inloggningen **nekas**, och orsaken är ett 401-fel. Det beror på att Overleaf skyddas av **CSRF**-verifiering.

</Warning>

  <img src="/images/dev/image-9.png" alt="" />

För att hantera detta i din Overleaf-utveckling behöver du konfigurera din CSRF-token. Här är en detaljerad guide.

<Steps>
<Step title="Lägg till Pre-Request">
Lägg till följande kod i Pre-Request

<Frame>
  <img src="/images/dev/image-11.png" alt="" />
</Frame>

Skriptet ser ut så här:

```js wrap
pm.sendRequest("http://web:3000/dev/csrf", function (err, res) {
    if (err) {
        console.log(err);
        return;
    }

    // 1) Save CSRF token (/dev/csrf)
    const token = res.text().trim();
    pw.env.set("csrftoken", token);
    console.log("csrftoken =", token);

    const setCookieHeader = (res.headers || []).find(h => h.key?.toLowerCase() === "set-cookie")?.value;
    console.log("set-cookie =", setCookieHeader);

    if (!setCookieHeader) return;

    const cookiePair = setCookieHeader.split(";")[0].trim(); // overleaf.sid=...
    pw.env.set("cookie_header", cookiePair);
    console.log("cookie_header =", cookiePair);
});
```
</Step>

<Step title="Lägg till request-headers">
Du behöver lägga till följande headers:

| Headernamn   | Headervärde         |
| ------------ | ------------------- |
| Content-Type | `application/json`  |
| X-Csrf-Token | `<<csrftoken>>`     |
| Cookie       | `<<cookie_header>>` |

<Frame>
  <img src="/images/dev/image-12.png" alt="" />
</Frame>
</Step>

<Step title="Logga in med API-verktyg">
Nu kan du logga in med ditt användarnamn och lösenord.

```json5
{
  "_csrf": "<<csrftoken>>",
  "email": "admin@overleaf.com",
  "password": "xxxxxx"
}
```

Så här ser svaret ut när du anger fel användarnamn eller lösenord.

</Step>
