## Rekommenderade utvecklingsverktyg {#develop-tools-recommended}

Dessa valfria tjänster behövs inte för att köra Overleaf, men de hjälper mycket vid utveckling, felsökning och granskning av data. Alla ingår i utvecklingsmiljön, så det finns inget att lägga till i `docker-compose.yml`. När du är inloggad på webbplatsen länkar menyn **Dev tools** i navigeringsfältet till de verktyg som webbplatsen serverar på egna sökvägar.

| Verktyg | Adress | Definieras i |
| --- | --- | --- |
| **Grafana**, tillstånd, mätvärden och loggar för varje tjänst | [http://localhost/grafana/](http://localhost/grafana/) | `develop/grafana/docker-compose.yml`, på när `GRAFANA_ENABLED=true` i `develop/dev.rc` (standard) |
| **Mailpit**, en inkorg för varje e-post som webbplatsen skickar | [http://localhost/mailpit/](http://localhost/mailpit/) | `develop/mail/docker-compose.yml`, på när `MAILPIT_ENABLED=true` (standard) |
| **Mongo Express**, ett gränssnitt för MongoDB | [http://localhost/mongo-express/](http://localhost/mongo-express/) | `develop/docker-compose.yml`, alltid på |
| **RedisInsight**, ett gränssnitt för Redis-data | [http://localhost/redis-insight/](http://localhost/redis-insight/) | `develop/docker-compose.yml`, alltid på |
| **Hoppscotch**, en webbläsarbaserad API-klient som liknar Postman | [http://localhost:9170](http://localhost:9170/) (`HOPPSCOTCH_PORT`) | `develop/hoppscotch/docker-compose.yml`, på när `HOPPSCOTCH_ENABLED=true` (standard) |

<Warning>

Inget av dessa verktyg har inloggning: Grafanas anonyma användare är dess administratörer, och Mongo Express kan ändra vilket dokument som helst. Webbplatsen, Hoppscotch, Mongo Express (8081) och RedisInsight (5540) lyssnar bara på värdens `127.0.0.1`, så andra värdar kan inte nå dem.

</Warning>

### Grafana {#grafana}

Grafana serveras av webbplatsen på `/grafana/` via webpack-dev-server och behöver därför ingen egen port. Mappen **Overleaf Develop** innehåller dessa instrumentpaneler:

| Instrumentpanel | Vad den visar |
| --- | --- |
| All services (start) | Tillstånd för varje tjänst, värdmätare, belastning och loggar. Ett klick på en tjänst öppnar dess instrumentpanel |
| Server | CPU, belastning, minne, disk och nätverk för värden, samt clsis kompileringar |
| Errors | Felloggar, 5xx- och 4xx-svar, vanligaste felmeddelanden och misslyckade rutter |
| Data flow | Vägen för en ändring: document-updater och Redis, project-history, history-v1, Mongo, objektlagring |
| Containers | Tillstånd för varje container, CPU, minne, nätverk och disk, inklusive sandlådekompileringar |
| En per tjänst | Node.js-tjänsterna, git-bridge (JVM), mongo och redis |

Prometheus hämtar `/metrics` från tjänsterna, `mongodb-exporter`, `redis-exporter`, `cadvisor` och `node-exporter`; Alloy skickar loggarna från varje container i projektet till Loki, där instrumentpanelernas filter **Log search**, **Service** och **Log level** läser dem. Deras data finns bara i containrarna, så om de återskapas töms den. cAdvisor körs privilegierat och läser värdens `/`, `/sys`, Docker-data och containerd-socketen, skrivskyddat; node-exporter läser värdens `/`.

Instrumentpanelerna genereras: ändra `develop/grafana/make-dashboards` och kör det i stället för att redigera JSON-filerna.

### Mailpit {#mailpit}

### Konfigurera Hoppscotch {#setup-hoppscotch}

#### Proxy för API-anrop {#proxy-api-request}

Hoppscotch skickar förfrågningar från webbläsaren, som inte kan nå tjänsterna via deras Docker-namn. Dess proxy, Proxyscotch, körs i Docker-nätverket och serveras på `/proxy` på Hoppscotch-adressen. Öppna [http://localhost:9170](http://localhost:9170/), gå till Settings → Interceptor, välj **Proxy** och ange Proxy URL till `http://localhost:9170/proxy`. Inställningen sparas i webbläsaren.

#### Importera tjänsternas API:er {#import-the-service-apis}

`develop/hoppscotch/openapi/` innehåller en OpenAPI-fil för varje tjänsts interna API. Öppna Collections → Import → Import from File i Hoppscotch och välj alla filer på en gång. Varje fil blir en samling vars förfrågningar går till tjänstens Docker-adress. Samma filer visas i avsnittet [Tjänste-API](/sv/dev/service-api/overview).

#### CSRF-problem {#csrf-problems}

<Warning>

Om du använder Postman eller andra felsökningsverktyg för att skicka en **POST**-förfrågan kan du märka att inloggningen **nekas**, och orsaken är ett 403-fel. Det beror på att Overleaf skyddas av **CSRF**-verifiering.

</Warning>

<Frame>
  <img src="/images/dev/image-8.png" alt="" />
</Frame>

I konsolen kan du se:

<Frame>
  <img src="/images/dev/image-9.png" alt="" />
</Frame>

För att hantera detta i din Overleaf-utveckling behöver du konfigurera din CSRF-token. Här är en detaljerad guide.

<Steps>
<Step title="Lägg till Pre-Request">
Lägg till följande kod i Pre-Request

<Frame>
  <img src="/images/dev/image-10.png" alt="" />
</Frame>

Skriptet ser ut så här:

```js wrap
pm.sendRequest("http://web:3000/dev/csrf", function (err, res) {
    if (err) {
        console.log(err);
        return;
    }

    // 1) Save CSRF token (/dev/csrf)
    const token = res.text().trim();
    pw.env.set("csrftoken", token);
    console.log("csrftoken =", token);

    const setCookieHeader = (res.headers || []).find(h => h.key?.toLowerCase() === "set-cookie")?.value;
    console.log("set-cookie =", setCookieHeader);

    if (!setCookieHeader) return;

    const cookiePair = setCookieHeader.split(";")[0].trim(); // overleaf.sid=...
    pw.env.set("cookie_header", cookiePair);
    console.log("cookie_header =", cookiePair);
});
```
</Step>

<Step title="Lägg till request-headers">
Du behöver lägga till följande headers:

| Headernamn   | Headervärde         |
| ------------ | ------------------- |
| Content-Type | `application/json`  |
| X-Csrf-Token | `<<csrftoken>>`     |
| Cookie       | `<<cookie_header>>` |

<Frame>
  <img src="/images/dev/image-11.png" alt="" />
</Frame>
</Step>

<Step title="Logga in med API-verktyg">
Nu kan du logga in med ditt användarnamn och lösenord.

```json5
{
  "_csrf": "<<csrftoken>>",
  "email": "admin@overleaf.com",
  "password": "xxxxxx"
}
```

Så här ser svaret ut när du anger fel användarnamn eller lösenord.

<Frame>
  <img src="/images/dev/image-12.png" alt="" />
</Frame>
</Step>
</Steps>
