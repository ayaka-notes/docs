### Docker

Docker erbjuder ett lättviktigt och portabelt sätt att paketera och köra applikationer i isolerade containrar. Genom att paketera applikationen tillsammans med alla nödvändiga beroenden säkerställer en container ett konsekvent beteende på olika maskiner, från bärbara datorer till produktionsservrar.

TeX Live är kraftfullt men stort och känsligt för skillnader på systemnivå. Genom att paketera TeX Live i en Docker-avbild blir LaTeX-verktygskedjan förutsägbar, reproducerbar och lätt att distribuera.

Vissa TeX Live-paket är dock beroende av skalåtkomst. Av säkerhetsskäl bör containern köras i en begränsad miljö som hindrar användare från att köra godtyckliga skalkommandon (till exempel via `\write18` eller shell escape). Denna isolering skyddar värdsystemet och förhindrar oavsiktlig åtkomst till containerns underliggande filsystem eller verktyg som `bash`.

### TeXLive Full Edition

[TeXLive-Full@ayaka-notes](https://github.com/ayaka-notes/texlive-full/) är en fullfjädrad **TeXLive Docker-avbild** utformad för sandlådad LaTeX-kompilering i [Ayakaleaf Pro](https://github.com/ayaka-notes/ayakaleaf-pro), [Overleaf CEP](https://github.com/yu-i-i/overleaf-cep) eller fristående LaTeX-kompileringsmiljöer.

Avbilden syftar till att tillhandahålla en nästan komplett TeXLive-distribution med vanliga typsnitt och verktyg förinstallerade, för att minimera kompileringsfel som orsakas av saknade paket eller typsnitt. Obs! Denna Docker-avbild **innehåller inte** några sharelatex/overleaf-komponenter. Den används för kompilering i Overleaf/Overleaf Pro.

#### Funktioner:

* 🚀 Stöd för både x86\_64- och arm64-serverarkitekturer
* 📦 Fullständig och optimerad TeXLive-installation
* 🧩 Förinstallerade vanliga typsnitt och verktyg
* 🐳 Redo att användas med Docker och Docker Compose
* 🧪 Testad med Overleaf Server Pro / Overleaf Pro
* 🔄 Uppdateras regelbundet med de senaste TeXLive-utgåvorna
* 🏷 Flera TeXLive-versionstaggar (2020 – senaste)
* 🧑‍🔬 Knitr-stöd för R-kod i LaTeX-dokument

### Användning med Ayakaleaf Pro

TeX Live Full från Ayaka-notes är särskilt utformad för [ayakaleaf-pro](https://github.com/ayaka-notes/ayakaleaf-pro). Om du är [Toolkit-användare](https://github.com/overleaf/toolkit) kan du lägga till följande miljövariabler i filen `config/variables.env`.

Till exempel:

```dotenv title="config/variables.env" wrap
ALL_TEX_LIVE_DOCKER_IMAGES=ghcr.io/ayaka-notes/texlive-full:2026.1, ghcr.io/ayaka-notes/texlive-full:2025.1
ALL_TEX_LIVE_DOCKER_IMAGE_NAMES=Texlive 2026, Texlive 2025
TEX_LIVE_DOCKER_IMAGE=ghcr.io/ayaka-notes/texlive-full:2026.1
```

### TeX Live-versioner

Tack vare GitHub Actions kan vi bygga alla TeX-avbilder parallellt, vilket omfattar:

* `ghcr.io/ayaka-notes/texlive-full:2026.1` (även taggen `latest`)
* `ghcr.io/ayaka-notes/texlive-full:2025.1`
* `ghcr.io/ayaka-notes/texlive-full:2024.1`
* `ghcr.io/ayaka-notes/texlive-full:2023.1`
* `ghcr.io/ayaka-notes/texlive-full:2022.1`
* `ghcr.io/ayaka-notes/texlive-full:2021.1`
* `ghcr.io/ayaka-notes/texlive-full:2020.1`
* `ghcr.io/ayaka-notes/texlive-full:base`

Vi använder spegelarkivet från [texlive info](https://texlive.info/tlnet-archive/), som innehåller nästan alla TeX Live-versioner från 1996 till 2025. Och tack vare Overleafs Dockerfile kan vi bygga det här projektet snabbare.

> Varför stöds inte TeX Live 2019 och tidigare?
>
> Det är extremt svårt att underhålla dessa gamla avbilder. Dessutom tillhandahåller webbplatsen [texlive.info](https://texlive.info/) ingen information om TeX Live-versioner som släpptes före 2019, så vi kan inte bygga avbilder för dessa versioner. Om du behöver en specifik äldre version kan du skapa ett ärende och meddela oss.

### Ingående komponenter

Följande paket ingår i Docker-avbilden.

* Alla TeXLive-paket (för det aktuella året)
* R-paket (endast ett urval)
* fontconfig inkscape pandoc python3-pygments wget python3
* gnupg gnuplot perl-modules perl ca-certificates
* ghostscript qpdf r-base-core tar

Följande typsnitt ingår i Docker-avbilden.

* [Google Fonts](https://fonts.google.com/)
* [Microsoft msttcorefonts](https://packages.ubuntu.com/jammy/ttf-mscorefonts-installer)
* [Typsnitt som stöds av Overleaf](https://www.overleaf.com/learn/latex/Questions/Which_OTF_or_TTF_fonts_are_supported_via_fontspec%3F)

Kontrollera om de aktuella typsnitten får användas kommersiellt. Vi **ansvarar inte** för några juridiska problem som uppstår till följd av att du använder typsnitt felaktigt. När du laddar ner avbilden godkänner du automatiskt detta.

### Problem

<Accordion title="Problem 01: Problem med saknade typsnitt i cachen">

När Overleaf kompilerar ett LaTeX-projekt och ett typsnitt saknas **kan du märka att kompileringen tar lång tid**. Det beror på att TeX Live, när ett typsnitt saknas, försöker **bygga om hela typsnittscachen**. Detta är en tidskrävande process.

I vår avbild har vi byggt typsnittscachen i förväg, och vi åtgärdar problemet med [den här committen](https://github.com/ayaka-notes/texlive-full/commit/0cb66b0dc8b82be628cf6999cfd659d9784e132f)

</Accordion>

<Accordion title="Problem 02: SyncTeX är extremt långsamt">

När du använder den här avbilden i sharelatex kan du märka att SyncTeX är extremt långsamt.

Se: [https://github.com/overleaf/overleaf/issues/1150](https://github.com/overleaf/overleaf/issues/1150) – inaktivera bara HTTP 2.0.

</Accordion>

<Accordion title="Problem 03: Fel vid omkompilering med den officiella TeX Live-avbilden">

Om du använder den officiella TeX Live-avbilden `texlive/texlive` på Docker Hub kan du märka att ett fel rapporteras när du kompilerar om ett projekt. I vår avbild är detta problem dock åtgärdat, eftersom vi använder den senaste Ubuntu-basavbilden och installerar alla beroenden från Ubuntus officiella repository.

</Accordion>

### Andra tekniska påminnelser

När du bygger TeX Live-avbilder (före 2019) kan du behöva vara uppmärksam på följande problem:

* Före TeX Live 2017 stöds endast `http`/`ftp`, så du kan inte använda `https` för nedladdning om du inte modifierar `peal`-skriptet.
* Före 2015 tillhandahålls endast sha256-filer, så du kan inte använda sha512 för kontroll.
