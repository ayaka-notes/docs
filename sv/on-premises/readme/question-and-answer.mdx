Här har vi sammanställt svar på några vanliga frågor om Ayakaleaf Pro.

### Grundläggande frågor

<Accordion title="F01: Är Ayakaleaf Pro en gratis provversion? Krävs det en licens?">

Nej. Ayakaleaf Pro är helt gratis att använda. Det är ingen provversion och kräver ingen licens.

</Accordion>

<Accordion title="F02: Innehåller ni (Ayakaleaf Pro) alla funktioner i Overleaf Server Pro?">

Ja. Ayakaleaf Pro innehåller alla funktioner i Overleaf Server Pro, inklusive Git-Bridge-integrationen. Det innehåller också utvalda funktioner från Overleafs SaaS-plattform. Vi fortsätter att utveckla och förbättra Ayakaleaf Pro.

</Accordion>

<Accordion title="F03: Vad kostar Overleaf Server Pro?">

Overleaf Server Pro kostar runt \$300 per användare och år. Det krävs minst 10 licenser, så installationer börjar på ungefär \$3,000 per år. Mindre offentliga kontrakt i USA visar årliga kostnader på cirka \$320–\$370 per användare. Det gör Server Pro dyrt, särskilt för mindre team. Se [#information-and-price-about-overleaf-server-pro](/sv/on-premises#information-and-price-about-overleaf-server-pro  "mention") för dokumenterade inköp och priser.

</Accordion>

<Accordion title="F04: Varför innehåller Overleaf Server Pro inte GitHub Sync eller AI-funktioner?">

Overleaf Server Pro används ofta av myndigheter och offentliga organisationer. De driftsätter det i privata nätverk och kontrollerar åtkomsten strikt. För att skydda känsliga data undviker de inkluderade funktionerna att utbyta data med tredjepartstjänster. Om du behöver GitHub Sync, AI eller liknande uppkopplade funktioner rekommenderar Overleaf en prenumeration på sin SaaS-plattform.

</Accordion>

<Accordion title="F05: Är Ayakaleaf Pro säkert och pålitligt?">

Ayakaleaf Pro är öppen källkod. Vi granskar koden med verktyg som Codex Security för att stärka säkerheten och tillförlitligheten. Om du inte aktiverar datasynkronisering med tredje part stannar dina data på din server. Ayakaleaf Pro innehåller ingen telemetri som skickar dina data någon annanstans.

</Accordion>

<Accordion title="F06: Kommer Ayakaleaf Pro att underhållas långsiktigt?">

Vi kommer att göra allt vi kan för att underhålla projektet på lång sikt.

</Accordion>

<Accordion title="F07: Är Ayakaleaf Pro regelefterlevande?">

Ayakaleaf Pro är en community-fork. Koden och de integrerade funktionerna kommer från bidrag från communityn. Projektet är licensierat under AGPL v3. Installationer kan följa licensen när de uppfyller dess krav.

</Accordion>

<Accordion title="F08: Varför heter projektet Ayakaleaf Pro?">

Projektet hette ursprungligen Overleaf Pro 2024. Utvecklingen pausades en tid och återupptogs i slutet av 2025. Under första kvartalet 2026 döpte Overleaf om sin AI-aktiverade prenumerationsplan till Pro. Feedback från communityn påpekade också att namnet Overleaf Pro kunde medföra risker för varumärkesintrång och förväxling. Det kunde få användare att tro att projektet var officiellt.

Vi döpte om projektet till Ayakaleaf Pro för att undvika den förvirringen. Namnet kan läsas som ”Ayaka-notes Overleaf Pro”. Underhållaren (du kan kalla mig ayaka!) har bidragit till utvecklingen i Overleaf-communityn sedan studietiden, för över fem år sedan. Den erfarenheten stöder vårt åtagande om långsiktigt underhåll.

</Accordion>

<Accordion title="F09: Vad skiljer Ayakaleaf Pro från nyare AI-byggda LaTeX-editorer?">

Sedan 2026 har open source-communityn släppt många AI-byggda LaTeX-editorer, däribland OpenAI Prism. Ayakaleaf Pro håller dina data och tjänster på din egen server. Det ger dig direkt kontroll över din installation och dina data.

Många experimentella community-editorer saknar en etablerad plan för långsiktigt underhåll. Kompileringsplattformar för LaTeX från tredje part kan också sluta fungera när användarbasen eller intäkterna inte räcker till. Ayakaleaf Pro levererar all källkod och låter dig själv drifta varje tjänst. Även om underhållet skulle upphöra kan din befintliga egendriftade tjänst fortsätta att köras.

</Accordion>

### Funktioner

<Accordion title="F01: Vilka funktioner erbjuder Ayakaleaf Pro? Kan jag önska en ny funktion?">

Se vår dokumentation för den aktuella funktionslistan. Om det finns en funktion du vill att vi lägger till är du välkommen att öppna ett issue (för funktionsönskemål) på GitHub. Vi gör vårt bästa för att implementera önskade funktioner, men utveckling tar tid och vi kan inte garantera att varje funktion levereras direkt.

</Accordion>

<Accordion title="F02: Jag har byggt några funktioner. Kan jag skicka in en PR, och är det garanterat att den accepteras?">

Bidrag är välkomna, men det finns ingen garanti för att de accepteras. Vi utvärderar varje PR utifrån dess påverkan på den underliggande Overleaf-kodbasen, underhållsbördan och värdet den tillför användarna. Vi gör vårt bästa för att slå samman och underhålla värdefulla bidrag.

Vi kan dock avvisa PR:er som inför alltför omfattande ändringar, består av ogranskad eller dåligt förstådd AI-genererad kod (”vibe coding”) eller lägger till funktioner som skulle vara svåra att underhålla över tid.

</Accordion>

<Accordion title="F03: Hur konfigurerar jag en specifik funktion?">

Vi uppdaterar i regel dokumentationen när vi släpper en ny funktion. Se den relevanta dokumentationen för detaljerade installationsanvisningar och förklaringar av de tillgängliga miljövariablerna.

</Accordion>

<Accordion title="F04: Vilka Python-bibliotek kan Python Runner använda?">

Python Runner kör Python i användarens webbläsare med [Pyodide](https://pyodide.org/) 0.29.3, inte på servern. Den läser in de paket som din kod importerar från [paketen som är inbyggda i Pyodide](https://pyodide.org/en/0.29.3/usage/packages-in-pyodide.html), till exempel NumPy, pandas och Matplotlib. Paket som installeras med `pip` och andra paket är inte tillgängliga. Det finns inget att konfigurera på servern.

</Accordion>

<Accordion title="F05: Kan stavningskontrollen kontrollera japanska eller kinesiska?">

Nej. Stavningskontrollen har ingen ordlista för japanska eller kinesiska, så dessa språk finns inte i listan över språk för stavningskontroll. Användarna kan stänga av stavningskontrollen för ett projekt i redigerarens inställningar.

</Accordion>

### Driftsättning

<Accordion title="F01: Stöder Ayakaleaf Pro distribuerad driftsättning i k8s?">

För de flesta användare rekommenderar vi driftsättning med [Toolkit](/sv/on-premises/installation/using-the-toolkit). Vi rekommenderar inte storskaliga klusterdriftsättningar med Kubernetes eller liknande plattformar, eftersom de avsevärt kan öka den operativa komplexiteten och underhållsarbetet.

</Accordion>

<Accordion title="F02: Hur kan jag säkerställa tillgänglighet när jag betjänar tusentals användare?">

Se vår guide om [horisontell skalning](/sv/on-premises/maintenance/horizontal-scaling). Du kan driftsätta flera Overleaf-instanser och konfigurera en lastbalanserare som fördelar trafiken mellan dem.

</Accordion>

<Accordion title="F03: Kan ni hjälpa mig att driftsätta eller migrera?">

Om du har en befintlig Overleaf Server Pro-instans hjälper vi gärna till att migrera till Ayakaleaf Pro. Kontakta oss via e-post eller issues.

</Accordion>

<Accordion title="F04: Kan jag hosta Ayakaleaf Pro under en undersökväg i URL:en, till exempel `https://example.com/overleaf`?">

Nej. Ayakaleaf Pro måste serveras från roten av en domän. Använd en dedikerad domän eller underdomän, till exempel `https://overleaf.example.com`.

</Accordion>

<Accordion title="F05: Kan jag köra Ayakaleaf Pro på Windows eller macOS, eller utan Toolkit?">

Vi stöder Linux-servrar med [Toolkit](/sv/on-premises/installation/using-the-toolkit). Docker Desktop på Windows, WSL2 eller macOS kan fungera, men vi testar det inte, se [Felsökning](/sv/on-premises/support/troubleshooting) för ett känt problem med MongoDB.

Vi tillhandahåller ingen fristående `docker-compose.yml`. För att se den Compose-konfiguration som Toolkit använder kör du `bin/docker-compose config` i Toolkit-katalogen.

</Accordion>

<Accordion title="F06: Hur avinstallerar jag Ayakaleaf Pro?">

Det finns inget avinstallationsskript. I Toolkit-katalogen:

1. Stoppa och ta bort containrarna med `bin/docker-compose down`.
2. Radera data. Som standard ligger den i katalogen `data/` i Toolkit. Om du har ändrat `OVERLEAF_DATA_PATH`, `MONGO_DATA_PATH`, `REDIS_DATA_PATH` eller `GIT_BRIDGE_DATA_PATH` i `config/overleaf.rc` raderar du även de katalogerna. Detta kan inte ångras, så [säkerhetskopiera](/sv/on-premises/maintenance/data-and-backups) först om du kan behöva data.
3. Radera Toolkit-katalogen.
4. Ta bort Docker-imagarna, som du kan lista med `docker images`: `ghcr.io/ayaka-notes/overleaf-pro`, git-bridge-imagen, `mongo`, `redis` och TeX Live-imagarna.

</Accordion>

<Accordion title="F07: Hur stoppar, startar eller startar jag om Ayakaleaf Pro?">

Kör följande i Toolkit-katalogen:

* `bin/stop` stoppar alla containrar och `bin/start` startar dem igen. Containrarna behålls, så användarna förblir inloggade.
* `bin/up -d` skapar containrarna och startar dem i bakgrunden. Kör det efter att du har ändrat `config/variables.env`, `config/overleaf.rc` eller `config/version`: det återskapar de containrar vars konfiguration har ändrats, och först då börjar ändringarna gälla. `bin/stop` och `bin/start` tillämpar dem inte.
* `bin/docker-compose restart sharelatex` startar bara om Overleaf-containern, utan att tillämpa konfigurationsändringar.

Om användarna loggas ut varje gång `bin/up` återskapar containern anger du `OVERLEAF_SESSION_SECRET`, se Frågor och svar i [Miljövariabler](/sv/on-premises/configuration/overleaf-toolkit/environment-variables).

</Accordion>

<Accordion title="F08: Var anger jag OAuth-callback-URL:en?">

I applikationen som du skapar hos leverantören, inte i Ayakaleaf Pro. Det finns ingen callback-inställning i `config/variables.env` för någon av dessa integrationer: Ayakaleaf Pro bygger varje callback-URL utifrån `OVERLEAF_SITE_URL` och skickar den till leverantören, som avvisar den om den inte matchar den som registrerats för applikationen. Du registrerar den alltså bara hos leverantören och anger `OVERLEAF_SITE_URL` till adressen som användarna öppnar.

| Integration | Fält hos leverantören | Värde |
| --- | --- | --- |
| [GitHub](/sv/on-premises/configuration/overleaf-toolkit/github-synchronisation) | Authorization callback URL | `${OVERLEAF_SITE_URL}/user/github-sync/oauth2/callback` |
| [GitLab](/sv/on-premises/configuration/overleaf-toolkit/gitlab-synchronisation) | Redirect URI | `${OVERLEAF_SITE_URL}/user/gitlab-sync/oauth2/callback` |
| [Gitea](/sv/on-premises/configuration/overleaf-toolkit/gitea-synchronisation) | Redirect URIs | `${OVERLEAF_SITE_URL}/user/gitea-sync/oauth2/callback` |
| [Dropbox](/sv/on-premises/configuration/overleaf-toolkit/dropbox-synchronisation) | Redirect URIs (klicka på **Add**) | `${OVERLEAF_SITE_URL}/user/dropbox/oauth/callback` |
| [Zotero](/sv/on-premises/configuration/overleaf-toolkit/zotero-integration) | Callback URL | `${OVERLEAF_SITE_URL}/user/zotero/oauth/callback` |
| [Mendeley](/sv/on-premises/configuration/overleaf-toolkit/mendeley-integration) | Redirect URL | `${OVERLEAF_SITE_URL}/user/mendeley/oauth/callback` |
| [OIDC-inloggning](/sv/on-premises/configuration/overleaf-toolkit/authentication/oidc-authentication) | Redirect URI | `${OVERLEAF_SITE_URL}/oidc/login/callback` |
| [SAML-inloggning](/sv/on-premises/configuration/overleaf-toolkit/authentication/saml-authentication) | ACS URL (Assertion Consumer Service) | `${OVERLEAF_SITE_URL}/saml/login/callback` |

Om du ändrar `OVERLEAF_SITE_URL`, till exempel till en ny domän, måste du även uppdatera URL:en hos varje leverantör, annars misslyckas länkningen.

</Accordion>

### LaTeX

<Accordion title="F01: Är användarnas LaTeX-kompileringar isolerade? Är Shell Escape aktiverat?">

När du aktiverar Sandbox Compiles körs varje användares kompilering i en separat Docker-container och är isolerad från andra användares kompileringar. Shell Escape är aktiverat som standard för Sandbox Compiles.

</Accordion>

<Accordion title="F02: Är Sandbox Compiles-avbildningen pålitlig? Kan kompileringen misslyckas?">

Vi har förbättrat vår TeX Live Full-avbildning för Sandbox Compiles under de senaste tre åren. I de flesta fall kompileras projekt som kompileras på overleaf.com även korrekt med Ayakaleaf Pro. Om ett nödvändigt typsnitt saknas kan du ladda upp typsnittet till ditt projekt manuellt.

</Accordion>

<Accordion title="F03: Mitt projekt kompileras inte. Kan ni hjälpa mig att felsöka det?">

Ladda upp ditt projekt till Overleafs officiella webbplats, aktivera delning via skrivskyddad länk och inkludera länken i ett GitHub-issue.

Vi undersöker och åtgärdar buggar som hindrar ett projekt från att kompileras i Ayakaleaf Pro när det kompileras utan problem på Overleafs officiella webbplats. Kompileringsproblem utanför detta omfång täcks inte av vår support.

</Accordion>
