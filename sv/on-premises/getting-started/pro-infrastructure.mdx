#### Tjänster

Overleaf Pro-infrastrukturen består av fyra huvudtjänster: `sharelatex`, `git-bridge` (valfri), `mongo` och `redis`. Tjänsten `sharelatex`, som kör huvudapplikationen Server Pro, är beroende av tjänsterna `mongo` och `redis` för databas respektive cachning/realtidsfunktioner, samt av `git-bridge` för att hantera [Git-integrationen](/sv/on-premises/configuration/overleaf-toolkit/git-integration) (valfri). Den enda port som publiceras på värddatorn är port 80, som används av containern `sharelatex`.

Server Pro har även valfritt stöd för [S3-kompatibel lagring](/sv/on-premises/configuration/overleaf-toolkit/s3) för projektfiler och fullständig projekthistorik, och kan dessutom fungera som proxy för åtkomst till Overleafs huvudsakliga [dokumentationswebbplats](https://www.overleaf.com/learn). Mer information finns i vår guide om sidor för att [lägga till LaTeX-användarhjälp](/sv/on-premises/configuration/overleaf-toolkit/adding-latex-user-help).

<Info>

Vid behov kan MongoDB och Redis flyttas ut genom att använda miljövariabler som pekar på externa tjänster. Mer information finns i [Konfigurera Overleaf](/sv/on-premises/configuration) om du använder Docker Compose och i [Toolkit-inställningar](/sv/on-premises/configuration/overleaf-toolkit/toolkit-settings) om du använder Overleaf Toolkit.

</Info>

#### Kompilering

För [Sandboxed Compiles](/sv/on-premises/configuration/overleaf-toolkit/sandboxed-compiles) orkestrerar containern `sharelatex` skapandet av nya containrar som hanterar projektkompileringar; detta sker via Docker-socketen på värddatorn. Du kan läsa mer om editorn och hela kompilerings-/cachningsprocessen [här](/sv/on-premises/getting-started/microservices#editor-and-compile-process).

#### Nätverk

Kommunikationen mellan containrar sker via Dockers interna DNS-upplösning i ett dedikerat bryggnätverk, och inga brandväggar är aktiverade. Som standard använder tjänsterna ovan sina respektive standardportar, men dessa kan konfigureras med miljövariabler. Containern `sharelatex` använder port 80 för extern webbåtkomst (som betjänas av Nginx), containern `mongo` använder port 27017 och `redis` använder port 6379.

För kunder som använder vår hanterade lösning [Overleaf Toolkit](https://github.com/overleaf/toolkit) går det att valfritt [aktivera en TLS-proxy](/sv/on-premises/configuration/overleaf-toolkit/tls-proxy) som avslutar HTTPS-anslutningar med Nginx via en miljövariabel. Alternativt kan du använda din befintliga TLS-proxy.

<Info>

Du kan se ett diagram som förklarar flödet av förfrågningar [här](/sv/on-premises/configuration/overleaf-toolkit/tls-proxy).

</Info>

#### Sammanfattning

* Utanför Docker-nätverket är endast port 80 åtkomlig, och den är bunden till Nginx. <strong>Obs:</strong> Containern `sharelatex` kör många [tjänster](https://github.com/overleaf/overleaf/tree/main/services) som kommunicerar med varandra via HTTP. Dessa portar är dock **inte** åtkomliga utanför Docker-nätverket.
* Inom Docker-nätverket kan Overleaf-tjänsterna, MongoDB, Redis och Git Bridge kommunicera fritt med varandra.
* Inuti containrar för [Sandboxed Compiles](/sv/on-premises/configuration/overleaf-toolkit/sandboxed-compiles) finns inget nätverk tillgängligt.
