## Ayakaleaf Pro 6.3.2

<strong>Releasedatum:</strong> 2026.10.23

Se: [https://github.com/ayaka-notes/ayakaleaf-pro/releases/tag/pro-v6.3.2](https://github.com/ayaka-notes/ayakaleaf-pro/releases/tag/pro-v6.3.2)

Vi är mycket stolta över att presentera Overleaf Pro 6.3.2. Overleaf 6.3.2 uppströms är en säkerhetsversion som uppdaterar Node.js, och vi levererar den tillsammans med Gitea-synkronisering och de buggfixar som hittats sedan 6.3.1.

<Info>

Gitea-synkronisering levereras i 6.3.2 som en **tidig förhandsversion** för gråtestning och släpps officiellt i v6.4.0. Dess konfiguration och beteende kan fortfarande ändras innan dess. Den är avstängd som standard. Rapportera eventuella problem på [GitHub](https://github.com/ayaka-notes/ayakaleaf-pro/issues).

</Info>

### Ändringar

* Gitea-synkronisering i båda riktningarna (tidig förhandsversion), för gitea.com och egendriftad Gitea 1.23+.
* Node.js 24.22.1, säkerhetsuppdateringen i Overleaf 6.3.2 uppströms.
* Buggfixar som hittats av vårt E2E-testsystem och Internal Horizon Issue Investigation.

#### Funktion 01: Gitea-synkronisering (förhandsversion)

Tvåvägssynkronisering med Gitea, på samma sätt som GitHub-synkronisering och GitLab-synkronisering fungerar: länka ditt konto, importera ett repositorium från menyn för nytt projekt, exportera ett projekt, pusha och hämta samt slå samman via pull requests. Overleaf kringgår aldrig repositoriets grenskydd. Se [Gitea-synkronisering](/sv/on-premises/configuration/overleaf-toolkit/gitea-synchronisation).

### Buggfixar

* GitHub-, GitLab- och Gitea-synkronisering: när en fil som tagits bort i repositoriet inte kan tas bort i Overleaf misslyckas synkroniseringen och kan göras om, i stället för att rapportera att den lyckades och lämna kvar filen i projektet. En `git push` som tar bort en fil misslyckas på samma sätt ([#121](https://github.com/ayaka-notes/ayakaleaf-pro/issues/121)).
* Git bridge: ett dokument som skapats i redigeraren med ett filnamnstillägg som inte är text (till exempel `.csv`) förblir ett redigerbart dokument när en `git push` ändrar det.
* Spåra ändringar: utloggade redigerare av ett länkdelat projekt kan ta bort kommentarstrådar men kan inte längre lösa eller öppna dem igen. Granskare kan ta bort sina egna svar.
* Mallgalleri: publicering av en mall kräver åtkomst till projektet.
* Learn: cachade hjälpsidor förblir tillgängliga när wikin inte kan nås.

### Uppgradering

* Från 6.3.1 eller 6.3.0: ingen migrering behövs. Hämta den nya imagen och starta om.
* Från 6.2.x eller tidigare med Zotero eller Mendeley i bruk: kör först Zotero/Mendeley-migreringen i [6.3.0](#ayakaleaf-pro-6.3.0).
* Gitea-synkroniseringen är avstängd som standard och behöver bara nya miljövariabler.

### Buggfixar

* Autentisering: lokala konton kan ange och ändra sitt lösenord på SSO-instanser, och OIDC-användare kan inte längre ändra sin egen e-postadress ([#112](https://github.com/ayaka-notes/ayakaleaf-pro/pull/112)). Inloggningsmetoderna LDAP, SAML och OIDC bevaras, och SAML/OIDC-utloggning fungerar igen. Se [Konton och lösenord](/sv/on-premises/configuration/overleaf-toolkit/authentication#accounts-and-passwords).
* LDAP, SAML och OIDC: namnattribut med flera värden (som `cn`) gör inte längre att inloggningen misslyckas, och e-postadresser från OIDC omvandlas till gemener precis som för LDAP och SAML, så ett konto vars e-postadress IdP:n skickar med annat skiftläge länkas i stället för att misslyckas.
* Avstängda användare: när en användare stängs av avslutas användarens sessioner och öppna redigerare stängs. Användarens Git-token och MCP-nedladdningar avvisas.
* GitHub-synkronisering: endast ägaren kan exportera ett projekt, ändringar som görs under en hämtning förblir väntande, tomma filer synkroniseras, manuella sammanslagningar verifieras på GitHub och en ersatt token återkallas vid omlänkning.
* Zotero / Mendeley: visar ett meddelande om att länka om när inloggningsuppgifterna inte längre fungerar, och indexerar om referenser efter en import.
* Anrop till externa API:er (Zotero, Mendeley, GitHub, GitLab, webbsökning) får en anslutningstidsgräns på 3 s i stället för 1 s ([#106](https://github.com/ayaka-notes/ayakaleaf-pro/pull/106)).
* Spåra ändringar: granskningsdata omfattar dokument som inte har lästs in och osparade ändringar (från [yu-i-i/overleaf-cep#262](https://github.com/yu-i-i/overleaf-cep/pull/262)).
* Felassistent: erbjuder korrigeringar endast för dokument i projektet ([#103](https://github.com/ayaka-notes/ayakaleaf-pro/pull/103)).
* Adminpanel: återställning av ett borttaget projekt, byte av ägare och redigering av användare fungerar korrekt. Sökningen använder den bokstavliga texten, och ett misslyckat e-postmeddelande förhindrar inte längre att konton skapas eller tas bort.
* Mallgalleri: en ogiltig sortering returnerar 400 i stället för 500, mall-ID:n valideras och vid publicering av ett projekt utan huvudfil efterfrågas en sådan.
* Git bridge: nginx vidarebefordrar `/git/` till `GIT_BRIDGE_HOST` och `GIT_BRIDGE_PORT`, och interna rutter döljs.
* Sandboxed compiles: containrar för nyligen kompilerade projekt behålls för återanvändning.

<Accordion title="Migrering av Zotero/Mendeley för befintliga installationer">

När du uppgraderar till den nya releasen av 6.3.0-imagen migrerar du befintliga metadata för länkade bibliografier från Zotero/Mendeley med skriptet nedan. Migreringen hör till korrigeringen `12031b8dfd`.

Den byter namn på `zoteroGroupId` / `mendeleyGroupId` till `group_id`, byter namn på `importedByUserId` till `importer_id` och tar bort `importedByName`.

Säkerhetskopiera MongoDB och stoppa applikationen innan du kör migreringen. Låt MongoDB fortsätta köra. Öppna dess skal (ersätt `mongo` med namnet på din container):

```bash
docker exec -it mongo mongosh
```

Kör följande i `mongosh` (ersätt `sharelatex` med namnet på din databas):

```javascript
use sharelatex

(async () => {
  let updated = 0
  await db.projects.find({}, { rootFolder: 1 }).forEach(async project => {
    const changes = {}
    function visit(folders, path) {
      for (const [i, folder] of (folders || []).entries()) {
        const folderPath = `${path}.${i}`
        for (const [j, file] of (folder.fileRefs || []).entries()) {
          const data = { ...file.linkedFileData }
          if (!["zotero", "mendeley"].includes(data.provider)) continue
          const groupKey = `${data.provider}GroupId`
          if (![groupKey, "importedByUserId", "importedByName"].some(key => key in data)) continue
          for (const [oldKey, newKey] of [[groupKey, "group_id"], ["importedByUserId", "importer_id"]]) {
            if (data[oldKey] != null && data[oldKey] !== "") {
              const value = String(data[oldKey])
              if (newKey in data && data[newKey] !== value) {
                throw new Error(`Conflicting ${newKey}: project ${project._id}, file ${file._id}`)
              }
              data[newKey] = value
            }
            delete data[oldKey]
          }
          delete data.importedByName
          changes[`${folderPath}.fileRefs.${j}.linkedFileData`] = data
        }
        visit(folder.folders, `${folderPath}.folders`)
      }
    }
    visit(project.rootFolder, "rootFolder")
    if (!Object.keys(changes).length) return
    const result = await db.projects.updateOne(
      { _id: project._id, rootFolder: { $eq: project.rootFolder } },
      { $set: changes }
    )
    if (!result.matchedCount) throw new Error(`Project changed during migration: ${project._id}`)
    updated += result.modifiedCount
  })
  print(`Updated ${updated} project(s).`)
})()
```

Skriptet inkluderar nästlade mappar och ändrar bara metadata för Zotero/Mendeley. Det är säkert att köra om: en slutförd migrering rapporterar `Updated 0 project(s).` vid nästa körning. Om det stoppar på grund av en konflikt undersöker du det rapporterade projektet/filen; tidigare projekt kan redan ha migrerats.

Starta den uppdaterade applikationen, ladda om editorn och uppdatera en befintlig bibliografifil som dess ursprungliga importör. Historiska ögonblicksbilder skrivs inte om. För att nedgradera till den gamla applikationen återställer du MongoDB-säkerhetskopian.

</Accordion>

#### Funktion 04: Sidindelning av mallar

Galleriet sköter nu sidindelning, sortering och sökning i MongoDB. Det fungerar utan förberedelser; med tusentals mallar kan du ändå lägga till dessa index för att hålla det snabbt (säkert att köra om, `mongo`/`sharelatex` = namnen på din container och databas):

```bash
docker exec mongo mongosh sharelatex --quiet --eval '
db.templates.createIndex({category:1,lastUpdated:-1},{name:"category_1_lastUpdated_-1",background:true});
db.templates.createIndex({lastUpdated:-1},{name:"lastUpdated_-1",background:true});
db.templates.createIndex({category:1,name:1},{name:"category_1_name_1_ci",collation:{locale:"en",strength:2},background:true});
db.templates.createIndex({name:1},{name:"name_1_ci",collation:{locale:"en",strength:2},background:true});
'
```

Behåll `collation` på de två `*_ci`-indexen exakt som de är skrivna — galleriet gör sökningar med samma collation och MongoDB använder bara ett matchande index.
