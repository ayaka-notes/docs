<Accordion title="Migrering av Zotero/Mendeley för befintliga installationer">

När du uppgraderar till den nya releasen av 6.3.0-imagen migrerar du befintliga metadata för länkade bibliografier från Zotero/Mendeley med skriptet nedan. Migreringen hör till korrigeringen `12031b8dfd`.

Den byter namn på `zoteroGroupId` / `mendeleyGroupId` till `group_id`, byter namn på `importedByUserId` till `importer_id` och tar bort `importedByName`.

Säkerhetskopiera MongoDB och stoppa applikationen innan du kör migreringen. Låt MongoDB fortsätta köra. Öppna dess skal (ersätt `mongo` med namnet på din container):

```bash
docker exec -it mongo mongosh
```

Kör följande i `mongosh` (ersätt `sharelatex` med namnet på din databas):

```javascript
use sharelatex

(async () => {
  let updated = 0
  await db.projects.find({}, { rootFolder: 1 }).forEach(async project => {
    const changes = {}
    function visit(folders, path) {
      for (const [i, folder] of (folders || []).entries()) {
        const folderPath = `${path}.${i}`
        for (const [j, file] of (folder.fileRefs || []).entries()) {
          const data = { ...file.linkedFileData }
          if (!["zotero", "mendeley"].includes(data.provider)) continue
          const groupKey = `${data.provider}GroupId`
          if (![groupKey, "importedByUserId", "importedByName"].some(key => key in data)) continue
          for (const [oldKey, newKey] of [[groupKey, "group_id"], ["importedByUserId", "importer_id"]]) {
            if (data[oldKey] != null && data[oldKey] !== "") {
              const value = String(data[oldKey])
              if (newKey in data && data[newKey] !== value) {
                throw new Error(`Conflicting ${newKey}: project ${project._id}, file ${file._id}`)
              }
              data[newKey] = value
            }
            delete data[oldKey]
          }
          delete data.importedByName
          changes[`${folderPath}.fileRefs.${j}.linkedFileData`] = data
        }
        visit(folder.folders, `${folderPath}.folders`)
      }
    }
    visit(project.rootFolder, "rootFolder")
    if (!Object.keys(changes).length) return
    const result = await db.projects.updateOne(
      { _id: project._id, rootFolder: { $eq: project.rootFolder } },
      { $set: changes }
    )
    if (!result.matchedCount) throw new Error(`Project changed during migration: ${project._id}`)
    updated += result.modifiedCount
  })
  print(`Updated ${updated} project(s).`)
})()
```

Skriptet inkluderar nästlade mappar och ändrar bara metadata för Zotero/Mendeley. Det är säkert att köra om: en slutförd migrering rapporterar `Updated 0 project(s).` vid nästa körning. Om det stoppar på grund av en konflikt undersöker du det rapporterade projektet/filen; tidigare projekt kan redan ha migrerats.

Starta den uppdaterade applikationen, ladda om editorn och uppdatera en befintlig bibliografifil som dess ursprungliga importör. Historiska ögonblicksbilder skrivs inte om. För att nedgradera till den gamla applikationen återställer du MongoDB-säkerhetskopian.

#### Funktion 04: Sidindelning av mallar

Galleriet sköter nu sidindelning, sortering och sökning i MongoDB. Det fungerar utan förberedelser; med tusentals mallar kan du ändå lägga till dessa index för att hålla det snabbt (säkert att köra om, `mongo`/`sharelatex` = namnen på din container och databas):

```bash
docker exec mongo mongosh sharelatex --quiet --eval '
db.templates.createIndex({category:1,lastUpdated:-1},{name:"category_1_lastUpdated_-1",background:true});
db.templates.createIndex({lastUpdated:-1},{name:"lastUpdated_-1",background:true});
db.templates.createIndex({category:1,name:1},{name:"category_1_name_1_ci",collation:{locale:"en",strength:2},background:true});
db.templates.createIndex({name:1},{name:"name_1_ci",collation:{locale:"en",strength:2},background:true});
'
```

Behåll `collation` på de två `*_ci`-indexen exakt som de är skrivna — galleriet gör sökningar med samma collation och MongoDB använder bara ett matchande index.

## Ayakaleaf Pro 6.2.2

<strong>Releasedatum:</strong> 2026.07.23

Se: [https://github.com/ayaka-notes/ayakaleaf-pro/releases/tag/pro-v6.2.2](https://github.com/ayaka-notes/ayakaleaf-pro/releases/tag/pro-v6.2.2)

### Ändringar

Bakåtporterar de officiella snabbkorrigeringarna som levererades i Overleaf `6.2.2` uppströms (ovanpå `6.2.1`):

* Slutar läcka den hemliga nyckeln för projektinbjudningstoken till loggarna. Krypteringsfunktionen för inbjudningstoken loggade sin egen konfiguration vid varje kryptering/dekryptering, vilket inkluderade chifferlösenorden som härleds från `OVERLEAF_INVITE_TOKEN_SECRET`.
* Migrerar utgående e-post från AWS SES v1-klienten, vars support har upphört, till SESv2. Instanser konfigurerade med e-postdrivrutinen `ses` kunde helt misslyckas med att skicka e-post; utskick går nu via `SESv2Client`.
* Döljer gruppposterna i rullgardinsmenyn för projektdelning bakom den nya funktionsflaggan `group-link-sharing`, så att gruppdelning via länk inte längre erbjuds på instanser där den inte är tillämplig.
* Åtgärdar dialogrutan för projektdelning för medarbetare. Om den öppnades av någon som inte var ägare, eller med flödet `sharing-updates` inaktiverat, skickades ett anrop som alltid misslyckades och visade felet "something went wrong".
* Lägger till `scripts/flush_docs_with_pending_updates.js` i document-updater, ett underhållsskript som återställer dokument som lämnats med en fastnad `PendingUpdates`-kö i Redis efter att deras projekt har tömts eller tagits bort permanent. Stöder `--dry-run` och en säkerhetskontroll med `--estimated-docs`.
* Uppdaterar beroenden: `multer` 2.2.0, `form-data` 2.5.6, `protobufjs` 7.6.3, `@grpc/grpc-js` 1.14.4.

Den här releasen innehåller även följande korrigeringar och förbättringar från Ayakaleaf Pro:

* Lägger till fullständiga översättningar för 16 ytterligare språk (cs, da, de, es, fi, fr, it, ja, ko, nl, no, pl, pt, ru, sv, tr), vilket åtgärdar oöversatta strängar som på sidan för lösenordsåterställning. Åtgärdar [#38](https://github.com/ayaka-notes/ayakaleaf-pro/issues/38).
* Åtgärdar antalet objekt på knappen "show N more projects" i adminpanelen, som visade fel antal eftersom platshållaren för plural inte skickades korrekt.
* Åtgärdar valideringsfel vid export till GitHub, som nu renderas via statiska i18n-nycklar i stället för råa meddelanden, och tar bort felnycklar som inte längre används av dialogrutan för GitHub Sync.

## Ayakaleaf Pro 6.2.0

<strong>Releasedatum:</strong> 2026.07.10

Se: [https://github.com/ayaka-notes/ayakaleaf-pro/releases/tag/pro-v6.2.0](https://github.com/ayaka-notes/ayakaleaf-pro/releases/tag/pro-v6.2.0)

Vi är stolta över att tillkännage releasen av Overleaf Pro 6.2.0, den mest kraftfulla och funktionsrika LaTeX-editorn online i communityn. Ett särskilt tack till yu-i-i och davrot för deras värdefulla bidrag. De förbättrade GitHub Sync och introducerade avancerad referenssökning och Zotero-integration.

### Anmärkningar

<Warning>

* En ny obligatorisk miljövariabel, `OVERLEAF_INVITE_TOKEN_SECRET`, har införts. Du måste generera den med `openssl rand -base64 32`. Om den inte är konfigurerad kommer din Overleaf-instans inte att starta.
* Om du aktiverar GitHub Sync måste du konfigurera miljövariabeln `GITHUB_TOKEN_CIPHER_PASSWORD`. Variabeln krävs för att kryptera GitHub-åtkomsttoken på ett säkert sätt. Utan den kommer din Overleaf-instans inte att starta.

</Warning>

* Lade till en ny miljövariabel, `DEFAULT_LATEX_COMPILER`, för att ange standardkompilatorn för nya projekt (antingen `pdflatex`, `latex`, `xelatex` eller `lualatex`).
* Den omdesignade editorn är nu det enda tillgängliga alternativet.

Den här releasen innehåller följande förbättringar och nya funktioner.

* `MAX_UPLOAD_SIZE` kan nu konfigureras i stället för att vara begränsad till **50 MB**.
* Åtgärdade en loop med omstarter av containern när kompilering i sandlåda var inaktiverad.
* Införde att borttagning av PAT är begränsad till ägaren för OAuth2.
* Åtgärdade ett problem med LDAP-import.

Funktionerna omfattar:

* Lade till en webbläsarbaserad Python-körare.
* Lade till Pandoc-stöd för import och export av Markdown, DOCX och andra format.

## Ayakaleaf Pro 6.0.0

<strong>Releasedatum:</strong> 2026.02.17

Testrelease, se: [https://github.com/ayaka-notes/ayakaleaf-pro/releases/tag/pro-v6.0.0](https://github.com/ayaka-notes/ayakaleaf-pro/releases/tag/pro-v6.0.0)

Det här är en testrelease och dessutom vår första version av Overleaf Pro. Den här versionen innehåller inga funktioner från Server Pro, så den markerar bara vår startpunkt. Vi kommer att lägga till nya funktioner senare, som adminpanel och git-bridge ...

I den här releasen har vi introducerat Overleafs Docker-image för ARM. Du kan prova den om du har en Mac eller en ARM-baserad server, men vissa funktioner kanske inte fungerar som de ska (ännu inte testat).

### Docker-image

Du hittar Docker-imagen här: [https://github.com/ayaka-notes/overleaf-pro/pkgs/container/overleaf-pro](https://github.com/ayaka-notes/overleaf-pro/pkgs/container/overleaf-pro)

För en image med flera arkitekturer, se [här](https://github.com/ayaka-notes/overleaf-pro/pkgs/container/overleaf-pro/691283454?tag=6.0.0).

```bash
docker pull ghcr.io/ayaka-notes/overleaf-pro:6.0.0
```

### Migrering av binärfiler

Den här nya releasen halverar lagringsanvändningen för binärfiler.

En onlinemigrering ingår i version `5.5`, vilket ger minimal driftstopp i samband med uppgraderingen. Innan du uppgraderar till Server Pro `v6` måste du se till att du redan kör den senaste versionen av Server Pro `v5.5` ([Versionsinformation 5.x.x](https://docs.overleaf.com/on-premises/release-notes/release-notes-5.x.x)) och har kört migreringen.

[Se de fullständiga migreringsinstruktionerna](https://docs.overleaf.com/on-premises/release-notes/release-notes-5.x.x/binary-files-migration).

### Uppgradering av MongoDB till v8

Den här releasen höjer lägsta MongoDB-version till `8.0`.

Om du för närvarande använder MongoDB `v6` eller tidigare måste du uppdatera en huvudversion i taget (`v6 → v7 → v8`).

<Warning>

Se till att du har en säkerhetskopia av [databasen](https://docs.overleaf.com/on-premises/maintenance/data-and-backups) **innan** du uppgraderar. Vid en återställning måste du återställa databasens säkerhetskopia.

</Warning>

Instruktioner för hur du uppgraderar MongoDB `v6 → v7 → v8` finns i vår steg-för-steg-guide [här](https://docs.overleaf.com/on-premises/maintenance/updating-mongodb#example-upgrading-mongodb-from-6.0-to-7.0-toolkit-users).

### Uppgradering av Redis till v7.4

Den här releasen höjer även lägsta Redis-version till `7.4`.

Uppdatera `REDIS_IMAGE` i din `config/overleaf.rc` till `REDIS_IMAGE=7.4`.

### Nya funktioner

* Länkdelning kan nu inaktiveras med `OVERLEAF_DISABLE_LINK_SHARING=true`.
* `OVERLEAF_MAINTENANCE_MESSAGE` och `OVERLEAF_MAINTENANCE_MESSAGE_HTML` finns nu tillgängliga för att anpassa titeln och innehållet på underhållssidan.
* `OVERLEAF_USER_HARD_DELETION_DELAY` och `OVERLEAF_PROJECT_HARD_DELETION_DELAY` kan konfigureras (i millisekunder) för att ändra fördröjningen innan borttagna användare/projekt förfaller (standard 90 dagar).

### Felkorrigeringar

* Åtgärdade rendering av sidfoten med länkar.
* Förbättrade felmeddelanden vid fel vid SAML-inloggning.
* Åtgärdade att en post i granskningsloggen inte lades till när en användares administratörsstatus uppdateras vid SSO-inloggning.
* Åtgärdade fel i historikpanelen när TLS är aktiverat i Redis.
* Kompileringar kan nu stoppas vid användning av kompilering utan sandlåda.

### Övriga ändringar

* Alla länkar till statussidan (som anges via `OVERLEAF_STATUS_PAGE_URL`) använder nu `HTTPS` och öppnas i en ny webbläsarflik.
