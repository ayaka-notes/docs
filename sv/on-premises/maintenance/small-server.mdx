Ayakaleaf Pro körs på en server med 2 CPU-kärnor och 2 GB minne, Git-integration inräknad, när du lägger till 2 GB swap. Utan swap tar minnet slut medan det startar. Inställningarna i steg 2 halverar sedan nästan swapanvändningen.

<Info>

Vi mätte detta på Ayakaleaf Pro 6.3.1 med Toolkit, i en QEMU/KVM-VM med 2 vCPU / 2 GiB som kör Ubuntu 24.04, med sandlådekompilering (`texlive-basic:2025.1`) och Git-integration aktiverade.

</Info>

## Varför 2 GB inte räcker som standard {#why-2-gb-is-not-enough-by-default}

I viloläge med standardinställningarna behöver Ayakaleaf Pro cirka 1,9 GiB. Ubuntu och Docker använder redan 364 MiB av en maskin med 2 GiB, vilket lämnar cirka 1600 MiB.

| Komponent            | Minne i viloläge | Anmärkningar                                                       |
| -------------------- | ----------- | ----------------------------------------------------------- |
| 12 Node.js-processer | 1620 MiB    | `web` och `web-api` cirka 255 MiB vardera, övriga 85–150 MiB |
| Git-integration      | 135 MiB     | Java tar halva minnet, 1 GiB, som maximal heap      |
| MongoDB 8.0          | 125 MiB     | dess cache kan växa till cirka 512 MiB                         |
| Redis 7.4            | 30 MiB      |                                                             |

## 1. Lägg till 2 GB swap {#1-add-2-gb-of-swap}

Detta är det viktigaste steget.

```bash
sudo fallocate -l 2G /swapfile && sudo chmod 600 /swapfile
sudo mkswap /swapfile && sudo swapon /swapfile
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab
```

## 2. Minska minnesanvändningen {#2-lower-memory-use}

Lägg till de här raderna i `config/variables.env`. Git-integrationens container läser också den här filen.

```bash title="variables.env"
NODE_OPTIONS=--require /overleaf/.pnp.cjs --import /overleaf/.pnp.register.mjs --max-semi-space-size=1
MALLOC_ARENA_MAX=2
JAVA_TOOL_OPTIONS=-Xmx160m -XX:+UseSerialGC
```

För att begränsa MongoDB-cachen lägger du till en `mongo`-post under `services` i `config/docker-compose.override.yml` (samma fil som anger Ayakaleaf Pro-avbildningen):

```yml title="docker-compose.override.yml"
services:
    mongo:
        command: "--replSet overleaf --wiredTigerCacheSizeGB 0.25"
```

Kör sedan `bin/up -d`.

| Inställning                                       | Effekt                                                         |
| --------------------------------------------- | -------------------------------------------------------------- |
| `--max-semi-space-size=1`                     | Node.js-processerna använder totalt 470 MiB mindre; kompileringstiderna är oförändrade |
| `MALLOC_ARENA_MAX=2`                          | Node.js-processerna använder totalt 65 MiB mindre                     |
| `JAVA_TOOL_OPTIONS=-Xmx160m -XX:+UseSerialGC` | Git-integrationens heap begränsas till 160 MiB i stället för 1 GiB |
| `--wiredTigerCacheSizeGB 0.25`                | MongoDB-cachen begränsas till 256 MiB i stället för cirka 512 MiB |

<Warning>

`NODE_OPTIONS` ersätter värdet som anges i avbildningen, så raden måste behålla `--require /overleaf/.pnp.cjs --import /overleaf/.pnp.register.mjs`. Utan dem kan Node.js-tjänsterna inte läsa in sina paket och startar inte. `--optimize-for-size` kan inte användas: Node.js avvisar det i `NODE_OPTIONS`.

`--replSet overleaf` är vad Toolkit skickar till MongoDB som standard. Behåll det.

</Warning>

Med en heap på 160 MiB kan kloning eller push av ett stort projekt via Git få slut på minne, och Git-integrationens container startar om. Vi har inte testat detta. Om det händer, höj `-Xmx`.

## Resultat {#results}

Varje test kompilerade ett 33 sidor långt LuaLaTeX-dokument med `fontspec` och 30 TikZ-figurer; samtidiga kompileringar gällde olika projekt.

| Konfiguration                         | 1 kompilering | 2 samtidigt                 | 3 samtidigt | Högsta swapanvändning |
| ----------------------------- | --------- | ------------------------- | --------- | ------------- |
| Standard, ingen swap              | minnet tar slut vid start | | |      |
| Endast steg 2, ingen swap          | 21 s      | `web` dödad, 502-fel  | inte testat |              |
| Endast steg 1                   | 21 s      | 23 s                      | 36 s      | 1267 MiB      |
| Steg 1 och 2                 | 22 s      | 23 s                      | 33 s      | 743 MiB       |

Utan swap leder en avslutning på grund av minnesbrist till nästa: `web` startar om, starten kräver minne igen och servern hänger sig tills en hård återställning. Med swap tar tre samtidiga kompileringar ungefär lika lång tid som en, eftersom det som hamnar i swap är inaktiva Node.js-sidor.

Inte testat: belastning från Git-kloning och push, många användare som redigerar samtidigt och swap på långsamma diskar (vår värd använde en SSD).

## Kubernetes {#kubernetes}

Vår Kubernetes-guide stänger av swap på noderna ([Förbered noderna](/sv/on-premises/installation/using-kubernetes/0.-prepare-the-nodes)), så där gäller bara steg 2. Lägg `NODE_OPTIONS` och `MALLOC_ARENA_MAX` i ConfigMap `overleaf-env` ([Anpassa din instans](/sv/on-premises/installation/using-kubernetes/4.-personalizing-your-instance)). MongoDB-cachen är redan inställd i [Driftsätt MongoDB och Redis](/sv/on-premises/installation/using-kubernetes/3.-deploy-mongodb-and-redis).
