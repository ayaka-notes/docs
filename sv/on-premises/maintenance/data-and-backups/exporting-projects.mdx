---
title: Exportera projekt
icon: file-export
---

I Server Pro och Community Edition `5.4.0` har vi inkluderat ett skript som låter administratörer exportera alla användarprojekt (inklusive de som fortfarande syns i mapparna **Deleted** och **Trashed**) till en katalog på disken.

<Info>

Resultatet av att köra skriptet är detsamma som att manuellt ladda ner en Zip-fil med alla projekt från användarens projektöversikt. Skriptet tömmer alla väntande ändringar innan nedladdningen startar för att säkerställa att exporten innehåller den senaste versionen av projektet.

</Info>

### Begränsningar

Exportskriptet har följande begränsningar:

* Inga projektinställningar, som namnet på TeX Live-imagen eller kompilatorn, exporteras. Dessa måste ställas in när projektet laddas upp till användarens konto.
* Exporterade projekt innehåller ingen versionshistorik.
* Ingen information om medarbetare bevaras. Projekten måste delas igen. Om länkdelning används genereras visnings- och redigeringslänkarna på nytt (de blir inte desamma som tidigare).
* Kommentarer och information om spårade ändringar exporteras inte.
* Projektets chatthistorik exporteras inte.

<Danger>

Skriptet är **inte** utformat för att ersätta en fullständig systemsäkerhetskopia. För att säkerställa att du kan återställa din instans vid en katastrof rekommenderar vi **starkt** att du tar en [konsekvent säkerhetskopia](https://docs.overleaf.com/on-premises/maintenance/#performing-a-consistent-backup).

</Danger>

### **Flaggor**

| Namn           | Beskrivning                                                                     |
| -------------- | ------------------------------------------------------------------------------- |
| `--help`       | Visa hjälp                                                                      |
| `--user-id`    | Användar-ID (krävs om inte `--export-all` eller `--project-id` används)         |
| `--project-id` | Exportera ett enskilt projekt (**kan inte** användas med `--user-id` eller `--export-all`) |
| `--list`       | Lista användarens projekt (**kan inte** användas med `--output`)                |
| `--output`     | Zip-fil för utdata (för enskilda exportåtgärder)                                |
| `--export-all` | Exportera alla användares projekt (kräver `--output-dir`)                       |
| `--output-dir` | Katalog där alla användares exportfiler lagras                                  |
| `--log-level`  | Loggnivåer som stöds: `trace`\|`debug`\|`info`\|`warn`\|`error`\|`fatal`        |

### **Användning**

Använd följande kommando för att exportera projekt för alla användare:

```bash wrap
# Overleaf Toolkit users
$ bin/docker-compose exec sharelatex /bin/bash -ce "cd /overleaf/services/web && node modules/server-ce-scripts/scripts/export-user-projects.mjs --export-all --output-dir=/var/lib/overleaf/data/exports"

# Legacy docker-compose.yml users
docker exec sharelatex /bin/bash -ce "cd /overleaf/services/web && node modules/server-ce-scripts/scripts/export-user-projects.mjs --export-all --output-dir=/var/lib/overleaf/data/exports"
```

<Info>

Om du kör Server Pro eller Community Edition &lt;= 3.5.13 behöver du ändra exemplet ovan så att skriptet **`export-legacy-user-projects.js`** används.

</Info>

### **Slutförande**

När exporten är klar kan du komma åt filerna via den katalog på värddatorn som är bind-monterad till **/var/lib/overleaf** i din **docker-compose.yml**-fil, eller via miljövariabeln `OVERLEAF_DATA_PATH` i filen **config/overleaf.rc** om du använder Toolkit.

<Info>

Overleaf tillåter för närvarande dubbletter av projektnamn. Om en användare har projekt med samma namn läggs de ändå till i användarens Zip-export, men vid uppackning finns bara en version kvar. På Linux skriver `unzip -B` filer med samma namn som säkerhetskopior i stället för att skriva över dem.

</Info>
