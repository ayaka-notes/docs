Arbeta med ett projekt på din egen dator med Git. Ändringar överförs bara när du kör `git pull` eller `git push`.

<Info>

En administratör måste först aktivera [Git-integrationen](/sv/on-premises/configuration/overleaf-toolkit/integrations/git-integration).

</Info>

## Skapa en token {#create-a-token}

Git loggar in med en Git-autentiseringstoken, inte med lösenordet till ditt konto.

<Steps>
<Step title="Öppna dina kontoinställningar">
Klicka på **Account** och sedan på **Account settings**. Under **Git integration** klickar du på **Generate token**. När du har en token heter knappen **Add another token**.

<Frame caption="Git-integration i kontoinställningarna">
  <img src="/images/on-premises/git-integration-settings.png" alt="Avsnittet Git integration i kontoinställningarna med knappen Generate token" />
</Frame>
</Step>

<Step title="Kopiera token">
Klicka på **Copy** och förvara token på ett säkert ställe. Du ser den bara en gång. Klicka sedan på **Close**.

<Frame caption="Din nya token">
  <img src="/images/on-premises/git-integration-token.png" alt="Dialogrutan för Git-autentiseringstoken med knappen Copy" />
</Frame>
</Step>

<Step title="Kontrollera token">
Listan visar nu början av token, när den skapades och när den senast användes. Den upphör att gälla efter ett år. Du kan ha upp till 10 tokens.

<Frame caption="Dina tokens">
  <img src="/images/on-premises/git-integration-tokens.png" alt="Listan med tokens med en token" />
</Frame>
</Step>
</Steps>

## Klona ett projekt {#clone-a-project}

<Steps>
<Step title="Öppna Git-integrationen i redigeraren">
Öppna projektet. Klicka på **Integrations** i vänstra fältet och sedan på **Git integration**.

<Frame caption="Panelen Integrations">
  <img src="/images/on-premises/git-integration-panel.png" alt="Panelen Integrations med kortet Git integration" />
</Frame>
</Step>

<Step title="Kopiera kommandot">
Dialogrutan **Clone with Git** visar kommandot, med adressen till din webbplats och projektets ID. Klicka på **Copy**. Om du inte har någon token ännu öppnar **Go to settings** dina kontoinställningar i en ny flik.

<Frame caption="Klonkommandot">
  <img src="/images/on-premises/git-integration-clone.png" alt="Dialogrutan Clone with Git med kommandot git clone" />
</Frame>
</Step>

<Step title="Kör det">
Klistra in kommandot i en terminal. När Git ber om ett lösenord klistrar du in din token.

```text
$ git clone https://git@<your-site>/git/<project-id>
Cloning into '<project-id>'...
Password for 'https://git@<your-site>': <your-token>
```

En mapp med projektets ID som namn innehåller nu projektets filer, på grenen `main`. Om du vill välja mappens namn lägger du till det i slutet av kommandot.
</Step>
</Steps>

Git frågar efter token varje gång den kontaktar webbplatsen. För att den ska kommas ihåg aktiverar du en credential helper: Git frågar en gång till och behåller sedan token. Helpern `store` sparar den okrypterad i `~/.git-credentials`.

```bash
git config --global credential.helper store
```

## Hämta ändringar från redigeraren {#pull-changes-from-the-editor}

Kör följande i mappen:

```bash
git pull
```

Git listar de filer som har ändrats. Ändringar som gjorts i redigeraren kommer som commits med namnet `Update on Overleaf.`.

```text
Updating db007e3..c3e6332
Fast-forward
 main.tex | 2 +-
 1 file changed, 1 insertion(+), 1 deletion(-)
```

## Skicka dina ändringar {#push-your-changes}

Gör commit av dina ändringar och skicka dem sedan:

```bash
git add main.tex
git commit -m "Add a line from Git"
git push
```

Den sista raden i utdata visar grenen som flyttades:

```text
   53aca61..db007e3  main -> main
```

Ändringarna visas i redigeraren, och en öppen redigerare uppdateras av sig själv. Nya filer, mappar och namnbyten visas i filträdet. I **History** är din ändring markerad som <strong>You (via Git)</strong>. Ditt commit-meddelande visas inte där.

### Om Git avvisar din push {#if-git-refuses-your-push}

Om projektet har ändrats under tiden avvisar Git din push:

```text
 ! [rejected]        main -> main (fetch first)
```

Hämta först de ändringarna och skicka sedan igen:

```bash
git pull --no-rebase --no-edit
git push
```

En vanlig `git pull` kan stanna med `fatal: Need to specify how to reconcile divergent branches.` Alternativet `--no-rebase` ovan löser det: det sammanfogar båda sidorna.

Om samma rader har ändrats på båda sidor stannar pull med `CONFLICT (content): Merge conflict in main.tex`. Rätta filen och kör sedan:

```bash
git add main.tex
git commit -m "Merge the changes from the editor"
git push
```

Det finns två saker som webbplatsen inte accepterar:

* Andra grenar: `! [remote rejected] feature -> feature (wrong branch)`. Bara `main` finns, så skicka ditt arbete dit.
* Force push: `! [remote rejected] main -> main (forced push prohibited)`. Lägg i stället dina ändringar ovanpå nuvarande `main`.

### Om Git säger Authentication failed {#if-git-says-authentication-failed}

```text
remote: Enter your Git authentication token when prompted for a password.
fatal: Authentication failed for 'https://<your-site>/git/<project-id>/'
```

Token är fel eller har tagits bort, eller så angav du lösenordet till ditt konto. Skapa en ny token om du inte längre har den, eftersom du inte kan se en befintlig token igen.

## Ta bort en token {#delete-a-token}

I **Account settings**, under **Git integration**, klickar du på borttagningsikonen bredvid token och sedan på **Delete** i dialogrutan. Därefter svarar Git `Authentication failed` på den token.
