### Konfigurera GitHub-synkronisering

<Warning>

Du måste aktivera [git-bridge](/sv/on-premises/configuration/overleaf-toolkit/git-integration) innan du kan använda GitHub-synkronisering.

```dotenv title="config/overleaf.rc"
GIT_BRIDGE_ENABLED=true
```

</Warning>

Gå till [utvecklarinställningarna](https://github.com/settings/developers) för att skapa din GitHub OAuth-applikation och kopiera ditt `CLIENT_ID` och `SECRET`.

**Obs!** När du skapar OAuth-appen anger du `${OVERLEAF_SITE_URL}/user/github-sync/oauth2/callback` i **Authorization callback URL**. Ayakaleaf Pro bygger samma adress utifrån `OVERLEAF_SITE_URL`, så det finns inget att ange för den i `config/variables.env`.

Lägg sedan till följande inställningar i dina filer med miljövariabler för Overleaf.

```dotenv title="config/variables.env" wrap
# used to encrypt the user's GitHub access token.
# How to generate: `openssl rand -hex 32`
GITHUB_TOKEN_CIPHER_PASSWORD=0123456789ABCDEFG # changed to yours

# Github Sync Settings
GITHUB_SYNC_ENABLED=true
GITHUB_SYNC_CLIENT_ID=
GITHUB_SYNC_CLIENT_SECRET=

# OAuth callback is: ${OVERLEAF_SITE_URL}/user/github-sync/oauth2/callback
# (Optional) GITHUB_SYNC_PROXY_URL=http://10.0.0.1:10808
```

<Warning>

Kontrollera att `OVERLEAF_SITE_URL` är korrekt angiven innan du konfigurerar callback-URL:en för GitHub OAuth.

</Warning>

Om du befinner dig i en region med begränsad nätverksåtkomst kan du behöva konfigurera en proxy för att nå GitHub. Ange följande miljövariabel: `GITHUB_SYNC_PROXY_URL=http://10.0.0.1:10808`. Se till att din användning av en proxy följer lokala lagar och föreskrifter.

<Warning>

`GITHUB_SYNC_PROXY_URL` måste vara en vanlig HTTP/HTTPS-framåtproxy (till exempel HTTP-porten i Clash). GitHub-nedladdningsspeglar som `gh-proxy.org` stöds inte.

</Warning>

<Warning>

Använd inte `127.0.0.1` som proxyvärd. Om proxyn körs på värdservern använder du serverns LAN-IP-adress (till exempel `192.168.1.xx`) och ser till att proxyn är konfigurerad att ta emot anslutningar från enheter i det lokala nätverket.

</Warning>

### GitHub Enterprise

<Info>

Stöd för GitHub Enterprise introducerades i v6.3.1 och finns i senare versioner. Tidigare versioner ansluter bara till `github.com`, och variablerna nedan har ingen effekt.

</Info>

Som standard ansluter GitHub-synkronisering till `github.com`. För att använda GitHub Enterprise Server (egen drift) eller GitHub Enterprise Cloud med datalagringsplats (`GHE.com`) anger du `GITHUB_SYNC_URL` till webbadressen för din instans, den du öppnar repositorier med i webbläsaren.

```dotenv title="config/variables.env" wrap
# GitHub Enterprise Server
GITHUB_SYNC_URL=https://github.example.com

# or GitHub Enterprise Cloud with data residency
# GITHUB_SYNC_URL=https://octocorp.ghe.com
```

Ändpunkterna för REST- och GraphQL-API:erna härleds från `GITHUB_SYNC_URL` på samma sätt som GitHub CLI gör:

| `GITHUB_SYNC_URL`             | REST-API                         | GraphQL-API                              |
| ----------------------------- | -------------------------------- | ---------------------------------------- |
| `https://github.com` (standard) | `https://api.github.com`         | `https://api.github.com/graphql`         |
| `https://SUBDOMAIN.ghe.com`   | `https://api.SUBDOMAIN.ghe.com`  | `https://api.SUBDOMAIN.ghe.com/graphql`  |
| `https://HOST` (alla andra)    | `https://HOST/api/v3`            | `https://HOST/api/graphql`               |

Ange bara API-ändpunkterna när din instans tillhandahåller dem någon annanstans, till exempel bakom en API-gateway:

| Variabel                  | Standard                                                                                   |
| ------------------------- | ----------------------------------------------------------------------------------------- |
| `GITHUB_SYNC_URL`         | `https://github.com`                                                                      |
| `GITHUB_SYNC_API_URL`     | Härleds från `GITHUB_SYNC_URL`, se tabellen ovan                                       |
| `GITHUB_SYNC_GRAPHQL_URL` | Härleds från `GITHUB_SYNC_API_URL` när den är angiven (`/api/v3` blir `/api/graphql`, annars läggs `/graphql` till), i annat fall från `GITHUB_SYNC_URL` |

<Warning>

* Skapa OAuth-applikationen på din enterprise-instans (_Settings → Developer settings → OAuth Apps_), en applikation från `github.com` fungerar inte där. Callback-URL:en är densamma: `${OVERLEAF_SITE_URL}/user/github-sync/oauth2/callback`.
* `GITHUB_SYNC_URL` är endast webbadressen. Ange den inte till en API-adress som `https://api.github.com` eller `https://HOST/api/v3`, och lägg inte till en organisationssökväg.
* Alla tre adresserna måste peka på samma GitHub-instans.

</Warning>

<Info>

Om din instans använder ett certifikat från en privat CA monterar du CA-certifikatet i containern och låter `NODE_EXTRA_CA_CERTS` peka på det, t.ex. `NODE_EXTRA_CA_CERTS=/var/lib/overleaf/certs/github-ca.pem`.

</Info>

<Danger>

Länkade konton och projekt hör till den instans de länkades med. Be användarna att avlänka sitt GitHub-konto och sina projekt innan du byter `GITHUB_SYNC_URL` till en annan instans.

</Danger>

### Vem kan länka och synkronisera

Precis som på Overleaf Cloud kan endast projektägaren länka ett projekt till ett GitHub-repositorium. När det väl är länkat kan alla medarbetare med redigeringsbehörighet synkronisera det.

| Åtgärd                                                     | Vem kan utföra den                                             |
| ---------------------------------------------------------- | -------------------------------------------------------------- |
| Exportera ett projekt till ett nytt GitHub-repositorium    | Projektägaren                                                  |
| Importera ett GitHub-repositorium till ett nytt projekt    | Alla användare, som då blir ägare till det nya projektet       |
| Hämta, pusha och slå samman ett länkat projekt             | Ägaren och medarbetare med redigeringsbehörighet               |
| Avlänka ett projekt från dess repositorium                 | Projektägaren                                                  |

* Overleaf kommunicerar med GitHub via GitHub-kontot för den användare som synkroniserar, så varje medarbetare som synkroniserar länkar sitt eget GitHub-konto och måste ha behörighet att pusha till repositoriets standardgren.
* Medarbetare med endast läsbehörighet kan inte använda GitHub-synkronisering för projektet.

### Q\&A

<Accordion title="Kan jag force-pusha till standardgrenen?">

<strong>Svar:</strong> Vi rekommenderar det inte. Overleaf upptäcker en force push, varnar för den och tar över den omskrivna grenen genom att slå samman de ändringar som gjorts i Overleaf sedan den senaste synkroniseringen. För att undvika överraskningar bör du skydda standardgrenen mot force pushes i repositoriets inställningar.

</Accordion>

<Accordion title="Kan jag byta namn på standardgrenen i ett länkat projekt?">

<strong>Svar:</strong> Gör inte det. Overleaf fortsätter att synkronisera med den gren som projektet länkades till. För att synkronisera med en annan gren avlänkar du projektet och importerar sedan repositoriet till ett nytt projekt, som då använder den aktuella standardgrenen.

</Accordion>

<Accordion title='GitHub-synkroniseringen visar "Something wrong with GitHub request"'>

<strong>Svar:</strong> Meddelandet innebär att servern inte kunde nå GitHub, till exempel på grund av ett nätverks-, DNS-, TLS- eller proxyproblem. Kör `bin/logs web` för att se hela felet. Om servern behöver en proxy för att nå GitHub anger du `GITHUB_SYNC_PROXY_URL`.

</Accordion>

<Accordion title='Ska jag inaktivera "Expire user access tokens" i GitHub OAuth-appen?'>

<strong>Svar:</strong> Ja. GitHub-synkroniseringen förnyar inte utgångna tokens. Med tokens som löper ut aktiverat måste användarna ansluta GitHub igen varje gång deras token går ut.

</Accordion>

<Accordion title="Måste min instans vara nåbar från internet?">

<strong>Svar:</strong> Nej. Länkningen av ett konto går via användarens webbläsare, så OAuth-callback-adressen behöver bara kunna öppnas i användarens webbläsare. Servern behöver bara kunna nå GitHub; om den behöver en proxy för det anger du `GITHUB_SYNC_PROXY_URL`. GitHub anropar aldrig din instans: ett projekt synkroniseras bara när en användare synkroniserar det i redigeraren.

</Accordion>
