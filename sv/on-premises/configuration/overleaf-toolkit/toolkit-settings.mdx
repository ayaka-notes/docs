Den här sidan beskriver de miljövariabler som stöds i filen `config/overleaf.rc` för Toolkit-driftsättningar.

Filen `config/overleaf.rc` består av variabeldefinitioner på formen `NAME=value`. Rader som börjar med `#` behandlas som kommentarer.

<Info>

Du måste återskapa Docker-containrarna genom att köra `bin/up` efter att du har ändrat något i `overleaf.rc` eller `variables.env`.

</Info>

## Containrar

### `sharelatex`

| Namn                         | Beskrivning                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| ---------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `PROJECT_NAME`               | <p>Anger värdet för flaggan `--project-name` som skickas till `docker-compose`. Detta är användbart när flera instanser av Overleaf körs på samma värd, eftersom varje instans kan ha ett eget projektnamn.<br /><br />- <strong>Standard</strong>: `overleaf`</p>                                                                                                                                                                                                                                                 |
| `OVERLEAF_IMAGE_NAME`        | <p>Docker-avbildningen som används av applikationscontainern för Server Pro/CE. Detta är bara namnet på Docker-avbildningen; taggen för Docker-avbildningen hämtas från `config/version`.<br /><br />- <strong>Standard:</strong><br />- Server Pro: `quay.io/sharelatex/sharelatex-pro`<br />- Community Edition: `sharelatex/sharelatex`</p>                                                                                                                                                                                                 |
| `SERVER_PRO`                 | <p>När den är satt till `true` använder Toolkit Server Pro-avbildningen (`quay.io/sharelatex/sharelatex-pro`) i stället för standardavbildningen för Server CE (`sharelatex/sharelatex`).<br /><br />- <strong>Standard</strong>: `false`</p>                                                                                                                                                                                                                                                                   |
| `GIT_BRIDGE_ENABLED`         | <p>Ange `true` för att aktivera funktionen git-bridge (endast Server Pro). Mer information finns i användardokumentationen <a href="https://www.overleaf.com/learn/how-to/Git_integration">https://www.overleaf.com/learn/how-to/Git_integration</a>.<br /><br />- <strong>Standard:</strong> `false`</p>                                                                                                                                                                                                                        |
| `GIT_BRIDGE_IMAGE`           | <p>Docker-avbildningen som används av git-bridge-containern (endast Server Pro). Detta är bara namnet på Docker-avbildningen; taggen för Docker-avbildningen hämtas från `config/version`.<br /><br />- <strong>Standard:</strong> `quay.io/sharelatex/git-bridge`</p>                                                                                                                                                                                                                                                                              |
| `GIT_BRIDGE_DATA_PATH`       | Anger sökvägen till katalogen som monteras i containern `git-bridge` (endast Server Pro) och används för att lagra git-repositoryn. Detta kan vara antingen en fullständig sökväg (som börjar med `/`) eller en sökväg relativ till Toolkits baskatalog.                                                                                                                                                                                                                                                                                     |
| `GIT_BRIDGE_LOG_LEVEL`       | <p>Konfigurerar loggnivån för containern `git-bridge`. Tillgängliga nivåer: `TRACE`, `DEBUG`, `INFO`, `WARN`, `ERROR`.<br /><br />- <strong>Standard:</strong> `INFO`</p>                                                                                                                                                                                                                                                                                       |
| `SIBLING_CONTAINERS_ENABLED` | <p>När den är satt till `true` använder Toolkit tekniken <strong>Sibling Containers</strong> för att kompilera projekt i separata sandlådor, med en separat Docker-container för varje projekt. Se dokumentationen &#x3C;server-pro-only-configuration/sandboxed-compiles> för mer information.<br /><br />- <strong>Kräver:</strong> `SERVER_PRO=true`<br />- <strong>Standard:</strong> `true`</p>                                                                                                    |
| `SIBLING_CONTAINERS_PULL`    | <p>När den är satt till `true` hämtar Toolkit automatiskt alla TeX Live-avbildningar som anges med `ALL_TEX_LIVE_DOCKER_IMAGES` i filen <strong>config/variables.env</strong> när kommandot `bin/up` används.<br /><br />- <strong>Standard:</strong> `true`</p>                                                                                                                                                                                                                                      |
| `DOCKER_SOCKET_PATH`         | <p>Anger sökvägen till Docker-socketen på värddatorn (datorn som kör Toolkit). När `SIBLING_CONTAINERS_ENABLED` är `true` monteras socketen i containern så att kompileringstjänsten kan starta nya Docker-containrar på värden.<br /><br />- <strong>Kräver:</strong> `SIBLING_CONTAINERS_ENABLED=true`<br />- <strong>Standard:</strong> `/var/run/docker.sock`</p>                                                                                               |
| `OVERLEAF_DATA_PATH`         | <p>Anger sökvägen till katalogen som monteras i huvudcontainern `sharelatex` och används för att lagra kompileringsdata. Detta kan vara antingen en fullständig sökväg (som börjar med `/`) eller en sökväg relativ till Toolkits baskatalog.<br /><br />- <strong>Standard:</strong> `data/overleaf`</p>                                                                                                                                                                                                               |
| `OVERLEAF_LISTEN_IP`         | <p>Anger den eller de IP-adresser på värden som containern binder till. Om detta till exempel är satt till `0.0.0.0` blir webbgränssnittet tillgängligt på alla värdens IP-adresser. För direkt åtkomst till containern måste `OVERLEAF_LISTEN_IP` sättas till din offentliga IP-adress. Att sätta `OVERLEAF_LISTEN_IP` till antingen `0.0.0.0` eller värdens externa IP-adress orsakar vanligtvis fel när det används tillsammans med .<br /><br />- <strong>Standard:</strong> `127.0.0.1`</p> |
| `OVERLEAF_PORT`              | <p>Anger den port på värden som containern binder till. Om detta till exempel är satt till `8099` och `OVERLEAF_LISTEN_IP` är satt till `127.0.0.1` blir webbgränssnittet tillgängligt på `http://localhost:8099`.<br /><br />- <strong>Standard:</strong> `80`</p>                                                                                                                                                                                                                        |
| `OVERLEAF_LOG_PATH`          | <p>Anger sökvägen till katalogen som monteras i huvudcontainern `sharelatex` och används för att göra applikationsloggar tillgängliga på Docker-värden. Detta kan vara antingen en fullständig sökväg (som börjar med `/`) eller en sökväg relativ till Toolkits baskatalog. Ta bort konfigurationsposten för att inaktivera bind-monteringen. Om den inte är satt kasseras loggarna när containern återskapas.<br /><br />Se för information om loggning.<br /><br />- <strong>Standard:</strong> not set</p>                                 |

### `mongo`

| Namn              | Beskrivning                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| ----------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `MONGO_ENABLED`   | <p>När den är satt till `true` skapar Toolkit en MongoDB-container som är värd för databasen. När den är satt till `false` skapas inte denna container, och systemet använder i stället den MongoDB-databas som anges i `MONGO_URL`.<br /><br />- <strong>Standard</strong>: `true`</p>                                                                                                                                 |
| `MONGO_URL`       | <p>Anger den MongoDB-anslutnings-URL som ska användas när `MONGO_ENABLED` är `false`.<br /><br />- <strong>Standard</strong>: inte satt</p>                                                                                                                                                                                                                                                                                                           |
| `MONGO_DATA_PATH` | <p>Anger sökvägen till katalogen som monteras i containern `mongo` och används för att lagra MongoDB-databasen. Detta kan vara antingen en fullständig sökväg (som börjar med `/`) eller en sökväg relativ till Toolkits baskatalog. Det här alternativet påverkar endast den lokala containern `mongo` som skapas när `MONGO_ENABLED` är `true`.<br /><br />- <strong>Standard</strong>: `data/mongo`</p> |
| `MONGO_IMAGE`     | <p>Docker-avbildningen som används av MongoDB-containern. Detta är bara namnet på Docker-avbildningen; taggen för Docker-avbildningen ska anges i `MONGO_VERSION` (se nedan).<br /><br />- <strong>Standard:</strong> `mongo`</p>                                                                                                                                                                                                                             |
| `MONGO_VERSION`   | <p>MongoDB-versionen som används av MongoDB-containern. Värdet måste börja med MongoDB:s huvudversion och en punkt, t.ex. `6.0` eller `6.0-with-suffix`.<br /><br />- <strong>Standard:</strong> `6.0`</p>                                                                                                                                                                                                                             |

### `nginx`

| `TLS_PRIVATE_KEY_PATH` | <p>Sökväg till den privata nyckel som ska användas för TLS-proxyn.<br /><br />- <strong>Standard</strong>: `config/nginx/certs/overleaf_key.pem`</p>                                                                                                                                                                                                                                                                                                                                                      |
