Du kan använda skriptet `bin/logs` för att visa loggar för tjänsterna.

Grundläggande användningsexempel:

```bash
# View the web service logs
bin/logs web

# Show help
bin/logs --help

# View logs for multiple services at once
bin/logs filestore docstore web clsi

# Follow log output (like tail -f)
bin/logs -f filestore docstore web clsi

# Limit the number of lines printed (default 50)
bin/logs -n 50 web

# Show all log lines
bin/logs -n all web

# Redirect output to a file
bin/logs -n all web > web.log
```

Du kan använda skriptet `bin/logs` för att visa loggar för följande tjänster: `clsi`, `contacts`, `docstore`, `document-updater`, `filestore`, `git-bridge`, `mongo`, `notifications`, `real-time`, `redis`, `spelling`, `tags`, `track-changes`, `web`, `web-api`, `history-v1`, `project-history`.

## Kopiera loggar

Se den ursprungliga dokumentationen: https://docs.overleaf.com/on-premises/configuration/overleaf-toolkit/logging#copying-logs

Kopiera loggfiler från huvudcontainern `sharelatex` till din lokala dator:

```bash
docker cp sharelatex:/var/log/overleaf/{service-name}.log {service-name}.log
```

## Spara loggar permanent

Docker-containrar är tillfälliga, vilket innebär att filer och kataloger som skapas i containern under körning (inklusive loggfiler) försvinner om containern återskapas (till exempel när du kör `bin/up`). För att behålla loggfiler när containrar återskapas:

* Ange miljövariabeln `OVERLEAF_LOG_PATH` i filen `config/overleaf.rc` som används av Toolkit. Detta ska vara katalogen på värden som bind-monteras till loggkatalogen inuti containern `sharelatex`.
* När du har ändrat detta och kört `bin/up -d` sparas loggfilerna permanent på värden och är direkt åtkomliga.

<Warning>

Du måste ange användaren `www-data` (uid=33) som ägare till loggkatalogen på värden som används för bind-monteringen och se till att behörigheterna är `drwxr-xr-x` (755).

Exempel:

```bash
chown 33:33 data/overleaf/logs
chmod 755 data/overleaf/logs
```

</Warning>
