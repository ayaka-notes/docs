Du kan öppna din Overleaf-instans för personer utan konto på tre sätt:

* [Projektåtkomst](/sv/on-premises/configuration/overleaf-toolkit/public-access#project-access  "mention"): låt gäster öppna en delad projektlänk utan att logga in
* [Sidåtkomst](/sv/on-premises/configuration/overleaf-toolkit/public-access#page-access  "mention"): låt utloggade besökare bläddra bland sidor som `/learn`, `/templates` och `/devs`
* [Offentlig registrering](/sv/on-premises/configuration/overleaf-toolkit/public-access#public-registration  "mention"): låt användare registrera sig själva, eventuellt med ett aktiveringsmejl och begränsat till e-postdomäner

### Projektåtkomst

<Info>

Som standard måste en användare **logga in** innan hen kan delta i en gemensam redigeringssession för ett projekt, även om hen har fått en delningslänk till projektet.

</Info>

För att tillåta anonym åtkomst till projekt som delas via länk sätter du båda variablerna nedan:

```dotenv title="config/variables.env"
OVERLEAF_ALLOW_ANONYMOUS_READ_AND_WRITE_SHARING=true
OVERLEAF_ALLOW_PUBLIC_ACCESS=true
```

`OVERLEAF_ALLOW_ANONYMOUS_READ_AND_WRITE_SHARING` aktiverar anonym läs- och skrivåtkomst till projekt som delas via länk.

`OVERLEAF_ALLOW_PUBLIC_ACCESS` förhindrar att oautentiserade användare omdirigeras till inloggningssidan.

Återskapa containrarna med `bin/up`. Öppna sedan en delningslänk i ett privat fönster.

### Sidåtkomst

Som standard (när `OVERLEAF_ALLOW_PUBLIC_ACCESS` inte är satt) omdirigeras utloggade besökare till inloggningssidan från **alla** sidor utom inloggnings- och registreringssidorna. Det gäller även sidor som är avsedda att vara offentliga, så länkar till dem fungerar bara för användare som redan är inloggade.

Med `OVERLEAF_ALLOW_PUBLIC_ACCESS=true` kan utloggade besökare öppna:

| Sida                                                                  | Kräver                           |
| --------------------------------------------------------------------- | -------------------------------- |
| LaTeX-hjälp på `/learn` (se [adding-latex-user-help.md](/sv/on-premises/configuration/overleaf-toolkit/adding-latex-user-help  "mention")) | `OVERLEAF_PROXY_LEARN=true`      |
| Mallgalleriet på `/templates`, mallsidor, förhandsvisningar och ZIP-nedladdningar (se [templates.md](/sv/on-premises/configuration/overleaf-toolkit/templates  "mention")) | `OVERLEAF_TEMPLATE_GALLERY=true` |
| Sidan för Overleaf Import API på `/devs` (se [overleaf-import-api.md](/sv/on-premises/configuration/overleaf-toolkit/overleaf-import-api  "mention")) | —                                |

Det gör också att [Overleaf Import API](/sv/on-premises/configuration/overleaf-toolkit/overleaf-import-api#signed-out-visitors  "mention") kan behålla ett formulär som skickats av en utloggad besökare tills hen har loggat in.

Projektlistan, editorn och att skapa projekt (även från en mall eller via Import API) kräver fortfarande inloggning.

### Offentlig registrering

Offentlig registrering finns bara i [ayaka-notes/ayakaleaf-pro](https://github.com/ayaka-notes/ayakaleaf-pro).

<Danger>

Observera att när du har aktiverat offentlig registrering kan **vem som helst** med åtkomst till din Overleaf-instans registrera sig som användare.

Med `true` verifierar registreringsprocessen inte e-postadresser, så använd den bara i ett intranät eller i en betrodd miljö, eller använd i stället [registrering med aktiveringsmejl](/sv/on-premises/configuration/overleaf-toolkit/public-access#registrering-med-aktiveringsmejl).

På en instans med OIDC ska du inte använda `true`: vem som helst skulle kunna registrera sig med en kollegas e-postadress före kollegans första OIDC-inloggning, vilket skulle länka kollegan till det kontot. Använd [registrering med aktiveringsmejl](/sv/on-premises/configuration/overleaf-toolkit/public-access#registrering-med-aktiveringsmejl) eller ingen offentlig registrering alls, se [Konton och lösenord](/sv/on-premises/configuration/overleaf-toolkit/authentication#konton-och-lösenord).

</Danger>

Som standard tillåter varken Community Edition eller Overleaf Pro offentlig registrering.

För att aktivera den lägger du till detta i `config/variables.env`:

```dotenv title="config/variables.env"
OVERLEAF_ALLOW_PUBLIC_REGISTRATION=true
```

Återskapa containrarna med `bin/up`.

Klicka sedan på **Sign up** eller besök `/register`.

### Registrering med aktiveringsmejl

Registrering med aktiveringsmejl finns bara i [ayaka-notes/ayakaleaf-pro](https://github.com/ayaka-notes/ayakaleaf-pro). Användarna registrerar sig med enbart sin e-postadress och anger sitt lösenord via länken i aktiveringsmejlet, så att endast ägaren till en adress kan använda kontot. En lista med domäner och jokertecken kräver v6.4.0 eller senare; tidigare versioner tar bara en enda domän, som `@example.com`.

Innan du aktiverar detta måste du konfigurera e-postleverans, annars får användarna aldrig aktiveringsmejlet. Se [E-postleverans](/sv/on-premises/configuration/overleaf-toolkit/email-delivery).

Lägg sedan till följande rad i `config/variables.env`:

```dotenv title="config/variables.env" wrap
OVERLEAF_ALLOW_PUBLIC_REGISTRATION=@example.com,@*.example.org
```

`OVERLEAF_ALLOW_PUBLIC_REGISTRATION` kan sättas till:

| Värde                         | Vem kan registrera sig                                | E-post verifieras |
| ----------------------------- | ----------------------------------------------------- | :---------------: |
| `true`                        | Vem som helst, med e-postadress och lösenord          |        Nej        |
| `@example.com`                | Adresser i `example.com`                              |        Ja         |
| `@*.example.org`              | Adresser i underdomäner som `cs.example.org`, inte i själva `example.org` |        Ja         |
| `@example.com,@*.example.org` | Någon av de listade posterna, separerade med kommatecken |        Ja         |
| `@*`                          | Vem som helst                                         |        Ja         |

Domäner matchas utan hänsyn till skiftläge. För att tillåta en domän och dess underdomäner listar du båda: `@example.org,@*.example.org`.

### Q\&A

<Accordion title="Vad kan en utloggad redaktör göra med kommentarer?">

<strong>Svar:</strong> En utloggad användare som öppnar ett projekt via dess redigeringslänk får samma åtkomst som en redaktör, förutom för åtgärder som registrerar vem som utförde dem:

| Åtgärd                                                    | Utloggad redaktör |
| --------------------------------------------------------- | ----------------: |
| Redigera texten, visa kommentarer och spårade ändringar   |                Ja |
| Godkänna spårade ändringar, byta redigeringsläge          |                Ja |
| Ta bort en kommentar eller en hel tråd                    |                Ja |
| Lägga till, svara på eller redigera en kommentar          |               Nej |
| Lösa eller öppna en kommentar igen                        |               Nej |

Granskningspanelen visar fortfarande knappen **Resolve** för dem, men lösningen misslyckas med ett felmeddelande.

Användare som öppnar ett projekt via dess visningslänk ser inga kommentarer alls, se [Roller och behörigheter](/sv/on-premises/user-and-project-management/roles-and-permissions#collaborating).

</Accordion>
