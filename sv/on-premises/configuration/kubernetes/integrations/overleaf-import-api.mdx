Import API:t (`/docs` och knapparna ”Open in Ayakaleaf”, modulen `open-in-overleaf`) körs i tjänsten **web** i varje Ayakaleaf Pro-pod och är påslaget som standard. Filer som anges via URL laddas ned via linked-url-proxy i samma pod. Hur du anropar det beskrivs i [Overleaf Import API](/sv/on-premises/configuration/overleaf-toolkit/integrations/overleaf-import-api).

| | |
| --- | --- |
| Tjänst | web (modulen `open-in-overleaf`); nedladdningar via linked-url-proxy |
| Utifrån → Overleaf | webbläsare gör `GET` eller `POST ${OVERLEAF_SITE_URL}/docs` från vilken webbplats som helst |
| Pod → utåt | nedladdningar via `snip_uri` och `zip_uri`, begränsade enligt beskrivningen i [Extern URL](/sv/on-premises/configuration/kubernetes/external-url) |
| Tillstånd | en utloggad besökares förfrågan, som hålls i Redis i 10 minuter tills besökaren loggar in |
| Periodiska jobb | inga |

### Konfiguration

Inget behövs för att slå på det. Relaterade inställningar i ConfigMap:en:

| Inställning | |
| --- | --- |
| `OVERLEAF_ALLOW_PUBLIC_ACCESS: "true"` | Utloggade besökare kan öppna `/devs`, och en förfrågan de skickar hålls kvar tills de loggar in, se [Offentlig åtkomst](/sv/on-premises/configuration/kubernetes/authentication/public-access). |
| `MAX_UPLOAD_SIZE` | Största ZIP-fil en förfrågan får innehålla, i MB (standard `50`). Din ingress eller lastbalanserare måste också acceptera förfrågningar av den storleken. |
| `OVERLEAF_LINKED_URL_*` | Vilka adresser `snip_uri` och `zip_uri` får peka på, se [Extern URL](/sv/on-premises/configuration/kubernetes/external-url). |

### Flera repliker

Inget extra. En utloggad besökares förfrågan hålls i Redis, så den återupptas på den replik besökaren når efter inloggningen.

### Testat på Kubernetes

På Kubernetes 1.37 med en replik klarar våra end-to-end-tester för Import API:t sig (14 fall): sidan `/devs` och dess exempelprojekt, utdrag, kompletta dokument, URL-kodade länkar och filer från data-URL:er som blir projekt, inskick som inte kan bli ett projekt avvisas, nedladdningar från interna adresser avvisas, inlägg och länkar från utloggade besökare bevaras genom inloggningen samt, med `OVERLEAF_ALLOW_PUBLIC_ACCESS`, `/devs` för utloggade besökare och ett inskickat utdrag som återupptas en gång efter inloggning; det sista fallet klarar sig även på tre repliker bakom HAProxy.
