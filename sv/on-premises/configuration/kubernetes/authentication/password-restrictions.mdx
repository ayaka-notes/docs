Tjänsten **web** kontrollerar lokala lösenord när användare registrerar sig, anger eller ändrar ett lösenord. SSO-inloggningar (LDAP, SAML, OIDC) påverkas inte; deras lösenord hanteras av identitetsleverantören. Se [Lösenordsbegränsningar](/sv/on-premises/configuration/overleaf-toolkit/authentication/password-restrictions) för Toolkit.

| | |
| --- | --- |
| Tjänst | web, i varje Ayakaleaf Pro-pod; läses när web startar |
| Nätverk | inget |
| Periodiska jobb | inga |

### Konfiguration

Lägg till i ConfigMap `overleaf-env` och starta om:

```yaml title="30-config.yaml (additions)"
  OVERLEAF_PASSWORD_VALIDATION_MIN_LENGTH: "12"
  OVERLEAF_PASSWORD_VALIDATION_MAX_LENGTH: "72"
```

```bash
kubectl apply -f 30-config.yaml
kubectl -n overleaf rollout restart deployment/overleaf     # or statefulset/overleaf
```

| Variabel | Standard | |
| --- | --- | --- |
| `OVERLEAF_PASSWORD_VALIDATION_MIN_LENGTH` | `8` | Kortaste godtagna lösenord. |
| `OVERLEAF_PASSWORD_VALIDATION_MAX_LENGTH` | `72` | Längsta godtagna lösenord; värden över `72` behandlas som `72`. |

Citera talen: en ConfigMap innehåller bara strängar.

<Warning>

`OVERLEAF_PASSWORD_VALIDATION_PATTERN` läses men tillämpas inte: ett lösenord som inte matchar det godtas. Endast längdgränserna gäller.

</Warning>

### Flera repliker

Inget extra: varje replik läser samma ConfigMap.

### Testat på Kubernetes

På Kubernetes 1.37 med en replik, `OVERLEAF_PASSWORD_VALIDATION_MIN_LENGTH: "12"` och `OVERLEAF_PASSWORD_VALIDATION_PATTERN: aA$3` i ConfigMap, nekade aktiveringen av ett nytt konto ett lösenord på 10 tecken och godtog ett lösenord på 20 tecken med enbart gemener, vilket mönstret skulle ha nekat. Våra end-to-end-tester för registrering nekar också `123456` som för kort med standardinställningarna.
