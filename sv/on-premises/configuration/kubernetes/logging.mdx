Varje tjänst i Ayakaleaf Pro-podden skriver sin egen loggfil under `/var/log/overleaf/`; `kubectl logs` visar bara containerns uppstartsutdata (init-skript, migreringar). Toolkits `bin/logs` läser samma filer, se [Loggning](/sv/on-premises/configuration/overleaf-toolkit/logging).

| Var | Vad |
| --- | --- |
| `kubectl -n overleaf logs <pod>` | uppstart: kontroll av hemligheter, migreringar (`Finished migrations`), tjänststarter |
| `/var/log/overleaf/<service>.log` i podden | `web.log`, `web-api.log`, `clsi.log`, `real-time.log`, `document-updater.log`, `docstore.log`, `filestore.log`, `history-v1.log`, `project-history.log`, `chat.log`, `notifications.log`, `linked-url-proxy.log` och `third-party-datastore.log` när Dropbox är påslaget |
| `/var/log/nginx/` i podden | `access.log`, `error.log` för nginx framför tjänsterna |
| `kubectl -n overleaf logs mongo-0`, `redis-0`, `git-bridge-0` | MongoDB, Redis och git-bridge, som körs i egna poddar |

### Läsa loggar

| Toolkit | Kubernetes |
| --- | --- |
| `bin/logs web` | `kubectl -n overleaf exec deploy/overleaf -- tail -n 20 /var/log/overleaf/web.log` |
| `bin/logs -f web clsi` | `kubectl -n overleaf exec deploy/overleaf -- tail -f /var/log/overleaf/web.log /var/log/overleaf/clsi.log` |
| `bin/logs -n all web > web.log` | `kubectl -n overleaf cp overleaf/<pod>:/var/log/overleaf/web.log web.log` |
| `bin/logs mongo` | `kubectl -n overleaf logs mongo-0` |

Med [flera repliker](/sv/on-premises/configuration/kubernetes/horizontal-scaling) har varje pod sina egna filer: använd poddnamnet (`overleaf-0`, `overleaf-1`, ...) i stället för `deploy/overleaf`. Huvudet `X-Served-By` som HAProxy lägger till visar vilken replik som besvarade en förfrågan.

`LOG_LEVEL` i ConfigMap:en (standard `info`, även `debug`, `warn`, `error`) anger nivån för alla tjänster i podden på en gång.

### Spara loggar

Filerna finns i containern och går förlorade när podden ersätts. För att spara dem monterar du en volym på `/var/log/overleaf`, till exempel en `hostPath` på noden eller en PersistentVolumeClaim, i Deployment:en eller StatefulSet:en:

```yaml
          volumeMounts:
            # ...
            - name: logs
              mountPath: /var/log/overleaf
      volumes:
        # ...
        - name: logs
          hostPath:
            path: /srv/overleaf-logs
            type: DirectoryOrCreate
```

Containern roterar filerna dagligen och behåller fem, så volymen växer inte obegränsat. Du kan också samla in dem från den sökvägen med klustrets loggagent.

### Testat på Kubernetes

På Kubernetes 1.37 med tre repliker och en `hostPath`-volym på `/var/log/overleaf` enligt ovan innehöll varje nods `/srv/overleaf-logs` de tolv tjänstloggarna för dess replik, och kommandona i tabellen fungerade som visat: `tail` via `kubectl exec`, `kubectl cp` av en loggfil, `kubectl logs` för Overleaf-podden (uppstart och migreringar) och för `mongo-0`.
