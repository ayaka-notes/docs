### Anpassa din instans

Innan du startar din Overleaf-instans för första gången uppdaterar du två konfigurationsfiler med dina egna uppgifter:

| Fil                    | Läses av                                   | Anges här                                                         |
| ---------------------- | ------------------------------------------ | ----------------------------------------------------------------- |
| `config/overleaf.rc`   | Toolkit-skripten, till exempel `bin/up`    | hur containrarna körs: `OVERLEAF_LISTEN_IP`, `OVERLEAF_PORT`, `SERVER_PRO`, datasökvägar |
| `config/variables.env` | applikationen i containern                 | hur Overleaf beter sig: `OVERLEAF_SITE_URL`, e-post, TeX Live-images |

<Steps>
<Step title="Redigera variabelfilen">
Öppna `config/variables.env` i din favoritredigerare och uppdatera miljövariablerna nedan med de värden som krävs.
</Step>

<Step title="Lyssningsadress och port">
Som standard publicerar Toolkit webbgränssnittet på `127.0.0.1:80`, så det kan bara öppnas från en webbläsare på själva servern. Andra datorer får felet "connection refused" eller "server not found". För att ändra detta redigerar du `config/overleaf.rc`:

```bash title="config/overleaf.rc"
OVERLEAF_LISTEN_IP=0.0.0.0
OVERLEAF_PORT=8080
```

`OVERLEAF_LISTEN_IP` är den IP-adress på värden som containern binder till, och `OVERLEAF_PORT` är porten på värden. Tillsammans bildar de Docker-portmappningen `OVERLEAF_LISTEN_IP:OVERLEAF_PORT:80`. Välj de värden som passar din uppsättning:

| Uppsättning                                                                     | `OVERLEAF_LISTEN_IP`                  | `OVERLEAF_PORT`        | Öppna i webbläsaren           |
| ------------------------------------------------------------------------------- | ------------------------------------- | ---------------------- | ----------------------------- |
| Endast på den här datorn (standard)                                             | `127.0.0.1`                           | `80`                   | `http://localhost`            |
| Andra datorer i det lokala nätverket eller på internet ansluter direkt          | `0.0.0.0`, eller en av serverns IP-adresser | `80`, eller valfri ledig port | `http://<server-ip>:<port>`   |
| Bakom din egen omvända proxy (NGINX, Caddy, Cloudflare Tunnel) på samma värd    | `127.0.0.1`                           | valfri ledig port      | proxyns URL                   |
| Bakom Toolkits [TLS-proxy](/sv/on-premises/configuration/overleaf-toolkit/tls-proxy) | `127.0.0.1`                           | `80`                   | `https://<your-domain>`       |

Om port `80` redan används på värden, till exempel av en annan webbserver, anger du `OVERLEAF_PORT` till en ledig port som `8080`. Annars misslyckas `bin/up` med `bind: address already in use`.

<Warning>

Portar som publiceras av Docker kringgår värdens brandväggar som `ufw` och `firewalld`. Med `0.0.0.0` kan instansen nås från alla nätverk som servern är ansluten till. På en molnserver måste du även tillåta porten i leverantörens säkerhetsgrupp. Använd HTTPS innan du exponerar instansen mot internet, se [TLS-proxy](/sv/on-premises/configuration/overleaf-toolkit/tls-proxy).

</Warning>

Du kan börja med standardvärdet och först öppna instansen på `localhost`. För att senare tillåta åtkomst från andra datorer ändrar du dessa två variabler i `config/overleaf.rc` och `OVERLEAF_SITE_URL` i `config/variables.env`, och kör sedan `bin/up` igen för att återskapa containrarna.
</Step>

<Step title="Obligatoriska miljövariabler">
Uppdatera följande variabler i `config/variables.env`:

| Namn                          | Beskrivning                                                                                                                                                    | Exempel                         |
| ----------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------- |
| `OVERLEAF_SITE_URL`           | Var din Overleaf-instans är offentligt tillgänglig. Används i offentliga länkar och vid anslutning via websockets, så den **måste vara korrekt konfigurerad**! | `https://overleaf.lilliput.com` |
| `OVERLEAF_EMAIL_FROM_ADDRESS` | Den här e-postadressen används som `from`-adress för all utgående e-post.                                                                                      | `no-reply@lilliput.com`         |
| `OVERLEAF_ADMIN_EMAIL`        | E-postadressen där användarna kan nå den som driver webbplatsen.                                                                                               | `it-services@lilliput.com`      |

`OVERLEAF_SITE_URL` är adressen som användarna skriver i sin webbläsare, inte lyssningsadressen. Ta med porten när den inte är `80` (HTTP) eller `443` (HTTPS), till exempel `http://192.168.1.20:8080`. Använd inte `http://0.0.0.0`. Om `OVERLEAF_SITE_URL` inte matchar adressen i webbläsaren kan redigeraren inte ansluta, och länkar i e-postmeddelanden och OAuth-callbacks pekar fel.

Ange även `OVERLEAF_SESSION_SECRET` till ett värde som genererats med `openssl rand -hex 32`. Utan den loggar varje `bin/up` som återskapar containern, och varje uppgradering, ut alla användare. Se Frågor och svar i [Miljövariabler](/sv/on-premises/configuration/overleaf-toolkit/environment-variables).

När du har uppdaterat miljövariablerna sparar du och avslutar.
</Step>

<Step title="Konfigurera kompilering i sandlåda">
Konfigurera sedan TeX Live Full för [sandboxed-compiles.md](/sv/on-premises/configuration/overleaf-toolkit/sandboxed-compiles  "mention"). Öppna `config/variables.env` och uppdatera följande miljövariabler:

```dotenv title="config/variables.env" wrap
ALL_TEX_LIVE_DOCKER_IMAGES=ghcr.io/ayaka-notes/texlive-full:2026.1, ghcr.io/ayaka-notes/texlive-full:2025.1
ALL_TEX_LIVE_DOCKER_IMAGE_NAMES=Texlive 2026, Texlive 2025
TEX_LIVE_DOCKER_IMAGE=ghcr.io/ayaka-notes/texlive-full:2026.1
```
</Step>

<Step title="Starta din instans">
Starta din instans genom att köra:

```text title="Start the instance"
bin/up
```

Det här kommandot laddar ned de images som krävs, inklusive texlive, skapar containrarna (med dina anpassningar) och startar instansen. Du bör se loggutdata från de olika Docker-containrarna.

För att starta dem igen senare (utan att koppla till loggutdatan) kör du:

```text title="Start without attaching to logs"
bin/start
```
</Step>
</Steps>

<Info>

Toolkit använder `docker compose` för att hantera Overleafs Docker-containrar. Toolkit tillhandahåller en uppsättning skript som omsluter `docker compose` och tar hand om de flesta detaljer åt dig.

</Info>

Om allt går bra bör du kunna se inloggningssidan för din nya Overleaf-instans genom att gå till [http://127.0.0.1/](http://127.0.0.1/) eller [http://localhost/](http://localhost/) i webbläsaren. Om du har ändrat `OVERLEAF_LISTEN_IP` eller `OVERLEAF_PORT` öppnar du i stället adressen från tabellen i steget **Lyssningsadress och port**, till exempel `http://<server-ip>:8080`.

För att kontrollera vilken adress och port webbgränssnittet publiceras på kör du:

```text title="Show the published port"
bin/docker-compose port sharelatex 80
```

Utdata, till exempel `0.0.0.0:8080`, visar den IP-adress och port på värden som används. Om den visar `127.0.0.1` kan instansen bara nås från själva servern.

<Warning>

Beroende på din nätverkskonfiguration och var din Overleaf-instans är hostad kan du behöva göra ytterligare konfigurationsändringar. Se Toolkit-inställningarna för mer information: [toolkit-settings.md](/sv/on-premises/configuration/overleaf-toolkit/toolkit-settings  "mention")

</Warning>
