---

`bin/podman-setup` kontrollerar allt som Ayakaleaf Pro behöver på Podman. Utan flaggor rapporterar det bara; med `--apply` åtgärdar det också det som hittas.

<Steps>
<Step title="Kontrollera värden">
```bash title="Check only"
bin/podman-setup
```

På en ren värd misslyckas de flesta kontroller, till exempel:

```text
====== Packages ======
[✗] podman not installed
[✗] podman-docker not installed
...
====== Summary ======
[✓] 7 passed  [!] 13 warnings  [✗] 4 failures
```
</Step>

<Step title="Tillämpa åtgärderna">
```bash title="Check and fix"
bin/podman-setup --apply
```

Kör det i en terminal: det frågar efter ditt `sudo`-lösenord för de systemövergripande stegen. Det laddar också ned Ayakaleaf Pro-avbildningen för att extrahera dess seccomp-profil, vilket tar några minuter första gången. I slutet kontrollerar det värden igen:

```text
====== Summary ======
[✓] 23 passed  [!] 2 warnings  [✗] 0 failures
[!] Warnings remaining:
[!] not logged in to quay.io
[!] container → socket skipped (sharelatex not running)
```

Båda varningarna är väntade i det här skedet:

* `not logged in to quay.io`: kontrollen kommer från den officiella Toolkit, där Server Pro-avbildningen finns i ett privat register. Ayakaleaf Pro-avbildningar är offentliga på `ghcr.io` och kräver ingen inloggning, så ignorera varningen. Den finns kvar även efter installationen.
* `container → socket skipped (sharelatex not running)`: det här testet kräver den körande instansen. Du kör skriptet igen i [3. Starta Ayakaleaf Pro](/sv/on-premises/installation/using-podman/3.-start-ayakaleaf-pro).

Skriptet avslutas med `0` när alla kontroller lyckas, `1` när det finns varningar och `2` när det finns fel. På grund av quay.io-varningen kan du förvänta dig `1`.
</Step>
</Steps>

### Vad skriptet ändrar {#what-the-script-changes}

Med `--apply` kan skriptet ändra följande.

Systemövergripande, med `sudo`:

* Installerar `podman`, `podman-docker`, `git`, `curl`, `checkpolicy` och `policycoreutils` med `dnf`.
* Aktiverar lingering för din användare med `loginctl`, så att dina containrar fortsätter att köras efter att du loggat ut.
* Skapar `/etc/containers/nodocker`, som tystar meddelandet "Emulate Docker CLI using podman".
* Läser in SELinux-policymodulen `podman_socket_clsi` när `SELINUX_MODE=managed`.

För din användare:

* Aktiverar användartjänsten `podman.socket`, det Docker-kompatibla API som Ayakaleaf Pro använder för att starta kompileringar.
* Installerar Docker Compose v2 från GitHub till `~/.local/bin/docker-compose` och länkar den i `~/.docker/cli-plugins/`.
* Får Podman att använda denna Compose i `~/.config/containers/containers.conf`.
* Lägger till aliasen `mongo` och `redis` i `~/.config/containers/registries.conf.d/overleaf-toolkit.conf`, så att Podman vet varifrån de korta avbildningsnamnen ska hämtas.

I Toolkit:

* Ställer in `DOCKER_SOCKET_PATH` och `DOCKER_HOST` i `config/overleaf.rc` på `/run/user/<uid>/podman/podman.sock`.
* Extraherar seccomp-profilen för kompileringar från Ayakaleaf Pro-avbildningen till `config/seccomp/<version>/clsi-profile.json` och ställer in `SECCOMP_PROFILE` i `config/variables.env`. Till skillnad från Docker behöver Podman profilen som en fil på värden.
* Bygger SELinux-policymodulen i `config/selinux/`.
* Ställer in ägarna till datakatalogerna i `data/` med `podman unshare chown`, när de finns.

<Info>

Varje ändring motsvarar en kontroll. Om du ändrar något för hand, till exempel i `config/overleaf.rc`, kör du `bin/podman-setup` igen för att verifiera det.

</Info>
