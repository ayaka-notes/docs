---
title: 1. Ladda ned och initiera Toolkit
description: Klona Ayakaleaf Toolkit, skapa konfigurationen och ställ in den för Ayakaleaf Pro på Podman.
icon: arrow-down-to-bracket
---

<Steps>
<Step title="Klona Toolkit">
Klona **Ayakaleaf Toolkit** ([ayaka-notes/toolkit](https://github.com/ayaka-notes/toolkit)) till din hemkatalog och gå in i den:

```bash title="Clone the Toolkit" wrap
git clone https://github.com/ayaka-notes/toolkit.git ~/overleaf-toolkit
cd ~/overleaf-toolkit
```

Kör alla följande kommandon från den här katalogen.
</Step>

<Step title="Skapa konfigurationen">
```bash title="Run initialization"
bin/init
```

Detta skapar `config/overleaf.rc`, `config/variables.env` och `config/version`, enligt beskrivningen i [3. Initiera konfigurationen](/sv/on-premises/installation/using-docker-compose/linux/3.-initialize-the-configuration) i Docker-guiden. `bin/init` behöver inte Podman än.
</Step>

<Step title="Ställ in config/overleaf.rc">
Öppna `config/overleaf.rc` och ändra de här raderna:

```bash title="config/overleaf.rc"
SERVER_PRO=true
OVERLEAF_PORT=8080
SIBLING_CONTAINERS_ENABLED=true
```

Lägg sedan till den här raden i slutet av filen:

```bash title="config/overleaf.rc"
SELINUX_MODE=managed
```

| Inställning                       | Varför                                                                                                                                                                                                       |
| --------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `SERVER_PRO=true`                 | Använder Ayakaleaf Pro-avbildningen från `ghcr.io`. Ingen inloggning behövs.                                                                                                                                 |
| `OVERLEAF_PORT=8080`              | Rootless Podman kan inte lyssna på portar under `1024`. Standardporten `80` misslyckas.                                                                                                                       |
| `SIBLING_CONTAINERS_ENABLED=true` | Kör varje kompilering i en egen TeX Live-container. Redan `true` som standard; Podman-konfigurationen stöder bara det här läget.                                                                             |
| `SELINUX_MODE=managed`            | Kör containern `sharelatex` med SELinux-typen `sharelatex_t`, som får använda Podman-socketen och inget annat. `bin/podman-setup --apply` installerar policymodulen för den. Se [Toolkit-inställningar](/sv/on-premises/configuration/overleaf-toolkit/toolkit-settings) för de andra lägena. |

Låt `DOCKER_SOCKET_PATH` vara som den är: `bin/podman-setup --apply` ställer in den på din Podman-socket i nästa steg.

<Warning>

Behåll `GIT_BRIDGE_ENABLED=false`. I Ayakaleaf Pro 6.3.4 fungerar Git-integrationen inte på Podman, se [Kända begränsningar](/sv/on-premises/installation/using-podman#known-limitations).

</Warning>
</Step>

<Step title="Välj TeX Live-avbildningar">
Öppna `config/variables.env`, ta bort `#` framför `TEX_LIVE_DOCKER_IMAGE` och `ALL_TEX_LIVE_DOCKER_IMAGES` och ange de TeX Live-avbildningar som ska användas:

```bash title="config/variables.env" wrap
TEX_LIVE_DOCKER_IMAGE=ghcr.io/ayaka-notes/texlive-full:2026.1
ALL_TEX_LIVE_DOCKER_IMAGES=ghcr.io/ayaka-notes/texlive-full:2026.1
```

`bin/up` avbryter med `Please configure ALL_TEX_LIVE_DOCKER_IMAGES` om listan är tom. `texlive-full` är stor; för en testserver fungerar även den mycket mindre `ghcr.io/ayaka-notes/texlive-basic:2026.1`. Se [Sandlådekompilering](/sv/on-premises/configuration/overleaf-toolkit/sandboxed-compiles) för tillgängliga avbildningar.

Ställ in de andra variablerna, till exempel `OVERLEAF_SITE_URL`, enligt beskrivningen i [5. Anpassa din instans](/sv/on-premises/installation/using-docker-compose/linux/5.-personalizing-your-instance#required-environment-variables). Med standardadressen för lyssning använder du `http://localhost:8080`.
</Step>
</Steps>
