---
title: 3. Starta Ayakaleaf Pro
description: Starta Ayakaleaf Pro på Podman, verifiera det med podman-setup och bin/doctor, och starta det efter omstarter.
icon: circle-play
---

<Steps>
<Step title="Starta containrarna">
```bash title="Start Ayakaleaf Pro"
bin/up -d
```

Den första starten laddar ned MongoDB-, Redis- och TeX Live-avbildningarna och skapar datakatalogerna i `data/`. Den skriver ut en varning om att stödet för Podman är experimentellt.

<Info>

Den första starten kan också skriva ut `MongoNetworkError: connect ECONNREFUSED 127.0.0.1:27017`. Toolkit konfigurerar MongoDB-replikuppsättningen medan MongoDB fortfarande startar, och försöker igen tills MongoDB svarar. Du kan ignorera den här raden.

</Info>

Efter en minut eller två kontrollerar du att containrarna körs:

```bash title="List the containers"
podman ps --format "{{.Names}} {{.Status}}"
```

```text
mongo Up 34 seconds (healthy)
redis Up 20 seconds
sharelatex Up 20 seconds
```
</Step>

<Step title="Kontrollera konfigurationen igen">
Nu när datakatalogerna finns och containern `sharelatex` körs kan `bin/podman-setup` slutföra sina kontroller:

```bash title="Check the setup"
bin/podman-setup
```

Det kontrollerar ägarna till de nya datakatalogerna och testar Podman-socketen inifrån containern `sharelatex`:

```text
====== Socket Connectivity ======
[✓] host → socket OK
[✓] container → socket OK

====== Data Directory Permissions ======
[✓] mongo data dir owned by 999
[✓] redis data dir owned by 999
[✓] overleaf data dir owned by 33
...
====== Summary ======
[✓] 27 passed  [!] 1 warnings  [✗] 0 failures
[!] Warnings:
[!] not logged in to quay.io
```

`container → socket OK` betyder att Ayakaleaf Pro kan starta kompileringscontainrar. Om en kontroll misslyckas kör du `bin/podman-setup --apply` och sedan `bin/up -d`. Varningen om quay.io gäller inte Ayakaleaf Pro, se [2. Kör podman-setup](/sv/on-premises/installation/using-podman/2.-run-podman-setup).
</Step>

<Step title="Kör doctor">
```bash title="Run the doctor"
bin/doctor
```

På Podman visar rapporten körmiljön och säkerhetsinställningarna:

```text
- Container Daemon
    - status: up
    - runtime: podman
    - server version: 5.8.5
    - socket: /run/user/1000/podman/podman.sock
    - DOCKER_HOST: unix:///run/user/1000/podman/podman.sock
    - host → socket: OK
    - container → socket: OK
- Security
    - SELinux: Enforcing
    - SELINUX_MODE: managed
    - SELINUX_LABEL: sharelatex_t
    - SELinux module: loaded (podman_socket_clsi)
    - SELinux rules: present
    - Seccomp profile: present
```

Varningen `Server Pro enabled, but not logged in to quay.io repository` i slutet är samma quay.io-kontroll, se [Få hjälp](/sv/on-premises/support/getting-help#q-and-a).
</Step>

<Step title="Starta Ayakaleaf Pro efter en omstart">
Med Docker startar Docker-daemonen containrarna igen efter en omstart. Rootless Podman har ingen daemon: aktivera användartjänsten som startar dina containrar när servern startar:

```bash title="Start the containers at boot"
systemctl --user enable podman-restart.service
```

Den startar alla containrar för din användare vars omstartspolicy är `always`, vilket Toolkit ställer in för alla sina containrar. Detta kräver lingering, som `bin/podman-setup --apply` aktiverade. Utan den här tjänsten kör du `bin/up -d` efter varje omstart.
</Step>

<Step title="Öppna porten i brandväggen">
Som standard tar instansen bara emot anslutningar från själva servern, på `http://localhost:8080`. För att öppna den från andra datorer ställer du in `OVERLEAF_LISTEN_IP` i `config/overleaf.rc` och `OVERLEAF_SITE_URL` i `config/variables.env` enligt beskrivningen i [5. Anpassa din instans](/sv/on-premises/installation/using-docker-compose/linux/5.-personalizing-your-instance#listen-address-and-port), och kör `bin/up -d` igen.

Till skillnad från Docker kringgår rootless Podman inte värdens brandvägg. Om `firewalld` körs, vilket är standard på RHEL, öppnar du porten:

```bash title="Open port 8080"
sudo firewall-cmd --permanent --add-port=8080/tcp
sudo firewall-cmd --reload
```

På en molnserver tillåter du även porten i leverantörens säkerhetsgrupp. Använd HTTPS innan du exponerar instansen mot internet, se [4. Uppgifter efter installationen](/sv/on-premises/installation/using-podman/4.-post-installation-tasks#use-https).
</Step>
</Steps>
