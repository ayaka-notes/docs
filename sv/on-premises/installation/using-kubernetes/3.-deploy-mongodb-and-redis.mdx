Ayakaleaf Pro behöver:

* **MongoDB 8** som en **replikuppsättning** (den använder transaktioner). Tre medlemmar fördelade över tre noder överlever förlusten av en nod; en enda medlem fungerar också.
* **Redis 7**, en server med AOF-persistens. Redis innehåller de ändringar som ännu inte skrivits till MongoDB, sessionerna och meddelandena mellan Overleaf-tjänsterna. Overleaf ansluter till en enda Redis-server: Sentinel och Redis Cluster stöds inte.

<Info>

Du kan använda hanterade tjänster i stället, till exempel MongoDB Atlas eller ditt molns Redis. Hoppa över den här sidan och ange `OVERLEAF_MONGO_URL` och `OVERLEAF_REDIS_HOST` till dem i [steg 4](/sv/on-premises/installation/using-kubernetes/4.-personalizing-your-instance).

</Info>

<Steps>
<Step title="MongoDB">
```yaml title="10-mongo.yaml" wrap
apiVersion: v1
kind: Service
metadata:
  name: mongo
  namespace: overleaf
spec:
  clusterIP: None                 # headless: gives mongo-0.mongo, mongo-1.mongo, ...
  publishNotReadyAddresses: true  # members must resolve each other before the set is initiated
  selector:
    app: mongo
  ports:
    - name: mongo
      port: 27017
---
apiVersion: apps/v1
kind: StatefulSet
metadata:
  name: mongo
  namespace: overleaf
spec:
  serviceName: mongo
  replicas: 3
  selector:
    matchLabels:
      app: mongo
  template:
    metadata:
      labels:
        app: mongo
    spec:
      affinity:
        podAntiAffinity:
          requiredDuringSchedulingIgnoredDuringExecution:
            - labelSelector:
                matchLabels:
                  app: mongo
              topologyKey: kubernetes.io/hostname
      containers:
        - name: mongo
          image: mongo:8.0
          args:
            - --replSet=overleaf
            - --bind_ip_all
            - --wiredTigerCacheSizeGB=0.25   # default is 50% of (RAM - 1 GB); size it for your nodes
          # env:
          #   - name: GLIBC_TUNABLES        # only on kernel 6.19+ (SERVER-121912)
          #     value: glibc.pthread.rseq=1
          ports:
            - containerPort: 27017
          readinessProbe:
            tcpSocket:
              port: 27017
          resources:
            requests:
              cpu: 100m
              memory: 384Mi
            limits:
              memory: 768Mi
          volumeMounts:
            - name: data
              mountPath: /data/db
  volumeClaimTemplates:
    - metadata:
        name: data
      spec:
        accessModes: [ReadWriteOnce]
        resources:
          requests:
            storage: 5Gi
---
# Initiates the replica set once. Safe to re-run: it does nothing when the set exists.
apiVersion: batch/v1
kind: Job
metadata:
  name: mongo-init-replica-set
  namespace: overleaf
spec:
  backoffLimit: 20
  template:
    spec:
      restartPolicy: OnFailure
      containers:
        - name: init
          image: mongo:8.0
          command:
            - mongosh
            - --quiet
            - --host=mongo-0.mongo
            - --eval
            - |
              try {
                rs.status()
                print('replica set already initiated')
              } catch (e) {
                rs.initiate({
                  _id: 'overleaf',
                  members: [
                    { _id: 0, host: 'mongo-0.mongo.overleaf.svc.cluster.local:27017' },
                    { _id: 1, host: 'mongo-1.mongo.overleaf.svc.cluster.local:27017' },
                    { _id: 2, host: 'mongo-2.mongo.overleaf.svc.cluster.local:27017' },
                  ],
                })
              }
```

```bash
kubectl apply -f 10-mongo.yaml
kubectl -n overleaf rollout status statefulset/mongo
kubectl -n overleaf wait --for=condition=complete job/mongo-init-replica-set --timeout=5m
kubectl -n overleaf exec mongo-0 -- mongosh --quiet --eval 'rs.status().members.map(m => m.name + " " + m.stateStr)'
```

En medlem bör vara `PRIMARY` och de andra `SECONDARY` efter några sekunder. Jobbet försöker igen tills alla medlemmar svarar, så några misslyckade jobbpoddar är normalt.

* Den headless Service:en behöver `publishNotReadyAddresses: true`: medlemmarna måste hitta varandra via namn innan replikuppsättningen finns.
* Medlemmarna läggs till med sina stabila namn (`mongo-0.mongo.overleaf.svc.cluster.local`), aldrig poddarnas IP-adresser, som ändras vid varje omstart.
* För en enda medlem anger du `replicas: 1` och behåller bara `mongo-0` i jobbet.
</Step>

<Step title="Redis">
```yaml title="20-redis.yaml" wrap
apiVersion: v1
kind: Service
metadata:
  name: redis
  namespace: overleaf
spec:
  selector:
    app: redis
  ports:
    - name: redis
      port: 6379
---
apiVersion: apps/v1
kind: StatefulSet
metadata:
  name: redis
  namespace: overleaf
spec:
  serviceName: redis
  replicas: 1
  selector:
    matchLabels:
      app: redis
  template:
    metadata:
      labels:
        app: redis
    spec:
      containers:
        - name: redis
          image: redis:7.4
          args: [--appendonly, "yes"]
          ports:
            - containerPort: 6379
          readinessProbe:
            tcpSocket:
              port: 6379
          resources:
            requests:
              cpu: 50m
              memory: 128Mi
            limits:
              memory: 512Mi
          volumeMounts:
            - name: data
              mountPath: /data
  volumeClaimTemplates:
    - metadata:
        name: data
      spec:
        accessModes: [ReadWriteOnce]
        resources:
          requests:
            storage: 2Gi
```

```bash
kubectl apply -f 20-redis.yaml
kubectl -n overleaf rollout status statefulset/redis
```
</Step>

### Frågor och svar

<Accordion title="MongoDB 8 kraschar vid uppstart på en ny kärna. Varför?">

<strong>Svar:</strong> MongoDB 8 misslyckas på Linux-kärna 6.19 och senare ([SERVER-121912](https://jira.mongodb.org/browse/SERVER-121912)). Avkommentera miljövariabeln `GLIBC_TUNABLES` i `10-mongo.yaml`.

</Accordion>

<Accordion title="Hur mycket minne behöver MongoDB?">

<strong>Svar:</strong> Som standard använder MongoDB hälften av nodens minne minus 1 GB till sin cache, och den ser nodens minne, inte poddens gräns. Ange `--wiredTigerCacheSizeGB` så att det passar dina noder; `0.25` höll varje medlem på cirka 200 till 260 MiB på våra testnoder med 4 GB.

</Accordion>
