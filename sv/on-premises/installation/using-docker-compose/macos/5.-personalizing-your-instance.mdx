<Steps>
<Step title="Containerinställningar">
Redigera dessa befintliga poster i `config/overleaf.rc`:

```bash title="config/overleaf.rc"
PROJECT_NAME=ayakaleaf-macos
SERVER_PRO=true
OVERLEAF_LISTEN_IP=127.0.0.1
OVERLEAF_PORT=8080
SIBLING_CONTAINERS_ENABLED=true
DOCKER_SOCKET_PATH=/var/run/docker.sock
```

Behåll standardsökvägarna för data och de medföljande tjänsterna MongoDB och Redis. Med `OVERLEAF_LISTEN_IP=127.0.0.1` kan endast webbläsare på den här Macen öppna instansen.
</Step>

<Step title="Applikationsinställningar">
I `config/variables.env` anger du dessa värden och ersätter eventuella aktiva poster med samma namn:

```dotenv title="config/variables.env"
OVERLEAF_SITE_URL=http://localhost:8080
TEX_LIVE_DOCKER_IMAGE=ghcr.io/ayaka-notes/texlive-full:2026.1
ALL_TEX_LIVE_DOCKER_IMAGES=ghcr.io/ayaka-notes/texlive-full:2026.1
ALL_TEX_LIVE_DOCKER_IMAGE_NAMES="TeX Live 2026"
```

Generera en sessionshemlighet:

```bash
openssl rand -hex 32
```

Lägg till resultatet som `OVERLEAF_SESSION_SECRET` i `config/variables.env`. Utan den loggas alla användare ut vid varje `bin/up` som återskapar containern, se [Miljövariabler](/sv/on-premises/configuration/overleaf-toolkit/environment-variables).

För en lokal instans utan e-post lämnar du SMTP-inställningarna och `OVERLEAF_EMAIL_FROM_ADDRESS` oinställda. Git Bridge, extern autentisering och de andra integrationerna kan läggas till senare med sina egna [konfigurationssidor](/sv/on-premises/configuration/overleaf-toolkit).
</Step>

<Step title="Kontrollera Linux-kärnan i Docker-VM:en" id="check-the-docker-vms-linux-kernel">
MongoDB körs på Linux-kärnan i Docker Desktops virtuella maskin, inte på macOS. Kontrollera dess version före den första starten:

```bash
docker info --format '{{.KernelVersion}}'
```

MongoDB dokumenterar en inkompatibilitet med Linux-kärnor **6.19 till och med 7.0.13**, som även påverkar MongoDB i Docker. Lösningen är en kärna **7.0.14 eller senare**, som följer med en uppdatering av Docker Desktop, se [MongoDB:s produktionsanteckningar](https://www.mongodb.com/docs/manual/administration/production-notes/).

Om din Docker-VM använder en påverkad kärna lägger du till följande i `config/docker-compose.override.yml`, sammanslaget med eventuella `services` som du redan har där:

```yaml title="config/docker-compose.override.yml"
services:
  mongo:
    environment:
      GLIBC_TUNABLES: glibc.pthread.rseq=1
```

<Warning>

Uppdatera till en åtgärdad kärna när en sådan finns tillgänglig. Om din kärna ligger utanför det påverkade intervallet behövs inte den här lösningen.

</Warning>
</Step>

<Step title="Starta din instans">
Kör följande från Toolkit-katalogen:

```bash
bin/up -d
```

Toolkit initierar MongoDB:s replikuppsättning, hämtar TeX Live-avbildningen och startar applikationen. Den första nedladdningen tar en stund. Så här följer du förloppet:

```bash
bin/docker-compose ps
bin/docker-compose logs --tail=100 -f sharelatex
```

Tryck på `Ctrl+C` för att sluta följa loggarna. Containrarna fortsätter att köras.

Kontrollera den publicerade porten och sidan för första körningen:

```bash
bin/docker-compose port sharelatex 80
curl -I http://localhost:8080/launchpad
```

Porten ska vara `127.0.0.1:8080`.
</Step>
</Steps>
