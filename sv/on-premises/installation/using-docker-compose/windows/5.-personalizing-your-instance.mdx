---
title: 5. Anpassa din instans
description: Ange port, webbplats-URL och TeX Live-avbildning, aktivera sandlådekompilering och starta Ayakaleaf Pro på WSL 2.
icon: square-sliders
---

Kör kommandon och redigera filer i **Ubuntu**, från `~/ayakaleaf-toolkit`.

<Steps>
<Step title="Containerinställningar">
Redigera de befintliga posterna i `config/overleaf.rc`:

```bash title="config/overleaf.rc"
PROJECT_NAME=ayakaleaf-wsl
SERVER_PRO=true
OVERLEAF_LISTEN_IP=127.0.0.1
OVERLEAF_PORT=8080
SIBLING_CONTAINERS_ENABLED=true
DOCKER_SOCKET_PATH=/var/run/docker.sock
```

Behåll standardsökvägarna för data och de medföljande tjänsterna MongoDB och Redis. Port `8080` är till för den lokala webbläsaren i Windows; bindningen till `127.0.0.1` håller den lokal. Sandlådekompilering använder en separat Linux-container för varje kompilering i stället för att köra TeX i applikationscontainern. Docker-socketen låter applikationen skapa dessa containrar, och Toolkit tillhandahåller värdsökvägen för kompileringsdata under `data/overleaf/data/compiles`.
</Step>

<Step title="Applikationsinställningar">
I `config/variables.env` anger du dessa värden och ersätter eventuella aktiva poster med samma namn:

```dotenv title="config/variables.env"
OVERLEAF_SITE_URL=http://localhost:8080
TEX_LIVE_DOCKER_IMAGE=ghcr.io/ayaka-notes/texlive-full:2026.1
ALL_TEX_LIVE_DOCKER_IMAGES=ghcr.io/ayaka-notes/texlive-full:2026.1
ALL_TEX_LIVE_DOCKER_IMAGE_NAMES="TeX Live 2026"
```

Den fullständiga avbildningen innehåller de paket och typsnitt som behövs för ett brett spektrum av projekt. Räkna med minst 40 GB ledigt lagringsutrymme för den och applikationen, plus utrymme för projektdata och framtida uppdateringar.

För ett snabbt driftsättningstest använder du i stället den mindre **basic**-avbildningen. Den räcker för det enkla artikeltestet i steg 6, men innehåller inte den fullständiga uppsättningen paket och typsnitt:

```dotenv
TEX_LIVE_DOCKER_IMAGE=ghcr.io/ayaka-notes/texlive-basic:2026.1
ALL_TEX_LIVE_DOCKER_IMAGES=ghcr.io/ayaka-notes/texlive-basic:2026.1
ALL_TEX_LIVE_DOCKER_IMAGE_NAMES="TeX Live 2026 Basic"
```

Välj en av dessa uppsättningar, utan dubbla aktiva nycklar. Basic-avbildningens [Dockerfile](https://github.com/ayaka-notes/texlive-full/blob/main/texlive/2026/Dockerfile.basic) innehåller `latexmk`, XeTeX och `fontspec`, men inte `ctex` eller den fullständiga typsnittssamlingen. Ett saknat LaTeX-paket i basic tyder inte i sig på ett problem med sandlådan.

Generera en sessionshemlighet:

```bash
openssl rand -hex 32
```

Lägg till resultatet som `OVERLEAF_SESSION_SECRET` i `config/variables.env`. Behåll även den genererade hemligheten för inbjudningstoken. För en lokal instans utan e-post lämnar du SMTP-inställningarna och `OVERLEAF_EMAIL_FROM_ADDRESS` oinställda.
</Step>

<Step title="Starta din instans">
```bash
bin/up -d
```

Toolkit startar MongoDB, initierar dess replikuppsättning, laddar ner den valda TeX Live-avbildningen och startar Redis och applikationen. Det kan se ut som att processen står still medan en stor avbildning laddas ner. Kör inte en andra `bin/up` medan den första fortfarande arbetar.

Kontrollera följande i en annan Ubuntu-terminal:

```bash
cd "$HOME/ayakaleaf-toolkit"
bin/docker-compose ps
bin/docker-compose logs --tail=100 mongo
bin/docker-compose logs --tail=100 -f sharelatex
```

Tryck på `Ctrl+C` för att sluta följa loggarna; frikopplade containrar fortsätter att köras. Om starten misslyckas vid MongoDB följer du [MongoDB startar inte](/sv/on-premises/installation/using-docker-compose/windows/troubleshooting#mongodb-fails-to-start) innan du försöker igen. Ta inte bort dess datakatalog för att återställa en befintlig installation.

Kontrollera porten och sidan för första körningen:

```bash
bin/docker-compose port sharelatex 80
curl -I http://localhost:8080/launchpad
```

Porten ska vara `127.0.0.1:8080`. Vänta tills applikationen har initierats om HTTP-begäran först misslyckas.
</Step>

<Step title="Öppna instansen från Windows">
Öppna [http://localhost:8080/launchpad](http://localhost:8080/launchpad) i din **webbläsare i Windows**. Använd den här adressen även i Windows, i stället för en tillfällig WSL-IP-adress.

För att kontrollera HTTP-åtkomsten från Windows separat från webbläsaren kör du följande i **PowerShell**:

```powershell
curl.exe -I http://localhost:8080/launchpad
```

Om Ubuntu kan nå sidan men Windows inte kan det, se [Windows kan inte öppna localhost](/sv/on-premises/installation/using-docker-compose/windows/troubleshooting#windows-cannot-open-localhost).
</Step>
</Steps>
