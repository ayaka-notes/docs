Ayakaleaf Pro använder Linux-containrar. På Windows installerar du Docker Desktop med dess WSL 2-backend och kör Toolkit-skripten i Ubuntu.

WSL 2 tillhandahåller Linux-kärnan. Docker Desktop hanterar Docker-motorn i sin egen miljö `docker-desktop`; när du aktiverar **WSL Integration** kan Docker CLI i Ubuntu kommunicera med den motorn. Toolkit startar sedan applikationen, MongoDB och Redis som containrar. När sandlådekompilering är aktiverad använder applikationen motorns Docker-socket för att starta en separat TeX Live-container för varje kompilering. Du behöver inga Windows-installationer av MongoDB, Redis eller TeX Live.

<Steps>
<Step title="Installera WSL 2 och Ubuntu">
Öppna **PowerShell som administratör** i Windows och kör:

```powershell
wsl --install -d Ubuntu
```

Starta om Windows om du uppmanas till det. Öppna **Ubuntu** från Start-menyn och skapa ett Linux-användarnamn och lösenord. Det här är kontot för `sudo` i Ubuntu; det är skilt från din Windows-inloggning.

Tillbaka i **PowerShell** uppdaterar du WSL och kontrollerar distributionen:

```powershell
wsl --update
wsl --version
wsl --list --verbose
```

Ubuntu-raden måste visa **VERSION 2**. Om den visar 1 använder du distributionens exakta namn från listan:

```powershell
wsl --set-version Ubuntu 2
```

Docker kräver WSL **2.1.5 eller senare**; programvaruversionen av WSL från `wsl --version` och distributionens kolumn **VERSION 2** är olika kontroller. Se [felsökning av installationen](/sv/on-premises/installation/using-docker-compose/windows/troubleshooting#wsl-or-docker-reports-that-virtualization-is-unavailable) och [Microsofts installationsinstruktioner](https://learn.microsoft.com/en-us/windows/wsl/install) om installationen misslyckas, och aktivera hårdvaruvirtualisering i BIOS/UEFI om WSL rapporterar att den inte är tillgänglig.
</Step>

<Step title="Installera och starta Docker Desktop">
Ladda ner [Docker Desktop for Windows](https://docs.docker.com/desktop/setup/install/windows-install/) för din processor och kör installationsprogrammet. Använd **WSL 2**-backend om det erbjuds. Öppna **Docker Desktop** från Start-menyn i Windows och vänta tills motorn har startat.

I Docker Desktops **Settings → General** aktiverar du **Use WSL 2 based engine** om alternativet visas. Under **Settings → Resources → WSL Integration** aktiverar du integrationen för **Ubuntu** och väljer sedan **Apply** eller **Apply & restart**. Om Ubuntu inte är din standarddistribution aktiverar du dess egen växel uttryckligen.

Om WSL Integration saknas kontrollerar du att Docker Desktop använder **Linux containers**. Se [Dockers guide för WSL 2-backend](https://docs.docker.com/desktop/features/wsl/).

Använd Docker Desktops integration för den här guiden. Att installera en andra Docker Engine med `apt install docker.io` eller starta `dockerd` i Ubuntu skapar en separat konfiguration och kan orsaka konflikter. Om du redan använder en Engine i Ubuntu följer du Dockers migreringsvägledning innan du byter; behåll befintliga applikationsdata och säkerhetskopior.
</Step>

<Step title="Kontrollera Docker från Ubuntu">
Öppna en **Ubuntu**-terminal. Kör dessa kommandon där, utan `sudo`:

```bash
docker version
docker compose version
docker ps
```

`docker version` måste visa både **Client** och **Server**. En tom containerlista är normal i en ny installation. `docker --version` ensamt bevisar inte att motorn körs.

Om `docker` inte är tillgängligt eller inte kan ansluta öppnar du Ubuntu igen efter att ha tillämpat WSL Integration och kontrollerar att Docker Desktop körs. Se [Felsökning](/sv/on-premises/installation/using-docker-compose/windows/troubleshooting#docker-is-unavailable-in-ubuntu).
</Step>

<Step title="Kontrollera resurser och Docker-socketen">
Kontrollera de resurser som är synliga för Docker:

```bash
docker info --format 'CPUs={{.NCPU}} Memory={{.MemTotal}} Kernel={{.KernelVersion}}'
df -h "$HOME"
ls -l /var/run/docker.sock
```

För en liten lokal instans är 4 CPU:er och 8 GB minne tillgängliga för Docker ett förslag att börja med, inte ett uppmätt minimum. Behåll tillräckligt med minne även för Windows. Med WSL 2-backend hanteras resursgränser via [WSL-inställningar](https://learn.microsoft.com/en-us/windows/wsl/wsl-config), inte med de resursreglage som Docker Desktop har på Mac. Ändringar som kräver `wsl --shutdown` avbryter alla WSL-distributioner och Docker-arbetsbelastningar som körs; tillämpa dem innan du startar instansen.

Behåll `DOCKER_SOCKET_PATH=/var/run/docker.sock` i Toolkit-konfigurationen. Applikationen behöver den här motorsocketen för sandlådekompilering. Ändra inte dess behörigheter till `777` för att åtgärda anslutningsfel; återställ i stället Docker Desktops integration.
</Step>
</Steps>
