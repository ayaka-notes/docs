## Skapa en administratörsanvändare {#creating-an-administrator-user}

Installationer med Overleaf Toolkit:

```bash title="Overleaf Toolkit" wrap
$ bin/docker-compose exec sharelatex /bin/bash -ce "cd /overleaf/services/web && node modules/server-ce-scripts/scripts/create-user --admin --email=joe@example.com"
```

Äldre installationer med docker-compose.yml:

```bash title="Legacy docker-compose" wrap
$ docker exec sharelatex /bin/bash -ce "cd /overleaf/services/web && node modules/server-ce-scripts/scripts/create-user --admin --email=joe@example.com"
```

Kommandot skapar en användare med den angivna e-postadressen om hen inte redan finns, och gör användaren till administratör. Kommandots utdata innehåller en URL som du kan besöka för att ange lösenordet för användaren och logga in för första gången.

<Info>

För ett programmatiskt tillvägagångssätt kan du använda samma skript för att skapa både vanliga användare och administratörer. För vanliga användare utelämnar du flaggan --admin.

</Info>

Om du använder interna konton för autentisering och behöver göra en befintlig användare till instansadministratör eller återkalla administratörsbehörigheter gör du så här:

<Steps>
<Step title="Via administrationsgränssnittet">
* Logga in som en befintlig administratör.
* Klicka på Admin -> Manage Users.
* Sök efter användaren och klicka på dennes e-postadress.
* Scrolla ned till avsnittet Site Admin och klicka på länken (show).
* Markera kryssrutan Is Site Admin.
* Klicka på Save för att slutföra.
</Step>
</Steps>

## Ta bort användare {#deleting-users}

Det är i allmänhet lämpligt att inte ta bort konton om de inte längre behövs. När ett konto tas bort försvinner kontot och medarbetare förlorar åtkomsten till projekt. Det finns för närvarande inget sätt att inaktivera konton — antingen finns de kvar med sina data bevarade, eller så tas de bort.

Som standard mjukraderas konton. Information om hur du permanent tar bort användare från din instans finns under `ENABLE_CRON_RESOURCE_DELETION` i guiden [Miljövariabler](/sv/on-premises/configuration/overleaf-toolkit/environment-variables).

<Info>

Konton mjukraderas som standard. Se `ENABLE_CRON_RESOURCE_DELETION` för beteendet vid permanent borttagning.

</Info>

### Via Admin -> Manage Users {#via-admin->-manage-users}

<Steps>
<Step title="">
* Logga in som administratör.
* Klicka på Admin -> Manage Users.
* Sök efter användaren och markera kryssrutan bredvid dennes e-postadress.
* Klicka på papperskorgsikonen.
* Klicka på Delete för att bekräfta.
</Step>
</Steps>

### Via kommandoraden {#via-the-command-line}

Användarkonton (och deras projekt) kan tas bort med följande kommandon.

Installationer med Overleaf Toolkit:

```bash title="Overleaf Toolkit"
$ bin/docker-compose exec sharelatex /bin/bash -ce "cd /overleaf/services/web && node modules/server-ce-scripts/scripts/delete-user.mjs --email=joe@example.com"
```

Äldre installationer med docker-compose.yml:

```bash title="Legacy docker-compose"
$ docker exec sharelatex /bin/bash -ce "cd /overleaf/services/web && node modules/server-ce-scripts/scripts/delete-user.mjs --email=joe@example.com"
```

<Danger>

Borttagningsskriptet använder ett hårdkodat force-alternativ som säkerställer att borttagningen genomförs även om e-postmeddelandet om kontoborttagningen inte kan skickas (t.ex. när användarens e-postadress inte längre används).

</Danger>

<Info>

Alternativet --skip-email kan användas för att förhindra att ett informationsmejl skickas till den borttagna användaren.

</Info>

## Återställa en mjukraderad användare {#restoring-a-soft-deleted-user}

Om en användare bara har mjukraderats kan du återställa kontot och projekten.

<Steps>
<Step title="">
* Logga in som administratör.
* Klicka på Admin -> Manage Users.
* Sök efter den användare du vill återställa.
* Klicka på knappen Display deleted users.
* Klicka på den borttagna användarens e-postadress.
* Klicka på Recover This Account.
* Klicka på Recover för att bekräfta.
</Step>
</Steps>

<Danger>

När ENABLE\_CRON\_RESOURCE\_DELETION är satt till true kan mjukraderade konton återställas inom en period på 90 dagar. Efter 90 dagar går det inte att återställa kontot.

</Danger>

## Räkna användare {#counting-users}

Du kan få fram antalet användare via administrationsgränssnittet på https://you-instance-url/admin/user#license. För programmatiska kontroller och exporter kan följande exempel vara till hjälp.

Totalt antal användare:

```bash title="Total number of users"
echo 'db.users.countDocuments()' | docker exec -i mongo mongosh --quiet localhost/sharelatex
# overleaf [direct: primary] sharelatex> 16
```

Totalt antal användare via metrics-endpointen:

```bash title="Num active users from metrics"
docker exec sharelatex curl http://127.0.0.1:3000/metrics | grep num_active_users
# # HELP num_active_users num_active_users
# # TYPE num_active_users gauge
# num_active_users{app="web-api",host="b3ae4ff549d8"} 16
```

Totalt antal aktiva användare (exempel: användare som varit aktiva under de senaste 365 dagarna):

```bash title="Total number of active users"
echo 'db.users.countDocuments({ lastActive: { $gte: new Date(new Date().getTime() - (365 * 24 * 60 * 60 * 1000)) } })' | docker exec -i mongo mongosh --quiet localhost/sharelatex
# overleaf [direct: primary] sharelatex> 10
```

## Uppdatera användarkontoinformation {#updating-user-account-information}

Hur kontouppdateringar görs beror på om SSO är aktiverat.

* Om SSO inte används:
  * Administratörer kan ändra användarkontoinformation via Admin -> Manage Users (e-postadress, förnamn, efternamn samt generera en länk för lösenordsåterställning).
  * Vanliga användare kan uppdatera sina egna uppgifter via Account -> Account Settings (inklusive att byta lösenord och generera autentiseringstoken för Git).
* Om SSO används:
  * Ayakaleaf Pro kan konfigureras att uppdatera en användares för- och efternamn vid inloggning baserat på autentiseringssystemet.
  * När OVERLEAF\_SAML\_UPDATE\_USER\_DETAILS\_ON\_LOGIN eller OVERLEAF\_LDAP\_UPDATE\_USER\_DETAILS\_ON\_LOGIN är true inaktiveras formuläret för användaruppgifter på https://your-instance-url/user/settings, och för-/efternamn kan endast anges i ditt system för identitetshantering.

Mer information finns här:

* [SAML 2.0-konfiguration](/sv/on-premises/configuration/overleaf-toolkit/authentication/saml-authentication)
* [LDAP-konfiguration](/sv/on-premises/configuration/overleaf-toolkit/authentication/ldap-authentication)

### Frågor och svar {#q&a}

<Accordion title="Kan jag skapa SSO-användare i förväg, till exempel med ett API?">

<strong>Svar:</strong> Det finns inget HTTP-API för detta. Skapa kontot med skriptet `create-user` ovan (utan `--admin`), eller under **Admin → Manage Users** med **Create account**. När `EXTERNAL_AUTH` är satt har det formuläret alternativet **External authentication**, som skapar kontot utan lokalt lösenord och utan aktiveringsmejl. Vid den första inloggningen via LDAP, SAML eller OIDC får användaren det befintliga kontot med samma e-postadress i stället för ett nytt, se [Konton och lösenord](/sv/on-premises/configuration/overleaf-toolkit/authentication#konton-och-lösenord).

</Accordion>

<Accordion title="Kan jag exportera användarlistan och återställa den senare?">

<strong>Svar:</strong> Nej. Det finns ingen export eller import av användarkonton, varken under **Admin → Manage Users** eller som skript. Kontona lagras i MongoDB, så säkerhetskopiera och återställ dem med en [säkerhetskopia av MongoDB](/sv/on-premises/maintenance/data-and-backups#mongodb). Skriptet `export-user-projects.mjs` exporterar användarnas projekt som zip-filer, inte kontona, se [Exportera projekt](/sv/on-premises/maintenance/data-and-backups/exporting-projects).

</Accordion>

<Accordion title="Hur länge är länken från `create-user` giltig, och hur återställer jag ett lösenord utan e-post?">

<strong>Svar:</strong> Länken som `create-user` skriver ut är giltig i 7 dagar, och den fungerar utan SMTP eftersom du kopierar den från utdata. För att få en ny länk kör du `create-user` igen med samma e-postadress. För ett befintligt konto skriver det bara ut en ny länk, men det sätter också kontots admin-flagga så att den matchar `--admin`, så behåll `--admin` när du kör det för en administratör.

En administratör kan också ange ett lösenord direkt: i **Admin → Manage Users** klickar du på **Update** på användarens rad, öppnar fliken **Password** och anger ett nytt lösenord på minst 8 tecken. Konton som endast loggar in via LDAP, SAML eller OIDC kan inte få ett lösenord där.

</Accordion>
