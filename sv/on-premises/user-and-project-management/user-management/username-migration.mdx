## Migrering av användarnamn

Ur inloggningssynpunkt är en användares primära identifierare dennes e-postadress. Om du migrerar från lokal autentisering till SSO, eller från en IdP till en annan, kan du behöva uppdatera användarnas e-postadresser.

För att underlätta detta tillhandahålls ett skript som migrerar användares e-postadresser med hjälp av en CSV-fil i följande format:

`oldEmail,newEmail`

Efter att ha utfört några valideringskontroller går skriptet igenom CSV-filen och uppdaterar användarnas e-postadresser från `oldEmail` till `newEmail`.

### **Validering**

Innan migreringen körs kontrolleras `<csv_file>` för att säkerställa att:

* både `oldEmail` och `newEmail` är giltiga e-postadresser på varje rad
* det inte finns några dubblettposter, till exempel att du inte försöker uppdatera olika användare till samma nya e-postadress eller uppdatera samma användarkonto med en e-postadress som redan används

### **Användning**

```bash wrap
docker cp <csv_file> sharelatex:/overleaf/services/web/<csv_file> docker exec sharelatex /bin/bash -c "cd /overleaf/services/web;node ./modules/server-ce-scripts/scripts/migrate-user-emails.js [--commit] [--continue|--ignore-missing] [--admin-id=ADMIN_USER_ID] <csv_file>"
```

### **Flaggor**

| Namn               | Beskrivning                                                                                                                                                                                                                                                      |
| ------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `--commit`         | <p>Om flaggan `--commit` anges genomförs migreringen faktiskt. När den utelämnas sker migreringen i ett testläge (dry-run) där inga ändringar görs men valideringen ändå utförs.<br /><br /><strong>Standard</strong>:`false`</p> |
| `--continue`       | Flaggan `--continue` fortsätter migreringsprocessen om e-postadressen på ett användarkonto redan har uppdaterats                                                                                                                         |
| `--ignore-missing` | Flaggan `--ignore-missing` fortsätter migreringsprocessen om ett användarkonto inte hittades                                                                                                                                                                  |
| `--admin-id`       | `--admin-id` ska sättas till ID:t för den administratör som utför migreringen och används för poster i granskningsloggen. Gå till **Admin** > **Manage Users**, sök efter din e-postadress och klicka på det första resultatet för att hitta ditt användar-id.   |
| `<csv_file>`       | `<csv_file>` är filen som innehåller de gamla och nya e-postadresserna                                                                                                                                                                                             |

### **Slutförande**

När migreringsskriptet körs avgör de flaggor du har valt om ett fel loggas till konsolen och körningen sedan fortsätter, eller om felet loggas till konsolen och skriptet avslutas. Om skriptet avbryts i förtid på grund av ett fel avslutas det med kod 1 för att visa att det misslyckades.

När migreringen är klar loggar skriptet antalet lyckade, misslyckade och överhoppade uppdateringar till konsolen. Om migreringen slutförs utan fel avslutas skriptet med kod 0.
