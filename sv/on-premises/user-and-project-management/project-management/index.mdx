### Visa ett projekts granskningslogg

Administratörer kan se en **Audit Log** (granskningslogg) för varje projekt. Granskningsloggen visar händelser som när länkdelning ändrades mellan privat och tokenbaserad, när inbjudningar skickades/accepterades och när en användare gick med i projektet med hjälp av en token. Administratörer kan visa loggarna per projekt via **Your Instance** -> **Admin** -> **Manage Users** och sedan:

* Söka efter användaren
* Klicka på fliken **Projects**
* Välja ett projekt
* Klicka på ikonen (i)
* Klicka på fliken **Audit Log**

Om ett projekt delas med en namngiven medarbetare (via dennes e-postadress) listas mottagaren, när hen har gått med, i delningsdialogen tillsammans med sin behörighet och är synlig för projektägaren. Denna information visas även för administratörer när de tittar på fliken Project Info för projektet via administrationspanelen.

### Återställa borttagna dokument

1. Logga in med dina administratörsuppgifter
2. Klicka på **Admin** och välj **Manage Users**
3. Ange i sökfältet e-postadressen till den användare vars dokument du vill återställa
4. Klicka på e-postadressen i resultatlistan för att öppna användarens informationssida
5. Klicka på fliken **Projects** och använd sökfältet för att söka efter projektet
6. Klicka på informationsikonen bredvid projektnamnet för att öppna **Project Info**
7. Klicka på fliken **Deleted Docs**
8. Klicka på knappen **Undelete** bredvid det borttagna dokumentet för att återställa det till användarens projekt.

Den återställda filen får följande format: `FILENAME-TIMESTAMP.EXTENSION`. Till exempel återställs en version av `main.tex` till projektets rot med filnamnet `main-2024-02-23-130441542.tex`.

### Överföra ägarskap av ett projekt

Administrationspanelen i Server Pro har en dedikerad sida för varje projekt. Du kan nå den antingen genom att söka efter användaren på "/admin/user", gå till fliken **Projects**, hitta projektet i listan och klicka på informationsikonen; eller genom att navigera direkt till sidan med ett känt projekt-id [**https://your-instance-url/admin/project/**](https://your-instance-url/admin/project/). På projektets informationssida finns knappen **Transfer Ownership**, som öppnar en dialog där du kan ange vilken användare som helst som ny ägare. Den nya ägaren behöver inte vara en befintlig medarbetare i projektet.

<Info>

Observera att den tidigare ägaren läggs till som medarbetare med läs- och skrivbehörighet till projektet som en del av ägarskapsöverföringen.

</Info>

### Uppdatera tidsgränsen för projektkompilering

Standardtidsgränsen för kompilering av projekt är för närvarande 180 sekunder. Det går att ändra värdet, och det kräver en process i två steg.

Redigera först filen **config/variables.env**, lägg till miljövariabeln `COMPILE_TIMEOUT` och ange önskad tidsgräns i sekunder som värde. Till exempel `COMPILE_TIMEOUT=300` för 5 minuter.

<Danger>

Det är inte värt att sätta tidsgränsen högre än 10 minuter. Om du gör det kommer du sannolikt att nå en tidsgräns i någon annan komponent i applikationen.

</Danger>

När ändringen är gjord måste du återskapa containern **sharelatex** genom att köra kommandot `bin/up -d`.

Att sätta den här miljövariabeln uppdaterar tidsgränsen endast för nya användare; den tillämpas **inte** retroaktivt på befintliga användare, eftersom värdet fylls i när användaren skapas.

För att justera tidsgränsen för befintliga användare måste du ändra varje användarpost i databasen. Vi råder dig att vara mycket försiktig med detta och rekommenderar att du tar en konsekvent säkerhetskopia innan du gör några ändringar.

Du hittar information om hur du tar säkerhetskopior [här](/sv/on-premises/maintenance/data-and-backups).

För att uppdatera kompileringstidsgränsen för alla befintliga användare kör du följande skalkommando på Docker-värden:

```bash wrap
echo 'db.users.updateMany({}, {$set: {"features.compileTimeout": <value>}})' | docker exec -i mongo mongosh --quiet localhost/sharelatex
```

Du behöver ersätta `<value>` i frågan ovan med önskad tidsgräns i sekunder.

När kommandot har körts bör du se en bekräftelse med antalet ändrade poster. Du kan sedan skriva exit och trycka på Enter för att återgå till värdens skal.

### Spåra åtkomst till projekt

Det går att se vem som har läst in ett projekt och när med följande kommando:

```bash wrap
docker exec sharelatex bash -c 'grep "join project request" /var/log/overleaf/web.log'
```

Detta ger både `timestamp`, `user_id` och `project_id`.
