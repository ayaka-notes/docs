<Accordion title="Köra Overleaf med ett NFS-filsystem">

Det är tekniskt möjligt att montera ett NFS-filsystem i en Overleaf-container, men det rekommenderas inte och kan leda till olika typer av prestandafel.

Ett vanligt fel som uppstår vid kompilering är:

```text
EBUSY: resource busy or locked, unlink '/var/lib/overleaf/data/compiles/62f3d57bef7cf9005c364e75-62f3d57bef7cf9005c364e7a/.nfs573663533034825247625441'
```

Vi avråder särskilt från att använda NFS-baserade filsystem för tillfälliga data, till exempel de kataloger som används för kompileringsdata. Vi rekommenderar att du använder en lokal arbetsdisk, helst en lokal SSD, för följande kataloger.

För `docker-compose`-baserade installationer föreslår vi att du helt enkelt åsidosätter bind-monteringen från NFS, vilket gör att du slipper ändra sökvägar i applikationen. Här är ett utdrag ur en `docker-compose`-konfiguration som använder en arbetsdisk monterad på `/scratch`:

```yaml title="docker-compose excerpt"
services:
  sharelatex:
    environment:
      SANDBOXED_COMPILES_HOST_DIR: /scratch/compiles/
    volumes:
      - nfs:/var/lib/overleaf/data
      - /scratch/cache/:/var/lib/overleaf/data/cache
      - /scratch/compiles/:/var/lib/overleaf/data/compiles
      - /scratch/output/:/var/lib/overleaf/data/output
      - /scratch/tmp/:/var/lib/overleaf/tmp
```

Du behöver inte migrera några befintliga filer från NFS till deras nya plats efter uppdateringen. LaTeX-kompilatorn kan återskapa alla filer genom att köra en fullständig kompilering igen.

Mer information finns på: https://docs.overleaf.com/on-premises/support/troubleshooting#running-overleaf-with-an-nfs-filesystem

</Accordion>

<Accordion title="När Overleaf körs på Windows eller macOS startar inte tjänsten `mongo`">

Om du kör Overleaf på Windows eller macOS kan tjänsten `mongo` misslyckas med att starta om, med felet:

```text title="Example error"
Failed to start up WiredTiger under any compatibility version.
Reason: 1: Operation not permitted
```

För att undvika detta fel måste data lagras i en volym i stället för i en bind-monterad katalog (se dokumentationen för avbildningen `mongo` för mer information: https://github.com/docker-library/docs/blob/master/mongo/content.md#where-to-store-data). För att lagra data i Docker-volymer som monteras i MongoDB- och Redis-containrarna lägger du till följande i `config/docker-compose.override.yml` (skapa filen om den inte redan finns):

```yaml title="config/docker-compose.override.yml"
volumes:
  mongo-data:
  redis-data:

services:
  mongo:
    volumes:
      - mongo-data:/data/db

  redis:
    volumes:
      - redis-data:/data
```

Mer information finns på: https://docs.overleaf.com/on-premises/support/troubleshooting#running-overleaf-on-windows-or-macos-results-in-the-mongoservice-not-starting

</Accordion>

<Accordion title="Uppgradering till Redis 6.2 leder till en omstartsloop">

Använd kommandot `docker logs redis` för att skriva ut en kopia av loggarna.

Om du ser raden `Fatal: Can't initialize Background Jobs` ser hela utdata ut ungefär så här:

```text title="Redis log example"
1:M 11 Feb 2024 15:19:22.609 # Server initialized
1:M 11 Feb 2024 15:19:22.609 # Fatal: Can't initialize Background Jobs.
1:C 11 Feb 2024 15:19:26.055 # oO0OoO0OoO0Oo Redis is starting oO0OoO0OoO0Oo
```

Detta kan ha att göra med den Docker-version som används. En uppdatering till version >= 20.10.10 bör lösa problemet.

Mer information finns i Redis uppströmsärende: https://github.com/redis/redis/issues/12362

Referens: https://docs.overleaf.com/on-premises/support/troubleshooting#upgrading-to-redis-6.2-results-in-a-restart-loop

</Accordion>

<Accordion title="Felaktig orientering av förhandsgransknings-/miniatyrbilder i mallgalleriet">

Ibland kan de förhandsgransknings-/miniatyrbilder som genereras av Server Pro skapas med fel orientering och kräva manuella åtgärder för att rättas. Dessa bilder lagras i `/var/lib/overleaf/data/template_files/` (>= 5.0.3) och `/var/lib/sharelatex/data/template_files/` (tidigare versioner).

Vi rekommenderar att du säkerhetskopierar den här mappen innan du gör några ändringar.

Du behöver följa stegen nedan för varje berörd mall:

Hitta mallens ID: Gå till din instans mallgalleri (/templates/all), öppna en berörd mall och kopiera ID:t från URL:en (till exempel: https://your-instance-url/templates/6645d346c224815e9460a695). Kör korrigeringskommandot: Kör följande kommando från Docker-värden (ersätt mall-ID:t med det du kopierade och uppdatera sökvägen vid behov):docker exec sharelatex /bin/bash -c "mogrify -rotate 90 /var/lib/overleaf/data/template\_files/6645d346c224815e9460a695\_\*\{thumbnail,preview\}"

Referens: https://docs.overleaf.com/on-premises/support/troubleshooting#incorrect-orientation-of-template-gallery-preview-thumbnail-images

</Accordion>

<Accordion title="Kontrollera att du har aktiverat systemanrop. För pdflatex är detta 'pdflatex -shell-escape'.">

Kommandot `\write18` är inaktiverat som standard i Community Edition eftersom alla kompileringar sker i samma `sharelatex`-container; detta är det säkrare standardvalet.

Om du vill aktivera det för pdflatex skapar du en `latexmkrc`-fil i projektets rot med följande innehåll:

```perl title="latexmkrc"
$pdflatex = 'pdflatex --shell-escape';
```

Försök sedan kompilera om.

Referens: https://docs.overleaf.com/on-premises/support/troubleshooting#please-verify-that-you-have-enabled-system-calls.-for-pdflatex-this-is-pdflatex-shell-escape

</Accordion>
