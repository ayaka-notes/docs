#### 服務

Overleaf Pro 基礎架構由四個主要服務組成：`sharelatex`、`git-bridge`（選用）、`mongo` 與 `redis`。執行 Server Pro 主應用程式的 `sharelatex` 服務，依賴 `mongo` 與 `redis` 服務提供資料庫及快取／即時功能，並依賴 `git-bridge` 處理 [Git 整合](/zh-TW/on-premises/configuration/overleaf-toolkit/git-integration)（選用）。主機上唯一對外發布的連接埠是 80 埠，由 `sharelatex` 容器使用。

Server Pro 也可選擇支援以 [S3 相容儲存空間](/zh-TW/on-premises/configuration/overleaf-toolkit/s3)存放專案檔案與完整專案歷程，並能代理存取主要的 [Overleaf 文件網站](https://www.overleaf.com/learn)。如需詳細資訊，請參閱我們的[新增 LaTeX 使用者說明](/zh-TW/on-premises/configuration/overleaf-toolkit/adding-latex-user-help)頁面指南。

<Info>

如有需要，可以透過環境變數將 MongoDB 與 Redis 外部化，指向外部服務。如需詳細資訊，若您使用 Docker Compose，請參閱[設定 Overleaf](/zh-TW/on-premises/configuration)；若您使用 Overleaf Toolkit，請參閱 [Toolkit 設定](/zh-TW/on-premises/configuration/overleaf-toolkit/toolkit-settings)。

</Info>

#### 編譯

對於[沙箱編譯](/zh-TW/on-premises/configuration/overleaf-toolkit/sandboxed-compiles)，`sharelatex` 容器會協調建立新的容器來處理專案編譯；這是透過主機上的 Docker socket 完成的。您可以在[這裡](/zh-TW/on-premises/getting-started/microservices#editor-and-compile-process)進一步了解編輯器以及端對端的編譯／快取流程。

#### 網路

容器之間的通訊是透過專用橋接網路上的 Docker 內部 DNS 解析進行，且未啟用任何防火牆。預設情況下，上述服務使用各自的標準連接埠，但可透過環境變數進行設定。`sharelatex` 容器使用 80 埠提供外部網頁存取（由 Nginx 提供服務），`mongo` 容器使用 27017 埠，`redis` 則使用 6379 埠。

對於使用我們管理方案 [Overleaf Toolkit](https://github.com/overleaf/toolkit) 的客戶，您可以選擇透過環境變數[啟用 TLS 代理](/zh-TW/on-premises/configuration/overleaf-toolkit/tls-proxy)，使用 Nginx 終止 HTTPS 連線。或者，您也可以使用現有的 TLS 代理。

<Info>

您可以在[這裡](/zh-TW/on-premises/configuration/overleaf-toolkit/tls-proxy)查看說明請求流程的圖表。

</Info>

#### 摘要

* 在 Docker 網路之外，只有 80 埠可供存取，並繫結至 Nginx。**注意：** `sharelatex` 容器執行許多透過 HTTP 相互通訊的[服務](https://github.com/overleaf/overleaf/tree/main/services)。不過，這些連接埠**無法**從 Docker 網路外部存取。
* 在 Docker 網路內部，Overleaf 服務、MongoDB、Redis 與 Git Bridge 可以自由地相互通訊。
* 在[沙箱編譯](/zh-TW/on-premises/configuration/overleaf-toolkit/sandboxed-compiles)容器內部，沒有任何可用的網路。
