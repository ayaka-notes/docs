<Accordion title="在 NFS 檔案系統上執行 Overleaf">

技術上可以在 Overleaf 容器中掛載 NFS 檔案系統，但不建議這麼做，因為可能導致各種效能錯誤。

編譯時常見的錯誤之一是：

```text
EBUSY: resource busy or locked, unlink '/var/lib/overleaf/data/compiles/62f3d57bef7cf9005c364e75-62f3d57bef7cf9005c364e7a/.nfs573663533034825247625441'
```

特別是，我們不建議將以 NFS 為後端的檔案系統用於暫時性資料，例如用於編譯資料的目錄。對於以下目錄，我們建議使用本機暫存磁碟，最好是本機 SSD。

對於以 `docker-compose` 為基礎的架構，我們建議直接覆寫來自 NFS 的綁定掛載，這樣就不需要變更應用程式中的路徑。以下是一個 `docker-compose` 設定摘錄的範例，使用掛載於 `/scratch` 的暫存磁碟：

```yaml title="docker-compose excerpt"
services:
  sharelatex:
    environment:
      SANDBOXED_COMPILES_HOST_DIR: /scratch/compiles/
    volumes:
      - nfs:/var/lib/overleaf/data
      - /scratch/cache/:/var/lib/overleaf/data/cache
      - /scratch/compiles/:/var/lib/overleaf/data/compiles
      - /scratch/output/:/var/lib/overleaf/data/output
      - /scratch/tmp/:/var/lib/overleaf/tmp
```

更新後，不需要將任何現有檔案從 NFS 遷移到新位置。LaTeX 編譯器在重新執行完整編譯時可以重新建立所有檔案。

更多詳細資訊請參閱：https://docs.overleaf.com/on-premises/support/troubleshooting#running-overleaf-with-an-nfs-filesystem

</Accordion>

<Accordion title="在 Windows 或 macOS 上執行 Overleaf 導致 `mongo` 服務無法啟動">

如果您在 Windows 或 macOS 上執行 Overleaf，`mongo` 服務可能無法重新啟動，並出現以下錯誤：

```text title="Example error"
Failed to start up WiredTiger under any compatibility version.
Reason: 1: Operation not permitted
```

當 MongoDB 資料是從無法提供其所需語意的檔案系統（例如 Windows 掛載的目錄）綁定掛載時，就可能發生此錯誤。對於[搭配 WSL 2 的 Windows](/zh-TW/on-premises/installation/using-docker-compose/windows)，請將 Toolkit 放在 Ubuntu 的 Linux 家目錄下，並使用預設的綁定掛載。請參閱該平台指南中的 [MongoDB 檢查](/zh-TW/on-premises/installation/using-docker-compose/windows/troubleshooting#mongodb-fails-to-start)。

對於需要由 Docker 管理儲存空間的新安裝，以下覆寫設定會使用具名磁碟區（請參閱 [MongoDB 映像檔的儲存指引](https://github.com/docker-library/docs/blob/master/mongo/content.md#where-to-store-data)）。在既有的安裝上，變更掛載並不會遷移資料：切換之前請先備份並還原資料庫／快取，否則服務會看到空的磁碟區。請將以下內容加入 `config/docker-compose.override.yml`，並與任何既有設定合併：

```yaml title="config/docker-compose.override.yml"
volumes:
  mongo-data:
  redis-data:

services:
  mongo:
    volumes:
      - mongo-data:/data/db

  redis:
    volumes:
      - redis-data:/data
```

更多資訊請參閱：https://docs.overleaf.com/on-premises/support/troubleshooting#running-overleaf-on-windows-or-macos-results-in-the-mongoservice-not-starting

</Accordion>

<Accordion title="升級至 Redis 6.2 導致不斷重新啟動">

使用 `docker logs redis` 指令輸出日誌副本。

如果您看到 `Fatal: Can't initialize Background Jobs` 這一行，完整輸出大致如下：

```text title="Redis log example"
1:M 11 Feb 2024 15:19:22.609 # Server initialized
1:M 11 Feb 2024 15:19:22.609 # Fatal: Can't initialize Background Jobs.
1:C 11 Feb 2024 15:19:26.055 # oO0OoO0OoO0Oo Redis is starting oO0OoO0OoO0Oo
```

這可能與目前使用的 Docker 版本有關。更新至 >= 20.10.10 的版本應可解決此問題。

更多資訊請參閱 Redis 上游 issue：https://github.com/redis/redis/issues/12362

參考資料：https://docs.overleaf.com/on-premises/support/troubleshooting#upgrading-to-redis-6.2-results-in-a-restart-loop

</Accordion>

<Accordion title="範本庫預覽圖／縮圖方向不正確">

有時，Ayakaleaf Pro 產生的預覽圖／縮圖可能方向錯誤，需要手動介入修正。這些圖片儲存在 `/var/lib/overleaf/data/template_files/`。

建議在進行任何變更之前先備份此資料夾。

您需要對每個受影響的範本執行以下步驟：

找出範本 ID：前往您執行個體的範本庫（/templates/all），開啟受影響的範本，並從 URL 複製 ID（例如：https://your-instance-url/templates/6645d346c224815e9460a695）。執行修正指令：從 Docker 主機執行以下指令（將範本 ID 替換為您複製的 ID，並視需要更新路徑）：docker exec sharelatex /bin/bash -c "mogrify -rotate 90 /var/lib/overleaf/data/template\_files/6645d346c224815e9460a695\_\*\{thumbnail,preview\}"

參考資料：https://docs.overleaf.com/on-premises/support/troubleshooting#incorrect-orientation-of-template-gallery-preview-thumbnail-images

</Accordion>

<Accordion title="請確認您已啟用系統呼叫。對於 pdflatex，這是 'pdflatex -shell-escape'。">

由於所有編譯都在同一個 `sharelatex` 容器中進行，Community Edition 預設停用 `\write18` 指令；這是較安全的預設值。

如果您希望為 pdflatex 啟用它，請在專案根目錄中建立一個 `latexmkrc` 檔案，內容如下：

```perl title="latexmkrc"
$pdflatex = 'pdflatex --shell-escape';
```

然後嘗試重新編譯。

參考資料：https://docs.overleaf.com/on-premises/support/troubleshooting#please-verify-that-you-have-enabled-system-calls.-for-pdflatex-this-is-pdflatex-shell-escape

</Accordion>

<Accordion title="在「Initiating Mongo replica set...」之後，`bin/up` 失敗並顯示 `unable to upgrade to tcp, received 409` 或 `OCI runtime exec failed`">

這些錯誤表示 `mongo` 容器不斷當機並重新啟動。`bin/up` 會先啟動 MongoDB，然後在其中執行指令，而該指令會在容器重新啟動時失敗。`bin/docker-compose ps` 會顯示 `mongo` 服務的狀態為 `Restarting`。

若要找出實際原因，請查看 MongoDB 日誌：

```sh
bin/logs mongo
```

常見原因包括：

* <strong>CPU 不支援 AVX。</strong>MongoDB 5.0 及更新版本在 x86-64 上需要 AVX，日誌會顯示 `MongoDB 5.0+ requires a CPU with AVX support`。在虛擬機器中，請將 CPU 類型設為 `host`，讓 AVX 能夠傳遞給虛擬機器。
* <strong>Linux 核心 6.19 至 7.0.13。</strong>MongoDB 拒絕在這些核心上啟動。因應方式請參閱[軟體需求](/zh-TW/on-premises/installation/introduction#software-requirements)。
* <strong>資料是由較舊的 MongoDB 版本建立的。</strong>MongoDB 8.0 無法直接開啟 4.4 或 5.0 的資料。請一次升級一個主要版本，請參閱[更新 MongoDB](/zh-TW/on-premises/maintenance/updating-mongodb)。

</Accordion>

<Accordion title="日誌顯示「Running Overleaf Community Edition, skipping TexLive checks」">

這在 Ayakaleaf Pro 中是預期的行為，您可以忽略此訊息。當 `OVERLEAF_IS_SERVER_PRO` 不是 `true` 時就會輸出此訊息，而 Ayakaleaf Pro 映像檔正是如此。Ayakaleaf Pro 不需要此變數，因此請保持未設定。

</Accordion>

<Accordion title="`sharelatex` 容器不斷重新啟動">

在 Overleaf 啟動之前，容器會執行啟動檢查，只要其中一項失敗就會結束。Toolkit 以 `restart: always` 執行該容器，因此 Docker 會再次啟動它，而同一項檢查又會再次失敗。啟動輸出中會指出失敗的檢查項目：

```sh
bin/docker-compose logs --tail=100 sharelatex
```

常見原因包括：

* **`Missing required secrets`**：請在 `config/variables.env` 中設定 `OVERLEAF_INVITE_TOKEN_SECRET`，請參閱[環境變數](/zh-TW/on-premises/configuration/overleaf-toolkit/environment-variables)。
* **`ShareLaTeX to Overleaf rebranding`**：設定中仍使用 `SHARELATEX_` 變數或路徑；請依訊息指示重新命名。
* **`Checking can connect to mongo and redis` 之後出現錯誤**：Overleaf 無法連線至 MongoDB 或 Redis。請檢查 `bin/logs mongo` 與 `bin/logs redis`。

修正原因後，請執行 `bin/up -d`。

</Accordion>

<Accordion title="容器停在 `910_initiate_doc_version_recovery`，或以結束代碼 2 結束">

每次啟動時，容器都會依序執行其啟動指令碼，而記錄檔會以 `*** Running /etc/my_init.d/<script>...` 標示每一個指令碼。`910_initiate_doc_version_recovery` 只在曾經執行過 Overleaf 5.0.1 的執行個體上才有工作要做。在其他任何執行個體上，它會印出 `No recovery of doc versions needed.`，然後繼續啟動。它的輸出也會寫入 `OVERLEAF_DATA_PATH` 中的 `data/history/doc-version-recovery.log`。

結束代碼以及 `bin/docker-compose logs --tail=100 sharelatex` 的結尾可以說明發生了什麼事：

* **結束代碼 2**，且記錄檔以 `*** Init system aborted.` 結尾：容器被停止了，例如透過 `bin/stop`、`docker stop` 或在 `bin/up` 上按下 Ctrl+C。最後一行 `Running` 中的指令碼只是當時正在執行的那一個，它並沒有失敗。請使用 `bin/up -d` 再次啟動容器，並讓啟動完成。
* **結束代碼 1**，且記錄檔顯示 `*** /etc/my_init.d/<script> failed with status <n>`：該指令碼失敗了，其錯誤就在上方幾行。若 `910_initiate_doc_version_recovery` 以 `Detected unflushed changes while recovering doc versions` 失敗，表示該執行個體曾執行 5.0.1 且仍有未清空（unflushed）的編輯；請依照官方的 [Doc version recovery](https://docs.overleaf.com/on-premises/release-notes/release-notes-5.x.x/doc-version-recovery) 指南操作。

</Accordion>

<Accordion title="「Restricted, sorry you don’t have permission to load this page」">

當您的帳號已登入、但沒有權限開啟該頁面時，就會顯示此頁面，例如以非管理員帳號開啟管理頁面，或開啟未與您共用的專案。

若要開啟管理頁面，請以管理員帳號登入。現有的管理員可以將其他帳號設為管理員，您也可以使用 `create-user --admin` 指令建立管理員帳號，請參閱[使用者管理](/zh-TW/on-premises/user-and-project-management/user-management)。在開發環境（`develop/`）中，管理頁面還需要在 `develop/dev.env` 中設定 `ADMIN_PRIVILEGE_AVAILABLE=true`；Ayakaleaf Pro 映像檔已預先設定此項。

</Accordion>
