Kubernetes 執行的映像檔與 Toolkit 相同，並沒有獨立的 Kubernetes 映像檔。

| 映像檔                                               | 使用者                                                                  |
| ---------------------------------------------------- | ----------------------------------------------------------------------- |
| `ghcr.io/ayaka-notes/overleaf-pro:6.3.2`             | Deployment `overleaf`                                                   |
| `ghcr.io/ayaka-notes/overleaf-pro/git-bridge:6.3.2`  | [Git 整合](/zh-TW/on-premises/configuration/kubernetes/integrations/git-integration)（選用），標籤與上方相同 |
| `ghcr.io/ayaka-notes/texlive-*`                      | 編譯，已於[步驟 0](/zh-TW/on-premises/installation/using-kubernetes/0.-prepare-the-nodes) 拉取至節點的 Docker 中 |

這些映像檔公開於 [ghcr.io](https://github.com/ayaka-notes/ayakaleaf-pro/pkgs/container/overleaf-pro/)，支援 amd64 與 arm64，因此 kubelet 不需要憑證即可拉取。

<Warning>

請一律使用版本標籤（例如 `6.3.2`），而不要使用 `latest`。升級會執行資料庫遷移，且必須依照[在 Kubernetes 上升級](/zh-TW/on-premises/maintenance/upgrading-on-kubernetes)進行；若使用會變動的標籤，Pod 每次被重新排程時都可能被升級。

</Warning>

### Q\&A

<Accordion title="我們的節點無法連線至 ghcr.io，該怎麼辦？">

<strong>回答：</strong>請將映像檔複製到節點可存取的映像檔登錄庫，並在 manifest 中使用該名稱，例如：

```bash
docker pull ghcr.io/ayaka-notes/overleaf-pro:6.3.2
docker tag ghcr.io/ayaka-notes/overleaf-pro:6.3.2 registry.example.com/ayakaleaf/overleaf-pro:6.3.2
docker push registry.example.com/ayakaleaf/overleaf-pro:6.3.2
```

若登錄庫未使用 TLS，containerd 需要在每個節點上有一個內容為 `server = "http://<registry>"` 的 `/etc/containerd/certs.d/<registry>/hosts.toml`，並依照[步驟 0](/zh-TW/on-premises/installation/using-kubernetes/0.-prepare-the-nodes) 設定 `config_path`。Docker 本身只會以純 HTTP 推送至 `localhost`，因此請在登錄庫主機上透過 `localhost:<port>` 推送，或將其加入 `insecure-registries`。

</Accordion>
