`bin/podman-setup` 會檢查 Ayakaleaf Pro 在 Podman 上所需的一切。不帶選項時它只回報結果；加上 `--apply` 時，它還會修正發現的問題。

<Steps>
<Step title="檢查主機">
```bash title="Check only"
bin/podman-setup
```

在全新的主機上，大多數檢查都會失敗，例如：

```text
====== Packages ======
[✗] podman not installed
[✗] podman-docker not installed
...
====== Summary ======
[✓] 7 passed  [!] 13 warnings  [✗] 4 failures
```
</Step>

<Step title="套用修正">
```bash title="Check and fix"
bin/podman-setup --apply
```

請在終端機中執行它：執行系統層級的步驟時，它會詢問您的 `sudo` 密碼。它也會下載 Ayakaleaf Pro 映像檔以擷取其中的 seccomp 設定檔，第一次執行需要幾分鐘。最後，它會再次檢查主機：

```text
====== Summary ======
[✓] 23 passed  [!] 2 warnings  [✗] 0 failures
[!] Warnings remaining:
[!] not logged in to quay.io
[!] container → socket skipped (sharelatex not running)
```

此時出現這兩個警告都是預期中的：

* `not logged in to quay.io`：這項檢查來自官方 Toolkit，在那裡 Server Pro 映像檔位於私有登錄中。Ayakaleaf Pro 映像檔在 `ghcr.io` 上公開提供，無需登入，因此可以忽略它。安裝完成後它也會一直存在。
* `container → socket skipped (sharelatex not running)`：這項測試需要正在執行的執行個體。您將在 [3. 啟動 Ayakaleaf Pro](/zh-TW/on-premises/installation/using-podman/3.-start-ayakaleaf-pro) 中再次執行此指令碼。

所有檢查通過時指令碼以 `0` 結束，有警告時以 `1` 結束，有失敗時以 `2` 結束。由於 quay.io 警告，預期結果是 `1`。
</Step>
</Steps>

### 指令碼會變更什麼 {#what-the-script-changes}

使用 `--apply` 時，指令碼可能會變更以下內容。

系統層級，透過 `sudo`：

* 使用 `dnf` 安裝 `podman`、`podman-docker`、`git`、`curl`、`checkpolicy` 和 `policycoreutils`。
* 使用 `loginctl` 為您的使用者啟用 lingering，讓您登出後容器仍會繼續執行。
* 建立 `/etc/containers/nodocker`，用來隱藏 "Emulate Docker CLI using podman" 訊息。
* 當 `SELINUX_MODE=managed` 時，載入 SELinux 原則模組 `podman_socket_clsi`。

針對您的使用者：

* 啟用使用者服務 `podman.socket`，也就是 Ayakaleaf Pro 用來啟動編譯的 Docker 相容 API。
* 從 GitHub 安裝 Docker Compose v2 到 `~/.local/bin/docker-compose`，並在 `~/.docker/cli-plugins/` 中建立連結。
* 在 `~/.config/containers/containers.conf` 中讓 Podman 使用這個 Compose。
* 在 `~/.config/containers/registries.conf.d/overleaf-toolkit.conf` 中加入別名 `mongo` 和 `redis`，讓 Podman 知道要從哪裡提取這些簡短的映像檔名稱。

在 Toolkit 中：

* 將 `config/overleaf.rc` 中的 `DOCKER_SOCKET_PATH` 和 `DOCKER_HOST` 設定為 `/run/user/<uid>/podman/podman.sock`。
* 從 Ayakaleaf Pro 映像檔中擷取編譯用的 seccomp 設定檔到 `config/seccomp/<version>/clsi-profile.json`，並在 `config/variables.env` 中設定 `SECCOMP_PROFILE`。與 Docker 不同，Podman 需要將這個設定檔作為主機上的檔案。
* 在 `config/selinux/` 中建置 SELinux 原則模組。
* 在 `data/` 中的資料目錄建立後，使用 `podman unshare chown` 設定它們的擁有者。

<Info>

每項變更都對應一項檢查。如果您手動變更了某些內容，例如 `config/overleaf.rc` 中的設定，請再次執行 `bin/podman-setup` 進行驗證。

</Info>
