與 Overleaf Server Pro 一樣，我們的 Ayakaleaf Pro 以 Docker 容器形式提供，可直接替換使用，並額外包含透過 LDAP 與 SAML2 提供的 SSO、更強的安全性、追蹤修訂、評論、我們最佳化的 TeX Live 版本、範本以及管理面板等功能。

* 如果您只是想測試 Ayakaleaf Pro 的功能或試用展示環境，可以參考我們的 [using-the-github-codespace.md](/zh-TW/on-premises/installation/using-the-github-codespace  "mention") 教學。展示環境使用最精簡的 TeX Live 安裝，因此您的部分專案可能無法成功編譯。
* 如果您從未部署過任何版本的 Overleaf，請先參閱[設定 Docker](/zh-TW/on-premises/installation/setup-docker) 安裝 Docker Engine，然後再[使用 Toolkit](/zh-TW/on-premises/installation/using-the-toolkit  "mention") 安裝 Overleaf。
* 如果您已部署了 Overleaf Community Edition，請參閱 [migrate-from-existing.md](/zh-TW/on-premises/installation/migrate-from-existing  "mention") 遷移至 Ayakaleaf Pro。
* 如果您偏好使用 Claude 或 Codex 等代理，可以參閱：[using-claude-or-codex.md](/zh-TW/on-premises/installation/using-claude-or-codex  "mention")。
* 如果您需要在離線或隔離網路環境中部署，請參閱：[air-gapped-offline-deployments.md](/zh-TW/on-premises/installation/air-gapped-offline-deployments  "mention")。
* 如果您是現有的 Server Pro 使用者，請在遷移至 Ayakaleaf Pro 之前先開一個 issue 告知我們，因為範本資料的儲存格式略有不同。我們非常樂意免費協助您從 Server Pro 遷移至 Ayakaleaf Pro。
* 如果哪天您用膩了 Ayakaleaf Pro，想切換回官方的 Overleaf Community Edition，這也完全支援，您的資料不會遺失。使用官方 Overleaf Toolkit 的使用者，只需移除您的覆寫 YAML 檔案即可；使用 ayaka-notes toolkit 的使用者，請停用 `SERVER_PRO` 選項。之後一切都會回復為標準的 Community Edition。

### 硬體需求

我們進行了相關測試，發現若在 2 核心、2 GB RAM 的伺服器上執行 Overleaf，其主要以 Node.js 為基礎的核心元件約會消耗 1 GB 記憶體。Redis 與 MongoDB 可能還需要額外 0.5 GB，而啟動一個用於編譯的沙箱 Docker 容器又會消耗 0.3 GB。這表示 2 核心、2 GB 的伺服器實際上一次只能處理約一個並行編譯。

* 安裝 Ayakaleaf Pro 的最低硬體需求為 2 核心 CPU 與 3 GB RAM。
* 由於我們的 TeX Live 映像檔體積較大，啟用沙箱編譯至少需要 40 GB 的儲存空間。
* 如果您想安裝 2020 至 2026 年的完整 TeX Live 映像檔，請確保至少有 150 GB 的可用磁碟空間。

以下是針對不同使用情境的建議硬體配置：

| 使用情境                                             | 建議配置                                                                            |
| ---------------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| 個人使用，偶爾協作          | 2 個 CPU 核心、4 GB RAM、80 GB 儲存空間                                                                 |
| 小型團隊，最多 10 位使用者，輕度協作 | 2 個 CPU 核心、8 GB RAM、256 GB 儲存空間                                                                |
| 中型團隊，最多 100 位使用者                  | 4 個 CPU 核心、16 GB RAM、1 TB 儲存空間                                                                 |
| 大規模或大學部署                | 分散式叢集部署，搭配 S3 儲存；如需部署協助，請與我們聯絡 |

### 軟體需求

在軟體需求方面，我們建議使用較新且穩定的 Ubuntu 版本（例如 2025–2026 年使用 Ubuntu 24.04，2023–2024 年使用 Ubuntu 22.04），並搭配最新穩定版的 Docker。

<Info>

穩定性優先：請選擇已發布一段時間的最新 Ubuntu LTS，而非剛發布的版本。例如，截至 2026 年 10 月，Ubuntu 26.04 尚不受支援：它搭載 Linux 核心 7.0，而 MongoDB 在 Linux 核心 6.19 至 7.0.13 上會拒絕啟動（[詳細資訊](https://www.mongodb.com/docs/manual/administration/production-notes/)），因此請使用 Ubuntu 24.04。

</Info>

我們不建議在 Windows 或其他不受支援的作業系統（例如 CentOS）上部署 Ayakaleaf Pro，因為在安裝與運作過程中可能會遇到相容性問題或非預期的狀況。

不過，如果您想嘗試在 ARM 架構系統或 macOS 上部署 Ayakaleaf Pro，歡迎與社群分享您的經驗與意見回饋。

### LaTeX 效能

LaTeX 是單執行緒程式，一次只能使用一個 CPU 核心。編譯單一文件時，效能主要受限於 CPU 的單核心時脈。因此，CPU 的單核心效能越快，編譯文件的速度就越快。更多的 CPU 核心只有在多位使用者同時編譯文件時才有幫助。

以 [ThuThesis 範本](https://www.overleaf.com/latex/templates/thuthesis-tsinghua-university-thesis-latex-template/cfwgcxtvkbsx)為例，在 Intel Core i9-14900K（5.6 GHz）上的編譯時間約為 6 秒，而在搭載 AMD EPYC 7763（3.2 GHz）的 Azure Standard D2as v5 執行個體（2 個 vCPU、8 GiB RAM）上則約需 13 秒。

當然，實際的編譯效能取決於您的硬體配置。大多數伺服器 CPU 的時脈不會像 14900K 那麼高，因此您需要在成本與編譯速度之間取捨。

此外，我們也對 LaTeX 編譯效能進行了深入分析。如有興趣，請參閱我們的部落格文章 [Overleaf Benchmark: A Deep Research of Concurrent LaTeX Compilation in Overleaf (SaaS and Self-host)](/zh-TW/blog/2026/overleaf-benchmark  "mention")。
