我們在此彙整了一些關於 Ayakaleaf Pro 的常見問題解答。

### 基本問題 {#basic-question}

<Accordion title="Q01：Ayakaleaf Pro 是免費試用版嗎？需要授權嗎？">

不是。Ayakaleaf Pro 完全免費使用。它不是試用版，也不需要任何授權。

</Accordion>

<Accordion title="Q02：Ayakaleaf Pro 是否包含 Overleaf Server Pro 的所有功能？">

是的。Ayakaleaf Pro 包含 Overleaf Server Pro 的所有功能，包括 Git-Bridge 整合。它還包含部分 Overleaf SaaS 平台的功能。我們會持續開發並改進 Ayakaleaf Pro。

</Accordion>

<Accordion title="Q03：Overleaf Server Pro 的價格是多少？">

Overleaf Server Pro 每位使用者每年的費用約為 \$300。它至少需要購買 10 個授權，因此部署費用每年約 \$3,000 起。美國規模較小的公開合約顯示，每位使用者每年的費用約為 \$320–\$370。這使得 Server Pro 相當昂貴，尤其是對小型團隊而言。有據可查的採購紀錄與價格請參閱 [#information-and-price-about-overleaf-server-pro](/zh-TW/on-premises#information-and-price-about-overleaf-server-pro  "mention")。

</Accordion>

<Accordion title="Q04：為什麼 Overleaf Server Pro 不包含 GitHub 同步或 AI 功能？">

Overleaf Server Pro 常被政府機關使用。這些機構會將其部署在私人網路中，並嚴格控管存取權限。為了保護敏感資料，其內建功能會避免與第三方服務交換資料。如果您需要 GitHub 同步、AI 或類似的連網功能，Overleaf 建議您訂閱其 SaaS 平台。

</Accordion>

<Accordion title="Q05：Ayakaleaf Pro 安全可靠嗎？">

Ayakaleaf Pro 是開放原始碼軟體。我們使用 Codex Security 等工具審查程式碼，以強化其安全性與可靠性。如果您未啟用第三方資料同步，您的資料就會保留在您的伺服器上。Ayakaleaf Pro 不包含任何會將您的資料傳送至其他地方的遙測功能。

</Accordion>

<Accordion title="Q06：Ayakaleaf Pro 會長期維護嗎？">

我們會盡一切努力長期維護此專案。

</Accordion>

<Accordion title="Q07：Ayakaleaf Pro 是否合規？">

Ayakaleaf Pro 是一個社群分支（fork）。其程式碼與整合的功能皆來自社群貢獻，並以 AGPL v3 授權發布。只要部署符合該授權的要求，即可遵循此授權規範。

</Accordion>

<Accordion title="Q08：為什麼這個專案叫做 Ayakaleaf Pro？">

此專案最初於 2024 年命名為 Overleaf Pro。開發曾暫停一段時間，並於 2025 年底重新啟動。2026 年第一季，Overleaf 將其具備 AI 功能的訂閱方案更名為 Pro。社群回饋也指出，Overleaf Pro 這個名稱可能帶來商標與冒名的風險，讓使用者誤以為此專案是官方產品。

為了避免這種混淆，我們將專案更名為 Ayakaleaf Pro。這個名稱可以解讀為「Ayaka-notes Overleaf Pro」。維護者（你可以叫我 ayaka！）從五年多前的學生時期就開始參與 Overleaf 社群開發，這份經驗支撐著我們長期維護的承諾。

</Accordion>

<Accordion title="Q09：Ayakaleaf Pro 與較新的 AI 打造 LaTeX 編輯器有何不同？">

自 2026 年以來，開源社群已推出許多以 AI 打造的 LaTeX 編輯器，包括 OpenAI Prism。Ayakaleaf Pro 將您的資料與服務保留在您自己的伺服器上，讓您能直接掌控自己的部署與資料。

許多實驗性的社群編輯器並沒有明確的長期維護計畫。第三方 LaTeX 編譯平台也可能在使用者基礎或營收不足時停止營運。Ayakaleaf Pro 提供全部原始碼，並讓您能自行託管所有服務。即使維護停止，您現有的自行託管服務仍可繼續運作。

</Accordion>

<Accordion title="Q10：GitHub 儲存庫 ayaka-notes/overleaf-pro 怎麼了？">

隨著專案更名（請參閱 Q08），它已更名為 [ayaka-notes/ayakaleaf-pro](https://github.com/ayaka-notes/ayakaleaf-pro)。它並未被封存或取代：仍是同一個儲存庫，GitHub 會將舊的 `ayaka-notes/overleaf-pro` 連結與 Git 遠端重新導向至新名稱。Docker 映像檔則維持原名 `ghcr.io/ayaka-notes/overleaf-pro`，因此您不需要變更 `config/overleaf.rc` 或 `config/version`。

</Accordion>

### 功能 {#features}

<Accordion title="Q01：Ayakaleaf Pro 提供哪些功能？我可以提出新功能需求嗎？">

目前的功能清單請參閱我們的文件。如果有您希望我們新增的功能，歡迎在 GitHub 上開立 issue（功能需求）。我們會盡力實作使用者提出的功能，但開發需要時間，我們無法保證每項功能都能立即推出。

</Accordion>

<Accordion title="Q02：我開發了一些功能，可以提交 PR 嗎？一定會被接受嗎？">

歡迎貢獻，但不保證一定會被接受。我們會根據每個 PR 對底層 Overleaf 程式碼的影響、維護負擔，以及為使用者帶來的價值進行評估。我們會盡力合併並維護有價值的貢獻。

不過，對於變更幅度過大、由未經審查或未被充分理解的 AI 生成程式碼（「vibe coding」）組成，或會新增難以長期維護之功能的 PR，我們可能會予以拒絕。

</Accordion>

<Accordion title="Q03：如何設定特定功能？">

我們通常會在推出新功能時同步更新文件。詳細的設定說明與可用環境變數的解釋，請參閱相關文件。

</Accordion>

<Accordion title="Q04：Python Runner 可以使用哪些 Python 函式庫？">

Python Runner 是在使用者的瀏覽器中以 [Pyodide](https://pyodide.org/) 0.29.3 執行 Python，而非在伺服器上執行。它會從 [Pyodide 內建的套件](https://pyodide.org/en/0.29.3/usage/packages-in-pyodide.html)中載入您程式碼所匯入的套件，例如 NumPy、pandas 與 Matplotlib。透過 `pip` 安裝的套件及其他套件均無法使用。伺服器端不需要任何設定。

</Accordion>

<Accordion title="Q05：拼字檢查可以檢查日文或中文嗎？">

不行。拼字檢查器沒有日文或中文的字典，因此這些語言不在拼字檢查語言清單中。使用者可以在編輯器設定中為專案關閉拼字檢查。

若不希望某個單字被標示為拼字錯誤，請在該單字上按右鍵並選擇 **Add to dictionary**。新增的單字會儲存在您的帳號中，並套用至您所有的專案。若要檢視或移除這些單字，請開啟編輯器設定，然後前往 **Spelling and language → Dictionary → Edit**。新增單字並不會新增拼字檢查語言。

</Accordion>

<Accordion title="Q06：我可以新增外掛嗎？">

沒有外掛安裝程式。各項功能是原始碼中 `services/web/modules` 內的模組，會建置進 Docker 映像檔，並透過本文件中的設定啟用。若要新增您自己的功能，請在原始碼中新增模組並建置您自己的映像檔。

</Accordion>

### 部署 {#deployment}

<Accordion title="Q01：Ayakaleaf Pro 是否支援在 k8s 中進行分散式部署？">

對大多數使用者而言，我們建議使用 [Toolkit](/zh-TW/on-premises/installation/using-docker-compose) 進行部署。Kubernetes 支援目前為實驗性質：[使用 Kubernetes](/zh-TW/on-premises/installation/using-kubernetes) 提供了我們以單一或多個副本測試過的 manifest，但叢集會增加營運複雜度與維護工作量。[沙箱編譯](/zh-TW/on-premises/configuration/overleaf-toolkit/sandboxed-compiles)會透過 Docker socket 建立編譯容器，因此每個執行 Ayakaleaf Pro 的節點都需要 Docker Engine。我們不提供 CRI-O、Podman 或 Quadlet 的設定。

</Accordion>

<Accordion title="Q02：在服務數千名使用者時，如何確保可用性？">

請參閱我們的[水平擴展](/zh-TW/on-premises/maintenance/horizontal-scaling)指南。您可以部署多個 Overleaf 執行個體，並設定負載平衡器將流量分散至各個執行個體。

</Accordion>

<Accordion title="Q03：你們可以協助我部署或遷移嗎？">

如果您已有 Overleaf Server Pro 執行個體，我們很樂意協助您遷移至 Ayakaleaf Pro。請透過電子郵件或 issue 與我們聯絡。

</Accordion>

<Accordion title="Q04：我可以將 Ayakaleaf Pro 架設在 URL 子路徑下嗎，例如 `https://example.com/overleaf`？">

不行。Ayakaleaf Pro 必須從網域的根目錄提供服務。請使用專用的網域或子網域，例如 `https://overleaf.example.com`。

</Accordion>

<Accordion title="Q05：我可以在 Windows 或 macOS 上執行 Ayakaleaf Pro，或不使用 Toolkit 嗎？">

可以。Toolkit 可在 [Linux](/zh-TW/on-premises/installation/using-docker-compose/linux)、[搭配 Docker Desktop 的 macOS](/zh-TW/on-premises/installation/using-docker-compose/macos)，以及[搭配 WSL 2 與 Docker Desktop 的 Windows](/zh-TW/on-premises/installation/using-docker-compose/windows) 上執行。對於共用與正式環境的伺服器，我們建議使用 Linux。macOS 與 Windows 指南中包含沙箱編譯的設定。

我們不提供獨立的 `docker-compose.yml`。若要查看 Toolkit 所使用的 Compose 設定，請在 Toolkit 目錄中執行 `bin/docker-compose config`。

</Accordion>

<Accordion title="Q06：如何解除安裝 Ayakaleaf Pro？">

沒有解除安裝指令碼。請在 Toolkit 目錄中：

1. 使用 `bin/docker-compose down` 停止並移除容器。
2. 刪除資料。預設情況下，資料位於 Toolkit 的 `data/` 目錄中。如果您在 `config/overleaf.rc` 中變更過 `OVERLEAF_DATA_PATH`、`MONGO_DATA_PATH`、`REDIS_DATA_PATH` 或 `GIT_BRIDGE_DATA_PATH`，也請刪除這些目錄。此操作無法復原，因此若您可能還需要這些資料，請先進行[備份](/zh-TW/on-premises/maintenance/data-and-backups)。
3. 刪除 Toolkit 目錄。
4. 移除 Docker 映像檔（可使用 `docker images` 列出）：`ghcr.io/ayaka-notes/overleaf-pro`、git-bridge 映像檔、`mongo`、`redis` 以及 TeX Live 映像檔。

</Accordion>

<Accordion title="Q07：如何停止、啟動或重新啟動 Ayakaleaf Pro？">

請在 Toolkit 目錄中執行以下指令：

* `bin/stop` 會停止所有容器，`bin/start` 則會再次啟動它們。容器會被保留，因此使用者會維持登入狀態。
* `bin/up -d` 會建立容器並在背景中啟動。變更 `config/variables.env`、`config/overleaf.rc` 或 `config/version` 後請執行此指令：它會重新建立設定有所變更的容器，變更也只有在此時才會生效。`bin/stop` 與 `bin/start` 不會套用這些變更。
* `bin/docker-compose restart sharelatex` 只會重新啟動 Overleaf 容器，不會套用設定變更。

如果每次 `bin/up` 重新建立容器時使用者都會被登出，請設定 `OVERLEAF_SESSION_SECRET`，請參閱[環境變數](/zh-TW/on-premises/configuration/overleaf-toolkit/environment-variables)中的問與答。

</Accordion>

<Accordion title="Q08：OAuth 回呼 URL 要填在哪裡？">

請填在您於服務供應商處建立的應用程式中，而非 Ayakaleaf Pro 中。這些整合在 `config/variables.env` 中都沒有回呼設定：Ayakaleaf Pro 會根據 `OVERLEAF_SITE_URL` 組出每個回呼 URL 並傳送給供應商，若與應用程式所登錄的 URL 不符，供應商便會拒絕。因此您只需要在供應商處登錄回呼 URL，並將 `OVERLEAF_SITE_URL` 設為使用者開啟的位址即可。

| 整合 | 供應商處的欄位 | 值 |
| --- | --- | --- |
| [GitHub](/zh-TW/on-premises/configuration/overleaf-toolkit/integrations/github-synchronisation) | Authorization callback URL | `${OVERLEAF_SITE_URL}/user/github-sync/oauth2/callback` |
| [GitLab](/zh-TW/on-premises/configuration/overleaf-toolkit/integrations/gitlab-synchronisation) | Redirect URI | `${OVERLEAF_SITE_URL}/user/gitlab-sync/oauth2/callback` |
| [Gitea](/zh-TW/on-premises/configuration/overleaf-toolkit/integrations/gitea-synchronisation) | Redirect URIs | `${OVERLEAF_SITE_URL}/user/gitea-sync/oauth2/callback` |
| [Dropbox](/zh-TW/on-premises/configuration/overleaf-toolkit/integrations/dropbox-synchronisation) | Redirect URIs（點選 **Add**） | `${OVERLEAF_SITE_URL}/user/dropbox/oauth/callback` |
| [Zotero](/zh-TW/on-premises/configuration/overleaf-toolkit/integrations/zotero-integration) | Callback URL | `${OVERLEAF_SITE_URL}/user/zotero/oauth/callback` |
| [Mendeley](/zh-TW/on-premises/configuration/overleaf-toolkit/integrations/mendeley-integration) | Redirect URL | `${OVERLEAF_SITE_URL}/user/mendeley/oauth/callback` |
| [OIDC 登入](/zh-TW/on-premises/configuration/overleaf-toolkit/authentication/oidc-authentication) | Redirect URI | `${OVERLEAF_SITE_URL}/oidc/login/callback` |
| [SAML 登入](/zh-TW/on-premises/configuration/overleaf-toolkit/authentication/saml-authentication) | ACS URL（Assertion Consumer Service） | `${OVERLEAF_SITE_URL}/saml/login/callback` |

如果您變更了 `OVERLEAF_SITE_URL`（例如改用新網域），也請在每個供應商處更新 URL，否則連結會失敗。

</Accordion>

<Accordion title="Q09：資料儲存在哪裡？我需要多少磁碟空間？">

預設情況下，所有資料都保存在伺服器的本機磁碟上，位於 Toolkit 的 `data/` 目錄中：`data/overleaf`（專案檔案、歷程記錄與編譯輸出）、`data/mongo` 與 `data/redis`。對於使用者少於 1000 人的執行個體，我們建議使用本機磁碟並定期進行[備份](/zh-TW/on-premises/maintenance/data-and-backups)。

Ayakaleaf Pro 映像檔約佔 5 GB。[簡介](/zh-TW/on-premises/installation/introduction)中提到的 40 GB 最低需求是針對沙箱編譯，其每個 `texlive-full` 映像檔約佔 28 GB。若未使用沙箱編譯，編譯會在 `sharelatex` 容器內以 TeX Live basic scheme 加上 `latexmk`、`texcount`、`synctex`、`etoolbox` 與 `xetex` 執行，因此許多專案會因缺少套件而失敗。之後 `data/` 目錄會隨著您的專案及其歷程記錄而增長；可使用 `du -sh data/*` 檢查。

</Accordion>

<Accordion title="Q10：我可以讓 Ayakaleaf 在 Windows 上全天候 24 小時執行嗎？">

可以，前提是 Windows 保持喚醒狀態，且 Docker Desktop 持續執行。請開啟 **Start Docker Desktop when you sign in to your computer**，保留 Toolkit 的 `restart: always` 原則，並在使用交流電源時停用自動睡眠與休眠。螢幕可以關閉；筆電上蓋的行為是另一項獨立設定。在執行 `bin/up -d` 後關閉 Ubuntu 終端機，並不會停止以分離模式執行的容器。結束 Docker Desktop、暫停其引擎或執行 `wsl --shutdown` 則會中斷服務。

Docker Desktop 的 Resource Saver 與 Windows 睡眠不同：它只在沒有任何容器執行時才會生效，因此正在執行的 Ayakaleaf 堆疊不會只因為沒有人在編輯就被視為閒置。Windows 重新開機後，登入時啟動的設定仍需要有人登入。檢查與復原步驟請參閱[保持執行個體可用](/zh-TW/on-premises/installation/using-docker-compose/windows/6.-post-installation-tasks#keep-the-instance-available)。當可用性不能依賴互動式桌面登入時，我們仍建議使用 Linux。

</Accordion>

<Accordion title="Q11：Docker Desktop 顯示虛擬化已停用。我需要 Hyper-V 嗎？">

本指南使用 **WSL 2 後端**。它需要在 BIOS/UEFI 中啟用 CPU 虛擬化、Windows 的 **Virtual Machine Platform** 功能，以及可正常運作的 WSL 2 安裝。完整的 **Hyper-V** 功能是 Docker Desktop 的另一種後端，並不是此 WSL 設定的先決條件。

請檢查 **工作管理員 → 效能 → CPU → 虛擬化**，並在 PowerShell 中執行 `wsl --list --verbose`。像 `0x80370102` 這類錯誤可能表示虛擬化、該 Windows 功能或開機 hypervisor 已停用。請參閱 [Windows 安裝疑難排解步驟](/zh-TW/on-premises/installation/using-docker-compose/windows/troubleshooting#wsl-or-docker-reports-that-virtualization-is-unavailable)，其中附有 Microsoft 與 Docker 的修復連結。啟用必要功能後請重新啟動 Windows；重新安裝 Ayakaleaf 無法修復無法啟動的 Docker 引擎。

</Accordion>

### LaTeX {#latex}

<Accordion title="Q01：使用者的 LaTeX 專案編譯是否相互隔離？是否啟用 Shell Escape？">

啟用沙箱編譯（Sandbox Compiles）後，每位使用者的編譯都會在獨立的 Docker 容器中執行，並與其他使用者的編譯相互隔離。沙箱編譯預設啟用 Shell Escape。

</Accordion>

<Accordion title="Q02：沙箱編譯的映像檔可靠嗎？編譯可能會失敗嗎？">

過去三年來，我們持續改進用於沙箱編譯的 TeX Live Full 映像檔。在大多數情況下，能在 overleaf.com 上編譯的專案，也能在 Ayakaleaf Pro 中正確編譯。如果缺少所需的字型，請手動將該字型上傳至您的專案。

</Accordion>

<Accordion title="Q03：我的專案無法編譯，可以協助我排除問題嗎？">

請將您的專案上傳至 Overleaf 官方網站，啟用唯讀連結分享，並在 GitHub issue 中附上該連結。

如果某個專案能在 Overleaf 官方網站上成功編譯，卻無法在 Ayakaleaf Pro 中編譯，我們會調查並修正造成問題的錯誤。超出此範圍的編譯問題不在我們的支援範圍內。

</Accordion>
