<Accordion title="現有安裝的 Zotero／Mendeley 遷移">

升級至重新發布的 6.3.0 映像檔時，請使用下方的指令碼遷移現有的 Zotero/Mendeley 連結書目中繼資料。此遷移搭配修正 `12031b8dfd`。

此遷移會將 `zoteroGroupId`／`mendeleyGroupId` 重新命名為 `group_id`，將 `importedByUserId` 重新命名為 `importer_id`，並移除 `importedByName`。

執行遷移前，請先備份 MongoDB 並停止應用程式。保持 MongoDB 執行中，然後開啟其 shell（將 `mongo` 替換為您的容器名稱）：

```bash
docker exec -it mongo mongosh
```

在 `mongosh` 中執行以下內容（將 `sharelatex` 替換為您的資料庫名稱）：

```javascript
use sharelatex

(async () => {
  let updated = 0
  await db.projects.find({}, { rootFolder: 1 }).forEach(async project => {
    const changes = {}
    function visit(folders, path) {
      for (const [i, folder] of (folders || []).entries()) {
        const folderPath = `${path}.${i}`
        for (const [j, file] of (folder.fileRefs || []).entries()) {
          const data = { ...file.linkedFileData }
          if (!["zotero", "mendeley"].includes(data.provider)) continue
          const groupKey = `${data.provider}GroupId`
          if (![groupKey, "importedByUserId", "importedByName"].some(key => key in data)) continue
          for (const [oldKey, newKey] of [[groupKey, "group_id"], ["importedByUserId", "importer_id"]]) {
            if (data[oldKey] != null && data[oldKey] !== "") {
              const value = String(data[oldKey])
              if (newKey in data && data[newKey] !== value) {
                throw new Error(`Conflicting ${newKey}: project ${project._id}, file ${file._id}`)
              }
              data[newKey] = value
            }
            delete data[oldKey]
          }
          delete data.importedByName
          changes[`${folderPath}.fileRefs.${j}.linkedFileData`] = data
        }
        visit(folder.folders, `${folderPath}.folders`)
      }
    }
    visit(project.rootFolder, "rootFolder")
    if (!Object.keys(changes).length) return
    const result = await db.projects.updateOne(
      { _id: project._id, rootFolder: { $eq: project.rootFolder } },
      { $set: changes }
    )
    if (!result.matchedCount) throw new Error(`Project changed during migration: ${project._id}`)
    updated += result.modifiedCount
  })
  print(`Updated ${updated} project(s).`)
})()
```

此指令碼會處理巢狀資料夾，且只會變更 Zotero/Mendeley 中繼資料。可以安全地重新執行：已完成的遷移在下次執行時會回報 `Updated 0 project(s).`。如果因衝突而停止，請檢查所回報的專案／檔案；較早的專案可能已經完成遷移。

啟動更新後的應用程式，重新載入編輯器，並以原始匯入者的身分重新整理現有的書目檔案。歷史快照不會被改寫。若要降級回舊版應用程式，請還原 MongoDB 備份。

我們非常自豪地宣布推出 Overleaf Pro 6.3.0，這是社群中功能最強大、最豐富的線上 LaTeX 編輯器。我們始終專注於改善使用者體驗，此版本帶來了重大變更與您一定會喜愛的精彩功能，包括 AI 助理與第三方參考文獻整合。

### 變更

* AI 聊天助理：直接在編輯器中，透過您自己的供應商與 AI 模型對話。
* LaTeX 錯誤助理：取得 AI 針對 LaTeX 編譯錯誤建議的修正方式。
* Mendeley 整合：以類似 Zotero 的方式從 Mendeley 匯入參考文獻。
* Open in Overleaf API：新增用於在 Overleaf 中開啟內容的 API。
* 範本庫：新增伺服器端分頁、搜尋與排序，大型範本庫不再需要在瀏覽器中載入所有範本。
* 翻譯：更新 6.3.0 的翻譯修補，包括所有支援語言的新介面文字。
* 上游 Overleaf 6.3.0：包含分頁式檔案編輯、淺色與深色主題各自的頁首標誌，以及相依套件與基礎映像檔更新。
* 新增 `OVERLEAF_HEADER_IMAGE_URL_LIGHT` 與 `OVERLEAF_HEADER_IMAGE_URL_DARK`，支援為淺色與深色主題分別設定頁首標誌圖片。
* 現在可以在編輯器的不同分頁中開啟檔案。
* 透過 `OVERLEAF_LINKED_URL_OUTBOUND_PROXY` 新增可設定的 HTTP(S) 代理支援（包括本機託管的代理），Open in Overleaf API 也會使用此設定。

#### 功能 04：範本分頁

範本庫現在會在 MongoDB 中進行分頁、排序與搜尋。無需任何準備即可運作；若有數千個範本，您仍可加入下列索引以維持速度（可安全地重新執行，`mongo`/`sharelatex` 為您的容器與資料庫名稱）：

```bash
docker exec mongo mongosh sharelatex --quiet --eval '
db.templates.createIndex({category:1,lastUpdated:-1},{name:"category_1_lastUpdated_-1",background:true});
db.templates.createIndex({lastUpdated:-1},{name:"lastUpdated_-1",background:true});
db.templates.createIndex({category:1,name:1},{name:"category_1_name_1_ci",collation:{locale:"en",strength:2},background:true});
db.templates.createIndex({name:1},{name:"name_1_ci",collation:{locale:"en",strength:2},background:true});
'
```

請保留兩個 `*_ci` 索引上的 `collation` 設定不變，因為範本庫使用相同的 collation 查詢，而 MongoDB 只會使用相符的索引。

## Ayakaleaf Pro 6.2.2

**發布日期：** 2026.07.23

請參閱：[https://github.com/ayaka-notes/ayakaleaf-pro/releases/tag/pro-v6.2.2](https://github.com/ayaka-notes/ayakaleaf-pro/releases/tag/pro-v6.2.2)

### 變更

反向移植上游 Overleaf `6.2.2` 中發布的官方緊急修補（以 `6.2.1` 為基礎）：

* 不再將專案邀請權杖密鑰洩漏到日誌中。邀請權杖加密器在每次加密／解密時都會記錄自身設定，其中包含由 `OVERLEAF_INVITE_TOKEN_SECRET` 衍生的加密密碼。
* 將外寄郵件從已停止支援的 AWS SES v1 用戶端遷移至 SESv2。設定為 `ses` 郵件驅動程式的執行個體可能完全無法寄送郵件；現在改由 `SESv2Client` 寄送。
* 以新的 `group-link-sharing` 功能旗標控制分享專案下拉選單中的群組項目，因此在不適用的執行個體上將不再提供群組連結分享。
* 修正協作者的分享專案對話框。先前以非擁有者身分開啟，或在停用 `sharing-updates` 流程時開啟，會發出一個必定失敗的請求，並顯示「something went wrong」錯誤。
* 在 document-updater 中新增 `scripts/flush_docs_with_pending_updates.js`，這是一個維護指令碼，用於復原專案被清空或永久刪除後，在 Redis 中仍留有卡住的 `PendingUpdates` 佇列的文件。支援 `--dry-run` 與 `--estimated-docs` 安全檢查。
* 更新相依套件：`multer` 2.2.0、`form-data` 2.5.6、`protobufjs` 7.6.3、`@grpc/grpc-js` 1.14.4。

此版本也包含以下來自 Ayakaleaf Pro 的修正與改進：

* 新增 16 種語言的完整翻譯（cs、da、de、es、fi、fr、it、ja、ko、nl、no、pl、pt、ru、sv、tr），修正密碼重設頁面等未翻譯的字串。修正 [#38](https://github.com/ayaka-notes/ayakaleaf-pro/issues/38)。
* 修正管理面板中「show N more projects」按鈕的項目數量，先前因複數佔位符未正確傳遞而顯示錯誤的數字。
* 修正 GitHub 匯出驗證錯誤，現在會透過靜態 i18n 鍵值而非原始訊息呈現，並移除 GitHub Sync 對話框中不再使用的錯誤鍵值。

## Ayakaleaf Pro 6.2.0

**發布日期：** 2026.07.10

請參閱：[https://github.com/ayaka-notes/ayakaleaf-pro/releases/tag/pro-v6.2.0](https://github.com/ayaka-notes/ayakaleaf-pro/releases/tag/pro-v6.2.0)

我們很自豪地宣布推出 Overleaf Pro 6.2.0，這是社群中功能最強大、最豐富的線上 LaTeX 編輯器。特別感謝 yu-i-i 與 davrot 的寶貴貢獻，他們強化了 GitHub Sync，並帶來了進階引用搜尋與 Zotero 整合。

### 注意事項

<Warning>

* 新增必要的環境變數 `OVERLEAF_INVITE_TOKEN_SECRET`。您必須使用 `openssl rand -base64 32` 產生此值。若未設定，您的 Overleaf 執行個體將無法啟動。
* 如果您啟用 GitHub Sync，就必須設定 `GITHUB_TOKEN_CIPHER_PASSWORD` 環境變數。此變數用於安全地加密 GitHub 存取權杖。若未設定，您的 Overleaf 執行個體將無法啟動。

</Warning>

* 新增 `DEFAULT_LATEX_COMPILER` 環境變數，用於設定新專案的預設編譯器（`pdflatex`、`latex`、`xelatex` 或 `lualatex`）。
* 重新設計的編輯器現在是唯一可用的選項。

### 變更

此版本包含以下改進與新功能。

* `MAX_UPLOAD_SIZE` 現在可以自行設定，不再限制為 **50 MB**。
* 修正停用沙箱編譯時容器不斷重新啟動的問題。
* 強制 OAuth2 的 PAT 刪除限定於擁有者範圍。
* 修正 LDAP 匯入問題。

功能包括：

* 新增以瀏覽器為基礎的 Python 執行器。
* 新增 Pandoc 支援，可匯入與匯出 Markdown、DOCX 及其他格式。
* 新增 GitHub Sync。
* 新增完整的中文翻譯。
* 新增 Zotero 整合。
* 新增 `DEFAULT_LATEX_COMPILER`。

這是一個測試版本，也是我們 Overleaf Pro 的初始版本。此版本不包含任何 Server Pro 的功能，僅作為我們的起點。我們之後會陸續加入新功能，例如管理面板與 git-bridge 等。

此版本推出了適用於 ARM 的 Overleaf Docker 映像檔。如果您有 Mac 或 ARM 架構的伺服器，可以試試看，但部分功能可能無法正常運作（尚未測試）。


### 二進位檔案遷移

此新版本將二進位檔案的儲存空間用量減半。

版本 `5.5` 包含線上遷移功能，讓升級過程中的停機時間降到最低。升級至 Server Pro `v6` 之前，請確認您已在執行最新版的 Server Pro `v5.5`（[5.x.x 版本資訊](https://docs.overleaf.com/on-premises/release-notes/release-notes-5.x.x)），並已執行遷移。

[查看完整的遷移說明](https://docs.overleaf.com/on-premises/release-notes/release-notes-5.x.x/binary-files-migration)。

### MongoDB 升級至 v8

此版本將最低 MongoDB 版本提高至 `8.0`。

如果您目前使用 MongoDB `v6` 或更早版本，需要一次升級一個主要版本（`v6 → v7 → v8`）。

<Warning>

請務必在升級**之前**備份[資料庫](https://docs.overleaf.com/on-premises/maintenance/data-and-backups)。若需要回復，您必須還原資料庫備份。

</Warning>

關於如何將 MongoDB 升級 `v6 → v7 → v8` 的說明，請參閱我們的[逐步指南](https://docs.overleaf.com/on-premises/maintenance/updating-mongodb#example-upgrading-mongodb-from-6.0-to-7.0-toolkit-users)。

### Redis 升級至 v7.4

此版本也將最低 Redis 版本提高至 `7.4`。

將 `config/overleaf.rc` 中的 `REDIS_IMAGE` 更新為 `REDIS_IMAGE=7.4`。

### 新功能

* 現在可以使用 `OVERLEAF_DISABLE_LINK_SHARING=true` 停用連結分享。
* 現在可以使用 `OVERLEAF_MAINTENANCE_MESSAGE` 與 `OVERLEAF_MAINTENANCE_MESSAGE_HTML` 自訂維護頁面的標題與內容。
* 可設定 `OVERLEAF_USER_HARD_DELETION_DELAY` 與 `OVERLEAF_PROJECT_HARD_DELETION_DELAY`（單位為毫秒），以修改已刪除使用者／專案的到期延遲時間（預設為 90 天）。

### 錯誤修正

* 修正含連結的頁尾呈現問題。
* 改善 SAML 登入錯誤時的錯誤訊息。
* 修正使用者在 SSO 登入時管理員狀態更新卻未新增稽核日誌項目的問題。
* 修正 Redis 啟用 TLS 時歷史記錄面板發生錯誤的問題。
* 使用非沙箱編譯時，現在可以停止編譯。

### 其他變更

* 所有指向狀態頁面（透過 `OVERLEAF_STATUS_PAGE_URL` 設定）的連結現在都使用 `HTTPS`，並在新的瀏覽器分頁中開啟。
