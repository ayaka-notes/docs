此功能由 [yu-i-i/overleaf-cep](https://github.com/yu-i-i/overleaf-cep) 開發。我們在此提供一些文件，協助您進行設定。

### 設定

在內部，Overleaf OIDC 模組使用 [passport-openidconnect](https://github.com/jaredhanson/passport-openidconnect) 函式庫。如果您在設定 OpenID Connect 時遇到問題，建議閱讀 `passport-openidconnect` 的 README，以了解其預期的設定方式。

啟用 OIDC 驗證模組需要設定環境變數 `EXTERNAL_AUTH`。此環境變數用於指定要啟用哪些外部驗證方式，其值為一個清單。如果清單中包含 `oidc`，就會啟用 OIDC 驗證。

例如：`EXTERNAL_AUTH=ldap oidc`

使用 OIDC 驗證方式時，使用者會被重新導向至身分提供者（IdP）的驗證網站。如果 IdP 成功驗證使用者，系統會在 Overleaf 使用者資料庫中檢查是否有記錄包含如下結構的 `thirdPartyIdentifiers` 欄位：

```text
thirdPartyIdentifiers: [
  {
    externalUserId: "...",
    externalData: null,
    providerId: "..."
  }
]
```

`externalUserId` 必須與 IdP 伺服器所回傳之個人資料中的使用者 ID 相符（請參閱 `OVERLEAF_OIDC_USER_ID_FIELD` 環境變數），而 `providerId` 必須與 OIDC 提供者的 ID 相符（請參閱 `OVERLEAF_OIDC_PROVIDER_ID`）。

如果找不到相符的記錄，系統會在資料庫中搜尋主要電子郵件地址與 IdP 使用者個人資料中電子郵件相符的使用者：

* 如果找到此類使用者，則會更新其 `thirdPartyIdentifiers` 欄位。
* 如果找不到相符的使用者，且未停用 JIT 帳號建立，則會使用 IdP 個人資料中的電子郵件地址與 `thirdPartyIdentifiers` 建立新使用者。

在這兩種情況下，該使用者即被視為已「連結」至外部 OIDC 使用者。使用者可以在 `/user/settings` 頁面上解除與 OIDC 提供者的連結。

#### 環境變數

以下五個必要變數的值，可以透過您 OpenID 提供者（OP）的 `.well-known/openid-configuration` 端點取得。

* `OVERLEAF_OIDC_ISSUER` **（必要）**
* `OVERLEAF_OIDC_AUTHORIZATION_URL` **（必要）**
* `OVERLEAF_OIDC_TOKEN_URL` **（必要）**
* `OVERLEAF_OIDC_USER_INFO_URL` **（必要）**
* `OVERLEAF_OIDC_LOGOUT_URL` **（必要）**

以下兩個必要變數的值將由您 OP 的管理員提供

* `OVERLEAF_OIDC_CLIENT_ID` **（必要）**
* `OVERLEAF_OIDC_CLIENT_SECRET` **（必要）**
* `OVERLEAF_OIDC_SCOPE`
  * 預設值：`openid profile email`
* `OVERLEAF_OIDC_PROVIDER_ID`
  * OP 的任意 ID，預設為 `oidc`。
* `OVERLEAF_OIDC_PROVIDER_NAME`
  * OP 的名稱，用於 `/user/settings` 頁面的 `Linked Accounts` 區段，預設為 `OIDC Provider`。
* `OVERLEAF_OIDC_IDENTITY_SERVICE_NAME`
  * 身分服務的顯示名稱，用於登入頁面（預設值：`Log in with $OVERLEAF_OIDC_PROVIDER_NAME`）。
* `OVERLEAF_OIDC_PROVIDER_DESCRIPTION`
  * OP 的說明，用於 `Linked Accounts` 區段（預設值：`Log in with $OVERLEAF_OIDC_PROVIDER_NAME`）。
* `OVERLEAF_OIDC_PROVIDER_INFO_LINK`
  * OP 說明中的 `Learn more` 網址，預設：說明中不顯示 `Learn more` 連結。
* `OVERLEAF_OIDC_PROVIDER_HIDE_NOT_LINKED`
  * 如果使用者的帳號未與 OP 連結，則不在 `/user/settings` 頁面上顯示該 OP，預設為 `false`。
* `OVERLEAF_OIDC_USER_ID_FIELD`
  * Overleaf 會將此屬性的值作為外部使用者 ID，預設為 `id`。其他可能合理的值包括 `email` 與 `username`（對應 `preferred_username` OIDC claim）。
* `OVERLEAF_OIDC_ALLOWED_EMAIL_DOMAINS`
  * 限制透過 OIDC 驗證之使用者的即時（JIT）帳號建立。若設為以逗號分隔的網域名稱清單，則只有在使用者電子郵件地址的網域與清單中的某個網域相符時，才會建立新帳號。如果網域不相符，管理員必須使用該 OIDC 使用者的電子郵件地址手動建立使用者帳號，並設定一組強度高的隨機密碼，或者最好完全不設定 `hashedPassword` 欄位。網域名稱可以包含開頭的 `*.` 萬用字元，以比對子網域。
    * 範例：若要允許電子郵件地址如 `name@example.com` 與 `name@math.example.com` 的使用者進行 JIT 帳號建立：\
      `OVERLEAF_OIDC_ALLOWED_EMAIL_DOMAINS=example.com, *.example.com`
    * 範例：若要完全停用 JIT 帳號建立：\
      `OVERLEAF_OIDC_ALLOWED_EMAIL_DOMAINS=`
* `OVERLEAF_OIDC_UPDATE_USER_DETAILS_ON_LOGIN`
  * 若設為 `true`，會在登入時更新使用者的 `first_name` 與 `last_name` 欄位，並停用 `/user/settings` 頁面上的使用者資料表單。
* `OVERLEAF_OIDC_IS_ADMIN_FIELD` 與 `OVERLEAF_OIDC_IS_ADMIN_FIELD_VALUE`
  * 當兩個環境變數都已設定時，如果 OP 回傳的個人資料包含 `OVERLEAF_OIDC_IS_ADMIN_FIELD` 所指定的屬性，且其值與 `OVERLEAF_OIDC_IS_ADMIN_FIELD_VALUE` 相符，登入流程會將 `user.isAdmin` 更新為 `true`，否則會將 `user.isAdmin` 設為 `false`。如果 `OVERLEAF_OIDC_IS_ADMIN_FIELD` 為 `email`，則會使用屬性 `emails[0].value` 的值進行比對。

您 OpenID 提供者的重新導向網址為 `https://my-overleaf-instance.com/oidc/login/callback`。
