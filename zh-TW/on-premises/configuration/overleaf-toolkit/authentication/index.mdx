### 全域設定 {#global-configuration}

必須設定環境變數 `EXTERNAL_AUTH` 才能啟用特定的身分驗證模組。此環境變數指定要啟用哪些外部身分驗證方式。可用選項如下（小寫）：

* saml
* ldap
* oidc

若要讓使用者只能透過這些方式登入，請設定 `OVERLEAF_DISABLE_LOCAL_LOGIN=true`。這會隱藏電子郵件與密碼登入。除非 `EXTERNAL_AUTH` 至少啟用了一種方式，否則此設定不會生效（於 6.3.1 新增）。

### 帳號與密碼 {#accounts-and-passwords}

設定 `EXTERNAL_AUTH` 後，一個執行個體中可以同時存在有本機密碼與沒有本機密碼的帳號。帳號能否設定或變更密碼只取決於這一點：有本機密碼的帳號自行管理密碼；沒有本機密碼的帳號只能透過 SSO 登入，也無法從管理員取得密碼。在只使用 OIDC 的執行個體上，除非設定了 `OVERLEAF_DISABLE_LOCAL_LOGIN=true`，否則該帳號可以透過重設郵件自行設定密碼。

| 帳號 | 本機密碼 | 登入方式 | 透過電子郵件重設 | 設定頁面 | 管理員設定密碼 |
| --- | --- | --- | --- | --- | --- |
| 本機帳號，未設定 `EXTERNAL_AUTH` | 是 | 電子郵件與密碼 | 是 | 是 | 是 |
| 設定了 `EXTERNAL_AUTH` 的執行個體上的本機帳號 | 是 | 電子郵件與密碼 | 是 | 是 | 是 |
| 已連結 OIDC 的本機帳號 | 是 | 電子郵件與密碼，或 OIDC | 是 | 是 | 是 |
| 首次透過 LDAP 或 SAML 登入時建立的帳號 | 無 | 僅 SSO | 否 | 否 | 否 |
| 首次透過 OIDC 登入時建立的帳號 | 無，直到自行設定 | OIDC，設定後也可用密碼 | 是，見上文 | 設定密碼後可用 | 否 |
| 曾以 LDAP 或 SAML 登入的本機帳號 | 否，於該次登入時移除 | 僅限 SSO | 否 | 否 | 否 |
| 由管理員建立為外部帳號的帳號 | 否 | 僅限 SSO | 否 | 否 | 否 |

* LDAP 與 SAML 會在首次登入時接管具有相同電子郵件的本機帳號，並在每次登入時移除其本機密碼。若電子郵件不同，則會建立新帳號，不影響原有的本機帳號。
* 如果首次透過 LDAP、SAML 或 OIDC 登入時使用的電子郵件是另一個帳號的[次要電子郵件](/zh-TW/on-premises/configuration/overleaf-toolkit/email-delivery#several-emails-per-account)，登入會被拒絕：不會登入那個帳號。
* OIDC 會連結至帳號並保留其密碼，因此已連結 OIDC 的本機帳號可以透過兩種方式登入。可以在設定頁面點擊 **Link** 進行連結，或在電子郵件相符時於首次 OIDC 登入時連結。連結方式請參閱 [OIDC 身分驗證](/zh-TW/on-premises/configuration/overleaf-toolkit/authentication/oidc-authentication)。
* 由管理員建立為本機帳號的帳號會收到啟用電子郵件：啟用帳號時設定密碼的方式，與透過電子郵件重設密碼相同。
* 啟用多種方式時（例如 `EXTERNAL_AUTH=ldap saml oidc`），上述規則不變：只看帳號的本機密碼，沒有本機密碼的帳號無法設定密碼，由 OIDC 建立的帳號也一樣。
* 如果你的 IdP 會關閉應失去存取權的帳號（例如離職員工的帳號），請在使用 OIDC 的執行個體上設定 `OVERLEAF_DISABLE_LOCAL_LOGIN=true`：否則設定過本機密碼的人在 IdP 關閉帳號後仍能登入。
* 透過電子郵件重設需要電子郵件設定（`OVERLEAF_EMAIL_*`）。沒有這些設定時不會寄出郵件，儘管頁面顯示已寄出：此時由管理員在 **Admin → Manage Users** 中複製重設連結或設定密碼。
* `OVERLEAF_DISABLE_LOCAL_LOGIN=true` 會隱藏電子郵件與密碼登入，但會保留密碼：重新顯示該登入方式後，密碼即可再次使用。
* 設定 `EXTERNAL_AUTH` 後，無論使用哪種方式，使用者都無法在設定頁面輸入新的電子郵件：使用者首次透過 OIDC 登入時，會連結到擁有該使用者電子郵件的帳號。管理員在 **Admin → Manage Users** 中變更電子郵件。設定了[電子郵件設定](/zh-TW/on-premises/configuration/overleaf-toolkit/email-delivery#several-emails-per-account)後，使用者可以新增以驗證碼確認的電子郵件，並在未啟用 LDAP 與 SAML 的執行個體上將其中一個設為主要電子郵件。
* 在啟用 OIDC 的執行個體上，請使用[透過啟用電子郵件註冊](/zh-TW/on-premises/configuration/overleaf-toolkit/authentication/public-access#registration-with-activation-email)，例如 `OVERLEAF_ALLOW_PUBLIC_REGISTRATION=@<domain>` 或 `@*`（啟用電子郵件可證明該地址的所有權），而非 `true`，或不開放公開註冊：若設為 `true`，任何人都可以在同事首次 OIDC 登入之前，以該同事的電子郵件註冊，導致同事被連結至該帳號。

### Q\&A {#q&a}

<Accordion title="可以為登入或註冊啟用 CAPTCHA 嗎？">

<strong>答：</strong>可以，自 v6.4.0 起支援。請使用 reCAPTCHA v2 隱形金鑰設定 `RECAPTCHA_SITE_KEY` 與 `RECAPTCHA_SECRET_KEY`，請參閱 [reCAPTCHA](/zh-TW/on-premises/configuration/overleaf-toolkit/authentication/recaptcha)。它涵蓋電子郵件與密碼登入、LDAP 登入、註冊以及密碼重設。較早的版本沒有此設定；所有版本的登入都有頻率限制：每個 IP 位址每分鐘 20 次嘗試，每個電子郵件每 2 分鐘 10 次嘗試。

</Accordion>
