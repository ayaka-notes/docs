## 先決條件

Overleaf 是典型的微服務架構開源專案，所有服務皆在 Docker 中執行。&#x20;

* 官方 Community Edition 原始碼位於 [GitHub Overleaf Official](https://github.com/overleaf/overleaf/tree)。&#x20;
* Overleaf-CEP 的原始碼位於 [GitHub Yu-i-i/Overleaf](https://github.com/yu-i-i/overleaf-cep)。
* Overleaf Pro Edition 位於 [GitHub Ayaka-notes/overleaf-pro](https://github.com/ayaka-notes/overleaf-pro)。

要建立 Overleaf 開發環境，您需要一台效能強大的伺服器；建議至少 8 核心與 16GB RAM 的配置，因為您需要同時執行 20 個以上的容器。

<Info>

由於 8 核心以上 CPU 的伺服器通常價格昂貴，強烈建議使用您的本機電腦進行開發。

</Info>

同時，身為開發者，我們相信您應該已熟悉 [Docker 安裝](https://docs.docker.com/engine/install/ubuntu/)。我們強烈建議使用較新且穩定的 Ubuntu LTS（例如 2025–2026 年的 Ubuntu 24.04）以及最新版 Docker 進行開發，以降低遇到非預期錯誤的可能性。

總結來說，您需要：

* [x] 一台效能強大的伺服器／桌上型電腦用於開發
* [x] 較新且穩定的 Ubuntu LTS（例如 Ubuntu 24.04）
* [x] Docker 與 Git 環境

## 設定教學

這裡我們將以 overleaf-cep 為例，示範如何設定 Overleaf 開發環境。

<Steps>
<Step title="拉取原始碼">
首先，複製儲存庫：

```bash title="bash"
git clone https://github.com/ayaka-notes/overleaf-pro.git
cd overleaf-pro
```
</Step>

<Step title="同步 `package-lock.json`">
由於 Overleaf 是在[內部儲存庫](http://github.com/overleaf/internal)中開發，`package-lock.json` 檔案很可能因某些開發問題而不同步。我們需要執行以下指令來同步它（如果您有本機 nodejs 環境）。

```bash title="bash"
npm install --package-lock-only --ignore-scripts
```

如果您沒有安裝 nodejs，不用擔心，您可以直接使用 `docker` 執行相同的指令。請**在 Overleaf 儲存庫的根目錄執行：**

```bash title="bash"
docker run --rm \
  -v "$(pwd)":/workspace \
  -w /workspace \
  node:22.18.0 \
  npm install --package-lock-only --ignore-scripts
```
</Step>

<Step title="建置開發映像檔">
Overleaf 提供專用目錄 `/develop` 用於存放開發指令碼。直接建置服務即可：

```bash title="bash"
cd ./develop
bin/build
```

<Info>

如果 Docker 在平行建置服務時記憶體不足，請在此目錄中建立內容為 `COMPOSE_PARALLEL_LIMIT=1` 的 `.env` 檔案。

</Info>
</Step>

<Step title="啟動所有微服務">
接著啟動服務：

```bash title="bash"
bin/up
```

服務執行後，開啟 [http://localhost/launchpad](http://localhost/launchpad) 建立第一個管理員帳號。

<Danger>

您必須先執行 `bin/up`，再執行 `bin/dev` 指令，否則可能會遇到一連串權限問題。

</Danger>
</Step>
</Steps>

<Info>

預設情況下無法使用管理員權限。您需要將以下內容加入 `develop/dev.env`，之後即可存取管理面板。

```text
ADMIN_PRIVILEGE_AVAILABLE=true
```

</Info>

### TeX Live

編譯 PDF 需要建置 TeX Live 映像檔，以在 Docker 內處理編譯：

```text
docker build texlive -t texlive-full
```

若要在 macOS 主機上編譯，您可能需要在此目錄中建立內容為 `DOCKER_SOCKET_PATH=/var/run/docker.sock.raw` 的 `.env` 檔案，以覆寫 Docker socket 的路徑。

此外，也歡迎使用 [ayaka-notes/texlive-full](https://github.com/ayaka-notes/texlive-full)，您可以使用 base 標籤，這是 texlive 的最小版本。

### 開發

為避免每次修改程式碼後都要執行 `bin/build && bin/up`，您可以在_開發模式_下執行 Overleaf Community Edition，服務會在程式碼變更時自動更新。

若要這麼做，請使用內附的 `bin/dev` 指令碼：

```text
bin/dev
```

這會使用 `node --watch` 啟動所有服務，自動監控程式碼並在必要時重新啟動服務。

為提升效能，您可以向 `bin/dev` 指令碼提供以空格分隔的清單，只在開發模式下啟動部分服務：

```text
bin/dev [service1] [service2] ... [serviceN]
```

<Info>

在_開發模式_下啟動 `web` 服務時，只有在後端程式碼變更時才會更新 `web` 服務。若要讓前端程式碼也自動更新，請務必同時在_開發模式_下啟動 `webpack` 服務。

</Info>

若未指定任何服務，所有服務都會以開發模式啟動。

### 偵錯

在_開發模式_下執行時，大多數服務會開放一個偵錯連接埠，您可以將偵錯器附加到該連接埠，例如 Chrome 開發人員工具中的檢查器或 IDE 內建的偵錯器。下表列出每個服務在**主機**上開放的連接埠：

| 服務               | 連接埠 |
| ------------------ | ---- |
| `web`              | 9229 |
| `clsi`             | 9230 |
| `chat`             | 9231 |
| `contacts`         | 9232 |
| `docstore`         | 9233 |
| `document-updater` | 9234 |
| `filestore`        | 9235 |
| `notifications`    | 9236 |
| `real-time`        | 9237 |
| `references`       | 9238 |
| `history-v1`       | 9239 |
| `project-history`  | 9240 |
| `linked-url-proxy` | 9241 |

若要使用 Chrome 的_遠端偵錯_附加到服務，請前往 chrome://inspect/ 並確認已勾選 _Discover network targets_。接著點選 _Configure..._，為每個要附加偵錯器的服務新增一筆 `localhost:[service port]` 項目。

新增項目後，該服務會顯示為_遠端目標（Remote Target）_，您即可對其進行檢查與偵錯。

### 日誌

在開發環境中，overleaf 提供了 `bin/logs` 指令碼，但您需要安裝一些相依套件：

```bash
sudo npm install -g bunyan
# Or sudo apt install node-bunyan 
```

或者，您也可以直接執行：

```text
docker compose logs -f [service name]
```
