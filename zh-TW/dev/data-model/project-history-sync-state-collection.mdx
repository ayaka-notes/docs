---
title: Project History Sync State 集合
icon: rotate
---

`projectHistorySyncState` 中每個經過重新同步的專案一個文件：目前或最近一次重新同步的狀態。重新同步是指 project-history 依據 web 與 docstore 中保存的內容重建專案歷史。此集合屬於 project-history，沒有 Mongoose schema；程式碼是 `services/project-history/app/js/SyncManager.js` 中的 `SyncState` 類別及其輔助函式。

#### 寫入方 {#who-writes-it}

| 程式碼 | 作用 |
| ---- | ------------ |
| `services/project-history/app/js/SyncManager.js:195-249` | `setResyncState`：upsert 狀態。在重新同步開始時（`SyncManager.js:163`）以及 project-history 處理重新同步更新期間（`services/project-history/app/js/UpdatesProcessor.js:637`, `784`）呼叫。 |
| `SyncManager.js:257-266` | `_recordStuckClearInSyncState`：計算被清除的卡住重新同步。 |
| `SyncManager.js:251-255` | `clearResyncState`：刪除文件，發生於硬重新同步開始時（`SyncManager.js:87`）、project-history 的 `DELETE /project/:project_id` 上（`services/project-history/app/js/HttpController.js:1363-1396`），以及僅結構的重新同步需要重新開始時（`SyncManager.js:705-716`）。 |
| `SyncManager.js:273-289` | `clearResyncStateIfAllAfter`：刪除歷史全部晚於某個日期的已完成狀態。`app/js` 中沒有任何程式碼呼叫它。 |
| `SyncManager.js:171-181` | `cloneResyncState`：把狀態複製到另一個專案，用於 project-history 的 `POST /project/:project_id/clone`（`HttpController.js:57`, `124`），web 中沒有任何程式碼呼叫它。 |

重新同步由 project-history 的 `POST /project/:project_id/resync`（`HttpController.js:950-994`）、重試 cron 工作（`services/project-history/app/js/RetryManager.js:156-179`, `server-ce/config/crontab-history`），以及 project-history 在處理更新需要時自行啟動（`UpdatesProcessor.js:75`, `224`）。

#### 備註 {#notes}

* 只要 `resyncProjectStructure` 為 `true` 或 `resyncDocContents` 不為空，重新同步就處於執行中（`SyncManager.js:565-567`）。超過 4 小時視為卡住，清除 5 次後視為永久卡住（`SyncManager.js:43-44`, `569-585`）。
* 重新同步完成時，project-history 也會在專案上設定 `overleaf.history.lastResyncedAt`（`SyncManager.js:239-248`）。
