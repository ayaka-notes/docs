title: Dropbox Projects 集合
icon: folder-open
---

`dropboxProjects` 將一個專案對應到某位使用者 Dropbox 中的資料夾。與多位 Dropbox 使用者共用的專案，每位使用者各有一份文件。此集合屬於 Dropbox 同步：third-party-datastore（`services/third-party-datastore/app/js/StateManager.mjs`）寫入它，`dropbox` web 模組（`services/web/modules/dropbox/app/src/DropboxHandler.mjs`）讀取並清除它。沒有 Mongoose schema。

#### 欄位 {#fields}

| 欄位 | 型別 | 意義 | 來源 |
| ---- | ---- | ---- | ---- |
| `_id` | ObjectId | 插入時由驅動程式設定。 | `StateManager.mjs:144` |
| `userId` | ObjectId | 其 Dropbox 中有該資料夾的 Overleaf 使用者。 | `StateManager.mjs:145` |
| `projectId` | ObjectId | 同步到該資料夾的專案。 | `StateManager.mjs:146` |
| `dropboxId` | String | Dropbox 資料夾中繼資料中該資料夾的 `id`。 | `StateManager.mjs:147`、`JobProcessor.mjs:82-87`、`PullManager.mjs:138` |
| `pathLower` | String | 資料夾在 Dropbox 中的路徑，小寫且不含結尾斜線。專案資料夾位於最上層，每個專案一個，例如 Dropbox 在另一個專案的 `Thesis` 旁為其編號時為 `/thesis (1)`。 | `StateManager.mjs:14-16,148`、`PullManager.mjs:112-117` |

#### 索引 {#indexes}

| 名稱 | 鍵 | 選項 | 遷移 |

CE 在這裡沒有其他索引。唯一索引 `projectId_userId_1` 與 `userId_dropboxId_1` 來自 `tools/migrations/20220815105500_create_dropboxProjects_index.mjs` 與 `20220817120900_create_dropboxProjects_index.mjs`，它們只帶有 `saas` 標籤，因此 CE 從不執行它們。

#### 說明 {#notes}

* 唯一性僅來自 `setProjectFolder` 中每次插入前的刪除（`StateManager.mjs:140-149`）。`StateManager.mjs:3-11` 的註解提到唯一索引；CE 沒有這些索引。
* 專案的對應被移除後，其資料夾仍留在 Dropbox 中。在那裡的編輯會被當作新專案讀取，與在 Dropbox 中建立的資料夾相同（`DropboxHandler.mjs:148-149`）。
* 已刪除的專案在到期前保留其對應，因為它仍可被還原（`index.mjs:52-53`）。
* 使用者的 Dropbox `list_folder` 游標不在這裡，而在 `users.dropbox.cursor` 中（`StateManager.mjs:177-184`）。
