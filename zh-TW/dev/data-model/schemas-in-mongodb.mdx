在本節中，我們將討論 Overleaf 的資料模型。Overleaf 使用 MongoDB 進行資料持久化，唯一的資料庫名稱為 `sharelatex`，這也是 Overleaf 的前身。

開發環境已經在 Mongo 旁邊執行 Mongo Express（請參閱 [setup-develop-tools.md](/zh-TW/dev/environment/setup-develop-tools  "mention")）。開啟 [http://localhost:8081/](http://localhost:8081/)，並使用 `admin:pass` 登入。

</Frame>

您也可以在 `develop` 目錄中開啟 Mongo 容器裡的 shell：

```bash
bin/docker-compose exec mongo mongosh sharelatex
```

#### 這些頁面的寫法 {#how-the-pages-are-written}

* 每個頁面列出程式碼寫入的欄位，以及欄位型別、含義和能說明它的程式碼行：Mongoose schema 中的一行，或寫入該欄位的位置。只有遷移、指令碼或某個 web 模組寫入的欄位會特別註明。
* 許多集合沒有 Mongoose schema：服務直接使用 MongoDB 驅動程式寫入它們。
* 索引只由 `tools/migrations/` 中的遷移建立。CE 每次啟動時執行標記為 `server-ce` 的遷移（`server-ce/init_scripts/900_run_web_migrations.sh`）；Mongoose 的 `autoIndex` 已關閉（`services/web/app/src/infrastructure/Mongoose.mjs:7`）。索引表只列出 CE 執行個體最終擁有的索引。
* doc 的文字在 Mongo 中，但其他內容不在。檔案內容以 blob 的形式、歷史以 chunk 的形式儲存在 history-v1 的 bucket 中（本機資料夾，或 S3 / RustFS）；已開啟的 doc 在 document-updater 排清之前保存在 Redis 中。

CE 資料庫中的集合比這些更多。許多集合由各自的索引遷移建立為空集合，只在 overleaf.com 上使用。例如，在正常使用中，CE 和我們的模組都不會寫入 `splittests`、`samlLogs`、`notificationsPreferences`、`onboardingDataCollection` 或 `userfeatureusages`，因此它們沒有對應頁面。
