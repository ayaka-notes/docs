`rooms` 中專案的每個聊天室對應一個文件：專案聊天，或一個審閱註解討論串。只有 chat 服務寫入它，位置在 `services/chat/app/js/Features/Threads/ThreadManager.js`。沒有 Mongoose schema。聊天室的訊息保存在 [messages](/zh-TW/dev/data-model/messages-collection) 集合中。

#### 欄位 {#fields}

| 欄位 | 型別 | 含義 | 來源 |
| ----- | ---- | ------- | ------ |
| `_id` | ObjectId | 聊天室 ID。`messages.room_id` 指向這裡。 | `ThreadManager.js:57-61` |
| `project_id` | ObjectId | 聊天室所屬的專案。 | `ThreadManager.js:43-54` |
| `thread_id` | ObjectId | 僅存在於註解討論串上：註解的 ID，與 `docs.ranges.comments` 中該註解的 `id` 和 `op.t` 相同（參見 [docs](/zh-TW/dev/data-model/docs-collection)）。專案聊天室沒有此欄位。 | `ThreadManager.js:38-55`, `services/docstore/app/js/RangeManager.js:54-57` |
| `resolved` | Object | 討論串被解決時設定，重新開啟時移除。沒有此欄位的討論串處於開啟狀態。 | `ThreadManager.js:94-123` |
| `resolved.user_id` | String | 解決該討論串的使用者 ID。以字串而非 ObjectId 儲存：請求本文只檢查其為有效 ID，不做轉換。 | `ThreadManager.js:103`, `services/chat/app/js/Features/Messages/MessageHttpSchemas.js:70` |
| `resolved.ts` | Date | 討論串被解決的時間。 | `ThreadManager.js:104` |

| `ThreadManager.js:94-109` `resolveThread` | 設定 `resolved`。由 Web 中的 track-changes 模組（`services/web/modules/track-changes/app/src/TrackChangesController.mjs:142`）、歷史還原（`services/web/app/src/Features/History/RestoreManager.mjs:276`）和 mcp-server 模組（`services/web/modules/mcp-server/app/src/CommentTools.mjs:159`）呼叫。 |

#### 說明 {#notes}

* 一個專案最多只有一個沒有 `thread_id` 的聊天室，即專案聊天。chat 服務用 `thread_id: { $exists: false }` 查找它（`ThreadManager.js:38-45`）。
* 註解的已解決狀態只保存在這裡。Docstore 在儲存範圍之前會去掉 `op.resolved`（`services/docstore/app/js/RangeManager.js:59-61`）。
* 複製專案後，同一個 `thread_id` 會存在於兩個專案中。請一律同時依 `project_id` 和 `thread_id` 查詢，就像 chat 服務那樣。
* 已刪除專案的聊天室會一直保留，直到已刪除專案過期。
