### Docker

Docker biedt een lichtgewicht en draagbare manier om applicaties te verpakken en in geïsoleerde containers uit te voeren. Door de applicatie samen met alle benodigde afhankelijkheden te bundelen, zorgt een container voor consistent gedrag op verschillende machines, van laptops tot productieservers.

TeX Live is krachtig, maar groot en gevoelig voor verschillen op systeemniveau. Door TeX Live in een Docker-image te verpakken, wordt de LaTeX-toolchain voorspelbaar, reproduceerbaar en eenvoudig te distribueren.

Sommige TeX Live-pakketten zijn echter afhankelijk van shell-toegang. Om veiligheidsredenen moet de container in een afgeschermde omgeving draaien die voorkomt dat gebruikers willekeurige shell-opdrachten uitvoeren (bijvoorbeeld via `\write18` of shell escape). Deze isolatie beschermt het hostsysteem en voorkomt onbedoelde toegang tot het onderliggende bestandssysteem van de container of tot tools zoals `bash`.

### TeXLive Full-editie

[TeXLive-Full@ayaka-notes](https://github.com/ayaka-notes/texlive-full/) is een volledig uitgeruste **TeXLive Docker-image**, ontworpen voor LaTeX-compilatie in een sandbox in [Ayakaleaf Pro](https://github.com/ayaka-notes/ayakaleaf-pro), [Overleaf CEP](https://github.com/yu-i-i/overleaf-cep) of zelfstandige LaTeX-compilatieomgevingen.

Deze image heeft als doel een vrijwel volledige TeXLive-distributie te bieden met veelgebruikte lettertypen en tools vooraf geïnstalleerd, om compilatiefouten door ontbrekende pakketten of lettertypen tot een minimum te beperken. Opmerking: deze Docker-image **bevat geen** sharelatex/overleaf-componenten. Ze wordt gebruikt voor het compileren in Overleaf/Overleaf Pro.

#### Functies:

* 🚀 Ondersteunt zowel x86\_64- als arm64-serverarchitecturen
* 📦 Volledige en geoptimaliseerde TeXLive-installatie
* 🧩 Veelgebruikte lettertypen en hulpprogramma's vooraf geïnstalleerd
* 🐳 Direct klaar voor gebruik met Docker en Docker Compose
* 🧪 Getest met Overleaf Server Pro / Overleaf Pro
* 🔄 Regelmatig bijgewerkt met de nieuwste TeXLive-releases
* 🏷 Tags voor meerdere TeXLive-versies (2020 – nieuwste)
* 🧑‍🔬 Knitr-ondersteuning voor R-code in LaTeX-documenten

### Gebruik met Ayakaleaf Pro

TeX Live Full van Ayaka-notes is speciaal ontworpen voor [ayakaleaf-pro](https://github.com/ayaka-notes/ayakaleaf-pro). Als je een [toolkit-gebruiker](https://github.com/overleaf/toolkit) bent, kun je de volgende omgevingsvariabelen toevoegen aan het bestand `config/variables.env`.

Bijvoorbeeld:

```dotenv title="config/variables.env" wrap
ALL_TEX_LIVE_DOCKER_IMAGES=ghcr.io/ayaka-notes/texlive-full:2026.1, ghcr.io/ayaka-notes/texlive-full:2025.1
ALL_TEX_LIVE_DOCKER_IMAGE_NAMES=Texlive 2026, Texlive 2025
TEX_LIVE_DOCKER_IMAGE=ghcr.io/ayaka-notes/texlive-full:2026.1
```

### TeX Live-versie

Dankzij GitHub Actions kunnen we alle TeX-images parallel bouwen, waaronder:

* `ghcr.io/ayaka-notes/texlive-full:2026.1` (ook tag `latest`)
* `ghcr.io/ayaka-notes/texlive-full:2025.1`
* `ghcr.io/ayaka-notes/texlive-full:2024.1`
* `ghcr.io/ayaka-notes/texlive-full:2023.1`
* `ghcr.io/ayaka-notes/texlive-full:2022.1`
* `ghcr.io/ayaka-notes/texlive-full:2021.1`
* `ghcr.io/ayaka-notes/texlive-full:2020.1`
* `ghcr.io/ayaka-notes/texlive-full:base`

We gebruiken het mirror-archief van [texlive info](https://texlive.info/tlnet-archive/), dat vrijwel alle TeX Live-versies van 1996 tot 2025 bevat. En dankzij het Dockerfile van Overleaf kunnen we dit project sneller bouwen.

> Waarom worden TeX Live 2019 en eerder niet ondersteund?
>
> Het onderhouden van deze oude images is uiterst lastig. Bovendien biedt de website [texlive.info](https://texlive.info/) geen informatie voor TeX Live-versies die vóór 2019 zijn uitgebracht, waardoor we voor die versies geen images kunnen bouwen. Als je een specifieke oude versie nodig hebt, open dan een issue en laat het ons weten.

### Meegeleverde componenten

De volgende pakketten zijn opgenomen in de Docker-image.

* Alle TeXLive-pakketten (van dat jaar)
* R-pakketten (alleen een selectie)
* fontconfig inkscape pandoc python3-pygments wget python3
* gnupg gnuplot perl-modules perl ca-certificates
* ghostscript qpdf r-base-core tar

De volgende lettertypen zijn opgenomen in de Docker-image.

* [Google Fonts](https://fonts.google.com/)
* [Microsoft msttcorefonts](https://packages.ubuntu.com/jammy/ttf-mscorefonts-installer)
* [Door Overleaf ondersteunde lettertypen](https://www.overleaf.com/learn/latex/Questions/Which_OTF_or_TTF_fonts_are_supported_via_fontspec%3F)

<Warning>

Controleer of de betreffende lettertypen commercieel mogen worden gebruikt. We zijn **niet verantwoordelijk** voor juridische problemen die voortvloeien uit onjuist gebruik van lettertypen. Zodra je de image downloadt, ga je hier automatisch mee akkoord.

</Warning>

### Problemen

<Accordion title="Probleem 01: ontbrekende lettertypen in de cache">

Als er bij het compileren van een LaTeX-project in Overleaf een lettertype ontbreekt, **kan het compileren lang duren**. Dat komt doordat TeX Live bij een ontbrekend lettertype probeert **de volledige lettertypecache opnieuw op te bouwen**. Dit is een tijdrovend proces.

In onze image hebben we de lettertypecache vooraf opgebouwd; we hebben dit probleem opgelost met [deze commit](https://github.com/ayaka-notes/texlive-full/commit/0cb66b0dc8b82be628cf6999cfd659d9784e132f)

</Accordion>

<Accordion title="Probleem 02: SyncTeX extreem traag">

Als je deze image in sharelatex gebruikt, kan het zijn dat SyncTeX extreem traag is.

Zie: [https://github.com/overleaf/overleaf/issues/1150](https://github.com/overleaf/overleaf/issues/1150); schakel gewoon HTTP 2.0 uit.

</Accordion>

<Accordion title="Probleem 03: fout bij opnieuw compileren met de officiële TeX Live-image">

Als je de officiële TeX Live-image `texlive/texlive` van Docker Hub gebruikt, kan het zijn dat er een fout wordt gemeld wanneer je een project opnieuw compileert. In onze image is dit probleem echter opgelost, omdat we de nieuwste Ubuntu-basisimage gebruiken en alle afhankelijkheden uit de officiële Ubuntu-repository installeren.

</Accordion>

### Overige technische aandachtspunten

Bij het bouwen van TeX Live-images (van vóór 2019) moet je mogelijk letten op de volgende problemen:

* Vóór TeX Live 2017 wordt alleen `http`/`ftp` ondersteund, dus je kunt niet via `https` downloaden, tenzij je het `peal`-script aanpast.
* Vóór 2015 wordt alleen een sha256-bestand aangeboden. Je kunt dus niet met sha512 controleren.
