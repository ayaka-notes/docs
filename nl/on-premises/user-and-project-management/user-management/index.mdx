## Een beheerder aanmaken {#creating-an-administrator-user}

Implementaties met de Overleaf Toolkit:

```bash title="Overleaf Toolkit" wrap
$ bin/docker-compose exec sharelatex /bin/bash -ce "cd /overleaf/services/web && node modules/server-ce-scripts/scripts/create-user --admin --email=joe@example.com"
```

Verouderde implementaties met docker-compose.yml:

```bash title="Legacy docker-compose" wrap
$ docker exec sharelatex /bin/bash -ce "cd /overleaf/services/web && node modules/server-ce-scripts/scripts/create-user --admin --email=joe@example.com"
```

De opdracht maakt een gebruiker aan met het opgegeven e-mailadres als die nog niet bestaat, en maakt deze gebruiker beheerder. De uitvoer van de opdracht bevat een URL waar je het wachtwoord voor deze gebruiker kunt instellen en voor de eerste keer kunt inloggen.

<Info>

Voor een programmatische aanpak kun je hetzelfde script gebruiken om zowel gewone gebruikers als beheerders aan te maken. Laat voor gewone gebruikers de vlag --admin weg.

</Info>

Als je interne accounts gebruikt voor authenticatie en een bestaande gebruiker tot instantiebeheerder wilt promoveren of beheerdersrechten wilt intrekken, doe dan het volgende:

<Steps>
<Step title="Via de beheerinterface">
* Log in als bestaande beheerder.
* Klik op Admin -> Manage Users.
* Zoek de gebruiker en klik op zijn naam.
* Klik op het potloodpictogram.
* Zet Admin aan of uit.
* Klik op Save om af te ronden.
</Step>
</Steps>

## Gebruikers verwijderen {#deleting-users}

Het is over het algemeen raadzaam om accounts alleen te verwijderen als ze niet meer nodig zijn. Het verwijderen van een account verwijdert het account en zorgt ervoor dat medewerkers de toegang tot projecten verliezen. Om te voorkomen dat een gebruiker zich aanmeldt en toch de gegevens te behouden, kunt u [het account uitschakelen](/on-premises/user-guide/administrators/user-management#disable-or-enable-an-account).

Standaard worden accounts zacht verwijderd (soft delete). Zie `ENABLE_CRON_RESOURCE_DELETION` in de handleiding [Omgevingsvariabelen](/nl/on-premises/configuration/overleaf-toolkit/environment-variables) voor informatie over het permanent verwijderen van gebruikers uit je instantie.

<Info>

Accounts worden standaard zacht verwijderd. Zie `ENABLE_CRON_RESOURCE_DELETION` voor het gedrag bij permanente verwijdering.

</Info>

### Via Admin -> Manage Users {#via-admin->-manage-users}

<Steps>
<Step title="">
* Log in als beheerder.
* Klik op Admin -> Manage Users.
* Zoek de gebruiker en vink het vakje naast zijn naam aan.
* Klik op het prullenbakpictogram.
* Klik op Delete account om te bevestigen.
</Step>
</Steps>

### Via de opdrachtregel {#via-the-command-line}

Gebruikersaccounts (en hun projecten) kunnen met de volgende opdrachten worden verwijderd.

Implementaties met de Overleaf Toolkit:

```bash title="Overleaf Toolkit"
$ bin/docker-compose exec sharelatex /bin/bash -ce "cd /overleaf/services/web && node modules/server-ce-scripts/scripts/delete-user.mjs --email=joe@example.com"
```

Verouderde implementaties met docker-compose.yml:

```bash title="Legacy docker-compose"
$ docker exec sharelatex /bin/bash -ce "cd /overleaf/services/web && node modules/server-ce-scripts/scripts/delete-user.mjs --email=joe@example.com"
```

<Danger>

Het verwijderscript gebruikt een vast ingestelde force-optie die ervoor zorgt dat de verwijdering doorgaat, zelfs als de e-mail over de accountverwijdering niet kan worden verzonden (bijv. wanneer het e-mailadres van de gebruiker niet meer in gebruik is).

</Danger>

<Info>

De optie --skip-email kan worden gebruikt om te voorkomen dat er een informatieve e-mail naar de verwijderde gebruiker wordt gestuurd.

</Info>

## Een zacht verwijderde gebruiker herstellen {#restoring-a-soft-deleted-user}

Als een gebruiker alleen voorlopig (soft) is verwijderd, kunt u zijn account en de projecten die ermee zijn verwijderd herstellen. Projecten die de gebruiker zelf had verwijderd, blijven verwijderd.

<Steps>
<Step title="">
* Log in als beheerder.
* Klik op Admin -> Manage Users.
* Zoek de gebruiker die je wilt herstellen.
* Klik op Display deleted users.
* Klik op het pijlpictogram in de rij van de gebruiker.
* Klik op Restore om te bevestigen.
</Step>
</Steps>

<Danger>

Wanneer ENABLE\_CRON\_RESOURCE\_DELETION is ingesteld op true, kunnen zacht verwijderde accounts binnen een periode van 90 dagen worden hersteld. Na 90 dagen is accountherstel niet meer mogelijk.

</Danger>

## Gebruikers tellen {#counting-users}

Je kunt het aantal gebruikers opvragen via de beheerinterface op https://you-instance-url/admin/user#license. Voor programmatische controles en exports kunnen de volgende voorbeelden helpen.

Totaal aantal gebruikers:

```bash title="Total number of users"
echo 'db.users.countDocuments()' | docker exec -i mongo mongosh --quiet localhost/sharelatex
# overleaf [direct: primary] sharelatex> 16
```

Totaal aantal gebruikers via het metrics-endpoint:

```bash title="Num active users from metrics"
docker exec sharelatex curl http://127.0.0.1:3000/metrics | grep num_active_users
# # HELP num_active_users num_active_users
# # TYPE num_active_users gauge
# num_active_users{app="web-api",host="b3ae4ff549d8"} 16
```

Totaal aantal actieve gebruikers (voorbeeld: gebruikers die in de afgelopen 365 dagen actief waren):

```bash title="Total number of active users"
echo 'db.users.countDocuments({ lastActive: { $gte: new Date(new Date().getTime() - (365 * 24 * 60 * 60 * 1000)) } })' | docker exec -i mongo mongosh --quiet localhost/sharelatex
# overleaf [direct: primary] sharelatex> 10
```

## Accountgegevens van gebruikers bijwerken {#updating-user-account-information}

Hoe accountupdates worden uitgevoerd, hangt af van of SSO is ingeschakeld.

* Als SSO niet wordt gebruikt:
  * Beheerders kunnen accountgegevens van gebruikers wijzigen via Admin -> Manage Users (e-mailadres, voornaam, achternaam en het genereren van een link om het wachtwoord opnieuw in te stellen).
  * Gewone gebruikers kunnen hun eigen gegevens bijwerken via Account -> Account Settings (inclusief het wijzigen van hun wachtwoord en het genereren van Git-authenticatietokens).
* Als SSO wordt gebruikt:
  * Ayakaleaf Pro kan zo worden geconfigureerd dat de voor- en achternaam van een gebruiker bij het inloggen worden bijgewerkt op basis van het authenticatiesysteem.
  * Wanneer OVERLEAF\_SAML\_UPDATE\_USER\_DETAILS\_ON\_LOGIN of OVERLEAF\_LDAP\_UPDATE\_USER\_DETAILS\_ON\_LOGIN true zijn, is het formulier met gebruikersgegevens op https://your-instance-url/user/settings uitgeschakeld en kunnen voor- en achternaam alleen in je identiteitsbeheersysteem worden ingesteld.

Zie voor meer details:

* [SAML 2.0-configuratie](/nl/on-premises/configuration/overleaf-toolkit/authentication/saml-authentication)
* [LDAP-configuratie](/nl/on-premises/configuration/overleaf-toolkit/authentication/ldap-authentication)

### Q\&A {#q&a}

<Accordion title="Kan ik SSO-gebruikers vooraf aanmaken, bijvoorbeeld met een API?">

<strong>Antwoord:</strong> Hiervoor is geen HTTP-API. Maak het account aan met het bovenstaande `create-user`-script (zonder `--admin`) of in **Admin → Manage Users** met **Create account**. Als `EXTERNAL_AUTH` is ingesteld, heeft dat formulier een optie **Log in with SSO**, die het account aanmaakt zonder lokaal wachtwoord en zonder activatie-e-mail of -link: het dialoogvenster sluit na **Create**. Bij de eerste LDAP-, SAML- of OIDC-aanmelding krijgt de gebruiker het bestaande account met hetzelfde e-mailadres in plaats van een nieuw account, zie [Accounts en wachtwoorden](/nl/on-premises/configuration/overleaf-toolkit/authentication#accounts-and-passwords).

</Accordion>

<Accordion title="Kan ik de gebruikerslijst exporteren en later herstellen?">

<strong>Antwoord:</strong> Nee. Er is geen export of import van gebruikersaccounts, niet in **Admin → Manage Users** en ook niet als script. Accounts worden in MongoDB opgeslagen, dus maak er een back-up van en herstel ze met een [MongoDB-back-up](/nl/on-premises/maintenance/data-and-backups#mongodb). Het script `export-user-projects.mjs` exporteert de projecten van gebruikers als zip-bestanden, niet de accounts, zie [Projecten exporteren](/nl/on-premises/maintenance/data-and-backups/exporting-projects).

</Accordion>

<Accordion title="Hoe lang is de `create-user`-link geldig, en hoe reset ik een wachtwoord zonder e-mail?">

<strong>Antwoord:</strong> De link die `create-user` afdrukt, is 7 dagen geldig en werkt zonder SMTP, omdat je hem uit de uitvoer kopieert. Voer `create-user` opnieuw uit met hetzelfde e-mailadres om een nieuwe link te krijgen. Voor een bestaand account drukt het alleen een nieuwe link af, maar het stelt ook de beheerdersvlag van het account in volgens `--admin`; gebruik dus `--admin` wanneer je het voor een beheerder uitvoert.

Een beheerder kan ook zonder e-mail een herstellink krijgen: klik in **Admin → Manage Users** op het slotpictogram in de rij van de gebruiker, daarna op **Send reset link**, en kopieer de link uit het dialoogvenster. De link is 1 uur geldig, zie [Een activatie- of herstellink versturen](/on-premises/user-guide/administrators/user-management#send-an-activation-or-reset-link).

Of stel direct een wachtwoord in: klik op de naam van de gebruiker, dan op het potloodpictogram, voer een **New password** van minimaal 8 tekens in en klik op **Save**. Accounts die zich alleen via LDAP, SAML of OIDC aanmelden, kunnen op geen van beide manieren een wachtwoord krijgen.

</Accordion>
