## Een beheerder aanmaken

Implementaties met de Overleaf Toolkit:

```bash title="Overleaf Toolkit" wrap
$ bin/docker-compose exec sharelatex /bin/bash -ce "cd /overleaf/services/web && node modules/server-ce-scripts/scripts/create-user --admin --email=joe@example.com"
```

Verouderde implementaties met docker-compose.yml:

```bash title="Legacy docker-compose" wrap
$ docker exec sharelatex /bin/bash -ce "cd /overleaf/services/web && node modules/server-ce-scripts/scripts/create-user --admin --email=joe@example.com"
```

De opdracht maakt een gebruiker aan met het opgegeven e-mailadres als die nog niet bestaat, en maakt deze gebruiker beheerder. De uitvoer van de opdracht bevat een URL waar je het wachtwoord voor deze gebruiker kunt instellen en voor de eerste keer kunt inloggen.

<Info>

Voor een programmatische aanpak kun je hetzelfde script gebruiken om zowel gewone gebruikers als beheerders aan te maken. Laat voor gewone gebruikers de vlag --admin weg.

</Info>

Als je interne accounts gebruikt voor authenticatie en een bestaande gebruiker tot instantiebeheerder wilt promoveren of beheerdersrechten wilt intrekken, doe dan het volgende:

<Steps>
<Step title="Via de beheerinterface">
* Log in als bestaande beheerder.
* Klik op Admin -> Manage Users.
* Zoek de gebruiker en klik op diens e-mailadres.
* Scrol omlaag naar de sectie Site Admin en klik op de link (show).
* Vink het vakje Is Site Admin aan.
* Klik op Save om af te ronden.
</Step>
</Steps>

## Gebruikers verwijderen

Over het algemeen is het raadzaam om accounts niet te verwijderen, tenzij ze niet meer nodig zijn. Het verwijderen van een account verwijdert het account en zorgt ervoor dat samenwerkers de toegang tot projecten verliezen. Er is momenteel geen manier om accounts te deactiveren: ze bestaan met behoud van hun gegevens, of ze worden verwijderd.

Standaard worden accounts zacht verwijderd (soft delete). Zie `ENABLE_CRON_RESOURCE_DELETION` in de handleiding [Omgevingsvariabelen](/nl/on-premises/configuration/overleaf-toolkit/environment-variables) voor informatie over het permanent verwijderen van gebruikers uit je instantie.

<Info>

Accounts worden standaard zacht verwijderd. Zie `ENABLE_CRON_RESOURCE_DELETION` voor het gedrag bij permanente verwijdering.

</Info>

### Via Admin -> Manage Users

<Steps>
<Step title="">
* Log in als beheerder.
* Klik op Admin -> Manage Users.
* Zoek de gebruiker en vink het vakje naast diens e-mailadres aan.
* Klik op het prullenbakpictogram.
* Klik op Delete om te bevestigen.
</Step>
</Steps>

### Via de opdrachtregel

Gebruikersaccounts (en hun projecten) kunnen met de volgende opdrachten worden verwijderd.

Implementaties met de Overleaf Toolkit:

```bash title="Overleaf Toolkit"
$ bin/docker-compose exec sharelatex /bin/bash -ce "cd /overleaf/services/web && node modules/server-ce-scripts/scripts/delete-user.mjs --email=joe@example.com"
```

Verouderde implementaties met docker-compose.yml:

```bash title="Legacy docker-compose"
$ docker exec sharelatex /bin/bash -ce "cd /overleaf/services/web && node modules/server-ce-scripts/scripts/delete-user.mjs --email=joe@example.com"
```

<Danger>

Het verwijderscript gebruikt een vast ingestelde force-optie die ervoor zorgt dat de verwijdering doorgaat, zelfs als de e-mail over de accountverwijdering niet kan worden verzonden (bijv. wanneer het e-mailadres van de gebruiker niet meer in gebruik is).

</Danger>

<Info>

Sinds versie 5.5.0 kan de optie --skip-email worden gebruikt om te voorkomen dat er een informatieve e-mail naar de verwijderde gebruiker wordt gestuurd.

</Info>

## Een zacht verwijderde gebruiker herstellen

Als een gebruiker alleen zacht is verwijderd, kun je diens account en projecten herstellen.

<Steps>
<Step title="">
* Log in als beheerder.
* Klik op Admin -> Manage Users.
* Zoek de gebruiker die je wilt herstellen.
* Klik op de knop Display deleted users.
* Klik op het e-mailadres van de verwijderde gebruiker.
* Klik op Recover This Account.
* Klik op Recover om te bevestigen.
</Step>
</Steps>

<Danger>

Wanneer ENABLE\_CRON\_RESOURCE\_DELETION is ingesteld op true, kunnen zacht verwijderde accounts binnen een periode van 90 dagen worden hersteld. Na 90 dagen is accountherstel niet meer mogelijk.

</Danger>

## Gebruikers tellen

Je kunt het aantal gebruikers opvragen via de beheerinterface op https://you-instance-url/admin/user#license. Voor programmatische controles en exports kunnen de volgende voorbeelden helpen.

Totaal aantal gebruikers:

```bash title="Total number of users"
echo 'db.users.countDocuments()' | docker exec -i mongo mongosh --quiet localhost/sharelatex
# overleaf [direct: primary] sharelatex> 16
```

Totaal aantal gebruikers via het metrics-endpoint:

```bash title="Num active users from metrics"
docker exec sharelatex curl http://127.0.0.1:3000/metrics | grep num_active_users
# # HELP num_active_users num_active_users
# # TYPE num_active_users gauge
# num_active_users{app="web-api",host="b3ae4ff549d8"} 16
```

Totaal aantal actieve gebruikers (voorbeeld: gebruikers die in de afgelopen 365 dagen actief waren):

```bash title="Total number of active users"
echo 'db.users.countDocuments({ lastActive: { $gte: new Date(new Date().getTime() - (365 * 24 * 60 * 60 * 1000)) } })' | docker exec -i mongo mongosh --quiet localhost/sharelatex
# overleaf [direct: primary] sharelatex> 10
```

## Accountgegevens van gebruikers bijwerken

Hoe accountupdates worden uitgevoerd, hangt af van of SSO is ingeschakeld.

* Als SSO niet wordt gebruikt:
  * Beheerders kunnen accountgegevens van gebruikers wijzigen via Admin -> Manage Users (e-mailadres, voornaam, achternaam en het genereren van een link om het wachtwoord opnieuw in te stellen).
  * Gewone gebruikers kunnen hun eigen gegevens bijwerken via Account -> Account Settings (inclusief het wijzigen van hun wachtwoord en het genereren van Git-authenticatietokens).
* Als SSO wordt gebruikt:
  * Server Pro kan zo worden geconfigureerd dat de voor- en achternaam van een gebruiker bij het inloggen worden bijgewerkt op basis van het authenticatiesysteem.
  * Wanneer OVERLEAF\_SAML\_UPDATE\_USER\_DETAILS\_ON\_LOGIN of OVERLEAF\_LDAP\_UPDATE\_USER\_DETAILS\_ON\_LOGIN true zijn, is het formulier met gebruikersgegevens op https://your-instance-url/user/settings uitgeschakeld en kunnen voor- en achternaam alleen in je identiteitsbeheersysteem worden ingesteld.

Zie voor meer details:

* SAML 2.0-configuratie: https://docs.overleaf.com/on-premises/configuration/overleaf-toolkit/server-pro-only-configuration/saml-2.0
* LDAP-configuratie: https://docs.overleaf.com/on-premises/configuration/overleaf-toolkit/server-pro-only-configuration/ldap
