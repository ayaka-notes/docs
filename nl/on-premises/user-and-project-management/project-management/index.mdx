### Het auditlogboek van een project bekijken

Beheerders kunnen voor elk project een **Audit Log** bekijken. Dit auditlogboek toont gebeurtenissen zoals wanneer het delen via een link werd gewijzigd tussen privé en op tokens gebaseerd, wanneer uitnodigingen werden verzonden/geaccepteerd en wanneer een gebruiker via een token aan het project deelnam. Beheerders kunnen deze logboeken per project bekijken via **Your Instance** -> **Admin** -> **Manage Users** en vervolgens:

* Zoek de gebruiker
* Klik op het tabblad **Projects**
* Selecteer een project
* Klik op het pictogram (i)
* Klik op het tabblad **Audit Log**

Als een project met een benoemde samenwerker wordt gedeeld (via diens e-mailadres), wordt de ontvanger, zodra deze is toegetreden, met zijn rechten vermeld in het venster Share en is deze zichtbaar voor de projecteigenaar. Deze informatie wordt ook aan beheerders getoond wanneer ze het tabblad Project Info van het project bekijken via het beheerpaneel.

### Verwijderde documenten herstellen

1. Log in met je beheerdersgegevens
2. Klik op **Admin** en selecteer **Manage Users**
3. Voer in het zoekveld het e-mailadres in van de gebruiker voor wie je het document wilt herstellen
4. Klik op het e-mailadres in de lijst met resultaten om de pagina met gebruikersinformatie te openen
5. Klik op het tabblad **Projects** en gebruik het zoekveld om het project te zoeken
6. Klik op het informatiepictogram naast de projectnaam om de **Project Info** te openen
7. Klik op het tabblad **Deleted Docs**
8. Klik op de knop **Undelete** naast het verwijderde document om het terug te zetten in het project van de gebruiker.

Het herstelde bestand krijgt de volgende indeling: `FILENAME-TIMESTAMP.EXTENSION`. Een herstelde versie van `main.tex` wordt bijvoorbeeld in de hoofdmap van het project teruggezet met de bestandsnaam `main-2024-02-23-130441542.tex`.

### Eigendom van een project overdragen

Het beheerpaneel in Server Pro heeft een eigen pagina per project. Je kunt deze bereiken door de gebruiker te zoeken op "/admin/user", vervolgens naar het tabblad **Projects** te gaan, het project in de lijst te zoeken en op het informatiepictogram te klikken; of door met een bekend project-id rechtstreeks naar de pagina [**https://your-instance-url/admin/project/**](https://your-instance-url/admin/project/) te navigeren. Op de pagina met projectinformatie vind je een knop **Transfer Ownership**, die een venster opent waarin je een willekeurige gebruiker als nieuwe eigenaar kunt opgeven. De nieuwe eigenaar hoeft geen bestaande samenwerker aan het project te zijn.

<Info>

Houd er rekening mee dat de vorige eigenaar als onderdeel van de eigendomsoverdracht wordt toegevoegd als samenwerker met lees- en schrijftoegang tot het project.

</Info>

### De compileertime-out van projecten bijwerken

De standaard compileertime-out voor projecten is momenteel ingesteld op 180 seconden. Deze waarde kan worden gewijzigd; dat gebeurt in twee stappen.

Bewerk eerst het bestand **config/variables.env**, voeg de omgevingsvariabele `COMPILE_TIMEOUT` toe en stel de waarde in op de gewenste time-out in seconden. Bijvoorbeeld `COMPILE_TIMEOUT=300` voor 5 minuten.

<Danger>

Het heeft geen zin om de time-out boven de 10 minuten in te stellen. Als je dat doet, loop je hoogstwaarschijnlijk tegen een time-out in een ander onderdeel van de applicatie aan.

</Danger>

Nadat deze wijziging is aangebracht, moet je de **sharelatex**-container opnieuw aanmaken door de opdracht `bin/up -d` uit te voeren.

Het instellen van deze omgevingsvariabele werkt de time-outwaarde alleen bij voor nieuwe gebruikers; deze wordt **niet** met terugwerkende kracht toegepast op bestaande gebruikers, omdat de waarde wordt ingevuld wanneer de gebruiker voor het eerst wordt aangemaakt.

Om de time-out voor bestaande gebruikers aan te passen, moet je elk gebruikersrecord in de database wijzigen. We raden aan hierbij zeer voorzichtig te zijn en een consistente back-up te maken voordat je wijzigingen aanbrengt.

Informatie over het maken van back-ups vind je [hier](/nl/on-premises/maintenance/data-and-backups).

Om de compileertime-out voor alle bestaande gebruikers bij te werken, voer je de volgende shellopdracht uit op de Docker-host:

```bash wrap
echo 'db.users.updateMany({}, {$set: {"features.compileTimeout": <value>}})' | docker exec -i mongo mongosh --quiet localhost/sharelatex
```

Vervang `<value>` in de bovenstaande query door de gewenste time-outwaarde in seconden.

Nadat de opdracht is voltooid, zou je een bevestiging moeten zien met het aantal gewijzigde records. Typ vervolgens exit en druk op Enter om terug te keren naar de shell van de host.

### Projecttoegang bijhouden

Met de volgende opdracht kun je zien wie een project heeft geladen en wanneer:

```bash wrap
docker exec sharelatex bash -c 'grep "join project request" /var/log/overleaf/web.log'
```

Dit geeft zowel de `timestamp`, `user_id` als `project_id`.
