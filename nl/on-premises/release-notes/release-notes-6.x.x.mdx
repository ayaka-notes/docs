## Ayakaleaf Pro 6.3.1

<strong>Releasedatum:</strong> 2026.10.18

Zie: [https://github.com/ayaka-notes/ayakaleaf-pro/releases/tag/pro-v6.3.1](https://github.com/ayaka-notes/ayakaleaf-pro/releases/tag/pro-v6.3.1)

Met grote trots kondigen we de release aan van Overleaf Pro 6.3.1. Waar een gewone patchrelease zich zou richten op kleine oplossingen voor v6.3.0, gaat deze release veel verder: naast talrijke bugfixes introduceert ze vijf nieuwe functies.

<Info>

Dropbox-synchronisatie en GitLab-synchronisatie worden in 6.3.1 geleverd als **vroege previews** voor graytests en worden officieel uitgebracht in v6.4.0. Hun configuratie en gedrag kunnen tot die tijd nog veranderen. Beide zijn standaard uitgeschakeld. Meld eventuele problemen op [GitHub](https://github.com/ayaka-notes/ayakaleaf-pro/issues).

</Info>

### Wijzigingen

* Dropbox-synchronisatie in twee richtingen (vroege preview).
* GitLab-synchronisatie in twee richtingen (vroege preview), inclusief zelfbeheerde GitLab 15.10+.
* MCP Server per project voor AI-clients zoals Claude Code, Codex, Cursor, VS Code en Gemini CLI.
* Ondersteuning voor GitHub Enterprise in GitHub-synchronisatie.
* Herkenning van handgeschreven symbolen in het symbolenpalet, volledig in de browser.
* `OVERLEAF_DISABLE_LOCAL_LOGIN` toegevoegd om het inloggen met e-mailadres en wachtwoord te verbergen op SSO-instanties.
* Bugfixes gevonden door ons E2E-testsysteem en Internal Horizon Issue Investigation.
* Upstream Overleaf 6.3.1-patches.

#### Feature 01: Dropbox-synchronisatie (preview)

Elke gebruiker koppelt zijn eigen Dropbox-account, en de projecten waarvan hij eigenaar is en die met hem zijn gedeeld, verschijnen onder `Apps/<DROPBOX_APP_NAME>/`. Bewerkingen in Overleaf worden naar Dropbox gepusht, en bewerkingen in Dropbox komen terug via een ondertekende webhook. Git-bridge moet zijn ingeschakeld. Zie [Dropbox-synchronisatie](/nl/on-premises/configuration/overleaf-toolkit/dropbox-synchronisation).

#### Feature 02: GitLab-synchronisatie (preview)

Synchronisatie in twee richtingen met GitLab, op dezelfde manier als GitHub-synchronisatie werkt: koppel uw account, importeer een repository via het menu voor een nieuw project, exporteer een project, push en pull, en merge via merge requests. Zie [GitLab-synchronisatie](/nl/on-premises/configuration/overleaf-toolkit/gitlab-synchronisation).

#### Feature 03: MCP Server

Elk project krijgt een MCP-endpoint op `/project/<project_id>/mcp`, dat samen met git-bridge wordt ingeschakeld. Authenticeer met hetzelfde Git-token dat u voor `git clone` gebruikt. De toegang volgt de rollen van het project, en elke tool heeft een rate limit. Zie [MCP Server](/nl/on-premises/configuration/overleaf-toolkit/mcp-server).

#### Feature 04: GitHub Enterprise

Laat GitHub-synchronisatie met `GITHUB_SYNC_URL` verwijzen naar GitHub Enterprise Server of GitHub Enterprise Cloud met data residency. De standaardwaarden blijven op github.com. Zie [GitHub Enterprise](/nl/on-premises/configuration/overleaf-toolkit/github-synchronisation#github-enterprise).

#### Feature 05: Herkenning van handgeschreven symbolen

Zet het symbolenpalet in tekenmodus en schets een symbool om bijpassende LaTeX-commando's te krijgen. De herkenning draait in de browser met een model dat door ayaka-notes is getraind, zodat er geen gegevens de computer van de gebruiker verlaten. De tekenschakelaar is verborgen in browsers zonder `OffscreenCanvas` (bijv. Safari 15).

### Bugfixes

* Authenticatie: lokale accounts kunnen hun wachtwoord instellen en wijzigen op SSO-instanties, en OIDC-gebruikers kunnen hun eigen e-mailadres niet langer wijzigen ([#112](https://github.com/ayaka-notes/ayakaleaf-pro/pull/112)). De loginmethoden LDAP, SAML en OIDC blijven behouden, en uitloggen via SAML/OIDC werkt weer. Zie [Accounts en wachtwoorden](/nl/on-premises/configuration/overleaf-toolkit/authentication#accounts-and-passwords).
* LDAP, SAML en OIDC: naamattributen met meerdere waarden (zoals `cn`) laten de login niet langer mislukken, en OIDC-e-mailadressen worden net als bij LDAP en SAML naar kleine letters omgezet, zodat een account waarvan de IdP het e-mailadres met andere hoofdletters stuurt, wordt gekoppeld in plaats van te mislukken.
* Opgeschorte gebruikers: het opschorten van een gebruiker beëindigt zijn sessies en sluit zijn geopende editors. Zijn Git-tokens en MCP-downloads worden geweigerd.
* GitHub-synchronisatie: alleen de eigenaar kan een project exporteren, bewerkingen die tijdens het pullen zijn gemaakt blijven in behandeling, lege bestanden worden gesynchroniseerd, handmatige merges worden op GitHub geverifieerd, en een vervangen token wordt ingetrokken bij het opnieuw koppelen.
* Zotero / Mendeley: er wordt een melding getoond om opnieuw te koppelen wanneer de inloggegevens niet meer werken, en referenties worden na een import opnieuw geïndexeerd.
* Verzoeken aan externe API's (Zotero, Mendeley, GitHub, GitLab, webzoekopdrachten) krijgen een verbindingstime-out van 3 s in plaats van 1 s ([#106](https://github.com/ayaka-notes/ayakaleaf-pro/pull/106)).
* Wijzigingen bijhouden: reviewgegevens omvatten niet-geladen documenten en niet-opgeslagen wijzigingen (van [yu-i-i/overleaf-cep#262](https://github.com/yu-i-i/overleaf-cep/pull/262)).
* Error Assistant: biedt alleen oplossingen aan voor documenten in het project ([#103](https://github.com/ayaka-notes/ayakaleaf-pro/pull/103)).
* Beheerpaneel: het herstellen van een verwijderd project, het wijzigen van eigenaren en het bewerken van gebruikers werken correct. Zoeken gebruikt de letterlijke tekst, en een mislukte e-mail verstoort het aanmaken of verwijderen van accounts niet langer.
* Sjabloongalerij: een ongeldige sortering geeft 400 terug in plaats van 500, sjabloon-ID's worden gevalideerd, en bij het publiceren van een project zonder hoofdbestand wordt om een hoofdbestand gevraagd.
* Git-bridge: nginx stuurt `/git/` door naar `GIT_BRIDGE_HOST` en `GIT_BRIDGE_PORT`, en interne routes worden verborgen.
* Sandboxed Compiles: containers van recent gecompileerde projecten worden bewaard voor hergebruik.

<Accordion title="Zotero-/Mendeley-migratie voor bestaande installaties">

Migreer bij het upgraden naar de opnieuw uitgebrachte 6.3.0-image de metadata van bestaande via Zotero/Mendeley gekoppelde bibliografiebestanden met het onderstaande script. Deze migratie hoort bij fix `12031b8dfd`.

Hiermee wordt `zoteroGroupId` / `mendeleyGroupId` hernoemd naar `group_id`, wordt `importedByUserId` hernoemd naar `importer_id` en wordt `importedByName` verwijderd.

Maak een back-up van MongoDB en stop de applicatie voordat u de migratie uitvoert. Laat MongoDB draaien. Open de shell ervan (vervang `mongo` door de naam van uw container):

```bash
docker exec -it mongo mongosh
```

Voer het volgende uit in `mongosh` (vervang `sharelatex` door de naam van uw database):

```javascript
use sharelatex

(async () => {
  let updated = 0
  await db.projects.find({}, { rootFolder: 1 }).forEach(async project => {
    const changes = {}
    function visit(folders, path) {
      for (const [i, folder] of (folders || []).entries()) {
        const folderPath = `${path}.${i}`
        for (const [j, file] of (folder.fileRefs || []).entries()) {
          const data = { ...file.linkedFileData }
          if (!["zotero", "mendeley"].includes(data.provider)) continue
          const groupKey = `${data.provider}GroupId`
          if (![groupKey, "importedByUserId", "importedByName"].some(key => key in data)) continue
          for (const [oldKey, newKey] of [[groupKey, "group_id"], ["importedByUserId", "importer_id"]]) {
            if (data[oldKey] != null && data[oldKey] !== "") {
              const value = String(data[oldKey])
              if (newKey in data && data[newKey] !== value) {
                throw new Error(`Conflicting ${newKey}: project ${project._id}, file ${file._id}`)
              }
              data[newKey] = value
            }
            delete data[oldKey]
          }
          delete data.importedByName
          changes[`${folderPath}.fileRefs.${j}.linkedFileData`] = data
        }
        visit(folder.folders, `${folderPath}.folders`)
      }
    }
    visit(project.rootFolder, "rootFolder")
    if (!Object.keys(changes).length) return
    const result = await db.projects.updateOne(
      { _id: project._id, rootFolder: { $eq: project.rootFolder } },
      { $set: changes }
    )
    if (!result.matchedCount) throw new Error(`Project changed during migration: ${project._id}`)
    updated += result.modifiedCount
  })
  print(`Updated ${updated} project(s).`)
})()
```

Het script verwerkt ook geneste mappen en wijzigt alleen metadata van Zotero/Mendeley. Het kan veilig opnieuw worden uitgevoerd: een voltooide migratie meldt bij de volgende uitvoering `Updated 0 project(s).`. Als het stopt met een conflict, controleer dan het gemelde project/bestand; eerdere projecten zijn mogelijk al gemigreerd.

Start de bijgewerkte applicatie, laad de editor opnieuw en vernieuw een bestaand bibliografiebestand als de oorspronkelijke importeur ervan. Historische snapshots worden niet herschreven. Om terug te gaan naar de oude applicatie, zet u de MongoDB-back-up terug.

#### Feature 04: Template Pagination

De galerij pagineert, sorteert en zoekt nu in MongoDB. Dit werkt zonder enige voorbereiding; met duizenden sjablonen kunt u nog steeds deze indexen toevoegen om het snel te houden (veilig om opnieuw uit te voeren; `mongo`/`sharelatex` = de namen van uw container en database):

```bash
docker exec mongo mongosh sharelatex --quiet --eval '
db.templates.createIndex({category:1,lastUpdated:-1},{name:"category_1_lastUpdated_-1",background:true});
db.templates.createIndex({lastUpdated:-1},{name:"lastUpdated_-1",background:true});
db.templates.createIndex({category:1,name:1},{name:"category_1_name_1_ci",collation:{locale:"en",strength:2},background:true});
db.templates.createIndex({name:1},{name:"name_1_ci",collation:{locale:"en",strength:2},background:true});
'
```

Laat de `collation` op de twee `*_ci`-indexen staan zoals geschreven — de galerij voert query's uit met dezelfde collation, en MongoDB gebruikt alleen een overeenkomende index.

## Ayakaleaf Pro 6.2.2

<strong>Releasedatum:</strong> 2026.07.23

Zie: [https://github.com/ayaka-notes/ayakaleaf-pro/releases/tag/pro-v6.2.2](https://github.com/ayaka-notes/ayakaleaf-pro/releases/tag/pro-v6.2.2)

### Wijzigingen

Backport van de officiële hotfixpatches die zijn meegeleverd in upstream Overleaf `6.2.2` (bovenop `6.2.1`):

* Het geheime project-uitnodigingstoken lekt niet langer naar de logs. De encryptor van uitnodigingstokens logde bij elke versleuteling/ontsleuteling zijn eigen configuratie, inclusief de van `OVERLEAF_INVITE_TOKEN_SECRET` afgeleide cipherwachtwoorden.
* Uitgaande e-mail gemigreerd van de AWS SES v1-client die end-of-life is naar SESv2. Instanties die waren geconfigureerd met de e-maildriver `ses` konden helemaal geen e-mail versturen; verzenden gaat nu via `SESv2Client`.
* De groepsitems in de vervolgkeuzelijst voor het delen van projecten zijn afgeschermd achter de nieuwe feature flag `group-link-sharing`, zodat het delen via groepslinks niet langer wordt aangeboden op instanties waar het niet van toepassing is.
* Het venster voor het delen van projecten voor medewerkers gerepareerd. Openen als niet-eigenaar, of met de `sharing-updates`-flow uitgeschakeld, deed een verzoek dat altijd mislukte en een foutmelding "something went wrong" opleverde.
* `scripts/flush_docs_with_pending_updates.js` toegevoegd aan document-updater, een onderhoudsscript dat documenten herstelt die met een vastgelopen `PendingUpdates`-wachtrij in Redis zijn achtergebleven nadat hun project was geflusht of definitief verwijderd. Ondersteunt `--dry-run` en een veiligheidscontrole `--estimated-docs`.
* Afhankelijkheden bijgewerkt: `multer` 2.2.0, `form-data` 2.5.6, `protobufjs` 7.6.3, `@grpc/grpc-js` 1.14.4.

Deze release bevat ook de volgende fixes en verbeteringen van Ayakaleaf Pro:

* Volledige vertalingen toegevoegd voor 16 extra talen (cs, da, de, es, fi, fr, it, ja, ko, nl, no, pl, pt, ru, sv, tr), waarmee onvertaalde teksten zoals op de pagina voor het opnieuw instellen van het wachtwoord zijn opgelost. Lost [#38](https://github.com/ayaka-notes/ayakaleaf-pro/issues/38) op.
* Het aantal items in de knop "show N more projects" van het beheerpaneel gerepareerd; dat toonde het verkeerde getal omdat de meervoudsplaatshouder niet correct werd doorgegeven.
* Validatiefouten bij GitHub-export gerepareerd; deze worden nu weergegeven via statische i18n-sleutels in plaats van ruwe berichten, en de foutsleutels die niet meer door het GitHub Sync-venster worden gebruikt, zijn verwijderd.

Backport van de officiële hotfixpatches die zijn meegeleverd in upstream Overleaf `6.2.1` (bovenop `6.2.0`):

* Het realtime-bericht `applyOtUpdate` is versterkt met een strikt validatieschema in plaats van elk object te accepteren, waardoor misvormde bewerkingsoperaties worden geweigerd.
* Dat schema is versoepeld zodat `meta.tc` optioneel is, waardoor geldige updates niet langer door de strengere validatie worden geweigerd.
* De editor (ShareJS-client) is gerepareerd, zodat operaties die tot een lege op worden gereduceerd — opgeheven door een externe/gelijktijdige op, of volledig teruggedraaid met ongedaan maken — worden genegeerd in plaats van naar de server te worden gestuurd, en het document correct als opgeslagen wordt gemeld. Voorkomt onterechte synchronisatieproblemen / problemen met "niet-opgeslagen wijzigingen" rond ongedaan maken en gelijktijdig bewerken.
