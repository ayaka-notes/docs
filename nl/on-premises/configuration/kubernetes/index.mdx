Een Kubernetes-implementatie leest dezelfde omgevingsvariabelen als de Toolkit. Waar een Toolkit-pagina zegt "voeg dit toe aan `config/variables.env`", zet je de waarde in de ConfigMap `overleaf-env`, of in de Secret `overleaf-secrets` als het om een wachtwoord, sleutel of token gaat. Herstart daarna:

```bash
kubectl -n overleaf apply -f 30-config.yaml        # after editing the ConfigMap
kubectl -n overleaf patch secret overleaf-secrets --type merge \
  -p '{"stringData":{"GITHUB_TOKEN_CIPHER_PASSWORD":"'"$(openssl rand -hex 32)"'"}}'
kubectl -n overleaf rollout restart deployment/overleaf
```

Waarden in `config/overleaf.rc` zijn Toolkit-instellingen, geen omgevingsvariabelen; de vragen en antwoorden aan het einde van deze pagina vertellen wat ze vervangt.

### Certificaten en andere bestanden

Sommige functies verwachten een bestandspad in plaats van een waarde: de SAML-certificaten (`OVERLEAF_SAML_IDP_CERT`, ...), de LDAP-CA (`OVERLEAF_LDAP_TLS_OPTS_CA_PATH`), of een privé-CA voor een zelfgehoste GitHub Enterprise, GitLab of Gitea (`NODE_EXTRA_CA_CERTS`). Zet de bestanden in een Secret en mount die waar de Toolkit-pagina's ze verwachten, `/var/lib/overleaf/certs`:

```bash
kubectl -n overleaf create secret generic overleaf-certs --from-file=idp_cert.pem --from-file=ca.pem
```

```yaml title="40-overleaf.yaml (additions)"
          volumeMounts:
            # ...
            - name: certs
              mountPath: /var/lib/overleaf/certs
              readOnly: true
      volumes:
        # ...
        - name: certs
          secret:
            secretName: overleaf-certs
```

Verwijs er daarna in de ConfigMap naar via hun pad, bijvoorbeeld `NODE_EXTRA_CA_CERTS: /var/lib/overleaf/certs/ca.pem`, en herstart.

<Warning>

<strong>Cipher-wachtwoorden.</strong> Stel elk `*_CIPHER_PASSWORD` van de functies die je gebruikt in de Secret in. Sommige functies genereren anders bij het eerste gebruik een sleutelbestand in het datavolume: met één replica werkt dat totdat het volume verloren gaat, met meerdere replica's zou elke replica met een andere sleutel versleutelen.

</Warning>

### Vragen en antwoorden

<Accordion title="Welke Toolkit-instellingen uit `config/overleaf.rc` heb ik nodig?">

<strong>Antwoord:</strong> Geen ervan wordt door Ayakaleaf Pro gelezen. Hun tegenhangers in Kubernetes:

| `config/overleaf.rc`                         | Kubernetes                                                        |
| -------------------------------------------- | ----------------------------------------------------------------- |
| `OVERLEAF_LISTEN_IP`, `OVERLEAF_PORT`        | de Service (NodePort) of je ingress                               |
| `SIBLING_CONTAINERS_ENABLED`                 | `SANDBOXED_COMPILES*` in de ConfigMap, Docker-socket in de pod    |
| `GIT_BRIDGE_ENABLED`                         | [Git-integratie](/nl/on-premises/configuration/kubernetes/integrations/git-integration)                       |
| `MONGO_ENABLED`, `REDIS_ENABLED`, `MONGO_URL`, `REDIS_HOST` | de StatefulSets of je beheerde services, `OVERLEAF_MONGO_URL` en `OVERLEAF_REDIS_HOST` |
| `REDIS_AOF_PERSISTENCE`                      | `--appendonly yes` in `20-redis.yaml`                             |
| `NGINX_ENABLED`, `TLS_*`                     | je ingress of load balancer                                       |

</Accordion>
