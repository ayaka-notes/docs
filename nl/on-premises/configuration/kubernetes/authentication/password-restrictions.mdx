De **web**-service controleert lokale wachtwoorden wanneer gebruikers zich registreren of een wachtwoord instellen of wijzigen. SSO-logins (LDAP, SAML, OIDC) worden niet beïnvloed; hun wachtwoorden zijn een zaak van de identity provider. Zie [Wachtwoordbeperkingen](/nl/on-premises/configuration/overleaf-toolkit/authentication/password-restrictions) voor de Toolkit.

| | |
| --- | --- |
| Service | web, in elke Ayakaleaf Pro-pod; gelezen wanneer web start |
| Netwerk | geen |
| Periodieke taken | geen |

### Configuratie

Voeg toe aan de ConfigMap `overleaf-env` en herstart:

```yaml title="30-config.yaml (additions)"
  OVERLEAF_PASSWORD_VALIDATION_MIN_LENGTH: "12"
  OVERLEAF_PASSWORD_VALIDATION_MAX_LENGTH: "72"
```

```bash
kubectl apply -f 30-config.yaml
kubectl -n overleaf rollout restart deployment/overleaf     # or statefulset/overleaf
```

| Variabele | Standaard | |
| --- | --- | --- |
| `OVERLEAF_PASSWORD_VALIDATION_MIN_LENGTH` | `8` | Kortste geaccepteerde wachtwoord. |
| `OVERLEAF_PASSWORD_VALIDATION_MAX_LENGTH` | `72` | Langste geaccepteerde wachtwoord; waarden boven `72` worden behandeld als `72`. |

Zet de getallen tussen aanhalingstekens: een ConfigMap bevat alleen strings.

<Warning>

`OVERLEAF_PASSWORD_VALIDATION_PATTERN` wordt gelezen maar niet afgedwongen: een wachtwoord dat er niet aan voldoet, wordt geaccepteerd. Alleen de lengtelimieten zijn van toepassing.

</Warning>

### Meerdere replica's

Niets extra's: elke replica leest dezelfde ConfigMap.

### Getest op Kubernetes

Op Kubernetes 1.37 met één replica, `OVERLEAF_PASSWORD_VALIDATION_MIN_LENGTH: "12"` en `OVERLEAF_PASSWORD_VALIDATION_PATTERN: aA$3` in de ConfigMap, weigerde het activeren van een nieuw account een wachtwoord van 10 tekens en accepteerde het een wachtwoord van 20 tekens met alleen kleine letters, dat het patroon zou hebben geweigerd. Onze end-to-endtests voor registratie weigeren met de standaardinstellingen ook `123456` als te kort.
