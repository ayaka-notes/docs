Gasttoegang tot gedeelde projecten, openbare pagina's en zelfregistratie worden ingeschakeld met omgevingsvariabelen die de **web**-service leest; de real-time-service bedient gasten vervolgens via hun sessie. Wat elke schakelaar openstelt, staat beschreven in [Openbare toegang](/nl/on-premises/configuration/overleaf-toolkit/authentication/public-access).

| | |
| --- | --- |
| Service | web (en real-time voor gasten in de editor), in elke Ayakaleaf Pro-pod; gelezen wanneer web start |
| Pod → buiten | de SMTP-server, wanneer registratie activeringsmails verstuurt |
| Status | toegangstokens van gasten in de sessie, rate limits voor registratie in Redis |
| Periodieke taken | geen |

### Configuratie

Voeg de schakelaars die je nodig hebt toe aan de ConfigMap `overleaf-env`:

```yaml title="30-config.yaml (additions)"
  # Guests open link-shared projects without an account
  OVERLEAF_ALLOW_ANONYMOUS_READ_AND_WRITE_SHARING: "true"
  # Signed-out visitors may open /learn, /templates, /devs and view links
  OVERLEAF_ALLOW_PUBLIC_ACCESS: "true"
  # Self-registration: "true", or only some domains
  OVERLEAF_ALLOW_PUBLIC_REGISTRATION: "@example.com, @*.uni.example"
```

```bash
kubectl apply -f 30-config.yaml
kubectl -n overleaf rollout restart deployment/overleaf     # or statefulset/overleaf
```

Zet elke waarde tussen aanhalingstekens. Waarden die met `@` beginnen, moeten in YAML tussen aanhalingstekens staan, anders weigert `kubectl apply` het bestand.

Registratie die tot domeinen is beperkt, verstuurt een activeringsmail, dus [E-mailbezorging](/nl/on-premises/configuration/kubernetes/email-delivery) moet vanuit de pods werken: zet de SMTP-host in de ConfigMap en `OVERLEAF_EMAIL_SMTP_PASS` in de Secret.

### Meerdere replica's

Niets extra's. De toegang van een gast tot een project wordt bewaard in de sessie in Redis, zodat de editor werkt op welke replica de load balancer ook kiest.

### Getest op Kubernetes

Op Kubernetes 1.37 slagen onze end-to-endtests voor openbare toegang: op één replica zelfregistratie met `OVERLEAF_ALLOW_PUBLIC_REGISTRATION` ingesteld op `true`, op één domein, op meerdere domeinen met een subdomein-wildcard en op `@*`, met de activeringsmail voor de domeinmodi (43 gevallen); uitgelogde bezoekers op `/devs` en een geplaatst fragment dat via de login behouden blijft met `OVERLEAF_ALLOW_PUBLIC_ACCESS` (2 gevallen); een uitgelogde gast in een via een link gedeeld project met beide schakelaars ingeschakeld (3 gevallen); en op drie replica's achter HAProxy, OIDC in combinatie met openbare toegang (1 geval).
