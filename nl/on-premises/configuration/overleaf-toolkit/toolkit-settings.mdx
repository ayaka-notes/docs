Deze pagina beschrijft de omgevingsvariabelen die worden ondersteund in het bestand `config/overleaf.rc` voor Toolkit-implementaties.

Het bestand `config/overleaf.rc` bestaat uit variabeledefinities in de vorm `NAME=value`. Regels die beginnen met `#` worden als commentaar behandeld.

<Info>

Na elke wijziging in `overleaf.rc` of `variables.env` moet je de Docker-containers opnieuw aanmaken door `bin/up` uit te voeren.

</Info>

## Container

### `sharelatex`

| Naam                         | Beschrijving                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| ---------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `PROJECT_NAME`               | <p>Stelt de waarde in van de vlag `--project-name` die aan `docker-compose` wordt meegegeven. Dit is handig wanneer je meerdere Overleaf-instanties op één host draait, omdat elke instantie een andere projectnaam kan hebben.<br /><br />- <strong>Standaard</strong>: `overleaf`</p>                                                                                                                                                                                                                                                 |
| `OVERLEAF_IMAGE_NAME`        | <p>Docker-image die wordt gebruikt door de Server Pro/CE-applicatiecontainer. Dit is alleen de naam van de Docker-image; de tag van de Docker-image wordt uit `config/version` gehaald.<br /><br />- <strong>Standaard:</strong><br />- Server Pro: `ghcr.io/ayaka-notes/overleaf-pro`<br />- Community Edition: `sharelatex/sharelatex`</p>                                                                                                                                                                                                 |
| `SERVER_PRO`                 | <p>Wanneer ingesteld op `true`, gebruikt de Toolkit de Server Pro-image (`ghcr.io/ayaka-notes/overleaf-pro`) in plaats van de standaard Server CE-image (`sharelatex/sharelatex`).<br /><br />- <strong>Standaard</strong>: `false`</p>                                                                                                                                                                                                                                                                   |
| `GIT_BRIDGE_ENABLED`         | <p>Stel in op `true` om de git-bridge-functie in te schakelen (alleen Server Pro). Zie voor meer informatie de gebruikersdocumentatie <a href="https://www.overleaf.com/learn/how-to/Git_integration">https://www.overleaf.com/learn/how-to/Git_integration</a>.<br /><br />- <strong>Standaard:</strong> `false`</p>                                                                                                                                                                                                                        |
| `GIT_BRIDGE_IMAGE`           | <p>Docker-image die wordt gebruikt door de git-bridge-container (alleen Server Pro). Dit is alleen de naam van de Docker-image; de tag van de Docker-image wordt uit `config/version` gehaald.<br /><br />- <strong>Standaard:</strong> `ghcr.io/ayaka-notes/overleaf-pro/git-bridge`</p>                                                                                                                                                                                                                                                                              |
| `GIT_BRIDGE_DATA_PATH`       | Stelt het pad in naar de map die in de container `git-bridge` (alleen Server Pro) wordt gemount en wordt gebruikt om de git-repositories op te slaan. Dit kan een volledig pad zijn (beginnend met een `/`) of een pad relatief ten opzichte van de basismap van de Toolkit.                                                                                                                                                                                                                                                                                     |
| `GIT_BRIDGE_LOG_LEVEL`       | <p>Configureer het logniveau van de container `git-bridge`. Beschikbare niveaus: `TRACE`, `DEBUG`, `INFO`, `WARN`, `ERROR`.<br /><br />- <strong>Standaard:</strong> `INFO`</p>                                                                                                                                                                                                                                                                                       |
| `SIBLING_CONTAINERS_ENABLED` | <p>Wanneer ingesteld op `true`, gebruikt de Toolkit de techniek <strong>Sibling Containers</strong> om projecten in afzonderlijke sandboxes te compileren, met een aparte Docker-container voor elk project. Zie de documentatie &#x3C;server-pro-only-configuration/sandboxed-compiles> voor meer informatie.<br /><br />- <strong>Vereist:</strong> `SERVER_PRO=true`<br />- <strong>Standaard:</strong> `true`</p>                                                                                                    |
| `SIBLING_CONTAINERS_PULL`    | <p>Wanneer ingesteld op `true`, haalt de Toolkit bij gebruik van de opdracht `bin/up` automatisch alle TeX Live-images op die zijn ingesteld met `ALL_TEX_LIVE_DOCKER_IMAGES` in het bestand <strong>config/variables.env</strong>.<br /><br />- <strong>Standaard:</strong> `true`</p>                                                                                                                                                                                                                                      |
| `DOCKER_SOCKET_PATH`         | <p>Stelt het pad in naar de Docker-socket op de hostmachine (de machine waarop de Toolkit draait). Wanneer `SIBLING_CONTAINERS_ENABLED` `true` is, wordt de socket in de container gemount, zodat de compilerservice nieuwe Docker-containers op de host kan starten.<br /><br />- <strong>Vereist:</strong> `SIBLING_CONTAINERS_ENABLED=true`<br />- <strong>Standaard:</strong> `/var/run/docker.sock`</p>                                                                                               |
| `OVERLEAF_DATA_PATH`         | <p>Stelt het pad in naar de map die in de hoofdcontainer `sharelatex` wordt gemount en wordt gebruikt om compilatiegegevens op te slaan. Dit kan een volledig pad zijn (beginnend met een `/`) of een pad relatief ten opzichte van de basismap van de Toolkit.<br /><br />- <strong>Standaard:</strong> `data/overleaf`</p>                                                                                                                                                                                                               |
| `OVERLEAF_LISTEN_IP`         | <p>Stelt de IP-adres(sen) van de host in waaraan de container wordt gekoppeld. Als dit bijvoorbeeld is ingesteld op `0.0.0.0`, is de webinterface beschikbaar op elk IP-adres van de host. Voor directe toegang tot de container moet `OVERLEAF_LISTEN_IP` worden ingesteld op je openbare IP-adres. Het instellen van `OVERLEAF_LISTEN_IP` op `0.0.0.0` of op het externe IP-adres van je host veroorzaakt doorgaans fouten in combinatie met de .<br /><br />- <strong>Standaard:</strong> `127.0.0.1`</p> |
| `OVERLEAF_PORT`              | <p>Stelt de hostpoort in waaraan de container wordt gekoppeld. Als dit bijvoorbeeld is ingesteld op `8099` en `OVERLEAF_LISTEN_IP` op `127.0.0.1`, is de webinterface beschikbaar op `http://localhost:8099`.<br /><br />- <strong>Standaard:</strong> `80`</p>                                                                                                                                                                                                                        |
| `OVERLEAF_LOG_PATH`          | <p>Stelt het pad in naar de map die in de hoofdcontainer `sharelatex` wordt gemount en wordt gebruikt om applicatielogs beschikbaar te maken op de Docker-host. Dit kan een volledig pad zijn (beginnend met een `/`) of een pad relatief ten opzichte van de basismap van de Toolkit. Verwijder de configuratieregel om de bind-mount uit te schakelen. Indien niet ingesteld, worden logs verwijderd bij het opnieuw aanmaken van de container.<br /><br />Zie voor informatie over logging.<br /><br />- <strong>Standaard:</strong> niet ingesteld</p>                                 |

### `mongo`

| Naam              | Beschrijving                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| ----------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `MONGO_ENABLED`   | <p>Wanneer ingesteld op `true`, maakt de Toolkit een MongoDB-container aan om de database te hosten. Wanneer ingesteld op `false`, wordt deze container niet aangemaakt en gebruikt het systeem in plaats daarvan de MongoDB-database die is opgegeven in `MONGO_URL`.<br /><br />- <strong>Standaard</strong>: `true`</p>                                                                                                                                 |
| `MONGO_URL`       | <p>Geeft de MongoDB-verbindings-URL op die wordt gebruikt wanneer `MONGO_ENABLED` `false` is.<br /><br />- <strong>Standaard</strong>: niet ingesteld</p>                                                                                                                                                                                                                                                                                                           |
| `MONGO_DATA_PATH` | <p>Stelt het pad in naar de map die in de container `mongo` wordt gemount en wordt gebruikt om de MongoDB-database op te slaan. Dit kan een volledig pad zijn (beginnend met een `/`) of een pad relatief ten opzichte van de basismap van de Toolkit. Deze optie heeft alleen invloed op de lokale container `mongo` die wordt aangemaakt wanneer `MONGO_ENABLED` `true` is.<br /><br />- <strong>Standaard</strong>: `data/mongo`</p> |
| `MONGO_IMAGE`     | <p>Docker-image die wordt gebruikt door de MongoDB-container. Dit is alleen de naam van de Docker-image; de tag van de Docker-image hoort in `MONGO_VERSION` (zie hieronder).<br /><br />- <strong>Standaard:</strong> `mongo`</p>                                                                                                                                                                                                                             |
| `MONGO_VERSION`   | <p>MongoDB-versie die wordt gebruikt door de MongoDB-container. De waarde moet beginnen met de hoofdversie van MongoDB en een punt, bijv. `6.0` of `6.0-with-suffix`.<br /><br />- <strong>Standaard:</strong> `6.0`</p>                                                                                                                                                                                                                             |

### `redis`

| Naam                    | Beschrijving                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| ----------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `REDIS_ENABLED`         | <p>Wanneer ingesteld op `true`, maakt de Toolkit een Redis-container aan om de Redis-database te hosten. Wanneer ingesteld op `false`, wordt deze container niet aangemaakt en gebruikt het systeem in plaats daarvan de Redis-database die is opgegeven in `REDIS_HOST` en `REDIS_PORT`.<br /><br />- <strong>Standaard</strong>: `true`</p>                                                                                                |
| `REDIS_HOST`            | <p>Geeft de Redis-host op die wordt gebruikt wanneer `REDIS_ENABLED` `false` is.<br /><br />- <strong>Standaard</strong>: niet ingesteld</p>                                                                                                                                                                                                                                                                                                                     |
| `REDIS_PORT`            | <p>Geeft de Redis-poort op die wordt gebruikt wanneer `REDIS_ENABLED` `false` is.<br /><br />- <strong>Standaard</strong>: niet ingesteld</p>                                                                                                                                                                                                                                                                                                                     |
| `REDIS_DATA_PATH`       | <p>Stelt het pad in naar de map die in de container `redis` wordt gemount en wordt gebruikt om de Redis-database op te slaan. Dit kan een volledig pad zijn (beginnend met een `/`) of een pad relatief ten opzichte van de basismap van de Toolkit. Deze optie heeft alleen invloed op de lokale container `redis` die wordt aangemaakt wanneer `REDIS_ENABLED` `true` is.<br /><br />- <strong>Standaard</strong>: `data/redis`</p> |
| `REDIS_AOF_PERSISTENCE` | <p>Schakel AOF-persistentie (Append Only File) in voor Redis. Dit is de <strong>aanbevolen</strong> configuratie voor Redis-persistentie.<br /><br />Zie voor meer details de sectie &#x3C;../../../maintenance/data-and-backups#aof-append-only-file> in &#x3C;../../maintenance/data-and-backups>.<br /><br />- <strong>Standaard:</strong> `true`</p>                                                                                               |

### `nginx`

| Naam                   | Beschrijving                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `NGINX_ENABLED`        | <p>Wanneer ingesteld op `true`, maakt de Toolkit een NGINX-container aan die als TLS-proxy fungeert.<br /><br />- <strong>Standaard</strong>: `false`</p>                                                                                                                                                                                                                                                                                                                                 |
| `NGINX_CONFIG_PATH`    | <p>Pad naar het NGINX-configuratiebestand dat voor de TLS-proxy wordt gebruikt.<br /><br />- <strong>Standaard</strong>: `config/nginx/nginx.conf`</p>                                                                                                                                                                                                                                                                                                                                                            |
| `NGINX_TLS_LISTEN_IP`  | <p>Stelt de IP-adres(sen) van de host in waaraan de TLS-proxycontainer voor HTTPS wordt gekoppeld. Als dit bijvoorbeeld is ingesteld op `0.0.0.0`, is de HTTPS-webinterface beschikbaar op elk IP-adres van de host. Doorgaans moet dit worden ingesteld op het externe IP-adres van je host.<br /><br />- <strong>Standaard</strong>: `127.0.1.1`</p>                                                                                                                                                       |
| `NGINX_HTTP_LISTEN_IP` | <p>Stelt de IP-adres(sen) van de host in waaraan de TLS-proxycontainer voor HTTP-omleiding wordt gekoppeld. Als dit bijvoorbeeld is ingesteld op `127.0.1.1`, worden HTTP-verbindingen naar `127.0.1.1` omgeleid naar de HTTPS-webinterface. Doorgaans moet dit worden ingesteld op het externe IP-adres van je host. Stel het niet in op `0.0.0.0`, omdat dit doorgaans een conflict met `OVERLEAF_LISTEN_IP` veroorzaakt.<br /><br />- <strong>Standaard</strong>: `127.0.1.1`</p> |
| `NGINX_HTTP_PORT`      | <p>Stelt de hostpoort in waaraan de TLS-proxycontainer voor HTTP wordt gekoppeld.<br /><br />- <strong>Standaard</strong>: `80`</p>                                                                                                                                                                                                                                                                                                                                                                  |
| `TLS_PORT`             | <p>Stelt de hostpoort in waaraan de TLS-proxycontainer voor HTTPS wordt gekoppeld.<br /><br />- <strong>Standaard</strong>: `443`</p>                                                                                                                                                                                                                                                                                                                                                                |
| `TLS_PRIVATE_KEY_PATH` | <p>Pad naar de privésleutel die voor de TLS-proxy wordt gebruikt.<br /><br />- <strong>Standaard</strong>: `config/nginx/certs/overleaf_key.pem`</p>                                                                                                                                                                                                                                                                                                                                                      |
| `TLS_CERTIFICATE_PATH` | <p>Pad naar het openbare certificaat dat voor de TLS-proxy wordt gebruikt.<br /><br />- <strong>Standaard</strong>: `config/nginx/certs/overleaf_certificate.pem`</p>                                                                                                                                                                                                                                                                                                                                       |
