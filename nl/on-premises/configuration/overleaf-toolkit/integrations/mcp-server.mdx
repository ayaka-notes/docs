Elk project heeft een MCP-server, zodat AI-clients zoals Claude Code, Codex, Cursor, VS Code of Gemini CLI eraan kunnen werken: de bestanden lezen en bewerken, het project compileren, het LaTeX-logboek lezen, de pdf downloaden en op opmerkingen reageren. Vanaf v6.3.3 kunnen ze ook de geschiedenis doorzoeken en versies herstellen, bijgehouden wijzigingen beoordelen, opmerkingen toevoegen, de projectchat gebruiken en bestanden verplaatsen.

<Info>

Deze functie is ontwikkeld door [ayaka-notes/ayakaleaf-pro](https://github.com/ayaka-notes/ayakaleaf-pro). Ze is geïntroduceerd in v6.3.1 en latere versies. De tools voor geschiedenis, bijgehouden wijzigingen, projectchat, nieuwe opmerkingen en het verplaatsen van bestanden zijn beschikbaar vanaf v6.3.3, zie [Nieuw in v6.3.3](/on-premises/user-guide/users/mcp-server#new-in-v6.3.3).

</Info>

### Instellen {#setup}

De MCP-server hoort bij de Git-integratie: schakel [git-bridge](/nl/on-premises/configuration/overleaf-toolkit/integrations/git-integration) in, en de MCP-server is ook beschikbaar. Verder hoef je niets te configureren.

### Een AI-client verbinden {#connect-an-ai-client}

1. Genereer in de **accountinstellingen** een Git-authenticatietoken. Hetzelfde token wordt gebruikt voor de MCP-server en voor Git.
2. Open in de editor **Integraties** en klik op **MCP-server**. Daar zie je het adres van de MCP-server van het project, `https://<your-overleaf>/project/<project_id>/mcp`, en hoe je deze aan elke AI-client toevoegt: kopieer de opdracht en vervang `<token>` door je token.

Het token wordt verzonden als de HTTP-header `Authorization: Bearer <token>`. De opdracht voor Claude Code is bijvoorbeeld:

```bash
claude mcp add --transport http overleaf \
  https://<your-overleaf>/project/<project_id>/mcp \
  --header "Authorization: Bearer <token>"
```

### Gebruik {#usage}

Zodra de verbinding er is, vraag je de AI-client in gewone taal wat je wilt. Bijvoorbeeld:

| Je vraagt | De AI-client gebruikt |
| --- | --- |
| _Verbeter de typfouten in de inleiding._ | `read_file`, `edit_file`: de wijzigingen verschijnen live in de editor |
| _Compileer het project en los de LaTeX-fouten op._ | `compile`, `get_compile_log`, `edit_file` |
| _Beantwoord de openstaande opmerkingen en markeer ze daarna als opgelost._ | `list_comments`, `reply_to_comment`, `resolve_comment` |
| _Schakel over naar XeLaTeX en download de pdf._ | `update_settings`, `compile`, `get_output_file_link` |
| _Herschrijf de samenvatting als bijgehouden wijziging._ | `read_file`, `edit_file` met `trackChanges` (v6.3.3) |
| _Wat is er veranderd sinds de ingediende versie?_ | `list_versions`, `list_changes`, `diff` (v6.3.3) |
| _Verplaats de hoofdstukken naar een map met de naam chapters._ | `move_file` (v6.3.3) |

### Tools {#tools}

| Groep | Tools |
| --- | --- |
| Project | `get_clone_info`, `get_settings`, `update_settings` |
| Bestanden | `list_files`, `read_file`, `edit_file`, `write_file`, `delete_file`, `move_file`, `create_folder` |
| Compileren | `compile`, `get_compile_log`, `get_output_file_link`, `word_count` |
| Opmerkingen | `list_comments`, `reply_to_comment`, `resolve_comment`, `reopen_comment`, `add_comment`, `edit_comment_message`, `delete_comment_message` |
| Bijgehouden wijzigingen | `list_tracked_changes`, `accept_tracked_changes`, `reject_tracked_changes` |
| Geschiedenis | `list_versions`, `list_changes`, `diff`, `create_version`, `delete_version`, `restore_file`, `restore_project` |
| Chat | `list_chat_messages`, `send_chat_message` |

v6.3.3 heeft 33 tools, of 31 met `OVERLEAF_DISABLE_CHAT=true`, waarmee de chattools verdwijnen. v6.3.1 en v6.3.2 hebben de andere 17: alles hierboven behalve `move_file`, `create_folder`, `add_comment`, `edit_comment_message`, `delete_comment_message`, de tools voor bijgehouden wijzigingen, de chattools en de geschiedenistools behalve `list_versions`. In v6.3.3 leest `read_file` ook een bestand in een versie van de geschiedenis, accepteren `edit_file` en `write_file` `trackChanges`, en stelt `update_settings` ook de taal van de spellingcontrole in.

Bewerkingen met `edit_file`, `write_file` en `move_file` verschijnen live in de editor en worden samengevoegd met die van medewerkers. Voor veel bestanden tegelijk of binaire bestanden kan de AI-client het project ook met Git klonen en pushen.

Met `trackChanges` is een bewerking van een bestaand bestand een bijgehouden wijziging van de gebruiker van het token, ook als wijzigingen bijhouden in het project uit staat; een nieuw bestand is dat nooit. Zonder `trackChanges` volgen bewerkingen de instelling voor wijzigingen bijhouden van het project.

### Rechten {#permissions}

De MCP-server volgt de deelinstellingen van het project, net als Git:

* Iedereen die het project kan bekijken, kan het lezen, compileren en de uitvoer downloaden.
* Alleen de eigenaar en bewerkers kunnen de bestanden en instellingen wijzigen, versies herstellen en bijgehouden wijzigingen accepteren of weigeren.
* Reviewers kunnen ook opmerkingen toevoegen en erop reageren, de opmerkingen die ze zelf begonnen zijn oplossen, heropenen of verwijderen, en versies opslaan. Ze kunnen geen bestanden bewerken, ook niet als bijgehouden wijzigingen.
* Iedereen bewerkt alleen de eigen opmerkingsberichten, en reviewers verwijderen alleen hun eigen berichten.
* Alleen de eigenaar verwijdert versies die anderen hebben opgeslagen.
* Kijkers die via een link zijn toegetreden, zien de opmerkingen, bijgehouden wijzigingen, geschiedenis en chat niet, net als in de editor. Uitgenodigde kijkers kunnen ze zien en de chat gebruiken.
* Als de projecteigenaar geen **Full project history** heeft, tonen de geschiedenistools alleen de wijzigingen van de laatste 24 uur, net als het geschiedenispaneel. Beheerders zien ze allemaal.

De gebruikershandleiding heeft een tabel met wat elke rol mag doen, zie [Wie mag wat](/on-premises/user-guide/users/mcp-server#who-may-do-what).

### Vragen en antwoorden {#q&a}

<Accordion title="Ik zie Integrations of MCP server niet in de editor">

<strong>Antwoord:</strong> De MCP-server heeft geen eigen omgevingsvariabele. Deze wordt ingeschakeld met `GIT_BRIDGE_ENABLED=true` in `config/overleaf.rc`, zie [Git-integratie](/nl/on-premises/configuration/overleaf-toolkit/integrations/git-integration). Voer na het wijzigen `bin/up -d` uit. Zonder de git-bridge toont de editor het tabblad **Integrations** niet in de linkerbalk.

</Accordion>

<Accordion title="De AI-client zegt ‘Track changes is off for this project’">

<strong>Antwoord:</strong> De client vroeg om een bijgehouden wijziging, maar het account van de projecteigenaar heeft geen wijzigingen bijhouden. Klik op **Admin** en dan op **Manage Users**, open de eigenaar en schakel op het tabblad **Features** **Track changes** in, zie [Features](/nl/on-premises/user-guide/administrators/user-management#features). Bewerkingen zonder `trackChanges` werken nog steeds.

</Accordion>

<Accordion title="De AI-client ziet alleen de wijzigingen van de laatste 24 uur">

<strong>Antwoord:</strong> Het account van de projecteigenaar heeft geen volledige projectgeschiedenis, dus de geschiedenistools tonen wat het geschiedenispaneel toont: de wijzigingen van de laatste 24 uur. Klik op **Admin** en dan op **Manage Users**, open de eigenaar en schakel op het tabblad **Features** **Full project history** in, zie [Features](/nl/on-premises/user-guide/administrators/user-management#features).

</Accordion>
