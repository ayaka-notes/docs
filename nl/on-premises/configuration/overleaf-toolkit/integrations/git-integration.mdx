De Git-integratie is momenteel beschikbaar in [ayaka-notes/overleaf](https://github.com/ayaka-notes/overleaf).

<Info>

Deze functie is oorspronkelijk ontwikkeld door [ayaka-notes/ayakaleaf-pro](https://github.com/ayaka-notes/ayakaleaf-pro).

</Info>

<Steps>
<Step title="De git-bridge inschakelen (alleen voor Toolkit-gebruikers)">
Als je de Toolkit gebruikt, schakel je de `git-bridge` in door het volgende in te stellen in je `config/overleaf.rc`:

```text title="config/overleaf.rc"
GIT_BRIDGE_ENABLED=true
```
</Step>

<Step title="De git-bridge-container toevoegen (alleen voor Docker Compose-gebruikers)">
Gebruikers met een eigen `docker-compose.yml` voegen de volgende containerconfiguratie toe aan hun compose-bestand:

```yaml title="docker-compose.yml (git-bridge service)" wrap
git-bridge:
    restart: always
    image: ghcr.io/ayaka-notes/overleaf-pro/git-bridge:6.3.2 # tag should match the `sharelatex` container tag
    volumes:
        - ~/git_bridge_data:/data/git-bridge
    container_name: git-bridge
    expose:
        - "8000"
    environment:
        GIT_BRIDGE_API_BASE_URL: "http://sharelatex:3000/api/v0/" 
        GIT_BRIDGE_OAUTH2_SERVER: "http://sharelatex"
        GIT_BRIDGE_POSTBACK_BASE_URL: "http://git-bridge:8000"
        GIT_BRIDGE_ROOT_DIR: "/data/git-bridge"
    user: root
    command: ["/server-pro-start.sh"]
```

Gebruik dezelfde tag als het image `sharelatex`. De [MCP Server](/nl/on-premises/configuration/overleaf-toolkit/mcp-server) (v6.3.1 en later) maakt deel uit van het image `sharelatex` en wordt samen met de Git-integratie ingeschakeld, dus er is geen extra container nodig.
</Step>

<Step title="De configuratie van de sharelatex-container bijwerken">
Je moet ook de container `git-bridge` koppelen in de container `sharelatex` en de volgende omgevingsvariabelen definiëren; let daarbij goed op `V1_HISTORY_URL`:

```yaml title="docker-compose.yml (sharelatex service)"
sharelatex:
    links:
        - git-bridge
    environment:
         GIT_BRIDGE_ENABLED: true
         GIT_BRIDGE_HOST: "git-bridge"
         GIT_BRIDGE_PORT: "8000"
         # We use v1 now, if you used to set V1_HISTORY_URL, please update now
         V1_HISTORY_URL: "http://sharelatex:3100/api"
```
</Step>

We raden aan de resources van je host te monitoren nadat je de `git-bridge` hebt ingeschakeld. De toename van de belasting hangt af van:

* het aantal gebruikers dat de functie gebruikt
* de soorten projecten die op je instantie worden gehost (grotere projecten vragen over het algemeen meer resources)

### Projecten naar S3 swappen

De Git-integratie slaat voor elk project dat door een gebruiker wordt gekloond een volledige git-repository op schijf op. Als je beperkte schijfruimte hebt, kun je een swap-job activeren die minder gebruikte repository's naar AWS S3 verplaatst. Als een geswapte repository opnieuw nodig is, wordt deze teruggezet naar de schijf. De volgende omgevingsvariabelen bepalen de swap-job:

| Naam                                  | Beschrijving                                                                                                                                        |
| ------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| `GIT_BRIDGE_SWAPSTORE_TYPE`           | Stel dit in op "s3" om de swap-job te activeren.                                                                                                         |
| `GIT_BRIDGE_SWAPSTORE_AWS_ACCESS_KEY` | Je AWS-toegangssleutel                                                                                                                                |
| `GIT_BRIDGE_SWAPSTORE_AWS_SECRET`     | Je AWS-secret                                                                                                                                    |
| `GIT_BRIDGE_SWAPSTORE_S3_BUCKET_NAME` | Deze bucket bevat de gezipte git-repository's                                                                                               |
| `GIT_BRIDGE_SWAPSTORE_AWS_REGION`     | De regio van de bucket                                                                                                                                |
| `GIT_BRIDGE_SWAPJOB_MIN_PROJECTS`     | <p>Hoeveel projecten er minimaal op schijf moeten blijven.<br /><br /><strong>- Standaard:</strong> 50</p>                                                      |
| `GIT_BRIDGE_SWAPJOB_LOW_GIB`          | <p>Lage drempel voor swappen. De swap-job verplaatst projecten totdat het schijfgebruik onder deze waarde ligt.<br /><br /><strong>- Standaard:</strong> 128 GB</p> |
| `GIT_BRIDGE_SWAPJOB_HIGH_GIB`         | <p>Hoge drempel voor swappen. De swap-job begint met swappen wanneer het schijfgebruik deze waarde bereikt.<br /><br /><strong>- Standaard:</strong> 256 GB</p> |
| `GIT_BRIDGE_SWAPJOB_INTERVAL_MILLIS`  | <p>De tijd tussen het controleren van het schijfgebruik en het uitvoeren van de swap-job.<br /><br /><strong>- Standaard:</strong> 3600000 ms = 1 uur</p>             |

### Vragen en antwoorden

<Accordion title="Als ik mijn project met iemand anders deel, hoe werkt dan het rechtenmodel van de Git Bridge?">

Gebruikers met alleen-lezentoegang kunnen dit project alleen klonen; gebruikers met lees- en schrijftoegang kunnen projecten klonen en pushen. Let op: gebruikers moeten aangemeld zijn om aan dit project deel te nemen.

</Accordion>

<Accordion title="Hoe kloon ik een project en welke gebruikersnaam en welk wachtwoord gebruik ik?">

Open in de editor **Integrations** in de linkerbalk en klik op **Git integration**. Daar wordt de kloonopdracht getoond, in de vorm:

```sh
git clone https://<your-overleaf>/git/<project_id>
```

Wanneer Git om inloggegevens vraagt, voer je `git` in als gebruikersnaam en een Personal Access Token als wachtwoord. Genereer het token in **Account Settings**; het is één jaar geldig. Je accountwachtwoord werkt niet.

Wijzigingen worden niet automatisch gesynchroniseerd: gebruik `git pull` om de wijzigingen uit de editor op te halen en `git push` om die van jou te versturen. Het pad `/git` wordt aangeboden door de container `sharelatex`, dus een reverse proxy ervoor heeft geen extra regel nodig.

</Accordion>

<Accordion title="`git push` mislukt met `HTTP 413` of `curl 55 Broken pipe`">

De push is groter dan de limiet voor de uploadgrootte, die wordt ingesteld met `MAX_UPLOAD_SIZE` (in megabytes, standaard `50`) en ook geldt voor pushes. Verhoog deze in `config/variables.env`, bijvoorbeeld `MAX_UPLOAD_SIZE=200`, en voer vervolgens `bin/up -d` uit. Als je de [TLS-proxy](/nl/on-premises/configuration/overleaf-toolkit/tls-proxy) of je eigen reverse proxy gebruikt, verhoog dan ook de `client_max_body_size` daarvan (`50M` in `config/nginx/nginx.conf` van de Toolkit).

De git-bridge weigert ook bestanden groter dan 50 MB en projecten met meer dan 2.000 bestanden. Deze limieten worden ingesteld met `GIT_BRIDGE_REPOSTORE_MAX_FILE_SIZE` (in bytes) en `GIT_BRIDGE_REPOSTORE_MAX_FILE_NUM` in `config/variables.env`.

</Accordion>
