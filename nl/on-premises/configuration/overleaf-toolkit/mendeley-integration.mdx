#### Mendeley-integratie instellen

1. Ga naar [deze link](https://dev.mendeley.com/myapps.html) om een Mendeley OAuth-applicatie te registreren
2. Stel de **Redirect URL** in op: `${OVERLEAF_SITE_URL}/user/mendeley/oauth/callback`
3. Noteer de gegenereerde **ID** (meestal numeriek, zoals `24061` hieronder) en het **Secret** van je applicatie
4. Pas je `config/variables.env` aan&#x20;
5. Laat de Authorisation Flow gewoon op Elsevier staan (aanbevolen)

```dotenv title="config/variables.env"
#################
#   Mendeley    #
#################
# 'mendeley' must be in ENABLED_LINKED_FILE_TYPES (keep 'zotero' too if you use both)
ENABLED_LINKED_FILE_TYPES=project_file,project_output_file,url,mendeley

# From a Mendeley OAuth application (register at https://dev.mendeley.com/myapps.html)
# Redirect URL -> ${OVERLEAF_SITE_URL}/user/mendeley/oauth/callback
MENDELEY_CLIENT_ID=
MENDELEY_CLIENT_SECRET=
# Encrypts the Mendeley OAuth tokens in mongo; if unset, a key file is generated
# in /var/lib/overleaf/data on first use
# How to generate: `openssl rand -hex 32`
MENDELEY_CIPHER_PASSWORD=
# Optional: route the module's server-side Mendeley requests (OAuth + API) through
# an HTTP proxy (must be reachable from the web container; same as github-sync)
# http://10.0.0.1:10808
# (Optional) MENDELEY_PROXY_URL=
```

<Info>

&#x20;`mendeley` moet zijn opgenomen in `ENABLED_LINKED_FILE_TYPES` (houd ook `zotero` in de lijst als je beide gebruikt). `MENDELEY_CLIENT_ID` en `MENDELEY_CLIENT_SECRET` komen van je geregistreerde OAuth-applicatie. Het cipher-wachtwoord versleutelt de Mendeley OAuth-tokens in MongoDB (genereer er een met `openssl rand -hex 32`); zonder dit wachtwoord wordt bij het eerste gebruik een sleutelbestand in het datavolume gegenereerd. Stel optioneel `MENDELEY_PROXY_URL` in om de server-side Mendeley-verzoeken (OAuth + API) via een HTTP-proxy te laten lopen die bereikbaar is vanuit de web-container.

</Info>

### Opmerkingen

<Warning>

Volg bij het upgraden van een bestaande installatie met gekoppelde Mendeley-bibliografiebestanden naar de opnieuw uitgebrachte 6.3.0 de [migratie-instructies voor Zotero / Mendeley](/nl/on-premises/release-notes/release-notes-6.x.x#ayakaleaf-pro-6.3.0  "mention"). Nieuwe installaties hebben deze migratie niet nodig.

</Warning>

<Danger>

Omdat Ayakaleaf een samenwerkingsplatform is, mag om de beveiliging te verbeteren vanaf versie 6.3.0 alleen de oorspronkelijke maker van een referentiebestand (`bib`) het geïmporteerde bestand bijwerken.

</Danger>

Stel bijvoorbeeld dat de projecteigenaar, gebruiker A, het delen via een link inschakelt en een bestand `test.bib` in het project aanmaakt dat is gekoppeld aan zijn eigen Zotero-account. Als een andere gebruiker, gebruiker B, het project via de gedeelde link opent, kan gebruiker B `test.bib` nog steeds lezen en downloaden, maar mag hij het bestand niet bijwerken of opnieuw importeren vanuit Zotero. Alleen gebruiker A, als oorspronkelijke maker van het referentiebestand, kan updates uitvoeren. Kortom: alleen de oorspronkelijke maker van het `.bib`-bestand heeft toestemming om het bij te werken.
