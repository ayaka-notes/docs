---
title: 5. Je instantie personaliseren
description: Stel de poort, site-URL en TeX Live-image in voor een lokale instantie op je Mac, controleer de kernel van de Docker-VM en start Ayakaleaf Pro.
icon: square-sliders
---

<Steps>
<Step title="Containerinstellingen">
Bewerk deze bestaande regels in `config/overleaf.rc`:

```bash title="config/overleaf.rc"
PROJECT_NAME=ayakaleaf-macos
SERVER_PRO=true
OVERLEAF_LISTEN_IP=127.0.0.1
OVERLEAF_PORT=8080
SIBLING_CONTAINERS_ENABLED=true
DOCKER_SOCKET_PATH=/var/run/docker.sock
```

Behoud de standaard gegevenspaden en de meegeleverde MongoDB- en Redis-services. Met `OVERLEAF_LISTEN_IP=127.0.0.1` kunnen alleen browsers op deze Mac de instantie openen.
</Step>

<Step title="Applicatie-instellingen">
Stel in `config/variables.env` deze waarden in en vervang eventuele actieve regels met dezelfde namen:

```dotenv title="config/variables.env"
OVERLEAF_SITE_URL=http://localhost:8080
TEX_LIVE_DOCKER_IMAGE=ghcr.io/ayaka-notes/texlive-full:2026.1
ALL_TEX_LIVE_DOCKER_IMAGES=ghcr.io/ayaka-notes/texlive-full:2026.1
ALL_TEX_LIVE_DOCKER_IMAGE_NAMES="TeX Live 2026"
```

Genereer een sessiegeheim:

```bash
openssl rand -hex 32
```

Voeg het resultaat toe als `OVERLEAF_SESSION_SECRET` in `config/variables.env`. Zonder dit geheim worden bij elke `bin/up` die de container opnieuw aanmaakt alle gebruikers uitgelogd; zie [Omgevingsvariabelen](/nl/on-premises/configuration/overleaf-toolkit/environment-variables).

Laat voor een lokale instantie zonder e-mail de SMTP-instellingen en `OVERLEAF_EMAIL_FROM_ADDRESS` leeg. Git Bridge, externe authenticatie en de andere integraties kun je later toevoegen met hun eigen [configuratiepagina's](/nl/on-premises/configuration/overleaf-toolkit).
</Step>

<Step id="check-the-docker-vms-linux-kernel" title="De Linux-kernel van de Docker-VM controleren">
MongoDB draait op de Linux-kernel van de virtuele machine van Docker Desktop, niet op macOS. Controleer de versie ervan vóór de eerste start:

```bash
docker info --format '{{.KernelVersion}}'
```

MongoDB documenteert een incompatibiliteit met Linux-kernels **6.19 tot en met 7.0.13**, die ook MongoDB in Docker treft. De oplossing is een kernel **7.0.14 of hoger**, die met een update van Docker Desktop wordt geleverd; zie de [productienotities van MongoDB](https://www.mongodb.com/docs/manual/administration/production-notes/).

Als je Docker-VM een getroffen kernel gebruikt, voeg dan het volgende toe aan `config/docker-compose.override.yml`, samengevoegd met eventuele `services` die je daar al hebt:

```yaml title="config/docker-compose.override.yml"
services:
  mongo:
    environment:
      GLIBC_TUNABLES: glibc.pthread.rseq=1
```

<Warning>

Werk bij naar een gerepareerde kernel zodra die beschikbaar is. Als je kernel buiten het getroffen bereik valt, is deze workaround niet nodig.

</Warning>
</Step>

<Step title="Je instantie starten">
Voer vanuit de Toolkit-map het volgende uit:

```bash
bin/up -d
```

De Toolkit initialiseert de replica set van MongoDB, haalt de TeX Live-image op en start de applicatie. De eerste download duurt even. Om de voortgang te volgen:

```bash
bin/docker-compose ps
bin/docker-compose logs --tail=100 -f sharelatex
```

Druk op `Ctrl+C` om te stoppen met het volgen van de logs. De containers blijven draaien.

Controleer de gepubliceerde poort en de pagina voor de eerste start:

```bash
bin/docker-compose port sharelatex 80
curl -I http://localhost:8080/launchpad
```

De poort moet `127.0.0.1:8080` zijn.
</Step>
</Steps>

<Info>

Om de instantie later vanaf andere computers te openen, wijzig je het luisteradres en de site-URL en stel je HTTPS in, zoals beschreven in [5. Uw instantie personaliseren](/nl/on-premises/installation/using-docker-compose/linux/5.-personalizing-your-instance) van de Linux-handleiding. De Mac moet dan wakker blijven; zie [De instantie beschikbaar houden](/nl/on-premises/installation/using-docker-compose/macos/6.-post-installation-tasks#keep-the-instance-available).

</Info>
