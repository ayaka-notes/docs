### Initialisatie mislukt met invalid command code {#initialization-fails-with-invalid-command-code}

`bin/init` meldt `sed: ... invalid command code` wanneer het de BSD sed van macOS aantreft. Zet GNU sed op het `PATH` zoals in [1. De Toolkit downloaden](/nl/on-premises/installation/using-docker-compose/macos/1.-download-the-toolkit) en controleer `sed --version`.

Een mislukte initialisatie kan alle drie de bestanden in `config/` achterlaten met een lege `OVERLEAF_INVITE_TOKEN_SECRET`. Als je `bin/init` dan opnieuw uitvoert, meldt het `Config files already exist`. Verplaats bij een nieuwe installatie die nog nooit is gestart de drie bestanden naar een back-upmap en voer `bin/init` opnieuw uit. Behoud bij een bestaande instantie de configuratie en geheimen, en verwijder de bestanden niet om `bin/init` opnieuw te kunnen uitvoeren.

### MongoDB blijft opnieuw opstarten {#mongodb-keeps-restarting}

Lees de MongoDB-logs en de kernelversie van de Docker-VM:

```bash
bin/docker-compose logs --tail=100 mongo
docker info --format '{{.KernelVersion}}'
```

Als het log de incompatibiliteit met de Linux-kernel noemt, volg dan [De Linux-kernel van de Docker-VM controleren](/nl/on-premises/installation/using-docker-compose/macos/5.-personalizing-your-instance#check-the-docker-vms-linux-kernel) en voer `bin/up -d` opnieuw uit. Exitcode `137` alleen bewijst niet dat MongoDB geen geheugen meer had: controleer de status van de container en de logs. Zie voor een ouder MongoDB-probleem op Docker Desktop ook [Probleemoplossing](/nl/on-premises/support/troubleshooting).

### Kan geen verbinding maken met de Docker-daemon {#cannot-connect-to-the-docker-daemon}

Start Docker Desktop en controleer de geselecteerde Docker-context; zie [0. Docker Desktop installeren](/nl/on-premises/installation/using-docker-compose/macos/0.-setup-docker-desktop). Als `docker info` werkt maar compilaties Docker niet kunnen bereiken, controleer dan de socketinstellingen in `config/overleaf.rc` en lees de `clsi`-logs. Een werkende Docker CLI op de Mac bewijst niet dat de socketmount van de applicatie correct is.

### De pagina opent, maar compilaties mislukken {#the-page-opens-but-compiles-fail}

Controleer of de TeX Live-image lokaal bestaat en overeenkomt met de architectuur van de Docker-engine:

```bash
docker image inspect ghcr.io/ayaka-notes/texlive-full:2026.1 \
  --format '{{.Os}}/{{.Architecture}}'
bin/logs -f clsi
```

Op Apple silicon moet de image `linux/arm64` zijn. Controleer of `SERVER_PRO` en `SIBLING_CONTAINERS_ENABLED` allebei `true` zijn en pas wijzigingen daarna toe met `bin/up -d`. Als de logs een ontbrekende compilatiemap melden, controleer dan het delen van bestanden in Docker Desktop en de locatie van `OVERLEAF_DATA_PATH`. Schakel sandbox-compilaties niet uit om een mislukte mount te verbergen.

### Not a directory, of een bind-mount ontbreekt {#not-a-directory-or-a-bind-mount-is-missing}

Een hostbestand dat een override mount, is mogelijk verwijderd, of Docker heeft een map aangemaakt waar het bestand zou moeten staan. Controleer het bronpad op de host en of de mount een bestand of een map verwacht. Herstel het configuratiebestand voordat je de container opnieuw aanmaakt. Een installatie onder `/tmp` kan hier tegenaan lopen nadat macOS tijdelijke bestanden heeft verwijderd.

### Conflicten met poorten of containernamen {#port-or-container-name-conflicts}

Als poort `8080` in gebruik is, kies dan een andere poort in `config/overleaf.rc`, stel `OVERLEAF_SITE_URL` daarop af en voer `bin/up -d` opnieuw uit.

De Toolkit geeft zijn containers vaste namen zoals `sharelatex`, `mongo` en `redis`. Alleen `PROJECT_NAME` wijzigen maakt twee Toolkit-installaties niet onafhankelijk. Controleer `docker ps -a` voordat je een tweede instantie start, en gebruik andere containernamen in een Compose-override, een andere poort en aparte gegevensmappen. Verwijder geen containers of gegevens van een bestaande deployment om een naamconflict op te lossen.

### De instantie is na een tijdje onbereikbaar {#the-instance-is-unreachable-after-a-while}

De Mac is waarschijnlijk in slaap gevallen, of Docker Desktop is afgesloten. Zie [De instantie beschikbaar houden](/nl/on-premises/installation/using-docker-compose/macos/6.-post-installation-tasks#keep-the-instance-available).

### `bin/doctor` meldt dat dit geen Linux is, of vraagt om een Quay-login {#bin/doctor-says-this-is-not-linux-or-asks-for-a-quay-login}

Beide waarschuwingen zijn te verwachten op macOS met de openbare image; zie [2. Maak kennis met de Toolkit](/nl/on-premises/installation/using-docker-compose/macos/2.-familiarize-yourself-with-the-toolkit). Controleer in plaats daarvan het ophalen van de images, de status van de services en de compilatieresultaten, en negeer geen andere fouten in het rapport.
