### De beheerder en een eerste project aanmaken {#create-the-administrator-and-a-first-project}

Open [http://localhost:8080/launchpad](http://localhost:8080/launchpad) in je **Windows-browser**, maak het eerste beheerdersaccount aan en log in. Volg daarna [6. Taken na de installatie](/nl/on-premises/installation/using-docker-compose/linux/6.-post-installation-tasks) van de Linux-handleiding, met poort `8080` in de voorbeeld-URL's.

### Compilatie controleren {#verify-compilation}

Een werkende inlogpagina bewijst niet dat de aparte compilercontainers toegang hebben tot de WSL-gegevensmap. Maak een leeg project aan en compileer deze `main.tex` met **pdfLaTeX**:

```latex
\documentclass{article}
\begin{document}
Ayakaleaf Pro on Windows WSL 2.
\end{document}
```

Het PDF-voorbeeld moet de tekst tonen. Selecteer voor de basic-image zo nodig **TeX Live 2026 Basic** in de projectinstellingen.

Selecteer **XeLaTeX** en test:

```latex
\documentclass{article}
\usepackage{fontspec}
\begin{document}
Ayakaleaf WSL XeLaTeX sandbox.
\end{document}
```

Beide voorbeelden werken met basic. Gebruik voor Chinese documenten een image die `ctex` en de benodigde lettertypen bevat, zoals full, voordat je het volgende test met **XeLaTeX**. Basic bevat ze niet:

```latex
\documentclass{ctexart}
\begin{document}
你好，Ayakaleaf Pro。
\end{document}
```

Om te bevestigen dat de sandbox wordt gebruikt, voer je tijdens het compileren in **Ubuntu** uit:

```bash
docker ps -a --filter ancestor=ghcr.io/ayaka-notes/texlive-basic:2026.1
bin/logs -f clsi
```

Gebruik in het filter de naam van de image die je hebt gekozen. Korte compilaties kunnen klaar zijn voordat `docker ps` draait; `-a` toont ook gestopte containers totdat ze worden opgeruimd. Een compilercontainer moet die image gebruiken en een `/compile`-bind-mount uit de WSL-gegevensmap van de Toolkit. Applicatielogs alleen zijn geen vervanging voor het controleren van de PDF.

### Persistentie controleren {#verify-persistence}

In **Ubuntu**, vanuit de Toolkit-map:

```bash
bin/stop
bin/start
```

Wacht op de applicatie, open het project opnieuw vanuit Windows en compileer opnieuw. Je account, de broncode en de projectbestanden moeten er nog zijn. De standaard live gegevens staan in `~/ayakaleaf-toolkit/data/` binnen Ubuntu. Bewaar zowel `config/` als `data/`; het verwijderen of afmelden (unregister) van de Ubuntu-distributie kan ze wissen.

### De instantie beschikbaar houden {#keep-the-instance-available}

Om de instantie draaiende te houden, zijn er drie onderdelen: Windows blijft wakker, Docker Desktop draait en de containers starten opnieuw met de engine.

Schakel in Docker Desktop onder **Settings → General** de optie **Start Docker Desktop when you sign in to your computer** in; zie [Docker Desktop settings](https://docs.docker.com/desktop/settings-and-maintenance/settings/). Dit start Docker na het aanmelden, niet ervoor. Meld je na een herstart van Windows aan, wacht tot Docker Desktop volledig is gestart, open Ubuntu en controleer `docker ps` en de site.

**Resource Saver** van Docker Desktop staat los van de Windows-slaapstand. Het wordt normaal alleen actief wanneer er geen containers draaien; de draaiende applicatie, MongoDB en Redis voorkomen die inactieve toestand. Op WSL 2 pauzeert het de Docker-engine in plaats van de gedeelde WSL-VM af te sluiten. Pauzeer Docker Desktop niet handmatig met **Pause** terwijl je gebruikers bedient. Je hoeft Resource Saver niet uit te schakelen alleen om deze stack draaiende te houden; zie de [documentatie van Docker over Resource Saver](https://docs.docker.com/desktop/use-desktop/resource-saver/).

De Toolkit-services gebruiken `restart: always`. Controleer de werkelijke instelling in **Ubuntu**:

```bash
docker inspect sharelatex mongo redis --format '{{.Name}} restart={{.HostConfig.RestartPolicy.Name}}'
```

Elke service moet `always` melden. Zodra Docker draait, kan het die bestaande containers opnieuw starten zonder een nieuwe `bin/up`. Een handmatig gestopte container blijft gestopt totdat je hem start of de engine herstart; met `always` kan een herstart van de engine hem weer starten. Zie het [gedrag van restartbeleid in Docker](https://docs.docker.com/engine/containers/start-containers-automatically/).

| Actie | Effect op Ayakaleaf |
| --- | --- |
| De Ubuntu-terminal sluiten na `bin/up -d` | Containers draaien losgekoppeld (detached); de terminal is niet hun supervisor. Houd Docker Desktop en de WSL-omgeving beschikbaar |
| Het venster van het Docker Dashboard sluiten | Het venster kan sluiten terwijl Docker Desktop in het systeemvak blijft draaien |
| **Quit Docker Desktop** kiezen | Stopt de engine en maakt de site onbeschikbaar; open Docker Desktop opnieuw om te herstellen |
| `wsl --shutdown` uitvoeren | Stopt alle WSL-distributies en onderbreekt de Docker WSL-backend; herstart Docker Desktop en open Ubuntu opnieuw |
| Windows in slaapstand of sluimerstand zetten of afsluiten | De service is niet beschikbaar; alleen het scherm aan of uit laten verandert dit niet |
| `bin/stop` uitvoeren | Stopt de instantie en behoudt de gegevens; gebruik `bin/start` om verder te gaan |

Open voor langdurig gebruik op netstroom in Windows 11 **Instellingen → Systeem → Energie en batterij → Time-outs voor scherm, slaapstand en sluimerstand** (sommige versies tonen **Energie** of **Scherm en slaapstand**). Stel de time-out voor slaapstand bij aangesloten stroom in op **Nooit** en schakel automatische sluimerstand uit als die is geconfigureerd. Het beeldscherm kan nog steeds uitgaan. De actie bij het sluiten van het deksel van een laptop is een aparte instelling; het sluiten van het deksel kan de laptop in slaapstand zetten, zelfs met een time-out voor slaapstand van Nooit. Zie de [energie-instellingen van Windows](https://support.microsoft.com/en-us/windows/experience/power-battery/power-settings-in-windows-11).

Voer `wsl --shutdown` niet uit als routinematige opschoning terwijl de site in gebruik is. Als een wijziging in de WSL-instellingen dit vereist, stop dan eerst de instantie en plan een onderbreking. Windows kan de instantie met deze instellingen continu draaien. Voor een gedeelde service die afmeldingen en onbewaakte herstarts moet overleven, raden we de [Linux-handleiding](/nl/on-premises/installation/using-docker-compose/linux) aan.

### Herstel controleren na het herstarten van Docker Desktop {#check-recovery-after-restarting-docker-desktop}

Nadat je je werk hebt opgeslagen en actieve compilaties hebt laten voltooien, kies je **Restart Docker Desktop** in het probleemoplossingsmenu van Docker Desktop. Wacht op de engine en controleer daarna in **Ubuntu**:

```bash
docker ps
curl -I http://localhost:8080/launchpad
```

Open het bestaande project in Windows en compileer het opnieuw. Bevestig dat het account en de broncode nog bestaan.

Als je de instantie bewust hebt gestopt met `bin/stop`, gebruik dan `bin/start`. Als Docker draait maar een service mislukt, lees dan de logs ervan in plaats van de configuratie opnieuw aan te maken. Windows Update, Docker-updates en stroomuitval kunnen een installatie die 24 uur per dag draait nog steeds onderbreken; maak back-ups en controleer het herstel na gepland onderhoud.

### Dagelijks gebruik {#daily-use}

Start Docker Desktop in Windows. Open **Ubuntu**:

```bash
cd "$HOME/ayakaleaf-toolkit"
```

| Taak | Commando |
| --- | --- |
| Bestaande containers starten | `bin/start` |
| Containers stoppen en gegevens behouden | `bin/stop` |
| Configuratiewijzigingen toepassen | `bin/up -d` |
| Status controleren | `bin/docker-compose ps` |
| Opstartlogs lezen | `bin/docker-compose logs --tail=100 sharelatex` |
| MongoDB-logs lezen | `bin/docker-compose logs --tail=100 mongo` |
| Compilerlogs lezen | `bin/logs -f clsi` |

`bin/start` past geen configuratiewijzigingen toe: gebruik `bin/up -d` nadat je `config/` hebt gewijzigd. Volg [Gegevens en back-ups](/nl/on-premises/maintenance/data-and-backups) voordat je de WSL-distributie upgradet, verplaatst of verwijdert. Live MongoDB-bestanden kopiëren terwijl de database schrijft, is geen consistente back-up.

Houd `127.0.0.1` aan voor lokaal gebruik. Om andere computers te bedienen, zijn ook een bewust gekozen luisteradres, site-URL, Windows-firewall-/netwerkconfiguratie en HTTPS nodig; alleen `OVERLEAF_SITE_URL` wijzigen publiceert geen poort.

Als iets niet werkt, zie [Probleemoplossing](/nl/on-premises/installation/using-docker-compose/windows/troubleshooting).
