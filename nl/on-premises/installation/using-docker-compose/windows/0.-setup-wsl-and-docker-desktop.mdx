Ayakaleaf Pro gebruikt Linux-containers. Installeer op Windows Docker Desktop met de WSL 2-backend en voer de Toolkit-scripts uit in Ubuntu.

WSL 2 levert de Linux-kernel. Docker Desktop beheert de Docker-engine in een eigen `docker-desktop`-omgeving; door **WSL Integration** in te schakelen, kan de Docker CLI in Ubuntu met die engine communiceren. De Toolkit start vervolgens de applicatie, MongoDB en Redis als containers. Met sandbox-compilaties ingeschakeld gebruikt de applicatie de Docker-socket van de engine om voor elke compilatie een aparte TeX Live-container te starten. Je hebt geen Windows-installaties van MongoDB, Redis of TeX Live nodig.

<Steps>
<Step title="WSL 2 en Ubuntu installeren">
Open **PowerShell als administrator** in Windows en voer uit:

```powershell
wsl --install -d Ubuntu
```

Start Windows opnieuw op als daarom wordt gevraagd. Open **Ubuntu** vanuit het Startmenu en maak een Linux-gebruikersnaam en -wachtwoord aan. Dit is het account voor `sudo` binnen Ubuntu; het staat los van je Windows-aanmelding.

Werk in **PowerShell** WSL bij en controleer de distributie:

```powershell
wsl --update
wsl --version
wsl --list --verbose
```

De rij van Ubuntu moet **VERSION 2** tonen. Als er 1 staat, gebruik dan de exacte distributienaam uit de lijst:

```powershell
wsl --set-version Ubuntu 2
```

Docker vereist WSL **2.1.5 of hoger**; de WSL-softwareversie uit `wsl --version` en de kolom **VERSION 2** van de distributie zijn verschillende controles. Zie [probleemoplossing bij de installatie](/nl/on-premises/installation/using-docker-compose/windows/troubleshooting#wsl-or-docker-reports-that-virtualization-is-unavailable) en de [installatie-instructies van Microsoft](https://learn.microsoft.com/en-us/windows/wsl/install) als de installatie mislukt, en schakel hardwarevirtualisatie in BIOS/UEFI in als WSL meldt dat die niet beschikbaar is.
</Step>

<Step title="Docker Desktop installeren en starten">
Download [Docker Desktop for Windows](https://docs.docker.com/desktop/setup/install/windows-install/) voor je processor en voer het installatieprogramma uit. Gebruik de **WSL 2**-backend als die wordt aangeboden. Open **Docker Desktop** vanuit het Windows-Startmenu en wacht tot de engine is gestart.

Schakel in Docker Desktop onder **Settings → General** de optie **Use WSL 2 based engine** in als die wordt getoond. Schakel onder **Settings → Resources → WSL Integration** de integratie voor **Ubuntu** in en selecteer daarna **Apply** of **Apply & restart**. Als Ubuntu niet je standaarddistributie is, schakel dan expliciet de eigen schakelaar ervan in.

Als WSL Integration ontbreekt, controleer dan of Docker Desktop **Linux containers** gebruikt. Zie de [handleiding van Docker voor de WSL 2-backend](https://docs.docker.com/desktop/features/wsl/).

Gebruik voor deze handleiding de integratie van Docker Desktop. Een tweede Docker Engine installeren met `apt install docker.io` of `dockerd` starten binnen Ubuntu creëert een aparte opzet en kan conflicten veroorzaken. Als je al een Engine in Ubuntu gebruikt, volg dan de migratierichtlijnen van Docker voordat je overstapt; behoud bestaande applicatiegegevens en back-ups.
</Step>

<Step title="Docker controleren vanuit Ubuntu">
Open een **Ubuntu**-terminal. Voer daar deze commando's uit, zonder `sudo`:

```bash
docker version
docker compose version
docker ps
```

`docker version` moet zowel **Client** als **Server** tonen. Een lege containerlijst is normaal bij een nieuwe installatie. `docker --version` alleen bewijst niet dat de engine draait.

Als `docker` niet beschikbaar is of geen verbinding kan maken, open Ubuntu dan opnieuw nadat je WSL Integration hebt toegepast en controleer of Docker Desktop draait. Zie [Probleemoplossing](/nl/on-premises/installation/using-docker-compose/windows/troubleshooting#docker-is-unavailable-in-ubuntu).
</Step>

<Step title="Resources en de Docker-socket controleren">
Controleer de resources die zichtbaar zijn voor Docker:

```bash
docker info --format 'CPUs={{.NCPU}} Memory={{.MemTotal}} Kernel={{.KernelVersion}}'
df -h "$HOME"
ls -l /var/run/docker.sock
```

Voor een kleine lokale instantie zijn 4 CPU's en 8 GB geheugen beschikbaar voor Docker een voorgesteld startpunt, geen gemeten minimum. Houd ook voldoende geheugen over voor Windows. Met de WSL 2-backend worden resourcelimieten beheerd via de [WSL-instellingen](https://learn.microsoft.com/en-us/windows/wsl/wsl-config), in plaats van via de resourceschuifregelaars van Docker Desktop op de Mac. Wijzigingen die `wsl --shutdown` vereisen, onderbreken alle draaiende WSL-distributies en Docker-workloads; pas ze toe voordat je de instantie start.

Laat `DOCKER_SOCKET_PATH=/var/run/docker.sock` staan in de Toolkit-configuratie. De applicatie heeft deze engine-socket nodig voor sandbox-compilaties. Wijzig de rechten niet naar `777` om verbindingsfouten op te lossen; herstel in plaats daarvan de integratie van Docker Desktop.
</Step>
</Steps>
