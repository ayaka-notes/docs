---
title: 5. Je instantie personaliseren
description: Stel de poort, site-URL en TeX Live-image in, schakel sandbox-compilaties in en start Ayakaleaf Pro op WSL 2.
icon: square-sliders
---

Voer commando's uit en bewerk bestanden in **Ubuntu**, vanuit `~/ayakaleaf-toolkit`.

<Steps>
<Step title="Containerinstellingen">
Bewerk de bestaande regels in `config/overleaf.rc`:

```bash title="config/overleaf.rc"
PROJECT_NAME=ayakaleaf-wsl
SERVER_PRO=true
OVERLEAF_LISTEN_IP=127.0.0.1
OVERLEAF_PORT=8080
SIBLING_CONTAINERS_ENABLED=true
DOCKER_SOCKET_PATH=/var/run/docker.sock
```

Behoud de standaard gegevenspaden en de meegeleverde MongoDB- en Redis-services. Poort `8080` is voor de lokale Windows-browser; door te koppelen aan `127.0.0.1` blijft deze lokaal. Sandbox-compilaties gebruiken voor elke compilatie een aparte Linux-container, in plaats van TeX binnen de applicatiecontainer uit te voeren. Via de Docker-socket kan de applicatie die containers aanmaken, en de Toolkit levert het hostpad voor de compilatiegegevens onder `data/overleaf/data/compiles`.
</Step>

<Step title="Applicatie-instellingen">
Stel in `config/variables.env` deze waarden in en vervang eventuele actieve regels met dezelfde namen:

```dotenv title="config/variables.env"
OVERLEAF_SITE_URL=http://localhost:8080
TEX_LIVE_DOCKER_IMAGE=ghcr.io/ayaka-notes/texlive-full:2026.1
ALL_TEX_LIVE_DOCKER_IMAGES=ghcr.io/ayaka-notes/texlive-full:2026.1
ALL_TEX_LIVE_DOCKER_IMAGE_NAMES="TeX Live 2026"
```

De volledige image bevat de pakketten en lettertypen die nodig zijn voor een breed scala aan projecten. Reken op minstens 40 GB vrije opslag voor deze image en de applicatie, plus ruimte voor projectgegevens en toekomstige updates.

Gebruik voor een snelle implementatietest in plaats daarvan de kleinere **basic**-image. Die volstaat voor de eenvoudige artikeltest in stap 6, maar bevat niet de volledige set pakketten en lettertypen:

```dotenv
TEX_LIVE_DOCKER_IMAGE=ghcr.io/ayaka-notes/texlive-basic:2026.1
ALL_TEX_LIVE_DOCKER_IMAGES=ghcr.io/ayaka-notes/texlive-basic:2026.1
ALL_TEX_LIVE_DOCKER_IMAGE_NAMES="TeX Live 2026 Basic"
```

Kies een van deze sets, zonder dubbele actieve sleutels. Het [Dockerfile](https://github.com/ayaka-notes/texlive-full/blob/main/texlive/2026/Dockerfile.basic) van de basic-image bevat `latexmk`, XeTeX en `fontspec`, maar niet `ctex` of de volledige lettertypecollectie. Een ontbrekend LaTeX-pakket in basic wijst op zichzelf niet op een sandboxprobleem.

Genereer een sessiegeheim:

```bash
openssl rand -hex 32
```

Voeg het resultaat toe als `OVERLEAF_SESSION_SECRET` in `config/variables.env`. Bewaar ook het gegenereerde geheim voor uitnodigingstokens. Laat voor een lokale instantie zonder e-mail de SMTP-instellingen en `OVERLEAF_EMAIL_FROM_ADDRESS` leeg.
</Step>

<Step title="Je instantie starten">
```bash
bin/up -d
```

De Toolkit start MongoDB, initialiseert de replica set, downloadt de geselecteerde TeX Live-image en start Redis en de applicatie. Het kan lijken alsof het proces pauzeert terwijl een grote image wordt gedownload. Voer geen tweede `bin/up` uit zolang de eerste nog bezig is.

Controleer in een andere Ubuntu-terminal:

```bash
cd "$HOME/ayakaleaf-toolkit"
bin/docker-compose ps
bin/docker-compose logs --tail=100 mongo
bin/docker-compose logs --tail=100 -f sharelatex
```

Druk op `Ctrl+C` om te stoppen met het volgen van de logs; losgekoppelde (detached) containers blijven draaien. Als het opstarten bij MongoDB mislukt, volg dan [MongoDB start niet](/nl/on-premises/installation/using-docker-compose/windows/troubleshooting#mongodb-fails-to-start) voordat je het opnieuw probeert. Verwijder de gegevensmap niet om een bestaande installatie te resetten.

Controleer de poort en de pagina voor de eerste start:

```bash
bin/docker-compose port sharelatex 80
curl -I http://localhost:8080/launchpad
```

De poort moet `127.0.0.1:8080` zijn. Wacht tot de applicatie is geïnitialiseerd als het HTTP-verzoek in eerste instantie mislukt.
</Step>

<Step title="De instantie openen vanuit Windows">
Open [http://localhost:8080/launchpad](http://localhost:8080/launchpad) in je **Windows-browser**. Gebruik dit adres ook in Windows, in plaats van een tijdelijk WSL-IP-adres.

Om de HTTP-toegang vanuit Windows los van de browser te controleren, voer je in **PowerShell** uit:

```powershell
curl.exe -I http://localhost:8080/launchpad
```

Als Ubuntu de pagina kan bereiken maar Windows niet, zie dan [Windows kan localhost niet openen](/nl/on-premises/installation/using-docker-compose/windows/troubleshooting#windows-cannot-open-localhost).
</Step>
</Steps>
