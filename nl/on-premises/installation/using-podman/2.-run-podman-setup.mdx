title: 2. podman-setup uitvoeren
description: Laat bin/podman-setup de host controleren en rootless Podman, SELinux en het seccomp-profiel instellen.

---

`bin/podman-setup` controleert alles wat Ayakaleaf Pro op Podman nodig heeft. Zonder opties rapporteert het alleen; met `--apply` lost het ook op wat het vindt.

<Steps>
<Step title="De host controleren">
```bash title="Check only"
bin/podman-setup
```

Op een schone host mislukken de meeste controles, bijvoorbeeld:

```text
====== Packages ======
[✗] podman not installed
[✗] podman-docker not installed
...
====== Summary ======
[✓] 7 passed  [!] 13 warnings  [✗] 4 failures
```
</Step>

<Step title="De oplossingen toepassen">
```bash title="Check and fix"
bin/podman-setup --apply
```

Voer het uit in een terminal: het vraagt om je `sudo`-wachtwoord voor de systeembrede stappen. Het downloadt ook de Ayakaleaf Pro-image om het seccomp-profiel eruit te halen, wat de eerste keer een paar minuten duurt. Aan het einde controleert het de host opnieuw:

```text
====== Summary ======
[✓] 23 passed  [!] 2 warnings  [✗] 0 failures
[!] Warnings remaining:
[!] not logged in to quay.io
[!] container → socket skipped (sharelatex not running)
```

Beide waarschuwingen zijn op dit moment te verwachten:

* `not logged in to quay.io`: de controle komt uit de officiële Toolkit, waar de Server Pro-image in een privéregistry staat. Ayakaleaf Pro-images zijn openbaar op `ghcr.io` en vereisen geen login, dus negeer deze waarschuwing. Ze blijft ook na de installatie staan.
* `container → socket skipped (sharelatex not running)`: deze test heeft de draaiende instantie nodig. Je voert het script opnieuw uit in [3. Ayakaleaf Pro starten](/nl/on-premises/installation/using-podman/3.-start-ayakaleaf-pro).

Het script eindigt met `0` als alle controles slagen, `1` als er waarschuwingen zijn en `2` als er fouten zijn. Vanwege de quay.io-waarschuwing kun je `1` verwachten.
</Step>
</Steps>

### Wat het script wijzigt {#what-the-script-changes}

Met `--apply` kan het script het volgende wijzigen.

Systeembreed, met `sudo`:

* Installeert `podman`, `podman-docker`, `git`, `curl`, `checkpolicy` en `policycoreutils` met `dnf`.
* Schakelt lingering in voor je gebruiker met `loginctl`, zodat je containers blijven draaien nadat je uitlogt.
* Maakt `/etc/containers/nodocker` aan, waardoor het bericht "Emulate Docker CLI using podman" verdwijnt.
* Laadt de SELinux-beleidsmodule `podman_socket_clsi`, als `SELINUX_MODE=managed`.

Voor je gebruiker:

* Schakelt de gebruikersservice `podman.socket` in, de Docker-compatibele API die Ayakaleaf Pro gebruikt om compilaties te starten.
* Installeert Docker Compose v2 vanaf GitHub in `~/.local/bin/docker-compose` en linkt het in `~/.docker/cli-plugins/`.
* Laat Podman deze Compose gebruiken in `~/.config/containers/containers.conf`.
* Voegt de aliassen `mongo` en `redis` toe in `~/.config/containers/registries.conf.d/overleaf-toolkit.conf`, zodat Podman weet waar het deze korte imagenamen vandaan moet halen.

In de Toolkit:

* Stelt `DOCKER_SOCKET_PATH` en `DOCKER_HOST` in `config/overleaf.rc` in op `/run/user/<uid>/podman/podman.sock`.
* Haalt het seccomp-profiel voor compilaties uit de Ayakaleaf Pro-image naar `config/seccomp/<version>/clsi-profile.json` en stelt `SECCOMP_PROFILE` in `config/variables.env` in. Anders dan Docker heeft Podman dit profiel nodig als bestand op de host.
* Bouwt de SELinux-beleidsmodule in `config/selinux/`.
* Stelt de eigenaren van de datamappen in `data/` in met `podman unshare chown`, zodra die bestaan.

<Info>

Elke wijziging hoort bij een controle. Als je iets met de hand wijzigt, bijvoorbeeld in `config/overleaf.rc`, voer dan `bin/podman-setup` opnieuw uit om het te verifiëren.

</Info>
