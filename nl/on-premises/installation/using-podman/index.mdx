RHEL en zijn rebuilds (Rocky Linux, AlmaLinux) leveren Podman mee in plaats van Docker, en sommige organisaties staan Docker niet toe op hun servers. De Toolkit kan Ayakaleaf Pro in plaats daarvan op **rootless Podman** draaien: de containers draaien onder een gewone gebruiker, compilaties draaien nog steeds in gesandboxte TeX Live-containers en SELinux blijft op enforcing staan. Het script `bin/podman-setup` controleert de host en lost op wat het kan.

Aan het einde van deze sectie heb je dezelfde instantie als met [Docker Compose gebruiken](/nl/on-premises/installation/using-docker-compose): Ayakaleaf Pro met gesandboxte compilaties, MongoDB en Redis, beheerd met de gebruikelijke `bin/up`, `bin/doctor` en `bin/upgrade`.

<Info>

Ondersteuning voor Podman is experimenteel. Ze komt uit de officiële Overleaf Toolkit, die het alleen test op RHEL 9 en later met rootless Podman, gesandboxte compilaties en SELinux op enforcing. We hebben deze pagina's getest op Rocky Linux 9.9 (Podman 5.8, SELinux enforcing) met Ayakaleaf Pro 6.3.4. Docker blijft de aanbevolen container-runtime.

</Info>

### Wat je nodig hebt {#what-you-need}

* **RHEL, Rocky Linux, AlmaLinux of CentOS Stream 9 of later**, met SELinux op enforcing. `bin/podman-setup` stopt op elke andere distributie. Gebruik op Ubuntu of Debian [Docker Compose gebruiken](/nl/on-premises/installation/using-docker-compose/linux).
* **Een niet-root-gebruiker met `sudo`** die eigenaar wordt van de containers. Voer elk commando in deze sectie uit als deze gebruiker; `bin/podman-setup` weigert te draaien als `root`.
* **Een schone host**: geen Docker Engine en geen bestaande Toolkit-installatie. Het verhuizen van een bestaande op Docker gebaseerde instantie naar Podman wordt niet behandeld.

### Hoe het verschilt van Docker {#how-it-differs-from-docker}

|                                  | Docker                                  | Rootless Podman                                                                          |
| -------------------------------- | --------------------------------------- | ---------------------------------------------------------------------------------------- |
| Wie de containers draait         | De Docker-daemon, als `root`            | Je eigen gebruiker                                                                       |
| Socket om compilaties te starten | `/var/run/docker.sock`                  | `/run/user/<uid>/podman/podman.sock`                                                     |
| Poorten                          | Elke poort, bijvoorbeeld `80` en `443`  | `1024` en hoger, bijvoorbeeld `8080`                                                     |
| Hostfirewall (`firewalld`)       | Omzeild door gepubliceerde poorten      | Van toepassing: open de poort met `firewall-cmd`                                         |
| Starten na een herstart          | De Docker-daemon start ze opnieuw       | De gebruikersservice `podman-restart`                                                    |
| SELinux                          | Niet geconfigureerd door de Toolkit     | Beleidsmodule `podman_socket_clsi` en `SELINUX_MODE=managed` in `config/overleaf.rc`      |
| Seccomp-profiel voor compilaties | Ingebouwd in de image                   | Door de Toolkit uitgepakt naar `config/seccomp/<version>/` en ingesteld als `SECCOMP_PROFILE` |

### Bekende beperkingen {#known-limitations}

* <strong>Git-integratie.</strong> In Ayakaleaf Pro 6.3.4 mislukt `git clone` op Podman met `502`: de NGINX in de image zoekt de container `git-bridge` op met de DNS-server van Docker (`127.0.0.11`), die Podman niet heeft. De oplossing ([1b911d1092](https://github.com/ayaka-notes/ayakaleaf-pro/commit/1b911d1092c80f7b0ff77c5e3805b40503d49964)) komt in de volgende release; laat tot die tijd `GIT_BRIDGE_ENABLED=false` staan.
* <strong>IP-adressen van clients.</strong> Rootless Podman stuurt de gepubliceerde poort door vanuit het netwerk van de container, waardoor Ayakaleaf Pro elke bezoeker ziet met een intern adres zoals `10.89.0.15`. De [auditlogs](/nl/on-premises/user-guide/administrators/user-management#audit-logs) van een gebruiker in het beheerpaneel tonen dit adres in plaats van zijn IP-adres.
