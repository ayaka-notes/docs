---
title: 3. Ayakaleaf Pro starten
description: Start Ayakaleaf Pro op Podman, controleer het met podman-setup en bin/doctor, en start het na herstarts.
icon: circle-play
---

<Steps>
<Step title="De containers starten">
```bash title="Start Ayakaleaf Pro"
bin/up -d
```

De eerste start downloadt de MongoDB-, Redis- en TeX Live-images en maakt de datamappen in `data/` aan. Er verschijnt een waarschuwing dat ondersteuning voor Podman experimenteel is.

<Info>

De eerste start kan ook `MongoNetworkError: connect ECONNREFUSED 127.0.0.1:27017` tonen. De Toolkit stelt de MongoDB-replicaset in terwijl MongoDB nog aan het opstarten is, en probeert het opnieuw totdat MongoDB antwoordt. Je kunt deze regel negeren.

</Info>

Controleer na een minuut of twee of de containers draaien:

```bash title="List the containers"
podman ps --format "{{.Names}} {{.Status}}"
```

```text
mongo Up 34 seconds (healthy)
redis Up 20 seconds
sharelatex Up 20 seconds
```
</Step>

<Step title="De setup opnieuw controleren">
Nu de datamappen bestaan en de container `sharelatex` draait, kan `bin/podman-setup` zijn controles afronden:

```bash title="Check the setup"
bin/podman-setup
```

Het controleert de eigenaren van de nieuwe datamappen en test de Podman-socket vanuit de container `sharelatex`:

```text
====== Socket Connectivity ======
[✓] host → socket OK
[✓] container → socket OK

====== Data Directory Permissions ======
[✓] mongo data dir owned by 999
[✓] redis data dir owned by 999
[✓] overleaf data dir owned by 33
...
====== Summary ======
[✓] 27 passed  [!] 1 warnings  [✗] 0 failures
[!] Warnings:
[!] not logged in to quay.io
```

`container → socket OK` betekent dat Ayakaleaf Pro compilatiecontainers kan starten. Als een controle mislukt, voer dan `bin/podman-setup --apply` uit en daarna `bin/up -d`. De quay.io-waarschuwing geldt niet voor Ayakaleaf Pro, zie [2. podman-setup uitvoeren](/nl/on-premises/installation/using-podman/2.-run-podman-setup).
</Step>

<Step title="De doctor uitvoeren">
```bash title="Run the doctor"
bin/doctor
```

Op Podman toont het rapport de runtime en de beveiligingsinstellingen:

```text
- Container Daemon
    - status: up
    - runtime: podman
    - server version: 5.8.5
    - socket: /run/user/1000/podman/podman.sock
    - DOCKER_HOST: unix:///run/user/1000/podman/podman.sock
    - host → socket: OK
    - container → socket: OK
- Security
    - SELinux: Enforcing
    - SELINUX_MODE: managed
    - SELINUX_LABEL: sharelatex_t
    - SELinux module: loaded (podman_socket_clsi)
    - SELinux rules: present
    - Seccomp profile: present
```

De waarschuwing `Server Pro enabled, but not logged in to quay.io repository` aan het einde is dezelfde quay.io-controle, zie [Hulp krijgen](/nl/on-premises/support/getting-help#q-and-a).
</Step>

<Step title="Ayakaleaf Pro starten na een herstart">
Met Docker start de Docker-daemon de containers opnieuw na een herstart. Rootless Podman heeft geen daemon: schakel de gebruikersservice in die je containers start wanneer de server opstart:

```bash title="Start the containers at boot"
systemctl --user enable podman-restart.service
```

Deze service start elke container van je gebruiker waarvan het herstartbeleid `always` is, wat de Toolkit voor al zijn containers instelt. Hiervoor is lingering nodig, dat `bin/podman-setup --apply` heeft ingeschakeld. Zonder deze service voer je na elke herstart `bin/up -d` uit.
</Step>

<Step title="De poort openen in de firewall">
Standaard accepteert de instantie alleen verbindingen van de server zelf, op `http://localhost:8080`. Om haar vanaf andere computers te openen, stel je `OVERLEAF_LISTEN_IP` in `config/overleaf.rc` en `OVERLEAF_SITE_URL` in `config/variables.env` in zoals beschreven in [5. Uw instantie personaliseren](/nl/on-premises/installation/using-docker-compose/linux/5.-personalizing-your-instance#listen-address-and-port), en voer je `bin/up -d` opnieuw uit.

Anders dan Docker omzeilt rootless Podman de hostfirewall niet. Als `firewalld` draait, wat de standaard is op RHEL, open dan de poort:

```bash title="Open port 8080"
sudo firewall-cmd --permanent --add-port=8080/tcp
sudo firewall-cmd --reload
```

Sta op een cloudserver de poort ook toe in de security group van de provider. Gebruik HTTPS voordat je de instantie aan het internet blootstelt, zie [4. Taken na de installatie](/nl/on-premises/installation/using-podman/4.-post-installation-tasks#use-https).
</Step>
</Steps>
