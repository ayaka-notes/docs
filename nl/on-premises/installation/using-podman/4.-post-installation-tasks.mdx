### Je eerste beheerdersaccount aanmaken {#create-your-first-administrator-account}

Open [http://localhost:8080/launchpad](http://localhost:8080/launchpad), of je `OVERLEAF_SITE_URL` gevolgd door `/launchpad`, en registreer het beheerdersaccount. Vanaf hier werkt alles zoals met Docker: volg [6. Taken na de installatie](/nl/on-premises/installation/using-docker-compose/linux/6.-post-installation-tasks) van de Docker-handleiding en gebruik poort `8080` in de `localhost`-links daarvan.

Maak het voorbeeldproject aan en compileer het. De PDF laat zien dat compilaties via Podman in hun TeX Live-containers draaien. Om de compilatiecontainer te zien:

```bash title="List the compile containers"
podman ps -a --filter name=project- --format "{{.Names}} {{.Image}} {{.Status}}"
```

### HTTPS gebruiken {#use-https}

De [TLS-proxy](/nl/on-premises/configuration/overleaf-toolkit/tls-proxy) van de Toolkit werkt op Podman: voer `bin/init --tls` uit en stel je certificaat en `NGINX_ENABLED=true` in zoals daar beschreven. De proxy luistert op de poorten `80` en `443`, die rootless Podman standaard niet mag gebruiken. Sta onbevoorrechte gebruikers toe poorten vanaf `80` te gebruiken:

```bash title="Allow ports 80 and 443"
echo "net.ipv4.ip_unprivileged_port_start=80" | sudo tee /etc/sysctl.d/99-unprivileged-ports.conf
sudo sysctl --system
```

Hiermee kan elke gebruiker op de server op deze poorten luisteren, dus doe dit alleen op een server die speciaal voor Ayakaleaf Pro bedoeld is. Open ze daarna in de firewall:

```bash title="Open ports 80 and 443"
sudo firewall-cmd --permanent --add-port=80/tcp --add-port=443/tcp
sudo firewall-cmd --reload
```

Stel `OVERLEAF_SITE_URL` in op je `https://`-adres en voer `bin/up -d` uit. Behoud de standaardwaarden `NGINX_HTTP_PORT=80` en `TLS_PORT=443`: met andere poorten leidt de omleiding van HTTP naar HTTPS naar de verkeerde poort.

<Info>

Laat `OVERLEAF_LISTEN_IP` op `127.0.0.1` staan wanneer je de TLS-proxy gebruikt, zodat poort `8080` niet bereikbaar is vanaf andere computers.

</Info>

### Upgraden {#upgrade}

Upgrade met `bin/upgrade`, zoals beschreven in [Je implementatie upgraden](/nl/on-premises/maintenance/upgrading-your-deployment). Op Podman haalt het ook het seccomp-profiel van de nieuwe versie uit naar `config/seccomp/<version>/` en werkt het `SECCOMP_PROFILE` bij:

```text
Over-writing config/version with 6.3.4
Set SECCOMP_PROFILE=/home/<user>/overleaf-toolkit/config/seccomp/6.3.4/clsi-profile.json in config/variables.env
```

Voer na een upgrade `bin/podman-setup` uit om de setup te controleren.

### De SELinux-modus wijzigen {#change-the-selinux-mode}

`SELINUX_MODE` in `config/overleaf.rc` bepaalt hoe SELinux de container `sharelatex` beperkt. `managed` is de modus die deze pagina's instellen; de andere modi worden beschreven in [Toolkit-instellingen](/nl/on-premises/configuration/overleaf-toolkit/toolkit-settings). Voer `bin/up -d` uit nadat je hem hebt gewijzigd.
