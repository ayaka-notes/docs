Kubernetes draait dezelfde images als de Toolkit. Er is geen aparte Kubernetes-image.

| Image                                                | Gebruikt door                                                           |
| ---------------------------------------------------- | ----------------------------------------------------------------------- |
| `ghcr.io/ayaka-notes/overleaf-pro:6.3.2`             | de Deployment `overleaf`                                                |
| `ghcr.io/ayaka-notes/overleaf-pro/git-bridge:6.3.2`  | [Git-integratie](/nl/on-premises/configuration/kubernetes/integrations/git-integration) (optioneel), dezelfde tag als hierboven |
| `ghcr.io/ayaka-notes/texlive-*`                      | compilaties, gepulld in Docker op de nodes in [stap 0](/nl/on-premises/installation/using-kubernetes/0.-prepare-the-nodes) |

De images zijn openbaar beschikbaar op [ghcr.io](https://github.com/ayaka-notes/ayakaleaf-pro/pkgs/container/overleaf-pro/) voor amd64 en arm64, zodat de kubelet ze zonder inloggegevens kan pullen.

<Warning>

Gebruik altijd een versietag, zoals `6.3.2`, niet `latest`. Upgrades voeren databasemigraties uit en moeten [Upgraden op Kubernetes](/nl/on-premises/maintenance/upgrading-on-kubernetes) volgen; een veranderende tag zou een pod upgraden telkens wanneer deze opnieuw wordt ingepland.

</Warning>

### Q\&A

<Accordion title="Onze nodes kunnen ghcr.io niet bereiken. Wat doen we?">

<strong>Antwoord:</strong> Kopieer de images naar een registry die de nodes kunnen bereiken en gebruik die naam in de manifests, bijvoorbeeld:

```bash
docker pull ghcr.io/ayaka-notes/overleaf-pro:6.3.2
docker tag ghcr.io/ayaka-notes/overleaf-pro:6.3.2 registry.example.com/ayakaleaf/overleaf-pro:6.3.2
docker push registry.example.com/ayakaleaf/overleaf-pro:6.3.2
```

Voor een registry zonder TLS heeft containerd op elke node een `/etc/containerd/certs.d/<registry>/hosts.toml` met `server = "http://<registry>"` nodig, en `config_path` ingesteld zoals in [stap 0](/nl/on-premises/installation/using-kubernetes/0.-prepare-the-nodes). Docker zelf pusht alleen via gewoon HTTP naar `localhost`, dus push via `localhost:<port>` op de registryhost of voeg deze toe aan `insecure-registries`.

</Accordion>
