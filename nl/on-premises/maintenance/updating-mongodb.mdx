</Info>

### Moet ik MongoDB bijwerken?

Je moet **alleen** overwegen je MongoDB-versie bij te werken als je van plan bent je instantie van Server CE/Server Pro te upgraden.

Als je een MongoDB-versie draait die nieuwer is dan de aanbevolen versie voor je huidige (of beoogde) versie, hoef je niets te wijzigen.

<Warning>

Je moet je MongoDB-versie nooit downgraden.

</Warning>

Als je een specifiek probleem ondervindt waarvan je denkt dat het met je huidige versie van MongoDB te maken heeft, kun je gerust [een issue aanmaken](https://github.com/overleaf/overleaf/issues) als je Server CE-gebruiker bent, of contact opnemen met Overleaf Support als je Server Pro-gebruiker bent.

### Updateproces

Het bijwerken van de MongoDB-versie tijdens een upgrade van je Server CE/Server Pro-instantie gaat als volgt:

1. Bepaal naar welke versie van Server CE/Server Pro je wilt upgraden.
2. Zoek de MongoDB-versie die door die specifieke Overleaf Server CE/Server Pro-release wordt aanbevolen.
3. Volg de instructies om MongoDB naar de beoogde versie te upgraden.
4. Upgrade de imageversie van Server CE/Server Pro en start de instantie opnieuw.

We raden aan **Server CE/Server Pro** altijd te upgraden naar de nieuwste beschikbare versie, omdat die gegarandeerd wordt ondersteund (alleen voor Server Pro-gebruikers).

<Danger>

Bij het upgraden van Server CE/Pro raden we aan eerst te upgraden naar de nieuwste release van de geïmplementeerde hoofdversie, **voordat** je upgradet naar de nieuwste release van de **volgende** hoofdversie. Als je implementatie meer dan één hoofdversie achterloopt, moet je in meerdere stappen upgraden.

Als je bijvoorbeeld 3.5.10 draait, moet je upgraden naar 3.5.13 -> de migratie naar Full Project History uitvoeren -> 4.2.9 -> 5.5.4.

Je mag **nooit** hoofdversies overslaan (3.5.10 -> 5.5.4). Als je de Toolkit gebruikt en meer dan één hoofdversie achterloopt, mag je het script `bin/upgrade` **niet** gebruiken, omdat je dan handmatig in meerdere stappen moet upgraden.

</Danger>

<Warning>

Het is belangrijk dat je **vóór** elke upgrade van een hoofdversie een [consistente back-up](/nl/on-premises/maintenance/data-and-backups#performing-a-consistent-backup) maakt, zodat je zo nodig kunt terugdraaien.

</Warning>

#### MongoDB upgraden

MongoDB vereist **stapsgewijze upgrades**. Dat betekent dat je niet rechtstreeks van bijvoorbeeld `4.0` naar `5.0` kunt gaan. Je moet eerst `4.2` bijwerken naar `4.4`, en daarna naar `5.0`.

<Info>

MongoDB gebruikt even nummers voor zijn stabiele versies.

</Info>

**Basisinstructies**

In de meeste gevallen moet je voor de update een compatibiliteitsvlag instellen voordat je de mongo-versie daadwerkelijk bijwerkt. De stappen zijn als volgt:

1. Stel de compatibiliteitsvlag in zoals beschreven in de releasenotes van MongoDB (zie de voorbeelden hieronder).
2. Werk vervolgens de mongo-image bij:
   1. **Toolkit-gebruikers** Werk `MONGO_VERSION` bij, bijv. `MONGO_VERSION=6.0`
   2. **Docker Compose-gebruikers** Werk de versie van de image-tag van `mongo` bij,\
      bijv. `services -> mongo -> image: mongo:6.0`;

**Voorbeeld: MongoDB upgraden van `5.0` naar `6.0`**

Laten we eerst controleren dat we MongoDB `6.0` draaien:

Gebruikers van de Overleaf Toolkit:

```bash
bin/docker-compose exec mongo mongod --version
# db version v5.0.24
```

Gebruikers van Docker Compose:

```bash
docker compose exec mongo mongod --version
# db version v5.0.24
```

Volgens de [upgrade-instructies](https://docs.mongodb.com/manual/release-notes/3.6-upgrade-standalone/#upgrade-version-path) is de enige vereiste dat `featureCompatibilityVersion` is ingesteld op `5.0`. Dat doen we door een MongoDB-shell te openen en de aangegeven opdracht uit te voeren:

Gebruikers van de Overleaf Toolkit:

```bash
bin/mongo
# MongoDB shell version v5.0.24
# ...
# overleaf:PRIMARY> db.adminCommand( { setFeatureCompatibilityVersion: "5.0" } )
# { 
# "ok" : 1,
# ...
# }
overleaf:PRIMARY> exit
# bye
```

<Info>

Docker Compose-gebruikers kunnen `docker compose exec mongo mongosh` uitvoeren om een shell te openen en dezelfde opdrachten uitvoeren als Toolkit-gebruikers.

</Info>

Gebruikers van de Overleaf Toolkit:

Vervolgens stoppen we de instanties van Server CE/Server Pro en MongoDB met de opdracht `bin/stop`, stellen we `MONGO_VERSION=6.0` in `config/overleaf.rc` in en starten we de `mongo`-service opnieuw met `bin/up mongo`) om te controleren of de update soepel is verlopen.

Ten slotte werken we de imageversie van Server CE/Server Pro bij naar onze beoogde versie en maken we alle services opnieuw aan met de opdracht `bin/up -d`.

Gebruikers van Docker Compose:

Vervolgens stoppen we de instanties van Server CE/Server Pro en MongoDB met de opdracht `docker compose stop`, werken we het bestand [`docker-compose.yml`](https://github.com/overleaf/overleaf/blob/4b1babd4ea634ab12c54e9a9aea7db0e8a500941/docker-compose.yml) bij om `image: mongo:6.0` te gebruiken en starten we de `mongo`-service opnieuw met de opdracht `docker compose up mongo` om te controleren of de update soepel is verlopen.

Ten slotte werken we de imageversie van Server CE/Server Pro bij naar onze beoogde versie en maken we alle services opnieuw aan met de opdracht `docker compose up`.

#### Equivalente opdrachten voor Docker Compose-gebruikers

Voor Docker Compose-gebruikers zijn de equivalente opdrachten:

* `docker compose exec mongo mongod --version` om de mongo-versie weer te geven
* `docker compose exec mongo mongosh` om een mongo-shell te starten voor beheeropdrachten
* de opdracht `docker compose stop` om de server te stoppen
* Bewerk het bestand [`docker-compose.yml`](https://github.com/overleaf/overleaf/blob/4b1babd4ea634ab12c54e9a9aea7db0e8a500941/docker-compose.yml) om `image: mongo:6.0` te gebruiken en zo de mongo-versie te upgraden
* `docker compose up mongo` om de mongo-service opnieuw te starten en te controleren of de update soepel is verlopen
* Bewerk het bestand [`docker-compose.yml`](https://github.com/overleaf/overleaf/blob/4b1babd4ea634ab12c54e9a9aea7db0e8a500941/docker-compose.yml) om `image: sharelatex:VERSION` te gebruiken en zo de imageversie te upgraden
* `docker compose up` om alle services opnieuw aan te maken.

### Een aangepaste rol aanmaken

In versie `5.5.1` hebben we een controle bij het opstarten geïntroduceerd die de Feature Compatibility Version van MongoDB verifieert. Als je MongoDB-database authenticatie gebruikt (bijv. basisauthenticatie), start de `sharelatex`-container mogelijk niet en wordt de rechtenfout "_not authorized on admin to execute command_" weergegeven.

Om dit op te lossen, kun je met de onderstaande instructies een nieuwe rol in MongoDB aanmaken en deze toewijzen aan het gebruikersaccount dat toegang heeft tot de database, of `ALLOW_MONGO_ADMIN_CHECK_FAILURES=true` instellen zodat de controle mag mislukken zonder dat de implementatie daardoor niet kan starten.

<Check>

Deze nieuwe rol geeft **alleen** toestemming om clusterbrede MongoDB-serverparameters te lezen en kan ook worden hergebruikt voor monitoringdoeleinden.

</Check>

```bash wrap
# Toolkit users
$ bin/docker-compose exec -it mongo mongosh -u {{YOUR-ADMIN-USERNAME}} -p

# Switch to the "admin" database using
overleaf [direct: primary] sharelatex> use admin
switched to db admin
overleaf [direct: primary] admin> 

# Create a new role with permission to use "getParamter". Copy and paste the function below into the shell and press the return key

db.createRole(
  {
    role: "clusterParameterReader",
    privileges: [
      {
        resource: { cluster: true },
        actions: ["getParameter"]    
      }
    ],
    roles: [] 
  }
);

# Switch back to the "sharelatex" database 
use sharelatex
switched to db sharelatex
overleaf [direct: primary] sharelatex> 

# Assign the new "clusterParameterReader" role to your database user by copy and pasting the function below into the shell and press the return key 
db.grantRolesToUser(
  "{{YOUR-DATABASE-USER}}",
  [
    { role: "clusterParameterReader", db: "admin" }
  ]
);

# Type exit then return to exit the MongoDB shell
# Run bin/up -d to start the deployment stack
$ bin/up -d
```
