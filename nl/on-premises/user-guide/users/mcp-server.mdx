Elk project heeft een eigen MCP-server, zodat een AI-client op uw computer het project kan lezen en bewerken, het kan compileren en op de opmerkingen kan reageren. De client meldt zich aan met een Git-authenticatietoken.

<Info>

Als u geen kaart **MCP server** ziet, verwijs uw beheerder dan naar [MCP-server](/nl/on-premises/configuration/overleaf-toolkit/integrations/mcp-server).

</Info>

## Nieuw in v6.3.3 {#new-in-v6-3-3}

Vanaf v6.3.3 kan de client ook met de projectgeschiedenis werken: de wijzigingen weergeven, twee versies vergelijken, een bestand lezen zoals het was, versies opslaan en verwijderen, en een bestand of het hele project herstellen. Hij kan de bijgehouden wijzigingen weergeven en accepteren of afwijzen, en zijn eigen bewerkingen als bijgehouden wijzigingen maken wanneer u daarom vraagt. Hij kan een stuk tekst van een opmerking voorzien en opmerkingsberichten bewerken of verwijderen, berichten in de projectchat lezen en versturen, bestanden en mappen verplaatsen en hernoemen, mappen maken en de taal van de spellingcontrole wijzigen. Wie wat mag, volgt uw rol in het project, net als in de editor, omdat de client met uw token werkt: zie [Wie mag wat](#who-may-do-what).

De MCP-server is geïntroduceerd in v6.3.1. v6.3.1 en v6.3.2 hebben dezelfde 17 tools; v6.3.3 heeft er 33.

| Tools | v6.3.1 en v6.3.2 | v6.3.3 |
| ----- | ----------------- | ------ |
| `get_clone_info`, `get_settings`, `list_files`, `delete_file`, `compile`, `get_compile_log`, `get_output_file_link`, `word_count`, `reply_to_comment`, `resolve_comment`, `reopen_comment` | Ja | Ja, ongewijzigd |
| `read_file` | De nieuwste inhoud | Ook een bestand zoals het was bij een `version` |
| `edit_file`, `write_file` | Volgen de instelling voor bijgehouden wijzigingen van het project | Ook `trackChanges`, om de bewerking een bijgehouden wijziging te maken |
| `update_settings` | Compiler, TeX Live-image en hoofddocument | Ook de taal van de spellingcontrole |
| `list_versions` | Versie, opmerking en datum | Ook de `id` die `delete_version` verwacht, en wie de versie heeft opgeslagen |
| `list_comments` | Berichten zonder id | Ook de `id` van elk bericht, die `edit_comment_message` en `delete_comment_message` verwachten |
| `list_changes`, `diff`, `create_version`, `delete_version`, `restore_file`, `restore_project`, `list_tracked_changes`, `accept_tracked_changes`, `reject_tracked_changes`, `add_comment`, `edit_comment_message`, `delete_comment_message`, `list_chat_messages`, `send_chat_message`, `move_file`, `create_folder` | Nee | Ja |

## Een client verbinden {#connect-a-client}

<Steps>
<Step title="Het venster openen">
Open het project. Klik in de linkerbalk op **Integrations** en daarna op **MCP server**.

<Frame caption="Het paneel Integrations">
  <img src="/images/on-premises/mcp-server-integrations.png" alt="Het paneel Integrations met de kaart MCP server" />
</Frame>

Het venster toont het adres van de server van dit project en een tabblad voor elke client: **Claude Code**, **Codex**, **Cursor**, **VS Code** en **Gemini CLI**.

<Frame caption="Het venster MCP server">
  <img src="/images/on-premises/mcp-server-dialog.png" alt="Het venster MCP server met het adres, een tabblad voor elke client en de opdracht voor Claude Code" />
</Frame>
</Step>

<Step title="Een token maken">
Klik op **Go to settings**. Uw accountinstellingen openen in een nieuw tabblad. Klik onder **Git integration** op **Generate token**, of op **Add another token** als u er al een hebt. Klik op **Copy** en bewaar het token op een veilige plek, want u ziet het maar één keer. Klik daarna op **Close**.

<Frame caption="Uw nieuwe token">
  <img src="/images/on-premises/mcp-server-token.png" alt="Het venster Git authentication token met een knop Copy" />
</Frame>

Een token dat u al gebruikt voor [Git-integratie](/nl/on-premises/user-guide/users/git-integration) werkt ook, net als één token voor al uw projecten.
</Step>

<Step title="De server aan uw client toevoegen">
Klik terug in het venster op het tabblad van uw client en daarna op **Copy** naast de configuratie.

| Tabblad | Waar het heen gaat | Het token |
| --- | ------------- | --------- |
| **Claude Code** | Voer de opdracht uit in een terminal | Vervang `<token>` in de opdracht |
| **Codex** | `~/.codex/config.toml` | Zet het in de omgevingsvariabele `OVERLEAF_TOKEN` |
| **Cursor** | `~/.cursor/mcp.json` | Zet het in de omgevingsvariabele `OVERLEAF_TOKEN` |
| **VS Code** | `.vscode/mcp.json` | Het bestand heeft een wachtwoordprompt met de naam `overleaf-token` in plaats van het token |
| **Gemini CLI** | Voer de opdracht uit in een terminal | Vervang `<token>` in de opdracht |

Het adres hoort bij één project. Om een ander project te verbinden, voegt u het onder een andere naam toe, omdat `overleaf` al bezet is. Verander voor Claude Code bijvoorbeeld `overleaf` in de opdracht in `overleaf-lab`.
</Step>
</Steps>

## De verbinding controleren {#check-the-connection}

### Met Claude Code {#with-claude-code}

```bash
claude mcp list
```

De server staat vermeld als verbonden:

```text
overleaf: https://<your-site>/project/<project-id>/mcp (HTTP) - ✔ Connected
```

### Met curl {#with-curl}

Dit werkt ongeacht uw client. Vervang het adres en het token en stuur het `initialize`-verzoek van het MCP-protocol:

```bash
curl -X POST https://<your-site>/project/<project-id>/mcp \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -H "Accept: application/json, text/event-stream" \
  -d '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2025-06-18","capabilities":{},"clientInfo":{"name":"curl","version":"1.0"}}}'
```

Het antwoord noemt de server, gevolgd door de instructies voor clients:

```json
{"result":{"protocolVersion":"2025-06-18","capabilities":{"tools":{"listChanged":true}},"serverInfo":{"name":"overleaf","version":"1.0.0"},"instructions":"This server works on one Overleaf project. ..."},"jsonrpc":"2.0","id":1}
```

Om de tools te zien, stuurt u `tools/list` met dezelfde opdracht. Het antwoord vermeldt 33 tools, of 31 als uw site de projectchat heeft uitgeschakeld. Vóór v6.3.3 zijn het er 17.

```bash
  -d '{"jsonrpc":"2.0","id":2,"method":"tools/list","params":{}}'
```

Om er een aan te roepen, stuurt u `tools/call`:

```bash
  -d '{"jsonrpc":"2.0","id":3,"method":"tools/call","params":{"name":"list_files","arguments":{}}}'
```

```json
{"result":{"content":[{"type":"text","text":"[\n  {\n    \"path\": \"main.tex\",\n    \"type\": \"doc\"\n  }\n]"}]},"jsonrpc":"2.0","id":3}
```

### Als er geen verbinding komt {#if-it-does-not-connect}

| Wat u ziet | Wat het betekent |
| ------------ | ------------- |
| Status `401`, of in Claude Code `✘ Failed to connect` met `HTTP 401` | Het token ontbreekt, is onjuist of is verwijderd |
| Status `404` | Geen project heeft deze ID |
| Status `405` | Het verzoek was geen `POST` |
| Status `406` met `Not Acceptable` | De `Accept`-header ontbreekt: de client moet zowel `application/json` als `text/event-stream` accepteren |

## Wat u ziet wanneer een client werkt {#what-you-see-when-a-client-works}

Bewerkingen verschijnen in een geopende editor terwijl de client ze maakt, net als die van een medewerker, zonder herladen. Nieuwe bestanden en mappen, verplaatsingen en hernoemingen verschijnen in de bestandsstructuur.

<Frame caption="Een regel toegevoegd door edit_file">
  <img src="/images/on-premises/mcp-server-live-edit.png" alt="De editor toont een regel die edit_file heeft toegevoegd, zonder venster en zonder herladen" />
</Frame>

`edit_file` wijzigt alleen tekst die precies één keer voorkomt. Anders krijgt de client een fout, zoals `oldString not found in main.tex, read_file again` of `oldString appears 2 times in main.tex, add context`, en verandert er niets.

Vanaf v6.3.3 verplaatst of hernoemt `move_file` een bestand of map en maakt het zo nodig de mappen van het nieuwe pad aan, en `create_folder` maakt een map. Als het bestand niet wordt gevonden of het nieuwe pad al bestaat, krijgt de client een fout en verandert er niets. `update_settings` kan ook de taal van de spellingcontrole wijzigen, bijvoorbeeld in `de`, of de spellingcontrole uitschakelen.

Antwoorden op opmerkingen verschijnen in het beoordelingspaneel onder uw naam, omdat het token van u is. Een opmerking die via de server is opgelost, verdwijnt uit het paneel, en heropenen brengt haar terug.

<Frame caption="Een antwoord verstuurd door reply_to_comment">
  <img src="/images/on-premises/mcp-server-comment.png" alt="Een opmerking in het beoordelingspaneel met een antwoord verstuurd door reply_to_comment" />
</Frame>

Vanaf v6.3.3 plaatst `add_comment` een opmerking bij een stuk tekst. De tekst moet precies één keer in het bestand voorkomen; komt hij vaker voor, dan geeft de client ook een langer stuk eromheen dat maar één keer voorkomt, en alleen de tekst krijgt de opmerking. De opmerking verschijnt in het beoordelingspaneel onder uw naam en blijft bij haar tekst als het bestand verandert. `edit_comment_message` wijzigt een van uw eigen berichten. `delete_comment_message` verwijdert een bericht, en het eerste verwijderen verwijdert de hele opmerking, zoals in het beoordelingspaneel.

`compile` compileert het project en geeft de lijst met uitvoerbestanden terug. `get_output_file_link` geeft daarna een link om de PDF of een ander uitvoerbestand te downloaden. De link heeft geen token nodig en werkt na 5 minuten niet meer.

Zie [Tools](/on-premises/configuration/overleaf-toolkit/integrations/mcp-server#tools) voor de volledige lijst met tools.

## Bijgehouden wijzigingen {#tracked-changes}

Vanaf v6.3.3 kunt u de client vragen zijn bewerkingen als bijgehouden wijzigingen te maken, bijvoorbeeld *Rewrite the abstract as a tracked change*. `edit_file` en `write_file` maken de wijziging in een bestaand bestand dan een bijgehouden wijziging op uw naam, zelfs als het bijhouden van wijzigingen in het project uit staat, en u accepteert of wijst haar af in het beoordelingspaneel. Een nieuw bestand is nooit een bijgehouden wijziging. Als u er niet om vraagt, volgen de bewerkingen de instelling voor bijgehouden wijzigingen van het project, net als die van u in de editor: ze worden bijgehouden als het bijhouden aan staat voor u of voor iedereen.

Als het account van de projecteigenaar geen bijgehouden wijzigingen heeft, krijgt de client `Track changes is off for this project` en verandert er niets.

Om elke bewerking van de client te beoordelen, zet u het bijhouden van wijzigingen voor uzelf aan. Om zijn bewerkingen in het beoordelingspaneel van die van u te onderscheiden, geeft u de client het token van een ander account waarmee u het project deelt.

`list_tracked_changes` geeft de bijgehouden wijzigingen weer met hun bestand, de ingevoegde of verwijderde tekst, de auteur en het tijdstip. `accept_tracked_changes` en `reject_tracked_changes` verwachten de id's van de wijzigingen en werken als het beoordelingspaneel: een geaccepteerde wijziging blijft in de tekst, een afgewezen invoeging wordt verwijderd en een afgewezen verwijdering komt terug. Een geopende editor toont het resultaat zonder herladen. De tools vertellen de client alleen de wijzigingen te accepteren of af te wijzen waar u om vraagt.

## Geschiedenis {#history}

Vanaf v6.3.3 ziet de client de projectgeschiedenis zoals het geschiedenispaneel die toont.

| Tool | Wat het doet |
| ---- | ------------ |
| `list_changes` | Geeft de wijzigingen weer, nieuwste eerst: wie welke bestanden wanneer heeft gewijzigd, met de versies voor en na elke wijziging. Oudere wijzigingen komen in volgende delen. |
| `diff` | Vergelijkt twee versies: één bestand als unified diff, zoals `git diff`, of de bestanden die zijn toegevoegd, verwijderd, bewerkt of hernoemd |
| `read_file` met `version` | Leest een bestand zoals het was bij een versie |
| `list_versions` | Geeft de opgeslagen versies weer, met hun opmerking en wie ze heeft opgeslagen |
| `create_version` | Slaat de nieuwste versie, of een eerdere, op met een opmerking, zoals **Label this version** |
| `delete_version` | Verwijdert een opgeslagen versie; de wijzigingen blijven |
| `restore_file` | Herstelt een bestand zoals het was bij een versie, zoals **Restore this version** |
| `restore_project` | Herstelt het hele project zoals het was bij een versie, zoals **Restore project to this version** |

Een herstel is zelf een nieuwe wijziging, dus u kunt het op dezelfde manier ongedaan maken. De tools vertellen de client alleen te herstellen wanneer u daarom vraagt.

Als de projecteigenaar geen volledige projectgeschiedenis heeft, ziet de client alleen de wijzigingen van de laatste 24 uur, of de nieuwste wijziging als alle wijzigingen ouder zijn, zoals in het geschiedenispaneel. Hij kan oudere versies niet vergelijken, lezen of herstellen.

## Projectchat {#project-chat}

Vanaf v6.3.3 leest `list_chat_messages` de projectchat, nieuwste eerst, 50 berichten tegelijk. `send_chat_message` verstuurt een bericht onder uw naam, en het verschijnt meteen in een geopende chat. Als uw site de projectchat heeft uitgeschakeld, heeft de client geen van beide tools.

## Wie mag wat {#who-may-do-what}

De client mag wat uw rol in het project toestaat.

| Wat de client doet | Eigenaar | Bewerker | Beoordelaar | Lezer (benoemde medewerker) | Lezer (delen via link) |
| -------------------- | ----: | -----: | -------: | --------------------------: | --------------------: |
| Bestanden en instellingen lezen, compileren, het log lezen, de PDF downloaden | Ja | Ja | Ja | Ja | Ja |
| Bestanden schrijven, bewerken, verplaatsen en verwijderen, mappen maken, de instellingen wijzigen | Ja | Ja | Nee | Nee | Nee |
| De geschiedenis, opmerkingen en bijgehouden wijzigingen zien | Ja | Ja | Ja | Ja | Nee |
| Chatberichten lezen en versturen | Ja | Ja | Ja | Ja | Nee |
| Opmerkingen toevoegen en erop antwoorden | Ja | Ja | Ja | Nee | Nee |
| Een opmerking oplossen, heropenen of verwijderen | Ja | Ja | Die ze zelf zijn begonnen | Nee | Nee |
| Een opmerkingsbericht bewerken | Eigen | Eigen | Eigen | Nee | Nee |
| Een opmerkingsbericht verwijderen | Ja | Ja | Eigen | Nee | Nee |
| Bijgehouden wijzigingen accepteren of afwijzen | Ja | Ja | Nee | Nee | Nee |
| Een versie opslaan | Ja | Ja | Ja | Nee | Nee |
| Een opgeslagen versie verwijderen | Ja | Die ze zelf hebben opgeslagen | Die ze zelf hebben opgeslagen | Nee | Nee |
| Een bestand of het project herstellen | Ja | Ja | Nee | Nee | Nee |

Bewerkers die via een link zijn toegetreden, tellen als bewerkers. Beoordelaars kunnen via MCP geen bestanden bewerken, ook niet als bijgehouden wijzigingen.

## Een client loskoppelen {#disconnect-a-client}

Verwijder het token: zie [Een token verwijderen](/nl/on-premises/user-guide/users/git-integration#delete-a-token). Vanaf dat moment antwoordt de server met `401` op dat token. Als u het ook voor Git gebruikt, accepteert Git het ook niet meer.
