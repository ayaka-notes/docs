Hier hebben we antwoorden verzameld op enkele veelgestelde vragen over Ayakaleaf Pro.

### Basisvragen

<Accordion title="V01: Is Ayakaleaf Pro een gratis proefversie? Is er een licentie voor nodig?">

Nee. Ayakaleaf Pro is volledig gratis te gebruiken. Het is geen proefversie en er is geen licentie voor nodig.

</Accordion>

<Accordion title="V02: Bevat Ayakaleaf Pro alle functies van Overleaf Server Pro?">

Ja. Ayakaleaf Pro bevat alle functies van Overleaf Server Pro, inclusief de Git-Bridge-integratie. Het bevat ook een selectie van functies van het Overleaf SaaS-platform. We blijven Ayakaleaf Pro verder ontwikkelen en verbeteren.

</Accordion>

<Accordion title="V03: Hoeveel kost Overleaf Server Pro?">

Overleaf Server Pro kost ongeveer \$300 per gebruiker per jaar. Er zijn minimaal 10 licenties vereist, dus implementaties beginnen bij ongeveer \$3.000 per jaar. Kleinere openbare Amerikaanse contracten laten jaarlijkse kosten zien van ongeveer \$320–\$370 per gebruiker. Dat maakt Server Pro duur, vooral voor kleinere teams. Zie [#information-and-price-about-overleaf-server-pro](/nl/on-premises#information-and-price-about-overleaf-server-pro  "mention") voor gedocumenteerde aankopen en prijzen.

</Accordion>

<Accordion title="V04: Waarom bevat Overleaf Server Pro geen GitHub Sync of AI-functies?">

Overleaf Server Pro wordt vaak gebruikt door overheidsorganisaties. Zij implementeren het op privénetwerken en beheren de toegang strikt. Om gevoelige gegevens te beschermen, wisselen de meegeleverde functies geen gegevens uit met diensten van derden. Als je GitHub Sync, AI of vergelijkbare verbonden functies nodig hebt, raadt Overleaf een abonnement op het SaaS-platform aan.

</Accordion>

<Accordion title="V05: Is Ayakaleaf Pro veilig en betrouwbaar?">

Ayakaleaf Pro is open source. We controleren de code met tools zoals Codex Security om de beveiliging en betrouwbaarheid te versterken. Als je geen gegevenssynchronisatie met derden inschakelt, blijven je gegevens op je eigen server. Ayakaleaf Pro bevat geen telemetrie die je gegevens naar elders verstuurt.

</Accordion>

<Accordion title="V06: Wordt Ayakaleaf Pro op lange termijn onderhouden?">

We zullen er alles aan doen om dit project op lange termijn te onderhouden.

</Accordion>

<Accordion title="V07: Voldoet Ayakaleaf Pro aan de licentievoorwaarden?">

Ayakaleaf Pro is een community-fork. De code en geïntegreerde functies komen voort uit bijdragen van de community. Het valt onder de AGPL v3-licentie. Implementaties voldoen aan deze licentie wanneer ze aan de bijbehorende vereisten voldoen.

</Accordion>

<Accordion title="V08: Waarom heet het project Ayakaleaf Pro?">

Het project heette oorspronkelijk Overleaf Pro in 2024. De ontwikkeling lag een tijd stil en werd eind 2025 hervat. In het eerste kwartaal van 2026 hernoemde Overleaf zijn abonnement met AI-functies naar Pro. Feedback uit de community wees er ook op dat de naam Overleaf Pro risico's op het gebied van merkrecht en imitatie met zich mee kon brengen. Gebruikers zouden kunnen denken dat het project officieel was.

We hebben het project hernoemd naar Ayakaleaf Pro om die verwarring te voorkomen. De naam kan worden gelezen als "Ayaka-notes Overleaf Pro". De maintainer (je mag me ayaka noemen!) draagt al sinds zijn studententijd, meer dan vijf jaar geleden, bij aan de ontwikkeling van de Overleaf-community. Deze ervaring onderbouwt onze toezegging om het project op lange termijn te onderhouden.

</Accordion>

<Accordion title="V09: Wat onderscheidt Ayakaleaf Pro van nieuwere, met AI gebouwde LaTeX-editors?">

Sinds 2026 heeft de opensourcecommunity veel met AI gebouwde LaTeX-editors uitgebracht, waaronder OpenAI Prism. Ayakaleaf Pro houdt je gegevens en services op je eigen server. Zo heb je directe controle over je implementatie en je gegevens.

Veel experimentele community-editors hebben geen vastgesteld plan voor onderhoud op lange termijn. LaTeX-compilatieplatforms van derden kunnen ook stoppen wanneer hun gebruikersbestand of inkomsten onvoldoende zijn. Ayakaleaf Pro levert alle broncode en laat je elke service zelf hosten. Zelfs als het onderhoud zou stoppen, kan je bestaande zelfgehoste service blijven draaien.

</Accordion>

### Functies

<Accordion title="V01: Welke functies biedt Ayakaleaf Pro? Kan ik een nieuwe functie aanvragen?">

Raadpleeg onze documentatie voor de actuele lijst met functies. Als er een functie is die je graag toegevoegd zou zien, open dan gerust een issue (voor een functieverzoek) op GitHub. We doen ons best om aangevraagde functies te implementeren, maar ontwikkeling kost tijd en we kunnen niet garanderen dat elke functie meteen wordt opgeleverd.

</Accordion>

<Accordion title="V02: Ik heb zelf functies gebouwd. Kan ik een PR indienen, en wordt die gegarandeerd geaccepteerd?">

Bijdragen zijn welkom, maar acceptatie is niet gegarandeerd. We beoordelen elke PR op basis van de impact op de onderliggende Overleaf-codebase, de onderhoudslast en de waarde die hij gebruikers biedt. We doen ons best om waardevolle bijdragen te mergen en te onderhouden.

We kunnen echter PR's afwijzen die buitensporig veel wijzigingen introduceren, bestaan uit niet-gereviewde of slecht begrepen door AI gegenereerde code ("vibe coding"), of functies toevoegen die op termijn moeilijk te onderhouden zijn.

</Accordion>

<Accordion title="V03: Hoe configureer ik een specifieke functie?">

Over het algemeen werken we de documentatie bij wanneer we een nieuwe functie uitbrengen. Raadpleeg de betreffende documentatie voor gedetailleerde installatie-instructies en uitleg over de beschikbare omgevingsvariabelen.

</Accordion>

<Accordion title="V04: Welke Python-bibliotheken kan de Python Runner gebruiken?">

De Python Runner voert Python uit in de browser van de gebruiker met [Pyodide](https://pyodide.org/) 0.29.3, niet op de server. Deze laadt de pakketten die je code importeert uit de [pakketten die in Pyodide zijn ingebouwd](https://pyodide.org/en/0.29.3/usage/packages-in-pyodide.html), zoals NumPy, pandas en Matplotlib. Pakketten die met `pip` zijn geïnstalleerd en andere pakketten zijn niet beschikbaar. Er hoeft niets op de server te worden geconfigureerd.

</Accordion>

<Accordion title="V05: Kan de spellingcontrole Japans of Chinees controleren?">

Nee. De spellingcontrole heeft geen woordenboek voor Japans of Chinees, dus deze talen staan niet in de lijst met talen voor de spellingcontrole. Gebruikers kunnen de spellingcontrole voor een project uitschakelen in de editorinstellingen.

</Accordion>

### Implementatie

<Accordion title="V01: Ondersteunt Ayakaleaf Pro gedistribueerde implementatie in k8s?">

Voor de meeste gebruikers raden we aan te implementeren met de [Toolkit](/nl/on-premises/installation/using-the-toolkit). We raden grootschalige clusterimplementaties met Kubernetes of vergelijkbare platforms af, omdat die de operationele complexiteit en het onderhoud aanzienlijk kunnen vergroten.

</Accordion>

<Accordion title="V02: Hoe kan ik de beschikbaarheid garanderen bij duizenden gebruikers?">

Raadpleeg onze handleiding voor [horizontaal schalen](/nl/on-premises/maintenance/horizontal-scaling). Je kunt meerdere Overleaf-instanties implementeren en een load balancer configureren om het verkeer over die instanties te verdelen.

</Accordion>

<Accordion title="V03: Kunnen jullie me helpen met implementeren of migreren?">

Als je een bestaande Overleaf Server Pro-instantie hebt, helpen we je graag bij de migratie naar Ayakaleaf Pro. Neem contact op via e-mail of issues.

</Accordion>

<Accordion title="V04: Kan ik Ayakaleaf Pro hosten onder een subpad van een URL, zoals `https://example.com/overleaf`?">

Nee. Ayakaleaf Pro moet vanaf de root van een domein worden aangeboden. Gebruik een eigen domein of subdomein, zoals `https://overleaf.example.com`.

</Accordion>

<Accordion title="V05: Kan ik Ayakaleaf Pro op Windows of macOS draaien, of zonder de Toolkit?">

We ondersteunen Linux-servers met de [Toolkit](/nl/on-premises/installation/using-the-toolkit). Docker Desktop op Windows, WSL2 of macOS werkt mogelijk, maar we testen dit niet; zie [Probleemoplossing](/nl/on-premises/support/troubleshooting) voor een bekend MongoDB-probleem.

We leveren geen losse `docker-compose.yml`. Om de Compose-configuratie te zien die de Toolkit gebruikt, voer je `bin/docker-compose config` uit in de Toolkit-map.

</Accordion>

<Accordion title="V06: Hoe verwijder ik Ayakaleaf Pro?">

Er is geen script om de installatie ongedaan te maken. In de Toolkit-map:

1. Stop en verwijder de containers met `bin/docker-compose down`.
2. Verwijder de gegevens. Standaard staan die in de map `data/` van de Toolkit. Als je `OVERLEAF_DATA_PATH`, `MONGO_DATA_PATH`, `REDIS_DATA_PATH` of `GIT_BRIDGE_DATA_PATH` in `config/overleaf.rc` hebt gewijzigd, verwijder die mappen dan ook. Dit kan niet ongedaan worden gemaakt, dus [maak eerst een back-up](/nl/on-premises/maintenance/data-and-backups) als je de gegevens mogelijk nog nodig hebt.
3. Verwijder de Toolkit-map.
4. Verwijder de Docker-images, die je kunt weergeven met `docker images`: `ghcr.io/ayaka-notes/overleaf-pro`, het git-bridge-image, `mongo`, `redis` en de TeX Live-images.

</Accordion>

<Accordion title="V07: Hoe stop, start of herstart ik Ayakaleaf Pro?">

Voer deze opdrachten uit in de Toolkit-map:

* `bin/stop` stopt alle containers, `bin/start` start ze weer. De containers blijven behouden, dus gebruikers blijven ingelogd.
* `bin/up -d` maakt de containers aan en start ze op de achtergrond. Voer dit uit na het wijzigen van `config/variables.env`, `config/overleaf.rc` of `config/version`: het maakt de containers waarvan de configuratie is gewijzigd opnieuw aan, en pas dan worden de wijzigingen van kracht. `bin/stop` en `bin/start` passen ze niet toe.
* `bin/docker-compose restart sharelatex` herstart alleen de Overleaf-container, zonder configuratiewijzigingen toe te passen.

Als gebruikers telkens worden uitgelogd wanneer `bin/up` de container opnieuw aanmaakt, stel dan `OVERLEAF_SESSION_SECRET` in; zie de Vragen en antwoorden in [Omgevingsvariabelen](/nl/on-premises/configuration/overleaf-toolkit/environment-variables).

</Accordion>

<Accordion title="V08: Waar vul ik de OAuth-callback-URL in?">

In de applicatie die je bij de provider aanmaakt, niet in Ayakaleaf Pro. Er is voor geen van deze integraties een callback-instelling in `config/variables.env`: Ayakaleaf Pro stelt elke callback-URL samen uit `OVERLEAF_SITE_URL` en stuurt deze naar de provider, die hem weigert tenzij hij overeenkomt met de URL die voor de applicatie is geregistreerd. Je registreert hem dus alleen bij de provider en stelt `OVERLEAF_SITE_URL` in op het adres dat gebruikers openen.

| Integratie | Veld bij de provider | Waarde |
| --- | --- | --- |
| [GitHub](/nl/on-premises/configuration/overleaf-toolkit/github-synchronisation) | Authorization callback URL | `${OVERLEAF_SITE_URL}/user/github-sync/oauth2/callback` |
| [GitLab](/nl/on-premises/configuration/overleaf-toolkit/gitlab-synchronisation) | Redirect URI | `${OVERLEAF_SITE_URL}/user/gitlab-sync/oauth2/callback` |
| [Gitea](/nl/on-premises/configuration/overleaf-toolkit/gitea-synchronisation) | Redirect URIs | `${OVERLEAF_SITE_URL}/user/gitea-sync/oauth2/callback` |
| [Dropbox](/nl/on-premises/configuration/overleaf-toolkit/dropbox-synchronisation) | Redirect URIs (klik op **Add**) | `${OVERLEAF_SITE_URL}/user/dropbox/oauth/callback` |
| [Zotero](/nl/on-premises/configuration/overleaf-toolkit/zotero-integration) | Callback URL | `${OVERLEAF_SITE_URL}/user/zotero/oauth/callback` |
| [Mendeley](/nl/on-premises/configuration/overleaf-toolkit/mendeley-integration) | Redirect URL | `${OVERLEAF_SITE_URL}/user/mendeley/oauth/callback` |
| [OIDC-login](/nl/on-premises/configuration/overleaf-toolkit/authentication/oidc-authentication) | Redirect URI | `${OVERLEAF_SITE_URL}/oidc/login/callback` |
| [SAML-login](/nl/on-premises/configuration/overleaf-toolkit/authentication/saml-authentication) | ACS URL (Assertion Consumer Service) | `${OVERLEAF_SITE_URL}/saml/login/callback` |

Als je `OVERLEAF_SITE_URL` wijzigt, bijvoorbeeld naar een nieuw domein, werk de URL dan ook bij elke provider bij, anders mislukt het koppelen.

</Accordion>

### LaTeX

<Accordion title="V01: Zijn de LaTeX-projectcompilaties van gebruikers geïsoleerd? Is Shell Escape ingeschakeld?">

Wanneer je Sandbox Compiles inschakelt, wordt de compilatie van elke gebruiker in een afzonderlijke Docker-container uitgevoerd, geïsoleerd van de compilaties van andere gebruikers. Shell Escape is standaard ingeschakeld voor Sandbox Compiles.

</Accordion>

<Accordion title="V02: Is de Sandbox Compiles-image betrouwbaar? Kan compileren mislukken?">

We hebben onze TeX Live Full-image voor Sandbox Compiles de afgelopen drie jaar verbeterd. In de meeste gevallen compileren projecten die op overleaf.com compileren ook correct met Ayakaleaf Pro. Als een benodigd lettertype niet beschikbaar is, upload dat lettertype dan handmatig naar je project.

</Accordion>

<Accordion title="V03: Mijn project compileert niet. Kunnen jullie me helpen het probleem op te lossen?">

Upload je project naar de officiële Overleaf-website, schakel delen via een alleen-lezen-link in en voeg de link toe aan een GitHub-issue.

We onderzoeken en verhelpen bugs die verhinderen dat een project in Ayakaleaf Pro compileert, wanneer het wel succesvol compileert op de officiële Overleaf-website. Compilatieproblemen buiten dit bereik vallen niet onder onze ondersteuning.

</Accordion>
