<Accordion title="Overleaf draaien met een NFS-bestandssysteem">

Het mounten van een NFS-bestandssysteem in een Overleaf-container is technisch mogelijk, maar wordt niet aanbevolen en kan tot verschillende soorten prestatieproblemen leiden.

Een veelvoorkomende fout bij compilaties is:

```text
EBUSY: resource busy or locked, unlink '/var/lib/overleaf/data/compiles/62f3d57bef7cf9005c364e75-62f3d57bef7cf9005c364e7a/.nfs573663533034825247625441'
```

We raden met name af om door NFS ondersteunde bestandssystemen te gebruiken voor tijdelijke gegevens, zoals de mappen voor compilatiegegevens. We raden aan om voor de volgende mappen een lokale scratchschijf te gebruiken, bij voorkeur een lokale SSD.

Voor opstellingen op basis van `docker-compose` raden we aan om simpelweg de bind-mount vanaf NFS te overschrijven, zodat je geen paden in de applicatie hoeft te wijzigen. Hier is een voorbeeld van een fragment uit een `docker-compose`-configuratie met een scratchschijf die op `/scratch` is gemount:

```yaml title="docker-compose excerpt"
services:
  sharelatex:
    environment:
      SANDBOXED_COMPILES_HOST_DIR: /scratch/compiles/
    volumes:
      - nfs:/var/lib/overleaf/data
      - /scratch/cache/:/var/lib/overleaf/data/cache
      - /scratch/compiles/:/var/lib/overleaf/data/compiles
      - /scratch/output/:/var/lib/overleaf/data/output
      - /scratch/tmp/:/var/lib/overleaf/tmp
```

Het is niet nodig om bestaande bestanden na de update van de NFS naar hun nieuwe locatie te migreren. De LaTeX-compiler kan alle bestanden opnieuw aanmaken met een volledige compilatierun.

Zie voor meer details: https://docs.overleaf.com/on-premises/support/troubleshooting#running-overleaf-with-an-nfs-filesystem

</Accordion>

<Accordion title="Overleaf draaien op Windows of macOS zorgt ervoor dat de service `mongo` niet start">

Als je Overleaf op Windows of macOS draait, kan het herstarten van de service `mongo` mislukken met de foutmelding:

```text title="Example error"
Failed to start up WiredTiger under any compatibility version.
Reason: 1: Operation not permitted
```

Om deze fout te voorkomen, moeten de gegevens in een volume worden opgeslagen in plaats van in een via bind-mount gekoppelde map (zie de documentatie van de image `mongo` voor meer details: https://github.com/docker-library/docs/blob/master/mongo/content.md#where-to-store-data). Om gegevens op te slaan in Docker-volumes die in de MongoDB- en Redis-containers zijn gemount, voeg je het volgende toe aan `config/docker-compose.override.yml` (maak dit bestand aan als het nog niet bestaat):

```yaml title="config/docker-compose.override.yml"
volumes:
  mongo-data:
  redis-data:

services:
  mongo:
    volumes:
      - mongo-data:/data/db

  redis:
    volumes:
      - redis-data:/data
```

Zie voor meer informatie: https://docs.overleaf.com/on-premises/support/troubleshooting#running-overleaf-on-windows-or-macos-results-in-the-mongoservice-not-starting

</Accordion>

<Accordion title="Upgraden naar Redis 6.2 leidt tot een herstartlus">

Gebruik de opdracht `docker logs redis` om een kopie van de logs weer te geven.

Als je de regel `Fatal: Can't initialize Background Jobs` ziet, ziet de volledige uitvoer er ongeveer zo uit:

```text title="Redis log example"
1:M 11 Feb 2024 15:19:22.609 # Server initialized
1:M 11 Feb 2024 15:19:22.609 # Fatal: Can't initialize Background Jobs.
1:C 11 Feb 2024 15:19:26.055 # oO0OoO0OoO0Oo Redis is starting oO0OoO0OoO0Oo
```

Dit kan verband houden met de Docker-versie die momenteel wordt gebruikt. Updaten naar een versie >= 20.10.10 zou dit probleem moeten oplossen.

Zie voor meer informatie de upstream-issue van Redis: https://github.com/redis/redis/issues/12362

Referentie: https://docs.overleaf.com/on-premises/support/troubleshooting#upgrading-to-redis-6.2-results-in-a-restart-loop

</Accordion>

<Accordion title="Onjuiste oriëntatie van voorbeeld-/miniatuurafbeeldingen in de sjabloongalerij">

Soms worden de voorbeeld-/miniatuurafbeeldingen die Server Pro genereert in de verkeerde oriëntatie aangemaakt en is handmatig ingrijpen nodig om dit te corrigeren. Deze afbeeldingen worden opgeslagen in `/var/lib/overleaf/data/template_files/` (>= 5.0.3) en `/var/lib/sharelatex/data/template_files/` (eerdere versies).

We raden aan om een back-up van deze map te maken voordat je wijzigingen aanbrengt.

Volg de onderstaande stappen voor elk getroffen sjabloon:

Zoek de sjabloon-IDGa naar de sjabloongalerij van je instantie (/templates/all), open een getroffen sjabloon en kopieer de ID uit de URL (bijvoorbeeld: https://your-instance-url/templates/6645d346c224815e9460a695).Voer de correctieopdracht uitVoer de volgende opdracht uit vanaf de Docker-host (vervang de sjabloon-ID door de ID die je hebt gekopieerd en pas het pad zo nodig aan):docker exec sharelatex /bin/bash -c "mogrify -rotate 90 /var/lib/overleaf/data/template\_files/6645d346c224815e9460a695\_\*\{thumbnail,preview\}"

Referentie: https://docs.overleaf.com/on-premises/support/troubleshooting#incorrect-orientation-of-template-gallery-preview-thumbnail-images

</Accordion>

<Accordion title="Controleer of je systeemaanroepen hebt ingeschakeld. Voor pdflatex is dit 'pdflatex -shell-escape'.">

De opdracht `\write18` is in de Community Edition standaard uitgeschakeld, omdat alle compilaties binnen dezelfde container `sharelatex` plaatsvinden; dit is de veiligere standaardinstelling.

Als je deze voor pdflatex wilt inschakelen, maak dan in de root van je project een bestand `latexmkrc` aan met de volgende inhoud:

```perl title="latexmkrc"
$pdflatex = 'pdflatex --shell-escape';
```

Probeer daarna opnieuw te compileren.

Referentie: https://docs.overleaf.com/on-premises/support/troubleshooting#please-verify-that-you-have-enabled-system-calls.-for-pdflatex-this-is-pdflatex-shell-escape

</Accordion>
