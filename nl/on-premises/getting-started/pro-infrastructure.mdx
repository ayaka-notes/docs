#### Services

De Overleaf Pro-infrastructuur bestaat uit vier primaire services: `sharelatex`, `git-bridge` (optioneel), `mongo` en `redis`. De `sharelatex`-service, die de hoofdapplicatie van Server Pro draait, is afhankelijk van de services `mongo` en `redis` voor de database en caching/realtimefunctionaliteit, en van `git-bridge` voor de [Git-integratie](/nl/on-premises/configuration/overleaf-toolkit/git-integration) (optioneel). De enige poort die op de hostmachine wordt gepubliceerd is poort 80, die door de `sharelatex`-container wordt gebruikt.

Server Pro ondersteunt optioneel ook [S3-compatibele opslag](/nl/on-premises/configuration/overleaf-toolkit/s3) voor projectbestanden en de volledige projectgeschiedenis, en kan daarnaast toegang tot de hoofd[documentatiesite van Overleaf](https://www.overleaf.com/learn) via een proxy aanbieden. Zie voor meer informatie onze handleiding over pagina's voor [LaTeX-gebruikershulp toevoegen](/nl/on-premises/configuration/overleaf-toolkit/adding-latex-user-help).

<Info>

Indien nodig kunnen MongoDB en Redis worden geëxternaliseerd door met omgevingsvariabelen naar externe services te verwijzen. Zie voor meer informatie [Overleaf configureren](/nl/on-premises/configuration) als je Docker Compose gebruikt en [Toolkit-instellingen](/nl/on-premises/configuration/overleaf-toolkit/toolkit-settings) als je de Overleaf Toolkit gebruikt.

</Info>

#### Compileren

Voor [Sandboxed Compiles](/nl/on-premises/configuration/overleaf-toolkit/sandboxed-compiles) regelt de `sharelatex`-container het aanmaken van nieuwe containers om projectcompilaties af te handelen; dit gebeurt via de Docker-socket op de hostmachine. Je kunt [hier](/nl/on-premises/getting-started/microservices#editor-and-compile-process) meer lezen over de editor en het end-to-end compileer- en cachingproces.

#### Netwerken

Communicatie tussen containers verloopt via de interne DNS-resolutie van Docker over een speciaal bridge-netwerk, en er zijn geen firewalls ingeschakeld. Standaard gebruiken de bovengenoemde services hun respectievelijke standaardpoorten, maar deze zijn configureerbaar via omgevingsvariabelen. De `sharelatex`-container gebruikt poort 80 voor externe webtoegang (geserveerd door Nginx), de `mongo`-container gebruikt poort 27017 en `redis` gebruikt poort 6379.

Klanten die onze beheerde oplossing [Overleaf Toolkit](https://github.com/overleaf/toolkit) gebruiken, kunnen optioneel via een omgevingsvariabele [een TLS-proxy inschakelen](/nl/on-premises/configuration/overleaf-toolkit/tls-proxy) om HTTPS-verbindingen met Nginx te termineren. Je kunt ook je bestaande TLS-proxy gebruiken.

<Info>

Je kunt [hier](/nl/on-premises/configuration/overleaf-toolkit/tls-proxy) een diagram bekijken dat de stroom van verzoeken uitlegt.

</Info>

#### Samenvatting

* Buiten het Docker-netwerk is alleen poort 80 toegankelijk, gebonden aan Nginx. <strong>Opmerking:</strong> De `sharelatex`-container draait veel [services](https://github.com/overleaf/overleaf/tree/main/services) die via HTTP met elkaar communiceren. Deze poorten zijn echter **niet** toegankelijk van buiten het Docker-netwerk.
* Binnen het Docker-netwerk kunnen Overleaf-services, MongoDB, Redis en Git Bridge vrij met elkaar communiceren.
* Binnen [Sandboxed Compiles](/nl/on-premises/configuration/overleaf-toolkit/sandboxed-compiles)-containers is geen netwerk beschikbaar.
