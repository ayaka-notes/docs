---
title: Wat is de Ayakaleaf Toolkit?
icon: toolbox
---

De Ayakaleaf Toolkit is de aanbevolen deploymentmethode voor on-premises installaties van de Community Edition en Ayakaleaf Pro. Hij is ontworpen voor de meest voorkomende omgeving: één fysieke server of virtuele machine. De Toolkit gebruikt `docker compose` om de Docker-containers van je server te beheren en biedt een reeks scripts die `docker`-commando's omhullen, om je te helpen met de meer technische kant van het beheren van een on-premises versie van Overleaf.

#### De `bin/docker-compose`-wrapper

Het script `bin/docker-compose` is een wrapper rond `docker compose`. Het laadt de configuratie uit de map `config/` voordat het `docker compose` aanroept met de argumenten die aan het script zijn meegegeven.

Je kunt `bin/docker-compose` beschouwen als een transparante wrapper voor het programma `docker compose` dat op je machine is geïnstalleerd.

Voorbeeld:

```bash title="Check running containers"
$ bin/docker-compose ps
```

#### Handige hulpscripts

Naast `bin/docker-compose` biedt de Toolkit handige scripts voor veelvoorkomende taken:

* `bin/up`: snelkoppeling voor `bin/docker-compose up`
* `bin/start`: snelkoppeling voor `bin/docker-compose start`
* `bin/stop`: snelkoppeling voor `bin/docker-compose stop`
* `bin/shell`: start een shell binnen de **sharelatex**-container
* `bin/doctor`: script om informatie over de installatie en deployment te verzamelen. Zie de sectie "Je server controleren" hieronder
* `bin/mongo`: start een shell binnen de **mongo**-container en schakelt over naar de juiste database (**sharelatex**)
* `bin/backup-config`: maakt een kopie (zip of tar) van je huidige configuratie en slaat deze op in een doelmap naar keuze
* `bin/logs`: servicelogs bekijken/volgen
* `bin/error-logs`: foutlogs van services bekijken/volgen
* `bin/rename-env-vars-5-0`: migratiescript om omgevingsvariabelen in **config/variables.env** bij te werken (rebranding van ShareLaTeX naar Overleaf)
* `bin/rename-rc-vars`: migratiescript om omgevingsvariabelen in **config/overleaf.rc** bij te werken (rebranding van ShareLaTeX naar Overleaf)
* `bin/run-script`: hulpmiddel om het uitvoeren van scripts in de **sharelatex**-container te vereenvoudigen
* `bin/upgrade`: helpt bij het upgraden van instanties. Het script controleert op Toolkit-updates (via git) en biedt aan wijzigingen te pullen, controleert op de nieuwste versie van de Docker-image en biedt aan deze bij te werken. Het vraagt stap voor stap om bevestiging, biedt de optie om de huidige configuratie te back-uppen en regelt het stoppen/starten van Docker-services. Zie Upgrading your deployment voor meer informatie: https://docs.overleaf.com/on-premises/maintenance/upgrading-your-deployment

<Info>

Als je je instantie liever draait zonder aan de Docker-logs gekoppeld te zijn, kun je `bin/up -d` uitvoeren om in detached-modus te draaien.

</Info>

#### Je server controleren

De Overleaf Toolkit bevat een handig script genaamd `bin/doctor` dat een rapport genereert van eventuele ontbrekende afhankelijkheden.

Voer voordat je verdergaat het script `bin/doctor` uit en controleer of alles correct werkt:

```bash title="Run Overleaf Doctor"
bin/doctor
```
