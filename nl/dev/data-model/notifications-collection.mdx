`notifications` bevat de meldingen die bovenaan het projectdashboard van een gebruiker worden getoond. Eén document is één melding voor één gebruiker, herkenbaar aan zijn `key`. Alleen de dienst `notifications` benadert de collectie (`services/notifications/app/js/Notifications.js`); `web` en `third-party-datastore` roepen de HTTP-API ervan aan. Er is geen Mongoose-schema.

#### Velden {#fields}

| Veld | Type | Betekenis | Bron |
| --- | --- | --- | --- |
| `_id` | ObjectId | Melding-id. `web` markeert een melding via deze id als gelezen. | `Notifications.js:58-65` |
| `user_id` | ObjectId | De gebruiker die de melding ziet. | `Notifications.js:26` |
| `key` | String | Identificeert de melding, bijvoorbeeld `project-invite-<inviteId>`. De upsert houdt één document per `user_id` en `key`; er is geen unieke index. | `Notifications.js:27`, `:51-55` |
| `templateKey` | String | Welke melding de frontend weergeeft. Wordt verwijderd wanneer de melding gelezen of gesloten is; het document blijft bestaan. | `Notifications.js:29`, `:63`, `:72`, `:78` |
| `messageOpts` | Object | Waarden voor de meldingstekst, afhankelijk van `templateKey` (bij een projectuitnodiging: `userName`, `projectName`, `projectId`, `token`). Wordt verwijderd wanneer de gebruiker de melding via haar id sluit. | `Notifications.js:28`, `:63` |
| `expires` | Date | Optioneel. De TTL-index verwijdert het document na dit tijdstip. | `Notifications.js:35-50` |

#### Opmerkingen {#notes}

* Een gelezen melding wordt niet verwijderd: alleen `templateKey` verdwijnt. Omdat het document de sleutel nog bevat, doet een latere `addNotification` zonder `forceCreate` voor dezelfde sleutel niets (`Notifications.js:21-24`).
* De routes `/key/:key` werken alleen op de sleutel, over alle gebruikers heen (`Notifications.js:76-100`).
* Als `web` geen `apis.notifications.url` heeft, maakt het geen meldingen aan en leest het ze niet (`NotificationsHandler.mjs:17`, `:41`).
