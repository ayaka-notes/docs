title: Dropbox Projects-collectie
icon: folder-open
---

`dropboxProjects` koppelt een project aan de map in de Dropbox van één gebruiker. Een project dat met meerdere Dropbox-gebruikers is gedeeld, heeft één document per gebruiker. De collectie hoort bij Dropbox-synchronisatie: third-party-datastore (`services/third-party-datastore/app/js/StateManager.mjs`) schrijft haar, en de webmodule `dropbox` (`services/web/modules/dropbox/app/src/DropboxHandler.mjs`) leest en wist haar. Er is geen Mongoose-schema.

| Veld | Type | Betekenis | Bron |

| `userId` | ObjectId | De Overleaf-gebruiker in wiens Dropbox de map staat. | `StateManager.mjs:145` |
| `projectId` | ObjectId | Het project dat naar de map wordt gesynchroniseerd. | `StateManager.mjs:146` |
| `dropboxId` | String | De `id` van de map in de Dropbox-mapmetadata. | `StateManager.mjs:147`, `JobProcessor.mjs:82-87`, `PullManager.mjs:138` |

Projectmappen staan op het hoogste niveau, één per project, bijvoorbeeld `/thesis (1)` wanneer Dropbox de map nummerde naast de `Thesis` van een ander project. | `StateManager.mjs:14-16,148`, `PullManager.mjs:112-117` |

| Naam | Sleutels | Opties | Migratie |

CE heeft hier geen andere index. De unieke indexen `projectId_userId_1` en `userId_dropboxId_1` komen uit `tools/migrations/20220815105500_create_dropboxProjects_index.mjs` en `20220817120900_create_dropboxProjects_index.mjs`, die alleen de tag `saas` hebben, dus CE voert ze nooit uit.

#### Opmerkingen {#notes}

* Uniciteit komt alleen van het verwijderen vóór elke invoeging in `setProjectFolder` (`StateManager.mjs:140-149`). Het commentaar in `StateManager.mjs:3-11` noemt unieke indexen; CE heeft die niet.
* Wanneer de koppeling van een project wordt verwijderd, blijft de map in Dropbox staan. Een bewerking daar wordt dan gelezen als een nieuw project, net als bij een map die in Dropbox is gemaakt (`DropboxHandler.mjs:148-149`).
* Een verwijderd project houdt zijn koppeling tot het verloopt, omdat het nog kan worden hersteld (`index.mjs:52-53`).
* De Dropbox-cursor `list_folder` van de gebruiker staat hier niet. Die staat in `users.dropbox.cursor` (`StateManager.mjs:177-184`).
