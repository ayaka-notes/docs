`oauthApplications` bevat de OAuth-clients die web kent. Eén document is één client. In Ayakaleaf Pro schrijft alleen de webmodule `git-bridge` erin: die maakt bij het starten van web één client met de naam `Overleaf Git Bridge` aan. Het schema is `services/web/app/src/models/OauthApplication.mjs`.

#### Velden {#fields}

| Veld | Type | Betekenis | Bron |
| ----- | ---- | ------- | ------ |
| `_id` | ObjectId | Document-id van de client. `oauthAccessTokens.oauthApplication_id` en `oauthAuthorizationCodes.oauthApplication_id` verwijzen ernaar. | `OauthApplication.mjs:5` |
| `id` | String | Client-id: 64 willekeurige kleine letters en cijfers. | `OauthApplication.mjs:7`, `services/web/modules/git-bridge/index.mjs:25` |
| `clientSecret` | String | Clientgeheim, geschreven als `v1.` plus 32 willekeurige tekens. Alleen `getClient` leest het, en niets roept `getClient` aan (zie Opmerkingen). | `OauthApplication.mjs:8`, `git-bridge/index.mjs:26` |
| `grants` | Array of String | Granttypen. De git-bridge-client heeft `['password']`. Wordt met de client teruggegeven als een token wordt gecontroleerd (`services/web/modules/oauth2-server/app/src/OAuth2Model.mjs:67-72`). | `OauthApplication.mjs:9`, `git-bridge/index.mjs:27` |
| `name` | String | Naam van de client. De git-bridge-module en de code voor persoonlijke toegangstokens vinden de client via de naam `Overleaf Git Bridge`. | `OauthApplication.mjs:10`, `git-bridge/index.mjs:15-16,28` |
| `redirectUris` | Array of String | Toegestane redirect-URI's. `[]` voor de git-bridge-client. | `OauthApplication.mjs:11`, `git-bridge/index.mjs:29` |
| `scopes` | Array of String | Scopes die de client mag gebruiken. `['git_bridge']` voor de git-bridge-client. | `OauthApplication.mjs:12`, `git-bridge/index.mjs:30` |
| `pkceEnabled` | Boolean | Alleen in het schema: geen code in deze repository schrijft het, en alleen de ongebruikte `getClient` leest het (`OAuth2Model.mjs:207`). | `OauthApplication.mjs:13` |

#### Wie schrijft {#who-writes-it}

| Code | Wat het doet |
| ---- | ------------ |
| `git-bridge/index.mjs:9-35` (module `git-bridge`) | Als `GIT_BRIDGE_ENABLED` `true` is, maakt het bij het starten van web de client `Overleaf Git Bridge` aan als er nog geen client met die naam bestaat. |

#### Wie leest {#who-reads-it}

| Code | Wat het doet |
| ---- | ------------ |
| `services/web/modules/oauth2-server/app/src/OAuthPersonalAccessTokenManager.mjs:53-61` (module `oauth2-server`) | Vindt de client `Overleaf Git Bridge` op naam en slaat zijn `_id` op in elk nieuw persoonlijk toegangstoken. Zonder de client wordt geen token gemaakt. |
| `OAuth2Model.mjs:31-39,67-72` (`getAccessToken`) | Laadt de client van een token via `oauthApplication_id` en geeft zijn `id` en `grants` terug. |
| `OAuth2Model.mjs:185-209,241,275` (`getClient`, `saveToken`, `saveAuthorizationCode`) | Zoeken clients op `id`. Worden in deze repository nooit bereikt, zie Opmerkingen. |

#### Indexen {#indexes}

Alleen de standaardindex op `_id`. De unieke index `id_1` komt uit migraties met de tags `saas` (`20190912145016_create_oauthApplications_indexes.mjs`) en `server-pro` (`20230502180757_server_pro_oauth_indexes.mjs`), die Community Edition niet uitvoert.

#### Opmerkingen {#notes}

* Web gebruikt `@node-oauth/oauth2-server` alleen om bearer-tokens te controleren (`server.authenticate` in `services/web/app/src/Features/Authentication/AuthenticationController.mjs:409-450`), wat alleen `getAccessToken` en `verifyScope` van het model aanroept. Geen route bedient `/oauth/token` of `/oauth/authorize`, dus `getClient`, `saveToken` en `saveAuthorizationCode` worden nooit aangeroepen.
* De module zoekt de client op naam en maakt hem daarna aan, en Community Edition heeft geen unieke index op `name` of `id`. Niets voorkomt dus een tweede client met dezelfde naam. Code die de client nodig heeft, neemt de client die `findOne` teruggeeft.
