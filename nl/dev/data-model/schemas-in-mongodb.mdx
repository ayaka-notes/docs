In deze sectie bespreken we het datamodel van Overleaf. Overleaf gebruikt MongoDB voor gegevensopslag. De enige database heet `sharelatex`, wat ook de naam is van de voorganger van Overleaf.

De ontwikkelomgeving draait Mongo Express al naast Mongo (zie [setup-develop-tools.md](/nl/dev/environment/setup-develop-tools  "mention")). Open [http://localhost:8081/](http://localhost:8081/) en log in met `admin:pass`.

Je kunt ook vanuit de map `develop` een shell in de Mongo-container openen:

```bash
bin/docker-compose exec mongo mongosh sharelatex
```

#### Hoe de pagina's zijn opgebouwd {#how-the-pages-are-written}

* Elke pagina somt de velden op die de code schrijft, met type, betekenis en de coderegel die dat laat zien: een regel van een Mongoose-schema, of de plek die het veld schrijft. Velden die alleen een migratie, een script of een van de webmodules schrijft, vermelden dat.
* Veel collecties hebben geen Mongoose-schema: de services schrijven ze met de MongoDB-driver.
* Indexen worden alleen aangemaakt door de migraties in `tools/migrations/`. CE voert bij elke start de migraties met de tag `server-ce` uit (`server-ce/init_scripts/900_run_web_migrations.sh`); Mongoose `autoIndex` staat uit (`services/web/app/src/infrastructure/Mongoose.mjs:7`). De indextabellen tonen alleen wat een CE-instantie uiteindelijk heeft.
* De tekst van de docs staat in Mongo, maar andere inhoud niet. Bestandsinhoud wordt als blobs en de geschiedenis als chunks opgeslagen in de buckets van history-v1 (lokale mappen, of S3 / RustFS); geopende docs staan in Redis totdat document-updater ze flusht.
