title: Project-History-Sharded-Blobs-collectie

`projectHistoryShardedBlobs` bevat de blobrecords die niet in [projectHistoryBlobs](/dev/data-model/project-history-blobs-collection) pasten: als de bucket voor een hashprefix daar al 8 records heeft, gaan de volgende hierheen. Een project heeft er hoogstens 16 documenten in, één per eerste hexcijfer van de hash. Er is geen Mongoose-schema; history-v1 schrijft het in `services/history-v1/storage/lib/blob_store/mongo.js` (opbouw beschreven bij `mongo.js:1-16`).

#### Velden {#fields}

| Veld | Type | Betekenis | Bron |
| ----- | ---- | ------- | ------ |
| `_id` | Binary | 13 bytes: de geschiedenis-id van het project, een `0`, en het shardcijfer, gelezen als hex (`<history id>0<digit>`). Het shardcijfer is het eerste hexcijfer van de hash. | `mongo.js:439-453` |
| `blobs` | Object | Blobrecords gegroepeerd in buckets. De sleutel van een bucket zijn hexcijfers 2 tot en met 4 van de hash. | `mongo.js:439-443` |
| `blobs.<bcd>` | Array of Object | De records van de bucket. De code beperkt de grootte niet. | `mongo.js:399-407` |
| `blobs.<bcd>[].h` | Binary | De hash, 20 bytes, zoals in projectHistoryBlobs. | `mongo.js:472` |
| `blobs.<bcd>[].b` | Number | Lengte van de inhoud in bytes. | `mongo.js:473` |
| `blobs.<bcd>[].s` | Number | Lengte van de inhoud als tekst; `null` als de inhoud geen bewerkbare tekst is. | `mongo.js:474` |

#### Wie schrijft het {#who-writes-it}

| Code | Wat het doet |
| ---- | ------------ |
| `services/history-v1/storage/lib/blob_store/mongo.js:399-407` | `insertRecordSharded`: upsert met `$addToSet` in de bucket. Aangeroepen door `insertBlob` wanneer de bucket in projectHistoryBlobs vol is (`mongo.js:387-389`). |
| `mongo.js:75-103` | `clone`: kopieert de shards van het project naar een andere geschiedenis-id, voor history-v1 `POST /projects/:project_id/clone`, dat niets in web aanroept. |
| `mongo.js:413-422` | `deleteBlobs`: verwijdert alle shards van het project samen met zijn projectHistoryBlobs-document, bij history-v1 `DELETE /projects/:project_id`. |

#### Wie leest het {#who-reads-it}

| Code | Wat het doet |
| ---- | ------------ |
| `mongo.js:144-157` | `findBlobSharded`: één blob, alleen opgezocht wanneer de bucket in projectHistoryBlobs 8 records heeft en de blob er niet in zit (`mongo.js:127-131`). |
| `mongo.js:217-260` | `findBlobsSharded`: de blobs die `findBlobs` niet in projectHistoryBlobs vond (`mongo.js:202-206`). |
| `mongo.js:285-306` | `getProjectBlobs`: alle shards van een project. |
| `mongo.js:337-361` | `getProjectBlobsBatch`: alle shards van meerdere projecten, voor de route met blobstatistieken. |

#### Indexen {#indexes}

Alleen de standaardindex `_id`. Geen enkele migratie in `tools/migrations/` voegt er een toe.

#### Opmerkingen {#notes}

* De shards van één project liggen naast elkaar in `_id`-volgorde, dus de code vindt ze met een `_id`-bereik van `<history id>00` tot `<history id>0f` (`mongo.js:75-80`, `287-295`).
* De collectie verschijnt pas als een project meer dan 8 blobs met hetzelfde 3-cijferige hashprefix heeft, dus een kleine instantie heeft haar mogelijk helemaal niet.
