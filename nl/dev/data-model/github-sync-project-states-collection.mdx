`githubSyncProjectStates` bevat één document per project dat aan een GitHub-repository is gekoppeld: welke repository, en waar de laatste synchronisatie is gebleven. De collectie hoort bij de webmodule `github-sync` (`services/web/modules/github-sync`). Het schema staat in `services/web/modules/github-sync/app/models/githubSyncProjectStates.mjs`, en alle toegang loopt via `services/web/modules/github-sync/app/src/SyncStateManager.mjs`.

#### Wie schrijft {#who-writes-it}

| Code | Wat het doet |
| ---- | ------------ |
| `SyncStateManager.mjs:9-14` (`createProjectState`) | Maakt het document aan: na het importeren van een repository als nieuw project (`services/web/modules/github-sync/app/src/GitHubSyncHandler.mjs:175-181`), of na het exporteren van een project naar een nieuwe repository (`GitHubSyncHandler.mjs:235-241`, alleen eigenaar, geweigerd als het al gekoppeld is). |
| `SyncStateManager.mjs:16-21` (`updateProjectState`) | `$set` van de gewijzigde velden. `getMergeOverview` zet `mergeStatus: 'diverged'` als de gesynchroniseerde branch niet meer op `lastSyncCommit` voortbouwt: de compare van GitHub antwoordt `diverged` of `behind` (`GitHubApiClient.mjs:382-400`), of de commit is verdwenen en de gebruiker mag pushen (`GitHubSyncHandler.mjs:123,126-137`). Een synchronisatie (`services/web/modules/github-sync/app/src/GitMerge.mjs`) verplaatst bij succes `lastSyncCommit`/`lastSyncVersion` (bijvoorbeeld `:143,173,224`), legt een conflict vast met `unmergedBranchName`, `unmergedBranchHead` en `conflictVersion` (`:207-213`), en wist die zodra het is opgelost (`:250-257`). |
| `SyncStateManager.mjs:23-25` (`removeProjectState`) | Verwijdert het document als de eigenaar het project ontkoppelt (`GitHubSyncHandler.mjs:83-97`) en als een verwijderd project verloopt (`services/web/modules/github-sync/index.mjs:56-58`). |

#### Indexen {#indexes}

| Naam | Sleutels | Opties | Migratie |
| ---- | ---- | ------- | --------- |
| `_id_` | `_id: 1` | | default |

Mongoose `autoIndex` staat uit (`services/web/app/src/infrastructure/Mongoose.mjs:7`), dus de `unique: true` van het schema op `projectId` maakt niets aan. `tools/migrations/20190912145010_create_githubSyncProjectStates_indexes.mjs` (`project_id` en `owner_id` van upstream) heeft alleen de tag `saas` en draait niet in CE.

#### Opmerkingen {#notes}

* Een synchronisatie draait onder de `gitSync`-lock van het project (`GitMerge.mjs:17-24`). GitLab Sync en Gitea Sync nemen dezelfde lock, dus er draait per project maar één synchronisatie tegelijk.
* Een verwijderd project houdt zijn document tot het project verloopt.
* Het GitHub-token van de gebruiker staat in [GitHub Sync User Credentials](/nl/dev/data-model/github-sync-user-credentials-collection).
