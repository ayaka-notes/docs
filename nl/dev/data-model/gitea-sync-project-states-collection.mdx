`giteaSyncProjectStates` bevat één document per project dat aan een Gitea-repository is gekoppeld: welke repository, en waar de laatste synchronisatie is gebleven. De collectie hoort bij de webmodule `gitea-sync` (`services/web/modules/gitea-sync`). Het schema staat in `services/web/modules/gitea-sync/app/models/giteaSyncProjectStates.mjs`, en alle toegang loopt via `services/web/modules/gitea-sync/app/src/SyncStateManager.mjs`. De velden zijn dezelfde als in [GitHub Sync Project States](/nl/dev/data-model/github-sync-project-states-collection).

#### Wie schrijft {#who-writes-it}

| Code | Wat het doet |
| ---- | ------------ |
| `SyncStateManager.mjs:9-14` (`createProjectState`) | Maakt het document aan: na het importeren van een repository als nieuw project (`services/web/modules/gitea-sync/app/src/GiteaSyncHandler.mjs:175-181`), of na het exporteren van een project naar een nieuwe repository (`GiteaSyncHandler.mjs:233-239`, alleen eigenaar, geweigerd als het al gekoppeld is). |
| `SyncStateManager.mjs:16-21` (`updateProjectState`) | `$set` van de gewijzigde velden. `getMergeOverview` zet `mergeStatus: 'diverged'` als `lastSyncCommit` geen voorouder meer is van de gesynchroniseerde branch (`services/web/modules/gitea-sync/app/src/GiteaApiClient.mjs:431`), of de commit is verdwenen en de gebruiker mag pushen (`GiteaSyncHandler.mjs:123,126-137`). Een synchronisatie (`services/web/modules/gitea-sync/app/src/GitMerge.mjs`) verplaatst bij succes `lastSyncCommit`/`lastSyncVersion` (bijvoorbeeld `:152,189,231`), legt een conflict vast met `unmergedBranchName`, `unmergedBranchHead` en `conflictVersion` (`:214-220`), en wist die zodra het is opgelost (`:257-264`). |
| `SyncStateManager.mjs:23-25` (`removeProjectState`) | Verwijdert het document als de eigenaar het project ontkoppelt (`GiteaSyncHandler.mjs:83-97`) en als een verwijderd project verloopt (`services/web/modules/gitea-sync/index.mjs:46-48`). |

#### Indexen {#indexes}

| Naam | Sleutels | Opties | Migratie |
| ---- | ---- | ------- | --------- |
| `_id_` | `_id: 1` | | default |

Mongoose `autoIndex` staat uit (`services/web/app/src/infrastructure/Mongoose.mjs:7`), dus de `unique: true` van het schema op `projectId` maakt niets aan. Geen enkele migratie maakt indexen aan voor deze collectie.

#### Opmerkingen {#notes}

* De API van Gitea kan geen commits buiten een branch maken zoals die van GitHub. Een synchronisatie commit direct op de gesynchroniseerde branch als die vooruit kan, of anders op een tijdelijke branch die daarna via een pull request wordt samengevoegd (`GitMerge.mjs:16-21`).
* Een synchronisatie draait onder de `gitSync`-lock van het project, gedeeld met GitHub Sync en GitLab Sync (`GitMerge.mjs:25-32`).
* Een verwijderd project houdt zijn document tot het project verloopt.
* Het Gitea-token van de gebruiker staat in [Gitea Sync User Credentials](/nl/dev/data-model/gitea-sync-user-credentials-collection).
