title: GitLab Sync Project States-collectie
icon: code-merge

`gitlabSyncProjectStates` bevat één document per project dat aan een GitLab-project is gekoppeld: welke repository, en waar de laatste synchronisatie is gebleven. De collectie hoort bij de webmodule `gitlab-sync` (`services/web/modules/gitlab-sync`). Het schema staat in `services/web/modules/gitlab-sync/app/models/gitlabSyncProjectStates.mjs`, en alle toegang loopt via `services/web/modules/gitlab-sync/app/src/SyncStateManager.mjs`. De velden zijn dezelfde als in [GitHub Sync Project States](/nl/dev/data-model/github-sync-project-states-collection).

#### Wie schrijft {#who-writes-it}

| Code | Wat het doet |
| ---- | ------------ |
| `SyncStateManager.mjs:9-14` (`createProjectState`) | Maakt het document aan: na het importeren van een repository als nieuw project (`services/web/modules/gitlab-sync/app/src/GitLabSyncHandler.mjs:175-181`), of na het exporteren van een project naar een nieuwe repository (`GitLabSyncHandler.mjs:234-240`, alleen eigenaar, geweigerd als het al gekoppeld is). |
| `SyncStateManager.mjs:16-21` (`updateProjectState`) | `$set` van de gewijzigde velden. `getMergeOverview` zet `mergeStatus: 'diverged'` als de gesynchroniseerde branch `lastSyncCommit` niet meer bevat (merge-basecontrole, `services/web/modules/gitlab-sync/app/src/GitLabApiClient.mjs:460`), of de commit is verdwenen en de gebruiker mag pushen (`GitLabSyncHandler.mjs:123,126-137`). Een synchronisatie (`services/web/modules/gitlab-sync/app/src/GitMerge.mjs`) verplaatst bij succes `lastSyncCommit`/`lastSyncVersion` (bijvoorbeeld `:152,189,231`), legt een conflict vast met `unmergedBranchName`, `unmergedBranchHead` en `conflictVersion` (`:214-220`), en wist die zodra het is opgelost (`:257-264`). |
| `SyncStateManager.mjs:23-25` (`removeProjectState`) | Verwijdert het document als de eigenaar het project ontkoppelt (`GitLabSyncHandler.mjs:83-97`) en als een verwijderd project verloopt (`services/web/modules/gitlab-sync/index.mjs:46-48`). |

#### Wie leest {#who-reads-it}

| Code | Wat het doet |
| ---- | ------------ |
| `GitLabSyncHandler.mjs:39-60` (`getProjectState`) | Geeft de editor `mergeStatus`, `repoFullName` en `unmergedBranchName`. Zonder document antwoordt het `need-export`, een waarde die nooit wordt opgeslagen. |
| `GitLabSyncHandler.mjs:110-143` (`getMergeOverview`) | Vergelijkt `lastSyncCommit` en `lastSyncVersion` met GitLab en de projectgeschiedenis om de nieuwe commits op te sommen. |

| `GitMerge.mjs:36` (`doGitMergeWithoutLock`) | Laadt de status aan het begin van een synchronisatie. |

#### Indexen {#indexes}

| Naam | Sleutels | Opties | Migratie |
| ---- | ---- | ------- | --------- |
| `_id_` | `_id: 1` | | default |

Mongoose `autoIndex` staat uit (`services/web/app/src/infrastructure/Mongoose.mjs:7`), dus de `unique: true` van het schema op `projectId` maakt niets aan. Geen enkele migratie maakt indexen aan voor deze collectie.

#### Opmerkingen {#notes}

* De API van GitLab kan een branch niet naar een willekeurige commit verplaatsen zoals die van GitHub. Een synchronisatie commit direct op de gesynchroniseerde branch als die vooruit kan, of anders op een tijdelijke branch die daarna via een merge request wordt samengevoegd (`GitMerge.mjs:16-21`).
* Een synchronisatie draait onder de `gitSync`-lock van het project, gedeeld met GitHub Sync en Gitea Sync (`GitMerge.mjs:25-32`).
* Een verwijderd project houdt zijn document tot het project verloopt.
* Het GitLab-token van de gebruiker staat in [GitLab Sync User Credentials](/nl/dev/data-model/gitlab-sync-user-credentials-collection).
