## Aanbevolen ontwikkeltools {#develop-tools-recommended}

Deze optionele services zijn niet nodig om Overleaf te draaien, maar helpen veel bij het ontwikkelen, debuggen en onderzoeken van de gegevens. Ze maken allemaal deel uit van de ontwikkelomgeving, dus er hoeft niets aan `docker-compose.yml` te worden toegevoegd. Zodra je bent ingelogd op de site, linkt het menu **Dev tools** in de navigatiebalk naar de tools die de site op eigen paden aanbiedt.

| Tool | Adres | Gedefinieerd in |
| --- | --- | --- |
| **Grafana**, de status, metrics en logs van elke service | [http://localhost/grafana/](http://localhost/grafana/) | `develop/grafana/docker-compose.yml`, aan bij `GRAFANA_ENABLED=true` in `develop/dev.rc` (standaard) |
| **Mailpit**, een inbox voor elke e-mail die de site verstuurt | [http://localhost/mailpit/](http://localhost/mailpit/) | `develop/mail/docker-compose.yml`, aan bij `MAILPIT_ENABLED=true` (standaard) |
| **Mongo Express**, een UI voor MongoDB | [http://localhost/mongo-express/](http://localhost/mongo-express/) | `develop/docker-compose.yml`, altijd aan |
| **RedisInsight**, een UI voor de Redis-gegevens | [http://localhost/redis-insight/](http://localhost/redis-insight/) | `develop/docker-compose.yml`, altijd aan |
| **Hoppscotch**, een API-client in de browser, vergelijkbaar met Postman | [http://localhost:9170](http://localhost:9170/) (`HOPPSCOTCH_PORT`) | `develop/hoppscotch/docker-compose.yml`, aan bij `HOPPSCOTCH_ENABLED=true` (standaard) |

<Warning>

Geen van deze tools heeft een login: de anonieme gebruikers van Grafana zijn de beheerders, en Mongo Express kan elk document wijzigen. De site, Hoppscotch, Mongo Express (8081) en RedisInsight (5540) luisteren alleen op `127.0.0.1` van de host, dus andere hosts kunnen ze niet bereiken.

</Warning>

### Grafana {#grafana}

Grafana wordt door de site aangeboden op `/grafana/`, via webpack-dev-server, en heeft dus geen eigen poort nodig. De map **Overleaf Develop** bevat deze dashboards:

| Dashboard | Wat het toont |
| --- | --- |
| All services (start) | Status van elke service, hostmeters, belasting en logs. Een klik op een service opent het dashboard ervan |
| Server | CPU, belasting, geheugen, schijf en netwerk van de host, en de compilaties van clsi |
| Errors | Foutlogs, 5xx- en 4xx-antwoorden, meest voorkomende foutmeldingen en falende routes |
| Data flow | Het pad van een bewerking: document-updater en Redis, project-history, history-v1, Mongo, objectopslag |
| Containers | Status van elke container, CPU, geheugen, netwerk en schijf, inclusief sandbox-compilaties |
| Eén per service | De Node.js-services, git-bridge (JVM), mongo en redis |

Prometheus haalt `/metrics` op van de services, `mongodb-exporter`, `redis-exporter`, `cadvisor` en `node-exporter`; Alloy stuurt de logs van elke container van het project naar Loki, waar de filters **Log search**, **Service** en **Log level** van de dashboards ze lezen. Hun gegevens staan alleen in de containers, dus opnieuw aanmaken maakt ze leeg. cAdvisor draait geprivilegieerd en leest `/`, `/sys`, de Docker-gegevens en de containerd-socket van de host, alleen-lezen; node-exporter leest `/` van de host.

De dashboards worden gegenereerd: wijzig `develop/grafana/make-dashboards` en voer het uit, in plaats van de JSON-bestanden te bewerken.

### Mailpit {#mailpit}

Met `MAILPIT_ENABLED=true` stuurt `web` elke e-mail naar Mailpit in plaats van naar een echte mailserver, en staat e-mailbevestiging aan (`EMAIL_CONFIRMATION_DISABLED=false`). Activatielinks, projectuitnodigingen, wachtwoordresets en bevestigingscodes kun je dan vanuit de inbox volgen.

### Hoppscotch instellen {#setup-hoppscotch}

#### API-verzoeken via proxy {#proxy-api-request}

Hoppscotch verstuurt verzoeken vanuit de browser, die de services niet via hun Docker-namen kan bereiken. De proxy, Proxyscotch, draait binnen het Docker-netwerk en wordt aangeboden op `/proxy` van het Hoppscotch-adres. Open [http://localhost:9170](http://localhost:9170/), ga naar Settings → Interceptor, kies **Proxy** en stel de Proxy URL in op `http://localhost:9170/proxy`. De instelling blijft in de browser bewaard.

#### De service-API's importeren {#import-the-service-apis}

`develop/hoppscotch/openapi/` bevat een OpenAPI-bestand voor de interne API van elke service. Open in Hoppscotch Collections → Import → Import from File en selecteer alle bestanden tegelijk. Elk bestand wordt een collectie waarvan de verzoeken naar het Docker-adres van de service gaan. Dezelfde bestanden worden getoond in de sectie [Service-API](/nl/dev/service-api/overview).

#### CSRF-problemen {#csrf-problems}

<Warning>

Als je Postman of andere debugtools gebruikt om een **POST**-verzoek te versturen, kan het gebeuren dat het inloggen **geweigerd** wordt, met een 403-fout als gevolg. Dat komt doordat Overleaf beveiligd is met **CSRF**-verificatie.

</Warning>

<Frame>
  <img src="/images/dev/image-8.png" alt="" />
</Frame>

In je console zie je mogelijk:

<Frame>
  <img src="/images/dev/image-9.png" alt="" />

Om dit tijdens je Overleaf-ontwikkeling op te lossen, moet je je CSRF-token instellen. Hieronder volgt een gedetailleerde handleiding.

<Steps>
<Step title="Pre-request toevoegen">
Voeg de volgende code toe aan Pre-Request

<Frame>
  <img src="/images/dev/image-10.png" alt="" />
</Frame>

Het script ziet er als volgt uit:

```js wrap
pm.sendRequest("http://web:3000/dev/csrf", function (err, res) {
    if (err) {
        console.log(err);
        return;
    }

    // 1) Save CSRF token (/dev/csrf)
    const token = res.text().trim();
    pw.env.set("csrftoken", token);
    console.log("csrftoken =", token);

    const setCookieHeader = (res.headers || []).find(h => h.key?.toLowerCase() === "set-cookie")?.value;
    console.log("set-cookie =", setCookieHeader);

    if (!setCookieHeader) return;

    const cookiePair = setCookieHeader.split(";")[0].trim(); // overleaf.sid=...
    pw.env.set("cookie_header", cookiePair);
    console.log("cookie_header =", cookiePair);
});
```
</Step>

<Step title="Request-headers toevoegen">
Je moet de volgende headers toevoegen:

| Headernaam   | Headerwaarde        |
| ------------ | ------------------- |
| Content-Type | `application/json`  |
| X-Csrf-Token | `<<csrftoken>>`     |
| Cookie       | `<<cookie_header>>` |

<Frame>
  <img src="/images/dev/image-11.png" alt="" />
</Frame>
</Step>

Nu kun je inloggen met je gebruikersnaam en wachtwoord.

```json5

}
```
