このセクションでは、Overleaf のデータモデルについて説明します。Overleaf はデータの永続化に MongoDB を使用しており、唯一のデータベース名は `sharelatex` です。これは Overleaf の前身の名前でもあります。

開発環境では、Mongo と並んで Mongo Express がすでに動いています（[setup-develop-tools.md](/ja/dev/environment/setup-develop-tools  "mention") を参照）。[http://localhost:8081/](http://localhost:8081/) を開き、`admin:pass` でログインしてください。

`develop` ディレクトリから Mongo コンテナーのシェルを開くこともできます。

```bash
bin/docker-compose exec mongo mongosh sharelatex
```

#### 各ページの書き方 {#how-the-pages-are-written}

* 各ページには、コードが書き込むフィールドを、型、意味、それを示すコード行（Mongoose スキーマの行、またはフィールドを書き込む箇所）とともに記載しています。マイグレーション、スクリプト、または web モジュールのいずれかだけが書き込むフィールドにはその旨を記しています。
* 多くのコレクションには Mongoose スキーマがなく、サービスが MongoDB ドライバーで書き込みます。
* インデックスは `tools/migrations/` のマイグレーションだけが作成します。CE は起動のたびに `server-ce` タグの付いたものを実行し（`server-ce/init_scripts/900_run_web_migrations.sh`）、Mongoose の `autoIndex` は無効です（`services/web/app/src/infrastructure/Mongoose.mjs:7`）。インデックスの表には、CE インスタンスが最終的に持つものだけを記載しています。
* doc のテキストは Mongo にありますが、それ以外の内容はありません。ファイルの内容は blob として、履歴はチャンクとして history-v1 のバケット（ローカルフォルダー、または S3 / RustFS）に保存されます。開いている doc は、document-updater がフラッシュするまで Redis にあります。
