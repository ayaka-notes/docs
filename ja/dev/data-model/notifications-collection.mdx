`notifications` は、ユーザーのプロジェクトダッシュボード上部に表示されるお知らせを保持します。1 つのドキュメントは 1 人のユーザーへの 1 件のお知らせで、`key` で識別されます。コレクションを直接扱うのは `notifications` サービスだけです（`services/notifications/app/js/Notifications.js`）。`web` と `third-party-datastore` はその HTTP API を呼び出します。Mongoose スキーマはありません。

#### フィールド {#fields}

| フィールド | 型 | 意味 | 出典 |
| --- | --- | --- | --- |
| `_id` | ObjectId | お知らせ id。`web` はこの id でお知らせを既読にします。 | `Notifications.js:58-65` |
| `user_id` | ObjectId | お知らせを見るユーザー。 | `Notifications.js:26` |
| `key` | String | お知らせを識別します。例: `project-invite-<inviteId>`。upsert により `user_id` と `key` ごとに 1 つのドキュメントが保たれます。一意インデックスはありません。 | `Notifications.js:27`, `:51-55` |
| `templateKey` | String | フロントエンドがどのお知らせを描画するか。お知らせが既読または閉じられると削除されますが、ドキュメントは残ります。 | `Notifications.js:29`, `:63`, `:72`, `:78` |
| `messageOpts` | Object | お知らせの文面に使う値で、`templateKey` によって異なります（プロジェクト招待では `userName`、`projectName`、`projectId`、`token`）。ユーザーが id でお知らせを閉じると削除されます。 | `Notifications.js:28`, `:63` |
| `expires` | Date | 任意。この日時を過ぎると TTL インデックスがドキュメントを削除します。 | `Notifications.js:35-50` |

#### 補足 {#notes}

* 既読のお知らせは削除されず、`templateKey` だけが消えます。ドキュメントにはキーが残るため、後で同じキーに対して `forceCreate` なしで `addNotification` を呼んでも何も起きません（`Notifications.js:21-24`）。
* `/key/:key` ルートはユーザーを問わず、キーだけを対象に動作します（`Notifications.js:76-100`）。
* `web` に `apis.notifications.url` がない場合、お知らせの作成も読み取りも行いません（`NotificationsHandler.mjs:17`、`:41`）。
