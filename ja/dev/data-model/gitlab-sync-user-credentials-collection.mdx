---
title: GitLab Sync User Credentials コレクション
icon: user-lock
---

`gitlabSyncUserCredentials` は、GitLab Sync のために GitLab アカウントをリンクしたユーザーごとに 1 つのドキュメントを保持します。 ユーザーの OAuth トークンを暗号化して保存します。 このコレクションは `gitlab-sync` Web モジュール（`services/web/modules/gitlab-sync`）に属します。スキーマは `services/web/modules/gitlab-sync/app/models/gitlabSyncUserCredentials.mjs` にあり、すべてのアクセスは `services/web/modules/gitlab-sync/app/src/TokenManager.mjs` を経由します。

#### フィールド {#fields}

| フィールド | 型 | 意味 | 出典 |
| ----- | ---- | ------- | ------ |
| `_id` | ObjectId | upsert が挿入するときに Mongoose が設定します。 | |
| `userId` | ObjectId | Overleaf ユーザー。必須。スキーマには `unique: true` とありますが、インデックスは作成されません（「インデックス」を参照）。`userId` による upsert でユーザーごとに 1 つのドキュメントが保たれます。 | `gitlabSyncUserCredentials.mjs:8`, `TokenManager.mjs:88-95` |
| `gitlab` | String | JSON `{ accessToken, refreshToken, expiresAt }`。`@overleaf/access-token-encryptor` で暗号化されます。`expiresAt` はエポックからのミリ秒、または `null` で、`refreshToken` は `null` の場合があります。パスワードは `GITLAB_TOKEN_CIPHER_PASSWORD` から取得し、暗号ラベルは `GITLAB_TOKEN_CIPHER_LABEL`（デフォルト `2026.10-v3`）です。必須。 | `gitlabSyncUserCredentials.mjs:9-10`, `TokenManager.mjs:18-31`, `services/web/modules/gitlab-sync/app/src/GitLabApiClient.mjs:209-220` |
| `__v` | Number | Mongoose のバージョンキー。スキーマでは無効化されていません。 | Mongoose のデフォルト |

#### 書き込み元 {#who-writes-it}

| コード | 処理内容 |
| ---- | ------------ |
| `TokenManager.mjs:88-95` (`saveUserToken`) | ユーザーの暗号化された認証情報を upsert します。 |
| `TokenManager.mjs:99-108` (`linkUserToken`) | OAuth コールバックで得た新しい認証情報を保存します（`services/web/modules/gitlab-sync/app/src/GitLabSyncController.mjs:146`）。ユーザーが再度リンクすると、置き換えられたアクセストークンはバックグラウンドで GitLab 上で取り消されます。 |
| `TokenManager.mjs:53-78` (`refreshUserToken`) | アクセストークンが `expiresAt` まで 5 分未満になると（`:13,47-49`）、リフレッシュトークンで新しいトークンを取得して保存します（`:75`）。GitLab はリフレッシュトークンを使うと消費するため、ユーザーごとのロック `gitlabSyncToken` の下で実行されます（`:15,54`）。 |
| `TokenManager.mjs:111-126` (`removeUserToken`) | GitLab でアクセストークンを取り消し（ベストエフォート）、その後ドキュメントを削除します。リンク解除時（`GitLabSyncController.mjs:173`）と、削除済みユーザーが期限切れになったとき（`services/web/modules/gitlab-sync/index.mjs:56-58`）に呼び出されます。 |

#### 読み取り元 {#who-reads-it}

| コード | 処理内容 |
| ---- | ------------ |
| `TokenManager.mjs:41-45,81-85` (`getUserCredentials`, `getUserToken`) | GitLab API を呼び出すたびに認証情報を復号し、トークンの期限が近い場合は先に更新します: `services/web/modules/gitlab-sync/app/src/GitLabSyncHandler.mjs`（例: `:27`）と `services/web/modules/gitlab-sync/app/src/GitMerge.mjs:52`。ドキュメントがない場合や、復号または更新できない認証情報の場合は `InvalidTokenError` をスローし、ユーザーはリンクされていないものとして扱われます（`GitLabSyncHandler.mjs:25-37`）。 |
| `services/web/modules/admin-tools/app/src/AdminUserListManager.mjs:394` | 管理パネルに表示する連携のために、ユーザーがドキュメントを持っているかを確認します。 |

#### インデックス {#indexes}

| 名前 | キー | オプション | マイグレーション |
| ---- | ---- | ------- | --------- |
| `_id_` | `_id: 1` | | default |

Mongoose の `autoIndex` は無効（`services/web/app/src/infrastructure/Mongoose.mjs:7`）なので、スキーマの `userId` にある `unique: true` は何も作成しません。 このコレクションのインデックスを作成するマイグレーションはありません。

#### 補足 {#notes}

* `GITLAB_TOKEN_CIPHER_PASSWORD` を変更すると、保存済みの認証情報が読めなくなります。それらのユーザーは、再度リンクするまでリンクされていないものとして扱われます。
* 削除済みユーザーは、期限切れになるまでドキュメントを保持します。
