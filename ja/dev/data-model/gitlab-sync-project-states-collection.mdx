---
title: GitLab Sync Project States コレクション
icon: code-merge
---

`gitlabSyncProjectStates` は、GitLab プロジェクトにリンクされたプロジェクトごとに 1 つのドキュメントを保持します。どのリポジトリか、そして前回の同期がどこまで進んだかを記録します。 このコレクションは `gitlab-sync` Web モジュール（`services/web/modules/gitlab-sync`）に属します。スキーマは `services/web/modules/gitlab-sync/app/models/gitlabSyncProjectStates.mjs` にあり、すべてのアクセスは `services/web/modules/gitlab-sync/app/src/SyncStateManager.mjs` を経由します。 フィールドは [GitHub Sync Project States](/ja/dev/data-model/github-sync-project-states-collection) と同じです。

#### フィールド {#fields}

| フィールド | 型 | 意味 | 出典 |
| ----- | ---- | ------- | ------ |
| `_id` | ObjectId | 作成時に Mongoose が設定します。 | |
| `projectId` | ObjectId | リンクされたプロジェクト。必須。スキーマには `unique: true` とありますが、インデックスは作成されません（「インデックス」を参照）。 | `gitlabSyncProjectStates.mjs:8` |
| `repoFullName` | String | 名前空間付きの GitLab プロジェクトパス（GitLab の `path_with_namespace`）。例: `group/subgroup/name`。必須。 | `gitlabSyncProjectStates.mjs:9`, `GitLabApiClient.mjs:347` |
| `defaultBranchName` | String | プロジェクトが同期するブランチ。プロジェクトのリンク時に設定され、その後は変更されません。インポート時はインポートフォームから送られたブランチ、エクスポート時は新しいリポジトリのデフォルトブランチで、API が返さない場合は `main` です。デフォルトは `null`。 | `gitlabSyncProjectStates.mjs:10`, `GitLabSyncHandler.mjs:175-181,234-240`, `GitLabApiClient.mjs:346-349` |
| `mergeStatus` | String | `clean`、`conflict`、`diverged` のいずれか。デフォルトは `clean`。 | `gitlabSyncProjectStates.mjs:11` |

| `conflictVersion` | Number | コンフリクト中: コンフリクトが記録された時点のプロジェクト履歴のバージョン。デフォルトは `null`。 | `gitlabSyncProjectStates.mjs:16` |
| `__v` | Number | Mongoose のバージョンキー。スキーマでは無効化されていません。 | Mongoose のデフォルト |

#### 書き込み元 {#who-writes-it}

| コード | 処理内容 |
| ---- | ------------ |
| `SyncStateManager.mjs:9-14` (`createProjectState`) | ドキュメントを作成します。リポジトリを新しいプロジェクトとしてインポートした後（`services/web/modules/gitlab-sync/app/src/GitLabSyncHandler.mjs:175-181`）、またはプロジェクトを新しいリポジトリにエクスポートした後（`GitLabSyncHandler.mjs:234-240`、オーナーのみ、すでにリンク済みの場合は拒否）です。 |
| `SyncStateManager.mjs:16-21` (`updateProjectState`) | 変更されたフィールドを `$set` します。同期対象ブランチに `lastSyncCommit` が含まれなくなった場合（マージベースのチェック、`services/web/modules/gitlab-sync/app/src/GitLabApiClient.mjs:460`）、またはコミットが消えていてユーザーがプッシュできる場合（`GitLabSyncHandler.mjs:123,126-137`）、`getMergeOverview` は `mergeStatus: 'diverged'` を設定します。 同期（`services/web/modules/gitlab-sync/app/src/GitMerge.mjs`）は、成功すると `lastSyncCommit`/`lastSyncVersion` を進め（例: `:152,189,231`）、コンフリクトを `unmergedBranchName`、`unmergedBranchHead`、`conflictVersion` で記録し（`:214-220`）、解決後にそれらをクリアします（`:257-264`）。 |
| `SyncStateManager.mjs:23-25` (`removeProjectState`) | オーナーがプロジェクトのリンクを解除したとき（`GitLabSyncHandler.mjs:83-97`）と、削除済みプロジェクトが期限切れになったとき（`services/web/modules/gitlab-sync/index.mjs:46-48`）にドキュメントを削除します。 |

#### 読み取り元 {#who-reads-it}

| コード | 処理内容 |
| ---- | ------------ |
| `GitLabSyncHandler.mjs:39-60` (`getProjectState`) | エディターに `mergeStatus`、`repoFullName`、`unmergedBranchName` を返します。ドキュメントがない場合は `need-export` を返しますが、この値は保存されません。 |
| `GitLabSyncHandler.mjs:110-143` (`getMergeOverview`) | `lastSyncCommit` と `lastSyncVersion` を GitLab およびプロジェクト履歴と比較し、新しいコミットを一覧にします。 |
| `GitLabSyncHandler.mjs:200` (`exportProject`) | すでにリンクされているプロジェクトのエクスポートを拒否します。 |
| `GitMerge.mjs:36` (`doGitMergeWithoutLock`) | 同期の開始時に状態を読み込みます。 |

#### インデックス {#indexes}

| 名前 | キー | オプション | マイグレーション |
| ---- | ---- | ------- | --------- |
| `_id_` | `_id: 1` | | default |

Mongoose の `autoIndex` は無効（`services/web/app/src/infrastructure/Mongoose.mjs:7`）なので、スキーマの `projectId` にある `unique: true` は何も作成しません。 このコレクションのインデックスを作成するマイグレーションはありません。

#### 補足 {#notes}

* GitLab の API では、GitHub のようにブランチを任意のコミットに移動できません。同期は、前進できる場合は同期対象ブランチに直接コミットし、そうでない場合は一時ブランチにコミットしてからマージリクエストでマージします（`GitMerge.mjs:16-21`）。
* 同期はプロジェクトの `gitSync` ロックの下で実行され、このロックは GitHub Sync および Gitea Sync と共有されます（`GitMerge.mjs:25-32`）。
* 削除済みプロジェクトは、期限切れになるまでドキュメントを保持します。
* ユーザーの GitLab トークンは [GitLab Sync User Credentials](/ja/dev/data-model/gitlab-sync-user-credentials-collection) にあります。
