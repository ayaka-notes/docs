---
title: Gitea Sync User Credentials コレクション
icon: lock
---

`giteaSyncUserCredentials` は、Gitea Sync のために Gitea アカウントをリンクしたユーザーごとに 1 つのドキュメントを保持します。 ユーザーの OAuth トークンを暗号化して保存します。 このコレクションは `gitea-sync` Web モジュール（`services/web/modules/gitea-sync`）に属します。スキーマは `services/web/modules/gitea-sync/app/models/giteaSyncUserCredentials.mjs` にあり、すべてのアクセスは `services/web/modules/gitea-sync/app/src/TokenManager.mjs` を経由します。

#### フィールド {#fields}

| フィールド | 型 | 意味 | 出典 |
| ----- | ---- | ------- | ------ |
| `_id` | ObjectId | upsert が挿入するときに Mongoose が設定します。 | |
| `userId` | ObjectId | Overleaf ユーザー。必須。スキーマには `unique: true` とありますが、インデックスは作成されません（「インデックス」を参照）。`userId` による upsert でユーザーごとに 1 つのドキュメントが保たれます。 | `giteaSyncUserCredentials.mjs:8`, `TokenManager.mjs:89-96` |
| `gitea` | String | JSON `{ accessToken, refreshToken, expiresAt }`。`@overleaf/access-token-encryptor` で暗号化されます。`expiresAt` はエポックからのミリ秒、または `null` で、`refreshToken` は `null` の場合があります。パスワードは `GITEA_TOKEN_CIPHER_PASSWORD` から取得し、暗号ラベルは `GITEA_TOKEN_CIPHER_LABEL`（デフォルト `2026.10-v3`）です。必須。 | `giteaSyncUserCredentials.mjs:9-10`, `TokenManager.mjs:17-30`, `services/web/modules/gitea-sync/app/src/GiteaApiClient.mjs:198-209` |
| `__v` | Number | Mongoose のバージョンキー。スキーマでは無効化されていません。 | Mongoose のデフォルト |

#### 書き込み元 {#who-writes-it}

| コード | 処理内容 |
| ---- | ------------ |
| `TokenManager.mjs:89-96` (`saveUserToken`) | ユーザーの暗号化された認証情報を upsert します。OAuth コールバックから呼び出されます（`services/web/modules/gitea-sync/app/src/GiteaSyncController.mjs:146`）。GitLab Sync と異なり、再度リンクしても置き換えられたトークンは取り消されません。 |
| `TokenManager.mjs:53-79` (`refreshUserToken`) | アクセストークンが `expiresAt` まで 5 分未満になると（`:12`）、リフレッシュトークンで新しいトークンを取得して保存します（`:76`）。Gitea はリフレッシュトークンを使うと置き換えるため、ユーザーごとのロック `giteaSyncToken` の下で実行されます（`:14,54`）。 |
| `TokenManager.mjs:100-102` (`removeUserToken`) | ドキュメントを削除します。Gitea には OAuth トークンを取り消す API がないため、ユーザーが Gitea で許可を取り消します（`:98-99`）。リンク解除時（`GiteaSyncController.mjs:173`）と、削除済みユーザーが期限切れになったとき（`services/web/modules/gitea-sync/index.mjs:56-58`）に呼び出されます。 |

#### 読み取り元 {#who-reads-it}

| コード | 処理内容 |
| ---- | ------------ |
| `TokenManager.mjs:40-44,82-86` (`getUserCredentials`, `getUserToken`) | Gitea API を呼び出すたびに認証情報を復号し、トークンの期限が近い場合は先に更新します: `services/web/modules/gitea-sync/app/src/GiteaSyncHandler.mjs`（例: `:27`）と `services/web/modules/gitea-sync/app/src/GitMerge.mjs:52`。ドキュメントがない場合や、復号または更新できない認証情報の場合は `InvalidTokenError` をスローし、ユーザーはリンクされていないものとして扱われます（`GiteaSyncHandler.mjs:25-37`）。 |
| `services/web/modules/admin-tools/app/src/AdminUserListManager.mjs:395` | 管理パネルに表示する連携のために、ユーザーがドキュメントを持っているかを確認します。 |

#### インデックス {#indexes}

| 名前 | キー | オプション | マイグレーション |
| ---- | ---- | ------- | --------- |
| `_id_` | `_id: 1` | | default |

Mongoose の `autoIndex` は無効（`services/web/app/src/infrastructure/Mongoose.mjs:7`）なので、スキーマの `userId` にある `unique: true` は何も作成しません。 このコレクションのインデックスを作成するマイグレーションはありません。

#### 補足 {#notes}

* `GITEA_TOKEN_CIPHER_PASSWORD` を変更すると、保存済みの認証情報が読めなくなります。それらのユーザーは、再度リンクするまでリンクされていないものとして扱われます。
* 削除済みユーザーは、期限切れになるまでドキュメントを保持します。
