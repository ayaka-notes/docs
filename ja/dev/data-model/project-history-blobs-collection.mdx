---
title: Project History Blobs コレクション
icon: cubes
---

`projectHistoryBlobs` にはプロジェクト履歴ごとに 1 つのドキュメントがあり、history-v1 がそのプロジェクト用に保存したすべての blob のメタデータ（ハッシュとサイズ）を保持します。blob は、ファイルまたは doc の履歴のある時点での内容です。バイト列そのものはプロジェクト blob バケット内のオブジェクトです。Mongoose スキーマはありません。history-v1 が `services/history-v1/storage/lib/blob_store/mongo.js` でコレクションに書き込み、CE と同様に 16 進数 24 文字の履歴 id にこれを使います（`services/history-v1/storage/lib/blob_store/index.js:108-116`）。

#### フィールド {#fields}

| フィールド | 型 | 意味 | 出典 |
| ----- | ---- | ------- | ------ |
| `_id` | ObjectId | プロジェクトの履歴 id。`projects.overleaf.history.id` の値です。 | `mongo.js:37-40` |
| `blobs` | Object | バケットごとにまとめた blob レコード。バケットのキーはハッシュの先頭 16 進数 3 桁です。 | `mongo.js:39`, `429-431` |
| `blobs.<abc>` | Array of Object | ハッシュが `abc` で始まる最大 8 件のレコード。バケットにすでに 8 件ある場合、次のレコードは [Project History Sharded Blobs コレクション](/ja/dev/data-model/project-history-sharded-blobs-collection) に入ります。 | `mongo.js:23`, `375-389` |
| `blobs.<abc>[].h` | Binary | ハッシュ、20 バイト：git blob の SHA-1、`sha1("blob " + byteLength + "\0" + content)`（`libraries/overleaf-editor-core/lib/blob_utils.js:36-43`）。その 16 進表記が他の場所で使われるハッシュで、たとえばプロジェクトの `fileRefs.hash` です。 | `mongo.js:472` |
| `blobs.<abc>[].b` | Number | 内容のバイト長。 | `mongo.js:473` |
| `blobs.<abc>[].s` | Number | テキストとしての内容の長さ。内容が編集可能なテキストでない場合（バイナリ、または編集するには大きすぎる場合）は `null` です（`blob_utils.js:116-130`）。 | `mongo.js:474` |

#### 書き込み元 {#who-writes-it}

| コード | 処理内容 |
| ---- | ------------ |
| `services/history-v1/storage/lib/blob_store/mongo.js:34-47` | `initialize`：history-v1 がプロジェクト履歴を作成するときに `{ _id, blobs: {} }` を挿入します（`services/history-v1/storage/lib/chunk_store/index.js:67-68`）。 |
| `mongo.js:370-390` | `insertBlob`：バケットのレコードが 8 件未満の間はレコードをそのバケットに `$addToSet` し、それ以外はシャードコレクションに入れます。バイト列のアップロード後に、`putString`、`putBlob`、`copyBlob` から実行されます（`blob_store/index.js:223-237`, `271-278`, `456-467`）。 |
| `mongo.js:54-105` | `clone`：history-v1 の `POST /projects/:project_id/clone` のために、バケットを別の履歴 id にコピーします。web にはこのルートを呼ぶものはありません（[Project History Chunks コレクション](/ja/dev/data-model/project-history-chunks-collection) を参照）。 |
| `mongo.js:413-422` | `deleteBlobs`：history-v1 の `DELETE /projects/:project_id` で、ドキュメントとプロジェクトのシャードドキュメントを削除します（`services/history-v1/api/controllers/projects.js:361-373`）。 |

新しい blob の出どころ：

* ファイルのアップロード：web がファイルを history-v1 の `PUT /projects/:project_id/blobs/:hash` に送ります（`services/web/app/src/Features/History/HistoryManager.mjs:164-169`, `services/history-v1/api/controllers/projects.js:376-402`）。
* プロジェクトのコピー：web が history-v1 に `POST /projects/:project_id/blobs/:hash?copyFrom=` で各ファイルの blob のコピーを依頼します（`services/web/app/src/Features/Project/ProjectDuplicator.mjs:333-338`, `HistoryManager.mjs:177-187`, `projects.js:521-555`）。
* doc のテキスト：history-v1 がチャンクを書き込むとき、各 doc のテキストと、そのコメントおよび変更履歴（JSON）を blob として保存します（`chunk_store/index.js:402-405`, `libraries/overleaf-editor-core/lib/file_data/string_file_data.js:166-173`）。

#### 読み取り元 {#who-reads-it}

| コード | 処理内容 |
| ---- | ------------ |
| `mongo.js:113-157` | `findBlob`：ハッシュで blob を 1 つ取得します。バケットが満杯ならシャードコレクションを探します。`BlobStore.getBlob`（`blob_store/index.js:376-387`）が blob ルート（`projects.js:416-480`）のために使い、挿入前には既存の blob をスキップするために使います（`blob_store/index.js:441-448`）。 |
| `mongo.js:165-260` | `findBlobs`：チャンクのファイルを読み込むため、多数の blob を一度に取得します。 |
| `mongo.js:265-309` | `getProjectBlobs`：プロジェクトのすべての blob。 |
| `mongo.js:316-363` | `getProjectBlobsBatch`：history-v1 の `POST /projects/blob-stats`（`projects.js:620`）のために、複数プロジェクトのすべての blob を取得します。admin-tools モジュールは結果をプロジェクトサイズとして表示します（`services/web/modules/admin-tools/app/src/AdminProjectManager.mjs:395-405`）。 |

#### インデックス {#indexes}

デフォルトの `_id` インデックスのみです。`tools/migrations/` のマイグレーションでインデックスを追加するものはありません。

#### 補足 {#notes}

* blob のバイト列は、バケット `OVERLEAF_EDITOR_PROJECT_BLOBS_BUCKET`（`services/history-v1/config/custom-environment-variables.json:49-52`）内のキー `<project key>/<hash[0:2]>/<hash[2:]>`（`blob_store/index.js:51-53`）にあります。プロジェクトキーは、ゼロ埋めした履歴 id を反転し、3/3/残りの文字に分割したものです（`libraries/object-persistor/src/ProjectKey.js:8-15`）。
* blob はプロジェクトごとに 1 回だけ保存されます。プロジェクトがすでに持つハッシュの挿入はスキップされます（`blob_store/index.js:227-230`, `249-252`）。
* 空の内容にはレコードが不要です。`getBlob` は検索なしで応答します（`blob_store/index.js:378-380`）。
* `projectHistoryGlobalBlobs` は起動時に読み込まれます（`blob_store/index.js:138-148`）が、CE のコードは書き込まないため、CE ではすべての blob がプロジェクト blob です。
