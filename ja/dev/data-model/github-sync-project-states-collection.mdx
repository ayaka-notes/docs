title: GitHub Sync Project States コレクション
icon: code-branch

`githubSyncProjectStates` は、GitHub リポジトリにリンクされたプロジェクトごとに 1 つのドキュメントを保持します。どのリポジトリか、そして前回の同期がどこまで進んだかを記録します。 このコレクションは `github-sync` Web モジュール（`services/web/modules/github-sync`）に属します。スキーマは `services/web/modules/github-sync/app/models/githubSyncProjectStates.mjs` にあり、すべてのアクセスは `services/web/modules/github-sync/app/src/SyncStateManager.mjs` を経由します。

#### フィールド {#fields}

| フィールド | 型 | 意味 | 出典 |
| ----- | ---- | ------- | ------ |
| `_id` | ObjectId | 作成時に Mongoose が設定します。 | |
| `projectId` | ObjectId | リンクされたプロジェクト。必須。スキーマには `unique: true` とありますが、インデックスは作成されません（「インデックス」を参照）。 | `githubSyncProjectStates.mjs:8` |
| `repoFullName` | String | `owner/name` 形式のリポジトリ（GitHub の `full_name`）。必須。 | `githubSyncProjectStates.mjs:9` |
| `defaultBranchName` | String | プロジェクトが同期するブランチ。プロジェクトのリンク時に設定され、その後は変更されません。インポート時はインポートフォームから送られたブランチ、エクスポート時は新しいリポジトリのデフォルトブランチです。デフォルトは `null`。 | `githubSyncProjectStates.mjs:10`, `GitHubSyncHandler.mjs:175-181,235-241` |
| `mergeStatus` | String | `clean`、`conflict`、`diverged` のいずれか。デフォルトは `clean`。 | `githubSyncProjectStates.mjs:11` |

#### 書き込み元 {#who-writes-it}

| コード | 処理内容 |
| ---- | ------------ |
| `SyncStateManager.mjs:9-14` (`createProjectState`) | ドキュメントを作成します。リポジトリを新しいプロジェクトとしてインポートした後（`services/web/modules/github-sync/app/src/GitHubSyncHandler.mjs:175-181`）、またはプロジェクトを新しいリポジトリにエクスポートした後（`GitHubSyncHandler.mjs:235-241`、オーナーのみ、すでにリンク済みの場合は拒否）です。 |
| `SyncStateManager.mjs:16-21` (`updateProjectState`) | 変更されたフィールドを `$set` します。同期対象ブランチが `lastSyncCommit` を基点としなくなったとき、`getMergeOverview` は `mergeStatus: 'diverged'` を設定します。GitHub の compare が `diverged` または `behind` を返した場合（`GitHubApiClient.mjs:382-400`）、またはコミットが消えていてユーザーがプッシュできる場合（`GitHubSyncHandler.mjs:123,126-137`）です。 同期（`services/web/modules/github-sync/app/src/GitMerge.mjs`）は、成功すると `lastSyncCommit`/`lastSyncVersion` を進め（例: `:143,173,224`）、コンフリクトを `unmergedBranchName`、`unmergedBranchHead`、`conflictVersion` で記録し（`:207-213`）、解決後にそれらをクリアします（`:250-257`）。 |
| `SyncStateManager.mjs:23-25` (`removeProjectState`) | オーナーがプロジェクトのリンクを解除したとき（`GitHubSyncHandler.mjs:83-97`）と、削除済みプロジェクトが期限切れになったとき（`services/web/modules/github-sync/index.mjs:56-58`）にドキュメントを削除します。 |

#### 読み取り元 {#who-reads-it}

| コード | 処理内容 |
| ---- | ------------ |
| `GitHubSyncHandler.mjs:39-60` (`getProjectState`) | エディターに `mergeStatus`、`repoFullName`、`unmergedBranchName` を返します。ドキュメントがない場合は `need-export` を返しますが、この値は保存されません。 |
| `GitHubSyncHandler.mjs:110-143` (`getMergeOverview`) | `lastSyncCommit` と `lastSyncVersion` を GitHub およびプロジェクト履歴と比較し、新しいコミットを一覧にします。 |
| `GitHubSyncHandler.mjs:200` (`exportProject`) | すでにリンクされているプロジェクトのエクスポートを拒否します。 |
| `GitMerge.mjs:27` (`doGitMergeWithoutLock`) | 同期の開始時に状態を読み込みます。 |

#### インデックス {#indexes}

| 名前 | キー | オプション | マイグレーション |
| ---- | ---- | ------- | --------- |
| `_id_` | `_id: 1` | | default |

Mongoose の `autoIndex` は無効（`services/web/app/src/infrastructure/Mongoose.mjs:7`）なので、スキーマの `projectId` にある `unique: true` は何も作成しません。 `tools/migrations/20190912145010_create_githubSyncProjectStates_indexes.mjs`（upstream の `project_id` と `owner_id`）は `saas` タグのみが付いており、CE では実行されません。

#### 補足 {#notes}

* 同期はプロジェクトの `gitSync` ロックの下で実行されます（`GitMerge.mjs:17-24`）。GitLab Sync と Gitea Sync も同じロックを取るため、1 つのプロジェクトで同時に実行される同期は 1 つだけです。
* 削除済みプロジェクトは、期限切れになるまでドキュメントを保持します。
* ユーザーの GitHub トークンは [GitHub Sync User Credentials](/ja/dev/data-model/github-sync-user-credentials-collection) にあります。
