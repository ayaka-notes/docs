### Docker

Docker は、アプリケーションを分離されたコンテナにパッケージ化して実行するための、軽量でポータブルな方法を提供します。アプリケーションと必要なすべての依存関係をまとめることで、コンテナはノート PC から本番サーバーまで、異なるマシン間で一貫した動作を保証します。

TeX Live は強力ですが、サイズが大きく、システムレベルの違いの影響を受けやすいものです。TeX Live を Docker イメージにパッケージ化することで、LaTeX ツールチェーンを予測可能かつ再現可能にし、配布も容易になります。

ただし、一部の TeX Live パッケージはシェルへのアクセスに依存しています。セキュリティ上の理由から、コンテナは、ユーザーが任意のシェルコマンドを実行できない（たとえば `\write18` やシェルエスケープ経由で）制限された環境で実行する必要があります。この分離によってホストシステムが保護され、コンテナの基盤となるファイルシステムや `bash` などのツールへの意図しないアクセスを防ぐことができます。

### TeXLive Full エディション

[TeXLive-Full@ayaka-notes](https://github.com/ayaka-notes/texlive-full/) は、[Ayakaleaf Pro](https://github.com/ayaka-notes/ayakaleaf-pro)、[Overleaf CEP](https://github.com/yu-i-i/overleaf-cep)、またはスタンドアロンの LaTeX コンパイル環境でのサンドボックス化された LaTeX コンパイル向けに設計された、フル機能の **TeXLive Docker イメージ**です。

このイメージは、不足しているパッケージやフォントが原因のコンパイル失敗を最小限に抑えるため、一般的なフォントやツールをプリインストールした、ほぼ完全な TeXLive ディストリビューションを提供することを目指しています。注意: この Docker イメージには sharelatex/overleaf のコンポーネントは**一切含まれていません**。Overleaf/Overleaf Pro のコンパイルに使用されるものです。

#### 特徴:

* 🚀 x86\_64 と arm64 の両方のサーバーアーキテクチャに対応
* 📦 完全かつ最適化された TeXLive のインストール
* 🧩 一般的なフォントとユーティリティをプリインストール
* 🐳 Docker および Docker Compose ですぐに使用可能
* 🧪 Overleaf Server Pro / Overleaf Pro で動作確認済み
* 🔄 最新の TeXLive リリースに合わせて定期的に更新
* 🏷 複数の TeXLive バージョンタグ（2020 – 最新）
* 🧑‍🔬 LaTeX 文書内の R コードに対する Knitr サポート

### Ayakaleaf Pro での使い方

Ayaka-notes による TeX Live Full は [ayakaleaf-pro](https://github.com/ayaka-notes/ayakaleaf-pro) 向けに特別に設計されています。[Toolkit ユーザー](https://github.com/overleaf/toolkit)の場合は、`config/variables.env` ファイルに次の環境変数を設定できます。

例:

```dotenv title="config/variables.env" wrap
ALL_TEX_LIVE_DOCKER_IMAGES=ghcr.io/ayaka-notes/texlive-full:2026.1, ghcr.io/ayaka-notes/texlive-full:2025.1
ALL_TEX_LIVE_DOCKER_IMAGE_NAMES=Texlive 2026, Texlive 2025
TEX_LIVE_DOCKER_IMAGE=ghcr.io/ayaka-notes/texlive-full:2026.1
```

### TeX Live のバージョン

GitHub Action のおかげで、すべての TeX イメージを並列でビルドできます。対象は次のとおりです。

* `ghcr.io/ayaka-notes/texlive-full:2026.1`（`latest` タグも付与）
* `ghcr.io/ayaka-notes/texlive-full:2025.1`
* `ghcr.io/ayaka-notes/texlive-full:2024.1`
* `ghcr.io/ayaka-notes/texlive-full:2023.1`
* `ghcr.io/ayaka-notes/texlive-full:2022.1`
* `ghcr.io/ayaka-notes/texlive-full:2021.1`
* `ghcr.io/ayaka-notes/texlive-full:2020.1`
* `ghcr.io/ayaka-notes/texlive-full:base`

[texlive info](https://texlive.info/tlnet-archive/) のミラーアーカイブを使用しており、1996 年から 2025 年までのほぼすべての TeX Live イメージが含まれています。また、Overleaf の Dockerfile のおかげで、このプロジェクトをより速くビルドできます。

> TeX Live 2019 以前がサポートされていないのはなぜですか？
>
> これらの古いイメージを保守するのは非常に困難です。また、[texlive.info](https://texlive.info/) のウェブサイトでは 2019 年より前にリリースされた TeX Live バージョンの情報が提供されていないため、それらのバージョンのイメージをビルドできません。特定の古いバージョンが必要な場合は、issue を作成してお知らせください。

### 含まれるコンポーネント

Docker イメージには次のパッケージが含まれています。

* すべての TeXLive パッケージ（その年のもの）
* R パッケージ（一部のみ）
* fontconfig inkscape pandoc python3-pygments wget python3
* gnupg gnuplot perl-modules perl ca-certificates
* ghostscript qpdf r-base-core tar

Docker イメージには次のフォントが含まれています。

* [Google Fonts](https://fonts.google.com/)
* [Microsoft msttcorefonts](https://packages.ubuntu.com/jammy/ttf-mscorefonts-installer)
* [Overleaf でサポートされているフォント](https://www.overleaf.com/learn/latex/Questions/Which_OTF_or_TTF_fonts_are_supported_via_fontspec%3F)

<Warning>

該当するフォントが商用利用可能かどうかを必ず確認してください。フォントの誤った使用によって生じたいかなる法的問題についても、私たちは**一切責任を負いません**。イメージをダウンロードした時点で、これに自動的に同意したものとみなされます。

</Warning>

### 問題

<Accordion title="問題 01: フォントキャッシュミスの問題">

Overleaf が LaTeX プロジェクトをコンパイルする際にフォントが見つからないと、**コンパイル処理に長い時間がかかる**ことがあります。これは、フォントが見つからない場合に TeX Live が**フォントキャッシュ全体を再構築**しようとするためで、時間のかかる処理です。

私たちのイメージではフォントキャッシュを事前に構築しており、[このコミット](https://github.com/ayaka-notes/texlive-full/commit/0cb66b0dc8b82be628cf6999cfd659d9784e132f)でこの問題を修正しています。

</Accordion>

<Accordion title="問題 02: SyncTeX が非常に遅い">

このイメージを sharelatex で使用すると、SyncTeX が非常に遅くなることがあります。

[https://github.com/overleaf/overleaf/issues/1150](https://github.com/overleaf/overleaf/issues/1150) を参照してください。HTTP 2.0 を無効にするだけで解決します。

</Accordion>

<Accordion title="問題 03: 公式 TeX Live イメージでの再コンパイルエラー">

Docker Hub の公式 TeX Live イメージ `texlive/texlive` を使用すると、プロジェクトを再コンパイルした際にエラーが報告されることがあります。私たちのイメージでは、この問題は修正されています。最新の Ubuntu ベースイメージを使用し、すべての依存関係を Ubuntu の公式リポジトリからインストールしているためです。

</Accordion>

### その他の技術的な注意点

TeX Live イメージ（2019 年より前）をビルドする際は、次の問題に注意が必要な場合があります。

* TeX Live 2017 より前は `http`/`ftp` のみがサポートされているため、`peal` スクリプトを変更しない限り `https` でダウンロードすることはできません。
* 2015 年より前は sha256 ファイルのみが提供されているため、sha512 でチェックすることはできません。
