ここでは、変更点、切り替える前に確認すべきこと、そして最もよく発生する新しいエラーの修正方法を紹介します。このリリースで最も注目すべき更新は、アクセシブルな PDF を生成する機能がプロトタイプの段階を卒業し、本番のワークフローで使用できるようになったことです。この更新では、新規および更新された TeX 関連のプログラム、フォント、マクロパッケージも利用できるようになります。このブログ記事では、知っておくべき重要な情報と主な変更点をすべて取り上げます。

Overleaf は、すべてが期待どおりに動作することを確認するための厳格なテストを経て、年に 1 回公式アップデートをリリースしています。これは、数百万人の Overleaf ユーザーに一貫した安定したエクスペリエンスを提供し、サポートチームが問題や質問に対応できるようにするためです。

### TeX Live とは？

[TeX Live](https://tug.org/texlive/) は TeX 組版システムの無料ディストリビューションで、LaTeX をはじめとする多数の TeX 関連プログラム、フォント、マクロパッケージを含んでおり、TeX ユーザーの中核グループと [TeX User Group](https://tug.org/) によって保守されています。Overleaf はコンパイルサーバー上で TeX Live を使用して、プレビューを表示し、プロジェクトの PDF を生成しています。

TeX Live 2026 の導入により、読み上げ可能な数式を含む、完全にアクセシブルなタグ付き PDF を作成できるようになります。

### 既存のプロジェクトはこれまでどおり動作しますか？

はい。既存のプロジェクトは、作成時の TeX Live バージョンを引き続き使用するため、これまでどおり動作します。必要な場合を除き、既存のプロジェクトで TeX Live のバージョンを変更することはおすすめしません。変更すると、新たなエラーや警告が発生する可能性があります。

**注意：** Overleaf のギャラリーにあるテンプレートの中には、アクセシビリティオプションを有効にすると動作しない、またはコンパイルできないものがある場合があります。ほとんどのテンプレートは Overleaf が作成・保守しているものではないため、問題がある場合は作成者にお問い合わせください。

### 既存のプロジェクトを TeX Live 2026 に切り替えることはできますか？

はい。既存のプロジェクトを TeX Live 2026 に簡単に切り替えることができ、移行は手軽で面倒もありません。変更したいプロジェクトで _Settings_ を開き、サイドバーの _Compiler_ をクリックすると、TeX Live のバージョンを選択するドロップダウンが表示されます。これにより、投稿のコンパイルに特定の TeX Live バージョンを使用する出版社、プレプリントサーバー、その他のプラットフォームの要件に合わせて、プロジェクトをすばやく更新できます。

TeX Live 2025（またはそれ以前のバージョン）では問題なくコンパイルできていたプロジェクトが TeX Live 2026 でエラーになる場合、カーネルや一部のパッケージの変更が原因である可能性があります。一部のパッケージは TeX Live 2026 で新たなエラーや警告を発生させることが知られています。最もよくあるものとその修正方法を、以下の別のセクションにまとめました。

### TeX Live 2026 の主な変更点

#### タグ付きのアクセシブルな PDF がプロトタイプの段階を脱却

LaTeX Project の [2025 年 11 月のアップデート](https://www.latex-project.org/news/latex2e-news/ltnews42.pdf) 以降、タグ付けはもはやプロトタイプとは位置付けられておらず、ドキュメントがタグ付けにすでに対応しているパッケージとクラスのみを使用している限り、本番のワークフローで使用できるものとみなされています。

タグ付き PDF の出力を有効にするには、`\documentclass` の前にコマンドを 1 つ記述するだけです。

```latex
\DocumentMetadata{
 pdfstandard = {UA-2, A-4f},
 tagging = on,
 lang = en
 }
\documentclass{article}
```

`\DocumentMetadata` を使用すると、いくつかのデフォルト設定も有効になります：T1 フォントエンコーディング、そして [2025 年 6 月以降](https://www.latex-project.org/news/latex2e-news/ltnews41.pdf) は、旧来の 1.7 ではなく **PDF 2.0** での出力です。PDF 2.0 が重要なのは、MathML によるタグ付け（数式をラベルのない記号の羅列ではなく、スクリーンリーダーで読み上げ可能にする仕組み）を可能にするためです。

実用上の注意点をいくつか挙げます。

* 下書き中は `tagging = draft` を設定すると、アクセシビリティの警告を維持したまま構造ツリーの書き出しを省略できます（長いドキュメントのコンパイルを高速化するのに便利です）。
* check-tagging-status キーを使用すると、使用しているパッケージがタグ付けに対応していることが確認済みかどうかがログの最後に報告されます。作業を始める前に確認できる [ライブステータスデータベース](https://latex3.github.io/tagging-project/tagging-status/) もあります。
* タグ付けのコードなしで PDF 管理の機能だけを使いたい場合は、そのための独立した `pdfmanagement` パッケージが新たに用意されています。

特に注意すべき変更点が 1 つあります：`\DocumentMetadata` は 1 つのドキュメント内で 1 回しか呼び出せなくなりました。2 回目の呼び出しは、`\documentclass` を 2 回記述した場合と同様にコンパイルエラーになります。

#### 意味を伴うアクセシブルな数式

[2025 年 11 月から新たに](https://www.latex-project.org/news/latex2e-news/ltnews42.pdf)、`\MathMLintent` と `\MathMLarg` により、著者は表記がどのように構成されているかだけでなく、それが何を意味するのかを支援技術に伝えられるようになりました。たとえば、`|y|` を _「bar y bar」_ ではなく _「y の絶対値」_ と読み上げられるようになります。

アクセシブルな数式のタグ付けには、MathML を生成するエンジンである LuaLaTeX でコンパイルし、`unicode-math` または `lua-unicode-math` パッケージのいずれかを使用する必要があります。

#### グラフィックや図にも意味を持たせられるように

アクセシビリティはテキストと数式に限りません。`\includegraphics`、`picture`、`tikzpicture` がアクセシビリティ用のキーを受け付けるようになったため、各グラフィックに適切なマークアップを付けられます。

```latex
\includegraphics[alt={A bar chart of quarterly revenue}]{revenue}
```

グラフィックは 4 つの方法で分類できます：実際に説明的な役割を持つ図、支援ツールが無視すべき装飾的なアーティファクト、記号の代わりとなるもの、または通常のテキスト（`todonotes` などに便利です）。TikZ の出力は標準でサポートされています。

#### タグ付きのアクセシブルなプレゼンテーションを作成するための新しいクラス

`beamer` ドキュメントクラスは、LaTeX でプレゼンテーションのスライドを作成するために非常に広く使われています。残念ながら、これは LaTeX のタグ付けコードと互換性がありません。その代わりに、新しいドキュメントクラス [`ltx-talk`](https://ctan.org/pkg/ltx-talk) がゼロから作成されました。その構文は `beamer` とほぼ同様ですが、`beamer` のすべての機能が `ltx-talk` に実装されているわけではありません。

#### セクション見出しのスタイル設定のための新しいテンプレート機構

セクション見出しのコマンドが、新しいテンプレート機構によって LaTeX カーネル内で再実装されました。これにより、`titlesec` などのパッケージが LaTeX のタグ付けコードと完全には互換性がないという問題が解決されています。簡単な例を示します。

```latex
\EditInstance{heading}{section}{
  number-format=\fbox{\LARGE\bfseries\theheading},
  title-decls=\Large\bfseries\sffamily\color{blue},
  before-vspace=20pt,
}
```

詳しい情報は [ドキュメント](https://tug.ctan.org/macros/latex-dev/required/latex-lab/latex-lab-sec-template.pdf) を参照してください。

#### 内部から再構築されたカーネル

今年のカーネルでは、いくつかの制限が取り除かれました。

* **出力ルーチンが設定可能に：** 40 年近くにわたり、LaTeX のページ組み立ての仕組みは事実上ハードコードされており、それを変更する必要があるパッケージは内部コードを上書きせざるを得ませんでした。現在は、変更を行うためのフックとソケットが公開されています。これにより、パッケージはより安定し、互いに競合しにくくなります。
* **モダンなマーク機構：** 互いに絡み合った 2 つのマークしかサポートしていなかった旧来の `\markboth` / `\leftmark` / `\rightmark` の仕組みが、任意の数の独立したマークをサポートする柔軟なシステムの上に再構築されました。おなじみのコマンドはこれまでとまったく同じように動作します。
* **ブロック環境とセクション見出しがテンプレートで動作するように：** リスト、引用、定理型の環境、そして新たに見出しコマンドが、一貫した共通の基盤システムを共有するようになりました。実用上の利点の 1 つとして、LaTeX は `enumitem` や `amsthm` の `\newtheoremstyle` といった人気パッケージをネイティブにエミュレートし始めており、`titlesec` のエミュレーションも進行中です。リストや定理ボックスのスタイルを変えるためだけにパッケージをインストールする必要が少なくなります。
* **定理型の環境における相互参照の改善：** 新しい `\newcounteralias` コマンドにより、定理とカウンターを共有する補題を `cleveref`、`zref-clever`、`hyperref` で参照した場合に、_「theorem 1」_ ではなく正しく _「lemma 1」_ と表示されるようになりました。

ドキュメントだけでなくパッケージも保守している場合は、注意すべき変更点が 2 つあります：カーネルが正式に **2023-11-27 以降の日付の `expl3`** を必要とするようになったこと、そして _「fake math」_（ボックスの配置のためだけに数式モードを使用すること）が `\textsuperscript`、`\parbox`/`minipage` などの構文や表形式の構造の周辺から削除されたことです。これにより、タグ付けと右から左に書くテキストのサポートが改善されますが、`\showoutput` の結果を古い TeX Live バージョンと比較すると違いに気付くでしょう。

#### 対応範囲の拡大：より多くの言語

* ベンガル語、グジャラート語、カンナダ語、マラヤーラム語、シンハラ語、タミル語、テルグ語を含む **ブラーフミー系文字の索引作成** が、`upmendex` で実験的にサポートされました。
* 新しい **BCP 47 言語メタデータ** キー（`language`、`other-languages`）により、ドキュメントの言語を地域的なバリエーションまで正確に宣言できるようになりました。これは PDF 自体の言語メタデータにも反映されます。

#### その他の注意点

* `enumerate`、`theorem`、`verbatim` パッケージはレガシーとみなされるようになりました。新しいドキュメントでは、それぞれ `enumitem`、`amsthm`、`fancyvrb` を使用することをおすすめします。
* 古い PDF バージョンを前提とする印刷ワークフローやプラットフォームを使用している場合でも、PDF バージョンを自分で設定できます（例：`\DocumentMetadata{pdfversion=1.7}`）。また、TeX Live 2026 のドキュメントでは、以前のデフォルトを対象としたドキュメントのコンパイル方法も解説されています。
* TeX Live 2026 の [公式リリースノート](https://tug.org/texlive/doc/texlive-en/texlive-en.html#news) および [すべての TeX Live バージョンのリリースノート](https://www.tug.org/texlive/doc/texlive-en/texlive-en.html#x1-710009) は、TeX Users Group（TUG）のウェブサイトで確認できます。

### TeX Live 2026 の影響を受ける主なパッケージ

以下のセクションでは、TeX Live 2025 では正常にコンパイルできていたプロジェクトが、TeX Live 2026 ではコンパイルエラーになる原因となる変更点をいくつか取り上げます。

#### サポートされなくなった表関連のパッケージ

LaTeX カーネルにおける表形式の構造の新たな変更により、`tabu` と `tabls` パッケージは TL2026 ではサポートされなくなり、コンパイルエラーの原因となります。`arydshln` パッケージも、`tabularx` や `tabular*` 環境など、他のパッケージと互換性がない場合があります。同様に、`\@array` や `\tabular` を再定義するパッケージやテンプレートも、表形式の構造の周辺でコンパイルエラーを引き起こします。

#### `babel` の廃止された言語オプション

`frenchb` と `francais` の言語オプションは廃止されました。これらは `french` に置き換える必要があります。

#### `varioref` のバグ

[`varioref` パッケージのバグ](https://github.com/latex3/latex2e/issues/2112#issuecomment-4881772493) により、KOMA-Script のドキュメントクラスでこのパッケージを読み込むと TeX capacity exceeded エラーが発生し、PDF が生成されません。

```text
\documentclass{scrartcl}
\usepackage{varioref}
\begin{document}
Hello World!
\end{document}
```

回避策として、プリアンブルに

```text
\def\extrasenglish{}
```

を追加します。

#### KOMA-script クラスと `capt-of`

KOMA-script のドキュメントクラス（`scrbook`、`scrartcl`、`scrreport`、`scrletter`）が `\captionof` を定義するようになったため、`capt-of` パッケージは読み込まないようにしてください（一方、`caption` パッケージはこれらのドキュメントクラスでも引き続き安全に読み込めます）。

#### `thmtools`：`sibling`/`numberlike`/`sharenumber` のエラー

`thmtools` のオプション `sibling`（または `numberlike`、`sharenumber`）を使用して新しい定理型の環境を宣言すると、`Command \c@proposal already defined` のような [カウンターがすでに定義されているというエラー](https://github.com/muzimuzhi/thmtools/issues/75) が発生します。

```text
\documentclass{article}
\usepackage{thmtools}
\declaretheorem{theorem}
\declaretheorem{proposal}[sibling=theorem]

\begin{document}

\begin{theorem}This is a theorem.\end{theorem}
\begin{proposal}This is a proposal.\end{proposal}

\end{document}
```

回避策として、プリアンブルの `thmtools` を読み込んだ後、`\declaretheorem` の前に次の行を追加します。

```text
\makeatletter
\@ifundefined{newcounteralias}{}{%
  \renewcommand\thmt@autorefsetup{\@xa\def\csname\thmt@envname autorefname\@xa\endcsname\@xa{\thmt@thmname}}%
}
\makeatother
```

#### `polyglossia`、`xepersian`、`array`

アラビア文字の組版に `polyglossia` または `xepersian` パッケージを使用しており、`array` パッケージ、または `array` を読み込む他の表関連のパッケージを読み込んでいる場合、表形式の構造の中にアラビア語のテキストを配置すると、`\UseMathForPositioningText` が定義されていないというエラーが発生します。

```text
\documentclass[12pt,a4paper]{article}
\usepackage{polyglossia}
\usepackage{array}
\setdefaultlanguage{arabic}
\newfontfamily\arabicfont[Script=Arabic]{Noto Naskh Arabic}
\begin{document}
\begin{tabular}{c}
السلام عليكم
\end{tabular}
\end{document}
```

これは、`\documentclass` の宣言の前に `\DocumentMetadata{}` を追加することで解決できます。または、アラビア文字の組版に `babel` パッケージへの切り替えを検討してください。

#### `babel-spanish` と `biblatex-apa`

`biblatex` のスタイル `apa` を使用している状態で `babel-spanish` を読み込むと、フックと `\@makecaption` に関するコンパイルエラーが発生します。

```text
\usepackage[spanish]{babel}
\usepackage[style=apa]{biblatex}
```

ただし、`babel` にオプション `shorthands=off` を追加することでエラーを回避できます。

#### `xgreek`、`hyperref`、`\appendix`

`xgreek`（XeLaTeX と LuaLaTeX 専用）と `hyperref` パッケージを読み込むと、`\appendix` の後に現れるセクション見出しでコンパイルエラーが発生します。

```text
\documentclass{article}
\usepackage{xgreek}
\usepackage{fontspec}
\setmainfont{GFS Artemisia}
\usepackage{hyperref}
\begin{document}
\section{Εισαγωγή}
\appendix
\section{Δεδομένα}
\end{document}
```

修正方法は、`hyperref` にオプション `hypertexnames=false` を追加することです。

#### `flowfram` と `titlesec`

現時点では、`flowfram` と `titlesec` パッケージは互いに互換性がありません。ただし、新しい `\EditInstance` インターフェースを使用してセクション見出しのスタイルを設定することを検討できます。例：

```text
\DocumentMetadata{}
\documentclass{article}
\usepackage{flowfram}
\usepackage[dvipsnames]{xcolor}
\EditInstance{heading}{section}{
  number-format=\fbox{\LARGE\bfseries\theheading},
  title-decls=\Large\bfseries\sffamily\color{NavyBlue}
}
\begin{document}
\section{Introduction}
\end{document}
```

詳しくは [こちらのリンク](https://mirrors.ctan.org/macros/latex-dev/required/latex-lab/latex-lab-sec-template.pdf) を参照してください。

### Ayakaleaf Pro における TeX Live 2026

Ayakaleaf Pro の管理者は、通常どおり設定を更新することで TeX Live 2026 をインストールできます。`TEX_LIVE_DOCKER_IMAGE`（および `ALL_TEX_LIVE_DOCKER_IMAGES`）を新しい TeX Live 2026 イメージに向けるだけです。その他のアップグレードは必要ありません。
