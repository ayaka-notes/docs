ここでは、変更点、切り替える前に確認すべきこと、そしてよくある新しいエラーの修正方法を紹介します。今回のリリースで最も注目すべき更新は、アクセシブルな PDF を生成する機能がプロトタイプの段階を卒業し、本番のワークフローで使用できるようになったことです。また、このアップデートにより、新しく追加・更新された TeX 関連のプログラム、フォント、マクロパッケージも利用できるようになります。このブログ記事では、知っておくべき重要な情報と主な変更点をすべて取り上げます。

Overleaf は、すべてが期待どおりに動作することを確認するための厳格なテストを経て、年に 1 回公式アップデートをリリースしています。これは、数百万人の Overleaf ユーザーに一貫した安定した体験を提供し、サポートチームが問題や質問に対応できるようにするためです。

### TeX Live とは？

[TeX Live](https://tug.org/texlive/) は TeX 組版システムの無料ディストリビューションで、LaTeX を含む多数の TeX 関連プログラム、フォント、マクロパッケージが含まれています。TeX ユーザーの中心グループと [TeX User Group](https://tug.org/) によって保守されています。Overleaf はコンパイルサーバーで TeX Live を使用し、プレビューの表示とプロジェクトの PDF の生成を行っています。

TeX Live 2026 の導入により、読み上げ可能な数式を含む、完全にアクセシブルなタグ付き PDF を作成できるようになります。

### 既存のプロジェクトはこれまでどおり動作しますか？

はい。既存のプロジェクトは、作成時の TeX Live バージョンを引き続き使用するため、これまでどおり動作します。必要な場合を除き、既存のプロジェクトで TeX Live のバージョンを変更しないことをおすすめします。変更すると、新しいエラーや警告が発生する可能性があります。

<strong>注意:</strong> Overleaf ギャラリーのテンプレートの中には、アクセシビリティオプションを有効にすると動作しない、またはコンパイルできないものがある可能性があります。ほとんどのテンプレートは Overleaf が作成・保守しているものではないため、問題がある場合は作成者にお問い合わせください。

### 既存のプロジェクトで TeX Live 2026 に切り替えられますか？

はい。既存のプロジェクトでも簡単に TeX Live 2026 に切り替えられます。移行はシンプルで手間がかかりません。変更したいプロジェクトで _Settings_ を開き、サイドバーの _Compiler_ をクリックすると、TeX Live のバージョンを選択するドロップダウンが表示されます。これにより、特定の TeX Live バージョンで投稿をコンパイルする出版社、プレプリントサーバー、その他のプラットフォームの要件に合わせて、プロジェクトをすばやく更新できます。

TeX Live 2025（またはそれ以前のバージョン）では問題なくコンパイルできていたプロジェクトが TeX Live 2026 でエラーになる場合、カーネルや一部のパッケージの変更が原因である可能性があります。一部のパッケージは TeX Live 2026 で新しいエラーや警告を出すことが知られています。よくあるものとその修正方法を、以下の別セクションにまとめました。

### TeX Live 2026 の主な変更点

#### タグ付きのアクセシブルな PDF がプロトタイプ段階を卒業

LaTeX Project の [2025 年 11 月のアップデート](https://www.latex-project.org/news/latex2e-news/ltnews42.pdf) 以降、タグ付けはもはやプロトタイプとは位置付けられておらず、ドキュメントがタグ付けにすでに対応しているパッケージやクラスのみを使用している限り、本番のワークフローで使用可能とみなされています。

タグ付き PDF の出力を有効にするには、`\documentclass` の前に 1 つのコマンドを置くだけです。

```latex
\DocumentMetadata{
 pdfstandard = {UA-2, A-4f},
 tagging = on,
 lang = en
 }
\documentclass{article}
```

`\DocumentMetadata` を使用すると、いくつかのデフォルト設定も有効になります。T1 フォントエンコーディング、そして [2025 年 6 月以降](https://www.latex-project.org/news/latex2e-news/ltnews41.pdf) は、従来の 1.7 ではなく **PDF 2.0** での出力です。ここで PDF 2.0 が重要なのは、MathML タグ付け（数式をラベルのない記号の羅列ではなく、スクリーンリーダーで読み上げ可能にする仕組み）を可能にするのが PDF 2.0 だからです。

実用上の注意点をいくつか挙げます。

* 下書き中は `tagging = draft` を設定すると、アクセシビリティの警告は維持しつつ、構造ツリーの書き出しをスキップできます（長いドキュメントのコンパイルを高速化するのに便利です）。
* check-tagging-status キーを使うと、使用しているパッケージがタグ付けに対応していることが確認されているかどうかが、ログの末尾に報告されます。作業を始める前に確認できる [ライブステータスデータベース](https://latex3.github.io/tagging-project/tagging-status/) もあります。
* タグ付けのコードなしで PDF 管理の機能だけを使いたい場合は、そのための独立した `pdfmanagement` パッケージが用意されました。

特に注意すべき変更が 1 つあります。`\DocumentMetadata` はドキュメント内で 1 回しか呼び出せなくなりました。2 回目の呼び出しは、`\documentclass` を 2 回呼び出した場合と同様にコンパイルエラーになります。

#### 意味を持つアクセシブルな数式

[2025 年 11 月の新機能](https://www.latex-project.org/news/latex2e-news/ltnews42.pdf) として、`\MathMLintent` と `\MathMLarg` により、著者は記法がどのように構成されているかだけでなく、それが何を意味するかを支援技術に伝えられるようになりました。たとえば、`|y|` は _「bar y bar」_ ではなく _「y の絶対値」_ と読み上げられるようになります。

アクセシブルな数式のタグ付けには、MathML を生成するエンジンである LuaLaTeX でのコンパイルと、`unicode-math` または `lua-unicode-math` パッケージのいずれかが必要です。

#### グラフィックスや図も意味を持つように

アクセシビリティはテキストや数式に限りません。`\includegraphics`、`picture`、`tikzpicture` がアクセシビリティ用のキーを受け付けるようになったため、各グラフィックに適切なマークアップを施せます。

```latex
\includegraphics[alt={A bar chart of quarterly revenue}]{revenue}
```

グラフィックスは 4 つの方法で分類できます。実際に内容を説明する図、支援ツールが無視すべき装飾的なアーティファクト、記号の代わり、または通常のテキスト（`todonotes` などに便利）です。TikZ の出力は追加設定なしでサポートされています。

#### タグ付きのアクセシブルなプレゼンテーションを作成するための新しいクラス

`beamer` ドキュメントクラスは、LaTeX でプレゼンテーションスライドを作成する際に非常に人気があります。しかし残念ながら、LaTeX のタグ付けコードとは互換性がありません。そこで、新しいドキュメントクラス [`ltx-talk`](https://ctan.org/pkg/ltx-talk) がゼロから作成されました。構文は `beamer` とほぼ同様ですが、`beamer` のすべての機能が `ltx-talk` に実装されているわけではありません。

#### 節見出しのスタイル設定のための新しいテンプレート機構

節見出しのコマンドが新しいテンプレート機構を用いて LaTeX カーネルに再実装され、`titlesec` などのパッケージが LaTeX のタグ付けコードと完全には互換性がないという問題が解決されました。簡単な例を示します。

```latex
\EditInstance{heading}{section}{
  number-format=\fbox{\LARGE\bfseries\theheading},
  title-decls=\Large\bfseries\sffamily\color{blue},
  before-vspace=20pt,
}
```

詳細は [ドキュメント](https://tug.ctan.org/macros/latex-dev/required/latex-lab/latex-lab-sec-template.pdf) を参照してください。

#### 内部から再構築されたカーネル

今年のカーネルでは、いくつかの制限が取り除かれました。

* <strong>出力ルーチンが設定可能に:</strong> 40 年近くにわたり、LaTeX のページ組み立て機構は事実上ハードコードされており、それを変更する必要のあるパッケージは内部コードを上書きせざるを得ませんでした。現在は、変更を加えるためのフックとソケットが公開されています。これにより、パッケージはより安定し、互いに競合しにくくなります。
* <strong>モダンなマーク機構:</strong> 2 つの絡み合ったマークしかサポートしていなかった従来の `\markboth` / `\leftmark` / `\rightmark` の仕組みが、任意の数の独立したマークをサポートする柔軟なシステムの上に再構築されました。おなじみのコマンドはこれまでとまったく同じように動作します。
* <strong>ブロック環境と節見出しがテンプレートで動作するように:</strong> リスト、引用、定理型の環境、そして見出しコマンドが、一貫した共通の基盤システムを共有するようになりました。実用上の利点の 1 つとして、LaTeX は `enumitem` や `amsthm` の `\newtheoremstyle` といった人気パッケージをネイティブにエミュレートし始めており、`titlesec` のエミュレーションも進行中です。リストや定理ボックスのスタイルを変えるためだけにパッケージをインストールする必要は少なくなりました。
* <strong>定理型環境の相互参照の改善:</strong> 新しい `\newcounteralias` コマンドにより、定理とカウンターを共有する補題を `cleveref`、`zref-clever`、`hyperref` で参照した場合に、_「theorem 1」_ ではなく正しく _「lemma 1」_ と表示されるようになります。

ドキュメントだけでなくパッケージを保守している場合は、2 つの変更に注意が必要です。カーネルが正式に **2023-11-27 以降の日付の `expl3`** を必要とするようになったこと、そして _「偽の数式」_（ボックスの配置のためだけに数式モードを使用すること）が `\textsuperscript`、`\parbox`/`minipage` などの構文や表組み構造の周辺から削除されたことです。これによりタグ付けと右から左に書くテキストのサポートが向上しますが、`\showoutput` の結果を以前の TeX Live バージョンと比較すると違いに気付くでしょう。

#### 対応範囲の拡大: より多くの言語

* ベンガル語、グジャラート語、カンナダ語、マラヤーラム語、シンハラ語、タミル語、テルグ語を含む<strong>ブラーフミー系文字の索引作成</strong>が、`upmendex` で実験的にサポートされました。
* 新しい **BCP 47 言語メタデータ**キー（`language`、`other-languages`）により、地域による変種まで含めてドキュメントの言語を正確に宣言できます。これは PDF 自体の言語メタデータにも反映されます。

#### その他の注意点

* `enumerate`、`theorem`、`verbatim` パッケージはレガシーとみなされるようになりました。新しいドキュメントでは、それぞれ `enumitem`、`amsthm`、`fancyvrb` を使用することをおすすめします。
* 古い PDF バージョンを想定した印刷ワークフローやプラットフォームを利用している場合でも、PDF バージョンを自分で設定できます（例: `\DocumentMetadata{pdfversion=1.7}`）。また、以前のデフォルトを対象としたドキュメントのコンパイル方法は、TeX Live 2026 のドキュメントで説明されています。
* TeX Live 2026 の [公式リリースノート](https://tug.org/texlive/doc/texlive-en/texlive-en.html#news) は TeX Users Group（TUG）のウェブサイトで確認できます。[すべての TeX Live バージョンのリリースノート](https://www.tug.org/texlive/doc/texlive-en/texlive-en.html#x1-710009) も公開されています。

### TeX Live 2026 の影響を受ける主なパッケージ

以下のセクションでは、TeX Live 2025 では正常にコンパイルできていたプロジェクトが、TeX Live 2026 ではコンパイルエラーになる原因となる変更をいくつか紹介します。

#### サポートされなくなった表組み関連のパッケージ

LaTeX カーネルにおける表組み構造の新しい変更により、`tabu` および `tabls` パッケージは TL2026 ではサポートされなくなり、コンパイルエラーが発生するようになりました。`arydshln` パッケージも、`tabularx` や `tabular*` 環境など、他のパッケージと互換性がない場合があります。同様に、`\@array` や `\tabular` を再定義するパッケージやテンプレートも、表組みに類する構造の周辺でコンパイルエラーを引き起こします。

#### `babel` の廃止された言語オプション

`frenchb` および `francais` 言語オプションは廃止されました。これらは `french` に置き換える必要があります。

#### `varioref` のバグ

[`varioref` パッケージのバグ](https://github.com/latex3/latex2e/issues/2112#issuecomment-4881772493) により、KOMA-Script のドキュメントクラスでこのパッケージを読み込むと TeX capacity exceeded エラーが発生し、PDF が生成されません。

```text
\documentclass{scrartcl}
\usepackage{varioref}
\begin{document}
Hello World!
\end{document}
```

回避策として、プリアンブルに

```text
\def\extrasenglish{}
```

を追加します。

#### KOMA-script クラスと `capt-of`

KOMA-script のドキュメントクラス（`scrbook`、`scrartcl`、`scrreport`、`scrletter`）が `\captionof` を定義するようになったため、`capt-of` パッケージは読み込まないでください。（一方、`caption` パッケージはこれらのドキュメントクラスでも引き続き安全に読み込めます。）

#### `thmtools`: `sibling`/`numberlike`/`sharenumber` のエラー

`thmtools` のオプション `sibling`（または `numberlike`、`sharenumber`）を使って新しい定理型環境を宣言すると、`Command \c@proposal already defined` のような [カウンターがすでに定義されているというエラー](https://github.com/muzimuzhi/thmtools/issues/75) が発生します。

```text
\documentclass{article}
\usepackage{thmtools}
\declaretheorem{theorem}
\declaretheorem{proposal}[sibling=theorem]

\begin{document}

\begin{theorem}This is a theorem.\end{theorem}
\begin{proposal}This is a proposal.\end{proposal}

\end{document}
```

回避策として、プリアンブルの `thmtools` を読み込んだ後、`\declaretheorem` の前に次の行を追加します。

```text
\makeatletter
\@ifundefined{newcounteralias}{}{%
  \renewcommand\thmt@autorefsetup{\@xa\def\csname\thmt@envname autorefname\@xa\endcsname\@xa{\thmt@thmname}}%
}
\makeatother
```

#### `polyglossia`、`xepersian`、`array`

アラビア文字の組版に `polyglossia` または `xepersian` パッケージを使用していて、`array` パッケージ、または `array` を読み込む他の表組み関連パッケージを読み込んでいる場合、表組みに類する構造の中にアラビア語のテキストを配置すると、`\UseMathForPositioningText` が定義されていないというエラーが発生します。

```text
\documentclass[12pt,a4paper]{article}
\usepackage{polyglossia}
\usepackage{array}
\setdefaultlanguage{arabic}
\newfontfamily\arabicfont[Script=Arabic]{Noto Naskh Arabic}
\begin{document}
\begin{tabular}{c}
السلام عليكم
\end{tabular}
\end{document}
```

これは、`\documentclass` の宣言の前に `\DocumentMetadata{}` を追加することで解決できます。あるいは、アラビア文字の組版に `babel` パッケージへの切り替えを検討してください。

#### `babel-spanish` と `biblatex-apa`

`biblatex` のスタイル `apa` を使用しながら `babel-spanish` を読み込むと、フックと `\@makecaption` に関するコンパイルエラーが発生します。

```text
\usepackage[spanish]{babel}
\usepackage[style=apa]{biblatex}
```

ただし、このエラーは `babel` に `shorthands=off` オプションを追加することで回避できます。

#### `xgreek`、`hyperref`、`\appendix`

`xgreek`（XeLaTeX および LuaLaTeX 専用）と `hyperref` パッケージを読み込んでいる場合、`\appendix` の後に現れる節見出しでコンパイルエラーが発生します。

```text
\documentclass{article}
\usepackage{xgreek}
\usepackage{fontspec}
\setmainfont{GFS Artemisia}
\usepackage{hyperref}
\begin{document}
\section{Εισαγωγή}
\appendix
\section{Δεδομένα}
\end{document}
```

修正方法は、`hyperref` に `hypertexnames=false` オプションを追加することです。

#### `flowfram` と `titlesec`

現時点では、`flowfram` パッケージと `titlesec` パッケージは互いに互換性がありません。ただし、新しい `\EditInstance` インターフェースを使って節見出しのスタイルを設定することを検討できます。例:

```text
\DocumentMetadata{}
\documentclass{article}
\usepackage{flowfram}
\usepackage[dvipsnames]{xcolor}
\EditInstance{heading}{section}{
  number-format=\fbox{\LARGE\bfseries\theheading},
  title-decls=\Large\bfseries\sffamily\color{NavyBlue}
}
\begin{document}
\section{Introduction}
\end{document}
```

詳細は [こちらのリンク](https://mirrors.ctan.org/macros/latex-dev/required/latex-lab/latex-lab-sec-template.pdf) を参照してください。

### Ayakaleaf Pro における TeX Live 2026

Ayakaleaf Pro の管理者は、通常の方法で設定を更新することで TeX Live 2026 をインストールできます。`TEX_LIVE_DOCKER_IMAGE`（および `ALL_TEX_LIVE_DOCKER_IMAGES`）を新しい TeX Live 2026 イメージに向けるだけです。その他のアップグレードは必要ありません。
