各プロジェクトには専用の MCP サーバーがあり、コンピューター上の AI クライアントがプロジェクトの読み取りと編集、コンパイル、コメントへの返信を行えます。クライアントは Git 認証トークンでサインインします。

<Info>

**MCP server** カードが表示されない場合は、管理者向けの [MCP サーバー](/ja/on-premises/configuration/overleaf-toolkit/integrations/mcp-server) を参照してください。

</Info>

## v6.3.3 の新機能 {#new-in-v6-3-3}

v6.3.3 から、クライアントはプロジェクト履歴も扱えます。変更の一覧表示、2 つのバージョンの比較、ある時点のファイルの読み取り、バージョンの保存と削除、ファイルまたはプロジェクト全体の復元ができます。変更履歴（tracked changes）を一覧表示して承認・却下でき、依頼すれば自分の編集を変更履歴として記録できます。テキストの一部へのコメント、コメントメッセージの編集と削除、プロジェクトチャットの読み取りと送信、ファイルとフォルダーの移動と名前変更、フォルダーの作成、スペルチェック言語の変更もできます。クライアントはあなたのトークンで動作するため、何ができるかはエディターと同様にプロジェクトでのあなたのロールに従います。[誰が何をできるか](#who-may-do-what)を参照してください。

MCP サーバーは v6.3.1 で導入されました。v6.3.1 と v6.3.2 のツールは同じ 17 個で、v6.3.3 には 33 個あります。

| ツール | v6.3.1 と v6.3.2 | v6.3.3 |
| ----- | ----------------- | ------ |
| `get_clone_info`, `get_settings`, `list_files`, `delete_file`, `compile`, `get_compile_log`, `get_output_file_link`, `word_count`, `reply_to_comment`, `resolve_comment`, `reopen_comment` | あり | あり、変更なし |
| `read_file` | 最新の内容 | `version` 時点のファイルも |
| `edit_file`, `write_file` | プロジェクトの変更履歴設定に従う | `trackChanges` で編集を変更履歴にすることも可能 |
| `update_settings` | コンパイラー、TeX Live イメージ、メインドキュメント | スペルチェック言語も |
| `list_versions` | バージョン、コメント、日付 | `delete_version` が受け取る `id` と保存者も |
| `list_comments` | id なしのメッセージ | 各メッセージの `id` も（`edit_comment_message` と `delete_comment_message` が受け取る） |
| `list_changes`, `diff`, `create_version`, `delete_version`, `restore_file`, `restore_project`, `list_tracked_changes`, `accept_tracked_changes`, `reject_tracked_changes`, `add_comment`, `edit_comment_message`, `delete_comment_message`, `list_chat_messages`, `send_chat_message`, `move_file`, `create_folder` | なし | あり |

## クライアントを接続する {#connect-a-client}

<Steps>
<Step title="ダイアログを開く">
プロジェクトを開きます。左のバーで **Integrations** をクリックし、**MCP server** をクリックします。

<Frame caption="Integrations パネル">
  <img src="/images/on-premises/mcp-server-integrations.png" alt="MCP server カードのある Integrations パネル" />
</Frame>

ダイアログには、このプロジェクトのサーバーのアドレスと、クライアントごとのタブ（**Claude Code**、**Codex**、**Cursor**、**VS Code**、**Gemini CLI**）が表示されます。

<Frame caption="MCP server ダイアログ">
  <img src="/images/on-premises/mcp-server-dialog.png" alt="アドレス、クライアントごとのタブ、Claude Code 用のコマンドが表示された MCP server ダイアログ" />
</Frame>
</Step>

<Step title="トークンを作成する">
**Go to settings** をクリックします。新しいタブでアカウント設定が開きます。**Git integration** の下で **Generate token** をクリックします。すでにトークンがある場合は **Add another token** をクリックします。トークンは一度しか表示されないため、**Copy** をクリックして安全な場所に保管してください。その後 **Close** をクリックします。

<Frame caption="新しいトークン">
  <img src="/images/on-premises/mcp-server-token.png" alt="Copy ボタンのある Git authentication token ダイアログ" />
</Frame>

[Git 連携](/on-premises/user-guide/users/git-integration)ですでに使っているトークンも使えます。1 つのトークンをすべてのプロジェクトで使うこともできます。
</Step>

<Step title="クライアントにサーバーを追加する">
ダイアログに戻り、使うクライアントのタブをクリックして、設定の横にある **Copy** をクリックします。

| タブ | 追加先 | トークン |
| --- | ------------- | --------- |
| **Claude Code** | ターミナルでコマンドを実行 | コマンド内の `<token>` を置き換える |
| **Codex** | `~/.codex/config.toml` | 環境変数 `OVERLEAF_TOKEN` に設定する |
| **Cursor** | `~/.cursor/mcp.json` | 環境変数 `OVERLEAF_TOKEN` に設定する |
| **VS Code** | `.vscode/mcp.json` | ファイルにはトークンの代わりに `overleaf-token` というパスワード入力欄がある |
| **Gemini CLI** | ターミナルでコマンドを実行 | コマンド内の `<token>` を置き換える |

アドレスは 1 つのプロジェクト専用です。別のプロジェクトを接続するには、`overleaf` はすでに使われているため、別の名前で追加します。たとえば Claude Code では、コマンド内の `overleaf` を `overleaf-lab` に変えます。
</Step>
</Steps>

## 接続を確認する {#check-the-connection}

### Claude Code で確認する {#with-claude-code}

```bash
claude mcp list
```

サーバーが接続済みとして表示されます:

```text
overleaf: https://<your-site>/project/<project-id>/mcp (HTTP) - ✔ Connected
```

### curl で確認する {#with-curl}

この方法はどのクライアントでも使えます。アドレスとトークンを置き換えて、MCP プロトコルの `initialize` リクエストを送信します:

```bash
curl -X POST https://<your-site>/project/<project-id>/mcp \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -H "Accept: application/json, text/event-stream" \
  -d '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2025-06-18","capabilities":{},"clientInfo":{"name":"curl","version":"1.0"}}}'
```

応答にはサーバー名と、それに続くクライアント向けの説明が含まれます:

```json
{"result":{"protocolVersion":"2025-06-18","capabilities":{"tools":{"listChanged":true}},"serverInfo":{"name":"overleaf","version":"1.0.0"},"instructions":"This server works on one Overleaf project. ..."},"jsonrpc":"2.0","id":1}
```

ツールを確認するには、同じコマンドで `tools/list` を送信します。応答には 33 個のツールが表示されます。サイトでプロジェクトチャットが無効な場合は 31 個です。v6.3.3 より前は 17 個です。

```bash
  -d '{"jsonrpc":"2.0","id":2,"method":"tools/list","params":{}}'
```

ツールを呼び出すには `tools/call` を送信します:

```bash
  -d '{"jsonrpc":"2.0","id":3,"method":"tools/call","params":{"name":"list_files","arguments":{}}}'
```

```json
{"result":{"content":[{"type":"text","text":"[\n  {\n    \"path\": \"main.tex\",\n    \"type\": \"doc\"\n  }\n]"}]},"jsonrpc":"2.0","id":3}
```

### アカウント設定で確認する {#in-your-account-settings}

**Git integration** の下の **Last used** に、サーバーがトークンを受け取った日付が表示されます。

<Frame caption="最初のトークンが使用済み">
  <img src="/images/on-premises/mcp-server-last-used.png" alt="トークン一覧。1 つ目のトークンの Last used に日付、2 つ目は N/A" />
</Frame>

### 接続できない場合 {#if-it-does-not-connect}

| 表示される内容 | 意味 |
| ------------ | ------------- |
| ステータス `401`、または Claude Code で `✘ Failed to connect` と `HTTP 401` | トークンがない、間違っている、または削除されている |
| ステータス `404` | この ID のプロジェクトがない |
| ステータス `405` | リクエストが `POST` ではない |
| ステータス `406` と `Not Acceptable` | `Accept` ヘッダーがない: クライアントは `application/json` と `text/event-stream` の両方を受け付ける必要がある |

## クライアントが作業するときの表示 {#what-you-see-when-a-client-works}

編集は、共同編集者の編集と同じように、開いているエディターにリロードなしで表示されます。新しいファイルやフォルダー、移動や名前変更はファイルツリーに表示されます。

<Frame caption="edit_file が追加した行">
  <img src="/images/on-premises/mcp-server-live-edit.png" alt="ダイアログもリロードもなく、edit_file が追加した行を表示するエディター" />
</Frame>

`edit_file` は、ちょうど 1 回だけ出現するテキストしか変更しません。そうでない場合、クライアントは `oldString not found in main.tex, read_file again` や `oldString appears 2 times in main.tex, add context` などのエラーを受け取り、何も変更されません。

v6.3.3 から、`move_file` はファイルまたはフォルダーを移動・名前変更し、新しいパスに必要なフォルダーを作成します。`create_folder` はフォルダーを作成します。ファイルが見つからない場合や新しいパスがすでに存在する場合、クライアントはエラーを受け取り、何も変更されません。`update_settings` ではスペルチェック言語を変更（たとえば `de` に）したり、スペルチェックをオフにしたりもできます。

トークンはあなたのものなので、コメントへの返信はあなたの名前でレビューパネルに表示されます。サーバー経由で解決したコメントはパネルから消え、再オープンすると戻ります。

<Frame caption="reply_to_comment が送信した返信">
  <img src="/images/on-premises/mcp-server-comment.png" alt="reply_to_comment が送信した返信の付いた、レビューパネルのコメント" />
</Frame>

v6.3.3 から、`add_comment` はテキストの一部にコメントを付けます。そのテキストはファイル内にちょうど 1 回だけ出現する必要があります。複数回出現する場合、クライアントはそれを含む 1 回だけ出現する長めのテキストも指定し、コメントはそのテキストにだけ付きます。コメントはあなたの名前でレビューパネルに表示され、ファイルが変わってもそのテキストに付いたままです。`edit_comment_message` は自分のメッセージを 1 つ変更します。`delete_comment_message` はメッセージを削除し、最初のメッセージを削除するとレビューパネルと同様にコメント全体が削除されます。

`compile` はプロジェクトをコンパイルし、出力ファイルの一覧を返します。続いて `get_output_file_link` が PDF やその他の出力ファイルをダウンロードするリンクを返します。このリンクにトークンは不要で、5 分後に無効になります。

ツールの完全な一覧は [Tools](/on-premises/configuration/overleaf-toolkit/integrations/mcp-server#tools) を参照してください。

## 変更履歴 {#tracked-changes}

v6.3.3 から、クライアントに編集を変更履歴にするよう依頼できます（例: *Rewrite the abstract as a tracked change*）。すると `edit_file` と `write_file` による既存ファイルへの変更は、プロジェクトで変更履歴がオフでも、あなたの名前の変更履歴になり、レビューパネルで承認または却下できます。新しいファイルが変更履歴になることはありません。依頼しない場合、編集はエディターでのあなたの編集と同じくプロジェクトの変更履歴設定に従い、あなたまたは全員に対して変更履歴がオンなら記録されます。

プロジェクトオーナーのアカウントに変更履歴機能がない場合、クライアントは `Track changes is off for this project` を受け取り、何も変更されません。

クライアントのすべての編集をレビューするには、自分に対して変更履歴をオンにします。レビューパネルでクライアントの編集と自分の編集を区別するには、プロジェクトを共有している別のアカウントのトークンをクライアントに渡します。

`list_tracked_changes` は、変更履歴をファイル、挿入または削除されたテキスト、作成者、時刻とともに一覧表示します。`accept_tracked_changes` と `reject_tracked_changes` は変更の id を受け取り、レビューパネルと同じように動作します。承認された変更はテキストに残り、却下された挿入は削除され、却下された削除は元に戻ります。開いているエディターにはリロードなしで結果が表示されます。ツールはクライアントに、依頼された変更だけを承認または却下するよう指示します。

## 履歴 {#history}

v6.3.3 から、クライアントには履歴パネルと同じようにプロジェクト履歴が見えます。

| ツール | 機能 |
| ---- | ------------ |
| `list_changes` | 変更を新しい順に一覧表示します。誰がいつどのファイルを変更したか、各変更の前後のバージョンを示します。古い変更は続きのバッチで返されます。 |
| `diff` | 2 つのバージョンを比較します。1 つのファイルを `git diff` のような unified diff で示すか、追加・削除・編集・名前変更されたファイルを示します |
| `version` 付きの `read_file` | あるバージョン時点のファイルを読み取ります |
| `list_versions` | 保存されたバージョンを、コメントと保存者とともに一覧表示します |
| `create_version` | 最新または以前のバージョンをコメント付きで保存します（**Label this version** と同様） |
| `delete_version` | 保存されたバージョンを削除します。変更そのものは残ります |
| `restore_file` | ファイルをあるバージョン時点に復元します（**Restore this version** と同様） |
| `restore_project` | プロジェクト全体をあるバージョン時点に復元します（**Restore project to this version** と同様） |

復元はそれ自体が新しい変更なので、同じ方法で元に戻せます。ツールはクライアントに、依頼されたときだけ復元するよう指示します。

プロジェクトオーナーが完全なプロジェクト履歴を持っていない場合、クライアントに見えるのは、履歴パネルと同様に直近 24 時間の変更（すべてそれより古い場合は最新の変更）だけです。それより古いバージョンの比較、読み取り、復元はできません。

## プロジェクトチャット {#project-chat}

v6.3.3 から、`list_chat_messages` はプロジェクトチャットを新しい順に 50 件ずつ読み取ります。`send_chat_message` はあなたの名前でメッセージを送信し、開いているチャットにすぐ表示されます。サイトでプロジェクトチャットが無効な場合、クライアントにはどちらのツールもありません。

## 誰が何をできるか {#who-may-do-what}

クライアントは、プロジェクトでのあなたのロールが許可することを行えます。

| クライアントの操作 | オーナー | 編集者 | レビュアー | 閲覧者（指名された共同作業者） | 閲覧者（リンク共有） |
| -------------------- | ----: | -----: | -------: | --------------------------: | --------------------: |
| ファイルと設定の読み取り、コンパイル、ログの読み取り、PDF のダウンロード | はい | はい | はい | はい | はい |
| ファイルの書き込み、編集、移動、削除、フォルダーの作成、設定の変更 | はい | はい | いいえ | いいえ | いいえ |
| 履歴、コメント、変更履歴の閲覧 | はい | はい | はい | はい | いいえ |
| チャットメッセージの読み取りと送信 | はい | はい | はい | はい | いいえ |
| コメントの追加と返信 | はい | はい | はい | いいえ | いいえ |
| コメントの解決、再オープン、削除 | はい | はい | 自分が始めたもの | いいえ | いいえ |
| コメントメッセージの編集 | 自分のもの | 自分のもの | 自分のもの | いいえ | いいえ |
| コメントメッセージの削除 | はい | はい | 自分のもの | いいえ | いいえ |
| 変更履歴の承認または却下 | はい | はい | いいえ | いいえ | いいえ |
| バージョンの保存 | はい | はい | はい | いいえ | いいえ |
| 保存されたバージョンの削除 | はい | 自分が保存したもの | 自分が保存したもの | いいえ | いいえ |
| ファイルまたはプロジェクトの復元 | はい | はい | いいえ | いいえ | いいえ |

リンクで参加した編集者は編集者として扱われます。レビュアーは MCP 経由でファイルを編集できず、変更履歴としての編集もできません。

## クライアントを切断する {#disconnect-a-client}

トークンを削除します。[トークンを削除する](/on-premises/user-guide/users/git-integration#delete-a-token)を参照してください。以降、サーバーはそのトークンに `401` を返します。Git でも使っている場合、Git もそのトークンを受け付けなくなります。
