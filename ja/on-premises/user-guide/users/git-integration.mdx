Git を使って、自分のコンピューターでプロジェクトを作業できます。変更は `git pull` または `git push` を実行したときにのみ転送されます。

<Info>

まず管理者が [Git 連携](/ja/on-premises/configuration/overleaf-toolkit/integrations/git-integration) を有効にする必要があります。

</Info>

## トークンを作成する {#create-a-token}

Git はアカウントのパスワードではなく、Git 認証トークンでサインインします。

<Steps>
<Step title="アカウント設定を開く">
**Account**、続いて **Account settings** をクリックします。**Git integration** の下で **Generate token** をクリックします。トークンを作成すると、このボタンは **Add another token** に変わります。

<Frame caption="アカウント設定の Git 連携">
  <img src="/images/on-premises/git-integration-settings.png" alt="Generate token ボタンがあるアカウント設定の Git integration セクション" />
</Frame>
</Step>

<Step title="トークンをコピーする">
**Copy** をクリックし、トークンを安全な場所に保管します。トークンは一度しか表示されません。その後 **Close** をクリックします。

<Frame caption="新しいトークン">
  <img src="/images/on-premises/git-integration-token.png" alt="Copy ボタンがある Git 認証トークンのダイアログ" />
</Frame>
</Step>

<Step title="トークンを確認する">
一覧に、トークンの先頭部分、作成日時、最終使用日時が表示されます。トークンは 1 年で期限切れになります。トークンは最大 10 個まで持てます。

<Frame caption="あなたのトークン">
  <img src="/images/on-premises/git-integration-tokens.png" alt="トークンが 1 つあるトークンの一覧" />
</Frame>
</Step>
</Steps>

## プロジェクトをクローンする {#clone-a-project}

<Steps>
<Step title="エディターで Git 連携を開く">
プロジェクトを開きます。左側のバーで **Integrations**、続いて **Git integration** をクリックします。

<Frame caption="Integrations パネル">
  <img src="/images/on-premises/git-integration-panel.png" alt="Git integration カードがある Integrations パネル" />
</Frame>
</Step>

<Step title="コマンドをコピーする">
**Clone with Git** ダイアログに、サイトのアドレスとプロジェクトの ID を含むコマンドが表示されます。**Copy** をクリックします。まだトークンがない場合は、**Go to settings** で新しいタブにアカウント設定が開きます。

<Frame caption="クローンコマンド">
  <img src="/images/on-premises/git-integration-clone.png" alt="git clone コマンドが表示された Clone with Git ダイアログ" />
</Frame>
</Step>

<Step title="コマンドを実行する">
コマンドをターミナルに貼り付けます。Git がパスワードを求めたら、トークンを貼り付けます。

```text
$ git clone https://git@<your-site>/git/<project-id>
Cloning into '<project-id>'...
Password for 'https://git@<your-site>': <your-token>
```

プロジェクト ID と同じ名前のフォルダーに、`main` ブランチのプロジェクトファイルが入ります。フォルダー名を指定するには、コマンドの末尾に名前を追加します。
</Step>
</Steps>

Git はサイトに接続するたびにトークンを求めます。記憶させるには credential helper を有効にします。Git はもう一度だけトークンを求め、その後は保持します。`store` helper はトークンを暗号化せずに `~/.git-credentials` に保存します。

```bash
git config --global credential.helper store
```

## エディターの変更を取得する {#pull-changes-from-the-editor}

フォルダー内で次を実行します。

```bash
git pull
```

Git は変更されたファイルを一覧表示します。エディターで行った変更は、`Update on Overleaf.` という名前のコミットとして届きます。

```text
Updating db007e3..c3e6332
Fast-forward
 main.tex | 2 +-
 1 file changed, 1 insertion(+), 1 deletion(-)
```

## 変更を push する {#push-your-changes}

変更をコミットしてから push します。

```bash
git add main.tex
git commit -m "Add a line from Git"
git push
```

出力の最後の行に、進んだブランチが表示されます。

```text
   53aca61..db007e3  main -> main
```

変更はエディターに反映され、開いているエディターは自動的に更新されます。新しいファイル、フォルダー、名前の変更はファイルツリーに表示されます。**History** では、変更に <strong>You (via Git)</strong> と表示されます。コミットメッセージはそこには表示されません。

### Git が push を拒否した場合 {#if-git-refuses-your-push}

その間にプロジェクトが変更されていると、Git は push を拒否します。

```text
 ! [rejected]        main -> main (fetch first)
```

まずその変更を取得してから、もう一度 push します。

```bash
git pull --no-rebase --no-edit
git push
```

単純な `git pull` は `fatal: Need to specify how to reconcile divergent branches.` で止まることがあります。上の `--no-rebase` オプションはこれに対応するもので、両側の変更をマージします。

両側で同じ行が変更されていると、pull は `CONFLICT (content): Merge conflict in main.tex` で止まります。ファイルを修正してから、次を実行します。

```bash
git add main.tex
git commit -m "Merge the changes from the editor"
git push
```

サイトが受け付けないものが 2 つあります。

* 他のブランチ: `! [remote rejected] feature -> feature (wrong branch)`。存在するのは `main` だけなので、作業はそこに push してください。
* 強制 push: `! [remote rejected] main -> main (forced push prohibited)`。代わりに、現在の `main` の上に変更を積み重ねてください。

### Git が Authentication failed と表示した場合 {#if-git-says-authentication-failed}

```text
remote: Enter your Git authentication token when prompted for a password.
fatal: Authentication failed for 'https://<your-site>/git/<project-id>/'
```

トークンが間違っているか削除されているか、アカウントのパスワードを入力しています。既存のトークンは再表示できないため、手元にない場合は新しいトークンを作成してください。

## トークンを削除する {#delete-a-token}

**Account settings** の **Git integration** で、トークンの横にある削除アイコンをクリックし、ダイアログで **Delete** をクリックします。それ以降、Git はそのトークンに対して `Authentication failed` を返します。
