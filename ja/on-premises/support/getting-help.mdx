### Doctor

Overleaf Toolkit には、デバッグに役立つ便利な `doctor` スクリプトが付属しています。`bin/doctor` を実行すると、ホスト環境、設定、Toolkit が必要とする依存関係に関する情報が出力されます。この出力は、Ayakaleaf Pro のインストールに関する問題を私たちが診断する際にも役立ちます。

<Info>

Overleaf Pro のユーザーは [GitHub で issue を作成](https://github.com/ayaka-notes/overleaf/issues)できます。

メッセージには `bin/doctor` スクリプトの出力を含めることをおすすめします。

</Info>

### ホスト情報

`Host Information` セクションには、Toolkit を実行しているマシンに関する情報（たとえば Linux ディストリビューションやリリース）が含まれます。

<Accordion title="Host Information の出力例">

```text
- Host Information
    - Linux
    - Output of 'lsb_release -a':
            No LSB modules are available.
            Distributor ID:	Ubuntu
            Description:	Ubuntu 22.04.5 LTS
            Release:	22.04
            Codename:	jammy
```

</Accordion>

### 依存関係

`Dependencies` セクションには、Toolkit の動作に必要なツールが一覧表示されます。ツールが存在する場合は、バージョン情報とともに `status: present` と表示されます。存在しない場合は `status: MISSING!` と表示され、`doctor` の出力の末尾に警告が追加されます。

<Accordion title="Dependency の出力例（存在する場合）">

```text
- docker
    - status: present
    - version info: Docker version 28.0.4, build b8034c0
```

</Accordion>

<Accordion title="Dependency の出力例（存在しない場合）">

```text
- docker
    - status: MISSING!
```

</Accordion>

依存関係が 1 つでも欠けていると、Toolkit はほぼ確実に動作しません。

### 設定

`Configuration` セクションには、`config/` ディレクトリ内のファイルに関する情報が含まれます。`config/overleaf.rc` については、doctor がいくつかの重要な値を出力します。存在しないファイルは `status: MISSING!` と表示され、`doctor` の出力の末尾に警告が追加されます。

<Accordion title="Configuration の出力例">

```text
====== Configuration ======
- config/version
    - status: present
    - version: 6.3.2
- config/overleaf.rc
    - status: present
    - values
        - OVERLEAF_DATA_PATH: /tmp/overleaf
        - SERVER_PRO: false
        - MONGO_ENABLED: false
        - REDIS_ENABLED: true
- config/variables.env
    - status: MISSING!
```

</Accordion>

上の例に関する注意点：

* `OVERLEAF_DATA_PATH` が `/tmp/overleaf` に設定されていますが、これは重要なデータの保存場所としては安全でない可能性があります。
* `MONGO_ENABLED: false` は、Toolkit が独自の MongoDB をプロビジョニングしないことを意味します。必要に応じて、`MONGO_URL` が外部で管理されている MongoDB を指していることを確認してください。
* この例では `config/variables.env` が存在しません。

### 警告

`Warnings` セクションには、doctor スクリプトが検出した問題がまとめられます。問題がない場合は、このセクションにその旨が表示されます。

<Accordion title="Warnings の出力例">

```text
====== Warnings ======
- configuration file variables.env not found
- rc file, OVERLEAF_DATA_PATH not set
====== End =======
```

</Accordion>

### Q\&A

<Accordion title="`bin/doctor` が出力する quay.io、Docker の設定、Perl のロケールに関するメッセージは修正が必要ですか？">

<strong>回答:</strong> いいえ、3 つとも情報提供のためのものです。`bin/doctor` はレポートを出力するだけで、`bin/up` を止めることはありません。

* `logged in to quay.io: false` と警告 `Server Pro enabled, but not logged in to quay.io repository`: このチェックは公式の Toolkit に由来するもので、公式では Server Pro のイメージが非公開の quay.io レジストリにあります。`SERVER_PRO=true` の場合、Toolkit は公開されている `ghcr.io/ayaka-notes/overleaf-pro` を取得するため、ログインは不要です。この警告は無視してください。
* `grep: /root/.docker/config.json: No such file or directory`（または別のホームディレクトリ）: quay.io のチェックは、このファイル内で `quay.io` を探します。Docker は保存すべき設定がある場合（たとえば `docker login` の後）にのみこのファイルを書き込むため、多くのサーバーでは存在しません。このファイルは必要ありません。
* `perl: warning: Setting locale failed`: Toolkit が `perl` を使うのは `bin/doctor` でバージョンを表示するこの箇所だけで、`LANG` や `LC_ALL` がホストにインストールされていないロケールを指定していると Perl が警告を出します。それでもバージョンは表示されます。警告を消すには、これらの変数を `locale -a` で一覧表示されるロケール（たとえば `C.UTF-8`）に設定してください。

`Docker daemon is not running`、`docker not found`、`Docker Compose not found`、あるいは `config/` 内のファイルが見つからないといった警告は修正が必要です。これらがないと Toolkit は起動できません。

</Accordion>
