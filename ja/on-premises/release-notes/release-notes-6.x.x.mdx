参照：[https://github.com/ayaka-notes/ayakaleaf-pro/releases/tag/pro-v6.3.0](https://github.com/ayaka-notes/ayakaleaf-pro/releases/tag/pro-v6.3.0)

<Warning>

Ayakaleaf Pro 6.3.0 は 2026 年 9 月 24 日に初回リリースされました。この再リリースでは、上流の更新が原因で発生した AI Assistant、Zotero、Mendeley 連携の問題に対処しています。

以前にリリースされたバージョンがデータを破損することはありません。最新の `6.3.0` イメージを pull して、デプロイをアップグレードしてください。<strong>Zotero または Mendeley とリンクされた参考文献ファイルがある既存のインストールでは、以下の移行も実行する必要があります。</strong> 新規インストールではこの移行は不要です。

</Warning>

<Accordion title="既存インストール向けの Zotero / Mendeley 移行">

再リリースされた 6.3.0 イメージにアップグレードする際は、以下のスクリプトを使用して、既存の Zotero/Mendeley リンク参考文献のメタデータを移行してください。この移行は修正 `12031b8dfd` に伴うものです。

これにより、`zoteroGroupId` / `mendeleyGroupId` が `group_id` に、`importedByUserId` が `importer_id` に名前変更され、`importedByName` が削除されます。

移行を実行する前に、MongoDB をバックアップし、アプリケーションを停止してください。MongoDB は稼働させたままにします。MongoDB のシェルを開きます（`mongo` はお使いのコンテナ名に置き換えてください）。

```bash
docker exec -it mongo mongosh
```

`mongosh` で次を実行します（`sharelatex` はお使いのデータベース名に置き換えてください）。

```javascript
use sharelatex

(async () => {
  let updated = 0
  await db.projects.find({}, { rootFolder: 1 }).forEach(async project => {
    const changes = {}
    function visit(folders, path) {
      for (const [i, folder] of (folders || []).entries()) {
        const folderPath = `${path}.${i}`
        for (const [j, file] of (folder.fileRefs || []).entries()) {
          const data = { ...file.linkedFileData }
          if (!["zotero", "mendeley"].includes(data.provider)) continue
          const groupKey = `${data.provider}GroupId`
          if (![groupKey, "importedByUserId", "importedByName"].some(key => key in data)) continue
          for (const [oldKey, newKey] of [[groupKey, "group_id"], ["importedByUserId", "importer_id"]]) {
            if (data[oldKey] != null && data[oldKey] !== "") {
              const value = String(data[oldKey])
              if (newKey in data && data[newKey] !== value) {
                throw new Error(`Conflicting ${newKey}: project ${project._id}, file ${file._id}`)
              }
              data[newKey] = value
            }
            delete data[oldKey]
          }
          delete data.importedByName
          changes[`${folderPath}.fileRefs.${j}.linkedFileData`] = data
        }
        visit(folder.folders, `${folderPath}.folders`)
      }
    }
    visit(project.rootFolder, "rootFolder")
    if (!Object.keys(changes).length) return
    const result = await db.projects.updateOne(
      { _id: project._id, rootFolder: { $eq: project.rootFolder } },
      { $set: changes }
    )
    if (!result.matchedCount) throw new Error(`Project changed during migration: ${project._id}`)
    updated += result.modifiedCount
  })
  print(`Updated ${updated} project(s).`)
})()
```

このスクリプトはネストされたフォルダーも対象とし、Zotero/Mendeley のメタデータのみを変更します。再実行しても安全です。移行が完了している場合、次回の実行では `Updated 0 project(s).` と報告されます。競合で停止した場合は、報告されたプロジェクト/ファイルを確認してください。それより前のプロジェクトはすでに移行済みの可能性があります。

更新後のアプリケーションを起動し、エディターを再読み込みして、既存の参考文献ファイルを元のインポート者として更新してください。過去のスナップショットは書き換えられません。古いアプリケーションにダウングレードするには、MongoDB のバックアップを復元してください。

</Accordion>

コミュニティで最も強力かつ機能豊富なオンライン LaTeX エディターである Overleaf Pro 6.3.0 のリリースを、誇りを持ってお知らせします。私たちは常にユーザー体験の向上に注力してきました。今回のリリースでは、AI アシスタントやサードパーティの参考文献連携など、きっと気に入っていただける大きな変更と素晴らしい機能をお届けします。

### 変更点

* AI チャットアシスタント：エディター内で、ご自身のプロバイダーを通じて AI モデルとチャットできます。
* LaTeX エラーアシスタント：LaTeX のコンパイルエラーに対して AI が修正案を提示します。
* Mendeley 連携：Zotero と同様に Mendeley から参考文献をインポートできます。
* Open in Overleaf API：Overleaf でコンテンツを開くための API を追加しました。
* テンプレートギャラリー：サーバー側のページネーション、検索、並べ替えを追加し、大規模なギャラリーでもすべてのテンプレートをブラウザに読み込む必要がなくなりました。
* 翻訳：6.3.0 向けの翻訳パッチを更新し、サポート対象の各言語で新しいインターフェーステキストを追加しました。
* 上流の Overleaf 6.3.0：タブによるファイル編集、ライトテーマとダークテーマで個別のヘッダーロゴ、依存関係とベースイメージの更新が含まれます。
* ライトテーマとダークテーマで個別のヘッダーロゴ画像を使えるよう、`OVERLEAF_HEADER_IMAGE_URL_LIGHT` と `OVERLEAF_HEADER_IMAGE_URL_DARK` を追加しました。
* エディターでファイルを別々のタブで開けるようになりました。
* `OVERLEAF_LINKED_URL_OUTBOUND_PROXY` により、ローカルでホストされたプロキシを含む HTTP(S) プロキシを設定できるようになりました。これは Open in Overleaf API でも使用されます。

#### 機能 04：テンプレートのページネーション

ギャラリーのページ分割、並べ替え、検索が MongoDB 上で行われるようになりました。事前の準備なしで動作しますが、テンプレートが数千件ある場合は、高速に保つために次のインデックスを追加できます（再実行しても安全です。`mongo`/`sharelatex` はお使いのコンテナ名とデータベース名です）。

```bash
docker exec mongo mongosh sharelatex --quiet --eval '
db.templates.createIndex({category:1,lastUpdated:-1},{name:"category_1_lastUpdated_-1",background:true});
db.templates.createIndex({lastUpdated:-1},{name:"lastUpdated_-1",background:true});
db.templates.createIndex({category:1,name:1},{name:"category_1_name_1_ci",collation:{locale:"en",strength:2},background:true});
db.templates.createIndex({name:1},{name:"name_1_ci",collation:{locale:"en",strength:2},background:true});
'
```

2 つの `*_ci` インデックスの `collation` は記載どおりに保ってください。ギャラリーは同じ collation でクエリを実行し、MongoDB は一致するインデックスしか使用しないためです。

## Ayakaleaf Pro 6.2.2

<strong>リリース日：</strong> 2026.07.23

参照：[https://github.com/ayaka-notes/ayakaleaf-pro/releases/tag/pro-v6.2.2](https://github.com/ayaka-notes/ayakaleaf-pro/releases/tag/pro-v6.2.2)

### 変更点

上流の Overleaf `6.2.2`（`6.2.1` ベース）で提供された公式ホットフィックスパッチをバックポートしました。

* プロジェクト招待トークンのシークレットがログに漏洩しないようにしました。招待トークンの暗号化処理が、暗号化/復号のたびに自身の設定をログに出力しており、その中に `OVERLEAF_INVITE_TOKEN_SECRET` から派生した暗号パスワードが含まれていました。
* 送信メールを、サポートが終了した AWS SES v1 クライアントから SESv2 に移行しました。`ses` メールドライバーを設定したインスタンスではメールをまったく送信できない場合がありましたが、現在は `SESv2Client` を通じて送信されます。
* プロジェクト共有ドロップダウンのグループ項目を新しい `group-link-sharing` 機能フラグで制御するようにし、該当しないインスタンスではグループリンク共有が表示されないようにしました。
* 共同編集者向けのプロジェクト共有モーダルを修正しました。所有者以外として開いた場合や `sharing-updates` フローが無効な場合に、常に失敗するリクエストが発行され、「something went wrong」エラーが表示されていました。
* document-updater に `scripts/flush_docs_with_pending_updates.js` を追加しました。これは、プロジェクトがフラッシュまたは完全削除された後に Redis の `PendingUpdates` キューが詰まったまま残ったドキュメントを復旧するメンテナンススクリプトです。`--dry-run` と `--estimated-docs` による安全チェックに対応しています。
* 依存関係を更新しました：`multer` 2.2.0、`form-data` 2.5.6、`protobufjs` 7.6.3、`@grpc/grpc-js` 1.14.4。

このリリースには、Ayakaleaf Pro による次の修正と改善も含まれています。

* 16 の追加言語（cs、da、de、es、fi、fr、it、ja、ko、nl、no、pl、pt、ru、sv、tr）の完全な翻訳を追加し、パスワードリセットページなどの未翻訳の文字列を修正しました。[#38](https://github.com/ayaka-notes/ayakaleaf-pro/issues/38) を修正。
* 管理パネルの「show N more projects」ボタンの件数を修正しました。複数形のプレースホルダーが正しく渡されていなかったため、誤った数が表示されていました。
* GitHub エクスポートの検証エラーを修正しました。エラーは生のメッセージではなく静的な i18n キーで表示されるようになり、GitHub Sync モーダルで使われなくなったエラーキーを削除しました。

## Ayakaleaf Pro 6.2.1

<strong>リリース日：</strong> 2026.07.18

参照：[https://github.com/ayaka-notes/ayakaleaf-pro/releases/tag/pro-v6.2.1](https://github.com/ayaka-notes/ayakaleaf-pro/releases/tag/pro-v6.2.1)

### 変更点

上流の Overleaf `6.2.1`（`6.2.0` ベース）で提供された公式ホットフィックスパッチをバックポートしました。

* リアルタイムの `applyOtUpdate` メッセージを、任意のオブジェクトを受け入れるのではなく厳格な検証スキーマで強化し、不正な編集操作を拒否するようにしました。
* そのスキーマを緩和して `meta.tc` を任意にし、より厳格な検証によって有効な更新が拒否されないようにしました。
* エディター（ShareJS クライアント）を修正し、空の操作に帰着する操作（リモート/同時操作によって相殺されたもの、または元に戻すによって完全に取り消されたもの）はサーバーに送信せずに破棄し、ドキュメントが正しく保存済みと報告されるようにしました。これにより、元に戻す操作や同時編集に伴う不要な同期や「unsaved changes」の問題を防ぎます。

## Ayakaleaf Pro 6.2.0

<strong>リリース日：</strong> 2026.07.10

参照：[https://github.com/ayaka-notes/ayakaleaf-pro/releases/tag/pro-v6.2.0](https://github.com/ayaka-notes/ayakaleaf-pro/releases/tag/pro-v6.2.0)

コミュニティで最も強力かつ機能豊富なオンライン LaTeX エディターである Overleaf Pro 6.2.0 のリリースを、誇りを持ってお知らせします。貴重な貢献をしてくださった yu-i-i 氏と davrot 氏に特に感謝します。お二人は GitHub Sync を強化し、高度な引用検索と Zotero 連携を導入してくださいました。

### 注意事項

<Warning>

* 新たに必須の環境変数 `OVERLEAF_INVITE_TOKEN_SECRET` が導入されました。`openssl rand -base64 32` で生成する必要があります。設定されていない場合、Overleaf インスタンスは起動に失敗します。
* GitHub Sync を有効にする場合は、`GITHUB_TOKEN_CIPHER_PASSWORD` 環境変数を設定する必要があります。この変数は GitHub アクセストークンを安全に暗号化するために必要です。設定しないと、Overleaf インスタンスは起動に失敗します。

</Warning>

* 新規プロジェクトで使用するデフォルトのコンパイラー（`pdflatex`、`latex`、`xelatex`、`lualatex` のいずれか）を設定する新しい環境変数 `DEFAULT_LATEX_COMPILER` を追加しました。
* 再設計されたエディターが唯一の選択肢になりました。

### 変更点

このリリースには、次の改善と新機能が含まれています。

* `MAX_UPLOAD_SIZE` が **50 MB** に制限されず、設定可能になりました。

* OAuth2 で、PAT の削除を所有者の範囲に限定するようにしました。
* LDAP のインポートの問題を修正しました。

機能は次のとおりです。

* ブラウザベースの Python ランナーを追加しました。
* Markdown、DOCX などの形式のインポートとエクスポートに対応する Pandoc サポートを追加しました。
* GitHub Sync を追加しました。
* 完全な中国語翻訳を追加しました。
* Zotero 連携を追加しました。
* `DEFAULT_LATEX_COMPILER` を追加しました。

### バイナリファイルの移行

この新しいリリースでは、バイナリファイルのストレージ使用量が半分に削減されます。

バージョン `5.5` にはオンライン移行が含まれており、アップグレードの一環としてダウンタイムを最小限に抑えられます。Server Pro `v6` にアップグレードする前に、Server Pro `v5.5` の最新バージョン（[Release Notes 5.x.x](https://docs.overleaf.com/on-premises/release-notes/release-notes-5.x.x)）をすでに実行しており、移行を実施済みであることを確認してください。

[移行手順の全文を見る](https://docs.overleaf.com/on-premises/release-notes/release-notes-5.x.x/binary-files-migration)。

### MongoDB の v8 へのアップグレード

このリリースでは、MongoDB の最小バージョンが `8.0` に引き上げられました。

現在 MongoDB `v6` 以前を使用している場合は、メジャーバージョンを 1 つずつ更新する必要があります（`v6 → v7 → v8`）。

<Warning>

アップグレードの**前に**、必ず[データベース](https://docs.overleaf.com/on-premises/maintenance/data-and-backups)のバックアップを取得してください。ロールバックする場合は、データベースのバックアップを復元する必要があります。

</Warning>

MongoDB を `v6 → v7 → v8` とアップグレードする手順については、[こちら](https://docs.overleaf.com/on-premises/maintenance/updating-mongodb#example-upgrading-mongodb-from-6.0-to-7.0-toolkit-users)のステップバイステップガイドを参照してください。

### Redis の v7.4 へのアップグレード

このリリースでは、Redis の最小バージョンも `7.4` に引き上げられました。

`config/overleaf.rc` の `REDIS_IMAGE` を `REDIS_IMAGE=7.4` に更新してください。

### 新機能

* `OVERLEAF_DISABLE_LINK_SHARING=true` でリンク共有を無効にできるようになりました。
* `OVERLEAF_MAINTENANCE_MESSAGE` と `OVERLEAF_MAINTENANCE_MESSAGE_HTML` で、メンテナンスページのタイトルと内容をカスタマイズできるようになりました。
* `OVERLEAF_USER_HARD_DELETION_DELAY` と `OVERLEAF_PROJECT_HARD_DELETION_DELAY` を（ミリ秒単位で）設定して、削除されたユーザー/プロジェクトの有効期限までの猶予（デフォルトは 90 日）を変更できます。

* リンクを含むフッターの表示を修正しました。

* Redis で TLS が有効な場合の履歴パネルのエラーを修正しました。
