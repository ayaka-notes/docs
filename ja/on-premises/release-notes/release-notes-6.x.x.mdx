<Accordion title="既存インストール向けの Zotero / Mendeley マイグレーション">

再リリースされた 6.3.0 イメージにアップグレードする際は、以下のスクリプトを使用して、既存の Zotero/Mendeley にリンクされた参考文献のメタデータを移行してください。このマイグレーションは修正 `12031b8dfd` に伴うものです。

これにより、`zoteroGroupId` / `mendeleyGroupId` が `group_id` に、`importedByUserId` が `importer_id` に名前変更され、`importedByName` が削除されます。

マイグレーションを実行する前に、MongoDB をバックアップしてアプリケーションを停止してください。MongoDB は起動したままにしておきます。MongoDB のシェルを開きます（`mongo` はお使いのコンテナ名に置き換えてください）。

```bash
docker exec -it mongo mongosh
```

`mongosh` で次を実行します（`sharelatex` はお使いのデータベース名に置き換えてください）。

```javascript
use sharelatex

(async () => {
  let updated = 0
  await db.projects.find({}, { rootFolder: 1 }).forEach(async project => {
    const changes = {}
    function visit(folders, path) {
      for (const [i, folder] of (folders || []).entries()) {
        const folderPath = `${path}.${i}`
        for (const [j, file] of (folder.fileRefs || []).entries()) {
          const data = { ...file.linkedFileData }
          if (!["zotero", "mendeley"].includes(data.provider)) continue
          const groupKey = `${data.provider}GroupId`
          if (![groupKey, "importedByUserId", "importedByName"].some(key => key in data)) continue
          for (const [oldKey, newKey] of [[groupKey, "group_id"], ["importedByUserId", "importer_id"]]) {
            if (data[oldKey] != null && data[oldKey] !== "") {
              const value = String(data[oldKey])
              if (newKey in data && data[newKey] !== value) {
                throw new Error(`Conflicting ${newKey}: project ${project._id}, file ${file._id}`)
              }
              data[newKey] = value
            }
            delete data[oldKey]
          }
          delete data.importedByName
          changes[`${folderPath}.fileRefs.${j}.linkedFileData`] = data
        }
        visit(folder.folders, `${folderPath}.folders`)
      }
    }
    visit(project.rootFolder, "rootFolder")
    if (!Object.keys(changes).length) return
    const result = await db.projects.updateOne(
      { _id: project._id, rootFolder: { $eq: project.rootFolder } },
      { $set: changes }
    )
    if (!result.matchedCount) throw new Error(`Project changed during migration: ${project._id}`)
    updated += result.modifiedCount
  })
  print(`Updated ${updated} project(s).`)
})()
```

このスクリプトはネストされたフォルダーも対象とし、Zotero/Mendeley のメタデータのみを変更します。再実行しても安全で、マイグレーションが完了していれば、次回の実行では `Updated 0 project(s).` と表示されます。競合によって停止した場合は、報告されたプロジェクト/ファイルを確認してください。それ以前のプロジェクトはすでに移行済みの可能性があります。

更新したアプリケーションを起動し、エディターを再読み込みして、既存の参考文献ファイルを元のインポート者として更新してください。過去のスナップショットは書き換えられません。旧バージョンのアプリケーションにダウングレードする場合は、MongoDB のバックアップを復元してください。

</Accordion>

コミュニティで最も強力かつ機能豊富なオンライン LaTeX エディターである Overleaf Pro 6.3.0 のリリースを発表できることを、大変誇りに思います。私たちは常にユーザー体験の向上に注力してきました。今回のリリースでは、AI アシスタントやサードパーティの参考文献連携など、きっと気に入っていただける大きな変更と素晴らしい機能をお届けします。

### 変更点

* AI Chat Assistant：エディター内で、独自のプロバイダーを通じて AI モデルとチャットできます。
* LaTeX Error Assistant：LaTeX のコンパイルエラーに対して、AI による修正案を得られます。
* Mendeley 連携：Zotero と同様に、Mendeley から参考文献をインポートできます。
* Open in Overleaf API：コンテンツを Overleaf で開くための API を追加しました。
* テンプレートギャラリー：サーバー側でのページネーション、検索、並べ替えを追加し、大規模なギャラリーでもすべてのテンプレートをブラウザーに読み込む必要がなくなりました。
* 翻訳：6.3.0 向けに翻訳パッチを更新し、サポート対象の各言語に新しいインターフェーステキストを追加しました。
* アップストリームの Overleaf 6.3.0：タブによるファイル編集、ライトテーマとダークテーマで別々のヘッダーロゴ、依存関係とベースイメージの更新が含まれます。
* ライトテーマとダークテーマで別々のヘッダーロゴ画像をサポートするため、`OVERLEAF_HEADER_IMAGE_URL_LIGHT` と `OVERLEAF_HEADER_IMAGE_URL_DARK` を追加しました。
* エディターでファイルを別々のタブで開けるようになりました。
* `OVERLEAF_LINKED_URL_OUTBOUND_PROXY` により、ローカルでホストされたプロキシを含む HTTP(S) プロキシを設定できるようになりました。これは Open in Overleaf API でも使用されます。

<a id="feature-04-template-pagination" />

#### 機能 04：テンプレートのページネーション

ギャラリーのページ分割、並べ替え、検索が MongoDB 上で行われるようになりました。特別な準備なしで動作しますが、テンプレートが数千件ある場合でも高速に保つために、次のインデックスを追加できます（再実行しても安全です。`mongo`/`sharelatex` はお使いのコンテナ名とデータベース名です）。

```bash
docker exec mongo mongosh sharelatex --quiet --eval '
db.templates.createIndex({category:1,lastUpdated:-1},{name:"category_1_lastUpdated_-1",background:true});
db.templates.createIndex({lastUpdated:-1},{name:"lastUpdated_-1",background:true});
db.templates.createIndex({category:1,name:1},{name:"category_1_name_1_ci",collation:{locale:"en",strength:2},background:true});
db.templates.createIndex({name:1},{name:"name_1_ci",collation:{locale:"en",strength:2},background:true});
'
```

2 つの `*_ci` インデックスの `collation` は記載どおりに保ってください。ギャラリーは同じ照合順序でクエリを実行し、MongoDB は一致するインデックスしか使用しないためです。

## Ayakaleaf Pro 6.2.2

**リリース日：** 2026.07.23

参照：[https://github.com/ayaka-notes/ayakaleaf-pro/releases/tag/pro-v6.2.2](https://github.com/ayaka-notes/ayakaleaf-pro/releases/tag/pro-v6.2.2)

### 変更点

アップストリームの Overleaf `6.2.2` で提供された公式のホットフィックスパッチを（`6.2.1` の上に）バックポートしました。

* プロジェクト招待トークンのシークレットがログに漏洩しないようにしました。招待トークンの暗号化処理は、暗号化/復号のたびに自身の設定をログに出力しており、その中には `OVERLEAF_INVITE_TOKEN_SECRET` から派生した暗号パスワードが含まれていました。
* 送信メールを、サポートが終了した AWS SES v1 クライアントから SESv2 に移行しました。`ses` メールドライバーを設定したインスタンスでは、メールがまったく送信できない場合がありましたが、現在は `SESv2Client` を通じて送信されます。
* プロジェクト共有ドロップダウンのグループ項目を新しい `group-link-sharing` 機能フラグで制御するようにし、該当しないインスタンスではグループリンク共有が表示されないようにしました。
* 共同編集者向けのプロジェクト共有モーダルを修正しました。オーナー以外のユーザーとして開いた場合や、`sharing-updates` フローが無効な場合に、常に失敗するリクエストが送信され、「問題が発生しました」というエラーが表示されていました。
* document-updater に `scripts/flush_docs_with_pending_updates.js` を追加しました。これは、プロジェクトがフラッシュまたは完全削除された後に Redis 内の `PendingUpdates` キューが詰まったまま残ったドキュメントを復旧するためのメンテナンススクリプトです。`--dry-run` と、安全確認のための `--estimated-docs` をサポートしています。
* 依存関係を更新：`multer` 2.2.0、`form-data` 2.5.6、`protobufjs` 7.6.3、`@grpc/grpc-js` 1.14.4。

このリリースには、Ayakaleaf Pro による次の修正と改善も含まれています。

* 16 の言語（cs、da、de、es、fi、fr、it、ja、ko、nl、no、pl、pt、ru、sv、tr）の完全な翻訳を追加し、パスワードリセットページなどの未翻訳の文字列を修正しました。[#38](https://github.com/ayaka-notes/ayakaleaf-pro/issues/38) を修正。
* 管理パネルの「show N more projects」ボタンの件数を修正しました。複数形のプレースホルダーが正しく渡されていなかったため、誤った数が表示されていました。
* GitHub エクスポートの検証エラーを修正しました。エラーは生のメッセージではなく静的な i18n キーで表示されるようになり、GitHub Sync モーダルで使用されなくなったエラーキーを削除しました。

## Ayakaleaf Pro 6.2.1

**リリース日：** 2026.07.18

参照：[https://github.com/ayaka-notes/ayakaleaf-pro/releases/tag/pro-v6.2.1](https://github.com/ayaka-notes/ayakaleaf-pro/releases/tag/pro-v6.2.1)

### 変更点

アップストリームの Overleaf `6.2.1` で提供された公式のホットフィックスパッチを（`6.2.0` の上に）バックポートしました。

* リアルタイムの `applyOtUpdate` メッセージについて、任意のオブジェクトを受け入れるのではなく厳格な検証スキーマを適用し、不正な編集操作を拒否するようにしました。
* そのスキーマを緩和して `meta.tc` を任意とし、有効な更新がより厳格な検証によって拒否されないようにしました。
* エディター（ShareJS クライアント）を修正し、空の操作に帰着する操作（リモート/同時の操作によって打ち消された場合や、元に戻す操作で完全に取り消された場合）はサーバーに送信せずに破棄し、ドキュメントが正しく保存済みと表示されるようにしました。これにより、元に戻す操作や同時編集にまつわる不要な同期や「未保存の変更」の問題を防ぎます。

## Ayakaleaf Pro 6.2.0

**リリース日：** 2026.07.10

参照：[https://github.com/ayaka-notes/ayakaleaf-pro/releases/tag/pro-v6.2.0](https://github.com/ayaka-notes/ayakaleaf-pro/releases/tag/pro-v6.2.0)

コミュニティで最も強力かつ機能豊富なオンライン LaTeX エディターである Overleaf Pro 6.2.0 のリリースを発表できることを誇りに思います。貴重な貢献をしてくださった yu-i-i 氏と davrot 氏に特に感謝します。お二人は GitHub Sync を強化し、高度な引用検索と Zotero 連携を導入してくれました。

### 注意事項

<Warning>

* 新たに必須の環境変数 `OVERLEAF_INVITE_TOKEN_SECRET` が導入されました。`openssl rand -base64 32` で生成する必要があります。設定されていない場合、Overleaf インスタンスは起動に失敗します。
* GitHub Sync を有効にする場合は、`GITHUB_TOKEN_CIPHER_PASSWORD` 環境変数を設定する必要があります。この変数は GitHub アクセストークンを安全に暗号化するために必要です。設定されていない場合、Overleaf インスタンスは起動に失敗します。

</Warning>

* 新規プロジェクトで使用するデフォルトのコンパイラー（`pdflatex`、`latex`、`xelatex`、`lualatex` のいずれか）を設定するための新しい環境変数 `DEFAULT_LATEX_COMPILER` を追加しました。
* 再設計されたエディターが唯一の選択肢になりました。

### 変更点

このリリースには、次の改善と新機能が含まれています。

* `MAX_UPLOAD_SIZE` が **50 MB** に制限されず、設定可能になりました。
* サンドボックスコンパイルが無効な場合にコンテナが再起動を繰り返す問題を修正しました。
* OAuth2 において、PAT の削除をオーナーの範囲に限定するようにしました。
* LDAP のインポートに関する問題を修正しました。

主な機能：

* ブラウザーベースの Python ランナーを追加しました。
* Markdown、DOCX などの形式のインポートとエクスポートのための Pandoc サポートを追加しました。
* GitHub Sync を追加しました。
* 中国語の完全な翻訳を追加しました。
* Zotero 連携を追加しました。
* `DEFAULT_LATEX_COMPILER` を追加しました。

### バイナリファイルの移行

この新しいリリースにより、バイナリファイルのストレージ使用量が半分になります。

バージョン `5.5` にはオンラインマイグレーションが含まれており、アップグレードの一環としてダウンタイムを最小限に抑えられます。Server Pro `v6` にアップグレードする前に、Server Pro `v5.5` の最新バージョン（[Release Notes 5.x.x](https://docs.overleaf.com/on-premises/release-notes/release-notes-5.x.x)）をすでに実行しており、マイグレーションを実行済みであることを確認してください。

### MongoDB の v8 へのアップグレード

このリリースでは、MongoDB の最小バージョンが `8.0` に引き上げられます。

現在 MongoDB `v6` 以前を使用している場合は、メジャーバージョンを 1 つずつ更新する必要があります（`v6 → v7 → v8`）。

<Warning>

アップグレードの**前に**、必ず[データベース](https://docs.overleaf.com/on-premises/maintenance/data-and-backups)のバックアップを取得してください。ロールバックする場合は、データベースのバックアップを復元する必要があります。

</Warning>

MongoDB を `v6 → v7 → v8` とアップグレードする方法については、[こちら](https://docs.overleaf.com/on-premises/maintenance/updating-mongodb#example-upgrading-mongodb-from-6.0-to-7.0-toolkit-users)のステップバイステップガイドを参照してください。

### Redis の v7.4 へのアップグレード

このリリースでは、Redis の最小バージョンも `7.4` に引き上げられます。

`config/overleaf.rc` の `REDIS_IMAGE` を `REDIS_IMAGE=7.4` に更新してください。
