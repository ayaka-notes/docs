ここでは、Ayakaleaf Pro に関するよくある質問への回答をまとめています。

### 基本的な質問

<Accordion title="Q01：Ayakaleaf Pro は無料トライアルですか？ライセンスは必要ですか？">

いいえ。Ayakaleaf Pro は完全に無料で使用できます。トライアル版ではなく、ライセンスも不要です。

</Accordion>

<Accordion title="Q02：Ayakaleaf Pro には Overleaf Server Pro のすべての機能が含まれていますか？">

はい。Ayakaleaf Pro には、Git-Bridge 連携を含む Overleaf Server Pro のすべての機能が含まれています。また、Overleaf SaaS プラットフォームの一部の機能も含まれています。私たちは引き続き Ayakaleaf Pro の開発と改善を進めています。

</Accordion>

<Accordion title="Q03：Overleaf Server Pro の価格はいくらですか？">

Overleaf Server Pro の費用は、1 ユーザーあたり年間約 \$300 です。最低 10 ライセンスが必要なため、導入費用は年間およそ \$3,000 からとなります。米国の小規模な公的契約では、1 ユーザーあたり年間約 \$320〜\$370 の費用が示されています。このため、Server Pro は特に小規模なチームにとって高価です。記録されている購入事例と価格については、[#information-and-price-about-overleaf-server-pro](/ja/on-premises#information-and-price-about-overleaf-server-pro  "mention") を参照してください。

</Accordion>

<Accordion title="Q04：Overleaf Server Pro に GitHub 同期や AI 機能が含まれていないのはなぜですか？">

Overleaf Server Pro は政府機関でよく使用されています。これらの組織はプライベートネットワーク上に導入し、アクセスを厳格に管理しています。機密データを保護するため、搭載されている機能はサードパーティのサービスとのデータのやり取りを避けています。GitHub 同期、AI、または同様の接続型機能が必要な場合、Overleaf は SaaS プラットフォームのサブスクリプションを推奨しています。

</Accordion>

<Accordion title="Q05：Ayakaleaf Pro は安全で信頼できますか？">

Ayakaleaf Pro はオープンソースです。セキュリティと信頼性を強化するため、Codex Security などのツールを使ってコードをレビューしています。サードパーティとのデータ同期を有効にしない限り、データはあなたのサーバー上に留まります。Ayakaleaf Pro には、データを外部に送信するテレメトリは一切含まれていません。

</Accordion>

<Accordion title="Q06：Ayakaleaf Pro は長期的にメンテナンスされますか？">

このプロジェクトを長期的にメンテナンスできるよう、あらゆる努力を続けていきます。

</Accordion>

<Accordion title="Q07：Ayakaleaf Pro はコンプライアンスに準拠していますか？">

Ayakaleaf Pro はコミュニティによるフォークです。コードと統合された機能はコミュニティの貢献によるものです。AGPL v3 の下でライセンスされています。導入環境は、このライセンスの要件を満たすことでライセンスに準拠できます。

</Accordion>

<Accordion title="Q08：なぜプロジェクト名が Ayakaleaf Pro なのですか？">

このプロジェクトは 2024 年に当初 Overleaf Pro という名前でした。開発は一時中断した後、2025 年末に再開されました。2026 年の第 1 四半期に、Overleaf は AI 機能を備えたサブスクリプションプランの名称を Pro に変更しました。また、コミュニティからのフィードバックでも、Overleaf Pro という名前は商標やなりすましのリスクを生む可能性があると指摘されました。ユーザーにこのプロジェクトが公式のものであると誤解させる恐れがあります。

こうした混乱を避けるため、プロジェクト名を Ayakaleaf Pro に変更しました。この名前は「Ayaka-notes Overleaf Pro」と読むことができます。メンテナー（ayaka と呼んでください！）は学生時代から 5 年以上にわたって Overleaf コミュニティの開発に貢献してきました。この経験が、私たちの長期的なメンテナンスへの取り組みを支えています。

</Accordion>

<Accordion title="Q09：Ayakaleaf Pro と、AI で構築された新しい LaTeX エディターとの違いは何ですか？">

2026 年以降、オープンソースコミュニティでは OpenAI Prism をはじめ、AI で構築された LaTeX エディターが数多くリリースされています。Ayakaleaf Pro は、データとサービスをあなた自身のサーバー上に保持します。これにより、導入環境とデータを直接管理できます。

コミュニティの実験的なエディターの多くには、確立された長期的なメンテナンス計画がありません。サードパーティの LaTeX コンパイルプラットフォームも、ユーザー基盤や収益が不十分な場合には運営を停止する可能性があります。Ayakaleaf Pro はすべてのソースコードを提供し、すべてのサービスをセルフホストできます。たとえメンテナンスが停止したとしても、既存のセルフホスト環境は引き続き稼働できます。

</Accordion>

### 機能

<Accordion title="Q01：Ayakaleaf Pro にはどのような機能がありますか？新しい機能をリクエストできますか？">

現在の機能一覧については、ドキュメントをご確認ください。追加してほしい機能がある場合は、GitHub で（機能リクエストとして）issue を気軽に作成してください。リクエストされた機能はできる限り実装するよう努めますが、開発には時間がかかるため、すべての機能をすぐに提供できるとは限りません。

</Accordion>

<Accordion title="Q02：いくつかの機能を開発しました。PR を提出できますか？また、必ず採用されますか？">

コントリビューションは歓迎しますが、採用は保証されません。各 PR は、基盤となる Overleaf のコードベースへの影響、メンテナンスの負担、ユーザーにもたらす価値に基づいて評価します。価値のあるコントリビューションは、できる限りマージしてメンテナンスしていきます。

ただし、過度な変更を加える PR、レビューされていない、または十分に理解されていない AI 生成コード（「バイブコーディング」）で構成された PR、長期的なメンテナンスが難しい機能を追加する PR は、却下する場合があります。

</Accordion>

<Accordion title="Q03：特定の機能はどのように設定すればよいですか？">

通常、新しい機能をリリースするたびにドキュメントを更新しています。詳しいセットアップ手順や利用可能な環境変数の説明については、該当するドキュメントを参照してください。

</Accordion>

<Accordion title="Q04：Python Runner ではどの Python ライブラリを使用できますか？">

Python Runner は、サーバー上ではなく、ユーザーのブラウザ内で [Pyodide](https://pyodide.org/) 0.29.3 を使って Python を実行します。コードがインポートするパッケージは、NumPy、pandas、Matplotlib など、[Pyodide に組み込まれたパッケージ](https://pyodide.org/en/0.29.3/usage/packages-in-pyodide.html)から読み込まれます。`pip` でインストールしたパッケージやその他のパッケージは利用できません。サーバー側で設定する項目はありません。

</Accordion>

<Accordion title="Q05：スペルチェックで日本語や中国語をチェックできますか？">

いいえ。スペルチェッカーには日本語や中国語の辞書がないため、これらの言語はスペルチェックの言語リストに含まれていません。ユーザーはエディターの設定で、プロジェクトのスペルチェックをオフにできます。

</Accordion>

### デプロイ

<Accordion title="Q01：Ayakaleaf Pro は k8s での分散デプロイに対応していますか？">

ほとんどのユーザーには、[Toolkit](/ja/on-premises/installation/using-the-toolkit) を使ったデプロイを推奨します。Kubernetes などのプラットフォームを使った大規模なクラスターデプロイは、運用の複雑さやメンテナンスの手間が大幅に増える可能性があるため推奨しません。

</Accordion>

<Accordion title="Q02：数千人のユーザーにサービスを提供する場合、可用性をどのように確保できますか？">

[水平スケーリング](/ja/on-premises/maintenance/horizontal-scaling) ガイドを参照してください。複数の Overleaf インスタンスをデプロイし、ロードバランサーを設定してトラフィックを分散できます。

</Accordion>

<Accordion title="Q03：デプロイや移行を手伝ってもらえますか？">

既存の Overleaf Server Pro インスタンスをお持ちの場合は、Ayakaleaf Pro への移行を喜んでお手伝いします。メールまたは issue でご連絡ください。

</Accordion>

<Accordion title="Q04：Ayakaleaf Pro を `https://example.com/overleaf` のような URL のサブパスでホストできますか？">

いいえ。Ayakaleaf Pro はドメインのルートから配信する必要があります。`https://overleaf.example.com` のような専用のドメインまたはサブドメインを使用してください。

</Accordion>

<Accordion title="Q05：Ayakaleaf Pro を Windows や macOS で、または Toolkit なしで実行できますか？">

[Toolkit](/ja/on-premises/installation/using-the-toolkit) を使用した Linux サーバーをサポートしています。Windows、WSL2、macOS 上の Docker Desktop でも動作する可能性はありますが、テストは行っていません。既知の MongoDB の問題については[トラブルシューティング](/ja/on-premises/support/troubleshooting)を参照してください。

単体の `docker-compose.yml` は提供していません。Toolkit が使用する Compose の設定を確認するには、Toolkit ディレクトリで `bin/docker-compose config` を実行してください。

</Accordion>

<Accordion title="Q06：Ayakaleaf Pro をアンインストールするにはどうすればよいですか？">

アンインストール用のスクリプトはありません。Toolkit ディレクトリで次の操作を行います。

1. `bin/docker-compose down` でコンテナを停止して削除します。
2. データを削除します。デフォルトでは Toolkit の `data/` ディレクトリにあります。`config/overleaf.rc` で `OVERLEAF_DATA_PATH`、`MONGO_DATA_PATH`、`REDIS_DATA_PATH`、`GIT_BRIDGE_DATA_PATH` を変更している場合は、それらのディレクトリも削除してください。この操作は元に戻せないため、データが必要になる可能性がある場合は、まず[バックアップ](/ja/on-premises/maintenance/data-and-backups)を取ってください。
3. Toolkit ディレクトリを削除します。
4. `docker images` で一覧表示できる Docker イメージ(`ghcr.io/ayaka-notes/overleaf-pro`、git-bridge イメージ、`mongo`、`redis`、TeX Live イメージ)を削除します。

</Accordion>

<Accordion title="Q07：Ayakaleaf Pro を停止、起動、再起動するにはどうすればよいですか？">

Toolkit ディレクトリで次を実行します。

* `bin/stop` はすべてのコンテナを停止し、`bin/start` はそれらを再び起動します。コンテナは保持されるため、ユーザーはログインしたままになります。
* `bin/up -d` はコンテナを作成し、バックグラウンドで起動します。`config/variables.env`、`config/overleaf.rc`、`config/version` を変更した後に実行してください。設定が変更されたコンテナが再作成され、その時点で初めて変更が反映されます。`bin/stop` と `bin/start` では変更は適用されません。
* `bin/docker-compose restart sharelatex` は、設定の変更を適用せずに Overleaf コンテナのみを再起動します。

`bin/up` がコンテナを再作成するたびにユーザーがログアウトされる場合は、`OVERLEAF_SESSION_SECRET` を設定してください。[環境変数](/ja/on-premises/configuration/overleaf-toolkit/environment-variables)の Q\&A を参照してください。

</Accordion>

<Accordion title="Q08：OAuth コールバック URL はどこに設定しますか？">

Ayakaleaf Pro ではなく、プロバイダー側で作成するアプリケーションに設定します。これらの連携のいずれについても、`config/variables.env` にコールバックの設定はありません。Ayakaleaf Pro はすべてのコールバック URL を `OVERLEAF_SITE_URL` から構築してプロバイダーに送信し、プロバイダーはアプリケーションに登録されたものと一致しない限りそれを拒否します。そのため、プロバイダー側で登録し、`OVERLEAF_SITE_URL` をユーザーが開くアドレスに設定するだけで済みます。

| 連携 | プロバイダー側のフィールド | 値 |
| --- | --- | --- |
| [GitHub](/ja/on-premises/configuration/overleaf-toolkit/github-synchronisation) | Authorization callback URL | `${OVERLEAF_SITE_URL}/user/github-sync/oauth2/callback` |
| [GitLab](/ja/on-premises/configuration/overleaf-toolkit/gitlab-synchronisation) | Redirect URI | `${OVERLEAF_SITE_URL}/user/gitlab-sync/oauth2/callback` |
| [Gitea](/ja/on-premises/configuration/overleaf-toolkit/gitea-synchronisation) | Redirect URIs | `${OVERLEAF_SITE_URL}/user/gitea-sync/oauth2/callback` |
| [Dropbox](/ja/on-premises/configuration/overleaf-toolkit/dropbox-synchronisation) | Redirect URIs(**Add** をクリック) | `${OVERLEAF_SITE_URL}/user/dropbox/oauth/callback` |
| [Zotero](/ja/on-premises/configuration/overleaf-toolkit/zotero-integration) | Callback URL | `${OVERLEAF_SITE_URL}/user/zotero/oauth/callback` |
| [Mendeley](/ja/on-premises/configuration/overleaf-toolkit/mendeley-integration) | Redirect URL | `${OVERLEAF_SITE_URL}/user/mendeley/oauth/callback` |
| [OIDC ログイン](/ja/on-premises/configuration/overleaf-toolkit/authentication/oidc-authentication) | Redirect URI | `${OVERLEAF_SITE_URL}/oidc/login/callback` |
| [SAML ログイン](/ja/on-premises/configuration/overleaf-toolkit/authentication/saml-authentication) | ACS URL (Assertion Consumer Service) | `${OVERLEAF_SITE_URL}/saml/login/callback` |

`OVERLEAF_SITE_URL` を新しいドメインなどに変更した場合は、すべてのプロバイダーで URL も更新してください。そうしないと連携に失敗します。

</Accordion>

### LaTeX

<Accordion title="Q01：ユーザーの LaTeX プロジェクトのコンパイルは分離されていますか？Shell Escape は有効ですか？">

Sandbox Compiles を有効にすると、各ユーザーのコンパイルは個別の Docker コンテナで実行され、他のユーザーのコンパイルから分離されます。Sandbox Compiles では、Shell Escape はデフォルトで有効になっています。

</Accordion>

<Accordion title="Q02：Sandbox Compiles のイメージは信頼できますか？コンパイルが失敗することはありますか？">

私たちは過去 3 年間にわたり、Sandbox Compiles 用の TeX Live Full イメージを改善してきました。ほとんどの場合、overleaf.com でコンパイルできるプロジェクトは Ayakaleaf Pro でも正しくコンパイルされます。必要なフォントが利用できない場合は、そのフォントを手動でプロジェクトにアップロードしてください。

</Accordion>

<Accordion title="Q03：プロジェクトがコンパイルできません。トラブルシューティングを手伝ってもらえますか？">

プロジェクトを Overleaf 公式サイトにアップロードし、読み取り専用のリンク共有を有効にして、そのリンクを GitHub の issue に記載してください。

Overleaf 公式サイトでは正常にコンパイルできるのに Ayakaleaf Pro ではコンパイルできない原因となっているバグについては、調査して修正します。この範囲外のコンパイルの問題はサポートの対象外です。

</Accordion>
