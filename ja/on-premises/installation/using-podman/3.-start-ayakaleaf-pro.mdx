---
title: 3. Ayakaleaf Pro の起動
description: Podman 上で Ayakaleaf Pro を起動し、podman-setup と bin/doctor で確認して、再起動後も起動するようにします。
icon: circle-play
---

<Steps>
<Step title="コンテナーを起動する">
```bash title="Start Ayakaleaf Pro"
bin/up -d
```

初回の起動では MongoDB、Redis、TeX Live のイメージをダウンロードし、`data/` にデータディレクトリを作成します。Podman のサポートが実験的であることを示す警告が表示されます。

<Info>

初回の起動では `MongoNetworkError: connect ECONNREFUSED 127.0.0.1:27017` と表示されることもあります。Toolkit は MongoDB の起動中にレプリカセットをセットアップし、応答があるまで再試行します。この行は無視して構いません。

</Info>

1〜2 分後、コンテナーが動いていることを確認します：

```bash title="List the containers"
podman ps --format "{{.Names}} {{.Status}}"
```

```text
mongo Up 34 seconds (healthy)
redis Up 20 seconds
sharelatex Up 20 seconds
```
</Step>

<Step title="セットアップを再度確認する">
データディレクトリが作成され `sharelatex` コンテナーが動いているので、`bin/podman-setup` はチェックを完了できます：

```bash title="Check the setup"
bin/podman-setup
```

新しいデータディレクトリの所有者を確認し、`sharelatex` コンテナーの内部から Podman ソケットをテストします：

```text
====== Socket Connectivity ======
[✓] host → socket OK
[✓] container → socket OK

====== Data Directory Permissions ======
[✓] mongo data dir owned by 999
[✓] redis data dir owned by 999
[✓] overleaf data dir owned by 33
...
====== Summary ======
[✓] 27 passed  [!] 1 warnings  [✗] 0 failures
[!] Warnings:
[!] not logged in to quay.io
```

`container → socket OK` は、Ayakaleaf Pro がコンパイル用のコンテナーを起動できることを意味します。チェックが失敗した場合は `bin/podman-setup --apply` を実行してから `bin/up -d` を実行してください。quay.io の警告は Ayakaleaf Pro には当てはまりません。[2. podman-setup の実行](/ja/on-premises/installation/using-podman/2.-run-podman-setup) を参照してください。
</Step>

<Step title="doctor を実行する">
```bash title="Run the doctor"
bin/doctor
```

Podman では、レポートにランタイムとセキュリティ設定が表示されます：

```text
- Container Daemon
    - status: up
    - runtime: podman
    - server version: 5.8.5
    - socket: /run/user/1000/podman/podman.sock
    - DOCKER_HOST: unix:///run/user/1000/podman/podman.sock
    - host → socket: OK
    - container → socket: OK
- Security
    - SELinux: Enforcing
    - SELINUX_MODE: managed
    - SELINUX_LABEL: sharelatex_t
    - SELinux module: loaded (podman_socket_clsi)
    - SELinux rules: present
    - Seccomp profile: present
```

最後に表示される警告 `Server Pro enabled, but not logged in to quay.io repository` は同じ quay.io のチェックです。[ヘルプを得る](/ja/on-premises/support/getting-help#q-and-a) を参照してください。
</Step>

<Step title="再起動後に Ayakaleaf Pro を起動する">
Docker では、再起動後に Docker デーモンがコンテナーを再び起動します。Rootless Podman にはデーモンがないため、サーバーの起動時にコンテナーを起動するユーザーサービスを有効にします：

```bash title="Start the containers at boot"
systemctl --user enable podman-restart.service
```

このサービスは、再起動ポリシーが `always` であるユーザーのすべてのコンテナーを起動します。Toolkit はすべてのコンテナーにこのポリシーを設定しています。これには lingering が必要で、`bin/podman-setup --apply` が有効にしています。このサービスがない場合は、再起動のたびに `bin/up -d` を実行してください。
</Step>

<Step title="ファイアウォールでポートを開く">
デフォルトでは、インスタンスはサーバー自身からの接続のみを `http://localhost:8080` で受け付けます。他のコンピューターから開けるようにするには、[5. インスタンスのカスタマイズ](/ja/on-premises/installation/using-docker-compose/linux/5.-personalizing-your-instance#listen-address-and-port) の説明に従って `config/overleaf.rc` の `OVERLEAF_LISTEN_IP` と `config/variables.env` の `OVERLEAF_SITE_URL` を設定し、もう一度 `bin/up -d` を実行します。

Docker と異なり、rootless Podman はホストのファイアウォールを迂回しません。RHEL のデフォルトのように `firewalld` が動いている場合は、ポートを開きます：

```bash title="Open port 8080"
sudo firewall-cmd --permanent --add-port=8080/tcp
sudo firewall-cmd --reload
```

クラウドサーバーでは、プロバイダーのセキュリティグループでもポートを許可してください。インスタンスをインターネットに公開する前に HTTPS を使ってください。[4. インストール後のタスク](/ja/on-premises/installation/using-podman/4.-post-installation-tasks#use-https) を参照してください。
</Step>
</Steps>
