RHEL とそのリビルド（Rocky Linux、AlmaLinux）には Docker ではなく Podman が付属しており、サーバーで Docker を許可していない組織もあります。Toolkit は代わりに **rootless Podman** 上で Ayakaleaf Pro を実行できます。コンテナーは通常のユーザーで実行され、コンパイルは引き続きサンドボックス化された TeX Live コンテナーで実行され、SELinux も enforcing のままです。スクリプト `bin/podman-setup` がホストを確認し、修正できるものを修正します。

このセクションを終えると、[Docker Compose の使用](/ja/on-premises/installation/using-docker-compose) と同じインスタンスが手に入ります。サンドボックス化されたコンパイル、MongoDB、Redis を備えた Ayakaleaf Pro を、いつもの `bin/up`、`bin/doctor`、`bin/upgrade` で管理できます。

<Info>

Podman のサポートは実験的です。これは公式の Overleaf Toolkit に由来し、公式では RHEL 9 以降で rootless Podman、サンドボックス化されたコンパイル、SELinux enforcing の組み合わせでのみテストされています。私たちはこれらのページを Rocky Linux 9.9（Podman 5.8、SELinux enforcing）と Ayakaleaf Pro 6.3.4 でテストしました。推奨のコンテナーランタイムは引き続き Docker です。

</Info>

### 必要なもの {#what-you-need}

* SELinux が enforcing の **RHEL、Rocky Linux、AlmaLinux、または CentOS Stream 9 以降**。それ以外のディストリビューションでは `bin/podman-setup` は停止します。Ubuntu や Debian では [Docker Compose の使用](/ja/on-premises/installation/using-docker-compose/linux) を使ってください。
* コンテナーを所有する **`sudo` を使える root 以外のユーザー**。このセクションのすべてのコマンドはこのユーザーで実行してください。`bin/podman-setup` は `root` での実行を拒否します。
* **クリーンなホスト**：Docker Engine も既存の Toolkit のインストールもないこと。既存の Docker ベースのインスタンスを Podman に移行する方法は扱いません。

### Docker との違い {#how-it-differs-from-docker}

|                                  | Docker                               | Rootless Podman                                                                          |
| -------------------------------- | ------------------------------------ | ---------------------------------------------------------------------------------------- |
| コンテナーを実行するのは         | Docker デーモン（`root` として）     | あなたのユーザー                                                                         |
| コンパイルの開始に使うソケット   | `/var/run/docker.sock`               | `/run/user/<uid>/podman/podman.sock`                                                     |
| ポート                           | 任意。例：`80` と `443`              | `1024` 以上。例：`8080`                                                                  |
| ホストのファイアウォール（`firewalld`） | 公開ポートはこれを迂回する    | 適用される：`firewall-cmd` でポートを開く                                                |
| 再起動後の起動                   | Docker デーモンが再起動する          | ユーザーサービス `podman-restart`                                                        |
| SELinux                          | Toolkit は設定しない                 | ポリシーモジュール `podman_socket_clsi` と `config/overleaf.rc` の `SELINUX_MODE=managed` |
| コンパイル用の Seccomp プロファイル | イメージに組み込み                | Toolkit が `config/seccomp/<version>/` に抽出し、`SECCOMP_PROFILE` に設定                |

### 既知の制限事項 {#known-limitations}

* <strong>Git 連携。</strong>Ayakaleaf Pro 6.3.4 では、Podman 上で `git clone` が `502` で失敗します。イメージ内の NGINX が Docker の DNS サーバー（`127.0.0.11`）で `git-bridge` コンテナーを探しますが、Podman にはこのサーバーがないためです。修正（[1b911d1092](https://github.com/ayaka-notes/ayakaleaf-pro/commit/1b911d1092c80f7b0ff77c5e3805b40503d49964)）は次のリリースに含まれます。それまでは `GIT_BRIDGE_ENABLED=false` のままにしてください。
* <strong>クライアントの IP アドレス。</strong>Rootless Podman は公開ポートをコンテナーのネットワーク内部から転送するため、Ayakaleaf Pro にはすべての訪問者が `10.89.0.15` のような内部アドレスとして見えます。管理パネルのユーザーの [監査ログ](/ja/on-premises/user-guide/administrators/user-management#audit-logs) には、そのユーザーの IP アドレスではなくこのアドレスが表示されます。
