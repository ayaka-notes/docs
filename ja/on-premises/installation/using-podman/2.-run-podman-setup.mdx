`bin/podman-setup` は、Ayakaleaf Pro が Podman 上で必要とするものをすべて確認します。オプションなしでは報告のみを行い、`--apply` を付けると見つかった問題も修正します。

<Steps>
<Step title="ホストを確認する">
```bash title="Check only"
bin/podman-setup
```

新しいホストでは、ほとんどのチェックが失敗します。例：

```text
====== Packages ======
[✗] podman not installed
[✗] podman-docker not installed
...
====== Summary ======
[✓] 7 passed  [!] 13 warnings  [✗] 4 failures
```
</Step>

<Step title="修正を適用する">
```bash title="Check and fix"
bin/podman-setup --apply
```

ターミナルで実行してください。システム全体に関わる手順では `sudo` のパスワードを尋ねます。また seccomp プロファイルを抽出するために Ayakaleaf Pro イメージをダウンロードするため、初回は数分かかります。最後にホストを再度確認します：

```text
====== Summary ======
[✓] 23 passed  [!] 2 warnings  [✗] 0 failures
[!] Warnings remaining:
[!] not logged in to quay.io
[!] container → socket skipped (sharelatex not running)
```

この時点では、どちらの警告も想定どおりです：

* `not logged in to quay.io`：このチェックは公式 Toolkit に由来し、そこでは Server Pro イメージがプライベートレジストリにあります。Ayakaleaf Pro のイメージは `ghcr.io` で公開されておりログインは不要なので、無視してください。インストール後も残ります。
* `container → socket skipped (sharelatex not running)`：このテストには実行中のインスタンスが必要です。[3. Ayakaleaf Pro の起動](/ja/on-premises/installation/using-podman/3.-start-ayakaleaf-pro) でスクリプトを再度実行します。

スクリプトは、すべてのチェックに合格すると `0`、警告があると `1`、失敗があると `2` で終了します。quay.io の警告があるため、`1` になるはずです。
</Step>
</Steps>

### スクリプトが変更する内容 {#what-the-script-changes}

`--apply` を付けると、スクリプトは次の内容を変更することがあります。

システム全体（`sudo` を使用）：

* `dnf` で `podman`、`podman-docker`、`git`、`curl`、`checkpolicy`、`policycoreutils` をインストールします。
* `loginctl` でユーザーの lingering を有効にし、ログアウト後もコンテナーが動き続けるようにします。
* `/etc/containers/nodocker` を作成し、"Emulate Docker CLI using podman" メッセージを表示しないようにします。
* `SELINUX_MODE=managed` のとき、SELinux ポリシーモジュール `podman_socket_clsi` を読み込みます。

ユーザー向け：

* ユーザーサービス `podman.socket` を有効にします。これは Ayakaleaf Pro がコンパイルを開始するために使う Docker 互換 API です。
* GitHub から Docker Compose v2 を `~/.local/bin/docker-compose` にインストールし、`~/.docker/cli-plugins/` にリンクします。
* `~/.config/containers/containers.conf` で、Podman がこの Compose を使うようにします。
* `~/.config/containers/registries.conf.d/overleaf-toolkit.conf` にエイリアス `mongo` と `redis` を追加し、これらの短いイメージ名をどこから取得するかを Podman に伝えます。

Toolkit 内：

* `config/overleaf.rc` の `DOCKER_SOCKET_PATH` と `DOCKER_HOST` を `/run/user/<uid>/podman/podman.sock` に設定します。
* コンパイル用の seccomp プロファイルを Ayakaleaf Pro イメージから `config/seccomp/<version>/clsi-profile.json` に抽出し、`config/variables.env` に `SECCOMP_PROFILE` を設定します。Docker と異なり、Podman はこのプロファイルをホスト上のファイルとして必要とします。
* `config/selinux/` に SELinux ポリシーモジュールをビルドします。
* `data/` 内のデータディレクトリが存在するようになったら、`podman unshare chown` でその所有者を設定します。

<Info>

各変更は 1 つのチェックに対応しています。`config/overleaf.rc` などで手動で何かを変更した場合は、`bin/podman-setup` を再度実行して確認してください。

</Info>
