コマンドの実行とファイルの編集は、**Ubuntu** で `~/ayakaleaf-toolkit` から行います。

<Steps>
<Step title="コンテナの設定">
`config/overleaf.rc` の既存エントリを編集します:

```bash title="config/overleaf.rc"
PROJECT_NAME=ayakaleaf-wsl
SERVER_PRO=true
OVERLEAF_LISTEN_IP=127.0.0.1
OVERLEAF_PORT=8080
SIBLING_CONTAINERS_ENABLED=true
DOCKER_SOCKET_PATH=/var/run/docker.sock
```

デフォルトのデータパスと、同梱の MongoDB および Redis サービスはそのままにしてください。ポート `8080` はローカルの Windows ブラウザー用で、`127.0.0.1` にバインドすることでローカルからのアクセスに限定されます。サンドボックスコンパイルでは、アプリケーションコンテナ内で TeX を実行するのではなく、コンパイルごとに個別の Linux コンテナを使用します。Docker ソケットによりアプリケーションがそれらのコンテナを作成でき、Toolkit は `data/overleaf/data/compiles` 以下のコンパイルデータ用のホストパスを提供します。
</Step>

<Step title="アプリケーションの設定">
`config/variables.env` で次の値を設定し、同じ名前の有効なエントリがあれば置き換えます:

```dotenv title="config/variables.env"
OVERLEAF_SITE_URL=http://localhost:8080
TEX_LIVE_DOCKER_IMAGE=ghcr.io/ayaka-notes/texlive-full:2026.1
ALL_TEX_LIVE_DOCKER_IMAGES=ghcr.io/ayaka-notes/texlive-full:2026.1
ALL_TEX_LIVE_DOCKER_IMAGE_NAMES="TeX Live 2026"
```

フルイメージには、幅広いプロジェクトに必要なパッケージとフォントが含まれています。このイメージとアプリケーション用に少なくとも 40 GB の空きストレージを確保し、さらにプロジェクトデータと今後のアップデート用の容量も確保してください。

デプロイを手早くテストするには、代わりに小さい **basic** イメージを使用してください。ステップ 6 のシンプルな article のテストには十分ですが、パッケージとフォントの完全なセットは含まれていません:

```dotenv
TEX_LIVE_DOCKER_IMAGE=ghcr.io/ayaka-notes/texlive-basic:2026.1
ALL_TEX_LIVE_DOCKER_IMAGES=ghcr.io/ayaka-notes/texlive-basic:2026.1
ALL_TEX_LIVE_DOCKER_IMAGE_NAMES="TeX Live 2026 Basic"
```

これらのセットのいずれか 1 つを選び、有効なキーが重複しないようにしてください。basic イメージの [Dockerfile](https://github.com/ayaka-notes/texlive-full/blob/main/texlive/2026/Dockerfile.basic) には `latexmk`、XeTeX、`fontspec` が含まれていますが、`ctex` やフォントの完全なコレクションは含まれていません。basic で LaTeX パッケージが見つからないことは、それだけではサンドボックスの問題を示すものではありません。

セッションシークレットを生成します:

```bash
openssl rand -hex 32
```

結果を `config/variables.env` に `OVERLEAF_SESSION_SECRET` として追加します。生成された招待トークンのシークレットも保持してください。メールを使用しないローカルインスタンスでは、SMTP の設定と `OVERLEAF_EMAIL_FROM_ADDRESS` は未設定のままにしてください。
</Step>

<Step title="インスタンスを起動する">
```bash
bin/up -d
```

Toolkit は MongoDB を起動してそのレプリカセットを初期化し、選択した TeX Live イメージをダウンロードしてから、Redis とアプリケーションを起動します。大きなイメージのダウンロード中は、処理が止まっているように見えることがあります。最初の `bin/up` が処理中の間は、2 回目の `bin/up` を実行しないでください。

別の Ubuntu ターミナルで次を確認します:

```bash
cd "$HOME/ayakaleaf-toolkit"
bin/docker-compose ps
bin/docker-compose logs --tail=100 mongo
bin/docker-compose logs --tail=100 -f sharelatex
```

`Ctrl+C` を押すとログの追跡を停止します。デタッチされたコンテナは引き続き実行されます。MongoDB で起動に失敗した場合は、再試行する前に [MongoDB が起動しない](/ja/on-premises/installation/using-docker-compose/windows/troubleshooting#mongodb-fails-to-start)に従ってください。既存のインストールをリセットするためにデータディレクトリを削除しないでください。

ポートと初回起動ページを確認します:

```bash
bin/docker-compose port sharelatex 80
curl -I http://localhost:8080/launchpad
```

ポートは `127.0.0.1:8080` になっているはずです。HTTP リクエストが最初に失敗する場合は、アプリケーションの初期化が終わるまで待ってください。
</Step>

<Step title="Windows からインスタンスを開く">
**Windows のブラウザー**で [http://localhost:8080/launchpad](http://localhost:8080/launchpad) を開きます。Windows でも、一時的な WSL の IP アドレスではなく、このアドレスを使用してください。

ブラウザーとは別に Windows からの HTTP アクセスを確認するには、**PowerShell** で次を実行します:

```powershell
curl.exe -I http://localhost:8080/launchpad
```

Ubuntu からはページにアクセスできるのに Windows からはアクセスできない場合は、[Windows から localhost を開けない](/ja/on-premises/installation/using-docker-compose/windows/troubleshooting#windows-cannot-open-localhost)を参照してください。
</Step>
</Steps>
