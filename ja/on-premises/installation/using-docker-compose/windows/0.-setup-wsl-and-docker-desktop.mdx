Ayakaleaf Pro は Linux コンテナを使用します。Windows では、WSL 2 バックエンドを使用する Docker Desktop をインストールし、Ubuntu で Toolkit のスクリプトを実行します。

WSL 2 は Linux カーネルを提供します。Docker Desktop は独自の `docker-desktop` 環境で Docker エンジンを管理し、**WSL Integration** を有効にすると、Ubuntu の Docker CLI がそのエンジンとやり取りできるようになります。その後、Toolkit がアプリケーション、MongoDB、Redis をコンテナとして起動します。サンドボックスコンパイルを有効にすると、アプリケーションはエンジンの Docker ソケットを使用して、コンパイルごとに個別の TeX Live コンテナを起動します。Windows 版の MongoDB、Redis、TeX Live をインストールする必要はありません。

<Steps>
<Step title="WSL 2 と Ubuntu をインストールする">
Windows で **PowerShell を管理者として**開き、次を実行します:

```powershell
wsl --install -d Ubuntu
```

再起動を求められた場合は Windows を再起動します。スタートメニューから **Ubuntu** を開き、Linux のユーザー名とパスワードを作成します。これは Ubuntu 内で `sudo` を使用するためのアカウントであり、Windows のログインとは別のものです。

**PowerShell** に戻り、WSL を更新してディストリビューションを確認します:

```powershell
wsl --update
wsl --version
wsl --list --verbose
```

Ubuntu の行には **VERSION 2** と表示される必要があります。1 と表示される場合は、一覧に表示されている正確なディストリビューション名を使用して次を実行します:

```powershell
wsl --set-version Ubuntu 2
```

Docker には WSL **2.1.5 以降**が必要です。`wsl --version` で表示される WSL ソフトウェアのバージョンと、ディストリビューションの **VERSION 2** 列は別のチェックです。インストールに失敗した場合は[インストールのトラブルシューティング](/ja/on-premises/installation/using-docker-compose/windows/troubleshooting#wsl-or-docker-reports-that-virtualization-is-unavailable)と [Microsoft のインストール手順](https://learn.microsoft.com/en-us/windows/wsl/install)を参照し、WSL が仮想化を利用できないと報告する場合は BIOS/UEFI でハードウェア仮想化を有効にしてください。
</Step>

<Step title="Docker Desktop をインストールして起動する">
お使いのプロセッサー向けの [Docker Desktop for Windows](https://docs.docker.com/desktop/setup/install/windows-install/) をダウンロードし、インストーラーを実行します。選択肢が表示された場合は **WSL 2** バックエンドを使用してください。Windows のスタートメニューから **Docker Desktop** を開き、エンジンが起動するまで待ちます。

Docker Desktop の **Settings → General** で、**Use WSL 2 based engine** オプションが表示されている場合は有効にします。**Settings → Resources → WSL Integration** で **Ubuntu** の連携を有効にし、**Apply** または **Apply & restart** を選択します。Ubuntu がデフォルトのディストリビューションでない場合は、Ubuntu 用のスイッチを明示的に有効にしてください。

WSL Integration が表示されない場合は、Docker Desktop が **Linux コンテナ**を使用していることを確認してください。[Docker の WSL 2 バックエンドガイド](https://docs.docker.com/desktop/features/wsl/)を参照してください。

このガイドでは Docker Desktop の連携機能を使用してください。`apt install docker.io` で 2 つ目の Docker Engine をインストールしたり、Ubuntu 内で `dockerd` を起動したりすると、別の構成が作られ、競合が発生する可能性があります。すでに Ubuntu で Engine を使用している場合は、切り替える前に Docker の移行ガイダンスに従い、既存のアプリケーションデータとバックアップを保持してください。
</Step>

<Step title="Ubuntu から Docker を確認する">
**Ubuntu** のターミナルを開きます。そこで次のコマンドを `sudo` なしで実行します:

```bash
docker version
docker compose version
docker ps
```

`docker version` には **Client** と **Server** の両方が表示される必要があります。新規インストールでは、コンテナの一覧が空でも正常です。`docker --version` だけでは、エンジンが実行されていることの証明にはなりません。

`docker` が利用できない、または接続できない場合は、WSL Integration を適用した後に Ubuntu を開き直し、Docker Desktop が実行中であることを確認してください。[トラブルシューティング](/ja/on-premises/installation/using-docker-compose/windows/troubleshooting#docker-is-unavailable-in-ubuntu)を参照してください。
</Step>

<Step title="リソースと Docker ソケットを確認する">
Docker から見えるリソースを確認します:

```bash
docker info --format 'CPUs={{.NCPU}} Memory={{.MemTotal}} Kernel={{.KernelVersion}}'
df -h "$HOME"
ls -l /var/run/docker.sock
```

小規模なローカルインスタンスの場合、Docker で利用可能な 4 CPU と 8 GB のメモリは出発点としての目安であり、測定された最小要件ではありません。Windows 用にも十分なメモリを残しておいてください。WSL 2 バックエンドでは、リソースの上限は Mac の Docker Desktop のリソーススライダーではなく、[WSL の設定](https://learn.microsoft.com/en-us/windows/wsl/wsl-config)で管理されます。`wsl --shutdown` が必要な変更は、実行中のすべての WSL ディストリビューションと Docker のワークロードを中断するため、インスタンスを起動する前に適用してください。

Toolkit の設定では `DOCKER_SOCKET_PATH=/var/run/docker.sock` をそのままにしてください。アプリケーションはサンドボックスコンパイルのためにこのエンジンソケットを必要とします。接続エラーを修正するためにソケットの権限を `777` に変更しないでください。代わりに Docker Desktop の連携を復元してください。
</Step>
</Steps>
