title: 5. インスタンスのカスタマイズ
description: Mac 上のローカルインスタンスのポート、サイト URL、TeX Live イメージを設定し、Docker VM のカーネルを確認して、Ayakaleaf Pro を起動します。
icon: square-sliders
---

<Steps>
<Step title="コンテナの設定">
`config/overleaf.rc` の次の既存エントリを編集します:

```bash title="config/overleaf.rc"
PROJECT_NAME=ayakaleaf-macos
SERVER_PRO=true
OVERLEAF_LISTEN_IP=127.0.0.1
OVERLEAF_PORT=8080
SIBLING_CONTAINERS_ENABLED=true
DOCKER_SOCKET_PATH=/var/run/docker.sock
```

デフォルトのデータパスと、同梱の MongoDB および Redis サービスはそのままにしてください。`OVERLEAF_LISTEN_IP=127.0.0.1` の場合、インスタンスを開けるのはこの Mac 上のブラウザーのみです。
</Step>

<Step title="アプリケーションの設定">
`config/variables.env` で次の値を設定し、同じ名前の有効なエントリがあれば置き換えます:

```dotenv title="config/variables.env"
OVERLEAF_SITE_URL=http://localhost:8080
TEX_LIVE_DOCKER_IMAGE=ghcr.io/ayaka-notes/texlive-full:2026.1
ALL_TEX_LIVE_DOCKER_IMAGES=ghcr.io/ayaka-notes/texlive-full:2026.1
ALL_TEX_LIVE_DOCKER_IMAGE_NAMES="TeX Live 2026"
```

セッションシークレットを生成します:

```bash
openssl rand -hex 32
```

結果を `config/variables.env` に `OVERLEAF_SESSION_SECRET` として追加します。これがないと、コンテナを再作成する `bin/up` のたびにすべてのユーザーがログアウトされます。[環境変数](/ja/on-premises/configuration/overleaf-toolkit/environment-variables)を参照してください。

メールを使用しないローカルインスタンスでは、SMTP の設定と `OVERLEAF_EMAIL_FROM_ADDRESS` は未設定のままにしてください。Git Bridge、外部認証、その他の連携機能は、それぞれの[設定ページ](/ja/on-premises/configuration/overleaf-toolkit)に従って後から追加できます。
</Step>

<Step id="check-the-docker-vms-linux-kernel" title="Docker VM の Linux カーネルを確認する">
MongoDB は macOS 上ではなく、Docker Desktop の仮想マシンの Linux カーネル上で動作します。初回起動の前にそのバージョンを確認してください:

```bash
docker info --format '{{.KernelVersion}}'
```

MongoDB は Linux カーネル **6.19 から 7.0.13** との非互換性を文書化しており、これは Docker 内の MongoDB にも影響します。修正方法はカーネル **7.0.14 以降**で、Docker Desktop のアップデートで提供されます。[MongoDB のプロダクションノート](https://www.mongodb.com/docs/manual/administration/production-notes/)を参照してください。

Docker VM が影響を受けるカーネルを使用している場合は、`config/docker-compose.override.yml` に次の内容を追加し、すでにある `services` とマージしてください:

```yaml title="config/docker-compose.override.yml"
services:
  mongo:
    environment:
      GLIBC_TUNABLES: glibc.pthread.rseq=1
```

<Warning>

修正済みのカーネルが利用可能になったらアップデートしてください。カーネルが影響を受ける範囲外であれば、この回避策は不要です。

</Warning>
</Step>

<Step title="インスタンスを起動する">
Toolkit のディレクトリで、次のコマンドを実行します:

```bash
bin/up -d
```

Toolkit は MongoDB のレプリカセットを初期化し、TeX Live イメージをプルして、アプリケーションを起動します。初回のダウンロードには時間がかかります。進行状況を確認するには:

```bash
bin/docker-compose ps
bin/docker-compose logs --tail=100 -f sharelatex
```

`Ctrl+C` を押すとログの追跡を停止します。コンテナは引き続き実行されます。

公開ポートと初回起動ページを確認します:

```bash
bin/docker-compose port sharelatex 80
curl -I http://localhost:8080/launchpad
```

ポートは `127.0.0.1:8080` になっているはずです。
</Step>
</Steps>

<Info>

後で他のコンピューターからインスタンスを開くには、Linux ガイドの [5. インスタンスのカスタマイズ](/ja/on-premises/installation/using-docker-compose/linux/5.-personalizing-your-instance)で説明しているように、待ち受けアドレスとサイト URL を変更し、HTTPS を設定してください。その場合、Mac はスリープしないようにしておく必要があります。[インスタンスを利用可能な状態に保つ](/ja/on-premises/installation/using-docker-compose/macos/6.-post-installation-tasks#keep-the-instance-available)を参照してください。

</Info>
