### 管理者と最初のプロジェクトを作成する {#create-the-administrator-and-a-first-project}

[http://localhost:8080/launchpad](http://localhost:8080/launchpad) を開き、最初の管理者アカウントを作成してログインします。その後、Linux ガイドの [6. インストール後のタスク](/ja/on-premises/installation/using-docker-compose/linux/6.-post-installation-tasks)に従ってください。その際、例の URL ではポート `8080` を使用してください。

### コンパイルを確認する {#verify-compilation}

ログインページが開いても、個別のコンパイラーコンテナとそのデータマウントが動作していることの証明にはなりません。空のプロジェクトを作成し、次の `main.tex` をコンパイルしてください:

```latex
\documentclass{article}
\begin{document}
Ayakaleaf Pro on macOS.
\end{document}
```

PDF プレビューにテキストが表示されるはずです。必要に応じて、プロジェクト設定で TeX Live 2026 を選択してください。

中国語のテキストを含むプロジェクトでは、コンパイラーとして **XeLaTeX** を選択し、次の内容でテストしてください:

```latex
\documentclass{ctexart}
\begin{document}
你好，Ayakaleaf Pro。
\end{document}
```

### 永続化を確認する {#verify-persistence}

```bash
bin/stop
bin/start
```

プロジェクトを再度開き、もう一度コンパイルしてください。アカウント、ソース、プロジェクトファイルが残っているはずです。デフォルトのパスでは、稼働中のデータは Mac 上の Toolkit の `data/` ディレクトリにあります。

### インスタンスを利用可能な状態に保つ {#keep-the-instance-available}

Mac がスリープしている間、macOS は Docker Desktop の仮想マシンをその中のすべてのコンテナごと一時停止します。誰もインスタンスを開けなくなり、実行中のコンパイルは Mac がスリープから復帰するまで停止します。影響するのはシステムのスリープだけです。ディスプレイはオフになってもかまいません。

他の人がインスタンスを使用する場合や、長時間のタスクを実行したままにする場合は、Mac を電源に接続したままにし、自動スリープを防いでください。[Mac のスリープとスリープ解除の設定を行う](https://support.apple.com/guide/mac-help/set-sleep-and-wake-settings-mchle41a6ccd/mac)を参照してください:

| Mac | 設定 |
| --- | --- |
| デスクトップ型 Mac（Mac mini、iMac、Mac Studio、Mac Pro） | **System Settings → Energy**: **Prevent automatic sleeping when the display is off** をオンにします |
| MacBook | **System Settings → Battery → Options**: **Prevent automatic sleeping on power adapter when the display is off** をオンにします。これは電源アダプターが接続されている間のみ有効で、蓋を閉じると MacBook はスリープします |

一時的にのみ Mac をスリープさせないようにするには、代わりにターミナルのウィンドウで `caffeinate -i` を実行してください。`Ctrl+C` を押すかウィンドウを閉じるまで、アイドル時のスリープを防ぎます。

Docker Desktop はユーザーセッション内のアプリです。再起動後にインスタンスが復帰するようにするには、Docker Desktop の **Settings → General** で **Start Docker Desktop when you sign in to your computer** をオンにしてください。Toolkit のコンテナは `restart: always` を使用しているため、Docker Desktop が起動すると、`bin/up` を実行しなくても Docker がコンテナを再起動します。再起動後に誰かが Mac にサインインするまで、インスタンスは停止したままです。

<Info>

スリープしない Mac はより多くの電力を消費します。常にアクセス可能である必要があるサービスには、Linux サーバーをおすすめします。[Linux](/ja/on-premises/installation/using-docker-compose/linux) を参照してください。

</Info>

### 日常的な使用 {#daily-use}

インスタンスを管理する前に Docker Desktop を開いてください。新しいターミナルで次を実行します:

```bash
export PATH="$(brew --prefix gnu-sed)/libexec/gnubin:$PATH"
cd "$HOME/ayakaleaf-toolkit"
```

| タスク | コマンド |
| --- | --- |
| 既存のコンテナを起動する | `bin/start` |
| データを保持したままコンテナを停止する | `bin/stop` |
| 設定の変更を適用する | `bin/up -d` |
| ステータスを確認する | `bin/docker-compose ps` |
| 起動ログを読む | `bin/docker-compose logs --tail=100 sharelatex` |
| コンパイラーのログを読む | `bin/logs -f clsi` |

`bin/start` は `config/` の変更を適用しません。設定を編集した後は `bin/up -d` を実行してください。`config/` と `data/` は保持し、アップグレードの前やインストールを移動する前には[データとバックアップ](/ja/on-premises/maintenance/data-and-backups)に従ってください。MongoDB が書き込んでいる最中にデータベースファイルをコピーしても、一貫性のあるバックアップにはなりません。

ローカルで使用する場合は、インスタンスを `127.0.0.1` のままにしてください。他のコンピューターに提供するには、待ち受けアドレス、サイト URL、HTTPS を意図的に設定してください。Linux ガイドの [5. インスタンスのカスタマイズ](/ja/on-premises/installation/using-docker-compose/linux/5.-personalizing-your-instance)を参照してください。

うまく動作しない場合は、[トラブルシューティング](/ja/on-premises/installation/using-docker-compose/macos/troubleshooting)を参照してください。
