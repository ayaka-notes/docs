---
title: エアギャップ/オフライン環境へのデプロイ
description: Docker イメージをエクスポート、転送、読み込みして、Ayakaleaf Pro をオフラインでデプロイします。
icon: block-brick
---

一般的に、Ayakaleaf Pro をオフライン環境にデプロイすることはおすすめしません。GitHub Sync や Zotero 連携など、多くの機能がインターネット接続を必要とするためです。

オフラインで運用する場合、必要な `ayakaleaf-pro` イメージや TeX Live イメージを pull するために `ghcr.io` レジストリにアクセスできないことがあります。しかし、Docker にはイメージのエクスポートとインポートを行うためのツールが用意されており、オフライン/エアギャップ環境へのデプロイに役立つため、問題はありません。

大まかな流れとしては、インターネットに接続できるデバイスで必要なイメージをダウンロードし、ポータブルデバイスにエクスポート（または SCP/Rsync で転送）して、エアギャップ環境のサーバーにインポートします。

そのためには、次の手順を実行する必要があります。

* インターネットに接続できるマシンで、必要なすべてのイメージ（`overleaf-pro`、`git-bridge`、`mongo`、`redis`、および [Sandboxed Compiles](https://docs.overleaf.com/on-premises/configuration/overleaf-toolkit/server-pro-only-configuration/sandboxed-compiles) で使用する必要な [TeX Live イメージ](https://docs.overleaf.com/on-premises/configuration/overleaf-toolkit/server-pro-only-configuration/sandboxed-compiles#available-tex-live-images)）を pull します
  * `docker pull ghcr.io/ayaka-notes/overleaf-pro:6.1.2`
  * `docker pull quay.io/sharelatex/git-bridge:6.1.2` （タグは `overleaf-pro` と同じである必要があります）
  * `docker pull mongo:6` （実際のバージョンに変更してください）
  * `docker pull redis:6.2` （実際のバージョンに変更してください）
  * `docker pull ghcr.io/ayaka-notes/texlive-full:2024.1` （実際のバージョンに変更してください）
* 次に、pull した**各**イメージを .tar ファイルにエクスポートする必要があります。例：`docker save ghcr.io/ayaka-notes/overleaf-pro:6.1.2 > overleaf-pro:6.1.2.tar`
* 任意の方法で、インターネットに接続されたマシンからオフライン/エアギャップ環境のサーバーへ `.tar` ファイルを転送します
* 各 .tar ファイルについて、`docker load` コマンドを使用して .tar ファイルからイメージを読み込みます。例：`docker load < overleaf-pro:6.1.2.tar`
* 最後に、`docker images` コマンドを実行して、イメージの読み込みが成功し、利用可能になっていることを確認します

<Danger>

デフォルトでは、`bin/up` コマンドを実行すると、Toolkit は `config/variables.env` の `ALL_TEX_LIVE_DOCKER_IMAGES` で設定された各 TeX Live イメージを自動的に pull しようとします。エアギャップ環境ではこれは失敗します。`config/overleaf.rc` で `SIBLING_CONTAINERS_PULL=false` を設定すると、これを止めることができます。

</Danger>
