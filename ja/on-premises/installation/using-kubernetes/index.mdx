1 台のサーバーで Ayakaleaf Pro を運用する場合は、[Toolkit](/ja/on-premises/installation/using-docker-compose) の使用を推奨します。すでに Kubernetes クラスターを運用している場合は、このセクションの手順で、同じコンテナをプレーンな `kubectl` マニフェストを使ってクラスターにデプロイできます。追加のイメージも Helm チャートも不要です。

このセクションを終えると、Sandboxed Compiles を備えた 1 つの Ayakaleaf Pro インスタンス、MongoDB レプリカセット、Redis が、すべて Namespace `overleaf` 内で動作します。ロードバランサーの背後で複数のインスタンスを実行するには、その後 [水平スケーリング](/ja/on-premises/configuration/kubernetes/horizontal-scaling)に進んでください。

<Info>

Kubernetes のサポートは試験的なものです。Helm チャートや Kubernetes 専用のイメージは公開していません。これらのページのマニフェストは、2 vCPU・メモリ 4 GB のノード 3 台で構成した Kubernetes 1.37（kubeadm、containerd 2.4、flannel）でテストしたものです。ストレージ、ネットワーク、Ingress はお使いのクラスターに合わせて調整してください。

</Info>

### 各要素の対応関係 {#how-the-pieces-fit}

| Toolkit（1 台のサーバー）                         | Kubernetes                                                               |
| -------------------------------------------- | ------------------------------------------------------------------------ |
| `config/variables.env`                       | ConfigMap `overleaf-env` と Secret `overleaf-secrets`                   |
| `sharelatex` コンテナ                       | Deployment `overleaf`（すべての Overleaf サービスを実行する 1 つの Pod）            |
| `mongo` と `redis` のコンテナ               | StatefulSet `mongo`（レプリカセット）と `redis`、またはマネージドサービス |
| `~/overleaf-toolkit/data/overleaf`           | PersistentVolumeClaim `overleaf-data`                                    |
| ホスト上の Docker（コンパイルに使用）        | Ayakaleaf Pro を実行するすべてのノード上の Docker Engine                      |
| `bin/up`、`bin/logs`、`bin/shell`            | `kubectl apply`、`kubectl logs`、`kubectl exec`                          |

### 必要なもの {#what-you-need}

* パッケージをインストールできる Kubernetes クラスター: Ayakaleaf Pro を実行する可能性のあるすべてのノードに **Docker Engine** が必要です。コンパイルは、Ayakaleaf Pro がノードの `/var/run/docker.sock` を通じて起動する TeX Live コンテナで実行されるためです。[0. ノードの準備](/ja/on-premises/installation/using-kubernetes/0.-prepare-the-nodes)を参照してください。
* `ReadWriteOnce` ボリュームを提供するデフォルトの StorageClass。
* ワークステーション上の `kubectl` と `openssl`。
