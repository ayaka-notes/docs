title: 1. Ayakaleaf Pro イメージの取得
description: Toolkit と同じ Ayakaleaf Pro イメージを使用します。

---

Kubernetes では Toolkit と同じイメージを実行します。Kubernetes 専用のイメージはありません。

| イメージ                                                | 使用箇所                                                                 |
| ---------------------------------------------------- | ----------------------------------------------------------------------- |
| `ghcr.io/ayaka-notes/overleaf-pro:6.3.2`             | Deployment `overleaf`                                               |
| `ghcr.io/ayaka-notes/overleaf-pro/git-bridge:6.3.2`  | [Git 連携](/ja/on-premises/configuration/kubernetes/integrations/git-integration)（任意）。上と同じタグ |
| `ghcr.io/ayaka-notes/texlive-*`                      | コンパイル。[手順 0](/ja/on-premises/installation/using-kubernetes/0.-prepare-the-nodes) でノードの Docker にプル済み |

イメージは amd64 と arm64 向けに [ghcr.io](https://github.com/ayaka-notes/ayakaleaf-pro/pkgs/container/overleaf-pro/) で公開されているため、kubelet は認証情報なしでプルできます。

<Warning>

`latest` ではなく、`6.3.2` のようなバージョンタグを必ず使用してください。アップグレードではデータベースのマイグレーションが実行されるため、[Kubernetes でのアップグレード](/ja/on-premises/maintenance/upgrading-on-kubernetes)の手順に従う必要があります。変動するタグを使うと、Pod が再スケジュールされるたびにアップグレードされてしまいます。

</Warning>

### Q\&A

<Accordion title="ノードから ghcr.io にアクセスできません。どうすればよいですか？">

<strong>回答：</strong> ノードからアクセスできるレジストリにイメージをコピーし、マニフェストではその名前を使用してください。例:

```bash
docker pull ghcr.io/ayaka-notes/overleaf-pro:6.3.2
docker tag ghcr.io/ayaka-notes/overleaf-pro:6.3.2 registry.example.com/ayakaleaf/overleaf-pro:6.3.2
docker push registry.example.com/ayakaleaf/overleaf-pro:6.3.2
```

TLS のないレジストリの場合、containerd にはすべてのノードで `server = "http://<registry>"` を記述した `/etc/containerd/certs.d/<registry>/hosts.toml` と、[手順 0](/ja/on-premises/installation/using-kubernetes/0.-prepare-the-nodes) のとおりに設定した `config_path` が必要です。Docker 自体はプレーンな HTTP では `localhost` にしかプッシュしないため、レジストリのホスト上で `localhost:<port>` 経由でプッシュするか、`insecure-registries` に追加してください。

</Accordion>
