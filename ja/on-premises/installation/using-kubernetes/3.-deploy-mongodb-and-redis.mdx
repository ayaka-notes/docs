---
title: 3. MongoDB と Redis のデプロイ
description: MongoDB をレプリカセットとして、Redis を永続化付きで実行するか、既存のものを指定します。
icon: database
---

Ayakaleaf Pro には次のものが必要です。

* **レプリカセット**として構成した **MongoDB 8**（トランザクションを使用するため）。3 つのノードに分散した 3 つのメンバーであれば、ノード 1 台の喪失に耐えられます。メンバー 1 つでも動作します。
* AOF 永続化を有効にした 1 台の **Redis 7** サーバー。Redis には、まだ MongoDB に書き込まれていない編集、セッション、Overleaf サービス間のメッセージが保持されます。Overleaf は 1 台の Redis サーバーに接続します。Sentinel と Redis Cluster はサポートされていません。

<Info>

代わりに、MongoDB Atlas やクラウドの Redis などのマネージドサービスを使用することもできます。その場合はこのページをスキップし、[手順 4](/ja/on-premises/installation/using-kubernetes/4.-personalizing-your-instance) で `OVERLEAF_MONGO_URL` と `OVERLEAF_REDIS_HOST` にそれらを設定してください。

</Info>

<Steps>
<Step title="MongoDB">
```yaml title="10-mongo.yaml" wrap
apiVersion: v1
kind: Service
metadata:
  name: mongo
  namespace: overleaf
spec:
  clusterIP: None                 # headless: gives mongo-0.mongo, mongo-1.mongo, ...
  publishNotReadyAddresses: true  # members must resolve each other before the set is initiated
  selector:
    app: mongo
  ports:
    - name: mongo
      port: 27017
---
apiVersion: apps/v1
kind: StatefulSet
metadata:
  name: mongo
  namespace: overleaf
spec:
  serviceName: mongo
  replicas: 3
  selector:
    matchLabels:
      app: mongo
  template:
    metadata:
      labels:
        app: mongo
    spec:
      affinity:
        podAntiAffinity:
          requiredDuringSchedulingIgnoredDuringExecution:
            - labelSelector:
                matchLabels:
                  app: mongo
              topologyKey: kubernetes.io/hostname
      containers:
        - name: mongo
          image: mongo:8.0
          args:
            - --replSet=overleaf
            - --bind_ip_all
            - --wiredTigerCacheSizeGB=0.25   # default is 50% of (RAM - 1 GB); size it for your nodes
          # env:
          #   - name: GLIBC_TUNABLES        # only on kernel 6.19+ (SERVER-121912)
          #     value: glibc.pthread.rseq=1
          ports:
            - containerPort: 27017
          readinessProbe:
            tcpSocket:
              port: 27017
          resources:
            requests:
              cpu: 100m
              memory: 384Mi
            limits:
              memory: 768Mi
          volumeMounts:
            - name: data
              mountPath: /data/db
  volumeClaimTemplates:
    - metadata:
        name: data
      spec:
        accessModes: [ReadWriteOnce]
        resources:
          requests:
            storage: 5Gi
---
# Initiates the replica set once. Safe to re-run: it does nothing when the set exists.
apiVersion: batch/v1
kind: Job
metadata:
  name: mongo-init-replica-set
  namespace: overleaf
spec:
  backoffLimit: 20
  template:
    spec:
      restartPolicy: OnFailure
      containers:
        - name: init
          image: mongo:8.0
          command:
            - mongosh
            - --quiet
            - --host=mongo-0.mongo
            - --eval
            - |
              try {
                rs.status()
                print('replica set already initiated')
              } catch (e) {
                rs.initiate({
                  _id: 'overleaf',
                  members: [
                    { _id: 0, host: 'mongo-0.mongo.overleaf.svc.cluster.local:27017' },
                    { _id: 1, host: 'mongo-1.mongo.overleaf.svc.cluster.local:27017' },
                    { _id: 2, host: 'mongo-2.mongo.overleaf.svc.cluster.local:27017' },
                  ],
                })
              }
```

```bash
kubectl apply -f 10-mongo.yaml
kubectl -n overleaf rollout status statefulset/mongo
kubectl -n overleaf wait --for=condition=complete job/mongo-init-replica-set --timeout=5m
kubectl -n overleaf exec mongo-0 -- mongosh --quiet --eval 'rs.status().members.map(m => m.name + " " + m.stateStr)'
```

数秒後、1 つのメンバーが `PRIMARY`、その他が `SECONDARY` になっているはずです。Job はすべてのメンバーが応答するまで再試行するため、Job の Pod がいくつか失敗するのは正常です。

* ヘッドレス Service には `publishNotReadyAddresses: true` が必要です。レプリカセットが存在する前に、メンバー同士が名前で互いを見つける必要があるためです。
* メンバーは安定した名前（`mongo-0.mongo.overleaf.svc.cluster.local`）で追加します。再起動のたびに変わる Pod の IP は決して使用しないでください。
* メンバーを 1 つにする場合は、`replicas: 1` に設定し、Job には `mongo-0` だけを残してください。
</Step>

<Step title="Redis">
```yaml title="20-redis.yaml" wrap
apiVersion: v1
kind: Service
metadata:
  name: redis
  namespace: overleaf
spec:
  selector:
    app: redis
  ports:
    - name: redis
      port: 6379
---
apiVersion: apps/v1
kind: StatefulSet
metadata:
  name: redis
  namespace: overleaf
spec:
  serviceName: redis
  replicas: 1
  selector:
    matchLabels:
      app: redis
  template:
    metadata:
      labels:
        app: redis
    spec:
      containers:
        - name: redis
          image: redis:7.4
          args: [--appendonly, "yes"]
          ports:
            - containerPort: 6379
          readinessProbe:
            tcpSocket:
              port: 6379
          resources:
            requests:
              cpu: 50m
              memory: 128Mi
            limits:
              memory: 512Mi
          volumeMounts:
            - name: data
              mountPath: /data
  volumeClaimTemplates:
    - metadata:
        name: data
      spec:
        accessModes: [ReadWriteOnce]
        resources:
          requests:
            storage: 2Gi
```

```bash
kubectl apply -f 20-redis.yaml
kubectl -n overleaf rollout status statefulset/redis
```
</Step>

### Q\&A

<Accordion title="新しいカーネルで MongoDB 8 が起動時にクラッシュします。なぜですか？">

<strong>回答：</strong> MongoDB 8 は Linux カーネル 6.19 以降で失敗します（[SERVER-121912](https://jira.mongodb.org/browse/SERVER-121912)）。`10-mongo.yaml` の `GLIBC_TUNABLES` 環境変数のコメントを解除してください。

</Accordion>

<Accordion title="MongoDB にはどのくらいのメモリが必要ですか？">

<strong>回答：</strong> デフォルトでは、MongoDB はノードのメモリから 1 GB を引いた量の半分をキャッシュに使用します。また、参照するのは Pod の制限ではなくノードのメモリです。ノードに合わせて `--wiredTigerCacheSizeGB` を設定してください。4 GB のテストノードでは、`0.25` で各メンバーが約 200〜260 MiB に収まりました。

</Accordion>
