Overleaf Server Pro と同様に、Ayakaleaf Pro は Docker コンテナとして提供され、そのまま置き換えて使用できます。さらに、LDAP や SAML2 による SSO、強化されたセキュリティ、変更履歴、コメント、最適化された TeX Live、テンプレート、管理パネルなどの機能を備えています。

* Ayakaleaf Pro の機能を試したい、またはデモを体験したいだけであれば、[using-the-github-codespace.md](/ja/on-premises/installation/using-the-github-codespace  "mention") のチュートリアルに従ってください。デモ環境では最小構成の TeX Live を使用しているため、一部のプロジェクトは正常にコンパイルできない場合があります。
* これまでどのバージョンの Overleaf もデプロイしたことがない場合は、まず [Docker のセットアップ](/ja/on-premises/installation/setup-docker)を参照して Docker Engine をインストールし、その後 [using-the-toolkit](/ja/on-premises/installation/using-the-toolkit  "mention") に従って Overleaf をインストールしてください。
* すでに Overleaf の Community Edition をデプロイしている場合は、[migrate-from-existing.md](/ja/on-premises/installation/migrate-from-existing  "mention") を参照して Ayakaleaf Pro に移行してください。
* Claude や Codex などのエージェントを使いたい場合は、[using-claude-or-codex.md](/ja/on-premises/installation/using-claude-or-codex  "mention") を参照してください。
* オフラインまたはエアギャップ環境にデプロイする必要がある場合は、[air-gapped-offline-deployments.md](/ja/on-premises/installation/air-gapped-offline-deployments  "mention") を参照してください。
* 既存の Server Pro ユーザーの場合は、テンプレートデータの保存形式が少し異なるため、Ayakaleaf Pro に移行する前に issue を作成してお知らせください。Server Pro から Ayakaleaf Pro への移行を無償で喜んでお手伝いします。
* もし Ayakaleaf Pro に満足できず、公式の Overleaf Community Edition に戻したくなった場合も、完全にサポートされています。データが失われることはありません。公式の Overleaf Toolkit を使用している場合は、override YAML ファイルを削除するだけです。ayaka-notes toolkit を使用している場合は、`SERVER_PRO` オプションを無効にしてください。これで標準の Community Edition に戻ります。

### ハードウェア要件

私たちのテストでは、2 コア・2 GB RAM のサーバーで Overleaf を実行すると、主に Node.js ベースのコアコンポーネントが約 1 GB のメモリを消費することがわかりました。Redis と MongoDB にはさらに 0.5 GB 程度が必要になる場合があり、コンパイル用のサンドボックス Docker コンテナを起動するとさらに 0.3 GB を消費することがあります。つまり、2 コア・2 GB のサーバーで現実的に処理できる同時コンパイルは 1 件程度です。

* Ayakaleaf Pro をインストールするための最小ハードウェア要件は、2 コア CPU と 3 GB の RAM です。
* TeX Live イメージのサイズが大きいため、サンドボックスコンパイルを有効にするには少なくとも 40 GB のストレージが必要です。
* 2020 年から 2026 年までの TeX Live イメージをすべてインストールする場合は、少なくとも 150 GB の空きディスク容量を確保してください。

利用シナリオ別の推奨ハードウェア構成は次のとおりです。

| ユースケース | 推奨構成 |
| ---------------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| 個人利用（ときどき共同作業する程度） | 2 CPU コア、4 GB RAM、80 GB ストレージ |
| 小規模チーム（最大 10 ユーザー、軽い共同作業） | 2 CPU コア、8 GB RAM、256 GB ストレージ |
| 中規模チーム（最大 100 ユーザー） | 4 CPU コア、16 GB RAM、1 TB ストレージ |
| 大規模または大学でのデプロイ | S3 ストレージを使用した分散クラスターデプロイ。デプロイの支援が必要な場合はお問い合わせください |

### ソフトウェア要件

ソフトウェア要件としては、新しく安定したバージョンの Ubuntu（例：2025〜2026 年なら Ubuntu 24.04、2023〜2024 年なら Ubuntu 22.04）と、最新の安定版 Docker の組み合わせをおすすめします。

<Info>

安定性を最優先してください。リリースされたばかりのものではなく、リリースからある程度時間が経った最新の Ubuntu LTS を選んでください。たとえば 2026 年 10 月時点では、Ubuntu 26.04 はサポートされていません。Linux カーネル 7.0 を搭載しており、MongoDB は Linux カーネル 6.19 から 7.0.13 では起動しないためです（[詳細](https://www.mongodb.com/docs/manual/administration/production-notes/)）。Ubuntu 24.04 を使用してください。

</Info>

Windows や CentOS などのサポート対象外のオペレーティングシステムに Ayakaleaf Pro をデプロイすることはおすすめしません。インストールや運用中に互換性の問題や予期しない問題が発生する可能性があります。

ただし、ARM ベースのシステムや macOS で Ayakaleaf Pro のデプロイを試してみたい場合は、その経験やフィードバックをぜひコミュニティで共有してください。

### LaTeX のパフォーマンス

LaTeX はシングルスレッドのプログラムであり、一度に 1 つの CPU コアしか使用できません。1 つのドキュメントをコンパイルする場合、パフォーマンスは主に CPU のシングルコアのクロック速度によって制限されます。そのため、CPU のシングルコア性能が高いほど、ドキュメントを速くコンパイルできます。CPU コア数が多いことが役立つのは、複数のユーザーが同時にドキュメントをコンパイルする場合だけです。

[ThuThesis テンプレート](https://www.overleaf.com/latex/templates/thuthesis-tsinghua-university-thesis-latex-template/cfwgcxtvkbsx)を例にとると、コンパイル時間は Intel Core i9-14900K（5.6 GHz）では約 6 秒ですが、AMD EPYC 7763（3.2 GHz）を搭載した Azure Standard D2as v5 インスタンス（2 vCPU、8 GiB RAM）では約 13 秒かかります。

もちろん、実際のコンパイル性能はハードウェア構成によって異なります。ほとんどのサーバー向け CPU は 14900K ほど高いクロック速度では動作しないため、コストとコンパイル速度のトレードオフを考える必要があります。

また、LaTeX のコンパイル性能についても詳細な分析を行っています。興味があれば、ブログ記事 [Overleaf Benchmark: A Deep Research of Concurrent LaTeX Compilation in Overleaf (SaaS and Self-host)](/ja/blog/2026/overleaf-benchmark  "mention") を参照してください。
