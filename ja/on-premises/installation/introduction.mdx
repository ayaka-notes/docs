Overleaf Server Pro と同様に、Ayakaleaf Pro は Docker コンテナとして提供され、そのまま置き換えて使用できます。さらに、LDAP や SAML2 による SSO、強化されたセキュリティ、変更履歴、コメント、最適化された TeX Live、テンプレート、管理パネルなどの機能を備えています。

* Ayakaleaf Pro の機能をテストしたい、またはデモを試してみたいだけの場合は、[using-the-github-codespace.md](/ja/on-premises/installation/using-the-github-codespace  "mention") のチュートリアルに従ってください。デモ環境は最小構成の TeX Live を使用しているため、一部のプロジェクトは正常にコンパイルできない場合があります。
* これまでに Overleaf をデプロイしたことがない場合は、まず [Docker のセットアップ](/ja/on-premises/installation/setup-docker)を参照して Docker Engine をインストールし、その後 [using-the-toolkit](/ja/on-premises/installation/using-the-toolkit  "mention") に従って Overleaf をインストールしてください。
* すでに Overleaf Community Edition をデプロイしている場合は、[migrate-from-existing.md](/ja/on-premises/installation/migrate-from-existing  "mention") を参照して Ayakaleaf Pro に移行してください。
* Claude や Codex などのエージェントを使用したい場合は、[using-claude-or-codex.md](/ja/on-premises/installation/using-claude-or-codex  "mention") を参照してください。
* オフラインまたはエアギャップ環境にデプロイする必要がある場合は、[air-gapped-offline-deployments.md](/ja/on-premises/installation/air-gapped-offline-deployments  "mention") を参照してください。
* 既存の Server Pro ユーザーの場合は、テンプレートデータの保存形式が若干異なるため、Ayakaleaf Pro に移行する前に issue を作成してお知らせください。Server Pro から Ayakaleaf Pro への移行を無償で喜んでお手伝いします。
* Ayakaleaf Pro に飽きて公式の Overleaf Community Edition に戻したくなった場合も、完全にサポートされています。データが失われることはありません。公式の Overleaf Toolkit のユーザーは、override YAML ファイルを削除するだけです。ayaka-notes toolkit のユーザーは、`SERVER_PRO` オプションを無効にしてください。これですべてが標準の Community Edition に戻ります。

ニーズに応じてインストール方法を選択してください。

### ハードウェア要件

私たちが行ったテストでは、2 コア、2 GB RAM のサーバーで Overleaf を実行すると、主に Node.js ベースのコアコンポーネントが約 1 GB のメモリを消費することがわかりました。Redis と MongoDB にはさらに 0.5 GB が必要になる場合があり、コンパイル用のサンドボックス化された Docker コンテナを起動するとさらに 0.3 GB を消費することがあります。つまり、2 コア、2 GB のサーバーで現実的に処理できる同時コンパイルは、一度に 1 件程度です。

* Ayakaleaf Pro をインストールするための最小ハードウェア要件は、2 コア CPU と 3 GB の RAM です。
* TeX Live イメージのサイズが大きいため、サンドボックスコンパイルを有効にするには少なくとも 40 GB のストレージが必要です。
* 2020 年から 2026 年までの TeX Live イメージをすべてインストールする場合は、少なくとも 150 GB の空きディスク容量を確保してください。

以下は、利用シナリオ別の推奨ハードウェア構成です。

| ユースケース                                             | 推奨構成                                                                            |
| ---------------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| 個人利用（ときどき共同作業あり）          | 2 CPU コア、4 GB RAM、80 GB ストレージ                                                                 |
| 小規模チーム（最大 10 ユーザー、軽度の共同作業） | 2 CPU コア、8 GB RAM、256 GB ストレージ                                                                |
| 中規模チーム（最大 100 ユーザー）                  | 4 CPU コア、16 GB RAM、1 TB ストレージ                                                                 |
| 大規模または大学でのデプロイ                | S3 ストレージを使用した分散クラスター構成。デプロイの支援が必要な場合はお問い合わせください |

### ソフトウェア要件

ソフトウェア要件としては、新しく安定したバージョンの Ubuntu（例：2025〜2026 年なら Ubuntu 24.04、2023〜2024 年なら Ubuntu 22.04）と、最新の安定版 Docker を組み合わせて使用することをおすすめします。

<Info>

安定性を最優先してください。リリースされたばかりのものではなく、リリースからしばらく経った最新の Ubuntu LTS を選択してください。たとえば、2026 年 10 月時点では Ubuntu 26.04 はサポートされていません。Ubuntu 26.04 には Linux カーネル 7.0 が搭載されていますが、MongoDB は Linux カーネル 6.19 から 7.0.13 では起動しないため（[詳細](https://www.mongodb.com/docs/manual/administration/production-notes/)）、Ubuntu 24.04 を使用してください。

</Info>

Windows や CentOS などのサポート対象外のオペレーティングシステムに Ayakaleaf Pro をデプロイすることはおすすめしません。インストールや運用の際に互換性の問題や予期しない問題が発生する可能性があります。

ただし、ARM ベースのシステムや macOS で Ayakaleaf Pro のデプロイを試してみたい場合は、ぜひその経験やフィードバックをコミュニティで共有してください。

### LaTeX のパフォーマンス

LaTeX はシングルスレッドのプログラムであり、一度に 1 つの CPU コアしか利用できません。1 つのドキュメントをコンパイルする場合、パフォーマンスは主に CPU のシングルコアのクロック速度によって制限されます。したがって、CPU のシングルコア性能が高いほど、ドキュメントを高速にコンパイルできます。CPU コアを増やすことが有効なのは、複数のユーザーが同時にドキュメントをコンパイルする場合だけです。

[ThuThesis テンプレート](https://www.overleaf.com/latex/templates/thuthesis-tsinghua-university-thesis-latex-template/cfwgcxtvkbsx)を例にすると、Intel Core i9-14900K（5.6 GHz）ではコンパイル時間が約 6 秒であるのに対し、AMD EPYC 7763（3.2 GHz）を搭載した Azure Standard D2as v5 インスタンス（2 vCPU、8 GiB RAM）では約 13 秒かかります。

もちろん、実際のコンパイル性能はハードウェア構成によって異なります。ほとんどのサーバー向け CPU は 14900K ほど高いクロック速度では動作しないため、コストとコンパイル速度のトレードオフを考慮する必要があります。

また、LaTeX のコンパイル性能についても詳細な分析を行っています。興味のある方は、ブログ記事 [Overleaf Benchmark: A Deep Research of Concurrent LaTeX Compilation in Overleaf (SaaS and Self-host)](/ja/blog/2026/overleaf-benchmark  "mention") を参照してください。
