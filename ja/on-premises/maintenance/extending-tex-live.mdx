新しい Dockerfile を使って既存の TeX Live イメージを拡張し、アプリケーションがその新しいイメージを使用するように設定できます。

ここでは新しいパッケージやフォントをインストールするためのガイドラインを紹介しますが、カスタムイメージの設定はサポート対象外です。

TeX Live イメージの更新頻度は高くありません。Server Pro をアップグレードする際には、カスタムイメージを再ビルドすることをおすすめします。

<Danger>

以下のセクションは Server Pro と [Sandboxed Compiles](/ja/on-premises/configuration/overleaf-toolkit/sandboxed-compiles) にのみ適用されます。

</Danger>

### 新しいパッケージのインストールと更新

次の例のように、`tlmgr install` や `tlmgr update` などの `tlmgr` コマンドを使用して TeX Live のパッケージを管理できます。

```dockerfile
FROM ghcr.io/ayaka-notes/texlive-full:2023.1

RUN tlmgr update --force ebproof
```

### 古い TeX Live イメージで `tlmgr` を使用する

デフォルトでは、`tlmgr` は最新の TeX Live リリースからリソースをダウンロードします。古い TeX Live イメージにパッチを適用する場合は、ダウンロード元を該当するアーカイブに切り替える必要があります。アーカイブのミラーについては [https://www.tug.org/historic/](https://www.tug.org/historic/) の一覧を参照してください。

```dockerfile
FROM ghcr.io/ayaka-notes/texlive-full:2022.1

RUN tlmgr option repository <MIRROR>/systems/texlive/<YEAR>/tlnet-final
# e.g. RUN tlmgr option repository ftp://tug.org/historic/systems/texlive/2022/tlnet-final

RUN tlmgr update --force ebproof
```

### 新しいフォントのインストール

TeX Live ディストリビューションに新しいフォントをインストールする手順はいくつかあり、カスタムフォントのインストールには複数のステップが必要になる場合があります。まずは TeX Live の公式ドキュメントにある [TeX フォントのインストール手順](https://tug.org/fonts/fontinstall.html)を確認するのがよいでしょう。

次の `Dockerfile` は、既存の TeX Live 2022 イメージに TrueType フォントをインストールする例です。

```dockerfile
FROM ghcr.io/ayaka-notes/texlive-full:2022.1

COPY ./myfonts/*.ttf /usr/share/fonts/truetype/myfont/

# rebuild font information cache
RUN fc-cache
```

### 新しいイメージを使用するよう Server Pro を設定する

次のように、`ghcr.io/ayaka-notes/texlive-full` という名前とカスタムタグを使用して新しいイメージをビルドします。

```bash
docker build -t ghcr.io/ayaka-notes/texlive-full:2023.1-custom
```

これで、`TEX_LIVE_DOCKER_IMAGE` および `ALL_TEX_LIVE_DOCKER_IMAGES` 環境変数を更新して、新しい `2023.1-custom` イメージを使用するよう Server Pro を設定できます。

```text wrap
TEX_LIVE_DOCKER_IMAGE: "ghcr.io/ayaka-notes/texlive-full:2023.1-custom"
ALL_TEX_LIVE_DOCKER_IMAGES: "ghcr.io/ayaka-notes/texlive-full:2023.1,ghcr.io/ayaka-notes/texlive-full:2023.1-custom"
```

上の例では、新しいプロジェクトはデフォルトで新しい `2023.1-custom` イメージを使用するように設定され、`2023.1` も必要なときに引き続き利用できます。
