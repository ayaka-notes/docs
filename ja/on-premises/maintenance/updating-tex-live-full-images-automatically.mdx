---

通常、`bin/up` を実行するたびに、[using-the-toolkit](/ja/on-premises/installation/using-the-toolkit  "mention") が TeX Live full イメージを自動的に更新します。手動での更新を避けたい場合は、次のスクリプトを使用して TeX Live サンドボックスイメージの更新を自動化できます。cron ジョブとして追加し、cron ユーザーに `docker` を実行する権限があることを確認してください。`crontab -e` を実行して、次の行を末尾に追加します。

```cron title="crontab -e"
0 * * * * /usr/bin/flock -n /tmp/pull-texlive.lock /usr/local/bin/pull-texlive.sh
```

`flock -n` は、前回の実行がまだロックを保持している間は実行をスキップするため、時間のかかる pull が積み重なることはありません。

<Tabs>
<Tab title="直接接続">

```bash title="/usr/local/bin/pull-texlive.sh"
#!/usr/bin/env bash
set -uo pipefail

IMAGE="ghcr.io/ayaka-notes/texlive-full"
TAGS=(2020.1 2021.1 2022.1 2023.1 2024.1 2025.1 2026.1)
LOG=/var/log/pull-texlive.log

exec >>"$LOG" 2>&1

# Hours since the epoch, modulo the tag count: one tag per hour,
# so all 7 tags are refreshed every 7 hours.
idx=$(( $(date +%s) / 3600 % ${#TAGS[@]} ))
tag="${TAGS[$idx]}"

echo "===== $(date -Is) pulling $tag (idx=$idx) ====="

if timeout 50m docker pull "$IMAGE:$tag"; then
  echo "OK   $tag"
else
  echo "FAIL $tag (exit $?)"
fi

docker image prune -f
docker system df | tail -n +2
```

</Tab>

<Tab title="ミラーサイトを使用">

```bash title="/usr/local/bin/pull-texlive.sh"
#!/usr/bin/env bash
set -uo pipefail

MIRROR="ghcr.nju.edu.cn"
CANONICAL="ghcr.io"
REPO="ayaka-notes/texlive-full"
TAGS=(2020.1 2021.1 2022.1 2023.1 2024.1 2025.1 2026.1)
LOG=/var/log/pull-texlive.log

exec >>"$LOG" 2>&1

# Hours since the epoch, modulo the tag count: one tag per hour,
# so all 7 tags are refreshed every 7 hours.
idx=$(( $(date +%s) / 3600 % ${#TAGS[@]} ))
tag="${TAGS[$idx]}"

echo "===== $(date -Is) pulling $tag (idx=$idx) via $MIRROR ====="

if timeout 50m docker pull "$MIRROR/$REPO:$tag"; then
  # Retag to the canonical name the compiler is configured with. This only
  # adds a second name for the same layers; nothing is copied.
  docker tag "$MIRROR/$REPO:$tag" "$CANONICAL/$REPO:$tag"
  echo "OK   $tag"
else
  echo "FAIL $tag (exit $?)"
fi

docker image prune -f
docker system df | tail -n +2
```

</Tab>
</Tabs>

**すべてを一度に pull するのではなく 1 時間ごとにローテーションする理由**：タグは現在時刻（エポックからの経過時間をタグ数で割った余り）から導出されるため、ジョブはステートレスです。「どこまで進んだか」を記録するものは何もなく、再起動や実行されなかった時間があってもサイクルは自動的に元に戻ります。各実行で扱うタグは 1 つだけです。レジストリのダイジェストが変わっていなければ、pull はマニフェストの確認（`Image is up to date`）のみで、数秒で完了します。実際の更新では 1 時間あたり最大 1 つのイメージをダウンロードし、`timeout 50m` で上限が設けられています。また、`docker image prune -f` によって、タグの移動で不要になったレイヤーが削除されます。

同期が正常に行われているかを確認するには、次を実行します。

```bash
tail -20 /var/log/pull-texlive.log     # each run ends with "OK <tag>" or "FAIL <tag>"
grep -c '^FAIL' /var/log/pull-texlive.log
```

新しい TeX Live リリースが公開されたら、そのタグを `TAGS` 配列に追加してください。ローテーションの長さは自動的に調整されます。ホストの電源が切れていた時間はキューに入らずスキップされ、該当するタグは次の順番が来たときに更新されます。
