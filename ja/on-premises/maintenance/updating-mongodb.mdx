<Info>

Server CE/Server Pro の新しいリリースでは、サポートされる MongoDB のバージョンに変更がある場合、その[リリースノート](https://docs.overleaf.com/on-premises/release-notes)に記載されます。

</Info>

### MongoDB を更新すべきか？

MongoDB のバージョンの更新は、Server CE/Server Pro のインスタンスをアップグレードする予定がある場合に**のみ**検討してください。

現在の（または移行先の）バージョンで推奨されているものより新しいバージョンの MongoDB を実行している場合は、何も変更する必要はありません。

<Warning>

MongoDB のバージョンを決してダウングレードしないでください。

</Warning>

現在の MongoDB のバージョンに関連すると思われる特定の問題が発生した場合は、Server CE ユーザーであれば気軽に [Issue を作成](https://github.com/overleaf/overleaf/issues)し、Server Pro ユーザーであれば Overleaf サポートにお問い合わせください。

### 更新プロセス

Server CE/Server Pro インスタンスのアップグレード時に MongoDB のバージョンを更新する手順は次のとおりです：

1. アップグレード先の Server CE/Server Pro のバージョンを決定します。
2. その Overleaf Server CE/Server Pro リリースで推奨されている MongoDB のバージョンを確認します。
3. 手順に従って、MongoDB を目的のバージョンにアップグレードします。
4. Server CE/Server Pro のイメージバージョンをアップグレードし、インスタンスを再起動します。

**Server CE/Server Pro** は、常に利用可能な最新バージョンにアップグレードすることを推奨します。最新バージョンは常にサポートが保証されているためです（Server Pro ユーザーのみ）。

<Danger>

Server CE/Pro をアップグレードする際は、**次の**メジャーバージョンの最新リリースにアップグレードする**前に**、導入済みのメジャーバージョンの最新リリースにアップグレードすることを推奨します。導入環境が最新から 2 つ以上のメジャーバージョン遅れている場合は、複数段階のアップグレードを行う必要があります。

たとえば 3.5.10 を実行している場合は、3.5.13 にアップグレード -> 完全なプロジェクト履歴への移行を実行 -> 4.2.9 -> 5.5.4 の順にアップグレードする必要があります。

メジャーバージョンを**決して**飛ばさないでください（3.5.10 -> 5.5.4）。Toolkit を使用していて、最新から 2 つ以上のメジャーバージョン遅れている場合は、手動で複数段階のアップグレードを行う必要があるため、`bin/upgrade` スクリプトを使用**しないでください**。

</Danger>

<Warning>

必要に応じてロールバックできるよう、メジャーバージョンのアップグレードの**前に**毎回必ず[整合性のあるバックアップ](/ja/on-premises/maintenance/data-and-backups#performing-a-consistent-backup)を取得することが重要です。

</Warning>

#### MongoDB をアップグレードする

MongoDB では**段階的なアップグレード**が必要です。つまり、たとえば `4.0` から `5.0` に直接アップグレードすることはできません。まず `4.2` から `4.4` に、次に `5.0` に更新する必要があります。

<Info>

MongoDB では、安定版に偶数のバージョン番号が使用されています。

</Info>

#### **Docker の外部で MongoDB を実行している場合の更新手順**

MongoDB をアップグレードする際の、mongodb.com の更新手順へのリンクは次のとおりです。

* [MongoDB リリースノート - MongoDB を `4.2` から `4.4` にアップグレードする](https://www.mongodb.com/docs/v4.4/release-notes/4.4-upgrade-standalone/)
* [MongoDB リリースノート - MongoDB を `4.4` から `5.0` にアップグレードする](https://www.mongodb.com/docs/v5.0/release-notes/5.0-upgrade-replica-set/)
* [MongoDB リリースノート - MongoDB を `5.0` から `6.0` にアップグレードする](https://www.mongodb.com/docs/v6.0/release-notes/6.0-upgrade-replica-set/)
* [MongoDB リリースノート - MongoDB を `6.0` から `7.0` にアップグレードする](https://www.mongodb.com/docs/manual/release-notes/7.0-upgrade-replica-set/#std-label-7.0-upgrade-replica-set)
* [MongoDB リリースノート - MongoDB を `7.0` から `8.0` にアップグレードする](https://www.mongodb.com/docs/manual/release-notes/8.0-upgrade-replica-set/#std-label-8.0-upgrade-replica-set)

<Info>

`5.0` 以降の手順は、スタンドアロンではなくレプリカセット構成のインストールを対象としています。Server Pro/CE 4.0.1 以降ではトランザクションを使用するため、MongoDB をレプリカセットとして実行する必要があります。

</Info>

<Warning>

MongoDB 3.2 〜 4.2 のドキュメントは、現在 [https://www.mongodb.com/docs/legacy/](https://www.mongodb.com/docs/legacy/) から参照できます。

</Warning>

**基本的な手順**

ほとんどの場合、更新では実際に mongo のバージョンを更新する前に互換性フラグを設定する必要があります。手順は次のとおりです：

1. MongoDB のリリースノートに記載されているとおりに互換性フラグを設定します（以下の例を参照）。
2. 次に mongo イメージを更新します：
   1. **Toolkit ユーザー** `MONGO_VERSION` を更新します。例：`MONGO_VERSION=6.0`
   2. **Docker Compose ユーザー** `mongo` イメージのタグのバージョンを更新します。\
      例：`services -> mongo -> image: mongo:6.0`

**例：MongoDB を `5.0` から `6.0` にアップグレードする**

まず、MongoDB `6.0` を実行していることを確認しましょう：

Overleaf Toolkit ユーザーの場合：

```bash
bin/docker-compose exec mongo mongod --version
# db version v5.0.24
```

Docker Compose ユーザーの場合：

```bash
docker compose exec mongo mongod --version
# db version v5.0.24
```

[アップグレード手順](https://docs.mongodb.com/manual/release-notes/3.6-upgrade-standalone/#upgrade-version-path)によると、唯一の要件は `featureCompatibilityVersion` を `5.0` に設定することです。MongoDB シェルを開いて、指示されたコマンドを実行します：

Overleaf Toolkit ユーザーの場合：

```bash
bin/mongo
# MongoDB shell version v5.0.24
# ...
# overleaf:PRIMARY> db.adminCommand( { setFeatureCompatibilityVersion: "5.0" } )
# { 
# "ok" : 1,
# ...
# }
overleaf:PRIMARY> exit
# bye
```

<Info>

Docker Compose ユーザーは、`docker compose exec mongo mongosh` を実行してシェルを開き、Toolkit ユーザーと同じコマンドを実行できます。

</Info>

Overleaf Toolkit ユーザーの場合：

次に、`bin/stop` コマンドを使用して Server CE/Server Pro と MongoDB のインスタンスを停止し、`config/overleaf.rc` で `MONGO_VERSION=6.0` を設定してから、`bin/up mongo` を使用して `mongo` サービスを再起動し、更新が問題なく完了したことを確認します。

最後に、Server CE/Server Pro のイメージバージョンを目的のバージョンに更新し、`bin/up -d` コマンドを使用してすべてのサービスを再作成します。

Docker Compose ユーザーの場合：

次に、`docker compose stop` コマンドを使用して Server CE/Server Pro と MongoDB のインスタンスを停止し、[`docker-compose.yml`](https://github.com/overleaf/overleaf/blob/4b1babd4ea634ab12c54e9a9aea7db0e8a500941/docker-compose.yml) ファイルを `image: mongo:6.0` を使用するように更新してから、`docker compose up mongo` コマンドを使用して `mongo` サービスを再起動し、更新が問題なく完了したことを確認します。

最後に、Server CE/Server Pro のイメージバージョンを目的のバージョンに更新し、`docker compose up` コマンドを使用してすべてのサービスを再作成します。

**例：MongoDB を `6.0` から `7.0` にアップグレードする（Toolkit ユーザー）**

まず、上記の `mongod --version` コマンドを使用して、MongoDB `6.0` を実行していることを確認します。

[アップグレード手順](https://www.mongodb.com/docs/manual/release-notes/7.0-upgrade-replica-set/#std-label-7.0-upgrade-replica-set)によると、唯一の要件は `featureCompatibilityVersion` を `6.0` に設定することです。MongoDB シェルを開いて、コマンド `db.adminCommand({ setFeatureCompatibilityVersion: "6.0" })` を実行します。

Overleaf Toolkit ユーザーの場合：

```bash
bin/mongo
# ...
# overleaf:PRIMARY> db.adminCommand( { setFeatureCompatibilityVersion: "6.0" } )
# { 
# "ok" : 1,
# ...
# }
overleaf:PRIMARY> exit
# bye
```

次に、`bin/stop` コマンドを使用して Server CE/Server Pro と MongoDB のインスタンスを停止し、`config/overleaf.rc` で `MONGO_VERSION=7.0` を設定してから、`bin/up mongo` を使用して `mongo` サービスを再起動し、更新が問題なく完了したことを確認します。

最後に、Server CE/Server Pro のイメージバージョンを目的のバージョンに更新し、`bin/up -d` コマンドを使用してすべてのサービスを再作成します。

**例：MongoDB を `7.0` から `8.0` にアップグレードする（Toolkit ユーザー）**

まず、上記の `mongod --version` コマンドを使用して、MongoDB `7.0` を実行していることを確認します。

[アップグレード手順](https://www.mongodb.com/docs/manual/release-notes/8.0-upgrade-replica-set/#std-label-8.0-upgrade-replica-set)によると、唯一の要件は `featureCompatibilityVersion` を `7.0` に設定することです。MongoDB シェルを開いて、コマンド `db.adminCommand({ setFeatureCompatibilityVersion: "7.0", confirm: true })` を実行します。これには追加の `confirm: true` パラメータが必要になったことに注意してください。

```bash
bin/mongo
# ...
# overleaf:PRIMARY> db.adminCommand( { setFeatureCompatibilityVersion: "7.0", confirm: true } )
# { 
# "ok" : 1,
# ...
# }
overleaf:PRIMARY> exit
# bye
```

次に、`bin/stop` コマンドを使用して Server CE/Server Pro と MongoDB のインスタンスを停止し、`config/overleaf.rc` で `MONGO_VERSION=8.0` を設定してから、`bin/up mongo` を使用して `mongo` サービスを再起動し、更新が問題なく完了したことを確認します。

最後に、Server CE/Server Pro のイメージバージョンを目的のバージョンに更新し、`bin/up -d` コマンドを使用してすべてのサービスを再作成します。

#### Docker Compose ユーザー向けの同等のコマンド

Docker Compose ユーザーの場合、同等のコマンドは次のとおりです：

* `docker compose exec mongo mongod --version`：mongo のバージョンを表示します
* `docker compose exec mongo mongosh`：管理コマンド用の mongo シェルを起動します
* `docker compose stop` コマンド：サーバーを停止します
* [`docker-compose.yml`](https://github.com/overleaf/overleaf/blob/4b1babd4ea634ab12c54e9a9aea7db0e8a500941/docker-compose.yml) ファイルを `image: mongo:6.0` を使用するように編集して、mongo のバージョンをアップグレードします
* `docker compose up mongo`：mongo サービスを再起動し、更新が問題なく完了したことを確認します
* [`docker-compose.yml`](https://github.com/overleaf/overleaf/blob/4b1babd4ea634ab12c54e9a9aea7db0e8a500941/docker-compose.yml) ファイルを `image: sharelatex:VERSION` を使用するように編集して、イメージのバージョンをアップグレードします
* `docker compose up`：すべてのサービスを再作成します。

### カスタムロールを作成する

バージョン `5.5.1` では、MongoDB の機能互換バージョンを確認する起動時チェックが導入されました。MongoDB データベースで認証（基本認証など）を使用している場合、`sharelatex` コンテナが起動せず、「_not authorized on admin to execute command_」という権限エラーが表示されることがあります。

これを解決するには、以下の手順に従って MongoDB で新しいロールを作成し、データベースへのアクセスに使用するユーザーアカウントに割り当てるか、`ALLOW_MONGO_ADMIN_CHECK_FAILURES=true` を設定して、チェックが失敗しても導入環境の起動が妨げられないようにします。

<Check>

この新しいロールが付与するのは、クラスター全体の MongoDB サーバーパラメータを読み取る権限**のみ**であり、監視目的で再利用することもできます。

</Check>

```bash wrap
# Toolkit users
$ bin/docker-compose exec -it mongo mongosh -u {{YOUR-ADMIN-USERNAME}} -p

# Switch to the "admin" database using
overleaf [direct: primary] sharelatex> use admin
switched to db admin
overleaf [direct: primary] admin> 

# Create a new role with permission to use "getParamter". Copy and paste the function below into the shell and press the return key

db.createRole(
  {
    role: "clusterParameterReader",
    privileges: [
      {
        resource: { cluster: true },
        actions: ["getParameter"]    
      }
    ],
    roles: [] 
  }
);

# Switch back to the "sharelatex" database 
use sharelatex
switched to db sharelatex
overleaf [direct: primary] sharelatex> 

# Assign the new "clusterParameterReader" role to your database user by copy and pasting the function below into the shell and press the return key 
db.grantRolesToUser(
  "{{YOUR-DATABASE-USER}}",
  [
    { role: "clusterParameterReader", db: "admin" }
  ]
);

# Type exit then return to exit the MongoDB shell
# Run bin/up -d to start the deployment stack
$ bin/up -d
```
