title: デプロイのアップグレード
icon: arrow-up-from-square
---

<Danger>

必要に応じてロールバックできるよう、メジャーバージョンをアップグレードする**前**には必ず [整合性のあるバックアップ](/ja/on-premises/maintenance/data-and-backups#performing-a-consistent-backup) を取得することが重要です。

</Danger>

[ayakaleaf toolkit↗](https://github.com/ayaka-notes/toolkit) は git リポジトリなので、Toolkit の新機能を簡単に取得できます。`bin/upgrade` コマンドを実行し、画面の指示に従うだけです。

なお、Docker イメージのバージョン（`config/version`）は、Toolkit のコードの更新とは別に管理されています。Toolkit のコードを更新しても、実行中の Docker イメージのバージョンが自動的に変更されることは**ありません**。つまり、ほとんどの場合、デプロイをアップグレードせずに Toolkit のバージョンだけをアップグレードできます。

#### `bin/upgrade` スクリプト

`bin/upgrade` コマンドを実行すると、スクリプトは Toolkit のコードに利用可能な更新があるかどうかを確認し、Toolkit の更新を提案します。このアップグレードはいつでも拒否でき、その場合は何も変更されません。

Toolkit のコードを更新することを選んだ場合、スクリプトは次に _デフォルト_ の Docker イメージのバージョンが変更されているかどうかを確認し、ローカルのバージョンファイル（`config/version`）を新しいデフォルトに合わせてアップグレードするよう提案します。

バージョンを切り替えることを選んだ場合、スクリプトは Docker サービスの停止、バックアップの取得、Docker サービスの再起動という一連の手順を案内します。古いバージョンファイルは、その Docker イメージのバージョンにロールバックする必要が生じた場合に備えて、自動的に `config/__old-version` にコピーされます。

<Info>

Docker イメージを手動でインポートするエアギャップ環境では、`config/overleaf.rc` ファイルで `PULL_BEFORE_UPGRADE=false` を設定してください。

エアギャップ／オフライン環境でのデプロイの詳細については、[こちら](/ja/on-premises/installation/air-gapped-offline-deployments) を確認してください。

</Info>

### アップグレードパス

v6.0.0 より前の Overleaf Community を実行している場合は、[Overleaf の公式ドキュメント](https://docs.overleaf.com/on-premises/maintenance/upgrading-your-deployment#upgrade-path) を参照してアップグレードを完了してください。
