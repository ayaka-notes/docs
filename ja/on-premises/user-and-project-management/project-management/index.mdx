### プロジェクトの監査ログを表示する

管理者は、各プロジェクトの**監査ログ（Audit Log）**を確認できます。この監査ログには、リンク共有がプライベートとトークンベースの間で変更されたとき、招待が送信／承認されたとき、ユーザーがトークンを使用してプロジェクトに参加したときなどのイベントが表示されます。管理者は、**Your Instance** -> **Admin** -> **Manage Users** からプロジェクトごとにこれらのログを表示できます。手順は次のとおりです：

* ユーザーを検索する
* **Projects** タブをクリックする
* プロジェクトを選択する
* (i) アイコンをクリックする
* **Audit Log** タブをクリックする

プロジェクトが（メールアドレスを使用して）指定の共同編集者と共有されている場合、受信者が参加すると、その共同編集者は権限とともに共有モーダルに表示され、プロジェクトのオーナーが確認できるようになります。この情報は、管理者が管理パネルからプロジェクトの Project Info タブを表示したときにも表示されます。

### 削除されたドキュメントを復元する

1. 管理者の認証情報でログインします
2. **Admin** をクリックし、**Manage Users** を選択します
3. 検索フィールドに、ドキュメントを復元したいユーザーのメールアドレスを入力します
4. 検索結果の一覧からそのユーザーのメールアドレスをクリックし、ユーザー情報ページを開きます
5. **Projects** タブをクリックし、検索フィールドを使用してプロジェクトを検索します
6. プロジェクト名の横にある情報アイコンをクリックし、**Project Info** を開きます
7. **Deleted Docs** タブをクリックします
8. 削除されたドキュメントの横にある **Undelete** ボタンをクリックし、ユーザーのプロジェクトに復元します。

復元されたファイルは `FILENAME-TIMESTAMP.EXTENSION` という形式になります。たとえば、`main.tex` を復元すると、`main-2024-02-23-130441542.tex` というファイル名でプロジェクトのルートに復元されます。

### プロジェクトの所有権を移譲する

Server Pro の管理パネルには、プロジェクトごとに専用のページがあります。このページには、"/admin/user" でユーザーを検索して **Projects** タブに移動し、一覧からプロジェクトを見つけて情報アイコンをクリックするか、既知のプロジェクト ID を使って [**https://your-instance-url/admin/project/**](https://your-instance-url/admin/project/) のページに直接移動することでアクセスできます。プロジェクト情報ページには **Transfer Ownership** ボタンがあり、クリックするとモーダルが開き、任意のユーザーを新しいオーナーとして指定できます。新しいオーナーは、プロジェクトの既存の共同編集者である必要はありません。

<Info>

所有権の移譲処理の一環として、以前のオーナーは読み取り・書き込みアクセス権を持つ共同編集者としてプロジェクトに追加されることに注意してください。

</Info>

### プロジェクトのコンパイルタイムアウトを更新する

プロジェクトのデフォルトのコンパイルタイムアウトは、現在 180 秒に設定されています。この値は変更可能で、2 段階の手順が必要です。

まず、**config/variables.env** ファイルを編集して `COMPILE_TIMEOUT` 環境変数を追加し、その値を目的のタイムアウト（秒単位）に設定します。たとえば、5 分にする場合は `COMPILE_TIMEOUT=300` とします。

<Danger>

タイムアウトを 10 分以上に延ばしても意味はありません。そうした場合、アプリケーションの別のコンポーネントでタイムアウトが発生する可能性が高くなります。

</Danger>

この変更を行ったら、`bin/up -d` コマンドを実行して **sharelatex** コンテナを再作成する必要があります。

この環境変数の設定によってタイムアウト値が更新されるのは新規ユーザーのみです。この値はユーザーの初回作成時に設定されるため、既存のユーザーにさかのぼって適用されることは**ありません**。

既存ユーザーのタイムアウトを調整するには、データベース内の各ユーザーレコードを変更する必要があります。この作業は十分に注意して行うことをお勧めします。また、変更を加える前に整合性のあるバックアップを取得することを推奨します。

バックアップの実行に関する情報は[こちら](/ja/on-premises/maintenance/data-and-backups)を参照してください。

既存のすべてのユーザーのコンパイルタイムアウト値を更新するには、Docker ホスト上で次のシェルコマンドを実行する必要があります：

```bash wrap
echo 'db.users.updateMany({}, {$set: {"features.compileTimeout": <value>}})' | docker exec -i mongo mongosh --quiet localhost/sharelatex
```

上記のクエリ内の `<value>` を、目的のタイムアウト値（秒単位）に置き換える必要があります。

コマンドが完了すると、変更されたレコード数を含む確認メッセージが表示されます。その後、exit と入力して Enter キーを押すと、ホストのシェルに戻ります。

### プロジェクトへのアクセスを追跡する

次のコマンドを使用すると、誰がいつプロジェクトを読み込んだかを確認できます：

```bash wrap
docker exec sharelatex bash -c 'grep "join project request" /var/log/overleaf/web.log'
```

これにより、`timestamp`、`user_id`、`project_id` が得られます。
