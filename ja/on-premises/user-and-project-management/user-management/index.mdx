## 管理者ユーザーの作成 {#creating-an-administrator-user}

Overleaf Toolkit を使用した導入環境の場合：

```bash title="Overleaf Toolkit" wrap
$ bin/docker-compose exec sharelatex /bin/bash -ce "cd /overleaf/services/web && node modules/server-ce-scripts/scripts/create-user --admin --email=joe@example.com"
```

従来の docker-compose.yml を使用した導入環境の場合：

```bash title="Legacy docker-compose" wrap
$ docker exec sharelatex /bin/bash -ce "cd /overleaf/services/web && node modules/server-ce-scripts/scripts/create-user --admin --email=joe@example.com"
```

このコマンドは、指定したメールアドレスのユーザーが存在しない場合は作成し、そのユーザーを管理者にします。コマンドの出力には URL が含まれており、そこにアクセスしてこのユーザーのパスワードを設定し、初回ログインを行うことができます。

<Info>

プログラムで処理する場合は、同じスクリプトを使用して管理者だけでなく一般ユーザーも作成できます。一般ユーザーの場合は --admin フラグを省略してください。

</Info>

認証に内部アカウントを使用しており、既存のユーザーをインスタンス管理者に昇格させたり、管理者権限を取り消したりする必要がある場合は、次の操作を行います：

<Steps>
<Step title="管理 UI から行う">
* 既存の管理者としてログインします。
* Admin -> Manage Users をクリックします。
* ユーザーを検索し、その名前をクリックします。
* 鉛筆アイコンをクリックします。
* Admin をオンまたはオフにします。
* Save をクリックして完了します。
</Step>
</Steps>

## ユーザーの削除 {#deleting-users}

一般に、アカウントが不要になった場合を除き、アカウントは削除しないことをお勧めします。アカウントを削除するとアカウントが削除され、共同編集者はプロジェクトにアクセスできなくなります。ユーザーのログインを止めつつデータを残すには、代わりに[アカウントを無効化](/ja/on-premises/user-guide/administrators/user-management#disable-or-enable-an-account)してください。

デフォルトでは、アカウントはソフト削除されます。インスタンスからユーザーを完全に削除する方法については、[環境変数](/ja/on-premises/configuration/overleaf-toolkit/environment-variables)ガイドの `ENABLE_CRON_RESOURCE_DELETION` を参照してください。

<Info>

アカウントはデフォルトでソフト削除されます。完全削除の動作については `ENABLE_CRON_RESOURCE_DELETION` を参照してください。

</Info>

### Admin -> Manage Users から削除する {#via-admin->-manage-users}

<Steps>
<Step title="">
* 管理者としてログインします。
* Admin -> Manage Users をクリックします。
* ユーザーを検索し、その名前の横にあるチェックボックスをオンにします。
* ゴミ箱アイコンをクリックします。
* Delete account をクリックして確定します。
</Step>
</Steps>

### コマンドラインから削除する {#via-the-command-line}

ユーザーアカウント（およびそのプロジェクト）は、次のコマンドを使用して削除できます。

Overleaf Toolkit を使用した導入環境の場合：

```bash title="Overleaf Toolkit"
$ bin/docker-compose exec sharelatex /bin/bash -ce "cd /overleaf/services/web && node modules/server-ce-scripts/scripts/delete-user.mjs --email=joe@example.com"
```

従来の docker-compose.yml を使用した導入環境の場合：

```bash title="Legacy docker-compose"
$ docker exec sharelatex /bin/bash -ce "cd /overleaf/services/web && node modules/server-ce-scripts/scripts/delete-user.mjs --email=joe@example.com"
```

<Danger>

削除スクリプトはハードコードされた強制オプションを使用しており、アカウント削除のメール送信に失敗した場合（ユーザーのメールアドレスが使用されなくなっている場合など）でも削除が確実に実行されます。

</Danger>

<Info>

--skip-email オプションを使用して、削除されたユーザーへの通知メールの送信を抑止できます。

</Info>

## ソフト削除されたユーザーの復元 {#restoring-a-soft-deleted-user}

ユーザーがソフト削除されただけの場合は、そのアカウントと、アカウントとともに削除されたプロジェクトを復元できます。ユーザーが自分で削除していたプロジェクトは削除されたままです。

<Steps>
<Step title="">
* 管理者としてログインします。
* Admin -> Manage Users をクリックします。
* 復元したいユーザーを検索します。
* Display deleted users をクリックします。
* ユーザーの行にある矢印アイコンをクリックします。
* Restore をクリックして確定します。
</Step>
</Steps>

<Danger>

ENABLE\_CRON\_RESOURCE\_DELETION が true に設定されている場合、ソフト削除されたアカウントは 90 日以内であれば復元できます。90 日を過ぎると、アカウントを復元することはできません。

</Danger>

## ユーザー数の集計 {#counting-users}

ユーザー数は、管理 UI の https://you-instance-url/admin/user#license で確認できます。プログラムによるチェックやエクスポートには、次の例が役立ちます。

ユーザーの総数：

```bash title="Total number of users"
echo 'db.users.countDocuments()' | docker exec -i mongo mongosh --quiet localhost/sharelatex
# overleaf [direct: primary] sharelatex> 16
```

メトリクスエンドポイントを使用したユーザーの総数：

```bash title="Num active users from metrics"
docker exec sharelatex curl http://127.0.0.1:3000/metrics | grep num_active_users
# # HELP num_active_users num_active_users
# # TYPE num_active_users gauge
# num_active_users{app="web-api",host="b3ae4ff549d8"} 16
```

アクティブユーザーの総数（例：過去 365 日以内にアクティブだったユーザー）：

```bash title="Total number of active users"
echo 'db.users.countDocuments({ lastActive: { $gte: new Date(new Date().getTime() - (365 * 24 * 60 * 60 * 1000)) } })' | docker exec -i mongo mongosh --quiet localhost/sharelatex
# overleaf [direct: primary] sharelatex> 10
```

## ユーザーアカウント情報の更新 {#updating-user-account-information}

アカウントの更新方法は、SSO が有効かどうかによって異なります。

* SSO を使用していない場合：
  * 管理者は、Admin -> Manage Users からユーザーアカウント情報（メールアドレス、名、姓）を変更したり、パスワードリセットリンクを生成したりできます。
  * 一般ユーザーは、Account -> Account Settings から自分の情報を更新できます（パスワードの変更や Git 認証トークンの生成を含む）。
* SSO を使用している場合：
  * Ayakaleaf Pro は、ログイン時に認証システムに基づいてユーザーの名と姓を更新するように設定できます。
  * OVERLEAF\_SAML\_UPDATE\_USER\_DETAILS\_ON\_LOGIN または OVERLEAF\_LDAP\_UPDATE\_USER\_DETAILS\_ON\_LOGIN が true の場合、https://your-instance-url/user/settings のユーザー詳細フォームは無効になり、名と姓は ID 管理システムでのみ設定できます。

詳細については、以下を参照してください：

* [SAML 2.0 の設定](/ja/on-premises/configuration/overleaf-toolkit/authentication/saml-authentication)
* [LDAP の設定](/ja/on-premises/configuration/overleaf-toolkit/authentication/ldap-authentication)

### Q\&A {#q&a}

<Accordion title="SSO ユーザーを事前に作成できますか（たとえば API で）？">

<strong>回答:</strong> そのための HTTP API はありません。上記の `create-user` スクリプト（`--admin` なし）でアカウントを作成するか、**Admin → Manage Users** の **Create account** で作成してください。`EXTERNAL_AUTH` が設定されている場合、このフォームには **Log in with SSO** オプションがあり、ローカルパスワードも、アクティベーションメールやリンクもないアカウントを作成します。**Create** の後、ダイアログは閉じます。最初の LDAP、SAML、OIDC ログイン時に、ユーザーには新しいアカウントではなく同じメールアドレスを持つ既存のアカウントが割り当てられます。[アカウントとパスワード](/ja/on-premises/configuration/overleaf-toolkit/authentication#accounts-and-passwords) を参照してください。

</Accordion>

<Accordion title="ユーザー一覧をエクスポートして、後で復元できますか？">

<strong>回答:</strong> いいえ。ユーザーアカウントのエクスポートやインポートの機能は、**Admin → Manage Users** にもスクリプトとしても存在しません。アカウントは MongoDB に保存されているため、[MongoDB のバックアップ](/ja/on-premises/maintenance/data-and-backups#mongodb)でバックアップと復元を行ってください。`export-user-projects.mjs` スクリプトはユーザーのプロジェクトを zip ファイルとしてエクスポートするもので、アカウントはエクスポートしません。[プロジェクトのエクスポート](/ja/on-premises/maintenance/data-and-backups/exporting-projects)を参照してください。

</Accordion>

<Accordion title="`create-user` のリンクの有効期間はどのくらいですか？また、メールなしでパスワードをリセットするにはどうすればよいですか？">

<strong>回答：</strong> `create-user` が出力するリンクの有効期間は 7 日間で、出力からコピーして使うため SMTP がなくても機能します。新しいリンクを取得するには、同じメールアドレスで `create-user` を再度実行してください。既存のアカウントに対しては新しいリンクを出力するだけですが、アカウントの管理者フラグも `--admin` に合わせて設定されるため、管理者に対して実行する場合は `--admin` を付けたままにしてください。

管理者は、メールなしでリセットリンクを取得することもできます。**Admin → Manage Users** でユーザーの行にある鍵アイコンをクリックし、**Send reset link** をクリックして、ダイアログからリンクをコピーします。リンクの有効期間は 1 時間です。[アクティベーションリンクまたはリセットリンクを送信する](/ja/on-premises/user-guide/administrators/user-management#send-an-activation-or-reset-link) を参照してください。

または、パスワードを直接設定します。ユーザー名をクリックし、鉛筆アイコンをクリックして、8 文字以上の **New password** を入力し、**Save** をクリックします。LDAP、SAML、OIDC のみでログインするアカウントは、どちらの方法でもパスワードを取得できません。

</Accordion>
