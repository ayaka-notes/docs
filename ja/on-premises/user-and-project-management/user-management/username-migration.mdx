## ユーザー名の移行

ログインの観点では、ユーザーの主要な識別子はメールアドレスです。ローカルベースの認証から SSO に移行する場合や、ある IdP から別の IdP に移行する場合は、ユーザーのメールアドレスを更新する必要があることがあります。

これを支援するため、次の形式の CSV ファイルを使用してユーザーのメールアドレスを移行するスクリプトが用意されています：

`oldEmail,newEmail`

いくつかの検証チェックを実行した後、スクリプトは CSV ファイルを順に処理し、ユーザーのメールアドレスを `oldEmail` から `newEmail` に更新します。

### **検証**

移行を実行する前に、`<csv_file>` について次の点が確認されます：

* 各行で、`oldEmail` と `newEmail` の両方が有効なメールアドレスであること
* 重複するエントリがないこと。たとえば、異なるユーザーを同じ新しいメールアドレスに更新しようとしていないこと、または同じユーザーアカウントをすでに使用されているメールアドレスで更新しようとしていないこと

### **使用方法**

```bash wrap
docker cp <csv_file> sharelatex:/overleaf/services/web/<csv_file> docker exec sharelatex /bin/bash -c "cd /overleaf/services/web;node ./modules/server-ce-scripts/scripts/migrate-user-emails.js [--commit] [--continue|--ignore-missing] [--admin-id=ADMIN_USER_ID] <csv_file>"
```

### **フラグ**

| 名前               | 説明                                                                                                                                                                                                                                                      |
| ------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `--commit`         | <p>`--commit` フラグを指定すると、実際に移行が行われます。省略した場合、移行はドライランモードで実行され、変更は行われませんが検証は実行されます。<br /><br /><strong>デフォルト</strong>：`false`</p> |
| `--continue`       | `--continue` フラグを指定すると、ユーザーアカウントのメールアドレスがすでに更新されている場合でも移行処理を続行します                                                                                                                         |
| `--ignore-missing` | `--ignore-missing` フラグを指定すると、ユーザーアカウントが見つからなかった場合でも移行処理を続行します                                                                                                                                                                  |
| `--admin-id`       | `--admin-id` には移行を実行する管理者の ID を設定します。この ID は監査ログのエントリに使用されます。自分のユーザー ID を確認するには、**Admin** > **Manage Users** に移動して自分のメールアドレスを検索し、最初の結果をクリックします。   |
| `<csv_file>`       | `<csv_file>` は、古いメールアドレスと新しいメールアドレスを含むファイルです                                                                                                                                                                                             |

### **完了**

移行スクリプトの実行中にエラーが発生した場合、選択したフラグに応じて、エラーをコンソールに記録して処理を続行するか、エラーをコンソールに記録して終了するかが決まります。エラーによりスクリプトが途中で終了した場合は、失敗を示す終了コード 1 で終了します。

移行が完了すると、スクリプトは成功、失敗、スキップされた更新の件数をコンソールに出力します。移行が正常に完了した場合は、終了コード 0 で終了します。
