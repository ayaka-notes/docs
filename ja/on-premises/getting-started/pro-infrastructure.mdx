#### サービス

Overleaf Pro のインフラストラクチャは、`sharelatex`、`git-bridge`（オプション）、`mongo`、`redis` の 4 つの主要サービスで構成されています。メインの Server Pro アプリケーションを実行する `sharelatex` サービスは、データベースとキャッシュ／リアルタイム機能のために `mongo` と `redis` サービスに依存し、[Git 連携](/ja/on-premises/configuration/overleaf-toolkit/git-integration)（オプション）を処理するために `git-bridge` に依存しています。ホストマシン上で公開されるポートは、`sharelatex` コンテナが使用するポート 80 のみです。

Server Pro はオプションで、プロジェクトファイルと完全なプロジェクト履歴のための [S3 互換ストレージ](/ja/on-premises/configuration/overleaf-toolkit/s3)をサポートしているほか、メインの [Overleaf ドキュメントサイトarrow-up-right](https://www.overleaf.com/learn) へのアクセスをプロキシすることもできます。詳細については、[LaTeX ユーザーヘルプの追加](/ja/on-premises/configuration/overleaf-toolkit/adding-latex-user-help)ページのガイドを参照してください。

<Info>

必要に応じて、環境変数を使用して外部サービスを指定することで、MongoDB と Redis を外部化できます。詳細については、Docker Compose を使用している場合は [Overleaf の設定](/ja/on-premises/configuration)を、Overleaf Toolkit を使用している場合は [Toolkit の設定](/ja/on-premises/configuration/overleaf-toolkit/toolkit-settings)を参照してください。

</Info>

#### コンパイル

[サンドボックスコンパイル](/ja/on-premises/configuration/overleaf-toolkit/sandboxed-compiles)では、`sharelatex` コンテナがプロジェクトのコンパイルを処理する新しいコンテナの作成をオーケストレーションします。これはホストマシン上の Docker ソケットを介して行われます。エディターとエンドツーエンドのコンパイル／キャッシュ処理の詳細については、[こちら](/ja/on-premises/getting-started/microservices#editor-and-compile-process)を参照してください。

#### ネットワーク

コンテナ間の通信は、専用のブリッジネットワークを介した Docker の内部 DNS 名前解決によって行われ、ファイアウォールは有効になっていません。デフォルトでは、上記のサービスはそれぞれの標準ポートを使用しますが、環境変数で設定を変更できます。`sharelatex` コンテナは外部からの Web アクセス用にポート 80（Nginx が提供）を使用し、`mongo` コンテナはポート 27017、`redis` はポート 6379 を使用します。

マネージドソリューションである [Overleaf Toolkitarrow-up-right](https://github.com/overleaf/toolkit) をご利用のお客様は、環境変数を使用して、Nginx で HTTPS 接続を終端する [TLS プロキシを有効化](/ja/on-premises/configuration/overleaf-toolkit/tls-proxy)することもできます。あるいは、既存の TLS プロキシを使用することもできます。

<Info>

リクエストの流れを説明する図は[こちら](/ja/on-premises/configuration/overleaf-toolkit/tls-proxy)で確認できます。

</Info>

#### まとめ

* Docker ネットワークの外部からは、Nginx にバインドされたポート 80 のみにアクセスできます。**注意：** `sharelatex` コンテナは、HTTP を介して相互に通信する多数の[サービスarrow-up-right](https://github.com/overleaf/overleaf/tree/main/services)を実行しています。ただし、これらのポートは Docker ネットワークの外部からはアクセス**できません**。
* Docker ネットワークの内部では、Overleaf のサービス、MongoDB、Redis、Git Bridge は相互に自由に通信できます。
* [サンドボックスコンパイル](/ja/on-premises/configuration/overleaf-toolkit/sandboxed-compiles)のコンテナ内では、ネットワークは利用できません。
