---
title: Ayakaleaf Toolkit とは？
icon: toolbox
---

Ayakaleaf Toolkit は、Community Edition および Ayakaleaf Pro をオンプレミスにインストールする際の推奨デプロイ方法であり、最も一般的な環境である単一の物理サーバーまたは仮想マシンで動作するように設計されています。Toolkit は `docker compose` を使用してサーバーの Docker コンテナを管理し、`docker` コマンドをラップする一連のスクリプトを提供して、オンプレミス版 Overleaf の管理における技術的な作業を支援します。

#### `bin/docker-compose` ラッパー

`bin/docker-compose` スクリプトは `docker compose` のラッパーです。`config/` ディレクトリから設定を読み込んだ後、スクリプトに渡された引数で `docker compose` を呼び出します。

`bin/docker-compose` は、マシンにインストールされている `docker compose` プログラムの透過的なラッパーとして扱うことができます。

例:

```bash title="Check running containers"
$ bin/docker-compose ps
```

#### 便利なヘルパー

`bin/docker-compose` に加えて、Toolkit は一般的なタスクを支援する便利なスクリプトを提供しています。

* `bin/up`: `bin/docker-compose up` のショートカット
* `bin/start`: `bin/docker-compose start` のショートカット
* `bin/stop`: `bin/docker-compose stop` のショートカット
* `bin/shell`: **sharelatex** コンテナ内でシェルを起動します
* `bin/doctor`: インストールとデプロイメントの情報を収集するためのスクリプトです。下記の「サーバーの確認」セクションを参照してください
* `bin/mongo`: **mongo** コンテナ内でシェルを起動し、正しいデータベース（**sharelatex**）に切り替えます
* `bin/backup-config`: 現在の設定のコピー（zip または tar）を作成し、任意の保存先ディレクトリに保存します
* `bin/logs`: サービスログを表示／追跡します
* `bin/error-logs`: サービスのエラーログを表示／追跡します
* `bin/rename-env-vars-5-0`: **config/variables.env** 内の環境変数を更新する移行スクリプトです（ShareLaTeX から Overleaf へのリブランディング）
* `bin/rename-rc-vars`: **config/overleaf.rc** 内の環境変数を更新する移行スクリプトです（ShareLaTeX から Overleaf へのリブランディング）
* `bin/run-script`: **sharelatex** コンテナ内に格納されたスクリプトの実行を簡単にするヘルパーです
* `bin/upgrade`: インスタンスのアップグレードを支援します。このスクリプトは（git を使って）Toolkit の更新を確認して変更の pull を提案し、最新の Docker イメージのバージョンを確認して更新を提案します。ステップごとの確認、現在の設定をバックアップするオプションを提供し、Docker サービスの停止／起動も処理します。詳細は「デプロイメントのアップグレード」を参照してください: https://docs.overleaf.com/on-premises/maintenance/upgrading-your-deployment

<Info>

Docker のログにアタッチせずにインスタンスを実行したい場合は、`bin/up -d` を実行してデタッチモードで起動できます。

</Info>

#### サーバーの確認

Overleaf Toolkit には、満たされていない依存関係を指摘するレポートを生成する `bin/doctor` という便利なスクリプトが含まれています。

先に進む前に、`bin/doctor` スクリプトを実行して、すべてが正しく動作していることを確認してください。

```bash title="Run Overleaf Doctor"
bin/doctor
```
