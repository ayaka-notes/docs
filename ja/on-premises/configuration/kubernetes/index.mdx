Kubernetes デプロイは、Toolkit と同じ環境変数を読み込みます。Toolkit のページで「`config/variables.env` に追加する」とある場合は、その値を ConfigMap `overleaf-env` に設定します。パスワード、鍵、トークンの場合は Secret `overleaf-secrets` に設定します。その後、再起動します。

```bash
kubectl -n overleaf apply -f 30-config.yaml        # after editing the ConfigMap
kubectl -n overleaf patch secret overleaf-secrets --type merge \
  -p '{"stringData":{"GITHUB_TOKEN_CIPHER_PASSWORD":"'"$(openssl rand -hex 32)"'"}}'
kubectl -n overleaf rollout restart deployment/overleaf
```

`config/overleaf.rc` の値は環境変数ではなく Toolkit の設定です。それらを何で置き換えるかは、このページ末尾の Q\&A で説明しています。

### 証明書とその他のファイル

一部の機能は、値ではなくファイルパスを受け取ります。SAML 証明書（`OVERLEAF_SAML_IDP_CERT` など）、LDAP の CA（`OVERLEAF_LDAP_TLS_OPTS_CA_PATH`）、セルフホストの GitHub Enterprise、GitLab、Gitea 用のプライベート CA（`NODE_EXTRA_CA_CERTS`）などです。ファイルを Secret に格納し、Toolkit のページが想定する場所 `/var/lib/overleaf/certs` にマウントします。

```bash
kubectl -n overleaf create secret generic overleaf-certs --from-file=idp_cert.pem --from-file=ca.pem
```

```yaml title="40-overleaf.yaml (additions)"
          volumeMounts:
            # ...
            - name: certs
              mountPath: /var/lib/overleaf/certs
              readOnly: true
      volumes:
        # ...
        - name: certs
          secret:
            secretName: overleaf-certs
```

次に、ConfigMap でパスを指定して参照し（例：`NODE_EXTRA_CA_CERTS: /var/lib/overleaf/certs/ca.pem`）、再起動します。

<Warning>

<strong>暗号化パスワード。</strong>使用する機能の `*_CIPHER_PASSWORD` はすべて Secret に設定してください。設定しないと、一部の機能は初回使用時にデータボリューム内に鍵ファイルを生成します。レプリカが 1 つの場合はボリュームが失われるまで機能しますが、複数のレプリカでは各レプリカが異なる鍵で暗号化してしまいます。

</Warning>

### Q\&A

<Accordion title="`config/overleaf.rc` のどの Toolkit 設定が必要ですか？">

<strong>回答：</strong>Ayakaleaf Pro はいずれも読み込みません。Kubernetes での対応は次のとおりです。

| `config/overleaf.rc`                         | Kubernetes                                                        |
| -------------------------------------------- | ----------------------------------------------------------------- |
| `OVERLEAF_LISTEN_IP`、`OVERLEAF_PORT`        | Service（NodePort）または Ingress                            |
| `SIBLING_CONTAINERS_ENABLED`                 | ConfigMap の `SANDBOXED_COMPILES*`、Pod 内の Docker ソケット  |
| `GIT_BRIDGE_ENABLED`                         | [Git 連携](/ja/on-premises/configuration/kubernetes/integrations/git-integration)                             |
| `MONGO_ENABLED`、`REDIS_ENABLED`、`MONGO_URL`、`REDIS_HOST` | StatefulSet またはマネージドサービス、`OVERLEAF_MONGO_URL` と `OVERLEAF_REDIS_HOST` |
| `REDIS_AOF_PERSISTENCE`                      | `20-redis.yaml` 内の `--appendonly yes`                             |
| `NGINX_ENABLED`、`TLS_*`                     | Ingress またはロードバランサー                                     |

</Accordion>
