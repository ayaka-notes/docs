description: Kubernetes デプロイで、ローカルパスワードの最小長と最大長を設定します。

---

**web** サービスは、ユーザーが登録、パスワードの設定、パスワードの変更を行う際にローカルパスワードをチェックします。SSO ログイン（LDAP、SAML、OIDC）は影響を受けません。それらのパスワードは ID プロバイダー側の管理対象です。Toolkit については [パスワードの制限](/ja/on-premises/configuration/overleaf-toolkit/authentication/password-restrictions) を参照してください。

| | |
| --- | --- |
| サービス | web、すべての Ayakaleaf Pro Pod 内。web の起動時に読み込まれます |
| ネットワーク | なし |
| 定期ジョブ | なし |

### 設定

ConfigMap `overleaf-env` に追加して再起動します。

```yaml title="30-config.yaml (additions)"
  OVERLEAF_PASSWORD_VALIDATION_MIN_LENGTH: "12"
  OVERLEAF_PASSWORD_VALIDATION_MAX_LENGTH: "72"
```

```bash
kubectl apply -f 30-config.yaml
kubectl -n overleaf rollout restart deployment/overleaf     # or statefulset/overleaf
```

| 変数 | デフォルト | |
| --- | --- | --- |
| `OVERLEAF_PASSWORD_VALIDATION_MIN_LENGTH` | `8` | 受け付けるパスワードの最小長。 |
| `OVERLEAF_PASSWORD_VALIDATION_MAX_LENGTH` | `72` | 受け付けるパスワードの最大長。`72` を超える値は `72` として扱われます。 |

数値は引用符で囲んでください。ConfigMap には文字列しか保持できません。

<Warning>

`OVERLEAF_PASSWORD_VALIDATION_PATTERN` は読み込まれますが、適用されません。パターンに一致しないパスワードも受け付けられます。適用されるのは長さの制限のみです。

</Warning>

### 複数のレプリカ

追加の作業は不要です。すべてのレプリカが同じ ConfigMap を読み込みます。

### Kubernetes でのテスト結果

Kubernetes 1.37 上でレプリカ 1 つ、ConfigMap に `OVERLEAF_PASSWORD_VALIDATION_MIN_LENGTH: "12"` と `OVERLEAF_PASSWORD_VALIDATION_PATTERN: aA$3` を設定した状態で新しいアカウントをアクティベートしたところ、10 文字のパスワードは拒否され、パターンでは拒否されるはずの小文字のみの 20 文字のパスワードは受け付けられました。登録に関するエンドツーエンドテストでも、デフォルト設定で `123456` が短すぎるとして拒否されます。
