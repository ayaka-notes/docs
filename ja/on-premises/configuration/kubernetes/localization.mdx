**web** サービスは、以下の設定に基づき、リクエストごとにブラウザーが使用したホスト名からインターフェースの言語を選択します。言語と設定については[ローカライズ](/ja/on-premises/configuration/overleaf-toolkit/localization)で説明しています。

| | |
| --- | --- |
| サービス | web、すべての Ayakaleaf Pro Pod 内。web の起動時に読み込まれる |
| ネットワーク | 言語ごとに 1 つのホスト名。すべて Ayakaleaf Pro にルーティングされる |
| 定期ジョブ | なし |

### 1 つの言語

```yaml
  OVERLEAF_SITE_LANGUAGE: zh-CN
```

```bash
kubectl apply -f 30-config.yaml
kubectl -n overleaf rollout restart deployment/overleaf     # or statefulset/overleaf
```

### サブドメインでの複数言語

<Steps>
<Step title="すべての言語ホストを Ayakaleaf Pro にルーティングする">
言語ごとに DNS 名を追加し、それらすべてをカバーする証明書（例: `*.example.com`）を使って、すべてを Ayakaleaf Pro にルーティングします。Ingress またはロードバランサーは `Host` ヘッダーを変更せずに渡す必要があります。ingress-nginx と HAProxy はデフォルトでそのように動作します。

ユーザーは標準ポートで言語ホストにアクセスする必要があります（`https://cn.example.com:30443` ではなく `https://cn.example.com`）。Ayakaleaf Pro はポートを除いたホストで比較するためです。
</Step>

<Step title="ConfigMap">
```yaml title="30-config.yaml (additions)" wrap
  OVERLEAF_SITE_URL: https://www.example.com
  COOKIE_DOMAIN: .example.com
  OVERLEAF_LANG_DOMAIN_MAPPING: '{"www": {"lngCode": "en", "url": "https://www.example.com"}, "cn": {"lngCode": "zh-CN", "url": "https://cn.example.com"}}'
```

`COOKIE_DOMAIN` により、ログイン Cookie がすべての言語ホストで有効になります。JSON は単一引用符で囲んでください。`OVERLEAF_LANG_DOMAIN_MAPPING` の JSON が不正な場合、起動時に Pod のすべてのサービスが停止するため、再起動後に `kubectl -n overleaf get pod` で確認してください。
</Step>
</Steps>

### 複数のレプリカ

言語は各リクエストのホスト名から決まるため、レプリカには依存しません。ロードバランサーのスティッキー Cookie は、ドメインを指定しない限りホスト名ごとに設定されるため、言語を切り替えるとユーザーが別のレプリカに移ることがあります。セッションは Redis にあるため、引き続き有効です。

### Kubernetes でのテスト

Kubernetes 1.37 上で HAProxy の背後に置き、`OVERLEAF_LANG_DOMAIN_MAPPING` でサイトのホストを英語、`de.` ホストをドイツ語、NodePort `:30081` 付きの `fr.` ホストをフランス語に対応付けた状態でテストしました。サイトのホストは英語、`de.` ホストはドイツ語で表示され、ポート付きの `fr.` ホストは上記のとおり英語にフォールバックしました。
