<Info>

この機能は OAuth 2.0 サポート付きで [ayaka-notes/ayakaleaf-pro](https://github.com/ayaka-notes/overleaf-pro) によって提供されており、v6.3.0 から利用できます。問題が発生した場合は、ぜひフィードバックをお寄せください。

</Info>

#### Mendeley 連携のセットアップ

1. [こちらのリンク](https://dev.mendeley.com/myapps.html)にアクセスして、Mendeley OAuth アプリケーションを登録します
2. **Redirect URL** を `${OVERLEAF_SITE_URL}/user/mendeley/oauth/callback` に設定します
3. 生成されたアプリケーションの **ID**（通常は下図の `24061` のような数字）と **Secret** を控えておきます
4. `config/variables.env` を編集します
5. Authorisation Flow は Elsevier のままにしておきます（推奨）

```dotenv title="config/variables.env"
#################
#   Mendeley    #
#################
# 'mendeley' must be in ENABLED_LINKED_FILE_TYPES (keep 'zotero' too if you use both)
ENABLED_LINKED_FILE_TYPES=project_file,project_output_file,url,mendeley

# From a Mendeley OAuth application (register at https://dev.mendeley.com/myapps.html)
# Redirect URL -> ${OVERLEAF_SITE_URL}/user/mendeley/oauth/callback
MENDELEY_CLIENT_ID=
MENDELEY_CLIENT_SECRET=
# Encrypts the Mendeley OAuth tokens in mongo; if unset, a key file is generated
# in /var/lib/overleaf/data on first use
# How to generate: `openssl rand -hex 32`
MENDELEY_CIPHER_PASSWORD=
# Optional: route the module's server-side Mendeley requests (OAuth + API) through
# an HTTP proxy (must be reachable from the web container; same as github-sync)
# http://10.0.0.1:10808
# (Optional) MENDELEY_PROXY_URL=
```

<Info>

`ENABLED_LINKED_FILE_TYPES` には `mendeley` を含める必要があります（両方を使用する場合は `zotero` もリストに残してください）。`MENDELEY_CLIENT_ID` と `MENDELEY_CLIENT_SECRET` は、登録した OAuth アプリケーションから取得します。cipher password は MongoDB 内の Mendeley OAuth トークンを暗号化するためのものです（`openssl rand -hex 32` で生成します）。設定しない場合は、初回使用時にデータボリューム内にキーファイルが生成されます。オプションで `MENDELEY_PROXY_URL` を設定すると、サーバー側の Mendeley リクエスト（OAuth + API）を、web コンテナからアクセス可能な HTTP プロキシ経由でルーティングできます。

</Info>

### 注意事項

<Warning>

Mendeley とリンクされた参考文献ファイルを持つ既存のインストール環境を、再リリースされた 6.3.0 にアップグレードする場合は、[Zotero / Mendeley の移行手順](/ja/on-premises/release-notes/release-notes-6.x.x#ayakaleaf-pro-6.3.0  "mention")に従ってください。新規インストールではこの移行は不要です。

</Warning>

<Danger>

Ayakaleaf は共同作業プラットフォームであるため、セキュリティ向上のため、バージョン 6.3.0 以降では、参考文献 `bib` ファイルの元の作成者のみがインポートしたファイルを更新できます。

</Danger>

たとえば、プロジェクトのオーナーであるユーザー A がリンク共有を有効にし、プロジェクト内に `test.bib` ファイルを作成して自分の Zotero アカウントにリンクしたとします。別のユーザー B が共有リンクからプロジェクトにアクセスした場合、ユーザー B は `test.bib` を読み取り・ダウンロードすることはできますが、Zotero からファイルを更新または再インポートすることはできません。更新を実行できるのは、参考文献ファイルの元の作成者であるユーザー A のみです。つまり、`.bib` ファイルを更新する権限を持つのは、その元の作成者だけです。
