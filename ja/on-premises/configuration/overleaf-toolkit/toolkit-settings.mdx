このページでは、Toolkit デプロイにおいて `config/overleaf.rc` ファイルでサポートされている環境変数について説明します。

`config/overleaf.rc` ファイルは、`NAME=value` 形式の変数定義で構成されます。`#` で始まる行はコメントとして扱われます。

<Info>

`overleaf.rc` または `variables.env` の内容を変更した後は、`bin/up` を実行して Docker コンテナを再作成する必要があります。

</Info>

## コンテナ

### `sharelatex`

| 名前                         | 説明                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| ---------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `PROJECT_NAME`               | <p>`docker-compose` に渡される `--project-name` フラグの値を設定します。1 台のホストで複数の Overleaf インスタンスを実行する場合に便利で、インスタンスごとに異なるプロジェクト名を付けられます。<br /><br />- <strong>デフォルト</strong>：`overleaf`</p>                                                                                                                                                                                                                                                 |
| `OVERLEAF_IMAGE_NAME`        | <p>Server Pro/CE アプリケーションコンテナで使用される Docker イメージ。これは Docker イメージ名のみで、Docker イメージのタグは `config/version` から取得されます。<br /><br />- <strong>デフォルト：</strong><br />- Server Pro：`quay.io/sharelatex/sharelatex-pro`<br />- Community Edition：`sharelatex/sharelatex`</p>                                                                                                                                                                                                 |
| `SERVER_PRO`                 | <p>`true` に設定すると、Toolkit はデフォルトの Server CE イメージ（`sharelatex/sharelatex`）ではなく、Server Pro イメージ（`quay.io/sharelatex/sharelatex-pro`）を使用します。<br /><br />- <strong>デフォルト</strong>：`false`</p>                                                                                                                                                                                                                                                                   |
| `GIT_BRIDGE_ENABLED`         | <p>`true` に設定すると git-bridge 機能が有効になります（Server Pro のみ）。詳しくは <a href="https://www.overleaf.com/learn/how-to/Git_integration">https://www.overleaf.com/learn/how-to/Git_integration</a> のユーザードキュメントを参照してください。<br /><br />- <strong>デフォルト：</strong> `false`</p>                                                                                                                                                                                                                        |
| `GIT_BRIDGE_IMAGE`           | <p>git-bridge コンテナ（Server Pro のみ）で使用される Docker イメージ。これは Docker イメージ名のみで、Docker イメージのタグは `config/version` から取得されます。<br /><br />- <strong>デフォルト：</strong> `quay.io/sharelatex/git-bridge`</p>                                                                                                                                                                                                                                                                              |
| `GIT_BRIDGE_DATA_PATH`       | `git-bridge` コンテナ（Server Pro のみ）にマウントされ、Git リポジトリの保存に使用されるディレクトリのパスを設定します。フルパス（`/` で始まるもの）か、Toolkit のベースディレクトリからの相対パスを指定できます。                                                                                                                                                                                                                                                                                     |
| `GIT_BRIDGE_LOG_LEVEL`       | <p>`git-bridge` コンテナのログレベルを設定します。使用可能なレベル：`TRACE`、`DEBUG`、`INFO`、`WARN`、`ERROR`。<br /><br />- <strong>デフォルト：</strong> `INFO`</p>                                                                                                                                                                                                                                                                                       |
| `SIBLING_CONTAINERS_ENABLED` | <p>`true` に設定すると、Toolkit は <strong>Sibling Containers</strong> 方式を使用して、プロジェクトごとに個別の Docker コンテナを用い、別々のサンドボックスでプロジェクトをコンパイルします。詳しくは &#x3C;server-pro-only-configuration/sandboxed-compiles> のドキュメントを参照してください。<br /><br />- <strong>必要条件：</strong> `SERVER_PRO=true`<br />- <strong>デフォルト：</strong> `true`</p>                                                                                                    |
| `SIBLING_CONTAINERS_PULL`    | <p>`true` に設定すると、`bin/up` コマンドの実行時に、<strong>config/variables.env</strong> ファイルの `ALL_TEX_LIVE_DOCKER_IMAGES` で指定されたすべての TeX Live イメージを Toolkit が自動的に取得します。<br /><br />- <strong>デフォルト：</strong> `true`</p>                                                                                                                                                                                                                                      |
| `DOCKER_SOCKET_PATH`         | <p>ホストマシン（Toolkit を実行しているマシン）上の Docker ソケットのパスを設定します。`SIBLING_CONTAINERS_ENABLED` が `true` の場合、コンパイラーサービスがホスト上で新しい Docker コンテナを起動できるように、このソケットがコンテナにマウントされます。<br /><br />- <strong>必要条件：</strong> `SIBLING_CONTAINERS_ENABLED=true`<br />- <strong>デフォルト：</strong> `/var/run/docker.sock`</p>                                                                                               |
| `OVERLEAF_DATA_PATH`         | <p>メインの `sharelatex` コンテナにマウントされ、コンパイルデータの保存に使用されるディレクトリのパスを設定します。フルパス（`/` で始まるもの）か、Toolkit のベースディレクトリからの相対パスを指定できます。<br /><br />- <strong>デフォルト：</strong> `data/overleaf`</p>                                                                                                                                                                                                               |
| `OVERLEAF_LISTEN_IP`         | <p>コンテナがバインドするホストの IP アドレスを設定します。たとえば `0.0.0.0` に設定すると、Web インターフェースはホストのすべての IP アドレスで利用可能になります。コンテナに直接アクセスする場合は、`OVERLEAF_LISTEN_IP` の値をパブリック IP アドレスに設定する必要があります。`OVERLEAF_LISTEN_IP` を `0.0.0.0` またはホストの外部 IP に設定すると、 と組み合わせて使用した場合に通常はエラーが発生します。<br /><br />- <strong>デフォルト：</strong> `127.0.0.1`</p> |
| `OVERLEAF_PORT`              | <p>コンテナがバインドするホストのポートを設定します。たとえば、これを `8099` に、`OVERLEAF_LISTEN_IP` を `127.0.0.1` に設定すると、Web インターフェースは `http://localhost:8099` で利用可能になります。<br /><br />- <strong>デフォルト：</strong> `80`</p>                                                                                                                                                                                                                        |
| `OVERLEAF_LOG_PATH`          | <p>メインの `sharelatex` コンテナにマウントされ、アプリケーションログを Docker ホスト上で参照できるようにするためのディレクトリのパスを設定します。フルパス（`/` で始まるもの）か、Toolkit のベースディレクトリからの相対パスを指定できます。バインドマウントを無効にするには、この設定項目を削除します。設定されていない場合、コンテナを再作成するとログは破棄されます。<br /><br />ログの詳細については を参照してください。<br /><br />- <strong>デフォルト：</strong> 未設定</p>                                 |

### `mongo`

| 名前              | 説明                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| ----------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `MONGO_ENABLED`   | <p>`true` に設定すると、Toolkit はデータベースをホストする MongoDB コンテナを作成します。`false` に設定すると、このコンテナは作成されず、代わりに `MONGO_URL` で指定された MongoDB データベースが使用されます。<br /><br />- <strong>デフォルト</strong>：`true`</p>                                                                                                                                 |
| `MONGO_URL`       | <p>`MONGO_ENABLED` が `false` の場合に使用する MongoDB の接続 URL を指定します。<br /><br />- <strong>デフォルト</strong>：未設定</p>                                                                                                                                                                                                                                                                                                           |
| `MONGO_DATA_PATH` | <p>`mongo` コンテナにマウントされ、MongoDB データベースの保存に使用されるディレクトリのパスを設定します。フルパス（`/` で始まるもの）か、Toolkit のベースディレクトリからの相対パスを指定できます。このオプションは、`MONGO_ENABLED` が `true` の場合に作成されるローカルの `mongo` コンテナにのみ影響します。<br /><br />- <strong>デフォルト</strong>：`data/mongo`</p> |
| `MONGO_IMAGE`     | <p>MongoDB コンテナで使用される Docker イメージ。これは Docker イメージ名のみで、Docker イメージのタグは `MONGO_VERSION`（下記参照）に指定します。<br /><br />- <strong>デフォルト：</strong> `mongo`</p>                                                                                                                                                                                                                             |
| `MONGO_VERSION`   | <p>MongoDB コンテナで使用される MongoDB のバージョン。値は MongoDB のメジャーバージョンとドットで始まる必要があります（例：`6.0` や `6.0-with-suffix`）。<br /><br />- <strong>デフォルト：</strong> `6.0`</p>                                                                                                                                                                                                                             |

### `redis`

| 名前                    | 説明                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| ----------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `REDIS_ENABLED`         | <p>`true` に設定すると、Toolkit は Redis データベースをホストする Redis コンテナを作成します。`false` に設定すると、このコンテナは作成されず、代わりに `REDIS_HOST` と `REDIS_PORT` で指定された Redis データベースが使用されます。<br /><br />- <strong>デフォルト</strong>：`true`</p>                                                                                                |
| `REDIS_HOST`            | <p>`REDIS_ENABLED` が `false` の場合に使用する Redis ホストを指定します。<br /><br />- <strong>デフォルト</strong>：未設定</p>                                                                                                                                                                                                                                                                                                                     |
| `REDIS_PORT`            | <p>`REDIS_ENABLED` が `false` の場合に使用する Redis ポートを指定します。<br /><br />- <strong>デフォルト</strong>：未設定</p>                                                                                                                                                                                                                                                                                                                     |
| `REDIS_DATA_PATH`       | <p>`redis` コンテナにマウントされ、Redis データベースの保存に使用されるディレクトリのパスを設定します。フルパス（`/` で始まるもの）か、Toolkit のベースディレクトリからの相対パスを指定できます。このオプションは、`REDIS_ENABLED` が `true` の場合に作成されるローカルの `redis` コンテナにのみ影響します。<br /><br />- <strong>デフォルト</strong>：`data/redis`</p> |
| `REDIS_AOF_PERSISTENCE` | <p>Redis の AOF（Append Only File）による永続化を有効にします。これは Redis の永続化における<strong>推奨</strong>設定です。<br /><br />詳しくは、&#x3C;../../maintenance/data-and-backups> の &#x3C;../../../maintenance/data-and-backups#aof-append-only-file> セクションを参照してください。<br /><br />- <strong>デフォルト：</strong> `true`</p>                                                                                               |

### `nginx`

| 名前                   | 説明                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `NGINX_ENABLED`        | <p>`true` に設定すると、Toolkit は TLS プロキシとして機能する NGINX コンテナを作成します。<br /><br />- <strong>デフォルト</strong>：`false`</p>                                                                                                                                                                                                                                                                                                                                 |
| `NGINX_CONFIG_PATH`    | <p>TLS プロキシで使用する NGINX 設定ファイルのパス。<br /><br />- <strong>デフォルト</strong>：`config/nginx/nginx.conf`</p>                                                                                                                                                                                                                                                                                                                                                            |
| `NGINX_TLS_LISTEN_IP`  | <p>TLS プロキシコンテナが HTTPS 用にバインドするホストの IP アドレスを設定します。たとえば `0.0.0.0` に設定すると、HTTPS の Web インターフェースはホストのすべての IP アドレスで利用可能になります。通常は、ホストの外部 IP に設定します。<br /><br />- <strong>デフォルト</strong>：`127.0.1.1`</p>                                                                                                                                                       |
| `NGINX_HTTP_LISTEN_IP` | <p>TLS プロキシコンテナが HTTP リダイレクト用にバインドするホストの IP アドレスを設定します。たとえば `127.0.1.1` に設定すると、`127.0.1.1` への HTTP 接続は HTTPS の Web インターフェースにリダイレクトされます。通常は、ホストの外部 IP に設定します。`0.0.0.0` に設定すると通常は `OVERLEAF_LISTEN_IP` と競合するため、設定しないでください。<br /><br />- <strong>デフォルト</strong>：`127.0.1.1`</p> |
| `NGINX_HTTP_PORT`      | <p>TLS プロキシコンテナが HTTP 用にバインドするホストのポートを設定します。<br /><br />- <strong>デフォルト</strong>：`80`</p>                                                                                                                                                                                                                                                                                                                                                                  |
| `TLS_PORT`             | <p>TLS プロキシコンテナが HTTPS 用にバインドするホストのポートを設定します。<br /><br />- <strong>デフォルト</strong>：`443`</p>                                                                                                                                                                                                                                                                                                                                                                |
| `TLS_PRIVATE_KEY_PATH` | <p>TLS プロキシで使用する秘密鍵のパス。<br /><br />- <strong>デフォルト</strong>：`config/nginx/certs/overleaf_key.pem`</p>                                                                                                                                                                                                                                                                                                                                                      |
| `TLS_CERTIFICATE_PATH` | <p>TLS プロキシで使用する公開証明書のパス。<br /><br />- <strong>デフォルト</strong>：`config/nginx/certs/overleaf_certificate.pem`</p>                                                                                                                                                                                                                                                                                                                                       |
