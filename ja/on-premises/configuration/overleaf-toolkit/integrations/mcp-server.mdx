各プロジェクトには MCP サーバーがあり、Claude Code、Codex、Cursor、VS Code、Gemini CLI などの AI クライアントがプロジェクトで作業できます。ファイルの読み取りと編集、コンパイル、LaTeX のログの読み取り、PDF のダウンロード、コメントへの返信が可能です。 v6.3.3 からは、履歴の閲覧とバージョンの復元、変更履歴の確認、コメントの追加、プロジェクトチャットの利用、ファイルの移動もできます。

<Info>

この機能は [ayaka-notes/ayakaleaf-pro](https://github.com/ayaka-notes/ayakaleaf-pro) によって開発されたものです。v6.3.1 以降で導入されています。 履歴、変更履歴、プロジェクトチャット、新しいコメント、ファイル移動のツールは v6.3.3 以降で利用できます。[v6.3.3 の新機能](/on-premises/user-guide/users/mcp-server#new-in-v6.3.3)を参照してください。

</Info>

### セットアップ {#setup}

MCP サーバーは Git 連携に含まれています。[git-bridge](/ja/on-premises/configuration/overleaf-toolkit/integrations/git-integration) を有効にすれば、MCP サーバーも利用できるようになります。その他の設定は必要ありません。

### AI クライアントを接続する {#connect-an-ai-client}

1. **アカウント設定** で Git 認証トークンを生成します。同じトークンが MCP サーバーと Git の両方で使用されます。
2. エディターで **Integrations** を開き、**MCP server** をクリックします。プロジェクトの MCP サーバーのアドレス `https://<your-overleaf>/project/<project_id>/mcp` と、各 AI クライアントへの追加方法が表示されます。コマンドをコピーし、`<token>` を自分のトークンに置き換えてください。

トークンは HTTP ヘッダー `Authorization: Bearer <token>` として送信されます。たとえば、Claude Code 用のコマンドは次のとおりです。

```bash
claude mcp add --transport http overleaf \
  https://<your-overleaf>/project/<project_id>/mcp \
  --header "Authorization: Bearer <token>"
```

### 使い方 {#usage}

接続したら、AI クライアントに普段の言葉で依頼します。例:

| 依頼内容 | AI クライアントが使用するツール |
| --- | --- |
| _序論の誤字を修正して。_ | `read_file`、`edit_file`: 編集はエディターにリアルタイムで表示されます |
| _プロジェクトをコンパイルして LaTeX のエラーを修正して。_ | `compile`、`get_compile_log`、`edit_file` |
| _未解決のコメントに返信してから解決済みにして。_ | `list_comments`、`reply_to_comment`、`resolve_comment` |
| _XeLaTeX に切り替えて PDF をダウンロードして。_ | `update_settings`、`compile`、`get_output_file_link` |
| _要旨を変更履歴付きで書き直して。_ | `read_file`、`trackChanges` 付きの `edit_file`（v6.3.3） |
| _提出したバージョンから何が変わった？_ | `list_versions`、`list_changes`、`diff`（v6.3.3） |
| _各章を chapters というフォルダーに移動して。_ | `move_file`（v6.3.3） |

### ツール {#tools}

| グループ | ツール |
| --- | --- |
| プロジェクト | `get_clone_info`, `get_settings`, `update_settings` |
| ファイル | `list_files`, `read_file`, `edit_file`, `write_file`, `delete_file`, `move_file`, `create_folder` |
| コンパイル | `compile`, `get_compile_log`, `get_output_file_link`, `word_count` |
| コメント | `list_comments`, `reply_to_comment`, `resolve_comment`, `reopen_comment`, `add_comment`, `edit_comment_message`, `delete_comment_message` |
| 変更履歴 | `list_tracked_changes`, `accept_tracked_changes`, `reject_tracked_changes` |
| 履歴 | `list_versions`, `list_changes`, `diff`, `create_version`, `delete_version`, `restore_file`, `restore_project` |
| チャット | `list_chat_messages`, `send_chat_message` |

v6.3.3 には 33 個のツールがあり、チャットツールを除外する `OVERLEAF_DISABLE_CHAT=true` を設定すると 31 個になります。v6.3.1 と v6.3.2 にはそれ以外の 17 個があります。上記のうち `move_file`、`create_folder`、`add_comment`、`edit_comment_message`、`delete_comment_message`、変更履歴ツール、チャットツール、`list_versions` 以外の履歴ツールを除いたすべてです。v6.3.3 では、`read_file` が履歴のバージョン時点のファイルも読み取り、`edit_file` と `write_file` が `trackChanges` を受け付け、`update_settings` がスペルチェックの言語も設定します。

`edit_file`、`write_file`、`move_file` による編集はエディターにリアルタイムで表示され、共同編集者の編集とマージされます。多数のファイルを一度に扱う場合やバイナリファイルについては、AI クライアントが Git でプロジェクトをクローンしてプッシュすることもできます。

`trackChanges` を指定すると、既存ファイルの編集は、プロジェクトで変更履歴がオフになっていても、トークンのユーザーによる変更履歴として記録されます。新しいファイルが変更履歴になることはありません。`trackChanges` を指定しない場合、編集はプロジェクトの変更履歴の設定に従います。

### 権限 {#permissions}

MCP サーバーは、Git と同様にプロジェクトの共有設定に従います。

* プロジェクトを閲覧できるユーザーは全員、プロジェクトの読み取り、コンパイル、出力のダウンロードができます。
* ファイルと設定の変更、バージョンの復元、変更履歴の承認や却下ができるのは、オーナーと編集者のみです。
* レビュアーは、コメントの追加と返信、自分が開始したコメントの解決・再オープン・削除、バージョンの保存もできます。ファイルは編集できず、変更履歴としての編集もできません。
* 自分のコメントメッセージを編集できるのは本人のみで、レビュアーが削除できるのも自分のメッセージのみです。
* 他のユーザーが保存したバージョンを削除できるのはオーナーのみです。
* リンクで参加した閲覧者は、エディターと同様に、コメント、変更履歴、履歴、チャットを見ることができません。招待された閲覧者はそれらを見ることができ、チャットも使えます。
* プロジェクトのオーナーに **Full project history** がない場合、履歴ツールは履歴パネルと同様に直近 24 時間の変更のみを表示します。管理者はすべて見ることができます。

各ロールができることの表はユーザーガイドにあります。[誰が何をできるか](/on-premises/user-guide/users/mcp-server#who-may-do-what)を参照してください。

### Q\&A {#q&a}

<Accordion title="エディターに Integrations や MCP server が表示されない">

<strong>回答：</strong> MCP サーバーには専用の環境変数はありません。`config/overleaf.rc` の `GIT_BRIDGE_ENABLED=true` で有効になります。[Git 連携](/ja/on-premises/configuration/overleaf-toolkit/integrations/git-integration)を参照してください。変更後は `bin/up -d` を実行してください。git-bridge がない場合、エディターの左レールに **Integrations** タブは表示されません。

</Accordion>

<Accordion title="AI クライアントが「Track changes is off for this project」と表示する">

<strong>回答：</strong> クライアントは変更履歴付きの編集を要求しましたが、プロジェクトオーナーのアカウントに変更履歴機能がありません。**Admin**、**Manage Users** の順にクリックし、オーナーを開いて **Features** タブで **Track changes** をオンにしてください。[Features](/ja/on-premises/user-guide/administrators/user-management#features)を参照してください。`trackChanges` を指定しない編集は引き続き使えます。

</Accordion>

<Accordion title="AI クライアントに直近 24 時間の変更しか見えない">

<strong>回答：</strong> プロジェクトオーナーのアカウントに完全なプロジェクト履歴がないため、履歴ツールは履歴パネルと同じく直近 24 時間の変更のみを表示します。**Admin**、**Manage Users** の順にクリックし、オーナーを開いて **Features** タブで **Full project history** をオンにしてください。[Features](/ja/on-premises/user-guide/administrators/user-management#features)を参照してください。

</Accordion>
