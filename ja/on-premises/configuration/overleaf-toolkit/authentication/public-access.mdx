アカウントを持たない人に Overleaf インスタンスを公開する方法は 3 つあります。

* [プロジェクトアクセス](/ja/on-premises/configuration/overleaf-toolkit/public-access#project-access  "mention")：ゲストがログインせずに共有プロジェクトのリンクを開けるようにする
* [ページアクセス](/ja/on-premises/configuration/overleaf-toolkit/public-access#page-access  "mention")：未ログインの訪問者が `/learn`、`/templates`、`/devs` などのページを閲覧できるようにする
* [公開登録](/ja/on-premises/configuration/overleaf-toolkit/public-access#public-registration  "mention")：ユーザーが自分でサインアップできるようにする（必要に応じてアクティベーションメールを使用し、メールドメインで制限可能）

### プロジェクトアクセス

<Info>

デフォルトでは、ユーザーがプロジェクトの共有リンクを入手しても、共同編集セッションに参加するには**ログイン**する必要があります。

</Info>

リンク共有されたプロジェクトへの匿名アクセスを許可するには、以下の 2 つの変数を両方とも設定します。

```dotenv title="config/variables.env"
OVERLEAF_ALLOW_ANONYMOUS_READ_AND_WRITE_SHARING=true
OVERLEAF_ALLOW_PUBLIC_ACCESS=true
```

`OVERLEAF_ALLOW_ANONYMOUS_READ_AND_WRITE_SHARING` は、リンク共有されたプロジェクトでの匿名の読み書きを有効にします。

`OVERLEAF_ALLOW_PUBLIC_ACCESS` は、未認証ユーザーがログインページにリダイレクトされるのを防ぎます。

`bin/up` でコンテナを再作成します。その後、プライベートウィンドウでリンク共有 URL を開いてください。

### ページアクセス

デフォルト（`OVERLEAF_ALLOW_PUBLIC_ACCESS` 未設定）では、ログインページと登録ページを除く**すべて**のページで、未ログインの訪問者はログインページにリダイレクトされます。これには公開を意図したページも含まれるため、それらへのリンクはすでにログインしているユーザーにしか機能しません。

`OVERLEAF_ALLOW_PUBLIC_ACCESS=true` を設定すると、未ログインの訪問者は次のページを開けるようになります。

| ページ | 必要な設定 |
| --------------------------------------------------------------------- | -------------------------------- |
| `/learn` の LaTeX ヘルプ（[adding-latex-user-help.md](/ja/on-premises/configuration/overleaf-toolkit/adding-latex-user-help  "mention") を参照） | `OVERLEAF_PROXY_LEARN=true`      |
| `/templates` のテンプレートギャラリー、テンプレートページ、プレビュー、ZIP ダウンロード（[templates.md](/ja/on-premises/configuration/overleaf-toolkit/templates  "mention") を参照） | `OVERLEAF_TEMPLATE_GALLERY=true` |
| `/devs` の Overleaf Import API ページ（[overleaf-import-api.md](/ja/on-premises/configuration/overleaf-toolkit/overleaf-import-api  "mention") を参照） | —                                |

また、[Overleaf Import API](/ja/on-premises/configuration/overleaf-toolkit/overleaf-import-api#signed-out-visitors  "mention") が未ログインの訪問者からのフォーム送信を、その訪問者がログインするまで保持できるようになります。

プロジェクト一覧、エディター、およびプロジェクトの作成（テンプレートからや Import API 経由の作成も含む）には、引き続きログインが必要です。

### 公開登録

公開登録は [ayaka-notes/ayakaleaf-pro](https://github.com/ayaka-notes/ayakaleaf-pro) でのみ利用できます。

<Danger>

公開登録を有効にすると、Overleaf インスタンスにアクセスできる**誰でも**ユーザーとして登録できるようになることに注意してください。

`true` の場合、登録プロセスではメールアドレスの検証を行わないため、イントラネットや信頼できる環境でのみ使用するか、代わりに[アクティベーションメールによる登録](/ja/on-premises/configuration/overleaf-toolkit/public-access#registration-with-activation-email)を使用してください。

OIDC を使用するインスタンスでは `true` を使用しないでください。同僚が最初に OIDC でログインする前に、誰でもその同僚のメールアドレスで登録できてしまい、同僚がそのアカウントに連携されてしまいます。[アクティベーションメールによる登録](/ja/on-premises/configuration/overleaf-toolkit/public-access#registration-with-activation-email)を使用するか、公開登録を無効にしてください。[アカウントとパスワード](/ja/on-premises/configuration/overleaf-toolkit/authentication#accounts-and-passwords)を参照してください。

</Danger>

デフォルトでは、Community Edition も Overleaf Pro も公開登録を許可していません。

有効にするには、`config/variables.env` に次を追加します。

```dotenv title="config/variables.env"
OVERLEAF_ALLOW_PUBLIC_REGISTRATION=true
```

`bin/up` でコンテナを再作成します。

その後、 **Sign up** をクリックするか、`/register` にアクセスします。

### アクティベーションメールによる登録

アクティベーションメールによる登録は [ayaka-notes/ayakaleaf-pro](https://github.com/ayaka-notes/ayakaleaf-pro) でのみ利用できます。ユーザーはメールアドレスのみでサインアップし、アクティベーションメール内のリンクからパスワードを設定するため、アドレスの所有者だけがアカウントを使用できます。ドメインのリストやワイルドカードを使用するには v6.4.0 以降が必要です。それより前のバージョンでは、`@example.com` のように 1 つのドメインのみを指定できます。

これを有効にする前に、メール配信を設定してください。設定しないと、ユーザーはアクティベーションメールを受け取れません。[メール配信](/ja/on-premises/configuration/overleaf-toolkit/email-delivery)を参照してください。

次に、`config/variables.env` に次の行を追加します。

```dotenv title="config/variables.env" wrap
OVERLEAF_ALLOW_PUBLIC_REGISTRATION=@example.com,@*.example.org
```

`OVERLEAF_ALLOW_PUBLIC_REGISTRATION` には次の値を設定できます。

| 値                         | サインアップできるユーザー                                       | メール検証 |
| ----------------------------- | ----------------------------------------------------- | :------------: |
| `true`                        | 誰でも（メールアドレスとパスワードで）                       |       なし       |
| `@example.com`                | `example.com` のアドレス                             |      あり       |
| `@*.example.org`              | `cs.example.org` などのサブドメインのアドレス（`example.org` 自体は除く） |      あり       |
| `@example.com,@*.example.org` | カンマ区切りで列挙したいずれかのエントリ         |      あり       |
| `@*`                          | 誰でも                                                 |      あり       |

ドメインは大文字と小文字を区別せずに照合されます。ドメインとそのサブドメインの両方を許可するには、`@example.org,@*.example.org` のように両方を列挙してください。

### Q\&A

<Accordion title="サインインしていない編集者はコメントに対して何ができますか？">

<strong>回答：</strong> 編集リンクからプロジェクトを開いたサインインしていないユーザーは、編集者と同じアクセス権を持ちます。ただし、誰が行ったかを記録する操作は除きます:

| 操作                                              | サインインしていない編集者 |
| ------------------------------------------------- | -------------------------: |
| テキストの編集、コメントと変更履歴の表示           |                       はい |
| 変更履歴の承認、編集モードの切り替え               |                       はい |
| コメントまたはスレッド全体の削除                   |                       はい |
| コメントの追加、返信、編集                         |                     いいえ |
| コメントの解決または再オープン                     |                     いいえ |

レビューパネルには引き続き **Resolve** ボタンが表示されますが、解決しようとするとエラーメッセージが表示されて失敗します。

閲覧リンクからプロジェクトを開いたユーザーには、コメントは一切表示されません。[ロールと権限](/ja/on-premises/user-and-project-management/roles-and-permissions#collaborating)を参照してください。

</Accordion>
