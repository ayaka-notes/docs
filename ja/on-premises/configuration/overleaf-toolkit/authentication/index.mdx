### グローバル設定

特定の認証モジュールを有効にするには、環境変数 `EXTERNAL_AUTH` が必要です。この環境変数で、どの外部認証方式を有効にするかを指定します。使用可能なオプションは次のとおりです（小文字）:

* saml
* ldap
* oidc

これらの方法でのみユーザーがログインできるようにするには、`OVERLEAF_DISABLE_LOCAL_LOGIN=true` を設定します。これにより、メールアドレスとパスワードによるログインが非表示になります。`EXTERNAL_AUTH` で少なくとも 1 つの方法が有効になっていない場合は効果がありません（6.4.0 で追加）。

### SSO に関する提案

私は Overleaf で saml、ldap、oauth をテストしました。saml と oauth はどちらも Overleaf で問題なく動作しますが、ldap は環境によります。[https://docs.goauthentik.io/](https://docs.goauthentik.io/) ではうまく動作しませんが、openLDAP（[https://github.com/rroemhild/docker-test-openldap](https://github.com/rroemhild/docker-test-openldap)）では問題なく動作します。

<Info>

passport-ldapauth を更新する必要があります。最近 [https://goauthentik.io/](https://goauthentik.io/) で Overleaf の LDAP をテストしようとしたところ、失敗しました。"passport-ldapauth" を 3.0.0 に更新したところ、すべて正常に動作しました。

```text
"passport-ldapauth": "^3.0.0",
```

元のバージョンは 6 年前の 2.x.x です。

</Info>

LDAP（および saml、oauth）認証はすべて外部パッケージに依存しているため、原因ははっきりしません。うまく動作しない場合、Overleaf Server Pro でも状況は同じである可能性があります。すべての環境変数を内部パッケージにそのまま渡しているだけなので、何らかのバグがあっても、現時点では把握できません。

**そのため、すべてのソースコードを使って SSO をテストできるよう、開発環境をセットアップすることを強くお勧めします。** 手順は [Setup Develop Environment (Local)](/ja/dev/environment/setup-develop-environment-local  "mention") で確認できます。開発環境ではターミナルですべてのログを確認できるため、デバッグに便利です。
