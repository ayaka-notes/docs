このページでは、Toolkit デプロイメントの `config/variables.env` ファイルでサポートされている環境変数について説明します。

`config/variables.env` ファイルは `NAME=value` 形式の変数定義で構成されており、`#` で始まる行はコメントとして扱われます。

<Info>

`overleaf.rc` または `variables.env` の内容を変更した後は、`bin/up` を実行して Docker コンテナを再作成する必要があります。

</Info>

### すべてのバージョン

これらの環境変数は Server CE と Server Pro の両方と互換性があり、この 2 つのオンプレミス版の間で簡単に移行できます。また、Toolkit と Docker Compose のどちらのデプロイメントでも使用できます。

<Info>

以前は、これらの環境変数には `OVERLEAF_` ではなく `SHARELATEX_` という接頭辞が付いていました。

</Info>

| 名前 | 説明 |
| ---- | ---- |
| `OVERLEAF_SITE_URL` | Overleaf インスタンスが公開されている場所。公開リンクや WebSocket 接続時に使用されるため、正しく設定する必要があります! |
| `OVERLEAF_ADMIN_EMAIL` | ユーザーがサイトの運営者に連絡するためのメールアドレス。 |
| `OVERLEAF_APP_NAME` | 実行中のアプリケーションを指す際に表示される名前。デフォルトは 'Overleaf (Community Edition)' です。 |
| `OVERLEAF_MONGO_URL` と `MONGO_URL` | 使用する Mongo データベースの URL。 |
| `OVERLEAF_REDIS_HOST` と `REDIS_HOST` | 使用する Redis インスタンスのホスト名。両方とも必須です([リリースノート](/ja/on-premises/release-notes)を参照)。 |
| `OVERLEAF_REDIS_PORT` と `REDIS_PORT` | 使用する Redis インスタンスのポート。両方とも必須です([リリースノート](/ja/on-premises/release-notes)を参照)。 |
| `OVERLEAF_REDIS_PASS` と `REDIS_PASSWORD` | Redis に接続する際に使用するパスワード(該当する場合)。**両方**の環境変数を設定する必要があります。詳細は[パスワード認証の有効化](/ja/on-premises/configuration/overleaf-toolkit/redis#enabling-password-authentication)を参照してください。 |
| `OVERLEAF_REDIS_TLS` | <p>`true` に設定すると、TLS を必要とする Redis インスタンスへの接続が可能になります。<br /><br /><strong>注意:</strong> mTLS は現在サポートされていません。</p> |
| `OVERLEAF_NAV_TITLE` | アプリケーションのタブタイトルを設定します。 |
| `OVERLEAF_HEADER_IMAGE_URL_LIGHT` と `OVERLEAF_HEADER_IMAGE_URL_DARK` | ライトテーマとダークテーマ用のカスタムヘッダーロゴの URL(6.3.0 で追加)。各テーマで固有の変数が設定されていない場合は `OVERLEAF_HEADER_IMAGE_URL` にフォールバックします。[Branding](/ja/on-premises/configuration/overleaf-toolkit/branding  "mention") を参照してください。 |
| `OVERLEAF_LINKED_URL_OUTBOUND_PROXY` | 外部リンクファイルや、Open in Overleaf API 経由の外部 ZIP または TeX リソースを取得するための HTTP(S) プロキシの URL。再リリースされた Ayakaleaf Pro `6.3.0`(2026 年 10 月 3 日)から利用できます。直接接続する場合は未設定のままにしてください。例: `OVERLEAF_LINKED_URL_OUTBOUND_PROXY=http://proxy.internal:3128`。設定方法とネットワークアクセス制限については [Outbound Proxy](/ja/on-premises/configuration/overleaf-toolkit/external-url#outbound-proxy  "mention") を参照してください。 |
| `OVERLEAF_INVITE_TOKEN_SECRET` | <p><strong>必須</strong>。プロジェクト共有トークンを保護するために使用されるランダムな文字列(Server Pro 6.2.0 で追加)。</p><p><strong>最小文字数:</strong> 16</p> |
| `OVERLEAF_SESSION_SECRET` | トークンを保護するために使用されるランダムな文字列。ロードバランシングを行う場合は、すべてのマシンで同じトークンを設定する必要があります。インスタンスを 1 つだけ実行している場合は、ユーザーが設定する必要はありません。 |
| `OVERLEAF_COOKIE_SESSION_LENGTH` | セッション Cookie のデフォルトの有効期限(5 日間)を上書きできます。上書きする値はミリ秒単位で指定します。例: セッションを 1 時間にするには `COOKIE_SESSION_LENGTH=3600000` を設定します。(Server Pro 4.2 で追加) |
| `OVERLEAF_TRUSTED_PROXY_IPS` | <p>設定しない場合、デフォルトは `loopback` です。手動で設定する場合は、信頼する IP に加えて `loopback`(または `127.0.0.1`)も含める必要があります。これは <strong>sharelatex</strong> コンテナ内で実行されている nginx インスタンスを信頼するためです。IP アドレスと CIDR 範囲のみが受け付けられます。`localhost` などのホスト名を追加しないでください。追加すると Overleaf の起動に失敗し、`502 Bad Gateway` が返されます。<br /><br />通常のネットワークに `172.16.0.0/12`(Docker ネットワークのデフォルトサブネット)のサブネットを使用している場合は、`config/variables.env` で `OVERLEAF_TRUSTED_PROXY_IPS=loopback,<network>` を設定してください。`<network>` は `docker inspect overleaf_default` の `IPAM -> Config -> Subnet` の値です(例: `OVERLEAF_TRUSTED_PROXY_IPS=loopback,172.19.0.0/16`)。これは `X-Forwarded` ヘッダーのなりすましを防ぐためです。<br /><br />外部の TLS プロキシ(つまり Overleaf Toolkit で管理されていないもの)を使用している場合は、`OVERLEAF_TRUSTED_PROXY_IPS=loopback,<ip-of-your-tls-proxy>` となっていることを確認してください(例: `OVERLEAF_TRUSTED_PROXY_IPS=loopback,192.168.13.37`)。</p> |
| `OVERLEAF_RESTRICT_INVITES_TO_EXISTING_ACCOUNTS` | `true` に設定すると、プロジェクトへの招待を既存のユーザーアカウントに対応するメールアドレスに制限します。 |
| `OVERLEAF_ALLOW_PUBLIC_ACCESS` | `true` に設定すると、認証されていないユーザーもサイトを閲覧できるようになります。デフォルトは `false` で、認証されていないユーザーがサイトのいずれかの部分を閲覧しようとすると、無条件にログインページへリダイレクトされます。なお、このオプションを設定しても、認証やセキュリティが無効になることはありません。ユーザーがプロジェクトを公開し、認証されていないユーザーにそのプロジェクトを閲覧させたい場合には、このオプションが必要です。 |
| `OVERLEAF_ALLOW_ANONYMOUS_READ_AND_WRITE_SHARING` | `true` に設定すると、[リンク共有](https://www.overleaf.com/blog/integration-update-link-sharing-2017-11-27)機能で共有されたプロジェクトを匿名ユーザーが閲覧・編集できるようになります。 |
| `OVERLEAF_DISABLE_LINK_SHARING` | [リンク共有](https://www.overleaf.com/blog/integration-update-link-sharing-2017-11-27)機能を無効にします。 |
| `EMAIL_CONFIRMATION_DISABLED` | `true` に設定すると、メールアドレスの確認を求めるバナーが表示されなくなります。 |
| `ADDITIONAL_TEXT_EXTENSIONS` | 編集可能なファイルの追加の拡張子を設定するための文字列の配列。 |
| `DEFAULT_LATEX_COMPILER` | <p><strong>新規</strong>プロジェクトで使用されるデフォルトのコンパイラーを設定します。(Server Pro 6.2.0 で追加)</p><p><strong>オプション:</strong> `pdflatex`、`latex`、`xelatex` または `lualatex`</p> |
| `OVERLEAF_STATUS_PAGE_URL` | カスタムのステータスページ URL(Server Pro 3.4.0 で追加)。例: `status.example.com`。 |
| `OVERLEAF_FPH_INITIALIZE_NEW_PROJECTS` | `'false'` に設定すると、新規プロジェクトが Full Project History で初期化されなくなります(Server Pro 3.5.0 で追加)。 |
| `OVERLEAF_FPH_DISPLAY_NEW_PROJECTS` | `'false'` に設定すると、新規プロジェクトでレガシー履歴の代わりに Full Project History が表示されなくなります(Server Pro 3.5.0 で追加)。 |
| `ENABLE_CRON_RESOURCE_DELETION` | この環境変数を `true` に設定すると、削除されたプロジェクトとユーザーが 90 日後に自動的にクリーンアップされるようになります。 |
| `OVERLEAF_USER_HARD_DELETION_DELAY` | <p>削除されたユーザーの有効期限までの猶予期間を変更するために使用します。ミリ秒単位で設定します。<br /><br /><strong>デフォルト:</strong> 90 日</p> |
| `OVERLEAF_PROJECT_HARD_DELETION_DELAY` | <p>削除されたプロジェクトの有効期限までの猶予期間を変更するために使用します。ミリ秒単位で設定します。<br /><br /><strong>デフォルト:</strong> 90 日</p> |
| `MAX_UPLOAD_SIZE` | <p>個々のアップロードの最大サイズをメガバイト単位で制御します。デフォルトは `50` です。<br /><br /><strong>注意</strong>: この変数は単位(MB)や囲み文字のない、単なる数値です。<br /><br />アップロードされた `.zip` ファイルの展開後の合計サイズは、この値の 6 倍(デフォルトでは 300 MB)に制限されます。</p> |
| `COMPILE_SIZE_LIMIT` | リクエストボディの最大サイズをバイト単位で制御します。これは、CLSI サービスへの最初のコンパイルリクエストで送信する必要がある、プロジェクト内のすべてのドキュメントファイル(`main.tex`、`references.bib`(リンクされていない場合)など)のサイズの合計です。 |
| `COMPILE_TIMEOUT` | コンパイルの完了に許容される時間(秒)。詳細は[プロジェクトのコンパイルタイムアウトの更新](/ja/on-premises/user-and-project-management/project-management#updating-project-compile-timeout)を参照してください。 |
| `MAX_RECONNECT_GRACEFULLY_INTERVAL_MS` | データ損失のリスクを軽減するための、エディターの正常な再接続、データのフラッシュ、コンテナのシャットダウンの間の設定可能な遅延時間。 |
| `SECCOMP_PROFILE` | <p>この環境変数には、Docker <strong>ホスト</strong>マシン上の SECCOMP プロファイルを指すパスを設定します。プロファイルのコピーは<a href="https://raw.githubusercontent.com/overleaf/overleaf/365af778b68a7940e08282119dc4ef473e2f0044/services/clsi/seccomp/clsi-profile.json">こちら</a>からダウンロードできます。<br /><br />現在、Sandboxed Compiles を使用する Podman デプロイメントで必要です。</p> |
| `OVERLEAF_DISABLE_CHAT` | `true` に設定すると、プロジェクト内のチャット機能が無効になります。 |
| `OVERLEAF_LOGIN_SUPPORT_TEXT` | 設定すると、ログインボタンの下にサポート情報を表示できます。テキストはログイン画面に表示され、ユーザーを社内サポートに誘導したり、ログインやアカウント作成などに関する案内を提供したりするために使用できます。 |
| `ALLOW_MONGO_ADMIN_CHECK_FAILURES` | <p>`true` に設定すると、MongoDB の起動時チェックが失敗してもデプロイメントの起動が妨げられなくなります。データベースユーザーが `clusterParameterReader` ロールを持たない MongoDB データベースを使用している場合に必要になることがあります。<br /><br />カスタムロールの作成方法については<a href="/ja/on-premises/maintenance/updating-mongodb#creating-a-custom-role">こちら</a>を参照してください。</p> |
| `V1_HISTORY_URL_FOR_GIT_BRIDGE` | 内部トラフィック(`web` サービス → `history-v1` サービス、どちらも `sharelatex` コンテナ内)と外部トラフィック(`git-bridge` → `history-v1`、別々のコンテナで実行)で **history-v1** エンドポイントを分離できるようにします。 |
| `OVERLEAF_MAINTENANCE_MESSAGE` と `OVERLEAF_MAINTENANCE_MESSAGE_HTML` | メンテナンスページのタイトルと内容をカスタマイズするために使用します。`OVERLEAF_STATUS_PAGE_URL` とは併用できません。 |

<Info>

LDAP などの SSO オプションではなく、Overleaf のログインシステム(ローカルアカウント)を使用している場合は、ユーザーにパスワードの制限を適用できます。SSO アカウントの場合、パスワードポリシーは ID プロバイダーまたはディレクトリサービスによって適用され、さらに多要素認証もサポートできます。

</Info>
