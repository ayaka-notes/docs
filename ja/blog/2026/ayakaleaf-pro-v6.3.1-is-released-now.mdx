コミュニティで最も強力かつ多機能なオンライン LaTeX エディター、Overleaf Pro 6.3.1 のリリースを発表できることを大変誇りに思います。パッチリリースといえば、通常はいくつかの小さな修正にとどまるものです。しかし今回はそれをはるかに超えています。数十件のバグ修正に加えて 5 つの新機能をお届けし、Dropbox や GitLab から、ターミナルで使っている AI エージェントまで、普段お使いの場所とプロジェクトをつなげます。

### 変更点

* Dropbox 同期（アーリープレビュー）: すべてのプロジェクトを自分の Dropbox と双方向に同期します。
* GitLab 同期（アーリープレビュー）: GitLab.com またはセルフマネージドの GitLab と双方向に同期します。
* MCP サーバー: Claude Code、Codex、Cursor、VS Code、Gemini CLI がプロジェクト上で直接作業できるようになります。
* GitHub Enterprise: GitHub 同期の接続先を自社の GitHub Enterprise インスタンスに設定できます。
* 手書きシンボル認識: シンボルを描くと、対応する LaTeX コマンドが得られます。
* `OVERLEAF_DISABLE_LOCAL_LOGIN`: メールアドレスとパスワードによるログインを非表示にし、ユーザーが SSO でのみサインインするようにします。
* E2E テストシステムと Internal Horizon Issue Investigation によって見つかったバグの修正。
* アップストリームの Overleaf 6.3.1 のパッチ。

<Info>

Dropbox 同期と GitLab 同期は、グレーテスト用の**アーリープレビュー**として 6.3.1 に含まれており、v6.4.0 で正式リリースされる予定です。それまでに設定や動作が変更される可能性があります。どちらもデフォルトでは無効です。問題があれば [GitHub](https://github.com/ayaka-notes/ayakaleaf-pro/issues) で報告してください。

</Info>

#### 機能 01: Dropbox 同期（プレビュー）

Git のことは一切考えたくない、という人もいます。論文はノートパソコン上のフォルダーであってほしい――Dropbox 同期はまさにそれを実現します。各ユーザーが自分の Dropbox アカウントを連携すると、所有しているプロジェクトと共有されているプロジェクトが `Apps/<your app name>/` の下に表示されます。Overleaf で編集すると、その変更が Dropbox に反映されます。お気に入りのエディターでローカルのファイルを編集して保存すると、その変更は署名付きの Webhook を通じて Overleaf に戻ります。

管理者向け: Git bridge を有効にする必要があります。Dropbox App Console でアプリを作成し、`DROPBOX_ENABLED`、`DROPBOX_APP_KEY`、`DROPBOX_APP_SECRET`、`DROPBOX_APP_NAME`、`DROPBOX_TOKEN_CIPHER_PASSWORD` を設定してください。`DROPBOX_SYNC_PROXY_URL` はオプションで、Dropbox に直接接続できないサーバー向けです。その後、ユーザーがアカウントを連携する前に、Dropbox 同期に必要な MongoDB のインデックスを一度作成してください。

セットアップ手順の詳細については、[Dropbox 同期](/ja/on-premises/configuration/overleaf-toolkit/dropbox-synchronisation  "mention") を参照してください。

#### 機能 02: GitLab 同期（プレビュー）

GitHub 同期は 6.2 以来、最も愛されている機能の 1 つですが、多くの大学や企業ではコードを GitLab で管理しています。GitLab 同期も同じように動作します。アカウントを連携し、新規プロジェクトメニューからリポジトリをインポートするか、プロジェクトを新しい GitLab プロジェクトにエクスポートします。あとはエディターからプッシュとプルを行い、マージリクエストでマージするだけです。

GitLab.com と、セルフマネージドの GitLab 15.10 以降で動作します。`GITLAB_SYNC_ENABLED`、`GITLAB_SYNC_CLIENT_ID`、`GITLAB_SYNC_CLIENT_SECRET`、`GITLAB_TOKEN_CIPHER_PASSWORD` を設定し、セルフマネージドのインスタンスの場合はさらに `GITLAB_SYNC_URL` を設定してください。

セットアップ手順の詳細については、[GitLab 同期](/ja/on-premises/configuration/overleaf-toolkit/gitlab-synchronisation  "mention") を参照してください。

#### 機能 03: MCP サーバー

6.3 では、エディターの中に AI アシスタントを組み込みました。6.3.1 では逆方向の扉を開きます。すべてのプロジェクトが独自の MCP サーバーを持つようになり、普段お使いの AI エージェントが論文の上で直接作業できるようになりました。Claude Code に序論の誤字を直してもらったり、Codex にコンパイルして LaTeX エラーを修正してもらったり、Cursor に未解決のレビューコメントへ返信してもらったりできます。エージェントはファイルをリアルタイムで読み書きするため、あなたや共同編集者は、エージェントが入力するそばから編集内容がエディターに現れるのを目にすることになります。コンパイル、ログの読み取り、PDF の取得、単語数のカウント、バージョンの一覧表示も行えます。

エンドポイントは `/project/<project_id>/mcp` です。`git clone` で使用するのと同じ Git トークンで認証します。アクセス権はプロジェクトの共有設定に従うため、閲覧者のエージェントは読み取りはできても編集はできません。また、すべてのツールにはレート制限があります。ほかに設定するものはありません。MCP サーバーは Git bridge と一緒に有効になります。

<img src="https://github.com/user-attachments/assets/a8702201-db3f-4985-a050-b7ebdbe7a952" alt="MCP サーバー" width="787" />

各 AI クライアントの接続方法については、[MCP サーバー](/ja/on-premises/configuration/overleaf-toolkit/mcp-server  "mention") を参照してください。

#### 機能 04: GitHub Enterprise

GitHub 同期は github.com だけのものではなくなりました。`GITHUB_SYNC_URL` に GitHub Enterprise Server、またはデータレジデンシー付きの GitHub Enterprise Cloud（`GHE.com`）を設定すると、REST と GraphQL のエンドポイントはそこから自動的に導出されます。インスタンスの構成が特殊な場合は、`GITHUB_SYNC_API_URL` と `GITHUB_SYNC_GRAPHQL_URL` で上書きできます。未設定のままにしておけば、すべて github.com のままです。

詳細については、[GitHub 同期](/ja/on-premises/configuration/overleaf-toolkit/github-synchronisation#github-enterprise  "mention") を参照してください。

#### 機能 05: 手書きシンボル認識

シンボルの形はわかっているのに、名前がわからない。`\varsigma` なのか `\zeta` なのか? `\models` なのか `\vDash` なのか? シンボルパレットを描画モードに切り替え、マウスやトラックパッドでスケッチすれば、パレットが一致する LaTeX コマンドを提案してくれます。

認識は ayaka-notes がトレーニングしたモデルによって完全にブラウザ内で実行されるため、描いたものがあなたのマシンの外に出ることはありません。`OffscreenCanvas` に対応していないブラウザ（Safari 15 など）では、描画の切り替えボタンは表示されません。

#### バグ修正

今回のリリースには、数多くの修正も含まれています。その多くは、現在すべてのモジュールのテストスイートを毎日実行している新しい E2E テストシステムと、Internal Horizon Issue Investigation によって見つかったものです。私たちはバグを 1 つ修正するたびに、それをクローズする前に、同種のバグがないかコードベース全体を洗い出しています。

* **認証**: SSO インスタンスでもローカルアカウントがパスワードを設定・変更できるようになり、OIDC ユーザーは自分のメールアドレスを変更できなくなりました。名前属性が複数の値を持つ場合でも LDAP、SAML、OIDC のログインが失敗しなくなり、SAML/OIDC のログアウトが再び機能するようになりました。
* **停止されたユーザー**: ユーザーを停止すると、そのユーザーのセッションが終了し、開いているエディターが閉じられるようになりました。また、そのユーザーの Git トークンと MCP のダウンロードは拒否されます。
* **GitHub 同期**: プロジェクトをエクスポートできるのはオーナーのみになり、プル中に行った編集は保留状態のまま保持され、空のファイルも同期され、手動マージは GitHub 上で検証されます。
* **Zotero / Mendeley**: 認証情報が使えなくなった場合に再連携のメッセージが表示され、インポート後に参考文献が再インデックスされます。
* **外部サービス**: Zotero、Mendeley、GitHub、GitLab、Web 検索へのリクエストの接続タイムアウトが 1 秒から 3 秒になり、低速なネットワークでも失敗しなくなりました。
* **変更履歴**: レビューデータに、読み込まれていないドキュメントと未保存の変更が含まれるようになりました。
* **管理パネル**: 削除されたプロジェクトの復元、オーナーの変更、ユーザーの編集が正しく機能するようになり、メール送信に失敗してもアカウントの作成や削除が失敗しなくなりました。
* **テンプレートギャラリー**: 無効な並べ替えは 500 ではなく 400 を返すようになり、メインファイルのないプロジェクトを公開する際にはメインファイルの指定が求められます。

すべての変更点については、[6.3.1 のリリースノート](/ja/on-premises/release-notes/release-notes-6.x.x#ayakaleaf-pro-6.3.1  "mention") を参照してください。

#### アップグレード

* 6.3.0 から: 移行は不要です。新しいイメージを pull して再起動してください。
* Zotero または Mendeley を使用している 6.2.x 以前から: まず 6.3.0 の [Zotero / Mendeley の移行](/ja/on-premises/release-notes/release-notes-6.x.x#ayakaleaf-pro-6.3.0  "mention")を実行してください。
* Dropbox 同期と GitLab 同期はデフォルトで無効です。GitLab 同期に必要なのは新しい環境変数だけです。Dropbox 同期では、ユーザーがアカウントを連携する前に、MongoDB のインデックスを一度作成する必要もあります。[データベースインデックスの作成](/ja/on-premises/configuration/overleaf-toolkit/dropbox-synchronisation#create-the-database-indexes  "mention") を参照してください。
