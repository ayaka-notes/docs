Kubernetes chạy cùng các image như Toolkit. Không có image riêng cho Kubernetes.

| Image                                                | Được dùng bởi                                                                 |
| ---------------------------------------------------- | ----------------------------------------------------------------------- |
| `ghcr.io/ayaka-notes/overleaf-pro:6.3.2`             | Deployment `overleaf`                                               |
| `ghcr.io/ayaka-notes/overleaf-pro/git-bridge:6.3.2`  | [Tích hợp Git](/vi/on-premises/configuration/kubernetes/integrations/git-integration) (tùy chọn), cùng tag như trên |
| `ghcr.io/ayaka-notes/texlive-*`                      | biên dịch, được pull vào Docker trên các node ở [bước 0](/vi/on-premises/installation/using-kubernetes/0.-prepare-the-nodes) |

Các image được công khai trên [ghcr.io](https://github.com/ayaka-notes/ayakaleaf-pro/pkgs/container/overleaf-pro/) cho amd64 và arm64, nên kubelet có thể pull chúng mà không cần thông tin xác thực.

<Warning>

Luôn dùng một tag phiên bản, chẳng hạn `6.3.2`, không dùng `latest`. Các lần nâng cấp sẽ chạy migration cơ sở dữ liệu và phải tuân theo [Nâng cấp trên Kubernetes](/vi/on-premises/maintenance/upgrading-on-kubernetes); một tag thay đổi liên tục sẽ nâng cấp pod mỗi khi nó được lập lịch lại.

</Warning>

### Q\&A

<Accordion title="Các node của chúng tôi không truy cập được ghcr.io. Chúng tôi phải làm gì?">

<strong>Trả lời:</strong> Hãy sao chép các image vào một registry mà các node truy cập được và dùng tên đó trong các manifest, ví dụ:

```bash
docker pull ghcr.io/ayaka-notes/overleaf-pro:6.3.2
docker tag ghcr.io/ayaka-notes/overleaf-pro:6.3.2 registry.example.com/ayakaleaf/overleaf-pro:6.3.2
docker push registry.example.com/ayakaleaf/overleaf-pro:6.3.2
```

Với một registry không có TLS, containerd cần một tệp `/etc/containerd/certs.d/<registry>/hosts.toml` chứa `server = "http://<registry>"` trên mọi node, và `config_path` được đặt như ở [bước 0](/vi/on-premises/installation/using-kubernetes/0.-prepare-the-nodes). Bản thân Docker chỉ push qua HTTP thuần tới `localhost`, vì vậy hãy push thông qua `localhost:<port>` trên máy chủ registry hoặc thêm nó vào `insecure-registries`.

</Accordion>
