Bạn có thể mở rộng một image TeX Live sẵn có bằng một Dockerfile mới và cấu hình ứng dụng để sử dụng image mới đó.

Dưới đây chúng tôi đưa ra một số hướng dẫn để cài đặt gói hoặc phông chữ mới, tuy nhiên việc cấu hình image tùy chỉnh không nằm trong phạm vi điều khoản hỗ trợ của chúng tôi.

Các image TeX Live hiếm khi được cập nhật. Chúng tôi khuyên bạn nên build lại các image tùy chỉnh khi nâng cấp Server Pro.

<Danger>

Các phần sau chỉ áp dụng cho Server Pro và [Sandboxed Compiles](/vi/on-premises/configuration/overleaf-toolkit/sandboxed-compiles).

</Danger>

### Cài đặt và cập nhật gói mới

Bạn có thể dùng các lệnh `tlmgr` như `tlmgr install` và `tlmgr update` để quản lý các gói TeX Live như trong ví dụ sau:

```dockerfile
FROM ghcr.io/ayaka-notes/texlive-full:2023.1

RUN tlmgr update --force ebproof
```

### Sử dụng `tlmgr` trong image TeX Live cũ hơn

Theo mặc định, `tlmgr` tải tài nguyên từ bản phát hành TeX Live mới nhất. Khi vá một image TeX Live cũ hơn, nguồn tải cần được chuyển sang kho lưu trữ (archive) tương ứng. Xem danh sách tại [https://www.tug.org/historic/](https://www.tug.org/historic/) để biết các mirror của kho lưu trữ.

```dockerfile
FROM ghcr.io/ayaka-notes/texlive-full:2022.1

RUN tlmgr option repository <MIRROR>/systems/texlive/<YEAR>/tlnet-final
# e.g. RUN tlmgr option repository ftp://tug.org/historic/systems/texlive/2022/tlnet-final

RUN tlmgr update --force ebproof
```

### Cài đặt phông chữ mới

Có nhiều quy trình khác nhau để cài đặt phông chữ mới trong một bản phân phối TeX Live, và việc cài đặt một phông chữ tùy chỉnh có thể cần nhiều bước. Tham khảo [hướng dẫn cài đặt phông chữ TeX](https://tug.org/fonts/fontinstall.html) trong tài liệu chính thức của TeX Live có lẽ là một điểm khởi đầu tốt.

`Dockerfile` sau đây minh họa việc cài đặt một phông chữ TrueType lên một image TeX Live 2022 sẵn có:

```dockerfile
FROM ghcr.io/ayaka-notes/texlive-full:2022.1

COPY ./myfonts/*.ttf /usr/share/fonts/truetype/myfont/

# rebuild font information cache
RUN fc-cache
```

### Cấu hình Server Pro để sử dụng image mới

Sử dụng tên `ghcr.io/ayaka-notes/texlive-full` và một tag tùy chỉnh để build image mới, ví dụ:

```bash
docker build -t ghcr.io/ayaka-notes/texlive-full:2023.1-custom
```

Giờ đây ta có thể cấu hình Server Pro để sử dụng image `2023.1-custom` mới bằng cách cập nhật các biến môi trường `TEX_LIVE_DOCKER_IMAGE` và `ALL_TEX_LIVE_DOCKER_IMAGES`:

```text wrap
TEX_LIVE_DOCKER_IMAGE: "ghcr.io/ayaka-notes/texlive-full:2023.1-custom"
ALL_TEX_LIVE_DOCKER_IMAGES: "ghcr.io/ayaka-notes/texlive-full:2023.1,ghcr.io/ayaka-notes/texlive-full:2023.1-custom"
```

Trong ví dụ trên, các dự án mới được đặt mặc định sử dụng image `2023.1-custom` mới, trong khi `2023.1` vẫn sẵn có khi cần.
