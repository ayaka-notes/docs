### Thiết lập đồng bộ hóa GitHub

<Warning>

Bạn cần bật [git-bridge](/vi/on-premises/configuration/overleaf-toolkit/git-integration) trước khi sử dụng đồng bộ hóa GitHub.

```dotenv title="config/overleaf.rc"
GIT_BRIDGE_ENABLED=true
```

</Warning>

Truy cập [developers settings](https://github.com/settings/developers) để tạo ứng dụng GitHub OAuth của bạn, sau đó sao chép `CLIENT_ID` và `SECRET`.

**Lưu ý**: khi tạo OAuth App, hãy nhập `${OVERLEAF_SITE_URL}/user/github-sync/oauth2/callback` vào ô **Authorization callback URL**. Ayakaleaf Pro tạo cùng địa chỉ này từ `OVERLEAF_SITE_URL`, vì vậy bạn không cần đặt gì cho nó trong `config/variables.env`.

Sau đó, thêm các cài đặt sau vào tệp biến môi trường của Overleaf.

```dotenv title="config/variables.env" wrap
# used to encrypt the user's GitHub access token.
# How to generate: `openssl rand -hex 32`
GITHUB_TOKEN_CIPHER_PASSWORD=0123456789ABCDEFG # changed to yours

# Github Sync Settings
GITHUB_SYNC_ENABLED=true
GITHUB_SYNC_CLIENT_ID=
GITHUB_SYNC_CLIENT_SECRET=

# OAuth callback is: ${OVERLEAF_SITE_URL}/user/github-sync/oauth2/callback
# (Optional) GITHUB_SYNC_PROXY_URL=http://10.0.0.1:10808
```

<Warning>

Trước khi cấu hình URL callback OAuth của GitHub, hãy đảm bảo `OVERLEAF_SITE_URL` đã được đặt chính xác.

</Warning>

Nếu bạn ở khu vực có hạn chế truy cập mạng, có thể bạn cần cấu hình proxy để truy cập GitHub. Hãy đặt biến môi trường sau: `GITHUB_SYNC_PROXY_URL=http://10.0.0.1:10808`. Vui lòng đảm bảo việc sử dụng proxy của bạn tuân thủ luật pháp và quy định địa phương.

<Warning>

`GITHUB_SYNC_PROXY_URL` phải là một proxy chuyển tiếp HTTP/HTTPS tiêu chuẩn (ví dụ: cổng HTTP của Clash). Các mirror tải xuống GitHub như `gh-proxy.org` không được hỗ trợ.

</Warning>

<Warning>

Không sử dụng `127.0.0.1` làm máy chủ proxy. Nếu proxy chạy trên máy chủ host, hãy dùng địa chỉ IP LAN của máy chủ (ví dụ `192.168.1.xx`) và đảm bảo proxy được cấu hình để chấp nhận kết nối từ các thiết bị trong mạng cục bộ.

</Warning>

### GitHub Enterprise

<Info>

Hỗ trợ GitHub Enterprise được giới thiệu từ v6.3.1 trở đi. Các phiên bản trước chỉ kết nối tới `github.com` và các biến bên dưới không có tác dụng.

</Info>

Theo mặc định, đồng bộ hóa GitHub kết nối tới `github.com`. Để sử dụng GitHub Enterprise Server (tự lưu trữ) hoặc GitHub Enterprise Cloud với lưu trữ dữ liệu theo khu vực (`GHE.com`), hãy đặt `GITHUB_SYNC_URL` thành địa chỉ web của phiên bản của bạn, tức là địa chỉ bạn dùng để mở các kho lưu trữ trong trình duyệt.

```dotenv title="config/variables.env" wrap
# GitHub Enterprise Server
GITHUB_SYNC_URL=https://github.example.com

# or GitHub Enterprise Cloud with data residency
# GITHUB_SYNC_URL=https://octocorp.ghe.com
```

Các endpoint REST API và GraphQL API được suy ra từ `GITHUB_SYNC_URL` theo cùng cách mà GitHub CLI thực hiện:

| `GITHUB_SYNC_URL`             | REST API                         | GraphQL API                              |
| ----------------------------- | -------------------------------- | ---------------------------------------- |
| `https://github.com` (mặc định) | `https://api.github.com`         | `https://api.github.com/graphql`         |
| `https://SUBDOMAIN.ghe.com`   | `https://api.SUBDOMAIN.ghe.com`  | `https://api.SUBDOMAIN.ghe.com/graphql`  |
| `https://HOST` (bất kỳ địa chỉ nào khác)    | `https://HOST/api/v3`            | `https://HOST/api/graphql`               |

Chỉ đặt các endpoint API khi phiên bản của bạn phục vụ chúng ở một địa chỉ khác, ví dụ phía sau một API gateway:

| Biến                  | Mặc định                                                                                   |
| ------------------------- | ----------------------------------------------------------------------------------------- |
| `GITHUB_SYNC_URL`         | `https://github.com`                                                                      |
| `GITHUB_SYNC_API_URL`     | Được suy ra từ `GITHUB_SYNC_URL`, xem bảng ở trên                                       |
| `GITHUB_SYNC_GRAPHQL_URL` | Được suy ra từ `GITHUB_SYNC_API_URL` khi biến này được đặt (`/api/v3` trở thành `/api/graphql`, nếu không thì `/graphql` được nối thêm vào cuối), ngược lại thì suy ra từ `GITHUB_SYNC_URL` |

<Warning>

* Hãy tạo ứng dụng OAuth trên phiên bản enterprise của bạn (_Settings → Developer settings → OAuth Apps_), ứng dụng từ `github.com` sẽ không hoạt động ở đó. URL callback vẫn giữ nguyên: `${OVERLEAF_SITE_URL}/user/github-sync/oauth2/callback`.
* `GITHUB_SYNC_URL` chỉ là địa chỉ web. Không đặt nó thành một địa chỉ API như `https://api.github.com` hoặc `https://HOST/api/v3`, và không thêm đường dẫn tổ chức.
* Cả ba địa chỉ phải trỏ tới cùng một phiên bản GitHub.

</Warning>

<Info>

Nếu phiên bản của bạn sử dụng chứng chỉ từ một CA riêng, hãy mount chứng chỉ CA vào container và trỏ `NODE_EXTRA_CA_CERTS` tới chứng chỉ đó, ví dụ `NODE_EXTRA_CA_CERTS=/var/lib/overleaf/certs/github-ca.pem`.

</Info>

<Danger>

Các tài khoản và dự án đã liên kết thuộc về phiên bản mà chúng được liên kết. Trước khi chuyển `GITHUB_SYNC_URL` sang một phiên bản khác, hãy yêu cầu người dùng hủy liên kết tài khoản GitHub và các dự án của họ.

</Danger>

### Ai có thể liên kết và đồng bộ

Giống như trên Overleaf Cloud, chỉ chủ sở hữu dự án mới có thể liên kết dự án với một kho lưu trữ GitHub. Sau khi đã liên kết, mọi cộng tác viên có quyền chỉnh sửa đều có thể đồng bộ dự án.

| Hành động                                                     | Ai có thể thực hiện                                                  |
| ---------------------------------------------------------- | -------------------------------------------------------------- |
| Xuất dự án sang một kho lưu trữ GitHub mới                | Chủ sở hữu dự án                                              |
| Nhập một kho lưu trữ GitHub vào một dự án mới              | Bất kỳ người dùng nào, người đó sẽ trở thành chủ sở hữu của dự án mới             |
| Pull, push và merge một dự án đã liên kết                      | Chủ sở hữu và các cộng tác viên có quyền chỉnh sửa                   |
| Hủy liên kết dự án khỏi kho lưu trữ của nó                       | Chủ sở hữu dự án                                              |

* Overleaf giao tiếp với GitHub bằng tài khoản GitHub của người dùng thực hiện đồng bộ, vì vậy mỗi cộng tác viên thực hiện đồng bộ cần liên kết tài khoản GitHub của riêng mình và phải được phép push lên nhánh mặc định của kho lưu trữ.
* Cộng tác viên chỉ có quyền xem không thể sử dụng đồng bộ hóa GitHub cho dự án.

### Q\&A

<Accordion title="Tôi có thể force push lên nhánh mặc định không?">

<strong>Trả lời:</strong> Chúng tôi không khuyến khích điều này. Overleaf sẽ phát hiện force push, đưa ra cảnh báo và tiếp quản nhánh đã bị viết lại, hợp nhất các thay đổi được thực hiện trong Overleaf kể từ lần đồng bộ gần nhất. Để tránh những bất ngờ, hãy bảo vệ nhánh mặc định khỏi force push trong phần cài đặt của kho lưu trữ.

</Accordion>

<Accordion title="Tôi có thể đổi tên nhánh mặc định của một dự án đã liên kết không?">

<strong>Trả lời:</strong> Vui lòng không làm vậy. Overleaf tiếp tục đồng bộ với nhánh mà dự án đã được liên kết. Để đồng bộ với một nhánh khác, hãy hủy liên kết dự án, sau đó nhập kho lưu trữ vào một dự án mới, dự án này sẽ sử dụng nhánh mặc định hiện tại.

</Accordion>

<Accordion title="Đồng bộ GitHub hiển thị “Something wrong with GitHub request”">

<strong>Trả lời:</strong> Thông báo này có nghĩa là máy chủ không thể kết nối tới GitHub, ví dụ do sự cố mạng, DNS, TLS hoặc proxy. Hãy chạy `bin/logs web` để xem lỗi đầy đủ. Nếu máy chủ cần proxy để kết nối tới GitHub, hãy đặt `GITHUB_SYNC_PROXY_URL`.

</Accordion>

<Accordion title="Tôi có nên tắt “Expire user access tokens” trong GitHub OAuth App không?">

<strong>Trả lời:</strong> Có. Đồng bộ GitHub không gia hạn các token đã hết hạn. Khi bật token có thời hạn, người dùng sẽ phải kết nối lại GitHub mỗi khi token của họ hết hạn.

</Accordion>

<Accordion title="Phiên bản của tôi có cần truy cập được từ internet không?">

<strong>Trả lời:</strong> Không. Việc liên kết tài khoản diễn ra thông qua trình duyệt của người dùng, vì vậy địa chỉ callback OAuth chỉ cần mở được trong trình duyệt của người dùng. Máy chủ chỉ cần kết nối được tới GitHub; nếu cần proxy để làm điều đó, hãy đặt `GITHUB_SYNC_PROXY_URL`. GitHub không bao giờ gọi tới phiên bản của bạn: một dự án chỉ được đồng bộ khi người dùng đồng bộ nó trong trình soạn thảo.

</Accordion>
