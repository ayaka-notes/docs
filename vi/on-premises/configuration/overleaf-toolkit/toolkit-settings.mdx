Trang này mô tả các biến môi trường được hỗ trợ trong tệp `config/overleaf.rc` cho các triển khai bằng Toolkit.

Tệp `config/overleaf.rc` bao gồm các định nghĩa biến ở dạng `NAME=value`. Các dòng bắt đầu bằng `#` được coi là chú thích.

<Info>

Bạn cần tạo lại các container Docker sau khi thay đổi bất kỳ nội dung nào trong `overleaf.rc` hoặc `variables.env` bằng cách chạy `bin/up`.

</Info>

## Container

### `sharelatex`

| Tên                          | Mô tả |
| ---------------------------- | ----- |
| `PROJECT_NAME`               | <p>Đặt giá trị của cờ `--project-name` được truyền cho `docker-compose`. Điều này hữu ích khi chạy nhiều phiên bản Overleaf trên cùng một máy chủ, vì mỗi phiên bản có thể có một tên dự án khác nhau.<br /><br />- <strong>Mặc định</strong>: `overleaf`</p> |
| `OVERLEAF_IMAGE_NAME`        | <p>Docker image được container ứng dụng Server Pro/CE sử dụng. Đây chỉ là tên Docker image; tag của Docker image được lấy từ `config/version`.<br /><br />- <strong>Mặc định:</strong><br />- Server Pro: `ghcr.io/ayaka-notes/overleaf-pro`<br />- Community Edition: `sharelatex/sharelatex`</p> |
| `SERVER_PRO`                 | <p>Khi được đặt là `true`, Toolkit sẽ dùng image Server Pro (`ghcr.io/ayaka-notes/overleaf-pro`) thay vì image Server CE mặc định (`sharelatex/sharelatex`).<br /><br />- <strong>Mặc định</strong>: `false`</p> |
| `GIT_BRIDGE_ENABLED`         | <p>Đặt là `true` để bật tính năng git-bridge (chỉ Server Pro). Để biết thêm thông tin, xem tài liệu người dùng <a href="https://www.overleaf.com/learn/how-to/Git_integration">https://www.overleaf.com/learn/how-to/Git_integration</a>.<br /><br />- <strong>Mặc định:</strong> `false`</p> |
| `GIT_BRIDGE_IMAGE`           | <p>Docker image được container git-bridge sử dụng (chỉ Server Pro). Đây chỉ là tên Docker image; tag của Docker image được lấy từ `config/version`.<br /><br />- <strong>Mặc định:</strong> `ghcr.io/ayaka-notes/overleaf-pro/git-bridge`</p> |
| `GIT_BRIDGE_DATA_PATH`       | Đặt đường dẫn tới thư mục sẽ được gắn vào container `git-bridge` (chỉ Server Pro) và được dùng để lưu trữ các kho git. Đây có thể là đường dẫn đầy đủ (bắt đầu bằng `/`) hoặc đường dẫn tương đối so với thư mục gốc của Toolkit. |
| `GIT_BRIDGE_LOG_LEVEL`       | <p>Cấu hình mức ghi log của container `git-bridge`. Các mức khả dụng: `TRACE`, `DEBUG`, `INFO`, `WARN`, `ERROR`.<br /><br />- <strong>Mặc định:</strong> `INFO`</p> |
| `SIBLING_CONTAINERS_ENABLED` | <p>Khi được đặt là `true`, Toolkit sẽ dùng kỹ thuật <strong>Sibling Containers</strong> để biên dịch các dự án trong các sandbox riêng biệt, sử dụng một container Docker riêng cho mỗi dự án. Xem tài liệu &#x3C;server-pro-only-configuration/sandboxed-compiles> để biết thêm thông tin.<br /><br />- <strong>Yêu cầu:</strong> `SERVER_PRO=true`<br />- <strong>Mặc định:</strong> `true`</p> |
| `SIBLING_CONTAINERS_PULL`    | <p>Khi được đặt là `true`, Toolkit sẽ tự động tải về tất cả các image TeX Live được đặt bằng `ALL_TEX_LIVE_DOCKER_IMAGES` trong tệp <strong>config/variables.env</strong> khi dùng lệnh `bin/up`.<br /><br />- <strong>Mặc định:</strong> `true`</p> |
| `DOCKER_SOCKET_PATH`         | <p>Đặt đường dẫn tới Docker socket trên máy chủ host (máy đang chạy Toolkit). Khi `SIBLING_CONTAINERS_ENABLED` là `true`, socket sẽ được gắn vào container để cho phép dịch vụ biên dịch tạo các container Docker mới trên máy chủ host.<br /><br />- <strong>Yêu cầu:</strong> `SIBLING_CONTAINERS_ENABLED=true`<br />- <strong>Mặc định:</strong> `/var/run/docker.sock`</p> |
| `OVERLEAF_DATA_PATH`         | <p>Đặt đường dẫn tới thư mục sẽ được gắn vào container `sharelatex` chính và được dùng để lưu trữ dữ liệu biên dịch. Đây có thể là đường dẫn đầy đủ (bắt đầu bằng `/`) hoặc đường dẫn tương đối so với thư mục gốc của Toolkit.<br /><br />- <strong>Mặc định:</strong> `data/overleaf`</p> |
| `OVERLEAF_LISTEN_IP`         | <p>Đặt (các) địa chỉ IP của máy chủ host mà container sẽ bind vào. Ví dụ, nếu giá trị này được đặt là `0.0.0.0`, giao diện web sẽ khả dụng trên mọi địa chỉ IP của máy chủ host. Để truy cập trực tiếp vào container, giá trị của `OVERLEAF_LISTEN_IP` phải được đặt là địa chỉ IP công khai của bạn. Việc đặt `OVERLEAF_LISTEN_IP` là `0.0.0.0` hoặc IP bên ngoài của máy chủ host thường sẽ gây lỗi khi dùng kết hợp với .<br /><br />- <strong>Mặc định:</strong> `127.0.0.1`</p> |
| `OVERLEAF_PORT`              | <p>Đặt cổng của máy chủ host mà container sẽ bind vào. Ví dụ, nếu giá trị này được đặt là `8099` và `OVERLEAF_LISTEN_IP` được đặt là `127.0.0.1`, giao diện web sẽ khả dụng tại `http://localhost:8099`.<br /><br />- <strong>Mặc định:</strong> `80`</p> |
| `OVERLEAF_LOG_PATH`          | <p>Đặt đường dẫn tới thư mục sẽ được gắn vào container `sharelatex` chính và được dùng để cung cấp log của ứng dụng trên máy chủ Docker host. Đây có thể là đường dẫn đầy đủ (bắt đầu bằng `/`) hoặc đường dẫn tương đối so với thư mục gốc của Toolkit. Xóa mục cấu hình này để tắt bind-mount. Khi không được đặt, log sẽ bị loại bỏ khi tạo lại container.<br /><br />Xem để biết thông tin về việc ghi log.<br /><br />- <strong>Mặc định:</strong> không đặt</p> |

### `mongo`

| Tên               | Mô tả |
| ----------------- | ----- |
| `MONGO_ENABLED`   | <p>Khi được đặt là `true`, Toolkit sẽ tạo một container MongoDB để chứa cơ sở dữ liệu. Khi được đặt là `false`, container này sẽ không được tạo và hệ thống sẽ dùng cơ sở dữ liệu MongoDB được chỉ định bởi `MONGO_URL`.<br /><br />- <strong>Mặc định</strong>: `true`</p> |
| `MONGO_URL`       | <p>Chỉ định URL kết nối MongoDB được dùng khi `MONGO_ENABLED` là `false`.<br /><br />- <strong>Mặc định</strong>: không đặt</p> |
| `MONGO_DATA_PATH` | <p>Đặt đường dẫn tới thư mục sẽ được gắn vào container `mongo` và được dùng để lưu trữ cơ sở dữ liệu MongoDB. Đây có thể là đường dẫn đầy đủ (bắt đầu bằng `/`) hoặc đường dẫn tương đối so với thư mục gốc của toolkit. Tùy chọn này chỉ ảnh hưởng đến container `mongo` cục bộ được tạo khi `MONGO_ENABLED` là `true`.<br /><br />- <strong>Mặc định</strong>: `data/mongo`</p> |
| `MONGO_IMAGE`     | <p>Docker image được container MongoDB sử dụng. Đây chỉ là tên Docker image; tag của Docker image nên được đặt trong `MONGO_VERSION` (xem bên dưới).<br /><br />- <strong>Mặc định:</strong> `mongo`</p> |
| `MONGO_VERSION`   | <p>Phiên bản MongoDB được container MongoDB sử dụng. Giá trị phải bắt đầu bằng phiên bản chính của MongoDB và một dấu chấm, ví dụ `6.0` hoặc `6.0-with-suffix`.<br /><br />- <strong>Mặc định:</strong> `6.0`</p> |

| `REDIS_DATA_PATH`       | <p>Đặt đường dẫn tới thư mục sẽ được gắn vào container `redis` và được dùng để lưu trữ cơ sở dữ liệu Redis. Đây có thể là đường dẫn đầy đủ (bắt đầu bằng `/`) hoặc đường dẫn tương đối so với thư mục gốc của Toolkit. Đây là cấu hình lưu trữ bền vững <strong>được khuyến nghị</strong> cho Redis.<br /><br />Để biết thêm chi tiết, xem phần &#x3C;../../../maintenance/data-and-backups#aof-append-only-file> trong &#x3C;../../maintenance/data-and-backups>.<br /><br />- <strong>Mặc định:</strong> `true`</p> |

### `nginx`

| Tên                    | Mô tả |
| ---------------------- | ----- |
| `NGINX_ENABLED`        | <p>Khi được đặt là `true`, Toolkit sẽ tạo một container NGINX để làm TLS Proxy.<br /><br />- <strong>Mặc định</strong>: `false`</p> |
| `NGINX_CONFIG_PATH`    | <p>Đường dẫn tới tệp cấu hình NGINX dùng cho TLS Proxy.<br /><br />- <strong>Mặc định</strong>: `config/nginx/nginx.conf`</p> |
| `NGINX_TLS_LISTEN_IP`  | <p>Đặt (các) địa chỉ IP của máy chủ host mà container TLS Proxy sẽ bind vào cho HTTPS. Ví dụ, nếu giá trị này được đặt là `0.0.0.0`, giao diện web HTTPS sẽ khả dụng trên mọi địa chỉ IP của máy chủ host. Thông thường, giá trị này nên được đặt là IP bên ngoài của máy chủ host.<br /><br />- <strong>Mặc định</strong>: `127.0.1.1`</p> |
| `NGINX_HTTP_LISTEN_IP` | <p>Đặt (các) địa chỉ IP của máy chủ host mà container TLS Proxy sẽ bind vào để chuyển hướng HTTP. Ví dụ, nếu giá trị này được đặt là `127.0.1.1`, các kết nối HTTP tới `127.0.1.1` sẽ được chuyển hướng tới giao diện web HTTPS. Thông thường, giá trị này nên được đặt là IP bên ngoài của máy chủ host. Không đặt là `0.0.0.0` vì điều này thường sẽ gây xung đột với `OVERLEAF_LISTEN_IP`.<br /><br />- <strong>Mặc định</strong>: `127.0.1.1`</p> |
| `NGINX_HTTP_PORT`      | <p>Đặt cổng của máy chủ host mà container TLS Proxy sẽ bind vào cho HTTP.<br /><br />- <strong>Mặc định</strong>: `80`</p> |
| `TLS_PORT`             | <p>Đặt cổng của máy chủ host mà container TLS Proxy sẽ bind vào cho HTTPS.<br /><br />- <strong>Mặc định</strong>: `443`</p> |
| `TLS_PRIVATE_KEY_PATH` | <p>Đường dẫn tới khóa riêng (private key) dùng cho TLS Proxy.<br /><br />- <strong>Mặc định</strong>: `config/nginx/certs/overleaf_key.pem`</p> |
| `TLS_CERTIFICATE_PATH` | <p>Đường dẫn tới chứng chỉ công khai dùng cho TLS Proxy.<br /><br />- <strong>Mặc định</strong>: `config/nginx/certs/overleaf_certificate.pem`</p> |
