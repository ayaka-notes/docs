`docSnapshots` зберігає копії документа, які document-updater робить безпосередньо перед редагуванням, що згортає коментарі або відстежувані зміни. Записує в неї лише document-updater, у `services/document-updater/app/js/SnapshotManager.js`. У web є модель Mongoose у `services/web/app/src/models/DocSnapshot.mjs`, але жоден код її не використовує.

#### Поля {#fields}

| Поле | Тип | Значення | Джерело |
| ----- | ---- | ------- | ------ |
| `_id` | ObjectId | Ідентифікатор знімка. | `SnapshotManager.js:24` |
| `project_id` | ObjectId | Проєкт. | `SnapshotManager.js:19,26`, `DocSnapshot.mjs:7` |
| `doc_id` | ObjectId | Документ (`docs._id`). | `SnapshotManager.js:20,27`, `DocSnapshot.mjs:8` |
| `version` | Number | OT-версія документа до редагування. | `SnapshotManager.js:28`, `services/document-updater/app/js/UpdateManager.js:132,264-271`, `DocSnapshot.mjs:9` |
| `lines` | Array of String | Вміст документа до редагування. | `SnapshotManager.js:29`, `DocSnapshot.mjs:10` |
| `pathname` | String | Шлях до документа в проєкті на той момент. | `SnapshotManager.js:30`, `DocSnapshot.mjs:11` |
| `ranges` | Mixed | `comments` і `changes` до редагування, у тій самій формі, що й `docs.ranges` (див. [docs](/uk/dev/data-model/docs-collection)). `id`, `op.t` і `metadata.user_id` перетворюються на ObjectId, а `metadata.ts` на Date. | `SnapshotManager.js:31,41-68`, `DocSnapshot.mjs:12` |
| `ts` | Date | Коли зроблено знімок. TTL-індекс видаляє знімок через 30 днів. | `SnapshotManager.js:32`, `DocSnapshot.mjs:13` |

#### Хто записує {#who-writes-it}

| Код | Що робить |
| ---- | ------------ |
| `UpdateManager.js:248-271` | Застосувавши редагування, document-updater зберігає документ у стані до редагування, якщо редагування згорнуло діапазони: порожніх діапазонів стало більше або було видалено більше ніж один діапазон (`services/document-updater/app/js/RangesManager.js:104-106`). |
| `SnapshotManager.js:17-36` `recordSnapshot` | Вставляє знімок. |

#### Хто читає {#who-reads-it}

Жоден код її не читає. Модель web визначено, але ніде не використано.

#### Примітки {#notes}

* Знімки створюють лише редагування, що проходять через `UpdateManager.applyUpdate`. Редагування, які обробляє `HistoryOTUpdateManager`, їх не створюють (`UpdateManager.js:74-77`).
* Індексу за `doc_id` немає. Шукайте знімки документа за `project_id` і `ts`, а потім фільтруйте за `doc_id`.
