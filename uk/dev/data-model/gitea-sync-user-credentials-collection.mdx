---
title: Колекція Gitea Sync User Credentials
icon: lock
---

`giteaSyncUserCredentials` зберігає по одному документу на кожного користувача, який пов’язав обліковий запис Gitea для Gitea Sync. Вона зберігає OAuth-токени користувача в зашифрованому вигляді. Колекція належить до вебмодуля `gitea-sync` (`services/web/modules/gitea-sync`). Схема міститься в `services/web/modules/gitea-sync/app/models/giteaSyncUserCredentials.mjs`, а весь доступ іде через `services/web/modules/gitea-sync/app/src/TokenManager.mjs`.

#### Поля {#fields}

| Поле | Тип | Значення | Джерело |
| ----- | ---- | ------- | ------ |
| `_id` | ObjectId | Задається Mongoose, коли upsert вставляє документ. | |
| `userId` | ObjectId | Користувач Overleaf. Обов’язкове. У схемі вказано `unique: true`, але індекс не створюється (див. «Індекси»); upsert за `userId` зберігає один документ на користувача. | `giteaSyncUserCredentials.mjs:8`, `TokenManager.mjs:89-96` |
| `gitea` | String | JSON `{ accessToken, refreshToken, expiresAt }`, зашифрований за допомогою `@overleaf/access-token-encryptor`. `expiresAt` задається в мілісекундах від початку епохи або дорівнює `null`; `refreshToken` може бути `null`. Пароль береться з `GITEA_TOKEN_CIPHER_PASSWORD`; мітка шифру `GITEA_TOKEN_CIPHER_LABEL`, типово `2026.10-v3`. Обов’язкове. | `giteaSyncUserCredentials.mjs:9-10`, `TokenManager.mjs:17-30`, `services/web/modules/gitea-sync/app/src/GiteaApiClient.mjs:198-209` |
| `__v` | Number | Ключ версії Mongoose. Схема його не вимикає. | Типово в Mongoose |

#### Хто записує {#who-writes-it}

| Код | Що робить |
| ---- | ------------ |
| `TokenManager.mjs:89-96` (`saveUserToken`) | Виконує upsert зашифрованих облікових даних користувача. Викликається з OAuth-колбека (`services/web/modules/gitea-sync/app/src/GiteaSyncController.mjs:146`). На відміну від GitLab Sync, повторне пов’язування не відкликає замінений токен. |
| `TokenManager.mjs:53-79` (`refreshUserToken`) | Коли до `expiresAt` токена доступу лишається менше 5 хвилин (`:12`), отримує нові токени за токеном оновлення й зберігає їх (`:76`). Працює під блокуванням `giteaSyncToken` для кожного користувача (`:14,54`), бо Gitea замінює токен оновлення під час використання. |
| `TokenManager.mjs:100-102` (`removeUserToken`) | Видаляє документ. Gitea не має API для відкликання OAuth-токена, тому користувач сам відкликає дозвіл у Gitea (`:98-99`). Викликається під час відв’язування (`GiteaSyncController.mjs:173`) і коли спливає термін видаленого користувача (`services/web/modules/gitea-sync/index.mjs:56-58`). |

#### Хто читає {#who-reads-it}

| Код | Що робить |
| ---- | ------------ |
| `TokenManager.mjs:40-44,82-86` (`getUserCredentials`, `getUserToken`) | Розшифровує облікові дані для кожного виклику API Gitea, спершу оновлюючи їх, якщо термін токена скоро спливає: `services/web/modules/gitea-sync/app/src/GiteaSyncHandler.mjs` (наприклад, `:27`) і `services/web/modules/gitea-sync/app/src/GitMerge.mjs:52`. Якщо документа немає або облікові дані не вдається розшифрувати чи оновити, кидає `InvalidTokenError`, і користувач вважається непов’язаним (`GiteaSyncHandler.mjs:25-37`). |
| `services/web/modules/admin-tools/app/src/AdminUserListManager.mjs:395` | Перевіряє, чи є в користувача документ, для інтеграцій, що показуються в панелі адміністратора. |

#### Індекси {#indexes}

| Назва | Ключі | Параметри | Міграція |
| ---- | ---- | ------- | --------- |
| `_id_` | `_id: 1` | | default |

`autoIndex` у Mongoose вимкнено (`services/web/app/src/infrastructure/Mongoose.mjs:7`), тому `unique: true` зі схеми на `userId` нічого не створює. Жодна міграція не створює індекси для цієї колекції.

#### Примітки {#notes}

* Зміна `GITEA_TOKEN_CIPHER_PASSWORD` робить збережені облікові дані нечитабельними. Такі користувачі вважаються непов’язаними, доки не пов’яжуть обліковий запис повторно.
* Видалений користувач зберігає документ, доки не спливе його термін.
