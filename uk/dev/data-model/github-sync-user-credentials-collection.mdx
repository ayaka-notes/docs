---
title: Колекція GitHub Sync User Credentials
icon: key
---

`githubSyncUserCredentials` зберігає по одному документу на кожного користувача, який пов’язав обліковий запис GitHub для GitHub Sync. Вона зберігає OAuth-токен доступу користувача в зашифрованому вигляді. Колекція належить до вебмодуля `github-sync` (`services/web/modules/github-sync`). Схема міститься в `services/web/modules/github-sync/app/models/githubSyncUserCredentials.mjs`, а весь доступ іде через `services/web/modules/github-sync/app/src/TokenManager.mjs`.

#### Поля {#fields}

| Поле | Тип | Значення | Джерело |
| ----- | ---- | ------- | ------ |
| `_id` | ObjectId | Задається Mongoose, коли upsert вставляє документ. | |
| `userId` | ObjectId | Користувач Overleaf. Обов’язкове. У схемі вказано `unique: true`, але індекс не створюється (див. «Індекси»); upsert за `userId` зберігає один документ на користувача. | `githubSyncUserCredentials.mjs:8`, `TokenManager.mjs:44-48` |
| `github` | String | OAuth-токен доступу GitHub, зашифрований за допомогою `@overleaf/access-token-encryptor`. Пароль береться з `GITHUB_TOKEN_CIPHER_PASSWORD`; мітка шифру `GITHUB_TOKEN_CIPHER_LABEL`, типово `2026.3-v3`. Обов’язкове. | `githubSyncUserCredentials.mjs:9`, `TokenManager.mjs:12-25` |
| `__v` | Number | Ключ версії Mongoose. Схема його не вимикає. | Типово в Mongoose |

Зберігається лише токен доступу: OAuth-колбек бере з відповіді GitHub тільки `access_token` (`services/web/modules/github-sync/app/src/GitHubApiClient.mjs:180-191`). Токена оновлення й терміну дії немає.

#### Хто записує {#who-writes-it}

| Код | Що робить |
| ---- | ------------ |
| `TokenManager.mjs:42-58` (`saveUserToken`) | Виконує upsert зашифрованого токена користувача. Коли користувач пов’язує обліковий запис повторно, замінений токен відкликається в GitHub у фоні. Викликається з OAuth-колбека (`services/web/modules/github-sync/app/src/GitHubSyncController.mjs:146`). |
| `TokenManager.mjs:61-76` (`removeUserToken`) | Відкликає токен у GitHub (за можливості), потім видаляє документ. Викликається під час відв’язування (`GitHubSyncController.mjs:167`) і коли спливає термін видаленого користувача (`services/web/modules/github-sync/index.mjs:66-68`). |

#### Хто читає {#who-reads-it}

| Код | Що робить |
| ---- | ------------ |
| `TokenManager.mjs:36-40` (`getUserToken`) | Розшифровує токен для кожного виклику API GitHub: `services/web/modules/github-sync/app/src/GitHubSyncHandler.mjs` (наприклад, `:27`) і `services/web/modules/github-sync/app/src/GitMerge.mjs:43`. Якщо документа немає або токен не вдається розшифрувати, кидає `InvalidTokenError`, і користувач вважається непов’язаним (`GitHubSyncHandler.mjs:25-37`). |
| `services/web/modules/admin-tools/app/src/AdminUserListManager.mjs:393` | Перевіряє, чи є в користувача документ, для інтеграцій, що показуються в панелі адміністратора. |

#### Індекси {#indexes}

| Назва | Ключі | Параметри | Міграція |
| ---- | ---- | ------- | --------- |
| `_id_` | `_id: 1` | | default |

`autoIndex` у Mongoose вимкнено (`services/web/app/src/infrastructure/Mongoose.mjs:7`), тому `unique: true` зі схеми на `userId` нічого не створює. `tools/migrations/20190912145011_create_githubSyncUserCredentials_indexes.mjs` (`user_id` з upstream) має лише тег `saas` і в CE не запускається.

#### Примітки {#notes}

* Зміна `GITHUB_TOKEN_CIPHER_PASSWORD` робить збережені токени нечитабельними. Такі користувачі вважаються непов’язаними, доки не пов’яжуть обліковий запис повторно.
* Видалений користувач зберігає документ, доки не спливе його термін.
