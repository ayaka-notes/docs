`rooms` зберігає по одному документу на чат-кімнату проєкту: чат проєкту або одну гілку коментарів рецензування. Записує в неї лише сервіс chat, у `services/chat/app/js/Features/Threads/ThreadManager.js`. Схеми Mongoose немає. Повідомлення кімнати зберігаються в колекції [messages](/uk/dev/data-model/messages-collection).

#### Поля {#fields}

| Поле | Тип | Значення | Джерело |
| ----- | ---- | ------- | ------ |
| `_id` | ObjectId | Ідентифікатор кімнати. Сюди вказує `messages.room_id`. | `ThreadManager.js:57-61` |
| `project_id` | ObjectId | Проєкт, якому належить кімната. | `ThreadManager.js:43-54` |
| `thread_id` | ObjectId | Лише в гілках коментарів: ідентифікатор коментаря, такий самий, як `id` і `op.t` коментаря в `docs.ranges.comments` (див. [docs](/uk/dev/data-model/docs-collection)). У кімнаті чату проєкту відсутній. | `ThreadManager.js:38-55`, `services/docstore/app/js/RangeManager.js:54-57` |
| `resolved` | Object | Встановлюється, коли гілку розв’язано, і видаляється, коли її знову відкрито. Гілка без цього поля відкрита. | `ThreadManager.js:94-123` |
| `resolved.user_id` | String | Ідентифікатор користувача, який розв’язав гілку. Зберігається як рядок, а не ObjectId: тіло запиту лише перевіряється на коректний ідентифікатор, але не перетворюється. | `ThreadManager.js:103`, `services/chat/app/js/Features/Messages/MessageHttpSchemas.js:70` |
| `resolved.ts` | Date | Коли гілку було розв’язано. | `ThreadManager.js:104` |

#### Примітки {#notes}

* Проєкт має щонайбільше одну кімнату без `thread_id`: це чат проєкту. Сервіс chat знаходить її за `thread_id: { $exists: false }` (`ThreadManager.js:38-45`).
* Стан «розв’язано» коментаря зберігається лише тут. Docstore видаляє `op.resolved` перед збереженням діапазонів (`services/docstore/app/js/RangeManager.js:59-61`).
* Після копіювання проєкту той самий `thread_id` існує у двох проєктах. Завжди виконуйте запит за `project_id` і `thread_id` разом, як це робить сервіс chat.
* Кімнати видаленого проєкту залишаються, доки не спливе термін видаленого проєкту.
