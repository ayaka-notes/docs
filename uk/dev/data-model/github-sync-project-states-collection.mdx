title: Колекція GitHub Sync Project States
icon: code-branch
---

`githubSyncProjectStates` зберігає по одному документу на кожен проєкт, пов’язаний із репозиторієм GitHub: який це репозиторій і де зупинилася остання синхронізація. Колекція належить до вебмодуля `github-sync` (`services/web/modules/github-sync`). Схема міститься в `services/web/modules/github-sync/app/models/githubSyncProjectStates.mjs`, а весь доступ іде через `services/web/modules/github-sync/app/src/SyncStateManager.mjs`.

#### Хто записує {#who-writes-it}

| Код | Що робить |
| ---- | ------------ |
| `SyncStateManager.mjs:9-14` (`createProjectState`) | Створює документ: після імпорту репозиторію як нового проєкту (`services/web/modules/github-sync/app/src/GitHubSyncHandler.mjs:175-181`) або після експорту проєкту в новий репозиторій (`GitHubSyncHandler.mjs:235-241`, лише власник, відмова, якщо проєкт уже пов’язаний). |
| `SyncStateManager.mjs:16-21` (`updateProjectState`) | `$set` змінених полів. `getMergeOverview` встановлює `mergeStatus: 'diverged'`, коли синхронізована гілка більше не базується на `lastSyncCommit`: compare у GitHub відповідає `diverged` або `behind` (`GitHubApiClient.mjs:382-400`), або коміт зник, а користувач може пушити (`GitHubSyncHandler.mjs:123,126-137`). Синхронізація (`services/web/modules/github-sync/app/src/GitMerge.mjs`) у разі успіху пересуває `lastSyncCommit`/`lastSyncVersion` (наприклад, `:143,173,224`), записує конфлікт у `unmergedBranchName`, `unmergedBranchHead` і `conflictVersion` (`:207-213`) та очищає їх, коли конфлікт розв’язано (`:250-257`). |
| `SyncStateManager.mjs:23-25` (`removeProjectState`) | Видаляє документ, коли власник відв’язує проєкт (`GitHubSyncHandler.mjs:83-97`) і коли спливає термін видаленого проєкту (`services/web/modules/github-sync/index.mjs:56-58`). |

#### Хто читає {#who-reads-it}

| Код | Що робить |
| ---- | ------------ |
| `GitHubSyncHandler.mjs:39-60` (`getProjectState`) | Передає редактору `mergeStatus`, `repoFullName` і `unmergedBranchName`. Якщо документа немає, відповідає `need-export`; це значення ніколи не зберігається. |
| `GitHubSyncHandler.mjs:110-143` (`getMergeOverview`) | Порівнює `lastSyncCommit` і `lastSyncVersion` з GitHub та історією проєкту, щоб перелічити нові коміти. |
| `GitHubSyncHandler.mjs:200` (`exportProject`) | Відмовляється експортувати вже пов’язаний проєкт. |
| `GitMerge.mjs:27` (`doGitMergeWithoutLock`) | Завантажує стан на початку синхронізації. |

#### Індекси {#indexes}

| Назва | Ключі | Параметри | Міграція |
| ---- | ---- | ------- | --------- |
| `_id_` | `_id: 1` | | default |

`autoIndex` у Mongoose вимкнено (`services/web/app/src/infrastructure/Mongoose.mjs:7`), тому `unique: true` зі схеми на `projectId` нічого не створює. `tools/migrations/20190912145010_create_githubSyncProjectStates_indexes.mjs` (`project_id` і `owner_id` з upstream) має лише тег `saas` і в CE не запускається.

#### Примітки {#notes}

* Синхронізація виконується під блокуванням проєкту `gitSync` (`GitMerge.mjs:17-24`). GitLab Sync і Gitea Sync беруть те саме блокування, тому для проєкту одночасно триває лише одна синхронізація.
* Видалений проєкт зберігає свій документ, доки не спливе його термін.
* Токен GitHub користувача зберігається в [GitHub Sync User Credentials](/uk/dev/data-model/github-sync-user-credentials-collection).
