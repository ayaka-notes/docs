title: Колекція OAuth Applications

`oauthApplications` зберігає OAuth-клієнти, відомі web. Один документ відповідає одному клієнту. В Ayakaleaf Pro до неї пише лише вебмодуль `git-bridge`: під час запуску web він створює один клієнт з іменем `Overleaf Git Bridge`. Схема: `services/web/app/src/models/OauthApplication.mjs`.

#### Поля {#fields}

| Поле | Тип | Значення | Джерело |
| ----- | ---- | ------- | ------ |
| `_id` | ObjectId | Id документа клієнта. На нього посилаються `oauthAccessTokens.oauthApplication_id` і `oauthAuthorizationCodes.oauthApplication_id`. | `OauthApplication.mjs:5` |
| `id` | String | Id клієнта: 64 випадкові малі літери та цифри. | `OauthApplication.mjs:7`, `services/web/modules/git-bridge/index.mjs:25` |
| `clientSecret` | String | Секрет клієнта, записується як `v1.` і 32 випадкові символи. Його читає лише `getClient`, а `getClient` ніхто не викликає (див. Примітки). | `OauthApplication.mjs:8`, `git-bridge/index.mjs:26` |
| `grants` | Array of String | Типи grant. У клієнта git-bridge: `['password']`. Повертається разом із клієнтом під час перевірки токена (`services/web/modules/oauth2-server/app/src/OAuth2Model.mjs:67-72`). | `OauthApplication.mjs:9`, `git-bridge/index.mjs:27` |
| `name` | String | Ім'я клієнта. Модуль git-bridge і код персональних токенів доступу знаходять клієнта за іменем `Overleaf Git Bridge`. | `OauthApplication.mjs:10`, `git-bridge/index.mjs:15-16,28` |
| `redirectUris` | Array of String | Дозволені URI переспрямування. У клієнта git-bridge: `[]`. | `OauthApplication.mjs:11`, `git-bridge/index.mjs:29` |
| `scopes` | Array of String | Scopes, які може використовувати клієнт. У клієнта git-bridge: `['git_bridge']`. | `OauthApplication.mjs:12`, `git-bridge/index.mjs:30` |
| `pkceEnabled` | Boolean | Лише у схемі: жоден код у цьому репозиторії його не записує, а читає лише невикористовуваний `getClient` (`OAuth2Model.mjs:207`). | `OauthApplication.mjs:13` |

#### Хто записує {#who-writes-it}

| Код | Що робить |
| ---- | ------------ |
| `git-bridge/index.mjs:9-35` (module `git-bridge`) | Якщо `GIT_BRIDGE_ENABLED` дорівнює `true`, під час запуску web створює клієнт `Overleaf Git Bridge`, якщо клієнта з таким іменем ще немає. |

#### Хто читає {#who-reads-it}

| Код | Що робить |
| ---- | ------------ |
| `services/web/modules/oauth2-server/app/src/OAuthPersonalAccessTokenManager.mjs:53-61` (module `oauth2-server`) | Знаходить клієнт `Overleaf Git Bridge` за іменем і зберігає його `_id` у кожному новому персональному токені доступу. Без клієнта токен не створюється. |
| `OAuth2Model.mjs:31-39,67-72` (`getAccessToken`) | Завантажує клієнт токена через `oauthApplication_id` і повертає його `id` та `grants`. |
| `OAuth2Model.mjs:185-209,241,275` (`getClient`, `saveToken`, `saveAuthorizationCode`) | Шукають клієнтів за `id`. У цьому репозиторії ніколи не викликаються, див. Примітки. |

#### Індекси {#indexes}

Лише типовий індекс на `_id`. Унікальний індекс `id_1` створюють лише міграції з тегами `saas` (`20190912145016_create_oauthApplications_indexes.mjs`) і `server-pro` (`20230502180757_server_pro_oauth_indexes.mjs`), які Community Edition не запускає.

#### Примітки {#notes}

* Web використовує `@node-oauth/oauth2-server` лише для перевірки bearer-токенів (`server.authenticate` у `services/web/app/src/Features/Authentication/AuthenticationController.mjs:409-450`), що викликає лише методи моделі `getAccessToken` і `verifyScope`. Жоден маршрут не обслуговує `/oauth/token` або `/oauth/authorize`, тому `getClient`, `saveToken` і `saveAuthorizationCode` ніколи не викликаються.
* Модуль шукає клієнта за іменем, а потім створює його, і в Community Edition немає унікального індексу на `name` або `id`. Тож ніщо не заважає появі другого клієнта з тим самим іменем. Код, якому потрібен клієнт, бере той, що поверне `findOne`.
