---
title: Колекція Dropbox Entities
icon: file-arrow-up
---

`dropboxEntities` зберігає по одному документу на кожен файл, який синхронізація з Dropbox скопіювала між проєктом і Dropbox одного користувача, а також короткочасні tombstone-записи. Колекція належить до синхронізації з Dropbox: third-party-datastore (`services/third-party-datastore/app/js/StateManager.mjs`) записує та читає її, а вебмодуль `dropbox` (`services/web/modules/dropbox/app/src/DropboxHandler.mjs`) очищує її. Схеми Mongoose немає.

#### Поля {#fields}

| Поле | Тип | Значення | Джерело |
| ---- | --- | -------- | ------- |
| `_id` | ObjectId | Встановлюється драйвером під час вставлення. | `StateManager.mjs:46,97` |
| `overleaf.userId` | ObjectId | Користувач, у чиєму Dropbox є файл. Встановлюється в кожному документі. | `StateManager.mjs:48,98` |
| `overleaf.projectId` | ObjectId | Проєкт doc або файлу. Встановлюється, коли відомий; tombstone його не мають. | `StateManager.mjs:49-51` |
| `overleaf.id` | ObjectId | `_id` doc або файлу в `rootFolder` проєкту. Встановлюється, коли відомий. | `StateManager.mjs:52` |
| `overleaf.type` | String | `doc` або `file`. Поточний код записує його, але не читає. | `StateManager.mjs:53`; значення з `services/web/app/src/Features/ThirdPartyDataStore/TpdsUpdateSender.mjs:35,96` і `UpdateMerger.mjs:104,119` |
| `dropbox.id` | String | `id` файлу в метаданих файлу Dropbox. Для tombstone не встановлюється. | `StateManager.mjs:56` |
| `dropbox.pathLower` | String | Шлях до файлу в Dropbox у нижньому регістрі й без кінцевої скісної риски. Оновлюється, коли файл або папку його проєкту переміщено. | `StateManager.mjs:14-16,57,91,99` |
| `dropbox.rev` | String | Ревізія Dropbox під час останньої синхронізації. Наступне завантаження надсилає її, тож файл, змінений у Dropbox, не перезаписується. | `StateManager.mjs:58`, `JobProcessor.mjs:114-122` |
| `dropbox.contentHash` | String | Хеш вмісту Dropbox під час останньої синхронізації. Файл зі списку з тим самим хешем пропускається, бо це наше власне завантаження або його вже застосовано. | `StateManager.mjs:59`, `PullManager.mjs:147-149` |
| `tombstone` | Boolean | `true` позначає шлях, який third-party-datastore сам видалив або перемістив у Dropbox. Коли Dropbox повідомляє про це видалення у відповідь, воно не застосовується до проєкту. | `StateManager.mjs:100`, `PullManager.mjs:189-192` |
| `createdAt` | Date | Лише для tombstone: коли запис створено. Завершений pull видаляє tombstone-записи, створені до його початку. | `StateManager.mjs:101,115-121` |

Tombstone має лише `overleaf.userId`, `dropbox.pathLower`, `tombstone` і `createdAt` (`StateManager.mjs:96-103`).

#### Примітки {#notes}

* Унікальність забезпечується лише видаленням перед кожним вставленням у `recordEntity` (`StateManager.mjs:38-45`). Коментар у `StateManager.mjs:3-11` згадує унікальні індекси; у CE їх немає.
* Запити за користувачем і шляхом (`findEntityByPath`, `findTombstone`, `removeEntities`) використовують індекс лише для `overleaf.userId`.
