`templates` містить один документ на кожен шаблон у галереї шаблонів. Файлів шаблону (zip проєкту та PDF) тут немає: вони зберігаються у filestore в `template/<_id>/v/<version>/`. Колекція належить web-модулю `template-gallery` (`services/web/modules/template-gallery`). Схему задає модель Mongoose `Template` у `services/web/modules/template-gallery/app/src/models/Template.mjs`; логіка міститься в `services/web/modules/template-gallery/app/src/TemplateGalleryManager.mjs` і в сусідньому `TemplateGalleryHelper.mjs`.

#### Хто записує {#who-writes-it}

| Код | Що робить |
| ---- | ------------ |
| `TemplateGalleryManager.mjs:53-97` (`createTemplateFromProject`) | `POST /template/new/:Project_id`. Копіює налаштування проєкту (`TemplateGalleryHelper.mjs:94-134`), завантажує zip і PDF у filestore та зберігає. Якщо назву зайнято, відповідає конфліктом, якщо тільки клієнт не попросив перезапис: тоді оновлює цей шаблон, збільшує його `version` і видаляє файли попередньої версії. |
| `TemplateGalleryManager.mjs:21-47` (`editTemplate`) | `POST /template/:template_id/edit`. Присвоює документу надіслані поля, заново рендерить `description` і `author` та встановлює `lastUpdated`. Форма редагування надсилає змінені поля з `name`, `license`, `category`, `language`, `authorMD` і `descriptionMD` (`services/web/modules/template-gallery/frontend/js/pages/template/util/api.ts:22-29`). |
| `TemplateGalleryHelper.mjs:186-222` (`deleteTemplateAssets`) | `DELETE /template/:template_id/delete` видаляє документ і файли вказаної версії (`TemplateGalleryManager.mjs:49-51`). |

Викликати ці три маршрути можуть лише адміністратори сайту й користувач з `OVERLEAF_TEMPLATES_USER_ID` (`services/web/modules/template-gallery/app/src/Router.mjs:55-62,70-84`, `PermissionsMiddleware.mjs:8-19`).

#### Хто читає {#who-reads-it}

| Код | Що робить |
| ---- | ------------ |
| `TemplateGalleryManager.mjs:158-183` (`getTemplate`) | Знаходить один шаблон за `_id` або `name` для сторінки шаблону й для `GET /api/template` (`services/web/modules/template-gallery/app/src/TemplateGalleryController.mjs:210-232`). Якщо `project_id` вказує на проєкт, якого вже немає, відповідь його пропускає; документ не змінюється. |
| `TemplateGalleryManager.mjs:190-236` (`getCategoryTemplates`) | `GET /api/templates`: одна сторінка категорії з пошуком у `name`, `authorMD` і `descriptionMD`, відсортована за `lastUpdated` або за `name` (без урахування регістру). |
| `TemplateGalleryHelper.mjs:64-80` (`canUserOverrideTemplate`) | Читає `owner`, щоб назвати власника в повідомленні про конфлікт. |

#### Індекси {#indexes}

| Назва | Ключі | Параметри | Міграція |
| ---- | ---- | ------- | --------- |
| `_id_` | `_id: 1` | | типовий |

`autoIndex` у Mongoose вимкнено (`services/web/app/src/infrastructure/Mongoose.mjs:7`). `tools/migrations/20190912145030_create_templates_indexes.mjs` (унікальні `project_id`, `user_id`, `name`) позначена тегами `server-pro` і `saas`, тому не виконується в CE, де виконуються лише міграції `server-ce` (`server-ce/init_scripts/900_run_web_migrations.sh`).

#### Примітки {#notes}

* Upstream вважає `templates` застарілою колекцією й видаляє її на своєму сайті (`tools/migrations/20241002180623_drop_unused_collections.mjs`, тег `saas`). В Ayakaleaf Pro її використовує модуль галереї шаблонів.
* Сортування за назвою використовує порівняння без урахування регістру, і коментар у `TemplateGalleryManager.mjs:186-188` зазначає, що індексу `name` знадобилося б таке саме. У CE індексу `name` немає, тому Mongo сортує в пам'яті.
* Видалення вихідного проєкту або власника не видаляє шаблон.
