У цьому розділі ми розглянемо модель даних Overleaf. Overleaf використовує MongoDB для зберігання даних; єдина база даних має назву `sharelatex` — так називався попередник Overleaf.

Середовище розробки вже запускає Mongo Express поруч із Mongo (див. [setup-develop-tools.md](/uk/dev/environment/setup-develop-tools  "mention")). Відкрийте [http://localhost:8081/](http://localhost:8081/) й увійдіть з `admin:pass`.

Ви також можете відкрити оболонку в контейнері Mongo з каталогу `develop`:

```bash
bin/docker-compose exec mongo mongosh sharelatex
```

#### Як побудовано сторінки {#how-the-pages-are-written}

* Кожна сторінка перелічує поля, які записує код, із їхнім типом, значенням і рядком коду, що це показує: рядком схеми Mongoose або місцем, де поле записується. Для полів, які пише лише міграція, скрипт або один із web-модулів, це зазначено.
* Багато колекцій не мають схеми Mongoose: сервіси пишуть у них через драйвер MongoDB.
* Індекси створюють лише міграції з `tools/migrations/`. CE під час кожного запуску виконує міграції з тегом `server-ce` (`server-ce/init_scripts/900_run_web_migrations.sh`); `autoIndex` у Mongoose вимкнено (`services/web/app/src/infrastructure/Mongoose.mjs:7`). У таблицях індексів перелічено лише те, що зрештою має екземпляр CE.
* Текст docs зберігається в Mongo, а решта вмісту ні. Вміст файлів зберігається як blob-и, а історія як чанки в бакетах history-v1 (локальні теки або S3 / RustFS); відкриті docs містяться в Redis, доки document-updater не скине їх на диск.

У базі даних CE більше колекцій, ніж перелічено тут. Багато з них створюються порожніми міграціями індексів і використовуються лише на overleaf.com. Наприклад, ні CE, ні наші модулі під час звичайної роботи не пишуть у `splittests`, `samlLogs`, `notificationsPreferences`, `onboardingDataCollection` і `userfeatureusages`, тому вони не мають сторінок.
