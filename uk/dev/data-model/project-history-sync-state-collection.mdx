---
title: Колекція Project History Sync State
icon: rotate
---

`projectHistorySyncState` містить один документ на кожен проєкт, який проходив ресинхронізацію: стан поточної або останньої ресинхронізації, під час якої project-history заново будує історію проєкту з того, що зберігають web і docstore. Колекція належить project-history і не має схеми Mongoose; код міститься в класі `SyncState` та його допоміжних функціях у `services/project-history/app/js/SyncManager.js`.

#### Хто записує {#who-writes-it}

| Код | Що робить |
| ---- | ------------ |
| `services/project-history/app/js/SyncManager.js:195-249` | `setResyncState`: upsert стану. Викликається під час запуску ресинхронізації (`SyncManager.js:163`) і поки project-history обробляє оновлення ресинхронізації (`services/project-history/app/js/UpdatesProcessor.js:637`, `784`). |
| `SyncManager.js:257-266` | `_recordStuckClearInSyncState`: враховує скинуту завислу ресинхронізацію. |
| `SyncManager.js:251-255` | `clearResyncState`: видаляє документ на початку жорсткої ресинхронізації (`SyncManager.js:87`), під час `DELETE /project/:project_id` у project-history (`services/project-history/app/js/HttpController.js:1363-1396`) і коли ресинхронізацію лише структури треба почати заново (`SyncManager.js:705-716`). |
| `SyncManager.js:273-289` | `clearResyncStateIfAllAfter`: видаляє завершений стан, уся історія якого новіша за певну дату. Ніщо в `app/js` її не викликає. |
| `SyncManager.js:171-181` | `cloneResyncState`: копіює стан в інший проєкт для `POST /project/:project_id/clone` у project-history (`HttpController.js:57`, `124`), який ніщо в web не викликає. |

Ресинхронізацію запускають `POST /project/:project_id/resync` у project-history (`HttpController.js:950-994`), завдання cron для повторних спроб (`services/project-history/app/js/RetryManager.js:156-179`, `server-ce/config/crontab-history`) і сам project-history, коли вона потрібна для обробки оновлень (`UpdatesProcessor.js:75`, `224`).

#### Хто читає {#who-reads-it}

| Код | Що робить |
| ---- | ------------ |
| `SyncManager.js:187-193` | `getResyncState`: завантажує стан. Використовується, щоб перед запуском нової ресинхронізації вирішити, чи не виконується вже інша (`SyncManager.js:106-149`), щоб пропускати звичайні оновлення під час її виконання (`SyncManager.js:291-300`) і щоб після скидання на диск повідомити про поточну ресинхронізацію (`UpdatesProcessor.js:463-466`). |
| `HttpController.js:533-545` | `GET /project/:project_id/resync-pending`: чи виконується ресинхронізація або чи зависла вона. |
| `HttpController.js:563-585` | `GET /project/:project_id/debug-info`: стан синхронізації разом із записом про збій. |

#### Примітки {#notes}

* Ресинхронізація виконується, поки `resyncProjectStructure` дорівнює `true` або `resyncDocContents` не порожній (`SyncManager.js:565-567`). Через 4 години вона вважається завислою, а після 5 скидань завислою назавжди (`SyncManager.js:43-44`, `569-585`).
* Коли ресинхронізація завершується, project-history також встановлює в проєкті `overleaf.history.lastResyncedAt` (`SyncManager.js:239-248`).
