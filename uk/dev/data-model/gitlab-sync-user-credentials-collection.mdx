---
title: Колекція GitLab Sync User Credentials
icon: user-lock
---

`gitlabSyncUserCredentials` зберігає по одному документу на кожного користувача, який пов’язав обліковий запис GitLab для GitLab Sync. Вона зберігає OAuth-токени користувача в зашифрованому вигляді. Колекція належить до вебмодуля `gitlab-sync` (`services/web/modules/gitlab-sync`). Схема міститься в `services/web/modules/gitlab-sync/app/models/gitlabSyncUserCredentials.mjs`, а весь доступ іде через `services/web/modules/gitlab-sync/app/src/TokenManager.mjs`.

#### Поля {#fields}

| Поле | Тип | Значення | Джерело |
| ----- | ---- | ------- | ------ |
| `_id` | ObjectId | Задається Mongoose, коли upsert вставляє документ. | |
| `userId` | ObjectId | Користувач Overleaf. Обов’язкове. У схемі вказано `unique: true`, але індекс не створюється (див. «Індекси»); upsert за `userId` зберігає один документ на користувача. | `gitlabSyncUserCredentials.mjs:8`, `TokenManager.mjs:88-95` |
| `gitlab` | String | JSON `{ accessToken, refreshToken, expiresAt }`, зашифрований за допомогою `@overleaf/access-token-encryptor`. `expiresAt` задається в мілісекундах від початку епохи або дорівнює `null`; `refreshToken` може бути `null`. Пароль береться з `GITLAB_TOKEN_CIPHER_PASSWORD`; мітка шифру `GITLAB_TOKEN_CIPHER_LABEL`, типово `2026.10-v3`. Обов’язкове. | `gitlabSyncUserCredentials.mjs:9-10`, `TokenManager.mjs:18-31`, `services/web/modules/gitlab-sync/app/src/GitLabApiClient.mjs:209-220` |
| `__v` | Number | Ключ версії Mongoose. Схема його не вимикає. | Типово в Mongoose |

#### Хто записує {#who-writes-it}

| Код | Що робить |
| ---- | ------------ |
| `TokenManager.mjs:88-95` (`saveUserToken`) | Виконує upsert зашифрованих облікових даних користувача. |
| `TokenManager.mjs:99-108` (`linkUserToken`) | Зберігає нові облікові дані з OAuth-колбека (`services/web/modules/gitlab-sync/app/src/GitLabSyncController.mjs:146`). Коли користувач пов’язує обліковий запис повторно, замінений токен доступу відкликається в GitLab у фоні. |
| `TokenManager.mjs:53-78` (`refreshUserToken`) | Коли до `expiresAt` токена доступу лишається менше 5 хвилин (`:13,47-49`), отримує нові токени за токеном оновлення й зберігає їх (`:75`). Працює під блокуванням `gitlabSyncToken` для кожного користувача (`:15,54`), бо GitLab витрачає токен оновлення під час використання. |
| `TokenManager.mjs:111-126` (`removeUserToken`) | Відкликає токен доступу в GitLab (за можливості), потім видаляє документ. Викликається під час відв’язування (`GitLabSyncController.mjs:173`) і коли спливає термін видаленого користувача (`services/web/modules/gitlab-sync/index.mjs:56-58`). |

#### Хто читає {#who-reads-it}

| Код | Що робить |
| ---- | ------------ |
| `TokenManager.mjs:41-45,81-85` (`getUserCredentials`, `getUserToken`) | Розшифровує облікові дані для кожного виклику API GitLab, спершу оновлюючи їх, якщо термін токена скоро спливає: `services/web/modules/gitlab-sync/app/src/GitLabSyncHandler.mjs` (наприклад, `:27`) і `services/web/modules/gitlab-sync/app/src/GitMerge.mjs:52`. Якщо документа немає або облікові дані не вдається розшифрувати чи оновити, кидає `InvalidTokenError`, і користувач вважається непов’язаним (`GitLabSyncHandler.mjs:25-37`). |
| `services/web/modules/admin-tools/app/src/AdminUserListManager.mjs:394` | Перевіряє, чи є в користувача документ, для інтеграцій, що показуються в панелі адміністратора. |

#### Індекси {#indexes}

| Назва | Ключі | Параметри | Міграція |
| ---- | ---- | ------- | --------- |
| `_id_` | `_id: 1` | | default |

`autoIndex` у Mongoose вимкнено (`services/web/app/src/infrastructure/Mongoose.mjs:7`), тому `unique: true` зі схеми на `userId` нічого не створює. Жодна міграція не створює індекси для цієї колекції.

#### Примітки {#notes}

* Зміна `GITLAB_TOKEN_CIPHER_PASSWORD` робить збережені облікові дані нечитабельними. Такі користувачі вважаються непов’язаними, доки не пов’яжуть обліковий запис повторно.
* Видалений користувач зберігає документ, доки не спливе його термін.
