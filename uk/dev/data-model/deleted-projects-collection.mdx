---
title: Колекція Deleted Projects
icon: trash-can
---

`deletedProjects` зберігає проєкт після видалення: один документ на кожен видалений проєкт, з копією всього документа проєкту та відомостями про те, хто його видалив. Web записує колекцію в `services/web/app/src/Features/Project/ProjectDeleter.mjs`; схема: `services/web/app/src/models/DeletedProject.mjs`. Коли минає строк до остаточного видалення, процедура завершення строку знищує дані проєкту й очищує `project`, але запис із `deleterData` залишається.

Проєкту в кошику тут немає: переміщення в кошик лише додає користувача до `trashed` проєкту, див. [Колекція Projects](/uk/dev/data-model/projects-collection).

#### Хто записує {#who-writes-it}

| Код | Що робить |
| ---- | ------------ |
| `ProjectDeleter.mjs:189-293` (`deleteProject`) | Скидає проєкт на диск, архівує його docs із Mongo, прибирає його з тегів, робить upsert запису й видаляє документ `projects`. |
| `ProjectDeleter.mjs:295-342` (`undeleteProject`) | Знову вставляє проєкт під назвою `<name> (Restored)` (унікальною для власника) і без архівації, потім видаляє запис. Завершується помилкою `project_too_old_to_restore`, коли `project` дорівнює `null`. Викликається з панелі адміністратора: відновлення одного проєкту (`AdminProjectManager.mjs:497-515`) або відновлення видаленого користувача разом із проєктами, видаленими разом з обліковим записом (`services/web/modules/admin-tools/app/src/AdminUserManager.mjs:678-689`). |
| `ProjectDeleter.mjs:344-416` (`expireDeletedProject`) | Знищує docs, історію, чат і журнал аудиту проєкту, викликає хук `projectExpired`, потім встановлює `project` і `deleterData.deleterIpAddress` в `null`. Якщо проєкт знову існує, видаляє лише застарілий запис. |
| `ProjectDeleter.mjs:97-146` (`expireDeletedProjectsAfterDuration`) | Завершує строк пакета записів, старших за затримку. Маршрут `POST /internal/expire-deleted-projects-after-duration` (`services/web/app/src/router.mjs:842-846`), який cron Community Edition викликає щогодини о 20-й хвилині, коли `ENABLE_CRON_RESOURCE_DELETION` дорівнює `true` (`server-ce/cron/delete-projects.sh:10-23`, `server-ce/config/crontab-deletion:3`). Один проєкт: `POST /internal/project/:projectId/expire-deleted-project` (`router.mjs:852-856`) або Purge у панелі адміністратора (`AdminProjectManager.mjs:517-529`). |

#### Примітки {#notes}

* Модулі, які слухають `projectExpired`, видаляють власні дані проєкту: `git-bridge` (`services/web/modules/git-bridge/index.mjs:37`), `github-sync` (`services/web/modules/github-sync/index.mjs:56`), `gitlab-sync` (`services/web/modules/gitlab-sync/index.mjs:46`), `gitea-sync` (`services/web/modules/gitea-sync/index.mjs:46`) і `dropbox` (`services/web/modules/dropbox/index.mjs:54`).
* Запис зі строком, що минув, ніколи не видаляється: `deleterData` залишається назавжди, очищуються лише `project` та IP-адреса.
* Mongoose також надає `deleterData` власний `_id`, який ніхто не читає.
