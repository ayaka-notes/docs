---
title: Колекція Docs
icon: file-lines
---

`docs` зберігає вміст редагованих текстових файлів проєкту (Overleaf називає їх docs), наприклад `main.tex` або `sample.bib`. Один документ на кожен doc: його рядки, коментарі й відстежувані зміни, два лічильники та стан видалення. Назви файлу та його місця в дереві тут немає, вони зберігаються в `projects.rootFolder` (див. [Колекція Projects](/uk/dev/data-model/projects-collection)). Двійкових файлів тут теж немає.

Окрім міграцій і скриптів обслуговування, у цю колекцію пише лише docstore, у `services/docstore/app/js/MongoManager.js`. Моделі Mongoose немає; web і document-updater звертаються до колекції через HTTP API docstore (`services/docstore/app.js:31-70`). У стовпці «Джерело» назви файлів без шляху містяться в `services/docstore/app/js/`.

| `ranges` | Object | Коментарі та відстежувані зміни, див. нижче. Відсутній, поки doc заархівовано. | `DocManager.js:317-319`, `RangeManager.js:36-65` |

#### Ranges {#ranges}

`ranges` містить два масиви. document-updater будує їх за допомогою `libraries/ranges-tracker/index.cjs`; docstore перед збереженням перетворює id на ObjectId, а `ts` на Date (`RangeManager.js:41-63`). Doc без коментарів і відстежуваних змін має `ranges: {}` або не має `ranges`.

| Поле | Тип | Значення | Джерело |
| ----- | ---- | ------- | ------ |
| `ranges.comments` | Array of Object | Прокоментовані фрагменти тексту. | `libraries/ranges-tracker/index.cjs:217-236` |
| `ranges.comments.id` | ObjectId | Id коментаря. Він дорівнює `op.t`, id гілки коментаря в колекції `rooms`; docstore забезпечує їхній збіг. | `RangeManager.js:54-57` |
| `ranges.comments.op.c` | String | Прокоментований текст у doc (не повідомлення коментаря). | `index.cjs:226-230` |
| `ranges.comments.op.p` | Number | Зміщення в символах початку `op.c` у doc. | `index.cjs:226-230` |
| `ranges.comments.op.t` | ObjectId | Id гілки, див. `id`. | `index.cjs:226-230`, `RangeManager.js:57` |
| `ranges.comments.metadata` | Object | `user_id` і `ts` коментаря. | `index.cjs:232`, `RangeManager.js:62` |
| `ranges.changes` | Array of Object | Відстежувані зміни, відсортовані за позицією. | `index.cjs:640-660` |
| `ranges.changes.id` | ObjectId | Id зміни. | `index.cjs:643-647`, `RangeManager.js:51` |
| `ranges.changes.op.i` / `op.d` | String | Вставлений або видалений текст. Одне з двох. | `index.cjs:640-660` |
| `ranges.changes.op.p` | Number | Зміщення зміни в символах. | `index.cjs:640-660` |
| `ranges.changes.metadata.user_id` | ObjectId or String | Автор. Зміни анонімних редакторів зберігають рядок `anonymous-user`. | `RangeManager.js:45-46`, `DocManager.js:192` |
| `ranges.changes.metadata.ts` | Date | Коли було зроблено зміну. | `RangeManager.js:42-43` |

Тексту коментаря та відповідей на нього немає в `docs`: він зберігається в колекції `messages`, у room, у якої `thread_id` дорівнює id коментаря. Чи розв'язано коментар, зберігається в цій room, а не тут; docstore відкидає прапорець `resolved`, якщо його передали (`RangeManager.js:59-61`). Див. [Колекція Rooms](/uk/dev/data-model/rooms-collection) і [Колекція Messages](/uk/dev/data-model/messages-collection).

#### Хто записує {#who-writes-it}

| Код | Що робить |
| ---- | ------------ |
| `DocManager.js:223-338` (`POST /project/:project_id/doc/:doc_id`) | Створює або оновлює doc: `lines`, `ranges` і `version`. Web викликає його під час створення doc і коли document-updater скидає відкритий doc на диск (`services/web/app/src/Features/Project/ProjectEntityUpdateHandler.mjs:174`). |
| `DocManager.js:346-366` (`PATCH /project/:project_id/doc/:doc_id`) | Позначає doc як видалений за допомогою `deleted`, `deletedAt` і `name`. |
| `DocArchiveManager.js:29-88` | Архівує doc: копіює `lines`, `ranges` і `rev` у сховище й встановлює `inS3`. Виконується для всього проєкту під час його деактивації та для окремого doc під час видалення, якщо `ARCHIVE_ON_SOFT_DELETE=true` (`DocManager.js:355-363`). |
| `DocArchiveManager.js:150-174` | Повертає заархівований doc у Mongo під час читання (`DocManager.js:40-41`). |
| `MongoManager.js:272-274` | Видаляє всі docs проєкту, коли проєкт знищують. |

#### Примітки {#notes}

* Поки doc відкритий, його найновіший текст міститься в document-updater (Redis), а не тут. Mongo оновлюється лише тоді, коли document-updater скидає дані на диск (`services/document-updater/app/js/PersistenceManager.js:128-160`). Код, що читає docs усього проєкту, має спершу викликати `flushProjectToMongo`, як це робить `ProjectDuplicator`.
* Видалені docs залишаються в цій колекції з `deleted: true`, доки проєкт не знищать. docstore повертає не більше `MAX_DELETED_DOCS` (типово 2000) з них, новіші першими (`MongoManager.js:29-44`, `services/docstore/config/settings.defaults.cjs:40`). Панель історії їх не використовує; вона читає history-v1.
* Лічильники `rev` і `version` не пов'язані з версіями історії проєкту в history-v1.
