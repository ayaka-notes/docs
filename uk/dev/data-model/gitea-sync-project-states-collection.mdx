---
title: Колекція Gitea Sync Project States
icon: code-pull-request
---

`giteaSyncProjectStates` зберігає по одному документу на кожен проєкт, пов’язаний із репозиторієм Gitea: який це репозиторій і де зупинилася остання синхронізація. Колекція належить до вебмодуля `gitea-sync` (`services/web/modules/gitea-sync`). Схема міститься в `services/web/modules/gitea-sync/app/models/giteaSyncProjectStates.mjs`, а весь доступ іде через `services/web/modules/gitea-sync/app/src/SyncStateManager.mjs`. Поля такі самі, як у [GitHub Sync Project States](/uk/dev/data-model/github-sync-project-states-collection).

#### Хто записує {#who-writes-it}

| Код | Що робить |
| ---- | ------------ |
| `SyncStateManager.mjs:9-14` (`createProjectState`) | Створює документ: після імпорту репозиторію як нового проєкту (`services/web/modules/gitea-sync/app/src/GiteaSyncHandler.mjs:175-181`) або після експорту проєкту в новий репозиторій (`GiteaSyncHandler.mjs:233-239`, лише власник, відмова, якщо проєкт уже пов’язаний). |
| `SyncStateManager.mjs:16-21` (`updateProjectState`) | `$set` змінених полів. `getMergeOverview` встановлює `mergeStatus: 'diverged'`, коли `lastSyncCommit` більше не є предком синхронізованої гілки (`services/web/modules/gitea-sync/app/src/GiteaApiClient.mjs:431`) або коміт зник, а користувач може пушити (`GiteaSyncHandler.mjs:123,126-137`). Синхронізація (`services/web/modules/gitea-sync/app/src/GitMerge.mjs`) у разі успіху пересуває `lastSyncCommit`/`lastSyncVersion` (наприклад, `:152,189,231`), записує конфлікт у `unmergedBranchName`, `unmergedBranchHead` і `conflictVersion` (`:214-220`) та очищає їх, коли конфлікт розв’язано (`:257-264`). |
| `SyncStateManager.mjs:23-25` (`removeProjectState`) | Видаляє документ, коли власник відв’язує проєкт (`GiteaSyncHandler.mjs:83-97`) і коли спливає термін видаленого проєкту (`services/web/modules/gitea-sync/index.mjs:46-48`). |

#### Хто читає {#who-reads-it}

| Код | Що робить |
| ---- | ------------ |
| `GiteaSyncHandler.mjs:39-60` (`getProjectState`) | Передає редактору `mergeStatus`, `repoFullName` і `unmergedBranchName`. Якщо документа немає, відповідає `need-export`; це значення ніколи не зберігається. |
| `GiteaSyncHandler.mjs:110-143` (`getMergeOverview`) | Порівнює `lastSyncCommit` і `lastSyncVersion` з Gitea та історією проєкту, щоб перелічити нові коміти. |
| `GiteaSyncHandler.mjs:200` (`exportProject`) | Відмовляється експортувати вже пов’язаний проєкт. |
| `GitMerge.mjs:36` (`doGitMergeWithoutLock`) | Завантажує стан на початку синхронізації. |

#### Індекси {#indexes}

| Назва | Ключі | Параметри | Міграція |
| ---- | ---- | ------- | --------- |
| `_id_` | `_id: 1` | | default |

`autoIndex` у Mongoose вимкнено (`services/web/app/src/infrastructure/Mongoose.mjs:7`), тому `unique: true` зі схеми на `projectId` нічого не створює. Жодна міграція не створює індекси для цієї колекції.

#### Примітки {#notes}

* API Gitea не вміє, як GitHub, створювати коміти поза гілкою. Синхронізація комітить просто в синхронізовану гілку, якщо може просунути її вперед, а інакше в тимчасову гілку, яку потім зливають через pull request (`GitMerge.mjs:16-21`).
* Синхронізація виконується під блокуванням проєкту `gitSync`, спільним із GitHub Sync і GitLab Sync (`GitMerge.mjs:25-32`).
* Видалений проєкт зберігає свій документ, доки не спливе його термін.
* Токен Gitea користувача зберігається в [Gitea Sync User Credentials](/uk/dev/data-model/gitea-sync-user-credentials-collection).
