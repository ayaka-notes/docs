---
title: Колекція Dropbox Projects
icon: folder-open
---

`dropboxProjects` зіставляє проєкт із його папкою в Dropbox одного користувача. Проєкт, до якого мають доступ кілька користувачів Dropbox, має по одному документу на користувача. Колекція належить до синхронізації з Dropbox: third-party-datastore (`services/third-party-datastore/app/js/StateManager.mjs`) записує її, а вебмодуль `dropbox` (`services/web/modules/dropbox/app/src/DropboxHandler.mjs`) читає та очищує її. Схеми Mongoose немає.

#### Поля {#fields}

| Поле | Тип | Значення | Джерело |
| ---- | --- | -------- | ------- |
| `_id` | ObjectId | Встановлюється драйвером під час вставлення. | `StateManager.mjs:144` |
| `userId` | ObjectId | Користувач Overleaf, у чиєму Dropbox є папка. | `StateManager.mjs:145` |
| `projectId` | ObjectId | Проєкт, що синхронізується в папку. | `StateManager.mjs:146` |
| `dropboxId` | String | `id` папки в метаданих папки Dropbox. | `StateManager.mjs:147`, `JobProcessor.mjs:82-87`, `PullManager.mjs:138` |
| `pathLower` | String | Шлях до папки в Dropbox у нижньому регістрі й без кінцевої скісної риски. Папки проєктів розташовані на верхньому рівні, по одній на проєкт, наприклад `/thesis (1)`, коли Dropbox пронумерував її поруч із `Thesis` іншого проєкту. | `StateManager.mjs:14-16,148`, `PullManager.mjs:112-117` |

#### Примітки {#notes}

* Унікальність забезпечується лише видаленням перед кожним вставленням у `setProjectFolder` (`StateManager.mjs:140-149`). Коментар у `StateManager.mjs:3-11` згадує унікальні індекси; у CE їх немає.
* Коли зіставлення проєкту видалено, його папка залишається в Dropbox. Редагування там тоді читається як новий проєкт, так само як для папки, створеної в Dropbox (`DropboxHandler.mjs:148-149`).
* Видалений проєкт зберігає зіставлення до закінчення терміну, бо його ще можна відновити (`index.mjs:52-53`).
* Курсора Dropbox `list_folder` користувача тут немає. Він міститься в `users.dropbox.cursor` (`StateManager.mjs:177-184`).
