---
title: Колекція Project History Failures
icon: triangle-exclamation
---

`projectHistoryFailures` зберігає по одному документу на проєкт, оновлення історії якого project-history не зміг обробити або для якого він запустив ресинхронізацію. Документ знову видаляється, щойно обробка проходить успішно. project-history записує її в `services/project-history/app/js/ErrorRecorder.js`; її тип описано в `services/project-history/app/js/mongo-types.ts:3-24`. У web теж є схема Mongoose для неї (`services/web/app/src/models/ProjectHistoryFailure.mjs:5-19`), але жоден код web цю модель не використовує.

#### Хто записує {#who-writes-it}

| Код | Що робить |
| ---- | ------------ |
| `services/project-history/app/js/ErrorRecorder.js:34-66` | `record`: upsert помилки, `attempts` +1, запис додається до `history`. Викликається, коли обробка оновлень проєкту завершується збоєм (`UpdatesProcessor.js:91`, `169`, `242`, `293`, `345`), і коли ресинхронізацію не вдається запустити (`SyncManager.js:75`, `96`). |
| `ErrorRecorder.js:86-102` | `recordSyncStart`: upsert, `resyncStartedAt`, `resyncAttempts` +1, запис додається до `history` під час кожного запуску ресинхронізації (`SyncManager.js:104`). |
| `ErrorRecorder.js:68-70` | `clearError`: видаляє документ після успішного flush (`UpdatesProcessor.js:101`, `194`, `259`, `355`), під час project-history `DELETE /project/:project_id` (`services/project-history/app/js/HttpController.js:1386`) і за некоректного ідентифікатора проєкту під час повторної спроби (`services/project-history/app/js/RetryManager.js:161`). |
| `ErrorRecorder.js:72-82` | `setForceDebug`: upsert `forceDebug` (`HttpController.js:1016-1035`, маршрут у `services/project-history/app/js/Router.js:82`). |
| `ErrorRecorder.js:109-119` | `cloneFailure`: копіює документ в інший проєкт, для project-history `POST /project/:project_id/clone` (`HttpController.js:135`), який ніщо у web не викликає. |

Soft-завдання знову обробляє чергу; hard-завдання ресинхронізує проєкт, причому як hard-ресинхронізацію, коли `resyncAttempts` не менше 1 і помилка не є запущеною ресинхронізацією (`RetryManager.js:30-31`, `35-56`, `106-111`). |

#### Примітки {#notes}

* Документ залишається, доки flush проєкту не пройде успішно або проєкт не буде видалено (`clearError` вище), тож кожен документ позначає проєкт, останній flush або ресинхронізація якого ще не вдалися.
* Рядки помилок, що починаються з `OError:`, повертаються як `Error:` (`ErrorRecorder.js:18-26`); збережене значення не змінюється.
