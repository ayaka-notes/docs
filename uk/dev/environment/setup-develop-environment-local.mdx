## Передумови {#prerequisites}

Overleaf — типовий проєкт з відкритим кодом із мікросервісною архітектурою, усі служби якого працюють у Docker.&#x20;

* Вихідний код офіційної Community Edition доступний на [GitHub Overleaf Official](https://github.com/overleaf/overleaf/tree).&#x20;
* Вихідний код Overleaf-CEP доступний на [GitHub Yu-i-i/Overleaf](https://github.com/yu-i-i/overleaf-cep).
* Ayakaleaf Pro доступний на [GitHub ayaka-notes/ayakaleaf-pro](https://github.com/ayaka-notes/ayakaleaf-pro).

Для налаштування середовища розробки Overleaf вам знадобиться потужний сервер; рекомендовано конфігурацію щонайменше з 8 ядрами та 16 ГБ оперативної пам'яті, оскільки одночасно потрібно запускати понад 20 контейнерів.

<Info>

Оскільки сервери з 8 і більше ядрами CPU зазвичай дорогі, наполегливо рекомендуємо використовувати для розробки свій локальний комп'ютер.

</Info>

Водночас ми вважаємо, що як розробник ви вже знайомі з [установленням Docker](https://docs.docker.com/engine/install/ubuntu/). Наполегливо радимо використовувати для розробки свіжу та стабільну Ubuntu LTS (наприклад, Ubuntu 24.04 у 2025–2026 роках) і найновішу версію Docker, оскільки це зменшує ймовірність несподіваних помилок.

Отже, вам знадобиться:

* [x] Потужний сервер/настільний комп'ютер для розробки
* [x] Свіжа та стабільна Ubuntu LTS (наприклад, Ubuntu 24.04)
* [x] Середовище Docker і Git

## Інструкція з налаштування {#configuration-tutorial}

Тут ми на прикладі Ayakaleaf Pro показуємо, як налаштувати середовище розробки Overleaf. Усі наведені нижче команди виконуються в каталозі `develop`, якщо не зазначено інше.

<Steps>
<Step title="Отримайте вихідний код">
Насамперед клонуймо репозиторій:

```bash title="bash"
git clone https://github.com/ayaka-notes/ayakaleaf-pro.git
cd ayakaleaf-pro/develop
```
</Step>

<Step title="Синхронізація `yarn.lock`">
Репозиторій використовує Yarn 4 (`packageManager` у кореневому `package.json`), і його `yarn.lock` може розходитися з файлами `package.json`. Синхронізуйте його після першого клонування та після будь-якої зміни `package.json`:

```bash title="bash"
bin/sync
```

`bin/sync` виконує `yarn install --mode=update-lockfile` у контейнері `node:24.18.1`, тож Node.js на хості не потрібен. Не комітьте змінений `yarn.lock`.
</Step>

<Step title="Зберіть образ для розробки">
Зберіть сервіси:

```bash title="bash"
bin/build
```

<Info>

Якщо Docker вичерпує оперативну пам'ять під час паралельного збирання служб, створіть у цьому каталозі файл `.env`, що містить `COMPOSE_PARALLEL_LIMIT=1`.

</Info>
</Step>

<Step title="Застосування перекладів">
Модулі Ayakaleaf Pro зберігають свої переклади в `services/web/locales/locales_patches/`, яких немає в закомічених файлах локалей. Застосуйте їх один раз перед першим запуском, інакше сторінки цих модулів показуватимуть замість тексту ключі на кшталт `about_to_permanently_delete_accounts`:

```bash title="bash"
bin/i18n
```

Потрібен `jq` на хості. Запустіть його знову після додавання перекладу або зміни гілки, див. [Оновлення перекладів i18n](/uk/dev/environment/update-i18n-translations).
</Step>

<Step title="Запустіть усі мікросервіси">
Потім запустіть служби:

```bash title="bash"
bin/up
```

Коли служби запрацюють, відкрийте [http://localhost/launchpad](http://localhost/launchpad), щоб створити перший обліковий запис адміністратора. Додайте порт, якщо ви змінили `OVERLEAF_PORT` (див. нижче).

<Info>

LDAP увімкнено за замовчуванням (`LDAP_ENABLED=true` у `dev.rc`). Тоді launchpad показує форму адміністратора LDAP: вона запитує лише email, а потім цей адміністратор входить через LDAP, наприклад як `professor` / `professor` (`professor@planetexpress.com`). Тестових користувачів перелічено в `develop/authentication/README.md`. Задайте `LDAP_ENABLED=false` і `SAML_ENABLED=false`, щоб натомість створити локального адміністратора з паролем.

</Info>
</Step>
</Steps>

<Info>

`develop/dev.env` уже задає `ADMIN_PRIVILEGE_AVAILABLE=true`, тож адміністратори можуть відкрити панель адміністратора без додаткового налаштування.

</Info>

### Конфігурація (`dev.rc`) {#configuration-dev-rc}

`develop/dev.rc` поруч із `dev.env` містить перемикачі середовища розробки, як `overleaf.rc` в Overleaf Toolkit. Змініть значення й знову запустіть `bin/dev`, щоб застосувати його; вимкнена функція також зупиняє свої контейнери.

| Змінна | За замовчуванням | Що робить |
| --- | --- | --- |
| `OVERLEAF_PORT` | `80` | Порт сайту на хості. |
| `LDAP_ENABLED` | `true` | Вхід через LDAP з тестовими користувачами. |
| `SAML_ENABLED` | `true` | Вхід через SAML з тестовими користувачами. |
| `MAILPIT_ENABLED` | `true` | Перехоплює в Mailpit кожен лист від `web`. Також вмикає підтвердження email (`EMAIL_CONFIRMATION_DISABLED=false`). |
| `S3_ENABLED` | `true` | Зберігає файли історії та шаблонів у RustFS (S3) замість локальних томів. |
| `HOPPSCOTCH_ENABLED` | `true` | Hoppscotch із проксі до мережі Docker, див. [Налаштування інструментів розробки](/uk/dev/environment/setup-develop-tools). |
| `HOPPSCOTCH_PORT` | `9170` | Порт Hoppscotch на хості. |
| `GRAFANA_ENABLED` | `true` | Grafana за шляхом `/grafana/` сайту, зі станом, метриками й логами кожного сервісу, див. [Налаштування інструментів розробки](/uk/dev/environment/setup-develop-tools). |

Кожна функція зберігає свій `docker-compose.yml` та інші файли в окремій теці: `authentication/ldap`, `authentication/saml`, `mail`, `s3`, `hoppscotch` і `grafana`. Функція, якій потрібне налаштування `web` без змінної середовища, монтує файл у `/etc/overleaf/settings.d/`, а `develop/settings.dev-env.cjs` об'єднує їх усі. Усі скрипти `bin/*` працюють через `bin/docker-compose`, який додає файли увімкнених функцій. Викликайте `bin/docker-compose` замість `docker compose`, коли вам самим потрібна команда compose.

<Warning>

Локальні томи й RustFS — окремі сховища: у проєкту, створеного з `S3_ENABLED=true`, після перемикання на `false` немає історії та двійкових файлів, і навпаки. Щоб скопіювати до RustFS файли середовища, яке працювало до появи `S3_ENABLED`, виконайте розділ «Moving existing data into RustFS» у [develop/README.md](https://github.com/ayaka-notes/ayakaleaf-pro/blob/server-pro/develop/README.md).

</Warning>

### Порти {#ports}

Сайт, консоль RustFS і Hoppscotch слухають `127.0.0.1` хоста; на віддаленій машині спершу перенаправте їхні порти, наприклад `ssh -L 9001:localhost:9001 <host>`. Сайт використовує `OVERLEAF_PORT` із `dev.rc`, тож додайте порт до адрес нижче, якщо ви його змінили.

| Сторінка | Адреса | Вхід |
| --- | --- | --- |
| Сайт | [http://localhost](http://localhost) | Облікові записи сайту або тестові користувачі |
| Поштова скринька (Mailpit) | [http://localhost/mailpit/](http://localhost/mailpit/) | Немає |
| Grafana | [http://localhost/grafana/](http://localhost/grafana/) | Немає, анонімні користувачі є адміністраторами |
| Mongo Express | [http://localhost/mongo-express/](http://localhost/mongo-express/) | Немає |
| RedisInsight | [http://localhost/redis-insight/](http://localhost/redis-insight/) | Немає |
| Консоль S3 (RustFS) | [http://localhost:9001/rustfs/console/](http://localhost:9001/rustfs/console/) | `rustfsadmin` / `rustfsadmin` |
| Hoppscotch | [http://localhost:9170](http://localhost:9170) (`HOPPSCOTCH_PORT`) | Немає |

Mailpit, Grafana, Mongo Express і RedisInsight віддаються сайтом за власними шляхами через webpack-dev-server, тому їм не потрібні власні порти. Після входу меню **Dev tools** на панелі навігації сайту посилається на них; сторінку, функцію якої вимкнено в `dev.rc`, не показано. [Налаштування інструментів розробки](/uk/dev/environment/setup-develop-tools) описує, що робить кожен із них.

API S3 (порт 9000) і SMTP (порт 1025) доступні лише всередині мережі Docker. Mongo (27017), Redis (6379), Mongo Express (8081), RedisInsight (5540) і git-bridge (8000) публікуються лише на `127.0.0.1` хоста.

### TeX Live {#tex-live}

Компіляцію в пісочниці ввімкнено за замовчуванням: `develop/dev.env` задає `SANDBOXED_COMPILES=true` та образи `ghcr.io/ayaka-notes/texlive-full:2026.1` і `ghcr.io/ayaka-notes/texlive-full:2025.1`. clsi не завантажує образи сам, тож завантажте їх один раз:

```bash
docker pull ghcr.io/ayaka-notes/texlive-full:2026.1
docker pull ghcr.io/ayaka-notes/texlive-full:2025.1
```

Подробиці див. у розділі [Налаштування ізольованої компіляції](/uk/dev/environment/setup-sandbox-compiles).

<Warning>

Проєкт, створений, коли `SANDBOXED_COMPILES` було вимкнено, не має образу TeX Live. Він і далі компілюється образом за замовчуванням, але перехід між кодом і PDF завершується помилкою «That didn't work. Recompile and try again.» Призначте таким проєктам один раз образ із `TEX_LIVE_DOCKER_IMAGE`; без `--commit` скрипт лише показує, що змінив би:

```bash
bin/docker-compose exec web sh -c 'cd /overleaf/services/web && node scripts/backfill_project_image_name.mjs --commit'
```

</Warning>

`dev.env` також вмикає конвертацію Pandoc з `PANDOC_IMAGE=overleaf-pandoc:local`. Зберіть цей образ один раз із кореня репозиторію:

```bash
docker build -t overleaf-pandoc:local develop/pandoc
```

Щоб компілювати на хості macOS, може знадобитися перевизначити шлях до сокета Docker, створивши в каталозі `develop` файл `.env` із вмістом `DOCKER_SOCKET_PATH=/var/run/docker.sock.raw`

### Розробка {#development}

Щоб не виконувати `bin/build && bin/up` після кожної зміни коду, можна запустити Overleaf Community Edition у _режимі розробки_, у якому служби автоматично оновлюються при змінах коду.

Для цього скористайтеся вбудованим скриптом `bin/dev`:

```text
bin/dev
```

Це запустить усі служби за допомогою `node --watch`, який автоматично відстежує код і за потреби перезапускає служби. Запустіть його знову після зміни `dev.rc`.

Для підвищення продуктивності можна запустити в режимі розробки лише частину служб, передавши скрипту `bin/dev` їхній список, розділений пробілами:

```text
bin/dev [service1] [service2] ... [serviceN]
```

<Info>

Запуск служби `web` у _режимі розробки_ оновлюватиме службу `web` лише при зміні коду бекенду. Щоб автоматично оновлювався й код фронтенду, обов'язково також запустіть у _режимі розробки_ службу `webpack`.

</Info>

Якщо служби не вказано, у режимі розробки буде запущено всі служби.

Після додавання перекладу або зміни гілки виконайте `bin/i18n`, див. [Оновлення перекладів i18n](/uk/dev/environment/update-i18n-translations).

### Налагодження {#debugging}

У _режимі розробки_ більшість сервісів відкривають порт налагодження, до якого можна під'єднати налагоджувач, наприклад інспектор у Chrome Dev Tools або налагоджувач, вбудований в IDE. У таблиці нижче наведено порт, відкритий на `127.0.0.1` **хост-машини** для кожного сервісу:

| Служба             | Порт |
| ------------------ | ---- |
| `web`                   | 9229 |
| `clsi`                  | 9230 |
| `chat`                  | 9231 |
| `docstore`              | 9233 |
| `document-updater`      | 9234 |
| `filestore`             | 9235 |
| `notifications`         | 9236 |
| `real-time`             | 9237 |
| `history-v1`            | 9239 |
| `project-history`       | 9240 |
| `linked-url-proxy`      | 9241 |
| `third-party-datastore` | 9242 |

Щоб під'єднатися до служби за допомогою _віддаленого налагодження_ Chrome, перейдіть на chrome://inspect/ і переконайтеся, що позначено _Discover network targets_. Далі натисніть _Configure..._ і додайте запис `localhost:[service port]` для кожної служби, до якої хочете під'єднати налагоджувач.

Після додавання запису служба з'явиться як _Remote Target_, яку можна інспектувати та налагоджувати.

### Журналювання {#logging}

Скрипт `bin/logs` стежить за логами й форматує їх за допомогою `bunyan`. Йому також потрібен `ggrep` — так називається GNU grep у разі встановлення через Homebrew у macOS; в Ubuntu команди `ggrep` немає.

```bash
sudo npm install -g bunyan
# Or sudo apt install node-bunyan 
```

Або можна виконати безпосередньо:

```text
bin/docker-compose logs -f [service name]
```

Використовуйте `bin/docker-compose` замість `docker compose`, щоб знаходилися й сервіси функцій із `dev.rc` (`mailpit`, `rustfs`, `ldap`, `saml`, `hoppscotch` і `grafana` з Prometheus, Loki та експортерами).

За `GRAFANA_ENABLED=true` логи кожного контейнера також є в Grafana, де їх можна фільтрувати за сервісом, рівнем і текстом, див. [Налаштування інструментів розробки](/uk/dev/environment/setup-develop-tools#grafana).
