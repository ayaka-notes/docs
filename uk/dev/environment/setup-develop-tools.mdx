## Рекомендовані інструменти розробки {#develop-tools-recommended}

Ці необов'язкові сервіси не потрібні для роботи Overleaf, але дуже допомагають під час розробки, налагодження та вивчення даних. Усі вони входять до середовища розробки, тож до `docker-compose.yml` нічого додавати не потрібно. Після входу на сайт меню **Dev tools** на його панелі навігації посилається на інструменти, які сайт віддає за власними шляхами.

| Інструмент | Адреса | Де визначено |
| --- | --- | --- |
| **Grafana**, стан, метрики й логи кожного сервісу | [http://localhost/grafana/](http://localhost/grafana/) | `develop/grafana/docker-compose.yml`, увімкнено за `GRAFANA_ENABLED=true` у `develop/dev.rc` (за замовчуванням) |
| **Mailpit**, поштова скринька для кожного листа, який надсилає сайт | [http://localhost/mailpit/](http://localhost/mailpit/) | `develop/mail/docker-compose.yml`, увімкнено за `MAILPIT_ENABLED=true` (за замовчуванням) |
| **Mongo Express**, інтерфейс для MongoDB | [http://localhost/mongo-express/](http://localhost/mongo-express/) | `develop/docker-compose.yml`, завжди увімкнено |
| **RedisInsight**, інтерфейс для даних Redis | [http://localhost/redis-insight/](http://localhost/redis-insight/) | `develop/docker-compose.yml`, завжди увімкнено |
| **Hoppscotch**, браузерний API-клієнт, схожий на Postman | [http://localhost:9170](http://localhost:9170/) (`HOPPSCOTCH_PORT`) | `develop/hoppscotch/docker-compose.yml`, увімкнено за `HOPPSCOTCH_ENABLED=true` (за замовчуванням) |

<Warning>

Жоден із цих інструментів не має входу: анонімні користувачі Grafana є її адміністраторами, а Mongo Express може змінити будь-який документ. Сайт, Hoppscotch, Mongo Express (8081) і RedisInsight (5540) слухають лише `127.0.0.1` хоста, тож інші хости не можуть до них звернутися.

</Warning>

### Grafana {#grafana}

Grafana віддається сайтом за шляхом `/grafana/` через webpack-dev-server, тому їй не потрібен власний порт. Її тека **Overleaf Develop** містить такі дашборди:

| Дашборд | Що показує |
| --- | --- |
| All services (головна) | Стан кожного сервісу, індикатори хоста, навантаження й логи. Клік на сервісі відкриває його дашборд |
| Server | CPU, навантаження, пам'ять, диск і мережа хоста, а також компіляції clsi |
| Errors | Логи помилок, відповіді 5xx і 4xx, найчастіші повідомлення про помилки та збійні маршрути |
| Data flow | Шлях редагування: document-updater і Redis, project-history, history-v1, Mongo, об'єктне сховище |
| Containers | Стан кожного контейнера, CPU, пам'ять, мережа й диск, включно з компіляціями в пісочниці |
| По одному на сервіс | Сервіси Node.js, git-bridge (JVM), mongo і redis |

Prometheus збирає `/metrics` сервісів, `mongodb-exporter`, `redis-exporter`, `cadvisor` і `node-exporter`; Alloy надсилає логи кожного контейнера проєкту до Loki, звідки їх читають фільтри **Log search**, **Service** і **Log level** дашбордів. Їхні дані зберігаються лише в контейнерах, тож перестворення контейнерів їх очищає. cAdvisor працює в привілейованому режимі й лише читає `/`, `/sys`, дані Docker і сокет containerd хоста; node-exporter читає `/` хоста.

Дашборди генеруються: замість редагування JSON-файлів змініть `develop/grafana/make-dashboards` і запустіть його.

### Mailpit {#mailpit}

За `MAILPIT_ENABLED=true` `web` надсилає кожен лист до Mailpit замість справжнього поштового сервера, а підтвердження email увімкнено (`EMAIL_CONFIRMATION_DISABLED=false`). Посилання активації, запрошення до проєктів, скидання пароля й коди підтвердження можна відкривати прямо з поштової скриньки.

### Налаштування Hoppscotch {#setup-hoppscotch}

#### Проксіювання API-запитів {#proxy-api-request}

Hoppscotch надсилає запити з браузера, який не може звернутися до сервісів за їхніми іменами в Docker. Його проксі, Proxyscotch, працює в мережі Docker і доступний за шляхом `/proxy` адреси Hoppscotch. Відкрийте [http://localhost:9170](http://localhost:9170/), перейдіть до Settings → Interceptor, виберіть **Proxy** і задайте Proxy URL `http://localhost:9170/proxy`. Налаштування зберігається в браузері.

#### Імпорт API сервісів {#import-the-service-apis}

У `develop/hoppscotch/openapi/` є файл OpenAPI для внутрішнього API кожного сервісу. У Hoppscotch відкрийте Collections → Import → Import from File і виберіть усі файли одразу. Кожен файл стає колекцією, запити якої йдуть на Docker-адресу сервісу. Ті самі файли показано в розділі [API сервісів](/uk/dev/service-api/overview).

#### Проблеми з CSRF {#csrf-problems}

<Warning>

Якщо ви використовуєте Postman або інші інструменти налагодження для створення **POST**-запиту, ви можете виявити, що вхід **заборонено**, а причиною є помилка 403. Це тому, що Overleaf захищений перевіркою **CSRF**.

</Warning>

Щоб розв'язати це під час розробки Overleaf, потрібно налаштувати CSRF-токен. Нижче наведено докладну інструкцію.

<Steps>
<Step title="Додайте Pre-Request">
Додайте такий код до Pre-Request

<Frame>
  <img src="/images/dev/image-10.png" alt="" />
</Frame>

Скрипт виглядає так:

```js wrap
pm.sendRequest("http://web:3000/dev/csrf", function (err, res) {
    if (err) {
        console.log(err);
        return;
    }

    // 1) Save CSRF token (/dev/csrf)
    const token = res.text().trim();
    pw.env.set("csrftoken", token);
    console.log("csrftoken =", token);

    const setCookieHeader = (res.headers || []).find(h => h.key?.toLowerCase() === "set-cookie")?.value;
    console.log("set-cookie =", setCookieHeader);

    if (!setCookieHeader) return;

    const cookiePair = setCookieHeader.split(";")[0].trim(); // overleaf.sid=...
    pw.env.set("cookie_header", cookiePair);
    console.log("cookie_header =", cookiePair);
});
```
</Step>

<Step title="Додайте заголовки запиту">
Потрібно додати такі заголовки:

| Назва заголовка | Значення заголовка  |
| ------------ | ------------------- |
| Content-Type | `application/json`  |
| X-Csrf-Token | `<<csrftoken>>`     |
| Cookie       | `<<cookie_header>>` |

<Frame>

</Step>

```json5
{
  "_csrf": "<<csrftoken>>",

  "password": "xxxxxx"
}
```

Ось відповідь у разі введення неправильного імені користувача або пароля.
