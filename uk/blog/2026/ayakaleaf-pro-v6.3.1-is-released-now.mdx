З великою гордістю оголошуємо про випуск Overleaf Pro 6.3.1 — найпотужнішого та найфункціональнішого онлайн-редактора LaTeX у спільноті. Патч-випуск зазвичай означає кілька дрібних виправлень. Цей іде набагато далі: крім десятків виправлень помилок, він приносить п'ять нових функцій і поєднує ваші проєкти з місцями, де ви вже працюєте, — від Dropbox і GitLab до ШІ-агента у вашому терміналі.

### Зміни

* Синхронізація з Dropbox (рання попередня версія): підтримуйте кожен проєкт синхронізованим із вашим власним Dropbox в обох напрямках.
* Синхронізація з GitLab (рання попередня версія): двостороння синхронізація з GitLab.com або вашим власним екземпляром GitLab.
* MCP-сервер: дозвольте Claude Code, Codex, Cursor, VS Code чи Gemini CLI працювати з проєктом безпосередньо.
* GitHub Enterprise: спрямуйте GitHub Sync на ваш власний екземпляр GitHub Enterprise.
* Розпізнавання рукописних символів: намалюйте символ і отримайте команду LaTeX.
* `OVERLEAF_DISABLE_LOCAL_LOGIN`: приховайте вхід за електронною поштою та паролем, щоб користувачі входили лише через SSO.
* Виправлення помилок, знайдених нашою системою E2E-тестування та в межах Internal Horizon Issue Investigation.
* Патчі upstream Overleaf 6.3.1.

<Info>

Синхронізація з Dropbox і синхронізація з GitLab постачаються в 6.3.1 як **ранні попередні версії** для поетапного (gray) тестування й будуть офіційно випущені у v6.4.0. До того їхні конфігурація та поведінка ще можуть змінитися. Обидві функції за замовчуванням вимкнено. Будь ласка, повідомляйте про будь-які проблеми на [GitHub](https://github.com/ayaka-notes/ayakaleaf-pro/issues).

</Info>

#### Функція 01: синхронізація з Dropbox (попередня версія)

Деякі люди взагалі не хочуть думати про Git. Їм просто потрібно, щоб їхня дисертація була папкою на ноутбуці, і синхронізація з Dropbox дає їм саме це. Кожен користувач прив'язує власний обліковий запис Dropbox, і проєкти, якими він володіє, а також проєкти, до яких йому надано спільний доступ, з'являються в `Apps/<your app name>/`. Відредагуйте файл в Overleaf — зміна з'явиться в Dropbox. Відредагуйте файл локально у своєму улюбленому редакторі, збережіть його — і зміна повернеться в Overleaf через підписаний вебхук.

Для адміністраторів: має бути ввімкнено Git bridge. Створіть застосунок у Dropbox App Console, потім задайте `DROPBOX_ENABLED`, `DROPBOX_APP_KEY`, `DROPBOX_APP_SECRET`, `DROPBOX_APP_NAME` і `DROPBOX_TOKEN_CIPHER_PASSWORD`. `DROPBOX_SYNC_PROXY_URL` необов'язковий і потрібен для серверів, які не можуть звертатися до Dropbox безпосередньо. Потім один раз, перш ніж користувачі прив'яжуть свої облікові записи, створіть індекси MongoDB, потрібні для синхронізації з Dropbox.

Повні інструкції з налаштування дивіться в розділі [Синхронізація з Dropbox](/uk/on-premises/configuration/overleaf-toolkit/dropbox-synchronisation  "mention").

#### Функція 02: синхронізація з GitLab (попередня версія)

GitHub Sync — одна з найулюбленіших функцій починаючи з 6.2, але багато університетів і компаній зберігають свій код у GitLab. Синхронізація з GitLab працює так само: прив'яжіть свій обліковий запис, імпортуйте репозиторій із меню нового проєкту або експортуйте проєкт у новий проєкт GitLab. Потім виконуйте push і pull прямо з редактора та зливайте зміни через merge requests.

Вона працює з GitLab.com і з власними екземплярами GitLab версії 15.10 або новішої. Задайте `GITLAB_SYNC_ENABLED`, `GITLAB_SYNC_CLIENT_ID`, `GITLAB_SYNC_CLIENT_SECRET` і `GITLAB_TOKEN_CIPHER_PASSWORD`, а для власного екземпляра — також `GITLAB_SYNC_URL`.

Повні інструкції з налаштування дивіться в розділі [Синхронізація з GitLab](/uk/on-premises/configuration/overleaf-toolkit/gitlab-synchronisation  "mention").

#### Функція 03: MCP-сервер

У 6.3 ми вбудували ШІ-асистента в редактор. У 6.3.1 ми відчиняємо двері у зворотний бік: тепер кожен проєкт має власний MCP-сервер, тож ШІ-агент, яким ви вже користуєтеся, може працювати з вашою статтею безпосередньо. Попросіть Claude Code виправити друкарські помилки у вступі, попросіть Codex скомпілювати проєкт і виправити помилки LaTeX або попросіть Cursor відповісти на відкриті коментарі рецензентів. Агент читає й редагує файли в реальному часі, тож ви та ваші співавтори бачите, як його правки з'являються в редакторі під час набору. Він також може компілювати проєкт, читати журнал, отримувати PDF, рахувати слова й показувати список версій.

Ендпоінт — `/project/<project_id>/mcp`. Для автентифікації використовуйте той самий Git-токен, що й для `git clone`. Доступ визначається налаштуваннями спільного доступу до проєкту, тож агент читача може читати, але не редагувати, а кожен інструмент має обмеження частоти запитів. Більше нічого налаштовувати не потрібно: MCP-сервер вмикається разом із Git bridge.

Як під'єднати кожен ШІ-клієнт, дивіться в розділі [MCP-сервер](/uk/on-premises/configuration/overleaf-toolkit/mcp-server  "mention").

#### Функція 04: GitHub Enterprise

GitHub Sync більше не обмежений github.com. Укажіть у `GITHUB_SYNC_URL` адресу вашого GitHub Enterprise Server або GitHub Enterprise Cloud із розміщенням даних (`GHE.com`), і ендпоінти REST і GraphQL буде визначено на її основі. Якщо ваш екземпляр влаштовано незвично, перевизначте їх за допомогою `GITHUB_SYNC_API_URL` і `GITHUB_SYNC_GRAPHQL_URL`. Якщо не задавати ці змінні, усе залишиться на github.com.

Подробиці дивіться в розділі [Синхронізація з GitHub](/uk/on-premises/configuration/overleaf-toolkit/github-synchronisation#github-enterprise  "mention").

#### Функція 05: розпізнавання рукописних символів

Ви знаєте, як виглядає символ, але не знаєте, як він називається. Це `\varsigma` чи `\zeta`? `\models` чи `\vDash`? Перемкніть палітру символів у режим малювання, намалюйте символ мишею або трекпадом, і палітра запропонує відповідні команди LaTeX.

Розпізнавання повністю виконується в браузері за допомогою моделі, навченої ayaka-notes, тож ніщо з намальованого вами не залишає вашого комп'ютера. Перемикач малювання приховано в браузерах без `OffscreenCanvas` (наприклад, Safari 15).

#### Виправлення помилок

Цей випуск також містить довгий список виправлень. Багато з них знайшла наша нова система E2E-тестування, яка тепер щодня запускає набори тестів для кожного модуля, а також Internal Horizon Issue Investigation: щоразу, виправляючи помилку, ми перевіряємо всю кодову базу на подібні помилки, перш ніж закрити її.

* **Автентифікація**: локальні облікові записи можуть задавати й змінювати пароль в екземплярах із SSO, а користувачі OIDC більше не можуть самостійно змінювати свою електронну адресу. Вхід через LDAP, SAML і OIDC більше не завершується помилкою, коли атрибут імені має кілька значень, а вихід із SAML/OIDC знову працює.
* **Призупинені користувачі**: призупинення користувача тепер завершує його сеанси й закриває відкриті ним редактори, а його Git-токени та завантаження через MCP відхиляються.
* **GitHub Sync**: експортувати проєкт може лише власник, правки, зроблені під час pull, залишаються в очікуванні, порожні файли синхронізуються, а ручні злиття перевіряються на GitHub.
* **Zotero / Mendeley**: коли ваші облікові дані перестають працювати, ви отримуєте повідомлення з пропозицією повторно прив'язати обліковий запис, а після імпорту джерела переіндексовуються.
* **Зовнішні сервіси**: запити до Zotero, Mendeley, GitHub, GitLab і вебпошуку отримують тайм-аут підключення 3 с замість 1 с, тож у повільніших мережах вони більше не завершуються помилкою.
* **Відстеження змін**: дані рецензування містять незавантажені документи та незбережені зміни.
* **Панель адміністратора**: відновлення видалених проєктів, зміна власників і редагування користувачів працюють коректно, а збій надсилання листа більше не порушує створення чи видалення облікового запису.
* **Галерея шаблонів**: недійсне сортування повертає 400 замість 500, а під час публікації проєкту без основного файлу пропонується його вказати.

Повний список дивіться в [примітках до випуску 6.3.1](/uk/on-premises/release-notes/release-notes-6.x.x#ayakaleaf-pro-6.3.1  "mention").

#### Оновлення

* З 6.3.0: міграція не потрібна. Завантажте новий образ і перезапустіть.
* З 6.2.x або ранішої версії, якщо використовуються Zotero чи Mendeley: спершу виконайте [міграцію Zotero / Mendeley](/uk/on-premises/release-notes/release-notes-6.x.x#ayakaleaf-pro-6.3.0  "mention") з 6.3.0.
* Синхронізацію з Dropbox і синхронізацію з GitLab за замовчуванням вимкнено. Для синхронізації з GitLab потрібні лише нові змінні середовища. Для синхронізації з Dropbox також потрібно один раз, перш ніж користувачі прив'яжуть свої облікові записи, створити її індекси MongoDB: дивіться [Створення індексів бази даних](/uk/on-premises/configuration/overleaf-toolkit/dropbox-synchronisation#create-the-database-indexes  "mention").
