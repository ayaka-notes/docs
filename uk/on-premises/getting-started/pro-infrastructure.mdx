#### Сервіси

Інфраструктура Overleaf Pro складається з чотирьох основних сервісів: `sharelatex`, `git-bridge` (необов'язковий), `mongo` і `redis`. Сервіс `sharelatex`, у якому працює основний застосунок Server Pro, залежить від сервісів `mongo` і `redis`, що забезпечують базу даних і функції кешування та роботи в реальному часі, а також від `git-bridge`, що відповідає за [інтеграцію з Git](/uk/on-premises/configuration/overleaf-toolkit/git-integration) (необов'язково). Єдиний порт, опублікований на хост-машині, — це порт 80, який використовує контейнер `sharelatex`.

Server Pro також додатково підтримує [S3-сумісне сховище](/uk/on-premises/configuration/overleaf-toolkit/s3) для файлів проєктів і повної історії проєктів, а також може проксіювати доступ до основного [сайту документації Overleafarrow-up-right](https://www.overleaf.com/learn). Докладніше див. наш посібник [Додавання довідки LaTeX для користувачів](/uk/on-premises/configuration/overleaf-toolkit/adding-latex-user-help).

<Info>

За потреби MongoDB і Redis можна винести назовні, вказавши зовнішні сервіси за допомогою змінних середовища. Докладніше див. [Налаштування Overleaf](/uk/on-premises/configuration), якщо ви використовуєте Docker Compose, і [Налаштування Toolkit](/uk/on-premises/configuration/overleaf-toolkit/toolkit-settings), якщо ви використовуєте Overleaf Toolkit.

</Info>

#### Компіляція

Для [ізольованої компіляції (Sandboxed Compiles)](/uk/on-premises/configuration/overleaf-toolkit/sandboxed-compiles) контейнер `sharelatex` керує створенням нових контейнерів для компіляції проєктів; він робить це через сокет Docker на хост-машині. Докладніше про редактор і наскрізний процес компіляції та кешування можна прочитати [тут](/uk/on-premises/getting-started/microservices#editor-and-compile-process).

#### Мережа

Зв'язок між контейнерами забезпечується внутрішнім DNS-розпізнаванням Docker через окрему мережу типу bridge; брандмауери не ввімкнено. За замовчуванням наведені вище сервіси використовують свої стандартні порти, але їх можна змінити за допомогою змінних середовища. Контейнер `sharelatex` використовує порт 80 для зовнішнього вебдоступу (обслуговується Nginx), контейнер `mongo` — порт 27017, а `redis` — порт 6379.

Клієнти, які використовують наше кероване рішення [Overleaf Toolkitarrow-up-right](https://github.com/overleaf/toolkit), можуть за бажанням [увімкнути TLS-проксі](/uk/on-premises/configuration/overleaf-toolkit/tls-proxy) для термінації HTTPS-з'єднань за допомогою Nginx через змінну середовища. Також можна використовувати ваш наявний TLS-проксі.

<Info>

Діаграму, що пояснює проходження запитів, можна переглянути [тут](/uk/on-premises/configuration/overleaf-toolkit/tls-proxy).

</Info>

#### Підсумок

* Поза мережею Docker доступний лише порт 80, прив'язаний до Nginx. <strong>Примітка:</strong> у контейнері `sharelatex` працює багато [сервісівarrow-up-right](https://github.com/overleaf/overleaf/tree/main/services), які взаємодіють між собою через HTTP. Проте ці порти **не** доступні ззовні мережі Docker.
* Усередині мережі Docker сервіси Overleaf, MongoDB, Redis і Git Bridge можуть вільно взаємодіяти між собою.
* Усередині контейнерів [ізольованої компіляції](/uk/on-premises/configuration/overleaf-toolkit/sandboxed-compiles) мережа недоступна.
