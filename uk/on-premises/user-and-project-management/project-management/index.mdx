### Перегляд журналу аудиту проєкту

Адміністратори можуть переглядати **журнал аудиту (Audit Log)** для кожного проєкту. Цей журнал показує такі події, як зміна режиму надання доступу за посиланням між приватним і на основі токена, надсилання та прийняття запрошень, а також приєднання користувача до проєкту за допомогою токена. Адміністратори можуть переглядати ці журнали для кожного проєкту окремо через **Your Instance** -> **Admin** -> **Manage Users**, а потім:

* Знайдіть користувача
* Натисніть вкладку **Projects**
* Виберіть проєкт
* Натисніть значок (i)
* Натисніть вкладку **Audit Log**

Якщо проєкт надано в спільний доступ іменованому співавтору (за його адресою електронної пошти), то після приєднання одержувача він відображатиметься у вікні Share разом зі своїми правами та буде видимий власнику проєкту. Ця інформація також показується адміністраторам під час перегляду вкладки Project Info для проєкту через панель адміністратора.

### Відновлення видалених документів

1. Увійдіть, використовуючи облікові дані адміністратора
2. Натисніть **Admin** і виберіть **Manage Users**
3. У полі пошуку введіть адресу електронної пошти користувача, для якого потрібно відновити документ
4. Натисніть його адресу електронної пошти у списку результатів, щоб відкрити сторінку з інформацією про користувача
5. Натисніть вкладку **Projects** і скористайтеся полем пошуку, щоб знайти проєкт
6. Натисніть значок інформації поруч із назвою проєкту, щоб відкрити **Project Info**
7. Натисніть вкладку **Deleted Docs**
8. Натисніть кнопку **Undelete** поруч із видаленим документом, щоб повернути його до проєкту користувача.

Відновлений файл матиме такий формат: `FILENAME-TIMESTAMP.EXTENSION`. Наприклад, відновлену версію `main.tex` буде відновлено в корені проєкту з назвою файлу `main-2024-02-23-130441542.tex`.

### Передавання права власності на проєкт

Панель адміністратора в Server Pro має окрему сторінку для кожного проєкту. Перейти до неї можна, знайшовши користувача на "/admin/user", потім перейшовши на його вкладку **Projects**, знайшовши проєкт у списку та натиснувши значок інформації; або безпосередньо перейшовши на сторінку за відомим project-id [<strong>https://your-instance-url/admin/project/</strong>](https://your-instance-url/admin/project/). На сторінці інформації про проєкт є кнопка **Transfer Ownership**, яка відкриває вікно, де можна вказати будь-якого користувача як нового власника. Новий власник не обов'язково має бути наявним співавтором проєкту.

<Info>

Зверніть увагу, що під час передавання права власності попереднього власника буде додано як співавтора з правами читання та запису до проєкту.

</Info>

### Оновлення тайм-ауту компіляції проєкту

Типовий тайм-аут компіляції проєктів наразі становить 180 секунд. Це значення можна змінити, і для цього потрібно виконати два кроки.

Спочатку відредагуйте файл **config/variables.env**, додайте змінну середовища `COMPILE_TIMEOUT` і встановіть її значення на потрібний тайм-аут у секундах. Наприклад, `COMPILE_TIMEOUT=300` для 5 хвилин.

<Danger>

Немає сенсу збільшувати тайм-аут понад 10 хвилин. Якщо ви це зробите, то, найімовірніше, зіткнетеся з тайм-аутом в іншому компоненті застосунку.

</Danger>

Після внесення цієї зміни потрібно повторно створити контейнер **sharelatex**, виконавши команду `bin/up -d`.

Встановлення цієї змінної середовища оновить значення тайм-ауту лише для нових користувачів; воно **не** буде застосоване заднім числом до наявних користувачів, оскільки значення задається під час першого створення користувача.

Щоб змінити тайм-аут для наявних користувачів, потрібно змінити кожен запис користувача в базі даних. Радимо бути дуже обережними під час цього та рекомендуємо створити узгоджену резервну копію перед внесенням будь-яких змін.

Інформацію про створення резервних копій можна знайти [тут](/uk/on-premises/maintenance/data-and-backups).

Щоб оновити значення тайм-ауту компіляції для всіх наявних користувачів, виконайте таку команду оболонки на хості Docker:

```bash wrap
echo 'db.users.updateMany({}, {$set: {"features.compileTimeout": <value>}})' | docker exec -i mongo mongosh --quiet localhost/sharelatex
```

У наведеному вище запиті замініть `<value>` на потрібне значення тайм-ауту в секундах.

Після завершення команди ви побачите підтвердження з кількістю змінених записів. Потім можна ввести exit і натиснути клавішу Enter, щоб повернутися до оболонки хоста.

### Відстеження доступу до проєктів

Побачити, хто і коли завантажував проєкт, можна за допомогою такої команди:

```bash wrap
docker exec sharelatex bash -c 'grep "join project request" /var/log/overleaf/web.log'
```

Вона виведе `timestamp`, `user_id` і `project_id`.
