Кожен проєкт має власний MCP-сервер, тож ШІ-клієнт на вашому комп'ютері може читати й редагувати проєкт, компілювати його та відповідати на коментарі. Клієнт входить за допомогою токена автентифікації Git.

<Info>

Якщо ви не бачите картки **MCP server**, скеруйте адміністратора на сторінку [MCP-сервер](/uk/on-premises/configuration/overleaf-toolkit/integrations/mcp-server).

</Info>

## Нове у v6.3.3 {#new-in-v6-3-3}

Починаючи з v6.3.3, клієнт може працювати й з історією проєкту: переглядати зміни, порівнювати дві версії, читати файл у попередньому стані, зберігати й видаляти версії та відновлювати файл або весь проєкт. Він може переглядати відстежувані зміни та приймати чи відхиляти їх, а також робити свої правки відстежуваними змінами, якщо ви про це попросите. Він може коментувати фрагмент тексту, редагувати й видаляти повідомлення коментарів, читати й надсилати повідомлення в чаті проєкту, переміщувати й перейменовувати файли та теки, створювати теки й змінювати мову перевірки правопису. Хто що може робити, залежить від вашої ролі в проєкті, як і в редакторі, бо клієнт працює з вашим токеном: див. [Хто що може робити](#who-may-do-what).

MCP-сервер з'явився у v6.3.1. У v6.3.1 і v6.3.2 ті самі 17 інструментів; у v6.3.3 їх 33.

| Інструменти | v6.3.1 і v6.3.2 | v6.3.3 |
| ----- | ----------------- | ------ |
| `get_clone_info`, `get_settings`, `list_files`, `delete_file`, `compile`, `get_compile_log`, `get_output_file_link`, `word_count`, `reply_to_comment`, `resolve_comment`, `reopen_comment` | Так | Так, без змін |
| `read_file` | Останній вміст | Також файл у стані на `version` |
| `edit_file`, `write_file` | Дотримуються налаштування відстеження змін проєкту | Також `trackChanges`, щоб зробити правку відстежуваною зміною |
| `update_settings` | Компілятор, образ TeX Live та основний документ | Також мова перевірки правопису |
| `list_versions` | Версія, коментар і дата | Також `id`, який приймає `delete_version`, і хто зберіг версію |
| `list_comments` | Повідомлення без id | Також `id` кожного повідомлення, який приймають `edit_comment_message` і `delete_comment_message` |
| `list_changes`, `diff`, `create_version`, `delete_version`, `restore_file`, `restore_project`, `list_tracked_changes`, `accept_tracked_changes`, `reject_tracked_changes`, `add_comment`, `edit_comment_message`, `delete_comment_message`, `list_chat_messages`, `send_chat_message`, `move_file`, `create_folder` | Ні | Так |

<Step title="Створіть токен">
Натисніть **Go to settings**. Налаштування облікового запису відкриються в новій вкладці. У розділі **Git integration** натисніть **Generate token** або **Add another token**, якщо токен у вас уже є. Натисніть **Copy** і збережіть токен у надійному місці, бо його показують лише один раз. Потім натисніть **Close**.

<Frame caption="Ваш новий токен">
  <img src="/images/on-premises/mcp-server-token.png" alt="Діалог Git authentication token з кнопкою Copy" />
</Frame>

Підійде й токен, який ви вже використовуєте для [інтеграції з Git](/uk/on-premises/user-guide/users/git-integration), а один токен можна використовувати для всіх проєктів.
</Step>

<Step title="Додайте сервер до клієнта">
Поверніться в діалог, відкрийте вкладку свого клієнта та натисніть **Copy** поруч із конфігурацією.

| Вкладка | Куди вставити | Токен |
| --- | ------------- | --------- |
| **Claude Code** | Виконайте команду в терміналі | Замініть `<token>` у команді |
| **Codex** | `~/.codex/config.toml` | Вкажіть його у змінній середовища `OVERLEAF_TOKEN` |
| **Cursor** | `~/.cursor/mcp.json` | Вкажіть його у змінній середовища `OVERLEAF_TOKEN` |
| **VS Code** | `.vscode/mcp.json` | Замість токена у файлі є запит пароля `overleaf-token` |
| **Gemini CLI** | Виконайте команду в терміналі | Замініть `<token>` у команді |

Адреса належить одному проєкту. Щоб підключити інший проєкт, додайте його під іншою назвою, бо `overleaf` уже зайнято. Наприклад, у Claude Code замініть `overleaf` у команді на `overleaf-lab`.
</Step>
</Steps>

## Перевірка з'єднання {#check-the-connection}

### За допомогою Claude Code {#with-claude-code}

```bash
claude mcp list
```

Сервер відображається як підключений:

```text
overleaf: https://<your-site>/project/<project-id>/mcp (HTTP) - ✔ Connected
```

### За допомогою curl {#with-curl}

Цей спосіб працює з будь-яким клієнтом. Замініть адресу й токен і надішліть запит `initialize` протоколу MCP:

```bash
curl -X POST https://<your-site>/project/<project-id>/mcp \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -H "Accept: application/json, text/event-stream" \
  -d '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2025-06-18","capabilities":{},"clientInfo":{"name":"curl","version":"1.0"}}}'
```

У відповіді зазначено назву сервера, а за нею його інструкції для клієнтів:

```json
{"result":{"protocolVersion":"2025-06-18","capabilities":{"tools":{"listChanged":true}},"serverInfo":{"name":"overleaf","version":"1.0.0"},"instructions":"This server works on one Overleaf project. ..."},"jsonrpc":"2.0","id":1}
```

Щоб побачити інструменти, надішліть `tools/list` тією самою командою. У відповіді 33 інструменти або 31, якщо на вашому сайті вимкнено чат проєкту. До v6.3.3 їх 17.

```bash
  -d '{"jsonrpc":"2.0","id":2,"method":"tools/list","params":{}}'
```

Щоб викликати інструмент, надішліть `tools/call`:

```bash
  -d '{"jsonrpc":"2.0","id":3,"method":"tools/call","params":{"name":"list_files","arguments":{}}}'
```

```json
{"result":{"content":[{"type":"text","text":"[\n  {\n    \"path\": \"main.tex\",\n    \"type\": \"doc\"\n  }\n]"}]},"jsonrpc":"2.0","id":3}
```

У розділі **Git integration** поле **Last used** показує дату для токена, який отримав сервер.

### Якщо з'єднання не встановлюється {#if-it-does-not-connect}

| Що ви бачите | Що це означає |
| ------------ | ------------- |
| Статус `401` або в Claude Code `✘ Failed to connect` з `HTTP 401` | Токен відсутній, неправильний або видалений |
| Статус `404` | Проєкту з таким ID немає |
| Статус `405` | Запит був не `POST` |
| Статус `406` з `Not Acceptable` | Відсутній заголовок `Accept`: клієнт має приймати і `application/json`, і `text/event-stream` |

## Що ви бачите, коли працює клієнт {#what-you-see-when-a-client-works}

Правки з'являються у відкритому редакторі в міру того, як клієнт їх вносить, як правки співавтора, без перезавантаження. Нові файли й теки, переміщення та перейменування з'являються в дереві файлів.

<Frame caption="Рядок, доданий edit_file">
  <img src="/images/on-premises/mcp-server-live-edit.png" alt="Редактор показує рядок, доданий edit_file, без діалогу та без перезавантаження" />
</Frame>

`edit_file` змінює лише текст, який трапляється рівно один раз. Інакше клієнт отримує помилку, наприклад `oldString not found in main.tex, read_file again` або `oldString appears 2 times in main.tex, add context`, і нічого не змінюється.

Починаючи з v6.3.3, `move_file` переміщує або перейменовує файл чи теку, за потреби створюючи теки нового шляху, а `create_folder` створює теку. Якщо файл не знайдено або новий шлях уже існує, клієнт отримує помилку, і нічого не змінюється. `update_settings` також може змінити мову перевірки правопису, наприклад на `de`, або вимкнути перевірку.

Відповіді на коментарі з'являються на панелі рецензування під вашим ім'ям, бо токен ваш. Коментар, розв'язаний через сервер, зникає з панелі, а повторне відкриття повертає його.

<Frame caption="Відповідь, надіслана reply_to_comment">
  <img src="/images/on-premises/mcp-server-comment.png" alt="Коментар на панелі рецензування з відповіддю, надісланою reply_to_comment" />
</Frame>

Починаючи з v6.3.3, `add_comment` коментує фрагмент тексту. Текст має траплятися у файлі рівно один раз; якщо він трапляється кілька разів, клієнт також указує довший фрагмент навколо нього, що трапляється один раз, і коментується лише сам текст. Коментар з'являється на панелі рецензування під вашим ім'ям і лишається прив'язаним до свого тексту, коли файл змінюється. `edit_comment_message` змінює одне з ваших повідомлень. `delete_comment_message` видаляє повідомлення, а видалення першого видаляє весь коментар, як на панелі рецензування.

`compile` компілює проєкт і повертає список вихідних файлів. Потім `get_output_file_link` дає посилання для завантаження PDF або іншого вихідного файлу. Посиланню не потрібен токен, і через 5 хвилин воно перестає працювати.

Повний список інструментів див. у розділі [Tools](/on-premises/configuration/overleaf-toolkit/integrations/mcp-server#tools).

## Відстежувані зміни {#tracked-changes}

Починаючи з v6.3.3, ви можете попросити клієнта вносити правки як відстежувані зміни, наприклад *Rewrite the abstract as a tracked change*. Тоді `edit_file` і `write_file` роблять зміну наявного файлу відстежуваною зміною від вашого імені, навіть якщо відстеження змін у проєкті вимкнено, і ви приймаєте або відхиляєте її на панелі рецензування. Новий файл ніколи не є відстежуваною зміною. Якщо ви не просите, правки дотримуються налаштування відстеження змін проєкту, як і ваші в редакторі: вони відстежуються, коли відстеження ввімкнено для вас або для всіх.

Якщо обліковий запис власника проєкту не має відстеження змін, клієнт отримує `Track changes is off for this project`, і нічого не змінюється.

Щоб перевіряти кожну правку клієнта, увімкніть відстеження змін для себе. Щоб відрізняти його правки від ваших на панелі рецензування, дайте клієнту токен іншого облікового запису, з яким ви ділите проєкт.

`list_tracked_changes` перелічує відстежувані зміни з їхнім файлом, вставленим чи видаленим текстом, автором і часом. `accept_tracked_changes` і `reject_tracked_changes` приймають id змін і працюють як панель рецензування: прийнята зміна лишається в тексті, відхилена вставка видаляється, а відхилене видалення повертається. Відкритий редактор показує результат без перезавантаження. Інструменти вказують клієнту приймати чи відхиляти лише ті зміни, про які ви просите.

## Історія {#history}

Починаючи з v6.3.3, клієнт бачить історію проєкту так само, як її показує панель історії.

| Інструмент | Що робить |
| ---- | ------------ |
| `list_changes` | Перелічує зміни, починаючи з найновіших: хто, коли й які файли змінив, з версіями до і після кожної зміни. Старіші зміни надходять наступними порціями. |
| `diff` | Порівнює дві версії: один файл як unified diff, як `git diff`, або файли, які було додано, видалено, змінено чи перейменовано |
| `read_file` з `version` | Читає файл у стані на певну версію |
| `list_versions` | Перелічує збережені версії з коментарем і тим, хто їх зберіг |
| `create_version` | Зберігає останню або ранішу версію з коментарем, як **Label this version** |
| `delete_version` | Видаляє збережену версію; її зміни лишаються |
| `restore_file` | Відновлює файл у стані на версію, як **Restore this version** |
| `restore_project` | Відновлює весь проєкт у стані на версію, як **Restore project to this version** |

Відновлення саме є новою зміною, тому його можна скасувати так само. Інструменти вказують клієнту відновлювати лише на ваше прохання.

Якщо власник проєкту не має повної історії проєкту, клієнт бачить лише зміни за останні 24 години або останню зміну, якщо всі вони старіші, як на панелі історії. Порівнювати, читати чи відновлювати старіші версії він не може.

## Чат проєкту {#project-chat}

Починаючи з v6.3.3, `list_chat_messages` читає чат проєкту, починаючи з найновіших, по 50 повідомлень за раз. `send_chat_message` надсилає повідомлення від вашого імені, і воно одразу з'являється у відкритому чаті. Якщо на вашому сайті чат проєкту вимкнено, у клієнта немає жодного з цих інструментів.

## Хто що може робити {#who-may-do-what}

Клієнт може робити те, що дозволяє ваша роль у проєкті.

| Що робить клієнт | Власник | Редактор | Рецензент | Читач (іменний співавтор) | Читач (доступ за посиланням) |
| -------------------- | ----: | -----: | -------: | --------------------------: | --------------------: |
| Читати файли й налаштування, компілювати, читати журнал, завантажувати PDF | Так | Так | Так | Так | Так |
| Записувати, редагувати, переміщувати й видаляти файли, створювати теки, змінювати налаштування | Так | Так | Ні | Ні | Ні |
| Переглядати історію, коментарі та відстежувані зміни | Так | Так | Так | Так | Ні |
| Читати й надсилати повідомлення в чаті | Так | Так | Так | Так | Ні |
| Додавати коментарі та відповідати на них | Так | Так | Так | Ні | Ні |
| Розв'язувати, повторно відкривати чи видаляти коментар | Так | Так | Розпочаті ним самим | Ні | Ні |
| Редагувати повідомлення коментаря | Свої | Свої | Свої | Ні | Ні |
| Видаляти повідомлення коментаря | Так | Так | Свої | Ні | Ні |
| Приймати чи відхиляти відстежувані зміни | Так | Так | Ні | Ні | Ні |
| Зберігати версію | Так | Так | Так | Ні | Ні |
| Видаляти збережену версію | Так | Збережені ним самим | Збережені ним самим | Ні | Ні |
| Відновлювати файл або проєкт | Так | Так | Ні | Ні | Ні |

Редактори, які приєдналися за посиланням, вважаються редакторами. Рецензенти не можуть редагувати файли через MCP, навіть як відстежувані зміни.

## Відключення клієнта {#disconnect-a-client}

Видаліть токен: див. [Видалення токена](/uk/on-premises/user-guide/users/git-integration#delete-a-token). Після цього сервер відповідає `401` на цей токен. Якщо ви використовуєте його й для Git, Git теж перестає його приймати.
