Працюйте над проєктом на власному комп'ютері за допомогою Git. Зміни передаються лише тоді, коли ви виконуєте `git pull` або `git push`.

<Info>

Спочатку адміністратор має увімкнути [інтеграцію з Git](/uk/on-premises/configuration/overleaf-toolkit/integrations/git-integration).

</Info>

## Створення токена {#create-a-token}

Git входить за допомогою токена автентифікації Git, а не пароля вашого облікового запису.

<Steps>
<Step title="Відкрийте налаштування облікового запису">
Натисніть **Account**, потім **Account settings**. У розділі **Git integration** натисніть **Generate token**. Коли у вас уже є токен, ця кнопка називається **Add another token**.

<Frame caption="Інтеграція з Git у налаштуваннях облікового запису">
  <img src="/images/on-premises/git-integration-settings.png" alt="Розділ Git integration у налаштуваннях облікового запису з кнопкою Generate token" />
</Frame>
</Step>

<Step title="Скопіюйте токен">
Натисніть **Copy** і збережіть токен у надійному місці. Ви бачите його лише один раз. Потім натисніть **Close**.

<Frame caption="Ваш новий токен">
  <img src="/images/on-premises/git-integration-token.png" alt="Діалогове вікно токена автентифікації Git із кнопкою Copy" />
</Frame>
</Step>

<Step title="Перевірте токен">
Тепер у списку видно початок токена, час його створення та останнього використання. Строк дії токена спливає через рік. Ви можете мати до 10 токенів.

<Frame caption="Ваші токени">
  <img src="/images/on-premises/git-integration-tokens.png" alt="Список токенів з одним токеном" />
</Frame>
</Step>
</Steps>

## Клонування проєкту {#clone-a-project}

<Steps>
<Step title="Відкрийте інтеграцію з Git у редакторі">
Відкрийте проєкт. На лівій панелі натисніть **Integrations**, потім **Git integration**.

<Frame caption="Панель Integrations">
  <img src="/images/on-premises/git-integration-panel.png" alt="Панель Integrations з карткою Git integration" />
</Frame>
</Step>

<Step title="Скопіюйте команду">
Діалогове вікно **Clone with Git** показує команду з адресою вашого сайту та ID проєкту. Натисніть **Copy**. Якщо у вас ще немає токена, **Go to settings** відкриє налаштування облікового запису в новій вкладці.

<Frame caption="Команда клонування">
  <img src="/images/on-premises/git-integration-clone.png" alt="Діалогове вікно Clone with Git з командою git clone" />
</Frame>
</Step>

<Step title="Виконайте її">
Вставте команду в термінал. Коли Git запитає пароль, вставте свій токен.

```text
$ git clone https://git@<your-site>/git/<project-id>
Cloning into '<project-id>'...
Password for 'https://git@<your-site>': <your-token>
```

Тепер тека з назвою, що дорівнює ID проєкту, містить файли проєкту в гілці `main`. Щоб вибрати назву теки, додайте її в кінець команди.
</Step>
</Steps>

Git запитує токен щоразу, коли звертається до сайту. Щоб він запам'ятався, увімкніть credential helper: Git запитає ще раз, а потім збереже токен. Helper `store` зберігає його в незашифрованому вигляді в `~/.git-credentials`.

```bash
git config --global credential.helper store
```

## Отримання змін із редактора {#pull-changes-from-the-editor}

У теці виконайте:

```bash
git pull
```

Git перелічить змінені файли. Зміни, зроблені в редакторі, надходять як коміти з назвою `Update on Overleaf.`.

```text
Updating db007e3..c3e6332
Fast-forward
 main.tex | 2 +-
 1 file changed, 1 insertion(+), 1 deletion(-)
```

## Надсилання змін {#push-your-changes}

Закомітьте зміни, потім надішліть їх:

```bash
git add main.tex
git commit -m "Add a line from Git"
git push
```

Останній рядок виводу показує гілку, яка просунулася:

```text
   53aca61..db007e3  main -> main
```

Зміни з'являються в редакторі, а відкритий редактор оновлюється сам. Нові файли, теки та перейменування з'являються в дереві файлів. В **History** вашу зміну позначено як <strong>You (via Git)</strong>. Повідомлення коміту там не показується.

### Якщо Git відхиляє push {#if-git-refuses-your-push}

Якщо проєкт тим часом змінився, Git відхиляє push:

```text
 ! [rejected]        main -> main (fetch first)
```

Спочатку отримайте ці зміни, потім знову виконайте push:

```bash
git pull --no-rebase --no-edit
git push
```

Звичайний `git pull` може зупинитися з повідомленням `fatal: Need to specify how to reconcile divergent branches.` Параметр `--no-rebase` вище розв'язує це: він об'єднує обидві сторони.

Якщо ті самі рядки змінилися з обох боків, pull зупиняється з повідомленням `CONFLICT (content): Merge conflict in main.tex`. Виправте файл, потім виконайте:

```bash
git add main.tex
git commit -m "Merge the changes from the editor"
git push
```

Сайт не приймає двох речей:

* Інші гілки: `! [remote rejected] feature -> feature (wrong branch)`. Існує лише `main`, тож надсилайте роботу туди.
* Примусовий push: `! [remote rejected] main -> main (forced push prohibited)`. Натомість розмістіть свої зміни поверх поточної `main`.

### Якщо Git повідомляє Authentication failed {#if-git-says-authentication-failed}

```text
remote: Enter your Git authentication token when prompted for a password.
fatal: Authentication failed for 'https://<your-site>/git/<project-id>/'
```

Токен неправильний або видалений, або ви ввели пароль облікового запису. Створіть новий токен, якщо у вас його більше немає: наявний токен не можна переглянути повторно.

## Видалення токена {#delete-a-token}

В **Account settings**, у розділі **Git integration**, натисніть значок видалення поруч із токеном, потім **Delete** у діалоговому вікні. Відтоді Git відповідає `Authentication failed` на цей токен.
