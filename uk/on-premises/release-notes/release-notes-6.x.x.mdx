## Ayakaleaf Pro 6.3.0

<strong>Дата випуску:</strong> 2026.10.03 (повторний випуск; початково випущено 2026.09.24)

Див.: [https://github.com/ayaka-notes/ayakaleaf-pro/releases/tag/pro-v6.3.0](https://github.com/ayaka-notes/ayakaleaf-pro/releases/tag/pro-v6.3.0)

<Warning>

Ayakaleaf Pro 6.3.0 початково було випущено 24 вересня 2026 року. Цей повторний випуск усуває проблеми з ШІ-асистентом та інтеграціями Zotero і Mendeley, спричинені оновленнями в основному проєкті.

Попередньо випущена версія не пошкоджує ваших даних. Завантажте найновіший образ `6.3.0` та оновіть своє розгортання. <strong>Наявні інсталяції з бібліографічними файлами, пов'язаними із Zotero чи Mendeley, також мають виконати наведену нижче міграцію.</strong> Новим інсталяціям ця міграція не потрібна.

</Warning>

<Accordion title="Міграція Zotero / Mendeley для наявних інсталяцій">

Під час оновлення до повторно випущеного образу 6.3.0 перенесіть наявні метадані бібліографії, пов'язаної із Zotero/Mendeley, за допомогою наведеного нижче скрипта. Ця міграція супроводжує виправлення `12031b8dfd`.

Вона перейменовує `zoteroGroupId` / `mendeleyGroupId` на `group_id`, перейменовує `importedByUserId` на `importer_id` і видаляє `importedByName`.

Перед запуском міграції створіть резервну копію MongoDB і зупиніть застосунок. MongoDB має залишатися запущеною. Відкрийте її оболонку (замініть `mongo` на назву свого контейнера):

```bash
docker exec -it mongo mongosh
```

Виконайте таке в `mongosh` (замініть `sharelatex` на назву своєї бази даних):

```javascript
use sharelatex

(async () => {
  let updated = 0
  await db.projects.find({}, { rootFolder: 1 }).forEach(async project => {
    const changes = {}
    function visit(folders, path) {
      for (const [i, folder] of (folders || []).entries()) {
        const folderPath = `${path}.${i}`
        for (const [j, file] of (folder.fileRefs || []).entries()) {
          const data = { ...file.linkedFileData }
          if (!["zotero", "mendeley"].includes(data.provider)) continue
          const groupKey = `${data.provider}GroupId`
          if (![groupKey, "importedByUserId", "importedByName"].some(key => key in data)) continue
          for (const [oldKey, newKey] of [[groupKey, "group_id"], ["importedByUserId", "importer_id"]]) {
            if (data[oldKey] != null && data[oldKey] !== "") {
              const value = String(data[oldKey])
              if (newKey in data && data[newKey] !== value) {
                throw new Error(`Conflicting ${newKey}: project ${project._id}, file ${file._id}`)
              }
              data[newKey] = value
            }
            delete data[oldKey]
          }
          delete data.importedByName
          changes[`${folderPath}.fileRefs.${j}.linkedFileData`] = data
        }
        visit(folder.folders, `${folderPath}.folders`)
      }
    }
    visit(project.rootFolder, "rootFolder")
    if (!Object.keys(changes).length) return
    const result = await db.projects.updateOne(
      { _id: project._id, rootFolder: { $eq: project.rootFolder } },
      { $set: changes }
    )
    if (!result.matchedCount) throw new Error(`Project changed during migration: ${project._id}`)
    updated += result.modifiedCount
  })
  print(`Updated ${updated} project(s).`)
})()
```

Скрипт обробляє вкладені каталоги й змінює лише метадані Zotero/Mendeley. Його безпечно запускати повторно: після завершеної міграції наступний запуск повідомить `Updated 0 project(s).` Якщо скрипт зупиниться через конфлікт, перевірте вказаний проєкт/файл; попередні проєкти вже могли бути перенесені.

Запустіть оновлений застосунок, перезавантажте редактор і оновіть наявний бібліографічний файл від імені користувача, який його початково імпортував. Історичні знімки не переписуються. Щоб повернутися до старої версії застосунку, відновіть резервну копію MongoDB.

</Accordion>

Ми з гордістю оголошуємо про випуск Overleaf Pro 6.3.0 — найпотужнішого та найбагатшого на функції онлайн-редактора LaTeX у спільноті. Оскільки ми завжди зосереджуємося на покращенні досвіду наших користувачів, цей випуск приносить величезні зміни та чудові функції, які вам неодмінно сподобаються, зокрема ШІ-асистента та інтеграцію зі сторонніми менеджерами посилань.

### Зміни

* ШІ-чат-асистент: спілкуйтеся з моделлю ШІ через власного постачальника просто у своєму редакторі.
* Асистент помилок LaTeX: отримуйте запропоновані ШІ виправлення помилок компіляції LaTeX.
* Інтеграція з Mendeley: імпортуйте посилання з Mendeley аналогічно до Zotero.
* Open in Overleaf API: додано API для відкриття вмісту в Overleaf.
* Галерея шаблонів: додано серверне розбиття на сторінки, пошук і сортування, тож великим галереям більше не потрібно завантажувати всі шаблони в браузер.
* Переклади: оновлено патчі перекладів для 6.3.0, зокрема новий текст інтерфейсу для всіх підтримуваних мов.
* Upstream Overleaf 6.3.0: містить редагування файлів у вкладках, окремі логотипи заголовка для світлої та темної тем, а також оновлення залежностей і базового образу.
* Додано `OVERLEAF_HEADER_IMAGE_URL_LIGHT` і `OVERLEAF_HEADER_IMAGE_URL_DARK` для підтримки окремих зображень логотипа заголовка для світлої та темної тем.
* Тепер файли можна відкривати в різних вкладках редактора.
* Додано підтримку налаштовуваних HTTP(S)-проксі, зокрема локально розміщених, через `OVERLEAF_LINKED_URL_OUTBOUND_PROXY`, яка також використовується Open in Overleaf API.

#### Feature 04: Template Pagination

Тепер галерея виконує розбиття на сторінки, сортування й пошук у MongoDB. Вона працює без жодної підготовки; якщо у вас тисячі шаблонів, ви все одно можете додати ці індекси, щоб зберегти швидкодію (повторний запуск безпечний; `mongo`/`sharelatex` — назви вашого контейнера та бази даних):

```bash
docker exec mongo mongosh sharelatex --quiet --eval '
db.templates.createIndex({category:1,lastUpdated:-1},{name:"category_1_lastUpdated_-1",background:true});
db.templates.createIndex({lastUpdated:-1},{name:"lastUpdated_-1",background:true});
db.templates.createIndex({category:1,name:1},{name:"category_1_name_1_ci",collation:{locale:"en",strength:2},background:true});
db.templates.createIndex({name:1},{name:"name_1_ci",collation:{locale:"en",strength:2},background:true});
'
```

Залиште `collation` у двох індексах `*_ci` саме так, як написано, — галерея виконує запити з тим самим collation, а MongoDB використовує лише відповідний індекс.

## Ayakaleaf Pro 6.2.2

<strong>Дата випуску:</strong> 2026.07.23

Див.: [https://github.com/ayaka-notes/ayakaleaf-pro/releases/tag/pro-v6.2.2](https://github.com/ayaka-notes/ayakaleaf-pro/releases/tag/pro-v6.2.2)

### Зміни

Перенесено офіційні патчі-виправлення, випущені в upstream Overleaf `6.2.2` (поверх `6.2.1`):

* Припинено витік секрету токена запрошення до проєкту в журнали. Шифрувальник токенів запрошення записував у журнал власну конфігурацію під час кожного шифрування/розшифрування, зокрема паролі шифрів, похідні від `OVERLEAF_INVITE_TOKEN_SECRET`.
* Вихідну пошту перенесено з клієнта AWS SES v1, підтримку якого завершено, на SESv2. Екземпляри, налаштовані з поштовим драйвером `ses`, могли взагалі не надсилати листи; тепер надсилання відбувається через `SESv2Client`.
* Групові елементи випадного списку спільного доступу до проєкту приховано за новим прапорцем функції `group-link-sharing`, тож спільний доступ за груповим посиланням більше не пропонується в екземплярах, де він не застосовний.
* Виправлено модальне вікно спільного доступу до проєкту для співавторів. Відкриття його не власником або з вимкненим потоком `sharing-updates` надсилало запит, який завжди завершувався невдачею й показував помилку «something went wrong».
* До document-updater додано `scripts/flush_docs_with_pending_updates.js` — скрипт обслуговування, який відновлює документи із застряглою чергою `PendingUpdates` у Redis після того, як їхній проєкт було скинуто або остаточно видалено. Підтримує `--dry-run` і перевірку безпеки `--estimated-docs`.
* Оновлено залежності: `multer` 2.2.0, `form-data` 2.5.6, `protobufjs` 7.6.3, `@grpc/grpc-js` 1.14.4.

Цей випуск також містить такі виправлення та покращення від Ayakaleaf Pro:

* Додано повні переклади для 16 додаткових мов (cs, da, de, es, fi, fr, it, ja, ko, nl, no, pl, pt, ru, sv, tr), що виправляє неперекладені рядки, як-от на сторінці скидання пароля. Виправляє [#38](https://github.com/ayaka-notes/ayakaleaf-pro/issues/38).
* Виправлено кількість елементів на кнопці «show N more projects» у панелі адміністратора, яка показувала неправильне число, бо заповнювач множини передавався некоректно.
* Виправлено помилки валідації експорту в GitHub, які тепер відображаються через статичні ключі i18n замість необроблених повідомлень, а також видалено ключі помилок, які більше не використовуються модальним вікном GitHub Sync.

### Зміни

Перенесено офіційні патчі-виправлення, випущені в upstream Overleaf `6.2.1` (поверх `6.2.0`):

* Посилено захист повідомлення реального часу `applyOtUpdate` за допомогою суворої схеми валідації замість приймання будь-якого об'єкта; некоректні операції редагування відхиляються.

* Виправлено редактор (клієнт ShareJS), щоб операції, які зводяться до порожньої операції — скасованої віддаленою/паралельною операцією або повністю відкоченої через скасування, — відкидалися, а не надсилалися на сервер, і документ коректно позначався як збережений. Це запобігає хибним проблемам синхронізації / «незбережених змін» під час скасування та паралельного редагування.

## Ayakaleaf Pro 6.2.0

<strong>Дата випуску:</strong> 2026.07.10

Див.: [https://github.com/ayaka-notes/ayakaleaf-pro/releases/tag/pro-v6.2.0](https://github.com/ayaka-notes/ayakaleaf-pro/releases/tag/pro-v6.2.0)

Ми з гордістю оголошуємо про випуск Overleaf Pro 6.2.0 — найпотужнішого та найбагатшого на функції онлайн-редактора LaTeX у спільноті. Особлива подяка yu-i-i та davrot за їхній цінний внесок. Вони вдосконалили GitHub Sync і додали розширений пошук цитувань та інтеграцію з Zotero.

### Примітки

<Warning>

* Додано нову обов'язкову змінну середовища `OVERLEAF_INVITE_TOKEN_SECRET`. Її потрібно згенерувати за допомогою `openssl rand -base64 32`. Якщо її не налаштовано, ваш екземпляр Overleaf не запуститься.
* Якщо ви вмикаєте GitHub Sync, потрібно налаштувати змінну середовища `GITHUB_TOKEN_CIPHER_PASSWORD`. Ця змінна необхідна для безпечного шифрування токенів доступу GitHub. Без неї ваш екземпляр Overleaf не запуститься.

</Warning>

* Додано нову змінну середовища `DEFAULT_LATEX_COMPILER` для встановлення компілятора за замовчуванням для нових проєктів (`pdflatex`, `latex`, `xelatex` або `lualatex`).
* Оновлений редактор тепер є єдиним доступним варіантом.

### Зміни

Цей випуск містить такі покращення та нові функції.

* `MAX_UPLOAD_SIZE` тепер можна налаштовувати, а не обмежено **50 МБ**.
* Виправлено цикл перезапуску контейнера, коли ізольовану компіляцію було вимкнено.
* Для OAuth2 запроваджено видалення PAT лише в межах власника.
* Виправлено проблему з імпортом LDAP.

Нові функції:

* Додано запуск Python у браузері.
* Додано підтримку Pandoc для імпорту й експорту Markdown, DOCX та інших форматів.
* Додано GitHub Sync.
* Додано повний китайський переклад.
* Додано інтеграцію з Zotero.
* Додано `DEFAULT_LATEX_COMPILER`.

#### Функція 01: GitHub Sync

Тримайте свої проєкти LaTeX синхронізованими з репозиторіями GitHub для безперебійного робочого процесу. Надсилайте та отримуйте зміни безпосередньо з редактора, співпрацюйте через pull request і інтегруйтеся з наявними конвеєрами CI/CD. Контроль версій спрощує відстеження редакцій, перегляд змін і підтримку відтворюваних наукових або технічних документів.

## Ayakaleaf Pro 6.0.0

<strong>Дата випуску:</strong> 2026.02.17

Тестовий випуск, див.: [https://github.com/ayaka-notes/ayakaleaf-pro/releases/tag/pro-v6.0.0](https://github.com/ayaka-notes/ayakaleaf-pro/releases/tag/pro-v6.0.0)

Це тестовий випуск і водночас наша початкова версія Overleaf Pro. Ця версія не містить жодних функцій Server Pro, тож вона позначена лише як наша відправна точка. Пізніше ми додамо нові функції, як-от панель адміністратора, git-bridge тощо.

У цьому випуску ми представили Docker-образ Overleaf для ARM. Ви можете спробувати його, якщо маєте Mac або сервер на ARM, але деякі функції можуть працювати некоректно (ще не протестовано).

### Docker-образ

Docker-образ можна знайти тут: [https://github.com/ayaka-notes/overleaf-pro/pkgs/container/overleaf-pro](https://github.com/ayaka-notes/overleaf-pro/pkgs/container/overleaf-pro)

Мультиархітектурний образ див. [тут](https://github.com/ayaka-notes/overleaf-pro/pkgs/container/overleaf-pro/691283454?tag=6.0.0).

```bash
docker pull ghcr.io/ayaka-notes/overleaf-pro:6.0.0
```

### Міграція бінарних файлів

Цей новий випуск удвічі зменшує обсяг сховища, що займають бінарні файли.

У версію `5.5` включено онлайн-міграцію, що дає змогу мінімізувати час простою під час оновлення. Перш ніж оновлюватися до Server Pro `v6`, переконайтеся, що ви вже використовуєте найновішу версію Server Pro `v5.5` ([Примітки до випусків 5.x.x](https://docs.overleaf.com/on-premises/release-notes/release-notes-5.x.x)) і виконали міграцію.

[Див. повні інструкції з міграції](https://docs.overleaf.com/on-premises/release-notes/release-notes-5.x.x/binary-files-migration).

### Оновлення MongoDB до v8

Цей випуск підвищує мінімальну версію MongoDB до `8.0`.

Якщо зараз ви використовуєте MongoDB `v6` або старішу, потрібно оновлюватися послідовно, по одній мажорній версії за раз (`v6 → v7 → v8`).

<Warning>

Обов'язково створіть резервну копію [бази даних](https://docs.overleaf.com/on-premises/maintenance/data-and-backups) **перед** оновленням. У разі відкату потрібно буде відновити резервну копію бази даних.

</Warning>

Інструкції з оновлення MongoDB `v6 → v7 → v8` див. у нашому покроковому посібнику [тут](https://docs.overleaf.com/on-premises/maintenance/updating-mongodb#example-upgrading-mongodb-from-6.0-to-7.0-toolkit-users).

### Оновлення Redis до v7.4

Цей випуск також підвищує мінімальну версію Redis до `7.4`.

Змініть `REDIS_IMAGE` у своєму `config/overleaf.rc` на `REDIS_IMAGE=7.4`.

### Нові функції

* Спільний доступ за посиланням тепер можна вимкнути за допомогою `OVERLEAF_DISABLE_LINK_SHARING=true`.
* Для налаштування заголовка та вмісту сторінки технічного обслуговування тепер доступні `OVERLEAF_MAINTENANCE_MESSAGE` і `OVERLEAF_MAINTENANCE_MESSAGE_HTML`.
* `OVERLEAF_USER_HARD_DELETION_DELAY` і `OVERLEAF_PROJECT_HARD_DELETION_DELAY` можна налаштувати (у мілісекундах), щоб змінити затримку остаточного видалення видалених користувачів/проєктів (за замовчуванням 90 днів).

### Виправлення помилок

* Виправлено відображення нижнього колонтитула з посиланнями.
* Покращено повідомлення про помилки входу через SAML.
* Виправлено відсутність запису в журналі аудиту, коли статус адміністратора користувача оновлюється під час входу через SSO.
* Виправлено помилки панелі історії, коли в Redis увімкнено TLS.
* Компіляції тепер можна зупиняти під час використання неізольованої компіляції.

### Інші зміни

* Усі посилання на сторінку стану (задану через `OVERLEAF_STATUS_PAGE_URL`) тепер використовують `HTTPS` і відкриваються в новій вкладці браузера.
