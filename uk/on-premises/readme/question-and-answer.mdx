Тут ми зібрали відповіді на деякі поширені запитання про Ayakaleaf Pro.

### Загальні запитання {#basic-question}

<Accordion title="Q01: Чи є Ayakaleaf Pro пробною версією? Чи потрібна для нього ліцензія?">

Ні. Ayakaleaf Pro повністю безкоштовний. Це не пробна версія, і ліцензія не потрібна.

</Accordion>

<Accordion title="Q02: Чи містить Ayakaleaf Pro усі функції Overleaf Server Pro?">

Так. Ayakaleaf Pro містить усі функції Overleaf Server Pro, зокрема інтеграцію Git-Bridge. Він також містить окремі функції SaaS-платформи Overleaf. Ми продовжуємо розвивати та вдосконалювати Ayakaleaf Pro.

</Accordion>

<Accordion title="Q03: Скільки коштує Overleaf Server Pro?">

Overleaf Server Pro коштує близько \$300 на одного користувача на рік. Потрібно щонайменше 10 ліцензій, тож вартість розгортання починається приблизно від \$3,000 на рік. Невеликі публічні контракти у США показують річну вартість близько \$320–\$370 на користувача. Це робить Server Pro дорогим, особливо для невеликих команд. Задокументовані закупівлі та ціни див. у [#information-and-price-about-overleaf-server-pro](/uk/on-premises#information-and-price-about-overleaf-server-pro  "mention").

</Accordion>

<Accordion title="Q04: Чому Overleaf Server Pro не містить GitHub Sync або AI-функцій?">

Overleaf Server Pro часто використовують державні організації. Вони розгортають його в приватних мережах і суворо контролюють доступ. Щоб захистити конфіденційні дані, вбудовані функції уникають обміну даними зі сторонніми сервісами. Якщо вам потрібні GitHub Sync, AI або подібні функції, що потребують зовнішніх підключень, Overleaf рекомендує підписку на свою SaaS-платформу.

</Accordion>

<Accordion title="Q05: Чи є Ayakaleaf Pro безпечним і надійним?">

Ayakaleaf Pro має відкритий вихідний код. Ми перевіряємо код за допомогою таких інструментів, як Codex Security, щоб посилити його безпеку та надійність. Якщо ви не вмикаєте синхронізацію даних зі сторонніми сервісами, ваші дані залишаються на вашому сервері. Ayakaleaf Pro не містить телеметрії, яка надсилала б ваші дані деінде.

</Accordion>

<Accordion title="Q06: Чи буде Ayakaleaf Pro підтримуватися довгостроково?">

Ми докладемо всіх зусиль, щоб підтримувати цей проєкт у довгостроковій перспективі.

</Accordion>

<Accordion title="Q07: Чи відповідає Ayakaleaf Pro ліцензійним вимогам?">

Ayakaleaf Pro — це форк спільноти. Його код та інтегровані функції походять із внесків спільноти. Він поширюється за ліцензією AGPL v3. Розгортання можуть відповідати цій ліцензії, якщо виконують її вимоги.

</Accordion>

<Accordion title="Q08: Чому проєкт називається Ayakaleaf Pro?">

Спочатку, у 2024 році, проєкт називався Overleaf Pro. Розробку на певний час було призупинено, а наприкінці 2025 року відновлено. У першому кварталі 2026 року Overleaf перейменував свій тарифний план із підтримкою AI на Pro. Спільнота також зазначила, що назва Overleaf Pro може створювати ризики, пов'язані з товарними знаками та видаванням себе за інших. Вона могла б змусити користувачів думати, що проєкт є офіційним.

Ми перейменували проєкт на Ayakaleaf Pro, щоб уникнути цієї плутанини. Назву можна прочитати як «Ayaka-notes Overleaf Pro». Супровідник (можете називати мене ayaka!) бере участь у розвитку спільноти Overleaf ще зі студентських років, тобто понад п'ять років. Цей досвід підкріплює наше зобов'язання щодо довгострокової підтримки.

</Accordion>

<Accordion title="Q09: Чим Ayakaleaf Pro відрізняється від новіших LaTeX-редакторів, створених за допомогою AI?">

Починаючи з 2026 року, спільнота відкритого коду випустила багато LaTeX-редакторів, створених за допомогою AI, зокрема OpenAI Prism. Ayakaleaf Pro зберігає ваші дані та сервіси на вашому власному сервері. Це дає вам безпосередній контроль над розгортанням і даними.

Багато експериментальних редакторів спільноти не мають усталеного плану довгострокової підтримки. Сторонні платформи для компіляції LaTeX також можуть припинити роботу, якщо їхня база користувачів або дохід недостатні. Ayakaleaf Pro надає весь вихідний код і дозволяє самостійно розміщувати кожен сервіс. Навіть якщо підтримку буде припинено, ваш наявний самостійно розміщений сервіс зможе працювати далі.

</Accordion>

<Accordion title="Q10: Що сталося з GitHub-репозиторієм ayaka-notes/overleaf-pro?">

Його перейменовано на [ayaka-notes/ayakaleaf-pro](https://github.com/ayaka-notes/ayakaleaf-pro) разом із перейменуванням проєкту (див. Q08). Його не архівовано й не замінено: це той самий репозиторій, і GitHub перенаправляє старі посилання та Git remotes `ayaka-notes/overleaf-pro` на нову назву. Docker-образ зберігає свою назву, `ghcr.io/ayaka-notes/overleaf-pro`, тож вам не потрібно змінювати `config/overleaf.rc` чи `config/version`.

</Accordion>

### Функції {#features}

<Accordion title="Q01: Які функції пропонує Ayakaleaf Pro? Чи можу я запросити нову функцію?">

Актуальний перелік функцій дивіться в нашій документації. Якщо ви хочете, щоб ми додали певну функцію, сміливо створіть issue (запит на функцію) на GitHub. Ми докладемо всіх зусиль, щоб реалізувати запитані функції, але розробка потребує часу, і ми не можемо гарантувати, що кожну функцію буде реалізовано одразу.

</Accordion>

<Accordion title="Q02: Я розробив деякі функції. Чи можу я надіслати PR, і чи гарантовано його буде прийнято?">

Внески вітаються, але їх прийняття не гарантоване. Ми оцінюємо кожен PR з огляду на його вплив на базовий код Overleaf, навантаження на супровід і цінність для користувачів. Ми докладемо всіх зусиль, щоб злити та підтримувати цінні внески.

Однак ми можемо відхилити PR, які вносять надмірні зміни, складаються з неперевіреного або погано зрозумілого коду, згенерованого AI («vibe coding»), або додають функції, які було б складно підтримувати з часом.

</Accordion>

<Accordion title="Q03: Як налаштувати певну функцію?">

Зазвичай ми оновлюємо документацію щоразу, коли випускаємо нову функцію. Детальні інструкції з налаштування та пояснення доступних змінних середовища дивіться у відповідній документації.

</Accordion>

<Accordion title="Q04: Які бібліотеки Python може використовувати Python Runner?">

Python Runner запускає Python у браузері користувача за допомогою [Pyodide](https://pyodide.org/) 0.29.3, а не на сервері. Він завантажує пакети, які імпортує ваш код, з [пакетів, вбудованих у Pyodide](https://pyodide.org/en/0.29.3/usage/packages-in-pyodide.html), як-от NumPy, pandas і Matplotlib. Пакети, встановлені через `pip`, та інші пакети недоступні. На сервері нічого налаштовувати не потрібно.

</Accordion>

<Accordion title="Q05: Чи може перевірка орфографії перевіряти японську або китайську мову?">

Ні. Засіб перевірки орфографії не має словника для японської чи китайської мови, тож цих мов немає у списку мов перевірки орфографії. Користувачі можуть вимкнути перевірку орфографії для проєкту в налаштуваннях редактора.

Щоб слово не позначалося як написане з помилкою, клацніть його правою кнопкою миші та виберіть **Add to dictionary**. Додані слова зберігаються у вашому обліковому записі й застосовуються до всіх ваших проєктів. Щоб переглянути або видалити їх, відкрийте налаштування редактора, а потім **Spelling and language → Dictionary → Edit**. Додавання слів не додає нової мови перевірки орфографії.

</Accordion>

<Accordion title="Q06: Чи можна додавати плагіни?">

Інсталятора плагінів немає. Функції — це модулі в `services/web/modules` вихідного коду, які вбудовуються в Docker-образ і вмикаються за допомогою налаштувань, описаних у цій документації. Щоб додати власну функцію, додайте модуль до вихідного коду та зберіть власний образ.

</Accordion>

### Розгортання {#deployment}

<Accordion title="Q01: Чи підтримує Ayakaleaf Pro розподілене розгортання в k8s?">

Більшості користувачів ми рекомендуємо розгортання за допомогою [Toolkit](/uk/on-premises/installation/using-docker-compose). Підтримка Kubernetes експериментальна: на сторінці [Використання Kubernetes](/uk/on-premises/installation/using-kubernetes) наведено маніфести, які ми протестували з однією або кількома репліками, але кластер ускладнює експлуатацію та збільшує зусилля на супровід. [Sandboxed Compiles](/uk/on-premises/configuration/overleaf-toolkit/sandboxed-compiles) створюють свої контейнери компіляції через Docker socket, тож на кожному вузлі, де працює Ayakaleaf Pro, потрібен Docker Engine. Ми не надаємо конфігурацій для CRI-O, Podman чи Quadlet.

</Accordion>

<Accordion title="Q02: Як забезпечити доступність під час обслуговування тисяч користувачів?">

Ознайомтеся з нашим посібником із [горизонтального масштабування](/uk/on-premises/maintenance/horizontal-scaling). Ви можете розгорнути кілька екземплярів Overleaf і налаштувати балансувальник навантаження для розподілу трафіку між ними.

</Accordion>

<Accordion title="Q03: Чи можете ви допомогти мені з розгортанням або міграцією?">

Якщо у вас є наявний екземпляр Overleaf Server Pro, ми з радістю допоможемо вам перейти на Ayakaleaf Pro. Зв'яжіться з нами електронною поштою або через issues.

</Accordion>

<Accordion title="Q04: Чи можна розмістити Ayakaleaf Pro за підшляхом URL, як-от `https://example.com/overleaf`?">

Ні. Ayakaleaf Pro має обслуговуватися з кореня домену. Використовуйте окремий домен або піддомен, наприклад `https://overleaf.example.com`.

</Accordion>

<Accordion title="Q05: Чи можна запускати Ayakaleaf Pro на Windows або macOS чи без Toolkit?">

Так. Toolkit працює в [Linux](/uk/on-premises/installation/using-docker-compose/linux), [macOS з Docker Desktop](/uk/on-premises/installation/using-docker-compose/macos) і [Windows з WSL 2 та Docker Desktop](/uk/on-premises/installation/using-docker-compose/windows). Для спільних і продакшн-серверів ми рекомендуємо Linux. Посібники для macOS і Windows містять налаштування ізольованої компіляції (sandboxed compiles).

Ми не надаємо окремого `docker-compose.yml`. Щоб побачити конфігурацію Compose, яку використовує Toolkit, виконайте `bin/docker-compose config` у каталозі Toolkit.

</Accordion>

<Accordion title="Q06: Як видалити Ayakaleaf Pro?">

Скрипта видалення немає. У каталозі Toolkit:

1. Зупиніть і видаліть контейнери командою `bin/docker-compose down`.
2. Видаліть дані. За замовчуванням вони містяться в каталозі `data/` Toolkit. Якщо ви змінювали `OVERLEAF_DATA_PATH`, `MONGO_DATA_PATH`, `REDIS_DATA_PATH` або `GIT_BRIDGE_DATA_PATH` у `config/overleaf.rc`, видаліть і ці каталоги. Цю дію не можна скасувати, тож спершу [створіть резервну копію](/uk/on-premises/maintenance/data-and-backups), якщо дані можуть вам знадобитися.
3. Видаліть каталог Toolkit.
4. Видаліть Docker-образи, список яких можна переглянути командою `docker images`: `ghcr.io/ayaka-notes/overleaf-pro`, образ git-bridge, `mongo`, `redis` та образи TeX Live.

</Accordion>

<Accordion title="Q07: Як зупинити, запустити або перезапустити Ayakaleaf Pro?">

Виконуйте ці команди в каталозі Toolkit:

* `bin/stop` зупиняє всі контейнери, `bin/start` знову їх запускає. Контейнери зберігаються, тож користувачі залишаються в системі.
* `bin/up -d` створює контейнери й запускає їх у фоновому режимі. Виконуйте її після зміни `config/variables.env`, `config/overleaf.rc` або `config/version`: вона перестворює контейнери, конфігурацію яких змінено, і лише тоді зміни набувають чинності. `bin/stop` і `bin/start` їх не застосовують.
* `bin/docker-compose restart sharelatex` перезапускає лише контейнер Overleaf, не застосовуючи змін конфігурації.

Якщо користувачів виводить із системи щоразу, коли `bin/up` перестворює контейнер, встановіть `OVERLEAF_SESSION_SECRET`, див. розділ «Питання та відповіді» у [Змінних середовища](/uk/on-premises/configuration/overleaf-toolkit/environment-variables).

</Accordion>

<Accordion title="Q08: Куди вказувати URL-адресу зворотного виклику OAuth?">

У застосунку, який ви створюєте в постачальника, а не в Ayakaleaf Pro. Для жодної з цих інтеграцій у `config/variables.env` немає параметра зворотного виклику: Ayakaleaf Pro формує кожну URL-адресу зворотного виклику з `OVERLEAF_SITE_URL` і надсилає її постачальнику, який відхиляє її, якщо вона не збігається з тією, що зареєстрована для застосунку. Тож ви лише реєструєте її в постачальника, а `OVERLEAF_SITE_URL` встановлюєте на адресу, яку відкривають користувачі.

| Інтеграція | Поле в постачальника | Значення |
| --- | --- | --- |
| [GitHub](/uk/on-premises/configuration/overleaf-toolkit/integrations/github-synchronisation) | Authorization callback URL | `${OVERLEAF_SITE_URL}/user/github-sync/oauth2/callback` |
| [GitLab](/uk/on-premises/configuration/overleaf-toolkit/integrations/gitlab-synchronisation) | Redirect URI | `${OVERLEAF_SITE_URL}/user/gitlab-sync/oauth2/callback` |
| [Gitea](/uk/on-premises/configuration/overleaf-toolkit/integrations/gitea-synchronisation) | Redirect URIs | `${OVERLEAF_SITE_URL}/user/gitea-sync/oauth2/callback` |
| [Dropbox](/uk/on-premises/configuration/overleaf-toolkit/integrations/dropbox-synchronisation) | Redirect URIs (натисніть **Add**) | `${OVERLEAF_SITE_URL}/user/dropbox/oauth/callback` |
| [Zotero](/uk/on-premises/configuration/overleaf-toolkit/integrations/zotero-integration) | Callback URL | `${OVERLEAF_SITE_URL}/user/zotero/oauth/callback` |
| [Mendeley](/uk/on-premises/configuration/overleaf-toolkit/integrations/mendeley-integration) | Redirect URL | `${OVERLEAF_SITE_URL}/user/mendeley/oauth/callback` |
| [Вхід через OIDC](/uk/on-premises/configuration/overleaf-toolkit/authentication/oidc-authentication) | Redirect URI | `${OVERLEAF_SITE_URL}/oidc/login/callback` |
| [Вхід через SAML](/uk/on-premises/configuration/overleaf-toolkit/authentication/saml-authentication) | ACS URL (Assertion Consumer Service) | `${OVERLEAF_SITE_URL}/saml/login/callback` |

Якщо ви змінюєте `OVERLEAF_SITE_URL`, наприклад на новий домен, оновіть URL-адресу й у кожного постачальника, інакше прив'язка не працюватиме.

</Accordion>

<Accordion title="Q09: Де зберігаються дані та скільки місця на диску мені потрібно?">

За замовчуванням усе зберігається на локальному диску сервера, у каталозі `data/` Toolkit: `data/overleaf` (файли проєктів, історія та результати компіляції), `data/mongo` і `data/redis`. Для екземплярів, що мають менше ніж 1000 користувачів, ми рекомендуємо локальний диск із регулярними [резервними копіями](/uk/on-premises/maintenance/data-and-backups).

Образ Ayakaleaf Pro займає близько 5 ГБ. Мінімум 40 ГБ, указаний у [Вступі](/uk/on-premises/installation/introduction), стосується Sandboxed Compiles, образи `texlive-full` яких займають близько 28 ГБ кожен. Без Sandboxed Compiles компіляція виконується всередині контейнера `sharelatex` з базовою схемою TeX Live разом із `latexmk`, `texcount`, `synctex`, `etoolbox` і `xetex`, тож багато проєктів не компілюються через відсутні пакети. Каталог `data/` потім зростає разом із вашими проєктами та їхньою історією; перевірити його розмір можна командою `du -sh data/*`.

</Accordion>

<Accordion title="Q10: Чи можна тримати Ayakaleaf запущеним у Windows цілодобово?">

Так, за умови що Windows не переходить у сплячий режим, а Docker Desktop залишається запущеним. Увімкніть **Start Docker Desktop when you sign in to your computer**, залиште політики `restart: always` з Toolkit і вимкніть автоматичний сплячий режим та гібернацію під час живлення від мережі. Екран може вимикатися; поведінка під час закриття кришки ноутбука — окреме налаштування. Закриття термінала Ubuntu після `bin/up -d` не зупиняє контейнери, запущені у фоновому режимі. Вихід із Docker Desktop, призупинення його рушія або виконання `wsl --shutdown` перериває роботу сервісу.

Resource Saver у Docker Desktop — це не те саме, що сплячий режим Windows: він застосовується, коли не запущено жодного контейнера, тож запущений стек Ayakaleaf не вважається бездіяльним лише тому, що ніхто нічого не редагує. Після перезавантаження Windows налаштування запуску під час входу все одно вимагає, щоб хтось увійшов у систему. Перевірки та кроки відновлення описано в розділі [Підтримання доступності екземпляра](/uk/on-premises/installation/using-docker-compose/windows/6.-post-installation-tasks#keep-the-instance-available). Якщо доступність не повинна залежати від інтерактивного входу на робочий стіл, ми й надалі рекомендуємо Linux.

</Accordion>

<Accordion title="Q11: Docker Desktop повідомляє, що віртуалізацію вимкнено. Чи потрібен мені Hyper-V?">

Цей посібник використовує **WSL 2 backend**. Для нього потрібні ввімкнена віртуалізація процесора в BIOS/UEFI, компонент Windows **Virtual Machine Platform** і робоча інсталяція WSL 2. Повний компонент **Hyper-V** — це окремий бекенд Docker Desktop, і для цього налаштування WSL він не обов'язковий.

Перевірте **Task Manager → Performance → CPU → Virtualization** і виконайте `wsl --list --verbose` у PowerShell. Помилки на кшталт `0x80370102` можуть означати, що вимкнено віртуалізацію, компонент Windows або гіпервізор під час завантаження. Див. [кроки з усунення несправностей встановлення у Windows](/uk/on-premises/installation/using-docker-compose/windows/troubleshooting#wsl-or-docker-reports-that-virtualization-is-unavailable) з посиланнями на інструкції з відновлення від Microsoft і Docker. Після ввімкнення потрібних компонентів перезавантажте Windows; перевстановлення Ayakaleaf не виправить рушій Docker, який не запускається.

</Accordion>

### LaTeX {#latex}

<Accordion title="Q01: Чи ізольовано компіляцію LaTeX-проєктів користувачів? Чи ввімкнено Shell Escape?">

Коли ви вмикаєте Sandbox Compiles, компіляція кожного користувача виконується в окремому контейнері Docker та ізольована від компіляцій інших користувачів. Для Sandbox Compiles Shell Escape увімкнено за замовчуванням.

</Accordion>

<Accordion title="Q02: Чи надійний образ Sandbox Compiles? Чи може компіляція завершитися помилкою?">

Протягом останніх трьох років ми вдосконалювали наш образ TeX Live Full для Sandbox Compiles. У більшості випадків проєкти, які компілюються на overleaf.com, також коректно компілюються в Ayakaleaf Pro. Якщо потрібний шрифт недоступний, завантажте цей шрифт до свого проєкту вручну.

</Accordion>

<Accordion title="Q03: Мій проєкт не компілюється. Чи можете ви допомогти з'ясувати причину?">

Завантажте свій проєкт на офіційний сайт Overleaf, увімкніть надання доступу за посиланням лише для читання та додайте це посилання до issue на GitHub.

Ми дослідимо та виправимо будь-які помилки, через які проєкт не компілюється в Ayakaleaf Pro, якщо він успішно компілюється на офіційному сайті Overleaf. Проблеми з компіляцією поза цими межами наша підтримка не охоплює.

</Accordion>
