<Accordion title="Запуск Overleaf із файловою системою NFS">

Монтування файлової системи NFS у контейнер Overleaf технічно можливе, але не рекомендоване і може призводити до різних проблем із продуктивністю.

Одна з поширених помилок, що виникає під час компіляції:

```text
EBUSY: resource busy or locked, unlink '/var/lib/overleaf/data/compiles/62f3d57bef7cf9005c364e75-62f3d57bef7cf9005c364e7a/.nfs573663533034825247625441'
```

Зокрема, ми не радимо використовувати файлові системи на основі NFS для тимчасових даних, наприклад для каталогів із даними компіляції. Для наведених нижче каталогів радимо використовувати локальний робочий диск, бажано локальний SSD.

Для інсталяцій на основі `docker-compose` пропонуємо просто перевизначити bind-mount з NFS, що дає змогу не змінювати шляхи в застосунку. Ось приклад фрагмента конфігурації `docker-compose` з використанням робочого диска, змонтованого в `/scratch`:

```yaml title="docker-compose excerpt"
services:
  sharelatex:
    environment:
      SANDBOXED_COMPILES_HOST_DIR: /scratch/compiles/
    volumes:
      - nfs:/var/lib/overleaf/data
      - /scratch/cache/:/var/lib/overleaf/data/cache
      - /scratch/compiles/:/var/lib/overleaf/data/compiles
      - /scratch/output/:/var/lib/overleaf/data/output
      - /scratch/tmp/:/var/lib/overleaf/tmp
```

Після оновлення немає потреби переносити наявні файли з NFS у нове місце. Компілятор LaTeX може повторно створити всі файли під час повної компіляції.

Докладніше див.: https://docs.overleaf.com/on-premises/support/troubleshooting#running-overleaf-with-an-nfs-filesystem

</Accordion>

<Accordion title="Під час запуску Overleaf у Windows або macOS служба `mongo` не запускається">

Якщо ви запускаєте Overleaf у Windows або macOS, служба `mongo` може не перезапуститися з такою помилкою:

```text title="Example error"
Failed to start up WiredTiger under any compatibility version.
Reason: 1: Operation not permitted
```

Щоб уникнути цієї помилки, дані потрібно зберігати в томі, а не в каталозі, підключеному через bind mount (докладніше див. документацію образу `mongo`: https://github.com/docker-library/docs/blob/master/mongo/content.md#where-to-store-data). Щоб зберігати дані в томах Docker, змонтованих у контейнери MongoDB і Redis, додайте наведене нижче до `config/docker-compose.override.yml` (створіть цей файл, якщо його ще немає):

```yaml title="config/docker-compose.override.yml"
volumes:
  mongo-data:
  redis-data:

services:
  mongo:
    volumes:
      - mongo-data:/data/db

  redis:
    volumes:
      - redis-data:/data
```

Докладніше див.: https://docs.overleaf.com/on-premises/support/troubleshooting#running-overleaf-on-windows-or-macos-results-in-the-mongoservice-not-starting

</Accordion>

<Accordion title="Оновлення до Redis 6.2 призводить до циклу перезапусків">

Скористайтеся командою `docker logs redis`, щоб вивести копію журналів.

Якщо ви бачите рядок `Fatal: Can't initialize Background Jobs`, повний вивід виглядатиме приблизно так:

```text title="Redis log example"
1:M 11 Feb 2024 15:19:22.609 # Server initialized
1:M 11 Feb 2024 15:19:22.609 # Fatal: Can't initialize Background Jobs.
1:C 11 Feb 2024 15:19:26.055 # oO0OoO0OoO0Oo Redis is starting oO0OoO0OoO0Oo
```

Це може бути пов'язано з версією Docker, що використовується. Оновлення до версії >= 20.10.10 має розв'язати цю проблему.

Докладніше див. відповідну проблему в Redis: https://github.com/redis/redis/issues/12362

Джерело: https://docs.overleaf.com/on-premises/support/troubleshooting#upgrading-to-redis-6.2-results-in-a-restart-loop

</Accordion>

<Accordion title="Неправильна орієнтація зображень попереднього перегляду/мініатюр у галереї шаблонів">

Іноді зображення попереднього перегляду/мініатюри, згенеровані Server Pro, можуть мати неправильну орієнтацію, і їх потрібно виправити вручну. Ці зображення зберігаються в `/var/lib/overleaf/data/template_files/` (>= 5.0.3) та `/var/lib/sharelatex/data/template_files/` (у старіших версіях).

Перед внесенням будь-яких змін радимо створити резервну копію цієї папки.

Для кожного проблемного шаблону потрібно виконати наведені нижче кроки:

Знайдіть ID шаблонуПерейдіть до галереї шаблонів вашого екземпляра (/templates/all), відкрийте проблемний шаблон і скопіюйте ID з URL-адреси (наприклад: https://your-instance-url/templates/6645d346c224815e9460a695).Виконайте команду виправленняВиконайте наведену нижче команду на хості Docker (замініть ID шаблону на скопійований і за потреби оновіть шлях):docker exec sharelatex /bin/bash -c "mogrify -rotate 90 /var/lib/overleaf/data/template\_files/6645d346c224815e9460a695\_\*\{thumbnail,preview\}"

Джерело: https://docs.overleaf.com/on-premises/support/troubleshooting#incorrect-orientation-of-template-gallery-preview-thumbnail-images

</Accordion>

<Accordion title="Переконайтеся, що ви ввімкнули системні виклики. Для pdflatex це 'pdflatex -shell-escape'.">

Команду `\write18` у Community Edition за замовчуванням вимкнено, оскільки всі компіляції відбуваються в одному контейнері `sharelatex`; це безпечніше налаштування за замовчуванням.

Якщо ви хочете ввімкнути її для pdflatex, створіть у корені проєкту файл `latexmkrc` з таким вмістом:

```perl title="latexmkrc"
$pdflatex = 'pdflatex --shell-escape';
```

Потім спробуйте скомпілювати повторно.

Джерело: https://docs.overleaf.com/on-premises/support/troubleshooting#please-verify-that-you-have-enabled-system-calls.-for-pdflatex-this-is-pdflatex-shell-escape

</Accordion>
