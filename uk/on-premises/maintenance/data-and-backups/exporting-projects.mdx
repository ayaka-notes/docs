У Server Pro і Community Edition `5.4.0` ми додали скрипт, який дає змогу адміністраторам експортувати всі проєкти користувачів (зокрема ті, що досі відображаються в теках **Deleted** і **Trashed**) до каталогу на диску.

<Info>

Результат роботи цього скрипта такий самий, як і під час ручного завантаження ZIP-архіву всіх проєктів з панелі проєктів користувача. Перед початком завантаження скрипт скидає всі незбережені зміни, щоб експорт містив останню версію проєкту.

</Info>

### Обмеження

Скрипт експорту має такі обмеження:

* Налаштування проєкту, як-от назва образу TeX Live чи компілятор, не експортуються. Їх потрібно задати під час завантаження проєкту в обліковий запис користувача.
* Експортовані проєкти не містять історії версій.
* Інформація про співавторів не зберігається. Проєктами потрібно буде поділитися повторно. Якщо використовується спільний доступ за посиланням, посилання для перегляду та редагування буде згенеровано заново (вони відрізнятимуться від попередніх).
* Коментарі та інформація про відстежувані зміни не експортуються.
* Історія чату проєкту не експортується.

<Danger>

Цей скрипт **не** призначений для заміни повної резервної копії системи. Щоб мати змогу відновити екземпляр у разі аварії, ми **наполегливо** рекомендуємо створювати [узгоджену резервну копію](https://docs.overleaf.com/on-premises/maintenance/#performing-a-consistent-backup).

</Danger>

### **Прапорці**

| Назва          | Опис                                                                            |
| -------------- | ------------------------------------------------------------------------------- |
| `--help`       | Показати довідку                                                                |
| `--user-id`    | ID користувача (обов'язковий, якщо не використовується `--export-all` або `--project-id`) |
| `--project-id` | Експортувати один проєкт (**не можна** використовувати з `--user-id` або `--export-all`) |
| `--list`       | Показати список проєктів користувача (**не можна** використовувати з `--output`) |
| `--output`     | Вихідний zip-файл (для операцій експорту одного елемента)                       |
| `--export-all` | Експортувати проєкти всіх користувачів (потребує `--output-dir`)                |
| `--output-dir` | Каталог для зберігання файлів експорту всіх користувачів                        |
| `--log-level`  | Підтримувані рівні журналювання: `trace`\|`debug`\|`info`\|`warn`\|`error`\|`fatal` |

### **Використання**

Скористайтеся такою командою, щоб експортувати проєкти всіх користувачів:

```bash wrap
# Overleaf Toolkit users
$ bin/docker-compose exec sharelatex /bin/bash -ce "cd /overleaf/services/web && node modules/server-ce-scripts/scripts/export-user-projects.mjs --export-all --output-dir=/var/lib/overleaf/data/exports"

# Legacy docker-compose.yml users
docker exec sharelatex /bin/bash -ce "cd /overleaf/services/web && node modules/server-ce-scripts/scripts/export-user-projects.mjs --export-all --output-dir=/var/lib/overleaf/data/exports"
```

<Info>

Якщо ви використовуєте Server Pro або Community Editition &lt;= 3.5.13, потрібно змінити наведений вище приклад, щоб використовувати скрипт **`export-legacy-user-projects.js`**.

</Info>

### **Завершення**

Після завершення експорту файли доступні в каталозі на хості, який змонтовано (bind mount) у <strong>/var/lib/overleaf</strong> у вашому файлі **docker-compose.yml**, або в каталозі, заданому змінною середовища `OVERLEAF_DATA_PATH` у файлі **config/overleaf.rc**, якщо ви використовуєте Toolkit.

<Info>

Наразі Overleaf допускає повторювані назви проєктів. Якщо серед проєктів користувача є дублікати, вони все одно потраплять до ZIP-експорту користувача, але після розпакування залишиться лише одна версія. У Linux `unzip -B` записуватиме файли з однаковими іменами як резервні копії, а не перезаписуватиме їх.

</Info>
