`bin/podman-setup` перевіряє все, що потрібно Ayakaleaf Pro на Podman. Без параметрів скрипт лише звітує; з `--apply` він також виправляє знайдені проблеми.

<Steps>
<Step title="Перевірка хоста">
```bash title="Check only"
bin/podman-setup
```

На чистому хості більшість перевірок не проходить, наприклад:

```text
====== Packages ======
[✗] podman not installed
[✗] podman-docker not installed
...
====== Summary ======
[✓] 7 passed  [!] 13 warnings  [✗] 4 failures
```
</Step>

<Step title="Застосування виправлень">
```bash title="Check and fix"
bin/podman-setup --apply
```

Запускайте скрипт у терміналі: для загальносистемних кроків він запитує пароль `sudo`. Він також завантажує образ Ayakaleaf Pro, щоб видобути з нього профіль seccomp, що вперше триває кілька хвилин. Наприкінці він знову перевіряє хост:

```text
====== Summary ======
[✓] 23 passed  [!] 2 warnings  [✗] 0 failures
[!] Warnings remaining:
[!] not logged in to quay.io
[!] container → socket skipped (sharelatex not running)
```

Обидва попередження на цьому етапі очікувані:

* `not logged in to quay.io`: ця перевірка походить з офіційного Toolkit, де образ Server Pro розміщено в закритому реєстрі. Образи Ayakaleaf Pro публічно доступні в `ghcr.io` і не потребують входу, тож ігноруйте це попередження. Воно залишиться й після встановлення.
* `container → socket skipped (sharelatex not running)`: для цієї перевірки потрібен запущений екземпляр. Ви знову запустите скрипт у кроці [3. Запуск Ayakaleaf Pro](/uk/on-premises/installation/using-podman/3.-start-ayakaleaf-pro).

Скрипт завершується з кодом `0`, якщо всі перевірки пройдено, `1` за наявності попереджень і `2` за наявності помилок. Через попередження про quay.io очікуйте `1`.
</Step>
</Steps>

### Що змінює скрипт {#what-the-script-changes}

З `--apply` скрипт може змінити таке.

На рівні системи, через `sudo`:

* Встановлює `podman`, `podman-docker`, `git`, `curl`, `checkpolicy` і `policycoreutils` за допомогою `dnf`.
* Вмикає lingering для вашого користувача за допомогою `loginctl`, щоб контейнери продовжували працювати після виходу із системи.
* Створює `/etc/containers/nodocker`, що вимикає повідомлення "Emulate Docker CLI using podman".
* Завантажує модуль політики SELinux `podman_socket_clsi`, якщо `SELINUX_MODE=managed`.

Для вашого користувача:

* Вмикає службу користувача `podman.socket`, сумісний з Docker API, через який Ayakaleaf Pro запускає компіляцію.
* Встановлює Docker Compose v2 з GitHub у `~/.local/bin/docker-compose` і створює на нього посилання в `~/.docker/cli-plugins/`.
* Налаштовує Podman на використання цього Compose в `~/.config/containers/containers.conf`.
* Додає псевдоніми `mongo` і `redis` у `~/.config/containers/registries.conf.d/overleaf-toolkit.conf`, щоб Podman знав, звідки завантажувати образи з цими короткими назвами.

У Toolkit:

* Задає `DOCKER_SOCKET_PATH` і `DOCKER_HOST` у `config/overleaf.rc` значенням `/run/user/<uid>/podman/podman.sock`.
* Видобуває профіль seccomp для компіляції з образу Ayakaleaf Pro в `config/seccomp/<version>/clsi-profile.json` і задає `SECCOMP_PROFILE` у `config/variables.env`. На відміну від Docker, Podman потрібен цей профіль як файл на хості.
* Збирає модуль політики SELinux у `config/selinux/`.
* Призначає власників каталогів даних у `data/` за допомогою `podman unshare chown`, щойно вони з'являться.

<Info>

Кожній зміні відповідає перевірка. Якщо ви щось змінюєте вручну, наприклад у `config/overleaf.rc`, знову запустіть `bin/podman-setup`, щоб перевірити результат.

</Info>
