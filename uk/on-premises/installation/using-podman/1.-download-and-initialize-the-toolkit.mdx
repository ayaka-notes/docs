description: Клонуйте Ayakaleaf Toolkit, створіть конфігурацію та налаштуйте її для Ayakaleaf Pro на Podman.
icon: arrow-down-to-bracket
---

<Steps>
<Step title="Клонування Toolkit">
Клонуйте **Ayakaleaf Toolkit** ([ayaka-notes/toolkit](https://github.com/ayaka-notes/toolkit)) у домашній каталог і перейдіть до нього:

```bash title="Clone the Toolkit" wrap
git clone https://github.com/ayaka-notes/toolkit.git ~/overleaf-toolkit
cd ~/overleaf-toolkit
```

Виконуйте всі подальші команди з цього каталогу.
</Step>

<Step title="Створення конфігурації">
```bash title="Run initialization"
bin/init
```

Ця команда створює `config/overleaf.rc`, `config/variables.env` і `config/version`, як описано в кроці [3. Ініціалізація конфігурації](/uk/on-premises/installation/using-docker-compose/linux/3.-initialize-the-configuration) посібника з Docker. Для `bin/init` Podman поки не потрібен.
</Step>

<Step title="Налаштування config/overleaf.rc">
Відкрийте `config/overleaf.rc` і змініть ці рядки:

```bash title="config/overleaf.rc"
SERVER_PRO=true
OVERLEAF_PORT=8080
SIBLING_CONTAINERS_ENABLED=true
```

Потім додайте цей рядок у кінець файлу:

```bash title="config/overleaf.rc"
SELINUX_MODE=managed
```

| Параметр                          | Навіщо                                                                                                                                                                                                       |
| --------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `SERVER_PRO=true`                 | Використовує образ Ayakaleaf Pro з `ghcr.io`. Вхід до реєстру не потрібен.                                                                                                                                   |
| `OVERLEAF_PORT=8080`              | Rootless Podman не може слухати порти нижче `1024`. Типовий порт `80` не працює.                                                                                                                              |
| `SIBLING_CONTAINERS_ENABLED=true` | Запускає кожну компіляцію в окремому контейнері TeX Live. Типово вже `true`; налаштування Podman підтримує лише цей режим.                                                                                    |
| `SELINUX_MODE=managed`            | Запускає контейнер `sharelatex` з типом SELinux `sharelatex_t`, якому дозволено використовувати сокет Podman і нічого більше. `bin/podman-setup --apply` встановлює для нього модуль політики. Інші режими описано в розділі [Налаштування Toolkit](/uk/on-premises/configuration/overleaf-toolkit/toolkit-settings). |

Залиште `DOCKER_SOCKET_PATH` без змін: на наступному кроці `bin/podman-setup --apply` вкаже в ньому ваш сокет Podman.

<Warning>

Залиште `GIT_BRIDGE_ENABLED=false`. В Ayakaleaf Pro 6.3.4 інтеграція з Git на Podman не працює, див. [Відомі обмеження](/uk/on-premises/installation/using-podman#known-limitations).

</Warning>
</Step>

<Step title="Вибір образів TeX Live">
Відкрийте `config/variables.env`, видаліть `#` перед `TEX_LIVE_DOCKER_IMAGE` і `ALL_TEX_LIVE_DOCKER_IMAGES` та перелічіть образи TeX Live, які потрібно використовувати:

```bash title="config/variables.env" wrap
TEX_LIVE_DOCKER_IMAGE=ghcr.io/ayaka-notes/texlive-full:2026.1
ALL_TEX_LIVE_DOCKER_IMAGES=ghcr.io/ayaka-notes/texlive-full:2026.1
```

Якщо список порожній, `bin/up` зупиняється з повідомленням `Please configure ALL_TEX_LIVE_DOCKER_IMAGES`. Образ `texlive-full` великий; для тестового сервера підійде й набагато менший `ghcr.io/ayaka-notes/texlive-basic:2026.1`. Доступні образи перелічено в розділі [Ізольована компіляція](/uk/on-premises/configuration/overleaf-toolkit/sandboxed-compiles).

Задайте інші змінні, наприклад `OVERLEAF_SITE_URL`, як описано в кроці [5. Персоналізація вашого екземпляра](/uk/on-premises/installation/using-docker-compose/linux/5.-personalizing-your-instance#required-environment-variables). Із типовою адресою прослуховування використовуйте `http://localhost:8080`.
</Step>
</Steps>
