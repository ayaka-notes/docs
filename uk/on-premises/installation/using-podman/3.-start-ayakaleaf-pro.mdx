---
title: 3. Запуск Ayakaleaf Pro
description: Запустіть Ayakaleaf Pro на Podman, перевірте його за допомогою podman-setup і bin/doctor та налаштуйте запуск після перезавантаження.
icon: circle-play
---

<Steps>
<Step title="Запуск контейнерів">
```bash title="Start Ayakaleaf Pro"
bin/up -d
```

Під час першого запуску завантажуються образи MongoDB, Redis і TeX Live та створюються каталоги даних у `data/`. Виводиться попередження про те, що підтримка Podman експериментальна.

<Info>

Під час першого запуску також може з'явитися `MongoNetworkError: connect ECONNREFUSED 127.0.0.1:27017`. Toolkit налаштовує набір реплік MongoDB, поки MongoDB ще запускається, і повторює спроби, доки вона не відповість. Цей рядок можна ігнорувати.

</Info>

Через хвилину-дві переконайтеся, що контейнери працюють:

```bash title="List the containers"
podman ps --format "{{.Names}} {{.Status}}"
```

```text
mongo Up 34 seconds (healthy)
redis Up 20 seconds
sharelatex Up 20 seconds
```
</Step>

<Step title="Повторна перевірка налаштування">
Тепер, коли каталоги даних існують і контейнер `sharelatex` працює, `bin/podman-setup` може завершити свої перевірки:

```bash title="Check the setup"
bin/podman-setup
```

Скрипт перевіряє власників нових каталогів даних і тестує сокет Podman зсередини контейнера `sharelatex`:

```text
====== Socket Connectivity ======
[✓] host → socket OK
[✓] container → socket OK

====== Data Directory Permissions ======
[✓] mongo data dir owned by 999
[✓] redis data dir owned by 999
[✓] overleaf data dir owned by 33
...
====== Summary ======
[✓] 27 passed  [!] 1 warnings  [✗] 0 failures
[!] Warnings:
[!] not logged in to quay.io
```

`container → socket OK` означає, що Ayakaleaf Pro може запускати контейнери компіляції. Якщо перевірка не проходить, виконайте `bin/podman-setup --apply`, а потім `bin/up -d`. Попередження про quay.io не стосується Ayakaleaf Pro, див. [2. Запуск podman-setup](/uk/on-premises/installation/using-podman/2.-run-podman-setup).
</Step>

<Step title="Запуск doctor">
```bash title="Run the doctor"
bin/doctor
```

На Podman звіт показує середовище виконання та параметри безпеки:

```text
- Container Daemon
    - status: up
    - runtime: podman
    - server version: 5.8.5
    - socket: /run/user/1000/podman/podman.sock
    - DOCKER_HOST: unix:///run/user/1000/podman/podman.sock
    - host → socket: OK
    - container → socket: OK
- Security
    - SELinux: Enforcing
    - SELINUX_MODE: managed
    - SELINUX_LABEL: sharelatex_t
    - SELinux module: loaded (podman_socket_clsi)
    - SELinux rules: present
    - Seccomp profile: present
```

Попередження `Server Pro enabled, but not logged in to quay.io repository` наприкінці стосується тієї самої перевірки quay.io, див. [Отримання допомоги](/uk/on-premises/support/getting-help#q-and-a).
</Step>

<Step title="Запуск Ayakaleaf Pro після перезавантаження">
У Docker після перезавантаження контейнери знову запускає демон Docker. У rootless Podman немає демона: увімкніть службу користувача, яка запускає ваші контейнери під час завантаження сервера:

```bash title="Start the containers at boot"
systemctl --user enable podman-restart.service
```

Вона запускає всі контейнери вашого користувача з політикою перезапуску `always`, яку Toolkit задає для всіх своїх контейнерів. Для цього потрібен lingering, який увімкнув `bin/podman-setup --apply`. Без цієї служби виконуйте `bin/up -d` після кожного перезавантаження.
</Step>

<Step title="Відкриття порту в брандмауері">
Типово екземпляр приймає підключення лише із самого сервера, за адресою `http://localhost:8080`. Щоб відкрити його з інших комп'ютерів, задайте `OVERLEAF_LISTEN_IP` у `config/overleaf.rc` і `OVERLEAF_SITE_URL` у `config/variables.env`, як описано в кроці [5. Персоналізація вашого екземпляра](/uk/on-premises/installation/using-docker-compose/linux/5.-personalizing-your-instance#listen-address-and-port), і знову виконайте `bin/up -d`.

На відміну від Docker, rootless Podman не оминає брандмауер хоста. Якщо працює `firewalld`, що в RHEL типово, відкрийте порт:

```bash title="Open port 8080"
sudo firewall-cmd --permanent --add-port=8080/tcp
sudo firewall-cmd --reload
```

На хмарному сервері також дозвольте порт у групі безпеки провайдера. Перш ніж відкривати екземпляр в інтернет, налаштуйте HTTPS, див. [4. Завдання після встановлення](/uk/on-premises/installation/using-podman/4.-post-installation-tasks#use-https).
</Step>
</Steps>
