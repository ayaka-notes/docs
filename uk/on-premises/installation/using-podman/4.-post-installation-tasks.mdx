### Створення першого облікового запису адміністратора {#create-your-first-administrator-account}

Відкрийте [http://localhost:8080/launchpad](http://localhost:8080/launchpad) або ваш `OVERLEAF_SITE_URL` з `/launchpad` у кінці та зареєструйте обліковий запис адміністратора. Далі все працює так само, як з Docker: виконайте крок [6. Завдання після встановлення](/uk/on-premises/installation/using-docker-compose/linux/6.-post-installation-tasks) посібника з Docker, використовуючи порт `8080` у його посиланнях на `localhost`.

Створіть приклад проєкту та скомпілюйте його. Поява PDF показує, що компіляція виконується в контейнерах TeX Live через Podman. Щоб побачити контейнер компіляції:

```bash title="List the compile containers"
podman ps -a --filter name=project- --format "{{.Names}} {{.Image}} {{.Status}}"
```

### Використання HTTPS {#use-https}

[TLS-проксі](/uk/on-premises/configuration/overleaf-toolkit/tls-proxy) з Toolkit працює на Podman: виконайте `bin/init --tls`, укажіть сертифікат і `NGINX_ENABLED=true`, як там описано. Проксі слухає порти `80` і `443`, які rootless Podman типово використовувати не може. Дозвольте непривілейованим користувачам використовувати порти починаючи з `80`:

```bash title="Allow ports 80 and 443"
echo "net.ipv4.ip_unprivileged_port_start=80" | sudo tee /etc/sysctl.d/99-unprivileged-ports.conf
sudo sysctl --system
```

Це дозволяє будь-якому користувачу сервера слухати ці порти, тому робіть так лише на сервері, виділеному під Ayakaleaf Pro. Потім відкрийте їх у брандмауері:

```bash title="Open ports 80 and 443"
sudo firewall-cmd --permanent --add-port=80/tcp --add-port=443/tcp
sudo firewall-cmd --reload
```

Задайте в `OVERLEAF_SITE_URL` вашу адресу `https://` і виконайте `bin/up -d`. Залиште типові значення `NGINX_HTTP_PORT=80` і `TLS_PORT=443`: з іншими портами переспрямування з HTTP на HTTPS веде на неправильний порт.

<Info>

Під час використання TLS-проксі залиште `OVERLEAF_LISTEN_IP` зі значенням `127.0.0.1`, щоб порт `8080` був недоступний з інших комп'ютерів.

</Info>

### Оновлення {#upgrade}

Оновлюйте екземпляр за допомогою `bin/upgrade`, як описано в розділі [Оновлення розгортання](/uk/on-premises/maintenance/upgrading-your-deployment). На Podman ця команда також видобуває профіль seccomp нової версії в `config/seccomp/<version>/` і оновлює `SECCOMP_PROFILE`:

```text
Over-writing config/version with 6.3.4
Set SECCOMP_PROFILE=/home/<user>/overleaf-toolkit/config/seccomp/6.3.4/clsi-profile.json in config/variables.env
```

Після оновлення виконайте `bin/podman-setup`, щоб перевірити налаштування.

### Зміна режиму SELinux {#change-the-selinux-mode}

`SELINUX_MODE` у `config/overleaf.rc` визначає, як SELinux обмежує контейнер `sharelatex`. На цих сторінках налаштовується режим `managed`; інші режими описано в розділі [Налаштування Toolkit](/uk/on-premises/configuration/overleaf-toolkit/toolkit-settings). Після зміни виконайте `bin/up -d`.
