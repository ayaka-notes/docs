Ayakaleaf Pro використовує Linux-контейнери. У Windows встановіть Docker Desktop з бекендом WSL 2 і запускайте скрипти Toolkit в Ubuntu.

WSL 2 надає ядро Linux. Docker Desktop керує рушієм Docker у власному середовищі `docker-desktop`; увімкнення **WSL Integration** дає змогу Docker CLI в Ubuntu звертатися до цього рушія. Потім Toolkit запускає застосунок, MongoDB і Redis як контейнери. Коли ізольовану компіляцію ввімкнено, застосунок використовує сокет Docker рушія, щоб запускати окремий контейнер TeX Live для кожної компіляції. Встановлювати MongoDB, Redis чи TeX Live у Windows не потрібно.

<Steps>
<Step title="Встановіть WSL 2 і Ubuntu">
Відкрийте у Windows **PowerShell від імені адміністратора** і виконайте:

```powershell
wsl --install -d Ubuntu
```

Перезавантажте Windows, якщо з'явиться відповідний запит. Відкрийте **Ubuntu** з меню «Пуск» і створіть ім'я користувача та пароль Linux. Це обліковий запис для `sudo` всередині Ubuntu; він не пов'язаний із вашим входом у Windows.

Поверніться до **PowerShell**, оновіть WSL і перевірте дистрибутив:

```powershell
wsl --update
wsl --version
wsl --list --verbose
```

Рядок Ubuntu має показувати **VERSION 2**. Якщо там 1, використайте точну назву дистрибутива зі списку:

```powershell
wsl --set-version Ubuntu 2
```

Docker потребує WSL **2.1.5 або новішої**; версія програмного забезпечення WSL з `wsl --version` і стовпець **VERSION 2** дистрибутива — це різні перевірки. Якщо встановлення не вдається, див. [усунення несправностей встановлення](/uk/on-premises/installation/using-docker-compose/windows/troubleshooting#wsl-or-docker-reports-that-virtualization-is-unavailable) та [інструкції зі встановлення від Microsoft](https://learn.microsoft.com/en-us/windows/wsl/install), а якщо WSL повідомляє, що апаратна віртуалізація недоступна, увімкніть її в BIOS/UEFI.
</Step>

<Step title="Встановіть і запустіть Docker Desktop">
Завантажте [Docker Desktop for Windows](https://docs.docker.com/desktop/setup/install/windows-install/) для свого процесора й запустіть інсталятор. Якщо буде запропоновано, використовуйте бекенд **WSL 2**. Відкрийте **Docker Desktop** з меню «Пуск» Windows і дочекайтеся запуску рушія.

У **Settings → General** Docker Desktop увімкніть **Use WSL 2 based engine**, якщо цей параметр показано. У **Settings → Resources → WSL Integration** увімкніть інтеграцію для **Ubuntu**, а потім виберіть **Apply** або **Apply & restart**. Якщо Ubuntu не є вашим дистрибутивом за замовчуванням, явно ввімкніть його власний перемикач.

Якщо WSL Integration відсутній, перевірте, що Docker Desktop використовує **Linux containers**. Див. [посібник Docker щодо бекенда WSL 2](https://docs.docker.com/desktop/features/wsl/).

Для цього посібника використовуйте інтеграцію Docker Desktop. Встановлення другого Docker Engine за допомогою `apt install docker.io` або запуск `dockerd` всередині Ubuntu створює окреме налаштування і може спричинити конфлікти. Якщо ви вже використовуєте Engine в Ubuntu, перед перемиканням дотримуйтеся рекомендацій Docker щодо міграції; збережіть наявні дані застосунків і резервні копії.
</Step>

<Step title="Перевірте Docker з Ubuntu">
Відкрийте термінал **Ubuntu**. Виконайте там ці команди без `sudo`:

```bash
docker version
docker compose version
docker ps
```

`docker version` має показати і **Client**, і **Server**. Порожній список контейнерів — це нормально для нової інсталяції. Сама лише команда `docker --version` не доводить, що рушій працює.

Якщо `docker` недоступний або не може підключитися, знову відкрийте Ubuntu після застосування WSL Integration і перевірте, що Docker Desktop запущено. Див. [Усунення несправностей](/uk/on-premises/installation/using-docker-compose/windows/troubleshooting#docker-is-unavailable-in-ubuntu).
</Step>

<Step title="Перевірте ресурси та сокет Docker">
Перевірте ресурси, видимі для Docker:

```bash
docker info --format 'CPUs={{.NCPU}} Memory={{.MemTotal}} Kernel={{.KernelVersion}}'
df -h "$HOME"
ls -l /var/run/docker.sock
```

Для невеликого локального екземпляра 4 CPU і 8 ГБ пам'яті, доступні Docker, — це рекомендована відправна точка, а не виміряний мінімум. Залиште достатньо пам'яті й для Windows. З бекендом WSL 2 ліміти ресурсів керуються через [налаштування WSL](https://learn.microsoft.com/en-us/windows/wsl/wsl-config), а не через повзунки ресурсів Docker Desktop, як на Mac. Зміни, які потребують `wsl --shutdown`, переривають роботу всіх запущених дистрибутивів WSL і навантажень Docker; застосуйте їх перед запуском екземпляра.

Залиште `DOCKER_SOCKET_PATH=/var/run/docker.sock` у конфігурації Toolkit. Застосунку потрібен цей сокет рушія для ізольованої компіляції. Не змінюйте його дозволи на `777`, щоб виправити помилки з'єднання; натомість відновіть інтеграцію Docker Desktop.
</Step>
</Steps>
