### Створення адміністратора та першого проєкту {#create-the-administrator-and-a-first-project}

Відкрийте [http://localhost:8080/launchpad](http://localhost:8080/launchpad), створіть перший обліковий запис адміністратора та увійдіть. Потім виконайте кроки з розділу [6. Завдання після встановлення](/uk/on-premises/installation/using-docker-compose/linux/6.-post-installation-tasks) посібника для Linux, використовуючи порт `8080` у прикладах URL.

### Перевірка компіляції {#verify-compilation}

Те, що сторінка входу відкривається, ще не доводить, що окремі контейнери компілятора та їхні підключені дані працюють. Створіть порожній проєкт і скомпілюйте цей `main.tex`:

```latex
\documentclass{article}
\begin{document}
Ayakaleaf Pro on macOS.
\end{document}
```

Попередній перегляд PDF має показати текст. За потреби виберіть TeX Live 2026 у налаштуваннях проєкту.

Для проєкту з китайським текстом виберіть компілятор **XeLaTeX** і перевірте:

```latex
\documentclass{ctexart}
\begin{document}
你好，Ayakaleaf Pro。
\end{document}
```

### Перевірка збереження даних {#verify-persistence}

```bash
bin/stop
bin/start
```

Знову відкрийте проєкт і скомпілюйте його ще раз. Ваш обліковий запис, вихідний код і файли проєкту мають залишитися на місці. Зі шляхами за замовчуванням робочі дані зберігаються в каталозі `data/` Toolkit на вашому Mac.

### Підтримання доступності екземпляра {#keep-the-instance-available}

Поки Mac перебуває в режимі сну, macOS призупиняє віртуальну машину Docker Desktop разом з усіма її контейнерами: ніхто не може відкрити екземпляр, а компіляція, що виконується, зупиняється, доки Mac не прокинеться. Важить лише режим сну системи. Дисплей може вимикатися.

Якщо екземпляром користуються інші люди або ви залишаєте тривалі завдання, тримайте Mac підключеним до живлення й забороніть автоматичний перехід у режим сну, див. [Set sleep and wake settings for your Mac](https://support.apple.com/guide/mac-help/set-sleep-and-wake-settings-mchle41a6ccd/mac):

| Mac | Налаштування |
| --- | --- |
| Настільний Mac (Mac mini, iMac, Mac Studio, Mac Pro) | **System Settings → Energy**: увімкніть **Prevent automatic sleeping when the display is off** |
| MacBook | **System Settings → Battery → Options**: увімкніть **Prevent automatic sleeping on power adapter when the display is off**. Це діє лише тоді, коли підключено адаптер живлення, а закриття кришки все одно переводить MacBook у режим сну |

Щоб Mac не засинав лише певний час, натомість виконайте `caffeinate -i` у вікні Terminal. Ця команда запобігає переходу в режим сну через бездіяльність, доки ви не натиснете `Ctrl+C` або не закриєте вікно.

Docker Desktop — це застосунок у вашому сеансі користувача. Щоб екземпляр знову запрацював після перезавантаження, увімкніть **Start Docker Desktop when you sign in to your computer** у **Settings → General** Docker Desktop. Контейнери Toolkit використовують `restart: always`, тож Docker знову запускає їх, щойно Docker Desktop працює, без `bin/up`. Доки після перезавантаження хтось не ввійде в Mac, екземпляр залишається недоступним.

<Info>

Mac, який не засинає, споживає більше енергії. Для сервісу, який має бути доступним завжди, ми рекомендуємо Linux-сервер, див. [Linux](/uk/on-premises/installation/using-docker-compose/linux).

</Info>

### Щоденне використання {#daily-use}

Відкрийте Docker Desktop, перш ніж керувати екземпляром. У новому терміналі:

```bash
export PATH="$(brew --prefix gnu-sed)/libexec/gnubin:$PATH"
cd "$HOME/ayakaleaf-toolkit"
```

| Завдання | Команда |
| --- | --- |
| Запустити наявні контейнери | `bin/start` |
| Зупинити контейнери й зберегти дані | `bin/stop` |
| Застосувати зміни конфігурації | `bin/up -d` |
| Перевірити стан | `bin/docker-compose ps` |
| Переглянути журнали запуску | `bin/docker-compose logs --tail=100 sharelatex` |
| Переглянути журнали компілятора | `bin/logs -f clsi` |

`bin/start` не застосовує зміни в `config/`: після редагування конфігурації виконайте `bin/up -d`. Зберігайте `config/` і `data/` та дотримуйтеся інструкцій з розділу [Дані та резервні копії](/uk/on-premises/maintenance/data-and-backups) перед оновленням або перенесенням інсталяції. Копіювання файлів бази даних, поки MongoDB у них записує, не є узгодженою резервною копією.

Для локального використання залишайте екземпляр на `127.0.0.1`. Щоб обслуговувати інші комп'ютери, свідомо налаштуйте адресу прослуховування, URL сайту та HTTPS, див. [5. Персоналізація вашого екземпляра](/uk/on-premises/installation/using-docker-compose/linux/5.-personalizing-your-instance) посібника для Linux.

Якщо щось не працює, див. [Усунення несправностей](/uk/on-premises/installation/using-docker-compose/macos/troubleshooting).
