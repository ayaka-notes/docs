<Steps>
<Step title="Налаштування контейнера">
Відредагуйте ці наявні записи в `config/overleaf.rc`:

```bash title="config/overleaf.rc"
PROJECT_NAME=ayakaleaf-macos
SERVER_PRO=true
OVERLEAF_LISTEN_IP=127.0.0.1
OVERLEAF_PORT=8080
SIBLING_CONTAINERS_ENABLED=true
DOCKER_SOCKET_PATH=/var/run/docker.sock
```

Залиште шляхи до даних за замовчуванням і вбудовані сервіси MongoDB та Redis. З `OVERLEAF_LISTEN_IP=127.0.0.1` відкрити екземпляр можуть лише браузери на цьому Mac.
</Step>

<Step title="Налаштування застосунку">
У `config/variables.env` задайте ці значення, замінивши всі активні записи з такими самими назвами:

```dotenv title="config/variables.env"
OVERLEAF_SITE_URL=http://localhost:8080
TEX_LIVE_DOCKER_IMAGE=ghcr.io/ayaka-notes/texlive-full:2026.1
ALL_TEX_LIVE_DOCKER_IMAGES=ghcr.io/ayaka-notes/texlive-full:2026.1
ALL_TEX_LIVE_DOCKER_IMAGE_NAMES="TeX Live 2026"
```

Згенеруйте секрет сеансу:

```bash
openssl rand -hex 32
```

Додайте результат як `OVERLEAF_SESSION_SECRET` у `config/variables.env`. Без нього кожен `bin/up`, що перестворює контейнер, виводить із системи всіх користувачів, див. [Змінні середовища](/uk/on-premises/configuration/overleaf-toolkit/environment-variables).

Для локального екземпляра без електронної пошти не задавайте налаштування SMTP та `OVERLEAF_EMAIL_FROM_ADDRESS`. Git Bridge, зовнішню автентифікацію та інші інтеграції можна додати пізніше за допомогою відповідних [сторінок конфігурації](/uk/on-premises/configuration/overleaf-toolkit).
</Step>

<Step id="check-the-docker-vms-linux-kernel" title="Перевірте ядро Linux віртуальної машини Docker">
MongoDB працює на ядрі Linux віртуальної машини Docker Desktop, а не на macOS. Перевірте його версію перед першим запуском:

```bash
docker info --format '{{.KernelVersion}}'
```

MongoDB документує несумісність з ядрами Linux **від 6.19 до 7.0.13**, яка стосується й MongoDB у Docker. Виправленням є ядро **7.0.14 або новіше**, яке постачається з оновленням Docker Desktop, див. [примітки MongoDB щодо продакшн-середовища](https://www.mongodb.com/docs/manual/administration/production-notes/).

Якщо ваша віртуальна машина Docker використовує уражене ядро, додайте наведене нижче до `config/docker-compose.override.yml`, об'єднавши з наявними там `services`:

```yaml title="config/docker-compose.override.yml"
services:
  mongo:
    environment:
      GLIBC_TUNABLES: glibc.pthread.rseq=1
```

<Warning>

Оновіться до виправленого ядра, щойно воно стане доступним. Якщо ваше ядро поза ураженим діапазоном, цей обхідний шлях не потрібен.

</Warning>
</Step>

<Step title="Запустіть свій екземпляр">
У каталозі Toolkit виконайте:

```bash
bin/up -d
```

Toolkit ініціалізує набір реплік MongoDB, завантажує образ TeX Live і запускає застосунок. Перше завантаження триває деякий час. Щоб стежити за перебігом:

```bash
bin/docker-compose ps
bin/docker-compose logs --tail=100 -f sharelatex
```

Натисніть `Ctrl+C`, щоб припинити стежити за журналами. Контейнери продовжать працювати.

Перевірте опублікований порт і сторінку першого запуску:

```bash
bin/docker-compose port sharelatex 80
curl -I http://localhost:8080/launchpad
```

Порт має бути `127.0.0.1:8080`.
</Step>
</Steps>

<Info>

Щоб пізніше відкрити екземпляр з інших комп'ютерів, змініть адресу прослуховування та URL сайту й налаштуйте HTTPS, як описано в розділі [5. Персоналізація вашого екземпляра](/uk/on-premises/installation/using-docker-compose/linux/5.-personalizing-your-instance) посібника для Linux. Тоді Mac має залишатися активним, див. [Підтримання доступності екземпляра](/uk/on-premises/installation/using-docker-compose/macos/6.-post-installation-tasks#keep-the-instance-available).

</Info>
