### Апаратні вимоги {#hardware-requirements}

Ми провели відповідні тести й з'ясували, що якщо запускати Overleaf на сервері з 2 ядрами та 2 ГБ RAM, його основні компоненти — переважно на основі Node.js — споживатимуть приблизно 1 ГБ пам'яті. Redis і MongoDB можуть потребувати ще 0,5 ГБ, а запуск ізольованого Docker-контейнера для компіляції може споживати ще 0,3 ГБ. Це означає, що сервер із 2 ядрами та 2 ГБ реально здатен обробляти лише приблизно одну одночасну компіляцію.

* Мінімальні апаратні вимоги для встановлення Ayakaleaf Pro — 2-ядерний CPU та 3 ГБ RAM.
* Через розмір нашого образу TeX Live для ввімкнення ізольованої компіляції потрібно щонайменше 40 ГБ дискового простору.
* Якщо ви хочете встановити повний набір образів TeX Live з 2020 по 2026 рік, переконайтеся, що маєте щонайменше 150 ГБ вільного місця на диску.

Ось кілька рекомендованих апаратних конфігурацій для різних сценаріїв використання:

| Сценарій використання                                             | Рекомендована конфігурація                                                                            |
| ---------------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| Особисте використання з епізодичною співпрацею          | 2 ядра CPU, 4 ГБ RAM, 80 ГБ сховища                                                                 |
| Невеликі команди, до 10 користувачів з легкою співпрацею | 2 ядра CPU, 8 ГБ RAM, 256 ГБ сховища                                                                |
| Команди середнього розміру, до 100 користувачів                  | 4 ядра CPU, 16 ГБ RAM, 1 ТБ сховища                                                                 |
| Великомасштабні або університетські розгортання                | Розподілене кластерне розгортання зі сховищем S3; зв'яжіться з нами, якщо потрібна допомога з розгортанням |

### Програмні вимоги {#software-requirements}

Щодо програмного забезпечення, рекомендуємо використовувати свіжу й стабільну версію Ubuntu (наприклад, Ubuntu 24.04 у 2025–2026 роках, Ubuntu 22.04 у 2023–2024 роках) разом з останньою стабільною версією Docker.

<Info>

Ubuntu 26.04 постачається з ядром Linux 7.0, а MongoDB відмовляється запускатися на ядрах Linux від 6.19 до 7.0.13 ([подробиці](https://www.mongodb.com/docs/manual/administration/production-notes/)). Щоб працювати на цих ядрах, додайте наведене нижче до сервісу `mongo` у файлі `overleaf-toolkit/config/docker-compose.override.yml` (у тому самому файлі, де задається образ Ayakaleaf Pro). Наш CI працює на Ubuntu 26.04 із цим налаштуванням. Ядрам 7.0.14 і новішим воно не потрібне.

```yml title="docker-compose.override.yml"
services:
    mongo:
        environment:
            GLIBC_TUNABLES: glibc.pthread.rseq=1
```

</Info>

Для спільних і продакшн-серверів ми рекомендуємо Linux. Ви також можете запустити Ayakaleaf Pro на [macOS](/uk/on-premises/installation/using-docker-compose/macos) або [Windows з WSL 2](/uk/on-premises/installation/using-docker-compose/windows) за допомогою Docker Desktop. Дотримуйтеся посібника для своєї платформи. Образи підтримують як AMD64, так і ARM64.

### Продуктивність LaTeX {#latex-performance}

LaTeX — однопотокова програма, тобто вона може одночасно використовувати лише одне ядро CPU. Під час компіляції одного документа продуктивність переважно обмежена тактовою частотою одного ядра CPU. Тому що вища одноядерна продуктивність вашого CPU, то швидше компілюватиметься документ. Більша кількість ядер CPU корисна лише тоді, коли кілька користувачів компілюють документи одночасно.

Наприклад, для [шаблону ThuThesis](https://www.overleaf.com/latex/templates/thuthesis-tsinghua-university-thesis-latex-template/cfwgcxtvkbsx) час компіляції становить близько 6 секунд на Intel Core i9-14900K (5,6 ГГц), тоді як на інстансі Azure Standard D2as v5 (2 vCPU, 8 GiB RAM) з процесором AMD EPYC 7763 (3,2 ГГц) він займає близько 13 секунд.

Звісно, реальна продуктивність компіляції залежить від вашої апаратної конфігурації. Більшість серверних CPU не працюють на таких високих частотах, як 14900K, тож доведеться шукати компроміс між вартістю та швидкістю компіляції.

Крім того, ми провели поглиблений аналіз продуктивності компіляції LaTeX. Якщо вам цікаво, зверніться до нашого блогу [Overleaf Benchmark: A Deep Research of Concurrent LaTeX Compilation in Overleaf (SaaS and Self-host)](/uk/blog/2026/overleaf-benchmark  "mention").
