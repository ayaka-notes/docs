Як і Overleaf Server Pro, наш Ayakaleaf Pro постачається у вигляді Docker-контейнера та є прямою заміною, яка додатково містить такі функції, як SSO через LDAP і SAML2, покращена безпека, відстеження змін, коментарі, наша оптимізована версія TeX Live, шаблони та панель адміністрування.

* Якщо ви лише хочете випробувати функції Ayakaleaf Pro або спробувати демоверсію, скористайтеся посібником [using-the-github-codespace.md](/uk/on-premises/installation/using-the-github-codespace  "mention"). Демосередовище використовує мінімальну інсталяцію TeX Live, тому деякі ваші проєкти можуть не скомпілюватися.
* Якщо ви ніколи раніше не розгортали жодної версії Overleaf, спершу зверніться до розділу [Налаштування Docker](/uk/on-premises/installation/setup-docker), щоб установити Docker Engine, а потім установіть Overleaf [using-the-toolkit](/uk/on-premises/installation/using-the-toolkit  "mention").
* Якщо ви вже розгорнули Community Edition Overleaf, зверніться до [migrate-from-existing.md](/uk/on-premises/installation/migrate-from-existing  "mention"), щоб перейти на Ayakaleaf Pro.
* Якщо ви віддаєте перевагу агентам на кшталт Claude чи Codex, див.: [using-claude-or-codex.md](/uk/on-premises/installation/using-claude-or-codex  "mention").
* Якщо вам потрібно розгорнути систему в офлайн- або ізольованому середовищі, див.: [air-gapped-offline-deployments.md](/uk/on-premises/installation/air-gapped-offline-deployments  "mention").
* Якщо ви вже користуєтеся Server Pro, перед переходом на Ayakaleaf Pro створіть issue, щоб повідомити нас, оскільки дані шаблонів зберігаються в дещо іншому форматі. Ми з радістю безплатно допоможемо вам перейти із Server Pro на Ayakaleaf Pro.
* Якщо вам колись набридне наш Ayakaleaf Pro і ви захочете повернутися до офіційної Overleaf Community Edition, це повністю підтримується. Жодні ваші дані не буде втрачено. Користувачам офіційного Overleaf Toolkit достатньо видалити свій override YAML-файл. Користувачам ayaka-notes toolkit потрібно вимкнути параметр `SERVER_PRO`. Після цього все повернеться до стандартної Community Edition.

### Апаратні вимоги

Ми провели відповідні тести й з'ясували, що якщо запускати Overleaf на сервері з 2 ядрами та 2 ГБ RAM, його основні компоненти — переважно на основі Node.js — споживатимуть приблизно 1 ГБ пам'яті. Redis і MongoDB можуть потребувати ще 0,5 ГБ, а запуск ізольованого Docker-контейнера для компіляції може споживати ще 0,3 ГБ. Це означає, що сервер із 2 ядрами та 2 ГБ реально здатен обробляти лише приблизно одну одночасну компіляцію.

* Мінімальні апаратні вимоги для встановлення Ayakaleaf Pro — 2-ядерний CPU та 3 ГБ RAM.
* Через розмір нашого образу TeX Live для ввімкнення ізольованої компіляції потрібно щонайменше 40 ГБ дискового простору.
* Якщо ви хочете встановити повний набір образів TeX Live з 2020 по 2026 рік, переконайтеся, що маєте щонайменше 150 ГБ вільного місця на диску.

Ось кілька рекомендованих апаратних конфігурацій для різних сценаріїв використання:

| Сценарій використання                                             | Рекомендована конфігурація                                                                            |
| ---------------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| Особисте використання з епізодичною співпрацею          | 2 ядра CPU, 4 ГБ RAM, 80 ГБ сховища                                                                 |
| Невеликі команди, до 10 користувачів з легкою співпрацею | 2 ядра CPU, 8 ГБ RAM, 256 ГБ сховища                                                                |
| Команди середнього розміру, до 100 користувачів                  | 4 ядра CPU, 16 ГБ RAM, 1 ТБ сховища                                                                 |
| Великомасштабні або університетські розгортання                | Розподілене кластерне розгортання зі сховищем S3; зв'яжіться з нами, якщо потрібна допомога з розгортанням |

### Програмні вимоги

Щодо програмного забезпечення, рекомендуємо використовувати свіжу й стабільну версію Ubuntu (наприклад, Ubuntu 24.04 у 2025–2026 роках, Ubuntu 22.04 у 2023–2024 роках) разом з останньою стабільною версією Docker.

<Info>

Стабільність понад усе: вибирайте найновішу Ubuntu LTS, яка вийшла вже деякий час тому, а не щойно випущену. Наприклад, станом на жовтень 2026 року Ubuntu 26.04 не підтримується: вона постачається з ядром Linux 7.0, а MongoDB відмовляється запускатися на ядрах Linux від 6.19 до 7.0.13 ([подробиці](https://www.mongodb.com/docs/manual/administration/production-notes/)), тому використовуйте Ubuntu 24.04.

</Info>

Ми не рекомендуємо розгортати Ayakaleaf Pro у Windows або інших непідтримуваних операційних системах, як-от CentOS, оскільки під час встановлення та роботи можуть виникнути проблеми сумісності чи інші неочікувані проблеми.

Але якщо ви хочете спробувати розгорнути Ayakaleaf Pro на системах з архітектурою ARM або на macOS, запрошуємо поділитися своїм досвідом і відгуками зі спільнотою.

### Продуктивність LaTeX

LaTeX — однопотокова програма, тобто вона може одночасно використовувати лише одне ядро CPU. Під час компіляції одного документа продуктивність переважно обмежена тактовою частотою одного ядра CPU. Тому що вища одноядерна продуктивність вашого CPU, то швидше компілюватиметься документ. Більша кількість ядер CPU корисна лише тоді, коли кілька користувачів компілюють документи одночасно.

Наприклад, для [шаблону ThuThesis](https://www.overleaf.com/latex/templates/thuthesis-tsinghua-university-thesis-latex-template/cfwgcxtvkbsx) час компіляції становить близько 6 секунд на Intel Core i9-14900K (5,6 ГГц), тоді як на інстансі Azure Standard D2as v5 (2 vCPU, 8 GiB RAM) з процесором AMD EPYC 7763 (3,2 ГГц) він займає близько 13 секунд.

Звісно, реальна продуктивність компіляції залежить від вашої апаратної конфігурації. Більшість серверних CPU не працюють на таких високих частотах, як 14900K, тож доведеться шукати компроміс між вартістю та швидкістю компіляції.

Крім того, ми провели поглиблений аналіз продуктивності компіляції LaTeX. Якщо вам цікаво, зверніться до нашого блогу [Overleaf Benchmark: A Deep Research of Concurrent LaTeX Compilation in Overleaf (SaaS and Self-host)](/uk/blog/2026/overleaf-benchmark  "mention").
