### Створення першого облікового запису адміністратора {#creating-your-first-administrator-account}

Відкрийте `OVERLEAF_SITE_URL` з `/launchpad` у кінці, наприклад `http://192.0.2.10:30080/launchpad`, і зареєструйте обліковий запис адміністратора, як описано в розділі [Завдання після встановлення для Toolkit](/uk/on-premises/installation/using-docker-compose/linux/6.-post-installation-tasks). Потім створіть приклад проєкту та скомпілюйте його.

Користувачів також можна створювати з командного рядка:

```bash
kubectl -n overleaf exec deploy/overleaf -- bash -c \
  'cd /overleaf/services/web && node modules/server-ce-scripts/scripts/create-user.mjs --admin --email=admin@example.com'
```

Команда виводить посилання для встановлення пароля.

### Перевірка того, що компіляції ізольовані {#checking-that-compiles-are-sandboxed}

Скомпілюйте проєкт, а потім перегляньте вузол, на якому працює под:

```bash
kubectl -n overleaf get pod -l app=overleaf -o wide   # NODE column
# on that node:
sudo docker ps -a --filter ancestor=ghcr.io/ayaka-notes/texlive-full:2026.1
ls -ln /srv/overleaf/compiles                          # owned by uid 33 (www-data)
```

Кожна компіляція відображається як короткочасний контейнер з іменем `project-<project id>-<user id>-...`.

### Журнали та оболонка {#logs-and-a-shell}

| Toolkit          | Kubernetes                                                               |
| ---------------- | ------------------------------------------------------------------------ |
| `bin/logs web`   | `kubectl -n overleaf exec deploy/overleaf -- tail -f /var/log/overleaf/web.log` |
| `bin/shell`      | `kubectl -n overleaf exec -it deploy/overleaf -- bash`                    |
| `bin/up`         | `kubectl apply -f .`, потім `kubectl -n overleaf rollout restart deployment/overleaf` |

Контейнер записує по одному файлу журналу на службу в `/var/log/overleaf/` (`web.log`, `clsi.log`, `real-time.log`, `document-updater.log`, ...); `kubectl logs` показує вивід під час запуску.
