Kubernetes запускає ті самі образи, що й Toolkit. Окремого образу для Kubernetes немає.

| Образ                                                | Використовується                                                        |
| ---------------------------------------------------- | ----------------------------------------------------------------------- |
| `ghcr.io/ayaka-notes/overleaf-pro:6.3.2`             | Deployment `overleaf`                                                   |
| `ghcr.io/ayaka-notes/overleaf-pro/git-bridge:6.3.2`  | [Інтеграцією з Git](/uk/on-premises/configuration/kubernetes/integrations/git-integration) (необов'язково), той самий тег, що й вище |
| `ghcr.io/ayaka-notes/texlive-*`                      | компіляціями; завантажуються в Docker на вузлах на [кроці 0](/uk/on-premises/installation/using-kubernetes/0.-prepare-the-nodes) |

Образи публічно доступні на [ghcr.io](https://github.com/ayaka-notes/ayakaleaf-pro/pkgs/container/overleaf-pro/) для amd64 і arm64, тож kubelet може завантажувати їх без облікових даних.

<Warning>

Завжди використовуйте тег версії, наприклад `6.3.2`, а не `latest`. Оновлення виконують міграції бази даних і мають відбуватися згідно з розділом [Оновлення в Kubernetes](/uk/on-premises/maintenance/upgrading-on-kubernetes); тег, що змінюється, оновлював би под щоразу, коли його переплановують.

</Warning>

### Q\&A

<Accordion title="Наші вузли не мають доступу до ghcr.io. Що робити?">

<strong>Відповідь:</strong> Скопіюйте образи в реєстр, доступний вузлам, і використовуйте це ім'я в маніфестах, наприклад:

```bash
docker pull ghcr.io/ayaka-notes/overleaf-pro:6.3.2
docker tag ghcr.io/ayaka-notes/overleaf-pro:6.3.2 registry.example.com/ayakaleaf/overleaf-pro:6.3.2
docker push registry.example.com/ayakaleaf/overleaf-pro:6.3.2
```

Для реєстру без TLS containerd потребує на кожному вузлі файл `/etc/containerd/certs.d/<registry>/hosts.toml` із `server = "http://<registry>"`, а також `config_path`, налаштованого як на [кроці 0](/uk/on-premises/installation/using-kubernetes/0.-prepare-the-nodes). Сам Docker виконує push через звичайний HTTP лише на `localhost`, тож надсилайте через `localhost:<port>` на хості реєстру або додайте його до `insecure-registries`.

</Accordion>
