Гостьовий доступ до спільних проєктів, публічні сторінки та самостійна реєстрація вмикаються змінними середовища, які зчитує служба **web**; служба real-time потім обслуговує гостей через їхню сесію. Що відкриває кожен перемикач, описано в розділі [Публічний доступ](/uk/on-premises/configuration/overleaf-toolkit/authentication/public-access).

| | |
| --- | --- |
| Служба | web (і real-time для гостей у редакторі), у кожному поді Ayakaleaf Pro; зчитується під час запуску web |
| Под → зовні | сервер SMTP, коли реєстрація надсилає листи активації |
| Стан | токени гостьового доступу в сесії, обмеження частоти реєстрації в Redis |
| Періодичні завдання | немає |

### Конфігурація

Додайте потрібні перемикачі до ConfigMap `overleaf-env`:

```yaml title="30-config.yaml (additions)"
  # Guests open link-shared projects without an account
  OVERLEAF_ALLOW_ANONYMOUS_READ_AND_WRITE_SHARING: "true"
  # Signed-out visitors may open /learn, /templates, /devs and view links
  OVERLEAF_ALLOW_PUBLIC_ACCESS: "true"
  # Self-registration: "true", or only some domains
  OVERLEAF_ALLOW_PUBLIC_REGISTRATION: "@example.com, @*.uni.example"
```

```bash
kubectl apply -f 30-config.yaml
kubectl -n overleaf rollout restart deployment/overleaf     # or statefulset/overleaf
```

Беріть у лапки кожне значення. Значення, що починаються з `@`, у YAML обов'язково мають бути в лапках, інакше `kubectl apply` відхиляє файл.

Реєстрація, обмежена доменами, надсилає лист активації, тож [Доставка електронної пошти](/uk/on-premises/configuration/kubernetes/email-delivery) має працювати з подів: додайте хост SMTP до ConfigMap, а `OVERLEAF_EMAIL_SMTP_PASS` — до Secret.

### Кілька реплік

Нічого додаткового. Доступ гостя до проєкту зберігається в сесії в Redis, тож редактор працює на будь-якій репліці, яку обере балансувальник навантаження.

### Перевірено в Kubernetes

У Kubernetes 1.37 наші наскрізні тести публічного доступу проходять: на одній репліці — самостійна реєстрація з `OVERLEAF_ALLOW_PUBLIC_REGISTRATION`, встановленим у `true`, в один домен, у кілька доменів із шаблоном піддоменів і в `@*`, з листом активації для режимів із доменами (43 випадки); відвідувачі без входу на `/devs` і надісланий фрагмент, що зберігається під час входу, з `OVERLEAF_ALLOW_PUBLIC_ACCESS` (2 випадки); гість без входу в проєкті, спільному за посиланням, з обома ввімкненими перемикачами (3 випадки); а на трьох репліках за HAProxy — OIDC разом із публічним доступом (1 випадок).
