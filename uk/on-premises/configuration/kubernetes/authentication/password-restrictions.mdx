Служба **web** перевіряє локальні паролі, коли користувачі реєструються, задають або змінюють пароль. Входу через SSO (LDAP, SAML, OIDC) це не стосується; їхні паролі — справа постачальника ідентифікації. Про Toolkit див. [Обмеження паролів](/uk/on-premises/configuration/overleaf-toolkit/authentication/password-restrictions).

| | |
| --- | --- |
| Служба | web, у кожному поді Ayakaleaf Pro; зчитується під час запуску web |
| Мережа | немає |
| Періодичні завдання | немає |

### Конфігурація

Додайте до ConfigMap `overleaf-env` і перезапустіть:

```yaml title="30-config.yaml (additions)"
  OVERLEAF_PASSWORD_VALIDATION_MIN_LENGTH: "12"
  OVERLEAF_PASSWORD_VALIDATION_MAX_LENGTH: "72"
```

```bash
kubectl apply -f 30-config.yaml
kubectl -n overleaf rollout restart deployment/overleaf     # or statefulset/overleaf
```

| Змінна | За замовчуванням | |
| --- | --- | --- |
| `OVERLEAF_PASSWORD_VALIDATION_MIN_LENGTH` | `8` | Найкоротший допустимий пароль. |
| `OVERLEAF_PASSWORD_VALIDATION_MAX_LENGTH` | `72` | Найдовший допустимий пароль; значення понад `72` вважаються за `72`. |

Беріть числа в лапки: ConfigMap містить лише рядки.

<Warning>

`OVERLEAF_PASSWORD_VALIDATION_PATTERN` зчитується, але не застосовується: пароль, що йому не відповідає, приймається. Діють лише обмеження довжини.

</Warning>

### Кілька реплік

Нічого додаткового: кожна репліка зчитує той самий ConfigMap.

### Перевірено в Kubernetes

У Kubernetes 1.37 з однією реплікою, `OVERLEAF_PASSWORD_VALIDATION_MIN_LENGTH: "12"` і `OVERLEAF_PASSWORD_VALIDATION_PATTERN: aA$3` у ConfigMap, під час активації нового облікового запису пароль із 10 символів було відхилено, а пароль із 20 символів, що складався лише з малих літер і який шаблон мав би відхилити, — прийнято. Наші наскрізні тести реєстрації також відхиляють `123456` як надто короткий за стандартних налаштувань.
