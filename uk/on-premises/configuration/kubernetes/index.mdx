Розгортання Kubernetes зчитує ті самі змінні середовища, що й Toolkit. Там, де сторінка Toolkit каже «додайте це до `config/variables.env`», додайте значення до ConfigMap `overleaf-env` або до Secret `overleaf-secrets`, якщо це пароль, ключ чи токен. Потім перезапустіть:

```bash
kubectl -n overleaf apply -f 30-config.yaml        # after editing the ConfigMap
kubectl -n overleaf patch secret overleaf-secrets --type merge \
  -p '{"stringData":{"GITHUB_TOKEN_CIPHER_PASSWORD":"'"$(openssl rand -hex 32)"'"}}'
kubectl -n overleaf rollout restart deployment/overleaf
```

Значення в `config/overleaf.rc` — це налаштування Toolkit, а не змінні середовища; що їх замінює, описано в розділі «Запитання та відповіді» наприкінці цієї сторінки.

### Сертифікати та інші файли

Деякі функції приймають шлях до файлу замість значення: сертифікати SAML (`OVERLEAF_SAML_IDP_CERT`, ...), CA LDAP (`OVERLEAF_LDAP_TLS_OPTS_CA_PATH`) або приватний CA для власного GitHub Enterprise, GitLab чи Gitea (`NODE_EXTRA_CA_CERTS`). Додайте файли до Secret і змонтуйте його туди, де їх очікують сторінки Toolkit, — у `/var/lib/overleaf/certs`:

```bash
kubectl -n overleaf create secret generic overleaf-certs --from-file=idp_cert.pem --from-file=ca.pem
```

```yaml title="40-overleaf.yaml (additions)"
          volumeMounts:
            # ...
            - name: certs
              mountPath: /var/lib/overleaf/certs
              readOnly: true
      volumes:
        # ...
        - name: certs
          secret:
            secretName: overleaf-certs
```

Потім посилайтеся на них за шляхом у ConfigMap, наприклад `NODE_EXTRA_CA_CERTS: /var/lib/overleaf/certs/ca.pem`, і перезапустіть.

<Warning>

<strong>Паролі шифрування.</strong> Задайте в Secret кожен `*_CIPHER_PASSWORD` функцій, якими ви користуєтеся. Інакше деякі функції під час першого використання генерують файл ключа на томі даних: з однією реплікою це працює, доки том не буде втрачено, а з кількома репліками кожна репліка шифрувала б іншим ключем.

</Warning>

### Запитання та відповіді

<Accordion title="Які налаштування Toolkit з `config/overleaf.rc` мені потрібні?">

<strong>Відповідь:</strong> Жодне з них Ayakaleaf Pro не зчитує. Їхні відповідники в Kubernetes:

| `config/overleaf.rc`                         | Kubernetes                                                        |
| -------------------------------------------- | ----------------------------------------------------------------- |
| `OVERLEAF_LISTEN_IP`, `OVERLEAF_PORT`        | Service (NodePort) або ваш ingress                                |
| `SIBLING_CONTAINERS_ENABLED`                 | `SANDBOXED_COMPILES*` у ConfigMap, сокет Docker у поді            |
| `GIT_BRIDGE_ENABLED`                         | [Інтеграція з Git](/uk/on-premises/configuration/kubernetes/integrations/git-integration)                             |
| `MONGO_ENABLED`, `REDIS_ENABLED`, `MONGO_URL`, `REDIS_HOST` | StatefulSet або ваші керовані служби, `OVERLEAF_MONGO_URL` і `OVERLEAF_REDIS_HOST` |
| `REDIS_AOF_PERSISTENCE`                      | `--appendonly yes` у `20-redis.yaml`                              |
| `NGINX_ENABLED`, `TLS_*`                     | ваш ingress або балансувальник навантаження                       |

</Accordion>
