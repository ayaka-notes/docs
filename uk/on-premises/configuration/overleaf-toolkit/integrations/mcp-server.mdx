Кожен проєкт має MCP-сервер, тож ШІ-клієнти, як-от Claude Code, Codex, Cursor, VS Code чи Gemini CLI, можуть працювати з ним: читати й редагувати його файли, компілювати його, читати журнал LaTeX, завантажувати PDF і відповідати на коментарі. Починаючи з v6.3.3, вони також можуть переглядати історію та відновлювати версії, перевіряти відстежувані зміни, додавати коментарі, користуватися чатом проєкту й переміщувати файли.

<Info>

Цю функцію розроблено в [ayaka-notes/ayakaleaf-pro](https://github.com/ayaka-notes/ayakaleaf-pro). Вона доступна починаючи з v6.3.1. Інструменти для історії, відстежуваних змін, чату проєкту, нових коментарів і переміщення файлів доступні починаючи з v6.3.3, див. [Нове у v6.3.3](/on-premises/user-guide/users/mcp-server#new-in-v6.3.3).

</Info>

### Налаштування {#setup}

MCP-сервер постачається разом з інтеграцією з Git: увімкніть [git-bridge](/uk/on-premises/configuration/overleaf-toolkit/integrations/git-integration), і MCP-сервер теж стане доступним. Більше нічого налаштовувати не потрібно.

### Підключення ШІ-клієнта {#connect-an-ai-client}

1. У **налаштуваннях облікового запису** згенеруйте токен автентифікації Git. Той самий токен використовується і для MCP-сервера, і для Git.
2. У редакторі відкрийте **Інтеграції** та натисніть **MCP-сервер**. Там показано адресу MCP-сервера проєкту, `https://<your-overleaf>/project/<project_id>/mcp`, а також як додати її до кожного ШІ-клієнта: скопіюйте команду й замініть `<token>` своїм токеном.

Токен надсилається в HTTP-заголовку `Authorization: Bearer <token>`. Наприклад, команда для Claude Code така:

```bash
claude mcp add --transport http overleaf \
  https://<your-overleaf>/project/<project_id>/mcp \
  --header "Authorization: Bearer <token>"
```

### Використання {#usage}

Після підключення звертайтеся до ШІ-клієнта звичайними словами. Наприклад:

| Ваш запит | ШІ-клієнт використовує |
| --- | --- |
| _Виправ друкарські помилки у вступі._ | `read_file`, `edit_file`: зміни відображаються в редакторі в реальному часі |
| _Скомпілюй проєкт і виправ помилки LaTeX._ | `compile`, `get_compile_log`, `edit_file` |
| _Дай відповіді на відкриті коментарі, а потім розв'яжи їх._ | `list_comments`, `reply_to_comment`, `resolve_comment` |
| _Перейди на XeLaTeX і завантаж PDF._ | `update_settings`, `compile`, `get_output_file_link` |
| _Перепиши анотацію як відстежувану зміну._ | `read_file`, `edit_file` з `trackChanges` (v6.3.3) |
| _Що змінилося від надісланої версії?_ | `list_versions`, `list_changes`, `diff` (v6.3.3) |
| _Перемісти розділи в теку chapters._ | `move_file` (v6.3.3) |

### Інструменти {#tools}

| Група | Інструменти |
| --- | --- |
| Проєкт | `get_clone_info`, `get_settings`, `update_settings` |
| Файли | `list_files`, `read_file`, `edit_file`, `write_file`, `delete_file`, `move_file`, `create_folder` |
| Компіляція | `compile`, `get_compile_log`, `get_output_file_link`, `word_count` |
| Коментарі | `list_comments`, `reply_to_comment`, `resolve_comment`, `reopen_comment`, `add_comment`, `edit_comment_message`, `delete_comment_message` |
| Відстежувані зміни | `list_tracked_changes`, `accept_tracked_changes`, `reject_tracked_changes` |
| Історія | `list_versions`, `list_changes`, `diff`, `create_version`, `delete_version`, `restore_file`, `restore_project` |
| Чат | `list_chat_messages`, `send_chat_message` |

У v6.3.3 є 33 інструменти, або 31 з `OVERLEAF_DISABLE_CHAT=true`, який прибирає інструменти чату. У v6.3.1 і v6.3.2 є решта 17: усе перелічене вище, крім `move_file`, `create_folder`, `add_comment`, `edit_comment_message`, `delete_comment_message`, інструментів відстежуваних змін, інструментів чату та інструментів історії, крім `list_versions`. У v6.3.3 `read_file` також читає файл у версії з історії, `edit_file` і `write_file` приймають `trackChanges`, а `update_settings` також задає мову перевірки правопису.

Зміни, зроблені через `edit_file`, `write_file` і `move_file`, одразу з'являються в редакторі та об'єднуються зі змінами співавторів. Для багатьох файлів одразу або двійкових файлів ШІ-клієнт також може клонувати проєкт через Git і виконати push.

З `trackChanges` редагування наявного файлу є відстежуваною зміною користувача токена, навіть якщо відстеження змін у проєкті вимкнено; новий файл ніколи нею не є. Без `trackChanges` редагування дотримуються налаштування відстеження змін проєкту.

### Дозволи {#permissions}

MCP-сервер дотримується налаштувань спільного доступу до проєкту, як і Git:

* Усі, хто може переглядати проєкт, можуть читати його, компілювати та завантажувати результат.
* Лише власник і редактори можуть змінювати його файли й налаштування, відновлювати версії та приймати або відхиляти відстежувані зміни.
* Рецензенти також можуть додавати коментарі та відповідати на них, закривати, повторно відкривати або видаляти розпочаті ними коментарі та зберігати версії. Вони не можуть редагувати файли, навіть як відстежувані зміни.
* Кожен редагує лише власні повідомлення в коментарях, а рецензенти видаляють лише власні.
* Лише власник видаляє версії, збережені іншими.
* Читачі, які приєдналися за посиланням, не бачать коментарів, відстежуваних змін, історії та чату, як і в редакторі. Запрошені читачі бачать їх і можуть користуватися чатом.
* Якщо власник проєкту не має **Full project history**, інструменти історії показують лише зміни за останні 24 години, як і панель історії. Адміністратори бачать усі.

У посібнику користувача є таблиця того, що може кожна роль, див. [Хто що може](/on-premises/user-guide/users/mcp-server#who-may-do-what).

### Питання та відповіді {#q&a}

<Accordion title="Я не бачу Integrations або MCP server у редакторі">

<strong>Відповідь:</strong> MCP-сервер не має власної змінної середовища. Він вмикається параметром `GIT_BRIDGE_ENABLED=true` у `config/overleaf.rc`, див. [Інтеграція з Git](/uk/on-premises/configuration/overleaf-toolkit/integrations/git-integration). Після зміни виконайте `bin/up -d`. Без git-bridge редактор не показує вкладку **Integrations** на своїй лівій панелі.

</Accordion>

<Accordion title="ШІ-клієнт повідомляє «Track changes is off for this project»">

<strong>Відповідь:</strong> Клієнт запросив відстежувану зміну, але обліковий запис власника проєкту не має відстеження змін. Натисніть **Admin**, потім **Manage Users**, відкрийте власника й на вкладці **Features** увімкніть **Track changes**, див. [Features](/uk/on-premises/user-guide/administrators/user-management#features). Редагування без `trackChanges` і далі працюють.

</Accordion>

<Accordion title="ШІ-клієнт бачить лише зміни за останні 24 години">

<strong>Відповідь:</strong> Обліковий запис власника проєкту не має повної історії проєкту, тому інструменти історії показують те саме, що й панель історії: зміни за останні 24 години. Натисніть **Admin**, потім **Manage Users**, відкрийте власника й на вкладці **Features** увімкніть **Full project history**, див. [Features](/uk/on-premises/user-guide/administrators/user-management#features).

</Accordion>
