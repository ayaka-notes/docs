Кожен проєкт має MCP-сервер, тож ШІ-клієнти, як-от Claude Code, Codex, Cursor, VS Code чи Gemini CLI, можуть працювати з ним: читати й редагувати його файли, компілювати його, читати журнал LaTeX, завантажувати PDF і відповідати на коментарі.

<Info>

Цю функцію розроблено в [ayaka-notes/ayakaleaf-pro](https://github.com/ayaka-notes/ayakaleaf-pro). Вона доступна починаючи з v6.3.1.

</Info>

### Налаштування

MCP-сервер постачається разом з інтеграцією з Git: увімкніть [git-bridge](/uk/on-premises/configuration/overleaf-toolkit/git-integration), і MCP-сервер теж стане доступним. Більше нічого налаштовувати не потрібно.

### Підключення ШІ-клієнта

1. У **налаштуваннях облікового запису** згенеруйте токен автентифікації Git. Той самий токен використовується і для MCP-сервера, і для Git.
2. У редакторі відкрийте **Інтеграції** та натисніть **MCP-сервер**. Там показано адресу MCP-сервера проєкту, `https://<your-overleaf>/project/<project_id>/mcp`, а також як додати її до кожного ШІ-клієнта: скопіюйте команду й замініть `<token>` своїм токеном.

### Використання

Після підключення звертайтеся до ШІ-клієнта звичайними словами. Наприклад:

| Ваш запит | ШІ-клієнт використовує |
| --- | --- |
| _Виправ друкарські помилки у вступі._ | `read_file`, `edit_file`: зміни відображаються в редакторі в реальному часі |
| _Скомпілюй проєкт і виправ помилки LaTeX._ | `compile`, `get_compile_log`, `edit_file` |
| _Дай відповіді на відкриті коментарі, а потім розв'яжи їх._ | `list_comments`, `reply_to_comment`, `resolve_comment` |
| _Перейди на XeLaTeX і завантаж PDF._ | `update_settings`, `compile`, `get_output_file_link` |

### Інструменти

| Група | Інструменти |
| --- | --- |
| Проєкт | `get_clone_info`, `get_settings`, `update_settings`, `list_versions` |
| Файли | `list_files`, `read_file`, `edit_file`, `write_file`, `delete_file` |
| Компіляція | `compile`, `get_compile_log`, `get_output_file_link`, `word_count` |
| Коментарі | `list_comments`, `reply_to_comment`, `resolve_comment`, `reopen_comment` |

Зміни, внесені через `edit_file` і `write_file`, відображаються в редакторі в реальному часі й об'єднуються зі змінами співавторів. Для роботи з багатьма файлами одночасно, бінарними файлами чи перейменуваннями ШІ-клієнт також може клонувати проєкт за допомогою Git і виконати push.

### Дозволи

MCP-сервер дотримується налаштувань спільного доступу до проєкту, як і Git:

* Кожен, хто може переглядати проєкт, може читати його, компілювати й завантажувати результати компіляції.
* Лише власник і редактори можуть змінювати його файли та налаштування.
* Рецензенти також можуть відповідати на коментарі, а також розв'язувати чи повторно відкривати коментарі, які вони розпочали.
* Читачі, які приєдналися за посиланням, не бачать коментарів, як і в редакторі.

### Питання та відповіді

<Accordion title="Я не бачу Integrations або MCP server у редакторі">

<strong>Відповідь:</strong> MCP-сервер не має власної змінної середовища. Він вмикається параметром `GIT_BRIDGE_ENABLED=true` у `config/overleaf.rc`, див. [Інтеграція з Git](/uk/on-premises/configuration/overleaf-toolkit/git-integration). Після зміни виконайте `bin/up -d`. Без git-bridge редактор не показує вкладку **Integrations** на своїй лівій панелі.

</Accordion>
