На цій сторінці описано конфігураційні файли, які Toolkit використовує для налаштування вашого локального розгортання Overleaf.

### Постійні дані

Overleaf Toolkit потребує зберігання постійних даних, як-от файлів, необхідних для компіляції проєктів LaTeX, і вмісту бази даних MongoDB. Для цього кілька каталогів із хост-машини монтуються в Docker-контейнери, і дані записуються в ці каталоги.

#### Каталоги даних

Контейнеру `sharelatex` потрібен каталог для зберігання даних, пов'язаних із компіляцією LaTeX. Цей каталог задається змінною `OVERLEAF_DATA_PATH` у `config/overleaf.rc`.

Контейнеру `mongo`, якщо його ввімкнено, потрібен каталог для зберігання файлів бази даних; те саме стосується і контейнера `redis`. Ці каталоги також можна налаштувати в `config/overleaf.rc`.

#### Права доступу до файлів

Оскільки Docker працює від імені `root`, власником каталогів даних зрештою стане користувач `root`, навіть якщо Toolkit використовується не від імені root. Це не проблема, але про це варто пам'ятати, якщо ви плануєте змінювати постійні дані ззовні контейнерів.

### Розташування конфігураційних файлів

Усі конфігураційні файли, що належать користувачеві, розташовані в каталозі `config/`.

Цей каталог **виключено** із системи контролю версій git, тому оновлення коду Toolkit його не змінить. Toolkit **не** змінюватиме жодних даних у каталозі `config/` без вашого дозволу.

<Info>

Зміни в конфігураційних файлах не застосовуються автоматично до наявних контейнерів, навіть якщо контейнер зупинити й перезапустити (за допомогою `bin/stop` і `bin/start`). Щоб застосувати зміни, виконайте `bin/up` — за лаштунками `docker compose` автоматично застосує зміни конфігурації до нового контейнера. (Або виконайте `bin/up -d`, якщо не бажаєте під'єднуватися до логів Docker.)

</Info>

### Файл `config/overleaf.rc`

Файл `config/overleaf.rc` містить найважливіші параметри конфігурації верхнього рівня, які використовує Toolkit. Він складається з інструкцій, що задають змінні у форматі: `VARIABLE_NAME=value`

Детальний перелік усіх доступних параметрів конфігурації наведено в нашому розділі налаштувань.

### Файл `variables.env`

Файл `config/variables.env` містить змінні середовища, які завантажуються в контейнер `sharelatex` і використовуються для налаштування мікросервісів Overleaf. Серед них — назва застосунку, що відображається в заголовку вебінтерфейсу, параметри надсилання електронної пошти та інші параметри, як-от SSO.

Детальний перелік усіх доступних змінних середовища наведено в розділі [Змінні середовища](/uk/on-premises/configuration/overleaf-toolkit/environment-variables).

### Файл `config/version`

Файл `config/version` містить номер версії Docker-образу, який буде використано для створення робочого екземпляра вашого сервера Overleaf.

<Info>

Зміни в цих конфігураційних файлах не застосовуються автоматично до наявних контейнерів, навіть якщо контейнер зупинити й перезапустити (за допомогою `bin/stop` і `bin/start`). Щоб застосувати зміни, виконайте `bin/up`, і Toolkit автоматично створить для вас новий контейнер із застосованими змінами конфігурації.

</Info>

### Файл `docker-compose.override.yml`

Якщо файл `config/docker-compose.override.yml` існує, його буде включено у виклик `docker compose`. Це зручно для перевизначення конфігурації, специфічної для Docker Compose.

`config/variables.env` не завантажується в контейнери `mongo` і `redis`. Щоб задати там змінну середовища, додайте її сюди й виконайте `bin/up -d`, наприклад:

```yml
services:
    mongo:
        environment:
            GLIBC_TUNABLES: glibc.pthread.rseq=1
```

Докладніше дивіться в [документації docker-compose](https://docs.docker.com/compose/extends/#adding-and-overriding-configuration).

### Питання та відповіді

<Accordion title="Яку файлову систему мають використовувати каталоги даних? Чи можна використовувати btrfs, copy-on-write або стиснення zstd?">

<strong>Відповідь:</strong> Toolkit не перевіряє файлову систему. Вимоги має MongoDB, тому вибір найважливіший для `data/mongo` (`MONGO_DATA_PATH`). У [виробничих примітках](https://www.mongodb.com/docs/v8.0/administration/production-notes/) MongoDB радить використовувати в Linux XFS або ext4 і наполегливо рекомендує XFS разом із WiredTiger — рушієм зберігання, який вона використовує. Btrfs та інші файлові системи copy-on-write там не розглядаються. Якщо ваша коренева файлова система — btrfs, можна змонтувати том XFS і вказати на нього `MONGO_DATA_PATH`. Файлова система також має підтримувати `fsync()` для каталогів, чого не підтримують HGFS і спільні папки VirtualBox.

Стиснення на рівні файлової системи дає мало користі для `data/mongo`: WiredTiger уже [стискає](https://www.mongodb.com/docs/v8.0/core/wiredtiger/) колекції за допомогою snappy, а індекси — за допомогою префіксного стиснення. Щодо NFS див. [Усунення несправностей](/uk/on-premises/support/troubleshooting).

</Accordion>
