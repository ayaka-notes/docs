Відкрити свій екземпляр Overleaf для людей без облікового запису можна трьома способами:

* [Доступ до проєктів](/uk/on-premises/configuration/overleaf-toolkit/public-access#project-access  "mention"): дозвольте гостям відкривати посилання на спільний проєкт без входу
* [Доступ до сторінок](/uk/on-premises/configuration/overleaf-toolkit/public-access#page-access  "mention"): дозвольте відвідувачам без входу переглядати такі сторінки, як `/learn`, `/templates` і `/devs`
* [Публічна реєстрація](/uk/on-premises/configuration/overleaf-toolkit/public-access#public-registration  "mention"): дозвольте користувачам реєструватися самостійно, за потреби з листом активації та обмеженням доменами електронної пошти

### Доступ до проєктів

<Info>

За замовчуванням, навіть якщо користувач отримав посилання для спільного доступу до проєкту, він має **увійти в систему**, перш ніж зможе приєднатися до спільного редагування проєкту.

</Info>

Щоб дозволити анонімний доступ до проєктів, якими поділилися за посиланням, встановіть обидві змінні нижче:

```dotenv title="config/variables.env"
OVERLEAF_ALLOW_ANONYMOUS_READ_AND_WRITE_SHARING=true
OVERLEAF_ALLOW_PUBLIC_ACCESS=true
```

`OVERLEAF_ALLOW_ANONYMOUS_READ_AND_WRITE_SHARING` вмикає анонімне читання/запис для проєктів, якими поділилися за посиланням.

`OVERLEAF_ALLOW_PUBLIC_ACCESS` запобігає перенаправленню неавтентифікованих користувачів на сторінку входу.

Перестворіть контейнери за допомогою `bin/up`. Потім відкрийте URL-адресу спільного доступу в приватному вікні.

### Доступ до сторінок

За замовчуванням (коли `OVERLEAF_ALLOW_PUBLIC_ACCESS` не встановлено) **кожна** сторінка, крім сторінок входу та реєстрації, перенаправляє відвідувачів без входу на сторінку входу. Це стосується й сторінок, які мають бути публічними, тож посилання на них працюють лише для користувачів, які вже ввійшли в систему.

З `OVERLEAF_ALLOW_PUBLIC_ACCESS=true` відвідувачі без входу можуть відкривати:

| Сторінка                                                                  | Вимагає                         |
| --------------------------------------------------------------------- | -------------------------------- |
| Довідка з LaTeX за адресою `/learn` (див. [adding-latex-user-help.md](/uk/on-premises/configuration/overleaf-toolkit/adding-latex-user-help  "mention")) | `OVERLEAF_PROXY_LEARN=true`      |
| Галерея шаблонів за адресою `/templates`, сторінки шаблонів, попередній перегляд і завантаження ZIP (див. [templates.md](/uk/on-premises/configuration/overleaf-toolkit/templates  "mention")) | `OVERLEAF_TEMPLATE_GALLERY=true` |
| Сторінка Overleaf Import API за адресою `/devs` (див. [overleaf-import-api.md](/uk/on-premises/configuration/overleaf-toolkit/overleaf-import-api  "mention")) | —                                |

Це також дає змогу [Overleaf Import API](/uk/on-premises/configuration/overleaf-toolkit/overleaf-import-api#signed-out-visitors  "mention") зберігати надіслану відвідувачем без входу форму, доки він не ввійде в систему.

Список проєктів, редактор і створення проєктів (зокрема із шаблону чи через Import API) і надалі вимагають входу.

### Публічна реєстрація

Публічна реєстрація доступна лише в [ayaka-notes/ayakaleaf-pro](https://github.com/ayaka-notes/ayakaleaf-pro).

<Danger>

Зверніть увагу: щойно ви ввімкнете публічну реєстрацію, **будь-хто**, хто має доступ до вашого екземпляра Overleaf, зможе зареєструватися як користувач.

Зі значенням `true` процес реєстрації не перевіряє адреси електронної пошти, тому використовуйте його лише в інтранеті чи довіреному середовищі або натомість використовуйте [реєстрацію з листом активації](/uk/on-premises/configuration/overleaf-toolkit/public-access#registration-with-activation-email).

В екземплярі з OIDC не використовуйте `true`: будь-хто може зареєструватися з електронною адресою колеги до першого входу цього колеги через OIDC, і тоді колегу буде прив'язано до цього облікового запису. Використовуйте [реєстрацію з листом активації](/uk/on-premises/configuration/overleaf-toolkit/public-access#registration-with-activation-email) або вимкніть публічну реєстрацію, див. [Облікові записи та паролі](/uk/on-premises/configuration/overleaf-toolkit/authentication#accounts-and-passwords).

</Danger>

За замовчуванням ні Community Edition, ні Overleaf Pro не дозволяють публічної реєстрації.

Щоб увімкнути її, додайте до `config/variables.env`:

```dotenv title="config/variables.env"
OVERLEAF_ALLOW_PUBLIC_REGISTRATION=true
```

Перестворіть контейнери за допомогою `bin/up`.

Потім натисніть **Sign up** або перейдіть на `/register`.

### Реєстрація з листом активації

Реєстрація з листом активації доступна лише в [ayaka-notes/ayakaleaf-pro](https://github.com/ayaka-notes/ayakaleaf-pro). Користувачі реєструються лише за допомогою електронної адреси й задають пароль за посиланням у листі активації, тож користуватися обліковим записом може лише власник адреси. Для списку доменів і шаблонів потрібна v6.4.0 або новіша; попередні версії приймають лише один домен, як-от `@example.com`.

Перш ніж її вмикати, налаштуйте доставку електронної пошти, інакше користувачі ніколи не отримають листа активації. Див. [Доставка електронної пошти](/uk/on-premises/configuration/overleaf-toolkit/email-delivery).

Потім додайте такий рядок до `config/variables.env`:

```dotenv title="config/variables.env" wrap
OVERLEAF_ALLOW_PUBLIC_REGISTRATION=@example.com,@*.example.org
```

`OVERLEAF_ALLOW_PUBLIC_REGISTRATION` може мати такі значення:

| Значення                      | Хто може зареєструватися                              | Перевірка email |
| ----------------------------- | ----------------------------------------------------- | :------------: |
| `true`                        | Будь-хто, з email і паролем                           |       Ні       |
| `@example.com`                | Адреси `example.com`                                  |       Так      |
| `@*.example.org`              | Адреси піддоменів, як-от `cs.example.org`, але не самого `example.org` |       Так      |
| `@example.com,@*.example.org` | Будь-який із перелічених записів, розділених комами   |       Так      |
| `@*`                          | Будь-хто                                              |       Так      |

Домени зіставляються без урахування регістру. Щоб дозволити домен і його піддомени, перелічіть обидва: `@example.org,@*.example.org`.

### Q\&A

<Accordion title="Що може робити з коментарями редактор, який не ввійшов у систему?">

<strong>Відповідь:</strong> Користувач, який не ввійшов у систему й відкрив проєкт за посиланням для редагування, отримує такий самий доступ, як редактор, за винятком дій, під час яких фіксується, хто їх виконав:

| Дія                                               | Редактор, який не ввійшов у систему |
| ------------------------------------------------- | ----------------------------------: |
| Редагування тексту, перегляд коментарів і відстежуваних змін | Так |
| Прийняття відстежуваних змін, перемикання режиму редагування | Так |
| Видалення коментаря або всієї гілки обговорення   | Так |
| Додавання коментаря, відповідь на нього або його редагування | Ні |
| Розв'язання або повторне відкриття коментаря      | Ні |

Панель рецензування й далі показує їм кнопку **Resolve**, але розв'язання коментаря завершується повідомленням про помилку.

Користувачі, які відкрили проєкт за посиланням для перегляду, взагалі не бачать коментарів, дивіться [Ролі та дозволи](/uk/on-premises/user-and-project-management/roles-and-permissions#collaborating).

</Accordion>
