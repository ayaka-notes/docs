### Налаштування синхронізації з GitHub

<Warning>

Перед використанням синхронізації з GitHub потрібно спершу ввімкнути [git-bridge](/uk/on-premises/configuration/overleaf-toolkit/git-integration).

```dotenv title="config/overleaf.rc"
GIT_BRIDGE_ENABLED=true
```

</Warning>

Перейдіть до [налаштувань розробника](https://github.com/settings/developers), щоб створити свій застосунок GitHub OAuth, і скопіюйте `CLIENT_ID` та `SECRET`.

**Примітки**: ваша URL-адреса зворотного виклику OAuth: `${OVERLEAF_SITE_URL}/user/github-sync/oauth2/callback`.

Потім додайте наведені нижче налаштування до файлів змінних середовища Overleaf.

```dotenv title="config/variables.env" wrap
# used to encrypt the user's GitHub access token.
# How to generate: `openssl rand -hex 32`
GITHUB_TOKEN_CIPHER_PASSWORD=0123456789ABCDEFG # changed to yours

# Github Sync Settings
GITHUB_SYNC_ENABLED=true
GITHUB_SYNC_CLIENT_ID=
GITHUB_SYNC_CLIENT_SECRET=

# OAuth callback is: ${OVERLEAF_SITE_URL}/user/github-sync/oauth2/callback
# (Optional) GITHUB_SYNC_PROXY_URL=http://10.0.0.1:10808
```

<Warning>

Перш ніж налаштовувати URL-адресу зворотного виклику GitHub OAuth, переконайтеся, що `OVERLEAF_SITE_URL` задано правильно.

</Warning>

Якщо ви перебуваєте в регіоні з обмеженим доступом до мережі, вам може знадобитися налаштувати проксі для доступу до GitHub. Встановіть таку змінну середовища: `GITHUB_SYNC_PROXY_URL=http://10.0.0.1:10808`. Переконайтеся, що використання проксі відповідає місцевому законодавству та нормативним актам.

<Warning>

`GITHUB_SYNC_PROXY_URL` має бути стандартним прямим HTTP/HTTPS-проксі (наприклад, HTTP-порт Clash). Дзеркала для завантаження з GitHub, як-от `gh-proxy.org`, не підтримуються.

</Warning>

<Warning>

Не використовуйте `127.0.0.1` як хост проксі. Якщо проксі працює на хост-сервері, використовуйте LAN IP-адресу сервера (наприклад, `192.168.1.xx`) і переконайтеся, що проксі налаштовано на прийом з'єднань від пристроїв у локальній мережі.

</Warning>

### GitHub Enterprise

<Info>

Підтримка GitHub Enterprise доступна починаючи з v6.3.1. Попередні версії підключаються лише до `github.com`, і наведені нижче змінні на них не впливають.

</Info>

За замовчуванням синхронізація з GitHub підключається до `github.com`. Щоб використовувати GitHub Enterprise Server (самостійно розміщений) або GitHub Enterprise Cloud із резидентністю даних (`GHE.com`), задайте в `GITHUB_SYNC_URL` вебадресу свого екземпляра — ту, за якою ви відкриваєте репозиторії в браузері.

```dotenv title="config/variables.env" wrap
# GitHub Enterprise Server
GITHUB_SYNC_URL=https://github.example.com

# or GitHub Enterprise Cloud with data residency
# GITHUB_SYNC_URL=https://octocorp.ghe.com
```

Адреси REST і GraphQL API визначаються на основі `GITHUB_SYNC_URL` так само, як це робить GitHub CLI:

| `GITHUB_SYNC_URL`             | REST API                         | GraphQL API                              |
| ----------------------------- | -------------------------------- | ---------------------------------------- |
| `https://github.com` (за замовчуванням) | `https://api.github.com`         | `https://api.github.com/graphql`         |
| `https://SUBDOMAIN.ghe.com`   | `https://api.SUBDOMAIN.ghe.com`  | `https://api.SUBDOMAIN.ghe.com/graphql`  |
| `https://HOST` (будь-яка інша)    | `https://HOST/api/v3`            | `https://HOST/api/graphql`               |

Задавайте адреси API лише тоді, коли ваш екземпляр надає їх за іншою адресою, наприклад за API-шлюзом:

| Змінна                    | Значення за замовчуванням                                                                 |
| ------------------------- | ----------------------------------------------------------------------------------------- |
| `GITHUB_SYNC_URL`         | `https://github.com`                                                                      |
| `GITHUB_SYNC_API_URL`     | Визначається на основі `GITHUB_SYNC_URL`, див. таблицю вище                               |
| `GITHUB_SYNC_GRAPHQL_URL` | Визначається на основі `GITHUB_SYNC_API_URL`, якщо її задано (`/api/v3` замінюється на `/api/graphql`, інакше додається `/graphql`), інакше — на основі `GITHUB_SYNC_URL` |

<Warning>

* Створюйте OAuth-застосунок у своєму корпоративному екземплярі (_Settings → Developer settings → OAuth Apps_): застосунок із `github.com` там не працює. URL-адреса зворотного виклику та сама: `${OVERLEAF_SITE_URL}/user/github-sync/oauth2/callback`.
* `GITHUB_SYNC_URL` — це лише вебадреса. Не задавайте в ній адресу API, як-от `https://api.github.com` чи `https://HOST/api/v3`, і не додавайте шлях до організації.
* Усі три адреси мають вказувати на один і той самий екземпляр GitHub.

</Warning>

<Info>

Якщо ваш екземпляр використовує сертифікат від приватного центру сертифікації (CA), змонтуйте сертифікат CA в контейнер і вкажіть шлях до нього в `NODE_EXTRA_CA_CERTS`, наприклад `NODE_EXTRA_CA_CERTS=/var/lib/overleaf/certs/github-ca.pem`.

</Info>

<Danger>

Прив'язані облікові записи та проєкти належать до екземпляра, з яким їх було прив'язано. Перш ніж перемкнути `GITHUB_SYNC_URL` на інший екземпляр, попросіть користувачів скасувати прив'язку своїх облікових записів і проєктів GitHub.

</Danger>

### Хто може прив'язувати та синхронізувати

Як і в Overleaf Cloud, лише власник проєкту може прив'язати проєкт до репозиторію GitHub. Після прив'язки синхронізувати його може кожен співавтор із правом редагування.

| Дія                                                        | Хто може це зробити                                            |
| ---------------------------------------------------------- | -------------------------------------------------------------- |
| Експорт проєкту в новий репозиторій GitHub                 | Власник проєкту                                                |
| Імпорт репозиторію GitHub у новий проєкт                   | Будь-який користувач, який стає власником нового проєкту       |
| Pull, push і злиття прив'язаного проєкту                    | Власник і співавтори з правом редагування                      |
| Скасування прив'язки проєкту до репозиторію                | Власник проєкту                                                |

* Overleaf взаємодіє з GitHub від імені облікового запису GitHub користувача, який виконує синхронізацію, тому кожен співавтор, який синхронізує, прив'язує власний обліковий запис GitHub і повинен мати дозвіл на push у гілку за замовчуванням репозиторію.
* Співавтори з правом лише перегляду не можуть використовувати синхронізацію з GitHub для проєкту.

### Q\&A

<Accordion title="Чи можна виконувати force push у гілку за замовчуванням?">

<strong>Відповідь:</strong> Ми не рекомендуємо цього робити. Overleaf виявляє force push, попереджає про нього та підхоплює переписану гілку, зливаючи зміни, внесені в Overleaf після останньої синхронізації. Щоб уникнути несподіванок, захистіть гілку за замовчуванням від force push у налаштуваннях репозиторію.

</Accordion>

<Accordion title="Чи можна перейменувати гілку за замовчуванням прив'язаного проєкту?">

<strong>Відповідь:</strong> Будь ласка, не робіть цього. Overleaf продовжує синхронізуватися з гілкою, до якої було прив'язано проєкт. Щоб синхронізуватися з іншою гілкою, скасуйте прив'язку проєкту, а потім імпортуйте репозиторій у новий проєкт, який використовуватиме поточну гілку за замовчуванням.

</Accordion>
